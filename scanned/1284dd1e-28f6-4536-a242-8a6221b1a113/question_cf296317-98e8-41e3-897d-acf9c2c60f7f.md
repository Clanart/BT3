In `RBF::create_funded_psbt` (crates/clementine-tx-sender/src/rbf.rs), `change_position: Some(tx.output.len())` places the wallet-added change output last specifically so `SinglePlusAnyoneCanPay` signatures on other inputs remain valid. Preconditions: a payout transaction created by `Operator::withdraw` is funded via `create_funded_psbt`/RBF. Call sequence: an unprivileged attacker (network peer relaying transactions) constructs and broadcasts a conflicting fee-bumped transaction that re-spends the same operator-added funding UTXO(s) (which are ordinary wallet outputs with no anchor/replace protection) with a different change destination or different second input, before the operator's version confirms, still preserving the untouched withdrawal-UTXO input+signature since `SinglePlusAnyoneCanPay` permits any additional inputs/outputs. Binding: the txid whose OP_RETURN attributes the payout to operator O == the txid whose funding inputs actually came from operator O's wallet. Impact: Critical - because `SinglePlusAnyoneCanPay` explicitly allows third parties to rebuild the transaction with different funding, and there is no on-chain or off-chain marker binding the confirmed payout's funding inputs back to the OP_RETURN-named operator, an attacker can get a self-funded variant confirmed that still carries operator O's OP_RETURN, again breaking attribution == actual funder.
