In `Verifier::update_finalized_payouts` (core/src/verifier.rs), `operator_xonly_pk` is parsed purely from `get_first_op_return_output(...)` of whatever transaction happens to spend the registered withdrawal UTXO in a finalized block, via `parse_op_return_data`. Preconditions: a withdrawal UTXO is registered; no operator has yet funded it. Call sequence: attacker (the withdrawer) constructs and broadcasts, using only their own SinglePlusAnyoneCanPay-signed input, a transaction spending the withdrawal UTXO to themselves with an OP_RETURN embedding an arbitrary 32 bytes that happens to parse as a valid XOnlyPublicKey belonging to a real, honest operator who never signed or funded this transaction. Binding: operator_xonly_pk recorded for withdrawal i == xonly pk of an operator that actually broadcast/funded a payout for withdrawal i. Impact: Critical - an honest operator can be falsely attributed a payout it never made (any output value came from the withdrawer's own dust UTXO, not the operator), and if enough of the flow (`mark_payout_handled`, kickoff, reimburse) proceeds automatically for that operator's kickoff bookkeeping, it corrupts round/kickoff state for a payout the operator never funded. Proof idea: cargo test in core/src/test constructing a payout-shaped tx signed solely by the withdrawer with OP_RETURN containing a real operator's xonly pk bytes, confirming it, and asserting `update_finalized_payouts`/`get_payout_info_from_move_txid` attributes it to that operator despite no operator signature or funding input being present.
