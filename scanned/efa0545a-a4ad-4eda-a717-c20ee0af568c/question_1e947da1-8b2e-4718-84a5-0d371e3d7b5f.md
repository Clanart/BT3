In `bridge_circuit` (circuits-lib/src/bridge_circuit/mod.rs), the `payout_input_index: u32` field of `BridgeCircuitInput` is host-supplied and only checked via `assert_eq!(user_wd_txid, input.payout_spv.transaction.input[payout_input_index].previous_output.txid)`. Preconditions: an attacker who is the registered withdrawer builds a payout transaction with the withdrawal UTXO consumed at a non-zero, non-canonical input index alongside decoy inputs from wallets they control. Call sequence: bridge circuit reads `payout_input_index` from host input without any circuit-side derivation from the SPV transaction itself, trusting the host/operator's claim. Binding: payout_input_index == index(payout_spv.transaction.input, actual withdrawal-UTXO-spending input) as independently recomputed by the circuit, not merely re-asserted against a host-picked index. Impact: Critical, since the deposit_constant and journal_hash computed downstream depend on this trusted index; if an operator (attacker cannot reach this alone, but the design gap is that no independent recomputation ever exists) supplies a wrong index paired with a crafted payout tx having decoy withdrawal-shaped inputs, a false claim about which output funded the withdrawal could be committed. Proof idea: circuits-lib test constructing a payout tx with two inputs, one being the real withdrawal outpoint and one being a decoy with the same txid pattern, and asserting whether `bridge_circuit` derives payout_input_index independently versus trusting the host value verbatim.
