In `TxSender::is_bridge_tx_nonstandard` (crates/clementine-tx-sender/src/nonstandard.rs), an attacker deposits normally, then as the registered withdrawer broadcasts their own copy of the operator's `Payout` transaction (rebuilt from the `SinglePlusAnyoneCanPay` signature and the OP_RETURN operator pubkey visible in the mempool) with a different funding input before the operator's version confirms. Preconditions: an operator has called `Operator::withdraw` and the payout tx sits unconfirmed; the attacker holds no operator or verifier role. Call sequence: attacker rebroadcasts a fee-bumped payout variant referencing the same withdrawal UTXO but funded by the attacker rather than the operator; if it confirms, `Verifier::update_finalized_payouts` records the OP_RETURN operator xonly pk from whichever payout transaction actually lands in a block. Binding that breaks: operator_xonly_pk recorded in withdrawals.payer_operator_xonly_pk == the xonly pk of the party whose BTC actually paid output value to the withdrawer. Impact: Critical - an operator can be credited/reimbursed (Reimburse tx via `create_reimburse_txhandler`) for a payout it never funded, since attribution is derived solely from OP_RETURN content, not from provenance of funding inputs. Proof idea: cargo test under core/src/test constructing two payout txs spending the same withdrawal UTXO with different funders and OP_RETURN operator keys, broadcasting the non-operator-funded one first, and asserting `get_payout_info_from_move_txid` returns an operator xonly pk whose wallet did not supply the payout value.
