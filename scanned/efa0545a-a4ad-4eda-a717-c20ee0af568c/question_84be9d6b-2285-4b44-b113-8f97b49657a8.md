In `parse_withdrawal_sig_params` (core/src/rpc/parser/operator.rs), a 64-byte Schnorr signature with `TapSighashType::Default` is silently normalized to `SinglePlusAnyoneCanPay`. Preconditions: attacker (the registered withdrawer) crafts a signature that is valid for `SIGHASH_ALL` semantics under some other interpretation but happens to also parse as a bare 64-byte sig. Call sequence: `Operator::withdraw` -> `parse_withdrawal_sig_params` normalizes sighash type -> `create_payout_txhandler` -> `calculate_sighash_txin` -> `SECP.verify_schnorr`. Binding: sighash_type used to compute the verified digest == sighash_type the withdrawer actually intended when producing the 64-byte signature. Impact: High - if the normalization assumption is wrong for a given input, an operator could construct/broadcast a payout transaction not properly authorized by the sighash the user believed they signed, an unauthenticated-shaped state mutation reachable purely from attacker-chosen bytes. Proof idea: cargo test in core/src/test that submits a raw 64-byte signature via `WithdrawParams.input_signature` and asserts the resulting `taproot::Signature.sighash_type` field used for verification equals `SinglePlusAnyoneCanPay`, then confirms whether an alternate legitimate interpretation was excluded.
