Target: `MMRGuest::verify_proof` and `MMRInclusionProof.subroot_idx`/`internal_idx` fields (untrusted, deserialized as part of `BridgeCircuitInput.payout_spv.mmr_inclusion_proof`). Attacker action: submit an `MMRInclusionProof` whose `internal_idx` bit pattern and `inclusion_proof` sibling list are chosen so that replaying `hash_pair` calls from an *unrelated* leaf (e.g. a leaf hash equal to `block_header.compute_block_hash()` of a non-canonical/reorged header the attacker fully controls, mined via regtest with lower work) collides with one of `MMRGuest.subroots[subroot_idx]` built from the real canonical chain. Preconditions: the header-chain proof (`hcp`) commits an MMR containing many canonical blocks; attacker needs one subroot collision under 32-byte `hash_pair` (infeasible generically, but the point is to test that no additional binding restricts `subroot_idx` to the segment actually corresponding to the header committed by `hcp.chain_state.best_block_hash`). Call sequence: `bridge_circuit` -> `let mmr = input.hcp.chain_state.block_hashes_mmr.clone()` -> `input.payout_spv.verify(mmr)` -> `MMRGuest::verify_proof(block_hash, mmr_inclusion_proof)`. Binding: `mmr_guest.subroots[mmr_inclusion_proof.subroot_idx]` == the subroot that the verified header-chain proof `hcp` actually committed for the segment containing `block_header`. Impact: Critical, a header-chain-committed MMR is used to admit a block hash the header chain never actually included, causing false proof of payout inclusion. Proof idea: cargo test appending N headers into `MMRGuest`/`MMRNative`, and then attempting to verify a foreign leaf against a `subroot_idx` from a different, smaller MMR snapshot, asserting `verify_proof` correctly rejects it and documenting that this rejection is solely due to hash preimage difficulty, not a structural check tying `subroot_idx` to `hcp`.
