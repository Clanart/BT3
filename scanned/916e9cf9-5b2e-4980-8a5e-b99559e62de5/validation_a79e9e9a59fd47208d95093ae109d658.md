## Title
Alpenglow inflation-reward points calculation permanently zeroes out small stake delegations via integer-division truncation, unlike Tower's deferral mechanism - (File: `runtime/src/inflation_rewards/points.rs`, `runtime/src/inflation_rewards/mod.rs`)

## Summary
The external report describes a class of bug where an integer division (`volume / price`) can round down to zero, causing a user to permanently lose the value they committed, and where the fix is to defer/reject payouts that would be truncated to zero rather than silently advancing accounting state. Agave's Alpenglow inflation-reward path contains the same broken invariant: `calculate_alpenglow_points` computes `earned_credits * stake_amount / total_stake` [1](#0-0) , which truncates to `0` for any staker whose stake is a sufficiently small fraction of the vote account's total delegated stake. Unlike the Tower epoch path — which explicitly refuses to advance `credits_observed` when a reward would round away (so points can accumulate across epochs until they're large enough to pay out) — the Alpenglow (non-Tower) path unconditionally advances `credits_observed` even when the resulting reward is `0`, permanently forfeiting that epoch's reward with no possibility of catch-up.

## Finding Description
`calculate_stake_rewards` in `runtime/src/inflation_rewards/mod.rs` branches on `ag_epoch_type`:

```rust
AlpenglowEpochType::Alpenglow { .. } => {
    if ag_points == 0 {
        return skip_reward(SkippedReason::ZeroPoints);
    }
    ag_points
}
``` [2](#0-1) 

`skip_reward` decides whether to advance `credits_observed` based on `advance_credits_for_skipped_reward`:

```rust
let is_tower_epoch = matches!(ag_epoch_type, AlpenglowEpochType::Tower);
let advance_credits_for_skipped_reward =
    !is_tower_epoch && new_credits_observed != stake.credits_observed;
let skipped_reward = || {
    Some(CalculatedStakeRewards {
        staker_rewards: 0,
        voter_rewards: 0,
        new_credits_observed,
    })
};
let skip_reward = |reason: SkippedReason| {
    ...
    if advance_credits_for_skipped_reward {
        skipped_reward()
    } else {
        None
    }
};
``` [3](#0-2) 

For any non-Tower (Alpenglow) epoch, `!is_tower_epoch` is `true`, so as long as the vote account recorded new credits that epoch (`new_credits_observed != stake.credits_observed`, the normal case), `skip_reward` returns `Some(CalculatedStakeRewards{staker_rewards: 0, voter_rewards: 0, new_credits_observed})` instead of `None`.

The caller, `redeem_stake_rewards`, unconditionally commits `new_credits_observed` whenever `calculate_stake_rewards` returns `Some(...)`, regardless of whether any reward was actually paid:

```rust
let maybe_rewards = calculate_stake_rewards(...)
    .map(|calculated_stake_rewards| {
        ...
        stake.credits_observed = calculated_stake_rewards.new_credits_observed;
        (calculated_stake_rewards.staker_rewards, calculated_stake_rewards.voter_rewards)
    });
``` [4](#0-3) 

The root cause is the truncating division itself:

```rust
earned_points = if earned_credits == 0 || stake_amount == 0 {
    0
} else {
    ...
    earned_credits * stake_amount / total_stake as u128
};
``` [1](#0-0) 

`earned_credits` is bounded by the number of slots in an epoch (on the order of hundreds of thousands), and `total_stake` is the vote account's entire delegated stake (can be tens of millions of SOL in lamports, i.e. up to ~10^16+). For any delegator whose `stake_amount` is small relative to `total_stake` such that `earned_credits * stake_amount < total_stake`, `earned_points` is `0` every single epoch. Because `credits_observed` is advanced regardless, this staker's entitlement for that epoch is discarded and can never be recovered — there is no mechanism, as there is for Tower (`return None` preserves `credits_observed` so points accumulate over multiple epochs until non-zero), to accumulate the fractional entitlement across epochs.

This directly mirrors the reported bug pattern: an integer division (`volume/price` there, `earned_credits*stake_amount/total_stake` here) truncates to zero for a "small" side of the ratio, and the surrounding bookkeeping (advancing `credits_observed` / consuming the bid) irreversibly locks in the loss instead of deferring or reverting.

## Impact Explanation
Impact is loss of legitimate inflation staking rewards for affected delegators — a fund-loss condition, not merely a cosmetic rounding artifact. The loss is permanent per-epoch (not merely delayed) because `credits_observed` is advanced even on a zero payout in Alpenglow epochs, unlike the explicit "don't collect if we lose a whole lamport" deferral logic retained for Tower epochs and highlighted by the `commission_split`/`commission_split_preserve_lamports` split later in the same function [5](#0-4) . Any stake account with a small enough proportion of a validator's total delegated stake is systematically and repeatedly denied rewards it is nominally entitled to.

## Likelihood Explanation
Likelihood is high for any validator with a very large total delegated stake relative to individual small delegations (e.g. dust delegations, small retail delegators to a mega-validator), which is common on mainnet. No malicious actor or privileged access is required — this triggers under entirely normal reward-distribution processing for ordinary stake accounts once Alpenglow reward epochs are active.

## Recommendation
For the Alpenglow branch, do not unconditionally advance `credits_observed` when the computed reward is zero solely due to truncation. Either (a) preserve `credits_observed` (mirroring the Tower path) so that a small stake's earned credits accumulate across epochs until `earned_credits * stake_amount / total_stake` becomes non-zero, or (b) track and carry forward the truncated remainder (e.g., in higher precision) so no lamports of entitlement are structurally discarded.

## Proof of Concept
1. Configure a vote account with a large `total_stake` (e.g. 20,000,000 SOL in lamports) delegated to it.
2. Delegate a small stake amount `S` such that `earned_credits * S < total_stake` for a typical epoch's `earned_credits` (e.g. `S` on the order of a few thousand lamports, or any small delegation versus a mega-validator's total stake).
3. Run reward distribution for an Alpenglow epoch (`AlpenglowEpochType::Alpenglow`). `calculate_alpenglow_points` returns `earned_points == 0` [1](#0-0) .
4. `calculate_stake_rewards` takes the `ag_points == 0` branch and calls `skip_reward(SkippedReason::ZeroPoints)`; since `!is_tower_epoch` and credits changed, `advance_credits_for_skipped_reward` is `true`, so `skipped_reward()` returns `Some(CalculatedStakeRewards{staker_rewards:0, voter_rewards:0, new_credits_observed})` [2](#0-1) .
5. `redeem_stake_rewards` commits `stake.credits_observed = new_credits_observed` even though `staker_rewards == 0` [6](#0-5) .
6. Repeat for subsequent epochs with the same small `S`: the staker earns `0` lamports every epoch indefinitely, with no accumulation, confirming permanent forfeiture of the reward entitlement that would otherwise have been preserved under the Tower path's `return None` behavior.
