**Rationale:**

`CompactUpdateVoteState` (and its `Switch` variant) is handled at [1](#0-0)  by calling `vote_state::process_vote_state_update`, which only processes slot-hash/lockout vote-state updates using the `SlotHashes` and `Clock` sysvars. It never touches commission, never calls `update_commission`, and carries no code path that reads or writes the commission field.

Commission timing is governed entirely by the separate `UpdateCommission` instruction handler at [2](#0-1) , which calls `vote_state::update_commission` with the *actual* `Clock` and `EpochSchedule` sysvars fetched fresh from the sysvar cache for that instruction's execution context [3](#0-2) . The timing rule itself is `is_commission_update_allowed`, which checks the real `clock.slot` against the epoch schedule midpoint [4](#0-3) ; this rule is only enforced when the new commission would be an *increase* (or the vote state is undecodable), by design — decreases are always allowed regardless of slot, which is intended behavior, not a bug.

Because `clock.slot` is a runtime sysvar reflecting the actual slot the transaction executes in, it cannot be altered by anything an attacker puts in the transaction (authority fields, seeds, BLS proof material, duplicated accounts, or a preceding `CompactUpdateVoteState` instruction in the same transaction). There is no code path by which invoking `CompactUpdateVoteState` — before, after, or alongside `UpdateCommission` — changes the epoch/clock values used by `is_commission_update_allowed`, since the two instructions operate on entirely independent fields and sysvar reads. The premise that `CompactUpdateVoteState` can influence commission-change timing has no basis in `process_instruction`'s dispatch logic.

pub fn update_commission<S: std::hash::BuildHasher>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    commission: u8,
    signers: &HashSet<Pubkey, S>,
    epoch_schedule: &EpochSchedule,
    clock: &Clock,
    disable_commission_update_rule: bool,
) -> Result<(), InstructionError> {
    let vote_state_result = get_vote_state_handler_checked(vote_account, target_version);
    let enforce_commission_update_rule = !disable_commission_update_rule
        && match vote_state_result.as_ref() {
            Ok(decoded_vote_state) => commission > decoded_vote_state.commission(),
            Err(_) => true,
        };

    if enforce_commission_update_rule && !is_commission_update_allowed(clock.slot, epoch_schedule) {
        return Err(VoteError::CommissionUpdateTooLate.into());
    }

    let mut vote_state = vote_state_result?;

    // current authorized withdrawer must say "yay"
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;

    vote_state.set_commission(commission);

    vote_state.set_vote_account_state(vote_account)
}

/// Given the current slot and epoch schedule, determine if a commission change
/// is allowed
pub fn is_commission_update_allowed(slot: Slot, epoch_schedule: &EpochSchedule) -> bool {
    // always allowed during warmup epochs
    if let Some(relative_slot) = slot
        .saturating_sub(epoch_schedule.first_normal_slot)
        .checked_rem(epoch_schedule.slots_per_epoch)
    {
        // allowed up to the midpoint of the epoch
        relative_slot.saturating_mul(2) <= epoch_schedule.slots_per_epoch
    } else {
        // no slots per epoch, just allow it, even though this should never happen
        true
    }
}
