Target: `bridge_circuit`'s L1 output-value blindness combined with `Aggregator::optimistic_payout`. Attacker action: a withdrawer signs a `withdraw` request expecting `optimistic_payout` to pay them `W` BTC; separately, any party broadcasts a Bitcoin payout tx spending the exact same withdrawal UTXO reference but paying 0 to the withdrawer address and everything to an anchor/fee output, then feeds this alternate tx (not the optimistic one) as `payout_spv.transaction` to the bridge circuit. Preconditions: the withdrawal outpoint is unique and once-spendable; both the optimistic payout and the malicious payout compete to spend it, only one confirms. Call sequence: whichever payout tx confirms and gets SPV-included is checked by `bridge_circuit` purely on `previous_output` match; the honest optimistic payout's output values are never distinguished from the malicious one's. Binding: confirmed_payout_tx_output_value_to_withdrawer == the value the aggregator's `optimistic_payout` route intended to pay. Scoped impact: Critical — a fronted-looking payout with 0 actual value to the withdrawer still authorizes full `bridge_amount` reimbursement via Reimburse. Proof idea: cargo test in `core/src/test` racing two payout tx candidates for the same withdrawal outpoint on regtest and confirming the zero-value one, then running the bridge-circuit-host-level `create_spv`/`bridge_circuit` pipeline to show journal acceptance.
