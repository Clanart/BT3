[core/src/verifier.rs] Verifier::sign_optimistic_payout does not remove or mark spent the session it partially consumes via `session.nonces.pop()`; the session (with any nonces still remaining) stays in `AllSessions.sessions` under the same id. Can an unprivileged caller who has already completed one successful optimistic_payout for deposit A (consuming the single nonce reserved for it) resend the identical nonce_session_id in a fresh optimistic_payout RPC for the SAME deposit A but with a different output_script_pubkey (redirecting funds to an address they control), relying on `session.nonces.pop()` returning `Err` only if the vector is empty — and given num_nonces from nonce_gen could have been requested as >1 to reserve extra unused nonces — is there a path where residual nonces let a second, differently-addressed partial signature be produced under the same session for the same deposit? Binding: SecretNonce popped for deposit A's optimistic payout == used for exactly one output_script_pubkey/output_amount pair, never a second. Impact: Critical, BTC leaving the move-to-vault UTXO to an output not matching the fronted withdrawal (custody violation) if a second, different output_script_pubkey obtains N verifiers' partial sigs. Proof idea: cargo test calling nonce_gen with num_nonces=3, then sign_optimistic_payout twice for the same deposit_id with two different output_script_pubkey values and the same session_id, asserting both calls do not both succeed with valid partial sigs verifying against different messages.
