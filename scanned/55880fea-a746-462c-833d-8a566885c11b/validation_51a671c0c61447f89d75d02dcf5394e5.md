### Title
Stake-weighted QUIC QoS controller (`SwQos`) never consults the connection banlist, letting banned/malicious staked peers keep consuming TPU connection and stream capacity - ([File: streamer/src/nonblocking/swqos.rs])

### Summary
The external report describes a "neutral adapter" that is exempted from a ratio-based block mechanism: setting `ratio = 0` is supposed to stop a compromised/faulty adapter from receiving further funds, but a special-cased code path (the neutral adapter deposit branch) ignores that block and keeps sending it money. The Agave analog is structurally identical but in the QUIC transaction-ingestion path: the streamer crate implements a `Banlist` mechanism specifically to exclude malicious/abusive peers from further service, but it is only enforced by one of the two `QosController` implementations. The controller that Agave actually wires into the TPU / TPU-forward sockets (`SwQos`, spawned via `spawn_stake_weighted_qos_server`) never checks the banlist at all, so a peer that has been banned can continue opening staked/unstaked connections and consuming streams exactly as if it were never banned.

### Finding Description
`solana_net_utils::banlist::Banlist` provides `ban()`/`is_banned()` primitives meant to temporarily exclude a pubkey from service [1](#0-0) .

`SimpleQos` (one `QosController` implementation) correctly enforces this: before adding any new connection it checks `self.banlist.is_banned(&remote_pubkey)` and immediately closes the connection with `CONNECTION_CLOSE_CODE_DISALLOWED` if the peer is banned [2](#0-1) . `SimpleQos` even holds an `Arc<Banlist<Pubkey>>` field (`SimpleQosBanlist`) with a background eviction task that proactively rips out already-established connections for a newly-banned pubkey from the staked connection table [3](#0-2) [4](#0-3) .

`SwQos`, the other `QosController` implementation, has no such field or check at all. Its struct only tracks `config`, `staked_stream_load_ema`, `stats`, `staked_nodes`, `unstaked_connection_table`, and `staked_connection_table` — no `Banlist` reference [5](#0-4) . Its `try_add_connection` implementation goes straight from `peer_type()` classification into staked/unstaked connection-table admission logic (pruning, adding, falling back to the unstaked table) without ever calling `is_banned` or any equivalent exclusion check [6](#0-5) . `build_connection_context` similarly only derives `peer_type`/`total_stake` from `staked_nodes`, with no banlist lookup [7](#0-6) .

Critically, `SwQos` (via `spawn_stake_weighted_qos_server`) is the controller actually spawned for the validator's real transaction-ingestion sockets — both the primary TPU QUIC listener and the TPU-forward QUIC listener — in `Tpu::new`/`core/src/tpu.rs` [8](#0-7) . This means the concrete QoS enforcement point that gates the vast majority of live transaction traffic performs no ban enforcement, while the ban-aware implementation (`SimpleQos`) is a separate, not-guaranteed-to-be-used code path.

This mirrors the reported invariant break exactly: a mechanism designed to fully exclude a flagged/malicious actor from receiving service (`ratio = 0` for the adapter / `Banlist::ban()` for the peer pubkey) does not apply on the alternate/default code path that actually handles the resource in question (the neutral-adapter deposit branch / `SwQos` connection admission), so the actor keeps receiving the protected resource (vault funds / QUIC connections & streams) indefinitely.

### Impact Explanation
A peer that has been identified as malicious or abusive (e.g., protocol violations or attack detection funneled into `Banlist::ban()`) is expected to be locked out of further TPU access. Because `SwQos` never checks the banlist, that peer can continue to open new staked or unstaked QUIC connections and consume stream/connection quota on the transaction ingestion path with no additional restriction beyond ordinary QoS limits. This defeats the security control's purpose: it allows an attacker who has already been flagged/banned to keep occupying staked connection-table slots and stream throughput that the ban was meant to free up for legitimate stake-weighted traffic, degrading TPU availability/QoS for honest, higher-priority senders — a non-RPC, unprivileged remote resource-exhaustion/degradation vector against the transaction-ingestion path.

### Likelihood Explanation
No special privileges are required by the attacker beyond already being (or becoming) a QUIC peer of the validator; the flaw is purely a missing check in the code that is exercised on every incoming connection to the TPU/TPU-forward endpoints. Since `SwQos` is the controller actually wired up for these endpoints in `core/src/tpu.rs`, any ban issued while `SwQos` is in use is silently ineffective for new connection attempts, making exploitation as simple as reconnecting after being banned.

### Recommendation
Add banlist enforcement (an `is_banned` check equivalent to `SimpleQos`'s) to `SwQos::try_add_connection` / `build_connection_context`, or thread a shared `Banlist` through both `QosController` implementations so that a ban has uniform effect regardless of which QoS controller is active on a given socket. Additionally, add integration coverage that spawns `SwQos`-backed servers and asserts a banned pubkey is rejected, mirroring the existing `SimpleQos` ban tests.

### Proof of Concept
1. Configure a validator to use the stake-weighted QoS server (default TPU/TPU-forward wiring in `core/src/tpu.rs::Tpu::new`, via `spawn_stake_weighted_qos_server`).
2. Trigger whatever mechanism inserts a pubkey into the shared `Banlist` (e.g., the same ban condition that `SimpleQos`'s eviction task reacts to).
3. From the banned pubkey/keypair, open a new QUIC connection to the TPU or TPU-forward port.
4. Observe that `SwQos::build_connection_context`/`try_add_connection` never queries the banlist [9](#0-8) , so the connection is admitted to the staked or unstaked connection table exactly as an un-banned peer's would be, and streams/transactions from it continue to be processed — in contrast to `SimpleQos`, where the same banned pubkey would be rejected immediately at `try_add_connection`'s banlist check [10](#0-9) .

**Uncertainty:** I could not fully trace, within the available search budget, the exact producer(s) that call `Banlist::ban()` for QUIC/TPU peers (the referenced usages in `streamer/src/quic.rs`, `bls-sigverify`, and `core/src/tvu.rs` were not fully read), nor definitively confirm whether any validator configuration path substitutes `SimpleQos` for `SwQos` on the TPU sockets. The core claim — that `SwQos`'s struct and connection-admission logic contain no banlist field or check, unlike `SimpleQos` — is directly supported by the cited code.

impl<T: Eq + Hash> Banlist<T> {
    /// Ban the `id` for the specified `timeout`
    ///
    /// Returns `true` if the `id` was already banned else `false`.
    pub fn ban(&self, id: T, timeout: Duration) -> bool {
        debug_assert!(!timeout.is_zero());
        debug_assert!(Instant::now().checked_add(timeout).is_some());
        let Some(expires_at) = Instant::now().checked_add(timeout) else {
            return false;
        };
        let prev = self.banned.write().unwrap().insert(id, expires_at);
        debug_assert!(prev < Some(expires_at));
        prev.is_some()
    }

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

    #[allow(clippy::manual_async_fn)]
    fn try_add_connection(
        &self,
        client_connection_tracker: ClientConnectionTracker,
        connection: &quinn::Connection,
        conn_context: &mut SwQosConnectionContext,
    ) -> impl Future<Output = Option<CancellationToken>> + Send {
        async move {
            const PRUNE_RANDOM_SAMPLE_SIZE: usize = 2;

            match conn_context.peer_type() {
                ConnectionPeerType::Staked(stake) => {
                    let mut connection_table_l = self.staked_connection_table.lock().await;

                    if connection_table_l.total_size >= self.config.max_staked_connections {
                        let num_pruned =
                            connection_table_l.prune_random(PRUNE_RANDOM_SAMPLE_SIZE, stake);
                        self.stats
                            .num_evictions_staked
                            .fetch_add(num_pruned, Ordering::Relaxed);
                        update_open_connections_stat(&self.stats, &connection_table_l);
                    }

                    if connection_table_l.total_size < self.config.max_staked_connections {
                        if let Ok((last_update, cancel_connection, stream_counter)) = self
                            .cache_new_connection(
                                client_connection_tracker,
                                connection,
                                connection_table_l,
                                conn_context,
                            )
                        {
                            self.stats
                                .connection_added_from_staked_peer
                                .fetch_add(1, Ordering::Relaxed);
                            conn_context.in_staked_table = true;
                            conn_context.last_update = last_update;
                            conn_context.stream_counter = Some(stream_counter);
                            return Some(cancel_connection);
                        }
                    } else {
                        // If we couldn't prune a connection in the staked connection table, let's
                        // put this connection in the unstaked connection table. If needed, prune a
                        // connection from the unstaked connection table.
                        if let Ok((last_update, cancel_connection, stream_counter)) = self
                            .prune_unstaked_connections_and_add_new_connection(
                                client_connection_tracker,
                                connection,
                                self.unstaked_connection_table.clone(),
                                self.config.max_unstaked_connections,
                                conn_context,
                            )
                            .await
                        {
                            self.stats
                                .connection_added_from_staked_peer
                                .fetch_add(1, Ordering::Relaxed);
                            conn_context.in_staked_table = false;
                            conn_context.last_update = last_update;
                            conn_context.stream_counter = Some(stream_counter);
                            return Some(cancel_connection);
                        } else {
                            self.stats
                                .connection_add_failed_on_pruning
                                .fetch_add(1, Ordering::Relaxed);
                            self.stats
                                .connection_add_failed_staked_node
                                .fetch_add(1, Ordering::Relaxed);
                        }
                    }
                }
                ConnectionPeerType::Unstaked => {
                    if let Ok((last_update, cancel_connection, stream_counter)) = self
                        .prune_unstaked_connections_and_add_new_connection(
                            client_connection_tracker,
                            connection,
                            self.unstaked_connection_table.clone(),
                            self.config.max_unstaked_connections,
                            conn_context,
                        )
                        .await
                    {
                        self.stats
                            .connection_added_from_unstaked_peer
                            .fetch_add(1, Ordering::Relaxed);
                        conn_context.in_staked_table = false;
                        conn_context.last_update = last_update;
                        conn_context.stream_counter = Some(stream_counter);
                        return Some(cancel_connection);
                    } else {
                        self.stats
                            .connection_add_failed_unstaked_node
                            .fetch_add(1, Ordering::Relaxed);
                    }
                }
            }

            None
        }
    }
