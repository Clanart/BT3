target: Operator::withdraw sighash verification. Attacker action: attacker supplies in_signature.sighash_type = TapSighashType::None over in_outpoint/out_script_pubkey/out_amount for a withdrawal_index whose Citrea withdrawal amount is W. Preconditions: withdrawal_utxo == in_outpoint per DB; is_profitable() passes because out_amount is set low enough to satisfy the bridge_amount bound even though None commits to no outputs at all. Call sequence: calculate_sighash_txin(0, TapSighashType::None) is computed and verified against user_xonly_pk with none of the tx's outputs bound to the signature; fund_raw_transaction and sign_raw_transaction_with_wallet then finalize any output set the operator's wallet chooses. Binding that breaks: the sighash type verified against the user's key == a flag that commits the payout output the operator is reimbursed for; with SIGHASH_NONE this equality fails because no output is committed at all. Impact: Critical - an operator (or anyone relaying the broadcast tx) can redirect out_amount to an arbitrary script_pubkey while reusing the user's valid signature, moving vault-funded value away from the registered withdrawer, i.e. BTC leaving without a matching fronted withdrawal.
