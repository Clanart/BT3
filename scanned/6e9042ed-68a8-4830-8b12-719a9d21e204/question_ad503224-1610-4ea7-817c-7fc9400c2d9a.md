Target: `Verifier::is_kickoff_malicious` (`core/src/verifier.rs`), which trusts `payout_op_xonly_pk` purely from `Database::get_payout_info_from_move_txid`. Attacker action: broadcast a payout tx identical to the legitimate operator's intended one (same input_outpoint, same output[0] value/script under the user's `SinglePlusAnyoneCanPay` signature) but with the OP_RETURN naming a different, uninvolved registered operator B's xonly_pk. Preconditions: operator A is about to front withdrawal idx N; operator B is a registered, unrelated operator with active collateral. Call sequence: attacker's tx confirms first -> `update_finalized_payouts` stores operator B as payer -> `PayoutCheckerTask::run_once` assigns the handled-payout obligation to B via `get_first_unhandled_payout_by_operator_xonly_pk` -> B's later kickoff passes `is_kickoff_malicious`'s check `operator_xonly_pk != kickoff_data.operator_xonly_pk` (equal, since attacker chose B) -> B reimbursed. Binding: the operator credited for withdrawal N (`payout_payer_operator_xonly_pk`) == the operator whose collateral-backed BTC paid output[0]. Scoped impact: Critical - operator B is reimbursed for a payout it never funded; operator A, if it had actually funded a competing broadcast that loses the race, is permanently unable to be reimbursed. Proof idea: `cargo test` in `core/src/test` constructing two payout txs racing for the same withdrawal UTXO, asserting the DB's credited xonly_pk equals the xonly_pk whose Bitcoin balance decreased by the payout amount.
