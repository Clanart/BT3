Target: `fn update_finalized_payouts` (`core/src/verifier.rs`), whose `operator_xonly_pk` is set to `None` whenever `get_first_op_return_output`/`parse_op_return_data` fails to yield a valid 32-byte key. Attacker action: broadcast a valid S+AP-signed payout tx for a withdrawal, but structure the transaction with zero OP_RETURN outputs (or an OP_RETURN push shorter/longer than 32 bytes), which is trivially possible since the withdrawer's signature never commits to output[1]/output[2]. Preconditions: withdrawal idx registered; no operator has yet fronted it. Call sequence: attacker's malformed-OP_RETURN tx confirms -> `update_finalized_payouts` stores `payout_payer_operator_xonly_pk = NULL` -> `is_kickoff_malicious` later sees `operator_xonly_pk_opt` is `None` and returns `Ok(true)` (assumed malicious) unconditionally for *any* operator who later tries to kick off for this withdrawal, since the check `let Some(operator_xonly_pk) = operator_xonly_pk_opt else { ...; return Ok(true); }` cannot distinguish 'optimistic payout' from 'attacker-griefed attribution'. Binding: `payout_payer_operator_xonly_pk == NULL` implies the payout was an authorised optimistic payout, not an attacker-severed attribution — this equivalence is assumed, never independently verified against a Citrea-side optimistic-payout record. Scoped impact: Critical - an honest operator that actually funded a payout (but whose OP_RETURN got raced/removed by the attacker's own malformed rebroadcast of the same UTXO) is permanently unable to be reimbursed, since `is_kickoff_malicious` forces `Ok(true)` and its kickoff is treated as malicious, leading to challengeable/disprovable/collateral-burn consequences.
