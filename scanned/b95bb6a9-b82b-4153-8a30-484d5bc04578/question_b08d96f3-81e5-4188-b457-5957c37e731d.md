In `core::verifier::Verifier::is_kickoff_malicious`, the Winternitz-committed `truncated_blockhash` (`&payout_blockhash[12..]`, 20 bytes) is compared against `committed_blockhash` extracted from `kickoff_witness` via `extract_winternitz_commits`. Since WOTS commitments are one-time and revealed IN this kickoff witness (an attacker-broadcastable Bitcoin transaction, if they can front-run submitting a competing kickoff spending the same round output before the legitimate operator, since kickoff txs are not access-controlled by anything but which UTXO they spend), can an attacker who observes the FIRST operator's kickoff witness on the mempool extract its committed WOTS blockhash value and reuse/replay it into a SECOND, attacker-broadcast transaction claiming a DIFFERENT `kickoff_data.operator_xonly_pk` while committing the SAME `truncated_blockhash`, breaking HIGH-impact binding: `WOTS preimage revealed by operator X == never usable to construct a valid-looking commitment for operator Y before X's own reveal is final`? Impact: High, leakage of a WOTS commitment usable to forge a claim for another operator before intended reveal, since anyone can read blockchain mempool data. Proof idea: cargo test under core/src/test extracting `extract_winternitz_commits` output from one broadcast kickoff and feeding it into a second kickoff transaction with a different `operator_xonly_pk`, asserting `is_kickoff_malicious` does not detect the reused commitment as belonging to the wrong operator (since it only compares byte equality, not signer identity).
