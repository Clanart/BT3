Can an attacker broadcast a payout transaction that funds output 0 from the attacker's own UTXO but sets the OP_RETURN's xonly_pk to match a currently-operating operator's kickoff_data.operator_xonly_pk, so send_asserts' equality check passes and that operator ends up asserting/kickoffing for a withdrawal it never funded? Binding: payout_op_xonly_pk (OP_RETURN-derived) == kickoff_data.operator_xonly_pk AND == the xonly_pk of whoever's UTXO funded the payout output. Impact: Critical, an operator's kickoff/assert flow (and eventual Reimburse) proceeds for a payout the operator never funded, while the true funding party's contribution is never reconciled.
