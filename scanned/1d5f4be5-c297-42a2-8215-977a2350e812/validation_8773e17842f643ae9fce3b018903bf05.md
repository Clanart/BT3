# Title
Global (non-per-peer) QUIC connection-rate token bucket at the TPU ingest path can be exhausted by a single low-cost unprivileged sender, denying connection acceptance to all other peers — (File: `streamer/src/nonblocking/quic.rs`)

## Summary
The Axelar report describes a *shared, time-replenished capacity* (the 6-hour flow limit) that any single unprivileged actor can drain at the start of every window, blocking all other users until the next refill. The same broken invariant — "one shared token bucket, consumable in full by a single unprivileged actor, gates access for everyone else" — exists in Agave's QUIC connection-acceptance path for the TPU/TPU-forward ports.

## Finding Description
When a new QUIC connection attempt arrives at the validator's TPU QUIC endpoint, the accept loop first checks a single, global `overall_connection_rate_limiter` before any per-IP or per-stake check is applied: [1](#0-0) 

This global limiter is a `TokenBucket` sized by two fixed constants that are not scaled by stake, identity, or per-peer accounting: [2](#0-1) 

`TokenBucket`/`KeyedRateLimiter` (`net-utils/src/token_bucket.rs`) implements exactly the "epoch flow-limit" pattern from the report: a capacity that refills at a fixed rate and is consumed by *any* caller regardless of identity: [3](#0-2) 

The per-IP limiter (`ConnectionRateLimiter`) is checked only *after* the global bucket, and it rate-limits per source `IpAddr`: [4](#0-3) 

Because the global bucket is checked first and is not keyed by IP/stake, its tokens are a single shared resource. The code comment itself acknowledges this class of gap — that the check happens *before a peer has asserted control over their IP address* (i.e., before the QUIC retry/address-validation challenge is completed): [5](#0-4) 

This means an attacker does not need to complete any handshake, hold any stake, or be a "peer" in any trusted sense — they only need to get enough UDP Initial packets to the TPU QUIC socket to be recognized as `incoming` connection attempts. Because the per-IP limiter is evaluated after the global bucket and keyed by (spoofable) source IP, an attacker can spread attempts across many source addresses to avoid ever triggering the per-IP limiter, while still draining the one shared bucket. Once `overall_connection_rate_limiter.current_tokens() == 0`, *every* incoming connection — from any IP, staked or unstaked, honest client or not — is ignored: [6](#0-5) 

This is the direct analog of the Axelar flow-limit bug: a single, shared, refill-on-a-clock capacity that any unprivileged actor can consume, denying the resource (here, QUIC connection acceptance to the transaction-submission port) to everyone else until the bucket refills.

## Impact Explanation
While the bucket refills continuously (unlike the Axelar 6-hour epoch), the sustained/burst parameters (`TOTAL_CONNECTIONS_PER_SECOND = 2500.0`, `MAX_CONNECTION_BURST = 1000`) are trivially achievable by a single unprivileged sender with no stake and no valid identity. Sustaining generation of Initial packets above the refill rate keeps the bucket perpetually empty, causing legitimate TPU connection attempts from staked and unstaked peers alike to be dropped ("Ignoring incoming connection ... due to overall rate limit"). This degrades the validator's ability to accept new transaction-submitting connections — a non-RPC, remote, low-rate-achievable availability/liveness impact on the TPU/QUIC ingest path, matching the class of impact judged Medium in the source report (temporary availability degradation of a core service).

## Likelihood Explanation
Likelihood is high for causing a *localized* dip in connection acceptance to a single validator's TPU port: it requires no stake, no privileged network position, and no protocol-level exploit — only sending UDP QUIC Initial packets at a rate exceeding a few thousand per second, which is inexpensive even on constrained infrastructure. It does not achieve a cluster-wide consensus halt because other validators are unaffected and existing per-peer connection limits (`max_connections_per_unstaked_peer`, `max_connections_per_staked_peer`) and stream throttles still bound sustained per-connection abuse once a connection is admitted — but the global pre-admission gate itself has no such per-peer bound.

## Recommendation
Key the "overall" rate limiter’s effective capacity to something that cannot be exhausted by an unauthenticated/unstaked single actor before IP or stake is asserted — e.g., apply the per-IP limiter (or a lightweight source-IP heuristic) before consuming from the shared bucket, or partition the global budget into staked/unstaked sub-buckets so unstaked, unauthenticated flooding cannot starve staked peers' connection attempts. Consider requiring the QUIC retry/address-validation challenge to be satisfied before any shared-capacity token is charged.

## Proof of Concept
1. From an unprivileged host (no validator identity, no stake), send a sustained stream of QUIC Initial packets to the target validator's TPU QUIC UDP port at a rate above the bucket's `TOTAL_CONNECTIONS_PER_SECOND`/`MAX_CONNECTION_BURST` parameters, rotating source IP/port to stay under the per-IP limiter's threshold (`ConnectionRateLimiter`).
2. Each Initial packet is processed as `incoming` and checked against `overall_connection_rate_limiter.current_tokens()` before per-IP checks: [6](#0-5) .
3. Once the shared bucket's tokens hit zero, all subsequent incoming connections — including from legitimate staked validators/clients — are logged as rate-limited and ignored (`incoming.ignore()`), regardless of their own IP/stake standing.
4. As long as the attacker sustains packet generation above the refill rate, legitimate TPU connection attempts continue to be dropped, producing an availability/liveness degradation for transaction submission to that validator.

Note: I was not able to locate the exact call site that constructs the `overall_connection_rate_limiter` instance (to confirm it is instantiated exactly once per endpoint and never re-partitioned by later code), so some detail of its lifecycle should be verified directly in the repository before treating this as fully confirmed.

use {
    solana_net_utils::token_bucket::{KeyedRateLimiter, TokenBucket},
    std::net::IpAddr,
};

/// Limits the rate of connections per IP address.
pub struct ConnectionRateLimiter {
    limiter: KeyedRateLimiter<IpAddr>,
}

/// The threshold of the size of the connection rate limiter map. When
/// the map size is above this, we will trigger a cleanup of older
/// entries used by past requests.
const CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD: usize = 100_000;

impl ConnectionRateLimiter {
    /// Create a new rate limiter per IpAddr. The rate is specified as the count per minute to allow for
    /// less frequent connections. Higher limit also allows higher bursts.
    /// num_shards controls how many shards are used in the underlying dashmap,
    /// should be set >= number of contending threads.
    pub fn new(limit_per_minute: u64, max_burst: u64, num_shards: usize) -> Self {
        Self {
            limiter: KeyedRateLimiter::new(
                CONNECTION_RATE_LIMITER_CLEANUP_SIZE_THRESHOLD,
                TokenBucket::new(limit_per_minute, max_burst, limit_per_minute as f64 / 60.0),
                num_shards,
            ),
        }
    }

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
