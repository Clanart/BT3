Attacker action: attempt a plaintext (non-TLS) connection attempt is not possible since server still uses TLS identity, but attacker can connect via an unauthenticated TLS client (no client cert offered at all, since server did not request one) and call Withdraw. Preconditions: client_verification=false. Call sequence: TLS handshake succeeds with zero client certs presented -> Noop interceptor -> withdraw executes AggregatorWithdrawalInput fan-out to operators. Binding broken: CALLER_AUTHORITY - caller of withdraw == aggregator's client cert holder; here caller presented no certificate whatsoever, not even a spoofed one. Scoped impact: Critical, operator payout/signing sessions triggered by a certificate-less internet caller, risking ATTRIBUTION violations if any operator credits itself for a withdrawal_id lacking a real fronting payout. Proof idea: cargo test connecting with a tonic Channel configured with no client identity at all against an aggregator started with client_verification=false, asserting withdraw() returns Ok rather than a TLS/authentication error.
