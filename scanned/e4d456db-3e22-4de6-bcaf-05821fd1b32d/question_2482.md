# Q2482: accrue via supply-collateral-add: satisfy the freshness gate with a timestamp the gate was n

## Question
Entering through `supply-collateral-add` (mainnet/contracts/market/v0-4-market.clar:1175) while controlling vault share price at the moment of the deposit leg, can an unprivileged attacker make `accrue` (mainnet/contracts/vault/v0-vault-stx.clar:835) satisfy the freshness gate with a timestamp the gate was never meant to accept? `accrue` advances `last-update` only inside `(if (or (not (is-eq idx next)) ...))`, so an interval whose multiplier rounds to INDEX-PRECISION leaves the clock stale, so the invariant that a position that holds value can always be priced, and therefore always closed would fail, yielding direct theft of another user's collateral.
