Attacker action: submit `BridgeCircuitInput.payout_spv.transaction` Borsh bytes describing a `Transaction` whose fields, when re-encoded, do NOT round-trip to the same bytes a real Bitcoin node would produce for the mined transaction (e.g. non-canonical script length encodings) while still hashing to the same `mid_state_txid` used in the inclusion proof. Preconditions: `BridgeCircuitInput` accepted from the host without independent Bitcoin-consensus re-validation. Call sequence: `guest.read_from_host()` -> `CircuitTransaction::deserialize_reader` -> `SPV::verify`. Binding: the deserialized `CircuitTransaction` == the exact transaction bytes mined in the block whose header the header-chain proof committed to. Impact: Critical if any output/witness content later trusted by `deposit_constant`/`journal_hash` diverges from what was truly mined. Proof idea: cargo test round-tripping a crafted `CircuitTransaction` through `borsh::to_vec`/`borsh::from_slice`, then independently reconstructing it via `bitcoin::consensus::deserialize` on the real mined block bytes, asserting `mid_state_txid()` equality does not imply full-transaction equality when witness/script encoding is manipulated.
