## Title
Attacker-selectable `before` signature forces full historical block reconstruction on every `getSignaturesForAddress` call - (File: `ledger/src/blockstore.rs`)

### Summary
`Blockstore::get_confirmed_signatures_for_address2` resolves the `before` (and `until`) signature to a slot and then calls `get_block_signatures_rev`, which fully reconstructs the entire block via `get_complete_block` merely to recover signature ordering. Because callers fully control the `before` signature, they can always target the largest rooted block in ledger history, making the per-call CPU/IO cost of this single unprivileged RPC method proportional to that block's size rather than to the requested `limit`.

### Finding Description
`get_confirmed_signatures_for_address2` first looks up the slot of the `before` signature, then calls `self.get_block_signatures_rev(slot)` to get signature ordering within that slot: [1](#0-0) 

`get_block_signatures_rev` obtains this ordering by calling `get_complete_block(slot, false)` — i.e., it deshreds and reconstructs the *entire* block (all entries, all transactions) just to extract the reversed list of first signatures: [2](#0-1) 

The same reconstruction is repeated for the `until` signature if supplied: [3](#0-2) 

There is no size cap, no caching, and no cost accounting tied to the size of the historical block being referenced by `before`/`until`. Since a rooted block's signature and slot are public information (any client that previously queried the chain, or that simply scans blocks, can learn the signature of a transaction in the largest historical block), an attacker can deterministically choose a `before` value whose slot corresponds to the largest block ever produced. The per-request cost of `get_confirmed_signatures_for_address2` is then bounded not by `limit` but by the size of that arbitrary historical block, which is attacker-selectable and can be repeated on every call.

### Impact Explanation
This falls into the "single-client low-rate RPC crash/degradation" category: a single, unprivileged client sending a normal rate of `getSignaturesForAddress` requests (each within any per-connection/per-IP rate limit) can force the validator to repeatedly perform disproportionately expensive full-block deshred/reconstruction work, since the cost of each call is decoupled from `limit` and instead tied to a `before` slot the caller chooses. Repeated calls degrade RPC-serving latency/CPU without needing a high request rate, unlike normal RPC costs that scale with the response size (`limit`).

### Likelihood Explanation
Likelihood is moderate-to-high: exploitation requires no privileges beyond normal RPC access, only knowledge of a signature within a large historical rooted block (trivially obtainable from any public block explorer or by scanning blocks once). The code path is reached on every call that supplies a `before` (or `until`) parameter, which is a documented, commonly-used parameter of the `getSignaturesForAddress` RPC method.

### Recommendation
Avoid reconstructing full blocks solely to recover signature ordering for `before`/`until` resolution. Options include: maintaining a lightweight per-slot signature-order index (already partially available via `address_signatures_cf`/`transaction_status_cf` keys, which include per-slot ordering) instead of calling `get_complete_block`; capping/caching per-slot signature-order lookups; or applying resource accounting that reflects the size of the referenced block in RPC rate limiting rather than only the response `limit`.

### Proof of Concept
1. Identify (or record ahead of time) a transaction signature contained in one of the largest rooted blocks in the ledger (e.g., a mainnet block with the maximum transaction count).
2. Call `getSignaturesForAddress` with `before` set to that signature and observe server-side latency/CPU for the call — it will trigger `get_complete_block` on that large block via `get_block_signatures_rev`.
3. Repeat the same call, replacing `before` with a signature from a small block (few transactions), and compare latency/CPU.
4. The disparity demonstrates that per-call cost is dictated by the attacker-chosen `before` block size rather than by `limit`, independent of any per-client rate limiting on call frequency. [4](#0-3)

    fn get_block_signatures_rev(&self, slot: Slot) -> Result<Vec<Signature>> {
        let block = self.get_complete_block(slot, false).map_err(|err| {
            BlockstoreError::Io(IoError::other(format!("Unable to get block: {err}")))
        })?;

        Ok(block
            .transactions
            .into_iter()
            .rev()
            .filter_map(|transaction_with_meta| {
                transaction_with_meta
                    .transaction
                    .signatures
                    .into_iter()
                    .next()
            })
            .collect())
    }

    pub fn get_confirmed_signatures_for_address2(
        &self,
        address: Pubkey,
        highest_slot: Slot, // highest_super_majority_root or highest_confirmed_slot
        before: Option<Signature>,
        until: Option<Signature>,
        limit: usize,
    ) -> Result<SignatureInfosForAddress> {
        let max_root = self.max_root();
        let confirmed_unrooted_slots: HashSet<_> =
            AncestorIterator::new_inclusive(highest_slot, self)
                .take_while(|&slot| slot > max_root)
                .collect();

        // Figure the `slot` to start listing signatures at, based on the ledger location of the
        // `before` signature if present.  Also generate a HashSet of signatures that should
        // be excluded from the results.
        let mut get_before_slot_timer = Measure::start("get_before_slot_timer");
        let (slot, mut before_excluded_signatures) = match before {
            None => (highest_slot, None),
            Some(before) => {
                let transaction_status =
                    self.get_transaction_status(before, &confirmed_unrooted_slots)?;
                match transaction_status {
                    None => return Ok(SignatureInfosForAddress::default()),
                    Some((slot, _)) => {
                        let mut slot_signatures = self.get_block_signatures_rev(slot)?;
                        if let Some(pos) = slot_signatures.iter().position(|&x| x == before) {
                            slot_signatures.truncate(pos + 1);
                        }

                        (
                            slot,
                            Some(slot_signatures.into_iter().collect::<HashSet<_>>()),
                        )
                    }
                }
            }
        };
        get_before_slot_timer.stop();
