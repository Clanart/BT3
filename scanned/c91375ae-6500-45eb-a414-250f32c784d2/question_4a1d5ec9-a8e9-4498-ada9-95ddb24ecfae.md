Target: `MMRGuest::verify_proof` (circuits-lib/src/header_chain/mmr_guest.rs) called from `SPV::verify`. Attacker action: submit an `MMRInclusionProof` whose `subroot_idx` points to a valid-looking subroot in `mmr_guest.subroots` that was NOT committed by the header-chain proof's actual `chain_state.block_hashes_mmr`, i.e., reuse a subroot computed from a different (attacker-chosen) sequence of block hashes that happens to sit at the same index length. Preconditions: attacker needs no key; only needs to submit a `BridgeCircuitInput.hcp` whose `chain_state.block_hashes_mmr` was itself derived from real headers (so `guest.verify` on the HCP succeeds) but crafts `payout_spv.mmr_inclusion_proof.subroot_idx`/`internal_idx` to select a subroot slot the real chain never used for that block. Call sequence: `bridge_circuit` -> `let mmr = input.hcp.chain_state.block_hashes_mmr.clone()` -> `input.payout_spv.verify(mmr)` -> `MMRGuest::verify_proof(block_hash, mmr_proof)` -> `self.subroots.get(subroot_idx) == Some(&current_hash)`. Binding: the `block_hash` recomputed from `block_header.compute_block_hash()` and proof path == the subroot the header-chain proof actually committed at `subroot_idx` for that specific block height. Impact: Critical - a block header never part of the canonical MMR sequence is accepted as included, letting a forged/never-mined block back a false journal_hash. Proof idea: cargo test in circuits-lib building two different `MMRNative` sequences, taking a subroot from one and an `internal_idx` path from generating a proof against the other at a colliding index, and asserting whether `MMRGuest::verify_proof` incorrectly returns true.
