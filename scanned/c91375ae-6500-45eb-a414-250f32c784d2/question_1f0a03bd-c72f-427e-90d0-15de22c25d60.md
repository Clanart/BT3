Target: `CircuitTransaction::mid_state_txid` (circuits-lib/src/bridge_circuit/transaction.rs) which hashes only `version`, `input`, `output`, `lock_time` with `consensus_encode`, omitting witness data entirely. Attacker action: broadcast a payout transaction `payout_tx_A` with witness `W1`, then present to the bridge circuit a `CircuitTransaction` wrapping the same non-witness fields but a different witness `W2` (e.g., a different Schnorr signature over the same sighash message, or garbage witness bytes) as `payout_spv.transaction`. Preconditions: attacker only needs to control the witness field of the proof-carrying transaction bytes fed to the bridge-circuit host, not a signing key. Call sequence: `SPV::verify` computes `mid_state_txid` ignoring witness -> matches the block's true mid-state leaf for `payout_tx_A` -> proof accepted for `payout_tx_B` (different witness) as if it were `payout_tx_A`. Binding: `payout_spv.transaction` (full transaction incl. witness) == the transaction actually broadcast and mined at `payout_input_index`'s referenced position. Impact: Critical - a transaction with a witness that was never validated on-chain (e.g., different signature) is treated as the proven payout, potentially crediting an operator for a payout it structured differently than what was mined. Proof idea: cargo test in circuits-lib constructing two `CircuitTransaction`s differing only in witness, asserting `mid_state_txid()` is equal for both, then showing `SPV::verify` accepts either interchangeably against the same block inclusion proof.
