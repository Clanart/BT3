# Q5024: get-cached-indexes via liquidate: make a required price path abort so the position can no lo

## Question
Does `liquidate` (mainnet/contracts/market/v0-4-market.clar:1382) let an unprivileged attacker who controls `borrower`, any third-party principal reach `get-cached-indexes` (mainnet/contracts/market/v0-4-market.clar:944) in a state where it make a required price path abort so the position can no longer be closed or seized? Given that it reads the per-block cache entry that `resolve-ztoken` and the debt conversions depend on, the invariant that every price is attached to the asset it was resolved for, and each asset enters the totals exactly once breaks and the result is protocol insolvency.

- Entrypoint: `liquidate` (`mainnet/contracts/market/v0-4-market.clar:1382`), unprivileged and publicly callable

- Invariant to test: every price is attached to the asset it was resolved for, and each asset enters the totals exactly once
- Expected Immunefi impact: Critical - protocol insolvency
- Fast validation: Write a Clarinet simnet test calling `liquidate` twice with `borrower`, any third-party principal varied, and assert that the value `get-cached-indexes` returns is identical in both runs; a divergence confirms the finding.
