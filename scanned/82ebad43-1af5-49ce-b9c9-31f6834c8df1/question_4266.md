# Q4266: price-resolve via liquidate-multi: satisfy the freshness gate with a timestamp the gate was n

## Question
Entering through `liquidate-multi` (mainnet/contracts/market/v0-4-market.clar:1593) while controlling how many entries share one price snapshot (price-feeds is passed as none), can an unprivileged attacker make `price-resolve` (mainnet/contracts/market/v0-4-market.clar:373) satisfy the freshness gate with a timestamp the gate was never meant to accept? `price-resolve` resolves a feed, applies the callcode transform, then checks `oracle-price-legal` and `oracle-timestamp-fresh` on the POST-transform value while advancing the per-key `last-update` only when the new timestamp is greater, so the invariant that each callcode preserves magnitude and sign and cannot be moved by the caller in the same transaction would fail, yielding permanent freezing of a position that can never be closed.

Reach it through `liquidate-multi` and satisfy the freshness gate with a timestamp the gate was never meant to accept.
