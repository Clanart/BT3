[Target: TxSenderClient::insert_try_to_send, kickoff-tx queueing] When an operator queues a Kickoff transaction via insert_try_to_send, nothing in this function cross-checks the kickoff's Winternitz-committed payout_blockhash (extract_winternitz_commits) against the payout_tx_blockhash actually stored for the withdrawal in the DB before persisting signed_tx. Precondition: attacker cannot forge WOTS commits directly, but can shape the payout tx's confirming block via a reorg-adjacent broadcast so the committed 20-byte truncated blockhash momentarily matches a different, attacker-preferred block than the one is_kickoff_malicious will later check. Call sequence: insert_try_to_send accepts the kickoff tx unconditionally -> later is_kickoff_malicious re-derives correctness only at challenge time, not at insertion time. Binding broken: SLASHING_TRUTH - the blockhash committed via WOTS at Kickoff broadcast time == the blockhash of the block that actually confirmed the payout, checked before commitment is irreversible, not only after. Impact: Critical, if the reorg/blockhash divergence is exploited between insertion and the later malicious-check, an operator could become permanently challengeable/disprovable, burning honest collateral, or a dishonest committed value could pass. Proof idea: cargo test under core/src/test inserting a kickoff signed_tx via insert_try_to_send while payout_tx_blockhash in the DB is later updated by a reorg, then asserting is_kickoff_malicious's committed_blockhash comparison diverges from what was accepted at insertion time.
