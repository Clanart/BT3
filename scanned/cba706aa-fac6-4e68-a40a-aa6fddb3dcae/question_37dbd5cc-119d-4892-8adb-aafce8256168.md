[Target: TxSenderClient::insert_try_to_send] insert_try_to_send never inspects tx_metadata.tx_type against the actual semantic content of signed_tx (e.g., a Reimburse-typed metadata tag can be attached to a transaction whose second output does not equal move_txhandler.get_spendable_output(UtxoVout::DepositInMove)'s value). Attacker precondition: none beyond an existing deposit/round; the caller (operator software) can be induced, via attacker-crafted storage_proof.index or payout_input_index mismatches upstream, to build a mis-valued reimburse tx. Call sequence: create_reimburse_txhandler -> insert_try_to_send(tx_metadata=Some(Reimburse), signed_tx, ...) -> save_tx persists it verbatim. Binding broken: CUSTODY - the amount paid out of the move-to-vault UTXO == move_txhandler.get_spendable_output(UtxoVout::DepositInMove).get_prevout().value, not independently re-checked by insert_try_to_send. Impact: Critical, BTC could leave the vault UTXO in an amount untied to the deposit it claims to reimburse. Proof idea: cargo test under core/src/test building a reimburse tx with an inflated output value, passing it to insert_try_to_send, and asserting no error is raised though value != deposit amount.
