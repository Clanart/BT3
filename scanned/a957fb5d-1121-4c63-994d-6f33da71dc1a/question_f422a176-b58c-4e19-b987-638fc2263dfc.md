Attacker action: after a deposit's move tx has already been broadcast via `SendMoveToVaultTx`, an unauthenticated caller replays `NewDeposit(Deposit)` for the *same* `deposit_outpoint`, driving verifiers into a second full MuSig2 signing session for a second move tx. Preconditions: `client_verification=false`; deposit UTXO is already spent by the first move tx but the deposit outpoint bytes are unchanged in the replayed request. Call sequence: `new_deposit` -> verifier nonce/sign/finalize pipeline runs again with no on-chain-spent check at this layer (the double-deposit test shows two movetxs can be produced) -> unauthenticated caller can then race `send_move_to_vault_tx` with the second signed tx. Binding: MINT_AUTHORITY — a move txid the verifiers presign == one *unspent* `bridge_amount` deposit output; violated if verifiers keep re-signing for an already-spent outpoint. Impact: Critical, N-of-N partial signatures produced for a spend that cannot correspond to any actual unspent deposit, wasting verifier state and potentially enabling a race that diverts value if the second movetx has a different destination encoding than the first.
