[Target: core/src/rpc/interceptors.rs is_internal, only_aggregator_and_self] The AddMethodMiddlewareLayer injects the grpc-method header consumed by is_internal to distinguish Internal* RPCs (InternalSendTx, InternalGetEmergencyStopTx) from public ones. Under Noop this distinction is never evaluated. Can an attacker, without ever satisfying is_internal's leaf_cert == our_cert branch, call InternalSendTx and get treated identically to a call from AggregatorServer's own self-client? Binding: is_internal(req) && leaf_cert==our_cert == true is required for Internal* methods to succeed; with Noop the left side of that equality is never computed, so it trivially 'succeeds' for anyone. Impact: Critical, an attacker gains parity with the entity's own internal automation client for broadcasting transactions via tx_sender. Proof: cargo test asserting that with client_verification=false a request carrying no grpc-method self-cert still reaches AggregatorServer::internal_send_tx and inserts a transaction into the tx_sender queue.
