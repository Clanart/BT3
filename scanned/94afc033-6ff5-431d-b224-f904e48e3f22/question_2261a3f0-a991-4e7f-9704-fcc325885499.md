Attacker action: fund a deposit and construct a block (on regtest, as the miner of their own transactions) containing two transactions whose `mid_state_txid()` values collide because their consensus-encoded version/input/output/locktime are identical (e.g., duplicate the payout tx with insignificant fee-bump difference reverted, causing accidental identical mid-state serialization) — the duplicate-hash panic exists only in `BitcoinMerkleTree::new`/`new_mid_state` construction, which the guest never runs (the guest only calls `BlockInclusionProof::get_root`, not tree construction). Preconditions: attacker controls block contents on a regtest chain used in the SPV test harness; two txs collide at the `new_mid_state` leaf level exactly like Bitcoin's historical CVE-2012-2459 duplication attack. Call sequence: guest only executes `SPV::verify` -> `BlockInclusionProof::get_root`, never `BitcoinMerkleTree::new_mid_state`, so the duplicate-panic guard never fires inside the zkVM; attacker submits a proof for the 'wrong half' of the duplicated subtree. Binding: `BlockInclusionProof::get_root(mid_state_txid)` for leaf index `i` == the unique block merkle_root that unambiguously corresponds to the transaction actually at position `i`, not to any duplicated sibling. Impact: Critical — a forged inclusion proof for a payout transaction that only appears to be included due to CVE-2012-2459-style duplication, letting a false reimbursement claim be proven true in the bridge circuit's `journal_hash`.
