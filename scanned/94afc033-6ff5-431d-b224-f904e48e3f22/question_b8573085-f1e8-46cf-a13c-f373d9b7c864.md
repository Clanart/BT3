target: `SPV::verify` (circuits-lib/src/bridge_circuit/spv.rs). Attacker action: broadcast a real Bitcoin tx `T_real` in block `B_real`, then submit a `BridgeCircuitInput.payout_spv` whose `SPV.transaction` is `T_real` but whose `SPV.block_header` is a *different* header `B_fake` (attacker-chosen `CircuitBlockHeader` bytes with a `merkle_root` recomputed so `BlockInclusionProof::get_root(mid_state_txid)` matches), while `mmr_inclusion_proof` is a real proof that `B_fake`'s hash sits in the MMR the header chain committed. Preconditions: existing kickoff/payout round, attacker only needs the two headers to differ while both have MMR membership (e.g. two blocks from an alternate fork the guest's `hcp` never actually connects to canonical work). Call sequence: `SPV::verify` -> `mid_state_txid = self.transaction.mid_state_txid()` -> `block_merkle_root = self.block_inclusion_proof.get_root(mid_state_txid)` -> compare to `self.block_header.merkle_root` -> `MMRGuest::verify_proof(block_hash, mmr_inclusion_proof)`. Binding: `self.block_header.compute_block_hash()` == the block hash whose txid membership the header-chain circuit actually proved for `mid_state_txid`. Impact: Critical — an operator can be reimbursed (`Operator::withdraw`/bridge circuit `journal_hash`) for a payout that is credited against a block never containing that payout, letting the bridge circuit accept a false claim and burn or spare collateral incorrectly. Proof idea: `cargo test` in `circuits-lib/src/bridge_circuit/spv.rs` constructing two headers with colliding merkle roots via `BitcoinMerkleTree::new_mid_state` and asserting `SPV::verify` returns true only when `block_header` equals the header that actually contains `transaction`.
