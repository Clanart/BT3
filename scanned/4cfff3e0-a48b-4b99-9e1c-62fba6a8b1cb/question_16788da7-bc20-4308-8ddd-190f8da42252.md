`Operator::withdraw`'s `SECP.verify_schnorr` (core/src/operator.rs:632-637) only authenticates `in_signature` over `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)`, i.e., input 0 under `SinglePlusAnyoneCanPay`. Because this sighash type by BIP-341 definition excludes all outputs except output 0, can any unprivileged party who obtains a valid `(in_signature, in_outpoint)` pair for a withdrawal (e.g., by observing it on Citrea or from a broadcast payout tx) construct their own `create_payout_txhandler` call with an arbitrary `operator_xonly_pk` of their choosing (not necessarily any real operator) and get `set_p2tr_key_spend_witness` to succeed, since the witness only needs to satisfy the same sighash? Binding: the `operator_xonly_pk` embedded in the payout tx's OP_RETURN == the xonly pk of the party whose collateral is at risk for this withdrawal, must be a currently-registered operator whose funds paid `out_amount`. Impact: Critical — allows an attacker to place a fabricated OP_RETURN naming a completely unrelated (possibly nonexistent) key, so `update_finalized_payouts` stores an `operator_xonly_pk` that resolves to no operator or the wrong operator, permanently orphaning the honest fronting operator's reimbursement path.
