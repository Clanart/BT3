## Title
`DynamicPacketToProcessThreshold` can latch at `0` and never recover, permanently dropping all repair-response packets - (File: `core/src/repair/packet_threshold.rs`)

### Summary
The Velodrome `Minter.nudge()` bug is a boundary-adjustment routine that, once it reaches a limit, becomes permanently unable to update because the guard logic treats the boundary as a hard stop rather than a saturating clamp. `DynamicPacketToProcessThreshold::update` in Agave implements the same class of self-adjusting boundary value (`max_packets`), used to decide whether to drop incoming ancestor-hashes/block-id repair-response packets under load, but it never clamps the value away from `0`, so integer-division decay can drive it to `0` and it will stay there forever, causing every future packet to be dropped permanently.

### Finding Description
`DynamicPacketToProcessThreshold::update` adjusts `max_packets` up or down using integer arithmetic with no lower bound: [1](#0-0) 

- `Increase`: `current * 100 / 90`
- `Decrease`: `current * 90 / 100`

Both branches use `saturating_mul`/`saturating_div`, which prevents overflow but does nothing to prevent the value from reaching `0` through repeated integer-truncating decreases (e.g. `1 * 90 / 100 = 0`). Once `max_packets == 0`:
- `Increase.calculate(0) = 0 * 100 / 90 = 0`
- `Decrease.calculate(0) = 0 * 90 / 100 = 0`

Both branches are fixed points at `0` — there is no code path that can ever push the value back above `0`. `update()` only mutates `max_packets` when `total_packets >= self.max_packets` (`update` in `core/src/repair/packet_threshold.rs`), so once `max_packets` is `0`, this condition is satisfied by any nonzero packet count, and `should_drop` (`total >= self.max_packets`) returns `true` for essentially every call thereafter: [2](#0-1) 

This directly parallels the reported bug class: a bidirectional boundary-adjustment mechanism that gets "stuck" once it touches a limit and can never self-correct, exactly as `nudge()` got stuck once `oldRate` hit `MAX_RATE`/`MINIMUM_TAIL_RATE`.

`DynamicPacketToProcessThreshold` is used to gate processing of `AncestorHashesResponse` and block-id repair-response packets: [3](#0-2) [4](#0-3) 

### Impact Explanation
If `max_packets` decays to `0` (which requires a sustained period where processing time consistently exceeds the 1-second `TIME_THRESHOLD` while packet volume stays at or above the current threshold — plausible under normal network/load conditions, not just malicious ones), the validator's ancestor-hashes/block-id repair-response ingestion path will begin dropping essentially all incoming repair-response packets indefinitely. Because the threshold can never increase again from `0`, this is a **permanent, self-inflicted denial-of-service** on the node's repair subsystem: the validator can no longer receive ancestor-hashes duplicate-slot repair responses or block-id repair responses, degrading its ability to resolve forks/duplicates and to catch up via repair, until process restart resets the in-memory threshold.

### Likelihood Explanation
Likelihood is moderate: reaching `max_packets == 0` requires several consecutive decrease events (each ~10% reduction, so it takes many rounds to reach a value where truncation collapses to `0` from `1`), which is plausible on an overloaded or resource-constrained validator under sustained repair traffic and slow processing — no attacker collusion or malicious peer/leader assumption is required, only ordinary load conditions triggering repeated `Decrease` updates via `update()`.

### Recommendation
Clamp `max_packets` with an explicit floor (and reasonable ceiling), e.g.:
```rust
self.max_packets = threshold_update.calculate(self.max_packets).max(MIN_PACKETS_THRESHOLD);
```
mirroring the fix pattern used in the reported analog (cap increases at a max, cap decreases at a min so the value never gets permanently stuck at a fixed point), ensuring the threshold can always recover once conditions improve.

### Proof of Concept
1. Repeatedly call `DynamicPacketToProcessThreshold::update(total_packets, compute_time)` with `total_packets >= max_packets` and `compute_time > Duration::from_secs(1)` to force consecutive `Decrease` updates.
2. Each call computes `max_packets = max_packets * 90 / 100` (integer truncation), e.g. `1024 -> 921 -> ... -> 1 -> 0`.
3. Once `max_packets == 0`, any further call to `update` with `total_packets >= 0` will compute `0 * 100/90 = 0` or `0 * 90/100 = 0`, leaving `max_packets` at `0` permanently.
4. `should_drop(total)` now returns `true` for any `total >= 0`, meaning all subsequent ancestor-hashes/block-id repair-response packets are dropped for the lifetime of the process, with no recovery path. [5](#0-4)

```rust
use std::time::Duration;

enum PacketThresholdUpdate {
    Increase,
    Decrease,
}

impl PacketThresholdUpdate {
    const PERCENTAGE: usize = 90;

    fn calculate(&self, current: usize) -> usize {
        match *self {
            PacketThresholdUpdate::Increase => {
                current.saturating_mul(100).saturating_div(Self::PERCENTAGE)
            }
            PacketThresholdUpdate::Decrease => {
                current.saturating_mul(Self::PERCENTAGE).saturating_div(100)
            }
        }
    }
}

#[derive(Debug)]
pub struct DynamicPacketToProcessThreshold {
    max_packets: usize,
}

impl Default for DynamicPacketToProcessThreshold {
    fn default() -> Self {
        Self {
            max_packets: Self::DEFAULT_MAX_PACKETS,
        }
    }
}

impl DynamicPacketToProcessThreshold {
    const DEFAULT_MAX_PACKETS: usize = 1024;
    const TIME_THRESHOLD: Duration = Duration::from_secs(1);

    pub fn update(&mut self, total_packets: usize, compute_time: Duration) {
        if total_packets >= self.max_packets {
            let threshold_update = if compute_time > Self::TIME_THRESHOLD {
                PacketThresholdUpdate::Decrease
            } else {
                PacketThresholdUpdate::Increase
            };
            self.max_packets = threshold_update.calculate(self.max_packets);
        }
    }

    pub fn should_drop(&self, total: usize) -> bool {
        total >= self.max_packets
    }
}
```
