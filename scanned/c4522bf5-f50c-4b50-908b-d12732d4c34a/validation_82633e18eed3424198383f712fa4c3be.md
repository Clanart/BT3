### Title
Vote program `authorize()` permits setting `authorized_withdrawer` to `Pubkey::default()`, permanently locking vote account lamports - (File: `programs/vote/src/vote_state/mod.rs`)

### Summary
The external report's bug class is "an address field is written without checking it is non-zero, causing funds tied to that address to become permanently unrecoverable." The direct Agave analog is the `VoteAuthorize::Withdrawer` branch of the `authorize()` function in the vote program, which writes an attacker/caller-supplied `Pubkey` into `authorized_withdrawer` state with no validation that the pubkey is non-default.

### Finding Description
`authorize()` handles all three `VoteAuthorize` variants (Voter, Withdrawer, VoterWithBLS). For `Withdrawer`, after checking that the *current* `authorized_withdrawer` signed the instruction, it unconditionally stores the new pubkey with no sanity check: [1](#0-0) 

```
VoteAuthorize::Withdrawer => {
    // current authorized withdrawer must say "yay"
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;
    vote_state.set_authorized_withdrawer(*authorized);
}
```

There is no check that `*authorized != Pubkey::default()` (or any other unspendable/burn address) before it is committed via `vote_state.set_vote_account_state(vote_account)` at the end of the function: [2](#0-1) 

`Pubkey::default()` (all-zero bytes) is not a public key that can be produced from a valid Ed25519 private key, so a transaction can never be signed by it. Once `authorized_withdrawer` is set to `Pubkey::default()`, the `Withdraw` instruction handler (which requires `authorized_withdrawer` to be a signer via the same `verify_authorized_signer` check pattern used above) can never again be satisfied — the vote account's lamports above the rent-exempt minimum become permanently frozen in the account, an irreversible fund-loss condition identical in nature to the RealityCards report ("if the value of an address variable turns out to be zero, funds will be lost").

### Impact Explanation
Any lamports held in the vote account above the rent-exempt reserve (validator commission/reward accumulation before withdrawal) become permanently unwithdrawable once `authorized_withdrawer` is set to the zero pubkey, since no key can produce a valid signature for `Pubkey::default()`. This is a direct,  unprivileged fund-loss vector: a vote account owner can be socially engineered or tricked into authorizing a zero pubkey as the new withdrawer, or a malicious authorized_withdrawer can deliberately set it to zero to lock out the original owner.

### Likelihood Explanation
The vulnerability is reachable by any unprivileged transaction that:
1. Holds a valid vote account in a writable state
2. Provides the current `authorized_withdrawer` as a signer
3. Calls `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)`

No special privileges, malicious peers, or leaked keys are required — only the legitimate authority's signature and a deliberate (or accidental) choice of zero pubkey. The runtime will accept and commit the transaction.

### Recommendation
Add a check in the `VoteAuthorize::Withdrawer` branch to reject `Pubkey::default()` (and optionally other known unspendable addresses):

```rust
VoteAuthorize::Withdrawer => {
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;
    if *authorized == Pubkey::default() {
        return Err(InstructionError::InvalidArgument);
    }
    vote_state.set_authorized_withdrawer(*authorized);
}
```

The same check should be applied to `VoteAuthorize::Voter` and `VoteAuthorize::VoterWithBLS` for consistency, since setting either to zero would similarly lock the vote account from future authorized updates.

### Proof of Concept
1. Create a vote account with `authorized_withdrawer = keypair_A.pubkey()`
2. Sign and submit a transaction with instruction `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)` signed by `keypair_A`
3. Observe that the vote account's `authorized_withdrawer` is now `Pubkey::default()`
4. Attempt to withdraw lamports via `Withdraw` instruction signed by any key — will fail because no key can sign for `Pubkey::default()`
5. Lamports above rent-exempt reserve are now permanently locked in the vote account [3](#0-2)

/// Authorize the given pubkey to withdraw or sign votes. This may be called multiple times,
/// but will implicitly withdraw authorization from the previously authorized
/// key
pub fn authorize<S: std::hash::BuildHasher, F>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    authorized: &Pubkey,
    vote_authorize: VoteAuthorize,
    signers: &HashSet<Pubkey, S>,
    clock: &Clock,
    is_vote_authorize_with_bls_enabled: bool,
    consume_pop_compute_units: F,
) -> Result<(), InstructionError>
where
    F: FnOnce() -> Result<(), InstructionError>,
{
    let mut vote_state = get_vote_state_handler_checked(vote_account, target_version)?;

    match vote_authorize {
        VoteAuthorize::Voter => {
            if is_vote_authorize_with_bls_enabled && vote_state.has_bls_pubkey() {
                return Err(InstructionError::InvalidInstructionData);
            }
            let authorized_withdrawer_signer =
                verify_authorized_signer(vote_state.authorized_withdrawer(), signers).is_ok();

            vote_state.set_new_authorized_voter(
                authorized,
                clock.epoch,
                clock
                    .leader_schedule_epoch
                    .checked_add(1)
                    .ok_or(InstructionError::InvalidAccountData)?,
                None,
                |epoch_authorized_voter| {
                    // current authorized withdrawer or authorized voter must say "yay"
                    if authorized_withdrawer_signer {
                        Ok(())
                    } else {
                        verify_authorized_signer(&epoch_authorized_voter, signers)
                    }
                },
            )?;
        }
        VoteAuthorize::Withdrawer => {
            // current authorized withdrawer must say "yay"
            verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;
            vote_state.set_authorized_withdrawer(*authorized);
        }
        VoteAuthorize::VoterWithBLS(args) => {
            if !is_vote_authorize_with_bls_enabled {
                return Err(InstructionError::InvalidInstructionData);
            }
            let authorized_withdrawer_signer =
                verify_authorized_signer(vote_state.authorized_withdrawer(), signers).is_ok();

            verify_bls_proof_of_possession(
                vote_account.get_key(),
                &args.bls_pubkey,
                &args.bls_proof_of_possession,
                consume_pop_compute_units,
            )?;

            vote_state.set_new_authorized_voter(
                authorized,
                clock.epoch,
                clock
                    .leader_schedule_epoch
                    .checked_add(1)
                    .ok_or(InstructionError::InvalidAccountData)?,
                Some(&args.bls_pubkey),
                |epoch_authorized_voter| {
                    // current authorized withdrawer or authorized voter must say "yay"
                    if authorized_withdrawer_signer {
                        Ok(())
                    } else {
                        verify_authorized_signer(&epoch_authorized_voter, signers)
                    }
                },
            )?;
        }
    }

    vote_state.set_vote_account_state(vote_account)
}
