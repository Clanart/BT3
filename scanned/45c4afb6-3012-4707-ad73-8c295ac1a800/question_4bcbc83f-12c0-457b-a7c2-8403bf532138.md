Target: `Verifier::sign_optimistic_payout`'s use of `musig2::partial_sign` with an aggregator-supplied `agg_nonce` versus each verifier's own `PublicNonce` never being cross-checked against the aggregate. Attacker action: an unprivileged caller, acting as the client of the public aggregator gRPC, submits an `agg_nonce` for the optimistic-payout MuSig2 round that was NOT honestly aggregated from all verifiers' `PublicNonce`s returned by their respective `nonce_gen`/session (e.g. an aggregate nonce the caller computed from only their own captured public nonce components, or a nonce reused from a prior, different aggregate round for the same verifier set). Preconditions: verifier's `sign_optimistic_payout` (and `deposit_sign`/`deposit_finalize`) trust whatever `agg_nonce` arrives on the channel without verifying it was derived from the specific `PublicNonce`s that verifier itself returned for `session_id`. Call sequence: `musig2::partial_sign(verifiers_public_keys, None, nonce, agg_nonce, ...)` runs with a mismatched `agg_nonce`, producing a partial signature whose combination with other verifiers' partials under the REAL aggregate nonce may not validate, OR — the critical case — if `agg_nonce` reuse across two different sighash rounds combined with a fixed secnonce (from a stalled session lookup) leaks nonce material via cross-round algebra. Binding: agg_nonce used in `partial_sign` == R_agg(session_id, sighash) actually built from every honest verifier's own `PublicNonce` for that exact sighash. Impact: Critical, verifier secnonce recoverable, since an attacker fully controlling `agg_nonce` for two different sighashes signed by the same secnonce provides two independent nonce/signature equations solvable for the secret nonce (classic ECDSA/Schnorr nonce-reuse key recovery), which combined with the earlier finding that the SAME session_id/secnonce can be reached from two flows (deposit_sign leftover vs. sign_optimistic_payout) completes the attack chain named in this file's Scope. Proof idea: cargo test where the aggregator layer is mocked to feed the SAME secnonce-bearing session two different `agg_nonce`/message pairs (using the prior findings' session-collision mechanism), then run the standard two-signature-same-nonce linear-algebra recovery on the resulting partial signatures and assert it CANNOT recover `self.signer.keypair`'s secret key — if it CAN, that is the Critical finding this file's Scope describes.
