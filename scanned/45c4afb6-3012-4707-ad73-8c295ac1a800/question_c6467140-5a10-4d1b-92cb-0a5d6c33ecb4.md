Target: `Verifier::sign_optimistic_payout`'s sighash construction from caller-supplied `input_outpoint`, `output_script_pubkey`, `output_amount`, `input_signature` (per `core/src/rpc/ecdsa_verification_sig.rs`'s `OptimisticPayoutMessage::new`) versus the actual `create_optimistic_payout_txhandler` sighash used for `musig2::partial_sign`. Attacker action: an unprivileged caller submits an `optimistic_payout` request where the EIP-712-signed `OptimisticPayoutMessage` fields (used only for ECDSA-address verification per the module doc) differ from the ACTUAL bitcoin transaction fields passed into `create_optimistic_payout_txhandler`'s sighash (e.g. same `withdrawal_id` and `input_signature` bytes but a different `output_amount` used to build the taproot spend the verifier ultimately signs). Preconditions: `sign_optimistic_payout` must independently re-derive the Bitcoin sighash from the SAME `output_script_pubkey`/`output_amount` that were EIP-712-verified; if instead the RPC layer passes a separately-parsed set of tx-building parameters that are not cross-checked byte-for-byte against the values fed into `OptimisticPayoutMessage::new`, an attacker can get address-recovery to pass on values A while the actual signed sighash commits to values B. Call sequence: `recover_address_from_ecdsa_signature` succeeds against the aggregator's address using fields A; `session.nonces.pop()` + `musig2::partial_sign` then signs the sighash of a `TxOut{output_amount: B, script_pubkey: B}` differing from A. Binding: fields hashed for `eip712_signing_hash` == fields committed in `move_tx_sighash`/optimistic payout sighash actually signed. Impact: Critical, BTC leaving a move-to-vault UTXO without a matching fronted withdrawal, since the amount actually authorized (per the ECDSA check) differs from the amount actually paid out via the co-signed transaction. Proof idea: cargo test constructing an `optimistic_payout` request with mismatched EIP-712-hashed output_amount vs. transaction-building output_amount, asserting `sign_optimistic_payout` rejects the request rather than partial-signing a sighash for unverified amounts.
