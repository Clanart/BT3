Target: `Operator::withdraw` in core/src/operator.rs, invoked via `ClementineOperator::withdraw` in core/src/rpc/operator.rs. Attacker action: register a Citrea withdrawal and hand the operator a `taproot::Signature` whose `sighash_type` is `TapSighashType::None` instead of the intended `SinglePlusAnyoneCanPay`, alongside a withdrawal UTXO `input_outpoint` and `output_script_pubkey`/`output_amount` chosen by the attacker. Preconditions: a live deposit exists with `bridge_amount` in the move-to-vault UTXO; operator has not yet funded a payout for this withdrawal id; no aggregator_verification_address configured (or attacker also forges the verification path bypass). Call sequence: `withdraw()` -> `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` -> `fund_raw_transaction` adds operator inputs -> operator signs and broadcasts. Binding: the sighash type verified against the user's key == the flag that commits the payout output the operator is reimbursed for; SIGHASH_NONE lets the signature be valid over a tx whose output amount/script the operator (or a third party) can rewrite after computing the sighash. Impact: Critical — operator reimbursed for a payout it never actually funded to the withdrawer, or vault value diverted to fees, since the signature doesn't bind output_script_pubkey/output_amount under SIGHASH_NONE. Proof idea: cargo test in core/src/test asserting the payout tx broadcast after `fund_raw_transaction` still pays exactly `output_amount` to `output_script_pubkey` when `in_signature.sighash_type` is SIGHASH_NONE; show a second tx with attacker-modified outputs is equally valid under the same signature (CUSTODY, ATTRIBUTION).
