Target: `Aggregator::optimistic_payout` in core/src/rpc/aggregator.rs. Attacker action: call the aggregator's public gRPC `OptimisticPayout` with an `input_signature.sighash_type = SIGHASH_NONE` and an `output_amount` set to `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` exactly (the maximum allowed), plus an arbitrary `output_script_pubkey` the attacker controls. Preconditions: `client_verification` interceptor disabled or attacker is any unauthenticated caller since `optimistic_payout` is reachable pre-verification per the described `Interceptors::Noop` default; a deposit exists with an unspent move-to-vault UTXO of `bridge_amount`. Call sequence: `optimistic_payout()` -> `calculate_pubkey_spend_sighash(0, input_signature.sighash_type)` -> verifiers sign via `sign_optimistic_payout` bounding only the amount, not the sighash flag -> N-of-N signature produced and returned to caller. Binding: sighash type verified against user's key == flag committing the payout output; SIGHASH_NONE means the produced N-of-N signature commits to no specific output, so the attacker can attach the aggregated signature to any transaction paying any script the same amount, or a different amount to a different address by feeding a modified template before broadcast. Impact: Critical — N-of-N partial signatures are produced for a spend no Citrea withdrawal actually authorizes (the output_script_pubkey requested from the aggregator need not match what Citrea recorded), letting vault value move to an address the attacker (not the true withdrawer) controls.
