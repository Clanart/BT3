Target: `CircuitTransaction::mid_state_txid` (circuits-lib/src/bridge_circuit/transaction.rs) and `BorshDeserialize for CircuitTransaction`. Attacker action: attacker submits (as host-supplied guest input bytes) a `CircuitTransaction` reconstructed via `deserialize_reader` whose `witness` fields were stripped to empty `Vec<Vec<u8>>` for every `TxIn`, producing a transaction object whose `mid_state_txid()` matches the real mined segwit transaction (since witness is excluded from the hash) but whose reconstructed `Transaction` (used later for `payout_input_index` lookups and `compute_txid`) differs from the one actually broadcast. Preconditions: the real payout transaction is a segwit spend with non-empty witness. Call sequence: `bridge_circuit` reads `BridgeCircuitInput` -> `input.payout_spv.transaction.mid_state_txid()` passes `SPV::verify` against the real block's `merkle_root` -> later `input.payout_spv.transaction.input[payout_input_index].previous_output` is used to assert `user_wd_txid` equality. Binding broken: `payout_spv.transaction` (the exact witness-bearing tx that was mined) == the tx object the circuit reasons about downstream; here `mid_state_txid` equality lets an attacker substitute an object with a different `witness`/`script_sig` while keeping the same mid-state hash. Scoped impact: Critical - the journal_hash and downstream checks operate on attacker-modified transaction fields not the mined tx, letting a false claim (or a manipulated `payout_input_index` lookup) pass proof soundness. Proof idea: cargo test that builds two `CircuitTransaction`s differing only in `witness` bytes, asserts `mid_state_txid()` is identical for both, then feeds the modified one through `SPV::verify` with a real block's MMR/merkle proof and asserts it still returns true.
