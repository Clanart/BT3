Preconditions: attacker can pre-create branches/refs in the shared remote `origin` the repo points to. Call sequence: agent runs `git branch --show-current` -> decides branch name -> `git checkout --branch <name>` -> `git push` to that name. Invariant: push target must be the user-approved new branch/target repo, not one silently reused/collided with attacker-created state. Impact: user's private diff pushed to a branch under attacker observation/control (secret exfiltration via ref collision). Proof idea: integration test pre-creating a same-named remote branch, assert the workflow detects collision and does not silently push over/into attacker-controlled ref.
