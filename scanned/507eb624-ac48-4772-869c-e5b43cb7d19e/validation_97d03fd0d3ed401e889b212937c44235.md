## Analog Found: SigVerify Packet Deduper False-Positive Rejection

### Title
Bloom-filter-style packet `Deduper` in the SigVerify pipeline can be saturated by unsigned packet floods to falsely reject legitimate transactions - (File: `core/src/sigverify.rs`, `core/src/sigverify_stage.rs`, `perf/src/deduper.rs`)

### Summary
The external report describes a Bloom filter used to mark "already redeemed" orders that saturates and produces false positives, silently blocking legitimate, distinct claims. Agave's `Deduper` (`perf/src/deduper.rs`) is a functionally identical structure — a fixed-size bit array with `K` independent hash functions used to mark packets/transactions as "already seen." It is used in the non-vote/TPU-vote packet path in `SigVerifyWorkerPool::run_transaction_task` (`core/src/sigverify.rs`), and it runs *before* signature verification, so an unprivileged sender does not need a valid signature to influence its state.

### Finding Description
`SigVerifyStage::new` allocates two `Deduper<2, [u8]>` instances (`non_vote_deduper`, `tpu_vote_deduper`) sized `DEDUPER_NUM_BITS = 63_999_979` bits, with `DEDUPER_FALSE_POSITIVE_RATE = 0.001` and `MAX_DEDUPER_AGE = 2s`: [1](#0-0) [2](#0-1) 

For every incoming packet batch, `run_transaction_task` calls `deduper::dedup_packets_and_count_discards` **before** any signature is checked: [3](#0-2) 

`Deduper::dedup` hashes the raw packet bytes with `K=2` independent `RandomState` hashers into a shared bit array and returns `true` (duplicate) only if all `K` bit positions were already set; otherwise it sets them and returns `false`: [4](#0-3) 

`dedup_packets_and_count_discards` marks a packet's `meta().discard()` flag when `dedup()` returns true, and once discarded it is dropped from the batch and never reaches signature verification or banking stage: [5](#0-4) 

The filter's own false-positive-rate estimate is purely a function of bit occupancy (`popcount`) relative to `num_bits`, raised to the `K`-th power: [6](#0-5) 

A background servicer thread only resets the filter when it detects saturation *or* when `MAX_DEDUPER_AGE` (2s) elapses, checked on a 10ms tick: [7](#0-6) 

Because `dedup()` is invoked on raw, unauthenticated packet content, any peer able to reach the TPU/non-vote ingestion path can flood it with arbitrary distinct byte sequences (no valid signature, no valid blockhash, no fee-payer required) to drive `popcount` toward the ~2M-item capacity that pushes the estimated false-positive rate over the 0.1% threshold. Once occupancy is high, hash collisions on the `K=2` bit positions will intermittently mark *genuinely distinct, legitimately signed* transaction packets from unrelated unprivileged users as "duplicate," causing them to be silently discarded before signature verification or banking stage even sees them — this is the exact "false positive blocks a legitimate, non-duplicate item" failure mode described in the reference report, just applied to transaction packets instead of reward order IDs.

### Impact Explanation
Legitimate, correctly-signed transactions from unrelated users can be silently dropped at the SigVerify stage without any error surfaced to the client (the packet is discarded before verification, so no `AlreadyProcessed`-style rejection is even returned) — the transaction simply vanishes from that node's protocol path. This does not (by itself) corrupt consensus state, but it is a real degradation of a validator's ability to process legitimate, unprivileged transaction traffic, achievable at low cost since the attacker does not need to be staked, does not need valid signatures, and does not need to spend fees — only enough distinct byte content to occupy bits.

### Likelihood Explanation
The `Deduper` is explicitly designed with a bounded false-positive-rate and periodic reset, and the reset check runs every 10ms, so the design intends to self-heal quickly. This limits (but does not eliminate) the exploitable window: an attacker must sustain a high-rate flood of distinct packets to keep the filter above the saturation threshold continuously. This is comparable in nature, but weaker in severity, than the reported Bloom-filter bug, because Agave's structure includes saturation detection and auto-reset that the vulnerable Solidity contract in the report lacked entirely.

### Recommendation
- Ensure the saturation check/reset cadence is tight enough (and metrics like `num_deduper_saturations` are alerted on) that an attacker cannot maintain saturation for an extended period.
- Consider gating/rate-limiting unauthenticated packet ingestion (e.g., via existing QUIC/stake-weighted connection throttling) before packets reach the Deduper, so that flooding with garbage bytes is not cheaper than legitimate traffic.
- Consider computing the dedup key over a value that is at least partially validated (e.g., after minimal well-formedness checks) rather than raw arbitrary bytes, to raise the cost of generating "novel" filter entries.

### Proof of Concept
Not independently executable from the index alone (would require running the validator with the SigVerify pipeline and a packet generator). The concrete path is:
1. Connect as any unprivileged peer/client able to reach the TPU non-vote packet ingestion path.
2. Send a sustained stream of packets containing arbitrary, syntactically-valid-sized but unsigned/garbage byte payloads (no valid `Ed25519` signature needed since dedup runs first) — see call order in [3](#0-2) .
3. Continue until `Deduper::popcount` (bit occupancy) approaches capacity for `DEDUPER_NUM_BITS = 63_999_979`, `K=2`, per `false_positive_rate()` in [6](#0-5) .
4. Concurrently submit a legitimate, correctly signed transaction from an unrelated keypair; observe it can be marked "duplicate" by `dedup_packets_and_count_discards` and discarded before verification, per [5](#0-4) , even though it is not actually a duplicate.

Existing unit tests already demonstrate the saturation/false-positive mechanics of the same `Deduper` type in isolation: [8](#0-7) .

    // Returns true if the data is duplicate.
    #[must_use]
    #[allow(clippy::arithmetic_side_effects)]
    pub fn dedup(&self, data: &T) -> bool {
        let mut out = true;
        let state = self.state.load();
        for random_state in state.random_states.iter() {
            let hash: u64 = random_state.hash_one(data) % self.num_bits;
            let index = (hash >> 6) as usize;
            let mask: u64 = 1u64 << (hash & 63);
            let old = self.bits[index].fetch_or(mask, Ordering::Relaxed);
            if old & mask == 0u64 {
                self.popcount.fetch_add(1, Ordering::Relaxed);
                out = false;
            }
        }
        out
    }

pub fn dedup_packets_and_count_discards<const K: usize>(
    deduper: &Deduper<K, [u8]>,
    batches: &mut [PacketBatch],
) -> u64 {
    batches
        .iter_mut()
        .flat_map(|batch| batch.iter_mut())
        .map(|mut packet| {
            if !packet.meta().discard()
                && packet
                    .data(..)
                    .map(|data| deduper.dedup(data))
                    .unwrap_or(true)
            {
                packet.meta_mut().set_discard(true);
            }
            u64::from(packet.meta().discard())
        })
        .sum()
}
