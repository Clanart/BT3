Target: `Interceptors::Noop` combined with `AddMethodMiddlewareLayer`'s `grpc-method` header used by `is_internal`. Attacker action: attacker crafts a raw gRPC request that sets its own `grpc-method` metadata header to a value not starting with `Internal`, then calls `InternalSendTx` anyway, exploiting that under `Noop` the `is_internal` classification is never consulted at all (since the whole interceptor is skipped), making the header-spoofing irrelevant to whether the call succeeds - the call succeeds regardless. Preconditions: `client_verification=false`. Call sequence: request bypasses `AddMethodMiddlewareLayer`'s intended purpose entirely because `Noop` never calls `is_internal`; reaches `AggregatorServer::internal_send_tx` directly. Binding: a caller reaching an `Internal`-prefixed method == a party holding `our_cert` per `is_internal`'s intended branch in `only_aggregator_and_self`, which is never evaluated. Impact: High - unauthenticated call mutates protocol state via the tx_sender queue regardless of any header-based classification, confirming the vulnerability is independent of `is_internal`'s own logic and lies solely in `create_grpc_server`'s `Noop` selection. Proof idea: `cargo test` sending `internal_send_tx` with and without a spoofed `grpc-method` header under `client_verification=false`, asserting both succeed identically, proving the classification path is dead code under `Noop`.
