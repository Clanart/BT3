Can an attacker craft two distinct raw Bitcoin transactions A and B such that `CircuitTransaction::mid_state_txid` (SHA256 of the concatenated version, inputs, outputs, locktime, no witness) produces the same 32-byte digest for both, then submit B as `payout_spv.transaction` while the real block contains only A, so that `BlockInclusionProof::get_root(mid_state_txid)` == `block_header.merkle_root` for a transaction that was never mined? Call sequence: `SPV::verify` -> `self.transaction.mid_state_txid()` -> `self.block_inclusion_proof.get_root(...)`. Binding: `payout_spv.transaction.mid_state_txid()` == the `mid_state_txid` of the transaction actually included at that block position. Impact: Critical, a forged payout transaction accepted as included, causing an operator to be reimbursed for a payout it never funded. Proof idea: cargo test under circuits-lib/src/bridge_circuit/spv.rs constructing a preimage collision attempt against `calculate_sha256` and asserting `SPV::verify` cannot be tricked when A and B differ; document the digest is single SHA256 (not double), and assert this is testable by directly submitting `CircuitTransaction(B)` with A's proof and confirming rejection, since PROOF_SOUNDNESS requires equality of claimed and actual content.
