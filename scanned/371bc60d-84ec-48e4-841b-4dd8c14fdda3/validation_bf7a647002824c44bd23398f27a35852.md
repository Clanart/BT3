## Title
Truncating integer division in `StakedStreamLoadEMA` biases the QUIC/TPU stream-load EMA downward, allowing sustained load to evade staked-stream throttling - (File: `streamer/src/nonblocking/stream_throttle.rs`)

### Summary
The Olympus finding is that a moving average computed by repeatedly adding a truncated delta (`_movingAverage += diff / numObs`) systematically loses precision because each division discards a remainder, and this discarded value is never recovered, causing the tracked average to drift away from the true value without bound. Agave's `StakedStreamLoadEMA::ema_function` in `streamer/src/nonblocking/stream_throttle.rs` implements essentially the same fixed-point EMA-by-truncating-integer-division pattern, with no rounding/remainder-carry correction, and the resulting biased state (`current_load_ema`) directly gates whether the anti-DoS "staked throttling" defense on the QUIC/TPU stream ingestion path is turned on.

### Finding Description
`ema_function` computes each interval's updated EMA as: [1](#0-0) 

```
(recent_load * multiplied_smoothing_factor
 + current_ema * (STREAM_LOAD_EMA_MULTIPLIER - multiplied_smoothing_factor))
 / STREAM_LOAD_EMA_MULTIPLIER
```

Two truncation points compound the drift:

1. The smoothing factor itself is derived via a truncating compile-time division: `multiplied_smoothing_factor = 2 * 1024 / (STREAM_LOAD_EMA_INTERVAL_COUNT + 1)` = `2048/41 = 49.95…` truncated to `49`, so the applied gain is already slightly off from the mathematically intended value before any run-time state exists. [2](#0-1) 

2. Every call to `update_ema` re-injects the *already-truncated* `current_load_ema` into the formula and truncates again on division by `STREAM_LOAD_EMA_MULTIPLIER`. This is called on essentially every incoming QUIC stream via `increment_load` -> `update_ema_if_needed` -> `update_ema`, i.e., driven directly by unprivileged remote peers opening streams, potentially many times per 5ms window. [3](#0-2) 

Because Rust's integer division truncates toward zero and there is no remainder-carry / rounding term (unlike the analogous EMA in `perf/src/recycler.rs`, which explicitly adds `RECYCLER_SHRINK_WINDOW_HALF` before dividing specifically "to make the remaining division round instead of truncate"), the recorded `current_load_ema` systematically underestimates the true load whenever the fractional remainder is non-zero. This is exactly the broken invariant from the Olympus report: the intended average value and the recorded, truncation-degraded value diverge, and the divergence is state that persists and re-compounds on every subsequent update rather than being corrected. [4](#0-3) 

The corrupted value, `current_load_ema` (mirrored into `stats.stream_load_ema`), is the sole input to the decision of whether `staked_throttling_enabled` is set: [5](#0-4) 

which in turn gates whether staked connections get throttled to `max_staked_load_in_throttling_window` or allowed unrestricted access via `available_load_capacity_in_throttling_duration`: [6](#0-5) 

No other guard revalidates the true instantaneous load against the threshold — the EMA truncation error is the only signal consulted, so nothing catches or bounds the drift.

### Impact Explanation
This EMA is the mechanism that is supposed to detect when staked-connection stream volume is approaching saturation and activate throttling to protect the QUIC/TPU stream ingestion path from being overwhelmed (a non-RPC remote resource-exhaustion vector). Because the tracked value systematically underestimates true sustained load, an attacker who can open large volumes of streams from staked or unstaked connections can keep the reported EMA below `staked_throttling_on_load_threshold` for longer than the real load justifies, delaying or effectively suppressing activation of `staked_throttling_enabled`. This weakens/bypasses the intended anti-DoS defense on validator TPU ingestion, extending the window in which the node accepts more streams/connections than the throttling policy intends — a remote resource-exhaustion/degradation impact consistent with the allowed impact classes (non-RPC remote exhaustion/crash on QUIC/TPU).

### Likelihood Explanation
Likelihood is limited by the small magnitude of the per-step truncation (division by 1024 and by 41), so any single update's error is small. However, unlike the Olympus case, the error here does not accumulate strictly monotonically — under many rapidly repeating updates driven by attacker-controlled stream opens, the persistent truncation bias plus the pre-biased smoothing constant (`49` instead of `49.95`) nudge the tracked value durably below the mathematically correct steady state, and this is directly and cheaply triggerable by any remote peer sending streams (`increment_load` is called per stream via `ConnectionPeerType`). No privileged, malicious-validator, or trusted-peer assumption is required.

### Recommendation
Apply the same rounding-compensation approach Agave already uses in `perf/src/recycler.rs::allocate` (adding half of the divisor before the division) to `ema_function`, and/or track the running numerator (`current_load_ema` scaled by `STREAM_LOAD_EMA_MULTIPLIER`, i.e., a "sum" rather than truncated "average") and only divide down to a plain rate when it is read for the threshold comparison, mirroring the Olympus fix of storing cumulative `sum` and dividing only at read time.

### Proof of Concept
Conceptually:
1. `multiplied_smoothing_factor` is computed once as `2 * 1024 / 41 = 49` (true value ≈ 49.95), a ~2% under-weighting of new observations baked in at compile time.
2. On each `update_ema` call (driven by `increment_load` for every accepted stream from a staked connection), `updated_ema = (recent_load*49 + current_ema*975) / 1024` truncates its result.
3. Repeating this every `STREAM_LOAD_EMA_INTERVAL_MS` (5ms) under sustained attacker-driven stream volume causes `current_load_ema` to converge to, and stay pinned below, the true steady-state load implied by `recent_load`, because each truncated remainder is discarded rather than carried forward.
4. As long as `current_load_ema` (as exposed via `stats.stream_load_ema` and used in the `staked_throttling_on_load_threshold` comparison) understates the real load, `staked_throttling_enabled` remains `false` in `update_ema`, so `available_load_capacity_in_throttling_duration` keeps returning the unrestricted `max_staked_load_in_throttling_window` rather than throttling, letting the attacker sustain more streams than the defense intends. [7](#0-6) 

Note: I could not fully trace the exact call sites in `streamer/src/nonblocking/swqos.rs` and `streamer/src/nonblocking/quic.rs` that invoke `increment_load`/`available_load_capacity_in_throttling_duration` per accepted stream due to tool-call limits in this session; the causal chain from remote stream acceptance to `increment_load` is inferred from the `ConnectionPeerType` parameter and doc comments in `stream_throttle.rs`, but a full trace through `swqos.rs` would strengthen confirmation of exact trigger frequency and confirm no additional bounding check exists downstream.

    fn ema_function(current_ema: u128, recent_load: u128) -> u128 {
        // Using the EMA multiplier helps in avoiding the floating point math during EMA related calculations
        const STREAM_LOAD_EMA_MULTIPLIER: u128 = 1024;
        let multiplied_smoothing_factor: u128 =
            2 * STREAM_LOAD_EMA_MULTIPLIER / (u128::from(STREAM_LOAD_EMA_INTERVAL_COUNT) + 1);

        // The formula is
        //    updated_ema = recent_load * smoothing_factor + current_ema * (1 - smoothing_factor)
        // To avoid floating point math, we are using STREAM_LOAD_EMA_MULTIPLIER
        //    updated_ema = (recent_load * multiplied_smoothing_factor
        //                   + current_ema * (multiplier - multiplied_smoothing_factor)) / multiplier
        (recent_load * multiplied_smoothing_factor
            + current_ema * (STREAM_LOAD_EMA_MULTIPLIER - multiplied_smoothing_factor))
            / STREAM_LOAD_EMA_MULTIPLIER
    }

    fn update_ema(&self, time_since_last_update_ms: u128) {
        // if time_since_last_update_ms > STREAM_LOAD_EMA_INTERVAL_MS, there might be intervals where ema was not updated.
        // count how many updates (1 + missed intervals) are needed.
        let num_extra_updates =
            time_since_last_update_ms.saturating_sub(1) / u128::from(STREAM_LOAD_EMA_INTERVAL_MS);

        let load_in_recent_interval =
            u128::from(self.load_in_recent_interval.swap(0, Ordering::Relaxed));

        let mut updated_load_ema = Self::ema_function(
            u128::from(self.current_load_ema.load(Ordering::Relaxed)),
            load_in_recent_interval,
        );

        for _ in 0..num_extra_updates {
            updated_load_ema = Self::ema_function(updated_load_ema, 0);
            if updated_load_ema == 0 {
                break;
            }
        }

        let Ok(updated_load_ema) = u64::try_from(updated_load_ema) else {
            error!("Failed to convert EMA {updated_load_ema} to a u64. Not updating the load EMA");
            self.stats
                .stream_load_ema_overflow
                .fetch_add(1, Ordering::Relaxed);
            return;
        };

        if self.staked_throttling_on_load_threshold > 0 {
            self.staked_throttling_enabled.store(
                updated_load_ema >= self.staked_throttling_on_load_threshold,
                Ordering::Relaxed,
            );
        }

        self.current_load_ema
            .store(updated_load_ema, Ordering::Relaxed);
        self.stats
            .stream_load_ema
            .store(updated_load_ema as usize, Ordering::Relaxed);
    }

    pub(crate) fn update_ema_if_needed(&self) {
        const EMA_DURATION: Duration = Duration::from_millis(STREAM_LOAD_EMA_INTERVAL_MS);
        // Read lock enables multiple connection handlers to run in parallel if interval is not expired
        if Instant::now().duration_since(*self.last_update.read().unwrap()) >= EMA_DURATION {
            let mut last_update_w = self.last_update.write().unwrap();
            // Recheck as some other thread might have updated the ema since this thread tried to acquire the write lock.
            let since_last_update = Instant::now().duration_since(*last_update_w);
            if since_last_update >= EMA_DURATION {
                *last_update_w = Instant::now();
                self.update_ema(since_last_update.as_millis());
            }
        }
    }

    pub(crate) fn increment_load(&self, peer_type: ConnectionPeerType) {
        if peer_type.is_staked() {
            self.load_in_recent_interval.fetch_add(1, Ordering::Relaxed);
        }
        self.update_ema_if_needed();
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
