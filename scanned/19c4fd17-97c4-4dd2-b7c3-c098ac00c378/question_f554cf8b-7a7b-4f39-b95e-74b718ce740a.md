Preconditions: attacker-controlled plugin.json consumed by an automation flow that reads 'repository' for target binding. Call sequence: plugin.json parse -> metadata extraction -> automation binds subsequent git/API calls to the extracted URL. Invariant tested: state must stay correctly bound (repo/issue target must not drift from user-approved target). Scoped impact: comments/labels/commits posted to an unintended, attacker-chosen repository or issue. Proof idea: unit test metadata-consuming automation with a plugin.json whose 'repository' field diverges from the actual git remote and assert the automation refuses to bind actions to the metadata-declared repo without explicit confirmation.
