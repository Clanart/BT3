Based on the code review, this is not a valid vulnerability.

**Analysis:**

The claim describes intended, designed, and already-mitigated behavior rather than a vulnerability:

1. **The pool cap is an explicit, documented safety mechanism.** `Config::retry_pool_max_size` (default `MAX_TRANSACTION_RETRY_POOL_SIZE` = 10,000) exists specifically to bound the size of `retry_transactions`; once the cap is hit, new transactions are dropped rather than added, as documented in the struct comment. [1](#0-0) 

2. **The send rate is already capped at startup via config validation** against `MAX_TRANSACTION_SENDS_PER_SECOND`, and this cap plus `retry_pool_max_size` are both admin-configurable — an operator can tune them down. [2](#0-1) 

3. **The per-entry work in the O(n) scan is not expensive.** `get_committed_transaction_status_and_slot` is just an `RwLock::read()` acquisition plus a couple of `HashMap` lookups against the in-memory status cache — not a disk/DB scan or CPU-heavy operation. [3](#0-2) [4](#0-3) 

4. **The retry scan runs on a dedicated background thread (`solStxRetry`)** holding only its own `retry_transactions` mutex and a shared status-cache read lock — it does not share a lock with, or block, the RPC/pubsub request-handling threads. Read locks on the status cache don't contend with other concurrent readers (RPC queries), only with the (much rarer) writer path during bank freezing/squashing.

    pub fn get_status<K: AsRef<[u8]>>(
        &self,
        key: K,
        transaction_blockhash: &Hash,
        ancestors: &Ancestors,
    ) -> Option<(Slot, T)> {
        let map = self.cache.get(transaction_blockhash)?;
        let (_, index, keymap) = map;
        let max_key_index = key.as_ref().len().saturating_sub(CACHED_KEY_SIZE + 1);
        let index = (*index).min(max_key_index);
        let key_slice: &[u8; CACHED_KEY_SIZE] =
            arrayref::array_ref![key.as_ref(), index, CACHED_KEY_SIZE];
        if let Some(stored_forks) = keymap.get(key_slice) {
            let res = stored_forks
                .iter()
                .find(|(f, _)| ancestors.contains_key(f) || self.roots.contains(f))
                .cloned();
            if res.is_some() {
                return res;
            }
        }
        None
    }
