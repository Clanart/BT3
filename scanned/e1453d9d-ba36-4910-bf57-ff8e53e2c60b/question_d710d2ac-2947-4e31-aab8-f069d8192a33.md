Target: `only_aggregator_and_self` (core/src/rpc/interceptors.rs) versus its total bypass when `Interceptors::Noop` is selected. Attacker action: call `Withdraw` while spoofing the `grpc-method` header to *not* start with `Internal`, relying on the fact that under Noop the header-based `is_internal` branch is never evaluated at all. Preconditions: `client_verification=false`. Call sequence: `AddMethodMiddlewareLayer` still stamps the real method name -> `Interceptors::Noop::call` ignores the header entirely -> handler executes. Binding: is_internal(req) driving an authorization decision == a decision that only has meaning under `OnlyAggregatorAndSelf`; under Noop the binding is never evaluated, so 'internal-only' methods and public methods are equally reachable by the attacker. Impact: Critical - internal-only surfaces (which by design assume only the aggregator's own client cert can call them) become reachable by an unprivileged caller, collapsing the internal/external trust boundary the rest of the codebase assumes holds. Proof idea: cargo test asserting that with `client_verification=false`, a call to an `Internal*`-named method succeeds from a connection presenting no certificate, contradicting the guarantee `test_auth_interceptor` (core/src/test/rpc_auth.rs) verifies only for the operator/verifier servers under `client_verification=true`.
