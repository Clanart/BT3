Target: `ClementineAggregator::optimistic_payout`, `create_optimistic_payout_txhandler`. Attacker action: sends `OptimisticPayoutParams{ withdrawal_id, sig, ... }` with an attacker-fabricated Schnorr signature and sighash flag over a withdrawal UTXO the attacker names, hitting the aggregator's public port with no cert. Preconditions: `client_verification=false`, an existing move-to-vault UTXO unspent. Call sequence: `Noop` interceptor -> `optimistic_payout` -> `create_optimistic_payout_txhandler` builds the payout tx and drives verifiers into signing it via the same nonce/partial-sig pipeline as `new_deposit`. Binding: the withdrawal the N-of-N signs for == a withdrawal the Citrea Bridge contract actually recorded; an unauthenticated caller reaching this endpoint means CALLER_AUTHORITY (caller_reaching_method == aggregator_cert_holder) already fails before signature validity is even checked. Impact: Critical - verifiers can be driven into signing a spend of the move-to-vault UTXO for a withdrawal that was never registered, risking BTC leaving custody without a matching fronted withdrawal. Proof idea: `cargo test` in `core/src/test` calling `optimistic_payout` from an unauthenticated client against a `MockCitreaClient` with no matching withdrawal event, asserting the RPC layer accepts the connection (no `Status::unauthenticated`) before any withdrawal-registration check runs.
