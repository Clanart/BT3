[Target: Verifier::update_finalized_payouts (core/src/verifier.rs)] Attacker crafts an on-chain payout transaction whose OP_RETURN happens to decode to a valid XOnlyPublicKey of ANY registered operator (not necessarily the one who fronted funds), by controlling script bytes of a Bitcoin transaction spending the withdrawal UTXO for index i. Preconditions: withdrawal UTXO for index i exists and is unspent; attacker can broadcast any transaction spending that UTXO (they own the withdrawal UTXO's private key as the withdrawing user). Call sequence: `update_finalized_payouts` -> `get_payout_txs_for_withdrawal_utxos` finds the spending tx by UTXO alone -> `get_first_op_return_output` parses attacker-chosen OP_RETURN bytes -> `parse_op_return_data` + `XOnlyPublicKey::from_slice` accepts attacker-chosen 32 bytes matching operator B's pubkey even though operator B never funded this payout -> `update_payout_txs_and_payer_operator_xonly_pk` credits operator B. Binding: operator credited (payout_payer_operator_xonly_pk) == operator whose funds paid the payout (the actual signer/broadcaster). Impact: Critical, an operator reimbursed for a payout it never funded, and the honest operator who actually fronted funds (if the attacker used their own coin) is permanently unable to be reimbursed. Proof idea: cargo test broadcasting a payout tx spending the registered withdrawal UTXO with attacker-crafted funds and an OP_RETURN containing a legitimate but unrelated operator's xonly pubkey; assert update_finalized_payouts does not credit that operator absent proof they funded the input.
