In `Verifier::is_deposit_valid`, the operator set check only compares `operators_in_deposit_data` (from the depositor-controlled `DepositParams.actors.operators`) against `operators_in_db` by collateral usability, never verifying the depositor didn't simply omit an operator whose collateral just became unusable in the same block as the deposit tx confirmation (TOCTOU on `collateral_check`). Binding: the operator set N-of-N verifiers agree to reimburse under == the operator set actually eligible at the deposit's `block_height`. Impact: Critical, an honest operator that funded a payout for this deposit could be excluded from the agreed reimbursement set due to a race, permanently unable to be reimbursed via the deposit's `Reimburse` path. Proof idea: cargo test flipping operator collateral status between deposit tx confirmation and `deposit_sign` and asserting operator inclusion is anchored to the confirmed block, not the call-time DB state.
