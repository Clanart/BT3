### Title
First-depositor dust attack can permanently freeze reward distribution in `BaseRewardPool` / `BaseRewardPoolV2` - (File: rewards/BaseRewardPool.sol, rewards/BaseRewardPoolV2.sol, rewards/MasterMagpie.sol)

### Summary
`BaseRewardPool`/`BaseRewardPoolV2` compute their reward accumulator (`rewardPerTokenStored`) by dividing the injected reward amount by `totalStaked()`, which is simply `MasterMagpie`'s live token balance for that staking token. Since `MasterMagpie` enforces no minimum deposit amount, and anyone can permissionlessly call `donateRewards()` to inject reward tokens, an unprivileged attacker can become the sole staker with `1 wei`, then donate a large reward amount to inflate `rewardPerTokenStored` to a value close to `type(uint256).max`. Any subsequent legitimate reward injection (`queueNewRewards`, used by pool helpers/compounders during normal harvesting) will then revert on Solidity 0.8's checked-arithmetic overflow of the `+=` accumulation, permanently freezing yield distribution for every staker of that pool. This mirrors the XDEFI H-01 bug class: dust-based inflation of a per-unit reward accumulator that DoSes future accounting for all other users.

### Finding Description
`_deposit()` in `MasterMagpie.sol` has no minimum-amount check, so any wallet can deposit `1 wei` of a newly-added staking token and become the pool's only staker: [1](#0-0) 

`BaseRewardPool.totalStaked()` reads live token balance held by `MasterMagpie`, which is exactly the quantity manipulated above: [2](#0-1) 

`donateRewards()` is callable by **anyone** (no `onlyManager` modifier), unlike `queueNewRewards()`: [3](#0-2) 

The reward accumulator update divides the injected amount by `totalStaked()`: [4](#0-3) 

The same pattern exists in `BaseRewardPoolV2.sol`: [5](#0-4) 

With `totalStaked() == 1`, a modest donation (e.g. attacker-owned reward tokens) inflates `rewardInfo.rewardPerTokenStored` by a factor of `10**stakingDecimals()` divided by `1`, pushing it near `type(uint256).max`. Because Solidity 0.8 reverts on arithmetic overflow, **any future call** to `_provisionReward` (via `queueNewRewards` from legitimate managers, e.g. pool helpers routing harvested protocol rewards) that adds even a tiny amount on top will revert at the `rewardInfo.rewardPerTokenStored = rewardInfo.rewardPerTokenStored + (...)` line, permanently blocking all subsequent reward distribution for every staker of that pool.

### Impact Explanation
This causes permanent freezing of unclaimed/future yield for an entire `BaseRewardPool`/`BaseRewardPoolV2` instance: legitimate reward managers (pool helpers/compounders) can no longer queue new rewards once the accumulator is saturated, since the transaction reverts on overflow. Depending on rounding, it can also make `earned()` calculations overflow for large stakers (`balanceOf(_account) * (rewardPerToken - paid)`), blocking `getReward()`/withdraw-triggered reward harvesting paths that call `updateFor`/`_harvestBaseRewarder`. This matches the accepted impact bucket of "theft or permanent freezing of unclaimed yield."

### Likelihood Explanation
The attack requires only two unprivileged actions available to any wallet: (1) deposit `1 wei` as first staker of a pool right after it is added, and (2) call the permissionless `donateRewards()` with attacker-owned reward tokens. No admin/governance action or oracle manipulation is needed. The only precondition is being first to stake in a freshly added pool, which is realistically achievable by monitoring `add()` transactions/mempool.

### Recommendation
- Enforce a minimum stake amount in `MasterMagpie._deposit` (or seed pools with a non-zero, non-withdrawable amount similar to Uniswap V2's minimum liquidity burn / XDEFI's fix).
- Restrict `donateRewards()` to trusted managers, or cap the ratio of `_amountReward` to `totalStaked()` to prevent extreme single-block inflation of `rewardPerTokenStored`.
- Consider using a fixed lower-precision multiplier (as XDEFI's remediation reduced `_pointsMultiplier` from `2**128` to `2**72`) and/or checked bounds on `rewardPerTokenStored` growth to avoid saturation from small-denominator divisions.

### Proof of Concept
1. Admin adds a new pool `S` with `BaseRewardPool` `R` for reward token `T` via `MasterMagpie.add()`.
2. Attacker front-runs other depositors: `MasterMagpie.deposit(S, 1)` — becomes sole staker; `R.totalStaked() == 1` (`IERC20(S).balanceOf(MasterMagpie) == 1`).
3. Attacker calls `R.donateRewards(hugeAmount, T)` (unprivileged, no `onlyManager` check) using tokens they own.
   - `_provisionReward` computes `rewardPerTokenStored += (hugeAmount * 10**decimals) / 1`, pushing the accumulator near `type(uint256).max`.
4. A legitimate manager (e.g., pool helper compounding harvested rewards) later calls `R.queueNewRewards(smallAmount, T)`.
   - `_provisionReward`'s `rewardInfo.rewardPerTokenStored = rewardInfo.rewardPerTokenStored + (...)` overflows and reverts under Solidity 0.8 checked arithmetic.
5. All subsequent legitimate reward injections for pool `S` permanently revert, freezing yield distribution for every staker of that pool indefinitely (no admin lever exists in these contracts to reset `rewardPerTokenStored`).

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
