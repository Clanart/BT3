## Finding: Unbounded-cardinality `contract_address` label on `wasm_contract_query_smart` telemetry (memory-exhaustion DoS)

This maps to the same bug class as the reported `otelhttp`/`otelbeego` CVE-2023-25151: a metrics instrument is labeled with an attacker-controlled, effectively infinite-cardinality value, so every distinct value creates a permanently retained time series, letting an unprivileged caller drive unbounded memory growth in a long-running node process.

### Title
Unbounded `contract_address` label cardinality in wasm `QuerySmart` telemetry causes node memory-exhaustion DoS - (`sei-wasmd/x/wasm/keeper/metrics.go`)

### Summary
`Keeper.QuerySmart` unconditionally records the raw, caller-supplied contract address string as a label value on legacy `go-metrics`/Prometheus counters/gauges before any existence check on the contract, letting an unprivileged CosmWasm query client or EVM precompile caller generate unlimited unique label values and grow the node's metrics memory without bound.

### Finding Description
`sei-wasmd/x/wasm/keeper/keeper.go` `QuerySmart` calls `recordContractQuerySmartInvocation(contractAddr.String())` immediately, before `checkAndIncreaseQueryStackSize` or `contractInstance` (the existence lookup): [1](#0-0) 

`recordContractQuerySmartInvocation` and `recordContractQuerySmartGasUsed` emit `contract_address` as a label on the legacy go-metrics sink via `telemetry.IncrCounterWithLabels` / `telemetry.SetGaugeWithLabels`: [2](#0-1) 

The code comment for `recordContractQuerySmartGasUsed` even documents the risk for the OTel instrument ("a per-contract label here would retain one series per distinct contract address queried for the process lifetime") and deliberately omits the label there — but the legacy `telemetry.IncrCounterWithLabels`/`SetGaugeWithLabels` calls still carry the unbounded `contract_address` label unconditionally, on every call, regardless of whether the contract exists.

The legacy sink is `sei-cosmos/telemetry`'s `armon/go-metrics` + Prometheus sink, configured via `PrometheusRetentionTime`: [3](#0-2) 

When `PrometheusRetentionTime > 0` (present in shipped `docker/localnode/config/app.toml` and `docker/rpcnode/config/app.toml`), every unique `contract_address` label value opens a new time series that is retained in memory until its individual expiration timer fires — the same "cumulative temporality never forgets attributes" pattern as the referenced CVE.

`QuerySmart` is reachable from:
- The CosmWasm gRPC `SmartContractState` query: [4](#0-3) 
- The EVM `wasmd` precompile's `query()` method, callable via a free `eth_call` JSON-RPC request with an attacker-chosen bech32 address string: [5](#0-4) 

Because `recordContractQuerySmartInvocation` fires before the contract-existence check, the caller does not even need to deploy real contracts — any syntactically valid bech32 `AccAddress` string (trivially and cheaply generated in bulk) produces a new, permanently-labeled series.

### Impact Explanation
An unprivileged party issuing repeated `eth_call`s to the wasmd precompile's `query` method (or repeated gRPC `SmartContractState` queries) with random contract addresses can force the validator/full node's telemetry subsystem to allocate an unbounded number of Prometheus label series. This is unauthenticated, free (query/eth_call, not a state-changing transaction with gas cost proportional to abuse), and reachable on any node with Prometheus telemetry enabled (shipped default configs enable `PrometheusRetentionTime`). Sustained abuse leads to continuous memory growth that can exhaust node memory and crash the process — matching the "crash of default-configuration RPC nodes" acceptance criterion.

### Likelihood Explanation
High. The attack requires no funds, no special privileges, and no deployed contracts — only the ability to send read-only `eth_call`/gRPC query requests, which is the baseline capability of any public-RPC client. Generating unique bech32 address strings is computationally trivial and can be automated at high request rates.

### Recommendation
Remove the raw `contract_address` label from the legacy telemetry emission paths in `recordContractQuerySmartInvocation` and `recordContractQuerySmartGasUsed` (mirroring the fix already applied to the OTel histogram, per the existing code comment), or move the invocation/gas-used counters to fire only after the contract-existence check and cap/bucket the label to a bounded vocabulary (similar to the pattern used in `giga/evmonly/metrics.go`'s `occLabel`/`occLabelVocabulary` bounded-label approach) rather than the raw address string.

### Proof of Concept
1. Configure a node with `telemetry.enabled = true` and `telemetry.prometheus-retention-time > 0` (as in the shipped `docker/rpcnode/config/app.toml`).
2. Repeatedly call `eth_call` against the `wasmd` precompile's `query(string,bytes)` method (or the gRPC `SmartContractState` query), each time supplying a freshly generated, syntactically valid but non-existent bech32 `sei1...` address as `contractAddrStr`.
3. Each call reaches `Keeper.QuerySmart`, which invokes `recordContractQuerySmartInvocation(contractAddr.String())` before the contract-existence check, creating a new `contract_address`-labeled series in the Prometheus sink.
4. Repeat at scale (no gas or fee cost beyond a JSON-RPC request) to observe unbounded growth in the node's metrics-related memory usage over time.

func (p PrecompileExecutor) query(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()
	if err := pcommon.ValidateNonPayable(value); err != nil {
		rerr = err
		return
	}

	if err := pcommon.ValidateArgsLength(args, 2); err != nil {
		rerr = err
		return
	}

	contractAddrStr := args[0].(string)
	// addresses will be sent in Sei format
	contractAddr, err := sdk.AccAddressFromBech32(contractAddrStr)
	if err != nil {
		rerr = err
		return
	}
	req := args[1].([]byte)

	rawContractMessage := wasmtypes.RawContractMessage(req)
	if err := rawContractMessage.ValidateBasic(); err != nil {
		rerr = err
		return
	}

	res, err := p.wasmdViewKeeper.QuerySmart(ctx, contractAddr, req)
	if err != nil {
		rerr = err
		return
	}
	ret, rerr = method.Outputs.Pack(res)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
