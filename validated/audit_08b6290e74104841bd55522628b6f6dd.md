### Title
Unbounded index read in `is_atom_canonical`/`is_clvm_canonical` lets a crafted spend bundle raise an uncaught `IndexError` during mempool validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse an attacker-supplied CLVM buffer (a coin's `puzzle_reveal` or `solution`) by walking length-prefix bytes read directly from the buffer, exactly analogous to the kernel bug: the parser advances an `offset` based on a length value taken from the buffer itself without ever validating that `offset` stays within the buffer bounds before dereferencing it again.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` to determine a multi-byte length-prefix encoding, then loops `prefix_len` times doing `offset += 1; atom_len |= clvm_buffer[offset]` with **no bounds check** that `offset < len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this in a loop, reading `b = clvm_buffer[offset]` at the top of each iteration and calling `is_atom_canonical` whenever the atom-length byte indicates a multi-byte encoding, again without checking `offset` against `len(clvm_buffer)` before the read: [2](#0-1) 

This is reachable directly from an unprivileged spend-bundle submission: `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in a submitted bundle, before any other CLVM-level validation of that check: [3](#0-2) 

`validate_spend_bundle()` is invoked from `add_spend_bundle()`, which is the standard mempool-admission path for any spend bundle a peer or wallet submits: [4](#0-3) 

Because these are plain Python `bytes` objects, an out-of-range index does not silently read adjacent memory (as in the C kernel case) — it raises an `IndexError`. Crucially, unlike `pre_validate_spendbundle()`, which wraps its CLVM/signature validation call in a `try/except ValueError` to translate failures into a clean `ValidationError`, `validate_spend_bundle()` has no such exception handling around the `is_clvm_canonical` calls: [5](#0-4) 

A submitter can craft a puzzle_reveal or solution whose final bytes are a truncated multi-byte atom-length prefix (e.g., a buffer ending in `0xFC` with fewer than 5 trailing bytes, or ending exactly on a `0xFF` pair byte with nothing following), causing `clvm_buffer[offset]` to index past the end of the buffer and raise an unhandled `IndexError` inside `validate_spend_bundle()`.

### Impact Explanation
An unhandled `IndexError` thrown from inside mempool-admission logic (which is not guarded the way the earlier CLVM-execution stage is) will propagate up through `add_spend_bundle()` into whatever caller processes incoming transactions/spend bundles (full node's transaction-handling task). Depending on how far up the call chain catches generic exceptions, this can abort processing of that spend bundle path or the calling task, effectively matching the "spend-triggered transaction-processing halt" impact category — any unprivileged actor able to submit a spend bundle (a wallet user, or a peer relaying it) can trigger it repeatedly with a single crafted, otherwise well-formed-looking coin spend.

### Likelihood Explanation
The trigger requires only crafting a coin_spend whose puzzle_reveal or solution bytes end in a truncated multi-byte CLVM atom-length prefix — this is a small, deterministic, and easily constructed byte sequence, requiring no privileged access, no valid signature (the check runs before/alongside other conds), and no special network position. This makes the likelihood high for a determined submitter, though the actual availability impact is bounded by however the top-level call site handles unexpected exceptions (which I was not able to fully trace before running out of investigation budget).

### Recommendation
Add explicit bounds checks in both `is_atom_canonical` (before each `clvm_buffer[offset]` read as `offset` is incremented across `prefix_len` iterations, and for the initial `b = clvm_buffer[offset]` read) and in `is_clvm_canonical`'s loop (before `b = clvm_buffer[offset]`), returning a "not canonical"/error result instead of raising `IndexError` when the buffer is exhausted. Additionally, wrap the `is_clvm_canonical` calls in `validate_spend_bundle()` in a try/except that converts any unexpected exception into `Err.INVALID_COIN_SOLUTION`, mirroring the defensive pattern already used in `pre_validate_spendbundle()`.

### Proof of Concept
1. Construct a `coin_spend` whose `solution` (or `puzzle_reveal`) serialization ends with a truncated multi-byte atom length prefix, e.g. a buffer such as `b"\xff\xff\xfc"` (a `0xFF` pair marker followed by a `0xFC` byte indicating "5 more length bytes follow" but with zero bytes remaining in the buffer).
2. Submit a `SpendBundle` containing this `coin_spend` to a full node (e.g., via `MempoolManager.add_spend_bundle`, reachable from ordinary transaction submission).
3. `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, which calls `is_atom_canonical(clvm_buffer, offset)`, which indexes past the end of `clvm_buffer` and raises an unhandled `IndexError`, unlike the clean `ValidationError` path used elsewhere in the module. This can be confirmed directly by calling `is_clvm_canonical(b"\xff\xff\xfc")` or `is_atom_canonical(b"\xfc", 0)` in isolation, which raises `IndexError: index out of range` per the function definitions at: [1](#0-0) [2](#0-1)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
