### Title
Unchecked parse result in ProtoJSON `Any` unparsing lets malformed payload bytes silently produce a default/empty message body - ([File: src/google/protobuf/json/internal/unparser_traits.h])

### Summary
The upstream finding flags `execute()` calls in `VaultController.sol` whose boolean success return is discarded, letting a failed operation be treated as if it had succeeded and letting execution continue on stale/incorrect state. The direct Protobuf analog is `Proto2Type::WithDecodedMessage()` in `src/google/protobuf/json/internal/unparser_traits.h:278-289`, used by the C++ ProtoJSON writer's `WriteAny()` (`src/google/protobuf/json/internal/unparser.cc:770-835`). It parses the attacker-controlled `Any.value` bytes with `ParsePartialFromString()` but discards the returned success/failure boolean, then unconditionally proceeds to serialize whatever ended up in `unerased` as if the parse had fully succeeded.

### Finding Description
`WriteAny()` decodes `google.protobuf.Any` messages when converting a `Message` to JSON via the public `MessageToJsonStream`/`BinaryToJsonStream` entry points. It resolves the dynamic type for `Any.type_url`, then calls:

```cpp
static absl::Status WithDecodedMessage(const Desc& desc,
                                       absl::string_view data, F body) {
  DynamicMessageFactory factory;
  std::unique_ptr<Message> unerased(factory.GetPrototype(&desc)->New());
  // TODO: Remove this suppression.
  (void)unerased->ParsePartialFromString(data);
  const Msg& ref = *unerased;
  return body(ref);
}
``` [1](#0-0) 

`ParsePartialFromString()` returns `false` when the bytes in `Any.value` are corrupt/incomplete for the resolved type (e.g., malformed varint tag, truncated length-delimited field, invalid wire type), matching the "corrupt, incomplete, or was never a protobuf" case documented on the method itself. `MessageLite::ParsePartialFromString` is declared `PROTOBUF_FUTURE_ADD_EARLY_NODISCARD`, meaning the API is meant to force callers to check it, yet the cast to `(void)` explicitly suppresses that check here, exactly mirroring the missing "if (!success) revert" pattern in the original report.

Because the return value is dropped, `body(ref)` is invoked on `unerased` regardless of whether the parse populated any fields. `ParsePartialFromString` may leave the message partially populated (whatever fields were parsed before the wire-format error was hit) rather than restoring it to the empty default, so the JSON writer can emit output based on an inconsistent/partial reinterpretation of the attacker-controlled bytes instead of surfacing an error.

This directly parallels the original bug's failed invariant: "every external state-changing call's success must be checked before relying on its result"; here the equivalent invariant "every parse of untrusted `Any.value` bytes must be checked before the result is treated as valid data to serialize" is violated.

### Impact Explanation
This is a data-integrity issue in the ProtoJSON output path, not memory corruption: a client that controls an `Any` field's `type_url`/`value` (via binary or ProtoJSON input to any public parse API, then re-serialized to JSON, or via `BinaryToJsonStream`) can supply `value` bytes that fail to parse as the declared type. Instead of the writer reporting a decode error (as the sibling upb C encoder does via `jsonenc_err`/`jsondec_err` on `upb_Decode` failure, see `upb/json/encode.c:405-408` and `upb/json/decode.c:1507-1512`, or as the Java `JsonFormat.printAny`/Python `text_format.PrintAny` do via a checked `parseFrom`/`ParseFromString`), the C++ ProtoJSON `WriteAny` silently emits JSON for a partially/incorrectly populated dynamic message, misrepresenting the true content of the `Any` payload to downstream consumers of the JSON. This is an integrity/output-correctness defect reachable purely through the public JSON serialization surface with a bounded, well-formed-at-the-outer-level `Any` message.

### Likelihood Explanation
High reachability: any caller that serializes a message containing a `google.protobuf.Any` field to JSON via `MessageToJsonStream` or resolves/serializes via `BinaryToJsonStream` exercises this code path. Triggering the discrepancy only requires the client to embed `Any.value` bytes that are valid enough to reach `WriteAny` (type_url resolvable) but malformed relative to the resolved schema — an ordinary, bounded crafted input, no privileged access or huge payload required.

### Recommendation
Check the return value of `ParsePartialFromString()` in `WithDecodedMessage()` (`src/google/protobuf/json/internal/unparser_traits.h:283`) and propagate an `absl::InvalidArgumentError` (or similar) up through `WriteAny()`/`WriteMessage()` when parsing fails, consistent with how `upb`'s JSON encoder (`jsonenc_err(e, "Error decoding message in Any")`) and other-language `Any` unparsers handle the same failure. This mirrors the recommended fix in the original report: add the missing success check before using the result.

### Proof of Concept
Conceptual repro (mirrors `TEST_P(JsonTest, TestParsingBrokenAny)` style tests already in the suite, e.g. `src/google/protobuf/json/json_test.cc:1000-1033`, but targeting the *serialization* direction instead of parsing):
1. Construct a `TestAny` message whose `value.type_url` resolves to a known message type (e.g. `proto3.TestMessage`).
2. Set `Any.value` (the inner bytes field) to a short byte string that is *not* valid wire-format for `proto3.TestMessage` (e.g. a single byte that decodes to an invalid tag/wire-type combination, or a length-delimited field whose declared length exceeds the remaining bytes).
3. Call the C++ `MessageToJson`/`MessageToJsonStream` API on the outer message.
4. Observe that no error status is returned and JSON is produced from `unerased`, which was left in an inconsistent partial state by the failed `ParsePartialFromString` call — instead of the call failing closed as it does in the analogous upb (`jsonenc_err`) and Java (`printAny`, guarded by a checked `parseFrom` that throws) implementations.
