### Title
Empty aggregate Schnorr signature verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero component signatures when the aggregated scalar `s` is zero, even though `SchnorrAggregator::complete` explicitly refuses to produce an empty aggregate. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrAggregate::read` allows the encoded `Rs` vector length to be zero and then reads `s` without rejecting the empty or zero-valued result. [3](#0-2)  `verify` only checks that `self.Rs.len()` equals `keys_and_challenges.len()`, so an empty aggregate paired with an empty key list reaches the final equation with only `(-s)G`. [1](#0-0)  When `s = 0`, that equation is always the identity and verification returns true without verifying any signer nonce or public-key term. [4](#0-3) 

### Impact Explanation
An unprivileged party can supply a byte encoding for an aggregate signature that contains no signatures and a zero scalar, and have it accepted for an empty `keys_and_challenges` list. [5](#0-4)  This bypasses the library's own invariant that aggregation should fail when no signatures were aggregated, producing a forged aggregate signature accepted by the verification formula. [2](#0-1) 

### Likelihood Explanation
The condition is deterministic rather than probabilistic: no malicious nonce, hash preimage, or zero challenge is required. [1](#0-0)  The practical impact depends on a caller invoking `verify` with an empty authorized-signer list, but the API does not prevent that state and the deserializer accepts the necessary encoding. [3](#0-2) 

### Recommendation
Reject empty aggregate signatures in `SchnorrAggregate::verify`, and preferably reject `Rs.is_empty()` or `s == 0` during `SchnorrAggregate::read`. [3](#0-2)  This should mirror `SchnorrAggregator::complete`, which already refuses to construct an aggregate when `self.sigs.is_empty()`. [6](#0-5) 

### Proof of Concept
```rust
use std::io::Read;

use ciphersuite::Ciphersuite;
use dalek_ff_group::Ed25519;
use schnorr::aggregate::SchnorrAggregate;

let mut bytes = vec![];
bytes.extend(0u32.to_le_bytes()); // zero Rs
bytes.extend([0u8; 32]);          // canonical s = 0

let aggregate =
  SchnorrAggregate::<Ed25519>::read::<&[u8]>(&mut bytes.as_slice()).unwrap();

assert!(aggregate.verify(b"any-dst", &[]));
```

The verifier only appends `(-s, generator())` after processing zero signatures, so `s = 0` makes the multiexp result the identity. [4](#0-3)
