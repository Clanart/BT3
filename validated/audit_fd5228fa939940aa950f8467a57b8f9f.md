### Title
DataLayer Mirror URL Server-Side Request Forgery via `dl_new_mirror` / subscription sync - (File: `chia/data_layer/data_layer.py`)

### Summary
The DataLayer subsystem lets any DataLayer singleton owner publish on-chain "mirror" URLs (via `add_mirror` → `dl_new_mirror`) that are advertised for a store id. Any other DataLayer client that subscribes to that store id automatically pulls these attacker-controlled URLs from wallet state and issues outbound HTTP requests to them with no destination restriction, mirroring the SSRF bug class described in the reference advisory (an externally supplied URL/host value is used verbatim to build an outbound request).

### Finding Description
`DataLayer.add_mirror()` pushes an on-chain mirror coin containing an arbitrary list of URLs for a given store id, with no validation on the URL value beyond being present: [1](#0-0) 

Any other node's `DataLayer.update_subscriptions_from_wallet()` reads these mirror URLs from wallet RPC (`dl_get_mirrors`) and inserts them directly as subscription server URLs for that store, with only trailing-slash trimming — no scheme/host/IP allow-listing: [2](#0-1) 

Those URLs are persisted verbatim into the subscriptions table: [3](#0-2) 

During the periodic sync loop, `DataLayer.fetch_and_validate()` picks a stored server URL and passes it straight into the download path: [4](#0-3) 

`download_file()`/`http_download()` then issue an unrestricted `aiohttp` GET to `server_info.url + "/" + filename` with no host/IP filtering (no blocking of loopback, link-local metadata addresses such as `169.254.169.254`, RFC1918 ranges, or non-HTTP(S) schemes): [5](#0-4) 

The module's own design notes explicitly flag mirror/plugin URLs as external, untrusted trust inputs, confirming this is a known-risky boundary rather than an incidental one: [6](#0-5) [7](#0-6) 

Manual subscription via the RPC/CLI (`subscribe`) exhibits the identical unrestricted-URL pattern, so even the explicit user-supplied path performs no SSRF hardening: [8](#0-7) [9](#0-8) 

### Impact Explanation
A DataLayer store owner (an unprivileged actor who just needs to create a store and pay a small on-chain fee to register a mirror coin) can set a mirror URL pointing at cloud metadata endpoints, internal-only services, or arbitrary internal hosts/ports. Any other DataLayer client (an unprivileged "Data Layer client" per the allowed actor list) who chooses to subscribe to that store — a normal, expected DataLayer usage pattern for consuming public data sets — will have their node automatically add that URL as a fetch target and periodically issue outbound HTTP GET requests to it in the background sync loop, without user awareness of the concrete destination. This can be used to probe/exfiltrate internal network services, hit cloud instance-metadata services (potentially leaking credentials), or perform internal port scanning/blind SSRF from the victim's host, satisfying "confidentiality: high" style impact analogous to the reference CVE.

### Likelihood Explanation
Likelihood is moderate-to-high: creating a DataLayer store and adding a mirror is a normal, low-cost, unprivileged wallet action; and subscribing to third-party stores (to receive their data) is the intended, expected DataLayer workflow, so a victim does not need to do anything unusual beyond normal use of the feature. The periodic `periodically_manage_data()` loop drives the fetch automatically once subscribed, without requiring the victim to trust the mirror provider for anything beyond wanting their store's data.

### Recommendation
Validate/restrict mirror and manually-provided subscription URLs before they are persisted or dereferenced: enforce `http`/`https` scheme, resolve and reject requests to loopback, link-local (including `169.254.169.254`), private/internal address ranges, and reject redirects into those ranges. This validation should occur both at `add_mirror`/mirror ingestion time and immediately before dispatching the `aiohttp` request in `http_download()`/`download_file()`, since URLs can also arrive via `update_subscriptions_from_wallet()` from on-chain mirror coins outside of local RPC input validation.

### Proof of Concept
1. Attacker creates a DataLayer store (`create_data_store`) and calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount=..., fee=...)`, which is accepted on-chain via `dl_new_mirror` with no URL validation (`chia/data_layer/data_layer.py:965-970`).
2. Attacker advertises the store id publicly for others to consume.
3. Victim runs `chia data subscribe -id <store_id>` (or their own automation subscribes based on discovered store ids). `DataLayer.subscribe()` records the store; `update_subscriptions_from_wallet()` subsequently pulls the malicious mirror URL from wallet state (`chia/data_layer/data_layer.py:979-985`) and stores it via `DataStore.update_subscriptions_from_wallet()`.
4. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects the malicious URL (`chia/data_layer/data_layer.py:642-694`) and `http_download()` issues an unrestricted `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` request (`chia/data_layer/download_data.py:298-324`), causing the victim's node to make an outbound request to the attacker-chosen internal/metadata address.

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
