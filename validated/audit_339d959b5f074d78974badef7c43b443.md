### Title
Tokenfactory denom `AllowList` is enforced only at the `MsgSend`/`MsgMultiSend` layer and can be bypassed via the EVM bank precompile or CosmWasm `BankMsg::Send` - ([File: sei-cosmos/x/bank/keeper/msg_server.go])

### Summary
The tokenfactory `AllowList` restriction (analogous to Ion's lender whitelist) is checked only in the bank `msgServer.Send`/`MultiSend` handlers, not inside `BaseSendKeeper.SendCoins` itself. Any code path that calls `SendCoins` directly — the EVM `IBank` precompile's `send`, and CosmWasm's native `BankMsg::Send` dispatch — moves allow-listed tokens to/from addresses without ever consulting `IsInDenomAllowList`.

### Finding Description
`IsInDenomAllowList` is the sole gate enforcing a tokenfactory denom's `AllowList`, and it is invoked exclusively from the bank message-server entry points: [1](#0-0) [2](#0-1) 

The underlying `BaseSendKeeper.SendCoins`/`InputOutputCoins` keeper functions used to actually move balances do not perform this check themselves — `IsInDenomAllowList` is defined on `send.go` purely as a helper that callers must opt into: [3](#0-2) 

Two production, unprivileged-reachable paths call `SendCoins` directly, bypassing the allow-list check entirely:

1. **EVM bank precompile (`IBank.send`)** — an EVM contract or EOA calling the `send` method of the bank precompile results in a direct `p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, ...)` call with no allow-list check, seen identically across multiple precompile versions: [4](#0-3) [5](#0-4) 

2. **CosmWasm native `BankMsg::Send`** — contract-issued bank sends are dispatched through `BankCoinTransferrer.TransferCoins` in `sei-wasmd`, which only checks `IsSendEnabledCoins` and `BlockedAddr`, then calls `keeper.SendCoins` directly, again without consulting the allow list: [6](#0-5) 

This mirrors the Ion Protocol bug class: a whitelist/allow-list is enforced only at one privileged "entry" function (`supply()` in Ion, `MsgSend`/`MsgMultiSend` here), while an alternate, equally reachable transfer mechanism (ERC20 `_transfer` in Ion; the EVM bank precompile or CW `BankMsg::Send` here) moves the same restricted asset without re-checking the permission list.

### Impact Explanation
Any tokenfactory denom that an admin has configured with a non-empty `AllowList` (e.g. for regulatory/KYC reasons, or to whitelist recipients of an interest/reward-bearing token) can have its tokens sent to, or pulled from, addresses that are **not** on the allow list, simply by routing the transfer through the EVM bank precompile or a CosmWasm contract instead of `MsgSend`. This defeats the entire purpose of the allow-list feature — a non-whitelisted address can receive and hold (and thus benefit from) an allow-listed denom, and an allow-listed sender's restriction can be routed around by wrapping the transfer in a CW/EVM call.

### Likelihood Explanation
High. Both entry points (EVM precompile calls and CosmWasm contract execution) are directly reachable by any unprivileged transaction sender or contract deployer on Sei, with no special permissions required. No pointer or association setup beyond normal EVM/Cosmos address linkage is needed to trigger the `send` precompile method or a `BankMsg::Send` from a contract.

### Recommendation
Move the `IsInDenomAllowList` (and ideally `BlockedAddr`) enforcement into `BaseSendKeeper.SendCoins`/`InputOutputCoins` themselves (or a shared internal helper always invoked by them), rather than relying on each caller (`msgServer.Send`, `MsgMultiSend`, the EVM bank precompile, and the wasmd `BankCoinTransferrer`) to independently perform the check. This guarantees the allow list is enforced uniformly regardless of the transfer path.

### Proof of Concept
1. Chain admin creates a tokenfactory denom `factory/{admin}/kyc` and sets `AllowList{Addresses: [A]}` via `SetDenomAllowList`, matching the pattern shown in [7](#0-6) , so only address `A` may send/receive it.
2. Fund address `A` with the `factory/{admin}/kyc` denom.
3. Address `A` (associated with an EVM address) calls the `IBank` precompile's `send(fromAddress=A, toAddress=B, denom="factory/{admin}/kyc", amount=X)` where `B` is not in the allow list, as exercised in [8](#0-7)  (the existing test only shows failure due to unrelated errors, not the allow-list check, because the precompile `send` function never calls `IsInDenomAllowList`).
4. The transfer succeeds because `p.bankKeeper.SendCoins` in [9](#0-8)  does not check the allow list, unlike the equivalent `MsgSend` path in [10](#0-9) .
5. Equivalently, a CosmWasm contract holding the restricted denom can emit a `BankMsg::Send` to a non-allow-listed address, and `BankCoinTransferrer.TransferCoins` in [6](#0-5)  will execute it without an allow-list check.

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
