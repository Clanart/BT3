### Title
Silent failure of `Message::mergeFrom()` on internal re-encode/decode error due to no-op `PBPHP_ASSERT` in production builds - (File: `php/ext/google/protobuf/message.c`)

### Summary
`PHP_METHOD(Message, mergeFrom)` re-serializes the source message with `upb_Encode()`, checks that status, then merges the resulting bytes into the destination message with `upb_Decode()`. The decode result is captured in `ok` but is only verified through `PBPHP_ASSERT(ok)`, a macro that compiles to a complete no-op unless the extension was built with `PBPHP_ENABLE_ASSERTS` defined. In a standard production build, a failed `upb_Decode()` is silently ignored: the PHP method returns normally as if the merge succeeded, while the destination message may be left partially merged or completely unmodified.

### Finding Description [1](#0-0) 

The relevant code:
```c
upb_EncodeStatus status = upb_Encode(from->msg, l, 0, arena, &pb, &size);
if (!Message_checkEncodeStatus(status)) return;

ok = upb_Decode(pb, size, intern->msg, l, NULL, 0, arena) ==
     kUpb_DecodeStatus_Ok;
PBPHP_ASSERT(ok);
``` [2](#0-1) 

Unlike the encode path, which is checked via `Message_checkEncodeStatus()` and throws a PHP exception on failure (`kUpb_EncodeStatus_OutOfMemory`, `kUpb_EncodeStatus_MaxDepthExceeded`, `kUpb_EncodeStatus_MissingRequired`, etc.), the decode result `ok` is never propagated to the caller with an exception. It is instead passed to `PBPHP_ASSERT`, which is defined as:
```c
#ifdef PBPHP_ENABLE_ASSERTS
#define PBPHP_ASSERT(x) do { if (!(x)) { fprintf(...); abort(); } } while (false)
#else
#define PBPHP_ASSERT(x) do { } while (false && (x))
#endif
``` [3](#0-2) 

`PBPHP_ENABLE_ASSERTS` is not defined by default and is only set in the test build script, not in the release/packaged build configuration for the PHP extension. In a release build the `ok` variable is entirely discarded (`while (false && (x))` never evaluates `x` for side effects other than to silence "unused variable" warnings), so a `upb_Decode` failure is not surfaced to the calling PHP code in any way — the method simply returns.

This mirrors the reported Vault bug's failed invariant precisely: the caller assumes "the operation either succeeds or reports failure," a status/boolean result is computed, and that result is discarded/unchecked in the code path that actually executes in production, causing the operation to appear to succeed when it actually failed or partially failed.

### Impact Explanation
If `upb_Decode()` fails while merging (e.g., a `kUpb_DecodeStatus_OutOfMemory`, `kUpb_DecodeStatus_MaxDepthExceeded`, or `kUpb_DecodeStatus_MissingRequired`/malformed re-encoded bytes scenario reachable through arena exhaustion or deeply nested messages produced by the re-encode step), the destination message's state after `mergeFrom()` is undefined/partial rather than a clean pre-merge or fully-merged state, and the caller receives no exception or error indication. Application code that trusts `mergeFrom()` to either succeed or throw will silently operate on an incompletely merged message — a data-integrity issue analogous to the unnoticed stuck-funds condition in the Vault report, though here the "value" at risk is application data correctness rather than tokens.

### Likelihood Explanation
This is reachable purely through the public PHP API `Message::mergeFrom($other)` using ordinary, schema-valid, bounded messages — no privileged access or malformed schema is required. The triggering condition is that `upb_Decode` returns non-`kUpb_DecodeStatus_Ok` on the arena-encoded intermediate buffer, which can occur under legitimate resource-limit conditions (e.g., max recursion/depth limits, missing-required-field mismatches between message versions) reachable by an ordinary caller supplying bounded input, without needing enormous or unbounded payloads.

### Recommendation
Check the `upb_Decode` status explicitly (as is already done for `upb_Encode`) and throw a PHP exception on failure instead of relying on a debug-only assertion:
```c
upb_DecodeStatus decode_status =
    upb_Decode(pb, size, intern->msg, l, NULL, 0, arena);
if (decode_status != kUpb_DecodeStatus_Ok) {
  zend_throw_exception_ex(NULL, 0, "Error merging message");
  return;
}
```
This ensures `mergeFrom()` never silently returns "success" on a real decode failure in release builds.
