**Rationale:** `get_address` in `stacks-codec/src/transaction.rs` (lines 1620-1627) is a pure, stateless accessor:

```rust
pub fn get_address(&self, mainnet: bool) -> StacksAddress {
    if mainnet {
        self.address_mainnet()
    } else {
        self.address_testnet()
    }
}
``` [1](#0-0) 

It simply computes a `StacksAddress` from the spending condition's hash-mode/public-key(s), delegating to `address_mainnet()`/`address_testnet()` [2](#0-1) . It takes no account balance, fee, nonce, or `AssetMap` as input or output, and has no side effects. There is no "balance snapshot," no fee-charging logic, and no ordering relative to payload execution anywhere in this function or its call chain within `stacks-codec` — that logic (fee deduction, `check_transaction_postconditions`, `AssetMap` commit, nonce checks) lives entirely in `stackslib`'s chainstate/transaction-processing code, which this function does not touch or influence.

The premised equality — "balance change == fee + authorised spends against the pre-tx balance" being broken by `get_address` charging fee against a post-payload balance — has no code path through this function to validate or falsify; `get_address` cannot cause a balance snapshot to be taken before or after a payload spend because it performs no balance snapshot at all. The question's premise does not correspond to what this function does, so there is no vulnerability to report here.
