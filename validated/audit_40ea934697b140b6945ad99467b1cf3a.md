## Analysis

Confirmed: `stakeFor`/`withdrawFor` in `BribeRewardPool.sol` have no cooldown or lock-up period, and `vote()`/`unvote()` in `WombatBribeManager.sol` have no time restriction preventing a stake-then-immediately-unstake within the same block/epoch cycle [1](#0-0) [2](#0-1) .

### Title
Reward-sniping via front-running `castVotes()`/`donateRewards()` to steal a disproportionate share of bribe rewards - ([File: rewards/BribeRewardPool.sol], [File: wombat/WombatBribeManager.sol])

### Summary
The reported bug class is: an unprivileged party front-runs a pending transaction that fixes a profit split, temporarily inflates their own share parameter to capture a disproportionate amount of the value being distributed, then reverts their share back afterward — with zero cost to themselves beyond gas. The same mechanical pattern exists in `WombatBribeManager`/`BribeRewardPool`'s bribe-reward accounting.

### Finding Description
`BribeRewardPool` (via `BaseRewardPoolV2`) computes reward shares using a standard `rewardPerTokenStored` accumulator model: when new rewards are injected (via `queueNewRewards`, called from `WombatBribeManager.castVotes()` → `WombatStaking.vote()`), the entire injected amount is divided by whatever `totalStaked()` (i.e. `totalSupply` of votes) happens to be at that exact moment [3](#0-2) .

`WombatBribeManager.vote()` and `unvote()` let any vlMGP holder immediately increase (`stakeFor`) or decrease (`withdrawFor`) their staked "vote" balance in a pool's `BribeRewardPool`, with no cooldown, minimum staking duration, or block delay [2](#0-1) . `castVotes()` is a permissionless, publicly-visible (mempool) function that harvests bribes and calls `queueNewRewards`, instantaneously bumping `rewardPerTokenStored` for the pool based on `totalStaked()` at call time [4](#0-3) [5](#0-4) .

An attacker can watch the mempool for a pending `castVotes()` (or `donateRewards()`, which is entirely permissionless [6](#0-5) ) call that will inject a large bribe/reward amount into a specific pool's `BribeRewardPool`, front-run it with `vote()` to add a large delta of vlMGP stake into that pool (diluting existing long-term voters' pending share and claiming a large chunk of the newly injected reward for themselves), and then immediately back-run with `unvote()` to withdraw their inflated stake — restoring their vote weight to its original value with no lasting exposure, analogous to Mallory calling `updateTerms()` then reverting it in the original report.

### Impact Explanation
This directly transfers bribe-reward value away from genuine long-term voters to the front-runner: legitimate voters who supplied liquidity/vote-weight over the accrual period receive less than their fair share of bribes, while the attacker who staked for a single transaction captures a share proportional to the reward event rather than to their time-weighted contribution. This is a theft of unclaimed yield rightfully due to other unprivileged users, one of the accepted impact categories.

### Likelihood Explanation
`castVotes()` is a public function anyone can call (with a caller fee incentive), meaning its calls and effects are visible in the mempool ahead of execution, and `vote()`/`unvote()` are permissionless, cooldown-free operations available to any vlMGP/BribeRewardPool participant, making the attack straightforward to execute for any observant unprivileged wallet with modest vlMGP.

### Recommendation
Introduce a minimum staking duration or cooldown between `vote()` (stake) and `unvote()`/vote-decrease (withdraw) actions in `WombatBribeManager`, or use a time-weighted average balance for reward-per-token computations in `BribeRewardPool`/`BaseRewardPoolV2` so that stakes added just before a `queueNewRewards`/`castVotes` call cannot capture a full pro-rata share of freshly injected rewards.

### Proof of Concept
1. Mallory holds vlMGP and has an existing small vote in pool `X`.
2. She observes an in-flight `castVotes()` transaction (or a large `donateRewards()` call) in the mempool that will inject a large bribe reward `R` into pool `X`'s `BribeRewardPool`.
3. Mallory front-runs with `WombatBribeManager.vote([X], [+largeDelta])`, which calls `IBribeRewardPool(pool.rewarder).stakeFor(mallory, largeDelta)`, sharply increasing `totalSupply` in `BribeRewardPool` right before the reward injection [7](#0-6) .
4. The victim's `castVotes()`/`donateRewards()` executes, calling `_provisionReward`, which computes `rewardPerTokenStored += (R * 10**decimals) / totalStaked()` using the now-inflated `totalStaked()` [8](#0-7) .
5. Mallory immediately calls `unvote(X)`, triggering `withdrawFor(mallory, largeDelta, true)`, which calls `updateRewards` (crediting her the inflated share of `R`) then `_getReward` to claim it, and removes her stake entirely [9](#0-8) [10](#0-9) .
6. Mallory nets a disproportionate share of `R` for a single-transaction stake, at the expense of long-term voters in pool `X`, and reverts her vote weight back to the original amount with no lasting cost besides gas.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();

        }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
