## Finding

CVE-2020-26260 in BookStack is an SSRF bug class: a user with only page-edit permission can set an image URL that the server-side exporter later fetches automatically, letting the app make requests to attacker-chosen destinations. Chia's DataLayer mirror/subscription mechanism has the same shape: an unprivileged, unauthenticated-to-the-victim party can register an arbitrary URL on-chain for *any* store, and any node's DataLayer service that syncs that store will later issue outbound HTTP requests to that URL automatically, without any host/scheme restriction.

### Title
Unrestricted SSRF via attacker-controlled DataLayer mirror URLs fetched automatically during store sync - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can submit a standard spend that creates a DataLayer "mirror" coin referencing an arbitrary `launcher_id` (store id) they do not own, embedding attacker-chosen URLs in the coin memo. `DataLayerWallet.create_new_mirror()` performs no validation of the URL and no check that the caller owns the referenced store. `DataLayer.update_subscriptions_from_wallet()` later reads these on-chain mirror URLs for any store id it is tracking/subscribed to and stores them as sync servers. `fetch_and_validate()` / `http_download()` then perform an aiohttp `GET` directly against `server_info.url + "/" + filename` with no restriction on scheme, host, or address range, so any DataLayer service that subscribes to or owns a store an attacker has "mirrored" will make outbound requests to whatever destination the attacker chose.

### Finding Description
- `DataLayerWallet.create_new_mirror()` builds a standard coin spend whose memo is `[launcher_id, *urls]`; there is no ownership check tying `launcher_id` to a store the caller controls, and `urls` is not validated in any way. [1](#0-0) 
- The wallet RPC endpoint `dl_new_mirror` exposes this directly to any wallet client with no additional authorization beyond paying the fee/amount. [2](#0-1) 
- `DataLayer.update_subscriptions_from_wallet()` pulls the on-chain mirror URLs for a given `store_id` and feeds them into the local subscription/server table, with only a trailing-slash strip — no scheme/host validation. [3](#0-2) 
- `fetch_and_validate()` iterates the (attacker-influenced) server list and calls `insert_from_delta_file()`, which ultimately calls `http_download()`. [4](#0-3) 
- `http_download()` performs `session.get(server_info.url + "/" + filename, ...)` with no allowlist of hosts/IP ranges (e.g., no blocking of loopback, link-local/cloud-metadata, or private RFC1918 ranges) and no restriction on scheme beyond what aiohttp itself supports. [5](#0-4) 
- The project's own internal notes acknowledge mirror/plugin URLs are untrusted inputs, but only in the context of *data* trust (validated via Merkle root), not in the context of *SSRF* (the request itself is still made regardless of whether the returned data is later rejected). [6](#0-5) 

This is structurally identical to the BookStack bug class: a low-privilege actor supplies a URL that is not fetched by themselves but by the server/node on their behalf, at a time and from a context the actor does not control, enabling requests into the node operator's internal network or cloud metadata services.

### Impact Explanation
A DataLayer node that owns or subscribes to a store is caused to issue outbound HTTP GET requests to arbitrary attacker-chosen destinations (e.g., internal admin interfaces, `169.254.169.254` cloud metadata endpoints, or other local-network-only services) purely because an unrelated third party published a mirror record for that store id on-chain. This can be used to probe/interact with internal-only services reachable from the victim's host, and error/timing differences in the DataLayer logs can leak information about the internal network topology (port-scanning primitive). Because the request goes out from the node process, this could also be leveraged against local-only RPC/admin endpoints that lack additional authentication and are only protected by "not reachable from the internet."

### Likelihood Explanation
Creating a mirror coin only requires an ordinary wallet transaction (no special permission, no ownership of the referenced store) and is exposed via a documented RPC/CLI (`dl_new_mirror`, `data add_mirror`). Any node participating in DataLayer sync for a targeted store (which itself may be a store the attacker also created cheaply) will periodically call `update_subscriptions_from_wallet` and `fetch_and_validate` as part of its normal background loop, with no operator interaction required.

### Recommendation
- Validate mirror/subscription URLs before they are added to the sync server list: enforce an explicit scheme allowlist (e.g., `http`/`https` only) and reject loopback, link-local, and private/reserved IP ranges (RFC1918, `169.254.0.0/16`, `::1`, etc.) unless explicitly configured otherwise by the operator.
- Consider requiring operator opt-in / an allowlist of trusted mirror hosts rather than trusting arbitrary on-chain-published URLs by default.
- Disable HTTP redirects (or re-validate the redirect target against the same allowlist) in `http_download()` and the plugin `handle_download`/`download` HTTP calls.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (or `chia data add_mirror`) with `launcher_id` set to a victim's DataLayer store id (public, discoverable on-chain) and `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-admin.local/..."]`, paying a minimal fee/amount. [2](#0-1) 
2. Once confirmed, any node's DataLayer service that owns or subscribes to that `launcher_id` runs its periodic sync loop, calls `update_subscriptions_from_wallet(store_id)`, which reads the attacker's mirror URLs via `dl_get_mirrors` and stores them as available servers. [3](#0-2) 
3. `fetch_and_validate()` selects that server and calls `insert_from_delta_file` → `http_download`, causing the victim node to issue `GET http://169.254.169.254/latest/meta-data/<filename>` (or the internal-admin URL) automatically, with no scheme/host restriction. [5](#0-4)

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
