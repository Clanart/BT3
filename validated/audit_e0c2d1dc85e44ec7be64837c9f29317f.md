### Title
`SmartWomConvert.smartConvert` hardcodes `_minRec = _amountIn`, causing a manipulable-price revert that propagates through `WombatStaking.deposit`/`depositLP`/`withdraw`/`harvest` - (File: wombat/SmartWomConvert.sol)

### Summary
`smartConvert()` in `wombat/SmartWomConvert.sol` calls `_convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode)`, forcing the internal buyback/deposit leg to return at least `_amountIn` mWOM or revert with `MinRecNotMatch`. Because `WombatStaking._sendRewards` calls `IConverter(smartWomConverter).smartConvert(feeAmount, 0)` with no `try/catch`, any revert here bubbles up through `_toMasterWomAndSendReward`, which is invoked from `deposit`, `depositLP`, `withdraw`, and `harvest`, blocking all of these user-facing entry points.

### Finding Description
`smartConvert` reads the pool state via `currentRatio()` [1](#0-0)  and, when the mWOM/WOM price is below `buybackThreshold`, computes a `convertRatio` and forwards to `_convertFor` with `_minRec` hardcoded to the full `_amountIn`: [2](#0-1) 

Inside `_convertFor`, the buyback portion is swapped through the router with no slippage protection at the swap level (`amountOutMin = 0`), and the only safety check is the aggregate comparison against `_minRec`: [3](#0-2) 

If the actual executed swap (subject to the Wombat stableswap curve's haircut/fee and price impact from `amountToSwap`) yields less mWOM than the WOM spent, `convertAmount + amountRec < _minRec` and the whole call reverts with `MinRecNotMatch`.

This function is invoked unconditionally (no try/catch) from `WombatStaking._sendRewards` whenever a WOM reward fee is configured with `isMWOM = true` and `smartWomConverter` is set: [4](#0-3) 

`_sendRewards` is called from `_toMasterWomAndSendReward`, which is itself invoked by `deposit`, `depositLP`, `withdraw`, and `harvest`: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

`harvest()` is publicly callable by anyone as long as the pool is active (`_onlyActivePool`, which only checks `poolInfo.isActive`, not `msg.sender`) [9](#0-8) , so an unprivileged EOA can trigger this path directly by calling `harvest(_lpToken)` after manipulating the WOM/mWOM pool price via a normal swap (no special privilege required to trade in an AMM pool). `deposit`/`depositLP`/`withdraw` are gated to the registered `PoolHelper` contract (`_onlyPoolHelper`/`_onlyActivePoolHelper`), but any end-user calling those user-facing helper contracts ultimately reaches the same vulnerable `_toMasterWomAndSendReward` → `_sendRewards` → `smartConvert` path.

### Impact Explanation
If the buyback swap's actual output underperforms 1:1 (plausible under price manipulation, pool imbalance/haircut, or size-driven slippage even when the marginal/quoted price looked favorable), `smartConvert` reverts. Since there is no `try/catch` around this external call in `_sendRewards`, the revert propagates and blocks `deposit`, `depositLP`, `withdraw`, and `harvest` for the entire pool — i.e., temporary freezing of principal deposits/withdrawals for all users of that pool, matching the "High – Temporary freezing of funds for at least 24 hours" Immunefi impact class, since the condition persists until the pool's cash/liability and WOM/mWOM pool price recover or governance intervenes (e.g., by unsetting `smartWomConverter` or adjusting `buybackThreshold`/`ratio`).

### Likelihood Explanation
- No privileged role is required: swapping in the WOM/mWOM pool and calling `harvest()` are both public actions.
- The condition is contingent on there being nonzero WOM reward fee flowing through `_sendRewards` with `isMWOM = true` and `smartWomConverter` configured, plus the buyback swap underperforming 1:1 (dependent on the underlying Wombat AMM's specific curve/haircut behavior and the size relationship between `maxSwapAmount()` and the attacker-influenced cash/liability of `womAsset`).
- The exact numeric conditions under which the swap output falls below the 1:1 floor depend on the Wombat core `IWombatPool`/`IAsset` stableswap math, which is external to this repo and was not fully traceable in this index; the DoS mechanism itself (hardcoded `_minRec = _amountIn`, no try/catch, revert propagation through four core entry points) is confirmed directly in the code, but a fully quantified numeric PoC of the price manipulation trigger could not be completed with available context.

### Recommendation
- Do not hardcode `_minRec = _amountIn` in `smartConvert`; instead compute an economically meaningful minimum (e.g., based on `estimateTotalConversion` with an allowed slippage tolerance), or make the minimum configurable/looser than strict 1:1.
- Wrap the `smartConvert` call in `WombatStaking._sendRewards` in a `try/catch`, falling back to direct `IMWom.deposit` (as already done when `smartWomConverter == address(0)`) so a reverting buyback never blocks `deposit`/`depositLP`/`withdraw`/`harvest`.
- Add slippage protection at the router call (`swapExactTokensForTokens` currently passes `amountOutMin = 0`) combined with a bounded acceptable loss rather than an all-or-nothing revert.

### Proof of Concept
Hardhat/Foundry test plan (WOM/mWOM Wombat pool + `WombatStaking` + `SmartWomConvert` deployed against a mainnet fork or mocked `IWombatRouter`/`IAsset`):
1. Deploy/fork the WOM/mWOM Wombat pool, `SmartWomConvert`, and `WombatStaking` with a WOM-reward fee configured with `isMWOM = true` and `smartWomConverter` set.
2. As an unprivileged attacker EOA, execute a swap in the WOM/mWOM pool (e.g., sell mWOM for WOM) sized to push `currentRatio()` below `buybackThreshold` while leaving `maxSwapAmount()`/pool cash-liability imbalance such that a subsequent buyback swap of `amountToSwap` WOM→mWOM returns less than `amountToSwap` mWOM (verify via `IWombatRouter.getAmountOut` before and after the manipulation swap).
3. In the same transaction (attacker's own contract), accrue pending WOM rewards on a registered pool and call `WombatStaking.harvest(_lpToken)`.
4. Assert the transaction reverts with `MinRecNotMatch` inside `SmartWomConvert._convertFor`.
5. Assert that legitimate user calls to `deposit`/`depositLP`/`withdraw` on the same pool (via their `PoolHelper`) also revert for as long as the manipulated price condition persists, demonstrating the funds-freezing DoS.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
