Confirmed: `urlsMatch` (used for `urlMatchesCloneURL` and via `doesRepositoryMatchUrl`) does case-sensitive comparison, unlike the sibling function `urlMatchesRemote` which explicitly uses `caseInsensitiveEquals`. This is a direct analog to the AMM `token_type` bug: two logically-identical GitHub identities (host/owner/repo names, which GitHub treats case-insensitively) are treated as distinct by one code path while the parallel path treats them correctly, creating an inconsistent identity check that attacker-controlled deep-link URLs can exploit.

### Title
Case-sensitive repository identity comparison in `urlsMatch` lets a crafted deep-link bypass existing-repository/PR matching - (File: `app/src/lib/repository-matching.ts`)

### Summary
GitHub Desktop resolves `x-github-client://openRepo/...` (and `github-mac://`/`github-windows://`) deep links, as well as "Open in Desktop" PR links, by parsing the target URL and comparing it against the repositories/PR endpoints the user already has tracked. This comparison is implemented in two different ways: `urlMatchesRemote` normalizes hostname/owner/name with `caseInsensitiveEquals` before comparing [1](#0-0) , but the sibling function `urlsMatch` (used by `urlMatchesCloneURL` and transitively by `Dispatcher.doesRepositoryMatchUrl`) compares the parsed `hostname`/`owner`/`name` fields with strict `===`, with no case folding [2](#0-1) . Since GitHub owner/repo names are case-insensitive on GitHub.com/GHE, two URLs that refer to the exact same repository but differ only in casing are treated as different identities by this path, mirroring the reported `TokenType::eq` bug where two logically-identical assets (differing only in case) were treated as distinct.

### Finding Description
`Dispatcher.doesRepositoryMatchUrl` uses `urlsMatch` to decide whether an attacker/GitHub-controlled URL (arriving via a protocol handler deep link or a PR's `clone_url`/`html_url` from the API) refers to a repository the user already has open in Desktop [3](#0-2) . This same broken comparison is reached from `openOrCloneRepository`, which is the fallback path invoked for `open-repository-from-url` deep links and CLI `clone-url` actions [4](#0-3) , and from `getRepositoryFromPullRequest`, which tries to find an already-open repository matching a PR's head/base repo before falling back to clone [5](#0-4) .

Because `urlsMatch` derives its identifiers from `parseRepositoryIdentifier`/`parseRemote`, which preserve the case exactly as it appears in the URL [6](#0-5) , and then compares them with plain `===` [7](#0-6) , an attacker who controls the casing of a deep-link URL or a PR repository URL can make Desktop fail to recognize it as the repository the user already has cloned. The existing, correct guard (`caseInsensitiveEquals`) that protects `urlMatchesRemote` is simply absent from `urlsMatch`'s code path, so it provides no protection here.

### Impact Explanation
When the identity check spuriously reports "no match" for what is actually the same repository, Desktop falls through to the clone path (`openOrCloneRepository`) and shows the "Clone Repository" popup pre-filled with the attacker-influenced URL [8](#0-7) , or, for the PR-open flow, `openPullRequestFromUrl` proceeds to `_checkoutPullRequest` against a freshly-cloned/looked-up repository instead of the already-tracked one [9](#0-8) . This can cause the user to end up with two disjoint local clones of the same GitHub repository under Desktop's management, one of which is not the repository the user believes they are interacting with — a form of "silent corruption of what the user commits or pushes" since subsequent commits/pushes made in the unintended clone (or against the wrong PR head) diverge from the user's actual intended remote/branch without an explicit warning that this is a duplicate of an existing tracked repository.

### Likelihood Explanation
Exploitation only requires a user to click a crafted `x-github-client://openRepo/...` link (or `github-mac://`/`github-windows://`, or receive a PR API payload whose `clone_url`/`html_url` casing differs from the repo the user already cloned) — an action fully within GitHub Desktop's documented deep-link/PR-open flow. GitHub tolerates arbitrary case in the owner/name segments of both HTML and API clone URLs, so an attacker (e.g., a malicious PR author, or a manipulated link shared with the victim) can trivially produce a differently-cased but functionally identical URL without needing any special access.

### Recommendation
Make `urlsMatch` use the same case-insensitive comparison already implemented for `urlMatchesRemote`: normalize `hostname`, `owner`, and `name` with `caseInsensitiveEquals` (or lowercase them before comparing) instead of `===` [7](#0-6) . Since `urlMatchesCloneURL` and `doesRepositoryMatchUrl` both rely on `urlsMatch`, this single fix closes the gap for the deep-link, CLI clone, and PR-lookup flows simultaneously.

### Proof of Concept
1. Open GitHub Desktop and clone `https://github.com/octocat/Hello-World` (tracked with owner `octocat`, name `Hello-World`).
2. Craft a deep link: `x-github-client://openRepo/https://github.com/OCTOCAT/hello-world` (case-flipped owner/name, same actual repository).
3. Have the user click the link (or trigger it via `github-mac://openRepo/...` on macOS). `handleAppURL` → `parseAppURL` → `openRepositoryFromUrl` → `openOrCloneRepository` is invoked with the case-flipped URL [10](#0-9) .
4. Inside `openOrCloneRepository`, `repositories.find(r => this.doesRepositoryMatchUrl(r, url))` calls `urlsMatch('https://github.com/octocat/Hello-World', 'https://github.com/OCTOCAT/hello-world')`, which parses to `{owner:'octocat', name:'Hello-World'}` vs `{owner:'OCTOCAT', name:'hello-world'}` and returns `false` on the `===` comparisons [2](#0-1) , even though this is objectively the same GitHub repository.
5. Desktop shows the Clone popup instead of switching to the already-open repository, and if the user proceeds, a second, disconnected local clone of the same repository is created and tracked by Desktop.

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }

export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}
