### Title
`ReceivedOutput::read` accepts attacker-chosen offset/script/value with no consistency check, letting forged bytes produce unspendable or fee-burning "received" outputs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
The Chrome bug hid security-critical information (the true origin/URL) from the user. The Serai analog hides the true *ownership and value* of a Bitcoin output: `ReceivedOutput::read` deserializes the scalar `offset`, the `TxOut`, and the `OutPoint` as three independent fields and never verifies that `output.script_pubkey == p2tr(key + G*offset)` nor that the declared `value` matches the on-chain output. Any consumer that deserializes `ReceivedOutput`s from an untrusted channel (they are explicitly a `read` sink, with `serialize`/`write` round-tripping over the wire) can be fed an output whose identity is falsified.

### Finding Description
`ReceivedOutput::read` performs only syntactic decoding [1](#0-0) :

```rust
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  ...
  output = TxOut::consensus_decode(&mut buf_r)...;
  outpoint = OutPoint::consensus_decode(&mut buf_r)...;
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

Compare with `Scanner::scan_transaction`, the only trusted producer, which derives `offset` *from* the script match (`self.scripts.get(&output.script_pubkey)`) and binds `outpoint` to the real txid/vout [2](#0-1) . The deserializer performs none of that binding: an attacker controls all three fields.

Two concrete corruptions are possible:

1. **Wrong offset/script pairing.** Attacker supplies `offset` `o` with a `TxOut` whose `script_pubkey` is `p2tr(key + G*o')` for `o' != o` (or an arbitrary script the node cannot spend at all). Downstream signing uses `offset()` to derive the spend key, so the "received" funds are reported but are not spendable under the supplied offset.
2. **Wrong value.** `TxOut.value` is attacker-controlled. `SignableTransaction`/sighash code uses the received output's value for fee/change math and the `Prevouts::All` commitment; an inflated value produces an invalid transaction or an overpayment burned to fees; a deflated value silently miscounts funds.

### Impact Explanation
Falsified-balance reporting: the protocol can be told it received funds that are not spendable (unspendable script or mismatched offset), or sign transactions on fabricated input values, burning the difference to miners or producing transactions that can never confirm while the accounting layer believes the spend succeeded. Matches the accepted criterion "funds reported received that are not spendable."

### Likelihood Explanation
Reachable only where `ReceivedOutput::read` consumes bytes an unprivileged party can influence (relayed/persisted output claims). The in-repo producers are trusted (`scan_transaction`), so exploitability depends on an integrator or peer-fed deserialization path — hence Medium, mirroring the CVSS 4.3 UI:R source.

### Recommendation
Add a verification step: either store the group key on `ReceivedOutput` (or pass it to `read`) and assert `p2tr_script_buf(key + GENERATOR*offset) == Some(output.script_pubkey)`, or expose a `ReceivedOutput::verify(key)` that integrators must call after `read`. Reject non-canonical scalars already handled by `read_F`; additionally confirm the `OutPoint`'s referenced `TxOut` matches when the spending transaction is built.

### Proof of Concept
```rust
// Given group key `key` and a real on-chain output paying p2tr(key + G*o'):
let honest = scanner.scan_transaction(&tx).pop().unwrap(); // offset o'
let mut forged = ReceivedOutput::read(
  &mut {
    // offset o (wrong), same TxOut (script is p2tr(key + G*o')), same outpoint
    let mut v = (honest.offset() + Scalar::ONE).to_bytes().to_vec();
    v.extend(serialize(honest.output()));
    v.extend(serialize(honest.outpoint()));
    v
  }.as_slice(),
).unwrap();
// read() accepts it; forged.offset() != the offset that actually spends the output
assert_ne!(p2tr_script_buf(key + G*forged.offset()).unwrap(), forged.output().script_pubkey);
```
