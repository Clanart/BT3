### Title
Unbounded, self-inflicted gasless bundle spam lets an attacker force the block proposer to pay real gas/lending cost while paying negligible fees - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`)

### Summary
The gasless module (KIP-247) lets any unprivileged sender submit an `ApproveTx`/`SwapTx` pair that the block proposer must front real KAIA for via a `LendTx` generated from the proposer's own key [1](#0-0) . This is structurally the same actor relationship as the JOJO report: an off-chain/privileged party (there, the matching engine; here, the block proposer) spends real, metered resources (gas, KAIA) on behalf of an unprivileged counterpart whose own cost is comparatively tiny and attacker-controlled. The `lendAmount`/`repayAmount` accounting is only checked as a self-consistency invariant at pool-admission time (`VerifyExecutable`), not tied to worst-case execution outcome, and pool-level economic/anti-spam checks (`ShouldCheckToken`, `ShouldCheckSwapAmount`, sender-code check) are optional/config-gated [2](#0-1) .

### Finding Description
`GetLendTxGenerator`/`lendAmount` compute the amount the proposer must lend the sender to cover both the `ApproveTx` and `SwapTx` fees: [3](#0-2) 

The proposer's `LendTx` is signed with the node's own key and actually transfers KAIA on-chain from the proposer's balance to the gasless sender before the `ApproveTx`/`SwapTx` run [4](#0-3) . The bundle that wraps `[LendTxGenerator, ApproveTx?, SwapTx]` is built with `targetRequired = false`: [5](#0-4) 

and `Bundle` itself has no notion of "all-or-nothing" execution — it is purely a scheduling/ordering construct (`TargetTxHash`, `TargetRequired`, conflict detection), not an atomic-revert guarantee tying `LendTx` success to `SwapTx` success: [6](#0-5) 

Balance checks for gasless senders are explicitly skipped ("Sender balance check is omitted for gasless transactions") [7](#0-6) , and the deeper economic sanity checks in `checkBalanceForSwap`/`checkBalanceForApprove` (token balance, allowance, required `amountIn` vs `minAmountOut`) are all gated behind optional config flags (`ShouldCheckToken`, `ShouldCheckSwapAmount`, `ShouldCheckSenderCode`) [8](#0-7) . Pool admission relies primarily on the self-referential `VerifyExecutable`/`repayAmount` arithmetic check [9](#0-8) , which validates that the fields the attacker supplies are internally consistent, but says nothing about whether the swap will actually succeed on-chain (AMM slippage, front-running, price movement between validation and inclusion, or the sender simply never having the token balance to begin with when `ShouldCheckToken` is disabled).

The only throttle against an attacker submitting large numbers of these bundles is `GetMaxBundleTxsInPending`/`GetMaxBundleTxsInQueue`, a configurable per-pool count limit [10](#0-9) [11](#0-10) , and the module's own README acknowledges the bundle is dropped only if it *conflicts* with a previous bundle, not if it is merely unprofitable for the proposer [12](#0-11) .

### Impact Explanation
Exactly analogous to the JOJO issue: an unprivileged transaction sender can cause the proposer (the party bearing real KAIA/gas cost, analogous to the off-chain engine in JOJO) to repeatedly spend real value (the `LendTx` KAIA transfer plus the gas of processing three chained transactions) while the attacker's own cost is a single cheap swap transaction whose repayment can fail to materialize if the swap does not go through as expected (slippage, stale price quotes, or disabled checks). Because the bundle is non-atomic (`TargetRequired: false` and no rollback semantics tying the lend to swap success), a proposer can lend KAIA that is not fully recouped, and can be forced to do this repeatedly up to the configured pending/queue limits, imposing an economic drain disproportionate to what the attacker pays. This is a fee/value-movement abuse vector (unauthorized value transfer to the attacker's benefit, funded by the block proposer) reachable purely from crafted `ApproveTx`/`SwapTx` submissions by any account — no privileged or malicious-node access required.

### Likelihood Explanation
Medium. The attack requires only crafting valid-looking `ApproveTx`/`SwapTx` pairs that pass `VerifyExecutable`'s self-consistency checks; whether the optional checks (`ShouldCheckToken`, `ShouldCheckSwapAmount`) are enabled in production configuration determines how easy it is to submit an intentionally-losing swap (e.g., where the token/allowance state changes between validation and block inclusion, or minAmountOut is set to barely exceed amountRepay and a sandwich/slippage event causes the swap to underperform). Repeated submission is bounded by `MaxBundleTxsInPending`/`MaxBundleTxsInQueue`, which lowers throughput but does not eliminate the economic asymmetry per bundle, and the attack can be repeated across blocks indefinitely.

### Recommendation
- Make the lend/repay relationship atomic: either roll back the `LendTx`'s value transfer if the subsequent `SwapTx` fails to produce the required repayment (e.g., via an escrow/refund pattern enforced at the protocol/EntryPoint contract level), or require the `GaslessSwapRouter` contract itself to pull repayment during the same transaction execution so the proposer is never exposed to a state where KAIA has been lent without guaranteed repayment.
- Do not treat `ShouldCheckToken`/`ShouldCheckSwapAmount`/`ShouldCheckSenderCode` as optional in production; make these mandatory pool-admission conditions, since they are the only guards against senders with insufficient balance/allowance being lent gas.
- Add a stricter global/per-sender rate limit and a minimum bonding/penalty mechanism (e.g., require attacker to post a bond or repeatedly failing senders get blacklisted) so that repeated unprofitable bundles are economically deterred beyond the current `MaxBundleTxsInPending`/`InQueue` counters.
- Re-validate `checkBalanceForSwap`'s AMM-quote-based checks (`GetAmountIn`) as close to inclusion time as possible (ideally within the same execution as the swap) to reduce the staleness window an attacker can exploit between pool admission and block building.

### Proof of Concept
Conceptual reproduction path (cannot be fully executed without a live node/AMM state, but the code path is traceable):
1. Attacker funds a throwaway EOA with a trivial ERC-20 token balance sufficient to pass `checkBalanceForApprove`/`checkBalanceForSwap` (or relies on `ShouldCheckToken=false`).
2. Attacker submits `GaslessApproveTx` + `GaslessSwapTx` with `AmountRepay` set exactly equal to `repayAmount(approveTx, swapTx)` so `VerifyExecutable` passes (`kaiax/gasless/impl/getter.go:211-266`).
3. The gasless module recognizes the pair as ready (`isSwapTxReady`/`isApproveTxReady`, `kaiax/gasless/impl/tx_pool.go:252-290`) and `ExtractTxBundles` produces `[LendTxGenerator, ApproveTx, SwapTx]` (`kaiax/gasless/impl/builder.go:28-72`).
4. The proposer's `LendTxGenerator` transfers `lendAmount` KAIA from the proposer to the attacker's address as part of block building (`kaiax/gasless/impl/getter.go:346-359`).
5. Because the bundle is not atomic (`work/builder/bundle.go:25-48`, `TargetRequired:false`), if the swap execution underperforms (e.g., attacker times the transaction so the AMM state shifts, minAmountOut just barely covers repay, or the sender's real token balance/allowance was insufficient because config-gated checks were off), the `SwapTx` can fail to produce full repayment while the `LendTx` transfer has already been executed and included, causing the proposer to bear a net KAIA loss for that bundle.
6. Attacker repeats this up to `GetMaxBundleTxsInPending()`/`GetMaxBundleTxsInQueue()` limits per block/queue window, accumulating losses to the proposer over many blocks at negligible attacker cost, mirroring the disproportionate cost/gain economics of the original JOJO gas-griefing report.

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

			return err
		}

			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

type Bundle struct {
	// each element can be either *types.Transaction, or TxGenerator
	BundleTxs []*TxOrGen

	// BundleTxs is placed AFTER the target tx. If empty hash, it is placed at the very front.
	TargetTxHash common.Hash

	// TargetRequired is true if the bundle must be executed after the target tx
	// and only if the target tx is successfully executed.
	TargetRequired bool

	// lookup map for O(1) membership checks (lazy initialized)
	txLookup map[common.Hash]int
}

func NewBundle(txs []*TxOrGen, targetTxHash common.Hash, targetRequired bool) *Bundle {
	b := &Bundle{
		BundleTxs:      txs,
		TargetTxHash:   targetTxHash,
		TargetRequired: targetRequired,
	}
	b.buildLookup()
	return b
}
