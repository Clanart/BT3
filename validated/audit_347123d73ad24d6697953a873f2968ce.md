### Title
Contract-governance path allows setting KIP-71 `LowerBoundBaseFee` / `UpperBoundBaseFee` without the cross-field consistency check enforced on header-vote governance - (File: `kaiax/gov/contractgov/impl/getter.go`)

### Summary
The bug class in the Wildcat report is: a value that is properly bounds-checked when set through one code path (market creation validated against `MinimumAnnualInterestBips`/`MaximumAnnualInterestBips`) can be set to an out-of-range/inconsistent value through a second, less-guarded code path (`setAnnualInterestBips`) that lacks the same validation. Kaia's governance-parameter system for the KIP-71 dynamic base fee bounds (`kip71.lowerboundbasefee` / `kip71.upperboundbasefee`) exhibits the same asymmetry between its two governance engines: header-vote governance and contract governance.

### Finding Description
Kaia has two engines that can set the same governance parameters, merged by `GovModule.GetParamSet`: [1](#0-0) 

1. **Header governance** validates cross-field consistency between the two KIP-71 bound parameters at vote-verification time in `checkConsistency`: a new `Kip71LowerBoundBaseFee` vote is rejected if it exceeds the current `UpperBoundBaseFee`, and a new `Kip71UpperBoundBaseFee` vote is rejected if it is below the current `LowerBoundBaseFee`: [2](#0-1) 

2. **Contract governance** (KIP-81 `GovParam` contract) reads all parameters via `contractGetAllParamsAtFromAddr` and converts them with `ParseContractCall`, which only applies each parameter's `Canonicalizer` and `FormatChecker` — no cross-parameter consistency check is performed: [3](#0-2) [4](#0-3) [5](#0-4) 

The `FormatChecker` for both `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` is `noopFormatChecker` (always returns true), so there is no per-value bound either: [6](#0-5) 

Post-Kore, `GetParamSet` lets contract-governance values silently override header-governance values for the *same* effective parameter set that is later used to compute the KIP-71 base fee: [7](#0-6) 

Consequently, a GC member with contract-governance access can call `GovParam.setParam`/`setParamIn` to set `LowerBoundBaseFee > UpperBoundBaseFee` (e.g., set `UpperBoundBaseFee` to a value below the existing `LowerBoundBaseFee`, or vice versa), a state that header governance explicitly disallows but which contract governance never checks.

### Impact Explanation
The resulting inconsistent `ParamSet` is converted directly to `KIP71Config` and fed into `NextMagmaBlockBaseFee`, the function used both to build blocks and to validate submitted blocks/headers: [8](#0-7) 

With `LowerBoundBaseFee > UpperBoundBaseFee`, the clamping logic (`parentBaseFee >= upperBoundBaseFee → clamp to upper`, `else if <= lowerBoundBaseFee → clamp to lower`) becomes ambiguous/contradictory for any `parentBaseFee` that falls between the (reversed) bounds, and the subsequent increase/decrease branches compare against a `min`/`max` semantics that assumes `lower <= upper`. This can produce a base fee that violates the documented invariant that the computed base fee always stays within `[lowerBound, upperBound]` (verified only under the assumption lower ≤ upper in the existing test suite), and it directly affects `BlockValidator.ValidateHeader`, which uses these same governance-derived bounds to validate the block's base fee. This is squarely within the allowed "governance parameters"/"state transition and gas/burn accounting" reachable-path category, since a bad/malformed base-fee bound feeding directly into header validation and block assembly can cause acceptance-of-invalid-block or fee-miscalculation risk.

### Likelihood Explanation
Likelihood is Medium: contract governance (KIP-81) is intended to be usable by permissioned GC members without the additional per-vote consistency gate that header governance enforces, so the "bypass validation via a second entry point" pattern is directly present in the code, mirroring the audited Wildcat vulnerability exactly (one path validated, a functionally equivalent second path is not). It requires GC voting/contract-owner privileges to trigger (analogous to the "borrower" role in the original finding, which was also a privileged role relative to protocol-level bounds), not an arbitrary unprivileged sender.

### Recommendation
Add the same cross-field consistency check used in `headergov`'s `checkConsistency` to the contract-governance ingestion path — either in `ParseContractCall`/`PartialParamSet.Add`, or as a final consistency pass on the merged `ParamSet` in `GovModule.GetParamSet`/`contractGovModule.GetParamSet`, rejecting or falling back to defaults when `LowerBoundBaseFee > UpperBoundBaseFee`.

### Proof of Concept
Not independently executable from the available index (no direct test harness call reproducing on-chain `GovParam.setParam` with reversed bounds was found), but the code path is traceable end-to-end:
1. GC member calls `GovParam.setParam("kip71.upperboundbasefee", true, <value below current lowerboundbasefee>, activation)` on the on-chain `GovParam` contract (as exercised generically in `tests/gov_contract_test.go`'s `deployGovParamTx_setParamIn` helper) — [9](#0-8) .
2. `contractGovModule.GetParamSet`/`GetPartialParamSet` reads it via `ParseContractCall`, applying only `Canonicalizer`+`noopFormatChecker`, with no comparison against `LowerBoundBaseFee` — [10](#0-9) .
3. `GovModule.GetParamSet` merges this into the effective `ParamSet` without re-validating consistency — [7](#0-6) .
4. The inconsistent bounds are converted via `ToKip71Config` and used by `NextMagmaBlockBaseFee` for block assembly and by `BlockValidator.ValidateHeader` for header verification — [11](#0-10) [12](#0-11) .

Note: full verification of the concrete numeric consequence (whether this yields out-of-range base fee, a panic, or merely a deterministic-but-wrong fee shared by all honest nodes) would require running the described sequence against a live/simulated chain, which is outside the scope of static code review in this pass.

func (c *contractGovModule) contractGetAllParamsAtFromAddr(blockNum uint64, addr common.Address) (gov.PartialParamSet, error) {
	chain := c.Chain
	if chain == nil {
		return nil, ErrNotReady
	}

	config := c.ChainConfig
	if !config.IsKoreForkEnabled(new(big.Int).SetUint64(blockNum)) {
		return nil, ErrNotReady
	}

	caller := backends.NewBlockchainContractBackend(chain, nil, nil)
	contract, err := govcontract.NewGovParamCaller(addr, caller)
	if err != nil {
		return nil, err
	}

	names, values, err := contract.GetAllParamsAt(nil, new(big.Int).SetUint64(blockNum))
	if err != nil {
		logger.Warn("ContractEngine disabled: getAllParams call failed", "err", err)
		return nil, nil
	}

	if len(names) != len(values) {
		logger.Warn("ContractEngine disabled: getAllParams result invalid", "len(names)", len(names), "len(values)", len(values))
		return nil, nil
	}

	ret := ParseContractCall(names, values)

	rules := config.Rules(new(big.Int).SetUint64(blockNum))
	for name := range ret {
		if gov.DeprecatedAt(name, rules) {
			logger.Warn("Ignoring deprecated parameter from contract governance", "name", name, "blockNum", blockNum)
			delete(ret, name)
		}
	}

	return ret, nil
}

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
