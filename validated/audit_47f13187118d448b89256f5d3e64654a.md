### Title
Stale sender/fee-payer validation cached on `Transaction` object allows reuse of outdated authorization across re-validation contexts - (File: blockchain/types/transaction.go)

### Summary
The Django advisory describes `LazyUser` caching a user identity across requests without invalidating it when the underlying context changes, allowing a stale/incorrect identity to be reused for authorization. The closest reachable analog in this codebase is the one-shot, "set-once" caching of `validatedSender` / `validatedFeePayer` / `validatedGas` on the `types.Transaction` struct, which is written once by `ValidateSender()` and never refreshed on subsequent validation calls against the same transaction object.

### Finding Description
`Transaction.ValidateSender()` computes the sender address and signature-validation gas from the currently supplied `AccountKeyPicker` (state) and `currentBlockNumber`, then caches the result into `tx.validatedSender` / `tx.validatedFeePayer` only if the field is still the zero address: [1](#0-0) 

Once `tx.validatedSender` is non-zero, any later call to `ValidateSender` on the *same* `*Transaction` object skips re-deriving/re-validating the sender against the account key currently in state — it just returns previously computed `gasKey`/error semantics from a state snapshot that may no longer reflect the account's current `AccountKey` (e.g., after an intervening `TxTypeAccountUpdate` changes the signer's key from a legacy key to a role-based multisig key, or vice versa). The `validatedGas` field, which also feeds directly into `ApplyTransaction()`'s intrinsic/sig-validation gas accounting, is likewise fixed by the first successful validation: [2](#0-1) 

`Transaction.Validate()` further relies on `tx.ValidatedSender()` / `tx.ValidatedFeePayer()` to fetch the account key for consensus-path signature/account-key checks, again trusting the cached fields rather than re-deriving them fresh each time: [3](#0-2) 

This mirrors the Django bug class: an authorization-relevant value (here, the validated sender/fee-payer/gas of a transaction) is memoized once and reused across multiple validation passes (e.g., txpool admission vs. block-body validation, or repeated validation after a state-changing event like an `AccountUpdate`) without being invalidated when the underlying account state changes.

### Impact Explanation
If the same `*Transaction` object is validated more than once across different state snapshots (a pattern the codebase's own sender-signature cache, `SenderFrom`/`SenderPubkey`/`SenderFeePayerPubkey`, explicitly supports and invalidates only when the *signer* changes — not when the *account key* changes, see `SenderPubkey`/`SenderFeePayerPubkey`): [4](#0-3)  — then a transaction that was validated once against a stale `AccountKeyPicker` (e.g., before an account-key rotation) can have its `validatedGas`/`validatedSender` reused during later consensus-path application via `ApplyTransaction`, potentially causing incorrect sig-validation gas accounting or accepting/mischarging a transaction whose signer authorization state has since changed. This falls into fee/gas-accounting divergence and potential improper access-control category, since the caching decouples "who was authorized to sign this tx" from "who is currently authorized," similar to the LazyUser class problem.

### Likelihood Explanation
Exploitation likelihood depends on whether the txpool/consensus path actually re-uses the same `*Transaction` pointer across multiple `ValidateSender`/`Validate` calls spanning different state snapshots (e.g., pooled then re-validated after a reorg, or during pending-pool revalidation loops in `blockchain/tx_pool.go`). I was not able to fully confirm this call pattern before running out of tool iterations — the `blockchain/tx_pool.go` usages of `ValidateSender` need to be traced against `demoteUnexecutables`/`promoteExecutables` re-validation loops to establish whether a pooled/stale tx object is revalidated against updated state without being re-derived. This is a gap I could not close with the remaining iterations.

### Recommendation
Re-derive `validatedSender`/`validatedFeePayer`/`validatedGas` (or invalidate the cache) whenever `ValidateSender`/`Validate` is called with a different `AccountKeyPicker`/`currentBlockNumber` context, rather than gating the cache write on "unset" (zero-address) alone — mirroring the `IsCompatibleWith` invalidation strategy already used for the ECDSA signer cache in `SenderFrom`/`SenderPubkey`.

### Proof of Concept
Not constructed — this requires confirming whether `blockchain/tx_pool.go`'s pool-management loops (promote/demote/revalidate) invoke `ValidateSender` more than once on the same `*Transaction` instance across an account-key-changing state transition; that call-graph trace could not be completed within the available tool budget.

func (tx *Transaction) Validate(db StateDB, signer Signer, currentBlockNumber uint64, checkMutableValue bool) error {
	// validate the sender's account key
	if checkMutableValue {
		accKey := db.GetKey(tx.ValidatedSender())
		if tx.IsEthereumTransaction() {
			if !accKey.Type().IsLegacyAccountKey() {
				return ErrNotLegacyAccount
			}
		} else {
			if pubkey, err := SenderPubkey(signer, tx); err != nil {
				return ErrInvalidSigSender
			} else if accountkey.ValidateAccountKey(currentBlockNumber, tx.ValidatedSender(), accKey, pubkey, GetRoleTypeForValidation(tx.Type())) != nil {
				return ErrInvalidAccountKey
			}
		}

		// validate the fee payer's account key
		if tx.IsFeeDelegatedTransaction() {
			feePayerAccKey := db.GetKey(tx.ValidatedFeePayer())
			if feePayerPubkey, err := SenderFeePayerPubkey(signer, tx); err != nil {
				return ErrInvalidSigFeePayer
			} else if accountkey.ValidateAccountKey(currentBlockNumber, tx.ValidatedFeePayer(), feePayerAccKey, feePayerPubkey, accountkey.RoleFeePayer) != nil {
				return ErrInvalidAccountKey
			}
		}
	}
	// Range-check the fee ratio on the consensus path.
	if feeRatio, isRatioTx := tx.FeeRatio(); isRatioTx && !feeRatio.IsValid() {
		return kerrors.ErrFeeRatioOutOfRange
	}
	return tx.data.Validate(db, currentBlockNumber, checkMutableValue)
}

// ValidateSender finds a sender from both legacy and new types of transactions.
// It returns the senders address and gas used for the tx validation.
func (tx *Transaction) ValidateSender(signer Signer, p AccountKeyPicker, currentBlockNumber uint64) (uint64, error) {
	if tx.IsEthereumTransaction() {
		addr, err := Sender(signer, tx)
		// Legacy transaction cannot be executed unless the account has a legacy key.
		if p.GetKey(addr).Type().IsLegacyAccountKey() == false {
			return 0, kerrors.ErrLegacyTransactionMustBeWithLegacyKey
		}
		tx.mu.Lock()
		if tx.validatedSender == (common.Address{}) {
			tx.validatedSender = addr
			tx.validatedFeePayer = addr
		}
		tx.mu.Unlock()
		return 0, err
	}

	pubkey, err := SenderPubkey(signer, tx)
	if err != nil {
		return 0, err
	}
	txfrom, ok := tx.data.(TxInternalDataFrom)
	if !ok {
		return 0, errNotTxInternalDataFrom
	}
	from := txfrom.GetFrom()
	accKey := p.GetKey(from)

	gasKey, err := accKey.SigValidationGas(currentBlockNumber, GetRoleTypeForValidation(tx.Type()), len(pubkey))
	if err != nil {
		return 0, err
	}

	if err := accountkey.ValidateAccountKey(currentBlockNumber, from, accKey, pubkey, GetRoleTypeForValidation(tx.Type())); err != nil {
		return 0, ErrInvalidAccountKey
	}

	tx.mu.Lock()
	if tx.validatedSender == (common.Address{}) {
		tx.validatedSender = from
		tx.validatedFeePayer = from
	}
	tx.mu.Unlock()

// SenderFeePayerPubkey returns the public key derived from the signature (V, R, S) using secp256k1
// elliptic curve and an error if it failed deriving or upon an incorrect
// signature.
//
// SenderFeePayerPubkey may cache the public key, allowing it to be used regardless of
// signing method. The cache is invalidated if the cached signer does
// not match the signer used in the current call.
func SenderFeePayerPubkey(signer Signer, tx *Transaction) ([]*ecdsa.PublicKey, error) {
	if sc := tx.feePayer.Load(); sc != nil {
		sigCache := sc.(sigCachePubkey)
		if signer.IsCompatibleWith(sigCache.signer, tx) {
			return sigCache.pubkey, nil
		}
	}

	pubkey, err := signer.SenderFeePayer(tx)
	if err != nil {
		return nil, err
	}

	tx.feePayer.Store(sigCachePubkey{signer: signer, pubkey: pubkey})
	return pubkey, nil
}

// SenderFrom returns the address derived from the signature (V, R, S) using secp256k1
// elliptic curve and an error if it failed deriving or upon an incorrect
// signature.
//
// SenderFrom may cache the address, allowing it to be used regardless of
// signing method. The cache is invalidated if the cached signer does
// not match the signer used in the current call.
func SenderFrom(signer Signer, tx *Transaction) (common.Address, error) {
	if sc := tx.from.Load(); sc != nil {
		sigCache := sc.(sigCache)
		if signer.IsCompatibleWith(sigCache.signer, tx) {
			return sigCache.from, nil
		}
	}

	addr, err := signer.Sender(tx)
	if err != nil {
		return common.Address{}, err
	}
	tx.from.Store(sigCache{signer: signer, from: addr})
	return addr, nil
}

func SenderPubkey(signer Signer, tx *Transaction) ([]*ecdsa.PublicKey, error) {
