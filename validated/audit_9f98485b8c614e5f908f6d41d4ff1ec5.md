## Title
`CallDispatcher.dispatch()` has no access control, letting anyone drain token/ETH dust left behind by `IntentGatewayV2` predispatch/output-call execution - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is the exact local analog of the `MixinWallet.executeTransaction()` pattern in the external report: a shared, generic contract that will execute arbitrary attacker-supplied `Call[]` batches to arbitrary targets with arbitrary calldata and value. In the external report, the flaw was that a *privileged owner* could reach this "execute anything" primitive and use it to call restricted functions on a third contract that trusted it. Here the flaw is structurally worse: `CallDispatcher.dispatch()` [1](#0-0)  has **no caller restriction whatsoever** — not even an owner check — even though `IntentGatewayV2` treats it as a trusted, semi-custodial execution sandbox that temporarily holds user/solver funds during `placeOrder` (predispatch) and `_execute` (output-call) flows.

### Finding Description
`IntentGatewayV2.placeOrder()` and `IntentsBase._execute()` route escrowed/solver-provided tokens through the shared `_params.dispatcher` (a `CallDispatcher` instance) so that arbitrary DeFi calldata (swaps, unwraps, etc.) can run before/after order settlement:

- In `placeOrder`, tokens are sent to `dispatcher`, `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` executes the order-creator-supplied calldata, then a second `dispatch()` call sweeps the resulting balance back to the gateway [2](#0-1) .
- In `_execute` (used by both same-chain and cross-chain fill paths), solver-provided `order.output.call` is dispatched through the same `CallDispatcher`, and only the tokens explicitly listed in `order.output.assets` are swept back; any other token balance left on the dispatcher is not tracked/swept [3](#0-2) .

Critically, `CallDispatcher.dispatch()` itself enforces no `onlyOwner`/`onlyGateway` restriction — it will execute any `Call[]` from any `msg.sender`: [1](#0-0) . This mirrors the report's root cause precisely: a generically-callable "execute arbitrary calldata" primitive is shared/trusted by a contract that manages user funds, without any per-caller access boundary equivalent to `onlyLendingMarketController`/`onlyAcceptedContracts`.

Because `_params.dispatcher` is a single configured address (potentially shared across multiple gateway deployments/chains per the same protocol), any token or native balance that is not perfectly swept out by `IntentGatewayV2`'s bookkeeping (e.g., attacker-crafted `order.output.call` that yields output in a token not present in `order.output.assets`, fee-on-transfer residues, or a failed/partial sweep) becomes attacker-reachable: an outside, unprivileged address can call `CallDispatcher.dispatch()` directly with a `Call[]` that transfers out whatever ERC20/ETH balance is currently sitting on the dispatcher, with zero authorization check.

### Impact Explanation
This breaks the "bridged assets ... must move exactly once and only to the rightful beneficiary and amount" invariant. Funds that transiently or residually sit on the shared `CallDispatcher` (from `placeOrder` predispatch flows or `_execute` output-call flows) are not protected by any access control at the dispatcher level — the only safety net is `IntentGatewayV2`'s own sweep bookkeeping, which is incomplete (it only sweeps tokens explicitly named in `order.inputs`/`order.output.assets`). Any leftover balance can be stolen by an arbitrary, unprivileged third party calling `dispatch()` directly, with no relayer, prover, or governance compromise required.

### Likelihood Explanation
Likelihood depends on how reliably `IntentGatewayV2` sweeps 100% of what predispatch/output calldata produces. Since `order.predispatch.call` and `order.output.call` are attacker/solver-controlled arbitrary calldata routed through DEXes/lending protocols, it is realistic for swaps to yield dust in tokens other than the ones explicitly declared, or for multi-hop calls to leave partial balances (fee-on-transfer tokens, slippage remainders, failed but partially-executed legs). Because `dispatch()` has zero access control, exploitation requires no privileged position — just monitoring the `CallDispatcher` contract's balances and calling `dispatch()` opportunistically.

### Recommendation
Restrict `CallDispatcher.dispatch()` to an explicit allow-list of trusted callers (e.g., an immutable `owner`/`gateway` address set at construction, checked via a modifier), analogous to how the report recommended separating `LendingMarketController` vs `ReserveFund` privileges instead of a shared blanket-trust list. At minimum, add `onlyOwner`-style restriction so arbitrary external accounts cannot invoke `dispatch()`, and ensure `IntentGatewayV2`'s sweep logic fully drains (or the dispatcher self-sweeps) any non-enumerated token balances after each `dispatch()` invocation to eliminate residual value at rest.

### Proof of Concept
1. A solver fills a cross-chain order via `fillOrder()`, supplying `order.output.call` that routes through a DEX for one of the declared output tokens but, due to slippage/multi-hop routing, also produces a small balance of an undeclared token (or leftover native ETH) on the `CallDispatcher`.
2. `IntentsBase._execute()` only builds sweep calls for tokens present in `order.output.assets` [4](#0-3) ; the undeclared token/ETH balance remains on the `CallDispatcher` contract after the transaction completes.
3. An unrelated third party observes the nonzero balance on `CallDispatcher` and calls `CallDispatcher.dispatch()` directly with a `Call[]` such as `{to: token, value: 0, data: transfer(attacker, balance)}` (or `{to: attacker, value: balance, data: ""}` for ETH) — no restriction in `dispatch()` prevents this [1](#0-0) .
4. The attacker receives the funds; nothing in `CallDispatcher` or `IntentGatewayV2` detects or prevents this because no ownership check gates `dispatch()`.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
