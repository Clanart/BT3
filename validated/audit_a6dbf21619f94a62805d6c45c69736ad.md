## Title
Malicious Git server can spoof GitHub identity via WWW-Authenticate header to trigger unauthorized "Sign in to GitHub" OAuth prompt - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The reported Unlock bug is about a value fully controlled by an untrusted party (`tx.gasprice`) being trusted as an input to a security/financial decision (token minting) without independent verification. The Desktop analog is the credential helper's `getEndpointKind` function, which uses the `wwwauth[]` credential attribute — a value copied verbatim from an HTTP `WWW-Authenticate` response header sent by whatever Git server/proxy the user is talking to — to decide whether that server is a trusted "GitHub"/"enterprise" endpoint, even though that header is 100% attacker-controlled.

### Finding Description
When Git needs credentials for an HTTP(S) remote, it captures any `WWW-Authenticate` header from the server's 401 response and forwards it to the configured credential helper as `wwwauth[N]=...` attributes [1](#0-0) . `getEndpointKind` explicitly treats a `realm="GitHub"` value in that header as proof the endpoint is GitHub Enterprise, before falling back to any actual verification such as `isGitHubHost`: [2](#0-1) 

Because the `WWW-Authenticate` header is emitted by the remote server (or an on-path proxy) itself, an attacker who controls a git remote/proxy the user is fetching/pushing/cloning from can simply respond with `WWW-Authenticate: Basic realm="GitHub"` and be classified as `'enterprise'`, entirely bypassing the "happy path" comment's intent of avoiding a spoofable signal.

Once classified as non-generic, `getCredential` checks whether a stored account already matches the endpoint's API host. Since the attacker's host is not a real GitHub host, no match will be found, so Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

This surfaces a native "Sign in to GitHub" dialog to the user for a URL that is entirely attacker-chosen (it is the URL of the git remote being operated on), even though it is not github.com or a legitimate GHE instance. The only safeguard that would normally stop this — `isGitHubHost(endpoint)` — is skipped entirely because the `wwwauth[]` branch returns earlier in the function.

The account matching itself (`findGitHubTrampolineAccount`) does use strict origin equality [4](#0-3) , so an attacker cannot directly harvest an *existing* stored token this way. But the attacker fully controls whether the user is shown a trusted-looking "Sign in to GitHub" prompt for their own server, which is the corrupted value in this analog: the authenticity classification (`endpointKind`) of an arbitrary remote.

### Impact Explanation
An attacker who controls a git remote (their own malicious server, a compromised mirror, or a MITM-capable proxy configured for the target) can:
- Cause Desktop to present an unsolicited, GitHub-branded sign-in prompt while the user is simply doing a normal clone/fetch/push against what may look like an unrelated URL, increasing the plausibility of a phishing-style OAuth/account-linking flow.
- Potentially cause the user to complete a device/OAuth flow they believe is tied to a legitimate GitHub Enterprise instance but is actually initiated in the context of the attacker's endpoint, since `endpoint` (attacker-controlled) is what gets passed into the sign-in flow and is used afterwards to key the stored `Account`.

This falls under "unauthorized OAuth or account binding" from the accepted impact categories, since the classification of trust is derived from attacker data with no cross-check against a real GitHub identity check when the `wwwauth[]` shortcut is taken.

### Likelihood Explanation
Likelihood is moderate: it requires the user to attempt a Git operation (clone/fetch/push/pull) against a URL that resolves to an attacker-controlled HTTP server or proxy — a fairly ordinary interaction (e.g., adding an untrusted remote, or being redirected through a malicious proxy) — and for that server to be configured to answer 401 requests with a spoofed `WWW-Authenticate: realm="GitHub"` header, which is a trivial one-line change to any HTTP server.

### Recommendation
Do not treat the `wwwauth[]` realm value as sufficient proof of GitHub identity. Either remove the "happy path" shortcut entirely and always fall back to `isGitHubHost(endpoint)` (which presumably does an authenticated capability check against the real API), or require the `wwwauth[]`-derived classification to still be corroborated by `isGitHubHost` before short-circuiting to `'enterprise'`/prompting the branded GitHub sign-in UI.

### Proof of Concept
1. Stand up an HTTP git server at `https://attacker.example/pretend-ghe.git` that responds to unauthenticated Git requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add this URL as a remote (or clone from it) with no stored credentials/account for `attacker.example`.
3. Git forwards the `wwwauth[0]=Basic realm="GitHub"` attribute to Desktop's credential helper via the trampoline.
4. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`) matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost`.
5. `getCredential` finds no matching account for `attacker.example` and calls `ui.promptForGitHubSignIn('https://attacker.example/...')`, showing the user a "Sign in to GitHub" dialog for a server that has nothing to do with GitHub.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
