### Title
Ed448 accepts torsion points as canonical, enabling forged Schnorr/PoP verification - (File: crypto/ed448/src/point.rs)

### Summary
The Ed448 `Point::from_bytes` path is intended to reject non-prime-order/torsioned points, but its `is_torsion_free` check is mathematically a no-op: it computes `(-P) + P` and asks whether the result is identity, which is true for every point. [1](#0-0)  Because `Ciphersuite::read_G` only rejects points whose canonical re-encoding differs after `from_bytes`, a decodable Ed448 torsion point is accepted wherever `read_G` is used. [2](#0-1) 

### Finding Description
The reachable mismatch is between byte interpretation and group-law interpretation: the decoder treats attacker-supplied Ed448 encodings as canonical `PrimeGroup` elements even when they carry a cofactor/torsion component, while later Schnorr/DLEq/FROST-style verification equations assume prime-order group elements. `SchnorrSignature::verify` checks `R + cA - sG == 0` via `batch_statements`/`multiexp_vartime`, with no additional prime-order or identity rejection inside generic `C::read_G`. [3](#0-2)  PedPoP reaches this through `EncryptedMessage::read`/`SchnorrSignature::read` and then batch-verifies the PoP against `msg.key`. [4](#0-3) [5](#0-4) 

### Impact Explanation
An attacker can use an accepted low-order Ed448 point as a Schnorr public key/PoP key even though it may have no discrete logarithm to the prime-order generator. For a torsion point `T` of order dividing 4, verification of `(R, s)` under public key `A = T` reduces to `R + cT == sG`; choosing `s = 0` and `R = -jT` succeeds whenever `c ≡ j mod 4`. This yields a forged Schnorr/PoP acceptance for a key outside the intended subgroup and makes subsequent ECDH/DLEq values derived from `msg.key` live in a tiny torsion quotient rather than the prime-order session-key space.

### Likelihood Explanation
This requires an Ed448 deployment and attacker-controlled bytes reaching `read_G`/verification APIs, which is within the allowed input surface for `SchnorrSignature::read`, `EncryptedMessage::read`, `EncryptionKeyMessage::read`, and `ThresholdKeys::read`. The trigger is not probabilistic at the parser level: every decodable torsion point passes because the torsion check always returns true. [6](#0-5)  The forged `(R, s)` needs only a small search over the four torsion residues and/or messages until `challenge mod 4` matches the chosen `R`.

### Recommendation
Fix `Point::is_torsion_free` to actually clear the Ed448 cofactor and reject the resulting non-identity torsion component, and keep `from_bytes` enforcing that check before canonical re-encoding. [7](#0-6)  Add regression vectors that feed known Ed448 torsion encodings through `Ed448::read_G`, `SchnorrSignature::read`/`verify`, `EncryptedMessage::read`, and `ThresholdKeys::read` to confirm rejection rather than acceptance.

### Proof of Concept
1. Instantiate the Ed448 ciphersuite path that uses `crypto/ed448/src/point.rs`.
2. Take a decodable order-4 torsion point `T`; encode it with `T.to_bytes()`. `Ed448::read_G` accepts it because `from_bytes` returns `Some` after the always-true `is_torsion_free`.
3. Set public key `A = T`. For `j ∈ {0,1,2,3}`, form candidate signature `(R_j = -jT, s = 0)` and compute the verifier challenge `c_j` for the chosen message/context.
4. Submit the first `j` where `c_j ≡ j mod 4`; if none match for that message, vary the message/context and repeat. Verification computes `R_j + c_jA - 0G = (c_j - j)T = identity`, so `verify`/batch PoP accepts despite `T` not being a valid prime-order public key.

  fn is_torsion_free(&self) -> Choice {
    ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
  }

impl GroupEncoding for Point {
  type Repr = <FieldElement as PrimeField>::Repr;

  fn from_bytes(bytes: &Self::Repr) -> CtOption<Self> {
    // Extract and clear the sign bit
    let sign = Choice::from(bytes[56] >> 7);
    let mut bytes = *bytes;
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] &= !(1 << 7);

    // Parse y, recover x
    FieldElement::from_repr(bytes).and_then(|y| {
      recover_x(y).and_then(|mut x| {
        x.conditional_negate(x.is_odd().ct_eq(&!sign));
        let not_negative_zero = !(x.is_zero() & sign);
        let point = Point { x, y, z: FieldElement::ONE };
        CtOption::new(point, not_negative_zero & point.is_torsion_free())
      })

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();

  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
  }
