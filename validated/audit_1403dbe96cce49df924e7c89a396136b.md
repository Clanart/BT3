## Analysis

The AMM report's underlying flaw is that a value is credited (`Synth` minted) based on a claim about the pool state that is never actually deducted/verified against what was truly contributed. The equivalent binding in Clementine is: **the operator recorded as having "fronted" a withdrawal (embedded in the `Payout` transaction's `OP_RETURN`) must equal the operator whose own funds actually paid the user.** This binding is not cryptographically enforced.

`create_payout_txhandler` builds the `Payout` transaction with an unauthenticated `OP_RETURN` output carrying whichever `operator_xonly_pk` the constructor chooses, and signs the transaction only with the user's `SIGHASH_SINGLE|ANYONECANPAY` signature over input 0 / output 0: [1](#0-0) 

Because the sighash flags are `SINGLE|ANYONECANPAY`, the user's signature commits only to the first input and first output. Every other input (the operator's funding UTXOs, added via `fund_raw_transaction`) and every other output (including the `OP_RETURN` naming the "fronting" operator) is **not covered by any signature**: [2](#0-1) 

Verifiers later attribute the withdrawal purely by parsing this unauthenticated `OP_RETURN` field from the confirmed payout transaction, with no check that the named operator's own wallet actually supplied the paying funds: [3](#0-2) 

An operator's own automation then treats any payout whose `OP_RETURN` names it as "unhandled" and automatically starts the reimbursement (kickoff) process for it: [4](#0-3) [5](#0-4) 

The only later cross-check (`send_asserts`) verifies the requesting operator's key equals the `OP_RETURN` value already baked into the confirmed transaction — it never re-derives which wallet actually funded the extra inputs: [6](#0-5) 

### Title
Unauthenticated `OP_RETURN` operator attribution in `Payout` tx allows reimbursement credit to be stolen from the fronting operator - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` signs the withdrawal payout with `SIGHASH_SINGLE|ANYONECANPAY`, which only commits the withdrawal input and the user's output. The `OP_RETURN` output naming the operator entitled to reimbursement, and any additional funding inputs, are entirely unsigned and can be freely substituted by anyone who obtains the user's signature (e.g., by observing an operator's first broadcast attempt in the mempool). The bridge's attribution logic (`update_finalized_payouts`) trusts this unauthenticated field to decide which operator gets reimbursed.

### Finding Description
The binding that must hold is: `operator credited for reimbursement == operator whose own BTC funded the payout`. Because the payout transaction's signature scheme (`SIGHASH_SINGLE|ANYONECANPAY`) leaves the funding inputs and the `OP_RETURN` output unauthenticated, any party that learns the user's withdrawal signature (which becomes visible once any operator broadcasts a payout attempt to the mempool) can construct a competing transaction that:
- reuses the same signed input (user's withdrawal UTXO) and output (user's payout), satisfying the only real signature check, and
- funds the transaction with its own money and rewrites the `OP_RETURN` to name a different (potentially colluding) operator's xonly pubkey.

Verifiers subsequently attribute the payout to whatever xonly pubkey appears in `OP_RETURN`, with no verification that the named operator's own wallet actually supplied the funds, and that operator's automation will proceed to claim reimbursement.

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding: an operator can be reimbursed (BTC drawn from the vault via `Reimburse`/`Kickoff`) for a payout that its own wallet never funded — matching the Critical-severity class "an operator reimbursed for a payout it never funded." It can also permanently deprive the honest, actually-paying party of reimbursement, since the vault treats the withdrawal as already handled once a confirmed payout with a matching OP_RETURN exists.

### Likelihood Explanation
Exploitation requires only observing a broadcast (unconfirmed, mempool-visible) payout transaction — the user's `SIGHASH_SINGLE|ANYONECANPAY` signature is exposed in its witness — and racing a replacement transaction with different funding inputs and OP_RETURN data before confirmation. No verifier, operator, or aggregator privilege is required to construct or broadcast such a transaction; standard Bitcoin RBF/mempool mechanics suffice.

### Recommendation
Bind the operator attribution to a value covered by an actual signature: e.g., require the operator's own signature over the constructed payout transaction (covering the `OP_RETURN` and funding inputs) rather than relying on an unauthenticated `OP_RETURN`, or use `SIGHASH_ALL`-equivalent commitments that include all inputs/outputs so no other party can graft in unrelated funding or a different operator identity.

### Proof of Concept
1. Operator A calls `withdraw`, builds and broadcasts a `Payout` tx spending the user's dust UTXO (signed `SINGLE|ANYONECANPAY`) with `OP_RETURN = operator_A_xonly_pk`, funded by Operator A's inputs (`core/src/operator.rs:620-637`).
2. Attacker observes this unconfirmed transaction in the mempool and extracts the witness signature (valid only over input 0/output 0).
3. Attacker constructs a new transaction reusing the same signed input/output, but supplies their own (or colluding Operator B's) funding inputs and sets `OP_RETURN = operator_B_xonly_pk`, then broadcasts with a higher fee to replace Operator A's transaction.
4. Once confirmed, `update_finalized_payouts` (`core/src/verifier.rs:2312-2335`) records Operator B as the payer; Operator B's `PayoutCheckerTask` (`core/src/task/payout_checker.rs:41-79`) automatically proceeds to claim reimbursement for a payout it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
