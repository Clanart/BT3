### Title
Cached FROST nonces are reusable across distinct signing sets, enabling key-share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` derives the same deterministic FROST nonce seed every time a context is used and never marks that cached seed as spent. Public preprocess messages can then vary the per-participant binding factor while the underlying `(d, e)` nonce pair remains fixed. Three successful shares under the same context disclose enough independent linear equations to recover the signer’s interpolated secret share.

### Finding Description
`preprocess_internal` stores only a 32-byte `CachedPreprocess`, encrypted under the signing context and local key. On every subsequent call it decrypts that same value and passes it to `AlgorithmSignMachine::from_cache`, without deleting or marking it consumed. [1](#0-0) 

`from_cache` reconstructs the machine through `seeded_preprocess`, so the same seed deterministically recreates the same nonce pair and public commitment. [2](#0-1) 

Attacker-controlled preprocess bytes are accepted through `read_preprocess` and passed to `sign`. [3](#0-2)  During signing, the binding transcript commits to the group key, message hash, and the transcript of all participant commitments, then calculates a per-participant `rho`. [4](#0-3)  The local effective nonce is then recomputed as `d + rho * e`. [5](#0-4) 

Because the cache is not consumed, repeating the same context with the same participant IDs and message but different valid commitment points produces shares of the form:

```text
s_j = d + rho_j * e + c_j * x
```

`d`, `e`, and the interpolated secret share `x` remain constant, while `rho_j` and `c_j` are public functions of the submitted preprocesses and message. Three such shares therefore provide three equations in three unknowns and recover `x`.

### Impact Explanation
A recovered interpolated secret share compromises the victim’s threshold-signing share for the signing set. For Lagrange interpolation, the original share is recovered by dividing by the participant’s public interpolation coefficient; any public offset can be subtracted when applicable. This converts repeated signing under a reused context from a protocol failure into disclosure of long-lived key material. [6](#0-5) 

### Likelihood Explanation
A party supplying public preprocess messages can vary commitment points while keeping participant IDs and the requested message fixed. Any retry, equivocated preprocessing set, or repeated `share`/`complete` path under the same context reconstructs the same seed. The affected calls only need to succeed and disclose shares; malformed preprocesses alone do not disclose new information.

### Recommendation
Make cached preprocesses strictly single-use. Atomically delete or tombstone `CachedPreprocesses[context]` before an externally visible signature share can be emitted, and reject subsequent `share` or `complete` calls for that consumed context. The consumption must survive reboots and be committed in the same database transaction as the emitted protocol state. Do not reconstruct a cached preprocess after a successful signing attempt.

### Proof of Concept
Conceptual execution against the affected path:

```text
context = fixed signing context
participants = fixed participant set containing the victim
msg = fixed message

for j in 1..=3:
    preprocesses_j = preprocesses for `participants`,
                     with one participant's D/E commitments changed
    share_j = victim.share_internal(participants, preprocesses_j, msg)
    rho_j = H_rho(group_key, hash_msg(msg), preprocesses_j, victim)
    c_j = Hram(R_j, group_key, msg)
```

The shares satisfy:

```text
s_1 = d + rho_1 * e + c_1 * x
s_2 = d + rho_2 * e + c_2 * x
s_3 = d + rho_3 * e + c_3 * x
```

Solving this linear system over the curve’s scalar field yields `x`, the victim’s interpolated secret share for that signing set.
