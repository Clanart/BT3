### Title
NFT eve-coin minting lets anyone forge a DID creator/minter association without the DID owner's authorization - (File: chia/wallet/nft_wallet/nft_wallet.py)

### Summary
`NFTWallet.generate_new_nft` allows any unprivileged wallet user minting an NFT to set the eve coin's ownership-layer `current_owner` field (and therefore the resulting `minter_did`) to an arbitrary DID puzzle hash — including a DID they do not control — without any signature, approval, or spend from that DID. This is the same bug class as the Gitcoin report: any unprivileged actor can permissionlessly attach their own asset/metadata to someone else's identity/hash, forging provenance/association that downstream consumers may treat as authentic.

### Finding Description
When minting a provenant NFT with a specified `did_id`, the eve singleton's ownership layer is curried directly from caller-supplied `did_id` bytes with no check that the caller controls that DID: [1](#0-0) 

The code's own comment acknowledges this:
"eve coin DID can be set to whatever so we keep it empty ... WARNING: wallets should always ignore DID value for eve coins as they can be set to any DID without approval."

The resulting `minter_did` is computed later by `WalletStateManager.get_minter_did` / `manual_nft_search` from the launcher coin, and surfaced through NFT info APIs and RPC responses: [2](#0-1) 

There is no cryptographic linkage requiring the referenced DID's owner to sign or otherwise approve the mint. The only enforcement mechanism the codebase relies on is a documentation warning telling *client code* to ignore this field for eve coins — this is a policy comment, not an on-chain or wallet-level authorization check. Any caller of `generate_new_nft` (reachable via the NFT wallet RPC `nft_mint_nft` path) can pass any `did_id` value and have it embedded in the ownership layer curry parameters, producing a full puzzle/coin that superficially "claims" affiliation with that DID.

This mirrors the Gitcoin `applyToRound` bug exactly: knowledge of a public identifier (a DID puzzle hash is public, just like a `projectID` hash) is sufficient to unilaterally associate arbitrary data/coins with that identity, with no signature check tying the association back to the identity's actual controller.

### Impact Explanation
An attacker can mint NFTs that appear to be associated with (created/owned-by) a victim's well-known DID (e.g., a verified creator/collection DID) without the victim's DID ever being spent or signing anything. Any UI, marketplace, offer-matching logic, or automated indexing that reads `minter_did`/`owner_did` from an eve coin without independently re-verifying a subsequent DID-authorized transfer could be misled into treating attacker-minted NFTs as legitimately affiliated with the victim's brand/identity. This is a forged-asset-identity condition: it lets an unprivileged minter counterfeit provenance metadata tied to another party's on-chain identity, which can facilitate fraud (e.g., selling fake "verified collection" NFTs, or being represented in offers as coming from a trusted DID). Because the ownership layer's actual DID-based control transfer requires a real signed transfer program spend later, the *ownership* of funds is not immediately stolen the way the Gitcoin bug directly redirected grant payouts — but the *identity association* itself is forgeable at zero cost to any minter, which is the core of the reported bug class (unauthorized identity binding).

### Likelihood Explanation
High feasibility: DID puzzle hashes/launcher IDs are public on-chain data. Any wallet user can call the standard NFT minting flow with `did_id` set to any bytes32 they choose; there is no signature requirement from the target DID, and the code comment explicitly documents this as expected, unmitigated behavior at the wallet layer. The only safeguard is that consumer code must remember to ignore this field for eve (freshly-minted, never-transferred) coins — a fragile, easily-missed convention rather than an enforced invariant.

### Recommendation
Do not allow arbitrary, unauthenticated DID association at mint time to be treated as trustworthy anywhere in the codebase or exposed APIs. Concretely:
- In `NFTWallet.generate_new_nft` / `nft_puzzle_utils.create_ownership_layer_puzzle`, require that setting a non-empty `did_id` on an eve coin either (a) be flagged as "unverified/self-claimed" in all API responses (`ManualNFTSearchResults`, `NFTInfo`, RPC `nft_get_info`), or (b) only be trusted once a subsequent DID-signed transfer-program spend confirms real DID association.
- Audit all downstream consumers (`get_nft_info_from_puzzle`, RPC responses, CLI `nft_get_info`) to ensure `minter_did`/`owner_did` on unspent eve coins are never surfaced without an explicit "unverified" flag, since currently the comment relies on external code remembering to ignore the field rather than the API contract enforcing it.

### Proof of Concept
1. Attacker creates/derives an arbitrary `did_id` value equal to a victim's real, publicly known DID launcher id (no private key needed — DID ids are public).
2. Attacker calls the NFT mint flow (`NFTWallet.generate_new_nft`) supplying `did_id=<victim_did>`, `royalty_puzzle_hash=<attacker address>`.
3. `create_ownership_layer_puzzle` curries the eve inner puzzle with `current_owner=victim_did` [3](#0-2) , with no signature or spend from the victim DID.
4. The resulting NFT's `owner_did`/`minter_did` (as returned by `manual_nft_search`/`get_minter_did`) now falsely shows the victim DID as associated with the attacker-minted NFT, even though the victim never authorized it, matching the "anybody can set an association pointer using another party's public identifier" bug class from the reference report.

    async def manual_nft_search(self, coin_id: bytes32, latest: bool = True) -> ManualNFTSearchResults:
        # Get coin state
        peer = self.wallet_node.get_full_node_peer()
        coin_spend, coin_state = await self.get_latest_singleton_coin_spend(peer, coin_id, latest)
        # convert to NFTInfo
        # Check if the metadata is updated
        full_puzzle: Program = Program.from_bytes(bytes(coin_spend.puzzle_reveal))

        uncurried_nft: UncurriedNFT | None = UncurriedNFT.uncurry(*full_puzzle.uncurry())
        if uncurried_nft is None:
            raise ValueError("The coin is not a NFT.")
        metadata, p2_puzzle_hash = get_metadata_and_phs(uncurried_nft, coin_spend.solution)
        # Note: This is not the actual unspent NFT full puzzle.
        # There is no way to rebuild the full puzzle in a different wallet.
        # But it shouldn't have impact on generating the NFTInfo, since inner_puzzle is not used there.
        if uncurried_nft.supports_did:
            inner_puzzle = nft_puzzle_utils.recurry_nft_puzzle(
                uncurried_nft, Program.from_serialized(coin_spend.solution), uncurried_nft.p2_puzzle
            )
        else:
            inner_puzzle = uncurried_nft.p2_puzzle

        full_puzzle = nft_puzzle_utils.create_full_puzzle(
            uncurried_nft.singleton_launcher_id,
            metadata,
            bytes32(uncurried_nft.metadata_updater_hash.as_atom()),
            inner_puzzle,
        )

        # Get launcher coin
        launcher_coin: list[CoinState] = await self.wallet_node.get_coin_state(
            [uncurried_nft.singleton_launcher_id], peer=peer
        )
        if len(launcher_coin) < 1 or launcher_coin[0].spent_height is None:
            raise ValueError(f"Launcher coin record 0x{uncurried_nft.singleton_launcher_id.hex()} not found")
        minter_did = await self.get_minter_did(launcher_coin[0].coin, peer)

        return ManualNFTSearchResults(
            nft_info=await nft_puzzle_utils.get_nft_info_from_puzzle(
                NFTCoinInfo(
                    uncurried_nft.singleton_launcher_id,
                    coin_state.coin,
                    None,
                    full_puzzle,
                    uint32(launcher_coin[0].spent_height),
                    minter_did,
                    uint32(coin_state.created_height) if coin_state.created_height else uint32(0),
                ),
                self.config,
            ),
            next_p2_puzzle_hash=p2_puzzle_hash,
        )
