### Title
PedPoP accepts an identity encryption key, silently reducing ECDH share encryption to a publicly-computable keystream - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary

The Wazuh bug class is a gate that checks the *existence* of an entry (an RBAC rule) rather than its *effect* (allow vs. deny), which disables a confidentiality protection (masking of `cluster.key`). The Serai analog lives in the PedPoP DKG encryption layer: `Decryption::register` treats the mere presence of a participant's `enc_key` in an `EncryptionKeyMessage` as sufficient, never checking whether the point is the identity. If a participant registers `enc_key = identity`, every ECDH computed against it yields the identity element, so `cipher()` derives its ChaCha20 key from a publicly known "shared secret". Encryption of that participant's secret shares is still "on" — messages are still produced and PoPs still verify — but the confidentiality it is supposed to provide is a no-op, exactly mirroring a deny rule that disables masking.

### Finding Description

`EncryptionKeyMessage::read` accepts `enc_key` via `C::read_G` with no validity constraint beyond a successful decode (`crypto/dkg/pedpop/src/encryption.rs:57-59`). `Decryption::register` asserts only that the participant has not already registered, then stores the point unconditionally (`encryption.rs:356-361`):

```rust
assert!(
  !self.enc_keys.contains_key(&participant),
  "Re-registering encryption key for a participant"
);
self.enc_keys.insert(participant, msg.enc_key);
```

Later, `encrypt()` computes `ecdh(&key, to)` where `to = enc_keys[&participant]` (`encryption.rs:466`, `95-97`). For `to == identity`, `public * private == identity` for every ephemeral `key`. `cipher()` then builds the ChaCha20 key solely from `transcript(context || domain || shared_key)` (`encryption.rs:101-133`), so the keystream is a deterministic public function of `context` and the identity encoding — anyone can reconstruct it.

Reachability: a participant submits an `EncryptionKeyMessage<Commitments>` whose `enc_key` is the 32-byte identity encoding. `verify_r1` registers it (`lib.rs:315`) and every other participant encrypts their PedPoP secret share for that participant under the identity ECDH (`lib.rs:369`). For `Ristretto` (used in `schnorrkel`-based sets), the identity is a canonical `GroupEncoding`, so `read_G` accepts it. The PoK batch check in `verify_r1` only covers `commitments[0]` (`lib.rs:323-329`); `enc_key` is never proof-checked at all — the PoP on `EncryptedMessage` proves knowledge of the *ephemeral* key, not the registered static key.

### Impact Explanation

Every `EncryptedMessage<SecretShare>` addressed to the offending participant can be decrypted by any observer of the wire bytes: recompute `cipher(context, identity)` and apply the keystream. The victim-equivalent here is the *senders*: they believe their shares are confidential to the intended recipient, yet the sum of those shares — the recipient's aggregate DKG secret share (`lib.rs:484`, `*self.secret += share`) — is recoverable publicly. A key share that the protocol explicitly encrypts "to protect the secret shares" (`lib.rs:186-187`) is exposed to parties outside the DKG entirely, breaking the protocol's confidentiality boundary without any party detecting a fault.

### Likelihood Explanation

Requires only that one DKG participant submit a malformed `EncryptionKeyMessage` — standard protocol input over the assumed authenticated channel. No collusion, no timing, no special privileges. Exploitation is passive observation of bytes that already transit the network. The scheme does eventually detect *invalid* shares, but this path produces perfectly valid shares that are merely readable by everyone.

### Recommendation

In `Decryption::register` (or `EncryptionKeyMessage::read`), reject non-prime-order/identity points: require `bool::from(!msg.enc_key.is_identity())` (and for curves with torsion, a prime-order check on `enc_key`). Optionally require a Schnorr PoK on `enc_key` bound to `(context, participant)` so the registered key is proven non-degenerate, matching the PoK already required for `commitments[0]`.

### Proof of Concept

1. Initialize `KeyGenMachine::<Ristretto>::new(params, context)` for attacker index `l`.
2. In `generate_coefficients`, emit `EncryptionKeyMessage { msg: Commitments{..valid PoK..}, enc_key: RistrettoPoint::identity() }` (enc_key is not PoK-covered; only `commitments[0]` is).
3. Each honest sender calls `encrypt(rng, context, from, to = identity, share)`: ECDH = `k * identity = identity`; keystream = `ChaCha20(H(context || "encryption_key" || identity_bytes) || "DKG IV v0.2\0")`.
4. Observer computes the same transcript-derived key/IV and applies the keystream to `msg.msg` → recovers `SecretShare<F>` plaintext for every sender, i.e., all shares `s_j(l)`, whose sum is participant `l`'s threshold secret share — readable by a non-participant.

Caveat: I verified the code paths shown above but could not exhaustively confirm `C::read_G` accepts the identity for every in-scope ciphersuite (e.g., kp256 `read_G` may reject it); the issue is confirmed structurally for `Ristretto`/`dalek-ff-group` where identity is canonical.
