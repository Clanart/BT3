### Title
`internal_withdraw` RPC Bypasses Aggregator ECDSA Verification Signature Check — (`core/src/rpc/operator.rs`)

### Summary

The `ClementineOperator` gRPC service exposes two withdrawal endpoints: `withdraw` and `internal_withdraw`. When `aggregator_verification_address` is configured, `withdraw` enforces an ECDSA verification signature from the aggregator/Citrea before processing a payout. `internal_withdraw` calls the identical underlying `operator.withdraw()` function but performs **no verification signature check at all**, creating a direct authorization bypass for any caller with mTLS access to the operator's gRPC port.

### Finding Description

`withdraw` (lines 193–258 of `core/src/rpc/operator.rs`) enforces the following guard when `aggregator_verification_address` is set in config: [1](#0-0) 

If the signature is absent or does not recover to the configured address, the call is rejected with `ECDSAVerificationSignatureMissing` or `InvalidECDSAVerificationSignature`.

`internal_withdraw` (lines 168–190) accepts a bare `WithdrawParams` (which has no `verification_signature` field at all) and immediately calls `operator.withdraw()`: [2](#0-1) 

The proto message `WithdrawParamsWithSig` carries the optional `verification_signature` field: [3](#0-2) 

`internal_withdraw` uses `WithdrawParams` instead, which has no such field, so the check is structurally impossible to perform — not merely skipped conditionally.

The CLI also exposes `internal_withdraw` as a callable command: [4](#0-3) 

### Impact Explanation

When `aggregator_verification_address` is configured (the intended production security model, where Citrea manually approves each optimistic payout before the operator processes it), any actor holding a valid mTLS certificate for the operator's gRPC service can call `internal_withdraw` with arbitrary `WithdrawParams` and trigger `operator.withdraw()` without the aggregator's ECDSA authorization. The underlying `operator.withdraw()` still checks that the withdrawal UTXO matches Citrea's on-chain record: [5](#0-4) 

However, the verification signature is specifically designed to gate **manual Citrea approval** of the payout parameters (output script, amount, outpoint) before the operator fronts liquidity. Bypassing it allows processing of a withdrawal that Citrea has not approved, causing the operator to spend its own collateral UTXO on an unapproved payout — a direct loss of operator-controlled BTC.

### Likelihood Explanation

The `internal_withdraw` endpoint is part of the live `ClementineOperator` gRPC service. Any party with a valid mTLS client certificate (e.g., the operator's own CLI, an aggregator, or any co-located service sharing the certificate) can reach it. The CLI explicitly exposes it. The bypass requires no special knowledge beyond knowing the endpoint name and having network/mTLS access.

### Recommendation

Remove `internal_withdraw` from the public gRPC service, or apply the identical verification-signature guard used in `withdraw`:

```rust
// In internal_withdraw, add before calling operator.withdraw():
if let Some(address_in_config) = self.operator.config.aggregator_verification_address {
    // require and validate verification_signature identically to `withdraw`
    return Err(BridgeError::ECDSAVerificationSignatureMissing).map_to_status();
}
```

Alternatively, if `internal_withdraw` is only needed for testing or CLI tooling, gate it behind a compile-time feature flag (`#[cfg(test)]` or a dedicated `internal` feature) so it is never compiled into production binaries.

### Proof of Concept

1. Configure the operator with `aggregator_verification_address = <some_address>` (production setting).
2. Obtain a valid mTLS client certificate for the operator's gRPC port (e.g., from the operator's own CLI config).
3. Call `internal_withdraw` with a valid `WithdrawParams` (withdrawal UTXO that exists in the DB):
   ```
   grpcurl -cert client.crt -key client.key \
     operator:port clementine.ClementineOperator/InternalWithdraw \
     '{"withdrawal_id": 0, "input_signature": "...", ...}'
   ```
4. The operator processes the payout and broadcasts the transaction — **without any aggregator ECDSA signature** — spending the operator's collateral UTXO on an unapproved withdrawal. [2](#0-1) [6](#0-5)

    async fn withdraw(
        &self,
        request: Request<WithdrawParamsWithSig>,
    ) -> Result<Response<RawSignedTx>, Status> {
        tracing::info!("Withdraw rpc called");
        let params = request.into_inner();
        let withdraw_params = params.withdrawal.ok_or(Status::invalid_argument(
            "Withdrawal params not found for withdrawal",
        ))?;
        let (withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount) =
            parser::operator::parse_withdrawal_sig_params(withdraw_params)?;

        tracing::warn!(
            "Parsed withdraw rpc params, withdrawal id: {:?}, input signature: {:?}, input outpoint: {:?}, output script pubkey: {:?}, output amount: {:?}, verification signature: {:?}", withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount, params.verification_signature
        );

        // if verification address is set in config, check if verification signature is valid
        if let Some(address_in_config) = self.operator.config.aggregator_verification_address {
            let verification_signature = params
                .verification_signature
                .map(|sig| {
                    PrimitiveSignature::from_str(&sig).map_err(|e| {
                        Status::invalid_argument(format!("Invalid verification signature: {e}"))
                    })
                })
                .transpose()?;
            // check if verification signature is provided by aggregator
            if let Some(verification_signature) = verification_signature {
                let address_from_sig =
                    recover_address_from_ecdsa_signature::<OperatorWithdrawalMessage>(
                        withdrawal_id,
                        input_signature,
                        input_outpoint,
                        output_script_pubkey.clone(),
                        output_amount,
                        verification_signature,
                    )?;

                // check if verification signature is signed by the address in config
                if address_from_sig != address_in_config {
                    return Err(BridgeError::InvalidECDSAVerificationSignature).map_to_status();
                }
            } else {
                // if verification signature is not provided, but verification address is set in config, return error
                return Err(BridgeError::ECDSAVerificationSignatureMissing).map_to_status();
            }
        }

        let payout_tx = self
            .operator
            .withdraw(
                withdrawal_id,
                input_signature,
                input_outpoint,
                output_script_pubkey,
                output_amount,
            )
            .await?;

        tracing::info!(
            "Withdraw rpc completed successfully for withdrawal id: {:?}",
            withdrawal_id
        );

        Ok(Response::new(RawSignedTx::from(&payout_tx)))
    }
