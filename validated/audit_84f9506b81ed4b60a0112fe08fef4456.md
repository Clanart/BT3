### Title
Unbounded manual atom-length parsing in `is_atom_canonical` can raise an uncaught `IndexError` during untrusted spend-bundle validation - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical` and `is_clvm_canonical` in `chia/full_node/mempool_manager.py` manually walk a CLVM-serialized buffer byte-by-byte to determine whether puzzle reveals/solutions use canonical (shortest-form) atom-length encoding [1](#0-0) . Unlike the length-prefixed parsers in `chia/full_node/full_block_utils.py`, which explicitly check `n > len(buf)` before slicing [2](#0-1) , this code indexes directly into `clvm_buffer[offset]` in a loop with no check that `offset` stays within `len(clvm_buffer)` [3](#0-2)  and [4](#0-3) .

### Finding Description
This function is invoked on attacker-controlled bytes: `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in a submitted `SpendBundle` before it is admitted to the mempool [5](#0-4) . If a crafted atom's multi-byte length-prefix header claims a `prefix_len` that extends past the actual end of the (short) buffer, the loop in `is_atom_canonical` will read `clvm_buffer[offset]` at an out-of-range index [6](#0-5) . In Python this raises an `IndexError` rather than causing memory corruption (Python bytes objects are bounds-checked), but the analog to CVE-2021-33928's root cause is the same: a parsing routine derives a length/offset from untrusted attacker input and walks the buffer without validating that the derived offset stays within bounds, exactly as `pool_installable` in libsolv did.

### Impact Explanation
`validate_spend_bundle()` has no `try/except` around the `is_clvm_canonical` calls; an `IndexError` raised there is not one of the expected `ValueError`/`ValidationError` types the pre-validation pipeline is built to catch (compare the `except ValueError` handling immediately above the atom/pair bound checks) [7](#0-6) . This can propagate an unhandled exception up through `add_spend_bundle()` and into the full-node request handling path (`chia/full_node/full_node.py`), which is reachable by any unprivileged party submitting a spend bundle for mempool admission — a spend-triggered transaction-processing halt on that request path.

### Likelihood Explanation
Any unprivileged wallet user or spend-bundle submitter can construct a puzzle reveal or solution byte string with a truncated/oversized multi-byte atom length prefix and small buffer, since `is_clvm_canonical` is only reached for `ELIGIBLE_FOR_DEDUP`/`ELIGIBLE_FOR_FF`-flagged spends going through this canonical-encoding check on every mempool admission attempt [5](#0-4) . No special privileges, peer trust, or timing are required beyond submitting a spend bundle through the normal RPC/tx-gossip mempool-admission path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access (mirroring the `len(buf) < n` style guards used in `full_block_utils.py`), and/or wrap the `is_clvm_canonical` calls in `validate_spend_bundle` with exception handling that converts any parsing failure into a controlled `Err.INVALID_COIN_SOLUTION` result rather than letting an `IndexError` propagate.

### Proof of Concept
Construct a `coin_spend.puzzle_reveal` (or `.solution`) whose bytes begin with a length-prefix byte selecting the 5-byte prefix branch (e.g., `0b11111100`-pattern byte, `prefix_len = 5`) but supply fewer than 5 additional bytes total in the buffer, e.g. `bytes([0xFC])` (a single byte). Submitting a `SpendBundle` containing a coin spend with this puzzle reveal/solution to `add_spend_bundle()` drives execution into `is_clvm_canonical` → `is_atom_canonical`, where the loop at [6](#0-5)  attempts to read `clvm_buffer[offset]` past the end of the one-byte buffer, raising an unhandled `IndexError` instead of the expected `Err.INVALID_COIN_SOLUTION` result path exercised by the existing non-canonical tests [8](#0-7) .

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
```
