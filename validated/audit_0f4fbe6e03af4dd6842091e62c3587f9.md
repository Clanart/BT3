### Title
Memory exhaustion via unbounded MODEXP precompile exponent length prior to Osaka (EIP-7823) - (File: blockchain/vm/contracts.go)

### Summary
The `bigModExp` precompile (address `0x05`) charges gas for the `base`/`modulus` length quadratically but for the `exponent` length only linearly, and — outside the Osaka fork — imposes **no upper bound at all** on `baseLen`, `expLen`, or `modLen`. An attacker can submit a single transaction whose calldata declares a huge `expLen` field (tens of millions of bytes) while the actual base/modulus/exponent data supplied is tiny (a few bytes), because `getData` zero-pads missing input up to the declared length. Because the gas cost is dominated by `multComplexity(max(baseLen, modLen))`, keeping base/modulus length at `1` makes the multiplier `1`, so gas grows only linearly and cheaply with `expLen`. This lets a caller force tens of megabytes of heap allocation per EVM call for a gas cost well within a single transaction/block gas limit — the same "unbounded allocation driven by an under-priced size parameter" bug class as the TensorFlow `ThreadPoolHandle` advisory (CWE-400/CWE-770).

### Finding Description
`bigModExp.Run` reads `baseLen`, `expLen`, `modLen` directly from the first 96 bytes of the precompile's calldata and, when `eip7823` is disabled, performs **no cap check** on these values before allocating buffers sized by them: [1](#0-0) 

Note the cap is conditional on `c.eip7823`:
```
if c.eip7823 && (inputLenOverflow || max(baseLen, expLen, modLen) > 1024) {
    return nil, errors.New("...")
}
```
`eip7823` is only `true` for `PrecompiledContractsOsaka`; every other fork map (Byzantium, Istanbul, Kore, Cancun, Prague) instantiates `bigModExp` with `eip7823: false`: [2](#0-1) 

Once past the (disabled) cap check, `Run` calls `getData(input, baseLen, expLen)`, which allocates and zero-right-pads a new slice of length `expLen` regardless of how much real calldata was supplied: [3](#0-2) 

The gas cost, computed in `GetRequiredGasAndComputationCost`, is `multComplexity(max(baseLen, modLen)) * iterationCount / divisor`, where `iterationCount` scales linearly (not quadratically) with `expLen`: [4](#0-3) [5](#0-4) 

If the attacker sets `baseLen = modLen = 1` (so `multComplexity == 1`), the required gas becomes approximately `(expLen - 32) * multiplier / divisor`. For the Berlin/EIP-2565 rules (`multiplier = 8`, `divisor = 3`), an `expLen` of ~37.5 million forces roughly 100,000,000 gas — near a typical block gas limit — while allocating ~37.5 MB of zero-filled memory for the `exp` buffer alone, and the actual `Exp()` computation is trivial (exponent value is `0` after zero-padding). This decouples per-byte allocation cost from per-byte gas cost in a way EIP-7823 was specifically introduced to close, but that fix is not yet active for any pre-Osaka Kaia fork.

### Impact Explanation
Any unprivileged transaction sender or public-RPC caller can invoke precompile `0x05` with a crafted 96-byte header and minimal calldata to force tens of megabytes of allocation per call for gas costs a normal user can afford within a single transaction. Because every full/execution node must replay the same transaction to reach consensus, this allows an attacker to impose disproportionate memory pressure (heap churn, GC pressure, potential OOM on resource-constrained nodes) on all validators/full nodes processing the block — a Denial-of-Service vector matching CWE-400 (Uncontrolled Resource Consumption) and CWE-770 (Allocation of Resources Without Limits), consistent with the cited TensorFlow advisory's bug class. This does not directly cause fund loss or consensus divergence, but can degrade or crash nodes, which the report accepts under "state divergence between honest nodes" concerns arising from OOM-induced node failures.

### Likelihood Explanation
The precompile is reachable by any signed transaction or `eth_call`; no special privileges, contract deployment, or governance change is needed. The exploit only requires knowledge of the EIP-198 MODEXP input layout, which is public. It is a straightforward, repeatable operation (can be embedded in a loop within a single contract call, or fired as separate transactions), making likelihood high on any Kaia network/fork that has not yet activated Osaka (all current fork maps except `PrecompiledContractsOsaka` have `eip7823: false`).

### Recommendation
Enforce the EIP-7823-style length cap (or an equivalent conservative bound) on `baseLen`, `expLen`, and `modLen` unconditionally in `bigModExp.Run` and `GetRequiredGasAndComputationCost`, rather than gating it behind the Osaka-only `eip7823` flag, or backport the cap to earlier active rule sets. Additionally, consider making the gas cost for `expLen`-driven allocation reflect actual memory/CPU cost more accurately (e.g., always factoring `expLen` into the quadratic multiplier, not only `max(baseLen, modLen)`).

### Proof of Concept
Construct calldata to precompile `0x0000000000000000000000000000000000000005` on a pre-Osaka Kaia network:
```
baseLen = 0x...01                     (32 bytes, value = 1)
expLen  = 0x...023C3460 (~37,500,000) (32 bytes)
modLen  = 0x...01                     (32 bytes, value = 1)
base    = 0x01                        (1 byte)
mod     = 0x01                        (1 byte)
# no exponent bytes supplied -- getData will zero-pad ~37.5MB
```
Send this as `data` in a normal `eth_call`/transaction with `gas` around 100,000,000 (or scaled to the target's block gas limit). `bigModExp.GetRequiredGasAndComputationCost` will return a gas figure the sender can afford (dominated by `multComplexity(1)=1` times a linear function of `expLen`), and `bigModExp.Run` will allocate a ~37.5MB zero-filled slice via `getData(input, baseLen, expLen)` for a trivial actual computation (`exp == 0`). Repeating this across transactions in a block multiplies the forced memory allocation on every executing node.

// modexpIterationCount calculates the number of iterations for the modexp precompile.
// This is the adjusted exponent length used in gas calculation.
func modexpIterationCount(expLen uint64, expHead uint256.Int, multiplier uint64) uint64 {
	var iterationCount uint64

	// For large exponents (expLen > 32), add (expLen - 32) * multiplier
	if expLen > 32 {
		carry, count := bits.Mul64(expLen-32, multiplier)
		if carry > 0 {
			return math.MaxUint64
		}
		iterationCount = count
	}

	// Add the MSB position - 1 if expHead is non-zero
	if bitLen := expHead.BitLen(); bitLen > 0 {
		count, carry := bits.Add64(iterationCount, uint64(bitLen-1), 0)
		if carry > 0 {
			return math.MaxUint64
		}
		iterationCount = count
	}

	return max(iterationCount, 1)
}

// byzantiumModexpGas calculates the gas cost for the modexp precompile using Byzantium rules.
func byzantiumModexpGas(baseLen, expLen, modLen uint64, expHead uint256.Int) uint64 {
	const (
		multiplier = 8
		divisor    = 20
	)

	maxLen := max(baseLen, modLen)
	multComplexity := byzantiumMultComplexity(maxLen)
	if multComplexity == math.MaxUint64 {
		return math.MaxUint64
	}
	iterationCount := modexpIterationCount(expLen, expHead, multiplier)

	// Calculate gas: (multComplexity * iterationCount) / divisor
	carry, gas := bits.Mul64(iterationCount, multComplexity)
	gas /= divisor
	if carry != 0 {
		return math.MaxUint64
	}
	return gas
}

// berlinModexpGas calculates the gas cost for the modexp precompile using Berlin rules.
func berlinModexpGas(baseLen, expLen, modLen uint64, expHead uint256.Int) uint64 {
	const (
		multiplier = 8
		divisor    = 3
		minGas     = 200
	)

	maxLen := max(baseLen, modLen)
	multComplexity := berlinMultComplexity(maxLen)
	if multComplexity == math.MaxUint64 {
		return math.MaxUint64
	}
	iterationCount := modexpIterationCount(expLen, expHead, multiplier)

	// Calculate gas: (multComplexity * iterationCount) / divisor
	carry, gas := bits.Mul64(iterationCount, multComplexity)
	gas /= divisor
	if carry != 0 {
		return math.MaxUint64
	}
	return max(gas, minGas)
}

// GetRequiredGasAndComputationCost returns the gas required to execute the pre-compiled contract
// and the computation cost of the precompiled contract.
func (c *bigModExp) GetRequiredGasAndComputationCost(input []byte) (uint64, uint64) {
	// Parse input lengths
	baseLenBig := new(uint256.Int).SetBytes(getData(input, 0, 32))
	expLenBig := new(uint256.Int).SetBytes(getData(input, 32, 32))
	modLenBig := new(uint256.Int).SetBytes(getData(input, 64, 32))

	// Convert to uint64, capping at max value
	baseLen := baseLenBig.Uint64()
	if !baseLenBig.IsUint64() {
		baseLen = math.MaxUint64
	}
	expLen := expLenBig.Uint64()
	if !expLenBig.IsUint64() {
		expLen = math.MaxUint64
	}
	modLen := modLenBig.Uint64()
	if !modLenBig.IsUint64() {
		modLen = math.MaxUint64
	}

	// Skip the header
	if len(input) > 96 {
		input = input[96:]
	} else {
		input = input[:0]
	}

	// Retrieve the head 32 bytes of exp for the adjusted exponent length
	var expHead uint256.Int
	if uint64(len(input)) > baseLen {
		if expLen > 32 {
			expHead.SetBytes(getData(input, baseLen, 32))
		} else {
			expHead.SetBytes(getData(input, baseLen, expLen))
		}
	}

	// Choose the appropriate gas calculation based on the EIP flags
	if c.eip7883 {
		gas := osakaModexpGas(baseLen, expLen, modLen, expHead)
		return gas, gas/100 + params.BigModExpBaseComputationCost
	} else if c.eip2565 {
		gas := berlinModexpGas(baseLen, expLen, modLen, expHead)
		if gas == math.MaxUint64 {
			// Contract: Kaia doesn't divide computation cost by 100 for backward compatibility
			return math.MaxUint64, math.MaxUint64
		}
		return gas, gas/100 + params.BigModExpBaseComputationCost
	} else {
		gas := byzantiumModexpGas(baseLen, expLen, modLen, expHead)
		if gas == math.MaxUint64 {
			// Contract: Kaia doesn't divide computation cost by 100 for backward compatibility
			return math.MaxUint64, math.MaxUint64
		}
		return gas, gas/100 + params.BigModExpBaseComputationCost
	}
}

func (c *bigModExp) Run(input []byte, contract *Contract, evm *EVM) ([]byte, error) {
	var (
		baseLenBig       = new(big.Int).SetBytes(getData(input, 0, 32))
		expLenBig        = new(big.Int).SetBytes(getData(input, 32, 32))
		modLenBig        = new(big.Int).SetBytes(getData(input, 64, 32))
		baseLen          = baseLenBig.Uint64()
		expLen           = expLenBig.Uint64()
		modLen           = modLenBig.Uint64()
		inputLenOverflow = max(baseLenBig.BitLen(), expLenBig.BitLen(), modLenBig.BitLen()) > 64
	)
	if len(input) > 96 {
		input = input[96:]
	} else {
		input = input[:0]
	}
	// enforce size cap for inputs
	if c.eip7823 && (inputLenOverflow || max(baseLen, expLen, modLen) > 1024) {
		return nil, errors.New("one or more of base/exponent/modulus length exceeded 1024 bytes")
	}
	// Handle a special case when both the base and mod length is zero
	if baseLen == 0 && modLen == 0 {
		return []byte{}, nil
	}
	// Retrieve the operands and execute the exponentiation
	var (
		base = new(patched_big.Int).SetBytes(getData(input, 0, baseLen))
		exp  = new(patched_big.Int).SetBytes(getData(input, baseLen, expLen))
		mod  = new(patched_big.Int).SetBytes(getData(input, baseLen+expLen, modLen))
	)

// getData returns a slice from the data based on the start and size and pads
// up to size with zero's. This function is overflow safe.
func getData(data []byte, start uint64, size uint64) []byte {
	length := uint64(len(data))
	if start > length {
		start = length
	}
	end := min(start+size, length)
	return common.RightPadBytes(data[start:end], int(size))
}
