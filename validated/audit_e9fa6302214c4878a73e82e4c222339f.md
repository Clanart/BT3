### Title
Unauthenticated on-chain Mirror URLs enable Server-Side Request Forgery against DataLayer node HTTP fetches - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet holder who can submit a standard XCH spend can create a `Mirror` coin for **any** DataLayer store's `launcher_id`, not just their own, and embed an arbitrary attacker-chosen URL in the coin's memos. `DataLayerWallet.create_new_mirror()` performs no ownership check on the target `launcher_id` before curry/spend. Any peer node that subscribes to that store id later ingests this mirror URL as a download server and issues a plain, redirect-following `aiohttp` GET to it via `http_download()`. This is the same bug class as CVE-2022-29153 (HashiCorp Consul): an externally reachable HTTP fetch that follows redirects can be weaponized as an SSRF pivot to internal-only network endpoints.

### Finding Description
`create_new_mirror()` in [1](#0-0)  builds a standard coin spend whose memo list is `[launcher_id, *urls]`, with no validation that `launcher_id` corresponds to a store the caller owns or has any relationship to:

```
async def create_new_mirror(
    self, launcher_id: bytes32, amount: uint64, urls: list[bytes], ...
) -> None:
    await self.standard_wallet.generate_signed_transaction(
        amounts=[amount],
        puzzle_hashes=[create_mirror_puzzle().get_tree_hash()],
        ...
        memos=[[launcher_id, *(url for url in urls)]],
        ...
    )
```

This is exposed unauthenticated (any funded wallet key) via the RPC `dl_new_mirror` handler, [2](#0-1) , and the DataLayer `add_mirror` RPC endpoint, [3](#0-2) .

Once the mirror coin is confirmed on-chain, `DataLayerWallet.coin_added()` tracks it for **any** locally tracked `launcher_id` (i.e., any store the local node is subscribed to, regardless of who created the mirror), storing the attacker-supplied URLs: [4](#0-3) .

`DataLayer.update_subscriptions_from_wallet()` then pulls these mirror URLs into the local subscription table for actual use as download servers: [5](#0-4) .

During periodic sync, `fetch_and_validate()` picks one of these attacker-controlled server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`: [6](#0-5) .

`http_download()` issues a plain GET to `server_info.url + "/" + filename` with default aiohttp redirect-following behavior (redirects are not disabled), and only bounds the *size* of the downloaded body — it performs no host/scheme allow-listing before making the request:

```
async with session.get(
    server_info.url + "/" + filename,
    headers=headers,
    timeout=timeout,
    proxy=proxy_url,
) as resp:
``` [7](#0-6) 

The project's own architecture notes acknowledge mirror URLs are untrusted for *data integrity* purposes ("Do not treat mirror URLs, plugins, or static file names as trusted data sources" — [8](#0-7) ), but that mitigation only covers content validation against the wallet-advertised Merkle root after the fact — it does not prevent the underlying node from making an outbound network request to an attacker-chosen destination and following any redirect that destination issues, which is the SSRF primitive itself.

### Impact Explanation
Any DataLayer node that subscribes to a store can be coerced into issuing outbound HTTP requests, including following redirects, to a URL fully chosen by an unprivileged attacker who merely needs to fund a standard mirror-coin spend for that store's `launcher_id` (no ownership of the store required). This can be used to probe or interact with internal network services and cloud metadata endpoints reachable from the DataLayer host, and — because 3xx redirects are followed transparently — to bypass simple string/host allow-lists an operator might apply to the initial mirror URL. This qualifies as High severity per the source advisory's own classification and the "coin-set divergence" / node-behavior-affecting SSRF impact class described in the validation rules.

### Likelihood Explanation
Likelihood is high: creating a mirror coin only requires a signed standard transaction with an arbitrary XCH amount (even `0` per the reorg test at [9](#0-8) ) and does not require owning or having any special relationship to the target `launcher_id`. Any node subscribing to a popular/public DataLayer store is a viable victim as soon as it syncs mirror URLs from chain.

### Recommendation
- Require that `create_new_mirror()` / `dl_new_mirror` only accept `launcher_id`s that the wallet owns, or otherwise clearly document and enforce that mirror-consuming nodes must not trust unauthenticated mirror URLs for outbound network access.
- In `http_download()` and `download_file()`, disable redirect following (`allow_redirects=False`) or strictly validate the redirect target against the same host/scheme allow-list applied to the original URL.
- Add an allow-list / block-list for private, link-local, and cloud-metadata IP ranges before dialing any mirror or downloader URL.

### Proof of Concept
1. Attacker (any funded wallet, no relationship to victim store) submits `dl_new_mirror` with `launcher_id` = victim's store id and `urls = ["http://169.254.169.254"]` (or any internal target), via `chia/wallet/wallet_rpc_api.py:dl_new_mirror`.
2. Transaction confirms; victim node subscribed to that `launcher_id` picks up the mirror via `coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) and `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`).
3. On its next sync cycle, victim's `DataLayer.fetch_and_validate()` selects the attacker's mirror and calls `http_download()` (`chia/data_layer/download_data.py:298-323`), which sends a GET to the attacker-controlled URL and transparently follows any redirect it returns, completing the SSRF.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
