## Analysis: Analog identified — missing `debug_redact` enforcement in upb's text-debug encoder

The Ansible report is a classic **CWE-532/CWE-117 "sensitive data leaks into logs because an output-formatting code path fails to apply an existing masking control."** The Ansible `uri` module has a documented mitigation model (fields marked as sensitive should be scrubbed before being written to task output/logs) that one code path bypassed. The transferable invariant is: *"a redaction/masking annotation that the project itself defines as its security control for 'never appears in logs' must be honored by every serializer that produces logging/debugging output."*

Protobuf has exactly this kind of documented control: the `debug_redact` field option, whose entire purpose is to guarantee that annotated fields are replaced by `[REDACTED]` whenever a message is turned into a human-readable debug string for logging [1](#0-0) . The C++ implementation enforces this centrally in `TextFormat::Printer::TryRedactFieldValue`, checked on every field before printing [2](#0-1) , and `StringifyMessage` (backing `Message::DebugString()`/`ShortDebugString()`/`Utf8DebugString()`) turns this on by default via `SetRedactDebugString(true)` [3](#0-2) . Java has the equivalent `shouldRedact()` check inline in `printFieldValue` [4](#0-3) , and `DebugFormat`/tests confirm this extends even to extension fields [5](#0-4) .

However, the **upb** (C) core's own text-debug encoder — used to back the Python/PHP/Ruby upb-based language bindings — implements `_upb_MessageDebugString`/`_upb_FieldDebugString`/`upb_DebugString` with **no `debug_redact` check whatsoever**: it walks base fields, extension fields, and unknown fields and unconditionally prints their scalar, string, bytes, or nested-message contents [6](#0-5) [7](#0-6) [8](#0-7) . A repo-wide search for `debug_redact`/`DebugRedact` handling shows it appears only in the C++ (`text_format.cc`), Java (`TextFormat.java`), and descriptor/compiler-validation files — never inside any file under `upb/` — confirming the upb C core has no analog to `TryRedactFieldValue`/`shouldRedact`.

### Why this matters (impact)
This is the same *failed invariant* as the Ansible bug: an application author annotates a proto field `[debug_redact = true]` — the officially documented mechanism to keep secrets (tokens, credentials, PII) out of logs — and relies on `DebugString()`/`str(msg)`/`repr(msg)` honoring that annotation, exactly as it does in the C++ and Java runtimes. But if that same schema and message are used through the upb-backed Python (or PHP/Ruby) binding, `upb_DebugString` prints the field's real content verbatim into whatever the caller logs, silently defeating the redaction control the application depends on. The attacker model matches the report's constraints: a client sends an ordinary, valid, bounded protobuf message (the schema, generated code and registries are all trusted); the vulnerability is purely in the *presentation/logging layer*, not in wire-format parsing safety, memory safety, or resource exhaustion — consistent with the report's CWE-116/117/532 classification.

### What I could not fully verify
I could not conclusively confirm, within the given tool budget, that Python's `message.c` `tp_repr`/`tp_str` (or PHP/Ruby's message string conversion) actually dispatch to `upb_DebugString` for `str()`/`repr()` output rather than some other pure-Python/PHP formatter — `python/message.c` had 22 matches for repr/str-related symbols, which is strong circumstantial evidence, but I did not read the exact call site before running out of iterations. Confirming this wiring (and the equivalent in `php/`, `ruby/`, and `rust/upb/sys/upb_api.c` bindings) is a straightforward follow-up in a full checkout/session.

### Recommendation
Add the same `debug_redact` check that exists in `text_format.cc`/`TextFormat.java` into `upb/text/internal/encode.c`'s `_upb_FieldDebugString`/`_upb_MessageDebugString`, gated on the corresponding mini-table field option, so that `upb_DebugString` (and therefore any language binding that surfaces it as `str()`/`repr()`/logging output) redacts annotated fields identically to the C++/Java runtimes.

### Proof of Concept (conceptual, pending confirmation of Python binding call path)
1. Define a proto message with `string secret = 1 [debug_redact = true];` (mirroring `unittest_redaction.proto`'s `RedactedFields`).
2. Using the upb-based Python binding, build a message and set `secret = "supersecret-token"`.
3. Call `str(msg)` (or log it via standard logging) — expect `[REDACTED]` per the documented `debug_redact` contract (as verified by C++/Java unit tests in `text_format_unittest.cc`/`DebugFormatTest.java`), but `upb_DebugString`'s unconditional field printing (no redaction branch exists in `encode.c`) would emit the raw value instead.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

                                  const upb_MiniTableExtension* ext) {
  UPB_PRIVATE(_upb_TextEncode_Indent)(e);
  const upb_CType ctype = upb_MiniTableField_CType(f);
  const bool is_ext = upb_MiniTableField_IsExtension(f);
  char number[10];  // A 32-bit integer can hold up to 10 digits.
  snprintf(number, sizeof(number), "%" PRIu32, upb_MiniTableField_Number(f));
  // label is to pass down whether we're dealing with a "key" of a map or
  // a "value" of a map.
  if (!label) label = number;

  if (is_ext) {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "[%s]", label);
  } else {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "%s", label);
  }

  if (ctype == kUpb_CType_Message) {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, " {");
    UPB_PRIVATE(_upb_TextEncode_EndField)(e);
    e->indent_depth++;
    const upb_MiniTable* subm = ext ? upb_MiniTableExtension_GetSubMessage(ext)
                                    : upb_MiniTable_SubMessage(f);
    UPB_PRIVATE(_upb_MessageDebugString)(e, val.msg_val, subm);
    e->indent_depth--;
    UPB_PRIVATE(_upb_TextEncode_Indent)(e);
    UPB_PRIVATE(_upb_TextEncode_PutStr)(e, "}");
    UPB_PRIVATE(_upb_TextEncode_EndField)(e);
    return;
  }

  UPB_PRIVATE(_upb_TextEncode_Printf)(e, ": ");

  if (ctype ==
      kUpb_CType_Enum) {  // Enum has to be processed separately because of

    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "%" PRId32, val.int32_val);
  } else {
    UPB_PRIVATE(_upb_TextEncode_Scalar)(e, val, ctype);
  }

  UPB_PRIVATE(_upb_TextEncode_EndField)(e);
}

void UPB_PRIVATE(_upb_MessageDebugString)(txtenc* e, const upb_Message* msg,
                                          const upb_MiniTable* mt) {
  size_t iter = kUpb_BaseField_Begin;
  const upb_MiniTableField* f;
  upb_MessageValue val;

  // Base fields will be printed out first, followed by extension fields, and
  // finally unknown fields.

  while (UPB_PRIVATE(_upb_Message_NextBaseField)(msg, mt, &f, &val, &iter)) {
    if (upb_MiniTableField_IsMap(f)) {
      _upb_MapDebugString(e, val.map_val, f, mt);
    } else if (upb_MiniTableField_IsArray(f)) {
      // ext set to NULL as we're not dealing with extensions yet
      _upb_ArrayDebugString(e, val.array_val, f, mt, NULL);
    } else {
      // ext set to NULL as we're not dealing with extensions yet
      // label set to NULL as we're not currently working with a MapEntry
      _upb_FieldDebugString(e, val, f, mt, NULL, NULL);
    }
  }

  const upb_MiniTableExtension* ext;
  upb_MessageValue val_ext;
  iter = kUpb_Message_ExtensionBegin;
  while (upb_Message_NextExtension(msg, &ext, &val_ext, &iter)) {
    const upb_MiniTableField* f = &ext->UPB_PRIVATE(field);
    // It is not sufficient to only pass |f| as we lose valuable information
    // about sub-messages. It is required that we pass |ext|.
    if (upb_MiniTableField_IsMap(f)) {
      UPB_UNREACHABLE();  // Maps cannot be extensions.
      break;
    } else if (upb_MiniTableField_IsArray(f)) {
      _upb_ArrayDebugString(e, val_ext.array_val, f, mt, ext);
    } else {
      // label set to NULL as we're not currently working with a MapEntry
      _upb_FieldDebugString(e, val_ext, f, mt, NULL, ext);
    }
  }

  UPB_PRIVATE(_upb_TextEncode_ParseUnknown)(e, msg);
}

                       int options, char* buf, size_t size) {

  e.ptr = buf;
  e.end = UPB_PTRADD(buf, size);

  _upb_mapsorter_destroy(&e.sorter);
