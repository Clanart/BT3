## Verdict: Valid vulnerability

The binding claimed to be broken:

`db.payout_payer_operator_xonly_pk[widx] == Some(A.xonly_pk)` **for every payout tx that spends the exact withdrawal outpoint signed by the user for operator A's `withdraw()` call.**

Tracing the code confirms this binding is *not* enforced by the signature scheme actually used. [1](#0-0) 

`Operator::withdraw` builds `create_payout_txhandler` with `operator_xonly_pk = self.signer.xonly_public_key` placed in output index 2 (the OP_RETURN), then verifies the user's signature against `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)`. The signature is required to use `SinglePlusAnyoneCanPay`, as documented and enforced in tests: [2](#0-1) 

The sighash computation for `SinglePlusAnyoneCanPay` uses `Prevouts::One(txin_index, ...)` (only input 0 is committed, ANYONECANPAY) and BIP341 `SIGHASH_SINGLE` semantics commit only to the output at the same index (output 0): [3](#0-2) 

This means the anchor output (index 1) and the operator-identifying OP_RETURN output (index 2) are **not covered by the user's signature at all**. Since `DEFAULT_SEQUENCE = Sequence::ENABLE_RBF_NO_LOCKTIME`, the payout tx opts into RBF: [4](#0-3) 

An unprivileged party who observes A's broadcast payout tx in the mempool can copy input 0's outpoint and witness (the same signature bytes remain valid), keep output 0 byte-identical, and replace outputs 1/2 with an anchor-only structure (dropping the OP_RETURN), funding the replacement with their own UTXOs (ANYONECANPAY means A's other funding inputs are irrelevant to the signature), and RBF-broadcast at a higher fee rate — all without any private key belonging to A or any bridge access.

Once mined, `Verifier::update_finalized_payouts` scans the block, finds no OP_RETURN, and stores `NULL` for `payout_payer_operator_xonly_pk`: [5](#0-4) 

Later, `Verifier::is_kickoff_malicious` reads this info and treats a `None` operator pubkey as an automatic malicious verdict regardless of who actually funded the payout: [6](#0-5) 

This flows into `handle_kickoff`, which queues a `Challenge` transaction against A's kickoff: [7](#0-6) 

No existing guard (`is_deposit_valid`, `is_profitable`, `SECP.verify_schnorr`, storage-proof checks, etc.) constrains the outputs beyond output 0, because the chosen sighash flag was explicitly designed to allow fee-bumping flexibility but was not paired with any secondary mechanism (e.g., re-verifying the mined tx's OP_RETURN against the operator that called `withdraw`, or using a sighash flag that commits to all outputs).

### Title
Third-party malleable OP_RETURN in payout tx lets anyone strip operator attribution via RBF, causing honest operator's kickoff to be marked malicious - (File: core/src/operator.rs)

### Summary
`Operator::withdraw` signs/verifies the payout transaction's input using `SinglePlusAnyoneCanPay`, which per BIP341 commits only to input 0 and output 0. The OP_RETURN output that records which operator fronted the withdrawal (output 2) and the anchor (output 1) are unsigned, so anyone who observes the broadcast payout tx can construct an RBF-replacement with the same input/output-0 and a stripped or altered OP_RETURN, funded with their own inputs.

### Finding Description
The broken binding: `db.payout_payer_operator_xonly_pk[widx] == Some(A)` whenever A funded the withdrawal via `withdraw()`. Because `create_payout_txhandler` puts the operator identity in output 2 [8](#0-7)  but the verified sighash (`SinglePlusAnyoneCanPay`) only commits to input 0 and output 0 [9](#0-8) , an attacker can reuse A's exact input-0 outpoint+witness in a new transaction that removes the OP_RETURN and RBF-replace A's tx in the mempool (enabled by `DEFAULT_SEQUENCE`). When mined, `update_finalized_payouts` finds no valid OP_RETURN and stores `NULL` operator pubkey [5](#0-4) , which `is_kickoff_malicious` unconditionally treats as malicious [6](#0-5) , triggering a `Challenge` against A's legitimate later kickoff.

### Impact Explanation
An honest operator (A) who correctly fronted a user's withdrawal can be permanently prevented from reimbursement and have their kickoff flagged malicious, triggering `Challenge`/`Disprove` flow that can burn A's collateral — despite A having paid the user out of pocket. This is repeatable per withdrawal and per operator, since it depends only on the universally-used `SinglePlusAnyoneCanPay` payout signing scheme, not on any operator-specific secret.

### Likelihood Explanation
Preconditions: default paramset (`DEFAULT_SEQUENCE = ENABLE_RBF_NO_LOCKTIME`) is used unconditionally for the payout input [4](#0-3) , no special config needed. Attacker cost is only mempool fee-bump (outbidding A's fee, no bridge funds required since output 0 must remain unchanged). Feasible for any observer of the Bitcoin mempool; entirely automatable and repeatable across every withdrawal serviced by every operator.

### Recommendation
Bind the operator identity to the user's signature: either move the operator's xonly pubkey commitment into an output covered by `SIGHASH_SINGLE` (output index 0), or switch to a sighash flag/scheme (e.g., `AllPlusAnyoneCanPay` with a fixed-shape transaction, or a covenant/anti-malleability construction) that commits to all outputs including the OP_RETURN, or verify off-chain that only the operator who obtained the user's off-chain authorization is entitled to attribute a mined payout to themselves (e.g., requiring the attribution as part of the signed message rather than an unsigned OP_RETURN).

### Proof of Concept
`cargo test` plan (regtest, no mainnet/live Citrea), building on `core/src/test/manual_reimbursement.rs`:
1. Run `deposit_and_get_reimbursement` up through the point where operator A's `withdraw()` produces `payout_tx_A` (with valid OP_RETURN containing A's xonly pk) and broadcasts it via `TxSender`/`fund_raw_transaction`.
2. Before confirmation, fetch `payout_tx_A` from the node's mempool; extract input 0 (`outpoint`, `witness`).
3. Construct `payout_tx_B`: input 0 = copied outpoint+witness; output 0 = byte-identical to `payout_tx_A`'s output 0; output 1 = anchor only funded by a locally controlled UTXO/signature; omit the OP_RETURN entirely. Sign the attacker-added input(s) with a throwaway key.
4. Broadcast `payout_tx_B` with a higher fee rate than `payout_tx_A`, assert it displaces `payout_tx_A` in the mempool, then mine it.
5. Run the verifier's block-sync path (`handle_finalized_block` → `update_finalized_payouts`) and assert `db.get_payout_info_from_move_txid(...).0 == None` (binding broken: expected `Some(A)`).
6. Have operator A send its legitimate kickoff; call `is_kickoff_malicious` (or drive it via `handle_kickoff`) and assert it returns `true`, and that a `Challenge` tx is queued against A's honest kickoff.

```rust
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
```
