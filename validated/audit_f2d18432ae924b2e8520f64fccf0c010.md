### Title
Stale `safe.directory` trust entry is never revoked when a repository is removed or relocated - ([File: app/src/lib/stores/app-store.ts])

### Summary
GitHub Desktop lets a user "Trust" a Git working directory that Git has flagged as unsafe (owned by a different user, e.g. a shared machine, network share, or removable drive). Trusting adds the path to the **global**, machine-wide `safe.directory` Git config value via `addSafeDirectory` [1](#0-0) , which is a system-wide, path-based allow-list, not tied to the specific repository content or identity that was trusted. When the user later removes that repository from Desktop (`_removeRepository` → `repositoriesStore.removeRepository`) [2](#0-1) [3](#0-2) , Desktop never calls the corresponding `removeGlobalConfigValue('safe.directory', ...)` to revoke the trust. The same is true for `_relocateRepository`, which drops the stale path entirely without ever untrusting it [4](#0-3) . This is the same class of bug as the reported Aave issue: a boolean "trust/enabled" flag that should be cleared once its underlying justification (the specific repository at that path) goes away, but is left permanently `true` at the OS/global-config level.

### Finding Description
The invariant that should hold is: *"a path is only treated as Git-safe for as long as Desktop still associates it with the specific repository the user consciously trusted."* Instead, `safe.directory` is a path string, appended once and never removed [5](#0-4) . The UI flows that add this entry are `MissingRepository.onTrustDirectory` [6](#0-5)  and `AddExistingRepository.onTrustDirectory` [7](#0-6) . Neither the repository-removal path (`_removeRepository`/`removeRepository`) nor the relocation path (`_relocateRepository`) ever calls `removeGlobalConfigValue` for `safe.directory` [8](#0-7) [3](#0-2) . Existing guards (Git's own ownership check via `getRepositoryType`, which returns `'unsafe'` for mismatched ownership) are bypassed entirely for any path once it has ever been added to the safe list, because Git's safety check is purely path-based and does not consider whether the on-disk content matches what was originally trusted [9](#0-8) .

### Impact Explanation
On systems where the untrusted-owner scenario legitimately arises (shared workstations, mounted network shares, removable media, some CI/container mount setups), a path that a user once trusted remains permanently exempt from Git's ownership check even after the user removes that repository from Desktop or the original content is deleted. If another user/process/attacker who has write access to that same path (this is exactly the precondition Git's unsafe-directory check exists to defend against) later places a different Git repository there — with malicious hooks, `core.fsmonitor`, filters, or `.gitattributes`-driven executables — Desktop and the embedded Git will silently treat it as trusted and run ordinary operations (status, checkout, commit, pull) against it, executing attacker-controlled hooks with the user's privileges. This is a case of "attacker controls a git repository object at a path" leading to code execution, exactly the class this rule targets, and it corrupts the security invariant "no execution from untrusted-owner directories" silently.

### Likelihood Explanation
This requires the specific precondition of a shared/multi-user path (already the only scenario Git's `safe.directory` protection targets), so it is not a universal attack, but it does not require local malware, admin rights, or leaked credentials — only that the victim previously trusted a directory that is later reused by another local user/process, a realistic scenario on shared machines, mounted drives, or CI runners with persistent Desktop state. Likelihood is moderate: it depends on directory reuse but requires no unusual user action beyond the one legitimate "Trust Repository" click Desktop already prompts for.

### Recommendation
When a repository is removed from Desktop (`removeRepository`) or its path is invalidated/relocated (`_relocateRepository`, `updateRepositoryMissing`), also revoke the corresponding `safe.directory` entry via `removeGlobalConfigValue('safe.directory', path)` for that specific path, mirroring the `addSafeDirectory` call made when trust was granted. Consider also scoping trust to the specific `.git` directory identity where possible, rather than the raw path, to avoid a "trust follows the path" persistence assumption.

### Proof of Concept
1. On a shared/multi-user machine, an unsafe repository exists at `/shared/repo` (owned by `userB`).
2. `userA` adds it in Desktop, sees the "potentially unsafe" screen, and clicks **Trust Repository** — Desktop runs `git config --global --add safe.directory /shared/repo` [10](#0-9) .
3. `userA` later removes this repository from Desktop via the repository list ("Remove") — this only deletes the DB record; `safe.directory` is untouched [3](#0-2) .
4. `userB` deletes `/shared/repo` and creates a new repository at the same path containing a malicious `post-checkout` hook.
5. `userA` re-adds `/shared/repo` in Desktop (or it's re-discovered); `getRepositoryType` no longer reports `'unsafe'` because `safe.directory` still lists the path, so Desktop proceeds normally and Git executes the malicious hook during the next checkout/clone/status refresh, achieving code execution as `userA`.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}

  public async _relocateRepository(repository: Repository): Promise<void> {
    const path = await showOpenDialog({ properties: ['openDirectory'] })

    if (path === null) {
      return
    }

    const rt = await getRepositoryType(path)

    if (rt.kind === 'regular') {
      // The repository has moved, so any main worktree we recorded before now
      // points at where it used to be. Resolve it again from the new location.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        rt.topLevelWorkingDirectory,
        rt.gitDir,
        await this.findMainWorktreePath(rt.topLevelWorkingDirectory)
      )
    } else if (rt.kind === 'unsafe') {
      // Git refuses to run in a repository it considers unsafe, so there's no
      // resolving the main worktree here. Drop the recorded path rather than
      // keep one we know is stale.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        path,
        undefined,
        undefined,
        true
      )
    } else {
      this.emitError(new Error(this.getInvalidRepoPathsMessage([path])))
    }
  }

  public async _removeRepository(
    repository: Repository | CloningRepository,
    moveToTrash: boolean
  ): Promise<void> {
    try {
      if (moveToTrash) {
        try {
          await shell.moveItemToTrash(repository.path)
        } catch (error) {
          log.error('Failed moving repository to trash', error)

          this.emitError(
            new Error(
              `Failed to move the repository directory to ${TrashNameLabel}.\n\nA common reason for this is that the directory or one of its files is open in another program.`
            )
          )
          return
        }
      }

      if (repository instanceof CloningRepository) {
        this._removeCloningRepository(repository)
      } else {
        await this.repositoriesStore.removeRepository(repository)
      }
    } catch (err) {
      this.emitError(err)
      return
    }

    const allRepositories = await this.repositoriesStore.getAll()
    if (allRepositories.length === 0) {
      this._closeFoldout(FoldoutType.Repository)
    } else {
      this._showFoldout({ type: FoldoutType.Repository })
    }
  }
