### Title
Trusting a "dubious ownership" repository writes a permanent, unscoped `safe.directory` exception that outlives the trusted repo and re-authorizes any future (attacker-controlled) content placed at that path - ([File: app/src/lib/git/config.ts])

### Summary
When Desktop encounters a repository whose directory is owned by a different user than the current OS user, Git refuses to operate on it ("dubious ownership") and Desktop surfaces a "Trust Repository" action. Clicking it calls `addSafeDirectory`, which permanently appends the path to the user's **global** `safe.directory` git config. This exception is never removed by Desktop under any circumstance (repository removal, path becoming missing, or the directory's contents being replaced).

### Finding Description
The bug-class from the Sherlock report is: an action that should be scoped to a single instance (a specific malicious proposal) instead mutates persistent global state (community score counters) that is never rolled back, letting the actor keep an unearned privilege tied to that instance forever.

In GitHub Desktop, the analog is `addSafeDirectory`: [1](#0-0) 
This is invoked from the "Trust Repository" UI flows in `AddExistingRepository.onTrustDirectory` and `MissingRepository.onTrustDirectory`: [2](#0-1) [3](#0-2) 

The trust decision is keyed **only on filesystem path**, not on repository identity (no commit SHA, remote URL, or git-dir fingerprint is recorded). `getRepositoryType` detects "unsafe" purely from Git's dubious-ownership error for a path: [4](#0-3) 

Once a path is added to `safe.directory`, there is no corresponding `removeSafeDirectory` function anywhere in the codebase — a repo-wide search confirms only `addSafeDirectory` exists, with no removal call site. This mirrors the exact "TODO: We currently never clear ... associations" pattern already acknowledged elsewhere in the codebase for GitHub repository associations: [5](#0-4) 

Because `safe.directory` entries persist indefinitely and are scoped to a path (not to repository content), any future filesystem object that later occupies that same path — e.g., a different, attacker-controlled repository dropped there after the original repo is deleted/moved, a re-mounted USB drive, a symlink retargeted to point elsewhere, or a shared-machine scenario where another OS user's directory ends up at the same absolute path — silently inherits the "trusted" status. Git will no longer warn about "dubious ownership" for that path, and Desktop will treat it as a normal repository, running git operations (and any hooks/config Git reads from that working tree) without the ownership warning that is supposed to gate exactly this scenario.

### Impact Explanation
`safe.directory` is a documented Git ownership-mismatch guard specifically designed to prevent an attacker who can place files at a path owned by another user (or who controls a directory a victim will git-operate on) from having their working-tree configuration/hooks executed. By granting the exception per-path-forever instead of per-verified-repository-instance, Desktop's "Trust Repository" feature permanently disables this guard for that filesystem location. If the original trusted repo is deleted and something else — including attacker-supplied content — is later placed at that exact path (a realistic scenario on shared machines, restored backups, redeployed CI checkout directories, or symlink swaps), the ownership check that would normally re-trigger a warning is bypassed, and Desktop/Git will operate on the malicious repository as if pre-approved, including reading its local `.git/config` (`core.hooksPath`, `core.fsmonitor`, etc.) without further user consent.

### Likelihood Explanation
Requires the user to have trusted at least one repository at a path previously (a supported, expected workflow) and later have that same path repopulated with different/malicious content owned by someone else — plausible on shared/multi-user systems, in CI-style reused workspace directories, or via directory-swap/symlink tricks, but it does depend on path reuse rather than a single click by an unsuspecting user on arbitrary attacker content. No admin rights or pre-existing malware are needed; the attacker only needs the ability to place content at a path the victim previously trusted.

### Recommendation
Do not treat `safe.directory` as a permanent, path-only exception granted by the UI. Either (a) scope the trust decision to the repository's identity (e.g., verify `.git` directory identity/inode or a stored fingerprint before treating a path as trusted, not just the string path) and re-validate it on every operation, or (b) remove the `safe.directory` entry (`git config --global --unset-all safe.directory <path>`) when the corresponding repository is removed from Desktop or detected as missing/replaced, so the exception does not outlive the trusted repository instance.

### Proof of Concept
1. User adds/opens `/shared/repoA` in Desktop; Git flags it as "unsafe" (different owner); user clicks "Trust Repository" → `addSafeDirectory('/shared/repoA')` permanently adds the path to the global git config.
2. User removes the repository from Desktop (or the directory is deleted).
3. An attacker (another OS user with write access to `/shared`, or a process that recreates that mount point/symlink) places a different, malicious git repository at the identical path `/shared/repoA`, owned by the attacker.
4. User re-adds/re-opens `/shared/repoA` in Desktop. Because `safe.directory` still contains that path, `getRepositoryType` no longer returns `{ kind: 'unsafe' }` — Git silently accepts the attacker's repository as already trusted, and Desktop performs normal git operations against it without any renewed ownership warning.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```
