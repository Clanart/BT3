Audit Report

## Title
`InitializeAccount`/`InitializeAccountV2` accepts unchecked zero `Pubkey` for `authorized_withdrawer`, permanently locking vote account funds - (File: programs/vote/src/vote_state/mod.rs)

## Summary
`vote_state::initialize_account` and `vote_state::initialize_account_v2` persist the caller-supplied `VoteInit`/`VoteInitV2` fields (`node_pubkey`, `authorized_voter`, `authorized_withdrawer`) into vote state without any check against `Pubkey::default()`. If `authorized_withdrawer` is set to the zero pubkey, the account's lamports become permanently unwithdrawable because `withdraw` requires a real signer matching that authority, which the all-zero pubkey can never satisfy in practice.

## Finding Description
`initialize_account` only calls `VoteStateHandler::check_vote_account_length`, checks the account isn't already initialized, and verifies the `node_pubkey` signer via `verify_authorized_signer(&vote_init.node_pubkey, signers)` before writing state via `VoteStateHandler::init_vote_account_state` [1](#0-0) . `initialize_account_v2` follows the same pattern, additionally validating collector accounts and the BLS proof-of-possession, but likewise performs no check on `authorized_withdrawer`/`authorized_voter`/`node_pubkey` against `Pubkey::default()` [2](#0-1) . Both are dispatched directly from the processor for `VoteInstruction::InitializeAccount`/`InitializeAccountV2` with no additional zero-address guard in that layer either [3](#0-2) .

The `withdraw` function subsequently enforces authorization solely via `verify_authorized_signer(vote_state.authorized_withdrawer(), signers)` [4](#0-3) . If `authorized_withdrawer` was initialized to `Pubkey::default()`, no legitimate signer can ever populate `signers` with that value (the all-zero value is not a pubkey any real signer can produce), so this check can never be satisfied and the withdrawal path is permanently blocked.

## Impact Explanation
Any lamports held by (or credited to) a vote account whose `authorized_withdrawer` is initialized to the zero pubkey become permanently unwithdrawable, since the sole authorization gate in `withdraw` cannot be satisfied by any real signer. This matches the "fund loss" impact category for unprivileged, reachable runtime/built-in issues, since the vulnerable path is exercised by an ordinary `InitializeAccount`/`InitializeAccountV2` instruction requiring no special privilege.

## Likelihood Explanation
The `InitializeAccount`/`InitializeAccountV2` instructions are fully reachable by any unprivileged user with only public inputs (the vote account and node signer) [3](#0-2) . However, exploitation requires the vote-account creator to (accidentally or deliberately) pass `Pubkey::default()` as `authorized_withdrawer`; the harmed party is the same party that constructs the instruction, so this is a self-inflicted foot-gun rather than a cross-account theft primitive, reducing the practical incentive for third-party exploitation while still constituting a genuine, reachable fund-loss defect.

## Recommendation
Add an explicit rejection of `Pubkey::default()` for `authorized_withdrawer` (and arguably `authorized_voter`/`node_pubkey`) inside `vote_state::initialize_account` and `initialize_account_v2` in `programs/vote/src/vote_state/mod.rs`, returning `InstructionError::InvalidArgument` when detected, before calling `VoteStateHandler::init_vote_account_state`/`init_vote_account_state_v2`.

## Proof of Concept
1. Create a new, rent-exempt vote account owned by the vote program.
2. Submit `VoteInstruction::InitializeAccount(VoteInit { node_pubkey, authorized_voter, authorized_withdrawer: Pubkey::default(), commission: 0 })` with `node_pubkey` as a valid signer, following the account layout in `test_initialize_vote_account` [5](#0-4) .
3. Observe the instruction succeeds because only signer/already-initialized checks are enforced [1](#0-0) .
4. Attempt `VoteInstruction::Withdraw` with any signer set; `verify_authorized_signer(vote_state.authorized_withdrawer(), signers)` in `withdraw` can never succeed since `authorized_withdrawer` is `Pubkey::default()` [4](#0-3) , permanently locking the account's lamports.

pub fn initialize_account_v2<S: std::hash::BuildHasher, F>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    vote_init: &VoteInitV2,
    inflation_rewards_collector: NewCommissionCollector,
    block_revenue_collector: NewCommissionCollector,
    signers: &HashSet<Pubkey, S>,
    clock: &Clock,
    rent: &Rent,
    consume_pop_compute_units: F,
) -> Result<(), InstructionError>
where
    F: FnOnce() -> Result<(), InstructionError>,
{
    VoteStateHandler::check_vote_account_length(vote_account, target_version)?;
    let versioned = vote_account.get_state::<VoteStateVersions>()?;

    if !versioned.is_uninitialized() {
        return Err(InstructionError::AccountAlreadyInitialized);
    }

    // node must agree to accept this vote account
    verify_authorized_signer(&vote_init.node_pubkey, signers)?;

    // Per SIMD-0464, validate the collector accounts using the same checks as
    // `UpdateCommissionCollector` (SIMD-0232).
    let inflation_rewards_collector_key =
        inflation_rewards_collector.validate_and_resolve_key(vote_account, rent)?;
    let block_revenue_collector_key =
        block_revenue_collector.validate_and_resolve_key(vote_account, rent)?;

    // verify the BLS pubkey proof of possession
    verify_bls_proof_of_possession(
        vote_account.get_key(),
        &vote_init.authorized_voter_bls_pubkey,
        &vote_init.authorized_voter_bls_proof_of_possession,
        consume_pop_compute_units,
    )?;

    VoteStateHandler::init_vote_account_state_v2(
        vote_account,
        vote_init,
        &inflation_rewards_collector_key,
        &block_revenue_collector_key,
        clock,
        target_version,
    )
}
