### Title
Automatic remote-URL rewrite trusts an unverified GitHub API `clone_url` field, allowing silent push/fetch redirection to an attacker-controlled remote - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The Astaria bug is fundamentally about a privileged flow (payment routing) trusting an attacker-controllable identity value (the lien's `ownerOf`/payee address) without verifying it is safe, and then automatically "pushing" value to it. The closest reachable analog in GitHub Desktop is `updateRemoteUrl`, which automatically rewrites the local git remote URL based on a `clone_url` string taken from a GitHub API repository object, with only superficial checks (protocol equality and "did the user manually change it" heuristics), and no verification that the new URL is trustworthy. Once rewritten, all subsequent `push`/`fetch`/`pull` operations use that URL without further confirmation.

### Finding Description
`updateRemoteUrl` reads `apiRepo.clone_url` — a field on a `IAPIRepository` object obtained from the GitHub REST API — and, if the protocol of the existing remote matches the protocol of the new URL and the current remote still equals the previously cached `gitHubRepository.cloneURL`, silently calls `gitStore.setRemoteURL(...)` to overwrite the repository's default remote: [1](#0-0) [2](#0-1) 

There is no verification that the new `clone_url` still points to the same physical host/repository the user originally trusted — the only guards are:
- protocol equality (`https` vs `https`, or `ssh` vs `ssh`) via `URL.parse`,
- "the current remote hasn't been manually edited" (`remoteUrlUnchanged`).

Neither of these validates the target host. This mirrors `LienToken#_getPayee`, which blindly trusts `ownerOf(lienId)` (an attacker-transferable value) as the destination for a "push" payment instead of validating it — here, `apiRepo.clone_url` (an attacker/server-controllable field on a GitHub API response object) is trusted as the destination for the git remote used in all future `push`/`fetch` "push" operations: [3](#0-2) [4](#0-3) 

Once `setRemoteURL` runs, `remote.url` is used directly to build the git command executed against the working copy — no interactive confirmation dialog is shown to the user, unlike the manual settings flow in `repository-settings.tsx`, which does surface the URL change for explicit user approval: [5](#0-4) [6](#0-5) 

The corrupted value is the repository's `origin` remote URL (`git remote get-url origin`), which is silently rewritten from an untrusted `IAPIRepository.clone_url` string rather than from a value the user explicitly reviewed.

### Impact Explanation
If a `GitHubRepository`'s API metadata can be made to report an attacker-chosen `clone_url` (e.g., a compromised/malicious GitHub Enterprise Server instance, a man-in-the-middle on an enterprise API proxy, or any scenario where the API response for a tracked repository is attacker-influenced — explicitly an in-scope trust boundary per this task's "GitHub API object" category), Desktop will silently repoint the user's default remote to the attacker's server. From that point on:
- `git push` (via `push.ts`) sends the user's commits/branches to the attacker-controlled remote, exposing source code and potentially credentials embedded in history.
- `git fetch`/`pull` retrieves objects from the attacker's server, feeding attacker-controlled refs/objects back into the user's repository — a "silent corruption of what the user commits or pushes" outcome, matching the impact class called out for this exercise.
- Because the switch happens silently, the user has no visible warning (unlike the explicit `repository-settings.tsx` UI flow), so they will keep working against the wrong remote without realizing it.

### Likelihood Explanation
Likelihood is moderate-to-low because it requires the attacker to control (or corrupt) the specific `clone_url` field of a `IAPIRepository` object that Desktop consumes for a repository the victim already has cloned/tracked — realistic mainly in enterprise/GHES environments with a compromised or spoofed API endpoint, or any code path that constructs `IAPIRepository` objects from less-trusted sources. It does not require local/physical access, admin rights, or pre-existing malware, and does not rely on unnatural user steps — the rewrite happens automatically as part of normal repository refresh flows.

### Recommendation
- Never auto-rewrite the default remote URL without explicit user confirmation, mirroring the `RepositorySettings` manual flow that surfaces a diff and requires user action.
- If automatic syncing of renamed/transferred repositories is required, restrict it to same-host changes (e.g., only allow owner/name path changes on the exact same hostname the account is already authenticated against) rather than accepting an arbitrary new hostname/URL from the API payload.
- Log/telemetry and, ideally, a one-time non-blocking notification whenever the origin URL is changed programmatically, so users can detect unexpected remote changes.

### Proof of Concept
1. Track a repository whose `GitHubRepository.cloneURL` currently equals the remote `origin` URL (the common case for repos cloned via Desktop).
2. Cause a repository-metadata refresh where the underlying `IAPIRepository.clone_url` for that repository resolves to an attacker-controlled URL sharing the same protocol scheme (e.g., `https://attacker.example/victim/repo.git`) — reachable if the API endpoint being queried is a compromised/malicious GHES instance or a MITM'd API proxy.
3. `updateRemoteUrl` computes `protocolsMatch = true`, `remoteUrlUnchanged = true`, `urlsMatch = false`, and calls `gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)` with no user prompt: [7](#0-6) 
4. The next `git push`/`git fetch` executed by Desktop silently targets `https://attacker.example/victim/repo.git`: [8](#0-7)

    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

export async function setRemoteURL(
  repository: Repository,
  name: string,
  url: string
): Promise<true> {
  await git(['remote', 'set-url', name, url], repository.path, 'setRemoteURL')
  return true
}
