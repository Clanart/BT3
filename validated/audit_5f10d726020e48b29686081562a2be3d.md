### Title
Global gasless bundle-tx queue slot exhaustion enables griefing/DoS of KIP-247 gasless swap service - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`PreAddTx()` in the gasless module enforces a single, global cap (`MaxBundleTxsInQueue`, default 200) shared by every sender's gasless approve/swap transactions before a transaction is even considered for promotion. Because the slot is global rather than per-sender or reserved-per-user, an attacker can cheaply flood the queue with bundle-classified transactions to occupy all slots, blocking legitimate users' gasless swap transactions from ever being tracked/promoted — directly analogous to the reported OpenQ NFT deposit-limit griefing bug where a small shared slot count is exhausted by an unprivileged, low-cost caller.

### Finding Description
The gasless module tracks "bundle" transactions (`GaslessApproveTx`/`GaslessSwapTx`) in a shared `knownTxs` map. Before any transaction is added to the underlying tx pool, `PreAddTx` checks the queue occupancy against a single global limit: [1](#0-0) 

`GetMaxBundleTxsInQueue()` returns the configured `MaxBundleTxsInQueue`, whose default is only 200 and is **not partitioned per sender** — it is one shared counter across the whole network of gasless users: [2](#0-1) [3](#0-2) 

A transaction is classified as a "bundle tx" purely based on `IsApproveTx`/`IsSwapTx` structural checks (target contract whitelist, calldata shape, spender/token whitelist) — it does **not** require the sender to actually hold funds or previously interact with the protocol: [4](#0-3) [5](#0-4) 

The README documents that the module intentionally skips normal sender-balance checks for gasless transactions, and the real economic checks (token balance, allowance, swap amount validity) are only optionally enforced depending on `BalanceCheckLevel`: [6](#0-5) [7](#0-6) 

If an operator runs with a lower `BalanceCheckLevel` (e.g. `BalanceCheckLevelStatic`, which only checks the relation between amounts and deadline, not actual token balance/allowance), an attacker can generate many syntactically valid approve/swap tx pairs from throwaway EOAs — using a whitelisted token/router pair — at essentially zero cost (only requiring gas, and the gas itself is meant to be lent by the proposer via `GetLendTxGenerator`). Each such tx is classified as `IsBundleTx` and consumes one of the 200 global queue slots via `PreAddTx`. Once `numQueue() >= MaxBundleTxsInQueue`, every subsequent legitimate user's gasless approve/swap tx submitted to that node is rejected outright with `ErrBundleTxQueueFull`, exactly mirroring how the OpenQ bug let an attacker occupy all 5 shared `nftDepositLimit` slots to block the legitimate issuer's real NFT deposit.

This is directly analogous to the reported bug class: a small, shared, and unprivileged-writable admission limit (5 NFT slots in OpenQ vs. 200 bundle-tx slots in Kaia gasless) that any unprivileged caller can exhaust cheaply, denying the intended real users' service.

### Impact Explanation
Exhausting the `MaxBundleTxsInQueue` slots denies legitimate gasless users the ability to have their `GaslessApproveTx`/`GaslessSwapTx` even considered for promotion on the affected node, causing a functional DoS of the KIP-247 gasless feature at that node (i.e., users who rely on the proposer lending gas can be locked out). Since the queue is a shared, global resource rather than isolated per sender, a single attacker with many cheap throwaway keys can occupy it entirely, independent of stake or balance size — this is a Medium-severity griefing/DoS analogous to the source report's rating.

### Likelihood Explanation
The classification logic (`IsApproveTx`/`IsSwapTx`) only requires calldata shape and whitelisted addresses — reachable by any externally submitted transaction to a public RPC/tx-pool endpoint, with no special privilege. Exploitability's cost depends on the deployment's `BalanceCheckLevel`; at the strictest level (`BalanceCheckLevelAll`, the documented default) balance/allowance checks partially mitigate it, but the config explicitly allows operators to lower this level, and even under `BalanceCheckLevelAll` the queue slot is still consumed by `PreAddTx` (a `knownTxs` queue entry) prior to eventual pool-level balance validation, since `PreAddTx` performs no balance check itself — it is purely a structural classification and counter check.

### Recommendation
Partition `MaxBundleTxsInQueue` per-sender (or track a per-address share of the limit, similar to `ExecSlotsAccount`/`NonExecSlotsAccount` in the base tx pool config) so that no single actor (or set of throwaway EOAs) can occupy the entire shared bundle queue. Alternatively, require stronger, cheap-to-verify pre-conditions (e.g., minimal token balance) before a tx consumes a `PreAddTx` bundle-queue slot, regardless of configured `BalanceCheckLevel`.

### Proof of Concept
1. Attacker generates N throwaway private keys (N approaching `MaxBundleTxsInQueue`, default 200).
2. For each key, craft a valid `GaslessApproveTx` (`approve(spender=whitelisted SwapRouter, amount=MaxUint256)` to a whitelisted ERC20) satisfying `isApproveTx()` checks in [8](#0-7)  — no real token holdings required if `BalanceCheckLevel < TokenBalanceAndAllowance`.
3. Submit all N transactions to the target node's tx pool/public RPC.
4. Each is classified `IsBundleTx() == true` and consumes a global queue slot via `PreAddTx` in [9](#0-8) .
5. Once `numQueue() >= MaxBundleTxsInQueue`, a legitimate user's gasless approve/swap transaction submitted afterward is rejected with `ErrBundleTxQueueFull`, denying them the gasless service on that node.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}
