### Title
Unguarded dict-key access on attacker-controlled Any JSON (`value['value']`) can raise an undocumented, uncaught `KeyError` instead of `ParseError` — ([File: python/google/protobuf/json_format.py])

### Summary
The Shardus report shows a classic "some inputs are validated, a sibling input is not" bug: `blockHash` length is checked, but the case where `blockHash` is entirely absent (`undefined`) is never checked before `.length` is read, so an unguarded property access throws an exception outside any `try/catch`, crashing the process. The Protobuf analog is in `json_format.py`'s `_ConvertAnyMessage`, which parses attacker-supplied `google.protobuf.Any` JSON via the public `json_format.Parse`/`ParseDict` API. It explicitly validates one attacker-controlled key (`@type`) with a `try/except KeyError`, but the sibling key (`value`) used to hold the packed payload for wrapper types and well-known types is accessed directly with `value['value']` and is not guarded the same way.

### Finding Description
In `_ConvertAnyMessage` [1](#0-0) , the function first safely extracts `@type`: [2](#0-1) 

but then, for wrapper messages (`google/protobuf/wrappers.proto`, e.g. `Int32Value`, `StringValue`) and other well-known types in `_WKTJSONMETHODS`, it indexes the same attacker-controlled `value` dict a second time without any guard: [3](#0-2) 

If the caller supplies JSON such as `{"@type": "type.googleapis.com/google.protobuf.Int32Value"}` (an `@type` for a wrapper type but no `value` key), `value['value']` raises a raw Python `KeyError`, a type not declared by the documented contract of `json_format.Parse`, which states only `ParseError` is raised on parsing problems [4](#0-3) . This mirrors the missing-parameter/missing-check pattern in the report: one required key (`blockHash`/`@type`) is defensively checked, the other (`value`) is not, and the resulting exception escapes the intended error-handling path.

The attacker-controlled value here is entirely bounded JSON text passed through the public `Parse`/`ParseDict` API — no privileged access, no huge payloads, no schema tampering, just a syntactically valid but semantically incomplete `Any` JSON object, exactly matching the assumption that this is client-supplied bounded input hitting a supported public parse API.

### Impact Explanation
This does not achieve memory corruption or RCE; it is an availability/robustness issue in a consuming application, analogous to the reported impact category (unhandled crash from parsing untrusted input). If an application built on `protobuf`'s Python JSON parser only catches `google.protobuf.json_format.ParseError` (per the documented API contract) around calls to `Parse`/`ParseDict` when accepting external JSON (e.g., a gRPC-JSON gateway, an internal API accepting Any-typed payloads), an unhandled `KeyError` will propagate past that guard. Depending on the framework, this can crash a worker/request thread or, in stricter deployments, take down the whole process — the direct analog to "network not confirming transactions" in the original report, scaled to "consuming service stops handling requests." This is a correctness/robustness gap rather than a memory-safety vulnerability, so it is best characterized as Medium severity.

### Likelihood Explanation
High likelihood of reachability: any client that can submit JSON to be parsed into a message containing an `Any` field (a common pattern for gRPC-JSON transcoding or generic payload envelopes) can trigger this with a single crafted, tiny JSON document. No authentication or special state is required, and the code path is on by default (`Any` fields are ubiquitous in `.proto` schemas using `google/protobuf/any.proto`).

### Recommendation
Wrap the `value['value']` accesses in `_ConvertAnyMessage` (both the wrapper-message branch and the well-known-type branch) in the same defensive pattern already used for `@type`, converting a missing `value` key into a documented `ParseError` (e.g., "Expect \"value\" field in google.protobuf.Any-like message"), rather than letting the raw `KeyError` propagate. Apply the same audit to any other direct `dict[...]` accesses in this module that operate on attacker-controlled JSON without a corresponding `try/except KeyError` (e.g., check `_ConvertGenericMessage`, `_ConvertStructMessage`, `_ConvertListValueMessage` for similarly unguarded key/index accesses).

### Proof of Concept
Using the public API as an ordinary client would:
```python
from google.protobuf import any_pb2
from google.protobuf import json_format

message = any_pb2.Any()
text = '{"@type": "type.googleapis.com/google.protobuf.Int32Value"}'
json_format.Parse(text, message)  # missing "value" key
```
This is the exact scenario already exercised (for message text, not necessarily for exposing the raw type) by the existing test `testInvalidAny`, which expects a `ParseError` whose message contains `"KeyError: 'value'"` [5](#0-4) . This confirms the code path is reachable with attacker-controlled, bounded JSON and that the underlying failure is an unguarded `KeyError` on the `value` key — the same class of "missing required parameter, accessed without a check" defect described in the Shardus report, just realized in Protobuf's ProtoJSON `Any` parsing rather than an HTTP query parameter.

I was not able to fully verify, within the tool budget, whether some outer call site in this checkout wraps `_ConvertAnyMessage` in a blanket `except Exception` that converts the `KeyError` into a `ParseError` before it reaches the caller (the test's expectation that `ParseError` is raised suggests some conversion happens somewhere in the call chain, but I could not locate the exact wrapping code before running out of iterations). If such a wrapper exists, the practical impact is reduced to "no worse than existing `TypeError`/`ValueError` normalization" rather than a fully unguarded crash; this should be confirmed by tracing `Parse` → `ParseDict` → `_Parser.ConvertMessage` in full before treating this as unmitigated.

  def _ConvertAnyMessage(self, value, message, path):
    """Convert a JSON representation into Any message."""
    if isinstance(value, dict) and not value:
      return
    try:
      type_url = value['@type']
    except KeyError as e:
      raise ParseError(
          '@type is missing when parsing any message at {0}'.format(path)
      ) from e

    try:
      sub_message = _CreateMessageFromTypeUrl(type_url, self.descriptor_pool)
    except TypeError as e:
      raise ParseError('{0} at {1}'.format(e, path)) from e
    message_descriptor = sub_message.DESCRIPTOR
    full_name = message_descriptor.full_name
    if _IsWrapperMessage(message_descriptor):
      self._ConvertWrapperMessage(
          value['value'], sub_message, '{0}.value'.format(path)
      )
    elif full_name in _WKTJSONMETHODS:
      # For well-known types (including nested Any), use ConvertMessage
      # to ensure recursion depth is properly tracked
      self.ConvertMessage(value['value'], sub_message, '{0}.value'.format(path))
    else:
      del value['@type']
      try:
        self._ConvertFieldValuePair(value, sub_message, path)
      finally:
        value['@type'] = type_url
    # Sets Any message
    message.value = sub_message.SerializeToString()
    message.type_url = type_url
