### Title
Ephemeral string-view read may return stale/garbage memory before bounds error is detected - (File: `upb/wire/internal/eps_copy_input_stream.h`)

### Summary
`upb_EpsCopyInputStream_ReadStringEphemeral` (used by upb's C wire-format decoder, which backs Ruby, Python, PHP and other language bindings) can return a `upb_StringView` pointing at bytes from the internal 32-byte "patch" scratch buffer that were never validated against the actual field/message limit. The function's own header comment documents that "the returned data may contain garbage bytes from the patch buffer" and that this "may result in nonsense bytes ending up in the output," with the bounds violation only detected later via `upb_EpsCopyInputStream_IsDone()`. [1](#0-0)  This mirrors the invariant broken in CVE-2024-27280: a read primitive returns bytes before a length/limit check confirms they are actually part of the validated stream, potentially exposing stale memory content rather than an error.

### Finding Description
The implementation only checks that `size` fits within `e->end + kUpb_EpsCopyInputStream_SlopBytes` (the physical "slop" region that always contains readable memory, per the `EpsCopyInputStream`/`upb_EpsCopyInputStream` invariant), not that it fits within the actual delimited-field limit (`e->limit`/`limit_ptr`): [2](#0-1) 
The comment explicitly states this is "for efficiency" and defers the correctness check to a later call to `IsDone()`/`IsDoneFallback()`, which validates the stream position against `e->limit` only once the caller gets around to checking it: [3](#0-2) 
The failed invariant is: "a returned `upb_StringView` always represents validated, in-limit input bytes." The attacker-controlled value is the wire-format length prefix of a length-delimited field (string/bytes/submessage), which determines `size` passed into `ReadStringEphemeral`. The missing check is validating `size` against `e->limit` (the real delimited-field boundary) rather than only against the physical slop-buffer boundary. The `patch` buffer (`char patch[kUpb_EpsCopyInputStream_SlopBytes * 2]`) is a stack/struct-embedded scratch area reused across fields during parsing, so bytes left over from a prior field's contents (or uninitialized stack memory) can be returned as if they were the current field's payload.

### Impact Explanation
If any consumer of the returned `upb_StringView` — the callers include unknown-field comparison (`upb/message/internal/compare_unknown.c`), unknown-field access in Python (`python/unknown_fields.c`), and text-format encoding of unknown fields (`upb/text/internal/encode.c`) — uses the ephemeral view's bytes (e.g., to print, compare, or copy them) before the deferred `IsDone()` bounds check fires, stale internal buffer contents could leak into observable output (an information-disclosure primitive), directly analogous to `StringIO#gets` returning uninitialized memory in CVE-2024-27280. I was not able to fully confirm, within the tool budget, whether every call site enforces the "check IsDone before using `sv`" ordering, or whether all current callers only use the ephemeral view for byte-length-scoped rehashing/copying where the deferred error safely discards the output before it becomes visible.

### Likelihood Explanation
The precondition (constructing a length-delimited field whose declared size straddles the boundary between the true field/message limit and the 16-byte slop region, on a bounded/regular client-supplied binary protobuf payload) is easily attacker-reachable through a public `ParseFromString`/`decode` entry point, requiring no special schema or privileges — it is purely a matter of the wire-format length prefix. However, likelihood of actual observable disclosure depends on whether a specific caller reads `sv->data` before checking for a subsequent parse error, which I could not fully verify against `upb/wire/decode.c`'s exact call ordering in this session.

### Recommendation
Because I could not conclusively confirm an unguarded caller path in `upb/wire/decode.c` that consumes `ReadStringEphemeral`'s output before an error check, this should be treated as a lead requiring direct source verification (which a Devin agent with full-file access could confirm) rather than a proven vulnerability. If confirmed, the fix is to have `ReadStringEphemeral` (or its callers) validate `size` against `e->limit` (real delimited boundary) in addition to the slop-buffer boundary before returning the `StringView`, or to ensure all callers unconditionally call `IsDone()`/check the return value before touching `sv->data`/`sv->size`.

UPB_INLINE bool upb_EpsCopyInputStream_IsDone(struct upb_EpsCopyInputStream* e,
                                              const char** ptr) {
  int overrun;
  switch (UPB_PRIVATE(upb_EpsCopyInputStream_IsDoneStatus)(e, *ptr, &overrun)) {
    case kUpb_IsDoneStatus_Done:
      UPB_PRIVATE(upb_EpsCopyInputStream_BoundsHit)(e);
      return true;
    case kUpb_IsDoneStatus_NotDone:
      UPB_PRIVATE(upb_EpsCopyInputStream_BoundsChecked)(e);
      return false;
    case kUpb_IsDoneStatus_NeedFallback:
      *ptr =
          UPB_PRIVATE(upb_EpsCopyInputStream_IsDoneFallback)(e, *ptr, overrun);
      if (*ptr) {
        UPB_PRIVATE(upb_EpsCopyInputStream_BoundsChecked)(e);
      } else {
        UPB_PRIVATE(upb_EpsCopyInputStream_BoundsHit)(e);
      }
      return *ptr == NULL;
  }
  UPB_UNREACHABLE();
}

UPB_INLINE const char* upb_EpsCopyInputStream_ReadStringEphemeral(
    struct upb_EpsCopyInputStream* e, const char* ptr, size_t size,
    upb_StringView* sv) {
  UPB_ASSERT(size <= PTRDIFF_MAX);
  // Size must be within the current buffer (including slop bytes).
  const char* limit = e->end + kUpb_EpsCopyInputStream_SlopBytes;
  if ((ptrdiff_t)size > limit - ptr) {
    // For the moment, we consider this an error.  In a multi-buffer world,
    // it could be that the requested string extends into the next buffer, which
    // is not an error and should be recoverable.
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
  *sv = upb_StringView_FromDataAndSize(ptr, size);
  return ptr + size;
}
