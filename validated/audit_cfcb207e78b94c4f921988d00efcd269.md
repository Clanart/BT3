### Title
Tokenfactory denom admin can retroactively impose a `DenomAllowList` to permanently freeze already-circulating user token balances - (File: x/tokenfactory/keeper/msg_server.go)

### Summary
The Blueberry finding describes an owner who can flip a bit-flag (`bankStatus`) after users already have open positions, disabling `repay`/`withdraw` and permanently trapping user funds inside the protocol. The Sei-chain analog is the `x/tokenfactory` module's `MsgUpdateDenom`, which lets a denom's admin retroactively install a `bank.AllowList` on a denom that is *already* freely transferable and already held by third-party users. Once installed, any holder not on the list permanently loses the ability to move the tokens they legitimately acquired — with no on-chain recourse — mirroring the "owner flips a flag → user funds get stuck" bug class.

### Finding Description
`CreateDenom` lets any account permissionlessly mint a tokenfactory denom `factory/{creator}/{subdenom}` with no `AllowList` (fully transferable), and the creator becomes "admin" of that denom [1](#0-0) . That denom can then circulate freely to any number of third parties via normal `MsgSend`.

At any later point, the denom admin can call `MsgUpdateDenom` to attach a `bank.AllowList` to the denom. `UpdateDenom` performs no check on whether affected addresses already hold a balance, and simply persists the new allow-list via `bankKeeper.SetDenomAllowList` — the only requirement is that `msg.Sender` matches the current denom admin: [2](#0-1) .

This allow-list is then enforced in the bank module's send path for *every* holder of the denom, regardless of when they acquired it: `IsInDenomAllowList` blocks any address not in the list from sending the denom at all: [3](#0-2) . `MsgSend`/`MsgMultiSend` enforce this check unconditionally before any transfer executes: [4](#0-3) .

Because the check is purely "is `addr` currently in the allow-list", not "was the allow-list active when the coins were acquired," a denom admin can:
1. Freely distribute/trade a denom with no allow-list (or an initial permissive allow-list).
2. Once outside parties hold balances, call `UpdateDenom` with an `AllowList` excluding those holders.
3. Those holders' balances remain in their accounts but become permanently un-transferable (they cannot send, swap, or otherwise move the tokens), functionally freezing user funds — the same "flip a flag to strand already-committed user funds" pattern as the Blueberry report.

### Impact Explanation
This is a permanent freezing-of-funds primitive reachable by an ordinary, permissionless actor (a tokenfactory denom creator/admin — one of the explicitly in-scope actors), with no governance or validator collusion required. Any tokenfactory denom that has traded hands to unaffiliated holders can have those holders' balances frozen unilaterally by the admin at any time via a single `MsgUpdateDenom` transaction, matching the "permanent freezing" impact bar.

### Likelihood Explanation
Likelihood is high in trigger simplicity: `CreateDenom` requires no permission, and `UpdateDenom` requires only being the current admin of a denom the attacker itself created and distributed. No other party's cooperation, timelock, or governance vote is needed. The only precondition is that the token has been distributed to victims before the allow-list update, which is a normal expected pattern for any token that reaches liquidity/usage.

### Recommendation
- Grandfather-protect existing non-empty balances when an `AllowList` is newly installed or narrowed (e.g., only enforce the allow-list on *new* incoming transfers, or provide a mandatory exit/burn-for-refund path for excluded holders).
- Require that `AllowList` can only be set at `CreateDenom` time (immutable thereafter) or add a timelock/notice period before an `UpdateDenom` allow-list change takes effect, so holders can exit beforehand.
- Emit a chain-level warning/require explicit consent flow before a wallet-held balance can become non-transferable.

### Proof of Concept
1. Attacker calls `MsgCreateDenom` with no `AllowList` to create `factory/attacker/foo`.
2. Attacker mints `foo` and distributes/sells it to victims via ordinary `MsgSend`/DEX trades (`sei-cosmos/x/bank/keeper/msg_server.go` `Send` succeeds because no allow-list exists yet).
3. After victims hold balances, attacker calls `MsgUpdateDenom` with `AllowList = {attacker}` (excluding all victims) — `UpdateDenom` performs no holder/history checks, only the admin check, and installs the list via `SetDenomAllowList`.
4. Victims subsequently attempt `MsgSend` of their `foo` balance; `IsInDenomAllowList` returns `false` for them, and the send handler rejects it with `sdkerrors.ErrUnauthorized`, permanently freezing their already-held balance.

func (server msgServer) CreateDenom(goCtx context.Context, msg *types.MsgCreateDenom) (*types.MsgCreateDenomResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	denom, err := server.Keeper.CreateDenom(ctx, msg.Sender, msg.Subdenom)
	if err != nil {
		return nil, err
	}

	createDenomEvent := sdk.NewEvent(
		types.TypeMsgCreateDenom,
		sdk.NewAttribute(types.AttributeCreator, msg.Sender),
		sdk.NewAttribute(types.AttributeNewTokenDenom, denom),
	)

	if msg.AllowList != nil {
		err = server.validateAllowList(ctx, msg.AllowList)
		if err != nil {
			return nil, err
		}
		server.bankKeeper.SetDenomAllowList(ctx, denom, *msg.AllowList)
		createDenomEvent = createDenomEvent.AppendAttributes(
			sdk.NewAttribute(types.AttributeAllowList, strings.Join(msg.AllowList.Addresses, ",")),
		)
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		createDenomEvent,
	})

	return &types.MsgCreateDenomResponse{
		NewTokenDenom: denom,
	}, nil
}

func (server msgServer) UpdateDenom(goCtx context.Context, msg *types.MsgUpdateDenom) (*types.MsgUpdateDenomResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	denom, err := server.validateUpdateDenom(ctx, msg)
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, denom)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	updateDenomEvent := sdk.NewEvent(
		types.TypeMsgUpdateDenom,
		sdk.NewAttribute(types.AttributeCreator, msg.Sender),
		sdk.NewAttribute(types.AttributeUpdatedTokenDenom, denom),
	)

	if msg.AllowList != nil {
		server.bankKeeper.SetDenomAllowList(ctx, denom, *msg.AllowList)
		updateDenomEvent = updateDenomEvent.AppendAttributes(
			sdk.NewAttribute(types.AttributeAllowList, strings.Join(msg.AllowList.Addresses, ",")),
		)
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		updateDenomEvent,
	})

	return &types.MsgUpdateDenomResponse{}, nil
}

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}
