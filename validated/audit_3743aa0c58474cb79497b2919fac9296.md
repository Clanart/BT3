### Title
Encrypted DKG share messages bind only a self-claimed `sender` index, letting an unprivileged party forge a blame proof against an honest participant - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Sustainsys bug class is "a response crafted by one party is processed as if issued by another, because the claimed issuer is not cryptographically validated." In Serai's PedPoP DKG, `EncryptedMessage` carries a self-chosen ephemeral key `msg.key` and a Schnorr proof-of-possession (`pop`) whose challenge binds only the *claimed* sender index (`sender: Participant`), not any key attributable to that participant. The code itself acknowledges this: "The per-message keys have no root of trust" (`encryption.rs:300-301`). Consequently, anyone — not just a registered participant — can construct a `EncryptedMessage` that passes the PoP check while claiming an arbitrary `from` participant, and whose ciphertext decrypts to a garbage share. That yields a `PedPoPError::InvalidShare { participant: honest_l, blame: Some(...) }` accompanied by a *valid* `EncryptionKeyProof` (DLEq of the ECDH key), so the honest participant is cryptographically blamed for a fault they never committed.

### Finding Description
`KeyMachine::calculate_share` takes `shares: HashMap<Participant, EncryptedMessage<...>>` and calls `self.encryption.decrypt(rng, batch, BatchId::Decryption(l), l, share_bytes)` for each (`pedpop/src/lib.rs:476-478`). Inside `Encryption::decrypt` (`encryption.rs:469-501`):

- The PoP challenge is `pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg)` where `from` is just the HashMap key — a label supplied by whoever delivered the message, not an authenticated identity (`encryption.rs:479-485`, `302-324`).
- `msg.key` is an ephemeral point chosen by the message author. The PoP is a Schnorr signature under `msg.key`, so the attacker knows its discrete log and can sign a challenge containing *any* `sender` value, including an honest participant's index.
- The ciphertext key is `ecdh::<C>(&self.enc_key, msg.key)` (`encryption.rs:487`), which the attacker can compute (they know `msg.key`'s scalar and the victim's public `enc_pub_key` from the round-1 registration broadcast).
- On share-verification failure, `calculate_share` returns `PedPoPError::InvalidShare { participant: l, blame: Some(blame) }` where `blame` is the `EncryptionKeyProof { key, dleq }` produced by `decrypt` (`lib.rs:489-499`). This DLEq is over `[C::generator(), msg.key]` with the receiver's `enc_key` — it will verify perfectly because the ECDH was genuinely computed. Nothing in the blame proof ties the message to participant `l` other than the attacker-chosen `sender` field inside the PoP challenge.

The downstream blame-verification path (used by the processor at `processor/src/key_gen.rs:409-425`, which propagates `PedPoPError::InvalidShare { participant, blame }` into `ProcessorMessage::InvalidShare { faulty: participant, blame }`) can only re-verify the same PoP and DLEq — both of which validate — so the forged attribution stands.

### Impact Explanation
An unprivileged party (or any participant) can fabricate an `EncryptedMessage` blaming an arbitrary honest participant `l` for delivering an invalid DKG share, complete with a blame proof that verifies. In Serai's deployment, `InvalidShare` blame proofs are the evidence used to identify faulty validators for slashing/removal. This enables getting honest validators flagged as faulty — and if repeated across the set, can stall or corrupt key generation by forcing honest participants out. It is the direct analog of the Saml2 flaw: a message is accepted as "issued by" an identity that never authorized it, because the issuer field is merely asserted rather than cryptographically bound.

### Likelihood Explanation
Reachable entirely with public inputs: `EncryptedMessage::read` (`encryption.rs:171-177`) reads `key`, `pop`, `msg` from untrusted bytes; the attacker picks `msg.key` (knowing its discrete log), computes the ECDH key against the victim's publicly broadcast `enc_pub_key` (round-1 `EncryptionKeyMessage` is broadcast to all), encrypts any garbage scalar, signs the PoP with `sender = victim_index`, and delivers it under `l` in the shares map. No collusion, no leaked keys, no malicious-validator assumption on the *victim's* side is needed — the attacker needs only the public registration data.

### Recommendation
Bind the message to a participant-controlled identity. Options: (a) include the sender's *registered encryption public key* in the message/PoP and require `msg`'s PoP to be verifiably tied to a long-term per-participant key, or (b) require the round-1 `EncryptionKeyMessage`/`Commitments` PoK (which already binds `context` and `participant` via `challenge::<C>` at `lib.rs:86-94`, `323-329`) to also sign each round-2 share message, so round-2 authorship is anchored to the authenticated round-1 identity. Blame verification must then check that anchor, not just the ephemeral PoP.

### Proof of Concept
```rust
// Attacker observes victim participant V's broadcast EncryptionKeyMessage
// (contains V's enc_pub_key). To frame V at recipient R:

// 1. Attacker picks ephemeral key they fully control
let a = Zeroizing::new(C::random_nonzero_F(rng));
let msg_key = C::generator() * a.deref();

// 2. Attacker computes the ECDH key R will compute
let shared = ecdh::<C>(&a, R_enc_pub_key); // R's registered enc key is public

// 3. Garbage "share" ciphertext under the correct keystream
let mut ciphertext = Zeroizing::new(SecretShare::<C::F>([0x41; 32])); // garbage
cipher::<C>(context, &shared).apply_keystream(ciphertext.0.as_mut());

// 4. PoP with `sender` = V — attacker signs since they know `a`
let nonce = Zeroizing::new(C::random_nonzero_F(rng));
let pub_nonce = C::generator() * nonce.deref();
let pop = SchnorrSignature::sign(
    &a, nonce,
    pop_challenge::<C>(context, pub_nonce, msg_key, /* sender = */ V, ciphertext.0.as_ref()),
);

let forged = EncryptedMessage { key: msg_key, pop, msg: ciphertext };

// 5. R calls calculate_share with `shares[V] = forged`:
//    - PoP verifies (challenge includes sender=V, signed under msg_key) 
//    - decrypt() produces a valid EncryptionKeyProof (real ECDH)
//    - share_verification_statements fails
//    => Err(PedPoPError::InvalidShare { participant: V, blame: Some(valid_proof) })
//    V is reported `faulty` with a verifying blame proof despite never sending it.
```

Key references: `pop_challenge` binds only the asserted `sender` (`crypto/dkg/pedpop/src/encryption.rs:302-324`); `decrypt` uses map-supplied `from` and attacker-chosen `msg.key` (`encryption.rs:469-501`); blame is emitted for the map key `l` (`crypto/dkg/pedpop/src/lib.rs:476-499`).
