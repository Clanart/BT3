### Title
Missing timestamp/deadline validation allows indefinite replay of signed App Proxy (and webhook) requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
The external report describes a missing `deadline` parameter on a swap call, which allows a previously-valid signed transaction to be held and replayed later under more favorable conditions. The structural analog in `shopify_app` is the App Proxy (and webhook) HMAC verification logic, which validates only that a signature matches the payload — it never checks a `timestamp` parameter for freshness, so a captured, validly-signed request remains acceptable forever.

### Finding Description
`ShopifyApp::AppProxyVerification#query_string_valid?` extracts the `signature` param and recomputes an HMAC over the remaining query params, then does a constant-time comparison — it never inspects the `timestamp` parameter that Shopify includes in proxy requests, nor rejects requests whose timestamp is stale: [1](#0-0) 

The same pattern exists for webhooks: `ShopifyApp::PayloadVerification#hmac_valid?` only verifies the HMAC digest of the raw body against configured secrets, with no timestamp/nonce/replay check: [2](#0-1) [3](#0-2) 

Because neither verification path enforces a deadline/freshness window (analogous to the missing `deadline` param in the referenced Uniswap AMM report), any previously observed valid signed request (e.g., a proxy URL leaked via browser history, referrer headers, shared logs, or a compromised intermediary) can be replayed by an unrelated party at any point in the future and will still be "accepted" as authentic by these concerns.

### Impact Explanation
A replayed app-proxy request is processed by the app as if freshly issued by Shopify/the storefront, since there is no time-bound check — this is a case of an "accepted forged/stale signed request" being processed as valid, mirroring the impact described in the source report where a stale-but-signed operation is executed later under different (attacker-favorable) conditions. The severity depends on what the app does with app-proxy input (e.g., state changes, purchases, discount application), but the underlying gem-level primitive unconditionally accepts old signed requests.

### Likelihood Explanation
Exploitation requires the attacker to have obtained a previously valid signed query string (via logs, browser history, network capture, or a shared/forwarded URL) — it does not require any secret leakage or privileged access, matching the "unrelated-merchant/anonymous HTTP request" threat model. This is a plausible but not trivial precondition, since it depends on request interception/observation rather than pure guessing.

### Recommendation
Add a freshness check by validating the `timestamp` query parameter in `query_string_valid?` (reject requests older than a small tolerance window, e.g. a few minutes), and consider adding a similar timestamp/nonce validation to webhook verification where Shopify provides one, to close the replay window analogous to adding a `deadline` parameter in the AMM swap flow.

### Proof of Concept
1. Capture a valid, Shopify-signed app-proxy request URL (e.g., from access logs, a shared link, or browser history) containing `signature=<hmac>&timestamp=<T>&...`.
2. At any later time `T' >> T`, replay the exact same query string to the app's proxy endpoint.
3. `query_string_valid?` in `lib/shopify_app/controller_concerns/app_proxy_verification.rb` recomputes the HMAC over the same params and successfully matches the `signature`, since `timestamp` is never checked against current time — the request is accepted as if freshly sent by Shopify.

```ruby
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      )
```

```ruby
    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
```
