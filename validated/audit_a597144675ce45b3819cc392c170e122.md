### Title
Aggregator gRPC methods (including `InternalGetEmergencyStopTx`) are unauthenticated when `client_verification=false` - ([File: core/src/servers.rs::create_grpc_server])

### Summary
`create_grpc_server` wires up `Interceptors::Noop` for the aggregator's gRPC service whenever `config.client_verification` is `false`, meaning no certificate check (and no `is_internal` enforcement) is ever applied to any RPC, including `Internal`-prefixed methods that are supposed to be restricted to the entity's own client certificate. Because `only_aggregator_and_self` (the only code path that checks `is_internal` and rejects non-self callers) is never invoked in this mode, any unauthenticated caller can invoke `InternalGetEmergencyStopTx` and retrieve the emergency-stop transaction before its intended reveal.

### Finding Description
The binding claimed by the question is: `caller_identity_used_by(InternalGetEmergencyStopTx) == our_cert (self)`, enforced only inside `only_aggregator_and_self`'s `is_internal` branch [1](#0-0) . This binding is only checked when the active interceptor is `Interceptors::OnlyAggregatorAndSelf`.

In `create_grpc_server`, the interceptor selection is gated purely on `config.client_verification`: [2](#0-1) 
When `config.client_verification` is `false`, the branch selects `Noop`, whose `call` implementation simply returns `Ok(req)` unconditionally for every request [3](#0-2) . `is_internal` and the self-cert equality check are therefore never executed for any method name, including ones that `starts_with(b"Internal")`.

The aggregator's gRPC server is built via `create_aggregator_grpc_server`, which calls `create_grpc_server` with the same config and only logs a warning if `client_verification` is enabled — it does nothing special to protect `Internal*` methods when verification is disabled [4](#0-3) . `InternalGetEmergencyStopTx` (and `InternalSendTx`) are exposed as normal methods of `ClementineAggregatorServer`, implemented in `core/src/rpc/aggregator.rs`.

Exploit flow: an attacker with no TLS certificate connects to the aggregator's public gRPC port (deployment with `client_verification=false`), sends an `InternalGetEmergencyStopTx` request for a target deposit, and the Noop interceptor forwards it straight to the handler with no authorization check, returning the decrypted emergency-stop transaction bytes.

### Impact Explanation
This leaks a commitment/secret transaction (the emergency-stop tx for a deposit's move-to-vault UTXO) to an unauthorized party before its intended reveal, matching the "High - premature disclosure of a protocol commitment" category. It does not by itself move BTC or credit a false reimbursement, but early disclosure of the emergency-stop transaction can undermine the security assumption that this transaction remains secret until the operator/aggregator chooses to broadcast it, potentially letting an attacker front-run or interfere with its use. The blast radius covers every deposit managed by an aggregator deployed with `client_verification=false`, and the leak is repeatable per deposit/request.

### Likelihood Explanation
The only precondition is a deployment configuration choice: `client_verification=false` on the aggregator. Given this configuration, the attack is trivial and free (a single unauthenticated gRPC call, no BTC spend or fees required), fully repeatable across deposits. The severity is entirely dependent on this specific deployment/config precondition — with `client_verification=true` (the presumably intended production setting, and the one that triggers a `tracing::warn!` when disabled), `OnlyAggregatorAndSelf` is enforced and `is_internal` correctly blocks non-self callers.

### Recommendation
Do not let `Interceptors::Noop` bypass the internal-method restriction. Either (a) always enforce the `is_internal` self-check regardless of `client_verification`, independent of peer-certificate verification, or (b) refuse to start the aggregator gRPC server with `client_verification=false` unless internal methods are additionally protected (e.g., separate listener/socket for internal methods, or a mandatory local-only bind). At minimum, ensure `Internal*`-prefixed RPCs are never reachable without an authenticated self-identity, even in Noop mode.

```rust
// cargo test in core/src, new test module
#[tokio::test]
async fn internal_method_leaks_without_client_verification() {
    let mut config = create_test_config_with_thread_name().await; // existing test helper
    config.client_verification = false; // simulate insecure deployment

    let (addr, _shutdown) = create_aggregator_grpc_server(config.clone())
        .await
        .expect("server starts");

    // Connect with NO client certificate at all (plain/unauthenticated channel).
    let channel = tonic::transport::Channel::from_shared(format!("http://{}", addr))
        .unwrap()
        .connect()
        .await
        .unwrap();
    let mut client = ClementineAggregatorClient::new(channel);

    let resp = client
        .internal_get_emergency_stop_tx(InternalGetEmergencyStopTxRequest {
            deposit_id: some_known_deposit_id,
        })
        .await;

    // Binding under test: caller identity == our_cert (self) should be required.
    // Assert it is NOT enforced: the uncertified caller receives the tx bytes.
    assert!(resp.is_ok());
    let tx_bytes = resp.unwrap().into_inner().raw_tx;
    assert!(!tx_bytes.is_empty(), "emergency-stop tx leaked to uncertified caller");
}
```
This demonstrates that with `client_verification=false`, `Interceptors::Noop` is installed [5](#0-4)  and the `is_internal`/self-cert check in `only_aggregator_and_self` [1](#0-0)  is never reached, allowing an unauthenticated caller to obtain the emergency-stop transaction.

```rust
pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
```
