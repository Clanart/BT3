### Title
Unbounded CLVM atom-length-prefix parser in mempool canonical-encoding check can raise unhandled `IndexError` on malformed spend-bundle input - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM byte buffer of every submitted coin spend's `puzzle_reveal` and `solution` during mempool admission, walking the buffer byte-by-byte based on attacker-controlled length prefixes without ever checking that `offset` stays within `len(clvm_buffer)`. This is structurally the same bug class as CVE-2022-3409: a hand-rolled parser that advances an offset/cursor according to a length field embedded in attacker input, but never validates that the declared length or advancing offset stays inside the buffer before dereferencing it, so a truncated/malformed record ("unclosed" atom, analogous to bmcweb's "unclosed http header") causes an out-of-bounds byte access.

### Finding Description
`is_atom_canonical()` [1](#0-0)  reads a length-prefix from `clvm_buffer[offset]`, computes `prefix_len` (0-5 extra bytes), and then loops `prefix_len` times doing `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset < len(clvm_buffer)` at any point.

`is_clvm_canonical()` [2](#0-1)  drives this: it reads `b = clvm_buffer[offset]` at the top of an unbounded `while True:` loop, increments `offset` on `0xFF` pair markers and small atoms, and calls `is_atom_canonical(clvm_buffer, offset)` for larger atoms — again with no bounds check before indexing `clvm_buffer[offset]`.

This is directly reachable from an unprivileged spend-bundle submitter: `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in every incoming `SpendBundle` before it is admitted to the mempool [3](#0-2) . Both `puzzle_reveal` and `solution` are fully attacker-controlled bytes supplied in the spend bundle.

A buffer that ends immediately after a `0xFF` pair marker, or an atom byte announcing a multi-byte length prefix (e.g. `0xC0`) that is truncated before enough trailing bytes are present, causes `clvm_buffer[offset]` to be indexed past the end of `bytes`, raising a Python `IndexError`. Unlike this code, the equivalent "cheap parser" helpers in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`, etc.) explicitly check remaining-buffer length before every read and raise a controlled `ValueError` [4](#0-3) , showing the intended hardening pattern that `is_atom_canonical`/`is_clvm_canonical` lack.

### Impact Explanation
An uncaught `IndexError` raised deep inside `validate_spend_bundle()` — rather than the intended, gracefully-handled `Err.INVALID_COIN_SOLUTION` rejection path — deviates from the mempool's designed error-handling contract for malformed spends. If this exception is not caught by a generic handler higher up the call stack (I could not fully confirm this within the available budget — see below), it would propagate out of the coroutine processing a spend-bundle submission, which is the "spend-triggered transaction-processing halt" impact category for this exercise: any unprivileged peer/RPC caller submitting a single crafted spend bundle can trigger an unhandled exception in core mempool-admission code, repeatable in a loop the way the original CVE describes ("It can be conducted multiple times in a loop to cause DoS").

### Likelihood Explanation
High: no special conditions are required — an attacker only needs to submit a spend bundle (via RPC `push_tx`, wallet transaction submission, or peer transaction gossip) whose `puzzle_reveal` or `solution` bytes end with a truncated multi-byte atom length prefix or a trailing `0xFF`. This is a single, cheap, deterministic malformed-input construction, requiring no signature validity or coin ownership (the check occurs before/independent of consensus validity of the spend).

### Recommendation
Add explicit remaining-buffer-length bounds checks in `is_atom_canonical()` before advancing `offset` and indexing `clvm_buffer[offset]` (mirroring the pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`), and add the same check for the initial `b = clvm_buffer[offset]` read in `is_clvm_canonical()`'s loop. On detecting a truncated/out-of-bounds atom, return `False` (non-canonical) instead of raising, so callers continue to receive the intended `Err.INVALID_COIN_SOLUTION` rejection rather than an unhandled exception. Additionally, wrap the call site in `validate_spend_bundle()` (or the exception itself) so any parsing failure degrades to a normal rejection rather than propagating.

### Proof of Concept
1. Construct a `CoinSpend` whose `puzzle_reveal` (or `solution`) serialized CLVM bytes are, e.g., `b"\xff"` alone, or `b"\xc0"` (a 2-byte atom-length-prefix marker with the trailing length byte missing).
2. Build a `SpendBundle` containing this `CoinSpend` and submit it through the normal mempool admission path (e.g. wallet `push_tx` / peer `respond_transaction`), reaching `MempoolManager.validate_spend_bundle()`.
3. Observe that `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` at `chia/full_node/mempool_manager.py:723` calls into `is_atom_canonical`/`is_clvm_canonical`, which indexes past the end of the (1-byte) buffer and raises `IndexError` instead of returning the expected boolean, deviating from the intended `Err.INVALID_COIN_SOLUTION` handling.

Note: I was unable to fully confirm, within the remaining tool budget, whether a broad `except Exception` handler exists somewhere between `validate_spend_bundle()` and the network/RPC message-dispatch layer that would catch this `IndexError` and convert it into a logged/ignored error instead of visibly halting processing of that request. This should be verified directly against `chia/full_node/full_node_api.py`'s `respond_transaction`/`send_transaction` handlers and `MempoolManager.add_spend_bundle()`/`pre_validate_spendbundle()` call chain before treating this as a confirmed transaction-processing-halt vulnerability rather than a locally-caught, non-impactful exception.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
