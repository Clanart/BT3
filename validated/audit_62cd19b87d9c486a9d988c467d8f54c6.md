### Title
Unauthenticated on-chain mirror-coin injection forces DataLayer nodes to issue outbound HTTP requests to attacker-chosen URLs (SSRF) - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
Any unprivileged spend-bundle submitter can create a coin paid to the DataLayer "mirror" puzzle hash with memos naming an arbitrary `launcher_id` (store id) and arbitrary URL(s). `DataLayerWallet.coin_added()` accepts and persists these attacker-supplied URLs as legitimate mirrors for *any* store the local wallet happens to be tracking, without verifying that the coin's spender owns or controls that store. `DataLayer.update_subscriptions_from_wallet()` then feeds these URLs straight into the subscription list used by `fetch_and_validate()`/`download_file()`/`http_download()`, causing the victim's DataLayer service to make outbound HTTP(S) requests to attacker-controlled destinations — the same bug class as CVE-2022-39359 (untrusted, attacker-supplied URL causes the server to make a request without restricting the destination).

### Finding Description
`create_mirror_puzzle()` is `P2_PARENT.curry(Program.to(1))` [1](#0-0) , an anyone-can-create-coin style puzzle: the mirror puzzle hash is public and any wallet can send a coin to it with a `CREATE_COIN` condition carrying memos `[launcher_id, url1, url2, ...]`. `get_mirror_info()` simply parses those memos out of the parent spend with no ownership check on `launcher_id` [2](#0-1) .

When such a coin appears on chain, `DataLayerWallet.coin_added()` detects the mirror puzzle hash, extracts `launcher_id` and `urls` from the parent spend, and — if the local wallet already tracks that `launcher_id` (i.e., the victim is following/owns that DataLayer store) — stores the URLs as a legitimate `Mirror` record with no check that the coin creator is the store owner or an authorized publisher: [3](#0-2) 

These persisted mirrors are later read back by `DataLayer.update_subscriptions_from_wallet()`, which unconditionally turns every mirror URL into a subscription server URL for that store: [4](#0-3) 

`DataLayer.fetch_and_validate()` then randomly selects one of the subscription server URLs (which now includes the attacker-injected one) and issues outbound requests via `insert_from_delta_file()` → `download_file()` → `http_download()`: [5](#0-4) [6](#0-5) 

Nothing in this path validates that the mirror URL's host/scheme is restricted to public, non-link-local, non-private-network addresses; test fixtures even use `http://127.0.0.1/8000`-style URLs as normal, accepted mirror server addresses [7](#0-6) , confirming that arbitrary loopback/private URLs are accepted as legitimate DataLayer mirror destinations. Because any wallet can push the coin that creates such a mirror record for someone else's tracked store id, this is a remotely triggerable SSRF/blind-request primitive: an unprivileged attacker forces a victim's already-running full node/DataLayer service to make outbound HTTP(S) connections to attacker-chosen hosts (internal services, cloud metadata endpoints, etc.), exactly mirroring the Metabase GeoJSON bug class where a user-supplied, insufficiently-restricted URL is fetched server-side.

### Impact Explanation
This lets a spend-bundle submitter who does not own or control a DataLayer store still inject its own mirror URLs for that store, causing the victim's node process to perform SSRF-style outbound requests to arbitrary hosts/ports (including internal-only services, localhost RPC ports, or cloud metadata endpoints) whenever that node happens to sync/subscribe to the targeted store. This can be used for internal network reconnaissance/exfiltration and denial-of-service against a DataLayer node's egress, and it also corrupts the mirror/subscription state for a store the attacker does not own.

### Likelihood Explanation
Likelihood is High for any node that tracks (owns or subscribes to) the targeted DataLayer store: creating the mirror coin only requires a standard on-chain spend to a known, public puzzle hash with attacker-chosen memos — no signature from the store owner, no CAT/NFT ownership, and only a trivial mojo amount plus fee is required. No special privilege beyond normal spend-bundle submission is needed.

### Recommendation
In `DataLayerWallet.coin_added()`, require that mirror-creating spends be authorized by the store owner (e.g., verify a signature/ownership condition tied to the DL singleton, or restrict mirror puzzle solutions to only be spendable in conjunction with a valid singleton announcement from that launcher) before persisting the URLs. Additionally, validate mirror/subscription URLs at ingestion (`update_subscriptions_from_wallet` / `DataStore.subscribe`) and again before every outbound fetch in `http_download`, rejecting link-local, loopback, and private-network destinations unless explicitly enabled, and disable following redirects to such destinations, mirroring the fix pattern in the referenced advisory.

### Proof of Concept
1. Victim node subscribes to (tracks) DataLayer store `S` owned by Alice.
2. Attacker Bob (with no relationship to `S`) creates and submits a standard coin spend that pays to `create_mirror_puzzle().get_tree_hash()` with a `CREATE_COIN` condition whose memos are `[S, b"http://169.254.169.254/latest/meta-data/"]` (or any internal victim-reachable URL).
3. Once the coin confirms, victim's `DataLayerWallet.coin_added()` sees the mirror puzzle hash, extracts `launcher_id=S` and the malicious URL, and — because `S` is tracked locally — stores it as a `Mirror` for `S` (no ownership check) [3](#0-2) .
4. `DataLayer.update_subscriptions_from_wallet(S)` merges the malicious URL into `S`'s subscription server list [4](#0-3) .
5. On the next `periodically_manage_data()` cycle, `fetch_and_validate(S)` may pick the malicious server and call `http_download()`, causing the victim node to issue an outbound request to the attacker-chosen internal/private address [5](#0-4) [6](#0-5) .

Note: the exact internal behavior of `http_download()` (redirect handling specifics) was not fully inspected due to iteration limits; the root cause demonstrated here — unauthenticated third-party injection of arbitrary mirror URLs for a store the attacker does not own, which are then used as fetch destinations — is confirmed directly from the cited code and is sufficient on its own to reproduce the SSRF-class impact regardless of redirect-following behavior.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope

            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)

                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
