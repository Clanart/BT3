## Finding

### Title
GitHub Desktop disables Git's built-in clone-time protection against malicious submodules (`GIT_CLONE_PROTECTION_ACTIVE=false`) - (File: `app/src/lib/git/clone.ts`)

### Summary
Every clone Desktop performs — whether started from the "Clone Repository" dialog with a user-entered generic URL, a GitHub repository picker, or an `x-github-client://openRepo/...` deep link — is executed with the environment variable `GIT_CLONE_PROTECTION_ACTIVE` explicitly forced to `'false'`, and always with `--recursive` submodule cloning enabled. [1](#0-0) 

`GIT_CLONE_PROTECTION_ACTIVE` is Git's own opt-out switch for the defense-in-depth checks Git added to `git clone --recursive` to stop a maliciously crafted submodule tree (using symlinks, case-insensitive/`\`-normalized path collisions, or nested `.git` directories) from writing files, or planting/overwriting hook scripts, outside of the intended working directory during checkout of the submodule. Desktop does not merely fail to enable this protection — it actively turns it off on every clone by unconditionally injecting the env override into the `git` execution options.

### Finding Description
The broken invariant is the same class as the report's seed bug: a value that gates a security-relevant outcome (here, Git's own clone-time symlink/collision protection flag) is placed under attacker influence at exactly the moment attacker-controlled content (the cloned repository and its submodules) is being materialized on disk. In the vault analog, the `highWaterMark` guard was neutralized by an attacker-timed call; here, the guard is neutralized unconditionally by Desktop itself for every clone, which is worse — there's no need to "front-run" anything since the protection is always off.

The only mitigation present, `isClonePathSensitive`, checks the *destination path* the user chose (e.g., not `~/.ssh`, `~/.gnupg`, home directory root): [2](#0-1) 

That check says nothing about the *content* of the remote repository being cloned or its submodules, so it does not stop a repository (or a submodule referenced inside `.gitmodules`) crafted to exploit symlink/collision handling once `GIT_CLONE_PROTECTION_ACTIVE` is disabled.

### Impact Explanation
An attacker who controls a repository URL that a victim clones through Desktop (a public/malicious repo, a link shared to a victim, or an "Open in Desktop"-style deep link that triggers `openOrCloneRepository`/clone) can craft `.gitmodules` entries and submodule blobs designed to abuse symlink or path-collision handling during the recursive submodule checkout. With Git's own protection disabled, this can result in files being written outside the intended clone directory, or a hook script (e.g. `post-checkout`) being planted such that it executes on a subsequent Desktop-driven checkout — i.e., code execution or file write outside the repository, both explicitly in-scope impacts.

### Likelihood Explanation
This triggers on the ordinary, unprivileged "Clone a repository" flow, which is one of Desktop's primary entry points and explicitly supports arbitrary/generic URLs via `CloneGenericRepository`: [3](#0-2) 

No local access, admin rights, prior malware, or unnatural steps are required — the victim just clones (or opens via deep link) a URL an attacker controls. The override is unconditional in `clone()`, so every such clone is exposed regardless of the source's trustworthiness.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `clone()` (or set it to Git's default "enabled" value) so Git's built-in submodule symlink/collision protections remain active during `git clone --recursive`. If this override exists to work around a compatibility issue with a specific Git/dugite version, that workaround needs to be scoped far more narrowly (e.g., only for known-safe, already-verified local sources) rather than applied to every remote clone of arbitrary, attacker-suppliable URLs.

### Proof of Concept
1. Attacker publishes a repository containing a `.gitmodules` file that adds a submodule whose path is crafted to collide (via symlink or case/8.3-name collision) with the repository's own `.git` directory or `.git/hooks` directory.
2. Attacker shares the repository's clone URL (or an "Open in Desktop"/`x-github-client://openRepo` link pointing at it) with the victim.
3. Victim clicks "Clone" in Desktop (`CloneRepository.clone` → `dispatcher.clone` → `clone()` in `app/src/lib/git/clone.ts`).
4. `clone()` runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` injected into the environment, disabling Git's own defense for the recursive submodule checkout.
5. During submodule initialization/checkout, the crafted symlink/collision structure is followed instead of being rejected, allowing writes outside the intended working directory or planting of a hook that executes on a later checkout performed by Desktop.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

  private clone = async () => {
    this.setState({ loading: true })

    const cloneInfo = await this.resolveCloneInfo()
    const { path } = this.getSelectedTabState()

    if (path == null) {
      const error = new Error(`Directory could not be created at this path.`)
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    if (!cloneInfo) {
      const error = new Error(
        `We couldn't find that repository. Check that you are logged in, the network is accessible, and the URL or repository alias are spelled correctly.`
      )
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    const { url, defaultBranch } = cloneInfo

    this.props.dispatcher.closeFoldout(FoldoutType.Repository)
    try {
      this.cloneImpl(url.trim(), path, defaultBranch)
    } catch (e) {
      log.error(`CloneRepository: clone failed to complete to ${path}`, e)
      this.setState({ loading: false })
      this.setSelectedTabState({ error: e })
    }
  }
