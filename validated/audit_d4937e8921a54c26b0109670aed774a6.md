### Title
Coinbase outputs are reported as spendable before maturity - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching outputs as `ReceivedOutput` values. The resulting amount is reported through `ReceivedOutput::value` and can be passed directly into `SignableTransaction::new`, which checks only the declared input amount, output script, and outpoint. A coinbase output is therefore treated as immediately spendable even though Bitcoin consensus prevents spending it until it has matured.

### Finding Description
`Scanner::scan_block` iterates over `block.txdata`, including `block.txdata[0]`, and calls `scan_transaction` for each transaction. When the coinbase contains an output paying a registered script, `scan_transaction` creates a `ReceivedOutput` containing the coinbase outpoint and nominal output value. Although the documentation notes that coinbase outputs are maturity-bound, the object itself is documented as a “spendable output” and carries no maturity marker. `SignableTransaction::new` accepts the object without checking whether its previous output is coinbase-created or whether the required confirmations exist. It then constructs a transaction spending the supplied outpoint and signs it using the normal Taproot path.

### Impact Explanation
An external miner can create a block whose coinbase pays a scanned address. The scanner reports the full output amount as a received, spendable balance even though that balance cannot be spent for the maturity period. If downstream accounting or transaction construction consumes the returned `ReceivedOutput`, Serai can overstate immediately available funds and produce/sign a transaction that Bitcoin consensus rejects. This is the same accounting mismatch class as the reported issue: the internally tracked amount reflects the nominal output amount rather than the amount currently usable by the system.

### Likelihood Explanation
Any block produced by an external miner can contain a coinbase output to a scanner-registered Taproot script. The vulnerable path is directly reachable by feeding that block to `Scanner::scan_block`, then passing the returned output to `SignableTransaction::new`. Exploitation requires the attacker to produce a valid block or otherwise cause a maturity-bound output to be scanned; it does not require access to Serai’s private keys or validator cooperation.

### Recommendation
Do not return coinbase outputs from `Scanner::scan_block` until they are mature. If the API must expose them, extend `ReceivedOutput` or its scan result with a maturity/confirmation status and reject immature outputs in `SignableTransaction::new`. At minimum, make `scan_block` skip `block.txdata[0]` and provide a separate explicit API for scanning maturity-bound coinbase outputs.

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
