I found a valid analog to the CVE-2015-8730 bug class (a dissector that does not validate the number of items in a structure before indexing into it, causing an invalid read/crash).

### Title
Unvalidated curried-argument count in `SingletonOuterPuzzle.match()`/`get_inner_puzzle()`/`solve()` causes unhandled crash on malformed puzzle reveals - (File: `chia/wallet/nft_wallet/singleton_outer_puzzle.py`)

### Summary
`match_singleton_puzzle()` only checks that the uncurried puzzle's mod hash equals `SINGLETON_MOD`/`SINGLETON_TOP_LAYER_MOD`; it never validates that the curried argument list actually contains exactly two items before the caller destructures it.

### Finding Description
`match_singleton_puzzle()` in `chia/wallet/puzzles/singleton_top_layer_v1_1.py` returns `(True, iter(puzzle.curried_args))` whenever `puzzle.mod == SINGLETON_MOD`, with no check on `len(puzzle.curried_args)`: [1](#0-0) 

`SingletonOuterPuzzle.match()`, `.get_inner_puzzle()`, and `.solve()` then unconditionally unpack that iterator into exactly two variables with **no try/except** guarding the unpack: [2](#0-1) [3](#0-2) [4](#0-3) 

Because CLVM `curry()` lets anyone construct a puzzle whose top-level mod hash matches `SINGLETON_MOD` while currying an arbitrary number of arguments (0, 1, 3, 4, ...), an attacker fully controls `puzzle.curried_args`'s length. A puzzle reveal crafted with more or fewer than two curried arguments passes the `puzzle.mod == SINGLETON_MOD` check but fails the `singleton_struct, inner_puzzle = curried_args` unpack with an unhandled `ValueError` ("too many values to unpack" / "not enough values to unpack"). This mirrors the NBAP dissector flaw: the "type" check (mod hash) passes, but the item-count check is missing before the code indexes/destructures the parsed items, leading to a crash.

This code is reachable through `match_puzzle()` in `chia/wallet/outer_puzzles.py`, which is invoked from wallet-facing, attacker-influenced entry points such as:
- `Offer.from_spend_bundle()` when the wallet parses a counterparty's offer file (`chia/wallet/trading/offer.py`), which calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` on every coin spend in the untrusted offer: [5](#0-4) 
- Wallet coin-received processing paths that call `match_puzzle`/driver `.match()` on puzzle reveals belonging to newly-seen coins (CAT/NFT/singleton identification flows via `chia/wallet/outer_puzzles.py`).

Unlike `Program.uncurry()` itself, which wraps its own tuple-unpack in `try/except ValueError`/`TypeError`/`EvalError` and safely falls back [6](#0-5) , and unlike `UncurriedNFT.uncurry()` which wraps its unpacks in `try/except` [7](#0-6) , `SingletonOuterPuzzle`'s unpacks have no such protection.

### Impact Explanation
A malicious offer counterparty (or a coin whose puzzle reveal a wallet is asked to identify) can supply a crafted CLVM program that mod-hash-matches `SINGLETON_MOD`/`SINGLETON_TOP_LAYER_MOD` but curries a wrong number of arguments. When the victim's wallet calls `match_puzzle()` while parsing the offer (e.g. `Offer.from_bech32` → `from_spend_bundle` → `match_puzzle`) or while identifying an incoming coin, the unguarded destructuring raises an unhandled `ValueError`, halting that transaction-processing operation (offer view/accept, coin identification) in the wallet. This is a spend/offer-triggered processing halt (denial of service) at the wallet layer, matching this scan's accepted impact category.

### Likelihood Explanation
Likelihood is moderate-to-high for a wallet user: it requires no special privileges, only that the victim wallet be asked to inspect a maliciously crafted offer file or receive/sync a coin whose puzzle reveal is a bogus "singleton-shaped" CLVM program. Constructing such a puzzle is straightforward with `Program.curry()` using any wrong argument count while forcing the mod hash to equal `SINGLETON_MOD`.

### Recommendation
In `match_singleton_puzzle()` (and equivalently in `chia/wallet/puzzles/singleton_top_layer.py`'s version), validate `len(list(curried_args)) == 2` before returning `matched=True`, or wrap the destructuring assignments in `SingletonOuterPuzzle.match()`, `.get_inner_puzzle()`, and `.solve()` in `try/except (ValueError, TypeError)` returning `None`/raising a handled `ValueError` consistent with how `Program.uncurry()` and `UncurriedNFT.uncurry()` already defend against malformed curried argument counts.

### Proof of Concept
```python
from chia.types.blockchain_format.program import Program
from chia.wallet.puzzles.singleton_top_layer_v1_1 import SINGLETON_MOD
from chia.wallet.outer_puzzles import match_puzzle
from chia.wallet.puzzles.puzzle_drivers import UnknownPuzzle

# Curry SINGLETON_MOD with only ONE argument instead of the expected two
# (singleton_struct, inner_puzzle). This still uncurries to mod == SINGLETON_MOD
# but curried_args has length 1, not 2.
malformed_singleton = SINGLETON_MOD.curry(Program.to(b"only_one_arg"))

# This raises an unhandled ValueError ("not enough values to unpack")
# inside SingletonOuterPuzzle.match() -> singleton_struct, inner_puzzle = curried_args
match_puzzle(UnknownPuzzle(known_program=malformed_singleton))
```
Embedding `malformed_singleton` as a `coin_spend.puzzle_reveal` inside an offer bech32 blob and having a victim wallet call `Offer.from_bech32(...)` (which invokes `Offer.from_spend_bundle` → `match_puzzle`) reproduces the crash during offer inspection.
