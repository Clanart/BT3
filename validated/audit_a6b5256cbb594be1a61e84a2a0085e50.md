### Title
Confused-deputy GitHub credential handoff to attacker-chosen submodule URL during on-demand submodule fetch - (File: `app/src/lib/trampoline/find-account.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`, `app/src/lib/git/fetch.ts`)

### Summary
The credential helper trampoline hands out a signed-in account's GitHub token to *any* credential request whose `host`/`url` origin matches an already-authenticated endpoint, without verifying that the request originates from the repository/remote the user actually opened or fetched. Because `fetch`/`pull` run with `--recurse-submodules=on-demand`, a malicious public repository can add or modify a `.gitmodules` entry pointing at `https://github.com/<victim-owned-private-repo>.git`; when the victim performs a routine fetch/pull of the malicious repo, Git will silently attempt to fetch that submodule, invoke the Desktop credential helper for `github.com`, and Desktop will hand over the victim's real GitHub token — fetching private repository content the attacker specified, using the victim's own credentials, without any additional prompt tying the credential use to the operation the user actually initiated.

### Finding Description
`withTrampolineEnv` configures Git's `credential.helper` globally for the whole process tree of a git invocation via `GIT_CONFIG_PARAMETERS`, which is explicitly designed so that child processes (submodule fetches, LFS filters) inherit it: [3](#0-2) 

`getFetchArgs`/`pull.ts` enable `--recurse-submodules=on-demand`, so any submodule reference added/changed in the fetched history is fetched automatically as part of the same operation, using the same credential-helper configuration: [2](#0-1) 

When Git needs credentials for the submodule URL, it calls the trampoline credential helper, which dispatches to `getGitHubCredential`: [4](#0-3) 

`findGitHubTrampolineAccount` only compares the *origin* of the requested URL against the origin of an already-signed-in account's endpoint — it has no notion of "which repository is this credential request for" or "is this the remote the user intended to operate on": [1](#0-0) 

The broken invariant: credential handoff is scoped only by hostname, not by the specific repository/operation the user authorized. An attacker who controls the *content* of a repository (via `.gitmodules`, similar to how the original report's `incoming` contract controls execution during a token transfer) can inject a URL that redirects the trampoline's trusted credential flow toward a target of the attacker's choosing (any repo under `github.com`), analogous to a callback re-entering a privileged code path before the original operation's intended scope is checked.

### Impact Explanation
This allows an unprivileged attacker who only controls a public repository the victim clones/fetches to make GitHub Desktop silently authenticate to and pull the contents of *any other private repository the victim has access to* (as long as the attacker can guess/know the owner/repo name), using the victim's own OAuth token, without the victim being shown any prompt that ties this credential use to the untrusted repository. The private data ends up written to the victim's local disk under `.git/modules/...`, which the attacker cannot directly read, but this still constitutes unauthorized use of the victim's credentials to access resources outside the scope of the operation the victim believed they were performing, and could be combined with other primitives (e.g., a subsequent push/PR from the victim, or a symlinked/`file://` submodule path) to exfiltrate the fetched content.

### Likelihood Explanation
Likelihood is moderate: submodules and `--recurse-submodules=on-demand` are a documented, default-enabled Git feature already invoked by Desktop's `fetch`/`pull` code paths, requiring no unusual user action beyond a normal fetch/pull of a repository the attacker controls. No local access, admin rights, or social engineering beyond "clone/fetch a public repo" is required.

### Recommendation
Scope credential handoff in `findGitHubTrampolineAccount`/`getCredential` to the repository/remote context of the trampoline token (already tracked via `getTrampolineEnvironmentPath(token)`), rejecting or prompting the user when a credential request's host does not match the primary remote(s) configured for that repository, rather than matching purely by hostname across all logged-in accounts.

### Proof of Concept
1. Attacker publishes a public GitHub repo `attacker/lure` containing a `.gitmodules` file with a submodule entry: `url = https://github.com/victim/private-repo.git`.
2. Victim, who is signed into Desktop with a GitHub account that has access to `victim/private-repo`, clones or fetches `attacker/lure`.
3. Desktop runs `git fetch --recurse-submodules=on-demand` (`app/src/lib/git/fetch.ts`), which triggers a submodule fetch of `https://github.com/victim/private-repo.git`.
4. Git invokes the credential helper (`credential.helper=desktop`), which reaches `getCredential` → `getGitHubCredential` → `findGitHubTrampolineAccount`, matching purely on `github.com` origin.
5. Desktop supplies the victim's real GitHub token, and the private repo contents are fetched to disk without any additional confirmation dialog referencing `attacker/lure`.

Note: I was not able to fully trace whether an existing confirmation UI (e.g., a submodule-fetch consent dialog) intercepts this flow before the credential helper is reached — this would need to be verified in a live Desktop session, since the index does not show any such gating in `app/src/lib/git/fetch.ts` or `pull.ts`.

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}

async function getGitHubCredential(cred: Credential, store: AccountsStore) {
  const endpoint = `${getCredentialUrl(cred)}`
  const account = await findGitHubTrampolineAccount(store, endpoint)

  }
