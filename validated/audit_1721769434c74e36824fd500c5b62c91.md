### Title
Schnorr half-aggregate verification is existentially forgeable: weights bind only the challenges, not the nonces - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` checks a single linear equation over `n` attacker-chosen nonce points `R_i` and one scalar `s`. The per-signature weights `z_i` are derived by `weight()` exclusively from the challenges `c_i`; neither the `R_i` nor the `s` value is bound into the weight transcript. This leaves `n + 1` free variables satisfying one group equation, so any unprivileged party can construct a fully verifying `SchnorrAggregate` for arbitrary keys and challenges without knowing any private key.

### Finding Description
Verification builds the multiexp at `crypto/schnorr/src/aggregate.rs:138-145`:

```
for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
  let z = weight(&mut digest);
  pairs.push((z, self.Rs[i]));
  pairs.push((z * challenge, *key));
}
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity()
```

i.e., it accepts iff `Σ_i z_i·R_i + Σ_i z_i·c_i·A_i − s·G = 0`.

The weights come from `weight()` at `aggregate.rs:22-65`, which hashes `DigestTranscript::new(dst)` + `domain_separate(b"signatures")` + each `challenge.to_repr()` (appended at `aggregate.rs:134-136`). The digest never absorbs `self.Rs[i]`, the keys, or `s`. Consequently `z_i` are fixed public scalars known to the attacker before choosing the `Rs`.

The equation is therefore a single constraint with `n` free group elements and a free scalar. A forger fixes arbitrary `R_1..R_{n-1}` and any `s`, then solves for `R_0 = z_0^{-1}·(s·G − Σ_i z_i·c_i·A_i − Σ_{i>0} z_i·R_i)`. The result passes `verify` for keys whose discrete logs the forger does not know.

This mirrors CVE-2025-33224's "execution with unnecessary privileges" class mapped onto Serai's shape: the verifier formula grants the authority of `n` valid signatures to a party holding none of the secrets — a forged signature reachable purely from public inputs (`keys_and_challenges` are public; `SchnorrAggregate::read` at `aggregate.rs:77-88` accepts attacker bytes via `C::read_G`/`C::read_F`).

### Impact Explanation
Anywhere `SchnorrAggregate::verify` is used to attest that `t` signatures authorize an action, a single attacker produces a verifying aggregate for keys/messages never signed — equivalent to forging the entire threshold's authorization. This is a complete break of the half-aggregation primitive (forgery with zero secret knowledge, cost = one inversion and one multiexp).

### Likelihood Explanation
The exploit requires no privileged position, no honest signers, and no protocol interaction: only public keys and the public challenge derivation. It is deterministic and works for every `n ≥ 1`. The only prerequisite is that the integrator exposes `SchnorrAggregate::verify` over attacker-supplied `(Rs, s)`.

### Recommendation
Bind each nonce and the signature scalar into the weight derivation so the equation cannot be solved pointwise. Concretely, transcript `Rs[i]` (and the aggregate `s`, or derive the weights over `challenge || R_i`) before computing each `z_i`, matching the half-aggregation construction of eprint 2021/350 where `z_i = H(..., R_i, pk_i, m_i)`. With `z_0` dependent on `R_0`, the solve-for-`R_0` step becomes circular and infeasible.

### Proof of Concept
```rust
// For any victim keys A_i and challenges c_i (all public):
// 1. digest = DigestTranscript::new(dst); domain_separate("signatures");
//    append each c_i; compute z_i = weight(&mut digest) for i in 0..n.
// 2. Choose arbitrary s and R_1..R_{n-1} (e.g., s = 0, R_i = i*G).
// 3. Compute R_0 = z_0^{-1} * (s*G - Σ_i z_i*c_i*A_i - Σ_{i>0} z_i*R_i).
// 4. SchnorrAggregate { Rs: [R_0, R_1..], s }.verify(dst, keys_and_challenges) == true
//
// Check: Σ z_i R_i + Σ z_i c_i A_i - sG
//      = z_0 R_0 + Σ_{i>0} z_i R_i + Σ z_i c_i A_i - sG  = 0  ✓ identity

One caveat I could not fully rule out: `C::read_G` canonicality rules (e.g., whether `R_0` must be non-identity) do not block the attack, since the forged `R_0` is generically a valid non-identity point. Also note the aggregator-side `SchnorrAggregator::complete` computes the same `weight()` sequence (`aggregate.rs:169-184`), so honest aggregation remains compatible if weights are changed on both sides consistently.

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res
}

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
