### Title
Missing expiration/replay-window check on App Proxy and Webhook HMAC-signed requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` and `ShopifyApp::WebhookVerification#verify_request` validate only the cryptographic correctness of an inbound signed request (HMAC-SHA256 over the app proxy query string or webhook raw body) using `ActiveSupport::SecurityUtils.secure_compare`. Neither path enforces a deadline/freshness window on the `timestamp` (app proxy) or delivery time (webhook), so a validly-signed request captured once by an on-path attacker, logging proxy, browser extension, or leaked in access logs remains fully replayable forever. [1](#0-0) [2](#0-1) 

### Finding Description
This is the direct analog of the reported "missing deadline check" bug class, mapped to shopify_app's own class of accepted-forged/replayed signed requests. In the audited DeFi report, the root cause is that a signed/authorized operation carries no expiry, so a captured transaction/message can be executed far later than intended, at attacker/observer advantage. Here:

- `AppProxyVerification#calculated_signature` recomputes the HMAC over all query params (including `timestamp`) and compares it to the supplied `signature`, but `timestamp` is never compared to `Time.now` — it's just another signed field, not an enforced deadline. [3](#0-2) 
- The project's own test suite demonstrates this: a request carrying `timestamp: "1466106083"` (an epoch from 2016) is asserted to pass verification (`assert query_string_valid?`), confirming no expiry enforcement exists. [4](#0-3) 
- `WebhookVerification#verify_request` only checks `hmac_valid?(request.raw_post)`; there is no `X-Shopify-Webhook-Id` replay cache, timestamp header check, or any time-bounding at all in this gem's implementation. [5](#0-4) [6](#0-5) 

### Impact Explanation
Because these signature checks are pure "was this HMAC produced with our shared secret" checks with no deadline, any captured valid app-proxy request or webhook delivery (e.g., sniffed from an unencrypted network hop, a compromised CDN/log, browser history, or a merchant support ticket pasting a URL) can be replayed at an arbitrary future time to re-trigger the same app-proxy action or re-deliver the same webhook event to the app's backend, potentially causing duplicate state changes (e.g., re-processing an `orders/create` or `app/uninstalled` webhook, or re-invoking an app-proxy endpoint that performs a mutating action) long after the original request should have expired.

### Likelihood Explanation
Exploitation requires the attacker to already possess a previously valid signed request (via network capture, log leakage, or referrer/history disclosure) — it is not exploitable purely by an anonymous attacker with no prior access, so likelihood is bounded by the difficulty of obtaining a captured request, but the missing check itself is unconditionally present in the gem's default implementation and confirmed by its own test fixtures using an old timestamp.

### Recommendation
Add a deadline check analogous to the Uniswap `ensure(deadline)` pattern in both concerns: in `AppProxyVerification#verify_proxy_request`, reject requests whose `timestamp` param is older than a configurable window (e.g., a few minutes) before comparing signatures; for `WebhookVerification`, leverage Shopify's webhook headers (or the `shopify_api` gem's built-in verification, if it exposes delivery time) to reject stale deliveries, in addition to the existing HMAC check.

### Proof of Concept
Using the gem's own test values: a GET to an app-proxy route with `shop=some-random-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd` passes `query_string_valid?` today exactly as it would have in 2016 — no code path ever compares `timestamp` to the current time.     def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
