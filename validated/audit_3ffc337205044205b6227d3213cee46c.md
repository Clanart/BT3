### Title
Hardcoded `DUST` Constant Applied to All Output Scripts Causes Fund Loss and Payment Rejection - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs` uses a single hardcoded dust threshold, `pub const DUST: u64 = 546` (send.rs:32), for every output regardless of its `script_pubkey` type. Analogous to the reported `DEFAULT_PRICING_TIMEOUT` being applied uniformly to all price feeds regardless of their heartbeat, this constant is the Bitcoin Core dust limit for legacy P2PKH outputs, yet it is applied to SegWit/Taproot outputs (real dust: 330 sats) and to arbitrary caller-supplied payment scripts whose dust threshold differs. The result: spendable funds are silently burned as miner fees, and valid payments are rejected.

### Finding Description
In `SignableTransaction::new` (send.rs:150-256):

1. Every payment is checked against the same constant:
```rust
for (_, amount) in payments {
  if *amount < DUST {          // send.rs:166
    Err(TransactionError::DustPayment)?;
  }
}
```
`payments` is `&[(ScriptBuf, u64)]` — the script type is available but never consulted. A P2TR payment of 330–545 sats is standard, relayable, and spendable, yet `new` returns `DustPayment`.

2. The change output decision uses the same constant (send.rs:228-234):
```rust
if let Some(value) = input_sat.checked_sub(payment_sat + fee_with_change) {
  if value >= DUST {
    tx_outs.push(TxOut { value: ..., script_pubkey: change });
    ...
  }
}
```
If the leftover is below 546 it is not given a change output and is instead absorbed into the fee (`sum(inputs) - sum(outputs)`, send.rs:139-140). For the P2TR change scripts Serai itself uses (`p2tr_script_buf`, wallet/mod.rs:80-86), any leftover in [330, 546) is a perfectly spendable output that is instead burned to miners. The code even acknowledges the conflation: the comment at send.rs:28-31 admits it "doesn't bother with delineation" across output types, citing policy.cpp — the same one-size-fits-all rationale the original report flags.

### Impact Explanation
- **Funds burned as fees:** whenever the leftover is in [330, 546) sats and change is a P2TR/other SegWit script, a spendable output is converted into excess miner fee. This is a direct, deterministic loss of funds reachable whenever a transaction is built with modest change — no attacker needed beyond normal operation.
- **Valid payments rejected:** P2TR payments of 330–545 sats are unconditionally refused, breaking withdrawals to small Taproot outputs.
- The symmetric risk also exists in the other direction: the constant is applied to payment scripts whose true dust limit could exceed 546, which would produce a dust output that won't relay (for nonstandard script sizes this is only prevented by accident).

### Likelihood Explanation
Every transaction built through `SignableTransaction::new` with change routes through this single threshold; the [330, 546) change-burn window is ~40% of the sub-546 range and Serai's own change outputs are always P2TR, so the misapplied constant triggers on ordinary transactions. An external party paying to a small Taproot withdrawal address hits the `DustPayment` rejection deterministically.

### Recommendation
Compute the dust threshold per output script, matching Bitcoin Core's `GetDustThreshold` (`dustRelayFee * (nSize + 148 + ...)` per script type), instead of a single `DUST` constant. Concretely:
- Replace the `*amount < DUST` loop (send.rs:165-169) with a per-`ScriptBuf` check, e.g. `payment.0.dust_value().to_sat()` from rust-bitcoin, which already implements per-script dust computation.
- Apply the same per-script check to the change output at send.rs:229.

### Proof of Concept
```rust
// A P2TR change script, as Serai itself produces via p2tr_script_buf(key)
let change = p2tr_script_buf(key).unwrap();

// Input worth payment + fee + 400 sats leftover
// 400 >= 330 (P2TR dust) so this output is standard, relayable, spendable
let tx = SignableTransaction::new(inputs, &payments, Some(change), None, fee_rate);

// Inside new(): value = 400 < DUST (546), so no change output is pushed.
// tx.fee() = input_sat - payment_sat = needed_fee + 400
// The 400 sats are paid to miners instead of returned to the wallet.
assert_eq!(tx.unwrap().fee(), expected_fee + 400); // silent burn

// And a valid P2TR payment of 400 sats is rejected outright:
assert_eq!(
  SignableTransaction::new(inputs, &[(p2tr_script_buf(key).unwrap(), 400)], None, None, fee_rate),
  Err(TransactionError::DustPayment) // despite being spendable on-chain
);
```
