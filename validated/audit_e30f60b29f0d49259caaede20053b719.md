### Title
Gasless swap admission uses a pre-execution `GetAmountIn` price read that is not re-validated at bundle execution time, allowing bundling of swaps priced against a stale AMM state - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `LiquidityWindowV2.sol` finding describes a time-of-check/time-of-use (TOCTOU) bug: a refund amount is computed from a pre-refresh oracle price, and only afterward is the oracle (and its circuit breaker) refreshed, so the value transferred is based on stale data that is never reconciled against the freshened state. The closest reachable analog in this Kaia codebase is the gasless-swap admission/bundling pipeline in `kaiax/gasless`, where the "required token input" for a swap is priced once via a view call and that same tx is later bundled and executed after other transactions may have altered the router's on-chain state, without any re-check tying the executed swap back to the originally validated price.

### Finding Description
`checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` computes the amount of token the sender must supply for the declared `minAmountOut` by calling the swap router's `GetAmountIn` as a view (`nil` `CallOpts`), which reads the **current** state at the moment of tx-pool admission: [1](#0-0) 

This check (`ShouldCheckSwapAmount`) is only performed once, when the transaction is validated for pool admission via `GetCheckBalance`: [2](#0-1) 

The transaction is later selected for block building by `ExtractTxBundles`, which wraps the previously-validated swap tx (and its paired approve tx) into a bundle together with a `LendTxGenerator`-produced gas-lending transaction, without re-running `checkBalanceForSwap` against the state that will actually exist when the bundle executes: [3](#0-2) 

Because `GetAmountIn`/router reserves are read once at admission time and the swap can remain queued and be reordered relative to other pool-affecting transactions (any other swap against the same router/pair) before it is finally included, the "correctness" gate (`amountIn >= requiredAmountIn`) is evaluated against AMM reserves that are not guaranteed to match the reserves at execution time. This mirrors the `LiquidityWindowV2` bug class exactly: a value-relevant quantity (price/amountIn) is read once via a view call, and the actual state-changing operation happens later without re-deriving that value from a refreshed read, or without the two being reconciled in the same atomic path.

### Impact Explanation
Because `BalanceCheckLevelSwapAmount` is only a pool-admission heuristic and not re-verified inside the bundle at inclusion time, a sender/searcher can craft a `GaslessSwapTx` that passes admission against a favorable (stale) reserve snapshot, then have the block builder include it later (potentially after other AMM-moving transactions the same block-builder is also including) so it executes against a different exchange rate than what gated its admission. This does not directly forge on-chain balances the way `LiquidityWindowV2`'s refund flaw does (Solidity `GaslessSwapRouter` still ultimately enforces `minAmountOut` and the real swap math on-chain), so the primary loss vector is: the gasless mempool-admission economics/gas-lending assumption (the proposer lends the gas fee expecting it to be repaid via `amountRepay` derived from a swap that was screened as solvent) can be invalidated by the time of execution, exposing the block proposer to unrepaid-lend risk if the swap now reverts or under-fills relative to what was screened, since the fee-lending (`LendTxGenerator`) transaction is unconditionally prepended before the bundle executes.

### Likelihood Explanation
This requires an attacker (the gasless-swap sender or a colluding party) to influence AMM reserves between the swap's tx-pool admission and its eventual bundling/execution — reachable purely via public transaction submission (no privileged access needed), since `checkBalanceForSwap` is invoked on ordinary `AddLocal`/`AddRemote` tx-pool admission and `ExtractTxBundles` is invoked later during block assembly by any block-producing node running the `gasless` kaiax module.

### Recommendation
Re-validate `checkBalanceForSwap` (or equivalently, re-derive `GetAmountIn`) at bundle-extraction/inclusion time against the state that will actually be committed to (or ensure the AMM-level `minAmountOut` check is the sole solvency guarantee and that gas-lending is contingent/reconciled after successful swap execution rather than granted unconditionally up front), so that the value used to gate mempool admission is not decoupled from the value used at execution.

### Proof of Concept

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
