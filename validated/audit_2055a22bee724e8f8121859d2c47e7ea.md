### Title
FROST nonce reuse: one-time `CachedPreprocesses` seed is never invalidated after `sign` errors, allowing secret share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The kernel bug class is "a fallible operation leaves a previously allocated one-time resource in place, so a retry reuses it." The Serai analog lives in `SigningProtocol::preprocess_internal` / `share_internal` in `coordinator/src/tributary/signing_protocol.rs`: a FROST preprocess seed is stored once per `context` in `CachedPreprocesses`, deterministic `AlgorithmSignMachine::from_cache` rebuilds identical nonces on every call, and the entry is never deleted or rotated — including when `machine.sign` aborts with `FrostError::InvalidPreprocess`/`InvalidShare` caused by an unprivileged participant's bytes.

### Finding Description
`preprocess_internal` writes `CachedPreprocesses::set(txn, context, seed)` once and then, on every subsequent invocation for the same `context`, reads the entry back and reconstructs the machine via `AlgorithmSignMachine::from_cache`, which calls `seeded_preprocess(cache)` (`crypto/frost/src/sign.rs`). The seeded derivation is deterministic: same `context` → same nonce seed → same `R` commitments and same internal `[base, actual]` nonce scalars consumed in `SignMachine::sign` (`crypto/frost/src/sign.rs:386-396`).

`share_internal` (lines 150-180) then:
1. Rebuilds the machine from the *unchanged* cached seed,
2. Parses attacker-supplied `serialized_preprocesses` via `read_preprocess`, returning `Err(participant)` on malformed bytes,
3. Calls `machine.sign(preprocesses, msg)`, which returns `Err(InvalidPreprocess(p))` if any participant's preprocess fails `process_addendum` or fails to parse — fully attacker-controllable through the `read_preprocess`/`Commitments::read` path.

On every one of these error returns, the `CachedPreprocesses` entry is left untouched. The `SignMachine` documentation explicitly warns: "After this, the preprocess must be deleted so it's never reused. Any reuse will presumably cause the signer to leak their secret share" (`crypto/frost/src/sign.rs:216-219`). No `delete`/`remove`/`clear` of `CachedPreprocesses` exists anywhere in the codebase — the only four references are in this file. This is the missing `macvlan_flush_sources()` cleanup: the one-time resource is committed before the fallible steps and is not torn down on error, nor after success.

### Impact Explanation
If the protocol ever performs a second share round under the same `context` — a retry after an `InvalidPreprocess`/`InvalidShare` abort with a re-formed participant set, or a re-sign of a differing `msg`/set under the same context — the validator signs again with the *identical* nonces. Two published Schnorr shares `s₁ = d + e₁·λ·x` and `s₂ = d + e₂·λ·x` with the same `d` and distinct challenges yield `x = (s₁ − s₂)/(λ(e₁ − e₂))`: full recovery of the validator's MuSig secret key share (`self.key`), i.e., compromise of the tributary signing key. Even absent a second published share, a forced `InvalidPreprocess` error leaves the same commitments bound to a retried session, enabling ROS-style grinding where the attacker chooses their preprocess after observing the victim's fixed `R`.

### Likelihood Explanation
An unprivileged participant controls the `serialized_preprocesses` bytes fed to `read_preprocess` and `sign`, so triggering the error/abort path is trivial. Exploitation requires a retry under the same `context`; whether the coordinator actually re-issues a share round for an identical `context` after an error is not fully verified from the indexed code (callers of `share_internal` are limited to this file and the retry semantics of the surrounding protocol were not fully resolvable). If retries reuse `context`, severity is High; if each retry gets a fresh `context`, the stale entry is merely dead state and severity drops — but the code provides no invariant enforcing the latter, directly contradicting the library's documented MUST.

### Recommendation
Delete the `CachedPreprocesses` entry for `context` once the share round completes or aborts (i.e., after `machine.sign` returns — success or failure — the seed must be burned), mirroring the required `macvlan_flush_sources()` cleanup. If the entry must persist for mid-protocol reboots, scope it to a single round-trip (preprocess + exactly one share round) and add an explicit guard that refuses a second `share_internal` for a `context` whose share round already executed or failed.

### Proof of Concept
```rust
// Conceptual, against SigningProtocol with fixed context C:
// Round 1: honest preprocess issued; attacker P submits malformed preprocess bytes.
share_internal(participants, {P: b"garbage"}, msg1)
// -> Err(P) from read_preprocess at line 165.
//    CachedPreprocesses[context] still holds the same 32-byte seed.

// Round 2 (retry / re-formed set / new message under same context):
share_internal(participants', valid_preprocesses, msg2)
// -> from_cache(seed) regenerates the SAME nonces (same public R).
// -> publish share s2 = d + e2 * lambda * x

// Round 3 or parallel coerced share under same context produces s3 = d + e3 * lambda' * x.
// x = (s2 - s3) / (lambda*e2 - lambda'*e3)  => validator secret key share recovered.
```
Root cause is the write-once-read-forever `CachedPreprocesses` at `signing_protocol.rs:123-147` combined with the error returns at `:166` and `:170-178` performing no invalidation, violating the one-use contract in `crypto/frost/src/sign.rs:216-219`.
