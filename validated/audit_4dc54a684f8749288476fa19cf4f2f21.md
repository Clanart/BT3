### Title
Repeated primitive fields marked `debug_redact = true` bypass text-format redaction via the short-repeated-primitives code path - (File: `src/google/protobuf/text_format.cc`)

### Summary
Protobuf's TextFormat/DebugString redaction feature (`debug_redact` field option) is the direct analog of Ansible's `ANSIBLE_NO_LOG` invariant: a field/value that is marked sensitive must never appear in human-readable/log-facing output, regardless of the code path used to print it. The Ansible CVE shows that some emission paths (loop items) forgot to apply the `no_log` check. In protobuf, `TextFormat::Printer::PrintField` has an early-exit branch for repeated primitive fields (`use_short_repeated_primitives_`) that dispatches to `PrintShortRepeatedField` *before* the field ever reaches the code that calls `TryRedactFieldValue`.

### Finding Description
The redaction invariant is implemented as: "if `enablingSafeDebugFormat`/`redact_debug_string_` is on and the field's `RedactionState.redact` is true, `TryRedactFieldValue` must intercept the value before printing it and substitute `[REDACTED]`." This check is correctly wired into the two normal emission paths:
- Message-typed fields: `PrintField` calls `TryRedactFieldValue` before recursing into the sub-message. [1](#0-0) 
- Scalar/enum fields: `PrintFieldValue` calls `TryRedactFieldValue` before dispatching to the type-specific printer. [2](#0-1) 

However, `PrintField` has a distinct, earlier branch that diverts *repeated, non-string, non-message* fields (i.e., repeated int32/int64/uint32/uint64/float/double/bool/enum) into `PrintShortRepeatedField` and returns immediately, never reaching the `PrintFieldValue`/`TryRedactFieldValue` call: [3](#0-2) 

Because the exclusion list is only `CPPTYPE_STRING` and `CPPTYPE_MESSAGE`, a repeated primitive field (e.g. `repeated int32`, `repeated MyEnum`) annotated with `[debug_redact = true]` falls into this short-form path whenever `use_short_repeated_primitives_` is enabled (e.g. via `TextFormat::Printer::SetUseShortRepeatedPrimitives(true)`), which is the same printer flag used by `ShortFormat`. The existing test suite for redaction (`text_format_unittest.cc::ShortFormat`) only exercises `optional_redacted_string`, `repeated_redacted_string`, `optional_redacted_message`, `repeated_redacted_message`, and `map_redacted_string` — all STRING/MESSAGE-typed fields — and never a repeated primitive/enum field with `debug_redact = true`, so this gap is untested. [4](#0-3) 

### Impact Explanation
This mirrors CWE-116/117 in the Ansible advisory: a value explicitly flagged as sensitive is emitted in clear text in a specific, less-common output mode (short/single-line format with short-repeated-primitives enabled), defeating the purpose of `debug_redact`. Applications that rely on `debug_redact`/`enablingSafeDebugFormat`/`ShortFormat`-style output to keep secrets (e.g., numeric tokens, sensitive enum status codes) out of logs would leak them whenever the field is a repeated primitive/enum instead of a string or message. Impact is confidentiality-only (information disclosure), matching the CVSS profile of the source advisory (`C:H/I:N/A:N`).

### Likelihood Explanation
Likelihood is Medium: exploitation requires (a) a schema author using `debug_redact = true` on a *repeated primitive or enum* field (uncommon relative to string/message fields, which are the typical carriers of secrets), and (b) the consuming application enabling `use_short_repeated_primitives_`/`ShortFormat`. I was not able to inspect the full body of `PrintShortRepeatedField` itself within the available search budget to conclusively confirm it never calls `TryRedactFieldValue` internally — the evidence here is the control-flow structure of `PrintField`, which returns immediately after dispatching to `PrintShortRepeatedField` without ever calling the redaction-aware `PrintFieldValue`. This should be verified directly against the implementation of `PrintShortRepeatedField` before treating this as confirmed.

### Recommendation
Add a `TryRedactFieldValue` (or equivalent per-element check) call inside `PrintShortRepeatedField`, or exclude fields whose `RedactionState.redact` is true from the short-primitives fast path in `PrintField`, and extend `text_format_unittest.cc`/`unredacted_debug_format_for_test_test.cc` with a `debug_redact`-annotated repeated primitive/enum field exercised under `ShortFormat`/`use_short_repeated_primitives_`.

### Proof of Concept
Conceptual reproduction (not executed — requires building the C++ test target):
1. Add to `unittest_redaction.proto` (or `unittest.proto`) a field `repeated int32 repeated_redacted_int32 = 30 [debug_redact = true];`.
2. Set values on it, then call `TextFormat::Printer` with `SetUseShortRepeatedPrimitives(true)` and `SetRedactDebugString(true)` (the same configuration `ShortFormat` uses), i.e. mirror the existing `ShortFormat` test at [5](#0-4) 
3. Expected (per the redaction contract): output shows `[REDACTED]` for `repeated_redacted_int32`. Predicted actual (per code path analysis): the raw integer values are printed because `PrintField` routes to `PrintShortRepeatedField` without invoking `TryRedactFieldValue`. [6](#0-5)

void TextFormat::Printer::PrintField(const Message& message,
                                     const Reflection* reflection,
                                     const FieldDescriptor* field,
                                     BaseTextGenerator* generator) const {
  if (use_short_repeated_primitives_ && field->is_repeated() &&
      field->cpp_type() != FieldDescriptor::CPPTYPE_STRING &&
      field->cpp_type() != FieldDescriptor::CPPTYPE_MESSAGE) {
    PrintShortRepeatedField(message, reflection, field, generator);
    return;
  }
