### Title
Out-of-bounds read / unhandled exception in canonical CLVM check crashes mempool spend-bundle validation - (File: chia/full_node/mempool_manager.py)

### Summary
`MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in an attacker-submitted `SpendBundle`, on data taken directly and unvalidated from the wire (an unprivileged spend-bundle submitter fully controls `puzzle_reveal` and `solution` bytes). `is_clvm_canonical`/`is_atom_canonical` walk this buffer using a length-prefix decoded from the buffer contents without ever bounds-checking the resulting `offset` against `len(clvm_buffer)`, mirroring the CVE-2019-14267 root cause (data associated with a length/marker field is trusted and used to advance a read cursor without validating it stays inside the buffer). [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine an atom's length-prefix class, then loops `prefix_len` times (up to 5 iterations) incrementing `offset` and indexing `clvm_buffer[offset]` again to build `atom_len`, with **no check** that `offset` stays within `len(clvm_buffer)`: [4](#0-3) 

`is_clvm_canonical` drives this loop over the whole buffer, and likewise indexes `clvm_buffer[offset]` at the top of its `while True:` loop without checking that `offset < len(clvm_buffer)` before dereferencing it: [5](#0-4) 

A crafted `puzzle_reveal` or `solution` can end with a byte such as `0xFC` (the widest length-prefix class, requiring 5 additional prefix bytes) placed at, or near, the very end of the buffer. Because none of the prefix-reading steps validate that enough bytes remain, `clvm_buffer[offset]` will raise an `IndexError` when `offset` runs past the buffer's end. This is directly analogous to the PDFResurrect bug class: a length/marker byte controls how many further bytes are consumed, and that consumption is never checked against the actual remaining buffer size before being dereferenced.

This function sits directly in the mempool's spend-bundle admission path — every submitted spend bundle's `coin_spend.puzzle_reveal` and `coin_spend.solution` are passed to it unconditionally, before any other content validation of that specific check: [6](#0-5) 

`validate_spend_bundle()` is invoked from `add_spend_bundle()` with no `try/except` wrapping around the `is_clvm_canonical` calls or the `validate_spend_bundle()` invocation itself: [7](#0-6) 

An uncaught `IndexError` raised mid-way through `validate_spend_bundle()` therefore propagates up through `add_spend_bundle()` uncaught, rather than being translated into a normal `MempoolInclusionStatus.FAILED` / `Err` response the way a deliberately-rejected canonical-form failure is (`Err.INVALID_COIN_SOLUTION`, at line 726). This is a crash/DoS-class defect distinct from the existing, intentional canonical-form rejection path that the test suite exercises with non-canonical length-prefix payloads (`ffffc001018080`, `c00101`): [8](#0-7) 

Those existing tests only cover cases where the length prefix is *technically valid but non-shortest-form* and stays within bounds — they do not cover a length prefix that runs the read cursor off the end of the buffer entirely, which is the scenario that triggers the unhandled exception.

### Impact Explanation
An unhandled exception thrown from deep inside mempool spend-bundle admission, on a code path that is reached for every single transaction accepted into the mempool, can halt normal transaction processing for the calling context (e.g. the RPC/network handler task processing that spend bundle) if the exception is not caught by an outer generic handler. Depending on how far up the call stack a bare `except Exception` sits, this can manifest as a mempool-item-processing halt triggered purely by a single crafted, unsigned/unauthorized spend bundle submitted by any peer or RPC caller — matching the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
The trigger requires only a `puzzle_reveal` or `solution` blob (fully attacker-controlled, not consensus-checked before this point) ending in a truncated multi-byte atom length prefix. Constructing such a payload is trivial — it does not require a valid signature, valid puzzle execution, or any privileged position; the attacker just needs their `SpendBundle` to reach `MempoolManager.add_spend_bundle()`, which happens for any submitted transaction.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` dereference (verify `offset < len(clvm_buffer)` for the initial byte read and for each of the `prefix_len` additional byte reads), and similarly bounds-check `offset` in `is_clvm_canonical()`'s main loop before indexing `clvm_buffer[offset]`. On detecting an out-of-range access, return "not canonical" (`False`) rather than raising, consistent with how the rest of the canonical-check contract signals malformed input via `Err.INVALID_COIN_SOLUTION`.

### Proof of Concept
Conceptual PoC (pending validation against actual mempool wiring/exception handling, which could not be fully traced in this environment):
1. Build a `puzzle_reveal`/`solution` blob whose last byte is `0xFC` (or another multi-byte length-prefix marker) with fewer than the required trailing bytes present, e.g. `b"\xfc"` alone, or `b"\xfc\x00\x00"` (3 bytes total but the class requires 5 more prefix bytes after the marker).
2. Submit a `SpendBundle` containing a `CoinSpend` with this blob as `puzzle_reveal` (or `solution`) via the normal transaction-submission path so it reaches `MempoolManager.add_spend_bundle()` → `validate_spend_bundle()`.
3. Observe that `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` at line 723 calls into `is_atom_canonical`, which indexes `clvm_buffer[offset]` past the end of the buffer and raises `IndexError`, propagating out of `validate_spend_bundle()`/`add_spend_bundle()` uncaught.

Note: I was unable to trace all the way up to the network/RPC entry points that call `add_spend_bundle()` to confirm whether a top-level generic exception handler exists that would downgrade this crash to a logged error rather than a task/service-level failure; this should be verified before treating the impact as confirmed process-halting DoS rather than a localized task failure.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
