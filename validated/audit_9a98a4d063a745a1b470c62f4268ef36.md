### Title
`Debug` impls on `ThresholdCore`/`ThresholdView` leak all participants' secret key shares via `Interpolation::Constant` - (File: crypto/dkg/src/lib.rs)

### Summary
CVE-2018-3817 is a bug class where a routine logging path (deprecated-setting warnings in Logstash) inadvertently emitted sensitive credentials. The Serai analog lives in `crypto/dkg/src/lib.rs`: the hand-written redacting `Debug` impls for `ThresholdCore` and `ThresholdView` correctly suppress `secret_share`, but both print the `interpolation` field verbatim. For `Interpolation::Constant`, that field is `Vec<F>` holding the secret key share coefficients of every participant, so any `{:?}`/`{:#?}` formatting, error message, or log line containing a `ThresholdKeys` (which `derive`s `Debug` over its `core`) or `ThresholdView` discloses the full set of threshold secret shares — i.e., the entire group private key — in cleartext.

### Finding Description
`Interpolation::Constant(Vec<F>)` is documented as "a list of constant coefficients, one for each of the secret key shares" — every element is secret scalar material [1](#0-0) .

The `enum` itself `derive`s `Debug`, so formatting it prints the raw `F` values [2](#0-1) . Meanwhile, the manual `Debug` impls carefully exclude `secret_share` via `finish_non_exhaustive()`, but include `interpolation`:

- `ThresholdCore` prints `interpolation` while omitting `secret_share` [3](#0-2) .
- `ThresholdView` does the same [4](#0-3) .
- `ThresholdKeys` uses `#[derive(Debug)]` over `core: Arc<Zeroizing<ThresholdCore<C>>>`, so formatting `ThresholdKeys` reaches `ThresholdCore::fmt` and leaks the coefficients [5](#0-4) .
- `Scalar` in `crypto/dalek-ff-group` also `derive`s `Debug`, so each leaked `F` renders its full secret value [6](#0-5) .

This contrasts with sibling types that were correctly scrubbed — e.g., `SecretShare`'s `Debug` emits only the struct name [7](#0-6)  — showing `interpolation` was simply missed during redaction.

### Impact Explanation
Anyone who obtains a `Debug` rendering of `ThresholdKeys`/`ThresholdView` (application logging of key-manager state, panic/expect messages, error reporting, debugger output committed to logs, `format!("{keys:?}")` in caller crates — `processor`/`coordinator` code routinely `Debug`-formats machines holding these types) recovers every participant's secret share under `Interpolation::Constant`. With all coefficients disclosed, the threshold private key is recovered outright: an attacker can forge arbitrary FROST signatures and spend all funds controlled by the group key. This is complete, silent secret-key compromise triggered by the most innocuous operation possible — logging — which is exactly the CVE-2018-3817 failure mode.

### Likelihood Explanation
Likelihood is moderate rather than high because the leak requires (a) the key set to have been generated/promoted with `Interpolation::Constant` (non-Lagrange DKG paths), and (b) some code path to `Debug`-format the keys. No secret material reaches the log through normal signatures; the trigger is operational (verbose logging, crash dumps, `unwrap`/`expect` chains printing state). Given that `processor`'s `KeyGen`, `Signer`, and coordinator code hold `ThresholdKeys` and pervasively `Debug`-log protocol objects, the precondition is realistic. Severity of outcome (full key recovery) is Critical; overall Medium–High consistent with the source CVE's Medium rating accounting for the required logging precondition.

### Recommendation
Replace the `interpolation` field in both `Debug` impls with a non-secret marker (e.g., which variant is in use), or implement `Debug` manually for `Interpolation` that prints `Constant(..)` without the coefficients. Audit all derived `Debug` impls on types transitively reachable from `ThresholdKeys`/`ThresholdView`/`SignMachine` for other unredacted `C::F` fields, and remove `Debug` from the `Scalar`/`Scalar(pub DScalar)` derive in `crypto/dalek-ff-group/src/lib.rs` in favor of a redacted impl.

### Proof of Concept
```rust
use dkg::{ThresholdParams, Interpolation, ThresholdKeys};
// Anywhere ThresholdKeys is formatted:
let keys: ThresholdKeys<C> = /* key set built with Interpolation::Constant */ ;
// Both of these print every participant's secret share coefficient:
let leaked = format!("{keys:?}");            // via ThresholdKeys -> ThresholdCore -> interpolation
let view = keys.view(&[Participant(1), /* ... */]).unwrap();
let leaked2 = format!("{view:?}");           // via ThresholdView -> interpolation
// `leaked` contains "Constant([<F repr>, <F repr>, ...])" — all secret shares in cleartext,
// sufficient to reconstruct the threshold private key and forge signatures.
```
Root cause is confirmed by the `derive(Debug)` on `Interpolation` [8](#0-7)  combined with `.field("interpolation", &self.interpolation)` in both impls [9](#0-8) [10](#0-9) .

Uncertainty note: I verified the leak exists at the type level in the in-scope `crypto/dkg` crate, but I did not fully enumerate every upstream call site that `Debug`-formats these values (most formatting sites sit in out-of-scope `processor`/`coordinator`); the finding stands on the exposed `Debug` contract of the in-scope types themselves.
