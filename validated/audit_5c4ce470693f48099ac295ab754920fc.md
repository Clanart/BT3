## Analog Found

### Title
Unvalidated forwarding of attacker-reachable PR `clone_url` into `git remote add` without the argument-injection guard used elsewhere - ([File: app/src/lib/git/remote.ts])

### Summary
The external report's broken invariant is: attacker-controlled data is forwarded **verbatim** into a privileged operation (a git-custody call) without validating its content, even though a "trust boundary" existed (the factory's own custody check) that the injected payload bypassed. The Desktop analog is the pull-request checkout path: a `clone_url` value sourced from a GitHub API pull-request object — reachable through the "Open Pull Request in Desktop" protocol-handler flow, which a user can be lured into via a link/deep link — is forwarded unvalidated into `git remote add <name> <url>` in `addRemote()`, while the sibling `clone()` code path explicitly hardens the equivalent call with a `--` end-of-options separator.

### Finding Description
The protocol handler `x-github-client://openRepo/<url>?pr=<n>` is parsed by `parseAppURL` in `app/src/lib/parse-app-url.ts`, which validates `pr` (numeric) and `branch` (ref-safe chars) but performs **no validation on `url`** beyond it being present [1](#0-0) . `main.ts` forwards this raw URL into the renderer via `handleAppURL`/`sendURLAction` [2](#0-1) .

In the dispatcher, `openPullRequestFromUrl(url, pr)` uses this attacker-supplied `url` to call `this.appStore.fetchPullRequest(url, pr)`, i.e. it queries whatever host the link points to for pull-request data, and then extracts `pullRequest.head.repo.clone_url` from that response and passes it straight into `_checkoutPullRequest` [3](#0-2) . That value is a field of a GitHub-API-shaped JSON object, one of the object classes the assignment explicitly treats as attacker-controllable.

`_checkoutPullRequest` → `_findPullRequestBranch` takes this `headCloneUrl` and, if no existing remote matches it, calls `addRemote(repository, forkRemoteName, headCloneUrl)` [4](#0-3) . `addRemote` executes:

```ts
await git(['remote', 'add', name, url], repository.path, 'addRemote')
``` [5](#0-4) 

There is **no `--` separator** before `url`, and no check that `url` doesn't begin with `-` (an option-like string) or otherwise conforms to a valid `https://`/`ssh://`/`git@` remote form (the kind of shape `parseRemote` in `app/src/lib/remote-parsing.ts` validates for URL *matching*, but that function is never invoked as a gate before `addRemote` is called).

Contrast this with `app/src/lib/git/clone.ts`, which is Desktop's own hardened precedent for exactly this class of bug: it explicitly appends the URL after a `--` end-of-options marker specifically to stop a crafted URL from being parsed as a git command-line flag:

```ts
args.push('--', url, path)
``` [6](#0-5) 

`clone.ts` even documents this defense-in-depth intent for path traversal via `isClonePathSensitive` [7](#0-6) , showing the team is aware this class of input needs hardening — yet `addRemote()`, reachable from the same "open repo from URL"/PR-checkout deep-link surface, was never given the equivalent guard.

### Impact Explanation
If `headCloneUrl` (attacker-controlled via a crafted PR API response served from a link the victim clicks and Desktop resolves) begins with `-`, it is passed as the last positional token to `git remote add name <url>` without an option-terminator. Depending on the installed git version's option parser, this creates surface for git-argument-injection style corruption of the invoked git invocation (the same general bug class as historical git URL/argument-injection issues), silently corrupting the remote/refs state that later `fetch`/`checkout` operations in the same PR flow operate on — matching the "silent corruption of what the user commits/pushes" and "arbitrary call injection via unvalidated forwarding" impact classes in scope. This is a lower-severity/lower-confidence analog than the original DeFi exploit (no fund loss possible), so I flag it as a hardening gap rather than a proven RCE, given I could not fully trace how far git's own parser tolerates a dash-prefixed remote URL in this exact command shape.

### Likelihood Explanation
Reaching this path requires only that the victim click an `x-github-client://openRepo/...?pr=N` link (or equivalent CLI `--cli-clone`/protocol-launcher invocation) pointing at a server the attacker controls, and have Desktop registered as the protocol handler (default on install) — no local access, no credentials, no admin rights, matching the "unprivileged... link or deep link the user clicks... or a GitHub API object" criteria. The remaining uncertainty is purely about the git binary's exact CLI-parsing behavior for a dash-prefixed positional after `remote add <name>`, which I could not verify further in this pass.

### Recommendation
Apply the same defense used in `clone.ts` to `addRemote()` (and any other `git(...)` call sites that place an externally/API-sourced URL as a bare positional argument): insert a `--` separator before the URL, and/or validate the URL against `parseRemote`'s expected shapes (or an explicit "does not start with `-`" check) before calling `git remote add`. Treat `pullRequest.head.repo.clone_url` from `fetchPullRequest` as untrusted input at the point it crosses into git subprocess argument construction, not just at URL-matching time.

### Proof of Concept
1. Register/point a server at an arbitrary hostname; host a fake "PR" API response for that host that `fetchPullRequest(url, pr)` will consume.
2. Craft the deep link `x-github-client://openRepo/<attacker-host>?pr=1` and get the victim to open it (or use `--cli-clone`).
3. `parseAppURL` accepts the `pr` (numeric) and forwards `url` unmodified [1](#0-0) ; Desktop calls `fetchPullRequest(url, 1)` against the attacker's server.
4. Have the fake API return `head.repo.clone_url` set to a dash-prefixed string.
5. `_findPullRequestBranch` calls `addRemote(repository, forkRemoteName, headCloneUrl)` → `git(['remote', 'add', name, headCloneUrl])` with no `--` guard [5](#0-4) [8](#0-7) , unlike the hardened `clone.ts` call site.

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
