### Title
Unvalidated `kip71.gastarget` governance parameter allows divide-by-zero panic in `NextMagmaBlockBaseFee` - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` (`x.Div(x, new(big.Int).SetUint64(gasTarget))`) in both the "usage above target" and "usage below target" branches, but `gasTarget` is taken directly from the governance-controlled `GasTarget` field without a zero check, unlike the sibling `BaseFeeDenominator` field which explicitly guards against zero.

### Finding Description
`KIP71Config.NextMagmaBlockBaseFee` computes the next block's base fee as part of Magma/KIP-71 dynamic gas pricing [3](#0-2) . It defends against `BaseFeeDenominator == 0` by substituting a fallback value of 64 [4](#0-3) , but performs no equivalent check for `gasTarget := kc.GasTarget` [5](#0-4) .

If `parentGasUsed != gasTarget`, the function computes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` in both the increase branch (line 102) and decrease branch (line 120) [6](#0-5) . Go's `math/big.Int.Div` panics with "division by zero" when the divisor is zero. If `gasTarget == 0` and `parentGasUsed > 0`, the "usage above target" branch is taken and the division panics, crashing the node.

The governance parameter registry defines `Kip71GasTarget` with `FormatChecker: noopFormatChecker`, meaning any `uint64` value including `0` passes validation, in contrast to `Kip71BaseFeeDenominator` which explicitly requires `v != 0` [1](#0-0) . The header-governance vote-consistency checker (`checkConsistency`) also does not reject a zero `Kip71GasTarget` vote — it only validates `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` relationships and passes `Kip71GasTarget` straight through as always valid [7](#0-6) .

### Impact Explanation
If a `kip71.gastarget = 0` value is ever accepted (via header governance vote or the GovParam contract governance path, which also goes through `ParamSet.Set` without additional zero-checks for this field), then on the next Magma block where `parentGasUsed != 0`, every node computing `NextMagmaBlockBaseFee` — both for block validation (`VerifyMagmaHeader`) and fee estimation (`feehistory.go`'s `processBlock`) — will panic on the `big.Int` division by zero. Since this function is called by all full nodes during block header verification, this crashes every node in the network simultaneously, resulting in a full network denial of service. This mirrors the CVE-2016-10266 bug class (divide-by-zero crash from an unchecked/attacker-influenced parameter).

### Likelihood Explanation
Reaching this requires a `kip71.gastarget` governance vote/parameter update to be accepted with value `0`. This is gated by governance permissions (only governing node / council members with voting rights, or via the GovParam contract's KIP-81 on-chain voting), not a directly attacker-controlled single transaction. However, no defense-in-depth check exists anywhere in the validation path (`FormatChecker`, `checkConsistency`, or `NextMagmaBlockBaseFee` itself) to prevent this — unlike the parallel `BaseFeeDenominator` field, which received an explicit zero-guard both in `FormatChecker` and in `NextMagmaBlockBaseFee`. A single governance misconfiguration or malicious/compromised governing-node vote is sufficient to trigger a chain-wide panic.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects `v == 0`, matching the pattern used for `Kip71BaseFeeDenominator` [8](#0-7) . Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` for `gasTarget`, mirroring the existing `BaseFeeDenominator == 0` fallback [9](#0-8) , so that even a value that slips through governance validation (e.g. via a legacy `ChainConfig`/genesis path that bypasses the `Params` map) cannot crash the node.

### Proof of Concept
1. Set `Governance.KIP71.GasTarget = 0` (e.g., via a `kip71.gastarget` governance vote accepted through `checkConsistency`, which does not validate this field, or directly via `ChainConfig`/genesis as in `params/kip71_config_test.go`'s test harness which allows `gasTarget: 0` combinations).
2. Produce/verify a Magma block where `parentHeaderGasUsed > 0` (i.e., `parentGasUsed != gasTarget`, taking the "usage above target" branch).
3. `NextMagmaBlockBaseFee` executes `gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)` then `x.Div(x, new(big.Int).SetUint64(gasTarget))` at [10](#0-9) , which panics with "division by zero" because `gasTarget` is `0`, crashing the node during header verification.

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.

		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
