### Title
Unauthenticated OP_RETURN operator-attribution in payout_tx allows crediting/reimbursing an operator that never funded the withdrawal - ([File: core/src/verifier.rs], root cause in [File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` only requires the withdrawer's own Schnorr signature over the payout input, using `SIGHASH_SINGLE|ANYONECANPAY`, which commits to input 0 and output 0 only. The OP_RETURN output (index 2) carrying the "payer" operator's x-only pubkey is completely outside the signed message, so any unprivileged party who controls the withdrawal input can insert an arbitrary 32-byte value there — including a real operator's public, unauthenticated key — with zero involvement from that operator. `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) blindly trusts this OP_RETURN content to populate `payout_payer_operator_xonly_pk`, which is later used by `is_kickoff_malicious` and `send_asserts` as the sole cryptographic-looking binding between a payout and the operator entitled to reimbursement.

### Finding Description
The claimed binding is: `operator_xonly_pk` recorded in `withdrawals.payout_payer_operator_xonly_pk` (from OP_RETURN, `core/src/verifier.rs:2319-2321`) == the operator that cryptographically authorized/funded this specific payout.

Trace:
- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with: input 0 = withdrawal UTXO (key-spend, signed only by `user_sig`), output 0 = user payout, output 1 = anchor, output 2 = `op_return_txout(operator_xonly_pk.serialize())`.
- The only in-protocol signature check is in `Operator::withdraw` (`core/src/operator.rs:630-637`): `SECP.verify_schnorr(&in_signature.signature, sighash, user_xonly_pk)`, where `in_signature.sighash_type` is attacker-controlled and typically `SinglePlusAnyoneCanPay` (see `sign_withdrawal_output`, `core/src/test/common/setup_utils.rs:529-540`). `SIGHASH_SINGLE|ANYONECANPAY` commits only to input 0 and output 0 — outputs 1 (anchor) and 2 (OP_RETURN) are **not** covered by any signature.
- Consequently, nothing in the transaction cryptographically ties the OP_RETURN's 32 bytes to any operator. Anyone who owns/controls the withdrawal input (the withdrawer/attacker, per the threat model) can construct and broadcast the entire payout tx themselves, fund output 0 with their own money, and place any operator's real public x-only pubkey into output 2 — no brute force or coincidence needed, since operator pubkeys are public.
- `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses this OP_RETURN via `parse_op_return_data` (`circuits-lib/src/bridge_circuit/mod.rs:608-617`) and `XOnlyPublicKey::from_slice`, then unconditionally records the parsed key as `payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`).
- `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1857-1915`) only checks `operator_xonly_pk != kickoff_data.operator_xonly_pk` (i.e., that the value recorded in the DB matches the operator who happens to send the kickoff) — it never checks that the named operator actually funded any input of the payout tx.
- `Operator::send_asserts` (`core/src/operator.rs:1275-1295`) performs the identical DB-value check (`payout_op_xonly_pk != kickoff_data.operator_xonly_pk`), again with no reference to actual fund provenance.
- `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:31-111`) is an **automated background task run by the operator's own node**, which polls `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` and automatically calls `handle_finalized_payout` → kickoff → reimbursement whenever a payout is attributed to that operator's own pubkey, with no manual verification that the operator actually spent BTC in that payout tx.

No existing guard (`SECP.verify_schnorr` on the withdrawal signature, `is_kickoff_malicious`, `send_asserts`'s comparison) re-derives or checks that the named operator's funds/signature are actually present in the payout transaction; they all merely check "does the DB-recorded key match the kickoff sender's key," which the attacker fully controls by choice of OP_RETURN bytes.

### Impact Explanation
This breaks the "operator reimbursed for a payout it never funded" Critical category. An attacker who is the withdrawer can:
1. Register a withdrawal on Citrea and obtain a valid withdrawal UTXO.
2. Construct and broadcast the payout tx themselves (fully self-funded, `SIGHASH_SINGLE|ANYONECANPAY` on input/output 0), attaching a targeted operator O's real, public x-only pubkey in the unauthenticated OP_RETURN, with O never touching a key or funding anything.
3. `update_finalized_payouts` attributes the payout to O.
4. O's own automated `PayoutCheckerTask` (or O acting maliciously/negligently) sends a kickoff, passes `is_kickoff_malicious`/`send_asserts` checks (since the DB value matches O's kickoff key), and O is reimbursed `bridge_amount` from the deposit's move-to-vault funds — real BTC that O never fronted.

This directly moves bridge value (deposit funds meant to reimburse the actual fronting operator) to an operator with zero funding contribution, per deposit/withdrawal, and is repeatable across any deposit/withdrawal where the attacker can control the withdrawal input and any named operator's public key.

### Likelihood Explanation
- Preconditions: attacker must be able to register/control a withdrawal on Citrea (standard `withdraw` call, well within the defined unprivileged attacker capability), and know any operator's public x-only pubkey (public information, no compromise needed).
- No paramset/config dependency beyond default protocol behavior (SIGHASH_SINGLE|ANYONECANPAY payout construction is standard, evidenced by `sign_withdrawal_output` test helper).
- Attacker cost: only the fee to fund and broadcast their own payout tx (they must fully fund the payout output themselves — no operator funds needed to trigger the mis-attribution).
- Feasibility: high, requires only standard bitcoin tx construction skills; no cryptographic break needed since the OP_RETURN is simply unauthenticated data.
- Repeatable across every deposit/withdrawal and against any operator whose pubkey is known (all operators' pubkeys are inherently public in this protocol).

### Recommendation
Bind the OP_RETURN operator attribution cryptographically to the actual funding operator. Options:
- Require the user's payout signature to use `SIGHASH_ALL` (or `SIGHASH_SINGLE` without `ANYONECANPAY`, plus commit all outputs) so the OP_RETURN output is covered by the signature, and additionally require the operator to co-sign or otherwise attest (e.g., via a MuSig2/aggregated signature or an operator-specific commitment in the deposit-time presigned data) that they are the one funding/authorizing the specific payout.
- Alternatively, verify that at least one input of the payout tx traces back to (or is signed by) the operator whose key appears in the OP_RETURN before recording `payout_payer_operator_xonly_pk`, rather than trusting the raw push bytes.
- At minimum, require the OP_RETURN content to be within the scope of a signature bound to the operator's own key (not just the withdrawer's key), so an unrelated third party cannot forge attribution.

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}

fn sign_withdrawal_output(
    config: &BridgeConfig,
    dust_utxo: &UTXO,
    withdrawal_address: &bitcoin::Address,
    withdrawal_amount: bitcoin::Amount,

        dust_utxo.txout.clone(),

        .with_version(NON_STANDARD_V3)

            NormalSignatureKind::NotStored,

        )

        .finalize();

    let sighash = tx

        signature: sig,

    };

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
