### Title
Blind SSRF via unauthenticated `isGitHubHost` probe triggered by attacker-controlled git remote URL - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's git credential trampoline automatically probes the hostname of *any* HTTPS remote URL it doesn't already recognize, sending an unauthenticated `HEAD` request to `<host>/meta` with TLS certificate validation deliberately suppressed. Because the probed URL is derived directly from the remote URL configured in the repository (attacker-controlled), a malicious `.git/config` remote, submodule URL, or cloned repo pointing to an internal address causes Desktop to make a blind outbound request into the user's private network — the same "unauthenticated blind SSRF triggered by an attacker-supplied endpoint" primitive as the GitLab Jira OAuth report.

### Finding Description
When git needs credentials for an HTTPS remote, Desktop's trampoline credential helper handles the request in `getCredential`/`getEndpointKind`: [1](#0-0) 

If the remote's endpoint is not already a known GitHub.com/GHE endpoint, has no `WWW-Authenticate` hint, and no existing stored account, and the protocol is `https:`, Desktop falls back to `isGitHubHost(endpoint)` where `endpoint` is built straight from the credential URL supplied by git for that remote (i.e., attacker-controlled if the attacker controls the remote): [2](#0-1) 

`isGitHubHost` then makes an outbound network probe using nothing but the attacker-supplied hostname, with certificate error suppression explicitly enabled for that exact URL so internal hosts with self-signed/invalid certificates don't fail the request: [3](#0-2) 

There is no restriction preventing the target host from being a private/internal address (loopback, RFC1918 ranges, link-local metadata IPs, internal corporate hostnames, etc.) — the same class of unrestricted `allow_local_requests: true` behavior in the original GitLab code. The request is fully blind from the attacker's perspective (result only affects Desktop's internal classification of "enterprise" vs "generic"), but the side effect — an HTTP(S) request being issued to an arbitrary internal host chosen by the repository owner — is identical to the reported SSRF primitive.

### Impact Explanation
An attacker who controls a repository's remote configuration (a public repo the victim clones, a submodule URL, or a maliciously edited `.git/config` opened in Desktop) can force the victim's GitHub Desktop instance to make outbound HTTPS requests to arbitrary internal hosts/ports whenever Desktop performs a git network operation against that remote (fetch, push, or Desktop's periodic background fetch). Because certificate validation is explicitly suppressed for the probe URL, internal services behind self-signed TLS (common for internal admin panels, cloud metadata-like endpoints, CI/infra dashboards) can be reached even where the certificate would normally block spoofing/interception protections. This matches the "git remote/proxy response attacker control -> internal network request" impact class in scope.

### Likelihood Explanation
Likelihood is moderate: it requires only that the victim add/clone/open a repository containing an attacker-chosen HTTPS remote and that Desktop subsequently perform a credentialed git network action against that remote — something that happens routinely (initial clone, background fetch, manual fetch/push) without any unusual user steps. The main constraints are that the URL scheme must be `https:` and that no `WWW-Authenticate` header short-circuits the check first, both of which are easily satisfied by choosing an appropriate victim-reachable internal hostname/IP for the remote.

### Recommendation
Restrict `isGitHubHost`'s probing to hosts that are not private/loopback/link-local addresses (mirroring SSRF-safe HTTP client guards), and avoid suppressing certificate validation for arbitrary attacker-controlled hosts. Alternatively, gate the fallback probe behind explicit user confirmation before Desktop issues any network request to an unrecognized remote host, and never issue it for private-IP-range or metadata-service-range targets.

### Proof of Concept
1. Create a repository whose remote URL points to an internal HTTPS service, e.g. `https://169.254.169.254/latest/meta-data/` or an internal corporate host `https://internal-admin.corp.local:8443/`.
2. Have the victim clone or open this repository in GitHub Desktop and let Desktop perform any git network operation (fetch/push, or wait for Desktop's background fetch).
3. Desktop's trampoline credential helper calls `getEndpointKind` → `isGitHubHost(endpoint)` for the unrecognized host [2](#0-1) , which issues a `HEAD /meta` request to the attacker-chosen host with certificate error suppression enabled [3](#0-2) .
4. Observe the outbound HTTPS request arriving at the internal/attacker-controlled endpoint from the victim's machine, confirming blind SSRF.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
