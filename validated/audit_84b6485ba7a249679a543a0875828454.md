### Title
Reward-dilution via direct token donation inflating `_calLpSupply` denominator in `updatePool` - (File: rewards/MasterMagpie.sol)

### Summary
`updatePool(address _stakingToken)` is a `public` function callable by anyone with no role restriction beyond `whenNotPaused`, and it derives the pool's staked-supply denominator from `_calLpSupply()`, which for any non-`vlmgp`/non-`mWomSV` pool simply returns `IERC20(_stakingToken).balanceOf(address(this))` rather than an internally tracked sum of `UserInfo.amount`. An attacker can transfer receipt tokens directly to the `MasterMagpie` contract (bypassing `deposit`) to inflate this balance, then call `updatePool` to permanently dilute `accMGPPerShare` for the interval, causing legitimately staked users to accrue less MGP than the `mgpPerSec` schedule actually emits for that period.

### Finding Description
`_calLpSupply` at [1](#0-0)  returns the raw ERC20 balance of the staking token held by the contract for any pool other than `vlmgp`/`mWomSV`, instead of an accounting variable incremented/decremented only through `_deposit`/`_withdraw`.

`updatePool` at [2](#0-1)  is `public` and only gated by `whenNotPaused` — there is no `onlyPoolManager`, `onlyOwner`, or any check tying the caller to a staked position. It computes:
```
uint256 lpSupply = _calLpSupply(_stakingToken);
uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
```

Legitimate deposits go through `_deposit`, which increases `user.amount`/`user.available` and pulls tokens via `safeTransferFrom`, keeping the ERC20 balance and the sum of `UserInfo.amount` in lockstep: [3](#0-2) . However, nothing prevents a third party from calling `IERC20(_stakingToken).transfer(address(masterMagpie), amount)` directly — this raises `balanceOf(address(this))` without touching any `UserInfo.amount`.

Once the attacker (or anyone, since `updatePool` is callable by anybody, including the attacker themselves right after the donation) triggers `updatePool`, the `mgpReward` computed for the elapsed `multiplier` seconds is divided by the inflated `lpSupply`, producing a smaller `accMGPPerShare` increment than the amount of MGP actually entitled to real stakers over that interval. Since `accMGPPerShare` monotonically increases and previous values are never revisited, this reward shortfall for the affected interval is permanently unrecoverable by legitimate stakers — it is not redistributed to anyone since only `UserInfo.amount * accMGPPerShare` is ever paid out via `_harvestMGP`/`_calNewMGP` (seen used at [4](#0-3) ). No modifier, `nonReentrant` guard, or reward-index safeguard prevents this because the check is purely `whenNotPaused` with no relation to the caller's stake.

### Impact Explanation
This permanently reduces (freezes) the MGP yield that should have accrued to genuine stakers of the targeted pool for the time interval bridged by the inflated `updatePool` call. Since `mgpPerSec * pool.allocPoint / totalAllocPoint` MGP is conceptually "emitted" for that interval (and the emission schedule/rate itself is unaffected — it's an accounting/distribution bug, not a supply-minting bug), but a fraction of it is siloed off due to the inflated denominator, that fraction becomes permanently non-claimable by any `UserInfo`. This matches "High – Permanent freezing of unclaimed yield" since the underpayment is baked into `accMGPPerShare` and can never be corrected retroactively for stakers present during that window.

### Likelihood Explanation
The precondition specified (the pool being the sole pool with non-zero `allocPoint` so the entire `mgpPerSec` stream lands on it) maximizes damage but is not strictly required — any pool with a non-zero allocation is affected proportionally. The attack requires only: (1) owning/acquiring some amount of the pool's staking (receipt) token on the open market, (2) a plain ERC20 `transfer` to the `MasterMagpie` contract address, and (3) calling the permissionless `updatePool(_stakingToken)`. No special role, flash loan, or privileged access is needed, and it is trivially repeatable across multiple intervals to compound the loss.

### Recommendation
Track staked supply internally (e.g., a `pool.totalStaked` field incremented/decremented exclusively inside `_deposit`/`_withdraw`) and use that value in `_calLpSupply`/`updatePool`/`_calMGPReward` instead of the raw `IERC20(_stakingToken).balanceOf(address(this))`, so that only staked-and-credited supply (matching the sum of `UserInfo.amount`) is ever used as the `accMGPPerShare` denominator.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `MasterMagpie`, a mock MGP token, and a mock ERC20 staking token; register the staking token as the only pool with non-zero `allocPoint` (`totalAllocPoint == pool.allocPoint`).
2. Victim calls `deposit(stakingToken, 100e18)` to stake 100 tokens (this both increases `user.amount` and the token balance of `MasterMagpie` to 100e18).
3. Advance time by `T` seconds.
4. Attacker (holding tokens bought separately, e.g., 900e18) directly calls `stakingToken.transfer(address(masterMagpie), 900e18)` — bypassing `deposit` — then calls `updatePool(stakingToken)`.
5. Assert: `pool.accMGPPerShare` increased by only `mgpPerSec*T*1e12/1000e18` instead of the correct `mgpPerSec*T*1e12/100e18` that should apply based on actual staked supply.
6. Advance more time and have the victim call `withdraw`/`multiclaim`; assert the victim's claimable MGP (`_calNewMGP`/`pendingTokens`) is materially less than `mgpPerSec*T` (the amount that should have fully accrued to the sole staker), while `IBaseRewardPool(rewarder).balanceOf(victim)` versus `totalStaked()` shows no change from the attacker's donation, confirming the reward shortfall is unrecoverable and not attributable to any `UserInfo`.

    function updatePool(address _stakingToken) public whenNotPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        if (block.timestamp <= pool.lastRewardTimestamp || totalAllocPoint == 0) {
            return;
        }
        uint256 lpSupply = _calLpSupply(_stakingToken);
        if (lpSupply == 0) {
            pool.lastRewardTimestamp = block.timestamp;
            return;
        }        
        uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
        uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
        
        pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
        pool.lastRewardTimestamp = block.timestamp;

        emit UpdatePool(
            _stakingToken,
            pool.lastRewardTimestamp,
            lpSupply,
            pool.accMGPPerShare
        );
    }

            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);

    }

    /// @notice calculate MGP reward based at current timestamp, for frontend only
    function _calMGPReward(address _stakingToken, address _user) internal view returns(uint256 pendingMGP) {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_user];
        uint256 accMGPPerShare = pool.accMGPPerShare;
        uint256 lpSupply = _calLpSupply(_stakingToken);

        if (block.timestamp > pool.lastRewardTimestamp && lpSupply != 0) {
            uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
            uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) /
            totalAllocPoint;
            accMGPPerShare = accMGPPerShare + (mgpReward * 1e12) / lpSupply;
        }

        pendingMGP = (user.amount * accMGPPerShare) / 1e12 - user.rewardDebt;
        pendingMGP += unClaimedMgp[_stakingToken][_user];
    }

    function _calLpSupply(address _stakingToken) internal view returns (uint256) {
        if (_stakingToken == address(vlmgp)) {
            return IERC20(address(vlmgp)).totalSupply();
        }
        if (_stakingToken == address(mWomSV)) {
            return IERC20(address(mWomSV)).totalSupply();
        }
        return IERC20(_stakingToken).balanceOf(address(this));
    }
