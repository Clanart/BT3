### Title
`isGitHubHost` misclassifies attacker-controlled hosts as GitHub via substring/label check, causing credential-helper to treat them as GitHub Enterprise - ([File: app/src/lib/api.ts])

### Summary
Analogous to the DNSSEC bug where `rrset.signerName.equals(0, name, ...)` treated a substring match as valid zone containment instead of checking label boundaries, `isGitHubHost` in `app/src/lib/api.ts` uses a loose regex to decide whether a hostname "belongs to GitHub" and returns `true` for any hostname that merely contains a label literally equal to `github`, without verifying it is an actual suffix/owned domain via the live `/meta` check that follows it in the same function.

### Finding Description
`isGitHubHost` is meant to be a best-effort classifier that ultimately confirms via a live request (`x-github-request-id` header check) whether an unknown host is a GitHub/GHE instance: [1](#0-0) 

The early-return regex `/(^|\.)(github)\./.test(hostname)` is intended to fast-path obvious cases like `github.example.com`, but it only checks that a *label* named `github` exists somewhere in the hostname preceded by a dot or start-of-string — it does not require that this be a trusted suffix, nor does it fall through to the live verification request that guards every other ambiguous case below it. Any attacker who controls a DNS zone can trivially create a hostname whose leftmost or an internal label is exactly `github` (e.g. `github.attacker.example`, or `x.github.attacker.example`), which satisfies `(^|\.)github\.` and causes the function to short-circuit and return `true` — completely bypassing the actual trust-establishing HEAD request to `/meta` that checks for GitHub's `x-github-request-id` response header.

This is the same broken-invariant class as the DNSSEC report: a substring/label match is used as a stand-in for "is contained within / belongs to" a trusted namespace, without validating that the match is anchored to the real authoritative suffix.

`isGitHubHost` feeds directly into the git-credential trampoline's endpoint classification: [2](#0-1) 

When Git needs credentials for a remote whose host doesn't match `isDotCom`/`isGHE`/`WWW-Authenticate` hints/known accounts, `getEndpointKind` falls back to `isGitHubHost(endpoint)`; if it returns `true`, the endpoint is classified `'enterprise'`. That classification changes behavior in `getCredential`: [3](#0-2) 

For an `'enterprise'`-classified endpoint with no matching stored account, Desktop calls `ui.promptForGitHubSignIn(endpoint)` instead of the generic credential path (`getGenericCredential`/external credential manager). This routes the user into the GitHub Enterprise sign-in flow, targeted at an attacker-chosen host, instead of the normal generic-git-auth prompt that a non-GitHub remote should receive.

### Impact Explanation
An attacker who controls a git remote/proxy hostname containing a `github` label (fully within their own DNS control, no GitHub infrastructure needed) can force Desktop to misclassify their server as a "GitHub Enterprise" endpoint. This:
- Bypasses the intended live verification (`/meta` + `x-github-request-id`) that is supposed to gate this classification for unknown hosts.
- Diverts credential handling away from the generic credential helper path (`getGenericCredential`) into the GitHub-specific sign-in flow (`ui.promptForGitHubSignIn`), presenting the user with a GitHub-branded authentication prompt for a host that has nothing to do with GitHub.
- Suppresses generic credential storage/erasure for that host (`storeCredential`/`eraseCredential` return early for non-`'generic'` endpoint kinds), silently changing how the user's credentials for that remote are persisted.

This matches the "unprivileged, attacker controls a git remote, result is unauthorized OAuth/account-binding-style flow and altered credential handling" impact class, since the user is misled into an enterprise GitHub sign-in dialog for a domain that was never actually verified as GitHub.

### Likelihood Explanation
Low-to-medium, similar to the original finding's judged severity. Exploitation only requires the attacker to name one DNS label `github` under a domain they control and get the user to add/clone from that remote — no privileged access, no compromised credentials, and no unusual user action beyond adding a normal-looking git remote. However, the actual damage is bounded: no real GitHub token or dotcom credential is exposed directly (the sign-in flow still targets the attacker's own endpoint), so the primary harm is UX-level trust confusion and altered credential-storage behavior rather than direct token theft — consistent with the original report being downgraded to Medium because of limited real-world exploitability.

### Recommendation
Do not use a bare label-boundary regex as a proxy for "is a GitHub host." Either:
- Require the match to be an actual suffix of a known/allow-listed domain (e.g., `hostname === 'github.com' || hostname.endsWith('.github.com')` plus explicit GHE domain checks), or
- Remove the early-return regex fast path entirely and always fall through to the authoritative `/meta` + `x-github-request-id` verification for unknown hosts, exactly as already done at the bottom of `isGitHubHost`.

### Proof of Concept
1. Attacker registers `github.attacker.example` (or `x.github.attacker.example`) and stands up a normal HTTPS git server there (no GitHub-specific behavior needed).
2. User adds/clones this remote in Desktop.
3. When Git needs credentials, `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts:137-179` falls through to `isGitHubHost(endpoint)`.
4. In `app/src/lib/api.ts:2452-2454`, `/(^|\.)(github)\./.test('github.attacker.example')` matches (label `github` anchored at string start), so the function returns `true` immediately — the `/meta` verification request is never issued.
5. `getEndpointKind` returns `'enterprise'`; since no stored account matches this endpoint, `getCredential` (`trampoline-credential-helper.ts:93-135`) invokes `ui.promptForGitHubSignIn(endpoint)` instead of the generic credential prompt, and generic credential storage/erasure is skipped for this host.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
