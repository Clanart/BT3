### Title
Unbounded recursion in outer-puzzle driver matching allows attacker-crafted offers to crash a wallet via Python stack exhaustion - (File: `chia/wallet/outer_puzzles.py`, `chia/wallet/cat_wallet/cat_outer_puzzle.py`, `chia/wallet/nft_wallet/singleton_outer_puzzle.py`, `chia/wallet/vc_wallet/cr_outer_puzzle.py`)

### Summary
The `stellar/rs-soroban-env` bug class is "unbounded recursion on untrusted input causes stack overflow because no `DepthLimiter` is enforced." Chia already hardens the two most obvious analog spots (`sha256_treehash` is deliberately iterative [1](#0-0) , and `chia_rs.datalayer` enforces `RecursionDepthExceededError` for Merkle tree ingestion [2](#0-1) ), but the wallet's "outer puzzle" driver dispatch used for offers/trades is genuinely recursive with no depth limit and is directly reachable from untrusted, attacker-supplied puzzle reveals.

### Finding Description
`match_puzzle()` and the sibling `get_inner_puzzle()`/`get_inner_solution()`/`construct_puzzle()`/`solve_puzzle()` functions in `chia/wallet/outer_puzzles.py` dispatch to a fixed set of outer-puzzle drivers (CAT, Singleton, Metadata, Ownership, CR, Revocation) [3](#0-2) . Each driver's `match()` recognizes a puzzle by mod hash (e.g. `CAT_MOD`, `SINGLETON_TOP_LAYER_MOD`) and then recursively invokes `self._match(...)` on the *inner* puzzle to discover further nested "also" layers, chaining these into a `PuzzleInfo` via `also()` [4](#0-3) [5](#0-4) [6](#0-5) .

Because these matches only test the *mod hash* of each layer (not any real economic/semantic validity), nothing prevents a puzzle_reveal from consisting of the same known mod (e.g. `CAT_MOD` or `SINGLETON_TOP_LAYER_MOD`) curried recursively around itself thousands of times. Building such a puzzle requires no CLVM execution or spend validation — an attacker fully controls the `puzzle_reveal` bytes of their own offered coin when constructing an `Offer`. `PuzzleInfo.also()`/`check_type()` is likewise explicitly recursive with unbounded depth driven by the same attacker-controlled chain [7](#0-6) .

When a victim wallet inspects or accepts such an offer (`Offer.from_bech32`/`from_bytes`, then `_get_offered_coins()` calling `match_puzzle`/`get_inner_puzzle`/`get_inner_solution`) [8](#0-7) , Python recurses one native stack frame per crafted layer. Python's default recursion ceiling (`sys.getrecursionlimit()`, typically 1000) is reachable with a few hundred nested curry layers — an offer file of only a few KB. This is directly analogous to the missing `DepthLimiter` in the Soroban `Host`: there is no depth check anywhere in the `match`/`get_inner_puzzle`/`get_inner_solution`/`construct`/`solve` recursion chain.

### Impact Explanation
A malicious offer file (or a spend bundle presented for `get_offer_summary`/`take_offer`-style inspection) can deterministically raise `RecursionError` (or in pathological cases corrupt the interpreter's C stack before Python's guard triggers, depending on frame size and platform) inside the wallet process that merely *previews* the offer, before the user has decided whether to accept it. This is a spend-triggered/offer-triggered transaction-processing halt reachable by any offer counterparty with no signature or on-chain broadcast required, satisfying the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
High: constructing the malicious puzzle reveal requires only pure Python/CLVM `curry()` calls with no cryptographic material, no on-chain broadcast, and no special privileges — any offer counterparty (or a malicious "verify this offer" file shared over IPC/Discord/marketplaces, which is the entire trust model of the offer file format) can trigger it merely by having it opened/previewed by `chia wallet` offer tooling.

### Recommendation
Add an explicit depth counter/limit threaded through `match_puzzle`, `get_inner_puzzle`, `get_inner_solution`, `construct_puzzle`, `solve_puzzle`, and `PuzzleInfo.also()`/`check_type()`, raising a clear, catchable error (not `RecursionError`) once a sane maximum layer count (e.g. 16–32, generously above any real puzzle stack) is exceeded — mirroring the `RecursionDepthExceededError` pattern already used in `chia_rs.datalayer`.

### Proof of Concept
Conceptual construction (not run, since this is a read-only analysis):
1. Take `CAT_MOD` (or `SINGLETON_TOP_LAYER_MOD`) and build `puzzle = CAT_MOD.curry(any_tail_atom, puzzle)` in a loop N times (e.g. N = 2000), starting from any innocuous leaf inner puzzle.
2. Construct a `CoinSpend` whose `puzzle_reveal` is this `puzzle` (puzzle-hash/coin identity need not correspond to a real spendable coin for offer-preview purposes — only offer inspection code paths need to run `match_puzzle` on it).
3. Wrap the spend into a `WalletSpendBundle`/`Offer` object and call `Offer._get_offered_coins()` (or the wallet RPC `get_offer_summary`) on the victim side.
4. Observe `match_puzzle` → `CATOuterPuzzle.match` → `self._match` recursing N times, exceeding Python's recursion limit and raising `RecursionError`, aborting the offer-preview/RPC call.

Note: I was not able to execute this PoC or trace through `chia_rs`'s Rust `uncurry_puzzle`/CLVM matching internals (not indexed) to confirm whether the mod-hash matching itself has any hidden depth cap; the analysis is based on the Python-level recursive dispatch logic shown above, which has no depth guard.

@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)

def match_puzzle(puzzle: UnknownPuzzle) -> PuzzleInfo | None:
    for driver in driver_lookup.values():
        potential_info: PuzzleInfo | None = driver.match(puzzle)
