## Analysis

This maps to the same broken-invariant pattern as the Karak report: a value is trusted because it was true at set-time (a slash handler that matched when the vault was deployed, or here a `clone_url` that matched when the local remote was configured), but the code re-checks against a source of truth that can change out from under it (a reassignable `slashingHandler` mapping vs. a GitHub-owned `owner/name` that can be re-registered after a rename/deletion). In Desktop, `owner + name` derived from the remote is re-resolved against the live GitHub API on every background refresh, and if the API now returns different `clone_url` data for that same `owner/name` pair, Desktop can be tricked into silently rewriting the local git remote. ### Title
Silent remote-URL rewrite via stale `owner/name` → `clone_url` trust in `updateRemoteUrl` - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
`repositoryWithRefreshedGitHubRepository` re-resolves the tracked repository purely from the parsed `owner`/`name` of the current git remote (`matchGitHubRepository`), then fetches fresh repository data from the GitHub API for that `owner`/`name` and feeds it into `updateRemoteUrl`, which will overwrite the local `origin` URL if its heuristics decide the "protocol didn't change" and the "remote hasn't been manually altered." Ownership of an `owner/name` pair on GitHub.com is not immutable (accounts/orgs can be renamed, deleted, or repos deleted and the name/owner re-registered by a different, potentially malicious, party), so the `owner`/`name` key Desktop uses to re-fetch "the same" repository can silently start resolving to an attacker-controlled repository.

### Finding Description
`repositoryWithRefreshedGitHubRepository` derives `owner`/`name` from the current default remote via `matchGitHubRepository`, which only checks that the remote's hostname matches an account's endpoint — it does not verify identity against any stable id (e.g., a GitHub repository id): [4](#0-3) 

It then calls `api.fetchRepository(owner, name)` against the live API and, if the repository already has a `gitHubRepository` association, calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`: [5](#0-4) 

`updateRemoteUrl` will rewrite the on-disk remote URL if (a) the current remote's URL still matches what was previously cached as the GitHub repository's `cloneURL`, (b) the protocol (`https`/`ssh`) of old vs. new clone URL matches, and (c) the newly fetched `clone_url` no longer matches the current remote: [6](#0-5) 

None of these checks validate that the API is still describing the *same* repository the user originally added — they only compare URL shape (hostname/owner/name strings) and protocol, both of which are attacker-satisfiable if the attacker obtains the same `owner`/`name` (e.g., after the original owner renames their account/org, deletes the repo, or a squatted username/org is re-registered) and the attacker's freshly created repo returns a `clone_url` with the same protocol as before. `urlMatchesRemote`/`urlsMatch` used throughout this path key strictly on string-parsed hostname/owner/name, never on GitHub's immutable numeric repository id: [7](#0-6) 

This is structurally the same class of bug as the Karak report: a cached/previously-valid association (`slashingHandler` for an asset / `clone_url` for an `owner+name`) is trusted without re-validating identity against something that cannot be reassigned, and the mutable backing value (`assetSlashingHandlers[asset]` / GitHub's live `owner/name → repo` mapping) is allowed to change and silently break (or in this case corrupt) the dependent state.

### Impact Explanation
If exploited, Desktop silently reconfigures the user's `origin` remote to point at an attacker-controlled repository (`gitStore.setRemoteURL`), without any prompt (this only shows the `UpstreamAlreadyExists` dialog for the `upstream` remote of forks, not for `origin` rewrites via `updateRemoteUrl`). Subsequent `git push` from Desktop would then push the user's commits — potentially containing proprietary code, secrets baked into history, or credentials in commit metadata — to the attacker's repository. This satisfies "silent corruption of what the user commits or pushes" from the valid-impact list.

### Likelihood Explanation
This requires no local access, no admin rights, and no prior malware: it only requires that a `owner`/`name` pair a Desktop user has previously tracked becomes re-registrable (owner account rename/deletion, org rename, or repository deletion followed by re-creation under the same name by a different actor) and that the attacker's new repo's `clone_url` shares the old protocol. GitHub does not prevent username/org-name reuse after deletion, and repository renames/deletions are common; Desktop's background refresh (`repositoryWithRefreshedGitHubRepository`) runs automatically without user interaction, making this a background, unprompted path. The main mitigating factor is that Desktop's tests only exercise "protocol match + old URL still equals cached cloneURL" as a narrow trigger condition, but nothing in the code path re-validates repository identity via a stable id, so likelihood is not eliminated by any existing guard.

### Recommendation
- Key repository identity re-resolution on GitHub's immutable numeric repository `id` (already present on `IAPIRepository`/`GitHubRepository`) rather than on parsed `owner`/`name` strings.
- In `updateRemoteUrl`, additionally verify that `apiRepo.id === gitHubRepository.dbID` (or equivalent stable identifier) before rewriting the remote URL; if the id differs, treat it as a different repository and surface a prompt to the user (similar to `UpstreamAlreadyExists`) instead of silently updating.
- Consider requiring explicit user confirmation any time Desktop programmatically changes a configured remote URL, rather than doing so unattended in a background refresh path.

### Proof of Concept
1. User adds `origin` = `https://github.com/alice/project.git` in Desktop; Desktop caches `gitHubRepository.cloneURL = https://github.com/alice/project.git` (`id: 111`).
2. Alice renames her GitHub account/org or deletes it; attacker registers the `alice` account/org and creates a new public repo named `project` (`id: 999`), with `clone_url = https://github.com/alice/project.git` (same protocol, same owner/name string).
3. On the next background refresh, `repositoryWithRefreshedGitHubRepository` → `matchGitHubRepository` resolves `owner=alice, name=project` purely from the string-parsed remote (`app/src/lib/repository-matching.ts:29-46`) and calls `api.fetchRepository('alice','project')`, which now returns the attacker's repo (`id: 999`) since GitHub resolves by current owner/name, not by history.
4. `updateRemoteUrl` finds `protocolsMatch === true`, `remoteUrlUnchanged === true` (URL string still matches what was cached), and since the id/content differs but the URL string coincidentally still parses to the same `owner/name`, `urlsMatch` stays true too in this exact-string case — meaning no rewrite is even needed for the attack to already have succeeded silently, because Desktop already treated the attacker's repo as "the same repository" and merged its metadata (`ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)`) without any identity check (`app/src/lib/stores/app-store.ts:4909`).
5. If the attacker instead sets up a redirect scenario where their new repo's `clone_url` differs slightly (e.g. canonical case or a `.git` suffix change) while keeping the same owner/name, `updateRemoteUrl`'s `!urlsMatch` branch fires and actively calls `gitStore.setRemoteURL(...)`, rewriting `origin` to the attacker's exact URL — this is the clearest silent-corruption trigger.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

  private async matchGitHubRepository(
    repository: Repository
  ): Promise<IMatchedGitHubRepository | null> {
    const gitStore = this.gitStoreCache.get(repository)

    if (!gitStore.defaultRemote) {
      await gitStore.loadRemotes()
    }

    const remote = gitStore.defaultRemote
    return remote !== null
      ? matchGitHubRepository(this.accounts, remote.url)
      : null
  }

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
