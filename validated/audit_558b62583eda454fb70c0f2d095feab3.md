### Title
Blame proof reveals decryption key before the message's proof-of-possession is verified, creating a decryption oracle over other participants' encrypted shares - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary

`KeyMachine::calculate_share` decrypts each participant's `EncryptedMessage` via `Encryption::decrypt`, which unconditionally produces an `EncryptionKeyProof` containing the ECDH shared key for that message's `key` point. The message's Schnorr proof-of-possession (PoP) is only *queued* into a `BatchVerifier`, yet if the decrypted bytes fail to deserialize as a scalar, `calculate_share` returns `PedPoPError::InvalidShare { blame: Some(blame) }` immediately — before `batch.verify_with_vartime_blame()` ever checks the PoP. A malicious participant can therefore attach an arbitrary `key` point (copied from another participant's encrypted share to the same victim) with an invalid PoP, and still obtain the victim's ECDH decryption key for that point — decrypting the honest participant's secret share.

### Finding Description

The `EncryptedMessage` design relies on a per-message Schnorr PoP to prevent exactly this attack, as documented at `crypto/dkg/pedpop/src/encryption.rs:83-91`: without the PoP, Eve could reuse Alice's encryption key `X`, trigger a blame, and have Bob reveal `bX` (the ECDH key), decrypting Alice's real message to Bob.

The mitigation is undermined by ordering in `calculate_share` (`crypto/dkg/pedpop/src/lib.rs:476-499`):

```rust
let (mut share_bytes, blame) =
  self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
let share = Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0))
  .ok_or_else(|| PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) })?);
```

`Encryption::decrypt` (`crypto/dkg/pedpop/src/encryption.rs:469-501`) only calls `msg.pop.batch_verify(...)`, which *queues* the PoP statement; it then computes `ecdh(&self.enc_key, msg.key)` and returns the `EncryptionKeyProof` containing that ECDH key. When `from_repr` fails — which it does with overwhelming probability for attacker-chosen garbage ciphertext — the function returns early with `blame: Some(...)`, so `batch.verify_with_vartime_blame()` is never reached and the invalid PoP is never detected before the key material is emitted.

The blame proof is intended for public adjudication (see `BlameMachine::blame` / `AdditionalBlameMachine`, and the processor's `VerifyBlame` flow which rebroadcasts blame for verification). Although a blame adjudicator via `decrypt_with_proof` (`encryption.rs:374-379`) would correctly blame the *sender* for the invalid signature, the ECDH key has already been publicly disclosed.

### Impact Explanation

Because the attacker controls the `key` field, this is a static-private-key DH decryption oracle: for any point `P`, the attacker obtains `enc_priv * P` together with a DLEq proof it is legitimately derived. Since all encrypted shares to a victim in a session use the victim's single `enc_key` (`encryption.rs:466` encrypts with `enc_keys[&participant]`), setting `P` to the `key` field of another participant's `EncryptedMessage` yields exactly the ChaCha20 key protecting that participant's `SecretShare` to the victim. The attacker recovers an honest dealer's secret share — secret material the encryption layer exists to protect — while the abort can be attributed (via a distinct invalid-PoP check at adjudication) to make the sender look faulty, or performed by a disposable participant identity. This is a confidentiality breach of DKG key material reachable by any participant feeding bytes to `calculate_share`.

### Likelihood Explanation

Any party holding a DKG participant slot can trigger it deterministically: no honest-party mistakes, races, or privileged access are needed. The only limit is that one leak occurs per attempt (the function returns on first error) and victim encryption keys are regenerated per `KeyMachine`, so disclosure is bounded to one peer's share per aborted session; attackers with multiple slots or repeated attempts can accumulate shares.

### Recommendation

Verify the PoP before revealing decryption material. Concretely, in `Encryption::decrypt`, do not return the `EncryptionKeyProof` along a path where the PoP is unverified — e.g., perform the `from_repr` check only after `batch.verify_with_vartime_blame()` succeeds, or eagerly verify `msg.pop` (non-batched) for messages whose decryption fails scalar deserialization, withholding `blame` (`None`, as with `BatchId::Decryption` failures) when the PoP is invalid. Additionally, binding the intended recipient's encryption key into `pop_challenge` would prevent relaying a message key across recipients.

### Proof of Concept

```rust
// Victim V runs KeyMachine::calculate_share with shares from all participants.
// Attacker E (participant e) crafts, instead of an honest encryption:
let mut malicious = EncryptedMessage::<C, SecretShare<C::F>> {
    // Copy `key` from honest participant B's EncryptedMessage to V (public on the wire)
    key: b_msg_to_v.key,
    // Invalid PoP: E does not know dlog(key), but the PoP is only batch-verified later
    pop: SchnorrSignature::<C> { R: C::generator(), s: C::F::ONE },
    // Garbage ciphertext which will not deserialize to a canonical scalar
    msg: Zeroizing::new(SecretShare([0xff; 32])),
};

// Inside calculate_share:
//   encryption.decrypt(...) queues pop into `batch` (never verified on this path),
//   computes proof.key = ecdh(v.enc_key_priv, b_msg_to_v.key), returns it as `blame`.
//   from_repr(garbage) fails -> returns Err(PedPoPError::InvalidShare {
//       participant: e, blame: Some(proof) }) before batch.verify_with_vartime_blame().

// Once the blame proof is published for adjudication, E reads proof.key and
// decrypts B's real share to V:
let mut plaintext = b_msg_to_v.msg.clone();
cipher::<C>(context, &proof.key).apply_keystream(plaintext.as_mut().as_mut());
// `plaintext` is B's SecretShare evaluated at V's index.
```

The root cause is confirmed by `encryption.rs:479-498` (PoP queued, key returned unconditionally) and `lib.rs:480-482` (early `Err` with `blame: Some` prior to batch verification).
