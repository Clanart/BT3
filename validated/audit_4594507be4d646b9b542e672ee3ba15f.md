### Title
`ReceivedOutput::read` accepts attacker-injected offsets/outputs with no authenticity binding, reporting unspendable or nonexistent funds as received - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to the unauthenticated event-injection flaw in Prefect's `/api/events/in` endpoint, `ReceivedOutput::read` deserializes a claimed spendable output (`offset`, `TxOut`, `OutPoint`) entirely from untrusted bytes with no check that the `offset` actually derives the `script_pubkey` contained in `output`, nor that the `outpoint` exists on-chain. `Scanner::scan_transaction` is the only path that produces a *bound* `ReceivedOutput` (it pairs a matched `script_pubkey` with the registered offset); the deserialization path performs no such binding, so any injected byte stream is accepted as a wallet-owned, spendable output.

### Finding Description
`ReceivedOutput::read` reads three independent fields and returns them without any consistency check: [1](#0-0) 

In contrast, the authentic construction path derives `offset` by looking up `output.script_pubkey` in the scanner's `scripts` map and derives `outpoint` from the containing transaction: [2](#0-1) 

The only downstream consistency check is inside `SignableTransaction::multisig`, which verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` and silently returns `None` on mismatch: [3](#0-2) 

Nothing in `read` or `SignableTransaction::new` rejects an injected output before it is treated as a confirmed receipt. `SignableTransaction::new` sums `input.output.value` directly as available funds: [4](#0-3) 

### Impact Explanation
An unprivileged party that can feed bytes to `ReceivedOutput::read` can inject fabricated "received" outputs: either a real-looking `TxOut`/`OutPoint` that was never paid to the wallet, or a genuine wallet output paired with a wrong `offset`. Consequences within the accepted impact classes:

- Funds reported received that are not spendable: the injected output is counted in `input_sat` and accepted as a valid input by `SignableTransaction::new`, but `multisig()` later returns `None` (offset/script mismatch) or the transaction references a nonexistent UTXO and is unbroadcastable — the wallet has credited balance it cannot spend.
- Signable-transaction DoS: a single injected input poisons the whole `SignableTransaction`, since `multisig` aborts on the first mismatching input, blocking spending of all co-spent genuine inputs.

### Likelihood Explanation
Reachable whenever a `ReceivedOutput` is round-tripped through any medium an attacker can influence (queued messages, stored/relayed serializations) rather than produced directly by `Scanner::scan_transaction`/`scan_block` on locally verified chain data. The fields are trust-presuming: `offset` is a wallet secret-adjacent scalar, yet `read` accepts it verbatim. Likelihood depends on the integrator's transport for serialized outputs, but the missing binding is unconditional — there is no authentication step to fail.

### Recommendation
Make the deserialized representation self-authenticating. Either (a) store only the `OutPoint` and re-derive `offset`/`output` by re-scanning the referenced transaction's output, or (b) have `ReceivedOutput::read`/`SignableTransaction::new` verify `p2tr_script_buf(group_key + GENERATOR * offset) == output.script_pubkey` at ingestion and reject mismatches, moving the check currently buried in `multisig()` to the point where untrusted bytes enter.

### Proof of Concept
```rust
// Construct a fake ReceivedOutput byte stream: a real-looking TxOut paid to
// an unrelated Taproot key, paired with an offset that does NOT derive the
// script_pubkey of the scanner's key.
let fake_offset = Scalar::random(&mut OsRng);
let attacker_key = ProjectivePoint::random(&mut OsRng); // not key + g*fake_offset
let fake_output = TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: p2tr_script_buf(make_even(attacker_key)).unwrap(),
};
let fake_outpoint = OutPoint::new(Txid::all_zeros(), 0);

let mut bytes = fake_offset.to_bytes().as_ref().to_vec();
bytes.extend(serialize(&fake_output));
bytes.extend(serialize(&fake_outpoint));

// Accepted unconditionally — no binding of offset to script_pubkey
let injected = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(injected.value(), 100_000);

// The wallet counts it as available funds
let stx = SignableTransaction::new(vec![injected], &payments, None, None, fee).unwrap();
// …but multisig() returns None / the tx can never be broadcast: funds
// "received" are unspendable.
assert!(stx.multisig(&keys).is_none());
```
