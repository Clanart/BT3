### Title
Attacker-controlled clone/remote host with a `github.` subdomain segment is misclassified as a trusted GitHub Enterprise host, triggering an OAuth-based sign-in flow (and credential-helper prompt) against the attacker's server - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` in `app/src/lib/api.ts` uses a naive hostname regex to decide whether an arbitrary remote host should be treated as a GitHub Enterprise instance. Any hostname containing the literal segment `github.` preceded by the start of string or a dot is unconditionally classified as GitHub, with no ownership/allow-list validation beyond a small hardcoded third-party set (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`).

### Finding Description
`isGitHubHost` is the fallback classifier used by the Git credential-helper trampoline (`app/src/lib/trampoline/trampoline-credential-helper.ts`, `getEndpointKind`) to decide how Desktop should authenticate a remote: [1](#0-0) 

The regex `/(^|\.)(github)\./.test(hostname)` matches any hostname that has `github.` as a full label preceded by either the beginning of the string or a dot — e.g. `push.github.attacker.com` or `github.attacker.com` both match, even though the actual registrable domain is `attacker.com`, fully controlled by a third party unrelated to GitHub. `isKnownThirdPartyHost` only rejects a small hardcoded set of competitor domains and does not help here: [2](#0-1) 

When a user adds/clones a repository whose remote points at such a crafted host, Git invokes the trampoline credential helper. `getEndpointKind` walks through checks (`isGist`, `isDotCom`, `isGHE`, `WWW-Authenticate` header) and, finding no match, falls back to `isGitHubHost`, classifying the attacker's host as `'enterprise'`: [3](#0-2) 

Because no existing account matches that made-up endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`: [4](#0-3) 

`promptForGitHubSignIn` then starts a full **GitHub Enterprise OAuth sign-in flow whose endpoint is the attacker's origin** (not github.com), showing a native Desktop "Sign in" dialog with a credential-helper context: [5](#0-4) 

If the user proceeds (a very plausible action, since Desktop's own UI is asking them to "Sign in to GitHub" in response to what looks like a normal authentication prompt for a repo they just cloned), the OAuth authorization URL and the subsequent access-token exchange are both built from `getHTMLURL(endpoint)`, which for a non-dotcom/non-`.ghe.com` endpoint just echoes back the attacker's hostname: [6](#0-5) 

This means the OAuth `client_id`/`client_secret` and the eventual authorization `code` exchange are sent directly to the attacker-controlled host (`requestOAuthToken` POSTs to `${urlBase}/login/oauth/access_token` where `urlBase` is derived straight from the attacker's hostname). If the user completes the browser-based OAuth handshake believing they're authenticating to a legitimate GitHub Enterprise deployment, the resulting access token returned by the attacker's fake OAuth endpoint (or a token obtained via a convincing phishing page at that host) gets stored as a Desktop `Account` and is thereafter available for API calls and credential fills scoped to that same origin — effectively binding a spoofed/malicious "enterprise" endpoint into Desktop's trusted account store.

### Impact Explanation
An attacker only needs to get the victim to add or clone a repository whose remote URL/hostname contains a `github.`-labeled subdomain under a domain they control (e.g. `code.github.acme-corp.com`, entirely attacker-owned `acme-corp.com`). This is a repository/remote the attacker fully controls, matching the "attacker controls a git remote" primitive. The result is:
- Desktop's own UI initiates an OAuth "sign in to GitHub Enterprise" flow scoped to the attacker's host, and the OAuth client secret is transmitted to that host.
- A user who completes the flow ends up with a bogus/attacker-served "enterprise account" persisted in Desktop's account store, tied to the attacker's origin, which can subsequently be used to phish real personal access tokens or intercept credentials Desktop later reuses for that host.
- This corrupts a security-relevant invariant (which hosts Desktop treats as "GitHub") based purely on unprivileged, attacker-supplied remote URL content, with no user warning that the domain is not affiliated with GitHub.

### Likelihood Explanation
Likelihood is moderate-to-high: crafting a hostname like `github.<anything>.com` or `<anything>.github.<attacker-domain>.com` requires only DNS control an attacker already has over their own domain, and the flow is reached automatically by cloning/opening a repo with such a remote and hitting a normal Git authentication prompt — no unusual steps, no local access, no pre-existing malware. The only user action required is completing a sign-in dialog that Desktop itself surfaces, which is expected app behavior for enterprise repos and not implausible for a user to trust.

### Recommendation
Do not use a substring/regex heuristic on hostnames to decide GitHub Enterprise trust. Require an explicit user-registered allow-list of GHE endpoints, or perform genuine verification (e.g., requiring a successful `/meta` check with `x-github-request-id` and valid TLS before the regex short-circuit even applies, not as a last resort after the pattern match), and never let the pattern-based branch (`/(^|\.)(github)\./`) return `true` without further verification. At minimum, the OAuth sign-in flow triggered by the credential helper should surface the literal origin being authenticated against prominently and never auto-elevate a heuristically-matched host to "enterprise" class before verification succeeds.

### Proof of Concept
1. Attacker registers `attacker.com` and stands up a git server (or GitHub Pages proxy) at `push.github.attacker.com`, along with a fake `/login/oauth/authorize` and `/login/oauth/access_token` page mimicking GitHub Enterprise's OAuth UI.
2. Victim clones `https://push.github.attacker.com/foo/bar.git` in GitHub Desktop (e.g., pasted from a link/README/deep link).
3. Git requests credentials; Desktop's trampoline credential helper (`getEndpointKind`) has no account, no matching `WWW-Authenticate` header, protocol is `https:`, so it calls `isGitHubHost('https://push.github.attacker.com')`.
4. The regex `/(^|\.)(github)\./` matches `push.github.attacker.com` (since `.github.` appears preceded by a dot), so the function returns `true` without contacting the real GitHub API. `getEndpointKind` returns `'enterprise'`.
5. `getCredential` finds no account for this endpoint and calls `ui.promptForGitHubSignIn('https://push.github.attacker.com/...')`, which calls `dispatcher.beginEnterpriseSignIn` + `setSignInEndpoint(origin)` and shows the "Sign in to GitHub Enterprise" popup.
6. If the victim proceeds, `getOAuthAuthorizationURL`/`requestOAuthToken` (`app/src/lib/api.ts:2357-2395`) build all OAuth URLs from `push.github.attacker.com`, sending the OAuth client secret to the attacker and allowing the attacker's fake OAuth server to hand back an arbitrary token, which Desktop stores as a legitimate `Account` tied to that malicious origin.   endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)

      null,
      'POST',

      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )

    return result.access_token

    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
