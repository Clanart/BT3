### Title
`RecoverPolynomialCoefficients` silently truncates a degree ≥ `numScalarsInDataWord` (4096) recovered polynomial instead of rejecting it, breaking the `recovered[cellIDs[i]] == cells[i]` invariant - (File: `internal/erasure_code/erasure_code.go`)

### Summary
`Context.RecoverCellsAndComputeKZGProofs` -> `recoverPolynomialCoeffs` -> `DataRecovery.RecoverPolynomialCoefficients` treats every supplied cell value as ground truth and zero-fills only the cells that were *not* supplied. When an attacker supplies **more** cells than the minimum `NumBlocksNeededToReconstruct()`, the erasure-decoder's vanishing polynomial `Z(x)` has degree strictly less than `numScalarsInCodeword - numScalarsInDataWord`, so the true quotient `Q(x) = D(x)/Z(x)` can legitimately have nonzero coefficients at index ≥ `numScalarsInDataWord` (e.g. index 4096) if the "extra" cells are not evaluations of any degree < 4096 polynomial. The code unconditionally truncates with `cosetQuotientEval[:dr.numScalarsInDataWord]` [1](#0-0) , discarding those high-order terms without ever checking they are zero, and without re-checking that recomputing cells/proofs from the truncated polynomial reproduces the attacker's originally supplied `cells[i]`.

### Finding Description
The invariant under test is: for every index `i`, `recovered[cellIDs[i]] == cells[i]`, and the recovered polynomial has degree `< ScalarsPerBlob` (4096), else the call must return an error.

Trace of the reachable path:
1. `Context.RecoverCellsAndComputeKZGProofs(cellIDs, cells, ...)` calls `ctx.recoverPolynomialCoeffs(cellIDs, cells)` [2](#0-1) .
2. `recoverPolynomialCoeffs` only validates ordering, cell-ID bounds, and a **minimum** count (`len(cellIDs) < ctx.dataRecovery.NumBlocksNeededToReconstruct()`) [3](#0-2) . It places every attacker-supplied cell value verbatim into `extendedBlob` at its `cellID` position and leaves all *other* positions as zero, then computes `missingCellIds` as exactly the complement of the supplied `cellIDs` set [4](#0-3) . Nothing prevents the attacker from supplying **more** cells than the minimum required, which shrinks the "missing" set below its minimum size.
3. Inside `RecoverPolynomialCoefficients`, the vanishing polynomial `Z(x)` is built solely from the (now smaller) missing set [5](#0-4) , giving `deg(Z) < numScalarsInCodeword - numScalarsInDataWord`. Because `D(x)` is only guaranteed to vanish at the *actual* roots of `Z(x)` (the missing positions), the quotient `Q(x)=D(x)/Z(x)` is only guaranteed to have `deg(Q) ≤ (numScalarsInCodeword-1) - deg(Z)`, which can now exceed `numScalarsInDataWord-1` when the attacker's "extra" present-cell values are not evaluations of any true low-degree polynomial.
4. The function truncates to `polyCoeff := cosetQuotientEval[:dr.numScalarsInDataWord]` with no check that `cosetQuotientEval[dr.numScalarsInDataWord:]` is all-zero [1](#0-0) .
5. `RecoverCellsAndComputeKZGProofs` then re-derives `recoveredCells`/`proofs` from this truncated `polyCoeff` and returns them directly, with **no post-check** that `recoveredCells[cellIDs[i]] == cells[i]` for the caller-supplied cells [6](#0-5) .

None of the existing guards (`isAscending`, cell-ID bound check, `NumBlocksNeededToReconstruct` minimum-count check) catch an *over-supplied*, internally-inconsistent batch; they only guard against too few cells or malformed indices, not against excess/inconsistent redundant cells whose recovered polynomial exceeds degree 4095.

### Impact Explanation
An attacker can construct a `cells`/`cellIDs` batch (using more than the minimum number of required cells) that go-eth-kzg accepts and turns into a `recoveredCells`/`proofs` output, even though the recovered polynomial has degree ≥ `ScalarsPerBlob` and therefore is not a valid blob polynomial. Reference implementations (c-kzg / consensus-specs) that check consistency or a strict recovered-cell-equals-original invariant would either reject such input or emit different `recoveredCells`/proofs — producing a client/consensus split (High severity: "library and c-kzg disagree on accept or on emitted... recovered data for the same input"). This is repeatable per call and requires no privileged access — it's exercised entirely through the public `RecoverCellsAndComputeKZGProofs` API with attacker-authored cell bytes.

### Likelihood Explanation
Preconditions: the attacker must submit a batch with more cells than `NumBlocksNeededToReconstruct()` (i.e., an over-determined/redundant reconstruction request), where the extra cells are deliberately crafted to be inconsistent with any degree<4096 polynomial that fits the other cells. Constructing such values requires only linear algebra over the known field domain (no cryptographic secret needed) and is fully within an ordinary user's capability since cell contents are entirely caller-controlled. The attack is repeatable on every call and costs nothing beyond crafting field elements.

### Recommendation
After computing `cosetQuotientEval`, either (a) verify all coefficients at index ≥ `numScalarsInDataWord` are zero before truncating, returning an error otherwise, or (b) after computing `polyCoeff`, re-evaluate it at each supplied `cellIDs[i]` and assert the result equals the caller's supplied `cells[i]`, returning an error on mismatch — matching the invariant that recovered data must reproduce the input exactly and lie on a polynomial of degree `< ScalarsPerBlob`.

    require.NoError(t, err)

    // ASSERT (currently fails to be checked by the library):
    // recovered polynomial must have degree < ScalarsPerBlob
    fullCoeffs := cosetQuotientEvalUnTruncated // capture before truncation for the test
    for i := numScalarsInDataWord; i < len(fullCoeffs); i++ {
        require.True(t, fullCoeffs[i].IsZero(), "coefficient %d must be zero", i)
    }

func (ctx *Context) recoverPolynomialCoeffs(cellIDs []uint64, cells []*Cell) ([]fr.Element, error) {
	if len(cellIDs) != len(cells) {
		return nil, ErrNumCellIDsNotEqualNumCells
	}

	// Check that the cell Ids are ordered (ascending)
	if !isAscending(cellIDs) {
		return nil, ErrCellIDsNotOrdered
	}

	// Check that each CellId is less than CellsPerExtBlob
	for _, cellID := range cellIDs {
		if cellID >= CellsPerExtBlob {
			return nil, ErrFoundInvalidCellID
		}
	}

	// Check that we have enough cells to perform reconstruction
	if len(cellIDs) < ctx.dataRecovery.NumBlocksNeededToReconstruct() {
		return nil, ErrNotEnoughCellsForReconstruction
	}

func (ctx *Context) RecoverCellsAndComputeKZGProofs(cellIDs []uint64, cells []*Cell, numGoRoutines int) ([CellsPerExtBlob]*Cell, [CellsPerExtBlob]KZGProof, error) {
	polyCoeff, err := ctx.recoverPolynomialCoeffs(cellIDs, cells)
	if err != nil {
		return [CellsPerExtBlob]*Cell{}, [CellsPerExtBlob]KZGProof{}, err
	}

	recoveredCells, err := ctx.computeCellsFromPolyCoeff(polyCoeff, numGoRoutines)
	if err != nil {
		return [CellsPerExtBlob]*Cell{}, [CellsPerExtBlob]KZGProof{}, err
	}

	proofs, err := ctx.computeKZGProofsFromPolyCoeff(polyCoeff, numGoRoutines)
	if err != nil {
		return [CellsPerExtBlob]*Cell{}, [CellsPerExtBlob]KZGProof{}, err
	}

	return recoveredCells, proofs, nil
}
