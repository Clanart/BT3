## Title
Trust exception is granted for a path different from the one the user reviewed, silently expanding `safe.directory` scope - (File: `app/src/lib/git/rev-parse.ts`, `app/src/ui/add-repository/add-existing-repository.tsx`, `app/src/lib/git/config.ts`)

### Summary
The audit finding is about a restriction (`restriction = NONE`) whose lifecycle/state transitions are undocumented and unverifiable, so a "cleared" restriction cannot reliably be re-applied. The closest verified analog in GitHub Desktop is the *unsafe-repository trust* restriction: Desktop detects a Git "dubious ownership" restriction, but the path it *asks the user to trust* is not guaranteed to be the same path the user *believes* they are trusting, and once trust is granted via `addSafeDirectory`, it is written to the **global** `~/.gitconfig` `safe.directory` list with no corresponding UI to scope, audit, or revoke it from inside Desktop.

### Finding Description
`getRepositoryType` executes `git rev-parse --is-bare-repository --show-cdup --git-dir` in the target `path`, and on failure parses `stderr` with a regex to recover the "unsafe" path Git reported: [1](#0-0) 

That regex-captured `unsafeMatch[1]` — not the path the user typed or selected — is what's stored as `repositoryUnsafePath` / `unsafePath` and shown in the UI: [2](#0-1) 

The component itself acknowledges these two values can diverge, since it conditionally renders the reported path only `{repositoryUnsafePath !== convertedPath && ...}`: [3](#0-2) 

When the user clicks "add an exception for this directory", Desktop calls `addSafeDirectory(repositoryUnsafePath)` — the value derived from Git's own error text, not the vetted input path — which appends it (unscoped, non-repo-specific) to the **global** git config: [4](#0-3) [5](#0-4) 

The same pattern exists in `MissingRepository`, triggered automatically when Desktop revisits a previously known repository path: [6](#0-5) 

Because a cloned/fetched repository can contain a `.git` file (gitlink) that redirects `--git-dir` to an arbitrary absolute location (worktrees, submodules), or can be nested/relocated such that Git's dubious-ownership check reports a directory that is not the one the user opened, the path that gets trusted can differ from the path the user visually confirmed in the dialog. There is no corresponding "untrust"/"remove exception" flow anywhere in the codebase — `addGlobalConfigValueIfMissing`/`addSafeDirectory` is the only mutator found — so once an entry is added to `safe.directory`, Desktop has no in-app mechanism to reset or scope it back down, mirroring the "restriction cannot be set/reset correctly" defect class from the report (a global config write with no documented reverse transition).

### Impact Explanation
`safe.directory` is a machine-wide Git ownership override, not scoped to the single repository the user opened. If an attacker controls the content or layout of a cloned/fetched repository such that Git reports a different, attacker-influenced directory as "dubious," a user who trusts what they believe is *this repository* is actually granting a persistent, global exception for a directory they never intended to trust. That silently disables Git's ownership protection for that other path for all future Git operations on the machine, which is exactly the protection dubious-ownership checks exist to enforce (protection against arbitrary hook/config execution from directories with different/unexpected ownership).

### Likelihood Explanation
Requires the victim to click through the "Trust Repository" prompt after opening/locating/re-adding a malicious repository — a normal, in-band interaction Desktop explicitly invites via this UI, not social engineering outside the app. The divergence between displayed/confirmed path and actually-trusted path is already visible in the component's own conditional rendering logic, indicating the code authors were aware paths can differ but did not add a hard warning or block when the mismatch occurs.

### Recommendation
- Do not trust `unsafeMatch[1]` parsed from Git stderr as the value passed to `addSafeDirectory`; instead, block the trust action (or force a distinct, explicit confirmation showing the exact resolved directory) whenever `repositoryUnsafePath !== convertedPath`.
- Scope `safe.directory` entries as tightly as Git allows and document the state machine for how a repository moves between `unsafe` → trusted → (optionally) untrusted.
- Add an in-app "remove trust exception" action so a mistakenly granted `safe.directory` entry can be reverted without manually editing `~/.gitconfig`.

### Proof of Concept
1. Attacker crafts a repository containing a `.git` file (gitlink) whose `gitdir:` value is an absolute path to a directory with different ownership than the current user context (achievable in shared/CI-like environments, or via a nested worktree layout).
2. Victim clones/opens this repository in GitHub Desktop; `getRepositoryType` runs `git rev-parse` in the repo path, Git detects dubious ownership on the *redirected* gitdir path and reports that path in `stderr`.
3. Desktop's `AddExistingRepository`/`MissingRepository` UI surfaces "The Git repository ... appears to be owned by another user," showing `repositoryUnsafePath` (the attacker-influenced gitdir path), which can render identically or ambiguously to the user versus the folder they selected.
4. Victim clicks "add an exception for this directory," triggering `addSafeDirectory(repositoryUnsafePath)`, which writes that path into the global `safe.directory` list [7](#0-6) .
5. Git's ownership protection is now permanently disabled for that path for every future Git invocation on the machine, with no in-app way to reverse it.

Note: I could not fully trace, within the indexing limits of this scan, the exact conditions under which Git's dubious-ownership stderr path diverges from the opened path (e.g., precise worktree/submodule redirection scenarios) beyond what the code comments/tests confirm is possible; a Devin session with full repository/test access would be needed to construct and verify an exact reproducible PoC path mismatch.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```
