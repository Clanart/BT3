## Title
Consensus-incentives reward for pending block-span is retroactively priced at the new `cost_per_block` after a rate change — ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` pays relayers (from the treasury) for delivering `ConsensusMessage`s, with reward = `(latest_height - baseline) * cost_per_block`, where `baseline` is a persisted watermark (`LastRewardedHeight`) rather than the height at the time the rate was last changed. Because the rate lookup always uses the *current* `StateMachinesCostPerBlock` value at call time, any unclaimed block-span accrued under an old (lower) rate is paid out entirely at the newest rate the moment it is next processed — the exact "change fee, then cash out the whole backlog at the new rate" pattern from the referenced Popcorn `Vault.feesUpdatedAt` bug.

### Finding Description
The reward calculation is: [1](#0-0) 

`calculate_reward` reads `block_cost` as the **current** value of `StateMachinesCostPerBlock` and multiplies it by the entire span `latest_height - baseline`, where `baseline` comes from the persisted `LastRewardedHeight` watermark (or `previous_commitment_height` if none exists yet): [2](#0-1) 

`update_cost_per_block` mutates `StateMachinesCostPerBlock` for a state machine at any time, with no interaction with `LastRewardedHeight` and no forced settlement of the pending span at the old rate before the change takes effect: [3](#0-2) 

This mirrors the reported Vault bug precisely: `feesUpdatedAt`/`LastRewardedHeight` is the "last settled" marker, and the rate (`managementFee`/`cost_per_block`) is looked up fresh at claim time rather than being locked in per elapsed sub-period. If the backlog (`latest_height - baseline`) spans a period during which the rate was low (or zero, if the state machine had no configured cost previously) and is then raised, the very next `on_executed` call — triggered by any relayer simply delivering the next `ConsensusMessage`, an entirely normal, unprivileged action — pays out the **entire backlog** at the new, higher rate.

### Impact Explanation
This is a direct loss of treasury funds: `T::Currency::transfer` moves the inflated reward from `TreasuryAccount` to the relayer, and `ReputationAsset::mint_into` mints a matching reputation credit, based on an amount that was never actually earned at the rates that were in effect during most of the backlog period: [4](#0-3) 

Any relayer who is aware of an imminent (or just-executed) rate increase can intentionally delay delivering consensus messages to let the un-rewarded span (`latest_height - baseline`) grow, then deliver right after the rate bump to collect a reward computed over the whole backlog at the new, higher price — draining more from the treasury than the protocol intended to pay for those already-delivered/older blocks.

### Likelihood Explanation
Rate changes via `update_cost_per_block` are a normal, expected operational action (adjusting incentive economics), not a compromise. The exploitation step — calling/triggering `on_executed` via delivering the next `ConsensusMessage` — requires no privilege at all; it is the routine action every relayer performs. Any relayer that notices (or causes, by withholding delivery) a backlog spanning a rate change can capture the mispriced reward. No malicious admin, prover, or peer is required — only the combination of a legitimate rate update and normal unprivileged message delivery.

### Recommendation
Settle (or checkpoint) the pending reward at the old rate before applying a new `cost_per_block`, or split the reward calculation into rate-effective sub-periods (e.g., by storing `(height, rate)` history and integrating the reward across rate boundaries), rather than applying the single current rate to the full `latest_height - baseline` span. Equivalently, force `LastRewardedHeight` to be advanced to the current `latest_commitment_height` for the affected state machine as part of `update_cost_per_block`'s effect, so no un-settled span is ever billed at a rate that wasn't in effect for it.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, X)` — a low rate, or the state machine has no configured cost yet (`StateMachinesCostPerBlock` is `None`, so no rewards accrue while a large `latest_height - previous_height` backlog silently builds).
2. Time passes; the remote chain's `latest_commitment_height` advances significantly while `LastRewardedHeight` is unset/stale, i.e. the backlog `latest_height - baseline` grows large.
3. Governance calls `update_cost_per_block(state_machine_id, Y)` with `Y >> X` (or sets a nonzero rate for the first time).
4. Any relayer submits the next `ConsensusMessage` for that state machine, invoking `FeeHandler::on_executed` → `process_message` → `calculate_reward`.
5. `calculate_reward` computes `reward = (latest_height - baseline) * Y`, paying the relayer for the *entire* backlog — including all blocks that elapsed while the rate was `X` or unset — at the new higher rate `Y`, draining the treasury by the difference `(latest_height - baseline) * (Y - X)`.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
