### Title
Missing non-payable fallback / stray-BNB recovery in `WombatStaking` permanently locks accidentally sent native BNB - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking` implements an unconditional `receive() external payable {}` function that accepts any native BNB sent to the contract, but the contract contains no function anywhere that can withdraw or sweep native BNB back out. Any ordinary wallet that mistakenly sends BNB directly to the `WombatStaking` contract address (e.g. by copy-pasting the contract address into a wallet "send" screen, a common user error the original report specifically warns about) will have those funds permanently and irrecoverably locked in the contract.

### Finding Description
`WombatStaking` defines a bare `receive()` function with no logic, no logging, and no restriction: [1](#0-0) 

This function is the only path by which the contract handles plain native-token transfers. Reviewing the entire contract, all native BNB usage is one-directional: BNB rewards harvested from bribes are wrapped into `wbnb` via `Address.sendValue(payable(wbnb), rewardAmount)`, and every other function operates strictly on ERC20 tokens (`IERC20(...).safeTransfer`/`safeTransferFrom`) using `SafeERC20`: [2](#0-1) 

There is no `withdraw`, `sweep`, `recoverToken`, or any owner-only function in the contract that references `address(this).balance` or otherwise moves native BNB out of the contract. All admin functions (`setMWom`, `setLockDays`, `removePool`, `updatePoolHelper`, `setMasterMagpie`, `setMasterWombat`, `setBribeManager`, `setSmartConvert`, `pause`/`unpause`, `addFee`/`setFee`/`removeFee`, `addBonusRewardForAsset`, `setPoolRewardFeeFree`, `setBribe`) only mutate storage variables and never touch `address(this).balance`: [3](#0-2) 

Because the `receive()` function silently accepts value with no bookkeeping, no event, and no exit path, any BNB sent to this address by an ordinary, unprivileged wallet (not through the intended `depositNative` flow of the pool helpers, which wraps BNB into WBNB before forwarding it) is captured by the contract with absolutely no mechanism, privileged or otherwise, to retrieve it.

### Impact Explanation
Any native BNB accidentally or mistakenly sent directly to the `WombatStaking` contract address is permanently and irreversibly frozen, since no function in the codebase can move native BNB out of `WombatStaking`. This satisfies the "permanent freezing of funds" impact bar: the locked value is unrecoverable by the sender or by the protocol owner, for as long as the contract exists.

### Likelihood Explanation
`WombatStaking` is a core, publicly documented, actively used contract address in the protocol (referenced by all `WombatPoolHelperV2`/`AnkrBNBPoolHelper` instances as `wombatStaking`), making it a plausible target for wallet mistakes (e.g., sending BNB to the wrong/contract address, a well-known and common on-chain user error). No privileged role or special conditions are required — any ordinary wallet triggering a plain value transfer to the contract address is sufficient to trigger the bug.

### Recommendation
Replace the empty `receive() external payable {}` with a non-payable fallback (removing the payable `receive()`/`fallback()` altogether unless native BNB receipt is truly required), or, if native BNB must be receivable (e.g., for the bribe-harvest flow that uses `Address.sendValue`), add an owner-restricted `sweepNative`/`recoverBNB` function with `address(this).balance` checks and events so mistakenly sent BNB can be recovered and returned to affected users.

### Proof of Concept
1. An ordinary wallet sends BNB directly to the deployed `WombatStaking` proxy address (e.g., via a wallet UI "send" transaction, not through `depositNative` on a pool helper).
2. The transaction succeeds silently via `receive() external payable {}` at `wombat/WombatStaking.sol:202`, with no event emitted and no state change recorded.
3. Inspecting the contract, there is no function (owner or otherwise) that references `address(this).balance` or performs a native value transfer out of the contract — confirmed across all external/admin functions in `wombat/WombatStaking.sol`.
4. The sent BNB is permanently stuck in the contract with no possible recovery path.

    /// @param _value the initial value for that fee
    /// @param _to the address or contract that receives the fee
    /// @param isMWOM true if the fee is sent as MWOM, otherwise it will be WOM
    /// @param _isAddress true if the receiver is an address, otherwise it's a BaseRewarder
    function addFee(
        uint256 _value,
        address _to,
        bool isMWOM,
        bool _isAddress
    ) external onlyOwner {
        if (_value >= DENOMINATOR)
            revert InvalidFee();

        feeInfos.push(
            Fees({
                value: _value,
                to: _to,
                isMWOM: isMWOM,
                isAddress: _isAddress,
                isActive: true
            })
        );
        totalFee += _value;

        emit AddFee(_to, _value, isMWOM, _isAddress);
    }

    /// @notice change the value of some fee
    /// @dev the value must be between the min and the max specified when registering the fee
    /// @dev the value must match the max fee requirements
    /// @param _index the index of the fee in the fee list
    /// @param _value the new value of the fee
    function setFee(uint256 _index, uint256 _value, address _to,
        bool _isMWOM, bool _isAddress, bool _isActive) external onlyOwner {
        if (_value >= DENOMINATOR)
            revert InvalidFee();        

        Fees storage fee = feeInfos[_index];
        fee.to = _to;
        fee.isMWOM = _isMWOM;
        fee.isAddress = _isAddress;
        fee.isActive = _isActive;

        totalFee = totalFee - fee.value + _value;
        fee.value = _value;

        emit SetFee(fee.to, _value);
    }

    /// @notice remove some fee
    /// @param _index the index of the fee in the fee list
    function removeFee(uint256 _index) external onlyOwner {
        Fees memory feeToRemove = feeInfos[_index];

        for (uint i = _index; i < feeInfos.length - 1; i++) {
           feeInfos[i] = feeInfos[i+1];
        }
        feeInfos.pop();
        totalFee -= feeToRemove.value;

        emit RemoveFee(feeToRemove.value, feeToRemove.to, feeToRemove.isMWOM, feeToRemove.isAddress);
    }
