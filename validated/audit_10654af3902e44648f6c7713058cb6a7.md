### Title
Native ERC20 pointer's `decimals`/`name`/`symbol` can be silently changed in-place after creation via a permissionless `addNativePointer` call - ([File: x/evm/keeper/pointer_upgrade.go])

### Summary
The `pointer` precompile's `addNativePointer` method is callable by any account with no privilege check, and re-invoking it against an already-registered token redeploys the same pointer contract address with whatever `name`/`symbol`/`decimals` the bank module's current `DenomMetaData` holds at call time. Because bank denom metadata for tokenfactory denoms can be updated post-creation by the denom's admin (`MsgSetDenomMetadata`), and for `usei` via governance, the ERC20 metadata backing the pointer is not immutable, and any unprivileged caller can trigger the update by simply calling `addNativePointer` again.

### Finding Description
`PrecompileExecutor.AddNative` reads the current `DenomMetaData` for the token and passes `Name`, `Symbol`, and `Decimals` into `UpsertERCNativePointer`: [1](#0-0) 

`UpsertERCPointer` looks up whether a pointer already exists for the token; if it does, instead of reverting, it redeploys the runtime bytecode in place at the same contract address, baking in the (possibly changed) constructor arguments: [2](#0-1) 

There is no check that the currently deployed pointer's metadata matches what is being written, nor any restriction on who may call `addNativePointer` — any account can invoke it (subject only to `ValidateNonPayable`/`ValidateArgsLength`). The underlying bank `DenomMetaData` is not immutable: the tokenfactory admin can update it at any time via `MsgSetDenomMetadata`, which only checks that the caller is the current denom admin, with no restriction preventing changing `decimals` after the pointer/token has already been in circulating use: [3](#0-2) 

A dedicated test (`TestUpsertERCNativePointer`) confirms that calling `UpsertERCNativePointer` twice for the same denom with different `Decimals` (6 → 12) keeps the same pointer contract address but changes its reported `decimals()`, `name()`, and `symbol()`: [4](#0-3) 

This is directly analogous to the reported issue: a value critical to how a token is interpreted (there: NFT `baseURI`; here: ERC20 `decimals`/`name`/`symbol`) can be changed after the token has already been distributed/integrated, without consent of holders, and the change is exposed on-chain to any consumer without restriction on when or how many times it may be updated.

### Impact Explanation
ERC20 `decimals` is assumed immutable by essentially all downstream consumers (wallets, DEX routers/AMM pools, price oracles, other smart contracts) that cache or read it once at integration time to convert the raw integer balance into a human/economic value. If a tokenfactory denom's admin updates its `DenomMetaData` decimals (e.g., 6 → 18) after the pointer and any integrations already exist, and then any unprivileged account calls `addNativePointer` again, the pointer contract's `decimals()` changes in place at the same address. Any contract or off-chain system that computed value using the old decimals will now misinterpret balances by orders of magnitude, which can be exploited for fund-loss scenarios (e.g., mispriced swaps/liquidations in integrations that read `decimals()` dynamically at different times, or a stale/cached-decimals contract now transacting against a live pointer with different decimals).

### Likelihood Explanation
Reaching this requires the tokenfactory denom admin (a legitimate but non-Sei-core-team party, not a "malicious node/validator") to update `DenomMetaData` — this is a normal, permitted admin action. The permissionless part — any address calling `addNativePointer` to force the redeploy/propagation of the new metadata into the already-deployed pointer contract — requires no special privilege at all. No safeguard exists preventing the decimals of an already-active pointer from being altered.

### Recommendation
Restrict `UpsertERCPointer`/`AddNative` so that once a pointer contract has been deployed for a given token, subsequent calls cannot silently change immutable ERC20 metadata (`decimals` in particular, and ideally `name`/`symbol`) in place. Either:
- Disallow redeploying an existing pointer's metadata when core fields like `decimals` differ from what is already deployed (require a new pointer address / explicit versioned migration instead), or
- Restrict `MsgSetDenomMetadata` to disallow changing an already-set `decimals`/exponent for a denom, once a pointer exists.

### Proof of Concept
1. Create a tokenfactory denom and set metadata with 6 decimals; anyone calls `addNativePointer(token)` to create the ERC20 pointer (decimals=6 baked into the pointer contract), and this pointer becomes integrated into a DEX/pool computing amounts with 6 decimals.
2. The denom admin calls `MsgSetDenomMetadata` to change the exponent/decimals to, e.g., 18 — this passes validation because there is no restriction preventing a decimals change post-issuance ( [5](#0-4) ).
3. Any unprivileged account calls `addNativePointer(token)` again; `UpsertERCPointer` sees `exists=true` and redeploys the same contract address's bytecode using the new decimals ( [6](#0-5) ).
4. `decimals()` on the pointer now returns 18 instead of 6 at the same address, exactly as reproduced by `TestUpsertERCNativePointer` ( [7](#0-6) ), silently breaking any downstream logic relying on the originally observed decimals value.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
}

func TestUpsertERCNativePointer(t *testing.T) {
	k := &testkeeper.EVMTestApp.EvmKeeper
	ctx := testkeeper.EVMTestApp.GetContextForDeliverTx([]byte{}).WithBlockTime(time.Now())
	ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
	var addr common.Address
	err := k.RunWithOneOffEVMInstance(ctx, func(e *vm.EVM) error {
		a, err := k.UpsertERCNativePointer(ctx, e, "test", utils.ERCMetadata{
			Name:     "test",
			Symbol:   "test",
			Decimals: 6,
		})
		addr = a
		return err
	}, func(s1, s2 string) {})
	require.Nil(t, err)
	var newAddr common.Address
	err = k.RunWithOneOffEVMInstance(ctx, func(e *vm.EVM) error {
		a, err := k.UpsertERCNativePointer(ctx, e, "test", utils.ERCMetadata{
			Name:     "test2",
			Symbol:   "test2",
			Decimals: 12,
		})
		newAddr = a
		return err
	}, func(s1, s2 string) {})
	require.Nil(t, err)
	require.Equal(t, addr, newAddr)
	res, err := k.QueryERCSingleOutput(ctx, "native", addr, "name")
	require.Nil(t, err)
	require.Equal(t, "test2", res.(string))
	res, err = k.QueryERCSingleOutput(ctx, "native", addr, "symbol")
	require.Nil(t, err)
	require.Equal(t, "test2", res.(string))
	res, err = k.QueryERCSingleOutput(ctx, "native", addr, "decimals")
	require.Nil(t, err)
	require.Equal(t, uint8(12), res.(uint8))
	_, err = k.QueryERCSingleOutput(ctx, "native", addr, "nonexist")
	require.NotNil(t, err)
}
