### Title
Gasless swap lend/repay is not atomic against AMM slippage between mempool admission and in-block execution, allowing users to keep lent gas funds without repaying the proposer - (File: kaiax/gasless/impl/tx_pool.go, kaiax/gasless/impl/builder.go)

### Summary
The `kaiax/gasless` module implements KIP-247 gasless transactions: a block proposer lends KAIA to a gas-less user via a `LendTxGenerator`-produced transaction, and the user is expected to repay that lend by swapping ERC20 tokens for KAIA through `GaslessSwapRouter.swapForGas`. The only place the module verifies that the swap can actually produce enough output to satisfy `minAmountOut`/`amountRepay` is `checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go`, which is run once at tx-pool admission time against the current chain state via `routerContract.GetAmountIn(nil, token, minAmountOut)`. [1](#0-0) 

This is directly analogous to the reported Ubiquity bug: a solvency/settlement guarantee is checked against a price/reserve snapshot that can become stale, and the last party to settle can be left unable to cover the obligation.

### Finding Description
`ExtractTxBundles` in `kaiax/gasless/impl/builder.go` builds the on-chain execution bundle `[LendTxGenerator, ApproveTx?, SwapTx]` for inclusion in the block, calling only `IsExecutable`/`VerifyExecutable`, which checks nonce ordering, token/sender consistency, and that `AmountRepay` equals the statically-computed `repayAmount()` (a function purely of gas price and gas limits, see `getter.go` `repayAmount`/`lendAmount`). Crucially, `VerifyExecutable` does **not** re-check AMM reserves/slippage (`GetAmountIn`) at bundle-extraction/block-building time. [2](#0-1) [3](#0-2) [4](#0-3) 

The only slippage/solvency-relevant check, `checkBalanceForSwap`, runs solely inside `GetCheckBalance()`, which is invoked by the tx pool's `validateTx` at admission time (`blockchain/tx_pool.go` lines 918-932), against whatever state is current at that moment (`g.currentState`/`g.Chain`). Once a `GaslessSwapTx` is admitted to the pool, it can sit there and be included in a later block, or be included after other transactions (including other gasless bundles or unrelated swaps against the same liquidity pool) have already executed earlier in the same block and moved the pool's reserves. Nothing re-validates that `AmountIn` is still sufficient to produce `MinAmountOut` at the moment the bundle is actually executed. [5](#0-4) [6](#0-5) 

Meanwhile, the `LendTxGenerator`-produced transaction unconditionally transfers `lendAmount(approveTxOrNil, swapTx)` KAIA (covering both the ApproveTx's and SwapTx's gas fees) from the proposer to the user's account as a plain value-transfer transaction that precedes the `SwapTx` in the bundle. This lend transaction is a separate, already-finalized transaction; it is not rolled back if the subsequent `SwapTx` reverts. If the on-chain AMM has moved such that `swapForGas`'s internal output check against `minAmountOut` fails (because the actual reserves at execution time differ from the reserves used for the mempool-time `GetAmountIn` check), `SwapTx` reverts. On revert, all of the swap's internal token transfers and the repayment to the proposer are rolled back, but the KAIA the user already received via `LendTxGenerator` is not returned, and the user's account (now funded with the lent KAIA) simply pays the reverted swap's own gas cost, keeping the remainder.

### Impact Explanation
This breaks the fundamental economic invariant of the gasless module described in its own README: "user repays the lent amount during gasless swap." Because the AMM-sufficiency check is a stale, admission-time-only check (analogous to relying on a Chainlink price snapshot that can move before redemption), an adversarial user (or one who benefits from ordinary market/AMM price movement between mempool admission and in-block execution) can end up with a `SwapTx` that reverts on-chain due to insufficient `minAmountOut`, while retaining the KAIA lent by the block proposer. This is a direct, unauthorized value transfer from the block proposer (playing the role of lender/pool) to the transaction sender — the same class of "no guarantee of solvency" issue as the original report, translated to Kaia's gasless settlement path. This is reachable by any unprivileged transaction sender through ordinary `GaslessApproveTx`/`GaslessSwapTx` submission, requiring no special privileges.

### Likelihood Explanation
Likelihood is Medium: it requires (a) the AMM pool reserves for the whitelisted token to shift between the time the gasless swap tx is admitted to the pool and the time it is actually executed in a block (achievable by submitting/witnessing other swaps against the same pool, or by intentionally delaying inclusion via low gas price so that natural market activity shifts price), and (b) the `SwapTx`'s own gas cost consumed on revert to be less than the total `lendAmount` the user received. Because gasless swap pools are typically low-liquidity, purpose-built pools (as seen in `tests/gasless_test.go`'s dedicated Uniswap-V2-style setup), triggering meaningful slippage with a modest counter-trade is realistic and cheap for a motivated user, especially across multiple attempts as the check only needs to be stale once per successful exploit.

### Recommendation
Re-validate the AMM sufficiency/slippage condition (`AmountIn >= GetAmountIn(token, MinAmountOut)`) against the state immediately preceding execution at block-building time (inside `ExtractTxBundles`/`VerifyExecutable`), not only at initial tx-pool admission. Additionally, consider making the lend transaction's KAIA transfer conditional on (or atomically bundled/rolled back with) the swap's successful repayment, e.g., by having the router pull funds from the proposer only after a successful swap rather than pre-funding the user unconditionally, or by having the txpool module re-run `checkBalanceForSwap` right before bundle extraction using the exact pre-execution state for that position in the block.

### Proof of Concept
1. A whitelisted low-liquidity token/KAIA pool is registered for `GaslessSwapRouter` (as in `tests/gasless_test.go`'s `setupLiquidity`).
2. Attacker (or attacker-controlled second account) submits `GaslessApproveTx` + `GaslessSwapTx` with `AmountIn`, `MinAmountOut`, and `AmountRepay` computed such that `checkBalanceForSwap`'s `GetAmountIn(token, MinAmountOut)` check passes at admission time against current reserves (see `kaiax/gasless/impl/tx_pool.go` lines 128-142).
3. Before this bundle is selected for inclusion (it can remain pending across blocks, or other bundles/transactions against the same pool are included earlier in the same block), the attacker (or any third party) executes an ordinary swap against the same pool that shifts the reserve ratio unfavorably for the pending `MinAmountOut`.
4. The gasless bundle `[LendTxGenerator, ApproveTx, SwapTx]` is extracted by `ExtractTxBundles` (`kaiax/gasless/impl/builder.go`) without re-checking AMM sufficiency, and included in the block.
5. `LendTxGenerator`'s transaction executes first, unconditionally crediting the attacker's account with `lendAmount(approveTx, swapTx)` KAIA.
6. `SwapTx` executes against the now-shifted reserves; the router's own `minAmountOut` enforcement causes the call to revert, rolling back the token swap and proposer repayment, while the attacker keeps the previously-lent KAIA (minus the reverted swap tx's own gas cost).

Full on-chain contract source for `GaslessSwapRouter`'s internal revert condition was not directly located in the indexed context (only ABI bindings were available), so the exact revert condition inside `swapForGas` could not be fully confirmed from the index; a Devin session with full repository access should verify the Solidity source (likely under `contracts/` or a submodule) to confirm the on-chain `minAmountOut` enforcement and whether the lend/repay is otherwise made atomic at the EVM level.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
