## Title
Untrusted child processes (Git LFS smudge/clean filters) inherit `DESKTOP_TRAMPOLINE_TOKEN`/`DESKTOP_PORT` and can impersonate the trampoline client to exfiltrate stored GitHub credentials for an arbitrary host - (File: `app/src/lib/trampoline/trampoline-environment.ts`, `app/src/lib/trampoline/trampoline-server.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The premise in the question is largely confirmed by the code: `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN` are ordinary environment variables set on the git process spawned for a clone/fetch, they are not scoped to the actual `desktop-trampoline` binary, and the server accepts any client that can present a currently-valid token, regardless of who sent it. However, the concrete high-value impact is not "arbitrary ASKPASS/CREDENTIALHELPER command injection" but **cross-host credential/token exfiltration**: a malicious child process (e.g. a Git LFS smudge/clean filter defined in an attacker-controlled `.gitattributes`) that inherits the environment can speak the trampoline wire protocol directly and request credentials for a host of its choosing (e.g. `github.com`), which the handler will happily resolve to the signed-in user's real OAuth token.

### Finding Description
`withTrampolineEnv` injects `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN` into the environment object used to spawn the top-level `git` process for the whole duration of the operation: [1](#0-0) 

The comment right above this explicitly states that `credential.helper` is configured via `GIT_CONFIG_PARAMETERS` (an environment variable) specifically *so that commands invoked by filters (i.e. Git LFS) can pick up the configuration* — confirming that filter subprocesses are expected to, and do, inherit the git process's environment, including `DESKTOP_TRAMPOLINE_TOKEN`/`DESKTOP_PORT`: [2](#0-1) 

The trampoline "protocol" is a trivial, unauthenticated, plaintext, NUL-delimited TCP protocol bound to `127.0.0.1`; the reference `desktop-trampoline` C client simply opens a socket to the port from `DESKTOP_PORT` and writes argc/args/envc/env pairs/stdin: [3](#0-2) 

Server-side, `onDataReceived`/`toCommand` parse this same wire format from any TCP client, with no verification that the caller is the real trampoline binary — the identifier (`ASKPASS` vs `CREDENTIALHELPER`) and the token are both just fields inside the attacker-controllable payload: [4](#0-3) 

The only access control is `isValidTrampolineToken`, which is a plain `Set.has()` check with no binding to a specific process, identifier, or expected remote host: [5](#0-4) [6](#0-5) 

Critically, once a `CREDENTIALHELPER`/`get` command reaches `createCredentialHelperTrampolineHandler`, the target host/endpoint used to look up stored credentials comes entirely from the attacker-supplied stdin payload (`host`, `protocol`, `path`, or `url` fields) via `getCredentialUrl`, with no check that this endpoint corresponds to the actual remote the current git operation is authenticating against: [7](#0-6) [8](#0-7) 

`getGitHubCredential`/`findGitHubTrampolineAccount` then resolve the account purely by matching the origin of the attacker-chosen endpoint against the user's signed-in accounts and return the real login + OAuth token: [9](#0-8) [10](#0-9) 

### Impact Explanation
A malicious repository can define a Git LFS `smudge`/`clean` filter (or any other filter/hook invoked as a git subprocess) that, while running with `DESKTOP_TRAMPOLINE_TOKEN` and `DESKTOP_PORT` inherited from the parent `git clone`/`fetch`, connects directly to `127.0.0.1:DESKTOP_PORT` and sends a hand-crafted frame with `DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER`, `DESKTOP_TRAMPOLINE_TOKEN=<stolen token>`, and stdin `get\nprotocol=https\nhost=github.com\n\n`. Because the handler trusts the attacker-supplied `host` value rather than validating it against the actual remote being operated on, this returns the signed-in user's real GitHub username + OAuth token to the malicious filter process, which can then exfiltrate it (e.g., over the network). This is a credential/token exfiltration vulnerability, not "arbitrary command injection" — there's no mechanism in this code path that lets the attacker execute arbitrary askpass/credential-helper *commands* beyond `get`/`store`/`erase`, but token theft for the user's real GitHub account is itself a severe, high-impact result.

### Likelihood Explanation
Likelihood is credible but constrained by prerequisites: the attacker needs the victim to run a git operation that (a) invokes `withTrampolineEnv` (any push/pull/clone/fetch through Desktop) so a valid token exists, and (b) executes an attacker-controlled child process during that operation, most plausibly via a Git LFS smudge/clean filter declared in the malicious repo's `.gitattributes`/`.lfsconfig`, or a custom `core.fsmonitor`/other externally invoked helper git spawns as a subprocess of the tracked operation. No local access, admin rights, or leaked credentials are required — only that the victim clones/fetches the attacker's repository, matching the stated valid-impact criteria (attacker controls a cloned/fetched repository).

### Recommendation
- Bind each trampoline token to the specific `TrampolineCommandIdentifier` (and ideally the specific git operation/expected remote) it was issued for, rejecting requests where the identifier or target host doesn't match what was expected for that token.
- For the credential helper handler, validate the requested credential host/endpoint against the actual remote URL of the git operation associated with the token (tracked already via `trampolineEnvironmentPath`) rather than trusting the attacker-supplied `host`/`url` fields unconditionally.
- Consider making the wire protocol require a per-invocation, process-bound secret (e.g., derived from PID or a nonce only known to the specific spawned child, not the entire env-inherited process tree) so that unrelated filter/hook subprocesses cannot reuse the token to open independent connections.

### Proof of Concept
1. Create a malicious repository with a `.gitattributes` declaring a Git LFS smudge filter (`filter=lfs`) that is actually a small script overriding `git-lfs`, or more directly a custom `clean`/`smudge` filter command pointing at an attacker script.
2. The script, when invoked as a subprocess of `git clone`/`fetch` from GitHub Desktop, reads `process.env.DESKTOP_PORT` and `process.env.DESKTOP_TRAMPOLINE_TOKEN` (both inherited).
3. It opens a raw TCP socket to `127.0.0.1:DESKTOP_PORT` and sends, per the protocol in `desktop-trampoline.c`/`trampoline-command-parser.ts`:
   - `0\0` (argc for `get` — actually needs 1 param `"get"`, so `1\0get\0`)
   - `2\0DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER\0DESKTOP_TRAMPOLINE_TOKEN=<stolen token>\0`
   - stdin: `protocol=https\nhost=github.com\n\n\0`
4. The trampoline server validates the token via `isValidTrampolineToken`, routes to `createCredentialHelperTrampolineHandler`, and returns `username=<real login>\npassword=<real OAuth token>\n` back over the socket, which the malicious script reads and exfiltrates.

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}

int runTrampolineClient(SOCKET *outSocket, int argc, char **argv, char **envp) {
  char *desktopPortString;

    fprintf(stderr, "ERROR: Missing DESKTOP_PORT environment variable\n");
    return 1;
  }

  unsigned short desktopPort = atoi(desktopPortString);

  SOCKET socket = openSocket();

  if (socket == INVALID_SOCKET) {
    printSocketError("ERROR: Couldn't create TCP socket");
    return 1;
  }

  *outSocket = socket;

  if (connectSocket(socket, desktopPort) != 0) {
    printSocketError("ERROR: Couldn't connect to 127.0.0.1:%d - Please make "
                     "sure you don't have an antivirus or firewall blocking "
                     "this connection.", desktopPort);
    return 1;
  }

  // Send the number of arguments (except the program name)
  char argcString[MAXIMUM_NUMBER_LENGTH];
  snprintf(argcString, MAXIMUM_NUMBER_LENGTH, "%d", argc - 1);
  WRITE_STRING_OR_EXIT("number of arguments", argcString);

  // Send each argument separated by \0
  for (int idx = 1; idx < argc; idx++) {
    WRITE_STRING_OR_EXIT("argument", argv[idx]);
  }

  // Get the number of environment variables
  char *validEnvVars[NUMBER_OF_VALID_ENV_VARS + 1];
  validEnvVars[0] = "DESKTOP_TRAMPOLINE_IDENTIFIER=" DESKTOP_TRAMPOLINE_IDENTIFIER;
  int envc = 1;
  for (char **env = envp; *env != 0; env++) {
    if (isValidEnvVar(*env)) {
      validEnvVars[envc] = *env;
      envc++;
    }
  }

  // Send the number of environment variables
  char envcString[MAXIMUM_NUMBER_LENGTH];
  snprintf(envcString, MAXIMUM_NUMBER_LENGTH, "%d", envc);
  WRITE_STRING_OR_EXIT("number of environment variables", envcString);

  // Send the environment variables
  for (int idx = 0; idx < envc; idx++) {
    WRITE_STRING_OR_EXIT("environment variable", validEnvVars[idx]);
