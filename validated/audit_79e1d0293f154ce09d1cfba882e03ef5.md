Based on my investigation, I found an analog vulnerability class.

### Title
Permissionless tokenfactory denom + `addNativePointer` allows attacker to mint an ERC20 pointer contract spoofing a legitimate token's name/symbol - (File: precompiles/pointer/pointer.go)

### Summary
The `AddNative` handler of the `pointer` precompile (used for `addNativePointer`) mints an ERC20 "pointer" contract for any bank denom that merely has metadata attached, without verifying that the `name`/`symbol` claimed by that metadata are unique or tied to the actual asset they resemble. Because `x/tokenfactory` permits any account to create a denom and to set arbitrary `Name`/`Symbol` metadata for it, an attacker can create a denom whose bank metadata impersonates a well-known token (e.g. Name="USD Coin", Symbol="USDC") and then call `addNativePointer` to deploy an ERC20 contract whose `name()`/`symbol()` match the real asset, similarly to how the referenced report's `createStream` let an attacker register a stream backed by an unvalidated, attacker-controlled token contract.

### Finding Description
`AddNative` in `precompiles/pointer/pointer.go` only checks that bank metadata exists for the given denom string; it never checks that the metadata's `Name`/`Symbol` are unique across denoms or correspond to a canonical/whitelisted asset: [1](#0-0) 

The bank metadata backing a `factory/{creator}/{subdenom}` denom is attacker-controlled: `x/tokenfactory.CreateDenom` lets any account permissionlessly create a denom (only checking length/format and uniqueness of the denom string itself, not the display name/symbol): [2](#0-1) 

The creator (who becomes admin) can later call `MsgSetDenomMetadata` to set arbitrary `Name`/`Symbol` fields for their own denom - the only checks performed are structural (`Metadata.Validate()`) and that the sender is the denom's admin, with no check against existing tokens' names/symbols: [3](#0-2) [4](#0-3) 

Once this fake metadata is set, calling `addNativePointer(token)` on the pointer precompile deploys an ERC20 contract that reports the spoofed `name`/`symbol`/`decimals` taken directly from the attacker-controlled metadata, and this contract address is then registered permanently in state via `SetERC20NativePointer`/`UpsertERCNativePointer`: [5](#0-4) 

This is the direct sei-chain analog of the reported bug: just as `createStream` failed to validate that the supplied token address genuinely represented a trusted asset (letting an attacker register fake tokens under the guise of legitimate ones), `addNativePointer` fails to validate that the denom metadata driving the pointer contract's identity (`name`/`symbol`) is trustworthy or unique, letting an attacker mint a spoofed ERC20 pointer.

### Impact Explanation
Wallets, EVM dApps, and other on-chain/off-chain integrations frequently identify ERC20 tokens by `name()`/`symbol()` rather than validating the exact contract address. An attacker can create a `factory/{attacker}/subdenom` denom, set its metadata to mimic a well-known, high-value token (e.g. USDC, USDT, WETH), mint themselves large "fake balances" via `MsgMint` (as denom admin, minting is unlimited for their own denom), and deploy an EVM-visible pointer contract via `addNativePointer` whose `name()`/`symbol()` are indistinguishable from the legitimate asset from a superficial UI check. This enables phishing/spoofing attacks that can lead to users approving/transferring value to, or accepting, a worthless spoofed asset believing it is the genuine one - a fund-loss vector via impersonation, analogous to the original "fake token" finding.

### Likelihood Explanation
Both `MsgCreateDenom`/`MsgSetDenomMetadata` and `addNativePointer` are reachable directly by any unprivileged account: tokenfactory denom creation is explicitly permissionless by design, and the pointer precompile is a public EVM precompile at address `0x100b` that can be called by any transaction sender. No governance or admin gating exists to prevent metadata spoofing or to compare newly-set name/symbol values against already-registered ones. This makes the attack straightforward and repeatable at will.

### Recommendation
- In `x/tokenfactory` `SetDenomMetadata` / bank `Metadata.Validate()`, reject metadata whose `Name`/`Symbol`/`Display` collide with an existing, non-attacker-owned denom's metadata (or restrict tokenfactory-created denoms' display name/symbol to be derived deterministically from `factory/{creator}/{subdenom}`, as `createDenomAfterValidation` already does at creation time, and disallow subsequently overriding it to arbitrary values).
- In the `pointer` precompile's `AddNative` (and `AddCW20`/`AddCW721`/`AddCW1155`), consider surfacing the underlying denom/contract address prominently in the pointer's identity (e.g., embedding the base denom or cw address, not just the spoofable display name) so that UIs and integrators are less likely to mistake it for a canonical asset, and/or require pointer creation for tokenfactory-originated denoms to go through additional governance/allow-list review as is already done for pointers lacking metadata.

### Proof of Concept
1. Attacker calls `MsgCreateDenom{sender: attacker, subdenom: "spoof"}` → creates `factory/{attacker}/spoof`, attacker becomes admin (`x/tokenfactory/keeper/createdenom.go`).
2. Attacker calls `MsgSetDenomMetadata{sender: attacker, metadata: {Base: "factory/{attacker}/spoof", Display: "USDC", Name: "USD Coin", Symbol: "USDC", DenomUnits: [...]}}` — passes `Metadata.Validate()` and admin check (`x/tokenfactory/keeper/msg_server.go:188-217`), and is stored as the denom's bank metadata.
3. Attacker calls the `pointer` precompile at `0x...100b` method `addNativePointer("factory/{attacker}/spoof")`. `AddNative` reads the spoofed `Name`/`Symbol` from step 2 and deploys/registers an ERC20 pointer contract whose `name()` returns `"USD Coin"` and `symbol()` returns `"USDC"` (`precompiles/pointer/pointer.go:99-131`).
4. Attacker mints large amounts of the fake denom via `MsgMint` (admin-only, but attacker is admin) and uses the EVM pointer contract to interact with dApps/users who trust the displayed name/symbol, facilitating phishing or mistaken-identity fund transfers.

func (k Keeper) CreateDenom(ctx sdk.Context, creatorAddr string, subdenom string) (newTokenDenom string, err error) {
	denom, err := k.validateCreateDenom(ctx, creatorAddr, subdenom)
	if err != nil {
		return "", err
	}

	err = k.createDenomAfterValidation(ctx, creatorAddr, denom)
	return denom, err
}

// Runs CreateDenom logic after the charge and all denom validation has been handled.
// Made into a second function for genesis initialization.
func (k Keeper) createDenomAfterValidation(ctx sdk.Context, creatorAddr string, denom string) (err error) {
	denomMetaData := banktypes.Metadata{
		DenomUnits: []*banktypes.DenomUnit{{
			Denom:    denom,
			Exponent: 0,
		}},
		Base: denom,
		// The following is necessary for x/bank denom validation
		Display: denom,
		Name:    denom,
		Symbol:  denom,
	}

	k.bankKeeper.SetDenomMetaData(ctx, denomMetaData)

	authorityMetadata := types.DenomAuthorityMetadata{
		Admin: creatorAddr,
	}
	err = k.setAuthorityMetadata(ctx, denom, authorityMetadata)
	if err != nil {
		return err
	}

	k.addDenomFromCreator(ctx, creatorAddr, denom)
	return nil
}

func (k Keeper) validateCreateDenom(ctx sdk.Context, creatorAddr string, subdenom string) (newTokenDenom string, err error) {
	// Temporary check until IBC bug is sorted out
	if k.bankKeeper.HasSupply(ctx, subdenom) {
		return "", fmt.Errorf("temporary error until IBC bug is sorted out, " +
			"can't create subdenoms that are the same as a native denom")
	}

	denom, err := types.GetTokenDenom(creatorAddr, subdenom)
	if err != nil {
		return "", err
	}

	_, found := k.bankKeeper.GetDenomMetaData(ctx, denom)
	if found {
		return "", types.ErrDenomExists
	}

	return denom, nil
}

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
}

func (m Metadata) Validate() error {
	if strings.TrimSpace(m.Name) == "" {
		return errors.New("name field cannot be blank")
	}

	if strings.TrimSpace(m.Symbol) == "" {
		return errors.New("symbol field cannot be blank")
	}

	if err := sdk.ValidateDenom(m.Base); err != nil {
		return fmt.Errorf("invalid metadata base denom: %w", err)
	}

	if err := sdk.ValidateDenom(m.Display); err != nil {
		return fmt.Errorf("invalid metadata display denom: %w", err)
	}

	var (
		hasDisplay      bool
		currentExponent uint32 // check that the exponents are increasing
	)

	seenUnits := make(map[string]bool)

	for i, denomUnit := range m.DenomUnits {
		// The first denomination unit MUST be the base
		if i == 0 {
			// validate denomination and exponent
			if denomUnit.Denom != m.Base {
				return fmt.Errorf("metadata's first denomination unit must be the one with base denom '%s'", m.Base)
			}
			if denomUnit.Exponent != 0 {
				return fmt.Errorf("the exponent for base denomination unit %s must be 0", m.Base)
			}
		} else if currentExponent >= denomUnit.Exponent {
			return errors.New("denom units should be sorted asc by exponent")
		}

		currentExponent = denomUnit.Exponent

		if seenUnits[denomUnit.Denom] {
			return fmt.Errorf("duplicate denomination unit %s", denomUnit.Denom)
		}

		if denomUnit.Denom == m.Display {
			hasDisplay = true
		}

		if err := denomUnit.Validate(); err != nil {
			return err
		}

		seenUnits[denomUnit.Denom] = true
	}

	if !hasDisplay {
		return fmt.Errorf("metadata must contain a denomination unit with display denom '%s'", m.Display)
	}

	return nil
