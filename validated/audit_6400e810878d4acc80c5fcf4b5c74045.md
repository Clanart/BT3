## Title
Consensus reward misattribution in `pallet-consensus-incentives` lets an unprivileged submitter steal (or null) another relayer's reward - (`modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet_ismp::Pallet::handle_unsigned` is a permissionless, unsigned extrinsic: "anyone execute ISMP messages for free, provided they have valid proofs" [1](#0-0) , and the docs confirm it is intentionally open to any submitter [2](#0-1) . Every batch submitted through this call is passed as one `Vec<MessageWithWeight>` to `T::FeeHandler::on_executed` [3](#0-2) . `pallet-consensus-incentives`'s `on_executed` implementation determines *who* to reward for **every** `StateMachineUpdated` event in the whole batch by recovering the signer of only `messages[0]` [4](#0-3) . Because the caller of `handle_unsigned` fully controls both the contents and ordering of the batch, an unprivileged attacker can place their own (trivial, cheaply produced) signed `ConsensusMessage` at index 0 and append another relayer's already-broadcast, independently valid `ConsensusMessage`(s) for a different, high-value state machine. The attacker then collects the reward for the entire batch's state-machine progress — including work they did not perform — or, if they instead lead with any non-`Consensus` message, they null the reward entirely so nobody gets paid for a genuinely delivered consensus update.

### Finding Description
`handle_unsigned` validates and executes an arbitrary, caller-supplied `Vec<Message>` with no signer restriction on the call itself (`ensure_none(origin)`) [5](#0-4) . Any account can submit a batch. `Pallet::execute` runs every message through `handle_incoming_message`, collects the resulting events, and hands the *whole* batch plus events to the configured `FeeHandler::on_executed` in one call [6](#0-5) .

`pallet-consensus-incentives::on_executed` computes the reward recipient from a single source of truth: `messages.get(0)` [7](#0-6) . If that first message is a `Message::Consensus`, its signature is recovered and used as `relayer_account`. That single account is then paid for the reward computed from **every** `StateMachineUpdated` event collapsed across the entire batch, regardless of which specific `ConsensusMessage` in the batch actually advanced each state machine [8](#0-7) .

`ConsensusMessage`s carry their own signature over the proof (`consensus_proof`, `signer`) and are meaningful/valid independent of who submits the enclosing extrinsic — the relayer network commonly batches multiple chained updates itself [9](#0-8) , but nothing on-chain ties a `ConsensusMessage`'s signer to the *other* messages bundled alongside it in the same `handle_unsigned` call. An attacker who observes any valid, not-yet-applied `ConsensusMessage` (public wire/mempool data, signature and proof both public) for a state machine with a lucrative `StateMachinesCostPerBlock` reward can:

1. Craft their own trivial, self-signed `ConsensusMessage` for some cheap/low-value state machine and place it at index 0.
2. Append the observed victim `ConsensusMessage` (for the high-value chain) at index 1+.
3. Submit the combined batch via `handle_unsigned` before the original submitter's transaction lands.

Because `on_executed` only ever recovers the relayer from `messages[0]`, the attacker's key is credited with the reward for *both* state machines' progress — including the high-value chain's advance that the victim actually produced. Reward computation (`calculate_reward`) also correctly advances `LastRewardedHeight` for that state machine [10](#0-9) , so the legitimate relayer's later, correctly-signed resubmission of the same update yields `blocks = 0` and no reward — permanently and correctly "used up," but paid to the wrong account.

Conversely, if the attacker instead leads the batch with any non-`Consensus` message (e.g., a cheap `Request`), `maybe_relayer_account` resolves to `None` and *no one* is rewarded for the batch, even though the state machine(s) inside it were genuinely, validly advanced — a pure griefing/reward-burn against the honest relayer, achievable by any unprivileged caller with no signature forgery at all.

### Impact Explanation
This directly maps to the "stealing or loss of funds" and "wrong beneficiary or amount" categories of the impact gate. The treasury-funded consensus relayer reward (and the accompanying reputation-asset mint) is diverted from the honest relayer who produced/delivered the state-machine-advancing proof to an unrelated, unprivileged attacker who contributed no meaningful proof work, or is destroyed outright for that batch. Over time this can materially defund the incentive pool intended to reward consensus relaying and misdirect treasury funds, which is exactly the "malicious user can control emissions to steal ... from other [participants]" pattern in the seed report, mapped onto Hyperbridge's `pallet-consensus-incentives` reward flow instead of AMM premium TWAP.

### Likelihood Explanation
The entry point (`handle_unsigned`) is explicitly permissionless/unsigned by design, requiring no privileged role, validator status, or key compromise — only the ability to observe a pending valid `ConsensusMessage` (public data) and resubmit it bundled with an attacker-controlled message ahead of the original submitter. No malicious relayer, prover, or admin assumption is required; the flaw is a pure batch-processing/attribution bug in `on_executed`'s use of `messages[0]` as a stand-in for "the relayer of this batch."

### Recommendation
Attribute reward per `StateMachineUpdated` event to the signer of the specific `ConsensusMessage` that produced it, not to `messages[0]` for the whole batch. Concretely, walk `messages` alongside `events`, recover the sr25519 signer from each individual `Message::Consensus` entry, and only credit that signer for the `StateMachineUpdated` events causally tied to that message (e.g., by correlating `consensus_state_id`/`state_machine_id`), rather than collapsing to a single relayer for the entire batch.

### Proof of Concept
1. Victim relayer `V` observes chain `X` needs a consensus update and broadcasts a `handle_unsigned([Message::Consensus(msg_X_signed_by_V)])` transaction to the txpool.
2. Attacker `A` (an unprivileged account) observes `msg_X_signed_by_V` in the mempool/gossip layer before it is included.
3. `A` crafts `msg_Y_signed_by_A`, a trivially cheap, self-authored valid `ConsensusMessage` for a different registered state machine `Y` (or reuses any already-known valid message they can sign).
4. `A` submits `handle_unsigned([msg_Y_signed_by_A, msg_X_signed_by_V])` and it lands before `V`'s original transaction.
5. In `on_executed`, `messages.get(0)` is `msg_Y_signed_by_A`, so `maybe_relayer_account = A`. The batch's collapsed `StateMachineUpdated` events for both `X` and `Y` are rewarded to `A` [11](#0-10) .
6. `A` receives the treasury-funded reward (plus reputation mint) for chain `X`'s advance that `V` produced; `V`'s own later submission of the same update computes `blocks = latest_height.saturating_sub(baseline) = 0` (baseline already moved forward), yielding zero reward for `V`.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
