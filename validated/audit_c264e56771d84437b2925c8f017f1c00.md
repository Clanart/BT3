### Title
Missing validation of registered DKG encryption keys allows identity/foreign `enc_key`, leaking a participant's secret share to any observer - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
PedPoP's `EncryptionKeyMessage` carries each participant's ECDH encryption public key (`enc_key`), but `EncryptionKeyMessage::read` deserializes it with `Ciphersuite::read_G` — which accepts the identity point — and `Decryption::register` inserts it into `enc_keys` with no identity check and no proof of possession. The Commitments PoK (`challenge()` in `lib.rs`) binds only `commitments[0]`, not `enc_key`. A participant who registers the identity point (or any key whose discrete log is publicly known/known to an eavesdropper) causes every dealer to encrypt that participant's secret shares with an ECDH output of identity, making the ChaCha20 key derivable by anyone. An unprivileged observer of the ciphertexts then recovers that participant's full threshold secret share.

### Finding Description
- `EncryptionKeyMessage::read` parses `enc_key` via `C::read_G`, the `Ciphersuite` method, which performs only canonical-encoding checks and does not reject identity — unlike `Curve::read_G` in FROST which explicitly rejects it. [1](#0-0) [2](#0-1) [3](#0-2) 
- The dalek backend `from_bytes` only enforces torsion-freeness; identity is a valid encoding. [4](#0-3) 
- `Decryption::register` stores `msg.enc_key` with no PoP or validity check. [5](#0-4) 
- The round-1 PoK challenge covers only the commitments bytes (`cached_msg`), not `enc_key`, so nothing authenticates the encryption key. [6](#0-5) 
- In `verify_r1`, the enc_key is registered before the batch PoK check, and `encrypt` computes `ecdh(key, enc_keys[participant])`. If `enc_keys[l] == identity`, `ecdh` yields identity for every sender. [7](#0-6) [8](#0-7) 
- `cipher()` derives the ChaCha20 key purely from `context || ecdh_bytes`; with ecdh = identity, the key is `H(context || identity_encoding)` — computable by anyone. The static IV is safe only because the key is assumed secret. [9](#0-8) 
- `calculate_share` then sums each dealer's decrypted share at the recipient index into `self.secret`. [10](#0-9) 

### Impact Explanation
Every secret share encrypted to the rogue `enc_key` is readable by any party observing the DKG transcript: sum the decrypted `p_j(e)` values to obtain participant e's complete FROST secret share. That is direct key-share recovery of a threshold signing share — equivalent to compromising that participant's private key material — enabling production of valid signature shares under e's index in any included-set containing e. This is the direct analog of improper certificate validation: a public key accepted without proof it belongs to / is usable by its claimed owner enables a man-in-the-middle style interception of confidential key material.

### Likelihood Explanation
Requires one DKG participant to submit a crafted `EncryptionKeyMessage` (a message bytes input to `EncryptionKeyMessage::read` / `generate_secret_shares`, an allowed public input). No other party needs to misbehave; honest dealers will encrypt to the malicious key without any error, and the protocol completes normally. Identity encoding is `0x00..00` for Ristretto — trivial to craft. The eavesdropper need only observe the share ciphertexts, which the blame protocol already assumes are public.

### Recommendation
- Reject identity in `EncryptionKeyMessage::read`/`Decryption::register` (use `Curve`-style identity rejection or an explicit `is_identity` check).
- Include a Schnorr proof of possession over `enc_key`, bound to `(context, participant)`, in the round-1 message — either a second signature or folding `enc_key` into the existing `challenge()` transcript — so a registered key is provably owned by its claimant.

### Proof of Concept
1. Initialize `KeyGenMachine` for all n participants. For malicious participant e, build a forged `EncryptionKeyMessage` by serializing honest e's message and overwriting the trailing `enc_key` bytes with `RistrettoPoint::identity().compress().to_bytes()` (32 zero bytes). `EncryptionKeyMessage::read` accepts it (`Ciphersuite::read_G` only checks canonicality).
2. All participants run `generate_secret_shares` including the forged message. `verify_r1` succeeds: the PoK covers only the commitments bytes, and `register` inserts the identity key.
3. For every dealer j, `encrypt(rng, e, share)` computes `ecdh = share_key * identity = identity`, so `cipher(context, identity)` is deterministic and public.
4. An observer takes each `EncryptedMessage` sent to e, recomputes `ChaCha20(key = transcript("DKG Encryption v0.2", context, identity), iv = "DKG IV v0.2\0")`, XORs the keystream against `msg`, and parses each plaintext as `SecretShare` scalar `p_j(e)`.
5. Summing all `p_j(e)` yields e's final secret share; verify against the public commitments via `share_verification_statements`, confirming a valid recovered share usable to sign as participant e.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
