### Title
A single malformed `ReceivedOutput` with an odd-parity offset aborts `SignableTransaction::multisig`, blocking spending of all co-batched inputs - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The M-02 bug class is: an all-or-nothing loop over attacker-influenced items, where one failing item reverts/abort the entire operation, leaving every other item (including honest deposits) unwithdrawable, with no "skip the bad item" escape path.

Serai's Bitcoin wallet has the same shape. `SignableTransaction::new` accepts a `Vec<ReceivedOutput>` — bytes fully attacker-controlled via `ReceivedOutput::read` (untrusted `read_F` scalar offset plus a claimed `TxOut`/`OutPoint`) — and stores the offsets and prevouts without checking that each `offset` produces a usable (even-Y) key or that the derived script matches the claimed `script_pubkey`. Validation is deferred to `SignableTransaction::multisig`, which iterates all inputs and returns `None` for the whole transaction the moment any single input fails `p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey`. One poisoned `ReceivedOutput` therefore makes the entire batch of inputs unbuildable.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, `SignableTransaction::new` (lines 150-256) performs only financial/size checks (dust, fee, weight) and records `offsets`/`prevouts` verbatim from the supplied `ReceivedOutput`s. The cryptographic well-formedness of each input is only checked later in `multisig` (lines 273-286):

```rust
for i in 0 .. self.tx.input.len() {
  let offset = keys.clone().offset(self.offsets[i]);
  if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
    None?;
  }
  sigs.push(AlgorithmMachine::new(...));
}
```

Two failure modes, both reachable with attacker-supplied bytes through `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`):

1. `p2tr_script_buf` returns `None` when `offset.group_key()` has odd Y parity (`wallet/mod.rs:80-86`). The `?` propagates `None` out of `multisig` immediately. An attacker can trivially pick a scalar `s` such that `group_key + s·G` is odd (public computation, ~50% chance per guess — no discrete log needed), while honestly scanned outputs can never have odd keys since `Scanner::register_offset`/`scan_transaction` only register even-parity scripts (`wallet/mod.rs:180-214`).
2. A `ReceivedOutput` whose claimed `output.script_pubkey` does not equal the script derived from its offset also makes the comparison fail → `None`.

Because `SignableTransaction` couples all inputs into one transaction and `multisig` validates atomically, the failure of input *i* blocks inputs *j ≠ i* too — the exact "one bad reward token DoSes everyone's withdrawal" pattern. There is no per-input skip, partial machine, or error distinguishing which input failed; `multisig` just returns `None` ("wrong keys"), giving the caller no programmatic way to locate the offending output other than re-running an O(n) bisection externally.

### Impact Explanation
Any flow where serialized `ReceivedOutput`s are collected from untrusted parties (e.g., a coordinator broadcasting outputs to signers for a withdrawal/rotation transaction) lets a single participant poison the batch: every legitimate input in the same `SignableTransaction` becomes unspendable for that attempt, and the honest participants cannot produce a `TransactionMachine` at all. Since the threshold wallet's funds are only movable via `multisig → preprocess → sign → complete`, repeatedly including the bad output (or one bad output per batch) halts withdrawals of all pooled UTXOs — funds stuck pending manual out-of-band triage, analogous to M-02's stuck deposits.

### Likelihood Explanation
Medium. Exploitation requires only public-key arithmetic (choose `s` so `group_key + s·G` is odd, ~1/2 per trial) and the ability to submit one serialized `ReceivedOutput` into a batch — an unprivileged party supplying transaction data, which the model explicitly allows. No collusion, no key material, no validator privilege needed. Impact is capped at a DoS on batch building (funds are recoverable once the bad input is identified and excluded), keeping it below High.

### Recommendation
Validate each `ReceivedOutput` at the atomicity boundary rather than at batch granularity:

- In `SignableTransaction::new` (or `multisig`), reject inputs individually: check `p2tr_script_buf(offset.group_key())` is `Some` and equals `output.script_pubkey` before folding the input into `tx_ins`/`prevouts` — e.g., a per-input `Result` or a `filter`/`partition` API returning the rejected outputs.
- Alternatively, have `multisig` return `Result<TransactionMachine, usize>` (index of the offending input) instead of `Option`, so callers can drop the bad input and rebuild — the analog of M-02's recommended `emergencyWithdraw` that ignores failed items.
- Independently, consider binding offset → script in `ReceivedOutput::read` consumers, since `Scanner` guarantees the invariant only for self-scanned outputs.

### Proof of Concept
```rust
// Attacker knows the threshold group's tweaked key (public).
let group_key: ProjectivePoint = keys.group_key(); // even Y, from tweak_keys

// Find an offset producing an odd-parity group key: ~2 trials expected.
let mut bad_offset = Scalar::ZERO;
loop {
  bad_offset += Scalar::ONE;
  let candidate = group_key + (ProjectivePoint::GENERATOR * bad_offset);
  if candidate.to_encoded_point(true).tag() == Tag::CompressedOddY { break; }
}

// Serialize a ReceivedOutput: bad offset + any TxOut/OutPoint.
let evil = ReceivedOutput { offset: bad_offset, output: some_txout, outpoint: some_outpoint };
let bytes = evil.serialize();

// Victim builds a withdrawal tx: honest inputs + attacker input.
let inputs: Vec<ReceivedOutput> = honest_inputs.iter().cloned()
    .chain([ReceivedOutput::read(&mut &bytes[..]).unwrap()]).collect();

// `new` succeeds — no per-input offset/script check.
let stx = SignableTransaction::new(inputs, &payments, change, None, fee_rate).unwrap();

// multisig hits `p2tr_script_buf(offset.group_key())?` == None on the evil input
// and returns None — honest inputs in the same tx are blocked too.
assert!(stx.multisig(&keys).is_none());
```
