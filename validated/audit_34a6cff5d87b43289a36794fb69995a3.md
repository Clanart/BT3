### Title
Repo-Controlled Git Hook Can Hijack the Trampoline Token to Exfiltrate GitHub Credentials - (File: app/src/lib/trampoline/trampoline-tokens.ts)

### Summary
GitHub Desktop implements its own "trampoline" authentication scheme instead of a vetted local-IPC authentication mechanism: a bare random UUID stored in a process-wide `Set` is treated as sufficient proof that a caller connecting to a loopback TCP socket is the trusted git-askpass/credential-helper client [1](#0-0) . The token is not bound to the repository, remote host, command type, or socket connection in any way, and it is passed to every `git` invocation as a plain environment variable [2](#0-1) . Because environment variables are inherited by any child process that `git` spawns (hooks, smudge/clean filters, merge/diff drivers), a malicious cloned/fetched repository can read `DESKTOP_TRAMPOLINE_TOKEN`/`DESKTOP_PORT` from its own hook process and reuse it to talk directly to Desktop's socket server, requesting the credential helper hand back the currently signed-in account's token for an arbitrary host.

### Finding Description
`TrampolineServer.processCommand` authorizes any command purely by checking `isValidTrampolineToken(command.trampolineToken)`, i.e. membership in an in-memory `Set<string>` of active UUIDs [3](#0-2) . There is no verification that:
- the connecting socket is the actual `desktop-trampoline`/`ssh-wrapper` binary spawned by Desktop for *this* git operation,
- the command's declared identifier/parameters correspond to the repository or remote host that the git operation is legitimately talking to,
- the token has not already been exposed to a third party.

The token is generated in `requestTrampolineToken`/`withTrampolineToken` [4](#0-3)  and handed to the `git` subprocess as the `DESKTOP_TRAMPOLINE_TOKEN` environment variable alongside `DESKTOP_PORT` [2](#0-1) . Standard git behavior is for hooks (`post-checkout`, `post-merge`, `pre-push`, etc.) and content filters (`clean`/`smudge`, configured via a repo's own `.gitattributes`/`.git/config`) to inherit the full environment of the `git` process that invoked them. That means a hook or filter shipped inside a cloned/fetched repository — fully attacker-controlled content — executes with `DESKTOP_TRAMPOLINE_TOKEN` and `DESKTOP_PORT` visible in its own environment.

With those two values, the hook can open a raw TCP connection to `127.0.0.1:<DESKTOP_PORT>` and speak the trampoline wire protocol itself (`\0`-separated parameter count, parameters, env-var count, `DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER`, `DESKTOP_TRAMPOLINE_TOKEN=<leaked token>`, then stdin) exactly as parsed by `TrampolineCommandParser` [5](#0-4) . The registered `CREDENTIALHELPER` handler will process a `get` request for an arbitrary `host`/`protocol` supplied in the crafted stdin, and if that host matches a signed-in GitHub/GHE account, `getGitHubCredential` returns that account's login and OAuth token in the clear [6](#0-5) [7](#0-6) . Nothing in `processCommand` or `getCredential` restricts the requested host/credential to the remote that the *original* git operation (which owns that token) was actually contacting — the token is a generic bearer secret good for the lifetime of the operation, not a scoped capability.

This mirrors the root cause criticized in the seed report: rolling a bespoke "signing/verification" (here, bearer-token authorization) primitive without the scoping/binding guarantees a standard mechanism would enforce (e.g., binding to a specific channel/peer, scoping to a specific resource, replay/reuse protection) opens a "backdoor to unknown issues" — in this case, cross-host credential disclosure via token replay from an untrusted child process.

### Impact Explanation
An attacker who gets a victim to clone or fetch their repository (a fully unprivileged, no-local-access primitive) can plant a hook/filter that steals the trampoline token during a git operation and use it to request Desktop hand over the OAuth token of the user's authenticated GitHub.com or GitHub Enterprise account. This is credential/token exfiltration of the signed-in account's OAuth token, which grants the attacker whatever scopes that token holds (repo read/write, etc.) — a high-impact compromise reachable purely by cloning/fetching an attacker-controlled repository.

### Likelihood Explanation
The trigger requires only that the victim clone/fetch/checkout a repository containing a git hook or content filter, an action GitHub Desktop performs routinely and without warning for hooks/filters embedded in a repo. The token/port are always present as environment variables during any trampoline-mediated git operation [8](#0-7) , and the socket is always bound to loopback and unauthenticated beyond the bare token check [9](#0-8) , so no additional attacker capability beyond "repo the user chooses to interact with" is needed once a hook/filter executes.

### Recommendation
Do not rely on a bare, unscoped shared-secret Set-membership check as the trust boundary for the trampoline socket. Bind each token to the specific spawned child process (e.g., via process handle/PID verification or a per-connection, single-use, cryptographically random capability that also encodes which repository/remote/command it is valid for), reject `CREDENTIALHELPER`/`ASKPASS` requests whose target host doesn't match the host the originating git invocation was launched for, and avoid propagating the token/port to environment scopes reachable by repository-controlled hooks and filters (e.g., strip them before invoking hooks, or use a mechanism that isn't a plain env var readable by arbitrary children).

### Proof of Concept
1. Attacker publishes a repository containing a `.git/hooks/post-checkout` (or a `clean`/`smudge` filter wired via `.gitattributes`) script that does the following on execution:
   - Reads `DESKTOP_TRAMPOLINE_TOKEN` and `DESKTOP_PORT` from its own environment (inherited from the `git` process Desktop spawned).
   - Opens a TCP socket to `127.0.0.1:${DESKTOP_PORT}`.
   - Sends a trampoline-formatted command with `identifier=CREDENTIALHELPER`, the leaked token, and stdin `protocol=https\nhost=github.com\n\n` (the `get` operation).
2. Victim clones/fetches the attacker's repository through GitHub Desktop; the hook fires during the clone/checkout while the trampoline token for that operation is still valid.
3. `TrampolineServer.processCommand` accepts the connection because `isValidTrampolineToken` only checks Set membership [3](#0-2) , and the `CREDENTIALHELPER` handler returns the victim's signed-in GitHub account credential for `github.com`, regardless of the fact that the original git operation may have been targeting the attacker's own remote [10](#0-9) .
4. The hook exfiltrates the returned `username`/`password` (OAuth token) over the network, completing account takeover of the victim's GitHub session.

Note: Full confirmation that GitHub Desktop does not explicitly strip `DESKTOP_TRAMPOLINE_TOKEN`/`DESKTOP_PORT` before invoking repository-defined hooks/filters would require dynamic testing or inspection of the native `dugite`/`git` invocation wrapper, which is outside what the indexed source shows; no such stripping logic was found in the reviewed trampoline/environment code.

const trampolineTokens = new Set<string>()

function requestTrampolineToken() {
  const token = crypto.randomUUID()
  trampolineTokens.add(token)
  return token
}

function revokeTrampolineToken(token: string) {
  trampolineTokens.delete(token)
}

/** Checks if a given trampoline token is valid. */
export function isValidTrampolineToken(token: string) {
  return trampolineTokens.has(token)
}

  /**
   * Returns a command.
   *
   * It will return null if the parser hasn't finished yet, or if the identifier
   * is missing or invalid.
   **/
  public toCommand(): ITrampolineCommand | null {
    if (this.hasFinished() === false) {
      const error = new Error(
        'The command cannot be generated if parsing is not finished'
      )
      this.logCommandCreationError(error)
      return null
    }

    const identifierString = this.environmentVariables.get(
      'DESKTOP_TRAMPOLINE_IDENTIFIER'
    )

    if (identifierString === undefined) {
      const error = new Error(
        `The command identifier is missing. Env variables received: ${Array.from(
          this.environmentVariables.keys()
        )}`
      )
      this.logCommandCreationError(error)
      return null
    }

    const identifier = parseEnumValue(
      TrampolineCommandIdentifier,
      identifierString
    )

    if (identifier === undefined) {
      const error = new Error(
        `The command identifier ${identifierString} is not supported`
      )
      this.logCommandCreationError(error)
      return null
    }

    const trampolineToken = this.environmentVariables.get(
      'DESKTOP_TRAMPOLINE_TOKEN'
    )

    if (trampolineToken === undefined) {
      const error = new Error(`The trampoline token is missing`)
      this.logCommandCreationError(error)
      return null
    }

    return {
      identifier,
      trampolineToken,
      parameters: this.parameters,
      environmentVariables: this.environmentVariables,
      stdin: this.stdin,
    }
  }
