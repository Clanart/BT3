### Title
Unsanitized internal error messages leaked to any public JSON-RPC caller - ([File: networks/rpc/json.go])

### Summary
Kaia's JSON-RPC error path serializes the raw Go `error.Error()` string of *any* error returned from an API callback directly into the client-facing JSON response, without distinguishing between deliberately "safe" RPC errors and internal implementation errors. This mirrors the api-platform/core CVE-2023-47639 bug class: non-HTTP/non-RPC-typed exceptions end up serialized verbatim in the JSON error response instead of being replaced with a generic message.

### Finding Description
Every JSON-RPC error response is built by `errorMessage(err error)`, which unconditionally sets the message field to `err.Error()`: [1](#0-0) 

This function is invoked from `runMethod` for *any* error value returned by a registered API method, and separately from `requestUpstream` when relaying a request to an upstream archive node fails: [2](#0-1) [3](#0-2) 

Note that `runMethod`/`requestUpstream` do not check whether `err` implements `rpc.Error` (a deliberately curated, safe error type such as `invalidParamsError`, `methodNotFoundError`, etc., defined in `networks/rpc/errors.go`) versus an arbitrary internal Go error bubbled up from deep inside the node (state DB errors, dial errors to the configured `UpstreamArchiveEN`, decoding errors, etc.). Whatever the error's `Error()` string contains is placed straight into the `message` field of the JSON-RPC response returned to the caller.

In particular, `requestUpstream` wraps the raw dial/call failure with `fmt.Errorf("from upstream rpc endpoint: %w", err)` and sends it back unmodified to the original caller: [4](#0-3) 

`shouldRequestUpstream`/`requestUpstream` is triggered whenever a callback returns a `statedb.MissingNodeError` (pruned/missing trie node), which is easily reachable from any public RPC caller by requesting state at an old/pruned block via ordinary state-reading RPCs (e.g. `eth_getBalance`, `eth_call`, `eth_getStorageAt` at historical block numbers) on a full/non-archive node: [5](#0-4) 

Since Go's `%w`/`err.Error()` chain for a failed `DialContext`/`CallContext` typically contains low-level network detail (destination host:port, TLS/handshake errors, connection-refused/timeout text, or resolved DNS information for the configured upstream archive endpoint), an unprivileged, unauthenticated public RPC caller can cause such internal errors to be reflected back to them, revealing internal network topology/configuration that operators did not intend to expose over the public JSON-RPC surface.

More broadly, because `errorMessage`/`msg.errorResponse(err)` performs no allow-listing of error types (unlike, e.g., only exposing `rpc.Error`/`rpc.DataError` payloads and hiding everything else behind a generic "internal error" message), any future or existing API method that returns a bare Go error (not one of the purpose-built RPC error types in `networks/rpc/errors.go`) will have its raw message text — and any embedded internal state (paths, connection strings, addresses) it may carry — echoed back to the calling client. This is architecturally identical to the api-platform/core flaw: JSON error normalization does not hide non-safe exception messages, only stack traces.

### Impact Explanation
This is an information-disclosure issue (CWE-209), matching Medium severity of the referenced advisory. It does not allow value movement or fund theft, but it lets any public, unauthenticated RPC caller (no special privilege required, single RPC call is sufficient) enumerate internal error text that can reveal:
- internal network configuration of the node (e.g., the `--upstreamarchiveen` endpoint address/hostname configured via `node/config.go` / `cmd/utils/flaggroup.go`),
- internal implementation detail about state/trie storage failures,
- potentially other backend-specific strings depending on which API method's underlying error bubbles up unmodified.

This can aid reconnaissance against node operators/infrastructure (e.g., discovering private archive-node addresses used for upstream fallback), which is a legitimate confidentiality concern for RPC-facing infrastructure.

### Likelihood Explanation
High likelihood of trigger, because:
- Any public RPC caller can trivially query state for an old/pruned block number to induce a `MissingNodeError`, causing the `requestUpstream` fallback path and, on failure, a reflected internal error.
- More generally, any operator-deployed custom API/precompile-adjacent Go error not wrapped in the curated `rpc.Error` types will leak verbatim through `errorMessage`, and this depends on ecosystem code outside `networks/rpc` which cannot be fully audited from the RPC layer alone.

### Recommendation
- In `errorMessage` (`networks/rpc/json.go`), only propagate the exact error message to the client when the error implements the deliberately-designed `rpc.Error`/`rpc.DataError` interfaces; for all other error types, substitute a fixed generic message (e.g., `"internal error"`) while logging the full error server-side.
- In `requestUpstream` (`networks/rpc/handler.go`), never forward the raw upstream dial/call error to the original client; log it internally and return a generic `internalServerError` instead.
- Audit call sites that return errors from deep storage/backend layers (e.g., `statedb.MissingNodeError` and similar) to ensure they are converted to safe, whitelisted RPC error types before reaching `runMethod`.

### Proof of Concept
1. Run a Kaia full (non-archive) node configured with `--upstreamarchiveen <internal-archive-url>` (`UpstreamArchiveEN`), as wired in `networks/rpc/handler.go` / `networks/rpc/server.go` and `node/config.go`.
2. As an unauthenticated public RPC caller, send `eth_getBalance` (or any state-reading call) for an address at a block number whose trie node has been pruned on the local node.
3. The local lookup returns a `statedb.MissingNodeError`; `shouldRequestUpstream` matches it and `requestUpstream` dials/forwards the call to `UpstreamArchiveEN` (`networks/rpc/handler.go:488-490, 507-529`).
4. If the upstream dial/call fails (e.g., due to network partition, TLS misconfig, or being temporarily unreachable), the caller receives a JSON-RPC error whose `message` field is `"from upstream rpc endpoint: " + <raw dial/call error>` (`networks/rpc/handler.go:528`, `networks/rpc/json.go:135-149`), exposing internal connectivity/configuration details about the operator's upstream archive infrastructure to the calling client — with no special privilege beyond making a normal public RPC call. func errorMessage(err error) *jsonrpcMessage {
	msg := &jsonrpcMessage{Version: vsn, ID: null, Error: &jsonError{
		Code:    defaultErrorCode,
		Message: err.Error(),
	}}
	ec, ok := err.(Error)
	if ok {
		msg.Error.Code = ec.ErrorCode()
	}
	de, ok := err.(DataError)
	if ok {
		msg.Error.Data = de.ErrorData()
	}
	return msg
}

// runMethod runs the Go callback for an RPC method.
func (h *handler) runMethod(ctx context.Context, msg *jsonrpcMessage, callb *callback, args []reflect.Value) *jsonrpcMessage {
	result, err := callb.call(ctx, msg.Method, args)
	if err != nil {
		// TODO-Kaia:
		// 1. The single URL may be extended to the list of URL.
		// 2. The URL (list or single) seems not modifiable at runtime.
		// 3. Any request can be relayed as well as the state lack.
		// 4. Make a new rpcErrorResponse struct.
		if UpstreamArchiveEN != "" && shouldRequestUpstream(err) {
			return requestUpstream(ctx, msg, args)
		}
		rpcErrorResponsesCounter.Inc(1)
		return msg.errorResponse(err)
	}

	rpcSuccessResponsesCounter.Inc(1)
	return msg.response(result)
}

// shouldRequestUpstream is a function that determines whether must be requested upstream.
func shouldRequestUpstream(err error) bool {
	// Checks if the error contains MissingNodeError in the wrapped error chain.
	// MissingNodeError is a strong evidence that the node has no state and worth dialing the upstream.
	var missingNodeError *statedb.MissingNodeError
	return errors.As(err, &missingNodeError)
}

// requestUpstream is the function to request upstream archive en
func requestUpstream(ctx context.Context, msg *jsonrpcMessage, args []reflect.Value) *jsonrpcMessage {
	ctx, cancel := context.WithTimeout(ctx, DefaultHTTPTimeouts.ExecutionTimeout)
	defer cancel()

	var result interface{}
	c, err := DialContext(ctx, UpstreamArchiveEN)
	if err == nil {
		defer c.Close()

		var params []interface{}
		for _, a := range args {
			params = append(params, a.Interface())
		}
		if err = c.CallContext(ctx, &result, msg.Method, params...); err == nil {
			rpcSuccessResponsesCounter.Inc(1)
			return msg.response(result)
		}
	}

	rpcErrorResponsesCounter.Inc(1)
	return msg.errorResponse(fmt.Errorf("from upstream rpc endpoint: %w", err))
}
