### Title
Missing zero puzzle-hash validation for plotnft/pool wallet `target_puzzle_hash` allows farming rewards to be sent to a burn address - (File: `chia/pools/pool_wallet.py`)

### Summary
`PoolWallet._verify_pool_state()` and its helpers `_verify_self_pooled()` / `_verify_pooling_state()` validate `pool_url` and `relative_lock_height`, and only check that `target_puzzle_hash` is not `None`, but never check that it is not the all-zero (`bytes32.zeros`) puzzle hash. This value is fully attacker/user-controlled through the wallet RPC / CLI `create_new_wallet` (`POOL_WALLET`) and `pw_join_pool` / payout-instruction flows, and it is streamed straight into the singleton puzzle that ultimately receives farming rewards.

### Finding Description
`PoolWallet._verify_initial_target_state()` calls `_verify_pool_state()`, which only rejects a `None` `target_puzzle_hash`: [1](#0-0) 

`_verify_self_pooled` and `_verify_pooling_state` add checks for `pool_url` and `relative_lock_height` but never validate `target_puzzle_hash` content: [2](#0-1) 

This `target_puzzle_hash` is the "final payout destination" for pool/self-pooling rewards and is embedded directly in the singleton's inner puzzle when the pool wallet launcher spend is generated: [3](#0-2) 

Because `NewPoolWalletInitialTargetState.__post_init__` only checks for `None`, not for the zero puzzle hash, and `_verify_pool_state` does the same, a wallet user (via `chia plotnft create` / `create_new_wallet` RPC or `pw_join_pool`/change-payout paths) can set `target_puzzle_hash = bytes32.zeros` (the well-known "burn" puzzle hash) as a completely valid state: [4](#0-3) 

The existing test suite even demonstrates the zero puzzle hash being accepted/used as a legitimate `target_puzzle_hash`/payout-instructions value without any rejection: [5](#0-4) 

### Impact Explanation
If a plotnft/pool wallet is created or transitioned (self-pooling or farming-to-pool) with `target_puzzle_hash` set to the zero address, all future farming/pool rewards claimed by `PoolWallet.claim_pool_rewards()` (which pays out to `status.current.target_puzzle_hash`) are sent to an unspendable puzzle hash, permanently destroying farmer rewards. This is a concrete, irreversible loss-of-funds condition reachable purely from a normal wallet user action (RPC/CLI), not requiring any privileged or malicious peer/node behavior, fitting the "reward redirection" / concrete unauthorized coin movement impact category since the coins become permanently unspendable/burned instead of reaching any real owner.

### Likelihood Explanation
Likelihood is moderate: this requires either a user mistake (fat-fingering an address that decodes to the zero puzzle hash) or a malicious front-end/CLI wrapper/GUI bug that defaults to a zero value being silently accepted by wallet-side validation instead of being rejected. Since no code path (`NewPoolWalletInitialTargetState.__post_init__`, `_verify_pool_state`, `_verify_self_pooled`, `_verify_pooling_state`) rejects the zero puzzle hash, any caller error propagates directly into an irreversible on-chain reward-burning singleton state.

### Recommendation
Add an explicit check in `PoolWallet._verify_pool_state()` (and/or in `NewPoolWalletInitialTargetState.__post_init__`) rejecting `target_puzzle_hash == bytes32.zeros` (and any other well-known unspendable/burn puzzle hashes) before it is accepted as a valid initial or transition pool state, mirroring the existing `None` check at `chia/pools/pool_wallet.py:166-167`.

### Proof of Concept
1. Call the wallet RPC `create_new_wallet` with `wallet_type=POOL_WALLET`, `initial_target_state.state="SELF_POOLING"`, and `target_puzzle_hash=bytes32.zeros` (or transition an existing plotnft via `pw_self_pool`/`pw_join_pool` to that value).
2. `PoolWallet._verify_initial_target_state()` → `_verify_pool_state()` → `_verify_self_pooled()`/`_verify_pooling_state()` all pass because none check for the zero puzzle hash (`chia/pools/pool_wallet.py:135-187`).
3. `PoolWallet.generate_launcher_spend()` curries this zero puzzle hash directly into the on-chain waiting-room/member inner puzzle (`chia/pools/pool_wallet.py:569-596`).
4. On every subsequent `claim_pool_rewards()` / travel-to-self-pooling absorb spend, farming rewards are paid to the zero puzzle hash and are permanently unspendable/burned.

    @classmethod
    def _verify_pool_state(cls, state: PoolState) -> str | None:
        if state.target_puzzle_hash is None:
            return "Invalid puzzle_hash"

        if state.version > POOL_PROTOCOL_VERSION:
            return (
                f"Detected pool protocol version {state.version}, which is "
                f"newer than this wallet's version ({POOL_PROTOCOL_VERSION}). Please upgrade "
                f"to use this pooling wallet"
            )

        if state.state == PoolSingletonState.SELF_POOLING.value:
            return cls._verify_self_pooled(state)
        elif state.state in {PoolSingletonState.FARMING_TO_POOL.value, PoolSingletonState.LEAVING_POOL.value}:
            return cls._verify_pooling_state(state)
        else:
            return "Internal Error"

    @classmethod
    def _verify_initial_target_state(cls, initial_target_state: PoolState) -> None:
        err = cls._verify_pool_state(initial_target_state)
        if err:
            raise ValueError(f"Invalid internal Pool State: {err}: {initial_target_state}")

    @staticmethod
    async def generate_launcher_spend(
        standard_wallet: Wallet,
        amount: uint64,
        fee: uint64,
        initial_target_state: PoolState,
        genesis_challenge: bytes32,
        delay_time: uint64,
        delay_ph: bytes32,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> tuple[bytes32, bytes32]:
        """
        Creates the initial singleton, which includes spending an origin coin, the launcher, and creating a singleton
        with the "pooling" inner state, which can be either self pooling or using a pool
        """
        coins: set[Coin] = await standard_wallet.select_coins(uint64(amount + fee), action_scope)
        if coins is None:
            raise ValueError("Not enough coins to create pool wallet")

        launcher_parent: Coin = coins.copy().pop()
        genesis_launcher_puz: Program = SINGLETON_LAUNCHER
        launcher_coin: Coin = Coin(launcher_parent.name(), genesis_launcher_puz.get_tree_hash(), amount)

        escaping_inner_puzzle: Program = create_waiting_room_inner_puzzle(
            initial_target_state.target_puzzle_hash,
            initial_target_state.relative_lock_height,
            initial_target_state.owner_pubkey,
            launcher_coin.name(),
            genesis_challenge,
            delay_time,
            delay_ph,
        )
        escaping_inner_puzzle_hash = escaping_inner_puzzle.get_tree_hash()

        self_pooling_inner_puzzle: Program = create_pooling_inner_puzzle(
            initial_target_state.target_puzzle_hash,
            escaping_inner_puzzle_hash,
            initial_target_state.owner_pubkey,
            launcher_coin.name(),
            genesis_challenge,
            delay_time,
            delay_ph,
        )

        if initial_target_state.state == SELF_POOLING.value:
            puzzle = escaping_inner_puzzle
        elif initial_target_state.state == FARMING_TO_POOL.value:
            puzzle = self_pooling_inner_puzzle
        else:
            raise ValueError("Invalid initial state")
        full_pooling_puzzle: Program = create_full_puzzle(puzzle, launcher_id=launcher_coin.name())

@streamable
@dataclass(frozen=True)
class NewPoolWalletInitialTargetState(Streamable):
    state: str  # must map to name of PoolSingletonState Enum
    # only when state == "FARMING_TO_POOL"
    target_puzzle_hash: bytes32 | None = None
    pool_url: str | None = None
    relative_lock_height: uint32 | None = None
    pool_memoization: Program = field(default_factory=lambda: Program.to(None))

    def __post_init__(self) -> None:
        if self.state not in {member.name for member in PoolSingletonState}:
            raise ValueError(f"Invalid pool wallet initial state: {self.state}")
        if PoolSingletonState[self.state] == PoolSingletonState.FARMING_TO_POOL:
            if self.target_puzzle_hash is None:
                raise ValueError("target_puzzle_hash must be set when state is FARMING_TO_POOL")
            if self.pool_url is None:
                raise ValueError("pool_url must be set when state is FARMING_TO_POOL")
            if self.relative_lock_height is None:
                raise ValueError("relative_lock_height must be set when state is FARMING_TO_POOL")
        else:
            if self.target_puzzle_hash is not None:
                raise ValueError("target_puzzle_hash is only valid for FARMING_TO_POOL")
            if self.pool_url is not None:
                raise ValueError("pool_url is only valid for FARMING_TO_POOL")
            if self.relative_lock_height is not None:
                raise ValueError("relative_lock_height is only valid for FARMING_TO_POOL")

        super().__post_init__()
