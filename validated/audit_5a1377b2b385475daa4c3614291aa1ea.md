### Title
Payout `OP_RETURN` operator attribution is not covered by the user's `SIGHASH_SINGLE|ANYONECANPAY` signature, allowing misattribution of reimbursement rights - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
### Finding Description
The bridge attributes reimbursement rights for a fronted withdrawal to whichever operator's x-only public key appears in the `OP_RETURN` output of the confirmed `payout_tx`. `create_payout_txhandler` builds this transaction with the withdrawal input signed only by the user's signature, using `SpendPath::KeySpend` / `SinglePlusAnyoneCanPay` sighash type [1](#0-0) . `SIGHASH_SINGLE|ANYONECANPAY` only commits the signer's input to the output at the same index (index 0, the user payout output); it places no constraint on output 1 (anchor) or output 2 (the `OP_RETURN` carrying `operator_xonly_pk`) [2](#0-1) .

Downstream, the protocol treats the `operator_xonly_pk` parsed from this unauthenticated `OP_RETURN` as ground truth for "who paid the user": `update_finalized_payouts` extracts it directly from whichever transaction is found on-chain spending the withdrawal UTXO and stores it in the `withdrawals` table [3](#0-2) . Both `is_kickoff_malicious` (verifier-side fraud check) and `send_asserts` (operator-side reimbursement flow) then trust this stored value as the authoritative attribution of who fronted the payout, requiring it to equal `kickoff_data.operator_xonly_pk` [4](#0-3) [5](#0-4) ; if it is `None`, no operator can ever be reimbursed for that withdrawal [6](#0-5) , and if `is_payout_handled`/`get_first_unhandled_payout_by_operator_xonly_pk` never finds this operator, the honest operator's payout is never even attempted to be reimbursed [7](#0-6) .

Because the signature does not bind the `OP_RETURN`, any unprivileged party who observes an operator's broadcast (but unconfirmed) `payout_tx` on the Bitcoin network or in the mempool can construct a modified version of the same transaction: identical input (with the same valid witness, since `SinglePlusAnyoneCanPay` witnesses remain valid for any transaction that keeps output 0 unchanged) and identical user payout output, but with the `OP_RETURN` output's `operator_xonly_pk` bytes replaced — either with a different (existing) operator's key, or with garbage bytes that fail `XOnlyPublicKey::from_slice` parsing. If this malleated version confirms instead of (or race-wins against) the original, the bridge's custody-attribution binding "operator credited == party that fronted the withdrawal" is broken.

### Impact Explanation
- If the attacker substitutes a different, existing operator's x-only key: that operator is falsely credited with having fronted a withdrawal it never paid for, letting it claim the reimbursement (kickoff/reimburse flow) it did not earn, while the operator who genuinely paid the user is left with no attribution and can never be reimbursed — this maps to "an operator reimbursed for a payout it never funded" and "an honest operator permanently unable to be reimbursed" (Critical).
- If the attacker substitutes invalid bytes, `operator_xonly_pk` becomes `None` in the DB, and `send_asserts`/reimbursement code paths require `Some` and error out, permanently blocking the honest operator's collateral recovery for that kickoff cycle (Critical: "an honest operator permanently unable to be reimbursed").

### Likelihood Explanation
This requires only observing a not-yet-confirmed `payout_tx` in the mempool/network (which is intended to be publicly broadcast) and rebroadcasting a variant with a modified third output; it needs no operator, verifier, or aggregator privileges, no key compromise, and no majority hashrate — only winning a mempool/confirmation race against the original broadcaster, which is realistic given typical propagation and fee-bumping delays.

### Recommendation
Bind the `OP_RETURN` (and ideally the anchor output) to the user's signature by using a sighash type that commits to all outputs (e.g., `SIGHASH_ALL`) for the payout transaction, or otherwise cryptographically bind the fronting operator's identity to the withdrawal fulfillment in a way the user's signature covers, so a third party cannot rewrite attribution after the fact.

### Proof of Concept
1. Operator O1 constructs and broadcasts `payout_tx` for withdrawal `W` via `create_payout_txhandler`, with input signed `SinglePlusAnyoneCanPay` by the user, output 0 = user's payout, output 2 = `OP_RETURN(O1_xonly_pk)` [1](#0-0) .
2. Before confirmation, an attacker observes this transaction in the mempool, copies input/witness and output 0 unchanged (valid per `SIGHASH_SINGLE|ANYONECANPAY`), and rewrites output 2's `OP_RETURN` payload to `O2_xonly_pk` (a different operator) or to invalid bytes.
3. Attacker broadcasts the modified transaction with a higher fee so it confirms instead of O1's original.
4. `update_finalized_payouts` scans the block, finds this confirmed payout tx, parses the (attacker-controlled) `OP_RETURN`, and stores `O2_xonly_pk` (or `NULL`) as `payout_payer_operator_xonly_pk` for withdrawal `W` [8](#0-7) .
5. O1, who actually paid the user, is never picked up by `get_first_unhandled_payout_by_operator_xonly_pk` (keyed on O1's pubkey) and can never trigger `handle_finalized_payout`/reimbursement for `W` [7](#0-6) , while O2 (if it colludes with the attacker) can claim reimbursement it never earned via the kickoff/`send_asserts` flow [9](#0-8) .

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
