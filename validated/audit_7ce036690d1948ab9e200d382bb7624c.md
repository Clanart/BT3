### Title
ProtoJSON `JsonToBinaryStream` logs unredacted client-supplied JSON input/output at debug-log level - (File: src/google/protobuf/json/internal/parser.cc)

### Summary
When Protobuf's C++ ProtoJSON conversion library is built in a build configuration where `PROTOBUF_DEBUG` is enabled, the public conversion entry point `google::protobuf::json::JsonToBinaryStream` (reachable via `util::JsonToBinaryStream`/`JsonToBinaryString`) buffers and logs the entire client-supplied JSON payload and the resulting decoded binary output via `ABSL_DLOG(INFO)`, with no awareness of `debug_redact` field annotations. This mirrors the CVE-2023-0436 pattern (sensitive request/config data written to logs when a debug-log mode is enabled), but here the leak point is the library's own JSON→binary parse path rather than an application log statement.

### Finding Description
The Atlas Operator CVE's failed invariant is: sensitive values (e.g., GCP keys, integration secrets) that flow through request/config processing get written verbatim to logs once DEBUG-level logging is turned on, because the logging statements dump entire objects without redaction.

The closest actual Protobuf analog is `JsonToBinaryStream` in [1](#0-0) , which is the internal implementation backing the public API `google::protobuf::json::JsonToBinaryStream` / `util::JsonToBinaryStream` / `JsonToBinaryString` [2](#0-1)  and [3](#0-2) . When `PROTOBUF_DEBUG` is true, the function copies the full raw JSON request body into `copy`, and after parsing, copies the fully-decoded binary protobuf output into `out`, logging both via `ABSL_DLOG(INFO) << "json2/input: " << absl::CHexEscape(copy);` and `ABSL_DLOG(INFO) << "json2/output: " << absl::BytesToHexString(out);` [4](#0-3) .

This bypasses the one safety mechanism Protobuf actually has for this exact class of issue: the `debug_redact` field-option mechanism used by `TextFormat::Printer::TryRedactFieldValue` / `GetRedactionState`, which explicitly redacts fields marked `[debug_redact = true]` when producing `DebugString()`/`ShortDebugString()`/`Utf8DebugString()` output [5](#0-4)  and [6](#0-5) . That redaction machinery is wired specifically into `TextFormat`/`DebugFormat` printers (see `TextFormat::Printer::SetRedactDebugString`/`SetReportSensitiveFields` at [7](#0-6) ) but is never consulted by the ProtoJSON debug-tee code path in `parser.cc`. The `ABSL_DLOG` calls print the raw hex/byte dump of whatever the client submitted and whatever gets decoded, unconditionally on all fields, regardless of `debug_redact` annotations on the target message's schema.

The attacker-controlled value here is the JSON payload submitted by an ordinary client to any application that calls `JsonToBinaryStream`/`JsonToBinaryString` as its public parse API for ProtoJSON→binary conversion (e.g., a gRPC-JSON transcoding gateway). If that payload contains values the schema author intended to be redacted from debug output (`debug_redact = true` fields, e.g. credentials/tokens embedded in a proto message), those values are still fully logged in the clear whenever the binary is compiled/run with `PROTOBUF_DEBUG` set, because the debug-tee logging in `JsonToBinaryStream` operates on the raw byte streams before/after the type-aware `debug_redact` check would ever apply.

### Impact Explanation
This is an information-disclosure issue similar in class to CVE-2023-0436: sensitive values that a schema author explicitly tried to protect via `debug_redact` can still end up recorded in plaintext (as hex) in application/process logs whenever the consuming application enables `PROTOBUF_DEBUG`-level tracing on its ProtoJSON conversion path. Because `JsonToBinaryStream` is a supported public parsing API (`google::protobuf::util::JsonToBinaryStream`), any host application that turns on this debug tracing for troubleshooting inherits an unredacted dump of client-submitted request bodies and their decoded contents — undermining the confidentiality guarantee that `debug_redact` is meant to provide for exactly this "debug logging" scenario.

### Likelihood Explanation
Requires the library to be built/run in a mode where `PROTOBUF_DEBUG` evaluates true (an opt-in debug configuration, analogous to the Atlas Operator's non-default DEBUG logging requirement noted in the report). It does not require any malicious schema, hostile input beyond a normal bounded ProtoJSON payload, or privileged access — an ordinary client's JSON body is enough to have its content pulled fully into `copy`/`out` and dumped to `ABSL_DLOG`. This matches the CVE's "Required Configuration: DEBUG logging is not enabled by default" caveat, which the report itself flags as lowering but not eliminating relevance.

### Recommendation
Route the debug-tee logging in `JsonToBinaryStream` (and its `BinaryToJsonStream` counterpart, if similarly instrumented) through the existing `debug_redact`-aware `TextFormat`/`DebugFormat` redaction path instead of dumping raw hex bytes of `copy`/`out` directly, or gate/strip logging of fields whose descriptors carry `debug_redact = true` before emitting `ABSL_DLOG` output. At minimum, document clearly that enabling `PROTOBUF_DEBUG` will cause full unredacted request/response payloads to be written to logs, so downstream users are aware this bypasses `debug_redact` protections.

### Proof of Concept
A minimal (not executed) illustration based on the code read:
1. Build Protobuf C++ with `PROTOBUF_DEBUG` evaluating to true (per `port_def.inc` definitions — exact triggering macro/build mode was not fully confirmed in this pass; see caveat below).
2. Define a proto message with a field marked `[debug_redact = true]` (e.g., `string api_secret = 1 [debug_redact = true];`), analogous to `RedactedFields.optional_redacted_string` used in existing tests [8](#0-7) .
3. Call `google::protobuf::util::JsonToBinaryString(resolver, type_url, R"({"apiSecret":"super-secret-value"})", &binary_out)`, which is the internal call chain shown at [9](#0-8)  → `json_internal::JsonToBinaryStream` [10](#0-9) .
4. Observe that, unlike calling `message.DebugString()` (which would print `api_secret: "[REDACTED]"` per `TryRedactFieldValue` [11](#0-10) ), the `ABSL_DLOG(INFO) << "json2/input: ..."` and `"json2/output: ..."` lines in `parser.cc` contain the literal `super-secret-value` string in hex form, unredacted.

**Caveat / unresolved items:** I was not able to fully confirm within this pass the exact conditions (build mode, macro definition) under which `PROTOBUF_DEBUG` evaluates to a compile-time or runtime true value (the definition lives in `port_def.inc`, which the search returned matches for but I did not get to read the exact macro expansion). This affects the precision of the "likelihood" assessment — it is possible `PROTOBUF_DEBUG` is gated tightly enough (e.g., only in internal Google debug builds, not in released `NDEBUG`-off builds) that real-world exposure is narrower than described. I recommend verifying the exact `PROTOBUF_DEBUG` definition in `port_def.inc` before treating this as conclusively exploitable in released builds; based on available evidence, the code path and missing-redaction logic are confirmed, but the exact trigger condition's prevalence in production deployments is uncertain.

absl::Status JsonToBinaryStream(google::protobuf::util::TypeResolver* resolver,
                                const std::string& type_url,
                                io::ZeroCopyInputStream* json_input,
                                io::ZeroCopyOutputStream* binary_output,
                                json_internal::ParseOptions options) {
  // NOTE: Most of the contortions in this function are to allow for capture of
  // input and output of the parser in ABSL_DLOG mode. Destruction order is very
  // critical in this function, because io::ZeroCopy*Stream types usually only
  // flush on destruction.

  // For ABSL_DLOG, we would like to print out the input and output, which
  // requires buffering both instead of doing "zero copy". This block, and the
  // one at the end of the function, set up and tear down interception of the
  // input and output streams.
  std::string copy;
  std::string out;
  absl::optional<io::ArrayInputStream> tee_input;
  absl::optional<io::StringOutputStream> tee_output;
  if (PROTOBUF_DEBUG) {
    const void* data;
    int len;
    while (json_input->Next(&data, &len)) {
      copy.resize(copy.size() + len);
      std::memcpy(&copy[copy.size() - len], data, len);
    }
    tee_input.emplace(copy.data(), copy.size());
    tee_output.emplace(&out);
    ABSL_DLOG(INFO) << "json2/input: " << absl::CHexEscape(copy);
  }

  // This scope forces the CodedOutputStream inside of `msg` to flush before we
  // possibly handle logging the binary protobuf output.
  absl::Status s;
  {
    MessagePath path(type_url);
    JsonLexer lex(tee_input.has_value() ? &*tee_input : json_input, options,
                  &path);
    Msg<ParseProto3Type> msg(tee_output.has_value() ? &*tee_output
                                                    : binary_output);

    ResolverPool pool(resolver);
    auto desc = pool.FindMessage(type_url);
    RETURN_IF_ERROR(desc.status());

    s = ParseMessage<ParseProto3Type>(lex, **desc, msg, /*any_reparse=*/false);
    if (s.ok() && !lex.AtEof()) {
      s = absl::InvalidArgumentError(
          "extraneous characters after end of JSON object");
    }
  }

  if (PROTOBUF_DEBUG) {
    tee_output.reset();  // Flush the output stream.
    io::zc_sink_internal::ZeroCopyStreamByteSink(binary_output)
        .Append(out.data(), out.size());
    ABSL_DLOG(INFO) << "json2/status: " << s;
    ABSL_DLOG(INFO) << "json2/output: " << absl::BytesToHexString(out);
  }

  return s;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}
