### Title
Nil pointer dereference in `CompactBitArray.UnmarshalJSON` on empty bit-string input - ([File: sei-cosmos/crypto/types/compact_bit_array.go])

### Summary
`CompactBitArray.UnmarshalJSON` reproduces the exact bug class fixed upstream in CometBFT's `BitArray.UnmarshalJSON` (commit 75d12c3, PR #2774): it fails to account for `NewCompactBitArray(<=0)` returning `nil`, and then dereferences that nil pointer.

### Finding Description
`NewCompactBitArray` is documented and implemented to return `nil` whenever `bits <= 0`: [1](#0-0) 

`UnmarshalJSON` accepts any string matching `\A"([_x]*)"\z`, which includes the empty string (`""`), yielding `numBits == 0`. It then calls `NewCompactBitArray(numBits)`, which returns `nil` for `numBits == 0`, and unconditionally dereferences it via `*bA = *bA2`: [2](#0-1) 

This is precisely the bug class described in the report: `NewBitArray`/`NewCompactBitArray` returning `nil` for zero bits, and the JSON unmarshaler failing to special-case zero bits before dereferencing the result, causing a `runtime nil pointer dereference` panic.

Notably, the sibling implementation in this same codebase, `bits.BitArray.UnmarshalJSON` (tendermint fork), already guards against this by calling `bA.reset(numBits)` on the receiver (which is never nil at that point) rather than allocating via `NewBitArray` and dereferencing the result: [3](#0-2) 

`CompactBitArray` was not patched analogously, so the exact crash pattern from the CometBFT advisory still exists here.

### Impact Explanation
Any code path that JSON-unmarshals a `CompactBitArray` with a malicious `""`-body string will panic with a nil-pointer dereference. `CompactBitArray` is used to represent the "which signers signed" bitmap for multisig public keys/signatures (`sei-cosmos/crypto/types/multisig.pb.go`, `sei-cosmos/crypto/keys/multisig/*`). Any component that accepts and JSON-decodes such structures — e.g. legacy Amino-JSON code paths, or protobuf JSON (`jsonpb`) decoding through `ProtoCodec.UnmarshalAsJSON` (gogoproto's `jsonpb.Unmarshaler` falls back to a type's `encoding/json.Unmarshaler` implementation when present) — is at risk of a crash if attacker-controlled JSON reaches this type. A crash of a node process handling such a request is a denial-of-service impact.

### Likelihood Explanation
I was unable to conclusively confirm, with the tools available, a fully unauthenticated public JSON-RPC/REST endpoint in this codebase that directly deserializes a `CompactBitArray` (or a message embedding it, such as `MultiSignatureData`/multisig `PubKey`) from raw client-supplied JSON without first requiring protobuf-encoded bytes. Cosmos-SDK's typical `BroadcastTx`/simulate flows accept base64/binary-encoded protobuf `Tx` bytes rather than raw JSON structures, which would reduce direct reachability. Establishing definitive reachability (e.g., a specific gRPC-gateway or legacy amino-JSON REST route that unmarshals a `CompactBitArray`-bearing message straight from a request body) requires further code tracing beyond what was verified here.

### Recommendation
Mirror the fix used in `bits.BitArray.UnmarshalJSON`: avoid allocating a new object via `NewCompactBitArray` and dereferencing it. Instead, mutate the receiver directly, handling `numBits == 0` by setting `bA.ExtraBitsStored = 0; bA.Elems = nil` (as already done for the `"null"` case), e.g.:
```go
match := bitArrayJSONRegexp.FindStringSubmatch(b)
if match == nil { ... }
bits := match[1]
numBits := len(bits)
if numBits == 0 {
    bA.ExtraBitsStored = 0
    bA.Elems = nil
    return nil
}
bA2 := NewCompactBitArray(numBits)
...
*bA = *bA2
```

// NewCompactBitArray returns a new compact bit array.
// It returns nil if the number of bits is zero, or if there is any overflow
// in the arithmetic to encounter for the number of its elements: (bits+7)/8,
// or if the number of elements will be an unreasonably large number like
// > maxint32 aka >2**31.
func NewCompactBitArray(bits int) *CompactBitArray {
	if bits <= 0 {
		return nil
	}
	nElems := (bits + 7) / 8
	if nElems <= 0 || nElems > math.MaxInt32 {
		// We encountered an overflow here, and shouldn't pass negatives
		// to make, nor should we allow unreasonable limits > maxint32.
		// See https://github.com/cosmos/cosmos-sdk/issues/9162
		return nil
	}
	return &CompactBitArray{
		ExtraBitsStored: uint32(bits % 8), //nolint:gosec // bits is validated positive above, bits%8 is always 0..MaxExtraBitsStored
		Elems:           make([]byte, nElems),
	}
}

var bitArrayJSONRegexp = regexp.MustCompile(`\A"([_x]*)"\z`)

// UnmarshalJSON implements json.Unmarshaler interface by unmarshaling a custom
// JSON description.
func (bA *CompactBitArray) UnmarshalJSON(bz []byte) error {
	b := string(bz)
	if b == "null" {
		// This is required e.g. for encoding/json when decoding
		// into a pointer with pre-allocated BitArray.
		bA.ExtraBitsStored = 0
		bA.Elems = nil

		return nil
	}

	match := bitArrayJSONRegexp.FindStringSubmatch(b)
	if match == nil {
		return fmt.Errorf("bitArray in JSON should be a string of format %q but got %s", bitArrayJSONRegexp.String(), b)
	}

	bits := match[1]

	// Construct new CompactBitArray and copy over.
	numBits := len(bits)
	bA2 := NewCompactBitArray(numBits)
	for i := 0; i < numBits; i++ {
		if bits[i] == 'x' {
			bA2.SetIndex(i, true)
		}
	}
	*bA = *bA2

	return nil
}

// UnmarshalJSON implements json.Unmarshaler interface by unmarshaling a custom
// JSON description.
func (bA *BitArray) UnmarshalJSON(bz []byte) error {
	b := string(bz)
	if b == "null" {
		// This is required e.g. for encoding/json when decoding
		// into a pointer with pre-allocated BitArray.
		bA.reset(0)
		return nil
	}

	// Validate 'b'.
	match := bitArrayJSONRegexp.FindStringSubmatch(b)
	if match == nil {
		return fmt.Errorf("bitArray in JSON should be a string of format %q but got %s", bitArrayJSONRegexp.String(), b)
	}
	bits := match[1]
	numBits := len(bits)

	bA.reset(numBits)
	for i := range numBits {
		if bits[i] == 'x' {
			bA.SetIndex(i, true)
		}
	}

	return nil
}
