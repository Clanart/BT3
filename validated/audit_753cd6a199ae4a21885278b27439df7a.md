### Title
`ReceivedOutput::read` accepts attacker-controlled `offset`/`TxOut`/`outpoint` without verifying the offset actually derives the output's `script_pubkey` — the deserialized buffer is handed to the wallet stack missing its consistency "sync" - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The upstream bug class is a buffer passed to consumers missing a required bookkeeping step: MANA recorded no page/DMA-sync offset for page-pool RX frags, so the CPU consumed packet data that was never synchronized. In `bitcoin-serai`, `ReceivedOutput` is exactly such a producer/consumer pair: `Scanner::scan_transaction` binds an `offset` to a `script_pubkey` it derived (`key + offset·G`), but `ReceivedOutput::read` deserializes `offset`, `output` (TxOut), and `outpoint` from raw bytes and performs no check that the three fields are mutually consistent — i.e., it never "re-syncs" the claimed offset against the claimed output before the object is used for balance accounting and transaction construction.

### Finding Description
`ReceivedOutput::read` reads a canonical scalar offset, then consensus-decodes a `TxOut` and `OutPoint`, and returns the struct unconditionally:
- `networks/bitcoin/src/wallet/mod.rs:122-134` — no validation that `output.script_pubkey` is even P2TR, let alone that it equals `p2tr_script_buf(key + offset·G)` for the scanning key.

The consistency invariant only exists implicitly:
- `Scanner::scan_transaction` (`wallet/mod.rs:199-214`) only creates `ReceivedOutput`s where `offset` was registered against that exact script.
- The spending-side check is deferred to `SignableTransaction::multisig` (`wallet/send.rs:273-284`), which returns `None` on mismatch — after the output has already been counted.

Meanwhile `SignableTransaction::new` (`wallet/send.rs:175`) sums `input.output.value` from the untrusted `TxOut` for funds/fee accounting, and the sighash commits to `Prevouts::All(&self.tx.prevouts)` (`wallet/send.rs:373-386`), binding signatures to the attacker-supplied `value`.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (the documented untrusted-bytes entry point) can claim arbitrary outpoints with arbitrary satoshi values and any offset. Downstream this produces:
- **Funds reported received that are not spendable**: fake/inflated balance is counted toward `input_sat`, so the wallet believes it has funds that either don't exist on-chain or whose script doesn't correspond to the claimed offset.
- **Invalid signed transactions**: if the offset is consistent but the `TxOut.value` is forged, the Taproot key-spend sighash (`Prevouts::All`) commits to a value different from the real UTXO, so the completed threshold-signed transaction is unrelayable — burning the real fee-paying inputs' signing round and halting wallet operation (DoS of the signing pipeline).

This is the accepted "funds reported received that are not spendable" impact class.

### Likelihood Explanation
Reachability is per the rules: `ReceivedOutput::read` is a listed untrusted-bytes sink (e.g., outputs persisted/loaded across the scanner DB boundary or transferred between components). Exploitation requires no key material and no collusion — only a malformed serialized `ReceivedOutput`. The deferred `multisig()` check prevents actual theft of a different key's output but does not prevent balance inflation or signing-pipeline stall, so impact is Medium rather than High.

### Recommendation
Validate at the deserialization boundary: `ReceivedOutput::read` (or a checked constructor) should require `output.script_pubkey.is_p2tr()` and recompute `p2tr_script_buf(key + offset·G)` — or store the scanning key/script in the `ReceivedOutput` — rejecting any tuple where the offset doesn't derive the claimed script. Failing that, verify `outpoint`'s on-chain `TxOut` (value and script) before counting it in `input_sat`.

### Proof of Concept
```rust
// networks/bitcoin: craft a ReceivedOutput claiming 21M BTC at a fake outpoint
let mut buf = vec![];
buf.extend(Scalar::ZERO.to_bytes());                 // offset = 0 (valid for base key)
let fake_out = TxOut {
  value: Amount::from_sat(21_000_000_0000_0000),
  script_pubkey: p2tr_script_buf(victim_key).unwrap(), // matches offset -> passes multisig check
};
buf.extend(serialize(&fake_out));
buf.extend(serialize(&OutPoint::null()));            // outpoint that doesn't exist on-chain
let fake = ReceivedOutput::read(&mut buf.as_slice()).unwrap(); // accepted, no validation

// Wallet accounting trusts it:
let tx = SignableTransaction::new(vec![fake], &payments, Some(change), None, fee).unwrap();
// input_sat includes 21M BTC; signatures commit to the forged prevout value via
// Prevouts::All -> resulting TX is rejected by the network; balance was inflated meanwhile.
```
