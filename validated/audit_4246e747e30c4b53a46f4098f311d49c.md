### Title
Amend delta-review path in `_resolve_amend_pre_sha` skips already-committed dangerous content without verifying it was ever reviewed - (File: `plugins/security-guidance/hooks/security_reminder_hook.py`)

### Summary
`handle_commit_review_posttooluse` uses `_resolve_amend_pre_sha` to switch from a full `git show` review of an amended commit to a narrow `git diff pre_amend_sha..post_sha` review, on the assumption that the pre-amend commit's content was already reviewed and only the amend's delta is new. That assumption is never verified against the plugin's own reviewed-commit record, so any dangerous code already present in the pre-amend commit — but never actually reviewed by this hook — permanently escapes review, including the degenerate case where a message-only amend produces an empty delta and skips review entirely.

### Finding Description
When a Bash command matches `git commit ... --amend`, `handle_commit_review_posttooluse` computes `is_amend` and calls `_resolve_amend_pre_sha(repo_root, expected_post_sha=shas[0])` [1](#0-0) . If a pre-amend SHA is resolved, the reviewer diffs only `pre_amend_sha..sha` instead of showing the full amended commit [2](#0-1) , and if that delta is empty (e.g. a message-only amend), the review is skipped outright with `skip_reason=35` [3](#0-2) .

`_resolve_amend_pre_sha` only validates git-mechanical properties of the amend (reflog subject shape, cross-repo SHA prefix match, back-to-back-amend exclusion) — it never checks whether `head1_sha` (the pre-amend commit) is actually present in the repo's own review ledger (`sg-reviewed-shas`, managed by `_load_reviewed_shas`/`_append_reviewed_shas` in `diffstate.py`) [4](#0-3) . That ledger is consulted elsewhere (e.g. the reflog-fallback SHA list is filtered against `_load_reviewed_shas`) [5](#0-4) , but not on the amend-delta path.

Exploit flow: an attacker-influenced repo/session can produce a commit whose dangerous content was never reviewed by this plugin — e.g. the commit was made before the plugin was enabled, while `ENABLE_CODE_SECURITY_REVIEW`/`HAS_API_CREDENTIALS`/`ensure_anthropic_reachable()` gated it off, while the LLM call rate-limited or errored, or simply pre-existing in a repo delivered to the agent. The agent (following attacker-crafted repo instructions/diff content) then runs `git commit --amend -m "<new message>"` with no code changes. `_resolve_amend_pre_sha` happily resolves `pre_amend_sha` to that never-reviewed commit purely from reflog shape, the delta diff is empty, and the hook exits with `skip_reason=35` — no warning, no LLM call, no rewake — even though the entire amended commit (containing the dangerous payload) is about to be pushed.

### Impact Explanation
This breaks the stated invariant that dangerous edits/commands must stay reviewable and blockable across retries, amends, and pushes. Dangerous file content that was committed without ever passing through commit-review or the Stop hook can be permanently laundered past review via a trivial no-op amend, and subsequently pushed (push-sweep only tracks/dedupes against the same `sg-reviewed-shas` ledger, so a commit marked as "delta-reviewed" here is treated as covered going forward). This allows unauthorized/unreviewed file content to reach the pushed history and the workspace outside the intended reviewable-diff scope, matching the "unauthorized file write outside approved scope" impact class.

### Likelihood Explanation
No special privilege is needed beyond normal repository content and standard commit/amend usage available to any agent session — an attacker only needs to get a dangerous commit into the pre-amend state (via repo delivery, timing a commit during a review-disabled window, or a failed/rate-limited review) and then have a follow-up `git commit --amend` (even message-only) executed. This is a normal, easily-triggered workflow (fix commit message, squash, etc.), making the bypass highly feasible and repeatable.

### Recommendation
In `_resolve_amend_pre_sha` (or its call site), require that `head1_sha` be present in `_load_reviewed_shas(repo_root)` before trusting the delta-only path; if the pre-amend SHA is not a known-reviewed commit, fall back to full `git show` review of the post-amend commit (the existing safe default). Also ensure `_append_reviewed_shas` only marks a SHA as reviewed after a real review actually ran (not on skip paths), so the amend-delta optimization can rely on the ledger as ground truth.

### Proof of Concept
Integration test in `plugins/security-guidance/hooks/test_*` style:
1. Init a git repo; with `ENABLE_CODE_SECURITY_REVIEW=0` (or by not calling the review hook at all), create a commit containing an obviously dangerous pattern (e.g. `os.system(user_input)`).
2. Re-enable review, run `git commit --amend -m "typo fix"` (no code change) through the Bash PostToolUse path invoking `handle_commit_review_posttooluse`.
3. Assert: current behavior — `_resolve_amend_pre_sha` resolves the pre-amend SHA, `git diff pre_amend_sha..sha` is empty, hook exits 0 with `skip_reason=35`, and `analyze_code_security`/LLM review is never invoked on the dangerous content.
4. Expected (fixed) behavior — since the pre-amend SHA is absent from `sg-reviewed-shas`, the hook should fall back to full `git show` review of the amended commit, invoke the LLM review, and flag the dangerous pattern (exit code 2 with guidance).

```python
def _resolve_amend_pre_sha(repo_root, expected_post_sha=None):
    """For a `git commit --amend` we just ran, return the pre-amend SHA via
    reflog, or None if it can't be safely determined.

    expected_post_sha: the post-amend SHA the caller parsed from bash stdout
    (or reflog). If provided, HEAD@{0} of `repo_root` must match it (prefix
    compare — bash stdout SHAs are abbreviated, reflog %H is 40 chars) before
    we trust the reflog-derived pre-amend SHA. This guards against the
    cross-repo case (`cd ../other && git commit --amend && cd -`) where
    `repo_root` happens to have its own recent amend that's unrelated to
    the bash command we're reviewing.

    We require HEAD@{0}'s reflog subject to start with `commit (amend)` —
    otherwise our `--amend` regex matched something that didn't actually
    perform an amend (e.g., `git commit --amend --dry-run`, aliased commands,
    aborted amends), and HEAD@{1} would be the wrong commit. Also requires
    HEAD@{1} to NOT itself be an amend, since back-to-back amends would have
    HEAD@{1} as the previous-amend's post state — the original commit we
    want to compare against is then HEAD@{2}, but at that point we're
    reaching and fall back to a full review.

    Bytes + decode('utf-8', errors='replace'): reflog subjects embed commit
    subjects, which git stores as raw bytes (commit messages may be latin-1
    / cp1252 / etc.). text=True would raise UnicodeDecodeError (a
    ValueError, not OSError) on non-UTF8 bytes and crash the hook.
    """
    if not repo_root:
        return None
    try:
        r = subprocess.run(
            [*GIT_CMD, "log", "-g", "-2", "--format=%H|%gs", "HEAD"],
            cwd=repo_root, capture_output=True, timeout=5,
        )
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
    if r.returncode != 0:
        return None
    stdout_text = r.stdout.decode("utf-8", errors="replace")
    lines = [ln for ln in stdout_text.splitlines() if "|" in ln]
    if len(lines) < 2:
        return None
    head0_sha, _, head0_subj = lines[0].partition("|")
    head1_sha, _, head1_subj = lines[1].partition("|")
    if not head0_subj.startswith("commit (amend)"):
        return None
    if head1_subj.startswith("commit (amend)"):
        return None
    # Cross-repo guard: the post-amend SHA the caller is about to review must
    # match HEAD@{0} of repo_root. Otherwise the bash command was likely run
    # in a different repo than repo_root, and the reflog we just read is
    # unrelated. Prefix-compare: expected_post_sha is typically the 7-char
    # abbreviated SHA captured from bash stdout by _COMMIT_SHA_RE (git's
    # default core.abbrev floor), while head0_sha is the full 40-char %H —
    # strict equality would always fail and silently disable the delta path.
    if expected_post_sha and not head0_sha.startswith(expected_post_sha):
        return None
    return head1_sha or None
```
