### Title
Malicious DKG participant can register an identity encryption key, forcing all ECDH shared secrets to a public constant and exposing every secret share sent to them - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The FFDH advisory class — "peer forces the DH shared secret into a small set of values via an unvalidated public key" — maps directly onto PedPoP's ECDH layer. `EncryptionKeyMessage.enc_key` (the long-term per-participant ECDH public key) is accepted with no non-identity check, so a participant registering `enc_key = identity` makes every honest sender's shared secret `key * identity = identity`, yielding a publicly derivable ChaCha20 key. All `SecretShare` ciphertexts addressed to that participant become world-decryptable, and the shares sum to the victim-indexed threshold key share.

### Finding Description
`EncryptionKeyMessage::read` accepts any canonically encoded point for `enc_key` via `C::read_G` — `read_G` only enforces canonical encoding, never rejects the identity: [1](#0-0) [2](#0-1) 

`Decryption::register` stores the key verbatim; no check for `C::G::identity()` or low-order/torsion points exists anywhere in the registration path: [3](#0-2) 

When honest participants call `generate_secret_shares` → `Encryption::encrypt` → `encrypt`, the ECDH shared secret is `enc_key * msg_key`. With `enc_key = identity`, the shared point is always the identity, and `cipher` derives the ChaCha20 key solely from the public `context` and the identity encoding — a value any observer can recompute: [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

Symmetrically, `EncryptedMessage::read` does not reject `msg.key = identity` either; a sender can forge a valid PoP for the identity key trivially (any `sG = R` satisfies `sG = R + c·identity`), making the recipient's `ecdh(&self.enc_key, msg.key)` the identity regardless of their secret: [8](#0-7) [9](#0-8) 

Note `EncMachine`/`Encryption::new` honestly generates `random_nonzero_F` keys, but nothing constrains the *peer-supplied* key — exactly the missing contributory-behavior check from the advisory.

### Impact Explanation
Each participant's final secret share is the sum of the `n-1` `SecretShare`s addressed to them (`*self.secret += share` in `calculate_share`). An attacker who registers `enc_key = identity` causes all senders to encrypt those shares under the publicly known key `H(context || identity_bytes)`. Any observer of the authenticated channel — and the design explicitly supports non-participant observers via `AdditionalBlameMachine::new`, which reconstructs decryption state purely from broadcast `commitment_msgs` — can decrypt every share addressed to the malicious index and recover `secret_j = Σ_i share_{i→j}`, a full threshold key share. This defeats the DKG's confidentiality guarantee; combined with knowledge of other shares (e.g., the attacker's own coalition's shares), it can collapse the effective threshold of the resulting `ThresholdKeys` group key. On ed448 (cofactor 4) a low-order non-identity point additionally reduces the shared secret to one of 4 values even without identity acceptance. [10](#0-9) [11](#0-10) 

### Likelihood Explanation
Reachable by any unprivileged DKG participant: registering an encryption key is an ordinary, expected protocol message (`EncryptionKeyMessage`), and the attacker merely sets `enc_key` to the canonical identity encoding instead of `generator * secret`. No collusion, no network position beyond observing the (documented as public/blame-shareable) ciphertexts, and no protocol deviation that honest code rejects — `register`, `verify_r1`, and `calculate_share` all proceed normally. The attack is silent: honest parties complete the DKG unaware their ciphertexts were public.

### Recommendation
Reject non-contributory ECDH inputs at the point of deserialization or registration:
- In `Decryption::register` (and/or `EncryptionKeyMessage::read` / `EncryptedMessage::read`), return an error if `enc_key`/`msg.key` `is_identity()`.
- For cofactored suites (ed448), additionally verify the point is in the prime-order subgroup (multiply by the group order or use a `is_torsion_free`-style check) before storing it in `enc_keys`.
- Consider making `read_G` callers that feed DH-like flows explicitly assert non-identity, since the Schnorr PoP on `msg.key` does not help: a valid signature over the identity key is forgeable by anyone.

### Proof of Concept
1. Attacker `M` (Participant index `j`) runs `KeyGenMachine::generate_coefficients` honestly for commitments, but constructs the registration message with `enc_key = C::G::identity()` — encodable canonically under `read_G` for Ristretto/kp256/ed448.
2. Every honest participant `i` calls `generate_secret_shares`, invoking `Encryption::encrypt(rng, j, share)` → `ecdh(&key_i, identity) = identity` → `cipher(context, identity)` — a ChaCha20 keystream anyone can regenerate from the public `context`.
3. `M` (or any passive observer archiving the transcript) reads each `EncryptedMessage` sent to `j`, applies the public keystream, and parses each `SecretShare<C::F>`.
4. Summing the decrypted scalars yields participant `j`'s complete secret share (`self.secret` in `KeyMachine::calculate_share`), i.e., key share recovery. With `t-1` cooperating/compromised participants or leaked shares, this reduces to full group secret recovery; alone it already breaks the DKG's share-confidentiality invariant.

Uncertain: whether the transport layer encrypts share messages end-to-end independently; the finding holds to the extent that ciphertexts are observable by third parties, which `AdditionalBlameMachine::new`'s existence (outsiders adjudicating blame from public messages) strongly implies.

  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
