### Title
`HostManager.setIsmpHost()` doesn't check that `hostAddr` isn't the zero address, permanently bricking the cross-chain governance channel and freezing bridge revenue withdrawal - ([File: evm/src/core/HostManager.sol])

### Summary
`HostManager.setIsmpHost()` is a one-shot admin function meant to bind the `HostManager` to its corresponding `EvmHost` right after deployment, sealing a cyclic constructor dependency. It sets `_params.host = hostAddr` and unconditionally zeroes out `_params.admin` in the same call, with no check that `hostAddr != address(0)`. This is the same missing-zero-address-check bug class as `LPToken.set_minter()`, but here the consequence is that the contract loses **both** its admin role setter and its host binding simultaneously and permanently.

### Finding Description
```solidity
// This function can only be called once by the admin to set the IsmpHost.
// This exists to seal the cyclic dependency between this contract & the ismp host.
function setIsmpHost(address hostAddr) public restrict(_params.admin) {
    _params.host = hostAddr;
    _params.admin = address(0);
}
``` [1](#0-0) 

If the admin calls this with `hostAddr == address(0)` (e.g. a copy-paste/deploy-script mistake — the deployment flow calls `manager.setIsmpHost(address(host))` right after deploying the host), the outcome is:
- `_params.host` becomes `address(0)`.
- `_params.admin` becomes `address(0)` regardless, since it's set unconditionally.

Both the `restrict(_params.admin)` guard on `setIsmpHost` itself and the `restrict(_params.host)` guard on `onAccept` now require `msg.sender == address(0)`, which is unsatisfiable. There is no other function to re-set `_params.host` or `_params.admin`. [2](#0-1) [3](#0-2) 

`onAccept` is the only entrypoint through which Hyperbridge's cross-chain governance can trigger `Withdraw` (bridge revenue withdrawal) and `SetHostParam` (updating `EvmHost`'s critical security params such as `consensusClient`, `handler`, `challengePeriod`) on the corresponding `EvmHost`: [4](#0-3) 

On the `EvmHost` side, both `withdraw()` and `updateHostParams()` are restricted to `_hostParams.hostManager`, i.e. only this `HostManager` contract can invoke them: [5](#0-4) [6](#0-5) 

Once the `HostManager` is bricked as described, no message from Hyperbridge can ever be accepted by it, so `withdraw` and `updateHostParams` on the bound `EvmHost` become permanently unreachable through the intended governance channel.

### Impact Explanation
This is a loss-of-funds / permanent-lock issue: any protocol/relayer revenue that accrues in the `EvmHost` contract (native token or fee token) can never be withdrawn again, because the only authorized caller of `withdraw()` — the `HostManager` — can no longer process any inbound governance request. It also permanently removes the ability to update `EvmHost`'s security-critical parameters (`consensusClient`, `handler`, `challengePeriod`, `hostManager` itself, etc.) via cross-chain governance, since `updateHostParams` is likewise gated the same way. The deployment script binds the `HostManager` to the host with exactly this call (`manager.setIsmpHost(address(host))`), making this a realistic one-shot administrative action with no recovery path once the wrong (zero) address is used. [7](#0-6) 

### Likelihood Explanation
`setIsmpHost` is explicitly documented as callable "only once by the admin," and is invoked exactly once in the standard deployment flow. A single mistaken call with the zero address (or any wrong value, though zero is the most severe as it also disables re-authorization since `msg.sender` can never equal `address(0)`) irreversibly bricks governance for that host deployment. No other code path re-derives or resets `_params.admin` or `_params.host`.

### Recommendation
Add a zero-address (and ideally non-zero-`hostAddr`-must-be-a-contract) check in `setIsmpHost` before committing the new host address and clearing the admin:
```solidity
function setIsmpHost(address hostAddr) public restrict(_params.admin) {
    if (hostAddr == address(0)) revert InvalidHostAddress();
    _params.host = hostAddr;
    _params.admin = address(0);
}
```

### Proof of Concept
1. Deploy `HostManager` with `HostManagerParams{admin: deployer, host: address(0)}`.
2. Deployer mistakenly calls `manager.setIsmpHost(address(0))` (e.g., wrong deploy-script argument order/variable).
3. `_params.host` and `_params.admin` are both now `address(0)`.
4. Any subsequent call to `setIsmpHost(...)` reverts with `UnauthorizedAction` because `msg.sender != address(0)` is always true.
5. Any subsequent `onAccept(...)` call from the real `EvmHost` reverts for the same reason — Hyperbridge-originated `Withdraw`/`SetHostParam` governance messages can never be processed again, permanently freezing revenue withdrawal and host-param updates for the bound `EvmHost`.
