### Title
Unsigned OP_RETURN in `payout_tx` lets anyone reassign reimbursement credit to an arbitrary operator, permanently freezing the true payer out of reimbursement - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The user's withdrawal authorization signature uses `TapSighashType::SinglePlusAnyoneCanPay`, which under BIP-341 only commits to input 0 and output 0 of `payout_tx`. The OP_RETURN output that records "the operator who fronted the withdrawal" (`operator_xonly_pk`) is output index 2, and is therefore completely unconstrained by the signature. Any party who obtains the presigned withdrawal message can broadcast a payout transaction that correctly pays the user (satisfying the signed output) while writing an arbitrary or non-operator `xonly_pk` into the OP_RETURN, permanently corrupting attribution of who actually fronted the withdrawal.

### Finding Description
`create_payout_txhandler` builds the transaction with:
1. output[0]: user payout (covered by signature),
2. output[1]: anchor (NOT covered),
3. output[2]: OP_RETURN with `operator_xonly_pk` (NOT covered), [1](#0-0) 

and the signature is verified only via `calculate_sighash_txin(0, in_signature.sighash_type)` in `Operator::withdraw`, matching the SinglePlusAnyoneCanPay semantics documented in the proto (`WithdrawParams.input_signature`). [2](#0-1) [3](#0-2) 

Because `SinglePlusAnyoneCanPay` only signs input 0 and output 0 (per `Prevouts::One` and standard BIP-341 semantics used in `calculate_pubkey_spend_sighash`), any party holding the presigned withdrawal params (exposed via `Withdraw`/`InternalWithdraw` RPCs, or observable once broadcast/rebroadcast attempts occur) can reconstruct their own `payout_tx` with the same input/output[0], but a different `operator_xonly_pk` (belonging to themselves, a competitor operator, or even a non-existent key) in the OP_RETURN. [4](#0-3) 

On-chain, `update_finalized_payouts` blindly trusts this unauthenticated OP_RETURN value to attribute the payout to an operator: [5](#0-4) 

This attribution is later relied upon by `validate_payer_is_operator` (equality check `payer_xonly_pk == self.signer.xonly_public_key`) to decide who is entitled to reimbursement, and by `PayoutCheckerTask`'s `get_first_unhandled_payout_by_operator_xonly_pk` which only surfaces payouts keyed by the (attacker-controlled) `payout_payer_operator_xonly_pk` column. [6](#0-5) [7](#0-6) 

If the OP_RETURN is set to a bogus/non-operator key, or to a different real operator's key, the true payer never satisfies `payer_xonly_pk == self.signer.xonly_public_key`, and `PayoutCheckerTask` never picks up the withdrawal for that operator either — the withdrawal becomes permanently un-reimbursable for the honest party who actually fronted the payout, since it can never be re-attributed after the block is finalized (equivalent to the report's "no way to fix after the fact" root cause).

### Impact Explanation
This breaks the binding "the operator credited (`payout_payer_operator_xonly_pk`) == the party that funded/paid the withdrawal (`self.signer.xonly_public_key` of the actual fronting operator)". An unprivileged attacker (anyone able to see/replay the presigned `SinglePlusAnyoneCanPay` withdrawal message before it's mined, e.g. via mempool observation or being one of many parties the aggregator's `Withdraw` RPC is sent to) can rewrite the OP_RETURN attribution while still correctly paying the user. This matches the Critical impact category "an honest operator permanently unable to be reimbursed" and the High impact category "premature disclosure/misuse of a protocol commitment prior to a deadline-bound step" — the honest operator's collateral remains locked in the round/kickoff cycle with no valid path to reimbursement once the malicious payout_tx confirms first.

### Likelihood Explanation
Requires no special role: any observer of the mempool, or any operator among the (typically many) recipients of the `Withdraw`/off-chain-shared signature, can win a race to broadcast a competing `payout_tx` with a corrupted OP_RETURN before the legitimate fronting operator's version confirms. Given `TxSender`'s RBF-based fee bumping (`fund_raw_transaction`, `replaceable`) already implies contested mempool conditions for this exact transaction, a race/replacement window plausibly exists in normal operation.

### Recommendation
Bind the OP_RETURN attribution to the user's signature by using a sighash type that also commits to all outputs (`AllPlusAnyoneCanPay`) for the payout, or otherwise cryptographically authenticate/commit the `operator_xonly_pk` at deposit-registration/withdrawal-registration time so it cannot be altered by whoever broadcasts the final `payout_tx`.

### Proof of Concept
1. User signs withdrawal params with `SinglePlusAnyoneCanPay` as in `sign_withdrawal_output` (`core/src/test/common/setup_utils.rs:499-543`), authorizing exactly output[0] (payout to user) and input[0].
2. Operator A calls `withdraw`/`InternalWithdraw`, builds `payout_tx` via `create_payout_txhandler` with its own `operator_xonly_pk` in OP_RETURN, and submits it via `TxSender` (RBF-eligible, `core/src/operator.rs:628-675`).
3. Before Operator A's version confirms, an attacker (or Operator B) constructs an alternate `payout_tx` with identical input/output[0] (so the same signature verifies), but writes an arbitrary xonly key (or Operator B's own key) into output[2]'s OP_RETURN, and gets it mined first (e.g., via a higher fee).
4. `update_finalized_payouts` records the attacker's key as `payout_payer_operator_xonly_pk` (`core/src/verifier.rs:2283-2343`).
5. Operator A's `get_reimbursement_txs`/`validate_payer_is_operator` now fails permanently (`payer_xonly_pk != self.signer.xonly_public_key`), and `PayoutCheckerTask::get_first_unhandled_payout_by_operator_xonly_pk` never surfaces this withdrawal for Operator A — Operator A funded the withdrawal but can never claim reimbursement.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,

    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
