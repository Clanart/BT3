**Analysis:** The Move-level check in `check_upgradability` at [1](#0-0)  already correctly enforces the monotonicity invariant via a hard `assert!` that reads the **actual stored** `old_pack.upgrade_policy` from on-chain `PackageRegistry` state (not attacker-supplied), compared against the attacker-supplied `new_pack.upgrade_policy` using `can_change_upgrade_policy_to`, defined as `from.policy <= to.policy` at [2](#0-1) .

This assertion aborts the entire transaction with `EUPGRADE_WEAKER_POLICY` if the attacker attempts a non-monotonic (weakening) transition, and it runs *before* the registry write (`*packages.borrow_mut(index) = pack`) and before `request_publish_with_allowed_deps` is invoked in `publish_package` at [3](#0-2) . Since Move transaction execution is atomic, a failed assert rolls back all effects including the write-set, so no corrupted `upgrade_policy` value can ever be persisted, and no downstream `check_dependencies` (`EDEP_WEAKER_POLICY` at line 320) can observe a manipulated policy.

The attacker does not control `old_pack` (it is read from existing on-chain state) — they only control `new_pack.upgrade_policy`, and the assert is the exact mechanism designed to reject any attempted non-monotonic transition. This matches the documented high-level requirement in the formal spec: "Package upgrades should abide by policy change rules... equal to or stricter" at [4](#0-3) .

The submission describes the correct, intended, and already-enforced behavior of the guard rather than a bypass of it. No code path exists that allows `publish_package`/`publish_package_txn` to reach the write-set commit or `request_publish_with_allowed_deps` with a weakened policy — the check is a blocking abort, not a bypassable soft check.

    /// Checks whether the given package is upgradable, and returns true if a compatibility check is needed.
    fun check_upgradability(
        old_pack: &PackageMetadata, new_pack: &PackageMetadata, new_modules: &vector<String>) {
        assert!(old_pack.upgrade_policy.policy < upgrade_policy_immutable().policy,
            error::invalid_argument(EUPGRADE_IMMUTABLE));
        assert!(can_change_upgrade_policy_to(old_pack.upgrade_policy, new_pack.upgrade_policy),
            error::invalid_argument(EUPGRADE_WEAKER_POLICY));
        let old_modules = get_module_names(old_pack);

        old_modules.for_each_ref(|old_module| {
            assert!(
                vector::contains(new_modules, old_module),
                EMODULE_MISSING
            );
        });
    }
