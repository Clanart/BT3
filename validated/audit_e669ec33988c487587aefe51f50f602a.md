### Title
Reward Sniping via Instant Vote Reallocation in `WombatBribeManager`/`BribeRewardPool` Dilutes Legitimate Voters' Bribes - (File: `wombat/WombatBribeManager.sol`, `rewards/BribeRewardPool.sol`, `rewards/BaseRewardPoolV2.sol`)

### Summary
`WombatBribeManager.vote()` lets any vlMGP holder instantly reallocate their voting weight between pools with no cooldown, and `castVotes()` is a fully permissionless function that harvests accrued Wombat bribes and dumps them into `BribeRewardPool.rewardPerTokenStored` in one lump-sum update via `queueNewRewards`/`_provisionReward`. Because the reward-per-share update uses the pool's `totalSupply` (i.e. `totalVoteInVlmgp`) at the instant `castVotes()` executes, a user can front-run `castVotes()` with `vote()` to inflate their share of `totalVoteInVlmgp` right before the bribe is queued, then immediately back-run with `unvote()`/negative-delta `vote()` to withdraw and claim, capturing rewards that accrued over the entire prior epoch without having voted for any meaningful duration.

### Finding Description
`vote()` in `WombatBribeManager.sol` updates `pool.totalVoteInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` immediately, with no time lock or minimum holding period: [1](#0-0) 

`castVotes()` is callable by anyone and, after computing target votes from `pool.totalVoteInVlmgp` at call time, forwards the harvested bribe rewards through `wombatStaking.vote()`: [2](#0-1) 

`WombatStaking.vote()` calls the external Wombat `voter.vote()` (which pays out bribes accrued since the last cast) and immediately funnels the full amount into the rewarder via `queueNewRewards`: [3](#0-2) 

`BribeRewardPool`/`BaseRewardPoolV2._provisionReward` then distributes that entire lump sum across `totalSupply` (i.e., `totalVoteInVlmgp`) as it stands at that exact block, with no time-weighting of contributions: [4](#0-3) 

`stakeFor`/`withdrawFor` in `BribeRewardPool` only checkpoint `userRewardPerTokenPaid` at the moment of stake/withdraw — there is no minimum staking duration or vesting on the bribe reward itself: [5](#0-4) 

This is the same root cause as the report's `GaugeController` bug: reward distribution uses an instantaneous snapshot of voting weight instead of a time-weighted contribution, and the update to that snapshot (`vote`/`unvote`) is unrestricted right up to the point rewards are realized (`castVotes`). Any user holding vlMGP already locked can:
1. Detect (or predict, since `castVotes` is permissionless and often called routinely) an imminent `castVotes()` call.
2. Front-run with `vote()`, adding a large delta of their existing vlMGP allocation to the target pool's `totalVoteInVlmgp`.
3. Let `castVotes()` execute — the freshly queued bribe reward (accrued over the whole prior period, e.g. multiple days) is split pro-rata using the now-inflated `totalVoteInVlmgp`, including the attacker's freshly added, un-aged stake.
4. Immediately call `vote()` with a negative delta (or `unvote()`) to withdraw and claim the reward via `withdrawFor(..., claim=true)`.

The attacker captures bribe rewards proportional to their vote weight even though it was held for a single block, diluting the rewards legitimate long-term voters should have earned for that pool over the full accrual period.

### Impact Explanation
This results in theft of unclaimed yield from legitimate long-term vlMGP voters: bribe rewards accrued over an entire period are redistributed based on a snapshot an attacker can manipulate in the same transaction window as `castVotes()`, taking a share disproportionate to actual voting contribution and reducing the payout to real voters. This can be repeated every time `castVotes()` is called (there is no cooldown on `vote()`/`unvote()`), causing recurring loss.

### Likelihood Explanation
`castVotes()` is a public, permissionless, gas-incentivized function (caller receives a fee), so it is called routinely and observable in the mempool, making front-running low-cost and repeatable. `vote()`/`unvote()` require only an existing vlMGP balance (already-locked MGP), no flash loan or special access is needed — only ordinary wallet transactions. `getUserVotable()` only checks the user's total locked MGP, not any holding-duration requirement: [6](#0-5) 

### Recommendation
- Time-weight bribe reward distribution (e.g., accrue `rewardPerTokenStored` continuously based on `totalVoteInVlmgp` integrated over time since the last update, similar to Synthetix/Curve streaming reward models) instead of applying the full lump sum against the instantaneous `totalSupply`.
- Enforce a minimum holding period (cooldown) between `vote()`/`unvote()` calls per pool per user, or disallow unvoting for some window after a `castVotes()` cycle that the user's vote participated in.
- Alternatively, snapshot `totalVoteInVlmgp` per pool at the start of each cast/reward-accrual period and require votes to be locked in prior to that snapshot to be eligible for that period's rewards.

### Proof of Concept
1. `attacker` and `legit_user` both hold locked vlMGP.
2. `legit_user` calls `vote([lpA], [1000e18])` well before any `castVotes()` call, remaining staked in `BribeRewardPool` for the entire epoch.
3. Wombat bribes accrue to `wombatStaking`/`voter` for `lpA` over the epoch.
4. Right before `castVotes()` is submitted (observed in mempool), `attacker` calls `vote([lpA], [5000e18])`, instantly inflating `pool.totalVoteInVlmgp` and their `BribeRewardPool` balance via `stakeFor`.
5. `castVotes()` executes: `wombatStaking.vote()` receives the epoch's bribe payout and calls `queueNewRewards` on `lpA`'s `BribeRewardPool`, updating `rewardPerTokenStored` based on the now-inflated `totalSupply` (which includes attacker's freshly added 5000e18).
6. Immediately after, `attacker` calls `vote([lpA], [-5000e18])` (or `unvote(lpA)`), triggering `withdrawFor(msg.sender, amount, claim=true)` → `_getReward` pays out attacker's share of the just-queued reward.
7. `attacker` receives roughly `5000/(1000+5000)` = 83% of the epoch's bribe reward for `lpA`, despite having voted for only one block, while `legit_user` — who voted the entire epoch — receives only `1000/(1000+5000)` = 17%. [7](#0-6) [5](#0-4) [8](#0-7)

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        virtual

        updateRewards(_for, rewardTokens)

    /// @notice Updates informaiton for a user in case of a withdraw. Can only be called by the Masterchief operator
    /// @param _for Address account
    /// @param _amount Amount of withdrawed tokens by the user on masterchief
    function withdrawFor(
        address _for,
        uint256 _amount,
        bool claim
    ) external virtual onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply - _amount;
        _balances[_for] = _balances[_for] - _amount;

        emit Withdrawn(_for, _amount);

        if (claim) {
            _getReward(_for);
        }
    }
