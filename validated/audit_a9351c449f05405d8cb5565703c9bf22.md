### Title
Argument injection via attacker-controlled PR head ref name in `createBranch` - (File: app/src/lib/git/branch.ts)

### Summary
`_findPullRequestBranch` in `app-store.ts` uses the pull request's `head.ref` (attacker-controlled, sourced from the GitHub API for a fork PR) to build a `startPoint` string that is passed unsanitized into `createBranch`, which invokes `git branch <name> <startPoint>` with no `--` end-of-options separator. [1](#0-0) [2](#0-1) 

### Finding Description
The broken invariant is analogous to the Magnetar bug: a value which is validated for one narrow purpose (as a display/matching string) is trusted broadly and fed into a sensitive low-level primitive without checking that it cannot be interpreted as a command flag.

`pull-request-store.ts` ingests `pr.head.ref` verbatim from the GitHub API response with no character restrictions applied (unlike the deep-link `branch` parameter in `parse-app-url.ts`, which is checked with `testForInvalidChars`) [3](#0-2) . This value flows into `_findPullRequestBranch`, where `remoteRef = ${remote.name}/${headRefName}` is used as the `startPoint` argument for branch creation when the PR head is on a fork remote: `this._createBranch(repository, pr/${prNumber}, remoteRef, false)` [4](#0-3) .

`createBranch` then builds `git(['branch', name, startPoint], ...)` — no `--` terminator is used to stop git from treating a leading-dash argument as an option [2](#0-1) . This differs from other git wrapper functions in the same codebase (e.g. `clone.ts` and `checkout.ts`) which deliberately append `'--'` before user-controlled refs/URLs to guard against exactly this class of argument injection [5](#0-4) [6](#0-5) .

Because `remoteRef` is only reached after a prior lookup against `gitStore.allBranches` fails to find a matching remote-tracking branch by exact string equality (`x.name === name`) [7](#0-6) , an attacker who names their fork branch beginning with a dash (e.g. `--upload-pack=...` is not valid for `branch <name> <startPoint>` but options such as `-t`/`--track` alterations, or crafted refspec-like strings) could cause `git branch` to interpret part of the ref as a flag rather than a commit-ish, since the value bypasses the `sanitizedRefName`/`testForInvalidChars` guard used elsewhere in the codebase for branch input originating from URLs.

### Impact Explanation
If the attacker-controlled `startPoint`/`headRefName` is interpretable as a git option rather than a ref, the practical impact ranges from a failed/aborted operation to altering the resulting branch/tracking configuration (e.g. forcing unexpected `--track`/`--no-track` behavior) without the user's awareness — a form of silent corruption of what gets committed to the local branch state, matching the "silent corruption of what the user commits or pushes" impact category. This is triggered purely by the victim viewing/checking out a pull request from a hostile fork; no local access or credentials are required.

### Likelihood Explanation
Likelihood is moderate: it requires an attacker to open a PR (or push a branch to a fork visible via a PR) with a maliciously crafted ref name, and requires the victim to attempt "Checkout this PR" or the drag-and-drop cherry-pick flow in Desktop for that fork PR — both are normal, unprompted user actions supported by the feature and don't require any unnatural steps. Exact exploitability (whether `git branch <name> <startpoint>` can be forced into a dangerous option) needs confirmation with a live git binary, which could not be verified from static code alone.

### Recommendation
Sanitize/validate `headRefName` (and any composed `remoteRef`) with the same `testForInvalidChars`/`sanitizedRefName` checks used for URL-based branch input before using it as a git command argument, and add a `--` end-of-options separator in `createBranch` (and any other git wrapper that accepts a `startPoint`/ref sourced from untrusted API data) so leading-dash values can never be interpreted as flags.

### Proof of Concept
1. Attacker forks the target repository and creates a branch whose name, when read back via the GitHub API as `pr.head.ref`, begins with a dash-prefixed sequence that git would treat as an option to `git branch` (e.g., a crafted option string valid for the `git branch` command).
2. Attacker opens a pull request from that fork branch against the victim's repository.
3. Victim, using GitHub Desktop, selects "Checkout this PR", triggering `dispatcher.checkoutPullRequest` → `appStore._checkoutPullRequest` → `_findPullRequestBranch` [8](#0-7) .
4. Since no existing local/remote-tracking branch matches, `remoteRef` (built from the attacker-controlled ref) is passed as `startPoint` into `_createBranch` → `createBranch`, which runs `git branch <name> <startPoint>` with no `--` separator [2](#0-1) .
5. Verification that a concrete git-branch flag can be smuggled this way (versus git rejecting it as an invalid revision) would require running the exact `dugite`/git version bundled with Desktop, which was not available for confirmation in this static review.

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }

export async function createBranch(
  repository: Repository,
  name: string,
  startPoint: string | null,
  noTrack?: boolean
): Promise<void> {
  const args =
    startPoint !== null ? ['branch', name, startPoint] : ['branch', name]

  // if we're branching directly from a remote branch, we don't want to track it
  // tracking it will make the rest of desktop think we want to push to that
  // remote branch's upstream (which would likely be the upstream of the fork)
  if (noTrack) {
    args.push('--no-track')
  }

  await git(args, repository.path, 'createBranch')
}
