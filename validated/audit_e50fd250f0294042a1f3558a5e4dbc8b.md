### Title
Untrusted `ReceivedOutput` deserialization enables unauthorized Bitcoin spends - ([File: `networks/bitcoin/src/wallet/mod.rs`])

### Summary
`ReceivedOutput::read` reconstructs a purportedly spendable output from an untrusted offset, `TxOut`, and outpoint without authenticating that it was produced by `Scanner` or that the outpoint corresponds to the supplied output. [1](#0-0)  Because `ReceivedOutput` has private fields and no public constructor, deserialization is effectively a way to forge the trusted ownership record normally created by `Scanner::scan_transaction`. [2](#0-1) [3](#0-2) 

### Finding Description
`SignableTransaction::new` consumes the deserialized `ReceivedOutput` values directly as transaction inputs, offsets, and previous outputs. [4](#0-3)  The only ownership check in `SignableTransaction::multisig` verifies that `keys.offset(offset)` produces the claimed previous output's `script_pubkey`; it does not verify that the claimed outpoint exists or was discovered through the authenticated scanner path. [5](#0-4) 

An attacker can therefore serialize an offset together with the exact publicly observable `TxOut` and `OutPoint` of a real wallet UTXO. For a UTXO controlled by the base key, the required offset is simply zero; for an offset-derived address, the attacker needs the corresponding offset. [6](#0-5)  When the resulting forged `ReceivedOutput` is combined with attacker-selected payment outputs, the transaction machine signs the real UTXO's Taproot key-spend sighash. [7](#0-6) 

### Impact Explanation
This allows an unprivileged party who can submit serialized `ReceivedOutput` bytes for signing to cause a threshold wallet to sign a valid Bitcoin transaction spending a selected wallet UTXO to attacker-controlled outputs. [8](#0-7)  The resulting signatures are inserted into the transaction witnesses, producing a broadcastable spend. [9](#0-8) 

### Likelihood Explanation
The target UTXO's outpoint, value, and script are public blockchain data. [10](#0-9)  If an API accepts client-supplied serialized `ReceivedOutput` values, exploitation requires no private key, malformed encoding, malicious peer assumption, or invalid curve point; it only requires selecting an existing wallet UTXO and requesting a spend. [1](#0-0) 

### Recommendation
Treat `ReceivedOutput` as authenticated internal state rather than an unauthenticated wire object. Either remove/publicly restrict `ReceivedOutput::read`, authenticate serialized outputs with an integrity check, or require `SignableTransaction` construction to resolve every `OutPoint` through a trusted Bitcoin node and compare the returned `TxOut` and spendability metadata before signing. The offset should also be bound to a registered scanner entry instead of accepted as an unattested scalar.

### Proof of Concept
1. Identify a confirmed target wallet UTXO with base-key offset zero, obtaining its `OutPoint` and exact consensus `TxOut` from the public chain.
2. Serialize:

```text
canonical_zero_scalar || consensus_serialize(actual_TxOut) || consensus_serialize(actual_OutPoint)
```

3. Feed those bytes to `ReceivedOutput::read`, which accepts them without checking scanner provenance or chain membership. [1](#0-0) 
4. Pass the result to `SignableTransaction::new` with an attacker-controlled payment script and amount below the UTXO value minus fees. [11](#0-10) 
5. Call `SignableTransaction::multisig`; it succeeds because the copied `TxOut` contains the wallet's expected `script_pubkey`. [5](#0-4) 
6. Complete the FROST preprocessing and signing rounds; `TransactionSignMachine::sign` signs the Taproot key-spend digest committing to the attacker's payment output. [12](#0-11) 
7. Broadcast the completed transaction, spending the selected wallet UTXO.
