### Title
Zero-length aggregate signature verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an attacker-supplied signature count of zero and deserializes an aggregate containing no nonce commitments. `SchnorrAggregate::verify` then reduces verification of an empty statement list to `-sG = identity`, allowing a forged aggregate with `s = 0` to pass verification.

### Finding Description
The parser reads a 32-bit count and returns `SchnorrAggregate { Rs: [], s }` when that count is zero, without rejecting the empty aggregate [1](#0-0) . Verification checks only that `Rs.len()` equals the verifier-provided statement count, so an empty `Rs` matches an empty `keys_and_challenges` [2](#0-1) . With no statements, the loop contributes no key or nonce terms, leaving only `(-s, generator)` in the multiexp [3](#0-2) . Consequently, `s = 0` makes the empty aggregate verify successfully.

This bypasses the invariant enforced by `SchnorrAggregator::complete`, which refuses to produce an aggregate when no signatures were supplied [4](#0-3) . The deserializer therefore admits an encoding that the legitimate construction API deliberately cannot produce.

### Impact Explanation
An unprivileged caller who can supply serialized aggregate signatures can forge acceptance of an aggregate signature over an empty verification set. The result is a signature accepted without any public key, nonce commitment, message challenge, or signer authorization.

### Likelihood Explanation
Exploitation requires a verifier path that deserializes an attacker-controlled `SchnorrAggregate` and then calls `verify` with an empty `keys_and_challenges` slice. If the verifier supplies at least one statement, the length check rejects the encoding. The issue is nevertheless reachable through public parsing and verification APIs whenever zero-statement verification is possible.

### Recommendation
Reject zero-length aggregates in `SchnorrAggregate::read`, matching `SchnorrAggregator::complete`'s existing nonempty invariant. Defense in depth should also make `SchnorrAggregate::verify` return `false` when `keys_and_challenges.is_empty()`.

### Proof of Concept
Conceptually, for any ciphersuite `C` whose zero scalar serializes as all-zero bytes:

```rust
// crypto/schnorr/src/aggregate.rs
let mut encoded = 0u32.to_le_bytes().to_vec();      // zero Rs
encoded.extend(C::F::ZERO.to_repr().as_ref());     // s = 0

let aggregate = SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();
assert!(aggregate.verify(b"domain", &[]));          // incorrectly succeeds
```

The encoded aggregate contains no `R` values and a zero `s`; verification evaluates only `-0 * G`, which is the identity.
