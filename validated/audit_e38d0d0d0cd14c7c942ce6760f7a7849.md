### Title
Unauthenticated `NonceGen` Spam Evicts Legitimate Deposit Sessions, Permanently Blocking Bridge Deposits — (File: `core/src/verifier.rs`)

### Summary

When `client_verification = false`, any network-reachable party can call the verifier's `NonceGen` gRPC endpoint without authentication. Each call inserts a new `NonceSession` into the in-memory `AllSessions` store. Because `AllSessions` silently evicts the **oldest** session once `MAX_NUM_SESSIONS = 2000` is reached, an attacker can flood the store and evict the legitimate deposit session that the aggregator just created. When the aggregator subsequently calls `DepositSign` referencing the evicted session ID, the verifier returns "Session not found" and the entire deposit pipeline fails.

### Finding Description

**Authentication bypass path:**

The `create_grpc_server` function in `core/src/servers.rs` conditionally applies the `OnlyAggregatorAndSelf` interceptor only when `config.client_verification == true`. When the flag is `false`, the `Noop` interceptor is installed instead, which passes every request unconditionally. [1](#0-0) 

The `NonceGen` RPC method name does not begin with `"Internal"`, so even when `client_verification = true` the interceptor allows the aggregator cert **and** the self cert to call it. When `client_verification = false`, the check is entirely absent. [2](#0-1) 

**Session eviction logic:**

`AllSessions::add_new_session_with_id` evicts the oldest session (FIFO) whenever the session count reaches `MAX_NUM_SESSIONS` (2000) or the byte budget is exceeded. [3](#0-2) 

`MAX_NUM_SESSIONS` is 2000 and `MAX_ALL_SESSIONS_BYTES` is 2 GB. With `num_nonces = 1` (132 bytes per session), the count limit is the binding constraint: 2000 single-nonce calls consume only ~264 KB, well under the byte budget. [4](#0-3) 

**Deposit session lifecycle:**

During `new_deposit`, the aggregator calls `NonceGen` on every verifier to obtain a session ID `S` and the corresponding public nonces. The session ID is embedded in the `DepositSignSession` proto and later passed back to the verifier in `DepositSign`. [5](#0-4) 

Inside `Verifier::deposit_sign`, the session is retrieved by ID. If it has been evicted, the call fails immediately. [6](#0-5) 

**Attack sequence:**

1. Aggregator calls `NonceGen(num_nonces = N)` → session `S` stored at position 1 in the FIFO queue.
2. Attacker calls `NonceGen(num_nonces = 1)` 2000 times → `remove_oldest_session()` is called 2000 times, evicting session `S` (and all others created before the flood).
3. Aggregator calls `DepositSign` with session ID `S` → `remove_session_with_id(S)` returns `Err("Session not found")`.
4. The deposit pipeline aborts; the BTC deposit UTXO remains unfinalized.

The global rate limit (`ratelimit_req_count = 1000` per 60 s) means the attacker needs ≥ 2 minutes to fill the store, but the `OVERALL_DEPOSIT_TIMEOUT` is 2 hours, giving ample time. The attacker can also open multiple connections to parallelize. [7](#0-6) 

### Impact Explanation

Every deposit attempt fails as long as the attacker continuously floods `NonceGen`. The bridge becomes permanently unusable for new deposits. Existing deposit UTXOs are not permanently lost — users can reclaim BTC after `user_takes_after` blocks — but the bridge liveness invariant is broken: no new BTC can be bridged until the attacker stops or the verifier is reconfigured.

### Likelihood Explanation

`client_verification` defaults to `true` in `BridgeConfig::default()` and is enforced on mainnet by `check_mainnet_requirements`. However:

- The flag is a runtime configuration option with no compile-time enforcement.
- Non-mainnet deployments (testnet4, regtest, staging) are not protected by `check_mainnet_requirements`.
- The `Noop` interceptor is explicitly coded as a first-class variant, not a debug stub. [8](#0-7) 

Any operator running a verifier with `CLIENT_VERIFICATION=false` (a documented, supported value) is fully exposed.

### Recommendation

1. **Bind `NonceGen` to a deposit outpoint**: Require the caller to supply the deposit outpoint in the `NonceGenRequest`. The verifier should reject requests for outpoints it has not seen from the aggregator, preventing blind session creation.
2. **Enforce `client_verification = true` at startup for all non-test builds**: Return a hard error (not just a mainnet warning) if `client_verification = false` in any production build.
3. **Per-caller rate-limit `NonceGen`**: Track call counts per TLS peer certificate and reject callers that exceed a threshold, independent of the global `RateLimitLayer`.
4. **Protect in-flight sessions from eviction**: Mark sessions that have been issued to the aggregator (i.e., whose ID has been sent in a `NonceGenFirstResponse`) as "pinned" so they cannot be evicted by new sessions.

    pub async fn nonce_gen(
        &self,
        num_nonces: u32,
    ) -> Result<(u128, Vec<PublicNonce>), BridgeError> {
        // reject if too many nonces are requested
        if num_nonces > NUM_NONCES_LIMIT {
            return Err(eyre::eyre!(
                "Number of nonces requested is too high, max allowed is {}, requested: {}",
                NUM_NONCES_LIMIT,
                num_nonces
            )
            .into());
        }
        if num_nonces == 0 {
            return Err(
                eyre::eyre!("Number of nonces requested is 0, cannot generate nonces").into(),
            );
        }
        let (sec_nonces, pub_nonces): (Vec<SecretNonce>, Vec<PublicNonce>) = (0..num_nonces)
            .map(|_| {
                // nonce pair needs keypair and a rng
                let (sec_nonce, pub_nonce) = musig2::nonce_pair(&self.signer.keypair)?;
                Ok((sec_nonce, pub_nonce))
            })
            .collect::<Result<Vec<(SecretNonce, PublicNonce)>, BridgeError>>()?
            .into_iter()
            .unzip();

        let session = NonceSession { nonces: sec_nonces };

        // save the session
        let session_id = {
            let all_sessions = &mut *self.nonces.lock().await;
            all_sessions.add_new_session_with_random_id(session)?
        };

        Ok((session_id, pub_nonces))
    }

                id: session_id.to_string(),

        });
