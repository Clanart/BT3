### Title
Free MGP incentive farming via instantly-reversible `ArbWomUp3.incentiveDeposit(mode=1)` stake - ([File: wombat/ArbWomUp3.sol])

### Summary
`ArbWomUp3.incentiveDeposit` with `_mode = 1` locks MGP for the caller via `vlMGP.lockFor` based on the WOM amount supposedly being "committed", but the underlying commitment (a `MasterMagpie` stake of `mWom`, opened through `SmartWomConvert.depositFor`) is a plain, un-locked stake that the attacker can withdraw in the very next call. The attacker therefore receives real, tier-based MGP incentive while retaining essentially full liquidity of the deposited WOM (as freely tradable `mWom`), and can repeat the deposit/withdraw cycle to keep farming MGP with only AMM swap cost as friction.

### Finding Description
`incentiveDeposit` computes `rewardToSend` from `getRewardAmount` and immediately locks it for `msg.sender` via `vlMGP.lockFor`, then performs the "commitment" side-effect through `_deposit`: [1](#0-0) 

For `_mode == 1`, `_deposit` converts WOM to `mWom` 1:1 and forwards it to `SmartWomConvert.depositFor`: [2](#0-1) 

`SmartWomConvert.depositFor` simply stakes the `mWom` into `MasterMagpie` on behalf of the attacker: [3](#0-2) 

`MasterMagpie.depositFor` (called via the registered pool helper) records the stake as a normal, non-locked `user.amount`/`user.available` position for `_for` (the attacker): [4](#0-3) [5](#0-4) 

Critically, the ordinary `withdraw` function lets the depositor (`msg.sender`) pull the staked `mWom` back out at any time with no cooldown, vesting, or lock check — only `whenNotPaused`/`nonReentrant`: [6](#0-5) [7](#0-6) 

Because `_for = msg.sender` in the `incentiveDeposit` call chain, the attacker who called `incentiveDeposit` is exactly the account entitled to call `MasterMagpie.withdraw(mWom, _amount)` right after, or even in a subsequent call within the same block/PoC, unstaking the exact `mWom` amount they just "committed." The `mWom` received is a liquid, transferable ERC20 and there is a live `wom`/`mWom` AMM pool (`womMWomPool`, referenced in `SmartWomConvert.currentRatio`/`maxSwapAmount`) that lets the attacker swap it back to WOM, recovering essentially their full principal minus AMM slippage — while the `rewardToSend` MGP is already irreversibly locked into `vlMGP` for their benefit.

Nothing in `incentiveDeposit`/`_deposit`/`depositFor` enforces that the `mWom` stay staked for any duration. The `bracketRewarded` mapping, which looks like it was meant to track/limit rewards per user, is explicitly commented as unused: [8](#0-7) 

so there is no per-user or per-tx guard preventing repeated deposit→withdraw→re-deposit cycles to keep re-triggering `getRewardAmount`/`vlMGP.lockFor` on the same recycled capital.

### Impact Explanation
This breaks the intended "backing" invariant that MGP incentives locked via `vlMGP.lockFor` correspond to WOM capital genuinely and durably committed to the campaign (staked `mWom`/`mWomSV`). An attacker can mint real, valuable locked-MGP incentive while keeping their WOM/`mWom` liquid, and can repeat the cycle to drain disproportionate MGP incentive relative to actual committed capital — this is a protocol-insolvency / incentive-drain class issue (theft of protocol-funded incentive value), scoped to `ArbWomUp3`/`SmartWomConvert`/`MasterMagpie` mWom-pool interaction.

### Likelihood Explanation
No privileged role is required — only an EOA holding WOM and gas. The only cost per loop is AMM slippage/fees swapping `mWom` back to WOM (or simply holding liquid `mWom`, which itself has market value and is not "committed" capital). The reward computation (`getRewardAmount`) depends only on the deposited `_amount` and the caller's tier from `mWomSV`, both of which are unaffected by the immediate `MasterMagpie.withdraw`, so the loop is fully repeatable and capital-efficient (limited mainly by pool depth/slippage, not by protocol-side controls).

### Recommendation
For `_mode == 1` in `_deposit`, do not route the `mWom` through a freely-withdrawable `MasterMagpie` stake if the intent is a durable commitment backing the incentive. Either: (1) route mode-1 deposits into a real lock (e.g., `mWomSV.lockFor`, as mode 2 does) instead of `MasterMagpie.depositFor`, or (2) if a liquid stake is intentional, decouple the MGP incentive size from raw `_amount` and base it on a time-weighted/committed measure (e.g., only count `mWomSV`-locked balances, as `getUserTier` already partially does), or (3) reintroduce and actually enforce the `bracketRewarded` accounting to prevent a user from re-claiming incentive on capital they've already withdrawn.

### Proof of Concept
Foundry test plan:
1. Deploy/mock `WOM`, `mWom`, `vlMGP` (real lock semantics), `MasterMagpie` with an `mWom` pool whose `helper` is `SmartWomConvert`, and `SmartWomConvert` wired to `MasterMagpie`.
2. Fund attacker EOA with `AMOUNT` WOM; record `womBefore = WOM.balanceOf(attacker)`.
3. Attacker calls `ArbWomUp3.incentiveDeposit(AMOUNT, 0, false, 1)`.
   - Assert `vlMGP` shows a locked position for attacker equal to `rewardToSend = getRewardAmount(AMOUNT, attacker, false)`.
   - Assert `MasterMagpie.stakingInfo(mWom, attacker)` shows `amount == available == AMOUNT`.
4. In the same test (immediately after, no time passing), attacker calls `MasterMagpie.withdraw(mWom, AMOUNT)`.
   - Assert call succeeds (no revert, no cooldown enforced).
   - Assert attacker now holds `AMOUNT` liquid `mWom` tokens (`mWom.balanceOf(attacker) == AMOUNT`).
5. Compute `womEquivalentAfter = mWom.balanceOf(attacker)` (treat 1:1 or route through the wom/mWom pool swap to get actual WOM back, recording slippage cost).
6. Assert: `womEquivalentAfter + mgpRewardValue > womBefore - realIlliquidCommitment`, where `realIlliquidCommitment == 0` since the `mWom` stake was fully withdrawn — demonstrating the attacker retained (near-)full liquidity of principal while keeping the locked MGP reward, violating the backing invariant.
7. Optionally loop steps 3–4 `N` times with the same capital to show cumulative `vlMGP` locked MGP grows roughly linearly with `N`, with degradation only from AMM slippage, proving repeatability.

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
