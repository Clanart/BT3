Confirmed: `addSafeDirectory()` in `app/src/lib/git/config.ts` only ever appends to the global `safe.directory` list, and there is no corresponding removal call anywhere in the codebase (no `removeSafeDirectory`/`removeGlobalConfigValue` matches, and `_removeRepository`/`repositories-store.ts`'s `removeRepository` only deletes the DB row and clears push tags — it never touches `safe.directory`). This mirrors the Velodrome bug class exactly: a trust-granting action (`_moveTokenDelegates` / `addSafeDirectory`) has no matching revocation on the corresponding teardown path (`_burn` / repository removal), leaving a permanent residual permission keyed on an identifier (NFT id / filesystem path) that can later be reused by an attacker.

### Title
Global `safe.directory` trust exception is never revoked when a repository is removed, permanently disabling Git's dubious-ownership protection for that path - (File: `app/src/lib/git/config.ts`)

### Summary
When GitHub Desktop encounters a repository whose ownership doesn't match the current user, Git refuses to operate on it and reports `kind: 'unsafe'`. The UI offers a "Trust Repository" action that calls `addSafeDirectory()`, which appends the path to the **global** `safe.directory` git config [1](#0-0) . This exception is written into `~/.gitconfig` and is not scoped to that specific repository object in GitHub Desktop's own database — it's scoped only to the raw filesystem path. When the user later removes that repository from GitHub Desktop via `_removeRepository()` / `repositoriesStore.removeRepository()`, only the app's internal repository record is deleted [2](#0-1) [3](#0-2)  — the `safe.directory` global config entry is never cleaned up.

### Finding Description
The trust exception is added from two flows: `AddExistingRepository.onTrustDirectory` [4](#0-3)  and `MissingRepository.onTrustDirectory` [5](#0-4) . Both ultimately call `addSafeDirectory(path)`, which does `git config --global --add safe.directory <path>` [6](#0-5) .

This is the "mint" side of the invariant. The "burn" side — `removeRepository()` in `repositories-store.ts` — only deletes the row from the app's local Dexie database and clears pending push tags; it never calls anything analogous to remove the path from `safe.directory` [2](#0-1) . A search of the codebase confirms there is no `removeSafeDirectory` or equivalent unset-config helper anywhere in the project.

Because `safe.directory` entries are matched purely by filesystem path string (not by repository identity, remote URL, or any content hash), once a path has been trusted it stays trusted in the user's global git config forever, even after the corresponding Repository object is deleted from GitHub Desktop.

### Impact Explanation
An attacker who can get a victim to trust a directory once (e.g., a shared/network drive, a mounted volume, a temp-extraction directory, or any path that could later be repopulated by another user/process) benefits from that trust indefinitely. If that same path is later reused — deliberately by an attacker (e.g., writing a new dubious-ownership repository at the exact path after the victim removed the old repo, such as a shared `/mnt`, `/tmp`, external drive, or CI workspace path) — Git will silently treat it as safe, skipping the "dubious ownership" check designed specifically to stop automatic execution of repository-controlled configuration/hooks belonging to another user. This defeats the entire purpose of the safety feature introduced in the changelog entries for "Surface Git's warning about unsafe directories" [7](#0-6) , and can lead to code execution via repository config/hooks under the "attacker controls a cloned/fetched repository" primitive.

### Likelihood Explanation
This requires no special access beyond the normal one-time act of clicking "Trust Repository" for a legitimately-owned-by-someone-else path (a supported, expected user action, not privilege escalation) followed by removing the repository from Desktop later — both are ordinary UI flows already present in the product. The residual global config state persists across app restarts and even across different repository objects, since matching is purely by path string.

### Recommendation
When a repository is removed via `_removeRepository()`/`repositoriesStore.removeRepository()`, also remove the corresponding entry from `safe.directory` (e.g., `git config --global --unset safe.directory <path>`) if no other tracked repository still relies on it. Alternatively, re-validate trust at every repository open rather than persisting it indefinitely, or scope trust decisions to something less reusable than a raw path.

### Proof of Concept
1. Plug in a network share or shared temp path owned by a different local user; add it in GitHub Desktop as an existing repository — Desktop reports `kind: 'unsafe'` via `getRepositoryType()` [8](#0-7) .
2. Click "Trust repository" — `addSafeDirectory(path)` appends the path to the user's global `~/.gitconfig` `safe.directory` list [6](#0-5) .
3. Remove the repository from GitHub Desktop — `_removeRepository()` deletes only the DB record; the global git config is untouched [3](#0-2) .
4. At a later time, an attacker (a different local/network user, or a process that recreates content at that same path) places a git repository with malicious `.git/config`/hooks at the identical path.
5. The victim (or an automated flow) re-adds/opens that path in GitHub Desktop (or plain `git` picks it up); Git no longer warns about dubious ownership because the path is still listed in `safe.directory`, so hooks/config from the attacker-controlled repository are trusted and can execute.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
