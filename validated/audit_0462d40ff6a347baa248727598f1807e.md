### Title
Security review coverage loss via baseline re-anchoring on interrupted/Bash-only turns - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
The `security-guidance` plugin's Stop-hook LLM review is gated by a git-diff-derived "review set" rather than a durable, append-only record of every edit made. Similar to the reported DeFi bug — where reward/fee accounting only happens inside `compound()` and any reward transfer that occurs outside that call is silently absorbed with no accounting — this plugin's vulnerability-review accounting only happens when the Stop hook successfully fires and re-baselines. If edits occur but the Stop hook is skipped or interrupted, the *next* turn's baseline capture re-anchors the git state past those edits, which then become indistinguishable from "pre-existing" content and are never sent for security review.

### Finding Description
`compute_v2_review_set` derives the set of files to review purely from `git diff` against `baseline_sha`, not from a persistent ledger of every file Claude has touched: [1](#0-0) 

The module's own docstring documents the escape hatch explicitly: a Bash-only turn that never triggers `record_touched_path` (which is normally called from `PostToolUse` on Edit/Write-style tools, not raw Bash file mutations) leaves `touched_paths` empty; if that turn is then interrupted before the Stop hook runs, the next `UserPromptSubmit` (UPS) re-captures `baseline_sha` from the *current* dirty working tree — meaning the unreviewed edits are baked into the new baseline and will never surface in a future `git diff baseline_sha` call: [2](#0-1) 

`restore_unreviewed_stop_state` exists specifically to guard against this by re-inserting `touched_paths` before an early-exit Stop hook returns, so the next UPS's "preservation guard" refuses to re-baseline: [3](#0-2) 

But this guard only works when `touched_paths` is non-empty — i.e., only when a Claude-driven Edit/Write tool call previously ran `record_touched_path`. For edits made via `Bash` (e.g., `sed -i`, `cat > file`, `python -c "open(...).write(...)"`), `touched_paths` is never populated in the first place, so the guard has nothing to restore. Once the turn ends (interrupted, timed out, or the Stop hook is otherwise skipped via one of the numerous `_skip(...)` early-return paths in `handle_stop_hook`, e.g. `_skip(2)`/`_skip(3)`/`_skip(4)`/`_skip(9)`/`_skip(6)`/`_skip(50)`), the next `UserPromptSubmit` calls `capture_git_baseline(cwd)` again, and the git-dirty content from the skipped turn becomes part of the new baseline: [4](#0-3) [5](#0-4) 

The pattern matches the external report's root cause exactly: the only code path that performs the security-sensitive accounting (`compound()` there, the Stop-hook LLM review here) is bypassed by an alternate, permitted state-mutating path (`PirexRewards.claim()` there, raw `Bash` file writes here), and the accounting mechanism (balance-delta / git-diff-vs-baseline) has no way to retroactively detect what happened before the next baseline snapshot silently swallows it.

### Impact Explanation
Any file changes written via `Bash` (rather than the `Edit`/`Write` tools that call `record_touched_path`) during a turn that gets interrupted, times out, or hits one of the Stop hook's early-skip conditions are never submitted to the LLM security scanner. Because `baseline_sha` is unconditionally re-captured from the working tree at the start of the next turn, those changes permanently disappear from all future diffs — the plugin will report "no changes since baseline" for content that was never actually reviewed. This defeats the entire purpose of the `security-guidance` Stop-hook review for a meaningful class of edits (shell-based file writes), which is exactly the kind of vector an attacker (or a compromised/malicious instruction fed to the agent) would prefer, since Bash is a normal, expected tool for the agent to use.

### Likelihood Explanation
This requires no privilege escalation — it only requires that file modifications happen through `Bash` instead of `Edit`/`Write`, which is a routine and frequent occurrence in agentic coding sessions, and that the Stop hook not complete cleanly, which the code's own extensive `_skip(...)` matrix (network unreachable, feature disabled, empty review set, etc.) shows is a common, expected occurrence, not a rare edge case. The module's docstring itself acknowledges this as a "known limitation," indicating the developers were aware the coverage gap exists but did not close it for the Bash-write case.

### Recommendation
Populate `touched_paths` (or an equivalent durable ledger) directly from `PostToolUse` events for **all** tools capable of mutating the filesystem, including `Bash`, not only for Edit/Write-style tools — e.g., by diffing the git working tree state before/after every `PostToolUse` invocation, or by unconditionally snapshotting `git status` deltas at every tool call rather than relying on selective instrumentation. Additionally, `capture_git_baseline` should never re-anchor past files that were dirty at the start of a turn but never confirmed as reviewed by a completed Stop-hook pass, regardless of whether `touched_paths` happens to be populated for that turn.

### Proof of Concept
1. Start a Claude Code session in a git repo with `security-guidance` enabled.
2. Have the agent execute a `Bash` command that writes a vulnerable pattern to a file, e.g. `python3 -c "open('app.py','a').write('os.system(user_input)')"` — this bypasses `record_touched_path` since it is not an `Edit`/`Write` tool call.
3. Force the turn to end without the Stop hook completing (e.g., interrupt the session, or the Stop hook naturally short-circuits via `_skip(9)` for other reasons in that turn).
4. Start a new turn; `UserPromptSubmit` calls `capture_git_baseline(cwd)` and stores the current (already-dirty) tree as the new `baseline_sha`.
5. On subsequent turns, `compute_v2_review_set` diffs against this new baseline; the vulnerable `app.py` content is now indistinguishable from "pre-existing" code and is never flagged, even though it was written entirely within an agent session that the security-guidance plugin was supposed to police.

def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.
