## Title
Reused `SIGHASH_SINGLE|ANYONECANPAY` payout signature lets anyone rebuild the payout transaction and frame an arbitrary operator via the OP_RETURN, causing that operator to be reimbursed for a withdrawal it never funded - ([File: core/src/builder/transaction/operator_reimburse.rs])

## Summary
`create_payout_txhandler` signs the payout transaction's input with `SpendPath::KeySpend` using the raw `user_sig` supplied off-chain by the user, which is required to carry the `SinglePlusAnyoneCanPay` sighash flag. Because that sighash flag only commits to input index 0 and output index 0, the signature remains cryptographically valid in *any* transaction an attacker constructs that reuses that same input/output pair, letting the attacker freely add their own funding inputs and pick the OP_RETURN operator identity. `Verifier::update_finalized_payouts` attributes payer identity purely from the on-chain OP_RETURN bytes with no check on who actually funded the extra inputs, so a framed operator's own `PayoutCheckerTask` will pick up this payout and drive it through the reimbursement flow.

## Finding Description
The broken binding is:

`withdrawals.payout_payer_operator_xonly_pk` (as set by `Verifier::update_finalized_payouts`) **==** the xonly public key of the party who actually funded output index 0 of the confirmed payout transaction.

Code path:
1. The operator/aggregator's `withdraw` flow requires the user signature to use `SinglePlusAnyoneCanPay` sighash - `parser::operator::parse_withdrawal_sig_params` explicitly checks this before forwarding to operators [1](#0-0) .
2. `create_payout_txhandler` builds the payout tx with the input spent via `SpendPath::KeySpend` and the raw `user_sig`, with output 0 = user payout and an OP_RETURN output carrying whichever `operator_xonly_pk` is passed in [2](#0-1) .
3. Because the signature only has `SIGHASH_SINGLE|ANYONECANPAY` semantics, Bitcoin consensus verification of the key-path spend for input 0 depends only on that input's own outpoint/prevout and the output at the same index (output 0). All other inputs and outputs (extra funding inputs, the anchor output, and critically the OP_RETURN operator pubkey) are unconstrained by the signature. An attacker who has observed `WithdrawParams.input_signature`, `input_outpoint`, `output_script_pubkey`, and `output_amount` (all public, sent to Citrea) can therefore construct an entirely new transaction: input 0 = the same withdrawal outpoint + user signature, output 0 = the same payout output, plus attacker-funded inputs to cover value/fees, plus an OP_RETURN naming any operator's `xonly_pk` (public info), and broadcast it first.
4. `Verifier::update_finalized_payouts` scans the confirmed spending transaction for the withdrawal UTXO, extracts the OP_RETURN via `parse_op_return_data`, and writes it as `payout_payer_operator_xonly_pk` with no verification of who supplied the other inputs [3](#0-2) .
5. The named operator's own `PayoutCheckerTask::run_once` queries `get_first_unhandled_payout_by_operator_xonly_pk` using its *own* xonly_pk and, finding this attacker-crafted payout attributed to itself, proceeds to `handle_finalized_payout` and the full kickoff/reimbursement pipeline automatically [4](#0-3) .
6. `handle_finalized_payout` and `validate_payer_is_operator`/`get_reimbursement_txs` only check that the stored `payout_payer_operator_xonly_pk` equals `self.signer.xonly_public_key` - they never verify that this operator's own wallet/session actually funded the payout inputs [5](#0-4) [6](#0-5) .

Existing guards do not stop this: `is_kickoff_malicious` only checks that the OP_RETURN's operator pubkey matches the pubkey that later sends the kickoff, which is trivially true since the framed operator's node itself sends that kickoff once it discovers the (forged) attribution [7](#0-6) . No component checks that the funding inputs of the payout transaction belong to the operator credited in the OP_RETURN.

## Impact Explanation
BTC leaves the move-to-vault UTXO as reimbursement to an operator that never funded the corresponding payout (the withdrawal was actually paid for out of the attacker's own wallet inputs, not the operator's). This directly matches the Critical category "an operator reimbursed for a payout it never funded." It breaks the 1:1 attribution invariant the bridge relies on for solvency accounting between fronted withdrawals and reimbursements, and is repeatable against any withdrawal/operator pair as long as the attacker is willing to front the withdrawal amount themselves (in BTC) in order to divert the on-chain reimbursement credit to an arbitrary operator.

## Likelihood Explanation
Preconditions: the withdrawal UTXO must still be unspent (attacker races the real operator's broadcast), and the framed operator must have valid deposit/kickoff signatures on file for that deposit (a normal state for any actively serving operator). The attacker cost is exactly the withdrawal `output_amount` plus fees (paid to fund output 0 and cover any extra inputs), which they must sacrifice to trigger the misattribution - this is a real BTC cost, not free, but requires only public information (`WithdrawParams` fields broadcast to Citrea, and any operator's public xonly_pk) and no privileged credentials. Feasibility is high for anyone monitoring Citrea's public withdraw calls and running a Bitcoin node/wallet.

## Recommendation
Do not rely solely on the OP_RETURN payload broadcast on-chain to attribute payout funding. Either (a) require the payout transaction to be signed/authorized end-to-end by the operator (e.g., via a dedicated operator commitment covering all inputs, not just the ANYONECANPAY-exempt ones), or (b) require the operator to pre-register the payout txid (e.g., via its own gRPC `Withdraw`/`InternalWithdraw` broadcast flow) before treating an on-chain OP_RETURN attribution as valid, cross-checking that the additional funding inputs are provably controlled by that operator (e.g., spent from a known operator wallet/output).

## Proof of Concept
Add a `cargo test` in `core/src/test` (non-mainnet, regtest, no live Citrea, using `MockCitreaClient`) that:
1. Performs a deposit and calls `withdraw` to obtain a valid `WithdrawParams` with `SinglePlusAnyoneCanPay` `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount` for withdrawal index `w`.
2. Instead of letting the real operator's payout tx confirm, constructs a new transaction: input 0 = same outpoint + same `user_sig` (key-path witness), output 0 = identical script/amount, plus an attacker-funded wallet input, plus an OP_RETURN with **operator B's** `xonly_pk` (a different, un-consenting operator registered in the test setup), and broadcasts+confirms it first.
3. Waits for verifier sync (`update_finalized_payouts`) and asserts `db.get_payout_info_from_move_txid(...).0 == Some(operator_B_xonly_pk)` while asserting the actual funding input of the confirmed transaction belongs to the attacker's test wallet, not operator B's `reimburse_addr`/collateral wallet - demonstrating the divergence between `payout_payer_operator_xonly_pk` and the true funder.
4. Optionally lets operator B's `PayoutCheckerTask` run and asserts it proceeds to `handle_finalized_payout`/kickoff for a withdrawal it never itself paid for.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
