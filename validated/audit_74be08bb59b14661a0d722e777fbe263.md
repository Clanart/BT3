### Title
Stale/removed working-directory entries bypass the "already resolved externally" guard in `_applyCopilotConflictResolutions()`, allowing silent overwrite of user changes - (File: `app/src/lib/stores/app-store.ts`)

### Summary
`_applyCopilotConflictResolutions()` is the write path that materializes Copilot's AI-generated conflict resolutions to disk before a merge/rebase/cherry-pick is continued. It contains an explicit safety check meant to stop Copilot's stale, previously-computed resolution from clobbering a file the user has *already resolved themselves* (e.g. in an external editor) while the result dialog was open. That check is keyed on finding the file in the *current* `workingDirectory.files` snapshot. When the file is no longer present in that snapshot at all (rather than present-but-resolved), the check is silently skipped and the write proceeds unconditionally — the exact same "guard exists on one path, missing on the sibling path" pattern as the reference report's missing decrement in `finalizeRedeemFor`.

### Finding Description [1](#0-0) 

```ts
      // If the user resolved this file externally (e.g. in their editor) while
      // the result dialog was open, git status will report it with no remaining
      // conflict markers. Overwriting it with Copilot's stored content would
      // silently clobber their work, so skip it and let their resolution stand.
      // This mirrors how the manual conflicts dialog determines a file is
      // resolved (`hasUnresolvedConflicts`).
      const onDiskFile = state.changesState.workingDirectory.files.find(
        f => f.path === resolution.path
      )
      if (
        onDiskFile !== undefined &&
        isConflictedFileStatus(onDiskFile.status) &&
        !hasUnresolvedConflicts(onDiskFile.status)
      ) {
        continue
      }

      await writeFile(absolutePath, resolution.resolvedContent, 'utf8')
      pathsToStage.push(resolution.path)
```

The `continue` (skip-write) branch only fires when `onDiskFile !== undefined`. If `onDiskFile` is `undefined` — because the path is no longer reported by `git status` at all (e.g. the user staged and committed a partial resolution, deleted the conflicted file, renamed it, or otherwise mutated the tree such that the path drops out of `workingDirectory.files` between the time Copilot's resolutions were generated and the time the user clicks "Continue Merge") — the guard is bypassed entirely and `writeFile()` executes with Copilot's stale `resolution.resolvedContent`. The path-traversal guard (`resolveWithin`, `app/src/lib/stores/app-store.ts:7233`) still applies, but it only prevents writes *outside* the repo — it does nothing to prevent overwriting a file the user no longer intends to have touched, or resurrecting a file the user just deleted.

Because `resolution.resolvedContent` originates from an LLM whose prompt context (`ConflictResolutionSystemPrompt`, `app/src/lib/copilot-conflict-resolution.ts:190-254`) is built from attacker-influenceable inputs — the conflicting branch content itself, plus commit messages and PR titles/descriptions pulled in as "intent" context — the content that gets silently written is not something Desktop can vouch for. The reassembly/validation logic (`validateResolutionPaths`, `parseCopilotConflictResolution`) only guards against structural malformation (wrong path set, missing hunks, literal leftover conflict markers); it performs no semantic validation of the resolved code and no re-check against the live working tree at apply time.

### Impact Explanation
This lets a stale, unreviewed AI-generated file resolution be committed on the user's behalf without the confirmation the code explicitly tries to guarantee ("skip it and let their resolution stand"). In the worst case:
- A file the user deleted moments before clicking "Continue Merge" is silently resurrected with Copilot's (attacker-influenced) content and staged via `git add` (`app/src/lib/stores/app-store.ts:7262-7268`).
- A file the user already partially hand-resolved and whose on-disk state fell out of the `workingDirectory.files` snapshot for any reason gets overwritten and staged without the "already resolved externally" protection the comment describes.

This matches the requested impact category of "silent corruption of what the user commits or pushes," driven by content whose provenance traces back to attacker-controlled repository/PR/commit data.

### Likelihood Explanation
Requires the Copilot conflict-resolution feature to be enabled/used (`enableCopilotConflictResolution()`) and a state change to the working directory between resolution generation and the user clicking "Continue Merge" — a normal, easily triggered sequence in an interactive merge/rebase/cherry-pick flow, not requiring elevated privileges or local/physical access. The precondition (attacker supplies the conflicting content/commit messages/PR text that shapes the model's `resolvedContent`) is inherent to any repository the user is merging from, satisfying the "attacker controls a cloned/fetched repository" threat model.

### Recommendation
Treat "not found in the current working-directory snapshot" the same as "found but no longer conflicted": skip the write (and drop the stale resolution) instead of defaulting to writing it. Re-derive the guard from a fresh `git status`/`hasUnresolvedConflicts` check performed at apply time rather than the state captured when Copilot's suggestion was generated, and require the file to still be present and still report unresolved conflicts before overwriting it.

### Proof of Concept
1. Trigger a merge/rebase with a conflicting file `src/a.ts` and invoke "Resolve with Copilot" (`_startCopilotConflictResolution`), which stores `copilotResolutions` for `src/a.ts`.
2. Before clicking "Continue Merge", delete `src/a.ts` from disk (or `git rm` it) so that the next `git status` read no longer includes `src/a.ts` in `workingDirectory.files`.
3. Click "Continue Merge", triggering `_applyCopilotConflictResolutions`. Because `onDiskFile` is now `undefined` for `src/a.ts`, the "already resolved externally" `continue` branch is skipped, and `writeFile(absolutePath, resolution.resolvedContent, 'utf8')` recreates `src/a.ts` with Copilot's stale content, which is then staged via `git add`.
4. The user's explicit deletion is silently reverted and replaced with unreviewed AI-generated content in the commit, with no dialog/confirmation surfaced.
