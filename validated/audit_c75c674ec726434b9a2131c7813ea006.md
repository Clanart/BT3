## Answer

Confirmed vulnerability. `Codec.DecodeHeader` mishandles `DIGEST_ITEM_OTHER` entries and desyncs the byte-slice cursor for every digest that follows.

### Finding

In the digest-parsing loop, the `DIGEST_ITEM_OTHER` branch only sets a boolean flag and never consumes the item's SCALE-encoded payload: [1](#0-0) 

Compare this to the sibling branches (`DIGEST_ITEM_CONSENSUS`, `DIGEST_ITEM_SEAL`, `DIGEST_ITEM_PRERUNTIME`), which all call `decodeDigestItem` to advance the slice by the item's length-prefixed data: [2](#0-1) 

Per Substrate's SCALE format, `DigestItem::Other(Vec<u8>)` is encoded as a compact-length-prefixed `Vec<u8>` following the 1-byte variant discriminant (`0`). Since `DecodeHeader` reads only the discriminant byte and never consumes the compact length or the following data bytes, `slice.offset` is left pointing into the middle of the `Other` digest's payload. Every subsequent digest is then decoded starting from the wrong offset: the next digest's real "kind" byte is actually read from inside the prior `Other` digest's data, and so on for the rest of the digest list.

### Downstream effect

The decoded `Digest[]` is consumed by `HeaderImpl.stateCommitment`, which scans for a `Consensus` digest with `consensusId == "ISMP"` (mmrRoot/childTrieRoot) and one with `consensusId == "ISTM"` (timestamp): [3](#0-2) 

This is invoked directly from the SP1 BEEFY consensus client's intermediate-state derivation path used to update Hyperbridge's trusted state commitments: [4](#0-3) 

If an `Other` digest precedes the real `ISMP`/`ISTM` consensus digests in a header, the misaligned parse can cause the loop to miss the true `ISMP` digest entirely (reverting via `TimestampNotFound()`) or, depending on byte content, misinterpret unrelated bytes as a spurious `Consensus` digest with a colliding 4-byte id, corrupting the derived `mmrRoot`/`childTrieRoot`/`timestamp` fed into `StateCommitment`.

### Assessment of exploitability

The header bytes processed here are not attacker-supplied SCALE payloads chosen freely — in `SP1Beefy.verify`, `para.header` is constrained by the ZK proof's public inputs via `keccak256(proof.headers[i].header)` and by the finality/authority-set checks, so the byte content must match an actual finalized parachain header: [5](#0-4) 

This means practical exploitation depends on a real chain block genuinely containing a `DigestItem::Other` entry ahead of the `ISMP`/`ISTM` consensus digests, which is not something the current runtime/pallet code in this repo emits — no `DigestItem::Other` usage was found in the Substrate pallets. That said, this is still a decoder correctness bug independent of who controls the header content: `DecodeHeader` does not faithfully mirror the on-chain SCALE digest sequence whenever an `Other` digest is present, which breaks the stated invariant and is a legitimate implementation defect that should be fixed regardless of current runtime digest usage, since any future digest emission (by this or any runtime module) or any parachain runtime already emitting `Other` digests would silently corrupt state-commitment derivation.

### Title
Codec.DecodeHeader fails to consume DIGEST_ITEM_OTHER payload, desyncing subsequent digest parsing - (File: evm/src/consensus/Codec.sol)

### Recommendation
In the `DIGEST_ITEM_OTHER` branch, read the compact-length-prefixed `Vec<u8>` (via `ScaleCodec.decodeUintCompact` + `Bytes.read`) just as `decodeDigestItem` does for the other variants, and store the resulting bytes in `digest.other`, so the cursor advances correctly past the item.

### Proof of Concept
Call `Codec.DecodeHeader` (exposed via the `BeefyConsensusClientTest.DecodeHeader` test harness) on a crafted header whose digest list is `[Other(data), Consensus("ISMP", commitmentBytes)]`. The returned `Digest[]` will not have `digests[1].isConsensus && digests[1].consensus.consensusId == "ISMP"` matching the real ISMP payload — either the offset misreads garbage as the kind byte, or the "ISMP" bytes end up at the wrong slice offset, demonstrating the desync described above.

    /// @dev Decodes a SCALE-encoded digest item (4-byte consensus id + length-prefixed data).
    function decodeDigestItem(ByteSlice memory slice) internal pure returns (DigestItem memory) {
        bytes4 id = Bytes.toBytes4(read(slice, 4), 0);
        uint256 length = ScaleCodec.decodeUintCompact(slice);
        bytes memory data = Bytes.read(slice, length);
        return DigestItem(id, data);
    }
