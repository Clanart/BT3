### Title
Unauthenticated/Unrestricted SSRF and Port-Scan Primitive via DataLayer Mirror/Subscription URL Fetch - (File: chia/data_layer/data_layer.py, chia/data_layer/download_data.py)

### Summary
The DataLayer service accepts arbitrary, attacker-controlled URLs — both via the local `subscribe`/`add_mirror` RPCs and via on-chain mirror coins that any wallet user can create with `dl_new_mirror` — and then makes outbound `aiohttp` requests to those URLs during its periodic sync loop, with no validation of scheme, host, or destination (no SSRF protections against internal/loopback/link-local addresses). This is the same bug class as the Homarr `widget.app.ping` SSRF/port-scan primitive: server-initiated fetches to attacker-chosen URLs whose success/failure/timing an attacker can use to fingerprint internal network topology.

### Finding Description
`DataLayer.subscribe()` stores caller-supplied URLs with no validation beyond trimming a trailing slash: [1](#0-0) 

More importantly, mirror URLs are not local-only: any wallet user can publish mirror URLs on-chain for any DataLayer store via `add_mirror`/`dl_new_mirror`, which any other node subscribing to that store id will subsequently pull and use as fetch targets: [2](#0-1) 

During the periodic sync loop, `update_subscription()` calls `update_subscriptions_from_wallet()` then `fetch_and_validate()`, which iterates the (attacker-supplied) server URLs and attempts a download from each one: [3](#0-2) [4](#0-3) 

The actual outbound request is a raw `aiohttp` GET built by simple string concatenation of the attacker-controlled URL with no scheme allowlist and no destination restriction (e.g., no blocking of `localhost`, RFC1918/loopback/link-local addresses, or non-HTTP schemes): [5](#0-4) 

Because outcomes differ observably — a successful HTTP response vs. `aiohttp.client_exceptions.ClientConnectorError` (logged distinctly) vs. a timeout — an attacker can use this to probe whether a given host:port on the DataLayer node's network is open, closed, or filtered, exactly mirroring the Homarr port-scan primitive: [6](#0-5) 

### Impact Explanation
Any node that runs the DataLayer service and subscribes to a store (a normal, expected DataLayer client action, and something an attacker can trigger indirectly by advertising mirrors for a store others subscribe to, or directly via the `subscribe`/`add_mirror` local RPCs) will make server-side HTTP requests to arbitrary attacker-chosen destinations. This is a classic SSRF: it can be used to port-scan the DataLayer host's internal network/localhost services, probe cloud metadata endpoints, or generate arbitrary outbound traffic from the victim's infrastructure. It does not directly cause coin-state divergence, inflation, or unauthorized coin movement, but it is a genuine, reachable server-side request forgery/port-scan primitive against a DataLayer client, matching the Medium-severity classification of the analogous Homarr report.

### Likelihood Explanation
Likelihood is high for any operator who runs DataLayer and subscribes to third-party stores (the intended use case for public/shared DataLayer stores), since mirror URLs are attacker-controllable and require no special privilege beyond a normal wallet spend (`dl_new_mirror`). The `subscribe`/`add_mirror` RPC path additionally requires local RPC access, but no additional validation exists once reached.

### Recommendation
- Validate mirror/subscription URLs before storing or fetching from them: enforce an `http(s)://` scheme allowlist and reject requests to loopback, link-local, and private-network addresses (SSRF-safe URL/IP validation) both in `DataLayer.subscribe()`/`add_mirror()` and in `http_download()`/`get_downloader()`.
- Consider resolving the hostname and checking the resolved IP against a blocklist immediately before each request (to avoid TOCTOU/DNS-rebinding bypass of scheme/host checks).
- Rate-limit and normalize error handling so that connection failures, timeouts, and non-2xx responses are not distinguishable in ways useful for port-scanning (e.g., uniform backoff/logging regardless of failure reason).

### Proof of Concept
1. Attacker creates a DataLayer store and mirror pointing at an internal target, e.g. via wallet RPC:
   `dl_new_mirror(launcher_id=<store_id>, urls=["http://127.0.0.1:22"], amount=..., fee=...)` — reachable by any wallet user, see `add_mirror`: [7](#0-6) 
2. Victim node runs DataLayer and subscribes to `<store_id>` (or already tracks it as an owned/replicated store).
3. On the next sync cycle, `update_subscription()` → `update_subscriptions_from_wallet()` pulls the mirror URL from chain, then `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues `GET http://127.0.0.1:22/<filename>` from the victim node: [8](#0-7) 
4. Attacker observes whether the request results in `aiohttp.client_exceptions.ClientConnectorError` (closed/filtered port, logged as "Server unavailable") versus an HTTP-level response/timeout (open port speaking or not speaking HTTP), inferring port state on the victim's internal network — the same distinguishing behavior described in the Homarr CVE.

    async def get_mirrors(self, store_id: bytes32) -> list[Mirror]:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
        return [mirror for mirror in mirrors if mirror.urls]

    async def update_subscriptions_from_wallet(self, store_id: bytes32) -> None:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
