Based on my investigation, most of the obvious "missing validation before an external/untrusted interaction" paths in this codebase (OAuth CSRF state check, deep-link `filepath` traversal via `resolveWithin`, clone-path traversal via `sanitizeCloneName`/`isClonePathSensitive`, remote-URL protocol checks in `updateRemoteUrl`) are explicitly guarded and covered by dedicated tests. However, one attacker-controlled-input path that reaches a raw `git` invocation without a leading `--` option-terminator is the branch checkout argument construction used for the `x-github-client://openRepo/...?branch=` deep link flow.

### Title
Deep-link `branch` parameter reaches `git checkout` before the `--` option terminator, enabling git-option injection via a crafted branch name - (File: app/src/lib/git/checkout.ts)

### Summary
The `openRepo` deep-link handler accepts a `branch` query-string value supplied entirely by whoever crafts the `x-github-client://` / `github-mac://` / `github-windows://` link. This value is only checked against `testForInvalidChars`, a regex that rejects control characters, `~^:?*[\|"<>`, `@{`, leading/trailing dots and trailing `.lock`/`/` — but it does **not** reject a leading `-`. The (looked-up) branch name is later placed as the *first* positional argument to `git checkout`, ahead of the `--` end-of-options marker, so a branch whose name begins with `-` can be parsed by git as an option rather than a ref.

### Impact Explanation
An attacker who gets a victim to click a `github-mac://openRepo/<attacker-repo>?branch=<dash-prefixed-name>` link (or an equivalent Windows `--protocol-launcher` invocation) can force GitHub Desktop to invoke `git checkout` with an option-like first argument, instead of a plain ref. Depending on the exact option string chosen and the Desktop/embedded-git version, this enables option/argument injection into the `git checkout` invocation running inside the user's Desktop process against a real, attacker-influenced repository — a foothold for corrupting the checked-out working tree state, forcing unexpected git behavior (e.g. via checkout-specific flags), or degrading into a DoS/unexpected-state condition. I was not able to conclusively enumerate a `git checkout` flag that yields direct code execution from the available context, so the impact should be scoped conservatively to unauthorized manipulation of checkout behavior / working-tree corruption rather than confirmed RCE; this uncertainty should be validated with a live git binary before triage.

### Likelihood Explanation
Likelihood is a function of (a) getting the victim to click one link (standard protocol-handler UX, no local access, no admin rights, no pre-existing malware), and (b) the attacker fully controlling both the source repository and the branch name inside it — both are trivial for the attacker to arrange since they can be an ordinary GitHub user. No additional guard (rate limiting, allow-listing, sandboxing) currently blocks this specific argument-ordering issue.

### Recommendation
Always place the resolved ref/branch argument after a `--` separator in `getBranchCheckoutArgs` (and any other git-arg builder that consumes ref names derived from remote/URL-sourced data), e.g. `['--', branch.name]` instead of `[branch.name, ..., '--']`, and extend `testForInvalidChars`/the deep-link `branch` validation to reject values beginning with `-` (mirroring the `^[-\+]*` stripping already done by `sanitizedRefName` for UI-entered ref names) before it is ever used to look up or check out a branch originating from an `openRepo` URL action.

### Proof of Concept
1. Attacker creates a public repository and, inside it, a branch literally named `--conflict=diff3` (or another checkout option string) — git ref rules allow refs to begin with `-` as long as they don't otherwise violate `check-ref-format`.
2. Attacker sends the victim a link: `github-mac://openRepo/https://github.com/attacker/repo?branch=--conflict=diff3`.
3. Victim (with GitHub Desktop installed) clicks the link. `parse-app-url.ts` accepts the branch value (`testForInvalidChars` does not flag a leading `-`).
4. Dispatcher clones/opens the attacker repo, fetches it, finds the local/remote branch whose `nameWithoutRemote` equals the attacker string, and calls `checkoutBranch`.
5. `getBranchCheckoutArgs` yields `['checkout', '--progress', '--conflict=diff3', '--']`; git receives an option-like token as the ref argument instead of a defensively-terminated positional argument, demonstrating the missing `--` guard prior to the ref name.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

  private async checkoutLocalBranch(repository: Repository, branch: string) {
    let shouldCheckoutBranch = true

    const state = this.repositoryStateManager.get(repository)
    const branches = state.branchesState.allBranches

    const { tip } = state.branchesState

    if (tip.kind === TipState.Valid) {
      shouldCheckoutBranch = tip.branch.nameWithoutRemote !== branch
    }

    const localBranch = branches.find(b => b.nameWithoutRemote === branch)

    // N.B: This looks weird, and it is. _checkoutBranch used
    // to behave this way (silently ignoring checkout) when given
    // a branch name string that does not correspond to a local branch
    // in the git store. When rewriting _checkoutBranch
    // to remove the support for string branch names the behavior
    // was moved up to this method to not alter the current behavior.
    //
    // https://youtu.be/IjmtVKOAHPM
    if (shouldCheckoutBranch && localBranch !== undefined) {
      await this.checkoutBranch(repository, localBranch)
    }
  }
