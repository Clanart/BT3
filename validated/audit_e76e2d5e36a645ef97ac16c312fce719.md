### Title
Unhandled `IndexError`/`ValueError` in DataLayer mirror-coin parsing crashes wallet coin-state processing - ([File: chia/wallet/db_wallet/db_wallet_puzzles.py])

### Summary
`get_mirror_info()`, which is invoked by `DataLayerWallet.coin_added()` for *any* coin observed on-chain whose puzzle hash equals the well-known DataLayer "mirror" puzzle hash, indexes into an attacker-controlled memo list without validating its length or content. An unprivileged spend-bundle submitter can create a coin with the mirror puzzle hash and a `CREATE_COIN` condition whose memo argument is empty (or otherwise malformed), causing an uncaught `IndexError`/`ValueError` when any wallet that runs a `DataLayerWallet` processes that coin during normal sync.

### Finding Description
`create_mirror_puzzle()` produces a fixed, non-owner-specific puzzle hash (`MIRROR_PUZZLE_HASH`) that DataLayer wallets treat as a globally "interesting" puzzle hash so they can discover mirror-server announcements from any peer, not just their own coins [1](#0-0) .

When a coin with that puzzle hash confirms, `DataLayerWallet.coin_added()` fetches the parent coin's spend and calls `get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)` unconditionally, with no try/except around the call: [2](#0-1) 

`get_mirror_info()` runs the (attacker-supplied) parent puzzle/solution, scans conditions for a `CREATE_COIN` that targets the mirror puzzle hash, and then blindly indexes into the memo list:
```python
memos: list[bytes] = condition.at("rrrf").as_python()
launcher_id = bytes32(memos[0])
return launcher_id, [url for url in memos[1:]]
``` [3](#0-2) 

Because the `memos`/hint argument of a `CREATE_COIN` condition is fully attacker-controlled CLVM data (any submitter can craft a spend bundle whose puzzle produces `(CREATE_COIN <mirror_puzzle_hash> <amount> ())`, i.e., an empty or absent memo list), `memos[0]` raises `IndexError` (or `bytes32(memos[0])` raises `ValueError` if the first memo element is not 32 bytes). This is the same class of bug as the reported Wireshark issue: a dissector/parser that trusts an externally supplied variable-length field to always contain an expected element, and dereferences/indexes it without a length check, crashing the parsing code path.

### Impact Explanation
The exception propagates out of `get_mirror_info()` through `DataLayerWallet.coin_added()`, which is called from the generic `WalletStateManager` coin-processing dispatch used during normal peer-driven sync of confirmed coin states. Any wallet operator with a `DataLayerWallet` enabled will hit this code path whenever an attacker publishes a transaction that creates a coin at the mirror puzzle hash with a malformed memo list — something requiring no special privilege beyond submitting an ordinary spend bundle to the network. This matches the "spend-triggered transaction-processing halt" category: it disrupts wallet coin-state ingestion for arbitrary third-party wallets (DoS on the wallet's sync/processing task), not just the attacker's own node.

### Likelihood Explanation
Likelihood is high for any user running a DataLayer-enabled wallet: the mirror puzzle hash is a fixed, publicly known constant (`create_mirror_puzzle().get_tree_hash()`), and constructing a spend whose CLVM output creates a coin to that puzzle hash with an empty/short memo list requires only basic CLVM crafting — no special coin ownership, signature bypass, or privileged access.

### Recommendation
In `get_mirror_info()` (chia/wallet/db_wallet/db_wallet_puzzles.py), validate `memos` length and element size (`len(memos) >= 1` and `len(memos[0]) == 32`) before constructing `bytes32(memos[0])`, and raise the existing `ValueError("The provided puzzle and solution do not create a mirror coin")` on malformed input instead of allowing an unhandled exception. Additionally, wrap the call to `get_mirror_info()` in `DataLayerWallet.coin_added()` in a try/except that logs and safely returns, consistent with how the code already tolerates other malformed/attacker-controlled hint data elsewhere in the wallet sync path (e.g., the `IndexError` handling already present in `DataLayerWallet.singleton_removed()`).

### Proof of Concept
1. Craft a spend bundle where the spent coin's puzzle, when run with its solution, outputs a condition list containing `(CREATE_COIN <MIRROR_PUZZLE_HASH> <amount> ())` (empty memo/hint list) — trivial to construct with a `(q . ((51 0xMIRRORHASH 1 ())))` style puzzle.
2. Submit the spend bundle to the network via the standard mempool submission path; it is a normal, validly-signed spend with no special coin, so it is accepted and confirmed.
3. Any node running a `DataLayerWallet` will, upon seeing the new coin at `MIRROR_PUZZLE_HASH`, invoke `coin_added()` → `get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)`, which executes `memos[0]` on the empty list, raising an unhandled `IndexError` inside the wallet's coin-state processing path [2](#0-1) [4](#0-3) .

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
```
