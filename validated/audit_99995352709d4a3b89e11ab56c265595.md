### Title
Address-association precompile accepts signatures without domain separation, enabling forced/unwanted balance migration via signature replay - (File: precompiles/addr/addr.go)

### Summary
The `addr` precompile's `associate` method (address `0x0000000000000000000000000000000000001004`) authenticates a caller-supplied identity claim purely from a raw ECDSA signature over `keccak256(customMessage)`, where `customMessage` is an attacker-controlled string, with no on-chain enforcement that it is an EIP-191 `personal_sign`-prefixed, Sei-specific association message. This mirrors the root cause of CVE-2020-16251 (Vault GCE auth bypass): an authentication artifact (there, a GCP-signed JWT; here, an ECDSA signature) is accepted as proof of intent for a specific privileged action without verifying it was actually produced for that action/scope, letting an out-of-context but validly-signed artifact be replayed to trigger the privileged operation. [1](#0-0) 

### Finding Description
`associate()` decodes `v, r, s` and an arbitrary `customMessage` string, computes `customMessageHash = keccak256(customMessage)`, recovers the signer's pubkey via `helpers.GetAddresses`, and immediately links the recovered EVM/Sei address pair: [2](#0-1) 

Nothing on-chain requires `customMessage` to be the EIP-191 `"\x19Ethereum Signed Message:\n<len>"`-wrapped, Sei-specific text that the client UI conventionally uses (that envelope/text, e.g. `ASSOCIATE_MESSAGE`/`eip191Envelope`, exists only in the integration test / front-end helper, not in the contract logic). Because the digest signed is just `keccak256(customMessage)` with `customMessage` fully attacker-chosen, any raw ECDSA signature a victim has produced over a digest whose exact preimage bytes are known — most notably an EIP-712 typed-data signature, where the signed digest is `keccak256("\x19\x01" || domainSeparator || structHash)` with no further wrapping — can be replayed by supplying those exact preimage bytes as `customMessage`. The signature does not need to have anything to do with "associating addresses"; it only needs to be a raw signature over a reproducible byte string.

Once the signature recovers successfully, `associateAddresses` performs the association unconditionally (only guarding against double-association) and calls `AssociationHelper.AssociateAddresses`, which migrates the direct-cast account's `usei`, other spendable coins, and wei balance to the new Sei address, and deletes the direct-cast account outright if it has no locked coins: [3](#0-2) [4](#0-3) 

The project has already recognized and fixed this exact bug class for the EIP-7702 SetCode authorization path, explicitly requiring the authorization's own chain ID to match before pre-associating an authority, because a cross-chain/out-of-context signature can be replayed to "force-associate them — migrating their direct-cast balance and orphaning staking/distribution state — even though the EVM skips the wrong-chain authorization": [5](#0-4) 

That same domain-binding discipline was not applied to the generic `associate` precompile method, which accepts any digest/preimage pair with no scope check at all.

### Impact Explanation
Any address whose owner has produced a raw (unwrapped) ECDSA signature over a publicly-derivable byte string — most commonly an EIP-712 signature used for approvals, permits, orders, or other dApp interactions on Sei or any other EVM chain the owner also uses — can be force-associated on Sei by an unrelated third party, without the owner ever intending or consenting to a Sei address association. This:
- Triggers an involuntary transfer of the direct-cast account's `usei`/wei balance to the newly linked Sei address (`MigrateBalance`), i.e., an unauthorized state-changing transfer executed via the precompile without the account holder's consent for this specific action.
- Can delete/"orphan" the direct-cast account object, matching the exact harm the project's own code comments describe for the analogous SetCode case (orphaned staking/distribution state).
- Locks in an address mapping (`SetAddressMapping`) prematurely and permanently, which the code elsewhere treats as sensitive enough to warrant explicit chain-ID/context checks before doing it opportunistically.

This satisfies "unauthorized transfer via precompile" and disruptive/irreversible account-state change categories from the validation criteria, even though the recipient of the migrated funds is still the victim's own derived Sei address rather than the attacker's.

### Likelihood Explanation
Exploitation requires only: (1) a signature (v, r, s) produced by the victim over some digest, and (2) knowledge of the exact byte preimage of that digest. Both are satisfied trivially for EIP-712 signatures (very common in DeFi/NFT approvals) because the preimage (`0x19 0x01 || domainSeparator || structHash`) is always public alongside the signature (it must be, for anyone to verify or relay the signature). No cooperation from the victim beyond having ever signed one EIP-712 message with any wallet is needed; the replaying transaction can be submitted by anyone as an ordinary EVM call to the `addr` precompile.

### Recommendation
Enforce domain separation on-chain in `associate()`:
- Require `customMessage` to begin with the exact EIP-191 personal-sign prefix `"\x19Ethereum Signed Message:\n"` followed by a Sei-specific, fixed association string (or otherwise bind the digest to a Sei-specific domain separator, e.g. include chain ID and a purpose tag, similar to the `AuthorityToPreAssociate` chain-ID check already used for SetCode authorizations).
- Reject any `customMessage` that does not match this expected format/prefix before recovering and applying the association.
- Apply the same fix to the legacy versioned copies of `addr.go` under `precompiles/addr/legacy/*` if they are still reachable by any active EVM version.

### Proof of Concept
1. Victim signs a normal EIP-712 message (e.g., a token `Permit` or DEX order) with their EVM key on any chain; the signature `(v, r, s)` and structured data are visible on-chain/relayed as usual.
2. Attacker computes the raw preimage bytes `data = 0x19 0x01 || domainSeparator || structHash` used for that EIP-712 signature.
3. Attacker calls the `addr` precompile's `associate(v, r, s, customMessage)` on Sei with `customMessage = data` and the victim's `(v, r, s)`.
4. `crypto.Keccak256Hash([]byte(customMessage))` reproduces the exact digest the victim signed, `helpers.GetAddresses` recovers the victim's real EVM/Sei address pair, and `associateAddresses` links them and migrates the victim's direct-cast balance — all without the victim ever calling `associate` or intending a Sei address association. func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// AuthorityToPreAssociate returns the authority of an EIP-7702 authorization that should be
// associated with its true (pubkey-derived) Sei address before execution, or ok=false.
//
// It mirrors go-ethereum's StateTransition.validateAuthorization (chain id, nonce overflow,
// authority code, and account-nonce checks) so that pre-association happens only for
// authorizations the EVM will actually apply, and additionally skips authorities that are
// already associated. Mirroring validateAuthorization is essential to security: the
// authorization sig hash is computed from the auth's own ChainID, so recovery and
// auth.Authority() succeed for an authorization signed for ANY chain. Without these checks a
// publicly-visible authorization a user signed for another chain (e.g. Ethereum mainnet)
// could be replayed in a sponsored Sei SetCode tx to force-associate them — migrating their
// direct-cast balance and orphaning staking/distribution state — even though the EVM skips
// the wrong-chain authorization and installs no delegation.
func AuthorityToPreAssociate(ctx sdk.Context, k AuthorizationStateReader, auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, bool) {
	// Chain ID must be null or match the local chain.
	if !auth.ChainID.IsZero() && auth.ChainID.CmpBig(k.ChainID(ctx)) != 0 {
		return common.Address{}, nil, nil, false
	}
	// Nonce must not overflow (EIP-2681).
	if auth.Nonce+1 < auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	evmAddr, seiAddr, pubkey, err := RecoverAddressesFromAuthorization(auth)
	if err != nil {
		return common.Address{}, nil, nil, false
	}
	// Cross-check against go-ethereum's authoritative recovery so we only ever act on the
	// exact address SetCode would target during execution.
	if authAddr, aerr := auth.Authority(); aerr != nil || authAddr != evmAddr {
		return common.Address{}, nil, nil, false
	}
	// Authority must have no code, or only an existing delegation designator.
	if code := k.GetCode(ctx, evmAddr); len(code) != 0 {
		if _, ok := ethtypes.ParseDelegation(code); !ok {
			return common.Address{}, nil, nil, false
		}
	}
	// Authority account nonce must match the authorization nonce.
	if k.GetNonce(ctx, evmAddr) != auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	// Already-associated authorities need no pre-association (and cannot be re-mapped).
	if _, associated := k.GetEVMAddress(ctx, seiAddr); associated {
		return common.Address{}, nil, nil, false
	}
	return evmAddr, seiAddr, pubkey, true
