### Title
Just-in-time staking into `DelegateVoteRewardPool` via unguarded `harvestAll()` allows theft of yield accrued by prior voters - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool.harvestAll()` has no access-control modifier and can be called by anyone, including immediately after the caller stakes voting weight into the pool via `WombatBribeManager.vote(delegatedPool, +X)`. Because reward distribution in `_queueNewRewardsWithoutTransfer` is based purely on the instantaneous `totalSupply` at the moment of harvest (not a time-weighted or snapshot-based accounting), an attacker can stake right before triggering a harvest of previously-accrued, un-realized bribes and capture a pro-rata share of yield that was earned entirely before they staked, diluting the payout owed to long-term delegators.

### Finding Description
`WombatBribeManager.vote()` lets any vlMGP holder vote into the special `delegatedPool` pool entry, which routes to `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, X)` on `DelegateVoteRewardPool`: [1](#0-0) . `stakeFor` in `DelegateVoteRewardPool` immediately increases `totalSupply` and checkpoints the caller's `userRewardPerTokenPaid` to the *current* `rewardPerTokenStored` via the `updateRewards` modifier before adding the new balance: [2](#0-1) [3](#0-2) .

`harvestAll()` has no modifier at all and is externally callable by anyone: [4](#0-3) . It pulls in all bribes accrued by `DelegateVoteRewardPool`'s underlying votes (`claimAllBribes(address(this))`) and immediately runs `_manageRewards` → `_queueNewRewardsWithoutTransfer`, which spreads the newly harvested amount over the **current** `totalSupply`: [5](#0-4) .

Because the harvested bribe amount `B` reflects value accrued over the entire period since the last harvest (contributed by long-term voters), but is divided by `totalSupply` **after** the attacker's fresh stake `X` is added, the attacker's `earned()` immediately reflects `X*B/(oldSupply+X)` even though they contributed zero time to earning `B`. This dilutes the share that existing/prior stakers would otherwise have received. The attacker can then call `getReward(attacker)` (via `DelegateVoteRewardPool.getReward` or `WombatBribeManager.claimAllBribes`) or `unvote()` (which auto-claims on withdraw) in the same or a following transaction to realize the stolen yield and exit: [6](#0-5) [7](#0-6) .

No existing check prevents this: `stakeFor` has no lock/cooldown, `harvestAll()` has no access restriction, and `_queueNewRewardsWithoutTransfer`'s reward-per-token model is not time-weighted, so the checkpoint mechanism (normally sufficient to prevent retroactive claims on *continuously accruing* rewards) does not protect against lump-sum harvests of bribes that accumulated while the attacker was not a participant.

### Impact Explanation
This is theft of unclaimed yield: the attacker extracts a pro-rata share of bribes that accrued to `DelegateVoteRewardPool`'s underlying votes before the attacker ever staked, at the expense of prior delegators whose effective share of the harvested lump sum is diluted. This matches the Immunefi "theft of unclaimed yield" impact class. The magnitude scales with the size of the unharvested bribe backlog and the size of the attacker's stake relative to `totalSupply` at harvest time.

### Likelihood Explanation
The attack requires only: (1) holding/locking enough vlMGP to vote, (2) calling `vote([delegatedPool],[+X])`, and (3) calling the fully permissionless `harvestAll()` — all of which can be sequenced by an unprivileged EOA in a single transaction or back-to-back transactions in the same block, with no special capital beyond vlMGP acquisition and no dependency on privileged roles. It is repeatable any time there is an unharvested bribe backlog on the `votePools` that `DelegateVoteRewardPool` has voted into (which is expected under normal operation, since harvesting is otherwise driven periodically by `castVotes`).

### Recommendation
Prevent newly-staked balances from participating in rewards that were accrued before the stake was made. Options:
- Force a harvest (checkpoint `rewardPerTokenStored` against the *old* `totalSupply`) inside `stakeFor`/`vote` before increasing `totalSupply`, so any pending-but-unharvested bribes captured by a subsequent `harvestAll()` are still split only among the pre-existing stakers proportionally, and add a mandatory minimum holding period before a staker becomes eligible for a given harvest.
- Alternatively, restrict `harvestAll()` to be invoked only as part of `castVotes` flows (still doesn't fully close JIT staking around `vote()`), combined with an epoch/snapshot-based distribution where rewards for epoch N only accrue to balances that existed at the start of epoch N.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool`, `WombatBribeManager`, mock `vlMGP`, mock underlying Wombat pool/bribe contracts, and register `delegatedPool` via `addPool`.
2. Simulate long-term voter `Alice`: lock vlMGP, `vote([delegatedPool],[+100])`, and let a mocked underlying bribe of `1000` reward tokens accrue on the votePools that `DelegateVoteRewardPool` has voted into (via `_updateVote`), so that when harvested it becomes claimable via `claimAllBribes(address(this))`.
3. In the same block, deploy attacker EOA/contract: lock minimal vlMGP, call `vote([delegatedPool],[+100])` to double `totalSupply` to `200`, then immediately call `DelegateVoteRewardPool.harvestAll()` directly (no privileged caller needed).
4. Assert `earned(attacker, rewardToken)` ≈ `500` (i.e., `100/200 * 1000`) despite the attacker having staked zero blocks/time before the bribe was earned.
5. Assert `earned(Alice, rewardToken)` is correspondingly reduced from the `1000` she would have received had the attacker not front-run the harvest, to `500`, demonstrating value transfer/dilution.
6. Show attacker can call `getReward(attacker)` (or `unvote`) to actually withdraw the `500` tokens and exit the position immediately, completing the round-trip theft with no time-based exposure.

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
