### Title
`internal_get_emergency_stop_tx` is reachable by unauthenticated callers when `client_verification=false` because `Interceptors::Noop` never enforces the `Internal*` method restriction - ([File: core/src/rpc/interceptors.rs], [File: core/src/servers.rs])

### Summary
The `is_internal()` check that is supposed to restrict `Internal*`-prefixed aggregator RPCs (like `internal_get_emergency_stop_tx`) to the aggregator's own self-call is implemented only inside the `Interceptors::OnlyAggregatorAndSelf` variant. `create_grpc_server` only constructs that variant when `config.client_verification == true`; otherwise it installs `Interceptors::Noop`, which unconditionally forwards every request with no identity or method-prefix check at all.

### Finding Description
The claimed binding is: `caller reaching Internal* method == self.our_cert` (per `is_internal`/`OnlyAggregatorAndSelf` semantics). Tracing the code:

- `is_internal(&req)` inspects the injected `grpc-method` header and returns true if the method name starts with `"Internal"` [1](#0-0) .
- This check is only invoked from `only_aggregator_and_self`, which itself is only reached when the active interceptor is `Interceptors::OnlyAggregatorAndSelf { our_cert, aggregator_cert }` [2](#0-1)  and [3](#0-2) .
- `Interceptors::Noop` simply returns `Ok(req)` for every request with no verification whatsoever [4](#0-3) .
- `create_grpc_server` selects between the two variants strictly based on `config.client_verification`: when false, `Noop` is installed regardless of TLS or method name [5](#0-4) .
- `create_aggregator_grpc_server` only emits a warning log when `client_verification` is *enabled* — there is no corresponding safeguard or fallback restriction when it is disabled [6](#0-5) .

So when an aggregator is deployed with `client_verification=false`, every RPC — including `Internal*`-prefixed ones such as `internal_get_emergency_stop_tx` — is dispatched to the handler with zero caller-identity enforcement. An attacker with a plain, unauthenticated `tonic::Channel` to the aggregator's port can call `internal_get_emergency_stop_tx(InternalGetEmergencyStopTxRequest{ txids: [...] })` and the request reaches `ClementineAggregatorServer`'s handler unfiltered, which forwards to `self.db.get_emergency_stop_txs` and returns the `encrypted_emergency_stop_txs` payload directly to the caller.

The root cause is architectural: caller-authorization for `Internal*` methods is enforced exclusively at the interceptor layer and is entirely absent from the handler itself, and the interceptor layer's enforcement is conditioned on an operator-controlled boolean config flag rather than being unconditional for `Internal*`-prefixed methods.

### Impact Explanation
The leaked artifact is the encrypted emergency-stop transaction, a presigned protocol commitment intended to be exposed only to the aggregator itself (self-call) ahead of its intended disclosure point. Premature disclosure of a protocol commitment to any unauthenticated party is one of the enumerated High-severity impact categories. The bypass is repeatable for every deposit whose emergency-stop tx exists in the database, and requires no BTC cost, no privileged role, and no key material from the attacker — only network access to the aggregator's gRPC port under this configuration.

### Likelihood Explanation
Exploitability is entirely gated by the deployment configuration flag `client_verification`. If it is `false` (which the question specifies as a precondition and which the code permits without any compensating internal check), the bypass is immediate and free: a single unauthenticated gRPC call with a known txid suffices, with no fee, no deposit, and no prior interaction needed beyond knowing a valid txid. If `client_verification` is `true` in a given deployment, `OnlyAggregatorAndSelf` is installed and the `is_internal` check correctly restricts the method to `our_cert`, closing the gap entirely for that deployment.

### Recommendation
Do not rely solely on a config-toggled interceptor for `Internal*` method protection. Enforce the `Internal*`-prefix / self-only restriction unconditionally regardless of `client_verification`, or reject/refuse to start the aggregator server with `client_verification=false` if it exposes any `Internal*`-prefixed methods. Alternatively, add an explicit caller-identity check inside `internal_get_emergency_stop_tx` (and other `Internal*` handlers) that does not depend on the interceptor layer at all.

### Proof of Concept
```
#[tokio::test]
async fn internal_method_reachable_without_client_verification() {
    // Build a BridgeConfig with client_verification = false and start
    // create_aggregator_grpc_server(config) as in existing test helpers,
    // seeding the DB with a real deposit that has an emergency-stop tx.

    // Connect with a bare, unauthenticated tonic Channel (no TLS client cert).
    let channel = tonic::transport::Channel::from_shared(format!("http://{addr}"))
        .unwrap()
        .connect()
        .await
        .unwrap();
    let mut client = ClementineAggregatorClient::new(channel);

    let resp = client
        .internal_get_emergency_stop_tx(InternalGetEmergencyStopTxRequest {
            txids: vec![known_move_txid.into()],
        })
        .await
        .expect("call should be rejected by is_internal binding but succeeds instead");

    // Binding under test: caller == self.our_cert is required by is_internal()/
    // OnlyAggregatorAndSelf semantics. With client_verification=false (Noop
    // interceptor), no such check ever executes.
    assert!(!resp.into_inner().encrypted_emergency_stop_txs.is_empty());
}
```
This demonstrates the binding `caller_authority == self.our_cert` does not hold before or after the call when `client_verification=false`: the unauthenticated caller receives the same non-empty response an internal self-call would receive.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
