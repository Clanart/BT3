### Title
Native precompiles (gov, staking, distribution, slashing, ics20, bank) lack the ETH-value guard that erc20/werc20 implement, causing permanent loss of user funds when a payable call is made — ([File: precompiles/gov/gov.go], [File: precompiles/staking/staking.go], [File: precompiles/distribution/distribution.go], [File: precompiles/slashing/slashing.go], [File: precompiles/ics20/ics20.go], [File: precompiles/bank/bank.go])

### Summary
This is the same root-cause class as the UMA `Governor` bug: a contract-call path that can carry native value (ETH/`msg.value`) has no consistent handling of that value at the destination, so a legitimate but unhandled `value` transfer produces unexpected, unrecoverable results. In this codebase, the ERC20 precompile explicitly documents and enforces the invariant that stateful precompiles which are not backed by an EOA must reject non-zero `contract.Value()`, because "it will not be possible to recover funds sent to an instance of them" [1](#0-0) . The WERC20 precompile independently enforces the same invariant by explicitly capturing `contract.Value()` and sending it back to the caller via the bank keeper [2](#0-1) . However, none of the other stateful precompiles (`gov`, `staking`, `distribution`, `slashing`, `ics20`, `bank`) implement this same check or refund logic in their `Execute` dispatch functions.

### Finding Description
The base `Precompile.RunNativeAction`/`runNativeAction` helper used by every stateful precompile does not itself reject or forward `contract.Value()` — it only manages snapshotting, gas metering, and the `BalanceHandler` for events emitted during execution [3](#0-2) . Each precompile's `Execute` method is solely responsible for deciding what to do with any attached call value:

- `erc20.Execute` explicitly checks `contract.Value()` and reverts with `ErrCannotReceiveFunds` before dispatching to any method [4](#0-3) .
- `werc20.Deposit` explicitly reads `contract.Value()` and immediately routes it back to the caller via `BankKeeper.SendCoins` [5](#0-4) .
- `gov.Execute`, `staking.Execute`, `distribution.Execute`, `slashing.Execute`, `ics20.Execute`, and `bank.Execute` dispatch directly to their method handlers with no equivalent check [6](#0-5) [7](#0-6) [8](#0-7) [9](#0-8) [10](#0-9) [11](#0-10) .

Under standard EVM call semantics, a `CALL` with non-zero `value` performs the native balance transfer from caller to callee (the precompile's fixed address) prior to executing the callee's code, independent of whether the callee's logic ever inspects that value. In Cosmos EVM, this balance transfer is backed by the same ledger as the bank module (confirmed by the `BalanceHandler`'s event-driven `stateDB.AddBalance`/`SubBalance` reconciliation with `bank` `EventTypeCoinSpent`/`EventTypeCoinReceived` [12](#0-11) , and by direct `StateDB.AddBalance`/`SubBalance` tests [13](#0-12) ). None of the affected precompiles' fixed addresses (e.g., gov `0x...805`, staking, distribution, slashing, ics20, bank precompile addresses) correspond to an EOA with a private key, nor do any of their exposed methods spend/forward `contract.Value()`.

### Impact Explanation
Any unprivileged EVM caller who attaches non-zero `msg.value`/native token value to a call into one of these unguarded precompiles (e.g., `gov.deposit(...)`, `staking.delegate(...)`, `distribution.withdrawDelegatorReward(...)`, `slashing.unjail(...)`, `ics20.transfer(...)`, or any bank method) will have that value irrecoverably debited from their account and credited to the precompile's account, with no method on the precompile that reads or refunds `contract.Value()`. This is a permanent, unauthorized loss/freezing of user funds — precisely the "Critical permanent freezing, locking, theft, or unauthorized extraction of user funds" impact called out in the allowed impact gate — triggerable by an ordinary user through the standard EVM transaction/precompile call flow, with no privileged actor involved.

### Likelihood Explanation
Likelihood is high in practice: many wallets/dApp integrations naively attach `value` fields to transactions (copy-pasting patterns from payable ERC20/WETH-style calls, or misconfiguring a `msg.value` alongside a `deposit`-sounding function name such as `gov.deposit`). The bug requires no adversarial setup — a single ordinary transaction with `value > 0` sent to any of the unguarded precompile addresses triggers it.

### Recommendation
Add the same `contract.Value()` guard used in the ERC20 precompile (reject any non-zero value for methods that are not designed to accept and route it) to all other stateful precompiles' `Execute`/dispatch functions (`gov`, `staking`, `distribution`, `slashing`, `ics20`, `bank`), or alternatively implement an explicit refund path analogous to `werc20.Deposit` for any precompile intended to accept native value. This should be centralized in the shared `common.Precompile` base (e.g., inside `runNativeAction`) so future precompiles inherit the protection by default rather than relying on each precompile author to remember it.

### Proof of Concept
1. Deploy/obtain access to any EVM account with a positive native token balance.
2. Construct an EVM transaction calling, e.g., the gov precompile's `deposit(address,uint64,Coin[])` method (or `staking.delegate`, `distribution.withdrawDelegatorReward`, `slashing.unjail`, `ics20.transfer`, or any `bank` method) at its fixed precompile address, attaching a non-zero `value` field (e.g., `{value: 1 ether}`) in addition to any calldata arguments.
3. Observe that the EVM's standard call value-transfer step debits the sender's account and credits the precompile's fixed address for the attached value (as it would for any ordinary contract call).
4. Observe that the precompile's `Execute`/dispatch method never reads `contract.Value()`, so the attached value is neither used for the operation (which uses the ABI-encoded `Coin[]`/amount parameter instead) nor refunded to the caller.
5. Query the caller's post-transaction balance and the bank balance of the precompile's address to confirm that the attached value has moved to the precompile address and remains there permanently, since no precompile method (and no EOA private key) exists to move funds out of that address.

Note: I was not able to fully trace the exact `x/vm` EVM call/`Context.Transfer` implementation within the available tool budget to directly cite the code performing the pre-`Run` value transfer into the precompile's `StateDB` balance; the analysis above is based on standard EVM `CALL` semantics (unconditionally moving `value` before invoking callee code) combined with the corroborating evidence that `erc20.go` and `werc20/tx.go` are the only precompiles in this codebase that explicitly account for `contract.Value()`, and `erc20.go`'s own comment confirms that unhandled value sent to a non-EOA-backed precompile is unrecoverable.

// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}

	bz, err := p.runNativeAction(evm, contract, action)
	if err != nil {
		return ReturnRevertError(evm, err)
	}

	return bz, nil

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	var balanceHandler *BalanceHandler
	if p.BalanceHandlerFactory != nil {
		balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()
	}

	if balanceHandler != nil {
		balanceHandler.BeforeBalanceChange(ctx)
	}

	bz, err = action(ctx)
	if err != nil {
		return bz, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	if balanceHandler != nil {
		if err := balanceHandler.AfterBalanceChange(ctx, stateDB); err != nil {
			return nil, err
		}
	}

	return bz, nil
}

		switch event.Type {

			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)

func (s *KeeperTestSuite) TestAddBalance() {
	testCases := []struct {
		name   string
		amount *uint256.Int
		isNoOp bool
	}{
		{
			"positive amount",
			uint256.NewInt(100),
			false,
		},
		{
			"zero amount",
			uint256.NewInt(0),
			true,
		},
	}

	for _, tc := range testCases {
		s.Run(tc.name, func() {
			vmdb := s.StateDB()
			prev := vmdb.GetBalance(s.Keyring.GetAddr(0))
			vmdb.AddBalance(s.Keyring.GetAddr(0), tc.amount, tracing.BalanceChangeUnspecified)
			post := vmdb.GetBalance(s.Keyring.GetAddr(0))

			if tc.isNoOp {
				s.Require().Equal(prev, post)
			} else {
				s.Require().Equal(new(uint256.Int).Add(prev, tc.amount), post)
			}
		})
	}
}
