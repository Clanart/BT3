### Title
`getEndpointKind` trusts a git-server-supplied `WWW-Authenticate` header to classify a remote as GitHub Enterprise, letting a malicious remote/proxy force the "sign in to GitHub" flow or reroute credential get/store/erase decisions - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Desktop's credential-helper trampoline decides whether a Git host is `github.com`, `ghe.com`, `enterprise`, or `generic` using, among other signals, the raw `WWW-Authenticate` response header that Git forwards from the remote server via the `wwwauth[]` credential field. This value is fully attacker-controlled by whatever server (or MITM/malicious proxy) the user's `git` process is talking to for that remote.

### Finding Description
`getEndpointKind` in [1](#0-0)  inspects `wwwauth[...]` entries taken directly from the credential map passed by Git (populated from the server's HTTP response headers), and short-circuits its classification: [2](#0-1) 

There is no verification that the header actually came from a certificate-validated GitHub/GHE endpoint — the string match on `realm="GitHub"` (or `realm="(GitLab|Gitea|Atlassian Bitbucket)"`) is taken at face value for *any* HTTPS remote. This value then drives `getCredential`, which decides whether to (a) prompt the user to "Sign in to GitHub" for that arbitrary endpoint, or (b) treat the host as `generic` and read/write the credential from/to Desktop's own generic-credential store: [3](#0-2) 

The `storeCredential`/`eraseCredential` handlers use the exact same, spoofable classification to decide which credential store (Desktop-internal generic store vs. "GitHub.com/GHE creds only stored internally") to write to or skip: [4](#0-3) 

This is analogous to the DYAD report's root cause: a security-relevant classification/gate (`isLicensed`) was checked against the wrong/untrusted source (`keroseneManager` instead of `vaultLicenser`), letting an unintended code path execute. Here, the classification gate for "is this a GitHub host that should get Desktop's privileged sign-in/token flow" is likewise derived from an untrusted, attacker-suppliable value rather than a verified source (e.g., TLS-pinned known endpoint list, or an actual authenticated API round-trip).

### Impact Explanation
An attacker who controls a git remote endpoint (e.g., a malicious/compromised HTTPS git server that a user adds as a remote, clones from, or is redirected to via a corporate proxy) can:
- Force `endpointKind` to `'enterprise'` for a completely arbitrary host by returning `WWW-Authenticate: Basic realm="GitHub"` on a 401 response, causing Desktop's credential-helper `get` path to invoke `ui.promptForGitHubSignIn(endpoint)` for that attacker-chosen endpoint (`app/src/lib/trampoline/trampoline-credential-helper.ts:109-125`). This routes the user into Desktop's Enterprise sign-in UI targeting the attacker's host, which — if the attacker's server implements a fake GHE OAuth/device-code flow — can be used to phish/capture a GitHub or GHE personal token that the user believes they are entering for a legitimate purpose.
- Conversely, force `endpointKind` to `'generic'` by spoofing `realm="GitLab"` (etc.), causing Desktop to fall back to `getGenericCredential`/`promptForCredential`/`setGenericCredential`, which stores whatever the user enters keyed only by the raw endpoint URL (`app/src/lib/generic-git-auth.ts:32-39`) — bypassing the "GitHub.com/GHE creds are only stored internally" special-casing intended for GitHub hosts.

The net effect is silent misclassification of the trust level of a remote host, controlled entirely by the remote server, which can be leveraged to misdirect the credential UX or storage behavior Desktop applies to that host.

### Likelihood Explanation
Any repository the user clones, fetches, or has as a remote is fully capable of triggering this path — no privileged position or existing malware is required; only a Git HTTPS server (or MITM/dev proxy) response header is needed, and Git already forwards these values through the standard credential-helper protocol used by every `git` HTTP operation. Existing guards (`isDotCom`, `isGHE` — see `app/src/lib/endpoint-capabilities.ts:47-62`) validate hostnames from a real URL and are safe, but they are checked *before* the spoofable `wwwauth[]` branch is reached, meaning the spoofable path is only reached for hosts that are not already known-good — i.e., precisely the case an attacker controls.

### Recommendation
Do not trust the `WWW-Authenticate` realm string to elevate a host's classification to `enterprise`/GitHub-privileged handling. At minimum:
- Require the `isGitHubHost()` network probe (which checks response headers over a real, direct request such as `x-github-request-id`) rather than accepting the header forwarded from the original authenticating request.
- If the `wwwauth[]` heuristic is kept as a fast-path optimization, use it only to *skip* an unnecessary network round trip when it indicates `generic` (a negative signal), never to *grant* the elevated `enterprise` classification, since granting trust is the security-relevant direction.

### Proof of Concept
Not independently executed (analysis based on static code review only; no sandbox/network available in this environment). A conceptual PoC:
1. Stand up an HTTPS git server (e.g., a minimal `git-http-backend` or nginx proxy) for `https://evil.example.com/attacker/repo.git`.
2. Configure it to respond to authentication challenges with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone or add `https://evil.example.com/attacker/repo.git` as a remote and perform a fetch/push requiring credentials.
4. Observe that `getEndpointKind` in `trampoline-credential-helper.ts` returns `'enterprise'` for `evil.example.com` purely from the spoofed header (`app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`), and that `getCredential` invokes `ui.promptForGitHubSignIn('https://evil.example.com')` (`app/src/lib/trampoline/trampoline-credential-helper.ts:109-125`) rather than treating it as an ungrouped/generic HTTPS remote.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)
  return approveCredential(cred, path, getGcmEnv(token))
}

/** Implementation of the 'erase' git credential helper command */
async function eraseCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? eraseExternalCredential(cred, token)
    : deleteGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username'))
      )
}
