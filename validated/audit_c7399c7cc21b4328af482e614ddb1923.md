### Title
Gasless module lends/repays gas fees based on user-declared `GasLimit` instead of actual gas consumed, letting a swap-tx sender drain KAIA from the block proposer - (File: kaiax/gasless/impl/getter.go)

### Summary
The `kaiax/gasless` module (KIP-247) has the block proposer "lend" a user KAIA to cover the gas fee of a `GaslessApproveTx`/`GaslessSwapTx` pair, and then has the user "repay" that lend during the swap. Both the lend amount and the repay amount are computed directly from the *declared* `GasPrice * GasLimit` of the user-submitted transactions, not from the gas actually consumed. Because Kaia's standard gas-refund mechanism (`returnGas`) always credits unused gas back to the transaction's own sender, an attacker can inflate `GasLimit` on their approve/swap transactions far beyond what they actually use, forcing the proposer to lend (and be nominally "fully repaid" for) an inflated amount, while pocketing the unused-gas refund as pure profit extracted from the proposer's wallet.

### Finding Description
`repayAmount`/`lendAmount` in `kaiax/gasless/impl/getter.go` compute the fee the proposer must lend to the user, and the amount the user must repay via `swapForGas`, purely from the transactions' self-declared gas parameters: [1](#0-0) 

- `lendAmount = ApproveTx.Fee() + SwapTx.Fee()`, i.e. `GasPrice * GasLimit` for each transaction, using the `GasLimit` field the *user themselves* set when constructing the approve/swap transactions.
- `repayAmount = R1 (SwapTx.GasPrice() * fixed TxGas for the lend tx itself) + lendAmount`.

`VerifyExecutable` only checks that the `amountRepay` argument encoded in the swap call matches this formula (`SP4`); it never validates that the declared `GasLimit` values are close to the actual intrinsic/execution gas needed: [2](#0-1) 

Meanwhile, at EVM execution time, `buyGas()` deducts `GasPrice * GasLimit` up front from the sender (who, for these ordinary approve/swap transactions, is both sender and fee payer), and afterward `returnGas()` refunds any unused portion (`GasLimit - GasUsed`) back to that **same address**: [3](#0-2) 

Because the user's wallet was only funded by the proposer's lend transaction, this leftover refund is money the proposer originally supplied but never gets back: the swap's `amountRepay` compensates the proposer for the full declared `GasLimit * GasPrice` (not the actual `GasUsed * GasPrice`), so the proposer is nominally made whole for the lend amount, but the unused-gas change that state transition credits back to the user's own balance is a completely separate, uncompensated leak of proposer funds.

### Impact Explanation
A single unprivileged user submitting a `GaslessApproveTx`/`GaslessSwapTx` pair through the public RPC/mempool (an explicitly in-scope path for the gasless module) can set an artificially large `GasLimit` on either or both transactions. As long as `amountRepay` is computed to satisfy `SP4`, the pair is accepted as valid and executable, and the proposer's `LendTxGenerator` transfers `GasPrice * (GasLimit_approve + GasLimit_swap)` KAIA out of its own wallet to the attacker. After execution, the attacker keeps: (a) the swap output net of the *declared* repay amount, and (b) the unused-gas refund (`GasPrice * (GasLimit - GasUsed)` for each of the two transactions), which is never reclaimed by the proposer. This is a direct, repeatable transfer of value from block proposers to an attacker, scalable up to the block gas limit per gasless-tx pair, and requires no special privileges — only a wallet with the target token balance and the ability to submit the two transactions.

### Likelihood Explanation
High. No special access is required: this is triggerable by any account holding a whitelisted token, using only the standard KIP-247 `swapForGas`/`approve` transaction shapes already documented and tested in the codebase (`tests/gasless_test.go`, `kaiax/gasless/impl/getter_test.go`). There is no gas-limit sanity check anywhere in the promotion (`IsExecutable`/`VerifyExecutable`) or block-building logic that would prevent inflating `GasLimit`, so the attack is straightforward to construct deterministically.

### Recommendation
Compute `lendAmount`/`repayAmount` from a fixed/expected intrinsic gas cost (or the actual metered gas usage after simulation) for the approve and swap calls rather than from the caller-controlled `GasLimit` field, and/or bound the accepted `GasLimit` for gasless transactions to a tight, protocol-defined ceiling matching the known call pattern (fixed ERC-20 `approve` + `swapForGas` calls). Alternatively, require any unused-gas refund from these bundled transactions to be swept back to the proposer (e.g., by making the lend/approve/swap sequence fee-delegated with the proposer as fee payer, so `returnGas()` credits the proposer instead of the user) so that the proposer is compensated exactly for gas actually consumed.

### Proof of Concept
1. Attacker acquires a small amount of a whitelisted ERC-20 token (as required for `IsApproveTx`/`IsSwapTx` eligibility) and constructs a `GaslessApproveTx` (nonce N) and `GaslessSwapTx` (nonce N+1) as in `tests/gasless_test.go`'s `sendApproveTx`/`sendSwapTx` helpers, but sets `GasLimit` on both far above what `approve`/`swapForGas` actually consume (e.g., 5,000,000 instead of ~100,000/500,000 used in the existing test constants): [4](#0-3) 
2. Sets `amountRepay` in the swap call data to exactly `repayAmount(approveTx, swapTx)` as computed by: [1](#0-0) 
so that `VerifyExecutable`'s SP4 check passes.
3. Submits both transactions to the mempool; the gasless module's `IsExecutable`/`GetLendTxGenerator` accepts them and the block-builder prepends a `LendTxGenerator` transaction funding the inflated `lendAmount` from the proposer's own account.
4. After block inclusion, `buyGas`/`returnGas` in `blockchain/state_transition.go` refund the unused portion of each inflated `GasLimit` back to the attacker's own account, while the swap's `amountRepay` (based on the full declared `GasLimit`, not actual usage) fully reimburses the proposer for the lend — leaving the unused-gas refund as an uncompensated transfer of proposer funds to the attacker.

Note: full on-chain verification of the exact KAIA recipient logic inside `GaslessSwapRouter`'s `swapForGas` implementation (Solidity source) was not available in the indexed codebase (only compiled ABI/bytecode bindings in `contracts/bindings/kip247/GaslessSwapRouter.go` were found); a Devin session with full repository/file access would be needed to confirm the exact repay-transfer destination logic inside the contract bytecode/source if it exists elsewhere in the repo.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

// returnGas returns KAIA for remaining gas, exchanged at the original rate.
func (st *StateTransition) returnGas() {
	remaining := new(big.Int).Mul(new(big.Int).SetUint64(st.gas), st.gasPrice)

	validatedFeePayer := st.msg.ValidatedFeePayer()
	validatedSender := st.msg.ValidatedSender()
	feeRatio, isRatioTx := st.msg.FeeRatio()
	if isRatioTx {
		feePayer, feeSender := types.CalcFeeWithRatio(feeRatio, remaining)

		st.state.AddBalance(validatedFeePayer, feePayer)
		st.state.AddBalance(validatedSender, feeSender)
	} else {
		// To make a short circuit, the below routine processes when feeRatio == 100.
		st.state.AddBalance(validatedFeePayer, remaining)
	}
}
