### Title
Gasless swap admission uses stale price/allowance checks that are never re-validated at block-inclusion time, letting a sender under-repay the proposer's lent gas fee - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `kaiax/gasless` module implements KIP-247 gasless transactions: a block proposer lends gas fee to a user via `LendTxGenerator`, and the user repays that lent amount through a `GaslessSwapRouter.swapForGas` call bundled as `[LendTx, GaslessApproveTx, GaslessSwapTx]`. The correctness of the repayment (`amountRepay`) is only checked once, against the exchange rate and allowance/balance **at tx-pool admission time**, via `checkBalanceForSwap` [1](#0-0)  which calls `GaslessSwapRouter.GetAmountIn` against the chain head state. There is no re-validation of this price/allowance/balance condition when the bundle is actually assembled into a block by the proposer (`GetLendTxGenerator`/bundle building described in the README) [2](#0-1) .

### Finding Description
`GaslessModule.GetCheckBalance()` is the only gate that enforces `amountIn >= GaslessSwapRouter.getAmountIn(token, minAmountOut)` and sufficient allowance/balance [3](#0-2) . This function is invoked from the transaction pool (`blockchain/tx_pool.go`, `blockchain/tx_list.go`) as a pool-admission/promotion check, using the current chain head state at the moment the check runs. The `amountRepay` value itself is fixed by the sender inside the signed `GaslessSwapTx` and is only checked for internal consistency (`minAmountOut >= amountRepay`, `amountRepay == RepayAmount(...)`) in `VerifyExecutable`/`isSwapTx` logic [4](#0-3) ; it does not re-derive `amountRepay` from freshly executed swap output at block-assembly or execution time.

Because the pool check queries `GetAmountIn` against a snapshot of state (the chain head at admission time) rather than the state at actual bundle execution, and because a `GaslessSwapTx` can remain queued/pending up to `QueueTimeout`/`PendingTimeout` (10 seconds) before being included [5](#0-4) , the DEX price backing `GetAmountIn`/`getAmountOut` can move between admission and inclusion (e.g., due to other swaps landing on the same DEX pool used by `GaslessSwapRouter`, which is exactly the swap-adapter/price-drift class of bug highlighted by the dTRINITY report on its swap adapter contracts). If the price moves unfavorably before inclusion, `swapForGas` executed on-chain will yield less output than the `minAmountOut`/`amountRepay` the sender committed to, and the fixed `amountRepay` value baked into the transaction is still what gets sent back to the proposer regardless of the real swap outcome. The proposer's lent gas (`LendTxGenerator`, which uses the node's own `NodeKey` to fund the swap fee) is the value directly exposed to this shortfall, since the lend/repay amounts are computed purely from tx fee math (`lendAmount`/`repayAmount` in `getter.go`) and not tied to the swap's realized output at inclusion time [6](#0-5) .

### Impact Explanation
Any unprivileged sender can submit a `GaslessApproveTx` + `GaslessSwapTx` pair that passes admission checks when the pool is queried, then rely on natural price movement (or intentionally trigger it via ordinary swaps on the same DEX pool while the gasless bundle sits in the queue) so that by the time the block proposer's node builds/executes the bundle, the swap yields less than the committed `amountRepay`. This directly drains value from the block proposer (who fronts the gas via `LendTxGenerator` from its own `NodeKey`-controlled balance) — matching the "loss belonging to core team members" characterization in the dTRINITY report, since in Kaia proposers/validators are typically operated by core/foundation-affiliated node operators. This is a concrete fee-delegation/gasless-settlement value-theft path reachable from a single submitted transaction pair, satisfying the "gasless or auction settlement theft" acceptance criterion.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to time submission and possibly co-submit ordinary swap transactions on the underlying DEX pool to move price during the pool-queue window (bounded by `QueueTimeout`/`PendingTimeout` = 10s), which is a realistic and repeatable window for a public-RPC caller with no special privileges. The check happens purely off admission-time state with no on-inclusion re-check, so there is no defense against this timing gap in the code reviewed.

### Recommendation
Re-validate `checkBalanceForSwap`'s price/allowance/balance conditions (or at minimum the `GetAmountIn`/`minAmountOut` relationship) against the state immediately before the bundle is included in the block being built, not just at pool-admission time. Alternatively, have the `GaslessSwapRouter` contract itself enforce that the lend amount can only be transferred to the proposer if the actual on-chain swap output at execution covers `amountRepay`, reverting the whole bundle (including the lend) otherwise, so a state-diverging price move cannot cause proposer loss.

### Proof of Concept
1. Attacker (or colluding accounts) submits ordinary swap transactions to the DEX pool backing the whitelisted `GaslessSwapRouter` token to shift the exchange rate favorably for a future gasless swap.
2. Attacker submits `GaslessApproveTx` + `GaslessSwapTx` with `amountIn`/`minAmountOut`/`amountRepay` computed to just barely satisfy `checkBalanceForSwap`'s `GetAmountIn` check against the current (pre-shift) chain head state [3](#0-2) .
3. The bundle sits in the pool for some seconds (bounded by `QueueTimeout`/`PendingTimeout`), during which the price of the token/DEX pool shifts unfavorably (e.g., via further public swaps).
4. The proposer includes `[LendTx, GaslessApproveTx, GaslessSwapTx]` in a block; `swapForGas` executes at the now-worse rate, producing less output than `amountRepay`, but the sender still only owes the pre-committed `amountRepay` figure — the proposer's `LendTxGenerator`-funded gas is not fully recovered from the swap proceeds.

**Uncertainty**: The exact enforcement inside `GaslessSwapRouter.swapForGas` (whether the Solidity contract itself reverts if actual DEX output is below `amountRepay`) is defined in the on-chain contract bytecode/ABI referenced by `contracts/bindings/kip247/GaslessSwapRouter.go`, whose Solidity source was not available in the indexed context — only the compiled bytecode/ABI bindings were found. This limits full certainty about whether a stronger on-chain guard already exists inside the router contract that mitigates this gap; a Devin session with full repo/contract-source access should confirm the router's internal repayment enforcement logic.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

// IsGaslessPattern checks following conditions:
// Ax. IsApproveTx conditions (if ApproveTx != nil)
// Sx. IsSwapTx conditions
// AP1. ApproveTx.from == SwapTx.from
// SP1. ApproveTx.to == SwapTx.token
// SP2. ApproveTx.amount >= SwapTx.amountIn
// SP3. ApproveTx.nonce+1 == SwapTx.nonce and Gasless transactions are head for nonce
// SP4. SwapTx.amountRepay = RepayAmount(ApproveTx, SwapTx)
func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
