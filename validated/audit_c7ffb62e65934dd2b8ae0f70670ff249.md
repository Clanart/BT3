### Title
Empty aggregate signature verifies as valid - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` accepts an aggregate with zero signers, zero `Rs`, and `s = 0` because it only checks length equality and then verifies the empty multiexp result. [1](#0-0) 

### Finding Description
`SchnorrAggregate::read` permits a serialized aggregate declaring zero `Rs`, followed by a canonical scalar. [2](#0-1)  `SchnorrAggregate::verify` accepts that object when the supplied signer/challenge list is also empty: it queues no statements, adds `-0 * G`, and treats the resulting identity point as success. [1](#0-0)  The Tributary adapter exposes this behavior through `Validators::verify_aggregate`, which likewise checks only that the signer count equals `Rs.len()` before delegating to `aggregate.verify`. [3](#0-2) 

### Impact Explanation
An unprivileged caller can forge a `SchnorrAggregate` that the signature-verification API accepts without any private key, nonce, or authorized signer. This is a direct signature-verification failure at the primitive and adapter layers. [4](#0-3) [5](#0-4)  The consensus `verify_commit` path subsequently requires threshold voting weight, so an empty signer list alone should not finalize a Tendermint block through that wrapper. [6](#0-5) 

### Likelihood Explanation
The forged input is 36 attacker-controlled bytes: a little-endian zero count followed by a zero scalar. Any reachable call that interprets an empty signer set as a valid authorization set, rather than separately enforcing non-emptiness or threshold, will accept it. [2](#0-1) [1](#0-0) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify` before performing verification. Also consider rejecting empty signer lists in `Validators::verify_aggregate`, so authorization failure is reported at the signature boundary rather than relying on downstream weight accounting. [1](#0-0) [5](#0-4) 

### Proof of Concept
For a 32-byte scalar ciphersuite, serialize:

```text
00 00 00 00                                      // len = 0
00 ... 00                                        // s = 0 (32 zero bytes)
```

Pass the resulting 36 bytes to `SchnorrAggregate::read`, then call `verify(dst, &[])`. The length check succeeds, the signer loop executes zero times, the only multiexp pair is `0 * G`, and verification returns `true`. [2](#0-1) [1](#0-0)  The same serialized value passed to `Validators::verify_aggregate(&[], msg, sig)` reaches the same successful empty verification path. [3](#0-2)

    signers: &[Self::ValidatorId],

    if signers.len() != aggregate.Rs().len() {
      return false;
