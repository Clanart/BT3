### Title
Native value sent directly to stateful precompiles (staking, distribution, ics20, bank, gov, slashing) is permanently locked with no refund/receive path - ([File: precompiles/staking, precompiles/distribution, precompiles/ics20, precompiles/bank, precompiles/gov, precompiles/slashing])

### Summary
The external report's "missing payable" pattern is a fund-lock bug class. In this codebase, `precompiles/erc20/erc20.go` explicitly rejects any `contract.Value() > 0` [1](#0-0) , and `precompiles/werc20/tx.go`'s `Deposit` explicitly consumes `contract.Value()` and sends it back to the caller via the bank keeper [2](#0-1) . However, the other stateful precompiles (staking, distribution, ics20, bank, gov, slashing) implement no such guard or refund logic in their `Run`/`Execute` paths [3](#0-2) .

### Finding Description
When an EVM `CALL` sends native value directly to a precompile address (e.g., `address(0x800).call{value: X}("")` or a payable wrapper contract that forwards `msg.value` on the call itself), the go-ethereum EVM's core call machinery transfers the value at the `StateDB` level (`AddBalance`/`SubBalance`, journaled) before invoking the precompile's `Run` function, exactly as it would for any other contract. This is confirmed by the `StateDB.AddBalance`/`GetBalance` implementation, which is fully generic and address-agnostic [4](#0-3) , and by `Keeper.GetAccount`, which loads the account's `Balance` field fresh from the bank keeper via `SpendableCoin` on every load [5](#0-4) [6](#0-5) , meaning the value transfer is ultimately reflected as a real bank-keeper coin balance credited to the precompile's Cosmos address on `Commit()` [7](#0-6) .

Unlike `erc20.go`, which checks `contract.Value()` and reverts [8](#0-7) , and `werc20.go`, which specifically implements `Deposit` to move any received value back to the caller [9](#0-8) , the `RunNativeAction` helper used by the other stateful precompiles (staking, distribution, ics20, bank, gov, slashing) contains no such check [10](#0-9) . If a caller sends native value directly to one of these precompile addresses (e.g., `0x...800` for staking), the funds are credited to that precompile's underlying module/account address in the bank keeper, but none of these precompile's methods contain logic to move that balance back out to any user — there is no `withdraw`, `deposit`, or refund entry point tied to the precompile's own address balance. The bank keeper's `BlockedAddr` mechanism referenced in `BalanceHandler.AfterBalanceChange` [11](#0-10)  is also unrelated to preventing or refunding this specific value-transfer path, since that logic only reacts to bank events emitted by keeper calls inside the precompile's `Execute`, not to the raw EVM value transfer that happens before `Run` is even entered.

### Impact Explanation
Native tokens sent directly (accidentally or intentionally, e.g., by a naive integrator who assumes precompiles behave like WETH/ERC20 with a `receive()`/refund pattern) to any of the non-ERC20/WERC20 static precompile addresses become permanently locked. There is no recovery path since these precompile addresses are not controlled by any private key and none of the module accounts backing them expose a "reclaim value sent by hex address X" operation.

### Likelihood Explanation
I could not verify from the available indexed code whether ante-handler or EVM message validation (e.g., checks that reject sending value to precompile addresses at the mempool/ante level) exists, since I did not locate such a guard in the reachable precompile execution path itself, but this is a plausible gap that should be confirmed against the ante handler and JSON-RPC gas estimation code, which were not part of my search results. Given how common accidental "plain transfer" mistakes are with tooling that assumes payable fallback semantics (as the original report notes), the likelihood of triggering this unintentionally is non-trivial, though it requires no privileged access — any unprivileged EOA can trigger it.

### Recommendation
Add the same `contract.Value().Sign() == 1` guard used in `precompiles/erc20/erc20.go` to the shared `RunNativeAction`/`runNativeAction` path in `precompiles/common/precompile.go`, so all stateful precompiles without an explicit deposit/refund mechanism reject direct native-value transfers by default, consistent with the ERC20 precompile's documented "No Direct Funding" security consideration.

### Proof of Concept
I was not able to construct or run an executable PoC against a live network within this investigation; this assessment is based on static code tracing of `precompiles/common/precompile.go`, `precompiles/erc20/erc20.go`, `precompiles/werc20/tx.go`, and `x/vm/statedb/statedb.go`/`x/vm/keeper/keeper.go`. A concrete PoC would involve: (1) deploying a simple forwarder contract or crafting a raw EVM tx with `to = 0x0000...0800` (staking precompile) and non-zero `value`, no calldata; (2) observing the transaction succeeds without reverting (since staking's `Execute`/`Run` has no value check); (3) querying the bank balance of the module/account address backing the staking precompile to confirm it increased by the sent amount with no corresponding withdrawal path available to any user. This should be verified with a Devin session running the integration test suite (`tests/integration/precompiles/staking`) to confirm whether a direct value-only call is actually accepted or reverted at a layer not visible in the indexed snippets (e.g., an ante handler restriction on "to precompile address with value" that I could not locate).

func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	var balanceHandler *BalanceHandler
	if p.BalanceHandlerFactory != nil {
		balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()
	}

	if balanceHandler != nil {
		balanceHandler.BeforeBalanceChange(ctx)
	}

	bz, err = action(ctx)
	if err != nil {
		return bz, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	if balanceHandler != nil {
		if err := balanceHandler.AfterBalanceChange(ctx, stateDB); err != nil {
			return nil, err
		}
	}

	return bz, nil
}

func (s *StateDB) commitWithCtx(ctx sdk.Context) error {
	for _, addr := range s.journal.sortedDirties() {
		obj := s.stateObjects[addr]
		if obj.selfDestructed {
			if err := s.keeper.DeleteAccount(ctx, obj.Address()); err != nil {
				return errorsmod.Wrapf(err, "failed to delete account %s", obj.Address())
			}
		} else {
			if obj.code != nil && obj.dirtyCode {
				if len(obj.code) == 0 {
					s.keeper.DeleteCode(ctx, obj.CodeHash())
				} else {
					s.keeper.SetCode(ctx, obj.CodeHash(), obj.code)
				}
			}
			if err := s.keeper.SetAccount(ctx, obj.Address(), obj.account); err != nil {
				return errorsmod.Wrap(err, "failed to set account")
			}

			for _, key := range obj.dirtyStorage.SortedKeys() {
				valueBytes := obj.dirtyStorage[key].Bytes()
				if len(valueBytes) == 0 {
					s.keeper.DeleteState(ctx, obj.Address(), key)
				} else {
					s.keeper.SetState(ctx, obj.Address(), key, valueBytes)
				}
			}
		}
	}
	return nil
