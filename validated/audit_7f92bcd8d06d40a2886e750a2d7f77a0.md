Found a concrete crash bug in the offer-parsing path that is a reasonable analog to CVE-2018-10373 (parsing a crafted binary triggers an unhandled/uncaught error in a lookup and crashes the parser). Here it's a `KeyError` (not `NULL`, but the same bug class: “trusted internal invariant about a lookup dictionary being fully populated is violated by attacker-controlled/malformed input, and the code doesn't guard the lookup”) reachable from parsing an **untrusted offer file supplied by an offer counterparty**.

### Title
Unhandled `KeyError` crash when parsing a maliciously crafted offer's coin spends - ([File: chia/wallet/trading/offer.py])

### Summary
`Offer.__post_init__` builds an internal `_additions: dict[Coin, list[Coin]]` cache keyed by each `CoinSpend.coin` in the offer's bundle [1](#0-0) . When `compute_spend_hints_and_additions` raises any generic `Exception` for a given coin spend (e.g. because the attacker crafts an unusual/invalid puzzle reveal or solution in the offer), that entry is silently skipped via a broad `except Exception: continue` [2](#0-1) , leaving `_additions` **without an entry for that coin**.

Later, `_get_offered_coins()` unconditionally does a direct dictionary index `self._additions[parent_spend.coin]` for every coin spend in the bundle [3](#0-2) , with no `.get()`/existence check. If the coin whose additions failed to compute is looked up here, this raises an unhandled `KeyError`, crashing whatever code path is examining/validating the offer.

### Finding Description
An offer (or any `WalletSpendBundle`) supplied by a counterparty is fully attacker-controlled data: its `coin_spends` (puzzle reveals and solutions) can be constructed to make `compute_spend_hints_and_additions` throw an exception that is not one of the explicitly re-raised types (`ValidationError`, cost-exceeded `ValueError`) — any other exception silently drops the entry from `adds` [4](#0-3) .

Once such an `Offer` object is constructed (e.g., via `Offer.from_bytes`/`Offer.from_compressed`/`Offer.try_offer_decompression`, or `Offer.from_spend_bundle`), any caller that subsequently invokes `get_offered_coins()`, `get_offered_amounts()`, or `arbitrage()` will hit the unguarded `self._additions[parent_spend.coin]` lookup and crash with an unhandled `KeyError` [5](#0-4) . These accessor methods are used throughout the trade-manager flow when a wallet examines or accepts an incoming offer from an untrusted counterparty.

This mirrors the CVE-2018-10373 bug class: a parser trusts that internal auxiliary data (there, DWARF filename tables; here, the per-coin additions cache) will always contain an entry for data being processed, and a crafted/malformed input can violate that assumption, causing a crash during parsing of attacker-supplied data.

### Impact Explanation
An offer counterparty can craft an offer file that crashes the wallet process (or any RPC handler) of anyone who attempts to inspect/take it, because the exception is unhandled by `_get_offered_coins`. This is a spend-triggered halt of the offer-processing path — a denial of service against a wallet user handling attacker-supplied offers, without requiring network-level or peer-level trust.

### Likelihood Explanation
Reaching this requires only that: 1) an attacker constructs an offer/spend bundle containing at least one coin spend whose puzzle causes `compute_spend_hints_and_additions` to throw a non-`ValidationError`/non-cost exception, and 2) a victim parses the offer and calls one of the affected accessor methods (which is the normal flow when examining or accepting an offer). No special privileges are needed; only user interaction (opening/taking an untrusted offer) is required, similar to CVE-2018-10373's requirement that a victim run a parser (`nm-new`) on the crafted file.

### Recommendation
- In `_get_offered_coins`, use `self._additions.get(parent_spend.coin, [])` (or otherwise validate the key exists) instead of a direct index lookup, and treat missing entries as "no additions could be determined for this coin" rather than crashing.
- Narrow the bare `except Exception: continue` in `Offer.__post_init__` so that unexpected errors are surfaced as a `ValidationError`/rejected offer rather than silently producing an inconsistent `_additions` cache, preventing downstream consumers from relying on an invariant that doesn't hold.

### Proof of Concept
1. Construct a `WalletSpendBundle` with two `CoinSpend`s:
   - One well-formed CAT/settlement-style coin spend (to satisfy other invariants in `__post_init__`).
   - One coin spend whose `puzzle_reveal`/`solution` is crafted so that when `compute_spend_hints_and_additions` runs it, it raises a generic `Exception` other than `ValidationError` or a cost-exceeded `ValueError` (e.g., a puzzle that raises during CLVM execution in a way that surfaces as, e.g., a `TypeError`/`AttributeError` inside `compute_spend_hints_and_additions` rather than the standard consensus error paths).
2. Build an `Offer` from this bundle via `Offer.from_spend_bundle(bundle)` — note the failing coin's entry is silently dropped from `self._additions`.
3. Serialize/compress the offer (`offer.compress()` / `to_bech32()`) and deliver it to a victim as an "incoming offer".
4. Victim (or their wallet RPC, e.g. `check_offer_validity`/`take_offer` flow) loads it with `Offer.try_offer_decompression` and calls `get_offered_coins()`/`arbitrage()`, which raises `KeyError` on `self._additions[parent_spend.coin]`, crashing the request/process handling the offer.     def __post_init__(self) -> None:
        # Verify that there are no duplicate payments
        for payments in self.requested_payments.values():
            payment_programs: list[bytes32] = [p.name() for p in payments]
            if len(set(payment_programs)) != len(payment_programs):
                raise ValueError("Bundle has duplicate requested payments")

        # Verify we have a type for every kind of asset
        for asset_id in self.requested_payments:
            if asset_id is not None and asset_id not in self.driver_dict:
                raise ValueError("Offer does not have enough driver information about the requested payments")

        # populate the _additions cache
        adds: dict[Coin, list[Coin]] = {}
        hints: dict[bytes32, bytes32] = {}
        max_cost = int(DEFAULT_CONSTANTS.MAX_BLOCK_COST_CLVM)
        for cs in self._bundle.coin_spends:
            # you can't spend the same coin twice in the same SpendBundle
            assert cs.coin not in adds
            try:
                hinted_coins, cost = compute_spend_hints_and_additions(cs, max_cost=max_cost)
                max_cost -= cost
                adds[cs.coin] = [hc.coin for hc in hinted_coins.values()]
                hints = {**hints, **{id: hc.hint for id, hc in hinted_coins.items() if hc.hint is not None}}
            except ValidationError:
                raise
            except ValueError as e:
                if e.args and e.args[0] == "cost exceeded or below zero":
                    raise ValidationError(Err.BLOCK_COST_EXCEEDS_MAX, "compute_additions for CoinSpend") from e
                continue
            except Exception:
                continue
            if max_cost < 0:
                raise ValidationError(Err.BLOCK_COST_EXCEEDS_MAX, "compute_additions for CoinSpend")
        object.__setattr__(self, "_additions", adds)

    def _get_offered_coins(self) -> dict[bytes32 | None, list[Coin]]:
        offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")
            else:
                # It's much easier if the asset is bare XCH
                asset_id = None
                coins_for_this_spend.extend([a for a in additions if a.puzzle_hash == OFFER_MOD_HASH])

            # We only care about unspent coins
            coins_for_this_spend = [c for c in coins_for_this_spend if c not in self._bundle.removals()]

            if coins_for_this_spend != []:
                offered_coins.setdefault(asset_id, [])
                offered_coins[asset_id].extend(coins_for_this_spend)
        return offered_coins

    def get_offered_coins(self) -> dict[bytes32 | None, list[Coin]]:
        try:
            if self._offered_coins is not None:
                return self._offered_coins
        except AttributeError:
            object.__setattr__(self, "_offered_coins", self._get_offered_coins())
        return self._offered_coins
