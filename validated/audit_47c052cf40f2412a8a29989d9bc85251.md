### Title
`SignableTransaction` trusts attacker-supplied `ReceivedOutput` value as equal to the on-chain UTXO value - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
The JOJO report describes a system that assumes a variable-valued asset (JUSD) is always equal to another asset (USDC), letting users transact at a wrong implicit price. The Serai analog lives in `bitcoin-serai`'s wallet: `ReceivedOutput` pairs an `OutPoint` (the on-chain reference) with a `TxOut` (a declared value/script), and `SignableTransaction::new` / `TransactionSignMachine::sign` assume the declared `TxOut.value` equals the true value of the referenced on-chain UTXO — an assumption that does not hold when the `ReceivedOutput` is reconstructed from untrusted bytes via `ReceivedOutput::read`.

### Finding Description
`ReceivedOutput::read` deserializes three independent fields — a scalar `offset`, an arbitrary `TxOut`, and an arbitrary `OutPoint` — with no check that the `OutPoint` exists on-chain or that `output.value` matches the real UTXO's value [1](#0-0) .

`SignableTransaction::new` then treats `input.output.value` as ground truth for the input amount when computing available funds and the change output [2](#0-1) , [3](#0-2) , and stores the unverified `TxOut`s as `prevouts` [4](#0-3) .

At signing time, `Prevouts::All(&self.tx.prevouts)` commits the forged amounts into the BIP-341 sighash, so every per-input signature attests to the attacker-chosen valuation [5](#0-4) . `multisig` only verifies that the prevout *script* matches the offset group key — the *value* is never cross-checked [6](#0-5) . Just as JOJO priced JUSD at USDC without a price check, this pipeline prices the UTXO at whatever value the deserialized bytes claim.

### Impact Explanation
Two directions of mis-valuation, both reachable by feeding crafted bytes to `ReceivedOutput::read`:

- **Understated value (fund loss):** if `output.value` is set below the real UTXO value, `input_sat` is too low, so the change output `input_sat - payment_sat - fee_with_change` is too small. The signed transaction is still consensus-valid (Taproot sighash binds the claimed amounts, which are internally consistent), but the unaccounted difference between the real input value and the declared `input_sat` is paid to miners as excess fee. The excess is permanently burned.
- **Overstated value (DoS / fee miscalculation):** if `output.value` is inflated, `NotEnoughFunds` checks pass and change may be computed, but the resulting transaction fails mempool/relay validation since claimed input sums exceed reality — the FROST signing round completes yet produces an unbroadcastable transaction, and `fee()` misreports the fee [7](#0-6) .

### Likelihood Explanation
`ReceivedOutput::read` exists precisely to deserialize these objects from an external byte stream, and nothing in `read`, `SignableTransaction::new`, or `multisig` verifies the outpoint against a node. Any context where serialized `ReceivedOutput`s cross a trust boundary (relayed between nodes, restored from storage an attacker can influence, or constructed by a coordinator) lets an unprivileged party set the implied valuation. The script-binding check in `multisig` gives a false sense of completeness — it binds the *key* to the prevout but not the *amount* to the chain.

### Recommendation
Treat the declared `TxOut` as a claim, not truth:

- After scanning, store and re-verify outputs via `scan_transaction`/`scan_block` (which populate `output` from real chain data) rather than trusting round-tripped `ReceivedOutput`s; or
- In `SignableTransaction::new`/`multisig`, re-fetch each `previous_output` from a trusted node and assert `prevout.value` and `prevout.script_pubkey` match the UTXO on-chain before signing; or
- At minimum, document `ReceivedOutput::read` as requiring trusted input and add a consistency check helper (`verify_against_utxo`) so integrators can enforce that the claimed value equals the on-chain value.

### Proof of Concept
1. Wallet owns UTXO `outpoint = (txid, 0)` worth `100_000` sats, script `p2tr_script_buf(key)`.
2. Attacker supplies bytes to `ReceivedOutput::read` encoding the real `offset`, the real `outpoint`, but a `TxOut { value: 10_000, script_pubkey: <correct script> }`.
3. `SignableTransaction::new(vec![forged], payments=[(dest, 9_000)], change=Some(change_script), None, fee_per_vbyte)` computes `input_sat = 10_000`; change is created as `10_000 - 9_000 - fee` (e.g., ~500 sats after fee checks) or payments are sized to leave small change.
4. `multisig()` succeeds because the forged `script_pubkey` still matches `offset.group_key()`. `sign()` commits `Prevouts::All` with the 10,000-sat claim and produces valid signatures.
5. Broadcast: the transaction spends the real `100_000`-sat UTXO, pays `9_000` + small change, and **~90,000+ sats are paid as an unintended miner fee** — funds irreversibly lost, caused purely by the code equating the deserialized declared value with the true UTXO value.
