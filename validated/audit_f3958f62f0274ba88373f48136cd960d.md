### Title
Payout tx's OP_RETURN operator attribution is not covered by the user's `SinglePlusAnyoneCanPay` signature, allowing misattribution of who fronted a withdrawal - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The withdrawal/payout flow authenticates only the withdrawal input and the user's payout output via a `SIGHASH_SINGLE|ANYONECANPAY` signature. The OP_RETURN output that records which operator "fronted" the withdrawal (used later to decide who gets reimbursed from the vault) sits outside the signed message and outside the anyone-can-pay input set, so it can be freely set by whoever finalizes/broadcasts the transaction, independent of who actually supplied the BTC that paid the user.

### Finding Description
The user only signs the withdrawal input and their own payout output with `TapSighashType::SinglePlusAnyoneCanPay`, which is enforced in `parse_withdrawal_sig_params`: [1](#0-0) 

`create_payout_txhandler` builds the transaction with the user output at index 0 (covered by SIGHASH_SINGLE), an anchor output at index 1, and an OP_RETURN output carrying `operator_xonly_pk` at index 2: [2](#0-1) 

Because the signature type is `SinglePlusAnyoneCanPay`, SIGHASH_SINGLE only commits to the output at the *same index* as the signed input (index 0), and ANYONECANPAY allows arbitrary additional inputs to be attached by anyone who broadcasts the final transaction. Consequently, the OP_RETURN output (index 2) that names the "fronting" operator is **not** covered by the user's signature and can be set to any x-only public key by whoever assembles and funds the final broadcast transaction — it need not match the party that actually supplied the BTC used to fund the user's payout output.

Downstream, verifiers trust this OP_RETURN content unconditionally to attribute the payout to an operator: [3](#0-2) 

This attribution is written to the `withdrawals` table's `payout_payer_operator_xonly_pk` column: [4](#0-3) 

and is later used, unconditionally, to determine which operator is authorized to claim reimbursement for that payout: [5](#0-4) [6](#0-5) 

The verifier's anti-malicious-kickoff check (`is_kickoff_malicious`) also only compares the kickoff operator's xonly_pk against this same untrusted OP_RETURN field, so it cannot detect the mismatch between who is credited and who actually paid: [7](#0-6) 

The binding that should hold is: `operator credited for reimbursement == party whose funds paid the withdrawal output`. Because the OP_RETURN field is unauthenticated and mutable by any broadcaster (SIGHASH_SINGLE|ANYONECANPAY leaves it and any extra funding inputs uncommitted), this equality can be broken: Operator/Actor A can fund the user's payout output with A's own bitcoin, while embedding Operator B's `xonly_pk` in the OP_RETURN. Verifiers will then record B as the payer, and B's own `PayoutCheckerTask`/reimbursement automation will proceed to claim reimbursement from the move-to-vault UTXO for a payout B never funded.

### Impact Explanation
This breaks the "operator credited versus party that paid" custody binding explicitly called out as Critical impact: an operator ends up reimbursed for a payout it never funded, while BTC leaves the move-to-vault UTXO without that operator having fronted the equivalent withdrawal. This also means the true funder of the payout gets nothing back for the BTC they spent, and could be used to grief/attack a specific operator by permanently misattributing their payouts (potentially interfering with `PayoutCheckerTask`'s automation and `end_round`/state machine progress tied to that "unhandled payout").

### Likelihood Explanation
No privileged role is required. Any party capable of observing a user's presigned withdrawal signature (`SinglePlusAnyoneCanPay`) and outpoint — data that must be shared off-chain with operators to allow multiple operators to compete to front the withdrawal, per the protocol's design — can construct and broadcast their own finalized transaction that reuses the signed input/output but substitutes an arbitrary OP_RETURN operator attribution and their own additional funding inputs. This does not require compromising any key, verifier, operator, or aggregator; it only requires access to withdrawal signature data that is, by design, distributed to multiple operators before broadcast (a race to front the withdrawal is a natural, intended feature of the protocol).

### Recommendation
Bind the OP_RETURN operator attribution to the user's signature commitment, or otherwise authenticate which entity actually funded the withdrawal payout before crediting it in `update_finalized_payouts`/`payout_payer_operator_xonly_pk`. Options include: switching to a sighash type that commits to all outputs (e.g., `AllPlusAnyoneCanPay` is not sufficient either since inputs vary; consider committing the OP_RETURN via a covenant/pre-signed structure), or cross-checking that the additional funding input(s) in the finalized payout transaction are provably controlled by the xonly_pk claimed in the OP_RETURN (e.g., requiring the funding input's spending key/address to match the claimed operator's registered wallet key) before recording `payout_payer_operator_xonly_pk`.

### Proof of Concept
1. User signs withdrawal params (`input_signature` with `SinglePlusAnyoneCanPay`, `input_outpoint`, `output_script_pubkey`, `output_amount`) and shares this off-chain, as intended by the protocol, so that any operator can race to fulfill it (see `core/src/rpc/clementine.proto` `Withdraw`/`InternalWithdraw` docs).
2. Actor A (could itself be a legitimate competing operator, or any funded party) constructs a payout transaction using `create_payout_txhandler`-equivalent structure: input = the user's signed withdrawal UTXO (SIGHASH_SINGLE|ANYONECANPAY), output[0] = the user's requested payout (satisfies the signed commitment), output[1] = anchor, output[2] = OP_RETURN containing operator B's `xonly_pk` (not A's own), and adds its own additional input(s) to cover `output_amount` funded from A's wallet.
3. A broadcasts this transaction. It is valid because SIGHASH_SINGLE|ANYONECANPAY only checks input 0 against output 0; the OP_RETURN and extra inputs are unconstrained.
4. Verifiers process the finalized block, call `update_finalized_payouts` (`core/src/verifier.rs:2283-2352`), parse the OP_RETURN, and record `payout_payer_operator_xonly_pk = B`.
5. Operator B's `PayoutCheckerTask` (`core/src/task/payout_checker.rs:31-113`) finds this "unhandled payout" attributed to itself via `get_first_unhandled_payout_by_operator_xonly_pk`, and `validate_payer_is_operator` (`core/src/operator.rs:1686-1740`) succeeds since `payer_xonly_pk == B`'s own key, so B proceeds through kickoff/reimbursement and is reimbursed from the move-to-vault UTXO for a payout it never funded.

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }
