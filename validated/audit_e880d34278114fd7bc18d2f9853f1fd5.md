### Title
Scanner::scan_block reports immature coinbase outputs as spendable received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to `registerRecipient` accepting `msg.value` it never uses, `Scanner::scan_block` accepts and reports every transaction output paying to a watched script — including coinbase transaction outputs — without distinguishing them. A coinbase output is cryptographically unspendable for 100 blocks, yet it is returned as a normal `ReceivedOutput`, ready to be fed into `SignableTransaction::new` and signed over.

### Finding Description
`Scanner::scan_transaction` matches outputs purely by `output.script_pubkey` against the registered script map and pushes a `ReceivedOutput` for every match, with no check on the transaction's position or type [1](#0-0) . `scan_block` iterates `block.txdata` starting at index 0, explicitly including `block.txdata[0]` — the coinbase [2](#0-1) . The doc comment admits the coinbase "is bound by maturity" and that "a post-processing pass is needed" to remove such outputs, but the API provides no marker on `ReceivedOutput` (only `offset`, `output`, `outpoint`) to let a caller tell a coinbase-originated output apart [3](#0-2) . Nothing in `ReceivedOutput`, `scan_transaction`, or `SignableTransaction` records or enforces maturity.

Downstream, `SignableTransaction::new` happily consumes any `ReceivedOutput`, builds `TxIn`s from its outpoint, and `TransactionSignMachine` produces valid Taproot signatures over it [4](#0-3) . The result is a fully signed transaction that Bitcoin consensus will reject (`bad-txns-premature-spend-of-coinbase`), or — worse for an automated wallet — the wallet's balance/scheduler treats immature funds as available.

Notably, the in-tree consumer already had to work around this: the processor's Bitcoin `get_outputs` skips `block.txdata[1 ..]`'s zeroth element precisely "which is burdened by maturity" — evidence that the default `scan_block` behavior is a real footgun rather than a theoretical one [5](#0-4) .

### Impact Explanation
An unprivileged miner (or anyone whose coinbase transaction happens to pay a watched Serai/Taproot key, e.g. a mining pool paying to the multisig address) causes `scan_block` to emit a `ReceivedOutput` that cannot be spent for 100 blocks. Any logic treating scanned outputs as available balance misaccounts funds; a transaction built spending it is consensus-invalid, and repeated naive retries can keep selecting the immature output, stalling withdrawals. This is "funds reported received that are not spendable," matching the accepted impact class.

### Likelihood Explanation
Any Bitcoin transaction paying to the watched P2TR script triggers it; a coinbase payout to that address requires only a miner choosing the address — no cooperation from Serai. The library exposes `scan_block` as the natural whole-block API, and the only guard is a doc comment, so misuse by integrators is plausible. Severity is Medium: no secret leakage, but direct availability/accounting impact on received funds.

### Recommendation
Make `scan_block` skip `block.txdata[0]` by default, or annotate `ReceivedOutput`/`scan` results with a coinbase/immature flag so callers can enforce maturity. Alternatively add a `scan_block_checked` that filters coinbase outputs whose block height is < 100 confirmations deep, rather than relying on callers to re-implement consensus rules.

### Proof of Concept
1. Construct a `Scanner` for an even `key` via `Scanner::new(key)`.
2. Mine a regtest block whose coinbase pays `p2tr_script_buf(key)` (any miner can do this).
3. Call `scanner.scan_block(&block)` — it returns a `ReceivedOutput` for the coinbase output, indistinguishable from a normal payment (`offset == Scalar::ZERO`).
4. Feed it into `SignableTransaction::new(vec![output], &payments, ...)` and run `TransactionMachine` signing — a validly-signed transaction is produced that the network rejects with `bad-txns-premature-spend-of-coinbase`, while the wallet has already accounted the funds as received/spendable.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
