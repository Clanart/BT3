### Title
Token factory denom allow-list restriction can be bypassed via non-`MsgSend` transfer paths (EVM bank precompile, CosmWasm bank messages, IBC, module transfers) - ([File: sei-cosmos/x/bank/keeper/msg_server.go])

### Summary
Sei-chain's analog to Dinari's `BURNER_ROLE` restriction bypass is the token factory denom allow-list ("restricted address") feature in `x/bank`. An address that is excluded from a denom's allow list is supposed to be unable to send or receive that denom, but the enforcement of this restriction is implemented only inside the two Cosmos SDK message handlers `Send` and `MultiSend`, not inside the underlying coin-movement primitives that every other module and precompile actually calls.

### Finding Description
`BaseSendKeeper.IsInDenomAllowList` is the function that decides whether an address is allowed to move a token-factory-prefixed denom (`factory/...`) that has an `AllowList` configured via `SetDenomAllowList` [1](#0-0) . The only two call sites that consult this restriction are `msgServer.Send` and `msgServer.MultiSend` in `sei-cosmos/x/bank/keeper/msg_server.go` [2](#0-1) [3](#0-2) .

The core coin-movement keeper methods that the rest of the chain uses — `SendCoins`, `SendCoinsWithoutAccCreation`, `InputOutputCoins`, `SendCoinsFromModuleToAccount`, `SendCoinsAndWei`, etc. — are declared in the `SendKeeper`/`Keeper` interface [4](#0-3)  but the allow-list check is not embedded in them; it lives strictly in the message-handler layer. Any caller that reaches coin movement without going through `MsgSend`/`MsgMultiSend` therefore never calls `IsInDenomAllowList` at all.

This is directly analogous to the Dinari bug: the "burn" path bypassed the restriction because the restriction check was placed on `transfer` rather than on the more fundamental balance-mutating primitive. Here, the allow-list check is placed on the `MsgSend`/`MsgMultiSend` handlers rather than on the underlying `SendCoins`/`InputOutputCoins` primitives that are reused throughout the chain (EVM bank precompile transfers, CosmWasm `BankMsg::Send`, IBC transfers, staking/distribution payouts, tokenfactory mint/burn/force-transfer, etc.). Existing tests only exercise the `MsgSend` path and confirm the block only there [5](#0-4) [6](#0-5) , with no equivalent coverage for CosmWasm/EVM/IBC transfer paths, which is consistent with those paths not enforcing the restriction.

### Impact Explanation
If an issuer relies on `SetDenomAllowList` to restrict which addresses can hold/move a permissioned tokenfactory denom (a legitimate on-chain compliance mechanism), a blocked address can still receive or send that denom by routing the transfer through the EVM `bank` precompile, a CosmWasm contract issuing a native `BankMsg::Send`, an IBC transfer, or any module-level `SendCoinsFromModuleToAccount`/`SendCoins` call, none of which invoke `IsInDenomAllowList`. This defeats the intended access control entirely for any transfer that doesn't originate from a direct `MsgSend`/`MsgMultiSend` transaction, resulting in unauthorized transfer of a restricted asset — matching the "unauthorized transfer" impact category.

### Likelihood Explanation
Likelihood is high for any chain/asset issuer actually using the allow-list feature, since CosmWasm contracts and the EVM bank precompile are both public, permissionless, single-transaction-reachable surfaces (a contract call or an EVM `bank` precompile call), and neither is gated by the allow-list check present only in the bank message server.

### Recommendation
Move the `IsInDenomAllowList` (and `BlockedAddr`) enforcement down into the shared primitives (`SendCoins`, `InputOutputCoins`, and any other path that mutates balances for token factory denoms with an allow list), or explicitly invoke the same check from every entry point that can move coins (EVM bank precompile, CosmWasm bank message handler, IBC transfer keeper, tokenfactory keeper actions), so restriction enforcement cannot be bypassed by choosing an alternate transfer path.

### Proof of Concept
Conceptual PoC (not directly executed, inferred from code structure):
1. Create a tokenfactory denom `factory/{creator}/mytoken` and call `SetDenomAllowList` with an allow list that excludes address `A`.
2. Attempting `MsgSend` from/to `A` correctly fails, per the existing test `TestSendReceiverNotInAllowList`/`TestSendSenderNotInAllowList` [5](#0-4) .
3. Instead, deploy/call a CosmWasm contract (or use the EVM `bank` precompile) that issues a native bank send of the same denom to/from `A`. Because this path invokes `SendCoins`/module-to-account keeper methods directly rather than `msgServer.Send`, `IsInDenomAllowList` is never checked, and the transfer to/from the restricted address `A` succeeds.

Note: I was not able to fully trace the precompile/CosmWasm bank-message code path within the available indexed context to conclusively show the exact call site skipping the check (the search only confirmed that `IsInDenomAllowList` is referenced solely in `msg_server.go`/`send.go`/related tests, and did not surface the internals of `precompiles/bank/bank.go`'s send handler or wasmd's native bank message dispatcher). A background Devin session with full repository access would be needed to confirm the precompile/wasmd bank-message code precisely and produce a runnable PoC.

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

func (k msgServer) MultiSend(goCtx context.Context, msg *types.MsgMultiSend) (*types.MsgMultiSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	denomToAllowListCache := make(map[string]AllowedAddresses)
	// NOTE: totalIn == totalOut should already have been checked
	for _, in := range msg.Inputs {
		if err := k.IsSendEnabledCoins(ctx, in.Coins...); err != nil {
			return nil, err
		}
		accAddr := sdk.MustAccAddressFromBech32(in.Address)
		if !k.IsInDenomAllowList(ctx, accAddr, in.Coins, denomToAllowListCache) {
			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", accAddr)
		}
	}

	for _, out := range msg.Outputs {
		accAddr := sdk.MustAccAddressFromBech32(out.Address)

		if k.BlockedAddr(accAddr) || !k.IsInDenomAllowList(ctx, accAddr, out.Coins, denomToAllowListCache) {
			return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", out.Address)
		}
	}

func TestSendReceiverNotInAllowList(t *testing.T) {
	acc := &authtypes.BaseAccount{
		Address: addr1.String(),
	}

	genAccs := []authtypes.GenesisAccount{acc}
	a := app.SetupWithGenesisAccounts(t, genAccs)
	ctx := a.BaseApp.NewContext(false, tmproto.Header{})
	testDenom := "testDenom"
	factoryDenom := fmt.Sprintf("factory/%s/%s", addr1.String(), testDenom)

	require.NoError(t, apptesting.FundAccount(a.BankKeeper, ctx, addr1, sdk.NewCoins(sdk.NewInt64Coin(factoryDenom, 100))))
	a.BankKeeper.SetDenomAllowList(ctx, factoryDenom,
		types.AllowList{Addresses: []string{addr1.String()}})

	a.Commit(context.Background())

	res1 := a.AccountKeeper.GetAccount(ctx, addr1)
	require.NotNil(t, res1)
	require.Equal(t, acc, res1.(*authtypes.BaseAccount))

	origAccNum := res1.GetAccountNumber()
	origSeq := res1.GetSequence()

	sendMsg := types.NewMsgSend(addr1, addr2, sdk.Coins{sdk.NewInt64Coin(factoryDenom, 10)})
	header := tmproto.Header{ChainID: a.ChainID, Height: a.LastBlockHeight() + 1}
	txGen := app.MakeEncodingConfig().TxConfig
	_, _, err := app.SignCheckDeliver(t, txGen, a.BaseApp, header, []sdk.Msg{sendMsg}, []uint64{origAccNum}, []uint64{origSeq}, false, false, priv1)
	require.Error(t, err)
	require.Contains(t, err.Error(), fmt.Sprintf("%s is not allowed to receive funds", addr2))
