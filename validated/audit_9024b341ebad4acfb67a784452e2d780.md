### Title
stSTXbtc and zstSTXbtc collateral/debt valuation priced with STX feed instead of BTC feed - (File: `mainnet/contracts/utility/v0-1-data.clar`)

### Summary
In `v0-1-data.clar`, the `get-asset-price` helper resolves the price for `stSTXbtc` (and its vault-wrapped counterpart `zstSTXbtc`) by calling `get-pyth-price PYTH-STX` — i.e., the STX/USD feed — while the adjacent comment explicitly states the intent is to use the "BTC price." This is a textbook "price attached to the wrong asset" defect: the code path for a BTC-denominated asset silently substitutes an unrelated STX price feed.

### Finding Description
`get-asset-price` in `mainnet/contracts/utility/v0-1-data.clar` dispatches per-asset pricing logic by asset id (`aid`): [1](#0-0) 

```clarity
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-STX))
;; zstSTXbtc - stSTXbtc price x liquidity index
(if (is-eq aid zstSTXbtc)
    (let ((btc-price (default-to u0 (get-pyth-price PYTH-STX)))
          (lindex (get-vault-liquidity-index stSTXbtc)))
      (mul-div-down btc-price lindex INDEX-PRECISION))
```

Both branches label the local variable/comment as "BTC price," yet both invoke `(get-pyth-price PYTH-STX)` — the STX/USD Pyth feed constant defined earlier in the same file — rather than `PYTH-BTC`. All sibling branches for genuinely BTC-denominated assets (`sBTC`, `zsBTC`) correctly call `(get-pyth-price PYTH-BTC)`, confirming this is an inconsistency rather than intended behavior: [2](#0-1) [3](#0-2) 

This value flows into `sum-collateral-usd` and `sum-debt-usd`, which sum USD notional across a user's positions using this exact price function: [4](#0-3) [5](#0-4) 

STX and BTC are economically unrelated assets with very different USD prices, so this substitution produces a grossly incorrect USD valuation for any position holding `stSTXbtc`/`zstSTXbtc` collateral or debt — understating or overstating true value depending on which asset is currently more expensive.

### Impact Explanation
**Reachability caveat (important):** I was only able to confirm that `get-asset-price` is invoked from `sum-collateral-usd`/`sum-debt-usd` inside `v0-1-data.clar`, a contract explicitly named as a "utility/protocol-data" aggregator. I could not confirm within the available context whether these summed values are consumed by any enforcement path (`borrow`, `collateral-withdraw`, `liquidate`, health checks) in `v0-4-market.clar`, which appears to implement its own independent oracle resolution (`price-resolve`/`resolve-callcode` keyed by per-asset `type`/`ident`/`callcode` registered in the assets registry) rather than this hardcoded `aid`-based switch. If `v0-1-data.clar`'s valuation is purely a read-only reporting/dashboard aggregator and is never used to gate borrows, withdrawals, or liquidations, the practical impact is limited to displaying an incorrect number rather than an exploitable wrong health verdict.

If, however, this helper (or an equivalent code path duplicated elsewhere) is consumed by any state-changing function that decides solvency, borrowing capacity, or liquidation eligibility for positions holding `stSTXbtc`/`zstSTXbtc`, the impact would be Critical: a wrong health verdict directly enables either (a) borrowing against overstated collateral (theft of protocol funds / insolvency) when STX price exceeds BTC price scaled to the same units, or (b) incorrect liquidation/freezing of healthy positions when the reverse holds.

### Likelihood Explanation
The defect is deterministic and always triggers whenever `stSTXbtc` or `zstSTXbtc` pricing is evaluated through this specific helper — no attacker action or market condition is required beyond holding the affected asset. The likelihood of the underlying code defect firing is therefore high; the likelihood of it causing on-chain financial harm depends entirely on the unconfirmed reachability into enforcement logic described above.

### Recommendation
Replace `PYTH-STX` with `PYTH-BTC` in both the `stSTXbtc` and `zstSTXbtc` branches of `get-asset-price` in `mainnet/contracts/utility/v0-1-data.clar` (lines 582 and 585) to match the stated intent and the pattern used for `sBTC`/`zsBTC`. Additionally, confirm and document whether `v0-1-data.clar`'s valuation functions are ever consumed by enforcement paths in `v0-4-market.clar`; if so, add cross-contract tests asserting price parity between the two independent oracle-resolution implementations to prevent this kind of divergence from recurring.

### Proof of Concept
1. Register `stSTXbtc` as collateral for a test account.
2. Call the read-only path that invokes `sum-collateral-usd` → `get-asset-price(stSTXbtc-aid)`.
3. Observe that the returned USD price equals the current STX/USD Pyth price rather than the BTC/USD Pyth price (verified by comparing against `get-pyth-price PYTH-BTC` for the same block).
4. Given STX/USD ≪ BTC/USD, any consumer of this valuation would see the `stSTXbtc` position's value collapse to a small fraction of its real BTC-denominated worth (or vice versa depending on relative price movements), demonstrating the wrong-asset price substitution.
