### Title
Permanent, path-scoped `safe.directory` trust exception lets an attacker silently regain trusted (auto-executing) status for a new/replaced repository - ([File: app/src/lib/git/config.ts])

### Summary
The "shutdown must be irreversible" bug class maps to Desktop's "unsafe repository" (dubious-ownership) protection. Git flags a repository path as untrusted when its ownership doesn't match the current user, and Desktop surfaces this as a hard stop ("Adding untrusted repositories may automatically execute files in the repository"). The user can grant a one-time "Trust Repository" exception, but that exception is written as a permanent, path-only entry in the *global* `safe.directory` git config and is never revoked or scoped to the specific repository content that was trusted at the time. Just like the Riz protocol's shutdown flag being reversible because upgradeable modules can silently flip it back, Desktop's "untrusted" state can be silently and permanently defeated for any *future* content that later occupies the same filesystem path.

### Finding Description
`addSafeDirectory` in [1](#0-0)  adds the trusted path to the **global** git config via `addGlobalConfigValueIfMissing('safe.directory', path)` [2](#0-1) . This call is triggered from the UI's `onTrustDirectory` handlers in both the "Add Existing Repository" dialog [3](#0-2)  and the "Missing Repository" view [4](#0-3) .

Crucially, the trust decision is bound only to the **path string**, not to the repository's identity (e.g., its initial commit, remote URL, or `.git` object history). Once a path is added to `safe.directory`, `getRepositoryType` in [5](#0-4)  will never again report `kind: 'unsafe'` for that path, regardless of what content occupies it afterward. Common real-world scenarios where the underlying content at a trusted path changes without additional ownership changes include:
- Network shares, shared temp directories, or CI-shared checkout folders that get re-populated with a different (attacker-controlled) repository at the same path.
- A directory that is deleted and recreated (e.g., `rm -rf` + `git clone`) by any process, including one triggered by a malicious script the user ran, a build tool, or a container mount that gets refreshed with new content.
- Removable/mounted volumes reused across sessions where the mount point is fixed but the volume's content is swapped.

Because the "unsafe" check in `getRepositoryType` only inspects Git's dubious-ownership detection (owner UID) and the `safe.directory` allow-list, and never re-validates that the *content* is what the user originally reviewed and trusted, an attacker who can get different repository content placed at a previously-trusted path inherits the "trusted" state automatically. The original design intent — requiring explicit user consent before Desktop treats a repo as safe to auto-execute hooks/scripts against — is silently and permanently bypassed for that path, exactly analogous to an "irreversible shutdown" being quietly reverted by an upgradeable component.

### Impact Explanation
Git repositories can auto-execute code via hooks, `.gitattributes`-driven filters, or LFS smudge/clean commands once Desktop treats the directory as trusted; this is precisely the risk the "unsafe" warning text itself calls out ("Adding untrusted repositories may automatically execute files in the repository"). A permanent, content-agnostic trust exception means an attacker who can influence what ends up at a previously-trusted path (shared machines, shared build directories, network shares, containers with persistent mount points) can achieve code execution without the user ever seeing or acknowledging the trust prompt again. This satisfies the "attacker controls a cloned/fetched repository ... resulting in code execution" criterion.

### Likelihood Explanation
Exploitation requires a plausible but non-trivial precondition: the attacker must be able to place different repository content at a path the user previously trusted (e.g., shared/network paths, reused CI workspace directories, or directories that get wiped and repopulated by tooling the user runs). This is a realistic but not universal scenario — it does not require local/physical access to the user's own private-only directories, admin rights, or pre-existing malware; it only requires that the trust decision is path-bound and never expires or is content-bound, which is a design property directly present in the code.

### Recommendation
Do not treat `safe.directory` trust as a permanent, path-only exception:
- Bind the trust exception to repository identity where possible (e.g., re-validate ownership and prompt again if the `.git` directory's inode/creation, remote URL, or initial commit differs from what was trusted).
- Consider scoping trust to a session or re-confirming trust when Desktop detects the directory was recreated (e.g., inode change, or the repository's root commit changed) rather than trusting indefinitely based on path string alone.
- Provide a way for users to review and revoke previously trusted directories from within Desktop, since currently there is no UI to manage the accumulated `safe.directory` global entries.

### Proof of Concept
1. User clones/creates a repository at `/shared/workspace/project` on a shared machine, path, or network share and it is later flagged unsafe (e.g., ownership mismatch) and the user clicks "Trust Repository," causing `addSafeDirectory('/shared/workspace/project')` to permanently add that path to the global `safe.directory` list [6](#0-5) .
2. At a later time, another user/process/attacker deletes `/shared/workspace/project` and replaces it with a different, malicious Git repository containing a hook or LFS filter designed to execute code (e.g., `post-checkout`).
3. The user reopens Desktop, and `getRepositoryType('/shared/workspace/project')` no longer returns `kind: 'unsafe'` because the path is already in `safe.directory`, even though the content is entirely different [5](#0-4) .
4. Desktop performs normal Git operations against the now-malicious repository without prompting the user again, and the attacker's hook/filter executes.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
```

```typescript
export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
```
