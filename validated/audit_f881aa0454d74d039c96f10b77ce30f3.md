### Title
Attacker-controlled Pull Request `head.repo.clone_url` is passed unsanitized to `git remote add` / `git fetch`, enabling `ext::` transport command execution - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The Sherlock report's core primitive is: an attacker-controlled object (`nextMsg_`/its `owner` field) flows into a privileged operation (`_lzCompose`/`_internalTransferWithAllowance`) without re-validating trust boundaries, letting the attacker impersonate a trusted principal. The closest verifiable Desktop analog is `Dispatcher.openPullRequestFromUrl` / `AppStore._checkoutPullRequest` → `_findPullRequestBranch`, where a value that is fully controlled by an untrusted third party (the head repository of a Pull Request, which anyone can create by forking and opening a PR) is passed straight into `addRemote()` and then fetched, without validating the git transport scheme.

### Finding Description
When a user opens a repository/PR via the `x-github-client://openRepo/...&pr=NNN` deep link or via `Dispatcher.checkoutPullRequest`, the flow is: [1](#0-0) 

`pullRequest.head.repo.clone_url` originates from the GitHub API response for the PR and is fully attacker-controlled: any user can open a PR from a fork whose `clone_url` field is whatever the API returns for that repository's remote URL configuration. This value is forwarded to `_checkoutPullRequest` → `_findPullRequestBranch`: [2](#0-1) 

`headCloneUrl` is passed unmodified to `addRemote()`: [3](#0-2) 

and, if no matching remote is found, `_fetchRemote` is subsequently invoked on that same remote/URL to look for the branch: [4](#0-3) 

Nowhere in the parsing or dispatch path (`parse-app-url.ts`, `dispatcher.ts`, `app-store.ts`) is the URL's *scheme* validated. Git supports the `ext::<command>` remote helper transport, which executes an arbitrary shell command when git performs any operation (fetch/ls-remote/clone) against such a URL. I searched the codebase for any allow-list enforcement (`GIT_ALLOW_PROTOCOL`, `protocol.ext.allow`, scheme validation) and found none: [5](#0-4) 

The existing input hygiene in this codebase (`sanitize-ref-name.ts`, `testForInvalidChars`) only sanitizes *ref/branch names*, not URLs: [6](#0-5) 

and `parse-app-url.ts` only validates `branch`/`pr` query parameters, leaving the repository URL (`parsedPath`) completely unvalidated for scheme: [7](#0-6) 

This mirrors the Sherlock bug's broken invariant: a value nominally scoped to identify a *remote/counterparty* (the compose message's `srcChainSender_`, here the PR's head-repo URL) is trusted and used directly in a privileged operation (spawning a git subprocess against an arbitrary transport) without checking that it stays within the expected trust boundary (an `https://`/`ssh://`/`git://` GitHub-hosted remote).

### Impact Explanation
If confirmed exploitable end-to-end (see Likelihood), this allows a fork/PR-controlled string to reach `git`'s `ext::` helper, which executes an arbitrary command with the privileges of the Desktop process — i.e., remote code execution triggered purely by a victim clicking "Checkout" on an attacker-authored Pull Request or Desktop deep link, without any local access, malware, or leaked credentials. This matches the requested impact class (code execution triggered by attacker-controlled GitHub API object / clone flow).

### Likelihood Explanation
Medium-to-High, with an important caveat I could not fully resolve from the index: modern `dugite`/git builds since 2.14.1 disable the `ext::`/`fd::` helpers or gate them behind `GIT_ALLOW_PROTOCOL` / `protocol.ext.allow=never` by default at the git binary level, independent of the calling application. I was unable to locate, within this repository's indexed files, any explicit environment configuration (e.g., in `app/src/lib/git/environment.ts` or equivalent) that either sets `GIT_ALLOW_PROTOCOL` to a safe allow-list or that would confirm the app relies purely on git's own upstream default protections. Because of index size limits, I could not verify the full contents of every environment-setup file that wraps `git()` invocations. This should be verified in the actual repository (not just index) — specifically whether the git spawn wrapper in `app/src/lib/git/core.ts` / `environment.ts` sets `GIT_ALLOW_PROTOCOL` or relies solely on git's own upstream defaults — before treating this as a confirmed, exploitable finding.

### Recommendation
- Validate `headCloneUrl` (and any other externally-sourced repository URL used in `addRemote`/`setRemoteURL`/clone flows) against an explicit allow-list of schemes (`https:`, `http:`, `ssh:`, `git:`) before calling `git remote add`/`git fetch`.
- Explicitly set `GIT_ALLOW_PROTOCOL` (or `protocol.ext.allow=never`, `protocol.fd.allow=never`) in the environment used for every `git()` invocation, rather than relying implicitly on the bundled git version's defaults.
- Apply the same scheme validation to `parseAppURL`'s `open-repository-from-url` action and to `fork.clone_url` used in `_convertRepositoryToFork`.

### Proof of Concept
Full exploitation could not be reproduced/confirmed against a live git binary configuration from static analysis alone; the concrete PoC path (pending verification of point above) would be:
1. Attacker forks a public repo and, via the GitHub API/manipulated response or a malicious GitHub Enterprise-style API, causes `pullRequest.head.repo.clone_url` to be `ext::sh -c "touch /tmp/pwned"` (or an equivalent OS command).
2. Victim clicks "Checkout" on the PR in Desktop's PR list (`pull-request-list.tsx` → `dispatcher.checkoutPullRequest`) or opens a `x-github-client://openRepo/...?pr=NNN` deep link.
3. `_findPullRequestBranch` calls `addRemote(repository, forkRemoteName, headCloneUrl)` then `_fetchRemote`, causing git to invoke the `ext::` helper and execute the attacker's command. [8](#0-7) [3](#0-2)

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }
