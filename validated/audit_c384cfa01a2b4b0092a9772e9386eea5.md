### Title
Gasless swap `deadline` is validated only at mempool admission time, not re-checked before block inclusion, allowing a lender-funded swap to execute with an expired deadline - (File: kaiax/gasless/impl/tx_pool.go / kaiax/gasless/impl/getter.go)

### Summary
The Sherlock report flags that `VestingEscrowFactory.deployVestingContract` fails to enforce that a time-bound parameter (`vestingStart`) is validated against `block.timestamp` at the time it actually matters, allowing an already-invalid time window to be accepted. The analogous root cause exists in Kaia's gasless module: the `SwapArgs.Deadline` supplied in a `swapForGas` transaction is checked against the current block time only in `checkBalanceForSwap` (invoked from `GetCheckBalance`, i.e., at transaction-pool admission), but the authoritative "is this transaction executable" gate used to promote a swap (and its paired lend transaction) into a block — `VerifyExecutable`/`IsExecutable` — never re-validates `Deadline` against the block being built.

### Finding Description
`checkBalanceForSwap` performs the deadline check once: [1](#0-0) 

This function is only reachable through `GetCheckBalance`, which is used at tx-pool admission (`PreAddTx`/`AddLocal`/`AddRemote` style balance checks), not at the point of actual promotion/execution: [2](#0-1) 

However, the function that governs whether a gasless swap (optionally paired with an approve tx) is promoted into `ready`/pending and ultimately executed with a proposer-funded `LendTx` is `VerifyExecutable`, which enforces sender/token/amount/nonce/repay invariants but contains **no deadline check at all**: [3](#0-2) 

`IsReady`/`isReady`/`isSwapTxReady`/`isApproveTxReady` — the functions that decide promotion into the pending pool for block building — call `IsExecutable`, which just wraps `VerifyExecutable`: [4](#0-3) [5](#0-4) 

Because a transaction can remain in the pool for an extended period between initial admission (when `checkBalanceForSwap` ran and deadline was valid) and actual block-building/promotion (when `VerifyExecutable` runs but does not re-check deadline), the deadline check can become stale. If the block time advances past `Deadline` while the swap tx is still queued/pending, `VerifyExecutable` will still return success, `IsReady` will still promote it, and the proposer will still generate a `LendTx` to front the gas fee via `GetLendTxGenerator`, executing a swap whose sender intended (via `deadline`) to bound their price/slippage exposure to a specific time window. This mirrors the reported vesting bug's root cause: a time-boundary check exists at contract construction/admission time but is not re-enforced at the point where the time-sensitive action is actually carried out.

### Impact Explanation
An expired-deadline swap being executed means the sender's price-protection intent (bounding execution to a time window, analogous to a slippage/MEV protection mechanism) is not honored by the node's block-assembly logic. Combined with `minAmountOut`/`amountRepay` checks that are done once at admission against potentially stale exchange rates (in `checkBalanceForSwap`'s `ShouldCheckSwapAmount` branch, also not re-verified in `VerifyExecutable`), this can let a proposer or a delayed promotion path settle a swap under conditions the user explicitly tried to time-bound, resulting in an economically unfavorable (or gameable) gasless-swap settlement funded by the protocol's `LendTx`/repay mechanism. This is a fee-delegation/gasless settlement integrity issue reachable by any ordinary swap sender or by block proposers deciding when to promote pending gasless bundles.

### Likelihood Explanation
Reachable by any unprivileged sender submitting a normal `swapForGas` (optionally preceded by an `approve`) transaction through the public transaction pool — no special privileges required. The condition triggers naturally whenever a swap transaction is not promoted immediately (e.g., it is queued behind nonce gaps, waiting for other module logic, or reprocessed after a chain reorg via `PostReset`/`PreReset`), which is an ordinary and expected occurrence in a live mempool, not a contrived edge case.

### Recommendation
Add a deadline (and any other block-time-relative) re-validation directly inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, comparing `swapArgs.Deadline` against the current block time available at promotion, so a swap tx is rejected/demoted the moment it becomes stale, mirroring the check already present in `checkBalanceForSwap`. Consider centralizing all `SwapArgs` runtime-condition checks (deadline, amount thresholds) so they are enforced consistently both at admission and at final promotion/execution.

### Proof of Concept
1. Attacker/sender submits `approveTx` (nonce N) and `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline=T)` (nonce N+1) where `T` is a few blocks in the future.
2. At admission, `checkBalanceForSwap` passes because `T > currentBlock.Time()` — see check at [1](#0-0) .
3. Due to other pending transactions, nonce gaps, or delayed promotion (`isApproveTxReady`/`isSwapTxReady` cycles across multiple `IsReady` calls), the swap tx is not promoted to `pending`/executed until several blocks later, when `currentBlock.Time() > T`.
4. When promotion finally occurs, `IsExecutable`→`VerifyExecutable` is called and returns `nil` (no error) because it never inspects `swapArgs.Deadline` — see [6](#0-5) .
5. The proposer generates and includes a `LendTx` via `GetLendTxGenerator`, and the expired-deadline swap executes on-chain, settling at a time the user's `deadline` parameter was meant to forbid.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

// isSwapTxReady assumes that the caller checked `g.IsSwapTx(swapTx)`
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
