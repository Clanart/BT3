### Title
`LazyFieldLite` silently swallows `InvalidProtocolBufferException` and reports parse success with an unused corruption flag - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
The Sherlock report flags `CrabNetting`'s constructor for calling `IERC20.approve()` without checking the boolean return value, so a token that returns `false` on failure is treated by the contract as if the approval succeeded. The transferable invariant is: **a call that can fail by returning a false/failure signal (instead of throwing) is not checked, so the caller proceeds as if the operation succeeded, silently corrupting downstream state.** In `LazyFieldLite`, the same shape of bug exists in Java's lite-runtime lazy-field parsing: when `ensureInitialized`, `mergeFrom`, and `mergeValueAndBytes` encounter an `InvalidProtocolBufferException` while lazily parsing an embedded message from a public `parseFrom`/`mergeFrom` entry point, the exception is caught and discarded, the field is silently replaced by the message's default instance (or left unchanged), and the only signal of failure — a private `corrupted` boolean — is written but never read by any consumer in the runtime.

### Finding Description
`LazyFieldLite.ensureInitialized` performs the actual lazy parse of an embedded/extension message from previously-buffered bytes: [1](#0-0) 

When `defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry)` throws `InvalidProtocolBufferException` (i.e., the attacker-controlled bytes are malformed protobuf), the exception is caught, `corrupted` is set to `true`, and `value`/`memoizedBytes` are quietly reset to the type's empty default — with the explicit comment "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." The same discard-on-failure pattern is repeated in `mergeFrom(CodedInputStream, ExtensionRegistryLite)` and the private helper `mergeValueAndBytes`: [2](#0-1) 

The `corrupted` flag is the only artifact recording that a failure occurred, exposed only via a package-private `isCorrupted()` accessor: [3](#0-2) 

A repository-wide search found no caller in the runtime that reads `isCorrupted()` — the failure signal is produced but never consumed, mirroring the report's "missing return value check": a signal exists that an operation failed, but nothing acts on it, so subsequent code (serialization, `equals`, `getValue()`, merge logic) treats the field as a normal, successfully-populated (empty) message rather than as evidence of tampered/malformed input.

### Impact Explanation
For lite-runtime messages using lazily-parsed embedded fields or extensions (`MessageSet`-style extensions, lazy nested messages), a malformed sub-message silently collapses to an empty default instance instead of surfacing a parse error to the caller of the outer message's public `parseFrom`/`mergeFrom` API. This breaks the general protobuf invariant that "parsing either fully succeeds and yields a faithful representation of the input, or reports failure" — here it can succeed at the outer level while quietly dropping/discarding a nested field's true (corrupt) content, and any application logic relying on `getValue()` returning genuine parsed data instead sees a silently-substituted empty message. This is analogous to the ERC20 case: a failure condition exists but is swallowed, and downstream logic (application/business logic keyed off the outer message) proceeds under an incorrect assumption of correctness/completeness.

### Likelihood Explanation
The condition is reachable by any client sending a bounded, malformed embedded/lazy sub-message via the standard public `parseFrom`/`mergeFrom` binary parsing APIs — no privileged access or hostile schema is required, only a crafted bounded payload for a lazily-parsed field. This is consistent with the assumed threat model (ordinary client sending bounded binary protobuf through a supported public parse API).

### Recommendation
Do not silently discard `InvalidProtocolBufferException` in `ensureInitialized`, `mergeFrom`, and `mergeValueAndBytes`. At minimum, propagate the `corrupted` state to a public, checkable signal (or rethrow/wrap the exception so it surfaces to the outer `parseFrom`/`mergeFrom` caller), so that callers cannot mistake a corrupted lazy field for a legitimately empty one — analogous to using `SafeERC20`-style explicit success checks instead of ignoring the boolean/error signal.

### Proof of Concept
Conceptual reproduction (not run, since this is static analysis of the checkout):
1. Construct a message type with a lazily-parsed embedded field (`LazyFieldLite`-backed) using the lite runtime.
2. Serialize the outer message with the sub-message bytes replaced by a truncated/invalid varint-length-delimited blob for that field.
3. Call the outer message's public `parseFrom(byte[])`.
4. Observe that outer parse succeeds and `outer.getExtension(...)`/lazy accessor returns the type's default (empty) instance rather than an error, while `LazyFieldLite.isCorrupted()` (internally set `true`) is never consulted by any caller in [1](#0-0) , confirming the failure signal is generated but discarded.

Note: I was unable to fully trace every external caller of `LazyFieldLite` across the whole `java/` tree (e.g., generated `GeneratedMessageLite` extension-handling code) within the available search budget, so I cannot rule out that some higher-level caller checks `isCorrupted()` indirectly through another path not surfaced by the grep search. This should be verified with a full-repository grep for `LazyFieldLite` usages and `corrupted`/`isCorrupted` before finalizing severity.

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
