### Title
Operator attribution in `payout_tx` is read from an OP_RETURN output that the withdrawer's signature never commits to - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The protocol's entire "who fronted this withdrawal and is therefore owed reimbursement" bookkeeping is derived by parsing an `OP_RETURN` output of the confirmed `payout_tx` for an embedded operator x-only pubkey. That `OP_RETURN` output is not covered by the withdrawer's signature because the withdrawal signature uses `SIGHASH_SINGLE|ANYONECANPAY`, which only commits to the single input being spent and the output at the same index (the user's payout output) — it explicitly leaves every other output, including the `OP_RETURN` attribution output, unsigned and mutable by anyone. This breaks the binding "the operator credited for reimbursement == the operator who actually funded the payout."

### Finding Description
`create_payout_txhandler` builds the payout transaction with three outputs: the user's payout, an anchor output, and an `OP_RETURN` output that embeds `operator_xonly_pk` — the value later used to determine who gets reimbursed: [1](#0-0) 

The witness for the sole (KeySpend) input is set directly from the caller-supplied `user_sig` without validating which output indices that signature actually commits to: [2](#0-1) 

The withdrawal signature scheme used throughout the codebase for this input is `TapSighashType::SinglePlusAnyoneCanPay`: [3](#0-2) 

`SIGHASH_SINGLE|ANYONECANPAY` commits only to the input being spent and to the output at the same index as that input (index 0, the user's payout). It does **not** commit to the anchor output or, critically, to the `OP_RETURN` output that records the operator's x-only pubkey. Anyone in possession of the raw signed transaction (obtained from the `Withdraw`/`InternalWithdraw` RPC response, which returns the `RawSignedTx` directly to the caller, or simply observed unconfirmed in the mempool) can therefore construct an alternate version of the same transaction — reusing the signed input and the signed user-payout output unchanged — but substituting an arbitrary x-only pubkey into the `OP_RETURN` output, and (since `ANYONECANPAY` also permits adding further inputs) attach their own fee-bump/RBF funding input(s) to get that variant confirmed instead of the original.

On confirmation, `update_finalized_payouts` blindly trusts this unauthenticated field to attribute the payout to an operator: [4](#0-3) 

That attribution is persisted and later drives the entire reimbursement pipeline: locating "first unhandled payout" for an operator's xonly key, [5](#0-4) 
validating that the credited payer matches the requesting operator before releasing reimbursement transactions, [6](#0-5) 
and finally spending the deposit's move-to-vault UTXO to the credited operator's reimbursement address via the `Reimburse` transaction: [7](#0-6) 

At no point is the party who actually supplied the funding input(s) to the confirmed `payout_tx` cross-checked against the x-only pubkey embedded in its `OP_RETURN`.

### Impact Explanation
This is the direct structural analog of the reported bug class ("balance/attribution recorded in accounting is not bound to the actual value movement, and nothing reconciles the two"). Here, the accounting primitive is on-chain (an `OP_RETURN` field) rather than a Solidity mapping, but the same disconnect exists: the field that grants entitlement to draw down the move-to-vault UTXO (an operator's reimbursement credit) is never cryptographically bound to who actually paid the user. An attacker who substitutes their own pubkey into the `OP_RETURN` and gets their variant of the transaction confirmed first can be credited as the payer and become eligible to claim reimbursement from the bridge's move-to-vault UTXO for a withdrawal an honest operator may have set up or intended to front — i.e., "an operator reimbursed for a payout it never funded," and correspondingly the honest operator that expected credit can be denied it.

### Likelihood Explanation
Exploitation requires only observing/obtaining the raw signed payout transaction (returned directly by the `Withdraw`/`InternalWithdraw` RPCs, or visible once broadcast to the mempool) and racing to get a modified variant (same signed input/output, different `OP_RETURN`, attacker-supplied extra funding input) confirmed first. No verifier, aggregator, or operator role is required — any unprivileged party who can observe the transaction and broadcast a competing one qualifies, which fits the required "unauthenticated state-changing/broadcasting call" threat model.

### Recommendation
Bind operator attribution to something the withdrawal signature (or a separate protocol-level commitment) actually authenticates: e.g., require the withdrawer's signature to use `SIGHASH_ALL` (or otherwise cover the `OP_RETURN` output), or have verifiers independently attest/co-sign which operator is entitled to reimbursement instead of trusting an unsigned `OP_RETURN` field parsed from the confirmed chain state.

### Proof of Concept
1. Operator A calls `Withdraw`, which builds `payout_tx` per `create_payout_txhandler` with `operator_xonly_pk = A`'s key and a `user_sig` using `SinglePlusAnyoneCanPay` (covering only the input and the user's payout output). [8](#0-7) 
2. Before this transaction confirms, an attacker (or colluding Operator B) observes it (via RPC response or mempool), and builds a variant transaction: same signed input, same signed user-payout output, but replaces the `OP_RETURN` output with `operator_xonly_pk = B`, and adds an extra funding input (permitted by `ANYONECANPAY`) with a higher fee.
3. The attacker's variant confirms instead of A's original.
4. `update_finalized_payouts` parses the `OP_RETURN` from the confirmed tx and records `payout_payer_operator_xonly_pk = B`. [4](#0-3) 
5. `validate_payer_is_operator`/`get_first_unhandled_payout_by_operator_xonly_pk` subsequently allow B to walk the kickoff/reimburse flow and receive the deposit's move-to-vault funds via `create_reimburse_txhandler`, even though B never funded A's original payout intent. [6](#0-5)

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

fn sign_withdrawal_output(
    config: &BridgeConfig,
    dust_utxo: &UTXO,
    withdrawal_address: &bitcoin::Address,
    withdrawal_amount: bitcoin::Amount,
) -> (bitcoin::TxOut, taproot::Signature) {
    let signer = Actor::new(config.secret_key, config.protocol_paramset().network);
    let txin = builder::transaction::input::SpendableTxIn::new(
        dust_utxo.outpoint,
        dust_utxo.txout.clone(),
        vec![],
        None,
    );
    let txout = bitcoin::TxOut {
        value: withdrawal_amount,
        script_pubkey: withdrawal_address.script_pubkey(),
    };
    let unspent_txout = builder::transaction::output::UnspentTxOut::from_partial(txout.clone());

    let tx = builder::transaction::TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            builder::transaction::DEFAULT_SEQUENCE,
        )
        .add_output(unspent_txout.clone())
        .finalize();

    let sighash = tx
        .calculate_sighash_txin(0, sighash::TapSighashType::SinglePlusAnyoneCanPay)
        .expect("Failed to calculate sighash");

    let sig = signer
        .sign_with_tweak_data(sighash, builder::sighash::TapTweakData::KeyPath(None), None)
        .expect("Failed to sign");

    let sig = taproot::Signature {
        signature: sig,
        sighash_type: sighash::TapSighashType::SinglePlusAnyoneCanPay,
    };

    (txout, sig)
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }
