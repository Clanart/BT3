### Title
Out-of-range blame recipient causes reachable panic in `Decryption::decrypt_with_proof` - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`AdditionalBlameMachine::blame` accepts `sender` and `recipient` identifiers without checking that they belong to the DKG participant set. If a blame request specifies a recipient outside `1..=n` and includes a syntactically valid `EncryptedMessage` plus any `EncryptionKeyProof`, `Decryption::decrypt_with_proof` indexes `self.enc_keys[&decryptor]` before validating the proof, causing a panic.

### Finding Description
`EncryptedMessage::read` permits an untrusted byte string to specify the ephemeral encryption key, Schnorr proof-of-possession, and encrypted share bytes [1](#0-0) . `EncryptionKeyProof::read` likewise deserializes an arbitrary canonical point and DLEq proof [2](#0-1) .

When `decrypt_with_proof` is called with `Some(proof)`, it evaluates `self.enc_keys[&decryptor]` while constructing the DLEq verification inputs [3](#0-2) . `AdditionalBlameMachine::new` only inserts keys for participant indexes `1..=n` [4](#0-3) , but `AdditionalBlameMachine::blame` performs no bounds check on `recipient` [5](#0-4) . A missing key therefore panics through `HashMap` indexing before the supplied proof is verified.

### Impact Explanation
An unprivileged protocol participant can send a blame claim naming a nonexistent participant index, accompanied by attacker-controlled serialized messages. The victim process reaches an unchecked indexing operation and terminates, creating a remote denial-of-service analogous to the TinyXML reachable assertion.

### Likelihood Explanation
The attacker only needs a valid Schnorr proof-of-possession for a public key they generated, malformed canonical proof bytes sufficient to make `Some(proof)`, and a blame request whose `recipient` is greater than `n`. The panic occurs before the DLEq proof is checked, so the proof does not need to be valid.

### Recommendation
Validate `sender` and `recipient` against the registered participant set at the start of `BlameMachine::blame_internal` and `AdditionalBlameMachine::blame`. Replace indexing with `HashMap::get` and return a defined error or classify the accusing party as faulty when either participant is unknown.

### Proof of Concept
```rust
// Setup: an AdditionalBlameMachine initialized for participants 1..=n.
let mut machine = AdditionalBlameMachine::<Ristretto>::new(
    context,
    n,
    valid_commitment_messages,
)?;

// Choose a malicious recipient outside the registered set.
let bad_recipient = Participant::new(n + 1).unwrap();
let sender = Participant::new(1).unwrap();

// Construct EncryptedMessage bytes where:
// - key = x * G
// - pop = SchnorrSignature { R: r * G, s: r + challenge * x }
// - challenge is the public pop_challenge transcript for `sender`
// - msg is any SecretShare-sized ciphertext
let mut encrypted_bytes = vec![];
encrypted_bytes.extend(key.to_bytes());
encrypted_bytes.extend(pop.R.to_bytes());
encrypted_bytes.extend(pop.s.to_repr());
encrypted_bytes.extend([0u8; 32]);

let encrypted = EncryptedMessage::<Ristretto, SecretShare<_>>::read(
    &mut encrypted_bytes.as_slice(),
    params,
)?;

// Any Some(proof) reaches decrypt_with_proof. The malformed DLEq is not checked
// before self.enc_keys[&bad_recipient] is indexed.
let proof = EncryptionKeyProof::read(&mut malformed_proof_bytes.as_slice()).ok();

// Panics: key `bad_recipient` was never inserted into enc_keys.
machine.blame(sender, bad_recipient, encrypted, proof);
```
