### Title
Reward Sniping via Flash Deposit/Withdraw into MasterMagpie/WombatStaking Pools — ([File: wombat/WombatStaking.sol], [File: rewards/BaseRewardPool.sol])

### Summary
`WombatStaking.harvest()` crystallizes the entire pending WOM (and bonus token) yield accrued since the last harvest and instantly distributes it into the corresponding `BaseRewardPool`/`BaseRewardPoolV2` proportional to the *current* `totalStaked()` snapshot. Because `MasterMagpie.deposit`/`withdraw` have no cooldown, lock, or same-block/same-transaction restriction, an unprivileged wallet can flash-deposit a large stake immediately before triggering (or piggybacking on) a harvest, capture a disproportionate share of previously-accrued yield that it did not earn, and withdraw in the same transaction — directly analogous to the reported tranche liquidation-penalty sniping bug.

### Finding Description
`WombatStaking.harvest(_lpToken)` is fully permissionless (only gated by `_onlyActivePool`, not by staker identity) and calls `_toMasterWomAndSendReward`, which pulls the entire pending WOM reward accumulated in `MasterWombat` since the previous harvest and routes it via `_sendRewards` to `queueNewRewards` on the pool's `BaseRewardPool`/`BaseRewardPoolV2`: [1](#0-0) [2](#0-1) 

`queueNewRewards`/`_provisionReward` increases `rewardPerTokenStored` in one atomic step based on `totalStaked()` at that exact instant, with no time-weighting of how long each staker has held their position: [3](#0-2) 

`totalStaked()` and `balanceOf()` simply read the live token balances tracked by `MasterMagpie`: [4](#0-3) 

`MasterMagpie._deposit`/`_withdraw` (and their `*For` variants used by pool helpers) apply immediately with no minimum holding period, no same-block guard, and no `onlyEOA`/flash-loan protection: [5](#0-4) 

Because deposits and withdrawals can be combined with a harvest call inside a single transaction, an attacker can inflate `totalStaked()` right before a large pending-reward crystallization, absorb a disproportionate share of `rewardPerTokenStored`, harvest it, and withdraw — all funded by a flash loan and at zero real capital cost or duration risk. This is the direct analog of the external report's tranche liquidation-penalty sniping: an instantaneous, lump-sum yield event distributed pro-rata to point-in-time stake, with no deposit/withdraw cooldown to prevent flash sniping.

### Impact Explanation
Legitimate long-term liquidity providers/stakers in `MasterMagpie` pools have their rightfully accrued WOM/bonus-token yield diluted and redirected to a flash attacker who contributed no real staking duration. This constitutes theft of unclaimed yield from genuine stakers, repeatable on every harvest cycle across all unlocked (non-cooldown) `MasterMagpie` pools.

### Likelihood Explanation
Medium-High: `harvest()` is permissionless and can be called by anyone (or implicitly triggered via deposit/withdraw flows in `WombatStaking.deposit`/`depositLP`/`withdraw`), no frontrunning is required since the attacker can atomically bundle deposit → harvest → withdraw in one transaction, and no anti-flash-loan mechanism (`onlyEOA`, minimum stake duration, same-block deposit/withdraw block) exists anywhere in `MasterMagpie.sol`, `WombatStaking.sol`, or `BaseRewardPool*.sol`.

### Recommendation
Forbid deposit and withdrawal (or claiming of newly-queued rewards) within the same transaction/block for a given account, or apply a minimum holding-period/vesting requirement before newly deposited stake becomes eligible to earn a share of rewards queued via `queueNewRewards`/`_toMasterWomAndSendReward`.

### Proof of Concept
1. Attacker flash-borrows a large amount of the pool's deposit token.
2. Attacker calls the pool helper's `deposit`/`depositLP`, which calls `WombatStaking.deposit`/`depositLP` → mints receipt tokens → stakes via `MasterMagpie.depositFor`, becoming the dominant share of `totalStaked()` for that pool (`rewards/MasterMagpie.sol:481-505`).
3. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)`, crystallizing all WOM/bonus rewards accrued since the last harvest into `queueNewRewards`, instantly inflating `rewardPerTokenStored` weighted by the now-inflated `totalStaked()` (`wombat/WombatStaking.sol:329-335`, `671-696`; `rewards/BaseRewardPoolV2.sol:290-313`).
4. Attacker calls withdraw via the pool helper → `MasterMagpie.withdrawFor` → `_harvestAndUnstake` claims the sniped reward share via `_harvestBaseRewarder`/`getRewards` (`rewards/MasterMagpie.sol:507-534`).
5. Attacker repays the flash loan, pocketing yield that was actually earned by long-term LPs over the harvest interval.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
