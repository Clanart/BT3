Confirmed: `addSafeDirectory` in `app/src/lib/git/config.ts` permanently appends the path to the global `safe.directory` list, and there is no corresponding call anywhere in the codebase that ever calls `removeGlobalConfigValue('safe.directory', ...)` or otherwise removes an entry once trust is granted. `RepositoriesStore.removeRepository` only deletes the local DB row and calls `clearTagsToPush` — it never touches the git global config trust list.

### Title
Trusted `safe.directory` entries are never revoked, letting a re-cloned/attacker-controlled repository at the same path silently bypass Git's dubious-ownership protection - (File: `app/src/lib/git/config.ts`)

### Summary
GitHub Desktop surfaces Git's "dubious ownership" protection (`getRepositoryType` returning `kind: 'unsafe'`) and offers a "Trust Repository" action that calls `addSafeDirectory`, which appends the path to the global `safe.directory` git config list. This entry is permanent: no code path ever removes it, including when the repository is removed from Desktop.

### Finding Description
`addSafeDirectory` (`app/src/lib/git/config.ts:181-189`) calls `addGlobalConfigValueIfMissing('safe.directory', path)`, which appends the path to the user's global `.gitconfig` if it isn't already present: [1](#0-0) 

This is invoked from two UI flows once a user clicks "Trust Repository" / "add an exception for this directory": [2](#0-1) [3](#0-2) 

Once added, the `path` string stays in `safe.directory` indefinitely — `RepositoriesStore.removeRepository` only deletes the DB record and clears pending tags, with no `removeGlobalConfigValue('safe.directory', ...)` call: [4](#0-3) 

`removeGlobalConfigValue`/`removeConfigValueInPath` exist and are capable of doing `git config --global --unset-all safe.directory <path>`, but they are simply never invoked for this purpose: [5](#0-4) 

The broken invariant is exactly analogous to the FSD report: a value (`pendingWithdrawals` / here, "this specific path is currently a trusted, user-verified Git working tree") is set once but never decremented/cleared when the underlying condition it was meant to represent (the currently-reviewed repository owned by that user) goes away. Downstream, `getRepositoryType` treats *any* future content at that same filesystem path as trusted forever, because Git's dubious-ownership check is solely path-based: [6](#0-5) 

Concretely, once a path has been trusted, "Clone Again" in `MissingRepository` can re-populate that exact path with content from an attacker-controlled `cloneURL` (`gitHubRepository.cloneURL`, itself sourced from the GitHub API), and Git will run without any ownership warning against it, since the path is already whitelisted: [7](#0-6) 

The unsafe-owner warning explicitly documents what this bypass protects against: automatic execution of files in the repository (hooks, filters, etc.): [8](#0-7) 

### Impact Explanation
Git's `safe.directory` mechanism exists specifically to stop automatic execution of repository-controlled content (hooks, `core.fsmonitor`, filters, etc.) for directories not owned/verified by the current user — this is the fix for CVE-2022-24765. Because Desktop's trust decision is permanently recorded per-path with no invalidation, an attacker who can get content written to a path that was previously trusted (e.g., via a GitHub-API-driven "Clone Again" using a malicious/renamed `cloneURL`, or content dropped into a directory whose ownership later changes) inherits the trust without any prompt, allowing repository-controlled hooks/config to execute automatically — potential code execution on the user's machine.

### Likelihood Explanation
This requires an initial legitimate trust decision on a path and then that same path later being repopulated with attacker content (e.g., via a manipulated clone URL fetched through Desktop's GitHub API integration, `IAPIRepository.clone_url`/`ssh_url`), which is a real, if narrow, workflow already built into the app (`cloneAgain`). No admin rights, local malware, or leaked credentials are needed — only reuse of a path the user previously trusted plus an attacker-influenced clone source. Likelihood is moderate rather than high because it depends on path reuse and an attacker-controlled clone target.

### Recommendation
- Call `removeGlobalConfigValue('safe.directory', path)` (already implemented via `removeConfigValueInPath`) whenever `RepositoriesStore.removeRepository` deletes a repository that was previously marked unsafe/trusted, and whenever a repository's path changes away from a trusted path.
- Re-validate ownership (not just path membership in `safe.directory`) before treating "Clone Again" targets as implicitly trusted, especially when the destination path was trusted for a *different* previously-known repository/remote.
- Consider scoping trust to a repository identity (e.g., remote URL + path) rather than path alone, or re-prompting when the on-disk repository's origin/remote no longer matches what was trusted originally.

### Proof of Concept
1. User clones/opens a legitimate repository at path `P`, Git reports "dubious ownership" (e.g., due to a shared/mounted directory), user clicks "Trust Repository" → `addSafeDirectory(P)` permanently adds `P` to global `safe.directory`.
2. User later removes this repository from Desktop (`removeRepository`) — `P` remains in `safe.directory` forever; nothing in `app/src/lib/stores/repositories-store.ts` calls `removeGlobalConfigValue`.
3. At some later point, path `P` is repopulated with a different, attacker-controlled Git repository (e.g., user does "Clone Again" using a `cloneURL` returned by the GitHub API for a repository that has since been compromised/renamed, or another process writes to `P`).
4. `getRepositoryType(P)` never returns `kind: 'unsafe'` for this new content because `P` is still whitelisted in `safe.directory`, so Desktop runs Git commands (status, hooks, etc.) against attacker-controlled content without any warning, whereas a fresh open of that same malicious content anywhere else would have correctly triggered the unsafe-directory prompt.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}

export async function removeGlobalConfigValue(

    HOME: string
  }

/**
 * Remove config value by name
 *
 * @param path The path to execute the `git` command in. If null
 *             we'll use the global configuration (i.e. --global)
 *             and execute the Git call from the same location that
 *             GitHub Desktop is installed in.
 */
async function removeConfigValueInPath(
  name: string,
  path: string | null,
  env?: {
    HOME: string
  }
): Promise<void> {
  const options = env ? { env } : undefined

  const flags = ['config']

  if (!path) {
    flags.push('--global')
  }

  flags.push('--unset-all', name)

  await git(flags, path || __dirname, 'removeConfigValueInPath', options)
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
