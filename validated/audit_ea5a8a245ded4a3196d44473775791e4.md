## Analysis Result

Based on my investigation, I found a legitimate analog to the reported "no oracle" bug class within the reachable scope (gasless module, single-transaction-reachable path).

### Title
Gasless Swap Pricing Relies on Manipulable AMM Spot Price with No Oracle/TWAP Protection, Enabling Frontrunning of Gasless Swap Repayment - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
Kaia's gasless-transaction feature (KIP-247) determines whether a `GaslessSwapTx` is admissible/executable by calling `GaslessSwapRouter.GetAmountIn()`, which is a live, on-chain AMM (Uniswap-V2-style) spot-price view call with no oracle or TWAP smoothing, directly analogous to the reported "no Oracle usage" bug class.

### Finding Description
`checkBalanceForSwap` validates a pending `GaslessSwapTx` by querying the DEX router for the current required `amountIn` for the user's declared `minAmountOut`, using the pool's instantaneous reserves: [1](#0-0) 

This value is a raw AMM spot price (`getAmountIn`/reserve-based, see `GaslessSwapRouter.GetAmountIn`) with no external oracle, no TWAP, and no manipulation-resistance mechanism: [2](#0-1) 

The repayment amount owed by the user to the block-proposer/lender is fixed at submission time based on gas price and lend amount, independent of the swap's actual execution-time output: [3](#0-2) 

The actual swap execution happens later, when the bundle (`[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]`) is incorporated into a block by the block builder: [4](#0-3) 

Because the AMM price used for `minAmountOut`/`amountRepay` validation is a spot price with no oracle protection, any unprivileged transaction sender who observes a pending `GaslessSwapTx` in the public mempool (or the block-building proposer itself, who controls transaction ordering within the block) can submit an adjacent large swap on the same DEX pool to shift reserves before the gasless swap executes — the same "frontrunning `putPrice`"-class attack described in the external report, but here applied to `GaslessSwapRouter`'s AMM-derived exchange rate instead of an oracle feed.

### Impact Explanation
If the swap's actual on-chain output falls below `minAmountOut` due to a sandwich/frontrun, the `GaslessSwapTx` reverts inside an already-lent-gas bundle. Since gas was already lent by the proposer via `LendTxGenerator` before the swap runs, this can result in the user being denied gasless-swap-based repayment, fee-delegation abuse (proposer's lent gas not being safely recovered), or a denial-of-service on all gasless transactions targeting a shallow-liquidity token, without needing a broken oracle at all — because Kaia's gasless swap price discovery has no oracle to begin with, an attacker can always sandwich the visible mempool transaction using ordinary AMM mechanics. This maps to the reported class of "Frontrunning Attacks" and "Center Point of Failure" arising from absence of a manipulation-resistant price source.

### Likelihood Explanation
Medium. It requires only a public mempool-visible pending `GaslessSwapTx`/`GaslessApproveTx` pair and a public swap transaction on the same DEX pool submitted by any unprivileged sender or the block proposer itself — no special privileges, node access, or validator collusion beyond ordinary transaction submission are needed. I was unable to fully verify (within available tool budget) whether bundle atomicity ensures the `LendTxGenerator` transaction and `GaslessSwapTx` revert or succeed together, which affects the exact loss vector (lender loss vs. user-only DoS); this affects severity calibration and would need confirmation in the `work/builder` bundle-execution code before treating the loss vector as fully proven.

### Recommendation
Bind the gasless swap's `minAmountOut`/`amountRepay` check to a manipulation-resistant price reference (e.g., a short TWAP over the target DEX pool, or a governance-approved oracle) rather than a pure instantaneous `GetAmountIn` spot-price call, and/or enforce a maximum allowable price deviation between mempool-admission time and block-inclusion time for gasless swaps.

### Proof of Concept
1. Attacker observes a pending `GaslessApproveTx`+`GaslessSwapTx` pair for token T on DEX pool P in the mempool (`checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go:107-182` validates it purely against `GaslessSwapRouter.GetAmountIn`, a live AMM reserve-based call).
2. Attacker (or the block proposer building the block) submits a large swap against pool P immediately before the gasless bundle is executed, shifting reserves and worsening T's exchange rate.
3. When the bundle `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` executes (`kaiax/gasless/impl/builder.go:28-72`), the DEX router returns less output than `minAmountOut`/`amountRepay` requires, causing the `GaslessSwapTx` to revert after gas has already been lent by the proposer, extracting value/denying service without any check against a manipulation-resistant price reference.

**Note on uncertainty:** I could not locate the actual Solidity source of `GaslessSwapRouter` (only its Go bindings) within the indexed codebase, and could not fully confirm bundle-revert atomicity semantics for lend/swap failure interactions. If precise confirmation of these mechanics is needed, a full Devin session with repository access would be required to inspect `kaiax/gasless` contract sources and `work/builder` bundle execution logic in full.

func (_GaslessSwapRouter *GaslessSwapRouterCaller) GetAmountIn(opts *bind.CallOpts, token common.Address, amountOut *big.Int) (*big.Int, error) {
	var out []interface{}
	err := _GaslessSwapRouter.contract.Call(opts, &out, "getAmountIn", token, amountOut)

	if err != nil {
		return *new(*big.Int), err
	}

	out0 := *abi.ConvertType(out[0], new(*big.Int)).(**big.Int)

	return out0, err

}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
