### Title
Payout tx's OP_RETURN operator credit is unauthenticated under `SinglePlusAnyoneCanPay`, letting an attacker hijack/deny operator reimbursement credit for a withdrawal - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the payout transaction with the withdrawal input signed only via `TapSighashType::SinglePlusAnyoneCanPay`, which BIP341/BIP118 semantics restrict to committing solely to input 0 and output 0. The OP_RETURN output that encodes `operator_xonly_pk` (output index 2) and all additional inputs (fee funding) are completely outside the signed message, so anyone possessing the user's signature can rebuild a competing, validly-signed transaction spending the same withdrawal outpoint with a different `operator_xonly_pk` in the OP_RETURN, and if it confirms first, the verifier's block-scan logic (`update_finalized_payouts`) and `get_payout_txs_for_withdrawal_utxos` will attribute the payout to whichever operator key appears in that OP_RETURN — regardless of who actually funded the transaction.

### Finding Description
The broken binding is:
`payout_payer_operator_xonly_pk` (written to DB by `update_finalized_payouts`) `==` `operator_that_actually_funded_output_txout` (the operator who spent real BTC fronting the user's withdrawal).

Trace:
1. `create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436) builds a tx with input 0 = withdrawal UTXO (key-spend, user-signed), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(`operator_xonly_pk`). Only input 0 is signed by the user via `set_p2tr_key_spend_witness(&user_sig, 0)`. [1](#0-0) 
2. The sighash type accepted from users is enforced to be exactly `SinglePlusAnyoneCanPay` in `parse_withdrawal_sig_params` (core/src/rpc/parser/operator.rs:161-203), and the operator itself computes/verifies this same sighash in `Operator::withdraw` (core/src/operator.rs:628-637). [2](#0-1) [3](#0-2) 
3. Per BIP341, `SinglePlusAnyoneCanPay` only commits to `input[0]`'s prevout and `output[0]`; `calculate_pubkey_spend_sighash`/`calculate_script_spend_sighash` explicitly use `Prevouts::One(txin_index, ...)` for this sighash type, confirming only a single input is bound and no other outputs are committed. [4](#0-3) 
4. The operator itself funds the tx via `fund_raw_transaction`/RBF (adding change/fee inputs) after user-sig verification, and never signs anything that covers the OP_RETURN output — there is no operator signature or commitment tying `operator_xonly_pk` in the OP_RETURN to the specific funding inputs. [5](#0-4) 
5. Once mined, `update_finalized_payouts` finds "whichever transaction spent the withdrawal outpoint" via `get_payout_txs_for_withdrawal_utxos`, which joins purely on `withdrawal_utxo_txid`/`vout` against `bitcoin_syncer_spent_utxos` — it does not pin to a specific pre-registered payout txid. [6](#0-5) 
6. It then parses whatever OP_RETURN appears in that mined transaction and blindly stores it as `payout_payer_operator_xonly_pk`, with no check that the credited key actually funded any of the transaction's inputs. [7](#0-6) [8](#0-7) 
7. `Verifier::is_kickoff_malicious` later only checks that the kickoff's `operator_xonly_pk` equals `payout_info.operator_xonly_pk` (the DB value written in step 6) and that the committed payout blockhash matches — it never re-derives who funded the payout. [9](#0-8) 

Exploit flow: An attacker (or colluding party) obtains the user's `SinglePlusAnyoneCanPay` signature and withdrawal parameters (these are public once posted through the withdraw path / visible in mempool once any operator broadcasts their own payout tx). The attacker constructs an alternate transaction re-using the same signed input 0 and output 0 (satisfying the exact same signature, since only those are covered), but swaps output 2's OP_RETURN to a different, uninvolved operator's `xonly_pk`, adds its own fee-paying input(s)/change, and broadcasts with a higher fee so it confirms before the honest operator's own broadcast (or replaces it via standard fee-based mempool/RBF competition — no majority hashrate required). Once mined, `update_finalized_payouts` credits the attacker-chosen operator as payer.

No existing guard prevents this: `SECP.verify_schnorr` only validates the user's signature over input 0/output 0 (unaffected by the swap), `is_deposit_valid`/`is_profitable` are unrelated to payout attribution, and `is_kickoff_malicious` trusts the DB-recorded `operator_xonly_pk` without any check against who funded the extra inputs.

### Impact Explanation
This is Critical: an honest operator that genuinely fronted the withdrawal payment becomes permanently unable to be reimbursed for it (since the DB now shows a different `payout_payer_operator_xonly_pk`, and the honest operator's own kickoff for that deposit would be flagged malicious by `is_kickoff_malicious` due to the mismatch), while the attacker-named operator can be credited and — if it proceeds through the kickoff/assert flow — reimbursed from bridge collateral for a payout it never funded. This is repeatable per-withdrawal for any deposit that goes through the operator payout path, and the blast radius spans all operators/deposits using this mechanism.

### Likelihood Explanation
Preconditions: the attacker needs the exact valid `SinglePlusAnyoneCanPay` signature and withdrawal parameters, which become available once any operator's payout transaction (or the underlying withdrawal request data) is visible (mempool broadcast or via Citrea's public withdraw call data/storage). The attacker must then win the standard Bitcoin fee/relay race to get their variant mined first — a normal, low-cost operation requiring only fee-rate competition, well within an unprivileged actor's stated capabilities (broadcasting txs, choosing signatures/witness/OP_RETURN). No majority hashrate, key compromise, or privileged access is required.

### Recommendation
Cryptographically bind the OP_RETURN operator credit to the payout transaction, e.g., have the *user's* signature also cover the OP_RETURN output (use `All`/`None` sighash variants appropriately, or commit the operator xonly_pk into the signed message/annex), or require an additional signature/commitment from the crediting operator over the whole transaction (including the OP_RETURN) before `update_finalized_payouts` accepts it. Alternatively, require the payout txid to match one that was explicitly pre-registered by the operator at withdraw-request time (pin txid, not just outpoint) rather than trusting whichever transaction happens to spend the withdrawal outpoint on-chain.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Returns the withdrawal indexes and their spending txid for the given

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
