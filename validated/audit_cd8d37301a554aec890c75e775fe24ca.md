### Title
Withdrawal payer attribution is forgeable via unauthenticated OP_RETURN output — `Operator::withdraw` sighash only commits input0+output0 - (File: core/src/operator.rs, core/src/builder/transaction/operator_reimburse.rs, core/src/verifier.rs)

### Summary
`Operator::withdraw` verifies the user's payout authorization with `SECP.verify_schnorr` over a sighash computed with `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, which only commits to input 0 and output 0 of the payout transaction. The OP_RETURN output (output 2) that names the operator credited as "payer" for the withdrawal is completely outside that commitment, so anyone who can observe the 64-byte signature and outpoint (via the public mempool, any operator's broadcast, or the aggregator) can construct a conflicting transaction with an arbitrary OP_RETURN and win the race to get it mined, hijacking which operator (or none) is recorded as the payer in the database.

### Finding Description
The binding the protocol relies on is:
`withdrawals.payout_payer_operator_xonly_pk` for withdrawal `i` (set by `update_finalized_payouts`) **==** the xonly pubkey of the entity that actually funded/authorized the payout for withdrawal `i`.

Trace of the code:
- `Operator::withdraw` (core/src/operator.rs:620-637) builds the payout tx via `create_payout_txhandler` and verifies:
  ```
  let sighash = payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)?;
  SECP.verify_schnorr(&in_signature.signature, &Message::from_digest(*sighash.as_byte_array()), user_xonly_pk)
  ``` [1](#0-0) 
- `create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436) builds three outputs: user payout (output0), anchor (output1), and an OP_RETURN with `operator_xonly_pk` (output2). Only output0 is covered by `SIGHASH_SINGLE|ANYONECANPAY`; outputs 1 and 2, and every additional input beyond input0, are unauthenticated by the user's signature. [2](#0-1) 
- Attribution is derived purely from whichever transaction is actually mined spending the registered withdrawal UTXO: `get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` on `(txid, vout)` with no signer/broadcaster check. [3](#0-2) 
- `update_finalized_payouts` parses the OP_RETURN of the winning mined tx and writes it into `payout_payer_operator_xonly_pk`, defaulting to `None` if missing/invalid. [4](#0-3) 
- Downstream, `Verifier::is_kickoff_malicious` and `Operator::validate_payer_is_operator` treat this stored pk as ground truth for who is entitled to reimbursement. [5](#0-4) [6](#0-5) 

Exploit flow: An attacker observes (from the public mempool, or from any operator's broadcast) a `payout_tx` for withdrawal `i` — or simply learns the 64-byte Schnorr signature and outpoint via any legitimate off-chain channel. The attacker extracts input0's witness (the user's presigned SINGLE|ANYONECANPAY signature) and constructs a new transaction reusing input0/output0 verbatim, adding their own fee-paying input(s), and a forged OP_RETURN naming an operator xonly pk of their choosing (or garbage bytes to force `None`). Because the sighash the signature covers ignores this OP_RETURN entirely, `SECP.verify_schnorr` — and consensus — accept the new transaction. If it confirms before the legitimate operator's transaction (a trivial RBF/fee race, cheap since the withdrawal UTXO itself is presumed pre-funded near the bridge amount by the withdrawal registration process, so only the marginal tx fee is at stake), `update_finalized_payouts` credits the attacker-chosen operator (or nobody) as payer.

No existing guard catches this: `SECP.verify_schnorr` only checks the covered sighash (input0+output0), `Verifier::is_kickoff_malicious` and `validate_payer_is_operator` both consume the already-corrupted DB column rather than independently verifying who funded/broadcast the transaction, and there is no uniqueness/ownership constraint tying the OP_RETURN bytes to the broadcaster's identity or signature.

### Impact Explanation
Two directly matching Critical categories from the rules:
- If the attacker names a legitimate but uninvolved operator's xonly pk, that operator becomes eligible to claim reimbursement via the kickoff/round mechanism for a payout it never actually funded/authorized broadcast of — "an operator reimbursed for a payout it never funded."
- If the attacker uses invalid/garbage OP_RETURN data (forcing `operator_xonly_pk = None`), `is_kickoff_malicious`/`validate_payer_is_operator` will reject every operator's claim for that withdrawal, since no operator's `signer.xonly_public_key` will ever match `None` — leaving the honest operator who intended to front the withdrawal permanently unable to be reimbursed, since the withdrawal UTXO is already spent and unattributable.

This is repeatable per-withdrawal, across every operator and every deposit that goes through a standard (non-optimistic) payout, since the flaw is structural to `create_payout_txhandler`'s sighash type and the DB attribution logic, not a per-instance bug.

### Likelihood Explanation
No privileged role is required — only the ability to observe a broadcast signature/outpoint (mempool, gossip, or any operator relay) and to broadcast a competing Bitcoin transaction paying a marginal fee. The attacker never needs verifier, operator, or aggregator credentials. The only cost is the transaction fee needed to outbid/replace the pending payout transaction in the mempool (cheap relative to the withdrawal size), making this highly feasible and repeatable against every withdrawal that uses the standard payout path.

### Recommendation
Bind the OP_RETURN operator-attribution output into the user's signed commitment, e.g., require the user's signature to use `SIGHASH_ALL` (or another sighash type/covenant construction, such as a script-path commitment) that covers the OP_RETURN output and the exact input set, so a third party cannot alter payer attribution without invalidating the signature. Alternatively, remove reliance on a mutable/unauthenticated OP_RETURN entirely and instead attribute payouts via a covenant-enforced structure (e.g., pre-committed per-operator payout scripts) that cannot be substituted after the fact.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Returns the withdrawal indexes and their spending txid for the given

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,

        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
