### Title
Reward/emission accounting relies on raw ERC20 balance of `MasterMagpie`, allowing anyone to permanently dilute unclaimed MGP and bonus-token yield via direct token donation - (File: `rewards/MasterMagpie.sol`, `rewards/BaseRewardPool.sol`)

### Summary
`MasterMagpie` and `BaseRewardPool` compute the denominator for per-share reward accrual (`_calLpSupply` / `totalStaked`) by reading the *live ERC20 balance* of the staking (receipt) token held by `MasterMagpie`, instead of using the internally tracked sum of user deposits. Any ordinary wallet holding the freely transferable receipt token can transfer it directly to the `MasterMagpie` contract (bypassing `deposit`/`depositFor`), inflating this denominator without increasing any user's `amount`. This permanently dilutes the MGP-per-share and reward-per-token math for every subsequent distribution, freezing/destroying yield owed to legitimate stakers, with no way to recover since the donated balance is never attributable to any `user.amount`.

### Finding Description
`MasterMagpie._calLpSupply` is used as the denominator for MGP emission accrual in `updatePool`/`_calMGPReward`: [1](#0-0) 

For any pool other than `vlmgp`/`mWomSV`, this simply returns `IERC20(_stakingToken).balanceOf(address(this))` — the *actual token balance* of the contract, not a ledger of deposited amounts. That value feeds directly into the reward-per-share update: [2](#0-1) 

Similarly, `BaseRewardPool.totalStaked()` (used to compute `rewardPerTokenStored` when bonus rewards are queued/donated) also reads the raw balance held by `operator` (`MasterMagpie`): [3](#0-2) [4](#0-3) 

The staking token for these pools is the receipt token minted by `WombatStaking`/pool helpers (e.g. `IMintableERC20` receipt tokens minted 1:1 on deposit in `WombatStaking.deposit`/`depositLP`), which is a standard, freely transferable ERC20: [5](#0-4) 

Because `deposit`/`depositFor` in `MasterMagpie` only increases `user.amount`/`user.available` when tokens arrive through the deposit path, and never reconciles `user.amount` totals against the contract's raw balance, an attacker can simply call `receiptToken.transfer(masterMagpieAddress, X)` directly. This inflates `_calLpSupply()` and `totalStaked()` immediately, without any corresponding increase in any user's tracked stake. All subsequent MGP emission (`updatePool`) and bonus reward distributions (`_provisionReward`/`queueNewRewards`) are then divided across an inflated denominator, permanently reducing the reward-per-share credited to every real staker. The donated tokens are never returned to anyone and are not tied to any `UserInfo`, so the dilution is irreversible.

### Impact Explanation
This is a direct, permanent freezing/loss of unclaimed yield for all legitimate stakers in the affected pool: every future MGP and bonus token distribution computed via `updatePool`/`_provisionReward` is diluted by the inflated, un-recoverable balance. Given the receipt tokens are cheap and easy to acquire (mint via deposit, or buy on open market since they're plain ERC20), an attacker can execute this at low cost repeatedly across every registered pool, materially and durably reducing rewards owed to real depositors. This satisfies the "permanent freezing of unclaimed yield" impact bar from an unprivileged wallet.

### Likelihood Explanation
High likelihood: no privileged role or governance action is required — any wallet holding the receipt/staking token (obtainable via ordinary deposit or open-market purchase) can call a plain `IERC20.transfer` to the known, public `MasterMagpie` contract address. No reentrancy or complex sequencing is needed.

### Recommendation
Track staked supply internally (e.g., a `totalStaked` state variable incremented/decremented in `_deposit`/`_withdraw`/`emergencyWithdraw`) instead of relying on `IERC20.balanceOf(address(this))`/`balanceOf(operator)` for both `MasterMagpie._calLpSupply` and `BaseRewardPool.totalStaked()`. This removes the ability for external token transfers to influence reward-per-share math.

### Proof of Concept
1. Attacker deposits (or buys) an amount of a pool's receipt token (e.g., via `WombatPoolHelper.deposit`), obtaining a transferable `stakingToken` (`IMintableERC20`) balance.
2. Attacker calls `stakingToken.transfer(masterMagpieAddress, largeAmount)` directly, bypassing `MasterMagpie.deposit`/`depositFor`.
3. `MasterMagpie._calLpSupply(_stakingToken)` (`rewards/MasterMagpie.sol:659-667`) now returns the inflated raw balance, and `BaseRewardPool.totalStaked()` (`rewards/BaseRewardPool.sol:126-128`) does the same for that pool's rewarder.
4. On the next `updatePool`/`massUpdatePools` call or reward donation (`queueNewRewards`/`donateRewards`), `accMGPPerShare` and `rewardPerTokenStored` are computed by dividing new rewards by this inflated denominator (`rewards/MasterMagpie.sol:385-387`, `rewards/BaseRewardPool.sol:314-317`), permanently reducing the reward-per-share credited to genuine stakers versus what they would have earned absent the donation.

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        if (block.timestamp <= pool.lastRewardTimestamp || totalAllocPoint == 0) {
            return;
        }
        uint256 lpSupply = _calLpSupply(_stakingToken);
        if (lpSupply == 0) {
            pool.lastRewardTimestamp = block.timestamp;
            return;
        }        
        uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
        uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
        
        pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
        pool.lastRewardTimestamp = block.timestamp;

        emit UpdatePool(
            _stakingToken,
            pool.lastRewardTimestamp,
            lpSupply,
            pool.accMGPPerShare
        );
    }

    function _calLpSupply(address _stakingToken) internal view returns (uint256) {
        if (_stakingToken == address(vlmgp)) {
            return IERC20(address(vlmgp)).totalSupply();
        }
        if (_stakingToken == address(mWomSV)) {
            return IERC20(address(mWomSV)).totalSupply();

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
