## Title
Locked/vesting balance at the EVM-cast address is permanently stranded during address association migration - (`utils/helpers/associate.go`)

## Summary
`AssociationHelper.MigrateBalance` only moves the *spendable* coins and wei balance from an account's EVM-cast Cosmos address (`castAddr = sdk.AccAddress(evmAddr[:])`) to the newly associated Sei address. Any `LockedCoins` (e.g. a vesting balance) held at `castAddr` is left behind. Because `castAddr` is not derived from a signable pubkey hash — it is simply the raw EVM address bytes cast to an `AccAddress` — no future Cosmos-signed transaction can ever produce that address as a valid `signer` once the corresponding EVM address has been associated elsewhere, and no EVM operation touches that Cosmos account either. The result is coins that become permanently unclaimable, exactly analogous to the reported Y2K Carousel bug where value tied to old shares is orphaned because only part of the position is carried into the new state.

## Finding Description
`MigrateBalance` in `utils/helpers/associate.go` is the single balance-migration routine used by every address-association code path: [1](#0-0) 

It transfers `SpendableCoins` and the wei remainder from `castAddr` to `seiAddr`, and only removes the `castAddr` account record if `LockedCoins` is zero:

```go
castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
...
if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
    p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
}
```

`SpendableCoins` excludes locked/vesting balances by definition, so any vesting grant sitting at `castAddr` (e.g. created via `MsgCreateVestingAccount` targeting the cast address before the owner associates) is never migrated. This behavior is directly confirmed by the existing unit test: [2](#0-1) 

The test funds `castAddr` with 2 `usei`, locks 1 of it in a `DelayedVestingAccount`, then calls `MigrateBalance`, and asserts that only the 1 spendable `usei` moves to `seiAddr` — the locked 1 `usei` remains at `castAddr` as `LockedCoins`.

This migration is invoked from every reachable association entry point:
- The public `Associate`/`AssociatePubKey` precompile methods: [3](#0-2) 
- The automatic association performed on the *first Cosmos-signed tx* from a not-yet-associated signer: [4](#0-3) 
- The automatic association performed by the EVM ante decorator on the *first EVM tx*: [5](#0-4) 

Once association happens, `castAddr` is orphaned: `GetEVMAddress`/`GetSeiAddress` mappings now route all future EVM-side activity for that private key to the newly associated Sei address, not `castAddr`. On the Cosmos side, `GetSigners()` for any future tx is computed from the pubkey's standard hash, which is a different address than the raw EVM-byte `castAddr` — so no signature can ever be produced with `castAddr` as the tx signer via normal ante signature verification. There is no other pathway (module-authorized sweep, governance action, or user-controlled tx) in the reachable codebase that later drains `castAddr`'s locked balance.

## Impact Explanation
Any vesting/locked balance held at a user's EVM-cast Cosmos address at the moment they associate their Sei/EVM address pair becomes permanently frozen — unreachable by the rightful owner through either the Cosmos or EVM interface. This is a direct "permanent freezing of funds" outcome, reachable by an ordinary, unprivileged account: any user who (deliberately or inadvertently) has a vesting grant landed on their pre-association cast address, then performs the very common action of sending a first Cosmos tx or EVM tx (which auto-triggers association), permanently loses access to the locked remainder. It requires no validator collusion, no governance action, and no p2p/consensus interaction — solely ordinary transaction/precompile calls that any public RPC client can issue.

## Likelihood Explanation
Address association is a routine, automatic action for every Sei account the first time it interacts via Cosmos or EVM transaction, and vesting accounts targeting arbitrary addresses (including a not-yet-associated EVM-cast address) are permitted by the standard `x/auth/vesting` message handlers. The precondition — locked coins existing at `castAddr` prior to association — is realistic (e.g. team/investor vesting grants, airdrop vesting programs, or a user pre-funding their own cast address with a vesting schedule before ever associating). Given the ubiquity of the association flow (it fires implicitly on virtually every account's first transaction), the likelihood of hitting this path is not merely theoretical.

## Recommendation
`MigrateBalance` (and its precompile/ante callers) should also migrate `LockedCoins`/vesting positions from `castAddr` to the associated `seiAddr` — e.g. by re-basing the vesting account onto the new address (analogous to how `AssociateAddresses` already reuses a plain `BaseAccount` when it has no pubkey) rather than silently leaving locked funds at an address that becomes permanently unsignable and unreachable. At minimum, association should be blocked/warned when `LockedCoins(ctx, castAddr)` is non-zero until a migration path for locked balances exists.

## Proof of Concept
1. Attacker or the account owner creates a standard vesting grant (`MsgCreateVestingAccount`) with `ToAddress` set to the raw byte-cast Cosmos address of a target EVM public key (`sdk.AccAddress(evmAddr[:])`), before that key has ever associated a Sei/EVM address pair.
2. The EVM key owner later sends any ordinary Cosmos tx (triggering `UpdateSigners` in `app/ante/cosmos_checktx.go`) or any EVM tx (triggering `EVMAddressDecorator.AnteHandle` in `x/evm/ante/preprocess.go`). This is the standard, expected first-use flow and requires no special permission.
3. `AssociationHelper.MigrateBalance` runs, moving only the spendable balance; the vesting-locked coins remain at `castAddr`.
4. `castAddr` can never again be produced as a valid tx `signer` (its bytes don't match any pubkey-derived address), and the EVM address mapping now points elsewhere, so the locked coins are permanently unreachable — reproducible directly via the existing test `TestMigrateBalance` in `x/evm/ante/preprocess_test.go:423-441`, which shows the 1 `usei` locked balance persisting at `castAddr` after migration with no further code path to release it to its rightful owner.

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

func TestMigrateBalance(t *testing.T) {

	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err

func UpdateSigners(ctx sdk.Context, tx sdk.Tx, accountKeeper authkeeper.AccountKeeper, evmKeeper *evmkeeper.Keeper) (sdk.Events, error) {
	signers := tx.(authsigning.SigVerifiableTx).GetSigners()
	var events sdk.Events
	for _, signer := range signers {
		acc := accountKeeper.GetAccount(ctx, signer)
		if err := acc.SetSequence(acc.GetSequence() + 1); err != nil {
			panic(err)
		}

		accountKeeper.SetAccount(ctx, acc)
		if evmAddr, associated := evmKeeper.GetEVMAddress(ctx, signer); associated {
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey, likely due to the fact that it isn't on secp256k1 curve", "pub-key", acc.GetPubKey(), "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(evmKeeper, evmKeeper.BankKeeper(), accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return nil, err
		}
	}
	return events, nil
}

//nolint:revive
func (p *EVMAddressDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	sigTx, ok := tx.(authsigning.SigVerifiableTx)
	if !ok {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrTxDecode, "invalid tx type")
	}
	signers := sigTx.GetSigners()
	for _, signer := range signers {
		if evmAddr, associated := p.evmKeeper.GetEVMAddress(ctx, signer); associated {
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		acc := p.accountKeeper.GetAccount(ctx, signer)
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey for account, likely due to the fact that it isn't on secp256k1 curve", "account", acc.GetPubKey(), "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		p.evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return ctx, err
		}
	}
	return next(ctx, tx, simulate)
}
