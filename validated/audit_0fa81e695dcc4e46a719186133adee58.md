### Title
Governance-settable `kip71.gastarget` accepts zero, causing division-by-zero panic in `NextMagmaBlockBaseFee` (KIP-71 base fee calculation) - ([File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base fee calculation `NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking for zero. The governance parameter `Kip71GasTarget` is registered with a `noopFormatChecker`, which — unlike numerous sibling parameters (`RewardRatio`, `RewardKip82Ratio`, `IstanbulPolicy`) — performs no value-range validation, meaning a value of `uint64(0)` passes both `NewVoteData()`'s format check and `checkConsistency()`'s header verification. If `GasTarget` is ratified to `0` via governance, every subsequent block's base-fee computation divides by zero and panics.

### Finding Description
`NextMagmaBlockBaseFee` in [1](#0-0)  computes the next block's base fee. When `parentGasUsed != gasTarget`, it performs:
```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
```
in both the increase branch [2](#0-1)  and the decrease branch [3](#0-2) . Unlike `BaseFeeDenominator`, which has an explicit `if kc.BaseFeeDenominator == 0 { ... default 64 }` safeguard [4](#0-3) , there is **no equivalent safeguard for `GasTarget`**. `big.Int.Div` with a zero divisor panics.

The `Kip71GasTarget` governance parameter is defined with `Canonicalizer: uint64Canonicalizer` and `FormatChecker: noopFormatChecker` (i.e., no value restriction beyond type) [5](#0-4) . Compare this to other parameters in the same table that do enforce nonzero/bounded values, e.g. `Kip71BaseFeeDenominator`'s checker requires `v != 0` [6](#0-5) , while `Kip71GasTarget` has no such check.

Header-level consistency checking in `checkConsistency()` also does not validate `Kip71GasTarget`'s value — it merely falls into the catch-all `return nil` branch alongside many other parameters [7](#0-6) , unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` which have explicit cross-parameter validation [8](#0-7) .

Existing unit tests only cover "good" values like `uint64(15000000)`/`uint64(30000000)` and only reject non-`uint64` typed values (`3000`, `false`, `true`, `"30000"`) for `Kip71GasTarget` [9](#0-8) ; `uint64(0)` is never tested as a bad value, confirming it is accepted by the current format checker.

Once ratified into `header.Governance` via `governance_vote`/`headergov` and epoch ratification, `GasTarget` becomes 0 for all nodes. Since real blocks almost always have `GasUsed > 0`, the `parentGasUsed > gasTarget` (or the reverse) branch executes on the very next block after the parent whose gas used differs from the target, hitting the unguarded division and panicking every node that processes/validates that block — a chain-wide halt (denial of service), and also affects `feehistory.go`'s `NextMagmaBlockBaseFee` call used by public RPC (`kaia_feeHistory`) [10](#0-9) .

### Impact Explanation
This is directly analogous to CVE-2021-29538: a divisor is derived from externally/governance-controllable input with no zero-check, causing a runtime division-by-zero panic. Because `NextMagmaBlockBaseFee` is invoked during core consensus header verification/preparation (`VerifyMagmaHeader`) for every block after Magma, a zero `GasTarget` value would crash every full/validating node that reaches this code path, causing a chain-wide halt — a severe state-divergence/liveness impact. This satisfies the "state divergence between honest nodes" / "acceptance of an invalid transaction or block" (in the inverse sense — total availability loss / consensus failure) criteria for Medium-or-higher severity.

### Likelihood Explanation
Reaching this bug requires a governance vote to set `kip71.gastarget` to `0` to be cast by the block proposer and ratified at an epoch boundary — this requires either the governing node (in `single` governance mode) or council-majority voting (in other modes). This is a governance-parameter class explicitly listed as in-scope. While not reachable by an arbitrary unprivileged transaction sender directly, the report is valid under the "governance parameters" reachable category. No format/range check exists today to prevent this misconfiguration from being introduced (accidentally or maliciously by a compromised/malicious governing node), whereas equivalent parameters (`BaseFeeDenominator`) are explicitly guarded.

### Recommendation
- Add a `FormatChecker` for `Kip71GasTarget` in [5](#0-4)  that rejects `0` (mirroring the `v != 0` check already used for `Kip71BaseFeeDenominator`).
- Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` in [1](#0-0) , analogous to the existing `BaseFeeDenominator == 0` fallback, so that a zero `GasTarget` (e.g. from a pre-existing genesis/chain-config value) cannot cause a panic even if the governance-layer check is bypassed.

### Proof of Concept
1. Governing node (or council majority under multi-sig governance mode) casts `governance_vote("kip71.gastarget", uint64(0))`. This passes `NewVoteData()`'s canonicalizer/format checker since `noopFormatChecker` accepts any `uint64` value including `0` [5](#0-4) .
2. The vote is included in `header.Vote`, passes `VerifyVote`/`checkConsistency` (no specific check for `Kip71GasTarget`) [7](#0-6) , and is ratified at the next epoch boundary into `header.Governance`, updating the global `ParamSet.GasTarget` to `0`.
3. On the next block after ratification with `GasUsed != 0` (virtually every block), header preparation/verification calls `KIP71Config.NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` with `kc.GasTarget == 0`.
4. Since `parentGasUsed > 0 = gasTarget`, execution enters the "increase" branch, computing `gasUsedDelta = parentGasUsed - 0`, then `y := x.Div(x, new(big.Int).SetUint64(0))` — `big.Int.Div` by zero panics [2](#0-1) , crashing the node process for every node processing this block (full nodes, validators, and public RPC servers calling `feehistory.go`'s `processBlock`).

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
