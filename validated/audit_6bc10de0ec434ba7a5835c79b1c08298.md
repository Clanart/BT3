### Title
Static (non-dynamic-gas) precompiles skip the super-linear ABI-decode gas charge, allowing unbounded memory allocation via crafted calldata - (File: precompiles/common/precompiles.go)

### Summary
`precompiles/common/decode_cost.go` documents and mitigates a known issue: go-ethereum's ABI decoder materializes `string` payloads by `string(output[begin:end])`, and because a single string payload can be referenced by many array/tuple slots (aliased offsets), the actual bytes copied during `Unpack` can be **super-linear in `len(input)`, worst case ~`len(input)^2`** [7](#0-6) . This was fixed for `DynamicGasPrecompile` by adding `chargeDecodeGas`, which prices the decode using `DecodeGasCost` *before* calling `Unpack` [2](#0-1) , and is regression-tested by `TestVoteWeightedAliasedOptionsRejectedBeforeUnpack`, which shows aliased-offset calldata can make decode cost blow past the caller's supplied gas [8](#0-7) .

The fix, however, was applied only to the `DynamicGasPrecompile.RunAndCalculateGas` path. The plain `Precompile.Run`/`Prepare` path used by all non-migrated precompiles still calls `method.Inputs.Unpack(argsBz)` with no equivalent pre-charge [9](#0-8) . For these precompiles, gas is charged only via `RequiredGas`, computed and consumed by go-ethereum's `vm.RunPrecompiledContract` before `Run` is invoked. Many of these `RequiredGas` implementations return small fixed constants regardless of calldata content/size (e.g. `pointerview` returns a flat `2000` [6](#0-5) ; `staking` returns 50000–100000 flat per method [4](#0-3) ; `addr`'s Associate methods return a flat `50000` [5](#0-4) ), and others fall back to `DefaultGasCost`, which is only linear in `len(input)` [10](#0-9)  — neither accounts for the super-linear string-copy amplification that `DecodeGasCost` was specifically built to price.

### Finding Description
Any method on a non-migrated (`Precompile`, not `DynamicGasPrecompile`) precompile whose ABI signature contains a `string`/`string[]`/tuple-with-string argument is reachable by an ordinary EVM transaction sender or contract via `evm.Call`/`staticcall`. Because `RequiredGas` for these executors does not call `DecodeGasCost`, an attacker can construct calldata where the head words for many array/tuple slots all point (alias) to the same offset of a single large string payload. `abi.Arguments.Unpack` will re-materialize (`string(...)` copy) that payload once per referencing slot, so total bytes copied/allocated scale with `(number of aliasing slots) × (string length)`, which can be driven to `~len(input)^2` while `len(input)` itself (and hence the flat/linear `RequiredGas` charge) stays small. This mirrors the MongoDB CVE's root cause: cost/size of the operation performed during error-path/argument processing is not bounded by what the caller was charged for, letting unbounded memory be allocated cheaply.

### Impact Explanation
Unpack runs synchronously inside `Precompile.Prepare`, called from EVM execution for every transaction targeting the precompile. If the constructed super-linear allocation is large enough (tens/hundreds of MB or more, feasible within EVM calldata-gas-affordable input sizes, similar to the already-demonstrated PoC against the gov precompile before the dynamic-gas fix), it can spike node memory during block execution across all validators processing the same transaction deterministically, causing OOM-kill / process crash on validators and RPC/full nodes running default configuration — i.e., a validator halt or crash of default-configuration nodes.

### Likelihood Explanation
High/Medium. The vulnerability is reachable by any address able to submit an EVM transaction or make a contract call to an affected precompile — no special privilege is required. The precise severity depends on which of the many non-migrated precompiles expose string/array arguments susceptible to the aliasing trick (this needs enumeration/testing per precompile, which was not exhaustively verified here due to the volume of precompiles); the `gov` precompile's `voteWeighted` method was already proven exploitable via this exact class of calldata before it was hardened, establishing the bug class is concretely realizable in this codebase, not merely theoretical.

### Recommendation
Extend the pre-decode gas charge (`chargeDecodeGas` / `DecodeGasCost`) currently applied only in `DynamicGasPrecompile.RunAndCalculateGas` to the plain `Precompile.Prepare` path as well, so `RequiredGas` (or an added charge before `Unpack`) prices the super-linear string-copy volume for every precompile method whose arguments can contain `string`/`bytes`-in-array/tuple types, not only those already migrated to dynamic gas. Audit each `RequiredGas` implementation across `precompiles/*` (not just `gov`) for ABI methods with string arguments inside dynamic arrays/tuples, and either migrate them to `DynamicGasPrecompile` or otherwise call `DecodeGasCost` before `Unpack`.

### Proof of Concept
Analogous to `precompiles/gov/gov_test.go`'s `TestVoteWeightedAliasedOptionsRejectedBeforeUnpack`/`craftAliasedVoteWeightedArgs`: craft calldata for a static-`Precompile` method whose ABI signature accepts a dynamic array of `string` (or tuple containing `string`), setting many array head-word offsets to alias the same tail string payload of length `s`. Total decode cost scales as `options × s` while `len(input)` (and thus `RequiredGas`) stays proportional only to `options + s`, so a modest-size, gas-cheap transaction forces a disproportionately large allocation during `method.Inputs.Unpack(argsBz)` in `Precompile.Prepare` [9](#0-8) . (Note: I could not exhaustively confirm which specific non-`gov` precompile ABI currently exposes a qualifying string-in-array/tuple method within this session — that requires enumerating each `precompiles/*/abi.json`; the `gov` precompile's own prior vulnerability, now fixed, demonstrates the underlying bug class is real and the fix's scope is limited to `DynamicGasPrecompile` only.)

func (p Precompile) Prepare(evm *vm.EVM, input []byte) (sdk.Context, *abi.Method, []interface{}, error) {
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return sdk.Context{}, nil, nil, errors.New("cannot get context from EVM")
	}
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}
	method, err := p.MethodById(methodID)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	argsBz := input[4:]
	args, err := method.Inputs.Unpack(argsBz)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	return ctxer.Ctx(), method, args, nil
}

func DefaultGasCost(input []byte, isTransaction bool) uint64 {
	if isTransaction {
		return storetypes.KVGasConfig().WriteCostFlat + (storetypes.KVGasConfig().WriteCostPerByte * uint64(len(input)))
	}

	return storetypes.KVGasConfig().ReadCostFlat + (storetypes.KVGasConfig().ReadCostPerByte * uint64(len(input)))
}
