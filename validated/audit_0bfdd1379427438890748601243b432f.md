### Title
Malformed PedPoP share with a copied encryption key leaks the ECDH key and decrypts another participant’s secret share - ([File: crypto/dkg/pedpop/src/lib.rs](crypto/dkg/pedpop/src/lib.rs))

### Summary
`KeyMachine::calculate_share` can emit an `EncryptionKeyProof` before proving that the submitted `EncryptedMessage` possessed a valid proof-of-possession. A malicious DKG participant can copy the public per-message encryption key from a victim’s encrypted share, submit it with an invalid PoP and a ciphertext that decrypts to a non-canonical scalar, and cause the recipient to return the ECDH shared point as blame evidence. That point is serialized into the blame message and is sufficient to decrypt the copied victim ciphertext, exposing the victim’s secret-share contribution.

### Finding Description
`EncryptedMessage` contains `key`, `pop`, and `msg`; the comments explicitly describe the attack where Eve copies Alice’s key `X` and induces Bob to reveal `bX`, thereby decrypting Alice’s message to Bob. [1](#0-0) 

`Encryption::decrypt` queues the PoP for batch verification, but immediately computes `ecdh(self.enc_key, msg.key)`, decrypts the message, and constructs an `EncryptionKeyProof` containing that ECDH point. [2](#0-1) 

`calculate_share` then deserializes the decrypted bytes as a scalar. If deserialization fails, it returns `PedPoPError::InvalidShare` with `blame: Some(blame)` before `batch.verify_with_vartime_blame` is reached. [3](#0-2) 

The queued PoP check is therefore bypassed on the malformed-scalar path. Because `EncryptionKeyProof::write` serializes `key` directly, the returned blame message publishes the ECDH point rather than merely proving knowledge of it. [4](#0-3) 

Anyone observing the blame can feed the published ECDH point into the deterministic `cipher` construction, which derives the ChaCha20 key from `context || shared_key` with a fixed IV, and decrypt the original victim ciphertext. [5](#0-4) 

### Impact Explanation
This leaks a DKG secret-share message across the intended sender/recipient boundary. The recipient’s blame proof discloses the ECDH shared secret for a ciphertext created by another party, allowing an observer to recover that party’s encrypted share contribution. The protection intended to prevent this exact co-option attack is ineffective on the malformed-share error path because its Schnorr PoP is only queued for later batch verification, not enforced before blame generation.

### Likelihood Explanation
The attacker needs to participate in, or observe, the authenticated DKG message transport sufficiently to copy another sender’s public `EncryptedMessage.key` and submit their own malformed `EncryptedMessage` to its intended recipient. They do not need the victim’s encryption private key or a valid PoP. A ciphertext that decrypts to a non-canonical field representation is enough to trigger the early error path.

### Recommendation
Authenticate `msg.pop` synchronously before deriving or returning `EncryptionKeyProof`. If the PoP is invalid, return a distinct unauthenticated-message error with `blame: None`; never serialize an ECDH point for an unauthenticated `EncryptedMessage`. Equivalently, delay construction and disclosure of the blame proof until the queued decryption PoP has successfully passed batch verification, including on scalar-deserialization failures.

### Proof of Concept
Conceptual reproduction for a `SecretShare` message:

1. Alice sends Bob `m_A = EncryptedMessage { key: X, pop: sig_A, msg: C_A }`.
2. Eve observes `X` and constructs:
   ```text
   m_E = EncryptedMessage {
     key: X,
     pop: arbitrary_invalid_schnorr_signature,
     msg: bytes chosen so decrypt(C_E) is non-canonical as C::F
   }
   ```
3. Bob calls `calculate_share` with `m_E` attributed to Eve.
4. `Encryption::decrypt` queues Eve’s invalid PoP, computes `bX`, and returns an `EncryptionKeyProof` containing `bX`.
5. `C::F::from_repr(decrypted_bytes)` fails, so `calculate_share` returns `InvalidShare { blame: Some(proof) }` before batch verification rejects the invalid PoP.
6. The serialized blame exposes `bX`. Eve derives `cipher(context, bX)` and applies it to Alice’s copied `C_A`, recovering Alice’s secret share to Bob.
