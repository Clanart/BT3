### Title
Ed448 torsion-point acceptance enables Schnorr proof forgery - (File: crypto/ed448/src/point.rs)

### Summary
Ed448’s subgroup-membership check is vacuous, allowing public inputs to decode to canonical points containing a small-order component. An attacker can use such a point as a Schnorr public key/proof commitment and grind a Fiat–Shamir nonce until the challenge annihilates the torsion component, producing a signature or proof that verifies despite the point having no discrete logarithm in the prime-order group.

### Finding Description
`Point` declares itself a `PrimeGroup`, meaning decoded values are expected to be members of the prime-order subgroup. [1](#0-0) 

However, `is_torsion_free` computes `P * (q - 1) + P`, where `q` is represented by the scalar field and therefore `q - 1 == -1`; the expression is consequently `-P + P`, which is identity for every point, including points with a torsion component. [2](#0-1) [3](#0-2) 

`Point::from_bytes` decodes the sign and `y`, recovers `x`, and then accepts the point when this always-true check returns success. [4](#0-3) 

The generic `read_G` only rejects failed decoding or an encoding that does not re-encode canonically; it relies on `Point::from_bytes` for subgroup validity. [5](#0-4) 

Schnorr verification checks the linear relation `R + cA - sG == 0` without clearing or independently rejecting a torsion component in `A`. [6](#0-5) [7](#0-6) 

For a malformed key `A = xG + T` with order-4 `T`, choose `R = rG` and `s = r + cx`. Whenever `cT = 0`, which occurs when `c ≡ 0 mod 4`, verification computes `R + cA - sG = cT = 0` and accepts the proof even though `A` is outside the declared prime-order group. [8](#0-7) 

### Impact Explanation
An unauthenticated party can submit malicious Ed448 point bytes through `C::read_G`, together with a Schnorr signature/proof through `SchnorrSignature::read`, and have the result accepted by `verify`. [5](#0-4) [9](#0-8) 

This is a concrete proof/signature forgery against an accepted malformed public key: the attacker proves possession of a discrete logarithm for `xG + T` even though no such scalar exists in the prime-order group. [10](#0-9) 

The same poisoned point shape can enter higher-level public inputs that deserialize group elements and Schnorr proofs, such as `EncryptedMessage::read`, which accepts an attacker-controlled key followed by a Schnorr proof. [11](#0-10) 

### Likelihood Explanation
The malformed encoding is easy to construct: an Ed448 `y = 0` encoding with either sign decodes to one of the order-4 points, and the defective membership check accepts it. [4](#0-3) 

When the challenge is Fiat–Shamir-derived from attacker-controlled nonce bytes, the attacker can retry nonce choices until `c ≡ 0 mod 4`; this is expected to succeed after only a small number of attempts. [7](#0-6) 

### Recommendation
Replace `is_torsion_free` with a real subgroup-membership check for Ed448. Since the scalar field cannot directly represent multiplication by the subgroup order, use an unreduced integer multiplication routine or another cofactor-aware test rather than `P * (q - 1) + P`. [3](#0-2) 

Reject identity and all non-prime-subgroup points in `Point::from_bytes`, then add regression vectors for the `y = 0` encodings and for a Schnorr signature whose challenge annihilates an order-4 component. [4](#0-3)

```rust
// This represents an order-4 point, but is accepted by the defective check.
let mut torsion_encoding = [0u8; 57];
torsion_encoding[56] = 0x80;
let torsion = Ed448::read_G(&mut torsion_encoding.as_slice()).unwrap();

let g = Ed448::generator();
let x = /* attacker-chosen scalar */;
let malformed_key = (g * x) + torsion;

for attempt in 0.. {
    let r = /* fresh attacker-chosen nonce for this attempt */;
    let nonce = g * r;

    // Use the verifier's Fiat-Shamir challenge derivation.
    let challenge = challenge(malformed_key, nonce, message);

    // T has order 4, so challenge * T is identity when challenge mod 4 = 0.
    let bits = challenge.to_le_bits();
    if bits[0].unwrap_u8() == 0 && bits[1].unwrap_u8() == 0 {
        let signature = SchnorrSignature {
            R: nonce,
            s: r + (challenge * x),
        };

        // Passes because:
        // sG = (r + cx)G
        // R + cA = rG + c(xG + T) = (r + cx)G + cT = sG
        assert!(signature.verify(malformed_key, challenge));
        break;
    }
}
```

The PoC’s root cause is that the accepted `malformed_key` is canonical and successfully decoded, despite not belonging to the declared `PrimeGroup`; the signature equation then treats its torsion component as valid whenever the challenge annihilates it. [5](#0-4) [6](#0-5)
