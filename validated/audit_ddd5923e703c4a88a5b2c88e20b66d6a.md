### Title
Missing Vote/Unvote Cooldown in `WombatBribeManager` Enables Flash-Vote Bribe Reward Sniping - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.vote()` and `unvote()` let any vlMGP holder freely reallocate their vote weight between pools with **no time restriction whatsoever** — there is no `lastVoteTime`/`VOTE_DELAY`-style cooldown analogous to the reported `GaugeController` bug. Because `BribeRewardPool` (via `BaseRewardPoolV2`) distributes newly-arrived bribe tokens as an instantaneous, non-streamed bump to `rewardPerTokenStored` based on whoever currently holds balance, a user can flash-vote into a heavily-bribed pool immediately before `castVotes()` is executed and flash-unvote immediately after, capturing a share of bribe rewards that were actually earned by long-term voters' real votes on the underlying Wombat protocol over the preceding period.

### Finding Description
`vote()` mutates `userVotedForPoolInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta))` with zero delay checks: [1](#0-0) 

`unvote()` similarly calls `withdrawFor(msg.sender, currentVote, true)` (immediate claim) with no cooldown: [2](#0-1) 

`castVotes()` converts the internal vlMGP vote tallies into real votes sent to Wombat's voter, claims the bribes that accrued to those real votes, and immediately forwards them to each pool's `BribeRewardPool` via `_forwardRewards`/`queueNewRewards`, using the **current** `totalSupply`/balances in the reward pool at that instant: [3](#0-2) 

`BribeRewardPool.stakeFor`/`withdrawFor` update `totalSupply`/`_balances` and immediately settle rewards via `updateRewards`, then `withdrawFor(..., claim=true)` pays out `earned()` right away: [4](#0-3) 

The reward accounting in `BaseRewardPoolV2._provisionReward` applies the entire incoming bribe amount as an instantaneous, non-time-weighted increment to `rewardPerTokenStored` divided by `totalStaked()` at that moment: [5](#0-4) 

Combining these: since `vote`/`unvote` have no delay (mirroring exactly the missing `VOTE_DELAY` enforcement in the reported `GaugeController.vote()`), a vlMGP holder can:
1. Call `vote()` to shift a large weight into the pool with the biggest pending bribe payout, right before (or in the same block as) a `castVotes()` call.
2. Let `castVotes()` execute, which forwards the bribe into `BribeRewardPool` and instantly raises `rewardPerTokenStored` based on the attacker's now-inflated share of `totalSupply`.
3. Call `unvote()` immediately, claiming the reward via `withdrawFor(..., true)`, then reallocate the same vlMGP elsewhere.

Because there is no cooldown between `vote`/`unvote`, this can be repeated every cast cycle, siphoning bribe yield from users who genuinely held votes for the pool over the period the bribe was earned.

### Impact Explanation
This results in theft/dilution of unclaimed bribe yield belonging to legitimate long-term voters, since reward entitlement is determined solely by instantaneous balance in `BribeRewardPool` at `castVotes()` time rather than by time-weighted contribution to the actual Wombat votes that generated the bribe. It also allows manipulation of which pools receive the internal vlMGP vote allocation right before harvest, directly affecting governance voting/bribe-distribution outcomes — the same impact class described in the source report ("manipulation of gauge weights through rapid successive votes").

### Likelihood Explanation
Any vlMGP holder can perform this with ordinary transactions (`vote`, then wait for/trigger `castVotes`, then `unvote`); `castVotes()` is a public function callable by anyone, and no privileged role or governance action is required. The only precondition is holding some locked vlMGP (unprivileged wallet interaction), and the attack can be repeated every cast cycle.

### Recommendation
Add a cooldown/lock period enforced by `vote()`/`unvote()` (mirroring the `lastVoteTime`/`VOTE_DELAY` pattern recommended in the source report), and/or make bribe reward distribution time-weighted (e.g., snapshot balances at the start of the bribe period rather than at `castVotes()` time) so that only users who held their vote allocation throughout the period during which the bribe was earned can claim a share of it.

### Proof of Concept
1. Alice locks MGP and obtains vlMGP voting power via `getUserVotable`.
2. Alice calls `WombatBribeManager.vote([targetPool], [largeDelta])`, which calls `BribeRewardPool.stakeFor(alice, largeDelta)` on the pool with the largest pending bribe, immediately increasing her share of `totalSupply` in that pool's reward pool: [6](#0-5) 
3. Anyone (or Alice) calls `castVotes()`, which claims accrued bribes and forwards them via `_forwardRewards`, bumping `rewardPerTokenStored` in `targetPool`'s `BribeRewardPool` based on the current (Alice-inflated) `totalSupply`: [7](#0-6) 
4. Alice immediately calls `WombatBribeManager.unvote(targetPool)`, which calls `withdrawFor(alice, currentVote, true)`, instantly paying out `earned()` computed from the just-updated `rewardPerTokenStored`: [8](#0-7) 
5. Alice reallocates her vlMGP to repeat the same pattern on the next pool/cast cycle, having captured bribe yield she did not genuinely help earn, at the expense of voters who held real allocation throughout the period.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
