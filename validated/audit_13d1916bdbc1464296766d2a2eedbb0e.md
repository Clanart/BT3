### Title
Integer divide-by-zero panic in KIP-71 base fee calculation when `governance.kip71.gastarget` is set to 0 - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking for zero, unlike the sibling `BaseFeeDenominator` parameter which explicitly guards against zero.

### Finding Description
`NextMagmaBlockBaseFee` computes the base-fee delta using `gasTarget` as a divisor in both the "gas used above target" and "gas used below target" branches: [1](#0-0) [2](#0-1) 

`gasTarget` comes directly from `kc.GasTarget` with no zero-guard, in contrast to `BaseFeeDenominator`, which is explicitly checked and defaulted to `64` if zero: [3](#0-2) 

The governance parameter registry (`kaiax/gov/param.go`) enforces `v != 0` for `Kip71BaseFeeDenominator`, but the `Kip71GasTarget` parameter uses `noopFormatChecker`, allowing it to be canonicalized and accepted as `0`: [4](#0-3) 

If `GasTarget` is set to `0` (via a governance vote/parameter update) and `parentGasUsed != 0` (essentially always true for any block with transactions), the code takes the "gas used above target" branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`. Go's `math/big.Int.Div`/`Quo` panics on division by zero, causing an unrecoverable runtime panic. This is analogous to the CVE-2021-34335 Exiv2 bug class: an unguarded integer division that panics/crashes when the divisor becomes zero, but here it is `NextMagmaBlockBaseFee`, which is called on **every node** during block header verification (`VerifyMagmaHeader` in `blockchain/block_validator.go`) and during block/fee-history processing (`node/cn/gasprice/feehistory.go`, `work/worker.go`).

### Impact Explanation
Because `NextMagmaBlockBaseFee` is invoked by every full node validating each new block's `BaseFee` field (via `VerifyMagmaHeader`) as well as by the block proposer/worker when assembling new blocks and by the RPC fee-history oracle, a `GasTarget = 0` governance parameter causes every node in the network to panic while processing the very next block with nonzero gas usage. This is a chain-halting denial of service affecting the entire network, not just a single node, satisfying the "state divergence/DoS on all honest nodes" bar for Medium/High severity.

### Likelihood Explanation
Exploitation requires the `governance.kip71.gastarget` parameter to be set to `0` through the governance voting mechanism. This is gated by governance access, not a single unprivileged transaction, but the parameter validation logic (`FormatChecker`) that is supposed to reject unsafe values fails to do so for this specific field even though the sibling parameter (`BaseFeeDenominator`) is correctly guarded — indicating this is an oversight/inconsistency rather than an intentionally restricted value. Once accepted, the very next block with nonzero gas usage deterministically triggers the panic on all nodes, so likelihood of triggering (once the value is set) is effectively 100%.

### Recommendation
Add a zero-check for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator` fallback, e.g., default to a safe nonzero value when `kc.GasTarget == 0`. Additionally, update the `Kip71GasTarget` `FormatChecker` in `kaiax/gov/param.go` to reject `0` (consistent with `Kip71BaseFeeDenominator`), preventing the invalid value from ever being accepted by governance.

### Proof of Concept
1. Governance sets `governance.kip71.gastarget = 0` (accepted due to `noopFormatChecker` in `kaiax/gov/param.go:324-333`).
2. Any subsequent block is produced/received with `GasUsed > 0` (virtually guaranteed).
3. `NextMagmaBlockBaseFee` is called with `parentGasUsed > gasTarget(0)`, entering the branch at `params/kip71_config.go:92-109`.
4. `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` executes division by zero, panicking the calling goroutine.
5. Since this function is called from `VerifyMagmaHeader` during header validation on every node, all nodes processing that block panic/crash, halting the chain.
