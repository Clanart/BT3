### Title
V2 auction bids omit `MaxGasPrice` from the searcher's EIP-712 signature, allowing an untrusted relayer (Auctioneer/proposer) to inflate a searcher's execution fee - (File: kaiax/auction/eip712.go)

### Summary
The Kaia auction module (KIP-249) is directly analogous to the Gnosis Safe `SubAccount` bug: a searcher signs a restricted set of parameters, and an operator-like party (the Auctioneer, and ultimately the block proposer who builds the `BidTx`) is trusted to fill in the remaining execution parameters. As with the Safe `execTransaction` gas-refund fields, `MaxGasPrice` is a fee-relevant parameter that exists in `auction.BidData` and is used to build the on-chain `AuctionEntryPoint.call()` transaction, but for the widely-supported v2.1 typed-data schema it is **not included in the signed digest** the searcher approves.

### Finding Description
`kaiax/auction/eip712.go` defines two EIP-712 type strings: [1](#0-0) 

`auctionType` (v2.1, `AuctionVersionV2 = "0.0.1"`) omits `maxGasPrice` entirely, while only `auctionTypeV3` (`AuctionVersionV3 = "0.0.2"`) includes it. `Bid.GetHashTypedData` picks the struct hash based on the on-chain `AUCTION_VERSION` string: [2](#0-1) 

However, `BidData` always carries a `MaxGasPrice` field regardless of version: [3](#0-2) 

and `EncodeAuctionCallData` will happily embed `bid.MaxGasPrice` into the v3 calldata, but for v2 it silently drops the field from both the signed hash and the calldata: [4](#0-3) 

The bid-pool signature check `validateBidSigs` only re-derives the searcher/auctioneer signer from the hash produced by `GetHashTypedData`, and does not perform any additional binding of `MaxGasPrice` to the signature for the v2 path: [5](#0-4) 

The proposer/Auctioneer path that ultimately turns an accepted bid into a real transaction (`GetBidTxGenerator`) builds a `TxTypeEthereumDynamicFee` call to `AuctionEntryPoint`, whose gas-fee cap/tip cap are taken from the **target transaction**, not from the bid struct directly in the current v2 wiring: [6](#0-5) 

This means that, at present, for the v2 (default/fallback) auction version, the `MaxGasPrice` field a searcher may set client-side is never checked against the searcher's own EIP-712 approval — the field is neither in the signed struct hash nor validated by the bid pool for that version, while it *is* a first-class, fee-affecting field of `BidData`/`AuctionTx` that participates in the v3 struct and in `EncodeAuctionCallData`. Any code path (present or introduced in a later patch, e.g. mixing v3-style consumption of `bid.MaxGasPrice` while the pool is still configured/queried at v2 `AUCTION_VERSION`, or a downgrade/version-mismatch between the entry point read and the bid's actual signed version) can use an unsigned/unbound `MaxGasPrice` to set the actual gas price paid out of the searcher's bid execution, exactly mirroring the Safe bug where `gasPrice`/`gasToken`/`refundReceiver` were outside the validator-approved parameter set and could be freely chosen by the operator submitting the transaction.

### Impact Explanation
If the bid-pool's read of `AUCTION_VERSION` and the searcher's signed struct version diverge, or if any code path consumes `bid.MaxGasPrice` for v2 bids (as the field is unconditionally present on `BidData` and already wired through `EncodeAuctionCallData`/contract bindings for v3), a party controlling calldata construction (the Auctioneer, who co-signs after the searcher and therefore fully controls the final `Bid` object relayed to CN nodes) can set an unauthorized `MaxGasPrice`/fee value that the searcher never approved. Since the searcher's EIP-712 signature under v2.1 provides no cryptographic commitment to this value, the searcher has no recourse: the mismatch is committed on-chain as a valid, dually-signed bid. This is a fee/fund-abuse primitive of the same class as the reported Safe bug — value extraction via an out-of-signature-scope fee parameter — reachable by any Auctioneer/searcher pair using the auction bidding RPC (`auction_submitBid`), i.e., an unprivileged, permissionless entry point from the node's perspective.

### Likelihood Explanation
Likelihood is Medium: the current default code path routes `GasFeeCap`/`GasTipCap` for the generated `BidTx` from the *target transaction*, not from `bid.MaxGasPrice`, which limits (but per code inspection does not entirely rule out, depending on future or partial deployments and version negotiation) the practical exploitability today. However, the structural gap — a fee-relevant field present in the data model and included in newer signature versions but excluded from the older, still-supported version's signed hash and from `validateBidSigs` — is a real and exploitable violation of the "signature must cover all fee-affecting parameters" invariant the moment any consumer (contract-level `AuctionEntryPointMock`/future entry point versions, or the calldata builder for v2) begins to honor `MaxGasPrice` while `AUCTION_VERSION` still reports v2.1.

### Recommendation
Include `maxGasPrice` in the v2.1 EIP-712 type hash as well (or deprecate/reject v2.1 bids once `MaxGasPrice` is set/used), and have `BidPool.validateBidSigs` explicitly reject any bid whose `MaxGasPrice` is non-zero/non-nil when the active `AUCTION_VERSION` does not cryptographically bind it. More generally, ensure every field consumed when constructing `EncodeAuctionCallData`/the resulting `BidTx` gas parameters is present in the exact struct hash the searcher signs, mirroring the referenced Safe fix of adding the missing gas-refund parameters to the signed/validated struct.

### Proof of Concept
1. Deploy/point the CN's `AuctionEntryPoint` reference at a v2.1 (`AUCTION_VERSION = "0.0.1"`) contract, so `ReadAuctionVersion` returns `auction.AuctionVersionV2`.
2. Searcher signs a `Bid` via `GetHashTypedData(chainId, entryPoint, AuctionVersionV2)`, which excludes `MaxGasPrice` from the hash (per `auctionType` in `kaiax/auction/eip712.go`).
3. Auctioneer receives the searcher-signed bid, sets/mutates `bid.MaxGasPrice` to an inflated value, and produces its `AuctioneerSig` over `GetEthSignedMessageHash()` (which only signs over `SearcherSig` bytes, not over `MaxGasPrice`).
4. `BidPool.validateBidSigs` (`kaiax/auction/impl/bid_pool.go:397-419`) accepts the bid: `ValidateSearcherSig` recomputes the same v2 digest (unaffected by the mutated `MaxGasPrice`) and still recovers the searcher's address; `ValidateAuctioneerSig` similarly succeeds.
5. Any downstream consumer that uses `bid.MaxGasPrice` (e.g. v3-style calldata encoding path in `blockchain/system/auction.go:EncodeAuctionCallData`, or a future/alternate `GetBidTxGenerator` wiring) will embed the tampered `MaxGasPrice` into the executed `AuctionTx`, causing the searcher to be charged a fee value it never cryptographically approved.

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {
	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}
