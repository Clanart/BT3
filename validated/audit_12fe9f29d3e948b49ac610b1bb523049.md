### Title
CW1155 pointer's `safeTransferFrom`/`safeBatchTransferFrom` perform the CosmWasm token-transfer state mutation *before* calling the untrusted recipient's `onERC1155Received`/`onERC1155BatchReceived` hook, with no reentrancy guard - ([File: contracts/src/CW1155ERC1155Pointer.sol])

### Summary
`CW1155ERC1155Pointer.safeTransferFrom()` and `safeBatchTransferFrom()` first mutate the underlying CW1155 contract's balances via `_execute()` (a `delegatecall` into the wasmd precompile that runs the CW1155 `send`/`send_batch` message), and only afterward invoke `IERC1155Receiver(to).onERC1155Received(...)`/`onERC1155BatchReceived(...)` on an arbitrary, caller-supplied `to` contract. Neither function has a reentrancy guard, so the recipient's hook can reenter the pointer (or any other contract in the same call stack, e.g. a marketplace/AMM that itself called `safeTransferFrom` to receive payment) while the transfer's underlying CW1155 state is already finalized but the outer call has not yet returned.

### Finding Description
`safeTransferFrom` in [1](#0-0)  performs the checks (`balanceOf`, `isApprovedForAll`), then calls `_execute(bytes(req))`, which `delegatecall`s the wasmd precompile to run the CW1155 `send` message and permanently update the CW1155 module's ledger, and only then calls `IERC1155Receiver(to).onERC1155Received(...)` on `to` if `to.code.length > 0`. `safeBatchTransferFrom` follows the identical pattern at [2](#0-1) .

The state-mutating `_execute()` call is analogous to `_withdrawManagerBalance()` in the original report: it is an "interaction" performed before the function has returned, and the subsequent call to `IERC1155Receiver` is an interaction with attacker-controlled code (any contract deployed by the caller). There is no `nonReentrant` modifier anywhere in this contract, unlike the pattern the codebase itself uses elsewhere for similar untrusted-callback flows (e.g. `FixtureReentrancyGuard.nonReentrant` in [3](#0-2) , and `DeterministicV3Pool.swap` which explicitly guards a callback with `nonReentrant` in [4](#0-3) ).

Because `balanceOf`/`isApprovedForAll` on this pointer are not cached locally but query the live CW1155 state via `WasmdPrecompile.query` ( [5](#0-4) , [6](#0-5) ), a reentrant call into `safeTransferFrom`/`safeBatchTransferFrom`/`burn`/`setApprovalForAll` during the receiver callback sees the fully-updated post-transfer CW1155 state. This lets an attacker's receiver contract reenter the pointer (or any external protocol contract that itself called into this pointer, e.g. a marketplace/AMM/lending protocol expecting the ERC1155 `safeTransferFrom` call to be atomic) mid-transaction, before the outer call unwinds and before the calling protocol's own post-transfer bookkeeping executes.

### Impact Explanation
Reachable by any unprivileged EVM transaction sender who deploys a malicious ERC1155-receiver contract and calls `safeTransferFrom`/`safeBatchTransferFrom` on a `CW1155ERC1155Pointer`. Any downstream protocol (marketplace, AMM, lending/vault contract) that integrates with CW1155 pointer tokens and relies on `safeTransferFrom` completing atomically before further reentrant calls are possible is exposed to classic ERC721/1155-style reentrancy: the receiver hook fires after the CW1155 ledger mutation but mid-call, letting the attacker perform additional transfers, mint/burn operations, or manipulate the calling protocol's other state (double-spend of allowances, front-running of pending listings, drain of escrowed funds) before the original call context resolves. This can result in unauthorized transfer of tokens routed through the pointer/wasm bridge and fund loss in any integrating contract that is not itself reentrancy-hardened against ERC1155 receiver callbacks.

### Likelihood Explanation
High reachability: no privileged role is required — a normal contract-deploying address can trigger this simply by being (or controlling) the `to` recipient of a CW1155 pointer transfer. The vulnerable code path is hit on every `safeTransferFrom`/`safeBatchTransferFrom` call where `to` is a contract, which is the standard usage pattern for pointer tokens interacting with DeFi protocols on Sei EVM.

### Recommendation
Add a `nonReentrant` guard (e.g. OpenZeppelin's `ReentrancyGuard`) to `safeTransferFrom`, `safeBatchTransferFrom`, and any other state-mutating function in `CW1155ERC1155Pointer.sol` that performs `_execute()` (CW1155 ledger mutation) followed by an external call into caller-controlled code (`onERC1155Received`/`onERC1155BatchReceived`). Alternatively/additionally, follow strict checks-effects-interactions ordering and ensure the wasmd `_execute` mutation plus the receiver-hook call are treated as a single non-reentrant unit, consistent with the `nonReentrant`-guarded callback pattern already used elsewhere in this repo's own fixtures.

### Proof of Concept
1. Deploy a malicious contract `Attacker` implementing `IERC1155Receiver.onERC1155Received` that, upon being called, reenters the same `CW1155ERC1155Pointer` (or an integrating marketplace/AMM contract that itself called `safeTransferFrom`) to perform an additional transfer, mint, burn, or state-dependent action while the outer transfer's CW1155 ledger state has already been mutated by `_execute()` in [7](#0-6) .
2. Call `pointer.safeTransferFrom(attackerControlledFrom, address(Attacker), id, amount, data)`.
3. Inside `onERC1155Received`, before the outer `safeTransferFrom` call returns to its own caller, `Attacker` reenters and exploits the fact that `balanceOf`/`isApprovedForAll` already reflect the completed transfer ( [8](#0-7) ), enabling double-processing in any integrating contract that assumed atomicity.

    function safeTransferFrom(
        address from,
        address to,
        uint256 id,
        uint256 amount,
        bytes memory data
    ) public override {
        require(to != address(0), "ERC1155: transfer to the zero address");
        require(balanceOf(from, id) >= amount, "ERC1155: insufficient balance for transfer");
        require(
            msg.sender == from || isApprovedForAll(from, msg.sender),
            "ERC1155: caller is not approved to transfer"
        );
    
        string memory f = _formatPayload("from", _doubleQuotes(AddrPrecompile.getSeiAddr(from)));
        string memory t = _formatPayload("to", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(id)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));

        string memory req = _curlyBrace(
            _formatPayload("send", _curlyBrace(_join(f, ",", _join(t, ",", _join(tId, ",", amt)))))
        );
        _execute(bytes(req));
        if (to.code.length > 0) {
            require(
                IERC1155Receiver(to).onERC1155Received(
                    msg.sender,
                    from,
                    id,
                    amount,
                    data
                ) == IERC1155Receiver.onERC1155Received.selector,
                "unsafe transfer"
            );
        }
    }

    function safeBatchTransferFrom(
        address from,
        address to,
        uint256[] memory ids,
        uint256[] memory amounts,
        bytes memory data
    ) public override {
        require(to != address(0), "ERC1155: transfer to the zero address");
        require(
            msg.sender == from || isApprovedForAll(from, msg.sender),
            "ERC1155: caller is not approved to transfer"
        );
        require(ids.length == amounts.length, "ERC1155: ids and amounts length mismatch");
        address[] memory batchFrom = new address[](ids.length);
        for (uint256 i = 0; i < ids.length; i++) {
            batchFrom[i] = from;
        }
        uint256[] memory balances = balanceOfBatch(batchFrom, ids);
        for (uint256 i = 0; i < balances.length; i++) {
            require(balances[i] >= amounts[i], "ERC1155: insufficient balance for transfer");
        }

        string memory payload = string.concat("{\"send_batch\":{\"from\":\"", AddrPrecompile.getSeiAddr(from));
        payload = string.concat(payload, "\",\"to\":\"");
        payload = string.concat(payload, AddrPrecompile.getSeiAddr(to));
        payload = string.concat(payload, "\",\"batch\":[");
        for (uint256 i = 0; i < ids.length; i++) {
            string memory batch = string.concat("{\"token_id\":\"", Strings.toString(ids[i]));
            batch = string.concat(batch, "\",\"amount\":\"");
            batch = string.concat(batch, Strings.toString(amounts[i]));
            if (i < ids.length - 1) {
                batch = string.concat(batch, "\"},");
            } else {
                batch = string.concat(batch, "\"}");
            }
            payload = string.concat(payload, batch);
        }
        payload = string.concat(payload, "]}}");
        _execute(bytes(payload));
        if (to.code.length > 0) {
            require(
                IERC1155Receiver(to).onERC1155BatchReceived(
                    msg.sender,
                    from,
                    ids,
                    amounts,
                    data
                ) == IERC1155Receiver.onERC1155BatchReceived.selector,

            );
        }
    }

    function isApprovedForAll(address owner_, address operator) public view override returns (bool) {
        string memory own = _formatPayload("owner", _doubleQuotes(AddrPrecompile.getSeiAddr(owner_)));
        string memory op = _formatPayload("operator", _doubleQuotes(AddrPrecompile.getSeiAddr(operator)));
        string memory req = _curlyBrace(_formatPayload("is_approved_for_all", _curlyBrace(_join(own, ",", op))));
        bytes32 response = keccak256(WasmdPrecompile.query(Cw1155Address, bytes(req)));
        bytes32 approvedMsg = keccak256("{\"approved\":true}");
        bytes32 unapprovedMsg = keccak256("{\"approved\":false}");
        if (response == approvedMsg) {
            return true;
        } else if (response == unapprovedMsg) {
            return false;
        }
        revert NotImplementedOnCosmwasmContract("is_approved_for_all");
    }
