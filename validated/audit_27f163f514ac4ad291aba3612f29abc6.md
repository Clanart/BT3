### Title
Unbounded recursion in PHP `Message::mergeFromJsonArray` for `Struct`/`Value`/`ListValue`/`Any` JSON parsing — no recursion-depth limit enforced (CWE-674 analog) - ([File: php/src/Google/Protobuf/Internal/Message.php])

### Summary
The Parse Server advisory's failed invariant is: a documented complexity/depth limit (`requestComplexity.queryDepth`) is enforced on one processing path (REST) but is silently skipped on another reachable path (LiveQuery subscriptions), letting an ordinary client trigger unbounded recursive evaluation from attacker-controlled nested input. The Protobuf analog with the same shape — a recursion-depth invariant that is enforced everywhere else in the codebase but is missing on one specific public-parsing code path — exists in the PHP pure-implementation of ProtoJSON merging for the well-known types `Struct`, `Value`, `ListValue`, and `Any`, in `Message::mergeFromJsonArray()`.

### Finding Description
Every other Protobuf language implementation I inspected treats `Struct`/`Value`/`ListValue`/`Any` JSON nesting as a recursion-depth-tracked operation, specifically because these well-known types are mutually recursive and their nesting depth is entirely attacker-controlled from the JSON text:

- C++ JSON lexer explicitly pushes/pops a depth counter and rejects overly nested arrays/objects: [1](#0-0) 
- Java `JsonFormat` tracks `currentDepth` against `recursionLimit` specifically inside `mergeStructConcrete`, `mergeListValueConcrete`, and `mergeAny`: [2](#0-1) [3](#0-2) 
- Python `json_format._Parser.ConvertMessage` increments/decrements `recursion_depth` and raises `ParseError` once `max_recursion_depth` is exceeded, and this is explicitly tested for `Struct` nesting: [4](#0-3) [5](#0-4) 
- C# `JsonParser.Merge` tracks `tokenizer.RecursionDepth` against `settings.RecursionLimit`, and there is an explicit regression test/comment noting that a previous "Any-in-Any" bypass of this exact limit was fixed to match the Java (`mergeAnyMessage`) and Python (`_ConvertAnyMessage`) fixes: [6](#0-5) [7](#0-6) 

In contrast, the PHP pure-implementation path `Message::mergeFromJsonArray()` (reached from the public `mergeFromJsonString`/`Google\Protobuf\Any::unpack`+decode entry points) recurses into nested `Value`/`Struct`/`ListValue`/`Any` payloads with **no depth counter, no limit parameter, and no recursion check at all**: [8](#0-7) 

Each branch (`Any` → `mergeFromJsonArray`, `Struct` fields → `Value::mergeFromJsonArray`, `Value` → nested `Struct`/`ListValue` → `Value::mergeFromJsonArray` again) calls back into `mergeFromJsonArray` unconditionally, purely driven by how deeply the attacker nests the input JSON array/object. There is no equivalent of Java's `currentDepth`/`recursionLimit`, Python's `recursion_depth`/`max_recursion_depth`, C#'s `RecursionDepth`/`RecursionLimit`, or the C++ lexer's `Push()`/`Pop()` depth guard anywhere in this function.

### Impact Explanation
This mirrors the CWE-674 "uncontrolled recursion" pattern in the advisory: a per-message recursion-depth invariant that is intentionally and consistently enforced in equivalent code across the project (C++, Java, Python, C#) is absent on this one reachable, attacker-facing PHP parsing path. A client that can feed ProtoJSON into `Struct`/`Value`/`ListValue`/`Any` decoding (a standard, supported public parse API for these well-known types) can supply deeply nested JSON arrays/objects and drive unbounded PHP call-stack recursion, leading to a PHP fatal error / process crash (availability impact), consistent with the "excessive recursion causing service disruption" impact described in the source advisory. There is no confidentiality or integrity impact, matching the advisory's `C:N/I:N/A:H` CVSS vector.

### Likelihood Explanation
Likelihood is high for any application that uses PHP's pure-runtime protobuf library (as opposed to the compiled C extension) to decode ProtoJSON payloads for `Struct`, `Value`, `ListValue`, or `Any`, and where the attacker controls the JSON body size/nesting (e.g., web APIs accepting `google.protobuf.Struct`/`Any` fields, common in gRPC-gateway / REST-JSON transcoding). No authentication bypass or special privilege is required — an ordinary client submitting a bounded, small ProtoJSON payload with a few thousand nested `[`/`{` characters is enough, exactly analogous to the LiveQuery subscription payload in the source advisory.

Note: I could not verify within available searches whether the PHP C extension (`php/ext/google/protobuf/message.c`) implements the equivalent JSON-array merge path with its own (possibly present) depth check; if the C extension is used in production instead of the pure-PHP fallback, the impact may be limited to installs using the pure-PHP implementation. This should be confirmed before treating this as conclusively exploitable in all PHP deployments.

### Recommendation
Add an explicit recursion-depth counter/parameter to `Message::mergeFromJsonArray()` (and thread it through the `Any`/`Struct`/`Value`/`ListValue` recursive calls), mirroring the `currentDepth`/`recursionLimit` pattern already used in the Java, Python, and C# JSON formatters, and reject the parse with a catchable `GPBDecodeException` once a configurable default limit (e.g., 100, consistent with other language defaults) is exceeded. Add a regression test analogous to `testRecursionLimitConsistency`/`testStructRecursionDepthEnforcement` (Java/Python) to confirm PHP's `Struct`/`Value`/`ListValue`/`Any` JSON decoding rejects deeply nested input identically to the other language bindings. Also audit the PHP C extension (`message.c`) to confirm parity.

### Proof of Concept
Conceptual reproduction against the pure-PHP path (not executed; provided as a minimal illustrative case consistent with the code read above):
```php
// Build a deeply nested JSON array representing google.protobuf.Value
// nesting, e.g. {"a":{"a":{"a": ... 100000 levels ... }}}
$depth = 100000;
$json = str_repeat('{"a":', $depth) . '1' . str_repeat('}', $depth);

$struct = new \Google\Protobuf\Struct();
$struct->mergeFromJsonString($json); // -> recurses through mergeFromJsonArray
                                      // with no depth check, unlike Java/Python/C#/C++,
                                      // causing uncontrolled recursion / crash.
```
This contrasts directly with the existing tests in other languages (e.g. `testStructRecursionDepthEnforcement` in Python, `testRecursionLimitStruct`/`testRecursionLimitListValue` in Java, `MaliciousRecursionOfObjectsInValue` in C#) which prove the same nested-`Struct`/`Value` input is rejected with a catchable error once a depth limit is set — a protection PHP's `mergeFromJsonArray` does not implement.
