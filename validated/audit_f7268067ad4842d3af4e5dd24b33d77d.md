### Title
Unconfirmed, attacker-triggerable branch checkout via `x-github-client://openRepo` deep link - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop registers a custom protocol handler (`x-github-client`, `github-mac`, `github-windows`) that is parsed by `parseAppURL` and dispatched by `Dispatcher.dispatchURLAction`. For the `open-repository-from-url` action, if the target repository is already added to Desktop (matched purely by comparing the remote URL string), Desktop will silently fetch and checkout an attacker-specified branch name with no user confirmation dialog — unlike the "add new repository" path, which does show a popup.

### Finding Description
`parseAppURL` builds an `IOpenRepositoryFromURLAction` from any URL of the form `x-github-client://openRepo/<remote-url>?branch=<name>` [1](#0-0) . This is reachable from `handleAppURL` in the main process, which is invoked whenever the OS activates the registered protocol — i.e., from any link (in a browser, email, chat client, etc.), not only from github.com [2](#0-1) .

`Dispatcher.dispatchURLAction` routes this to `openRepositoryFromUrl`, which — when a `branch` is present — calls `openBranchNameFromUrl` [3](#0-2) . That function locates a match via `openOrCloneRepository`, which looks for an **already-added** repository whose origin/upstream URL string-matches the URL in the link (`doesRepositoryMatchUrl`) [4](#0-3) [5](#0-4) . If a match exists, Desktop immediately calls `_refreshRepository`, `_fetch`, and then `checkoutLocalBranch(repository, branchName)` — with **no popup, confirmation, or diff review shown to the user** [6](#0-5) .

This contrasts with the "no branch/no repo yet" case, which does prompt the user via `PopupType.CloneRepository`/`PopupType.AddRepository` before doing anything [7](#0-6) .

The broken invariant mirrors the report's pattern: a state-changing action intended to originate from a specific, trusted context (a user consciously clicking "Open in Desktop" from a GitHub page they trust) can instead be triggered by an unrelated party — since custom protocol activation carries no origin/sender authentication, and Desktop performs no corroborating check (e.g., confirming the click actually originated from github.com, or prompting the user before mutating repository state). The only two guards present are content-format sanitization on `branch` (regex reject for invalid ref characters, `testForInvalidChars`) [8](#0-7)  and a path-traversal guard on the unrelated `filepath` parameter [9](#0-8) . Neither of these guards prevents an attacker from picking any pre-existing branch name on the same repository and forcing the checkout.

### Impact Explanation
If exploitable as described, a user with a repository already added to Desktop can have their working directory silently switched to an attacker-chosen branch merely by clicking a crafted link. Depending on what `checkoutLocalBranch`/the underlying `_checkoutBranch` does with uncommitted local changes (an implementation detail I could not verify in the time available), this could range from an unwanted, unconfirmed branch switch to loss/corruption of uncommitted work, or placing the user on a branch whose content differs from what they believe they're working on when they next build, run, commit, or push — matching the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
The attacker precondition is simply knowing (a) that the victim uses GitHub Desktop, (b) the URL of a repository the victim has already cloned/added (often public and easily guessable, e.g. any public GitHub repo the target contributes to), and (c) an existing branch name on that repo. No credentials, local access, or malware are required — only getting the victim to click a link, which is an ordinary, expected user action for this exact protocol handler (it exists specifically to be clicked from web pages).

### Recommendation
- Require explicit user confirmation (a popup, similar to the `AddRepository`/`CloneRepository` flow) before fetching and checking out a branch triggered via the `open-repository-from-url` protocol action, especially when it targets a repository that is already present locally.
- Warn or block the checkout if there are uncommitted changes rather than performing it unconditionally.
- Consider surfacing the source branch/repo in a confirmation dialog so the user can visually verify the action before it mutates their working directory.

### Proof of Concept
1. Victim has previously added `https://github.com/acme/widgets` to GitHub Desktop, with a branch `release-1.0` already present locally/remotely.
2. Attacker sends the victim (via chat, email, or a hosted web page) a link:
   `x-github-client://openRepo/https://github.com/acme/widgets?branch=release-1.0`
3. Victim clicks the link. The OS activates GitHub Desktop's registered protocol handler; `handleAppURL` → `parseAppURL` → `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl` runs `_fetch` + `checkoutLocalBranch` against the matched local repository with no confirmation prompt [10](#0-9) .
4. The victim's working directory is switched to `release-1.0` without any indication that this was requested by an external, non-GitHub-originated link.

Note: I could not verify within the available tool budget whether `checkoutLocalBranch`/`_checkoutBranch` (defined in `app/src/lib/stores/app-store.ts`, not fully retrieved) performs any uncommitted-changes safety check before switching branches — this affects the precise severity (silent branch switch vs. potential work loss) and should be confirmed by reading that implementation directly.

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }
