### Title
`ManualCompound.compound()` sweeps the entire contract balance of every registered reward token to the caller instead of only the amount claimed for them - (File: `rewards/ManualCompound.sol`)

### Summary
`ManualCompound.compound()` is a public, unprivileged-callable function that claims rewards on behalf of `msg.sender` via `MasterMagpie.multiclaimOnBehalf`, but then distributes to `msg.sender` the **full current token balance held by the `ManualCompound` contract**, not the delta actually claimed in that call. This is the exact bug class described in the external report: functions that measure/transfer full contract balances instead of tracking a protected "starting balance" end up sweeping tokens that belong to someone else (dust, remainders, or previously accumulated balances).

### Finding Description
`ManualCompound.compound()` [1](#0-0)  works as follows:
1. It calls `IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender)` [2](#0-1) , which is restricted to `_onlyCompounder` in `MasterMagpie.sol` and only the `ManualCompound` contract itself is authorized as `compounder` [3](#0-2) .
2. For non-compoundable rewards it reads `IERC20(_rewards[i][j]).balanceOf(address(this))` and transfers the **entire** balance to `msg.sender`, with no comparison against a pre-call balance: [4](#0-3) .
3. For compoundable rewards, it iterates the **global** `rewards` array (all registered reward tokens for the whole protocol, not just what this caller claimed) and again reads `IERC20(_tokenAddress).balanceOf(address(this))` as `receivedBalance`, then converts/locks/transfers that entire balance on behalf of `msg.sender`: [5](#0-4) .

There is no `startingBalance`/delta protection at all (worse than the LiFi pattern, which at least computed `postSwapBalance - startingBalance`). Any dust or residual balance left in `ManualCompound` — from a prior caller's partial/failed conversion (`IConverter`/`ILocker`/`ISimpleHelper` calls can leave remainders due to rounding or partial consumption), from precision loss in `WombatStaking._sendRewards`'s fee math [6](#0-5) , or simply because a previous `compound()` transaction reverted after tokens were already pulled into the contract — becomes freely sweepable by the *next* unrelated caller of `compound()`, since the function does not scope the transferred amount to what was actually claimed for `msg.sender` in the current call.

### Impact Explanation
An unprivileged wallet can call `compound()` with an arbitrary/minimal `_lps`/`_rewards` selection (even claiming nothing new) and still receive the full standing balance of every registered reward token sitting in `ManualCompound`, including funds that rightfully belong to other users whose rewards/conversions left a remainder in the contract. This is a direct theft-of-user-funds vector, consistent with the report's core defect: unprotected balances swept by any caller of shared swap/convert/distribute logic.

### Likelihood Explanation
Likelihood is moderate: `ManualCompound` handles multiple reward tokens across many users and multiple external calls (`IConverter.convertFor`, `ILocker.lockFor`, `ISimpleHelper.depositFor`) whose exact output amounts are not always fully consumed/forwarded in a single pass; rounding in `WombatStaking._sendRewards` fee splitting, or any reverted/partial compound transaction, naturally leaves residual token balances in the contract that any subsequent caller can claim in full.

### Recommendation
Compute a `startingBalance` for each relevant token immediately before `multiclaimOnBehalf` is invoked, and only forward/convert/lock the **difference** (`balanceAfter - startingBalance`) to `msg.sender`, mirroring the intended fix pattern from the referenced report. Do not read and disburse the raw `balanceOf(address(this))` for tokens whose provenance is not scoped to the current caller's claim.

### Proof of Concept
1. Reward token `R` is registered via `addReward` and is not currently `compoundableRewards`-excluded, or a compoundable path leaves a remainder (e.g., `IConverter.convertFor` is called with `receivedBalance` but the underlying conversion routes only part of it, or a prior user's `compound()` call for `R` is left partially processed because of a downstream external call revert after tokens were pulled in).
2. `ManualCompound` now holds a residual balance of `R` that is not attributable to any pending caller.
3. Any wallet (attacker) calls `compound()` with `_lps`/`_rewards` such that `multiclaimOnBehalf` claims little or nothing new for `R`.
4. In the loop over `rewards`, `receivedBalance = IERC20(R).balanceOf(address(this))` picks up the full residual balance (not just the attacker's newly claimed amount) and is transferred/converted/locked entirely to the attacker via `safeTransfer`/`convertFor`/`lockFor`/`depositFor` [7](#0-6) .
5. The attacker has swept tokens that were not part of their own claim.

    function compound(address[] calldata _lps, address[][] calldata _rewards, uint256 _convertRatio, uint256 _minRec, bool _lockMgp) external {
        uint256 rewardTokensLength = rewards.length;        
        IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender);
        // send none compoundable reward back to caller
        for(uint256 i; i < _lps.length; i++) {
            uint256 rewardLength = _rewards[i].length;
            if (rewardLength > 0) {
                for (uint j; j < rewardLength; j++) {
                    if (!compoundableRewards[_rewards[i][j]]) {
                        uint256 rewardBalance = IERC20(_rewards[i][j]).balanceOf(address(this));
                        if (rewardBalance > 0)
                            IERC20(_rewards[i][j]).safeTransfer(msg.sender, rewardBalance);
                    }
                }
            }
        }
        for (uint256 i; i< rewardTokensLength; i++) {
            address _tokenAddress = rewards[i].tokenAddress;
            address _helperAddress = rewards[i].tokenHelper;
            address _convertor = rewards[i].convertor;
            address _locker = rewards[i].locker;
            uint256 receivedBalance = IERC20(_tokenAddress).balanceOf(address(this));

            if (receivedBalance > 0) {
                if (_convertor != address(0)) {
                    IERC20(_tokenAddress).safeApprove(_convertor, receivedBalance);
                    IConverter(_convertor).convertFor(receivedBalance, _convertRatio, _minRec, msg.sender, 2);
                } else if (_locker != address(0) && _lockMgp) {
                    IERC20(_tokenAddress).safeApprove(_locker, receivedBalance);
                    ILocker(_locker).lockFor(receivedBalance, msg.sender);                        
                } else if (_helperAddress != address(0)) { 
                    IERC20(_tokenAddress).safeApprove(_helperAddress, receivedBalance);
                    ISimpleHelper(_helperAddress).depositFor(receivedBalance, msg.sender);
                } else {
                    IERC20(_tokenAddress).safeTransfer(msg.sender, receivedBalance);
                }
            }
        }

        emit Compounded(msg.sender, rewardTokensLength, _lockMgp);
    }
