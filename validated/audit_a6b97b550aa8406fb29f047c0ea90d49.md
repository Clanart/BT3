## Finding: Confusable/spoofed branch & ref names bypass Desktop's name-uniqueness and validation checks

This closely mirrors the zNS bug class: the underlying identifier-uniqueness check operates on raw string/byte equality, while the *displayed* representation can be made visually identical for two different underlying identifiers, letting an attacker's object masquerade as a trusted one.

### Title
Ref-name sanitizer strips illegal `git check-ref-format` bytes but not bidi/invisible Unicode, letting a remote-supplied branch name visually spoof an existing/trusted branch - (File: `app/src/lib/sanitize-ref-name.ts`)

### Summary
Desktop validates untrusted branch names — including the `branch` query parameter of "Open in Desktop" `x-github-client://` deep links and remote/PR branch names — with a single regex, `invalidCharacterRegex`, that only rejects ASCII control characters `\x00-\x20`, `DEL`, and a short list of shell/filesystem-unsafe symbols. It does not strip Unicode bidirectional control characters (e.g. U+202E RIGHT-TO-LEFT OVERRIDE, U+2066–U+2069 isolates) or invisible/zero-width characters (U+200B, U+FEFF, etc.). Two byte-distinct branch names can therefore render identically (or in a deliberately misleading order) in Desktop's UI, while being treated as distinct refs by every downstream string-equality check (duplicate-branch detection, "already exists on remote" warning, PR/repo matching).

### Finding Description
`sanitizedRefName`/`testForInvalidChars` in [1](#0-0)  is the sole gatekeeper used to validate a branch name coming from a fully untrusted, attacker-controlled source: the `branch` querystring parameter of an "Open in Desktop" deep link, parsed in [2](#0-1) , where the only check performed is `testForInvalidChars(branch)`.

That regex range (`\x00-\x20`) does not cover Unicode bidi-override characters or zero-width characters, which live outside the Basic Latin control-character range. A crafted branch name such as `main` + U+202E + reversed malicious suffix, or `release/v1` with an interleaved zero-width space, passes validation untouched and is forwarded as-is:

- `openBranchNameFromUrl` in [3](#0-2)  calls `checkoutLocalBranch(repository, branchName)` with the raw, unsanitized branch string obtained from the deep link.
- Every place Desktop de-duplicates or warns about name collisions compares names with plain string equality, e.g. the "branch already exists" check in [4](#0-3)  and the remote-collision warning in [5](#0-4) .

None of these comparisons normalize or strip bidi/invisible characters before comparing, and the `<Ref>` component used throughout the UI (rename/create-branch dialogs, warnings) renders the raw string, so a rendering engine that honors Unicode bidi controls will display the byte-distinct ref name identically to (or as a misleading permutation of) a real, trusted branch name such as `main` or a release branch.

### Impact Explanation
An attacker who can get a user to click a crafted "Open in Desktop" deep link (a standard, expected attack surface for this feature — GitHub itself renders these links on `github.com`) can supply a `branch` value that Desktop's validation accepts as-is but that visually spoofs a different, trusted branch name in the checkout confirmation UI, the current-branch indicator, and any "branch already exists" collision warnings. Because the identifier used for actual git operations (`checkoutLocalBranch`) is the raw byte sequence while the identifier the user relies on to judge trust is the rendered glyph sequence, this can cause the user to review/build/push on a branch they believe is a different, legitimate one — i.e. silent corruption of what the user believes they are committing to or pushing from, the same "visually indistinguishable identifiers, different underlying identity" primitive as the zNS report.

### Likelihood Explanation
Requires only that the victim click an attacker-supplied link (a normal, expected interaction for this feature — no local access, malware, or leaked credentials needed). The character classes involved (bidi overrides, zero-width characters) are well-known, low-effort attack primitives ("Trojan Source"-style) and require no special tooling to embed in a URL-encoded querystring value.

### Recommendation
Extend `invalidCharacterRegex` (or add a companion check) in `app/src/lib/sanitize-ref-name.ts` to also strip/reject Unicode bidirectional control characters (U+202A–U+202E, U+2066–U+2069) and invisible/zero-width characters (U+200B–U+200F, U+FEFF), consistent with how `git`/GitHub itself now flags such characters. Apply the same check to any ref name obtained from an untrusted source before it is used for both git operations and UI display, not just the deep-link `branch` parameter.

### Proof of Concept
1. Construct a deep link: `x-github-client://openRepo/https://github.com/attacker/repo?branch=main%E2%80%AEcod.exe` (URL-encoded U+202E between `main` and the reversed suffix).
2. `parseAppURL` accepts it because `testForInvalidChars` only checks `\x00-\x20` and a short symbol list — see [6](#0-5) .
3. `openBranchNameFromUrl` checks out the branch and it is subsequently rendered via `<Ref>` in dialogs/warnings, displaying a string that is visually confusable with a trusted branch name while being a distinct git ref for every exact-string comparison in the codebase.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

export function renderBranchNameExistsOnRemoteWarning(
  sanitizedName: string,
  branches: ReadonlyArray<Branch>
) {
  const alreadyExistsOnRemote =
    branches.findIndex(
      b => b.nameWithoutRemote === sanitizedName && b.type === BranchType.Remote
    ) > -1

  if (alreadyExistsOnRemote === false) {
    return null
  }

  return (
    <Row className="warning-helper-text">
      <Octicon symbol={octicons.alert} />
      <p>
        A branch named <Ref>{sanitizedName}</Ref> already exists on the remote.
      </p>
    </Row>
  )
}
