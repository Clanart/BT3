### Title
Schnorr aggregate signature weights do not bind the nonces or public keys, enabling forgery of aggregate signatures - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` computes the verification weights `z_i` from a transcript that commits only to the per-signature challenges, never to the nonce commitments `Rs` nor to the public keys. Because the weights are computable before the attacker chooses their `R`, a malicious co-signer can select a nonce point that algebraically cancels every other participant's term, producing an aggregate signature that verifies over a public key whose owner never produced a corresponding signature component.

### Finding Description
The half-aggregation scheme of https://eprint.iacr.org/2021/350 requires each per-signature weight `z_i` to be unpredictable and bound to *all* inputs of the verification instance (each `R_i`, each public key, each challenge/message, and the index). Otherwise a rogue participant can compute the weights, then craft `R` values that cancel victim terms.

In `crypto/schnorr/src/aggregate.rs`, `SchnorrAggregate::verify` builds the digest by appending only the challenges:

```rust
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
``` [1](#0-0) 

Then, for each `(key_i, challenge_i)`, it draws `z_i = weight(&mut digest)` and queues `z_i·R_i` and `z_i·c_i·P_i`. Neither `R_i` nor `P_i` is ever appended to `digest`, so `z_i` is a pure function of `(dst, c_1..c_n)` — all publicly known before the attacker commits to their `R`. The aggregate signature `read` path accepts arbitrary attacker-controlled `Rs` and `s` with no further binding.

### Impact Explanation
An attacker who contributes one component to an aggregate verification can forge an aggregate signature over a set that includes a victim's `(R_v, P_v, c_v)` triple (e.g., a previously published signature), making the verifier accept `s·G = Σ z_i·R_i + Σ z_i·c_i·P_i` while the victim's term is fully cancelled:

- Attacker knows all `c_i`, so computes every `z_i` before choosing anything.
- Attacker picks random `k` and sets their nonce `R_a = k·G - c_a·P_a - (z_v/z_a)·(R_v + c_v·P_v)`.
- Attacker sets `s = z_a·k`. Verification then yields `z_v·(R_v + c_v·P_v) + z_a·(R_a + c_a·P_a) - s·G = z_v·(R_v + c_v·P_v) - z_v·(R_v + c_v·P_v) + z_a·k·G - z_a·k·G = identity` → accepted.

This is a forged signature accepted by `verify` — an unauthorized "modification" of the accepted statement set, matching the CVE's integrity impact class, reachable by an unprivileged party supplying `SchnorrAggregate` bytes plus their own key/challenge entry.

### Likelihood Explanation
Any verifier that aggregates signatures where at least one `(key, challenge)` pair and the `SchnorrAggregate`'s `Rs`/`s` come from an untrusted party is exploitable with certainty — no racing, negligible probabilities, or privileged position is required. The only precondition is that the attacker can learn the challenges (which are public by construction) before submitting their `R`.

### Recommendation
Bind the weights to the full verification instance: append each `R_i.to_bytes()` and each `key.to_bytes()` (and ideally the index `i`) to `digest` inside `SchnorrAggregate::verify` before/while deriving each `z_i`, mirroring the transcript format used when the aggregate was created. The signer-side weight derivation must be updated identically so honest signatures still verify.

### Proof of Concept
```rust
// C: any in-scope Ciphersuite (e.g., dalek_ff_group::Ed25519)
// Victim published signature components: key_v, challenge c_v, nonce R_v
// Attacker controls (key_a, c_a) and supplies the SchnorrAggregate.

// 1. Recompute the weights exactly as verify() does
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for c in [c_v, c_a] { digest.append_message(b"challenge", c.to_repr()); }
let z_v = weight(&mut digest);
let z_a = weight(&mut digest);

// 2. Choose k randomly, craft R_a to cancel the victim term
let k = C::random_nonzero_F(&mut OsRng);
let R_a = (C::generator() * k) - (key_a * c_a) - ((R_v + key_v * c_v) * (z_v * z_a.invert().unwrap()));

// 3. Forged aggregate
let forged = SchnorrAggregate::<C> { Rs: vec![R_v, R_a], s: z_a * k };
assert!(forged.verify(dst, &[(key_v, c_v), (key_a, c_a)])); // passes without knowing x_v
```
