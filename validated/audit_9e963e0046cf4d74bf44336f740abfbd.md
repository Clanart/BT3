### Title
Out-of-bounds buffer read in canonical-CLVM length-prefix parser can crash mempool validation on a malicious spend bundle - ([File: chia/full_node/mempool_manager.py])

### Summary
The Apache CVE describes an out-of-bounds read caused by trusting a length/size value while consuming a buffer without validating that enough bytes remain. The Chia codebase has an analogous pattern in `is_atom_canonical()`, the CLVM length-prefix parser used to validate canonical serialization of untrusted `puzzle_reveal`/`solution` bytes from a submitted `SpendBundle`.

### Finding Description
`is_atom_canonical()` decodes a CLVM atom's variable-length size prefix (1–6 bytes) directly from attacker-controlled bytes without ever checking that `offset` stays within `len(clvm_buffer)`: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` reads `prefix_len` additional bytes purely based on the top bits of the first byte, with no check that the buffer actually contains that many trailing bytes. `is_clvm_canonical()`, which drives this function, also indexes `clvm_buffer[offset]` in its main loop without a bounds check before dereferencing: [2](#0-1) 

Per the repo's own architecture notes, this canonical-serialization check is invoked during spend-bundle admission to determine DEDUP eligibility for each coin spend's `puzzle_reveal`/`solution`: [3](#0-2) 

Contrast this with the length-prefixed buffer parsers in `chia/full_node/full_block_utils.py`, which explicitly validate remaining-buffer length before reading (`skip_bytes`, `skip_list`, `generator_from_block`), showing the codebase is normally careful about this exact bug class: [4](#0-3) [5](#0-4) 

`is_atom_canonical`/`is_clvm_canonical` do not follow that same discipline: a crafted atom whose length-prefix marker byte appears as the last byte(s) of the buffer causes `clvm_buffer[offset]` to index past the end of the `bytes` object.

### Impact Explanation
In CPython, indexing a `bytes` object past its end raises `IndexError` rather than reading adjacent process memory — so this is not a memory-disclosure vulnerability the way the Apache C-level OOB read is. The reachable impact is instead an **unhandled exception during mempool admission of an untrusted spend bundle**, i.e., a spend-triggered exception in the transaction-validation path. If this exception is not caught around the canonical-serialization check, a single malicious `SpendBundle` with a crafted `puzzle_reveal` or `solution` (e.g., a truncated multi-byte atom length prefix) could raise `IndexError` inside `MempoolManager`'s spend-processing pipeline, at minimum failing that admission call ungracefully, and at worst disrupting processing of subsequent spend bundles if not isolated per-item.

### Likelihood Explanation
Reaching this code only requires submitting a `SpendBundle` whose puzzle reveal or solution contains a malformed atom near the end of the buffer — fully controllable by any unprivileged spend-bundle submitter, with no signature or fee requirements to reach the parser (canonical-check happens as part of building `BundleCoinSpend` metadata). However, I could not confirm from the retrieved code whether the call site wraps `is_clvm_canonical()` in a broad `try/except` that gracefully converts this into `Err.INVALID_COIN_SOLUTION` (existing tests such as `test_mempool_requires_canonical_clvm` only cover non-canonical-but-well-formed cases, not truncated/malformed buffers that trigger `IndexError`) — this is the main open uncertainty limiting confidence in a full mempool-halt impact versus a per-bundle rejection.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (mirroring the `len(buf) < N` guards already used in `chia/full_node/full_block_utils.py`), and ensure the canonical-CLVM check call site in `mempool_manager.py` catches `IndexError`/`ValueError` and converts it to a normal `MempoolInclusionStatus.FAILED` / `Err.INVALID_COIN_SOLUTION` result rather than letting it propagate.

### Proof of Concept
A `SpendBundle` whose `puzzle_reveal` or `solution` ends with a truncated multi-byte atom length prefix, e.g. bytes `b"\xff\xc0"` (a CLVM pair marker `0xFF` followed by an atom marker `0xC0` that requires one more length byte which is absent), passed through `is_clvm_canonical()` / `is_atom_canonical()` causes `clvm_buffer[offset]` to be indexed at `offset == len(clvm_buffer)`, raising `IndexError` while processing an untrusted, submitted spend bundle.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
