## Finding: Gasless module lends KAIA based on declared GasLimit but the EVM refunds unused gas to the sender, letting attackers extract free KAIA from the block proposer on every swap - ([File: kaiax/gasless/impl/getter.go])

### Summary

The KIP-247 gasless module (`kaiax/gasless`) has the block proposer "lend" KAIA to a user so the user can pay for the gas of a `GaslessApproveTx`/`GaslessSwapTx` pair, and the user is supposed to fully repay that lend via a token swap embedded in `swapForGas`. The lent amount and the required repayment amount are both computed from the transactions' **declared gas limit** (`Transaction.Fee() = GasLimit * GasPrice`), not from the **actual gas used**. Because the Kaia EVM state-transition model refunds unused gas (GasLimit − GasUsed) × GasPrice back to the fee payer (`returnGas()`), and the fee payer for the Approve/Swap transactions is the gasless sender itself, the sender ends up keeping that unused-gas refund as a pure windfall on top of fully repaying the proposer through the token swap. Any unprivileged transaction sender who can construct a valid gasless bundle can inflate the gas limits of the Approve/Swap transactions (while keeping actual execution cost low) to extract free native KAIA from the block proposer.

### Finding Description

The gasless flow is:
1. `GetLendTxGenerator` builds a `LendTx` from the proposer to the sender, with value `lendAmount(approveTxOrNil, swapTx)`: [1](#0-0) 

2. `VerifyExecutable` enforces that the `GaslessSwapTx.AmountRepay` field equals `repayAmount(approveTxOrNil, swapTx)`, which is `LendTx.Fee() (R1) + lendAmount (R2+R3)`: [2](#0-1) [3](#0-2) 

Both `lendAmount` and `repayAmount` are derived from `Transaction.Fee()`, which multiplies **GasLimit** (not gas actually used) by GasPrice — confirmed by the test helper computing `R2 = gasLimit(100000) * gasPrice` and `R3 = gasLimit(500000) * gasPrice` for the Approve/Swap legs, matching declared gas limits rather than execution cost: [4](#0-3) 

3. When the ApproveTx and SwapTx actually execute, the sender (fee payer) is first debited the *full* `GasLimit*GasPrice` in `buyGas()`, then refunded the unused portion `(GasLimit − GasUsed) * GasPrice` at the end of execution in `returnGas()`: [5](#0-4) [6](#0-5) 

Because `AmountRepay` (paid to the proposer via the on-chain swap, a value stream entirely separate from the sender's native-KAIA gas accounting) already reimburses the proposer for the *full* declared `lendAmount`, the leftover gas refund that lands back in the sender's own KAIA balance is not deducted from anywhere else — it is a net creation of spendable KAIA balance for the sender, funded entirely by the proposer's lend. A sender who deliberately sets high `GasLimit` values on the Approve/Swap transactions (while consuming only the minimal actual gas, e.g., simple `approve`/`swapForGas` calls) maximizes this leftover and can repeat the gasless flow across many transactions/blocks to accumulate real KAIA drained from the proposer's own balance, with no equivalent debit anywhere in the protocol's accounting.

This is conceptually analogous to the MIM Spell incident: a legitimate-looking, "supported" code path (deprecated Cauldron logic there; gas-accounting mismatch here) that fails to enforce that value handed out matches value actually consumed, allowing unauthorized creation/extraction of tokens (MIM there, KAIA here) by an ordinary counterparty.

### Impact Explanation

This is a fee-delegation/gasless-settlement value-extraction bug: an unprivileged transaction sender can systematically drain native KAIA from the block proposer's balance every time they perform a KIP-247 gasless swap, by inflating the gas limits declared on the bundled Approve/Swap transactions relative to their actual gas consumption. Given repeated exploitation across many blocks/proposers, this constitutes concrete unauthorized value movement from proposers to attacker-controlled accounts, satisfying the "gasless or auction settlement theft" impact category.

### Likelihood Explanation

Reachable by any ordinary user: gasless transactions are a standard, publicly available feature (KIP-247) that any address can use by submitting an `Approve`+`Swap` pair (or a standalone swap) that passes `IsApproveTx`/`IsSwapTx`/`VerifyExecutable`. No special privileges, validator role, or governance access is required — only the ability to submit normal transactions and control their `GasLimit` fields, which is entirely attacker-controlled input.

### Recommendation

Base `lendAmount`/`repayAmount` (and the on-chain `AmountRepay` requirement) on actual gas consumption rather than the declared `GasLimit`, or alternatively require the leftover gas refund from the Approve/Swap transactions to be swept back to the proposer/rewardbase rather than left in the sender's balance. At minimum, the repayment amount enforced by `VerifyExecutable`/the `GaslessSwapRouter` contract should be reconciled against the *actual* gas used by the bundled transactions (available post-execution) before finalizing the block, not merely their declared gas limits.

### Proof of Concept

Conceptual reproduction using existing test scaffolding in `kaiax/gasless/impl`:
1. Construct `ApproveTx` and `SwapTx` with an inflated `GasLimit` (e.g., 500,000) while the actual logic executed (`approve`, `swapForGas`) consumes far less gas (e.g., ~50,000).
2. Set `SwapArgs.AmountRepay` exactly equal to `repayAmount(approveTx, swapTx)` as computed by `kaiax/gasless/impl/getter.go` (based on the inflated GasLimit), so `VerifyExecutable` accepts the bundle — see the exact check at: [7](#0-6) 
3. Let the proposer build the block: `GetLendTxGenerator` sends `lendAmount` (based on inflated GasLimit) to the sender.
4. After the block executes, per `blockchain/state_transition.go`'s `returnGas()`, the sender's balance retains `(GasLimit − GasUsed) * GasPrice` for both transactions as leftover, in addition to the swap proceeds used to pay `AmountRepay` to the proposer.
5. Repeating this across many gasless-swap cycles nets the attacker a steady stream of native KAIA sourced from the proposer's lending balance, with no corresponding debit recorded anywhere in the `kaiax/reward` or `kaiax/supply` accounting.

Note: I was unable to fully inspect the Solidity source of `GaslessSwapRouter.swapForGas` (only compiled bytecode/bindings were indexed) to confirm exactly how `AmountRepay` is transferred to the proposer on-chain; a Devin session with full repository access would be needed to verify the precise on-chain repayment mechanics and confirm there is no additional reconciliation step that offsets this leftover.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (st *StateTransition) buyGas() error {
	var (
		validatedFeePayer = st.msg.ValidatedFeePayer()
		validatedSender   = st.msg.ValidatedSender()
		feeRatio, _       = st.msg.FeeRatio()
		isOsaka           = st.evm.ChainConfig().Rules(st.evm.Context.BlockNumber).IsOsaka
	)

	// mgval is the maximum gas fee that can actually be paid in the worst case (e.g., revert)
	// st.gasPrice = tx.gasPrice (before Magma) or effectiveGasPrice (since Magma)
	mgval := new(big.Int).Mul(new(big.Int).SetUint64(st.msg.Gas()), st.gasPrice)

	// feeCap is the maximum gas fee the sender was willing to pay
	// GasFeeCap = tx.maxFeePerGas (if exists) or tx.gasPrice
	feeCap := new(big.Int).Mul(new(big.Int).SetUint64(st.msg.Gas()), st.msg.GasFeeCap())

	if isOsaka {
		if blobGas := st.blobGasUsed(); blobGas > 0 {
			// Check that the user has enough funds to cover blobGasUsed * tx.BlobGasFeeCap
			blobFeeCap := new(big.Int).SetUint64(blobGas)
			blobFeeCap.Mul(blobFeeCap, st.msg.BlobGasFeeCap())
			feeCap.Add(feeCap, blobFeeCap)
			// Pay for blobGasUsed * actual blob fee
			blobFee := new(big.Int).SetUint64(blobGas)
			blobFee.Mul(blobFee, st.evm.Context.BlobBaseFee)
			mgval.Add(mgval, blobFee)
		}
	}

	if validatedFeePayer == validatedSender {
		// 1. Non fee-delegated tx
		// 2. FeeDelegatedWithRatio with sender == feePayer
		// 3. FeeDelegated          with sender == feePayer

		// Before Osaka, only the check of the amount to be deducted is applied.
		// Therefore, all options are false.
		checkOverflow, checkWithValue := false, false
		balanceCheck := mgval
		if isOsaka {
			// Overflow will be checked from osaka onwards.
			// A value check is also performed.
			checkOverflow, checkWithValue = true, true
			balanceCheck = feeCap
		}
		if err := st.checkFeePayerBalance(balanceCheck, checkOverflow, checkWithValue); err != nil {
			return err
		}
		st.state.SubBalance(validatedFeePayer, mgval)
	} else {
		// 1. FeeDelegatedWithRatio with sender != feePayer
		// 2. FeeDelegated          with sender != feePayer

		// Before Osaka, only the check of the amount to be deducted is applied.
		// Therefore, all options are false.
		feePayerCheckOverflow, feePayerCheckWithValue := false, false
		senderCheckOverflow, senderCheckWithValue := false, false

		// For 2, feeRatio will be always 100 (feePayer pays all fee)
		feePayerFee, senderFee := types.CalcFeeWithRatio(feeRatio, mgval)
		feePayerBalanceCheck, senderBalanceCheck := feePayerFee, senderFee
		if isOsaka {
			// Overflow will be checked from osaka onwards.
			// Since the value is paid entirely by the sender, value checks only apply to sender.
			feePayerCheckOverflow, feePayerCheckWithValue = true, false
			senderCheckOverflow, senderCheckWithValue = true, true

			feePayerBalanceCheck, senderBalanceCheck = types.CalcFeeWithRatio(feeRatio, feeCap)
		}
		if err := st.checkFeePayerBalance(feePayerBalanceCheck, feePayerCheckOverflow, feePayerCheckWithValue); err != nil {
			return err
		}
		if err := st.checkSenderBalance(senderBalanceCheck, senderCheckOverflow, senderCheckWithValue); err != nil {
			return err
		}
		st.state.SubBalance(validatedFeePayer, feePayerFee)
		st.state.SubBalance(validatedSender, senderFee)
	}

	st.gas += st.msg.Gas()

	st.initialGas = st.msg.Gas()
	return nil
}

// returnGas returns KAIA for remaining gas, exchanged at the original rate.
func (st *StateTransition) returnGas() {
	remaining := new(big.Int).Mul(new(big.Int).SetUint64(st.gas), st.gasPrice)

	validatedFeePayer := st.msg.ValidatedFeePayer()
	validatedSender := st.msg.ValidatedSender()
	feeRatio, isRatioTx := st.msg.FeeRatio()
	if isRatioTx {
		feePayer, feeSender := types.CalcFeeWithRatio(feeRatio, remaining)

		st.state.AddBalance(validatedFeePayer, feePayer)
		st.state.AddBalance(validatedSender, feeSender)
	} else {
		// To make a short circuit, the below routine processes when feeRatio == 100.
		st.state.AddBalance(validatedFeePayer, remaining)
	}
}
