### Title
`fillOrder` allows draining escrowed input tokens for zero payment when a placed order has no (or zero-amount) output assets - ([File: evm/src/apps/IntentGatewayV2.sol], [File: evm/src/apps/intentsv2/ExtrinsicIntents.sol], [File: evm/src/apps/intentsv2/IntrinsicIntents.sol])

### Summary
`placeOrder` validates that `order.inputs.length != 0` and that every input amount is non-zero, but it never validates `order.output.assets.length` or that each output asset amount is non-zero. [1](#0-0) [2](#0-1) 

Both the cross-chain fill path (`_fillCrossChain`) and the same-chain fill path (`_fillSameChain`) iterate over `order.output.assets.length` to determine how much value/tokens the solver must actually transfer to the beneficiary. If that length is `0` (or each entry's `amount` is `0`), the loop body that enforces `solverAmount >= totalRequired` and performs the token/ETH transfer never executes, yet the function still marks the order filled and still releases (or dispatches a request to release) the full escrowed input tokens to the caller. [3](#0-2) [4](#0-3) 

### Finding Description
This is the direct analog of the reported bug: `makeBuyOer()` failed to require `msg.value > 0`, so a buy order could be placed with zero payment yet still complete a token transfer when accepted. Here, `placeOrder()` fails to require that the order actually demands any output payment (`order.output.assets.length > 0` and each `amount > 0`), so a caller can escrow real input tokens under an order that has an effectively empty/zero output requirement.

Once such an order exists on-chain, `fillOrder()` (dispatching to `_fillCrossChain` or `_fillSameChain`) is a fully public, unprivileged entrypoint. Any caller can invoke it with `msg.value = 0` and an `outputs` array whose length matches the order's (possibly `0`-length) `order.output.assets`:

- In `_fillCrossChain`, the `for` loop over `outputsLen` (which is `0`) never runs, so none of the `InvalidInput()`, `InsufficientNativeToken()`, or `safeTransferFrom` checks execute. The function proceeds straight to `_execute(order, outputsLen)` and dispatches a `RedeemEscrow` message to the source chain, which on `onAccept()` calls `_withdraw()` to release every escrowed input token to `msg.sender` (the caller). [3](#0-2) [5](#0-4) 

- In `_fillSameChain`, the same empty/zero-amount output loop skips all transfer logic, `_filled[commitment]` is set, and `_withdraw()` is called directly to hand the caller the full escrowed input tokens. [6](#0-5) 

The root cause mirrors the report precisely: the "buy/fill" side of the transaction is permitted to proceed with zero value because the contract only validates the amount that exists on record (`order.output.assets`), and never enforces that this record is non-empty/non-zero at order-creation time. Any order that ends up with an empty or all-zero output array — whether from a buggy SDK/UI integration, a malformed `Order` struct submitted directly to the contract (it is a public function taking a raw `Order memory`), or any other means — becomes a "free fill" for the first caller of `fillOrder`.

### Impact Explanation
This directly causes stealing/loss of escrowed input tokens. The first caller of `fillOrder()` on such an order takes the full escrowed input value while transferring zero tokens/ETH to the beneficiary, and the transaction that triggers the loss is a normal, public, unprivileged entrypoint — no malicious relayer, prover, or admin is required. The fund flow moves the wrong amount (zero) to the beneficiary while releasing full value to the "solver," directly matching the bounty's "stealing or loss of funds" and "logic attacks" categories.

### Likelihood Explanation
Exploitation requires only a public call to `fillOrder()` against an order whose `output.assets` is empty or zero-valued; no privileged role, proof forgery, or peer/relayer manipulation is needed. The likelihood scales with whether such degenerate orders can appear on-chain (e.g., SDK misuse, integrator error, or an order deliberately crafted this way by any address that also wants a channel to move input tokens cross-chain without real payment) — since `placeOrder` accepts a raw `Order memory` from any caller with no validation on `output.assets`, nothing in the contract prevents it.

### Recommendation
In `placeOrder()`, require `order.output.assets.length > 0` and that every `order.output.assets[i].amount > 0` (mirroring the existing `order.inputs[i].amount == 0` check), so an order can never be created with an unenforceable/zero output requirement. As defense in depth, `_fillCrossChain` and `_fillSameChain` should also reject fills where `outputsLen == 0`.

### Proof of Concept
1. Attacker (or any user) calls `placeOrder(order, graffiti)` with `order.inputs = [{token: USDC, amount: 1000e6}]` and `order.output.assets = []` (empty array) or `order.output.assets = [{token: X, amount: 0}]`. `placeOrder` only checks `order.inputs[i].amount == 0` and duplicate output tokens — an empty/zero-amount output array passes unchecked. [7](#0-6) 
2. The 1000 USDC is transferred into escrow (`_orders[commitment][USDC] = 1000e6`). [8](#0-7) 
3. Any address calls `fillOrder(order, options)` with `options.outputs = []` (matching length) and `msg.value = 0`. The output loop in `_fillCrossChain`/`_fillSameChain` never executes (0 iterations), so no ETH/ERC20 is ever sent to the beneficiary. [9](#0-8) 
4. `_execute` runs and a `RedeemEscrow` request is dispatched to the source chain; when it lands, `onAccept` → `_withdraw` releases the full 1000 USDC escrow to `msg.sender` (the "solver"), who paid nothing. [10](#0-9) [5](#0-4)

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            uint256 dust = solverAmount - totalRequired;
            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;

            if (dust > 0) {
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            }

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        address hostAddr = host();
        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RedeemEscrow)),
            abi.encode(
                WithdrawalRequest({
                    commitment: commitment, tokens: order.inputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
                })
            )
        );
        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        if (options.nativeDispatchFee > 0 && msgValue >= options.nativeDispatchFee) {
            IDispatcher(hostAddr).dispatch{value: options.nativeDispatchFee}(request);
            msgValue -= options.nativeDispatchFee;
        } else {
            dispatchWithFeeToken(request);
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function _fillSameChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        bool isFullyFilled = true;

        TokenInfo[] memory escrowedInputs = new TokenInfo[](outputsLen);
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            uint256 alreadyFilled = _partialFills[commitment][outputToken];
            uint256 remaining = totalRequired - alreadyFilled;
            if (remaining == 0 || solverAmount == 0) {
                if (solverAmount == 0 && remaining > 0) isFullyFilled = false;
                continue;
            }
            uint256 fillAmount;

            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;
            if (alreadyFilled == 0 && solverAmount > totalRequired) {
                fillAmount = totalRequired;
                uint256 dust = solverAmount - totalRequired;
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            } else {
                fillAmount = solverAmount > remaining ? remaining : solverAmount;
            }

            uint256 amountFilled = alreadyFilled + fillAmount;
            _partialFills[commitment][outputToken] = amountFilled;
            uint256 beneficiaryTotal = fillAmount + beneficiaryShare;

            if (token == address(0)) {
                if (msgValue < beneficiaryTotal + protocolShare) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, beneficiaryTotal);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }

            if (totalRequired > amountFilled) isFullyFilled = false;
            if (protocolShare > 0) emit DustCollected(token, protocolShare);

            uint256 escrowedAmount;
            if (amountFilled == totalRequired) {
                escrowedAmount = _orders[commitment][address(uint160(uint256(order.inputs[i].token)))];
            } else {
                escrowedAmount = (order.inputs[i].amount * fillAmount) / totalRequired;
            }
            escrowedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: escrowedAmount});
            outputFills[i] = TokenInfo({token: outputToken, amount: fillAmount});
        }

        // Orders carrying output calldata must be filled completely in a single fill.
        // The attached call is only executed on a full fill, so a partial fill would
        // leave the intended side effect unexecuted while releasing proportional escrow.
        if (order.output.call.length > 0 && !isFullyFilled) revert PartialFillNotAllowed();

        WithdrawalRequest memory body = WithdrawalRequest({
            commitment: commitment, tokens: escrowedInputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
        });
        _withdraw(body, false, isFullyFilled);

        if (isFullyFilled) {
            _execute(order, outputsLen);
            emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        } else {
            delete _filled[commitment];
            emit PartialFill({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: escrowedInputs});
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }
    }
