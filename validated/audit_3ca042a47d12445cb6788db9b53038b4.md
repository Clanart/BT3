### Title
Missing Length Validation on Auction Bid Signatures Causes Out-of-Bounds Slice Access - ([File: kaiax/auction/bid.go])

### Summary
`getSigner`, used to recover the searcher/auctioneer address from `Bid.SearcherSig` / `Bid.AuctioneerSig`, indexes the signature byte slice at fixed offsets (`[64]`, `[0:32]`, `[32:64]`) without ever checking that the slice is at least 65 bytes long. [1](#0-0)  Both signature fields are attacker-controlled: they are populated directly from the untrusted RPC input `BidInput.SearcherSig` / `BidInput.AuctioneerSig` (`hexutil.Bytes`, no length constraint) via `ToBid`, and then passed to `bidPool.AddBid`, which triggers signature validation. [2](#0-1) [3](#0-2)  An auction bidder can submit a bid with a `searcherSig`/`auctioneerSig` shorter than 65 bytes (including empty) via the public `auction_submitBid` RPC.

### Finding Description
`Bid.ValidateSearcherSig` and `Bid.ValidateAuctioneerSig` both call the shared helper `getSigner(sig, digest)`. [4](#0-3)  `getSigner` clones the caller-supplied `sig` and immediately indexes it:

```go
copiedSig := slices.Clone(sig)
if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
    copiedSig[crypto.RecoveryIDOffset] -= 27
}
v := copiedSig[crypto.RecoveryIDOffset]
r := new(big.Int).SetBytes(copiedSig[0:32])
s := new(big.Int).SetBytes(copiedSig[32:64])
``` [5](#0-4) 

`crypto.RecoveryIDOffset` is 64, and there is no prior check that `len(sig) >= 65`. If `sig` is empty or any length ≤ 64, `copiedSig[64]` (and, for very short inputs, the `[0:32]`/`[32:64]` slicing) is an out-of-bounds access, causing a runtime `index out of range` panic — the Go analog of the "operations outside the bounds of a memory buffer" bug class described in the referenced doslib CVE.

The upstream `BidInput` struct places no length constraint on `SearcherSig`/`AuctioneerSig` (`hexutil.Bytes` accepts any byte length, including zero), and `ToBid` copies these fields verbatim into `BidData` without validation. [6](#0-5)  `SubmitBid` builds the `Bid` and forwards it straight to `api.a.bidPool.AddBid(bid)`. [7](#0-6)  `AddBid` is expected to invoke the signature validators (referenced in `kaiax/auction/impl/bid_pool.go`, which I could not fully inspect within tool budget) before/while admitting the bid into the pool that later participates in block assembly.

### Impact Explanation
A single unprivileged auction bidder can trigger an out-of-bounds slice panic during bid submission simply by sending a malformed/short `searcherSig` or `auctioneerSig`. Because bid validation is on the path used to admit bids that are later consumed during proposer block assembly (the auction bid pool feeds block building), an unrecovered panic in this code path can disrupt bid processing/admission for that request or, if not isolated by the RPC layer's panic recovery, destabilize the goroutine handling bid intake, degrading the reliability of the auction/MEV bidding pipeline used for fee/priority-ordering of transactions. This is a memory-safety defect (uncontrolled buffer indexing) directly reachable by an external, unauthenticated auction bidder without any privileged access.

### Likelihood Explanation
High likelihood: `auction_submitBid` is a public, unauthenticated-facing API intended to accept third-party bids, and `SearcherSig`/`AuctioneerSig` are raw hex byte arrays with no server-side minimum-length check anywhere between the RPC boundary (`BidInput`) and the vulnerable indexing in `getSigner`. Triggering the bug requires only one RPC call with a short/empty signature field — no special timing, race, or validator collusion needed. I was unable to fully confirm (within the available tool budget) whether the outer JSON-RPC dispatcher in `networks/rpc/handler.go` recovers panics per-request (it does reference `recover()`), which would limit the blast radius to a single failed request; if bid admission is also exercised outside of the RPC-server's recover wrapper (e.g., directly from `bidPool` internals during block-building), the crash could propagate further. This should be verified directly in the codebase.

### Recommendation
In `getSigner` (kaiax/auction/bid.go), validate `len(sig) == crypto.SignatureLength` (65 bytes) before any indexing, and return `ErrInvalidSignature` otherwise, mirroring the length checks already present in `crypto.VerifySignature`/`decodeSignature`. Additionally, add an explicit length check on `BidInput.SearcherSig` / `BidInput.AuctioneerSig` at the RPC boundary (`ToBid` or `SubmitBid`) to reject malformed bids before they reach signature validation.

### Proof of Concept
1. Call the `auction_submitBid` RPC with a well-formed `targetTxRaw`/`targetTxHash`, but set `searcherSig` (or `auctioneerSig`) to `"0x"` (empty) or any byte string shorter than 65 bytes.
2. `SubmitBid` decodes and forwards the target tx, then calls `ToBid(bidInput)` and `api.a.bidPool.AddBid(bid)`. [7](#0-6) 
3. Bid validation eventually calls `getSigner(b.SearcherSig, digest)` (or `getSigner(b.AuctioneerSig, digest)`), which executes `copiedSig[crypto.RecoveryIDOffset]` on the short/empty slice, causing a Go runtime `index out of range` panic. [5](#0-4)

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

func ToBid(bidInput BidInput) *auction.Bid {

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
