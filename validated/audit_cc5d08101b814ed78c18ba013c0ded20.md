### Title
Unbounded length-prefix walk in `is_atom_canonical`/`is_clvm_canonical` allows attacker-crafted spend bundle to raise an unhandled `IndexError` during mempool admission - (File: chia/full_node/mempool_manager.py)

### Summary
`MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical()` on every submitted coin spend's `puzzle_reveal` and `solution` bytes before any other structural validation of that atom's length prefix bytes. `is_clvm_canonical()` and its helper `is_atom_canonical()` walk the raw CLVM byte buffer using an attacker-controlled multi-byte length prefix, but never verify that the buffer actually contains enough bytes to satisfy that prefix before indexing into it, and never verify that the "atom length" advance stays within the buffer before the next loop iteration indexes again.

### Finding Description
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` (lines 144-183) decodes a CLVM atom-length prefix directly from `clvm_buffer[offset]`: [1](#0-0) 

For encodings with `prefix_len` of 1-5 (`0xC0`, `0xE0`, `0xF0`, `0xF8`, `0xFC` leading nibble patterns), the function loops `prefix_len` times doing:
```python
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
There is no check anywhere in this function, nor in its caller `is_clvm_canonical()` (lines 186-227), that `offset + prefix_len < len(clvm_buffer)` before this loop dereferences `clvm_buffer[offset]`. If the submitted bytes end right after the leading prefix byte (e.g. a 6-byte length-prefix byte `0xFC` with no trailing length bytes, or a truncated multi-byte length field), `clvm_buffer[offset]` raises a plain Python `IndexError`.

Separately, once `atom_len` is decoded (which can be an attacker-chosen huge value up to `2**40`-ish), `is_clvm_canonical()` does `offset += atom_len` and loops back to `b = clvm_buffer[offset]` (line 199) with no bounds check on `offset` before that read either — so even a "successfully" decoded length can walk `offset` far past the end of the buffer and again raise `IndexError` on the next iteration.

This call path is directly reachable by an unprivileged spend-bundle submitter: `MempoolManager.validate_spend_bundle()` invokes `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` unconditionally for every coin spend in every incoming spend bundle, before checking canonical-CLVM-only concerns like fast-forward/dedup eligibility: [2](#0-1) 

Unlike the parallel Rust/CLVM-level validators (`validate_clvm_and_signature`) and the streaming parsers in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`) which explicitly raise a caught `ValueError` on truncated/oversized length fields, this Python helper performs no such bounds validation and instead lets a raw `IndexError` escape.

This bug class is directly analogous to the dnsmasq CVE: `rfc1035.c:extract_name()` lacked length checks on a length-prefixed field before it was consumed downstream in `get_rdata()`, causing memory corruption/crash. Here, `is_atom_canonical()`/`is_clvm_canonical()` lack length checks on an attacker-controlled length-prefixed CLVM atom before consuming it via direct indexing, causing an unhandled exception instead of memory corruption (Python bounds-checks memory itself), but with the same "malformed length field crashes an availability-critical code path" root cause.

### Impact Explanation
If the `IndexError` is not caught anywhere between `is_clvm_canonical()` and the outer request-handling code that invokes `MempoolManager.validate_spend_bundle()` (e.g. `add_spend_bundle()` / the WebSocket `respond_transaction`/`new_transaction` full-node handlers), a single crafted spend bundle can throw an unhandled exception in the transaction-processing pipeline. Depending on how the calling coroutine/task is supervised, this can manifest as a per-request failure (low impact) or, if it escapes the task without being awaited/handled, an unhandled exception that disrupts the mempool manager's admission processing for that spend bundle — a spend-triggered transaction-processing halt matching the categories explicitly in scope for this analog (mempool admission, spend-triggered halt).

I was not able to fully confirm, within the available tooling, whether every caller of `validate_spend_bundle()`/`add_spend_bundle()` wraps it in a broad `try/except Exception` (the full_node.py caller context that processes `respond_transaction`/`new_transaction` was only partially inspected before the tool budget ran out). This is a real gap: if such wrapping exists, the impact is reduced to a rejected single transaction rather than a broader halt. This should be verified directly against `chia/full_node/full_node.py`'s transaction-handling coroutines and their exception-handling/task-supervision behavior.

### Likelihood Explanation
High likelihood of triggering the crash: constructing a `CoinSpend` with a `puzzle_reveal` or `solution` whose trailing bytes end with a truncated multi-byte CLVM atom length prefix (e.g., ending exactly on a `0xC0`–`0xFC` prefix byte, or with a length value that pushes `offset` past the buffer end) is trivial and fully attacker-controlled — no signatures or special permissions are needed to reach this code path, since `is_clvm_canonical()` runs unconditionally in `validate_spend_bundle()` before fee/signature/timelock checks for every submitted spend bundle.

### Recommendation
Add explicit remaining-length checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access in the prefix-decoding loop (mirroring the `if n > len(buf): raise ValueError(...)` pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`), and add a bounds check in `is_clvm_canonical()` before dereferencing `clvm_buffer[offset]` at the top of each loop iteration (both the pair-tag read and the post-atom-skip re-entry). Treat any out-of-bounds condition as "not canonical" (return `False`) rather than allowing an `IndexError` to propagate, and add a regression test with a buffer truncated mid-length-prefix and a buffer whose atom length decodes past the buffer end.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xFC introduces a 5-extra-byte (6 total) length prefix; buffer ends right after
# the prefix byte, with no length bytes and no atom payload at all.
truncated = bytes([0xFC])
is_clvm_canonical(truncated)  # raises IndexError instead of returning False

# A "successfully" decoded but attacker-chosen huge atom length walks `offset`
# far past the buffer end on the next loop iteration:
# 0xF8 = 5-byte prefix header; next 4 bytes = big length value; short buffer.
huge_len_truncated = bytes([0xF8, 0x07, 0xFF, 0xFF, 0xFF])
is_clvm_canonical(huge_len_truncated)  # also raises IndexError
```
Both inputs, if placed as the raw bytes of a submitted `CoinSpend.puzzle_reveal` or `CoinSpend.solution`, reach `is_clvm_canonical()` unconditionally inside `MempoolManager.validate_spend_bundle()` (chia/full_node/mempool_manager.py:723-726) and raise `IndexError` rather than being rejected as `Err.INVALID_COIN_SOLUTION`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
