Audit Report

## Title
Single unprivileged WebSocket client can exhaust the entire global RPC PubSub subscription pool, denying subscription service to all other clients - (File: `rpc/src/rpc_subscription_tracker.rs`)

## Summary
`SubscriptionControl::subscribe` in `rpc/src/rpc_subscription_tracker.rs` reserves a slot from a single shared, global `subscriber_count` counter bounded only by `max_active_subscriptions` (default `1_000_000`), with no per-connection, per-IP, or per-client quota anywhere in the pubsub stack. A single unprivileged WebSocket client can issue enough distinct-parameter `accountSubscribe`/`programSubscribe`/`logsSubscribe`/`signatureSubscribe` calls over one connection to consume the entire global budget, denying subscription service to every other client on the node.

## Finding Description
`rpc/src/rpc_pubsub_service.rs`'s `handle_connection` (lines 349-427) accepts any TCP client, builds one `RpcSolPubSubImpl` per connection wired to the shared `SubscriptionControl`, and dispatches every parsed JSON-RPC request straight into `RpcSolPubSubImpl::subscribe` (`rpc/src/rpc_pubsub.rs:380-393`), which calls `SubscriptionControl::subscribe` (`rpc/src/rpc_subscription_tracker.rs:219-230`). That function reserves a slot via `SubscriberCountGuard::try_reserve` (`rpc/src/rpc_subscription_tracker.rs:594-611`), which performs a single `fetch_update` against `control.subscriber_count` compared to `control.max_active_subscriptions` — a value shared across the whole node (`rpc/src/rpc_pubsub_service.rs:33`, and documented in `validator/src/commands/run/args/pub_sub_config.rs:81-90` as applying "across all connections"). There is no dimension of the check tied to connection identity, socket address, or client identity anywhere in `rpc/src/rpc_pubsub_service.rs`, `rpc/src/rpc_pubsub.rs`, or `rpc/src/rpc_subscription_tracker.rs` — confirmed by grepping for any per-connection/per-IP/rate-limit logic in `rpc/src/*.rs`, which returns no results. Because subscriptions are keyed by `SubscriptionParams` (pubkey, filters, encoding, commitment, etc.), a connection can trivially avoid dedup by varying parameters per call; the code comment and test at `rpc/src/rpc_subscription_tracker.rs:224-230` and `735-759` explicitly confirm each distinct-params subscribe consumes its own slot from the shared pool ("duplicate subscribes to the same params each consume their own slot"). Once the shared pool is saturated, every other client's subscribe attempts fail with `Error::TooManySubscriptions`, mapped to a generic `InternalError` in `rpc_pubsub.rs:384-389`.

## Impact Explanation
This is a reachable RPC-service-denial condition: a single, unprivileged WebSocket client with only public inputs (valid but distinct pubkeys/filters) can deplete the shared subscription-slot pool and deny the PubSub subscription capability to every other client connected to the same node, without needing elevated privileges, a malicious peer/validator, or a race condition. This matches the "single-client low-rate RPC crash/degradation" / "non-RPC remote exhaustion" categories for the RPC/pubsub subsystem.

## Likelihood Explanation
The exploit requires only opening one WebSocket connection to the public RPC PubSub port and sending a sequence of ordinary, publicly documented subscribe calls with varied parameters — no authentication, no special access. The global counter (`subscriber_count`) monotonically increments as requests succeed and is never decremented until the corresponding `SubscriptionToken`/guard is dropped, so a client that simply holds its subscriptions open (never unsubscribing) can deterministically consume up to the full configured cap.

## Recommendation
Add a per-connection (and/or per-IP) subscription quota, strictly smaller than the global `max_active_subscriptions` cap, enforced either inside `SubscriptionControl::subscribe` (by threading a connection-scoped counter/context through the call) or in `handle_connection`/`RpcSolPubSubImpl` before delegating to `subscription_control.subscribe`. Consider also rate-limiting subscribe requests per connection.

## Proof of Concept
1. Run `agave-validator` with the default `--rpc-pubsub-max-active-subscriptions` (1,000,000).
2. From a single unauthenticated WebSocket client connected to the pubsub port, loop sending `accountSubscribe` requests, each with a freshly generated distinct `Pubkey`, until a very large number of successful subscriptions accumulate (bounded practically only by the configured cap and connection throughput), and keep the tokens open (never unsubscribe).
3. From a second, independent client, attempt any subscribe call (e.g. `slotSubscribe`); once the shared pool is exhausted, this call fails with `Error::TooManySubscriptions` → `InternalError` ("Node subscription limit reached"), demonstrating denial of PubSub subscription service to a legitimate client caused entirely by one unthrottled client. // RAII guard for one subscriber slot. The slot is reserved atomically against
// the configured cap by `try_reserve` (returns `None` if the cap is reached)
// and released on drop. Intentionally not `Clone`: each holder must go through
// `try_reserve` so duplicates cannot bypass the cap.
struct SubscriberCountGuard(Arc<SubscriptionControlInner>);

impl SubscriberCountGuard {
    fn try_reserve(control: &Arc<SubscriptionControlInner>) -> Option<Self> {
        let max = control.max_active_subscriptions;
        control
            .subscriber_count
            .fetch_update(Ordering::Relaxed, Ordering::Relaxed, |current| {
                (current < max).then_some(current + 1)
            })
            .ok()?;
        Some(Self(Arc::clone(control)))
    }
}

async fn handle_connection(
    socket: TcpStream,
    subscription_control: SubscriptionControl,
    config: PubSubConfig,
    mut tripwire: Tripwire,
) -> Result<(), Error> {
    let mut server = Server::new(socket.compat());
    let request = server.receive_request().await?;
    let accept = server::Response::Accept {
        key: request.key(),
        protocol: None,
    };
    server.send_response(&accept).await?;
    let mut builder = server.into_builder();
    builder.set_max_message_size(4_096);
    builder.set_max_frame_size(4_096);
    let (mut sender, mut receiver) = builder.finish();

    let mut broadcast_receiver = subscription_control.broadcast_receiver();
    let mut data = Vec::new();
    let current_subscriptions = Arc::new(DashMap::new());

    let mut json_rpc_handler = IoHandler::new();
    let rpc_impl = RpcSolPubSubImpl::new(
        config,
        subscription_control,
        Arc::clone(&current_subscriptions),
    );
    json_rpc_handler.extend_with(rpc_impl.to_delegate());
    let broadcast_handler = BroadcastHandler::new(current_subscriptions);
    loop {
        // Extra block for dropping `receive_future`.
        {
            // soketto is not cancel safe, so we have to introduce an inner loop to poll
            // `receive_data` to completion.
            let receive_future = receiver.receive_data(&mut data);
            pin!(receive_future);
            loop {
                select! {
                    biased; // See [prioritization] note below.

                    // [prioritization]
                    // This block must come FIRST in the `select!` macro. This prioritizes
                    // processing received messages over sending messages. This ensures the timely
                    // processing of new subscriptions and time-sensitive opcodes like `PING`.
                    result = &mut receive_future => match result {
                        Ok(_) => break,
                        Err(soketto::connection::Error::Closed) => return Ok(()),
                        Err(err) => return Err(err.into()),
                    },
                    result = broadcast_receiver.recv() => {

                        // In both possible error cases (closed or lagged) we disconnect the client.
                        if let Some(json) = broadcast_handler.handle(result?)? {
                            sender.send_text(&*json).await?;
                        }
                    },
                    _ = &mut tripwire => {
                        warn!("disconnecting websocket client: shutting down");
                        return Ok(())
                    },

                }
            }
        }
        let Ok(data_str) = str::from_utf8(&data) else {
            // Old implementation just closes the connection, so we preserve that behavior
            // for now. It would be more correct to respond with an error.
            break;
        };

        if let Some(response) = json_rpc_handler.handle_request(data_str).await {
            sender.send_text(&response).await?;
        }
        data.clear();
    }

    Ok(())
}
