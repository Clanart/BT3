### Title
Payout attribution (operator credited for reimbursement) is not bound to who actually funds the payout tx - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The withdrawal/payout transaction that fronts a Citrea withdrawal contains an `OP_RETURN` output declaring which operator's x-only pubkey should be credited/reimbursed for having fronted the peg-out. This attribution output is not covered by the user's withdrawal signature (which uses `SinglePlusAnyoneCanPay`), so anyone who observes the user-signed input in the mempool can complete an alternative, still-valid version of the payout transaction with a *different* `OP_RETURN` operator attribution than the party who actually supplies the fronting funds. The protocol later trusts this on-chain `OP_RETURN` value as ground truth for who gets reimbursed from the vault, without validating that the credited operator's own funds paid for the withdrawal.

### Finding Description
`create_payout_txhandler` builds the payout tx with:
- Input 0: the user's withdrawal UTXO, signed by the user with `SinglePlusAnyoneCanPay`.
- Output 0: the payout to the withdrawing user (the only output covered by the user's `SIGHASH_SINGLE` commitment).
- Output 2: an `OP_RETURN` containing `operator_xonly_pk`, the identity that will later be credited as the "payer" for reimbursement purposes. [1](#0-0) 

Because the sighash type is `SIGHASH_SINGLE | ANYONECANPAY`, the user's signature only commits to input 0 and the output at the same index (output 0). It does **not** commit to any additional funding inputs or to the `OP_RETURN` output. This is by design so that whichever party fronts the withdrawal can freely add its own funding inputs (via `fund_raw_transaction`/RBF) in `Operator::withdraw`: [2](#0-1) [3](#0-2) 

Once a first version of this transaction is broadcast (visible unconfirmed in the mempool), any party can build a *competing/replacement* transaction that keeps input 0 and the required output 0 unchanged (satisfying the user's `SIGHASH_SINGLE|ANYONECANPAY` signature) but substitutes different funding inputs and an arbitrary `operator_xonly_pk` in the `OP_RETURN`. Nothing cryptographically binds the `OP_RETURN` payer identity to the party whose inputs actually fund the transaction.

The block syncer later reads this unauthenticated `OP_RETURN` value directly from the confirmed transaction as the sole source of truth for attribution: [4](#0-3) 

This value is persisted and used to unlock the entire reimbursement pipeline for whichever operator's key appears there: [5](#0-4) [6](#0-5) 

Crucially, when a kickoff is later evaluated to determine whether an operator maliciously claimed a reimbursement, the only check performed is that the operator sending the kickoff matches the `OP_RETURN`-derived attribution in the DB — there is no check that this operator's own funds actually paid for the withdrawal: [7](#0-6) 

This is the same class of defect as the referenced `LineOfCredit.addCredit`/`LineLib.receiveTokenOrETH` bug: a `sender`/`payer` identity is passed and later trusted for accounting purposes without verifying it matches the party that actually contributed the value.

### Impact Explanation
This breaks the "operator credited == operator that actually funded/paid" binding. An operator (or anyone colluding with/framing an operator) can end up credited via `payout_payer_operator_xonly_pk` for a withdrawal that was, in the confirmed on-chain transaction, actually funded by different inputs than expected/assumed by that operator's own accounting, then proceed through `validate_payer_is_operator` → kickoff → `create_reimburse_txhandler` to withdraw real BTC from the deposit's `MoveToVault` UTXO: [8](#0-7) [9](#0-8) 

Since the malicious-kickoff check (`is_kickoff_malicious`) only cross-checks the `OP_RETURN` value against the kickoff sender and never re-derives the actual funding source of the confirmed payout tx, an operator can be reimbursed for a payout it never truly fronted with its own collateral/wallet — matching the Critical impact category "an operator reimbursed for a payout it never funded."

### Likelihood Explanation
Exploitation requires observing an unconfirmed payout transaction in the mempool (public, unprivileged information) and constructing/broadcasting an RBF replacement with a higher fee before the original confirms, while still satisfying the user's `SIGHASH_SINGLE|ANYONECANPAY` commitment on input 0/output 0. This requires real BTC to fund the replacement (so it is not free), which limits large-scale exploitation to specific griefing/self-serving scenarios, but the underlying binding is nonetheless unauthenticated and can be forced by any party willing to spend funds to win the race.

### Recommendation
Do not rely solely on an unauthenticated `OP_RETURN` output for payer/operator attribution. Either:
- Require the `OP_RETURN` (or an equivalent operator-attribution commitment) to be covered by a signature from the credited operator itself (proving consent/ownership of the claim), or
- Additionally verify, at `is_kickoff_malicious`/reimbursement-validation time, that the actual funding inputs of the confirmed payout transaction are attributable to the operator being credited (e.g., inputs originate from that operator's known wallet/collateral outputs), rather than trusting the `OP_RETURN` value alone.

### Proof of Concept
1. Operator A (or any bystander) constructs and broadcasts a payout tx for withdrawal W: input 0 = user's `SinglePlusAnyoneCanPay`-signed withdrawal UTXO, output 0 = required user payout, `OP_RETURN` = A's xonly pubkey, extra funding input = A's wallet UTXO. [10](#0-9) 
2. Before confirmation, an unprivileged party observes this transaction in the mempool and builds a replacement tx keeping input 0 and output 0 identical (satisfying the user's signature), but with a different `OP_RETURN` (attributing operator B) and different (their own) funding input, broadcast with a higher fee to win the RBF race.
3. The replacement confirms. The block syncer parses the `OP_RETURN`, unconditionally trusting it as `payout_payer_operator_xonly_pk = B`. [11](#0-10) 
4. Operator B's automated `PayoutCheckerTask` picks up this "unhandled payout" attributed to B and drives it through the kickoff/reimbursement flow; `is_kickoff_malicious` only checks that B's kickoff matches the DB-recorded `OP_RETURN` attribution and does not verify B funded the payout. [12](#0-11) [13](#0-12) 
5. Operator B is reimbursed from the deposit's `MoveToVault` UTXO for a withdrawal it did not actually front with its own funds.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
