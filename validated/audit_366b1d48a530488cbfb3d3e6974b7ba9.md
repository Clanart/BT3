## Finding: `aptos move verify-package` never checks actual on-chain bytecode against the local build

### Title
`VerifyPackage`/`CachedPackageRegistry::verify` compares only package metadata, not the actually deployed module bytecode - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
`aptos move verify-package` is documented as a tool that "checks that on-chain bytecode matches a local source tree" [1](#0-0) . In practice, the `VerifyPackage::execute` command fetches only the `PackageRegistry` resource (metadata) via `CachedPackageRegistry::create(client, self.account, false)` — note `with_bytecode=false` — and calls `package.verify(&compiled_metadata)` [2](#0-1) .

### Finding Description
`CachedPackageMetadata::verify` compares only `name`, `deps`, `modules` (which is `ModuleMetadata { name, source, source_map, extension }` — not compiled bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest` fields between the locally-built metadata and the on-chain `PackageMetadata` resource [3](#0-2) . None of these fields is the actual serialized bytecode that is stored as a `0x1::code` module at the given address; `ModuleMetadata.source`/`source_map` are optional, gzip-compressed **source text** and source maps supplied at publish time, not compiled bytes [4](#0-3) .

`CachedPackageRegistry::create` has a `with_bytecode: bool` parameter that, when `true`, downloads each module's actual bytecode via `client.get_account_module(...)` into a separate `bytecode: BTreeMap<String, Vec<u8>>` map, exposed only through `get_bytecode()` [5](#0-4) . The `verify()` function never touches this `bytecode` map, and `VerifyPackage::execute` always calls `create(..., false)`, so the bytecode is never even downloaded during verification [2](#0-1) .

`source_digest` is a hash of the **source files** (per `code.move`'s doc comment: "sha256 of each individual source... sorted alphabetically, sha256 again") [6](#0-5) , computed from local `.move` source and `Move.toml` files via `compute_digest` [7](#0-6) . This digest is derived and compared *client-side* purely from files the caller controls, and it does not bind to the specific bytecode published on-chain. Nothing in `publish_package` (`code.move`) enforces at publish time that the bytecode's contents match the declared `source_digest`, `manifest`, or `ModuleMetadata.source` fields — these are supplied by the publisher and only self-consistency-checked in `PackageMetadata` (name uniqueness, dependency policy, upgrade policy) at `publish_package` [8](#0-7) .

### Impact Explanation
An account/object owner (or anyone else who controls what gets published, e.g. through a compromised build pipeline or intentionally) can publish a package whose metadata (`manifest`, `source`, `source_digest`) legitimately describes one set of Move sources, while the **actual compiled bytecode bundle** submitted in the same transaction (the `code: vector<vector<u8>>` argument to `publish_package`) differs arbitrarily from what that metadata implies, as long as `expected_modules` names match and (if dependency check is enabled) declared dependencies are honored at the bytecode level. A downstream user relying on `aptos move verify-package` to confirm "the on-chain bytecode matches this source" would get a false "Successfully verified source of package" result, because the tool never fetches or compares actual bytecode. This directly matches the Publish Impact Gate's "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes" category, and could mislead auditors/users about code provenance for real deployed contracts.

### Likelihood Explanation
This is not a Move-runtime vulnerability that can be exploited to corrupt chain state, freeze/upgrade authority, or bypass on-chain publish invariants — the on-chain `code::publish_package` logic itself remains correctly gated by ownership and upgrade-policy checks I reviewed (`object::is_owner`, `can_change_upgrade_policy_to`, `check_dependencies`, native `validate_publish_request` cross-checking `immediate_dependencies` against `allowed_deps`) [9](#0-8) [10](#0-9) . This is purely a CLI tooling gap: `aptos move verify-package` silently under-delivers on its documented guarantee. Likelihood of the gap being hit is high (every user of `verify-package` is affected), but severity is limited to false assurance/social trust rather than a direct on-chain compromise, since the module verifier/loader still validates bytecode independently at actual publish/execution time.

### Recommendation
- In `VerifyPackage::execute`, call `CachedPackageRegistry::create(client, self.account, true)` to fetch actual bytecode, and extend `CachedPackageMetadata::verify` (or add a new check) to compare each module's downloaded bytecode (`get_bytecode`) against the locally compiled bytecode (`pack.extract_code()`), not merely metadata fields.
- Update the tool's help text/docs to accurately state current limitations until bytecode comparison is added, since `third_party/move/documentation/book/src/cli-deploy.md` currently overstates the guarantee.

### Proof of Concept
1. Compile package `P` locally with sources `S1`, extract metadata `M1` (`manifest`, `source_digest` computed from `S1`, `modules` referencing `S1`'s source text).
2. Craft a bytecode bundle `B2` for modules with the same names/signatures as declared in `M1`'s `modules`, but with materially different logic/bytecode (still passing bytecode verifier/compatibility rules), and publish `(M1, B2)` via `code::publish_package_txn`. `publish_package` only checks module name-set equality (`expected_modules`) and (if enabled) dependency policy; it does not check that `B2`'s actual instructions correspond to `M1.modules[i].source` [11](#0-10) .
3. Run `aptos move verify-package --account <addr>` from a checkout of the original sources `S1`. Because `verify()` only compares `name`, `deps`, `modules` metadata, `manifest`, `upgrade_policy`, `extension`, `source_digest` — all of which still match `M1` — the command prints `"Successfully verified source of package"` [12](#0-11) , despite the deployed bytecode `B2` not actually matching source `S1`.

Note: I was not able to fully verify from the available index whether any other Aptos SDK/tooling paths (outside this CLI command) perform a genuine bytecode-diff check as a substitute safeguard; if such a check exists elsewhere it would reduce real-world impact, and should be confirmed with a full checkout via a Devin session.

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    /// Returns the list of packages in this registry by name.
    pub fn package_names(&self) -> Vec<&str> {
        self.inner
            .packages
            .iter()
            .map(|p| p.name.as_str())
            .collect()
    }

    /// Finds the metadata for the given module in the registry by its unique name.
    pub async fn get_module(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedModuleMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            for module in &package.modules {
                if module.name == name {
                    return Ok(CachedModuleMetadata { metadata: module });
                }
            }
        }
        bail!("module `{}` not found", name)
    }

    /// Finds the metadata for the given package in the registry by its unique name.
    pub async fn get_package(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedPackageMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            if package.name == name {
                return Ok(CachedPackageMetadata { metadata: package });
            }
        }
        bail!("package `{}` not found", name)
    }

    /// Gets the bytecode associated with the module.
    pub async fn get_bytecode(
        &self,
        module_name: impl AsRef<str>,
    ) -> anyhow::Result<Option<&[u8]>> {
        Ok(self
            .bytecode
            .get(module_name.as_ref())
            .map(|v| v.as_slice()))
    }
}

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

use crate::source_package::{layout::SourcePackageLayout, parsed_manifest::PackageDigest};
use anyhow::Result;
use move_command_line_common::files::MOVE_EXTENSION;
use sha2::{Digest, Sha256};
use std::path::{Path, PathBuf};

pub fn compute_digest(paths: &[PathBuf]) -> Result<PackageDigest> {
    let mut hashed_files = Vec::new();
    let mut hash = |path: &Path| {
        let contents = std::fs::read(path)?;
        hashed_files.push(format!("{:X}", Sha256::digest(&contents)));
        Ok(())
    };
    let mut maybe_hash_file = |path: &Path| -> Result<()> {
        match path.extension() {
            Some(x) if MOVE_EXTENSION == x => hash(path),
            _ if path.ends_with(SourcePackageLayout::Manifest.path()) => hash(path),
            _ => Ok(()),
        }
    };

    for path in paths {
        if path.is_file() {
            maybe_hash_file(path)?;
        } else {
            for entry in walkdir::WalkDir::new(path)
                .follow_links(true)
                .into_iter()
                .filter_map(|e| e.ok())
            {
                if entry.file_type().is_file() {
                    maybe_hash_file(entry.path())?
                }
            }
        }
    }

    // Sort the hashed files to ensure that the order of files is always stable
    hashed_files.sort();

    let mut hasher = Sha256::new();
    for file_hash in hashed_files.into_iter() {
        hasher.update(file_hash.as_bytes());
    }

    Ok(PackageDigest::from(format!("{:X}", hasher.finalize())))
}
