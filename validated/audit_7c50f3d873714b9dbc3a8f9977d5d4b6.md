The Tautulli CVE describes an unsanitized `callback` query parameter used for JSONP responses, allowing an attacker-controlled script name to be reflected back and executed cross-origin, enabling API key theft. I searched the sei-chain codebase for any JSONP-style callback parameter handling in the EVM JSON-RPC server, the Tendermint/CometBFT JSON-RPC server, and the Cosmos API server, and found none. The RPC surfaces here use standard JSON-RPC over HTTP/WebSocket [1](#0-0)  and URI-based GET handlers with typed parameter parsing [2](#0-1) , with cross-origin access controlled purely through the standard `cors` middleware (allow-list based `Access-Control-Allow-Origin`, not reflected script injection) [3](#0-2) [4](#0-3) [5](#0-4) . There is no code path anywhere in the EVM JSON-RPC surface, the Cosmos gRPC-gateway API server, or the CometBFT RPC server that generates a JSONP-wrapped response using a client-supplied `callback` parameter, so this bug class does not map onto any reachable transaction, contract-call, wasm-message, or RPC-request path in sei-chain.
