### Title
Forged `ReceivedOutput` value via `ReceivedOutput::read` causes signed transactions to burn funds as fees — the accounted balance is not the spendable balance - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput` bundles an `offset`, a `TxOut`, and an `OutPoint`, and `ReceivedOutput::read` deserializes all three from untrusted bytes without any validation against the chain. `SignableTransaction::new` then trusts `input.output.value` as the input amount for fee/change accounting, and `TransactionSignMachine::sign` commits to those attacker-controlled `TxOut`s via `Prevouts::All`. `SignableTransaction::multisig` only checks that the prevout's `script_pubkey` equals `p2tr_script_buf(key + offset)` — it never verifies the `outpoint` exists or that the real on-chain output carries the claimed `value`. An untrusted byte string can therefore encode a value that does not match the spendable value of the UTXO, mirroring the "accounted balance not equal to distributable balance" class of the external report. ### Finding Description
- `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) accepts an arbitrary scalar offset, an arbitrary `TxOut` (value + script_pubkey), and an arbitrary `OutPoint`. No check ties them together or to chain state.
- `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:150-256`) sums `input.output.value` into `input_sat` (line 175), validates payments/fee/change against that claimed total, and stores the claimed `TxOut`s as `prevouts` (line 253).
- `SignableTransaction::multisig` (`send.rs:273-285`) verifies only `p2tr_script_buf(keys.offset(offset).group_key()) == prevouts[i].script_pubkey`. The `value` and `outpoint` are unchecked.
- `TransactionSignMachine::sign` (`send.rs:373-397`) produces real FROST Schnorr signatures over `taproot_key_spend_signature_hash(i, Prevouts::All(&prevouts), Default)`, binding the forged amounts into a validly signed transaction.

Consequences by forged value relative to the real UTXO:
- **Understated value**: the transaction remains valid (real inputs exceed declared outputs), and the discrepancy `real − claimed` is silently paid to miners as excess fee. Funds accounted as spendable are burned — the precise analog of tokens counted in share price but not distributable.
- **Overstated value**: the signed transaction is invalid (`input_sat` was checked against the forged total), permanently wasting a signing round and any real co-inputs' scheduling.

### Impact Explanation
An unprivileged party who can feed serialized `ReceivedOutput`s into the signing path (the rules explicitly designate `ReceivedOutput::read` as an untrusted-bytes sink) can cause the threshold wallet to produce and sign a transaction that permanently burns arbitrary amounts of vault-controlled BTC as miner fees, or emit permanently-invalid transactions. The forged value is committed into the BIP-341 sighash, so the resulting signature is genuine and the burn is irreversible once broadcast. Impact: Medium (irrecoverable fund loss bounded by the forged delta; no key compromise).

### Likelihood Explanation
Likelihood: Medium–High. Exploitation requires only that attacker-controlled bytes reach `ReceivedOutput::read` and be scheduled into a `SignableTransaction`; no collusion, no honest-signer misbehavior, and no exotic primitives are needed. The only constraint is selecting an `outpoint` and `offset` whose script matches — `offset = Scalar::ZERO` with the vault's own `p2tr_script_buf` script satisfies `multisig` trivially.

### Recommendation
When constructing or deserializing a `ReceivedOutput`, authenticate the `OutPoint`/`TxOut` pair against chain state (fetch the prevout and compare `value` and `script_pubkey`) before it reaches `SignableTransaction::new`. At minimum, `SignableTransaction::multisig` should reject outputs whose `outpoint` cannot be resolved, and `ReceivedOutput::read` consumers should treat `output.value` as untrusted until confirmed. The binding could also be tightened by committing each input's expected value into the message the signer is shown.

### Proof of Concept
```rust
// Attacker crafts bytes for a real vault outpoint but a lower claimed value.
let real_vault_outpoint: OutPoint = /* an unspent UTXO paying to the vault key */;
let real_value: u64 = 100_000;

let forged = ReceivedOutput {
    offset: Scalar::ZERO,                                  // passes multisig() script check
    output: TxOut {
        value: Amount::from_sat(real_value - 10_000),      // understated by 10k sats
        script_pubkey: p2tr_script_buf(vault_key).unwrap(),// matches key + ZERO offset
    },
    outpoint: real_vault_outpoint,
};
let bytes = forged.serialize();

// Victim side: bytes are read via the public untrusted API.
let ro = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// Accounted input = 90_000; tx is built and signed normally.
let tx = SignableTransaction::new(vec![ro], &payments, change, None, fee_rate).unwrap();
let signed = sign(&keys, &tx); // valid: real input is 100_000

// signed.broadcast() succeeds; the 10_000-sat discrepancy is paid to miners.
assert_eq!(signed.input_value_onchain() - signed.output_sum(), needed_fee + 10_000);
```

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
