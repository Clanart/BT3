## Title
Attacker-controlled `WWW-Authenticate` header spoofs GitHub Enterprise identity and triggers an unverified OAuth sign-in flow against the attacker's own host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The credential-helper trampoline classifies an arbitrary git remote as a "GitHub"/"enterprise" endpoint purely by pattern-matching the `WWW-Authenticate` HTTP header the *remote server itself* returns, with no independent verification that the host is actually a GitHub product. Because that classification directly gates whether Desktop pops the "Sign in to your GitHub Enterprise instance" OAuth flow (scoped to the attacker's origin), a malicious or compromised git remote/proxy can force this trusted UI to appear for a host it fully controls.

### Finding Description
`getEndpointKind()` first checks legitimate, verifiable signals (`isGist`, `isDotCom`, `isGHE`, a known account, or an actual reachability probe via `isGitHubHost`). But before any of those fallbacks, it short-circuits on a value supplied entirely by the remote peer: [1](#0-0) 

The comment itself acknowledges the header is attacker-reachable: *"When Git attempts to authenticate with a host it captures any WWW-Authenticate headers and forwards them to the credential helper."* This value comes verbatim from the HTTP response of whatever server the git operation is talking to — there is no TLS-pinning, no independent call to `/api/v3` or GitHub's meta endpoint, no cross-check against `getHTMLURL`/known GitHub infrastructure. It is a pure string match on attacker-controlled response data (`realm="GitHub"`).

That classification feeds directly into `getCredential()`: [2](#0-1) 

When `endpointKind !== 'generic'` and there's no existing matching account, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which opens the real GitHub Enterprise sign-in dialog scoped to the attacker's origin: [3](#0-2) 

`beginEnterpriseSignIn` + `setSignInEndpoint(origin)` drive the standard enterprise OAuth flow (`getOAuthAuthorizationURL`/`requestOAuthToken`/`fetchUser`), all targeted at the attacker's `endpoint`: [4](#0-3) [5](#0-4) 

The broken invariant mirrors the seed report: a privileged trust decision (is this endpoint really "GitHub", eligible to trigger the trusted sign-in/OAuth UI and later auto-fill credentials) is derived from attacker-supplied data (`owner` param in the seed; `WWW-Authenticate` header here) instead of a verified, authoritative source (`msg.sender` in the seed; an actual reachability/identity check like `isGitHubHost` here, which exists in the code but is only reached *after* the spoofable header check).

### Impact Explanation
Once the sign-in dialog is shown and the user completes it, `fetchUser(endpoint, token)` is called against the attacker's own host, and the resulting `Account` (login/avatar/token, all attacker-supplied) is persisted via `AccountsStore`, `credWithAccount` binding it into future credential fills for that origin. This is a form of unauthorized/forged GitHub account binding driven entirely by remote-controlled response data — the user is shown Desktop's legitimate "Sign in to your GitHub Enterprise instance" chrome for a host that never proved it's GitHub, and the OAuth browser hand-off (`requestOAuthToken`) goes to attacker infrastructure. This can be leveraged for credential-harvesting style phishing using Desktop's own trusted native dialog as cover, and it corrupts the account/credential store used for subsequent `git` operations against that origin.

### Likelihood Explanation
Exploitation only requires the victim to perform a normal HTTPS git operation (clone/fetch/push) against an attacker-controlled or attacker-MITM'd remote (e.g. a malicious fork's submodule URL, a "clone in Desktop" style link pointing at a self-hosted git server, or a compromised/malicious proxy in front of a legitimate-looking git host) that responds with a 401 and a crafted `WWW-Authenticate: Basic realm="GitHub"` header. No local access, admin rights, or pre-existing malware is required — this is exactly the "attacker controls...a git remote/proxy response" class explicitly in scope.

### Recommendation
Do not trust the `wwwauth[]` header content to classify a host as GitHub/enterprise. Only treat an endpoint as 'enterprise'/'github.com' when: (1) it matches `isDotCom`/`isGHE`, (2) it matches an already-registered account, or (3) an authoritative check like `isGitHubHost(endpoint)` (the same check that already exists later in the function) succeeds. Remove or de-prioritize the `wwwauth[]` heuristic entirely, or at minimum require it to be corroborated by `isGitHubHost` before it can promote an unknown endpoint to a status that triggers the sign-in/OAuth UI.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://evil.example.com/repo.git` (or MITMs a proxy for it) that, on any authenticated request, returns `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds/clones this remote in GitHub Desktop and performs any fetch/push requiring auth.
3. Git invokes Desktop's credential helper `get` command with the captured `wwwauth[...]` header forwarded as-is.
4. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'` for `evil.example.com`, despite it never being verified as GitHub (`isGHE`/`isGitHubHost` never run).
5. `getCredential()` finds no existing account for that endpoint and calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which pops the native "Sign in to your GitHub Enterprise instance" dialog scoped to `evil.example.com` and drives the OAuth authorize/token/fetchUser calls to that attacker-controlled host. async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async resolveOAuthRequest(action: IOAuthAction) {
    if (!this.state || this.state.kind !== SignInStep.Authentication) {
      return
    }

    if (!this.state.oauthState) {
      return
    }

    if (this.state.oauthState.state !== action.state) {
      log.warn(
        'requestAuthenticatedUser was not called with valid OAuth state. This is likely due to a browser reloading the callback URL. Contact GitHub Support if you believe this is an error'
      )
      return
    }

    const { endpoint } = this.state
    const token = await requestOAuthToken(endpoint, action.code)

    if (token) {
      const account = await fetchUser(endpoint, token)
      this.state.oauthState.onAuthCompleted(account)
    } else {
      this.state.oauthState.onAuthError(
        new Error('Failed retrieving authenticated user')
      )
    }
  }
