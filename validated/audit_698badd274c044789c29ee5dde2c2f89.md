### Title
Scanner reports immature coinbase outputs as spendable `ReceivedOutput`s, causing funds to be reported received that are not spendable - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The original finding's bug class is an entitlement/action being irrevocably consumed (merkle proof marked used) based on a transaction that cannot actually complete, leaving the user stuck with an unusable asset. In Serai, the analogous shape is `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs`, which reports received outputs purely by `script_pubkey` match, with no check for whether the output is actually spendable. Because it iterates `block.txdata` including `txdata[0]` (the coinbase), a coinbase output paying to a scanned key is emitted as a normal `ReceivedOutput` even though the Bitcoin consensus rules forbid spending it for 100 blocks.

### Finding Description
`scan_transaction` iterates every output of a transaction and pushes a `ReceivedOutput` whenever `output.script_pubkey` is in `self.scripts` — no validation of the containing transaction type: [1](#0-0) 

`scan_block` calls `scan_transaction` over *all* transactions, including the coinbase at `txdata[0]`: [2](#0-1) 

The only guard is a doc comment noting coinbase outputs "are bound by maturity" and that callers "must" do a post-processing pass — but nothing in the API enforces this, and `ReceivedOutput` carries no maturity/`is_coinbase` flag to let downstream code distinguish it. The `Output`/`OutputTrait` wrapper in `processor/src/networks/bitcoin.rs` also derives `id()` purely from the outpoint and `balance()` from value, so an immature coinbase output is indistinguishable from a confirmed, spendable one once scanned: [3](#0-2) 

### Impact Explanation
An unprivileged miner (or anyone mining a block, e.g. via a pool payout to a Serai address) can craft a coinbase transaction paying to a registered Serai P2TR script. `scan_block` then emits a `ReceivedOutput` that the multisig processor treats as spendable balance. The output cannot be spent for 100 blocks: any `SignableTransaction`/witness spending it produces an invalid transaction rejected by consensus ("bad-txns-premature-spend-of-coinbase"). This matches the accepted impact class "funds reported received that are not spendable" — the protocol credits/handles value it cannot actually move, directly analogous to users being left holding a worthless deprecated asset after their one-shot proof was burned.

### Likelihood Explanation
Coinbase outputs to a watched script require winning a block, so the trigger is constrained, but pools routinely pay out to arbitrary addresses and a miner deliberately mining on regtest/testnet or cooperating with a pool can do this trivially. No cryptographic assumption or trusted-party compromise is needed — only a transaction the attacker causes to appear in a block, which is within the permitted threat model (Bitcoin transactions an unprivileged party causes).

### Recommendation
- Have `scan_transaction` (or a caller-visible variant) detect coinbase transactions (`tx.is_coinbase()`) and either skip them or annotate the resulting `ReceivedOutput` with a maturity flag/block height.
- Alternatively, in `scan_block`, skip `block.txdata[0]` or require `coinbase_maturity` before returning such outputs, rather than relying on every integrator performing a documented manual post-processing pass — the same "frontend will handle it" objection applies.

Existing test code already demonstrates exactly this scan path (`scan_block` over a block containing a coinbase paying the key) — it just additionally mines 100 blocks before use, masking the issue: [4](#0-3)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
