### Title
Unauthenticated `shop` request parameter used to select and authorize a stored offline session - ([File: app/controllers/concerns/shopify_app/ensure_installed.rb])

### Summary
`ShopifyApp::EnsureInstalled#current_shopify_domain` derives the "current" shop identity purely from the unauthenticated `params[:shop]` value, and `installed_shop_session` uses that value to look up and load a *different* shop's stored offline `ShopifyAPI::Auth::Session` from `SessionRepository`. That looked-up session (with its real access token) is then assigned to `@shop` and used to make authenticated Admin API calls, with no verification that the requester is actually the authenticated party for that shop (no session-token/HMAC check binding the request to the shop param). This mirrors the root cause of the reported bug class: a security-relevant decision is made from the wrong/unverified data source (request-supplied identity) instead of the verified one (an authenticated session/token), leading to cross-tenant confusion.

### Finding Description
`current_shopify_domain` in this concern is defined solely as the sanitized `params[:shop]`: [1](#0-0) 

This value — fully attacker-controlled and never verified against any session token, HMAC, or cookie — is then used directly as the lookup key for a previously-installed shop's stored offline session: [2](#0-1) 

`check_shop_known` assigns the result of that lookup to `@shop` whenever any prior installation exists for that domain, without any check that the current request is authenticated as belonging to that shop: [3](#0-2) 

`validate_non_embedded_session` then uses that session (which carries the victim shop's real offline access token) to perform a live Admin API call: [4](#0-3) 

This is the same bug class as the report: `borrowWithInterest()` used the wrong data source (`crossChainBorrows`, i.e., where debt *originated*) instead of the data actually representing debt *executed here* (`crossChainCollaterals`). Here, the shop identity used to select and authorize a session is taken from the untrusted request parameter (`params[:shop]`) rather than from a verified identity source (a validated session token / HMAC-signed callback), causing the wrong tenant's session/token to be used for the request in progress.

Note this concern is explicitly gated to the legacy (non-token-exchange) install flow: [5](#0-4) 
When `ShopifyApp.configuration.use_new_embedded_auth_strategy?` is false, no session-token verification (`TokenExchange`/`activate_shopify_session`) runs at all before `@shop` is derived purely from `params[:shop]`.

### Impact Explanation
Any anonymous or unrelated caller can supply `shop=<victim-shop>.myshopify.com` in the query string of a request to a controller that only includes `EnsureInstalled` (legacy flow). If that shop has previously installed the app, `installed_shop_session` will resolve and load the victim shop's real offline session/access token into `@shop`, and it will be used for outbound Admin API calls performed on behalf of "the current shop" within that controller action — a cross-shop/cross-tenant session confusion. Any app logic that trusts `@shop`/`installed_shop_session` to represent the actual caller (e.g., to read/write data, perform webhooks setup, or serve shop-specific content) can be tricked into acting on or disclosing another merchant's data using their own stored token, without the victim's involvement.

### Likelihood Explanation
This requires: (1) the host app to use the legacy `EnsureInstalled` concern rather than the modern token-exchange/`TokenExchange`+`EnsureHasSession` path (deprecated but still supported and documented), and (2) a target shop with an existing stored offline session. Given `EnsureInstalled` is a first-party, documented, still-supported concern shipped by the gem and requires no elevated privileges or secrets to trigger — just an HTTP GET with a `shop` query param — likelihood is moderate for apps still on the legacy flow.

### Recommendation
`current_shopify_domain`/`installed_shop_session` in `EnsureInstalled` should not treat `params[:shop]` as an authoritative identity for authorizing session use. Instead:
- Require and verify a signed context (HMAC on the request, or the OAuth-derived/verified session) before using any shop-derived session for outbound API calls, analogous to how `ShopifyApp::TokenExchange#reject_mismatched_requested_shopify_domain` cross-checks the unauthenticated `requested_shopify_domain` against the authenticated domain before permitting use.
- At minimum, gate `validate_non_embedded_session`'s use of `installed_shop_session` on a verified indicator (e.g., `loaded_directly_from_admin?` already covers the embedded case, but the non-embedded path should equally validate the request signature/HMAC before trusting `params[:shop]`).
- Migrate documentation/guidance to steer apps away from `EnsureInstalled` toward the token-exchange strategy, which already implements the requested-vs-authenticated domain check.

### Proof of Concept
1. App A is installed on `victim-shop.myshopify.com`, creating a stored offline `ShopifyApp::SessionRepository` entry for that domain.
2. An anonymous actor sends `GET /some_ensure_installed_controller_action?shop=victim-shop.myshopify.com` with no valid session cookie, no signed session token, and no HMAC.
3. `check_shop_domain` passes because `current_shopify_domain` returns the sanitized `params[:shop]` value: [6](#0-5) .
4. `check_shop_known` finds `installed_shop_session` for `victim-shop.myshopify.com` and assigns it to `@shop`: [3](#0-2) .
5. `validate_non_embedded_session` (or any controller action using `@shop`/`installed_shop_session`) performs Admin API calls using the victim shop's real access token on behalf of the unauthenticated caller's request: [4](#0-3) .

    def current_shopify_domain
      if params[:shop].blank?
        ShopifyApp::Logger.info("Could not identify installed store from current_shopify_domain")
        return
      end

      @shopify_domain ||= ShopifyApp::Utils.sanitize_shop_domain(params[:shop])
      ShopifyApp::Logger.info("Installed store:  #{@shopify_domain} - deduced from Shopify Admin params")
      @shopify_domain
    end

    def installed_shop_session
      @installed_shop_session ||= SessionRepository.retrieve_shop_session_by_shopify_domain(current_shopify_domain)
    end

    private

    def check_shop_domain
      redirect_to(ShopifyApp.configuration.login_url) unless current_shopify_domain
