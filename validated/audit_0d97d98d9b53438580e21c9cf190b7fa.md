### Title
Gasless mempool admission relies on the *declared* `amountIn`/`GetAmountIn` estimate instead of the tokens actually receivable, so a fee‑on‑transfer ERC‑20 whitelisted for gasless swaps breaks the proposer‑repayment guarantee - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`kaiax/gasless` implements KIP‑247 gasless transactions: a block proposer fronts gas to a user via a `LendTxGenerator` transaction, and the user repays the proposer by swapping a whitelisted ERC‑20 token for KAIA through `GaslessSwapRouter.swapForGas`. Mempool admission for the swap leg is validated by `checkBalanceForSwap`, which never accounts for tokens that deduct a transfer fee, mirroring exactly the "fee-on-transfer breaks accounting" bug class from the referenced report.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  validates a `GaslessSwapTx` purely from *declared* amounts and on-chain `balanceOf`/`allowance` snapshots:
- It computes `requiredAmountIn` via `routerContract.GetAmountIn(nil, token, minAmountOut)` — a quote based on reserves, not on how many tokens will actually leave the sender's balance after the token's own transfer-fee logic.
- It checks `swapArgs.AmountIn.Cmp(requiredAmountIn) < 0` and `balance.Cmp(swapArgs.AmountIn) < 0`, i.e., "sender owns/approved at least `amountIn` tokens," never "the router will actually receive `amountIn` tokens."

The token that is swapped is selected from `g.allowedTokens` [2](#0-1) , a governance/registry‑controlled allow‑list (`gasless.allowed-tokens` flag / `GaslessConfig.AllowedTokens`) [3](#0-2) . Nothing in the admission or bundling logic requires the token to be a standard, fee‑free ERC‑20; the check only inspects `balanceOf`/`allowance`, exactly the same class of assumption the Carapace report flags (assuming declared transfer amount == actually credited amount).

At execution time, `GaslessSwapRouter.swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` (bound in [4](#0-3) ) pulls `amountIn` tokens from the sender via `transferFrom`, swaps them, and is expected to repay `amountRepay` KAIA to the proposer (verified in the end‑to‑end flow in [5](#0-4) , where a `SwappedForGas` event with `FinalUserAmount` is checked). If `token` charges a transfer fee, the router actually receives less than `amountIn`, so the resulting swap output can fall below `amountRepay`, even though the tx pool's `checkBalanceForSwap` (mempool `Ready`/promotion gate) declared the transaction executable. The Solidity source of `GaslessSwapRouter` itself is not present in this repository (only the generated Go bindings are indexed), so I could not directly verify whether the router enforces a post-transfer balance-diff check before repaying the proposer; this is a gap in what I could confirm from the indexed sources.

### Impact Explanation
This is a fee‑delegation/gasless‑settlement path reachable by a single unprivileged transaction sender (the gasless swap sender) and directly affects the block proposer, who is the party fronting gas via the `LendTxGenerator`. If a fee‑on‑transfer token is (or becomes) allow‑listed, a malicious sender could craft `amountIn`/`minAmountOut` values that pass the declared-balance/allowance checks in the mempool, but that yield insufficient output at execution to fully repay the proposer's lent gas — resulting in proposer fund loss (reward/fee redirection away from the proposer) each time such a bundle is included. This matches the "fee or fee-delegation abuse" / "gasless settlement theft" impact categories.

### Likelihood Explanation
Likelihood is bounded by governance: only tokens present in `GaslessConfig.AllowedTokens` (set via the `gasless.allowed-tokens` CLI flag, defaulting to "all") are eligible [6](#0-5) . If operators run with the default "all" tokens allowed, any fee‑on‑transfer ERC‑20 in circulation is automatically eligible with no additional code-level protection, making exploitation straightforward for any holder of such a token. If the default is `Disable=false` and no explicit allow‑list is curated, the exposure is real in a permissive default configuration.

### Recommendation
- Enforce a "no-fee/no-rebase" invariant on any token in `AllowedTokens`, or better, compute the *actual* amount received by the router using pre/post `balanceOf` snapshots rather than trusting a static `GetAmountIn`/allowance/balance quote.
- In `checkBalanceForSwap` (`kaiax/gasless/impl/tx_pool.go`), reject or flag tokens whose `transfer`/`transferFrom` behavior can reduce the credited amount (e.g., simulate the transfer and diff balances) before promoting a `GaslessSwapTx`.
- At execution time, have `GaslessSwapRouter.swapForGas` measure actual balance delta after `transferFrom` (and revert if it doesn't cover the required swap input), so proposer repayment (`amountRepay`) can never be shorted by transfer-time deductions.

### Proof of Concept
Conceptual walk-through (constrained by the fact that `GaslessSwapRouter.sol` source is not present in this repo — only Go bindings/tests were indexed):
1. Governance/operator allow-lists a fee-on-transfer ERC-20 token `T` (e.g., a token that burns/redirects 5% on every `transfer`/`transferFrom`) in `gasless.allowed-tokens`.
2. A user submits `GaslessApproveTx` + `GaslessSwapTx(token=T, amountIn=X, minAmountOut=Y, amountRepay=Z, deadline)` where `X`, `Y`, `Z` are chosen to just pass `checkBalanceForSwap`'s checks: `Y >= Z`, `X >= routerContract.GetAmountIn(Y)`, `allowance(sender, router) >= X`, `balanceOf(sender) >= X` — all satisfied using the user's *nominal* token balance (before fee deduction) as in [7](#0-6) .
3. Proposer includes `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` as a bundle based on the mempool's `IsExecutable`/`Ready` check passing.
4. On execution, `transferFrom(sender, router, X)` actually delivers `X * (1 - fee%)` tokens to the router due to token `T`'s fee-on-transfer logic. The resulting swap output is less than `Y`/`Z`, so the proposer's lent gas (`amountRepay`) is not fully recovered, while the mempool admission logic gave no signal of this shortfall because it only checked nominal balances/allowances, not actual transferred amounts.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
