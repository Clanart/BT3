### Title
Unvalidated attacker-controlled memo indexing causes uncaught `IndexError` in Data Layer mirror-coin parsing - ([File: chia/wallet/db_wallet/db_wallet_puzzles.py])

### Summary
`get_mirror_info()` reads the CREATE_COIN memo list produced by a parent spend's puzzle output and unconditionally does `memos[0]`/`memos[1:]` without checking that the list has at least one element, unlike the neighboring `launch_solution_to_singleton_info()` in the same file, which guards identical indexing with `try/except (IndexError, TypeError)`.

### Finding Description
`get_mirror_info()` runs the parent puzzle/solution and scans the returned conditions for a `CREATE_COIN` targeting the mirror puzzle hash (`create_mirror_puzzle().get_tree_hash()`), then extracts the memo list from the CLVM output and immediately indexes it: [1](#0-0) 

The memo list (`condition.at("rrrf").as_python()`) is fully attacker-controlled: it comes from the puzzle reveal + solution of a coin spend that any peer/attacker can construct, since `create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))` — a generic anyone-can-spend-style puzzle whose CREATE_COIN memo contents are dictated entirely by the solution supplied by the spender. If a spend creates a coin with puzzle hash equal to the mirror puzzle hash but supplies an empty memo list (`()`), `memos[0]` raises an uncaught `IndexError`.

This is called from `DataLayerWallet.coin_added()` during normal wallet sync whenever a coin is created with the mirror puzzle hash: [2](#0-1) 

Unlike the `IndexError`/`TypeError`-guarded `launch_solution_to_singleton_info()` a few lines above it in the same file, `get_mirror_info()` has no equivalent guard, so the exception propagates up through `coin_added()`.

### Impact Explanation
This is the direct Python analog of the ImageMagick bug class: an externally supplied value (an index/count that should be validated) is used to access a collection without a bounds check, causing an out-of-range access. In this Python code the "out-of-bounds read" manifests as an uncaught `IndexError` rather than memory corruption, but it is reachable purely by an attacker crafting a coin spend (no privileged access required) whose CREATE_COIN targets the mirror puzzle hash with an empty memo list. Since `coin_added()` is invoked during wallet coin-state processing, an uncaught exception here can abort processing of that sync callback for any Data Layer wallet client that observes the crafted coin, degrading/halting Data Layer coin tracking for that wallet (a spend-triggered processing halt in the reachable DL wallet flow).

### Likelihood Explanation
Triggering requires only submitting a spend whose puzzle hash matches the mirror puzzle and whose CREATE_COIN condition supplies zero memos — trivial for any wallet-level attacker/counterparty to construct, and it doesn't require validator or consensus-level coordination, only that a Data Layer wallet observes the coin.

### Recommendation
Wrap the `memos[0]`/`memos[1:]` access in `get_mirror_info()` with the same defensive handling used in `launch_solution_to_singleton_info()` (e.g., `try/except (IndexError, TypeError)` raising a `ValueError`), and have `coin_added()` treat a malformed/empty-memo mirror coin as non-fatal (skip it) rather than letting the exception propagate.

### Proof of Concept
1. Construct a `CoinSpend` whose puzzle reveal, when run with an attacker-chosen solution, outputs a condition `(CREATE_COIN <mirror_puzzle_hash> <amount> ())` — i.e., a `CREATE_COIN` to `create_mirror_puzzle().get_tree_hash()` with an empty memo list.
2. Broadcast/confirm the coin so it appears in a Data Layer wallet's `coin_added()` sync path with `coin.puzzle_hash == create_mirror_puzzle().get_tree_hash()`.
3. `coin_added()` calls `get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)` [3](#0-2) , which executes `memos[0]` on the empty list and raises an uncaught `IndexError`, aborting that coin-state processing call.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```
