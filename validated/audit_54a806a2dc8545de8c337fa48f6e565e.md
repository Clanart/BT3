### Title
Fee-on-transfer whitelisted tokens break `GaslessSwapRouter.swapForGas()` admission/execution accounting - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`)

### Summary
The `kaiax/gasless` module admits and executes gasless swap transactions (KIP-247) based on the declared `amountIn` value taken from the transaction's calldata, checking only the sender's `balanceOf`/`allowance` against that declared value — never the actual amount of tokens the `GaslessSwapRouter` contract will receive after `transferFrom`. If a whitelisted ERC20 token later becomes (or is deployed as) a fee-on-transfer token, the amount actually received by the router will be less than `amountIn`, breaking the swap logic exactly as described in the referenced report for `PirexGmx`/`AutoPxGlp`.

### Finding Description
The gasless flow works as follows:
1. `GaslessModule.checkBalanceForSwap` (tx pool admission) decodes `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` and validates:
   - `tx.token.allowance(sender, router) >= tx.amountIn`
   - `tx.token.balanceOf(sender) >= tx.amountIn` [1](#0-0) 
   These checks only look at the *sender's* balance/allowance, never at what the router will actually receive.

2. The block-building logic in `VerifyExecutable`/`GetLendTxGenerator` bundles `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` and validates `amountRepay` against a pre-computed `repayAmount()`, again based purely on the declared `amountIn`/`minAmountOut` values in the transaction, not on actual token transfer amounts. [2](#0-1) 

3. On-chain, `GaslessSwapRouter.swapForGas` (whose only available representation in this repo is the compiled bytecode/bindings, not Solidity source) is documented as calling `transferFrom(sender, router, amountIn)` and then swapping `amountIn` through the Uniswap-style router. [3](#0-2) 
Notably, the underlying Uniswap router used here explicitly distinguishes fee-supporting variants (`swapExactTokensForETHSupportingFeeOnTransferTokens`), implying the ordinary `swapExactTokensForTokens`/`swapExactTokensForETH` path used by `GaslessSwapRouter` is *not* fee-on-transfer safe. [4](#0-3) 

If any whitelisted token (`g.allowedTokens[token]`, checked in `isSwapTx`/`isApproveTx`) starts charging a transfer fee, the router will receive `amountIn * (1 - fee)` tokens instead of `amountIn`, but the swap call still attempts to swap the full `amountIn`, causing the swap to revert — mirroring the exact root cause in the external report (using the pre-fee amount instead of the balance actually received).

### Impact Explanation
This is reachable by any unprivileged sender submitting an ordinary `GaslessApproveTx`/`GaslessSwapTx` pair — no privileged role is required. Because the module already prepends a `LendTxGenerator` transaction that lends the user KAIA for gas *before* the swap executes (per the module's own bundling design), a swap that reverts due to fee-on-transfer token mismatch means:
- The bundle either as a whole fails/reverts (state divergence risk between nodes that estimate gas/repay differently), or
- The lent gas is not properly repaid if the revert happens after commitments were made, directly threatening the "gasless" invariant (block proposer's gas advance not repaid) that KIP-247 depends on.

This is a concrete fee/fee-delegation-style abuse and value-movement/DoS risk on the gasless settlement path, reachable purely from a public transaction — satisfying the required impact bar (fee-delegation/gasless settlement abuse).

### Likelihood Explanation
Likelihood is Medium: it requires a whitelisted token (`g.allowedTokens`) to be, or become, fee-on-transfer. Since token whitelisting is a governance/admin decision (via `Registry`/`GaslessSwapRouter` allowed-token updates) rather than something the code defends against, and since many real ERC20 tokens (e.g., USDT-style tokens) can enable transfer fees via upgradeable proxies, this is a realistic operational risk rather than a purely theoretical one — directly analogous to the cited finding, where USDT was already an accepted token that could add fees.

### Recommendation
- In `checkBalanceForSwap` / the router's `swapForGas` logic, compute the actual amount transferred by checking the router's token balance before and after `transferFrom`, and use that measured amount (not the caller-declared `amountIn`) for the subsequent swap and for the `minAmountOut`/`amountRepay` validations.
- Alternatively, restrict `allowedTokens` to token contracts verified to be fee-free (e.g., via a governance-controlled test/allowlist check), and reject swap validation when `balanceAfter - balanceBefore != amountIn`.

### Proof of Concept
1. Governance whitelists a token `T` in `GaslessSwapRouter`/`allowedTokens` that currently has 0% transfer fee.
2. Token `T`'s owner (via upgradeable proxy, common for stablecoins) later enables a 1% transfer fee.
3. User Alice sends `GaslessApproveTx` (approve router for `MaxUint256`) then `GaslessSwapTx` calling `swapForGas(T, amountIn=100, minAmountOut, amountRepay, deadline)`.
4. `checkBalanceForSwap` passes admission because Alice's balance/allowance of `T` is `>= 100` (pre-fee value) — see checks at [5](#0-4) 
5. The proposer prepends `LendTxGenerator` and includes the bundle in the block per `VerifyExecutable`'s repay-amount check, which also only uses the declared `amountIn`/`amountRepay` values. [6](#0-5) 
6. On execution, `transferFrom(Alice, router, 100)` on token `T` only delivers `99` tokens to the router due to the fee, but the router attempts to swap `100` tokens it does not actually hold, causing the swap call to revert and breaking the gasless repayment guarantee for that bundle.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
