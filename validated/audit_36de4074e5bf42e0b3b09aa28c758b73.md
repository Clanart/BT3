### Title
`updateRemoteUrl()` silently rewrites the `origin` remote to an attacker-controlled host supplied by the GitHub API, with no hostname validation - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The audited finding is about `AccountantDelegate.initialize()` accepting a `treasury_` address with no zero-address check, letting a critical, hard-to-fix configuration value (where funds go) be set to an unsafe value without validation. The Desktop analog is `updateRemoteUrl()`, which takes a `clone_url` fetched from the GitHub API and, if a handful of loose conditions hold, silently overwrites the repository's `origin` remote URL via `gitStore.setRemoteURL()` — without ever validating that the new host is the same as the one the user originally configured.

### Finding Description
`updateRemoteUrl` in [1](#0-0)  reads `apiRepo.clone_url` — a value returned by a GitHub API call (dotcom or an Enterprise server) — and compares it against the repository's current default remote.

The only checks performed before rewriting the remote are:
- that the URL protocol (`https`/`ssh`) hasn't changed [2](#0-1) 
- that the *current* remote URL still matches the previously cached `gitHubRepository.cloneURL` (i.e., the user hasn't manually repointed the remote) [3](#0-2) 
- that the new URL doesn't already match the current remote [4](#0-3) 

None of these checks compare the **hostname** of the new `clone_url` against the original repository's hostname/owner/name. `urlMatchesRemote` (used for the other two checks) does perform hostname/owner/name comparisons [5](#0-4) , but it is never invoked between the *old* remote and the *new* `clone_url` — only protocol equality is enforced there. As long as the scheme matches (e.g., both `https://`), a `clone_url` pointing to an entirely different host (`https://evil.example.com/attacker/repo.git`) satisfies `protocolsMatch` and will be written straight into the local git config via:

```
app/src/lib/stores/updates/update-remote-url.ts:43
await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
```

which calls down to `git remote set-url` with no further validation [6](#0-5) [7](#0-6) .

The `clone_url` field originates from an `IAPIRepository`/`IAPIFullRepository` object returned by `API.fetchRepository` / repository refresh calls [8](#0-7) . This is exactly the "GitHub API object" attacker-controlled input surface called out in the task's valid-impact list: a malicious or compromised GitHub Enterprise server (or a MITM'd/manipulated API response for a GHE instance without pinned TLS) can return a crafted `clone_url` for a repo the user already has cloned, and Desktop will rewrite `origin` to point there without any prompt or confirmation.

### Impact Explanation
Silently repointing `origin` corrupts what the user pushes: subsequent "Push" operations from Desktop will send the user's commits (potentially private/proprietary source code) to the attacker's server instead of the legitimate one, without any visible change in the UI other than the remote URL field in Repository Settings. This matches the report's "risk of loss of funds and the inability to easily fix" analog closely — here it's "loss of code / IP" and "inability to easily notice", since nothing else in the UI surfaces this silent remote change to the user. There is also no re-confirmation or warning dialog comparable to a "treasury changed" event.

### Likelihood Explanation
This requires the attacker to control (or be able to inject responses from) a GitHub Enterprise server or MITM position that the Desktop client is configured to query — which is within the described threat model of "a GitHub API object" being attacker-controlled. It does not require local access, admin rights, or pre-existing malware, matching the accepted class of findings. The trigger path (`_publishRepository`/periodic GitHub repository refresh eventually calling `updateRemoteUrl`) is normal application behavior, not an unnatural user action; a full end-to-end call-graph trace to the exact refresh scheduler could not be completed within available tool calls, so the precise refresh cadence/trigger site in `app-store.ts` is not fully confirmed, but the vulnerable function itself and its unsafe write path are directly verified in the codebase.

### Recommendation
Before calling `gitStore.setRemoteURL()` in `updateRemoteUrl`, validate that the new `clone_url`'s hostname/owner/name relationship to the *original* repository identity is preserved (e.g., require `urlMatchesRemote(updatedRemoteUrl, { url: gitHubRepository.htmlURL, name })` style hostname pinning, not just protocol equality), or require explicit user confirmation before silently changing a remote URL sourced from a network response.

### Proof of Concept
1. User has a repository cloned with `origin` pointing at `https://ghe.corp.example/org/repo.git`, tracked as a `GitHubRepository` against that Enterprise endpoint.
2. Attacker compromises/MITMs the Enterprise API endpoint (or operates a malicious "Enterprise" server the user was tricked into adding) and, on the next repository-info refresh, returns an `IAPIRepository` object with `clone_url: "https://attacker.example/org/repo.git"` (same scheme, different host).
3. `updateRemoteUrl` computes `protocolsMatch = true` (both `https:`), `remoteUrlUnchanged = true` (user hadn't manually changed remote), `urlsMatch = false` (different host/owner) — see conditions at [9](#0-8) .
4. `gitStore.setRemoteURL('origin', 'https://attacker.example/org/repo.git')` executes silently, rewriting the local `.git/config` remote URL.
5. The user's next `git push` from Desktop sends commits to the attacker's server without any warning.

```typescript
export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
```
