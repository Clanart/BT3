### Title
Weak hostname/owner/name equality in `urlsMatch()` allows deep-link URL to be treated as matching an unrelated existing repository - (File: `app/src/lib/repository-matching.ts`)

### Summary
The core-invariant break in the Uniswap report is: a value that is supposed to be *derived consistently* from the same underlying object (init code) is instead computed with a stale/mismatched derivation, so two things that should be equal are treated as equal when they are not (or vice versa), silently routing calls to the wrong address. The closest Desktop analog is `urlsMatch()` / `urlMatchesRemote()`, which decide "is this remote URL the *same repository* as this other URL" using only a loose, case-insensitive string comparison of `hostname`/`owner`/`name` extracted by `parseRepositoryIdentifier()` / `parseRemote()`, with no canonicalization of `owner`/`name` beyond casing, and no verification against the GitHub API or clone URL of record.

### Finding Description
`urlsMatch()` [1](#0-0)  compares two attacker-controllable strings after running them through `parseRepositoryIdentifier()` [2](#0-1) , which itself simply splits on regexes with no normalization of Unicode look-alike characters, no `.git` suffix consistency check beyond the regex's own capture, and no verification that `owner`/`name` actually resolve to the same GitHub repository ID. `doesRepositoryMatchUrl()` [3](#0-2)  uses this string match to decide whether an `open-repository-from-url` deep link (originating from `parseAppURL()` [4](#0-3) , itself reachable via any `x-github-client://openRepo/...` link a user clicks) should be considered "the same repository" the user already has open/cloned, versus being routed through `openOrCloneRepository()`.

Because the equality check is purely a case-insensitive string comparison of `hostname/owner/name` with no cross-check against the authoritative `GitHubRepository` API object (unlike, say, `matchGitHubRepository()`, which at least walks accounts by real API `endpoint`), a repository can be renamed, transferred, or an owner/name can be reused/typosquatted (e.g. a deleted-and-recreated GitHub repo under the same `owner/name`) between the time Desktop persisted a local `Repository`/`GitHubRepository` record and the time a deep link is clicked, causing Desktop to silently treat the attacker's link as pointing at the user's pre-existing local clone.

### Impact Explanation
If an attacker can get a target to click a crafted `x-github-client://openRepo/https://github.com/<owner>/<name>?branch=...&filepath=...` link (e.g., via a webpage, chat message, or `README`) where `<owner>/<name>` string-matches an already-known local repository (through a renamed/transferred/typosquatted repo that shares the same owner/name string, or a case-difference bypass), Desktop's `openRepositoryFromUrl()` path will operate on the user's existing local repository under the illusion it corresponds to the URL's actual (different) upstream: it will checkout an attacker-chosen `branch` in that repo, and open a `filepath` inside it via `resolveWithin()`/`shell.showItemInFolder()` [5](#0-4) . This can silently corrupt what the user later commits/pushes (checked-out branch mismatch) since no confirmation UI ties the clicked link's real host/repo identity to the local repository being manipulated.

### Likelihood Explanation
Requires the attacker to control only a link the victim clicks (no local access, no credentials, no admin rights) — squarely in-scope per the task's valid-impact criteria. The likelihood of finding a `owner/name` collision is non-trivial in practice (needs a same-named/transferred/deleted-recreated repo, or exploiting case-insensitivity, e.g. `Owner/Repo` vs `owner/repo` matching a differently-cased local record) — this constrains it to Medium rather than High confidence without further evidence of a guaranteed collision technique, and I could not verify from the index whether `GitHubRepository` records are additionally keyed/cross-checked by immutable API repository ID elsewhere before the branch checkout / file-open steps execute.

### Recommendation
Have `doesRepositoryMatchUrl()`/`urlsMatch()` corroborate the deep-link's `owner/name` against the repository's actual immutable GitHub API identity (e.g. `GitHubRepository.dbId`/API `id`) rather than only string-comparing `hostname/owner/name`, and require explicit user confirmation before checking out a branch or opening a file path sourced from an untrusted deep link when redirecting into a pre-existing local repository.

### Proof of Concept
Deterministic-reasoning PoC (not fully verified end-to-end against `GitHubRepository` persistence internals, which the index does not fully expose):
1. Victim has previously cloned `https://github.com/acme/widgets` into Desktop, which is persisted as a local `Repository` with `GitHubRepository{owner: 'acme', name: 'widgets'}`.
2. The `acme/widgets` GitHub repo is later deleted and an attacker (or unrelated party) recreates a different repository at the same `acme/widgets` slug (a common squatting technique on GitHub), or the attacker crafts a link using a differently-cased variant matched by `caseInsensitiveEquals` in `urlsMatch()`.
3. Attacker sends victim a link: `x-github-client://openRepo/https://github.com/acme/widgets?branch=malicious-branch&filepath=..%2F..%2Fsome-file` (subject to `testForInvalidChars`/`isAbsolute` guards on `filepath`).
4. `parseAppURL()` parses this into an `open-repository-from-url` action [6](#0-5) ; `doesRepositoryMatchUrl()` string-matches it to the victim's pre-existing local `acme/widgets` repository via `urlsMatch()` and proceeds to check out `malicious-branch` and open a file inside that local repo, without confirming the link's origin repository is actually the same object as the one on disk.

Because I could not fully confirm from the index whether an additional integrity check exists elsewhere in the `GitHubRepository` persistence/refresh flow (e.g., dbId reconciliation prior to `openOrCloneRepository`), this finding should be treated as **Medium-confidence** pending a full Devin session review of `app-store.ts`'s repository refresh/matching logic.

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}

export function parseRepositoryIdentifier(
  url: string
): IRepositoryIdentifier | null {
  const parsed = parseRemote(url)
  // If we can parse it as a remote URL, we'll assume they gave us a proper
  // URL. If not, we'll try treating it as a GitHub repository owner/name
  // shortcut.
  if (parsed) {
    const { owner, name, hostname } = parsed
    if (owner && name) {
      return { owner, name, hostname }
    }
  }

  const pieces = url.split('/')
  if (pieces.length === 2 && pieces[0].length > 0 && pieces[1].length > 0) {
    const owner = pieces[0]
    const name = pieces[1]
    return { owner, name, hostname: null }
  }

  return null
}

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
}
