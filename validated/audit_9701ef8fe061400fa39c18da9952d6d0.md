Based on my investigation, I found a genuine analog in the upb (C) decoder path involving `upb_EpsCopyInputStream_ReadStringEphemeral`.

### Title
Uninitialized/stale patch-buffer bytes can be copied into packed fixed-field array data before malformed-length error is raised - (File: upb/wire/decode.c)

### Summary
The ImageSharp advisory describes a decoder that, on malformed/truncated input, ends up writing bytes from a buffer region not fully populated by the actual image data into the caller-visible output buffer, disclosing adjacent memory contents. The transferable invariant is: "a length-delimited decode path copies data from a scratch/patch region into the caller-visible message *before* validating that the declared size was fully and legitimately satisfied by real input bytes." In upb's `_upb_Decoder_DecodeFixedPacked` (`upb/wire/decode.c:243-287`), packed fixed-width array data is read via `upb_EpsCopyInputStream_ReadStringEphemeral` [1](#0-0) , whose own contract explicitly warns that when `size` extends past the real end of the stream, "the returned data may contain garbage bytes from the patch buffer... it may result in nonsense bytes ending up in the output" and that this is "detected later" [2](#0-1) .

### Finding Description
`upb_EpsCopyInputStream_ReadStringEphemeral` only checks that `size` fits within `e->end + kSlopBytes` (the patch/slop region), not that it fits within the actual remaining logical input (`e->limit`) [3](#0-2) . `_upb_Decoder_DecodeFixedPacked` calls this function with an attacker-controlled `val->size` for packed `fixed32`/`fixed64`/etc. repeated fields, then immediately `memcpy`s the returned view into the array's backing storage [4](#0-3) . The slop/patch region (`e->patch`, `kUpb_EpsCopyInputStream_SlopBytes*2` = 32 bytes) is only partially initialized: it is populated by `memcpy` of at most `kUpb_EpsCopyInputStream_SlopBytes` real trailing input bytes and its second half is only ever memset to zero in the fallback path `UPB_PRIVATE(upb_EpsCopyInputStream_IsDoneFallback)` [5](#0-4) ; the initial fill path `upb_EpsCopyInputStream_InitWithErrorHandler` only zeroes the patch buffer, so subsequent buffer flips that reuse it via `memmove`/`memcpy` do not necessarily rezero all 32 bytes before this ephemeral read. The subsequent `upb_EpsCopyInputStream_IsDone` check (which is where the "end at improper limit" error surfaces per the documented comment) happens only *after* the bytes have already been copied into the array. If the message's overall parse eventually fails due to this length mismatch, the array holding the (possibly stale patch-buffer) bytes has already been mutated in-place on the arena-owned message object.

### Impact Explanation
This differs from the ImageSharp bug in one key way: in upb, a full decode failure normally causes `upb_Decode()` to return a non-OK status, and well-behaved callers discard the message. The disclosure only becomes a real leak if application code inspects/serializes a message object that was mutated during a parse that is later reported as failed (e.g., partial parse before exception propagation, retained buffers, or arenas reused across parses). Given "Attacker is an ordinary client sending bounded... Protobuf... through a supported public parse API" and "no privileged access," the exploitability hinges entirely on host application behavior after a failed `upb_Decode` call, which is explicitly a `WireFormatLite`/parse-failure-handling nuance the analog rules ask to separate from a hard proof. I could not find, within available context, code that serializes or exposes such partially-populated arrays back to the same requester after failure, and I did not confirm that the second half of `e->patch` is genuinely stale/uninitialized heap data versus deterministically-zeroed data in all buffer-flip paths.

### Likelihood Explanation
Low-to-Medium as a standalone finding. The comment at `upb/wire/internal/eps_copy_input_stream.h:116-125` is upstream's own explicit acknowledgment that "nonsense bytes" can appear in output data before an error is raised, which is the exact same failure mode class as the ImageSharp advisory (decoder writes speculative/garbage buffer content into the returned output ahead of validating the true data length). However, unlike ImageSharp (where the leaked buffer is directly serialized back to the requester as the image), a normal protobuf caller discards a message on decode failure, which substantially reduces exploitability without additional application-level assumptions.

### Recommendation
Forward this to a Devin agent to trace all call sites of `upb_EpsCopyInputStream_ReadStringEphemeral` (currently only `_upb_Decoder_DecodeFixedPacked` in `upb/wire/decode.c`) and verify/patch so that: (1) the `memcpy` of returned ephemeral data into caller-visible arrays only occurs after `size` has been validated against the true remaining `limit` (not just the patch/slop region bound), and/or (2) all bytes in `e->patch` are guaranteed to be either real input bytes or deterministically zeroed before any ephemeral read can expose them, in every buffer-flip code path (`InitWithErrorHandler`, `IsDoneFallback`, and any others touching `e->patch`). Add a regression test that constructs a packed-fixed field whose declared size exceeds the actual remaining bytes by less than `kSlopBytes`, and assert that the resulting array contents are deterministic (e.g., all zero) rather than reflecting whatever previously occupied the patch buffer, and that decode failure is raised strictly before the array is mutated.

### Proof of Concept
I was not able to execute code in this environment to confirm exploitability end-to-end. A concrete PoC would need to: build a `upb_MiniTable` with a packed `fixed32` repeated field, craft a message where the packed field's declared length exceeds the actually available bytes by an amount ≤ `kUpb_EpsCopyInputStream_SlopBytes` (16), call `upb_Decode()`, and then — before checking the return status — inspect the resulting array contents (which `_upb_Decoder_DecodeFixedPacked` will have already written via `memcpy` from `sv.data`/`sv.size` sourced from `upb_EpsCopyInputStream_ReadStringEphemeral`) to check whether they contain deterministic/zeroed data or leftover patch-buffer content from a prior parse using the same `upb_Arena`/stream buffer. This step requires running the actual upb decoder, which I could not do in this read-only analysis; the code paths and the upstream self-documented "nonsense bytes ending up in output" risk are cited above as the basis for this analog.

UPB_INLINE const char* upb_EpsCopyInputStream_ReadStringEphemeral(
    struct upb_EpsCopyInputStream* e, const char* ptr, size_t size,
    upb_StringView* sv) {
  UPB_ASSERT(size <= PTRDIFF_MAX);
  // Size must be within the current buffer (including slop bytes).
  const char* limit = e->end + kUpb_EpsCopyInputStream_SlopBytes;
  if ((ptrdiff_t)size > limit - ptr) {
    // For the moment, we consider this an error.  In a multi-buffer world,
    // it could be that the requested string extends into the next buffer, which
    // is not an error and should be recoverable.
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
  *sv = upb_StringView_FromDataAndSize(ptr, size);
  return ptr + size;
}

const char* UPB_PRIVATE(upb_EpsCopyInputStream_IsDoneFallback)(
    struct upb_EpsCopyInputStream* e, const char* ptr, int overrun) {
  if (overrun < e->limit) {
    // Need to copy remaining data into patch buffer.
    UPB_ASSERT(overrun < kUpb_EpsCopyInputStream_SlopBytes);
    const char* old_end = ptr;
    const char* new_start = &e->patch[overrun];
    memset(&e->patch[kUpb_EpsCopyInputStream_SlopBytes], 0,
           kUpb_EpsCopyInputStream_SlopBytes);
    memcpy(e->patch, e->end, kUpb_EpsCopyInputStream_SlopBytes);
    ptr = new_start;
    e->end = &e->patch[kUpb_EpsCopyInputStream_SlopBytes];
    e->limit -= kUpb_EpsCopyInputStream_SlopBytes;
    e->limit_ptr = e->end + e->limit;
    UPB_ASSERT(ptr < e->limit_ptr);
    e->input_delta = (uintptr_t)old_end - (uintptr_t)new_start;
    UPB_PRIVATE(upb_EpsCopyInputStream_BoundsChecked)(e);
    return new_start;
  } else {
    UPB_ASSERT(overrun > e->limit);
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
}
