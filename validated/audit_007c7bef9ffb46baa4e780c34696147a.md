### Title
Blame proof revealing the ECDH shared key is emitted before the proof-of-possession is verified, leaking other participants' decrypted secret shares - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` calls `Encryption::decrypt`, which only *queues* the Schnorr proof-of-possession (`msg.pop`) over the attacker-controlled per-message key `msg.key` into a `BatchVerifier`, then immediately computes `b * msg.key` (ECDH) and returns it wrapped in an `EncryptionKeyProof` meant for public blame attribution. When the decrypted bytes are not a canonical scalar, `calculate_share` early-returns `PedPoPError::InvalidShare { blame: Some(blame) }` — **before** `batch.verify_with_vartime_blame()` ever runs. This resurrects the exact attack the `pop` field was introduced to prevent: a malicious participant copies the `key` field `X` from an honest sender's `EncryptedMessage`, submits a message with an invalid PoP and ciphertext that decrypts to a non-canonical scalar, and the victim publishes `bX` — the shared key decrypting the honest message — as a "blame proof".

### Finding Description
In `crypto/dkg/pedpop/src/encryption.rs`, `Encryption::decrypt` (lines 469-501) does three things in order:

1. `msg.pop.batch_verify(...)` — only *queues* the PoP statement into `batch`; nothing is verified yet (line 479-485).
2. Computes `ecdh(self.enc_key, msg.key)` = `b · msg.key` where `b` is the local participant's long-term encryption secret, and decrypts (line 487-488).
3. Returns `(msg.msg, EncryptionKeyProof { key: ecdh_result, dleq })` — a publishable proof containing the ECDH shared key (line 489-500).

In `crypto/dkg/pedpop/src/lib.rs`, `calculate_share` (lines 476-499) then:

```rust
let (mut share_bytes, blame) =
  self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
let share =
  Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0)).ok_or_else(|| {
    PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }
  })?);
```

The `?` on the `from_repr` failure returns immediately. `batch.verify_with_vartime_blame()` at line 493 is never reached, so the queued `BatchId::Decryption(l)` PoP statement — the only thing proving the sender actually knows the discrete log of `msg.key` — is never checked. Yet `blame`, containing `b · msg.key` plus a valid DLEq proof binding it to `msg.key` and the victim's registered `enc_key`, is returned to the caller as `Some(blame)`, and `processor/src/key_gen.rs` (lines 419-425) serializes it into a public `ProcessorMessage::InvalidShare` message.

The in-code comment at `encryption.rs` lines 83-91 documents precisely this attack and states the PoP is the mitigation:

> "Eve could observe Alice encrypt to Bob with key X, then send Bob a message also claiming to use X. While Eve's message would fail to meaningfully decrypt, Bob would then use this to create a blame argument against Eve. When they do, they'd reveal bX, revealing Alice's message to Bob."

Because the PoP is verified lazily via the batch verifier but the blame material is produced eagerly and emitted on the early-return path, the mitigation is bypassed. Additionally, even on paths where the batch *is* verified, `blame_vartime` identifies only the leftmost failing statement — but here the failure exits before blame search at all.

The untrusted byte path: `EncryptedMessage::read` (`encryption.rs` lines 171-177) reads `key`, `pop`, and `msg` from untrusted bytes; `msg.key` is attacker-chosen and used in `self.enc_key * msg.key` before any authenticity check completes — directly analogous to a local `credential_command` value being consumed before the trust decision.

### Impact Explanation
A malicious DKG participant `l` can:

1. Observe an honest participant Alice's encrypted share message to victim Bob, extracting its `key` field `X = x·G` (keys are attached to messages in the clear).
2. Construct `EncryptedMessage { key: X, pop: <arbitrary invalid signature>, msg: <bytes that decrypt under b·X to a non-canonical F repr, or any bytes since the attacker can't predict the keystream — see PoC note> }` and send it to Bob as their own share message.
3. Bob's `calculate_share` computes `b·X`, queues the (invalid) PoP, attempts `F::from_repr` on the garbage plaintext, fails with overwhelming probability (~1 − q/2^256 for Ristretto), and returns `InvalidShare { participant: l, blame: Some(b·X + DLEq) }`.
4. Bob's processor publishes this blame (`ProcessorMessage::InvalidShare`), revealing `b·X` — the shared key for *Alice's* message to Bob — to everyone.
5. Anyone (including the attacker) uses `b·X` with `cipher(context, ...)` to decrypt Alice's ciphertext, recovering Alice's secret share contribution to Bob. Combined with the public Feldman commitments this doesn't directly recover Bob's final share alone, but in Pedersen/Feldman DKG knowing other parties' shares enables targeted share recovery / bias attacks; at minimum the confidentiality guarantee that the PoP exists to protect is broken, and leaked shares across multiple victims can enable reconstruction of secret material.

### Likelihood Explanation
- Requires a malicious DKG participant (rejected categories cover malicious *validators/nodes* — however here the attacker is a *participant in the DKG protocol supplying public inputs* — `EncryptedMessage` bytes — which is an in-scope reachable path via `EncryptedMessage::read` → `calculate_share`).
- The only subtlety: the attacker cannot predict the keystream `cipher(context, b·X)`, so they cannot *guarantee* the decrypted bytes are non-canonical — but non-canonicality occurs with probability ≈ 1 − (l/2^256) for random 32-byte output, i.e., essentially always. Any garbage ciphertext suffices.
- No collusion required; single malicious participant vs. one honest sender and one honest victim.
- Deterministic trigger on the victim side given the early return path.

Severity: **High** — leaks the ECDH shared key protecting another participant's encrypted secret share, violating the protocol's documented blame-safety invariant.

### Recommendation
Do not produce/return the `EncryptionKeyProof` until the PoP for the message has actually been verified. Concretely:

- In `Encryption::decrypt`, either verify `msg.pop` eagerly (non-batched) before computing/returning the ECDH proof, or split the API: decrypt to bytes first, and only generate the `EncryptionKeyProof` after `batch.verify_...` confirms the `BatchId::Decryption(l)` statement passed.
- In `KeyMachine::calculate_share`, ensure every early return (`from_repr` failure, batch failure with `BatchId::Share`) only attaches `Some(blame)` once that participant's `BatchId::Decryption` statement is known to be valid — e.g., verify PoP statements in a separate batch that must pass before share statements are queued and before any blame is emitted.

### Proof of Concept
Conceptual, on `C = Ristretto` (as in `pedpop/src/tests.rs`):

```rust
// Alice -> Bob honest message: EncryptedMessage { key: X, pop: valid, msg: enc_alice }
let honest_msg = &secret_shares[&ALICE][&BOB];
let X_bytes = honest_msg.serialize(); // extract `key` field X

// Eve constructs a malicious EncryptedMessage reusing X
let mut evil_bytes = vec![];
evil_bytes.extend(&X_bytes[..32]);          // key = X (copied)
evil_bytes.extend(&[0u8; 64]);              // invalid SchnorrSignature pop
evil_bytes.extend(&[0xAAu8; 32]);           // ciphertext -> decrypts to non-canonical repr w.h.p.
let evil = EncryptedMessage::<Ristretto, SecretShare<_>>::read(
    &mut evil_bytes.as_slice(), params).unwrap();

// Bob's calculate_share:
//  - decrypt() queues the (invalid) PoP, computes b*X, returns EncryptionKeyProof{key: b*X, dleq}
//  - F::from_repr(garbage) fails -> early return:
//    Err(InvalidShare { participant: EVE, blame: Some(proof_containing_bX) })
// batch.verify_with_vartime_blame() is never executed; the bad PoP is never detected.
// Bob's processor serializes the blame -> publishes b*X
// Attacker decrypts honest_msg.msg with cipher(context, b*X) -> Alice's share to Bob.
```

The failure mode is confirmed structurally by `tests.rs` `invalid_share_serialization_blame` (lines 282-313), which exercises exactly this early-return path (`blame: Some(...)` on non-canonical share) — except in the test the PoP is valid, masking that the PoP is never verified before the blame is emitted.
