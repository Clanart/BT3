### Title
First locker after `totalStaked()==0` can seize the entire queued forfeiture reward - (File: `rewards/vlMGPBaseRewarder.sol`)

### Summary
`_queueNewRewardsWithoutTransfer` (called from `queueMGP`/`_sendReward` on early-unlock forfeitures) buffers forfeited MGP into `rewardInfo.queuedRewards` whenever `totalStaked()==0` [1](#0-0) . The buffered amount is only folded into `rewardPerTokenStored` the next time a reward-queuing function runs while `totalStaked()>0`, using whatever `totalStaked()` is *at that instant* [2](#0-1) . Since `balanceOf`/`totalStaked` are read live from `vlMGP`/`masterMagpie` and there is no vesting/streaming of the buffered amount, whoever is staked (even with 1 wei) at the moment the buffer is finally flushed captures it in full via `earned`/`_earned` on the next `getReward` call [3](#0-2) .

### Finding Description
`queueNewRewards` and `_queueNewRewardsWithoutTransfer` share the same accounting pattern: if `totalStaked() == 0` the incoming reward is stashed in `queuedRewards` instead of being converted into `rewardPerTokenStored`; the conversion happens lazily on the *next* call to either function once `totalStaked() > 0` [4](#0-3) [1](#0-0) .

`VLMGP.lock()` itself does not call any reward-index-updating function on `vlMGPBaseRewarder`; it only changes `balanceOf`/`totalStaked()`. So simply locking after the pool is empty does not, by itself, pull in the queued reward. The capture happens on the *subsequent* trigger — another forfeiture (`queueMGP` → `_sendReward` → `_queueNewRewardsWithoutTransfer`) or a manager `queueNewRewards` call — at which point `rewardPerTokenStored += queuedRewards * 1e18 / totalStaked()`. If the attacker is the only staked account (e.g., locked 1 wei) when that trigger fires, `totalStaked()` equals their own tiny stake, so the entire `queuedRewards` bucket is credited to `rewardPerTokenStored` and becomes claimable in full by the attacker via `getReward`, regardless of how briefly they were staked.

No modifier (`onlyManager`, `nonReentrant`, `updateReward`) prevents this because the reward-index math itself has no time-weighting/vesting; it is a point-in-time proportional split based on whoever holds stake when the flush occurs. Note also that when `totalStaked()==0`, there are, by construction, no other active lockers with a legitimate pro-rata claim to the buffered amount at that specific moment — the unfairness materializes only when a subsequent locker with negligible stake and negligible holding time is present at the flush moment while other lockers might arrive shortly after.

### Impact Explanation
An unprivileged attacker can capture MGP yield that was forfeited by other users (early-unlock penalties) without having contributed any meaningful economic exposure during the accrual period, effectively diverting yield away from lockers who re-lock moments later. This matches "theft of unclaimed yield" — the loss is proportional to the size of `queuedRewards` at the time of exploitation, borne by subsequent legitimate lockers who no longer receive that share.

### Likelihood Explanation
Requires: (1) `totalStaked()` to transiently hit exactly zero (all vlMGP unlocked/withdrawn simultaneously, or the last locker's own unlock forfeiture pushes `queuedRewards` while zeroing `totalStaked()`), (2) attacker able to front-run other re-lockers with a minimal-amount `lock()` call, and (3) a subsequent trigger (any `queueMGP`/`queueNewRewards` call) to flush the buffer while the attacker remains the sole/dominant staked balance. Capital required is minimal (as little as 1 wei of MGP plus lock overhead), and the mempool position needed is a simple front-run, which is realistic on public chains. The precondition of `totalStaked()==0` is rare in a healthy protocol but not impossible (e.g., migrations, mass unlock events, or a small/early-stage pool).

### Recommendation
Avoid instantaneous, un-vested crediting of buffered rewards to whatever stake exists at flush time. Options: (a) time-weight the queued rewards using a minimum bonding/observation period before a locker becomes eligible for previously-queued rewards, (b) accrue `queuedRewards` using a checkpoint of `totalStaked()` sampled over the accrual window rather than at flush time, or (c) require a minimum total-staked/minimum-lock-duration threshold before flushing queued rewards, so a single-wei, single-block staker cannot absorb the entire bucket.

### Proof of Concept
Foundry test outline:
1. Deploy `VLMGP`, `masterMagpie`, and `vlMGPBaseRewarder`; have Alice and Bob lock MGP normally.
2. Have Alice and Bob fully unlock (including any cooldown/withdraw) so `IERC20(vlMGP).totalSupply() == 0` (`totalStaked() == 0`).
3. As part of Bob's final unlock, trigger a `queueMGP` forfeiture path (or otherwise call `_queueNewRewardsWithoutTransfer` indirectly) so `rewards[MGP].queuedRewards > 0` while `totalStaked()==0`; assert `rewardPerTokenStored` unchanged and `queuedRewards > 0`.
4. Attacker calls `VLMGP.lock(1)` (1 wei) — assert this alone does NOT change `rewardPerTokenStored` (confirms lock() doesn't auto-flush).
5. Trigger any subsequent `queueMGP`/`queueNewRewards`/forfeiture event while attacker is the sole locker with `totalStaked()==1`; assert `rewardPerTokenStored` jumps by `queuedRewards * 1e18 / 1`.
6. Have attacker call `getReward` via `masterMagpie` and assert they receive (approximately) the full previously-queued forfeited amount, despite holding stake for a negligible duration and amount — confirming disproportionate capture at the expense of Alice/Bob (or any future locker) who would otherwise have shared in it.

    function queueNewRewards(uint256 _amountReward, address _rewardToken)
        override
        external
        onlyManager
        returns (bool)
    {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        IERC20Metadata(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
        return true;
    }
