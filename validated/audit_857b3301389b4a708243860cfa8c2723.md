### Title
Citrea LCP Prover Unavailability Blocks Operator Kickoff Initiation, Locking Reimbursement — (`core/src/task/payout_checker.rs`)

### Summary

In `PayoutCheckerTask::run_once()`, `fetch_validate_and_store_lcp()` is called after `handle_finalized_payout()` solely to pre-cache the light client proof for a *future* challenge defense. However, the call uses `.await?`, propagating any error and rolling back the entire database transaction. When the Citrea LCP prover is temporarily unavailable, the kickoff transaction is never queued, the payout is never marked handled, and the operator's reimbursement flow is permanently stalled for the duration of the outage. The same pattern appears in the manual `get_next_txs_to_send()` path.

### Finding Description

`PayoutCheckerTask::run_once()` processes unhandled payouts in this sequence:

1. `handle_finalized_payout()` — selects an unused kickoff connector, builds the kickoff transaction, and enqueues it in `tx_sender`, all within `dbtx`.
2. `fetch_validate_and_store_lcp()` — contacts the Citrea light client prover RPC to pre-fetch and store the LCP receipt.
3. `end_round()` (automation) — advances the round.
4. `mark_payout_handled()` — marks the payout as handled in the DB.
5. `dbtx.commit()` — commits all of the above atomically.

The code at step 2 is:

```rust
// fetch and save the LCP for if we get challenged and need to provide proof of payout later
let _ = self
    .operator
    .citrea_client
    .fetch_validate_and_store_lcp(
        payout_block_height as u64,
        citrea_idx,
        &self.operator.db,
        Some(&mut dbtx),
        self.operator.config.protocol_paramset(),
    )
    .await?;   // ← error propagated; Ok value discarded
```

The comment explicitly states the LCP is only needed *if the operator is challenged later* — it is purely preparatory. Despite this, `.await?` propagates any error from the Citrea LCP prover RPC. When that RPC is unavailable (restart, network partition, maintenance), `fetch_validate_and_store_lcp()` returns an error, the `?` unwinds the function, `dbtx` is dropped without commit, and every effect from step 1 is rolled back. Steps 3–5 are never reached.

The identical pattern appears in the non-automation path `get_next_txs_to_send()`:

```rust
let _ = self
    .citrea_client
    .fetch_validate_and_store_lcp(
        payout_block_height as u64,
        citrea_idx as u32,
        &self.db,
        dbtx.as_deref_mut(),
        self.config.protocol_paramset(),
    )
    .await?;
// kickoff_tx is only pushed to txs_to_send after this point
txs_to_send.push(kickoff_tx.clone());
```

Here too, the kickoff transaction is never returned to the caller when the LCP prover is down.

The `fetch_validate_and_store_lcp()` implementation calls `get_light_client_proof_by_l1_height` on the external `light_client_prover_client` HTTP endpoint. Any network error or prover unavailability causes it to return `Err`.

### Impact Explanation

The operator has already fronted BTC for the user's withdrawal (payout tx is on-chain). The kickoff transaction is the first step of the reimbursement flow. Because `PayoutCheckerTask` cannot commit its transaction while the LCP prover is down:

- The kickoff transaction is never queued in `tx_sender` and never broadcast to Bitcoin.
- The payout row remains in the "unhandled" state; every subsequent poll of `PayoutCheckerTask` (every 60 seconds in production) fails identically.
- The operator cannot advance to the challenge-response phase and cannot recover the fronted BTC.
- If the LCP prover outage extends beyond the protocol's kickoff deadline window, the operator permanently loses the reimbursement for the fronted BTC — a direct loss of bridge-controlled/operator-managed funds.

This matches the allowed impact gate: permanent lock of reimbursement outputs and operator-managed balances.

### Likelihood Explanation

The Citrea light client prover is an external HTTP service. Any restart, deployment, network partition, or rate-limit event causes `get_light_client_proof_by_l1_height` to fail. The `HttpClientBuilder` timeout defaults to 60 seconds, so a slow prover also triggers the failure. This is a realistic operational scenario, not a theoretical one.

### Recommendation

Decouple the preparatory LCP fetch from the critical kickoff-initiation path. The LCP is only needed if a challenge arrives later; it should not gate the kickoff transaction. Two concrete options:

**Option A** — Swallow the error and log it; retry the LCP fetch in a separate background task:
```rust
if let Err(e) = self.operator.citrea_client
    .fetch_validate_and_store_lcp(...)
    .await
{
    tracing::warn!("LCP pre-fetch failed (will retry): {:?}", e);
    // do NOT propagate; continue to mark_payout_handled and commit
}
```

**Option B** — Move the LCP pre-fetch entirely out of `PayoutCheckerTask` into a dedicated `LcpPrefetchTask` that retries independently, so the kickoff path has no dependency on LCP prover availability.

### Proof of Concept

1. Operator fronts BTC for a user withdrawal; payout tx is confirmed on Bitcoin.
2. `PayoutCheckerTask::run_once()` detects the unhandled payout.
3. `handle_finalized_payout()` succeeds: kickoff connector selected, kickoff tx built and enqueued in `tx_sender` — all within `dbtx` (not yet committed).
4. Citrea LCP prover is unreachable (restart / network issue).
5. `fetch_validate_and_store_lcp()` → `get_light_client_proof_by_l1_height` → HTTP error → `Err` returned.
6. `.await?` propagates the error; `dbtx` is dropped without `commit()`.
7. All DB writes from step 3 are rolled back; kickoff tx is not in `tx_sender`.
8. Payout row remains "unhandled"; next poll (60 s later) repeats steps 3–7.
9. Operator cannot broadcast the kickoff transaction; reimbursement flow is stalled.
10. If the prover outage exceeds the protocol's kickoff deadline, the operator's fronted BTC is unrecoverable.

    async fn fetch_validate_and_store_lcp(
        &self,
        payout_block_height: u64,
        deposit_index: u32,
        db: &Database,
        mut dbtx: Option<DatabaseTransaction<'_>>,
        paramset: &'static ProtocolParamset,
    ) -> Result<Receipt, BridgeError> {
        let saved_data = db
            .get_lcp_for_assert(dbtx.as_deref_mut(), deposit_index)
            .await?;
        if let Some(lcp) = saved_data {
            // if already saved, do nothing
            return Ok(lcp);
        };

        let lcp_result = self
            .get_light_client_proof(payout_block_height, paramset)
            .await?;
        let (_lcp, lcp_receipt, _l2_height) = match lcp_result {
            Some(lcp) => lcp,
            None => {
                return Err(eyre::eyre!(
                    "Light client proof could not be fetched found for block height {}",
                    payout_block_height
                )
                .into())
            }
        };

        // save the LCP for assert
        db.insert_lcp_for_assert(dbtx, deposit_index, lcp_receipt.clone())
            .await?;

        Ok(lcp_receipt)
    }
