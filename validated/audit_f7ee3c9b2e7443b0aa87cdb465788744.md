### Title
Untrusted `ReceivedOutput` bytes let an attacker set the reserved key-derivation `offset` and fabricated prevout data, which the wallet later trusts for signing - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

Analogous to the ntfs3 bug — where reserved `$LX*` xattrs could be written through a public interface and were later reloaded as trusted ownership/permission metadata — `ReceivedOutput::read` deserializes the reserved `offset` scalar (which selects which `ThresholdKeys` derivation signs) plus the `TxOut` value and `OutPoint` entirely from attacker-controlled bytes, with no verification that these fields correspond to a real on-chain output. `SignableTransaction::new` and `SignableTransaction::multisig` then trust these fields for balance accounting and signing.

### Finding Description

`ReceivedOutput` is intended to be produced only by `Scanner::scan_transaction` / `scan_block`, which legitimately derive `offset` from the script↔offset map built by `register_offset`. However, `ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) accepts a serialized blob containing:

- `offset`: a scalar read via `Secp256k1::read_F`, later applied to the threshold keys via `keys.clone().offset(self.offsets[i])` in `SignableTransaction::multisig` (send.rs:276, 281).
- `output`: an attacker-fully-controlled `TxOut`, whose `value` is summed into `input_sat` for balance/fee accounting (send.rs:175) and committed into the sighash via `Prevouts::All(&self.tx.prevouts)` (send.rs:375).
- `outpoint`: arbitrary, placed directly into `TxIn.previous_output` (send.rs:180).

The only integrity check in `multisig` is `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` (send.rs:277), which binds `offset` to the *script* but not to the outpoint, the output's existence, or its value. An attacker who supplies a serialized `ReceivedOutput` can therefore:

1. Take a real script_pubkey paying to the Serai wallet (public on-chain data), pair it with a fabricated `outpoint` and an inflated `value`, and choose `offset` consistent with that script (offsets for a given script are computable since `register_offset`'s increment-until-even behavior is public).
2. The wallet counts the fabricated value as spendable balance (`input_sat`), constructs a transaction, and produces a valid threshold signature over a sighash committing to the fabricated prevouts.

The resulting transaction is consensus-invalid (the prevout doesn't exist or has a different value), so the signed outputs are unspendable — yet the wallet recorded funds as received and expended a FROST signing round on an unintended, attacker-constructed message. Conversely, an attacker can also down-value a real UTXO, causing the difference to be silently burned as an oversized "fee" (`fee()` = `sum(prevouts) - sum(outputs)`, send.rs:138-141) if the transaction were otherwise valid — though the sighash commitment means it remains invalid on-chain, the wallet's accounting is corrupted either way.

### Impact Explanation

- **Funds reported received that are not spendable**: fabricated `outpoint`/`value` pairs are treated as balance, inflating `input_sat` and enabling transactions that can never confirm — a persistent false-balance condition reachable purely from untrusted bytes.
- **Signing of attacker-constructed sighashes**: the threshold group signs a sighash whose prevout commitments (`Prevouts::All`) are attacker-supplied values, not verified against chain state.
- Severity: Medium. The signatures themselves are only valid for the invalid transaction, so direct theft is not achieved, but the integrity of the wallet's UTXO set and its signing decisions are fully attacker-controlled wherever serialized `ReceivedOutput`s cross a trust boundary.

### Likelihood Explanation

Any path where a `ReceivedOutput` is transported or stored in serialized form — `serialize()`/`write()` round-trips, relay between scanner and signer components, or persistence — is a trust boundary an unprivileged party can write to, exactly as the `$LX*` xattrs were writable via the owner-accessible `setxattr` path. The vulnerability requires only that the reader trusts the deserialized fields, which `SignableTransaction::new` does unconditionally.

### Recommendation

- Either remove the public `read`/`write` serialization of `ReceivedOutput` (making it constructible only via `Scanner`), or store a commitment to the scanner's `key`/script map in the encoding and verify `p2tr_script_buf(key + G*offset) == output.script_pubkey` inside `read` (equivalent to rejecting userspace writes to reserved names — the offset must be re-derived, not trusted).
- At minimum, `SignableTransaction::multisig` should additionally verify that `outpoint` resolves to a UTXO matching `output` (value and script) before signing.

### Proof of Concept

```rust
// Attacker observes a real deposit on-chain:
//   real_script = p2tr_script_buf(key + G*real_offset) // public
//   real_offset is recovered by scanning: Scanner maps script -> offset publicly
//   (offset derivation is deterministic: increment until p2tr_script_buf returns Some)

// Attacker serializes a forged ReceivedOutput:
let forged = ReceivedOutput_bytes {
    offset: real_offset,                       // valid: passes the multisig script check
    output: TxOut {
        value: Amount::from_sat(1_000_000_000),// fabricated: real output was 10_000 sats
        script_pubkey: real_script,            // copied from the real on-chain output
    },
    outpoint: OutPoint::new(real_txid, 0),     // or entirely fabricated
};

// Victim deserializes and spends:
let ro = ReceivedOutput::read(&mut &forged[..]).unwrap();   // succeeds, no validation
let stx = SignableTransaction::new(vec![ro], &payments, change, None, fee).unwrap();
// stx.fee()/needed_fee accounting now trusts the 1 BTC fabricated input;
// stx.multisig(&keys) returns Some since script_pubkey matches key+offset,
// and the FROST round signs a sighash committing to the fake prevout.
// The broadcast transaction is rejected by the network; the wallet's balance
// remains permanently inflated by the phantom output.
```
