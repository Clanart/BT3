### Title
Cross-recipient replay of PedPoP encrypted shares causes false fatal blame of an honest sender — recipient identity is unbound - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptedMessage`'s proof-of-possession and encryption transcripts bind the `context`, the per-message key, the `sender`, and the plaintext — but never the *intended recipient*. Consequently a ciphertext produced by an honest sender `S` for participant `A` can be delivered to any other participant `B`. `B` verifies a fully valid PoP, derives the wrong ECDH key, decrypts garbage, and `calculate_share`/`blame` attribute the fault to the honest `S`, who is then fatally blamed (slashed) for a message that was never addressed to `B`.

### Finding Description
In `encrypt`/`pop_challenge`, the transcript commits to `context`, `nonce`, `key`, `sender`, and `msg`, but the recipient's identity (`to` / its encryption key) is absent:

- `crypto/dkg/pedpop/src/encryption.rs:135-168` (`encrypt`)
- `crypto/dkg/pedpop/src/encryption.rs:302-324` (`pop_challenge`)
- `crypto/dkg/pedpop/src/encryption.rs:95-133` (`ecdh`/`cipher` — binds only `context` + ECDH point)

When `B` receives `S`'s message in `calculate_share`, `Encryption::decrypt` computes `ecdh(enc_key_B, msg.key)` — a validly-formed but wrong shared key — producing an invalid scalar share, which raises `PedPoPError::InvalidShare { participant: S }` (`lib.rs:476-499`).

In the blame arbitration path (`Decryption::decrypt_with_proof`, `encryption.rs:366-397`; `BlameMachine::blame_internal`, `lib.rs:575-609`):
1. `msg.pop.verify` succeeds because the PoP is genuine — it was honestly created by `S` (just for `A`).
2. `B`'s `EncryptionKeyProof` DLEq verifies against `enc_keys[&B]` because it is `B`'s own ECDH proof.
3. The decrypted bytes fail `from_repr` or share verification → `blame_internal` returns `sender` (`S`).

So every honest participant's share can be redirected to condemn the sender. This is the direct analog of the Snipe-IT bug: an object (an encrypted share) is acted on outside its authorized scope (its intended recipient) because a scope/ownership field (the recipient) is never checked — a null-check equivalent.

### Impact Explanation
- Wrongful fatal blame: an honest, correctly-behaving participant `S` is adjudicated faulty by every participant who is fed a redirected ciphertext. In Serai this maps to a slashing/key-removal event and forced DKG abort.
- Amplification: the attacker needs to relay only public channel objects (`EncryptedMessage`, `EncryptionKeyMessage`); no secret material is required. Any party able to inject or reorder channel messages — including a single malicious participant who forwards `S→A` ciphertext as if it were `S→B` — can trigger it.
- Because `AdditionalBlameMachine::new` lets arbitrary evaluators adjudicate (`lib.rs:649-662`), the forged "accusation" propagates to on-chain blame arbitration identically to a legitimate one.

### Likelihood Explanation
Reachable with public inputs only: the attacker copies a broadcast `EncryptedMessage` (whose PoP is publicly verifiable) into the share-map slot destined for a different participant index. `Participant` IDs are enumerable (1..=n), mirroring the sequential-ID enumeration of the CVE. No collusion, leaked keys, or trusted-party compromise is needed — only the ability to present an existing ciphertext under a different (sender, recipient) pairing, which the protocol cannot distinguish because the recipient was never committed.

### Recommendation
Bind the recipient into the message scope:
1. Extend `pop_challenge` to append `recipient`'s `Participant` index and/or the recipient's registered `enc_key`, so a PoP is only valid for its addressed recipient.
2. Alternatively/additionally, append the recipient key to `cipher`'s transcript context so a misdelivered message yields a deterministically distinguishable failure from "invalid share".
3. In `Decryption::decrypt_with_proof`/`blame_internal`, treat "PoP valid for a different recipient" as malformed delivery rather than sender fault (e.g., verify the PoP under the intended recipient derived from the message, not the caller-supplied `decryptor`).

### Proof of Concept
1. Run PedPoP with n ≥ 3. Honest sender `S` produces `EncryptedMessage`s `m_A = encrypt(S→A, share_A)` and `m_B = encrypt(S→B, share_B)`.
2. Attacker delivers `m_A` to `B` in place of `m_B` (the map is keyed by `S` only; nothing authenticates which ciphertext belongs to `B`).
3. `B.calculate_share` decrypts `m_A` with `ecdh(enc_key_B, m_A.key)` → garbage bytes → `InvalidShare { participant: S }` with a blame proof `B` generates honestly.
4. `BlameMachine::blame(S, B, m_A, proof)` → PoP verifies (signed by `S`, `sender=S` bound correctly), DLEq verifies for `B`'s key, share is non-canonical → returns `S` as faulty.
5. `S`, who behaved perfectly, is reported to the coordinator as the malicious party and is fatally blamed/slashed; the DKG aborts.
