### Title
Unauthenticated JSON-RPC `send_tx` Endpoint Allows Any Network Peer to Enqueue Arbitrary Transactions and Drain Fee-Payer UTXOs — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The tx-sender JSON-RPC server exposes `send_tx` over plain HTTP with zero authentication. When `TX_SENDER_JSONRPC_BIND=0.0.0.0` is set (an explicitly supported and validated configuration option), any network-reachable attacker can call `send_tx` without a TLS client certificate, API token, or any other credential, and directly enqueue arbitrary Bitcoin transactions into the bridge's broadcast queue — including with `fee_paying_type=CPFP`, which causes the tx-sender to spend its own wallet funds to create fee-payer UTXOs for the attacker-supplied transaction.

---

### Finding Description

`start_jsonrpc_server` builds a plain `jsonrpsee` HTTP server with no middleware, no TLS, and no authentication layer:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
    ...
``` [1](#0-0) 

The `send_tx` handler immediately calls `client.insert_try_to_send(...)` with all fields taken directly from the unauthenticated request — including `fee_paying_type`, `cancel_outpoints`, and `activate_outpoints`:

```rust
module.register_async_method("send_tx", |params, client, _| async move {
    let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;
    ...
    let try_to_send_id = client
        .insert_try_to_send(
            &mut dbtx,
            req.tx_metadata,
            &signed_tx,
            req.fee_paying_type,   // attacker-controlled
            req.rbf_signing_info,
            &req.cancel_outpoints, // attacker-controlled
            ...
        )
        .await
``` [2](#0-1) 

The configuration explicitly permits binding to `0.0.0.0`:

```rust
if bind != "127.0.0.1" && bind != "0.0.0.0" {
    return Err(BridgeError::EnvVarMalformed(...));
}
Ok(TxSenderJsonRpcConfig { bind, port })
``` [3](#0-2) 

The `run.sh` smoke-test script demonstrates the design intent: it calls `send_tx` over plain HTTP with no credentials, and the default bind is `127.0.0.1` but `0.0.0.0` is a first-class supported value: [4](#0-3) 

By contrast, every gRPC actor endpoint (operator, verifier, aggregator) is protected by mTLS with `OnlyAggregatorAndSelf` certificate verification: [5](#0-4) 

The tx-sender JSON-RPC has none of this.

---

### Impact Explanation

**1. Unauthorized privileged action (authentication bypass):** The tx-sender is the sole component authorized to broadcast bridge transactions. Enqueuing a transaction is a privileged bridge action. Any unauthenticated caller can perform it.

**2. Fee-payer UTXO drain (loss of tx-sender-managed balances):** When `fee_paying_type=CPFP` is submitted, the tx-sender's loop calls `create_fee_payer_utxo`, which calls `self.rpc.send_to_address(...)` to fund a new fee-payer UTXO from the tx-sender's own Bitcoin wallet: [6](#0-5) 

An attacker who controls their own Bitcoin UTXOs can craft a valid transaction with a P2A anchor output, submit it via `send_tx` with `fee_paying_type=CPFP`, and the tx-sender will spend its wallet funds to create a fee-payer UTXO for the attacker's transaction. Repeating this at scale drains the tx-sender's wallet, which holds bridge-operational funds.

**3. Liveness disruption:** Flooding the queue with garbage entries prevents legitimate bridge transactions (kickoff, payout, reimburse, challenge, disprove) from being processed in a timely manner, breaking bridge safety/liveness.

---

### Likelihood Explanation

- `TX_SENDER_JSONRPC_BIND=0.0.0.0` is an explicitly validated, documented configuration option. Any deployment that exposes the tx-sender to a non-loopback interface (e.g., in a containerized or cloud environment where the tx-sender is a separate service) is immediately exploitable.
- No exploit prerequisites beyond network reachability: no key material, no privileged role, no prior bridge state.
- The `run.sh` smoke test itself demonstrates the attack: plain `curl` with no TLS client certificate successfully calls `send_tx`. [7](#0-6) 

---

### Recommendation

1. **Add authentication to the JSON-RPC server.** Options include:
   - A shared secret / bearer token validated in a `jsonrpsee` middleware layer.
   - Mutual TLS using the same CA and certificate infrastructure already used for gRPC actors.
   - Restricting `TX_SENDER_JSONRPC_BIND` to `127.0.0.1` only (removing `0.0.0.0` support) and enforcing this at the code level, not just documentation.

2. **Add an IP allowlist** if the JSON-RPC interface must be network-exposed.

3. **Rate-limit and cap queue depth** to bound the DoS/drain impact even if authentication is added.

---

    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };
