I'll look closer at the Bitcoin network code to map this "missing receiver / cannot accept funds" bug class onto a reachable path.### Title
Deposit metadata (InInstruction data and refund origin) overwritten by later transactions in the same block, misrouting or wiping received funds - (File: processor/src/networks/bitcoin.rs)

### Summary
The "lack of receiver support" class maps onto Serai as deposits that are detected on-chain but whose attribution metadata is lost or corrupted. In `Bitcoin::get_outputs`, the `outputs` vector is declared **outside** the per-transaction loop, while the `presumed_origin`/`data` enrichment pass mutates the entire cumulative vector on **every** transaction iteration. A later transaction in the same block — including a completely unrelated one — therefore rewrites the `data` (the Serai `InInstruction` carrying the depositor's destination address) and `presumed_origin` (the refund address) of deposits made by earlier transactions in that block.

### Finding Description
`get_outputs` scans each non-coinbase transaction for outputs matching the registered offset scripts (`External`, `Branch`, `Change`, `Forwarded`):

```rust
let mut outputs = vec![];
// Skip the coinbase transaction which is burdened by maturity
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ...; outputs.push(output); }

  if outputs.is_empty() { continue; }

  let presumed_origin = { let input = &tx.input[0]; ... };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs {
    if output.kind == OutputType::External {
      output.data.clone_from(&data);
    }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
``` [1](#0-0) 

Two root-cause defects:

1. **Cumulative mutation:** `outputs` accumulates across all transactions in the block, but `for output in &mut outputs` applies `tx`'s origin and data to *every* previously collected output, not just the ones found in the current `tx`. Each later iteration overwrites the prior tx's values.
2. **Non-empty check is cumulative:** `if outputs.is_empty() { continue; }` only skips when *no* output has been seen yet. Once any deposit has been found, every subsequent transaction in the block — even one with zero outputs to Serai — triggers a full overwrite of `data` and `presumed_origin` using its own `tx.input[0]` origin and `extract_serai_data(tx)` result.

`data` is only populated for `OutputType::External` outputs and carries the depositor's `InInstruction` (e.g. a `Shorthand::transfer` destination), extracted either from an `OP_RETURN` output or from a `P2WSH` witness stack matching the `OP_SHA256 <hash> OP_EQUALVERIFY` pattern (`extract_serai_data`, `segwit_data_pattern`). [2](#0-1)  `presumed_origin` is the refund source address, taken from the first input's spent `script_pubkey`. [3](#0-2) 

### Impact Explanation
Any unprivileged party who gets an ordinary transaction included in the same block *after* a victim's deposit can:

- **Wipe the victim's `data`**: if the later tx has no `OP_RETURN`/`P2WSH` data payload, `extract_serai_data` returns `vec![]`, clearing the victim's `InInstruction`. The BTC is detected and counted as received, but with no routing instruction — the deposit is unclaimable/unspendable in the protocol's accounting, mirroring the reported bug class (funds sent to a receiver that cannot accept/process them).
- **Replace `data` with attacker-controlled bytes**: the attacker's `OP_RETURN` or witness `InInstruction` is applied to the victim's `External` output, crediting the victim's BTC to an attacker-chosen Serai destination — theft of the deposit's value.
- **Corrupt `presumed_origin`**: the refund source is set to the attacker tx's input origin, so any refund path sends the funds to an attacker-influenced address.

This satisfies the accepted-impact criterion: funds are reported received by the scanner that are not spendable/creditable as intended, and deposit value can be redirected.

### Likelihood Explanation
- The attacker controls arbitrary Bitcoin transactions and merely needs one to be ordered after the victim's deposit in the same block. Bitcoin gives the attacker several chances per block (they can broadcast many low-fee txs; miners order by fee/incentive, and the attacker can also time submission after observing the victim's tx in the mempool).
- Even without deliberate attack, any multi-deposit block or a block where a random later transaction exists after a deposit produces corrupted metadata — so deposits are routinely at risk whenever the block is non-trivial.
- No special privileges, threshold collusion, or malicious node are required — only public on-chain transaction data, which is exactly the reachable-input class allowed.

### Recommendation
Scope the enrichment pass to the current transaction's outputs only:

```rust
for tx in &block.txdata[1 ..] {
  let scanned: Vec<Output> = scanner.scan_transaction(tx)
    .into_iter()
    .map(|o| Output { kind: kinds[o.offset().to_repr().as_ref()], presumed_origin: None, output: o, data: vec![] })
    .collect();
  if scanned.is_empty() { continue; }
  let presumed_origin = /* tx.input[0] origin */;
  let data = Self::extract_serai_data(tx);
  for mut output in scanned {
    if output.kind == OutputType::External { output.data = data.clone(); }
    output.presumed_origin = presumed_origin.clone();
    outputs.push(output);
  }
}
```

Additionally, `presumed_origin` should be set per-deposit (per matching output's transaction), and a deposit that loses its `InInstruction` should still be attributable — consider refusing to finalize `External` outputs whose expected data was clobbered, and add a regression test with a deposit followed by an unrelated transaction in the same block.

### Proof of Concept
Conceptual (regtest, as exercised by `processor/src/tests/addresses.rs`):

1. Victim broadcasts `tx_v` (block index 1) with an output paying the multisig `External` P2TR script and an `OP_RETURN` containing `Shorthand::transfer(victim_serai_addr)`. `get_outputs` pushes the output and sets `data = victim_data`.
2. Attacker broadcasts `tx_a` spending their own P2PKH UTXO with an `OP_RETURN` containing `Shorthand::transfer(attacker_serai_addr)`, mined later in the same block (any index > `tx_v`). `tx_a` needs no outputs to Serai at all.
3. On the `tx_a` iteration, `outputs` is non-empty, so `data = attacker's instruction` is cloned onto `output.data` of the **victim's** `External` output, and `presumed_origin` is set to the attacker's address.
4. The scanner emits the victim's deposit carrying the attacker's `InInstruction`; the bridge credits the attacker's Serai account with the victim's BTC. If `tx_a` instead carries no data, the victim's instruction is silently wiped to `vec![]` and the deposit is received but unroutable.

  // Expected script has to start with SHA256 PUSH MSG_HASH OP_EQUALVERIFY ..
  fn segwit_data_pattern(script: &ScriptBuf) -> Option<bool> {
    let mut ins = script.instructions();

    // first item should be SHA256 code
    if ins.next()?.ok()?.opcode()? != OP_SHA256 {
      return Some(false);
    }

    // next should be a data push
    ins.next()?.ok()?.push_bytes()?;

    // next should be a equality check
    if ins.next()?.ok()?.opcode()? != OP_EQUALVERIFY {
      return Some(false);
    }

    Some(true)
  }

  fn extract_serai_data(tx: &Transaction) -> Vec<u8> {
    // check outputs
    let mut data = (|| {
      for output in &tx.output {
        if output.script_pubkey.is_op_return() {
          match output.script_pubkey.instructions_minimal().last() {
            Some(Ok(Instruction::PushBytes(data))) => return data.as_bytes().to_vec(),
            _ => continue,
          }
        }
      }
      vec![]
    })();

    // check inputs
    if data.is_empty() {
      for input in &tx.input {
        let witness = input.witness.to_vec();
        // expected witness at least has to have 2 items, msg and the redeem script.
        if witness.len() >= 2 {
          let redeem_script = ScriptBuf::from_bytes(witness.last().unwrap().clone());
          if Self::segwit_data_pattern(&redeem_script) == Some(true) {
            data.clone_from(&witness[witness.len() - 2]); // len() - 1 is the redeem_script
            break;
          }
        }
      }
    }

    data.truncate(MAX_DATA_LEN.try_into().unwrap());
    data
  }
