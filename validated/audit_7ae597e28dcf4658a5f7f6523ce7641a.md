### Title
Unrecovered type-assertion panic in the pointer precompile's CW20/CW721/CW1155 metadata parsing crashes EVM transaction execution on attacker-controlled query responses - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query a CosmWasm contract (`token_info`/`contract_info`) and then blindly type-assert the returned JSON fields as `string` (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`), without checking that the key exists or holds a string. Any unprivileged EVM caller can deploy their own CW20/CW721-shaped contract that returns a malformed `token_info`/`contract_info` response (missing `name`/`symbol`, or non-string types), then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on it from an EVM transaction, causing a Go panic (`interface conversion: interface {} is nil, not string`) inside precompile execution reachable from ordinary transactions — directly analogous to CVE-2015-2929, where a remote party supplying a malformed/unexpected-shape structure to a client caused an unhandled assertion failure crash.

### Finding Description
`AddCW20`/`AddCW721` (and the equivalent `AddCW1155` and their duplicated "legacy" versions under `precompiles/pointer/legacy/vXXX/pointer.go`) execute: [1](#0-0) 

```go
res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))
...
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
`cwAddr` (the CW contract address queried) is a fully caller-supplied argument, validated only for bech32 well-formedness: [2](#0-1) 
There is no schema/shape validation of the contract's smart-query response before the unchecked assertions. Since `wasmdKeeper.QuerySmart(Safe)` merely executes whatever CosmWasm query logic the target contract defines, any attacker who deploys a contract exposing a `token_info`/`contract_info` query handler that returns JSON without a `name`/`symbol` key (or with a non-string value, e.g. a number or `null`) will trigger `formattedRes["name"].(string)` to panic with a raw (non-`, ok`) type assertion.

Once inside precompile execution, this panic propagates up: the pointer precompile's `Execute`/`Run` and the shared `Prepare` helper across all versions (`precompiles/common/precompiles.go` and the many `legacy/vXXX` copies) do not wrap the method dispatch in a `recover()`, unlike other precompiles such as `solo` which explicitly `defer recover()` around their execution: [3](#0-2) 
No equivalent recovery exists in `pointer.go`'s `Execute`: [4](#0-3) 

The panic then reaches `x/evm/keeper/msg_server.go`'s `EVMTransaction` handler, which explicitly recovers only to log/count it and then **re-panics** (except for the OCC read-estimate sentinel): [5](#0-4) 
From there it propagates through `sei-cosmos/baseapp/baseapp.go`'s `RunMsgs`, which likewise recovers only to log and re-panic: [6](#0-5) 

### Impact Explanation
This is a reachable "malformed remote data causes unhandled panic" bug class matching CVE-2015-2929's root cause — the difference from Tor's client crash is that Sei's outer transaction-processing layers (giga executor's per-tx recover in `app.go`, and presumably the equivalent V2 baseapp DeliverTx recovery middleware referenced in the code comments) are designed to catch generic panics and convert them into a failed-transaction ABCI response rather than crashing the node process. I was not able to fully confirm, within the tool budget, whether every code path that can reach `EVMTransaction` (including RPC-triggered simulate/estimateGas/trace paths in `evmrpc/`) has an outer recovery guard equivalent to the giga/DeliverTx one; if any RPC-facing path invokes the pointer precompile's Prepare/AddCW20 logic without a wrapping recover, this could crash a public JSON-RPC node process, not just fail a single transaction.

### Likelihood Explanation
Trivial to trigger: no privileges, no economic cost beyond one CW contract deployment and one EVM transaction gas fee; a malicious CW20/CW721-mimicking contract with a broken `token_info`/`contract_info` handler is simple to write and deploy on any Sei chain (mainnet or testnet).

### Recommendation
Replace unchecked type assertions with safe, checked assertions (`v, ok := formattedRes["name"].(string)`) returning a normal `error` on failure, in `AddCW20`, `AddCW721`, `AddCW1155` across `precompiles/pointer/pointer.go` and every `precompiles/pointer/legacy/vXXX/pointer.go` copy. Additionally, add a `defer recover()` guard inside the pointer precompile's `Execute`/`Run` (mirroring `precompiles/solo`) so that any future unhandled panic degrades to a reverted transaction rather than relying solely on outer recovery layers.

### Proof of Concept
1. Deploy a CosmWasm contract whose `contract_info`/`token_info` query handler returns `{}` (no `name`/`symbol` keys) or `{"name": 123, "symbol": null}`.
2. From any EVM account, call `pointer.addCW20Pointer(cwContractAddress)` (or `addCW721Pointer`) at `0x000000000000000000000000000000000000100b`.
3. Execution reaches `formattedRes["name"].(string)` with `formattedRes["name"] == nil`, causing an `interface conversion: interface {} is nil, not string` panic inside the precompile, propagating through `msg_server.go`'s `EVMTransaction` and `baseapp.RunMsgs`'s re-panic logic.
