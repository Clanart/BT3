### Title
`payout_tx`'s SIGHASH_SINGLE|ANYONECANPAY leaves the OP_RETURN payer-identifier output unsigned, letting an attacker malleate the operator xonly_pk and permanently break payer attribution - (File: `core/src/builder/transaction/operator_reimburse.rs`, `core/src/verifier.rs`)

### Summary
`create_payout_txhandler` signs `payout_tx`'s input 0 with `TapSighashType::SinglePlusAnyoneCanPay`, which under BIP341 only commits to input 0's outpoint/amount/scriptPubKey and to output 0 (same index as the signed input). The anchor output and, critically, the OP_RETURN output carrying the fronting operator's xonly_pk are outside the signed message and can be freely replaced by anyone who observes the signature (e.g. in the mempool). `Verifier::update_finalized_payouts` trusts whichever tx actually spends the withdrawal outpoint and blindly parses its OP_RETURN as the "payer" xonly_pk with no cryptographic binding to who actually funded the payout.

### Finding Description
The claimed binding is: `withdrawals.payout_payer_operator_xonly_pk` (recorded for a withdrawal idx) == the xonly_pk of the party whose funds paid the output. Before the attack, when the honest operator's `payout_tx` is mined, this holds. After the attack it is broken.

Code path:
1. `Operator::withdraw` (`core/src/operator.rs:560-637`) builds `payout_tx` via `create_payout_txhandler` and verifies only the user's signature over input 0/output 0 (`SECP.verify_schnorr` at line 632-637). It then funds the tx with `fund_raw_transaction` (adding the operator's own inputs) and broadcasts.
2. `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds outputs: `[0] user payout, [1] anchor, [2] OP_RETURN(operator_xonly_pk)`, and signs only input 0 with the user-supplied `TapSighashType::SinglePlusAnyoneCanPay` signature (`txhandler.set_p2tr_key_spend_witness`).
3. Per BIP341, `SinglePlusAnyoneCanPay` sighash commits to: input 0's outpoint/amount/scriptPubKey (explicitly, since ANYONECANPAY), and output 0 only (SIGHASH_SINGLE). Outputs 1 and 2, and any additional inputs, are **not** covered - confirmed by `calculate_pubkey_spend_sighash`/`calculate_script_spend_sighash` using `Prevouts::One` (`core/src/builder/transaction/txhandler.rs:222-229`, `315-322`).
4. Once the honest operator's `payout_tx` is broadcast (visible in the mempool with the witness signature in the clear), an attacker builds their own transaction reusing the identical signed input 0 and output 0, but appends different funding inputs (to cover output 0's value/fees) and a different OP_RETURN payload - an arbitrary 32-byte value that is a syntactically valid xonly pubkey but belongs to no configured operator. This transaction remains valid because the signature never covered outputs 1/2.
5. If the attacker's version gets mined first (double-spending the same withdrawal outpoint, RBF-style fee competition), `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) locates the payout purely via `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`), which joins on `bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout` - i.e. whichever tx actually spent the withdrawal UTXO, with no check on which operator constructed it. It parses the OP_RETURN of that tx (`get_first_op_return_output`/`parse_op_return_data`) and stores whatever 32 bytes it finds as `payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`), with no validation that it equals any registered operator's key.
6. `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-51`) calls `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` (`core/src/database/verifier.rs:282-313`), which filters `WHERE w.payout_payer_operator_xonly_pk = $1`. Since the stored value is the attacker's junk key, it never matches any real operator, so `handle_finalized_payout`/kickoff/reimbursement is never triggered for the honest operator.
7. Additionally, `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1857-1915`) compares `operator_xonly_pk != kickoff_data.operator_xonly_pk` for **any** operator's future kickoff attempt on that deposit's `move_txid`; since the stored payer key is the attacker's junk value, it will never equal any real operator's key, so every operator's kickoff for that deposit is flagged malicious forever, permanently freezing that deposit's move-to-vault UTXO from ever being reimbursed.

No existing guard intercepts this: `SECP.verify_schnorr` only checks input 0/output 0 (by construction of the sighash), `is_deposit_valid`/`is_profitable` run before broadcast and don't re-validate the mined tx's malleated fields, and there is no on-chain or DB uniqueness/consistency check tying the OP_RETURN pubkey to an actual signature from that operator.

### Impact Explanation
- The honest operator that genuinely funded (or attempted to fund) the withdrawal permanently loses its ability to trigger `handle_finalized_payout`/kickoff/Reimburse for that withdrawal id, matching "an honest operator permanently unable to be reimbursed."
- Because `is_kickoff_malicious` compares against the same corrupted `payout_payer_operator_xonly_pk` for every operator, the underlying deposit's move-to-vault UTXO becomes unclaimable by any operator forever, matching "a move-to-vault UTXO permanently frozen."
- Repeatable across every withdrawal/deposit and every operator, since the flaw is structural in `create_payout_txhandler`'s choice of sighash flag and in `update_finalized_payouts`'s unauthenticated OP_RETURN parsing - it is not deposit- or operator-specific.

### Likelihood Explanation
- No special privileges are required: any observer of the mempool (or of any public RPC that returns the raw signed payout tx/signature) can extract the exact signature and input/output 0 needed.
- The attacker must supply additional inputs covering the full payout output value plus a competitive fee to win the block race against the honest operator's broadcast, which is a real BTC cost roughly equal to the withdrawal amount - this makes the attack costly per instance, but it requires no bridge collateral, no key compromise, and no majority hashrate; ordinary fee-bumping/RBF competition suffices.
- The attack is deterministic given code inspection; it does not depend on any timing race with Citrea, watchtowers, or verifiers - only with the honest operator's own broadcast/confirmation.

### Recommendation
Change `create_payout_txhandler`'s signature scheme so that all fields relevant to payer attribution are cryptographically bound to the actual funder:
- Have operators co-sign (or otherwise authenticate) the OP_RETURN output and any additional funding inputs/outputs they add, e.g. by using `SIGHASH_ALL` (or a covenant/committing scheme) once the operator's funding inputs are attached, instead of leaving those fields outside the user's `SinglePlusAnyoneCanPay` signature.
- Alternatively, require operators to include a per-operator signature (e.g., a Schnorr signature by the claimed `operator_xonly_pk` over the payout txid/outpoint) verified independently by verifiers before recording `payout_payer_operator_xonly_pk`, so the OP_RETURN pubkey cannot be freely set by any party that merely appends unsigned outputs/inputs.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        &self,

        sighash_type: TapSighashType,

            }
            _ => bitcoin::sighash::Prevouts::All(&prevouts_vec),
        };

        let sig_hash = sighash_cache
            .taproot_key_spend_signature_hash(txin_index, &prevouts, sighash_type)

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,

                ))

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
