## Title
Use-After-Free of Python message wrapper on message-map key overwrite during `MergeFromString`/`MergeFrom` — ([File: python/google/protobuf/pyext/message.cc])

## Summary
The external CVE-2021-21772 describes a use-after-free in lib3mf's `releaseZIP()`: a container-parsing operation frees/releases underlying storage while a higher-level handle still references it, and subsequent access to that handle touches freed memory. The transferable invariant is: **when a parse/merge operation replaces or destroys an underlying native object, any live higher-level handle/wrapper pointing at that object must be invalidated or kept valid — not silently left dangling.**

Protobuf's Python C-extension (`pyext`) has exactly this class of bug for `oneof` message fields during `MergeFrom`/`MergeFromString`, and it is explicitly fixed via `MaybeReleaseOneofBeforeMerge()` / `FixupMessageAfterMerge()` [1](#0-0) . However, the same fix explicitly **excludes repeated and map fields** from this protection, with the comment noting that for a message-valued map "with same keys, it is overwrite" [2](#0-1) . This distinguishes the (fixed) oneof case from the (unaudited) map/repeated case, which is the strongest analog surface to re-examine, though I could not fully confirm reachable exploitation.

## Finding Description
`MaybeReleaseOneofBeforeMerge` walks `composite_fields` (the map of Python wrapper objects that cache pointers into the underlying C++ `Message`) and releases (detaches) any oneof-message wrapper whose underlying field is about to be destroyed by the merge's oneof-switch, specifically to avoid the UAF documented in `testOneofSwitchMergeUAF` [3](#0-2) . The routine's filter is:

```cpp
if (descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE &&
    // For normal repeated message, MergeFrom will append the messages.
    // For message map with same keys, it is overwrite
    !descriptor->is_repeated() &&
    reflection->HasField(*message, descriptor)) {
``` [4](#0-3) 

This explicitly skips any field where `is_repeated()` is true, which includes map fields (map entries are represented internally as a repeated message field of key/value pairs). The parse path in `MergeFromStringImpl` still calls `_InternalParse` directly into a temp message and then `message->MergeFrom(*temp_message)` [5](#0-4) , so any pre-existing Python wrapper object for a map value (obtained e.g. via `msg.map_field[key]`) is not walked/released before the merge touches that map entry.

At the C++ layer, `UntypedMapBase::UntypedMergeFrom` allocates new nodes and calls `InsertOrReplaceNode`, which for a colliding key destroys/replaces the existing node's value in place [6](#0-5) . If a Python `CMessage` wrapper for that map value's message is still alive and pointing at the now-replaced/destroyed underlying `MessageLite`, subsequent attribute access on that Python object would touch freed/reused memory — the same failure mode as the (fixed) oneof case.

Notably, the project's own test suite already demonstrates this exact overwrite behavior for message-valued maps via `MergeFromString`, without any assertion that a previously obtained wrapper reference stays valid or safely detects invalidation:
```python
msg.map_int32_foreign_message[222].c = 123
msg2.map_int32_foreign_message[222].d = 20
msg.MergeFromString(msg2.SerializeToString())
self.assertEqual(msg.map_int32_foreign_message[222].d, 20)
self.assertNotEqual(msg.map_int32_foreign_message[222].c, 123)
``` [7](#0-6) 
This test only checks the final map value from a fresh accessor — it does not test whether a wrapper reference obtained *before* the merge (analogous to `sub_ref` in `testOneofSwitchMergeUAF`) remains valid, which is precisely the scenario the oneof fix was created to cover.

## Impact Explanation
If confirmed reachable, this would be a memory-safety (use-after-free) issue in the CPython extension reachable purely from an ordinary client calling the public `MergeFromString`/`MergeFrom`/`ParseFromString` API with attacker-controlled bytes, provided the application code retains a Python reference to a map-valued submessage across a subsequent merge call. Because Python object attribute access after the free could read/write freed heap memory, this is potentially memory corruption / information disclosure, matching the CVSS profile of the reference CVE (though without a demonstrated crash or PoC in this investigation, this remains unproven).

## Likelihood Explanation
Likelihood is Medium-to-uncertain: the trigger requires application-level code to (a) obtain and hold a reference to a message value inside a map field, and (b) later call `MergeFrom`/`MergeFromString` with a payload that reuses the same map key. This is a plausible, not contrived, usage pattern (analogous to the already-fixed oneof pattern), but I was not able to locate or execute a concrete reproduction confirming that the Python wrapper's underlying C++ pointer is actually freed rather than just superseded/still-valid-but-stale. The C++ map internally reuses arena-allocated node storage; whether the specific memory backing the previously-referenced value is deallocated, reused, or merely overwritten in-place (which would be a correctness bug, not a memory-safety bug) was not determined from available code excerpts (I did not locate `MessageMapContainer`'s C-extension wrapper-caching code in this pass, so I cannot state with confidence whether Python-level map value wrappers even persist independent pointers the way oneof-field wrappers do).

## Recommendation
- Audit `python/google/protobuf/pyext/map_container.cc` (or equivalent) to determine whether Python wrapper objects for message-map values cache a raw `Message*` independent of arena/node lifetime, and whether `InsertOrReplaceNode`/`UntypedMergeFrom` can free/reuse that memory while a wrapper is alive.
- If such caching exists, extend `MaybeReleaseOneofBeforeMerge` (or add an analogous routine) to also detach/release wrappers for repeated/map message fields whose entries will be overwritten by the incoming merge, mirroring the oneof fix.
- Add a regression test parallel to `testOneofSwitchMergeUAF` that retains a map-value wrapper reference across a `MergeFromString` call that overwrites the same key, and assert the wrapper either remains valid or is safely detached (not merely that a fresh lookup returns the new value).

## Proof of Concept
No working PoC was produced or run in this investigation. The closest available evidence is the existing (passing, non-UAF-detecting) test `testMapMergeFrom` (map overwrite) at `python/google/protobuf/internal/message_test.py:3231-3238`, contrasted with the UAF-detecting test `testOneofSwitchMergeUAF` at `python/google/protobuf/internal/message_test.py:2184-2202`, which shows the exact test pattern that would need to be adapted (retain `sub_ref` before merge, assert its value post-merge) to determine whether the map case is actually vulnerable. Confirming exploitability requires source access to the Python map-container wrapper implementation, which was not available in the indexed context.

int MaybeReleaseOneofBeforeMerge(CMessage* self, const Message& other) {
  CMessage::CompositeFieldsMap* composite_fields =
      self->composite_fields.TryGet();
  if (!composite_fields) {
    return 0;
  }

  Message* message = AssureWritable(self);
  if (message == nullptr) return -1;
  const Reflection* reflection = message->GetReflection();
  PyMessageFactory* factory = GetFactoryForMessage(self);
  std::vector<const FieldDescriptor*> fields_to_release;
  std::vector<std::pair<const FieldDescriptor*, ScopedPyObjectPtr>>
      nested_message_fields;
  composite_fields->ForEach([&](const void* key, PyObject* value) {
    const FieldDescriptor* descriptor =
        reinterpret_cast<const FieldDescriptor*>(key);
    if (descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE &&
        // For normal repeated message, MergeFrom will append the messages.
        // For message map with same keys, it is overwrite
        !descriptor->is_repeated() &&
        reflection->HasField(*message, descriptor)) {
      if (reflection->HasField(other, descriptor)) {
        Py_INCREF(value);
        nested_message_fields.emplace_back(descriptor, value);
      } else {
        // Release oneof message if the other message has set a different oneof
        const OneofDescriptor* oneof = descriptor->containing_oneof();
        if (oneof && reflection->HasOneof(other, oneof)) {
          fields_to_release.push_back(descriptor);
        }
      }
    }
  });

  for (const auto& [field, value] : nested_message_fields) {
    if (MaybeReleaseOneofBeforeMerge(
            reinterpret_cast<CMessage*>(value.get()),
            reflection->GetMessage(other, field, factory->message_factory)) <
        0) {
      return -1;
    }
  }

  for (const FieldDescriptor* field : fields_to_release) {
    if (InternalReleaseFieldByDescriptor(self, field) < 0) {
      return -1;
    }
  }
  return 0;
}

void UntypedMapBase::UntypedMergeFrom(Arena* arena,
                                      const UntypedMapBase& other) {
  ABSL_DCHECK_EQ(arena, this->arena());
  if (other.empty()) return;

  // Do the merging in steps to avoid Key*Value number of instantiations and
  // reduce code duplication per instantation.
  NodeBase* nodes = nullptr;

  // First, allocate all the nodes without types.
  for (size_t i = 0; i < other.num_elements_; ++i) {
    NodeBase* new_node = AllocNode(arena);
    new_node->next = nodes;
    nodes = new_node;
  }

  // Then, copy the values.
  VisitValueType([&](auto value_type) {
    using Value = typename decltype(value_type)::type;
    NodeBase* out_node = nodes;

    // Get the ClassData once to avoid redundant virtual function calls.
    const internal::ClassData* class_data =
        std::is_same_v<MessageLite, Value>
            ? GetClassData(*other.GetValue<MessageLite>(other.begin().node_))
            : nullptr;

    for (auto it = other.begin(); !it.Equals(EndIterator()); it.PlusPlus()) {
      Value* out = GetValue<Value>(out_node);
      out_node = out_node->next;
      auto& in = *other.GetValue<Value>(it.node_);
      if constexpr (std::is_same_v<MessageLite, Value>) {
        class_data->PlacementNew(out, arena)->CheckTypeAndMergeFrom(in);
      } else {
        Arena::CreateInArenaStorage(out, arena, in);
      }
    }
  });

  // Finally, copy the keys and insert the nodes.
  VisitKeyType([&](auto key_type) {
    using Key = typename decltype(key_type)::type;
    for (auto it = other.begin(); !it.Equals(EndIterator()); it.PlusPlus()) {
      NodeBase* node = nodes;
      nodes = nodes->next;
      const Key& in = *other.GetKey<Key>(it.node_);
      Key* out = GetKey<Key>(node);
      if (!internal::InitializeMapKey(out, in, arena)) {
        Arena::CreateInArenaStorage(out, arena, in);
      }

      static_cast<KeyMapBase<Key>*>(this)->InsertOrReplaceNode(
          arena, static_cast<typename KeyMapBase<Key>::KeyNode*>(node));
    }
  });
}
