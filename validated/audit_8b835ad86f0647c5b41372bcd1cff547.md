### Title
Front-runnable `castVotes()` computes vote ratio from instantaneous, unsnapshotted `totalVlMgpInVote`/`pool.totalVoteInVlmgp`, allowing flash-in/flash-out vote sandwiching - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.castVotes()` derives the vote weight pushed to the real Wombat gauge (`targetVote = pool.totalVoteInVlmgp * totalVotes() / totalVlMgpInVote`) purely from the current state of two mutable accumulators that `vote()`/`unvote()` update instantly and without any cooldown, snapshot, or time-weighting. An attacker with a real, already-locked vlMGP balance can call `vote(+delta)` immediately before a pending `castVotes()` transaction, let it execute with the skewed ratio, and then call `vote(-delta)` in the same block to withdraw, since `BribeRewardPool.stakeFor`/`withdrawFor` impose no lock period.

### Finding Description
`castVotes()` reads `pool.totalVoteInVlmgp` and `totalVlMgpInVote` at call time to compute `targetVote` per pool and forwards it via `wombatStaking.vote()` to Wombat's real `IWombatVoter` [1](#0-0) . These two state variables are mutated synchronously and without delay inside `vote()`: `pool.totalVoteInVlmgp` and `totalVlMgpInVote` are incremented/decremented immediately based on `_deltas`, and the corresponding `IBribeRewardPool.stakeFor`/`withdrawFor` calls apply the balance change with no lock/cooldown [2](#0-1) [3](#0-2) .

Because there is no minimum holding period, snapshot block, or time-weighted average enforced between `vote()` and `castVotes()`, an attacker who already holds (per the stated precondition) enough locked vlMGP can:
1. Call `vote(pool, +delta)` to inflate `pool.totalVoteInVlmgp` and `totalVlMgpInVote` right before a pending `castVotes()` transaction lands.
2. Let `castVotes()` (called by anyone, including the attacker) execute, computing `targetVote` using the skewed ratio and pushing it to `wombatStaking.vote()`, which forwards it to the real Wombat `voter` contract.
3. Immediately call `vote(pool, -delta)` in the same block to withdraw, restoring `pool.totalVoteInVlmgp` and `totalVlMgpInVote` to their pre-attack values.

No existing modifier (`nonReentrant`, `whenNotPaused`) or accounting check blocks this because `getUserVotable`/`userTotalVotedInVlmgp` checks only enforce that the user's outstanding vote doesn't exceed their locked balance at each individual transaction — they do not prevent rapid stake-then-unstake within one block, and `castVotes()` has no protection against being sandwiched.

### Impact Explanation
The Wombat gauge vote actually submitted via `wombatStaking.vote()` is persisted on Wombat's `voter` contract and remains in effect until the next `castVotes()` call (which could be a day or more later, per `lastCastTime` usage patterns). By sandwiching a single `castVotes()` call, an attacker can temporarily but materially skew the real allocation of votes/emissions across Wombat LP pools without sustaining that vlMGP backing, matching the "governance voting result manipulation of real Wombat LP gauge allocations" impact class explicitly scoped in this audit.

### Likelihood Explanation
Exploitation requires: (a) the attacker already holds a large amount of locked vlMGP (stated precondition, not flash-loanable since vlMGP presumably requires locking MGP over time), (b) the ability to front-run/back-run a public `castVotes()` transaction within the same block, which is straightforward on any chain with a public mempool or via MEV/bundling. `castVotes()` can be called by any third party (`override public`, no access control), making it a predictable, repeatable target. No special privileges are needed beyond capital and standard front-running tooling.

### Recommendation
Decouple the vote ratio used in `castVotes()` from instantaneous, freely-mutable state:
- Snapshot `pool.totalVoteInVlmgp` and `totalVlMgpInVote` at a fixed point (e.g., using a checkpoint/epoch system) rather than reading live values during `castVotes()`.
- Enforce a minimum holding/lock period for votes before they count toward `castVotes()` (e.g., votes must be held for N blocks or until the next epoch boundary).
- Alternatively, disallow `vote()`/`unvote()` calls within the same block as, or immediately surrounding, a `castVotes()` call (e.g., via a per-block or per-epoch guard).

### Proof of Concept
Foundry/Hardhat fork test plan:
1. Deploy/fork with `WombatBribeManager`, `WombatStaking`, and a low-liquidity pool with small existing `totalVoteInVlmgp`.
2. Have a benign user submit a `castVotes(false)` transaction (pending in mempool).
3. Attacker, holding a large pre-locked vlMGP balance, front-runs with `vote([targetPool], [+delta])`, materially inflating `pool.totalVoteInVlmgp` and `totalVlMgpInVote`.
4. Let `castVotes(false)` execute; record `targetVote` computed for `targetPool` (via emitted event or by reading `getVoteForLp(targetPool)` after the call) and compare with a control run without step 3.
5. Attacker back-runs immediately with `vote([targetPool], [-delta])` in the same block, restoring `pool.totalVoteInVlmgp` and `totalVlMgpInVote`.
6. Assert: `targetVote_withAttack != targetVote_withoutAttack` (materially different), while `pool.totalVoteInVlmgp` and `totalVlMgpInVote` after step 5 equal their pre-attack values — proving the attacker altered the real Wombat vote sent via `wombatStaking.vote()` without any sustained vlMGP backing.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Updates informaiton for a user in case of a withdraw. Can only be called by the Masterchief operator
    /// @param _for Address account
    /// @param _amount Amount of withdrawed tokens by the user on masterchief
    function withdrawFor(
        address _for,
        uint256 _amount,
        bool claim
    ) external virtual onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply - _amount;
        _balances[_for] = _balances[_for] - _amount;

        emit Withdrawn(_for, _amount);

        if (claim) {

        }
    }
