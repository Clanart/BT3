### Title
Gasless swap admission relies on an unprotected DEX spot-price call (`GetAmountIn`), enabling oracle/price manipulation of `swapForGas` mempool admission - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Vesper Finance incident exploited a lending pool that priced collateral/borrow amounts from a manipulable on-chain price source (a thinly-liquidity Uniswap V3 pool), letting the attacker inflate the price in one transaction sequence and borrow far more than the real value of the collateral. Kaia's KIP-247 gasless-transaction module performs an analogous unprotected read of a DEX-derived exchange rate to gate `swapForGas` transactions into the transaction pool / bundle: `checkBalanceForSwap` calls `GaslessSwapRouter.GetAmountIn(token, minAmountOut)`, a live view call into the router (backed by a DEX pool), with no TWAP or deviation protection.

### Finding Description
`GaslessModule.checkBalanceForSwap` computes the "required" `amountIn` for a swap purely from the current on-chain state via a single, un-cached call to the gasless swap router: [1](#0-0) 

This value comes from `GaslessSwapRouter.GetAmountIn`, which is a thin wrapper querying the DEX for the token's current exchange rate: [2](#0-1) 

The same routine is also what ultimately performs the swap for gas, driven from state that any unprivileged address can influence in the same block by trading against the token's DEX pool directly before submitting (or bundling ahead of) a `GaslessApproveTx`/`GaslessSwapTx` pair: [3](#0-2) 

Because the admission check (`checkBalanceForSwap`, invoked from `GetCheckBalance` used at pool admission) and the actual execution both read from the *current* state of the same DEX pool with no protection against short-term manipulation (no TWAP, no maximum price-impact bound, no minimum liquidity requirement enforced at the kaia layer), an attacker who moves the pool's spot price with a preceding swap can:
- force `requiredAmountIn` to be temporarily depressed, allowing a `swapForGas` to pass admission with a smaller `amountIn` than the honest exchange rate would require, extracting more `KAIA`/gas value than the token amount justifies, or
- force `requiredAmountIn` to spike, causing honest gasless users' transactions to be rejected (denial of gasless service), and then execute at a favorable rate for the attacker once reverted back.
This mirrors the Vesper/Rari Fuse root cause: a lending/gasless module trusting a spot AMM price without manipulation resistance, reachable purely by submitting ordinary transactions (an unprivileged trade against the pool followed by/bundled with `swapForGas`).

### Impact Explanation
Successful manipulation lets an attacker cause the block proposer's `LendTxGenerator`-funded gas advance (paid by the proposer per KIP-247) to be repaid with a manipulated/undervalued amount of tokens, directly costing the proposer/protocol value analogous to the $3M drained from Vesper via oracle manipulation. This satisfies "fee/fee-delegation abuse" and "gasless settlement theft" criteria, and is High-severity because it is a direct value-extraction path reachable by any transaction sender controlling the target token/DEX pool liquidity.

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to control or manipulate a DEX pool for a specific `allowedToken` registered in the `GaslessSwapRouter`'s allow-list (`g.allowedTokens`), and the check is performed against `nil` (latest state) at admission time, then again by the router logic during actual swap execution which is itself against the pool. Exact quantification of profit depends on the router's internal AMM math and slippage guard (`minAmountOut`/`amountRepay` checks) which are only partially visible in the compiled Go bindings; the Solidity source of `GaslessSwapRouter.sol` was not found in this index, so the full extent of on-chain slippage protection inside the swap itself could not be fully confirmed.

### Recommendation
- Use a time-weighted or multi-block price for `GetAmountIn` rather than pure spot price, or bound the maximum allowed deviation between the admission-time and execution-time price.
- Enforce a minimum liquidity/reserve threshold for tokens allowed into the gasless allow-list.
- Consider re-validating `checkBalanceForSwap`'s price condition immediately before block-inclusion (not just at initial pool admission), and add a max price-impact guard within `GaslessSwapRouter` itself, not only the `minAmountOut/amountRepay` sender-supplied bound (which the attacker also controls).

### Proof of Concept
1. Attacker identifies a low-liquidity ERC20 registered in `GaslessSwapRouter`'s `allowedTokens` (governance-controlled but reachable once a token is allowed).
2. Attacker performs a large token→WKAIA (or vice versa) swap against the same DEX pair used by `GetAmountIn`, moving the spot price.
3. In the same or a following block, attacker submits `GaslessApproveTx` + `GaslessSwapTx` (`swapForGas`) with `amountIn` computed against the manipulated price; `checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` accepts it because `GetAmountIn` returns the manipulated `requiredAmountIn`.
4. Attacker reverts the pool price (sells back) after the bundle executes, having received gas advanced by `LendTxGenerator` while repaying below fair value, or having denied honest users' admission during the price spike window. [4](#0-3)

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}

		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

// GetAmountIn is a free data retrieval call binding the contract method 0x632db21c.
//
// Solidity: function getAmountIn(address token, uint256 amountOut) view returns(uint256 amountIn)
func (_GaslessSwapRouter *GaslessSwapRouterCaller) GetAmountIn(opts *bind.CallOpts, token common.Address, amountOut *big.Int) (*big.Int, error) {
	var out []interface{}
	err := _GaslessSwapRouter.contract.Call(opts, &out, "getAmountIn", token, amountOut)

	if err != nil {
		return *new(*big.Int), err
	}

	out0 := *abi.ConvertType(out[0], new(*big.Int)).(**big.Int)

	return out0, err

}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()
