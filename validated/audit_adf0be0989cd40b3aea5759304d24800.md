### Title
Untrusted promotion map containing the local participant causes a panic - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` validates the number and upper bound of participant indexes in `proofs`, but does not reject the local participant index `params.i()`. A malformed caller-supplied map containing `params.i()` and omitting another valid participant satisfies the `n - 1` length check, then reaches `proofs.get(&i).unwrap()` for the omitted participant and panics. [1](#0-0) 

### Finding Description
The function expects `proofs` to contain every participant except `params.i()`, but it only checks `proofs.len() == n - 1` and that each key is at most `n`. [2](#0-1)  Because the map may contain `params.i()`, these checks do not prove that all other indexes `1..=n` are present; by pigeonhole, at least one required participant is missing. [3](#0-2)  The subsequent iteration unconditionally unwraps each required participant's proof, converting the missing map entry into a panic rather than a `PromotionError`. [4](#0-3) 

### Impact Explanation
An unprivileged party that can influence the participant-to-proof map passed to `complete` can crash the promotion participant instead of receiving a recoverable validation error. [1](#0-0)  This is analogous to the reported null-pointer dereference: an unchecked missing object is dereferenced through `Option::unwrap`, producing a local denial of service from untrusted input. [5](#0-4) 

### Likelihood Explanation
The malformed map is short and does not require valid proofs because the panic occurs before the missing participant's proof is verified. [4](#0-3)  Exploitation requires the caller to accept attacker-controlled participant mappings rather than constructing `proofs` exclusively from authenticated participant identities.

### Recommendation
Before iterating, reject `proofs.contains_key(&params.i())`, or replace the unconditional `unwrap` with `ok_or(PromotionError::InvalidParticipant { n: params.n(), participant: i })?`. [6](#0-5)  A direct map membership check for every expected participant would be less error-prone than relying on length and upper-bound checks. [2](#0-1) 

### Proof of Concept
For an `n`-of-`n` promotion where the local participant is `params.i() = 2`, supply a `HashMap` with `n - 1` entries keyed `{2, 3, ..., n}`; participant `1` is absent while the length and key-range checks still pass. [7](#0-6)  When the loop reaches `i = 1`, `proofs.get(&i)` returns `None` and `unwrap()` panics before any proof verification is attempted. [4](#0-3) 

```rust
// Conceptual trigger:
// params.i() == Participant(2), params.n() >= 2.
let mut proofs = HashMap::new();
proofs.insert(Participant::new(2).unwrap(), syntactically_valid_proof);
for i in 3 ..= params.n() {
  proofs.insert(Participant::new(i).unwrap(), syntactically_valid_proof);
}
// proofs.len() == n - 1 and every key <= n, but participant 1 is absent.
promotion.complete(&proofs); // panics at proofs.get(&1).unwrap()
```

  pub fn complete(
    self,
    proofs: &HashMap<Participant, GeneratorProof<C1>>,
  ) -> Result<ThresholdKeys<C2>, PromotionError> {
    let params = self.base.params();
    if proofs.len() != (usize::from(params.n()) - 1) {
      Err(PromotionError::IncorrectAmountOfParticipants {
        t: params.n(),
        n: params.n(),
        amount: proofs.len() + 1,
      })?;
    }
    for i in proofs.keys().copied() {
      if u16::from(i) > params.n() {
        Err(PromotionError::InvalidParticipant { n: params.n(), participant: i })?;
      }
    }

    let mut verification_shares = HashMap::new();
    verification_shares.insert(params.i(), self.proof.share);
    for i in 1 ..= params.n() {
      let i = Participant::new(i).unwrap();
      if i == params.i() {
        continue;
      }

      let proof = proofs.get(&i).unwrap();
      proof
        .proof
        .verify(
          &mut transcript(&self.base.original_group_key(), i),
          &[C1::generator(), C2::generator()],
          &[self.base.original_verification_share(i), proof.share],
        )
        .map_err(|_| PromotionError::InvalidProof(i))?;
