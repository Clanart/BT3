### Title
Wallet RPC `sign_message_by_address`/`sign_message_by_id` unsafe-mode raw signing acts as a coin-spend authorization oracle - (File: chia/wallet/wallet_rpc_api.py)

### Summary
The wallet RPC's message-signing endpoints (`sign_message_by_address`, `sign_message_by_id`) sign whatever raw bytes a caller supplies using the exact same key and signing primitive (`AugSchemeMPL.sign` with the standard-coin `synthetic_secret_key`) that authorizes real on-chain coin spends via `AGG_SIG_ME`. When `safe_mode=False` and `is_hex=True`, no CHIP-0002 domain-separation prefix ("Chia Signed Message") is applied, so a caller can request a signature over `delegated_puzzle_hash + coin_id + AGG_SIG_ME_ADDITIONAL_DATA` — all publicly computable values — and receive back a signature that is directly usable to authorize a real spend of that coin. This mirrors the MSQ report's core concern: a "protected"/administrative RPC surface (here the local wallet RPC) exposes a raw signing primitive without any consent screen or "harmful transaction" detection, letting a caller obtain fund-moving authorization under the guise of an innocuous "sign a message" action.

### Finding Description
`sign_message_by_address()` and `sign_message_by_id()` fetch the wallet's `synthetic_secret_key` (the same key used to satisfy `AGG_SIG_ME` conditions in standard-coin spends) and call `sign_message()` with a caller-controlled `signing_mode`. [6](#0-5) 

`signing_mode_enum()` derives the mode purely from caller-supplied `is_hex`/`safe_mode` flags on the request object; when `is_hex=True` and `safe_mode=False` it selects `BLS_MESSAGE_AUGMENTATION_HEX_INPUT`, which skips the CHIP-0002 `("Chia Signed Message", message)` tree-hash wrapping. [4](#0-3) 

`sign_message()` then signs the raw hex bytes directly: `AugSchemeMPL.sign(secret_key, hex_message)` with no additional domain separation. [5](#0-4) 

This is structurally identical to how a real standard-coin spend is authorized: `AugSchemeMPL.sign(synthetic_secret_key, delegated_puzzle_hash + coin.name() + AGG_SIG_ME_ADDITIONAL_DATA)`. [1](#0-0) [7](#0-6) 

`delegated_puzzle_hash`, `coin.name()` (parent id, puzzle hash, amount), and the network's `AGG_SIG_ME_ADDITIONAL_DATA` constant are all public/derivable data — an attacker does not need any wallet secret to construct this 32+-byte message; they only need the wallet to sign it. The `safe_mode` toggle is the only guard against this, and it is entirely caller-controlled with no server-side inspection of whether the "message" looks like a spend-authorization payload — exactly the "harmful transaction detection" gap the MSQ report flagged as the critical missing control for message-signing APIs.

### Impact Explanation
Any entity able to invoke the wallet RPC's `sign_message_by_address`/`sign_message_by_id` endpoints (a local process, a CLI/GUI bridge, or any less-trusted caller reaching this "semi-trusted local/admin surface" as documented) can obtain a valid `AGG_SIG_ME` signature for an arbitrary standard-coin spend of the target address/DID/NFT p2 puzzle hash, without the wallet ever constructing, reviewing, or logging a transaction. Combined with a known `delegated_puzzle` (e.g., one paying the attacker), this yields unsigned/unauthorized coin movement — a critical fund-theft primitive — while the wallet UI shows only "message signing" activity, not a transaction.

### Likelihood Explanation
Exploitation requires only knowledge of the coin's public identity (parent id, puzzle hash, amount — all visible on-chain) and the ability to call one existing, unauthenticated-by-content RPC endpoint with attacker-chosen `safe_mode=False`/`is_hex=True` parameters; both are already exercised in the endpoint's own test suite, showing the code path is live and reachable through the standard client. [8](#0-7) 

### Recommendation
Do not allow raw/unsafe signing (`safe_mode=False`) over the same key material used for on-chain spend authorization from a generic "sign message" RPC. Either: (1) always apply CHIP-0002 domain separation for `sign_message_by_address`/`sign_message_by_id` regardless of caller-supplied flags, removing the `safe_mode=False` raw-signing path entirely for these endpoints, or (2) if raw signing must be retained for compatibility (e.g., hardware wallet flows), inspect the message for `AGG_SIG_ME`/coin-id-shaped patterns and require explicit user confirmation before signing, analogous to the "harmful transaction detection" the MSQ dApp added for its sign API.

### Proof of Concept
1. Observe (or select) any coin locked by the standard `p2_delegated_puzzle_or_hidden_puzzle` puzzle with hash `phash` and coin id `coin.name()` for a chosen `delegated_puzzle` that transfers the coin's value to the attacker.
2. Compute `msg = delegated_puzzle.get_tree_hash() + coin.name() + AGG_SIG_ME_ADDITIONAL_DATA` (public values, network constant known).
3. Call wallet RPC `sign_message_by_address(address=<owner address of phash>, message=msg.hex(), is_hex=True, safe_mode=False)`.
4. Use the returned `signature` together with a `CoinSpend(coin, puzzle_reveal, solution_for_delegated_puzzle(delegated_puzzle, ...))` to build a `SpendBundle` and submit it via `push_tx` — the signature satisfies the `AGG_SIG_ME` condition and the spend is accepted, moving the coin to the attacker without the wallet ever presenting a transaction-approval UI.

def make_aggsig_final_message(
    opcode: ConditionOpcode,
    msg: bytes,
    spend_conditions: Coin | SpendConditions,
    agg_sig_additional_data: dict[ConditionOpcode, bytes],
) -> bytes:
    if isinstance(spend_conditions, Coin):
        coin = spend_conditions
    elif isinstance(spend_conditions, SpendConditions):
        coin = Coin(spend_conditions.parent_id, spend_conditions.puzzle_hash, uint64(spend_conditions.coin_amount))
    else:
        raise ValueError(f"Expected Coin or Spend, got {type(spend_conditions)}")  # pragma: no cover

    COIN_TO_ADDENDUM_F_LOOKUP: dict[ConditionOpcode, Callable[[Coin], bytes]] = {
        ConditionOpcode.AGG_SIG_PARENT: lambda coin: coin.parent_coin_info,
        ConditionOpcode.AGG_SIG_PUZZLE: lambda coin: coin.puzzle_hash,
        ConditionOpcode.AGG_SIG_AMOUNT: lambda coin: int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PUZZLE_AMOUNT: lambda coin: coin.puzzle_hash + int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PARENT_AMOUNT: lambda coin: coin.parent_coin_info + int_to_bytes(coin.amount),
        ConditionOpcode.AGG_SIG_PARENT_PUZZLE: lambda coin: coin.parent_coin_info + coin.puzzle_hash,
        ConditionOpcode.AGG_SIG_ME: lambda coin: coin.name(),
    }
    addendum = COIN_TO_ADDENDUM_F_LOOKUP[opcode](coin)
    return msg + addendum + agg_sig_additional_data[opcode]

def signing_mode_enum(request: SignMessageByAddress | SignMessageByID) -> SigningMode:
    if request.is_hex and request.safe_mode:

    elif not request.is_hex and not request.safe_mode:
        return SigningMode.BLS_MESSAGE_AUGMENTATION_UTF8_INPUT

def sign_message(secret_key: PrivateKey, message: str, mode: SigningMode) -> SignMessageResponse:
    public_key = secret_key.get_g1()
    if mode == SigningMode.CHIP_0002_HEX_INPUT:
        hex_message: bytes = Program.to((CHIP_0002_SIGN_MESSAGE_PREFIX, bytes.fromhex(message))).get_tree_hash()
    elif mode == SigningMode.BLS_MESSAGE_AUGMENTATION_UTF8_INPUT:
        hex_message = bytes(message, "utf-8")
    elif mode == SigningMode.BLS_MESSAGE_AUGMENTATION_HEX_INPUT:
        hex_message = bytes.fromhex(message)
    else:
        hex_message = Program.to((CHIP_0002_SIGN_MESSAGE_PREFIX, message)).get_tree_hash()
    return SignMessageResponse(
        pubkey=public_key,
        signature=AugSchemeMPL.sign(secret_key, hex_message),
    )
