### Title
FROST cached preprocess reused across `share` and `complete`, enabling nonce reuse and secret share recovery - (File: crypto/frost/src/sign.rs)

### Summary
`AlgorithmMachine::seeded_preprocess` deterministically derives the FROST nonces `(d, e)` from a 32-byte seed (`ChaCha20Rng::from_seed(*seed.0)`), and `AlgorithmSignMachine::from_cache` regenerates the *identical* nonces whenever the same `CachedPreprocess` is presented [1](#0-0) . The crate documents that a cached preprocess "MUST only be used once" because reuse leaks the private key share [2](#0-1) . Serai's own signing stack stores that seed in `CachedPreprocesses` keyed only by a fixed `context`, never deletes it, and calls `share_internal` — which reloads the seed via `preprocess_internal` — twice per protocol run: once from `DkgConfirmer::share` and again inside `DkgConfirmer::complete` [3](#0-2) . Because each `share_internal` invocation re-executes `machine.sign(preprocesses, msg)` with the same nonces but an attacker-influenced participant set, the same `(d, e)` is consumed twice with different binding factors — the classic FROST nonce-reuse break.

### Finding Description
- `seeded_preprocess` derives both FROST nonce scalars and all addendum randomness solely from the cached seed, so `from_cache` with the same `CachedPreprocess` is a pure function of the seed [4](#0-3) .
- `preprocess_internal` only writes the cached seed `if CachedPreprocesses::get(...).is_none()` and never removes it after use; every later call hits `from_cache` with the same seed and emits a fresh signature share over re-derived nonces [5](#0-4) .
- `DkgConfirmer::complete` unconditionally calls `share_internal` a second time (after `share` already produced a share), so `SignMachine::sign` runs twice on identical nonces [6](#0-5) .
- The preprocess set fed into `sign` is built from whatever `HashMap<Participant, Vec<u8>>` the coordinator aggregated; a peer can cause the two invocations to see different signer sets (e.g., withhold/deliver additional preprocesses between the share and complete rounds). `sign` computes per-participant binding factors `rho` over the included set, so different sets yield `rho1 ≠ rho2` for the same signer [7](#0-6) .
- Each share is of the form `s_i = d + rho_i·e + λ_i·c_i·x`. With two shares, the public `rho_i`, `λ_i`, `c_i` give two linear equations in the two unknowns `e` and the secret share `x`, so an observer solves for `x`.

### Impact Explanation
Recovery of a validator's MuSig/FROST secret share over Ristretto (`ThresholdKeys<Ristretto>` secret) — the exact primitive the `CachedPreprocess` docs warn must never be reused. With `t` recovered shares (or combined with a corrupt minority), the set key — the DKG-confirmed validator set key protecting Substrate↔network bridge operations — is compromised, enabling forged `set_keys` signatures and theft of bridged funds. This is key-share recovery, the highest-impact accepted analog class.

### Likelihood Explanation
No malicious internal state is required: the deterministic reuse happens on every honest execution of `DkgConfirmer::complete`, which calls `share_internal` even though `share` already consumed the seed. An unprivileged counterparty only needs to influence which preprocess messages reach the signer before each round — e.g., by timing their own preprocess transmission — to force the two `sign` calls onto different `preprocesses` maps and hence different binding factors. Even absent adversarial timing, re-attempts keyed to the same `(b"DkgConfirmer", attempt)` context reuse the seed outright.

### Recommendation
Consume-once semantics must be enforced, not documented: delete `CachedPreprocesses` the moment `from_cache` is invoked (or atomically inside `preprocess_internal` after loading), and make `DkgConfirmer::complete` reuse the `AlgorithmSignatureMachine` produced by `share` rather than re-running `share_internal`. Longer-term, key the cache by a per-session nonce included in the signing transcript so a stale seed can never satisfy a new session.

### Proof of Concept
1. Validator V runs `DkgConfirmer::preprocess` / `share` for context `(b"DkgConfirmer", attempt)`, loading seed `k` from `CachedPreprocesses` and emitting share `s1` over nonces `(d, e)` and signer set `I1` with binding factor `rho1` for V.
2. A peer delivers preprocesses so that `complete` is invoked with a different map `I2` (e.g., including an extra participant's preprocess withheld in round 1). `complete` → `share_internal` → `preprocess_internal` → `from_cache(k)` regenerates the identical `(d, e)` [8](#0-7) .
3. `machine.sign` emits `s2 = d + rho2·e + λ2·c2·x` with `rho2 ≠ rho1` because the challenge transcript covers the sorted `included` set [7](#0-6) .
4. The attacker computes `e = (s1 − s2 − (λ1c1 − λ2c2)x)/…` — equivalently solves the 2×2 linear system over `Ristretto::F` for `(e, x)` — recovering V's secret share `x`, since `rho1, rho2, λ1, λ2, c1, c2` are all publicly derivable from the broadcast preprocesses and message.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
