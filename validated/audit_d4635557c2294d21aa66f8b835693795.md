### Title
Deterministic CachedPreprocess reuse across signing invocations leaks the FROST secret share via nonce reuse - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`preprocess_internal` deterministically regenerates the FROST signing nonces from a seed cached in `CachedPreprocesses`, keyed only by `context`. The cached seed is never consumed or deleted. Every call to `preprocess_internal`/`share_internal` for the same context rebuilds an `AlgorithmSignMachine` with *identical* nonces via `AlgorithmSignMachine::from_cache` → `seeded_preprocess` → `ChaCha20Rng::from_seed(*seed.0)`. If `share_internal` is invoked more than once for the same context — e.g., a retry after `sign` returns `InvalidPreprocess`/`InvalidShare`, or a second signing attempt with a different signing set or message — the validator signs twice with the same nonce pair, enabling third-party recovery of its private key share. This is the exact analog of the referenced bug class: secret material exposed to a party who only observes public protocol outputs (two signature shares).

### Finding Description
In `SigningProtocol::preprocess_internal`, the preprocess seed is stored under `CachedPreprocesses: (context) -> [u8; 32]` and reused unconditionally on every subsequent call for that context (`coordinator/src/tributary/signing_protocol.rs:123-145`). `from_cache` feeds the seed into `ChaCha20Rng::from_seed` and derives the same `Nonce`s and `Commitments` (`crypto/frost/src/sign.rs:121-145`, `:268-274`). `share_internal` then calls `machine.sign(preprocesses, msg)` with whatever preprocess set and message the coordinator layer passes (`signing_protocol.rs:150-180`). The FROST documentation itself states: "Reusing preprocesses would enable a third-party to recover your private key share" (`spec/cryptography/FROST.md:51-55`), and `SignMachine::cache`/`from_cache` carry a MUST-not-reuse contract (`crypto/frost/src/sign.rs:209-224`). The coordinator violates this contract at the storage layer: the seed persists in the DB, so any code path that reaches `share_internal` twice for one `context` — including a failed `sign` that returns `Err(Participant)` and is retried with a modified preprocess map — produces two signature shares `s = d + (rho·e + λ·c·share)` over the same `(d, e)` but different `rho`/`c`, leaking `share` algebraically to anyone who observes both shares (they are broadcast over authenticated but public channels).

### Impact Explanation
Recovery of a validator's MuSig/tributary signing key share by any observer of the protocol transcript, using only public outputs (two signature shares and the preprocess commitments). With threshold-many compromised shares this collapses to full group key recovery; even a single share weakens the threshold assumption the DKG provides. Confidentiality and integrity impact matches the High-severity source advisory class (sensitive credential material disclosed to unauthorized actors).

### Likelihood Explanation
Reachability requires only that `share_internal` (or `preprocess_internal` followed by a re-sign) execute twice for an identical `context`. The code takes no defensive step to prevent this: there is no "spent" flag, no deletion of `CachedPreprocesses` after `sign`, and `sign`'s `Err(InvalidPreprocess(p) | InvalidShare(p))` path explicitly contemplates a faulted round that higher layers may retry. Whether any caller actually retries under an identical context depends on coordinator attempt-management; the in-scope crypto library provides no protection and the DB layer actively makes reuse the default behavior.

### Recommendation
Mark a cached preprocess as consumed once `share_internal` completes a `sign` — e.g., delete or overwrite `CachedPreprocesses` entry after use, or mix a monotonically increasing counter/attempt into the seed (`H(seed || invocation_counter)`). Alternatively, bind the seed decryption to the exact message/preprocess-set hash so a second invocation under the same context derives distinct nonces.

### Proof of Concept
1. `share_internal(ctx, participants, preprocesses_A, msg_A)` → `preprocess_internal` loads cached seed `S`, rebuilds nonces `(d, e)`, returns share `s_A`.
2. A fault occurs (or the caller simply retries): `share_internal(ctx, participants, preprocesses_B, msg_B)` → `CachedPreprocesses::get(txn, ctx)` returns the same `S` → identical `(d, e)` → share `s_B`.
3. With the same nonce commitments `D, E` and different binding factors `rho_A, rho_B` / challenges `c_A, c_B`: `share = (s_A - s_B - rho_A·e + rho_B·e)/(...)·λ⁻¹` — the secret share is recovered from the two public signature shares, directly violating the documented single-use contract of `CachedPreprocess` (`crypto/frost/src/sign.rs:83-92`).
