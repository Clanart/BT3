## Analysis

The external report's core broken invariant is: **a contract designed to move native value has no caller-side guard, and value that lands in it becomes permanently exposed/unrecoverable to the wrong party.** The Hyperbridge analog is not a governor lacking `receive()` — it's the opposite and more dangerous defect in `CallDispatcher`: a shared, persistently-funded forwarding contract whose value-moving entrypoint has **no caller restriction at all**, combined with intent-gateway sweep logic that only recovers a *known* subset of balances.

### Root cause

`CallDispatcher.dispatch()` accepts arbitrary `Call[]` and forwards arbitrary `value` from its own balance to arbitrary targets, with **zero access control** (no `onlyHost`, `onlyGateway`, `restrict`, or `msg.sender` check of any kind): [1](#0-0) 

It also holds a `receive()` so it can persistently accumulate native balance: [2](#0-1) 

`IntentsBase._execute` and `ExtrinsicIntents`'s predispatch flow route order assets *through* this shared dispatcher and then sweep back **only the tokens explicitly listed in `order.output.assets` / `order.inputs`**: [3](#0-2) [4](#0-3) 

Since `order.predispatch.call` / `order.output.call` is attacker/solver-controlled calldata (it can be a Uniswap swap or any arbitrary sequence), any residual token/ETH produced that is *not* in the declared asset list (e.g., an intermediate swap token, slippage surplus, rounding dust) is left sitting in `CallDispatcher`'s balance, unswept, indefinitely — because the sweep loop only iterates over `outputsLen`/`inputsLen`, not the dispatcher's actual balance across all tokens.

### Exploitation

Because `dispatch()` has no caller restriction, **any unprivileged external address** can call `CallDispatcher.dispatch()` directly (bypassing `IntentGatewayV2` entirely) with a `Call[]` such as `{to: attacker, value: <residual balance>, data: ""}` or an ERC20 `transfer` to themselves, stealing any value stranded there — value that belongs to the protocol (as dust) or to a legitimate order participant. This satisfies the bounty's "stealing or loss of funds" / "unauthorized transaction or execution" criteria without requiring a malicious relayer, prover, or admin — a plain externally owned account suffices.

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain residual/unswept native and token balances left by intent execution - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch()` is a public function with no caller authentication that executes arbitrary `to.call{value: call.value}(data)`. The contract is designed to be a stateless pass-through used by `IntentGatewayV2` for predispatch/postdispatch calldata execution, but `IntentsBase._execute` and the predispatch escrow flow only sweep back balances for the token addresses explicitly enumerated in `order.inputs`/`order.output.assets`. Any balance produced by attacker/solver-supplied calldata that falls outside that enumerated set (intermediate swap tokens, native ETH surplus, rounding dust) remains parked in `CallDispatcher`. Since `dispatch()` performs no `msg.sender` check, any external account can invoke it directly to pull that residual balance to an address of their choosing.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` decodes a `Call[]` and loops calling `to.call{value: call.value}(call.data)` for each entry, reverting the whole batch on any failure, but never checking who invoked `dispatch()`: [5](#0-4) . The contract also implements `receive() external payable {}`, letting it hold native balance across calls: [2](#0-1) .

`IntentGatewayV2`'s intent flows route order assets through this same dispatcher instance (`_params.dispatcher`) for predispatch (swap-then-escrow) and postdispatch (fill-then-act) execution, then sweep declared tokens back: [3](#0-2)  and [6](#0-5) . The sweep loops are bounded by `outputsLen`/`inputsLen` — i.e., only tokens that were declared as order inputs/outputs get pulled back; any other token or native-ETH surplus generated by the attacker-controlled `predispatch.call`/`output.call` payload is left behind in `CallDispatcher`.

Because `dispatch()` is globally callable, any address can invoke it against the shared `CallDispatcher` deployment to sweep out whatever balance currently sits there, regardless of which order or gateway deposited it.

### Impact Explanation
This is a direct, unauthorized loss/theft-of-funds path: value that is meant to eventually return to the protocol (as `DustCollected`) or to order participants can instead be seized by any third party via a permissionless call to a shared utility contract, matching the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories.

### Likelihood Explanation
Any solver is free to construct `order.predispatch.call`/`order.output.call` payloads (this is explicitly a supported, user/solver-controlled feature for "swap-then-escrow" and "fill-then-act" patterns), so producing an off-list token balance or ETH surplus in `CallDispatcher` is trivially achievable without any privileged role, and the follow-up drain requires only a plain, unprivileged call to `dispatch()`.

### Recommendation
Restrict `CallDispatcher.dispatch()` to an authorized caller set (e.g., an `onlyGateway`/allow-listed caller modifier), and/or make the dispatcher per-order/ephemeral (e.g., minimal proxy per execution) so no cross-call residual balance can accumulate. Additionally, harden the sweep logic in `IntentsBase._execute` / predispatch flow to enumerate and reclaim the dispatcher's *actual* balances rather than only the pre-declared asset list.

### Proof of Concept
1. A solver fills or places an order whose `output.call`/`predispatch.call` includes a DEX swap that yields a token not present in `order.output.assets`/`order.inputs` (or leaves native ETH surplus due to slippage).
2. `IntentsBase._execute` (or the predispatch flow) calls `ICallDispatcher(dispatcher).dispatch(...)`, then sweeps only the declared asset list back to `IntentGatewayV2`; the off-list token/ETH remains in `CallDispatcher`.
3. An unrelated external account calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: dispatcherBalance, data: ""})]))` directly — no check prevents this — and receives the stranded funds.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
