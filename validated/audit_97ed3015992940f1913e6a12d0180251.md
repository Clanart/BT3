## Title
Git pathspec-magic injection via colon-prefixed filenames bypasses Stop-hook diff/review scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

## Summary
`_diff_pathspec` and `_temp_index` build `git diff` / `git add --intent-to-add` pathspec argument lists directly from repo-relative filenames without disabling git's pathspec "magic" parsing (`core.literalPathspecs` is never set in `GIT_CMD`). Because git treats any pathspec string beginning with `:` as a magic signature (e.g. `:(exclude)`, `:!`) regardless of the `--` separator, an attacker-controlled filename can act as an exclude directive that removes itself and/or other legitimately-changed files from the diff the LLM reviews.

## Finding Description
`GIT_CMD` is defined once and reused for all git invocations, and never includes `-c core.literalPathspecs=true`: [1](#0-0) 

`_diff_pathspec` turns every review path into a plain repo-relative string and appends it after a single `--`: [2](#0-1) 

`get_git_diff` then runs `git diff ... baseline_sha <pathspec-list>` using that unescaped list: [3](#0-2) 

`_temp_index` similarly forwards `untracked_paths` — which are raw filenames discovered via `git status --porcelain`/`ls-files` (fully attacker-controllable, since they come from whatever files exist in the working tree) — straight into `git add --intent-to-add -- <paths>`: [4](#0-3) 

Git's pathspec matcher treats any argument beginning with `:` as a "magic" pathspec unless `core.literalPathspecs`/`--literal-pathspecs` is set or the pathspec is itself wrapped in `:(literal)`. The leading `--` before the pathspec list only stops option parsing of the *preceding* flags — it does **not** disable pathspec magic for the strings that follow. Consequently, an attacker who can place an untracked/dirty file named e.g. `:(exclude)vulnerable_file.py` (a syntactically valid POSIX filename — colons/parentheses are legal) causes two effects when its repo-relative name is passed into the pathspec list built by `_diff_pathspec`/`_temp_index`:

1. The malicious file itself is never matched as a literal path (it's consumed as an exclude directive), so its own content is silently omitted from the diff shown to the reviewing LLM.
2. Any other pathspec entry in the same invocation matching the literal name `vulnerable_file.py` is excluded from the diff result, even though `compute_v2_review_set` correctly identified it as part of the review set.

Both `get_git_diff`'s `_diff_pathspec` pathspec list and `_temp_index`'s `git add --intent-to-add` pathspec list are populated from `review_paths`/`untracked_paths`, which are derived from `compute_v2_review_set` in `diffstate.py` — i.e., directly from the current git worktree/status state that ordinary repository content (including a maliciously crafted commit, checked-out branch, or file dropped by a prompt-injected agent turn) fully controls. No existing check strips or literal-escapes pathspec magic characters anywhere in `gitutil.py` or `diffstate.py`.

## Impact Explanation
This breaks the invariant that git path scoping used for the security review must always match the intended, actually-changed files. An attacker can hide a maliciously modified/introduced source file from the Stop-hook / commit-review LLM security scan by naming a co-located file with pathspec-exclude magic, causing `handle_stop_hook` to see an empty or incomplete diff (`_skip(6)` "no changes since baseline") or a diff missing the targeted file, even though `compute_v2_review_set` correctly computed it as dirty. This is a logic-level bypass of the security-guidance plugin's core enforcement mechanism — a required security guard (automated vulnerability review before Stop) is silently defeated, matching the "bypassing a required guard" impact category.

## Likelihood Explanation
No special privilege is required beyond the ability to introduce a file with an attacker-chosen name into the working tree during a Claude Code session (e.g. via a crafted repository the agent operates on, an untrusted PR checkout, or content an agent writes as a side effect of following prompt-injected instructions from issue/PR text). Creating a file whose basename starts with `:` is a normal filesystem operation with no sandbox restriction, and the resulting bypass is deterministic and repeatable every time the Stop/commit-review hook runs a diff while that file is present in the review set.

## Recommendation
Force literal pathspec interpretation everywhere `gitutil.py` builds `git diff`/`git add` pathspecs, either by adding `-c core.literalPathspecs=true` to `GIT_CMD` globally, or by prefixing each computed pathspec entry with the `:(literal)` magic in `_diff_pathspec` and in the `add_args` construction inside `_temp_index`, so filenames beginning with `:` are always treated as literal paths rather than magic pathspec signatures.

## Proof of Concept
Integration test plan (pytest, mirroring existing tests for `gitutil.py`):
1. Init a temp git repo, commit an initial file, then create two untracked files: `":(exclude)secret.py"` containing arbitrary content, and `"secret.py"` containing an intentionally "vulnerable" code pattern (e.g. `os.system(user_input)`).
2. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture)` — assert both `":(exclude)secret.py"` and `"secret.py"` are present in the returned review set (git status correctly reports both as untracked).
3. Call `get_git_diff(repo_root, baseline_sha, paths=review_paths, untracked_paths=untracked)`.
4. Assert (current buggy behavior) that the returned diff text does **not** contain `secret.py`'s content/filename at all — demonstrating both the magic-named file and its exclude target are missing from the diff, despite both being legitimately part of the review set.
5. After applying the fix (`core.literalPathspecs=true` or `:(literal)` wrapping), rerun step 3-4 and assert the diff **does** contain both `":(exclude)secret.py"` and `"secret.py"` as added files.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
