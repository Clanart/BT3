## Finding

### Title
`aptos move verify-package` never compares on-chain module bytecode, only self-reported metadata - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
The Aptos CLI's `verify-package` command is documented and intended to "download the package from onchain and verify the bytecode matches a local compilation of the Move code" [1](#0-0) , and the docs reiterate: "checks that on-chain bytecode matches a local source tree" [2](#0-1) . In reality, `CachedPackageRegistry::create` is invoked with `with_bytecode = false`, so no on-chain module bytecode is ever fetched, and `CachedPackageMetadata::verify()` only compares `PackageMetadata` struct fields (name, deps, modules metadata, manifest, upgrade_policy, extension, source_digest) between the on-chain registry and a locally rebuilt metadata object [3](#0-2) .

### Finding Description
`PackageMetadata`/`ModuleMetadata` (as published to `0x1::code::PackageRegistry`) never contain the compiled bytecode or a hash of it — only gzipped source text and source map: [4](#0-3) . The actual module bytecode is stored separately, supplied to `code::publish_package_txn`/`code::publish_package` purely as a `vector<vector<u8>>` parameter that is disconnected on-chain from the metadata's `modules[i].source`/`source_map` fields — the native `request_publish` only checks module *names* against `expected_modules`, never that the bytecode corresponds to the declared source: [5](#0-4) .

`VerifyPackage::execute` builds the package locally, gets its metadata via `pack.extract_metadata()`, fetches the on-chain `PackageRegistry` via `CachedPackageRegistry::create(client, self.account, false)` (bytecode not fetched), and calls `package.verify(&compiled_metadata)` [6](#0-5) . `verify()` exclusively performs equality checks between the two `PackageMetadata` values, never touching real deployed bytecode: [3](#0-2) . `CachedPackageRegistry` does expose a `get_bytecode` helper that would fetch real on-chain module bytes via `get_account_module`, but it is only populated when `with_bytecode = true`, which `VerifyPackage` never sets, and `get_bytecode`/module bytecode is never used in the verify path at all [7](#0-6) .

Because the on-chain `PackageMetadata` is itself supplied by the publisher at publish time (via `code::publish_package_txn`) with no on-chain linkage to the actual module bytes, a publisher can: (1) publish `code` (real bytecode) that differs materially from what the accompanying `metadata.modules[i].source` claims to represent, and (2) `verify-package` will still report success as long as the locally-recompiled metadata (built from the claimed/matching source) is structurally equal to that same self-reported on-chain metadata. The tool is comparing "declared metadata" against "declared metadata," never validating either against the real bytecode blob that actually executes on-chain.

### Impact Explanation
This breaks the code-safety invariant that "verified bytes, package metadata, dependency declarations, and committed module bytes" must agree, per the Publish Impact Gate. Users, auditors, wallets, or third-party dependency resolution tooling that rely on `aptos move verify-package` (or the underlying `CachedPackageMetadata::verify`/`AptosPackageHooks::resolve_custom_dependency`, which downloads dependency packages via the same `CachedPackageRegistry` without bytecode verification [8](#0-7) ) to confirm that deployed contract bytecode matches published/audited source code get a false assurance of integrity. This can mislead depending packages, integrators, or end-users into trusting mainnet-deployed bytecode as "verified" when the actual executable bytecode was never checked, enabling deployment of unverified or subtly malicious modules under an apparently source-verified package.

### Likelihood Explanation
This affects every invocation of the documented `aptos move verify-package` command and the dependency-resolution flow (`resolve_custom_dependency`) as currently implemented — no special privileges are required by an attacker who controls or compromises the publishing account; they simply publish metadata whose declared `source`/`source_map` matches what a legitimate compile would produce, while supplying different actual bytecode in the `code` argument, since nothing on-chain or in the CLI cross-checks the two.

### Recommendation
`CachedPackageMetadata::verify` (and the `VerifyPackage` command) must fetch actual on-chain module bytecode (`CachedPackageRegistry::create(..., with_bytecode = true)` or equivalent `get_account_module` calls) and compare it byte-for-byte against the locally compiled bytecode units (`BuiltPackage::extract_code()`), not merely compare self-reported `PackageMetadata` structures. Additionally, consider adding an on-chain or protocol-level binding between `ModuleMetadata` source/source_map and the actual published module bytes (e.g., a bytecode hash field checked at publish time) so verification tooling has a trustworthy anchor rather than relying purely on the publisher's own metadata claims.

### Proof of Concept
1. Compile a legitimate Move package `P` with module `m` whose source is benign; extract its metadata `M` (source, source_map, manifest, deps, name, upgrade_policy all reflect the benign source).
2. Separately compile (or hand-craft) a different, malicious bytecode blob `B'` for module `m` (e.g., with an extra hidden privileged function or altered logic) that still satisfies the bytecode verifier and matches the module name `m` and address (self-address check in `third_party/move/move-vm/runtime/src/storage/publishing.rs:158-173`).
3. Publish via `code::publish_package_txn(signer, bcs(M), [B'])` — this succeeds because `request_publish` only checks module names/dependency policy, not that `B'` was compiled from `M.modules[0].source`.
4. Run `aptos move verify-package --account <addr>` using the original benign source package `P`. `VerifyPackage::execute` recompiles `P` to get `compiled_metadata` (== `M`), fetches on-chain `PackageRegistry` (metadata only, `with_bytecode=false`), and calls `package.verify(&compiled_metadata)`, which succeeds because both sides are the same self-reported `M` — despite the actually deployed bytecode being `B'`, not derived from the shown source at all.
5. Output: "Successfully verified source of package," even though the real on-chain executable bytecode was never inspected or compared.

        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    /// Returns the list of packages in this registry by name.
    pub fn package_names(&self) -> Vec<&str> {
        self.inner
            .packages
            .iter()
            .map(|p| p.name.as_str())
            .collect()
    }

    /// Finds the metadata for the given module in the registry by its unique name.
    pub async fn get_module(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedModuleMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            for module in &package.modules {
                if module.name == name {
                    return Ok(CachedModuleMetadata { metadata: module });
                }
            }
        }
        bail!("module `{}` not found", name)
    }

    /// Finds the metadata for the given package in the registry by its unique name.
    pub async fn get_package(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedPackageMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            if package.name == name {
                return Ok(CachedPackageMetadata { metadata: package });
            }
        }
        bail!("package `{}` not found", name)
    }

    /// Gets the bytecode associated with the module.
    pub async fn get_bytecode(
        &self,
        module_name: impl AsRef<str>,
    ) -> anyhow::Result<Option<&[u8]>> {
        Ok(self
            .bytecode
            .get(module_name.as_ref())
            .map(|v| v.as_slice()))
    }
