## Title
Unchecked type assertion on attacker-controlled CosmWasm query response causes EVM node panic in pointer precompile - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query a CosmWasm contract that the caller freely chooses (`{"token_info":{}}` / `{"contract_info":{}}`), JSON-decode the raw response into `map[string]interface{}`, and then perform unchecked type assertions `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)` on the decoded values. Because the queried contract is entirely attacker-controlled, an attacker can deploy a CW20/CW721/CW1155 contract whose `name`/`symbol` fields are non-string JSON values (numbers, objects, arrays) or omitted entirely, causing a Go `interface conversion` panic when a pointer is created for that contract.

### Finding Description
`AddCW20` (and the analogous `AddCW721`/`AddCW1155`) in `precompiles/pointer/pointer.go` does: [1](#0-0) 

The call chain is: `cwAddr := args[0].(string)` (safe, guaranteed by ABI decoding) → `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))` returns raw bytes produced entirely by the target CosmWasm contract's query handler → `json.Unmarshal(res, &formattedRes)` decodes into a generic `map[string]interface{}` → `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` assert, without any `, ok` check, that the decoded values are strings.

Unlike the ABI-arg type assertions elsewhere in the precompiles (e.g. `args[0].(string)`), which are safe because `ethabi.Unpack` already enforces the ABI type before the executor runs, this assertion operates on data that originates from an arbitrary, attacker-deployed CosmWasm contract's smart-query response. Any CW20/CW721/CW1155 contract can return a `token_info`/`contract_info` JSON payload where `name` or `symbol` is a number, boolean, array, object, or simply absent (yielding `nil`), and the type assertion will panic with `interface conversion: interface {} is <type>, not string`.

This mirrors the reported OBI bug class exactly (CWE-704 unchecked type assertion, e.g. `parseFirstField`'s unchecked cast on a BSON field assumed to be a string), except here the "attacker-controlled wire message" is a CosmWasm contract's smart query response rather than a MongoDB wire message, and the trigger is a public EVM transaction calling the `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` precompile method against a contract the attacker deployed and controls.

### Impact Explanation
A panic inside precompile execution during EVM message processing, if not recovered at a sufficiently high level in the EVM/ante/msg-server pipeline, terminates the transaction's processing goroutine ungracefully rather than reverting with an error. Even if some outer layer eventually recovers the panic (unconfirmed from available code — the top-level recover behavior in `x/evm/keeper/msg_server.go` and `precompiles/common/precompiles.go` could not be fully traced within the available iterations), this remains a robustness/DoS-class defect reachable by any unprivileged CosmWasm contract deployer: they deploy a minimal CW20/CW721/CW1155-like contract with a malformed `token_info`/`contract_info` response, then call the `pointer` precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` method against it from a plain EVM transaction. Because this executes during normal block processing (not merely a static call), an unrecovered panic here would affect all validators processing the block identically, risking a validator halt or crash of the node executing the block — squarely in the "crash of default-configuration node" / "validator halt" impact category.

### Likelihood Explanation
High: no privileged access is required. A contract deployer can permissionlessly instantiate a CosmWasm contract with a crafted `token_info`/`contract_info` query response and then call the pointer precompile from an EVM transaction — both steps are available to any unprivileged public RPC client.

### Recommendation
Replace the unchecked type assertions with safe, checked conversions in `AddCW20`, `AddCW721`, and `AddCW1155`:
```go
nameVal, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info/contract_info returned non-string name field")
}
symbolVal, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info/contract_info returned non-string symbol field")
}
```
Additionally, verify that any similar unchecked type assertions on externally supplied/query-derived JSON (as opposed to ABI-decoded `args`) elsewhere in the precompiles are audited and hardened, and confirm/add a top-level `recover()` around dynamic-gas precompile execution so that any remaining unhandled panic degrades to a reverted call instead of crashing the node.

### Proof of Concept
1. Deploy a CosmWasm contract whose query handler responds to `{"token_info":{}}` with a JSON object where `"name"` is a non-string value, e.g. `{"name": 12345, "symbol": "X", "decimals": 6, "total_supply": "0"}` (or omit `"name"`/`"symbol"` entirely, yielding a Go `nil` value from the map).
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b` invoking `addCW20Pointer(cwAddr)` with `cwAddr` set to the malicious contract's bech32 address (per [2](#0-1) ).
3. Execution reaches `formattedRes["name"].(string)` at [3](#0-2) , and Go panics with `interface conversion: interface {} is float64, not string` (or `interface conversion: interface {} is nil, not string` if the field is absent), since `formattedRes["name"]` is not a string.
