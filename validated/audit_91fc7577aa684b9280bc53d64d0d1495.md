### Title
Server-Side Request Forgery via unauthenticated DataLayer mirror URLs - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user (unprivileged spend-bundle submitter) can create a "mirror coin" that advertises arbitrary URLs for **any** DataLayer store, including stores they do not own. Once a node tracks that store (as a subscriber or owner), its DataLayer service will periodically enumerate all mirror URLs pulled from chain state and issue outbound HTTP requests to them without any allow-listing or destination validation — a classic SSRF, analogous to CVE-2023-1971 (tpAdmin's `Upload.php` `remote()` fetching an attacker-supplied `url`).

### Finding Description
The DataLayer "mirror" feature lets anyone announce URLs for a given `launcher_id` (store id) by spending a coin to the fixed puzzle `create_mirror_puzzle()` (`P2_PARENT.curry(Program.to(1))`) with `memos=[launcher_id, *urls]`: [1](#0-0) 

There is no check anywhere in this path that the caller owns or controls `launcher_id` — `add_mirror`/`create_new_mirror` simply spends the caller's own coins with an arbitrary memo payload: [2](#0-1) 

When any wallet is tracking that launcher (subscribed store, or the store it owns), `DataLayerWallet.coin_added()` picks up the mirror coin and stores the attacker-chosen URLs verbatim, with no scheme/host restriction: [3](#0-2) 

The DataLayer service then folds these wallet-reported mirror URLs directly into its subscription server list: [4](#0-3) 

During the periodic sync loop (`periodically_manage_data` → `update_subscription` → `insert_from_delta_file` → `download_file`), these URLs are used as the target of an outbound HTTP GET with no destination validation, only filename validation: [5](#0-4) 

`is_filename_valid()` only checks the *file name* format, not the URL/host: [6](#0-5) 

So `server_info.url + "/" + filename` can be anything the attacker chose in the mirror coin memo (e.g. `http://169.254.169.254`, `http://127.0.0.1:<internal-port>`, an internal-network host, etc.), and the victim node's own process will make the outbound request, including it in the response-size/streaming handling path. The attacker fully controls the destination host and can also observe indirect signals (timing, error type) from the victim node.

### Impact Explanation
This is a genuine SSRF: an unprivileged party who can submit a spend bundle (a tiny XCH-funded transaction creating a mirror coin) can force any peer running the DataLayer service and tracking that store to make outbound HTTP(S) requests to attacker-chosen internal or otherwise restricted endpoints (cloud metadata services, internal admin panels, other services on localhost, etc.). This can be used for internal network reconnaissance/pivoting, cloud credential theft (metadata endpoints), or as a confused-deputy request against internal infrastructure from the victim node's network position. It does not directly forge on-chain state, but it is a network-reachable, unauthenticated request-forgery vector consistent with CWE-918/the referenced advisory's bug class.

### Likelihood Explanation
Likelihood is high for any node that has DataLayer enabled and either subscribes to third-party stores or owns a store that anyone else "mirrors" — mirror coins for a `launcher_id` can be created by anyone regardless of ownership, and no operator interaction is required beyond running DataLayer and having a tracked/subscribed store (which is normal usage). The mirror coin creation itself only costs the attacker's own coin fee; the attack requires no privileged access, leaked keys, or malicious peer/node — a single spend bundle from an ordinary wallet suffices.

### Recommendation
- Restrict outbound mirror/server URLs to an explicit allow-list of schemes/hosts (reject `http(s)://` targets resolving to private/link-local/loopback ranges) before use in `http_download`.
- Consider requiring mirror URLs to be attested by the store owner (e.g., signed via the singleton's inner puzzle) rather than accepting URLs from any arbitrary coin creator, since currently `create_mirror_puzzle()` places no restriction on who may announce URLs for a given `launcher_id`.
- Add DNS-rebinding-safe URL validation (resolve once, pin the resolved IP, re-check against a private-IP block list) at the point `http_download` and the S3/plugin `download`/`handle_download` handlers consume attacker-influenced URLs.

### Proof of Concept
1. Attacker crafts and broadcasts a spend bundle that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and `CREATE_COIN` memos `[victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/"]`, paying only the standard fee — no ownership of `victim_store_launcher_id` is required (`chia/wallet/db_wallet/db_wallet_puzzles.py:90-109`, `chia/data_layer/data_layer_wallet.py:687-703`).
2. Once confirmed, any node whose wallet tracks `victim_store_launcher_id` (owner or subscriber) picks up the mirror in `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores the URL unmodified.
3. That node's `DataLayer.update_subscriptions_from_wallet()` copies the URL into its subscription server list (`chia/data_layer/data_layer.py:979-985`).
4. On the next periodic sync cycle, `download_file`/`http_download` issues `session.get("http://169.254.169.254/latest/meta-data/" + "/" + filename, ...)` from the victim node's process (`chia/data_layer/download_data.py:298-323`), completing the SSRF.

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
```

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
