### Title
`get_outputs` overwrites previously scanned outputs' `presumed_origin`/`data` with a later transaction's values - (File: processor/src/networks/bitcoin.rs)

### Summary
The npm advisory concerns a shared namespace where a later installation silently clobbers an earlier one. The analog exists in `Bitcoin::get_outputs`: the `outputs` accumulator is declared outside the per-transaction loop, but the post-processing pass that assigns `presumed_origin` and Serai `data` iterates over **all accumulated outputs**, not just the ones found in the current transaction. Every subsequent matching transaction in the same block overwrites the origin attribution and InInstruction data of every output found earlier in the block.

### Finding Description
In `Bitcoin::get_outputs`, `let mut outputs = vec![]` is created once before iterating `block.txdata[1 ..]` and is never drained per transaction.

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ...; outputs.push(output); }
  if outputs.is_empty() { continue; }
  let presumed_origin = { /* tx.input[0]'s spent script_pubkey */ };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs {           // ALL outputs, incl. earlier txs
    if output.kind == OutputType::External { output.data.clone_from(&data); }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
```

`presumed_origin` is derived from `tx.input[0]`'s spent output and `data` from `Self::extract_serai_data(tx)` — both specific to the *current* `tx` — yet they are applied to every output collected so far. When two transactions in one block each pay to a scanned Serai script (external, branch, change, or forwarded), the second transaction's origin and embedded `InInstruction` data overwrite the first transaction's outputs' fields. Only the last matching transaction's values survive.

### Impact Explanation
`presumed_origin` and `data` are the fields Serai uses to attribute an inbound Bitcoin output: `data` carries the `InInstruction` (destination Serai address / action) for `OutputType::External` outputs, and `presumed_origin` records the payer. An attacker who gets a transaction paying any scanned Serai script into the same block *after* a victim's deposit causes the victim's output to be re-tagged with the attacker's `presumed_origin` and, for `External` outputs, the attacker's `data` — redirecting the credited instruction/origin. This produces funds reported received with attacker-controlled attribution data, satisfying the "incorrect verifier / misattributed funds" impact bar with no key material required.

### Likelihood Explanation
Reachable by any unprivileged party able to broadcast a Bitcoin transaction. Requirements: (1) a victim transaction paying a Serai-registered script in the same block, (2) an attacker transaction paying any scanned script (trivially done by sending to the published external/forward address, which anyone can compute via `forward_address`/`p2tr_script_buf`) ordered later in `txdata`. No collusion, no threshold participation, and no malformed encodings are needed; ordering within a block is miner/attacker-influenceable.

### Recommendation
Scope the metadata pass to only the outputs found in the current transaction — e.g., record `let start = outputs.len()` before scanning `tx`, then iterate `&mut outputs[start ..]`, or build a per-transaction vec and extend the accumulator after tagging. Skip coinbase handling and `data`/`presumed_origin` assignment must remain per-transaction.

### Proof of Concept
1. Victim broadcasts `tx_v` paying the Serai external address (`p2tr_script_buf(group_key)`) with InInstruction data crediting `serai_victim`.
2. Attacker broadcasts `tx_a` paying the same (or forwarded) script with `extract_serai_data(tx_a)` encoding InInstruction data crediting `serai_attacker`, mined in the same block after `tx_v`.
3. `get_outputs` scans `tx_v` → pushes output V, tags V with `origin_v`/`data_v`. It then scans `tx_a` → pushes output A, and the `for output in &mut outputs` loop re-tags **both** V and A with `origin_a` and `data_a`.
4. Returned `outputs` report V (the victim's funds) with the attacker's `presumed_origin` and attacker `data`, silently overwriting the victim's attribution. [1](#0-0)

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
