## Analog Found: Nil Pointer Dereference in Precompile Error-Handling Path for Legacy Precompile Versions

### Title
Nil pointer dereference in legacy precompile error-handling (`HandlePrecompileError`/inline defer) reachable via historical-block EVM tracing RPCs - (File: `precompiles/common/legacy/v605/precompiles.go`)

### Summary
CVE-2016-8887 is a NULL pointer dereference in a JasPer cleanup/destroy routine (`jp2_colr_destroy`) that is invoked on an object that was never fully populated. The structurally identical bug class exists in sei-chain's precompile framework: several **legacy precompile implementations** unconditionally dereference the result of `state.GetDBImpl(evm.StateDB)` inside their error-handling "cleanup" path, without checking for `nil`, even though the same codebase demonstrates (in later versions and in `Prepare()`) that `GetDBImpl` can legitimately return `nil`.

### Finding Description
`state.GetDBImpl(evm.StateDB)` is a type-assertion helper that only returns a non-nil object when `evm.StateDB` is backed by the chain's `*DBImpl`. Every precompile's own `Prepare()` function defensively checks this for `nil`: [1](#0-0) 

However, in the earlier precompile generations (v5.5.2 through v6.1.0), the error-cleanup helper `HandlePrecompileError` — invoked from a `defer` in `Run`/`RunAndCalculateGas` whenever a precompile call errors — dereferences the same call **without** the nil guard: [2](#0-1) 

This is functionally the same as `jp2_colr_destroy` unconditionally destroying a member that the constructor path may have left unset: a "teardown on error" routine assumes a fully-initialized object it never checked.

Later versions (v6.1.4 onward) fixed exactly this pattern by adding the nil check, and the current/latest precompile code carries the fix: [3](#0-2) [4](#0-3) 

The same unguarded pattern is repeated identically across many other legacy per-precompile packages (`addr`, `bank`, `distribution`, `gov`, `json`, `oracle`, `pointer`, `pointerview`, `staking`, `wasmd` — v5.5.2 through v6.1.0), all sharing the single-line `state.GetDBImpl(evm.StateDB).SetPrecompileError(err)` call.

Critically, these legacy implementations are **not dead code**. The EVM keeper keeps a `VersionedPrecompiles` map per precompile address and selects the version to execute **based on `ctx.BlockHeight()`** relative to when each chain upgrade was applied: [5](#0-4) 

And when the context is a tracing context, the keeper deliberately re-derives the height-appropriate (i.e., possibly legacy) precompile set instead of always using the latest: [6](#0-5) 

This means any public JSON-RPC client that requests tracing of a historical transaction/block (e.g. `debug_traceTransaction`, `debug_traceBlockByNumber`) that invoked one of these precompiles before the relevant upgrade height will execute the exact legacy Go code shown above, including the unguarded `HandlePrecompileError` call.

### Impact Explanation
If `GetDBImpl(evm.StateDB)` returns `nil` during trace-mode execution of one of these legacy precompile code paths (the same condition `Prepare()` in the very same file explicitly guards against), the deferred error handler dereferences a nil pointer and panics. Since this occurs inside the EVM tracing/simulation call stack rather than the ordinary `baseapp` `runTx` recover-wrapped path, an unrecovered panic here can propagate up through the tracer and crash the servicing RPC node goroutine/process, resulting in denial of service for that public RPC node — the same "reachable NULL pointer dereference causing a crash" impact class as CVE-2016-8887.

### Likelihood Explanation
Reaching this code requires only a normal, unprivileged JSON-RPC caller invoking a trace-style RPC method against a historical block/transaction that called an affected precompile prior to the corresponding chain upgrade. No special privileges, validator status, or malicious peer/consensus behavior are needed — this fits the "public-RPC client" reachable category. The likelihood that `GetDBImpl` actually returns `nil` in that exact call path (i.e., the precondition under which the bug manifests) could not be fully confirmed from the indexed code alone; the tracer's `StateDB` wiring (in `evmrpc/tracers.go`) was only partially inspectable, so this should be validated end-to-end before treating it as fully proven.

### Recommendation
Backport the nil-check fix already present in `precompiles/common/legacy/v614/precompiles.go` (and the current `precompiles/common/precompiles.go`) into every earlier legacy `HandlePrecompileError`/inline-defer implementation (`v552` through `v610`, across all precompile packages: `addr`, `bank`, `distribution`, `gov`, `json`, `oracle`, `pointer`, `pointerview`, `staking`, `wasmd`), so that `SetPrecompileError` is only called when `state.GetDBImpl(evm.StateDB)` is non-nil, exactly mirroring the guard already used in each version's own `Prepare()` method.

### Proof of Concept
1. Identify a historical block/transaction that invoked one of the affected precompiles (e.g. `addr`, `pointer`, `oracle`) at a chain height prior to the `v6.1.4` upgrade (i.e., resolved to `v552`–`v610` via `GetCustomPrecompilesVersions`).
2. Issue a `debug_traceTransaction` (or `debug_traceBlockByNumber`) JSON-RPC call for that historical transaction against a full/RPC node, using a tracer/state-wrapping mode where `evm.StateDB` is not the concrete `*DBImpl` type that `state.GetDBImpl` expects (causing it to return `nil`).
3. Trigger any error condition inside that legacy precompile call (e.g., malformed calldata / staticcall restriction) so the deferred `HandlePrecompileError`/inline error-handling block executes.
4. Observe: `state.GetDBImpl(evm.StateDB).SetPrecompileError(err)` dereferences a nil result and panics, potentially crashing the servicing RPC node process outside of `baseapp`'s tx-execution recover wrapper. [2](#0-1) [3](#0-2) [5](#0-4) [6](#0-5)

```go
func (k *Keeper) GetCustomPrecompilesVersions(ctx sdk.Context) map[common.Address]string {
	height := ctx.BlockHeight()
	cp := make(map[common.Address]string, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		mostRecentUpgradeHeight := int64(0)
		noForkHistory := true
		for upgrade := range versioned {
			upgradeHeight := k.upgradeKeeper.GetDoneHeight(ctx, upgrade)
			if upgradeHeight != 0 {
				noForkHistory = false
			}
			if height < upgradeHeight {
				// requested height hasn't seen this upgrade version yet.
				continue
			}
			if upgradeHeight > mostRecentUpgradeHeight {
				mostRecentUpgradeHeight = upgradeHeight
				cp[addr] = upgrade
			}
		}
		if noForkHistory {
			cp[addr] = k.latestUpgrade
		}
	}
	return cp
}
```

```go
func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {
	if !ctx.IsTracing() {
		return k.latestCustomPrecompiles
	}
	versions := k.GetCustomPrecompilesVersions(ctx)
	cp := make(map[common.Address]vm.PrecompiledContract, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		cp[addr] = versioned[versions[addr]]
	}
	return cp
}
```
