### Title
Silent origin-remote hijack via renamed/deleted-and-recreated GitHub repository - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl` rewrites a repository's local `origin` remote URL to whatever `clone_url` the GitHub API returns for the owner/name parsed from the *current* remote, without ever verifying that the API response still describes the *same* repository the user originally cloned/associated. Because repository owner/name slugs can be vacated (rename, transfer, deletion) and then reclaimed by a different account, an attacker who reclaims a stale owner/name can cause Desktop to silently repoint the user's git remote to the attacker's repository.

### Finding Description
`repositoryWithRefreshedGitHubRepository` runs during routine repository refreshes and:
1. Calls `this.matchGitHubRepository(repository)`, which derives `owner`/`name` purely from the currently-configured remote URL (via `parseRemote`), not from any stored repository ID.
2. Fetches `api.fetchRepository(owner, name)` using those parsed values. [1](#0-0) 

3. If a GitHub repository association already exists, it calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`, which will overwrite the local `origin` remote URL with `apiRepo.clone_url` whenever the protocol matches and the remote hasn't been "manually changed" (as far as Desktop can tell) — with **no check that `apiRepo` corresponds to the same repository ID/dbID that Desktop had previously associated**: [2](#0-1) 

The invariant that is silently violated is: *"the git remote for a tracked repository should only ever be updated to point at the same GitHub repository entity, never a different one."* Nothing in `updateRemoteUrl`, `_upsertGitHubRepository` (which keys off `[ownerID+name]`, not a stable GitHub node/repo ID) enforces this — see the lookup by name rather than immutable ID: [3](#0-2) 

This mirrors the DeFi bug's shape: an operation trusts a derived/looked-up value (owner/name string) as a stand-in for the real object being tracked (a specific repository entity/margin balance) and updates persistent state (`self.margin[...]` / the git remote) based on that assumption without re-validating identity, corrupting the state that the user relies on (withdrawable margin / where their code is pushed).

### Impact Explanation
If the original repository at `owner/name` is deleted, renamed, or transferred, and an attacker registers a new repository under the vacated `owner/name` slug, the next background refresh will silently rewrite the victim's `origin` remote to the attacker's `clone_url`. Subsequent `git push` operations from the victim (using their own credentials/trampoline token) will push their code — potentially private source, secrets in history, commits — to a repository the attacker controls, and subsequent `git pull`/`fetch` will pull attacker-controlled content into the user's working tree, all without any user prompt (contrast with `UpstreamAlreadyExists`, which *does* prompt when an upstream mismatch is detected, but only for the upstream remote in the fork-contribution flow, not for this auto-refresh path): [4](#0-3) 

This is squarely "silent corruption of what the user commits or pushes," one of the valid impact categories, and can also lead to exfiltration of source code/history to the attacker.

### Likelihood Explanation
Requires no local access, no admin rights, no prior malware, and no unnatural user steps — only that the user has previously cloned/associated a repository whose owner/name is later reclaimed by an attacker (a well-known "repo-jacking"/"dependency confusion"-style takeover technique already seen in the wild for CI/CD and package ecosystems). The refresh path (`repositoryWithRefreshedGitHubRepository`) runs automatically as part of normal repository housekeeping, so the victim does not need to take any explicit action for the remote to be silently repointed.

### Recommendation
Before calling `updateRemoteUrl`/`upsertGitHubRepository` with a freshly fetched `apiRepo`, verify that `apiRepo.id` (or equivalent immutable GitHub repository ID) matches the ID stored in the existing `GitHubRepository` record for this local repository. If the ID differs (i.e., the owner/name now points at a different repository than the one Desktop previously associated), do not silently update the remote — instead surface a warning/confirmation dialog (similar to the existing `UpstreamAlreadyExists` pattern) so the user can confirm before Desktop changes where their commits are pushed.

### Proof of Concept
1. Victim clones `https://github.com/acme/widget` and works in Desktop normally; Desktop stores a `GitHubRepository` record (id 123) associated with `origin` pointing at that URL.
2. `acme/widget` is deleted or renamed away (e.g., organization renamed, or repo deleted after archival).
3. Attacker creates a new repository at the now-vacant `acme/widget` slug.
4. On the next periodic refresh, `repositoryWithRefreshedGitHubRepository` → `matchGitHubRepository` parses `owner=acme, name=widget` from the victim's still-configured remote URL, `api.fetchRepository('acme','widget')` returns the attacker's new repository object (different underlying ID, but Desktop never checks that), and `updateRemoteUrl` rewrites the victim's `origin` URL to the attacker's `clone_url` because `protocolsMatch && remoteUrlUnchanged && !urlsMatch` all hold.
5. Victim's next `git push` sends their local commits to the attacker's repository; next `git pull` fetches attacker-controlled content — with no dialog or warning ever shown.

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
