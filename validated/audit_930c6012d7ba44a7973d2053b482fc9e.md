### Title
Emergency withdraw in `MasterMagpie` skips reward-pool checkpoint sync, enabling later theft of other stakers' bonus rewards - ([File: rewards/MasterMagpie.sol])

### Summary
`MasterMagpie.emergencyWithdraw()` zeroes out a user's stake without first syncing that user's checkpoint in the associated `BaseRewardPoolV2`. Because `BaseRewardPoolV2.balanceOf()` is a live read from `MasterMagpie`, a subsequent re-deposit re-syncs the checkpoint using a stale `userRewardPerTokenPaid` value against the *current* reward-per-token index, crediting the user rewards that accrued while they held zero real stake — funds that are actually owed to other stakers.

### Finding Description
`emergencyWithdraw` reduces the user's position but deliberately avoids calling `_harvestBaseRewarder`, which is the function that calls `rewarder.updateFor(_account)` to persist the user's bonus-reward checkpoint: [1](#0-0) 

Compare with the normal withdraw path, `_harvestAndUnstake`, which always calls `_harvestBaseRewarder` before mutating `user.amount`/`user.available`: [2](#0-1) 

`BaseRewardPoolV2.balanceOf()` does not store a local balance; it reads live state from `MasterMagpie`: [3](#0-2) 

The per-user checkpoint (`userRewardPerTokenPaid`) is only advanced when `_updateFor`/`updateReward` runs for that account: [4](#0-3) 

Because `emergencyWithdraw` skips this sync, the user's `userRewardPerTokenPaid[rewardToken][account]` is left at its pre-withdrawal value while their real stake in `MasterMagpie` (and therefore `balanceOf`) drops to 0. When the account later re-deposits any amount, `_deposit` unconditionally calls `_harvestBaseRewarder`: [5](#0-4) [6](#0-5) 

That call recomputes `earned()` as `newBalance * (currentRewardPerToken - staleRewardPerTokenPaid)`: [7](#0-6) 

Since `currentRewardPerToken - staleRewardPerTokenPaid` reflects the *entire* elapsed period — including the time the account held zero real stake after the emergency withdrawal — but is now multiplied by the account's newly re-deposited balance, the account is credited bonus-token rewards it never earned. These reward tokens are drawn from the finite pool funded by `donateRewards`/`queueNewRewards`, which is shared among all real stakers: [8](#0-7) 

### Impact Explanation
Any ordinary staker can extract more bonus-reward tokens than they are entitled to, at the expense of the reward token balance intended for other stakers in the same `BaseRewardPoolV2`. Because the reward pool's token balance is finite (funded via `queueNewRewards`/`donateRewards`), this can drain funds so that legitimate stakers' later `getReward`/`getRewards` calls fail due to insufficient balance — a direct theft/permanent freezing of unclaimed yield belonging to other users.

### Likelihood Explanation
The only precondition is that the contract be in the `whenPaused` state, which `emergencyWithdraw` requires. Pausing is a normal, non-malicious operational state (e.g., during a protocol pause/upgrade window), not a privileged/malicious-admin action taken to enable the exploit. Once paused, any staker holding an `available` balance in a pool with an active bonus rewarder can trigger this sequence (`emergencyWithdraw` → wait for more rewards to accrue → re-deposit) using entirely their own funds and permissionless calls.

### Recommendation
`emergencyWithdraw` should sync the user's reward-pool checkpoint before mutating `user.amount`/`user.available`, e.g., by calling `_harvestBaseRewarder(_stakingToken, msg.sender)` (without transferring the harvested MGP/bonus amounts, consistent with the "no rewards" emergency semantics) so `userRewardPerTokenPaid` is brought current at the point the user's real balance drops to zero, preventing later re-deposits from claiming rewards accrued during the zero-balance period.

### Proof of Concept
1. Alice deposits LP receipt tokens into a `MasterMagpie` pool that has an active `BaseRewardPoolV2` bonus rewarder (via `WombatPoolHelper`/`depositFor`).
2. The rewarder periodically receives bonus tokens via `queueNewRewards`, increasing `rewardPerTokenStored`.
3. The protocol is paused (`whenPaused`), a normal operational state.
4. Alice calls `MasterMagpie.emergencyWithdraw(_stakingToken)`. Her `user.available`/`user.amount` go to 0, but `rewarder.updateFor(Alice)` is never called, so `userRewardPerTokenPaid[rewardToken][Alice]` stays at the pre-withdrawal value. [9](#0-8) 
5. The protocol is unpaused. More bonus rewards are queued, raising `rewardPerTokenStored` further while Alice holds zero real stake.
6. Alice re-deposits a small amount. `_deposit` calls `_harvestBaseRewarder` unconditionally, which calls `rewarder.updateFor(Alice)`, computing `earned = newBalance * (rewardPerToken_now - staleCheckpoint)` — crediting her rewards for the period she had zero stake. [7](#0-6) 
7. Alice calls `multiclaim`/`getReward` to withdraw the inflated bonus reward, depleting funds meant for other stakers, causing their subsequent claims to under-pay or revert.

    /// @notice Withdraw all available tokens without caring about rewards. EMERGENCY ONLY. 
    ///         Locked Token can not be emergent withdraw.
    /// @param _stakingToken Staking token of the pool
    /// @dev withdrawFor of the rewarder with the third param at false is an emergency withdraw
    function emergencyWithdraw(address _stakingToken) external whenPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][msg.sender];
        uint256 availableaAmount = user.available;
        user.available = 0;
        IERC20(pool.stakingToken).safeTransfer(address(msg.sender), availableaAmount);
        emit EmergencyWithdraw(msg.sender, _stakingToken, availableaAmount);
        user.amount = user.amount - availableaAmount;
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;
    }

    function _updateFor(address _account) internal {
        uint256 length = rewardTokens.length;
        for (uint256 index = 0; index < length; ++index) {
            address rewardToken = rewardTokens[index];
            // if a reward stopped queuing, no need to recalculate to save gas fee
            if (userRewardPerTokenPaid[rewardToken][_account] == rewardPerToken(rewardToken))
                continue;

            userRewards[rewardToken][_account] = earned(_account, rewardToken);
            userRewardPerTokenPaid[rewardToken][_account] = rewardPerToken(rewardToken);
        }
    }
