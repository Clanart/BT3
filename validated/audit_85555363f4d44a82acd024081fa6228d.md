### Title
Silent data-loss on corrupted lazy MessageSet extension: successful getter masks a failed parse and permanently discards the original serialized bytes - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
`LazyFieldLite.ensureInitialized()` catches `InvalidProtocolBufferException` when lazily parsing an attacker-supplied sub-message, but instead of surfacing the failure it silently replaces the field's authoritative state (`value` and `memoizedBytes`) with the default instance / empty bytes, permanently discarding the original bytes. Any caller of the getter sees success (a valid, if empty, message) with no indication that the underlying bytes were malformed and have now been overwritten.

### Finding Description
`LazyFieldLite` stores an unparsed field as `delayedBytes` and lazily parses it into `value` on first access, caching the reparsed bytes in `memoizedBytes` for future serialization [1](#0-0) . When the lazy bytes fail to parse, `ensureInitialized()` swallows the exception: [2](#0-1) 

Critically, this path does not just return a default value to the caller (an allowed, catchable-exception scenario) - it overwrites `memoizedBytes` with `ByteString.EMPTY`. Since `toByteString()` and `writeTo()` prefer `memoizedBytes`/`delayedBytes` over recomputing from `value` [3](#0-2) [4](#0-3) , once `ensureInitialized()` runs, the field's serialized representation is irreversibly changed from "some corrupted bytes" to "empty," and the field's `getSerializedSize()` will likewise now report 0 for future computations [5](#0-4) .

This mirrors the ERC20 report's invariant failure: an operation that can silently fail (`transfer()` return value ignored / here, a parse exception caught) is treated by the surrounding state machine as if it succeeded, and the object's persistent state (`memoizedBytes`, akin to the contract's "claimed" flag) is updated to reflect success even though the actual payload was lost. The caller (equivalent to Alice) gets no signal that anything went wrong, and the original data can never be recovered (equivalent to the lost prize).

Notably, the sibling class `InternalLazyField` (used for `DynamicMessage`/full extensions in MessageSets) explicitly documents and fixes this exact class of bug: it keeps `bytes` untouched on corruption, sets an internal `corrupted` flag, and - depending on `ExtensionRegistryLite.lazyExtensionEnabled()` - either re-throws on repeated access or explicitly falls back to the "old behavior" of silently returning the default instance while preserving the original bytes for reserialization [6](#0-5) . The regression test `testLoadCorruptedLazyField_getSerializedSize` demonstrates that for `InternalLazyField`, round-tripping via `toByteString()` after a corrupted access still preserves equality with the original message set container [7](#0-6) . `LazyFieldLite` has no such preservation: it destroys the bytes on first failed access.

### Impact Explanation
For any lite/full generated message with a field marked `[lazy = true]` containing a message-typed submessage, an attacker who supplies a well-formed outer message but a malformed/corrupt payload for that lazy submessage can cause:
- The application to silently observe a default/empty value where corrupted data existed, hiding evidence of the malformed input (masking impact for logging/auditing/security-relevant fields).
- Permanent, unrecoverable loss of the original bytes for that field once any getter is invoked - if the application later re-serializes/forwards/persists the message (a common pattern for proxies, gateways, and message brokers), the corrupted payload is silently replaced by an empty one, changing the on-wire representation without error, and defeating any downstream expectation that unmodified/unknown/corrupt data would be preserved or would fail loudly.

This is a Medium-severity integrity issue: it is a genuine violation of "operation should not commit destructive state change without confirming success," directly analogous to the reported ERC20 issue, but it does not lead to memory corruption, RCE, or resource exhaustion.

### Likelihood Explanation
Any consuming application that uses `lazy = true` fields (a supported, documented protobuf feature) and accepts external/untrusted serialized protobuf input is exposed. Triggering it only requires sending a bounded, syntactically valid outer message with an intentionally malformed lazy sub-message payload, and then having the application call any getter on that field (which is the normal way of consuming it). This is a common, unprivileged, client-reachable code path (any public "ParseFrom" API followed by a getter call on a lazy field), and does not require special configuration beyond the schema declaring the field as lazy.

### Recommendation
Align `LazyFieldLite.ensureInitialized()` with the behavior already implemented in `InternalLazyField`:
- Do not overwrite `memoizedBytes`/`delayedBytes` with `ByteString.EMPTY` on a caught `InvalidProtocolBufferException`. Preserve the original bytes so that `toByteString()`/`writeTo()` continue to serialize the untouched original payload.
- Set the existing package-private `corrupted` flag and make it consistently checkable/actionable by higher-level code (e.g., throw on repeated access, as `InternalLazyField` does when `lazyExtensionEnabled()`), rather than silently normalizing to a default instance while destroying the backing bytes.
- Audit `LazilyParsedMessageSetTest`/`LazyFieldLiteTest` to add a regression test asserting that `toByteString()` after a failed lazy parse still reproduces the original (corrupted) bytes, matching the guarantee already tested for `InternalLazyField`.

### Proof of Concept
1. Define a lite message `Outer` with a field `message Inner inner_field = 1 [lazy = true];`, where `Inner` has at least one required/typed field that can be violated by malformed bytes (e.g., an invalid UTF-8 string field or invalid varint).
2. Craft `outer_bytes` = a valid length-delimited encoding of field 1 whose payload is *not* a valid encoding of `Inner` (e.g., a truncated field or a string field with invalid UTF-8 continuation bytes), but is a well-formed byte blob that `Outer.parseFrom()` accepts because `Outer.parseFrom()` never eagerly parses the lazy field.
3. `Outer outer = Outer.parseFrom(outer_bytes);` succeeds (as expected for a lazy field: bytes are just captured, not parsed).
4. Call `outer.getInnerField()` (or any other accessor) - triggers `LazyFieldLite.ensureInitialized()`. Confirm (via package-internal test access, e.g. `LazyFieldLite.isCorrupted()`) that `corrupted == true`, and that `value` is now `Inner.getDefaultInstance()`.
5. Call `outer.toByteString()` (or serialize `outer` again). Show that the reserialized bytes for field 1 are now `ByteString.EMPTY` (length-delimited field of size 0), not the originally-supplied corrupted bytes - demonstrating irreversible, silent data loss triggered merely by reading the field once.

This behavior can be directly compared against `LazilyParsedMessageSetTest.testLoadCorruptedLazyField_getSerializedSize`, which shows the *correct* invariant-preserving behavior for the analogous `InternalLazyField` path [7](#0-6) , confirming that `LazyFieldLite`'s behavior is an inconsistency/regression relative to the fixed sibling implementation, not an intended design choice.

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }

  /**
   * Guarantees that `this.value` is non-null or throws.
   *
   * @throws InvalidProtocolBufferException If `bytes` cannot be parsed.
   */
  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }

  /**
   * Returns the parsed message value.
   *
   * <p>If the lazy field is corrupted, it will throw a runtime exception if {@link
   * ExtensionRegistryLite#lazyExtensionEnabled()} is true, otherwise it will return the default
   * instance.
   */
  MessageLite getValue() {
    try {
      ensureInitialized();
      return value;
    } catch (InvalidProtocolBufferException e) {
      if (extensionRegistry.lazyExtensionEnabled()) {
        // New behavior: runtime exception on corrupted extensions.
        throw new InvalidProtobufRuntimeException(e);
      } else {
        // Old behavior: silently return the default instance.
        return defaultInstance;
      }
    }
  }
