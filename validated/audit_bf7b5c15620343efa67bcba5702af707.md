### Title
Endpoint "GitHub host" trust status is cached indefinitely and never re-verified, allowing a spoofed response header to silently upgrade a generic Git remote into a trusted (credential-injected) GitHub Enterprise endpoint - (File: `app/src/lib/endpoint-capabilities.ts`, `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The external report's broken invariant is: *a piece of "earned" state (voting balance) is never reset/re-validated, so it keeps granting an ongoing privilege (bribe claims) it should no longer grant.* The closest reachable analog in this GitHub Desktop codebase is the endpoint-type classification cache used to decide whether a remote is a trusted GitHub/GitHub-Enterprise host. That classification is written once from an unauthenticated response header, persisted forever in `localStorage`, keyed only by URL string, and is later trusted blindly by the credential helper to decide whether to auto-attach a signed-in account's real token to Git network requests.

### Finding Description
`isGitHubHost()` first checks a permanent cache before doing any live verification: [1](#0-0) 

If `getEndpointVersion(endpoint)` returns anything non-null, the host is unconditionally trusted: [2](#0-1) 

That cache is written by `updateEndpointVersion`, which persists into `localStorage` (and an in-memory map) with **no expiry, no reset, and no re-validation ever performed**: [3](#0-2) 

The value comes from an `x-github-enterprise-version` response header, which is attacker-controllable content from any server Desktop happens to talk to. It gets written from two places that fire on essentially every HTTP interaction, regardless of authentication result:

- Every authenticated API request, including 401s: [4](#0-3) 
- The very probe `isGitHubHost` itself uses to decide trust, whose response is fed right back into the same cache before returning: [5](#0-4) 

This "trust" classification then flows directly into the Git credential helper, which uses it to decide whether a remote is `'generic'` (prompt/store a one-off credential) or `'enterprise'`/`'github.com'` (treat it like a real GitHub endpoint and auto-fill the signed-in account's token): [6](#0-5) 

Once a host is classified as non-generic, `getCredential` looks up a matching signed-in `Account` purely by **origin** (protocol+host), and if found, injects that account's real token as the Git credential: [7](#0-6) [8](#0-7) 

**Why existing guards don't stop this**: nothing ever calls `versionCache.delete`/clears the `localStorage` key for an endpoint. There is no invariant check requiring the "GitHub host" determination to be re-validated per session, per repository, or after an account is added/removed for that endpoint — exactly like `Bribe.sol`'s `balanceOf[tokenId]` never being reset after `getRewardForOwner` pays out. A single interaction with a URL can "pre-authorize" all future credential-handling decisions for that exact URL string, indefinitely, for any repository that later uses it as a remote.

### Impact Explanation
If an attacker controls (or can inject responses for, e.g. via a compromised/malicious self-hosted Git-over-HTTP remote, a corporate proxy, or a MITM on an `http://` remote) a host that the victim's Desktop client talks to even once with an `x-github-enterprise-version` header present, that host's classification is permanently flipped from `generic` to `enterprise`/`github.com` in local storage. From then on:
- Any repository (including ones added later, or unrelated repos sharing that same origin string) that uses that same URL as a remote is treated by the credential helper as a genuine GitHub Enterprise endpoint.
- If the user has (or later adds) an `Account` whose endpoint origin matches, `getGitHubCredential`/`findGitHubTrampolineAccount` will automatically hand that account's real OAuth-derived token to the attacker-influenced host as the HTTPS Basic-auth password — without any further prompt, confirmation, or re-verification that the host is actually who it claims to be.
- This is a credential-exfiltration primitive reachable purely from a Git remote/proxy response the attacker controls, matching the "impact" categories: token exfiltration and silent misuse of what the user's client sends when interacting with a repository.

### Likelihood Explanation
Moderate-to-low confidence, and I want to be explicit about the parts I could not fully trace in the time available:
- I confirmed the cache-write, cache-read, and credential-injection code paths exist and behave as described above.
- I did **not** fully trace every caller of `updateEndpointVersion`/`tryUpdateEndpointVersionFromResponse` to enumerate every network code path where an attacker-controlled server's headers reach it (I found two: `ghRequest` in `api.ts` and the `isGitHubHost` meta probe). There may be additional or fewer reachable call sites, and I could not verify within this session whether Desktop performs the `isGitHubHost` probe automatically for arbitrary user-added remotes versus only in specific enterprise sign-in flows.
- I likewise could not fully verify in-repo whether `Account` matching by "origin only" (`find-account.ts`) is further constrained elsewhere (e.g. by certificate pinning or additional endpoint-equality checks) before a token is actually placed on the wire.

Given the uncertainty above, treat this as the strongest identified analog to the report's "state not reset → unearned privilege reused" pattern, but recommend a Desktop engineer verify the full call graph before treating it as fully confirmed.

### Recommendation
- Do not let `x-github-enterprise-version` (or any single header) alone permanently flip a host's trust classification; require it to be re-validated per Git operation, or at minimum re-validated whenever an `Account` is being matched for automatic credential injection.
- Scope the endpoint-version cache key to something that can't be silently satisfied by a single attacker response, and add explicit invalidation whenever an account for that endpoint is added, removed, or its token changes (mirroring the fix needed in `Bribe.sol`: reset the earned/trusted state after it is "spent" or reused).
- When matching accounts to a remote for automatic credential injection (`findGitHubTrampolineAccount`), consider not relying solely on cached "is GitHub host" heuristics for hosts that are not exactly `github.com`/the account's originally-configured GHE endpoint.

### Proof of Concept
Conceptual PoC (I was not able to run this against the app in this session, so it is derived purely from the code paths cited above):
1. Attacker stands up an HTTPS Git server (or a proxy in front of one) that, on any request (including the `HEAD /meta` probe Desktop issues, or a normal `git fetch`/`clone` request), returns the header `x-github-enterprise-version: 3.9.0`.
2. Victim adds this server as a plain, non-GitHub remote in Desktop (e.g. `git remote add origin https://attacker-host/foo.git`) and performs any Git operation. This triggers `isGitHubHost()` → `updateEndpointVersion()` writes the fake version to `localStorage`, permanently, with no expiry (`app/src/lib/endpoint-capabilities.ts:91-100`).
3. On any subsequent Git network operation against that same origin — in this session or a future one, for this repo or any other repo the user later points at the same host — `getEndpointKind()` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`) now classifies the host as `'enterprise'` instead of `'generic'`.
4. If the victim has (now or later) an `Account` whose endpoint origin matches, `getGitHubCredential` (`trampoline-credential-helper.ts:50-57`) silently attaches that account's real token to the credential response sent back to Git for use against the attacker-influenced host, with no further prompt.

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
