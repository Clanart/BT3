### Title
`SchnorrAggregate::verify` derives aggregation weights bound only to challenges, not to the nonce/key pairs, allowing trivial forgery of aggregate signatures - (File: crypto/schnorr/src/aggregate.rs)

### Summary

Analogous to CVE-2018-8074 — where attacker-supplied input injected unintended conditions into a query — `SchnorrAggregate::verify` lets attacker-controlled signature components (`Rs`, `s`) enter a verification equation whose random weights (`z_i`) are derived exclusively from the ordered list of challenges, never from the `Rs` or public keys themselves. Because the weights are fully predictable before the attacker chooses `Rs`, the attacker can inject a cancellation term that collapses the multiexp to identity, producing a forgery.

### Finding Description

`SchnorrAggregate::verify` builds the weight transcript at crypto/schnorr/src/aggregate.rs:132-136 by appending only `challenge.to_repr()` for each `(key, challenge)` pair:

```rust
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
```

Then at lines 138-145 it draws `z_i = weight(&mut digest)` and checks `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G == 0` via `multiexp_vartime`.

Neither the `R_i` values nor the public keys `A_i` are hashed into `digest`. The weights are therefore a pure public function of the challenges — which the verifier itself supplies and which are, per the API contract, computable by anyone from the (key, nonce, message) tuples. An unprivileged attacker submitting a `SchnorrAggregate` (e.g., via `SchnorrAggregate::read` at lines 77-88, which accepts arbitrary non-identity points) knows every `z_i` before choosing a single byte of `Rs` or `s`.

`SchnorrAggregator::complete` (lines 175-186) has the identical defect on the production side, meaning honestly-produced aggregates and forgeries are verified under the same weight schedule.

### Impact Explanation

Concrete forged aggregate signature. Given any `n ≥ 2` of `(A_i, c_i)` pairs, the attacker:

1. Computes `z_i` by replaying the public transcript (only the `c_i` values are needed).
2. Picks arbitrary `R_2 … R_n` (e.g., the generator).
3. Sets `s = 0` and solves for `R_1`:
   `R_1 = −c_1·A_1 − (z_1^{-1}) · Σ_{i≥2} z_i·(R_i + c_i·A_i)`
4. `Σ z_i·R_i + z_i·c_i·A_i = z_1·(R_1 + c_1·A_1) + Σ_{i≥2} z_i·(R_i + c_i·A_i) = −Σ_{i≥2} z_i·(R_i + c_i·A_i) + Σ_{i≥2} z_i·(R_i + c_i·A_i) = 0`, and `s·G = 0`, so `multiexp_vartime` returns identity and `verify` returns `true`.

The result is a valid aggregate signature over public keys the attacker does not control and messages never signed — a complete break of the aggregate scheme's unforgeability for any verifier relying on `SchnorrAggregate::verify`.

### Likelihood Explanation

Fully deterministic and reachable with public inputs only. The attacker needs no secret material, no valid partial signature, and no interaction — only knowledge of the challenges, which are public by construction (they bind key/R/message). Any code path that deserializes an attacker-supplied `SchnorrAggregate` and calls `verify` accepts the forgery with probability 1. The only mitigating factor is that exploitation requires at least two component signatures (`n = 1` still works if the attacker can set `R_1 = −c_1·A_1` — that verifies too with `s = 0`, since `z_1(R_1 + c_1A_1) = 0`; in fact the single-signature case is even simpler).

### Recommendation

Bind the full statement into the weight transcript before drawing each `z_i`. In `verify`, append each `Rs[i].to_bytes()` and `key.to_bytes()` (and ideally per-index separation) to `digest` prior to calling `weight`, and make `SchnorrAggregator::aggregate`/`complete` commit to the identical data in the identical order so honest aggregates still verify. Standard half-aggregation constructions (eprint 2021/350) require the weights to be unpredictable relative to the adversary's choice of nonces precisely to prevent this cancellation.

let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
digest.append_message(b"challenge", c1.to_repr());
digest.append_message(b"challenge", c2.to_repr());
let z1 = weight::<_, C::F>(&mut digest);   // public
let z2 = weight::<_, C::F>(&mut digest);   // public

// Choose arbitrary R2 (any non-identity point), then:
let R2 = C::generator();
let R1 = (-(c1 * A1)) - ((z2 * z1.invert().unwrap()) * (R2 + (c2 * A2)));
let s = C::F::ZERO;

// verify() computes:
//   z1*R1 + z1*c1*A1 + z2*R2 + z2*c2*A2 - s*G
// = z1*(R1 + c1*A1) + z2*(R2 + c2*A2)
// = -z2*(R2 + c2*A2) + z2*(R2 + c2*A2) = 0  -> is_identity() == true

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }

  pub fn complete(mut self) -> Option<SchnorrAggregate<C>> {
    if self.sigs.is_empty() {
      return None;
    }

    let mut aggregate = SchnorrAggregate { Rs: Vec::with_capacity(self.sigs.len()), s: C::F::ZERO };
    for i in 0 .. self.sigs.len() {
      aggregate.Rs.push(self.sigs[i].R);
      aggregate.s += self.sigs[i].s * weight::<_, C::F>(&mut self.digest);
    }
    Some(aggregate)
  }
