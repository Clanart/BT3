## Analysis Result [1](#0-0) 

I found a concrete, reachable analog of this bug class in the KIP-71 governance parameter validation.

### Title
Missing input validation on `kip71.gastarget` governance parameter allows division-by-zero panic in base-fee calculation — ([File: kaiax/gov/param.go], [File: params/kip71_config.go])

### Summary
The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker` that accepts any `uint64` value, including `0`, unlike its sibling parameter `Kip71BaseFeeDenominator` which explicitly rejects zero (`v != 0`). Because `GasTarget` is later used as a divisor in the KIP-71 (Magma) next-base-fee formula, a zero value causes a `big.Int` division-by-zero panic that is reachable by every node executing consensus-critical code.

### Finding Description
The parameter table in [1](#0-0)  defines:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,
    ...
}
```
`noopFormatChecker` always returns `true` [2](#0-1) , so any `uint64` including `0` passes format validation in `NewVoteData` [3](#0-2) .

The consistency check performed when a vote is submitted or a header is verified also does **not** validate `Kip71GasTarget` — it falls into the "no more checks here" default-pass bucket alongside several other parameters [4](#0-3) , unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` which do get bounds-checked against each other [5](#0-4) .

Once ratified, `GasTarget=0` flows into `KIP71Config.GasTarget` and is consumed by `NextMagmaBlockBaseFee`:
```go
gasTarget := kc.GasTarget
...
} else if parentGasUsed > gasTarget {
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // divide by zero
``` [6](#0-5) 

`math/big.Int.Div` panics on a zero divisor. With `gasTarget = 0`, the `parentGasUsed == gasTarget` shortcut only triggers when `parentGasUsed` is also `0` (i.e., an entirely empty block), so essentially every normal block with nonzero gas usage triggers the `parentGasUsed > gasTarget` branch and panics.

This function is invoked on the hot consensus path for every node:
- Block header validation, called by all full nodes for every incoming block: `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee` [7](#0-6) 
- Gas price oracle used for RPC `eth_gasPrice`/tip suggestions: `oracle.isRelaxedNetwork` [8](#0-7) 
- Block proposers computing the next block's base fee during block assembly.

### Impact Explanation
Once a `kip71.gastarget = 0` vote is ratified at an epoch boundary (a normal governance mechanism, not requiring any exploit beyond a standard `governance_vote` call by the governing node/GC member), **every** node on the network — validators, full nodes, and RPC nodes alike — will panic in `NextMagmaBlockBaseFee` the moment it tries to validate, propose, or price a block referencing the new parameter set. This is a full network halt / consensus-wide denial-of-service, not merely an isolated node crash, and it deterministically affects all honest nodes identically (a state-divergence/liveness failure of the entire chain), matching the "state divergence between honest nodes" and "acceptance of an invalid transaction or block" impact classes.

### Likelihood Explanation
The root cause is entirely deterministic: any single header-governance vote with `kip71.gastarget = 0` passes every layer of validation present in the codebase (`Canonicalizer`, `FormatChecker`, `checkConsistency`) with no rejection, exactly mirroring the reported bug class of admin/governance-parameter setters lacking range checks (as in the reference report's `_updateBaseFee`/`_updatePercentFee`). The only friction is that in "single" governance mode only the designated governing node can cast the vote — but no additional protocol-level safeguard exists to prevent this specific value even from that legitimate, low-friction governance path, and the test suite (`kaiax/gov/headergov/vote_test.go`) reveals `Kip71MaxBlockGasUsedForBaseFee=0` is explicitly rejected (bad test case) while the near-identical `Kip71GasTarget=0` case is absent from bad-vote tests, confirming the omission is unintentional given the analogous check exists for the sibling `BaseFeeDenominator` parameter (`v != 0`).

### Recommendation
Add a non-zero `FormatChecker` for `Kip71GasTarget` analogous to `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, add a defensive `gasTarget == 0` guard directly inside `NextMagmaBlockBaseFee` (mirroring the existing `baseFeeDenominator == 0` fallback at [9](#0-8) ) so that even a pre-existing bad genesis/config value cannot crash the node.

### Proof of Concept
1. Governing node (single mode) or any GC member (none mode) calls `governance_vote("kip71.gastarget", 0)`. `NewVoteData` canonicalizes `0` to `uint64(0)` and `noopFormatChecker` accepts it.
2. `checkConsistency` for `gov.Kip71GasTarget` falls into the default-pass case and returns `nil` [4](#0-3) .
3. The vote is embedded in `header.Vote`, ratified at the next epoch boundary, and becomes part of `ParamSet.GasTarget = 0` from that point on.
4. On the first subsequent block with nonzero `GasUsed`, every node calling `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` (block validators, miners, gas price oracle) executes `x.Div(x, new(big.Int).SetUint64(0))`, which panics in Go's `math/big` package, crashing the node process — reproducible deterministically with the existing `TestNextBlockBaseFee`-style harness in [10](#0-9)  by setting `GasTarget = 0` and any nonzero `parentGasUsed`.

// isRelaxedNetwork returns true if the current network congestion is low to the point
// paying any tip is unnecessary. It returns true when the head block is after Magma fork
// and the next base fee is at the lower bound.
func (oracle *Oracle) isRelaxedNetwork(header *types.Header) bool {
	pset := oracle.govModule.GetParamSet(header.Number.Uint64() + 1)
	nextBaseFee := pset.ToKip71Config().NextMagmaBlockBaseFee(header.Number, header.BaseFee, header.GasUsed)
	return nextBaseFee.Cmp(big.NewInt(int64(pset.LowerBoundBaseFee))) <= 0
}
