# Finding: Governance-only `onAccept` actions authenticate by source **chain** only, not by source **module**

## Summary
`IntentGatewayV2`'s `onAccept` handler (both the EVM `ExtrinsicIntents.sol`/`IntentsBase.sol` implementation and the Tron `IntentGatewayV2.sol` implementation) gates its most sensitive actions — `UpdateParams`, `SweepDust`, `NewDeployment`, and `UpgradeContract` — with a check that only verifies the *chain id* of the incoming request's source, not the *module identity* (`request.from`) that dispatched it. This is a materially weaker check than the one used two functions away in the same contract for user-facing escrow flows, which does bind on module identity.

## Finding Description
In `evm/src/apps/intentsv2/ExtrinsicIntents.sol`, `onAccept` dispatches on `RequestKind`: [1](#0-0) 

For `RedeemEscrow`/`RefundEscrow` it calls `_authenticate`, which checks both source chain **and** that `request.from` equals the registered gateway instance for that chain: [2](#0-1) 

But for the governance-only branch (`NewDeployment`, `UpdateParams`, `SweepDust`, `UpgradeContract`), the guard is:
```solidity
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
```
This checks only that the message originated from the Hyperbridge state machine — it never inspects `incoming.request.from`. Any module/pallet on the Hyperbridge chain capable of dispatching an ISMP `PostRequest` to this gateway's address is treated as authorized governance, because nothing constrains `from` to the specific intents-governance pallet id.

This asymmetry is structural: the same weak pattern is repeated in the Tron variant of the contract: [3](#0-2) 

On the Substrate side, `pallet-ismp`'s generic `IsmpDispatcher::dispatch_request` forwards the caller-supplied `from` field into the outgoing `PostRequest` verbatim, with no enforcement that it matches the calling pallet's own module id: [4](#0-3) 

The example/demo dispatch pallets in the repo confirm the `from` field is simply whatever the dispatching code chooses to put there: [5](#0-4) 

Because `onAccept`'s governance branch never checks `from`, the EVM-side authorization effectively collapses to "any message legitimately proven to have originated from the Hyperbridge state machine, addressed `to` this gateway" — regardless of which pallet/module on that chain actually dispatched it.

## Impact Explanation
If any pallet on the Hyperbridge chain other than the intended intents-governance pallet can dispatch a `PostRequest` with `to` set to an `IntentGatewayV2` address (a capability that generic dispatcher patterns in this repo demonstrate is architecturally supported, since `from`/`to` are caller-supplied plain bytes with no cross-checking against a module allowlist on dispatch), that message would be fully accepted by `onAccept` as legitimate governance. This allows:
- `UpdateParams` — set `protocolFeeBps` up to 9,999 bps (~99.99%) and arbitrary per-destination fee overrides, directly analogous to the reported `setFee`-to-100% griefing issue, but bypassing even the intended admin/governance restriction, [6](#0-5) 
- `SweepDust` — drain accumulated protocol token/native balances to an attacker-chosen beneficiary, [7](#0-6) 
- `UpgradeContract` — point the ERC-1967 proxy at an arbitrary implementation and execute arbitrary init calldata, i.e. full contract takeover, [8](#0-7) 

This satisfies the bounty's impact gate directly: unauthorized execution, transaction/logic manipulation, and fund loss via false authorization acceptance.

## Likelihood Explanation
The vulnerable check itself is unconditionally present in production code, not test-only. What remains unverified from available files is whether a specific *other* pallet in the current Hyperbridge runtime configuration is actually wired to dispatch messages `to` an `IntentGatewayV2` address with a `from` value it controls (i.e., whether the attack surface is currently reachable end-to-end, or only reachable if/when a new pallet with dispatch rights is added). I could not fully inspect `modules/pallets/intents-coprocessor/src/lib.rs`'s internal `Self::dispatch` helper to confirm what `from` value it uses and whether it's uniquely reserved. Given this, likelihood should be treated as **moderate**, contingent on runtime pallet composition, while the code-level defect (missing module-binding check) is a confirmed, provable weakness that violates the stated Hyperbridge invariant that "cross-chain admin effects must not be reachable through ... wrong module bindings."

## Recommendation
Require `onAccept`'s governance branch to check `incoming.request.from` against a stored, dedicated governance-module identifier (the same pattern already used by `_authenticate` for escrow actions), in addition to the chain-id check, e.g.:
```solidity
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())
    || keccak256(incoming.request.from) != keccak256(governanceModuleId)) revert Unauthorized();
```
Apply the same fix to `evm/tron/contracts/apps/IntentGatewayV2.sol`. On the Substrate side, restrict which pallets are permitted to set an arbitrary `to`/`from` when dispatching to governance-sensitive destinations, or route all governance dispatches through a single audited pallet whose module id is the only one ever accepted by downstream `onAccept` checks.

## Proof of Concept
1. Identify (or introduce, if reachable) any pallet on the Hyperbridge chain with access to `T::IsmpDispatcher::dispatch_request` (per the pattern in `modules/pallets/demo/src/lib.rs::dispatch_to_evm`).
2. Construct a `DispatchPost { dest: StateMachine::Evm(<target>), from: <any bytes>, to: <IntentGatewayV2 address>, body: <UpgradeContract or UpdateParams payload> }` and dispatch it.
3. Once relayed and proven (a legitimate state proof, since it's a real committed request on the Hyperbridge chain), the EVM `onAccept` check `keccak256(incoming.request.source) == keccak256(hyperbridge())` passes — `request.from` is never checked.
4. `onAccept` executes the `UpgradeContract`/`UpdateParams`/`SweepDust` branch as if issued by real governance, achieving contract takeover, fee manipulation, or dust theft.

            _authenticate(incoming.request);

	fn dispatch_request(
		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

    function _validateParams(Params memory p) internal view {
        if (p.host == address(0) || p.host.code.length == 0) revert InvalidInput();
        if (p.dispatcher == address(0) || p.dispatcher.code.length == 0) revert InvalidInput();
        if (p.surplusShareBps > 10_000) revert InvalidInput();
        if (p.protocolFeeBps >= 10_000) revert InvalidInput();
        if (p.priceOracle != address(0) && p.priceOracle.code.length == 0) revert InvalidInput();
    }

    /**
     * @dev Updates the gateway's configuration parameters and per-destination protocol fees.
     * Called by Hyperbridge governance to modify fee settings, host address, dispatcher,
     * price oracle, and other operational parameters.
     *
     * Validates all params before applying. Emits ParamsUpdated with the old and new params,
     * then iterates over any destination-specific fee overrides and applies them to
     * `_destinationProtocolFees`.
     *
     * @param update The parameter update containing new params and destination fee overrides.
     */
    function _updateParams(ParamsUpdate memory update) internal {
        _validateParams(update.params);

        emit ParamsUpdated({previous: _params, current: update.params});
        _params = update.params;

        for (uint256 i; i < update.destinationFees.length;) {
            bytes memory chain = update.destinationFees[i].chain;
            uint256 feeBps = update.destinationFees[i].destinationFeeBps;
            if (feeBps >= 10_000) revert InvalidInput();
            _destinationProtocolFees[keccak256(chain)] = feeBps;

            unchecked {
                ++i;
            }
            emit DestinationProtocolFeeUpdated(string(chain), feeBps);
        }
    }
