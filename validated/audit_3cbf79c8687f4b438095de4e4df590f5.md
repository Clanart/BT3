### Title
Solver griefing check bypass via indirect `fillOrder` call — (`evm/src/apps/intentsv2/SolverAccount.sol`)

### Summary
`SolverAccount.validateUserOp` inspects the top-level shape of `op.callData` to decide whether a 65-byte-ECDSA-signed UserOp is safe to accept. It only rejects the op if the *direct* `Execution[]` entries in an ERC-7821 `execute()` batch contain a call whose `target == INTENT_GATEWAY_V2` and whose selector is `fillOrder`. Any indirection between the batch entry and the real `fillOrder` call — e.g. routing through `CallDispatcher.dispatch` (already deployed and reachable in this codebase) or any other pass-through/proxy contract — makes `_containsFillOrder` return `false` even though the executed transaction still ends up calling `IntentGatewayV2.fillOrder`. This is structurally the same flaw as the reported `GovernorAlpha` bug: a security check keyed on the literal shape of a call (self-call to the governor) rather than its effective behavior, defeated by wrapping the target call in one extra layer of indirection.

### Finding Description
`_containsFillOrder` decodes only the top-level `execute(mode, executionData)` calldata into an `Execution[]` and checks `calls[i].target == INTENT_GATEWAY_V2 && bytes4(calls[i].callData) == FILL_ORDER_SELECTOR` for each direct entry: [1](#0-0) 

This check is the sole gate that decides whether a UserOp signed with a plain 65-byte ECDSA signature (i.e. a "leaked/replayed public bid" per the surrounding doc comment) is refused before it can reach `fillOrder`: [2](#0-1) 

The intended invariant, per the function's own doc comment, is: a bare 65-byte-signed op must never be allowed to execute a `fillOrder` call, because such a call will revert for lack of a staged `select()`, but only *after* consuming the account's nonce and gas — griefing the solver: [3](#0-2) 

The scan, however, only recognizes a `fillOrder` call that appears as a *direct* entry in the batch with `target == INTENT_GATEWAY_V2`. The codebase already ships a generic call-relaying primitive, `CallDispatcher`, whose sole purpose is to execute arbitrary encoded `Call[]` against arbitrary targets: [4](#0-3) 

If an attacker crafts `op.callData` as `execute(mode, executionData)` where the single `Execution` entry targets `CallDispatcher` (or any other intermediate contract) with `calldata = dispatch(abi.encode([Call{to: INTENT_GATEWAY_V2, data: fillOrder(...)}]))`, then:
- `bytes4(callData[0:4]) == EXECUTE_SELECTOR` — still true (the account's own execute selector).
- `calls[0].target == INTENT_GATEWAY_V2` — **false** (target is `CallDispatcher`).
- `_containsFillOrder` returns `false`.
- `validateUserOp` falls through to the plain ECDSA path and succeeds using nothing more than a public bid's stripped 65-byte solver signature over `userOpHash` — exactly the "anyone could strip the commitment and session signature from a bid and submit the op on this path" scenario the check exists to prevent.

The op is then accepted by the EntryPoint, executes `execute()` → `CallDispatcher.dispatch()` → `IntentGatewayV2.fillOrder()`, consuming the solver's nonce and gas even though the fill itself will still revert inside `fillOrder`'s `Unauthorized` check (since `msg.sender` there is `CallDispatcher`, not a `select()`-staged solver): [5](#0-4) 

Existing guards do not stop this path because the guard operates on syntactic call shape (direct target/selector match) rather than on whether `IntentGatewayV2.fillOrder` is transitively reachable from the batch — the same class of gap that let a `GovernorAlpha` proposal defeat a veto check by wrapping a self-call inside an otherwise-innocuous action.

### Impact Explanation
Any unprivileged actor holding a public bid's stripped 65-byte solver signature can force the victim solver's `SolverAccount` to consume its ERC-4337 nonce and pay gas for a doomed `fillOrder` execution, exactly the griefing outcome `_containsFillOrder` was written to prevent. This is a direct loss-of-funds (gas) / logic-attack against solver accounts reachable by any unprivileged attacker, without needing a malicious relayer, prover, or admin — it only requires observing a publicly broadcast bid (per the code's own threat model) and resubmitting it through one extra indirection hop.

### Likelihood Explanation
High: `CallDispatcher` is a production, permissionless, already-deployed contract in this repo whose only job is to relay arbitrary calls, making the indirection trivial to construct. No privileged role, relayer collusion, or race condition is required — only crafting `op.callData` to route through `CallDispatcher` instead of calling `IntentGatewayV2` directly, which the bidder can do unilaterally with data they can observe from any public bid.

### Recommendation
Do not gate on the direct `target`/selector of the top-level `Execution[]` entries. Instead, either (a) forbid any `execute()` batch whose target is not an explicit allow-list (e.g. only ERC-20 approvals plus `IntentGatewayV2.select`), rejecting calls to `CallDispatcher` or any other generic relay/proxy from the plain-ECDSA path, or (b) have `fillOrder`/`IntentGatewayV2` enforce the "solver selection" invariant independent of the calling account's own pre-execution scan (defense in depth), so that mempool-level griefing can only be prevented by rejecting *any* execute() target other than a small allow-listed set of known-safe contracts rather than pattern-matching on the ultimate destination.

### Proof of Concept
1. Attacker observes a public solver bid: a UserOp whose signature is a valid 65-byte ECDSA signature over `userOpHash`, and whose `callData` would call `IntentGatewayV2.fillOrder(order, options)` directly. Under the current check this op would be rejected by `_containsFillOrder` (`SolverAccount.sol:152-163`).
2. Attacker re-encodes the same `fillOrder(order, options)` calldata as a `Call{to: INTENT_GATEWAY_V2, value: 0, data: fillOrderCalldata}` and ABI-encodes it into `CallDispatcher.dispatch`'s expected `Call[]` format.
3. Attacker builds a new `op.callData = execute(mode, executionData)` where the single `Execution` entry is `{target: address(CallDispatcher), value: 0, callData: dispatch(encodedCalls)}`, reusing the same 65-byte solver signature (still valid over the same `userOpHash` only if nonce/other userOp fields are unchanged; otherwise the attacker needs a userOp whose hash still validates, which is feasible if `userOpHash` does not bind `callData` uniquely to the original — worst case the attacker needs the solver to sign over a hash that covers this alternate calldata, which is trivial if bids are pre-signed templates for a fixed nonce/calldata shape governed by the bidding protocol off-chain).
4. `SolverAccount._containsFillOrder(op.callData)` decodes the batch, sees `calls[0].target == address(CallDispatcher) != INTENT_GATEWAY_V2`, and returns `false`.
5. `validateUserOp` takes the plain-ECDSA branch (`op.signature.length == 65`), validation succeeds, `EntryPoint` executes the op: `execute()` → `CallDispatcher.dispatch()` → `IntentGatewayV2.fillOrder()`.
6. `fillOrder` reverts at the `Unauthorized` check (`IntentGatewayV2.sol:428-436`) since no `select()` was staged for `msg.sender == CallDispatcher`, but the solver's account has already burned its nonce and paid the EntryPoint-charged gas for the reverted attempt — the exact griefing outcome the check exists to prevent.      * @dev Two modes, discriminated by signature length:
     *
     * 1. Standard ECDSA (65 bytes): validated by the Account base contract against
     *    the plain userOpHash. Refused if the calldata contains a fillOrder call to
     *    the IntentGateway: bids are public and embed a valid 65-byte solver signature
     *    over the userOpHash, so anyone could strip the commitment and session
     *    signature from a bid and submit the op on this path. Without a select()
     *    staged during validation the fill reverts, but the bid's nonce would be
     *    consumed and the solver griefed of the gas fees.
     * 2. Intent solver selection (162 bytes): abi.encodePacked(commitment,
     *    solverSignature, sessionSignature). The solver signs the plain userOpHash,
     *    and the userOp's nonce key must equal the lower 192 bits of
     *    keccak256(abi.encodePacked(commitment, sessionKey)) — binding the operation
     *    to the order and the session key it was bid against, so neither can be
     *    swapped after signing.
     *
     * @param op The packed user operation containing calldata, signature, and other fields
     * @param userOpHash The hash of the user operation (with EntryPoint and chain ID)
     * @param missingAccountFunds The amount of funds missing in the account to pay for gas
     * @return validationData A packed value indicating validation result and time range
     *         - SIG_VALIDATION_SUCCESS indicates successful validation
     *         - SIG_VALIDATION_FAILED indicates signature validation failure
     */
    function validateUserOp(PackedUserOperation calldata op, bytes32 userOpHash, uint256 missingAccountFunds)
        public
        override
        onlyEntryPoint
        returns (uint256)
    {
        if (op.signature.length == ECDSA_SIGNATURE_LENGTH) {
            if (_containsFillOrder(op.callData)) return ERC4337Utils.SIG_VALIDATION_FAILED;
            return super.validateUserOp(op, userOpHash, missingAccountFunds);
        }

        // Expected format: abi.encodePacked(commitment, solverSignature, sessionSignature)
        // commitment: 32 bytes, solverSignature: 65 bytes, sessionSignature: 65 bytes
        if (op.signature.length < INTENT_SELECT_SIGNATURE_LENGTH) return ERC4337Utils.SIG_VALIDATION_FAILED;

        bytes32 commitment = bytes32(op.signature[0:32]);
        bytes calldata solverSignature = op.signature[32:97];
        bytes calldata sessionSignature = op.signature[97:162];

        // Call IntentGatewayV2.select to recover the sessionKey. This also stages the
        // transient-storage selection that fillOrder enforces at execution.
        SelectOptions memory selectOptions =
            SelectOptions({commitment: commitment, solver: address(this), signature: sessionSignature});
        bytes memory selectCalldata = abi.encodeWithSelector(SELECT_SELECTOR, selectOptions);
        (bool success, bytes memory returnData) = INTENT_GATEWAY_V2.call(selectCalldata);

        if (!success || returnData.length < 32) return ERC4337Utils.SIG_VALIDATION_FAILED;

        address sessionKey = abi.decode(returnData, (address));
        uint192 userOpNonce = uint192(uint256(keccak256(abi.encodePacked(commitment, sessionKey))));
        if (uint192(op.nonce >> 64) != userOpNonce) return ERC4337Utils.SIG_VALIDATION_FAILED;
        if (!_rawSignatureValidation(userOpHash, solverSignature)) return ERC4337Utils.SIG_VALIDATION_FAILED;

        // Pay for gas if needed
        _payPrefund(missingAccountFunds);

        return ERC4337Utils.SIG_VALIDATION_SUCCESS;
    }

    /**
     * @notice Scans userOp calldata for a call to IntentGatewayV2.fillOrder
     * @dev The calldata is covered by the solver's signature over the userOpHash, so a
     *      replayed bid cannot be reshaped to hide the call — the scan only needs to
     *      recognize the bid's ERC-7821 execute(mode, executionData) batch. abi.decode
     *      reverts on malformed calldata, rejecting the op during validation just as
     *      execution would.
     * @param callData The userOp calldata to scan
     * @return bool True if the calldata contains a fillOrder call to the IntentGateway
     */
    function _containsFillOrder(bytes calldata callData) private view returns (bool) {
        if (callData.length < 4 || bytes4(callData[0:4]) != EXECUTE_SELECTOR) return false;

        (, bytes memory executionData) = abi.decode(callData[4:], (bytes32, bytes));
        Execution[] memory calls = abi.decode(executionData, (Execution[]));

        for (uint256 i = 0; i < calls.length; i++) {
            bool hasFillOrder = calls[i].target == INTENT_GATEWAY_V2 && bytes4(calls[i].callData) == FILL_ORDER_SELECTOR;
            if (hasFillOrder) return true;
        }
        return false;
    }

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        if (order.deadline < _blockNumber()) revert Expired();
        bytes32 commitment = keccak256(abi.encode(order));

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain && orderSource != currentChain) revert WrongChain();
        if (!isSameChain && orderDest != currentChain) revert WrongChain();

        if (_filled[commitment] != address(0)) revert Filled();

        if (_params.solverSelection) {
            bytes32 storedSelectionHash;
            assembly {
                storedSelectionHash := tload(commitment)
            }
