## Title
Unsynchronized cross-copy read of shared `MemNode` hash cache during live commits diverges the AppHash - ([File: sei-db/state_db/sc/memiavl/tree.go])

### Summary
The Chrome/Mojo CVE describes a race between two threads mutating shared IPC state without proper synchronization, exploitable via a crafted page for a sandbox escape. The closest reachable analog in sei-chain is a documented, still-open data race between a `Tree.Copy()` (used for trace snapshots taken every `EndBlock`) and the live tree it was copied from: `RootHash()`/`GetProof()` mutate `MemNode.hash` in place under the *tree's own* `mtx`, but a `Copy()` gets an independent mutex while still sharing the underlying `MemNode` pointers with the original tree, so the two trees "serialize against nothing."

### Finding Description
`Tree.RootHash()` and `Tree.GetProof()` were hardened (per the code comments referencing "Immunefi 83246 / STO-601") to take the tree's write lock `t.mtx` before touching node hashes, because `Node.Hash()`/`SafeHash()` lazily populate `MemNode.hash` in place — a data race if two goroutines do this concurrently under only a read lock. [1](#0-0) [2](#0-1) 

However, the accompanying test `TestCopyReadRaceWithLiveCommits` explicitly documents that this fix does **not** close the whole class of the bug: `Tree.Copy()` returns a snapshot object with its own, independent mutex while the copy and the original tree continue to share the same underlying `MemNode` instances. Because `RootHash`/`GetProof`/`Set`/`Remove` on the *live* tree only take the live tree's lock, and the *copy's* `RootHash`/`Get`/`GetProof` only take the copy's own (different) lock, concurrent hash-cache mutation on shared nodes is possible with no serialization at all between the two trees — the same unsynchronized in-place write that the original fix targeted, just reachable through a different code path. [3](#0-2) 

The comment identifies the concrete production trigger: `SnapshotSCStore` hands `EndBlock` a `DB.Copy()` for the tracing/replay snapshot store, and by the time that copy is taken, `ApplyChangeSets` has already released `db.mtx`, so the copy can share nodes stamped at `version+1` that remain mutable under the old `cowVersion = t.version` floor. This path (`k.traceSnapshotCapture()` / `k.traceSnapshotStore.Put`) runs unconditionally in `EndBlock` for every block once trace snapshotting is wired up, i.e., driven purely by ordinary transaction processing — no privileged actor required. [4](#0-3) 

Concurrently, a client can trigger reads on that just-taken copy (or on the live tree it diverged from) via ordinary state queries/proofs while the consensus goroutine keeps applying further change sets and calling `RootHash`/`SaveVersion` on the live tree, corrupting the shared `MemNode.hash` cache in place.

### Impact Explanation
A corrupted internal hash cache serialized into a store root can diverge the computed AppHash from what other validators compute for the same block (this is precisely the impact of the original Immunefi 83246 / STO-601 finding that the `RootHash`/`GetProof` locking was built to prevent). An AppHash divergence across validators on a live network is a consensus/chain-split condition — validators would halt or fork depending on how many are affected by the race timing, satisfying the "permanent chain split" / "validator halt" impact bar. Because trace-snapshot capture (`k.traceSnapshotCapture()`) runs on every `EndBlock` once configured, and any node running with tracing enabled has a live query surface, the vulnerable window recurs continuously in production rather than being a one-off/edge case.

### Likelihood Explanation
Likelihood is data-race-timing-dependent (matching the nature of the CVE hint, a Mojo race requiring precise timing under `-race`/adversarial scheduling), so it is not deterministically triggerable on demand, but the test file's own docstring states this is "one lock away from the fix," i.e., an acknowledged, unresolved gap rather than a hypothetical. It requires: (1) trace snapshotting enabled (a supported, documented node configuration, not a special/experimental flag), (2) ordinary block production continuing to mutate the live tree, and (3) a concurrent read (query/proof) against the just-taken copy or the live tree during the same window. All three are reachable purely through public RPC read traffic combined with normal transaction throughput — no privileged network position, validator collusion, or governance action needed.

### Recommendation
Extend the same protection used for `RootHash`/`GetProof` to the `Copy()` boundary: either (a) make `Copy()` perform a true deep/structural clone of nodes whose hash has not yet been finalized (not just a shallow pointer copy) so the copy never shares mutable `MemNode` state with the live tree, or (b) have the copy and the source share a single mutex (or otherwise serialize `Copy()` against any in-flight `RootHash`/`GetProof`/mutation on the source) so hash-cache population can never race across the two views. Add the currently-missing enforcement so that `TestCopyReadRaceWithLiveCommits` actually exercises the fixed path under `go test -race` as a regression guard, mirroring `TestTreeProofRaceWithCommit`.

// RootHash updates the hashes and return the current root hash,
// it clones the persisted node's bytes, so the returned bytes is safe to retain.
//
// It takes the write lock (not RLock) because Hash() lazily populates
// MemNode.hash in place on the live nodes. Two goroutines mutating that
// shared cache under a read lock — e.g. a commit's RootHash racing a
// latest-height proof query's GetProof — is a data race that can serialize
// a stale internal hash into the store root and diverge the AppHash
// (Immunefi 83246 / STO-601). Callers that already hold t.mtx must use
// rootHashNoLock instead.
func (t *Tree) RootHash() []byte {
	t.mtx.Lock()
	defer t.mtx.Unlock()
	return t.rootHashNoLock()
}

// GetProof takes a key for creating existence or absence proof and returns the
// appropriate merkle.Proof. Since this must be called after querying for the value, this function should never error
// Thus, it will panic on error rather than returning it
//
// It takes the write lock for the whole proof build because the traversal
// reads sibling node hashes via Node.Hash(), which lazily populates
// MemNode.hash in place. Holding the write lock serializes that mutation
// against a concurrent commit's RootHash and against Set/Remove, closing the
// AppHash-divergence race (Immunefi 83246 / STO-601). Internally it uses the
// *NoLock helpers to avoid recursively re-acquiring t.mtx.
func (t *Tree) GetProof(key []byte) *ics23.CommitmentProof {
	t.mtx.Lock()
	defer t.mtx.Unlock()
	return t.getProofNoLock(key)
}

// TestCopyReadRaceWithLiveCommits covers the cross-copy hole that the per-tree
// write lock does not close. RootHash and the proof builders take the write lock
// because MemNode.Hash fills the hash cache in place (Immunefi 83246), but Copy
// gives each tree its own mutex, so a copy and the tree it came from serialize
// against nothing. Reading a copy whose nodes the live tree is still free to
// mutate is the same unsynchronized access, one lock away from the fix for it.
//
// This is the trace-snapshot path: SnapshotSCStore hands EndBlock a DB.Copy, and
// ApplyChangeSets has already released db.mtx by then, so the copy can share
// nodes stamped at version+1 that the old cowVersion = t.version floor left
// mutable. Its consequence is a wrong trace or proof rather than a bad snapshot
// file, which is why it is separate from the writer test below.
func TestCopyReadRaceWithLiveCommits(t *testing.T) {
	const (
		rounds           = 4
		blocksPerRound   = 20
		keysPerChangeSet = 200
	)

	tree := seedTree(t, copyTestSeedKeys)

	for round := 0; round < rounds; round++ {
		// Copy mid-version, where DB.Copy lands between ApplyChangeSets and Commit.
		tree.ApplyChangeSet(changeSet(round*53, keysPerChangeSet, fmt.Sprintf("pre%02d", round)))
		leased := tree.Copy()

		var wg sync.WaitGroup
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := 0; i < blocksPerRound; i++ {
				_ = leased.RootHash()
				_ = leased.Get([]byte(fmt.Sprintf("key%08d", i)))
				_ = leased.GetProof([]byte(fmt.Sprintf("key%08d", i)))
			}
		}()

		_, _, err := tree.SaveVersion(true)
		require.NoError(t, err)
		for block := 0; block < blocksPerRound; block++ {
			tree.ApplyChangeSet(changeSet(block*17, keysPerChangeSet, fmt.Sprintf("r%02db%02d", round, block)))
			_, _, err := tree.SaveVersion(true)
			require.NoError(t, err)
		}
		wg.Wait()
	}
