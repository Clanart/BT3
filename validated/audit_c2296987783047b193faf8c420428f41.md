### Title
Consensus-incentive reward misattribution via `messages[0]`-only signer lookup lets an unprivileged submitter collect rewards earned by other consensus messages in the same batch - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
The Lido report shows that hardcoding a single value (`address(0)` as referral) instead of correctly attributing a reward to the party that earned it causes that reward to be silently lost/misdirected. `pallet-consensus-incentives::on_executed` has the same class of bug: it hardcodes reward attribution to the signer recovered from `messages[0]` alone, then pays that one signer for **every** `StateMachineUpdated` event produced anywhere in the whole batch, regardless of which message in the batch actually produced each state advance.

### Finding Description
`FeeHandler::on_executed` is invoked once per batch of ISMP messages processed by `pallet_ismp::Pallet::<T>::execute` [1](#0-0) .

The consensus-incentives implementation only inspects the **first** message in the batch to recover a payee, ignoring the signer of any other `Message::Consensus` that may be present later in the same `Vec<MessageWithWeight>`: [2](#0-1) 

It then collapses **all** `StateMachineUpdated` events in the batch — for every state machine touched, no matter which message triggered the update — into a single reward loop paid entirely to that one `messages[0]` signer: [3](#0-2) 

The `signer` field on a `Message::Consensus` is not a proof of who produced/discovered the underlying consensus data — the consensus proof bytes themselves are public/verifiable cryptographic material (BEEFY/GRANDPA/sync-committee proofs), and the pallet only checks that `signer` recovers to a valid sr25519 key over `keccak256(consensus_proof)`; it never ties that signature to exclusive possession of the proof. Anyone who can obtain a valid consensus proof (their own, or one that is publicly obtainable/about to be relayed by someone else) can sign its hash with their own key and place that `Message::Consensus` at index 0 of their own batch, then append additional (possibly large-impact) consensus or other messages after it. Since `execute()` processes the whole `Vec<Message>` from a single unsigned submission and `on_executed` derives the payee from index 0 only, the submitter of that batch collects reward for every `StateMachineId` advanced by the batch — including advances driven by messages that were not signed by them.

### Impact Explanation
This is a wrong-beneficiary / loss-of-funds bug in a reward-distribution path funded from `TreasuryAccount`: [4](#0-3) 
An attacker who submits a batch mixing a cheap, self-signed `Message::Consensus` at position 0 with additional consensus updates for other, higher-value state machines can redirect the entire `RelayerRewarded` payout to themselves, at the expense of whichever party actually should be credited for the other state machine's advance. The `LastRewardedHeight` watermark prevents double-paying the *same* span twice, but it does nothing to fix *who* gets paid for a given span — the attribution itself is corrupted, matching exactly the "loss of rewards due to hardcoded/misattributed payee" pattern in the external report.

### Likelihood Explanation
- `pallet_ismp::Pallet::execute` accepts `Vec<Message>` and does not require all messages to be signed by the same relayer key or the extrinsic caller; each `Message::Consensus`'s `signer` is a self-attached attestation, not an origin check [5](#0-4) .
- Consensus proof bytes are inherently public (finality/BEEFY/light-client proofs), so no compromised key, malicious relayer, or privileged access is required — any unprivileged party that can package a batch can attempt this.
- No malicious peer, prover, or governance actor is needed; this is a pure logic flaw in reward bookkeeping reachable through a normal, permissionless message-submission entrypoint.

### Recommendation
Attribute rewards per `Message::Consensus` rather than to `messages[0]` globally: iterate every `Message::Consensus` in the batch, recover its own signer, and only credit the `StateMachineUpdated` events that are demonstrably produced by *that specific message* (e.g., by correlating `MessageResult::ConsensusMessage` events per-message instead of flattening all events into one collection before the reward loop, as `Pallet::<T>::execute` currently does at [6](#0-5) ). This keeps the per-message → per-event association intact so `on_executed` can pay the correct signer for each state machine's advance.

### Proof of Concept
1. Attacker crafts `Message::Consensus` `A` with `consensus_proof = <trivial/no-op proof for chain X>`, signs `keccak256(consensus_proof)` with their own key, producing `signer = attacker_sig`.
2. Attacker obtains a second, independently valid `Message::Consensus` `B` carrying a real, publicly available consensus proof that meaningfully advances chain Y (this proof data does not need to be secret or attacker-produced — it is public cryptographic proof material anyone can package).
3. Attacker submits the unsigned batch `[A, B]` to `pallet_ismp`'s message-handling extrinsic, which calls `Pallet::<T>::execute(vec![A, B])`.
4. `execute()` validates both messages, producing `StateMachineUpdated` events for both chain X and chain Y, and calls `T::FeeHandler::on_executed(messages_with_weights, events)` [7](#0-6) .
5. `consensus-incentives::on_executed` reads `messages.get(0)` → message `A` → recovers `attacker` as the sole payee, then pays `attacker` the reward for **both** chain X's and chain Y's advance via `process_message` [8](#0-7) .
6. The relayer who actually should be credited for chain Y's advance (had they submitted `B` alone) receives nothing; the treasury pays out to the attacker instead — a wrong-beneficiary fund loss identical in structure to the CSBondCore hardcoded-referral bug.

**Note:** I was unable to locate the exact extrinsic definition that wraps `Pallet::<T>::execute` (e.g., a `handle` or `handle_messages` call in `modules/pallets/ismp/src/lib.rs`) within the indexed content to confirm its exact origin check (`ensure_none` vs signed); other reward-claim extrinsics in this codebase (e.g., `claim_outbound_consensus_delivery_reward`, `claim_outbound_request_delivery_reward`) are confirmed `ensure_none`/unsigned and permissionless [9](#0-8) , which is consistent with `handle_incoming_message`/`execute` also being reachable without privileged origin, but a Devin session with full file access should verify the exact extrinsic wiring before treating this as fully confirmed.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
