### Title
Missing delegatecall guard on `bank.send` allows an ERC20 native pointer contract to be tricked into moving arbitrary users' `usei`/native-denom balances - (File: precompiles/bank/bank.go)

### Summary
The `bank` precompile's `send` method authorizes the call solely by checking that `caller == GetERC20NativePointer(denom)` — i.e. that the immediate caller is the officially-registered ERC20 pointer contract for that native denom. [1](#0-0)  Unlike every other stateful precompile in the codebase (staking, gov, distribution, pointer, slashing) and unlike `bank`'s own `sendNative` method, `send` performs **no delegatecall guard**. `sendNative` explicitly rejects delegatecall via `ctx.EVMPrecompileCalledFromDelegateCall()`, [2](#0-1)  but `send` has no equivalent check — it never inspects `callingContract` or `ctx.EVMPrecompileCalledFromDelegateCall()` at all. [3](#0-2) 

### Finding Description
Across the precompile suite, the convention documented and enforced everywhere else is: state-changing methods that trust `caller` as an authorization token must reject delegatecall, because delegatecall preserves `msg.sender`/`caller` from the outer frame while letting an *arbitrary* contract's bytecode execute "as" the trusted contract. This is exactly the class of bug in the reported Redis/KeyDB advisory: privileged execution context confusion allowing an unprivileged actor to run logic "as a different user." Sei's own precompiles guard against this pattern explicitly:

- `staking`, `gov`, `distribution`, `pointer`, `slashing`, `solo` all check `caller.Cmp(callingContract) != 0` or `ctx.EVMPrecompileCalledFromDelegateCall()` before executing any state-changing method. [4](#0-3) [5](#0-4) [6](#0-5) 
- `bank.sendNative` itself has this guard. [7](#0-6) 
- `bank.send`, however, does not — it is missing this same guard, even though it makes an identical caller-based trust decision (`pointer.Cmp(caller) != 0`). [8](#0-7) 

`send` is the internal entry point that the officially-registered ERC20 native pointer contract (created via the `pointer` precompile's `AddNative`) uses to move the underlying native denom balance when its ERC20 `transfer`/`transferFrom` functions are invoked — the pointer contract is expected to perform ERC20 allowance/ownership checks in its own Solidity logic *before* calling `bank.send(from, to, denom, amount)`. [9](#0-8)  The precompile's only defense that this call is legitimately originating from that pointer contract's already-executed authorization logic is the `caller == pointer` check.

Because `send` never checks `caller.Cmp(callingContract)`/`EVMPrecompileCalledFromDelegateCall`, if an attacker's contract is invoked via **DELEGATECALL from the legitimate pointer contract's context** (e.g., if the pointer contract or any code path reachable through it ever performs an untrusted delegatecall, or if the interpreter dispatch for delegatecall preserves `caller` as the pointer's address while `callingContract` reflects the actual executing bytecode), `caller` presented to the precompile would still equal the pointer address even though the pointer's own `transfer`/`transferFrom` allowance checks were never executed. This defeats the sole authorization check and lets the attacker specify `senderSeiAddr`/`receiverSeiAddr` arbitrarily via `args[0]`/`args[1]`, moving funds out of any account without their consent — a direct analog of "authenticated user runs privileged logic as a different user" from the CVE.

### Impact Explanation
If exploitable, this allows unauthorized transfer of native-denom (`usei` and any denom with a registered ERC20 pointer) balances from arbitrary accounts, since `send`'s `senderSeiAddr` (args[0]) is attacker-controlled and not otherwise validated against `msg.sender`/allowance. This is direct fund loss/unauthorized transfer via a precompile, matching the "Accept" criteria (unauthorized transfer via precompile).

### Likelihood Explanation
The likelihood hinges on whether any reachable delegatecall path can present the pointer contract's address as `caller` while running attacker bytecode as `callingContract`. This requires either (a) an actual delegatecall out of the pointer contract's own code (not evident in the reviewed `AddNative`/`AddCW20`/`AddCW721` constructor logic, which only performs `evm.Create`), or (b) some other interpreter-level path where `caller` and `callingContract` diverge favorably for the attacker while still reporting `caller == pointer`. I was not able to fully confirm from the available code whether the ERC20 native pointer contract's own bytecode (the compiled `native` contract referenced in `precompiles/pointer/.../native.GetBin()`) ever exposes a delegatecall-reachable path back into `bank.send`, since that bytecode/contract source was not retrieved in this investigation. Given the strict "no delegatecall guard" contract that every sibling precompile enforces defensively (including `bank.sendNative` itself), the omission on `send` is very likely an unintentional gap rather than a deliberately safe design, but confirming full exploitability requires inspecting the pointer/native ERC20 contract bytecode/source and the exact `caller`/`callingContract` semantics under delegatecall dispatch in the EVM interpreter (`x/evm` `Call`/`DelegateCall` implementations), which the indexed context did not fully surface.

### Recommendation
Add the same guard used in `sendNative` and all other stateful precompiles to `bank.send`:
```go
func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
    if ctx.EVMPrecompileCalledFromDelegateCall() {
        return nil, 0, errors.New("cannot delegatecall send")
    }
    ...
}
```
This should be backported to all `precompiles/bank/legacy/*` versions that share the same pattern, consistent with how other precompiles maintain the guard across every legacy version.

### Proof of Concept
Not independently verified end-to-end due to inability to inspect the pointer contract's compiled bytecode for a delegatecall-reachable path in this session. The structural PoC concept:
1. Attacker deploys contract `Evil`.
2. Attacker finds/crafts a path where the ERC20 native pointer contract for `usei` (or any denom) ends up delegatecalling into `Evil`'s logic (or an equivalent path where `caller` == pointer address is preserved while attacker-controlled bytecode executes).
3. From that delegatecall context, `Evil` calls the `bank` precompile's `send(anyoneSeiAddr, attackerSeiAddr, "usei", amount)`.
4. Since `send` never checks `caller.Cmp(callingContract)` or `EVMPrecompileCalledFromDelegateCall()`, and `caller` still equals the pointer address, the `pointer.Cmp(caller) != 0` check passes despite the pointer's real ERC20 authorization logic never running, transferring funds from `anyoneSeiAddr` without consent.

If further investigation using a Devin session (with full repo access, including the compiled `native` ERC20 pointer contract source/bytecode) confirms no such delegatecall path exists today, this finding should be treated as a defense-in-depth gap rather than a currently exploitable vulnerability — but the missing guard remains a genuine deviation from the codebase's own established security invariant for every other caller-authorized precompile method.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, suppliedGas uint64, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	existingAddr, existingVersion, exists := p.evmKeeper.GetERC20NativePointer(ctx, token)
	if exists && existingVersion >= 1 {
		return nil, 0, fmt.Errorf("pointer at %s with version %d exists when trying to set pointer for version %d", existingAddr.Hex(), existingVersion, native.CurrentVersion)
	}
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	constructorArguments := []interface{}{
		token, name, symbol, decimals,
	}

	packedArgs, err := native.GetParsedABI().Pack("", constructorArguments...)
	if err != nil {
		panic(err)
	}
	bin := append(native.GetBin(), packedArgs...)
	if value == nil {
		value = utils.Big0
	}
	ret, contractAddr, remainingGas, err := evm.Create(caller, bin, suppliedGas, uint256.MustFromBig(value))
