### Title
Server-Side Request Forgery via unauthenticated on-chain DataLayer mirror URLs - (File: `chia/data_layer/data_layer_wallet.py`)

### Summary
`DataLayerWallet.coin_added()` accepts a DataLayer "mirror" URL purely from the memos of any coin spend that creates a coin with the well-known mirror puzzle hash. No wallet or DataLayer node code validates the origin, scheme, or target host of that URL before the `DataLayer` service later fetches data from it with `aiohttp`. An unprivileged spend-bundle submitter can therefore plant an attacker-controlled URL (pointing at internal services, cloud metadata endpoints, or arbitrary hosts) as a "mirror" for any DataLayer store that a victim node is tracking, causing the victim's DataLayer service to issue outbound HTTP requests to that URL — the same bug class as CVE-2024-38514 (unvalidated `endpoint` parameter driving server-initiated HTTP requests).

### Finding Description
The mirror puzzle is a fixed, ownerless puzzle (`create_mirror_puzzle()` = `P2_PARENT.curry(Program.to(1))`), so anyone can spend into a coin with that puzzle hash. `get_mirror_info()` extracts the `launcher_id` and URL list straight from the `CREATE_COIN` condition's memos with no signature or ownership check tying the memo data to the actual store owner: [1](#0-0) 

`DataLayerWallet.coin_added()` picks up any coin matching the mirror puzzle hash and, if the referenced `launcher_id` happens to be tracked locally (i.e., the victim is subscribed to that store), records the attacker-supplied URLs as a legitimate `Mirror` with no host/scheme validation: [2](#0-1) 

The `DataLayer` service later pulls these mirror URLs straight from wallet state into its local subscription/server list: [3](#0-2) 

and `fetch_and_validate()` iterates over these attacker-influenced `server_info.url` values and passes them into the download pipeline: [4](#0-3) 

`download_file()` then makes the outbound HTTP request via `http_download(...)` (or a `PluginRemote` POST) using that URL, again with no scheme/host allow-listing (e.g., blocking loopback, link-local, or private ranges): [5](#0-4) 

The DataLayer module's own internal documentation explicitly acknowledges mirror URLs as an untrusted external input, but frames the mitigation purely in terms of validating *downloaded content* against the wallet-advertised root — not in terms of restricting *where the request itself is sent*: [6](#0-5) 

This is the SSRF-relevant gap: content-integrity validation (comparing reconstructed Merkle roots) does not prevent the request itself from being routed to an internal/forbidden host chosen entirely by an unprivileged party.

### Impact Explanation
Any node running a DataLayer service that subscribes to or owns a public DataLayer store can be coerced into issuing outbound HTTP(S) requests to an attacker-chosen URL, simply because some other unprivileged user broadcast a spend bundle creating a mirror coin with malicious memos referencing that store's `launcher_id`. This can be used to probe or attack internal network services reachable from the DataLayer host (e.g., other local RPC ports, cloud metadata endpoints, internal admin panels) — a classic SSRF impact. Because store `launcher_id`s are public and mirror creation costs only a small on-chain fee/coin, this is broadly reachable by any spend-bundle submitter, not an operator or peer with special trust.

### Likelihood Explanation
High likelihood of reachability for any actively used public DataLayer store: mirror-coin creation requires no special permission beyond being able to submit a standard spend bundle with the fixed mirror puzzle hash and desired memos, and `is_launcher_tracked()` is satisfied for any store a victim is already following (a normal, common configuration for DataLayer clients that mirror/replicate public datasets).

### Recommendation
Validate mirror/server URLs before they are persisted as trusted subscription servers and again immediately before making an outbound request: enforce an `http(s)`-only scheme, reject loopback/link-local/private/reserved IP ranges (including after DNS resolution, to prevent DNS-rebinding), and consider requiring mirror-URL updates to be authenticated by the actual DataLayer singleton owner (e.g., verifying the mirror coin's provenance ties back to the singleton's authorized spend path) rather than trusting arbitrary memo data from any coin matching the fixed mirror puzzle hash.

### Proof of Concept
1. Identify a public DataLayer `launcher_id` (store id) that is widely subscribed to (e.g., a popular public dataset store).
2. Craft and broadcast a spend bundle creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and a `CREATE_COIN` condition whose memos are `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or any internal target URL), per the format parsed by `get_mirror_info()`.
3. Once the coin confirms, any node tracking that `launcher_id` records the malicious URL via `DataLayerWallet.coin_added()` → `dl_store.add_mirror()`.
4. On its next subscription cycle, that node's `DataLayer.update_subscriptions_from_wallet()` and `fetch_and_validate()` will include the malicious URL in `servers_info` and issue an outbound HTTP request to it via `download_file()`/`http_download()`, achieving SSRF against the victim's network context.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),

                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
