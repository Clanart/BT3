### Title
Scanner reports immature coinbase outputs as spendable - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`Scanner::scan_block` scans every transaction in a block, including `block.txdata[0]` — the coinbase transaction — and returns matching outputs as `ReceivedOutput` values without checking Bitcoin’s 100-block coinbase maturity rule. [1](#0-0) 

### Finding Description
`scan_transaction` reports any output whose `script_pubkey` matches a registered scanner script, constructing a `ReceivedOutput` from the transaction ID and output index. [2](#0-1)  `scan_block` invokes this logic for all transactions, including the coinbase transaction, rather than skipping `block.txdata[0]`. [3](#0-2) 

The resulting `ReceivedOutput` is accepted by `SignableTransaction::new`, which uses its `outpoint` directly as a transaction input without tracking whether the source was a coinbase output or whether it has reached maturity. [4](#0-3) 

### Impact Explanation
A miner can create a coinbase output paying to the monitored Taproot script. `scan_block` reports that output as received, and downstream wallet code can construct and sign a spend attempt for it. Bitcoin consensus rules prohibit spending a coinbase output until it has 100 confirmations, so the wallet reports funds as received that are not currently spendable and can produce an invalid transaction. [3](#0-2) 

### Likelihood Explanation
This is reachable through a normal Bitcoin block containing a coinbase transaction paying to a registered script. A miner controls the coinbase output script and can intentionally target the scanner; ordinary mining can also trigger the behavior. [5](#0-4) 

### Recommendation
Change `Scanner::scan_block` to skip `block.txdata[0]`, or extend `ReceivedOutput`/scanner results to carry coinbase-maturity metadata and reject immature coinbase inputs in `SignableTransaction::new`. Add a regression test containing a mature regular transaction and an immature coinbase output paying to the same script. [6](#0-5) 

### Proof of Concept

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
