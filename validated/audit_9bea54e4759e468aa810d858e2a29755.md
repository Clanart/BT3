### Title
Division-by-zero in mempool block-bundle assembly via fully-deduplicated identical spend crashes `create_bundle_from_mempool_items` - ([File: chia/full_node/mempool.py])

### Summary
`Mempool.create_bundle_from_mempool_items` computes `item_cost = cost - cost_saving` and then unconditionally evaluates `fee / item_cost` as an argument to `log.info(...)`, without guarding against `item_cost == 0`. An unprivileged mempool submitter can craft two mempool items that both spend the same coin with an identical solution and mark that spend `ELIGIBLE_FOR_DEDUP`. When the block-bundle builder processes the second (lower-priority) item, the whole item's cost is fully absorbed by `cost_saving` (because for a single-coin item the item's total `conds.cost` equals that one spend's per-coin cost, which is exactly what gets deduplicated), driving `item_cost` to `0` and raising an uncaught `ZeroDivisionError`.

### Finding Description
In `chia/full_node/mempool.py`, `create_bundle_from_mempool_items` iterates mempool items in priority order and, for each item, computes the cost that should be added to the in-progress block: [1](#0-0) 

Specifically:
- `cost = item.conds.cost` is the whole spend bundle's total CLVM cost.
- `cost_saving` comes from `IdenticalSpendDedup.get_deduplication_info`, which sums `dedup_coin_spend.cost` for every coin in the item that is `eligible_for_dedup` and was already registered by a prior item in the same block-building pass with an identical solution: [2](#0-1) 
- `item_cost = cost - cost_saving` is then used directly as the divisor in an eagerly-evaluated logging call: `log.info("Cumulative cost: %d, fee per cost: %0.4f, item cost: %d", cost_sum, fee / item_cost, item_cost)`.

For a mempool item that spends exactly one coin, `item.conds.cost` (the item's total cost) is numerically identical to that single coin spend's per-coin cost, which is computed the same way in `validate_spend_bundle`: [3](#0-2) 

If an attacker submits two single-coin spend bundles that (a) spend the exact same coin, (b) carry the exact same puzzle reveal/solution, and (c) are both marked `ELIGIBLE_FOR_DEDUP` by the CLVM conditions, `check_removals` in `mempool_manager.py` explicitly allows both to coexist in the mempool rather than treating them as a conflict: [4](#0-3) 

When the second item is processed during block assembly, `get_deduplication_info` finds the coin already registered (from the first, higher-fee-rate item) with an identical solution, so `cost_saving` becomes exactly equal to that coin spend's cost — which for a single-coin item equals the item's total `cost`. This makes `item_cost = cost - cost_saving == 0`, and `fee / item_cost` raises `ZeroDivisionError`. Because the log statement's arguments (including the division) are evaluated as part of the Python call regardless of the configured log level, this crash cannot be avoided by disabling logging.

This is directly analogous to the reported ImageMagick `MeanShiftImage` divide-by-zero: attacker-supplied input (here, a pair of mempool spend bundles) drives an internal denominator to zero in a core processing routine, crashing the routine.

### Impact Explanation
`create_bundle_from_mempool_items` is the routine full nodes/farmers use to assemble a block from the mempool. An unhandled `ZeroDivisionError` here aborts block bundle creation for that call, which is a spend-triggered halt of transaction processing — precisely the class of impact this scan accepts ("a spend-triggered transaction-processing halt"). Because it only requires submitting two ordinary spend bundles from any wallet/RPC client (no special privileges, no malicious peer/node needed), this is reachable by a single unprivileged spend-bundle submitter.

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to construct a CLVM spend whose conditions carry the `ELIGIBLE_FOR_DEDUP` flag (used by known aggregation-style puzzles, e.g., CAT ring/offer settlement flows) and to submit it twice wrapped with different fee-paying coins so both fit in the mempool simultaneously without conflicting. This does not require any privileged access, malicious peer, or leaked keys — only crafting/submitting spend bundles through the normal wallet/RPC path.

### Recommendation
Guard the division before constructing the log message, e.g.:
```python
item_cost = cost - cost_saving
fee_per_cost = fee / item_cost if item_cost > 0 else 0.0
log.info("Cumulative cost: %d, fee per cost: %0.4f, item cost: %d", cost_sum, fee_per_cost, item_cost)
```
Additionally, consider treating `item_cost <= 0` as a defensive skip condition (similar to the existing `cost == 0` check in `validate_spend_bundle`) so such items cannot enter block accounting with a non-positive cost.

### Proof of Concept
1. Craft a CLVM puzzle/solution for a coin `C` whose conditions set the dedup-eligibility flag (`ELIGIBLE_FOR_DEDUP`), e.g. an offer/ring-style spend as used in CAT settlement.
2. Build spend bundle `SB1 = {spend(C, solution), spend(feeCoin1, ...)}` with a higher fee rate, and `SB2 = {spend(C, solution) [identical bytes], spend(feeCoin2, ...)}` with a lower fee rate, where `spend(C, solution)` alone constitutes the entire cost of at least one of the mempool items when isolated (or otherwise arrange for the single-coin dedup case as described).
3. Submit both `SB1` and `SB2` to the mempool via the normal wallet/RPC `push_tx` path; `check_removals` (`chia/full_node/mempool_manager.py:293-305`) admits both since the dedup solution is identical.
4. Trigger block bundle creation (`Mempool.create_bundle_from_mempool_items`); when the lower-priority item is processed, `get_deduplication_info` reports `cost_saving == cost` for the fully-deduplicated single-coin item, making `item_cost == 0`, and the `fee / item_cost` expression at `chia/full_node/mempool.py:668` raises `ZeroDivisionError`, aborting block assembly.
