### Title
Cached FROST preprocess seed is reused across `share`/`complete` calls, enabling nonce reuse and private key share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The kernel bug fixed a GDSC hardware-control flag that was frozen at definition time and could not be switched at runtime when the driver began requiring a different mode. The Serai analog is a nonce-generation seed that is frozen at first use and reused across distinct calls: `SigningProtocol::preprocess_internal` stores a `CachedPreprocess` keyed only by `context` (e.g. `(b"DkgConfirmer", attempt)`), and every subsequent `share_internal` call reconstructs a sign machine `from_cache` with the identical 32-byte seed. Because the cache is never deleted or rotated, the same FROST nonces are regenerated for every `share()`/`complete()` invocation under the same context, regardless of the message or signing set actually supplied.

### Finding Description
In `coordinator/src/tributary/signing_protocol.rs`, `preprocess_internal` checks `CachedPreprocesses::get(self.txn, &self.context)`; if unset it generates a random seed via `AlgorithmMachine::preprocess(&mut OsRng)`, XOR-encrypts it, and stores it. It then unconditionally reloads that same seed and calls `AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached))`, which runs `seeded_preprocess` → `ChaCha20Rng::from_seed(*seed.0)` → `Commitments::new`, producing fully deterministic nonces [1](#0-0) [2](#0-1) .

`share_internal` invokes `preprocess_internal` on every call [3](#0-2) , and `DkgConfirmer::complete` calls `share_internal` again after `DkgConfirmer::share` already did [4](#0-3) . The signed message is `set_keys_message(set, removed, key_pair)`, where `key_pair` and the participant `preprocesses` map are supplied per call [5](#0-4) . The FROST docs state reuse of a preprocess "will enable third-party recovery of your private key share" [6](#0-5) .

So if `share()` is invoked with one `(preprocesses, key_pair)` tuple and `complete()` (or a retry of `share`) is invoked with a different `key_pair` or a different set of counterparty preprocesses, this validator signs two different challenge values `c` with the identical nonce `d + b·e·ρ`. Each share has the form `s = nonce + c·λ·secret_share`; subtracting two shares yields `(c1 − c2)·λ·secret_share`, directly recovering the validator's MuSig/FROST secret share over Ristretto — the key protecting the tributary signing identity.

### Impact Explanation
An unprivileged counterparty participant can cause the honest validator to emit two Schnorr signature shares under the same binomial nonce but over different binding-factor/challenge transcripts, by feeding different `serialized_preprocesses` or a different `key_pair` across the `share` and `complete` calls of the same attempt. From the two published 32-byte shares they algebraically recover the validator's private key share, then can forge tributary signatures. This is key-share recovery reachable purely via protocol inputs (preprocess messages and the key pair being confirmed).

### Likelihood Explanation
The cache is deterministic and never invalidated within a context; any divergence between the inputs of two `share_internal` calls under the same `(b"DkgConfirmer", attempt)` triggers reuse. A malicious validator controls the preprocess bytes they submit and the timing/content of confirmation rounds, and failed/retried rounds naturally induce repeat calls. Requires no collusion beyond a single malicious participant.

### Recommendation
Delete (or version) the `CachedPreprocesses` entry after the first `share_internal` consumes it, or mix the signing-set/message commitment into the seed so different inputs cannot reuse identical nonces. Alternatively, refuse to sign twice under one context.

### Proof of Concept
1. Validator runs `DkgConfirmer::share(preprocesses_A, key_pair_1)` → internally `preprocess_internal` loads seed `S`, generates nonces `(d, e)`, returns share `s1 = d + e·ρ1 + c1·λ·x`.
2. Attacker supplies a different `key_pair_2` (or different preprocess set changing ρ/c) and the validator runs `DkgConfirmer::complete(preprocesses_B, key_pair_2, shares)` → `share_internal` reloads the same `S`, emits `s2 = d + e·ρ2 + c2·λ·x` over a different challenge.
3. `x = (s1 − s2 − e·(ρ1 − ρ2)) / (λ·(c1 − c2))`; since `e` is recoverable from the public nonce commitments and ρ values, the private share `x` is recovered.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
