## Finding Validated

The binding claimed broken: **payer_of_record(withdrawal i) == funder_of(payout output 0, withdrawal i)**. Tracing the code confirms this equality is *not* enforced anywhere — attribution is derived solely from OP_RETURN bytes in whichever transaction happens to spend the withdrawal outpoint first, with zero linkage to who actually funded the payout output.

### Title
Payout attribution is derived purely from unauthenticated OP_RETURN data on the first tx spending the withdrawal outpoint, letting anyone forge which operator gets reimbursed - (File: `core/src/database/verifier.rs`, `core/src/verifier.rs`, `core/src/task/payout_checker.rs`)

### Summary
`Database::get_payout_txs_for_withdrawal_utxos` matches a payout to a withdrawal purely by `bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout`, and `Verifier::update_finalized_payouts` blindly parses the OP_RETURN of that first-seen spending transaction to set `payout_payer_operator_xonly_pk`, without any check that the named operator's own wallet/`TxSender` funded output 0. Because the withdrawal UTXO is unlocked with a `SinglePlusAnyoneCanPay` signature (deliberately permissionless completion), anyone possessing that signature can build their own transaction with output 0 exactly matching the registered payout and an OP_RETURN naming an arbitrary operator, fund it from their own wallet, and get it mined first.

### Finding Description
`Database::get_payout_txs_for_withdrawal_utxos` [1](#0-0)  attributes a payout to a withdrawal index solely via a join on `bitcoin_syncer_spent_utxos.txid/vout == withdrawals.withdrawal_utxo_txid/vout` — there is no check tying the spending transaction to any operator identity or to a transaction the protocol itself queued.

`Verifier::update_finalized_payouts` then reads whichever transaction was returned, extracts the first OP_RETURN output, and parses its bytes as an `XOnlyPublicKey`, storing it verbatim as `payout_payer_operator_xonly_pk` [2](#0-1) . There is no verification that the funding inputs of that transaction (beyond input 0, the user's dust UTXO) belong to the named operator.

The payout input is signed by the user with `SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0 [3](#0-2) ; by design this allows *any* party holding that signature to complete the transaction by adding their own funding inputs and an arbitrary OP_RETURN output, as `create_payout_txhandler` shows the OP_RETURN's operator pk is just a plain output the constructor chooses [4](#0-3) .

Once the DB records `payout_payer_operator_xonly_pk = X` for a real operator X, `PayoutCheckerTask::run_once` for operator X unconditionally treats it as its own fronted payout: it calls `get_first_unhandled_payout_by_operator_xonly_pk` filtered by `self.operator.signer.xonly_public_key`, and if found, immediately calls `handle_finalized_payout` to create/send a kickoff and proceed toward reimbursement, with no check that operator X's own `TxSender`/wallet actually broadcasted that payout tx [5](#0-4) .

The one existing cross-check, `Verifier::is_kickoff_malicious`, only verifies that the OP_RETURN's operator pk matches the pk of whoever *sends the kickoff* [6](#0-5) . In this attack, the tricked operator X is the one sending its own kickoff (`kickoff_data.operator_xonly_pk = self.signer.xonly_public_key`), so this check trivially passes — it does not, and cannot, verify who funded the payout's non-input-0 inputs.

Exploit flow: attacker obtains the registered `WithdrawParams` (signature, outpoint, output script/amount) — e.g. from a public mempool broadcast by any operator that hasn't yet confirmed, or a leaked/retried gRPC call. Attacker builds a from-scratch transaction: input 0 = withdrawal UTXO with the known S+AP signature, output 0 = the exact registered script/amount (required for signature validity), additional input(s) from the attacker's own wallet to cover the amount+fees, and an OP_RETURN naming operator X's xonly pk. Attacker broadcasts and fee-bumps to get it mined before any real operator's payout tx. `update_finalized_payouts` records X as payer; `PayoutCheckerTask` for X automatically proceeds through kickoff/Reimburse, crediting X for funds X never paid.

### Impact Explanation
This breaks the custody/attribution invariant that the entity crediting itself as payer for a withdrawal must actually be the entity that funded that payout's output 0. It matches the listed Critical category "an operator reimbursed for a payout it never funded": operator X's automation will spend real kickoff/round resources and ultimately claim the move-to-vault reimbursement (the full bridge amount) for a payout entirely funded by the attacker's own BTC. This is repeatable across every pending withdrawal and every operator xonly pk the attacker chooses to name, and requires no cooperation from any operator, verifier, or aggregator — only knowledge of a signature that becomes public the moment any operator's attempt appears in a public mempool.

### Likelihood Explanation
Preconditions are realistic given normal operation: a withdrawal is registered on Citrea with a public/known outpoint, and any operator's earlier attempt to broadcast the payout tx (even one that is delayed, low-fee, or retried) exposes the S+AP signature in the public Bitcoin mempool, satisfying the "signature known to attacker" precondition without any privileged access. Attacker cost is simply the payout output amount plus fees (their own capital, refundable if they self-name, or lost if griefing/donating to a chosen operator) plus fee-bumping to win the race. No majority hashrate, key compromise, or insider access is required — only standard Bitcoin RBF fee competition.

### Recommendation
Do not derive `payout_payer_operator_xonly_pk` from an unauthenticated OP_RETURN in an arbitrary transaction. Instead, require that the payout transaction match a transaction actually constructed/queued by the named operator's own `TxSender` (e.g., track the exact txid the operator queued when calling `withdraw`, and only accept that tracked txid — or any RBF replacement signed with the operator's committed template — as the attributable payout). Alternatively, bind the OP_RETURN operator identity to a signature/commitment that only the true funder could have produced, rather than plaintext bytes any funder can append.

    pub async fn get_payout_txs_for_withdrawal_utxos(

             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

/// Creates a [`TxHandler`] for the `payout_tx`.
///
/// This transaction is sent by the operator to front a peg-out, after which operator will send a kickoff transaction to get reimbursed.
///
/// # Inputs
/// 1. UTXO: User's withdrawal input (committed in Citrea side, with the signature given to operators off-chain)
///
/// # Outputs
/// 1. User payout output
/// 2. OP_RETURN output (with operators x-only pubkey that fronts the peg-out)
///
/// # Arguments
/// * `input_utxo` - The input UTXO for the payout, committed in Citrea side, with the signature given to operators off-chain.
/// * `output_txout` - The output TxOut for the user payout.
/// * `operator_xonly_pk` - The operator's x-only public key that fronts the peg-out.
/// * `user_sig` - The user's signature for the payout, given to operators off-chain.
/// * `network` - The Bitcoin network.
///
/// # Returns
/// A [`TxHandler`] for the payout transaction, or a [`BridgeError`] if construction fails.
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

#[async_trait]
impl<C> Task for PayoutCheckerTask<C>
where
    C: CitreaClientT,
{
    type Output = bool;
    const VARIANT: TaskVariant = TaskVariant::PayoutChecker;

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
