## Title
`aptos move verify-package` never compares actual on-chain bytecode, so it can report success for a package whose deployed module bytes do not match the verified source — ([File: aptos-move/cli/src/commands.rs], [File: aptos-move/cli/src/stored_package.rs])

### Summary
The Chainlink report's root pattern is: a verification/consistency routine implicitly trusts a value (`roundId`) that is not actually cross-checked against the real state it is supposed to represent, causing the check to silently diverge from reality. The Aptos-native analog is in the code-publish verification tooling: `VerifyPackage::execute` in `aptos-move/cli/src/commands.rs` and `CachedPackageMetadata::verify` in `aptos-move/cli/src/stored_package.rs` claim to verify "that the on-chain copy matches" a local build, but they only compare `PackageMetadata` fields (name, deps, module list, manifest, upgrade policy, extension, `source_digest`) — never the actual compiled module bytecode stored on-chain. `PackageMetadata` (including `source`, `source_map`, and `source_digest`) is attacker-supplied data submitted alongside — but never linked to — the real `code: vector<vector<u8>>` bytes in `code::publish_package`.

### Finding Description
`code::publish_package` in `aptos-move/framework/aptos-framework/sources/code.move:159-231` takes two independent inputs: `pack: PackageMetadata` (name, modules' names/source/source_map, `source_digest`, manifest, deps, upgrade policy) and `code: vector<vector<u8>>` (the actual module bytecode). The only linkage enforced on-chain is that the module *names* in `pack.modules` match the module names extracted from `code` (via `get_module_names` and the native publish path); nothing checks that `pack.modules[i].source`/`source_map`/`source_digest` were actually derived from `code[i]`. A publisher can submit legitimate-looking source metadata (matching a well-known, audited package) while embedding arbitrary bytecode, as long as the bytecode passes the bytecode verifier/compatibility check and has matching module names.

Downstream, the CLI's verification tool is expected to catch this. `VerifyPackage::execute` (`aptos-move/cli/src/commands.rs:2098-2140`) builds the package **locally** to get `compiled_metadata`, downloads the on-chain package via `CachedPackageRegistry::create(client, self.account, false)` — passing `false` for `with_bytecode` — and calls `package.verify(&compiled_metadata)`. `CachedPackageMetadata::verify` (`aptos-move/cli/src/stored_package.rs:193-241`) only compares `name`, `deps`, `modules` (which is just `ModuleMetadata { name, source, source_map, extension }`), `manifest`, `upgrade_policy`, `extension`, and `source_digest`. It never fetches or diffs the actual on-chain module bytecode. `CachedPackageRegistry::get_bytecode` exists specifically for this purpose but is only populated when `with_bytecode = true`, and `VerifyPackage` never sets it (`DownloadPackage` does, via `--bytecode`, but that's a separate, non-verifying command).

Because `source`/`source_map`/`source_digest` inside `PackageMetadata` are themselves publisher-supplied and are not derived on-chain from `code`, an attacker who controls what's published can trivially make the on-chain metadata's `source`/`source_digest` match a benign, expected source tree while the actual bytecode differs completely (e.g., contains additional malicious logic, backdoors, or drains). `aptos move verify-package` would then report "Successfully verified source of package" even though the deployed bytecode is not what was verified.

### Impact Explanation
This breaks the code-safety invariant that "verified bytes, package metadata, and committed module bytes agree" (explicitly called out in the Publish Pivots). Users, auditors, or tooling relying on `aptos move verify-package` (and the analogous documented guarantee in `third_party/move/documentation/book/src/cli-deploy.md:70-83`: "Build the package locally and verify that the on-chain copy matches") receive a false assurance that the deployed contract matches audited source, when in fact only cosmetic metadata was checked. This can mask malicious or backdoored bytecode being published/upgraded under a legitimate-looking package name, enabling supply-chain-style attacks against integrators who trust `verify-package` output before interacting with or building on top of a contract. This is a code-safety/verification-integrity issue with direct mainnet relevance since `verify-package` is a documented, user-facing trust mechanism.

### Likelihood Explanation
High likelihood of being reachable: any account (including third parties, since `code::publish_package` is permissionless for a signer's own address, and `object_code_deployment::publish` is permissionless for objects) can publish a package with metadata whose `source`/`source_digest` fields are crafted independently of the actual `code` bytes — no special privilege is required, only that `code` passes the bytecode verifier and matches the declared module names. No on-chain code exists that cross-validates metadata source fields against bytecode; this is a tooling/verification gap, not a network-condition-dependent race.

### Recommendation
- `aptos move verify-package` should default to (or require) fetching on-chain bytecode (`with_bytecode = true`) and byte-for-byte compare each downloaded module against the bytecode produced from the local `BuiltPackage` build, not merely compare `PackageMetadata` fields.
- Treat `source`/`source_map`/`source_digest` in `PackageMetadata` purely as documentation, and never present a "verified" success result unless the actual module bytecode has been compared.
- Consider adding an on-chain or CLI-computed digest that binds `PackageMetadata.source_digest` cryptographically to the actual published `code` bytes at publish time, so metadata cannot be presented independently of the code it claims to describe.

### Proof of Concept
Conceptual PoC (tooling-level, no chain state corruption required):
1. Compile a legitimate, benign package `Good` from source `S_good`; note its `PackageMetadata` (`source`, `source_digest`, `manifest`) computed by `BuiltPackage::extract_metadata()`.
2. Compile a malicious package `Evil` from different source `S_evil` that has the same module names/signatures (satisfying compatibility/dependency checks) but different logic (e.g., a backdoored `transfer` function). Extract `Evil`'s bytecode (`code`).
3. Submit a `code::publish_package_txn` (or `object_code_deployment::publish`) transaction using `Good`'s `PackageMetadata` (serialized) together with `Evil`'s `code` bytes. Since `code::publish_package` never cross-checks `pack.modules[i].source`/`source_digest` against `code[i]`, and the module names match, the transaction succeeds.
4. Run `aptos move verify-package --account <addr>` against local source `S_good`. Because `VerifyPackage`/`CachedPackageMetadata::verify` only compares `PackageMetadata` fields (all of which match, since the same `PackageMetadata` — describing `S_good` — was published), the command reports `"Successfully verified source of package"`, even though the deployed bytecode is actually `Evil`'s.

Note: full end-to-end execution of this PoC (building two packages and running the actual CLI binary) was not performed in this analysis; the conclusion is based on static tracing of `verify()`'s logic in `aptos-move/cli/src/stored_package.rs:193-241` and confirming that `CachedPackageRegistry::create` is invoked with `with_bytecode = false` in `VerifyPackage::execute` (`aptos-move/cli/src/commands.rs:2121`), and that no on-chain code path links `PackageMetadata.source*` fields to the `code` bytes in `code::publish_package`. impl CliCommand<&'static str> for VerifyPackage {
    fn command_name(&self) -> &'static str {
        "VerifyPackage"
    }

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    /// Publishes a package at the given signer's address. The caller must provide package metadata describing the
    /// package.
    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

## `aptos move verify-package`

Build the package locally and verify that the on-chain copy matches.

```shellscript filename="Terminal"
aptos move verify-package --account 0xABC...123
```

| Flag | Meaning |
|---|---|
| `--account <ADDR>` | Address of the on-chain package to verify against. |
| `--included-artifacts <none\|sparse\|all>` | Match what was used at publish time. |

A package published with `upgrade_policy = "arbitrary"` cannot be verified — its content can change at any time, so the verifier refuses to depend on it.
