## Title
Unanchored `commitMentionUrl` regex allows link-text spoofing of commit-mention links via embedded GitHub URL substrings — ([File: app/src/lib/markdown-filters/commit-mention-link-filter.ts])

### Summary
The `commitMentionUrl` getter builds a regex from `escapeRegExp(gitHubURL)` plus the owner/name, action and sha patterns without a leading `^` anchor or origin check, so it matches any string that merely *contains* a valid GitHub commit/pull/compare URL as a substring anywhere (query string, fragment, etc.), not only strings whose true origin is `https://github.com`.

### Finding Description
`commitMentionUrl` is used in `createFilterTreeWalker`'s `acceptNode` to decide whether an anchor's `href` "looks like" a GitHub commit-mention URL: [1](#0-0) 

Because the pattern has no `^` anchor and is not validated via `URL.origin`, an `href` such as
`https://evil.example/attacker/repo/commit/1234567#https://github.com/owner/repo/commit/abcdef1`
satisfies `this.commitMentionUrl.test(el.href)`, since the literal substring `https://github.com/owner/repo/commit/abcdef1` (placed harmlessly in the URL fragment) matches the pattern, even though the anchor's real destination is `evil.example`.

The `acceptNode` gate also requires `el.href === el.innerText` [2](#0-1) 
which is trivially satisfiable because this filter runs after the markdown auto-linker has already turned a raw pasted/typed URL into `<a href="X">X</a>` — the attacker fully controls both `href` and `innerText` as the same string.

In `filter()`, the label is derived not from the embedded GitHub substring but from parsing the attacker's own URL structure: [3](#0-2) 
`new URL(text)` resolves `evil.example` as host and `/attacker/repo/commit/1234567` as the path, so `owner`/`name`/`ref` become `attacker`/`repo`/`1234567` (or, if the attacker sets the path to match the current repository's actual `owner/name`, the bare `<tt>sha</tt>` label with no `owner/repo@` prefix is produced — visually identical to a legitimate same-repo commit reference). Because the trailing fragment (`#...`) is never consulted (only `url.search` is appended), none of the telltale GitHub substring appears in the rendered label.

The net effect: Desktop replaces a raw pasted URL with a clean, short, trusted-looking commit-reference label (`owner/repo@1234567` or `1234567`) while the underlying `href` attribute of the anchor still points at the attacker's server. This corrupts the link-trust invariant that a rendered "commit mention" label implies its `href` resolves to the expected GitHub host/repo.

### Impact Explanation
This is a link/content-spoofing issue: a user viewing GitHub-sourced markdown (PR/issue/commit body, comments, release notes, etc.) rendered inside Desktop sees what looks like a normal, trustworthy commit-sha reference, but clicking it navigates to an attacker-controlled destination instead of GitHub. Given Desktop typically opens such links via the OS default browser, this can be used to funnel users to credential-phishing pages or drive-by content while presenting a highly convincing "this is a GitHub commit link" UI cue. It does not by itself achieve code execution or sandbox escape, but it does defeat the specific link-trust guarantee this filter is meant to provide.

### Likelihood Explanation
Exploitation requires only that an attacker control markdown text visible to the victim in Desktop (a PR description, issue/PR comment, commit description, etc.) — squarely within the "attacker controls a GitHub API object/repository content" threat model in scope. No special privileges, local access, or unusual user action beyond a normal click on a rendered link are needed. The crafted URL is a plain string that any GFM auto-linker will treat as a normal link.

### Recommendation
- Validate that `el.href`'s parsed `origin`/`host` equals `getHTMLURL(this.repository.endpoint)`'s origin (e.g., `new URL(el.href).origin === new URL(gitHubURL).origin`) rather than doing a raw, unanchored substring regex test.
- Anchor the `commitMentionUrl` regex with `^` (and ideally `$`/structured parsing) so it must match from the start of the string, not merely appear anywhere within it.
- Apply the same origin-check fix pattern used (or that should be used) in sibling filters like `IssueLinkFilter` for consistency.

### Proof of Concept
1. In a GitHub PR/issue/commit description (attacker-controlled content rendered by Desktop's markdown pipeline), paste the raw URL:
   `https://evil.example/attacker/repo/commit/1234567#https://github.com/owner/repo/commit/abcdef1234567`
2. GFM auto-linking turns this into `<a href="...">...</a>` with `href === innerText`.
3. `CommitMentionLinkFilter.createFilterTreeWalker`'s `acceptNode` calls `this.commitMentionUrl.test(el.href)`; because the regex is unanchored, the trailing fragment substring `https://github.com/owner/repo/commit/abcdef1234567` satisfies it, so the node is `FILTER_ACCEPT`ed.
4. `filter()` parses `new URL(text)` (host = `evil.example`, pathname = `/attacker/repo/commit/1234567`), extracts `owner=attacker`, `name=repo`, `ref=1234567`, and replaces the text with `attacker/repo@<tt>1234567</tt>` — a clean commit-mention-looking label.
5. The rendered anchor now shows the trusted-looking label `attacker/repo@1234567` (or, if `attacker/repo` is set to the real repository's `owner/name`, just `1234567`) but its `href` still points to `https://evil.example/...`, confirmed by inspecting the DOM/hovering the link. [4](#0-3) [3](#0-2)

  private get commitMentionUrl(): RegExp {
    const gitHubURL = getHTMLURL(this.repository.endpoint)
    return new RegExp(
      escapeRegExp(gitHubURL) +
        '/' +
        this.nameWithOwner.source +
        '/' +
        /(commit|pull|compare)/.source +
        '/' +
        /(\d+\/commits\/)?/.source +
        /([0-9a-f]{7,40})/.source +
        /\b/.source
    )
  }

  /** The parent github repository of which the content the filter is being
   * applied to belongs  */
  private readonly repository: GitHubRepository

  public constructor(repository: GitHubRepository) {
    this.repository = repository
  }

  /**
   * Commit mention link filter iterates on all anchor elements that are not
   * inside a pre, code, or anchor tag and resemble a commit mention link and
   * their href matches their inner text.
   *
   * Looking for something like:
   * <a href="https://github.com/desktop/desktop/commit/6fd7945">https://github.com/desktop/desktop/commit/6fd7945</a>
   * Where the href could be like:
   *  - Plain Single Commit: https://github.com/desktop/desktop/commit/6fd7945
   *  - Compare a range of Commits: https://github.com/desktop/desktop/compare/6fd7945...6fd7945
   *  - Pull Request Commit: https://github.com/desktop/desktop/pull/14239/commits/6fd7945
   */
  public createFilterTreeWalker(doc: Document): TreeWalker {
    return doc.createTreeWalker(doc.body, NodeFilter.SHOW_ELEMENT, {
      acceptNode: (el: Element) => {
        return (el.parentNode !== null &&
          ['CODE', 'PRE', 'A'].includes(el.parentNode.nodeName)) ||
          !isElement(el, 'a') ||
          el.href !== el.innerText ||
          !this.commitMentionUrl.test(el.href)
          ? NodeFilter.FILTER_SKIP
          : NodeFilter.FILTER_ACCEPT
      },
    })
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const newNode = node.cloneNode(true)
    const { textContent: text } = newNode
    if (!isElement(newNode, 'a') || text === null) {
      return null
    }

    const url = new URL(text)
    const [, owner, name] = url.pathname.split('/', 3)
    if (owner === undefined || name === undefined) {
      return null
    }
    const slashes = 3
    const path = url.pathname.substring(owner.length + name.length + slashes)

    let ref, filepathToAppend

    const commitComparePathMatch =
      this.getRefFromCommitPath(path) ?? this.getRefFromComparePath(path)
    if (commitComparePathMatch !== null) {
      ;({ ref, filepathToAppend } = commitComparePathMatch)

      filepathToAppend =
        filepathToAppend !== undefined
          ? filepathToAppend + url.search
          : url.search
    } else {
      ref = this.getRefFromPullPath(path)
    }

    if (ref === null || ref === undefined) {
      return null
    }

    newNode.innerHTML = this.getCommitMentionRef(
      owner,
      name,
      ref,
      filepathToAppend
    )
    return [newNode]
  }
