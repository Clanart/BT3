### Title
Empty `SchnorrAggregate` trivially verifies, bypassing signer authentication - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate signature containing zero nonces and a zero `s` scalar when the caller supplies an empty `keys_and_challenges` slice. Analogous to the CVE-2021-32800 bug class (authentication succeeds without the required second factor ever being checked), the multiexp "proof of signature" reduces to the identity point unconditionally, so a caller who treats `verify(...) == true` as proof that *someone* signed is authenticating an empty signer set — no private key, no signer participation, nothing.

### Finding Description
In `SchnorrAggregate::verify` (crypto/schnorr/src/aggregate.rs:127-146):

```rust
if self.Rs.len() != keys_and_challenges.len() {
  return false;
}
...
for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
  let z = weight(&mut digest);
  pairs.push((z, self.Rs[i]));
  pairs.push((z * challenge, *key));
}
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity().into()
```

When `keys_and_challenges` is empty and `Rs` is empty, the length check passes (`0 == 0`), the loop pushes nothing, and `pairs` contains only `(-s, G)`. With `s == 0` the product is `-0 * G = identity`, so `verify` returns `true`.

The encoding is fully attacker-controlled: `SchnorrAggregate::read` (aggregate.rs:77-88) accepts a 4-byte little-endian length of `0` followed by `s` — and `C::F::ZERO` is a canonical scalar encoding accepted by `read_F`. So the 36-byte payload `00 00 00 00 || 00..00` parses into `Rs = [], s = 0` and verifies.

The downstream caller pattern exists in `Validators::verify_aggregate` (coordinator/tributary/src/tendermint/mod.rs:201-229), which maps `signers` to `keys_and_challenges` and passes them straight to `aggregate.verify` without enforcing a non-empty signer set itself.

### Impact Explanation
Any protocol that interprets a successful `SchnorrAggregate::verify` as "this message was authorized/signed" can be bypassed by an unauthenticated party submitting the trivially-valid empty aggregate whenever the signer set it resolves is empty (e.g., a lookup that yields no eligible signers, or a code path that forwards an empty validator list). This is the same shape as the 2FA bypass in the reference CVE: the verification routine reports success while zero authenticating factors (signatures) were actually checked. Forgery requires no key material, no nonce knowledge, and no valid signature shares.

### Likelihood Explanation
Exploitation requires a reachable call path where an empty signer set is plausible. The crate-internal API permits it unconditionally — `verify` never asserts `keys_and_challenges` is non-empty, and neither does `read`. The concrete production caller (`verify_aggregate` in the tendermint signature scheme) derives `signers` from block vote data; if an empty validator/signature list can reach that path, the forged aggregate is accepted. This is conditional on caller behavior, so likelihood is moderate rather than certain; it is not a purely theoretical edge since no defensive check exists anywhere in the stack.

### Recommendation
- In `SchnorrAggregate::verify` (crypto/schnorr/src/aggregate.rs:127), return `false` when `keys_and_challenges.is_empty()` (mirroring `SchnorrAggregator::complete`, which already returns `None` for an empty aggregation at aggregate.rs:175-178 — the producer side refuses to create the object the consumer side accepts).
- Optionally also reject `s == 0` / identity `R` components at `read` time as defense-in-depth.

The only non-trivial term in the multiexp is `(-0) * G = identity`, so `multiexp_vartime(...).is_identity()` holds and the forgery is accepted.

**Caveat:** I did not fully verify a reachable production path that forwards an empty signer set into `verify` (the tendermint caller derives the set from consensus vote data outside the in-scope crates), so the practical severity depends on whether such a path exists; the library-level forgery itself is unconditional.
