## Finding [1](#0-0) 

### Title
Disabling then re-enabling `StateMachinesCostPerBlock` lets a single relayer collect a treasury reward for the entire disabled span - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives` computes relayer rewards as `(latest_height - baseline) * cost_per_block`, where `baseline` is the `LastRewardedHeight` watermark. The watermark is only advanced inside the `if let Some(block_cost) = StateMachinesCostPerBlock::get(...)` branch of `process_message`. When incentives are disabled for a state machine (`remove_incentives`, or simply never configured) the chain keeps advancing but the watermark is frozen. Re-enabling incentives with `update_cost_per_block` then lets the very next relayer to submit a consensus update collect a reward for the *entire* disabled span, multiplied by the newly set (potentially much higher) rate — exactly the "wrong call order results in wrong reward distribution" class from the Masterchef `setTopPoolIdsWithWeights` report, where a new rate is applied retroactively across a stale, unsettled interval.

### Finding Description
`process_message` and `calculate_reward` in [2](#0-1)  implement the reward formula:

```
baseline = LastRewardedHeight::get(state_machine_id).unwrap_or(previous_height)
blocks   = latest_height - baseline
reward   = blocks * cost_per_block
```

`LastRewardedHeight` is only mutated at the end of `process_message`, and only when `StateMachinesCostPerBlock::get(state_machine_id)` returns `Some(_)`: [3](#0-2) 

If governance calls `remove_incentives` (or the state machine simply never had a cost configured), `StateMachinesCostPerBlock::get` returns `None`, so `process_message` returns early without touching `LastRewardedHeight`. The chain's `latest_commitment_height` for that state machine keeps advancing via ordinary consensus updates during this period (this progression is independent of the incentives pallet, driven by `pallet-ismp`/`IsmpHost`). The watermark stays frozen at whatever height it was before disabling.

When governance later calls `update_cost_per_block` with a new (possibly much larger) rate, the very next relayer to deliver a consensus message triggers `calculate_reward` with:
- `latest_height` = the current, far-advanced height
- `baseline` = the old, stale `LastRewardedHeight`

This yields `blocks = latest_height - stale_baseline`, spanning the *entire disabled/unpaid period*, multiplied by the newly configured `cost_per_block`. The full amount is transferred from the treasury to whichever single relayer happens to submit that one message: [4](#0-3) 

No re-baselining of the watermark happens when `update_cost_per_block`/`remove_incentives` are called — there is no "settle before changing rate" step, mirroring the missing `updateAll` call in the original Masterchef report.

### Impact Explanation
A single, unprivileged relayer can capture a treasury payout sized to the entire span of blocks that accrued while incentives were off (or before they were ever turned on for a distant `previous_height` window), at whatever new `cost_per_block` governance sets. This is direct loss of treasury funds to one party for work they did not perform across most of the rewarded span (only the very last consensus update was actually delivered by them). This matches the bounty's "stealing or loss of funds" / "logic attacks" category — the corrupted value is `LastRewardedHeight` (or its `previous_height` fallback), which is stale relative to `latest_height` at the moment the rate is (re)applied, and no guard rejects an unexpectedly large `blocks` span or requires re-baselining before/after a rate change.

### Likelihood Explanation
This does not require a malicious relayer, prover, or admin — it is triggered by the pallet's normal operational lifecycle: pause incentives (`remove_incentives`) for maintenance/cost reasons, let the chain progress, then resume (`update_cost_per_block`). The first relayer to deliver a consensus update afterward is rewarded for the whole gap. This is a realistic governance workflow (e.g., temporarily disabling incentives for a state machine during an incident, then re-enabling), and the existing test suite even documents watermark semantics for rollback scenarios but does not cover the disable/re-enable gap, showing the pallet authors did not model this path.

### Recommendation
When `remove_incentives` is called, snapshot the current `latest_commitment_height` into `LastRewardedHeight` so the "unpaid" clock stops advancing during the disabled period. Symmetrically, when `update_cost_per_block` is called to (re-)enable a state machine, initialize/refresh `LastRewardedHeight` to the current `latest_commitment_height` if it does not already reflect the current chain state, so the new rate only applies going forward — analogous to the recommended fix for `setTopPoolIdsWithWeights`: settle/checkpoint state before changing the rate, not after.

### Proof of Concept
1. Governance calls `update_cost_per_block(sm, cost=0 or leaves it unset)` / or never configures a cost for state machine `SM` — incentives are effectively off (`StateMachinesCostPerBlock::get(SM) == None`).
2. Over many blocks, honest relayers deliver consensus updates for `SM`, advancing `latest_commitment_height(SM)` from `H0` to `H_big` (e.g., +100,000 blocks). Because `StateMachinesCostPerBlock::get` returns `None`, `process_message` returns early each time and `LastRewardedHeight[SM]` remains at (or near) `H0`.
3. Governance calls `update_cost_per_block(SM, cost_per_block = C)` to (re)enable incentives, per [5](#0-4) .
4. Any single relayer submits the next consensus message for `SM`. `on_executed` → `process_message` → `calculate_reward` computes `blocks = H_big - H0 ≈ 100,000`, `reward = 100,000 * C`, paid entirely from `TreasuryAccount` to that one relayer, per [6](#0-5) .
5. `LastRewardedHeight[SM]` jumps to `H_big`, hiding the anomaly for future calls, but the treasury has already paid out a windfall for a span of updates the paid relayer did not deliver.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
