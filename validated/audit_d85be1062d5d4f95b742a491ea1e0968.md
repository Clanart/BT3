### Title
Anyone can force misclassification of scanned outputs by sending to Serai's internal offset addresses - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The Cooler bug class is "a state-changing function lacks an authorization check, so any third party can alter terms reserved for a privileged role." The Serai analog is `Scanner::scan_transaction`/`get_outputs`: the scanner attributes a received output to an internal role (`Branch`, `Change`, `Forwarded`) purely by matching `script_pubkey`, and the offset addresses are publicly computable by anyone. Any external sender can therefore send a Bitcoin transaction to an internal offset address and have it reported by the processor as an `OutputType::Branch`/`OutputType::Change`/`OutputType::Forwarded` output — a classification only the multisig's own transactions are supposed to produce — with no authorization possible.

### Finding Description
`Scanner` maps scripts to offsets in `self.scripts`, and `scan_transaction` emits a `ReceivedOutput` whenever an output's `script_pubkey` matches — with no check on who created the transaction [1](#0-0) . `register_offset` inserts offset-derived scripts into that same map [2](#0-1) . The processor registers deterministic offsets via `Secp256k1::hash_to_F(KEY_DST, b"branch"|b"change"|b"forward")` with the fixed public DST `b"Serai Bitcoin Output Offset"`, then maps scanned offsets back to `OutputType` via `kinds[offset_repr]` [3](#0-2) . `get_outputs` then tags each scanned output with that `kind`, and only `OutputType::External` outputs get `presumed_origin`/InInstruction `data` populated [4](#0-3) .

Because `KEY_DST` and the offset labels are fixed public constants, and `forward_address` even exposes the derived `Address` publicly [5](#0-4) , any unprivileged party can compute the Branch/Change/Forwarded P2TR addresses and pay them directly. `scan_transaction` cannot distinguish such a payment from an output the multisig created itself. These misclassified outputs pass the `>= N::DUST` filter in the scanner loop and are emitted as received outputs [6](#0-5) .

### Impact Explanation
An external attacker can inject outputs that the processor reports as internally-typed (`Branch`, `Change`, `Forwarded`) rather than `External`. These outputs are spendable (the offset scalar is known), so they enter the scheduler's output set and accounting under a false classification — e.g., an attacker-funded output treated as the multisig's own change/forwarded/branch output. This corrupts the processor's view of which outputs it created versus which are deposits, and strips the attacker-controlled `data`/`presumed_origin` fields (only populated for `External`), giving the attacker a way to slip arbitrary-value outputs into internal flows that are never supposed to be externally fundable.

### Likelihood Explanation
Trivially reachable by any unprivileged party: the offset scalars derive from public constants (`Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", …)`) and the group key is public, so computing the internal P2TR scriptPubKeys and broadcasting a transaction paying them costs only the satoshis sent and fees. No threshold cooperation, no key material, and no protocol participation is required — exactly mirroring "anybody can call `roll()`".

### Recommendation
Distinguish externally-received outputs from internally-created ones rather than classifying solely by `script_pubkey`. Options: track internally-created outpoints (the multisig knows the txids/vouts of its own sends) and only classify scanned outputs as `Branch`/`Change`/`Forwarded` if their outpoint matches a known internally-created transaction; otherwise treat unrecognized payments to internal offsets as `External` (or ignore/flag them). At minimum, `get_outputs` should not assume every script match is an internal output.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),

    OutputType::Change,

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
