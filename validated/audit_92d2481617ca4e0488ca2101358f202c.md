## Finding

### Title
Unbacked native coin minting via malicious ERC20 contract in `ConvertERC20` self-verifying balance checks - (File: `x/erc20/keeper/msg_server.go`)

### Summary
This is the same trust-pattern bug as the Maverick `exactInput` issue: a "router"-equivalent (the `x/erc20` keeper) accepts an attacker-supplied, unverified contract address (an ERC20 contract registered permissionlessly via `MsgRegisterERC20`) and then calls back into that same untrusted contract to *validate its own escrow invariant*, rather than relying on an independent source of truth. Because the validation oracle and the value transfer are both controlled by the attacker's contract, the invariant check can never fail, allowing the mint step to be reached unconditionally.

### Finding Description
`RegisterERC20` in [1](#0-0)  permits **any address** to register **any** externally-deployed ERC20 contract as a token pair when `PermissionlessRegistration` is enabled (the default/typical configuration exercised throughout the test suite, e.g. [2](#0-1) ). No bytecode/behavior verification of the contract is performed — analogous to the Router never checking that the "pool" address was created by the trusted Factory.

`convertERC20IntoCoinsForNativeToken` in [3](#0-2)  then uses that same untrusted contract as the sole oracle for both the value-transfer call and the invariant check that gates minting: [4](#0-3) 

Specifically:
1. `balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)` — calls `balanceOf()` on the attacker's contract.
2. `k.evmKeeper.CallEVMWithData(...)` invokes `transfer(ModuleAddress, amount)` on the same attacker's contract.
3. `balanceTokenAfter := k.BalanceOf(...)` — again queries the attacker's contract.
4. The keeper trusts `balanceTokenAfter == balanceToken + amount` as proof that real value was escrowed, then unconditionally does `k.bankKeeper.MintCoins(ctx, types.ModuleName, coins)` followed by `SendCoinsFromModuleToAccount`.

Because `balanceOf` and `transfer` are both defined by attacker-controlled bytecode, the contract can trivially satisfy this self-referential check (e.g., `balanceOf` simply returns a stored counter that `transfer` increments by the exact requested `amount`, without any real value ever changing hands, or without any cap). There is no independent invariant (e.g., using pre-registration `totalSupply`, or cross-checking with a trusted oracle) — the same untrusted party is both the payer and the auditor of the payment.

This mirrors the Maverick pattern precisely: an unverified, attacker-supplied contract address is invoked mid-transaction by a trusted module, and that same untrusted contract is relied upon for a security-critical decision (in Maverick's case, `pool.swap`'s return values feeding subsequent trust decisions; here, `balanceOf`'s return value feeding the mint decision).

### Impact Explanation
A successful call to `MsgConvertERC20` mints native Cosmos bank coins of denom `erc20:<attacker_contract_address>` (per `CreateDenom` in [5](#0-4) ) with **no real backing**, in unlimited/arbitrary amounts of the caller's choosing. These coins are fully spendable native bank coins: transferable via `bank.Send`, usable through the `erc20` precompile, and transferable out via ICS-20 (`x/ibc/transfer/keeper/msg_server.go`), where the receiving chain has no way to know the tokens are unbacked. This corrupts the intended 1:1 accounting invariant between escrowed ERC20 balances and minted native coins that the `x/erc20` "asset-representation path" is explicitly designed to preserve, and produces coins that behave identically to genuinely-backed ERC20-derived tokens in every downstream flow (precompiles, IBC, EVM).

### Likelihood Explanation
Fully triggerable by an unprivileged user in the ordinary transaction flow: deploy a trivial fake ERC20 contract, call `MsgRegisterERC20` (permissionless by default), then call `MsgConvertERC20` for any desired amount. No relayer, validator, or governance action is required.

### Recommendation
Do not use the same untrusted ERC20 contract as the sole source of truth for the amount actually escrowed. Options:
- Require the token pair contract to be either module-deployed (`OWNER_MODULE`) using the audited `ERC20MinterBurnerDecimalsContract` bytecode, or otherwise verify bytecode/behavior for `OWNER_EXTERNAL` pairs before allowing conversion.
- Cross-check the balance delta against an independently verified `totalSupply()` invariant recorded at registration time and monitor for supply inflation outside of `Convert*` flows.
- Rate-limit / cap per-denom minting so a compromised or malicious external ERC20 cannot mint unbounded native coin supply, and clearly separate "attacker-created representation" denoms from ones the chain has verified.

### Proof of Concept
1. Deploy a minimal `EvilERC20` contract whose `balanceOf(address)` returns `_counter[address]` and whose `transfer(to, amount)` does `_counter[to] += amount; return true;` (no real supply is ever moved/limited).
2. Call `MsgRegisterERC20{Erc20Addresses: [EvilERC20]}` (permissionless registration).
3. Call `MsgConvertERC20{ContractAddress: EvilERC20, Amount: <huge_amount>, Sender: attacker, Receiver: attacker}`.
4. `convertERC20IntoCoinsForNativeToken` reads `balanceToken` (0), calls `transfer(ModuleAddress, huge_amount)` (increments the counter), reads `balanceTokenAfter` (== huge_amount), the invariant check passes trivially, and `huge_amount` of `erc20:<EvilERC20>` native coin is minted and sent to the attacker — see [6](#0-5) .

func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}
