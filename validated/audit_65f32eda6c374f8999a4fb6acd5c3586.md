Based on my investigation, I found a concrete, locally provable analog in `pallet-consensus-incentives`.

### Title
Consensus-incentive reward misattribution lets any relayer batch messages to steal other relayers' `RelayerRewarded` payouts — ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`FeeHandler::on_executed` derives the reward recipient from **only the first message in the batch** (`messages.get(0)`), but then pays that single relayer for **every** `StateMachineUpdated` event produced by the whole batch — regardless of which of the batch's `ConsensusMessage`s actually advanced which state machine.

### Finding Description
`pallet_ismp::Pallet::<T>::execute` accepts an arbitrary `Vec<Message>` via the permissionless unsigned extrinsic `handle_unsigned`, executes them all, collects the union of resulting events, and hands the whole batch plus events to `T::FeeHandler::on_executed` in one call: [1](#0-0) 

`pallet-consensus-incentives`'s `on_executed` implementation recovers a relayer identity from **only `messages.get(0)`**: [2](#0-1) 

It then iterates over **all** `StateMachineUpdated` events in the batch (deliberately collapsed to the highest height per `state_machine_id` to avoid double-paying the *same* chain twice), and pays `Self::process_message` — i.e., transfers treasury funds and mints reputation — for every distinct state machine advance found, using the single relayer recovered from message index 0: [3](#0-2) 

Since `handle_unsigned` is permissionless and takes an arbitrary `Vec<Message>` (any caller can concatenate *previously broadcast, still-valid* `ConsensusMessage`s for multiple state machines, each carrying a legitimate signature from a different honest relayer, alongside a message the attacker controls at index 0), the attacker can construct a batch where:
- index 0 is a message signed by the attacker (or trivially crafted to decode to the attacker's key),
- the remaining entries are valid consensus proofs for other state machines that other relayers already produced/broadcast.

`Pallet::execute` will happily process the whole batch (each message is independently valid and not yet applied), advancing multiple `StateMachineId`s, and `on_executed` will pay the **entire** reward for **all** those advances to the attacker's account, not to the relayers whose proofs actually produced the advances.

### Impact Explanation
This directly violates the "relayer rewards ... must move exactly once and only to the rightful beneficiary" invariant. Any unprivileged party who can observe pending/broadcastable consensus proofs (which are public, since they must be relayed) can rebatch them behind their own message and redirect the treasury payout (`RelayerRewarded`) and reputation mint (`ReputationMintFailed`/`ReputationAsset::mint_into`) for other chains' proof deliveries to themselves — draining treasury funds meant for honest relayers and inflating the attacker's reputation asset (which feeds into collator selection per `pallet-collator-manager`, per the docs on Collator selection ranking by reputation).

### Likelihood Explanation
High for an unprivileged attacker: `handle_unsigned` is explicitly permissionless/unsigned by design (docs: "permits anyone to execute ISMP messages for free, provided they have valid proofs"), and consensus proofs are inherently public once broadcast to be relayed. No malicious peer, prover, or leaked key is required — only observing and rebroadcasting already-valid public proofs in a crafted batch order, which is exactly the kind of "public-entrypoint, unprivileged attacker" path this class of Hyperbridge bug requires.

### Recommendation
Attribute and pay rewards per-message rather than per-batch: recover the relayer's key from the specific `ConsensusMessage` whose `consensus_proof`/`consensus_state_id` produced each `StateMachineUpdated` event (matching event to originating message), instead of using `messages.get(0)` for the entire batch's set of advances.

### Proof of Concept
1. Relayer A submits (or has already broadcast, prior to inclusion) a valid `ConsensusMessage` `M_A` for `state_machine_id = X`, correctly signed by A.
2. Relayer B submits a valid `ConsensusMessage` `M_B` for `state_machine_id = Y`, correctly signed by B.
3. Attacker observes both still-valid, not-yet-applied messages in the transaction pool / mempool (both are public consensus proofs awaiting inclusion).
4. Attacker crafts their own message `M_attacker` (signed by the attacker, e.g., a cheap/no-op proof for a third chain or a duplicate that still validates) and submits `handle_unsigned(messages: [M_attacker, M_A, M_B])`.
5. `Pallet::execute` processes all three, producing `StateMachineUpdated` events for the attacker's chain, X, and Y.
6. `on_executed` recovers only the attacker's key from `messages[0]`, then loops over the `highest_per_state_machine` map (which now includes X and Y) and calls `process_message` for each, transferring the treasury reward and minting reputation for X's and Y's advances **to the attacker**, not to A or B — despite A and B having produced and signed the actual proofs.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
