### Title
Payout `OP_RETURN` operator attribution is unauthenticated, allowing misattributed operator reimbursement - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
### Finding Description
The payout transaction that fronts a Citrea withdrawal is signed by the user with `SIGHASH_SinglePlusAnyoneCanPay`, which is verified in `Operator::withdraw` [1](#0-0) . `SIGHASH_SINGLE|ANYONECANPAY` only commits to input 0 and the output at the same index (the user payout output). The remaining outputs — the CPFP anchor and, critically, the `OP_RETURN` output that records `operator_xonly_pk` (“the operator's x-only public key that fronts the peg-out”) — are **not covered by the signature** at all, as built in `create_payout_txhandler`: [2](#0-1) .

Because the OP_RETURN value is unsigned, whoever actually funds and broadcasts the transaction (via `fund_raw_transaction`/`sign_raw_transaction_with_wallet` in `Operator::withdraw`, see [3](#0-2) ) can place *any* xonly public key in that output — including the key of a completely different, uninvolved registered operator — while still paying the exact user-committed output.

Downstream, verifiers treat this on-chain `OP_RETURN` value as the ground truth for "who paid": `update_finalized_payouts` parses it straight from the confirmed payout transaction and stores it as `payout_payer_operator_xonly_pk` with no further authentication: [4](#0-3) . The operator side then consumes this DB value unconditionally: `PayoutCheckerTask` looks up "my" unhandled payouts by `operator_xonly_pk` [5](#0-4) , and `validate_payer_is_operator` only checks that the stored payer matches `self.signer.xonly_public_key` — i.e. it just re-confirms the DB value equals the running operator's own key, which is trivially true if the attacker wrote that operator's key into the transaction: [6](#0-5) .

The one cross-check that exists, `is_kickoff_malicious`, only verifies that the OP_RETURN-derived payer equals `kickoff_data.operator_xonly_pk` (i.e. whichever operator's own signer submits the kickoff): [7](#0-6) . It does **not** verify that the credited operator actually broadcast/funded the payout transaction, so this check passes cleanly when the credited (victim) operator's own automation later drives the normal kickoff/reimbursement flow for a payout it never paid for.

### Impact Explanation
This breaks the required custody binding "the operator credited versus the party that paid." An unprivileged third party who obtains the withdrawal's presigned `SinglePlusAnyoneCanPay` signature (available to anyone who can call the aggregator's `Withdraw`/`OptimisticPayout`-adjacent flow, or observe a broadcast/mempool payout tx, since it is explicitly designed to be reusable by any funder) can front the withdrawal themselves while writing an arbitrary *other* registered operator's key into the `OP_RETURN`. That operator's own `PayoutCheckerTask`/kickoff automation will then transparently proceed through `handle_finalized_payout` → kickoff → `Reimburse` and be paid from bridge collateral for a payout it never funded — a misattributed reimbursement, matching the Critical impact "an operator reimbursed for a payout it never funded." Alternatively, an attacker can name a bogus/uncontrolled key, permanently orphaning the reimbursement path for that deposit since no operator's signer will ever match the attacker-chosen key in `validate_payer_is_operator`, mapping to "an honest operator permanently unable to be reimbursed."

### Likelihood Explanation
Exploitation requires no privileged role (no verifier/operator/watchtower access) — only knowledge of the presigned withdrawal input and enough BTC to cover the payout amount and fees, both of which are inherent to the normal, permissionless "anyone can front a withdrawal" design intentionally enabled by `ANYONECANPAY`. The unsigned `OP_RETURN` is a straightforward oversight rather than requiring any race condition or malleability trick beyond constructing the transaction directly.

### Recommendation
Bind the `OP_RETURN` operator attribution to the actual funder cryptographically — e.g. require the fronting operator to also contribute a signature over the whole transaction (or a covenant/witness proving control of the funding inputs matches the claimed `operator_xonly_pk`), or otherwise ensure `SIGHASH_ALL`-style coverage over the OP_RETURN output so it cannot be altered independently of the signer who actually pays.

### Proof of Concept
1. Obtain the user's `SinglePlusAnyoneCanPay` signature for withdrawal `W` (e.g. from a broadcast/mempool payout tx, or via the same off-chain channel operators receive it through).
2. Build a payout transaction reusing that signed input, with output[0] identical to the signed commitment (correct amount/script), your own funding input(s)/anchor, but set the `OP_RETURN` to a victim operator `V`'s registered `xonly_pk` (not your own) — this remains fully valid because `SIGHASH_SINGLE|ANYONECANPAY` does not cover the anchor or `OP_RETURN` outputs, per `create_payout_txhandler` [2](#0-1) .
3. Broadcast; once confirmed, `update_finalized_payouts` records `V` as the payer [4](#0-3) .
4. `V`'s own `PayoutCheckerTask` picks up the "unhandled payout" for its own key [5](#0-4)  and proceeds through kickoff/reimbursement, receiving bridge collateral for a withdrawal it never funded.

Note: I was unable to fully trace every downstream consumer of `payout_payer_operator_xonly_pk` (e.g. all BitVM assert/disprove circuit-side checks) within the available research budget to rule out an additional cross-check that might reject this specific misattribution before final reimbursement; the `is_kickoff_malicious` check, which is the one designed to catch operator-payer mismatches, does not cover this case as analyzed above.

            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
