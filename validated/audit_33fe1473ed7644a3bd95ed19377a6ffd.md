### Title
Unprivileged external sender can assign internal output roles (Branch/Change/Forwarded) to arbitrary deposits via publicly computable offsets - (File: processor/src/networks/bitcoin.rs)

### Summary
The bug class is improper privilege management on assignment of a privileged role: an authenticated but low-privilege party selects a high-privilege role (admin) because the system validates the role exists without checking the caller may assign it. The Serai analog lives in the Bitcoin wallet classification path: `Scanner::register_offset` maps deterministic, publicly computable scalar offsets to internal output "kinds" (`Branch`, `Change`, `Forwarded`), and `Scanner::scan_transaction` + `get_outputs` classify any on-chain output whose `script_pubkey` matches as that internal kind. Because the offsets are `hash_to_F(KEY_DST, b"branch"/"change"/"forward")` over a public key, any external sender can compute the internal addresses and assign their own transaction the privileged "Change"/"Branch"/"Forwarded" role, bypassing the `External` deposit path and its required InInstruction data.

### Finding Description
`networks/bitcoin/src/wallet/mod.rs` builds a `Scanner` that maps `script_pubkey -> offset` (`scripts: HashMap<ScriptBuf, Scalar>`) and `scan_transaction` emits a `ReceivedOutput { offset, .. }` purely on script match — no authentication of who created the output: [1](#0-0) 

`processor/src/networks/bitcoin.rs` then registers the internal roles with fixed public constants and classifies scanned outputs by looking the offset up in `kinds`: [2](#0-1) [3](#0-2) 

The `KEY_DST`, `"branch"`, `"change"`, `"forward"` strings and the scanner `key` (the multisig group key) are all public, so `Secp256k1::hash_to_F(KEY_DST, b"change")` is computable by anyone. Only `External` outputs get `data`/`presumed_origin` populated (`if output.kind == OutputType::External`), meaning deposit metadata handling is gated on the attacker-controlled classification: [4](#0-3) 

### Impact Explanation
An unprivileged party who sends a Bitcoin transaction can cause funds to be reported with a privileged internal type:

- A payment to `key + G*change_offset` is emitted as `OutputType::Change` — indistinguishable from genuine wallet change, so it is treated as protocol-owned spendable balance without ever carrying a Serai deposit instruction. This mis-attributes an external deposit as internal funds, corrupting balance accounting (internal balances inflated; deposit never credited to a Serai account — or conversely, attacker-crafted "change" outputs entering the schedulable input set without the external-deposit validation path).
- Payments to `G*branch_offset` / `G*forward_offset` scripts are classified as `Branch`/`Forwarded`, entering flows reserved for internally generated outputs.
- Since the classification is purely script-based and the offsets are surjective/public, there is no check — analogous to "validates the role exists but not the caller's privilege to assign it."

### Likelihood Explanation
Trivially reachable: the attacker only needs to send a standard P2TR Bitcoin transaction to `address_from_key(key + G*offset)`, with `offset` computed from public constants and the public multisig key. No collusion, validator compromise, or special access is required — exactly the "Bitcoin transactions they send" input class in scope.

### Recommendation
Treat the offset classification as non-authoritative provenance: mark `Change`/`Branch`/`Forwarded` outputs as trusted only if they are produced by transactions the multisig itself constructed (e.g., match against outpoints created by known signed transactions), or require corroborating evidence before crediting internal-type outputs as protocol-owned/spendable funds.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }

const KEY_DST: &[u8] = b"Serai Bitcoin Output Offset";
static BRANCH_OFFSET: OnceLock<Scalar> = OnceLock::new();
static CHANGE_OFFSET: OnceLock<Scalar> = OnceLock::new();
static FORWARD_OFFSET: OnceLock<Scalar> = OnceLock::new();

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}
