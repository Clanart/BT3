### Title
Unauthenticated `governance_vote` RPC allows any caller reaching the `governance` namespace to force a node to cast a governance vote - (File: kaiax/gov/headergov/impl/api.go)

### Summary
`governance_vote` is registered as a `Public: true` RPC method in the `governance` namespace [1](#0-0) . Its handler performs no check on who is calling the RPC — it accepts a `(name, value)` pair from any caller and queues a vote using the node's own configured identity, gated only by whether the *node* happens to be the governing node, not by whether the *caller* is authorized to direct that node's governance behavior.

### Finding Description
`headerGovAPI.Vote` reads the vote's voter identity from `api.h.nodeAddress` (the node's own key), not from any authenticated caller credential, and only rejects the call if the chain is in `single` governance mode and the node itself is not the `GoverningNode`: [2](#0-1) 

There is no eauth/ACL-style check on the RPC caller at all — this mirrors the CVE-2021-25281 root cause (an administrative-effect API exposed without honoring credential/authorization checks). Because the API is marked `Public: true`, it is auto-registered on any HTTP/WS endpoint whose module whitelist includes `governance` (or has an empty whitelist, since `Public` APIs are then included by default) per `StartHTTPEndpoint`'s whitelist logic: [3](#0-2) 

If the endpoint's `governance` module is enabled (or module list is left empty), any remote caller who can reach the JSON-RPC port can invoke `governance_vote` with arbitrary parameter names/values. When the mode is `none` (all GC members may vote) or when the node itself is the governing node, the call succeeds unconditionally for any caller — no signature, no session, no role check tied to the actual RPC client. This queues a vote (`PushMyVotes`) that gets embedded in `header.Vote` the next time this node proposes a block: [4](#0-3) 

While `VerifyVote` re-validates the vote against on-chain council membership/proposer identity when propagated to peers [5](#0-4) , that check only limits *which node* may embed a vote in a block header — it does nothing to prevent an unauthorized remote RPC caller from puppeteering that node into voting on its behalf, since the vote content and timing are entirely attacker-controlled once the RPC call succeeds.

### Impact Explanation
An attacker with network access to a governing-node's (or `none`-mode participant's) JSON-RPC endpoint (if `governance` module is exposed) can drive governance parameter changes — e.g. `governance.unitprice`, `kip71.*` fee bounds, `reward.*` distribution ratios, or even `governance.addvalidator`/`removevalidator` — entirely without holding any key or session tied to that node, by simply calling `governance_vote`. This is a direct governance-parameter manipulation / validator-set manipulation vector reachable via a single unauthenticated RPC call, matching the "governance parameters" and "staking and reward distribution" in-scope categories.

### Likelihood Explanation
Exploitability depends entirely on RPC exposure configuration: the `governance` module must be enabled on a network-reachable HTTP/WS listener (default module whitelists for CN/PN nodes are configured via `--rpcapi`/`--wsapi` and are not verified here to include `governance` by default in this codebase). Where operators do expose it, the attack requires no credentials, only a JSON-RPC POST, making it trivially and remotely exploitable.

### Recommendation
Add explicit RPC-level authorization to `governance_vote` (e.g., IPC-only, or checked against an operator-configured trusted-caller list), independent of the on-chain `GoverningNode`/mode check, since the current check only validates the node's own configured role, not the identity of the RPC caller invoking it.

### Proof of Concept
1. Configure/reach a CN node whose HTTP or WS RPC server has the `governance` module enabled (e.g. `--rpcapi governance` or empty module whitelist with default `Public` inclusion).
2. As an unauthenticated remote client, send:
```
curl "http://<node-host>:8551" -X POST -H 'Content-Type: application/json' --data \
'{"jsonrpc":"2.0","id":1,"method":"governance_vote","params":["governance.unitprice", 1]}'
```
3. If the node is in `none` governance mode, or is itself the `GoverningNode`, the call succeeds and queues the vote (`api.h.PushMyVotes(vote)`), which will be embedded into `header.Vote` the next time the node produces a block — all without the caller ever presenting any credential establishing authorization to direct that node's governance participation.

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}

func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
