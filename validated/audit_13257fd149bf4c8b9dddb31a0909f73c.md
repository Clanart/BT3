### Title
Users cannot clear their vote for a deactivated pool, permanently locking their vlMGP and freezing their voting power - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.unvote()` is documented to let a user remove their vote from a **deactivated** pool, but the implemented guard reverts unless the pool **is** active, achieving the opposite of its stated purpose. Combined with the vote-locking check in `VLMGP.startUnlock()`, this permanently traps a voter's `vlMGP` for any pool the admin deactivates.

### Finding Description
`unvote()` is explicitly commented as the mechanism to let a user withdraw their vote from a pool that has been made inactive ("This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing"), but its guard condition is inverted — it reverts when the pool is **not** active, i.e. it can only be called on still-active pools: [1](#0-0) 

Once an admin deactivates a pool (normal, expected maintenance operation of the bribe list, not a privileged attack), any user who previously voted for it via `vote()` can never call `unvote(_lp)` for that pool again, because `pool.isActive` is now `false` and the function immediately reverts. As a result:
- `userVotedForPoolInVlmgp[msg.sender][lp]` for that pool can never be zeroed.
- `userTotalVotedInVlmgp[msg.sender]` (aggregate across all pools) stays permanently inflated by that amount, since it is only decremented inside the now-unreachable `unvote()` branch.

This stuck vote total then interacts with `VLMGP.startUnlock()`, which blocks a user from starting the unlock (withdrawal) process for any amount of `vlMGP` that would push their remaining locked balance below their outstanding `userTotalVotedInVlmgp`: [2](#0-1) 

Because the vote allocated to the dead pool can never be released through `unvote()`, the portion of the user's locked MGP tied to that vote can never be reduced below the stuck amount — it is permanently unlockable through the normal user-facing flow.

### Impact Explanation
Any ordinary DAO member (unprivileged wallet) who voted for a pool that is later deactivated has a portion of their locked `vlMGP` (and the corresponding voting weight) permanently frozen, with no user-callable path to release it. This is a direct, permanent freeze of user funds (locked MGP) exceeding the 24-hour threshold, reachable purely through normal wallet transactions (`vote()` then later attempting `startUnlock()`/`unlock()`), triggered by a routine, non-malicious admin pool-list change.

### Likelihood Explanation
Pool deactivation is an expected, routine operational action (removing a stale or deprecated LP/rewarder from the bribe list), not an attack. Any user who voted for that pool before deactivation is affected without any special conditions, making the likelihood high whenever pool maintenance occurs.

### Recommendation
Fix the condition in `unvote()` so that it only reverts when the pool **is** active is required to prevent it (or, per the doc comment's intent, allow unvoting when the pool is inactive and block/replace it with revocation logic for active pools separately). Ensure `userVotedForPoolInVlmgp` and `userTotalVotedInVlmgp` can always be cleared for a pool regardless of its `isActive` state, and skip the `IBribeRewardPool(pool.rewarder).withdrawFor` call (or handle it defensively) when the pool/rewarder is no longer active, so it does not itself revert the whole "clear vote" flow.

### Proof of Concept
1. Admin adds pool `P` and marks it active; `bribeManager.addPool(...)`.
2. User locks MGP in `VLMGP`, then calls `bribeManager.vote([P], [amount])`, setting `userVotedForPoolInVlmgp[user][P] = amount` and `userTotalVotedInVlmgp[user] += amount`.
3. Admin later sets `poolInfos[P].isActive = false` (normal pool-list maintenance).
4. User calls `bribeManager.unvote(P)` → reverts with `PoolNotActive()` because `unvote()`'s guard requires `pool.isActive == true`.
5. User calls `VLMGP.startUnlock(fullLockedAmount)` → reverts with `NotEnoughLockedMPG()` because `totalLockAfterStartUnlock < userTotalVotedInVlmgp(user)`, since the stuck vote for `P` can never be subtracted.
6. The user's MGP corresponding to the vote for `P` remains locked indefinitely with no user-accessible remediation path.

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
