### Title
Payout transaction's operator-credit output (OP_RETURN) is not covered by the user's `SinglePlusAnyoneCanPay` signature, allowing reimbursement to be misattributed to a different operator than the one who fronted the withdrawal - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary

### Finding Description
The `payout_tx` created by `create_payout_txhandler` has three outputs: the user payout, an anchor (CPFP) output, and an OP_RETURN output carrying the fronting operator's x-only public key [1](#0-0) . The only signature securing this transaction is the withdrawal user's signature, which is required to use `TapSighashType::SinglePlusAnyoneCanPay` [2](#0-1)  and is verified against sighash of input 0 only [3](#0-2) .

Because the sighash flag is `SIGHASH_SINGLE | ANYONECANPAY`, the signature commits only to input 0 and the output at the matching index (output 0, the user payout). It does **not** commit to the anchor output or, critically, to the OP_RETURN output that records which operator is to be credited/reimbursed. `calculate_pubkey_spend_sighash` explicitly restricts prevouts to only the signed input for `*PlusAnyoneCanPay` types, confirming only one input/matching-output pair is bound by the signature [4](#0-3) .

Downstream, the verifier attributes reimbursement rights purely from whatever OP_RETURN ends up in the transaction that is actually mined spending the withdrawal UTXO: `update_finalized_payouts` parses the OP_RETURN of the confirmed payout tx and stores that pubkey as `payout_payer_operator_xonly_pk` [5](#0-4) . `PayoutCheckerTask`/`get_first_unhandled_payout_by_operator_xonly_pk` and `validate_payer_is_operator` then grant kickoff/reimbursement rights strictly based on that stored pubkey [6](#0-5) [7](#0-6) . There is no on-chain binding tying "the operator whose funds actually paid the withdrawal input" to "the operator xonly pk in OP_RETURN" — the OP_RETURN field is entirely unauthenticated with respect to the withdrawal signature.

This breaks the intended equality: `operator credited (OP_RETURN pubkey in the confirmed payout tx)` == `operator that fronted (funded/broadcast) the payout`. Since the anchor and OP_RETURN outputs are unsigned, any party who obtains the raw payout transaction before it confirms (e.g., observes it in the mempool, or via `fund_raw_transaction`/RBF flow which explicitly enables replaceable funding [8](#0-7) ) can rebuild a transaction that still spends the same signed input/output pair (satisfying the signature) but swaps the OP_RETURN value to name a different operator's x-only pubkey, then get that version confirmed instead (via RBF fee-bump or mempool race), diverting the reimbursement credit.

### Impact Explanation
If successful, this results in an operator being reimbursed for a payout it never actually funded (the "operator credited" side is decoupled from "the party that paid"), which maps directly to the Critical impact category "an operator reimbursed for a payout it never funded." Conversely, the honest operator that funded/broadcast the payout could be denied credit and become permanently unable to claim reimbursement for the funds it fronted, which maps to "an honest operator permanently unable to be reimbursed."

### Likelihood Explanation
Exploitation requires only observing/obtaining the yet-unconfirmed payout transaction (public once broadcast to the mempool) and rebroadcasting a variant with a modified, unsigned OP_RETURN output while keeping the signed input/output untouched — no operator, verifier, or other privileged role is required, and no key compromise is needed since the OP_RETURN and anchor outputs were never covered by any signature. The main precondition is that the transaction must actually be replaceable/raceable before confirmation (e.g., RBF signaling via the funding flow, or a mempool race prior to first confirmation), which is a realistic condition given the code explicitly funds the payout tx for broadcast/RBF handling.

### Recommendation
Bind the operator-credit output to the same signature that authorizes spending the withdrawal UTXO, e.g. by using `SIGHASH_ALL|ANYONECANPAY` (or a full `SIGHASH_ALL`) so all outputs, including the OP_RETURN and anchor, are covered by the user's signature, or by embedding the committing operator's x-only pubkey inside the script/spend path that must be satisfied to spend the user's UTXO rather than relying on an unauthenticated OP_RETURN. At minimum, verifiers should require that the OP_RETURN commitment be reproducible from data that is itself signed/committed (e.g., re-derive expected operator identity from the same off-chain-signed request that authorized broadcasting), rather than trusting whatever ends up on-chain.

### Proof of Concept
1. Operator A calls `withdraw`/`internal_withdraw` with a valid user `SinglePlusAnyoneCanPay` signature over `input_outpoint`/`output_script_pubkey`/`output_amount`; this builds a `payout_tx` with OP_RETURN = Operator A's xonly pk, and funds/broadcasts it via `fund_raw_transaction`, allowing RBF [9](#0-8) .
2. Before confirmation, an attacker observes the pending `payout_tx` in the mempool and constructs a variant: same input (same witness/signature, since only input 0 + output 0 are signed), same user output, but a different OP_RETURN payload (e.g., Operator B's xonly pk), and a bumped fee via RBF (or races the honest broadcast).
3. The attacker's variant confirms instead. `update_finalized_payouts` parses the OP_RETURN of the confirmed tx and records `payout_payer_operator_xonly_pk` = Operator B [5](#0-4) .
4. `PayoutCheckerTask` and `validate_payer_is_operator` subsequently grant Operator B (not Operator A, who actually funded the withdrawal) the right to kickoff and claim reimbursement [6](#0-5) [7](#0-6) , while Operator A — who actually paid — has no recorded claim and cannot be reimbursed.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
