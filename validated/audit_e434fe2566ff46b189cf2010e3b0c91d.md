### Title
Authority/host confusion in `parseRemote()`'s regex-based URL parsing lets a crafted `#@` remote URL be misattributed to a trusted account, causing token/account misuse for attacker-controlled hosts - (File: `app/src/lib/remote-parsing.ts`, `app/src/lib/find-account.ts`)

### Summary
`parseRemote()` extracts the "hostname" from a remote/clone URL using a hand-rolled regex instead of a spec-compliant URL parser, while the account/credential-selection logic in `findAccountForRemoteURL()` trusts that extracted hostname to decide which authenticated account (and thus token) is associated with a given URL. Because the regex's greedy `(?:.+@)?` group can consume a fragment-delimiter (`#`) the same way CVE-2016-8624 exploited curl's authority parsing, a crafted URL such as `https://evil.com#@github.com/owner/repo.git` is parsed by `parseRemote()` as hostname `github.com`, while the real network endpoint any spec-compliant client (git, curl, WHATWG `URL`) would contact is `evil.com`. This is the same broken invariant as the report: "the host used for a security decision differs from the host actually contacted."

### Finding Description
`parseRemote()` in <cite repo="blackvul/desktop--002" path="app/src/lib/remote-parsing.ts" start="27-33" end="27-33" /> uses:
```
regex: new RegExp('^https?://(?:.+@)?(.+)/([^/]+)/([^/]+?)(?:/|\\.git/?)?$')
``` [1](#0-0) 

The optional `(?:.+@)?` group is greedy and unanchored to any actual URL syntax (no notion of scheme/authority/fragment boundaries). Given input `https://evil.com#@github.com/owner/repo.git`, this group backtracks to consume everything up through the last `@` (i.e. `evil.com#@`), leaving group 1 (treated as "hostname") to match `github.com`. `parseRemote()` therefore returns `{ hostname: 'github.com', owner: 'owner', name: 'repo' }` for a string whose actual network authority — as any WHATWG `URL` or git/libcurl parser would compute — is `evil.com` (everything before `#` in the authority component terminates at the first `/`, `?`, or `#`).

This parsed (wrong) hostname is then used as a trust anchor in `findAccountForRemoteURL()`:
```
const parsedURL = parseRemote(urlOrRepositoryAlias)
if (parsedURL) {
  const account = allAccounts.find(a => {
    const htmlURL = getHTMLURL(a.endpoint)
    const parsedEndpoint = URL.parse(htmlURL)
    return parsedURL.hostname === parsedEndpoint.hostname
  }) || null
  if (account) { return account }
}
``` [2](#0-1) 

Because `parsedURL.hostname` is `github.com` (attacker-forced via the `#@` trick) rather than the real destination `evil.com`, this function returns the user's real, authenticated GitHub.com account for a URL that will actually cause git/network traffic to go to `evil.com`. `getEndpointForRepository()` in `app/src/lib/api.ts` has the identical class of bug: it uses Node's legacy, non-WHATWG `url.parse()` (`import * as URL from 'url'`) to derive a hostname/endpoint used for account/token lookup [3](#0-2) , a second, independent parser from the regex used elsewhere for owner/name extraction, so the two parsers can disagree about "the host" for the same input string — exactly the differential-parsing root cause the cURL advisory describes.

The user-reachable trigger is the "Open in Desktop" deep link / CLI clone path: `x-github-client://openRepo/<url>` is parsed by `parseAppURL()` [4](#0-3)  with the embedded `<url>` passed through essentially unchecked as `openRepo.url`, then routed via `dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository`/`resolveCloneInfo` (in `clone-repository.tsx`, which calls `findAccountForRemoteURL(url, this.props.accounts)` at [5](#0-4) ). None of these steps validate that the "hostname" `parseRemote` reports actually matches what git/curl will connect to.

### Impact Explanation
An attacker who gets a victim to click a "Open in GitHub Desktop" deep link (or supplies a malicious `--cli-clone` argument, or a crafted PR/repository clone URL surfaced through the app) can make Desktop believe a URL belongs to the user's already-authenticated GitHub.com (or GHE) account when the real destination host is attacker-controlled. This breaks the trust boundary that account/token selection is supposed to enforce: the wrong account context is selected for a URL whose real target is different from what the parser reported, mirroring exactly the SSRF/host-confusion primitive in the cURL CVE ("connecting to a different host than the one that was checked/allowed"). Depending on how far the mis-selected account propagates (credential fill for a subsequent `git fetch/clone` against `evil.com`, or being treated as the account entitled to a private repository), this can result in credential exposure to an unintended host or unauthorized cross-account repository access.

### Likelihood Explanation
Medium. The attacker fully controls the input string (an "Open in Desktop" URL or CLI clone URL) and the vulnerable regex is unconditionally exercised without any allow-list or canonicalization step; no local access, admin rights, or pre-existing malware is required — only that the user click a link or run a Desktop CLI clone with an attacker-supplied URL. The severity is somewhat bounded by downstream steps (e.g. `resolveCloneInfo` re-validates `owner`/`name` against the GitHub API before actually cloning), but the fundamental parser/trust-decision mismatch is real and directly reachable from untrusted input.

### Recommendation
Replace the hand-rolled regex parsing of hostnames in `parseRemote()` (`app/src/lib/remote-parsing.ts`) and the legacy `URL.parse()` usage in `getEndpointForRepository`/`findAccountForRemoteURL` with a single, spec-compliant parser (WHATWG `URL`) for HTTPS URLs, and ensure the *same* parser/host value is used consistently for both "select account/credentials" and "select owner/name" decisions. Reject or normalize inputs containing `#`/embedded credentials before matching against known account hostnames, and add a regression test asserting `parseRemote('https://evil.com#@github.com/owner/repo.git').hostname === 'evil.com'` (matching real network behavior), not `github.com`.

### Proof of Concept
1. Craft the URL `https://evil.com#@github.com/owner/repo.git`.
2. Call `parseRemote(url)` (`app/src/lib/remote-parsing.ts:55`) — observe it returns `hostname: 'github.com'` (not `evil.com`, the real authority).
3. Pass the same URL to `findAccountForRemoteURL(url, accounts)` (`app/src/lib/find-account.ts:38`) with a victim account list containing a real, authenticated `github.com` account — observe it returns that account, even though any RFC-3986-compliant client (git, curl, WHATWG `URL`) resolves the authority/host of this URL to `evil.com`.
4. Trigger this path unprompted via `x-github-client://openRepo/https%3A%2F%2Fevil.com%23%40github.com%2Fowner%2Frepo.git` (or `--cli-clone`), reachable from `parseAppURL` → `dispatchURLAction` → `openOrCloneRepository`/`resolveCloneInfo`.

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
}
