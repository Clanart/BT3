### Title
Coinbase outputs reported as spendable received outputs before maturity - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction (`block.txdata[0]`). Coinbase outputs are bound by Bitcoin's 100-block maturity rule and cannot be spent until then. `scan_block` returns them as ordinary `ReceivedOutput`s indistinguishable from mature outputs, so a wallet that scans a block directly will treat immature coins as spendable inputs.

### Finding Description
`scan_transaction` credits any output whose `script_pubkey` matches a registered offset, with no notion of transaction position or maturity [1](#0-0) . `scan_block` iterates `block.txdata` in full — including the coinbase — and emits `ReceivedOutput`s for it [2](#0-1) . A `ReceivedOutput` is defined as "a spendable output" [3](#0-2) , yet a coinbase output is provably unspendable for 100 blocks. If such an output is fed to `SignableTransaction::new` and `multisig`, the threshold signing round produces a fully valid-looking transaction that the Bitcoin network will reject as a consensus violation (immature coinbase spend), since `taproot_key_spend_signature_hash` over `Prevouts::All` happily signs it [4](#0-3) .

This mirrors the report's bug class: value credited against a balance before the required waiting/accounting boundary has elapsed — here, coinbase rewards counted in the spendable set without the maturity wait.

### Impact Explanation
A miner (or any party able to get a coinbase paying the scanner's key into a block) causes the wallet to report funds as received and spendable that are not. The resulting multisig signing session wastes a FROST round on a transaction that can never confirm, and if the immature output is co-mingled with real inputs, the entire spend fails, potentially DoS-ing withdrawals until the offending outpoint is manually excluded. Under the accepted-impact criteria, this is "funds reported received that are not spendable."

### Likelihood Explanation
Low-to-moderate: exploitation requires an attacker to mine a block (or the pool/miner paying Serai to do so). However, the doc comment on `scan_block` acknowledges the hazard only as a note — the function itself performs no filtering, so any downstream caller that uses `scan_block` instead of re-implementing the `txdata[1..]` skip is exposed. Notably, Serai's own processor skips the coinbase (`block.txdata[1 ..]`), showing the correct behavior is known but not enforced by the library [5](#0-4) .

### Recommendation
`scan_block` should skip `block.txdata[0]` itself (or return immature outputs flagged/tagged so callers cannot accidentally treat them as spendable). Relying on each consumer to replicate the skip invites exactly this accounting error.

### Proof of Concept
```rust
// Given a Scanner for `key` and a block whose coinbase pays key's P2TR script:
let scanner = Scanner::new(key).unwrap();
let outputs = scanner.scan_block(&block);
// outputs contains a ReceivedOutput for the coinbase output.
// The following constructs a tx spending the immature output and produces
// valid Schnorr signature shares for it; the resulting tx is rejected by
// consensus (bad-txns-coinbase / immature spend).
let tx = SignableTransaction::new(outputs, &payments, Some(change), None, fee).unwrap();
let machine = tx.multisig(&keys).unwrap(); // signs successfully, never confirms
```
Coinbase maturity is consensus-enforced (BIP-30/COINBASE_MATURITY = 100), so any output from `block.txdata[0]` returned by `scan_block` is a `ReceivedOutput` that cannot actually be spent at scan time.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
