## Title
Potential ante-pipeline bypass for `MsgEVMTransaction` via nested Cosmos-message dispatch paths (authz `MsgExec`, wasm Stargate encoder) - ([File: app/antedecorators/authz_nested_message.go], [File: sei-wasmd/x/wasm/keeper/handler_plugin_encoders.go])

### Summary
The JumpServer CVE is a class of bug where an input-validation/allowlist mechanism that is supposed to constrain what a downstream privileged executor can run is incomplete, letting an attacker slip a dangerous payload past the filter into a privileged execution context (root Celery worker). The closest reachable analog in sei-chain is the explicit, but narrow, guard that exists specifically to stop `MsgEVMTransaction` from being smuggled into execution through a non-ante code path: `AuthzNestedMessageDecorator`.

### Finding Description
Sei's EVM transactions are gated by a dedicated ante pipeline (`evmAnteDecorators` in `app/ante.go`, including `EVMPreprocessDecorator`, `EVMFeeCheckDecorator`, `EVMSigVerifyDecorator`, `GasDecorator`) that is only invoked when `EVMRouterDecorator`/`IsEVMMessage` sees a top-level `*types.MsgEVMTransaction` in `tx.GetMsgs()` [1](#0-0) . Sei-chain's engineers were clearly aware that this top-level-only detection is fragile, because a dedicated decorator, `AuthzNestedMessageDecorator`, was added purely to reject transactions that wrap `MsgEVMTransaction` inside an `authz.MsgExec`, recursively up to `maxNestedMsgs` levels [2](#0-1) . This is a special-cased allowlist/denylist patch bolted onto the ante pipeline rather than a structural guarantee that `MsgEVMTransaction` can never reach `DispatchActions`/message routing outside the EVM ante pipeline.

That patch only covers one dispatch vector: `x/authz`'s `MsgExec` → `Keeper.DispatchActions`, which calls `k.router.Handler(msg)` directly, bypassing baseapp's `runTx`/ante entirely [3](#0-2) . However, sei-chain (via `sei-wasmd`) has at least one more code path with the exact same shape: CosmWasm contracts can return a `CosmosMsg::Stargate` message containing an arbitrary registered protobuf `Any` (`TypeURL`/`Value`), which `EncodeStargateMsg` unpacks via the `AnyUnpacker`/interface registry into a concrete `sdk.Msg` [4](#0-3) . That decoded message is then dispatched by `SDKMessageHandler.handleSdkMessage`, which only checks `ValidateBasic()` and that the contract is among `msg.GetSigners()`, then calls `h.router.Handler(msg)` directly [5](#0-4) . Like the authz path, this is a message-router invocation that never passes back through `app/ante.go`'s `evmAnteDecorators`/`EVMRouterDecorator`, so if `MsgEVMTransaction` (or any privileged EVM/precompile-adjacent Msg) were reachable this way, it would run without EVM-specific signature verification, fee checking, or sender/nonce association.

### Impact Explanation
I was **not able to fully confirm** whether this path is actually exploitable end-to-end in this codebase snapshot:
- I could not verify (within the remaining tool budget) whether `MsgEVMTransaction` is registered in the interface registry in a way that makes it unpackable from an arbitrary `Any` via the wasm Stargate encoder, or whether `GetSigners()`/message-router `Handler` for `MsgEVMTransaction` even accepts being invoked outside the dedicated EVM ante+handler flow (it may simply error out, similar to how `authz.MsgExec` nesting required its own explicit denylist rather than "just working").
- I could not confirm whether sei-chain restricts the wasm Stargate encoder with an accept-list (some sei-cosmos/wasmd forks add a `StargateWhitelist` type of restriction) that would block dispatch of chain-privileged message types like `MsgEVMTransaction` from contracts.

If such a bypass were confirmed, the impact would be severe: a CosmWasm contract (or an authz-exec sender) could inject an EVM transaction that runs with the contract's/granter's SDK address as sender, without going through `EVMSigVerifyDecorator`/`EVMFeeCheckDecorator`/`GasDecorator`, i.e., unauthorized transfer or code execution and fee/gas accounting bypass. This would match the "unauthorized transfer via precompile or pointer" / "fee or refund abuse" impact categories.

### Likelihood Explanation
Likelihood is uncertain and cannot be assessed with confidence given the available evidence. The presence of `AuthzNestedMessageDecorator` shows the sei-chain team specifically anticipated and patched one instance of this exact bug class (nested-message dispatch bypassing the EVM ante pipeline), which suggests the underlying risk pattern is real, but I could not confirm that the wasmd Stargate path (or any other nested-dispatch surface such as ICA, gov `MsgExecLegacyContent`, or feegrant) has not received an equivalent guard, nor could I confirm the message actually deserializes/dispatches successfully for `MsgEVMTransaction` specifically.

### Recommendation
Because this could not be conclusively validated as a working bypass, I am not asserting it as a confirmed exploitable vulnerability. It should be verified with lower-level access (a Devin session) by:
1. Checking whether `x/evm/types/codec.go`'s `RegisterInterfaces` registers `MsgEVMTransaction` as an `sdk.Msg` implementation reachable by the codec's `AnyUnpacker`.
2. Checking whether the wasmd `EncodeStargateMsg` path (and any ICA/gov content-dispatch equivalents) has an accept-list/denylist analogous to `AuthzNestedMessageDecorator`, and if not, add one that rejects `MsgEVMTransaction` (and any other ante-gated message types) from being dispatched via non-ante router paths.
3. If a bypass is confirmed, generalize the fix: instead of enumerating dispatch vectors one at a time (authz today, wasm/ICA/gov tomorrow), enforce the EVM-specific checks (signature, fee, nonce/association) at the message-handler level for `MsgEVMTransaction` itself, so it cannot be executed correctly through any router path that skips the dedicated ante decorators.

### Proof of Concept
Not provided — I could not construct or verify a concrete PoC within the current investigation because confirming reachability requires inspecting the `x/evm/types/codec.go` interface registration and the wasmd/ICA/gov dispatch allowlists, which I was unable to complete before the iteration budget was exhausted. A Devin session with full repository access should verify these two points before treating this as a confirmed, exploitable finding.

func IsEVMMessage(tx sdk.Tx) (bool, error) {
	hasEVMMsg := false
	for _, msg := range tx.GetMsgs() {
		switch msg.(type) {
		case *types.MsgEVMTransaction:
			hasEVMMsg = true
		default:
			continue
		}
	}

	if hasEVMMsg && len(tx.GetMsgs()) != 1 {
		return false, errors.New("EVM tx must have exactly one message")
	}

	return hasEVMMsg, nil
}

func (ad AuthzNestedMessageDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (newCtx sdk.Context, err error) {
	for _, msg := range tx.GetMsgs() {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// find nested evm messages
			containsEvm, err := ad.CheckAuthzContainsEvm(ctx, m, 0)
			if err != nil {
				return ctx, err
			}
			if containsEvm {
				return ctx, errors.New("permission denied, authz tx contains evm message")
			}
		default:
			continue
		}
	}

	return next(ctx, tx, simulate)
}

// grants from the message signer to the grantee.
func (k Keeper) DispatchActions(ctx sdk.Context, grantee sdk.AccAddress, msgs []sdk.Msg) ([][]byte, error) {
	results := make([][]byte, len(msgs))

	for i, msg := range msgs {
		signers := msg.GetSigners()
		if len(signers) != 1 {
			return nil, sdkerrors.ErrInvalidRequest.Wrap("authorization can be given to msg with only one signer")
		}

		granter := signers[0]

		// If granter != grantee then check authorization.Accept, otherwise we
		// implicitly accept.
		if !granter.Equals(grantee) {
			authorization, _ := k.GetCleanAuthorization(ctx, grantee, granter, sdk.MsgTypeURL(msg))
			if authorization == nil {
				return nil, sdkerrors.ErrUnauthorized.Wrap("authorization not found")
			}
			resp, err := authorization.Accept(ctx, msg)
			if err != nil {
				return nil, err
			}

			if resp.Delete {
				err = k.DeleteGrant(ctx, grantee, granter, sdk.MsgTypeURL(msg))
			} else if resp.Updated != nil {
				err = k.update(ctx, grantee, granter, resp.Updated)
			}
			if err != nil {
				return nil, err
			}

			if !resp.Accept {
				return nil, sdkerrors.ErrUnauthorized
			}
		}

		handler := k.router.Handler(msg)
		if handler == nil {
			return nil, sdkerrors.ErrUnknownRequest.Wrapf("unrecognized message route: %s", sdk.MsgTypeURL(msg))
		}

		msgResp, err := handler(ctx, msg)
		if err != nil {
			return nil, sdkerrors.Wrapf(err, "failed to execute message; message %v", msg)

func EncodeStargateMsg(unpacker codectypes.AnyUnpacker) StargateEncoder {
	return func(sender sdk.AccAddress, msg *wasmvmtypes.StargateMsg) ([]sdk.Msg, error) {
		any := codectypes.Any{
			TypeUrl: msg.TypeURL,
			Value:   msg.Value,
		}
		var sdkMsg sdk.Msg
		if err := unpacker.UnpackAny(&any, &sdkMsg); err != nil {
			return nil, sdkerrors.Wrap(types.ErrInvalidMsg, fmt.Sprintf("Cannot unpack proto message with type URL: %s", msg.TypeURL))
		}
		if err := codectypes.UnpackInterfaces(sdkMsg, unpacker); err != nil {
			return nil, sdkerrors.Wrap(types.ErrInvalidMsg, fmt.Sprintf("UnpackInterfaces inside msg: %s", err))
		}
		return []sdk.Msg{sdkMsg}, nil
	}
}

func (h SDKMessageHandler) handleSdkMessage(ctx sdk.Context, contractAddr sdk.Address, msg sdk.Msg) (*sdk.Result, error) {
	if err := msg.ValidateBasic(); err != nil {
		return nil, err
	}
	// make sure this account can send it
	for _, acct := range msg.GetSigners() {
		if !acct.Equals(contractAddr) {
			return nil, sdkerrors.Wrap(sdkerrors.ErrUnauthorized, "contract doesn't have permission")
		}
	}

	// find the handler and execute it
	if handler := h.router.Handler(msg); handler != nil {
		// ADR 031 request type routing
		msgResult, err := handler(ctx, msg)
		return msgResult, err
	}
	// legacy sdk.Msg routing
	// Assuming that the app developer has migrated all their Msgs to
	// proto messages and has registered all `Msg services`, then this
	// path should never be called, because all those Msgs should be
	// registered within the `msgServiceRouter` already.
	return nil, sdkerrors.Wrapf(sdkerrors.ErrUnknownRequest, "can't route message %+v", msg)
}
