### Title
`SignableTransaction::new` allows an untrusted proposer to specify an arbitrary `change` script and unbounded `fee_per_vbyte`, redirecting leftover multisig funds or burning them as fees - (File: `networks/bitcoin/src/wallet/send.rs`)

### Summary
The Derby report describes a publicly-callable function (`rebalanceXChain`) where an unprivileged caller supplies a security-critical value parameter (`_slippage`), producing a trade at a bad rate that drains protocol funds. The Serai analog is `SignableTransaction::new`: it accepts fully caller-controlled `payments`, `change: Option<ScriptBuf>`, and `fee_per_vbyte`, and the resulting transaction is then signed by the threshold group via `TransactionMachine` without any validation that the change output is controlled by the group or that the effective fee is bounded.

### Finding Description
`SignableTransaction::new` computes `needed_fee = fee_per_vbyte * vbytes` with only a *lower* bound check (`TooLowFee` at `send.rs:211`) — there is no upper bound on the fee rate [1](#0-0) . If `input_sat > payment_sat + needed_fee` and `change` is `None` (or the change remainder is below `DUST`), the entire leftover is silently absorbed into the fee — `fee()` is defined as `sum(inputs) - sum(outputs)` with no cap [2](#0-1) . Worse, `change` is an arbitrary caller-supplied `ScriptBuf`; all leftover value above the dust threshold is sent to it (`tx_outs.push(TxOut { value, script_pubkey: change })`) [3](#0-2) . The only integrity check downstream is in `multisig()`, which verifies that the *inputs'* `script_pubkey`s match the offset group keys — it never inspects the outputs, the change destination, or the fee [4](#0-3) . `TransactionSignMachine::sign` then produces FROST shares over `taproot_key_spend_signature_hash` of exactly that attacker-shaped transaction [5](#0-4) .

### Impact Explanation
An unprivileged party who can get a `SignableTransaction` they construct routed to the threshold signers (a swap/withdrawal request routed through the coordinator path) can: (a) set `change` to a script they control, sweeping `input_sat - payment_sat - fee_with_change` to themselves, or (b) omit `change` and set a huge `fee_per_vbyte` so `fee() >> needed_fee`, burning nearly the entire input value to miners — the exact "bad exchange rate / no slippage bound" shape of the report, resulting in loss of the vault's funds.

### Likelihood Explanation
Any code path where transaction proposals originate from external users (withdrawal requests, external coins being routed) feeds attacker-chosen payments/change/fee parameters into this constructor. The library provides no API-level guard; each signer independently calls `multisig()`/`sign()` and none of those functions reject a malicious output set, so a single crafted proposal signed by `t` honest participants produces a valid, fund-draining transaction.

### Recommendation
Enforce in `SignableTransaction::new` (or in `multisig`) that `change`, when present, is the group's own script — e.g., `change == p2tr_script_buf(keys.group_key())` — and add an upper bound: `self.fee() <= needed_fee` (or a bounded multiple), returning a `TooHighFee` error. Alternatively, have signers verify the change output belongs to the threshold key before producing shares.

### Proof of Concept

// Attacker constructs a transaction spending a group-controlled output.
let inputs = vec![received_output]; // output paying to the threshold key's P2TR script
let payments = [(attacker_script.clone(), DUST)]; // nominal payment
// change = attacker-controlled script sweeps the remainder
let tx = SignableTransaction::new(
  inputs, &payments,
  Some(attacker_change_script), // NOT the group's key
  None,
  fee_per_vbyte,
).unwrap();
// Or: change = None, fee_per_vbyte = huge => fee() consumes nearly all input_sat.
assert!(tx.fee() > tx.needed_fee()); // unbounded fee, no check exists

// Honest signers run the state machines; multisig() only checks input scripts.
let machine = tx.multisig(&keys).unwrap(); // returns Some(...)
// After t signers complete(), the signed TX pays the leftover to the attacker
// or burns it as miner fees.
