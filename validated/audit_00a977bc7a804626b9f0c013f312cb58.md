## Analog Found: No way to revoke a trusted ("safe.directory") repository once added

### Title
Persistent, unrevocable Git `safe.directory` trust exception with no removal path in GitHub Desktop - (File: `app/src/lib/git/config.ts`)

### Summary
GitHub Desktop lets a user permanently mark a repository directory as "safe" (bypassing Git's ownership-mismatch protection) via `addSafeDirectory`, but the codebase contains no corresponding function or UI control to remove/untrust that directory afterward. This mirrors the reported bug class exactly: an entity ("merchant" in the report, a trusted directory here) can be added to a persistent allow-list but never removed through the application.

### Finding Description
When Desktop detects a repository owned by a different user than the current OS user (a Git safety check meant to stop automatic execution of files/hooks from directories the user doesn't control), it shows a warning and offers a "Trust Repository" button in both the *Add Existing Repository* flow and the *Missing Repository* view: [1](#0-0) [2](#0-1) 

Clicking that button calls `addSafeDirectory`, which appends the path to the **global** (machine-wide) `safe.directory` Git config value: [3](#0-2) 

This uses `addGlobalConfigValueIfMissing`, which only ever appends values via `git config --global --add`: [4](#0-3) 

`app/src/lib/git/config.ts` does contain generic `removeConfigValue` / `removeGlobalConfigValue` helpers, but they are never wired to `safe.directory`: [5](#0-4) 

There is no `removeSafeDirectory` function, no dispatcher action, and no Preferences/Settings UI entry that lists or lets a user revoke previously trusted directories — confirmed by the absence of any such symbol across the codebase. Once a path is trusted, it stays in the user's global `~/.gitconfig` `safe.directory` list forever, silently disabling Git's ownership-mismatch protection for that path across **all** Git usage on the machine (not just Desktop), until a user manually edits the gitconfig file outside of Desktop.

### Impact Explanation
The `safe.directory` guard exists specifically because operating on a repository owned by another user can lead to automatic execution of attacker-controlled config/hooks. Desktop's own warning text says this explicitly: "Adding untrusted repositories may automatically execute files in the repository." Because trust, once granted, is permanent and cannot be revoked from within Desktop, any directory the user trusted once (e.g., a shared network drive, a shared multi-user workstation path, or a path later repurposed/taken over by another account) remains permanently exempt from the ownership check. If the ownership of that path is later assumed by an attacker (e.g., a re-provisioned shared folder, a compromised low-privilege account on a shared machine, or content synced into that path by another user), Git/Desktop will continue treating the attacker-controlled content as safe, enabling execution of hooks/config placed there — with no in-app remediation available to the user.

### Likelihood Explanation
Realistic on any shared/multi-user machine or network share workflow, which Desktop explicitly supports (the changelog documents "Support trusting repositories on network shares (Windows)"). A user is only required to have clicked "Trust Repository" once for a legitimately-owned path; no admin rights, malware, or leaked credentials are needed for the persistence/no-revocation flaw itself — it is a design gap in the app's own feature, not an external prerequisite. [6](#0-5) 

### Recommendation
Add an explicit "untrust"/"remove safe directory" capability: implement a `removeSafeDirectory(path)` in `app/src/lib/git/config.ts` (mirroring `removeConfigValueInPath` but targeting the specific value with `git config --global --unset` for that entry), expose it through the dispatcher, and surface a management UI (e.g., in Preferences) listing all `safe.directory` entries added by Desktop with a way to remove them. At minimum, confirm to users that trust is permanent and machine-global so they understand the scope of the exception they're granting.

### Proof of Concept
1. On a shared machine/network share, clone or place a repository at path `P` that is owned by a different OS user account.
2. Open Desktop, add `P` as an existing repository; Desktop shows the "unsafe" warning and a "Trust Repository" button (`app/src/ui/add-repository/add-existing-repository.tsx`).
3. Click "Trust Repository" → `addSafeDirectory(P)` runs `git config --global --add safe.directory P` (`app/src/lib/git/config.ts:181-189`).
4. Later, ownership of `P` changes to an attacker-controlled account (e.g., shared folder reassigned, or a low-privileged account on the shared host is compromised) and the attacker plants malicious hooks/config in `P`.
5. The user reopens Desktop (or runs `git` from that path); because `P` is still listed in the global `safe.directory` config with no expiry and no UI to remove it, Git/Desktop treats it as safe and executes the attacker's hooks/config — with no warning and no way the user could have revoked the earlier trust decision from within the app.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
```
