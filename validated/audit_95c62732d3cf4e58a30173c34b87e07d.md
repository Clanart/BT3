## Analysis Summary

The RUSTSEC-2020-0019 report's core defect is a **stale termination/state check**: `tokio-rustls` failed to re-evaluate `wants_read` immediately after consuming new data, so a condition that should reflect the *current* state kept returning a value based on outdated state, letting unbounded work continue.

The closest local analog is in Hyperbridge's GET-request lifecycle on the EVM handler: `handleGetRequestTimeouts()` never re-checks the *current* response-receipt state before executing a timeout, and instead accepts a non-membership proof anchored at **any historical, already-finalized Hyperbridge height** — even one that predates a response that has since been delivered.

### Title
Stale non-membership proof height in `handleGetRequestTimeouts` lets an already-fulfilled GET request be timed out, double-executing `onGetResponse` and `onGetTimeout` - (File: `evm/src/core/HandlerV2.sol`)

### Finding Description
`handleGetResponses()` in [1](#0-0)  explicitly skips a local timeout check ("don't check for timeouts because it's checked on Hyperbridge") and, on success, `EvmHost.dispatchIncoming(GetResponse ...)` [2](#0-1)  stores a `_responseReceipts[commitment]` entry but **does not delete `_requestCommitments[commitment]`**.

Separately, `handleGetRequestTimeouts()` [3](#0-2)  only checks:
1. that `_requestCommitments[commitment]` still exists (`UnknownMessage` guard) — which remains true even after a successful response, since delivery never clears it, and
2. a non-membership proof that Hyperbridge's `ResponseReceipts[commitment]` is empty **at an arbitrary, caller-supplied historical height `message.height`** (`PolkadotTrie.VerifyProof(state.stateRoot, ...)` against `RESPONSE_RECEIPTS_STORAGE_PREFIX`).

There is no requirement that `message.height` be the *latest* known Hyperbridge state commitment, and no check of `host.responseReceipts(commitment)` on the source chain itself (the same check `handleGetResponses` performs against duplicate delivery). Any state commitment height that (a) has its challenge period elapsed and (b) has a destination timestamp past `request.timeout()` is accepted — including a height that predates when Hyperbridge actually recorded the response in a later block. `dispatchTimeOut(GetRequestTimeout, ...)` then unconditionally deletes `_requestCommitments[commitment]` and invokes `onGetTimeout()` on the app [4](#0-3) .

This mirrors the RUSTSEC pattern exactly: a guard (`wants_read` / "request already answered") is evaluated against a **stale snapshot** instead of the authoritative current state, so the intended one-shot invariant ("exactly one of `onGetResponse`/`onGetTimeout` fires per request") is not actually enforced.

### Impact Explanation
Any permissionless caller can invoke `handleGetRequestTimeouts()` with a proof anchored at an older, already-superseded state commitment to force a second, conflicting callback (`onGetTimeout`) on a module whose GET response (`onGetResponse`) has already executed a fund-moving/state-finalizing action. Applications built on `IApp` that treat "exactly one callback per GET request" as an invariant (e.g. escrow release vs. cleanup/refund logic keyed off `onGetResponse` vs `onGetTimeout`) can be driven into double execution, matching the bounty's "replay/double-claim/double-settlement" and "false proof/state acceptance" categories — the protocol accepts state that is no longer true (a since-superseded absence of a response receipt) as if it were current.

### Likelihood Explanation
The call is fully permissionless (`handleGetRequestTimeouts` has no access control), requires only a normal timeout proof at any historical qualifying height, and depends solely on ordinary protocol timing (response delivered later than an earlier, still-valid height) — no malicious relayer, prover, or governance actor is required, satisfying the impact-gate's requirement of an unprivileged-attacker path.

### Recommendation
- **Short term:** In `handleGetRequestTimeouts`, add an explicit check `if (host.responseReceipts(commitment).relayer != address(0)) revert DuplicateMessage();` before dispatching the timeout, mirroring the duplicate-response guard already used in `handleGetResponses`.
- **Long term:** Require timeout/non-membership proofs to be anchored at the *latest* known state commitment height for the relevant state machine (or otherwise bind the accepted height to be monotonically fresh), so stale historical snapshots can never be used to assert an invariant that has since changed.

### Proof of Concept
1. App `A` dispatches a `DispatchGet` with non-zero `timeout`, implementing both `onGetResponse` (e.g., release funds) and `onGetTimeout` (e.g., refund/cleanup) as mutually exclusive terminal actions.
2. At Hyperbridge height `H1` (before the response is processed) the request's `timeout_timestamp` has already elapsed relative to `state.timestamp`, but `ResponseReceipts[commitment]` is still empty at `H1`.
3. At a later Hyperbridge height `H2 > H1`, the relayer legitimately delivers the response; `handleGetResponses()` succeeds and calls `A.onGetResponse(...)`, releasing funds. `_requestCommitments[commitment]` is **not** deleted by this path.
4. Anyone now submits `handleGetRequestTimeouts()` using the proof anchored at the **earlier** height `H1` (still valid: challenge period elapsed, `state.timestamp(H1) > timeout`, and the non-membership proof against `ResponseReceipts` at `H1` still verifies since the receipt wasn't recorded yet at that height).
5. `handleGetRequestTimeouts` passes all its checks (commitment still present, non-membership proof at `H1` valid) and calls `A.onGetTimeout(...)`, triggering the refund/cleanup path a second time on top of the already-executed `onGetResponse` path — a double-settlement of the same GET request.

**Confidence caveat:** I could not fully verify whether any currently shipped `IApp` implementation (e.g. `IntentGatewayV2`/`ExtrinsicIntents`) is presently vulnerable end-to-end, because the intent-gateway's cancel-from-source GET flow uses `timeout: 0` (no timeout), which sidesteps this specific path. The vulnerability is in the generic `IHandlerV2`/`IHost` primitive itself, exploitable by any current or future `IApp` module that dispatches non-zero-timeout GET requests and implements both callbacks as mutually exclusive.

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
