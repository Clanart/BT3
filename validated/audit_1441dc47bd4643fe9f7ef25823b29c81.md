### Title
Secret-dependent table indexing in Straus multiexponentiation leaks FROST nonce/key-share scalars via cache-timing - (File: crypto/multiexp/src/straus.rs)

### Summary
Analogous to ALPINE-CVE-2025-9231 (a timing side channel in scalar multiplication enabling private-key recovery), Serai's "constant-time" `multiexp` is not actually constant-time with respect to its scalar inputs: `straus` performs direct memory indexing into precomputed tables using digits derived from the secret scalar's bits (`tables[s][usize::from(groupings[s][b])]` at `crypto/multiexp/src/straus.rs:43`). `groupings` come from `prep_bits(pairs, window)` over the scalar, so the cache lines touched depend on secret digits. FROST nonce-commitment generation in `crypto/frost/src/nonce.rs` runs secret nonce scalars through `multiexp`, and FROST signing multiplies secret nonces/shares by generator points — operations reachable whenever an unprivileged party causes a message to be signed (public preprocess/sign flow). A co-located or network-measurable cache-timing signal on the table lookups leaks nonce digits; recovered nonces yield the private key share via `s = r + cx`.

### Finding Description
- `multiexp` dispatches to `straus`/`pippenger` for the constant-time path (`crypto/multiexp/src/lib.rs:180-190`).
- `straus` builds per-point tables of size `2^window` and indexes them with `groupings[s][b]`, a chunk of the scalar's little-endian bits (`crypto/multiexp/src/straus.rs:31-44`). No `conditional_select` sweep is used (contrast with `crypto/ed448/src/point.rs:258-266`, which does a constant-time select over the table — showing the correct pattern exists in-tree).
- The same pattern exists in `pippenger` bucket accumulation (`crypto/multiexp/src/pippenger.rs`).
- Secret scalars flow into `multiexp`: nonce commitments in `crypto/frost/src/nonce.rs` compute `nonce * G` per generator via multiexp with the freshly generated secret nonce from `Curve::random_nonce` (`crypto/frost/src/curve/mod.rs:94-121`), and combined nonces `base + rho*actual` feed `sign_share` (`crypto/frost/src/sign.rs:386-398`).

### Impact Explanation
The indexed memory access leaks the scalar digit values through cache/branch-predictor timing. An attacker who can measure signing/preprocess timing (repeatedly supplying messages to be signed) recovers nonce digits; combined with the public signature share `s = d + e·rho + c·x_i`, known nonces expose the FROST secret share `x_i`. This is a key-share-recovery primitive reachable from public signing inputs — the same bug class and severity as CVE-2025-9231.

### Likelihood Explanation
Medium: exploitation requires fine-grained timing (co-residency/flush-reload or very low-noise remote measurement) and many observations, matching the "Moderate" classification upstream. No malicious validator or collusion is required — only the ability to cause signatures.

### Recommendation
Replace direct table indexing in `straus`/`pippenger` (non-vartime variants) with `ConditionallySelectable::conditional_select` sweeps over the tables/buckets, as already done in `crypto/ed448/src/point.rs:258-266`. Alternatively route secret-scalar multiplication through per-scalar `Mul` impls that are constant-time, reserving `multiexp` for public scalars (use `multiexp_vartime` explicitly for verification).

### Proof of Concept
In `straus` (`crypto/multiexp/src/straus.rs:42-44`):
```rust
for s in 0 .. tables.len() {
  res += tables[s][usize::from(groupings[s][b])]; // secret-dependent index
}
```
`groupings[s][b]` is `window` bits of the secret scalar. A cache-timing measurement (e.g., Flush+Reload on the `tables` region, or timing variance over repeated `Curve::random_nonce` → commitment generation in `crypto/frost/src/nonce.rs`) recovers each window digit of the nonce scalar. With `s = r + cx_i` observed on the wire, recovered `r` yields `x_i = (s - r)/c`.
