### Title
Missing Minimum Output Amount Check in `sign_optimistic_payout` Allows Permanent Destruction of Bridged BTC - (File: core/src/verifier.rs)

---

### Summary

`Verifier::sign_optimistic_payout` enforces only an **upper** bound on `output_amount` but no **lower** bound. Any depositor can call the aggregator's `OptimisticPayout` RPC with `output_amount` set to Bitcoin dust (≥ 330 sat), supply a valid Taproot signature committing to that dust amount, and cause all N-of-N verifiers to co-sign the spend of the `MoveToVaultTx` UTXO. The resulting transaction consumes the full `bridge_amount` (e.g. 10 BTC) from the vault UTXO while paying the user only dust; the remainder is irrecoverably paid to miners as fees. Neither the aggregator nor the verifier enforces a floor on the payout amount.

---

### Finding Description

**Affected code – upper-bound-only check in `sign_optimistic_payout`:**

```rust
// core/src/verifier.rs  lines 1634-1644
// amount in move_tx is exactly the bridge amount
if output_amount
    > self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
{
    return Err(eyre::eyre!(
        "Output amount is greater than the bridge amount: {} > {}",
        output_amount,
        self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
    ).into());
}
``` [1](#0-0) 

`output_amount = 0` or any dust value passes this guard without error. There is no corresponding lower-bound check anywhere in the function.

**Aggregator entry point also lacks a floor check:**

```rust
// core/src/rpc/aggregator.rs  lines 1024-1126
let (deposit_id, input_signature, input_outpoint, output_script_pubkey, output_amount) =
    parser::operator::parse_withdrawal_sig_params(withdraw_params)?;
// ... UTXO spent check, script-type check, UTXO match check ...
SECP.verify_schnorr(&input_signature.signature, &message, &user_xonly_pk)
    .map_err(|_| Status::internal("Invalid signature for optimistic payout tx. ..."))?;
// No minimum output_amount check before forwarding to verifiers
``` [2](#0-1) 

**Transaction structure that makes the loss permanent:**

`create_optimistic_payout_txhandler` builds a transaction with two inputs and two outputs:

| # | Input | Value |
|---|-------|-------|
| 0 | User's withdrawal UTXO | ~330 sat (dust) |
| 1 | `MoveToVaultTx` UTXO (`UtxoVout::DepositInMove`) | `bridge_amount` (e.g. 1 000 000 000 sat) |

| # | Output | Value |
|---|--------|-------|
| 0 | User payout | `output_amount` (unchecked floor) |
| 1 | Non-ephemeral anchor | 240 sat | [3](#0-2) 

When `output_amount` is dust, the entire `bridge_amount` minus dust and anchor is paid to miners as transaction fees. The `MoveToVaultTx` UTXO is spent and cannot be reclaimed.

---

### Impact Explanation

A depositor who has completed the peg-in flow (move_tx confirmed, Citrea deposit recorded) can permanently destroy their own bridged BTC — and, critically, the bridge-controlled vault UTXO — by submitting an optimistic payout request with `output_amount = MIN_TAPROOT_AMOUNT` (330 sat). The vault UTXO holding `bridge_amount` (regtest default: 10 BTC) is irrecoverably consumed. The operator can never be reimbursed for this deposit because the move_tx output is already spent; the reimbursement transaction `create_reimburse_txhandler` requires `UtxoVout::DepositInMove` as its first input. [4](#0-3) 

This satisfies the allowed impact gate: **permanent loss of bridge-controlled UTXOs and bridged BTC**.

---

### Likelihood Explanation

The `ClementineAggregator/OptimisticPayout` gRPC endpoint is the public-facing entry point for withdrawals. Any party that has completed a deposit and holds the withdrawal UTXO key can call it. The `aggregator_verification_address` guard on the verifier side is **optional** (config field, defaults absent); when unset the verifier applies no caller authentication beyond mTLS, and the aggregator itself is the mTLS peer that forwards the user-supplied `output_amount` verbatim. [5](#0-4) 

The user's Taproot signature is verified by the aggregator against the sighash of the constructed payout tx, which commits to `output_amount`. A user who deliberately (griefing) or accidentally (wallet bug) signs with `output_amount = 330 sat` produces a valid signature that passes all existing checks.

---

### Recommendation

Add a lower-bound check in `sign_optimistic_payout` before the existing upper-bound check:

```rust
// core/src/verifier.rs – inside sign_optimistic_payout
if output_amount < MIN_TAPROOT_AMOUNT {
    return Err(eyre::eyre!(
        "Output amount {} is below minimum allowed {}",
        output_amount,
        MIN_TAPROOT_AMOUNT
    ).into());
}
```

Apply the same guard in the aggregator's `optimistic_payout` handler (before building the tx handler) so the error is surfaced early:

```rust
// core/src/rpc/aggregator.rs – inside optimistic_payout
if output_amount < Amount::from_sat(MIN_TAPROOT_AMOUNT.to_sat()) {
    return Err(Status::invalid_argument(format!(
        "output_amount {} is below minimum {}", output_amount, MIN_TAPROOT_AMOUNT
    )));
}
```

A stricter bound — e.g. requiring `output_amount >= bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT - max_acceptable_fee` — would further limit the fee-drain surface.

---

### Proof of Concept

1. Complete a standard deposit; `move_txid` is recorded in the DB and on Citrea.
2. Construct an optimistic payout transaction locally with `output_amount = 330 sat` (dust minimum for a Taproot output) and sign input 0 (the withdrawal UTXO) with `SIGHASH_SINGLE | ANYONECANPAY`.
3. Call `ClementineAggregator/OptimisticPayout` with this request.
4. Aggregator builds the tx with `output_amount = 330 sat`, computes the sighash, and verifies the user's signature — **passes** (signature commits to 330 sat output).
5. Aggregator calls `ClementineVerifier/OptimisticPayoutSign` on all N verifiers, forwarding `output_amount = 330 sat`.
6. Each verifier executes `sign_optimistic_payout`:
   - `330 sat <= bridge_amount - 240 sat` → upper-bound check **passes**
   - No lower-bound check exists → proceeds to sign
7. Aggregator aggregates partial signatures, sets the script-spend witness on input 1 (the `MoveToVaultTx` UTXO), and broadcasts the transaction.
8. Bitcoin miners confirm the transaction: `bridge_amount - 330 - 240 ≈ 9.9999997 BTC` is paid as fees; the vault UTXO is permanently spent; the user receives 330 sat. [6](#0-5) [7](#0-6)

        output_script_pubkey: ScriptBuf,
        output_amount: Amount,
        verification_signature: Option<PrimitiveSignature>,

        if self.rpc.is_utxo_spent(&input_outpoint).await? {
            return Err(
                eyre::eyre!("Withdrawal utxo {:?} is already spent", input_outpoint).into(),

        }

            || output_script_pubkey.is_p2sh()
            || output_script_pubkey.is_p2wpkh()
            || output_script_pubkey.is_p2wsh())
        {
            return Err(eyre::eyre!(format!(
                "Output script pubkey is not a valid script pubkey: {}, must be p2tr, p2pkh, p2sh, p2wpkh, or p2wsh",
                output_script_pubkey
            )).into());
        }

        // if verification address is set in config, check if verification signature is valid
        if let Some(address_in_config) = self.config.aggregator_verification_address {
            // check if verification signature is provided by aggregator
            if let Some(verification_signature) = verification_signature {

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_optimistic_payout_txhandler(
    deposit_data: &mut DepositData,
    input_utxo: UTXO,
    output_txout: TxOut,
    user_sig: taproot::Signature,
    paramset: &'static ProtocolParamset,
) -> Result<TxHandler, BridgeError> {
    let move_txhandler: TxHandler = create_move_to_vault_txhandler(deposit_data, paramset)?;
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::NotStored,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::non_ephemeral_anchor_output(),
        ))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    Ok(txhandler)
}
