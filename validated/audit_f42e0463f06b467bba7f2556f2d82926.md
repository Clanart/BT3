## Analysis

The Sherlock finding concerns an owner-controlled fee setter (`OptionsConfig.setMinFee`) that has no upper/lower bound, letting the privileged party impose arbitrary (unbounded) fees on users. The closest reachable analog in kaia is the KIP-71 base-fee governance parameters, `kip71.lowerboundbasefee` and `kip71.upperboundbasefee`, which directly determine the mandatory `baseFee` that every transaction must pay to be included in a block.

### Title
Governance can set KIP-71 base fee bounds to unbounded/extreme values, forcing arbitrary tx fees - ([File: kaiax/gov/param.go], [File: kaiax/gov/headergov/impl/header.go], [File: params/kip71_config.go])

### Summary
The governance parameters `kip71.lowerboundbasefee` and `kip71.upperboundbasefee`, which bound the network's dynamically-computed `baseFee` (the price every transaction must pay per unit gas post-Magma), are validated only by a `noopFormatChecker` — i.e., no absolute range/sanity check is enforced on their values.

### Finding Description
Both `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` are declared with `FormatChecker: noopFormatChecker`, meaning any `uint64` value is accepted as format-valid [1](#0-0) .

The only additional validation is a *relative* consistency check performed when the vote is committed to a block header: a new `LowerBoundBaseFee` must not exceed the currently effective `UpperBoundBaseFee`, and vice versa [2](#0-1) . There is no absolute ceiling — the governing node can, over two separate votes, first raise `UpperBoundBaseFee` to `2^64-1` and then raise `LowerBoundBaseFee` to match it, since each vote is only checked against the *other* bound's current value, not against any hardcoded sane maximum.

Once both bounds are pinned to an extreme value, `NextMagmaBlockBaseFee` computes and clamps the block's `baseFee` to lie within `[LowerBoundBaseFee, UpperBoundBaseFee]` [3](#0-2) . The transaction pool then rejects any transaction whose `gasPrice`/`gasFeeCap` is below this `baseFee` [4](#0-3) .

This mirrors the original report's root cause precisely: a governance-controlled fee parameter with no upper/lower sanity bound, allowing the controlling party to force arbitrarily high transaction fees on all users.

### Impact Explanation
If the governing node (single-governance mode owner) sets both KIP-71 bounds to an extreme value, the effective `baseFee` for every future block becomes pinned at that value. All senders — regular tx senders, contract deployers, gasless/fee-delegation payers — would be forced to pay an arbitrarily large fee per unit of gas to have any transaction included, or transactions become effectively unincludable due to unaffordable fees. This is a direct, permanent fee-abuse condition imposed on the entire network with no in-protocol cap.

### Likelihood Explanation
This requires control of governance voting (the governing node in single mode), which is the same privilege level as the "owner" role in the original Sherlock finding. Given the parameter has no format-level bound check and the consistency check is only relative between the two bounds (not absolute), a governing node acting maliciously or erroneously can reach this state in two sequential votes.

### Recommendation
Add an absolute `FormatChecker` for `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` (e.g., enforce a maximum reasonable ceiling and a sane minimum), in addition to the existing relative consistency check in `checkConsistency`.

### Proof of Concept
1. Governing node submits a vote to set `kip71.upperboundbasefee` to `2^64-1` (accepted: `noopFormatChecker` passes, and the consistency check in `checkConsistency` for `Kip71UpperBoundBaseFee` only requires it be `>= current LowerBoundBaseFee`) [5](#0-4) .
2. Governing node then submits a vote to set `kip71.lowerboundbasefee` to the same extreme value (accepted: only checked against `UpperBoundBaseFee`, which was already raised) [6](#0-5) .
3. Once both bounds take effect, `NextMagmaBlockBaseFee` clamps the block `baseFee` to this extreme value for all subsequent blocks [7](#0-6) .
4. All transactions in the tx pool are rejected unless `gasPrice`/`gasFeeCap` meets this extreme `baseFee` [8](#0-7) .

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}
