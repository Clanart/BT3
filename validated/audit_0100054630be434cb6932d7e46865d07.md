### Title
Payout attribution (`payout_payer_operator_xonly_pk`) is derived from an unauthenticated, malleable OP_RETURN output, allowing a misattributed operator reimbursement - ([File: core/src/verifier.rs])

### Summary
The bridge credits an operator for having "fronted" a user withdrawal purely by parsing the OP_RETURN output of the confirmed payout transaction. That OP_RETURN output is **not** committed to by any signature that only the credited operator could produce, so the identity written into it is fully attacker-controlled, breaking the binding "operator credited == party that actually funded the payout" — the same class of missing-ownership/authorization check as the CryptoPunks bug, where a seller's private-sale data was trusted without verifying the seller actually held the asset being transferred.

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
1. Input 0: the user's withdrawal UTXO, spent with `user_sig` using a `SinglePlusAnyoneCanPay` sighash.
2. Output 0: the user's payout (committed by the SIGHASH_SINGLE portion of `user_sig`).
3. Output 2: an OP_RETURN containing the fronting operator's x-only pubkey. [1](#0-0) 

Because the sighash type is `SIGHASH_SINGLE | ANYONECANPAY`, `user_sig` only commits to input 0 and output 0 — it commits to **nothing** about which additional funding inputs are used or what value is written into the OP_RETURN operator-attribution output. Any party that obtains this reusable, unconfirmed witness (per the design comment, it is "given to operators off-chain" but nothing cryptographically restricts its use to a specific operator) can assemble their own payout transaction, fund it from their own wallet, and write **any** operator's x-only public key into the OP_RETURN field before broadcasting it.

Downstream, `update_finalized_payouts` in the verifier trusts this field verbatim to determine who gets credited for the payout: [2](#0-1) 

This value is persisted as `payout_payer_operator_xonly_pk` and is the sole basis used later to authorize reimbursement:
- `get_first_unhandled_payout_by_operator_xonly_pk` selects unhandled payouts strictly by this stored pubkey. [3](#0-2) 
- `validate_payer_is_operator` / `handle_finalized_payout` gate the entire kickoff/reimbursement flow on this same stored value matching the operator's own key — there is no independent check that the named operator's own funds were actually used to pay the withdrawal. [4](#0-3) 
- `is_kickoff_malicious` only checks that the operator sending the kickoff equals the OP_RETURN-derived pubkey — again trusting the same unauthenticated field, not the actual funding source. [5](#0-4) 

At no point in this flow is there a check equivalent to `cryptoPunkContract.punkIndexToAddress(tokenId) == item.sellerAddress` — i.e., a check that the entity named in the OP_RETURN (the party to be credited/reimbursed) is cryptographically tied to the party that actually supplied the funding inputs of the payout transaction.

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding. An operator can be credited with fronting a withdrawal it never funded (because a third party who obtained the reusable `SIGHASH_SINGLE|ANYONECANPAY` witness broadcast the actual funding transaction but stamped a different operator's pubkey into the OP_RETURN). That falsely credited operator's automation (`PayoutCheckerTask`) will pick up the "unhandled payout" as its own, spend its own collateral to run the kickoff/reimbursement pipeline, and ultimately receive the vault UTXO's bridge funds via the `Reimburse` transaction — reimbursement for BTC it never actually sent to the user. This matches the Critical-impact category "an operator reimbursed for a payout it never funded."

### Likelihood Explanation
Exploitation requires only possession of the reusable withdrawal signature (not any protocol role or key compromise), since the sighash type used for the user's input explicitly excludes commitment to the OP_RETURN output and to any additional funding inputs. No verifier, operator, or aggregator privilege is needed to construct and broadcast such a transaction once the signature is known/observed.

### Recommendation
Bind the operator-attribution output to the actual funding party. For example, require the operator's own signature over the whole payout transaction (including the OP_RETURN output) using a sighash mode that commits to all inputs/outputs (e.g., SIGHASH_ALL for the funding inputs already achieves this for those inputs, but the protocol must additionally verify — at DB-ingestion time in `update_finalized_payouts` / at kickoff-validation time in `is_kickoff_malicious` — that the funding inputs of the confirmed payout transaction are provably controlled by the xonly pubkey declared in the OP_RETURN, e.g. by checking that at least one input's script/witness cryptographically resolves to that same operator key, analogous to checking `punkIndexToAddress(tokenId) == item.sellerAddress` before trusting a claimed transfer.

### Proof of Concept
1. Party E (any entity that obtains the user's withdrawal signature, e.g. by observing it in a submitted-but-unconfirmed transaction, since `user_sig` uses `SIGHASH_SINGLE|ANYONECANPAY`) builds a new transaction spending the same withdrawal UTXO with `input[0]` witness = the observed `user_sig`.
2. E adds its own funding input(s) sufficient to pay `output[0]` (the required user payout, fixed by the SIGHASH_SINGLE commitment) and constructs `output[2]` OP_RETURN with operator O's x-only pubkey (O being any currently registered operator, not E).
3. E signs its own added inputs and broadcasts; the transaction confirms.
4. `update_finalized_payouts` parses OP_RETURN, sets `withdrawals.payout_payer_operator_xonly_pk = O`. [6](#0-5) 
5. Operator O's `PayoutCheckerTask` retrieves this as its own unhandled payout via `get_first_unhandled_payout_by_operator_xonly_pk` and proceeds through `handle_finalized_payout` / kickoff / reimburse, ultimately receiving the vault funds for a withdrawal it never funded. [7](#0-6)

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
