### Title
Operator collateral UTXO silently consumed as fee input during `Operator::withdraw()` payout funding — (`core/src/operator.rs`)

### Summary
`Operator::withdraw()` funds the payout transaction by delegating to Bitcoin Core's `fund_raw_transaction` with `add_inputs: true` and no exclusion of the collateral UTXO. When the operator's Bitcoin Core wallet holds no other spendable UTXOs, coin-selection picks the collateral UTXO as a fee input, spending it outside the protocol's round-tx chain. The state machine then treats this as an operator exit, permanently blocking the operator from advancing rounds or recovering the BTC they already paid out.

### Finding Description

In `core/src/operator.rs`, `Operator::withdraw()` calls `fund_raw_transaction` with `add_inputs: Some(true)` and no locked outpoints or exclusion list: [1](#0-0) 

The operator's collateral UTXO lives at `signer.address` — a plain taproot key-path address that is fully tracked by the Bitcoin Core wallet, because the collateral is funded directly from that wallet via `rpc.send_to_address(&signer.address, ...)`: [2](#0-1) 

Bitcoin Core's coin selection is therefore free to pick the collateral UTXO to cover the payout transaction's fee. There is no guard in `withdraw()` to prevent this.

The asymmetry with `transfer_outpoints_to_wallet()` is the clearest evidence of the missing guard: that function explicitly enumerates all collateral outpoints via `get_all_collateral_outpoints()` and rejects any request that would spend them: [3](#0-2) 

No equivalent protection exists in `withdraw()`.

The collateral UTXO is the root of the entire round-tx chain. The state machine watches for it being spent outside the expected round transaction via a `SpentUtxoButNotTxid` matcher: [4](#0-3) 

If the collateral is consumed as a fee input, this matcher fires `RoundEvent::OperatorExit`, permanently removing the operator from the protocol.

### Impact Explanation

- The operator's collateral UTXO is spent outside the protocol's round-tx chain by Bitcoin Core's automatic coin selection.
- The state machine fires `RoundEvent::OperatorExit`, blocking the operator from sending any further round, kickoff, or reimburse transactions.
- The operator has already paid out the user's `bridge_amount` (e.g., 0.1 BTC) via the payout transaction. Without the ability to send the kickoff and reimburse transactions, the operator permanently loses that fronted BTC.
- All pending deposits assigned to this operator become unreimbursable, locking the corresponding vault UTXOs.
- This satisfies the allowed impact gate: permanent loss of operator collateral and reimbursement outputs.

### Likelihood Explanation

- Triggered whenever the operator's Bitcoin Core wallet has no spendable UTXOs other than the collateral UTXO.
- This is realistic for a freshly initialized operator (collateral is the first and only UTXO funded to the operator's address) or one whose wallet UTXOs have been depleted by prior fee payments.
- No privileged access is required. Any user submitting a valid withdrawal request to the operator's `Withdraw` RPC endpoint can trigger this path.

### Recommendation

1. Before calling `fund_raw_transaction`, lock the collateral UTXO using Bitcoin Core's `lockunspent(false, [collateral_outpoint])` RPC so coin selection skips it. Unlock it after the call.
2. Alternatively, apply the same `get_all_collateral_outpoints()` check used in `transfer_outpoints_to_wallet()` before calling `fund_raw_transaction`, and pass the collateral outpoints as explicit exclusions or pre-lock them.
3. Consider maintaining a dedicated fee-payment wallet address separate from the operator's protocol address (`signer.address`) so the collateral UTXO is never eligible for coin selection.

### Proof of Concept

1. Initialize an operator whose Bitcoin Core wallet contains only the collateral UTXO (e.g., 0.2 BTC at `signer.address`) and no other spendable UTXOs.
2. A user submits a valid withdrawal request via the `Withdraw` gRPC endpoint.
3. `Operator::withdraw()` constructs the payout transaction and calls `fund_raw_transaction` with `add_inputs: Some(true)`.
4. Bitcoin Core's coin selection, finding no other UTXOs, selects the collateral UTXO as the fee input. Change is returned to a new wallet address.
5. The payout transaction is signed and broadcast with the collateral UTXO as an input.
6. The collateral UTXO is now spent by a transaction whose txid is not the expected round transaction txid.
7. The `SpentUtxoButNotTxid` matcher in `states/round.rs` fires `RoundEvent::OperatorExit`.
8. The operator is permanently removed from the protocol. The kickoff and reimburse transactions can never be sent.
9. The operator has lost the `bridge_amount` they fronted for the withdrawal, with no path to recovery.
