### Title
Duplicate `withdrawal_utxo` bytes across two Citrea withdrawal indices let one Bitcoin payout be double-counted, causing two `kickoff_txid`s / two Reimburse claims for one fronted payment - ([File: core/src/database/verifier.rs])

### Summary
`Database::get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` solely on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, with no uniqueness guarantee that a given UTXO is registered for only one `withdrawals.idx`. If an attacker registers the same `withdrawal_utxo` bytes for two different Citrea withdrawal indices via `withdraw()`, one real Bitcoin spend of that UTXO is joined against both `withdrawals` rows, so `update_payout_txs_and_payer_operator_xonly_pk` writes the identical `payout_txid` into two distinct `idx` rows. `PayoutCheckerTask::run_once` then processes each row independently across successive polls, calling `handle_finalized_payout` and `mark_payout_handled` twice for the same underlying BTC payment.

### Finding Description
Binding claimed: `count(DISTINCT kickoff_txid marked handled for a single fronted payout_txid) == 1`.

Path:
1. An attacker (any Citrea user) makes two deposits and calls `withdraw()`/`safeWithdraw()` on the Citrea Bridge contract twice, specifying the exact same `(txid, vout)` as the withdrawal UTXO bytes for two different withdrawal indices. Nothing in this repo's client code (`CitreaClientT::collect_withdrawal_utxos`, `core/src/citrea.rs:458-497`) or the verifier ingestion path (`update_withdrawal_utxo_from_citrea_withdrawal`, `core/src/database/verifier.rs:108-135`) rejects or deduplicates repeated UTXO bytes across indices.
2. Both `withdrawals` rows (`idx1`, `idx2`) end up with identical `withdrawal_utxo_txid`/`withdrawal_utxo_vout`.
3. The operator fronts a payout that spends the shared UTXO once. `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) calls `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`), whose join condition `bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout` matches the single `bitcoin_syncer_spent_utxos` row against both `withdrawals` rows, returning `(idx1, payout_txid)` and `(idx2, payout_txid)`.
4. `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`) writes the same `payout_txid`/`payout_payer_operator_xonly_pk`/`payout_tx_blockhash` into both rows.
5. `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-111`) calls `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`), which returns rows one at a time (`LIMIT 1`, `ORDER BY idx ASC`), unaware they share a `payout_txid`. On the first poll it processes `idx1`: calls `Operator::handle_finalized_payout` for `idx1`'s deposit outpoint, producing `kickoff_txid1`, and marks it handled via `Database::mark_payout_handled` (`core/src/database/verifier.rs:348-362`). On the next poll cycle it finds `idx2` still unhandled (different deposit, same `payout_txid`), calls `handle_finalized_payout` for `idx2`'s deposit outpoint, producing a distinct `kickoff_txid2`, and marks that handled too.
6. No existing guard intervenes: `is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`) only checks that the payout's OP_RETURN operator matches the kickoff and that the committed blockhash matches — it does not check whether the same `payout_txid`/UTXO already funded a different deposit's kickoff. `get_handled_payout_kickoff_txid` uses `fetch_optional`, which is a query bug's downstream symptom, not a preventive constraint, and nothing before the write path enforces `payout_txid` (or `withdrawal_utxo`) uniqueness across `idx` values (no such constraint in `core/src/database/schema.sql`).

### Impact Explanation
Two `kickoff_txid`s get marked handled (`is_payout_handled = TRUE`, distinct `kickoff_txid`) for the same underlying `payout_txid`, each tied to a different deposit's presigned transaction graph. Each kickoff can proceed through `ReadyToReimburse` → `Reimburse`, releasing the operator's collateral for both deposit slots even though only one deposit's withdrawer actually received a fronted BTC payout. This matches the Critical category "an operator reimbursed for a payout it never funded": the operator's collateral for the second deposit slot is freed without that deposit's withdrawal ever being separately serviced, while the second withdrawer's deposited BTC is never returned to them. The blast radius scales with however many withdrawal indices an attacker chooses to alias to the same UTXO, and is repeatable across deposits/operators since it only depends on attacker-controlled withdrawal UTXO bytes, not on any specific operator or deposit.

### Likelihood Explanation
The only precondition is that Citrea's `withdraw()`/`safeWithdraw()` accepts the same UTXO bytes for two distinct withdrawal indices (an unprivileged, permissionless call the attacker can make directly, per the granted capability to "choose the bytes of a withdrawal UTXO"), and that the attacker fund two real deposits to obtain two withdrawal slots. No verifier/operator/aggregator privilege, key share, or majority hashrate is required, and the cost is just two deposit amounts plus fees, one of which the attacker forfeits to demonstrate the DB conflation (or which an operator could quietly exploit against itself for free). The bug is deterministic given the described state, not probabilistic.

### Recommendation
Enforce a 1:1 mapping between a withdrawal UTXO and a withdrawal index before honoring it as a payout signal: add a uniqueness constraint (or explicit validation) rejecting/ignoring a `withdrawal_utxo` that is already registered against a different `idx`, and change `get_payout_txs_for_withdrawal_utxos`/`update_payout_txs_and_payer_operator_xonly_pk` to only attribute a spent UTXO to a single `withdrawals.idx` (e.g., require `payout_txid` to be unique across `idx`, or select only the first-registered `idx` for a given UTXO and mark any duplicate registration as invalid instead of writing a payout for it).

#[tokio::test]
async fn duplicate_withdrawal_utxo_causes_double_payout_attribution() {
    let db = /* test db */;
    let operator_xonly_pk = /* generate */;
    let shared_utxo = OutPoint { txid: Txid::from_byte_array([0xAA; 32]), vout: 0 };
    let payout_txid = Txid::from_byte_array([0xBB; 32]);
    let block_hash = BlockHash::all_zeros();

    // Seed two distinct deposits/withdrawal rows (idx1, idx2) with
    // identical withdrawal_utxo_txid/vout, simulating attacker-chosen
    // duplicate UTXO bytes across two withdraw() calls.
    // ... insert idx1 with move_to_vault_txid1, withdrawal_utxo = shared_utxo
    // ... insert idx2 with move_to_vault_txid2, withdrawal_utxo = shared_utxo
    // ... record one bitcoin_syncer_spent_utxos row for shared_utxo -> payout_txid

    let payouts = db.get_payout_txs_for_withdrawal_utxos(None, block_id).await.unwrap();
    // ASSERT the bug: both idx1 and idx2 appear for the single spend
    assert_eq!(payouts.len(), 2);

    db.update_payout_txs_and_payer_operator_xonly_pk(
        None,
        vec![(idx1, payout_txid, Some(operator_xonly_pk), block_hash),
             (idx2, payout_txid, Some(operator_xonly_pk), block_hash)],
    ).await.unwrap();

    // Simulate two PayoutCheckerTask::run_once cycles (or call
    // mark_payout_handled directly for both idx after handle_finalized_payout).
    db.mark_payout_handled(None, idx1, kickoff_txid1).await.unwrap();
    db.mark_payout_handled(None, idx2, kickoff_txid2).await.unwrap();

    // Binding check: exactly one kickoff_txid should ever be handled
    // for payout_txid, but we observe two distinct rows.
    let rows = sqlx::query_as::<_, (i32, Option<TxidDB>)>(
        "SELECT idx, kickoff_txid FROM withdrawals WHERE payout_txid = $1 AND is_payout_handled = TRUE"
    )
    .bind(TxidDB(payout_txid))
    .fetch_all(&db.connection)
    .await
    .unwrap();
    assert_eq!(rows.len(), 2); // FAILS the binding: should be 1
    assert_ne!(rows[0].1, rows[1].1); // two distinct kickoff_txids for one payout
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }
