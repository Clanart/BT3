## Analysis

The iExec bug's core invariant break: **a value that reflects "trust already spent" can be silently restored to a stale, higher value after the spending has already happened**, and there is no reconciliation between the "spend" event and the later "restore" event.

The closest local analog in Hyperbridge is in `pallet-consensus-incentives`, which pays relayers `$BRIDGE` **and mints reputation** immediately when a consensus proof is accepted, based on the block-height span of the update — before any fraud-detection/veto mechanism has a chance to run, and with no clawback path if the underlying state commitment is later proven fraudulent and reverted.

### The mechanics

`Pallet::store_latest_commitment_height` in `modules/pallets/ismp/src/host.rs` updates `LatestStateMachineHeight` on every accepted consensus message: [1](#0-0) 

`pallet-consensus-incentives::process_message` reads that height and immediately transfers treasury funds and mints reputation to the relayer, then advances the `LastRewardedHeight` watermark: [2](#0-1) 

If the accepted state commitment is later found fraudulent and vetoed, `delete_state_commitment` rolls `LatestStateMachineHeight` back to `PreviousStateMachineHeight`: [3](#0-2) 

Critically, this veto path only touches `LatestStateMachineHeight`/`PreviousStateMachineHeight` in `pallet-ismp` storage — it never touches `LastRewardedHeight` in `pallet-consensus-incentives`, and there is no mechanism anywhere in the codebase that claws back the `$BRIDGE` transfer or burns the minted reputation that was already paid out for the (now-reverted) fraudulent height jump.

### Title
Consensus-incentive rewards and reputation are paid out on fraudulent height jumps before veto, with no clawback on `delete_state_commitment` - (File: `modules/pallets/ismp/src/host.rs`, `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
A relayer can submit a consensus proof that advances a state machine's height by a large span (real dispute/fraud scenario), be paid `$BRIDGE` and minted equivalent reputation for the entire span immediately, and keep both even after the state commitment is later vetoed as fraudulent via `IsmpHost::delete_state_commitment`.

### Finding Description
`pallet-consensus-incentives::calculate_reward` pays `(latest_height - baseline) * cost_per_block` the moment a `ConsensusMessage` is processed, sourcing `latest_height` from `IsmpHost::latest_commitment_height`, which is whatever height the just-processed message wrote via `store_latest_commitment_height` [4](#0-3) . Reward transfer and 1:1 reputation minting happen unconditionally in the same call [5](#0-4) , before any challenge-period or fraud-proof window has resolved the correctness of that update.

`delete_state_commitment` exists specifically to walk back a state commitment that is later found bad ("vetoed"), resetting `LatestStateMachineHeight` back to `PreviousStateMachineHeight` [6](#0-5) . This function has no awareness of, and never touches, `pallet-consensus-incentives::LastRewardedHeight`, the `$BRIDGE` treasury balance, or the `ReputationAsset` balance already minted to the relayer who submitted the (now-reverted) update.

The watermark comment even documents the one-directional, non-reconciling nature of the mechanism: "Rewards only ever cover the span above this watermark" [7](#0-6) . It correctly prevents double-payment for the same span, but it does not prevent payment for a span that turns out to be fraudulent, nor does it recover any funds/reputation after the fact.

### Impact Explanation
Reputation minted here is not cosmetic — it is soulbound but directly determines collator selection: "It ranks the remaining candidates from highest to lowest based on their Controller's Reputation Asset balance" [8](#0-7) . An attacker who gets a large, fraudulent height-jump accepted (even if later vetoed) walks away with real `$BRIDGE` from the treasury and a permanent, un-clawed-back reputation credit that can push them into the collator set — a direct "unauthorized/incorrect fund transfer" plus a governance-adjacent privilege escalation (collator selection) built on a state update that the protocol itself later disowns as false.

### Likelihood Explanation
Likelihood depends on how easy it is to get a fraudulent/large height jump accepted long enough to trigger `on_executed` before it is vetoed — this requires either a consensus-client bug, a compromised/misbehaving validator set on the source chain, or a race against the fisherman/veto window, which are the kinds of "malicious peer/relayer/prover" assumptions this review is instructed to discard as sole preconditions. However, the underlying protocol *design* explicitly anticipates that accepted state commitments can later be vetoed (`delete_state_commitment` exists for exactly this purpose), which means the reward/reputation payout path was never hardened against that documented possibility — this is a structural, code-level gap rather than a hypothetical.

### Recommendation
- Gate `pallet-consensus-incentives` payouts behind the chain's configured challenge period, or defer reward/reputation issuance until the corresponding state commitment has survived its veto window.
- Extend `delete_state_commitment` (or add a hook it calls) to also roll back `LastRewardedHeight`, claw back the `$BRIDGE` transfer where possible, and burn the reputation minted for the vetoed span.
- At minimum, emit an event on veto correlating the reverted height range with any `RelayerRewarded` event so off-chain tooling/governance can manually claw back funds and reputation.

### Proof of Concept
1. Relayer submits a `ConsensusMessage` that advances `StateMachineId::X` from height `H0` to a large `H1` (e.g., via a since-patched consensus-client bug or a source-chain reorg/equivocation not yet caught).
2. `store_latest_commitment_height` sets `LatestStateMachineHeight(X) = H1`, `PreviousStateMachineHeight(X) = H0`.
3. In the same extrinsic, `pallet-consensus-incentives::on_executed` → `process_message` → `calculate_reward` computes `reward = (H1 - baseline) * cost_per_block` and transfers it from treasury to the relayer, then mints the same amount of `ReputationAsset`, and sets `LastRewardedHeight(X) = H1`.
4. Governance/fisherman later determines the update was fraudulent and calls the veto path, which invokes `delete_state_commitment`, resetting `LatestStateMachineHeight(X)` back to `H0`.
5. `LastRewardedHeight(X)` remains `H1`; the relayer's `$BRIDGE` balance and `ReputationAsset` balance from step 3 are never reversed. The relayer keeps funds and reputation earned for a state update the protocol itself has just disowned, and honest relayers who later resubmit the correct chain of updates up to `H1` are never paid for that already-"claimed" span.

	fn delete_state_commitment(&self, height: StateMachineHeight) -> Result<(), Error> {
		// The height's entry in the state commitment queue is deliberately left
		// behind; locating it would mean scanning the queue, which is the per-insert
		// cost the queue exists to avoid. Usually its eviction is a no-op, but when
		// the vetoed height is the latest the reset below re-opens it for honest
		// resubmission, and the resubmitted height gets a *second* queue entry. The
		// stale entry then evicts the live commitment when it reaches the head —
		// one insertion before the live entry would have, since the resubmission
		// lands directly behind its stale twin. So a veto costs that height one
		// insertion of retention and permanently burns one queue slot. Both are
		// negligible against the configured caps; making it exact would need a
		// height -> index map on the insert path.
		BoundedStateCommitments::<T>::remove(height.id, height.height);
		BoundedStateMachineUpdateTime::<T>::remove(height.id, height.height);

		// technically any state commitment can be vetoed,
		// safety check that it's the latest before resetting it.
		if let Some(latest) = LatestStateMachineHeight::<T>::get(height.id) {
			if latest == height.height {
				// Reset back to the initial height to allow for honest updates
				let prev_height =
					PreviousStateMachineHeight::<T>::get(height.id).ok_or_else(|| {
						Error::Custom("Previous state machine height should exist".to_string())
					})?;
				LatestStateMachineHeight::<T>::insert(height.id, prev_height);
			}
		}
		Ok(())
	}

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
