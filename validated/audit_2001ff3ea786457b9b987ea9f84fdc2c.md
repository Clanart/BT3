### Title
Distribution Precompile's `rewards()` View Method Lacks a Non-Payable Check, Permanently Stranding Any ETH/usei Sent With the Call - (File: precompiles/distribution/distribution.go)

### Summary
The `distribution` precompile's `rewards(address)` view method is dispatched without the `pcommon.ValidateNonPayable(value)` guard that every other read-only method in the same precompile enforces, so a caller who attaches `msg.value` to a `rewards()` call has that value irreversibly debited from their EVM balance with no way to recover it, since `rewards()` never forwards the payment via `HandlePaymentUsei`/`HandlePaymentUseiWei` and the precompile exposes no compensating withdrawal path.

### Finding Description
In `PrecompileExecutor.Execute`, most view/query methods (`ParamsMethod`, `ValidatorOutstandingRewardsMethod`, `ValidatorCommissionMethod`, `ValidatorSlashesMethod`, `DelegationRewardsMethod`, `DelegatorValidatorsMethod`, `DelegatorWithdrawAddressMethod`, `CommunityPoolMethod`) are invoked while relying on the caller to reject non-zero value where needed, and state-mutating methods like `WithdrawValidatorCommissionMethod` explicitly call `pcommon.ValidateNonPayable(value)` before executing: [1](#0-0) 

`RewardsMethod`, however, is dispatched straight to `p.rewards(ctx, method, args)` with no non-payable check and, critically, the `value` argument is not even threaded into the `rewards` handler: [2](#0-1) 

The `rewards` implementation itself only queries `DelegationTotalRewards` and packs the response; it never touches `value`, never calls `HandlePaymentUsei`/`HandlePaymentUseiWei`, and never refunds anything to the caller: [3](#0-2) 

This exact gap is called out by the project's own integration-test documentation for the `distribution` precompile, which explicitly states the guard omission and its consequence: [4](#0-3) 

Since the standard EVM `Call` opcode path performs the `value` balance transfer from caller to callee (the precompile address) unconditionally before invoking the precompile's `Run`/`Execute` logic — this is inherited go-ethereum semantics used throughout Sei's EVM precompile framework, exactly analogous to how `HandlePaymentUsei` in every payable precompile method has to explicitly "refund payer" the debited value before applying it to a Cosmos-side action — any wei sent to `rewards()` is debited from the caller and credited to the distribution precompile address `0x...1007` in the EVM state, but the distribution precompile has no code path (transaction or otherwise) that reads, forwards, or refunds a balance sitting at its own precompile address. Note that `0x...1007` (distribution) is also not registered in the `payablePrecompiles` allow-list that other genuinely payable precompiles (`bank`, `staking`, `gov`, `wasmd`) use, reinforcing that value was never intended to land there and no sweep/withdraw mechanism exists for it: [5](#0-4) 

This mirrors the reported Optimism issue precisely: a payable entry point that accepts and irreversibly retains funds with no recovery function, reachable directly by any unprivileged EVM caller.

### Impact Explanation
Any address (association not even required, since `rewards()` takes the delegator address as an explicit argument and doesn't require the caller to be associated) can send arbitrary `usei`/`wei` value on a call to `rewards()` and have those funds permanently and irrecoverably locked at the precompile address, with no admin, governance, or user-facing function to reclaim them — a direct, permanent loss of user funds satisfying the "concrete fund loss or permanent freezing" bar.

### Likelihood Explanation
Likelihood is high: this requires only a single crafted EVM transaction (not even a special contract) calling the `rewards(address)` selector on `0x...1007` with non-zero `value`; no special privileges, race conditions, or governance actions are needed, and the omission is a static code-path gap present regardless of chain state.

### Proof of Concept
1. From any funded EOA (no association with a Sei account required), construct and sign an EVM transaction with:
   - `to`: distribution precompile address (`0x0000000000000000000000000000000000001007`)
   - `data`: ABI-encoded call to `rewards(address)` with any valid delegator address argument
   - `value`: any non-zero wei/usei amount
2. Submit the transaction. Since `Execute` dispatches `RewardsMethod` directly to `p.rewards(ctx, method, args)` without calling `pcommon.ValidateNonPayable(value)` (unlike every state-changing sibling method), the call succeeds and returns the queried rewards data instead of reverting.
3. The EVM value-transfer step (executed before `Run`/`Execute` per standard `vm.Call` semantics) debits `value` from the sender's balance and credits it to the precompile address's balance in the EVM `StateDB`.
4. Because `rewards()` never invokes `HandlePaymentUsei`/`HandlePaymentUseiWei` (contrast with `delegate()` in the staking precompile, which explicitly refunds the payer via `HandlePaymentUsei` before applying the payment) and the distribution precompile exposes no method to withdraw or sweep a balance held at its own address, the sent funds are permanently unrecoverable.

### Recommendation
Add `pcommon.ValidateNonPayable(value)` to the `RewardsMethod` (and any other view methods that similarly omit the check) branch in `precompiles/distribution/distribution.go`'s `Execute` function, matching the guard already applied to `WithdrawValidatorCommissionMethod`, so that a value-bearing call to a pure query method reverts instead of silently stranding funds.

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
