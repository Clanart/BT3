## Analysis Result

I found a concrete null-pointer/type-assertion panic reachable from an unprivileged EVM transaction sender, in the pointer precompile's CW20/CW721 registration path.

### Title
Unrecovered panic (nil interface type assertion) in the `pointer` precompile when registering a pointer for a malicious CW20/CW721 contract - (File: `precompiles/pointer/pointer.go`)

### Summary
`AddCW20` and `AddCW721` in `precompiles/pointer/pointer.go` query an attacker-controlled CosmWasm contract and blindly type-assert the JSON response fields to `string` without checking key presence or type, causing a Go panic that is not recovered anywhere in the call chain (`DynamicGasPrecompile.RunAndCalculateGas`).

### Finding Description
`AddCW20` calls `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))` against a CW20/CW721 contract address supplied by the caller, unmarshals the JSON response into `map[string]interface{}`, then does: [1](#0-0) 
```go
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
If the queried contract does not include a `"name"` or `"symbol"` key (map lookup returns `nil` interface{}), or returns a non-string type (number, bool, null, object), the unchecked type assertion `nil.(string)` / `wrongType.(string)` panics ("interface conversion: interface {} is nil, not string"). The same pattern exists in `AddCW721` at [2](#0-1)  and is also present in every historical precompile version under `precompiles/pointer/legacy/*/pointer.go` (v552 through v640) as shown by the 4–6 matches per file for `formattedRes[`.

This precompile is invoked through `DynamicGasPrecompile.RunAndCalculateGas`, which calls `d.executor.Execute(...)` (which dispatches to `AddCW20`/`AddCW721`) with **no `recover()`** around that call: [3](#0-2) 
Compare this to other precompiles in the same package family (`addr`, `oracle`, `solo`) which explicitly wrap `Execute` with `defer recover()` specifically "to catch gas meter panics" and non-gas panics that get converted to `execution reverted` — e.g.: [4](#0-3) 
The `pointer` precompile's `PrecompileExecutor.Execute` (the dispatcher in `precompiles/pointer/pointer.go`) has no such recover wrapper, so a panic inside `AddCW20`/`AddCW721` propagates unhandled up through `DynamicGasPrecompile.RunAndCalculateGas` and into the EVM call stack.

An attacker only needs to: (1) deploy a CW20 or CW721 contract whose `token_info`/`contract_info` query response omits `name`/`symbol` or returns non-string values for them, and (2) call `AddCW20Pointer`/`AddCW721Pointer` on the pointer precompile at `0x000000000000000000000000000000000000100b`, targeting that contract address. Both are permissionless actions any transaction sender/contract deployer can perform.

### Impact Explanation
A panic thrown while processing a transaction inside precompile execution, if unrecovered by any outer layer, propagates through go-ethereum's EVM interpreter into the Cosmos SDK message handler / `RunTx`/`DeliverTx` path. Whether this crashes the whole node (full node halt / consensus-relevant unhandled panic) depends on whether an outer layer (e.g., the SDK's `runtx` recover-and-convert-to-error path, or go-ethereum's `Call`/`vm.EVM` panic handling) ultimately catches it. I was not able to fully verify within this session whether a higher-level recover exists in the ante/msg-server or EVM `Call` wrapper that converts this specific panic into a normal tx failure rather than a node crash — the integration test comment in `integration_test/precompile_tests/utils/precompileUtils.ts` (`"a panic occurred" trace would mean a consensus-relevant unhandled error path`) suggests panics in precompiles are treated by the project as a serious, consensus-relevant class of bug that they specifically guard against elsewhere (e.g. `addr`, `oracle`, `solo` precompiles all added recover wrappers), but the `pointer` precompile itself lacks this protection.

If the panic is caught higher up and merely reverts the single transaction, impact is limited to a griefing/wasted-gas DoS against the caller's own transaction (low severity, likely does not meet the bug bar). If it is not caught anywhere and crashes/halts the validator or full node processing the block (matching the "crash of default-configuration RPC nodes" or "validator halt" acceptance criteria), impact would be Medium/High. Given the uncertainty over whether an outer recover exists, I cannot assert with full confidence that this reaches the required "validator halt" or "RPC node crash" bar — this needs confirmation via runtime testing.

### Likelihood Explanation
Likelihood of triggering the panic itself is high: it requires only deploying a trivial CosmWasm contract and calling a public, permissionless EVM precompile method (`AddCW20Pointer`/`AddCW721Pointer`) with no special privileges. This is a single-transaction, unprivileged-caller attack vector matching the CWE-476-style "malformed/missing field causes unchecked dereference/type assertion" pattern from the report.

### Recommendation
- In `precompiles/pointer/pointer.go` (`AddCW20`, `AddCW721`, and `AddCW1155` if it has the same pattern) and all `precompiles/pointer/legacy/*/pointer.go` variants, replace the unchecked type assertions with the comma-ok form and return a proper error, e.g.:
```go
nameVal, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw20 token_info response missing or invalid 'name' field")
}
```
- Additionally/defensively, wrap `PrecompileExecutor.Execute` in the `pointer` precompile with the same `defer func(){ if r := recover(); ... }()` pattern already used in `addr`, `oracle`, and `solo` precompiles, so any future unchecked-assertion-style bug degrades to `execution reverted` instead of a raw Go panic.

### Proof of Concept
1. Deploy a CosmWasm "CW20-like" contract whose `{"token_info":{}}` query handler returns valid JSON but omits the `name` or `symbol` field (or returns e.g. `"name": null` / `"name": 5`).
2. From any EVM account, call the pointer precompile at `0x000000000000000000000000000000000000100b` method `addCW20Pointer(cwAddress)` (per `AddCW20Pointer` ABI) with the malicious contract's Sei address.
3. Execution reaches `precompiles/pointer/pointer.go:154` (`name := formattedRes["name"].(string)`), where the missing/invalid field triggers a Go type-assertion panic that is not recovered by `DynamicGasPrecompile.RunAndCalculateGas`. [5](#0-4) [6](#0-5)

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}
