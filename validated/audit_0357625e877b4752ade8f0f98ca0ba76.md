**Reasoning**: The question targets `mapStatus` in `app/src/lib/status.ts`, but that function is not a parser of git/API output at all. It is a pure display-label formatter that takes an already-typed `AppFileStatus` object (produced elsewhere, after parsing) and returns a human-readable string like `'New'`, `'Modified'`, `'Deleted'`, etc., via an exhaustive `switch` with `assertNever` as the fallback. [1](#0-0) 

It receives no raw bytes, filenames, delimiters, or git/API records — its only input is the `kind` discriminant of a strongly-typed union, and (for the `Conflicted` case) a numeric `conflictMarkerCount` that was already computed upstream. [2](#0-1) 

The actual parsing of attacker-influenced `git status --porcelain=2 -z` output — where filenames, NUL delimiters, and status codes are genuinely security-relevant — happens in a *different* function that is also (confusingly) named `mapStatus`, but lives in `app/src/lib/status-parser.ts`. That one takes `statusCode`/`submoduleStatusCode` strings extracted by `parsePorcelainStatus` and maps them to a `FileEntry`. [3](#0-2) 

The path-splitting/tokenization of raw buffer output (where a crafted filename or delimiter could matter) happens in `parsePorcelainStatus`, using NUL-splitting via `splitBuffer` and regexes anchored with `^...$` per token, with malformed entries causing a thrown parse error rather than silent misclassification. [4](#0-3) [5](#0-4) 

Since the question explicitly scopes the target to `mapStatus` in `app/src/lib/status.ts`, and that function does not parse any attacker-controlled git/API output (it only formats an already-validated, strongly-typed status enum for display), there is no reachable path from crafted repository/API bytes to a misparse in this function.

export function mapStatus(status: AppFileStatus): string {
  switch (status.kind) {
    case AppFileStatusKind.New:
    case AppFileStatusKind.Untracked:
      return 'New'
    case AppFileStatusKind.Modified:
      return 'Modified'
    case AppFileStatusKind.Deleted:
      return 'Deleted'
    case AppFileStatusKind.Renamed:
      return 'Renamed'
    case AppFileStatusKind.Conflicted:
      if (isConflictWithMarkers(status)) {
        const conflictsCount = status.conflictMarkerCount
        return conflictsCount > 0 ? 'Conflicted' : 'Resolved'
      }

      return 'Conflicted'
    case AppFileStatusKind.Copied:
      return 'Copied'
    default:
      return assertNever(status, `Unknown file status ${status}`)
  }
}
