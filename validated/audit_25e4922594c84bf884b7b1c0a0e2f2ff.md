### Title
Permissionless `purchase()` Lets Anyone Evict a Victim App's Prepaid Bandwidth via Dust-Tier Subscription Flooding - (File: modules/pallets/bandwidth/src/lib.rs / evm/src/apps/BandwidthManager.sol)

### Summary
`BandwidthManager.purchase()` is a fully public, permissionless entrypoint that lets any caller top up bandwidth for an arbitrary `app`/`chain` pair of their choosing, at whatever tier is currently cheapest. On the pallet side, `push_subscription` appends every purchase to a shared, capacity-1024 FIFO queue keyed only by `(app_chain, app)` and evicts the *oldest* entry once the cap is hit — with no regard for who paid for it or how much bandwidth it represents. This lets an attacker who never owns or controls the victim app pay the cheapest configured tier repeatedly to flood a victim's queue and permanently evict its legitimately paid, higher-value subscriptions, destroying prepaid, non-refundable bandwidth funds with no recourse.

### Finding Description
`purchase()` [1](#0-0)  takes an attacker-supplied `app` and `chain` with no ownership check, pulls only `tierPrice[tier] * months` in fee tokens from `msg.sender`, and dispatches a `BandwidthPurchaseMsg` crediting that arbitrary `(chain, app)` pair. `pallet-bandwidth::on_accept` [2](#0-1)  only checks that the *source chain's registered manager* sent the message — never that the purchaser is related to `app` — and then unconditionally calls `push_subscription`.

`push_subscription` [3](#0-2)  appends every purchase to a single shared `BoundedVec<Subscription, MaxSubscriptions>` per `(app_chain, app)`, capped at `MAX_SUBSCRIPTIONS` (1024). Once the cap is reached, each new push evicts the entry at index 0 — the oldest by insertion order — regardless of its tier, remaining bytes, or who paid for it, and emits `SubscriptionEvicted { lost_bytes, .. }` acknowledging the loss [4](#0-3) .

Because the queue is a single shared resource per `app` with no per-payer isolation, minimum-purchase floor, or rate limit, an attacker holding only enough fee token to buy the cheapest tier repeatedly can:
1. Fill the victim `(chain, app)` queue up to 1024 entries with the cheapest tier/`months=1` purchases.
2. Continue purchasing — each additional call now evicts the oldest live entry. Once the attacker's flood has pushed past the victim's original entries, those legitimate, unexpired, higher-value subscriptions are evicted one by one and their `remaining_bytes` are permanently lost.

This mirrors the reported bug class exactly: a public function (`claimRewards`/`purchase`) that recalculates/mutates a *shared* accounting structure (`rewardPerSecond`/`Allowance` FIFO) based on attacker-controllable low-cost input (dust reward transfer / cheapest-tier purchase), with no minimum-value guard, degrading or destroying value for legitimate participants who never authorized the interaction.

### Impact Explanation
This is a direct loss-of-funds logic attack reachable by any unprivileged EVM account holding fee tokens — no malicious relayer, prover, or admin is required. A victim app's prepaid, non-refundable bandwidth (a bridged asset analogous to escrowed funds) can be permanently destroyed by a third party who has no relationship to that app, purely by paying the cheapest tier price repeatedly. Because eviction is strictly FIFO/oldest with no per-payer isolation, the attack works deterministically regardless of how much the victim had prepaid.

### Likelihood Explanation
The attack cost is bounded and deterministic (`1024 × cheapest_tier_price`), not probabilistic — the attacker is guaranteed success once the purchase count is met. Depending on how tiers are priced (governance sets prices independently per chain via `dispatch_set_tiers`), the cost of evicting a high-value subscription (e.g. the $1000/8MB tier) can be made cheap relative to the value destroyed, especially since nothing prevents a very low-priced tier from existing.

### Recommendation
1. Isolate subscription capacity per payer (or require `request.from`/`app` binding) so an unrelated account cannot evict another payer's entries.
2. Change eviction policy to prefer evicting the *same payer's* oldest entry, or reject/queue-limit new purchases from callers other than the app itself while the list is near capacity.
3. Enforce a minimum purchase value (in USD-equivalent) per tier, and/or per-source rate limiting on `push_subscription`, so dust-tier flooding is not economically trivial relative to the value it can destroy.

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
