### Title
`EvmHost.dispatchIncoming(GetResponse)` never clears `_requestCommitments`, enabling a double payout of the same GET relayer fee - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost` pays the relayer fee for a GET response out of `_requestCommitments[commitment]` but, unlike every timeout path, never deletes that entry afterward. Because `handleGetRequestTimeouts` only guards against replay by checking `meta.sender == address(0)`, a stale (still-populated) commitment left behind after a normal response delivery can later be consumed a second time through the timeout path, paying the same fee out again.

### Finding Description
Every request-lifecycle terminal state in `EvmHost.sol` deletes `_requestCommitments[commitment]` for replay protection **except** GET-response delivery:

- `dispatchTimeOut(GetRequestTimeout...)` — `delete _requestCommitments[commitment];` before refunding [1](#0-0) 
- `dispatchTimeOut(PostRequestTimeout...)` — same pattern [2](#0-1) 
- `dispatchIncoming(GetResponse...)` — pays the relayer fee from `_requestCommitments[commitment].fee` but **does not delete the commitment entry** afterward [3](#0-2) 

The only replay guard on the timeout path is presence of the commitment (`meta.sender == address(0)` → reject): [4](#0-3) 

Because a successful `handleGetResponses` delivery leaves `_requestCommitments[commitment]` fully intact (same `sender` and `fee` as at dispatch time), the request still looks "live" to `handleGetRequestTimeouts`. A relayer/attacker can subsequently submit a timeout proof for the same commitment — a non-membership proof of the response receipt in Hyperbridge's state trie at *some* height `H` where `state.timestamp >= request.timeout()` but the response had not yet been committed at `H` (Hyperbridge produces GET responses asynchronously relative to block production, so such a height window can exist even after a response is eventually delivered at a later height). `handlePostRequestTimeouts`/`handleGetRequestTimeouts` only check non-membership at the specific proven height, not "has this ever been fulfilled" — the comment in `handleGetResponses` even states timeouts are "checked on Hyperbridge," relying on Hyperbridge's off-chain enforcement rather than an on-chain state guard on the EVM host itself: [5](#0-4) 

Once that timeout proof is accepted, `EvmHost.dispatchTimeOut(GetRequestTimeout...)` deletes the commitment and refunds `meta.fee` to `meta.sender` — a **second** payout of the exact same fee that was already paid to the relayer when the response was delivered: [1](#0-0) 

This is structurally identical to the `DepositManager` bug: a value (`referralRewards` / here, `_requestCommitments[commitment].fee`) is credited/paid out on one lifecycle path but never cleared/deducted, so a second lifecycle path can act on the same stale record and pay out again.

### Impact Explanation
This allows the fee token escrowed for a single GET dispatch to be paid out twice from `EvmHost`'s fee-token balance — once to the relayer that delivered the response, and again to the payer via a timeout claim — directly draining protocol/fee-token funds that were only ever meant to cover one delivery. This matches the bounty's "stealing or loss of funds" and "replay/double-claim/double-settlement" categories, since it is a public, permissionless entry point (`handleGetRequestTimeouts`) reachable by any relayer without needing a malicious peer, prover, or admin.

### Likelihood Explanation
Exploitability depends on being able to produce a valid non-membership proof at a height that satisfies `state.timestamp >= request.timeout()` while the actual response was recorded at a strictly later height on Hyperbridge — a timing/race condition inherent to the asynchronous nature of GET response production, not a privileged capability. The `EvmHost` contract itself provides no additional on-chain check (e.g., "has a response already been delivered for this commitment") to prevent this, so the guarantee is entirely dependent on Hyperbridge never producing/relaying a response for an already-expired request, which is an off-chain assumption rather than an enforced on-chain invariant on the EVM side.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` after (or as part of) paying out the relayer fee, mirroring the replay-protection pattern already used in both `dispatchTimeOut` overloads. This closes the window where a fulfilled request's fee metadata remains claimable a second time via the timeout path.

### Proof of Concept
1. App on chain A dispatches a `DispatchGet` to Hyperbridge with `fee = F`, `payer = P`; `_requestCommitments[commitment] = {sender: P, fee: F}` is stored [6](#0-5) .
2. Hyperbridge processes the GET after the request's nominal `timeoutTimestamp` has passed (asynchronous processing), producing a valid response later than the timeout height.
3. Relayer R submits `handleGetResponses` with a valid proof; `dispatchIncoming(GetResponse, R)` pays `F` fee tokens to `R` and leaves `_requestCommitments[commitment]` unchanged. [3](#0-2) 
4. The same or a colluding relayer builds a non-membership proof of the response-receipt slot at an earlier height `H` (before Hyperbridge actually committed the response) where `state.timestamp(H) >= request.timeout()`, and submits `handleGetRequestTimeouts`. Since `_requestCommitments[commitment].sender != address(0)` (never cleared in step 3), the check passes. [7](#0-6) 
5. `EvmHost.dispatchTimeOut(GetRequestTimeout...)` refunds `F` fee tokens to `P` a second time, deleting the commitment only now. [1](#0-0) 
6. Total payout for one dispatched GET request is `2F` instead of `F`, drained from the host's fee-token balance.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
