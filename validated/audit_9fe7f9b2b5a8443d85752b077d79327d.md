### Title
`ThresholdKeys::read`/`ThresholdKeys::new` accept key material without verifying the secret share corresponds to the registered verification shares — a "registered" group key nobody may actually control - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to `registerWallet()` accepting any address as a "Safe" without checking it is actually a supported Safe proxy, `ThresholdKeys::read` (and the underlying `ThresholdKeys::new`) accept an arbitrary secret share and an arbitrary map of verification shares without ever checking that the secret share is actually a member of the polynomial — i.e. that `C::generator() * secret_share == verification_shares[params.i()]`. A malformed byte stream fed to `ThresholdKeys::read` yields a `ThresholdKeys` object that claims participation in a group while holding a share unrelated to the group's `group_key`, which is computed purely by interpolating the (attacker-chosen) verification shares over participants `1..=t`.

### Finding Description
`ThresholdKeys::new` validates only structural properties: the count of `verification_shares` equals `n`, participant indexes are `<= n`, and `Constant` interpolation is only used when `t == n` (crypto/dkg/src/lib.rs:355-374). It then derives `group_key` by Lagrange/Constant interpolation of the supplied verification shares for participants `1..=t` (crypto/dkg/src/lib.rs:376-378), and stores the caller-supplied `secret_share` unconditionally — no statement of the form `C::generator() * secret_share == verification_shares[i]` (or equivalently that the share satisfies the committed polynomial) is ever checked.

`ThresholdKeys::read` (crypto/dkg/src/lib.rs:574-632) reaches this same unchecked constructor from raw bytes: it checks the curve `C::ID` (the analog of a "version check", which is present), reads `t`, `n`, `i`, the interpolation variant, `secret_share` via `C::read_F`, and `n` verification shares via `C::read_G`, then calls `ThresholdKeys::new`. Nothing in the read path authenticates that the deserialized share belongs to the deserialized group.

Honest in-protocol constructors (PedPoP's `KeyMachine::calculate_share`, `GeneratorPromotion::complete`, `musig`, `dealer::key_gen`) all produce consistent material, so the only reachable producer of inconsistent keys is the deserialization/external-import path — exactly the "user registers an unsupported/illegitimate wallet" surface from the report. `musig()` even demonstrates the intended check exists in spirit: it returns `NotParticipating` when the caller's public key is absent from `keys` (crypto/dkg/musig/src/lib.rs:122-124). `ThresholdKeys::new`/`read` have no equivalent membership check.

### Impact Explanation
The resulting `ThresholdKeys` is incoherent in two exploitable directions:

- **Group key nobody controls:** `group_key` is interpolated solely from `verification_shares[1..=t]`. An attacker can craft a blob where these shares interpolate to a key the attacker fully knows (e.g. all shares `x_j·G` for known `x_j`), while `secret_share` is unrelated. If an integrator imports such keys (backup restore, coordinator-supplied key material) and treats `group_key()` as a custody address, funds sent to it are controlled by the attacker, not the holder — "funds reported received that are not spendable" (or spendable by the wrong party).
- **Invalid signing identity:** `view()`/`sign` produce signature shares that verify against `verification_shares[i]` (crypto/dkg/src/lib.rs:500-507, crypto/frost/src/algorithm.rs:219-230). If `secret_share·G != verification_shares[i]`, every share the holder produces fails verification, so the participant silently cannot sign for the group it believes it belongs to — the analog of a Safe registering an incompatible wallet leaving subaccounts "unprotected".

### Likelihood Explanation
Requires an attacker-controlled or corrupted byte stream reaching `ThresholdKeys::read` — e.g. key material imported from an untrusted source rather than produced by an honest local DKG. Within-protocol paths cannot produce inconsistent keys, so exploitation depends on an integrator deserializing foreign `ThresholdKeys`, which is precisely the supported-but-unchecked public API surface (`ThresholdKeys::read` is a public `io::Read` constructor). Impact when triggered is high (loss of custody / inability to sign), likelihood moderate → Medium.

### Recommendation
In `ThresholdKeys::new`, verify membership/consistency before accepting the keys:

```rust
// crypto/dkg/src/lib.rs, inside ThresholdKeys::new
if verification_shares[&params.i()] != C::generator() * secret_share.deref() {
  Err(DkgError::InvalidShare)?; // or a new NotParticipating-style error
}
```

This mirrors `musig()`'s existing `NotParticipating` check and the Safe recommendation to verify the registered artifact is a genuine member of the expected set. Optionally also reject identity verification shares / a `secret_share` of zero.

// Attacker-controlled blob: group_key resolves to attacker-known x·G,
// while the victim's secret_share is a decoy.
let x = <Ristretto as Ciphersuite>::F::random(&mut OsRng);       // attacker secret
let fake_share = <Ristretto as Ciphersuite>::F::random(&mut OsRng); // victim's useless share

let mut serialized = vec![];
serialized.extend(4u32.to_le_bytes());
serialized.extend(Ristretto::ID);
serialized.extend(1u16.to_le_bytes()); // t = 1
serialized.extend(1u16.to_le_bytes()); // n = 1
serialized.extend(1u16.to_le_bytes()); // i = 1
serialized.push(1);                    // Lagrange
serialized.extend(fake_share.to_repr());
serialized.extend((Ristretto::generator() * x).to_bytes()); // verification_shares[1]

let keys = ThresholdKeys::<Ristretto>::read(&mut serialized.as_ref()).unwrap(); // accepted
assert_eq!(keys.group_key(), Ristretto::generator() * x); // attacker-controlled group key
// keys.sign(...) produces shares verifying against x·G with fake_share — always invalid,
// while group_key() advertises the attacker's key as the victim's custody address.

  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
  }

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
