## Analog Found: Unvalidated fork `clone_url` from the GitHub API is written directly into the repository's remote configuration

### Title
Unvalidated GitHub API `clone_url` is written to the local git remote when converting a repository to a fork - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The Console bug reduces to: a state-mutating function consumes a value from an external source (`_upgradablePaths[fromWalletType]`) and writes it straight into critical state (`walletType`) without validating that the value is well-formed, breaking an invariant enforced everywhere else (`isWallet()`). `AppStore._convertRepositoryToFork()` has the same shape: it takes `fork.clone_url` — a field on an `IAPIFullRepository` object returned by the GitHub API — and writes it directly into the repository's `origin` remote via `gitStore.setRemoteURL()`, with no check that the value is actually a well-formed git remote URL.

### Finding Description
`_convertRepositoryToFork` reads the clone URL straight off the API object and passes it to `setRemoteURL`: [1](#0-0) 

Compare this to the one other place in the codebase that rewrites a remote URL sourced from the GitHub API, `updateRemoteUrl()`, which explicitly guards the write with format/host/owner/name matching (`urlMatchesRemote`, built on `parseRemote`) and a protocol-equality check before ever calling `setRemoteURL`: [2](#0-1) 

`_convertRepositoryToFork` has none of these guards. It only checks that a local default remote *exists* (`defaultRemoteName !== undefined && remoteUrl !== undefined`); it never validates `fork.clone_url` with `parseRemote`/`urlMatchesRemote` before writing it into the repository's git config as the new `origin` URL, and then reconfigures `upstream` to point at the previous `origin` value: [3](#0-2) 

`IAPIFullRepository.parent`/fork data is explicitly documented elsewhere as untrusted, optional API payload: [4](#0-3) 

The broken invariant: every other consumer of API-sourced clone/remote URLs in this codebase (`updateRemoteUrl`, `repository-matching.ts`'s `urlMatchesRemote`/`urlMatchesCloneURL`) treats them as untrusted and re-derives/validates hostname+owner+name+protocol via `parseRemote` before trusting them. `_convertRepositoryToFork` skips this validation entirely, so a malformed or attacker-influenced `clone_url` (e.g., from a compromised/MITM'd GitHub Enterprise Server endpoint, or a proxy sitting between Desktop and the API) is written verbatim into the user's git remote configuration.

### Impact Explanation
This directly matches the "silent corruption of what the user commits or pushes" impact class: after conversion, all future `git push`/`git fetch` on `origin` target whatever URL was supplied in the untrusted API response, without the user seeing or approving the change (they only asked to "convert to fork," not to repoint their remote to an arbitrary host). Depending on the value supplied, this could redirect pushes (credential/token exposure to a rogue remote during authentication) or, since git remote URLs support handler syntax that some git configurations parse specially, expose the user to remote-triggered behavior on the next fetch/push. Unlike `updateRemoteUrl`, there is no host/owner/name/protocol re-validation to fall back on here.

### Likelihood Explanation
The `fork` argument comes from a `IAPIFullRepository` fetched over the network from the account's configured endpoint (GitHub.com or, more commonly for this attack surface, a GitHub Enterprise Server instance). An attacker who controls or can tamper with responses from that endpoint (compromised/malicious GHES instance, or an on-path proxy/MITM position relative to the API host — an explicitly valid attacker primitive per the task's scope) can supply an arbitrary `clone_url` value that Desktop will trust unconditionally. No local access, admin rights, or social engineering beyond the user's normal "create/use a fork" workflow is required.

### Recommendation
Before calling `gitStore.setRemoteURL(defaultRemoteName, fork.clone_url)`, validate `fork.clone_url` the same way `updateRemoteUrl.ts` does: parse it with `parseRemote`, confirm the protocol is one of the expected `GitProtocol` values, and ideally confirm the hostname matches the endpoint/account the fork data was fetched from before writing it into the repository's git configuration.

### Proof of Concept
1. Configure Desktop against a GitHub Enterprise Server endpoint (or place an on-path proxy in front of the configured API endpoint).
2. Have the compromised/malicious endpoint respond to the fork-creation/fork-lookup API call with an `IAPIFullRepository` object whose `clone_url` is an attacker-chosen value (e.g., a URL pointing to attacker infrastructure) rather than the real fork's clone URL.
3. Trigger the "convert repository to fork" flow (`create-fork-dialog.tsx` → `Dispatcher.convertRepositoryToFork` → `AppStore._convertRepositoryToFork`).
4. Observe that `origin` is rewritten to the attacker-supplied URL with no format/host validation, since `_convertRepositoryToFork` (`app/src/lib/stores/app-store.ts:8969-8991`) never calls `parseRemote`/`urlMatchesRemote`, unlike `updateRemoteUrl` (`app/src/lib/stores/updates/update-remote-url.ts:7-44`), which is the only other API-driven remote-URL writer in the codebase and does perform that validation.

Note: I was not able to trace the full UI trigger path in `create-fork-dialog.tsx` in detail (only its reference to `convertRepositoryToFork` was located), so confirmation of exactly which UI action supplies the `fork` object would benefit from opening that file directly — the index may not have surfaced its full contents.

```typescript
  public async _convertRepositoryToFork(
    repository: RepositoryWithGitHubRepository,
    fork: IAPIFullRepository
  ): Promise<Repository> {
    const gitStore = this.gitStoreCache.get(repository)
    const defaultRemoteName = gitStore.defaultRemote?.name
    const remoteUrl = gitStore.defaultRemote?.url
    const { endpoint } = repository.gitHubRepository

    // make sure there is a default remote (there should be)
    if (defaultRemoteName !== undefined && remoteUrl !== undefined) {
      // update default remote
      if (await gitStore.setRemoteURL(defaultRemoteName, fork.clone_url)) {
        await gitStore.ensureUpstreamRemoteURL(remoteUrl)
        // update associated github repo
        return this.repositoriesStore.setGitHubRepository(
          repository,
          await this.repositoriesStore.upsertGitHubRepository(endpoint, fork)
        )
      }
    }
    return repository
  }
```

```typescript
export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
```
