### Title
Wasm-side CW721→ERC721 wrapper uses `transferFrom` instead of `safeTransferFrom`, permanently freezing NFTs sent to non-receiver contracts - (File: x/evm/client/wasm/query.go)

### Summary
The CosmWasm CW721 wrapper contract that represents an underlying ERC721 token (`example/cosmwasm/cw721/src/contract.rs`) transfers NFTs by delegate-calling the ERC721 contract's `transferFrom` function rather than `safeTransferFrom`. Any CosmWasm user (or contract) that calls `transfer_nft`/`send_nft` on the wrapper with a `recipient` whose associated EVM address is a smart contract lacking `onERC721Received` support will have the NFT irrecoverably locked in that contract.

### Finding Description
`transfer_nft` in `example/cosmwasm/cw721/src/contract.rs:175-192` builds the transfer payload via `querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())` and sends it as `EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload }`. The payload itself is constructed in `HandleERC721TransferPayload` ( [1](#0-0) ), which packs the ABI-encoded call to `transferFrom(fromEvmAddr, toEvmAddr, tokenId)` — never `safeTransferFrom`. This mirrors the underlying Solidity ERC721 implementations in the repo (e.g. [2](#0-1)  and the loadtest variant at [3](#0-2) ), which perform the ERC721-receiver check only inside `safeTransferFrom`, not `transferFrom`.

Because the wrapper only validates the recipient as a syntactically valid Sei address (`deps.api.addr_validate(recipient)?` at [4](#0-3) ) and never checks whether the resolved EVM address is a contract capable of handling ERC721 tokens, a CW user can transfer_nft to any address — including a smart-contract address that has no `onERC721Received`/ERC721Receiver implementation. The underlying ERC721 `transferFrom` call succeeds unconditionally (no receiver check), and ownership of the NFT is reassigned to that contract's EVM address.

### Impact Explanation
Once the token is owned by a contract address that cannot itself call `transferFrom`/`approve` (e.g., an arbitrary non-NFT-aware EVM contract, or even a Sei-native module/precompile address), the NFT becomes permanently locked — neither the original owner, the CW721 wrapper, nor any other party can recover it, since there is no privileged withdraw path. This is a permanent, irreversible loss of a user's asset, satisfying "permanent freezing" impact criteria.

### Likelihood Explanation
This is reachable by any ordinary CosmWasm user submitting a single `transfer_nft` or `send_nft` execute message to the CW721↔ERC721 wrapper contract with an attacker-influenced or accidentally-chosen recipient (e.g., a deployed EVM contract address that isn't ERC721-receiver-aware, or a Sei precompile/module address translated to an EVM address). No special privileges are required, making the likelihood high whenever a user or dApp integration passes an incorrect/contract recipient.

### Recommendation
Change `HandleERC721TransferPayload` (and the corresponding CW721 wrapper `transfer_nft`/`send_nft` logic) to pack and call `safeTransferFrom` instead of `transferFrom` when the target ERC721 contract supports it, or add an explicit check that the resolved recipient EVM address is either an EOA or a contract implementing `IERC721Receiver` (`onERC721Received`) before performing the transfer, mirroring the safety check already present in `contracts/src/ERC721.sol`'s `safeTransferFrom`.

### Proof of Concept
1. Deploy/point a CW721 wrapper contract at an existing ERC721 collection via `ERC721_ADDRESS` (`example/cosmwasm/cw721/src/contract.rs:24`).
2. Deploy an arbitrary EVM contract that does not implement `onERC721Received` and associate a Sei address with it (or use any existing non-receiver contract's associated Sei address).
3. As the NFT owner, call `ExecuteMsg::TransferNft { recipient: <sei address of the non-receiver contract>, token_id }` on the wrapper.
4. `transfer_nft` (`contract.rs:175-192`) resolves `owner`, builds the `transferFrom` payload via `HandleERC721TransferPayload`, and delegate-calls the ERC721 contract, which executes `transferFrom` ( [5](#0-4) ) unconditionally, reassigning `_ownerOf[id]` to the contract address.
5. The NFT is now owned by a contract with no ERC721 handling logic and no way to invoke `transferFrom`/`approve` on itself — the token is permanently frozen.

func (h *EVMQueryHandler) HandleERC721TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string) ([]byte, error) {
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")

	if err != nil {
		return nil, err
	}

        require(from == _ownerOf[id], "from != owner");
