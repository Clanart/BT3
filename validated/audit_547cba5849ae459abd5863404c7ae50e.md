### Title
Unauthenticated `shop` query param triggers Shopify Admin API call using victim shop's offline access token in `EnsureInstalled#validate_non_embedded_session` - ([File: app/controllers/concerns/shopify_app/ensure_installed.rb])

### Summary
When `use_new_embedded_auth_strategy?` is `false`, `ShopifyApp::EnsureInstalled` gates access purely on the unauthenticated `shop` request parameter. `check_shop_known` and `validate_non_embedded_session` derive `installed_shop_session` solely from `params[:shop]` and then issue a live `ShopifyAPI::Clients::Rest::Admin` call using that shop's stored offline access token, with no verification that the request actually originated from that shop's authenticated session (no HMAC, no session-token/JWT check, no cookie/session binding).

### Finding Description
The before_action chain for the legacy (non token-exchange) flow is: [1](#0-0) 

`current_shopify_domain` is derived only from `params[:shop]` via `ShopifyApp::Utils.sanitize_shop_domain` — no signature, JWT, or cookie is checked: [2](#0-1) 

`check_shop_known` uses that attacker-suppliable domain to look up the victim's `installed_shop_session` and, if a session exists (i.e., the shop is installed), lets the request proceed without redirect: [3](#0-2) 

`validate_non_embedded_session` then only short-circuits if `loaded_directly_from_admin?` is true, which itself requires `params[:embedded] == "1"` — an attacker-controlled param that is trivial to omit or spoof to `"0"`. When that condition is false (the attacker's crafted request, e.g. `GET action?shop=victim-shop.myshopify.com` with no `embedded` param), the code proceeds to instantiate a REST Admin client bound to the victim shop's offline session and performs a live API call: [4](#0-3) [5](#0-4) 

No check anywhere in this concern verifies that the caller is the legitimate merchant/admin for `shop` — there is no comparison against a Rack session value, no HMAC verification of the request, and no App Bridge/session-token check in this code path. This violates the stated invariant (`AUTHENTICATION_ENFORCED`/`SESSION_BINDING`): authorization to reach `installed_shop_session`-gated behavior is based solely on the `shop` param.

### Impact Explanation
An unauthenticated caller can force the app server to authenticate to Shopify's Admin API as an arbitrary already-installed victim shop, consuming that shop's API rate-limit budget and access token on the attacker's behalf (a form of cross-shop/session confusion and token misuse — corresponds to Shopify's "Broken Authentication"/"Improper Access Control" impact class). Whether shop data is actually returned in the HTTP response to the attacker depends on what the concrete controller action does after the before_actions run (i.e., whether it further uses `@shop`/`installed_shop_session` to render victim data), but the gem itself provides no barrier preventing this — the `EnsureInstalled` concern's own before_action already performs an authenticated API call on the victim's behalf using nothing but the unauthenticated `shop` param.

### Likelihood Explanation
Fully reachable by any anonymous HTTP client: requires only knowledge of an installed shop's `.myshopify.com` domain (often guessable/public), `use_new_embedded_auth_strategy?` set to `false` (a supported, documented configuration), and omission of `embedded=1` in the request. No secrets, tokens, or victim interaction are needed, making this highly repeatable.

### Recommendation
`EnsureInstalled`'s non-embedded path should not authorize/act on `installed_shop_session` based solely on `params[:shop]`. Require verification that the request actually originates from that shop's authenticated context (e.g., valid Shopify session token/JWT, verified HMAC, or a server-side session value set during OAuth) before calling `check_shop_known`/`validate_non_embedded_session`, and avoid treating an attacker-controlled `embedded` param as a security-relevant signal for skipping the API validation call.

### Proof of Concept
```ruby
class DummyController < ApplicationController
  include ShopifyApp::EnsureInstalled
  def index
    render plain: "ok"
  end
end

test "unauthenticated shop param reaches installed_shop_session-backed API call" do
  ShopifyApp::SessionRepository.stubs(:retrieve_shop_session_by_shopify_domain)
    .with("victim-shop.myshopify.com")
    .returns(ShopifyAPI::Auth::Session.new(shop: "victim-shop.myshopify.com", access_token: "victim-token"))

  admin_client = mock
  admin_client.expects(:get).with(path: "shop") # proves API is called with victim's session/token
  ShopifyAPI::Clients::Rest::Admin.expects(:new)
    .with(session: has_property(:shop, "victim-shop.myshopify.com"))
    .returns(admin_client)

  get "/dummy?shop=victim-shop.myshopify.com" # no token, no cookie, no embedded param

  # Expected under a secure implementation: request should be rejected/redirected
  # without ever constructing an Admin client for victim-shop using its stored token.
  # Actual: admin_client.get(path: "shop") is invoked using victim-shop's offline session.
end
```

      return if loaded_directly_from_admin?
