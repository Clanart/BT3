### Title
Zero-signature multisig spending condition allows trivial authentication bypass via 0-of-0 threshold - (File: `stacks-codec/src/transaction.rs`, `MultisigSpendingCondition::verify`)

### Summary
`MultisigSpendingCondition::verify` (and the analogous `OrderIndependentMultisigSpendingCondition::verify`) checks that the number of signatures collected equals (or exceeds) `self.signatures_required`, then verifies the recovered address matches `self.signer`. Neither function rejects `signatures_required == 0` with an empty `fields` vector, so the "at least one signature" invariant that the protocol implicitly assumes is never enforced — mirroring the reported Go `Root()` bug where an empty input trivially satisfies a check that should have rejected it outright.

### Finding Description
In `MultisigSpendingCondition::verify`, `num_sigs` starts at 0 and is only incremented when a `TransactionAuthField::Signature` is present in `fields`. If `fields` is empty and `signatures_required` is 0, the check
```rust
if num_sigs != self.signatures_required { ... }
``` [1](#0-0) 
is trivially satisfied (`0 != 0` is false), so no error is returned. The same pattern occurs in `OrderIndependentMultisigSpendingCondition::verify`, where `num_sigs < self.signatures_required` (`0 < 0`) is also false [2](#0-1) .

With an empty `pubkeys` vector, the code proceeds to compute an address purely from `hash_mode` and `signatures_required = 0`:
```rust
let addr = StacksAddress::from_public_keys(
    0,
    &self.hash_mode.to_address_hash_mode(),
    self.signatures_required as usize,
    &pubkeys,
)
``` [3](#0-2) 
and compares it to `self.signer` (an attacker-controlled field of the spending condition) [4](#0-3) . Because `from_public_keys(0, mode, 0, &[])` is deterministic for a given `hash_mode`, this produces one fixed, publicly-computable `Hash160` value per hash mode. An attacker who sets `signer` to that precomputed value, `signatures_required = 0`, and `fields = []` will pass `verify()` with **zero real signatures and zero public keys** — the equality `num_sigs == signatures_required` is satisfied by two empty/zero quantities rather than by any actual cryptographic proof of authorization, exactly the "empty expansion trivially satisfies an equality" bug class described in the report.

The deserialization-time checks in `consensus_deserialize` (`num_sigs_given != signatures_required` / `num_sigs_given < signatures_required`) have the identical blind spot [5](#0-4) [6](#0-5) , so a transaction with `signatures_required = 0` and no auth fields is not rejected as malformed either.

### Impact Explanation
This breaks the fundamental equality that a Stacks transaction's spending condition should only validate ("authenticate") when it is backed by the number of signatures its own `signatures_required` field claims are needed, and that field/threshold should never legitimately be zero for a real key-derived address. In practice, the impact is bounded: the resulting "magic" address is a fixed, publicly computable value with no known private key — it behaves like a well-known burn/no-key address rather than letting an attacker forge authorization over an *arbitrary victim's* existing address. Nonetheless, if any STX or asset happens to be sent to that deterministic zero-of-zero address (e.g., by a wallet, exchange, or contract that mishandles multisig threshold generation), any party — not just the address's nominal owner — can construct a transaction that passes `verify()` and moves those assets with no valid signature at all, which is a "forging authorization so that an asset moves without any legitimate signature" scenario.

### Likelihood Explanation
Likelihood is low-to-moderate. Nothing in the transaction-construction or deserialization path rejects `signatures_required = 0`, so any actor who understands `StacksAddress::from_public_keys`'s hashing scheme can precompute the magic address deterministically and construct a transaction spending it — this requires no privileged access, no signer, and no other account's key, satisfying the unprivileged-sender requirement. The precondition (funds present at that specific deterministic address) is what limits real-world exploitation, but the validation gap itself is unconditionally present in the auth-verification code today.

### Recommendation
In `MultisigSpendingCondition::verify`, `OrderIndependentMultisigSpendingCondition::verify`, and their `consensus_deserialize` implementations in `stacks-codec/src/transaction.rs`, explicitly reject `signatures_required == 0` (and, symmetrically, an empty `fields`/pubkeys list) before performing the `num_sigs`-vs-`signatures_required` comparison, so that a 0-of-0 multisig condition can never authenticate a transaction. Add unit/property tests asserting that `verify()` always fails when no real signature fields are present, regardless of the claimed threshold.

### Proof of Concept
1. Compute `addr = StacksAddress::from_public_keys(0, hash_mode.to_address_hash_mode(), 0, &[])` for a chosen `hash_mode` (e.g. `MultisigHashMode::P2SH`) — this is a fixed, attacker-computable `Hash160`.
2. Construct a `MultisigSpendingCondition { hash_mode, signer: addr.bytes, nonce, tx_fee, fields: vec![], signatures_required: 0 }` and wrap it in a `TransactionAuth::Standard`.
3. Call `verify(initial_sighash, cond_code, mode)`; observe that `num_sigs (0) == signatures_required (0)` passes, `pubkeys` is empty so `from_public_keys` recomputes the same fixed `addr`, and `addr.bytes() == self.signer` succeeds — `verify()` returns `Ok(...)` despite zero signatures ever being checked. [7](#0-6) 
4. Any funds held at the resulting deterministic address can then be spent by anyone constructing this zero-signature condition.

    pub fn verify(
        &self,
        initial_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        mode: TransactionAuthVerificationMode,
    ) -> Result<Txid, AuthError> {
        let mut pubkeys = vec![];
        let mut cur_sighash = initial_sighash.clone();
        let mut num_sigs: u16 = 0;
        let mut have_uncompressed = false;
        for field in self.fields.iter() {
            let pubkey = match field {
                TransactionAuthField::PublicKey(ref pubkey) => {
                    if !pubkey.compressed() {
                        have_uncompressed = true;
                    }
                    pubkey.clone()
                }
                TransactionAuthField::Signature(ref pubkey_encoding, ref sigbuf) => {
                    if *pubkey_encoding == TransactionPublicKeyEncoding::Uncompressed {
                        have_uncompressed = true;
                    }

                    let (pubkey, next_sighash) = TransactionSpendingCondition::next_verification(
                        &cur_sighash,
                        cond_code,
                        self.tx_fee,
                        self.nonce,
                        pubkey_encoding,
                        sigbuf,
                        mode,
                    )?;
                    cur_sighash = next_sighash;
                    num_sigs = num_sigs
                        .checked_add(1)
                        .ok_or(AuthError::VerifyingError("Too many signatures".to_string()))?;
                    pubkey
                }
            };
            pubkeys.push(pubkey);
        }

        if num_sigs != self.signatures_required {
            return Err(AuthError::VerifyingError(
                "Incorrect number of signatures".to_string(),
            ));
        }

        if have_uncompressed && self.hash_mode == MultisigHashMode::P2WSH {
            return Err(AuthError::VerifyingError(
                "Uncompressed keys are not allowed in this hash mode".to_string(),
            ));
        }

        let addr = StacksAddress::from_public_keys(
            0,
            &self.hash_mode.to_address_hash_mode(),
            self.signatures_required as usize,
            &pubkeys,
        )
        .ok_or_else(|| {
            AuthError::VerifyingError("Failed to generate address from public keys".to_string())
        })?;

        if addr.bytes() != &self.signer {
            return Err(AuthError::VerifyingError(format!(
                "Signer hash does not equal hash of public key(s): {} != {}",
                addr.bytes(),
                self.signer
            )));
        }

        Ok(cur_sighash)
    }
