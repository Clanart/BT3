### Title
Malformed CLVM atom length prefix causes out-of-bounds index read in `is_atom_canonical`/`is_clvm_canonical` during mempool DEDUP eligibility checks - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM byte buffer of a submitted spend's solution to decide DEDUP eligibility, walking the buffer using attacker-controlled length-prefix bytes without validating that the computed atom length stays within the buffer bounds, mirroring the "invalid read from a crafted length field" bug class of CVE-2017-9147.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` decodes a variable-length atom-length prefix (1–6 bytes) directly from attacker-supplied bytes and returns `1 + prefix_len + atom_len` without ever checking that `atom_len` (or the prefix bytes themselves) fit inside `clvm_buffer`: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` then drives this function in a loop, repeatedly indexing `clvm_buffer[offset]` and advancing `offset` by the untrusted `atom_len`, with no bounds check before the next `clvm_buffer[offset]` read: [2](#0-1) 

Per the in-repo documentation, this canonical-encoding check is required to determine DEDUP-eligible spends, meaning it runs on the solution bytes of a spend bundle submitted by an ordinary, unprivileged submitter through normal mempool admission: [3](#0-2) 

A crafted solution whose atom length-prefix byte encodes a size field extending past the end of the buffer (analogous to the crafted TIFF fields in CVE-2017-9147 that made `_TIFFVGetField` read out of bounds) causes `clvm_buffer[offset]` to raise an unhandled `IndexError` inside the CPython bytes/memoryview object rather than a controlled `ValueError`.

### Impact Explanation
If the `IndexError` is not specifically caught by the mempool add-item pipeline (only `ValueError`/`Err`-style exceptions appear to be anticipated), a single crafted spend bundle submission can raise an unexpected exception during mempool processing, potentially aborting the add-spend-bundle task and disrupting transaction admission for the node processing it — a spend-triggered transaction-processing halt reachable from a normal unprivileged submitter, without needing malicious peers, farmers, or timelords.

### Likelihood Explanation
Likelihood is moderate: the code path is only exercised when the mempool attempts to classify a spend for DEDUP eligibility, and I was not able to fully trace, within the available tool budget, whether callers of `is_clvm_canonical` wrap this call in a broad `try/except` that would swallow an `IndexError` as a generic canonical-check failure. If such broad exception handling exists upstream, this degrades from a processing-halt bug to a benign "not canonical" classification; if it does not, the crash is trivially reproducible by any spend bundle submitter. This uncertainty should be resolved by inspecting the exact call site(s) of `is_clvm_canonical` in `mempool_manager.py`.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before reading each prefix byte and before returning `atom_len`, e.g., verify `offset + 1 + prefix_len <= len(clvm_buffer)` prior to the prefix-byte loop, and verify `offset + 1 + prefix_len + atom_len <= len(clvm_buffer)` before returning, raising a caught `ValueError` (consistent with the rest of the function) instead of allowing a raw `IndexError` to propagate. Add a matching bounds check in `is_clvm_canonical`'s loop before each `clvm_buffer[offset]` read.

### Proof of Concept
Construct a spend bundle whose coin solution buffer is a single non-canonical atom lead byte such as `0xC0` (5+8 bit length prefix indicator) followed by a truncated/absent length byte and no atom payload, e.g. `clvm_buffer = bytes([0xC0])`. Calling `is_clvm_canonical(clvm_buffer)` invokes `is_atom_canonical(clvm_buffer, 0)`, which enters the `prefix_len = 1` branch and executes `offset += 1; atom_len |= clvm_buffer[offset]` where `offset == 1 == len(clvm_buffer)`, raising `IndexError: index out of range` instead of a handled `ValueError`. Submitting a spend bundle whose solution serializes to such a buffer and is routed through the DEDUP-eligibility canonical check reproduces the unhandled exception during mempool processing.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

## Canonical serialization

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
