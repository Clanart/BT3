### Title
Unhandled `IndexError` in mempool canonical-CLVM check crashes/halts spend-bundle validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()`/`is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse an attacker-supplied `puzzle_reveal`/`solution` byte buffer to detect non-canonical CLVM atom-length prefixes, mirroring the bug class in CVE-2017-5482 (a parser reading past the end of an attacker-controlled buffer). The Python analog of an out-of-bounds read is an unhandled `IndexError`, and this code path is reachable directly from `MempoolManager.validate_spend_bundle()` on every submitted spend bundle, unguarded by a `try`/`except`.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the first byte at `offset` to determine a length-prefix size (`prefix_len`, 0–5 extra bytes), then loops reading `clvm_buffer[offset]` for each additional prefix byte, incrementing `offset` without ever checking that `offset` stays within `len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this atom-by-atom walk over the whole buffer, similarly never bounding `offset` against `len(clvm_buffer)` until after the loop naturally terminates (`tokens_left == 0`); if a length prefix byte signals more prefix/atom bytes than actually remain, the very next `clvm_buffer[offset]` access (either inside `is_atom_canonical`'s prefix loop or in the outer `while True: b = clvm_buffer[offset]`) indexes past the end of the buffer: [2](#0-1) 

This function is called directly on attacker-controlled bytes from every coin spend in a submitted `SpendBundle`, inside `validate_spend_bundle()`, with no exception handling around the call: [3](#0-2) 

A truncated multi-byte length-prefix atom (e.g. a single `0xC0` byte with no following byte, or any prefix byte whose declared `prefix_len` exceeds the remaining buffer length) triggers `bytes.__getitem__` to raise `IndexError: index out of range`, which is not a `ValueError`/`Err` the mempool pipeline expects to catch here.

### Impact Explanation
`validate_spend_bundle()` is invoked from `add_spend_bundle()`, which is called on the full-node's blockchain-lock-protected mempool admission path for every spend bundle received from RPC or the network. An unhandled `IndexError` propagating out of this synchronous validation step is not one of the recognized `Err`/`ValueError` outcomes the surrounding pipeline is built to convert into a graceful `MempoolInclusionStatus.FAILED`; depending on how far up the call stack the exception is caught (or not), a single malformed but otherwise well-formed spend bundle can raise an unexpected exception during mempool admission, which is a spend-triggered disruption of transaction processing consistent with the analog CVE-2017-5482 bug class (attacker-controlled buffer, malformed length-prefixed field, out-of-bounds parser access).

### Likelihood Explanation
Likelihood is high for a submitter who can construct or fetch this file's parsing logic: crafting a single truncated atom length-prefix byte (e.g., `0xC0`, `0xE0`, `0xF0`, `0xF8`, `0xFC` at the very end of a `puzzle_reveal` or `solution` buffer with no trailing bytes) is trivial and requires no privileged access — any wallet user or spend-bundle submitter can place this pattern in a `CoinSpend`'s puzzle or solution field and submit it via `push_tx`/RPC.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (verify `offset < len(clvm_buffer)` for every prefix byte read) and in `is_clvm_canonical()`'s main loop (verify `offset < len(clvm_buffer)` before reading `b = clvm_buffer[offset]`, and that the newly computed `offset` after an atom does not exceed `len(clvm_buffer)`), returning `False` (non-canonical/invalid) instead of letting Python raise `IndexError`. Alternatively, wrap the `is_clvm_canonical` calls in `validate_spend_bundle()` in a `try/except (IndexError, ...)` that maps to `Err.INVALID_COIN_SOLUTION`, matching the existing non-canonical rejection path.

### Proof of Concept
1. Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) serialized CLVM bytes end with a single `0xC0` byte and nothing after it (a 5+8-bit length-prefix marker claiming one more length byte follows, but the buffer ends there).
2. Wrap it in a `SpendBundle` and submit via the full node RPC `push_tx` (or local wallet spend) so it reaches `MempoolManager.add_spend_bundle()` → `validate_spend_bundle()`.
3. `is_clvm_canonical(bytes(coin_spend.solution))` is invoked at `mempool_manager.py:723`, which calls `is_atom_canonical(clvm_buffer, offset)`; the prefix-byte read loop executes `atom_len |= clvm_buffer[offset]` with `offset == len(clvm_buffer)`, raising `IndexError: index out of range` uncaught by the surrounding pipeline.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
