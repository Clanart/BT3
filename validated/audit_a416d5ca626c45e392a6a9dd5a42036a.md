### Title
Divide-by-zero panic in `KIP71Config.NextMagmaBlockBaseFee` when `kip71.gastarget` governance parameter is set to 0 - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking for zero, unlike the sibling `BaseFeeDenominator` field which is explicitly special-cased against zero. The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker`, meaning a value of `0` passes format validation and can be ratified through normal header-governance voting. Once ratified, every full node computing the next block's base fee (both when preparing and when verifying a header) hits a native `big.Int` division by zero, which panics the Go process. This is directly analogous to CVE-2021-46244 (division-by-zero DoS in `H5T__complete_copy`), but here the effect is a chain-wide crash of every full node rather than a single library call.

### Finding Description
`NextMagmaBlockBaseFee` explicitly guards against `BaseFeeDenominator == 0` by substituting a safe default: [1](#0-0) 

But it performs no equivalent guard for `GasTarget`: [2](#0-1) 

When the parent block's gas usage differs from `gasTarget`, the code divides by `gasTarget` directly: [3](#0-2) [4](#0-3) 

If `gasTarget == 0` and `parentGasUsed != 0` (the overwhelmingly common case, since any nonzero block gas usage exceeds a target of 0), the code takes the "gas used > target" branch and executes `x.Div(x, new(big.Int).SetUint64(0))`, which is a division by zero in Go's `math/big` package and panics the process. The special-case shortcuts (`parentGasUsed == gasTarget`, or `parentBaseFee` already at bound) only avoid the panic in the corner case where the parent block used zero gas.

`GasTarget` is a normal governance parameter (`kip71.gastarget`) reachable via on-chain header governance, and it has no format validation preventing zero: [5](#0-4) 

Compare this to `Kip71BaseFeeDenominator`, whose `FormatChecker` explicitly rejects zero: [6](#0-5) 

This asymmetry indicates the missing zero-check on `GasTarget` is an oversight, not an intentional design choice.

`NextMagmaBlockBaseFee` is invoked both when a proposer prepares the next header and, critically, when **every node** verifies a Magma-era header's `BaseFee` field: [7](#0-6) 

It is also called by the gas price oracle for `eth_feeHistory`/gas suggestions: [8](#0-7) 

### Impact Explanation
Because `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` runs on every full node during header verification of every post-Magma block, a `GasTarget = 0` ratification is a **network-wide, unrecoverable chain halt**: as soon as any block with nonzero gas usage is processed under the new parameter set, every honest node's process panics attempting to compute/verify the expected base fee. This is a denial-of-service condition affecting availability of the entire chain, not merely one connection or one node, and it also breaks the RPC gas price oracle (`node/cn/gasprice`) which calls the same function.

### Likelihood Explanation
Reaching this bug class requires only that `kip71.gastarget` be ratified to `0` through the normal header-governance voting mechanism, which enforces no lower bound or nonzero check on this parameter (unlike `BaseFeeDenominator`). In `single` governance mode (used on Mainnet/Kairos), only the designated governing node can cast the vote that gets ratified — but the vulnerability sits squarely in the explicitly in-scope "governance parameters" pathway, and the code contains **no defense at all** against this specific value once ratified, unlike the adjacent `BaseFeeDenominator` field which is defended. The bug is trivially triggerable (single vote + one ratification epoch) and its blast radius (every node crashes) is disproportionate to the low bar for triggering it.

### Recommendation
Add a zero-check for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing fallback used for `BaseFeeDenominator`:
```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    gasTarget = someSafeDefault // e.g. DefaultGasTarget
}
```
Additionally, update the `Kip71GasTarget` `FormatChecker` in `kaiax/gov/param.go` to reject `0` (and ideally reject any absurdly small values), consistent with `Kip71BaseFeeDenominator`'s existing check (`v != 0`), so that such a vote can never be ratified in the first place.

### Proof of Concept
1. On a chain in `single` governance mode, the governing node calls `governance_vote("kip71.gastarget", 0)`.
2. The vote is included in `header.Vote` by the governing node when it is the proposer, per the standard header-governance flow (`kaiax/gov/headergov`).
3. At the next epoch boundary, the vote is ratified into `header.Governance`, and the `kip71.gastarget` parameter set becomes `0` starting from the following epoch, since the `FormatChecker` (`noopFormatChecker`) does not reject `0`.
4. Starting from the first block of the new epoch that reports nonzero `GasUsed` in the parent header, every node calling `KIP71Config.NextMagmaBlockBaseFee` (via `VerifyMagmaHeader` during block verification, or via header preparation when proposing) executes:
   ```go
   gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // gasTarget == 0
   x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
   y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // division by zero -> panic
   ```
5. This panics on all full nodes attempting to process the block, resulting in a full-chain halt. [9](#0-8)

```go
func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
```
