### Title
Attacker-controlled `WWW-Authenticate` header spoofs host classification and downgrades secure GitHub/Enterprise credential handling to insecure Basic-Auth "generic" flow, exfiltrating credentials - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The Git credential-helper trampoline decides how to authenticate a remote host by inspecting `WWW-Authenticate` header values forwarded verbatim by the server through git's credential protocol. This is a naive substring/regex check on fully attacker-controlled data, analogous to the `AnyswapFacet` bug's blind trust in an external contract's `underlying()` return value: a single crafted value from an untrusted party (the remote git server) is used to make a security-relevant classification, and that classification short-circuits before the actual safety check (`isGitHubHost`) runs.

### Finding Description
In `getEndpointKind` ( [1](#0-0) ), after the unspoofable exact-domain checks for `github.com`/`ghe.com`, the function iterates over the credential map's `wwwauth[...]` entries: [2](#0-1) 

If a server response header contains the literal substring `realm="GitHub"`, the host is unconditionally classified `'enterprise'`. If it matches `realm="GitLab"|"Gitea"|"Atlassian Bitbucket"`, it's classified `'generic'`. Crucially, this check happens *before* the actual verification step, the network-based `isGitHubHost()` probe ( [3](#0-2) ), which is the mechanism actually designed to determine host trust via TLS/response-header validation with a real HTTP request. The `wwwauth[]` values themselves originate from raw `WWW-Authenticate` headers that git forwards to the credential helper via stdin, parsed with no validation in `parseCredential` ( [4](#0-3) ). A malicious or MITM'd server fully controls this value.

By emitting `WWW-Authenticate: Basic realm="Gitea"` (or `GitLab`/`Atlassian Bitbucket`), an attacker forces `getEndpointKind` to return `'generic'` for what may actually be a legitimate GitHub Enterprise-class host that the user hasn't yet added as an Account. This routes the flow in `getCredential` ( [5](#0-4) ) away from the internally-managed GitHub OAuth/token credential path and into `getGenericCredential`/`promptForCredential` ( [6](#0-5) ), which prompts the user for a plain username/password and, once entered, has git send it as HTTP Basic-Auth credentials directly over the connection to that (attacker-controlled/MITM) server via `storeCredential`'s generic path ( [7](#0-6) ).

### Impact Explanation
This corrupts the security-relevant value: **host trust classification** (`endpointKind`), the exact analog of the "underlying token" value corrupted in the AnyswapFacet bug. Instead of routing authentication through Desktop's safe internal account/token store, the attacker can force a downgrade to plaintext Basic-Auth credentials transmitted directly to the connection they control, resulting in credential/token exfiltration (a PAT or password the user believes is only used for their trusted GHE-like host). Existing guards, the exact-domain checks for `github.com`/`ghe.com` and the `isGitHubHost()` network probe, never execute for hosts that match the header-spoofing branch first, because the `wwwauth[]` check comes earlier in the function and returns immediately.

### Likelihood Explanation
Any git server (or network-level MITM/proxy in front of one, e.g. via a compromised submodule URL, a malicious fork's mirror remote, or a corporate-network attacker) that the user's Desktop client connects to over HTTP(S) can trivially emit an arbitrary `WWW-Authenticate` header on a 401 response, git's credential protocol will forward it verbatim. No local access, admin rights, or prior compromise of the host is required, only that the user attempts a fetch/push/clone against the attacker-influenced remote, an ordinary Desktop action.

### Recommendation
Do not trust `WWW-Authenticate` realm hints from the remote server as a basis for security classification. At minimum, treat them only as an optimization hint, and always corroborate with the exact-domain check or the `isGitHubHost()` network verification (checking `x-github-request-id`) before short-circuiting into either the `'enterprise'` or `'generic'` path. Never allow attacker-controlled header content to bypass the verified network probe.

### Proof of Concept
1. Stand up a plain HTTP(S) git server (or MITM proxy) at `https://internal-ghe.example.net` that is not registered as an Account in Desktop.
2. Configure it to respond to authentication challenges with `WWW-Authenticate: Basic realm="Gitea"`.
3. In Desktop, add this URL as a remote and perform a fetch/push.
4. Git invokes the `desktop` credential helper (`createCredentialHelperTrampolineHandler` in `trampoline-credential-helper.ts`) with a credential map containing `wwwauth[0]=Basic realm="Gitea"`.
5. `getEndpointKind` matches the Gitea regex and returns `'generic'` without ever calling `isGitHubHost()`.
6. `getCredential` falls through to `getGenericCredential` → `promptForCredential`, presenting a generic sign-in dialog instead of the internally-secured GitHub Enterprise flow.
7. The username/password entered by the user is handed to git and transmitted via HTTP Basic Auth directly to the attacker/MITM-controlled server connection.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}
