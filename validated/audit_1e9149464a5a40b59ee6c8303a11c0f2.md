### Title
Missing timestamp freshness check allows indefinite replay of valid app-proxy signed requests - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Finding Description
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies an app-proxy request solely by recomputing an HMAC over the sorted query parameters (excluding `signature`) and comparing it via `ActiveSupport::SecurityUtils.secure_compare` to the supplied `signature`. [1](#0-0) 
The `timestamp` parameter that Shopify includes in every app-proxy request is treated like any other ordinary parameter folded into the HMAC input — it is never compared against the current time or checked for staleness. [2](#0-1) 
`verify_proxy_request` only calls `query_string_valid?` and returns `403` on failure; there is no other before_action, nonce store, or timestamp-window check anywhere in this concern. [3](#0-2) 

Because the signature is a deterministic function of the query parameters (including the old `timestamp` value) and the shared app secret, a `(query_string, signature)` pair captured once (e.g., from a browser network log, proxy log, referrer leakage, or a shared/public link containing the signed query string) remains valid forever and can be replayed against the same app-proxy route an unlimited number of times.

### Impact Explanation
Any state-changing app-proxy endpoint protected only by this concern (e.g., endpoints that write data, consume credits, or trigger notifications) can be invoked repeatedly by any party who obtains one previously-valid proxy URL, without needing the app secret, a live Shopify session, or any of the JWT/session-token checks used elsewhere in the gem. This falls under improper request validation leading to replay-triggered unauthorized/duplicate actions in app-proxy handlers — a lower-severity design gap since it requires possession of a previously issued signed URL rather than forging a new one, but it defeats the "one-time, freshness-bound instruction" guarantee that HMAC+timestamp app-proxy verification is intended to provide.

### Likelihood Explanation
Exploitability requires the attacker to first obtain one valid, complete `(query_string, signature)` pair (e.g., via browser history, logs, or a link shared out of its original context) — no secret or victim credentials are needed beyond that. Once obtained, replay is trivial and fully repeatable indefinitely since nothing in `query_string_valid?` depends on wall-clock time or a used-signature cache.

### Recommendation
Add an explicit freshness check: parse `query_hash["timestamp"]`, reject requests where it is missing or outside an acceptable window (e.g., a few minutes) of the current time, and reject as soon as HMAC verification has been rebuilt to compare after extracting/validating the timestamp — mirroring Shopify's own guidance for OAuth/webhook HMAC timestamp validation. Optionally also track/deduplicate recently seen signatures to prevent replay within the freshness window.

### Proof of Concept
```ruby
class AppProxyController < ActionController::Base
  include ShopifyApp::AppProxyVerification
  def index
    # side effect, e.g. increments a counter
    head :ok
  end
end

test "a valid but stale (query_string, signature) pair can be replayed indefinitely" do
  old_timestamp = 10.days.ago.to_i
  query_hash = { "shop" => "test-shop.myshopify.com", "timestamp" => old_timestamp.to_s, "path_prefix" => "/apps/test" }
  signature = OpenSSL::HMAC.hexdigest(OpenSSL::Digest.new("sha256"), ShopifyApp.configuration.secret,
    query_hash.collect { |k, v| "#{k}=#{v}" }.sort.join)
  query_string = query_hash.merge(signature: signature).to_query

  3.times do
    get "/apps/test?#{query_string}"
    assert_response :success # accepted every time, no expiry enforcement
  end
end
```

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
