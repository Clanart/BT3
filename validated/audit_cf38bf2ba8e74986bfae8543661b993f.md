### Title
Unprivileged co-signer can panic `TransactionSignatureMachine::complete` with a truncated share vector, aborting Bitcoin transaction signing - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
CVE-2019-9003 is a concurrency-triggered kernel OOPS (availability impact). The Serai analog is an unvalidated-indexing panic in Bitcoin transaction signature aggregation: `TransactionSignatureMachine::complete` calls `shares.remove(0)` once per transaction input on each participant's `Vec<SignatureShare<Secp256k1>>` without checking the vector length. A participant who supplies a share vector shorter than the number of transaction inputs (including an empty vector) causes `Vec::remove(0)` on an empty vector to panic, crashing the signing routine after shares have already been committed. This is reachable purely through untrusted bytes fed to `read_share` / `complete`, the exact input surfaces in scope.

### Finding Description
`TransactionSignMachine::sign` produces one `SignatureShare` per transaction input, so a well-formed `SignatureShare = Vec<SignatureShare<Secp256k1>>` has `tx.input.len()` elements. `read_share` parses a per-input vector from the peer's serialized bytes, imposing no length equality with `self.tx.input.len()`: [1](#0-0) . `complete` then iterates over every input and pops one element per input from each participant's vector: [2](#0-1) . `shares.remove(0)` panics on an empty `Vec`, so a peer whose vector has `k < inputs` elements crashes the process at input index `k`. Note the panic happens inside the `zip`/`map` argument evaluation before `schnorr.complete` runs, so no error path handles it — it is an unconditional `panic!` under attacker control.

### Impact Explanation
Any threshold participant (or anyone able to inject share bytes into the aggregation step) can deterministically abort transaction completion, an availability failure on the Bitcoin signing path. Because the panic occurs while processing already-received shares, it can be repeated on every retry, wedging a withdrawal/batch that requires that signing set. This mirrors the CVE's impact class (attacker-triggered OOPS/DoS) without requiring any protocol-level collusion, broken BFT, or leaked secrets — only malformed untrusted input bytes.

### Likelihood Explanation
Requires only that the attacker be a signing participant for a transaction, or otherwise control bytes passed to `read_share`/`complete`. Constructing a short vector is trivial — `read_share` returns whatever number of elements successfully parse, and nothing validates `shares[l].len() == self.sigs.len()` before `remove(0)` is called. There is no cryptographic hurdle, timing window, or privileged position needed.

### Recommendation
In `TransactionSignatureMachine::complete` (networks/bitcoin/src/wallet/send.rs:413-425), validate each participant's vector length against `self.sigs.len()` before consuming elements — e.g., reject with `FrostError::InvalidShare(l)` when `shares.len() != self.sigs.len()`, or use `Vec::pop`/iterator `next()` with an explicit error instead of `remove(0)` on a potentially empty vector. Ideally `read_share` should already enforce that the parsed vector length equals the number of inputs so malformed encodings are rejected at parse time.

### Proof of Concept
Conceptual trigger (no memory unsafety needed):

1. A `SignableTransaction` is built with `N ≥ 2` inputs and `multisig(keys)` produces `TransactionSignMachine` with `N` `AlgorithmSignMachine`s.
2. During the share round, the attacker serializes a `Vec<SignatureShare<Secp256k1>>` containing fewer than `N` elements (e.g., `N - 1` valid 32-byte scalars, or zero elements).
3. The victim's `TransactionSignatureMachine::read_share` successfully parses the short vector since it does not compare against `self.sigs.len()` (send.rs:409-411).
4. `complete` iterates `self.tx.input.iter_mut().zip(self.sigs.drain(..))` and evaluates `shares.remove(0)` per input (send.rs:419); at input index `k` equal to the attacker's vector length, `remove(0)` is invoked on an empty `Vec`, panicking and aborting signature completion.
