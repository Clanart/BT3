### Title
Gasless block proposer bears unrecoverable "bad debt" when the fee-repaying SwapTx reverts after the fee-lending transaction already transferred value - (File: kaiax/gasless/impl/builder.go)

### Summary
The gasless (KIP-247) flow unconditionally transfers real KAIA from the block proposer to a gasless user via a `LendTxGenerator` transaction placed before the user's `GaslessApproveTx`/`GaslessSwapTx`, expecting repayment to occur inside `swapForGas`. If the swap fails on-chain (e.g. due to price movement between mempool-admission checks and actual block execution), the lend transfer is not reverted, but the repayment never happens, leaving the proposer with an unrecoverable loss that the protocol has no mechanism to redistribute or account for — the same "bad debt is never handled" bug class as the external report, mapped onto Kaia's gasless module.

### Finding Description
The gasless module lends gas fees to a user and expects the swap transaction to repay the lender: [1](#0-0) 

The bundle building logic prepends the lend transaction before the user's approve/swap transactions: [2](#0-1) 

`lendAmount`/`repayAmount` compute the fixed KAIA amount the proposer fronts and the amount the swap is expected to return: [3](#0-2) 

The only protections against the swap failing to produce enough output are checked once, at tx-pool admission time, using the state at that moment: [4](#0-3) 

Crucially, the module explicitly disables the sender balance check for gasless transactions: [5](#0-4) 

Because `checkBalanceForSwap`'s `GetAmountIn`/allowance/balance checks are evaluated against a snapshot state (during tx-pool promotion), and the actual on-chain execution happens later at block-building/execution time, the AMM reserves referenced by `GetAmountIn` can shift (from any other transaction preceding this bundle in the same block, or from blocks mined between admission and inclusion). If the reserves move unfavorably, `swapForGas` will revert its internal `minAmountOut` check inside the `GaslessSwapRouter` contract (`SwapForGas`, bound in `contracts/bindings/kip247/GaslessSwapRouter.go`), causing the entire `GaslessApproveTx`/`GaslessSwapTx` execution to revert and fail to transfer `amountRepay` back to the proposer/router. However, the `LendTxGenerator` transaction is a plain, unconditional value transfer that is not contingent on the swap's success — it is simply the first transaction in the bundle, and nothing in `ExtractTxBundles` or `NewBundle` (`TargetRequired`, `IsConflict`) enforces that the lend is reverted or clawed back if the paired swap transaction reverts: [6](#0-5) 

As a result, the proposer's lent KAIA becomes unrecoverable "bad debt" with no reserve, redistribution, or accounting mechanism defined anywhere in the module (no such mechanism appears in `kaiax/gasless/README.md` or the `impl` package), mirroring the exact gap described in the external report: the lending/liquidity provider (here, the block proposer) can be left holding a loss that the protocol never handles.

### Impact Explanation
Every block proposer running the gasless module is exposed to guaranteed value loss (the lent gas amount) whenever a `GaslessSwapTx` reverts after admission-time checks passed but before/at execution time. Because this can be triggered by ordinary market conditions (price movement) or by an adversarial actor deliberately front-running the swap's expected exchange rate within the same block window, this is a repeatable and directly exploitable value-extraction vector against the proposer, not a rare edge case. Given that this affects every CN running the gasless feature and is uncompensated (no reserve/backstop mechanism), the impact is Medium-High: honest proposers suffer direct, unrecoverable financial loss driven by an unprivileged public transaction sender's swap/approve transaction pair.

### Likelihood Explanation
Likelihood is Medium-High: any public user (or MEV searcher) can submit a `GaslessApproveTx`/`GaslessSwapTx` pair with `minAmountOut` set just above `amountRepay` (the minimum allowed by `checkBalanceForSwap`'s `minAmountOut >= amountRepay` rule), then place or wait for a market-moving trade to land ahead of their bundle in the block, causing `swapForGas`'s internal slippage check to fail. Because the sender-balance check is explicitly waived for gasless txs and the only slippage validation happens once at pool-admission time against a state that can go stale, this scenario does not require any privileged access — only ordinary transaction submission capability.

### Recommendation
Introduce a mechanism to prevent or account for this "bad debt": e.g. (1) make the lend and repayment atomic within the same enforced bundle so that if the swap reverts, the lend transaction is also invalidated/not included; (2) re-validate `checkBalanceForSwap` conditions immediately before block inclusion using the exact pre-state of the block being built, not a stale admission-time snapshot; (3) require the `GaslessSwapRouter` to escrow or claw back the lent amount from the sender's other assets on swap failure; or (4) explicitly document and fund a proposer-loss reserve (analogous to a bad-debt treasury) to cover unrecoverable lends, as suggested for BendDAO.

### Proof of Concept
1. User submits `GaslessApproveTx` (nonce N) and `GaslessSwapTx` (nonce N+1) with `Token=T`, `AmountIn`, `MinAmountOut = AmountRepay` (the minimum allowed by `checkBalanceForSwap`).
2. At tx-pool admission time, `checkBalanceForSwap` computes `requiredAmountIn = GetAmountIn(token, minAmountOut)` against the current AMM reserves and passes because `AmountIn >= requiredAmountIn`. [7](#0-6) 
3. Before this bundle is executed within the block being built (or in a subsequent block if not yet included), a large trade shifts token `T`'s AMM reserves against the pending swap.
4. The proposer's block-building logic still bundles `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` per `ExtractTxBundles`. [2](#0-1) 
5. `LendTxGenerator`'s transaction (a plain KAIA transfer of `lendAmount`) executes and succeeds unconditionally.
6. `GaslessSwapTx` calls `swapForGas`, which now reverts on-chain because the achievable output is below `MinAmountOut`.
7. The lent KAIA is never repaid to the proposer, and no code path in `kaiax/gasless` recovers or accounts for this loss.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

type Bundle struct {
	// each element can be either *types.Transaction, or TxGenerator
	BundleTxs []*TxOrGen

	// BundleTxs is placed AFTER the target tx. If empty hash, it is placed at the very front.
	TargetTxHash common.Hash

	// TargetRequired is true if the bundle must be executed after the target tx
	// and only if the target tx is successfully executed.
	TargetRequired bool

	// lookup map for O(1) membership checks (lazy initialized)
	txLookup map[common.Hash]int
}

func NewBundle(txs []*TxOrGen, targetTxHash common.Hash, targetRequired bool) *Bundle {
	b := &Bundle{
		BundleTxs:      txs,
		TargetTxHash:   targetTxHash,
		TargetRequired: targetRequired,
	}
	b.buildLookup()
	return b
}
