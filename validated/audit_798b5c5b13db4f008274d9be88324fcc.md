### Title
Unbounded atom length-prefix walk in mempool canonical-serialization check causes attacker-triggered crash - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk a raw CLVM byte buffer using attacker-controlled length-prefix bytes without ever checking that the computed offsets stay within the buffer bounds, mirroring the Pillow `TiffDecode.c` bug class where an out-of-bounds read is reached via invalid/attacker-influenced tile boundary values that are trusted without a bounds check.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine a multi-byte length-prefix encoding, then for `prefix_len` iterations increments `offset` and reads `clvm_buffer[offset]` again to accumulate `atom_len`: [1](#0-0) 

None of these reads validate that `offset` (or `offset + prefix_len`) is less than `len(clvm_buffer)` before indexing. The caller, `is_clvm_canonical()`, loops over the whole buffer calling `is_atom_canonical()` whenever it encounters an atom-header byte, again without any length check before dereferencing: [2](#0-1) 

Both functions operate directly on the raw bytes of a spend bundle's puzzle reveal / solution — data fully controlled by the submitter of a spend bundle. Per the accompanying architectural notes, `is_clvm_canonical()` is invoked during mempool processing specifically to decide whether a spend is eligible for dedup handling, i.e., it runs on every incoming spend bundle's CLVM buffer as part of normal mempool admission, not on any already-validated/trusted data. A spend bundle can be crafted so that a multi-byte atom length-prefix header byte (e.g. `0xF8`, `0xFC`, etc.) appears as the very last byte(s) of the buffer, so that the prescribed number of continuation bytes runs past the end of the buffer. In Python, indexing `bytes`/`bytearray` past the end of the object raises `IndexError` rather than reading adjacent memory (so this is not a memory-disclosure bug like the C-level Pillow OOB read), but the uncaught exception propagates out of the canonical-serialization check during spend-bundle processing.

### Impact Explanation
Because `is_clvm_canonical()`/`is_atom_canonical()` run during standard spend-bundle admission (dedup-eligibility determination) with no bounds validation, a single malicious but syntactically-plausible spend bundle can trigger an unhandled `IndexError` inside the mempool manager's spend-bundle processing path. Depending on how far up the call stack this exception is caught, this is a spend-triggered transaction-processing halt: it can disrupt admission of that spend bundle (and potentially the batch/task processing it), which is an explicitly in-scope impact per the report's validation criteria (denial of mempool/transaction processing triggered by a single submitted spend bundle).

### Likelihood Explanation
Likelihood is high for triggering the code path: any unprivileged party can submit a spend bundle to a full node's mempool RPC or via the P2P transaction protocol, and crafting a puzzle reveal/solution whose serialized CLVM bytes end mid-way through a multi-byte atom length prefix is straightforward and requires no special permissions, signatures beyond what a normal spend bundle needs, or race conditions.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (raising a normal parse failure / returning "not canonical" instead of indexing past the buffer), and add an equivalent guard in `is_clvm_canonical()`'s main loop before it reads `clvm_buffer[offset]`, so that truncated/malformed atom headers are rejected cleanly (e.g. treated as non-canonical or as a parse error caught by the caller) rather than raising an unguarded `IndexError` from attacker-supplied data.

### Proof of Concept
1. Construct a spend bundle whose coin spend solution/puzzle-reveal CLVM bytes end with a byte matching one of the multi-byte atom-length-prefix patterns handled in `is_atom_canonical()` (e.g. `0b11110000` pattern, requiring 3 additional length bytes) as the very last byte of the buffer, i.e. `buffer[-1] == 0xF0` with no trailing bytes.
2. Submit the spend bundle to a full node (via RPC `push_tx` or the transaction protocol) so it enters `MempoolManager` processing and reaches the dedup-eligibility canonical-serialization check that calls `is_clvm_canonical()` on this buffer.
3. `is_atom_canonical()` will attempt to read `clvm_buffer[offset]` past the end of the buffer while accumulating `atom_len`, raising an unhandled `IndexError` inside the mempool processing path instead of gracefully rejecting the malformed spend. [3](#0-2)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
