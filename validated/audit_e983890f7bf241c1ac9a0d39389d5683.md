### Title
`fetch_validate_and_store_lcp` Returns Stale Light Client Proof When `payout_block_height` Changes — (`core/src/citrea.rs`)

### Summary

`fetch_validate_and_store_lcp` caches the Light Client Proof (LCP) receipt keyed only by `deposit_id`, completely ignoring the `payout_block_height` argument on cache hits. The underlying `insert_lcp_for_assert` SQL uses `ON CONFLICT (deposit_id) DO NOTHING`, making the first-stored LCP permanent and immutable. If the operator's payout transaction is re-confirmed at a different L1 block height (e.g., after a Bitcoin reorg), every subsequent call for that deposit silently returns the stale LCP from the original height. The stale LCP's embedded `last_l2_height` is then used to fetch a storage proof against the wrong L2 state, producing an assert transaction whose bridge-circuit proof is internally inconsistent and disprovable.

### Finding Description

In `core/src/citrea.rs`, `fetch_validate_and_store_lcp` is called by the operator's automation to obtain the LCP needed to construct the assert transaction:

```rust
// core/src/citrea.rs  lines 326-361
async fn fetch_validate_and_store_lcp(
    &self,
    payout_block_height: u64,   // ← the actual L1 height of the payout tx
    deposit_index: u32,
    db: &Database,
    ...
) -> Result<Receipt, BridgeError> {
    let saved_data = db
        .get_lcp_for_assert(dbtx.as_deref_mut(), deposit_index)  // keyed by deposit_id ONLY
        .await?;
    if let Some(lcp) = saved_data {
        return Ok(lcp);   // ← returns immediately; payout_block_height is NEVER checked
    };
    // only reached on first call
    let lcp_result = self.get_light_client_proof(payout_block_height, paramset).await?;
    ...
    db.insert_lcp_for_assert(dbtx, deposit_index, lcp_receipt.clone()).await?;
    Ok(lcp_receipt)
}
```

`ON CONFLICT … DO NOTHING` means the stored LCP is never refreshed, regardless of how many times the function is called with a different `payout_block_height`.

The stale LCP is then consumed directly in `operator.rs`:

```rust
// core/src/operator.rs  lines 1315-1336
let lcp_receipt = self.citrea_client
    .fetch_validate_and_store_lcp(payout_block_height as u64, deposit_idx as u32, ...)
    .await?;
let proof_output: LightClientCircuitOutput =
    borsh::from_slice(&lcp_receipt.journal.bytes)?;
let l2_height = proof_output.last_l2_height;   // ← wrong height from stale LCP
let storage_proof = self.citrea_client
    .get_storage_proof(l2_height, deposit_idx as u32)   // ← proof for wrong L2 state
    .await?;
```

### Impact Explanation

The assert transaction bundles the LCP receipt and a storage proof that must be consistent with each other: the storage proof must be rooted in the L2 state committed to by the LCP. When the LCP is for L1 height H1 but the payout was confirmed at H2 ≠ H1, the `last_l2_height` extracted from the stale LCP is wrong, the storage proof is fetched against the wrong L2 state root, and the resulting assert is internally inconsistent. A watchtower or verifier can disprove the assert, causing the operator to lose their entire collateral deposit — a material, irreversible loss of bridged BTC collateral.

### Likelihood Explanation

The trigger is a Bitcoin reorg that moves the operator's payout transaction from block H1 to block H2. Bitcoin reorgs of 1–2 blocks occur naturally on mainnet and are common on testnet4. The operator's automation will call `fetch_validate_and_store_lcp` again after detecting the reorg, but the `ON CONFLICT DO NOTHING` guard silently returns the stale H1 LCP. Because the bug is in the caching layer and not in any per-call validation, the operator has no indication that the wrong LCP is being used.

### Recommendation

Change the cache key from `deposit_id` alone to `(deposit_id, payout_block_height)`:

1. Add a `payout_block_height` column to `lcp_for_asserts` and make the primary key `(deposit_id, payout_block_height)`.
2. Pass `payout_block_height` to `get_lcp_for_assert` and `insert_lcp_for_assert` and include it in the `WHERE` / `ON CONFLICT` clauses.
3. In `fetch_validate_and_store_lcp`, only return the cached LCP when both `deposit_id` and `payout_block_height` match.

### Proof of Concept

1. Deposit is processed; operator's payout tx is confirmed at L1 height H1.
2. `fetch_validate_and_store_lcp(H1, deposit_idx)` is called → LCP for H1 is fetched and stored in `lcp_for_asserts` with key `deposit_idx`.
3. A 1-block Bitcoin reorg occurs; the payout tx is re-confirmed at L1 height H2 (H2 ≠ H1).
4. The operator's automation detects the new confirmation height and calls `fetch_validate_and_store_lcp(H2, deposit_idx)`.
5. `get_lcp_for_assert(deposit_idx)` finds the row from step 2 and returns the H1 LCP immediately — `payout_block_height = H2` is never consulted.
6. `proof_output.last_l2_height` is the L2 height corresponding to H1, not H2.
7. `get_storage_proof(l2_height_from_H1, deposit_idx)` returns a proof rooted in the H1 L2 state.
8. The assert transaction is broadcast with an LCP for H1 and a storage proof for H1's L2 state, while the on-chain payout is at H2.
9. A watchtower disproves the assert; the operator's collateral is slashed. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    async fn fetch_validate_and_store_lcp(
        &self,
        payout_block_height: u64,
        deposit_index: u32,
        db: &Database,
        mut dbtx: Option<DatabaseTransaction<'_>>,
        paramset: &'static ProtocolParamset,
    ) -> Result<Receipt, BridgeError> {
        let saved_data = db
            .get_lcp_for_assert(dbtx.as_deref_mut(), deposit_index)
            .await?;
        if let Some(lcp) = saved_data {
            // if already saved, do nothing
            return Ok(lcp);
        };

        let lcp_result = self
            .get_light_client_proof(payout_block_height, paramset)
            .await?;
        let (_lcp, lcp_receipt, _l2_height) = match lcp_result {
            Some(lcp) => lcp,
            None => {
                return Err(eyre::eyre!(
                    "Light client proof could not be fetched found for block height {}",
                    payout_block_height
                )
                .into())
            }
        };

        // save the LCP for assert
        db.insert_lcp_for_assert(dbtx, deposit_index, lcp_receipt.clone())
            .await?;

        Ok(lcp_receipt)
    }
