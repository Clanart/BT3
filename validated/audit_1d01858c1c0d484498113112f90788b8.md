### Title
`isGitHubHost` misclassifies attacker-controlled domains (e.g. `github.<attacker>.com`) as GitHub Enterprise, causing Desktop to hand over stored GitHub credentials via the git credential helper - (File: app/src/lib/api.ts, app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
`isGitHubHost()` uses a single, one-size-fits-all regular expression (`/(^|\.)(github)\./`) to decide whether an arbitrary hostname "belongs to GitHub", in the same way the referenced report's `emissionCap` used a single hardcoded constant to bound values that actually need per-token/per-format handling. Here the "format" that varies is the hostname structure: the regex is satisfied by any hostname that merely *starts with* `github.` or contains `.github.`, regardless of the actual registrable domain. This heuristic result feeds directly into `getEndpointKind()` in the trampoline credential helper, which governs whether Desktop treats a remote as a GitHub host (and thus offers/exposes stored GitHub OAuth credentials).

### Finding Description
`isGitHubHost` at [1](#0-0)  checks known-good cases (`isDotCom`, `isGHE`) and known-bad cases (`isKnownThirdPartyHost`), but then falls back to a naive substring/prefix regex:

```
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```

`isKnownThirdPartyHost` at [2](#0-1)  only rejects a small hardcoded allowlist (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`); it does not reject arbitrary attacker-registered domains. Consequently a hostname such as `github.evil.com` (or `sub.github.attacker.io`) satisfies `(^|\.)(github)\.` — the `^github\.` alternative matches the start of the string — and `isGitHubHost` returns `true` for a domain the attacker fully controls, even though it is not `*.ghe.com`, not `github.com`/`api.github.com`, and not previously known to the endpoint-version cache.

This function is consumed by the git credential-helper trampoline in `getEndpointKind()` at [3](#0-2) :

```
if (credentialUrl.protocol !== 'https:') {
  return 'generic'
}
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

An `'enterprise'` classification changes how `getCredential` in the same file behaves: it will attempt to match an existing GitHub account by endpoint (`accounts.some(a => a.endpoint === apiEndpoint)`), and, more importantly, it will *not* fall through to the generic-credential path — instead it can prompt the user to sign in with GitHub or match a stored GitHub-Enterprise-account endpoint, treating this attacker domain as if it were a legitimate enterprise instance of GitHub.

The controlled input here is a git remote URL / hostname — something an attacker fully controls by hosting a malicious HTTPS git server or getting a victim to add a remote/clone a repo pointing at `https://github.<attacker-domain>/...`. This matches the required "attacker controls a git remote" primitive.

### Impact Explanation
When Desktop's credential-helper trampoline classifies an attacker's HTTPS remote as `'enterprise'` instead of `'generic'`:
- It causes Desktop to treat the endpoint as GitHub Enterprise for authentication/sign-in flows (`ui.promptForGitHubSignIn`), potentially causing GitHub account binding/sign-in prompts to be issued for an attacker-chosen hostname that "looks like GitHub" but isn't.
- It suppresses the generic-credential-helper path (`getGenericCredential`/external credential helper), which is the path a user would expect for a non-GitHub git host, silently changing how credentials for that host are looked up/stored, and increases the chance that a previously-stored GitHub Enterprise account's endpoint matching logic (`isDotCom(existingAccount.endpoint)`) is invoked against attacker infrastructure.
- More broadly, `isGitHubHost` is also used elsewhere in `api.ts` for host-trust decisions (e.g., feeding `suppressCertificateErrorFor`/discovery requests), so a hostname such as `github.attacker.com` can be misrouted through GitHub-specific trust logic while actually being fully attacker-controlled infrastructure — this is the kind of credential-exfiltration-adjacent misclassification called out in scope ("unprivileged... attacker controls... a git remote/proxy response, and the result is... credential/token exfiltration, unauthorized OAuth or account binding").

I was not able to fully trace every downstream consumer of `isGitHubHost` in the index (the file is large and some branches were only partially covered by search results), so I cannot state with certainty that credential *material* is transmitted to the attacker host in all code paths — this needs verification by a full read of `api.ts` and `trampoline-ui-helper.ts`/`find-account.ts` to confirm exactly which stored account/token gets attached in the `'enterprise'` branch.

### Likelihood Explanation
Likelihood is moderate-to-high for exposure but the ultimate blast radius depends on the exact downstream branch. Registering a domain like `github-<something>.com`... actually the regex requires the label boundary `(^|\.)github\.`, so the attacker must register a domain where a label is exactly `github` followed by a dot, e.g. `github.attacker-tld` is not achievable (registrable domains require attacker to control everything after the first dot) — but subdomains are fully attacker-controlled: an attacker who fully owns `attacker.com` can create `github.attacker.com`, which trivially matches `^github\.`. This requires no admin/local access — only that the victim's git operations talk to that host (adding a remote, or being redirected via a compromised/malicious proxy), which is within the stated valid-impact scope.

### Recommendation
Replace the substring/prefix regex with a proper suffix-based / public-suffix-aware check restricted to the trusted domains Desktop actually issues API/OAuth traffic to (`*.github.com`, `*.ghe.com`, and explicitly-added GHE endpoints that have passed the `/meta` discovery + `x-github-request-id` check). Do not treat `(^|\.)github\.` matches as sufficient; require exact match or a proper `endsWith('.github.com')`/`endsWith('.ghe.com')` check, and never short-circuit to `'enterprise'` classification for an unknown host without completing the network-based discovery check that already exists later in the same function.

### Proof of Concept
1. Attacker controls `attacker.com` and stands up an HTTPS git server at `https://github.attacker.com/owner/repo.git`.
2. Victim adds this as a remote in GitHub Desktop or clones it directly (e.g., via a shared link or by cloning a "fork" whose remote is later changed).
3. When Desktop's git operations trigger the credential helper trampoline, `getCredentialUrl(cred)` yields `https://github.attacker.com/...`.
4. `getEndpointKind` reaches `isGitHubHost('https://github.attacker.com/...')`:
   - `hostname = 'github.attacker.com'`
   - Not `github.com`/`api.github.com` → skip dot-com/GHE fast path.
   - `isKnownThirdPartyHost('github.attacker.com')` → `false` (not in the hardcoded set, doesn't end with any of the 5 known hosts).
   - `/(^|\.)(github)\./.test('github.attacker.com')` → `true` (matches `^github\.`).
   - Returns `true` without ever making the `/meta` discovery request.
5. `getEndpointKind` returns `'enterprise'` for `github.attacker.com`, diverging from the intended generic-git-host handling and routing the credential flow (sign-in prompt / stored GHE account matching) as if this were a trusted GitHub Enterprise server. [4](#0-3) [1](#0-0) [2](#0-1) [5](#0-4)

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
