### Title
Data Layer mirror URLs enable Server-Side Request Forgery via unauthenticated wallet mirror creation - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet holding funds can create a Data Layer "mirror" record with arbitrary attacker-chosen URL strings via the `dl_new_mirror` wallet RPC (or CLI `chia data add_mirror`). Those URLs are stored in a coin memo on-chain (via `create_new_mirror` → `Mirror`/`create_mirror_puzzle` memo) with no scheme, host, or network-location restriction. Any Data Layer node subscribed to that store id will later read the mirror URLs and issue outbound HTTP requests to them, without validating that the URL points to a safe, external, expected server. This is a classic analog to the gibbon `gibbon` SSRF (CVE-2022-27311): an attacker-controlled URL supplied through a legitimate application feature is dereferenced server-side without restriction.

### Finding Description
`DataLayerWallet.create_new_mirror()` accepts a caller-supplied list of URL bytes and puts them straight into the mirror coin's memos with no validation of scheme or destination: [1](#0-0) 

The RPC entrypoint `dl_new_mirror` in `WalletRpcApi` passes the request's raw `urls` straight through `Mirror.encode_urls()` to `create_new_mirror()` with no sanitization: [2](#0-1) 

Once that spend confirms on-chain, any DataLayer service subscribed to (or owning/mirroring) that `store_id` retrieves the mirror URLs from wallet RPC and stores them in `data_store` via `update_subscriptions_from_wallet()`, with only trailing-slash trimming — no host/scheme allow-listing: [3](#0-2) 

During the periodic sync loop, `fetch_and_validate()` picks a server from `get_available_servers_for_store()` (populated from those same untrusted mirror URLs) and performs outbound requests against it — either a plain HTTP GET via `http_download()`/`download_file()`, or a POST to `<url>/handle_download` through `get_downloader()`: [4](#0-3) [5](#0-4) [6](#0-5) 

None of these code paths restrict the target host to public/allow-listed addresses (e.g., blocking loopback, link-local, RFC1918 private ranges, or the cloud metadata IP `169.254.169.254`). The only mitigations present are unrelated to SSRF: content-length caps (`max_delta_file_size`) and per-server ban/backoff logic after failures (`server_misses_file`).

### Impact Explanation
This is Server-Side Request Forgery: an unprivileged remote actor who can fund a small spend (create a mirror coin, cost is only the mirror `amount` + fee) can force any Data Layer node that later subscribes to that store to issue arbitrary outbound HTTP GET/POST requests to attacker-chosen hosts and ports — including internal-network services, the local RPC server, cloud metadata endpoints, or other locally-bound daemons (e.g. `127.0.0.1:<rpc_port>`), potentially triggering authenticated local RPC actions if any local service does not require additional auth, and at minimum enabling internal network reconnaissance/port-scanning and denial-of-service on the DL node's outbound resources. Because Data Layer mirror discovery/subscription is a routine, automatic mechanism (`periodically_manage_data()` syncs from wallet-recorded mirrors), no direct interaction from the victim operator is required beyond having previously subscribed to (or owning) the targeted store.

### Likelihood Explanation
Likelihood is high for any node that participates in Data Layer subscriptions: mirror creation is a normal, unauthenticated (from the node's perspective — merely a funded spend) wallet operation, and mirror URLs propagate automatically to all subscribers through the DL sync loop with no allow-list or private-IP filtering. The victim node has to be actively subscribed to the malicious store, which is a normal Data Layer usage pattern for taking offers / consuming public datasets, so exposure is realistic in intended usage.

### Recommendation
Validate and sanitize all mirror/server URLs before they are stored or dereferenced:
- Enforce `http://`/`https://` scheme only.
- Resolve the hostname and reject requests to loopback, link-local, private (RFC1918), multicast, and cloud metadata addresses unless explicitly allow-listed by the operator.
- Apply the same validation both when persisting subscription URLs (`data_layer.py update_subscriptions_from_wallet`, `add_mirror`) and immediately before making the outbound request in `download_data.py` (`http_download`, `download_file`) and `get_downloader`/`get_uploaders` in `data_layer.py`, since URLs can also arrive directly through those paths without re-validation at fetch time.
- Consider disabling automatic following of redirects to externally-supplied hosts, and add a configurable network egress allow-list for the Data Layer HTTP client.

### Proof of Concept
1. Attacker funds a small XCH balance and calls the wallet RPC:
   `dl_new_mirror { "id": "<attacker's store_id>", "amount": 1, "urls": ["http://169.254.169.254/latest/meta-data/", "http://127.0.0.1:<victim_rpc_port>/get_routes"] , "fee": 0 }`
   (mirroring `DLNewMirror` usage as exercised in tests) [7](#0-6) 
2. Once confirmed, any victim node calls `dl track_new <attacker's store_id>` or otherwise subscribes/mirrors that store.
3. The victim's `DataLayer.periodically_manage_data()` loop calls `update_subscriptions_from_wallet()` to pull the attacker URLs into local subscription state [3](#0-2) , then `fetch_and_validate()` issues an outbound request to the attacker-chosen host/port via `http_download()`/`get_downloader()` [8](#0-7) .
4. The victim's Data Layer process makes the SSRF request to the internal/metadata target chosen by the attacker.

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
