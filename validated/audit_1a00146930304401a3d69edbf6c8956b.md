## Finding

### Title
Unvalidated `foldername` parameter allows arbitrary-path file write via DataLayer RPC `add_missing_files` - (File: `chia/data_layer/data_layer_rpc_api.py`)

### Summary
The `add_missing_files` DataLayer RPC endpoint accepts a client-supplied `foldername` string and converts it directly into a filesystem `Path` with no validation, sanitization, or restriction to the configured `server_files_location`. This path is then used as the write destination for DataLayer tree-snapshot (`.dat`) files, letting any caller of the DataLayer RPC redirect file writes (including directory creation and, with `overwrite=True`, overwriting existing files) to an arbitrary location reachable by the DataLayer process, mirroring the GHSL-2023-250 "limited file write via unauthenticated route" bug class where a request parameter controls a write path that should have been fixed/sandboxed.

### Finding Description
`DataLayerRpcApi.add_missing_files()` takes `foldername` straight from the JSON request body: [1](#0-0) 

`foldername = Path(request["foldername"])` performs no check that the path is relative, contained under `server_files_location`, or otherwise sane — it is passed straight through to the service layer.

`DataLayer.add_missing_files()` then treats this attacker-chosen `foldername` as the effective `server_files_location` for the whole write operation: [2](#0-1) 

For each generation, `write_files_for_root()` is called with that folder and performs the actual filesystem write: [3](#0-2) 

Key points:
- `filename_full_tree.parent.mkdir(parents=True, exist_ok=True)` creates arbitrary directory structure under the caller-supplied path.
- `open(filename_full_tree, mode)` / `open(filename_diff_tree, mode)` write serialized tree content there. `mode` is `"xb"` by default but becomes `"wb"` (truncate-and-overwrite) when the caller also sets `overwrite: true` in the request, which `add_missing_files` forwards unmodified (`overwrite = request.get("overwrite", False)`).
- The written bytes come from `data_store.write_tree_to_file`, which serializes the caller's own DataLayer store content (key/value pairs the RPC caller previously inserted via `batch_update`), so the content is attacker-influenced (length-prefixed `SerializedNode` records embedding attacker-chosen key/value bytes), even though the framing bytes are not fully free-form — consistent with a "limited" file write rather than fully arbitrary content.
- Unlike the mirror/plugin download path (`insert_from_delta_file` / `download_file`), which is size- and name-validated via `download_data.is_filename_valid()` and `max_delta_file_size` before being trusted, this RPC-driven write path performs no equivalent validation on the destination directory.

This differs materially from the doc's documented invariant that "Static file serving validates filenames but... assumes files are already written under `server_files_location` by the service or plugin" — `add_missing_files` breaks that assumption by letting the RPC caller pick the destination directory directly.

### Impact Explanation
A caller with access to the DataLayer RPC surface (the local DataLayer RPC client role explicitly in scope) can:
- Create arbitrary directories and drop files with deterministic, attacker-computable names (`get_full_tree_filename_path`/`get_delta_filename_path` derived from store id / root hash / generation, all attacker-controlled since the caller owns the store) at any filesystem location the DataLayer process user can write to.
- With `overwrite=True`, truncate and rewrite pre-existing files at that location.
- Because the embedded content is a serialization of caller-supplied key/value data, the caller has partial control over bytes written into the target file, which is the classic "limited file write" primitive that can be escalated depending on what is reachable on disk (e.g. writing into another service's data/config directory that is world-writable-adjacent, poisoning DataLayer's own `server_files_location` siblings, or filling arbitrary paths for later processing by other tooling that reads well-known filenames).

This matches the CVSS 5.3 profile of the referenced advisory (limited, path-controlled file write, no direct RCE demonstrated but integrity impact via unauthorized file creation/overwrite).

### Likelihood Explanation
Any entity able to reach the DataLayer RPC (the "Data Layer client" actor explicitly listed as in-scope) and call `add_missing_files` can trigger this with a single RPC call — no additional privilege escalation is required beyond having RPC access to the DataLayer service, and no on-chain interaction is needed at all. The vulnerable code path executes unconditionally for any store id the caller can name (they need not even own the store to be listed, since `ids_bytes` is taken from the request's `"ids"` list without an ownership check in this endpoint) — the only precondition is that a local root exists for that store.

### Recommendation
- In `data_layer_rpc_api.py`'s `add_missing_files`, reject or normalize `foldername` so it must resolve within the configured `server_files_location` (e.g., `Path(...).resolve()` and verify it is a subpath), or remove client-controlled destination folders from the RPC surface entirely (keep `foldername` as an internal/CLI-only override, not a network-reachable RPC parameter).
- Apply the same filename/path validation used for downloaded mirror files (`download_data.is_filename_valid()`) to writes performed via `add_missing_files`/`write_files_for_root`.
- Reconsider allowing `overwrite=True` from the RPC layer without additional confirmation, since it enables truncation of pre-existing files at the (currently unchecked) target path.

### Proof of Concept
1. Start a DataLayer RPC client with valid credentials (any local caller with DataLayer RPC access, e.g. per `chia/cmds/data_funcs.py`/`chia/cmds/data.py`).
2. Create a data store and insert attacker-chosen key/value pairs via `batch_update`, then confirm a root on chain so `add_missing_files` has data to serialize.
3. Call the RPC endpoint:
```json
POST /add_missing_files
{
  "ids": ["<owned_store_id_hex>"],
  "overwrite": true,
  "foldername": "/absolute/or/traversal/path/outside/server_files_location"
}
```
4. Observe that `DataLayerRpcApi.add_missing_files` → `DataLayer.add_missing_files` → `write_files_for_root` creates the target directory (if missing) and writes `<store_id>-<node_hash>-full-<generation>-v1.0.dat` / `...-delta-...` files there, overwriting any pre-existing file of that name because `overwrite=True` forced write mode `"wb"`.         """

        if "ids" in request:
            store_ids = request["ids"]
            ids_bytes = [bytes32.from_hexstr(id) for id in store_ids]
        else:
            subscriptions: list[Subscription] = await self.service.get_subscriptions()
            ids_bytes = [subscription.store_id for subscription in subscriptions]
        overwrite = request.get("overwrite", False)
        foldername: Path | None = None
        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)
            if res.full_tree is not None:
                files.append(res.full_tree.name)

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass

    return WriteFilesResult(written, filename_full_tree if written_full_file else None, filename_diff_tree)
