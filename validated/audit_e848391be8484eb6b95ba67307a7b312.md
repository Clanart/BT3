## Title
`trimCoAuthorsTrailers` uses non-anchored `String.replace` that can strip the wrong text from a commit body, silently corrupting content on amend — (File: `app/src/models/commit.ts`)

### Summary
`trimCoAuthorsTrailers` is supposed to remove only the `Co-Authored-By` trailer line(s) from a commit's body when computing `Commit.bodyNoCoAuthors`. It does this with a plain, non-global `String.prototype.replace(substring, '')` call, which removes only the **first** occurrence of the literal string `"${token}: ${value}"` anywhere in the body — not specifically the trailer block at the end of the message. A commit body cloned from an attacker-controlled remote can contain an earlier line of ordinary text that happens to be byte-identical to the real trailer line, causing that unrelated line to be deleted instead of (or in addition to) the actual trailer.

### Finding Description
`trimCoAuthorsTrailers` iterates the trailers parsed by `git interpret-trailers` and blindly does a substring replace on the raw body: [1](#0-0) 

The trailers themselves are legitimately parsed from the well-formed trailer block at the end of the message via `git interpret-trailers --parse`, which respects Git's trailer-block syntax: [2](#0-1) 

However, once `trimCoAuthorsTrailers` has the `token`/`value` pair, it no longer respects *where* the trailer lives in the body — it just does `body.replace(`${token}: ${value}`, '')`, which:
1. Is not anchored to line boundaries, the trailer block, or the end of the string.
2. Only removes the first match, per `String.prototype.replace` semantics when passed a string (not a `/g` regex).

If an attacker crafts a commit whose description body contains, earlier in the text, a line that is textually identical to `Co-Authored-By: Name <email>` (e.g., a documentation quote, code sample, or copied text demonstrating trailer syntax) *and* also contains a real `Co-Authored-By` trailer at the end (required for `parseTrailers`/`isCoAuthoredByTrailer` to surface it as a trailer at all), the `replace` call deletes the **first** (unrelated) occurrence and leaves the genuine trailer text untouched in `bodyNoCoAuthors`.

This directly violates the function's intended invariant: only the actual trailer line should be stripped when computing the "body without co-authors."

### Impact Explanation
`Commit.bodyNoCoAuthors` is consumed downstream (e.g., in `app/src/lib/squash/squashed-commit-description.ts`) as the description text that gets shown to and re-committed by the user, in flows such as amending a commit or handling squashed commit messages. If the wrong text is stripped:
- The user's legitimate body text is silently deleted.
- The application's UI (which separately re-adds co-author trailers based on the `coAuthors` list) may then append the trailer again, so the final amended commit ends up with the coincidental unrelated line missing and/or a duplicated trailer — silently corrupting what the user pushes, without any warning to the user.

This matches the "silent corruption of what the user commits or pushes" impact category. That said, the practical severity is limited: it requires the attacker-crafted body to contain a byte-for-byte duplicate of the real trailer's `token: value` string elsewhere in the message, which is a narrow, specific condition rather than a generically triggerable corruption.

### Likelihood Explanation
Low-to-moderate. It requires:
- The victim to clone/fetch a repository containing a specially crafted commit.
- That commit to include a genuine `Co-Authored-By` trailer at the end (satisfying `git interpret-trailers` parsing) plus an unrelated line elsewhere in the body that is textually identical to `"${token}: ${value}"`.
- The victim to open that commit for amend/restore in GitHub Desktop, which computes `bodyNoCoAuthors` via `trimCoAuthorsTrailers`.

No unusual user interaction beyond normal amend/restore usage is required once the crafted commit is present, but the attacker needs precise control of commit body text to construct the collision.

### Recommendation
Make the trailer removal anchored and exhaustive instead of a naive first-match substring replace:
- Split the body into lines, identify the actual trailer block (e.g., using the same logic/format Git uses — trailing block after a blank line), and remove trailer lines only from that block, or
- Use a `RegExp` anchored to line start/end with the `g` flag (`new RegExp('^' + escapeRegExp(`${token}: ${value}`) + '$', 'gm')`) so only whole-line matches are removed, and all occurrences within the actual trailer block are handled, not just the first substring hit anywhere in the body.

### Proof of Concept
1. Attacker creates a commit with the following body:
```
Co-Authored-By: Jane Doe <jane@example.com>

Some legitimate explanation of the change.

Co-Authored-By: Jane Doe <jane@example.com>
```
(the first line is ordinary body text that happens to match the trailer string exactly; the second is the real trailer recognized by `git interpret-trailers`).
2. Victim clones the repository and opens this commit to amend in GitHub Desktop.
3. `Commit.bodyNoCoAuthors` is computed via `trimCoAuthorsTrailers`, which calls `body.replace('Co-Authored-By: Jane Doe <jane@example.com>', '')` — removing the **first** occurrence (the legitimate-looking body line) and leaving the real trailer intact.
4. The amend dialog now shows a body missing the intended explanatory line while still containing the trailer text; if the user proceeds, the resulting amended/re-committed message differs from what was intended, silently corrupting the commit content. [3](#0-2)

```typescript
function trimCoAuthorsTrailers(
  trailers: ReadonlyArray<ITrailer>,
  body: string
) {
  let trimmedCoAuthors = body

  trailers.filter(isCoAuthoredByTrailer).forEach(({ token, value }) => {
    trimmedCoAuthors = trimmedCoAuthors.replace(`${token}: ${value}`, '')
  })

  return trimmedCoAuthors
}
```
