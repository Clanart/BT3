### Title
Unbounded acceptance of attacker-created dust outputs DoSes spend construction and credits unspendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` treats every transaction output paying to a registered script as a `ReceivedOutput`, with no minimum-value or count bound. Since the multisig's P2TR script (and the deterministic `branch`/`change`/`forward` offset scripts) are publicly derivable, any unprivileged third party can broadcast transactions flooding the wallet with arbitrarily many minimal-value outputs. These outputs are unconditionally reported as received funds, yet when aggregated into `SignableTransaction::new` they either push the transaction over `MAX_STANDARD_TX_WEIGHT` (`TooLargeTransaction`) or cost more in input weight than their value — mirroring the external report's "attacker inflates victim's request queue so finalization fails" bug class.

### Finding Description
- `Scanner::scan_transaction` iterates `tx.output` and pushes a `ReceivedOutput` for every output whose `script_pubkey` is in `self.scripts`, with no filter on `output.value` and no cap on results. `scan_block` extends this across all transactions. [1](#0-0) 
- The base script is registered at offset `Scalar::ZERO` for any even group key, and `processor/src/networks/bitcoin.rs::scanner` deterministically registers `hash_to_F(KEY_DST, "branch"|"change"|"forward")` offsets — all public functions of the (public) group key, so an attacker needs no secret information to pay to them. [2](#0-1) [3](#0-2) 
- `get_outputs` converts every scanned output into an `Output { kind, .. }` credited to the multisig, again with no value check. [4](#0-3) 
- On the spend side, `SignableTransaction::new` includes *all* provided `inputs` unconditionally; the only guards are `input_sat < payment_sat + needed_fee` (`NotEnoughFunds`) and `weight > MAX_STANDARD_TX_WEIGHT` (`TooLargeTransaction`). Signing commits to `Prevouts::All`, so inputs cannot be silently dropped inside a signing round. [5](#0-4) [6](#0-5) 
- Each spam input adds a fixed ~57.5 WU to weight. An attacker who floods the wallet with enough tiny outputs makes any single-transaction spend that sweeps them exceed `MAX_STANDARD_TX_WEIGHT`, while including them raises `needed_fee` proportionally — spending a dust output can cost more than it contributes, and the only alternative is abandoning them as permanently stranded credited balance.

### Impact Explanation
- **DoS of spends:** sufficient spam inputs force `TooLargeTransaction` from `SignableTransaction::new`, blocking construction of the withdrawal/spend transaction containing the legitimate UTXOs — the direct analog of the report's out-of-gas `finalize()`. [7](#0-6) 
- **Funds reported received that are not spendable:** outputs are credited as received balance though spending them is economically irrational or impossible within a standard-weight transaction.
- **Fee grief:** every attacker-created input inflates `needed_fee` by `fee_per_vbyte * ~58`, draining the multisig's change when swept. [8](#0-7) 

### Likelihood Explanation
The attack requires only broadcasting ordinary Bitcoin transactions to a publicly computable P2TR script — no validator status, no internal API, no threshold of colluders. Cost is one transaction plus per-output value (which the attacker could even recover partially if outputs are later spent), and consensus permits many outputs per transaction. Likelihood is moderate-to-high; impact severity is bounded by the multisig's ability (if its caller implements input selection, which this library does not provide) to exclude dust inputs.

### Recommendation
- In `Scanner::scan_transaction` (or `get_outputs`), drop outputs below an economic minimum (e.g., the fee cost of spending one input at a reference feerate) or flag them `OutputType::Dust`.
- Bound the number of `ReceivedOutput`s emitted per transaction/block and let `SignableTransaction::new` accept an input-selection policy rather than requiring all inputs be swept.
- Document that consumers must filter/sort scanned inputs before calling `SignableTransaction::new`.

### Proof of Concept
```rust
// Attacker: anyone who knows the group key (public).
let attacker_scanner = Scanner::new(group_key).unwrap();
let victim_script = p2tr_script_buf(group_key).unwrap();

// Broadcast one tx with many minimal-value outputs to victim_script,
// e.g. 2000 outputs of a few hundred sats each.
// On the victim side:
let outputs = scanner.scan_transaction(&attacker_tx);
assert_eq!(outputs.len(), 2000); // all credited, no filtering

// When all received outputs (spam + legitimate) are swept:
inputs.extend(outputs);
let res = SignableTransaction::new(inputs, &payments, change, None, fee_rate);
// => Err(TransactionError::TooLargeTransaction) once weight > MAX_STANDARD_TX_WEIGHT,
// or NotEnoughFunds as needed_fee grows ~58 vbytes per spam input.
```

The fix is analogous to the report's mitigation: access control is impossible on-chain, so enforce a minimum economic value per recognized output and a hard bound on queued inputs instead.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );

    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
