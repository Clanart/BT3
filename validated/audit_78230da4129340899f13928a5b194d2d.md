Because the dynamic-gas precompile dispatcher (`DynamicGasPrecompile.RunAndCalculateGas`) applies the EVM's normal value-transfer semantics for a `CALL` with `value>0` before invoking `Execute` [4](#0-3) , any non-zero `value` sent alongside a call to `rewards(address)` is accepted by the EVM (debited from caller, credited to the distribution precompile's backing account) even though `rewards()` performs a pure query and never forwards, refunds, or accounts for that value anywhere. This exactly mirrors the reported bug class: value is accepted by a payable-by-accident entry point with no corresponding withdrawal/refund path, permanently stranding the sent native tokens at the precompile's underlying account, which has no keeper method to reclaim.

This is also explicitly flagged as a known quirk in the test suite's own comment: *"Guard quirk worth knowing: rewards() is the one phase-2 view WITHOUT a non-payable check (a value-bearing call would succeed and strand the funds)"* [6](#0-5) .

### Title
Missing non-payable guard on distribution precompile's `rewards` view permanently strands attached native value - (File: precompiles/distribution/distribution.go)

### Summary
The `rewards(address)` method of the distribution precompile (0x0000000000000000000000000000000000001007) is a read-only query, but unlike every other view method in the same executor, it never calls `pcommon.ValidateNonPayable(value)`. A caller can attach `usei`/`wei` value to a call to `rewards`, the EVM will debit the caller and credit the precompile's backing account as part of the normal `CALL` value-transfer, and the query executes and returns successfully without touching, refunding, or accounting for that value anywhere.

### Finding Description
`PrecompileExecutor.Execute` dispatches `RewardsMethod` directly to `p.rewards(ctx, method, args)` without a `value` parameter or a `ValidateNonPayable` check [1](#0-0) . Every other query in the file (`params`, `validatorOutstandingRewards`, `validatorCommission`, `validatorSlashes`, `delegationRewards`, `delegatorValidators`, `delegatorWithdrawAddress`, `communityPool`) is gated by `p.validateInput(value, args, n)`, which explicitly rejects non-zero value via `pcommon.ValidateNonPayable` [7](#0-6) . `rewards()` alone omits this, only validating argument length [3](#0-2) .

Because precompiles are ordinary EVM `CALL` targets, the go-ethereum EVM state-transition moves `value` from the caller to the precompile's account before/around invoking `RunAndCalculateGas`/`Execute` [4](#0-3) . Since `rewards()` succeeds (it doesn't error out), the call is not reverted, so the transferred value is not rolled back by the EVM. No code path inside `rewards()` forwards this value back to the caller or to any bank-tracked destination the caller controls, unlike the explicit refund pattern used by `sendNative`/`send` (`HandlePaymentUsei`/`HandlePaymentUseiWei`, which immediately `SendCoins`/`SendCoinsAndWei` the debited amount back to the payer before doing the real work) [5](#0-4) .

### Impact Explanation
Any usei/wei attached to a `rewards(address)` call is permanently locked in the precompile's underlying account, with no withdraw/rescue mechanism exposed by the distribution keeper or precompile. This is a concrete, permanent loss of user funds triggerable by any unprivileged EVM transaction sender or contract that (mistakenly or via a crafted integration) sends value with this specific call — for example, a front-end or contract wrapper that blindly forwards `msg.value` to a "read" call, or a user manually setting a non-zero `value` field when invoking `rewards`.

### Likelihood Explanation
Likelihood is limited by the fact that `rewards()` is documented/expected to be called as a view with zero value in normal integrations, and most callers use view helpers (`eth_call`/`staticcall`) that don't attach value. However, it is directly reachable by any transaction sender who crafts a `CALL` with non-zero `value` and the `rewards` selector — no privilege, association, or special setup is required beyond a funded EVM account.

### Recommendation
Add a `pcommon.ValidateNonPayable(value)` check to the `rewards` case in `PrecompileExecutor.Execute` (or inside `rewards()` itself), mirroring every other view method in `precompiles/distribution/distribution.go`, so that a value-bearing call to `rewards` reverts instead of silently stranding funds.

### Proof of Concept
1. Fund an EVM account and associate it with a Sei address.
2. Construct a raw EVM transaction / contract call to `0x0000000000000000000000000000000000001007` with calldata = 4-byte selector for `rewards(address)` + encoded delegator address, and set `value` to a non-zero amount of `usei`/`wei`.
3. Observe the transaction succeeds and returns the reward data (per `precompiles/distribution/distribution.go:543-579`), while the attached value is debited from the sender's EVM balance and never returned; there is no `withdraw` method on the distribution precompile or `distrKeeper` to reclaim it (contrast with `sendNative`, which explicitly refunds the payer via `HandlePaymentUseiWei` before doing its real transfer, at `precompiles/common/precompiles.go:292-309`).

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}

func HandlePaymentUsei(ctx sdk.Context, precompileAddr sdk.AccAddress, payer sdk.AccAddress, value *big.Int, bankKeeper putils.BankKeeper, evmKeeper putils.EVMKeeper, hooks *tracing.Hooks, depth int) (sdk.Coin, error) {
	usei, wei := state.SplitUseiWeiAmount(value)
	if !wei.IsZero() {
		return sdk.Coin{}, fmt.Errorf("selected precompile function does not allow payment with non-zero wei remainder: received %s", value)
	}
	coin := sdk.NewCoin(sdk.MustGetBaseDenom(), usei)
	// refund payer because the following precompile logic will debit the payments from payer's account
	// this creates a new event manager to avoid surfacing these as cosmos events
	if err := bankKeeper.SendCoins(ctx.WithEventManager(sdk.NewEventManager()), precompileAddr, payer, sdk.NewCoins(coin)); err != nil {
		return sdk.Coin{}, err
	}
	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		if hooks.OnEnter != nil {
			hooks.OnEnter(depth+1, byte(vm.CALL), evmKeeper.GetEVMAddressOrDefault(newCtx, precompileAddr), evmKeeper.GetEVMAddressOrDefault(newCtx, payer), []byte{}, GetRemainingGas(newCtx, evmKeeper), value)
		}
		if hooks.OnExit != nil {
			hooks.OnExit(depth+1, []byte{}, 0, nil, false)
		}
	}
	return coin, nil
}

		}
