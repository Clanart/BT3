### Title
Static (non-dynamic-gas) EVM precompiles skip the superlinear ABI-decode gas charge, allowing CPU-amplification via crafted calldata - (File: `precompiles/common/precompiles.go`)

### Summary
`precompiles/common/decode_cost.go` documents and defends against a specific class of resource-amplification bug in Go's ABI decoder: a single `string`/`bytes` payload can be referenced by many array/tuple offset slots, so `abi.Arguments.Unpack` can copy data volume that is super-linear (worst case ~`len(input)^2`) in the calldata size [1](#0-0) . This is conceptually the same bug class as CVE-2026-3592: a crafted, cheap-looking input causes disproportionate internal work relative to what the "resolver" (here, the precompile gas-metering layer) expects to pay for.

That mitigation (`DecodeGasCost` / `chargeDecodeGas`) is only wired into the **dynamic-gas** precompile path, `DynamicGasPrecompile.RunAndCalculateGas`, which explicitly charges the decode cost before calling `Unpack` [2](#0-1) . The **static** precompile path, `Precompile.Run` → `Precompile.Prepare`, calls `method.Inputs.Unpack(argsBz)` directly with no equivalent charge [3](#0-2) . For static precompiles, gas is instead charged up-front by go-ethereum's precompile dispatcher via `Precompile.RequiredGas`, which simply delegates to each executor's own `RequiredGas(input, method)` implementation [4](#0-3) . None of the static precompile executors (`addr`, `bank`, `auth`, `authz`, etc., and their legacy versions) reference `DecodeGasCost` anywhere in the codebase — a repo-wide search for `DecodeGasCost` only returns the dynamic-gas precompile files and the decode-cost package itself, not any static executor's `RequiredGas`.

### Finding Description
The `DynamicGasPrecompile.chargeDecodeGas` comment states the rationale plainly: "ABI decoding of attacker-controlled calldata can cost far more than len(input) ... so it must be paid for out of the gas the caller supplied" [5](#0-4) . This concern was addressed only for the dynamic-gas precompile family. Static precompiles (using `NewPrecompile`/`Precompile.Run`) charge gas solely through their own `RequiredGas` functions before `Prepare`/`Run` decodes the calldata with the real go-ethereum ABI unpacker [6](#0-5) . If any static precompile method accepts a dynamic array or tuple containing `string`/`bytes` elements, an attacker can construct calldata where multiple array/tuple offset words alias the same payload location, forcing `Unpack` to copy that payload once per referencing slot — the exact super-linear pattern `decode_cost.go` was written to price and reject [7](#0-6) . Because the static path's `RequiredGas` was never updated to include this surcharge, the EVM only deducts the flat/linear gas the executor's `RequiredGas` computes, not the true (super-linear) decode cost the go-ethereum decoder will actually perform.

### Impact Explanation
A caller submitting a single EVM transaction (or `eth_call`) against a static precompile with crafted, offset-aliased calldata can force validator nodes to spend CPU time on ABI decoding that is disproportionate to the gas charged/paid — an amplified resource-consumption condition triggered by one external request, directly analogous to the BIND resolver CVE. Because Sei is a single-lane, deterministically-ordered blockchain, CPU amplification during transaction/block processing can push block execution time past acceptable bounds, risking block-time delay or validator resource exhaustion under repeated/parallel submission of such transactions targeting the affected precompile(s).

### Likelihood Explanation
The root-cause asymmetry (dynamic-gas path charges `DecodeGasCost`, static path does not) is directly confirmed in code. What I was not able to fully confirm within the available search budget is which specific static precompile method(s) declare an argument type that is an array/tuple of `string`/`bytes` (a prerequisite for the offset-aliasing amplification to be reachable) — repo indexing limits and remaining iterations prevented enumerating every static precompile's ABI JSON/method signatures. This should be verified by inspecting each static precompile's `*.abi.json`/Go bindings for array-of-string or tuple-of-string parameters before treating this as fully exploitable end-to-end.

### Recommendation
Apply the same `chargeDecodeGas`/`DecodeGasCost` charge to the static precompile path (`Precompile.RequiredGas` and/or `Precompile.Prepare`) that is already applied in `DynamicGasPrecompile.RunAndCalculateGas`, so that all precompile calldata decoding — static or dynamic gas — is priced for its true (potentially super-linear) cost before `Unpack` is invoked.

### Proof of Concept
Conceptual PoC (pending confirmation of a concrete vulnerable static-precompile method signature):
1. Identify a static precompile method whose ABI signature includes a dynamic array or tuple containing `string`/`bytes` elements.
2. Encode calldata for that method where every element's offset word points to the same underlying string/bytes payload (offset aliasing), maximizing the number of times the decoder copies that payload — as described in `decode_cost.go`'s threat model [7](#0-6) .
3. Submit this as calldata to the static precompile via a normal EVM transaction; `Precompile.RequiredGas` charges only for the (undercounted) flat/linear cost, then `Precompile.Prepare` calls `method.Inputs.Unpack(argsBz)` unmetered for the decode's true cost [4](#0-3) [8](#0-7) .
4. Repeat/parallelize across blocks to amplify aggregate CPU cost relative to gas paid.

```go
// DecodeGasCost returns the gas to charge for ABI-decoding a dynamic precompile
// call's calldata (the full input, including the 4-byte selector) given the
// method's argument list. ok is false when the calldata is structurally invalid
// (or too deeply nested to price cheaply); the caller should reject such input
// rather than decode it, since the real decoder would reject it too.
//
// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
```

```go
func (p Precompile) RequiredGas(input []byte) uint64 {
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return UnknownMethodCallGas
	}

	method, err := p.MethodById(methodID)
	if err != nil {
		// This should never happen since this method is going to fail during Run
		return UnknownMethodCallGas
	}
	return p.executor.RequiredGas(input[4:], method)
}
```

```go
func (p Precompile) Prepare(evm *vm.EVM, input []byte) (sdk.Context, *abi.Method, []interface{}, error) {
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return sdk.Context{}, nil, nil, errors.New("cannot get context from EVM")
	}
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}
	method, err := p.MethodById(methodID)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	argsBz := input[4:]
	args, err := method.Inputs.Unpack(argsBz)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	return ctxer.Ctx(), method, args, nil
}
```
