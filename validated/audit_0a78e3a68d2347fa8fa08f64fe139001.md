## Title
Division-by-zero panic in KIP-71 base fee calculation when `kip71.gastarget` governance parameter is set to zero - (File: `params/kip71_config.go`)

## Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without ever checking that it is non-zero, unlike the sibling `BaseFeeDenominator` parameter which is explicitly protected against a zero value. Because `Kip71GasTarget`'s format checker is a no-op, a governance vote can set `gastarget=0`, and once ratified, the very next block that consumes any gas will make every full node panic with a Go `big.Int` "division by zero" runtime error while computing/verifying the next block's base fee — crashing the entire network, analogous to the arithmetic-exception crash in CVE-2016-5241.

## Finding Description
`NextMagmaBlockBaseFee` computes the next block's base fee using the `GasTarget` governance parameter as a divisor in both the "gas used above target" and "gas used below target" branches: [1](#0-0) 

Specifically:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // <-- division by gasTarget
```
and the symmetric branch when gas used is below target. There is no guard against `gasTarget == 0`, unlike `BaseFeeDenominator`, which explicitly falls back to a safe default when zero: [2](#0-1) 

The `GasTarget` value comes directly from the governance parameter `kip71.gastarget`, whose format checker (`noopFormatChecker`) performs no validation, unlike `Kip71BaseFeeDenominator` which explicitly rejects zero: [3](#0-2) 

Header-level vote verification (`checkConsistency`) also performs no special sanity check for `Kip71GasTarget` — it falls into the generic "no more checks" bucket: [4](#0-3) 

Governance votes are submitted through the `governance_vote` RPC API and are cast by the governing node (in `single` mode) or any GC member (in `none` mode): [5](#0-4) 

Once ratified, `GasTarget=0` becomes effective, and `NextMagmaBlockBaseFee` is invoked on every node during header preparation/verification for every subsequent Magma-era block: [6](#0-5) 

Because `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` will be `0` only for an entirely empty block, any block containing at least one transaction (`parentGasUsed > 0 = gasTarget`) takes the `parentGasUsed > gasTarget` branch and divides by `gasTarget = 0`, causing an unrecoverable Go runtime panic (`big.Int` division by zero) on every node that computes or verifies that header — i.e., a network-wide crash/DoS.

## Impact Explanation
This is a Medium/High-severity denial-of-service: once the malicious/erroneous `gastarget=0` value is ratified, all full nodes (validators and non-validators alike) will panic and crash the moment they process the next block containing any transaction, halting the entire chain. This directly parallels the underlying bug class in CVE-2016-5241 (unchecked divisor leading to an arithmetic exception and application crash from attacker/governance-controlled input).

## Likelihood Explanation
Reaching the vulnerable code requires a governance vote for `kip71.gastarget=0` to be cast and ratified — a legitimate use of the public `governance_vote` API that passes all existing format/consistency checks because no non-zero check exists for this parameter (in contrast to `Kip71BaseFeeDenominator`, which explicitly requires nonzero). After ratification, any regular transaction sender (an unprivileged user) submitting even a single transaction is sufficient to trigger the crash on the very next block, since almost no block will have exactly zero gas usage.

## Recommendation
Add a non-zero format checker for `Kip71GasTarget` (mirroring `Kip71BaseFeeDenominator`'s check), and/or add a defensive zero-check inside `NextMagmaBlockBaseFee` (e.g., fall back to a safe default like `BaseFeeDenominator` does) before performing the division by `gasTarget`.

## Proof of Concept
1. Governing node (or any GC member under `none` mode) calls:
   ```
   curl "http://localhost:8551" -X POST -H 'Content-Type: application/json' --data '
     {"jsonrpc":"2.0","id":1,"method":"governance_vote","params":["kip71.gastarget", 0]}'
   ```
2. The vote passes `NewVoteData`/`checkConsistency` (no bounds check on `Kip71GasTarget`) and is included in `header.Vote`.
3. At the next epoch boundary the vote is ratified into `header.Governance`, and `GasTarget=0` becomes effective for blocks in the following epoch.
4. Any unprivileged user submits a normal transaction, so the block's `GasUsed > 0 = gasTarget`.
5. Every node calling `NextMagmaBlockBaseFee(parentHeaderNumber, parentBaseFee, parentGasUsed)` executes `x.Div(x, big.NewInt(0))`, panicking with "division by zero" and crashing block processing network-wide.

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}
