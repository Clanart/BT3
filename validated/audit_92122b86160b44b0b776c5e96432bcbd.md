### Title
Flashloan-driven stake inflation before a permissionless `harvest()` call steals pending WOM/bonus yield from existing stakers - ([File: rewards/BaseRewardPool.sol], [File: wombat/WombatStaking.sol])

### Summary
`BaseRewardPool._provisionReward` distributes newly harvested rewards **instantly** and proportionally to whatever `totalStaked()` is at the moment the reward is queued, with no linear vesting/streaming period. `WombatStaking.harvest(_lpToken)` is a fully permissionless, unrestricted external function that any wallet can call at any time to pull pending WOM (and bonus token) rewards out of Wombat Exchange and push them into the corresponding `BaseRewardPool` via `queueNewRewards`. Because deposits/withdrawals of the Magpie receipt token are instantaneous (no lock, unlike `mWomSV`), an attacker can inflate their share of `totalStaked()` immediately before triggering `harvest()`, capture a disproportionate share of the yield that accrued to long-term stakers, then withdraw in the same transaction — a bug-class analog of flashloan-driven balance manipulation used to unfairly capture yield accounted for by an instantaneous balance snapshot (as in the referenced ParaSpace `scaledBalanceOf` exploit).

### Finding Description
`_provisionReward` computes the new `rewardPerTokenStored` using the *current* `totalStaked()` snapshot at the time reward is queued: [1](#0-0) 

`totalStaked()` simply reads `IERC20(stakingToken).balanceOf(operator)` — i.e., the current balance held by `MasterMagpie` — with no time-weighting or vesting of the reward over a duration: [2](#0-1) 

`WombatStaking.harvest()` is unauthenticated (open to any pool that is active) and can be called by anyone to force-harvest all pending WOM/bonus rewards accrued in Wombat Exchange for a pool and queue them into the rewarder: [3](#0-2) 

Deposits and withdrawals through `WombatPoolHelperV2` (and `WombatStaking.deposit`/`depositLP`/`withdraw`) are atomic and unlocked — a user can stake and unstake the receipt token in the same transaction: [4](#0-3) [5](#0-4) 

An attacker can therefore, in a single transaction:
1. Flashloan a large amount of the pool's `depositToken`/LP token.
2. Deposit it into the pool via `WombatPoolHelperV2.depositLP`/`deposit`, which stakes a large receipt-token balance for the attacker in `MasterMagpie`, drastically increasing `totalStaked()` for that pool's `BaseRewardPool`.
3. Call the permissionless `WombatStaking.harvest(_lpToken)`, which harvests all WOM/bonus rewards that accrued to genuine long-term stakers over time and calls `queueNewRewards`, which distributes that reward proportionally against the *now-inflated* `totalStaked()` — giving the attacker's flashloaned stake a large, undeserved share of that reward.
4. Claim the reward via `getReward`.
5. Withdraw the stake and repay the flashloan.

This differs from the "self-triggered deposit harvest" path (`WombatStaking.deposit`/`depositLP`, where the harvest inside `_toMasterWomAndSendReward` happens *before* the depositor's own stake is minted/credited, so a depositor cannot dilute the harvest they themselves triggered) — but the standalone `harvest()` entry point has no such ordering protection and lets any pre-existing stake at call time capture the harvest, including a stake established microseconds earlier in the same transaction.

### Impact Explanation
This directly results in theft of unclaimed yield: rewards that accrued to genuine long-term liquidity providers are diverted to a flashloan attacker who has no genuine long-term exposure to the pool, satisfying the "theft ... of unclaimed yield" impact bar.

### Likelihood Explanation
The attack requires only an ordinary wallet, a flashloan of the deposit/LP token, and calls to already-public, unauthenticated functions (`depositLP`/`deposit`, `harvest`, `getReward`, `withdraw`) — no privileged role or governance action is needed. It is more profitable for pools that have accumulated a large amount of un-harvested WOM/bonus rewards and have comparatively low existing `totalStaked()`, which is a normal, achievable market condition (e.g., pools where `harvest()` hasn't been called in a while).

### Recommendation
- Vest/stream newly queued rewards linearly over a fixed duration (similar to Synthetix-style `rewardRate`/`periodFinish` staking rewards) instead of instantly minting `rewardPerTokenStored` against the current `totalStaked()` snapshot.
- Alternatively, restrict `harvest()` to be gated by pool helpers/keepers combined with a minimum time-since-last-harvest, or snapshot `totalStaked()` prior to same-block deposits (e.g., using a checkpoint/cooldown similar to `mWomSV`) so a same-transaction stake increase cannot participate in a harvest it immediately triggered.

### Proof of Concept
1. Attacker flashloans `_lpAmount` of `depositToken` for a Wombat pool with significant un-harvested WOM in `MasterWombat`.
2. Attacker calls `WombatPoolHelperV2.depositLP(_lpAmount)` (or `deposit`), staking the flashloaned amount into `MasterMagpie` via `WombatStaking.depositLP` → `_toMasterWomAndSendReward` → `IMasterMagpie.depositFor`, so `totalStaked()` for that pool's rewarder is now dominated by the attacker's stake.
3. Attacker calls `WombatStaking.harvest(_lpToken)`, which pulls all pending WOM (and bonus rewards) accumulated over time and calls `BaseRewardPool.queueNewRewards`, computing `rewardPerTokenStored` against the now-inflated `totalStaked()`.
4. Attacker calls `getReward` on the rewarder (via `MasterMagpie`) to claim their inflated share of the harvested rewards.
5. Attacker calls `WombatPoolHelperV2.withdraw` to unstake and `WombatStaking.withdraw` to redeem the underlying tokens, then repays the flashloan — all in the same transaction, net profit equal to the diverted share of yield that belonged to prior stakers.

```text
    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
```
