## Finding: Stale cached diff used to construct destructive `git apply` patches for "Discard Changes"

### Title
Discard-changes flow applies patches built from a stale cached diff, allowing silent corruption/loss of unrelated working-directory content - (File: `app/src/lib/stores/updates/changes-state.ts`, `app/src/lib/git/apply.ts`)

### Summary
GitHub Desktop's "discard selected lines" feature builds a `git apply` patch from the `diff` object cached in application state rather than a freshly computed diff of the file's current on-disk content. That cached diff is deliberately reused across repository refreshes whenever the same file remains selected, with no check that the file's actual contents have changed since the diff was generated. If the tracked file is modified by anything outside of Desktop's own edit flow between the time the diff was rendered and the time the user clicks "Discard changes," Desktop applies a patch computed against outdated line offsets/content to the now-different file, mirroring the report's underlying flaw: an administrative/destructive action operating on a stale internal tracker instead of the true current state.

### Finding Description
`updateChangedFiles` explicitly preserves the previously loaded diff object across status refreshes as long as the same single file id stays selected, without any content-hash or mtime comparison: [1](#0-0) 

This cached `selection.diff` is exactly what's threaded through to the discard flow. The `Changes` component hands `this.props.diff` (i.e., `changesState.selection.diff`) straight to the dispatcher when the user discards a selection: [2](#0-1) 

That call eventually reaches `discardChangesFromSelection` in the git layer, which builds a patch purely from the passed-in `diff` object (not a freshly recomputed one) and applies it directly to the working tree with `git apply`: [3](#0-2) 

Contrast this with `applyPatchToIndex`, used for staging, which explicitly re-fetches `getWorkingDirectoryDiff` immediately before building the patch: [4](#0-3) 

No equivalent re-fetch exists in the discard path. Periodic repository refreshes (`_refreshRepository` → `refreshChangesSection`) reload file status but do not force a diff reload for the already-selected file: [5](#0-4) 

The diff is refreshed only in `updateChangesWorkingDirectoryDiff`, which is triggered by selection changes, not by every background/periodic refresh: [6](#0-5) 

So, exactly as `pool.amount` in the original report could drift from the real staked amount due to external events (rewards/slashing) the router didn't observe, the cached `selection.diff` can drift from the real file content due to external events (any process that rewrites the tracked file - an npm/build watch task, a linter's "--fix", an editor auto-format-on-save, or a git hook run as part of a Desktop-initiated checkout/merge/pull) that Desktop's diff cache does not observe.

### Impact Explanation
When the file changes after the diff was cached but before "Discard changes" runs, `git apply` operates against outdated hunk headers/content:
- If offsets no longer line up, `git apply` may fail — a denial-of-service style annoyance (excluded from scope on its own).
- More importantly, because the discard patch uses `--unidiff-zero --whitespace=nowarn`, it is applied with minimal context validation. If the new file content happens to still contain matching context around the stale hunk (e.g., only intervening lines changed, or line-based tools reformatted the file), `git apply` can succeed while reverting/removing content the user never saw or intended to discard — silently corrupting the working directory relative to what the user believed they were discarding, and that corrupted state is what subsequently gets staged/committed/pushed. This falls squarely under "silent corruption of what the user commits or pushes."

### Likelihood Explanation
Any workflow where a file is modified by something other than the user's direct edit while Desktop has it open in the diff view is sufficient: build watchers, format-on-save extensions in an external editor, linters with auto-fix, LFS smudge/clean re-runs, or git hooks (post-checkout/post-merge/post-commit) shipped inside an attacker-authored repository that Desktop executes as part of normal clone/checkout/pull/merge operations. Given how common "watch mode" tooling and format-on-save are in developer workflows, and that Desktop's own refresh cycle doesn't reload the diff, the drift condition described above is realistically reachable without any unusual user action.

### Recommendation
In `discardChangesFromSelection` (`app/src/lib/git/apply.ts`), re-fetch the current working-directory diff for the file (as `applyPatchToIndex` already does) immediately before constructing and applying the discard patch, and abort/warn the user if the freshly fetched diff differs from the one the discard selection was made against. Alternatively, invalidate `selection.diff` in `updateChangedFiles` whenever the underlying blob/mtime for the selected file has changed, rather than only checking that the same file id remains selected.

### Proof of Concept
1. Open a repository in Desktop and modify a tracked file so it shows changes in the Changes view; select a hunk to review in the diff pane (this diff is now cached in `changesState.selection.diff`).
2. While the diff is displayed, have an external process rewrite the same file (e.g., a watch-mode formatter, or a git hook triggered by a concurrent `git pull`/`git merge` performed via Desktop) such that line offsets shift but the file still has plausible context lines.
3. Without reselecting the file (which would force a diff refresh), click "Discard changes" on the previously selected hunk.
4. Desktop calls `discardChangesFromSelection(repository, filePath, diff, selection)` with the stale `diff`, builds a patch from it via `formatPatchToDiscardChanges`, and runs `git apply --unidiff-zero --whitespace=nowarn -` against the now-different file, silently reverting/removing content that no longer corresponds to what the user visually selected for discard.

```typescript
/**
 * Discards the local changes for the specified file based on the passed diff
 * and a selection of lines from it.
 *
 * When passed an empty selection, this method won't do anything. When passed a
 * full selection, all changes from the file will be discarded.
 *
 * @param repository The repository in which to update the working directory
 *                   with information from the index
 *
 * @param filePath   The relative path in the working directory of the file to use
 *
 * @param diff       The diff containing the file local changes
 *
 * @param selection  The selection of changes from the diff to discard
 */
export async function discardChangesFromSelection(
  repository: Repository,
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
) {
  const patch = formatPatchToDiscardChanges(filePath, diff, selection)

  if (patch === null) {
    // When the patch is null we don't need to apply it since it will be a noop.
    return
  }

  const args = ['apply', '--unidiff-zero', '--whitespace=nowarn', '-']

  await git(args, repository.path, 'discardChangesFromSelection', {
    stdin: patch,
  })
```

```typescript
  /**
   * Loads or re-loads (refreshes) the diff for the currently selected file
   * in the working directory. This operation is a noop if there's no currently
   * selected file.
   */
  private async updateChangesWorkingDirectoryDiff(
    repository: Repository
  ): Promise<void> {
    const stateBeforeLoad = this.repositoryStateCache.get(repository)
    const changesStateBeforeLoad = stateBeforeLoad.changesState

    if (
      changesStateBeforeLoad.selection.kind !==
      ChangesSelectionKind.WorkingDirectory
    ) {
      return
    }

    const selectionBeforeLoad = changesStateBeforeLoad.selection
    const selectedFileIDsBeforeLoad = selectionBeforeLoad.selectedFileIDs

    // We only render diffs when a single file is selected.
    if (selectedFileIDsBeforeLoad.length !== 1) {
      if (selectionBeforeLoad.diff !== null) {
        this.repositoryStateCache.updateChangesState(repository, () => ({
          selection: {
            ...selectionBeforeLoad,
            diff: null,
          },
        }))
        this.emitUpdate()
      }
      return
    }

    const selectedFileIdBeforeLoad = selectedFileIDsBeforeLoad[0]
    const selectedFileBeforeLoad =
      changesStateBeforeLoad.workingDirectory.findFileWithID(
        selectedFileIdBeforeLoad
      )

    if (selectedFileBeforeLoad === null) {
      return
    }

    const diff = await getWorkingDirectoryDiff(
      repository,
      selectedFileBeforeLoad,
      this.hideWhitespaceInChangesDiff
    )
```
