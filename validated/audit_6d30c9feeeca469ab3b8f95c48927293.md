## Title
Payout transaction's operator-attribution OP_RETURN output is unsigned, allowing an unprivileged attacker to reassign reimbursement credit away from the operator who actually funded the withdrawal - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The `payout_tx` that fronts a user withdrawal commits the operator's identity via a plain `OP_RETURN` output containing the operator's x-only pubkey [1](#0-0) . The only cryptographic signature on this transaction is the user's `SinglePlusAnyoneCanPay` signature over input 0 and output 0 [2](#0-1) . That sighash flag does not commit to any other input or output, so the `OP_RETURN` output that later determines *which operator gets reimbursement credit* is unauthenticated and can be swapped by any party who can get a competing spend of the same withdrawal UTXO mined first.

### Finding Description
`create_payout_txhandler` builds a transaction with: output 0 = user payout, output 1 = anchor, output 2 = `OP_RETURN` carrying `operator_xonly_pk` [1](#0-0) . The user only signs this transaction with `SinglePlusAnyoneCanPay`, and `Operator::withdraw` verifies exactly that: it computes the sighash for input index 0 using the sighash type embedded in the user-supplied signature and checks it against output 0 only [3](#0-2) . Because `SIGHASH_SINGLE|ANYONECANPAY` binds only input 0 and output 0, the anchor output and the operator-attribution `OP_RETURN` output are entirely outside the signature's commitment. Anyone possessing the raw (unconfirmed) payout transaction — visible in the mempool once the legitimate operator's node broadcasts it — can construct an alternative transaction spending the same withdrawal UTXO with the *same valid user signature*, keeping output 0 identical, but replacing the `OP_RETURN` payload with a different operator's x-only pubkey (or garbage), and fund/bump fees on their own version to win the mining race against the original.

Downstream, the chain-observed `OP_RETURN` value is trusted blindly to decide who is credited:
- `update_finalized_payouts` extracts `operator_xonly_pk` from the first `OP_RETURN` output of whichever payout tx actually confirms on-chain and stores it as `payout_payer_operator_xonly_pk` [4](#0-3) .
- `PayoutCheckerTask`/`get_first_unhandled_payout_by_operator_xonly_pk` looks up unhandled payouts *by that stored pubkey* and triggers `handle_finalized_payout` for whichever operator it names [5](#0-4) [6](#0-5) .
- `is_kickoff_malicious` compares the stored `operator_xonly_pk` against `kickoff_data.operator_xonly_pk` and marks the kickoff as malicious on any mismatch [7](#0-6) .

Binding broken: `operator credited (payout_payer_operator_xonly_pk from on-chain OP_RETURN) == operator that actually fronted the withdrawal (funded input 0's spend)`. An attacker who mutates the unsigned `OP_RETURN` before confirmation breaks this equality: the honest operator who really paid the user (input 0 spent, their BTC left) is no longer recognized as the payer, while an arbitrary other operator (chosen by the attacker) is recorded as payer with no funds actually spent by them.

### Impact Explanation
- The operator falsely named in the substituted `OP_RETURN` is now the one whose `PayoutCheckerTask` sees an "unhandled payout" for a withdrawal it never funded, letting it attempt/obtain reimbursement it is not entitled to — "an operator reimbursed for a payout it never funded."
- The operator that genuinely funded the payout will have its kickoff rejected as malicious by `is_kickoff_malicious` (`operator_xonly_pk != kickoff_data.operator_xonly_pk`), permanently preventing that honest operator from ever being reimbursed for real, spent BTC — "an honest operator permanently unable to be reimbursed."
Both are explicitly listed Critical impacts.

### Likelihood Explanation
No privileged role is required. Any network participant who can observe the unconfirmed payout transaction (mempool visibility) and race a replacement spend of the same withdrawal UTXO — reusing the untouched user signature over input/output 0 while altering the unsigned anchor/`OP_RETURN` outputs and adding their own fee-paying input — can perform this attack. This is a pure sighash-malleability issue inherent to using `SIGHASH_SINGLE|ANYONECANPAY` for the only authenticating signature while leaving custody-attribution data in an uncommitted output.

### Recommendation
Bind the operator-attribution `OP_RETURN` output (and the anchor output) to the same signature that authorizes the spend — e.g., require the operator to co-sign with a sighash type (`ALL`/`SIGHASH_DEFAULT` combined with a second required signature, or a script-path commitment) that covers all outputs, so the operator identity recorded in the confirmed transaction cannot be altered by any party other than the constructing operator itself.

### Proof of Concept
1. Operator A calls `Operator::withdraw`, producing and broadcasting `payout_tx` with `output[0]`=user payout, `output[2]`=`OP_RETURN(A_xonly_pk)`, signed by the user with `SIGHASH_SINGLE|ANYONECANPAY` over input 0/output 0 only [1](#0-0) .
2. Attacker observes this unconfirmed transaction, copies input 0 (with the same valid witness) and output 0 unchanged, but crafts a new transaction replacing `output[2]` with `OP_RETURN(B_xonly_pk)` for a different existing operator B, adding its own fee input/output as needed.
3. Attacker gets its version mined first (e.g. by paying a higher fee / CPFP on the anchor).
4. `update_finalized_payouts` records `payout_payer_operator_xonly_pk = B` for this withdrawal [4](#0-3) .
5. Operator B's `PayoutCheckerTask` picks it up as its own unhandled payout via `get_first_unhandled_payout_by_operator_xonly_pk` and proceeds to reimbursement [6](#0-5) , while Operator A's later kickoff for the same deposit is flagged malicious by `is_kickoff_malicious` since the stored payer no longer matches A [7](#0-6) .

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
