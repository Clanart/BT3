## Analysis

The OtterAudits report's core broken invariant is: **an aggregate value computed from a formula is misattributed/miscapped, allowing a party to extract more value than they are entitled to, because the guard clamps against the wrong baseline (`0` instead of `base_fee`)**. The local Hyperbridge analog I found is not in fee clamping arithmetic, but in **relayer-reward attribution** for `pallet-consensus-incentives`, where a single unrelated field (`messages[0]`'s self-declared signature) is used to attribute rewards for *every* state-machine advance in an entire batch, regardless of which message actually produced which advance.

### Title
Reward misattribution in `pallet-consensus-incentives::on_executed` pays the whole batch to the signer of `messages[0]` - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet_ismp::Pallet::execute` accepts an unsigned, permissionless `Vec<Message>` and processes them as one atomic batch, feeding the combined message list and combined event list to a single `FeeHandler::on_executed` call. [1](#0-0) 
`pallet-consensus-incentives`'s `on_executed` implementation derives the *only* relayer identity to be rewarded from `messages.get(0)` — decoding a self-declared `signer` field and verifying it against `keccak256(consensus_proof)` of that single message. [2](#0-1) 
It then iterates over **every** `StateMachineUpdated` event collected from the **whole batch** (potentially caused by other, unrelated `Message::Consensus` entries later in the same `Vec`) and pays the single extracted account a reward for each one. [3](#0-2) 

### Finding Description
`Pallet::execute` (in `pallet-ismp`) takes a `Vec<Message>` supplied wholesale by an unsigned caller (`handle_unsigned`), processes every message with `handle_incoming_message`, collects **all** resulting events (including `StateMachineUpdated` for however many distinct consensus clients/state machines were advanced), and calls `T::FeeHandler::on_executed(messages_with_weights, events)` exactly once for the entire batch: [4](#0-3) 

`pallet-consensus-incentives::on_executed` only inspects `messages.get(0)`. If it is a `Message::Consensus`, it decodes the embedded `signer` (an sr25519 `Signature`) and recovers a public key by verifying it against `keccak256(&consensus_msg.consensus_proof)` — of *that one message only*: [2](#0-1) 

It then builds `highest_per_state_machine` from **every** `StateMachineUpdated` event in the batch — which can originate from `Message::Consensus` entries at any other index in the `Vec`, each carrying its own independent (and independently valid) `signer`/proof — and pays the *single* account recovered from `messages[0]` for each one: [3](#0-2) 

The code comment even documents that the collapsing logic was added to stop *double*-paying the same relayer for duplicate events in a batch, but it never re-examined the more basic assumption that all events in a batch belong to `messages[0]`'s signer: [5](#0-4) 

Because the ISMP consensus proof itself (BEEFY/GRANDPA proof) is verified for cryptographic correctness independently of the `signer` field — the `signer` is a **self-declared, unauthenticated attribution tag**, not part of the proof's validity — nothing stops a caller from constructing a batch where:
- `messages[0]` is a trivially cheap `Message::Consensus` (e.g., a single-block, low-`cost_per_block` state machine) signed with the attacker's own key, and
- `messages[1..N]` are additional, independently-valid `Message::Consensus` entries for *other*, higher-value state machines (their proofs are public data on the source chains, so anyone can source and resubmit them in the same unsigned extrinsic without needing anyone else's key or cooperation).

The pallet correctly verifies each proof's cryptographic validity, but pays out reward for *all* the resulting `StateMachineUpdated` advances to the account recovered from `messages[0]` alone, regardless of `cost_per_block` size or which proof/key actually caused each advance. The `LastRewardedHeight` watermark and `saturating_sub` math in `calculate_reward` correctly stop *double*-paying the same span twice, but do nothing to stop *cross-attribution* within a single batch: [6](#0-5) 

### Impact Explanation
This is a **wrong-beneficiary / logic-attack fund-loss** issue against the treasury account (`T::TreasuryAccount`), matching the bounty's "logic attacks" and "wrong beneficiary or amount" categories. An unprivileged party can construct a single unsigned batch that mixes a trivial self-signed consensus update with any number of independently-sourced, genuinely valid consensus proofs for other (possibly high-`cost_per_block`) state machines, and collect the *entire* combined reward under one account, rather than each proof's actual work being compensated proportionally/per-signer. Since rewards are paid from `T::TreasuryAccount` via `T::Currency::transfer` and reputation is minted via `T::ReputationAsset::mint_into` for the same misattributed account, this is a direct drain of protocol-owned treasury funds and reputation-asset inflation to a single actor disproportionate to the actual signed work performed, for every batch they choose to construct this way. [7](#0-6) 

### Likelihood Explanation
High. `handle_unsigned` accepts an arbitrary `Vec<Message>` from any caller with no origin binding to the embedded `signer` fields, so no privileged role, leaked key, or malicious relayer/prover collusion is required — only knowledge of (a) any keypair the attacker controls to self-sign a cheap proof as `messages[0]`, and (b) publicly obtainable consensus proofs for other state machines to append afterward. `StateMachinesCostPerBlock` values are configured per-chain and can differ significantly, making this profitable whenever a batch spans state machines with meaningfully different reward rates.

### Recommendation
Attribute rewards per-message rather than per-batch: extract and verify the `signer` from *each* `Message::Consensus` in the batch, and only credit the `StateMachineUpdated` events that are causally linked to that specific message's consensus_state_id/state_machine_id to the corresponding recovered account, instead of assuming all events in the batch belong to `messages[0]`'s signer.

### Proof of Concept
1. Attacker controls keypair `K_a` and observes/obtains a valid, publicly available BEEFY/GRANDPA consensus proof `P_b` for state machine `B` (high `cost_per_block`), originally intended to be relayed by a different party.
2. Attacker constructs `consensus_proof_a` for a cheap/low-cost state machine `A` and signs `keccak256(consensus_proof_a)` with `K_a`, forming `messages[0] = Message::Consensus { consensus_proof: consensus_proof_a, signer: sig_a, .. }`.
3. Attacker appends `messages[1] = Message::Consensus { consensus_proof: P_b, signer: <anything, unchecked>, .. }`.
4. Attacker submits `pallet_ismp::Pallet::handle_unsigned(RuntimeOrigin::none(), vec![messages[0], messages[1]])`.
5. `execute()` validates both proofs successfully (independent of `signer`), emits two `StateMachineUpdated` events (for `A` and `B`), and calls `on_executed` once with both messages/events. [4](#0-3) 
6. `on_executed` recovers only `K_a`'s public key from `messages[0]` and pays the account derived from `K_a` for **both** `A`'s and `B`'s reward spans, even though `messages[1]`'s (`B`'s) proof was not signed/attributed to `K_a`. [8](#0-7)

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
