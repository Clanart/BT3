### Title
`ReceivedOutput::read` accepts unspendable outputs as valid received funds - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` deserializes an arbitrary scalar offset, `TxOut`, and `OutPoint` without verifying that the output’s `script_pubkey` is derived from the claimed offset or that the outpoint belongs to a real transaction. This is analogous to accepting a malformed or mismatched payload after only checking its container/signature: the byte encoding may parse correctly while the semantic claim—that this is a spendable received output—is false.

### Finding Description
`ReceivedOutput` represents “a spendable output” and carries the scalar offset needed to spend it, the output itself, and its outpoint. [1](#0-0) 

The scanner only creates these objects when a transaction output’s `script_pubkey` matches a script registered for a specific offset. [2](#0-1) 

However, `ReceivedOutput::read` performs no equivalent validation. It accepts any canonical scalar, any consensus-valid `TxOut`, and any consensus-valid `OutPoint`, then returns `Ok(ReceivedOutput)`. [3](#0-2) 

The mismatch is only detected much later, and only if the caller attempts to sign: `SignableTransaction::multisig` checks whether `keys + offset` produces the previous output’s script. [4](#0-3)  A caller that deserializes and reports balances or spendable coins before reaching that point will treat the forged object as valid.

### Impact Explanation
An attacker-controlled serialized `ReceivedOutput` can cause Serai to report funds as received even though the described output cannot be spent with the supplied offset and threshold keys.

This can create false balance accounting or cause a wallet to attempt spending a nonexistent or unrelated UTXO. The latter also enables transaction-construction failure or fee/funding misaccounting, depending on how the caller handles `SignableTransaction::multisig` returning `None`.

### Likelihood Explanation
The input is only a byte stream passed to a public deserialization API, so it is reachable under the stated model for untrusted `ReceivedOutput::read` input. Exploitation does not require a threshold participant, validator, peer, leaked key, or control over Bitcoin consensus.

The necessary bytes are easy to construct: a canonical scalar plus consensus encodings of an unrelated `TxOut` and arbitrary `OutPoint` are sufficient because the function only checks syntactic decoding.

### Recommendation
Do not treat `ReceivedOutput::read` as proof that an output was scanned successfully. Either:

- remove standalone public deserialization of `ReceivedOutput`, or
- require the expected scanner/view key as a parameter and validate that `p2tr_script_buf(key + GENERATOR * offset)` equals `output.script_pubkey`, and
- ensure the `outpoint` refers to an output produced by the relevant transaction/block scan.

At minimum, rename or document this API as a raw container decoder rather than validation of a spendable received output.

### Proof of Concept
```rust
use k256::{Scalar, ProjectivePoint};
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut,
  consensus::encode::serialize_hex,
};
use bitcoin::key::TweakedPublicKey;
use bitcoin::secp256k1::XOnlyPublicKey;
use serai_bitcoin::wallet::{ReceivedOutput, p2tr_script_buf};

let base_key = ProjectivePoint::GENERATOR * Scalar::ONE;

// A P2TR output for a different key than `base_key + offset`.
let unrelated_point = ProjectivePoint::GENERATOR * Scalar::from(7u64);
let unrelated_x_only =
  XOnlyPublicKey::from_slice(&unrelated_point.to_affine().x()).unwrap();
let unrelated_script = ScriptBuf::new_p2tr_tweaked(
  TweakedPublicKey::dangerous_assume_tweaked(unrelated_x_only),
);

let output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: unrelated_script.clone(),
};
let outpoint = OutPoint::null();

let mut bytes = Vec::new();
bytes.extend(Scalar::ONE.to_bytes());
bytes.extend(bitcoin::consensus::serialize(&output));
bytes.extend(bitcoin::consensus::serialize(&outpoint));

// Syntactically valid, and accepted despite not representing a scanned output.
let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(received.value(), 100_000);

// The stored offset does not produce the output's script.
assert_ne!(
  p2tr_script_buf(base_key + (ProjectivePoint::GENERATOR * received.offset())).unwrap(),
  unrelated_script,
);
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
