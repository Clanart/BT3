### Title
Silent auto-rewrite of git remote URL trusts owner/name text match to GitHub API, enabling repo-name-squat push/fetch hijack - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
When Desktop refreshes a repository's GitHub association (on selecting a repo, after sign-in/out, or periodically), it resolves the associated GitHub API repository by parsing `owner/name` out of the existing local git remote URL and querying the API for that literal owner/name. If the API returns a repository whose `clone_url` differs from the current remote (e.g., because the original repo was deleted/renamed and the owner/name was reused by a different, now attacker-controlled, repository), Desktop automatically calls `gitStore.setRemoteURL` to rewrite the local `origin` remote to point at that API-returned `clone_url` — with no user confirmation.

### Finding Description
`matchGitHubRepository` [1](#0-0)  derives `owner`/`name` solely from a regex parse of the existing remote URL text, with no reference to any previously stored, immutable GitHub repository ID. `repositoryWithRefreshedGitHubRepository` [2](#0-1)  uses that match to call `api.fetchRepository(owner, name)` and, if a repository is returned, immediately passes it to `updateRemoteUrl` before any comparison against the previously known repository identity. `updateRemoteUrl` [3](#0-2)  only guards against (1) protocol mismatch and (2) the local remote having been manually changed away from the last known `cloneURL`; it does not verify that the "same" owner/name still refers to the same underlying repository. When those two guards pass and the newly fetched `clone_url` textually differs from the current remote (e.g., following a rename), it calls `gitStore.setRemoteURL(...)` [4](#0-3)  to silently overwrite the git config `remote.origin.url`, and this refresh path runs automatically as part of normal repository selection [5](#0-4) .

The broken invariant: Desktop treats "owner/name text still resolves to *a* repository via the API" as proof that it's the *same* repository the user originally cloned, instead of anchoring identity to the GitHub repository's stable numeric ID. On GitHub, `owner/name` is not permanently bound to one repository — it can be freed by a rename, transfer, or deletion, and reused by an unrelated (attacker-controlled) repository shortly after. In that scenario Desktop's next background refresh will fetch the attacker's repository object under the old owner/name and rewrite the trusted `origin` remote to the attacker's `clone_url`, all silently.

### Impact Explanation
If exploited, the user's next `git push`/`git fetch`/`git pull` from Desktop silently targets an attacker-controlled repository instead of the one the user originally cloned. Since GitHub credential helper/auth is tied to hostname rather than a specific repo, the user's existing GitHub credentials would be used against the attacker's repository, and future pushes send code (potentially proprietary/private) to a destination the user never approved — a silent corruption of what the user pushes and a potential credential/data exposure, without any local access or the user editing their remote.

### Likelihood Explanation
This requires an attacker to be able to claim a specific `owner/name` combination after the original repository moved away from it (rename, transfer, org/user rename, or deletion) — a known and previously-exploited "repo/npm/package name-squatting" style takeover pattern that requires no privileged access to the victim's machine, no credentials, and no unusual user action; the victim only needs to keep Desktop open/selected on the affected repository so the routine background refresh (`_selectRepositoryRefreshTasks` / periodic account-change refresh) runs.

### Recommendation
Anchor GitHub repository identity to the immutable repository ID rather than owner/name text: store and check the API repository `id` when it was first associated, and in `updateRemoteUrl`/`repositoryWithRefreshedGitHubRepository`, refuse to auto-rewrite the remote (or prompt the user) if the newly fetched repository's ID differs from the previously stored `GitHubRepository`'s ID, even when the owner/name text still parses identically.

### Proof of Concept
1. Victim clones `https://github.com/owner/repo` in Desktop; Desktop stores the associated `GitHubRepository` (owner=`owner`, name=`repo`, cloneURL) and the local git remote `origin` points at it.
2. `owner/repo` is renamed/transferred or deleted, freeing the `owner/repo` slug (a legitimate, unprivileged GitHub action outside Desktop's control).
3. Attacker creates a new public repository under the exact same freed `owner/repo` slug.
4. Victim reopens/reselects the repository in Desktop (or Desktop's periodic refresh runs). `matchGitHubRepository` re-parses the still-unchanged local remote URL to `owner/repo`, and `api.fetchRepository('owner','repo')` now returns the attacker's repository object with the attacker's `clone_url`.
5. `updateRemoteUrl` sees protocols match, `remoteUrlUnchanged` is true (local remote still equals the last known `cloneURL` text), and `urlsMatch` is false only if the attacker's `clone_url` differs textually (e.g., attacker used a slightly different but API-returned canonical form, or a subsequent legitimate rename triggered the same code path pointing to the wrong target) — triggering `gitStore.setRemoteURL` to silently rewrite `origin` to the attacker-controlled `clone_url` with no dialog or confirmation shown to the victim.

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
