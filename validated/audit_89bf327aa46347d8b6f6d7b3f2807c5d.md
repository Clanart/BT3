## Analysis

The H-12 broken invariant: a public, unprivileged, freely-repeatable entrypoint appends to a shared per-key accounting structure with **no dedup / ownership / idempotency guard**, letting an attacker corrupt state another party depends on and destroy value that was already paid for.

The local analog is `pallet-bandwidth`'s FIFO subscription ledger, fed by the fully public `BandwidthManager.purchase()` entrypoint.

### Title
Unrestricted `purchase()` lets an attacker grief-evict a victim's paid bandwidth subscriptions via the FIFO cap - (File: `modules/pallets/bandwidth/src/lib.rs`, `evm/src/apps/BandwidthManager.sol`)

### Summary
`BandwidthManager.purchase()` is callable by anyone and accepts a caller-supplied `app` and `chain` with no ownership check tying them to `msg.sender`. The resulting `BandwidthPurchaseMsg` is delivered to `pallet-bandwidth::on_accept`, which unconditionally calls `push_subscription` on the `(app_chain, app)` key from the message body. `push_subscription`'s only capacity control is the 1024-entry FIFO cap, which on overflow silently **evicts the oldest entry** (`Allowance::<T>::mutate` → `list.remove(0)`) regardless of who purchased it or how many bytes/how much time remain on it.

### Finding Description
`evm/src/apps/BandwidthManager.purchase(app, tier, months, chain)` (`evm/src/apps/BandwidthManager.sol:148-180`) lets any address pay for any tier and specify an arbitrary `app` identifier and an arbitrary `chain` (the credit chain). There is no binding between `msg.sender` and `app`— this is documented as an intentional "sponsorship" feature (`docs/content/developers/evm/bandwidth/overview.mdx:108-114`), but it also means an attacker can target *any victim's* `(app_chain, app)` key at will.

On the Hyperbridge side, `pallet-bandwidth`'s FIFO ledger is keyed exactly by `(app_chain, app)`: [1](#0-0) 

Every successful purchase (`on_accept`, which is minimally gated — only `request.from` must equal the registered manager for the source chain) calls `push_subscription`, which appends unconditionally: [2](#0-1) 

The eviction logic is the exact broken invariant from H-12's pattern: a public/permissionless call increments/pushes into a shared accounting list with no guard checking whether the pushed entry belongs to the same beneficiary, and once the counter (list length) hits the cap, the oldest entry — which may belong to an entirely different, honest payer — is destroyed:
```rust
let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
    let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
        Some(list.remove(0))
    } else {
        None
    };
    let _ = list.try_push(new_sub);
    evicted
});
```
There is no check that the evicted subscription has already been (mostly) consumed, no minimum-remaining-value guard, and no per-payer isolation within the list. The only price friction is `tierPrice[tier]` on the manager contract for the *cheapest configured tier*, which governance can set arbitrarily low, and which in any case is bounded — the attacker only needs to fund 1024 minimum-tier purchases (a one-time, attacker-controlled cost) to fully evict every legitimate subscription for a targeted `(app_chain, app)`, including large, long-duration, high-value subscriptions purchased by the victim moments before.

This directly mirrors H-12: `pushVaultAmounts` had no guard against being called again after the intended keeper call, letting an attacker corrupt `fundsReceived` and permanently block the intended state transition. Here, `purchase()`/`on_accept` has no guard against being called again against a victim's key, letting an attacker corrupt the FIFO list and permanently destroy the intended (paid-for) allowance.

### Impact Explanation
This is a direct loss-of-funds vector for any app relying on `pallet-bandwidth`: an attacker can permanently destroy a victim's prepaid bandwidth allowance (which can be a $1000+ tier, `docs/content/developers/evm/bandwidth/overview.mdx:18-27`) for the cost of 1024 cheapest-tier purchases, well before the victim's subscription is consumed or naturally expires. The victim's app then either has its cross-chain messages rejected by the `BandwidthGate` (`GateError::NoAllowance`/`Insufficient`) or must repurchase — a straightforward "loss of funds" / "unauthorized... transaction manipulation" against the bounty's own accepted impact categories (bridged assets / bandwidth balances "must move exactly once and only to the rightful beneficiary and amount"). `SubscriptionEvicted` records the loss but does not prevent or compensate it.

### Likelihood Explanation
High. `purchase()` is a fully public, unprivileged EVM entrypoint requiring only fee-token balance; no relayer, prover, admin, or governance action is needed. The attacker fully controls the `app` and `chain` fields, so any known victim `(app_chain, app)` pair (discoverable from `BandwidthCredited`/`BandwidthConsumed` events) is directly targetable. The only cost is 1024 minimum-tier purchases, a bounded, attacker-controlled, one-time expense with no other barrier (no per-app cooldown, no minimum-remaining-bytes protection on eviction, no ownership check).

### Recommendation
Apply the same fix class recommended for H-12 — add a guard before mutating the shared counter/list:
- Reject a purchase (or force_credit) that would evict a subscription whose `remaining_bytes` is still economically significant / not yet substantially drained, or
- Require the pushed subscription's `expires_at`/value to exceed the subscription being evicted before allowing eviction (protect-the-larger-value invariant), or
- Segment the FIFO list per-payer (or raise/parametrize `MAX_SUBSCRIPTIONS` per (chain,app,payer)) so an unrelated purchaser cannot evict another payer's entries, or at minimum
- Emit a hard failure (reject the purchase) instead of silently evicting when the oldest entry has significant unused value remaining, forcing governance/manual intervention rather than silent fund destruction.

### Proof of Concept
1. Victim (a legitimate app operator or sponsor) calls `BandwidthManager.purchase(appBytes, TierFour, 12, "EVM-8453")`, crediting `(EVM-8453, appBytes)` with a 12-month, 96MB high-value subscription (`docs/content/developers/evm/bandwidth/overview.mdx:18-27`, `43-52`).
2. Attacker, with no relationship to the victim's app, observes the `BandwidthCredited` event and extracts `app_chain = EVM-8453`, `app = appBytes`.
3. Attacker calls `BandwidthManager.purchase(appBytes, TierOne, 1, "EVM-8453")` 1024 times (any distinct payer address, only needs `TierOne` price × 1024, cheapest configured SKU) — see `evm/src/apps/BandwidthManager.sol:148-180`, no ownership check on `app`.
4. Each purchase reaches `pallet-bandwidth::on_accept` → `push_subscription` (`modules/pallets/bandwidth/src/lib.rs:400-437`); once `Allowance::<T>::get(EVM-8453, appBytes).len() == 1024`, subsequent pushes evict from the front (`list.remove(0)`), which is the victim's original 12-month/96MB entry (oldest, inserted first) once 1024 attacker entries have superseded it in FIFO order relative to remaining cap slots.
5. `SubscriptionEvicted { app_chain: EVM-8453, app: appBytes, tier: TierFour, lost_bytes: <mostly-unused> }` fires — the victim's paid-for bandwidth is gone, and their app's future dispatches fail the `BandwidthGate` (`GateError::Insufficient`/`NoAllowance`) despite having paid in full.

```rust
		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
```
