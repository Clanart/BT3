### Title
`ReceivedOutput::read` accepts an offset that does not correspond to the output's `script_pubkey`, reporting unspendable funds as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes three independent fields — a scalar `offset`, a `TxOut`, and an `OutPoint` — and returns them as a coherent "spendable output" without ever checking that `key + G * offset` actually produces `output.script_pubkey`. This is the direct analog of consuming externally supplied data (a Chainlink price) without validating it is the data you asked for: the reader trusts an attacker-controlled consistency claim.

### Finding Description
In `Scanner::scan_transaction`, an honest `ReceivedOutput` is only ever constructed when `self.scripts.get(&output.script_pubkey)` returns an offset — i.e., the offset is *proven* to map to the script by the scanner's `HashMap<ScriptBuf, Scalar>` built via `p2tr_script_buf(self.key + (GENERATOR * offset))` in `register_offset` (lines 180–196, 205–212).

`ReceivedOutput::read` (lines 122–134) bypasses this invariant entirely:

```rust
let offset = Secp256k1::read_F(r)?;
output = TxOut::consensus_decode(&mut buf_r)...;
outpoint = OutPoint::consensus_decode(&mut buf_r)...;
Ok(ReceivedOutput { offset, output, outpoint })
```

Any party feeding bytes to `read` can pair:
1. an `offset` that maps to a Serai-controlled script, with
2. a `TxOut` whose `script_pubkey` is an arbitrary attacker-chosen P2TR output (or vice versa — a real Serai output paired with a wrong offset).

Nothing binds the offset to the script. Just as the IronBank oracle accepts `latestRoundData`'s `price` without checking `answeredInRound`/`updatedAt`, `read` accepts the claimed offset without checking `p2tr_script_buf(key + G*offset) == output.script_pubkey`.

### Impact Explanation
Downstream consumers treat a `ReceivedOutput` as a spendable input: the offset is used to derive the signing key share (via `ThresholdKeys::offset` / scheduler paths), and the `output`/`outpoint` identify the UTXO. With a mismatched pair:

- Funds are reported received that are not spendable: the wallet credits an output whose real `script_pubkey` pays to an attacker key or an unrelated script, then constructs/signs a spend using `key + G*offset`, producing a signature valid for the wrong taproot key — the transaction is unspendable/rejected, while the balance was already accounted.
- Conversely, pairing a genuine Serai script output with an incorrect offset causes the multisig to sign with a key that does not control the output, again burning a real deposit.

Either way an unprivileged sender of crafted bytes can corrupt the set of outputs the system believes it owns.

### Likelihood Explanation
Reachable wherever `ReceivedOutput::read` is applied to bytes not produced by the local `Scanner` — e.g., outputs relayed between components, restored from untrusted storage, or supplied by a peer. The attacker needs only control of the serialized byte stream, matching the "untrusted bytes fed to `ReceivedOutput::read`" surface. Crafting the bytes is trivial (any scalar + any `TxOut` + any `OutPoint`); no cryptographic break is required.

### Recommendation
Bind the offset to the script at deserialization or first use. Either:

- Add a `ReceivedOutput::verify(&self, key: ProjectivePoint) -> bool` that recomputes `p2tr_script_buf(key + (GENERATOR * self.offset))` and compares it to `self.output.script_pubkey`, and require callers of `read` to run it; or
- Change `read` to take the base `key` (or a `&Scanner`) and perform the check internally, returning an error on mismatch.

This is the exact analogue of the recommended `require(answeredInRound >= roundId)` check: validate the returned data against what was requested before using it.

### Proof of Concept
```rust
// Given a Scanner whose base key is `key`:
let mut scanner = Scanner::new(key).unwrap();
let offset = scanner.register_offset(Scalar::ONE).unwrap(); // any valid offset

// Attacker-controlled TxOut paying to the attacker's own taproot key:
let evil_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: ScriptBuf::new_p2tr_tweaked(TweakedPublicKey::dangerous_assume_tweaked(
    attacker_x_only_key,
  )),
};
let real_outpoint = OutPoint::new(some_txid, 0);

// Serialize: valid offset bytes + attacker TxOut + real outpoint
let mut bytes = offset.to_bytes().to_vec();
bytes.extend(serialize(&evil_output));
bytes.extend(serialize(&real_outpoint));

let ro = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
// ro.offset() == offset (maps to Serai script)
// ro.output().script_pubkey == attacker's script
// Invariant `p2tr_script_buf(key + G*offset) == output.script_pubkey` is violated,
// yet `read` accepted it as a spendable received output.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
