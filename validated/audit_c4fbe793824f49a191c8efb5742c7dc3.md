### Title
Scanner reports immature coinbase outputs as spendable received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over every transaction in a block, including the coinbase transaction (`block.txdata[0]`), and returns matching coinbase outputs as ordinary `ReceivedOutput`s. Coinbase outputs are consensus-immature for 100 blocks and cannot be spent. Because a `ReceivedOutput` carries no maturity/confirmation metadata, a downstream caller that treats scan results as spendable UTXOs will accept attacker-controlled coinbase payments as received funds that are in fact unspendable — the same bug class as CVE-2024-2628 (UI/spoofing: presenting input as valid/spendable when it is not).

### Finding Description
`scan_transaction` matches `output.script_pubkey` against registered scripts and emits a `ReceivedOutput` for every match [1](#0-0) . `scan_block` applies this to `block.txdata` unconditionally, including `txdata[0]` (the coinbase) [2](#0-1) . There is no check for `tx.is_coinbase()` and no maturity field on `ReceivedOutput` [3](#0-2) . The only mitigation is a doc comment telling callers to post-filter or use `scan_transaction` on `block.txdata[1 ..]` [4](#0-3)  — the API itself still returns immature outputs indistinguishable from spendable ones, so any caller using `scan_block` (the natural "scan a block" API) gets spoofed spendable funds.

An unprivileged miner (or anyone whose transaction ends up as a coinbase, i.e., any miner paying to a watched/registered script_pubkey) can cause a `ReceivedOutput` to be reported that cannot be included in a valid transaction for 100 blocks. If those outputs feed `SignableTransaction::new`, the built transaction's `taproot_key_spend_signature_hash` will commit to an input that consensus rejects [5](#0-4) , or the funds are credited as received while not actually spendable.

### Impact Explanation
Funds are reported received that are not spendable: a coinbase output paying to a registered offset address is surfaced as a normal spendable `ReceivedOutput`. If credited/spent, the resulting transaction is consensus-invalid (immature coinbase spend), and accounting that treats scanned outputs as liquid balance is spoofed by an amount fully controlled by the miner.

### Likelihood Explanation
Any miner can include a payment to a scanned script_pubkey in their coinbase at zero cost beyond the payment itself. Triggering only requires the integrator to consume `scan_block` results without the documented manual post-filter — a footgun the API invites since it returns coinbase matches with no distinguishing marker.

### Recommendation
In `Scanner::scan_block`, skip `block.txdata[0]` (or check `tx.is_coinbase()`) so coinbase outputs are never returned, or add a maturity/coinbase flag to `ReceivedOutput` and reject them in `SignableTransaction::new` / spending paths.

### Proof of Concept
```rust
// A miner crafts a coinbase tx paying `value` sats to `script`,
// where `script` is a script_pubkey registered in `scanner` (e.g. the base P2TR key).
let block: Block = /* mined block whose txdata[0] outputs include
                    TxOut { value, script_pubkey: script } */;
let outputs = scanner.scan_block(&block);
// outputs contains a ReceivedOutput for the coinbase outpoint.
// It is indistinguishable from a spendable output, yet any transaction
// spending it is consensus-invalid for 100 blocks (BIP-113/COINBASE_MATURITY).
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
