### Title
Unauthenticated `ReceivedOutput` records can drive unintended transaction signing - (File: `networks/bitcoin/src/wallet/send.rs`)

### Summary
`ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` without authenticating that the output was actually discovered by `Scanner`, belongs to the expected key, or exists on-chain. If attacker-controlled bytes are passed to this reader and the resulting object is used by `SignableTransaction::new`, the transaction-signing path treats it as an owned input and creates FROST signing machines for it.

### Finding Description
`ReceivedOutput::read` accepts all three fields directly from untrusted bytes:

- `offset`, read with `Secp256k1::read_F`
- `output`, decoded as an arbitrary `TxOut`
- `outpoint`, decoded as an arbitrary `OutPoint` [1](#0-0) 

`SignableTransaction::new` then uses each supplied object's `output.value`, `offset`, and `outpoint` to construct transaction inputs and calculate available funds. [2](#0-1) 

During signing, `SignableTransaction::multisig` applies the supplied offset to the threshold keys and only checks that the resulting tweaked group key matches `prevouts[i].script_pubkey`. It does not prove that the supplied `outpoint`/`TxOut` pair came from `Scanner`, nor does it independently authenticate the claimed UTXO. [3](#0-2) 

The resulting `TransactionSignMachine` generates each input's Taproot sighash and calls the FROST signer on those messages. [4](#0-3) 

### Impact Explanation
An attacker who can cause a signer to deserialize an attacker-chosen `ReceivedOutput` can make the signing flow treat attacker-declared UTXO data as wallet-owned input data. For a real Serai-controlled UTXO, copying its actual `TxOut` and `OutPoint` and supplying the matching scalar offset causes the script check to pass and causes the threshold signer to produce signature shares for a transaction spending that UTXO.

This permits signing an unintended transaction when the surrounding construction path accepts attacker-supplied received-output records. The impact is unauthorized use of the threshold signing operation and potential theft of wallet funds if the resulting transaction is completed and broadcast.

### Likelihood Explanation
The cryptographic encodings remain canonical, and the script check prevents arbitrary offsets from claiming unrelated scripts. The issue requires an application path to deserialize untrusted `ReceivedOutput` bytes and use them in transaction construction. Within that reachable boundary, no secret material, malformed curve point, malformed scalar, or protocol participant collusion is required: the attacker only controls the serialized record and transaction data that induces signing.

### Recommendation
Treat `ReceivedOutput` as an authenticated scanner result rather than a self-authenticating wire object. Prefer an explicit `AuthenticatedReceivedOutput` construction path only reachable from `Scanner`. If serialized outputs must cross trust boundaries, authenticate the complete serialization or require `SignableTransaction::multisig`/construction to verify the `outpoint`, amount, script, and offset against scanner state or confirmed chain data before creating signing machines.

### Proof of Concept
```rust
use bitcoin::{OutPoint, TxOut};
use bitcoin_serai::wallet::{ReceivedOutput, p2tr_script_buf};
use frost::{curve::Secp256k1, ThresholdKeys};

fn attacker_record(
  keys: &ThresholdKeys<Secp256k1>,
  owned_outpoint: OutPoint,
  owned_txout: TxOut,
) -> Vec<u8> {
  // For a base-key P2TR output, the correct offset is zero.
  let forged = ReceivedOutput::read(&mut [
    Secp256k1::F::ZERO.to_repr().as_ref(),
    &bitcoin::consensus::serialize(&owned_txout),
    &bitcoin::consensus::serialize(&owned_outpoint),
  ].concat().as_slice()).unwrap();

  forged.serialize()
}
```

Using the returned object as a `SignableTransaction` input makes `multisig` accept it whenever `owned_txout.script_pubkey == p2tr_script_buf(keys.group_key()).unwrap()`. The signer then generates Taproot sighashes for the attacker-influenced transaction and produces FROST shares through `TransactionSignMachine::sign`.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
