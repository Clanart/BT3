### Title
Auto-deletion of a `TokenPair` on ERC20 self-destruct permanently orphans already-minted native coins with no supply/backing check - ([File: x/erc20/keeper/msg_server.go])

### Summary
`ConvertERC20` and `ConvertCoin` both auto-delete a native-ERC20 `TokenPair` the moment they detect the underlying contract has been self-destructed, without ever checking whether the associated Cosmos denom still has outstanding minted supply. This mirrors the `removePToken` bug class: state cleanup happens without verifying that no user-facing value is still tracked against the entity being removed.

### Finding Description
For a `IsNativeERC20()` pair, any unprivileged caller invoking `ConvertERC20` or `ConvertCoin` triggers this check: [1](#0-0) 
and the mirrored path in `ConvertCoin`: [2](#0-1) 

If `GetAccountWithoutBalance` shows no code hash (self-destructed or never-a-contract), `DeleteTokenPair` is called unconditionally: [3](#0-2) 

This removes the `denom -> pair` mapping (`deleteDenomMap`) with **no check on `bankKeeper.GetSupply(ctx, pair.Denom)`**. Coins previously minted via `convertERC20IntoCoinsForNativeToken` (1:1 backed by ERC20 escrowed in the module account) remain in circulation in users' wallets, but the denom is now unregistered. `MintingEnabled` (used by `ConvertCoin`/`ConvertERC20` to look up the pair from a denom or contract) will fail to resolve the token pair for that denom going forward, since `GetDenomMap`/`GetTokenPair` return not-found after deletion. There is no `ConvertCoin`-only fallback that still allows redemption of the orphaned coin once the pair is gone.

Because `RegisterERC20` is permissionless when `params.PermissionlessRegistration` is true, an attacker can register an ordinary ERC20, let users convert real economic value into the wrapped Cosmos coin (minting coins backed by escrowed tokens in the module account), then self-destruct the ERC20 contract. As soon as anyone next calls `ConvertERC20`/`ConvertCoin` against that pair, the pair is silently deleted with no compensating action for coin holders. Every unit of the wrapped coin still in wallets becomes permanently unredeemable: it cannot be converted back to the (destroyed) ERC20, since the pair no longer exists, and it cannot be re-registered under the exact same denom (new registrations create a new address-keyed pair pointing to a *new* contract with a colliding denom check via `IsDenomRegistered`, which would in fact now succeed since the old mapping was deleted — opening the door to a second, unrelated party registering a new ERC20 that reuses the freed denom slot for a completely different token).

This is the direct structural analog of `removePToken`: state removal is performed without any invariant check on the outstanding balance/supply tied to the entity being removed, and Origin's own mitigation ("we can recover funds by re-adding the strategy") does **not** apply here — there is no re-registration path with the same address (contract is dead) and the `CreateCoinMetadata` denom collision guard could actually let a stale denom slot be reused by an unrelated ERC20.

### Impact Explanation
Users who hold the wrapped Cosmos coin at the moment (or after) the pair auto-deletes lose the ability to redeem it for the underlying ERC20 — the coin becomes permanently frozen/unbacked value, satisfying the "Critical permanent freezing/locking of user funds" impact bucket. If the freed denom is later reused by a new, unrelated `RegisterERC20` call, holders of the stale coin could also convert it against value backed by a completely different asset pool, corrupting escrow accounting between the stale supply and the newly-escrowed tokens.

### Likelihood Explanation
Reachable by any unprivileged account: registering a self-destructible ERC20 (trivial to write, e.g. exposing a public `selfdestruct` function or triggering `SELFDESTRUCT` opcode), depositing/converting some amount to mint coins, then self-destructing and calling `ConvertERC20` once more to trigger the auto-delete. No governance or privileged role is required at any step, assuming `PermissionlessRegistration` is enabled (a supported, non-privileged-assumption configuration for this module).

### Recommendation
Before calling `DeleteTokenPair` in the self-destruct branches of `ConvertERC20`/`ConvertCoin`, check `bankKeeper.GetSupply(ctx, pair.Denom)`. If supply is non-zero, either (a) refuse to auto-delete and instead mark the pair `Enabled = false` (as `ToggleConversion` already supports) while keeping the denom mapping alive so a governance-controlled recovery/re-mapping path remains possible, or (b) burn/reconcile outstanding supply against the destroyed contract's last-known escrow balance before removing the mapping. Additionally, `CreateCoinMetadata`/`SetToken` should never allow a freed denom slot to be reissued to a different underlying contract while any of the old denom's supply remains outstanding.

### Proof of Concept
1. With `PermissionlessRegistration=true`, deploy a minimal ERC20 contract that also implements a callable `kill()` function invoking `SELFDESTRUCT`.
2. Call `MsgRegisterERC20` with the contract address — `registerERC20` creates a `TokenPair` (native ERC20 owner) and coin metadata/denom. [4](#0-3) 
3. Call `MsgConvertERC20` to escrow tokens and mint the wrapped coin to a receiver (`convertERC20IntoCoinsForNativeToken`), then transfer/distribute the minted coin to multiple holders. [5](#0-4) 
4. Call `kill()` on the ERC20 contract to self-destruct it (code hash cleared via `DeleteAccount`/`DeleteCodeHash`). [6](#0-5) 
5. Call `MsgConvertERC20` again (any amount, any signer) against the same pair — `GetAccountWithoutBalance` shows no code hash, so `DeleteTokenPair` executes and removes the denom mapping, while wallets still hold the previously minted coin. [1](#0-0) 
6. Any holder attempting `MsgConvertCoin` for that denom now fails to resolve a `TokenPair` (mapping deleted), permanently freezing their coin balance with no recovery path.

// convertERC20IntoCoinsForNativeToken handles the erc20 conversion for a native erc20 token
// pair:
//   - escrow tokens on module account
//   - mint coins on bank module
//   - send minted coins to the receiver
//   - check if coin balance increased by amount
//   - check if token balance decreased by amount
//   - check for unexpected `Approval` event in logs
func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

// DeleteTokenPair removes a token pair.
func (k Keeper) DeleteTokenPair(ctx sdk.Context, tokenPair types.TokenPair) {
	id := tokenPair.GetID()
	k.deleteTokenPair(ctx, id)
	k.deleteERC20Map(ctx, tokenPair.GetERC20Contract())
	k.deleteDenomMap(ctx, tokenPair.Denom)
	k.deleteAllowances(ctx, tokenPair.GetERC20Contract())
}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}

// DeleteAccount handles contract's suicide call:
// - clear balance
// - remove code
// - remove states
// - remove the code hash
// - remove auth account
func (k *Keeper) DeleteAccount(ctx sdk.Context, addr common.Address) error {
	cosmosAddr := sdk.AccAddress(addr.Bytes())
	acct := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	if acct == nil {
		return nil
	}

	// NOTE: only Ethereum contracts can be self-destructed
	if !k.IsContract(ctx, addr) {
		return errors.New("only smart contracts can be self-destructed")
	}

	// set account to a base account to set the whole balance as spendable
	baseAccount := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	k.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(cosmosAddr, baseAccount.GetPubKey(), baseAccount.GetAccountNumber(), baseAccount.GetSequence()))

	// clear balance
	if err := k.SetBalance(ctx, addr, new(uint256.Int)); err != nil {
		return err
	}

	var keys []common.Hash

	// clear storage
	k.ForEachStorage(ctx, addr, func(key, _ common.Hash) bool {
		keys = append(keys, key)
		return true
	})

	for _, key := range keys {
		k.DeleteState(ctx, addr, key)
	}

	// clear code hash
	k.DeleteCodeHash(ctx, addr)

	// remove auth account
	k.accountKeeper.RemoveAccount(ctx, acct)

	k.Logger(ctx).Debug(
		"account suicided",
		"ethereum-address", addr.Hex(),
		"cosmos-address", cosmosAddr.String(),
	)

	return nil
}
