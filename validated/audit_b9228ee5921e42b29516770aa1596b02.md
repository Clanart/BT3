### Title
`SignableTransaction::new` trusts the attacker-supplied `TxOut.value` inside `ReceivedOutput` instead of the actual on-chain UTXO value - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
`BountyCore.receiveFunds` credited a deposit for whatever `_volume` was declared while only checking `msg.value` when the token was native — the claimed amount was decoupled from the amount actually delivered. The same bug class exists in `networks/bitcoin/src/wallet`: `ReceivedOutput` bundles a *claimed* `TxOut` (script + value) with an `OutPoint`, and `ReceivedOutput::read` accepts that claim verbatim from untrusted bytes. `SignableTransaction::new` then computes `input_sat`, the `NotEnoughFunds` check, change, and the implicit fee entirely from the *claimed* `output.value`, and `multisig` verifies only that `script_pubkey` matches the offset-derived key — never that the claimed value equals the value of the UTXO the `OutPoint` actually references on chain.

### Finding Description
`ReceivedOutput` contains `offset: Scalar`, `output: TxOut`, `outpoint: OutPoint` (`networks/bitcoin/src/wallet/mod.rs:89-97`). `ReceivedOutput::read` deserializes all three fields from attacker-controlled bytes with no consistency check against the chain (`mod.rs:122-134`).

In `SignableTransaction::new`:

- `input_sat` is summed from `input.output.value` — the claimed amount, not the referenced UTXO's amount (`send.rs:175`).
- The `NotEnoughFunds` gate compares claimed inputs against payments (`send.rs:215-221`), so an inflated claim passes.
- The change output is `input_sat - payment_sat - fee`, so an inflated claim mints an oversized change output (`send.rs:228-230`).
- `prevouts` stores the claimed `TxOut`s (`send.rs:253`), and `fee()` reports `sum(prevouts.value) - sum(outputs.value)` (`send.rs:138-141`).

At signing time, `TransactionSignMachine::sign` uses `Prevouts::All(&self.tx.prevouts)` (`send.rs:373-386`), i.e., the Schnorr signature commits to the *claimed* amounts under BIP-341. The only validation of a `ReceivedOutput` is `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` in `multisig` (`send.rs:273-285`), which constrains the script but never the value nor the existence/ownership of the `outpoint`.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (e.g., any path where stored/relayed outputs are re-deserialized, such as the processor's `Output::read` → `ReceivedOutput::read` chain in `processor/src/networks/bitcoin.rs:156`) can:

1. **Report funds received that are not spendable / don't exist** — set `output.value` to an arbitrary amount over a real or fake outpoint. Downstream accounting (`Output::balance()` → `self.output.value()`, `processor/src/networks/bitcoin.rs:128-130`) credits the claimed value.
2. **Force the threshold multisig to sign an unbroadcastable transaction** — since the BIP-341 sighash commits to the claimed prevout amounts, consensus nodes recompute the sighash with the *actual* UTXO amounts; any discrepancy makes every input signature invalid. The multisig burns a signing round on a transaction that can never confirm, halting scheduled payments until the poisoned output is cycled out — a direct analog of the report's `deposits[]`-poisoning DoS of `refundDeposit`.
3. **Burn real funds as fee** — conversely, if a genuine large UTXO is repackaged with a smaller claimed value elsewhere in accounting, or `NotEnoughFunds` is bypassed with a fabricated input, the arithmetic produces transactions whose "leftover" becomes fee, or whose signatures commit to wrong amounts, permanently stalling the UTXO set.

### Likelihood Explanation
Reachability requires feeding crafted bytes to `ReceivedOutput::read`. The rules explicitly classify bytes fed to `ReceivedOutput::read` as reachable untrusted input. Once reached, exploitation is deterministic: no check anywhere in `wallet/` compares `TxOut.value` against the referenced UTXO, and `SignableTransaction::new` never inspects the `outpoint` beyond copying it into `TxIn.previous_output` (`send.rs:179-184`). The malformed transaction will pass `multisig` (script check only), produce valid signature *shares*, complete into a `Transaction`, and fail only at broadcast — after the multisig has already committed a signing session.

### Recommendation
Bind the claimed value to reality the way the fix binds `_volume` to `msg.value`:

- Wherever `ReceivedOutput`s are constructed or re-read, verify `outpoint` resolves on-chain and that the resolved `TxOut` equals the stored `output` (value *and* `script_pubkey`) before accounting or signing.
- In `SignableTransaction::new`, treat `ReceivedOutput` as untrusted: at minimum, document/enforce that `output.value` must equal the confirmed UTXO value, and have `multisig` re-derive the expected output for each input rather than trusting the embedded `TxOut`.
- Fail loudly (return a `TransactionError`) instead of signing when any input's claimed amount cannot be verified, so a poisoned input cannot burn a FROST signing round.

// Build a Scanner and register an offset so we know a script the multisig owns.
let mut scanner = Scanner::new(key).unwrap();
let offset = scanner.register_offset(Scalar::random(&mut OsRng)).unwrap();
let offset_key = key + (ProjectivePoint::GENERATOR * offset);
let script = p2tr_script_buf(offset_key).unwrap();

// Take a real outpoint paying `script` worth only `real_value` sats,
// then craft a ReceivedOutput claiming an inflated value.
let forged = ReceivedOutput::read(&mut {
    let mut w = Vec::new();
    w.extend(offset.to_bytes());                                          // offset
    // TxOut with claimed value far above the real UTXO value
    bitcoin::consensus::serialize(&TxOut {
        value: Amount::from_sat(real_value * 1000),
        script_pubkey: script.clone(),
    }).iter().for_each(|b| w.push(*b));
    bitcoin::consensus::serialize(&real_outpoint).iter().for_each(|b| w.push(*b));
    w
}.as_slice()).unwrap();

// This succeeds: NotEnoughFunds is checked against the CLAIMED value.
let tx = SignableTransaction::new(
    vec![forged],
    &payments,            // payments sized to the claimed balance
    Some(change_script),  // receives claimed_value - payments - fee
    None,
    FEE,
).unwrap();

// multisig accepts it: only script_pubkey is checked, never the value.
let machine = tx.multisig(&keys[&Participant::new(1).unwrap()]).unwrap();

// The threshold signs sighashes committing to Prevouts::All(claimed amounts).
// Every node recomputing BIP-341 sighash with the real UTXO amount rejects
// each input signature -> transaction is permanently unbroadcastable.
