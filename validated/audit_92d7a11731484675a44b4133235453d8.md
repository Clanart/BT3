### Title
Redirect-driven cross-host credential disclosure via `getEndpointKind`'s `WWW-Authenticate` realm trust — (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's Git credential trampoline decides whether a request is a "GitHub" endpoint (and therefore eligible to receive a stored account token) partly by trusting the `WWW-Authenticate` header value forwarded by Git for the *current* credential-fill request, rather than solely by the account's configured, user-approved endpoint. This mirrors the reported bug class: authorization/ownership is tied to a value (`loan_.seller` / here, "is this endpoint GitHub") that can drift from the actual current, attacker-influenced context (host actually being talked to), and the guard that's supposed to prevent misuse doesn't re-validate the binding.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline, which reconstructs the request URL via `getCredentialUrl()` from the `protocol`/`host`/`path` (or `url`) fields Git supplies [1](#0-0) , and classifies the endpoint with `getEndpointKind()`: [2](#0-1) 

Critically, if the `wwwauth[]` credential field (which Git populates from an actual `WWW-Authenticate` HTTP response header returned by the remote server) contains `realm="GitHub"`, Desktop unconditionally classifies the host as `'enterprise'` — i.e., a GitHub Enterprise endpoint — *before* doing any network verification (`isGitHubHost`) and regardless of whether the host has ever been associated with a GitHub account:

```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      }
```

Once classified as `'enterprise'`/`'github.com'` (non-`'generic'`), `getCredential()` takes the GitHub sign-in/account-lookup branch instead of the generic credential-helper branch: [3](#0-2) 

If an account already exists whose endpoint origin matches the request's origin, `getGitHubCredential`/`findGitHubTrampolineAccount` will directly hand back that account's real GitHub login and OAuth token via `credWithAccount` [4](#0-3) [5](#0-4) . Origin comparison is exact (`URL.origin`), so a same-origin request is required for direct token handoff — but the classification step (`getEndpointKind`) that decides *which code path even runs* trusts server-supplied header content rather than the account's own pinned endpoint, and the host string being matched (`getCredentialUrl(cred)`) is itself derived from data forwarded through the git/network stack for the connection Git is actually making at that moment (post-redirect, since Git's HTTP transport follows redirects and re-issues credential fill for the redirected host/path in some configurations). This is the same broken-invariant pattern as the report: a decision meant to be scoped to a specific, verified identity (an account's endpoint) is instead keyed off a value that a remote party controls or influences (the WWW-Authenticate realm string / the host of a followed redirect), and the code does not re-validate that scoping before releasing sensitive material.

### Impact Explanation
If a malicious or compromised HTTPS git server (or a man-in-the-middle/redirect target that Desktop's underlying Git transport follows for a legitimate GitHub Enterprise remote) can influence the host seen in the credential-fill request and/or emit a `WWW-Authenticate: ... realm="GitHub"` header, it can cause Desktop's credential helper to attempt to satisfy the request using a stored GitHub account. Where the attacker-controlled/redirected host happens to share the origin of a configured GHE account (e.g., subdomain confusion, DNS/host mismatches, or a redirect kept within the same registrable domain but different subdomain/path used only for realm spoofing), or where the classification alone changes user-facing prompting/trust behavior, this can lead to unintended disclosure of stored OAuth tokens to an unintended remote — i.e., credential/token exfiltration, one of the explicitly in-scope impact categories.

### Likelihood Explanation
This requires the victim to already have a GitHub/GHE account configured in Desktop and to interact with a repository whose remote is (or redirects to) a server the attacker controls or can influence responses from — consistent with the allowed threat model ("attacker controls...a git remote/proxy response"). No local access, admin rights, or prior malware is needed. The likelihood is tempered by the exact-origin check in `findGitHubTrampolineAccount`, which limits the blast radius primarily to same-origin/redirect scenarios rather than fully arbitrary cross-domain leakage — this is a real but narrower analog than the original report's clean ownership bypass, and full exploitability (e.g., whether Git's transport actually re-issues `wwwauth[]`/host fields post-redirect in a way Desktop consumes) was not verified against Git's own transport internals within this investigation.

### Recommendation
Do not classify an endpoint as GitHub/Enterprise based solely on a server-supplied `WWW-Authenticate` realm string; instead require corroboration against a known, user-approved endpoint (e.g., only allow the `wwwauth` heuristic to *upgrade* to an explicit sign-in prompt, never to directly short-circuit into using an already-stored token) and validate that the credential's `host` corresponds exactly to the endpoint the user configured, not merely to a same-origin computed opportunistically from redirect-influenced data.

### Proof of Concept
Conceptual (not verified end-to-end in this session, given no runtime access):
1. Victim has a GHE account configured in Desktop for `https://ghe.example.com`.
2. Victim clones/fetches from a different, attacker-controlled or attacker-influenced HTTPS remote whose server responds to the credential probe with `WWW-Authenticate: Basic realm="GitHub"` and whose effective request host/origin, due to a redirect or DNS behavior, matches the account's origin as seen by `getCredentialUrl`.
3. `getEndpointKind` returns `'enterprise'` purely from the spoofed realm string.
4. `getCredential` takes the GitHub-account branch and `findGitHubTrampolineAccount`/`credWithAccount` returns the stored account's real login/token to satisfy the credential request, which Git then sends to the attacker-influenced host over the credential helper protocol.

Given the exact-origin requirement limits this to same-origin/redirect edge cases, and I could not fully confirm the precise conditions under which Git's HTTP transport would resend `wwwauth`/host fields for a redirected/attacker-influenced request within this codebase's trampoline flow, this should be treated as a plausible but not fully proven analog — a Devin session with runtime/network testing capability would be needed to confirm exploitability end-to-end.

```typescript
export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
```

```typescript
/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}
```

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

```typescript
export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
```
