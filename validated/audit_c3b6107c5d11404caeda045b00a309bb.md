## Finding

Both `Vault.sol`'s missing pause wiring and this Desktop analog share the same broken-invariant pattern: a security control that exists in the dependency (OpenZeppelin's pausable / Git's own clone-time protections) is present but the calling code actively neutralizes it instead of enabling it.

### Title
Git's built-in clone-time protection is explicitly disabled during recursive clones - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` builds the execution environment for `git clone --recursive` and hard-codes `GIT_CLONE_PROTECTION_ACTIVE: 'false'` into the environment passed to the `git` process, unconditionally overriding whatever value the environment/Git defaults would otherwise use. [1](#0-0) 

### Finding Description
Modern Git ships a built-in protection mechanism (surfaced via the `GIT_CLONE_PROTECTION_ACTIVE` environment toggle) that guards recursive clones against malicious repository content — e.g. crafted nested/submodule repositories that abuse symlinked `.git` directories or embedded hook files to escape the intended clone destination or trigger code execution during checkout of an attacker-controlled remote. Desktop layers its own defense-in-depth check, `isClonePathSensitive()`, which validates the *destination* path but says nothing about the *content* of the repository being cloned. [2](#0-1) 

The `clone()` function does call `isClonePathSensitive()`, so that particular guard is correctly wired up. [3](#0-2) 

However, immediately after that check, the same function builds the `git clone --recursive` environment and forces `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`, which disables Git's own upstream safeguard for the exact operation (`--recursive` clone of a fully attacker-controlled, unauthenticated remote URL) that the safeguard was designed to protect. This mirrors the `Vault`/`ERC20PausableUpgradeable` pattern from the seed report: a safety mechanism is available (inherited from the underlying dependency/library) but the integrating code either fails to invoke it (Vault) or, worse here, deliberately flips it off (Desktop), leaving the "pause"-equivalent protection unreachable for the very code path that needs it.

### Impact Explanation
`clone()` is invoked by the "Clone repository" UI flow and by the `open-repository-from-url` deep-link handler in `Dispatcher.openOrCloneRepository` / `openRepositoryFromUrl`, both of which accept a remote URL entirely controlled by whoever crafted the clone URL or "Open in Desktop" link. [4](#0-3) [5](#0-4) 

Because `--recursive` is always passed and the environment strips out the protection Git itself would otherwise apply, cloning a malicious repository (or one with malicious submodules) removes a layer of defense specifically meant to stop symlink/hook-based escapes during recursive clone — i.e. exactly the "attacker controls a cloned/fetched repository … result is code execution or file write outside the repo" class called out as in-scope. [6](#0-5) 

### Likelihood Explanation
The path is reachable with no special user action beyond the app's normal, intended clone workflow (typing/pasting a clone URL, or clicking a "github-mac://openRepo/…" style deep link) — the exact “attacker controls … a link or deep link the user clicks” scenario, since `openRepositoryFromUrl` will silently invoke `_startOpenInDesktop` → clone with a URL taken straight from the deep link. [7](#0-6) 
The `isClonePathSensitive` destination check does not inspect repository content, so it provides no mitigation for this specific disabled protection.

### Recommendation
Do not override `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. Either omit it entirely (letting Git apply its default/upstream protection) or set it to `'true'`/leave it unset so Git's native recursive-clone safeguards remain active for untrusted remotes. If the override was added to work around a specific compatibility issue, gate it narrowly (e.g., only for known-trusted, already-authenticated remotes) rather than unconditionally for every clone.

### Proof of Concept
1. Craft a malicious Git repository containing a submodule entry whose gitlink/`.git` reference is replaced with a symlink or otherwise attempts to abuse Git's recursive-submodule checkout behavior (the class of issue Git's own clone protection was built to stop).
2. Host it at a URL and either:
   - Send the victim a `x-github-client://openRepo/<attacker-url>` deep link (parsed by `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository`), or
   - Have the victim paste the URL into the normal "Clone repository" dialog.
3. Desktop calls `clone(url, path, options)`, which passes `isClonePathSensitive` (destination is a normal folder, not a "sensitive location") but sets `GIT_CLONE_PROTECTION_ACTIVE=false` for the underlying `git clone --recursive` invocation, removing the guard that would otherwise have blocked the malicious submodule behavior.
4. Because the protection is disabled at the environment level, whatever mitigation Git's protection was meant to enforce during the recursive submodule checkout does not apply.

**Note / uncertainty:** I could not fully determine, from the indexed code alone, the exact upstream Git version/behavior gated by `GIT_CLONE_PROTECTION_ACTIVE` in this fork's bundled Git, nor find a comment in this repo explaining why it's forced to `'false'` (no matches for `GIT_CLONE_PROTECTION_ACTIVE` elsewhere in the indexed codebase). Given the file index size limits, some related files (e.g. embedded Git version metadata or additional comments) may not be fully covered — starting a Devin session against the full repository would allow confirming exactly which Git-side protection is disabled and its precise exploit conditions before treating this as a confirmed, high-confidence vulnerability rather than a strong analog candidate.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
