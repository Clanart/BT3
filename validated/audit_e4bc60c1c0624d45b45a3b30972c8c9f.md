I need to check whether the round-1 `EncryptionKeyMessage` binds the encryption key to the sender (e.g., PoK signature covering it) — the analog is "secret sent to an unauthenticated peer key".### Title
DKG secret share encrypted to an unauthenticated encryption key: `enc_key` is never bound to the sender's proof-of-knowledge, so a party able to tamper with a commitments message in transit receives the victim's share - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Daytona bug class is "credentials sent over a connection whose peer was never authenticated." PedPoP's analog: every participant broadcasts an `EncryptionKeyMessage` carrying their ephemeral decryption key `enc_key`, and every dealer encrypts that participant's secret share via ECDH to whatever key was registered — but `enc_key` is never authenticated. The only signature in the round-1 message, the Schnorr PoK `sig`, covers `cached_msg`, which is built exclusively from the `t` Feldman commitments in `Commitments::read`/`write` [1](#0-0) . The challenge is computed over `context`, participant index `l`, `R`, and `Am = cached_msg` only [2](#0-1) . `Decryption::register` then stores `msg.enc_key` verbatim with no validity check at all [3](#0-2) , and `Encryption::encrypt` derives the shared key from `self.decryption.enc_keys[&participant]` [4](#0-3) .

### Finding Description
An attacker who can modify the wire bytes of participant `l`'s round-1 message — a MITM on the transport, or a deployment where the in-band Schnorr PoK is treated as the message authentication (the crate explicitly disclaims authenticated channels: "This still doesn't mean the DKG offers an authenticated channel" [5](#0-4) ) — replaces `enc_key` with a key `G*x` they control. The PoK `sig` still verifies because `enc_key` is not part of `cached_msg` nor of `challenge`. All `n-1` honest dealers then encrypt `f_j(l)` under `cipher(context, ecdh(key_i, G*x))` [6](#0-5)  and hand the ciphertexts to "participant `l`". The attacker decrypts every `f_j(l)` (each `EncryptedMessage` carries its per-message public key `key` and a valid `pop`, so nothing else rejects). The per-message PoP only proves knowledge of the per-message key, not that the destination key belongs to `l`.

### Impact Explanation
The attacker learns the victim's complete secret share `s_l = Σ_j f_j(l)` for participant index `l`. That is a threshold key share: the attacker can produce valid FROST signature shares as participant `l` in any signing session including `l`, and combined with shares for `t-1` other controlled indices can recover the full group key. This is exactly the "credential leak to an unauthenticated endpoint" shape of the reference bug — the secret share (the credential) is sent encrypted to a party whose key was never verified.

### Likelihood Explanation
Requires the ability to substitute bytes of one participant's commitments message before dealers call `generate_secret_shares`. The crate documents reliance on an external authenticated channel, but the PoK signature is the natural in-band authentication and it demonstrably does not cover `enc_key` — the key field travels completely outside the signed transcript. Medium severity, matching the reference (high attack complexity, confidentiality impact on key material).

### Recommendation
Bind `enc_key` into the round-1 authentication: either append `msg.enc_key.to_bytes()` to the `cached_msg`/commitments bytes fed into `challenge::<C>` [2](#0-1) , or add a second Schnorr proof-of-possession over `enc_key` verified in `verify_r1` alongside `msg.sig.batch_verify` [7](#0-6) .

### Proof of Concept
1. Honest participant `l` broadcasts `EncryptionKeyMessage { msg: Commitments{…, sig}, enc_key: K_l }`.
2. Attacker intercepts, replaces `enc_key` with `K_e = G*x` (x known), forwards the message. `msg.sig` still passes `batch_verify` since `challenge` never includes `enc_key`.
3. Each dealer `j` calls `self.encryption.encrypt(rng, l, share_bytes)` which ECDHs to `enc_keys[l] = K_e` [8](#0-7) .
4. Attacker collects all `EncryptedMessage`s for `l`, computes `ecdh(x, msg.key)` per message, applies `cipher(context, …)`, sums the decrypted `SecretShare`s: recovers `s_l`, and can sign as participant `l` in FROST.

  pub(crate) fn register<M: Message>(
    &mut self,
    participant: Participant,
    msg: EncryptionKeyMessage<C, M>,
  ) -> M {
    assert!(
      !self.enc_keys.contains_key(&participant),
      "Re-registering encryption key for a participant"
    );
    self.enc_keys.insert(participant, msg.enc_key);
    msg.msg
  }
