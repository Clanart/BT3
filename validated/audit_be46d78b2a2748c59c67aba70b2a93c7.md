Based on my investigation, the analog is in the KIP-249 auction (MEV) module's off-chain bid admission logic.

### Title
Auction `BidPool` admits and rebroadcasts bids without checking searcher nonce reuse, enabling replay of a previously consumed `AuctionTx` bid - (File: kaiax/auction/impl/bid_pool.go)

### Summary
The SAML report's root cause is that a signed, security-critical, single-use assertion (`SAMLResponse`) is accepted repeatedly because the consuming component never checks whether it has already been used, relying only on signature and expiry validity. The Kaia analog is the `kaiax/auction` module's `BidPool.validateBid`/`insertBid`, which validates a searcher-signed `AuctionTx` bid purely by signature, block-number-window, bid amount, size, and gas limit — it never checks `bid.Nonce` against the searcher's currently unconsumed on-chain nonce before admitting the bid into the pool and building/broadcasting a bundle for it.

### Finding Description
A `Bid` (`kaiax/auction/bid.go`) carries a `Nonce` field that is part of the EIP-712 signed struct (`kaiax/auction/eip712.go:75-118`, `auctionType`/`auctionTypeV3` include `nonce`), mirroring the design of a single-use, replay-resistant credential — analogous to a SAML bearer assertion that is supposed to be consumable once. However, `BidPool.validateBid` (`kaiax/auction/impl/bid_pool.go:345-395`) only checks: bid-hash dedup, sender-has-different-winner-for-block, block-number window, bid > 0, data size, gas limit, and the two ECDSA signatures (`validateBidSigs`, lines 397-419). At no point does it query the auction entry point contract's nonce state (`GetNoncesAndDeposits`, seen in the generated bindings `contracts/bindings/auction/Kip249.go:448-471`) or otherwise verify that `bid.Nonce` matches the searcher's next unused nonce before accepting the bid, building a bundle from it (`kaiax/auction/impl/builder.go`), and gossiping it to peers.

Because the pool's admission rules are keyed on `(blockNumber, targetTxHash)` and `(blockNumber, sender)` rather than on-chain nonce state, an old, previously-executed `AuctionTx` (with a stale nonce that was already consumed on-chain in an earlier block) can be resubmitted against a *new* target transaction hash / block number combination and will pass every off-chain admission check in `validateBid`, since none of those checks reference nonce freshness. The bid will be bundled and included in a candidate block; only the final on-chain contract call (out of scope for this repo, only present as a `Kip249`/`Kip249V3` binding and as a non-production `AuctionEntryPointMock.sol` with the nonce check explicitly commented out at `contracts/testing/system_contracts/AuctionEntryPointMock.sol:75-107`) is left as the last line of defense, exactly like esaml's no-op default duplicate detector.

### Impact Explanation
If the on-chain replay guard is bypassed, delayed, or the deployed `AuctionEntryPoint` differs from what the client validates against, a captured/leaked `AuctionTx` bid (signed once by a searcher and observed via the block, mempool, gossip, or CN logs) could be rebroadcast and reprocessed by proposers as a fresh winning bid, resulting in duplicate settlement / unauthorized fee or bid extraction from the searcher's deposit, or a proposer building an invalid bundle that a different honest node rejects — a state-divergence / consensus-safety risk consistent with the "acceptance of an invalid transaction" and "gasless/auction settlement theft" categories.

### Likelihood Explanation
Reachable by any unprivileged party that can observe a previously broadcast, network-visible `AuctionTx`/bid (P2P bid gossip, RPC `auction_submitBid`, or block data) and resubmit it via the public `auction_submitBid` RPC (`kaiax/auction/impl/api.go:118-142`) — no special privileges required. Likelihood is tempered because the final authorization still nominally depends on the deployed on-chain `AuctionEntryPoint` contract's own nonce bookkeeping, which is not present in this repository's source (only bindings and a mock with the check commented out), so it cannot be confirmed from this codebase whether that on-chain defense is actually enforced in production.

### Recommendation
Add an explicit nonce-freshness check to `BidPool.validateBid` (or `insertBid`) that reads the searcher's current on-chain nonce (e.g., via the equivalent of `GetNoncesAndDeposits`) and rejects any bid whose `Nonce` does not match the expected next value, mirroring the one-time-use enforcement that `esaml`'s `DuplicateFun` was meant to provide. This closes the gap at the bid-pool layer rather than depending solely on the (unverified in this repo) on-chain contract enforcement.

### Proof of Concept
1. A searcher submits a valid signed `AuctionTx` bid (nonce N) via `auction_submitBid`; it is admitted, bundled, and included in block B.
2. An attacker who observed this bid (via P2P `HandleBid`, block data, or logs) resubmits the identical `SearcherSig`/`AuctioneerSig` bid payload for a new `TargetTxHash`/future `BlockNumber` within the `allowFutureBlock` window.
3. `BidPool.validateBid` (`kaiax/auction/impl/bid_pool.go:345-395`) performs no nonce-vs-current-state check, so all checks pass (different bid hash due to different target/blockNumber, valid signatures, sender not already a winner for that block).
4. The stale bid is admitted, bundled by `builder.go`, and proposed for inclusion — with the actual replay-prevention outcome depending entirely on unverifiable on-chain contract logic not present in this repository. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

	Deposits []*big.Int

		Deposits []*big.Int
	})

	outstruct.Deposits = *abi.ConvertType(out[1], new([]*big.Int)).(*[]*big.Int)

	return *outstruct, err

}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
