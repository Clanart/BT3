### Title
Sender-code restriction for gasless swaps is enforced only at mempool admission, not at block-building/execution time, allowing a restricted contract account to consume proposer-funded gasless lending - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The gasless module (KIP-247) is designed to block contract accounts ("sender with code") from using the gasless swap/lend flow, since this flow lets a proposer front gas fees on behalf of the swapper and is meant only for plain EOAs performing a simple swap-to-repay. This restriction (`ShouldCheckSenderCode`) is implemented only inside `checkBalanceForApprove`/`checkBalanceForSwap`, which are invoked through `GetCheckBalance()` at transaction-pool admission time. The block-building path that actually selects and bundles gasless transactions (`ExtractTxBundles` → `IsExecutable`/`VerifyExecutable`) never calls this sender-code check, and `ApplyTransactions` explicitly skips re-validation, assuming pool-time checks already covered it. This is structurally the same root cause as the wiTry finding: a restriction meant to gate value-affecting behavior is enforced on one path but not on the actual path that performs the value movement (in wiTry: the vault deposit path via `wiTryVaultComposer`; here: the block-inclusion/bundle path via the worker).

### Finding Description
The gatekeeping restriction is defined in `kaiax/gasless/config.go`: [1](#0-0) 

and enforced in `checkBalanceForApprove`/`checkBalanceForSwap`: [2](#0-1) [3](#0-2) 

These functions are reachable only via `GetCheckBalance()`: [4](#0-3) 

which is wired into transaction-pool admission (`blockchain/tx_pool.go`), not into the block-assembly path.

The block-building path that actually decides which gasless transactions get bundled with a proposer-funded `LendTx` and included in a block is `ExtractTxBundles`, which relies on `IsExecutable`/`VerifyExecutable`: [5](#0-4) [6](#0-5) 

`VerifyExecutable` checks nonce sequencing, token/spender matching, amounts, and deadlines (Sx, Ax, AP1, SP1-4), but it never calls `checkBalanceForSwap`/`checkBalanceForApprove` and therefore never checks `ShouldCheckSenderCode()`. During actual block assembly, `Task.ApplyTransactions` explicitly documents that it relies on pool-time validation and does not redo it: [7](#0-6) 

Because the sender-code restriction exists solely inside the pool-admission helper and is not part of `VerifyExecutable`/`ExtractTxBundles`/`ApplyTransactions`, any path that gets a gasless swap/approve transaction into the pending set without going through the normal `AddLocal`/`AddRemote` balance-check hook (e.g., transactions received as part of `p2p`-gossiped bundles, transactions re-queued after a reorg, or any other route that skips `GetCheckBalance`) will be bundled and executed by the block-building code without ever verifying that the sender is a plain EOA. This is the direct analog of the wiTry bug: the `SOFT_RESTRICTED_STAKER_ROLE` check exists only in `StakediTry`'s direct staking function, and the alternate path (`wiTryVaultComposer._depositAndSend` → `VAULT.deposit`) never re-checks it, letting a restricted actor reach the vault through a path that doesn't enforce the restriction. Here, the "restricted actor" is a contract account (which the module intends to exclude from gasless swaps, likely to prevent reentrancy/flash-loan-style abuse of the proposer-funded lending mechanism), and the alternate, unchecked path is the block-building/bundling pipeline.

### Impact Explanation
If a contract account can get a `GaslessApproveTx`/`GaslessSwapTx` into a proposer's pending pool set without passing through `GetCheckBalance` (e.g., via any tx-pool ingestion route that bypasses the balance-check hook, or through logic changes/refactors that call `ExtractTxBundles` on a broader tx set than what was pool-validated), the block builder will still generate a `LendTx` funded by the block proposer and mint gasless lending value to that contract, exactly the abuse `ShouldCheckSenderCode` was meant to prevent. This can result in unauthorized value transfer from block proposers (loss of proposer-funded gas) and misuse of the gasless subsidy mechanism by exactly the class of accounts the protocol design intended to exclude, since the sender-restriction check is not re-validated at the only place where the value-transferring `LendTx` is actually generated and included.

### Likelihood Explanation
The likelihood is bounded by whether any tx-pool ingestion route other than the standard `AddLocal`/`AddRemote` validation path (which calls `GetCheckBalance`) can populate the pending transaction set consumed by `ExtractTxBundles`/`ApplyTransactions`. This code path is reachable purely through a submitted transaction (no privileged access needed) provided such an alternate ingestion route exists; confirming the exact set of all such routes in `blockchain/tx_pool.go` beyond what was inspected here (only 1 direct reference to `checkBalance` in `blockchain/tx_pool.go`) would require deeper tracing of every tx admission entry point, which was not fully completed within available exploration.

### Recommendation
Re-verify `ShouldCheckSenderCode()` (and ideally the full `checkBalanceForSwap`/`checkBalanceForApprove` logic) inside `VerifyExecutable`/`ExtractTxBundles`, immediately before generating the `LendTx` via `GetLendTxGenerator`, so that the sender-code (and other balance/ allowance) restrictions are enforced at the actual point where proposer-funded value is created and included in a block, not solely at pool-admission time.

### Proof of Concept
Not independently reproducible from static analysis alone; a concrete PoC would require identifying and exercising a transaction-pool ingestion route that reaches `ExtractTxBundles`/`ApplyTransactions` for a `GaslessSwapTx` from a sender with code without first passing through `GetCheckBalance()`. This determination requires runtime tracing of `blockchain/tx_pool.go`'s full set of admission/promotion code paths, which could not be fully completed with the available static index.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
