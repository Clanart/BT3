### Title
Scanner reports immature coinbase outputs as spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, while `Scanner::scan_transaction` returns a `ReceivedOutput` solely because its `script_pubkey` matches a registered key. Coinbase outputs are not spendable for 100 blocks under Bitcoin consensus rules. Consequently, an attacker who mines a block can cause the scanner to report an output that `SignableTransaction` will accept and sign, even though the resulting transaction cannot be confirmed.

### Finding Description
`scan_block` iterates over `block.txdata` without skipping `block.txdata[0]` or otherwise checking whether a transaction is coinbase. For each transaction, `scan_transaction` creates a `ReceivedOutput` when the output script is registered, recording only the Taproot offset, `TxOut`, and `OutPoint`. No coinbase maturity information is retained or enforced.

The resulting `ReceivedOutput` can be passed to `SignableTransaction::new`, which converts it into a `TxIn`, includes its value in `input_sat`, and permits a transaction to be constructed. `TransactionSignMachine::sign` then produces a Taproot key-spend signature share for that input. Bitcoin consensus will reject a transaction spending the coinbase output before maturity.

### Impact Explanation
An unprivileged miner can direct a coinbase output to a scanned Serai address. If the wallet path treats scanner results as immediately available funds, it can account for and attempt to spend an output that is not yet spendable. Any signatures generated for the transaction are valid Schnorr signatures, but the transaction itself is consensus-invalid until maturity. This can cause unavailable funds to be selected, transactions to be constructed and signed, and wallet/signing attempts to fail on publication.

### Likelihood Explanation
The condition requires a miner to send a coinbase output to a tracked script and the consumer to call `scan_block` rather than scanning only non-coinbase transactions. Mining a block is permissionless, and `scan_block` exposes the behavior as part of the normal block-scanning API. The API documentation warns that a post-processing pass is needed when outputs must be immediately spendable, but the `ReceivedOutput` type itself does not carry maturity status, making incorrect use straightforward.

### Recommendation
Change `Scanner::scan_block` to skip `block.txdata[0]` by default, matching the processor's `block.txdata[1 ..]` behavior. Alternatively, make `ReceivedOutput` carry a maturity height or coinbase flag and have `SignableTransaction::new` reject immature coinbase inputs. If retaining the current API for a specialized use case, expose it under an explicitly unsafe/immature-aware name and provide a safe `scan_block` that only returns immediately spendable outputs.

### Proof of Concept
```rust
use bitcoin::{Block, Transaction, TxOut};
use bitcoin_serai::wallet::{Scanner, SignableTransaction};

fn scan_immature_coinbase(block: &Block, scanner: &Scanner) {
  // A miner controls the coinbase transaction and can create a P2TR output to
  // the scanner's registered script.
  assert!(block.txdata[0].is_coinbase());

  // scan_block includes txdata[0], so this returns a ReceivedOutput despite
  // Bitcoin's 100-block coinbase maturity rule.
  let outputs = scanner.scan_block(block);
  assert_eq!(outputs.len(), 1);
  let coinbase_output = outputs[0].clone();

  // The wallet accepts the immature output as an input and counts its value.
  let spendable = SignableTransaction::new(
    vec![coinbase_output],
    &[(scanner_script(), 1_000)],
    None,
    None,
    1,
  );

  // Construction succeeds, but broadcasting the fully signed transaction will
  // fail consensus validation because the coinbase input is immature.
  assert!(spendable.is_ok());
}
```

The relevant flow is `Scanner::scan_block` including every transaction, `Scanner::scan_transaction` matching only `script_pubkey`, and `SignableTransaction::new` converting the resulting `ReceivedOutput` into a spend input without a maturity check.
