### Title
Unvalidated attacker-controlled URLs from on-chain DataLayer mirror coins enable SSRF in DataLayer file fetch (`chia/data_layer/download_data.py`)

### Summary
Any unprivileged wallet user can submit a spend bundle that creates a "mirror" coin for an arbitrary DataLayer `store_id`, embedding arbitrary attacker-chosen strings as `urls` in the coin's memos. Every node that owns or subscribes to that store automatically ingests these URLs into its local mirror/subscription database and its `DataLayer` service will later issue outbound HTTP `GET`/`POST` requests to them with no scheme or host validation — mirroring the Mautic Asset SSRF bug class (CVE-2022-25777), where a low-privilege, attacker-supplied "URL" field is used directly for a server-side HTTP fetch.

### Finding Description
A mirror coin is created via `create_mirror_puzzle()` (`P2_PARENT.curry(Program.to(1))`) with a `CREATE_COIN` condition whose memos are `[launcher_id, *urls]` [1](#0-0) . This is exposed to any wallet owner through the `dl_new_mirror` RPC, which takes a raw `urls: list[str]` from the caller and pushes it on-chain with no validation [2](#0-1) [3](#0-2) .

When any node's wallet sees a coin with `create_mirror_puzzle().get_tree_hash()` and it is tracking that `launcher_id` (i.e. it owns or has subscribed to that DataLayer store), it unconditionally decodes the memos and inserts the URLs into the local mirrors table via `dl_store.add_mirror`, without any scheme/host allow-listing: [4](#0-3) .

`DataLayer.update_subscriptions_from_wallet()` then pulls all these mirror URLs straight from wallet RPC into the DataLayer's own subscription server list with no filtering (only trailing-slash stripping) [5](#0-4) .

During periodic sync, `fetch_and_validate()` picks one of these `server_info.url` values and passes it into `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a raw `aiohttp` GET directly against `server_info.url + "/" + filename` with no validation of the host (no blocking of loopback/link-local/private ranges, no scheme allow-list beyond what aiohttp itself enforces): [6](#0-5) [7](#0-6) .

Similarly, `get_downloader()` and `upload_files()` will POST to attacker-influenced `PluginRemote` targets configured from local plugin config, but the more directly exploitable path is the mirror-sourced `server_info.url` consumed by `http_download`, which is fully attacker-controlled string data coming from an on-chain coin memo that any spend-bundle submitter can create.

### Impact Explanation
An unprivileged party (anyone who can submit a spend bundle creating a `create_mirror_puzzle()` coin for a store they don't even need to own) can force any node that is a subscriber or owner of that DataLayer store to make outbound HTTP requests to attacker-chosen destinations — e.g., cloud metadata endpoints (`http://169.254.169.254/...`), internal admin interfaces, or arbitrary internal hosts/ports — classic SSRF. This can be used for internal network reconnaissance/pivoting or to trigger requests against internal-only services from the victim node's IP, matching the CWE-918 pattern in the reference Mautic advisory. It does not directly allow coin theft or consensus divergence, but it is a genuine, remotely triggerable SSRF against any DataLayer participant reachable by an on-chain mirror coin for their subscribed store.

### Likelihood Explanation
Likelihood is high for any node participating in DataLayer as a store owner or subscriber: creating a mirror coin only requires a minimal-value coin spend to the mirror puzzle plus a fee, no special permissions, and the resulting URL is propagated automatically via `coin_added`/`update_subscriptions_from_wallet`/`fetch_and_validate` with no manual approval step. The primary constraint is that the victim node must be tracking (owning or subscribed to) the targeted `launcher_id`.

### Recommendation
Validate mirror/subscription URLs before ever using them for outbound requests: enforce an `http(s)` scheme allow-list, resolve and reject requests to loopback, link-local, and RFC1918 private address ranges (unless explicitly running in a trusted/dev mode), and consider requiring operator confirmation before adding externally-sourced mirror URLs to the active subscription/download list in `data_layer_wallet.py`'s `coin_added` and `data_layer.py`'s `update_subscriptions_from_wallet`/`fetch_and_validate`/`http_download` paths.

### Proof of Concept
1. Attacker submits a normal wallet spend creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memos `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` for a `launcher_id` the victim node is known to subscribe to/own (test harness pattern shown in `test_dl_wallet_rpc.py`, e.g. `dl_new_mirror(... urls=["foo","bar"] ...)` at [8](#0-7) , replacing `urls` with an internal-network target).
2. Victim node's wallet processes the mirror coin in `coin_added`, storing the attacker URL via `dl_store.add_mirror` [4](#0-3) .
3. Victim's `DataLayer.update_subscriptions_from_wallet()` copies the URL into its subscription server list [5](#0-4) .
4. On the next `fetch_and_validate()` cycle, `http_download()` issues an `aiohttp` GET to the attacker-supplied URL, causing the victim's node to make an outbound request to the attacker-chosen internal target [7](#0-6) .

    async def dl_new_mirror(
        self,
        request: DLNewMirror,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""
        if self.service.wallet_state_manager is None:
            raise ValueError("The wallet service is not currently initialized")

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()
        async with self.service.wallet_state_manager.lock:
            await dl_wallet.create_new_mirror(
                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )

        # tx_endpoint will take care of default values here
        return DLNewMirrorResponse(unsigned_transactions=[], transactions=[])

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
