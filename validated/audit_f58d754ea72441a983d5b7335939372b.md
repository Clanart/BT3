Based on my investigation, I found a genuine analog to the reported bug class in the Agave QUIC streamer QoS code, though I want to flag upfront that I was unable to fully verify connection idle-timeout/keepalive limits that could bound the exploitation window — this is noted as an open uncertainty below.

### Title
Staked-peer QUIC connection privilege (`ConnectionPeerType::Staked`) is snapshotted once at connect time and never re-validated against current stake, allowing a peer to retain elevated QoS after unstaking - (File: streamer/src/nonblocking/swqos.rs / streamer/src/nonblocking/quic.rs)

### Summary
The Venus Prime bug is a class of "eligibility timer/flag captured once, never refreshed" bug: `stakedAt` is set from a real staking event but then never re-validated/reset on a later state transition (`issue` irrevocable), so stale state grants a benefit (`claim`) the current on-chain state no longer justifies. The same pattern exists in Agave's QUIC QoS layer (`SwQos`/`SimpleQos`): a connecting peer's stake is looked up once in `get_connection_stake` / `build_connection_context` and cached into `SwQosConnectionContext { peer_type, total_stake, .. }` for the entire lifetime of the QUIC connection. Stream/connection quotas (`compute_max_allowed_uni_streams_with_rtt`, `max_streams_per_throttling_interval`, staked connection-table slot) are derived from that one-time snapshot, not from the live `staked_nodes` map, which is updated independently (e.g., each epoch boundary as stakes change). A peer whose stake later drops to zero (or is removed from the stake set) keeps its previously-granted `Staked` quota and a slot in the limited `staked_connection_table` for as long as the QUIC connection stays open.

### Finding Description
`get_connection_stake` performs a single point-in-time lookup against `staked_nodes`: [1](#0-0) 

This is called from `build_connection_context`, which is only invoked once, when the connection is first accepted: [2](#0-1) 

The resulting `peer_type`/`total_stake` are stored in `SwQosConnectionContext` and used for the entire life of the connection to compute stream limits and to decide placement into the `staked_connection_table` (which has a much larger `max_staked_connections` quota than the unstaked table): [3](#0-2) [4](#0-3) 

Per-stream/connection throughput limits are computed from that cached `total_stake`/`peer_type`, not from a fresh lookup: [5](#0-4) [6](#0-5) 

There is no code path that re-checks `staked_nodes` for an already-established connection and downgrades it from `Staked` to `Unstaked` (or evicts it from the staked table) when the underlying stake disappears. `StakedNodes::get_node_stake` simply reflects the current epoch's stake map, but nothing ties an existing `SwQosConnectionContext`/`ConnectionTable` entry back to it after connection setup: [7](#0-6) 

This mirrors the Prime.sol flaw exactly: a privilege-granting value (`isIrrevocable`/`stakedAt` in Prime, `peer_type: Staked(stake)`/`total_stake` here) is derived from a real state check at one point in time but is never invalidated or re-derived when the underlying condition (staked XVS / active stake) later becomes false.

### Impact Explanation
An attacker who is a validator/staker at connection time (or briefly becomes one, e.g. via a small/temporary stake or a delegator relationship that is later withdrawn/unstaked) can open a long-lived QUIC connection to a target TPU/QUIC endpoint while staked, then let their stake go to zero. The connection keeps its `Staked` classification and its reserved slot in the bounded `staked_connection_table`, plus its stream throughput allowance computed from the stale `total_stake`. Because the staked connection table has a fixed capacity (`max_staked_connections`) that is meant to be reserved for currently-staked, economically-accountable validators, a formerly-staked peer occupying that slot indefinitely reduces available capacity/quota for legitimately-staked validators, and lets the attacker sustain a disproportionate volume of transaction/stream traffic relative to their real (zero) current stake. This is a non-RPC remote resource-degradation vector against the TPU/QUIC ingestion path, one of the explicitly valid Agave impact categories (non-RPC remote exhaustion/degradation), without requiring any malicious-validator/trusted-party assumption beyond ordinary permissionless staking/unstaking, which any user can do.

### Likelihood Explanation
The precondition (become staked briefly, open a connection, then unstake) is fully achievable by an unprivileged actor using ordinary stake delegate/deactivate instructions, so no privileged or colluding party is required. The main uncertainty I could not fully verify from local code is the QUIC idle-timeout/keepalive configuration and whether some other layer forcibly closes/rechecks long-lived connections independent of the QoS module; if idle timeouts are short, the exploitation window per connection is bounded, but the peer can simply keep the connection alive with traffic (which is the entire point of holding the slot) and/or repeat the process with multiple connections/stake cycles across epochs. I did not locate any periodic re-validation of `SwQosConnectionContext.peer_type`/`total_stake` against `staked_nodes` in `swqos.rs`, `simple_qos.rs`, or `quic.rs`, which is the concrete missing guard.

### Recommendation
Periodically re-validate each open connection's cached `peer_type`/`total_stake` against the current `staked_nodes` snapshot (e.g., on a timer, on epoch boundary, or lazily on each stream open) and downgrade/evict connections whose backing stake has dropped to zero or fallen out of `staked_nodes`, mirroring how the Prime.sol fix re-derives/reset the eligibility state (`stakedAt`) whenever the underlying condition changes, instead of trusting a one-time snapshot for the lifetime of the session.

### Proof of Concept
1. Stand up (or use) a validator identity with a small stake delegated to a vote account so that `staked_nodes.get_node_stake(pubkey)` returns a non-zero value.
2. Open a QUIC connection to the target's TPU/QUIC listener as that identity; `build_connection_context` calls `get_connection_stake`, classifies the connection as `ConnectionPeerType::Staked(stake)`, and `try_add_connection` places it in `staked_connection_table` with a stream quota derived from `total_stake` at that moment (`streamer/src/nonblocking/swqos.rs:301-382`, `streamer/src/nonblocking/quic.rs:416-428,510-519`).
3. Deactivate/withdraw the stake so that in the next epoch `staked_nodes.get_node_stake(pubkey)` returns `None`/0.
4. Keep the already-open QUIC connection alive (send periodic traffic to avoid idle timeout). Because there is no re-lookup of `staked_nodes` tied to the existing `SwQosConnectionContext`, the connection retains its `Staked` slot in `staked_connection_table` and its `total_stake`-derived stream allowance (`compute_max_allowed_uni_streams_with_rtt`, `streamer/src/nonblocking/swqos.rs:147-179,292-298`), even though the peer now has zero real stake — occupying capacity reserved for genuinely staked validators and sustaining traffic beyond what an unstaked peer would be permitted.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

impl StakedNodes {
    fn calculate_total_stake(
        stakes: &HashMap<Pubkey, u64>,
        overrides: &HashMap<Pubkey, u64>,
    ) -> u64 {
        stakes
            .iter()
            .filter(|(pubkey, _)| !overrides.contains_key(pubkey))
            .map(|(_, &stake)| stake)
            .chain(overrides.values().copied())
            .sum()
    }

    pub fn new(stakes: Arc<HashMap<Pubkey, u64>>, overrides: HashMap<Pubkey, u64>) -> Self {
        let total_stake = Self::calculate_total_stake(&stakes, &overrides);
        Self {
            stakes,
            overrides,
            total_stake,
        }
    }

    pub fn get_node_stake(&self, pubkey: &Pubkey) -> Option<u64> {
        self.overrides
            .get(pubkey)
            .or_else(|| self.stakes.get(pubkey))
            .filter(|&&stake| stake > 0)
            .copied()
    }

    #[inline]
    pub fn total_stake(&self) -> u64 {
        self.total_stake
    }
