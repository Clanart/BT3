### Title
Zero-signature `MultisigSpendingCondition` / `OrderIndependentMultisigSpendingCondition` allows spending-condition forgery with no signature - (File: `stacks-common/src/address/mod.rs`, `stacks-codec/src/transaction.rs`)

### Summary
`TransactionSpendingCondition::verify()` for the multisig variants accepts `signatures_required == 0` with an empty `fields` vector as a valid, fully-authenticated spending condition, and `StacksAddress::from_public_keys` does not reject `num_sigs == 0` with an empty public-key list. This lets anyone deterministically construct the fixed "0-of-0 multisig" address and later spend from it without ever presenting a signature, breaking the equality that a spending condition must be backed by the number of signatures it claims.

### Finding Description
`TransactionSpendingCondition::verify` (for both `MultisigSpendingCondition` and `OrderIndependentMultisigSpendingCondition`) loops over `self.fields`, incrementing `num_sigs` for each `Signature` field, then checks: [1](#0-0) 
For `OrderIndependentMultisigSpendingCondition` the analogous check is `num_sigs < self.signatures_required`: [2](#0-1) 

If `self.fields` is empty and `self.signatures_required == 0`, `num_sigs` is `0`, so both checks pass trivially — no cryptographic signature is verified at all. The code then derives an address from the (empty) `pubkeys` vector and `signatures_required` (0), and compares it to `self.signer`: [3](#0-2) 

The address derivation goes through `StacksAddress::from_public_keys`, which only rejects the case `pubkeys.len() < num_sigs`; `0 < 0` is `false`, so it proceeds: [4](#0-3) 

For `AddressHashMode::SerializeP2SH`/`SerializeP2WSH`, the hash is computed by `to_bits_p2sh`, which builds a Bitcoin-style multisig redeem script `OP_0 OP_0 OP_CHECKMULTISIG` (`push_int(num_sigs=0)`, no pubkeys pushed, `push_int(pubkeys.len()=0)`, `OP_CHECKMULTISIG`) and hashes it: [5](#0-4) 

This script and its hash are **fixed, publicly computable constants** — no private key material is involved. Any transaction whose `TransactionAuth` is `Standard(Multisig(MultisigSpendingCondition{ signer: <that fixed Hash160>, hash_mode: P2SH, fields: vec![], signatures_required: 0, .. }))` will pass `verify()` unconditionally, because:
1. `num_sigs (0) == signatures_required (0)` — the loop check passes.
2. `StacksAddress::from_public_keys(0, P2SH, 0, &[])` succeeds and returns exactly the same fixed hash.
3. `addr.bytes() == &self.signer` — trivially true by construction.

No consensus-level check anywhere in the codebase rejects `signatures_required == 0` (confirmed by searching for `signatures_required == 0`, `< 1`, or similar guards — none found), nor does `consensus_deserialize` for `MultisigSpendingCondition`/`OrderIndependentMultisigSpendingCondition` reject it (it only checks `num_sigs_given == signatures_required` / `>= signatures_required`, both trivially satisfied by `0 == 0`): [6](#0-5) [7](#0-6) 

The origin/sponsor address used for balances/nonces is derived purely from this `signer` hash plus the fixed multisig version byte (`address_mainnet`/`address_testnet`), independent of any actual key ownership: [8](#0-7) 

### Impact Explanation
This breaks the fundamental equality that a Stacks account can only be spent from by a party that can produce the threshold of signatures corresponding to its address hash. Because the "0-of-0" address hash is a fixed, deterministic, publicly-known value (for a given `hash_mode`), *any* value ever paid to that specific address (e.g., accidentally, via a faucet, a mistaken transfer, an exchange consolidation address, a sponsor account, etc.) can be drained by anyone, with zero signatures and no knowledge of any private key. This is a concrete forgery/unauthorized-asset-movement primitive: `tx.verify()` returns `Ok` for a transaction that transfers/spends funds from an account nobody controls cryptographically. This satisfies the "Critical: forging or replaying a transaction so an asset moves without authorization" impact category.

### Likelihood Explanation
The precondition (funds present at the fixed 0-of-0 address) is external to the protocol, but the address itself requires no discovery effort — it is a fixed constant per `hash_mode`/version that can be computed offline from the code shown above (analogous to Bitcoin's well-known historical "0-of-0 OP_CHECKMULTISIG" anyone-can-spend script). Once any value lands there (by accident, tooling bug, or social engineering), exploitation is trivial: construct an unsigned `TransactionAuth::Standard(Multisig(...))` with `signatures_required: 0`, `fields: vec![]`, `signer` set to the known hash, and broadcast it — `verify()` accepts it with no cryptographic work.

### Recommendation
Reject `signatures_required == 0` for `MultisigSpendingCondition` and `OrderIndependentMultisigSpendingCondition` at both deserialization (`consensus_deserialize`) and `verify()` time, and reject `num_sigs == 0` in `StacksAddress::from_public_keys` (mirroring how Bitcoin's policy layer disallows 0-of-0/`OP_CHECKMULTISIG` with `n=0`). At minimum, add an explicit check `if self.signatures_required == 0 { return Err(...) }` before the loop in both `verify()` implementations in `stacks-codec/src/transaction.rs`, and a symmetric check in the corresponding `consensus_deserialize` implementations.

### Proof of Concept
1. Compute the fixed Hash160 of the "0-of-0" P2SH script offline using `to_bits_p2sh(0, &Vec::<StacksPublicKey>::new())` (equivalently, `StacksAddress::from_public_keys(version, &AddressHashMode::SerializeP2SH, 0, &vec![])`).
2. Derive the corresponding Stacks address: `StacksAddress::new(C32_ADDRESS_VERSION_MAINNET_MULTISIG, that_hash160)`.
3. Construct a `StacksTransaction` with:
   - `auth = TransactionAuth::Standard(TransactionSpendingCondition::Multisig(MultisigSpendingCondition { signer: that_hash160, hash_mode: MultisigHashMode::P2SH, nonce: <account nonce>, tx_fee: <fee>, fields: vec![], signatures_required: 0 }))`
   - a `TokenTransfer` (or other) payload moving out whatever balance exists at that address.
4. Call `tx.verify(...)` (as done in `process_transaction_precheck` → `tx.verify(verification_mode)` in `stackslib/src/chainstate/stacks/db/transactions.rs`) — it returns `Ok`, with no signature ever produced or checked.
5. If any STX balance exists at that address, this transaction is fully valid per node consensus rules and moves those funds without authorization from any keyholder.

Note: I was not able to execute this end-to-end in a live node/test harness (no runtime access in this environment), so the PoC is a code-path trace supported by the cited logic rather than an executed exploit; the described logical path is directly traceable through the cited functions with no intervening guard.

    pub fn from_public_keys(
        version: u8,
        hash_mode: &AddressHashMode,
        num_sigs: usize,
        pubkeys: &Vec<StacksPublicKey>,
    ) -> Option<StacksAddress> {
        // must be sufficient public keys
        if pubkeys.len() < num_sigs {
            return None;
        }

        // address hash mode must be consistent with the number of keys
        match *hash_mode {
            AddressHashMode::SerializeP2PKH | AddressHashMode::SerializeP2WPKH
                // must be a single public key, and must require one signature
                if (num_sigs != 1 || pubkeys.len() != 1) => {
                    return None;
                }
            _ => {}
        }

        // if segwit, then keys must all be compressed
        match *hash_mode {
            AddressHashMode::SerializeP2WPKH | AddressHashMode::SerializeP2WSH => {
                for pubkey in pubkeys {
                    if !pubkey.compressed() {
                        return None;
                    }
                }
            }
            _ => {}
        }

        let hash_bits = public_keys_to_address_hash(hash_mode, num_sigs, pubkeys);
        StacksAddress::new(version, hash_bits).ok()
    }

/// Internally, the Stacks blockchain encodes address the same as Bitcoin
/// multi-sig address (p2sh)
fn to_bits_p2sh<K: PublicKey>(num_sigs: usize, pubkeys: &Vec<K>) -> Hash160 {
    let mut bldr = Builder::new();
    bldr = bldr.push_int(num_sigs as i64);
    for pubk in pubkeys {
        bldr = bldr.push_slice(&pubk.to_bytes());
    }
    bldr = bldr.push_int(pubkeys.len() as i64);
    bldr = bldr.push_opcode(btc_opcodes::OP_CHECKMULTISIG);

    let script = bldr.into_script();
    Hash160::from_data(script.as_bytes())
}
