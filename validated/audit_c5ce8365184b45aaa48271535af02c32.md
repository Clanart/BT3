### Title
GaslessSwapRouter owner can front-run a signed `swapForGas` tx by raising `commissionRate`, siphoning off the user's swap proceeds - (File: kaiax/gasless/impl/tx_pool.go, contracts/bindings/kip247/GaslessSwapRouter.go)

### Summary
`GaslessSwapRouter` exposes an owner-only `updateCommissionRate(uint256)` function that changes the commission percentage taken out of a gasless user's swap output at the moment `swapForGas` executes. The gasless-tx pool admission rules that the kaiax `gasless` module enforces on the pending `GaslessSwapTx` (`amountIn`, `minAmountOut`, `amountRepay`, `deadline`) never read or pin the router's current `commissionRate`. This is structurally identical to the Teller `MarketRegistry.setMarketFeePercent` issue: a fee parameter that is fetched fresh at settlement time, is fully controllable by a privileged-but-reachable actor, and is never bound into the counterparty's signed intent.

### Finding Description
A gasless user signs a `SwapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` transaction off-chain. Before it is included, the kaiax `gasless` tx-pool admission logic only checks:
- `minAmountOut >= amountRepay`
- `amountIn >= router.GetAmountIn(minAmountOut)`
- token allowance/balance and deadline [1](#0-0) 

None of these checks reference `commissionRate`. The lend/repay accounting used by the module (`lendAmount`/`repayAmount`) is based purely on transaction gas fees, not on the router's on-chain commission state: [2](#0-1) 

Meanwhile, `GaslessSwapRouter` is `Ownable` and lets its owner call `updateCommissionRate` at any time, changing `commissionRate` which is read live inside `swapForGas` when computing the commission taken from swap proceeds (as evidenced by the `SwappedForGas(proposer, amountRepaid, user, finalUserAmount, commission)` event and the `CommissionRateUpdated(oldRate, newRate)` event): [3](#0-2) [4](#0-3) 

Because the user's signed `SwapForGas` tx fixes `minAmountOut`/`amountRepay` but not the commission rate, the owner can observe a pending gasless swap in the mempool (or in a bundle awaiting proposer inclusion), call `updateCommissionRate` to a much higher value, and have it apply before the swap executes — exactly mirroring how the Teller market owner raised `marketFeePercent` between `submitBid` and `lenderAcceptBid`.

### Impact Explanation
The user's `amountRepay` is still deducted in full to reimburse the block proposer's `LendTxGenerator`, so raising the commission comes directly out of `finalUserAmount` — the residual KAIA the user is supposed to receive after their gas-fee-lending swap. In the worst case (commission ≥ remaining margin over `amountRepay`), `finalUserAmount` can be reduced to zero or cause the swap to revert while the user has still consumed their token allowance/approval flow and paid the on-chain gas-lending arrangement, i.e., unauthorized value extraction/fee abuse against gasless swap users, reachable purely by a privileged contract owner acting opportunistically against a queued, already-signed transaction from an unprivileged sender.

### Likelihood Explanation
This requires the `GaslessSwapRouter` owner to actively monitor pending `GaslessSwapTx`s and race a `updateCommissionRate` call before the target swap is included — feasible any time a swap is queued, and trivially exploitable if the owner colludes with or is the block proposer/auctioneer bundling gasless transactions. The kaiax `gasless` module's own README explicitly states the balance check for gasless transactions is relaxed (`GetCheckBalance()`), and no fee-pinning safeguard exists in the admission path, increasing the practical window for this manipulation. [5](#0-4) 

### Recommendation
- Require `SwapForGas` calls to pass an `expectedCommissionRate` (or `minFinalUserAmount`) parameter that is validated against the router's current `commissionRate` at execution time, reverting on mismatch, analogous to the Teller fix suggestion of binding expected fees into the signed transaction.
- Alternatively, snapshot/lock the commission rate applicable to a given `swapForGas` call using a delay (e.g., rate changes take effect only after N blocks) so pending signed swaps cannot be retroactively affected.
- Emit and enforce a maximum allowed commission rate ceiling that cannot be exceeded even by the owner, bounding worst-case loss.

### Proof of Concept
1. User A signs and broadcasts `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` where `minAmountOut` only slightly exceeds `amountRepay` (small margin, as in the test helper computing `margin = swapExpectedOutput/100`, see [6](#0-5) ).
2. Router owner observes the pending tx (in mempool / bundling stage) and calls `updateCommissionRate(newHigherRate)` before the swap tx is included, using `GaslessSwapRouterTransactor.UpdateCommissionRate` ( [3](#0-2) ).
3. The gasless module's admission checks (`checkBalanceForSwap`) already passed and do not re-validate commission ( [7](#0-6) ), so the tx is still promoted/executed.
4. `swapForGas` executes with the new, higher `commissionRate`, reducing `finalUserAmount` (possibly to zero or causing revert) while `amountRepay` is still deducted in full — confirmed by the `SwappedForGas` event fields `finalUserAmount`/`commission` ( [4](#0-3) ).

Note: The actual Solidity source for `GaslessSwapRouter.sol` (commission computation formula) was not present in the indexed codebase — only the generated Go bindings and bytecode were available — so the precise arithmetic of how `commissionRate` interacts with `minAmountOut`/`amountRepay` inside `swapForGas` could not be directly inspected. A Devin session with full repository access would be needed to confirm the exact commission formula and underflow/revert behavior.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.

See ready condition [KIP-247](https://kips.kaia.io/KIPs/kip-247) and the implementation `IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool`.

#### Balance check

Sender balance check is omitted for gasless transactions (see `GetCheckBalance()`).
