### Title
CPU-exhaustion DoS via quadratic-time coin-membership scans in `Offer._get_offered_coins()` when parsing an attacker-supplied offer - (File: `chia/wallet/trading/offer.py`)

### Summary
`chia.wallet.trading.offer.Offer` recomputes an O(n) list scan (`self._bundle.removals()`, plus repeated `in` tests against Python lists) once **per coin spend** while deriving the offered coins for a parsed offer. As with the Mistune `parse_link_text` advisory (GHSA-qcq2-496w-v96p / CVE-2026-49851), where an O(n) inner scan is repeated inside an O(n) outer loop, an attacker who controls the number of coin spends in a bech32-encoded offer can drive this code to O(n²), causing severe CPU consumption on the machine that parses the offer (wallet RPC caller, offer counterparty, or a wallet UI that opens an offer file).

### Finding Description
`Offer.from_bech32()` → `Offer.try_offer_decompression()` → `Offer.from_bytes()` → `Offer.from_spend_bundle()` deserializes an attacker-supplied `WalletSpendBundle` without requiring a valid aggregated signature or that any of the constituent coins actually exist on-chain [1](#0-0) [2](#0-1) . The public entry point `TakeOffer.parsed_offer` exposes exactly this path to any wallet RPC caller / offer counterparty: `Offer.from_bech32(self.offer)` [3](#0-2) .

`Offer.__post_init__` runs `compute_spend_hints_and_additions` bounded by `MAX_BLOCK_COST_CLVM`, which limits *CLVM execution* cost but not the *number* of coin spends an attacker can pack into the bundle, since trivial puzzle reveals (e.g. quoted `()` puzzles producing no conditions) cost almost nothing [4](#0-3) .

The actual quadratic hotspot is `Offer._get_offered_coins()`:
```
for parent_spend in self._bundle.coin_spends:
    ...
    coins_for_this_spend = [c for c in coins_for_this_spend if c not in self._bundle.removals()]
``` [5](#0-4) 

`self._bundle.removals()` itself iterates over **every** coin spend in the bundle to build a fresh list, and this call is re-executed **inside** the outer loop that also iterates over every coin spend — an O(n) rescan nested inside an O(n) loop, exactly the same structural bug class as `parse_link_text`'s repeated O(n) `]`-search inside `InlineParser.parse()`'s O(n) outer loop. With `n` coin spends, total work is O(n²).

This function is not just a debug/UI helper — it backs `get_offered_amounts()` [6](#0-5) , which backs `arbitrage()` [7](#0-6)  and `summary()` [8](#0-7) , both of which are invoked whenever a wallet inspects or takes an offer (e.g. `GetOfferSummary` and the `respond_to_offer`/`_create_offer_for_ids`/`check_for_special_offer_making` flow in `TradeManager`, which calls `offer.arbitrage()` directly) [9](#0-8) .

Related O(n) rescans compounding the same problem exist in `get_root_removal()` (a `next()` linear scan over `all_removals` executed once per coin, called from `get_pending_amounts()`/`get_primary_coins()`) [10](#0-9) , and in the nested `while`/`for` loops of `get_cancellation_coins()` that recompute set intersections over all remaining dependencies on every iteration [11](#0-10) .

### Impact Explanation
An offer counterparty or any local wallet RPC caller who is asked to inspect/take a maliciously crafted offer (bech32 string) can trigger this quadratic-time code path merely by parsing/summarizing the offer, before any signature validation or chain-state check occurs. A moderately sized offer (thousands of trivial coin spends, still well inside the generous `MAX_BLOCK_COST_CLVM` execution-cost budget) can make `get_offered_amounts()`/`summary()`/`arbitrage()` take seconds to minutes, blocking the wallet's event loop / RPC worker and constituting a spend-triggered transaction-processing halt for that wallet.

### Likelihood Explanation
High likelihood of triggerability, but capped severity because it only affects the victim wallet's own responsiveness (a local resource-exhaustion / halt, not consensus-breaking or fund-theft); it requires the victim to actively request a summary/take of an attacker-supplied offer, a normal step in the offer workflow (`TakeOffer`, `GetOfferSummary`, `respond_to_offer`). No signature or real coin ownership is required from the attacker to build the offending bundle.

### Recommendation
- In `Offer._get_offered_coins()`, precompute `self._bundle.removals()` once (or use a `set`/dict keyed by coin) outside the per-spend loop instead of recomputing and linear-scanning it for every parent spend.
- Convert other repeated list-membership checks (`get_root_removal`, `get_involved_coins`, `get_pending_amounts`, `get_cancellation_coins`) to use `set`/`dict` lookups instead of `list`/`in`, and avoid rebuilding derived collections inside loops.
- Consider bounding the number of coin spends an `Offer`/`WalletSpendBundle` may contain before these O(n) helper methods are invoked, independent of CLVM cost.

### Proof of Concept
Conceptually mirroring the Mistune PoC:
1. Construct a `WalletSpendBundle` with `n` (e.g. 5,000–50,000) `CoinSpend`s, each using a trivial puzzle reveal (`(q ())`, quoted-nil) and a solution, so CLVM execution cost per spend is negligible and the whole bundle fits comfortably under `MAX_BLOCK_COST_CLVM`.
2. Wrap as an `Offer` via `Offer.from_spend_bundle(bundle)` / serialize with `bytes(offer)` / `to_bech32()`.
3. Send this bech32 string to a wallet via the `TakeOffer` RPC (`parsed_offer` property) or `GetOfferSummary`, or have the counterparty "take" the offer, and measure wall-clock time of `offer.summary()` / `offer.arbitrage()` versus `n` — timing should grow superlinearly (approaching O(n²)) as `n` increases, analogous to the benchmark curve in the Mistune advisory.

    def arbitrage(self) -> dict[bytes32 | None, int]:
        """
        Returns a dictionary of the type of each asset and amount that is involved in the trade
        With the amount being how much their offered amount within the offer
        exceeds/falls short of their requested amount.
        """
        offered_amounts: dict[bytes32 | None, int] = self.get_offered_amounts()
        requested_amounts: dict[bytes32 | None, int] = self.get_requested_amounts()

        arbitrage_dict: dict[bytes32 | None, int] = {}
        for asset_id in [*requested_amounts.keys(), *offered_amounts.keys()]:
            arbitrage_dict[asset_id] = offered_amounts.get(asset_id, 0) - requested_amounts.get(asset_id, 0)

    def get_root_removal(self, coin: Coin) -> Coin:
        all_removals: set[Coin] = set(self.removals())
        all_removal_ids: set[bytes32] = {c.name() for c in all_removals}
        non_ephemeral_removals: set[Coin] = {
            c for c in all_removals if c.parent_coin_info not in {r.name() for r in all_removals}
        }
        if coin.name() not in all_removal_ids and coin.parent_coin_info not in all_removal_ids:
            raise ValueError("The specified coin is not a coin in this bundle")

        while coin not in non_ephemeral_removals:
            coin = next(c for c in all_removals if c.name() == coin.parent_coin_info)

        return coin

    # This will only return coins that are ancestors of settlement payments
    def get_primary_coins(self) -> list[Coin]:
        primary_coins: set[Coin] = set()
        for _, coins in self.get_offered_coins().items():
            for coin in coins:
                primary_coins.add(self.get_root_removal(coin))
        return list(primary_coins)

    # This returns the minimum coins that when spent will invalidate the rest of the bundle
    def get_cancellation_coins(self) -> list[Coin]:
        # First, we're going to gather:
        dependencies: dict[bytes32, list[bytes32]] = {}  # all of the hashes that each coin depends on
        announcements: dict[bytes32, list[bytes32]] = {}  # all of the hashes of the announcement that each coin makes
        coin_names: list[bytes32] = []  # The names of all the coins
        additions = self.additions()
        for spend in [cs for cs in self._bundle.coin_spends if cs.coin not in additions]:
            name = bytes32(spend.coin.name())
            coin_names.append(name)
            dependencies[name] = []
            announcements[name] = []
            conditions: Program = run_with_cost(spend.puzzle_reveal, INFINITE_COST, spend.solution)[1]
            for condition in conditions.as_iter():
                if condition.first() == 60:  # create coin announcement
                    announcements[name].append(
                        AssertCoinAnnouncement(asserted_id=name, asserted_msg=condition.at("rf").as_python()).msg_calc
                    )
                elif condition.first() == 61:  # assert coin announcement
                    dependencies[name].append(bytes32(condition.at("rf").as_python()))

        # We now enter a loop that is attempting to express the following logic:
        # "If I am depending on another coin in the same bundle, you may as well cancel that coin instead of me"
        # By the end of the loop, we should have filtered down the list of coin_names to include only those that will
        # cancel everything else
        while True:
            removed = detect_dependent_coin(coin_names, dependencies, announcements)
            if removed is None:
                break
            removed_coin, provider = removed
            removed_announcements: list[bytes32] = announcements[removed_coin]
            remove_these_keys: list[bytes32] = [removed_coin]
            while True:
                for coin, deps in dependencies.items():
                    if set(deps) & set(removed_announcements) and coin != provider:
                        remove_these_keys.append(coin)
                removed_announcements = []
                for coin in remove_these_keys:
                    dependencies.pop(coin)
                    removed_announcements.extend(announcements.pop(coin))
                coin_names = [n for n in coin_names if n not in remove_these_keys]
                if removed_announcements == []:
                    break
                else:
                    remove_these_keys = []

        return [cs.coin for cs in self._bundle.coin_spends if cs.coin.name() in coin_names]

    @classmethod
    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}
        driver_dict: dict[bytes32, PuzzleInfo] = {}
        leftover_coin_spends: list[CoinSpend] = []
        for coin_spend in bundle.coin_spends:
            driver = match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))
            if driver is not None:
                asset_id = create_asset_id(driver)
                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []
                for payment_group in Program.from_serialized(coin_spend.solution).as_iter():
                    nonce = bytes32(payment_group.first().as_atom())
                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)

        return cls(
            requested_payments, WalletSpendBundle(leftover_coin_spends, bundle.aggregated_signature), driver_dict
        )
