### Title
Untrusted `ReceivedOutput` bytes can fabricate unspendable Bitcoin deposits - ([File: `networks/bitcoin/src/wallet/mod.rs`](../../networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` deserializes the spend offset, `TxOut`, and `OutPoint` as three independent fields but performs no check that the outpoint exists or that the claimed `TxOut` is actually the referenced blockchain output. An attacker who can submit serialized `ReceivedOutput` bytes can therefore claim a nonexistent deposit whose script corresponds to a known Serai key. [1](#0-0) 

### Finding Description
The parser reads a canonical scalar offset, then consensus-decodes a `TxOut` and an `OutPoint`, and immediately returns `Ok(ReceivedOutput { offset, output, outpoint })`. [1](#0-0)  Unlike `Scanner::scan_transaction`, which derives the outpoint from the containing transaction and selects the output from the scanner’s registered `script_pubkey` map, deserialization has no scanner, transaction, block, or UTXO context available to validate those relationships. [2](#0-1) 

The only later ownership check is `SignableTransaction::multisig`, which derives `keys.offset(input.offset).group_key()` and compares its P2TR script with the serialized `TxOut.script_pubkey`. [3](#0-2)  That check proves only that the embedded `TxOut` would be controlled by Serai if it existed; it does not prove that `input.outpoint` references that `TxOut` or any confirmed UTXO. [4](#0-3) 

### Impact Explanation
A forged object can report an arbitrary balance through `ReceivedOutput::value()` and can pass `SignableTransaction::multisig` when its `TxOut` uses the correct deposit script and its `OutPoint` is fabricated. [5](#0-4) [6](#0-5)  The wallet may therefore treat funds as received and construct/sign a spend even though the input is nonexistent or does not contain the claimed amount, yielding funds reported received that are not spendable. [4](#0-3) 

### Likelihood Explanation
This requires an attacker to supply serialized `ReceivedOutput` data to a component that treats it as a trusted wallet output. [1](#0-0)  The attacker does not need a private key or validator privilege: they only need the target group/deposit key to construct the corresponding P2TR script, after which an arbitrary outpoint and amount can be encoded. [7](#0-6)  Likelihood is bounded by whether such bytes cross a trust boundary rather than being confined to internally generated scanner state. [2](#0-1) 

### Recommendation
Treat `ReceivedOutput` serialization as an opaque trusted-state encoding, not an authenticated proof of receipt. [8](#0-7)  Prefer reconstructing outputs exclusively through `Scanner::scan_transaction`/`scan_block`, or validate deserialized entries against the authenticated blockchain/RPC UTXO data before exposing them to balance accounting or transaction construction. [9](#0-8)  If untrusted persistence must be supported, bind the object to the containing transaction and verified `vout`, and verify that the chain output’s `TxOut` equals the embedded one. [2](#0-1) 

### Proof of Concept
Given a target’s public base key `group_key`, an attacker can form these serialized fields:

```rust
use bitcoin::{
  consensus::encode::serialize,
  hashes::Hash,
  Amount, OutPoint, TxOut, Txid,
};
use k256::Scalar;

// Known public deposit script for offset 0.
let script_pubkey = p2tr_script_buf(group_key).unwrap();

let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());
bytes.extend(serialize(&TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey,
}));
bytes.extend(serialize(&OutPoint {
  txid: Txid::from_byte_array([0x41; 32]), // attacker-chosen/nonexistent
  vout: 0,
}));

// This succeeds even though no such UTXO exists.
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 100_000);
```

The forged input is then accepted by transaction construction and the multisig ownership check because `SignableTransaction::new` trusts `input.outpoint`/`input.output`, while `multisig` compares only the embedded script to the key derived from `input.offset`. [4](#0-3) [6](#0-5)

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
