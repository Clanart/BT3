### Title
Missing integrity/ownership check in `ReceivedOutput::read` lets untrusted bytes claim unspendable outputs as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes CWE-639/CWE-862: an object is returned to a caller based on an attacker-supplied identifier without verifying the caller is authorized for (i.e., actually owns) that object. The Serai analog is `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs`: it deserializes a `ReceivedOutput` — the type a downstream consumer treats as "funds received and spendable under `key + offset*G`" — purely from untrusted bytes, and never verifies that the claimed `offset` actually derives the output's `script_pubkey` from the scanner's key. Any triple of `(offset, TxOut, outpoint)` is accepted.

### Finding Description
`Scanner::scan_transaction` is the only *authenticated* producer of `ReceivedOutput`: it builds the struct only when `self.scripts.get(&output.script_pubkey)` succeeds, meaning the offset genuinely maps the wallet key to that script (wallet/mod.rs:199-214). `ReceivedOutput::read`, however, reconstructs the same trusted type from raw bytes with no such consistency check (wallet/mod.rs:122-134). `read_F` only enforces scalar canonicity; `TxOut::consensus_decode` and `OutPoint::consensus_decode` only enforce encodings. There is no binding between `offset` and `output.script_pubkey`, and no binding between `outpoint` and `output` at all — a deserialized `ReceivedOutput` can reference any transaction output on the chain, or none, with an arbitrary offset. This mirrors the advisory exactly: a "getter" returns a protected resource keyed on caller-controlled data without verifying entitlement.

### Impact Explanation
A `ReceivedOutput` is the wallet's claim of spendable funds; consumers use `offset()` to build the spending key (`key + offset*G`, then the TapTweak) and `outpoint()`/`output()` as the input being spent. An attacker who can supply serialized `ReceivedOutput` bytes (e.g., via an untrusted data feed or corrupted storage the node re-reads) can cause funds to be reported as received that are not spendable: the output's script is not derivable from the wallet key under the claimed offset, so the wallet will attempt (and fail, or worse, silently mis-account) spends of outputs it does not control. It can also cause the same real output to be claimed under a wrong offset, permanently poisoning wallet accounting for that UTXO.

### Likelihood Explanation
The path is reachable only where serialized `ReceivedOutput`s transit untrusted boundaries (peer coordination, persisted state restored after compromise, or integrator plumbing that mixes scan results with deserialized claims). For a pure single-node scan → spend pipeline the type never round-trips through hostile bytes, so the exploitability is conditional on deployment — comparable to the advisory's requirement of an authenticated-but-unprivileged caller.

### Recommendation
Bind the deserialized output to the wallet: `ReceivedOutput::read` should take the `Scanner` (or the key and expected `script_pubkey`) and verify `output.script_pubkey == p2tr_script_buf(key + GENERATOR*offset).unwrap()` before returning the object, mirroring the check `scan_transaction` performs at construction time (wallet/mod.rs:205). Alternatively, make `read` crate-private / mark deserialization as producing an unverified claim requiring re-validation against `Scanner::scripts`.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
