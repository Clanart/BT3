### Title
DataLayer mirror-URL SSRF: `http_download` fetches attacker-controlled URLs (with automatic redirects) without any address validation - ([File: chia/data_layer/download_data.py])

### Summary
The `RecursiveUrlLoader` bug class is: a fetch client trusts a URL string supplied by an untrusted source and allows automatic redirect-following without revalidating the final destination, enabling SSRF into internal/metadata endpoints. Chia's DataLayer sync path has the same reachable shape: any DataLayer store owner can register mirror URLs on-chain (a `Mirror` coin, added via `dl_new_mirror`/`add_mirror`), and any local DataLayer client that subscribes to that store id will automatically fetch those URLs to sync deltas — with no host/IP allow-list check and default `aiohttp` redirect following.

### Finding Description
`DataLayer.fetch_and_validate()` pulls candidate server URLs for a subscribed store via `self.data_store.get_available_servers_for_store()` [1](#0-0) , then calls `insert_from_delta_file()` → `download_file()` → `http_download()` [2](#0-1) .

`http_download()` performs a plain `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` with no scheme/host/IP validation of `server_info.url` and no restriction on redirects (aiohttp's default `allow_redirects=True`), so the final destination is never checked against private/loopback/metadata ranges: [3](#0-2) 

The URLs driving this fetch (`ServerInfo.url`) originate from mirror coins published on-chain by the DataLayer singleton owner — an untrusted, attacker-influenced input from the perspective of any node that subscribes to that store — as documented in the module notes: "Do not treat mirror URLs, plugins, or static file names as trusted data sources." [4](#0-3)  and "Plugin and mirror URLs are external trust inputs." [5](#0-4) 

Unlike the LangChain case (which had an initial-URL check that redirects could bypass), this code path has **no validation at all**, not even of the initial URL — so it is a strictly broader instance of the same bug class (fetch of attacker-supplied URL to arbitrary hosts, redirects followed automatically, no revalidation).

### Impact Explanation
A malicious DataLayer store owner (an unprivileged wallet user who creates a DataLayer store and adds a mirror URL) can cause any peer that subscribes to that store — a normal, unprivileged Data Layer client action — to issue outbound HTTP requests to attacker-chosen destinations, including:
- Cloud instance metadata endpoints (`169.254.169.254`), potentially leaking credentials to logs/errors surfaced through DataLayer.
- Internal/private network services (`127.0.0.1`, `10.x`, `192.168.x`), used as a network-reachability probe or pivot.
- A redirector chain (`https://...redirect.../?url=http://169.254.169.254/...`) since aiohttp follows redirects by default, meaning even if a future fix added an initial-URL allow-list check, it could be bypassed the same way as the LangChain advisory describes.

This matches the required "unauthorized/forged" classes only loosely (it's primarily an SSRF/information-disclosure and internal-network-access issue triggered by a normal Data Layer client action), which caps the severity around Medium.

### Likelihood Explanation
Likelihood is high for any operator running a DataLayer node with subscriptions enabled: subscribing to a store id supplied by any third party is a normal, low-privilege workflow (`chia data subscribe`), and the mirror URL is fully attacker-controlled once the attacker creates a store and mirror coin — no special permissions or race conditions are required.

### Recommendation
- Add strict validation of `server_info.url` (and any plugin/downloader `PluginRemote.url`) before use in `http_download()` / `download_file()`: enforce scheme allow-list, resolve and reject private/loopback/link-local/multicast/metadata IP ranges (`169.254.169.254`, RFC1918, `127.0.0.0/8`, etc.), consistent with the "external trust input" note in the module docs.
- Disable automatic redirects in the `aiohttp.ClientSession().get()` call in `http_download()` (`chia/data_layer/download_data.py`) and instead manually follow `3xx` responses, re-validating each `Location` header against the same allow-list before continuing, mirroring the LangChain fix (`redirect: "manual"` + per-hop `validateSafeUrl`).
- Apply the same treatment to `get_downloader()` in `chia/data_layer/data_layer.py` (POST to plugin URL) if plugin URLs are ever derived from untrusted config/state rather than local operator configuration.
- Cap redirect count to prevent loops once manual redirect handling is added.

### Proof of Concept
1. Attacker creates a DataLayer store and, via normal wallet RPC (`dl_new_mirror`/`add_mirror`), publishes a mirror URL such as `https://redirector.example/?to=http://169.254.169.254/latest/meta-data/iam/security-credentials/` (or a directly internal URL if no redirector is needed, since there is no validation at all).
2. A victim operator runs `chia data subscribe --id <attacker_store_id>` — an ordinary, unprivileged Data Layer client action.
3. `DataLayer.periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()` iterates `servers_info` including the attacker URL [6](#0-5)  and calls `insert_from_delta_file()` → `download_file()` → `http_download()`.
4. `http_download()` issues `session.get(server_info.url + "/" + filename, ...)` [7](#0-6) , which follows any redirect automatically and reaches the internal/metadata target with no host check, exfiltrating (or at minimum probing) internal network state on the victim's machine.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
