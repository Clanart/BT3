## Title
Modified-row line checkbox mismap causes only one side of a diff to be selected, silently corrupting the committed patch - (File: `app/src/ui/diff/side-by-side-diff.tsx`)

### Summary
In `SideBySideDiff.onLineNumberCheckedChanged` the code is supposed to update the selection state for a diff line, using the same idea from the `BloomPool` analogy where two coupled quantities must both be updated when one side of a partial match changes. Instead of computing the "before" line number and "after" line number for a row, both variables are computed identically from the single `column` argument that was actually clicked, so one side of a `Modified` row's before/after pair is never touched.

### Finding Description
`onLineNumberCheckedChanged` receives the `row` and the specific `column` (`Before` or `After`) the user actually clicked, from `onLineNumberCheckboxChange` in `side-by-side-diff-row.tsx`, which resolves `column` via `getDiffColumn(checkbox)`: [1](#0-0) 

That single `column` is then passed into `onLineNumberCheckedChanged`, which is meant to translate row+column into the actual diff line number(s) to flip: [2](#0-1) 

Both `lineBefore` and `lineAfter` are computed with the exact same arguments — `this.getDiffLineNumber(row, column)` — so they always resolve to the same value. `getDiffLineNumber`/`getDiffRowLineNumber` only distinguish `Before` vs `After` for `Modified` rows: [3](#0-2) 

For an `Added` or `Deleted` row this redundancy is harmless (there is only one line). But for a `Modified` row — which independently renders and tracks two checkboxes, one for the deleted "before" line and one for the added "after" line via `beforeData.isSelected` / `afterData.isSelected` — clicking either checkbox drives both `lineBefore` and `lineAfter` to the *same* line number (whichever column was actually clicked), so `withLineSelection` is invoked twice on the identical line and the paired counterpart line's selection state (`DiffSelection.divergingLines`, `app/src/models/diff/diff-selection.ts:78-118`) is never modified at all: [4](#0-3) 

This is the direct structural analog of the reported bug: two coupled state values (`lCollateral`/`bCollateral` in the report, `before line`/`after line` selection here) must be kept in sync on a partial update, and the code only updates one of them, leaving the UI-visible per-line "isSelected" state at odds with what the underlying `DiffSelection` object (which is later serialized into the actual git patch used for staging/committing) actually contains for the other line.

### Impact Explanation
The `DiffSelection` produced here is what downstream code (`patch-formatter.ts`, `git apply`) uses to build the partial patch that is staged and committed. If the "before" and "after" halves of a `Modified` row diverge from what the checkboxes visually show, the user can uncheck what looks like a full line replacement in the UI (both before/after boxes appear to toggle since the checkbox state is driven by the same `row.beforeData.isSelected`/`afterData.isSelected` re-render) but the actual `DiffSelection.divergingLines` set only reflects the change for the clicked column. The end result is a patch/commit that silently differs from the reviewer's visual intent — e.g. staging the "added" replacement line while failing to also unstage/restage the corresponding "deleted" line (or vice versa), producing a corrupted diff of what actually gets committed/pushed relative to what the user believed they selected in the review UI. This matches the accepted "silent corruption of what the user commits or pushes" impact category, since an attacker who controls the content of a fetched/cloned repository can shape a diff with many adjacent modified lines to make this divergence likely to be exploited unnoticed by a reviewer relying on the side-by-side partial-selection UI.

### Likelihood Explanation
This path triggers on ordinary use of the partial-line-selection checkboxes in the side-by-side diff view for `Modified` rows (a very common UI feature used any time a user wants to stage/commit only some lines of a change). No special repo content is required beyond having modified (paired before/after) lines in a diff, which is trivially present in normal repositories or ones crafted by an attacker to contain many such modified regions to increase the chance of confusing partial-selection.

### Recommendation
Fix `onLineNumberCheckedChanged` to compute the before/after line numbers independently using the appropriate `DiffColumn` for each side of a `Modified` row (mirroring `getDiffRowLineNumber`'s `Before`/`After` branching), e.g.:
```ts
const lineBefore = this.getDiffLineNumber(row, DiffColumn.Before)
const lineAfter = this.getDiffLineNumber(row, DiffColumn.After)
```
and only apply `withLineSelection` to the line(s) that actually correspond to the clicked column, or explicitly decide (and document/test) whether checking one side of a modified pair should also flip the other side.

### Proof of Concept
1. Open a repository with a file containing a hunk where a line is modified (one deleted "before" line paired with one added "after" line), rendered as a `DiffRowType.Modified` row in the side-by-side diff.
2. In the Changes view, uncheck only the "after" (added-line) checkbox for that row.
3. Because `onLineNumberCheckedChanged` computes `lineBefore` and `lineAfter` both from `getDiffLineNumber(row, column)` with `column = DiffColumn.After`, only the after-line's selection is toggled off; the before-line's `divergingLines` entry (from the previous state) is left untouched.
4. Commit the partial selection. Inspect the generated patch (via `patch-formatter.ts`) — the staged/committed change no longer matches the pairing shown in the UI (e.g., the deleted line is still staged for removal while the corresponding replacement line was excluded, or vice versa), silently corrupting the intended commit content.   private onLineNumberCheckedChanged = (
    row: number,
    column: DiffColumn,
    isSelected: boolean
  ) => {
    if (this.props.onIncludeChanged === undefined) {
      return
    }

    let selection = this.getSelection()
    if (selection === undefined) {
      return
    }

    const lineBefore = this.getDiffLineNumber(row, column)
    const lineAfter = this.getDiffLineNumber(row, column)

    if (lineBefore !== null) {
      selection = selection.withLineSelection(lineBefore, isSelected)
    }

    if (lineAfter !== null) {
      selection = selection.withLineSelection(lineAfter, isSelected)
    }

    this.props.onIncludeChanged(selection)
  }

  private getDiffLineNumber(
    rowNumber: number,
    column: DiffColumn
  ): number | null {
    const { diff } = this.state
    const rows = getDiffRows(
      diff,
      this.props.showSideBySideDiff,
      this.canExpandDiff()
    )
    const row = rows[rowNumber]

    if (row === undefined) {
      return null
    }

    return this.getDiffRowLineNumber(row, column)
  }

  private getDiffRowLineNumber(row: SimplifiedDiffRow, column: DiffColumn) {
    if (row.type === DiffRowType.Added || row.type === DiffRowType.Deleted) {
      return row.data.diffLineNumber
    }

    if (row.type === DiffRowType.Modified) {
      return column === DiffColumn.After
        ? row.afterData.diffLineNumber
        : row.beforeData.diffLineNumber
    }

    return null
  }

  public withRangeSelection(
    from: number,
    length: number,
    selected: boolean
  ): DiffSelection {
    const computedSelectionType = this.getSelectionType()
    const to = from + length

    // Nothing for us to do here. This state is when all lines are already
    // selected and we're being asked to select more or when no lines are
    // selected and we're being asked to unselect something.
    if (typeMatchesSelection(computedSelectionType, selected)) {
      return this
    }

    if (computedSelectionType === DiffSelectionType.Partial) {
      const newDivergingLines = new Set<number>(this.divergingLines!)

      if (typeMatchesSelection(this.defaultSelectionType, selected)) {
        for (let i = from; i < to; i++) {
          newDivergingLines.delete(i)
        }
      } else {
        for (let i = from; i < to; i++) {
          // Ensure it's selectable
          if (this.isSelectable(i)) {
            newDivergingLines.add(i)
          }
        }
      }

      return new DiffSelection(
        this.defaultSelectionType,
        newDivergingLines.size === 0 ? null : newDivergingLines,
        this.selectableLines
      )
    } else {
      const newDivergingLines = new Set<number>()
      for (let i = from; i < to; i++) {
        if (this.isSelectable(i)) {
          newDivergingLines.add(i)
        }
      }

      return new DiffSelection(
        computedSelectionType,
        newDivergingLines,
        this.selectableLines
      )
    }
