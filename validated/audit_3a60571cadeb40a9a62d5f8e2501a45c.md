### Title
`compute_v2_review_set`'s `head_at_capture` ancestry check lets non-linear HEAD movement (branch switch/orphan checkout) hide committed dangerous code from Stop-hook review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only folds committed changes into the reviewable `dirty_now` set when the current `HEAD` is a *linear descendant* of `head_at_capture` (`_is_ancestor` check). If, within the same turn, `HEAD` moves sideways — e.g. via `git checkout <other-branch>` or `git checkout --orphan` followed by a commit — the working tree is clean (nothing in `tracked_dirty`) and the ancestry check fails, so the newly committed dangerous file is silently dropped from `dirty_now`, and therefore from `review_set = dirty_now & changed_since`, even though the content genuinely differs from the pre-turn baseline. `load_baseline_sha`/`head_at_capture` bookkeeping is exactly what is supposed to bind the review to "the right repo, baseline, and touched paths," and this path breaks that binding.

### Finding Description
`handle_user_prompt_submit` captures `head_at_capture` as the `HEAD` SHA at the start of a turn [1](#0-0) . At Stop, `compute_v2_review_set` tries to include commits made this turn only when `HEAD` advanced in a straight line from `head_at_capture`:

```
diff_base = "HEAD"
current_head = _git_rev_parse_head(repo)
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
``` [2](#0-1) 

`_is_ancestor` uses `git merge-base --is-ancestor` — reachability only, so it is `False` whenever `HEAD` moved to a branch/commit that doesn't have `head_at_capture` in its history (branch switch to unrelated lineage, `--orphan` checkout, rebase onto an unrelated base, etc.) [3](#0-2) . `tracked_dirty`/`untracked` come from `git status --porcelain`, which is empty once the dangerous change has been committed and the tree is clean [4](#0-3) . So in this scenario `dirty_now` never gains the file, while `changed_since` (computed from `_git_name_only(repo, baseline_sha)`, a pure content diff against the stashed baseline) still correctly reports the file as changed [5](#0-4) . Because `review_set = dirty_now & changed_since`, intersecting an empty `dirty_now` entry with a non-empty `changed_since` entry drops the file entirely [6](#0-5) .

Concretely: within a turn, Claude (driven by ordinary/injected git-workflow instructions) can (1) edit a file to introduce dangerous code, (2) commit it, (3) switch to an unrelated branch or `git checkout --orphan` a new branch and re-commit/carry the dangerous content there. Steps 1–2 alone would be linearly caught via the `head_at_capture..HEAD` diff; step 3 breaks the invariant used to bind "touched paths" to the review, and `handle_stop_hook` then sees `review_paths` empty for that file and calls `_skip(9)` well before any LLM diff review happens [7](#0-6) . No approval prompt, allowlist, or workspace guard intervenes here — the whole detection mechanism is this git-derived set, and it silently degrades to "no changes to review" for the dangerous file.

### Impact Explanation
This breaks the core guarantee of the security-guidance Stop hook: that all code changed by Claude during a turn is diffed and passed to the LLM vulnerability scanner before Claude is allowed to finish. A dangerous change (e.g. injected `os.system`/`eval`/hardcoded secret) can persist in the final `HEAD`/working tree, fully committed and visible in the repo, yet never be surfaced to the reviewer or trigger the `exit(2)` "must fix" gate. This matches the "Unauthorized local command execution that bypasses Claude Code approval or deny controls" impact class: the plugin's only enforcement mechanism (forcing continued remediation via exit code 2) is bypassed for code that should have been flagged.

### Likelihood Explanation
No special privilege is required — only the ability to run "normal git operations" during the turn (commit, checkout a different/unrelated branch or orphan branch), which is well within scope for an agentic coding session, especially if repo content (CONTRIBUTING.md, CI scripts, issue text) nudges Claude toward such a branch workflow. It is fully reproducible and deterministic given the described sequence, since `_is_ancestor` reliably returns `False` for genuinely non-linear history.

### Recommendation
Do not gate inclusion of committed changes on strict linear ancestry. Instead of `dirty_now |= diff(head_at_capture..HEAD)` only under `_is_ancestor`, always union in `changed_since` (`git diff --name-only baseline_sha` against current `HEAD`/working tree) directly into the reviewed set rather than intersecting it away when `dirty_now` is empty — or compute the committed-files term unconditionally as `_git_name_only(repo, head_at_capture)` (content diff against the captured baseline, not a range diff dependent on ancestry) so a sideways `HEAD` move can't erase already-flagged content. At minimum, fall back to reviewing `changed_since` alone whenever `_is_ancestor` is `False` and `HEAD != head_at_capture`, instead of silently excluding it via the intersection.

### Proof of Concept
Integration test plan (pytest, mirroring existing `diffstate`/`compute_v2_review_set` tests):

2. Turn simulation: edit `app.py` to add `os.system(user_input)`; `git add -A && git commit -m "feat"` → commit `B` (child of `A`).
3. `git checkout --orphan other && git add -A && git commit -m "orphan"` (or checkout a pre-existing unrelated branch and cherry-pick/commit the same dangerous `app.py` content there) → current `HEAD = C`, with `_is_ancestor(A, C) == False`.
4. Call `compute_v2_review_set(cwd, baseline_sha=A, head_at_capture=A, untracked_at_baseline={})`.
5. Assert (failing today, expected fix): `app.py` (containing `os.system`) IS present in the returned `review_paths` — i.e. `any("app.py" in p for p in review_paths)` is `True`, and `metrics["review_set_count"] > 0`.
6. Cross-check with `handle_stop_hook`: feed the same session state through `consume_stop_state`/`handle_stop_hook` and assert it does not hit `_skip(9)` ("empty review set") and instead proceeds to `analyze_code_security` with `app.py` included in `diff_files`.

def _git_status_porcelain(cwd):
    """One `git status --porcelain=v1 -z` → (tracked_dirty, untracked) sets of
    repo-root-relative paths, or (None, None) on error. Replaces the
    `_temp_index + git diff HEAD --name-only` pair for the v2 dirty_now
    computation: faster in large repos, and yields the
    untracked set separately so the later get_git_diff can do a targeted
    `add -N -- <files>` instead of a whole-tree `add -N .`.

    -uall: list individual files inside untracked directories (default
    collapses to `dir/`). Required so the untracked set subtracts cleanly
    against the UPS-time `_list_untracked` snapshot, which uses ls-files and
    therefore always lists individual files."""
    try:
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "status",
             "--porcelain=v1", "-uall", "-z"],
            cwd=cwd, capture_output=True, text=True, timeout=30,
        )
        if r.returncode != 0:
            debug_log(f"_git_status_porcelain rc={r.returncode}: {r.stderr[:200]}")
            return None, None
        tracked, untracked = set(), set()
        entries = r.stdout.split("\0")
        i = 0
        while i < len(entries):
            e = entries[i]
            if not e:
                i += 1
                continue
            xy, path = e[:2], e[3:]
            if xy == "??":
                untracked.add(path)
            else:
                tracked.add(path)
                # Rename/copy entries are XY old\0new\0 — second NUL field is
                # the origin path; consume it so it isn't misparsed as a new
                # 2-char-status entry.
                if "R" in xy or "C" in xy:
                    i += 1
            i += 1
        return tracked, untracked
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_status_porcelain error: {e}")
        return None, None
```

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
