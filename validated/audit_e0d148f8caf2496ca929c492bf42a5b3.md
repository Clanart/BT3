### Title
Unchecked buffer indexing in mempool CLVM canonical-encoding check causes IndexError crash on malformed puzzle_reveal/solution - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` parse the CLVM variable-length atom-length prefix (1–6 bytes, RFC-style tagged length encoding analogous to the BHTTP varint in the report) directly on attacker-controlled `puzzle_reveal` and `solution` bytes from every coin spend in a submitted spend bundle, without ever checking that the computed offsets stay within the buffer before indexing into it. A truncated/malformed length-prefix byte causes an unhandled `IndexError` instead of a graceful rejection, mirroring the reported `ArrayIndexOutOfBoundsException` crash pattern from the BHTTP parser.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the length-prefix tag byte and then, for `prefix_len` additional bytes, does: [1](#0-0) 
```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
There is no check that `offset` (after incrementing) is still `< len(clvm_buffer)` before `clvm_buffer[offset]` is dereferenced. If the buffer ends right after the tag byte (e.g. a lone `0xC0` byte claiming a 2-byte length prefix with no following bytes), this indexing raises an unhandled `IndexError`.

`is_clvm_canonical()` calls this in a loop and also directly indexes `clvm_buffer[offset]` with no bounds check: [2](#0-1) 

This is invoked unconditionally, for every coin spend, on both `puzzle_reveal` and `solution` inside `validate_spend_bundle()`: [3](#0-2) 
```
if not is_clvm_canonical(bytes(coin_spend.puzzle_reveal)) or not is_clvm_canonical(
    bytes(coin_spend.solution)
):
    return Err.INVALID_COIN_SOLUTION, None, []
```

The function is expected to *return* `False` for malformed/non-canonical input (as documented and tested for the "non-canonical length prefix" cases), but it does not defensively bound-check offset arithmetic before array access — exactly the same "trusted length used for indexing without validation" bug class as the BHTTP `sumBytes`/`in.getByte(...)` overflow. Here the class of bug is not integer overflow (Python ints don't wrap), but the identical missing-bounds-check pattern: a variable-length size field taken from attacker data drives buffer indexing without first confirming the buffer has enough remaining bytes.

### Impact Explanation
`validate_spend_bundle()` is on the direct path for accepting a spend bundle into the mempool — reachable by any unprivileged spend-bundle submitter (wallet peer or RPC caller) via `add_spend_bundle()`: [4](#0-3) 
The only error handling around this call captures `Err` return values from validation logic, not raised Python exceptions: [5](#0-4) 
An unhandled `IndexError` raised from `is_clvm_canonical` therefore propagates out of `validate_spend_bundle`/`add_spend_bundle` uncaught at this layer, matching the reported "decoder crash from a tiny malformed payload" impact — a remote, unprivileged submitter can trigger a processing-path exception with a single crafted spend bundle whose `puzzle_reveal` or `solution` ends immediately after a length-prefix tag byte.

### Likelihood Explanation
High likelihood of triggering the crash condition: constructing a `CoinSpend` with a 1-byte `puzzle_reveal` such as `b"\xc0"` (or similarly for `solution`) is trivial and requires no privileges, matching the test suite's existing non-canonical-encoding test vectors style: [6](#0-5) 
However, whether this actually reaches an *unhandled* exception at the process level (vs. being caught by an outer generic exception handler in the RPC/protocol dispatch layer, which was not confirmed in this investigation) is uncertain — the code available to review does not show a `try/except` wrapping `is_clvm_canonical` calls, but the ultimate caller (`full_node`/transaction protocol message handler) was not traced in this pass.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before every `clvm_buffer[offset]` access (`if offset >= len(clvm_buffer): return ...treat-as-non-canonical/raise ConsensusError`), so malformed/truncated length prefixes are rejected as ordinary invalid input (`Err.INVALID_COIN_SOLUTION`) rather than raising an uncaught `IndexError`. Add regression tests for truncated 1–6-byte length-prefix headers at every prefix-length boundary, similar to `test_overflow_atoms` in `chia/_tests/clvm/test_chialisp_deserialization.py`.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# a lone tag byte claiming a 2-byte length prefix, with nothing following
is_clvm_canonical(b"\xc0")
# -> IndexError: index out of range, instead of returning False
```
Embedding this single byte string as a `CoinSpend.puzzle_reveal` (or `.solution`) in a `SpendBundle` and submitting it drives execution into `validate_spend_bundle()`'s `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` call, raising the same class of unchecked-length-driven indexing crash described in the report.
