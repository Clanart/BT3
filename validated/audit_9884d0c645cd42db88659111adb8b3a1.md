Confirmed root cause: `PreAddTx` in `kaiax/gasless/impl/tx_pool.go` takes an **RLock** (`g.knownTxsMu.RLock()`) but then calls `g.knownTxs.add(tx, TxStatusQueue)` which is a **write** operation on the underlying `map[common.Hash]*knownTx` (mutating map entries and inserting new keys), whereas every other accessor of the same map — `IsReady`, `PreReset`, `PostReset` — correctly takes the **write** lock (`g.knownTxsMu.Lock()`) before calling `add`/`delete`. This is exactly the "fix applied in the sibling function but missed in one occurrence" pattern described in the external report (a mutation guarded by the wrong lock type in one code path while parallel/analogous code paths got the correct fix).

### Title
Gasless module's `PreAddTx` takes a read lock while mutating the shared `knownTxs` map, causing a data race reachable from concurrent transaction submissions - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`GaslessModule.PreAddTx` is invoked by `TxPool` for every transaction being added (including transactions submitted remotely via public RPC, e.g. `eth_sendRawTransaction`/`txpool.AddRemote`). It acquires `g.knownTxsMu.RLock()` and then calls `g.knownTxs.add(tx, TxStatusQueue)`, which writes into the shared `knownTxs` map. All other methods that mutate the same map/underlying counters (`IsReady`, `PreReset`, `PostReset`) correctly use the exclusive `g.knownTxsMu.Lock()`.

### Finding Description
`knownTxs` is a plain `map[common.Hash]*knownTx` with no internal synchronization [1](#0-0) . Every write path (`add`, `addKnownTx`, `delete`) mutates this map directly and is only made safe by the caller holding `knownTxsMu` for writing. `IsReady`, `PreReset`, and `PostReset` all correctly take the exclusive lock before touching the map [2](#0-1) [3](#0-2) .

However, `PreAddTx` — the entry point called on every transaction insertion into the pool, including concurrent, unprivileged, remotely submitted transactions — only takes `RLock()` while still calling the mutating `g.knownTxs.add(...)`: [4](#0-3) 

Because Go maps are not safe for concurrent read/write or concurrent write/write access, if two goroutines call `PreAddTx` with gasless approve/swap transactions at the same time (or `PreAddTx` races with `IsReady`/`PreReset`/`PostReset`, which take the correct write lock but can be running concurrently while `PreAddTx` believes it only needs a read lock), the underlying map can become corrupted, causing a runtime panic (`fatal error: concurrent map writes` or `concurrent map read and map write`) or a crash of the node process. `TxPool.AddRemote`/`AddLocal` are called from many goroutines simultaneously (P2P propagation, RPC submissions), so it is realistic for multiple approve/swap transactions to be preprocessed concurrently.

### Impact Explanation
An unprivileged public-RPC caller (or any set of concurrent submitters) who sends multiple gasless `GaslessApproveTx`/`GaslessSwapTx` transactions concurrently to a node can trigger concurrent map access to the un-synchronized `knownTxs` map. Because `IsBundleTx`/`add` is invoked from `PreAddTx` (RLock) at the same time other legitimate flows (`IsReady` during block building, `PreReset`/`PostReset` during chain reorgs) hold the write lock and mutate the same map, this is a genuine race, not merely a "read/read" scenario, and Go's race detector/runtime will report and can fatally crash the process (`fatal error: concurrent map writes` is unrecoverable and terminates the whole node, not just a goroutine). This is a node-availability (DoS) issue reachable purely by submitting ordinary gasless transactions, without any special privileges — satisfying "state divergence between honest nodes" concerns (a crashed node stops producing/validating blocks) and can degrade network liveness if triggered on multiple full/validator nodes simultaneously.

### Likelihood Explanation
Likelihood is high under normal network conditions: any two gasless-eligible transactions (approve/swap) submitted to txpool within a short window from different goroutines (e.g., simultaneous RPC calls, or an RPC submission racing with the node's own promotion/reset cycle) can trigger the race. No coordination with validators or any privileged access is required — a single external actor sending two transactions in rapid succession from two connections is sufficient to create the race window, since `PreAddTx` runs per transaction as it's inserted into the pool.

### Recommendation
Change `PreAddTx` in `kaiax/gasless/impl/tx_pool.go` to acquire the exclusive lock (`g.knownTxsMu.Lock()`/`defer g.knownTxsMu.Unlock()`) instead of `RLock()`, consistent with `IsReady`, `PreReset`, and `PostReset`, since it performs a map write via `g.knownTxs.add(...)`.

### Proof of Concept
1. Configure a node with the gasless module enabled (`GaslessConfig` set with valid `GaslessSwapRouter`).
2. From two or more concurrent RPC clients, repeatedly submit valid `GaslessApproveTx`/`GaslessSwapTx` pairs for different senders such that `TxPool.AddRemote` invokes `GaslessModule.PreAddTx` concurrently for many transactions (this happens naturally under load, e.g. via `go test -race` around concurrent `txpool.AddRemote` calls feeding `PreAddTx`, or by stress-testing `eth_sendRawTransaction` concurrently).
3. Because `PreAddTx` takes `RLock()` while calling `g.knownTxs.add()` (a write), and other goroutines executing `IsReady`/`PreReset`/`PostReset` correctly hold `Lock()` concurrently during block building/reorgs, the Go runtime detects the concurrent map write and crashes the process with `fatal error: concurrent map writes` (unrecoverable, terminates the node).

Note: I could not run the actual race detector against this code path in this environment; the conclusion is based on static analysis of the locking discipline in `tx_pool.go` and `tx_counter.go` cited above, where `PreAddTx` is the only mutator of `knownTxs` using a read lock while all sibling mutators use a write lock.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// PostReset re-categorizes knownTxs based on the current txpool.queue and txpool.pending.
func (g *GaslessModule) PostReset(oldHead, newHead *types.Header, queue, pending map[common.Address]types.Transactions) {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	flattenedQueue := make(map[common.Hash]*types.Transaction)
	flattenedPending := make(map[common.Hash]*types.Transaction)
	for _, txs := range queue {
		for _, tx := range txs {
			flattenedQueue[tx.Hash()] = tx
		}
	}
	for _, txs := range pending {
		for _, tx := range txs {
			flattenedPending[tx.Hash()] = tx
		}
	}

	for _, knownTx := range *g.knownTxs {
		if _, ok := flattenedQueue[knownTx.tx.Hash()]; ok {
			g.knownTxs.add(knownTx.tx, TxStatusQueue)
		} else if _, ok := flattenedPending[knownTx.tx.Hash()]; ok {
			g.knownTxs.add(knownTx.tx, TxStatusPending)
		} else {
			g.knownTxs.add(knownTx.tx, TxStatusDemoted)
