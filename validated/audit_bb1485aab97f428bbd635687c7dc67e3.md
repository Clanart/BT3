## Title
Unprivileged withdrawer can permanently freeze a move-to-vault UTXO's reimbursement by respending their own withdrawal dust UTXO with a non-payout transaction - (File: core/src/database/verifier.rs)

### Summary
`get_payout_txs_for_withdrawal_utxos` matches any transaction that spends the registered `withdrawal_utxo_txid`/`withdrawal_utxo_vout` outpoint, with no check that the spending transaction is actually a valid `payout_tx` (correct output amount/script, correct OP_RETURN operator pubkey). Because the withdrawal dust UTXO's private key is controlled solely by the unprivileged withdrawer (the same actor who calls `withdraw()` on the Citrea Bridge contract and chooses the UTXO bytes), that same actor can preempt any operator by respending the UTXO with an ordinary, unrelated transaction, which gets permanently recorded as the withdrawal's `payout_txid` with a `NULL` payer, freezing the paired deposit's move-to-vault UTXO from ever being reimbursed.

### Finding Description
The intended binding is: `withdrawals.payout_txid` for index `w.idx` should equal the txid of a transaction shaped like `create_payout_txhandler` (spending the withdrawal UTXO to the committed output/OP_RETURN operator pubkey) [1](#0-0) , so that `get_payout_info_from_move_txid`/`get_first_unhandled_payout_by_operator_xonly_pk` can later route the deposit's move-to-vault UTXO to a real reimbursing operator [2](#0-1) .

Instead, `get_payout_txs_for_withdrawal_utxos` only joins on `(txid, vout)` equality with `bitcoin_syncer_spent_utxos`, with no validation of the spending transaction's structure: [3](#0-2) 

`update_finalized_payouts` then unconditionally writes whatever `spending_txid` was found into `payout_txid` for that `idx`, only falling back to `operator_xonly_pk = None` if the OP_RETURN is missing/invalid — it never skips or rejects the row as invalid: [4](#0-3) 

`upsert_move_to_vault_txid_from_citrea_deposit` and `update_withdrawal_utxo_from_citrea_withdrawal` both key on the same `idx` in the single `withdrawals` table, so a deposit's `move_to_vault_txid` and a withdrawal's UTXO share one row/index pairing [5](#0-4) .

The withdrawal dust UTXO is generated and solely controlled by the withdrawer (the unprivileged attacker), who signs it with `SinglePlusAnyoneCanPay` for the operator to complete later: [6](#0-5) . Nothing prevents this same key holder from broadcasting a different transaction spending that outpoint (e.g., a plain self-transfer) before any operator's `payout_tx` confirms — `Operator::withdraw` only checks the outpoint against Citrea's recorded UTXO and signature validity, not that the outpoint is still unspent at request time in a race-safe way [7](#0-6) .

Once the attacker's unrelated transaction confirms and is indexed by `update_finalized_payouts`, `withdrawals.idx` gets `payout_txid = <attacker's txid>` and `payout_payer_operator_xonly_pk = NULL` permanently (since the real Bitcoin outpoint is already spent, no operator can ever construct a competing, confirmable `payout_tx` for the same input). Consequently:
- `get_first_unhandled_payout_by_operator_xonly_pk`, which requires `payout_payer_operator_xonly_pk = $1` (a specific operator) and drives `PayoutCheckerTask`/kickoff/reimburse, will never match this row for any operator [2](#0-1) [8](#0-7) .
- The optimistic-payout path is also blocked because it explicitly rejects already-spent withdrawal UTXOs [9](#0-8) .

Since the paired move-to-vault UTXO (same `idx`) can only be released via `create_reimburse_txhandler`, which is reachable only after a legitimate payout is recorded and picked up by `get_payout_info_from_move_txid`/`send_asserts` [10](#0-9) [11](#0-10) , that move-to-vault UTXO becomes permanently unreimbursable by any operator.

None of the listed guards (`is_deposit_valid`, `SECP.verify_schnorr`, `SPV::verify`, `verify_storage_proofs`, presigned tx graph) validate that the *bitcoin-layer* spending transaction of the withdrawal UTXO is actually a well-formed payout; they only validate the operator-submitted payout at kickoff/assert time, by which point the outpoint may already be irrecoverably consumed.

### Impact Explanation
This directly matches the Critical category "a move-to-vault UTXO permanently frozen": the deposit funds paired (via the shared `idx`) with the griefed withdrawal record can never be routed through `create_reimburse_txhandler` because no operator payout for that index can ever be recorded with a non-null `payout_payer_operator_xonly_pk`. This is repeatable per withdrawal the attacker initiates (one griefing transaction per withdrawal id, each locking one deposit's vault UTXO), and requires no operator, verifier, or aggregator cooperation.

### Likelihood Explanation
The attacker only needs to: (1) create and own the dust withdrawal UTXO (already required to call `withdraw()` on Citrea normally), (2) broadcast an alternate spend of that UTXO with normal fees before any operator's `payout_tx` confirms. This costs only the dust amount plus fees (a few hundred to a few thousand sats) and requires no privileged role, key share, or collateral — fully within the stated unprivileged attacker capability set. It is trivially repeatable for every withdrawal the attacker (or any withdrawer) initiates.

### Recommendation
Before accepting a `bitcoin_syncer_spent_utxos` row as a legitimate payout for a withdrawal index, validate the spending transaction's structure (output value/script matching Citrea's committed withdrawal output, and OP_RETURN carrying a valid operator xonly pubkey) prior to writing `payout_txid`/marking the row as settled; if the structure doesn't match, do not record it as the withdrawal's payout (leave `payout_txid` NULL) so operators can still be alerted that the underlying UTXO was griefed/spent and can escalate (e.g., flag the withdrawal id as unpayable) rather than silently freezing the paired vault UTXO.

### Proof of Concept
Extend `core/src/database/verifier.rs`'s `update_get_payout_txs_from_citrea_withdrawal`-style test:
1. Register a withdrawal `idx` with `upsert_move_to_vault_txid_from_citrea_deposit` and `update_withdrawal_utxo_from_citrea_withdrawal` pointing at a dust `utxo`.
2. Instead of inserting a real payout tx, call `insert_spent_utxo` with an arbitrary/unrelated `spending_txid` (not shaped as a payout tx, no OP_RETURN with operator pubkey) for that `(utxo.txid, utxo.vout)`.
3. Call `get_payout_txs_for_withdrawal_utxos(block_id)` and assert it returns `(idx, spending_txid)` — i.e., the bogus spend IS recorded, proving no structural validation exists.
4. Call `update_payout_txs_and_payer_operator_xonly_pk` with `operator_xonly_pk = None` (mirroring `update_finalized_payouts`'s fallback), then call `get_first_unhandled_payout_by_operator_xonly_pk` for any operator xonly_pk and assert it returns `None` forever for this `idx`, while `get_payout_info_from_move_txid(move_txid).payout_txid` is `Some(spending_txid)` permanently — demonstrating the move-to-vault UTXO at this `idx` can never be routed to `create_reimburse_txhandler`.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;
