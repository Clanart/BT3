### Title
Pausing `WombatStaking` and `VLMGP`/`mWomSV` blocks all withdraw/unlock paths with no emergency exit, permanently locking user funds - ([File: wombat/WombatStaking.sol], [File: VLMGP.sol], [File: wombat/mWomSV.sol])

### Summary
Every user-facing exit function for staked LP tokens and for locked MGP/mWOM (via `VLMGP`/`mWomSV`) is gated by the `whenNotPaused` modifier, while no compensating emergency-withdraw path exists for these flows. If the contracts are paused, users cannot retrieve principal already deposited/locked, even though deposits into these systems were made under normal operation.

### Finding Description
`WombatStaking.withdraw()`, which is the sole function that returns a user's underlying deposit token from the Wombat pool, is protected by `whenNotPaused`: [1](#0-0) 

This function is the only path `WombatPoolHelper`/`WombatPoolHelperV2`/`AnkrBNBPoolHelper` use to let a user pull LP principal back out, so pausing `WombatStaking` blocks every pool helper's `withdraw()` call site: [2](#0-1) [3](#0-2) 

`WombatStaking` has no emergency-withdraw function that bypasses the pause, unlike `MasterMagpie`, which at least offers a `whenPaused`-gated `emergencyWithdraw()` for its own staking-token balances: [4](#0-3) 

The same pattern exists for the lock/unlock mechanisms of `VLMGP` and `mWomSV`. `startUnlock`, `unlock`, `cancelUnlock`, and `forceUnLock` are all `whenNotPaused`, and none has a paused-mode escape hatch: [5](#0-4) [6](#0-5) 

Pause of these contracts is triggered by simple owner calls to `pause()`, which is a standard operational action (not a malicious admin scenario) intended for temporary emergency response: [7](#0-6) [8](#0-7) 

Because none of these three contracts provide any way for a user to reclaim principal while paused, any pause (even a legitimate, temporary one) freezes:
- All LP principal already deposited into Wombat pools via `WombatStaking`/pool helpers.
- All MGP locked in `VLMGP` that is mid-cooldown or fully unlocked-but-unclaimed (since `unlock()` itself is blocked).
- All mWOM locked in `mWomSV` under the same conditions.

### Impact Explanation
This meets the "permanent freezing of funds" / "24-hour-plus freeze" bar: as long as the contract stays paused, ordinary users have zero mechanism to retrieve already-deposited LP tokens or already-unlockable locked tokens. Since there is no time-bound auto-unpause and no bypass, the freeze duration is entirely at the discretion of contract state (pause is not time-limited), and can trivially exceed 24 hours during any real incident response or prolonged pause window.

### Likelihood Explanation
Pausing is a standard, expected operational lever (used for incident response, upgrades, or Wombat-side incidents) rather than an exotic edge case, so the freeze condition is likely to occur during the contract's normal operational lifecycle, not merely under a hypothetical malicious scenario.

### Recommendation
- Remove `whenNotPaused` from `WombatStaking.withdraw()` and `burnReceiptToken()` (and correspondingly from pool helper `withdraw()` calls), or add a `whenPaused`-only emergency withdraw path that returns principal directly without harvesting rewards.
- Remove `whenNotPaused` from `VLMGP.unlock()`/`forceUnLock()`/`mWomSV.unlock()` (and their `startUnlock`/`cancelUnlock` companions), or add an emergency unlock function usable while paused that skips the `IMasterMagpie.multiclaimFor` reward-claim step if that step is the reason these are paused-gated.

### Proof of Concept
1. Owner calls `WombatStaking.pause()` (or `VLMGP.pause()` / `mWomSV.pause()`) for an operational reason (e.g., responding to an incident elsewhere in the system). [9](#0-8) 
2. A user who deposited LP principal earlier calls `WombatPoolHelper.withdraw()` to retrieve their stables; this reverts because `WombatStaking.withdraw()` requires `whenNotPaused`. [10](#0-9) 
3. Similarly, a user whose `VLMGP` cooldown has completed calls `unlock()` to retrieve their MGP; this reverts due to the same modifier, with no alternative exit function available. [11](#0-10) 
4. Funds remain locked in the contract for the entire duration of the pause, with no way for the user to intervene.

        UserInfo storage user = userInfo[_stakingToken][msg.sender];
        uint256 availableaAmount = user.available;
