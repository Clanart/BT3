### Title
Race condition in `GaslessModule.PreAddTx` allows the gasless bundle-tx queue admission limit to be bypassed via concurrent transaction submission - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
`PreAddTx` enforces the `MaxBundleTxsInQueue` admission limit for gasless bundle transactions by reading `g.knownTxs.numQueue()` and, if under the limit, writing a new entry into the same `knownTxs` map — but the entire check-then-write sequence is guarded only by a **read lock** (`g.knownTxsMu.RLock()`), not an exclusive lock. This mirrors the Craft CMS TOCTOU pattern (check usage count, then update non-atomically), allowing concurrent callers to race past the limit check.

### Finding Description
`PreAddTx` is invoked from `TxPool.add()` for every transaction that a registered `TxBundlingModule` claims via `IsModuleTx` [1](#0-0) . For gasless bundle transactions, `PreAddTx` performs:

1. Read `g.knownTxs.get(tx.Hash())` for a duplicate/known-tx check.
2. Read `g.knownTxs.numQueue()` and compare against `g.GetMaxBundleTxsInQueue()`.
3. If under the limit, write the new tx into the map with `g.knownTxs.add(tx, TxStatusQueue)`.

All three steps are performed while holding only `g.knownTxsMu.RLock()` (a shared/read lock), not `Lock()`: [2](#0-1) 

Because `RLock()` permits multiple concurrent holders, two or more goroutines processing different transactions from different senders (e.g., concurrent `AddRemote`/`AddRemotes` calls into `TxPool`, or concurrent `AddLocal` calls) can simultaneously:
- Both call `numQueue()` and observe the same count value below `MaxBundleTxsInQueue`.
- Both pass the `>= GetMaxBundleTxsInQueue()` check.
- Both call `g.knownTxs.add(...)`, which mutates the underlying `map[common.Hash]*knownTx` (`knownTxs.add` in [3](#0-2) ) concurrently under only a shared read lock.

This is precisely the check-then-update TOCTOU pattern from the CVE (read usage count → check limit → write, without atomicity), and additionally it is an unsynchronized concurrent write to a plain Go map (not even a benign race), because `RLock` does not serialize writers against each other. The queue-admission cap (`--gasless.max-bundle-txs-in-queue`, default 100, see `MaxBundleTxsInQueueFlag`) exists specifically to bound resource usage of the gasless bundling subsystem [4](#0-3) ; a race that bypasses it defeats that admission-control mechanism.

The existing tests only cover sequential admission behavior and do not exercise concurrent `PreAddTx` calls: [5](#0-4) 

### Impact Explanation
An attacker who can submit or relay many gasless bundle transactions concurrently (e.g., many parallel `eth_sendRawTransaction`/RPC submissions from different sender keys, which is entirely reachable by any public-RPC/unprivileged transaction sender) can:
- Exceed the configured `MaxBundleTxsInQueue` limit, defeating the resource-control/admission gate meant to bound the number of pending gasless bundle candidates held in the endpoint node's memory.
- Corrupt the `knownTxs` map via concurrent unsynchronized writes to a Go map, which can panic the node process (Go maps panic with "concurrent map writes" under data races) — i.e., node-level denial of service triggerable purely from valid, unprivileged transaction submission traffic on an Endpoint Node.

This is reachable purely through the gasless transaction path exposed to any user submitting `GaslessApproveTx`/`GaslessSwapTx` transactions, consistent with the allowed analog categories (gasless module reachable by an unprivileged transaction sender).

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to submit multiple bundle-eligible gasless transactions in rapid concurrent succession so that `TxPool.addTxs`/parallel RPC submission paths invoke `PreAddTx` concurrently from separate goroutines. This is achievable without any special privileges — the same mechanism by which the Craft CMS bug required "concurrent requests" against a single validation path. Since gasless transactions are a public, permissionless feature (KIP-247) reachable via ordinary transaction submission, no impersonation-token-equivalent secret is required, making exploitation reachability higher than the original CVE, though it does require sending many transactions in a tight time window to win the race.

### Recommendation
Replace `g.knownTxsMu.RLock()`/`RUnlock()` in `PreAddTx` with a full `Lock()`/`Unlock()` so that the check (`numQueue()` vs `MaxBundleTxsInQueue`) and the mutating `knownTxs.add()` call happen atomically under exclusive access, consistent with how `IsReady`, `PreReset`, and `PostReset` already correctly use `g.knownTxsMu.Lock()` for mutations [6](#0-5) . Add a concurrency test that fires many parallel `PreAddTx` calls near the `MaxBundleTxsInQueue` boundary and asserts the queue count never exceeds the configured limit and no `-race` violations occur.

### Proof of Concept
Conceptual PoC (Go, targeting `GaslessModule.PreAddTx` directly or via `TxPool.AddRemotes`):
1. Configure `GaslessConfig.MaxBundleTxsInQueue = 1`.
2. Construct N (e.g., 50) distinct valid `GaslessApproveTx` transactions from N different sender keys, all satisfying `IsBundleTx`.
3. Launch N goroutines that each call `g.PreAddTx(tx_i, false)` (or drive them through `TxPool.AddRemotes` concurrently) simultaneously via a start barrier (channel close), similar to the existing `TestBidPool_ConcurrentAddBid_OneWinnerPerSender` pattern used elsewhere in the codebase for auction bid races [7](#0-6) .
4. Observe that more than 1 transaction is admitted into `g.knownTxs` with `TxStatusQueue` (violating `MaxBundleTxsInQueue == 1`), and/or observe a Go runtime "fatal error: concurrent map writes" panic when run with `go test -race`.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (k knownTxs) add(tx *types.Transaction, status int) {
	if tx == nil {
		return
	}

	if ktx, ok := k.get(tx.Hash()); ok {
		ktx.status = status
	} else {
		k[tx.Hash()] = &knownTx{
			tx:           tx,
			addedTime:    time.Time{},
			promotedTime: time.Time{},
			status:       status,
		}
	}

	if status == TxStatusQueue {
		k[tx.Hash()].startAddedTimeIfZero()
	} else if status == TxStatusPending {
		k[tx.Hash()].startPromotedTimeIfZero()
	}

	updateMetrics(&k)
}

func TestPreAddTxQueueLimit(t *testing.T) {
	log.EnableLogForTest(log.LvlError, log.LvlTrace)

	newModule := func(maxQueue uint) *GaslessModule {
		cfg := *gasless.DefaultGaslessConfig()
		cfg.MaxBundleTxsInQueue = maxQueue
		g := NewGaslessModule()
		dbm := database.NewMemoryDBManager()
		backend := backends.NewSimulatedBackendWithDatabase(dbm, testAllocStorage(), testChainConfig)
		nodekey, _ := crypto.GenerateKey()
		require.NoError(t, g.Init(&InitOpts{
			ChainConfig:   testChainConfig,
			GaslessConfig: &cfg,
			NodeKey:       nodekey,
			Chain:         backend.BlockChain(),
			NodeType:      common.ENDPOINTNODE,
		}))
		return g
	}

	bundleTx := func() *types.Transaction {
		privkey, _ := crypto.GenerateKey()
		return makeApproveTx(t, privkey, 0, ApproveArgs{Spender: common.HexToAddress("0x1234"), Amount: abi.MaxUint256})
	}

	// --gasless.max-bundle-txs-in-queue <= 0 maps to the math.MaxUint64 "no limit"
	// sentinel (config.go).
	t.Run("no limit sentinel accepts on empty queue", func(t *testing.T) {
		g := newModule(math.MaxUint64)
		tx := bundleTx()
		require.True(t, g.IsBundleTx(tx))
		require.NoError(t, g.PreAddTx(tx, false))
		require.Equal(t, 1, g.knownTxs.numQueue())
	})

	t.Run("finite limit still enforced", func(t *testing.T) {
		g := newModule(1)
		require.NoError(t, g.PreAddTx(bundleTx(), false))
		require.ErrorIs(t, g.PreAddTx(bundleTx(), false), ErrBundleTxQueueFull)
	})
}

func TestBidPool_ConcurrentAddBid_OneWinnerPerSender(t *testing.T) {
	bidA, bidB := testBids[0], testBids[4]
	require.Equal(t, bidA.Sender, bidB.Sender)
	require.Equal(t, bidA.BlockNumber, bidB.BlockNumber)
	require.NotEqual(t, bidA.TargetTxHash, bidB.TargetTxHash)

	for i := 0; i < 10; i++ {
		func() {
			mockCtrl := gomock.NewController(t)
			defer mockCtrl.Finish()

			chain := chain_mock.NewMockBlockChain(mockCtrl)
			chain.EXPECT().CurrentBlock().Return(types.NewBlockWithHeader(&types.Header{Number: big.NewInt(1)})).AnyTimes()

			pool := NewBidPool(testChainConfig, chain, &auction.AuctionConfig{MaxBidPoolSize: 1024})
			require.NotNil(t, pool)
			pool.start()
			atomic.StoreUint32(&pool.running, 1)
			defer pool.stop()
			pool.auctioneer = testAuctioneer
			pool.auctionEntryPoint = testAuctionEntryPoint

			var (
				wg         sync.WaitGroup
				errA, errB error
			)
			startGate := make(chan struct{})

			wg.Add(2)
			go func() {
				defer wg.Done()
				<-startGate
				_, errA = pool.AddBid(bidA)

				defer wg.Done()
				<-startGate

			pool.bidMu.RUnlock()

			require.False(t, errA == nil && errB == nil && gotA && gotB,
				"iter %d: both same-sender bids accepted", i)
		}()
	}
