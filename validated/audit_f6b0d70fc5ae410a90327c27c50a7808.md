### Title
A single attacker-crafted `ReceivedOutput` poisons the input list, making `SignableTransaction::multisig` reject the entire transaction and DoSing all spends - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) deserializes an `offset` scalar, a `TxOut`, and an `OutPoint` with no consistency check that `offset` actually derives `script_pubkey`. Later, `SignableTransaction::multisig` (send.rs:273-285) loops over every input and returns `None` for the *whole* transaction the first time `p2tr_script_buf(offset.group_key()) != prevout.script_pubkey`. This is the same bug class as the OpenQ report: one maliciously injected element in an iterated collection aborts the entire payout/spend operation, with no way to identify or skip the offending element.

### Finding Description
- `ReceivedOutput::read` accepts arbitrary bytes: `Secp256k1::read_F` for the offset, then `TxOut::consensus_decode` / `OutPoint::consensus_decode` (mod.rs:122-133). It never verifies `output.script_pubkey == p2tr_script_buf(key + offset*G)` — it cannot, since it doesn't know the key.
- `SignableTransaction::new` (send.rs:150) takes a `Vec<ReceivedOutput>` wholesale as inputs.
- `SignableTransaction::multisig` (send.rs:273-285) iterates all inputs:

```rust
for i in 0 .. self.tx.input.len() {
  let offset = keys.clone().offset(self.offsets[i]);
  if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
    None?;
  }
  sigs.push(...);
}
```

If input `i` has a valid p2tr `script_pubkey` but an `offset` that doesn't correspond to it (which `read` happily produces), the `None?` aborts construction of `TransactionMachine` entirely. Every honest input in the same transaction is unspendable through this API, and the caller gets no indication of which input is faulty — directly mirroring the report's "one reverting token transfer reverts the entire claim loop."

### Impact Explanation
An unprivileged party who can feed crafted bytes into `ReceivedOutput::read` (an explicitly in-scope untrusted-byte sink) can inject one poisoned input into a spend. The multisig then can never construct a `TransactionMachine` for any `SignableTransaction` containing it — a persistent DoS of funds withdrawal indistinguishable from "the signer is offline," since `multisig` returns `None` rather than an error identifying the bad input. All other legitimate received outputs bundled in the transaction are held hostage, exactly as all whitelisted reward tokens were held hostage by the malicious token.

### Likelihood Explanation
The on-chain path is safe: `Scanner::scan_transaction` (mod.rs:199-214) only emits outputs whose `script_pubkey` was registered via `register_offset`, so scanned outputs are always self-consistent. The vulnerability is reachable wherever serialized `ReceivedOutput`s are accepted from an untrusted party or merged with locally scanned outputs (e.g., outputs relayed between processors, restored from externally writable storage, or supplied by an integrator mixing foreign sources). That is the only ingestion route, which lowers the likelihood, but the sink is part of the declared attack surface.

### Recommendation
Perform the offset↔script consistency check early: either give `ReceivedOutput::read` access to the expected key set, or validate each input inside `SignableTransaction::new`/`multisig` and return a per-input error (`TransactionError::InvalidInput(index)`) instead of `None`, so callers can drop the single bad output rather than having the whole spend silently fail. Alternatively, store the script's registered offset alongside outputs in `Scanner`'s DB write path so deserialization can't disagree with the scan.

### Proof of Concept
```rust
// Craft a ReceivedOutput whose offset doesn't derive its script_pubkey.
let mut bytes = vec![];
// offset = 1, but use the *un-offset* p2tr script for `key`
bytes.extend(Scalar::ONE.to_bytes());
bytes.extend(serialize(&TxOut {
  value: Amount::from_sat(1000),
  script_pubkey: p2tr_script_buf(key).unwrap(), // script for offset 0
}));
bytes.extend(serialize(&OutPoint::new(txid, 0)));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// Combine with a legitimate scanned output.
let tx = SignableTransaction::new(
  vec![legit_output, forged], &payments, None, None, fee_rate
).unwrap();

// This returns None: input 1 fails the script check, and there is no
// error indicating which input is bad — the entire spend is bricked.
assert!(tx.multisig(&keys).is_none());
```
