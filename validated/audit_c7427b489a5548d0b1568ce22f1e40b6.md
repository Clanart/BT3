### Title
Cached FROST preprocess is never deleted after use, enabling nonce reuse and key-share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` stores a reusable nonce seed in `CachedPreprocesses` keyed only by `context` and never removes it. Every subsequent `share_internal` call for the same context reloads the same seed via `AlgorithmSignMachine::from_cache`, regenerating identical FROST nonces. This is the direct analog of `rescind()` marking a request inactive without deleting it: the consumed ("deactivated") preprocess stays in the collection and is silently reused, and here the consequence is not gas creep but private key share recovery.

### Finding Description
In `preprocess_internal`, a fresh preprocess is created and its 32-byte seed is XOR-encrypted and persisted under `CachedPreprocesses::set(self.txn, &self.context, ...)` [1](#0-0) . On every later invocation, `CachedPreprocesses::get` returns the same seed and `from_cache` deterministically re-derives the same nonces and commitments via `seeded_preprocess` (`ChaCha20Rng::from_seed(*seed.0)`) [2](#0-1) [3](#0-2) .

`share_internal` consumes this machine and calls `machine.sign(preprocesses, msg)`, where `preprocesses` is whatever map of participant preprocesses was supplied [4](#0-3) . Critically, `DkgConfirmer::share` calls `share_internal` once, and `DkgConfirmer::complete` calls `share_internal` **again** on the same context `(b"DkgConfirmer", attempt)` before completing [5](#0-4) . There is no `CachedPreprocesses::del`/removal anywhere in the codebase — the entry persists forever.

The safety argument in the file header relies on received messages being identical between the two `sign` executions [6](#0-5) , but the *set* of preprocesses passed to `sign` is not fixed by consensus: `share` may run when exactly `t` preprocesses are available, while `complete` runs later with a larger/different map (more validators' preprocesses finalized in the interim, or a different subset via `threshold_i_map_to_keys_and_musig_i_map` after `removed` changes). In `AlgorithmSignMachine::sign`, the `included` vector and per-participant binding factor `rho` are computed from the supplied preprocess map [7](#0-6) , so a differing map yields a different aggregate nonce `R` and challenge `c` while the local nonces `(d, e)` are identical.

Two shares `s₁ = d + e·rho₁ + λ₁·c₁·x` and `s₂ = d + e·rho₂ + λ₂·c₂·x` published with the same `(d, e)` but different `rho`/`c` are exactly the FROST nonce-reuse equation that leaks the secret share `x` (and the nonce itself via the known `rho` values). The frost crate's own docs state the cached preprocess "MUST only be used once. Reuse will enable third-party recovery of your private key share" [8](#0-7)  — this contract is violated because the consumed entry is never deleted.

### Impact Explanation
Recovery of a validator's Ristretto MuSig secret key share — the key used to confirm DKG results on-chain and act as the root of trust for the tributary set. Any two distinct signing-set compositions under the same `(b"DkgConfirmer", attempt)` context (e.g., `share` executed with `t` preprocesses, `complete` executed after additional preprocesses finalized) produce two public signature shares sufficient to solve for the secret share.

### Likelihood Explanation
The seed persists indefinitely in the DB, so reuse is guaranteed to occur on the `share` → `complete` path whenever the preprocess map differs between the two calls, and also after any partial rebuild/crash that re-executes `share_internal` on a reordered set. No collusion or BFT break is required — only normal asynchronous arrival of validators' preprocess transactions between the share phase and the complete phase.

### Recommendation
Delete the `CachedPreprocesses` entry atomically when it is loaded for signing (e.g., `get`-then-`del` within `self.txn`, or `del` after `from_cache`), mirroring how `defaulted()` removes entries in the reference code. Alternatively, key the cache by a hash of the exact preprocess set so that a differing set cannot regenerate the same nonces.

### Proof of Concept
1. `DkgConfirmer::share(preprocesses_A, key_pair)` runs at attempt `k` with `|preprocesses_A| = t`; `preprocess_internal` stores seed under `("DkgConfirmer", k)`, derives nonces `(d, e)`, and publishes share `s₁ = d + e·rho₁ + λ₁·c₁·x`.
2. Additional preprocess transactions finalize; `DkgConfirmer::complete(preprocesses_B ⊋ A, key_pair, shares)` calls `share_internal` again under the same context, reloads the identical seed, regenerates `(d, e)`, and computes a second share `s₂ = d + e·rho₂ + λ₂·c₂·x` with `rho₂ ≠ rho₁`, `c₂ ≠ c₁`.
3. From the two published shares and the public preprocess commitments, solve the two-equation system for `x` (validator secret share) and `d`, `e`.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
  }

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }

    msg: &[u8],

    let multisig_params = self.params.multisig_params();

    let mut included = Vec::with_capacity(preprocesses.len() + 1);
    included.push(multisig_params.i());
    for l in preprocesses.keys() {
      included.push(*l);
    }
    included.sort_unstable();

    // Included < threshold
    if included.len() < usize::from(multisig_params.t()) {
      Err(FrostError::InvalidSigningSet("not enough signers"))?;
    }
    // OOB index
    if u16::from(included[included.len() - 1]) > multisig_params.n() {
      Err(FrostError::InvalidParticipant(multisig_params.n(), included[included.len() - 1]))?;

    for i in 0 .. (included.len() - 1) {
      if included[i] == included[i + 1] {
        Err(FrostError::DuplicatedParticipant(included[i]))?;
      }
    }

    let view = self.params.keys.view(included.clone()).unwrap();
    validate_map(&preprocesses, &included, multisig_params.i())?;
