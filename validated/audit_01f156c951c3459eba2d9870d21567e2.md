### Title
PedPoP encryption-key registration accepts the identity point because `EncryptionKeyMessage::read`/`EncryptedMessage::read` use `Ciphersuite::read_G` which does not inherit FROST's identity rejection, making all shares sent to that participant decryptable by any observer - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The calibre bug class is a nested evaluation context that fails to inherit a restrictive flag (`allow_python_templates=False`), letting attacker input reach a forbidden code path. The Serai analog is the nested `read_G` used inside PedPoP's DKG messages: the FROST layer defines a stricter reader, `Curve::read_G`, which rejects the identity point [1](#0-0) , but PedPoP's `EncryptionKeyMessage::read` and `EncryptedMessage::read` call the unrestricted `Ciphersuite::read_G`, which only enforces canonical encoding [2](#0-1) . The inner read never inherits the non-identity invariant, so an unprivileged DKG participant can register the identity point as their encryption key — or attach the identity as a message key with a trivially forged proof-of-possession.

### Finding Description
`EncryptionKeyMessage::read` reads `enc_key` via `C::read_G`, where `C: Ciphersuite` only, so `Ciphersuite::read_G` is used and the identity encoding is accepted [3](#0-2) . `Decryption::register` stores this key with no further validation [4](#0-3) .

When an honest participant later calls `Encryption::encrypt` for that participant, the ECDH shared secret is computed as `ecdh(k, to) = k * to` [5](#0-4) . With `to = identity`, the shared point is `identity` regardless of the ephemeral scalar `k`. The ChaCha20 key is then `transcript(context).append("shared_key", identity.to_bytes()).challenge("key")` [6](#0-5)  — a purely public value. The `EncryptedMessage` broadcast (`key = kG`, ciphertext) therefore decrypts under a key anyone can recompute; the message key `kG` isn't even needed.

The same gap exists in `EncryptedMessage::read`: `key` is read with `C::read_G` [7](#0-6) , and the per-message Schnorr PoP `msg.pop.verify(msg.key, ...)` [8](#0-7)  is checked against public key `msg.key`. For `msg.key = identity`, `batch_statements` degenerates to `R - sG` [9](#0-8) , so any `(R = rG, s = r)` passes — a forged proof-of-possession with no secret. This re-opens the exact attack the PoP was added to prevent (lines 84-90 of the file describe Eve reusing a key to force a victim to reveal `bX` via blame): an attacker can supply `key = identity` and the victim's `decrypt` computes `b * identity = identity`, producing an `EncryptionKeyProof` whose "shared key" is the constant identity point [10](#0-9) .

### Impact Explanation
- **Secret-share confidentiality loss / key-share recovery:** every `SecretShare` an honest party sends to the malicious participant is ChaCha20-encrypted under a publicly derivable key. Any passive observer of the authenticated channel can decrypt all of them and reassemble that participant slot's assembled secret share of the group key. That is recovery of a threshold key share reachable purely from the attacker's public `EncryptionKeyMessage` bytes. For `t = n` (`Interpolation::Constant`) and small `n`, this materially reduces the work needed to reconstruct the group secret when combined with other compromised slots.
- **Forged proof-of-possession:** the identity `key` makes the Schnorr PoP vacuously satisfiable, defeating the malleability defense documented in the code and letting blame proofs be generated against attacker-controlled messages whose "decryption key" is a fixed public constant.

### Likelihood Explanation
The trigger is a single DKG round-1 message: an attacker (any participant, no privileges) sets `enc_key` to the canonical identity encoding in their broadcast `EncryptionKeyMessage<Commitments>`. The bytes pass `read_G` canonical checks, the PoK over `commitments` is unaffected (it covers the commitments, not the enc key), and `register` stores it unconditionally. Every honest party then encrypts to the identity in `generate_secret_shares`. No interaction, timing, or probabilistic element is required — deterministic exploitability.

### Recommendation
Reject the identity point for all protocol-supplied group elements in `crypto/dkg/pedpop`: mirror `Curve::read_G`'s check by adding an `is_identity()` rejection inside `EncryptionKeyMessage::read`, `EncryptedMessage::read`, and `EncryptionKeyProof::read` (or perform the check in `Decryption::register`/`decrypt`). Additionally, in `Decryption::decrypt`/`decrypt_with_proof`, assert the computed ECDH point is non-identity before deriving the cipher, so a degenerate shared secret can never silently produce a publicly-known stream key.

### Proof of Concept
1. Attacker `l` runs `KeyGenMachine::generate_coefficients`, then serializes their `EncryptionKeyMessage` and rewrites the trailing `enc_key` bytes to the canonical encoding of `C::G::identity()` before broadcasting (equivalently, constructs the message directly: `Commitments` + `identity` via `write`). `EncryptionKeyMessage::read` accepts it because `Ciphersuite::read_G` never checks `is_identity` [2](#0-1) .
2. Each honest `SecretShareMachine::generate_secret_shares` calls `self.encryption.encrypt(rng, l, share)` → `ecdh(k, identity) = identity` → `cipher(context, identity)`; the resulting `EncryptedMessage` is broadcast.
3. Observer recomputes `key = challenge(transcript(context, "encryption_key", identity.to_bytes()))`, instantiates `ChaCha20::new(key, b"DKG IV v0.2\0")`, applies the keystream to `msg`, and parses `SecretShare<F>` — recovering every honest party's polynomial evaluation at `l`, i.e. participant `l`'s full secret share, without ever sending a message.
4. For the forged PoP: attacker sends `EncryptedMessage { key: identity, pop: SchnorrSignature { R: rG, s: r }, msg }`; `verify(identity, c)` reduces to `rG + c·identity - rG = 0` and passes `decrypt`'s batch check [11](#0-10) .

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0

      // R

      (challenge, public_key),
