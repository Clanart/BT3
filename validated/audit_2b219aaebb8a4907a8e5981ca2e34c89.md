### Title
Self-destructing a registered native ERC20 permanently uncollateralizes its minted Cosmos coin, allowing irreversible unbacked-supply creation - (File: `x/erc20/keeper/msg_server.go`)

### Summary
The Arbitrum report describes a privileged actor (`MEMBER_ADDER_ROLE`) silently undoing a state-changing action (member removal) because the removal is never tracked, breaking an invariant the system relies on ("a removed member stays removed"). The equivalent invariant in Cosmos EVM's `x/erc20` module is: *every unit of a native-ERC20-backed Cosmos coin must remain 1:1 collateralized by an equal amount of ERC20 tokens escrowed in the module account*. `x/erc20/keeper/msg_server.go` silently discards this invariant by deleting the `TokenPair` the moment the underlying contract self-destructs, without reconciling or burning the outstanding coin supply that was collateralized by that now-destroyed contract's balance.

### Finding Description
When a user converts ERC20 → native coin via `ConvertERC20`, the module escrows the ERC20 tokens into `types.ModuleAddress`'s EVM balance and mints an equal amount of the corresponding Cosmos coin: [1](#0-0) 

The reverse conversion (`ConvertCoin`) unescrows tokens from the module account and burns the coins, preserving the 1:1 relationship: [2](#0-1) 

Both `ConvertERC20` and `ConvertCoin` contain identical logic that treats a self-destructed contract as a signal to simply erase the token pair, with **no check on outstanding coin supply**: [3](#0-2) [4](#0-3) 

`DeleteTokenPair` only removes the pair/denom/erc20/allowance indexes — it never inspects or burns the native coin supply that was backed by the destroyed contract's escrowed balance: [5](#0-4) 

Crucially, `DeleteAccount` (triggered by `SELFDESTRUCT`) wipes the contract's balance, code, storage, and even removes the underlying auth account entirely: [6](#0-5) 

This means the module's escrowed ERC20 balance backing already-minted coins is destroyed along with the contract, while the minted native coins already sent to users remain fully valid, spendable, transferable Cosmos coins (bank module tracks balances/supply independently of `x/erc20` token pairs). Once the pair is deleted, there is no mechanism to burn, freeze, or otherwise reconcile that now-unbacked supply — it is a **permanent, irreversible corruption of the 1:1 backing invariant**, i.e., an unauthorized/uncollateralized token creation.

The attack requires only an ERC20 contract that (a) can mint tokens to the attacker (attacker deploys the malicious contract themselves) and (b) can self-destruct — both trivial for an attacker-authored contract. Registration of the token pair itself can be fully unprivileged if the module parameter `PermissionlessRegistration` is enabled (confirmed present in `x/erc20/types/params.go` and checked in `RegisterERC20`): [7](#0-6) 

Even when registration requires governance, a malicious/compromised token project can pass review, accumulate real conversions from third-party users (their tokens get pooled with the attacker's in the shared module-address escrow balance), and then self-destruct — destroying the shared collateral pool and leaving **all** holders of that coin denom (not just the attacker) holding permanently unbacked, still-spendable coins.

### Impact Explanation
This breaks the "Asset-representation path" invariant explicitly called out in scope: `x/erc20`, bank, and precompile-visible balances must preserve 1:1 accounting between native coins and ERC20 representations. The result is irreversible accounting corruption / unauthorized creation of spendable value: coins that are supposed to represent locked ERC20 collateral continue to circulate freely (can be transferred, used to pay fees, bridged out via IBC, etc.) after their collateral has been permanently destroyed, with no burn or freeze mechanism triggered by the deletion path. This matches the "Critical unauthorized minting/duplication/irreversible accounting corruption of spendable user value" impact category.

### Likelihood Explanation
Any unprivileged user can deploy an arbitrary ERC20 contract (mint-to-self + selfdestruct function), which is standard Solidity and requires no special privilege on the Cosmos EVM chain. The only prerequisite is getting the contract registered as a `TokenPair`, which is either fully permissionless (`PermissionlessRegistration=true`) or achievable via a single passed governance proposal (a realistic bar many chains meet for legitimate-looking tokens). No relayer, validator, or admin cooperation is required — the exploit is entirely a sequence of ordinary `MsgRegisterERC20`, `MsgConvertERC20`, and an EVM `SELFDESTRUCT` call, followed by any subsequent `ConvertERC20`/`ConvertCoin` call (by anyone) that triggers the `DeleteTokenPair` path.

### Recommendation
Before allowing `DeleteTokenPair` to be invoked for a self-destructed contract, the keeper must check `bankKeeper.GetSupply(ctx, pair.Denom)` (or track escrowed balance explicitly) and only proceed if the outstanding supply is zero; otherwise it should either (a) reject the deletion and leave the pair frozen/disabled to prevent further conversions while flagging the shortfall for governance resolution, or (b) atomically burn/write off the corresponding outstanding native coin supply as part of the deletion so total supply and locked collateral stay reconciled. Additionally, consider disabling further `ConvertERC20` mints for a token pair once total escrowed balance can no longer be verified live against the contract (e.g., periodically or on toggle), and emit an event/alert so the discrepancy cannot occur silently.

### Proof of Concept
1. Attacker deploys `MaliciousERC20` with a `mint(address,uint256)` function (self-mint) and a `kill()` function that calls `selfdestruct`.
2. Attacker (or, if `PermissionlessRegistration=true`, directly; otherwise via a passed governance proposal) calls `MsgRegisterERC20` for `MaliciousERC20`, creating a `TokenPair` (`x/erc20/keeper/msg_server.go:324-362`, `x/erc20/keeper/proposals.go:16-42`).
3. Attacker mints `1,000,000` tokens to themselves, then calls `MsgConvertERC20` to escrow all `1,000,000` tokens into `types.ModuleAddress` and mint `1,000,000` of the corresponding native Cosmos coin to their own account (`x/erc20/keeper/msg_server.go:71-188`).
4. Attacker calls `kill()` in the same or later transaction, triggering `SELFDESTRUCT` → `x/vm/keeper/statedb.go` `DeleteAccount` wipes the contract's code, storage, and balance (including the module's escrowed `1,000,000` token balance) and removes the auth account entirely (`x/vm/keeper/statedb.go:243-295`).
5. Attacker (or anyone) submits a trivial follow-up `MsgConvertERC20`/`MsgConvertCoin` referencing the pair; the keeper detects `acc == nil || !acc.HasCodeHash()` and calls `DeleteTokenPair`, erasing the pair with no supply check (`x/erc20/keeper/msg_server.go:42-53`, `208-220`; `x/erc20/keeper/token_pairs.go:110-117`).
6. The attacker still holds `1,000,000` fully valid, transferable, spendable native Cosmos coins with zero remaining ERC20 collateral — an irreversible, unauthorized creation of spendable value.

func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

// DeleteAccount handles contract's suicide call:
// - clear balance
// - remove code
// - remove states
// - remove the code hash
// - remove auth account
func (k *Keeper) DeleteAccount(ctx sdk.Context, addr common.Address) error {
	cosmosAddr := sdk.AccAddress(addr.Bytes())
	acct := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	if acct == nil {
		return nil
	}

	// NOTE: only Ethereum contracts can be self-destructed
	if !k.IsContract(ctx, addr) {
		return errors.New("only smart contracts can be self-destructed")
	}

	// set account to a base account to set the whole balance as spendable
	baseAccount := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	k.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(cosmosAddr, baseAccount.GetPubKey(), baseAccount.GetAccountNumber(), baseAccount.GetSequence()))

	// clear balance
	if err := k.SetBalance(ctx, addr, new(uint256.Int)); err != nil {
		return err
	}

	var keys []common.Hash

	// clear storage
	k.ForEachStorage(ctx, addr, func(key, _ common.Hash) bool {
		keys = append(keys, key)
		return true
	})

	for _, key := range keys {
		k.DeleteState(ctx, addr, key)
	}

	// clear code hash
	k.DeleteCodeHash(ctx, addr)

	// remove auth account
	k.accountKeeper.RemoveAccount(ctx, acct)

	k.Logger(ctx).Debug(
		"account suicided",
		"ethereum-address", addr.Hex(),
		"cosmos-address", cosmosAddr.String(),
	)

	return nil
}
