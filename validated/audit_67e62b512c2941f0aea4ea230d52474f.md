Based on my investigation, I found a directly analogous bug class in the mempool's CLVM canonical-encoding checker, which mirrors the libredwg bug: an untrusted length/count field is used to advance an offset into a buffer without validating that the buffer actually has that many remaining bytes, producing an out-of-bounds read.

### Title
Out-of-bounds buffer read in CLVM canonical-encoding checker via attacker-controlled length prefix - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a CLVM atom's length prefix and advance `offset` by the decoded `atom_len` without ever checking that `offset`/`atom_len` stay within the bounds of `clvm_buffer`. This is the same bug class as CVE-2023-26157 (libredwg reading `section->num_pages` from untrusted input and using it to index without a bounds check), just in Python: a crafted length prefix causes a read past the end of the buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the length-prefix byte(s) directly from `clvm_buffer[offset]` in a loop keyed by `prefix_len` [1](#0-0) , and returns `1 + prefix_len + atom_len` as the new offset without validating `atom_len` against `len(clvm_buffer) - offset`. The caller, `is_clvm_canonical()`, uses that returned length to advance its own `offset` and then unconditionally re-indexes `clvm_buffer[offset]` on the next loop iteration [2](#0-1) . If a submitted solution/program encodes an atom whose declared length exceeds the number of bytes actually remaining in the buffer, `offset` will be advanced past `len(clvm_buffer)`, and the very next `clvm_buffer[offset]` access reads out of bounds (in Python this raises `IndexError` rather than corrupting memory, but it is the same missing-bounds-check root cause: a size field taken from untrusted bytes is trusted to index/advance through a buffer with no `offset < len(buf)` / `atom_len <= remaining` check, exactly as `num_pages` was trusted in `decode_r2007.c`).

### Impact Explanation
If this exception is not caught somewhere between the untrusted CLVM buffer entry point and this function, a single maliciously crafted coin spend's solution/puzzle bytes can raise an unhandled `IndexError` during mempool processing of a submitted spend bundle, potentially halting or crashing the transaction-processing task that inspects the bundle for eligibility (fast-forward/dedup canonical-encoding checks). This matches the required impact class ("a spend-triggered transaction-processing halt") if reachable and unguarded — but this is contingent on confirming the exact call path and whether it's wrapped in exception handling, which I could not fully verify in the time available.

### Likelihood Explanation
The length-prefix decoding logic has no defensive check anywhere in the function bodies shown, so triggering the out-of-bounds index only requires crafting a CLVM atom whose length-prefix bits claim more bytes than remain in the buffer — a trivial, deterministic construction requiring no special privileges, only the ability to submit a spend bundle whose solution is inspected by this code path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` (validate `offset + prefix_len < len(clvm_buffer)` before reading prefix bytes, and validate `atom_len <= len(clvm_buffer) - offset - 1 - prefix_len`) and in `is_clvm_canonical()`'s main loop (validate `offset < len(clvm_buffer)` before every `clvm_buffer[offset]` access), returning/raising a well-defined, caught error (e.g. treat as non-canonical / reject the bundle) rather than allowing an unhandled `IndexError` to propagate, mirroring the bounds checks already present in `chia/full_node/full_block_utils.py`'s `skip_list`/`skip_bytes` helpers [3](#0-2) .

### Proof of Concept
Construct a `clvm_buffer` whose first atom uses the "5+8 bits length prefix" form (`0xC0`-`0xDF` leading byte) but is truncated immediately after the leading byte, e.g. `bytes([0xC0])` (a single byte, claiming a 1-byte extra length prefix that is missing) or `bytes([0xC0, 0xFF])` (claims `atom_len` far larger than the remaining buffer). Calling `is_clvm_canonical(buf)` with such input drives `is_atom_canonical()`/`is_clvm_canonical()` to compute an `offset` beyond `len(buf)` and then index `clvm_buffer[offset]`, raising `IndexError` [4](#0-3) [5](#0-4) .

**Note on confidence:** I could not, within the available iterations, locate and confirm the exact call site(s) that pass attacker-controlled coin-spend solution bytes into `is_clvm_canonical()` during spend-bundle admission, nor whether that call is wrapped in exception handling that would downgrade this to a harmless rejection rather than an unhandled crash. This should be verified (e.g., via `grep` for all callers of `is_clvm_canonical` in `mempool_manager.py` and tracing whether they run inside a try/except during `add_spend_bundle`/pre-validation) before treating this as a confirmed exploitable DoS.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
