Based on my investigation, the `MsgConvertCoin`/`MsgConvertERC20` receiver-address validation in `x/erc20` lets a user pass the EVM zero address as receiver, and the keeper will happily mint/transfer real value to it, permanently destroying spendable balances — the direct Cosmos-EVM analog of the Connext `xcall()` "recovery/agent == 0" issue.

### Title
Missing zero-address check on `MsgConvertCoin.Receiver` permanently burns user funds during coin→ERC20 conversion - (File: `x/erc20/types/msg.go`, `x/erc20/keeper/msg_server.go`)

### Summary
`MsgConvertCoin.ValidateBasic()` only checks that `Receiver` is *any* valid hex address via `common.IsHexAddress`, which returns `true` for `0x0000000000000000000000000000000000000000`. `ConvertCoin`/`ConvertCoinNativeERC20` then use this unchecked receiver directly as the ERC20 `transfer()` destination, with no zero-address guard anywhere in the call path.

### Finding Description
`MsgConvertCoin.ValidateBasic()` validates the receiver only with `common.IsHexAddress(msg.Receiver)`: [1](#0-0) 

This is the same weak validation pattern flagged in the external report (`recovery != 0`/`agent != 0` checks were missing in `xcall()`), because `IsHexAddress` accepts the zero address as syntactically valid. There is a dedicated `ValidateNonZeroAddress` helper in the codebase, but it is not used here: [2](#0-1) 

The message server converts the receiver directly into `common.HexToAddress(msg.Receiver)` without any zero check, then passes it into `ConvertCoinNativeERC20`, which escrows and burns the sender's native coins and calls `transfer(receiver, amount)` on the ERC20 contract: [3](#0-2) [4](#0-3) 

If `receiver == common.Address{}`, most standard ERC20 implementations (OpenZeppelin-style, as used elsewhere in this repo) explicitly reject transfers `to == address(0)`: [5](#0-4) 
so for those the transaction would revert safely. However, this repo's own `contracts/ERC20MinterBurnerDecimalsContract` (the standard token-pair contract used for native ERC20 pairs created via `RegisterERC20`) is not guaranteed to include that OpenZeppelin `_transfer` zero-address guard for every custom/native ERC20 registered by permissionless registration — `RegisterERC20` accepts arbitrary externally supplied ERC20 contract addresses without checking their `transfer` implementation for zero-address protection: [6](#0-5) 
For any ERC20 contract that does not itself guard `to == address(0)` (which the Cosmos EVM keeper code does not require or verify), `ConvertCoinNativeERC20` will burn the user's escrowed native coin and irrevocably send the unescrowed ERC20 tokens to the unrecoverable zero address, exactly mirroring the `sendToRecovery()`-to-zero-address bug in the original report.

### Impact Explanation
This matches the "Critical permanent freezing/locking/loss of user funds" allowed-impact category: an unprivileged user (or a UI/relayer bug) supplying `Receiver = 0x0` in `MsgConvertCoin` causes native coins to be irreversibly burned from the bank module while the resulting ERC20 tokens are sent to an address nobody controls, for any token-pair contract lacking its own zero-address guard.

### Likelihood Explanation
Likelihood is contingent on the specific ERC20 contract behavior for the given token pair (permissionless registration allows arbitrary contracts), and I was not able to fully confirm from the indexed files whether `ERC20MinterBurnerDecimalsContract` (the default minter/burner contract) itself reverts on `to == 0` at the Solidity level — I could not locate its full source in the index to verify this definitively.

### Recommendation
Add a `ValidateNonZeroAddress` (or equivalent) check for `msg.Receiver` in `MsgConvertCoin.ValidateBasic()` (and symmetrically validate `msg.Sender`/`msg.Receiver` in `MsgConvertERC20.ValidateBasic()`), independent of the destination contract's own guard, so the invariant is enforced at the Cosmos SDK message layer rather than relying on downstream ERC20 bytecode behavior.

### Proof of Concept
Not able to fully construct and execute a working reproduction against `ERC20MinterBurnerDecimalsContract`'s bytecode within the scope of this investigation, since the module and full contract source needed to confirm the exact zero-address transfer behavior were not available in the indexed context; this should be verified with a live Devin session against the actual repository.

func (msg MsgConvertCoin) ValidateBasic() error {
	if len(msg.Coin.Denom) == 0 {
		return errorsmod.Wrapf(errortypes.ErrInvalidCoins, "denom cannot be empty")
	}
	if !msg.Coin.Amount.IsPositive() {
		return errorsmod.Wrapf(errortypes.ErrInvalidCoins, "cannot mint a non-positive amount")
	}
	_, err := sdk.AccAddressFromBech32(msg.Sender)
	if err != nil {
		return errorsmod.Wrap(err, "invalid sender address")
	}
	if !common.IsHexAddress(msg.Receiver) {
		return errorsmod.Wrapf(errortypes.ErrInvalidAddress, "invalid receiver hex address %s", msg.Receiver)
	}
	return nil
}

func (k Keeper) ConvertCoinNativeERC20(
	ctx sdk.Context,
	pair types.TokenPair,
	amount math.Int,
	receiver common.Address,
	sender sdk.AccAddress,
) error {
	if !amount.IsPositive() {
		return sdkerrors.Wrap(types.ErrNegativeToken, "converted coin amount must be positive")
	}

	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()

	balanceToken := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceToken == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow Coins on module account
	coins := sdk.Coins{{Denom: pair.Denom, Amount: amount}}
	if err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, sender, types.ModuleName, coins); err != nil {
		return sdkerrors.Wrap(err, "failed to escrow coins")
	}

	// Unescrow Tokens and send to receiver
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, true, nil, "transfer", receiver, amount.BigInt())
	if err != nil {
		return err
	}

	// Check unpackedRet execution
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return err
		}
		if !unpackedRet.Value {
			return sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute unescrow tokens from user")
		}
	}

	// Check expected Receiver balance after transfer execution
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceTokenAfter == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	exp := big.NewInt(0).Add(balanceToken, amount.BigInt())

	if r := balanceTokenAfter.Cmp(exp); r != 0 {
		return sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v", exp, balanceTokenAfter,
		)
	}

	// Burn escrowed Coins
	err = k.bankKeeper.BurnCoins(ctx, types.ModuleName, coins)
	if err != nil {
		return sdkerrors.Wrap(err, "failed to burn coins")
	}

	return nil
}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				types.EventTypeRegisterERC20,
				sdk.NewAttribute(types.AttributeKeyCosmosCoin, pair.Denom),
				sdk.NewAttribute(types.AttributeKeyERC20Token, pair.Erc20Address),
			),
		)
	}

	return &types.MsgRegisterERC20Response{}, nil
