### Title
Payout attribution (`OP_RETURN` operator key) is unauthenticated and unbound by the withdrawal signature, allowing anyone to credit an arbitrary operator with a payout it never funded - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The reimbursement pipeline attributes a Bitcoin withdrawal ("payout") to an operator solely by reading an `OP_RETURN` output that anyone constructing the transaction can set to any x-only public key, and by identifying "the" payout transaction purely as whichever transaction happens to spend the committed withdrawal UTXO. Neither of these facts is bound by the user's withdrawal authorization signature, so any unprivileged party who learns the user's `SinglePlusAnyoneCanPay` payout signature (which is not a bridge secret — it is exchanged off-chain with any operator, and the only output/amount it commits to is the user's own payout output) can build and broadcast a rival payout transaction that fronts the withdrawal itself but embeds an arbitrary operator's x-only public key in the `OP_RETURN`. The bridge then treats that operator as having fronted the payout, entitling it to reimbursement it never funded, or denying the real fronting operator its own reimbursement route.

### Finding Description
`create_payout_txhandler` builds the payout transaction with the user's committed input, the user's payout output, an anchor output, and an `OP_RETURN` output carrying `operator_xonly_pk`: [1](#0-0) 

The only thing cryptographically checked against the user is the signature over input index 0, using sighash type `SinglePlusAnyoneCanPay`: [2](#0-1) 

`SIGHASH_SINGLE | ANYONECANPAY` commits only to the single input being spent and the single output at the same index (the user's payout output). It does **not** commit to the anchor output or, critically, the `OP_RETURN` output that names the crediting operator. This means any party who has the user's payout outpoint and signature (exchanged off-chain to operators, and derivable from the publicly registered Citrea withdrawal parameters) can construct their own version of the payout transaction — reusing the exact same signed input/output pair required by the signature — while freely choosing the `OP_RETURN` payload (any operator's `xonly_pk`), adding their own funding inputs (permitted by `ANYONECANPAY`), and broadcasting it themselves.

On Citrea sync, the verifier identifies "the" payout transaction purely by which transaction spends the withdrawal UTXO outpoint recorded in the `withdrawals` table, with no check that the party who signed/broadcast it is the same as the operator named in the `OP_RETURN`: [3](#0-2) 

The operator identity is then extracted purely from the `OP_RETURN` bytes of whatever transaction won that race: [4](#0-3) 

Downstream, this operator attribution is used, unquestioned, as the trigger for the entire reimbursement flow: `PayoutCheckerTask` looks up the "first unhandled payout" keyed by `payout_payer_operator_xonly_pk` and calls `handle_finalized_payout` for that operator: [5](#0-4) 

`validate_payer_is_operator` only checks that the *stored* payer key equals the operator's own key — it has no way to know whether that operator actually funded the on-chain spend: [6](#0-5) 

`is_kickoff_malicious` similarly only compares the stored (attacker-controllable) `OP_RETURN` key against the kickoff's operator key, never against who actually paid: [7](#0-6) 

The reimbursement itself pays the full deposited amount to `operator_reimbursement_address` based on this same operator identity, with no other cross-check against the payer: [8](#0-7) 

This is the same missing-binding bug class as the auction "self-bid" report: there, `_placeBidOnAuction` failed to verify the bidder role was distinct from the owner role even though both actions funnel through the same function; here, the protocol fails to verify that the "operator who fronted the payout" (as declared, unauthenticated, in `OP_RETURN`) is the same party whose funds actually left the withdrawal UTXO — the binding `operator credited == party that paid` is never enforced.

### Impact Explanation
This breaks the Critical-severity binding explicitly called out for this class: "an operator reimbursed for a payout it never funded." An unprivileged attacker (no operator/verifier/watchtower role required) who can observe or obtain the user's `SinglePlusAnyoneCanPay` withdrawal signature can front the withdrawal from their own funds while naming a chosen operator in `OP_RETURN`. That operator will subsequently be credited by the bridge's Citrea-sync bookkeeping and become eligible to run the reimbursement flow (kickoff → challenge-timeout → reimburse) to receive the deposited bridge funds from `move_to_vault`, despite never having spent anything to satisfy the withdrawal. This can also be used to grief: naming an operator that is not actually participating/available for that deposit locks the withdrawal's attribution to a payer identity that can never legitimately complete the reimbursement path, effectively freezing the deposit's normal reimbursement route (since `get_first_unhandled_payout_by_operator_xonly_pk` and `validate_payer_is_operator` gate the entire flow on this single, forgeable field).

### Likelihood Explanation
Exploitability only requires knowledge of the user's off-chain-shared payout signature and outpoint (already exchanged to any operator, and mirrored in the on-chain Citrea withdrawal event data model) plus the ability to broadcast a standard Bitcoin transaction — no special role, key compromise, or protocol privilege is needed. The race is won by whoever gets a spend of the withdrawal outpoint confirmed first; since the signature does not bind the `OP_RETURN`, constructing a competing transaction is straightforward.

### Recommendation
Bind the operator-attribution `OP_RETURN` output to the withdrawal authorization the same way the payout output is bound — e.g., have the user's signature use `SIGHASH_ALL` (or otherwise explicitly commit to the `OP_RETURN` output) so the fronting operator's identity cannot be substituted, or require the operator's own signature/co-signature over the full payout transaction (including `OP_RETURN`) before Citrea-sync attribution accepts it as that operator's payout.

### Proof of Concept
1. User registers a withdrawal on Citrea; the withdrawal outpoint, output script/amount, and the user's `SinglePlusAnyoneCanPay` signature become available (they are shared off-chain with operators and mirrored in Citrea withdrawal parameters used to build `WithdrawParams`).
2. Attacker (not an operator) constructs a transaction spending the same withdrawal outpoint with: (a) output 0 identical to the committed user payout (satisfying the `SIGHASH_SINGLE|ANYONECANPAY` signature check in `create_payout_txhandler`/`withdraw`), (b) an `OP_RETURN` output naming Operator B's `xonly_pk` (chosen arbitrarily, not Operator B's doing), and (c) attacker-funded additional inputs for fees (allowed by `ANYONECANPAY`).
3. Attacker broadcasts and gets this transaction confirmed before Operator B (or any operator) submits its own payout.
4. During Citrea sync, `update_finalized_payouts` records Operator B as `payout_payer_operator_xonly_pk` for this withdrawal solely from the forged `OP_RETURN`.
5. `PayoutCheckerTask`/`validate_payer_is_operator` treat Operator B as the legitimate payer and proceed through kickoff/reimbursement, ultimately paying the deposited funds to Operator B's `operator_reimbursement_address` even though Operator B never funded the withdrawal.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
