### Title
Gasless Swap Repayment Is Fixed at Declared Gas Limits Rather Than Actual Gas Used, So Overpaid Amount Is Never Refunded to the User - (File: kaiax/gasless/impl/getter.go)

### Summary
The gasless-transaction module (KIP-247) forces a `swapForGas` sender to repay a token amount computed purely from the **declared gas limits** of the bundled transactions, not from the gas actually consumed during execution. Like the `IB_Champions.safeMint()` bug where `msg.value` above the required price is silently kept by the contract instead of being refunded, the gasless-swap flow silently keeps the difference between the gas the user is charged for and the gas actually spent, with no mechanism to return the excess to the user.

### Finding Description
A gasless swap transaction pair (optional `ApproveTx` + `SwapTx`) is validated by `VerifyExecutable`, which requires `swapArgs.AmountRepay` to exactly equal `repayAmount(approveTxOrNil, swapTx)`: [1](#0-0) 

`repayAmount` and its helper `lendAmount` compute the amount the user must repay using the **gas limits and gas prices declared in the transactions themselves** — `approveTxOrNil.Fee()`, `swapTx.Fee()`, and a fixed `params.TxGas` allowance for the lend transaction — not the gas that is actually consumed on execution: [2](#0-1) 

`checkBalanceForSwap` only enforces `minAmountOut >= amountRepay` and that the user has enough token balance/allowance; it never checks or reconciles the fixed repay amount against actual gas usage: [3](#0-2) 

At block-building time, `ExtractTxBundles`/`GetLendTxGenerator` prepends a `LendTxGenerator` transaction that funds the sender with exactly the `lendAmount` in native KAIA so the bundled `ApproveTx`/`SwapTx` can pay gas, then the user's `SwapForGas` call repays `amountRepay` in ERC20 tokens back through the router: [4](#0-3) 

Because `repayAmount` is derived from `GasLimit * GasPrice` (the transaction's declared fee ceiling) rather than `GasUsed * GasPrice`, any transaction that completes using less gas than its `GasLimit` (a very common case — `TxGas` legacy transfer, ERC20 approve/swap calls rarely consume 100% of their gas limit) results in the user being charged, in tokens, for gas it never actually consumed. The overcharged token value flows to the router's swap output and is split between commission and "FinalUserAmount" per the `SwappedForGas` event, but the leftover **native KAIA gas differential** (the unused portion of `GasLimit` that a normal EVM state transition would refund to whoever paid for gas) is never returned to the user who funded the repayment — it accrues to the proposer/lend flow instead.

### Impact Explanation
Every unprivileged sender who submits a KIP-247 gasless swap systematically overpays for gas by the gap between `GasLimit` and `GasUsed`, and that excess value is permanently unrecoverable by the user — the same "loss of funds due to missing refund" root cause as the referenced report, but reachable via ordinary public transaction submission rather than a privileged/admin path. This is a repeatable value-extraction bug affecting any gasless swap user, not a one-off accounting error, and the amount lost scales with transaction volume, justifying Medium severity per the value-movement/fee-abuse acceptance criteria.

### Likelihood Explanation
High likelihood: any account with zero KAIA balance that uses the standard gasless UX (the intended entry point for KIP-247) triggers this path on every swap, since `GasLimit != GasUsed` is the normal case for EVM calls (ERC20 `approve`/`transferFrom`/DEX swap paths practically never use exactly their full gas limit).

### Recommendation
Compute `repayAmount` from the **actual gas used** by the bundled `LendTxGenerator`/`ApproveTx`/`SwapTx` (post-execution receipts) rather than their declared `GasLimit`, or add an explicit refund step that returns the unused-gas-equivalent value (in KAIA or token) to the user after the bundle executes, mirroring the CEI-pattern refund recommended for `safeMint()`.

### Proof of Concept
1. User with 0 KAIA submits `ApproveTx` (gasLimit `G_a`) + `SwapTx` (gasLimit `G_s`) for a gasless swap.
2. `repayAmount = R1 + G_a*gasPrice + G_s*gasPrice` (per `lendAmount`/`repayAmount` in `kaiax/gasless/impl/getter.go:346-367`), computed from declared gas limits.
3. Actual execution consumes `usedGas_a < G_a` and `usedGas_s < G_s` (typical for ERC20 approve/swap).
4. `checkBalanceForSwap` only validates `AmountRepay == repayAmount(...)` computed from gas limits (`kaiax/gasless/impl/tx_pool.go:102-121`), so the swap proceeds and the user's tokens are debited for the full gas-limit-based amount.
5. The difference `(G_a - usedGas_a + G_s - usedGas_s) * gasPrice` worth of value is never credited back to the user — no refund path exists in `builder.go`/`getter.go`.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
