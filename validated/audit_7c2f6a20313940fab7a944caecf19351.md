### Title
`WombatStaking.depositLP` mints receipt tokens 1:1 for `_lpAmount` without verifying actual LP tokens received, breaking accounting for fee-on-transfer/deflationary LP tokens - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.depositLP()` transfers `_lpAmount` of the wombat pool LP token from the user and then mints exactly `_lpAmount` of receipt token and stakes `_lpAmount` into the master wombat accounting, without checking the actual amount of LP tokens the contract received from the transfer.

### Finding Description
In `WombatStaking.sol`, `deposit()` correctly measures the actual LP tokens obtained by diffing balances before/after the external pool deposit call: [1](#0-0) 

However, the sibling function `depositLP()`, used by `WombatPoolHelper`/`WombatPoolHelperV2`/`AnkrBNBPoolHelper` (`depositLP`) to allow users to directly stake existing LP tokens, does not perform this check. It transfers `_lpAmount` from `_for` and then immediately uses the pre-transfer `_lpAmount` value both to update master-wombat-side accounting via `_toMasterWomAndSendReward` and to mint receipt tokens: [2](#0-1) 

If `poolInfo.lpAddress` (the wombat pool LP/asset token) were ever a token with a transfer fee, rebase-down, or any deflationary transfer behavior, `IERC20(poolInfo.lpAddress).balanceOf(address(this))` would increase by less than `_lpAmount` after the `safeTransferFrom` call, yet the contract still mints `_lpAmount` of receipt tokens to the caller and credits `_lpAmount` toward `_toMasterWomAndSendReward` (staking into the underlying master wombat contract). This creates receipt tokens that are not fully backed by custodied/staked LP tokens.

### Impact Explanation
Over-minting receipt tokens relative to actual LP custody directly causes protocol insolvency: total minted receipt tokens (and corresponding pool-helper balances tracked in `BaseRewardPool`) would exceed the real LP balance staked with master wombat. When later users attempt to withdraw via `WombatPoolHelper.withdraw()` → `WombatStaking.withdraw()`, the pool would be unable to honor all receipt-token holders' claims, leading to loss/freezing of funds for some users. This satisfies the "protocol insolvency" / "permanent freezing of funds" bar.

### Likelihood Explanation
Likelihood depends entirely on whether any wombat pool's LP/asset token whitelisted via `addPool`/pool configuration ever exhibits fee-on-transfer or deflationary transfer semantics. Standard Wombat `Asset` LP tokens are plain ERC20 mint/burn tokens without transfer fees today, so under the current known token set this is not exploitable. The `deposit()` function in the same contract already defensively uses the before/after balance-diff pattern, showing the developers considered this token-behavior class important for LP-token accounting, but the pattern was not consistently applied to `depositLP()`, leaving it exposed to the same class of token if such a pool is ever added.

### Recommendation
Apply the same before/after balance-diff pattern used in `deposit()` to `depositLP()`: measure `poolInfo.lpAddress` balance before and after the `safeTransferFrom`, and use the actual received amount (not the requested `_lpAmount`) for both `_toMasterWomAndSendReward` and the receipt-token mint amount.

### Proof of Concept
1. Assume/whitelist a wombat pool whose `lpAddress` token charges a transfer fee (e.g., burns 1% on each transfer).
2. User calls `WombatPoolHelper.depositLP(1000)` → `WombatStaking.depositLP(lpAddress, 1000, user)`.
3. `IERC20(lpAddress).safeTransferFrom(user, address(this), 1000)` only credits the staking contract 990 tokens due to the transfer fee.
4. Despite this, `_toMasterWomAndSendReward(lpAddress, 1000, true)` and `IMintableERC20(receiptToken).mint(msg.sender, 1000)` both use the full `1000` figure.
5. Receipt token supply and internal master-wombat-side accounting are now inflated by 10 tokens relative to actual custodied/staked LP, compounding with every deposit and ultimately preventing later withdrawals from being fully honored.

    function depositLP(
        address _lpAddress,
        uint256 _lpAmount,
        address _for
    ) nonReentrant whenNotPaused _onlyActivePoolHelper(_lpAddress) external {
        // Get information of the Pool of the token
        Pool storage poolInfo = pools[_lpAddress];

        // Transfer lp to this contract and stake it to wombat
        IERC20(poolInfo.lpAddress).safeTransferFrom(_for, address(this), _lpAmount);

        _toMasterWomAndSendReward(_lpAddress, _lpAmount, true); // triggers harvest from wombat exchange
        IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount);

        emit NewLPDeposit(_for, poolInfo.lpAddress, _lpAmount, poolInfo.receiptToken, _lpAmount);
    }
