### Title
Server-Side Request Forgery via unauthenticated DataLayer mirror coins — `chia/data_layer/data_layer_wallet.py::coin_added` / `chia/data_layer/data_layer.py::fetch_and_validate`

### Summary
Any unprivileged spend-bundle submitter can create an on-chain coin that DataLayer nodes interpret as a "mirror" record for an arbitrary, already-known store id, embedding attacker-chosen URLs. DataLayer's periodic subscription/fetch loop later issues outbound HTTP GET (and, if downloader plugins are configured, HTTP POST) requests to those attacker-controlled URLs — a textbook SSRF, directly analogous to CVE-2021-30108 where server-side requests are driven by unauthenticated, attacker-supplied input.

### Finding Description
`DataLayerWallet.coin_added()` watches for any coin whose puzzle hash equals `create_mirror_puzzle().get_tree_hash()` (`MIRROR_PUZZLE_HASH`) [1](#0-0) . This is not restricted to coins created by the local wallet's own `add_mirror` flow — it fires for *any* on-chain coin matching that puzzle hash, regardless of who created it. It decodes `launcher_id` and a list of `urls` straight from the parent coin's spend memos via `get_mirror_info()` [2](#0-1) , and as long as the wallet already tracks that `launcher_id` (which is public on-chain information, not a secret), it persists the attacker-supplied URLs into `dl_store` via `add_mirror()` [3](#0-2) .

The DataLayer service then trusts these URLs as legitimate mirror endpoints: `update_subscriptions_from_wallet()` pulls all mirror URLs for a store and feeds them into local subscription state [4](#0-3) . During the periodic `update_subscription()` → `fetch_and_validate()` loop, the service iterates these server URLs and calls `insert_from_delta_file()` / `download_file()` / `http_download()`, which performs `session.get(server_info.url + "/" + filename, ...)` with no scheme/host allow-list or private-network blocklist [5](#0-4) [6](#0-5) . If a downloader plugin is configured, `get_downloader()` additionally POSTs the attacker URL plus store id to the plugin [7](#0-6) . No code in the DataLayer module validates or restricts mirror URLs (`grep` for scheme/host/private-IP checks in `chia/data_layer/*.py` returns nothing relevant to mirror handling).

### Impact Explanation
An attacker only needs to know a public `launcher_id` (store id) that a target node already tracks (owned or subscribed) and spend a minimal-value coin to the well-known mirror puzzle hash with a memo containing that launcher id and arbitrary URLs. This forces the victim's DataLayer service to make outbound HTTP requests — potentially against internal-only hosts, cloud metadata endpoints (e.g. `169.254.169.254`), or other network-restricted services reachable from the DataLayer process — entirely at attacker's chosen timing and target. This is a real SSRF affecting any Data Layer client, satisfying the reachable-actor and impact requirements (server-triggered request to attacker-controlled destination).

### Likelihood Explanation
Likelihood is high: creating a coin with the mirror puzzle hash and arbitrary memo URLs requires no special privilege beyond funding a low-value coin and a fee, and the `launcher_id` needed is not secret — it is a public store identifier. The victim doesn't need to run `add_mirror` themselves; simply already tracking the launcher (as owner or subscriber) is sufficient for `coin_added()` to ingest the malicious mirror record automatically.

### Recommendation
- Validate/restrict mirror and subscription URLs before persisting or using them: enforce an allow-list of schemes (e.g. `https` only), reject loopback/link-local/private-network hosts (SSRF blocklist), and consider requiring explicit user confirmation (e.g. via `add_mirror` RPC only) rather than automatically ingesting URLs observed purely from on-chain coin memos in `coin_added()`.
- Apply the same URL validation in `download_file()`/`http_download()`/`get_downloader()` in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py` before issuing outbound requests.
- Consider requiring some proof of authorization (e.g., mirror coin must be spent by/for the store's actual owner) before trusting mirror URLs for a launcher, instead of trusting any coin matching `MIRROR_PUZZLE_HASH` with a tracked `launcher_id`.

### Proof of Concept
1. Note any public DataLayer store's `launcher_id` that the victim node tracks (owned or subscribed store; discoverable via `dl_owned_singletons`/`dl_history` RPCs or public chain data).
2. Craft and submit a spend bundle that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` (`P2_PARENT.curry(1)`), with `CREATE_COIN` memos of the form `[launcher_id, url1, url2, ...]` where `url1` = `http://169.254.169.254` or an internal-only test endpoint the attacker controls for logging.
3. Wait for the block to confirm; the victim's `DataLayerWallet.coin_added()` ingests the mirror record since `launcher_id` is tracked.
4. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` adds the attacker URL as a subscription server, and `fetch_and_validate()`/`http_download()` issues an HTTP GET to the attacker-controlled/internal URL — confirmable by observing the request landing at the attacker's listener or by observing internal service access logs.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
        Add a mirror coin to the DB
        """

        async with self.db_wrapper.writer_maybe_transaction() as conn:
            await conn.execute_insert(
                "INSERT OR REPLACE INTO mirrors VALUES (?, ?, ?, ?, ?)",

                    mirror.amount.stream_to_bytes(),
                    b"".join(
                        [uint16(len(url)).stream_to_bytes() + url for url in Mirror.encode_urls(mirror.urls)]
                    ),  # prefix each item with a length
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
