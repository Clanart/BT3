### Title
Dust outputs sent to a scanned address are reported as received yet are economically (or outright) unspendable - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to JUSDBank's `maxDepositAmountPerAccount` grief (an unprivileged party's 1-wei deposit forcing a victim's operation to fail), any unprivileged party can send dust-valued Bitcoin outputs to the Serai wallet's `script_pubkey`. `Scanner::scan_transaction` matches solely on `output.script_pubkey`, so every such output is returned as a `ReceivedOutput` indistinguishable from legitimate deposits [1](#0-0) . `SignableTransaction::new` only enforces `DUST` (546 sats) on *payments*, never on *inputs* [2](#0-1) , so dust inputs are accepted as spendable funds. Each input adds ~68 vbytes of fee cost [3](#0-2) ; a dust input's value is less than the fee required to spend it, and a flood of them pushes any transaction attempting to sweep them over `MAX_STANDARD_TX_WEIGHT`, returning `TooLargeTransaction` [4](#0-3) .

### Finding Description
`Scanner` keys `scripts` by `ScriptBuf` and reports any transaction output paying to a registered offset's P2TR script as a `ReceivedOutput`, with no minimum-value check [5](#0-4) . `ReceivedOutput` carries only `offset`, `output`, and `outpoint` — no spendability marker [6](#0-5) . When constructing a spend, `SignableTransaction::new` sums all provided input values, deducts `payment_sat + needed_fee`, and errors `NotEnoughFunds` or `TooLargeTransaction` if the dust-bloated input set can't cover its own fee or exceeds standard weight [7](#0-6) . There is no filtering of inputs whose value is below the marginal fee they add, and no cap on how many attacker-created outputs land in the wallet's UTXO set.

### Impact Explanation
Funds are reported received that are not (economically) spendable: each dust output below ~68 sats × fee rate costs more to spend than it is worth, so the wallet's "received" balance overstates recoverable value. At scale, an attacker can grief spends: enough dust outputs force `NotEnoughFunds` (the inputs' aggregate value is consumed by their own fee) or `TooLargeTransaction`, blocking a transaction entirely — directly mirroring the JUSDBank forced-revert grief where an attacker causes the victim's deposit/spend to fail.

### Likelihood Explanation
Any unprivileged party can broadcast a Bitcoin transaction paying dust to the publicly known Serai `script_pubkey`. This requires no validator access, no leaked keys, and only trivial cost (dust amounts plus one tx fee), making it a realistic medium-severity griefing vector identical in shape to the source finding's 1-wei front-run.

### Recommendation
In `SignableTransaction::new` (or in the caller's input selection), skip/reject `ReceivedOutput`s whose `value()` is below the marginal fee an additional input contributes (≈ `fee_per_vbyte * input_vbytes`), and/or enforce a minimum deposit value at `Scanner` integration so dust outputs are never reported as spendable funds.

### Proof of Concept
```rust
// Attacker broadcasts a tx paying 100 outputs of 10 sats each to Serai's P2TR script.
// Scanner reports all 100 as ReceivedOutputs (mod.rs:199-214).
let inputs: Vec<ReceivedOutput> = scanner.scan_block(&block); // 100 x 10-sat inputs
// Each input adds ~68 vbytes; at 10 sat/vb the needed fee for inputs alone
// (~6800 sats) exceeds total input value (1000 sats):
let res = SignableTransaction::new(inputs, &[(payment_script, 1000)], None, None, 10);
// => Err(TransactionError::NotEnoughFunds { inputs: 1000, payments: 1000, fee: ~6800 })
// Or, with enough dust inputs, Err(TransactionError::TooLargeTransaction).
// The dust outputs were reported as received balance yet can never cover their own spend cost.
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
