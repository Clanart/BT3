### Title
FROST signing accepts identity nonce commitments, defeating the binding factor and enabling ROS-style parallel-session forgery - (File: crypto/frost/src/nonce.rs)

### Summary
The reported bug class is "a guard rejects the dangerous operation but leaves the capability bit set so the restriction can be bypassed later." `vmclock_miscdev_mmap()` rejected writable mappings with `-EROFS` yet left `VM_MAYWRITE`, allowing a later `mprotect()` upgrade. The Serai analog is in the FROST nonce-commitment path: `Commitments::read` enforces *canonical* point encodings via `C::read_G`, but never rejects the identity point. An attacker-supplied identity `E` commitment nullifies the per-participant binding factor `rho` (`bound = D + rho*E = D`), so the safety check that FROST's binding factor exists to provide — randomizing each signer's effective nonce per session — is silently disabled. That "capability left set" is exactly what enables the parallel-session (ROS/Wagner) forgery the binding factor was designed to prevent.

### Finding Description
`NonceCommitments::read` → `GeneratorCommitments::read` parses `D` and `E` with `C::read_G` (crypto/frost/src/nonce.rs:34-36), and `Ciphersuite::read_G` only checks canonicality (`to_bytes() == encoding`), accepting the identity element (crypto/ciphersuite/src/lib.rs:91-101). The resulting commitments flow into `BindingFactor::insert` (crypto/frost/src/sign.rs:345,356) and are bound in `BindingFactor::bound`/`nonces` as `generator.0[0] + (generator.0[1] * rho)` (crypto/frost/src/nonce.rs:187,206). When `E = identity`, the contribution is `D` regardless of `rho`. RFC 9591 requires nonce commitments to be valid non-identity group elements precisely because the binding factor is FROST's defense against ROS-style attacks; this implementation performs the canonical-encoding check but leaves the identity "writable" — i.e., the escape hatch open.

### Impact Explanation
A malicious participant in a FROST signing session submits a preprocess whose second commitment `E` is the identity point through `read_preprocess` → `Commitments::read`. Their effective nonce contribution becomes a fixed, `rho`-independent point `D` they choose. Across multiple concurrent signing sessions (which Serai's two-round protocol exposes via preprocess collection), the adversary's signature share `s = d + rho*e + lambda*c*x` degenerates to `s = d + lambda*c*x` with `d` fixed in advance, restoring the Wagner/ROS linear-algebra conditions the binding factor was introduced to break. This permits signature forgery against the threshold group key under parallel-session conditions — concrete signing of an unintended message.

### Likelihood Explanation
Requires the adversary to be an accepted participant in the signing set and to induce multiple concurrent signing sessions — both reachable in a coordinator-based multisig where preprocesses are gathered from untrusted counterparties. The read path (`read_preprocess` on attacker bytes) is explicitly in scope. Exploitation additionally needs enough parallel sessions for the ROS reduction; severity is High/Medium rather than Critical because honest participants' contributions remain bound, so the adversary must drive the concurrent-session structure themselves.

### Recommendation
Reject the identity point in `GeneratorCommitments::read` (crypto/frost/src/nonce.rs:34-36) — or centrally in `Commitments::read` — by checking `bool::from(point.is_identity())` after `C::read_G`, returning `io::Error`. This is the analogue of clearing `VM_MAYWRITE`: don't merely validate the encoding, remove the capability (identity) that bypasses the binding factor. Add a regression test feeding `Commitments` containing identity `D`/`E` through `read_preprocess` and asserting rejection.

### Proof of Concept
1. Instantiate `AlgorithmMachine` for any curve (e.g., `Secp256k1`, `Ristretto`) and obtain a `SignMachine`.
2. Craft a preprocess buffer where `commitments.nonces[0].generators[0] = (D, identity)`: write any valid `D` encoding, then the canonical identity encoding (e.g., all-zero compressed Ristretto point, or `0x00...` per the curve's `GroupEncoding`), followed by the addendum bytes.
3. Feed it to `machine.read_preprocess(&mut buf)` — it parses successfully because `read_G` only checks canonicality.
4. Call `sign(preprocesses, msg)`; `BindingFactor::bound(l)` returns `D` for that participant independent of `rho`. Repeating across concurrent sessions with distinct honest preprocesses yields the fixed-contribution precondition for the ROS forgery.

Uncertainty note: I verified the identity-acceptance path in source (`read_G`, `GeneratorCommitments::read`, `BindingFactor::bound`/`nonces`); I did not execute a full ROS forgery, and feasibility depends on the number of concurrent sessions an integration permits.
