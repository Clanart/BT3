### Title
Auto-refresh silently rewrites the local git remote URL to an untrusted host based on unvalidated GitHub API data - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`staleCheckLatestRoundData()` in the report trusts oracle data without confirming the upstream source (the sequencer) is still authentic/live. The Desktop analog is `updateRemoteUrl()`, which trusts the `clone_url` field of a `IAPIRepository` object returned from the GitHub API and uses it to silently overwrite the user's `origin` remote via `git remote set-url`, without validating that the new URL still points to the same host/endpoint as before.

### Finding Description
`updateRemoteUrl` is invoked automatically, without user interaction, from `repositoryWithRefreshedGitHubRepository` every time Desktop refreshes a repository's associated GitHub metadata: [1](#0-0) 

The function's guard logic only checks that:
1. The old and new remote URL use the same *protocol* (`https:` vs `https:`), and
2. The cached `gitHubRepository.cloneURL` still matches the current remote (i.e., the user hasn't manually changed it), and
3. The new URL differs from the current remote. [2](#0-1) 

Crucially, it never verifies that the new `clone_url`'s **hostname** matches the previous remote's hostname, nor that its owner/name are consistent with an expected, previously-trusted identity beyond a loose string comparison performed by `urlMatchesRemote`/`parseRemote`. If `protocolsMatch` and `remoteUrlUnchanged` are true and `urlsMatch` is false, `gitStore.setRemoteURL()` is called unconditionally with the API-supplied URL: [3](#0-2) 

This mirrors the oracle bug's broken invariant: a value fetched from an external, network-controlled source (`IAPIRepository.clone_url`, analogous to the Chainlink price feed) is trusted and immediately acted upon (rewriting the persisted git remote used for all future `fetch`/`push`) without an independent "liveness/authenticity" check equivalent to the sequencer-uptime check — here, a same-origin/host check.

### Impact Explanation
If the GitHub API response used to populate `apiRepo.clone_url` can be influenced (e.g., a compromised or malicious GitHub Enterprise Server endpoint the account is registered against, or any response path where the returned repository object's `clone_url` field does not match the previously known host), Desktop will silently retarget the user's `origin` remote to a different host. This corrupts what the user pushes and fetches going forward: subsequent `git push`/`git fetch` operations, and any credential negotiation tied to the remote's host, would be issued against the attacker-controlled host instead of the real one, entirely transparently to the user (no dialog, no diff shown, just a background remote rewrite). This falls squarely in the "silent corruption of what the user commits or pushes" and potential "credential exfiltration" impact categories described in the task's valid-impact list.

### Likelihood Explanation
The trigger path (`repositoryWithRefreshedGitHubRepository`) runs during routine, automatic background refresh of repository metadata — it does not require any unusual user action. The missing check is a straightforward oversight (protocol-only comparison instead of full origin comparison), so any code path that can make `api.fetchRepository()` return a `clone_url` with an unexpected hostname (while keeping the same scheme) would trigger the silent rewrite. I could not fully verify from the index whether Desktop's HTTPS credential injection (`envForRemoteOperation`, referenced in `app/src/lib/git/environment.ts`) restricts injected GitHub tokens strictly to the account's known endpoint hostname before this remote is used for the next `push`/`fetch` — this file's contents were not fully retrievable in this session, so the credential-exfiltration half of the impact should be treated as unconfirmed pending direct inspection of `app/src/lib/git/environment.ts`.

### Recommendation
In `updateRemoteUrl` (app/src/lib/stores/updates/update-remote-url.ts), before calling `gitStore.setRemoteURL`, additionally require that `parseRemote(updatedRemoteUrl)?.hostname` equals `parseRemote(remoteUrl)?.hostname` (or, more strictly, that it matches the endpoint associated with the `GitHubRepository`/account). Reject the update — and surface a warning to the user instead of silently rewriting — if the hostname changes.

### Proof of Concept
Conceptual reproduction based on the existing test harness for this function: [4](#0-3) 

1. User has `origin` set to `https://github.com/my-user/my-repo.git`, with `gitHubRepository.cloneURL` cached as the same URL.
2. Desktop's periodic refresh calls `api.fetchRepository(owner, name)`; suppose the response's `clone_url` is `https://evil-mirror.example/my-user/my-repo.git` (same `https:` protocol, different host) — achievable if the account's configured endpoint is compromised/malicious, or via any bug that lets the API-returned `clone_url` diverge in host from the expected endpoint.
3. `protocolsMatch` is `true` (both `https:`), `remoteUrlUnchanged` is `true` (cache still matches old remote), `urlsMatch` is `false` (owner/name differ from parse of new host) → condition passes.
4. `gitStore.setRemoteURL('origin', 'https://evil-mirror.example/my-user/my-repo.git')` executes silently, with no user prompt, permanently changing where the user's next push/fetch is sent.

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

  return true
}
