## Analysis

**Core broken invariant:** The Nouns bug is that a reward-period boundary is derived from an attacker-supplied item in a batch (a bogus last proposal) instead of the entity that actually earned it, letting the attacker capture rewards for work performed by others. The local Hyperbridge analog is in `pallet-consensus-incentives`'s `FeeHandler::on_executed`, where the beneficiary of an entire batch's rewards is derived from the *first* message in a caller-controlled `Vec<Message>`, while the rewarded events are computed by merging **all** `StateMachineUpdated` events in the batch — regardless of which message actually produced them.

### Title
Consensus-incentive rewards for an entire `handle_unsigned` batch are paid to the signer of message[0] only, letting an attacker steal rewards owed for other relayers' consensus proofs bundled in the same call - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet_ismp::Pallet::handle_unsigned` is a permissionless, unsigned extrinsic that accepts an arbitrary `Vec<Message>` and executes them all in a single transactional call, then invokes `FeeHandler::on_executed(messages_with_weights, events)` exactly once for the whole batch [1](#0-0) . `pallet-consensus-incentives`'s implementation of `on_executed` recovers the relayer account **only from `messages.get(0)`** and then pays that single account the reward for **every** `StateMachineUpdated` event collected across the whole batch [2](#0-1) . Because anyone can assemble the batch, an attacker can place their own cheaply-signable consensus message first and bundle in any other publicly-available valid consensus proof(s) (proofs are explicitly public/freely generated per the docs), causing the entire multi-chain reward to be paid to the attacker instead of whoever actually produced the additional proofs.

### Finding Description
`handle_unsigned` explicitly documents that "anyone" may submit ISMP messages "for free, provided they have valid proofs" [3](#0-2) . `Pallet::execute` runs `handle_incoming_message` over every message in the caller-supplied vector, collects the resulting events, and calls `T::FeeHandler::on_executed(messages_with_weights, events)` a single time for the whole batch [4](#0-3) .

`pallet-consensus-incentives::on_executed` then:
1. Picks `maybe_relayer_account` by decoding the signer **only from `messages[0]`** if it is a `Message::Consensus` [5](#0-4) .
2. Independently scans the entire `events` vector for `IsmpEvent::StateMachineUpdated`, collapsing to the highest `latest_height` per `state_machine_id`, with no linkage back to which specific message in the batch produced each event [6](#0-5) .
3. Pays the *single* `relayer_account` from step 1 the reward for *every* state machine advance found in step 2, computed as `(latest_height - baseline) * cost_per_block`, transferred straight from the treasury [7](#0-6) .

The corrupted value is the **reward beneficiary binding**: it is bound to `messages[0].signer` regardless of which message(s) in the same batch actually advanced which state machine. No code checks that the message at index 0 corresponds to the state machine being rewarded, nor that a message exists per state machine authored by the same account credited. Since consensus proofs are, by design, public data that "can be generated by anyone" and "freely provided by connected chains" [8](#0-7) , an attacker does not need any privileged relayer role — they only need to construct any valid `Message::Consensus` for at least one chain (which they can sign themselves), and append it, as element 0, ahead of any other legitimate, currently-valid consensus proof for a different, higher-value chain (rebroadcast from public sources or mempool). Bundling both into one `handle_unsigned` call causes the pallet to advance both chains' commitments and pay the *entire* combined reward to the attacker's own account.

This exactly mirrors the Nouns bug's core primitive: a caller-controlled ordering/composition choice (there: `lastProposalId`; here: `messages[0]`) is used to select the entity whose identity determines fund distribution for value contributed by other, unrelated entities in the same call, with no eligibility/ownership check tying the credited party to the actual work rewarded.

### Impact Explanation
Direct theft of treasury-funded relayer rewards (`RelayerRewarded` payouts) plus minted `ReputationAsset` from the legitimate submitter of a consensus proof to an unrelated attacker, for every batch where more than one consensus update is bundled. This is a stealing-of-funds / wrong-beneficiary bug against the live consensus-incentive reward pool, directly reachable via the public, permissionless `handle_unsigned` extrinsic with no privileged role required.

### Likelihood Explanation
`handle_unsigned` is unsigned and permissionless by design, and consensus proofs for any tracked state machine are, by protocol design, public and reusable by anyone who observes them (BEEFY proofs, GRANDPA finality proofs, etc., are not secret to a single relayer). An attacker merely needs to watch pending/recent valid consensus submissions for high `cost_per_block` chains, and race/bundle them behind their own minimal, self-authored consensus message for any chain (even a cheap or already up-to-date one) as index 0. No compromised keys, no malicious relayer collusion, and no reliance on front-running timing beyond ordinary transaction composition are required — the attacker fully controls the `Vec<Message>` argument.

### Recommendation
Attribute rewards per-message rather than per-batch: derive the signer from the specific `Message::Consensus` whose `consensus_proof` produced each `StateMachineUpdated` event (e.g., by tagging events with the index/state_machine_id of the message that generated them during `handle_incoming_message`, and looking up the corresponding message's signer in `process_message` instead of a single batch-wide `messages[0]` signer). Alternatively, reject batches containing consensus messages for more than one distinct `state_machine_id`, or require that the signer recovered per state machine match the signer of the specific consensus message that advanced that chain.

### Proof of Concept
1. Relayer B broadcasts (or has already submitted, and it becomes publicly visible pre-finalization/in mempool) a valid `Message::Consensus` proof `M_expensive` that advances `chain_X` (high `StateMachinesCostPerBlock`) by many blocks, signed with B's key.
2. Attacker A crafts their own minimal, self-signed valid `Message::Consensus` proof `M_cheap` for any tracked chain (`chain_Y`), signed with A's key — this can even be a proof advancing `chain_Y` by 0 or 1 block, since only its presence at index 0 matters.
3. Attacker calls `pallet_ismp::handle_unsigned(vec![M_cheap, M_expensive])`.
4. `execute` processes both, producing `StateMachineUpdated` events for both `chain_Y` and `chain_X` [4](#0-3) .
5. `on_executed` decodes the relayer as A (signer of `messages[0]` = `M_cheap`) [5](#0-4) , then loops over the collapsed `highest_per_state_machine` map containing both `chain_Y` and `chain_X`, paying A the full `(latest_height - baseline) * cost_per_block` reward for **both**, including the large reward that should have gone to relayer B for `M_expensive` [9](#0-8) .
6. Relayer B, who actually produced and would normally submit `M_expensive` alone, receives nothing for that advance; the treasury funds are transferred to attacker A's account instead.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;
