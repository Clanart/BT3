### Title
`CW721ERC721Pointer` does not override `safeTransferFrom`, causing marketplaces/standard EVM tooling to permanently freeze funds and revert all CW721-pointer sales - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
`CW721ERC721Pointer` overrides `transferFrom`, `approve`, `setApprovalForAll`, `balanceOf`, `ownerOf`, etc. to route every state-changing/state-reading call through the CW721 contract via the wasmd precompile [1](#0-0) . However it never overrides `safeTransferFrom(address,address,uint256)` / `safeTransferFrom(address,address,uint256,bytes)`, so calls to these standard, EIP-721-recommended entry points fall through to the un-overridden OpenZeppelin `ERC721` implementation, which operates on the contract's local (and always-empty) `_owners`/`_balances` storage instead of the CW721 backing store [2](#0-1) . This is the same bug class as the referenced report: a bridging/gateway contract implements only a narrower method signature than the one the calling tool (Arbitrum's `L2GatewayRouter` in the original, or any standard NFT marketplace/wallet using `safeTransferFrom` here) actually invokes.

### Finding Description
`CW721ERC721Pointer` is a Solidity contract meant to be a live, storage-transparent proxy for a CW721 (CosmWasm NFT) contract, exposing the token as an ERC721 to the EVM [3](#0-2) . Every state query (`balanceOf`, `ownerOf`, `getApproved`, `isApprovedForAll`) and every mutating call it does implement (`transferFrom`, `approve`, `setApprovalForAll`) bypasses OpenZeppelin's internal storage and instead queries/executes against the CosmWasm contract through `WasmdPrecompile` [4](#0-3) [5](#0-4) .

Because the contract never calls `_mint`, `_burn`, or `_update` to populate OpenZeppelin's private `_owners`/`_balances` mappings (all "minting" happens exclusively on the CW721 side), those mappings are permanently empty for every token id. `safeTransferFrom` is not among the overridden functions in the file, so any call resolves to OpenZeppelin's base `ERC721.safeTransferFrom`, which authorizes/transfers using the internal (`_ownerOf`) storage rather than the pointer's CW-backed `ownerOf()` override. Since `_ownerOf(tokenId)` always returns `address(0)`, every `safeTransferFrom` call reverts (`ERC721IncorrectOwner`/`ERC721NonexistentToken`), completely decoupled from the actual CW721 ownership state that `ownerOf()`/`transferFrom()` correctly reflect.

This exactly mirrors the referenced bug class: an entity (a generic router/marketplace/wallet) calls the standard/expected method (`safeTransferFrom`, the EIP-721-recommended transfer path, analogous to `L2GatewayRouter.outboundTransfer`), but the bridging/pointer contract only implements a subset of the interface (`transferFrom`, analogous to `L2LPTGateway`'s narrower `outboundTransfer` overload), so the call silently fails via a different, disconnected code path instead of using the correct CW-routing logic.

### Impact Explanation
This is concretely reachable by any unprivileged EVM contract or user that uses the standard, EIP-721-preferred method to move a CW721-pointer NFT — for example, the integration-tests' own reference `NftMarketplace` contract calls `IERC721(nftAddress).safeTransferFrom(...)` for `listItem`, `cancelListing`, and `buyItem` [6](#0-5) . When `nftAddress` is a `CW721ERC721Pointer`:
- `listItem` records the listing state (`s_listings[...] = Listing(...)`) *before* calling `safeTransferFrom`, then the external `safeTransferFrom` call reverts. Because Solidity fully reverts on an unhandled revert inside an external call chain unless wrapped in try/catch, the whole `listItem` transaction reverts — but if a caller wraps this in a higher-level flow expecting partial success/silent failure, or if a future contract change catches this revert (e.g., using `try/catch` for listing), the internal accounting (listing recorded) could become inconsistent with actual custody (no NFT actually moved into escrow), enabling a lister to “sell” an NFT never actually held in escrow, or a buyer to pay (`buyItem` credits `s_proceeds[seller] += msg.value` before the failed transfer) while the transfer silently fails.
- More directly, `buyItem` performs the state change `s_proceeds[listedItem.seller] += msg.value` and deletes the listing *before* invoking `safeTransferFrom` to deliver the NFT to the buyer [7](#0-6) . Since `safeTransferFrom` unconditionally reverts for a pointer NFT, the buyer's ETH is refunded by the revert in this particular non-catching implementation, but any marketplace or aggregator contract that does *not* fully revert on this failure (e.g. catches the error to preserve gas or continue a batch), or that relies on `safeTransferFrom` succeeding as a post-condition, will have already credited the seller's proceeds while the buyer never received the NFT — a fund-loss/broken-invariant scenario for CW721-pointer collections.
- At minimum, this permanently breaks the ability to trade, escrow, or use pointer-token NFTs with any protocol, wallet, or router in the ecosystem that uses the standard/safe transfer path rather than the raw, non-standard `transferFrom` — a systemic denial of a core described capability of the CW↔EVM pointer bridge.

### Likelihood Explanation
High likelihood: `safeTransferFrom` is the EIP-721-documented, recommended transfer method and is the default method used by virtually all NFT marketplaces, wallets, and DeFi integrations. Any user or contract holding a CW721-pointer NFT that attempts to use this standard interface — which requires no special privileges, just a normal transaction/contract call — will trigger the bug. The provided `NftMarketplace.sol` fixture in this very repository demonstrates this exact call path is expected to work with pointer-wrapped NFTs (`nftMarketplaceTests.js` explicitly tests “listing and buying erc721 pointer”) [8](#0-7) .

### Recommendation
Override both `safeTransferFrom(address,address,uint256)` and `safeTransferFrom(address,address,uint256,bytes)` in `CW721ERC721Pointer` to route through the same CW721-execute logic used by `transferFrom` (i.e., verify ownership/authorization via the CW-backed `ownerOf`, execute the `transfer_nft` (or equivalent) CW message via `_execute`, and then perform the ERC721 receiver check exactly as done correctly in the analogous `CW1155ERC1155Pointer.safeTransferFrom` [9](#0-8) ), instead of relying on OpenZeppelin's un-overridden default implementation that operates on disconnected local storage.

### Proof of Concept
1. Register a CW721 pointer for an existing CW721 NFT collection via the pointer precompile (`addCW721Pointer`), obtaining a `CW721ERC721Pointer` contract instance whose `ownerOf(tokenId)` correctly reflects CW-side ownership [10](#0-9) .
2. As the actual NFT owner (confirmed via `ownerOf`), call `pointer.safeTransferFrom(owner, recipient, tokenId)` directly, or through `NftMarketplace.listItem(pointerAddress, tokenId, price)` [11](#0-10) .
3. Observe the call reverts with `ERC721InsufficientApproval`/`ERC721IncorrectOwner` (OpenZeppelin's internal storage check), even though `ownerOf(tokenId)` (querying the CW contract) correctly returns the caller's address — proving `safeTransferFrom` is disconnected from the actual CW-backed ownership state that every other function in the contract correctly uses.
4. Repeat using `NftMarketplace.buyItem` after a successful `listItem` (which would itself already fail per step 2/3) to show the entire marketplace flow for CW721-pointer NFTs is broken, and that a marketplace implementation which does not strictly revert-on-failure could credit seller proceeds without ever delivering the NFT.

    function ownerOf(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("owner_of", _curlyBrace(tId)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes memory owner_ = JsonPrecompile.extractAsBytes(response, "owner");
        return AddrPrecompile.getEvmAddr(string(owner_));
    }

    function getApproved(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("approvals", _curlyBrace(tId)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes[] memory approvals = JsonPrecompile.extractAsBytesList(response, "approvals");
        if (approvals.length > 0) {
            bytes memory res = JsonPrecompile.extractAsBytes(approvals[0], "spender");
            return AddrPrecompile.getEvmAddr(string(res));
        }
        return address(0);
    }

    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }

        string memory req = _curlyBrace(_formatPayload("approve", _curlyBrace(_join(spender, tId, ","))));

    function cancelListing(address nftAddress, uint256 tokenId) external {
        // Checks

            revert NftMarketplace__NotOwner();
        }

        delete s_listings[nftAddress][tokenId];

     * @notice Method for buying listing
     * @notice The owner of an NFT could unapprove the marketplace,
     * @param nftAddress Address of NFT contract
     * @param tokenId Token ID of NFT
     */
    function buyItem(address nftAddress, uint256 tokenId) external payable {
        Listing memory listedItem = s_listings[nftAddress][tokenId];
        // Checks
        if (listedItem.seller == address(0)) {
            revert NftMarketplace__NotListed(nftAddress, tokenId);
        }
        if (msg.value < listedItem.price) {
            revert NftMarketplace__PriceNotMet(nftAddress, tokenId, listedItem.price);

        s_proceeds[listedItem.seller] += msg.value;
        delete s_listings[nftAddress][tokenId];
        emit ItemBought(msg.sender, nftAddress, tokenId, listedItem.price);

        // Interactions (External)
        IERC721(nftAddress).safeTransferFrom(address(this), msg.sender, tokenId);
    }

    function safeTransferFrom(
        address from,
        address to,
        uint256 id,
        uint256 amount,
        bytes memory data
    ) public override {
        require(to != address(0), "ERC1155: transfer to the zero address");
        require(balanceOf(from, id) >= amount, "ERC1155: insufficient balance for transfer");
        require(
            msg.sender == from || isApprovedForAll(from, msg.sender),
            "ERC1155: caller is not approved to transfer"
        );
    
        string memory f = _formatPayload("from", _doubleQuotes(AddrPrecompile.getSeiAddr(from)));
        string memory t = _formatPayload("to", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(id)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));

        string memory req = _curlyBrace(
            _formatPayload("send", _curlyBrace(_join(f, ",", _join(t, ",", _join(tId, ",", amt)))))
        );
        _execute(bytes(req));
        if (to.code.length > 0) {
            require(
                IERC1155Receiver(to).onERC1155Received(
                    msg.sender,
                    from,
                    id,
                    amount,
                    data
                ) == IERC1155Receiver.onERC1155Received.selector,
                "unsafe transfer"
            );
        }
    }
