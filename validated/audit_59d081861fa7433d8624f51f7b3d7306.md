### Title
Scanner credits coinbase outputs as immediately spendable, letting a miner make Serai sign consensus-invalid spends of immature outputs - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The source report's bug class is: a permissionless entry point makes an economic decision from attacker-manipulable instantaneous state (Uniswap spot price / pool balances), letting an attacker force the protocol to move collateral on a value that isn't real/stable. The Serai analog lives in the Bitcoin wallet scanner: `Scanner::scan_block` feeds every transaction in a block — including the coinbase — through `scan_transaction`, which reports any output paying a watched `script_pubkey` as a `ReceivedOutput`. `SignableTransaction::new` then consumes `ReceivedOutput`s unconditionally to construct and threshold-sign a spend. A coinbase output paying a Serai-registered address is not spendable for 100 blocks (BIP/consensus coinbase maturity), yet the wallet treats it as a normal spendable input. Any miner — an unprivileged party whose only capability is sending Bitcoin transactions, which is an in-scope reachability surface — can cause Serai to report received funds that are not spendable and to produce a fully-signed, consensus-invalid transaction.

### Finding Description
`scan_transaction` matches outputs purely on `script_pubkey` membership in `self.scripts` and immediately wraps them into `ReceivedOutput { offset, output, outpoint }` with no check on the transaction's position in the block or coinbase status. [1](#0-0)  `scan_block` iterates `block.txdata` starting at index 0, so the coinbase is scanned identically to regular transactions. [2](#0-1)  The only mitigation is a doc comment telling integrators to post-process or slice `txdata[1 ..]` — an undocumented-in-code footgun rather than an enforced invariant.

Downstream, `SignableTransaction::new` sums `input.output.value` from the supplied `ReceivedOutput`s and builds `TxIn`s from their outpoints with no maturity validation. [3](#0-2)  `multisig` verifies only that `p2tr_script_buf(offset.group_key())` equals the prevout's `script_pubkey` — it cannot detect immaturity — and `sign` then produces real threshold signature shares over the sighash committing to all prevouts (`Prevouts::All`). [4](#0-3) [5](#0-4) 

### Impact Explanation
Funds reported received that are not spendable, plus consumption of a threshold signing session on a transaction that consensus rejects (immature coinbase spend). Any coordinator/processor logic that treats scanner output as wallet balance will overstate the spendable balance; if the signed invalid transaction is the output of a batch/attempt flow, the spend fails after the full signing ceremony completes, burning a signing attempt and any fee budget. If mixed with mature inputs, the tx remains invalid (one bad input invalidates the whole transaction), so a single crafted coinbase payment poisons an entire spend — mirroring the report's "one cheap state manipulation forces the protocol into an erroneous rebalance" shape.

### Likelihood Explanation
Reachable by any miner at negligible cost: a coinbase can pay arbitrary scriptPubKeys, so mining (or being) a miner that directs a coinbase output to a Serai-scanned `script_pubkey` — e.g., the zero-offset script registered in `Scanner::new` — suffices. [6](#0-5)  No validator collusion, key material, or timing window is required; the forged "deposit" persists on-chain. Medium likelihood: it requires mining a block (or being paid by a miner to include the output), but that is exactly the class of unprivileged, publicly-submittable Bitcoin transaction in scope.

### Recommendation
Enforce maturity in the wallet rather than documenting around it: have `scan_transaction`/`scan_block` take the coinbase flag (or scan `block.txdata[1 ..]` internally and return coinbase outputs through a separate, clearly-immature API), and/or have `SignableTransaction::new`/`multisig` reject `ReceivedOutput`s whose outpoint belongs to a coinbase lacking 100 confirmations. Alternatively, record the block height at scan time in `ReceivedOutput` and check maturity at signing time so the invariant can't be bypassed by integrator misuse.

### Proof of Concept
1. Attacker (a miner) registers knowledge of Serai's watch script `s0 = p2tr_script_buf(group_key)`, which `Scanner::new` always monitors with `Scalar::ZERO` offset. [6](#0-5) 
2. Attacker mines block B whose coinbase includes an output `{ value: X, script_pubkey: s0 }`.
3. Serai runs `Scanner::scan_block(B)`; the loop over `block.txdata` includes `txdata[0]`, so the coinbase output is returned as `ReceivedOutput { offset: 0, output, outpoint: (coinbase_txid, vout) }`. [2](#0-1) 
4. Before height +100, Serai constructs `SignableTransaction::new(vec![received], payments, change, data, fee)` — `input_sat` counts X, the `TxIn` commits to the immature outpoint, and `multisig`/`sign` produce valid FROST signature shares because `script_pubkey` verification passes. [3](#0-2) 
5. `complete` assembles the signed transaction; broadcast fails consensus validation (`bad-txns-premature-spend-of-coinbase`), while the scanner had already reported X as received balance and a signing session was consumed.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
```
