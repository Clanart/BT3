### Title
Ed448 low-order points are accepted as canonical, enabling Schnorr proof forgery - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary
`Ed448` point decoding claims to reject non-prime-order points, but `Point::is_torsion_free` computes `-P + P`, which is always the identity and therefore accepts every decoded curve point, including low-order components. [1](#0-0) 

A `Ciphersuite::read_G` caller consequently receives a supposedly prime-order `Ed448` point that is actually malformed for the protocol. [2](#0-1) 

The stricter FROST `Curve::read_G` only rejects the identity, so non-identity torsion points still pass. [3](#0-2) 

### Finding Description
`Ed448` has cofactor 4, so valid curve encodings can represent points with a nonzero low-order component in addition to, or instead of, a prime-order component. [1](#0-0) 

`is_torsion_free` is implemented as `((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()`. Since `Scalar::ZERO - Scalar::ONE` is `-1`, this is always `-P + P == identity`, regardless of whether `P` is in the prime-order subgroup. [1](#0-0) 

`SchnorrSignature::verify` checks `R + cA - sG == identity` without cofactor clearing or an additional subgroup check. [4](#0-3) 

Therefore an attacker can set `A` to a low-order point and adjust the low-order component of `R` so the verification equation balances with a probability-dependent challenge, without possessing a prime-order discrete logarithm for `A`. [4](#0-3) 

### Impact Explanation
This produces a forged Schnorr proof/signature under an accepted `Ed448` public key or commitment that has no discrete logarithm with respect to the prime-order generator. [5](#0-4) 

Protocols using Schnorr proofs for possession or commitment validity can therefore admit a malformed commitment that should have been rejected by subgroup membership. [6](#0-5) 

### Likelihood Explanation
The malformed public key can be the order-two point `(x = 0, y = -1)`, whose encoding is canonical and passes the current checks because its x-coordinate sign is zero rather than negative-zero. [7](#0-6) 

For a Fiat-Shamir challenge dependent on `R`, the attacker only needs to retry ordinary nonce choices until the challenge parity matches the selected low-order component, making the forgery practical. [4](#0-3) 

### Recommendation
Replace `Point::is_torsion_free` with a real prime-subgroup check, such as multiplication by the Ed448 prime subgroup order, or delegate to a verified torsion-free implementation in the underlying curve backend. [1](#0-0) 

The check must distinguish points containing cofactor components, not merely reject the identity or negative zero, before any `read_G`, proof verification, DKG commitment, or nonce processing consumes the point. [2](#0-1) 

### Proof of Concept
Let `T` be the order-two Ed448 point `(x = 0, y = -1)`. Its compressed encoding is the 57-byte little-endian encoding of `p - 1`, with the x-sign bit clear:

```rust
// crypto/ed448/src/point.rs decoding path
let mut t = [0u8; 57];
t[0] = 0xfe;
t[1..28].fill(0xff);
t[28] = 0xfe;
t[29..56].fill(0xff);

// Accepted by the current decoder even though it is order-two.
let T = Ed448::read_G(&mut t.as_slice()).unwrap();
```

Construct the verification forgery as follows:

```text
G = Ed448 prime-order generator
A = T
Choose random scalar r.
For t in {0, 1}:
    R = rG + tT
    c = H(R, A, message)

    if t + c == 0 mod 2:
        s = r
        return (R, s)
```

The verification expression becomes:

```text
R + cA - sG
= (rG + tT) + cT - rG
= (t + c)T
= identity
```

Retrying `r` changes `c` and quickly finds a matching `t`, so `SchnorrSignature { R, s }.verify(T, c)` returns true even though `T` has no prime-order discrete logarithm and no corresponding private key was used. [4](#0-3)
