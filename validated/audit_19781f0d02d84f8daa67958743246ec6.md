### Title
JIT reward sniping via instant, non-time-weighted `rewardPerTokenStored` update in `BaseRewardPoolV2`/`BaseRewardPool` - (File: `rewards/BaseRewardPoolV2.sol`, `rewards/BaseRewardPool.sol`, `wombat/WombatStaking.sol`)

### Summary
The reported SushiSwap issue describes a JIT (Just-In-Time) attack where a user inflates their share of a reward-eligible quantity right before a reward-distributing event, harvests a disproportionate reward, and immediately reverses the position with no lasting exposure. The same *pattern* — capturing an instant, un-vested reward snapshot by momentarily inflating one's share of the pool right before it is baked in — is reachable in this codebase's `BaseRewardPool`/`BaseRewardPoolV2` reward accounting, which is fed by the permissionless `WombatStaking.harvest()` entrypoint.

### Finding Description
`_provisionReward` in `BaseRewardPoolV2.sol` updates the global reward index **instantly and irreversibly** based on `totalStaked()` at the exact block the reward is queued, with no linear time-vesting: [1](#0-0) 

Rewards are pushed into this function through `queueNewRewards`, which is called from `WombatStaking._sendRewards` every time pending WOM (and bonus tokens) accumulated in the underlying MasterWombat gauge are realized: [2](#0-1) 

Critically, the trigger for realizing this pending reward, `WombatStaking.harvest(_lpToken)`, is **permissionless** — callable by any wallet at any time, subject only to `whenNotPaused` and `_onlyActivePool`: [3](#0-2) 

which is also exposed through the public `WombatPoolHelperV2.harvest()` wrapper: [4](#0-3) 

Because `rewardPerTokenStored` is bumped by `(_amountReward * 10**decimals) / totalStaked()` at the instant of harvest, an attacker can:
1. Deposit a large amount of the pool's staking token (via `MasterMagpie.deposit`/`WombatPoolHelperV2.deposit`) to inflate their fraction of `totalStaked()` immediately before calling (or front-running someone else's call to) `harvest()`.
2. Trigger `harvest()`, which pulls the WOM (and bonus token) rewards accrued in MasterWombat since the last harvest and instantly credits `rewardPerTokenStored` using the *current* (attacker-inflated) `totalStaked()`.
3. Call `getReward`/`getRewards` to claim the disproportionate share of the freshly queued reward, then immediately `withdraw` the deposited principal.

This mirrors the JIT liquidity pattern from the report: momentarily and artificially maximizing one's weight in a reward-determining denominator right before a reward event is realized, then reversing the position with no genuine long-term exposure, at the expense of long-term stakers whose share of the same lump-sum reward is diluted.

### Impact Explanation
Long-term stakers receive a diluted share of every harvested WOM/bonus-token reward whenever this is exploited, because the reward is split according to `totalStaked()` at the instant of `queueNewRewards`, not weighted by how long each staker actually held their position during the accrual period. This is a direct, repeatable theft of unclaimed yield (Impact 2 in the accepted categories), executable by an ordinary wallet with capital to temporarily flash- or self-fund a large deposit, with `harvest()` being fully permissionless and callable on demand (or trivially front-run) to control the exact timing.

### Likelihood Explanation
Likelihood is high: `harvest()` requires no privileged role, no cooldown, and no fee beyond gas and (if not self-funded) transient capital cost; deposits/withdraws in `MasterMagpie`/`WombatPoolHelperV2` have no minimum staking duration or lock, so the deposit → harvest → claim → withdraw sequence can be executed atomically or within a couple of blocks, repeatable every time meaningful pending WOM rewards accumulate in MasterWombat.

### Recommendation
Convert the `BaseRewardPool`/`BaseRewardPoolV2` reward accounting from an instant lump-sum `rewardPerTokenStored` bump to a time-weighted linear-vesting model (e.g., Synthetix-style `rewardRate`/`periodFinish`/`lastUpdateTime`), so that a newly queued reward streams out over a duration rather than being instantly attributable to whoever holds the largest balance at the exact harvest block. Alternatively, add a minimum staking duration/cooldown before a deposit is eligible to receive a share of any reward queued in the same block or shortly after.

### Proof of Concept
1. Attacker observes (or triggers) pending WOM rewards accruing in `MasterWombat` for a given `_lpToken` pool.
2. Attacker calls `WombatPoolHelperV2.deposit()` (or `depositLP`) with a large amount, staking through `MasterMagpie`, becoming a large fraction of `totalStaked()` for that pool's `BaseRewardPoolV2`.
3. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)` → `_toMasterWomAndSendReward` → `_sendRewards` → `IBaseRewardPool(_rewarder).queueNewRewards(...)`, which executes `_provisionReward` and bumps `rewardPerTokenStored` using the current, attacker-inflated `totalStaked()`. [5](#0-4) 
4. Attacker calls `getReward`/`getRewards` to claim their inflated share of the just-queued reward.
5. Attacker calls `withdraw` on `MasterMagpie`/`WombatPoolHelperV2` to remove the deposited principal, having captured reward disproportionate to actual time-weighted stake.
6. Repeat on each subsequent harvest event.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);

    /// @param _rewardToken the address of the reward token to send
    /// @param _rewarder the rewarder that will get the rewards
    /// @param _amount the initial amount of rewards after harvest

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }
