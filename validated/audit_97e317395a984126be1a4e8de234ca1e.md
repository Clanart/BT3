[1](#0-0) ### Title
Coinbase outputs are reported as spendable `ReceivedOutput`s without enforcing the maturity requirement — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary

`Scanner::scan_block` scans every transaction in `block.txdata`, including the coinbase transaction at index 0. [2](#0-1)  `Scanner::scan_transaction` constructs a `ReceivedOutput` solely because an output’s `script_pubkey` matches a registered key or offset, without distinguishing coinbase transactions from ordinary transactions. [3](#0-2)  The returned `ReceivedOutput` is explicitly documented as “a spendable output,” but carries only its key offset, output, and outpoint, with no maturity or transaction-type metadata. [1](#0-0) 

### Finding Description

Bitcoin coinbase outputs are subject to an additional spendability condition: they cannot be spent until they have reached coinbase maturity. [4](#0-3)  Serai separately checks that an output pays to a registered `script_pubkey`, but does not combine that ownership check with the required coinbase-maturity check before reporting the output as spendable. [5](#0-4) 

This is analogous to validating each liability independently without proving that all obligations can be satisfied together: an immature coinbase output satisfies the wallet’s ownership criterion, but not its consensus-level spendability criterion. [1](#0-0) 

### Impact Explanation

A caller of `Scanner::scan_block` can receive a `ReceivedOutput` that looks like an ordinary spendable UTXO even though Bitcoin consensus rejects any transaction attempting to spend it before maturity. [2](#0-1)  If that output is subsequently supplied to `SignableTransaction::new`, its value is included in `input_sat` and can satisfy the transaction’s funds check despite being unspendable. [6](#0-5)  The resulting transaction either cannot enter consensus-valid form or incorrectly relies on unavailable funds to cover payments and fees. [7](#0-6) 

### Likelihood Explanation

Exploitation requires a coinbase transaction paying one of the scanner’s registered scripts, which normally means a miner or mining-pool-controlled block template creates the output. [8](#0-7)  The trigger is nevertheless reachable through public Bitcoin data fed to `scan_block`, and no validator compromise, malformed curve point, or protocol-key knowledge is required. [3](#0-2) 

### Recommendation

`scan_block` should skip `block.txdata[0]` or return coinbase outputs through a type/API that cannot be consumed as an immediately spendable `ReceivedOutput`. [2](#0-1)  Alternatively, `ReceivedOutput` should carry transaction position and confirmation/maturity state, and transaction construction should reject immature coinbase inputs before adding their values to `input_sat`. [1](#0-0)  A regression test should assert that a coinbase paying `p2tr_script_buf(key)` produces no spendable output from `scan_block`. [5](#0-4) 

### Proof of Concept

```rust
// networks/bitcoin/src/wallet/mod.rs

let scanner = Scanner::new(key).unwrap();
let script = p2tr_script_buf(key).unwrap();

// coinbase is a Transaction whose only input has a null previous output
// and whose output pays `script`.
let coinbase: Transaction = make_coinbase_paying(script);

let outputs = scanner.scan_transaction(&coinbase);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].offset(), Scalar::ZERO);

// scan_block performs the same scan on txdata[0], so a block containing only
// this coinbase also reports it as a spendable ReceivedOutput.
let block = make_block_with_txdata(vec![coinbase]);
assert_eq!(scanner.scan_block(&block).len(), 1);
```

The first assertion follows because `scan_transaction` checks only `output.script_pubkey`. [5](#0-4)  The second follows because `scan_block` iterates from `block.txdata[0]` rather than excluding the coinbase transaction. [9](#0-8)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };
