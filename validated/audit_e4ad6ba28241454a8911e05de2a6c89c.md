I found a concrete crash analog in the pointer precompile: unchecked type assertions on attacker-influenced CW contract query responses, with **no panic recovery** anywhere in the call path from EVM precompile dispatch down to these assertions.

### Title
Unrecovered panic in `pointer` precompile CW20/CW721/CW1155 pointer creation crashes the node on malformed contract metadata - (File: precompiles/pointer/pointer.go)

### Summary
The CVE describes a crafted, malformed binary (a MEW-packed PE) that a parser processes without adequate validation, triggering an unhandled crash. The analogous class in sei-chain is a precompile parsing untrusted/attacker-shaped data (a CW contract's JSON query response) with unchecked Go type assertions and no panic recovery in the dispatch chain, so a single crafted input crashes the EVM execution goroutine.

### Finding Description
`PrecompileExecutor.AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` query an arbitrary CosmWasm contract (`cwAddr`, fully attacker-supplied) via `p.wasmdKeeper.QuerySmartSafe`, unmarshal the JSON response into `map[string]interface{}`, and then immediately perform unchecked type assertions: [1](#0-0) 

If the target contract's `token_info`/`contract_info` response has `name` or `symbol` fields that are not JSON strings (e.g., numbers, objects, arrays, `null`, or the keys are simply absent because a malicious CW20/CW721/CW1155 contract intentionally returns a different response shape), `formattedRes["name"].(string)` is a bare (non-`, ok`) type assertion that panics with `interface conversion: interface {} is nil, not string` (or similar).

This is called from `PrecompileExecutor.Execute`, dispatched by `DynamicGasPrecompile.RunAndCalculateGas` in `precompiles/common/precompiles.go`: [2](#0-1) 

The `defer` in `RunAndCalculateGas` only calls `HandlePrecompileError`, which records the error into StateDB and increments a metric — it does **not** call `recover()`. Unlike the legacy `addr` precompile executor which explicitly wraps its `Execute` with `defer func() { recover() }()` to convert gas-meter panics into a reverted error: [3](#0-2) 

the `pointer` precompile's dynamic-gas path has no equivalent recovery. A panic from the bare type assertion therefore propagates unrecovered up through the EVM interpreter and the transaction-processing goroutine.

### Impact Explanation
Any unprivileged EVM caller can deploy (or already control) a CW20/CW721/CW1155 contract that returns a `token_info`/`contract_info` JSON response where `name`/`symbol` are missing or non-string, then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` at precompile address `0x100b` targeting that contract. This triggers an unrecovered panic during transaction execution. Depending on whether the panic occurs inside a goroutine/context that has its own top-level recovery (e.g., Cosmos SDK's `runTx` panic handler) this could be contained to a single tx failure, or — if reached from a code path lacking that top-level recovery (such as concurrent preprocessing paths that do have their own recover, as seen in `app.go`) — could crash the node process, matching the "crash of default-configuration RPC/full nodes" impact criterion.

### Likelihood Explanation
High likelihood of reachability: constructing a CosmWasm contract that returns an unexpected JSON shape for `token_info`/`contract_info` queries is trivial and entirely within the control of any user who can instantiate a CW contract, then call the public `pointer` precompile method from a normal EVM transaction — no special privileges, validator status, or network position required.

### Recommendation
Replace the unchecked type assertions in `precompiles/pointer/pointer.go` (`AddNative` already avoids this pattern via `metadata.Name`, but `AddCW20`, `AddCW721`, `AddCW1155` do not) with the two-value form and return a normal error on failure:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid or missing name in response")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid or missing symbol in response")
}
```
Additionally, add a `defer recover()` guard in `DynamicGasPrecompile.RunAndCalculateGas` (mirroring the pattern already used in legacy static precompiles like `addr`) so that any unexpected panic from executor code is converted into `execution reverted` rather than propagating and risking a node crash.

### Proof of Concept
1. Instantiate a CosmWasm contract whose `{"token_info":{}}` (or `{"contract_info":{}}`) query handler returns valid JSON such as `{"name": 12345, "symbol": null}` (numeric/`null` instead of strings), or omits the fields entirely.
2. From any EVM account, call `addCW20Pointer(cwAddr)` (or `addCW721Pointer`/`addCW1155Pointer`) on the pointer precompile at `0x100000000000000000000000000000000000100b`, passing the malicious contract's bech32 address.
3. Execution reaches `formattedRes["name"].(string)` in `AddCW20`/`AddCW721`/`AddCW1155`, panics on the failed type assertion, and propagates unrecovered through `RunAndCalculateGas`, since no `recover()` exists in that call path. [4](#0-3) [2](#0-1)

	}
