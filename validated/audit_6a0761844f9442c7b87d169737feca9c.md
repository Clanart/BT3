### Title
Payout tx's OP_RETURN operator-attribution is unsigned under `SinglePlusAnyoneCanPay`, letting an attacker win the withdrawal-outpoint race with a garbage OP_RETURN and permanently orphan the honest operator's reimbursement path - (`core/src/builder/transaction/operator_reimburse.rs`, `core/src/verifier.rs`)

### Summary
`create_payout_txhandler` builds the payout tx's OP_RETURN output (which encodes `operator_xonly_pk`) as an output the withdrawing user's signature does not cover, because the withdrawal input is signed with `TapSighashType::SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0 [1](#0-0) . This signature — along with the withdrawal outpoint, amount, and payout output — is publicly readable from the Citrea withdraw() call, which the rules state an unprivileged attacker can invoke and observe. An attacker can therefore independently assemble their own competing spend of the exact same withdrawal UTXO, reusing the user's signature verbatim, keeping output 0 identical, but attaching a garbage 32-byte OP_RETURN and funding it with their own inputs, then race it to confirmation ahead of the honest operator's payout tx.

### Finding Description
The broken binding: **"If an honest operator's `withdraw()` funded and broadcast a payout tx for withdrawal `idx`, then the chain-confirmed tx that spends `withdrawals[idx].withdrawal_utxo` carries that operator's `operator_xonly_pk` in its OP_RETURN."** Before vs after the attack, this binding fails: the confirmed spender of the withdrawal outpoint is the attacker's tx, whose OP_RETURN parses to `None`.

Trace:
1. `Operator::withdraw` builds the payout tx via `create_payout_txhandler`, which sets output 0 to the user's `output_txout`, output 1 to an anchor, and output 2 to `op_return_txout(operator_xonly_pk)`, then attaches only the user's `SinglePlusAnyoneCanPay` witness at input 0 [1](#0-0) .
2. The gRPC layer strictly enforces the sighash flag to be `SinglePlusAnyoneCanPay` for this signature [2](#0-1) , and the operator verifies it against exactly this sighash [3](#0-2) . This sighash type by definition commits only to input 0 (ANYONECANPAY) and output 0 (SINGLE); nothing constrains outputs 1/2 (anchor, OP_RETURN) or any additional funding inputs.
3. The withdrawal signature, outpoint, output script/amount are all public — the attacker is explicitly permitted to "call `withdraw` on the Citrea Bridge contract" and observe these values, i.e. they can read them directly from Citrea state before or concurrently with any operator.
4. The attacker constructs their own transaction: input 0 = the same withdrawal outpoint + copied user witness, output 0 = the identical user payout (required, since it's covered by SIGHASH_SINGLE), plus attacker-funded fee inputs, an anchor, and an OP_RETURN of 32 garbage bytes that is a valid push but fails `XOnlyPublicKey::from_slice`. They broadcast/fee-bump this ahead of the honest operator's real payout tx so it confirms first — since a UTXO can only be spent once, whichever tx is mined "wins" and the other becomes permanently unconfirmable.
5. On the finalized block, `Verifier::update_finalized_payouts` looks up whichever tx actually spent `withdrawal_utxo_txid:vout` via `get_payout_txs_for_withdrawal_utxos` (a DB join keyed purely on the spent outpoint, not on tx content or origin) [4](#0-3) , extracts the first OP_RETURN, and tries `XOnlyPublicKey::from_slice`; on the attacker's garbage bytes this fails, storing `operator_xonly_pk = NULL` [5](#0-4) .
6. Downstream, `Operator::validate_payer_is_operator` requires `payer_xonly_pk == Some(self operator)`, and errors otherwise — this is the entry point of `get_reimbursement_txs` [6](#0-5) [7](#0-6) . With `payer_xonly_pk = NULL`, `get_reimbursement_txs` permanently errors for this deposit, and the operator can never obtain the Round/Kickoff/Reimburse tx chain for it. Additionally `is_kickoff_malicious` treats `operator_xonly_pk_opt == None` as "assuming malicious" [8](#0-7) , meaning if the honest operator nonetheless attempts a kickoff for this deposit it would be flagged malicious by verifiers, risking collateral loss via the disprove/challenge path.

Why guards don't catch this: none of `is_deposit_valid`, `SECP.verify_schnorr` (it only checks the input-0 signature, which remains valid on the attacker's tx too), `is_kickoff_malicious`, or the DB uniqueness constraints validate that the OP_RETURN or the funding inputs originate from the actual operator who "owns" the reimbursement claim — the protocol's sole binding of "who funded this payout" to "who gets reimbursed" is the unsigned OP_RETURN pubkey, which any party can forge/omit as long as they can win the outpoint-spend race with the reused public signature.

### Impact Explanation
This matches the Critical category "an honest operator permanently unable to be reimbursed for bridge_amount it fronted." Concretely: an honest operator's genuine payout attempt never confirms (it's a losing double-spend), and even though the user's withdrawal output still eventually gets paid to them (bound by the SINGLE sighash), the DB permanently records `payout_payer_operator_xonly_pk = NULL` for that withdrawal `idx`, permanently blocking `get_reimbursement_txs`/`validate_payer_is_operator` and exposing any real kickoff attempt to being judged malicious. This is repeatable per-withdrawal and does not require compromising any key, verifier, or operator — only observing/copying a public signature and outbidding the operator's fee/confirmation race.

### Likelihood Explanation
The attacker needs: (1) visibility into the withdrawal's `input_signature`/`input_outpoint`/`output_script_pubkey`/`output_amount`, all obtainable from the public Citrea `withdraw()` call (which the attacker is permitted to invoke or observe) and re-derivable off-chain without any protocol secret; (2) capital to fund the output amount plus fees themselves (since the dust input alone cannot cover `bridge_amount`), which is a real BTC cost but is a griefing cost, not a profit requirement; (3) winning a fee/first-broadcast race against the operator's automated payout submission, which is plausible since operator automation timing is observable and RBF/fee competition is a normal, unprivileged capability. No key compromise, majority hashrate, or insider access is required, satisfying the constraint of an "unprivileged attacker."

### Recommendation
Bind the OP_RETURN operator-attribution output to the same signature that authorizes the spend, e.g., have the operator's payout tx use `SIGHASH_ALL`/`SIGHASH_SINGLE` (non-ANYONECANPAY, non-partial) covering the OP_RETURN output for the withdrawal input, or otherwise make operator attribution independent of the malleable OP_RETURN — for instance, deriving payer attribution primarily from `withdrawals.payout_txid`'s registered/expected funding inputs (attributable to a specific operator's known UTXO set) rather than trusting an unauthenticated OP_RETURN push. At minimum, before an operator broadcasts `withdraw()`, it should check the mempool/chain for any existing spend of the same `withdrawal_utxo` and treat a foreign spend with mismatched attribution as a signal to retry/fee-bump aggressively, and the protocol should provide a recovery/appeal path (e.g., allow verifiers to re-attribute a payout to the operator who can prove they funded it, using the funding inputs of the confirmed tx) rather than making OP_RETURN parse failure a terminal, unrecoverable state.

4. Assert:
   - `db.get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(...)` (or equivalently query `withdrawals.payout_payer_operator_xonly_pk`) returns `None` for this withdrawal `idx`, even though `Operator::withdraw` was never able to get its own tx confirmed.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
