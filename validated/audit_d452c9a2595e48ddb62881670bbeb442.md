### Title
Silent remote-URL rewrite driven by parser-differential trust in `apiRepo.clone_url` - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl` automatically rewrites the local `origin` remote to whatever `clone_url` value the GitHub API reports for a repository, guarded by a same-origin-style check. That guard, however, is built from two different URL-identity computations on the same strings: a legacy `url.parse()` call used only to compare *protocol*, and a separate regex-based identifier parser (`urlMatchesRemote`/`parseRepositoryIdentifier`) used to compare *host/owner/name*. This is structurally the same defect class as the UMA report: the same conceptual value (a URL's identity) is derived two different ways in two different places, and the code assumes they agree when they may not, letting an attacker-influenced value slip past the check that's supposed to gate a trust-changing action.

### Finding Description
`updateRemoteUrl` decides whether to overwrite the user's configured git remote based on three independently computed conditions: [1](#0-0) 

- `urlsMatch` and `remoteUrlUnchanged` are computed with `urlMatchesRemote` (in `app/src/lib/repository-matching.ts`), which itself calls `parseRepositoryIdentifier`, a custom parser distinct from Node's `url` module. [2](#0-1) 
- `protocolsMatch` is computed with Node's legacy, deprecated `URL.parse()` (the "legacy API", known to be lenient/inconsistent for malformed or unusual URLs, e.g. userinfo tricks, backslashes, or scheme confusion), which is never used anywhere else in this function to validate host identity.

The security-relevant branch is:
```
if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
  await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
```
i.e. "the scheme looks unchanged, and this used to be the API's repo, but the owner/name no longer match → silently point `origin` at the new `clone_url`." The `clone_url` field originates entirely from the GitHub API response object (`apiRepo.clone_url`), which for GitHub Enterprise users is fetched from a self-hosted, admin-controlled/MITM-able endpoint, and is not otherwise re-validated by Desktop before being written into `.git/config` as the remote URL.

Because the "is this really a rename I should follow" decision depends on the interaction of two structurally different URL parsers (Node's legacy `url.parse` vs. the regex-based `parseRepositoryIdentifier`), a URL string can be crafted so that:
- `url.parse()` reports the same `protocol` as the existing remote (satisfying `protocolsMatch`), while
- `parseRepositoryIdentifier`/`urlMatchesRemote` disagrees about hostname/owner/name in exactly the way needed to make `remoteUrlUnchanged === true` and `urlsMatch === false`.

This mirrors the UMA bug precisely: two different computations of "is this the same object" are combined as if they were consistent, and the discrepancy is exactly what lets an invalid/attacker state pass the guard.

### Impact Explanation
If the guard is bypassed with a malicious `clone_url`, Desktop silently rewrites the user's trusted `origin` remote to an attacker-controlled URL via `gitStore.setRemoteURL`. Subsequent `git fetch`/`push`/`pull` (`app/src/lib/git/fetch.ts`, `push.ts`, `pull.ts`) will then transparently talk to the attacker's server, including:
- Credential/token exfiltration through the git credential flow (`envForRemoteOperation`) sent to the wrong host.
- Silent corruption of what the user pushes/fetches — pushes go to attacker infrastructure, and future fetched history could be attacker-supplied content that the user believes came from the legitimate repository.

This satisfies the "unauthorized...binding" and "silent corruption of what the user commits or pushes" impact categories.

### Likelihood Explanation
This requires the victim to be using a GitHub Enterprise (or otherwise attacker-influenceable) API endpoint that can supply a crafted `clone_url` value for a repository the app already has as `origin`, and requires a crafted URL string that produces divergent results between Node's legacy `url.parse` and Desktop's custom `parseRepositoryIdentifier` regexes. I was not able to fully verify a concrete divergent input from the code available in the index (the exact regex definitions for `parseRepositoryIdentifier` were not fully retrievable), so I cannot confirm a working exploit string — only that the architecture (two different parsers gating one trust decision) is the same broken-invariant pattern as the UMA report.

### Recommendation
- Use a single, canonical URL-parsing/normalization function for both the protocol comparison and the host/owner/name comparison in `updateRemoteUrl`.
- Additionally require the *host* (not just scheme) to remain unchanged before automatically rewriting `origin`, or prompt the user before silently changing a remote URL to a value straight from the API.

### Proof of Concept
Not fully constructible from the indexed code — the exact regex source for `parseRepositoryIdentifier` was not available to confirm a concrete divergent URL. This should be validated by a Devin session with full repo access: instantiate `updateRemoteUrl` with a spoofed `IAPIRepository.clone_url` value and a real `defaultRemote`, and search for a URL string where `URL.parse().protocol` matches the existing remote's protocol while `parseRepositoryIdentifier`/`urlMatchesRemote` disagree in the direction needed to satisfy `remoteUrlUnchanged && !urlsMatch`.

  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

export function urlMatchesCloneURL(
  url: string,
  gitHubRepository: GitHubRepository
): boolean {
  if (gitHubRepository.cloneURL === null) {
    return false
  }

  return urlsMatch(gitHubRepository.cloneURL, url)
}

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}
