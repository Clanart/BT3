### Title
Missing zero/null puzzle-hash validation in pool wallet `target_puzzle_hash` allows permanent loss of pool rewards - (File: chia/pools/pool_wallet.py)

### Summary
`PoolWallet._verify_pool_state()` is the only sanity check applied to a `PoolState.target_puzzle_hash` before it is committed to a plot-NFT/pool singleton, and it only rejects the value when it is `None`. Since `PoolState.target_puzzle_hash` is a non-optional `bytes32`, that `is None` check can never actually trigger, meaning a caller-supplied all-zero puzzle hash (`bytes32.zeros`) passes validation unchecked, analogous to the reported Solidity issue where setter functions accepted a zero address because no explicit zero-value check existed.

### Finding Description
`PoolState.target_puzzle_hash` is documented as "the final destination" for pool rewards [1](#0-0) . The only guard applied when accepting a new/initial pool state is `_verify_pool_state`, which checks `state.target_puzzle_hash is None` and otherwise defers to `_verify_self_pooled`/`_verify_pooling_state`, neither of which inspects the actual puzzle-hash value: `_verify_self_pooled` only checks `pool_url`/`relative_lock_height`, and `_verify_pooling_state` only checks `relative_lock_height` bounds and `pool_url` emptiness [2](#0-1) .

Because `target_puzzle_hash` is typed as `bytes32` (not `Optional[bytes32]`), the `is None` branch is effectively dead code — a caller can supply `bytes32.zeros` (the all-zero puzzle hash) and it will pass this check unmodified. This value flows directly into `create_pool_state()` [3](#0-2)  and from there into `pool_state_to_inner_puzzle()`, which curries it straight into the on-chain member/waiting-room inner puzzle as the reward payout destination [4](#0-3) . The existing test suite even demonstrates this path being exercised with a zero puzzle hash accepted without any rejection when calling `pw_join_pool` with `target_puzzlehash=bytes32.zeros` [5](#0-4) .

This is directly reachable by an unprivileged local wallet RPC caller (the owner of a plot NFT) through the `pw_join_pool` RPC endpoint (self-service state transition), or through `create_new_wallet`'s `NewPoolWalletInitialTargetState`, both of which ultimately call `_verify_initial_target_state` / `generate_travel_transactions`, neither of which perform a non-zero puzzle-hash check [6](#0-5) [7](#0-6) .

### Impact Explanation
If a plot-NFT owner (or a malicious/misbehaving pool server whose `pool_info` response supplies `target_puzzle_hash`) causes the wallet to accept an all-zero puzzle hash as the pool state's `target_puzzle_hash`, all future pool reward absorption (`claim_pool_rewards`) and the terminal payout of the singleton will pay coins to the unspendable zero puzzle hash, permanently burning farming rewards for that plot NFT. Note in `chia/cmds/plotnft_funcs.py`, the pool's `target_puzzle_hash` returned from a remote `/pool_info` HTTP response is parsed and used directly (`target_puzzle_hash = bytes32.from_hexstr(json_dict["target_puzzle_hash"])`) without a zero check before being passed into `create_new_wallet`/`pw_join_pool` [8](#0-7) [9](#0-8) . This qualifies as a spend-triggered fund-loss/lock condition reachable from a normal wallet operation, matching the report's "can lock the contract"/fund-locking impact class.

### Likelihood Explanation
Medium likelihood: this requires either (a) a user/CLI/RPC-caller mistake passing a zero-filled address (analogous to the original report's "accidentally sent as zero address" scenario) or (b) a malicious/compromised pool server returning a zero `target_puzzle_hash` in its `/pool_info` response, which the wallet code parses and forwards without validation. It does not require any protocol-level attack, malicious peer, or privileged access — a single RPC call from the wallet owner (or accepting a bad pool response) is sufficient to reach the vulnerable code path.

### Recommendation
Add an explicit check in `PoolWallet._verify_pool_state` (and/or in `initial_pool_state_from_dict`/`create_pool_state`) that rejects `target_puzzle_hash == bytes32.zeros` (and any other well-known burn addresses if applicable) in addition to the current `is None` check, so that both self-pooling and farming-to-pool states cannot be created or transitioned to with a null/zero destination puzzle hash. Apply the same validation to pool-supplied `target_puzzle_hash` values before they are used in `chia/cmds/plotnft_funcs.py`'s `create_pool_args`/`join_pool` flows.

### Proof of Concept
1. Call the wallet RPC `pw_join_pool` with `target_puzzlehash=bytes32.zeros` (as exercised in the existing test) [10](#0-9) .
2. `PoolWallet.generate_travel_transactions` builds a `PoolState` with `target_puzzle_hash=bytes32.zeros`, curries it into the on-chain inner puzzle via `pool_state_to_inner_puzzle` [11](#0-10) , and the transaction is confirmed since `_verify_pool_state`'s only related check (`is None`) never fires for a valid `bytes32` value.
3. Subsequent `claim_pool_rewards`/absorb spends will pay accumulated block rewards for that singleton to the zero puzzle hash, which is unspendable, permanently destroying those rewards.

class PoolState(Streamable):
    """
    `PoolState` is a type that is serialized to the blockchain to track the state of the user's pool singleton
    `target_puzzle_hash` is either the pool address, or the self-pooling address that pool rewards will be paid to.
    `target_puzzle_hash` is NOT the p2_singleton puzzle that block rewards are sent to.
    The `p2_singleton` address is the initial address, and the `target_puzzle_hash` is the final destination.
    `relative_lock_height` is zero when in SELF_POOLING state
    """

    version: uint8
    state: uint8  # PoolSingletonState
    # `target_puzzle_hash`: A puzzle_hash we pay to
    # When self-farming, this is a main wallet address
    # When farming-to-pool, the pool sends this to the farmer during pool protocol setup

    # owner_pubkey is set by the wallet, once
    owner_pubkey: G1Element
    pool_url: str | None
    relative_lock_height: uint32

    def _verify_self_pooled(cls, state: PoolState) -> str | None:
        err = ""
        if state.pool_url not in {None, ""}:
            err += " Unneeded pool_url for self-pooling"

        if state.relative_lock_height != 0:
            err += " Incorrect relative_lock_height for self-pooling"

        return None if err == "" else err

    @classmethod
    def _verify_pooling_state(cls, state: PoolState) -> str | None:
        err = ""
        if state.relative_lock_height < cls.MINIMUM_RELATIVE_LOCK_HEIGHT:
            err += (
                f" Pool relative_lock_height ({state.relative_lock_height})"
                f"is less than recommended minimum ({cls.MINIMUM_RELATIVE_LOCK_HEIGHT})"
            )
        elif state.relative_lock_height > cls.MAXIMUM_RELATIVE_LOCK_HEIGHT:
            err += (
                f" Pool relative_lock_height ({state.relative_lock_height})"
                f"is greater than recommended maximum ({cls.MAXIMUM_RELATIVE_LOCK_HEIGHT})"
            )

        if state.pool_url in {None, ""}:
            err += " Empty pool url in pooling state"
        return err

    @classmethod
    def _verify_pool_state(cls, state: PoolState) -> str | None:
        if state.target_puzzle_hash is None:
            return "Invalid puzzle_hash"

        if state.version > POOL_PROTOCOL_VERSION:
            return (
                f"Detected pool protocol version {state.version}, which is "
                f"newer than this wallet's version ({POOL_PROTOCOL_VERSION}). Please upgrade "
                f"to use this pooling wallet"
            )

        if state.state == PoolSingletonState.SELF_POOLING.value:
            return cls._verify_self_pooled(state)
        elif state.state in {PoolSingletonState.FARMING_TO_POOL.value, PoolSingletonState.LEAVING_POOL.value}:
            return cls._verify_pooling_state(state)
        else:
            return "Internal Error"

def pool_state_to_inner_puzzle(
    pool_state: PoolState, launcher_id: bytes32, genesis_challenge: bytes32, delay_time: uint64, delay_ph: bytes32
) -> Program:
    escaping_inner_puzzle: Program = create_waiting_room_inner_puzzle(
        pool_state.target_puzzle_hash,
        pool_state.relative_lock_height,
        pool_state.owner_pubkey,
        launcher_id,
        genesis_challenge,
        delay_time,
        delay_ph,
    )
    if pool_state.state in {LEAVING_POOL.value, SELF_POOLING.value}:
        return escaping_inner_puzzle
    else:
        return create_pooling_inner_puzzle(
            pool_state.target_puzzle_hash,
            escaping_inner_puzzle.get_tree_hash(),
            pool_state.owner_pubkey,
            launcher_id,
            genesis_challenge,
            delay_time,
            delay_ph,
        )
