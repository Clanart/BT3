### Title
`InternalLazyField`/`LazyFieldLite` silently substitutes a default/stale instance for a corrupted MessageSet extension, hiding attacker-controlled sub-message content from downstream field checks - (File: `java/core/src/main/java/com/google/protobuf/InternalLazyField.java`, `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
Java protobuf's lazy-extension machinery (`InternalLazyField.getValue()` and `LazyFieldLite.mergeFrom()`/`merge()`) can, on legacy/eager-parse-disabled paths, catch `InvalidProtocolBufferException` for a corrupted or malformed extension payload and silently return a default instance or drop the update — with no exception surfaced to the caller and no log — instead of failing the parse. This mirrors the Kora bug's core defect: an unrecognized/unparsable inner payload is converted into an "empty stub" that satisfies structural checks (the outer message parses fine, the extension slot exists) while application logic that inspects the actual sub-message content for policy decisions never sees the real (or any) data.

### Finding Description
`InternalLazyField.getValue()` at [1](#0-0)  explicitly implements two behaviors gated by `extensionRegistry.lazyExtensionEnabled()`: when the "old behavior" path is active, a corrupted lazy field's `InvalidProtocolBufferException` is swallowed and the **default instance** of the extension type is returned instead of propagating the error. The `ensureInitialized()` method captures this "corrupted" state at [2](#0-1)  but the outer `getValue()` decides, based only on a registry flag, whether callers ever learn parsing failed.

`LazyFieldLite.mergeFrom()` exhibits the same pattern unconditionally for the lite runtime: `catch (InvalidProtocolBufferException e) { // Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto was invalid. }` at [3](#0-2) , and `mergeValueAndBytes()` has the identical swallow-and-keep-old-value pattern at [4](#0-3) .

The invariant that fails to transfer cleanly, and the reason this is a **weak, not strong**, analog: in Kora, the stub is silently substituted for *any* unrecognized instruction and then reaches a policy engine that treats absence-of-match as "no risk," directly enabling fund theft. In protobuf, this behavior is:
- Restricted to the legacy `LazyExtensionMode` used only for `MessageSet`-style lazy extensions, gated by a static/instance flag (`lazyExtensionModeOverride`, default `EAGER`) — the "silently return default instance" branch corresponds to the **old, non-default** behavior; the current default (`EAGER`) parses eagerly and would throw normally during the initial merge, not defer failure to `getValue()`.
- A corrupted payload, not an "unrecognized type" in the sense of the report (Kora's bug is about *valid* data whose *instruction type tag* isn't in a known list; protobuf's unknown fields/extensions are preserved byte-for-byte in `UnknownFieldSet`/`UnknownFieldSetLite`, which is the opposite of Kora's behavior — Protobuf's actual "unknown" handling round-trips data rather than discarding it, as shown in `UnknownFieldSet.MergeFieldFrom` [5](#0-4)  and Java's `MessageReflection.mergeFieldFrom` unknown-field skip path [6](#0-5) ).
- Requires that consuming application code make a security decision based on the *content* of a lazily-parsed extension field, and that code path specifically use the pre-`EAGER` legacy mode or a lite-only `LazyFieldLite` merge sequence with a corrupted/attacker-crafted byte string for that specific extension.

### Impact Explanation
If a consuming application performs a security-relevant check strictly against a message's fields (e.g., an authorization or metadata extension) and that extension is represented via `LazyFieldLite`/`InternalLazyField` with legacy lazy semantics, an attacker-controlled corrupted byte sequence for just that extension field can cause the check to silently operate on a default (empty) instance instead of failing the whole parse — potentially bypassing whatever field the app expected to enforce (e.g., a "signed_by" or "policy" extension field defaulting to zero/empty rather than raising a decode error). This is analogous to Kora's fee-payer-policy bypass in spirit (silent substitution defeats field-level enforcement) but the mechanism, defaults, and blast radius are far narrower — it is scoped to a specific legacy runtime mode for a niche feature (`MessageSet` lazy extensions), not a general-purpose parser code path exercised by every client.

### Likelihood Explanation
Low. The vulnerable "silently return default instance" branch in `InternalLazyField.getValue()` only executes when `lazyExtensionEnabled()` is true, which is not the default (`EAGER` mode is default per `ExtensionRegistryLite.getLazyExtensionMode()` initialization [7](#0-6) ). The `LazyFieldLite.mergeFrom`/`mergeValueAndBytes` swallow-and-keep behavior is unconditional but only affects `LazyFieldLite`-based paths (used for `MessageSet` and specific lazy fields), not the general binary/ProtoJSON parse path most applications rely on for field-by-field validation. This is a narrow, opt-in surface, not a default-path defect analogous to Kora's always-on instruction dispatch.

### Recommendation
- Ensure `LazyFieldLite.mergeFrom()`/`mergeValueAndBytes()` propagate `InvalidProtocolBufferException` (or at minimum mark the containing message invalid / log loudly) rather than silently discarding corrupted extension bytes, closing the "unaware of invalid proto" behavior noted in the code comment.
- Deprecate/remove the legacy (non-`EAGER`) `LazyExtensionMode` path in `InternalLazyField.getValue()` that substitutes a default instance for corrupted lazy fields, or require explicit opt-in with prominent documentation that consumers must treat default-valued lazy extension fields as potentially indicating a parse failure, not attacker-supplied absence.
- Any application relying on extension-field content for authorization decisions should call `ensureInitialized()`/force eager parsing and check for thrown exceptions rather than trusting default-valued fields.

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }
