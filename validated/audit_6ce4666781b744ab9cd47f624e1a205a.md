## Analysis

The external report's core pattern — a privileged cross-cutting action gated only by a coarse check (`onlySelfOrModule`) rather than a precise identity check — has a direct analog in Hyperbridge's EVM `HostManager` contract, which authorizes cross-chain governance calls (`updateHostParams`, `withdraw`) based **only on the source chain ID**, never on the sending module's identity.

### Title
Insufficient module-identity check in `HostManager.onAccept` lets any Hyperbridge-side module trigger `EvmHost` governance actions - (File: `evm/src/core/HostManager.sol`)

### Summary
`HostManager.onAccept` is the single entry point through which cross-chain "governance" messages from the Hyperbridge/Nexus parachain reach the EVM `EvmHost` and execute `updateHostParams` or `withdraw`. It validates only that the request's `source` state machine equals the configured `hyperbridge` chain id — it never checks `request.from` (the sending module/pallet id on that chain). [1](#0-0) 

### Finding Description
On the Substrate side, `pallet-host-executive::update_host_params`/`set_host_params` are properly gated behind `T::HostExecutiveOrigin::ensure_origin(origin)?` before constructing a `DispatchPost{ to: inner.host_manager, from: PALLET_ID, body: HostParams }` and calling the generic `IsmpDispatcher`. [2](#0-1) 

However, `pallet-ismp`'s `IsmpDispatcher::dispatch_request` is a **generic, unauthenticated primitive**: any pallet in the runtime can call it with an arbitrary attacker/pallet-chosen `to` and `body`, while `from`, `to`, and `source` are only meaningfully bound by the caller's own choice, not verified against any registry of "who is allowed to target the HostManager module id." [3](#0-2) 

The documented pattern for building pallets confirms `to`/`from`/`body` are fully composable by any calling pallet/extrinsic (e.g. `dispatch_to_evm`), with `from` simply set to the caller's own `PALLET_ID` — nothing on the sending side or the ISMP dispatcher enforces that only `pallet-host-executive` may set `to = <the EVM HostManager address>`. [4](#0-3) 

On the receiving EVM side, `EvmHost.updateHostParams` is `restrict(_hostParams.hostManager)` — i.e., it trusts *any* call coming from the `HostManager` contract. [5](#0-4) 

`HostManager.onAccept` is the only gate standing between an arbitrary Hyperbridge-chain module and this trusted call, and it checks only the chain id, not the module id: [6](#0-5) 

Because no per-module authorization exists at the destination (`HostManager` never checks `request.from` against `HYPERBRIDGE_MODULE_ID`/`host-executive`'s pallet id, the way, e.g., the `ProxyModule` router matches destination `to` against specific registered `pallet_id`s), **any pallet on the Hyperbridge/Nexus chain that is able to dispatch an ISMP POST request with `to` set to the EVM `HostManager` address** — not just the governance-restricted `pallet-host-executive` — can reach `updateHostParams` (rewriting `admin`, `handler`, `consensusClient`, `hostManager`, `feeToken`) or `withdraw` (draining bridge revenue to an arbitrary `beneficiary`) on the destination `EvmHost`. This mirrors the report's flaw exactly: a critical, meant-to-be-privileged function (`onlySelfOrModule` in the original report; `restrict(hostManager)`/module-routing here) is reachable by any registered module rather than only the one specific authorized identity.

### Impact Explanation
An unauthorized module reaching `updateHostParams` can rewrite the `EvmHost`'s admin, handler, consensus client, or host manager address — a full protocol takeover primitive — or reach `withdraw` to redirect escrowed bridge revenue to an attacker-chosen beneficiary. This is unauthorized execution and potential direct loss of funds, matching the bounty's "unauthorized transaction or execution" / "logic attacks" / "stealing or loss of funds" categories.

### Likelihood Explanation
Exploitability depends on whether any other pallet in the deployed Hyperbridge/Nexus runtime (besides `pallet-host-executive`) is able to call the generic `IsmpDispatcher::dispatch_request` with attacker/pallet-controlled `to` and `body` targeting the `HostManager` contract address. I could not fully verify from the indexed code whether such a pallet currently exists in the production `gargantua`/`nexus` runtimes beyond the demo pallets (whose bodies are hardcoded, not attacker-controlled) — this is the key open question and reduces confidence to Low-Medium. The structural gap (no `from`/module-id check in `HostManager.onAccept`) is nonetheless real and directly verifiable in code.

### Recommendation
In `HostManager.onAccept`, additionally verify `request.from` equals the specific expected module id for `pallet-host-executive` (or whichever single pallet is authorized to issue `SetHostParam`/`Withdraw` actions), not merely `request.source`. This closes the module-identity gap analogous to restricting the report's flagged functions to a single authorized caller instead of any registered module.

### Proof of Concept
1. On the Hyperbridge/Nexus chain, from any pallet/extrinsic capable of invoking `T::IsmpDispatcher::dispatch_request` (per the documented generic pattern in `modules/pallets/demo/src/lib.rs:216-239` or `docs/content/developers/polkadot/dispatching.mdx:57-77`), construct:
   - `dest = StateMachine::Evm(<hostChainId>)`
   - `to = <HostManager contract address>` (public, known)
   - `from = <this pallet's own id>` (arbitrary, unchecked by destination)
   - `body = [SetHostParam byte] ++ abi.encode(HostParams{ hostManager: attackerContract, admin: attacker, ... })`
2. Once delivered and proven on EVM, `EvmHost.dispatchIncoming` routes to `HostManager.onAccept` (`evm/src/core/HostManager.sol:95`), which checks only `request.source == hyperbridge`, passes, and calls `IHostManager(_params.host).updateHostParams(hostParams)` (`evm/src/core/HostManager.sol:105-107`).
3. `EvmHost.updateHostParams` executes because the caller is the trusted `HostManager` contract (`evm/src/core/EvmHost.sol:573`), rewriting critical host parameters despite the request never having gone through `pallet-host-executive`'s `HostExecutiveOrigin` gate.

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }

	fn dispatch_request(
		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,
					to: dispatch_post.to,
					timeout_timestamp: if dispatch_post.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

		let commitment = Pallet::<T>::dispatch_request(request, fee)?;

		Ok(commitment)
	}
