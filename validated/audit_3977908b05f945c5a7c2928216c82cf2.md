**Analysis:**

Tracing the path: `CICheckRunStepListHeader.renderLinkExternal` invokes `onViewCheckExternally` [1](#0-0)  which in the pull-request-checks-failed notification resolves to `onViewSelectedCheckRunOnGitHub` → `onViewOnGitHub`, which opens `checkRun.htmlUrl` directly via `dispatcher.openInBrowser(url)` [2](#0-1) . `openInBrowser` ultimately calls `shell.openExternal(url)` [3](#0-2) .

`checkRun.htmlUrl` is populated from the GitHub API's `html_url`/`details_url` field on a check run object [4](#0-3) . This is not a Desktop-introduced flaw: GitHub's Checks API explicitly allows the CI provider/app that creates a check run to set an arbitrary `details_url`, and GitHub.com itself links out to that exact URL when a user clicks "Details" on a check — third-party CI providers (CircleCI, Netlify, Travis, etc.) routinely populate this with their own domains. Desktop mirrors GitHub.com's intended behavior rather than introducing a new trust boundary violation.

Additionally, `shell.openExternal` opens the link in the user's default system browser, not an embedded/authenticated Desktop webview, so no GitHub Desktop session, OAuth token, or credential material is exposed to the destination page — the exposure is equivalent to the user clicking any ordinary hyperlink, and the browser's own address bar reveals the real destination host. There is no allowlist check missing here because there's no expectation that check-run detail links stay on `github.com`; that's the documented, intended semantics of the GitHub Checks feature. This does not meet the bar for a Desktop-specific security defect under the review scope.

```typescript
  private onViewOnGitHub = (checkRun: IRefCheck) => {
    const { repository, pullRequest, dispatcher } = this.props

    // Some checks do not provide htmlURLS like ones for the legacy status
    // object as they do not have a view in the checks screen. In that case we
    // will just open the PR and they can navigate from there... a little
    // dissatisfying tho more of an edgecase anyways.
    const url =
      checkRun.htmlUrl ??
      `${repository.gitHubRepository.htmlURL}/pull/${pullRequest.pullRequestNumber}`
    if (url === null) {
      // The repository should have a htmlURL.
      return
    }
    dispatcher.openInBrowser(url)
  }
```
