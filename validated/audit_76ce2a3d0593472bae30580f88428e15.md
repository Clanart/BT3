### Title
Scanner reports dust outputs as spendable inputs, letting an unprivileged sender flood the wallet with unprofitable UTXOs - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The Swan.sol bug class — a missing lower-bound check on an attacker-controlled numeric value allowing cheap flooding of a bounded resource — maps onto `Scanner::scan_transaction` in `bitcoin-serai`. `scan_transaction` registers every output paying to a tracked `script_pubkey` with no minimum-value check, and `SignableTransaction::new` never validates that inputs are worth more than the fee they add. An unprivileged party can send dust-valued outputs (1 sat, or anything below the ~57-vbyte input cost) to a Serai address; each is returned as a `ReceivedOutput`, indistinguishable from a real deposit.

### Finding Description
`Scanner::scan_transaction` (networks/bitcoin/src/wallet/mod.rs:199-214) pushes a `ReceivedOutput` for any `tx.output` whose `script_pubkey` is in `self.scripts`, with no check on `output.value`. The only bound anywhere in the wallet code is `DUST` (send.rs), and it is applied solely to `payments` at `SignableTransaction::new` (send.rs:165-169) — never to `inputs`. Meanwhile, every added input costs ~230 weight units (~57 vbytes, send.rs:606-620 in processor/networks/bitcoin.rs) and increases `needed_fee` accordingly (send.rs:204-213). A ReceivedOutput worth less than the marginal fee it imposes is net-negative: including it drains value rather than adding it.

The processor-side scanner compensates with an explicit `output.balance().amount.0 >= N::DUST` filter (processor/src/multisigs/scanner.rs:562-566), proving the library authors recognized dust as a threat — but the in-scope `bitcoin-serai` library itself, which is what integrators consume, performs no such filtering. Like the Swan `list`/`relist` functions accepting `_price = 1`, the wallet accepts "price" (output value) = 1 sat with no floor.

### Impact Explanation
An unprivileged attacker sends many dust transactions to the multisig's P2TR address (or any registered offset address) for near-zero cost. Each output is reported by `scan_transaction`/`scan_block` as a spendable `ReceivedOutput`. A wallet that naively consolidates scanned outputs produces transactions that pay more in fees than the dust contributes — funds reported received are effectively not spendable at a profit — and enough dust inputs push the transaction over `MAX_STANDARD_TX_WEIGHT` (send.rs:241), causing `TooLargeTransaction` errors and a DoS on withdrawal construction until the dust is manually excluded.

### Likelihood Explanation
Medium likelihood: sending dust to a known watch-only address requires only mempool-standard transactions and trivial fees. Impact is bounded (fee drain / consolidation DoS, no key or signature compromise), so Medium overall.

### Recommendation
Enforce a minimum value on inputs mirroring the payment-side check: reject or skip outputs with `value < DUST` inside `Scanner::scan_transaction`, or validate `input.output.value >= DUST` (or at least `> marginal input fee`) in `SignableTransaction::new`.

### Proof of Concept
```rust
let mut scanner = Scanner::new(key).unwrap();
// Attacker broadcasts a tx paying `key`'s script with value = 1 sat
let tx = Transaction {
  output: vec![TxOut { value: Amount::from_sat(1), script_pubkey: p2tr_script_buf(key).unwrap() }],
  ..Default::default()
};
let outputs = scanner.scan_transaction(&tx);
// Reported as a spendable ReceivedOutput despite being worth less than its spend fee
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].value(), 1); // 1 sat < 57 vbytes * fee_per_vbyte marginal cost
```
`SignableTransaction::new(vec![outputs[0].clone()], &payments, ...)` accepts it as an input with no dust validation, inflating `needed_fee` beyond the input's value — the analog of listing an asset at `_price = 1`. [1](#0-0) [2](#0-1) [3](#0-2)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
