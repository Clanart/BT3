### Title
`ThresholdKeys::read` trusts serialized secret/verification shares without any consistency check, enabling a crafted key blob to redefine `group_key` and inject an unspendable attacker key - (File: crypto/dkg/src/lib.rs)

### Summary
The external report concerns a deserialization path where crafted stored data is trusted and later drives privileged behavior. The Serai analog is `ThresholdKeys::<C>::read` in `crypto/dkg/src/lib.rs` (lines 574–632). It reconstructs a threshold keypair entirely from serialized bytes — `t`, `n`, `i`, interpolation coefficients, `secret_share`, and all `n` `verification_shares` — and passes them to `ThresholdKeys::new` (lines 349–391). `new` checks only share count, participant range, and interpolation applicability, then computes `group_key` as the interpolated sum of attacker-controlled `verification_shares` at lines 376–378. It never verifies that `secret_share` is consistent with `verification_shares[&params.i()]` (i.e., `generator * secret_share == verification_shares[i]`), and never verifies the shares encode a coherent polynomial. The same trust pattern exists in `crypto/dkg/pedpop/src/lib.rs` where `Commitments::read` (lines 110–128) reads `t` arbitrary group elements that later define every participant's verification shares in `calculate_share` (lines 505–521).

### Finding Description
- `ThresholdKeys::read` (`crypto/dkg/src/lib.rs:574-632`) deserializes every field of `ThresholdCore` from untrusted bytes. The only scalar/point validation is canonicality via `read_F`/`read_G` (`crypto/ciphersuite/src/lib.rs:74-101`); there is no semantic validation.
- `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:349-391`) computes `group_key` purely from `verification_shares` and never checks `secret_share` matches `verification_shares[i]` nor that any verification share equals `generator * share` of a shared polynomial.
- Consequently a crafted blob yields a `ThresholdKeys` whose `group_key()` is an arbitrary attacker-selected point while `secret_share` is an arbitrary unrelated scalar. `view()` then interpolates these forged shares and produces a `ThresholdView` used for FROST signing (`crypto/frost/src/sign.rs:312-398`), and downstream consumers (e.g., the multisig scanner in `processor/src/networks/bitcoin.rs:686-740`, which builds a `Scanner` from `key`/`register_offset`) treat `group_key` as the funds-receiving key.

### Impact Explanation
Two concrete impacts within the accepted classes:

1. **Funds reported received that are not spendable.** A poisoned `ThresholdKeys` yields an attacker-chosen `group_key` (e.g., a key the attacker solely controls, or a key no valid share set can sign for). The Bitcoin `Scanner` registers `p2tr_script_buf(key)` and reports deposits to it as received `ReceivedOutput`s (`networks/bitcoin/src/wallet/mod.rs:162-214`). Those outputs are either stealable by the attacker or unspendable by the protocol — the signature pipeline in `crypto/frost/src/sign.rs:447-495` will never produce a valid aggregate signature because the `secret_share`/share-verification inconsistency makes honest shares fail `verify`, yet the funds were already credited.
2. **Inconsistent threshold semantics.** Because `secret_share` is not bound to `verification_shares[i]`, a deserialized "participant i" can be given a share unrelated to the group key, breaking the t-of-n invariant that the rest of the codebase (e.g., `crypto/dkg/dealer/src/lib.rs:46-64`, which `debug_assert_eq!`s the group key, and `pedpop` `calculate_share`, which derives shares from verified commitments) assumes is guaranteed by construction.

### Likelihood Explanation
Mirroring the advisory, this requires a crafted serialized `ThresholdKeys` blob to reach `ThresholdKeys::read` — i.e., write access to the persisted key material (DB/keystore) or a transport path feeding untrusted bytes into `read`. Serai's docs note `ThresholdKeys` is stored/rehydrated by the coordinator/processor; the rules exclude honest-validator-produced data but explicitly allow untrusted bytes fed to `ThresholdKeys::read`. Under that condition the attack is deterministic: no probabilistic element, and the inconsistency is only detectable later when signing fails. Severity is High (fund crediting of unspendable/attacker-owned outputs); likelihood is bounded by the need to poison stored key material, same as the source advisory.

### Recommendation
In `ThresholdKeys::new` (and thus `read`), verify consistency before accepting the keys:
- Check `C::generator() * secret_share == verification_shares[&params.i()]` — this binds the deserialized secret share to the verification shares.
- For `Interpolation::Lagrange`, optionally verify `group_key` consistency by recomputing and, where feasible, checking each verification share lies on the implied polynomial (or at minimum document that `ThresholdKeys` must only be deserialized from trusted/authenticated storage and add authentication on the persisted bytes).
- Apply the same principle to `Commitments::read` consumers: the existing Schnorr PoK at `crypto/dkg/pedpop/src/lib.rs:323-329` binds knowledge of `commitments[0]`'s discrete log, but commitments identity/non-degeneracy should be enforced at read time rather than relying on callers.

```rust
// Conceptual PoC against crypto/dkg/src/lib.rs ThresholdKeys::read
// Craft bytes for Secp256k1 (C::ID matching) with t=2, n=3, i=1.

use frost::curve::Secp256k1 as C;
use ciphersuite::Ciphersuite;
use dkg::{ThresholdKeys, Participant};
use zeroize::Zeroizing;

// Attacker-chosen full secret key
let attacker_secret = C::random_nonzero_F(&mut rand_core::OsRng);
let attacker_key = C::generator() * attacker_secret;

// Build verification_shares so that participants 1..=t interpolate to attacker_key.
// Simplest: v1 = attacker_key - v2 (for t=2 Lagrange factors over {1,2}:
//   f(1)=2*1/(2-1)... pick Lagrange coefficients l1=-1, l2=2 for x=0:
//   group_key = -v1 + 2*v2. Set v2 = identity won't pass; choose v2 random, v1 = 2*v2 - attacker_key.
let v2 = C::generator() * C::random_nonzero_F(&mut rand_core::OsRng);
let v1 = v2 + v2 - attacker_key; // so -v1 + 2*v2 == attacker_key

// Serialized format (write() in crypto/dkg/src/lib.rs:538-562):
//   u32 id_len, id bytes, u16 t, u16 n, u16 i, interpolation tag (1=Lagrange),
//   secret_share repr, then n verification-share point encodings.
let mut blob = vec![];
blob.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
blob.extend(C::ID);
blob.extend(2u16.to_le_bytes());          // t
blob.extend(3u16.to_le_bytes());          // n
blob.extend(1u16.to_le_bytes());          // i
blob.push(1);                             // Interpolation::Lagrange
// secret_share: arbitrary scalar unrelated to verification_shares[1]
blob.extend(C::random_nonzero_F(&mut rand_core::OsRng).to_repr().as_ref());
blob.extend(v1.to_bytes().as_ref());
blob.extend(v2.to_bytes().as_ref());
blob.extend((C::generator() * C::random_nonzero_F(&mut rand_core::OsRng)).to_bytes().as_ref());

let keys = ThresholdKeys::<C>::read(&mut blob.as_slice()).unwrap();
// Accepted: group_key() == attacker_key, secret_share unrelated to it.
assert_eq!(keys.group_key(), attacker_key);
// Scanner::new(keys.group_key()) now credits deposits to an attacker-owned key,
// and sign() on any inclusion set can never produce a valid aggregate signature.
```

Root cause: `ThresholdKeys::read`/`new` performs only syntactic (canonicality, count, range) checks and omits the semantic check binding `secret_share` to `verification_shares[i]` and the shares to a self-consistent polynomial — the Serai analogue of trusting a crafted stored object during deserialization.     params: ThresholdParams,
```rust
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,

  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
  }
```

```rust
  fn read_F<R: Read>(reader: &mut R) -> io::Result<Self::F> {
    let mut encoding = <Self::F as PrimeField>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    // ff mandates this is canonical
    let res = Option::<Self::F>::from(Self::F::from_repr(encoding))
      .ok_or_else(|| io::Error::other("non-canonical scalar"));
    encoding.as_mut().zeroize();
    res
  }

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
```

```rust
      responses.insert(l, share.0);
      sum += share.0;

    // For the success route, which should be much more frequent, this should be faster
    // It also acts as an integrity check of this library's signing function
    if let Some(sig) = self.params.algorithm.verify(self.view.group_key(), &self.Rs, sum) {
      return Ok(sig);
    }

    // We could remove blame_entropy by taking in an RNG here
    // Considering we don't need any RNG for a valid signature, and we only use the RNG here for
    // performance reasons, it doesn't feel worthwhile to include as an argument to every
    // implementor of the trait
    let mut rng = ChaCha20Rng::from_seed(self.blame_entropy);
    let mut batch = BatchVerifier::new(self.view.included().len());

        self.view.verification_share(*l),
        &self.B.bound(*l),

    // The only known way to cause this, for valid parameters/algorithms, is to deserialize a

    Err(FrostError::InternalError("everyone had a valid share yet the signature was still invalid"))
```

```rust
  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
