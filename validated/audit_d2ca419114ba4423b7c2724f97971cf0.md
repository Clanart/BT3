## Analog Found: Incomplete Redaction Traversal in `TextFormat::IsOptionSensitive` Silently Leaks `debug_redact` Fields Through Meta-Annotated Options

### Title
Meta-Annotation-Based Field Redaction Silently Fails to Honor Nested `debug_redact` Fields in Debug/Log Output - (File: `src/google/protobuf/text_format.cc`)

### Summary
Protobuf provides a `debug_redact` field option (defined in `descriptor.proto`) specifically to prevent sensitive field values from appearing in `DebugString()`, `TextFormat` debug printers, and `AbslStringify`/logging output [1](#0-0) . This mirrors exactly the failure class in the NiFi advisory (CWE-532: sensitive values reaching application logs). Protobuf's C++ implementation additionally supports transitive/meta-annotation-based redaction, where a custom field option message can mark a target field as sensitive indirectly through `TextFormat::IsOptionSensitive` [2](#0-1) . That traversal, however, only propagates redaction when the nested option is an `ENUM` (checking `debug_redact` on the selected enum value) or recurses into nested `MESSAGE` options — it never checks whether a nested option message's own *field* carries `debug_redact = true` directly. As a result, a field intentionally marked sensitive via a nested option is not redacted, and its value is printed in plaintext by `DebugString()`/`AbslStringify()`, which are exactly the APIs application code (and default logging integrations, e.g., via `absl::StrCat`/`ABSL_LOG`) uses to emit debug logs.

### Finding Description
`debug_redact` is protobuf's built-in mitigation for CWE-532-style disclosure through debug logs: setting it on a field guarantees `[REDACTED]` is emitted instead of the value by `TextFormat::Printer::TryRedactFieldValue` [3](#0-2) . Whether a field must be redacted is computed by `TextFormat::GetRedactionState`, which checks the field's own `options().debug_redact()` and then walks any options set on the field looking for further sensitivity via `IsOptionSensitive` [4](#0-3) .

`IsOptionSensitive` only implements two propagation rules [5](#0-4) :
1. If the option field is an `ENUM`, redact if the resolved `EnumValueDescriptor`'s own options have `debug_redact()` set.
2. If the option field is a `MESSAGE`, recurse into that sub-message's *set* fields and call `IsOptionSensitive` again on each.

Crucially, the recursive call at step 2 re-applies the same two rules to each nested field — it never independently checks `field->options().debug_redact()` for a nested option field the way `GetRedactionState` does for the top-level field. So a `string`/`bytes`/other non-enum, non-message field nested inside an option message, even if explicitly annotated `debug_redact = true` in its own schema, is never detected as sensitive when reached through this indirect (meta-annotation) path.

This exact gap is reproduced and codified by the repo's own test suite: `unittest_redaction.proto` defines `TestNestedMessageEnum.redacted_string` with `debug_redact = true` [6](#0-5) , and a target field `test_redacted_message_enum` is meta-annotated to reference it via the `test_nested_message_enum` custom option, embedding `redacted_string: "redacted_but_doesnt_redact"` [7](#0-6) . The corresponding unit test, `StringifyRedactedOptionDoesNotRedact`, explicitly asserts the field is emitted **unredacted** by `absl::StrCat(proto)` (i.e., `AbslStringify`, the mechanism used by generic logging sinks) [8](#0-7) . This confirms the gap is a real, currently-existing behavior of the shipped code rather than a hypothetical.

### Impact Explanation
Any application relying on protobuf's field-level or meta-annotation-level `debug_redact` mechanism to keep sensitive values (credentials, PII, tokens embedded in a schema field marked sensitive via a nested/meta option) out of debug logs will have that expectation silently violated for the meta-annotated path. Because `Message::DebugString()`, `ShortDebugString()`, `Utf8DebugString()`, and the `AbslStringify` hook (`sink.Append(internal::StringifyMessage(message))`) all funnel through the same `TextFormat::Printer` redaction logic [9](#0-8) [10](#0-9) , any log statement, `absl::StrCat`, or generic diagnostic dump of the message will disclose the value. This matches the NiFi advisory's impact class precisely: a documented, intended data-protection control (there: default non-debug logging; here: `debug_redact`) fails under a specific, reachable configuration, and sensitive information ends up in application logs (CWE-532).

### Likelihood Explanation
Likelihood is Medium: it requires a schema author to use the meta-annotation redaction feature (nested custom field options with `debug_redact` on an inner field) rather than the more common direct `debug_redact` on the field itself. Direct `debug_redact` usage (the vastly more common case, `RedactedFields` in `unittest.proto`) works correctly, as shown by the surrounding passing tests [11](#0-10) . Meta-annotation-based redaction is a newer/advanced feature, so exposure is limited to teams adopting it, but for those teams the failure is silent and deterministic — every debug-string/stringify call on such a field leaks it, with no error or warning.

### Recommendation
Update `TextFormat::IsOptionSensitive` (and any Java equivalent, `Descriptors.isOptionSensitive`, which has the identical structure at [12](#0-11) ) to also check `field->options().debug_redact()` directly for each nested option field before/independent of the enum/message-specific checks, mirroring the top-level check already performed in `GetRedactionState`. Add regression coverage that fails when a nested option field's own `debug_redact = true` is not honored (the existing `StringifyRedactedOptionDoesNotRedact` test currently asserts the *broken* behavior and should be inverted once fixed).

### Proof of Concept
Using the existing test fixtures in this repository:
1. Schema (`unittest_redaction.proto`) defines `TestNestedMessageEnum.redacted_string` with `debug_redact = true`, and `TestRedactedMessage.test_redacted_message_enum` carries a `(test_nested_message_enum)` option instance setting `redacted_string: "redacted_but_doesnt_redact"`.
2. Set `proto.set_test_redacted_message_enum("foo")` on a `TestRedactedMessage`.
3. Call `absl::StrCat(proto)` (or `proto.DebugString()`), which routes through `internal::StringifyMessage` → `TextFormat::Printer::TryRedactFieldValue` → `GetRedactionState` → `IsOptionSensitive`.
4. Observed/expected-by-test output: `test_redacted_message_enum: "foo"` — value printed in cleartext, **not** `[REDACTED]` — exactly as asserted by `StringifyRedactedOptionDoesNotRedact` [8](#0-7) , confirming the redaction bypass is reproducible with the checked-in test data.

// Traverse the tree of field options and check if any of them are sensitive.
// We check for sensitive enum values in the options and in the fields of the
// message-type options, recursively.
TextFormat::RedactionState TextFormat::IsOptionSensitive(
    const Message& opts, const Reflection* reflection,
    const FieldDescriptor* option) {
  if (option->type() == FieldDescriptor::TYPE_ENUM) {
    auto count =
        option->is_repeated() ? reflection->FieldSize(opts, option) : 1;
    for (auto i = 0; i < count; i++) {
      int enum_val = option->is_repeated()
                         ? reflection->GetRepeatedEnumValue(opts, option, i)
                         : reflection->GetEnumValue(opts, option);
      const EnumValueDescriptor* option_value =
          option->enum_type()->FindValueByNumber(enum_val);
      if (option_value == nullptr) {
        // Ignore values we don't know about.
        continue;
      }
      if (option_value->options().debug_redact()) {
        return TextFormat::RedactionState{true, false};
      }
    }
  } else if (option->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
    auto count =
        option->is_repeated() ? reflection->FieldSize(opts, option) : 1;
    for (auto i = 0; i < count; i++) {
      const Message& sub_message =
          option->is_repeated()
              ? reflection->GetRepeatedMessage(opts, option, i)
              : reflection->GetMessage(opts, option);
      const Reflection* sub_reflection = sub_message.GetReflection();
      std::vector<const FieldDescriptor*> message_fields;
      sub_reflection->ListFields(sub_message, &message_fields);
      for (const FieldDescriptor* message_field : message_fields) {
        auto result = TextFormat::IsOptionSensitive(sub_message, sub_reflection,
                                                    message_field);
        if (result.redact) {
          return result;
        }
      }
    }
  }
  return TextFormat::RedactionState{false, false};
}

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    @SuppressWarnings("unchecked") // List<EnumValueDescriptor> guaranteed by protobuf runtime.
    private static RedactionState isOptionSensitive(FieldDescriptor field, Object value) {
      if (field.getType() == Descriptors.FieldDescriptor.Type.ENUM) {
        if (field.isRepeated()) {
          for (EnumValueDescriptor v : (List<EnumValueDescriptor>) value) {
            if (v.getOptions().getDebugRedact()) {
              return RedactionState.of(true, false);
            }
          }
        } else {
          if (((EnumValueDescriptor) value).getOptions().getDebugRedact()) {
            return RedactionState.of(true, false);
          }
        }
      } else if (field.getJavaType() == Descriptors.FieldDescriptor.JavaType.MESSAGE) {
        if (field.isRepeated()) {
          for (Message m : (List<Message>) value) {
            for (Map.Entry<FieldDescriptor, Object> entry : m.getAllFields().entrySet()) {
              RedactionState state = isOptionSensitive(entry.getKey(), entry.getValue());
              if (state.redact) {
                return state;
              }
            }
          }
        } else {
          for (Map.Entry<FieldDescriptor, Object> entry :
              ((Message) value).getAllFields().entrySet()) {
            RedactionState state = isOptionSensitive(entry.getKey(), entry.getValue());
            if (state.redact) {
              return state;
            }
          }
        }
      }
      return RedactionState.of(false);
    }
