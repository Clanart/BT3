## Title
Debt asset always included in price resolution mask (unfiltered by enabled bitmap) → single unresolvable oracle feed permanently blocks borrow/repay/liquidate - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`get-assets` resolves a user's collateral+debt mask into an asset list with live prices via `price-multi-resolve`/`iter-price-multi`. Unlike collateral bits, which are intersected against the registry's `enabled` bitmap in `user-safe-mask`, debt bits are passed through unconditionally. If a single debt asset's price feed cannot be resolved (fails `oracle-price-legal` or `oracle-timestamp-fresh`, or the underlying Pyth/DIA call errors), `iter-price-multi` marks the whole batch invalid and `price-multi-resolve` reverts with `ERR-ORACLE-MULTI`, aborting `get-assets` entirely — exactly analogous to the reported HoneyFactory bug where a single bad collateral in the loop blocks the entire `mint` call rather than being skipped.

### Finding Description
`user-safe-mask` filters only the collateral half of the mask by the enabled-asset bitmap, but passes the debt half through unfiltered: [1](#0-0) 

`get-assets` then converts the resulting (partially-filtered) mask into a list of asset ids and batch-resolves all of their oracle prices: [2](#0-1) 

`price-multi-resolve`/`iter-price-multi` fold over every asset in that list; if `price-resolve` fails for even one entry, the whole result is marked invalid and the function reverts: [3](#0-2) 

`price-resolve` itself reverts with `ERR-ORACLE-INVARIANT` if the resolved price is non-positive or the feed timestamp is stale/non-monotonic relative to `max-staleness`: [4](#0-3) 

Because there is no admin mechanism to disable/skip a *debt* asset the way collateral can be excluded via the enabled bitmap, any borrower who has open debt in an asset whose feed goes stale, is delisted, or otherwise stops resolving will have `get-assets` unconditionally revert for their account — every code path that needs to evaluate the position (`borrow`, `repay`, and critically `liquidate`, all of which call `get-assets`/`get-notional-evaluation` after `get-position`/`get-full-position`/`get-liquidation-position`) is blocked, since these all funnel through `get-assets`: [5](#0-4) [6](#0-5) 

This mirrors the reported bug class precisely: the loop/fold has no "skip if bad/unresolvable" branch, so one broken entry blocks the operation for everyone touching that entry, instead of being isolated to just that asset.

### Impact Explanation
Once a debt asset's price feed becomes permanently unresolvable (feed deprecated, oracle contract stops publishing, staleness threshold repeatedly violated), no liquidator can call `liquidate` on any borrower who holds debt in that asset, because `get-liquidation-position` → `get-assets` → `price-multi-resolve` reverts before health/LTV can even be computed. The borrower also cannot `repay` to reduce their own exposure through the standard path (or add collateral to become healthy) since that too depends on `get-assets`. This is a protocol-insolvency-class impact: undercollateralized positions denominated in a "frozen-price" debt asset become permanently unliquidatable, and any of their backing collateral becomes permanently frozen for both the borrower and the liquidator/protocol.

### Likelihood Explanation
This does not require any admin misconfiguration or DAO action — it can be triggered purely by an external oracle feed (Pyth/DIA) going stale or being discontinued for a specific asset while open debt still exists in that asset, which is a realistic and foreseeable operational event (feed deprecation, provider outage beyond `max-staleness`, asset delisting from the oracle). Given assets like `USDH` rely on a single DIA source with no fallback and no way to bypass a broken feed for debt resolution, likelihood is medium-to-high over the protocol's lifetime.

### Recommendation
Mirror the collateral-side filtering for debt: either (a) allow governance to mark a specific asset's oracle as "frozen"/use a last-known-good price with an explicit flag rather than reverting the whole batch, or (b) make `price-multi-resolve`/`iter-price-multi` skip (rather than abort on) entries that fail resolution when computing liquidation eligibility, falling back to a governance-set emergency price for that single asset so `liquidate` and `repay` remain callable. At minimum, add an emergency-override path (analogous to Berachain's basket-mode-as-emergency-mode fix) so a single broken debt-asset feed cannot permanently block liquidation of a position.

### Proof of Concept
1. Attacker/borrower opens debt in asset `X` (e.g. `USDH`, oracle type `TYPE-DIA`) via `borrow`.
2. `X`'s DIA feed stops updating past `max-staleness`, or the DIA contract begins reverting on `get-value`.
3. Any call to `liquidate(borrower, ...)` on this position calls `get-liquidation-position` → `get-assets` → `price-multi-resolve`, which now fails `oracle-timestamp-fresh` (or the underlying `call-dia` reverts), causing `iter-price-multi` to set `valid: false` and `price-multi-resolve` to abort with `ERR-ORACLE-MULTI`. [3](#0-2) 
4. The `liquidate` transaction reverts unconditionally, regardless of how undercollateralized the position becomes, because there is no per-asset skip/fallback and debt bits are never excluded by `user-safe-mask` the way collateral bits are. [1](#0-0)

(define-private (price-resolve
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))

(define-private (price-multi-resolve
  (data (list 64 { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (aids (list 64 uint)))
  (let ((init { output: (list), valid: true, aids: aids, idx: u0 })
        (response (fold iter-price-multi data init)))
    (asserts! (get valid response) ERR-ORACLE-MULTI)
    (ok (get output response))))

(define-private (iter-price-multi
  (oracle-data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint })
  (acc { output: (list 64 uint), valid: bool, aids: (list 64 uint), idx: uint }))
  (let ((valid (get valid acc))
        (skip? (asserts! valid acc))
        (asset-ids (get aids acc))
        (idx (get idx acc))

    { output: next,
      valid: true,
      aids: asset-ids,
      idx: (+ idx u1) }))
