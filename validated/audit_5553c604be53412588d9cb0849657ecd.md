## Analysis

The Stylus report's underlying bug class is: **a nominal identity claim (the interface's declared selector) is trusted as proof of implementation-compatibility, without ever validating it against the real, concrete implementation.** The closest concrete analog in GitHub Desktop is the string-based "URL matching" logic that Desktop uses to decide whether a locally-tracked repository *is* the same repository referenced by an untrusted, attacker-influenceable payload (a PR object fetched from the GitHub API via a deep link), and then uses that unverified match to add a remote and fetch/checkout attacker-influenced refs.

### Title
Deep-link "Open PR" flow selects and mutates a local repository based on unverified hostname/owner/name string matching instead of true repository identity - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
`x-github-client://openrepo/...?pr=NNN` deep links are parsed by `parseAppURL` and routed to `openPullRequestFromUrl`, which fetches a pull request object from the GitHub API and then decides which already-open local repository to operate on using only string comparison of `owner`/`name`/`hostname` parsed out of `clone_url` — never a stable repository identifier. This "matching by name" is the same broken invariant as the Stylus report: a superficial selector/name match is accepted as proof that two things are "the same trait/interface implementation," when in fact GitHub repo names/owners are not stable identifiers (they can be renamed, deleted, and reused by unrelated accounts).

### Finding Description
`parseAppURL` (`app/src/lib/parse-app-url.ts:66-128`) turns a clicked link into an `open-repository-from-url` action carrying an attacker-supplied `url` and `pr` number: [1](#0-0) 

`openPullRequestFromUrl` in the dispatcher fetches the PR object for that `url`/`pr` from the GitHub API and then calls `getRepositoryFromPullRequest`: [2](#0-1) 

`getRepositoryFromPullRequest` searches the user's already-open repositories and treats a repository as "the PR's repository" purely if `doesRepositoryMatchUrl` returns true for the PR's `head.repo.clone_url` or `base.repo.clone_url`: [3](#0-2) 

`doesRepositoryMatchUrl` ultimately delegates to `urlsMatch`, which is a pure string comparison of hostname/owner/name extracted via regex in `remote-parsing.ts` — there is no check against any stable GitHub repository id: [4](#0-3) [5](#0-4) 

Once a "matching" local repository is selected, the dispatcher immediately performs a privileged, network-touching action, using an **attacker-controlled** `clone_url`/`ref` taken from the PR JSON (`pullRequest.head.repo.clone_url`, `pullRequest.head.ref`) to add a remote, fetch it, and check out a new local branch: [6](#0-5) [7](#0-6) 

The broken invariant: Desktop assumes "owner/name/hostname string match ⇒ this is the same repository the user already trusts and has open," exactly like the Rust bug assumed "selector present in trait ⇒ implementation is compatible." Neither checks the actual backing identity (a GitHub numeric repo id vs. a Cargo/Rust function signature). GitHub repository names and owner logins are **not stable**: repos can be deleted/renamed and the same owner/name pair can later be claimed by a different, unrelated GitHub account or repository. `urlsMatch`/`repositoryMatchesRemote` have no way to distinguish the original trusted repository from a same-named impostor.

### Impact Explanation
An attacker who can get a namesake repository (same owner login + repo name, e.g. after the original repo is renamed/deleted and the username/repo-name becomes available, or via a GHES/alternate host misconfiguration edge) can craft a link with a matching `openrepo` URL and a PR number on their own repo. When a victim who still has a Desktop repository entry for that owner/name clicks the link, `getRepositoryFromPullRequest` will resolve it to the victim's existing local repository purely by name equality, and Desktop will silently add a new remote and fetch/checkout a branch supplied entirely by the attacker's PR object into that repository's working tree — without any confirmation that this is genuinely the same project the user has been working on. This corrupts local repository state (extraneous remote + branch pointing at attacker content) under the pretense of "your PR review," which can mislead the user into building/running/committing on top of attacker-supplied code.

### Likelihood Explanation
Moderate-to-low but realistic: it requires (1) the victim to have previously used Desktop with a repository under a given owner/name, (2) that owner/name later becoming available and reclaimed (or hostname otherwise reused), and (3) the victim clicking a crafted `x-github-client://openrepo/...` link. GitHub does allow repo/owner renames and deletions, and username squatting/repo-name reuse is a known, previously exploited pattern in the wider GitHub ecosystem (e.g. dependency/repo-jacking), so the precondition is not far-fetched. No local access, malware, or leaked credentials are required — only a link click and an attacker-controlled PR that any GitHub user can open.

### Recommendation
Do not rely solely on hostname/owner/name string equality (`urlsMatch`, `repositoryMatchesRemote`, `urlMatchesRemote`) to decide that a PR's head/base repository is the same as an already-tracked local `GitHubRepository`. Instead, compare against the stored GitHub repository's stable numeric `id` (already fetched and cached as part of `GitHubRepository`/API responses) before treating a name-based match as authoritative, and require that id to be verified via an authenticated API call before adding remotes or performing fetch/checkout driven by data in the PR object.

### Proof of Concept
1. Victim has previously cloned/opened `https://github.com/victim-org/project` in Desktop (tracked locally with GitHub repository metadata for that owner/name).
2. `victim-org/project` is later deleted or renamed on GitHub, and the `victim-org` login (or just the `project` repo name under a reachable host) becomes available; attacker claims it and creates `victim-org/project` (or a same-named repo on a reachable alternate host) with a pull request whose `head.repo.clone_url`/`head.ref` point to attacker-controlled content.
3. Attacker sends the victim a link: `x-github-client://openrepo/https://github.com/victim-org/project?pr=<attacker-PR-number>`.
4. Victim clicks the link. `parseAppURL` → `openPullRequestFromUrl` (`app/src/ui/dispatcher/dispatcher.ts:1998`) fetches the PR, `getRepositoryFromPullRequest` (line 1890) matches it to the victim's pre-existing local `project` repository purely via `urlsMatch` string comparison, and `_checkoutPullRequest` (`app-store.ts:8613`) adds a remote from the attacker's `clone_url` and checks out a new local branch `pr/<n>` from it, with no indication to the user that the "matched" repository is not verified against a stable identity.

  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}

export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
