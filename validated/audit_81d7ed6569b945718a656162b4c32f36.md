### Title
Unbounded `storageKeys` array in `eth_getProof`/`kaia_getProof` enables RPC-triggered resource-exhaustion DoS - (File: api/api_eth.go)

### Summary
`EthAPI.GetProof` and `KaiaBlockChainAPI.GetProof` accept an arbitrary-length `storageKeys []string` parameter and pass it directly into `doGetProof`, which iterates over every key and performs a full Merkle-proof trie walk (`storageTrie.Prove`) for each one, with no upper bound on the number of keys a single RPC caller may request.

### Finding Description
`doGetProof` decodes every element of the caller-supplied `storageKeys` slice and then, for each decoded key, opens the account's storage trie and calls `storageTrie.Prove(...)`, which walks (and potentially resolves from disk) every node on the path to that key: [1](#0-0) 

Both public RPC entry points forward the caller-controlled slice unmodified: [2](#0-1) [3](#0-2) 

Unlike other range/list-based Kaia RPC APIs in this codebase — e.g. `GetLogs`/`GetFilterLogs`, which are bounded by `GetLogsMaxItems` and `GetLogsDeadline` ( [4](#0-3) ), `GetBlockWithConsensusInfoByNumberRange`, which is bounded by `maxConsensusInfoBlocks = 50` ( [5](#0-4) ), and `governance_getRewardsAccumulated`, which is bounded by `accumulatedRewardsRangeLimit` ( [6](#0-5) ) — `doGetProof` imposes no cap on `len(storageKeys)`. Each element triggers disk-backed trie node resolution and cryptographic proof generation (`crypto.Keccak256`, `hasher.hashChildren`, `hasher.store` per node on path) inside `(*Trie).Prove`: [7](#0-6) 

Because this all happens synchronously inside a single JSON-RPC call, the request-level protections that exist for other DoS classes are ineffective:
- `RPCBatchRequestLimit`/`RPCBatchResponseMaxSize` only cap the number/size of items in a JSON-RPC *batch*, not the size of a single method's array parameter ( [8](#0-7) ).
- `RPCConcurrencyLimit` and `pendingRequestLimit` only cap concurrent connections/pending calls, not per-call work.

An unauthenticated public-RPC caller can submit one `eth_getProof`/`kaia_getProof` request with a very large `storageKeys` array (e.g., hundreds of thousands of hex strings), forcing the node to perform that many trie-proof computations and trie-node disk reads in one call.

### Impact Explanation
This matches the reachable-and-in-scope "public RPC caller" surface. A single crafted RPC request can consume disproportionate CPU and I/O (trie node lookups/hashing) on a full/archive node, degrading or denying service to other RPC clients — the same unbounded-limit-params resource-exhaustion bug class as the referenced Discourse advisory (BIT-discourse-2023-38684 / CVE-2023-38684), applied here to `eth_getProof`/`kaia_getProof`.

### Likelihood Explanation
High likelihood: `eth_getProof`/`kaia_getProof` are standard, publicly exposed JSON-RPC methods with no authentication, no per-request key-count validation, and no execution-timeout enforcement analogous to `GetLogsDeadline`. Exploitation requires only a single JSON-RPC POST with an oversized `storageKeys` array; no special privileges, staking, or prior transactions are needed.

### Recommendation
Impose an upper bound on `len(storageKeys)` in `doGetProof` (e.g., analogous to `GetLogsMaxItems`), reject requests exceeding the bound with an RPC error, and/or apply a request-scoped execution deadline similar to `GetLogsDeadline` around the proof-generation loop.

### Proof of Concept
1. Send a single JSON-RPC request to a public Kaia endpoint:
```json
{"jsonrpc":"2.0","id":1,"method":"eth_getProof","params":["0x<any address>", ["0x0","0x1","0x2", ... /* e.g. 500,000 unique hex keys */], "latest"]}
```
2. `doGetProof` decodes all keys, opens the storage trie once, then performs one `storageTrie.Prove` call per key, each walking/resolving trie nodes from the database, as shown in `api/api_eth.go:296-350`.
3. Repeated concurrent submissions of such requests (bounded only by `RPCConcurrencyLimit`, which does not limit per-call work) can exhaust node CPU/I/O, degrading RPC availability for legitimate users.

func doGetProof(ctx context.Context, b Backend, address common.Address, storageKeys []string, blockNrOrHash rpc.BlockNumberOrHash) (*EthAccountResult, error) {
	var (
		keys         = make([]common.Hash, len(storageKeys))
		keyLengths   = make([]int, len(storageKeys))
		storageProof = make([]EthStorageResult, len(storageKeys))
	)
	// Deserialize all keys. This prevents state access on invalid input.
	for i, hexKey := range storageKeys {
		var err error
		keys[i], keyLengths[i], err = decodeHash(hexKey)
		if err != nil {
			return nil, err
		}
	}
	state, header, err := b.StateAndHeaderByNumberOrHash(ctx, blockNrOrHash)
	if state == nil || err != nil {
		return nil, err
	}
	codeHash := state.GetCodeHash(address)

	contractStorageRootExt, err := state.GetContractStorageRoot(address)
	if err != nil {
		return nil, err
	}
	contractStorageRoot := contractStorageRootExt.Unextend()

	// if we have a storageTrie, (which means the account exists), we can update the storagehash
	if len(keys) > 0 {
		storageTrie, err := statedb.NewTrie(contractStorageRoot, state.Database().TrieDB(), nil)
		if err != nil {
			return nil, err
		}
		// Create the proofs for the storageKeys.
		for i, key := range keys {
			// Output key encoding is a bit special: if the input was a 32-byte hash, it is
			// returned as such. Otherwise, we apply the QUANTITY encoding mandated by the
			// JSON-RPC spec for getProof. This behavior exists to preserve backwards
			// compatibility with older client versions.
			var outputKey string
			if keyLengths[i] != 32 {
				outputKey = hexutil.EncodeBig(key.Big())
			} else {
				outputKey = hexutil.Encode(key[:])
			}
			if storageTrie == nil {
				storageProof[i] = EthStorageResult{outputKey, &hexutil.Big{}, []string{}}
				continue
			}
			var proof proofList
			if err := storageTrie.Prove(crypto.Keccak256(key.Bytes()), 0, &proof); err != nil {
				return nil, err
			}
			value := (*hexutil.Big)(state.GetState(address, key).Big())
			storageProof[i] = EthStorageResult{outputKey, value, proof}
		}

func (t *Trie) Prove(key []byte, fromLevel uint, proofDB ProofDBWriter) error {
	// Collect all nodes on the path to key.
	key = keybytesToHex(key)
	nodes := []node{}
	tn := t.root
	for len(key) > 0 && tn != nil {
		switch n := tn.(type) {
		case *shortNode:
			if len(key) < len(n.Key) || !bytes.Equal(n.Key, key[:len(n.Key)]) {
				// The trie doesn't contain the key.
				tn = nil
			} else {
				tn = n.Val
				key = key[len(n.Key):]
			}
			nodes = append(nodes, n)
		case *fullNode:
			tn = n.Children[key[0]]
			key = key[1:]
			nodes = append(nodes, n)
		case hashNode:
			var err error
			tn, err = t.resolveHash(n, nil)
			if err != nil {
				logger.Error(fmt.Sprintf("Unhandled trie error: %v", err))
				return err
			}
		default:
			panic(fmt.Sprintf("%T: invalid node: %v", tn, tn))
		}
	}
	hasher := newHasher(nil)
	defer returnHasherToPool(hasher)

	for i, n := range nodes {
		// Don't bother checking for errors here since hasher panics
		// if encoding doesn't work and we're not writing to any database.
		n, _ = hasher.hashChildren(n, nil, false)
		hn, _ := hasher.store(n, nil, false, false)
		if hash, ok := hn.(hashNode); ok || i == 0 {
			// If the node's database encoding is a hash (or is the
			// root node), it becomes a proof element.
			if fromLevel > 0 {
				fromLevel--
			} else {
				// hash is for the merkle proof. hash = Keccak(rlp.Encode(nodeForHashing(n)))
				enc, _ := rlp.EncodeToBytes(hasher.nodeForHashing(n))
				if !ok {
					hash = hasher.hashData(enc, false)
				}
				dbKey := database.TrieNodeKey(common.BytesToExtHash(hash))
				proofDB.WriteMerkleProof(dbKey, enc)
			}
		}
	}
	return nil
}
