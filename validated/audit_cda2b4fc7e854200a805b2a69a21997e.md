### Title
Identity encryption key in `EncryptedMessage` forges the PoP barrier and lets a malicious sender frame honest DKG participants - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
CVE-2020-12417 is a type-confusion bug: a value with an unexpected tag slips through a type barrier and is later interpreted as a different kind of object. The Serai analog is the PedPoP DKG encryption layer, where the "type barrier" is the canonical-point check in `Ciphersuite::read_G`. `EncryptedMessage::read` and `EncryptionKeyMessage::read` accept the group identity as a valid ephemeral key `key` / registered `enc_key` because they use `Ciphersuite::read_G`, which only enforces canonicality — unlike `Curve::read_G` in FROST which explicitly rejects identity (`crypto/frost/src/curve/mod.rs:125-130`). An identity point then passes every downstream "this is a real public key" assumption, which breaks both the Schnorr proof-of-possession and the ECDH blame mechanism.

### Finding Description
`EncryptedMessage::read` deserializes `key` with `C::read_G` (`crypto/dkg/pedpop/src/encryption.rs:173`), which resolves to `Ciphersuite::read_G` and only checks that the encoding is canonical (`crypto/ciphersuite/src/lib.rs:91-100`). The identity element is a canonical encoding, so `key = identity` is accepted.

With `key = identity`, two barriers collapse:

1. **PoP forgery.** `decrypt_with_proof` and `decrypt` verify `msg.pop` as a Schnorr signature under public key `msg.key` (`encryption.rs:374-379`, `479-485`). `SchnorrSignature::verify(A, c)` checks `s*G == R + c*A`. With `A = identity` this reduces to `s*G == R`, so anyone can forge a valid PoP for the identity key by picking any `s` and setting `R = s*G`. No knowledge of a discrete log is required — the barrier is void.

2. **Publicly-derivable ECDH "shared secret".** The victim's `decrypt` computes `ecdh(&self.enc_key, msg.key) = enc_key_priv * identity = identity` (`encryption.rs:95-97`, `487`). The ChaCha20 cipher key is then `transcript(context || identity.to_bytes())` (`encryption.rs:101-133`) — a fully public, attacker-computable value. The attacker can therefore encrypt *arbitrary* plaintext to any honest participant and it will "decrypt" correctly.

3. **Valid blame proof revealing a constant key.** When the forged message produces an invalid share, `blame_internal` calls `decrypt_with_proof`, where the victim produces `EncryptionKeyProof { key: identity, dleq }`. The DLEq `verify(&[G, msg.key=identity], &[enc_pub, proof.key=identity])` (`encryption.rs:383-390`) passes because `enc_priv*G = enc_pub` and `enc_priv*identity = identity = proof.key`. The blame proof is accepted, the revealed "ECDH key" is the constant identity (leaking nothing but authenticating nothing), and `blame_internal` then decodes the attacker-chosen garbage share and returns `sender` as the faulty party (`pedpop/src/lib.rs:582-605`).

The same missing identity check applies to `EncryptionKeyMessage::read` for the registered `enc_key` (`encryption.rs:58`): a participant registering `enc_key = identity` causes every share encrypted to them to use the public shared secret `identity`, so their incoming shares are readable by anyone observing the authenticated (but not confidential) channel.

### Impact Explanation
An unprivileged participant (or anyone able to inject an `EncryptedMessage` into the authenticated channel attributed to a participant index) can:

- Frame an honest participant: submit a forged `EncryptedMessage` with `key = identity`, a forged PoP, and ciphertext that decrypts to an invalid share. The victim's `calculate_share` flags it, and `blame` incorrectly identifies the honest *sender* as faulty (`pedpop/src/lib.rs:590-608`), aborting the DKG and potentially getting an honest validator penalized/excluded.
- Leak shares: a malicious participant registering `enc_key = identity` receives shares encrypted under a publicly computable key, breaking the confidentiality the ECDH layer exists to provide.

This is a forged proof accepted by verification plus misattribution of fault — both concrete outcomes under the engagement rules.

### Likelihood Explanation
The attack requires only the ability to send a PedPoP `EncryptedMessage`/`EncryptionKeyMessage` to a DKG participant — the exact public input surface these `read` functions exist for. Forging the PoP requires no discrete-log knowledge (identity makes the Schnorr equation trivially satisfiable). The DKG abort and false blame follow deterministically. No collusion, no malformed curve, no unsafe code is needed — just a canonical identity encoding, which `Ciphersuite::read_G` is documented to accept.

### Recommendation
Reject the identity point everywhere a public key is expected in `crypto/dkg/pedpop/src/encryption.rs`:

- In `EncryptedMessage::read` and `EncryptionKeyMessage::read`, check `key.is_identity()` / `enc_key.is_identity()` after `C::read_G` and error out, mirroring `Curve::read_G` in `crypto/frost/src/curve/mod.rs:125-130`.
- Additionally, `Decryption::register` should reject identity `enc_key` values, and `decrypt`/`decrypt_with_proof` should reject `msg.key == identity` even for programmatically constructed messages, so the PoP/ECDH barriers cannot be bypassed via any path that skips deserialization.

### Proof of Concept
```rust
// For any C: Ciphersuite, the attacker crafts:
let s = C::F::random(&mut OsRng);
let forged = EncryptedMessage::<C, SecretShare<C::F>> {
    key: C::G::identity(),                       // passes C::read_G canonicality check
    pop: SchnorrSignature::<C> { R: C::generator() * s, s }, // verifies trivially:
                                                          // s*G == R + c*identity == R
    msg: Zeroizing::new(SecretShare(
        // attacker-chosen plaintext XOR ChaCha20 keystream derived from
        // transcript(context || identity.to_bytes()) — fully public
        chosen_share_repr,
    )),
};
// Victim: encryption.decrypt(...) -> pop batch-verifies, ecdh = enc_priv*identity = identity,
// plaintext = attacker's garbage share -> share_verification_statements fails ->
// PedPoPError::InvalidShare { participant: honest_sender, ... }
// blame() -> decrypt_with_proof succeeds (dleq over identity points is satisfiable and
// reveals the constant identity "key") -> blame_internal returns honest `sender` as faulty.
```
The identity-encoded `key` and a PoP where `R = s*G` pass `C::read_G`, `SchnorrSignature::verify`, and the DLEq-based blame proof, while the decrypted share is attacker-controlled — causing an honest participant to be blamed and the key-generation session to abort.
