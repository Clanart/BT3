## Analog Confirmed: Blind SSRF via unauthenticated DataLayer mirror URLs

### Title
Unauthenticated on-chain "mirror" coins let any spend-bundle submitter make a victim's DataLayer service issue blind SSRF HTTP requests - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user — including an unrelated third party who does not own or control a DataLayer store — can spend a coin to the well-known `MIRROR_PUZZLE_HASH` with a memo encoding an arbitrary `launcher_id` and arbitrary `url` strings. Once that transaction confirms, every node that tracks that `launcher_id` (i.e. every DataLayer participant subscribed to or owning that store) will automatically add the attacker-chosen URL to its local mirror/subscription list and periodically issue outbound HTTP GET requests to it with no host/scheme validation. This is a blind SSRF primitive analogous to CVE-2023-34959 (Chamilo's unvalidated user-supplied URLs fetched server-side), except here the "attacker input" is a cheap, unprivileged on-chain coin spend rather than a web form field.

### Finding Description
1. **Attacker-controlled input reaches the chain without authorization.** `create_mirror_puzzle()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-94` is `P2_PARENT.curry(Program.to(1))` — a fixed puzzle hash anyone can pay a coin to. `get_mirror_info()` (same file, lines 97-110) extracts `launcher_id` and `urls` purely from the `CREATE_COIN` condition's memo field, with no signature, ownership, or ACL check tying the mirror to the store's actual owner. The CLI/RPC path `add_mirror`/`dl_new_mirror` (`chia/data_layer/data_layer.py:965-970`, `chia/wallet/wallet_rpc_api.py:3255-3274`) is just one way to create such a coin — since the puzzle hash and memo format are public, an attacker can also just submit a raw spend bundle directly to the mempool without using this RPC at all.

2. **Any node tracking the launcher_id ingests the attacker's URL.** `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) watches for coins with `create_mirror_puzzle().get_tree_hash()`; the only gate is `is_launcher_tracked(launcher_id)` — i.e., whether the *victim* wallet happens to be tracking/owning that store, not whether the *mirror creator* has any authority over it. It then stores the mirror `urls` unconditionally.

3. **The DataLayer service automatically fetches from that URL.** In the periodic loop (`chia/data_layer/data_layer.py:1102-1112`, `update_subscription()`), `update_subscriptions_from_wallet()` (lines 979-985) pulls `dl_get_mirrors()` results straight into the local subscription table via `DataStore.update_subscriptions_from_wallet()` (`chia/data_layer/data_store.py:1668-1704`) with no URL validation. `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-706`) then selects one of these `ServerInfo.url` values and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:110-169, 298-345`), which does:
```python
async with session.get(
    server_info.url + "/" + filename,
    headers=headers,
    timeout=timeout,
    proxy=proxy_url,
) as resp:
```
There is no scheme allowlist, no blocking of loopback/link-local/private ranges (e.g. `http://127.0.0.1:...`, `http://169.254.169.254/...`, internal RPC ports), and no confirmation that the URL was ever supplied by the store owner. Existing tests (`chia/_tests/core/data_layer/test_data_rpc.py:2767-2801`) even demonstrate mirrors accepting arbitrary `http://127.0.0.1/<port>` URLs.

### Impact Explanation
This gives any unprivileged chain participant a repeatable, low-cost way to force arbitrary Chia full-node/DataLayer-operator infrastructure to make outbound HTTP requests to attacker-chosen destinations (internal services, cloud metadata endpoints, localhost RPC ports, etc.) with no interaction required from the victim beyond running DataLayer and tracking/owning the targeted store. Because the request is a real, timed, followed (`aiohttp` handles redirects/status by default) HTTP GET carrying headers like `accept-encoding`, it can be used to probe internal network topology, port-scan internal services, or trigger side effects on internal HTTP endpoints that trust localhost/private-network callers — a classic blind SSRF impact matching CVE-2023-34959's class. It does not by itself grant unsigned coin movement, but it is a network-reachable pivot originating from a spend-bundle submission, satisfying the required "single submitted spend bundle" attack surface.

### Likelihood Explanation
Likelihood is high for any node that runs DataLayer and tracks at least one store (owned or subscribed): the mirror coin can be created by any wallet with a trivial spend (amount can be `0`, per `create_new_mirror` allowing `uint64(0)`, see `chia/_tests/wallet/db_wallet/test_dl_wallet.py:812`), it confirms like a normal transaction, and the periodic management loop (`periodically_manage_data`) automatically syncs and fetches without any operator action. The only requirement is that the victim be tracking the targeted `launcher_id`, which is trivially learnable since store ids and their mirrors are public/queryable on-chain data.

### Recommendation
- Validate and restrict mirror/subscription URLs before allowing `http_download`/`download_file` to fetch them: enforce an allowed scheme list (`http`/`https` only, no internal-only schemes), and reject or explicitly opt-in for URLs resolving to loopback, link-local, and private/reserved IP ranges (RFC1918, `169.254.0.0/16`, etc.) at both DNS-resolution and connection time (SSRF-safe HTTP client / DNS pinning).
- Consider gating which mirrors are trusted based on store ownership context (e.g., only sync/act on mirror URLs for stores the node actually cares about, and rate-limit/backoff more aggressively for mirrors that repeatedly fail or point to non-routable ranges — already partially covered by `server_misses_file`, but that doesn't prevent the first SSRF probe).
- Document and warn operators that mirror URLs are fully attacker-controlled off-chain pointers (the existing `.cursor/context/data-layer.md` already notes "Plugin and mirror URLs are external trust inputs" — this should be enforced in code, not just documentation).

### Proof of Concept
1. Attacker identifies (or targets) a `launcher_id` known to be tracked by a victim DataLayer node (any subscribed or owned store; store ids are public on-chain).
2. Attacker constructs and submits a standard-wallet spend bundle that creates a coin with `puzzle_hash = create_mirror_puzzle().get_tree_hash()` and memo `[launcher_id, b"http://169.254.169.254/latest/meta-data/", ...]` — equivalent to what `DataLayerWallet.create_new_mirror()` (`chia/data_layer/data_layer_wallet.py:687-703`) produces, but submitted directly without requiring any RPC authorization on the attacker's own node/wallet.
3. Once the transaction confirms, the victim's `DataLayerWallet.coin_added()` records the mirror because it is tracking `launcher_id` (`chia/data_layer/data_layer_wallet.py:788-800`).
4. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` copies the URL into local subscriptions, and `fetch_and_validate()`/`download_file()`/`http_download()` issues `GET http://169.254.169.254/latest/meta-data/<delta-filename>` from the victim's node — the SSRF request — without any operator interaction. def create_mirror_puzzle() -> Program:
```python
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
