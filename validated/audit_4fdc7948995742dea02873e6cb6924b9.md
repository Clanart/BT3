### Title
Loose hostname-heuristic misclassifies an attacker-controlled git remote as a GitHub Enterprise host, triggering OAuth sign-in (and client secret disclosure) toward that remote - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The Sherlock finding is a *classification-completeness* bug: an untrusted, externally supplied value (a negative price) falls outside the finite set of cases the code explicitly recognizes as "safe/expected" (`OracleUtils.isEmptyPriceError()`), so it slides into a fallback branch that performs a destructive action (order cancellation) instead of the safe path. The GitHub Desktop analog is `getEndpointKind()` / `isGitHubHost()`, which classify an arbitrary git remote hostname as `'github.com' | 'ghe.com' | 'enterprise' | 'generic'` using regex heuristics rather than a verified allow-list, and route the fallthrough case into a privileged enterprise sign-in/OAuth flow.

### Finding Description
When git needs credentials for a remote (during `clone`/`fetch`/`push`), Desktop's trampoline credential helper is invoked and calls `getEndpointKind()`: [1](#0-0) 

The classification tries several heuristics in order: exact `isGist`/`isDotCom`/`isGHE` matches, `WWW-Authenticate` header hints, an existing matching account, protocol checks, and finally an API discovery probe via `isGitHubHost()`: [2](#0-1) 

`isGitHubHost()` itself contains a broad substring heuristic — `/(^|\.)(github)\./.test(hostname)` — that classifies *any* host beginning with `github.` (e.g. `github.attacker-domain.com`) as a genuine GitHub Enterprise host **without ever contacting it**, short-circuiting the network-based `/meta` verification that follows: [3](#0-2) 

Because the fully-qualified hostname of a remote the user clones/fetches from is entirely attacker-controlled, an attacker only needs to register a domain containing `github.` as a label prefix (fully legal DNS, e.g. `github.evilcorp.io`) and get the victim to add/fetch from it as a remote. `getCredential()` then treats the endpoint as non-`'generic'`: [4](#0-3) 

Since no existing account matches that made-up endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — because the hostname isn't literally `github.com` — routes into the **Enterprise** sign-in flow and sets the sign-in endpoint to the attacker's origin: [5](#0-4) 

If the user completes that flow, `requestOAuthToken()` will POST GitHub Desktop's OAuth `client_id`/`client_secret` and the authorization `code` to the attacker-controlled origin (derived from `getHTMLURL(endpoint)`, which is the attacker's host because `isGHE`/`isDotCom` don't match it, so the raw endpoint is used): [6](#0-5) [7](#0-6) 

This is structurally the same defect class as the Sherlock bug: a security-relevant classification function is not exhaustive/verified against the true set of trusted values, and unrecognized-but-crafted input falls into a branch that was designed for the trusted case, producing unintended and harmful behavior (order cancellation there; OAuth secret disclosure / unauthorized enterprise-binding here).

### Impact Explanation
If exploited, this results in:
- Disclosure of GitHub Desktop's OAuth `client_secret` to an attacker-controlled server via `requestOAuthToken`.
- The user being funneled into an "enterprise sign-in" flow bound to an attacker-chosen origin, which can be used to phish GitHub credentials or bind a bogus/attacker "enterprise" account into Desktop's account store.
- This falls squarely under the allowed impact categories: "unauthorized OAuth or account binding" and "credential/token exfiltration," triggered purely by fetching/cloning an attacker-controlled remote — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Likelihood is moderate: the attacker only needs to control a DNS name matching `/(^|\.)(github)\./` (trivially satisfiable, e.g. `github.example-attacker.com`) and get the victim to interact with it as a git remote (clone/add remote/fetch) so the credential-helper flow runs. Some user interaction (completing the resulting sign-in prompt) is required to fully leak the OAuth secret, but the misclassification itself is fully automatic and silent up to that point — same "classification gap under attacker-chosen input" pattern as the Sherlock report.

### Recommendation
- Do not use substring/prefix regex heuristics (`/(^|\.)(github)\./`) to decide trust; require either an exact match against a known/authenticated endpoint or a verified network round-trip (the existing `/meta` + `x-github-request-id` check) before treating a host as GitHub/GHE.
- Never send the OAuth `client_secret` to an endpoint that hasn't been positively verified as GitHub.com or a previously-trusted/verified GHE instance.
- Treat unverifiable hosts as `'generic'` by default (fail closed) instead of `'enterprise'`.

### Proof of Concept
1. Attacker stands up a git server at `https://github.evilcorp.io` (a legal, attacker-owned domain matching the `github.` prefix heuristic).
2. Victim adds/clones from this remote in GitHub Desktop and performs a `fetch`/`push`; git invokes Desktop's credential helper for host `github.evilcorp.io`.
3. `getEndpointKind()` finds no `isDotCom`/`isGHE`/existing-account match, falls through to `isGitHubHost()`, whose `/(^|\.)(github)\./` regex matches `github.evilcorp.io`, returning `true` without any verification request. `getEndpointKind` returns `'enterprise'`.
4. `getCredential()` sees `endpointKind !== 'generic'` and no matching account, so it calls `ui.promptForGitHubSignIn('https://github.evilcorp.io')`.
5. `promptForGitHubSignIn` sees hostname `!== 'github.com'` and starts `beginEnterpriseSignIn` + `setSignInEndpoint('https://github.evilcorp.io')`.
6. If the victim proceeds through the shown sign-in dialog, `requestOAuthToken('https://github.evilcorp.io', code)` POSTs `client_id`/`client_secret`/`code` directly to the attacker's server.

Note: I was unable to fully trace `getGitHubCredential()` (not covered by index results) which is checked before this fallback and could gate some paths; readers should verify that function's behavior directly in the repository to confirm no additional check blocks step 3–4. Given index size limits, some file contents (e.g. `getGitHubCredential` implementation) may not have been available — a full Devin session with repository access is recommended to confirm this call path end-to-end before treating this as a finalized, confirmed vulnerability.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

export function getHTMLURL(endpoint: string): string {
  if (envHTMLURL !== undefined) {
    return envHTMLURL
  }

  // In the case of GitHub.com, the HTML site lives on the parent domain.
  //  E.g., https://api.github.com -> https://github.com
  //
  // Whereas with Enterprise, it lives on the same domain but without the
  // API path:
  //  E.g., https://github.mycompany.com/api/v3 -> https://github.mycompany.com
  //
  // We need to normalize them.
  if (endpoint === getDotComAPIEndpoint() && !envEndpoint) {
    return 'https://github.com'
  } else {
    if (isGHE(endpoint)) {
      const url = new window.URL(endpoint)

      url.pathname = '/'

      if (url.hostname.startsWith('api.')) {
        url.hostname = url.hostname.replace(/^api\./, '')
      }

      return url.toString()
    }

    const parsed = URL.parse(endpoint)
    return `${parsed.protocol}//${parsed.hostname}`
  }

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
