### Title
Missing slippage protection in `ArbWomUp3._deposit` when mode=2 causes user funds to be swapped in `SmartWomConvert.convert` with `_minRec = 0`, exposing depositors to sandwich attacks - (File: wombat/ArbWomUp3.sol)

### Summary
`ArbWomUp3.incentiveDeposit` (an unprivileged, user-callable entry point) lets a caller deposit WOM with `_mode == 2`, which routes half of the deposited amount through `SmartWomConvert.convert` with a hardcoded `_minRec` of `0`. This is the exact bug class described in the external report: a user-initiated transaction that converts/buys at a market-determined price with no way to bound the price impact, allowing front-running/sandwiching to extract value from the depositor.

### Finding Description
`incentiveDeposit` is public and callable by any wallet, and internally calls `_deposit`: [1](#0-0) 

Inside `_deposit`, for `_mode == 2`, half the deposited WOM is routed to `SmartWomConvert.convert` with the minimum-received parameter hardcoded to `0`, regardless of any value the caller passes to `incentiveDeposit`: [2](#0-1) 

`SmartWomConvert.convert` forwards this `_minRec` straight into `_convertFor`, which performs a real AMM swap against the `womMWomPool` via `IWombatRouter.swapExactTokensForTokens` and then checks the received amount only against the caller-supplied `_minRec`: [3](#0-2) [4](#0-3) 

Because `ArbWomUp3` always passes `_minRec = 0` for this swap, the check `if (convertAmount + amountRec < _minRec) revert MinRecNotMatch();` can never fail no matter how unfavorable the executed swap price is. There is no parameter on `incentiveDeposit` (or on `_deposit`) that lets the depositor set an acceptable minimum output for this internal swap — the caller only controls `_convertRatio`, not the swap's minimum-received amount. This mirrors the report's root cause in `Crowdinvesting.buy`/`onTokenTransfer`: a price-affecting operation triggered by an ordinary user transaction with no way for that user to bound the resulting price/amount.

### Impact Explanation
An attacker (MEV searcher) can observe a pending `incentiveDeposit(..., _mode = 2)` transaction in the mempool, sandwich the `womMWomPool` swap performed inside `SmartWomConvert._convertFor` (front-run to push the WOM→mWOM price down, let the victim's swap execute at the manipulated price, then back-run to restore the price and capture the difference). Since `_minRec` is fixed at `0`, the victim's swap will succeed even if it returns close to zero mWOM out of the swapped half of their deposit. This is a direct theft of the depositing user's funds, not merely a slippage nuisance, since the entire downside is unbounded.

### Likelihood Explanation
The function is public, requires no privileged role, and is part of the normal user-facing deposit flow (`incentiveDeposit` with `_mode == 2`). Any user choosing (or being directed to use) the "lock" mode is exposed, and sandwiching a public AMM swap with a zero minimum-out is a well-known, low-cost, reliably profitable MEV strategy, making exploitation practical whenever there is executable value in the swapped WOM amount.

### Recommendation
Add a caller-supplied minimum-received parameter to `incentiveDeposit`/`_deposit` (analogous to the fix used for `Crowdinvesting.buy`) and forward that value as `_minRec` into `IConverter(smartWomConvert).convert(...)` instead of hardcoding `0`, so users can explicitly bound the acceptable output of the internal swap.

### Proof of Concept
1. User calls `incentiveDeposit(amount, convertRatio, bullMode, 2)` on `ArbWomUp3`.
2. `_deposit` computes `toSwap = amount - amount/2` and calls `IConverter(smartWomConvert).convert(toSwap, convertRatio, 0, 0)` — note the hardcoded `0` for `_minRec`. [5](#0-4) 
3. Attacker front-runs with a large WOM→mWOM swap on `womMWomPool` via the same router, depressing the mWOM output rate.
4. The victim's swap inside `_convertFor` executes at the depressed rate; the check `convertAmount + amountRec < _minRec` (with `_minRec = 0`) never reverts. [6](#0-5) 
5. Attacker back-runs to restore the pool price and realizes the price difference as profit, extracted directly from the victim's deposited WOM.
