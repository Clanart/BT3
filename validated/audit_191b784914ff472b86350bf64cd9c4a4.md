### Title
Permissionless `CallDispatcher.dispatch()` lets any unprivileged caller drain funds held by the shared intent-execution helper - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
The Tapioca report's core broken invariant is: a "helper" contract that is trusted to construct/execute privileged calldata on behalf of a protected flow is never checked for identity or caller authorization, so an attacker can redirect its output/execution to steal assets it is holding. Hyperbridge's `CallDispatcher` reproduces the identical pattern: `IntentGatewayV2` / `IntentsBase` treat it as a semi-trusted helper that temporarily custodies user/solver funds during `predispatch`/`postdispatch` order execution, but `CallDispatcher.dispatch()` itself is a fully public function with **no caller restriction whatsoever** — anyone, not just the intent gateway, can invoke it to make the dispatcher execute arbitrary `to.call{value}(data)` against arbitrary targets using whatever ETH/ERC20 balance currently sits on the dispatcher.

### Finding Description
`CallDispatcher.dispatch()` has zero access control: [1](#0-0) 

It is used as the execution engine for order calldata in both the predispatch (pre-escrow) and postdispatch/output (post-fill) flows of `IntentGatewayV2` and `IntentsBase`: [2](#0-1) [3](#0-2) 

In both flows, real user/solver funds (native ETH or ERC20 tokens) are transferred into the dispatcher's balance, `dispatch()` is invoked to run attacker/order-supplied calldata, and only afterward is a *specific, hard-coded* set of tokens (`order.inputs` / `order.output.assets`) swept back out via a second `dispatch()` call built from `dispatcher.balance` / `IERC20(token).balanceOf(dispatcher)` snapshots. Because the sweep only targets the tokens explicitly declared in the order, any token or ETH that ends up on the dispatcher outside that declared set (e.g. as a byproduct of the predispatch calldata's own swap/execution, a failed/partial sweep, or residual dust from any of the many other callers of this shared, singleton dispatcher across `IntentGatewayV2`, `HyperFungibleToken`, and Tron equivalents) is left stranded on the contract.

Because `dispatch()` never verifies `msg.sender` is the intent gateway (or any other authorized caller), and never binds the call to a specific order/commitment/module, **any external account can call `CallDispatcher.dispatch()` directly** with a `Call[]` array pointing at the stranded token/ETH and sweep it to themselves — exactly analogous to how the unchecked `marketHelper` in the Tapioca report let an attacker redirect privileged execution because the helper's identity/output was never validated before being executed with elevated trust.

### Impact Explanation
This is a direct fund-theft primitive on a production Solidity path: an unprivileged, unauthenticated actor can drain any ETH/ERC20 balance that is not immediately and fully swept by the intended order flow from the shared `CallDispatcher` singleton. Because the dispatcher is reused across all `IntentGatewayV2` orders (and other consumers listed via the `ICallDispatcher` interface — `HyperFungibleToken`, `WrappedHyperFungibleToken`, Tron `IntentGatewayV2`), the blast radius is protocol-wide rather than scoped to a single order or user.

### Likelihood Explanation
No privileged role, relayer, prover, or malicious peer is required — this is a plain unauthenticated public-entrypoint call (`dispatch(bytes)`), satisfying the "unprivileged attacker" requirement of the bounty gate. The only precondition is that the dispatcher hold a non-zero balance of some token/ETH outside the order's declared `inputs`/`output.assets` set at the moment the attacker calls `dispatch()` — plausible any time a predispatch/postdispatch swap produces slippage residue, a different intermediate token, or a sweep that fails to be constructed for a token the calldata actually produced (the sweep logic only iterates over `order.inputs`/`order.output.assets`, not the dispatcher's full token surface).

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the authorized gateway/module contract(s) (e.g. an `onlyGateway`/whitelisted-caller modifier, similar to the module/marketHelper whitelist fix applied elsewhere in the Tapioca codebase), and additionally ensure the sweep logic accounts for the dispatcher's *full* balance of any token touched by the predispatch/postdispatch calldata (not just the declared `inputs`/`output.assets`), so no value can ever be left resting on a permissionless, shared execution helper.

### Proof of Concept
1. A user calls `IntentGatewayV2.placeOrder` with a `predispatch.call` that swaps `assets[0]` for `tokenA`, but due to slippage/multi-hop routing the swap also yields a small amount of `tokenB` not present in `order.inputs`.
2. `IntentGatewayV2` sweeps only `order.inputs` tokens back from the dispatcher (`evm/src/apps/IntentGatewayV2.sol:230-258`); the `tokenB` dust remains on `CallDispatcher`.
3. An attacker, with no relationship to the order, calls `CallDispatcher.dispatch(abi.encode([Call({to: tokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly (`evm/src/utils/CallDispatcher.sol:44-61`) — this succeeds because `dispatch()` performs no caller check, draining the stranded `tokenB` to the attacker.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {

                }
