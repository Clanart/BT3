### Title
Unchecked `fee_per_vbyte` with no change output lets a transaction proposer burn the entire wallet balance as miner fee - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` accepts an arbitrary `fee_per_vbyte` and, when `change` is `None`, intentionally sends all leftover input value to miners (`The actual fee this transaction will use is sum(inputs) - sum(outputs)`). This mirrors TRST-H-1: an unbounded, proposer-controlled fee parameter converts the wallet's balance into fees paid to a third party, and the resulting transaction is then threshold-signed without any re-validation of the fee against the payment intent.

### Finding Description
In `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:150-256`):

- `fee_per_vbyte` is a caller-supplied `u64` with no upper bound. The only sanity check is a *lower* bound: `needed_fee < DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000` errors out (`send.rs:206-213`). An arbitrarily large fee rate is accepted.
- The sufficiency check only requires `input_sat >= payment_sat + needed_fee` (`send.rs:215-221`); it does not bound `needed_fee` relative to `input_sat`.
- If `change` is `None`, no change output is added and the doc comment states "all leftover funds will become part of the paid fee" (`send.rs:145-147`). `fee()` confirms the actual fee is `sum(inputs) - sum(outputs)` (`send.rs:138-141`).
- Even with `change` set, a huge `fee_per_vbyte` makes `fee_with_change` consume nearly everything; the leftover `value` check (`send.rs:228-234`) just needs `>= DUST` to add a change output, otherwise the remainder is burned too.

Downstream, `TransactionSignMachine::sign` computes the sighash over this transaction (`send.rs:373-397`) and `multisig()` only verifies the prevout script pubkeys match the offset group keys (`send.rs:275-281`) — nothing binds the signers' intent about fee magnitude. A proposer (the party who constructs the `SignableTransaction` that signers then run through `preprocess`/`sign`/`complete`) can set `fee_per_vbyte = u64::MAX`-ish and `change = None`, producing a transaction that pays the entire input set minus `payment_sat` to miners.

### Impact Explanation
A malicious transaction proposer can cause the threshold group to sign a Bitcoin transaction whose entire wallet balance (minus the nominal payments) is paid as miner fee. Because the sighash commits to outputs and prevouts (`Prevouts::All`, `send.rs:375-386`), the inflated fee is part of the signed message, yet no signer-side check distinguishes a legitimate fee from a draining one — the same structure as the Brahma report where `tx.gasprice` was trusted blindly. Loss is the full wallet balance; the analog of "losses go to the fund manager" is that they go to miners.

### Likelihood Explanation
Reachable by whichever party proposes transaction parameters in the multisig flow; the library provides no defense and documents the burn-to-fee behavior as intended for the `None` change case. It requires the signers to run a proposer-supplied `SignableTransaction` rather than independently constructing it — but the API is explicitly designed so a single `SignableTransaction` is cloned/shared across participants, so this is the expected usage.

### Recommendation
Cap `fee_per_vbyte` (e.g., a governance/protocol-defined maximum fee rate, analogous to the report's "capped priority fee"), and/or require `change` to be `Some` whenever `input_sat - payment_sat - needed_fee` exceeds a dust threshold, erroring instead of silently donating the remainder to miners.

### Proof of Concept
```rust
// Attacker-controlled proposer constructs:
let st = SignableTransaction::new(
    vec![received_output],              // wallet UTXO, e.g. 1 BTC
    &[(payment_script, DUST)],          // minimal payment
    None,                               // change: None -> leftover becomes fee
    None,
    u64::MAX / 1_000_000,               // absurd fee_per_vbyte, no upper-bound check
).unwrap();                             // passes: needed_fee >= min relay fee, input_sat >= payment+fee
// st.fee() == input_sat - payment_sat; signers' multisig()/sign() succeed;
// complete() yields a TX paying ~all funds to miners.
```
