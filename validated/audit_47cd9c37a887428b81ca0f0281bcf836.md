### Title
Unsigned OP_RETURN operator-attribution in the payout transaction allows an unprivileged party to misattribute or block reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The payout transaction that fronts a Citrea withdrawal is signed by the user with `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, which only commits to the withdrawal input and its matching output. The OP_RETURN output that records which operator's x-only pubkey fronted the payout is *not* covered by that signature. Any party who obtains the user's signature and outpoint (transmitted to every operator by the aggregator, and visible in the mempool prior to confirmation) can rebuild the same transaction with their own fee-funding input and an arbitrary OP_RETURN payload, and win the race to get it confirmed. This breaks the "operator credited == party that paid" binding that later drives reimbursement.

### Finding Description
`create_payout_txhandler` builds the payout tx with the withdrawal UTXO as the only signed input/output pair, and appends an unsigned anchor output and an unsigned OP_RETURN output containing `operator_xonly_pk`: [1](#0-0) 

The witness set on the tx is `set_p2tr_key_spend_witness(&user_sig, 0)` — i.e. only input 0 is signed by the user, using `SinglePlusAnyoneCanPay`, which is explicitly enforced (and even auto-normalized from a legacy default) in the RPC parser: [2](#0-1) 

Because `SIGHASH_SINGLE` only commits output index 0 (the user payout) and `ANYONECANPAY` allows arbitrary additional inputs, any party — not just the intended operator — can take the same user signature/outpoint (available to every operator via the aggregator's fan-out `Withdraw` call, or observable in the mempool before confirmation) and construct a *different, still-valid* transaction spending the same withdrawal UTXO, funding it from their own wallet, but writing a *different* `operator_xonly_pk` (or an invalid/unregistered one) into the OP_RETURN.

This OP_RETURN value is later trusted as ground truth for who fronted the withdrawal, both off-chain and inside the circuit:
- The verifier's chain-sync logic extracts `operator_xonly_pk` straight from the OP_RETURN with no further authentication and stores it as the payer of record: [3](#0-2) 
- `is_kickoff_malicious` compares the kickoff's claimed operator against this stored value to decide whether a kickoff is fraudulent: [4](#0-3) 
- The operator-side reimbursement path requires the recorded payer to equal its own key before it will proceed with `get_reimbursement_txs`/`handle_finalized_payout`: [5](#0-4) 
- The zk bridge circuit itself derives `deposit_constant` directly from the OP_RETURN-parsed `operator_xonlypk`, so the same forgeable field is baked into the on-chain-verifiable claim of who is entitled to reimbursement: [6](#0-5) 

### Impact Explanation
Two Critical outcomes follow directly from forging the OP_RETURN:
1. **Operator reimbursed for a payout it never funded.** An attacker fronts the withdrawal with their own BTC but stamps a real, registered operator's `xonly_pk` into the OP_RETURN. `update_finalized_payouts` records that operator as payer, `validate_payer_is_operator` passes for that operator, and the operator becomes entitled to run the kickoff/reimburse flow (`create_reimburse_txhandler` spending the `DepositInMove` output) for a withdrawal it did not pay for: [7](#0-6) 
2. **Honest operator permanently unable to be reimbursed / vault UTXO effectively frozen.** If the attacker stamps an invalid or unregistered key, no operator's `validate_payer_is_operator` check will ever match the recorded payer, so no one can advance the reimbursement flow for that deposit, and the corresponding `deposit_constant` computed by the bridge circuit can never be reproduced by the honest operator who actually should be reimbursed — a true claim becomes unprovable.

### Likelihood Explanation
The withdrawal signature and outpoint are not secret to a single trusted party: the aggregator forwards the full `WithdrawParamsWithSig` (including `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount`) to every operator it targets, and any resulting transaction becomes visible in the mempool before it confirms. Since the sighash type leaves the funding inputs, anchor output, and OP_RETURN completely unauthenticated, no signature, key, or privileged role is required to construct the competing transaction — any unprivileged party capable of observing the withdrawal request or the mempool and racing a replacement transaction to confirmation can carry out the attack.

### Recommendation
Bind the operator attribution to the same signature that authorizes the withdrawal, e.g. by using a sighash type that also commits to the OP_RETURN output (or moving the operator identity into a covered output), or by having the aggregator/user co-sign a full-coverage payout template per assigned operator so the OP_RETURN cannot be swapped by a third party while still allowing fee-input flexibility.

### Proof of Concept
1. Operator O (or attacker) observes an aggregator `Withdraw` request (or its resulting unconfirmed payout tx in the mempool) containing `WithdrawParams{withdrawal_id, input_signature (SinglePlusAnyoneCanPay), input_outpoint, output_script_pubkey, output_amount}`.
2. Attacker builds their own transaction re-using `input_outpoint`/`user_sig` on input 0 and the required output 0 (both covered by the signature, per `create_payout_txhandler`), adds their own funding input (`ANYONECANPAY` permits this), and sets the OP_RETURN payload to an arbitrary `operator_xonly_pk` of their choosing.
3. Attacker broadcasts and gets this transaction confirmed before the legitimate operator's transaction.
4. `update_finalized_payouts` parses the attacker-chosen `operator_xonly_pk` from the OP_RETURN and records it as the payer for this withdrawal (`core/src/verifier.rs:2312-2343`), which is then used by `validate_payer_is_operator` (`core/src/operator.rs:1703-1729`) and the bridge circuit's `deposit_constant` (`circuits-lib/src/bridge_circuit/mod.rs:206-229`) to gate/attribute reimbursement — crediting a party that never funded the payout, or making the deposit unreimbursable by anyone if the injected key is invalid.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))
}
