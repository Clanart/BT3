## Title
Reward tokens permanently lost when there are no stakers at the start of a `WomUp` reward period - (File: `wombat/WomUp.sol`)

### Summary
`WomUp.sol` implements a classic Synthetix-style `StakingRewards` time-weighted reward accrual (`rewardPerTokenStored`, `lastUpdateTime`, `periodFinish`, `rewardRate`). Exactly like the referenced M-15 report, if no user has staked WOM by the time `initializeRewards()` is called (or during any idle stretch where `totalSupply() == 0`), the reward accrued during that idle window is silently discarded and can never be claimed or rolled into a future period.

### Finding Description
`initializeRewards()` sets `rewardRate = rewardsAvailable / duration`, `lastUpdateTime = block.timestamp`, and `periodFinish = block.timestamp + duration`: [1](#0-0) 

`rewardPerToken()` explicitly skips accrual whenever `totalSupply() == 0`, simply returning the stored value without accounting for elapsed time: [2](#0-1) 

The `updateReward` modifier (triggered by any ordinary user calling `stake`, `withdraw`, `migrate`, or `getReward`) then unconditionally advances `lastUpdateTime` to `lastTimeRewardApplicable()` (i.e., "now"), discarding the elapsed idle time forever: [3](#0-2) 

So if `duration` seconds pass with zero stakers, `rewardRate * elapsedTime` worth of MGP reward is never distributed to anyone, and once the first ordinary wallet calls `stake()`, `lastUpdateTime` jumps to the current timestamp — the unused reward for the idle window is permanently unrecoverable through the reward-accounting path.

Unlike `BaseRewardPool.sol`/`BaseRewardPoolV2.sol`/`mWOMSVBaseRewarder.sol`, which explicitly handle the zero-total-staked case by accumulating a `queuedRewards` value that is folded into the next `_provisionReward` call: [4](#0-3) 

`WomUp.sol` has no equivalent mechanism — the idle-period reward is simply lost.

Compounding this, the only admin recovery path, `rescueReward()`, is only usable *before* `rewardRate` is set (`revert AlreadyStarted()` if `rewardRate > 0`), so once `initializeRewards()` has run, there is no way to reclaim the stranded MGP even by governance: [5](#0-4) 

### Impact Explanation
This causes permanent freezing/loss of unclaimed yield: MGP tokens allocated as rewards for stakers are locked in the contract and become mathematically unattributable to any user or future period once the idle window passes and the first ordinary stake transaction resets `lastUpdateTime`. No privileged action is required to trigger the loss — it is a natural consequence of the reward-rate design combined with any period without stakers (e.g., right after `initializeRewards()` is called, before the first user stakes).

### Likelihood Explanation
Likelihood is moderate to high: any gap between `initializeRewards()` being called and the first user staking (a very plausible real-world scenario, e.g., delay in announcing/discovering the migration incentive) results in permanent loss. No attacker coordination or privileged role is needed — an ordinary user's routine `stake()` call is what finalizes/crystallizes the loss.

### Recommendation
Mirror the `queuedRewards` pattern used in `BaseRewardPoolV2.sol`/`mWOMSVBaseRewarder.sol`: when `totalSupply() == 0` in the `updateReward` modifier (or in `rewardPerToken()`), do not silently advance `lastUpdateTime` past the idle window without preserving the corresponding reward amount; instead, track `(elapsedIdleTime * rewardRate)` as unallocated/queued reward and fold it back in when a subsequent `initializeRewards()`/reward-notification occurs, or extend `periodFinish` to compensate for the idle time actually experienced by stakers.

### Proof of Concept
1. Owner deposits MGP to the `WomUp` contract and calls `initializeRewards()`, setting `rewardRate`, `lastUpdateTime = T0`, `periodFinish = T0 + duration`.
2. No user calls `stake()` for `Δt` seconds (`_totalSupply == 0` the whole time).
3. A user finally calls `stake()`. `updateReward` executes: `rewardPerTokenStored = rewardPerToken()` returns the unchanged stored value (branch `totalSupply()==0`), then `lastUpdateTime = lastTimeRewardApplicable() = T0 + Δt`.
4. The `Δt * rewardRate` MGP reward corresponding to the idle window is never reflected in `rewardPerTokenStored` and is never distributed to any staker; it remains stuck in the contract with no further code path (including `rescueReward`, which reverts once `rewardRate > 0`) to recover it.

        if (totalSupply() == 0) {
            return rewardPerTokenStored;
        }
        return

                (lastTimeRewardApplicable() - (lastUpdateTime)) * rewardRate * (1e18) / (totalSupply())
            );
    }

    function initializeRewards() external onlyOwner returns (bool) {
        if(rewardRate > 0) revert MustZero();

        uint256 rewardsAvailable = IERC20(mgp).balanceOf(address(this));
        if(rewardsAvailable == 0) revert MustNotZero();

        rewardRate = rewardsAvailable / (duration);

        lastUpdateTime = block.timestamp;
        periodFinish = block.timestamp + (duration);

        emit RewardAdded(rewardsAvailable);

        return true;
    }
