### Title
Flash-loan reward-dilution attack allows theft of unclaimed WOM yield via permissionless `harvest()` and no deposit/withdraw cooldown - ([File: rewards/BaseRewardPool.sol], [File: wombat/WombatStaking.sol], [File: rewards/MasterMagpie.sol])

### Summary
`BaseRewardPool` distributes rewards using an instantaneous "reward-per-token" model where each `queueNewRewards`/`donateRewards` call immediately divides the incoming reward amount by the *current* `totalStaked()` [1](#0-0) . Because `MasterMagpie.deposit()`/`withdraw()` have no minimum holding period or same-block restriction [2](#0-1) [3](#0-2) , and `WombatStaking.harvest()` is a fully permissionless, unprivileged-caller function that pulls accrued WOM rewards and immediately calls `queueNewRewards` on the pool's rewarder [4](#0-3) [5](#0-4) , an attacker can flash-deposit a large amount of stake, trigger `harvest()` to realize accrued yield against an artificially inflated `totalStaked()`, and immediately withdraw to capture a disproportionate share of that yield — precisely the bug class described in the external report, but here reachable through an ordinary (non-privileged) wallet transaction.

### Finding Description
`BaseRewardPool._provisionReward` computes the reward-per-token increment as `_amountReward * 10**decimals / totalStaked()` at the moment the reward is added [6](#0-5) . `totalStaked()` reads the live balance of the staking (receipt) token held by `MasterMagpie` [7](#0-6) , so any deposit made in the same block as (or immediately before) a reward injection instantly participates in diluting/capturing that reward.

`MasterMagpie.deposit`/`withdraw` (and the `PoolHelper`-mediated `depositFor`/`withdrawFor`) have no deposit timestamp or minimum lock, unlike the recommendation from the referenced report ("depositTs" field + validation on withdraw) [8](#0-7) . There is no `Deposit` struct field tracking time, and no check preventing withdrawal in the same block as deposit.

Critically, the reward-injection trigger itself is callable by any unprivileged wallet: `WombatStaking.harvest(address _lpToken)` has no `onlyOwner`/`onlyPoolHelper` restriction — it is guarded only by `whenNotPaused` and `_onlyActivePool` (i.e., the pool must simply be active) [4](#0-3) . It routes to `_toMasterWomAndSendReward` → `_sendRewards` → `IBaseRewardPool(_rewarder).queueNewRewards(...)` [9](#0-8) [10](#0-9) . Additionally, `BaseRewardPool.donateRewards` is fully permissionless for any already-registered reward token, providing an alternate/complementary reward-injection trigger an attacker fully controls [11](#0-10) .

Exploit path (all unprivileged wallet calls, single block/transaction bundle):
1. Attacker takes a flash loan of the pool's deposit token.
2. Attacker deposits the flash-loaned amount via `WombatPoolHelper`/`WombatStaking.deposit` → receipt token minted and staked into `MasterMagpie` via `depositFor` [12](#0-11) , inflating the attacker's registered balance and `totalStaked()` in `BaseRewardPool`.
3. Attacker calls `WombatStaking.harvest(_lpToken)`, which harvests real accrued WOM (built up over time by long-term stakers) and calls `queueNewRewards`, computing the reward-per-token increment using the now-inflated `totalStaked()` [9](#0-8) .
4. Attacker immediately withdraws via `WombatPoolHelper.withdraw` → `MasterMagpie._withdraw` → `_harvestAndUnstake` → `_harvestBaseRewarder` → `BaseRewardPool.getReward`, which pays out `earned()` proportional to the attacker's inflated `balanceOf` [13](#0-12) [14](#0-13) .
5. Attacker repays the flash loan, having captured a disproportionate slice of yield that was accrued over time and rightfully belonged to long-standing stakers.

### Impact Explanation
This constitutes theft of unclaimed yield from existing stakers: WOM rewards that accrued over time (from real trading fees/emissions) are redirected to a transient flash-loan depositor who held stake for a single block, diluting and stealing the proportional share legitimate long-term stakers should have received. This falls under the accepted impact category of "theft ... of unclaimed yield."

### Likelihood Explanation
Likelihood is high for smaller/thin farms (as the report notes, "more feasible for smaller farms") because a modest flash loan can dominate `totalStaked()`. The attack requires only unprivileged wallet actions (`deposit`, `harvest`, `withdraw`), all of which are externally callable with no cooldown, role check, or minimum holding-period gate, and can be composed atomically in one transaction via a contract wallet.

### Recommendation
Introduce a deposit timestamp per user (as the referenced fix did) in `MasterMagpie`'s `UserInfo`, and enforce a minimum delay between deposit and withdraw/decrease actions in `_withdraw`/`_harvestAndUnstake`. Additionally, consider restricting `WombatStaking.harvest()` to trusted keepers/managers or decoupling harvest timing from instantaneous `totalStaked()` snapshots (e.g., checkpoint-based or time-weighted reward accrual) so freshly deposited balances cannot immediately capture previously-accrued rewards.

### Proof of Concept
```
1. attacker.flashBorrow(depositToken, X)
2. WombatPoolHelper.deposit(X, minLiquidity)   // stakes X in MasterMagpie via WombatStaking.deposit -> depositFor
3. WombatStaking.harvest(lpToken)              // permissionless; harvests accrued WOM, queueNewRewards() divides by inflated totalStaked()
4. WombatPoolHelper.withdraw(X, minAmount)     // unstakes, MasterMagpie._harvestAndUnstake pays earned() proportional to inflated balance
5. attacker.flashRepay(depositToken, X)
// attacker nets a share of WOM rewards accrued by long-term stakers, all within one transaction/block
``` [15](#0-14)

        IERC20(_rewardToken).safeTransferFrom(

            _amountReward
        );

    /// @notice Send rewards to the rewarders
    /// @param _rewardToken the address of the reward token to send
    /// @param _rewarder the rewarder that will get the rewards
    /// @param _amount the initial amount of rewards after harvest

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }
