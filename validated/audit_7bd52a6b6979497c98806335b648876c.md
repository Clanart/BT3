### Title
Governance-settable `KIP71.GasTarget = 0` causes divide-by-zero panic in `NextMagmaBlockBaseFee` — ([File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base-fee formula in `NextMagmaBlockBaseFee` divides by `GasTarget` without ever checking it against zero, while the sibling denominator parameter (`BaseFeeDenominator`) is explicitly guarded against the zero case in the same function. `GasTarget` is a plain governance-votable `uint64` parameter whose format checker is a no-op that accepts `0`, so a governance vote can push the network into a state where every node panics while computing/verifying the next block's base fee.

### Finding Description
`NextMagmaBlockBaseFee` computes the delta to the base fee using `gasTarget` as a divisor: [1](#0-0) 

It explicitly protects against `BaseFeeDenominator == 0` ("To avoid panic, set the fluctuation range small") but performs no equivalent guard for `GasTarget`: [2](#0-1) [3](#0-2) 

When `parentGasUsed != gasTarget` (true for any nonzero `GasTarget` if `gasTarget == 0` and the parent block used any gas), the code executes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))`. Go's `big.Int.Div` panics on division by zero.

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, unlike `Kip71BaseFeeDenominator` which explicitly requires `v != 0`: [4](#0-3) 

This asymmetry is confirmed by the test suite, where `Kip71GasTarget` bad-vote cases reject wrong types (`string`, `int`, `bool`) but never reject the value `0`, while there is no analogous zero-allowing test for `BaseFeeDenominator`: [5](#0-4) 

Once a `kip71.gastarget = 0` vote is cast by a council member/governing node via `governance_vote` and ratified into `header.Governance` at an epoch boundary (per `kaiax/gov/headergov`'s standard vote/ratify flow), the new `ParamSet` is used everywhere `NextMagmaBlockBaseFee` is invoked: header preparation/verification in `blockchain/block_validator.go`, block building in `work/worker.go`, chain test helpers in `blockchain/chain_makers.go`, and RPC endpoints such as `node/cn/gasprice/feehistory.go` and `node/cn/gasprice/gasprice.go`.

### Impact Explanation
Because `NextMagmaBlockBaseFee` is called on the hot path of consensus header validation (`VerifyMagmaHeader`) as well as block assembly, a `GasTarget == 0` value causes every node (proposers and validators) processing the very next block with nonzero gas usage to panic. This is a chain-halting denial-of-service: no client can produce or validate blocks after the parameter takes effect, since the divide-by-zero is deterministic and unconditionally reached whenever gas is used. Even RPC-only nodes serving `eth_feeHistory`/`eth_gasPrice` would crash on the same code path.

### Likelihood Explanation
The path requires a governance vote to set `kip71.gastarget` to `0`, which is restricted to a council member or the governing node (analogous to the original report's requirement that curvature/leverage parameters are set/adjusted by a privileged pool owner). Given the `FormatChecker` is a no-op, `NewVoteData` accepts the value, `VerifyVote`'s `checkConsistency` for `gov.Kip71GasTarget` performs no additional validation (falls into the pass-through case at `kaiax/gov/headergov/impl/header.go:216`), and the value is ratified normally at the next epoch. No other invariant in the codebase prevents a governance participant (malicious or mistaken) from setting this to zero, unlike `BaseFeeDenominator` which is explicitly protected both in the format checker and defensively in the formula itself.

### Recommendation
- Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`, `Kip71LowerBoundBaseFee`, `Kip71UpperBoundBaseFee`) requiring `v != 0`, mirroring the existing check for `Kip71BaseFeeDenominator` at `kaiax/gov/param.go:310-315`.
- Defensively guard `NextMagmaBlockBaseFee` in `params/kip71_config.go` against `gasTarget == 0` the same way it already guards `BaseFeeDenominator == 0`, so a single bad parameter cannot crash the client even if it slips through governance validation.

### Proof of Concept
1. A council member (or the governing node in single mode) calls `governance_vote("kip71.gastarget", uint64(0))`. `NewVoteData` accepts it because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` (`kaiax/gov/param.go:324-334`).
2. The vote is embedded in `header.Vote`, validated successfully by `VerifyVote`/`checkConsistency` (no special-case rejects a zero `GasTarget`, `kaiax/gov/headergov/impl/header.go:214-220`), and ratified into `header.Governance` at the next epoch boundary.
3. From the following block onward, `ParamSet.GasTarget == 0` and `ToKip71Config().GasTarget == 0`.
4. Any block whose parent used gas ≠ 0 triggers `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)`: since `parentGasUsed > gasTarget(0)`, code reaches `y := x.Div(x, new(big.Int).SetUint64(0))`, which panics in Go's `math/big`.
5. This function executes inside `VerifyMagmaHeader` (block validation) and worker block-building paths, so every full node/validator panics attempting to process/verify the block — halting the chain.
