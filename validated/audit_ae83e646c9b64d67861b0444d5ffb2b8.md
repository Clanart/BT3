### Title
Untrusted DDS texture header fields drive WebGL texture upload without cross-validation against actual buffer size - (File: `app/src/ui/diff/image-diffs/dds-converter.ts`)

### Summary
`convertDDSImage` in `app/src/ui/diff/image-diffs/dds-converter.ts` parses a `.dds` image blob (originating from a repository blob or working-directory file that the attacker fully controls, e.g. a `.dds` file committed to a cloned/fetched repo) with the third-party `parse-dds` library, then trusts the parsed `width`/`height`/`offset`/`length` fields to slice the raw buffer and hand it directly to `gl.compressedTexImage2D`, exactly mirroring the report's core issue: structured, attacker-supplied binary data is only partially validated before being consumed by a lower-level, unsafe-by-default API.

### Finding Description
`ImageContainer.loadImage` invokes `convertDDSImage(image.rawContents)` whenever a diffed file's media type is detected as `image/vnd-ms.dds` [1](#0-0) . The `rawContents` buffer comes straight from `getBlobImage`/`getWorkingDirectoryImage`, i.e. the raw bytes of a blob read from `git show` or the working directory — fully attacker-controlled content in a cloned/checked-out repository [2](#0-1) .

`convertDDSImage` then does:
```
const ddsData = parseDDS(contents)
const [image] = ddsData.images
const [imageWidth, imageHeight] = image.shape
const imageData = new Uint8Array(contents, image.offset, image.length)
...
drawToCanvas(canvas, ddsData.format, imageWidth, imageHeight, imageData)
``` [3](#0-2) 

Just like the `BlockhashRegistry.getParentAndBlockhash` bug, this code:
- Delegates structural parsing to a routine (`parseDDS`) whose header fields (`width`, `height`, mip-level `offset`/`length`) are attacker-supplied and are not independently re-validated against the actual size of `contents` before being consumed.
- Feeds the resulting `width`/`height`/`imageData` directly into a low-level, unmanaged API — `gl.compressedTexImage2D` — which sets the canvas backing-store dimensions and image size based on values taken from the untrusted header rather than a value cross-checked against the real payload length [4](#0-3) .
- Performs no explicit min/max sanity check on the DDS header (magic, size, pixel format, mip count) before using its derived offsets, relying entirely on whatever `parse-dds` happens to validate (or not) and on the JS engine's implicit `RangeError` from the `Uint8Array` constructor as the only backstop — the same "rely on implicit exceptions instead of validating up-front" pattern flagged in the original report.

### Impact Explanation
`compressedTexImage2D` is a WebGL entry point that is backed by native GPU driver code (via ANGLE/ Chromium's command buffer). Compressed-texture upload paths that trust attacker-influenced width/height/format/size metadata rather than deriving them strictly from the verified payload size are a well-known class of GPU-driver memory-safety bugs (multiple browser CVEs exist in exactly this code path). Because GitHub Desktop's renderer runs this parsing/upload automatically the moment a diff for a `.dds` file is displayed (no user interaction beyond viewing the diff), a maliciously crafted `.dds` blob committed to a repository the user clones, fetches, or checks out could reach the GPU driver with attacker-chosen dimension/size metadata mismatched from the real buffer contents — a potential renderer/GPU out-of-bounds read or driver crash/RCE primitive, consistent with the report's impact category of "attacker-controlled parsing of structurally-unvalidated binary input reaching a privileged/unsafe consumer."

### Likelihood Explanation
Likely to trigger automatically: any file with an extension in `imageFileExtensions` and detected as binary in a diff is passed to `getImageDiff`, and if the DDS-preview feature flag is enabled and the media type resolves to `image/vnd-ms.dds`, `ImageContainer` calls `convertDDSImage` on `componentDidMount`/`componentDidUpdate` with no further user gesture [5](#0-4) . The only gating is `enableImagePreviewsForDDSFiles`, referenced in `app/src/lib/git/diff.ts` [6](#0-5) ; whether this feature is enabled by default could not be confirmed from the indexed code and would need to be checked directly in the repository (feature-flag definitions were not available in the search index).

### Recommendation
1. After calling `parseDDS`, explicitly validate that `image.offset + image.length <= contents.byteLength` and that `imageWidth`/`imageHeight` are within sane bounds (e.g., matching the expected compressed block size for `ddsData.format`) before calling `compressedTexImage2D`.
2. Recompute the expected `imageData.length` from `imageWidth`/`imageHeight`/format block size and compare it to `image.length`; reject the file (fail closed, as `ImageContainer` already does via try/catch) if they don't match.
3. Consider sandboxing/limiting DDS preview parsing (e.g., a strict allow-list of supported header configurations) rather than trusting the full range of what `parse-dds` will accept.
4. Audit whether `enableImagePreviewsForDDSFiles` is enabled by default; if so, treat this path as reachable-by-default and prioritize the validation above.

### Proof of Concept
Not independently verified end-to-end (requires confirming `parse-dds`'s internal validation and reproducing an actual GPU-level OOB, which is outside what could be verified via static code search). Conceptual PoC:
1. Craft a `.dds` file whose header declares a mip-level `offset`/`length` and `width`/`height` that are inconsistent with each other (e.g., width/height implying a much larger decoded size than the actual compressed byte length, while still passing whatever checks `parse-dds` performs).
2. Commit this file to a repository and have the victim clone/fetch it, then open the file's diff in GitHub Desktop with DDS preview enabled.
3. `ImageContainer` calls `convertDDSImage`, which slices `contents` using the header-derived `offset`/`length` and calls `gl.compressedTexImage2D` with header-derived `width`/`height`, potentially causing the GPU driver to read outside the intended buffer. [3](#0-2) [5](#0-4) [2](#0-1)

  file: FileChange

function drawToCanvas(
  canvas: HTMLCanvasElement,
  format: string,
  width: number,
  height: number,
  imageData: ArrayBufferView
) {
  canvas.width = width
  canvas.height = height
  const gl = canvas.getContext('webgl2', { preserveDrawingBuffer: true })
  if (!gl) {
    throw new Error('Failed to get webgl2 context')
  }

  gl.bindTexture(gl.TEXTURE_2D, gl.createTexture())
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR)
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR)
  const ext = gl.getExtension('WEBGL_compressed_texture_s3tc')
  if (!ext) {
    throw new Error('Failed to get WEBGL_compressed_texture_s3tc extension')
  }

  const internalFormat = getFormat(ext, format)
  gl.compressedTexImage2D(
    gl.TEXTURE_2D,
    0,
    internalFormat,
    width,
    height,
    0,
    imageData
  )

  const program = compileProgram(gl, vert, frag)
  gl.useProgram(program)

  gl.viewport(0, 0, width, height)
  triangle(gl)
}

export function convertDDSImage(contents: ArrayBufferLike) {
  const ddsData = parseDDS(contents)

  // Get the first mipmap texture.
  const [image] = ddsData.images
  const [imageWidth, imageHeight] = image.shape
  const imageData = new Uint8Array(contents, image.offset, image.length)

  // Draw the DXT texture to the canvas using WebGL2.
  const canvas = document.createElement('canvas')
  drawToCanvas(canvas, ddsData.format, imageWidth, imageHeight, imageData)

  const mediaType = 'image/png'
  const dataURL = canvas.toDataURL(mediaType, 1.0)
  return dataURL
}
