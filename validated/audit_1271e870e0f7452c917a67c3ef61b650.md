### Title
Forged Schnorr signature accepted for identity public key - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
`SchnorrSignature::read` accepts a canonically encoded identity nonce `R`, while `Ciphersuite::read_G` accepts a canonically encoded identity public key because it validates only canonicality, not non-identity. The resulting `(R = identity, s = 0)` signature satisfies the verifier’s `R + cA - sG = identity` equation for any challenge `c` when `A = identity`.

### Finding Description
`SchnorrSignature::read` deserializes `R` using `C::read_G` and `s` using `C::read_F`. [1](#0-0)  The generic `Ciphersuite::read_G` implementation checks that the point decodes and re-encodes canonically, but does not reject `G::identity()`. [2](#0-1) 

Verification expands the signature into the equation `R + challenge * public_key - s * generator = identity`. [3](#0-2)  With `R = identity`, `public_key = identity`, and `s = 0`, every term is the identity regardless of the challenge, so `verify` returns true. [4](#0-3) 

Unlike FROST’s preprocessing parser, which explicitly rejects identity commitments, this Schnorr decoding path has no equivalent non-identity validation. [5](#0-4) 

### Impact Explanation
An unprivileged party can submit canonical encodings of an identity public key, identity nonce, and zero scalar to a verifier that treats the public key as untrusted input. The verifier accepts a signature without knowledge of a discrete logarithm and without the signature being bound to a nonzero public key. In protocols where an identity or all-zero key represents an absent/default authorization key, this permits signature forgery for that account or state.

### Likelihood Explanation
Exploitation requires the caller to accept attacker-supplied encoded public keys and to use `SchnorrSignature::read`/`verify` without separately rejecting identity keys. The encoded forgery is deterministic and does not require a hash collision, secret leakage, malicious validator, or protocol participant compromise.

### Recommendation
Reject identity points when deserializing Schnorr signatures and public keys used by `SchnorrSignature::verify`, or expose a Schnorr-specific non-identity `read_G` equivalent to `Curve::read_G`. Applications should also reject identity public keys before calling `verify`.

### Proof of Concept
```rust
use ciphersuite::{
  group::{ff::Field, GroupEncoding},
  Ciphersuite,
};
use schnorr::SchnorrSignature;
use std::io::Cursor;

fn forge_identity_signature<C: Ciphersuite>() {
  // Canonical identity public key.
  let identity_encoding = C::G::identity().to_bytes();
  let public_key = C::read_G(&mut Cursor::new(identity_encoding.as_ref())).unwrap();

  // Canonical forged signature: R = identity, s = 0.
  let mut encoded_sig = Vec::new();
  encoded_sig.extend_from_slice(identity_encoding.as_ref());
  encoded_sig.extend_from_slice(C::F::ZERO.to_repr().as_ref());

  let signature = SchnorrSignature::<C>::read(&mut Cursor::new(encoded_sig)).unwrap();

  // Any challenge verifies because all three multiexp terms are identity.
  let arbitrary_challenge = C::F::ONE;
  assert!(signature.verify(public_key, arbitrary_challenge));
}
```
