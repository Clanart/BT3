### Title
OP_RETURN `data` output is excluded from the fee/weight accounting in `SignableTransaction::new` - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
`SignableTransaction::new` appends an OP_RETURN output carrying the caller-supplied `data` to `tx_outs`, but the weight/vsize used to compute `needed_fee` and to enforce the minimum relay fee is derived only from `payments`. The data output is therefore never counted in the fee accounting — an accounting mismatch of the same class as an allocation that is created but not tracked.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is pushed into `tx_outs` before the fee is calculated:

```rust
// networks/bitcoin/src/wallet/send.rs:194-202
if let Some(data) = data {
  tx_outs.push(TxOut {
    value: Amount::ZERO,
    script_pubkey: ScriptBuf::new_op_return(...),
  })
}

// send.rs:204-206
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;
```

`calculate_weight_vbytes` builds its synthetic `Transaction` with `output` set to `payments` (plus optional `change`) — `data` is not a parameter and is never included (`send.rs:85-99`). The same omission applies to the change variant at `send.rs:225-226`. The resulting `needed_fee`, the `TooLowFee` check (`send.rs:211`), and the `NotEnoughFunds` check (`send.rs:215`) all assume a transaction that is smaller than the one actually serialized into `tx`. A caller-controlled `data` of up to 80 bytes (`send.rs:171-173`) adds a full extra output (~34 bytes of output overhead plus the pushdata payload) whose weight is entirely unaccounted.

### Impact Explanation
The real transaction is larger than the one priced. A transaction constructed with a `data` output at a fee rate near the minimum can fall below `DEFAULT_MIN_RELAY_TX_FEE` for its actual vsize (or below the requested `fee_per_vbyte`), so it will be rejected/dropped by relay policy and never confirm, while `needed_fee()`/`fee()` misreport the discrepancy as an intended overpayment. Funds committed as inputs are locked behind an unbroadcastable plan until the transaction is re-planned — a mismatch between recorded accounting (`needed_fee`) and actual obligation (the signed tx's true vsize), directly analogous to shares issued but not counted in `boughtShares` causing later `sell` checks to fail. Caveat: within the in-repo processor, `make_signable_transaction` always passes `data: None` (`processor/src/networks/bitcoin.rs:446-452`), so the buggy path is reachable only through the public `SignableTransaction::new` API for callers that attach OP_RETURN data; I could not confirm an in-crate caller that supplies `data`.

### Likelihood Explanation
Low-to-moderate. It requires a caller to use the `data` parameter, and the underpayment only becomes fatal when the resulting effective fee rate falls below the relay minimum or the intended rate — i.e., when `data` is large and `fee_per_vbyte` is near the floor. The code path itself deterministically mis-accounts the fee whenever `data` is provided.

### Recommendation
Include the data output in weight accounting, e.g., pass the constructed `tx_outs` (or an `Option<&PushBytesBuf>` data parameter) into `calculate_weight_vbytes` so the synthetic transaction mirrors the real outputs, and re-check `TooLowFee`/`NotEnoughFunds` against the corrected vsize in both the change and no-change branches.

### Proof of Concept
```rust
// networks/bitcoin/tests/wallet.rs style
let output = send_and_get_output(&rpc, &scanner, key).await;
let inputs = vec![output];
let data = vec![0x42; 80];

// A TX with an OP_RETURN output reports needed_fee as if it had none
let tx = SignableTransaction::new(inputs, &[], None, Some(data), FEE).unwrap();

// Weight of the real tx exceeds what needed_fee was priced for
let (real_weight, _) = SignableTransaction::calculate_weight_vbytes_helper(&tx);
// Equivalently: tx.transaction().weight() - used vbytes > 0
assert!(tx.transaction().weight().to_wu() > /* priced weight */);
// needed_fee() / actual vsize < FEE, and may be < DEFAULT_MIN_RELAY_TX_FEE
```
