### Title
Panic on `GeneratorProof` map keyed to the local participant (missing-index `unwrap`) enables remote DoS — (File: crypto/dkg/promote/src/lib.rs)

### Summary
CVE-2021-46239 is an invalid-free → crash (DoS) bug class: improper handling of attacker-influenced input leads to memory corruption / abort. Serai is memory-safe Rust, so the direct analog is an unprivileged-reachable panic. In `GeneratorPromotion::complete`, an attacker can supply a `proofs` map whose keys all satisfy `<= n` and whose length is `n - 1`, yet which omits one index in `1..=n` (e.g., by including the local participant `params.i()` as a key). The loop then hits `proofs.get(&i).unwrap()` on a missing key and panics, crashing the promotion/signing path.

### Finding Description
`GeneratorPromotion::complete` validates only the count and upper bound of the supplied proofs:

```rust
if proofs.len() != (usize::from(params.n()) - 1) { ... }
for i in proofs.keys().copied() {
  if u16::from(i) > params.n() { ... }
}
```

It never checks that the keys cover every participant `1..=n` other than the local `params.i()`. The subsequent loop iterates all `i in 1..= params.n()`, skips `params.i()`, and unconditionally unwraps:

```rust
let proof = proofs.get(&i).unwrap();   // crypto/dkg/promote/src/lib.rs:146
```

A `GeneratorProof` is parsed from raw bytes via `GeneratorProof::read` (`read_G` + `DLEqProof::read`), so the `Participant` key an attacker associates it with is fully attacker-controlled. Because `HashMap` keys are unique, supplying a proof keyed to `params.i()` (or otherwise duplicating coverage such that some `i != params.i()` is absent) leaves the map at size `n - 1`, passes both validation checks, and guarantees `proofs.get(&i)` returns `None` for the omitted participant — panicking on `unwrap`.

### Impact Explanation
An unauthenticated/unprivileged participant in a key-promotion ceremony can abort the entire promotion (and thereby any downstream `ThresholdKeys<C2>` usage such as signing under the promoted generator) by crashing the victim's process at a deterministic point. This mirrors the CVE's outcome — a crash-level DoS triggered by crafted input — realized in Rust as a panic rather than an invalid free. Since the panic occurs while processing per-participant messages, it also denies the honest set the ability to complete the protocol round.

### Likelihood Explanation
Likelihood is moderate: it requires only that the attacker can submit a `GeneratorProof` map (or influence the `Participant` key under which their serialized proof is stored) during a `GeneratorPromotion::complete` call. No valid proof or private state is needed — the panic fires before any DLEq verification on the missing index. The check bypass is trivial (use `params.i()` as the map key, or send `n-1` proofs covering fewer than `n-1` distinct non-self indexes — impossible via HashMap dedup, so the self-keyed variant is the reliable path).

### Recommendation
Replace `proofs.get(&i).unwrap()` with a checked lookup returning `PromotionError::InvalidParticipant { n: params.n(), participant: i }` (or a dedicated `MissingParticipant` variant) when absent, and additionally reject any `proofs` key equal to `params.i()` during the initial key-validation loop so the coverage invariant `keys == {1..=n} \ {i}` is fully enforced.

### Proof of Concept
```rust
// Victim: let promo = GeneratorPromotion::<C1, C2>::promote(rng, my_keys).0;
// params: n = 3, i = 1

// Attacker builds proofs for participants {1 (self!), 2} instead of {2, 3}
let mut proofs = HashMap::new();
proofs.insert(Participant::new(1).unwrap(), attacker_proof); // keyed to victim's i
proofs.insert(Participant::new(2).unwrap(), attacker_proof);
// proofs.len() == n - 1 == 2  -> passes count check
// all keys <= n == 3          -> passes bound check

// Victim calls:
promo.complete(&proofs);
// Loop reaches i = 3: proofs.get(&Participant(3)) -> None -> unwrap() panics
```

Root cause: `crypto/dkg/promote/src/lib.rs:146` — `let proof = proofs.get(&i).unwrap();` executed after incomplete coverage validation at lines 125–136.
