### Title
Attacker can spam uneconomical dust UTXOs to the vault key to drain funds via forced input fees - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` registers every on-chain output paying to a registered script_pubkey as a spendable `ReceivedOutput`, with no minimum-value check. Because spending a Taproot input costs a fixed amount of fee (~57 vbytes per `SignableTransaction::calculate_weight_vbytes`), any UTXO whose value is below that cost is net-negative: consuming it in a `SignableTransaction` burns more value in fees than it contributes. An unprivileged attacker can send arbitrarily many dust-value UTXOs to the publicly known vault/branch addresses, and the wallet will either pay more in fees than the inputs are worth (draining the vault) or must permanently write the deposits off as operating costs. This mirrors the reported bug class: a per-operation cost (taker fee / input fee) is absorbed by the protocol rather than charged to the party that triggered it.

### Finding Description
`Scanner::scan_transaction` matches solely on `script_pubkey` and pushes every matching output into `res` as a `ReceivedOutput`, regardless of `output.value` [1](#0-0) . `ReceivedOutput::read` similarly accepts any `TxOut`, including zero-value outputs [2](#0-1) .

On the spend side, `SignableTransaction::new` only enforces `DUST` (546 sats) on *payments* it creates, never on *inputs* it consumes [3](#0-2) . Each input adds a fixed ~230 weight units (~57 vbytes) to the transaction [4](#0-3) , so the marginal fee cost of spending an input is `57 * fee_per_vbyte` sats. A received output valued below that — e.g., 546 sats at 5+ sat/vbyte, or anything below the processor's own 10,000-sat `DUST` constant — costs more to spend than it returns.

When change exists, `prepare_send` treats unrecouped remainder and dropped branches as `operating_costs` borne by the protocol [5](#0-4) , and the change-amount-under-dust case is likewise booked as an operating cost [6](#0-5) . The cost of each attacker-created dust input is therefore socialized across the vault's other funds, exactly as the PerpDepository socialized taker fees across LPs.

### Impact Explanation
The vault's Bitcoin address is public (anyone can derive `p2tr_script_buf(key)`). An attacker sends N transactions each containing dust outputs to that script. The scanner accepts them all as legitimate received outputs. The scheduler/wallet must then either:
- include them as inputs, paying `N * ~57 vbytes * feerate` in fees exceeding `N * dust_value` — a net drain on vault funds proportional to attacker spend at ~1/N cost ratio advantage, or
- strand them, permanently locking accounting value and accumulating operating costs.

Either way, funds deposited to the vault are drained or rendered unspendable, at a cost to the attacker far below the damage inflicted.

### Likelihood Explanation
Reachable by any unprivileged party with only public knowledge of the vault address — no validator cooperation, leaked keys, or malformed signatures required. The attacker only needs to broadcast ordinary Bitcoin transactions paying dust to the vault script. The only mitigation is the attacker's own transaction fees, which are amortized over many dust outputs per transaction while the vault pays a per-input fee on every spend.

### Recommendation
- In `Scanner::scan_transaction` (or wherever `ReceivedOutput`s are admitted to the scheduler), reject outputs whose `value` is below the marginal fee cost of spending them (`input_vbytes * current_fee_per_vbyte`, with a safety margin such as `Bitcoin::DUST`).
- In `SignableTransaction::new`, skip or refuse inputs where `input.value < fee_per_vbyte * 57` instead of unconditionally including all supplied inputs, so uneconomical inputs are never signed even if they slip through scanning.
- Charge such ignored deposits as unrecoverable rather than amortizing their implied value into `operating_costs` funded by honest users' payments.

### Proof of Concept
1. Attacker computes `script = p2tr_script_buf(vault_key)` — the vault's P2TR scriptPubKey is publicly derivable from the group key (`networks/bitcoin/src/wallet/mod.rs:80-86`).
2. Attacker broadcasts transactions creating 1000 outputs of 546 sats each to `script` (total cost ~546,000 sats + one tx fee).
3. `Scanner::scan_transaction` returns all 1000 as `ReceivedOutput`s (`networks/bitcoin/src/wallet/mod.rs:205-211`); no value filter exists.
4. `SignableTransaction::new` adds each as a `TxIn`; weight accounting in `calculate_weight_vbytes` charges ~57 vbytes per input (`networks/bitcoin/src/wallet/send.rs:71-83`, `processor/src/networks/bitcoin.rs:619-620`). At 5 sat/vbyte each input costs ~285 sats in fee for 546 sats of value — near break-even; at 15+ sat/vbyte each input is net-negative (~855 sats fee vs 546 sats value). The deficit is absorbed into `operating_costs`/`change` (`processor/src/networks/mod.rs:458-474`), draining honest vault funds, or the payments are dropped while the cost is still socialized.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
