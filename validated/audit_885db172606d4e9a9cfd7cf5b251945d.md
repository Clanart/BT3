### Title
Auto-updated git remote trusts unverified GitHub API `clone_url`, allowing silent remote hijack - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl()` automatically rewrites a repository's local git `origin` URL to match the `clone_url` returned by the GitHub API whenever the API's `clone_url` no longer matches the locally-recorded remote, as long as two partial guard conditions hold. Like the `solverMetaTryCatch()` bug (checks that don't cover all situations), these guards validate *some* invariants (protocol continuity, "has the user manually changed it") but never validate the most important invariant: that the new URL still points at the *same* repository (same host/owner/name) the user originally added. This lets a server-controlled value silently redirect where the user's future pushes/fetches go.

### Finding Description [1](#0-0) 

The function performs only two checks before calling `gitStore.setRemoteURL(...)`:
1. `protocolsMatch` — the old and new URL protocol strings are equal (or both unparseable, i.e. SSH-style) [2](#0-1) 
2. `remoteUrlUnchanged` — the current remote still matches what Desktop last recorded as the GitHub repository's `cloneURL` (i.e., the user hasn't hand-edited the remote) [3](#0-2) 

If both hold and the new `clone_url` differs from the current remote (`!urlsMatch`), the code unconditionally rewrites the remote: [4](#0-3) 

Neither guard checks that the new `clone_url`'s hostname/owner/name is a "reasonable" evolution of the old one (e.g., same host, or an actual rename event correlated with the same repository ID). `urlMatchesRemote()` — the only function that compares hostname/owner/name — is used solely to decide *whether* an update is needed, not to bound *what* the update is allowed to change it to [5](#0-4) . The unit tests confirm the intended benign case (GitHub rename: `my-repo` → `my-updated-repo` under the same `github.com/my-user` host) but do not exercise, and the code does not defend against, a `clone_url` pointing at an entirely different host [6](#0-5) .

The `apiRepo` object ultimately originates from a GitHub API/GHE response tied to a repository the user already trusts by ID, fetched over HTTPS validated only for scheme, not certificate pinning or host consistency [7](#0-6) . Any enterprise/API-side compromise, response tampering, or a maliciously configured GHE instance the user has authenticated to can therefore supply an arbitrary `clone_url` for a repository object Desktop already tracks, and Desktop will silently accept it as the new authoritative remote — exactly analogous to the smart-contract bug where a check ("has `reconcile()`/`solverCalledBack` fired") is only exercised along some code paths and is trivially satisfiable/bypassable along others (here: "is this URL for the same repo" is never checked at all, only "did the protocol stay the same" and "did the user avoid touching the remote").

### Impact Explanation
If exploited, a user's `origin` remote is silently repointed to an attacker-controlled git server without any prompt or confirmation. Subsequent `git push` operations would send commits/credentials (via whatever credential helper matches the new host) to the attacker's endpoint, and subsequent `git fetch`/`pull` would merge attacker-supplied history into the user's working repository — a silent corruption of what the user pushes and pulls, matching the "silent corruption of what the user commits or pushes" and "credential exfiltration" categories in the report's valid-impact list.

### Likelihood Explanation
This requires the "attacker controls a GitHub API object" primitive explicitly listed as in-scope: a compromised/malicious GitHub Enterprise server, or a party able to tamper with API responses for a repository the user has already added to Desktop. It does not require local access, malware, or leaked credentials. The trigger path (periodic repository refresh calling `updateRemoteUrl`) runs automatically and silently in the background without user interaction, increasing exploitability once the attacker controls the API response.

### Recommendation
Add an explicit check that the new `clone_url`'s hostname is unchanged (or matches the trusted endpoint the account is authenticated to) before rewriting the remote, and/or surface a visible confirmation prompt to the user whenever the origin remote is about to change hosts — do not rely solely on `protocolsMatch` and `remoteUrlUnchanged`, since neither constrains the target host.

### Proof of Concept
1. User adds `https://ghe.example.com/org/repo` in GitHub Desktop and authenticates against `ghe.example.com`.
2. The GHE server (compromised, or an attacker with response-tampering capability on that endpoint) later returns an API repository object for the same repo ID with `clone_url: "https://evil.example.com/org/repo"`.
3. On the next background refresh, `updateRemoteUrl()` sees `protocolsMatch === true` (both `https:`) and `remoteUrlUnchanged === true` (user never touched the remote), and calls `gitStore.setRemoteURL('origin', 'https://evil.example.com/org/repo')` [4](#0-3) .
4. The user's next `git push`/`git fetch` silently targets `evil.example.com` with no warning shown in the UI.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export function validateURL(address: string): string {
  // ensure user has specified text and not just whitespace
  // we will interact with this server so we can be fairly
  // relaxed here about what we accept for the server name
  const trimmed = address.trim()
  if (trimmed.length === 0) {
    const error = new Error('Unknown address')
    error.name = InvalidURLErrorName
    throw error
  }

  let url = URL.parse(trimmed)
  if (!url.host) {
    // E.g., if they user entered 'ghe.io', let's assume they're using https.
    address = `https://${trimmed}`
    url = URL.parse(address)
  }

  if (!url.protocol) {
    const error = new Error('Invalid URL')
    error.name = InvalidURLErrorName
    throw error
  }

  if (url.protocol !== 'https:') {
    const error = new Error('Invalid protocol')
    error.name = InvalidProtocolErrorName
    throw error
  }

  return address
}
