## Finding

The Hyperbridge nexus runtime's `ProxyModule` — the `IsmpRouter`/`IsmpModule` implementation that fronts every request and timeout processed on the Hyperbridge chain — reuses a single deny-list check (`is_deprecated_token_gateway`) for two structurally different purposes: rejecting *new* incoming requests from deprecated `TokenGateway` deployments, and rejecting the *timeout callback* for requests that were already dispatched before deprecation. Because the ISMP timeout handler restores (rather than deletes) the request commitment whenever the module callback errors, this second use permanently and irrecoverably locks the request's escrowed relayer fee (and blocks the destination gateway's own asset-refund flow), since the deny-list check can never succeed for that `from` address again. [1](#0-0) 

### Title
Permanent fund lock: deprecated-TokenGateway deny-list check applied to `on_timeout` blocks refund of already-dispatched requests forever - ([File: parachain/runtimes/nexus/src/ismp.rs])

### Summary
`ProxyModule::on_accept` and `ProxyModule::on_timeout` both unconditionally reject any `PostRequest` whose `from` matches one of the three hardcoded `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`. This is correct for `on_accept` (stop new traffic from a deprecated deployment), but the same check is copied verbatim into `on_timeout`, which is the callback the core ISMP handler invokes to let a module react to (and settle) a request that has already timed out. [2](#0-1) [3](#0-2) 

### Finding Description
The core ISMP timeout handler in `modules/ismp/core/src/handlers/timeout.rs` deletes the request commitment, invokes the module's `on_timeout`, and only calls `host.on_request_timeout` (which performs the actual relayer-fee refund) if the module callback returns `Ok`. If the callback errors, the commitment is **restored** ("so the request can be retried") instead of being finalized as timed out: [4](#0-3) 

The unit test `test_dispatch_fees_and_refunds` explicitly documents this behavior: "Failing inner callback means `on_request_timeout` is never reached, so the escrow stays in place." [5](#0-4) 

Since `is_deprecated_token_gateway(&post.from)` is a static, unconditional, address-only check with no way to ever return `false` for a listed address, any Post request whose `from` is one of the three deprecated addresses will *always* fail the `on_timeout` callback, no matter how many times a relayer retries it. This is the same shape as the reported Voter bug: a guard meant to gate one action path (new dispatch) is silently reused on the "refresh/settle stale state" path (timeout/poke), and once triggered, the resulting stuck state can never be corrected because the same immutable input (the request's `from` field / the deprecated NFT's disabled bribe vault) that caused the block will always cause it again.

### Impact Explanation
Any request already in flight from one of the `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` when the request times out on Hyperbridge:
- Never receives its relayer-fee refund — the `RELAYER_FEE_ACCOUNT` (or the payer-designated escrow) permanently retains the fee, since `host.on_request_timeout`/settlement is never reached.
- Never reaches a terminal state on Hyperbridge — the commitment is repeatedly restored on every retry, so the request is neither delivered nor timed out, forever.
- Downstream, the origin `TokenGateway` deployment on the EVM chain that is waiting for this specific timeout proof to unlock/refund the user's escrowed assets can never receive a valid timeout confirmation for that commitment, because Hyperbridge can never finalize the timeout. This is a direct, permanent loss/lock of user funds with no governance or admin remediation path exposed in code (the callback is a hardcoded, `const` deny-list check with no override).

This matches the "loss of funds" and "false state acceptance/incorrect settlement" categories in the bounty scope, and it is fully local to Hyperbridge's own router/handler logic — no malicious relayer, prover, or governance action is required beyond the deprecation list that already ships in the runtime today.

### Likelihood Explanation
Medium: the three deprecated addresses are already hardcoded in the shipped nexus runtime, so any pre-existing in-flight request from a legacy `TokenGateway` deployment that times out after this runtime went live will hit this path today. The failure is deterministic and requires zero attacker sophistication — it is purely a consequence of normal relayer timeout-submission activity for legacy traffic.

### Recommendation
Differentiate the two use cases the way the original report recommends for `Voter`: keep the deny-list check in `on_accept` (reject new dispatches from a deprecated gateway), but do not apply it in `on_timeout`. A request that was validly dispatched before deprecation should still be allowed to settle/refund via its timeout path — treat deprecation as "stop accepting new business from this address," not "retroactively poison every already-escrowed request from this address." At minimum, `on_timeout` should perform the fee-refund/settlement logic unconditionally (or route it to a dedicated deprecated-gateway refund handler) rather than returning an `Err` that the core handler interprets as "retry later."

### Proof of Concept
1. Prior to being added to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`, a `TokenGateway` contract at one of the three listed addresses dispatches a `PostRequest` through Hyperbridge with a non-zero relayer fee, `from = <deprecated address>`.
2. The request is delivered/forwarded but ultimately times out (destination unreachable, or the forwarding hop fails) after the deprecation list already contains this address (as it does in the current runtime).
3. A relayer submits the timeout proof to Hyperbridge. `modules/ismp/core/src/handlers/timeout.rs` deletes the commitment, calls `ProxyModule::on_timeout`.
4. `ProxyModule::on_timeout` sees `is_deprecated_token_gateway(&post.from) == true` and returns `Err(...)` unconditionally.
5. The core handler restores the commitment via `host.store_request_commitment` and never calls `host.on_request_timeout`, so the relayer fee is never refunded and the request never reaches a terminal state.
6. Every subsequent retry of the same timeout proof repeats steps 3–5 forever — the fee is permanently stuck and the origin-chain `TokenGateway` escrow tied to this commitment can never be released via a valid Hyperbridge timeout confirmation. [6](#0-5) [7](#0-6)

/// Deprecated TokenGateway contract addresses whose incoming ISMP Post requests
/// must be rejected unconditionally by the nexus runtime.
/// Any [`PostRequest`] whose `from` field matches any of these 20-byte addresses
/// is rejected in [`ProxyModule::on_accept`] before any other processing — the
/// message is neither dispatched locally nor forwarded onwards.
pub const DEPRECATED_TOKEN_GATEWAY_ADDRESSES: &[[u8; 20]] = &[
	// Ethereum / Arbitrum / Optimism / Base / BSC / Gnosis TokenGateway
	hex_literal::hex!("Fd413e3AFe560182C4471F4d143A96d3e259B6dE"),
	// Polygon / Unichain TokenGateway
	hex_literal::hex!("8b536105b6Fae2aE9199f5146D3C57Dfe53b614E"),
	// Soneium TokenGateway
	hex_literal::hex!("Ce304770236f39F9911BfCC51afBdfF3b8635718"),
];

/// Returns `true` if `from` is exactly one of the deprecated TokenGateway
/// contract addresses in [`DEPRECATED_TOKEN_GATEWAY_ADDRESSES`].
fn is_deprecated_token_gateway(from: &[u8]) -> bool {
	DEPRECATED_TOKEN_GATEWAY_ADDRESSES.iter().any(|deprecated| deprecated == from)
}

	fn on_timeout(&self, timeout: Request) -> Result<Weight, anyhow::Error> {
		// Permanently reject Post-request timeouts whose originating module is a
		// deprecated TokenGateway deployment, before any other handling runs. Only
		// Post requests are subject to this — Get requests and Response timeouts
		// are untouched.
		if let Request::Post(post) = &timeout {
			if is_deprecated_token_gateway(&post.from) {
				return Err(anyhow!(
					"rejecting Post-request timeout from deprecated TokenGateway address {:?}",
					post.from,
				));
			}
		}

		let (from, source) = match &timeout {
			Request::Post(post) => (&post.from, post.source.clone()),
			Request::Get(get) => (&get.from, get.source.clone()),
		};

		if source != HostStateMachine::get() {
			return Ok(Weight::from_parts(0, 0));
		}

		let pallet_id = ModuleId::from_bytes(from).map_err(|err| Error::Custom(err.to_string()))?;
		match pallet_id {
			pallet_hyper_fungible_token::PALLET_ID =>
				pallet_hyper_fungible_token::Pallet::<Runtime>::default().on_timeout(timeout),
			_ => Ok(Weight::from_parts(300_000_000, 0)),
		}
	}
