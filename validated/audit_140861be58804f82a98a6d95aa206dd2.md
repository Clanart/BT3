### Title
Payout OP_RETURN operator attribution is unauthenticated, letting anyone front a withdrawal and mis-credit (or orphan) the reimbursement - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` writes the "fronting" operator's x-only pubkey into an `OP_RETURN` output that is not covered by the user's withdrawal signature, and `update_finalized_payouts` later trusts that `OP_RETURN` value as the sole source of truth for who gets credited (and later reimbursed) for the payout. Because the signature scheme used for the withdrawal input is `SIGHASH_SINGLE|ANYONECANPAY`, the `OP_RETURN` output and any extra funding inputs are entirely unconstrained by the user's authorization, so any unprivileged party who reconstructs the transaction can pick an arbitrary `operator_xonly_pk` to attribute the payout to, breaking the "operator credited == party that paid" binding.

### Finding Description
The payout transaction is built as: [1](#0-0) 

Only input index 0 (the user's withdrawal UTXO) is signed by the user, via `set_p2tr_key_spend_witness(&user_sig, 0)`, and the operator's `withdraw()` verifies the sighash for **only that input**: [2](#0-1) 

The `output_amount`/`out_script_pubkey` checked here correspond to output index 0. Because the sighash type used for this input is `SinglePlusAnyoneCanPay` (confirmed by the `parse_withdrawal_sig_params`/verification-signature machinery in `core/src/rpc/parser/operator.rs` and `core/src/rpc/aggregator.rs`), the signature commits only to input #0 and its matching output #0 — **not** to the anchor output, **not** to the `OP_RETURN` output carrying `operator_xonly_pk`, and **not** to any additional funding inputs that get appended by whoever assembles the final broadcast transaction (as happens in `fund_raw_transaction`/wallet funding in `withdraw()`): [3](#0-2) 

Because `input_utxo`'s outpoint and required output are both derived from the withdrawal state that is committed on Citrea (public, permissionless data — every operator or client independently reconstructs the identical `input_outpoint`/`output_txout`/`user_sig` from `get_withdrawal_utxo_from_citrea_withdrawal`), any party capable of observing this public information can build its own payout transaction: it reuses the untouched, signed input+output #0, funds any additional fee inputs from its own wallet, and inserts **any x-only public key it wants** in the `OP_RETURN` output — including the pubkey of a legitimate, uninvolved operator, or an arbitrary/garbage key that matches no registered operator.

Downstream, the chain-observing verifier code takes this self-declared `OP_RETURN` value at face value as the "payer": [4](#0-3) 

and persists it permanently to the `withdrawals` table via `update_payout_txs_and_payer_operator_xonly_pk`, gating the entire reimbursement lifecycle on this unauthenticated value: [5](#0-4) 

The reimbursement path (`get_reimbursement_txs` → `validate_payer_is_operator`) only proceeds for the operator whose own xonly pubkey exactly equals the recorded `payout_payer_operator_xonly_pk`: [6](#0-5) 

and `is_kickoff_malicious` in the verifier enforces the same equality when validating a kickoff against the recorded payout: [7](#0-6) 

There is no on-chain proof (e.g., a signature, a matching funding input from a known operator wallet address, or a check against the registered operator set) tying the claimed `operator_xonly_pk` to whoever actually funded/broadcast the transaction.

### Impact Explanation
Once a payout transaction for a given Citrea withdrawal index is confirmed and finalized by verifiers, the withdrawal's `withdrawal_utxo` is spent — no second payout tx can ever be created for the same withdrawal. If the `OP_RETURN` operator pubkey embedded by the (possibly non-operator) broadcaster does not equal any currently active operator's key, `validate_payer_is_operator`/`is_kickoff_malicious` will never match for any operator, so:
- No operator will ever be able to trigger the kickoff/reimburse flow for this deposit (`get_reimbursement_txs` errors out for everyone since no signer's own key equals the DB-recorded payer), permanently orphaning the reimbursement claim and leaving the corresponding `move_to_vault` UTXO's BTC unreachable via the intended flow — this matches the "vault UTXO permanently frozen" / "honest operator permanently unable to be reimbursed" impact class.
- Alternatively, if the attacker sets the `OP_RETURN` to a real, uninvolved operator's pubkey, that operator's `PayoutCheckerTask` will treat the withdrawal as its own payout and attempt kickoff/reimbursement for BTC it never fronted, risking that operator being challenged/slashed for a kickoff it did not actually cause, or (if unchallenged) reimbursed for a payment it never made — matching "operator reimbursed for a payout it never funded."

This is a Critical-severity custody/attribution binding break with an unprivileged attacker as the only prerequisite.

### Likelihood Explanation
Exploitation requires only: (1) observing the withdrawal's public commitment data on Citrea (outpoint, output script/amount, user signature) which is by design accessible off-chain to any party that wants to front the payout, and (2) constructing/broadcasting a standard Bitcoin transaction with `SIGHASH_SINGLE|ANYONECANPAY` reuse of the signed input, funding fees from any wallet, and an arbitrary `OP_RETURN`. No verifier or operator key, no race condition beyond normal mempool competition, and no protocol misconfiguration is needed — this is directly reachable by any external, unprivileged actor with basic Bitcoin tooling.

### Recommendation
Do not trust a self-declared `OP_RETURN` field as attribution proof. Options:
- Bind the payer identity cryptographically to the transaction, e.g. require the operator's fee-funding input(s) to originate from that operator's registered on-chain address (verified during `update_finalized_payouts`), or require an operator signature over the full transaction (not just the SINGLE-input-covered part).
- Change the sighash to cover the `OP_RETURN` output as well (e.g. use `SIGHASH_ALL` won't work since fee funding must remain flexible, but at minimum extend the committed outputs, or add a covenant/second signature requiring the operator's own key to sign the whole payout package).
- At minimum, in `update_finalized_payouts`, reject/ignore any `operator_xonly_pk` parsed from `OP_RETURN` that does not correspond to a currently registered operator, and require some economic/cryptographic proof that the claimed operator's own funds were spent in the transaction (e.g., verify one of the additional inputs pays from that operator's known collateral/wallet address).

### Proof of Concept
1. Observe the public Citrea withdrawal commitment for `withdrawal_index`: `input_outpoint`, `out_script_pubkey`, `out_amount`, and `in_signature` (all obtainable the same way any operator obtains them, via `get_withdrawal_utxo_from_citrea_withdrawal`/Citrea client, as done in `core/src/operator.rs:560-626`).
2. Build a transaction identical to `create_payout_txhandler`'s output #0 (matching the signed sighash), add your own wallet UTXO(s) as extra funding inputs (any additional inputs are unconstrained under `ANYONECANPAY`), attach the same `in_signature` at input #0 via key-spend witness, and set the `OP_RETURN` output to any `operator_xonly_pk` of your choosing (e.g., a currently-registered but uninvolved operator's key, or a garbage key).
3. Broadcast the transaction before any legitimate operator's `withdraw()` call lands; it confirms and spends the withdrawal UTXO.
4. Verifiers' `update_finalized_payouts` parses the injected `OP_RETURN` value and records it in `withdrawals.payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`), permanently fixing (mis)attribution for this withdrawal since the UTXO can never be spent again.
5. Depending on the chosen key, either no operator's `validate_payer_is_operator` check ever succeeds (permanent freeze of the corresponding vault funds/reimbursement), or the targeted operator's automation (`PayoutCheckerTask`) begins acting as though it made a payout it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self

            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
