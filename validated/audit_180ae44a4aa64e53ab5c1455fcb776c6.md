### Title
Untrusted `ReceivedOutput` deserialization permits forged unspendable UTXOs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an attacker-controlled scalar offset, transaction output, and outpoint without binding them to scanner registration, blockchain existence, or ownership evidence. [1](#0-0) 

### Finding Description
`ReceivedOutput` is defined as a spendable output consisting of `offset`, `output`, and `outpoint`. [2](#0-1) 

The parser validates only that the scalar and Bitcoin consensus encodings are structurally valid; it does not prove that the outpoint exists, that the output is unspent, or that the offset corresponds to the output's script. [3](#0-2) 

Legitimate outputs are normally produced by `Scanner::scan_transaction`, which records an offset only after matching `output.script_pubkey` against registered scripts. [4](#0-3) 

Deserializing bytes bypasses that scan path and can directly inject an arbitrary tuple into the trusted `ReceivedOutput` representation. [1](#0-0) 

### Impact Explanation
An attacker who controls bytes passed to `ReceivedOutput::read` can cause the wallet to report funds that are not spendable. [1](#0-0) 

If the forged `TxOut` uses the wallet's Taproot script and the serialized offset is `0`, `SignableTransaction::multisig` accepts the forged input because it checks only that `keys.offset(offset).group_key()` produces `prevouts[i].script_pubkey`; it does not verify that the referenced outpoint exists or is unspent. [5](#0-4) 

The resulting transaction can then be generated and signed against a nonexistent or already-spent outpoint, causing incorrect balance accounting and a transaction that Bitcoin consensus will reject. [6](#0-5) 

### Likelihood Explanation
The sink is directly reachable through public attacker-controlled bytes supplied to `ReceivedOutput::read`. [1](#0-0) 

The attacker only needs a valid canonical scalar plus consensus-valid `TxOut` and `OutPoint` encodings; no malformed scalar, invalid point, malformed script structure, or private-key knowledge is required. [3](#0-2) 

Using the wallet's known script_pubkey and offset `0` satisfies the downstream ownership check for the wallet's base Taproot output. [7](#0-6) 

### Recommendation
Do not treat deserialized `ReceivedOutput` values as authoritative wallet observations. [1](#0-0) 

After deserialization, revalidate each object by rescanning the referenced transaction output through `Scanner`, confirming that the stored outpoint refers to the expected transaction and `vout`, and checking blockchain confirmation and spentness before exposing it as spendable. [4](#0-3) 

If untrusted persisted or network input is supported, authenticate it or include enough context to bind `offset`, `TxOut`, `OutPoint`, and scanner state together. [8](#0-7) 

### Proof of Concept

```rust
use bitcoin::{
  consensus::encode::serialize,
  hashes::Hash,
  Amount, OutPoint, TxOut, Txid,
};
use frost::curve::{Ciphersuite, Secp256k1};
use serai_bitcoin::wallet::ReceivedOutput;

// `victim_script` is the base P2TR script produced for the wallet's group key.
fn forge(victim_script: bitcoin::ScriptBuf) -> ReceivedOutput {
  let mut bytes = Vec::new();

  // Offset 0 selects the wallet's untweaked/base scanned output.
  bytes.extend_from_slice(
    <Secp256k1 as Ciphersuite>::F::ZERO.to_repr().as_ref()
  );

  // The script matches the wallet, but the outpoint below does not identify
  // an existing spendable UTXO.
  let fake_output = TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: victim_script,
  };
  bytes.extend_from_slice(&serialize(&fake_output));

  let fake_outpoint = OutPoint {
    txid: Txid::all_zeros(),
    vout: 0,
  };
  bytes.extend_from_slice(&serialize(&fake_outpoint));

  // Accepted solely because all fields are encodable/decodable.
  ReceivedOutput::read(&mut bytes.as_slice()).unwrap()
}
```

The returned value reports a 100,000-satoshi output controlled by offset `0`, despite referring to a fabricated outpoint. [3](#0-2) 

Passing it to `SignableTransaction::new` and then `multisig` reaches the script/offset check, which accepts the tuple when the forged `TxOut` uses the corresponding wallet script. [7](#0-6)
