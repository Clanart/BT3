### Title
`ThresholdKeys::read` accepts identity verification shares, silently resetting the group key to the zero key - (File: crypto/dkg/src/lib.rs)

### Summary
The bug class is a zero value being accepted into a state setter, causing downstream logic to treat the state as freshly initialized. In Serai, `ThresholdKeys::read` deserializes `verification_shares` with `Ciphersuite::read_G`, which enforces canonical encodings but does **not** reject the identity point (the point encoding of zero). `ThresholdKeys::new` then derives `group_key` purely as an interpolation of these shares. An untrusted blob filled with identity verification shares and a zero `secret_share` deserializes into a fully "valid" `ThresholdKeys` whose `group_key()` is the identity — i.e. the public key of secret `0`. All signing/verification paths over these keys then operate on a key whose discrete logarithm is publicly known, analogously to `setAddress(0)` wiping a module back to genesis state.

### Finding Description
`ThresholdKeys::read` reads `n` verification shares via `<C as Ciphersuite>::read_G`: [1](#0-0) 

`Ciphersuite::read_G` only checks canonicality, not identity: [2](#0-1) 

This contrasts with FROST's `Curve::read_G`, which explicitly rejects identity: [3](#0-2) 

`ThresholdKeys::new` never checks that any verification share is non-identity, nor that `secret_share * G == verification_shares[i]`; it computes the group key solely as the interpolated sum of the supplied shares: [4](#0-3) 

With `t = 1, n = 1`, `verification_shares = {1: identity}`, `secret_share = 0`, `Interpolation::Lagrange`, deserialization succeeds and yields `group_key() == identity`, while `view()` and `secret_share()` proceed normally since participant validation only checks indexes, not point values (`crypto/dkg/src/lib.rs:463-521`). A FROST `AlgorithmMachine` built on these keys will produce signature shares that verify against the identity verification share, and `complete()` emits a `SchnorrSignature` valid under the identity group key — a signature anyone can forge independently of this code path, since the discrete log of the group key is `0`.

### Impact Explanation
Any component that instantiates a multisig from untrusted `ThresholdKeys::read` bytes and then uses `group_key()` as an authorization root (scanning for received funds, verifying FROST signatures, registering validator sets) can be fed keys whose reported group key is the zero key. Funds credited to that group key are spendable by anyone knowing scalar `0`, and signatures "produced" by the multisig are forgeable without any threshold participation — a forged signature / funds reported received that are controlled by the attacker.

### Likelihood Explanation
The identity encodings are canonical, so `read_G` accepts them; no index, interpolation, or share-consistency check catches the inconsistency (`ThresholdKeys::new` only checks the share count and participant bounds). Exploitation requires an integrator to load `ThresholdKeys` from an attacker-influenceable source, which is exactly the untrusted-bytes-to-`read` reachability this audit models. Severity is Medium: it requires an integrator feeding attacker-controlled key blobs rather than honest DKG output, but the resulting loss of key authenticity is complete.

### Recommendation
In `ThresholdKeys::new` (covering both `read` and programmatic construction), reject identity verification shares and additionally verify `C::generator() * secret_share == verification_shares[&params.i()]`, mirroring how `Curve::read_G` rejects identity for FROST protocol messages. Rejecting identity at deserialization time prevents the zero-key "reset" state from ever being constructed.

### Proof of Concept
```rust
// t = n = i = 1, single identity verification share, zero secret share
let mut buf = vec![];
buf.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
buf.extend(C::ID);
buf.extend(1u16.to_le_bytes());            // t
buf.extend(1u16.to_le_bytes());            // n
buf.extend(1u16.to_le_bytes());            // i
buf.push(1);                               // Interpolation::Lagrange
buf.extend(C::F::ZERO.to_repr().as_ref()); // secret_share = 0
buf.extend(C::G::identity().to_bytes().as_ref()); // verification_shares[1] = identity

let keys = ThresholdKeys::<C>::read::<&[u8]>(&mut buf.as_ref()).unwrap();
assert!(bool::from(keys.group_key().is_identity())); // group key is the zero key
// Schnorr signatures under this group key are forgeable by anyone (secret = 0).
```
