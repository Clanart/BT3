### Title
Credential helper trusts attacker-controlled `WWW-Authenticate` realm to classify a remote as GitHub, triggering GitHub sign-in prompts for arbitrary hosts - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
`getEndpointKind()` in the git credential-helper trampoline decides whether a remote endpoint is treated as `github.com`, `ghe.com`, `enterprise`, or `generic`. When the URL doesn't match known GitHub.com/GHE.com hosts, the function falls back to trusting the `WWW-Authenticate` HTTP header value that Git captured from the remote server's 401 response and forwarded to the credential helper as `wwwauth[]` fields. [1](#0-0) 

### Finding Description
The classification logic is: [2](#0-1) 

Any server the user's Desktop connects to over HTTP(S) — a self-hosted git server, a proxy, or a compromised/malicious remote — fully controls the `WWW-Authenticate` header it returns on a 401. If it includes `realm="GitHub"`, `getEndpointKind` returns `'enterprise'` for a completely arbitrary hostname, with no verification (e.g. no call to `isGitHubHost()`, which does an actual API probe) at that branch. This value then flows into `getCredential()`: [3](#0-2) 

Because `endpointKind !== 'generic'` and no existing account matches that (attacker-chosen) endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which is wired to begin a real Enterprise sign-in flow (`dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint`) using the attacker-supplied endpoint string: [4](#0-3) 

The broken invariant: the "is this a GitHub host" classification — which gates whether Desktop opens a trusted-looking GitHub/Enterprise sign-in UI — is derived from data the remote itself controls, not from any cryptographic or server-verified property. Existing guards (`isDotCom`, `isGHE`, and the network-probing `isGitHubHost`) are bypassed by the header-trust branch, which runs before the harder `isGitHubHost` check at line 178.

### Impact Explanation
An attacker who controls a git remote/proxy (a repo the user clones/adds, or a MITM/compromised HTTP proxy in the fetch/push path) can force Desktop's credential-helper trampoline to present the user with a "sign in to this GitHub Enterprise server" prompt for an arbitrary attacker-chosen domain, even though the domain has no real relationship to GitHub. This is a spoofing primitive that could be used to social-engineer/phish OAuth or PAT-based sign-in against an attacker endpoint under the guise of Desktop's legitimate, trusted sign-in dialog. If the resulting sign-in flow performs any exchange (OAuth callback, device code, or PAT validation request) against the attacker endpoint, this could result in unauthorized account binding as covered by the report's valid-impact list.

### Likelihood Explanation
I could **not** fully confirm within the available tool budget whether `beginEnterpriseSignIn`/`sign-in-store.ts` performs any authenticity check on the endpoint (e.g., verifying it actually exposes a GitHub Enterprise API) before initiating OAuth/token exchange, so the severity of the eventual UI action is uncertain. The classification bypass itself (`getEndpointKind` trusting `wwwauth[]`) is directly evidenced in code. Triggering it only requires the user to perform an ordinary git fetch/push against a remote the attacker controls or intercepts — no elevated privileges or unnatural steps are needed, which aligns with the report's threat model of an attacker-controlled git remote/proxy response.

### Recommendation
Do not use the client-supplied `WWW-Authenticate` realm as sufficient evidence that a host is a genuine GitHub/GHE instance for purposes of triggering the GitHub sign-in UI. At minimum, require the server-verifying `isGitHubHost()` check (which is already used as the final fallback) before ever presenting a GitHub-branded sign-in prompt, and/or require confirmation that the resulting sign-in target matches a user-configured/trusted Enterprise endpoint before starting an OAuth or token exchange flow.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
