### Title
Permissionless `addCW20Pointer` creates an ERC20 pointer for any wasm contract that merely mimics a `token_info` query, without verifying CW20 spec compliance - ([File: precompiles/pointer/pointer.go])

### Summary
The Allo report flags that `Allo.sol` casts any address to `IStrategy` without checking that it actually implements `BaseStrategy`, breaking the protocol's invariant that "every strategy implements `BaseStrategy`". The same class of bug exists in sei-chain's CW20↔ERC20 pointer precompile: `addCW20Pointer` treats any CosmWasm contract that returns a JSON object with `name`/`symbol` fields from a `{"token_info":{}}` query as if it were a fully spec-compliant CW20 token, and permanently registers a corresponding on-chain "canonical" ERC20 pointer for it — without ever validating that the contract implements the rest of the CW20 execute/query surface (`transfer`, `transfer_from`, `balance`, `allowance`, `increase_allowance`, `decrease_allowance`).

### Finding Description
`PrecompileExecutor.AddCW20` in [1](#0-0)  only performs a single sanity check: it queries `{"token_info":{}}` on the target address and unmarshals `name`/`symbol` out of the JSON response. If that single query succeeds and returns those two fields, it immediately creates and registers a pointer contract via `UpsertERCCW20Pointer`, with no verification that the target contract implements any other part of the CW20 interface. This is the same acceptance criteria seen across all historical/legacy versions of the same handler, e.g. [2](#0-1) , [3](#0-2) , and via the `MsgRegisterPointer` message handler which likewise only checks contract existence, not interface compliance, in [4](#0-3) .

Once registered, the resulting `CW20ERC20Pointer.sol` contract is treated by the whole EVM ecosystem (wallets, DEXes, RPC consumers) as a standards-compliant `ERC20`. Its `balanceOf`, `allowance`, `transfer`, `transferFrom`, and `approve` implementations blindly forward CosmWasm queries/executes to the underlying wasm contract and trust its internal accounting completely — there is no independent EVM-side balance/allowance bookkeeping to cross-check against: [5](#0-4) 

Because `AddCW20`/`MsgRegisterPointer` never confirm the target implements `transfer`, `transfer_from`, `balance`, or `allowance` semantics correctly (or at all — beyond the single `token_info` probe), any user can deploy a minimal or intentionally malicious wasm contract that:
- Responds to `token_info` with plausible `name`/`symbol` fields (satisfying registration), and
- Implements a broken/malicious `transfer_from` or `transfer` handler (e.g., ignoring allowance checks, moving a different amount than requested, or always returning success without moving funds),

and register it as the chain's canonical CW20→ERC20 pointer. This mirrors the root cause in the referenced report exactly: an address is accepted and treated as implementing a full standard interface based on a partial/no-op interface check, breaking the invariant that "pointer == spec-compliant token."

### Impact Explanation
Downstream EVM consumers (bridges, DEX routers, custodians, any contract or off-chain integrator that queries the pointer's `allowance`/`transferFrom`) rely on the pointer behaving like a standard, allowance-respecting ERC20. Since `transferFrom`'s authorization logic is entirely delegated to the wasm contract's own `transfer_from` handler [6](#0-5)  with no EVM-side allowance enforcement, a wasm contract that does not correctly enforce the CW20 allowance model (or the caller-address translation done via `AddrPrecompile.getSeiAddr`) could allow unauthorized transfers of the tokens it represents — i.e., unauthorized transfer via a pointer, and consequent fund loss/confusion for anyone who trusted the pointer as a genuine CW20 wrapper. This satisfies the "unauthorized transfer via precompile or pointer" / "concrete fund loss" impact bar.

### Likelihood Explanation
Registration is fully permissionless and reachable from a single EVM transaction: any address can call `addCW20Pointer(cwAddr)` on the pointer precompile (`0x...100b`), or send `MsgRegisterPointer`, pointing at a wasm contract they themselves deployed and control. The only gate is `GetRegisterPointerDisabled` (an on/off chain param, not per-contract validation) [7](#0-6) . No governance or privileged action is required to trigger the mis-registration; the only requirement is crafting a wasm contract whose `token_info` query returns the two expected string fields, which is trivial.

### Recommendation
Extend the `AddCW20`/`RegisterPointer` validation to require successful, spec-consistent responses from the full required CW20 query/execute surface before registering a pointer — at minimum verify `balance`, `allowance`, and that `transfer`/`transfer_from`/`increase_allowance`/`decrease_allowance` execute messages are accepted and produce state changes consistent with the CW20 spec (e.g., via a dry-run/simulate or by checking for the correctly typed CW20 attributes in message responses), analogous to requiring `IStrategy` implementations to conform to `BaseStrategy` in the referenced report.

### Proof of Concept
1. Deploy a wasm contract `EvilCW20` that:
   - Responds to `{"token_info":{}}` with `{"name":"Evil","symbol":"EVIL","decimals":6,"total_supply":"1000000"}` (satisfies the only check performed).
   - Implements `balance` query returning attacker-controlled values.
   - Implements `transfer_from` execute message that ignores the `allowance` state entirely and always succeeds, moving funds regardless of prior `approve`/`increase_allowance` calls.
2. Call `addCW20Pointer(EvilCW20Address)` on the pointer precompile at `0x000000000000000000000000000000000000100b` from any unprivileged EVM account; this succeeds because only `token_info` is checked ( [8](#0-7) ), producing a live `CW20ERC20Pointer` contract for `EvilCW20`.
3. Any third party that treats the returned pointer address as a legitimate ERC20 (e.g., approving it, or relying on `allowance`/`transferFrom` semantics) can have funds moved via `transferFrom` without a valid allowance, since the pointer's `transferFrom` merely delegates to the wasm contract's `transfer_from` handler with no independent allowance enforcement on the EVM side ( [6](#0-5) ).

Note: full exploitation depends on downstream integrators trusting the pointer as a compliant ERC20; the core vulnerability (accepting any contract based on a single unauthenticated `token_info` probe) is directly verified in code, matching the report's root cause of casting to an interface without enforcing its full contract.

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (server msgServer) RegisterPointer(goCtx context.Context, msg *types.MsgRegisterPointer) (*types.MsgRegisterPointerResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	if server.GetRegisterPointerDisabled(ctx) {
		return nil, fmt.Errorf("registering CW->ERC pointers has been disabled")
	}
	var existingPointer sdk.AccAddress
	var existingVersion uint16
	var currentVersion uint16
	var exists bool
	switch msg.PointerType {
	case types.PointerType_ERC20:
		currentVersion = erc20.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW20ERC20Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC721:
		currentVersion = erc721.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW721ERC721Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC1155:
		currentVersion = erc1155.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW1155ERC1155Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	default:
		panic("unknown pointer type")
	}
	if exists && existingVersion >= currentVersion {
		return nil, fmt.Errorf("pointer %s already registered at version %d", existingPointer.String(), existingVersion)
	}
	payload := map[string]interface{}{}
	switch msg.PointerType {
	case types.PointerType_ERC20:
		payload["erc20_address"] = msg.ErcAddress
	case types.PointerType_ERC721:
		payload["erc721_address"] = msg.ErcAddress
	case types.PointerType_ERC1155:
		payload["erc1155_address"] = msg.ErcAddress
	default:
		panic("unknown pointer type")
	}
	codeID := server.GetStoredPointerCodeID(ctx, msg.PointerType)
	moduleAcct := server.accountKeeper.GetModuleAddress(types.ModuleName)
	var err error
	var pointerAddr sdk.AccAddress
	if exists {
		bz, _ := json.Marshal(map[string]interface{}{})
		pointerAddr = existingPointer
		_, err = server.wasmKeeper.Migrate(ctx, existingPointer, moduleAcct, codeID, bz)
	} else {
		bz, jerr := json.Marshal(payload)
		if jerr != nil {
			return nil, jerr
		}
		pointerAddr, _, err = server.wasmKeeper.Instantiate(ctx, codeID, moduleAcct, moduleAcct, bz, fmt.Sprintf("Pointer of %s", msg.ErcAddress), sdk.NewCoins())
	}

    function transfer(address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));
        string memory req = _curlyBrace(_formatPayload("transfer", _curlyBrace(_join(recipient, amt, ","))));

        return true;
    }

    function transferFrom(address from, address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory sender = _formatPayload("owner", _doubleQuotes(AddrPrecompile.getSeiAddr(from)));
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));
        string memory req = _curlyBrace(_formatPayload("transfer_from", _curlyBrace(_join(_join(sender, recipient, ","), amt, ","))));
        _execute(bytes(req));
        return true;
    }

    function _execute(bytes memory req) internal returns (bytes memory) {
        (bool success, bytes memory ret) = WASMD_PRECOMPILE_ADDRESS.delegatecall(
            abi.encodeWithSignature(
                "execute(string,bytes,bytes)",
                Cw20Address,
                bytes(req),
                bytes("[]")
            )
        );
        require(success, "CosmWasm execute failed");
        return ret;
    }
