### Title
Governance-controlled `GaslessSwapRouter` address change can rug all users who granted `abi.MaxUint256` gasless approvals - (File: kaiax/gasless/impl/getter.go, kaiax/gasless/impl/tx_pool.go)

### Summary
The KIP-247 gasless-transaction flow requires users to grant an unlimited (`abi.MaxUint256`) ERC-20 `approve()` to whatever address is currently registered in the `Registry` (KIP-149) system contract under the `GaslessSwapRouter` key. The node's `kaiax/gasless` module re-reads this address every block from the `Registry`/`MultiCall` system contracts and immediately trusts it as the valid spender for all future `GaslessSwapTx`s. If the address registered for `GaslessSwapRouter` is changed to a malicious/compromised contract (an action gated only by the `Registry` contract's admin/owner logic, analogous to the proxy-admin in the original Controller.sol finding), then every user who had previously executed a `GaslessApproveTx` (unlimited approval) can have their entire approved-token balance pulled by the new "router" contract without any further action or consent from the user.

### Finding Description
Gasless approve transactions are validated only against the *currently registered* router address and require the approved amount to equal `abi.MaxUint256`: [1](#0-0) 

The swap router address itself is not immutable — it is fetched fresh every block from the `Registry` system contract via `getGaslessInfo`/`MultiCallGaslessInfo`, and the module simply overwrites its cached `swapRouter` with whatever value is currently registered: [2](#0-1) [3](#0-2) 

The end-to-end integration test confirms this: the `GaslessSwapRouter` address is set via a simple `registry.Register(owner, GaslessSwapRouterName, gsrAddr, targetBlockNum)` call, and a scheduled block-number can activate a *different* registered address (`anotherGSR`) that the module will pick up automatically on the next block: [4](#0-3) [5](#0-4) 

Because `GaslessApproveTx` grants `abi.MaxUint256` allowance (see condition `A4` above) to the router address that is valid *at approval time*, and the module (and therefore honest nodes/tx-pool promotion logic) will treat any subsequently-registered address as the trusted spender, an admin/governance actor controlling the `Registry` contract's `GaslessSwapRouterName` record can redirect the "router" role to an attacker-controlled contract. Because users' unlimited approvals remain outstanding on-chain against the token contracts (the approval targets the *address*, not a specific implementation), the newly registered malicious contract can call `transferFrom` on every user who had an outstanding unlimited approval and drain their full balance of the allowed tokens, with no interaction required from the victims. This mirrors the Controller.sol report exactly: the entity trusted to hold/consume users' allowances is swappable by a privileged party, and the "current amount of user funds at risk" is the sum of all outstanding unlimited approvals.

### Impact Explanation
This is a direct value-extraction path: an admin/governance actor (or anyone who can get a malicious address registered as `GaslessSwapRouter` in the `Registry`) can steal the full allowed-token balances of every user who used the gasless-approve flow, without any additional user transaction. The impact is equivalent in kind to the original finding — theft of user funds via allowance abuse triggered by a privileged configuration change — and is High/Medium depending on whether the "governance attack" precondition is treated as in-scope (Rolla's own finding was downgraded to Medium for the same reason: a governance/admin action must occur first).

### Likelihood Explanation
Requires control over (or compromise of) the `Registry`'s update/ownership mechanism for the `GaslessSwapRouterName` key, which is the same category of "governance attack must happen first" precondition that the original report was downgraded for. Given the module blindly re-reads and trusts the registered router address every block with no additional validation (e.g., no allow-list of historically approved routers, no timelock enforcement visible in the node logic, no revocation check), the likelihood of exploitation is high once such control is obtained.

### Recommendation
- Avoid relying on unbounded (`MaxUint256`) approvals to a system-registry-mutable address; use per-transaction, bounded allowances (`Permit`/exact-amount `approve`) so that changing the registered router cannot retroactively grant spend rights over previously-approved balances.
- Enforce a timelock and/or multi-step confirmation combined with an allow-list/deny-list of router addresses so a single registry update cannot instantly redirect trust.
- Have the gasless module validate that `swapRouter` transitions are only accepted from a known-good address set, or require users to explicitly re-approve after a router rotation rather than implicitly trusting the newly registered address for pre-existing approvals.

### Proof of Concept
1. Alice calls `approve(GaslessSwapRouter_v1, MaxUint256)` on `TokenX` and successfully executes a `GaslessApproveTx`/`GaslessSwapTx` pair, as validated by `isApproveTx`/`isSwapTx` in [6](#0-5) .
2. The `Registry` owner/governance calls `Registry.register("GaslessSwapRouter", maliciousRouter, targetBlockNum)`, exactly as done in the test at [5](#0-4) .
3. At `targetBlockNum`, `updateAddresses`/`getGaslessInfo` on every kaia node updates `g.swapRouter = maliciousRouter` ( [2](#0-1) ), and the node's gasless module now treats `maliciousRouter` as the canonical spender.
4. `maliciousRouter` calls `TokenX.transferFrom(Alice, attacker, aliceBalance)` directly (outside of the gasless TxPool checks, e.g. via a normal transaction) using the still-outstanding `MaxUint256` allowance Alice granted in step 1 — draining Alice's full `TokenX` balance without her consent.

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func getGaslessInfo(bc backends.BlockChainForCaller, header *types.Header) (common.Address, []common.Address, error) {
	statedb, err := bc.StateAt(header.Root)
	if err != nil {
		return common.Address{}, nil, err
	}

	// If Registry is not installed, do not query GaslessSwapRouter contract.
	if statedb.GetCode(system.RegistryAddr) == nil || bc.Config().IsRandaoForkBlockParent(header.Number) {
		return common.Address{}, nil, nil
	}

	caller, err := system.NewMultiCallContractCaller(statedb, bc, header)
	if err != nil {
		return common.Address{}, nil, err
	}

	opts := &bind.CallOpts{BlockNumber: header.Number}
	info, err := caller.MultiCallGaslessInfo(opts)

	return info.Gsr, info.Tokens, err
}
