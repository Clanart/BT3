### Title
Unbounded loop over the growing `pools` array in `castVotes()` can permanently DoS bribe voting/harvesting - (File: `wombat/WombatBribeManager.sol`)

### Summary
`WombatBribeManager.castVotes()` is a public, unprivileged function that iterates over the entire `pools` array with no bound, size cap, or pagination mechanism, mirroring the reported `Project.projectCost()` unbounded-loop DoS pattern.

### Finding Description
`castVotes()` reads `uint256 length = pools.length;` and then loops `for (uint256 i; i < length; i++)` performing a storage read (`poolInfos[pools[i]]`), an external call `getVoteForLp(pool.poolAddress)` (itself calling `voter.getUserVotes(...)`), and arithmetic per pool, before finally calling `wombatStaking.vote(...)` with arrays sized to the full pool count [1](#0-0) . The `pools` array only grows via `addPool()` and is never bounded in size [2](#0-1) . There is no stopping mechanism, size cap, or way for a caller to page/limit the range of pools processed in a single `castVotes()` call — exactly the bug class described in the external report where `projectCost()` iterates the full `tasks[]` array with no cap. As the number of supported Wombat LP pools grows over the life of the protocol (a normal, expected operational trajectory, not an admin attack), `castVotes()`'s gas cost grows linearly and unboundedly until it exceeds the block gas limit, at which point the transaction will always revert regardless of who calls it or how much gas they supply.

`claimAllBribes()` has the identical unbounded-loop structure over `pools.length` [3](#0-2) , but a workaround exists via `claimBribe(lps)`/`claimBribeFor(lps, _for)`, which take an explicit caller-supplied subset of LPs [4](#0-3) [5](#0-4) . `castVotes()`, however, has no such subset/paged variant — it is the sole entry point that both casts votes to Wombat's veWom voting system and harvests+forwards the actual bribe rewards into each pool's `IBribeRewardPool` rewarder [6](#0-5) . If `castVotes()` can never execute due to gas exhaustion, bribe rewards from Wombat are never harvested and forwarded to the per-pool `BribeRewardPool` rewarders, so even `claimBribe`/`claimAllBribes` (which merely call `getReward` on the rewarder) would have nothing new to distribute.

### Impact Explanation
Once the `pools` array grows large enough that `castVotes()` exceeds the block gas limit, no address (privileged or not) can successfully cast votes or trigger harvesting/forwarding of bribe rewards into the pool rewarders — there is no alternate, paginated code path for this specific operation. This results in a permanent (>24h, effectively indefinite) freeze of unclaimed/future bribe yield for all vlMGP voters, satisfying the "theft or permanent freezing of unclaimed yield" / "24-hour-plus freeze" bar. The condition is triggered purely by ordinary, expected growth of supported pools, not by malicious admin behavior — `addPool` being restricted to `onlyOwner` is incidental to normal protocol operation, not the exploit itself.

### Likelihood Explanation
Likelihood depends on the number of Wombat pools onboarded over time and current chain gas limits; it is not immediately exploitable at small pool counts but is a foreseeable and unavoidable operational failure mode as the pool list expands, with no mitigation currently present in the contract (unlike `removePool`, which exists but does not prevent net growth as new pools are continuously listed).

### Recommendation
Refactor `castVotes()` (and `claimAllBribes()`) to support processing pools in bounded batches/pages (e.g., accept a start/end index or explicit subset like `claimBribe` already does), so that gas cost per call is bounded regardless of total pool count, and callers can iterate across multiple transactions to fully cast votes/harvest bribes.

### Proof of Concept
1. Owner repeatedly calls `addPool()` to add new Wombat LP pools over time as the protocol integrates more pools [2](#0-1) ; `pools.length` grows without any cap.
2. Any user calls `castVotes()` (public, unprivileged) [7](#0-6) .
3. `castVotes()`'s loop cost scales linearly with `pools.length` [8](#0-7) ; once `pools.length` is large enough, the transaction's gas requirement exceeds the block gas limit and it reverts unconditionally.
4. Because there is no alternate path to cast votes/harvest+forward bribes in smaller batches, this becomes a permanent denial of service on bribe reward harvesting/forwarding, freezing yield for all voters indefinitely.

    function castVotes(bool swapForBnb)
        override public
        returns (address[][] memory finalRewardTokens, uint256[][] memory finalFeeAmounts)
    {
        lastCastTime = block.timestamp;
        uint256 length = pools.length;
        address[] memory _pools = new address[](length);
        int256[] memory votes = new int256[](length);
        address[] memory rewarders = new address[](length);

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[pools[i]];
            _pools[i] = pool.poolAddress;
            rewarders[i] = pool.rewarder;

            uint256 currentVote = getVoteForLp(pool.poolAddress);
            uint256 targetVoteInLMGP = pool.totalVoteInVlmgp;
            uint256 targetVote = 0;

            if (totalVlMgpInVote != 0) {

            if (targetVote >= currentVote) {
                votes[i] = int256(targetVote - currentVote);
            } else {
                votes[i] = int256(targetVote) - int256(currentVote);
            }
        }
