### Title
Unauthenticated OP_RETURN operator attribution in `create_payout_txhandler` lets an attacker steal payout credit from the real funding operator - (File: `core/src/builder/transaction/operator_reimburse.rs`, `core/src/task/payout_checker.rs`, `core/src/verifier.rs`)

### Summary
The payout transaction's OP_RETURN output, which records which operator "fronted" a withdrawal and is later used to decide who gets reimbursed, is not covered by the user's `SinglePlusAnyoneCanPay` signature. Anyone observing an unconfirmed payout transaction in the mempool can rebroadcast a fee-bumped variant with the same withdrawal input/output but an arbitrary operator's xonly public key in the OP_RETURN, hijacking the reimbursement credit for a payout that operator never funded.

### Finding Description
The broken binding: `party_credited_and_reimbursed == party_that_funded_the_payout`. It must hold `payout_payer_operator_xonly_pk == the operator whose Bitcoin wallet actually paid the user`. After the attack it becomes `payout_payer_operator_xonly_pk == C` while the party who actually funded/attempted the withdrawal is `A` (or the attacker's own fee-bumping funds), a clear violation.

Root cause: `Operator::withdraw` builds the payout tx via `create_payout_txhandler`, which adds an OP_RETURN output containing `operator_xonly_pk`, and signs input 0 with the user's `TapSighashType::SinglePlusAnyoneCanPay` signature: [1](#0-0) [2](#0-1) 

`calculate_pubkey_spend_sighash`/`calculate_sighash_txin` compute the sighash using `Prevouts::One` for any `*PlusAnyoneCanPay` type: [3](#0-2) 

Per BIP341, `SinglePlusAnyoneCanPay` only commits to the single input being spent (previous outpoint, amount, script, sequence) and to the *one* output at the same index (output 0, the user's payout). The circuit-lib reimplementation of the sighash algorithm confirms that `sha_outputs` is only produced for sighash types other than `None`/`Single`, and no equivalent commitment exists for any of the other outputs when the type is `Single`: [4](#0-3) 

This means the anchor output (index 1) and, critically, the OP_RETURN output (index 2) carrying the operator's xonly pk are **not signed by anyone** — they can be freely substituted without invalidating the user's signature.

Exploit flow:
1. Operator A calls `withdraw`, builds and broadcasts a payout tx with OP_RETURN = A's xonly pk, using additional funding inputs from A's own wallet, signed input 0 with the extracted `SinglePlusAnyoneCanPay` signature.
2. Attacker observes this unconfirmed transaction in the mempool (or otherwise obtains the witness for input 0), and constructs a new transaction reusing input 0's witness verbatim, the identical output 0 (user's payout, so the signature check on that output still passes), but with an OP_RETURN carrying operator C's xonly pk instead, funded with attacker-controlled fee inputs and a higher fee rate.
3. Attacker broadcasts and gets this variant confirmed first (simple fee-race replacement before first confirmation, explicitly in scope).
4. `Verifier::update_finalized_payouts` parses the confirmed payout tx's OP_RETURN and writes C's xonly pk as `payout_payer_operator_xonly_pk` for that withdrawal, with no check that C actually authorized or funded anything: [5](#0-4) 
5. `PayoutCheckerTask::run_once`, running for operator C, picks up the withdrawal via `get_first_unhandled_payout_by_operator_xonly_pk(C_pk)` (a pure DB filter on the attacker-controlled column), calls `Operator::handle_finalized_payout`, and marks the payout handled for C: [6](#0-5) [7](#0-6) 
6. C proceeds toward kickoff/reimbursement believing it is the legitimate payer, eventually spending a reimbursement UTXO out of the vault for a payout it never funded.
7. Operator A, meanwhile, finds no unhandled payout under its own key (the DB row is now attributed to C), and if A attempts to kick off anyway, `Verifier::is_kickoff_malicious` compares the DB's `operator_xonly_pk` (C) against `kickoff_data.operator_xonly_pk` (A) and flags A's kickoff as malicious: [8](#0-7) 

Existing guards don't catch this: `SECP.verify_schnorr` in `withdraw`/`internal_finalized_payout` only checks the user's signature over input 0/output 0, which the attacker's variant still satisfies unmodified; `is_profitable` and `only_aggregator_and_self` apply only to the legitimate operator's own RPC call, not to an attacker directly broadcasting to Bitcoin; and the ZK bridge circuit (`verify_storage_proofs`, `SPV::verify`, `lc_proof_verifier`) simply trusts whatever `operator_xonlypk` is parsed from the OP_RETURN of the confirmed payout tx as the deposit-constant input — it never re-derives or authenticates that pubkey against a signature.

### Impact Explanation
This is Critical impact per the defined categories: "an operator reimbursed for a payout it never funded" (C) combined with "an honest operator permanently unable to be reimbursed" (A). BTC ultimately leaves the move-to-vault UTXO credited to the wrong operator. The attack is fully repeatable across every withdrawal and every pair of operators — it requires no operator collusion, no verifier compromise, and no privileged access; the attacker only needs to observe/replace an unconfirmed payout transaction and pay a higher fee, both explicitly in-scope attacker capabilities.

### Likelihood Explanation
Preconditions are minimal and realistic: any operator's normal `withdraw` payout tx sits unconfirmed in the mempool for at least one block (standard behavior), during which any network participant can see it, copy the witness for input 0, and rebroadcast a fee-bumped variant with a different OP_RETURN. The attacker cost is only the marginal fee needed to outbid the original transaction — no BTC value at risk beyond fees, since the "funding" input amounts for the user's fixed output are unaffected by the OP_RETURN substitution. This requires no special timing beyond typical mempool replacement dynamics and works against the default configuration of the codebase (no additional configuration/paramset changes needed).

### Recommendation
Cryptographically bind the operator attribution to the payout transaction, e.g. by having the operator sign (or be committed to) the full output set including the OP_RETURN using a sighash type that commits to all outputs (`All` or a custom operator-only ANYONECANPAY signature over the OP_RETURN+anchor), or require the operator's own signature/witness over the additional funding input(s) and verify that the OP_RETURN pubkey matches the wallet that actually supplied the funding inputs before attributing/crediting a payout in the database.

### Proof of Concept
```
cargo test payout_op_return_hijack_attribution
```
Test plan:
1. Set up two registered operators A and C (as in existing `deposit_and_withdraw_e2e` test scaffolding) with a funded deposit and registered withdrawal UTXO.
2. Have operator A call `withdraw`/`InternalWithdraw` to build and broadcast its payout tx (OP_RETURN = A's xonly pk), but do not mine it yet.
3. From a test-only "attacker" context, take the raw payout tx, extract input 0's witness, and construct a variant transaction: same input 0 + witness, same output 0 (user payout), replace OP_RETURN with C's xonly pk, add a distinct funding input/output with a higher fee.
4. Broadcast the attacker's variant and mine it to confirmation depth; assert A's original tx is evicted/never confirms.
5. Run `PayoutCheckerTask::run_once` for operator C: assert it returns `Ok(true)`, `mark_payout_handled` is recorded for C (`db.get_handled_payout_kickoff_txid` returns `Some`), and C proceeds to build `create_reimburse_txhandler`.
6. Run `PayoutCheckerTask::run_once` for operator A: assert it returns `Ok(false)` (no unhandled payout found for A).
7. If A attempts to kick off anyway (e.g. via `internal_finalized_payout`), assert `Verifier::is_kickoff_malicious` returns `true` for A's kickoff, confirming A can never be reimbursed while C is credited/reimbursed for a payout it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
