### Title
Unauthenticated JSON-RPC `send_tx` Allows Any Network Peer to Enqueue Arbitrary CPFP Transactions, Draining the Operator Bitcoin Wallet — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The standalone tx-sender JSON-RPC server exposes `send_tx` with zero authentication. The production configuration explicitly supports binding to `0.0.0.0`. Any network-reachable attacker can call `send_tx` with a crafted transaction carrying a P2A anchor output and `FeePayingType::CPFP`. The tx-sender loop will then call `fund_raw_transaction` + `sign_raw_transaction_with_wallet` + `send_raw_transaction` on the operator's Bitcoin Core wallet to create fee-payer UTXOs for the attacker's transaction, directly draining operator collateral.

---

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds the server with `ServerBuilder::default()` — no authentication middleware, no API key, no mTLS, no IP allowlist of any kind: [1](#0-0) 

The `send_tx` handler accepts caller-controlled `fee_paying_type` (including `CPFP`) and passes it directly to `insert_try_to_send` without any identity check: [2](#0-1) 

The production configuration code in `config.rs` explicitly validates and accepts `0.0.0.0` as a first-class bind address — this is not a test-only path: [3](#0-2) 

When the tx-sender loop processes a queued CPFP entry and no confirmed fee-payer UTXOs exist, `create_fee_payer_utxo` is called. It calls `fund_raw_transaction` (which adds operator wallet inputs), `sign_raw_transaction_with_wallet`, and `send_raw_transaction`, broadcasting a transaction that spends operator wallet UTXOs: [4](#0-3) 

The attacker's transaction only needs to be a syntactically valid Bitcoin transaction with a P2A anchor output (`OP_1 OP_PUSHBYTES_2 0x4e73`). The tx-sender's own test demonstrates that a minimal transaction with no real inputs is accepted by the queue: [5](#0-4) 

---

### Impact Explanation

An attacker who can reach the JSON-RPC port (when bound to `0.0.0.0`) can:

1. Insert an unlimited number of crafted CPFP transactions into `tx_sender_try_to_send_txs`.
2. For each entry, the tx-sender loop calls `fund_raw_transaction` on the operator's Bitcoin Core wallet, adding real wallet UTXOs as fee-payer inputs.
3. The funded, signed fee-payer transactions are broadcast on-chain, permanently spending operator collateral.

Repeated calls drain the operator wallet entirely. The `tx_sender_fee_payer_utxos` table records each spend, but there is no mechanism to recover the funds once broadcast. [6](#0-5) 

---

### Likelihood Explanation

The code explicitly supports `0.0.0.0` as a valid bind address with no authentication option available in the codebase. Any operator deploying the standalone tx-sender with `TX_SENDER_JSONRPC_BIND=0.0.0.0` (e.g., in a containerized or cloud environment where the service must be reachable by other internal components) is immediately exposed. There is no way to add authentication even if the operator wanted to — the code provides no such mechanism. [7](#0-6) 

---

### Recommendation

- Add mandatory authentication to `start_jsonrpc_server` (e.g., a shared secret / bearer token checked in a middleware layer, or mTLS) before the server is usable with any bind address other than `127.0.0.1`.
- Alternatively, remove `0.0.0.0` as a supported bind address and enforce loopback-only operation, requiring callers to use a local Unix socket or SSH tunnel for remote access.
- Add a rate limit and a maximum queue depth per source IP to limit the blast radius even if authentication is bypassed.

### Proof of Concept

Attack steps (no credentials required):

```bash
# Craft a minimal Bitcoin transaction with a P2A anchor output (script: 51024e73)
# Any syntactically valid tx hex with a P2A output works.
RAW_TX_HEX="<hex of tx with P2A anchor output>"

curl -s -X POST http://<operator-ip>:<TX_SENDER_JSONRPC_PORT> \
  -H 'content-type: application/json' \
  --data "{
    \"jsonrpc\": \"2.0\",
    \"id\": 1,
    \"method\": \"send_tx\",
    \"params\": [{
      \"tx_metadata\": null,
      \"signed_tx_hex\": \"${RAW_TX_HEX}\",
      \"fee_paying_type\": \"CPFP\",
      \"rbf_signing_info\": null,
      \"cancel_outpoints\": [],
      \"cancel_txids\": [],
      \"activate_txids\": [],
      \"activate_outpoints\": []
    }]
  }"
```

On the next tx-sender poll cycle, `send_cpfp_tx` is invoked for the queued entry. With no existing fee-payer UTXOs, `create_fee_payer_utxo` calls `fund_raw_transaction` on the operator wallet, signs, and broadcasts — spending real operator BTC. Repeating the call with distinct transaction hex (different txid) creates a new queue entry each time, multiplying the drain. [8](#0-7)

    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };

        tracing::debug!(
            "Creating fee payer UTXO with amount {} ({} sat/kvB)",
            new_fee_payer_amount,
            fee_rate
        );

        let fee_payer_tx = Transaction {
            version: Version::TWO,
            lock_time: LockTime::ZERO,
            input: vec![],
            output: vec![TxOut {
                value: new_fee_payer_amount,
                script_pubkey: self.signer.address().script_pubkey(),
            }],
        };

        let fee_payer_bytes = crate::serialize_tx_for_fund_raw(&fee_payer_tx);

        let funded_fee_payer_tx = self
            .rpc
            .fund_raw_transaction(
                &fee_payer_bytes,
                Some(&FundRawTransactionOptions {
                    add_inputs: Some(true),
                    // for cpfp txs, the speed of tx inclusion is not that important, so we can not use unsafe utxos and wait for them to become safe. Also all cpfp fee payer tx's are safe (all wallet owned inputs), so wallet can already chain them
                    include_unsafe: Some(self.include_unsafe),
                    change_address: None,
                    change_position: None,
                    change_type: None,
                    include_watching: None,
                    lock_unspents: None,
                    fee_rate: Some(Amount::from_sat(fee_rate.to_sat_per_kvb())),
                    subtract_fee_from_outputs: None,
                    replaceable: Some(true),
                    conf_target: None,
                    estimate_mode: None,
                }),
                None,
            )
            .await
            .wrap_err("Failed to fund cpfp fee payer tx")?
            .hex;

        let signed_fee_payer_tx: Transaction = bitcoin::consensus::deserialize(
            &self
                .rpc
                .sign_raw_transaction_with_wallet(&funded_fee_payer_tx, None, None)
                .await
                .wrap_err("Failed to sign funded tx through bitcoin RPC")?
                .hex,
        )
        .wrap_err("Failed to deserialize signed tx")?;

        let outpoint_vout = signed_fee_payer_tx
            .output
            .iter()
            .position(|o| {
                o.value == new_fee_payer_amount
                    && o.script_pubkey == self.signer.address().script_pubkey()
            })
            .ok_or(eyre!("Failed to find outpoint vout"))?;

        self.rpc
            .send_raw_transaction(&signed_fee_payer_tx)
            .await
            .wrap_err("Failed to send signed fee payer tx")?;

        self.db
            .save_fee_payer_tx(
                dbtx,
                bumped_id,
                signed_fee_payer_tx.compute_txid(),
                outpoint_vout as u32,
                new_fee_payer_amount,
                None,
            )
            .await
            .map_to_eyre()?;

        Ok(())
