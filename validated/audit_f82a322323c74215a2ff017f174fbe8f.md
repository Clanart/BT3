## Finding

### Title
Unverified `WWW-Authenticate: realm="GitHub"` header spoofing forces an unsolicited GitHub Enterprise sign-in flow scoped to an attacker-controlled origin - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` classifies a git remote as an `'enterprise'` GitHub host purely by substring-matching a `WWW-Authenticate` header value that the remote HTTP server supplies, with no cryptographic or network verification. This lets any HTTP(S) remote a user fetches/clones from claim to be a GitHub Enterprise instance and get Desktop to automatically launch its native "Sign in to GitHub Enterprise" popup pre-scoped to that attacker's own origin — bypassing the legitimate fallback check (`isGitHubHost`) that would otherwise make a real API request to verify the host.

### Finding Description
When git performs an HTTP(S) fetch/clone and receives a `401` with a `WWW-Authenticate` header, git forwards it to the credential helper as a `wwwauth[N]=<header value>` field. `getEndpointKind` trusts this attacker-supplied string outright: [1](#0-0) 

If the header contains `realm="GitHub"`, the endpoint is unconditionally classified as `'enterprise'` — skipping the safer fallback path a few lines below that would actually query the host's real API to confirm it's GitHub (`isGitHubHost(endpoint)`): [2](#0-1) 

This classification feeds directly into `getCredential()`. For the `REQUIRED_STATE` in the question (no existing stored account for that endpoint), Desktop calls `ui.promptForGitHubSignIn(endpoint)` for *any* endpoint classified as non-`'generic'`: [3](#0-2) 

`promptForGitHubSignIn` then programmatically drives the sign-in store directly to the `Authentication` step for the attacker's origin — bypassing the normal `EndpointEntry` step where a user would manually type/confirm a server URL: [4](#0-3) 

The resulting popup lets the user click "Sign in using your browser," which opens `shell.openExternal(getOAuthAuthorizationURL(endpoint, csrfToken))` — an authorize URL built from the attacker-controlled `endpoint`: [5](#0-4) 

On completion, `resolveOAuthRequest` exchanges the code and fetches the "user" directly against the attacker's endpoint, and the resulting `Account` is what gets bound/stored by Desktop as a legitimate enterprise account for that host: [6](#0-5) 

The wrong value here is that `getEndpointKind` treats a fully attacker-controlled HTTP response header as sufficient proof of GitHub Enterprise identity, instead of requiring the network-verified check (`isGitHubHost`) that exists later in the same function for exactly this purpose.

### Impact Explanation
This meets the "unauthorized OAuth or account binding" impact category: a malicious remote (any plain HTTP(S) server, not necessarily a real GitHub Enterprise deployment) can force Desktop's native, first-party-looking "Sign in to GitHub Enterprise" UI to appear, scoped to the attacker's own server, without the user ever typing that URL. This is a stronger phishing primitive than an ordinary generic-git-credential prompt because:
- It uses Desktop's dedicated GitHub sign-in chrome (branding/trust cues distinct from the generic "enter username/password" dialog used for non-GitHub remotes), increasing the chance a user completes it believing they are authenticating to a genuine enterprise instance related to the repository.
- It bypasses `isGitHubHost`, the one check designed to confirm the remote is actually speaking the GitHub API before treating it as an enterprise endpoint.

The direct consequence is bound to the attacker's own endpoint (an account record pointing at their own server), so it does not directly exfiltrate a *different, real* GitHub credential by itself; the primary risk is UI/consent bypass and social-engineering amplification via a native, unsolicited GitHub-branded sign-in flow that a purely malicious git remote can trigger.

### Likelihood Explanation
Any attacker who controls the Git remote a victim clones/fetches from (a common, low-privilege attacker capability in this program's scope) can trivially return a crafted `WWW-Authenticate: Basic realm="GitHub"` header on a `401` response — this requires no special server software, just a hand-crafted HTTP response. No existing account for that endpoint is a very common state (any first-time clone from a new host).

### Recommendation
Do not trust the `WWW-Authenticate` realm value as sufficient evidence of a GitHub Enterprise host. At minimum, require it to be corroborated by an actual network check (the existing `isGitHubHost(endpoint)` call), or drop the header-based fast path entirely and always perform the verified API check before classifying an unknown endpoint as `'enterprise'`.

### Proof of Concept
1. Serve a git-over-HTTP(S) remote (e.g., `https://evil.example`) with a repo that a target user is invited/linked to clone.
2. Configure the server to respond to the Git HTTP auth request with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. User runs `git clone https://evil.example/foo.git` (or Desktop performs a fetch) with no existing account stored for `evil.example`.
4. Desktop's credential helper (`getCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`) classifies the endpoint as `'enterprise'` solely from the header.
5. Desktop calls `ui.promptForGitHubSignIn('https://evil.example/...')`, which opens the native "Sign in to GitHub Enterprise" dialog pre-bound to `evil.example`, with no prior manual entry step required from the user. [7](#0-6)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })

  public async resolveOAuthRequest(action: IOAuthAction) {
    if (!this.state || this.state.kind !== SignInStep.Authentication) {
      return
    }

    if (!this.state.oauthState) {
      return
    }

    if (this.state.oauthState.state !== action.state) {
      log.warn(
        'requestAuthenticatedUser was not called with valid OAuth state. This is likely due to a browser reloading the callback URL. Contact GitHub Support if you believe this is an error'
      )
      return
    }

    const { endpoint } = this.state
    const token = await requestOAuthToken(endpoint, action.code)

    if (token) {
      const account = await fetchUser(endpoint, token)
      this.state.oauthState.onAuthCompleted(account)
    } else {
      this.state.oauthState.onAuthError(
        new Error('Failed retrieving authenticated user')
      )
    }
  }
