### Title
DataLayer `add_missing_files` RPC accepts an unsanitized, attacker-supplied output directory, enabling arbitrary file write - (File: chia/data_layer/data_layer_rpc_api.py)

### Summary
The `add_missing_files` DataLayer RPC endpoint reads a raw `foldername` string directly out of the request body and turns it into a `Path` with no validation, canonicalization, or containment check against the intended `server_files_location`. That path is then used as the destination directory for writing DataLayer full-tree/delta-tree files. This mirrors the CVE-2020-15236 bug class: a user-supplied path is handed to filesystem write logic without being restricted to the expected storage root, letting the caller redirect writes (and, with `overwrite=True`, overwrite) to arbitrary filesystem locations.

### Finding Description
`DataLayerRpcApi.add_missing_files()` takes `request["foldername"]` verbatim: [1](#0-0) 

This `foldername` is passed straight into `DataLayer.add_missing_files()`, which uses it in place of the normally-computed, network-scoped `self.server_files_location`: [2](#0-1) 

That directory is then combined with deterministic, protocol-derived filenames via `get_full_tree_filename_path`/`get_delta_filename_path` (`foldername.joinpath(...)`) and opened directly for writing in `write_files_for_root()`: [3](#0-2) 

Note the write mode: `mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"` — when the caller sets `overwrite=True` (also an unchecked request field, `data_layer_rpc_api.py:411`), the destination file is opened in truncate/overwrite mode (`"wb"`), not exclusive-create.

Unlike the HTTP static file server (`chia/data_layer/data_layer_server.py`) and the S3 plugin (`chia/data_layer/s3_plugin_service.py`), which validate requested filenames with `is_filename_valid()` before joining them to a fixed `server_dir`, this RPC path performs no equivalent validation on the *directory* component at all — `foldername` can be any absolute path (e.g. `/etc`, a service config directory, another user's home directory, a certs directory) supplied by whoever can reach the DataLayer RPC.

### Impact Explanation
Because the destination directory is fully attacker-controlled and unconstrained, and `overwrite=True` opens target files in truncate mode, a DataLayer RPC caller can direct the DataLayer service to write/overwrite files at file-system paths outside the intended `server_files_location` sandbox. This is the same root cause pattern as the Wiki.js CVE: a path supplied by an untrusted/lower-trust caller is not sanitized before being used for local file writes by a storage/caching subsystem, enabling out-of-scope file writes (here — file overwrite rather than disclosure, since DataLayer writes rather than reads on this path). Depending on operator configuration and where the daemon has write permissions, this could be used to corrupt or replace files it shouldn't touch, including other service data under the same OS user.

### Likelihood Explanation
Likelihood is bounded by RPC access control: `add_missing_files` is served through the DataLayer RPC service, which requires the standard local/keyed RPC authorization used by other Chia RPC endpoints. Any caller with access to that RPC endpoint (e.g. an operator-issued RPC key holder, or a compromised local client that gained access to the DataLayer RPC certs) can trigger this immediately with two JSON fields (`foldername`, `overwrite`) — no additional preconditions, cryptographic material, or race conditions are required.

### Recommendation
Validate and canonicalize the `foldername` request parameter in `DataLayerRpcApi.add_missing_files()`: resolve it and confirm it is contained within an allow-listed base directory (or reject absolute/`..`-containing paths outright), mirroring the strict filename validation (`is_filename_valid()`) already applied on the HTTP/S3 file-serving code paths. Alternatively, remove the ability to override `server_files_location` from the RPC surface entirely and only allow it via trusted local config/CLI-only flows that are not exposed over RPC to less-trusted callers.

### Proof of Concept
1. Start `chia data_layer` with an owned store and confirmed generations so `add_missing_files` has data to write.
2. Call the DataLayer RPC `add_missing_files` with:
```json
{
  "ids": ["<owned_store_id_hex>"],
  "overwrite": true,
  "foldername": "/absolute/attacker/chosen/path"
}
```
3. Observe that `DataLayer.add_missing_files()` calls `write_files_for_root(..., server_files_location=<attacker path>, overwrite=True, ...)` (`chia/data_layer/data_layer.py:854-866`), which opens deterministic-named full/delta tree files under `/absolute/attacker/chosen/path` in `"wb"` mode (`chia/data_layer/download_data.py:83-98`), writing/overwriting files there regardless of the service's configured `server_files_location`.
