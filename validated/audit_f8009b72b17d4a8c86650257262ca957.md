### Title
Untrusted `ReceivedOutput` bytes allow fabricating arbitrary input value ("minting" unbacked funds) - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes a scalar `offset`, a full `TxOut` (including its `value` field), and an `OutPoint` entirely from attacker-controlled bytes, with no binding to any on-chain output. Downstream, `SignableTransaction::new` sums `input.output.value.to_sat()` as the available input balance (`input_sat`). Feeding crafted bytes to `ReceivedOutput::read` therefore mints a phantom input claiming arbitrary value — an unbounded, discretionary "issuance" of spendable-looking balance analogous to unconstrained minting in the reference report.

### Finding Description
In `networks/bitcoin/src/wallet/mod.rs` (lines 120–134):

```rust
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  let output;
  let outpoint;
  {
    let mut buf_r = BufReader::with_capacity(0, r);
    output = TxOut::consensus_decode(&mut buf_r)...;
    outpoint = OutPoint::consensus_decode(&mut buf_r)...;
  }
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

Every field — including `output.value` — is taken verbatim from the input stream. There is no check that `outpoint` references a real UTXO nor that `value` matches the chain's recorded amount. `Scanner::scan_transaction` (lines 199–214) produces honest `ReceivedOutput`s, but nothing enforces that a `ReceivedOutput` came from the scanner.

`SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs` then computes:

- `let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();` (line 175)
- `if input_sat < (payment_sat + needed_fee) { Err(NotEnoughFunds) }` (line 215)
- `self.prevouts` is populated from `input.output` (line 253) and `fee()` reports `sum(prevouts) - sum(outputs)` (lines 137–141).

So a forged `ReceivedOutput` with `value = u64::MAX` (or any inflated amount) is counted as real input funds, satisfies `NotEnoughFunds` checks, inflates the reported balance (`Output::balance` in `processor/src/networks/bitcoin.rs:128–130` returns `self.output.value()` directly), and causes `change` to be computed against nonexistent sats. The processor's `Output::read` (lines 145–166) calls `ReceivedOutput::read` on the same stream, so the forgery propagates through the full output pipeline.

### Impact Explanation
The deserialization path lets an unprivileged party who can feed bytes into `ReceivedOutput::read` (or `Output::read`, which embeds it) conjure inputs claiming arbitrary value. Concretely:

- **Funds reported received that are not spendable**: `Output::balance` and `ReceivedOutput::value` report the attacker-claimed amount, inflating the tracked Bitcoin balance with unbacked "minted" sats.
- **Inconsistent accounting**: `SignableTransaction::fee()` computes `sum(prevouts) - sum(outputs)` from fabricated prevouts, so fee/change bookkeeping (`input_sat - payment_sat - fee_with_change`, send.rs line 228) operates on phantom funds, producing change outputs that look funded but are not.

If the fabricated output is ever signed, the Taproot sighash commits the claimed amount (`Prevouts::All`), so the resulting transaction is consensus-invalid — but the damage to balance reporting, fee accounting, and any code path that trusts `ReceivedOutput` values occurs before and independent of broadcast.

### Likelihood Explanation
Reachability requires untrusted bytes reaching `ReceivedOutput::read`/`Output::read`, which the in-scope rules explicitly enumerate as an attack surface. The processor's `Output::read` wrapper (bitcoin.rs:145–166) makes this reachable wherever serialized `Output`s cross a trust boundary (DB entries, coordinator messages, or resync data). No cryptographic break is needed — the bug is the unconditional trust in deserialized `TxOut.value`.

### Recommendation
Bind `ReceivedOutput` to verified chain data: either (a) make `ReceivedOutput` constructible only via `Scanner` (seal the constructor / remove or gate `read` behind re-validation against the UTXO set or the source transaction), or (b) after `read`, require callers to re-verify `outpoint`/`value`/`script_pubkey` against a trusted source before using `input_sat`, `balance()`, or `fee()`. At minimum, document that `ReceivedOutput::read` produces an unverified claim and must not be used for accounting without external verification.

### Proof of Concept
```rust
use bitcoin_serai::{bitcoin::{consensus::Encodable, OutPoint, TxOut, Amount, Txid, hashes::Hash}, wallet::{ReceivedOutput, SignableTransaction}};
use k256::Scalar;

// Craft bytes: offset || TxOut(value = u64::MAX-ish, our script) || fake outpoint
let mut bytes = Scalar::ZERO.to_bytes().to_vec();
let fake = TxOut { value: Amount::from_sat(21_000_000 * 100_000_000), script_pubkey: our_p2tr.clone() };
fake.consensus_encode(&mut bytes).unwrap();
OutPoint::new(Txid::all_zeros(), 0).consensus_encode(&mut bytes).unwrap();

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 21_000_000 * 100_000_000); // "minted" balance

// Passes NotEnoughFunds and reports a huge fee/change against nonexistent sats
let tx = SignableTransaction::new(vec![forged], &[(dest, 1000)], Some(change), None, 20).unwrap();
```
