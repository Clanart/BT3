### Title
Dust outputs are reported as received and spendable because `Scanner::scan_transaction` matches on script_pubkey only — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` accepts any transaction output whose `script_pubkey` matches a registered script, without checking the output's value. An unprivileged third party can send a dust output to a Serai-controlled address; the scanner reports it as a `ReceivedOutput`, and downstream wallet code treats it as a spendable input even though spending it costs more in fees than its value (or is consensus/relay-impossible below the dust threshold).

### Finding Description
`scan_transaction` iterates `tx.output` and pushes a `ReceivedOutput` whenever `self.scripts.get(&output.script_pubkey)` matches:

```rust
// networks/bitcoin/src/wallet/mod.rs:199-213
pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for (vout, output) in tx.output.iter().enumerate() {
    let Ok(vout) = u32::try_from(vout) else { break };
    if let Some(offset) = self.scripts.get(&output.script_pubkey) {
      res.push(ReceivedOutput {
        offset: *offset,
        output: output.clone(),
        outpoint: OutPoint::new(tx.compute_txid(), vout),
      });
    }
  }
  res
}
```

The only acceptance criterion is script membership — a blocklist-style "reject nothing, match anything that hits the table" filter with no semantic validity check on the output itself. `ReceivedOutput::value()` simply returns `self.output.value.to_sat()` and `ReceivedOutput::read`/`write` round-trip the same unchecked value, so the poisoned output is indistinguishable from a legitimate deposit.

This mirrors the advisory's bug class: a check that enumerates what to *reject* (or here, a single shallow property to *accept*) rather than enforcing the full set of invariants required for the object to be usable. Just as the Ibexa validator only rejected `javascript:`/`vbscript:` and let `data:` and case variants through, the scanner only requires a script match and lets economically-invalid outputs through.

### Impact Explanation
An attacker sends a transaction paying a dust amount (e.g., 1–546 sats, below the `DUST` constant referenced in `processor/src/networks/bitcoin.rs:638` and `networks/bitcoin/src/wallet/send.rs`) to Serai's P2TR external address. `scan_block`/`scan_transaction` returns it as a `ReceivedOutput`, and the wallet reports funds as received that are not spendable: the fee required to spend the input (~230 weight units per input) exceeds its value, and for sub-dust values the spend may be non-standard outright. If `SignableTransaction::new` later selects it as an input, the fee accounting in `needed_fee`/`change` math is polluted by an input whose inclusion is strictly loss-making. This is a reachable "funds reported received that are not spendable" outcome driven purely by a third-party Bitcoin transaction — exactly the allowed reachability model.

### Likelihood Explanation
Any unprivileged party who can send a Bitcoin transaction to a public Serai deposit address triggers this — no validator role, no collusion, no leaked material. The deposit address is public by design. Cost to the attacker is a dust output and one transaction fee. Caveat: whether downstream processor code (`processor/src/networks/bitcoin.rs::get_outputs`, out of the in-scope crates) applies its own value filter could not be fully verified; the in-scope wallet crate itself performs no filtering.

### Recommendation
Apply allowlist-style validation in `scan_transaction` / `ReceivedOutput` construction: only yield outputs whose `value` is at or above `wallet::DUST` (and ideally above the estimated spend cost), or expose the check so callers must filter before treating outputs as spendable. Alternatively, have `SignableTransaction::new` reject inputs below the dust/spend-cost threshold so unspendable outputs cannot enter fee math even if scanned.

### Proof of Concept
```rust
// Any third party broadcasts a tx with:
//   TxOut { value: 100 sats, script_pubkey: <serai p2tr script> }
let tx = /* attacker's transaction, one dust output to serai_addr */;
```
