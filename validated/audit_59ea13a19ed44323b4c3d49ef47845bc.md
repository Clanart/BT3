### Title
Reward sniping via same-block stake/claim/withdraw in `BaseRewardPool._provisionReward` lump-sum accounting - (File: rewards/BaseRewardPool.sol)

### Summary
`_provisionReward` distributes a newly queued reward instantly across `totalStaked()` at the moment the transaction executes, with no vesting period, minimum stake duration, or withdrawal cooldown anywhere in `BaseRewardPool` or `MasterMagpie`. An attacker who deposits into `MasterMagpie` immediately before a `queueNewRewards`/`donateRewards` call lands, then claims and withdraws immediately after, captures a reward share proportional to their capital for zero economic duration, diluting the yield legitimately earned by long-term stakers.

### Finding Description
`_provisionReward` (rewards/BaseRewardPool.sol:297-320) computes:
```
rewardInfo.rewardPerTokenStored += (_amountReward * 10**stakingDecimals()) / this.totalStaked();
```
using the instantaneous `totalStaked()` (`IERC20(stakingToken).balanceOf(operator)`, see `totalStaked()` at line 126-128) — a single lump-sum bump rather than a time-weighted streaming rate (unlike Synthetix-style `rewardRate * duration` accrual). `balanceOf(_account)` (line 133-136) reads the user's current staked amount directly from `MasterMagpie.userInfo`, with no snapshot, checkpoint, or time-weighting either [1](#0-0) .

Attack flow:
1. Attacker observes a pending `queueNewRewards`/`donateRewards` transaction from a manager (or public `donateRewards` caller) in the mempool.
2. Attacker calls `MasterMagpie.deposit()` → `_deposit()` (rewards/MasterMagpie.sol:482-505), which increases `user.amount`/`user.available` and transfers `stakingToken` into `MasterMagpie`, with a higher gas price to land first.
3. `queueNewRewards`/`donateRewards` executes, calling `_provisionReward`, which bumps `rewardPerTokenStored` using the now-inflated `totalStaked()` that includes the attacker's large deposit.
4. Attacker immediately calls `withdraw()` → `_withdraw()` → `_harvestAndUnstake()` (rewards/MasterMagpie.sol:508-534), which calls `_harvestMGP` and `_harvestBaseRewarder` (ultimately `BaseRewardPool.getReward`, updateReward modifier at line 88-91/225) to compute `earned()` using the just-updated `rewardPerTokenStored`, paying out the attacker's proportional share, then withdraws principal.

No modifier, timelock, deposit/withdraw fee, or minimum holding period exists in `_deposit`/`_withdraw`/`_harvestAndUnstake` in `MasterMagpie.sol` or in `BaseRewardPool`'s `updateReward`/`getReward` to prevent this; `nonReentrant`/`whenNotPaused` guards only prevent reentrancy/pausing, not time-based sniping [2](#0-1) . The same pattern is repeated identically in `BaseRewardPoolV2._provisionReward`, `mWOMSVBaseRewarder._provisionReward`, and `vlMGPBaseRewarder.queueNewRewards` [3](#0-2) [4](#0-3) [5](#0-4) .

### Impact Explanation
This is a theft of unclaimed yield from long-term stakers: a large, momentary deposit dilutes the per-token reward denominator and lets the attacker extract a disproportionate share of `_amountReward` funded by the reward manager/protocol treasury for a stake duration of effectively zero blocks, while permanently reducing the amount available to legitimate long-duration stakers. This matches the Immunefi impact class "theft of unclaimed yield" / "direct theft of user funds."

### Likelihood Explanation
Feasibility depends entirely on the attacker's ability to sequence transactions around a `queueNewRewards`/`donateRewards` call within a very short window (ideally the same block/bundle). `queueNewRewards` is `onlyManager`-gated, so the attacker cannot trigger it themselves, but must front-run a manager's pending transaction, which is visible in the public mempool on most EVM chains. `donateRewards` is unrestricted and could even be called by a colluding/careless third party without malicious intent, making the attack triggerable by any donation event. Capital requirement is proportional to the size of a flash-loanable/available stakingToken position; no flash-loan protection or balance snapshotting exists, and the technique is fully repeatable for every future reward injection.

### Recommendation
Replace the instant/lump-sum reward-per-token bump with time-weighted, streaming distribution (rate-based accrual over a duration, as in the standard Synthetix `StakingRewards` pattern), and/or introduce a minimum stake duration / checkpointed balances (e.g., snapshot balances used for reward calculation at the block prior to `_provisionReward`, or a cooldown between deposit and reward-eligible withdrawal) so momentary balance inflation cannot capture disproportionate reward share.

### Proof of Concept
Hardhat test plan:
1. Deploy `MasterMagpie`, `BaseRewardPool` (or `BaseRewardPoolV2`), stakingToken (mock ERC20), rewardToken (mock ERC20); register manager.
2. Have "honest" staker deposit `X` stakingToken and hold for several blocks (simulate long-term stake) before any reward is queued.
3. In a single block (using `hre.network.provider.send("evm_setAutomine", [false])` to batch or via a multicall/bundle):
   - attacker calls `MasterMagpie.deposit(stakingToken, LARGE_AMOUNT)`
   - manager calls `queueNewRewards(rewardAmount, rewardToken)`
   - attacker calls `MasterMagpie.withdraw(stakingToken, LARGE_AMOUNT)` (internally harvesting reward first)
4. Mine the block; assert attacker received `earned(attacker, rewardToken) > 0` despite holding stake for 0 blocks/seconds, while honest staker's `earned()` per token-second is far lower.
5. Compute reward/(balance*duration) ratio for both parties; assert attacker's ratio is orders of magnitude higher, confirming disproportionate extraction with zero economic exposure duration.

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
