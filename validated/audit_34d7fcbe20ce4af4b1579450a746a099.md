### Title
Bundle incorporation failure in block building silently drops all pending transactions instead of only the offending bundle - ([File: work/builder/builder.go])

### Summary
The reported Aave issue is about an external dependency (paused LendingPool) causing an unhandled revert in `deposit`/`withdraw`, with no graceful fallback. The analogous root cause in kaia is in `work/builder.ExtractBundlesAndIncorporate`, which calls `IncorporateBundleTx` to insert `TxBundlingModule` (Gasless/Auction) bundles into the transaction list during block building. If `IncorporateBundleTx` fails, the function does not gracefully skip only the failing bundle — it returns an essentially-empty transaction list, causing the block builder to drop **all** pending transactions for that assembly attempt.

### Finding Description
`ExtractBundlesAndIncorporate` builds `flattenedTxs` only in the `txBundlingModules == nil` branch; in the normal path (with bundling modules registered, e.g. gasless and auction) `flattenedTxs` remains an empty, unpopulated slice: [1](#0-0) 

```go
func ExtractBundlesAndIncorporate(arrayTxs []*types.Transaction, txBundlingModules []TxBundlingModule) ([]*TxOrGen, []*Bundle) {
	bundles := []*Bundle{}
	flattenedTxs := []*TxOrGen{}
	if txBundlingModules == nil {
		for _, tx := range arrayTxs {
			flattenedTxs = append(flattenedTxs, NewTxOrGenFromTx(tx))
		}
		return flattenedTxs, nil
	}
	...
	incorporatedTxs, err := IncorporateBundleTx(arrayTxs, bundles)
	if err != nil {
		return flattenedTxs, nil   // <-- returns the still-empty slice, not arrayTxs
	}
	return incorporatedTxs, bundles
}

`IncorporateBundleTx` returns an error whenever `incorporate()` cannot find a bundle's `TargetTxHash` in the current transaction list: [2](#0-1) 

This can be triggered by a bundling module (e.g. the Gasless module) producing a bundle whose `TargetTxHash` no longer matches the current arrangement of `arrayTxs` (for example due to reordering/removal of the target tx between calls, or any edge case in `ExtractTxBundles`/`coordinateTargetTxHash` that yields an inconsistent target). Because `arrayTxs` passed into `IncorporateBundleTx` is the full pending-transaction list at that point in block assembly: [3](#0-2) 

any single malformed/unlucky bundle failing to incorporate wipes out the entire batch of transactions being assembled into the block, not just the transactions belonging to the offending bundle.

The Gasless and Auction modules are exactly the reachable, permissionless entry points that can produce such bundles from ordinary submitted transactions — an unprivileged user submitting a `GaslessApproveTx`/`GaslessSwapTx` pair (or an auction bid) is enough to create a bundle that flows through this code path during block building: [4](#0-3) 

### Impact Explanation
This is analogous to the reported bug class: an unhandled failure/edge-case in a dependent flow (here, bundle incorporation) causes complete denial-of-service instead of a bounded, isolated failure. Rather than the deposit/withdraw functions reverting due to an external pause, here a single malformed bundle causes the block-building routine to discard the entire transaction set for that build attempt, denying block inclusion to all other unrelated, valid, fee-paying transactions in that round. This is a chain/proposer-level denial-of-service vector reachable by a single crafted transaction (or transaction sequence) from an unprivileged sender, which is Medium severity per the same bug class as the source report (unhandled external failure → broad service disruption).

### Likelihood Explanation
Reachable directly via `worker.go`'s call to `ExtractBundlesAndIncorporate` (verified caller) during normal block-building, whenever any registered `TxBundlingModule` (gasless, auction) is active and produces a bundle whose target/tx set becomes inconsistent with the current `arrayTxs` ordering at incorporation time. Because bundle target hashes are computed based on transaction ordering that can shift between extraction and incorporation (reordering, other bundles' insertion, tx removal), triggering the `ErrFailedToIncorporateBundle` path is plausible under adversarial transaction submission patterns, though I could not fully verify from the available index whether `coordinateTargetTxHash` and the worker's usage guarantee target-hash consistency in all cases — this warrants further live investigation to confirm exact preconditions.

### Recommendation
On `IncorporateBundleTx` failure, drop/skip only the offending bundle (and its associated bundle transactions) rather than discarding the whole `arrayTxs`. At minimum, `ExtractBundlesAndIncorporate` should fall back to returning `NewTxOrGenFromTx`-flattened `arrayTxs` (as done in the `txBundlingModules == nil` branch) instead of the empty `flattenedTxs`, and ideally should retry incorporation with the failing bundle excluded so unrelated pending transactions are still included in the block.

### Proof of Concept
Not independently reproduced in this session — this analysis is based on static code review of `work/builder/builder.go` (`ExtractBundlesAndIncorporate`, `IncorporateBundleTx`, `incorporate`) and `kaiax/gasless/impl/builder.go` (`ExtractTxBundles`). A concrete PoC would require constructing a sequence of pending transactions (e.g., interleaved Gasless approve/swap pairs and ordinary transactions, or reordering across `PopTxs`/multiple builder invocations) that causes a bundle's `TargetTxHash` to no longer be found in `arrayTxs` at `IncorporateBundleTx` time, then confirming that the resulting block-building call in `work/worker.go` receives an empty transaction set instead of the original pending set. This should be validated via a live Devin session with test/debug tooling against `work/worker.go`'s block-building flow.

// IncorporateBundleTx incorporates bundle transactions into the transaction list.
// Caller must ensure that there is no conflict between bundles.
func IncorporateBundleTx(txs []*types.Transaction, bundles []*Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, len(txs))
	for i, tx := range txs {
		ret[i] = NewTxOrGenFromTx(tx)
	}

	for _, bundle := range bundles {
		var err error
		ret, err = incorporate(ret, bundle)
		if err != nil {
			return nil, err
		}
	}
	return ret, nil
}

// incorporate assumes that `txs` does not contain any bundle transactions.
func incorporate(txs []*TxOrGen, bundle *Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, 0, len(txs)+len(bundle.BundleTxs))
	targetFound := false

	// 1. place bundle at the beginning
	if bundle.TargetTxHash == (common.Hash{}) {
		ret = append(ret, bundle.BundleTxs...)
		targetFound = true
	}

	// 2. place bundle after TargetTxHash
	for _, txOrGen := range txs {
		// if tx-in-bundle, the tx will be appended when target is found.
		if bundle.Has(txOrGen) {
			continue
		}
		ret = append(ret, txOrGen)
		if txOrGen.Id == bundle.TargetTxHash {
			targetFound = true
			ret = append(ret, bundle.BundleTxs...)
		}
	}

	if !targetFound {
		return nil, ErrFailedToIncorporateBundle
	}

	return ret, nil
}

func ExtractBundlesAndIncorporate(arrayTxs []*types.Transaction, txBundlingModules []TxBundlingModule) ([]*TxOrGen, []*Bundle) {
	// Detect bundles and add them to bundles
	bundles := []*Bundle{}
	flattenedTxs := []*TxOrGen{}
	if txBundlingModules == nil {
		for _, tx := range arrayTxs {
			flattenedTxs = append(flattenedTxs, NewTxOrGenFromTx(tx))
		}
		return flattenedTxs, nil
	}

	for _, txBundlingModule := range txBundlingModules {
		newBundles := txBundlingModule.ExtractTxBundles(arrayTxs, bundles)
		for _, newBundle := range newBundles {
			isConflict := false
			// Check for conflicts with all previous bundles
			for _, prevBundle := range bundles {
				isConflict = prevBundle.IsConflict(newBundle)
				if isConflict {
					break
				}
			}
			// Not allowing empty bundles
			if !isConflict && len(newBundle.BundleTxs) > 0 {
				bundles = append(bundles, newBundle)
			}
		}
	}

	// Coordinate target tx hash of bundles. It assumes the Gasless and Auction modules only currently.
	// This reordering does not break the execution result.
	// For example, if bundle reordering breaks the nonce ordering, the execution result will be different.
	bundles = coordinateTargetTxHash(bundles)

	incorporatedTxs, err := IncorporateBundleTx(arrayTxs, bundles)
	if err != nil {
		return flattenedTxs, nil
	}

	return incorporatedTxs, bundles
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
