## Confirmed local analog

This is a genuine, locally-provable analog to the 1inch "unvalidated `msg.value`" bug: `EvmHost.dispatch(DispatchPost)`, `EvmHost.dispatch(DispatchGet)`, and `EvmHost.fundRequest()` never validate that `msg.value` matches the amount actually required for the fee-token swap, and never refund any surplus to the caller.

### Title
Overpaid native `msg.value` in `EvmHost.dispatch`/`fundRequest` is silently absorbed by the host instead of refunded to the caller - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()` all follow the same pattern: if `msg.value > 0`, they call `IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)`. [1](#0-0) [2](#0-1) [3](#0-2) 

Uniswap's `swapETHForExactTokens` only consumes the ETH needed to buy the exact output amount and refunds any unspent ETH to `msg.sender` **of that call** — which is `EvmHost` itself, not the original external caller. `EvmHost` never forwards that refund back out. As a result, any overpayment of native token by a caller of `dispatch`/`fundRequest` is permanently absorbed into the host contract's own balance instead of being returned.

### Finding Description
The codebase demonstrates the correct pattern elsewhere: `IntentGatewayV2.placeOrder` explicitly tracks `msgValue`, performs the swap itself (so any router refund lands on the gateway, which it controls), and then refunds any leftover native token to `msg.sender` at the end of the function. [4](#0-3) 

`EvmHost.dispatch`/`fundRequest`, by contrast, hand the *entire* `msg.value` to the router and never compute or refund a remainder — there is no `msgValue -= amounts[0]` bookkeeping and no `.call{value: ...}("")` back to `_msgSender()` afterward. [5](#0-4) 

This exact belief — that the router "refunds" excess ETH to the *payer* — is baked into other integrations. `HyperbridgeLzEndpoint.send()` forwards `msg.value` directly to `IDispatcher(_host).dispatch{value: msg.value}(request)`, and its `quote()` function deliberately applies a "generous 2x buffer" with the comment that "Excess native is refunded by the uniswap router," i.e., developers assumed the caller gets their surplus back. [6](#0-5) [7](#0-6) 

But because the swap is executed inside `EvmHost` (the router sees `EvmHost` as `msg.sender`), the "refund" actually lands in `EvmHost`'s own balance, not back at the OApp/user who sent the 2x-buffered `msg.value` through `HyperbridgeLzEndpoint`. Since `send()` deliberately over-quotes by 2x to be safe, this guarantees systematic native-token loss on every dispatch that pays with native token, for any caller of `dispatch`/`fundRequest` (directly or via `HyperbridgeLzEndpoint`/any other `IApp` that forwards `msg.value`).

The only way this stuck ETH can move is via `EvmHost.withdraw()`, which is restricted to `_hostParams.hostManager` (cross-chain governance) and sends funds to an arbitrary `beneficiary`, not back to the original overpaying caller. [8](#0-7) 

### Impact Explanation
Users/integrating contracts (e.g., `HyperbridgeLzEndpoint`, or any `IApp`/EOA calling `dispatch`/`fundRequest` directly with native token) lose any ETH sent in excess of the exact swap cost — this is direct, unrecoverable loss of user funds trapped in the host contract, matching the bounty's "stealing or loss of funds" category. Given `quote()` intentionally pads by 2x, this is not an edge case but the expected normal-usage path for LZ-endpoint-routed dispatches.

### Likelihood Explanation
High. `dispatch(DispatchPost)`/`dispatch(DispatchGet)`/`fundRequest()` are all public, unprivileged, `payable` entry points reachable by any EOA or contract, requiring no malicious peer, relayer, or admin. The `HyperbridgeLzEndpoint` code path guarantees overpayment (2x buffer) on every native-fee dispatch, and any app author using the "native token" fee-payment mode documented in `IDispatcher` faces the same risk whenever price movement/slippage estimation causes them to send `msg.value` above the exact required fee amount.

### Recommendation
In `EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()`, mirror the pattern already used in `IntentGatewayV2.placeOrder`: capture the actual amount spent by the swap (`swapETHForExactTokens` returns `amounts[0]`), and refund `msg.value - amounts[0]` back to `_msgSender()` via a low-level call, reverting on failure. Alternatively, require `msg.value == amounts[0]` (post-swap) or provide a `refundAddress`/`payer`-based refund similar to `WithdrawParams`, ensuring surplus native token never remains trapped in the host contract's general balance.

### Proof of Concept
1. Deploy `EvmHost` with a configured `uniswapV2` router and `feeToken`.
2. An app (e.g., a `HyperFungibleToken.send()` caller or a direct EOA) calls `EvmHost.dispatch{value: 1 ether}(post)` where `post.fee` requires only `0.1 ether` worth of ETH to acquire via `swapETHForExactTokens`.
3. Internally: `swapETHForExactTokens{value: 1 ether}(post.fee, path, address(this), ...)` spends only the ETH needed (e.g. 0.1 ether) and refunds the remaining ~0.9 ether — but to `msg.sender` of the swap call, i.e. `EvmHost`, not to the original caller.
4. `EvmHost.dispatch` returns without touching the leftover ~0.9 ether; it sits in `EvmHost`'s balance.
5. The original caller has permanently lost ~0.9 ether with no path to reclaim it, except via privileged `EvmHost.withdraw()` sending it to a governance-chosen beneficiary — not the original payer. [1](#0-0)

    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});

            source: string(request.source),

            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
