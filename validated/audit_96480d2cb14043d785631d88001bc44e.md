### Title
Untrusted serialized threshold keys trigger quadratic Lagrange interpolation DoS - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` accepts an attacker-controlled participant count `n` and interpolation selector before validating threshold parameters. When supplied `t = n = 65535` and Lagrange interpolation, `ThresholdKeys::new` computes an interpolation factor for every participant, while each factor iterates over all included participants. This creates approximately `65535²` field operations, over 4.2 billion iterations, from a serialized object of only a few megabytes. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, and `i`, then accepts interpolation tag `1` as `Interpolation::Lagrange`, reads `n` verification shares, and calls `ThresholdKeys::new`. [4](#0-3) 

`ThresholdKeys::new` builds the participant list `1..=t` and evaluates `interpolation_factor` for each participant to reconstruct `group_key`. [2](#0-1) 

For Lagrange interpolation, `interpolation_factor` loops over every entry in `included` and multiplies both the numerator and denominator once per included participant. [5](#0-4) 

Therefore, `t = n = 65535` produces roughly `65535 * 65535` scalar multiplications/subtractions before inversion, along with 65,535 point deserialization operations. The path returns an error only after this work if parameters are structurally valid. [6](#0-5) 

### Impact Explanation
A single crafted `ThresholdKeys` byte stream can cause a service thread to perform billions of field operations while deserializing it. Repeated submissions can exhaust CPU capacity and prevent honest signing, verification, or key-loading work from progressing. This matches a remotely triggerable availability failure rather than a cryptographic correctness failure. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
The triggering bytes contain no malformed field or point encodings and require no private state, collusion, or special privilege. An attacker only needs to reach a caller that passes untrusted bytes to `ThresholdKeys::read`, which is one of the explicitly exposed deserialization entry points. The input is approximately a few megabytes for common group encodings, making the amplification factor substantial. [7](#0-6) 

### Recommendation
Bound `t` and `n` to a protocol-supported maximum before allocating or reading variable-length material, and reject parameters whose interpolation complexity exceeds that bound. Alternatively, derive `group_key` without independent quadratic Lagrange evaluations, or defer expensive group-key reconstruction until all cheap validation has completed. At minimum, enforce a small deserialization limit such as `n <= MAX_PARTICIPANTS` before the coefficient/share loops in `ThresholdKeys::read`. [4](#0-3) 

### Proof of Concept
Construct a syntactically valid `ThresholdKeys<C>` encoding using a valid canonical scalar and point encoding:

```rust
let n = u16::MAX;
let t = u16::MAX;
let i = 1u16;

let mut bytes = Vec::new();
bytes.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
bytes.extend(C::ID);
bytes.extend(t.to_le_bytes());
bytes.extend(n.to_le_bytes());
bytes.extend(i.to_le_bytes());
bytes.push(1); // Interpolation::Lagrange
bytes.extend(C::F::ZERO.to_repr().as_ref());

let point = C::generator().to_bytes();
for _ in 0 .. n {
  bytes.extend(point.as_ref());
}

// This performs ~4.29 billion inner Lagrange loop iterations.
let _ = ThresholdKeys::<C>::read(&mut bytes.as_slice());
```

The payload is accepted far enough to invoke `ThresholdKeys::new`, whose `1..=t` loop invokes an `O(t)` Lagrange computation for each participant. [9](#0-8) [2](#0-1)

  /// The interpolation factor for this participant, within this signing set.
  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
