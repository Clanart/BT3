### Title
Diff-kind transition silently discards partial line exclusions and re-includes deselected content in the next commit - (File: `app/src/lib/stores/app-store.ts`)

### Summary
`ERC20Rewards._updateRewardsPerToken` short-circuited without updating `rewardsPerToken_.lastUpdated` when `totalSupply == 0`, so a later state transition (the first mint) inherited stale bookkeeping and silently attributed rewards that should not have existed. The same *"skip updating derived state when a special-case guard is hit, then blindly reuse the stale/derived value on the next transition"* pattern exists in GitHub Desktop's working-directory diff/selection pipeline: `updateChangesWorkingDirectoryDiff` in [1](#0-0)  only recomputes the `selectableLines` set when the newly-loaded diff is `DiffType.Text` or `DiffType.LargeText`. For any other diff kind, an **empty** `Set<number>` is passed straight into `DiffSelection.withSelectableLines`.

### Finding Description
`DiffSelection.withSelectableLines` in [2](#0-1)  filters the existing `divergingLines` (the lines the user has explicitly toggled away from the file's default selection state) against the newly supplied `selectableLines`:

```
const divergingLines = this.divergingLines
  ? new Set([...this.divergingLines].filter(x => selectableLines.has(x)))
  : null
```

If `selectableLines` is empty (which is exactly what `updateChangesWorkingDirectoryDiff` passes whenever the reloaded diff is not `Text`/`LargeText`), every previously diverging line is filtered out, leaving `divergingLines` as an **empty Set** (not `null`). `getSelectionType()` then hits its "happy path" check in [3](#0-2) :

```
if (!divergingLines) { return this.defaultSelectionType }
if (divergingLines.size === 0) { return this.defaultSelectionType }
```

so the selection silently reverts to `defaultSelectionType` (`All` for the common case of a modified file where a user has *deselected* some lines to keep them out of the commit). The comment in `app-store.ts` even acknowledges the shortcut: *"Ideally we would be more clever about validating that any partial selection state is still valid... but for now we'll settle on just updating the selectable lines"* — but the fallback for the non-text branch loses the exclusion information entirely instead of preserving it or refusing the update, unlike the reward contract fix which was told to never skip updating the tracked state.

### Impact Explanation
This corrupts what the user believes they are excluding from a commit. A user who has partially staged a modified text file (deliberately deselecting specific lines/hunks — e.g., a hardcoded secret, a local-only config change, or a merge marker) will have that exclusion silently discarded if the diff for that file is reloaded and classified as a non-text kind (binary/large/unrenderable) on the next refresh, because `updateChangesWorkingDirectoryDiff` runs automatically after every file selection change and status refresh via `_selectWorkingDirectoryFiles` ( [4](#0-3) ). Since the selection reverts to the default ("All"), the very next commit made from Desktop's UI will include the previously excluded lines — a silent corruption of what the user commits, matching the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
Triggering the diff-kind flip does not require local/physical access or malware: it can occur naturally whenever the working copy content underlying a tracked file changes such that Desktop's diff classification differs between two refreshes (e.g., the file crosses the large-diff-size threshold, git reports it differently, or a background operation such as an LFS smudge/clean filter, checkout, or externally-triggered write alters the file between the initial diff load and the follow-up refresh that `updateChangesWorkingDirectoryDiff` performs). Refreshes happen routinely (file watcher events, focus changes, status polling), so the race window between "user deselects lines" and "diff reloads with a different kind" is realistic without any unnatural user steps. I was not able to fully confirm the exact conditions under which `getWorkingDirectoryDiff` flips `DiffType` for a given file in this session (the relevant thresholds in `app/src/lib/git/diff.ts` were located but not fully inspected), so the precise trigger conditions for the kind change remain unverified from the index alone.

### Recommendation
When `diff.kind` is not `Text`/`LargeText`, `updateChangesWorkingDirectoryDiff` should not blindly call `withSelectableLines(new Set())`; it should either preserve the existing `DiffSelection` untouched (skip the update, analogous to always updating `lastUpdated` without corrupting `accumulated`) or explicitly reset the file's selection to a well-defined, user-visible state rather than silently deriving "All" from an empty selectable set. `DiffSelection.getSelectionType()`/`withSelectableLines` should also distinguish "no selectable-lines information available" from "definitely no diverging lines" so an empty `selectableLines` set can't masquerade as "everything selected."

### Proof of Concept
1. Modify a tracked text file and open it in Desktop's Changes view; the diff loads as `DiffType.Text`.
2. Deselect several added/removed lines (e.g., a line containing a secret) so the file's `DiffSelection` becomes `Partial` (`divergingLines` = the deselected lines, `defaultSelectionType = All`).
3. Cause a refresh of the working directory diff for that same file while its on-disk classification flips to a non-text `DiffType` (e.g., the diff becomes large enough to be treated as `LargeText`'s complement, or a filter/tool rewrites it such that git/Desktop's diff parser reports a different kind) before the file selection changes — `_selectWorkingDirectoryFiles` → `updateChangesWorkingDirectoryDiff` runs automatically after every status refresh.
4. In `updateChangesWorkingDirectoryDiff`, `selectableLines` stays an empty `Set` because the `diff.kind === DiffType.Text || DiffType.LargeText` branch is skipped (`app-store.ts:3478-3493`).
5. `currentlySelectedFile.selection.withSelectableLines(selectableLines)` filters out all previously diverging lines, and `getSelectionType()` now returns `DiffSelectionType.All`.
6. The user commits via the UI, believing the previously deselected lines were excluded; instead, the full file (including the secret/excluded content) is committed.

  public getSelectionType(): DiffSelectionType {
    const divergingLines = this.divergingLines
    const selectableLines = this.selectableLines

    // No diverging lines, happy path. Either all lines are selected or none are.
    if (!divergingLines) {
      return this.defaultSelectionType
    }
