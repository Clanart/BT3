## Title
Webhook HMAC verification is not bound to the shop domain, permitting cross-shop webhook forgery/replay - (File: `lib/shopify_app/controller_concerns/webhook_verification.rb`)

### Summary
The reported bug is that a signature's domain separator (chain ID) is never checked against the contract's actual chain, so a valid signature for one chain can be replayed on another. The direct analog in `shopify_app` is in `ShopifyApp::WebhookVerification`/`ShopifyApp::PayloadVerification`: the webhook HMAC is computed only over the raw request body with the app's shared secret, and the shop that the webhook is attributed to is read from an **unsigned** header, so a validly-signed webhook body can be replayed with a different shop-domain header and still pass verification.

### Finding Description
`hmac_valid?` computes/validates the digest using only `request.raw_post` and the app-wide secret(s): [1](#0-0) 

`WebhookVerification#verify_request` calls `hmac_valid?(data)` with `data = request.raw_post` — the shop is never part of the signed material: [2](#0-1) 

The module then exposes a `shop_domain` helper that is read straight from the client-supplied, unsigned `X-Shopify-Shop-Domain` header, with no cryptographic binding to the HMAC that was just verified: [3](#0-2) 

This is exactly the pattern `shopify_app`'s own documentation recommends for custom webhook controllers — the "domain" is trusted for authorization/business logic (`shop_domain:`) purely because the header says so, while only the body was authenticated: [4](#0-3) 

Because the app secret is shared across all shops that install the app (it is not shop-specific), any legitimately-signed `(body, hmac)` pair obtained from Shopify for shop A remains a *valid* HMAC pair regardless of which shop domain header accompanies it. This is structurally the same flaw as the reported bug: the "domain separator" (the shop identity) is absent from the data that is actually cryptographically verified, enabling replay across the "chain" boundary — here, across shops instead of blockchains.

By contrast, `AppProxyVerification` in the same codebase does this correctly by including `shop` inside the signed query string itself, so the domain is part of the verified digest: [5](#0-4) 

### Impact Explanation
An attacker who is a normal merchant with the app installed on their own shop can capture a legitimate `(raw_post, X-Shopify-Hmac-Sha256)` pair generated by Shopify for their own store, then replay that exact body/HMAC to the same app's webhook endpoint with the `X-Shopify-Shop-Domain` header rewritten to a victim shop's domain. `verify_request` will accept it because it only checks the HMAC over the body, and any controller/job built following `shopify_app`'s documented `shop_domain` pattern will process the (attacker-controlled) payload as if it belongs to the victim shop, e.g. `SomeJob.perform_later(shop_domain: shop_domain, webhook: webhook_params.to_h)`. This can lead to cross-shop data injection, forged events attributed to a shop the attacker does not control, or triggering shop-specific side effects (e.g. redact/data-request jobs, order/product state changes) under a spoofed shop identity — a cross-shop trust boundary bypass caused by an accepted forged signed request.

### Likelihood Explanation
Exploitability requires only: (1) the app secret is shared for all installs — a standard Shopify configuration, not misconfiguration; (2) the attacker can install the app on any shop (often self-serve) to obtain one valid `(body, hmac)` sample; and (3) the receiving controller uses the documented `shop_domain` helper for shop attribution, which is the pattern `shopify_app`'s own docs instruct developers to use. No secrets need to be leaked and no special privileges beyond "any merchant with the app installed" are required, making this a High-likelihood, unprivileged-actor scenario.

### Recommendation
Bind the shop identity into the value that is cryptographically verified rather than trusting an unsigned header:
- Compute/verify the HMAC over a canonical string that includes the shop domain (and ideally the webhook id/topic) in addition to the body, or
- After `hmac_valid?` succeeds, independently corroborate the `X-Shopify-Shop-Domain` header against a trusted, already-established relationship for that shop (e.g., only accept it if a session/webhook registration already exists for that domain, similar to how `AppProxyVerification` includes `shop` inside the signed query string), so that a captured signature/body pair cannot be re-attributed to an arbitrary shop.

### Proof of Concept
1. Install the target app on attacker-controlled shop `attacker.myshopify.com`; trigger any webhook topic the app subscribes to and capture the resulting POST body `B` and header `X-Shopify-Hmac-Sha256: H` sent by Shopify.
2. Craft a new POST to the same webhook endpoint (e.g. `/webhooks/<topic>`, following the documented custom-controller pattern in `docs/shopify_app/webhooks.md`) with:
   - Body: `B` (unchanged)
   - Header `X-Shopify-Hmac-Sha256: H` (unchanged, still validates because it only signs `B`)
   - Header `X-Shopify-Shop-Domain: victim.myshopify.com` (attacker-controlled)
3. `WebhookVerification#verify_request` → `hmac_valid?(B)` returns true (same secret, same body), so the request passes.
4. The controller reads `shop_domain` (`lib/shopify_app/controller_concerns/webhook_verification.rb:23-25`), which now returns `victim.myshopify.com`, and queues/executes shop-scoped logic as though the event genuinely originated from the victim's store.

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end

  end

  def webhook_params

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
