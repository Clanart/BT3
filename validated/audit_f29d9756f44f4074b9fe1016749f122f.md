### Title
Unsigned OP_RETURN payout output lets any unprivileged Bitcoin broadcaster overwrite operator payout attribution - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`Operator::withdraw`'s equality check `withdrawal_utxo != input_utxo.outpoint` only pins the spent outpoint and output 0 (via the user's `SinglePlusAnyoneCanPay` signature); it does nothing to authenticate output 2, the OP_RETURN that Clementine later reads back from the chain to decide *which* operator fronted a payout. Because the sighash flag `SIGHASH_SINGLE|ANYONECANPAY` only commits input index 0 and output index 0, anyone who observes the honest operator's payout transaction (e.g. in the mempool) can reuse the exact same witness to build a conflicting transaction with an arbitrary OP_RETURN, and whichever transaction is the one actually confirmed determines the DB-recorded "payer" operator.

### Finding Description
The binding the system relies on is:
`withdrawals.payout_payer_operator_xonly_pk (recorded for withdrawal idx i) == xonly_pk of the operator whose capital actually funded output 0 of the confirmed spend of withdrawal_utxo[i]`

`Operator::withdraw` checks only `withdrawal_utxo != input_utxo.outpoint` [1](#0-0) , and then verifies the user's signature solely over input index 0 of the payout transaction: `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` [2](#0-1) . The sighash type is enforced to be `SinglePlusAnyoneCanPay` [3](#0-2) , which by BIP-341/342 semantics commits only to input 0 and output 0 (`ANYONECANPAY` drops commitment to other inputs, `SINGLE` drops commitment to outputs beyond index 0).

`create_payout_txhandler` builds three outputs — user payout (0), anchor (1), OP_RETURN with the fronting operator's x-only pubkey (2) — and signs *only* input 0 via `set_p2tr_key_spend_witness(&user_sig, 0)` [4](#0-3) . Outputs 1 and 2 are therefore completely outside the signature's coverage: any party holding the raw witness (visible the moment the honest operator broadcasts, or even the moment it enters the mempool) can build their own transaction spending the same input with the same witness, keep output 0 fixed (forced by `SIGHASH_SINGLE`), and freely substitute the OP_RETURN and anchor outputs, then attach their own fee-paying inputs (permitted by `ANYONECANPAY`) to try to win the race to confirmation for that UTXO.

The downstream attribution mechanism trusts whichever transaction is eventually mined: `update_finalized_payouts` scans the block that spends the recorded `withdrawal_utxo` (joined via `bitcoin_syncer_spent_utxos` on txid/vout) and extracts the operator xonly pk purely from that confirmed transaction's OP_RETURN [5](#0-4) , then persists it via `update_payout_txs_and_payer_operator_xonly_pk` [6](#0-5) . Since a Bitcoin outpoint can only ever be spent once, whichever of the two conflicting transactions is confirmed permanently and irreversibly determines the DB row for that withdrawal index — there is no re-check against who actually paid; the outpoint being spent is the only "proof of funding" and it says nothing about the OP_RETURN content.

This attribution is later load-bearing for reimbursement gating: `is_kickoff_malicious` rejects a kickoff unless the OP_RETURN-derived pubkey equals `kickoff_data.operator_xonly_pk` [7](#0-6) , and `send_asserts` enforces the same equality before proceeding with reimbursement proof construction [8](#0-7) . If an attacker's replacement transaction confirms with a different (or unparsable) xonly pk in the OP_RETURN, the honest operator who actually fronted the payout (added their own fee/change inputs and got output 0 delivered to the user) can never pass this equality check again for that withdrawal — their kickoff will be flagged malicious or simply never match, permanently blocking their reimbursement.

None of the existing guards address this: `Operator::withdraw`'s outpoint check only prevents mismatched Citrea state, not OP_RETURN forgery; `SECP.verify_schnorr` only covers input 0/output 0 by design of the sighash flag; `is_kickoff_malicious` and `send_asserts` trust the DB value that is itself derived from unauthenticated bytes.

### Impact Explanation
An unprivileged party who observes the honest operator's broadcast payout transaction can, without spending any real capital of their own (beyond trivial fee-bumping to win the confirmation race), rewrite the OP_RETURN operator-attribution for a withdrawal they did not fund. This falls into the Critical bucket "an honest operator permanently unable to be reimbursed" — the operator who genuinely fronted the withdrawal (their fee-paying inputs, `add_inputs: true` in `fund_raw_transaction`) loses their sole on-chain proof of having done so, since the recorded attribution no longer matches their `kickoff_data.operator_xonly_pk`. The blast radius covers every withdrawal for which the honest operator's payout transaction is still unconfirmed and publicly visible (mempool), across any deposit/operator, and is repeatable per withdrawal.

### Likelihood Explanation
The precondition is simply mempool visibility of the honest payout transaction (a normal, unavoidable condition once it is broadcast) and the ability to broadcast a Bitcoin transaction and pay fees — squarely inside the defined unprivileged attacker capability set. The attacker cost is only the marginal fee needed to win a mempool/mining race against the honest operator's transaction (e.g., via RBF or simply being selected by a miner), no protocol capital or key compromise is required. This is deployable on any Bitcoin network configuration Clementine runs on (regtest/signet/mainnet) since it relies purely on the standardized `SIGHASH_SINGLE|ANYONECANPAY` semantics and normal Bitcoin mempool/fee mechanics.

### Recommendation
Move the operator-attribution commitment inside the signed portion of the payout transaction (e.g. commit the operator's xonly pubkey into a value that is covered by a full-transaction sighash, such as an operator-cosigned commitment, or require the operator to additionally sign the whole transaction with `SIGHASH_ALL` over a separate operator-controlled input/output) so that the OP_RETURN content cannot be altered by any party without invalidating the transaction.

Test plan:
1. Set up an e2e/manual test (following `core/src/test/manual_reimbursement.rs` pattern) with one honest `Operator` fronting a withdrawal via `operator0.withdraw(...)`, capturing the resulting `payout_tx` before it confirms.
2. Extract `payout_tx`'s witness for input 0 (the user's `SinglePlusAnyoneCanPay` signature) and output 0 (`payout_txout`), which remain identical/reusable.
3. As a plain wallet actor (not an `Operator`, `Verifier`, or `Aggregator` instance — just an RPC client with a funded wallet), construct a new raw transaction spending the same `input_outpoint` with the same witness, same output 0, but a different (or garbage) OP_RETURN in place of `operator_xonly_pk`, funded/fee-bumped from the attacker's own wallet, and broadcast it so it is the one that confirms instead of the honest operator's version.
4. After finality, call `db.get_payout_info_from_move_txid` and assert:
   - Before: `payout_op_xonly_pk == honest_operator.signer.xonly_public_key`.
   - After the attacker's tx confirms: `payout_op_xonly_pk != honest_operator.signer.xonly_public_key` (or `None`), proving the DB attribution equality is broken by an unprivileged party.
5. Additionally call `Verifier::is_kickoff_malicious` (or drive the honest operator through `send_asserts`) with the honest operator's real kickoff and assert it now fails/returns `true` (malicious) or errors on `payout_op_xonly_pk != kickoff_data.operator_xonly_pk`, demonstrating the honest operator can no longer be reimbursed.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
