## Answer

This report doesn't map to `bsaldua/chia-blockchain--011`'s spend-bundle/consensus/wallet surfaces directly, but Chia's **Data Layer mirror mechanism** exhibits the same bug class: an unprivileged party can inject an arbitrary URL that a victim service will later fetch from, with no host/scheme restriction — the same SSRF pattern as FoodCoopShop's manufacturer-supplied `remoteProductId`/`image` URL.

### Title
Unauthenticated on-chain mirror URLs allow SSRF from a Data Layer node - (File: `chia/data_layer/data_layer.py`)

### Summary
Any wallet holder can create a "mirror" coin for **any** DataLayer store (including stores they don't own) by spending a coin to `create_mirror_puzzle()` with a memo encoding an arbitrary `launcher_id` and arbitrary URL strings, via `DataLayerWallet.create_new_mirror()`. [1](#0-0) 
Once confirmed, any peer's wallet tracking that `launcher_id` records the mirror and its attacker-chosen URLs unconditionally in `coin_added()`. [2](#0-1) 

### Finding Description
`DataLayer.update_subscriptions_from_wallet()` pulls every mirror's URL list for a tracked store straight from the wallet RPC and merges them into the local `subscriptions` table with no validation of scheme or host. [3](#0-2) [4](#0-3) 

During the periodic management loop, `fetch_and_validate()` iterates these server URLs and calls `insert_from_delta_file` → `download_file` → `http_download`, which makes an outbound `aiohttp` HTTP request to `server_info.url + filename` for any store the node tracks (owned or subscribed). [5](#0-4) [6](#0-5) 

There is no allow-list/deny-list for private/loopback/link-local addresses (e.g. `127.0.0.1`, `169.254.169.254`, RFC1918 ranges) and no scheme restriction beyond what `aiohttp` itself enforces, exactly mirroring the FoodCoopShop flaw where a "manufacturer" supplied a remote image URL that the server fetched (CWE-918).

### Impact Explanation
Because store `launcher_id`s for public/shared DataLayer stores are public (they are singleton launcher coin IDs visible on-chain and typically advertised for subscription), any unprivileged party who can get a coin spend confirmed can plant a mirror URL pointing at an internal host/port of a victim's DataLayer node (e.g. cloud metadata endpoints, internal RPC ports, LAN services). The victim node will then autonomously issue outbound HTTP requests to that target as part of its normal `periodically_manage_data` cycle, providing a network-reachable SSRF primitive from a service that is otherwise not internet-facing to arbitrary attackers. Content returned is fed into delta-file parsing/insertion, which is validated against expected root hashes before being trusted, so the primary confirmed impact is SSRF (internal network reconnaissance / requests to sensitive internal endpoints) rather than confirmed data corruption.

### Likelihood Explanation
Exploitation only requires standing up a store the mirror targets and submitting one on-chain mirror-coin spend with a crafted URL memo — no special privileges, no cooperation from the store owner, and no validation blocks it in `create_new_mirror`/`coin_added`/`update_subscriptions_from_wallet`. Any node subscribed to or owning that store id will pick up the malicious mirror URL automatically on its next management cycle.

### Recommendation
- Validate mirror URLs before persisting/using them: enforce `http`/`https` scheme only, resolve and reject private/loopback/link-local/multicast IP ranges (RFC1918, 127.0.0.0/8, 169.254.0.0/16, ::1, fc00::/7, etc.), similar to standard SSRF mitigations.
- Re-validate resolved IPs at connection time (not just at DNS-lookup time) to prevent DNS-rebinding/TOCTOU bypasses, and disable HTTP redirects (or re-validate redirect targets) in `http_download`/`get_downloader`/`get_plugin_info`.
- Consider requiring operator opt-in/allow-listing for mirror URLs rather than trusting arbitrary on-chain mirror data automatically.

### Proof of Concept
1. Attacker publishes (or targets an existing) DataLayer store `launcher_id` that a victim node tracks.
2. Attacker calls `dl_new_mirror` (or crafts the equivalent spend directly) with `urls=["http://169.254.169.254/latest/meta-data/"]` for that `launcher_id`, using `DataLayerWallet.create_new_mirror()`. [1](#0-0) 
3. Once the mirror coin is confirmed, the victim's `coin_added()` records the Mirror with the attacker URL for the tracked `launcher_id`. [2](#0-1) 
4. On the next `periodically_manage_data`/`update_subscription` cycle, the victim's `DataLayer` service calls `fetch_and_validate()`, which issues an HTTP request to the attacker-controlled URL via `http_download`, completing the SSRF. [5](#0-4)

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
