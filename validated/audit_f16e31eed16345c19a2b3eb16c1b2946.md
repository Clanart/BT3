### Title
Scanner reports dust outputs as spendable `ReceivedOutput`s without accounting for the fee required to claim them - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` accepts any output paying to a registered script, with no minimum-value check, while `SignableTransaction::new` separately enforces a `DUST` limit on *payments*. The result mirrors the EIP-4626 preview/deposit fee mismatch: the value credited for a deposit (the face value of the output) does not account for the cost of actually claiming it. Inputs whose value is below the fee required to spend them are reported as received funds but are economically unspendable, and `SignableTransaction` will include them anyway, silently converting their deficit into additional fee paid by the multisig.

### Finding Description
The deposit-detection path is `Scanner::scan_transaction`, which pushes a `ReceivedOutput` for every `tx.output` whose `script_pubkey` matches a registered script, with no check on `output.value`:

```rust
// networks/bitcoin/src/wallet/mod.rs
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput { offset: *offset, output: output.clone(), outpoint: ... });
}
```

An unprivileged party can send a Bitcoin transaction paying as little as 1 sat to any of Serai's deposit scripts (the base script or any `register_offset`-derived script). The scanner reports this as a spendable `ReceivedOutput` with `value() == 1`.

On the spend side, `SignableTransaction::new` enforces `DUST = 546` for outgoing *payments* (`networks/bitcoin/src/wallet/send.rs:32`, `:165-169`), but performs no equivalent check on *inputs*. Each dust input adds ~58 vbytes of weight; at any viable `fee_per_vbyte`, the incremental `needed_fee` (`send.rs:204-233`) exceeds the input's value. The transaction still succeeds: the shortfall is absorbed by the other inputs, i.e. paid out of the multisig's own funds (`fee()` at `send.rs:138-141` is `sum(prevouts) - sum(outputs)` and happily exceeds `needed_fee`).

There is no path that reconciles "value reported as received" with "value net of the fee needed to spend it" — the exact inconsistency class of the reference finding (a conversion/reporting function that ignores fees charged in reality).

### Impact Explanation
- The network credits funds as received that cannot be spent profitably; the only ways to realize a dust `ReceivedOutput` are to pay more fee than it is worth (net loss to the multisig) or to leave it permanently unclaimed.
- Repeated dust deposits to deposit/offset scripts accumulate unspendable UTXOs that the scanner will keep reporting, and any spend path that indiscriminately includes scanned inputs inflates `needed_fee` and burns multisig funds proportional to attacker-controlled input count.

### Likelihood Explanation
Exploitation requires only a standard on-chain Bitcoin transaction from an unprivileged party to a publicly known deposit script — fully within the permitted attacker model. Whether the loss materializes depends on the input-selection policy outside this crate, but the missing invariant (no minimum-claimable-value check on inputs, while payments enforce `DUST`) is present in the in-scope code itself.

### Recommendation
Enforce a minimum economical value for received outputs — e.g., filter outputs below `DUST` (or a fee-rate-scaled claim threshold) in `Scanner::scan_transaction`, and/or reject inputs whose value is below the marginal fee of spending them in `SignableTransaction::new` — so that reported deposits reflect value that can actually be claimed.

### Proof of Concept
1. Attacker broadcasts a transaction with an output `{ value: 100, script_pubkey: <serai deposit script> }` (100 sats < `DUST`).
2. `Scanner::scan_transaction` returns a `ReceivedOutput` with `value() == 100`.
3. Passing it as an input to `SignableTransaction::new` succeeds; its ~58-vbyte weight raises `needed_fee` by more than 100 sats at any fee rate ≥ 2 sat/vB, so spending it strictly decreases the funds available to the multisig, and `fee()` reflects a real fee higher than `needed_fee()`.
