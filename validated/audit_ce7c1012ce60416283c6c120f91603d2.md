### Title
Unauthenticated SSRF via attacker-controlled DataLayer mirror URLs in `http_download` - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer subsystem lets any user with enough XCH create an on-chain "mirror" coin (`dl_new_mirror`) that advertises arbitrary URLs for a given store id [1](#0-0) . Any DataLayer client that later subscribes to that store id (a normal, unprivileged Data Layer operation) will pull this attacker-supplied URL list from wallet state and use it verbatim to issue outbound HTTP GET requests, with no host/scheme allow-list, no protection against internal/loopback/link-local targets, and default `aiohttp` redirect-following. This mirrors the reported Ech0 SSRF bug class: an unauthenticated/untrusted input controls a server-side outbound fetch URl that is used with no validation.

### Finding Description
- Mirror URLs are stored on-chain by anyone via the `MIRROR_PUZZLE_HASH` mechanism and read back through `dl_get_mirrors` / `get_mirror_info` with no content filtering [2](#0-1) .
- `DataLayer.update_subscriptions_from_wallet()` copies these mirror URLs verbatim into the local subscription server list for any subscribed store id, with only `rstrip("/")` normalization — no validation of scheme, host, or target address: [3](#0-2) .
- `DataLayer.add_mirror()` similarly accepts and forwards arbitrary URLs with no validation beyond emptiness checks: [1](#0-0) .
- During sync, `fetch_and_validate()` selects one of these (possibly malicious) `server_info.url` entries and passes it into `insert_from_delta_file()`/`download_file()` [4](#0-3) .
- `download_file()` and `http_download()` in `chia/data_layer/download_data.py` construct the request from `server_info.url + "/" + filename` and issue a plain `aiohttp.ClientSession().get(...)` with no destination filtering, no disabling of redirects, and streams the full response body to disk based only on a `Content-Length` size check: [5](#0-4) .

This is functionally identical to the Ech0 vulnerability: a network-reachable, low-privilege actor (anyone who can put a coin/spend on chain) supplies a URL that a service later fetches unconditionally from the server process, with no SSRF-safe URL policy, no redirect limits, and no allow-list — enabling requests against internal services, cloud metadata endpoints, or other hosts reachable only from the victim node's network position.

### Impact Explanation
A DataLayer operator who subscribes to (or owns/mirrors) a store controlled or influenced by an attacker can be coerced into making their node issue arbitrary outbound HTTP(S) requests during routine sync (`fetch_and_validate`/`periodically_manage_data`). This can be used to probe/reach internal network services, hit cloud metadata endpoints (`169.254.169.254`), or exhaust node resources/disk by pointing at large or slow responses despite the size cap (a DoS vector on the sync loop). Because the URL is embedded in on-chain-derived mirror data, this crosses a trust boundary: the DataLayer subscriber trusts store content integrity (verified against Merkle roots) but not necessarily arbitrary mirror URL destinations, yet URLs are used with full server-side network privilege of the node process. This qualifies as Medium severity given the requirement that a victim opt to subscribe/track the malicious store id, which is standard Data-Layer usage but is nonetheless attacker-influenced input.

### Likelihood Explanation
Any user can create a DataLayer store and a mirror coin with attacker-chosen URLs for the price of a normal spend bundle; no special privilege on the victim node is required, and mirror lists refresh automatically in the background sync loop (`periodically_manage_data`) once a client subscribes to that store id — a routine, expected Data Layer client action. The only limiting factor is that the victim must choose to track/subscribe to the malicious store, which is a common workflow for third-party or public DataLayer stores.

### Recommendation
- Validate mirror/server URLs before use: enforce an allow-listed scheme (`http`/`https`), reject loopback/link-local/private/metadata address ranges unless explicitly configured, and resolve DNS to re-check target IPs to prevent DNS-rebinding bypasses.
- Disable or strictly cap HTTP redirects in `http_download()`/`download_file()`, and re-validate the final resolved target against the same allow-list.
- Add explicit outbound request timeouts and firm response-size limits enforced independent of `Content-Length` headers.
- Consider making cross-network mirror fetching opt-in/configurable per-operator risk tolerance, and document the trust model for mirror URLs clearly.

### Proof of Concept
1. Attacker creates a DataLayer store and mirror coin, e.g. via `chia data_layer add_mirror`/`dl_new_mirror`, with `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-host:9999/leak"]` [1](#0-0) .
2. The store id, along with its mirror coin, is included in a block; any Data Layer client (victim) that subscribes to this store id will observe the mirror via `dl_get_mirrors` and, on the next `periodically_manage_data` cycle, calls `update_subscriptions_from_wallet()`, adding these URLs to its local subscription server list [3](#0-2) .
3. During the subsequent `fetch_and_validate()` call, the victim node picks the malicious `server_info.url` and calls `http_download()`, issuing an outbound `GET http://169.254.169.254/latest/meta-data/...` (or the internal host) directly from the victim's DataLayer process, with no scheme/host validation [5](#0-4) .

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
