### Title
`SignableTransaction::new` omits the OP_RETURN data output from fee/weight accounting, underpaying the fee and inflating change - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
Analogous to the Tokemak finding — where an accumulated accounting quantity (`idleIncrease`) was effectively dropped from the final `totalIdle` computation — `SignableTransaction::new` pushes an OP_RETURN `TxOut` onto `tx_outs` but computes `vbytes`, `needed_fee`, the minimum-relay check, the change amount, and the `MAX_STANDARD_TX_WEIGHT` check from a reconstructed transaction that contains only `payments` (and optionally `change`). The data output's size is never accounted for, so the signed transaction systematically pays a lower feerate than the caller-specified `fee_per_vbyte`.

### Finding Description
In `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs`), the OP_RETURN output is appended to `tx_outs` at send.rs:194-202. Immediately after, size and fee are derived from `calculate_weight_vbytes(tx_ins.len(), payments, None)` at send.rs:204 — and `calculate_weight_vbytes` (send.rs:62-99) builds its synthetic transaction's `output` solely from `payments` plus an optional `change` output. The OP_RETURN output is therefore excluded from:

1. `vbytes` → `needed_fee = fee_per_vbyte * vbytes` (send.rs:206) is underestimated by roughly `9 + script_len` vbytes (up to ~92 vbytes for 80 bytes of data, permitted by the check at send.rs:171).
2. The minimum relay fee check (send.rs:211), which uses the same underestimated `vbytes` on both sides.
3. The change computation (send.rs:225-234): `fee_with_change` is also computed without the OP_RETURN output, so `value = input_sat - payment_sat - fee_with_change` is over-credited to change relative to the intended feerate — the "missing" fee is silently redirected into the change output instead of being paid, and the actual fee `sum(inputs) - sum(outputs)` equals the underestimated `fee_with_change`.
4. The `weight > MAX_STANDARD_TX_WEIGHT` standardness check (send.rs:241), which can pass while the real transaction is non-standard.

The divergence is proportional to `fee_per_vbyte * (~9 + data.len() + 2)`.

### Impact Explanation
Every transaction carrying a `data` payload pays `fee_per_vbyte * op_return_vsize` less than intended. When `fee_per_vbyte` is chosen near the minimum relay fee, the effective feerate can fall below `DEFAULT_MIN_RELAY_TX_FEE` for the transaction's true vsize, producing a signed transaction that nodes will not relay or mine — inputs are consumed into a plan whose completion transaction cannot confirm, and any subsequent rebroadcast attempt at the requested rate still underpays. This is a correctness violation of the function's contract ("the fee necessary to achieve the fee rate specified"), reachable purely via public inputs (the `data` argument to `SignableTransaction::new`). No funds are directly stolen; the damage is a systematically wrong fee formula and potentially unbroadcastable signed transactions locking UTXOs.

### Likelihood Explanation
Triggering requires only that `SignableTransaction::new` be called with `Some(data)` — a documented, supported parameter ("If data is specified, an OP_RETURN output will be added with it"), used for protocol metadata/memos. No malicious validator, key compromise, or misuse is needed; any caller passing data hits the underpayment deterministically. Whether it becomes a stuck transaction depends on how close the requested `fee_per_vbyte` is to the relay minimum and the size of `data`.

### Recommendation
Include the OP_RETURN output in the weight/vbytes estimate. Either pass the already-built `tx_outs` (payments + OP_RETURN) into `calculate_weight_vbytes` instead of reconstructing outputs from `payments`, or add an explicit `data_len`/`extra_outputs` parameter so both the no-change estimate (send.rs:204) and the with-change estimate (send.rs:226) account for the data output. Concretely, reorder: build `tx_outs` first (payments + OP_RETURN), then compute weight over `tx_outs` and `tx_outs + change`.

### Proof of Concept
```rust
// networks/bitcoin conceptual test
let data = vec![0u8; 80]; // max permitted by the TooMuchData check
let tx = SignableTransaction::new(
    vec![output],          // input worth input_sat
    &payments,
    Some(change_script),   // change branch taken
    Some(data.clone()),    // OP_RETURN pushed onto tx_outs (send.rs:194-202)
    fee_per_vbyte,
).unwrap();

// Actual size includes the OP_RETURN TxOut (~92 extra vbytes),
// but needed_fee was computed from payments+change only (send.rs:204, 226):
let real_vsize = tx.transaction().vsize() as u64;
assert!(tx.needed_fee() < real_vsize * fee_per_vbyte);
// Effective feerate = needed_fee / real_vsize < fee_per_vbyte.
// If fee_per_vbyte was exactly the relay minimum for the *estimated* size,
// needed_fee / real_vsize < 1 sat/vbyte -> transaction fails relay policy.
```
