### Title
Gasless-Tx Queue Capacity Can Be Denial-of-Serviced by Cheap Repeated Approve Transactions - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The kaiax `gasless` module admits `GaslessApproveTx`/`GaslessSwapTx` transactions into a bounded "known bundle-tx" tracking structure whose capacity is governed by a fixed configuration value (`MaxBundleTxsInQueue`, default 200). Any unprivileged transaction sender who can produce a transaction satisfying `IsApproveTx` can occupy a queue slot at very low cost, and by repeating this from many throwaway senders can keep the shared queue permanently saturated, blocking legitimate users' gasless approve/swap transactions from ever being tracked/promoted — the same "cheap repeated action exhausts a shared bounded resource" bug class described in the external report about rate limiter abuse.

### Finding Description
`PreAddTx` is the tx-pool admission hook for the gasless module: [1](#0-0) 

Any transaction that satisfies `IsBundleTx` (i.e., `IsApproveTx` or `IsSwapTx`, see `IsModuleTx`) is added to `g.knownTxs` as long as `numQueue() < GetMaxBundleTxsInQueue()`; once the counter reaches the configured limit, every further bundle tx — from any sender — is rejected with `ErrBundleTxQueueFull`: [2](#0-1) 

`IsApproveTx` only requires that `tx.to` be a whitelisted ERC20 token, that the call be `approve(spender, amount)`, that `spender` be the whitelisted `SwapRouter`, and that `amount == MaxUint256`: [3](#0-2) 

The default queue capacity is small and configurable but bounded: [4](#0-3) 

Entries only leave the queue counter after they are promoted to pending or after a fixed `QueueTimeout` of 10 seconds: [5](#0-4) 

An attacker controlling many sender addresses, each holding a nonzero balance of a single whitelisted gasless token (the only balance precondition checked, per `checkBalanceForApprove`, and only when `BalanceCheckLevel` includes token checks): [6](#0-5) 

can submit a steady stream of cheap `approve(router, MaxUint256)` transactions (one per sender, satisfying only static ABI/whitelist conditions, no swap execution needed) to keep `numQueue()` pinned at the configured maximum indefinitely (re-filling every ~10s as entries expire), permanently returning `ErrBundleTxQueueFull` for legitimate gasless senders. This mirrors the rate-limiter abuse pattern in the report: a bounded, shared "capacity" resource that any low-cost, repeated unprivileged action can saturate to deny service to others, at a cost of only gas fees (plus trivial token holdings).

### Impact Explanation
This is a protocol-level denial-of-service against the gasless (KIP-247) feature: legitimate users' `GaslessApproveTx`/`GaslessSwapTx` transactions will be persistently rejected at admission (`ErrBundleTxQueueFull`), preventing them from using the sponsored-gas swap flow. Because the queue is a shared, global structure (not per-sender), a single attacker can deny the feature to all users on the node with a comparatively small number of cheap transactions repeated continuously. This does not directly cause fund loss but denies a core protocol feature to legitimate users, which is the same class of impact flagged as valid ("Medium" DoS) in the original report.

### Likelihood Explanation
Likelihood is moderate-to-high for a determined attacker: the precondition is holding a nonzero balance of a single whitelisted gasless token across a modest number of addresses (cheap to acquire, e.g. via a DEX or by self-minting on chains where the attacker also controls the token/router allow-list proposal, or simply buying dust amounts), and continuously submitting well-formed approve transactions before each 10-second expiry window. No special privilege, signature, or node/validator role is required — only a regular transaction sender able to reach `PreAddTx` through normal tx-pool submission (RPC `eth_sendRawTransaction`/`kaia_sendRawTransaction`).

### Recommendation
- Make the queue capacity per-sender rate limited (e.g., cap concurrent queued bundle txs per sender/IP) in addition to (or instead of) a single global counter, so no single actor can consume the entire shared capacity.
- Consider requiring a minimum token/economic stake or increasing the cost of holding queue slots (e.g., weighting by token balance or requiring escrow) to raise the cost of the attack, consistent with the report's recommendation of withdrawal-fee-like friction.
- Shorten `QueueTimeout`/`MaxBundleTxsInQueue` dynamically or provide an operator-adjustable "emergency" override (analogous to the 0-day `updateTotalLimit` recommended in the report) to quickly raise capacity or evict abusive senders during an active flood, rather than requiring a node restart/reconfiguration.
- Track and penalize (e.g., temporarily blacklist) senders who repeatedly submit approve transactions that are never followed by a valid swap, since this pattern is indicative of queue-filling abuse rather than genuine gasless usage.

### Proof of Concept
1. Attacker acquires a small nonzero balance of a whitelisted gasless ERC-20 token (`AllowedTokens` config) across `N` throwaway EOAs, where `N` ≈ `MaxBundleTxsInQueue` (default 200).
2. Each EOA broadcasts an `approve(router, type(uint256).max)` transaction on the whitelisted token, satisfying `IsApproveTx` (`kaiax/gasless/impl/getter.go:74-86`).
3. Each transaction is admitted via `PreAddTx` (`kaiax/gasless/impl/tx_pool.go:38-53`), incrementing `g.knownTxs.numQueue()` until it hits `GetMaxBundleTxsInQueue()`.
4. From this point, any other legitimate user's `GaslessApproveTx`/`GaslessSwapTx` submitted via `PreAddTx` receives `ErrBundleTxQueueFull` and is rejected.
5. Before each queued entry's 10-second `QueueTimeout` expires, the attacker resubmits fresh approve transactions (new nonces) from the same or additional EOAs to keep the queue saturated indefinitely, sustaining the denial of service at the cost of gas fees only.

Note: I could not fully verify from the indexed code whether there is additional per-sender de-duplication or pool-level eviction logic beyond what is shown in `tx_pool.go`/`tx_counter.go` (the `tx_counter.go` internals were not retrieved in full). If a stricter per-sender cap or additional expiry/promotion logic exists there, it could reduce the practical severity of this DoS; a Devin session with full repository access would be needed to confirm the complete behavior of `kaiax/gasless/impl/tx_counter.go`.

```go
func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}
```

```go
func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}
```

```go
// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}
```
