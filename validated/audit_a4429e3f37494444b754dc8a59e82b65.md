## Finding: PlotNFT payout instructions (`payee`) not reset on ownership transfer

### Title
Stale pool payout instructions after PlotNFT ownership transfer causes farming-reward redirection - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`)

### Summary
`PlotNFT2Wallet.coin_added()` keys the locally-persisted `PoolingShareState` pool config by `p2_singleton_puzzle_hash`, which is derived purely from the PlotNFT's launcher/singleton id and is therefore identical before and after an ownership change. When a PlotNFT that is already tracked (i.e. the entry exists for that `p2_singleton_puzzle_hash`) transitions to a new owner via `transfer_plotnft()`, `coin_added()` updates `owner_public_key` and `key_derivation_index` but never updates `payout_instructions`.

### Finding Description
`PlotNFT2Wallet.transfer_plotnft()` re-keys the PlotNFT's inner puzzle to a new owner's synthetic public key while the singleton/launcher id (and thus `p2_singleton_puzzle_hash`) stays the same: [1](#0-0) 

`p2_singleton_puzzle_hash` and `rewards_claim_puzhash` are derived from the singleton id and read `PoolingShareState.payout_instructions`, independent of current owner: [2](#0-1) 

When the wallet syncs the resulting coin, `coin_added()` branches on whether `p2_singleton_puzzle_hash` already has a `PoolingShareState` entry. If it does (already-tracked PlotNFT, now under new ownership), it updates `owner_public_key` and `key_derivation_index` but leaves `payout_instructions` untouched: [3](#0-2) 

Only in the `else` branch — i.e. only when the `p2_singleton_puzzle_hash` was never previously registered — is a fresh `payout_instructions` derived for the new owner: [4](#0-3) 

`PoolingShareState.acquire()`/`add()` persist this config keyed only by `p2_singleton_puzzle_hash` in `pooling_share_state.yaml`, with no coupling to `owner_public_key`: [5](#0-4) [6](#0-5) 

This is the same class of bug as the reported `LienToken.payee` issue: an owner-controlled "payee" field is detached from the token/singleton's actual current owner and is not reset on transfer, so it survives a change of custody.

### Impact Explanation
For a self-pooling PlotNFT, `rewards_claim_puzhash` (== `payout_instructions`) is the destination used when claiming/absorbing farming rewards. If a PlotNFT that already has a `PoolingShareState` entry (e.g. previously owned/tracked on this node) is transferred to a different local wallet/key via `plotnft_transfer`/`transfer_plotnft`, the new owner takes over singleton control (`owner_public_key`, `key_derivation_index`) but pool/self-pooling reward payouts continue to be directed to the puzzle hash chosen by the *previous* owner. This is a reward-redirection bug: farming income tied to the singleton the new owner now controls can be silently paid to a puzzle hash the new owner does not control.

### Likelihood Explanation
The bug triggers deterministically whenever a tracked PlotNFT's `p2_singleton_puzzle_hash` is already present in `PoolingShareState` and its owner changes via the supported `plotnft_transfer` RPC/`transfer_plotnft()` flow (e.g. a farming-as-a-service/pool-operator node managing multiple customers' PlotNFTs, or a PlotNFT changing hands between wallets tracked by the same node). No malicious peer or privileged access is required — it is reachable purely through the documented wallet transfer feature.

### Recommendation
When `coin_added()` observes an owner change for an already-registered `p2_singleton_puzzle_hash` (i.e. `owner_public_key`/`key_derivation_index` differ from the stored values), also reset `payout_instructions` to a freshly derived puzzle hash for the new owner (mirroring the `else` branch), rather than only updating ownership/target fields.

### Proof of Concept
1. Node tracks PlotNFT A (self-pooling), with `PoolingShareState` entry keyed by `p2_singleton_puzzle_hash = H`, `payout_instructions = P_old` (old owner's puzzle hash).
2. Old owner calls `plotnft_transfer` (`chia/wallet/wallet_rpc_api.py` `plotnft_transfer`, `chia/wallet/plotnft_wallet/plotnft_wallet.py:transfer_plotnft`) targeting a new owner's key fingerprint tracked by the same node/keychain.
3. Wallet sync observes the new PlotNFT coin; `PlotNFT2Wallet.coin_added()` finds `H` already in `PoolingShareState` and only updates `owner_public_key`/`key_derivation_index` (lines 606-622), leaving `payout_instructions = P_old`.
4. New owner farms and later claims self-pooled rewards; `rewards_claim_puzhash` still resolves to `P_old`, so reward payouts go to the old owner's puzzle hash instead of the new owner's.
