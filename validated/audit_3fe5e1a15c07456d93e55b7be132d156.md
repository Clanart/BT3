### Title
Attacker-controlled `_minMGPRec` enables self-sandwich price manipulation of the fixed BUSD→MGP swap in `_bullMGP`, inflating locked MGP/vlMGP voting weight funded by protocol reserves - ([File: wombat/ArbWomUp2.sol])

### Summary
`incentiveDeposit(_amount, _minMGPRec, true)` computes a fixed `rewardToSend` BUSD amount (independent of market price) and swaps it for MGP via `ROUTER.swapExactTokensForTokens` using the caller-supplied `_minMGPRec` as the only slippage bound. Because the attacker fully controls `_minMGPRec` (can set it to 0) and can manipulate the BUSD/MGP pool price immediately before the swap, they can make the fixed-BUSD swap execute at an artificially depressed MGP price, receiving more MGP than a fair-price execution would, which is then bonus-multiplied and locked as `vlMGP` voting power under their own address.

### Finding Description
`incentiveDeposit` in [1](#0-0)  computes `rewardToSend` via `getRewardAmount`, a BUSD amount drawn from the protocol's own BUSD balance based on deposit tier tables, not from any market rate [2](#0-1) . When `_bullMode` is true, this fixed BUSD amount is passed straight into `_bullMGP`, which performs `ROUTER.swapExactTokensForTokens(_busdAmount, _minRec, path, address(this), block.timestamp)` and locks `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` into `vlMGP` for the caller [3](#0-2) .

The only slippage/price protection on this swap is `_minRec`, which is supplied directly by the caller (`_minMGPRec` in `incentiveDeposit`) with no floor enforced by the contract and no TWAP/oracle sanity check. Since `_busdAmount` (the input) is fixed by the protocol's reward schedule and does not depend on the execution price, an attacker who both calls `incentiveDeposit` and manipulates the BUSD/MGP pool price in the same transaction (a "self-sandwich": sell MGP into the pool to depress price, call `incentiveDeposit(bullMode=true, _minMGPRec=0)`, then restore the pool) can cause `amounts[1]` (MGP received for the fixed BUSD) to be inflated relative to fair market price. The resulting `mgpAmountToLcok`, multiplied further by `bullBonusRatio`, is locked to the attacker's `vlMGP` position, granting them disproportionate voting weight/emission share for the same protocol-funded BUSD reward.

Existing guards (`whenNotPaused`, `nonReentrant`, `_checkAmount`) do not address this because they check reentrancy/pausing/zero-amount, not price manipulation or minimum-output floors independent of caller input.

### Impact Explanation
This allows an unprivileged attacker to convert a fixed protocol BUSD reward into an inflated MGP/vlMGP lock by manipulating the swap price of the pool used by `ROUTER`, directly increasing their governance voting weight and future emission share beyond what the protocol intended to pay out for a given deposit tier. This maps to "theft of unclaimed yield" / "governance voting result manipulation" since the same BUSD subsidy yields more locked MGP than a non-manipulated execution would produce, at the expense of protocol-intended reward parity and diluting other vlMGP holders' relative voting weight.

### Likelihood Explanation
Exploitability depends on the depth/liquidity of whichever BUSD/MGP pool is configured behind `ROUTER` — the shallower the pool, the cheaper it is for an attacker to move the price temporarily. The attack requires only capital to briefly move the pool price (potentially via flash loan) plus normal swap fees, no privileged role, and is repeatable per `incentiveDeposit` call subject to the attacker's own WOM deposit and the tier-based `rewardToSend` calculation, which caps the exploitable BUSD amount per call to the contract's available `busd` balance and the deposit-tier reward table.

### Recommendation
Do not let the caller supply `_minRec`/`_minMGPRec` for a swap whose input notional is protocol-funded; instead compute a protocol-enforced minimum output from a manipulation-resistant reference price (e.g., a TWAP oracle) before calling `_bullMGP`, or cap `mgpAmountToLcok` by an independent oracle-derived fair value rather than relying solely on raw AMM spot output.

### Proof of Concept
Foundry fork test plan:
1. Fork BSC/Arbitrum at a block where the BUSD/MGP pool behind `ROUTER` (and `vlMGP`) is deployed with realistic liquidity; fund the `ArbWomUp2` contract with BUSD reward reserve.
2. Baseline: call `incentiveDeposit(amount, minMGPRec=fairMinOut, bullMode=true)` without manipulating the pool; record `mgpAmountToLcok` from the `VLMGPRewarded` event.
3. Attack: in a single transaction (attacker contract), (a) swap MGP for BUSD on the same pool to depress MGP price, (b) call `incentiveDeposit(amount, minMGPRec=0, bullMode=true)`, (c) swap BUSD back for MGP to restore price.
4. Assert the `mgpAmountToLcok` credited to the attacker's `vlMGP` lock in step 3 is significantly higher than the baseline from step 2 for the identical `_amount`/BUSD reward input, quantifying the inflated voting weight obtained purely via price manipulation.

        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function getRewardAmount(uint256 _amount, address _account) external view returns (uint256) {
        if (_amount == 0 || rewardMultiplier.length == 0) return 0;
        uint256 accumulated = _amount + userWOMDeposited[_account];

        uint256 rewardAmount = 0;
        uint256 i = 1;
        while (i < rewardTier.length && accumulated > rewardTier[i]) {
            rewardAmount +=
                (rewardTier[i] - rewardTier[i - 1]) *
                rewardMultiplier[i - 1];
            i++;
        }
        rewardAmount += (accumulated - rewardTier[i - 1]) * rewardMultiplier[i - 1];

        uint256 busdReward = (rewardAmount / DENOMINATOR) - this.calDoubledCounted(_account);
        uint256 busdleft = IERC20(busd).balanceOf(address(this));

        return busdReward > busdleft ? busdleft : busdReward;
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
