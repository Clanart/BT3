## Title
Native ERC20 self-destruct permanently breaks the 1:1 backing invariant between minted Cosmos coins and escrowed ERC20 collateral, permanently freezing/duplicating value - (File: `x/erc20/keeper/msg_server.go`, `x/erc20/keeper/token_pairs.go`)

### Summary
The `x/erc20` module lets any unprivileged account permissionlessly register an externally-owned ("native") ERC20 contract as a `TokenPair` and convert between the ERC20 token and a freshly-minted Cosmos coin representation 1:1. If the registered ERC20 contract is later self-destructed, the keeper's only recovery action is to silently delete the `TokenPair` mapping — it never reconciles or burns the Cosmos coins that were already minted against the (now destroyed) ERC20 collateral. This is the same bug class as the reported `TokenManager` issue: removing an asset entry from an accounting registry without settling the debt/collateral it was backing, letting a user keep freely-minted value while destroying its backing.

### Finding Description
`RegisterERC20` allows permissionless registration when `params.PermissionlessRegistration` is true, with no validation that the target contract can never self-destruct: [1](#0-0) 

`registerERC20`/`CreateCoinMetadata` only check for duplicate registration and pull ERC20 metadata via a normal `eth_call`; there is no bytecode/immutability check: [2](#0-1) 

`ConvertERC20` escrows the caller's ERC20 tokens into the module address (verified by a real balance-diff check) and then mints an equal amount of Cosmos coins to the receiver: [3](#0-2) 

Because the token is externally owned (`OWNER_EXTERNAL`), the attacker fully controls the contract and can self-destruct it at will after this conversion. `DeleteAccount` (invoked on `SELFDESTRUCT`) wipes the entire contract storage, including the balance entry recorded for the module account that "holds" the escrowed collateral: [4](#0-3) 

The only place that detects this is the next `ConvertERC20`/`ConvertCoin` call, which checks `acc == nil || !acc.HasCodeHash()` and, instead of reverting or burning the outstanding coin supply, simply deletes the `TokenPair` mapping (mirroring the `TokenManager.removeAcceptedToken` pattern in the report): [5](#0-4) [6](#0-5) 

`DeleteTokenPair` removes the ERC20 map, denom map, and allowances, but performs no `BurnCoins` or supply reconciliation against the coins already minted and now sitting in user wallets: [6](#0-5) 

The net effect: the attacker legitimately transfers ERC20 tokens to the module (satisfying all in-flow invariant checks in `convertERC20IntoCoinsForNativeToken`), receives freshly minted, fully spendable, transferable, IBC-transferable Cosmos coins, then self-destructs the contract to erase the "collateral" that was supposed to back those coins. The coins remain valid native bank balances forever — there is no mechanism anywhere in the module to detect or claw back this now-unbacked supply.

### Impact Explanation
This is a Critical unauthorized duplication of spendable user value: an unprivileged attacker can mint an arbitrary amount of freely spendable native Cosmos coins backed by an asset they then destroy, permanently corrupting the 1:1 accounting invariant between the ERC20 collateral and the minted representation, with no admin/governance recovery path since `DeleteTokenPair` never touches circulating supply.

### Likelihood Explanation
Fully reachable by an ordinary user when `PermissionlessRegistration` is enabled (test suite explicitly exercises the "ok - non-governance, permissionless true" registration path), requiring only: (1) deploy a self-destructible ERC20, (2) register it via `MsgRegisterERC20`, (3) convert some ERC20 balance via `MsgConvertERC20`, (4) self-destruct the contract. No privileged role or race condition is needed.

### Recommendation
- Before allowing conversion/registration of an "external" (`OWNER_EXTERNAL`) ERC20 as backing for mintable Cosmos coins, require it to be non-self-destructible, or track and lock/burn the corresponding minted coin supply whenever the backing contract is detected as destroyed (instead of only deleting the registry entry).
- On detecting `!acc.HasCodeHash()` in `ConvertERC20`/`ConvertCoin`, atomically burn/freeze the outstanding bank coin supply for that denom (or transfer it to a recovery/insurance module account) before/while deleting the `TokenPair`, rather than leaving previously-minted coins fully spendable with no backing.
- Consider disabling `PermissionlessRegistration` by default or adding a bytecode allow-list / static analysis check to reject self-destructible contracts at registration time.

### Proof of Concept
1. Attacker deploys `EvilERC20` — a standard ERC20 with an owner-only `kill()` function calling `selfdestruct`.
2. Attacker submits `MsgRegisterERC20{Signer: attacker, Erc20Addresses: [EvilERC20]}` (passes when `PermissionlessRegistration=true`, no governance needed) — see `RegisterERC20` at [7](#0-6) .
3. Attacker mints/holds `N` EvilERC20 tokens, then calls `MsgConvertERC20{Amount: N, ContractAddress: EvilERC20}`. This escrows `N` tokens to the module address and mints `N` native coins of the derived denom to the attacker (`convertERC20IntoCoinsForNativeToken`).
4. Attacker calls `EvilERC20.kill()`, self-destructing the contract; `DeleteAccount` wipes all contract storage (including the module's escrowed balance record).
5. Attacker now holds `N` fully valid, spendable/transferable/IBC-transferable native coins while the ERC20 collateral backing them has been permanently destroyed.
6. Any subsequent `ConvertERC20`/`ConvertCoin` call for this pair merely deletes the `TokenPair` via `DeleteTokenPair`; the attacker's `N` coins are never burned or reconciled.

// convertERC20IntoCoinsForNativeToken handles the erc20 conversion for a native erc20 token
// pair:
//   - escrow tokens on module account
//   - mint coins on bank module
//   - send minted coins to the receiver
//   - check if coin balance increased by amount
//   - check if token balance decreased by amount
//   - check for unexpected `Approval` event in logs
func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}

// DeleteTokenPair removes a token pair.
func (k Keeper) DeleteTokenPair(ctx sdk.Context, tokenPair types.TokenPair) {
	id := tokenPair.GetID()
	k.deleteTokenPair(ctx, id)
	k.deleteERC20Map(ctx, tokenPair.GetERC20Contract())
	k.deleteDenomMap(ctx, tokenPair.Denom)
	k.deleteAllowances(ctx, tokenPair.GetERC20Contract())
}
