## Title
Spoofable `WWW-Authenticate` realm lets an attacker-controlled Git server force GitHub Desktop's credential trampoline to trust it as a GitHub Enterprise host - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

## Summary
The upstream finding's root cause is a "wrong source used for a security-relevant decision" bug: `leave()` mixes up `collateralSource` and `supplySource` when both are attacker-influenced state, letting the caller redirect a payout to the wrong pool. The Desktop analog is `getEndpointKind()` in [1](#0-0)  which classifies an arbitrary remote host as `'enterprise'`/GitHub based on a `wwwauth[]` header value that is fully controlled by whatever server the user's git remote points to, instead of validating that the host is actually a trusted GitHub endpoint.

## Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's `credential.helper=desktop`, which is dispatched to `createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`: [2](#0-1) 

The classification logic first checks `isGist`/`isDotCom`/`isGHE` (all based on hostname), but then falls back to trusting attacker-suppliable data: any `wwwauth[...]` line in the credential-helper protocol payload whose value contains `realm="GitHub"` is treated as proof the host is a GitHub Enterprise Server (`'enterprise'`), and this data comes directly from the HTTP `WWW-Authenticate` response header that git captured from **whatever server answered the request** - i.e., a git remote/server the user (or a fork/clone/submodule the user checked out) points Desktop at. Any HTTP server the attacker controls can respond `WWW-Authenticate: Basic realm="GitHub"` on a 401, regardless of hostname.

Downstream, `getCredential()` uses that misclassification to decide the authentication UX: [3](#0-2) 

If `endpointKind !== 'generic'` and no existing account matches the computed `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` instead of the generic username/password prompt: [4](#0-3) 

`promptForGitHubSignIn` inspects only the hostname of the attacker-controlled `endpoint` to pick GitHub.com vs. Enterprise sign-in, and for anything other than `github.com` it calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)`, pointing Desktop's real GitHub-Enterprise-authentication machinery (which performs live API/OAuth calls) at the attacker's `origin` — a host that never claimed to be anything more than a git remote, but is now driving Desktop's enterprise sign-in flow because of a single spoofed header value.

The correct invariant, analogous to `preRelease()`'s use of `s.supplySource` for supply funds, would be to never let unauthenticated peer-supplied protocol data (`wwwauth[]` values) upgrade trust classification for a host; classification of "is this GitHub" should rely only on the hostname/API probe (`isGitHubHost`), never on a header the remote itself emits.

## Impact Explanation
An attacker who runs (or compromises) an arbitrary Git HTTP server that a victim adds as a remote (e.g., a coworker's fork, a "helpful" mirror, a CI proxy) can cause GitHub Desktop to:
- Route the credential prompt through the Enterprise sign-in path (which performs real network calls to the attacker's origin for endpoint validation/version probing and OAuth/PAT verification) instead of the generic-git-credential dialog. This can result in exfiltration of whatever the user submits as their PAT/OAuth secret to the attacker-controlled endpoint, and it also causes Desktop to make outbound API calls containing session data to the attacker's host under the belief it is a legitimate GHE server.

This directly matches the "unauthorized OAuth or account binding" and "credential/token exfiltration" categories in the scope, and the attacker primitive required (controlling a git remote/proxy response) is explicitly in-scope.

## Likelihood Explanation
Exploitation requires only that the victim add/clone from an attacker-controlled remote and that a credential prompt is triggered (e.g., the remote returns 401 with a crafted header on the first HTTPS request) — no admin rights, no local access, and no dependency on leaked credentials. The realm-string check is a simple substring match on unauthenticated header content, so spoofing it is trivial for anyone who controls the server.

## Recommendation
Remove trust in the `wwwauth[]` realm string entirely for classification purposes, or only use it as a weak hint that is always re-verified by `isGitHubHost(endpoint)` (an actual API probe) before ever routing the user into the GitHub/Enterprise sign-in flow. At minimum, never call `dispatcher.setSignInEndpoint(origin)` / `beginEnterpriseSignIn` for a host that hasn't been positively confirmed via `isGitHubHost`.

## Proof of Concept
1. Attacker stands up an HTTPS git server at `https://git.attacker.example/evil/repo.git` that, on any authentication challenge, returns `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this URL as a remote in GitHub Desktop (or clones it, or it's referenced as a submodule of a repo they clone) and triggers a fetch/pull requiring auth.
3. Git invokes the desktop credential helper; `getEndpointKind` sees the spoofed `wwwauth[]` header and returns `'enterprise'` [5](#0-4) .
4. Since no account exists for `https://git.attacker.example`, Desktop shows the "Sign in to GitHub Enterprise" dialog and calls `setSignInEndpoint('https://git.attacker.example')` [6](#0-5)  — driving Desktop's real enterprise-auth network calls at the attacker's server instead of showing a neutral generic-credential prompt.

*Note: I was unable to trace the full downstream Enterprise sign-in network flow (`beginEnterpriseSignIn`) in this pass due to iteration limits, so the exact data sent to the attacker's origin (e.g., whether a PAT is POSTed directly) is not fully confirmed from the indexed code and should be verified with a live Devin session against `app/src/lib/dispatcher.ts` / the enterprise sign-in store logic.*

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
