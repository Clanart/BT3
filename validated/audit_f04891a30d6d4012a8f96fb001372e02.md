### Title
Unchecked type assertion on attacker-controlled CosmWasm query response panics the `pointer` precompile's `AddCW20`/`AddCW721`/`AddCW1155` handlers - ([File: precompiles/pointer/pointer.go])

### Summary
The TensorFlow advisory describes a `CHECK`/assertion failure triggered by feeding an op a value that violates an implicit shape/type invariant the op author assumed would always hold. The sei-chain analog is the CW→ERC "pointer" precompile: it queries an arbitrary, caller-supplied CosmWasm contract and blindly asserts the JSON response fields are Go `string`s with unchecked type assertions such as `formattedRes["name"].(string)`. Any contract that returns a non-string (or missing) `name`/`symbol` field causes an unrecovered Go panic reachable from a plain EVM transaction.

### Finding Description
`AddCW20` (and the analogous `AddCW721`/`AddCW1155` handlers) in the `pointer` precompile call an attacker-chosen CosmWasm contract via `QuerySmart`/`QuerySmartSafe` with a fixed `{"token_info":{}}` query, then unmarshal the response into a generic `map[string]interface{}` and immediately do: [1](#0-0) 

```go
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
``` [2](#0-1) 

The `wasmdKeeper` (`QuerySmart`) calls into a CosmWasm contract deployed and controlled by the caller — the caller can deploy a minimal contract whose `token_info` handler returns `{"name":123,"symbol":null}` (or omits the fields entirely). `json.Unmarshal` succeeds (any valid JSON decodes into `interface{}`), but the field values are not Go `string` (they'd be `float64`, `nil`, a nested map, etc., or missing which yields `nil`). The subsequent `.( string)` type assertion then panics with `interface conversion: interface {} is nil, not string` (or `is float64, not string`).

This is exactly the CHECK_EQ bug class: an internal invariant ("`token_info` responses always have string `name`/`symbol`") is enforced with a hard runtime assertion instead of a graceful type check, and the invariant is trivially violatable by attacker-supplied contract logic — the caller fully controls both which contract is queried (any bech32 CW address) and, via contract deployment, that contract's `token_info` response shape.

Unlike the sibling JSON-precompile helpers (`extractAsBytes` etc.), which also perform "safe" type assertions but only on ABI-decoded arguments already validated by `p.Prepare`, here the asserted value originates from **external, untrusted contract state/execution output**, not from validated ABI input. There is no `recover()` around this code path in `AddCW20`/`Execute`, and the dynamic-gas precompile framework's `RunAndCalculateGas` is confirmed to intentionally *not* swallow non-gas panics — it re-panics them so they propagate up the call stack: [3](#0-2) 

### Impact Explanation
A caller reachable path is: unprivileged EVM user deploys/controls a CosmWasm contract, then calls the `pointer` precompile's `addCW20Pointer` (or CW721/CW1155 equivalents) targeting that contract. Because the panic propagates out of the EVM `Call`/precompile execution frame rather than being converted into a revert, it depends on where up the stack recovery happens:
- If caught by the outer `runTx`/DeliverTx recovery middleware, the transaction fails but the node continues — this is a lower-impact DoS limited to wasted resources for that transaction, not sufficient to meet this scan's required impact bar.
- If this precompile path is exercised somewhere that lacks that top-level recovery (e.g., certain RPC simulation/eth_call/eth_estimateGas code paths, or a path invoked during EndBlock/state-sync/pre-commit processing that isn't wrapped identically to normal DeliverTx), the panic can crash the process, matching the "crash of default-configuration RPC nodes" impact bar. I was not able to conclusively trace whether every reachable caller of `AddCW20`/`Execute` for this precompile is wrapped by a panic-recovering handler equivalent to the DeliverTx recovery middleware confirmed elsewhere in the codebase, so the most severe impact (validator halt / RPC node crash) is plausible but unconfirmed from the available index.

### Likelihood Explanation
High likelihood of triggering the panic itself: deploying a CosmWasm contract with a custom `token_info` query handler that emits non-string `name`/`symbol` fields is straightforward and requires no special privilege — only the ability to deploy a CW contract and call the `addCW20Pointer` precompile method, both of which are open to any user. The uncertain part is solely the blast radius (single tx failure vs. node crash), not the reachability of the panic.

### Recommendation
Replace the unchecked type assertions in every version of `AddCW20`/`AddCW721`/`AddCW1155` (`precompiles/pointer/pointer.go` and all `precompiles/pointer/legacy/v*/pointer.go` variants) with safe, two-value assertions (`name, ok := formattedRes["name"].(string)`) and return a normal error (e.g., `fmt.Errorf("token_info response missing string name/symbol")`) instead of panicking when the field is absent or of the wrong type. Additionally, verify (or add) a top-level `recover()`/error-conversion wrapper around every precompile invocation path (including RPC simulate/eth_call paths) so that any residual panic from untrusted external contract output is converted into a transaction revert rather than propagating to the node process.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` query handler returns JSON such as `{"name": 123, "symbol": null, "decimals": 6, "total_supply": "0"}` (non-string `name`, null `symbol`) instead of the standard CW20 `TokenInfoResponse`.
2. From any EVM account, call the `pointer` precompile (`0x...100b`) method `addCW20Pointer(cwAddress)` with the contract address from step 1.
3. Execution reaches `AddCW20`, `QuerySmart`/`QuerySmartSafe` succeeds and returns the crafted JSON, `json.Unmarshal` succeeds into `map[string]interface{}`, and `formattedRes["name"].(string)` panics with an unrecovered `interface conversion` runtime error, propagating out of the precompile `Execute`/`Run` call.

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
