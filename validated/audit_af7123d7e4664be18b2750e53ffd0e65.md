### Title
Legacy `pattern:` rules for `prompt`/`stop` events are silently dead code due to field-name mismatch, bypassing intended blocking - (File: `plugins/hookify/core/config_loader.py`)

### Summary
`Rule.from_dict` converts a legacy `pattern:` field into a `Condition` whose `field` is inferred from `event`, but for any event other than `bash`/`file` (i.e. `prompt`, `stop`, `all`) it hardcodes `field='content'`. `RuleEngine._extract_field` never resolves `'content'` for `Stop`/`UserPromptSubmit` events (it only recognizes `user_prompt`, `reason`, `transcript` for those), so the resulting condition's `field_value` is always `None` and `_check_condition` always returns `False`. This makes any legacy-style rule targeting `prompt` or `stop` events permanently non-matching, while the semantically equivalent explicit-`conditions` form (`field: user_prompt`) works correctly — a silent, exploitable divergence between legacy and explicit rule forms.

### Finding Description
`Rule.from_dict` at [1](#0-0)  builds the legacy condition:

```python
event = frontmatter.get('event', 'all')
if event == 'bash':
    field = 'command'
elif event == 'file':
    field = 'new_text'
else:
    field = 'content'
```

For `event: prompt` or `event: stop`, the field is set to `'content'`. This rule loads successfully (`load_rule_file` reports no error) and is enabled, giving operators/users the false impression that it is active and enforcing.

At evaluation time, `RuleEngine._extract_field` ( [2](#0-1) ) only special-cases `field == 'reason'`, `field == 'transcript'`, and `field == 'user_prompt'` for non-tool events, and falls through per-tool-name branches for `Bash`/`Write`/`Edit`/`MultiEdit`. There is no handling of `field == 'content'` for `Stop` or `UserPromptSubmit` hook events (tool_name is empty there), so `_extract_field` returns `None`. Back in `_check_condition` ( [3](#0-2) ):

```python
field_value = self._extract_field(condition.field, tool_name, tool_input, input_data)
if field_value is None:
    return False
```

A `None` field value always short-circuits to `False`, so the condition — and therefore the whole rule — can never match, regardless of the actual prompt/transcript/reason content. This affects both `/hookify`-generated rule files (whose documented "simple format" template in [4](#0-3)  uses `pattern:` for any event, including `prompt`/`stop`) and any repo-shipped `.claude/hookify.*.local.md` file using the same legacy shorthand.

By contrast, the exact same intended policy expressed with the "advanced"/explicit `conditions:` form (`field: user_prompt`, per README [5](#0-4) ) is correctly resolved by `_extract_field` and works as intended. This is precisely the legacy-vs-explicit semantic divergence the audit calls out: identical author intent, differing effective enforcement, with the weaker (silently disabled) path being the one the tooling itself generates by default for `pattern:`-style rules.

### Impact Explanation
Any `action: block` (or `warn`) rule authored with the legacy `pattern:` shorthand for `event: prompt` or `event: stop` is completely inert — it never blocks or warns, no matter what the user prompt, stop reason, or transcript contains. Since `/hookify` is documented to generate exactly this simple `pattern:` format by default, and repo-shipped `.claude/hookify.*.local.md` files commonly follow the same shorthand, this represents a silent security-control bypass: users and maintainers believe a blocking/review guardrail is active (file loads without warning, `enabled: true`), but it never actually fires for the `prompt`/`stop` event class, letting dangerous prompts or premature/incomplete stops proceed unchecked.

### Likelihood Explanation
No special privilege is required beyond normal repository/plugin content control: any attacker who can add or influence a `.claude/hookify.*.local.md` file (or induce `/hookify` to generate one using the documented default `pattern:` template for a `prompt`/`stop` rule) triggers this every time, deterministically, since the bug is unconditional field-name mismatch, not a race or edge case.

### Recommendation
In `Rule.from_dict`, map legacy `pattern:` fields correctly per event type — e.g. `field = 'user_prompt'` for `event == 'prompt'` and `field = 'reason'` (or another explicitly supported field) for `event == 'stop'` — matching exactly what `RuleEngine._extract_field` resolves for those events. Additionally, add a load-time or engine-time validation/warning when a condition's `field` cannot be resolved for a given event, so silently dead rules are surfaced instead of failing open.

### Proof of Concept
Unit test in `plugins/hookify/core` test suite:
```python
from hookify.core.config_loader import Rule
from hookify.core.rule_engine import RuleEngine

frontmatter = {
    "name": "block-dangerous-prompt",
    "enabled": True,
    "event": "prompt",
    "pattern": "delete all secrets",
    "action": "block",
}
rule = Rule.from_dict(frontmatter, "Blocked dangerous prompt")

engine = RuleEngine()
input_data = {
    "hook_event_name": "UserPromptSubmit",
    "user_prompt": "please delete all secrets now",
}

result = engine.evaluate_rules([rule], input_data)
assert result == {}  # BUG: rule never blocks despite matching pattern intent

# Equivalent explicit-condition rule works correctly:
frontmatter_explicit = {
    "name": "block-dangerous-prompt-explicit",
    "enabled": True,
    "event": "prompt",
    "action": "block",
    "conditions": [{"field": "user_prompt", "operator": "regex_match", "pattern": "delete all secrets"}],
}
rule2 = Rule.from_dict(frontmatter_explicit, "Blocked dangerous prompt")
result2 = engine.evaluate_rules([rule2], input_data)
assert result2.get("decision") == "block"  # Confirms explicit form works while legacy form silently fails
```

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```
