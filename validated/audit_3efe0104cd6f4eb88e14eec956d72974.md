### Title
Undelegate can burn delegator shares while returning zero tokens due to unchecked share/token rounding - (File: sei-cosmos/x/staking/keeper/delegation.go)

### Summary
`MsgUndelegate` (reachable directly, or via the EVM staking precompile `undelegate` function) reduces a delegator's shares and a validator's `DelegatorShares`/`Tokens` based on a computed share amount, but never checks whether the token amount ultimately returned to the delegator is non-zero. Because the share↔token conversion goes through two independent `Dec` divisions with truncation, a delegator can request the minimum non-zero unbonding amount (or a value near a validator's diluted exchange rate) and have `RemoveDelShares` truncate the returned token amount to zero, while the delegation/validator shares are permanently reduced. The zero-value unbonding entry is later silently dropped by `CompleteUnbonding` with no transfer and no error.

### Finding Description
`MsgUndelegate` computes the `sharesAmount` to remove via `ValidateUnbondAmount`, which calls `validator.SharesFromTokens(amt)` — an *exact* (non-truncating) `Quo` division: [1](#0-0) 

That share amount is passed to `Keeper.Undelegate` → `Keeper.Unbond`, which unconditionally subtracts the shares from the delegation and calls `RemoveValidatorTokensAndShares` → `RemoveDelShares`: [2](#0-1) 

`RemoveDelShares` computes the tokens to actually return via `TokensFromShares(delShares).TruncateInt()`, a *second*, independently-rounded conversion: [3](#0-2) 

Because `SharesFromTokens` and `TokensFromShares` each perform their own `Dec` rounding, the round-trip `TokensFromShares(SharesFromTokens(amt))` is not guaranteed to reproduce `amt`; for the minimum representable amount (`amt = 1usei`), or for a validator whose exchange rate has been diluted by slashing, the result can round down to `0`. `Unbond` returns this `amount` (possibly zero) with no zero-check: [4](#0-3) 

`Keeper.Undelegate` then unconditionally creates an `UnbondingDelegationEntry` with this (possibly zero) `returnAmount` and inserts it into the unbonding queue — again with no zero-check: [5](#0-4) 

`msgServer.Undelegate` likewise performs no validation on the returned completion regarding a zero payout: [6](#0-5) 

When the unbonding entry matures, `CompleteUnbonding` explicitly special-cases a zero balance: it removes the entry but skips the bank transfer entirely, returning success with no funds moved: [7](#0-6) 

Critically, the sibling code path `BeginRedelegation` *does* guard against this exact scenario by explicitly checking `returnAmount.IsZero()` and reverting with `ErrTinyRedelegationAmount`: [8](#0-7) 

No equivalent check exists in `Keeper.Undelegate`/`msgServer.Undelegate`. This asymmetry demonstrates the fix pattern already known to the codebase for one path but missing from the other — directly mirroring the external report's core defect: burn/withdraw of the "share" asset succeeds and reduces internal accounting, but the corresponding underlying asset transfer can silently resolve to zero without reverting.

This is reachable by any delegator via a plain `MsgUndelegate` transaction, and equivalently through the public EVM staking precompile's `undelegate(validator, amount)` function: [9](#0-8) 

### Impact Explanation
A delegator who submits an `Undelegate` request for an amount that rounds to zero tokens after the two independent share/token conversions permanently loses the corresponding delegation shares (and thus staked value) without receiving any tokens in return — this is a genuine "successful redeem may not pay assets in exchange" fund-loss scenario, matching the external report's bug class. It is most reliably triggered against validators whose exchange rate (`Tokens`/`DelegatorShares`) has been diluted below 1 by prior slashing, where even normal-looking `amt` values can truncate to a zero return, or trivially at the minimum unit (`amt = 1usei`).

### Likelihood Explanation
Any unprivileged account with an existing delegation can trigger this by choosing a sufficiently small `amt` relative to the validator's current exchange rate — no special privileges, precompile access, or malicious-peer/validator behavior is required. The trigger condition (rounding a sub-unit token amount to zero across two `Dec` conversions) is a straightforward, deterministic arithmetic edge case, not a probabilistic or hard-to-reach state, especially for validators that have experienced any slashing event (a common, expected occurrence on any live chain).

### Recommendation
Add the same zero-return-amount guard that already exists in `BeginRedelegation` to the plain `Undelegate`/`Unbond` path: after computing `returnAmount` in `Keeper.Unbond` (or immediately in `Keeper.Undelegate`), reject the transaction (e.g., with an `ErrTinyUndelegationAmount`-style error) if `returnAmount.IsZero()`, before any shares are subtracted from the delegation or validator.

### Proof of Concept
1. Delegate to a validator, then cause (or wait for) a slashing event so that `validator.Tokens / validator.DelegatorShares < 1` (exchange rate diluted below par).
2. Submit `MsgUndelegate` (directly, or via the EVM staking precompile `undelegate` function) with `Amount = 1usei` (or another small `amt` chosen so the round-trip `TokensFromShares(SharesFromTokens(amt)).TruncateInt()` evaluates to `0`).
3. Observe that:
   - `ValidateUnbondAmount` returns a positive `shares` value and the transaction succeeds.
   - `Keeper.Unbond` reduces the delegator's `Shares` and the validator's `DelegatorShares`/`Tokens` by the computed share amount.
   - The `UnbondingDelegationEntry` created has `Balance = 0` (verifiable via `GetUnbondingDelegation`).
4. After the unbonding period elapses, `EndBlocker` triggers `CompleteUnbonding`, which removes the entry without any `UndelegateCoinsFromModuleToAccount` call (see the `if !entry.Balance.IsZero()` guard) — the delegator's account balance is unchanged, i.e., the delegator has permanently lost the staked value backing the burned shares.

// RemoveDelShares removes delegator shares from a validator.
// NOTE: because token fractions are left in the valiadator,
//
//	the exchange rate of future shares of this validator can increase.
func (v Validator) RemoveDelShares(delShares sdk.Dec) (Validator, sdk.Int) {
	remainingShares := v.DelegatorShares.Sub(delShares)

	var issuedTokens sdk.Int
	if remainingShares.IsZero() {
		// last delegation share gets any trimmings
		issuedTokens = v.Tokens
		v.Tokens = sdk.ZeroInt()
	} else {
		// leave excess tokens in the validator
		// however fully use all the delegator shares
		issuedTokens = v.TokensFromShares(delShares).TruncateInt()
		v.Tokens = v.Tokens.Sub(issuedTokens)

		if v.Tokens.IsNegative() {
			panic("attempting to remove more tokens than available in validator")
		}
	}

	v.DelegatorShares = remainingShares

	return v, issuedTokens
}

// Undelegate unbonds an amount of delegator shares from a given validator. It
// will verify that the unbonding entries between the delegator and validator
// are not exceeded and unbond the staked tokens (based on shares) by creating
// an unbonding object and inserting it into the unbonding queue which will be
// processed during the staking EndBlocker.
func (k Keeper) Undelegate(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, sharesAmount sdk.Dec,
) (time.Time, error) {
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return time.Time{}, types.ErrNoDelegatorForAddress
	}

	if k.HasMaxUnbondingDelegationEntries(ctx, delAddr, valAddr) {
		return time.Time{}, types.ErrMaxUnbondingDelegationEntries
	}

	returnAmount, err := k.Unbond(ctx, delAddr, valAddr, sharesAmount)
	if err != nil {
		return time.Time{}, err
	}

	// transfer the validator tokens to the not bonded pool
	if validator.IsBonded() {
		k.bondedTokensToNotBonded(ctx, returnAmount)
	}

	completionTime := ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))
	ubd := k.SetUnbondingDelegationEntry(ctx, delAddr, valAddr, ctx.BlockHeight(), completionTime, returnAmount)
	k.InsertUBDQueue(ctx, ubd, completionTime)

	return completionTime, nil
}

// Undelegate defines a method for performing an undelegation from a delegate and a validator
func (k msgServer) Undelegate(goCtx context.Context, msg *types.MsgUndelegate) (*types.MsgUndelegateResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	addr, err := sdk.ValAddressFromBech32(msg.ValidatorAddress)
	if err != nil {
		return nil, err
	}
	delegatorAddress, err := sdk.AccAddressFromBech32(msg.DelegatorAddress)
	if err != nil {
		return nil, err
	}
	shares, err := k.ValidateUnbondAmount(
		ctx, delegatorAddress, addr, msg.Amount.Amount,
	)
	if err != nil {
		return nil, err
	}

	bondDenom := k.BondDenom(ctx)
	if msg.Amount.Denom != bondDenom {
		return nil, sdkerrors.Wrapf(
			sdkerrors.ErrInvalidRequest, "invalid coin denomination: got %s, expected %s", msg.Amount.Denom, bondDenom,
		)
	}

	completionTime, err := k.Keeper.Undelegate(ctx, delegatorAddress, addr, shares)
	if err != nil {
		return nil, err
	}

	if msg.Amount.Amount.IsInt64() {
		defer func() {
			stakingMetrics.undelegateTotal.Add(goCtx, 1)
			stakingMetrics.undelegateAmount.Record(goCtx, msg.Amount.Amount.Int64())
		}()
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.EventTypeUnbond,
			sdk.NewAttribute(types.AttributeKeyValidator, msg.ValidatorAddress),
			sdk.NewAttribute(sdk.AttributeKeyAmount, msg.Amount.String()),
			sdk.NewAttribute(types.AttributeKeyCompletionTime, completionTime.Format(time.RFC3339)),
		),
		sdk.NewEvent(
			sdk.EventTypeMessage,
			sdk.NewAttribute(sdk.AttributeKeyModule, types.AttributeValueCategory),
			sdk.NewAttribute(sdk.AttributeKeySender, msg.DelegatorAddress),
		),
	})

	return &types.MsgUndelegateResponse{
		CompletionTime: completionTime,
	}, nil
}
