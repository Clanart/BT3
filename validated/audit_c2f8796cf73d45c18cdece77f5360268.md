### Title
Missing lower-bound validation on governance-settable `Kip71GasTarget` causes divide-by-zero panic in base fee calculation - ([File: params/kip71_config.go], [File: kaiax/gov/param.go])

### Summary
The `governance.kip71.gastarget` parameter (`Kip71GasTarget`) is validated using `noopFormatChecker`, meaning it accepts any `uint64` value, including `0`. This value flows unchecked into `KIP71Config.NextMagmaBlockBaseFee`, which divides by `gasTarget` when the parent block's gas usage differs from the target. A `GasTarget` of `0` causes a division-by-zero panic every time `parentGasUsed != 0`, which is invoked during header validation on every single node processing every subsequent block.

### Finding Description
The governance parameter registry defines `Kip71GasTarget` with no bound checking: [1](#0-0) 

Compare this to `Kip71BaseFeeDenominator`, which explicitly rejects zero: [2](#0-1) 

`Kip71GasTarget` has no analogous protection. The `PartialParamSet.Add` path used when a governance vote is cast only calls the parameter's `Canonicalizer` and `FormatChecker`: [3](#0-2) 

The consistency check that runs when verifying a header's vote (`checkConsistency`) also performs no additional validation for `Kip71GasTarget` — it is grouped with parameters that "pass as long as it passes the format checks": [4](#0-3) 

Once a vote setting `GasTarget = 0` is ratified into governance history (via the standard `governance_vote` API / header vote mechanism), the resulting `ParamSet.GasTarget` is `0`, and is converted directly into a `KIP71Config`: [5](#0-4) 

`NextMagmaBlockBaseFee` uses `gasTarget` as a divisor without ever checking it for zero (unlike `BaseFeeDenominator`, which has an explicit zero-guard at line 71-76): [6](#0-5) 

If `gasTarget == 0` and `parentGasUsed > 0` (essentially guaranteed in any live network), execution enters the `parentGasUsed > gasTarget` branch and divides by `gasTarget` at line 102 (`y := x.Div(x, new(big.Int).SetUint64(gasTarget))`), causing a runtime panic. This function is called from block header validation on every full node for every block after Magma: [7](#0-6) 

and again in the tx pool's fork-transition logic: [8](#0-7) 

This is a direct analog to the referenced report's Item #1 (`_interestPer3Min` unchecked against `DIVISION_BASE`, leading to permanent division-by-zero/broken virtual price) — a governance/config-writable numeric parameter is not validated against the trivial edge case of zero before being used as a divisor in a core pricing computation.

### Impact Explanation
Once the malicious/careless `GasTarget = 0` vote is ratified at an epoch boundary, **every honest full node** computing the next block's base fee (in `ValidateHeader`, and in the tx pool's `reset`) will panic on divide-by-zero as soon as any block has non-zero gas usage relative to target. This is a full-network halt/crash triggered purely by a governance parameter change — no malicious node or peer message required, only a normal governance vote transaction/API call that is accepted because of the missing validation. This matches "acceptance of an invalid... parameter" leading to state divergence/chain halt across all nodes, which is explicitly in-scope under "governance parameters."

### Likelihood Explanation
Requires a single governance vote (`governance_vote` API, or a validator/governing-node header vote) setting `governance.kip71.gastarget` to `0`. In single-governance mode this requires the governing node's cooperation; under council/permissionless mode a validator (already an actor explicitly reachable under this scope) can cast this vote. Because no format check or consistency check rejects `0`, the vote is accepted and ratified normally through the existing governance pipeline with no additional privilege beyond normal voting rights.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects `0` (and any other degenerate values), mirroring the existing `Kip71BaseFeeDenominator` check:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, defensively guard `NextMagmaBlockBaseFee` against `gasTarget == 0` the same way it already guards `baseFeeDenominator == 0`.

### Proof of Concept
1. Governing node (or validator under council mode) submits `governance_vote("governance.kip71.gastarget", 0)`.
2. The vote passes `Canonicalizer`/`FormatChecker` (`noopFormatChecker` accepts any uint64) and `checkConsistency` (no-op for this key), and is ratified at the next epoch header.
3. Starting from the epoch block, `GetParamSet` returns `GasTarget = 0`.
4. On the very next block where `GasUsed > 0` (virtually every real block), `ValidateHeader` invokes `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee(...)`, which executes `x.Div(x, new(big.Int).SetUint64(0))` and panics.
5. All full nodes validating that block panic simultaneously, halting the chain.

		return err
	}

		return ErrInvalidParamValue
