### Title
Trust-directory action for unsafe repositories is permanently applied per path with no revoke mechanism, allowing later re-use of a "trusted" path to bypass Git's ownership safety check - (File: `app/src/lib/git/config.ts`)

### Summary
The report's underlying bug class is a one-way "forbid"/"allow" flag that, once set, cannot be reversed by the owner even though circumstances change, leading to broken invariants later. GitHub Desktop has a structurally analogous, irreversible one-way grant: `addSafeDirectory()` permanently appends a path to the global `safe.directory` Git config the first time a user clicks "Trust Repository," and there is no corresponding "untrust"/remove function anywhere in the app.

### Finding Description
When Desktop detects a repository directory owned by a different user than the current OS user (Git's `dubious ownership` / `safe.directory` protection), it shows a warning in `MissingRepository`/`AddExistingRepository` explaining that "Adding untrusted repositories may automatically execute files in the repository," and offers a one-time "Trust Repository" action: [1](#0-0) 

Clicking it calls `addSafeDirectory(path)`, which appends the path to the global `safe.directory` multi-value config: [2](#0-1) 

using `addGlobalConfigValueIfMissing`, an append-only, idempotent operation with no corresponding removal counterpart in the codebase (a repo-wide search for "removeSafeDirectory"/"untrust" shows no such function exists). Once a path is trusted, Git and Desktop will never re-check ownership for that exact path string again — the invariant "only execute repo config/hooks for directories the user has vetted at the time of trust" is permanently broken for that path, regardless of what content later occupies it.

This mirrors the reported bug class precisely: like `forbidCreditManagerToBorrow()`/`forbidCreditManagerToRepay()`, which set an irreversible boolean with no path back, `addSafeDirectory()` sets an irreversible allow-list entry with no path back. The original report's harm was "can no longer repay debt"; the Desktop analog's harm is "can no longer regain Git's ownership-based protection for that path," which is a real security control, not just app state.

### Impact Explanation
`safe.directory` is Git's core defense against local privilege/trust confusion: a directory owned by another user can contain a `.git/config` with `core.fsmonitor`, hooks, or other executables that Git will run automatically. Because the trust grant is permanent and keyed only by filesystem path (not by content hash, owner SID, or timestamp), any future content placed at that same path — e.g. a synced folder, mapped network drive, container mount, or removable/shared storage location that gets reused — inherits the trust without the user ever being warned again. An attacker who can write to (or cause Desktop to point at) a previously-trusted path can plant a malicious `.git/config`/hooks and have them silently trusted and potentially executed the next time Desktop or Git operates on that directory, without any prompt. This satisfies the "silent corruption / code execution via attacker-controlled repository content, without further user action" bar in the scope, because the second occurrence requires no re-approval.

### Likelihood Explanation
Likelihood is moderate: exploitation requires that a previously "trusted" path be reachable again by attacker-influenced content — most plausibly shared/synced directories (cloud sync folders, VMs/containers reusing mount points, multi-user machines, removable media reusing a drive letter/mount path) which are realistic but not universal setups. It does not require admin rights, physical access, or leaked credentials — only that the same path string is trusted once and later repopulated by different, attacker-influenced content, which is the normal, expected behavior of shared-storage/dev environments.

### Recommendation
- Provide a way to revoke trust for a directory (remove the specific value from `safe.directory` when the user removes/relocates a repository, or via an explicit "Untrust" action), mirroring how the original report recommended a toggle instead of a one-way "forbid."
- Consider re-validating trust based on additional binding beyond the bare path (e.g., re-prompt if the repository's initial-commit hash, remote URL, or owner SID changes for a previously trusted path).
- At minimum, surface to the user (e.g., in Repository Settings) which paths are currently marked safe and allow removing entries.

### Proof of Concept
1. On a multi-user machine (or a machine using a shared/synced folder), place a Git repository owned by a different OS user at path `P`.
2. Open Desktop, attempt to add/open `P`; Desktop shows the "potentially unsafe" warning and a "Trust Repository" button (`app/src/ui/missing-repository.tsx` / `app/src/ui/add-repository/add-existing-repository.tsx`).
3. Click "Trust Repository" → `addSafeDirectory(P)` permanently writes `P` into the global `safe.directory` config.
4. Later, the directory at path `P` is deleted/unmounted and replaced (e.g., a new sync, a different USB drive mounted at the same path, container remount) with attacker-controlled Git content, including a malicious `.git/config`/hooks.
5. Desktop/Git operate on `P` again. Because `P` is already present in `safe.directory`, no ownership warning is shown and no re-trust prompt occurs — the attacker-supplied config/hooks are treated as trusted, even though the user never reviewed this new content.

Note: I was not able to find any UI or store code that removes an entry once added, and the index may not contain every reference (e.g., any hidden/removed feature); if such a revoke path exists elsewhere in the codebase, it was not surfaced by the available search tools.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
