### Title
Git "unsafe repository" trust flow can silently grant a global `safe.directory` bypass instead of a scoped exception - (File: `app/src/lib/git/config.ts`, `app/src/lib/git/rev-parse.ts`)

### Summary
The Enso report describes an admin function (`setDelay`) that lets a privileged actor covertly reduce the scope of a protection meant to give users an inspection window before an unsafe action takes effect. The GitHub Desktop analog is the "dubious ownership" / untrusted-repository trust flow: the app extracts a directory path from Git's own stderr message and writes it verbatim into the user's **global** `safe.directory` git config when the user clicks "Trust Repository." Because the extracted string is never validated against the path the user actually asked to trust, and because Git treats the literal value `*` for `safe.directory` as "trust every repository on this machine," a directory that is reported (or crafted) as `*` causes the "trust this one folder" action to silently become "disable ownership protection for all repositories forever."

### Finding Description
`getRepositoryType` runs `git rev-parse` and, on failure, extracts the unsafe path purely via regex against `stderr`: [1](#0-0) 

That value is stored as `repositoryUnsafePath`/`unsafePath` and shown to the user as "the directory you're about to trust": [2](#0-1) [3](#0-2) 

When the user clicks "Trust Repository," that exact string is written into the **global** Git config via `addSafeDirectory`, with no whitelist/format check other than a Windows UNC-prefix tweak: [4](#0-3) 

`addSafeDirectory` calls `addGlobalConfigValueIfMissing('safe.directory', path)`, which runs `git config --global --add safe.directory <path>`: [5](#0-4) 

Git treats `safe.directory = *` as a special sentinel meaning "trust every directory regardless of ownership," disabling the dubious-ownership protection machine-wide. Nothing in this code path rejects `*` (or other Git-special values) before it is persisted to the global config, and nothing confirms the extracted path matches the specific directory the user was shown/consented to. The UI presents this as a narrow, single-directory exception ("If you trust the owner of the directory you can add an exception for this directory"), but the actual guard being written is scoped by whatever string comes out of Git's stderr parsing — not by the app.

The user-facing intent (a scoped, per-repository grace/inspection mechanism, conceptually parallel to the timelock in the report) is silently converted into a global disablement, exactly the "delay/guard degraded without the user's informed consent" pattern in the seed report — except here the actor eroding the guard is the app's own trust flow acting on unvalidated external input rather than an on-chain admin.

### Impact Explanation
If the value trusted ends up being `*` (e.g., a repository folder literally named `*` — trivially achievable by an attacker publishing/naming a repository `*` that a victim clones or receives, or via any directory-naming edge case that causes Git to echo `*` in its dubious-ownership message), clicking "Trust Repository" for that single occurrence disables ownership verification for **every** Git repository the user ever opens with Desktop or the Git CLI afterward. This is a silent, machine-wide downgrade of a security control the user believed was being granted narrowly, enabling the classic "dubious ownership" attack (arbitrary hook/config execution from any subsequently opened untrusted repository) against a scope far larger than the user consented to.

### Likelihood Explanation
The trust flow is triggered any time Desktop encounters a "dubious ownership" repository — a state reachable purely by opening/cloning a repository on shared drives, extracted archives, or synced folders where ownership metadata differs, which is a normal, unprivileged occurrence for many users (already documented in the changelog as a supported/expected flow, e.g., "Surface Git's warning about unsafe directories"). No admin rights or local malware are required; the attacker only needs to influence the directory name/path that ends up being reported by Git, which is plausible via a repository name (`*`) that becomes the clone target directory.

### Recommendation
Before calling `addSafeDirectory`, validate that the extracted path is a real, absolute filesystem path equal to (or a resolved form of) the directory the user was actually shown, and explicitly reject/normalize any value equal to Git's wildcard sentinel `*` (and other non-path special forms) so the trust exception can never be widened beyond the single directory the user consented to.

### Proof of Concept
1. An attacker creates/names a Git repository (or a folder a victim will clone into) such that the resulting local directory is `*`.
2. The victim opens/clones this directory in GitHub Desktop; ownership differs from the current user (e.g., copied from a shared drive/archive), so `git rev-parse` fails with `fatal: detected dubious ownership in repository at '*'`.
3. `getRepositoryType` regex-extracts `path = '*'` [6](#0-5) , and the UI shows "The Git repository ... appears to be owned by another user ... add an exception for this directory" [7](#0-6) .
4. The victim clicks "Trust Repository," triggering `addSafeDirectory('*')` [2](#0-1)  → `git config --global --add safe.directory *` [8](#0-7) .
5. From this point on, Git's dubious-ownership protection is disabled for every repository on the victim's machine, not just the one directory they intended to trust.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
```
