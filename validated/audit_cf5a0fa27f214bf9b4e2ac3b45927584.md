### Title
`Scanner::scan_block` returns immature coinbase outputs as spendable `ReceivedOutput`s - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class in the external report is a state guard (`whenNotPaused`) applied to all sibling functions that move value, but omitted on one path — letting funds move under a condition the protocol intended to forbid. In `bitcoin-serai`, `Scanner::scan_transaction` correctly produces spendable outputs for ordinary transactions, but `Scanner::scan_block` blindly extends the results with the block's coinbase transaction (`block.txdata[0]`), whose outputs are consensus-immature for 100 blocks. The returned `ReceivedOutput`s are indistinguishable from spendable ones and flow directly into `SignableTransaction::new`, which builds spends for them without any maturity check.

### Finding Description
`Scanner::scan_block` at `networks/bitcoin/src/wallet/mod.rs:221-227` iterates `block.txdata` in full and calls `scan_transaction` on every transaction, including the coinbase:

```rust
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
        res.extend(self.scan_transaction(tx));
    }
    res
}
```

`scan_transaction` (`mod.rs:199-214`) has no notion of coinbase maturity — it only matches `output.script_pubkey` against registered scripts. The resulting `ReceivedOutput` (`mod.rs:89-97`) carries only `offset`, `output`, and `outpoint`; there is no flag or field that would let a downstream consumer distinguish an immature coinbase output from a spendable one. The doc comment on `scan_block` acknowledges the issue ("a post-processing pass is needed") but offers no API to perform it — since `ReceivedOutput` doesn't record which transaction (or its index) it came from, a caller cannot even reconstruct which returned outputs were coinbase-derived without re-scanning `block.txdata[0]` itself.

`SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:150-256`) then consumes `Vec<ReceivedOutput>` and builds `TxIn`s for each input unconditionally; `TransactionSignMachine::sign` (`send.rs:373-397`) produces valid BIP-340 signatures over them. The resulting transaction is fully well-formed and properly signed, yet any node will reject it under the `bad-txns-premature-spend-of-coinbase` consensus rule until 100 confirmations pass.

### Impact Explanation
Funds reported received that are not spendable: a `ReceivedOutput` produced by `scan_block` for a coinbase payout to a Serai key is indistinguishable from a spendable deposit. Any pipeline feeding `scan_block` results into `SignableTransaction::new` will generate and threshold-sign a transaction that cannot be relayed or confirmed for 100 blocks. Depending on the consumer, this means falsely crediting deposits that cannot be moved, or constructing batches that are guaranteed-invalid at broadcast, forcing re-selection of inputs and re-running the FROST signing protocol.

### Likelihood Explanation
Reachability requires a coinbase transaction paying to a Serai-registered script, which only a miner can produce — so an unprivileged party cannot trigger this at will. However, miners do send coinbase payouts to arbitrary addresses (e.g., pool payouts, or a deliberate dusting attack by a mining pool operator to poison the scanner's output set), and reorgs/scanning of historical blocks make `scan_block` the natural API for block ingestion. The guard omission is unconditional: every coinbase output matching a registered script is returned as spendable, every time.

### Recommendation
Have `scan_block` skip `block.txdata[0]` (or return coinbase-derived outputs in a separately tagged structure so callers can enforce the 100-block maturity rule). Alternatively, add a `coinbase: bool` field to `ReceivedOutput` and reject such inputs in `SignableTransaction::new`, mirroring the report's fix of applying the missing guard to the unguarded path.

### Proof of Concept

// networks/bitcoin/tests/wallet.rs style scenario

let outputs = scanner.scan_block(&block);

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
