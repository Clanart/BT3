### Title
Ed448 point decoding accepts torsion points, enabling forged Schnorr signatures - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary
`Point::is_torsion_free` is tautological and therefore accepts every valid Ed448 curve point, including non-identity low-order points. `Ed448::read_G` consequently exposes inputs as `PrimeGroup` members even when they are outside the prime-order subgroup. An attacker can submit the order-two public key encoding and a crafted Schnorr signature which verifies whenever the challenge is odd.

### Finding Description
`Point::is_torsion_free` computes `(*self * -1) + self`, which is always the identity for every group element, including torsion components. `GroupEncoding::from_bytes` then treats this check as proving prime-subgroup membership. [1](#0-0) 

For the order-two point `A = (0, -1)`, `A + A` is the identity. The generic Schnorr equation accepts `(R, s) = (A, 0)` whenever `c` is odd because:

```text
R + cA - sG = A + A - 0 = identity
```

The verification formula performs no cofactor clearing or subgroup rejection. [2](#0-1) 

`Ciphersuite::read_G` accepts canonical points returned by `from_bytes`, while FROST's stricter `Curve::read_G` only rejects the identity and therefore still accepts order-two Ed448 points. [3](#0-2) [4](#0-3) 

### Impact Explanation
An attacker can forge a Schnorr signature for a malformed public key accepted by the decoder. Wherever an Ed448 public key, proof point, commitment, or nonce commitment is deserialized from attacker-controlled bytes, protocol code can incorrectly treat a low-order point as a prime-order point. The deterministic identity-key case is also accepted by the raw group decoder: `(A, R, s) = (identity, identity, 0)` satisfies the equation for every challenge.

For the order-two key, the attacker selects a message whose Ed448 challenge is odd. Since the challenge is effectively uniform, approximately half of candidate messages qualify. This produces a forged proof-of-key/signature for a public key which has no discrete logarithm in the advertised prime-order group.

### Likelihood Explanation
The malformed input is a single canonical 57-byte Ed448 encoding and requires no private state, collusion, leaked key, malformed curve implementation, or unsafe code. The only requirement is that an application accepts an Ed448 public point from untrusted bytes and does not separately reject non-prime-subgroup points.

### Recommendation
Implement a real prime-subgroup membership check in `Point::is_torsion_free`: multiply the candidate by the Ed448 prime subgroup order and require the result to be the identity. Because the cofactor is four and the subgroup order is odd, multiplication by the subgroup order preserves any nonzero torsion component and therefore rejects it.

Additionally:

- Reject identity and torsion public keys at protocol boundaries.
- Reject identity and torsion points in Schnorr public keys and nonces where they are semantically invalid.
- Add deserialization tests for the Ed448 order-two and order-four encodings, including negative-zero encodings.
- Add a negative Schnorr verification test for `(R, s) = (A, 0)` with an odd challenge.

### Proof of Concept
The order-two point is the RFC8032 encoding of `(0, -1)`:

```rust
use ciphersuite::{Ciphersuite, group::ff::Field};
use frost::curve::ed448::{Ed448, IetfEd448Hram};
use frost::algorithm::Hram;
use schnorr::SchnorrSignature;

// Canonical Ed448 encoding of y = -1 with sign bit 0:
// p - 1 in the 56-byte coordinate field, followed by the sign byte.
let mut encoded_a = [0u8; 57];
encoded_a[0] = 0xfe;
encoded_a[1 .. 28].fill(0xff);
encoded_a[28] = 0xfe;
encoded_a[29 .. 56].fill(0xff);

// This should fail because A is order-two, but it succeeds because
// Point::is_torsion_free always returns true.
let A = Ed448::read_G(&mut encoded_a.as_slice()).unwrap();

// Signature (R, s) = (A, 0).
let signature = SchnorrSignature::<Ed448> {
  R: A,
  s: <Ed448 as Ciphersuite>::F::ZERO,
};

// A direct call with challenge 1 verifies immediately.
assert!(signature.verify(A, <Ed448 as Ciphersuite>::F::ONE));

// With the real Ed448 HRAM, grind messages until the challenge is odd.
for counter in 0u64 .. {
  let msg = counter.to_le_bytes();
  let challenge = IetfEd448Hram::hram(&A, &A, &msg);
  if bool::from(challenge.is_odd()) {
    assert!(signature.verify(A, challenge));
    break;
  }
}
```
