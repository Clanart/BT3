Audit Report

## Title
Staked-connection pruning is triggered and committed unconditionally before the per-peer capacity check, allowing a maxed-out staked peer to repeatedly evict unrelated legitimate staked connections without ever occupying a slot itself - (File: `streamer/src/nonblocking/simple_qos.rs`)

## Summary
In `SimpleQos::try_add_connection`, the decision to run `prune_random` and commit an eviction is gated solely on the global staked-table size (`connection_table_l.total_size >= self.config.max_staked_connections`), independent of whether the connecting peer's own per-`(ip, pubkey)` bucket has capacity. Because `cache_new_connection` → `ConnectionTable::try_add_connection` performs a separate, uncoordinated per-key capacity check with no rollback path, a peer that has already saturated its own bucket can repeatedly trigger evictions of unrelated legitimate staked connections while its own connection attempts are always rejected.

## Finding Description
The relevant code confirms the claim exactly. In `try_add_connection` at `streamer/src/nonblocking/simple_qos.rs`, lines 314–327, when `connection_table_l.total_size >= self.config.max_staked_connections`, `prune_random(PRUNE_RANDOM_SAMPLE_SIZE, stake)` is called and its result is unconditionally added to `stats.num_evictions_staked` before any admission attempt occurs. [1](#0-0) 

`prune_random` (in `streamer/src/nonblocking/quic.rs`, lines 986–1006) samples a small set of existing connections, evicts the lowest-staked one below `threshold_stake`, and decrements `total_size` — this commit happens with no knowledge of, or connection to, the incoming peer's own admissibility. [2](#0-1) 

Only afterward, if `connection_table_l.total_size < self.config.max_staked_connections`, does the code call `cache_new_connection` (lines 329-336), which invokes `ConnectionTable::try_add_connection` keyed by `ConnectionTableKey::new(remote_addr.ip(), conn_context.remote_pubkey)` — a per-peer key entirely distinct from the aggregate `total_size` check that gated the prune. [3](#0-2) 

Inside `ConnectionTable::try_add_connection`, admission is gated by `has_connection_capacity`, computed from `connection_entry.len() + 1 <= max_connections_per_peer` for that specific key — independent of the global size used to trigger the prune. If the peer already holds `max_connections_per_peer` live connections under its key, this returns `None`/closes the connection with `CONNECTION_CLOSE_CODE_TOO_MANY`, and there is no code path that reverts the eviction already committed by `prune_random`. [4](#0-3) 

The existing guard — the `total_size < max_staked_connections` recheck at line 329 — only prevents attempting admission when there's still no room globally; it does nothing to prevent or roll back the eviction that already occurred, and it does not check the attacker's own per-key capacity at all. The identical decoupled pattern exists in `SwQos::try_add_connection`'s staked branch in `streamer/src/nonblocking/swqos.rs`, lines 355-366. [5](#0-4) 

## Impact Explanation
This is a QUIC/TPU non-RPC remote degradation vector against other validators' connections. A staked peer that has saturated its own per-key connection bucket can, at zero additional benefit to itself, repeatedly trigger `prune_random` evictions of unrelated legitimate staked peers' TPU/QUIC connections whenever the staked table is at capacity, forcing those victims to reconnect. This corrupts the resource-allocation invariant of the staked connection table — total connection slots are consumed by churn/eviction rather than legitimate admission — and matches the "non-RPC remote exhaustion/degradation" impact category for QUIC/TPU.

## Likelihood Explanation
The attacker only needs: (1) some non-negligible stake exceeding at least one other connected peer's stake (since `prune_random` filters on `stake < threshold_stake`), and (2) the ability to hold `max_connections_per_peer` connections open under its own identity while sending additional connection attempts. Both are trivial for any staked validator operator using standard QUIC connections to the TPU — no privileged access, key compromise, or validator collusion is required, and the input (a QUIC connection attempt with a valid staked identity) is a normal public input to the listener.

## Recommendation
Unify or reorder the eviction and admission decisions so `prune_random` is only invoked/committed when it would actually enable the connecting peer's own admission — e.g., check `has_connection_capacity` for the connecting peer's key before pruning, or roll back/skip counting the eviction in `num_evictions_staked` if the subsequent `cache_new_connection` call fails in `streamer/src/nonblocking/simple_qos.rs` and equivalently in `streamer/src/nonblocking/swqos.rs`.

## Proof of Concept
1. Build a `ConnectionTable::new(ConnectionTableType::Staked, ...)` and fill it to `max_staked_connections` with distinct legitimate staked peers via `try_add_connection`, as in the existing `test_prune_table_random` test in `streamer/src/nonblocking/quic.rs` (lines 1894-1937). [6](#0-5) 
2. Pre-fill one attacker `ConnectionTableKey` to `max_connections_per_peer`.
3. Call `SimpleQos::try_add_connection` for the attacker's staked identity while the staked table is at `max_staked_connections`.
4. Assert `stats.num_evictions_staked` increased, a legitimate unrelated staked connection was removed, the call returned `None`, and `stats.connection_add_failed` incremented — confirming the attacker caused a victim eviction without gaining a slot.

    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    pub(crate) fn try_add_connection<F: FnOnce() -> Arc<S>>(
        &mut self,
        key: ConnectionTableKey,
        port: u16,
        client_connection_tracker: ClientConnectionTracker,
        connection: Option<Connection>,
        peer_type: ConnectionPeerType,
        last_update: Arc<AtomicU64>,
        max_connections_per_peer: usize,
        stream_counter_factory: F,
    ) -> Option<(Arc<AtomicU64>, CancellationToken, Arc<S>)> {
        let connection_entry = self.table.entry(key).or_default();
        let has_connection_capacity = connection_entry
            .len()
            .checked_add(1)
            .map(|c| c <= max_connections_per_peer)
            .unwrap_or(false);
        if has_connection_capacity {
            let cancel = self.cancel.child_token();
            let stream_counter = connection_entry
                .first()
                .map(|entry| entry.stream_counter.clone())
                .unwrap_or_else(stream_counter_factory);
            connection_entry.push(ConnectionEntry::new(
                cancel.clone(),
                peer_type,
                last_update.clone(),
                port,
                client_connection_tracker,
                connection,
                stream_counter.clone(),
            ));
            self.total_size += 1;
            Some((last_update, cancel, stream_counter))
        } else {
            if let Some(connection) = connection {
                connection.close(
                    CONNECTION_CLOSE_CODE_TOO_MANY.into(),
                    CONNECTION_CLOSE_REASON_TOO_MANY,
                );
            }
            None
        }
    }

    #[test]
    fn test_prune_table_random() {
        use std::net::Ipv4Addr;
        agave_logger::setup();
        let cancel = CancellationToken::new();
        let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);

        let num_entries = 5;
        let max_connections_per_peer = 10;
        let sockets: Vec<_> = (0..num_entries)
            .map(|i| SocketAddr::new(IpAddr::V4(Ipv4Addr::new(i, 0, 0, 0)), 0))
            .collect();
        let stats: Arc<StreamerStats> = Arc::new(StreamerStats::default());

        for (i, socket) in sockets.iter().enumerate() {
            table
                .try_add_connection(
                    ConnectionTableKey::IP(socket.ip()),
                    socket.port(),
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Staked((i + 1) as u64),
                    Arc::new(AtomicU64::new(i as u64)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {}),
                )
                .unwrap();
        }

        // Try pruninng with threshold stake less than all the entries in the table
        // It should fail to prune (i.e. return 0 number of pruned entries)
        let pruned = table.prune_random(/*sample_size:*/ 2, /*threshold_stake:*/ 0);
        assert_eq!(pruned, 0);

        // Try pruninng with threshold stake higher than all the entries in the table
        // It should succeed to prune (i.e. return 1 number of pruned entries)
        let pruned = table.prune_random(
            2,                      // sample_size
            num_entries as u64 + 1, // threshold_stake
        );
        assert_eq!(pruned, 1);
        // We had 5 connections and pruned 1, we should have 4 left
        assert_eq!(stats.open_connections.load(Ordering::Relaxed), 4);
    }
