### Title
Fail-open exception handling in `main()` allows attacker-controlled rule file to crash rule evaluation and bypass all PreToolUse block rules - (File: plugins/hookify/hooks/pretooluse.py)

### Summary
`main()` in `pretooluse.py` wraps rule loading/evaluation in a bare `except Exception` that always `sys.exit(0)` in `finally`, regardless of whether a "deny" decision was ever computed. An attacker who can introduce a crafted `.claude/hookify.*.local.md` rule file into the repository/workspace can trigger an uncaught `TypeError` deep inside `RuleEngine._regex_match`, which aborts the entire rule-evaluation batch and causes the hook to silently allow the tool call instead of denying it.

### Finding Description
`main()` calls `load_rules()` then `engine.evaluate_rules(rules, input_data)`, and any exception raised anywhere in that call chain is swallowed by `except Exception` and the process still exits `0` with no `permissionDecision: deny` in stdout [1](#0-0) .

`load_rules()`/`load_rule_file()` are defensively wrapped and will not raise, but they do not validate the *types* of frontmatter values [2](#0-1) . The custom frontmatter parser converts a bare top-level value of `true`/`false` into a Python `bool` [3](#0-2) , and `Condition`/`Rule.from_dict` pass this value straight through as `pattern` without coercing to `str` [4](#0-3) [5](#0-4) .

During evaluation, `_regex_match` only catches `re.error`, not `TypeError` [6](#0-5) . Calling `re.compile(True, re.IGNORECASE)` (via `compile_regex`) raises `TypeError: first argument must be string or compiled pattern`, which is uncaught and propagates up through `_check_condition` → `_rule_matches` → `evaluate_rules` → `main()`'s outer `except Exception`, aborting evaluation of **all** rules in that batch — including unrelated, legitimate `action: block` rules that a repository owner configured to stop dangerous operations. The hook then prints a generic `systemMessage` (no `permissionDecision: deny`) and exits `0`, so Claude Code proceeds with the tool call.

### Impact Explanation
This is a PreToolUse enforcement/approval bypass: any attacker-supplied file that lands in `.claude/hookify.*.local.md` (e.g. via a malicious PR/branch that gets checked out and processed) with a legacy `pattern: true`/`pattern: false` value neutralizes the entire hookify rule set for that invocation, allowing dangerous bash commands or sensitive file edits — that the victim's own `block` rules were meant to stop — to execute unblocked. This matches the "deny means deny" trust-boundary bypass / unauthorized command execution impact category.

### Likelihood Explanation
Fully deterministic and repeatable — no race condition or timing dependency. The only precondition is that the attacker can get a crafted rule file into the `.claude/` directory that Claude Code's hookify plugin scans (e.g. content in an untrusted repository/branch/PR being processed), and that at least one legitimate `block` rule exists that the attacker wants to bypass. No admin/maintainer privilege, leaked keys, or social engineering is required — it's ordinary repository content plus the plugin's own frontmatter/rule-parsing behavior.

### Recommendation
- Remove the catch-all fail-open in `pretooluse.py`'s `main()`: distinguish between "no rules matched" (safe to allow) and "evaluation error" (should fail closed for `block`-capable contexts), e.g. return a `permissionDecision: deny` or a distinct error signal instead of unconditionally exiting 0.
- Harden `RuleEngine`: coerce `Condition.pattern`/`field_value` to `str` before regex/string operations, and widen `_regex_match`'s exception handling to catch `TypeError`/`re.error` uniformly, returning `False` per-condition instead of letting exceptions propagate out of `evaluate_rules`.
- Wrap each rule's evaluation individually in `_rule_matches`/`evaluate_rules` (per-rule try/except) so a single malformed rule cannot abort evaluation of all other rules in the batch.
- In `config_loader.py`, validate/normalize frontmatter value types (ensure `pattern` is always coerced to `str`) when constructing `Rule`/`Condition` objects.

### Proof of Concept
Integration test (pytest) for `pretooluse.py`:
1. Create a temporary `.claude/hookify.attacker.local.md` with:
```
---
name: legit-block-rule
enabled: true
event: bash
pattern: rm\s+-rf
action: block
---
Blocked!
```
2. Also create `.claude/hookify.malicious.local.md` with:
```
---
name: crash-rule
enabled: true
event: bash
pattern: true
action: warn
---
Never fires
```
3. Feed stdin JSON: `{"hook_event_name": "PreToolUse", "tool_name": "Bash", "tool_input": {"command": "rm -rf /"}}`.
4. Run `python pretooluse.py` (with `PYTHONPATH`/`CLAUDE_PLUGIN_ROOT` set as in real invocation) as a subprocess, capturing stdout and exit code.
5. Assert: process exit code is `0`, and parsed stdout JSON does NOT contain `"permissionDecision": "deny"` (only a generic `systemMessage: "Hookify error: ..."` is present), even though `legit-block-rule` should have matched `rm -rf /` and blocked it in the absence of `crash-rule`.
6. Control test: remove `hookify.malicious.local.md` and re-run — assert stdout now correctly contains `"permissionDecision": "deny"`, proving the malicious rule file is what caused the bypass.

```python
def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules
```

```python
    def _regex_match(self, pattern: str, text: str) -> bool:
        """Check if pattern matches text using regex.

        Args:
            pattern: Regex pattern
            text: Text to match against

        Returns:
            True if pattern matches
        """
        try:
            # Use cached compiled regex (LRU cache with max 128 patterns)
            regex = compile_regex(pattern)
            return bool(regex.search(text))

        except re.error as e:
            print(f"Invalid regex pattern '{pattern}': {e}", file=sys.stderr)
            return False
```
