### Title
Identity encryption key forces fixed ChaCha20 key/IV reuse, leaking all secret shares sent to a PedPoP participant - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
PedPoP encrypts each participant's secret share with a ChaCha20 stream cipher whose IV is hardcoded (`b"DKG IV v0.2\0"`), relying on the assumption that the derived key is single-use. The key is derived solely from the ECDH shared point `msg.key * recipient_enc_key` (sender side) / `enc_priv * msg.key` (recipient side). A participant can register an identity point as their encryption key via `EncryptionKeyMessage`, which is accepted without any identity/non-triviality check. Every share encrypted to that participant then uses the shared point `identity`, producing an identical, publicly computable cipher for all senders — allowing any observer to decrypt every share sent to that participant and recover threshold key shares.

### Finding Description
`cipher()` constructs ChaCha20 with a fixed IV and acknowledges this is only safe because "the key is single-use" (`encryption.rs` lines 120–126): [1](#0-0) 

The key is derived by hashing the ECDH shared point (`encryption.rs` lines 95–110): [2](#0-1) 

`encrypt` computes `ecdh(&key, to)` where `to` is the recipient's registered encryption key (`encryption.rs` lines 153–154, 466): [3](#0-2) [4](#0-3) 

`Encryption::register` stores `msg.enc_key` verbatim with no identity check, no proof of possession on the encryption key (the Schnorr PoK covers only `commitments[0]`), and no non-triviality validation: [5](#0-4) [6](#0-5) 

`C::read_G` accepts any canonically encoded point, including the identity (it only checks canonicality, not non-identity): [7](#0-6) 

Root cause: if `to = G::identity()`, then `ecdh = identity * key = identity` for every sender and every message, so `cipher(context, identity)` yields one fixed ChaCha20 key and the fixed IV for all shares addressed to that participant — a complete breakdown of the single-use-key assumption the static IV relies on.

### Impact Explanation
Every honest participant's encrypted `SecretShare` addressed to the malicious participant is XORed with the identical keystream. Since the shared point is `identity` — publicly derivable — any passive observer of the DKG traffic can compute `cipher(context, identity)` themselves and directly decrypt all `n - 1` shares sent to that participant. This is secret share / threshold key share recovery reachable purely from protocol messages, satisfying the "key share recovery" acceptance bar. It is the exact analog of the reported bug class: a hardcoded IV that is only safe under a key-freshness invariant that an unvalidated public input breaks.

### Likelihood Explanation
Any participant in the DKG can mount this by placing `G::identity()`'s canonical encoding in the `enc_key` field of their `EncryptionKeyMessage`. Nothing authenticates or validates `enc_key` — the round-1 verification (`verify_r1`) batch-verifies the Schnorr PoK against `commitments[0]`, not `enc_key`, so the malformed registration passes all checks. The attacker needs no private key for the identity point and no collusion; all other participants then deterministically encrypt their shares under the attacker-chosen degenerate key. The only cost to the attacker is their inability to receive valid shares — a cheap trade for compromising everyone's shares.

### Recommendation
Reject identity (and low-order/invalid-subgroup where applicable) points when registering `enc_key` in `Decryption::register` / `Encryption::register`, or require a proof of possession for `enc_key` in `EncryptionKeyMessage`. Additionally, mix a fresh random nonce into the ChaCha20 setup (or into the transcript challenge) instead of relying on a constant IV, so the cipher remains safe even if an ECDH collision occurs.

### Proof of Concept
1. Attacker `M` (participant index `m`) builds a `KeyGenMachine` normally but crafts its `EncryptionKeyMessage` with `enc_key = <C::G as Group>::identity()` (canonical encoding passes `read_G`).
2. All `n - 1` other participants call `generate_secret_shares`, each computing `ecdh = identity * random_key = identity`, then `cipher(context, identity)` — the same ChaCha20 state for every message to `M`.
3. Any observer (or `M`) computes `ChaCha20::new(key = transcript("DKG Encryption v0.2" | context | identity).challenge("key"), iv = "DKG IV v0.2\0")` and XORs the keystream against each ciphertext addressed to `M`, directly recovering every `SecretShare` byte-for-byte.
4. The recovered shares are valid evaluations of the senders' polynomials; combined with the public commitments they yield threshold key share material for the group key, breaking confidentiality of the DKG output.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
