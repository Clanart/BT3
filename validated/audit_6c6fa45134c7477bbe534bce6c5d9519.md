### Title
Aggregate Schnorr verification omits `Rs`/keys from weights, enabling forged aggregate signatures - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` derives each half-aggregation weight only from the caller-supplied per-signature challenges, then checks `sum(z_i * (R_i + c_i * A_i)) - s * G == 0` without binding `z_i` to `R_i`, `A_i`, or the aggregate `s`. [1](#0-0)  Because `SchnorrAggregate::read` accepts attacker-controlled `Rs` and `s` from bytes, an unprivileged caller can submit an aggregate that satisfies the verifier equation without any valid constituent Schnorr signatures. [2](#0-1) 

### Finding Description
The aggregation transcript appends only `challenge` values before producing each `weight`, so the weights are public and reproducible before `Rs`/`s` are chosen. [3](#0-2)  The verifier then queues `(z_i, R_i)` and `(z_i * c_i, A_i)` plus `(-s, G)`, requiring only that the weighted sum be identity. [4](#0-3)  For any nonempty `keys_and_challenges` with nonzero `c_j`, an attacker can choose arbitrary `R_i` for `i != j`, set `s = 0`, and solve `R_j = -c_j * A_j - z_j^-1 * sum_{i != j} z_i * (R_i + c_i * A_i)` using only public point arithmetic; the resulting aggregate passes `verify` despite no knowledge of the corresponding secret keys or valid `s_i`. [5](#0-4)  The single-signature case degenerates to `R = -c * A, s = 0`, which satisfies `z * (R + c * A) = 0` for any nonzero `z`. [4](#0-3) 

### Impact Explanation
A forged aggregate proof is accepted for statements it does not prove, violating the aggregate Schnorr soundness property and allowing public input bytes to `SchnorrAggregate::read`/`verify` to stand in for signatures that were never produced. [6](#0-5) [5](#0-4)  Any downstream logic that treats a passing aggregate as evidence that each listed public key signed its challenge can be convinced by data constructible entirely from public keys/challenges. [7](#0-6) 

### Likelihood Explanation
The attack needs only the public inputs already supplied to `verify`: the challenge list and public keys, because `weight` is deterministically derived from the challenges alone and `Rs`/`s` are attacker-selected fields. [8](#0-7) [3](#0-2)  There is no requirement to invert a discrete logarithm; the missing binding lets the attacker place the required linear-combination result directly into one `R_j`. [4](#0-3) 

### Recommendation
Bind every aggregate component into each weight transcript, including the ordered `Rs`, public keys, challenges, and the aggregate `s` commitment context, before deriving `z_i`; alternatively use a provably secure aggregation construction where per-signature weights are unpredictable until all signature components are fixed. [3](#0-2)  Reject identity/non-canonical `R` inputs during `SchnorrAggregate::read` where the ciphersuite permits such encodings, and add a regression test that the `R = -c * A, s = 0` forgery fails. [2](#0-1) [9](#0-8) 

### Proof of Concept
For `keys_and_challenges = [(A, c)]` with `c != 0`, deserialize `SchnorrAggregate { Rs: [-(c * A)], s: 0 }`; `verify` computes a nonzero weight `z` from `c` and checks `z * R + z * c * A - 0 * G = z * (-c * A) + z * c * A = identity`. [5](#0-4)  For `n > 1`, choose `s = 0`, arbitrary nonzero `R_i` for `i < n`, recompute each `z_i` from the public challenge sequence, and set `R_n = -c_n * A_n - z_n^-1 * Σ_{i<n} z_i * (R_i + c_i * A_i)`, which makes the final multiexp identity without producing any valid constituent signatures. [4](#0-3)

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res
}
