### Title
Stale AMM-price check in gasless swap admission allows front-running griefer to force `swapForGas` reverts and risks unrepaid gas loans - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The Kaia gasless module (KIP-247) admits `GaslessSwapTx` into the pool/bundle pipeline based on a point-in-time quote from the swap router's AMM state. Just like the Sherlock finding where `beforeWithdraw`'s protocol-liquidity check used mutable state that an unprivileged actor could shift via a front-run withdrawal to make `internalSeize`/`liquidate` revert, here `checkBalanceForSwap` validates `swapArgs.AmountIn` against `routerContract.GetAmountIn(nil, token, minAmountOut)` computed from the *current* AMM reserves at admission time [1](#0-0) . Because the actual `swapForGas()` execution happens later (at block-building/execution time), any unprivileged trader can submit an ordinary swap on the same token pair to shift the AMM reserves between admission and inclusion, causing the on-chain `swapForGas` call embedded in the gasless bundle to fail its own slippage/`minAmountOut` check at execution, even though the transaction passed pool admission.

### Finding Description
`GaslessModule.checkBalanceForSwap` is the pool's "ready"/admission gate for `GaslessSwapTx`, and it re-derives the required `amountIn` from the router's live quote: [2](#0-1) 

This check is only evaluated once, at the moment the transaction is being considered for promotion/bundling (`GetCheckBalance`) [3](#0-2) . The block-building flow then wraps the swap (plus an optional approve tx) together with a `LendTxGenerator` transaction that unconditionally transfers KAIA from the proposer to the user to cover gas, in a `builder.Bundle`: [4](#0-3) 

The lend amount and the required repay amount are purely deterministic (based on gas price/gas limit), independent of the swap's actual AMM output: [5](#0-4) 

But whether the swap can actually produce `minAmountOut` (and thus whether `swapForGas` succeeds on-chain) depends on the router's AMM reserves *at the time the bundle is finally executed*, not at the time `checkBalanceForSwap` ran. Any account (an ordinary, unprivileged trader/public-RPC caller) can submit transactions against the same swap pool to move the price between the pool's admission-time quote and the actual inclusion of the gasless bundle, causing the swap to revert for slippage at execution even though it looked valid at admission — directly mirroring the root cause pattern in the referenced report: a value/liquidity check computed from external mutable state that an unprivileged party can manipulate to invalidate a later, otherwise-valid protocol operation.

### Impact Explanation
This is reachable by any unprivileged public-RPC caller: an attacker just needs to trade against the pool used by the `GaslessSwapRouter` (identified via `getGaslessInfo`/`MultiCallGaslessInfo`) shortly before a gasless bundle is executed, or repeatedly, to grief targeted users' gasless transactions. The `swapForGas` contract call is expected to include its own slippage guard (comparing `minAmountOut`/`amountRepay` against realized swap output), so when the AMM price has moved unfavorably, the swap reverts on execution. Because the `LendTxGenerator` transaction that funds the user's gas is a plain, unconditional value transfer (no logic that can fail besides being out of gas) [6](#0-5) , if the bundle inclusion mechanism does not guarantee strict atomic all-or-nothing inclusion of the Lend/Approve/Swap set at the block-assembly level, the proposer's lent KAIA could be paid out while the compensating `swapForGas` repayment reverts — a direct unauthorized value transfer from the block proposer to the user. At minimum, this is a reliable, repeatable denial-of-service against gasless transaction settlement for the affected user/token pair, which is the core deliverable of the gasless module (time-sensitive, protocol-core functionality), analogous to the accepted Medium severity in the referenced report ("issue impacts the availability of time-sensitive functions").

### Likelihood Explanation
Likelihood is high: any address can submit ordinary swap transactions against the token/pool pair used by the whitelisted `GaslessSwapRouter` — no special privilege, staking, or governance access is required, and the cost is only the price impact/gas of an ordinary swap, similar to how the original report's attacker only needed ordinary deposit/withdraw calls. Given AMM slippage windows are typically tight for gasless UX (users need repayable, near-deterministic swap outputs), even modest reserve shifts caused by concurrent public trading (organically or adversarially triggered) can push the swap below `minAmountOut` between the pool's admission-time quote and actual on-chain execution.

### Recommendation
- Re-validate the AMM quote/slippage bound at the moment the bundle is assembled for the block (immediately before execution), not only at initial pool admission, and drop bundles whose swap would fail under the just-computed state.
- Ensure the `LendTxGenerator`/Lend transaction is only included in the final block atomically with a successful `swapForGas` execution (i.e., guarantee bundle-level all-or-nothing inclusion at the block-assembly and state-commit level, discarding the whole bundle including the lend transfer if the swap reverts) — verify and, if needed, enforce this invariant in the bundle-building/worker code path (`work/builder`), which was not fully inspected due to tool-call limits.
- Consider adding a minimum safety margin/deadline-based re-check or a router-level guard that refunds/no-ops the lend if the swap cannot be completed, to remove any possibility of a state where KAIA is lent to a user without a corresponding successful repayment.

### Proof of Concept
1. Attacker identifies the whitelisted `GaslessSwapRouter` and one of its allowed tokens via `getGaslessInfo`/`MultiCallGaslessInfo` (public state, readable by any RPC caller).
2. A victim submits `GaslessApproveTx` + `GaslessSwapTx` with `minAmountOut` computed against the current pool quote (validated by `checkBalanceForSwap`, which calls `routerContract.GetAmountIn(nil, token, minAmountOut)` against current state) [7](#0-6) .
3. Before the bundle (Lend + Approve + Swap) is assembled/executed in a block, the attacker submits an ordinary swap on the same token/pool pair, shifting the AMM reserves.
4. When the gasless bundle finally executes, `swapForGas` reverts on-chain because the realized output no longer satisfies `minAmountOut`/`amountRepay`, even though the transaction was accepted into the pool/bundle earlier.
5. Result: the victim's gasless transaction is denied service (repeatable at will by the attacker), and if the surrounding `LendTxGenerator` transfer is not strictly atomic with the reverted swap at the block-assembly layer (unverified in this pass), the proposer's lent KAIA is paid out without repayment.

**Note on confidence**: I was able to confirm the stale-quote admission check and the deterministic, unconditional nature of the `LendTxGenerator` transfer from the code, but I could not fully verify within the available tool budget whether the `work/builder` bundle mechanism guarantees strict atomic inclusion (all txs in a bundle succeed or none are included) at the block-assembly/state-commit level. If atomicity is guaranteed, the impact is limited to a reliable DoS of gasless settlement for targeted users/pools rather than direct fund loss; if not guaranteed, it constitutes direct value loss to the proposer. This should be verified against `work/builder` bundle-commit logic.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
