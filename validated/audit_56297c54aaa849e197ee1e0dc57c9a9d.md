## Title
Clone recursive operation explicitly disables Git's clone protection (`GIT_CLONE_PROTECTION_ACTIVE=false`), exposing users to malicious-submodule RCE/arbitrary file write - (File: `app/src/lib/git/clone.ts`)

### Summary
The `clone()` function in `app/src/lib/git/clone.ts` unconditionally sets the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to the string `'false'` while running `git clone --recursive` against a **fully attacker-controlled URL**. This mirrors the pattern in the seed report: a safety mechanism designed to guard against unsafe/attacker-supplied values is deliberately short-circuited by a hardcoded permissive constant, so the guard can never fire regardless of what the malicious remote returns. [1](#0-0) 

### Finding Description
`clone()` builds the execution environment for the `git clone` subprocess by merging `envForRemoteOperation(url)` with a hardcoded override:

```ts
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
``` [1](#0-0) 

This same code path performs the clone with `--recursive`, meaning any submodules declared in the attacker-controlled repository's `.gitmodules` are cloned automatically. The `isClonePathSensitive` check that precedes this only validates the local destination path (protecting `~/.ssh`, `~/.gnupg`, `~/.config`, etc.), it does nothing to validate content coming from the remote (submodule URLs, `.gitmodules` contents, or in-repository paths): [2](#0-1) 

By forcing `GIT_CLONE_PROTECTION_ACTIVE` to `false`, the invariant "clone-time protections against maliciously crafted repository content are active" is broken exactly the same way the seed report broke "slippage protection is active" by hardcoding `token_min_a`/`token_min_b` to `0` — the disabling constant is baked into the call site itself, so no caller-supplied value or downstream check can restore the protection. Just as `delta_a < 0` and `delta_b < 0` can never be true (making the AMM's min-token check unreachable), a protection flag hardcoded to `'false'` can never be flipped back on for any clone operation performed through this function, no matter how untrusted the remote.

### Impact Explanation
Since `clone()` is reachable from the "Clone repository" UI flow with a URL fully supplied/controlled by an attacker (e.g., a malicious public repo shared via link, or a crafted deep link), disabling this protection while running `--recursive` removes the safety net specifically intended to stop unsafe repository/submodule content from being processed during clone. Depending on what this flag governs in the embedded Git binary, the practical impact ranges from writing files outside the intended clone destination to execution of attacker-controlled content during the recursive submodule checkout — i.e., exactly the class of "file write or read outside the repo" / "code execution" impact called out as valid for this scan.

### Likelihood Explanation
Likelihood is high: this is not a corner case, it fires on **every** clone performed by GitHub Desktop, and the URL is attacker-controlled by definition whenever a user clones a public/untrusted repository or opens a "clone" deep link. No special local access, admin rights, or social engineering beyond "user clones a repo" (an ordinary, expected Desktop action) is required.

### Recommendation
Do not hardcode `GIT_CLONE_PROTECTION_ACTIVE` (or whatever the underlying safety mechanism is) to a disabling value at the `clone()` call site. Instead:
- Remove the hardcoded override entirely and let Git use its default (protective) behavior for this setting.
- If there is a legitimate compatibility reason to touch this variable, make it opt-in only for trusted/local operations, never for `clone` against an arbitrary user-supplied remote URL.
- Add a regression test asserting that `GIT_CLONE_PROTECTION_ACTIVE` is never set to `'false'` (or any disabling value) by the `clone()` code path.

### Proof of Concept
1. Attacker publishes a repository (or sends a `x-github-client://` / `github-mac://` style clone deep link) pointing to a URL they control, with a `.gitmodules` file/submodule crafted to exploit whatever Git currently guards against via `GIT_CLONE_PROTECTION_ACTIVE`.
2. Victim clicks "Clone" in GitHub Desktop (or opens the link) and clones the malicious URL.
3. `clone()` in `app/src/lib/git/clone.ts` runs `git -c init.defaultBranch=... clone --recursive -- <attacker_url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` forced into the environment.
4. Because the protection is disabled for this invocation only by a hardcoded constant with no override path, the safety check that would normally reject/guard the malicious submodule content never executes, regardless of the destination path or repository content — analogous to how `token_min_a = token_min_b = 0` in `liquidity_lockbox::withdraw` guaranteed the `decreaseLiquidity` slippage check could never trigger. function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
```

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]
