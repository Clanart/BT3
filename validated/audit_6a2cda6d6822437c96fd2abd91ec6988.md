### Title
Variable-time scalar multiplication on secret FROST nonces enables Minerva-style timing recovery of key shares - (File: crypto/frost/src/nonce.rs)

### Summary
CVE-2019-13627 (Minerva) is a timing attack on ECDSA where variable-time scalar multiplication leaked information about nonce bits, enabling lattice-based private key recovery. The same bug class exists in Serai: FROST nonce commitments and Schnorr signature nonces are computed with variable-time point-by-secret-scalar multiplication on the dalek-backed curves.

### Finding Description
`NonceCommitments::new` computes the two FROST nonce commitments via `*generator * nonce.0[0]` and `*generator * nonce.0[1]`, where `generator` is a plain group element and `nonce.0[i]` are secret scalars derived from the secret share via `C::random_nonce` [1](#0-0) . `SchnorrSignature::sign` similarly computes `R = C::generator() * nonce` on a secret single-use scalar [2](#0-1) . In `dalek-ff-group`, `Point * Scalar` is wired to `$DPoint::mul` [3](#0-2) , which is curve25519-dalek's variable-time scalar multiplication (it only dispatches to the constant-time precomputed basepoint table through the separate `Mul<Scalar> for &$Table` impl [4](#0-3) ). Variable-time multiplication executes point operations dependent on the scalar's (w)NAF digits, so wall-clock time / operation count leaks information about the secret nonce's bit structure — precisely the side channel Minerva exploited on libgcrypt's ECDSA. The multiexp crate is careful to expose `multiexp` (constant-time) vs `multiexp_vartime` separately [5](#0-4) , but the scalar-on-secret multiplication paths in signing do not benefit from that distinction. Note: `ed448`'s `Mul<Scalar>` uses a fixed 16-entry table with `conditional_select` and is constant-time [6](#0-5) , and k256's `*` operator is constant-time, so the exposure is concentrated on the Ristretto/Ed25519 dalek-backed ciphersuites (substrate/Schnorrkel signing, tributary transaction signing, message-queue acks [7](#0-6) ).

### Impact Explanation
Partial nonce-bit leakage per signature aggregates across many signatures into a Hidden Number Problem instance solvable via lattice reduction, recovering the FROST secret share (for `d`/`e` nonce leaks) or the signing key (for Schnorr `R` leaks). This is key-share/private-key recovery — the accepted concrete impact — directly mirroring the original CVE, which rated the confidentiality impact high.

### Likelihood Explanation
An unprivileged party that can cause the node to sign attacker-influenced messages (tributary transactions, message-queue acks, FROST signing sessions over submitted transaction data) and observe operation timing — locally, per the advisory's AV:L model, or remotely with sufficient measurement repetition as the Minerva paper demonstrated against network-exposed signers — can collect the required signature/timing pairs. Exploitation complexity is high (noisy remote timing, lattice machinery), matching the advisory's AC:H.

### Recommendation
Route all secret-scalar point multiplications through constant-time paths: use the precomputed basepoint tables (`constants::RISTRETTO_BASEPOINT_TABLE * scalar` / the `$Table` `Mul` impl) for `generator() * secret`, and a constant-time variable-base multiplication for `*generator * nonce` when the generator isn't the basepoint. Audit `crypto/dalek-ff-group` `math_neg!` wiring so `Point * Scalar` on secrets is constant-time or provides a distinct `mul_ct` API, mirroring the `multiexp`/`multiexp_vartime` split already enforced in `crypto/multiexp`.

### Proof of Concept
1. Stand up a signer using a dalek-backed ciphersuite (Ristretto) whose `sign` path calls `SchnorrSignature::sign` (e.g., `Signer::sign` in `coordinator/tributary/src/tendermint/mod.rs:89-117`, or FROST `AlgorithmMachine::preprocess` → `NonceCommitments::new`).
2. Submit many distinct messages for signing while precisely timing each operation; each signature leaks NAF-digit-position timing of that signature's secret nonce.
3. Convert the per-signature leaked nonce-bit constraints into a lattice (HNP) instance over signatures sharing the same private key/secret share; solving it recovers the key — the standard Minerva/LadderLeak exploitation pipeline, applied to `*generator * nonce` where the point operand is a non-table point and `DPoint::mul` runs variable-time.

impl Mul<Scalar> for Point {
  type Output = Point;
  fn mul(self, mut other: Scalar) -> Point {
    // Precompute the optimal amount that's a multiple of 2
    let mut table = [Point::identity(); 16];
    table[1] = self;
    for i in 2 .. 16 {
      table[i] = table[i - 1] + self;
    }

    let mut res = Self::identity();
    let mut bits = 0;
    for (i, mut bit) in other.to_le_bits().iter_mut().rev().enumerate() {
      bits <<= 1;
      let mut bit = u8_from_bool(&mut bit);
      bits |= bit;
      bit.zeroize();

      if ((i + 1) % 4) == 0 {
        if i != 3 {
          for _ in 0 .. 4 {
            res = res.double();
          }

          }
        }
        res += add_by;
        bits = 0;
      }
    }
