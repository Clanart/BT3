## Analysis: DataLayer Mirror URL SSRF

The elFinder CVE-2019-6257 pattern — an application performing outbound HTTP fetches to an unvalidated, attacker-supplied URL (`get_remote_contents()`) — has a direct analog in the Chia DataLayer subsystem: mirror URLs are attacker-controlled, chain-published values that DataLayer clients automatically consume and fetch via `aiohttp` with no scheme/host restrictions.

### Title
DataLayer Mirror-URL SSRF: unrestricted outbound `aiohttp` fetch of attacker-chosen URLs during subscription sync - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can create a DataLayer "mirror" coin for *any* store/launcher id and attach arbitrary URL strings to it via `dl_new_mirror`. These URLs are stored on-chain in the mirror coin's memos, are automatically ingested by every DataLayer client tracking that store, and are later used as literal HTTP request targets by `http_download()`. No validation of scheme, host, or target address (e.g. loopback, link-local, RFC1918, cloud metadata IPs) is performed before the outbound request is issued.

### Finding Description
- `DataLayerWallet.create_new_mirror()` lets a wallet create a mirror coin carrying an arbitrary list of URL bytes in the coin memo, for any `launcher_id` — including a store the creator does not own: [1](#0-0) 
- When any node's `DataLayerWallet` observes a mirror coin on chain, it decodes the memo URLs and, as long as the associated launcher is already tracked, stores it as a `Mirror` with no URL validation: [2](#0-1) 
- The DataLayer service periodically pulls these wallet-known mirrors and merges their URLs directly into the local subscription table for automatic use, again without validation: [3](#0-2) [4](#0-3) 
- During the fetch cycle, `fetch_and_validate()` iterates the resulting server list and calls `insert_from_delta_file()` → `download_file()` using `server_info.url` taken straight from the mirror-supplied string: [5](#0-4) 
- `download_file()` (when no downloader plugin is configured — the default) calls `http_download()`, which issues an `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` request with no scheme allow-list, no host allow-list, and no blocking of private/loopback/link-local ranges: [6](#0-5) 

This mirrors the elFinder `get_remote_contents()` bug class exactly: a remote/attacker-influenced URL is fed straight into an HTTP client without any target-restriction, and the requesting service will happily connect to internal-only addresses (localhost admin ports, cloud metadata endpoints, RFC1918 ranges, etc.) chosen by the attacker.

### Impact Explanation
Any Chia user running the DataLayer service and subscribing to (or owning) a public store is forced to make outbound HTTP requests to arbitrary attacker-chosen network locations whenever another user creates a mirror coin for that store's `launcher_id`. This is a classic SSRF: the DataLayer node becomes a proxy that an attacker can use to probe or interact with internal-network-only services reachable from the victim node (metadata endpoints, internal dashboards, other localhost-bound services), and can be used to trigger repeated/timed connection attempts (useful for internal port-scanning/timing side channels) or to exhaust node resources by pointing many mirrors at slow/hanging endpoints. Because URL creation only costs a small mirror-coin fee and requires no relationship to the target store's owner, this is broadly reachable by any wallet user, matching the "Data Layer client" and "wallet action" reachability the analog rules require.

### Likelihood Explanation
High reachability, low cost: creating a mirror coin with an arbitrary URL is a standard, unprivileged wallet transaction (`dl_new_mirror` / `add_mirror` CLI/RPC) requiring only a fee, and any DataLayer node tracking (or subscribing to) that launcher id will automatically merge the URL into its subscription table and periodically fetch it (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`), with no manual approval step and no URL vetting.

### Recommendation
Validate mirror/subscription URLs before they are persisted or used for outbound requests: restrict to `http`/`https` schemes, resolve and reject requests targeting loopback, link-local, and private/reserved IP ranges (and re-validate after redirects), and consider requiring explicit user opt-in/allow-listing before auto-merging wallet-discovered mirror URLs into the local subscription/fetch path in `chia/data_layer/data_store.py:update_subscriptions_from_wallet()` and `chia/data_layer/download_data.py:http_download()`.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (or CLI `chia data add_mirror`) with `launcher_id` set to a store id being tracked/subscribed to by a victim DataLayer node, and `urls=["http://169.254.169.254/latest/meta-data/"]` (or any internal-only address reachable from the victim's network).
2. The mirror coin is farmed; the victim's `DataLayerWallet.coin_added()` picks it up and stores it as a `Mirror` (per `chia/data_layer/data_layer_wallet.py:775-800`).
3. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` merges the attacker's URL into the victim's local subscriptions (`chia/data_layer/data_layer.py:979-985`).
4. `fetch_and_validate()` selects that server and calls `download_file()` → `http_download()`, causing the victim's node process to issue an outbound `GET` to the attacker-chosen internal URL (`chia/data_layer/download_data.py:298-323`), demonstrating the SSRF.

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
