### Title
Attacker-controlled `ReceivedOutput` deserialization reports arbitrary Bitcoin outputs as spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts an independently supplied scalar offset, `TxOut`, and `OutPoint` without validating that the offset derives the output's Taproot key or that the referenced UTXO contains that `TxOut`. An attacker who can provide these serialized bytes can therefore make an application report arbitrary Bitcoin value as received, while the resulting input cannot actually be spent by the wallet.

### Finding Description
`ReceivedOutput` stores three fields that must satisfy external invariants: `offset` selects the spendable derived key, `output` contains the script and amount, and `outpoint` identifies where that output exists on-chain. The constructor used by `Scanner::scan_transaction` establishes the offset/script relationship by looking up `output.script_pubkey` in the scanner's registered script map and binds `outpoint` to the transaction actually being scanned. [1](#0-0) 

The deserializer does not re-establish either invariant. It reads a canonical scalar, decodes an arbitrary `TxOut`, decodes an arbitrary `OutPoint`, and returns all three unchanged. [2](#0-1) 

Downstream accounting uses the deserialized `TxOut` value directly. [3](#0-2)  `SignableTransaction::new` likewise trusts the decoded output's value for balance calculation and its outpoint as the transaction input. [4](#0-3) 

Although `SignableTransaction::multisig` checks that the supplied offset produces the script stored in `prevouts[i]`, it cannot check that the supplied `prevouts[i]` is the real UTXO referenced by `input.previous_output`. [5](#0-4) 

### Impact Explanation
An attacker can encode a nonexistent or third-party outpoint together with a high-value `TxOut`, or pair an existing outpoint with a different value. A consumer that treats `ReceivedOutput::read` output as an authenticated received-output record will report those funds as wallet balance even though no corresponding spendable UTXO exists.

If the encoded script is made to match the wallet's derived Taproot key, `multisig` can proceed and construct a transaction whose signature commits to the attacker-supplied prevout data; the transaction will fail consensus validation because the claimed `TxOut` is not the actual UTXO. If the script does not match, `multisig` rejects it, but accounting code may already have credited `ReceivedOutput::value()`.

### Likelihood Explanation
The attacker only needs to supply bytes to a reachable `ReceivedOutput::read` call. No private keys, validator privileges, malformed encodings, or hash collisions are required: all fields are syntactically valid but semantically unrelated.

The exploitability boundary is whether an application persists or exchanges serialized `ReceivedOutput` values as trusted records. The public API exposes serialization and deserialization as symmetric operations, while the struct documentation describes the result as “a spendable output,” making that trust assumption plausible. [6](#0-5) 

### Recommendation
Do not deserialize `ReceivedOutput` without the scanner/base-key context needed to validate it. Require an expected base key or `Scanner`, recompute `p2tr_script_buf(base_key + G * offset)`, and reject inputs whose decoded `script_pubkey` differs.

Also validate the `OutPoint` against a trusted UTXO source and require the returned on-chain `TxOut` to equal the decoded `TxOut` before exposing the object as spendable. If this cannot be done inside the crate, rename/document the API as decoding an unverified claim rather than a spendable output, and ensure balance and signing paths cannot consume it without UTXO verification.

### Proof of Concept
```rust
use bitcoin::{
  transaction::Version, absolute::LockTime, Amount, OutPoint, ScriptBuf,
  Transaction, TxOut, Txid,
};
use bitcoin::hashes::Hash;
use bitcoin_serai::wallet::ReceivedOutput;
use k256::Scalar;

// Any syntactically valid P2TR-looking script.
let script = ScriptBuf::from_bytes(vec![0x51, 0x20, /* 32-byte x-only key */]);

let mut encoded = Vec::new();
encoded.extend(Scalar::ZERO.to_bytes());

TxOut {
  value: Amount::from_sat(100_000_000),
  script_pubkey: script.clone(),
}
.consensus_encode(&mut encoded)
.unwrap();

// An arbitrary/nonexistent outpoint.
OutPoint {
  txid: Txid::from_byte_array([0x42; 32]),
  vout: 0,
}
.consensus_encode(&mut encoded)
.unwrap();

let claimed = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// The API reports 1 BTC as received despite there being no validated UTXO.
assert_eq!(claimed.value(), 100_000_000);
assert_eq!(claimed.output().script_pubkey, script);
assert_eq!(claimed.outpoint().vout, 0);
```
