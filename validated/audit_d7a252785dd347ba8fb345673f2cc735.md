### Title
Challenger EVM-address swap on the unauthenticated OP_RETURN output of the Challenge transaction — (File: core/src/builder/transaction/challenge.rs)

### Summary
The Challenge transaction's operator-reimbursement input is signed with `TapSighashType::SinglePlusAnyoneCanPay`, which by BIP-341 semantics only covers the single input and the single output at the same index. The second output — an OP_RETURN carrying the `challenger_evm_address` that determines who is later reimbursed by Citrea if the challenge later proves the operator dishonest — is not covered by the operator's/N-of-N's signature at all. Anyone in possession of a validly-signed, unbroadcast Challenge transaction can therefore strip or replace this OP_RETURN output with their own EVM address before broadcasting, without invalidating the SIGHASH_SINGLE|ANYONECANPAY signature, and claim the reimbursement intended for the actual challenger who incurred the cost.

### Finding Description
`create_challenge_txhandler` builds two outputs: output 0 is the operator reimbursement payment, output 1 (optional) is an OP_RETURN with the `challenger_evm_address` [3](#0-2) . This tx is the "signature-owner" of a shared N-of-N (verifier committee)/operator-signed presigned transaction, signed at deposit time with sighash `SinglePlusAnyoneCanPay` per `SignatureId::get_deposit_sig_owner` [4](#0-3) . `calculate_script_spend_sighash`/`calculate_pubkey_spend_sighash` explicitly restrict prevouts to `Prevouts::One(txin_index, ...)` for `SinglePlusAnyoneCanPay`, and Bitcoin's SIGHASH_SINGLE only commits to the output with the same index as the signed input (index 0 here) [2](#0-1) . This means output index 1 (the OP_RETURN with the challenger's EVM address) is entirely unsigned data. Given the presigned witness for input 0, a third party can take the raw transaction bytes, delete/replace output 1 with a different EVM address (their own), and rebroadcast — the signature remains valid because SIGHASH_SINGLE does not commit to that output.

This breaks the binding: the operator reimbursed on Bitcoin ↔ the EVM address later credited by Citrea for a correct challenge should be the party that actually incurred the challenge cost, but an unauthenticated third party can redirect that credit to themselves.

### Impact Explanation
If the challenge is later proven correct (operator found malicious), Citrea's light-client circuit uses the OP_RETURN-embedded EVM address to determine who receives reimbursement from the operator's slashed collateral. An attacker who intercepts/observes the Challenge tx before confirmation (e.g., from mempool, or from any verifier's `internal_create_signed_txs` response since each verifier independently constructs and can leak its own version) can rebroadcast a modified version with their own EVM address, stealing the reimbursement that was meant for the entity that actually paid the challenge cost. This is a misattributed reimbursement claim tied to a bridge-custody binding (the entity that funded the challenge vs. the entity credited on Citrea), matching the High-impact class of "an unauthenticated state-changing or broadcasting call" redirecting value.

### Likelihood Explanation
Exploitation only requires observing a valid but unconfirmed Challenge transaction (e.g. in the mempool, or obtained via any verifier/operator RPC that returns signed-but-unbroadcast transactions such as `internal_create_signed_txs`) and rebroadcasting a variant with a swapped OP_RETURN output before the original confirms. This requires no special privilege beyond normal network access to observe/replace mempool transactions, making it an unprivileged-attacker path.

### Recommendation
Use a sighash type that commits to all outputs (e.g. `Default`/`All`) for the Challenge transaction's signature, or otherwise bind the `challenger_evm_address` output to the signed input (for instance, by including it in a committed hash inside the signed output/script, or requiring `AllPlusAnyoneCanPay` so it commits to every output while still allowing additional inputs to be attached for fee bumping).

### Proof of Concept
1. Verifier committee (or operator) presigns Challenge input 0 with `TapSighashType::SinglePlusAnyoneCanPay` per `create_challenge_txhandler`/`get_deposit_sig_owner` [3](#0-2) .
2. The resulting raw transaction (input 0 witness valid, output 0 = operator payment, output 1 = OP_RETURN with challenger A's EVM address) becomes visible to an attacker (e.g. via mempool or via a verifier RPC response before broadcast).
3. Attacker constructs a new transaction with the same input/witness for index 0 but replaces output 1's OP_RETURN payload with their own EVM address B, keeping output 0 unchanged (so the SIGHASH_SINGLE commitment over output 0 and input 0 still matches).
4. Attacker broadcasts this modified transaction first (or via RBF utilizing the ANYONECANPAY flexibility). The transaction is accepted because sighash validation only checks the single input and matching single output, both unmodified.
5. If the kickoff is later proven malicious, Citrea reimburses EVM address B instead of the original challenger A.

pub fn create_challenge_txhandler(
    kickoff_txhandler: &TxHandler,
    operator_reimbursement_address: &bitcoin::Address,
    challenger_evm_address: Option<EVMAddress>,
    paramset: &'static ProtocolParamset,
) -> Result<TxHandler, BridgeError> {
    let mut builder = TxHandlerBuilder::new(TransactionType::Challenge)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Challenge,
            kickoff_txhandler.get_spendable_output(UtxoVout::Challenge)?,
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: paramset.operator_challenge_amount,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }));

    if let Some(challenger_evm_address) = challenger_evm_address {
        builder = builder.add_output(UnspentTxOut::from_partial(op_return_txout(
            challenger_evm_address.0,
        )));
    }

    Ok(builder.finalize())
}
