### Title
Reward sniping via zero-totalSupply queuedRewards captured entirely by next single staker in `DelegateVoteRewardPool` - (File: rewards/DelegateVoteRewardPool.sol)

### Summary
`DelegateVoteRewardPool._queueNewRewardsWithoutTransfer` (invoked from `_manageRewards`, which is invoked from the public `harvestAll()`) buffers rewards into `rewardInfo.queuedRewards` whenever `totalSupply == 0`, with no accounting of which users were entitled to that yield. Any account that becomes the sole subsequent staker (via `WombatBribeManager.vote()` → `stakeFor`) will have the full queued batch folded into `rewardPerTokenStored` on the next harvest, letting it claim yield collectively earned while no one (or other, now-exited voters) held a stake.

### Finding Description
`harvestAll()` is unauthenticated/public and is also triggered as a side effect of the public `WombatBribeManager.castVotes()`: [1](#0-0) 

It flows into `_manageRewards` and then `_queueNewRewardsWithoutTransfer`: [2](#0-1) 

When `totalSupply == 0` (e.g., no user has voted for `delegatedPool` yet, or all prior voters withdrew via `unvote`/negative `vote()` deltas), any newly-claimed bribe amount is added to `rewardInfo.queuedRewards` instead of being distributed pro-rata to nobody — it is deferred. The deferral itself is a reasonable design (mirrors Synthetix-style reward pools), but the flaw is that when `totalSupply` later becomes non-zero, the *entire* queued balance is folded into `rewardPerTokenStored` in one shot, weighted only by whoever holds the (possibly tiny) `totalSupply` at that exact moment — with no time-weighting or snapshot of who was entitled to the earlier-earned yield.

The staking entry point is reachable by any unprivileged account: `WombatBribeManager.vote()` lets a user submit a positive delta for the LP whose registered rewarder is `delegatedPool`, which calls `DelegateVoteRewardPool.stakeFor(msg.sender, amount)`: [3](#0-2) [4](#0-3) 

Attack flow:
1. `totalSupply` of `DelegateVoteRewardPool` hits `0` (initial state before any voter, or after a mass `unvote`/negative-delta `vote()`).
2. Anyone calls (or waits for someone to call) `castVotes()`, which unconditionally calls `harvestAll()`; bribes earned across this whole period get queued via the `totalSupply == 0` branch.
3. Attacker calls `vote()` with a minimal positive delta (e.g., 1 wei) for the pool mapped to `delegatedPool`, causing `stakeFor(attacker, 1)` and `totalSupply` becoming `1`.
4. On the next `harvestAll()`/`castVotes()`, `_queueNewRewardsWithoutTransfer` executes the `else` branch, adding the entire `rewardInfo.queuedRewards` plus new earnings and dividing by `totalSupply == 1`, crediting the whole batch to the attacker's `rewardPerTokenStored` share.
5. Attacker calls `getReward`/`harvestAll` → `_getDelegateReward` to withdraw the full amount.

No existing check (no minimum lock time, no per-block/time-weighted queued reward release, no ownership check on who queued vs who benefits) prevents this. `stakeFor`'s `updateRewards` modifier only computes `earned()` up to the point of staking (which is zero for a fresh staker) and does not protect against this queued-batch dilution.

### Impact Explanation
This is theft/misappropriation of unclaimed yield: rewards accrued while `totalSupply == 0` (or attributable to prior voters who have since exited) are diverted entirely to whichever address opportunistically becomes the sole/first staker afterward, at negligible capital cost (1 wei of vlMGP vote weight). This matches the "theft of unclaimed yield" impact class.

### Likelihood Explanation
The precondition (`totalSupply == 0` momentarily) is realistic: it is true at pool bootstrap before the first voter, and is trivially reachable any time all current delegators withdraw their vote (or their votes decay to zero via `unvote`), even briefly within a single block/transaction ordering window. The attacker needs no special privileges — just the ability to call the public `vote()` and `castVotes()`/`harvestAll()` functions with minimal vlMGP holdings, and can front-run/time entry around any known zero-supply window. Repeatable each time queued rewards accumulate under this state.

### Recommendation
Do not permit the full historically-queued rewards to be assigned instantaneously to a single new/first staker. Options: (a) track a minimum vesting/lock period before queued rewards convert to claimable `rewardPerTokenStored` for new stakers, (b) forward queued rewards to a protocol treasury/redistribution mechanism when `totalSupply` is zero rather than silently deferring them to the future first staker, or (c) require a minimum stake and elapsed-time weighting before a staker's share of newly-unqueued rewards is realized.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool` with a mock `operator` (BribeManager) and reward token; ensure `totalSupply == 0`.
2. Simulate bribe income: call `harvestAll()` (mock `claimAllBribes` to return a nonzero reward amount) → assert `rewardInfo.queuedRewards == fullAmount` and `rewardPerTokenStored == 0`.
3. As attacker, call `stakeFor(attacker, 1)` (via mocked operator context) to set `totalSupply = 1`.
4. Call `harvestAll()` again with zero new bribes (or a small additional amount) → assert `rewardPerTokenStored` reflects the entire previously queued amount divided by `totalSupply = 1`.
5. Call `getReward(attacker)` → assert the transferred reward equals (approximately) the full originally-queued batch, despite the attacker having staked only 1 wei for zero elapsed time relative to when the rewards were earned.
6. Assert no other account can claim any portion of that same reward batch.

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
