## Title
Data Layer mirror URLs are attacker-controlled and unvalidated, enabling Server-Side Request Forgery against any node tracking the target store - (File: `chia/data_layer/download_data.py`)

### Summary
Any user who can submit a spend bundle can create a "mirror" coin carrying an arbitrary `launcher_id` and arbitrary URL strings in its memos. If a victim's wallet is already tracking that `launcher_id` (which happens automatically for anyone subscribed to that DataLayer store), the victim's `DataLayerWallet` unconditionally records the attacker-supplied URLs as mirror servers for that store [1](#0-0) . The DataLayer service then periodically pulls these mirror URLs and issues outbound HTTP requests to them with no host/scheme validation, resulting in classic SSRF.

### Finding Description
`DataLayerWallet.coin_added()` detects coins sent to the mirror puzzle hash, decodes `launcher_id` and `urls` straight from the parent coin's spend memos via `get_mirror_info()`, and stores them if the launcher id is tracked — with no check that the sender owns or is authorized for that launcher/store: [1](#0-0) 

`get_mirror_info()` simply reads the `CREATE_COIN` condition's memos as the URL list, with no format or scheme restriction: [2](#0-1) 

Nothing gates who may create such a coin: `create_new_mirror()` on the wallet side is a plain standard-coin spend to the mirror puzzle, carrying the memos: [3](#0-2) 

`DataLayer.update_subscriptions_from_wallet()` pulls these wallet-tracked mirrors verbatim and stores them as subscription server URLs: [4](#0-3) 

`fetch_and_validate()` later selects one of these server URLs and passes it into `insert_from_delta_file()`/`download_file()`: [5](#0-4) 

Finally, `http_download()` performs an unauthenticated `aiohttp` GET straight to `server_info.url + "/" + filename`, with no allow-list, no scheme check, and no restriction on private/internal/link-local addresses (e.g. `127.0.0.1`, RFC1918 ranges, or cloud metadata endpoints like `169.254.169.254`): [6](#0-5) 

If a plugin downloader is configured, the URL is instead forwarded as JSON to the plugin's `/download` endpoint, so even plugin-mediated flows relay the attacker-chosen URL onward: [7](#0-6) 

A grep across `chia/data_layer/*.py` confirms there is no `urlparse`/host-allowlist/private-IP check anywhere in the mirror-URL or HTTP-download path (only the unrelated `s3_plugin_service.py` validates `scheme == "s3"` against a locally configured bucket list, which does not apply to the plain HTTP mirror path).

This is the same bug class as CVE-2023-1046 (MuYuCMS SSRF via an unvalidated `url` parameter): user-controlled input directly drives an outbound request with no destination validation, only here the "user-controlled input" is data embedded on-chain in coin memos rather than an HTTP request parameter.

### Impact Explanation
Any wallet/DataLayer node that tracks a given store id (which happens for every subscriber, and is trivially inferable/public since DataLayer store ids and subscriptions are meant to be shared) can be forced to make outbound HTTP requests to attacker-chosen hosts, including internal-only network endpoints, localhost services, or cloud-metadata IPs. This can be used for internal network reconnaissance/port scanning, requesting sensitive data from internal services reachable only from the victim host, and (via plugin download flows) triggering a plugin service to fetch attacker-controlled URLs on its own network segment. Because the attacker fully controls `launcher_id` and URL strings via a single spend bundle (mirror coin creation costs only a nominal mojo amount plus fee), this is reachable by any unprivileged, unauthenticated mempool submitter.

### Likelihood Explanation
Likelihood is high: creating a mirror coin is a normal, low-cost, unprivileged spend-bundle operation (`dl_new_mirror` / `add_mirror`), requiring no special permission, no store ownership, and only knowledge of a `launcher_id` that some victim already tracks (which is the normal state for any DataLayer subscriber). The victim's periodic `update_subscription()` loop automatically ingests and later dereferences these URLs with no destination validation.

### Recommendation
- Validate mirror/server URLs before storing/using them: enforce an allowed scheme (e.g., `http`/`https` only), and reject or explicitly opt-in for URLs resolving to loopback, link-local, and private/reserved IP ranges (SSRF-style egress filtering), similar in spirit to the scheme allow-list already used in `s3_plugin_service.py`.
- Consider requiring explicit user confirmation/allow-listing of mirror hosts rather than automatically trusting on-chain memo data as fetchable server endpoints.
- Apply the same validation both to the direct HTTP downloader path (`http_download`) and to the plugin-forwarded `url` field (`download_file`/plugin `/download` and `/handle_download` requests).

### Proof of Concept
1. Attacker crafts and submits a standard spend bundle creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memo list `[victim_tracked_launcher_id, b"http://169.254.169.254/latest/meta-data/", b"http://10.0.0.5:6379/"]` (mirroring the shape used in `create_new_mirror`/`dl_new_mirror`, see test at [8](#0-7) ).
2. Once confirmed, any node whose wallet already tracks `launcher_id` (e.g., a DataLayer subscriber) picks up the mirror via `coin_added()` and stores the attacker URLs as subscription servers.
3. On the next `periodically_manage_data()` cycle, `update_subscription()` → `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues an HTTP GET to the attacker-chosen internal URL from the victim node, with no destination filtering.

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
```

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
