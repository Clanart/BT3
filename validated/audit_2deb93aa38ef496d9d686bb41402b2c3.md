### Title
Attacker-controlled `WWW-Authenticate` header spoofs "GitHub Enterprise" classification, redirecting the in-app sign-in flow to an untrusted endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The report describes ENS `NameWrapper.wrapETH2LD` extending a narrow approval (wrapper-only) into a broader, unintended permission (control over unwrapped domains) because the code trusted a self-referential flag rather than the correct scope. The Desktop analog is `getEndpointKind` in the trampoline credential helper: it classifies an arbitrary remote as `'enterprise'` (i.e., a trusted GitHub-brand host worthy of the GitHub sign-in UI and account-binding flow) purely because the *remote itself* sent a `WWW-Authenticate` header claiming `realm="GitHub"`. That claim is entirely attacker-controlled, over-extending "GitHub-trusted" classification to any HTTPS git remote a user tries to clone/fetch/push to.

### Finding Description
When Git needs credentials for an HTTPS remote, the request/response cycle (including any `WWW-Authenticate` header from the server) is forwarded to Desktop's credential helper trampoline. `getEndpointKind` inspects these headers before doing any real host verification: [1](#0-0) 

Specifically:
- Lines 153-165: for any `wwwauth[...]` entry in the credential map, if the value contains `realm="GitHub"`, the endpoint is immediately classified as `'enterprise'` - no cryptographic or DNS-based verification is performed, just a string match against attacker-supplied header content.
- Only later, and only if the header-based shortcut doesn't fire, does the code fall back to the legitimate check `isGitHubHost(endpoint)` (line 178), which presumably does real verification. The header-based branch **bypasses that check entirely**.

This attacker-controlled classification then drives privileged behavior in `getCredential`: [2](#0-1) 

If `endpointKind !== 'generic'` and no existing account matches the endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` (line 118), which opens the "Sign in to GitHub Enterprise" flow bound to that attacker-chosen origin: [3](#0-2) 

`promptForGitHubSignIn` calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` where `origin` is derived directly from the attacker's remote URL - not from any verified GitHub Enterprise instance. This is the same broken-invariant pattern as the ENS bug: a scope-limited trust signal (the "GitHub-trusted host" classification, which should be reserved for verified `github.com`/GHE hosts) is extended to cover an entity that only *claims* to be in that category, because the check that should gate it (`isGitHubHost`) is skipped in favor of trusting attacker-supplied data.

### Impact Explanation
A malicious git server (attacker-controlled remote or a MITM/malicious proxy sitting on the git HTTP path) can return a 401 with `WWW-Authenticate: Basic realm="GitHub"` on any HTTPS git operation (clone/fetch/push). This causes Desktop to:
1. Skip the legitimate `isGitHubHost` verification.
2. Present the user with an in-app "Sign in to GitHub Enterprise" dialog whose sign-in endpoint is set to the attacker's own domain (`dispatcher.setSignInEndpoint(origin)`).

If the user, believing this is a legitimate Desktop-initiated authentication prompt (it looks identical to a real one), completes the sign-in (enters PAT/OAuth flow), their credentials/token exchange happens against the attacker's endpoint - i.e., "unauthorized OAuth or account binding" and potential "credential/token exfiltration," both explicitly listed as valid impact categories, achieved purely by controlling a git remote/proxy response.

### Likelihood Explanation
The trigger requires no special user action beyond a normal clone/fetch/push against an attacker-controlled or MITM'd HTTPS remote - a scenario already in scope per the task's threat model ("attacker controls ... a git remote/proxy response"). Setting a custom `WWW-Authenticate` header is trivial for any HTTP server the attacker operates. The only "user action" needed afterward is completing the sign-in prompt, which is the same flow users are trained to expect for legitimate GHE remotes, making it plausible for at least some users.

### Recommendation
Do not classify an endpoint as `'enterprise'`/GitHub-trusted based solely on the `WWW-Authenticate` realm string reported by the remote. Always run the endpoint through the verified `isGitHubHost(endpoint)` check (or equivalent DNS/certificate/API-based verification) before granting the "GitHub-trusted" classification, and before invoking `promptForGitHubSignIn`/`beginEnterpriseSignIn` with an endpoint derived from unverified remote input.

### Proof of Concept
1. Stand up an HTTPS git server (or a MITM proxy) that responds to Git's credential probe with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or fetch from `https://attacker.example/some/repo.git`.
3. Git forwards the response to the credential trampoline; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-163`) matches the `realm="GitHub"` substring and returns `'enterprise'`.
4. `getCredential` (lines 109-124) finds no existing account for `attacker.example` and calls `ui.promptForGitHubSignIn('https://attacker.example')`.
5. `TrampolineUIHelper.promptForGitHubSignIn` (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-93`) invokes `dispatcher.setSignInEndpoint('https://attacker.example')` and opens the Enterprise sign-in dialog, directing any credentials/OAuth exchange the user completes to the attacker's domain.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
