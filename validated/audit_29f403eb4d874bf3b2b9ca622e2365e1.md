### Title
`Scanner::scan_block` reports immature coinbase outputs as received spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to `RFPSimpleStrategy._distribute` acting on `milestones[upcomingMilestone]` without checking the milestone's status, `Scanner::scan_block` in bitcoin-serai returns `ReceivedOutput`s for every transaction in a block — including `block.txdata[0]`, the coinbase — without checking the transaction's coinbase/maturity status. Coinbase outputs are unspendable for 100 blocks (BIP-30/CORE maturity rule), so the wallet reports funds as received that are not actually spendable.

### Finding Description
`scan_transaction` matches outputs purely on `script_pubkey` and constructs a `ReceivedOutput` with `offset`, `TxOut`, and `OutPoint` — it has no notion of transaction status (networks/bitcoin/src/wallet/mod.rs:199-214). `scan_block` then iterates `&block.txdata` unconditionally, starting at index 0 (lines 221-227), so the coinbase transaction is scanned identically to normal transactions. A miner can place an output paying to Serai's registered P2TR script in their coinbase; `scan_block` will emit a `ReceivedOutput` for it, and `ReceivedOutput::value()` reports its amount as received. The doc comment on `scan_block` (lines 216-220) acknowledges the caveat ("a post-processing pass is needed to remove those outputs") but the function itself performs no status check — exactly the pattern of the source bug, where the presence of an item in the sequence was treated as sufficient to act on it.

### Impact Explanation
Any consumer calling `scan_block` on untrusted block data receives `ReceivedOutput`s for immature coinbase outputs. These outputs cannot be spent until the coinbase matures (100 blocks); a spend attempt built from such an outpoint produces a transaction the Bitcoin network rejects. This satisfies "funds reported received that are not spendable": accounting/crediting logic keyed off scanned outputs will over-report confirmed, spendable balance, and any automated spend path consuming these `ReceivedOutput`s will produce invalid transactions.

### Likelihood Explanation
Reachability requires a miner to craft a coinbase paying to the scanned script — an unprivileged party can do this only if they mine a block, which has real cost but is achievable (e.g., via solo mining or directing pool payouts). Once mined, no further interaction is needed: any caller feeding the block through `scan_block` gets a spendable-looking output for ~100 blocks. This is not a hypothetical encoding edge case; it is a deterministic property of every scanned block containing such a coinbase.

### Recommendation
In `scan_block`, skip `block.txdata[0]` (the coinbase) or record the block height and filter/defer coinbase-derived `ReceivedOutput`s until maturity is reached. Alternatively, extend `ReceivedOutput` with a maturity/confirmation-status field so callers cannot mistake an immature coinbase output for a spendable one — i.e., check the item's status before acting on it, per the source bug's recommendation.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs
let scanner = Scanner::new(even_key).unwrap();

// Attacker mines a block whose coinbase pays to Serai's P2TR script
let coinbase_tx = Transaction {
  input: vec![coinbase_input],          // prevout = null -> is_coinbase() == true
  output: vec![TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: scanner_p2tr_script, // matches scanner.scripts
  }],
  ..Default::default()
};
let block = Block { header, txdata: vec![coinbase_tx] };

// scan_block returns the immature coinbase output as a normal ReceivedOutput
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].value(), 1_000_000);
// outputs[0].outpoint references txdata[0], which is unspendable for 100 blocks,
// yet is indistinguishable to the caller from a spendable payment.
```
Any code path that scans `block.txdata[0]` (e.g., `network.get_outputs`/`get_block` feeding `scan_block`) will report the coinbase output as received; an attempted spend builds an invalid transaction rejected by the network until maturity.
