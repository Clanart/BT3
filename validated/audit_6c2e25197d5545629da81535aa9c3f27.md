### Title
Out-of-bounds panic in auction bid signature recovery due to missing length check before indexing `SearcherSig`/`AuctioneerSig` - (File: kaiax/auction/bid.go)

### Summary
`getSigner()` in the auction module indexes into the raw signature byte slice (`copiedSig[crypto.RecoveryIDOffset]`, `copiedSig[0:32]`, `copiedSig[32:64]`) without first validating that the slice is at least `crypto.SignatureLength` (65) bytes long, mirroring the `btrtl` bug where `patch_length` was used to index/copy a buffer before validating it was long enough for the fixed-size version field.

### Finding Description
`Bid.ValidateSearcherSig` and `Bid.ValidateAuctioneerSig` both call `getSigner(sig, digest)` [1](#0-0) , which immediately does:
```go
copiedSig := slices.Clone(sig)
if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
``` [2](#0-1) 
`crypto.RecoveryIDOffset` is 64 [3](#0-2) . `SearcherSig` and `AuctioneerSig` are attacker-controlled `[]byte` fields on `BidData`, populated directly from RPC input in `SubmitBid`/`kaiax/auction/impl/api.go` (`BidInput.SearcherSig`/`AuctioneerSig`) and from P2P `BidMsg` decoding in `handleBidMsg` [4](#0-3) . Neither path enforces a minimum length before `getSigner` runs: if `sig` is shorter than 65 bytes (e.g., empty, 2 bytes as used in the existing test `invalidSearcherSigLenBid.SearcherSig = common.Hex2Bytes("1234")` [5](#0-4) ), indexing `copiedSig[64]` or slicing `copiedSig[32:64]` panics with an index-out-of-range runtime error rather than returning a controlled error.

This is structurally identical to the CVE: a length field/slice (`patch_length` / `SearcherSig` length) is used to index/copy a buffer (`patch_length - 4` / `copiedSig[64]`, `copiedSig[32:64]`) without validating the buffer is long enough first.

### Impact Explanation
A crafted RPC `debug_submitBid`/`auction_submitBid`-style call (or `BidMsg` from any consensus-node peer once auction module accepts external bid submission) with an undersized `searcherSig` or `auctioneerSig` triggers a Go slice-index panic inside signature validation. Depending on whether this panic is recovered at the call boundary (RPC handler middleware typically recovers panics, but the `BidMsg` P2P handler path may not have equivalent protection for every code path), this can crash the auction/bid processing goroutine or the node process, denying auction/bid service — a public-RPC/bid-submission reachable crash.

Whether existing test coverage (`invalidSearcherSigLenBid`) demonstrates this path currently returns `auction.ErrInvalidSearcherSig` cleanly suggests a length check exists upstream in the actual `SubmitBid` API flow (in `kaiax/auction/impl/api.go`) that this analysis did not fully trace to `getSigner`. This could not be conclusively verified — it's possible a `len(sig) != crypto.SignatureLength` check exists elsewhere before `getSigner` is invoked, in which case this specific panic path may already be mitigated for the RPC path but the raw `bid.go` function itself remains unsafe for any other caller (including P2P bid ingestion) that doesn't pass through that check.

### Likelihood Explanation
Medium: reachable by any party who can submit an auction bid over RPC or, if auction module bid propagation accepts bids from peers before validation, via P2P `BidMsg`. Exploitability requires only crafting a sub-65-byte signature field, which is trivial.

### Recommendation
Add an explicit length check at the top of `getSigner()`:
```go
func getSigner(sig, digest []byte) (common.Address, error) {
    if len(sig) != crypto.SignatureLength {
        return common.Address{}, ErrInvalidSignature
    }
    ...
}
```
This centralizes the bound check so all callers (`ValidateSearcherSig`, `ValidateAuctioneerSig`, and any future caller) are protected regardless of whether an upstream API layer already performs the check, closing the same class of bug as the `btrtl` fix (validate length/bounds before any indexing or copy).

### Proof of Concept
1. Construct a `BidInput`/`BidData` with `SearcherSig = []byte{0x12, 0x34}` (2 bytes) instead of the required 65-byte ECDSA signature.
2. Call `Bid.ValidateSearcherSig(chainId, verifyingContract, version)` directly, or submit via the path that calls it without a prior explicit `len(sig) == 65` check.
3. `getSigner` executes `copiedSig[crypto.RecoveryIDOffset]` where `crypto.RecoveryIDOffset == 64` on a 2-byte slice, causing `panic: runtime error: index out of range [64] with length 2`.

**Note on uncertainty:** I could not fully confirm from the indexed code whether `kaiax/auction/impl/api.go`'s `SubmitBid`/RPC entry point performs a `len(sig) == crypto.SignatureLength` check before calling `ValidateSearcherSig`/`ValidateAuctioneerSig` — the test file references `auction.ErrInvalidSearcherSig` for short-signature inputs, implying such a check likely exists somewhere in that call chain, but the exact location was not visible in the retrieved snippets. A Devin session with full repository access would be needed to trace the complete call path from `SubmitBid` through to `getSigner` to determine definitively whether the RPC path is already guarded, and whether the P2P `handleBidMsg` path (which calls `HandleBid` on decoded, unvalidated bids) reaches `getSigner` without an equivalent guard.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}
