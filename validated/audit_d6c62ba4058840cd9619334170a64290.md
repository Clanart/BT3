## Finding

### Title
Unbounded HTTP request body read in NewRelic RPC middleware causes memory exhaustion DoS - (File: networks/rpc/http_newrelic.go)

### Summary
When the NewRelic APM integration is enabled on a Kaia node's JSON-RPC HTTP server, every incoming request is first passed through `getRPCRequests`, which reads the **entire** HTTP request body with `io.ReadAll(r.Body)` before any content-length/size validation occurs. Unlike the normal request path (which wraps `r.Body` in `io.LimitReader(r.Body, common.MaxRequestContentLength)` before decoding), this pre-processing step imposes no size limit at all, allowing any public RPC caller to force the node to buffer an arbitrarily large request body into memory — the same bug class as the containerd OCI import advisory (unbounded read of untrusted input with no length limit, CWE-400/CWE-770).

### Finding Description
The standard JSON-RPC HTTP path enforces a size limit before reading the body: [1](#0-0) [2](#0-1) 

However, when NewRelic monitoring is configured (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` env vars set), `newNewRelicHTTPHandler` is installed as the **outermost** wrapper around the whole handler chain, so it runs on every request before `validateRequest`/`newHTTPServerConn` are ever reached: [3](#0-2) 

That outer handler calls `getRPCRequests(r)` to extract the RPC method name for tracing purposes: [4](#0-3) 

`getRPCRequests` reads the full body with `io.ReadAll(r.Body)`, with **no `io.LimitReader` and no `ContentLength` check**, unlike `newHTTPServerConn`'s `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))`: [5](#0-4) 

Only after this unlimited read completes does control pass to `handler.ServeHTTP(dupW, r)`, which eventually reaches `ServeHTTP`/`validateRequest` and enforces `common.MaxRequestContentLength`: [6](#0-5) 

Because Go's `net/http` server does not itself cap request body size (absent `http.MaxBytesReader`), and the `defer recover()` in the NewRelic handler only guards against panics — not against a large allocation triggering OOM — an attacker can send a POST body many times larger than `common.MaxRequestContentLength` and it will be fully materialized in memory via `io.ReadAll` before it is ever rejected.

### Impact Explanation
Any unauthenticated public RPC caller can send oversized HTTP POST requests to a Kaia node's RPC endpoint when NewRelic APM is enabled, causing the node to allocate memory proportional to the attacker-controlled body size with no upper bound. Repeated or concurrent large requests can exhaust available memory, leading to denial of service (node crash/OOM) — impacting availability of the RPC service and potentially the node process itself. This aligns with the CVSS vector of the analog advisory (`AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:N/A:H`), impacting only availability.

### Likelihood Explanation
Exploitation requires no special privileges — any client capable of reaching the JSON-RPC HTTP endpoint can trigger it — and requires only that the node operator has enabled NewRelic monitoring (a supported, documented feature via environment variables), which is a legitimate operational configuration rather than an adversarial one. Given RPC endpoints are commonly public-facing infrastructure, this is straightforward to trigger with a single crafted large HTTP request.

### Recommendation
Wrap `r.Body` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or `http.MaxBytesReader`) in `getRPCRequests` before calling `io.ReadAll`, mirroring the limit already applied in `newHTTPServerConn`. Alternatively, perform the same `validateRequest`/content-length check inside `newNewRelicHTTPHandler` before invoking `getRPCRequests`, so the size limit is enforced consistently regardless of handler wrapping order.

### Proof of Concept
1. Start a Kaia node with `NEWRELIC_APP_NAME` and `NEWRELIC_LICENSE` environment variables set to enable the NewRelic HTTP handler.
2. As an unauthenticated remote client, send an HTTP POST request to the node's JSON-RPC endpoint with a body far exceeding `common.MaxRequestContentLength` (e.g., several GB), with `Content-Length` either omitted/chunked or set to the actual oversized value.
3. `newNewRelicHTTPHandler` invokes `getRPCRequests(r)` which calls `io.ReadAll(r.Body)`, fully buffering the oversized payload into memory with no size check — before `validateRequest`'s `ContentLength` check is ever reached.
4. Repeating this with multiple concurrent oversized requests drives the node's memory usage up, resulting in denial of service.

```go
	if r.Method == http.MethodGet && r.ContentLength == 0 && r.URL.RawQuery == "" {
		return
	}
	if code, err := validateRequest(r); err != nil {
		http.Error(w, err.Error(), code)
		return
	}
```

```go
func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}
```

```go
func newNewRelicHTTPHandler(nrApp *newrelic.Application, handler http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if err := recover(); err != nil {
				logger.ErrorWithStack("NewRelic http handler panic", "err", err)
			}
		}()

		reqMethod := ""

		// parse RPC requests
		reqs, isBatch, err := getRPCRequests(r)
		if err != nil || len(reqs) < 1 {
			// The error will be handled in `handler.ServeHTTP()` and printed with `printRPCErrorLog()`
			logger.Debug("failed to parse RPC request", "err", err, "len(reqs)", len(reqs))
		} else {
			reqMethod = reqs[0].Method
			if isBatch {
				reqMethod += "_batch"
			}
		}
```

```go
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
```
