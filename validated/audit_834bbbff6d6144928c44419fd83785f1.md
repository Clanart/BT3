### Title
Spoofed `WWW-Authenticate` header from a malicious git remote bypasses GitHub-host verification and triggers a fake "Sign in to GitHub" flow bound to an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` in the git credential-helper trampoline classifies a remote endpoint as `'enterprise'` (i.e. "this is a GitHub host") solely because the *credential-helper input* contains a `wwwauth[...]` entry whose value includes `realm="GitHub"`. That value is nothing more than a `WWW-Authenticate` HTTP response header that git forwarded verbatim from whatever server answered the request. A malicious or MITM'd git server can therefore forge this classification for an arbitrary host it controls, without ever passing the app's actual GitHub-detection check (`isGitHubHost`), which requires seeing an `x-github-request-id` header on a real HTTPS discovery request. [1](#0-0) 

### Finding Description
When a git operation (clone/fetch/push against a remote the user has added, or an upstream/`insteadOf`-rewritten URL) requires HTTP auth, Git invokes Desktop's credential helper trampoline (`createCredentialHelperTrampolineHandler`) with the credential fields it collected, including any `wwwauth[]` entries copied straight from the server's `WWW-Authenticate` response header. [2](#0-1) 

`getCredential()` first tries `getGitHubCredential()`, which only matches existing stored accounts by origin, so it is not attacker-influenced for hosts the user hasn't already signed into. If that fails, it calls `getEndpointKind()`: [3](#0-2) 

`getEndpointKind()` checks `isDotCom`/`isGHE`/known account first, but for an arbitrary unknown host it falls back to trusting the raw `wwwauth[]` value before ever calling the "real" verification function `isGitHubHost` (which performs an HTTPS `HEAD /meta` request and checks for the `x-github-request-id` header, a value that cannot be forged by an arbitrary HTTP endpoint the same way a `WWW-Authenticate` realm string can): [4](#0-3) [5](#0-4) 

Because the attacker-controlled `realm="GitHub"` string short-circuits this logic and forces `endpointKind = 'enterprise'`, and because no stored account will match this arbitrary host (`apiEndpoint`), `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` being the attacker's own remote URL: [6](#0-5) 

`promptForGitHubSignIn()` then unconditionally treats the attacker's host as a genuine GitHub Enterprise instance, calling `dispatcher.beginEnterpriseSignIn()` and `setSignInEndpoint(origin)` with the attacker's origin, and shows a "Sign in" popup labeled as a GitHub credential-helper sign-in: [7](#0-6) 

This starts Desktop's real GitHub Enterprise OAuth sign-in UX (`SignInStep.Authentication`/browser-based OAuth flow in `sign-in-store.ts`) but pointed at an endpoint the attacker fully controls, with no host verification beyond the forged header.

### Impact Explanation
The corrupted value is the credential-helper's `endpointKind` classification (and downstream `credentialHelperUrl`/sign-in `endpoint`), which Desktop treats as authoritative proof "this is GitHub" purely from an untrusted header echoed by the remote server being contacted (the same party that is the attacker). This lets an attacker who merely operates a git remote (e.g., published as a clone URL, an `insteadOf` rewrite target, or a MITM/malicious proxy) induce Desktop to:
- Display a GitHub-branded "Sign in" dialog for an endpoint the attacker chose, rather than a generic-git-auth prompt — a UI/trust-indicator forgery that primes the user to enter GitHub-style OAuth credentials against the attacker's infrastructure (unauthorized OAuth/account-binding risk called out as valid impact).
- If the user completes the flow, the resulting `Account` is persisted and bound to the attacker's endpoint, and its token is subsequently handed back to git (`credWithAccount`) for that host, and reused by Desktop for any future request whose host matches that origin.

This bypasses the one guard the codebase already has for genuine GitHub-host detection (`isGitHubHost`'s `x-github-request-id` check), because the `wwwauth[]` branch is evaluated first and returns unconditionally.

### Likelihood Explanation
No local access, admin rights, or pre-existing malware is required. The only precondition is that the user performs a normal git operation (clone/fetch/push) against a remote controlled by the attacker, or that a git operation traverses a malicious/compromised HTTP proxy or MITM server — both fall within "attacker controls...a git remote/proxy response" from the stated valid-impact scope. Sending a crafted `WWW-Authenticate: Basic realm="GitHub"` header on a 401 response is trivial for any HTTP server the attacker controls.

### Recommendation
Do not use the `wwwauth[]` realm string as sufficient evidence that a host is GitHub/GHE. Either drop this heuristic entirely and always fall back to the certificate/`x-github-request-id`-based `isGitHubHost()` check, or require that heuristic to be corroborated by an actual `isGitHubHost()` call before classifying an unknown host as `'enterprise'` and before invoking `promptForGitHubSignIn()`.

### Proof of Concept
1. Attacker stands up an HTTPS git server (or MITM proxy) at `https://evil.example.com/repo.git`.
2. On any authenticated request (e.g. `GET /repo.git/info/refs`), the server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds/uses this URL as a remote in GitHub Desktop and performs a Fetch/Clone.
4. Git invokes the credential helper trampoline with `wwwauth[0]=Basic realm="GitHub"` in stdin.
5. `getEndpointKind()` returns `'enterprise'` purely from this header (`trampoline-credential-helper.ts:157-165`), skipping `isGitHubHost()`.
6. `getCredential()` finds no matching stored account for `evil.example.com` and calls `promptForGitHubSignIn('https://evil.example.com/repo.git')` (`trampoline-credential-helper.ts:118`).
7. Desktop shows a "Sign in" dialog and initiates a GitHub Enterprise OAuth flow bound to `evil.example.com` (`trampoline-ui-helper.ts:87-98`), which the victim may reasonably believe is a legitimate GitHub prompt because Desktop itself surfaced it as such.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
