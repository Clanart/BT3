### Title
Unauthenticated access to `ClementineAggregator`'s internal and state-mutating gRPC methods when `client_verification=false` - ([File: core/src/servers.rs], [File: core/src/rpc/interceptors.rs])

### Summary
`create_grpc_server` in `core/src/servers.rs` only builds the `Certificate`-based client CA root and the `OnlyAggregatorAndSelf` interceptor when `config.client_verification` is `true`; when it is `false`, the TLS listener is built without `.client_ca_root(...)` and the service is wrapped with `Interceptors::Noop`, which unconditionally forwards every request. Since `only_aggregator_and_self` (the only code that enforces caller identity, including the `is_internal` "Internal*" method gate) lives entirely inside the `OnlyAggregatorAndSelf` variant, setting `client_verification=false` removes both the mTLS client-cert requirement and the identity check from the aggregator's gRPC port at once.

### Finding Description
The binding the system is supposed to guarantee is:
`CALLER_AUTHORITY == true` **iff** `peer_leaf_cert == aggregator_cert_path` (for normal methods) **or** `peer_leaf_cert == client_cert_path` (for `Internal*` methods), as enforced by `only_aggregator_and_self` in `core/src/rpc/interceptors.rs:36-77`.

That check is only reachable through the `Interceptors::OnlyAggregatorAndSelf` variant selected in `core/src/servers.rs`:
```
let service = InterceptedService::new(
    service,
    if config.client_verification {
        ... OnlyAggregatorAndSelf { aggregator_cert, our_cert: client_cert }
    } else {
        Noop
    },
);
```
`Interceptors::Noop::call` (core/src/rpc/interceptors.rs:30) is `Ok(req)` unconditionally — no certificate is inspected. Additionally, when `client_verification` is `false`, the `ServerTlsConfig` is built without `.client_ca_root(client_ca)` (core/src/servers.rs:106-112), so the TLS handshake itself does not request/require a client certificate. `create_aggregator_grpc_server` (core/src/servers.rs:293-317) only logs `tracing::warn!` when verification **is** enabled; it takes no action, and does not refuse to start, when it is disabled — there is no compensating control anywhere else on this path.

With `client_verification=false`, an attacker can complete a one-sided TLS handshake to the aggregator's port (server presents its identity; no client identity is required or checked) and call any RPC exposed by `ClementineAggregator`, including `Internal*`-prefixed methods, because `is_internal`'s gate (core/src/rpc/interceptors.rs:12-20, 62-69) is never invoked. Structurally analogous internal handlers (e.g. `Aggregator::send_emergency_stop_tx`, core/src/rpc/aggregator.rs:927-958) push an attacker-supplied `bitcoin::Transaction` into `self.tx_sender.insert_try_to_send(...)`, which is the same queue used to eventually broadcast/fee-bump transactions.

The evaluated equality before vs. after: before, `only_aggregator_and_self` guarantees the check runs on every request reaching an aggregator method; after (with `client_verification=false`), the interceptor call graph never executes that function at all — the equality is vacuously "true" for any caller, breaking `CALLER_AUTHORITY`.

### Impact Explanation
Any caller reaching the aggregator's port without holding the aggregator or self client certificate can invoke methods that mutate protocol state or push transactions into the broadcast/fee-bumping queue (`InternalSendTx` and other `Internal*` methods), and can additionally invoke `Setup`, `NewDeposit`, `Withdraw`, `OptimisticPayout` which are normally reserved to callers matching `aggregator_cert_path`/`client_cert_path`. This matches the High category: "an unauthenticated state-changing or broadcasting call." The attacker does not gain the ability to forge N-of-N signatures for a bridge UTXO (musig2 partial signatures still require verifier key shares), so this does not by itself allow BTC to leave a move-to-vault UTXO without a fronted withdrawal; the concrete demonstrated impact is unauthenticated invocation of state-changing/broadcasting RPCs. This is repeatable per request and is not scoped to a single deposit — every deployed aggregator instance with this setting is affected identically.

### Likelihood Explanation
This requires the deployer to actually set `client_verification=false`. Every configuration file found in the repository (`core/src/test/data/bridge_config.toml:73`, `scripts/docker/configs/testnet4/bridge_config.toml:77`, `.env.example:82`) sets `client_verification=true`; I found no `BridgeConfig::default()` value confirming `false` is the shipped default (the struct's `Default` impl was not located in the excerpts examined, so the audit prompt's claim that `false` is "the documented default" is not substantiated by the configuration files in this repo — it appears to be an opt-out, not the shipped default). If an operator does disable it (e.g., for the aggregator specifically, as the code comment/log implies is a supported deployment mode), exploitation costs the attacker only network reachability to the port — no BTC, no key, no certificate.

### Recommendation
Do not allow `client_verification=false` to also disable the caller-identity interceptor. At minimum, for the aggregator: always require `.client_ca_root(...)` on the TLS listener and always use `OnlyAggregatorAndSelf` (or a stricter aggregator-specific interceptor) regardless of `client_verification`, or fail startup (`check_mainnet_requirements`/`check_general_requirements`) if `client_verification=false` for `Command::Aggregator`. Remove or gate the `Interceptors::Noop` path so it cannot be selected for any production/internet-reachable listener.

### Proof of Concept
```
// core/src/test/rpc_auth.rs style test
#[tokio::test]
async fn test_noop_interceptor_allows_unauthenticated_internal_call() -> Result<(), eyre::Report> {
    let mut config = create_test_config_with_thread_name().await;
    config.client_verification = false; // disable mTLS enforcement
    let port = find_available_port().await;
    config.host = "127.0.0.1".into();
    config.port = port;

    let (_addr, _shutdown) = create_aggregator_grpc_server(config.clone()).await?;

    // Connect with a channel that presents NO client identity at all.
    let endpoint = tonic::transport::Channel::from_shared(format!("https://127.0.0.1:{port}"))?
        .tls_config(tonic::transport::ClientTlsConfig::new().with_native_roots())? // no .identity(...)
        .connect()
        .await?;
    let mut client = ClementineAggregatorClient::new(endpoint);

    // BEFORE: only_aggregator_and_self should have rejected this; assert it is bypassed.
    let resp = client.internal_send_tx(SendTxRequest {
        raw_tx: attacker_signed_tx_bytes.clone(),
        fee_type: FeeType::Rbf as i32,
    }).await;
    assert!(resp.is_ok(), "unauthenticated caller must not reach InternalSendTx");
}
```
Assert on both sides of the binding: before the fix, `peer_certs()` is never consulted (`Interceptors::Noop`) and the call succeeds; after enforcing `OnlyAggregatorAndSelf` unconditionally, the same call must return `Status::unauthenticated`.
