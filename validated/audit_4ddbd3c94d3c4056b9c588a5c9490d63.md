### Title
Unbounded balance migration for unassociated EVM addresses allows attackers to grief a victim's first EVM transaction / association - ([File: utils/helpers/associate.go])

### Summary
The EVM ante pipeline migrates all Cosmos-side balances from an address's "cast" account (`sdk.AccAddress(evmAddr[:])`) to its associated Sei address the first time an EVM address transacts or is associated. This migration calls `SpendableCoins`, which iterates every denom balance held by the cast account with no cap, mirroring the OpenQ `getLockedFunds` pattern of iterating an attacker-inflatable list with no maximum-size guard.

### Finding Description
`EVMPreprocessDecorator.AnteHandle` sets an **infinite gas meter** before performing address association/migration for any not-yet-associated EVM sender: [1](#0-0) 

For any unassociated sender it calls `AssociationHelper.AssociateAddresses`, which in turn calls `MigrateBalance`: [2](#0-1) 

`MigrateBalance` calls `p.bankKeeper.SpendableCoins(ctx, castAddr)` to fetch **every coin denom** held by the cast address (`sdk.AccAddress(evmAddr[:])`), then sends the entire `sdk.Coins` set in one `SendCoins` call. `SpendableCoins`/`GetAllBalances` perform a full KV-store prefix iteration over the account's balance keys with no pagination or maximum-denom cap, unlike the OpenQ report's `getLockedFunds` iterating `BountyCore.deposits` without any length limit.

Because Sei's tokenfactory module allows **any unprivileged account** to create new denoms cheaply and send arbitrary amounts of each to any address without permission, an attacker can:
1. Compute the victim's `castAddr = sdk.AccAddress(evmAddr[:])` from their public EVM address (no association needed to compute this).
2. Create a very large number of distinct tokenfactory (or native) denoms.
3. Send a small amount of each denom to `castAddr`.

When the victim later submits their first EVM transaction (or an `Associate` transaction), the ante-handler's `MigrateBalance`/`SpendableCoins` call must iterate and move **all** of these attacker-created balances, and this happens under the infinite gas meter set at line 65 of `preprocess.go`, so it is not bounded by the transaction's gas limit and cannot fail with an out-of-gas ante error. Instead it can consume unbounded wall-clock time/CPU inside block processing.

### Impact Explanation
This does not risk direct fund theft, but it can:
- Prevent a targeted victim from ever completing their first EVM transaction/association (the ante step effectively never returns in a timely manner), a form of griefing/permanent denial of association for that specific account.
- Because the migration runs synchronously inside `ProcessBlock`/`DeliverTx` with no gas bound, a sufficiently large attacker-crafted balance set can make block processing for that block take excessive time, risking block delay beyond the network's target block time, which the rules explicitly recognize as a qualifying impact.

### Likelihood Explanation
The prerequisites are fully reachable by an unprivileged actor: tokenfactory denom creation is permissionless (subject only to a creation fee), and sending tokens to an arbitrary address requires no permission from the recipient. The victim's cast address is deterministically derivable from their public EVM address before they ever transact. The attack requires no special privileges, validator collusion, or contract bugs beyond the missing bound in `SpendableCoins`/`MigrateBalance`.

### Recommendation
Bound the migration path:
- Cap the number of denoms considered during cast-address migration (e.g., migrate only up to N denoms per call, or require an explicit, gas-metered follow-up call/message to migrate any denom beyond a fixed cap), and/or
- Avoid running `MigrateBalance` under an infinite gas meter — meter this operation against a fixed budget and fail predictably (with a clear error) rather than looping unbounded, similar to how the OpenQ recommendation proposes capping loop length instead of leaving it unbounded.
- Alternatively, since native token transfers from `castAddr` (`usei`) are the security-critical case, consider migrating only the base denom by default (as already offered via the `migrateUseiOnly` flag in `MigrateBalance`) for the address-derivation/first-tx codepath, and require an explicit opt-in/rate-limited path for migrating arbitrary long-tail denoms.

### Proof of Concept
1. Victim's public EVM address (and hence `castAddr = sdk.AccAddress(evmAddr[:])`) is known/observed on-chain (e.g., posted to interact with a dApp) before the victim ever sends a Sei-side EVM transaction.
2. Attacker calls `MsgCreateDenom` (tokenfactory) repeatedly to create a large number (e.g., tens of thousands) of distinct denoms — permissionless, limited only by the creation fee. [3](#0-2) 
3. Attacker sends 1 unit of each denom to `castAddr` via ordinary `MsgSend`s — no permission from the victim required.
4. Victim submits their first EVM transaction. `EVMPreprocessDecorator.AnteHandle` detects the sender is unassociated and calls `AssociateAddresses -> MigrateBalance -> bankKeeper.SpendableCoins(ctx, castAddr)`, which must enumerate all attacker-planted denoms and build/send a huge `sdk.Coins` set, running under the infinite gas meter set moments earlier in the same handler. [4](#0-3) [5](#0-4) 
5. The resulting excessive iteration/CPU cost inside block execution can delay or effectively block the victim's transaction from completing in a normal timeframe, and can slow down block production for the block containing it.

Note: I was not able to directly inspect `sei-cosmos/x/bank/keeper/view.go`'s `SpendableCoins`/`GetAllBalances` implementation in this pass (only located it via `grep_search`) to confirm the exact iteration mechanics and whether any existing denom cap applies there; this should be verified in a full session before treating the impact bound as unlimited in practice.

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

package keeper

import (
	sdk "github.com/sei-protocol/sei-chain/sei-cosmos/types"
	"github.com/sei-protocol/sei-chain/sei-cosmos/types/query"
)

func (k Keeper) addDenomFromCreator(ctx sdk.Context, creator, denom string) {
	store := k.GetCreatorPrefixStore(ctx, creator)
	store.Set([]byte(denom), []byte(denom))
}

func (k Keeper) getDenomsFromCreator(ctx sdk.Context, creator string, pagination *query.PageRequest) ([]string, *query.PageResponse, error) {
	store := k.GetCreatorPrefixStore(ctx, creator)
	var denoms []string
	pageRes, err := query.Paginate(ctx, store, pagination, func(key []byte, _ []byte) error {
		denoms = append(denoms, string(key))
		return nil
	})
	if err != nil {
		return nil, nil, err
	}
	return denoms, pageRes, nil
}

// GetAllDenomsFromCreator returns every denom for a creator with no page cap.
// Safe to use in the wasm query path: gas metering bounds execution cost, so unbounded iteration does not pose a DoS risk.
func (k Keeper) GetAllDenomsFromCreator(ctx sdk.Context, creator string) []string {
	store := k.GetCreatorPrefixStore(ctx, creator)
	iterator := store.Iterator(nil, nil)
	defer func() { _ = iterator.Close() }()
	var denoms []string
	for ; iterator.Valid(); iterator.Next() {
		denoms = append(denoms, string(iterator.Key()))
	}
	return denoms
}

func (k Keeper) GetAllDenomsIterator(ctx sdk.Context) sdk.Iterator {
	return k.GetCreatorsPrefixStore(ctx).Iterator(nil, nil)
}
