## Analysis

The ThunderNFT bug's core flaw is: **a security-relevant decision is made from mutable/untrusted state instead of ground truth, and no re-validation happens once that state changes**, letting an attacker-influenced condition steer the code into an unsafe branch that the original guard was meant to prevent.

The closest verifiable analog in this GitHub Desktop codebase is in the Git credential trampoline's host-classification logic, which decides whether to treat an arbitrary remote endpoint as a trusted "GitHub" host based on a header **supplied by the remote server itself**, bypassing the actual verification check that exists for exactly this purpose. [1](#0-0) 

### Title
Spoofable `WWW-Authenticate: realm="GitHub"` header lets a malicious remote/proxy trigger an unverified GitHub Enterprise sign-in/account-binding flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` classifies a Git remote endpoint as `'enterprise'` (GitHub-hosted) solely because a `WWW-Authenticate` header captured during credential fill contains the substring `realm="GitHub"`, without any network-based verification. This classification is attacker-controlled (any HTTP server the user's Git client talks to — including a malicious clone/fetch remote or a MITM proxy — can emit that header), and it is used before the codebase's own legitimate verification path (`isGitHubHost(endpoint)`) is ever reached.

### Finding Description
`getCredential` calls `getEndpointKind(cred, store)` to decide how to resolve credentials for a remote URL: [2](#0-1) 

Inside `getEndpointKind`, before ever calling the real host-verification function `isGitHubHost(endpoint)`, the code trusts caller-supplied `wwwauth[]` header content: [3](#0-2) 

```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
```

These `wwwauth[]` fields originate from the `WWW-Authenticate` HTTP response header of the remote Git server, forwarded by Git's credential-fill protocol into `parseCredential`/`fillCredential`: [4](#0-3) 

Because any server the app talks to over Git HTTP(S) — a cloned/fetched remote, or a MITM-capable proxy the environment already routes traffic through — fully controls its own response headers, an attacker can simply answer with `401 WWW-Authenticate: Basic realm="GitHub"` to force `getEndpointKind` to return `'enterprise'` for an endpoint that is not actually a GitHub Enterprise server. The real verification, `isGitHubHost(endpoint)` (which presumably performs an out-of-band check), is only reached in the fallback branch and is therefore skipped entirely for this attacker-controlled path.

Once classified as `'enterprise'`, if no existing account matches the attacker's endpoint, `getCredential` invokes `ui.promptForGitHubSignIn(endpoint)`: [5](#0-4) 

`promptForGitHubSignIn` then drives a real Enterprise OAuth sign-in flow scoped to the attacker's own origin: [6](#0-5) 

The resulting sign-in flow (`beginEnterpriseSignIn` / `authenticateWithBrowser` / `resolveOAuthRequest`) opens the OAuth authorization URL and exchanges the code, entirely against the attacker-chosen endpoint: [7](#0-6) 

This is the same broken-invariant shape as the ThunderNFT report: a downstream security gate (`is_asset_supported` there, `isGitHubHost`/account-endpoint match here) is supposed to be the authority on trust, but a separate, attacker-influenced signal (`asset_manager` removal state there, remote-supplied `WWW-Authenticate` header here) is allowed to short-circuit that gate and steer execution into a privileged path (withdrawal blocked there; unauthorized enterprise sign-in/account-binding flow triggered here).

### Impact Explanation
A successful completion of this flow results in an "account" whose token and profile data were fully sourced from the attacker's endpoint being created and stored in `AccountsStore`, tied to the attacker's chosen hostname. Any Git credential request Desktop makes for that same host afterward will preferentially resolve via `findGitHubTrampolineAccount` (origin match), meaning the attacker-provided token becomes the "legitimate" GitHub credential for that endpoint going forward — this is unauthorized OAuth/account binding driven purely by a spoofable header, not by any real verification that the endpoint is a GitHub Enterprise server.

### Likelihood Explanation
This requires only that the user perform a normal Git network operation (`clone`, `fetch`, `pull`, `push`) against a repository/remote controlled by, or proxied through, an attacker — no local access, malware, or leaked credentials are needed. The trigger is a single crafted HTTP response header, which is trivial to serve. The main mitigating factor is that the resulting "Sign in to GitHub Enterprise" dialog does display the endpoint URL (`credentialHelperUrl: endpoint`), so an attentive user could notice the unexpected prompt/hostname — this lowers likelihood of full exploitation but does not prevent the flawed classification/flow from being reached.

### Recommendation
In `getEndpointKind`, do not treat the `wwwauth[]` header content as sufficient to classify a host as GitHub Enterprise; always perform (or at minimum precede/gate the header-based fast path with) the network-based `isGitHubHost(endpoint)` verification before triggering `promptForGitHubSignIn`/`beginEnterpriseSignIn` for a previously-unknown endpoint.

### Proof of Concept
1. Attacker sets up an HTTP server (or a MITM proxy for a target's Git traffic) at `https://evil.example.com`.
2. User adds/clones/fetches a repository whose remote URL is `https://evil.example.com/repo.git` in GitHub Desktop.
3. When Git performs the HTTP request and receives a `401` challenge, the attacker's server responds with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git's credential-fill invokes the trampoline helper with a `wwwauth[]` field containing that value; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`) matches `realm="GitHub"` and returns `'enterprise'` without calling `isGitHubHost`.
5. Since no stored account matches `evil.example.com`, `getCredential` (`app/src/lib/trampoline/trampoline-credential-helper.ts:109-125`) calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
6. `promptForGitHubSignIn` (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-99`) launches `beginEnterpriseSignIn` against `evil.example.com`, opening an OAuth flow entirely controlled by the attacker's server, which can return an arbitrary token/user profile that gets persisted as a Desktop "account" for that endpoint.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

import { exec as git } from 'dugite'

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

    return new Promise<Account | undefined>(async resolve => {

        await this.dispatcher.setSignInEndpoint(origin)

        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
