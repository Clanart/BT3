### Title
Python protobuf's TextFormat/`__str__`/`__repr__` never honor `debug_redact`, unconditionally printing fields marked sensitive-for-debug — (File: `python/google/protobuf/text_format.py`, `python/google/protobuf/internal/python_message.py`)

### Summary
The `debug_redact` `FieldOptions` extension (`src/google/protobuf/descriptor.proto:778`) is a schema-declared, security-relevant contract: "Indicate that the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials." Every other checked runtime enforces it on its default debug-string paths — C++'s `Message::DebugString()/ShortDebugString()/Utf8DebugString()` explicitly set `redact_debug_string_=true` before printing [1](#0-0) , and `TryRedactFieldValue`/`GetRedactionState` consult `debug_redact` to substitute `[REDACTED]` [2](#0-1) ; Java's `TextFormat.Printer.shouldRedact()`/`DebugFormat` do the analogous check when `enablingSafeDebugFormat` is set [3](#0-2) . In the Python implementation, `debug_redact`/`DebugRedact` is referenced nowhere in `text_format.py` (0 matches), and the default `__str__`/`__repr__` on every generated message simply call `text_format.MessageToString(self)` with no redaction path at all [4](#0-3) .

### Finding Description
The invariant that transfers from the report is: "a security-relevant behavior (an authorization/redaction check) that every sibling code path enforces, but one specific path in the same feature family silently omits, causing sensitive data to be disclosed to a party that trusted the check to be uniformly applied." In vttablet, the sibling paths are debug HTTP handlers and the omitted check is `acl.CheckAccessHTTP`. In protobuf, the sibling "debug output" paths are `DebugString()`/`ShortDebugString()`/`Utf8DebugString()`/`AbslStringify` in C++ and `DebugFormat`/`TextFormat.debugFormatPrinter()` in Java, all of which consult the `debug_redact` field option before emitting field values, and the omitted path is Python's `str(message)`/`repr(message)`/`text_format.MessageToString(message)`, which never looks at `debug_redact` at all.

This is reachable by an ordinary consuming application: any Python service that (a) uses a trusted, valid `.proto` schema in which an operator has marked a field `[debug_redact = true]` (e.g. a credential, token, or PII field) expecting that behavior to hold across the officially supported protobuf debug-string APIs, and (b) logs or displays a message via `str(msg)`, `repr(msg)`, `f"{msg}"`, or `text_format.MessageToString(msg)` — the same set of APIs that in C++/Java are the ones that actually enforce redaction. The field value flows straight through `PrintMessage`/`PrintField` in `text_format.py` with no `debug_redact` lookup, so the raw sensitive value is emitted in cleartext, defeating the schema-declared expectation that this field is protected under debug formatting.

### Impact Explanation
Confidentiality impact only, matching the CWE-862 (missing authorization/check) class and the medium severity of the source report: no memory corruption, no write capability, no crash — purely an information-disclosure/contract-bypass issue. The blast radius is every Python application that (1) defines fields with `debug_redact = true` specifically to prevent them from appearing in logs/debug output (the documented purpose of the option) and (2) relies on `str()`/`repr()`/`MessageToString()` to honor that contract the same way the C++ and Java runtimes do. Because Python is one of the officially supported protobuf runtimes and shares the same `.proto` schema/option semantics as C++/Java, an operator who annotated a field as `debug_redact=true` in a shared `.proto` file — trusting the security contract documented in `descriptor.proto` — gets silent, unredacted disclosure specifically in the Python runtime while believing the protection is uniform across languages.

### Likelihood Explanation
High likelihood of occurrence in practice: `__str__`/`__repr__` are the default, implicit way Python code renders messages into logs, exceptions, and debug traces, so any accidental `logging.info(str(request))` or f-string interpolation of a message containing a `debug_redact` field trivially leaks the value. No attacker action beyond normal application logging/observability is required; this is a straightforward, deterministic bypass of a documented redaction contract, not a probabilistic race or edge case. It requires no privileged access and no malformed input — a completely valid, trusted schema and normal message content are sufficient to demonstrate the gap by code inspection (`text_format.py` has zero references to `debug_redact`/`redact`).

### Recommendation
Port the `debug_redact` check into `python/google/protobuf/text_format.py`'s `PrintMessage`/`PrintField` path (and any place implementing `MessageToString`/`__str__`/`__repr__`), mirroring the C++ `TryRedactFieldValue`/`GetRedactionState` logic [2](#0-1)  and the Java `TextFormat.Printer.shouldRedact()` logic [3](#0-2) : before printing a field's value, look up `field.GetOptions().debug_redact` (including the enum-based indirect redaction markers used by C++/Java) and substitute a `[REDACTED]`-style placeholder when true, at minimum for the default `__str__`/`__repr__`/`MessageToString()` entry points that are the Python analogs of `DebugString()`.

  // Indicate all scoped reflection calls are from DebugString function.

  TextFormat::Printer printer;

  switch (option) {
    case Option::kShort:
      printer.SetSingleLineMode(true);
      break;

      printer.SetUseUtf8StringEscaping(true);

}

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}
bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    // option must be on. 2) The field must be considered "sensitive". A sensitive field can be

      FieldDescriptor.RedactionState state = field.getRedactionState();
