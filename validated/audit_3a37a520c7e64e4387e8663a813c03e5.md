## Title
Cosmos EVM precompiles charge zero gas on invalid/unknown method selectors, enabling a compute-amplification DoS via looped static calls - (File: `precompiles/common/precompile.go`, `precompiles/bank/bank.go`, `precompiles/staking/staking.go`, `precompiles/distribution/distribution.go`, `precompiles/gov/gov.go`, `precompiles/slashing/slashing.go`, `precompiles/ics20/ics20.go`, `precompiles/erc20/erc20.go`)

### Summary
This is the same bug class as the referenced minievm H-08 finding: stateful precompiles compute their EVM gas charge from the ABI method resolved from the 4-byte selector, but when the selector does not resolve to a known method, `RequiredGas` returns `0` and the subsequent `Run`/`Execute` path fails before any gas is ever deducted from the calling contract. This lets an attacker loop precompile calls with a bogus/garbage selector, forcing the node to repeatedly perform real work (Cosmos SDK multi-store snapshotting, cache-context creation, journal bookkeeping, ABI method-map lookups) essentially for free.

### Finding Description
Every stateful Cosmos EVM precompile in this repo (`bank`, `staking`, `distribution`, `gov`, `slashing`, `ics20`, `erc20`, `werc20`) implements `RequiredGas` in the same pattern: [1](#0-0) 

If `len(input) < 4` or `MethodById` fails to resolve the selector, `RequiredGas` returns `0` with the comment "This should never happen since this method is going to fail during Run" — but it *can* happen, deliberately, from attacker-controlled call data. The same pattern repeats in `distribution.go`, `gov.go`, `slashing.go`, `staking.go`, and `ics20.go`: [2](#0-1) [3](#0-2) [4](#0-3) 

In standard go-ethereum precompile dispatch, the EVM first deducts `RequiredGas(input)` from the caller's remaining gas *before* invoking `Run`. When `RequiredGas` returns `0` for a malformed/unknown selector, this pre-charge is a no-op.

Once inside `Run`, execution flows through `RunNativeAction` → `runNativeAction`, which performs non-trivial Cosmos SDK work — obtaining a cache context, taking a multi-store snapshot, appending to the state DB journal, and committing the cache context — *before* the target method logic (and its real gas accounting) ever runs: [5](#0-4) 

The actual gas cost is only charged at the end via `contract.UseGas(cost, ...)` on line 115, computed from `ctx.GasMeter().GasConsumed() - initialGas`. But if `action(ctx)` (i.e., `Execute`, which calls `cmn.SetupABI`) returns an error — which happens immediately for an unresolvable method ID or a failed `Inputs.Unpack` — the function returns early at line 109-111, **before** reaching the `contract.UseGas` call at line 115: [6](#0-5) 

`SetupABI` itself resolves the method and unpacks arguments, and returns an error without any gas being consumed for that CPU/state work: [7](#0-6) 

The net effect: a `STATICCALL`/`CALL` to any of these precompiles with a garbage 4-byte selector consumes the pre-charge from `RequiredGas` (which is `0`), performs real SDK state/snapshot work in `runNativeAction`, and then reverts without ever calling `contract.UseGas`. Only the outer EVM call-opcode overhead (e.g., ~100 gas warm `STATICCALL`) is charged, exactly mirroring the minievm PoC pattern where a loop contract could call the precompile with an unknown selector until it ran out of gas while the real wall-clock cost vastly exceeded the gas paid.

### Impact Explanation
An unprivileged EVM caller can deploy a trivial loop contract that repeatedly `staticcall`s any of these precompiles (bank, staking, distribution, gov, slashing, ics20, erc20, werc20) with a bogus selector. Each iteration costs only the fixed opcode gas for the call (no proportional charge for the actual snapshot/cache-context/journal work performed inside `runNativeAction`), so an attacker can pack far more real computational work into a block than the gas limit is supposed to allow. This is a gas-metering/consensus-safety invariant break reachable by any ordinary transaction, matching the "chain halt / non-determinism triggerable via ordinary transaction flow" impact category — a single transaction can be crafted so that execution wall-clock time is disproportionate to gas charged, threatening block-time targets and enabling a network-wide DoS if abused across many transactions/blocks.

### Likelihood Explanation
High likelihood: no privileged access is required, and the vulnerable code path (`RequiredGas` returning 0 for malformed input, `Run`/`Execute` erroring out before `contract.UseGas`) is present uniformly across essentially all stateful precompiles in the module and is trivially reachable by sending any transaction/contract call with an invalid method selector.

### Recommendation
Charge a static minimum gas cost for every precompile invocation before attempting method resolution/ABI decoding, or ensure the input-length/flat cost is deducted via `contract.UseGas` even when `SetupABI`/`Execute` fails early. Concretely, in `runNativeAction` (`precompiles/common/precompile.go`), compute and charge the flat/per-byte cost (as done by `RequiredGas`) unconditionally — even on the error path — before returning, rather than skipping `contract.UseGas` when `action(ctx)` errors. Equivalent to the `minievm` recommendation: consume the input-based gas cost before returning any error from `SetupABI`/`MethodById`/`Unpack` failures.

### Proof of Concept
1. Deploy a minimal bytecode loop contract (analogous to the referenced report's `getLoopBytecode()`) that repeatedly issues `STATICCALL` to a Cosmos EVM precompile address (e.g., the bank precompile at `evmtypes.BankPrecompileAddress`) with a 4-byte garbage selector that does not match any ABI method.
2. Because `RequiredGas` returns `0` for unresolved selectors [8](#0-7) , the EVM pre-charge for each call is `0`.
3. Inside `Run`, `runNativeAction` performs cache-context creation, multi-store snapshotting, and journal bookkeeping [9](#0-8)  before `Execute`/`SetupABI` errors out on the unresolved method ID, causing an early return that bypasses `contract.UseGas` [6](#0-5) .
4. Loop this call until the EVM's outer opcode gas (e.g., ~100 gas per warm `STATICCALL`) is exhausted, while measuring wall-clock execution time versus the fixed block gas limit — reproducing the same disproportion demonstrated in the minievm PoC (`~2.1s` execution for a `30M` gas block).

func (p Precompile) RequiredGas(input []byte) uint64 {
	// NOTE: This check avoid panicking when trying to decode the method ID
	if len(input) < 4 {
		return 0
	}

	method, err := p.MethodById(methodID)
	if err != nil {
		// This should never happen since this method is going to fail during Run
		return 0
	}

	switch method.Name {
	case BalancesMethod:
		return GasBalances
	case TotalSupplyMethod:
		return GasTotalSupply
	case SupplyOfMethod:
		return GasSupplyOf
	}

	return 0
}

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

// SetupABI runs the initial setup required to run a transaction or a query.
// It returns the ABI method, initial gas and calling arguments.
func SetupABI(
	api abi.ABI,
	contract *vm.Contract,
	readOnly bool,
	isTransaction func(name *abi.Method) bool,
) (method *abi.Method, args []interface{}, err error) {
	// NOTE: This is a special case where the calling transaction does not specify a function name.
	// In this case we default to a `fallback` or `receive` function on the contract.

	// Simplify the calldata checks
	isEmptyCallData := len(contract.Input) == 0
	isShortCallData := len(contract.Input) > 0 && len(contract.Input) < 4
	isStandardCallData := len(contract.Input) >= 4

	switch {
	// Case 1: Calldata is empty
	case isEmptyCallData:
		method, err = emptyCallData(api, contract)

	// Case 2: calldata is non-empty but less than 4 bytes needed for a method
	case isShortCallData:
		method, err = methodIDCallData(api)

	// Case 3: calldata is non-empty and contains the minimum 4 bytes needed for a method
	case isStandardCallData:
		method, err = standardCallData(api, contract)
	}

	if err != nil {
		return nil, nil, err
	}

	// return error if trying to write to state during a read-only call
	if readOnly && isTransaction(method) {
		return nil, nil, vm.ErrWriteProtection
	}

	// if the method type is `function` continue looking for arguments
	if method.Type == abi.Function {
		argsBz := contract.Input[4:]
		args, err = method.Inputs.Unpack(argsBz)
		if err != nil {
			return nil, nil, err
		}
	}

	return method, args, nil
}
