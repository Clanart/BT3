### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The WebDAV CVE maps to the bug class "an operation accepted without checking a condition that makes the result unusable/unsafe." In Serai's in-scope Bitcoin wallet, `Scanner::scan_block` iterates over *all* transactions in a block — including `block.txdata[0]`, the coinbase — and returns matching outputs as `ReceivedOutput`s indistinguishable from normal, immediately-spendable outputs. Coinbase outputs cannot be spent for 100 blocks (BIP-30/consensus maturity rule), so a `ReceivedOutput` produced from the coinbase is "funds reported received that are not spendable." [1](#0-0) 

### Finding Description
`scan_transaction` matches `output.script_pubkey` against the scanner's registered scripts and builds a `ReceivedOutput { offset, output, outpoint }` for every match, with no notion of which transaction in the block produced it. [2](#0-1)  `scan_block` then feeds `block.txdata` — the full vector, starting at index 0 — into `scan_transaction`. The doc comment concedes the issue: "This will also scan the coinbase transaction which is bound by maturity," but the only mitigation offered is a caller-side post-processing pass that nothing in the in-scope crate performs or enforces. `ReceivedOutput` itself carries no "immature" flag, so downstream code (`SignableTransaction::new`, `TransactionMachine`) will happily treat it as a normal input and produce a transaction Bitcoin consensus rejects. [3](#0-2) 

Notably, the processor-side consumer in `processor/src/networks/bitcoin.rs` already had to work around this exact defect by manually slicing `block.txdata[1 ..]` with the comment "Skip the coinbase transaction which is burdened by maturity" — confirming the bug is real and that correct usage requires every caller to independently remember to bypass part of the library's output. [4](#0-3) 

### Impact Explanation
Any caller using the natural API — `Scanner::scan_block(&block)` — receives `ReceivedOutput`s that are not spendable. Feeding such an output into `SignableTransaction::new` builds a transaction spending an immature coinbase outpoint; once the threshold signing completes, the signed transaction is invalid under consensus (bad-txns-premature-spend-of-coinbase) and cannot be broadcast. The multisig has produced a signed transaction for an unintended, unexecutable spend, and the affected input set/fee planning is wasted; on a schedule that retries, the same immature output is re-scanned on every new block because `scan_block` never marks it, potentially causing repeated failed sign attempts. This matches the accepted impact classes: "funds reported received that are not spendable" and signing of a transaction that cannot achieve its intended effect.

### Likelihood Explanation
Reachability is unprivileged: a coinbase pays to whatever `script_pubkey` the miner chooses. Any miner (or mining pool) can point the coinbase reward at a Serai P2TR address — requiring no authentication, no validator status, and no cooperation — and `scan_block` will emit a `ReceivedOutput` for it. Coinbase outputs paying to arbitrary registered/external addresses occur naturally as well (e.g., a pool paying out to an address that is also a Serai deposit address). Exploitation cost is essentially zero; the only requirement is that a caller uses `scan_block` directly rather than hand-rolling `block.txdata[1 ..]`, which is precisely what the API's signature invites.

### Recommendation
In `scan_block`, skip `block.txdata[0]` (or the transaction(s) marked `tx.is_coinbase()`), matching the workaround already present in `processor/src/networks/bitcoin.rs`. Alternatively, return a richer type (e.g., flag immaturity on `ReceivedOutput` and make `SignableTransaction::new` reject it) so the maturity constraint is enforced in the type rather than delegated to every caller's memory.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
