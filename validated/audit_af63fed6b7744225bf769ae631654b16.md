### Title
`mWOMSVBaseRewarder._calExpireForfeit` never applies the early-unlock forfeit penalty, letting users steal redistributed yield — (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
The reported bug class is a formula meant to enforce an invariant (a `Math.max`-based clamp) that was broken because the wrong variable was substituted in, silently defeating the intended protection. `mWOMSVBaseRewarder.sol` contains the same class of defect: the formula that is supposed to compute a user's *rewardable* (non-forfeited) share of MGP is replaced with a no-op that always returns the full amount, permanently disabling the forfeiture mechanism for early/partial mWOMSV unlockers.

### Finding Description
`vlMGPBaseRewarder._calExpireForfeit` correctly computes the rewardable share from the user's actual unlock state: [1](#0-0) 

The sibling contract for mWomSV, `mWOMSVBaseRewarder._calExpireForfeit`, is supposed to perform the analogous calculation but instead sets `rewardableAmount` directly equal to `_amount` (a tautology), so `forfeitAmount` is always `_amount - _amount == 0`: [2](#0-1) 

This function is reached on every reward claim through the normal, unprivileged user flow: `getReward`/`getRewards` (callable only by `MasterMagpie`, i.e. triggered by an ordinary user harvesting) call `_sendReward`, which calls `_calExpireForfeit` to determine how much of the accrued MGP-denominated reward should be forfeited (and redistributed to remaining stakers via `_queueNewRewardsWithoutTransfer`) versus paid out: [3](#0-2) 

Because `rewardableAmount` is hard-coded to `_amount`, `forfeitAmount` is always `0`, regardless of the user's actual lock/cooldown state. The intended penalty — meant to claw back part of an early/partial unlocker's reward and redistribute it as extra yield to users who remain locked — never fires.

### Impact Explanation
Every mWOMSV-locked user can withdraw/harvest their full reward amount unconditionally, bypassing the forfeiture mechanism entirely. Yield that should have been forfeited and redistributed to remaining (loyal) stakers via `_queueNewRewardsWithoutTransfer` is instead retained by the unlocking user. This is a direct, unprivileged-wallet-reachable diversion of unclaimed/redistributed yield away from the pool of remaining stakers — a protocol-level accounting break in the "lock slots and forfeits" mechanism explicitly in scope.

### Likelihood Explanation
High. No special conditions or malicious admin action are required — any regular mWOMSV holder who claims rewards through the standard `getReward`/`getRewards` path (triggered via `MasterMagpie`) automatically receives a forfeit of `0`, on every single claim.

### Recommendation
Mirror the `vlMGPBaseRewarder` implementation: compute `rewardableAmount` from the user's actual unlock/cooldown percentage (e.g., via an equivalent `getRewardablePercentWAD`-style call against the mWOMSV locker) rather than assigning `rewardableAmount = _amount`, and keep the invariant check (`rewardableAmount > _amount` should revert) meaningful rather than a dead tautology.

### Proof of Concept
1. A user locks MGP into mWOMSV, accrues rewards over time.
2. User triggers withdrawal that puts them in an "early/partial unlock" state that should be subject to the forfeiture schedule.
3. User calls harvest via `MasterMagpie`, which invokes `mWOMSVBaseRewarder.getReward` → `_sendReward` → `_calExpireForfeit(_account, userRewards[...])`.
4. `_calExpireForfeit` returns `forfeitAmount == 0` unconditionally (since `rewardableAmount` is set equal to `_amount` with no dependency on lock state), so the user receives 100% of `userRewards[...]` with no penalty and no residual amount is queued back via `_queueNewRewardsWithoutTransfer` for other stakers.     function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
