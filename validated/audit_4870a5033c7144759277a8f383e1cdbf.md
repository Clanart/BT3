### Title
Ethereum-compatible RPC namespace bypasses module allowlist exclusion when `NonEthCompatible` is enabled - ([File: networks/rpc/service.go])

### Summary
The JSON-RPC dispatcher's method-to-namespace resolution logic hard-codes a fallback that routes any `eth_*` call to the `kaia` service's callbacks whenever the global `NonEthCompatible` flag is enabled, without checking whether the `eth` namespace was actually registered/whitelisted on the specific HTTP/WS endpoint that received the request. This mirrors the JBoss AS bug class: an administrator's explicit exclusion list (here, the `--rpcapi`/`--wsapi` module allowlist that omits `eth`) is silently bypassed because a separate, mismatched code path (namespace aliasing in the dispatcher) does not honor the same exclusion.

### Finding Description
When an HTTP or WS endpoint is started, `StartHTTPEndpoint`/`StartWSEndpoint` builds a per-server whitelist from the configured modules and only registers (`handler.RegisterName`) namespaces present in that whitelist (or public ones if the whitelist is empty): [1](#0-0) 

If an operator explicitly restricts an endpoint to, e.g., `--rpcapi kaia` to exclude the Ethereum-compatibility surface, `eth` is never registered in that server's `serviceRegistry.services` map.

However, method dispatch does not consult this exclusion consistently. In `serviceRegistry.callback`, when the global `NonEthCompatible` flag is `true`, any call whose method starts with `eth_` is unconditionally redirected to `r.services["kaia"].callbacks[method]`, bypassing the check for whether `"eth"` was ever registered/whitelisted on that server instance: [2](#0-1) 

Because `kaia` and `eth` methods share the same method names (e.g. `getBalance`, `getTransactionByHash`), and `kaia` is virtually always enabled (it's the primary namespace), any endpoint that was configured to exclude `eth` for policy reasons still fully services `eth_*` calls once `NonEthCompatible` is turned on — the exclusion list ("eth" not in `--rpcapi`/`--wsapi`) and the actual behavior of the dispatcher ("eth_* still works via kaia fallback") are mismatched, exactly like the mismatched hostname/excluded-contexts handling in the JBoss advisory.

The `NonEthCompatible` flag is a process-wide global variable, not scoped per endpoint: [3](#0-2) 
so enabling it for one purpose (disabling Ethereum-style response formatting) has the side effect of overriding namespace exclusion decisions on every HTTP/WS listener in the process.

### Impact Explanation
A public, unprivileged RPC caller can invoke `eth_*` methods against an endpoint whose operator explicitly configured the module allowlist to exclude the `eth` namespace, defeating that administrative access-control decision (CWE-200: exposure of functionality/data through an unintended API surface). While much of the underlying chain data returned by `eth_*` mirrors `kaia_*` data, operators may rely on module exclusion as a security boundary (e.g., disabling the Ethereum-compatibility surface entirely on a restricted/private RPC endpoint to reduce attack surface, avoid known eth-namespace quirks, or comply with an intended API contract). The bypass silently reintroduces the excluded surface.

### Likelihood Explanation
Reachable by any unauthenticated public-RPC caller with no special privileges — a single `eth_*` JSON-RPC call is sufficient. Exploitability is conditioned on the node operator having set `rpc.eth.noncompatible` (`NonEthCompatible = true`) while also using `--rpcapi`/`--wsapi` to exclude `eth`, which is a plausible/likely real-world configuration combination for operators trying to lock down the Ethereum-compatibility surface.

### Recommendation
In `serviceRegistry.callback`, verify that the `eth` (or aliased) namespace was actually registered for the current server instance before applying the `NonEthCompatible` fallback, e.g., only redirect to `kaia` callbacks if `r.services["eth"]` (or the equivalent per-endpoint whitelist state) indicates `eth` is permitted on that endpoint; otherwise return `nil` so the exclusion is honored consistently between endpoint registration and method dispatch.

### Proof of Concept
1. Start a Kaia node with `--rpc --rpcapi kaia --rpc.eth.noncompatible` (i.e. HTTP RPC restricted to the `kaia` namespace only, with `NonEthCompatible` enabled).
2. As an unauthenticated caller, send `POST /` with body `{"jsonrpc":"2.0","method":"eth_getBalance","params":["0x...","latest"],"id":1}`.
3. Observe that despite `eth` not being in `--rpcapi`, the call succeeds and returns balance data, because `serviceRegistry.callback` reroutes it to the `kaia` service's `getBalance` callback via the `NonEthCompatible` shortcut in [4](#0-3) , regardless of the endpoint's configured module whitelist enforced in [5](#0-4) .

func StartHTTPEndpoint(endpoint string, apis []API, modules []string, cors []string, vhosts []string, timeouts HTTPTimeouts) (net.Listener, *Server, error) {
	// Generate the whitelist based on the allowed modules
	whitelist := make(map[string]bool)
	for _, module := range modules {
		// for backward compatibility
		if module == "klay" {
			module = "kaia"
		}
		whitelist[module] = true
	}
	// Register all the APIs exposed by the services
	handler := NewServer()
	for _, api := range apis {
		if api.Namespace == "klay" {
			api.Namespace = "kaia"
		}

		if !api.IPCOnly && (whitelist[api.Namespace] || (len(whitelist) == 0 && api.Public)) {
			if err := handler.RegisterName(api.Namespace, api.Service); err != nil {
				return nil, nil, err
			}
			logger.Debug("HTTP registered", "namespace", api.Namespace)
		}
	}

// callback returns the callback corresponding to the given RPC method name.
func (r *serviceRegistry) callback(method string) *callback {
	elem := strings.SplitN(method, serviceMethodSeparator, 2)
	if len(elem) != 2 {
		return nil
	}
	r.mu.Lock()
	defer r.mu.Unlock()

	namespace, method := elem[0], elem[1]

	// when NonEthCompatible is true, the return formatting for the eth namespace API provided for Ethereum compatibility is disabled.
	// convert ethereum namespace to klay namespace.
	if NonEthCompatible && namespace == "eth" {
		return r.services["kaia"].callbacks[method]
	}

	if namespace == "klay" {
		namespace = "kaia"
	}

	return r.services[namespace].callbacks[method]
