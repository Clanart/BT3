### Title
Missing `minAmountOut >= amountRepay` check in `VerifyExecutable` allows proposer fund loss on gasless swap - (File: kaiax/gasless/impl/getter.go)

### Summary
The Rubicon `RubiconRouter` bug allowed a user-controlled input to bypass a bound check present nowhere else in the call path, letting a swap "succeed" while returning less value than expected. The `kaiax/gasless` module has an analogous split-validation defect: the invariant `minAmountOut >= amountRepay` is enforced only in the tx-pool admission path, but not in the `VerifyExecutable`/`IsExecutable` path that actually decides whether a `GaslessSwapTx` is turned into a block-included bundle funded by the proposer's `LendTx`.

### Finding Description
`checkBalanceForSwap` (used for tx-pool admission via `GetCheckBalance`) explicitly checks `tx.minAmountOut >= tx.amountRepay`: [1](#0-0) 

However, the authoritative function that determines whether a `(approveTxOrNil, swapTx)` pair is executable and eligible for bundling with a proposer-funded `LendTx` — `VerifyExecutable`, called by `IsExecutable` — does **not** perform this check at all. It only validates token/sender/nonce consistency and that `amountRepay` equals the computed `repayAmount`: [2](#0-1) 

The formula `repayAmount` is purely a function of gas price/fees, independent of `minAmountOut`: [3](#0-2) 

Because `IsExecutable`/`VerifyExecutable` is the function that gates whether the block-building logic prepends a `LendTxGenerator` (funded by the block proposer) ahead of the swap, as documented in the block building rules: [4](#0-3) [5](#0-4) 

a user (or a malicious searcher/relay bypassing the tx-pool `checkBalanceForSwap` gate — e.g., submitting the swap tx directly to a proposer's private RPC or via a path where `BalanceCheckLevel` is below `BalanceCheckLevelStatic`'s minAmountOut check, or via any future code path that consults `IsExecutable` directly without going through `checkBalanceForSwap`) can supply `minAmountOut` far below `amountRepay`. `IsExecutable` will still return `true` since it never checks this relation, letting the block builder lend the sender `amountRepay` in KAIA via the `LendTx` while the actual `swapForGas` on-chain execution may realize proceeds below `amountRepay` (the on-chain contract's own slippage protection only guarantees `amountOut >= minAmountOut`, which is not tied to `amountRepay` at the consensus/mempool-independent path). This mirrors the RubiconRouter issue: a bound check that exists in one place (`buy_amt_min`/slippage check analog) is missing from the actually authoritative acceptance path, causing an under-collateralized or unprofitable operation to be treated as valid and executed, resulting in value loss for the party funding the transaction (the block proposer, via `LendTxGenerator`) instead of the swap user.

### Impact Explanation
If `IsExecutable`/`VerifyExecutable` is relied upon as the sole gate for whether to fund a `GaslessSwapTx` with proposer capital (as the README's block-building rules imply), a swap that would yield actual proceeds under `amountRepay` can still be accepted and lent against. This is a fee-delegation/gasless settlement theft scenario: the proposer/lender advances `amountRepay` worth of KAIA but the swap can fail to return enough for the sender to fully cover it, causing real value loss for the block proposer counterparty — directly analogous to the original "user will lose funds" pattern, but shifted to the fee-delegation counterparty in Kaia's gasless design.

### Likelihood Explanation
Medium likelihood: exploitation requires reaching `IsExecutable` with a swap tx whose `minAmountOut < amountRepay` while bypassing (or without going through) the tx-pool's `checkBalanceForSwap`, which is the current gate for locally/network-received transactions. This makes the primary mitigation (mempool check) effective for normal transaction propagation, but the analog is valid because `VerifyExecutable` — the function documented and named as authoritative for "is this GaslessTx executable" — silently omits the invariant, creating a defense-in-depth gap identical in nature to the reported bug class (a check present in one code path, absent from another that actually gates value movement).

### Recommendation
Add the `minAmountOut.Cmp(amountRepay) < 0` check directly inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, so that the check is enforced consistently regardless of which code path (`tx_pool.go`'s admission check vs. `IsExecutable` used for bundling) evaluates the swap transaction, rather than relying solely on `checkBalanceForSwap`.

### Proof of Concept
1. Construct a `GaslessSwapTx` with `Token`, `AmountIn`, `Deadline` valid, but `MinAmountOut = 0` (or any value less than `AmountRepay`), and `AmountRepay` set correctly per `repayAmount(approveTxOrNil, swapTx)` so that the SP4 check passes. [6](#0-5) 
2. Call `GaslessModule.IsExecutable(nil, swapTx)` directly (bypassing `checkBalanceForSwap`, e.g., from a code path that consumes `IsExecutable` without first running `GetCheckBalance`). Observe it returns `true` despite `MinAmountOut < AmountRepay`, as demonstrated by the existing test `TestIsExecutable`'s "single swap tx" cases, none of which exercise a `MinAmountOut < AmountRepay` scenario against `VerifyExecutable` itself: [7](#0-6) 
3. The block builder would then generate and prepend a `LendTx` funding `amountRepay` via `GetLendTxGenerator`, exposing the proposer to loss if the actual swap proceeds fall short of `amountRepay`. [8](#0-7)

```go
// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
```

```go
// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
```

```go
func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
```

```markdown
### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.
```
