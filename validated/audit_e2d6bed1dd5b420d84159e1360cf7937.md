### Title
SSRF via unauthenticated mirror/subscription URLs fetched by the Data Layer client - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's Data Layer service downloads delta/full-tree files from mirror server URLs that are sourced from on-chain mirror coins and wallet-tracked subscriptions, not from any trust-authenticated origin. `DataLayer.fetch_and_validate()` pulls `ServerInfo` records via `self.data_store.get_available_servers_for_store()` and passes the stored `url` directly into `insert_from_delta_file()` / `download_file()` / `http_download()`, which issues an `aiohttp` GET to `server_info.url + "/" + filename` with no scheme/host allowlisting.

### Finding Description
`http_download()` in `chia/data_layer/download_data.py` performs `session.get(server_info.url + "/" + filename, ...)` where `server_info.url` originates from mirror records that on-chain participants can publish (mirror coins carry a URL as metadata, tracked in `dl_wallet_store.py` / surfaced through `DLGetMirrors`/`DLNewMirror` wallet RPCs referenced in `chia/data_layer/data_layer.py`). Any DataLayer store owner or a peer who creates a mirror coin for a store id can set this URL to point at internal-network addresses (e.g., `http://127.0.0.1:PORT`, cloud metadata endpoints, or other internal services) since there is no validation restricting the URL to public/expected hosts before the local node's DataLayer client fetches from it in `fetch_and_validate()` at `chia/data_layer/data_layer.py:642-706`. This mirrors the CVE-2025-55911 bug class: a remote/unprivileged party supplies a URL/file value that is later fetched server-side without origin validation, enabling SSRF against internal services reachable from the DataLayer host.

### Impact Explanation
If validated, an attacker-controlled mirror URL could cause the local node's DataLayer service to make outbound requests to internal-only endpoints (local RPC ports, cloud metadata services, other internal hosts) whenever `fetch_and_validate()` / `update_subscription()` iterates over mirror server info. This is limited to Data Layer's own outbound HTTP fetch of delta/full-tree files; the response is still fed through `DataStore.insert_into_data_store_from_file()` which validates it against the wallet-advertised Merkle root, so it cannot be used to forge tree content, but the SSRF request itself (port-scanning internal hosts, hitting metadata services, potentially triggering side effects on internal HTTP endpoints) is the disclosed risk.

### Likelihood Explanation
I was unable to fully verify, within the available tool budget, whether mirror coin creation/URL values are unrestricted (no scheme/host allowlist) at the point they are persisted via `dl_wallet_store.py` and surfaced through `DLNewMirror`/`DLGetMirrors` — I could not complete reading `chia/data_layer/data_layer_wallet.py`'s mirror-creation logic to confirm there is no URL-scheme or host validation before a mirror coin's URL becomes an entry consumed by `get_available_servers_for_store()`. The `download_data.py` and `data_layer.py` fetch paths clearly perform unauthenticated GETs against the stored URL, but confirming that the URL field is genuinely attacker-controllable end-to-end (versus filtered/allowlisted elsewhere) requires further code review that I could not finish confirming.

### Recommendation
Given the above uncertainty on mirror-URL validation, this should be treated as a **candidate finding requiring further verification** rather than a fully confirmed vulnerability. A Devin agent with full repo access should:
1. Inspect `chia/data_layer/data_layer_wallet.py` mirror creation/parsing logic and `chia/data_layer/dl_wallet_store.py` mirror storage to determine whether URLs are validated (scheme restricted to http/https, host restricted to public/allowed ranges) before being surfaced to `get_available_servers_for_store()`.
2. If unrestricted, add server-side validation in `chia/data_layer/download_data.py::http_download()` (and the plugin `download_file()`/S3 paths) to reject non-http(s) schemes and block private/loopback/link-local/metadata IP ranges before issuing outbound requests, or require explicit user opt-in per mirror host.

### Proof of Concept
Not confirmed as exploitable without verifying mirror-URL provenance; a concrete PoC would require confirming that `DLNewMirror`/mirror-coin URL values pass unfiltered into `ServerInfo.url` and thus into `http_download()`'s `session.get(server_info.url + "/" + filename, ...)` call.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
