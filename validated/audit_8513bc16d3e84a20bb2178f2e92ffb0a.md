### Title
Missing bounds validation in `is_atom_canonical`/`is_clvm_canonical` allows attacker-controlled length prefix to index past the end of untrusted spend-bundle CLVM buffer - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the raw, attacker-supplied bytes of a coin spend's `puzzle_reveal` and `solution` to decide DEDUP/fast-forward eligibility for a submitted spend bundle, but they index into the buffer using an offset derived purely from the encoded length-prefix byte, with no check that the buffer actually contains that many bytes.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine the atom's length-prefix class, then loops `prefix_len` times reading `clvm_buffer[offset]` again to accumulate `atom_len`, all without ever checking `offset < len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this in a loop over the whole buffer, similarly indexing `clvm_buffer[offset]` without a length guard before each read, and calling `is_atom_canonical` to advance `offset` by `atom_len` — an attacker-controlled value that can exceed the remaining buffer: [2](#0-1) 

This is invoked on `bytes(spend.puzzle_reveal)` / `bytes(spend.solution)` taken directly from a submitted `SpendBundle`, i.e., fully unprivileged, attacker-controlled input, as exercised in the test suite: [3](#0-2) 

By contrast, every other length-prefixed parser in this codebase that operates on untrusted/serialized buffers explicitly validates the declared length against the remaining buffer size before consuming it, e.g. `skip_bytes`/`skip_list` in `chia/full_node/full_block_utils.py` raise `ValueError` if the declared size exceeds what remains: [4](#0-3) 
and the generator-buffer parsing in `block_info_from_block` does the same: [5](#0-4) 

`is_atom_canonical`/`is_clvm_canonical` lack this same discipline: a crafted `puzzle_reveal` or `solution` whose final byte is a multi-byte atom-length prefix (e.g. `0xFC` class, which reads 5 more length bytes) with insufficient trailing bytes will cause a Python `IndexError` when indexing past the end of `clvm_buffer`. This is the direct structural analog of CVE-2020-17507 (`read_xbm_body` reading past the end of an image buffer because of an unchecked/attacker-influenced length value) — a memory/data-format parser trusting an encoded length field without bounding it to the actual available bytes.

### Impact Explanation
An unhandled `IndexError` raised while a submitted spend bundle is being checked for canonical/DEDUP eligibility during mempool admission would propagate out of the canonicality check. Depending on whether the call site wraps this logic in a try/except (which I was not able to fully confirm from the available index before running out of tool calls), this could either be caught and simply reject the bundle, or propagate and disrupt the mempool worker/thread handling that spend bundle — a spend-triggered transaction-processing disruption reachable by any unprivileged spend-bundle submitter. This falls short of proven fund-loss or consensus-divergence, and its ultimate severity depends on the (unverified) exception-handling wrapper around the DEDUP-eligibility check.

### Likelihood Explanation
Trivial to trigger: constructing a `puzzle_reveal` or `solution` whose trailing atom uses a non-canonical multi-byte length prefix truncated near the buffer end requires no special privileges — any spend bundle submitter (mempool, RPC `push_tx`, or gossip) can supply such bytes as part of a normal-looking coin spend.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` (verify `offset + prefix_len < len(clvm_buffer)` before each indexed read) and in `is_clvm_canonical`'s loop (verify `offset < len(clvm_buffer)` before reading `clvm_buffer[offset]`), returning "not canonical" (or raising a handled error) rather than allowing an unguarded index into the buffer, mirroring the bounds checks already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`.

### Proof of Concept
1. Craft a `solution` (or `puzzle_reveal`) byte string ending in a length-prefix byte from the `0xFC` class (5 extra length bytes expected) followed by fewer than 5 remaining bytes, e.g. `bytes.fromhex("80" * N + "fc")` with no trailing bytes after `fc`.
2. Submit a `SpendBundle` containing a `CoinSpend` with this `solution` via the standard mempool-admission path (`MempoolManager.add_spend_bundle` / RPC `push_tx`), matching the same call path exercised by `test_mempool_requires_canonical_clvm` in `chia/_tests/core/mempool/test_mempool_manager.py`.
3. When the mempool manager evaluates DEDUP/fast-forward eligibility, `is_clvm_canonical` invokes `is_atom_canonical`, which indexes past the end of the truncated buffer, raising `IndexError` instead of returning a controlled `False`/`Err`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
