### Title
Unrecovered nil-pointer panic on empty `To` in `SetCodeTx.AsEthereumData()` crashes nodes during concurrent EVM tx preprocessing - (File: `x/evm/types/ethtx/set_code_tx.go`)

### Summary
An EIP-7702 `SetCodeTx` (EVM tx type 0x04) can be submitted with an empty `To` string. `SetCodeTx.Validate()` only validates `To` when it is non-empty, so an empty `To` passes basic validation. `SetCodeTx.AsEthereumData()` unconditionally dereferences the pointer returned by `GetTo()`, which is `nil` for an empty `To`, causing a nil-pointer dereference panic. This call path is reached from `app.DecodeTransactionsConcurrently`'s per-tx goroutine via `finalizeDecodedEVMSlot`'s EVM preprocessing, where only the decode step (not preprocessing) is wrapped in `recover()`. An unrecovered panic inside a goroutine terminates the whole process, matching the CVE's "NULL pointer dereference and application crash" bug class from crafted/malformed input.

### Finding Description
`GetTo()` explicitly returns `nil` for an empty `To`: [1](#0-0) 

`AsEthereumData()` dereferences that nil pointer directly with `*tx.GetTo()`: [2](#0-1) 

`Validate()` only checks address validity conditionally on `tx.To != ""`, so an empty `To` is accepted: [3](#0-2) 

An attacker can construct a `MsgEVMTransaction` whose `Data` is a protobuf `Any` directly containing a `SetCodeTx` with `To=""`, bypassing the normal `NewSetCodeTx(tx *ethtypes.Transaction)` constructor (which only ever gets `To` from a real go-ethereum `SetCodeTx`, where the field is a non-pointer `common.Address` and therefore always populated). `UnpackTxData` accepts any well-formed protobuf matching the `SetCodeTx` shape: [4](#0-3) 

`ValidateBasic()` on `MsgEVMTransaction` calls `txData.Validate()`, which — as shown above — does not reject an empty `To`, so the malformed tx passes `ValidateBasic`: [5](#0-4) 

During ante preprocessing, `PreprocessUnpacked` calls `ethtypes.NewTx(txData.AsEthereumData())` before any signature check is performed, so the crash happens pre-authentication: [6](#0-5) 

Critically, this preprocessing is invoked from `app.DecodeTransactionsConcurrently`, which runs each transaction's decode-and-preprocess step in its own goroutine. The `recover()` there is scoped only to `app.txDecoder`, not to `app.finalizeDecodedEVMSlot` (which performs the EVM preprocessing that triggers `AsEthereumData()`): [7](#0-6) 

Because Go cannot recover a panic that escapes a goroutine at any outer call frame other than one inside that same goroutine, an unrecovered panic here crashes the entire node process, not just the single transaction's execution.

### Impact Explanation
A single crafted transaction (a `MsgEVMTransaction` carrying a `SetCodeTx` payload with `To=""`) included in a block or proposal being processed causes a nil-pointer dereference panic inside a bare goroutine with no enclosing recover, which crashes the process. This is a crash of a default-configuration node handling normal transaction/proposal processing (validators and full/RPC nodes that decode and preprocess incoming block transactions), which is one of the explicitly accepted high-impact outcomes (crash/halt of nodes, potential block-delay/consensus disruption if enough validators process the same malicious tx).

### Likelihood Explanation
Likelihood is high: constructing the malicious `MsgEVMTransaction`/`SetCodeTx` protobuf payload requires no special privileges, no valid signature, and no prior state — it is a pure client-side encoding operation. The tx passes `ValidateBasic` (since `Validate()` does not require `To` when empty) and reaches the vulnerable `AsEthereumData()` call during preprocessing before signature verification, i.e., before the tx is rejected as unsigned/invalid.

### Recommendation
- In `SetCodeTx.AsEthereumData()`, check `GetTo()` for `nil` and return an error / reject the tx instead of dereferencing it (EIP-7702 requires `To` to be present; treat an empty `To` as a validation failure rather than allowing it through `Validate()`).
- Update `SetCodeTx.Validate()` to reject an empty `To` outright for `SetCodeTx` (unlike other tx types, EIP-7702 transactions must always have a `To` address).
- Wrap the EVM preprocessing step invoked in `app.finalizeDecodedEVMSlot`'s goroutine (called from `DecodeTransactionsConcurrently`) in the same panic-recovery pattern already used for `app.txDecoder`, so any panic during preprocessing degrades to "clear the slot" rather than crashing the process.

### Proof of Concept
1. Build a `MsgEVMTransaction` whose `Data` field is a protobuf `Any` with type URL for `ethtx.SetCodeTx` and a serialized `SetCodeTx` message where `To = ""`, `GasTipCap`/`GasFeeCap`/`ChainID` set to valid non-nil values (to pass the other `Validate()` checks), and a non-empty `AuthList`.
2. Wrap it in a Cosmos `Tx` and submit it via broadcast/RPC or include it directly as raw tx bytes in a proposed block.
3. When the node calls `app.DecodeTransactionsConcurrently` → `app.finalizeDecodedEVMSlot` → EVM ante preprocessing → `PreprocessUnpacked` → `ethtypes.NewTx(txData.AsEthereumData())`, `SetCodeTx.AsEthereumData()` executes `*tx.GetTo()` on a `nil` pointer, panicking inside the goroutine and crashing the node process.

func UnpackTxData(any *codectypes.Any) (ethtx.TxData, error) {
	if any == nil {
		return nil, errors.New("protobuf Any message cannot be nil")
	}

	txData, ok := any.GetCachedValue().(ethtx.TxData)
	if !ok {
		ltx := ethtx.LegacyTx{}
		if proto.Unmarshal(any.Value, &ltx) == nil {
			// value is a legacy tx
			return &ltx, nil
		}
		atx := ethtx.AccessListTx{}
		if proto.Unmarshal(any.Value, &atx) == nil {
			// value is a accesslist tx
			return &atx, nil
		}
		dtx := ethtx.DynamicFeeTx{}
		if proto.Unmarshal(any.Value, &dtx) == nil {
			// value is a dynamic fee tx
			return &dtx, nil
		}
		btx := ethtx.BlobTx{}
		if proto.Unmarshal(any.Value, &btx) == nil {
			// value is a blob tx
			return &btx, nil
		}
		astx := ethtx.AssociateTx{}
		if proto.Unmarshal(any.Value, &astx) == nil {
			// value is an associate tx
			return &astx, nil
		}
		stx := ethtx.SetCodeTx{}
		if proto.Unmarshal(any.Value, &stx) == nil {
			// value is a set code tx
			return &stx, nil
		}
		return nil, fmt.Errorf("cannot unpack Any into TxData %T", any)
	}

	return txData, nil
}

	}
	return nil
}

// DecodeTransactionsConcurrently decodes each tx and runs EVM preprocessing in one goroutine per index.
// Failed decodes, decode panics, and failed preprocessing clear the slot (nil), matching prior behavior.
func (app *App) DecodeTransactionsConcurrently(ctx sdk.Context, txs [][]byte) []sdk.Tx {
	typedTxs := make([]sdk.Tx, len(txs))
	giga := app.GigaExecutorEnabled
	wg := sync.WaitGroup{}
	for i, tx := range txs {
		wg.Add(1)
		go func(idx int, encodedTx []byte) {
			defer wg.Done()
			var typedTx sdk.Tx
			func() {
				defer func() {
					if err := recover(); err != nil {
						logger.Error("encountered panic during transaction decoding", "err", err)
						typedTx = nil
					}
				}()
				var err error
				typedTx, err = app.txDecoder(encodedTx)
				if err != nil {
					logger.Error("error decoding transaction at index", "index", idx, "error", err)
					typedTx = nil
				}
			}()
			typedTxs[idx] = typedTx
			if giga || typedTx == nil {
				return
			}
			isEVM, _ := evmante.IsEVMMessage(typedTx)
			if !isEVM {
				return
			}
			app.finalizeDecodedEVMSlot(ctx, idx, typedTx, typedTxs)
		}(i, tx)
	}
	wg.Wait()
	return typedTxs
}
