### Title
Gasless `LendTx` is paid unconditionally before `SwapTx` settlement, allowing stale balance/allowance checks to cause proposer fund loss - (File: kaiax/gasless/impl/builder.go, kaiax/gasless/impl/getter.go, kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module's block-building logic (`ExtractTxBundles`) prepends an unconditional native-KAIA transfer (`LendTx`, generated by `GetLendTxGenerator`) ahead of the user's `ApproveTx`/`SwapTx` pair. The decision to lend gas is based on a balance/allowance/liquidity check (`checkBalanceForSwap`) performed at tx-pool admission time, using state that can become stale by the time the bundle is actually incorporated into a block and executed. This mirrors the reported bug class: a payout/commitment decision is made against a liquidity/balance snapshot that is not re-validated atomically at settlement time, so the payer (here, the block proposer) can lose funds if the underlying state changes between the check and the actual value transfer.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  validates the swapper's ERC20 balance, allowance, and DEX-derived `amountIn` requirement using the token contract's state read via `backends.NewBlockchainContractBackend`. This check is invoked from `GetCheckBalance()` [2](#0-1)  which is used only for tx-pool admission/promotion, since gasless transactions explicitly skip the standard sender-balance check ("Sender balance check is omitted for gasless transactions").

At block-building time, `ExtractTxBundles` [3](#0-2)  builds a bundle `[LendTxGenerator, ApproveTx?, SwapTx]` for every `IsExecutable` approve/swap pair found in the pending pool, without re-checking the current token balance/allowance/DEX rate against the state that will actually be used at inclusion time.

`GetLendTxGenerator` / `MakeLendTx` [4](#0-3)  creates a plain `TxTypeEthereumDynamicFee` value-transfer transaction that unconditionally sends `lendAmount(approveTxOrNil, swapTx)` KAIA from the proposer's node key to the swap sender. This transaction is a normal, independently-executing EVM transaction — it is not wrapped in any all-or-nothing "bundle" semantics. Inspection of the bundle incorporation logic in `work/builder/builder.go` (`incorporate`, `IncorporateBundleTx`, `ExtractBundlesAndIncorporate`) shows that bundles only control transaction *ordering* within the block; there is no mechanism causing the `LendTx` to be reverted or unwound if a later transaction in the same bundle (`ApproveTx`/`SwapTx`) reverts. Each transaction in the sequence is applied to state independently via the normal `ApplyMessage`/state-transition path [5](#0-4) .

Consequently, if the token balance/allowance/DEX price used at the time `checkBalanceForSwap` ran (pool-admission time) differs from the state at actual inclusion time — e.g., the sender transfers away/spends the approved token, the DEX rate moves so `GetAmountIn` now exceeds `swapArgs.AmountIn`, or `Deadline` elapses — the `SwapForGas` call in `swapForGas(...)` reverts on-chain, yet the preceding `LendTx` has already unconditionally paid the sender real KAIA. There is no repayment mechanism recoverable from a reverted `SwapTx`; the proposer's lent KAIA is simply lost.

### Impact Explanation
This directly parallels the reported bug class: a value-movement decision (lend gas to a user in anticipation of repayment) is authorized using a liquidity/balance check taken at one point in time (tx-pool admission), but the actual settlement (the repayment via `SwapForGas`) happens later against different state, with the "locked" resource (the lent KAIA) already irreversibly disbursed regardless of settlement outcome. This causes direct loss of proposer funds (fee/gas-lending abuse), analogous to the analog report's "player may not get paid because liquidity moved between check and settlement" — here inverted so the *lender* (proposer) loses funds because the *borrower's* solvency check is stale by settlement time.

### Likelihood Explanation
Exploitation requires only a normal unprivileged transaction sender: a user submits a valid `ApproveTx`+`SwapTx` pair that passes the pool's `checkBalanceForSwap` at submission time, then performs an action (e.g., transferring away the approved token balance via any other transaction, or waiting for on-chain price movement / deadline drift) that invalidates the balance/allowance/rate condition before the bundle is actually built and included in a block. Because the pool-level check and the block-building bundle extraction can occur at different states (pool promotion vs. actual block assembly), and the `LendTx` execution is unconditional and not tied to the swap's success, this is reachable purely through ordinary transaction submission — no privileged access, node compromise, or consensus manipulation needed.

### Recommendation
- Re-validate `checkBalanceForSwap` conditions (token balance, allowance, DEX-derived `amountIn`, deadline) against the exact state that will be used when the bundle is incorporated into the block (i.e., immediately before/during `ExtractTxBundles`), not only at pool-admission time.
- Make the `LendTx` payout contingent on `SwapTx` succeeding — for example, by having the lend performed within the same atomic call (e.g., a contract-mediated flash-lend-and-repay pattern) rather than as an independently-executing, unconditionally-value-transferring transaction ahead of the swap.
- Alternatively, track and enforce a lending budget/liquidity accounting per block similar to how the analog report recommends tracking `lockedLiquidity`, so that a proposer's outstanding lent amount versus repayment guarantee is verified before committing the `LendTx`, and stale/invalid bundles are dropped rather than partially executed.

### Proof of Concept
1. A user (Alice) holds `X` amount of an allowed ERC20 token and submits `ApproveTx(spender=SwapRouter, amount=MaxUint256)` followed by `SwapTx(token, amountIn=X, minAmountOut, amountRepay, deadline)`.
2. At submission time, `checkBalanceForApprove`/`checkBalanceForSwap` [6](#0-5)  pass because Alice currently holds `X` tokens and the DEX rate at that moment satisfies `AmountIn >= GetAmountIn(MinAmountOut)`.
3. Before the block containing this bundle is built, Alice sends another transaction transferring away her `X` tokens (or the DEX price moves adversely, e.g. via a large trade), so that at actual inclusion time her balance/allowance no longer suffices, or `GetAmountIn` exceeds `AmountIn`.
4. `ExtractTxBundles` [7](#0-6)  still forms bundle `[LendTx, ApproveTx, SwapTx]` since it only calls `IsExecutable` (structural/static checks), not a fresh balance re-check.
5. The proposer's `LendTx` executes first and unconditionally transfers `lendAmount` KAIA to Alice's address.
6. `SwapTx`'s `swapForGas(...)` call subsequently reverts (insufficient balance/allowance/slippage/deadline), so Alice never repays the proposer, but she has already received the lent KAIA — a real, unrecoverable value loss to the proposer.

Note: I was not able to inspect the on-chain `GaslessSwapRouter.sol` source (only its Go bindings were available in the index) to confirm there is no additional safety mechanism inside the router contract itself (e.g., a pull-based repayment guarantee) that might mitigate this; if such a file exists and enforces additional protection, it should be reviewed directly. A Devin session with full repository access would be needed to confirm this router-contract detail.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
