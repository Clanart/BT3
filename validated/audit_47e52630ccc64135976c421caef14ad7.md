### Title
FROST `sign` accepts participant index 0, letting an unauthenticated preprocess claim the group-secret interpolation index - (File: crypto/frost/src/sign.rs)

### Summary
The n8n advisory describes inbound requests processed without validation of an authentication token. The Serai analog is `AlgorithmSignMachine::sign`, which processes attacker-supplied preprocess messages keyed by `Participant` without validating that the index is within `1..=n`. It rejects indexes greater than `n` and duplicates, but never rejects `Participant(0)`, the index at which the polynomial's constant term (the group secret) is interpolated.

### Finding Description
`sign` builds `included` from the keys of the attacker-supplied `preprocesses` map, sorts it, then performs only three validations: `included.len() < t`, `included.last() > n`, and adjacent-equality duplicates (crypto/frost/src/sign.rs:290-310). [1](#0-0)  No check enforces `included[0] >= 1`. The participant index reaches this code from untrusted bytes: `read_preprocess` parses commitments (`Commitments::read`, crypto/frost/src/nonce.rs:133) with no participant-index validation, and the caller (`processor/src/batch_signer.rs:241`) only checks that deserialization succeeded. [2](#0-1) [3](#0-2) [4](#0-3) 

Because `included` is sorted ascending, a forged `Participant(0)` preprocess becomes `included[0]`. `ThresholdView` applies the key offset to `included[0]` (per the documented ThresholdView scalar/offset design), so the attacker-controlled index additionally absorbs the offset term. The forged participant then enters the binding-factor map `B` (sign.rs:325-356), receives a `rho` binding factor (nonce.rs:161-173), and contributes its commitments to the group nonces `Rs` (nonce.rs:194-212). [5](#0-4) [6](#0-5)  At completion, `verify_share` is invoked for `l = Participant(0)` using `view.verification_share(0)` — the verification share at interpolation index 0 is the group key itself — and the lagrange coefficient for index 0 is defined over a set where honest indexes are `1..=n`. [7](#0-6) 

### Impact Explanation
An unprivileged participant (or any party able to submit preprocess/share bytes to a signer) can inject a phantom signer at index 0 into any signing session they join. Lagrange interpolation at index 0 corresponds to the polynomial's constant term — the group secret position — so the resulting aggregate `sum`, the bound nonces `Rs`, and the offset applied to `included[0]` are computed over a corrupted signing set. This either produces signatures verifiable under an unintended verification-share mapping or lets the attacker bias the nonce/offset binding, undermining the FROST binding guarantees that `rho`, `hash_msg`, and the preprocesses transcript are meant to enforce. It is the direct analog of "inbound request not validated → forged payload processed": the participant-index field of an inbound preprocess is trusted without validation.

### Likelihood Explanation
Any party that can deliver a `Preprocess` message to a signing participant can attempt it; no key material is required to forge the index field. Exploitation into a full forgery depends on the offset/interpolation interaction in `ThresholdView`, which is complex, hence Medium rather than High.

### Recommendation
In `sign`, reject `included[0] == 0` (add `if u16::from(included[0]) == 0 { Err(FrostError::InvalidParticipant(..)) }`), and/or validate participant indexes when the `preprocesses`/`shares` maps are constructed (`validate_map`).

### Proof of Concept
A participant in a signing session serializes a `Preprocess` and submits it under `Participant(0)` in the `preprocesses` map passed to `AlgorithmSignMachine::sign`. `included` becomes `[0, i, ...]`; the `> n` and duplicate checks pass, `view(0)` is computed with the offset applied to index 0, `B.insert(Participant(0), commitments)` succeeds, and the forged participant's bound nonces enter `Rs`, demonstrating the missing-validation path end to end.
