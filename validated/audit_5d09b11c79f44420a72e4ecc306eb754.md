## Finding

### Title
Out-of-bounds slice access on attacker-controlled signature bytes in auction bid verification - (File: kaiax/auction/bid.go)

### Summary
`getSigner()` in `kaiax/auction/bid.go` indexes and slices a signature byte array supplied directly from an RPC caller without first validating its length, mirroring the CVE-2020-13398 root cause (missing length/bounds check before indexing attacker-controlled crypto material, `crypto_rsa_common` in FreeRDP). Any auction bidder calling the `auction_submitBid` RPC method can supply a `searcherSig` or `auctioneerSig` shorter than 65 bytes and trigger an out-of-bounds slice access panic in the RPC handler goroutine.

### Finding Description
`getSigner` clones the caller-supplied signature and immediately indexes/slices it at fixed offsets without checking `len(sig)`: [1](#0-0) 

Specifically:
- `copiedSig[crypto.RecoveryIDOffset]` (index 64) is accessed on line 145/149 with no prior length check.
- `copiedSig[0:32]` and `copiedSig[32:64]` are sliced on lines 150-151, again without a length guard.

Unlike every other signature-consuming path in the codebase — e.g. `crypto.Ecrecover`/`crypto.SigToPub` (`len(sig) != SignatureLength` check) [2](#0-1) , `RecoverFromMessage`/`EcRecover` (`len(sig) != crypto.SignatureLength` check) [3](#0-2) , and `decodeSignature` (explicit length assertion) [4](#0-3)  — `getSigner` performs no such validation before touching the buffer.

The `sig` value here is fully attacker-controlled. It is populated from the JSON-RPC `BidInput.SearcherSig` / `AuctioneerSig` fields (typed `hexutil.Bytes`, i.e., arbitrary length) via `ToBid`: [5](#0-4) 

And reaches `getSigner` through `AuctionAPI.SubmitBid` → `bidPool.AddBid` → (eventually) `Bid.ValidateSearcherSig`/`ValidateAuctioneerSig`: [6](#0-5) [7](#0-6) 

If `SearcherSig` or `AuctioneerSig` is submitted with fewer than 65 bytes (including empty), the line `copiedSig[crypto.RecoveryIDOffset]` panics with an index-out-of-range runtime error before any of the existing signature-format checks (`crypto.ValidateSignatureValues`, `crypto.SigToPub`) can run.

### Impact Explanation
An unprivileged auction bidder can crash the goroutine handling `auction_submitBid` by submitting a bid with an undersized signature field. Whether this only aborts the single RPC request or destabilizes the node process depends on whether the RPC server's dispatch layer recovers panics for this specific service (this was not fully verified within the available search tooling — it is uncertained whether a top-level `recover()` wraps each RPC method invocation). At minimum this is a reliable, remotely-triggerable panic in the auction bid validation path reachable by any bidder without any special privilege, directly analogous to the missing-bounds-check root cause of CVE-2020-13398.

### Likelihood Explanation
High likelihood: the trigger requires only a single JSON-RPC call (`auction_submitBid`) with a `searcherSig` or `auctioneerSig` field shorter than the expected 65-byte ECDSA signature format — no special account balance, staking position, or governance privilege is needed, and no other code path filters the length beforehand.

### Recommendation
Add an explicit length check in `getSigner` (e.g., `if len(sig) != crypto.SignatureLength { return common.Address{}, ErrInvalidSignature }`) before any indexing/slicing occurs, consistent with the pattern already used in `crypto.Ecrecover`, `crypto.SigToPub`, `api_personal.EcRecover`, and `decodeSignature` elsewhere in the codebase.

### Proof of Concept
1. Call the `auction_submitBid` RPC method with a well-formed `BidInput` except set `searcherSig` (or `auctioneerSig`) to a short byte string, e.g. `"0x00"` (1 byte) or `"0x"` (0 bytes).
2. `ToBid` copies this directly into `BidData.SearcherSig`/`AuctioneerSig` with no length validation (`kaiax/auction/impl/api.go:84-105`).
3. `AddBid` triggers `ValidateSearcherSig`/`ValidateAuctioneerSig` → `getSigner(sig, digest)`.
4. Execution reaches `copiedSig[crypto.RecoveryIDOffset]` (`kaiax/auction/bid.go:145`) with `len(copiedSig) < 65`, causing a runtime panic: `index out of range [64] with length N`.

**Uncertainty note:** I was not able to confirm within the available tools whether the RPC dispatch layer wraps individual method calls (like `SubmitBid`) with a `recover()` that would downgrade this from a goroutine/process crash to a simple error response returned to the caller. If no such recovery exists in this call path, the impact would be a full DoS of the JSON-RPC server process; if recovery exists, the practical impact is limited to a failed request. Confirming this would require tracing the `networks/rpc` package's request dispatch, which the current search results did not surface in sufficient detail.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

	}

		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
