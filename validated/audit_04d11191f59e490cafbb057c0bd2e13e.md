## Analog Identified: Stale Balance-Event Tracking Across Recursive Precompile Calls (`BalanceHandler`)

### Title
Double-application of bank balance-change events in `BalanceHandler` during recursive/nested precompile calls causes StateDB/bank balance desync (analog: stale-cache-not-refreshed-before-use) - (File: `precompiles/common/precompile.go`, `precompiles/common/balance_handler.go`)

### Summary
The external report's bug class is "a piece of tracked/cached state (TWAP price) is not refreshed before being consumed, producing incorrect values used for critical accounting." The closest reachable analog in this Cosmos EVM repository is the `BalanceHandler` used by every stateful precompile (`erc20`, `bank`, `staking`, `distribution`, `gov`, `slashing`, `ics20`, `werc20`, etc.) to translate Cosmos SDK bank events into EVM `StateDB` balance mutations. Its "cursor" (`prevEventsLen`) is captured once at the start of a precompile call against a **shared, tx-scoped event manager** (`stateDB.cacheCtx`). When a precompile call recursively/re-entrantly triggers another precompile call before returning (e.g. via callback contracts, ICS20 recursive flows), the inner call's own `BalanceHandler` consumes and applies the same events to `StateDB`, and then the outer call's `AfterBalanceChange` re-processes the same event slice (because its `prevEventsLen` was captured *before* the nested call and is never advanced to account for it), applying `StateDB.AddBalance`/`SubBalance` twice for the same underlying bank transfer.

### Finding Description
In `precompiles/common/precompile.go`, `runNativeAction` is executed for every precompile call: [1](#0-0) 

Each call creates a **new** `BalanceHandler` and records `prevEventsLen` from the **shared** cache-context event manager: [2](#0-1) 

The cache context (`stateDB.cacheCtx`) is created once per StateDB/transaction and reused for all precompile invocations within that transaction, including nested/recursive ones: [3](#0-2) 

After `action(ctx)` executes, `AfterBalanceChange` replays every bank `coin_spent`/`coin_received`/`fractional_balance_change` event emitted since `prevEventsLen` and mutates `StateDB` balances accordingly: [4](#0-3) 

If, during `action(ctx)`, the EVM call stack re-enters another precompile (a nested `runNativeAction`), that nested call's own `BalanceHandler` captures its own `prevEventsLen` (pointing after the outer's snapshot) and calls its own `AfterBalanceChange`, mutating `StateDB` for the events emitted during its own execution. Control then returns to the outer call, whose `AfterBalanceChange` executes next and re-scans `events[bh.prevEventsLen:]` — a range that **still includes the events already consumed and applied by the nested call**, because `prevEventsLen` was fixed before the nested call and is never advanced past it. Consequently, the same bank event (and its corresponding balance delta) is applied to `StateDB` twice: once by the inner handler and once again by the outer handler.

The repository's own test suite documents and reproduces exactly this defect: [5](#0-4) [6](#0-5) 

This is a structurally identical bug class to the external report: a piece of tracked state (`prevEventsLen`, analogous to the oracle's TWAP window) is not "updated"/refreshed to reflect intervening state changes (nested precompile calls consuming the same event stream) before being used to compute a critical value (the balance delta applied to `StateDB`).

### Impact Explanation
This directly matches the in-scope "Critical unauthorized minting/duplication/irreversible accounting corruption of spendable user value across ... EVM balances ... precompile-mediated assets" impact class. Double-applying a `CoinReceived` event to `StateDB.AddBalance` inflates the recipient's EVM-visible native-token balance beyond what is actually backed in the bank module, creating a `StateDB` balance that exceeds the real spendable bank balance. Because `StateDB` balance is what governs subsequent EVM transfers/`SELFBALANCE`/value-transfer opcodes within the same and future transactions (once committed via `Commit()`/`commitWithCtx`), this desync becomes a durable accounting corruption: the EVM ledger and the native bank ledger diverge, and the inflated EVM balance is potentially spendable (e.g., via further EVM value transfers), effectively duplicating value out of thin air relative to backing bank coins.

### Likelihood Explanation
Reachability depends on being able to trigger a recursive/re-entrant precompile call within a single top-level precompile invocation — i.e., a contract flow where a precompile's native action itself causes another EVM call that lands on a (possibly the same) stateful precompile before the outer call returns. The repository's own recursive-call test infrastructure (`evmd/tests/testdata/debug` "caller" contracts, `ics20_recursive_precompile_calls_test.go`) demonstrates that such recursive precompile invocation paths are reachable and are an actively-tested scenario in this codebase, and the dedicated `balance_handler_test.go` was written specifically to exercise and observe this defect. This indicates the trigger is achievable by an ordinary (unprivileged) EVM transaction that calls a contract designed to re-enter a precompile, not by a privileged actor.

### Recommendation
Track the balance-change event cursor globally per transaction (e.g., on the shared `StateDB`/cache context) rather than as a field local to each per-call `BalanceHandler` instance, so nested/recursive precompile calls advance a single shared cursor and never re-process events already consumed by an inner call. Alternatively, make `AfterBalanceChange` idempotent per-event (e.g., tag/consume events so they cannot be replayed) or restructure so only the outermost precompile invocation performs `BeforeBalanceChange`/`AfterBalanceChange`, with nested calls deferring to the enclosing handler.

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

// GetCacheContext returns the stateDB CacheContext.
func (s *StateDB) GetCacheContext() (sdk.Context, error) {
	if s.writeCache == nil {
		err := s.cache()
		if err != nil {
			return s.ctx, err
		}
	}
	return s.cacheCtx, nil
}

// MultiStoreSnapshot snapshots stateDB CacheMultiStore
// and returns snapshot index
func (s *StateDB) MultiStoreSnapshot() int {
	return s.snapshotter.Snapshot()
}

func (s *StateDB) RevertMultiStore(snapshot int, events sdk.Events) {
	s.snapshotter.RevertToSnapshot(snapshot)
	s.writeCache = func() {
		s.ctx.EventManager().EmitEvents(events)
		s.cacheCtx.MultiStore().(storetypes.CacheMultiStore).Write()
	}
}

// cache creates the stateDB cache context
func (s *StateDB) cache() error {
	if s.ctx.MultiStore() == nil {
		return errors.New("ctx has no multi store")
	}
	s.cacheCtx, _ = s.ctx.CacheContext()

	// Get KVStores for modules wired to app
	cms := s.cacheCtx.MultiStore().(storetypes.CacheMultiStore)
	storeKeys := s.keeper.KVStoreKeys()

	// Create and set snapshot store to stateDB
	snapshotStore := snapshotmulti.NewStore(cms, storeKeys)
	s.snapshotter = snapshotStore
	s.cacheCtx = s.cacheCtx.WithMultiStore(snapshotStore)
	s.writeCache = func() {
		s.ctx.EventManager().EmitEvents(s.cacheCtx.EventManager().Events())
		s.cacheCtx.MultiStore().(storetypes.CacheMultiStore).Write()
	}

	return nil
}

// TestRecursivePrecompileCallsWithDebugPrecompile demonstrates the balance handler bug
// by triggering recursive calls that share the same BalanceHandler instance.
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))

		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier

	s.Require().NoError(err, "callback transaction should succeed")

		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")

	// Advance to next block to finalize state
	s.chain.NextBlock()
