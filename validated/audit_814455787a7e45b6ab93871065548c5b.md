### Title
Attacker-controlled `ReceivedOutput` bytes claim arbitrary outpoints and values, yielding "received" funds that are not spendable - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The Liferay bug class — attacker-supplied path components resolving to an arbitrary server-side resource, plus repeated load causing denial of service — maps onto `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs`. Here the "path" is the serialized `(offset, TxOut, OutPoint)` triple: an unprivileged party feeding bytes to `ReceivedOutput::read` can name *any* outpoint (analogous to any file path) with *any* claimed value, and the only downstream consistency check binds the offset to the attacker-chosen `script_pubkey` — a check the attacker trivially satisfies — never to actual chain state.

### Finding Description
`ReceivedOutput::read` deserializes three fully attacker-controlled fields: a scalar `offset`, a `TxOut` (value + `script_pubkey`), and an `OutPoint` (txid + vout), with no validation that the referenced UTXO exists or carries the claimed value [1](#0-0) . The honest producer of this structure is `Scanner::scan_transaction`, which derives the offset and outpoint from real on-chain data [2](#0-1)  — but the `read` path bypasses that guarantee entirely.

`SignableTransaction::new` then trusts the claimed value for its funds accounting (`input_sat`), and adopts the attacker's `offset` verbatim into `self.offsets` [3](#0-2) . The only safeguard is in `SignableTransaction::multisig`, which requires `p2tr_script_buf(keys.offset(offset).group_key()) == prevouts[i].script_pubkey` [4](#0-3) . Because the attacker chooses both `offset` and `script_pubkey`, they satisfy this check by setting `script_pubkey` to the P2TR payload of `key + offset·G` — the same surjective-offset mechanism `register_offset` uses [5](#0-4) . Nothing ever checks that `outpoint` exists on chain or that its real value/script matches the claimed `TxOut`.

### Impact Explanation
A forged `ReceivedOutput` with an inflated `TxOut.value` makes `input_sat` arbitrary, so `NotEnoughFunds` is bypassed and fee/change math is computed against phantom balance [6](#0-5) . Consequences:

- **Funds reported received that are not spendable**: any consumer crediting balance from these bytes records deposits that have no corresponding UTXO.
- **Denial of service on spends**: every `Plan`/`SignableTransaction` built over the forged input produces a transaction referencing a nonexistent prevout, which can never confirm — permanently stalling the batch and locking the real inputs co-spent in it. The attacker can also repeat the load arbitrarily (the "loaded multiple times via the query string" half of the original bug), forcing repeated multisig setup and FROST signing rounds for transactions that are invalid by construction.

Note the check that does exist (`script_pubkey` ↔ offset binding) prevents *stealing* a real output via a mismatched offset, but does nothing against fabricated prevouts — exactly the traversal-within-allowed-shape gap.

### Likelihood Explanation
Medium. Exploitation requires no keys, no threshold collusion, and no malformed encodings — only the ability to supply bytes to `ReceivedOutput::read` (an explicitly in-scope untrusted sink) or to any storage/channel populated from such bytes. The attacker needs one even-Y point, which `register_offset` shows is found within ~2 iterations [7](#0-6) . The attacker's cost is zero since no real UTXO is needed.

### Recommendation
Treat `ReceivedOutput` as a claim, not a fact: only construct `ReceivedOutput` from `Scanner::scan_transaction`/`scan_block` against verified chain data, or require a Merkle/SPV proof binding `outpoint` → `TxOut` before accepting deserialized bytes. At minimum, `SignableTransaction::new` or `multisig` should re-verify each input's `outpoint` against a trusted UTXO view, and deserialization entry points should document that `read` produces unvalidated claims unsuitable for balance accounting.

### Proof of Concept
```
// Given multisig group key K (post tweak_keys), attacker picks o = 0x01....
K_off  = K + G * o                                // k256 affine add
script = p2tr_script_buf(K_off).unwrap()          // retry o += 1 if odd (None)
forged = ReceivedOutput {
    offset:   o,
    output:   TxOut { value: 1_0000_0000, script_pubkey: script },
    outpoint: OutPoint { txid: <random>, vout: 0 },   // nonexistent
};
bytes  = forged.serialize();                       // or raw attacker bytes
let ro = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();   // accepted

// ro is placed into a plan alongside a real input `real_ro`:
let stx = SignableTransaction::new(
    vec![ro, real_ro], payments, Some(change), None, fee_per_vbyte,
).unwrap();                                        // NotEnoughFunds bypassed via phantom value
stx.multisig(&keys).unwrap();                      // script_pubkey check passes (attacker-consistent)
// The signed transaction references a nonexistent prevout -> can never confirm,
// yet the plan recorded `ro.value()` as received balance.
```

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
