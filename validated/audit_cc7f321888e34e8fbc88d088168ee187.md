## Finding: Anyone can steal reward tokens accidentally sent to `ManualCompound`

### Title
Unprivileged callers of `compound()` can steal any token balance sitting in `ManualCompound` (including accidentally-transferred funds) - (File: `rewards/ManualCompound.sol`)

### Summary
`ManualCompound.compound()` is a fully public, unprivileged function that sweeps the contract's entire `balanceOf` for each configured reward token (and for any non-compoundable reward token claimed) and sends/deposits/locks that whole balance to the caller (`msg.sender`), rather than tracking only the amount that was actually harvested during that call.

### Finding Description
In `compound()`, after calling `IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender)`, the function computes the amount to distribute using the raw current token balance of the contract instead of a before/after balance delta: [1](#0-0) 

Both loops use `IERC20(...).balanceOf(address(this))` directly as the amount to transfer/convert/lock to `msg.sender`:
- The "non-compoundable reward" loop: `rewardBalance = IERC20(_rewards[i][j]).balanceOf(address(this))` then `safeTransfer(msg.sender, rewardBalance)`.
- The main compounding loop: `receivedBalance = IERC20(_tokenAddress).balanceOf(address(this))`, which is approved and passed whole to `IConverter.convertFor`, `ILocker.lockFor`, `ISimpleHelper.depositFor`, or `safeTransfer` — all crediting `msg.sender`.

This is the same root cause pattern described in the external report: using the contract's total balance instead of the value actually produced/received by the current operation. Note that elsewhere in this codebase (e.g. `WombatStaking.deposit`/`withdraw`) the correct before/after balance-delta pattern is used to avoid exactly this class of bug: [2](#0-1) 

`ManualCompound.compound()` has no access control (no `onlyOwner`/allowlist), so any wallet can call it at any time.

### Impact Explanation
If any reward token accidentally ends up in the `ManualCompound` contract's balance (a mis-sent transfer, dust left over from a partial/failed prior compound, or reward tokens sent by `masterMagpie` claims that are batched across multiple callers), the next unrelated caller of `compound()` will sweep that entire balance to themselves. This is a direct theft-of-funds vector against whichever user's tokens end up resting in the contract, satisfying the "direct theft of user funds" impact bar.

### Likelihood Explanation
Any unprivileged wallet can trigger this by simply calling `compound()` after observing an incoming transfer to the contract or after a prior partial/failed compound left a balance behind — no privileged role, governance, or oracle manipulation is required, and the attack is a simple front-run/opportunistic call.

### Recommendation
Track balances before and after `multiclaimOnBehalf` (and before/after each conversion step) and use the delta (amount actually harvested in this call) instead of the raw `balanceOf(address(this))`, mirroring the pattern already used in `WombatStaking.deposit`/`withdraw`.

### Proof of Concept
1. Alice (or a buggy prior transaction) accidentally transfers `WOM` (or any configured reward token) directly to the `ManualCompound` contract address.
2. Eve calls `compound(_lps, _rewards, _convertRatio, _minRec, _lockMgp)` with any valid `_lps`/`_rewards` inputs that trigger a legitimate (even zero-value) claim.
3. Inside `compound()`, `receivedBalance = IERC20(_tokenAddress).balanceOf(address(this))` now includes Alice's accidentally transferred tokens along with Eve's legitimately harvested rewards.
4. The whole `receivedBalance` is converted/locked/transferred to `msg.sender` (Eve), so Eve receives Alice's tokens. [3](#0-2)

    function compound(address[] calldata _lps, address[][] calldata _rewards, uint256 _convertRatio, uint256 _minRec, bool _lockMgp) external {
        uint256 rewardTokensLength = rewards.length;        
        IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender);
        // send none compoundable reward back to caller
        for(uint256 i; i < _lps.length; i++) {
            uint256 rewardLength = _rewards[i].length;
            if (rewardLength > 0) {
                for (uint j; j < rewardLength; j++) {
                    if (!compoundableRewards[_rewards[i][j]]) {
                        uint256 rewardBalance = IERC20(_rewards[i][j]).balanceOf(address(this));
                        if (rewardBalance > 0)
                            IERC20(_rewards[i][j]).safeTransfer(msg.sender, rewardBalance);
                    }
                }
            }
        }
        for (uint256 i; i< rewardTokensLength; i++) {
            address _tokenAddress = rewards[i].tokenAddress;
            address _helperAddress = rewards[i].tokenHelper;
            address _convertor = rewards[i].convertor;
            address _locker = rewards[i].locker;
            uint256 receivedBalance = IERC20(_tokenAddress).balanceOf(address(this));

            if (receivedBalance > 0) {
                if (_convertor != address(0)) {
                    IERC20(_tokenAddress).safeApprove(_convertor, receivedBalance);
                    IConverter(_convertor).convertFor(receivedBalance, _convertRatio, _minRec, msg.sender, 2);
                } else if (_locker != address(0) && _lockMgp) {
                    IERC20(_tokenAddress).safeApprove(_locker, receivedBalance);
                    ILocker(_locker).lockFor(receivedBalance, msg.sender);                        
                } else if (_helperAddress != address(0)) { 
                    IERC20(_tokenAddress).safeApprove(_helperAddress, receivedBalance);
                    ISimpleHelper(_helperAddress).depositFor(receivedBalance, msg.sender);
                } else {
                    IERC20(_tokenAddress).safeTransfer(msg.sender, receivedBalance);
                }
            }
        }

        emit Compounded(msg.sender, rewardTokensLength, _lockMgp);
    }
