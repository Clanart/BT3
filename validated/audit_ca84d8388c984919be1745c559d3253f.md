## Title
Non-atomic bandwidth deduction allows permissionless, cost-free draining of an app's prepaid bandwidth balance via replay of a request that fails downstream - ([File: parachain/runtimes/nexus/src/ismp.rs], [File: modules/ismp/core/src/handlers/request.rs], [File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth`'s `try_consume` deducts bytes from an app's prepaid subscription *before* the destination module actually finishes processing the request. If the downstream module call fails after the deduction, `pallet-ismp`'s request handler deletes the request receipt so the (unmodified, still-valid) message can be resubmitted — but the bandwidth already spent is never refunded. Because `handle_unsigned` is a free, permissionless, unsigned extrinsic that anyone can call with the original proof, an unrelated third party can resubmit the exact same failing request over and over, burning the victim app's bandwidth balance to zero without ever delivering the message and without needing a malicious relayer, prover, or admin.

### Finding Description
The bandwidth gate is consulted inside `IsmpModule::on_accept`, *before* the request is actually routed to its destination pallet/module: [1](#0-0) 

`try_consume` mutates `Allowance` storage immediately and unconditionally on success — there is no rollback mechanism tied to the ultimate outcome of the request: [2](#0-1) 

The ISMP request handler stores a receipt before calling `on_accept`, and if `on_accept` returns an error (e.g. `"Destination module not found"`, or any downstream pallet failure that happens *after* the gate already succeeded), it deletes that receipt specifically so the message "can be replayed": [3](#0-2) 

This documented behavior is explicitly called out as a general contract for `IsmpModule` implementers — state mutated before failure is *not* automatically undone, and the protocol relies on modules to avoid irreversible state changes before success is guaranteed: [4](#0-3) 

However, `ProxyModule::on_accept` violates this invariant: it performs the bandwidth deduction (an irreversible, monetarily meaningful state change — the app paid real fee-token for these bytes) *before* the destination dispatch that can still fail (unregistered module, forwarding failure, downstream module logic errors, etc.). Since `handle_unsigned` is explicitly documented as a free, permissionless call ("permits anyone execute ISMP messages for free, provided they have valid proofs and the messages have not been previously processed"): [5](#0-4) 

any observer can watch for a request whose downstream processing predictably fails (e.g. a `to` field pointing at a destination module id that doesn't resolve, or one whose pallet-side logic reliably errors for some independent reason) and repeatedly resubmit the identical `RequestMessage` (same proof, same request, still not "delivered" because the receipt keeps getting deleted). Each resubmission:
1. Passes membership/replay checks (no receipt exists, since it was deleted on prior failure).
2. Re-enters `ProxyModule::on_accept`, which calls `BandwidthGate::try_consume` again, deducting bytes again from the same `(source, app)` subscription.
3. Fails downstream again, receipt deleted again, ready for another free replay.

The corrupted value is `Allowance::<T>` (the `SubscriptionList.remaining_bytes` FIFO ledger) — it is drained on every replay attempt even though the request is never actually delivered, and the "no mutation on insufficient" guarantee documented for the gate only protects against a single failed *attempt*, not against unlimited free retries of a *successful-but-ultimately-failing* consumption.

### Impact Explanation
Bandwidth is a purchased, monetarily-priced on-chain asset (fee-token is spent for it via `BandwidthManager.purchase()`). An attacker who identifies any inbound request destined for a victim app that deterministically fails after the gate check can drain that app's entire prepaid bandwidth allowance for free, permanently denying the app the ability to send further messages until it repurchases — a direct loss of purchased funds/resources inflicted on an innocent third party, reachable purely through the permissionless `handle_unsigned` entrypoint with no privileged or malicious-relayer assumption required. This matches the bounty's "stealing or loss of funds" / "bandwidth balances must move exactly once" pivot.

### Likelihood Explanation
Likelihood is moderate-to-high in specific conditions: it requires a request whose destination processing fails deterministically and repeatably (e.g., misconfigured `to` module id, or any legitimate transient/permanent downstream error condition) after the bandwidth gate has already succeeded. Such conditions are plausible in practice (misconfiguration, module upgrades, paused destination pallets) and, once identified, the exploit itself is trivial and cheap — no proof forgery is needed, only resubmission of an already-valid proof via a free unsigned extrinsic.

### Recommendation
Perform bandwidth accounting only after the destination module has confirmed it can (or did) successfully process the request, or make the deduction transactionally tied to the overall `on_accept` outcome — e.g., wrap the gate consumption and destination dispatch so a downstream failure also reverts the bandwidth mutation (mirrors the `AccountCollateral` recommendation: "if subtraction ... occurs, then transactions should not be reversed" — here, inversely, if the transaction *is* reversed/replayable, the subtraction must be reversed too). Alternatively, only charge bandwidth once a receipt is durably persisted (i.e., move `try_consume` to run only when `on_accept` is about to return `Ok`), or add a per-commitment idempotency check independent of the receipt so repeated free replays cannot re-trigger metering.

### Proof of Concept
1. App `A` on chain `S` purchases a bandwidth tier via `BandwidthManager.purchase()`, crediting `Allowance::<T>` for `(S, A)`.
2. `A` dispatches (or an attacker gets `A` to dispatch, or simply waits for) a POST request whose `to` field addresses a destination module id that is not registered on the destination runtime's router (`ProxyModule::on_accept` will hit the `_ => Err(anyhow!("Destination module not found"))` arm), see: [6](#0-5) 
3. Any third party submits this request + its valid membership proof via `Ismp::handle_unsigned` (unsigned, permissionless, free).
4. `handlers::request::handle` stores the receipt, calls `on_accept`, which consumes bandwidth via `try_consume`, then fails at the destination-module-not-found step; the receipt is deleted per [7](#0-6) .
5. Since the receipt no longer exists, the same third party resubmits the identical `RequestMessage` again — the proof is still valid (membership doesn't change), so step 4 repeats, deducting bandwidth again.
6. Repeating steps 4–5 as many times as blocks allow drains `A`'s entire `remaining_bytes` allowance without a single message ever being delivered, at zero cost to the attacker.

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
