### Title
Zero-value/dust Bitcoin outputs are reported as spendable and accepted as signing inputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` treats a matching `script_pubkey` as sufficient and appends the output without checking its value. An attacker can create consensus-valid zero-value or economically unspendable dust outputs to a scanned Taproot script, causing them to be returned as `ReceivedOutput`s even though `ReceivedOutput` is documented as “a spendable output.” `SignableTransaction::new` similarly enforces a dust minimum on outgoing payments but not on selected inputs, allowing worthless attacker-created outputs to consume transaction weight, fee budget, and threshold-signing work.

### Finding Description
`Scanner::scan_transaction` iterates every transaction output, matches only `output.script_pubkey`, and pushes a `ReceivedOutput` without checking `output.value` [1](#0-0) . `ReceivedOutput::read` has the same issue for serialized inputs: it accepts any consensus-decodable `TxOut` and `OutPoint`, including a zero-value output or an outpoint that was never observed on-chain [2](#0-1) .

On the spend side, `SignableTransaction::new` rejects empty inputs and sub-dust payments, but never rejects zero-value or economically unspendable inputs [3](#0-2) . Each such input is converted into a `TxIn`, included in fee calculation, retained in `prevouts`, and later assigned a per-input FROST signing machine [4](#0-3) [5](#0-4) .

### Impact Explanation
This maps the original “zero mint still registers state” bug class onto Bitcoin scanning: attacker-controlled transaction data creates nominally received outputs that carry no spendable value. If a consumer stores or automatically consumes all scanner results, repeated deposits can grow tracked UTXO state and force transaction construction/signing attempts over useless inputs. The wallet can burn fees or fail with `TooLargeTransaction`/`NotEnoughFunds` only after processing the attacker-supplied entries.

### Likelihood Explanation
An unprivileged party can send Bitcoin transactions paying the multisig’s registered script. A zero-value output is consensus-serializable and decoded by `TxOut::consensus_decode`, while low-value dust outputs can be standard but still uneconomical to spend. The attack does not require a validator, leaked key, malformed curve point, or invalid encoding.

### Recommendation
Enforce a minimum economically spendable value before reporting an output. Prefer making the threshold explicit, such as `Scanner::scan_transaction(tx, min_value)` or scanner-level configuration based on the expected marginal input fee. Also reject zero-value `TxOut`s and null/default outpoints in `ReceivedOutput::read`, and validate input values in `SignableTransaction::new` rather than only validating payment outputs.

### Proof of Concept
```rust
use bitcoin::{
  transaction::{Transaction, Version, TxIn, TxOut},
  Amount, LockTime, OutPoint, ScriptBuf, Sequence, Witness,
};
use serai_bitcoin::wallet::Scanner;

// `script` is a script returned by p2tr_script_buf/registered via
// Scanner::register_offset.
let tx = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![TxIn {
    previous_output: OutPoint::null(),
    script_sig: ScriptBuf::new(),
    sequence: Sequence::MAX,
    witness: Witness::new(),
  }],
  output: vec![TxOut {
    value: Amount::ZERO,
    script_pubkey: script,
  }],
};

let outputs = scanner.scan_transaction(&tx);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].value(), 0);
```

The same result is reached by passing serialized bytes containing `value = 0` to `ReceivedOutput::read`. Adding many such outputs demonstrates unbounded junk entries from public transaction data; passing them to `SignableTransaction::new` demonstrates that there is no input-value/dust rejection before the inputs enter fee and signing machinery.

    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),

        });
