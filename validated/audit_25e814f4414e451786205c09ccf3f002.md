### Title
On-chain DataLayer mirror coins let any unprivileged coin spender force SSRF/HTTP requests to arbitrary attacker-chosen hosts from other users' DataLayer nodes - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user can spend a small XCH coin to create a Chia DataLayer "mirror" coin whose memo field encodes a completely attacker-controlled URL string for a specific `launcher_id` (store id). Any other participant's `DataLayer` service that is tracking that store id will automatically ingest that URL as a trusted subscription server and periodically issue unauthenticated outbound HTTP `GET`/`POST` requests to it (or hand it to a downloader/uploader plugin), with no scheme, host, or IP restriction. This is analogous to CVE-2024-10524, where an attacker-controlled URL fed into a networking client with no host-validation results in SSRF, except here the "URL" originates from on-chain memo data controlled by any spend-bundle submitter rather than a CLI argument.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a standard-wallet spend that creates a mirror coin whose puzzle is `create_mirror_puzzle()` (a `P2_PARENT` puzzle), with memos of `[launcher_id, *urls]` [1](#0-0) . The `urls` list is raw, unvalidated bytes supplied by the coin creator — there is no scheme allow-list, DNS/IP restriction, or format check anywhere in this path.

When any node observes a coin spent to the mirror puzzle hash, `DataLayerWallet.coin_added()` decodes the memo, and — as long as it is tracking that `launcher_id` — persists the attacker-chosen URLs into its local `DataLayerStore.add_mirror()` table, without any validation of the URL contents [2](#0-1) [3](#0-2) .

The `DataLayer` service coordinator periodically pulls these wallet-known mirror URLs into its subscription table via `update_subscriptions_from_wallet()`, which only strips a trailing `/` — no other validation [4](#0-3) .

During the background sync loop, `fetch_and_validate()` selects one of these attacker-controlled URLs and either performs a raw HTTP GET via `http_download()` or POSTs the URL to a configured downloader plugin [5](#0-4) . `http_download()` builds the request directly from `server_info.url + "/" + filename` with no host restriction [6](#0-5) . There is no validation anywhere in `chia/data_layer/` restricting scheme (`http://`, `file://`, internal hostnames) or destination IP (loopback, link-local, cloud metadata addresses, RFC1918 ranges) — confirmed by the absence of any such checks in `data_layer.py`, `download_data.py`, or `dl_wallet_store.py`.

### Impact Explanation
This lets any unprivileged party who can broadcast a spend bundle (the cost of one small-amount coin plus fee) plant a persistent, on-chain "beacon" URL that will be automatically and repeatedly fetched by every other node that subscribes to or tracks the same DataLayer store — a common cooperative action for DataLayer clients sharing data. This enables SSRF against internal services reachable from those nodes' machines (e.g., cloud metadata endpoints, internal admin panels, local RPC ports), outbound request forgery for reconnaissance/DoS against third parties chosen by the attacker, and forced network fetches that leak the victim node's IP/timing to attacker infrastructure. Because the URL is embedded in an on-chain coin spend, it is durable, replicated to all nodes, and cannot be revoked except by spending a `delete_mirror` transaction (which the attacker's coin owner must sign, not the victim).

### Likelihood Explanation
Likelihood is high for any DataLayer user who subscribes to third-party stores (a normal use case). No signature or permission beyond the ability to spend an XCH coin (any wallet) is required, and the resulting periodic fetch happens automatically in the background sync loop without operator interaction.

### Recommendation
Add a strict allow-list/validation layer for all DataLayer mirror/subscription URLs before they are persisted or dereferenced: enforce `https://` scheme, resolve and reject loopback/link-local/private/cloud-metadata IP ranges, and re-validate at fetch time (not just at ingestion) to defend against DNS rebinding. Apply this validation uniformly in `DataLayerWallet.coin_added()` (before persisting mirrors), `DataLayer.update_subscriptions_from_wallet()` (before adding subscriptions), and `download_data.http_download()`/`DataLayer.get_downloader()` (before making the request), so that no code path can dereference an unvalidated attacker-supplied URL.

### Proof of Concept
1. Attacker creates any DataLayer store or references an existing `launcher_id` that a victim already subscribes to/tracks.
2. Attacker calls `create_new_mirror(launcher_id, amount, urls=[b"http://169.254.169.254/latest/meta-data/"], action_scope, fee=...)` (exposed via RPC `dl_new_mirror` / CLI `chia data add_mirror`) and pushes the resulting spend bundle to the mempool [1](#0-0) .
3. Once the transaction confirms, any victim node tracking `launcher_id` picks up the mirror via `coin_added()` and stores the URL [2](#0-1) .
4. The victim's `DataLayer.periodically_manage_data()` loop calls `update_subscription()` → `update_subscriptions_from_wallet()` → `fetch_and_validate()`, which issues an outbound HTTP request to the attacker-chosen URL via `http_download()`, with no host/scheme validation [5](#0-4) [6](#0-5) .

    async def add_mirror(self, mirror: Mirror) -> None:
        """
        Add a mirror coin to the DB
        """

        async with self.db_wrapper.writer_maybe_transaction() as conn:
            await conn.execute_insert(
                "INSERT OR REPLACE INTO mirrors VALUES (?, ?, ?, ?, ?)",
                (
                    mirror.coin_id,
                    mirror.launcher_id,
                    mirror.amount.stream_to_bytes(),
                    b"".join(
                        [uint16(len(url)).stream_to_bytes() + url for url in Mirror.encode_urls(mirror.urls)]
                    ),  # prefix each item with a length
                    1 if mirror.ours else 0,
                ),
            )

async def http_download(

    """

    """
    async with aiohttp.ClientSession() as session:

        async with session.get(
