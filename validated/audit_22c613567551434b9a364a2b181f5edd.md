### Title
`_calExpireForfeit` in mWOMSVBaseRewarder never applies the unlock-decay forfeit, letting users in cooldown claim full rewards without redistribution - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` hardcodes `rewardableAmount = _amount` instead of scaling by `mWomSV.getRewardablePercentWAD(_account)` as the sibling `vlMGPBaseRewarder._calExpireForfeit` does. As a result, `forfeitAmount` is always `0`, so any user who has started unlocking (cooldown) via `mWomSV.startUnlock` and then calls `getReward`/`getRewards` (directly or via `MasterMagpie.multiclaim`) receives 100% of their accrued rewards instead of the decayed share, and nothing is redistributed to remaining lockers via `_queueNewRewardsWithoutTransfer`.

### Finding Description
`_sendReward` computes the payout as:
```
forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
toSend = userRewards[_rewardToken][_account] - forfeitAmount;
``` [1](#0-0) 

In the correct implementation (`vlMGPBaseRewarder`), `_calExpireForfeit` reduces the rewardable amount proportionally to the user's `getRewardablePercentWAD`, which decays as unlocking cooldown progresses:
```
uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
``` [2](#0-1) 

But `mWOMSVBaseRewarder._calExpireForfeit` never calls `mWomSV.getRewardablePercentWAD`; it sets `rewardableAmount = _amount` directly:
```
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardableAmount = _amount;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;
    ...
}
``` [3](#0-2) 

This means `forfeitAmount` is always `0` regardless of cooldown state, so `toSend == userRewards[...]` always, and the forfeit-redistribution branch `_queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken)` never executes. The `mWomSV` contract does implement the decay logic (`getRewardablePercentWAD`) that accounts for `amountInCoolDown` and elapsed time [4](#0-3) , but the rewarder simply fails to consult it. `getReward` is only gated by `onlyMasterMagpie` and `updateReward(_account)`, both of which are satisfied by a normal unprivileged user calling `MasterMagpie.multiclaim`, so no existing modifier blocks this path.

### Impact Explanation
This is a theft/misallocation of unclaimed yield: the protocol's invariant is that a user who has started unlocking (i.e., partially exiting the mWomSV lock) should only be able to claim a time-decayed share of rewards, with the forfeited remainder redistributed pro-rata to users who keep their mWomSV locked (via `rewardPerTokenStored` bump in `_queueNewRewardsWithoutTransfer`). Because the forfeit is never computed, unlocking users capture 100% of accrued rewards, permanently denying the forfeited share to remaining lockers — a direct, quantifiable loss of unclaimed yield for the honest, still-locked stakers.

### Likelihood Explanation
This requires no special privilege: any holder of mWOMSV can call `mWomSV.startUnlock` (a normal public unlock action) and then call `getReward`/`getRewards` through `MasterMagpie.multiclaim` at any time, including immediately or after cooldown expiry, to claim full rewards. It is trivially repeatable by every mWOMSV holder and requires no flash loans or front-running — just normal protocol usage — making exploitation both cheap and highly likely to occur even unintentionally by normal users, let alone attackers.

### Recommendation
Fix `_calExpireForfeit` in `mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder.sol`: fetch `uint256 rewardablePercentWAD = mWomSV.getRewardablePercentWAD(_account);` and compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18;` before deriving `forfeitAmount`.

### Proof of Concept
Foundry test outline:
1. Deploy `MasterMagpie`, `mWomSV`, `mWOMSVBaseRewarder`, and a reward token; register the rewarder pool.
2. Two users (Alice, Bob) each deposit equal mWOMSV and accrue rewards via `queueNewRewards`.
3. Alice calls `mWomSV.startUnlock(amount)` to enter cooldown, then warps `block.timestamp` past `endTime` without withdrawing.
4. Alice calls `getReward` (or `MasterMagpie.multiclaim`).
5. Assert: `received == earned(alice, token)` (full amount) instead of a decayed amount computed via `getRewardablePercentWAD`.
6. Assert: `rewards[token].queuedRewards` and `rewardPerTokenStored` are unchanged by Alice's claim (no forfeit contribution), proving Bob never receives the redistributed share he is owed under the intended invariant.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
