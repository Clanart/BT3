### Title
Malformed generator-promotion proof set crashes `GeneratorPromotion::complete` - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` trusts a peer-supplied `HashMap<Participant, GeneratorProof<C1>>` to contain exactly the expected participant indexes. It validates only the map length and that every key is `<= n`; it does not reject the local participant's index or verify that all required participants are present. A peer can therefore submit `n - 1` entries containing the victim's own participant index while omitting another participant. The subsequent mandatory lookup unwraps `None` and panics. [1](#0-0) 

### Finding Description
The function first requires `proofs.len() == n - 1`, then checks only the upper bound of each supplied participant index. [2](#0-1)  It does not check whether `proofs` contains `params.i()`, nor does it compare the key set with all indexes `1..=n` excluding `params.i()`. [3](#0-2) 

Later, the code iterates every participant except the local one and unconditionally executes `proofs.get(&i).unwrap()`. [4](#0-3)  Because `HashMap` keys are unique, inserting an entry under `params.i()` consumes one of the accepted `n - 1` entries and necessarily causes at least one required non-local participant to be absent. Reaching that absent participant causes a panic before proof verification or key promotion completes. [5](#0-4) 

### Impact Explanation
An unauthenticated protocol participant that can supply a generator-promotion proof map can repeatedly crash the caller's key-promotion path. The malformed input does not need a valid proof, valid promoted share, or knowledge of any secret; it only needs the right number of map entries and participant indexes no greater than `n`. In a service that invokes `complete` on peer-provided messages, this produces a repeatable denial of service and prevents completion of the promotion ceremony. [6](#0-5) 

### Likelihood Explanation
The malformed map is accepted by the explicit validation path: it has `n - 1` entries and every key satisfies `i <= n`. The panic is deterministic because `proofs.get(&i).unwrap()` is executed for every non-local participant, including the omitted one. Any integration that deserializes or otherwise accepts peer-selected `Participant` keys into this map is exposed. [7](#0-6) 

### Recommendation
Validate the exact expected participant set before indexing. For every `i in 1..=params.n()` where `i != params.i()`, require `proofs.contains_key(&i)`, and reject any proof whose key equals `params.i()` or is otherwise outside that set. Replace `proofs.get(&i).unwrap()` with an error-returning lookup, for example `proofs.get(&i).ok_or(PromotionError::MissingParticipant(i))`, while retaining a strict equality check between the supplied and expected sets. [8](#0-7) 

### Proof of Concept
```rust
// Assume victim has participant index i and n >= 2.
let mut proofs = HashMap::new();

// Insert a syntactically valid map entry under the victim's own index.
// The concrete proof contents do not matter because lookup failure occurs
// before proof verification for the omitted participant.
proofs.insert(params.i(), attacker_controlled_or_dummy_proof);

// Fill the remaining n - 2 entries with any other participant indexes <= n,
// omitting at least one required non-victim participant.
for p in other_participants_excluding_victim_and_one_required_participant {
    proofs.insert(p, attacker_controlled_or_dummy_proof);
}

assert_eq!(proofs.len(), usize::from(params.n()) - 1);

// Passes both existing checks, then panics on:
//   proofs.get(&omitted_participant).unwrap()
let _ = promotion.complete(&proofs);
```

The panic occurs because `complete` treats `n - 1` arbitrary in-range keys as equivalent to the required set `1..=n` excluding the local participant. [7](#0-6)

  pub fn complete(
    self,
    proofs: &HashMap<Participant, GeneratorProof<C1>>,
  ) -> Result<ThresholdKeys<C2>, PromotionError> {
    let params = self.base.params();
    if proofs.len() != (usize::from(params.n()) - 1) {
      Err(PromotionError::IncorrectAmountOfParticipants {
        t: params.n(),
        n: params.n(),
        amount: proofs.len() + 1,
      })?;
    }
    for i in proofs.keys().copied() {
      if u16::from(i) > params.n() {
        Err(PromotionError::InvalidParticipant { n: params.n(), participant: i })?;
      }
    }

    let mut verification_shares = HashMap::new();
    verification_shares.insert(params.i(), self.proof.share);
    for i in 1 ..= params.n() {
      let i = Participant::new(i).unwrap();
      if i == params.i() {
        continue;
      }

      let proof = proofs.get(&i).unwrap();
      proof
        .proof
        .verify(
          &mut transcript(&self.base.original_group_key(), i),
          &[C1::generator(), C2::generator()],
          &[self.base.original_verification_share(i), proof.share],
        )
        .map_err(|_| PromotionError::InvalidProof(i))?;
      verification_shares.insert(i, proof.share);
