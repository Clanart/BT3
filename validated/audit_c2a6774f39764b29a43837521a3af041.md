### Title
Unanchored `commitMentionUrl` regex lets `CommitMentionLinkFilter` render a trusted-looking commit label over an attacker-controlled `href` - (File: `app/src/lib/markdown-filters/commit-mention-link-filter.ts`)

### Summary
`CommitMentionLinkFilter` is applied to markdown rendered from repository/API content (issue, PR, and commit descriptions) via `buildCustomMarkDownNodeFilterPipe` [1](#0-0) . It looks for anchors whose visible text equals the `href` and whose `href` matches `commitMentionUrl` [2](#0-1) , then rewrites the label to a short `owner/repo@sha` reference while leaving the original `href` untouched [3](#0-2) [4](#0-3) .

### Finding Description
`commitMentionUrl` is built without a leading `^` anchor, so `RegExp.test()` matches the GitHub URL pattern anywhere inside the `href` string, not just when the `href` begins with it [5](#0-4) . Additionally, `filter()` never re-checks the URL's actual origin/host - it only parses `url.pathname` of the anchor text/href to derive `owner`, `name`, and the ref [6](#0-5) .

By crafting a markdown auto-link whose raw URL text (and therefore `href`, since markdown auto-linking sets `href === text`) is on an attacker-controlled host but:
1. contains `owner/repo/commit/<sha>` as the malicious host's own path (which `filter()` parses into `owner`, `name`, `ref`), and
2. also contains the literal substring `https://github.com/.../commit/<sha>` elsewhere in the URL (e.g. in the query string), purely to satisfy the unanchored `commitMentionUrl.test()` gate,

the filter passes the tree-walker gate and replaces the anchor's inner text with `owner/repo@<sha>` while the anchor's `href` attribute is copied unmodified from the original malicious URL (`newNode = node.cloneNode(true)` only mutates `innerHTML`, not `href`) [7](#0-6) .

Example crafted `href`/text:
```
https://evil.example/owner/repo/commit/abcdef1234567?ref=https://github.com/owner/repo/commit/abcdef1234567
```
- `commitMentionUrl.test(href)` → `true`, because the regex (unanchored) finds `https://github.com/owner/repo/commit/abcdef1234567` inside the query string.
- `filter()` parses `new URL(href).pathname` = `/owner/repo/commit/abcdef1234567`, extracting `owner=owner`, `name=repo`, `path="commit/abcdef1234567"`, which matches `commitPath`, yielding `ref="abcdef1234567"`.
- Output: the anchor's inner HTML becomes `owner/repo@<tt>abcdef1234567</tt>` (a trusted-looking GitHub commit reference), while `href` still points to `https://evil.example/...`.

The specific PoC suggested in the review question (`https://evil.example/?x=https://github.com/owner/repo/commit/abcdef1`) does pass the `commitMentionUrl.test()` gate for the same unanchored-regex reason, but does **not** by itself produce a spoofed label: `new URL(text).pathname` for that URL is `/`, so `owner`/`name` extraction fails (`name === undefined`) and `filter()` returns `null`, leaving the original (honest, matching) link untouched. The exploit only becomes live when the attacker also places a legitimate-looking `owner/repo/commit/<sha>` path segment as the malicious host's *own* path (as shown above), independent of the decoy GitHub substring used purely to pass the gate.

### Impact Explanation
This breaks the link-trust invariant: Desktop renders a short, GitHub-style commit reference label (`owner/repo@sha`) for a link that actually navigates to an attacker-controlled URL. A user who trusts the rendered `owner/repo@sha` text and clicks it is redirected to the attacker's site instead of GitHub, which can be used for credential phishing, delivering further exploit payloads, or chaining into other renderer-side issues, all without requiring unnatural user interaction beyond a normal click on a rendered markdown link (issue/PR/commit descriptions are attacker-controlled content that Desktop renders).

### Likelihood Explanation
Reasonably likely: the content path is attacker-controlled repository/PR/issue markdown, rendered automatically whenever a maintainer or collaborator views the PR/issue/commit in Desktop's markdown viewer via `buildCustomMarkDownNodeFilterPipe` [8](#0-7) . No special privileges are needed - just posting a crafted URL as a comment/description on a repository the victim views in Desktop, relying on the markdown auto-linker to set `href === text`.

### Recommendation
Anchor the `commitMentionUrl` regex to the start of the string (and ideally validate it against `url.origin`/`url.host` rather than only `url.pathname`) so that the GitHub host must be the actual origin of the `href`, not merely a substring anywhere in it. Additionally, `filter()` should independently verify `url.origin === getHTMLURL(this.repository.endpoint)` before trusting `url.pathname` to build the replacement label.

### Proof of Concept
Markdown/plain-text content that would auto-link to an anchor tag with `href === innerText`:
```
https://evil.example/owner/repo/commit/abcdef1234567?ref=https://github.com/owner/repo/commit/abcdef1234567
```
When rendered through the `CommitMentionLinkFilter` pipeline, the resulting anchor keeps `href="https://evil.example/owner/repo/commit/abcdef1234567?ref=..."` but displays the label `owner/repo@abcdef1234567`, misrepresenting the link destination.

export const buildCustomMarkDownNodeFilterPipe = memoizeOne(
  (options: ICustomMarkdownFilterOptions): ReadonlyArray<INodeFilter> => {
    const { emoji, repository, markdownContext } = options
    const filterPipe: Array<INodeFilter> = []

    if (repository !== undefined) {
      /* The CloseKeywordFilter must be applied before the IssueMentionFilter or
       * IssueLinkFilter so we can scan for plain text or pasted link issue
       * mentions in conjunction wth the keyword.
       */
      if (
        markdownContext !== undefined &&
        isIssueClosingContext(markdownContext)
      ) {
        filterPipe.push(new CloseKeywordFilter(markdownContext, repository))
      }

      filterPipe.push(
        new IssueMentionFilter(repository),
        new IssueLinkFilter(repository)
      )
    }

    filterPipe.push(new EmojiFilter(emoji))

    if (repository !== undefined) {
      filterPipe.push(
        // Note: TeamMentionFilter was placed before MentionFilter as they search
        // for similar patterns with TeamMentionFilter having a larger application.
        // @org/something vs @username. Thus, even tho the MentionFilter regex is
        // meant to prevent this, in case a username could be encapsulated in the
        // team mention like @username/something, we do the team mentions first to
        // eliminate the possibility.
        new TeamMentionFilter(repository),
        new MentionFilter(repository),
        new CommitMentionFilter(repository),
        new CommitMentionLinkFilter(repository)
      )
    }

    filterPipe.push(new VideoTagFilter(), new VideoLinkFilter())

    return filterPipe
  }
)

  private get commitMentionUrl(): RegExp {
    const gitHubURL = getHTMLURL(this.repository.endpoint)
    return new RegExp(
      escapeRegExp(gitHubURL) +
        '/' +
        this.nameWithOwner.source +
        '/' +
        /(commit|pull|compare)/.source +
        '/' +
        /(\d+\/commits\/)?/.source +
        /([0-9a-f]{7,40})/.source +
        /\b/.source
    )
  }

  public createFilterTreeWalker(doc: Document): TreeWalker {
    return doc.createTreeWalker(doc.body, NodeFilter.SHOW_ELEMENT, {
      acceptNode: (el: Element) => {
        return (el.parentNode !== null &&
          ['CODE', 'PRE', 'A'].includes(el.parentNode.nodeName)) ||
          !isElement(el, 'a') ||
          el.href !== el.innerText ||
          !this.commitMentionUrl.test(el.href)
          ? NodeFilter.FILTER_SKIP
          : NodeFilter.FILTER_ACCEPT
      },
    })
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const newNode = node.cloneNode(true)
    const { textContent: text } = newNode
    if (!isElement(newNode, 'a') || text === null) {
      return null
    }

    const url = new URL(text)
    const [, owner, name] = url.pathname.split('/', 3)
    if (owner === undefined || name === undefined) {
      return null
    }
    const slashes = 3
    const path = url.pathname.substring(owner.length + name.length + slashes)

    let ref, filepathToAppend

    const commitComparePathMatch =
      this.getRefFromCommitPath(path) ?? this.getRefFromComparePath(path)
    if (commitComparePathMatch !== null) {
      ;({ ref, filepathToAppend } = commitComparePathMatch)

      filepathToAppend =
        filepathToAppend !== undefined
          ? filepathToAppend + url.search
          : url.search
    } else {
      ref = this.getRefFromPullPath(path)
    }

    if (ref === null || ref === undefined) {
      return null
    }

    newNode.innerHTML = this.getCommitMentionRef(
      owner,
      name,
      ref,
      filepathToAppend
    )
    return [newNode]
  }

  private getCommitMentionRef(
    owner: string,
    name: string,
    shaRef: string,
    filePath?: string
  ) {
    const ownerRepo =
      owner !== this.repository.owner.login || name !== this.repository.name
        ? `${owner}/${name}@`
        : ''
    const trimmedSha = this.trimCommitSha(shaRef)
    return `${ownerRepo}<tt>${trimmedSha}</tt>${filePath ?? ''}`
  }
