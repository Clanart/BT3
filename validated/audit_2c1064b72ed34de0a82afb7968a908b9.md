### Title
Unbounded recursive outer-puzzle driver traversal causes wallet stack-overflow/DoS on crafted nested puzzle reveals - (File: chia/wallet/cat_wallet/cat_outer_puzzle.py, chia/wallet/nft_wallet/ownership_outer_puzzle.py, chia/wallet/vc_wallet/cr_outer_puzzle.py, chia/wallet/puzzle_drivers.py)

### Summary
Chia's wallet-side "outer puzzle" driver framework (`CATOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`, and the underlying `PuzzleInfo.also()`/`check_type()` chain) recursively unwraps nested puzzle layers when matching, constructing, or solving a puzzle reveal, with no bound on how many "also" layers may be chained. A spend bundle or offer containing a puzzle reveal with an attacker-controlled, arbitrarily deep stack of recognized wrapper layers (CAT / ownership / CR / singleton / metadata, etc., each of which is cheap to curry in CLVM) drives unbounded Python-level recursion in the wallet when it processes that spend, mirroring the Suricata bug class of "attacker-controlled nesting depth drives unbounded recursive processing → stack exhaustion."

### Finding Description
`PuzzleInfo.also()` and `PuzzleInfo.check_type()` recurse once per nested `"also"` key with no depth limit: `chia/wallet/puzzle_drivers.py` lines 60-79 [1](#0-0) . `PuzzleInfo` objects are produced by the various `OuterPuzzle.match()` implementations, which themselves recurse into the inner puzzle for every layer found: `CATOuterPuzzle.match()`/`get_inner_puzzle()` call `self._match(...)` / `self._get_inner_puzzle(...)` on the wrapped inner puzzle [2](#0-1) , `OwnershipOuterPuzzle.match()`/`construct()`/`get_inner_puzzle()`/`get_inner_solution()`/`solve()` do the same for the ownership layer [3](#0-2) , and `CROuterPuzzle` mirrors this for the credential-restricted (CR-CAT/VC) layer [4](#0-3) . None of these functions caps the number of "also" layers it will traverse — each layer only requires a cheap CLVM curry to construct on-chain, so an attacker can build a puzzle reveal with thousands of nested recognized wrapper layers at negligible CLVM cost, then hand it to a victim wallet inside a `CoinSpend`, an offer file, or a spend bundle to be inspected/imported (offers/CATs/NFTs/VCs are all "unprivileged spend-bundle submitter / offer counterparty" reachable flows per the wallet's driver lookup).

This is structurally the same bug class as CVE-2026-22260: a piece of untrusted, attacker-controlled data encodes its own nesting/recursion depth, and the parser/decompressor recurses once per nesting level with no depth cap, eventually exhausting the call stack.

### Impact Explanation
When a wallet (or a component using the outer-puzzle driver lookup, e.g. offer parsing/`Offer` construction, CAT/CR-CAT/VC wallet code, or NFT driver resolution) processes such a crafted puzzle reveal, the recursive `match()`/`construct()`/`get_inner_puzzle()`/`get_inner_solution()`/`solve()` calls, plus `PuzzleInfo.also()`/`check_type()`, will recurse proportionally to the attacker-chosen nesting depth. This can raise an uncaught `RecursionError` (or, in more constrained embedded/threaded contexts, exhaust the native stack), halting processing of that spend/offer and potentially crashing the wallet task/process that is inspecting it — a spend/offer-triggered transaction-processing halt, matching the "Accept" criteria for a spend-triggered processing halt. Impact is limited to availability (no direct fund loss or supply inflation), consistent with the original CVE's `C:N/I:N/A:H` profile.

### Likelihood Explanation
Likelihood is high for triggering the recursion, since constructing N nested recognized outer-puzzle layers (CAT/ownership/CR/singleton) is cheap on-chain and requires no special privileges — any spend-bundle submitter or offer creator can build it. What is less certain (and not fully verifiable from the available index) is the exact practical recursion depth achievable before Python's default recursion limit is hit versus native stack exhaustion, and whether any of the calling contexts (e.g., `driver_lookup` iteration in `chia/wallet/outer_puzzles.py`) impose an implicit cap — that file's contents could not be retrieved in this session due to tool/time limits, so this should be independently confirmed before treating this as a fully proven exploit path.

### Recommendation
Add an explicit maximum nesting-depth check in `PuzzleInfo.also()`/`check_type()` and in each `OuterPuzzle` implementation's recursive `match`/`construct`/`get_inner_puzzle`/`get_inner_solution`/`solve` methods, rejecting puzzle reveals whose "also" chain exceeds a small sane bound (e.g., a few dozen layers), and convert the traversal to an iterative loop where practical (similar to the non-recursive `sha256_treehash` implementation already used elsewhere in the codebase) [5](#0-4) .

### Proof of Concept
Construct a puzzle reveal that nests N (e.g., 5,000) recognized outer-puzzle layers (e.g., alternating CAT and ownership layers) around a trivial inner puzzle, each layer costing only a `curry` operation in CLVM. Include this puzzle reveal in a `CoinSpend`/offer and have a wallet call the driver lookup's `match()` (or `get_inner_puzzle`/`get_inner_solution`/`solve`) on it, e.g. via `CATOuterPuzzle.match()` [6](#0-5)  or `OwnershipOuterPuzzle.get_inner_puzzle()` [7](#0-6) ; observe a `RecursionError` (or stack fault) once N exceeds the interpreter's recursion limit.

class CROuterPuzzle:
    _match: Callable[[UnknownPuzzle], PuzzleInfo | None]
    _construct: Callable[[PuzzleInfo, Program], Program]
    _solve: Callable[[PuzzleInfo, Solver, Program, Program], Program]
    _get_inner_puzzle: Callable[[PuzzleInfo, UnknownPuzzle, Program | None], Program | None]
    _get_inner_solution: Callable[[PuzzleInfo, Program], Program | None]

    def match(self, puzzle: UnknownPuzzle) -> PuzzleInfo | None:
        args: tuple[list[bytes32], Program, Program] | None = match_cr_layer(puzzle)
        if args is None:
            return None
        authorized_providers, proofs_checker, inner_puzzle = args
        constructor_dict: dict[str, Any] = {
            "type": "credential restricted",
            "authorized_providers": ["0x" + ap.hex() for ap in authorized_providers],
            "proofs_checker": disassemble(proofs_checker),
        }
        next_constructor = self._match(UnknownPuzzle(known_program=inner_puzzle))
        if next_constructor is not None:
            constructor_dict["also"] = next_constructor.info
        return PuzzleInfo(constructor_dict)

    def get_inner_puzzle(
        self, constructor: PuzzleInfo, puzzle_reveal: UnknownPuzzle, solution: Program | None = None
    ) -> Program | None:
        args: tuple[list[bytes32], Program, Program] | None = match_cr_layer(puzzle_reveal)
        if args is None:
            raise ValueError("This driver is not for the specified puzzle reveal")  # pragma: no cover
        _, _, inner_puzzle = args
        also = constructor.also()
        if also is not None:
            deep_inner_puzzle: Program | None = self._get_inner_puzzle(
                also, UnknownPuzzle(known_program=inner_puzzle), None
            )
            return deep_inner_puzzle
        else:
            return inner_puzzle

    def get_inner_solution(self, constructor: PuzzleInfo, solution: Program) -> Program | None:
        my_inner_solution: Program = solution.at("rrrrrrf")
        also = constructor.also()
        if also:
            deep_inner_solution: Program | None = self._get_inner_solution(also, my_inner_solution)
            return deep_inner_solution
        else:
            return my_inner_solution

    def asset_id(self, constructor: PuzzleInfo) -> bytes32 | None:
        return None

    def construct(self, constructor: PuzzleInfo, inner_puzzle: Program) -> Program:
        also = constructor.also()
        if also is not None:
            inner_puzzle = self._construct(also, inner_puzzle)
        return construct_cr_layer(
            constructor["authorized_providers"],
            constructor["proofs_checker"] if "proofs_checker" in constructor else PROOF_FLAGS_CHECKER,
            inner_puzzle,

        coin_name: str = coin.name().hex()

            vc_info: tuple[Program, Program, bytes32, bytes32 | None, bytes32 | None] = tuple(
                solver["vc_authorizations"][coin_name]
            )
        else:
            proofs_checker = UnknownPuzzle(known_program=constructor["proofs_checker"])
            assert proofs_checker.curried_args is not None
            vc_info = (

                None,
                None,

        also = constructor.also()
        if also is not None:
            inner_solution = self._solve(also, solver, inner_puzzle, inner_solution)

        return solve_cr_layer(
            *vc_info,

            inner_solution,
