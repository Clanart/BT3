### Title
Unbounded ABI-decode memory amplification in static (non-dynamic-gas) EVM precompiles allows out-of-gas-budget memory allocation - (File: precompiles/common/precompiles.go)

### Summary
The static precompile execution path (`Precompile.Run` → `Precompile.Prepare`) calls go-ethereum's `abi.Arguments.Unpack` on raw calldata immediately after only a linear, length-based `RequiredGas` charge, with no charge proportional to the actual decode cost. The `DynamicGasPrecompile` path was hardened against exactly this issue via `chargeDecodeGas`/`DecodeGasCost`, and a regression test (`TestVoteWeightedAliasedOptionsRejectedBeforeUnpack`) documents the underlying bug class, but the fix was not applied to the static `Precompile.Prepare` path that many other precompiles still use.

### Finding Description
`Precompile.RequiredGas` charges gas linearly in `len(input)` via `p.executor.RequiredGas(input[4:], method)` [3](#0-2) . `Precompile.Prepare` then unpacks the calldata directly with `method.Inputs.Unpack(argsBz)` without any additional gas charge tied to the actual decode cost [1](#0-0) .

The `DynamicGasPrecompile.RunAndCalculateGas` comment explicitly documents the root cause this analog exploits: "ABI decoding of attacker-controlled calldata can cost far more than len(input) (a single string can be referenced by many array/tuple slots), so it must be paid for out of the gas the caller supplied" [4](#0-3) . For the dynamic-gas path this is mitigated by `chargeDecodeGas`, which walks the ABI type tree to compute the real string-copy volume via `DecodeGasCost`/`decodeStringCopyBytes` before calling `Unpack`, and rejects the call if the gas meter can't afford it [5](#0-4) , [6](#0-5) .

The comment in `decode_cost.go` explains the amplification mechanism precisely: "a single string can be referenced by many array/tuple slots, the copied volume can be super-linear in len(input) (worst case ~len(input)^2)" [7](#0-6) . This is the same bug class as the Pillow CVE: a size/offset value embedded in attacker-controlled input drives a memory allocation whose actual cost is not validated/charged against a declared bound before the allocation is performed.

The existing regression test constructs exactly this attack shape — many array elements whose dynamic-tuple offsets all alias one shared payload, so calldata stays small (~40 KiB) while `Unpack`'s decoded copy volume would be large — and asserts it is caught before `Unpack` runs on the dynamic-gas path [8](#0-7) . However, all precompiles built on the plain `Precompile` type (not `DynamicGasPrecompile`) — e.g. `addr`, `bank`, `json`, `staking`, and their numerous versioned `legacy/vNNN` copies — invoke `Prepare`/`Unpack` with no equivalent protection, e.g. `precompiles/bank/legacy/v555/bank.go:135-165`, `precompiles/addr/legacy/v552/addr.go:97-110`, `precompiles/common/legacy/v552/precompiles.go:37-58`, and the many other `legacy/vNNN/precompiles.go` variants that all share the same unprotected `Prepare` shape.

### Impact Explanation
An unprivileged EVM caller can invoke any static (non-`DynamicGasPrecompile`) precompile method whose ABI signature contains a `string`, `bytes`, or dynamic array/tuple type, with crafted calldata that pays only linear `RequiredGas` (bounded by EVM block gas limit / calldata gas cost) but triggers a decode whose Go-heap allocation volume is quadratic in the calldata size (worst case ~len(input)^2, as documented in the mitigation comment). Because static precompiles are gas-metered by `vm.RunPrecompiledContract`'s linear `RequiredGas` alone before `Run`/`Unpack` executes, an attacker can size calldata just under whatever tx gas limit is available while forcing the node to allocate memory disproportionate to what was paid for, causing excessive per-call memory pressure/GC load on validator/RPC nodes executing the transaction. This does not directly cause fund loss but can degrade block-processing performance and increase block time when repeated (e.g., in a batch of transactions in one block), potentially contributing to block delay.

### Likelihood Explanation
Medium-High: the attack requires no special privileges — just calling an affected static precompile method with adversarial calldata that a normal EVM transaction sender or contract can construct and submit. The vulnerable code path is a straightforward reuse of the unmitigated `Precompile.Prepare`, used by many precompiles across many versioned packages, indicating the mitigation applied to `DynamicGasPrecompile` was not uniformly rolled out.

### Recommendation
Apply the same `chargeDecodeGas`/`DecodeGasCost` pattern used in `DynamicGasPrecompile.RunAndCalculateGas` to the static `Precompile.Prepare` path before calling `method.Inputs.Unpack`, so the decode's real string/array-copy cost is charged against the gas meter (and rejected on insufficient gas) prior to allocation, for every precompile method whose inputs can contain dynamic types.

### Proof of Concept
1. Identify a static (non-dynamic-gas) precompile method whose ABI inputs include a dynamic type reachable via `abiContainsString` (e.g. `string`, `string[]`, or a tuple/array containing one) — for example any similarly-shaped method on `bank`, `addr`, `json`, or `staking` precompiles that use `pcommon.NewPrecompile` rather than `pcommon.NewDynamicGasPrecompile`.
2. Craft calldata analogous to `craftAliasedVoteWeightedArgs`/`newAliasedVoteWeightedArgs` in `precompiles/gov/gov_test.go:1268-1282` and `precompiles/common/decode_cost_test.go:145-165`: build an array whose N dynamic-tuple/array element offsets all point at one shared (small) payload containing a large declared string/bytes length, keeping raw calldata small (tens of KiB) while the ABI-decoded copy volume scales as N × payload size.
3. Submit this calldata as the target precompile's method call in an EVM transaction with gas just sufficient for the small, linear `RequiredGas` charge.
4. Observe that `Precompile.Prepare` calls `method.Inputs.Unpack` and performs the full (disproportionately large) allocation/copy, unlike the protected `DynamicGasPrecompile` path which would reject the same shape before `Unpack` per `TestVoteWeightedAliasedOptionsRejectedBeforeUnpack`.

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
	decodeCost, ok := DecodeGasCost(method.Inputs, input)
	if !ok {
		// Calldata is structurally invalid (Unpack would reject it too); reject
		// now, without attempting the decode.
		return fmt.Errorf("invalid calldata encoding for %s", d.name)
	}
	// DecodeGasCost already includes scanCost; charge only the remaining
	// (string-copy) portion so the decode is priced exactly once.
	ctx.GasMeter().ConsumeGas(decodeCost-scanCost, fmt.Sprintf("%s precompile calldata decode", d.name))
	return nil
}

// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
func DecodeGasCost(args abi.Arguments, input []byte) (uint64, bool) {
	base := DefaultGasCost(input, false)
	if len(input) < 4 {
		return base, true
	}
	strBytes, ok := decodeStringCopyBytes(args, input[4:])
	if !ok {
		return 0, false
	}
	return satAdd(base, satMul(storetypes.KVGasConfig().ReadCostPerByte, strBytes)), true
}
