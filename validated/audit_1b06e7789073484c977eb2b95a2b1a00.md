### Title
Hardcoded Zero Slippage in `WombatBribeManager._swapFeesForBnb` Allows Theft of Bribe/Fee Value via Sandwich Attack - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager._swapFeesForBnb()` swaps collected bribe reward tokens into BNB by calling `IBNBZapper(PancakeZapper).zapInToken(rewardTokens[i][j], feeAmounts[i][j], 0, msg.sender)` with the `minRec` parameter hardcoded to `0`, giving no slippage protection. [1](#0-0)  This path is reachable by any unprivileged wallet via `castVotesAndClaimBribes`, which calls `castVotes(swapForBnb)` (an externally callable, non-owner-gated function) before claiming bribes. [2](#0-1) 

### Finding Description
`_swapFeesForBnb` iterates over collected reward tokens and swaps each nonzero amount through `PancakeZapper.zapInToken`, always passing `0` as the minimum amount to receive:
```solidity
bnbAmount += IBNBZapper(PancakeZapper).zapInToken(
    rewardTokens[i][j],
    feeAmounts[i][j],
    0,
    msg.sender
);
``` [3](#0-2) 

`zapInToken` in turn performs a real on-chain PancakeSwap-router swap (`swapExactTokensForETH`) using this attacker-influenceable-zero `minRec` value with no protection against price manipulation. [4](#0-3) 

This is functionally identical to the reported bug class in `PositionManager._swapToVolt()`: a swap function with `amountOutMin` hardcoded to `0`, invoked from a permissionless entry point, letting anyone trigger the swap and sandwich it to steal the swapped value. Here, the permissionless entry point is `castVotesAndClaimBribes` (external, unprivileged, callable by any wallet), which calls `castVotes(swapForBnb)`, the code path that (per the harvesting logic) triggers fee collection and subsequent `_swapFeesForBnb` conversion, sending the resulting BNB to `msg.sender` as the caller's incentive/fee for triggering the vote-cast-and-harvest. [2](#0-1) 

### Impact Explanation
Any ordinary wallet can call `castVotesAndClaimBribes`, forcing `_swapFeesForBnb` to swap accrued bribe/fee reward tokens into BNB with zero slippage protection. An attacker can sandwich this swap (front-run to move the pool price, let the zero-min-out swap execute at a manipulated rate, then back-run to restore price), extracting value that should have accrued to the protocol/bribe fee recipients. This is a direct theft of unclaimed yield/fee value belonging to the protocol, satisfying the "theft or permanent freezing of unclaimed yield" impact bar.

### Likelihood Explanation
High. The only requirement is calling a public, unprivileged function (`castVotesAndClaimBribes`) that any wallet can invoke, and sandwiching the resulting Pancake swap in the same block — a fully permissionless, always-available attack vector requiring no special access or timing beyond normal MEV capability.

### Recommendation
Add a caller-specified (and validated) minimum-output parameter through `castVotes`/`_swapFeesForBnb`/`zapInToken`, or restrict the fee-swap execution to a trusted/private-relay path, so that `minRec` is never hardcoded to `0` in a permissionlessly triggerable swap.

### Proof of Concept
1. Attacker monitors the mempool for `castVotesAndClaimBribes(lps, true)` calls (or calls it themselves).
2. Attacker front-runs with a large swap on the relevant PancakeSwap pair to skew the price against the token being converted to BNB.
3. `castVotes` executes, internally triggering `_swapFeesForBnb`, which calls `zapInToken(token, feeAmount, 0, caller)` — the swap executes at the manipulated (unfavorable) rate since `minRec = 0`.
4. Attacker back-runs to restore the price, pocketing the difference extracted from the bribe/fee tokens that should have gone to `msg.sender`/the protocol at fair value.

    function _swapFeesForBnb(address[][] memory rewardTokens, uint256[][] memory feeAmounts)
        internal
        returns (uint256 bnbAmount)
    {
        if(PancakeZapper == address(0)) revert PancakeZapperNotSet();
        uint256 bribeLength = rewardTokens.length;
        for (uint256 i; i < bribeLength; i++) {
            uint256 rewardLength = rewardTokens[i].length;
            for (uint256 j; j < rewardLength; j++) {
                if (rewardTokens[i][j] != address(0) && feeAmounts[i][j] > 0) {
                    _approveTokenIfNeeded(rewardTokens[i][j], PancakeZapper, feeAmounts[i][j]);
                    bnbAmount += IBNBZapper(PancakeZapper).zapInToken(
                        rewardTokens[i][j],
                        feeAmounts[i][j],
                        0,
                        msg.sender
                    );
                }
            }
        }
    }
