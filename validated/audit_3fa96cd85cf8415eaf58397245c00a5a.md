### Title
DataLayer HTTP Server Follows Symlinks Planted Under `server_files_location`, Enabling Arbitrary File Disclosure - ([File: chia/data_layer/data_layer_server.py])

### Summary
`DataLayerServer.file_handler` / `folder_handler` open `.dat` files under the configured `server_files_location` directory purely by joining a filename-format-validated string to `server_dir`, without ever checking that the resolved path is a regular file (not a symlink) or that it stays within the intended directory. A local low-privileged process that can write into that directory can pre-plant a symbolic link using a syntactically valid DataLayer filename, pointing at an arbitrary file elsewhere on disk. Because the DataLayer HTTP server binds to `0.0.0.0` by default, any network caller who requests that filename receives the contents of the symlink target — a direct analog of the reported RustDesk "Transfer File" symlink-following disclosure, where uploading a symlink lets an attacker read arbitrary files.

### Finding Description
`is_filename_valid()` only checks that the filename string round-trips through `get_delta_filename`/`get_full_tree_filename` (store_id/node_hash/type/generation/version) — it never inspects the actual filesystem object: [1](#0-0) 

`DataLayerServer.file_handler` and `folder_handler` then do a bare `open(file_path, "rb")` on the joined path once the name passes that string check: [2](#0-1) 

The legitimate writer path in `write_files_for_root()` uses exclusive creation (`"xb"`) by default, so it will raise `FileExistsError` (silently swallowed) if a file — or a symlink — already occupies the target path; it never overwrites it: [3](#0-2) 

Similarly, `DataLayer`'s fallback full-tree write only fires `if not os.path.exists(filename_full_tree)`, and `os.path.exists()` follows symlinks, so a pre-planted symlink (even a dangling one resolving to an unrelated but real file) is treated as "already written" and the loop moves on without validating what that path actually points to: [4](#0-3) 

Because filenames are fully deterministic (`store_id-node_hash-full/delta-generation-v1.0.dat`), an attacker who can write to `server_files_location` (a normal, non-privileged-owned directory under the Chia root, default `data_layer/db/server_files_location_CHALLENGE`) can predict or brute force a filename that will later be requested, and substitute a symlink to any file readable by the DataLayer service (wallet DB, keyring, other users' files if permissions allow, etc.). Any subsequent GET to the DataLayer HTTP server for that filename returns the target file's contents verbatim, since neither `file_handler`/`folder_handler` nor the write paths reject symlinks or canonicalize/verify the resolved path stays inside `server_dir`.

### Impact Explanation
Successful exploitation discloses the contents of an arbitrary file readable by the DataLayer service process to any client able to reach the DataLayer HTTP server (which defaults to listening on `0.0.0.0:8575`), without requiring any authentication on that static-file endpoint. This is a confidentiality-only issue (matches the reported CVSS vector C:H/I:N/A:N) but can leak highly sensitive local data (wallet database, keyring material, other config) once a local process plants the symlink.

### Likelihood Explanation
Requires local low-privileged write access to the DataLayer `server_files_location` directory to plant the symlink beforehand — the same precondition as the RustDesk analog ("An attacker must first obtain the ability to execute low-privileged code on the target system"). Given typical single-user Chia installs, or any co-located process/service sharing that data directory, this is readily achievable, and no race condition with the writer is needed because the exclusive-create write path silently no-ops when the path already exists.

### Recommendation
- In `DataLayerServer.file_handler`/`folder_handler`, before opening, verify the resolved path with `os.path.realpath()`/`Path.resolve()` stays within `server_dir` and reject if `Path.is_symlink()` is true.
- In `write_files_for_root()` and the `DataLayer.fetch_and_validate()` fallback writer, use `os.path.lexists()`-aware checks and explicitly reject/replace symlinks found at the target path rather than treating their mere presence as "already written."
- Consider opening target files with `O_NOFOLLOW` (or equivalent) when serving/writing DataLayer static files.

### Proof of Concept
1. On a host running the DataLayer service (default `server_files_location` under `<chia_root>/data_layer/db/server_files_location_<network>/`), as a local low-privileged user with write access to that directory, create a symlink named with a valid DataLayer filename pointing at a sensitive file, e.g.:
   `ln -s /home/victim/.chia/mainnet/keyring.yaml <store_id>-<node_hash>-full-<generation>-v1.0.dat`
   choosing `store_id`, `node_hash`, and `generation` values that will plausibly be requested (e.g., a store the victim owns/subscribes to, at a near-future generation).
2. Wait for (or trigger) the victim's DataLayer node to reach that generation/root for the store; `os.path.exists()` in `DataLayer.fetch_and_validate` (or the `"xb"` exclusive open in `write_files_for_root`) sees the path as already present and does not overwrite the symlink.
3. Send `GET http://<victim_host>:8575/<store_id>-<node_hash>-full-<generation>-v1.0.dat` to the DataLayer HTTP server.
4. The response body contains the full contents of `/home/victim/.chia/mainnet/keyring.yaml` (or whatever file the symlink targets), disclosed via `DataLayerServer.file_handler`'s unchecked `open(file_path, "rb")`.

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

```python
    async def file_handler(self, request: web.Request) -> web.Response:
        filename = request.match_info["filename"]
        if not is_filename_valid(filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response

    async def folder_handler(self, request: web.Request) -> web.Response:
        tree_id = request.match_info["tree_id"]
        filename = request.match_info["filename"]
        if not is_filename_valid(tree_id + "-" + filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(tree_id).joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response
```
