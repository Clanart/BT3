## Finding [1](#0-0) 

### Title
IntentGatewayV2.placeOrder() credits orders from the shared CallDispatcher's ambient balance instead of the caller's actual contribution, letting any user claim stray/leftover token balances as free escrow - (File: evm/src/apps/IntentGatewayV2.sol)

### Summary
`placeOrder()`'s predispatch flow sweeps *the entire current token balance* of the shared `CallDispatcher` contract into the gateway and credits it to the calling order, rather than only crediting the amount that this specific call's predispatch actually produced. Because `CallDispatcher` is a single, globally shared, access-control-free contract (`_params.dispatcher`), any balance it happens to be holding — from a prior user's incompletely-consumed predispatch swap, a stray direct ERC-20 transfer, or any other source — is fair game for whoever next declares that token as an order input, with essentially no real contribution required from them.

### Finding Description
In `placeOrder()`, when `order.predispatch.call.length > 0`, the flow is:
1. Transfer `order.predispatch.assets` to the shared `dispatcher` [2](#0-1) .
2. Execute the caller-supplied, arbitrary `order.predispatch.call` via `ICallDispatcher(dispatcher).dispatch(...)` [3](#0-2) .
3. Build sweep calls that pull **the dispatcher's entire current balance** of each `order.inputs[i].token` — not the amount attributable to step 1/2 — back to the gateway: `uint256 balance = IERC20(token).balanceOf(dispatcher); ... transferCalls[i] = Call({..., data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)});` [4](#0-3) .
4. `received = balanceOf(this) - balancesBefore[i]` is computed and credited to `order.inputs[i].amount` (capped at the declared amount; only the *excess* becomes protocol dust) [5](#0-4) .

There is no check that the swept balance was actually produced by *this caller's* predispatch step — only that `balance >= requiredAmount` [6](#0-5) . `CallDispatcher` itself is a bare pass-through with a public unguarded `receive()` and `dispatch()` [7](#0-6) , and it is a single shared instance referenced by every order via `_params.dispatcher` [8](#0-7) . Any token X left sitting in that shared contract — e.g. because a previous predispatch swap didn't fully convert its input asset into an `order.inputs` token, or because tokens were sent to the well-known dispatcher address by mistake or by an attacker priming a separate transaction — is not tied to any specific order or owner. A subsequent caller can:
- Satisfy the `order.predispatch.call.length > 0 && order.predispatch.assets.length > 0` gate with a trivial/negligible predispatch asset and a no-op `predispatch.call`.
- Declare `order.inputs[i].token = X`, `amount = <whatever balance is already sitting in dispatcher>`.
- Let the sweep code pull that ambient balance into escrow, crediting it entirely to their own order, at effectively zero real cost.

This is structurally identical to the Arrakis H-3 root cause: an arbitrary, caller-controlled intermediate call followed by a balance-snapshot-based accounting step that blindly trusts the post-call balance of a shared contract, rather than validating that the balance change is attributable to the caller's own contribution.

### Impact Explanation
Once escrowed, the attacker can immediately call `cancelOrder()` on a same-chain order to redeem the full escrowed `_orders[commitment][token]` amount back to themselves via `_withdraw` [9](#0-8) , or simply let a solver fill the order and take the solver's output while paying with tokens they never actually contributed. This is direct, unauthorized extraction of value that was never theirs — either other users' stranded predispatch remainders or protocol dust that should have been swept to treasury — satisfying the "stealing or loss of funds" / "unauthorized transaction or execution" impact categories.

### Likelihood Explanation
The entrypoint (`placeOrder`, followed by `cancelOrder`) is fully public and requires no privileged role, relayer, prover, or governance action — only an unprivileged EVM account. The only precondition is that the shared `CallDispatcher` holds a nonzero balance of some token not yet swept out, which is a realistic byproduct of predispatch swaps that don't perfectly consume 100% of their input, or of any direct transfer to the dispatcher's known address (it has no restriction on depositor and a public `receive()`).

### Recommendation
Track the dispatcher's balance-before/after strictly scoped to the current call (e.g., compare against a balance snapshot taken immediately before this order's predispatch transfer, not an unscoped `balanceOf(dispatcher)`), or have `CallDispatcher` sweep any residual balance back to a protocol-controlled address at the end of every `dispatch()` invocation so no token balance ever persists in it between transactions. Additionally, require that `order.predispatch.call`'s resulting balance be reconciled per-order (e.g., via a per-order sub-account or pull-based accounting) rather than trusting the dispatcher's ambient `balanceOf`.

### Proof of Concept
1. User A places an order with `predispatch.assets = [WETH: 1e18]` and `predispatch.call` that performs a swap which, due to slippage/rounding or a deliberately crafted no-op target, leaves `0.05 WETH` unconverted and un-swept in the shared `CallDispatcher` (since the sweep loop only pulls balances for tokens in `order.inputs`, not the original predispatch asset if it differs).
2. Attacker B observes the `0.05 WETH` sitting at the known `CallDispatcher` address (`_params.dispatcher`, readable via `params()` [10](#0-9) ).
3. Attacker B calls `placeOrder` with a trivial `predispatch.assets` entry (e.g., `1 wei` of any cheap token) and a no-op `predispatch.call`, and declares `order.inputs = [{token: WETH, amount: 0.05e18}]`.
4. The sweep logic checks `balanceOf(dispatcher) >= 0.05e18` (true, from User A's leftover), transfers the full `0.05 WETH` to the gateway, and credits it to Attacker B's order as `received` [11](#0-10) .
5. Attacker B immediately calls `cancelOrder` (same-chain), receiving the `0.05 WETH` refund to themselves [9](#0-8) , having contributed no real WETH.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
