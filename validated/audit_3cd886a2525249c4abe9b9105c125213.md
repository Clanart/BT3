### Title
Permissionless `associatePubKey`/`associate` precompile lets anyone force-remap a victim's mutable direct-cast Sei identity to their true address using only a public public key, orphaning state accumulated under the cast address - (File: precompiles/addr/addr.go)

### Summary
The Capgo bug is a case where a mutable, attacker-controlled identity field (`public.users.email`) is trusted by a privileged merge/provisioning routine to bind a victim's real identity into an attacker-chosen account. Sei-chain has a structurally identical pattern: every EVM address has an implicit, *mutable* "direct-cast" Sei identity (`sdk.AccAddress(evmAddr[:])`) that is used by default until an explicit, permissionless "association" call rebinds it to the pubkey-derived "true" Sei address. That rebind — `AssociateAddresses` — is reachable by **any address, at any time, for any target's public key**, with no consent from, or transaction by, the owner of the target account.

### Finding Description
Every EVM address defaults to a direct-cast Sei address via `GetSeiAddressOrDefault`/`GetEVMAddressOrDefault` [1](#0-0) . This cast address is a normal, usable Cosmos account: third parties can send it funds, delegate stake to it, etc., before its owner ever submits a transaction or explicitly associates.

The `addr` precompile's `associatePublicKey`/`associate` methods derive `evmAddr`/`seiAddr`/`pubkey` purely from a **caller-supplied public key** (compressed pubkey bytes or an ECDSA signature over an arbitrary message) — not from `msg.sender` — and then unconditionally call `AssociateAddresses` for that derived target: [2](#0-1) 

The only guard is that the *target seiAddr* must not already be associated: [3](#0-2) . Because ECDSA public keys are public data (recoverable from any signed transaction the victim has ever broadcast, or directly known if the victim shared it), **any user** can force-associate **any other unassociated EVM user's** identity at a time of the attacker's choosing.

`AssociateAddresses`/`MigrateBalance` only moves bank-module `SpendableCoins`/wei from the cast address to the true address and then deletes the cast `BaseAccount` if `LockedCoins` is zero [4](#0-3) . It does **not** touch staking delegations, distribution reward records, or other module state that may have been created against the cast address's raw bytes (e.g., a third party delegating tokens to, or a validator self-delegating from, that cast address before the owner ever associated).

This is exactly the failure mode the codebase's own comments describe as dangerous — but the code only defends against it for one specific vector (EIP-7702 `SetCode` authorities), via `associateAuthorizationAuthorities`/`AuthorityToPreAssociate`, which pre-associates *those* authorities before `SetCode` can install delegation code that would otherwise get remapped later: [5](#0-4) . The accompanying comment states the precise risk: "SetCode creates a mutable direct-cast EVM->Sei mapping that a later associatePubKey call can remap, orphaning any staking/distribution state created under the direct-cast identity (which can then halt the chain via the distribution validator-removal hook)" [6](#0-5) .

This fix is scoped only to `SetCode` authorities inside a single transaction's authorization list. It does nothing to protect an **ordinary EVM user's dormant EOA cast address** that has accumulated staking/distribution state (via direct delegation to, or reward accrual under, its raw byte address by any third party) before that user submits their first EVM transaction. The permissionless `associatePubKey` precompile can be called by an attacker at any time to trigger exactly the same "mutable direct-cast identity remap" the code warns about, for any victim whose public key the attacker has observed.

### Impact Explanation
If the direct-cast address of a validator operator or delegator accumulates staking/distribution state before that address performs its first EVM-side association, an attacker can call `associatePubKey` (fully permissionless, requiring only the victim's already-public ECDSA public key) to force an association event. Per the codebase's own documented failure mode, this class of remap "can halt the chain via the distribution validator-removal hook," i.e., cause a validator halt / chain split condition through orphaned distribution/staking references tied to an account whose `BaseAccount` entry is deleted mid-remap. This satisfies the "validator halt" / "permanent chain split" impact bar from the validation rules.

### Likelihood Explanation
Likelihood is moderate-to-high in terms of reachability: the precompile is public, requires only a valid secp256k1 public key (not a private key or victim cooperation), and the target's public key is generally recoverable from any prior signed transaction. Exploitation additionally requires that a cast address has accumulated staking/distribution state prior to association, a state that legitimately occurs in the wild since delegations/deposits can be sent to any account address without requiring that account to have ever signed anything.

### Recommendation
Extend the same protection built for `SetCode` authorities to the general `associatePubKey`/`associate` precompile path: before allowing an unrelated caller to force-associate a target seiAddr/evmAddr pair, check for existing staking delegations, distribution state, or other module references against the cast address and either migrate them atomically along with the balance migration in `AssociateAddresses`/`MigrateBalance`, or reject/queue the association until such state is empty. Alternatively, restrict `associatePubKey`/`associate` so it can only be invoked by (or on behalf of, with an authenticated proof of intent from) the actual key holder, removing the "anyone with a public public key can force-associate anyone else" primitive entirely.

### Proof of Concept
1. Victim uses their EVM address's direct-cast Sei address (`sdk.AccAddress(evmAddr[:])`) to receive a third-party stake delegation or accrue distribution rewards via normal Cosmos-SDK module calls, without ever submitting an EVM transaction or explicit association.
2. Attacker observes the victim's public key from any external source (any previously broadcast Ethereum-style signature reveals the recoverable public key) and calls the `addr` precompile's `associatePubKey(pubKeyHex)` from any account — no permission from the victim required: [7](#0-6) .
3. `associateAddresses` passes the "seiAddr not yet associated" check and calls `AssociateAddresses`, migrating only bank balances/wei and deleting the cast `BaseAccount` if `LockedCoins` is zero, while leaving staking/distribution references pointed at the now-deleted cast address bytes: [8](#0-7) .
4. Downstream distribution/staking hooks referencing the orphaned cast-address delegator can hit the exact validator-removal-hook halt condition the codebase's comments describe for the (already patched) `SetCode` case, but which remains open for this generic, permissionless precompile path.

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// associateAuthorizationAuthorities associates every EIP-7702 authorization authority in
// the transaction with its true (pubkey-derived) Sei address, so that a subsequent
// SetCode for the authority does not create a mutable direct-cast mapping. It is
// best-effort: authorities with invalid signatures (which EVM execution would also skip)
// or that are already associated are left untouched, and an association failure skips
// only that authority rather than rejecting the transaction, which go-ethereum would
// still accept.
func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
