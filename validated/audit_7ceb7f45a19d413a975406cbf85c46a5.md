### Title
`fetch_and_validate()` treats a legitimately non-empty generation-0 DataLayer root as "no data on chain," causing mirror/subscription clients to silently skip real committed data - (File: `chia/data_layer/data_layer.py`)

### Summary
This is the same bug class as the Sherlock M-7 finding: a numeric field whose valid domain includes `0` is used as a sentinel for "not set." In `Factory.sol`, `templateVersion == 0` collided with the "no implementation registered yet" check on `latestImplementation[templateName]`. In `chia/data_layer/data_layer.py`, `DataLayer.fetch_and_validate()` treats `singleton_record.generation == uint32(0)` as "no data on chain" and returns early [1](#0-0) , but generation `0` is exactly the generation produced for the very first singleton root pushed at store creation, and that first root can be genuinely non-empty data (e.g. `generate_new_reporter(initial_root, ...)` records `generation=uint32(0)` for whatever `initial_root` the caller supplies) [2](#0-1) .

### Finding Description
`DataLayerWallet.generate_new_reporter()` creates the initial DataLayer singleton with an arbitrary caller-supplied `initial_root` and always records it with `generation=uint32(0)` [3](#0-2) . Tests demonstrate that this initial root is not required to be empty — `test_dl_offers` and `test_initial_creation` construct the launcher with a real, non-empty Merkle root as the very first (generation 0) singleton state [4](#0-3) .

`DataLayer.fetch_and_validate()`, which drives the subscription/mirror sync path, uses `generation == uint32(0)` as a sentinel meaning "nothing has been published for this store yet" and returns without doing any fetch/validate work:
```
if singleton_record.generation == uint32(0):
    self.log.info(f"Fetch data: No data on chain for {store_id}.")
    return
``` [1](#0-0) 

Because generation `0` is a normal, reachable value that can carry real committed data (the store's first root), this check conflates "generation counter starts at 0" with "no data has been published." Any subscribed/mirrored store whose current on-chain tip is still at generation 0 (i.e., the owner has never pushed a second update) is treated by every syncing client as if it had no data, so `fetch_and_validate()` exits before running `_update_confirmation_status()`, before downloading/validating delta or full files, and before making that data locally available [5](#0-4) . This mirrors the Solidity bug precisely: a zero-valued but valid state is misclassified as "unset," causing downstream logic (subscriber node in Chia; `_templateNames`/`latestImplementation` bookkeeping in the audit) to behave as though setup never happened.

### Impact Explanation
Subscribing DataLayer nodes and any Data Layer client relying on the periodic `update_subscription()`/`fetch_and_validate()` sync loop will fail to fetch, verify, or serve the store's actual first-generation data whenever the origin store is at generation 0 with real content — a state reachable by any wallet user who creates a store with an initial non-empty root and never updates it again. Downstream consumers (proof verification against a mirror's local files, offer construction requiring another party's proof data, static file serving) will observe "no data" for a store that legitimately has committed key/value content, producing incorrect availability/proof results for that store's consumers. This is a correctness/availability bug in coin-set/state divergence between what the chain actually holds (a real root at generation 0) and what syncing nodes believe is available, but it does not directly enable unauthorized fund movement, so it should be scoped as a Data-Layer correctness/availability issue rather than a fund-theft vulnerability.

### Likelihood Explanation
High likelihood of occurrence in normal usage: any store creator can call `create_new_dl`/`generate_new_reporter` with a non-empty `initial_root` and simply never submit a second update — a very plausible, unprivileged, single-transaction workflow (no attacker collusion, no special permissions needed). Every other node that subscribes to or mirrors that store's launcher id will hit this code path on every sync cycle via `periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()` [1](#0-0) .

### Recommendation
Do not use `generation == 0` as a proxy for "no data published." Instead check the actual anchored root, e.g. compare `singleton_record.root` (or the corresponding `bytes32.zeros`/`DataLayer.none_bytes` empty-root sentinel) rather than the generation counter, so a legitimately non-empty root at generation 0 is fetched and validated like any other generation. This matches the audited fix pattern of not conflating a valid zero value with "not set" (in Sherlock M-7, changing `>` to `>=` against the version counter; here, checking the root value instead of the generation counter).

### Proof of Concept
1. Wallet A calls `create_new_dl`/`generate_new_reporter` with `initial_root = real_merkle_root` (non-empty, as done in `test_dl_offers`) [6](#0-5) . The resulting `SingletonRecord` is confirmed on-chain with `generation=uint32(0)` and `root=real_merkle_root`.
2. Wallet A never submits a second root update (store remains at generation 0 permanently).
3. Node B subscribes to A's store id and its DataLayer service periodically calls `fetch_and_validate(store_id)`.
4. Inside `fetch_and_validate`, `singleton_record.generation == uint32(0)` is true, so the function logs "No data on chain" and returns immediately, without ever attempting to build the local tree, download files, or validate against `real_merkle_root` [1](#0-0) .
5. Node B's local `DataStore` never gets a tree for `store_id`, so any proof request, offer involving that store, or file serving on Node B for that data will fail/behave as if the store is empty — despite the store having real, on-chain-confirmed data since its creation.

    async def fetch_and_validate(self, store_id: bytes32) -> None:
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.info(f"Fetch data: No singleton record for {store_id}.")
            return
        if singleton_record.generation == uint32(0):
            self.log.info(f"Fetch data: No data on chain for {store_id}.")
            return

        await self._update_confirmation_status(store_id=store_id)

        root = None
        if await self.data_store.store_id_exists(store_id=store_id):
            root = await self.data_store.get_tree_root(store_id=store_id)

        if root is None:
            await self.data_store.reset_store_to_empty_root(store_id)
        elif (
            root.node_hash is not None
            and root.generation <= singleton_record.generation
            and not self.data_store.merkle_blob_available(store_id, root.node_hash)
        ):
            if self.data_store.merkle_blobs_path.is_dir():
                self.log.warning(
                    f"Detected committed root with missing blob for {store_id} at generation "
                    f"{root.generation}; resetting and resyncing."
                )
                await self.data_store.reset_store_to_empty_root(store_id)
            else:
                self.log.warning(
                    f"Merkle blobs path {self.data_store.merkle_blobs_path} is missing; skipping "
                    f"self-heal for {store_id} - check the storage volume."
                )

    async def generate_new_reporter(
        self,
        initial_root: bytes32,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> bytes32:
        """
        Creates the initial singleton, which includes spending an origin coin, the launcher, and creating a singleton
        """

        coins: set[Coin] = await self.standard_wallet.select_coins(uint64(fee + 1), action_scope)
        if coins is None:
            raise ValueError("Not enough coins to create new data layer singleton")

        launcher_parent: Coin = next(iter(coins))
        launcher_coin: Coin = Coin(launcher_parent.name(), SINGLETON_LAUNCHER_PUZZLE_HASH, uint64(1))

        inner_puzzle: Program = await action_scope.get_puzzle(self.wallet_state_manager)
        full_puzzle: Program = create_host_fullpuz(inner_puzzle, initial_root, launcher_coin.name())

        genesis_launcher_solution: Program = Program.to(
            [full_puzzle.get_tree_hash(), 1, [initial_root, inner_puzzle.get_tree_hash()]]
        )
        announcement_message: bytes32 = genesis_launcher_solution.get_tree_hash()
        announcement = AssertCoinAnnouncement(asserted_id=launcher_coin.name(), asserted_msg=announcement_message)

        await self.standard_wallet.generate_signed_transaction(
            amounts=[uint64(1)],
            puzzle_hashes=[SINGLETON_LAUNCHER_PUZZLE_HASH],
            action_scope=action_scope,
            fee=fee,
            origin_id=launcher_parent.name(),
            coins=coins,
            extra_conditions=(*extra_conditions, announcement),
        )

        launcher_cs: CoinSpend = make_spend(
            launcher_coin,
            SINGLETON_LAUNCHER_PUZZLE,
            genesis_launcher_solution,
        )
        launcher_sb = WalletSpendBundle([launcher_cs], G2Element())
        launcher_id = launcher_coin.name()

        async with action_scope.use() as interface:
            interface.side_effects.extra_spends.append(launcher_sb)
            interface.side_effects.singleton_records.append(
                SingletonRecord(
                    coin_id=Coin(launcher_id, full_puzzle.get_tree_hash(), uint64(1)).name(),
                    launcher_id=launcher_id,
                    root=initial_root,
                    inner_puzzle_hash=inner_puzzle.get_tree_hash(),
                    confirmed=False,
                    confirmed_at_height=uint32(0),
                    timestamp=uint64(0),
                    lineage_proof=LineageProof(
                        launcher_id,
                        create_host_layer_puzzle(inner_puzzle, initial_root).get_tree_hash(),
                        uint64(1),
                    ),
                    generation=uint32(0),
                )
            )
