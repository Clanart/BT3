### Title
Reward-sandwiching in WombatStaking/BaseRewardPool: attacker can deposit large LP amount before `harvest()`, capture a disproportionate share of newly queued rewards, and immediately withdraw - (File: wombat/WombatStaking.sol, rewards/BaseRewardPoolV2.sol)

### Summary
`WombatStaking.harvest()` is a public, permissionless function that pulls accrued WOM rewards from the underlying Wombat `masterWombat` contract and queues them into the pool's `BaseRewardPool` proportionally to the **current** total staked amount, with no time-weighting or lock-up. An unprivileged wallet can deposit a very large LP position immediately before calling `harvest()`, capture a large share of rewards that accrued over time (belonging to long-term stakers), then immediately withdraw, repeating the process to continuously siphon yield away from genuine long-term liquidity providers.

### Finding Description
`WombatStaking.deposit()` / `depositLP()` mint receipt tokens 1:1 for LP deposited and stake them into `MasterMagpie` via the pool helper's `depositFor`, while `withdraw()` reverses this and burns the receipt token. [1](#0-0) [2](#0-1) 

The public `harvest()` function is callable by anyone with no restriction beyond the pool being active, and triggers `_toMasterWomAndSendReward`, which harvests from the underlying Wombat masterchef and queues the harvested WOM into the `BaseRewardPool`/`BaseRewardPoolV2`: [3](#0-2) 

`queueNewRewards`/`_provisionReward` distributes the newly harvested amount by dividing it by `totalStaked()` **at the moment of the call**, i.e., the current staked balance in MasterMagpie for that staking token, without regard to how long each staker has held their position: [4](#0-3) [5](#0-4) 

Because `MasterMagpie.depositFor`/`withdrawFor` allow instant deposit and withdrawal (subject only to `nonReentrant`, no cooldown or lock-up), and because rewards harvested from the underlying Wombat pool reflect WOM emissions accrued continuously over time (independent of when a given staker joined), a large last-second deposit immediately before `harvest()` is called captures a share of rewards proportional to the attacker's inflated stake, at the expense of the genuine long-term stakers whose share of `totalStaked()` is diluted at exactly the moment the reward is queued: [6](#0-5) 

The attacker then withdraws immediately afterward via `WombatPoolHelper.withdraw`, which calls `_unstake` (triggering `getReward`/`_harvestBaseRewarder` before removing the stake), collecting their inflated share of the reward, and burns the receipt token to exit the position: [7](#0-6) 

This mirrors the referenced `liquidity_lockbox` bug class: deposit a large position, trigger reward distribution, and withdraw immediately to disproportionately capture rewards, repeatable at will.

### Impact Explanation
Every call to `harvest()` (permissionless, callable by anyone at any time) distributes accumulated WOM yield based on instantaneous stake share rather than time-weighted contribution. A user can flash a large deposit right before triggering `harvest()`, receive an outsized share of the queued reward, and withdraw in the same or next transaction, directly stealing yield that should have accrued to long-term LPs. This is a direct theft of unclaimed yield from other stakers and can be repeated indefinitely, and is economically similar to a sandwich attack around reward-queuing events without needing any privileged role.

### Likelihood Explanation
`harvest()` requires no permission (only `whenNotPaused` and pool-active checks), and deposit/withdraw functions in `WombatStaking`/`MasterMagpie` have no minimum holding period, cooldown, or anti-flash-loan protection. An attacker only needs enough capital (or a flashloan of the deposit token/LP) to temporarily dominate `totalStaked()` for the target pool at the moment of harvesting, which is realistic for pools with modest TVL. This makes the attack straightforwardly executable by any unprivileged wallet.

### Recommendation
- Introduce a minimum holding period (or reward-vesting/streaming mechanism) before newly staked balances become eligible for reward accrual/queuing, similar to a time-weighted average balance.
- Alternatively, snapshot `totalStaked()` and per-user balances prior to the block in which `harvest()` executes, or stream queued rewards linearly over time rather than crediting them instantly against the current stake snapshot.
- Consider restricting or rate-limiting who/how often `harvest()` can be triggered, or require deposits to be locked for a minimum duration before they count toward reward-sharing eligibility.

### Proof of Concept
1. Attacker observes that a WombatStaking pool has accumulated a large pending WOM reward in `masterWombat` (has not been harvested in a while) while `totalStaked()` for that pool in `MasterMagpie` is currently small.
2. Attacker acquires a large amount of the pool's LP/deposit token (via flashloan or capital) and calls `WombatPoolHelper.deposit()`/`depositLP()`, which mints receipt tokens and stakes them via `MasterMagpie.depositFor`, dramatically inflating `totalStaked()` for that staking token. [8](#0-7) 
3. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)`, which pulls the accumulated WOM and queues it into `BaseRewardPool` proportional to the now-inflated `totalStaked()`, crediting the attacker's newly-added stake a large `rewardPerToken` share. [3](#0-2) 
4. Attacker immediately calls `WombatPoolHelper.withdraw()`, which unstakes from `MasterMagpie` (harvesting/claiming the disproportionate reward share) and burns the receipt token, exiting the position and repaying any flashloan. [7](#0-6) 
5. This sequence can be repeated every time a harvestable reward accumulates, continuously extracting yield that should accrue to genuine long-term stakers.

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }
