## Finding [1](#0-0) 

### Title
Line-selection column mismatch when toggling a modified row's checkbox may silently include/exclude the wrong diff line - (File: app/src/ui/diff/side-by-side-diff.tsx)

### Summary
`SideBySideDiff.onLineNumberCheckedChanged` is the handler that translates a user's checkbox click in the diff gutter into a change to the `DiffSelection` object that later drives `formatPatch()` / `formatPatchToDiscardChanges()` when building the partial-commit patch that is actually staged and committed.

### Finding Description
`onLineNumberCheckedChanged` receives the `row` and the `column` (`DiffColumn.Before` or `DiffColumn.After`) that the user actually clicked, then computes two line numbers to update:

```ts
const lineBefore = this.getDiffLineNumber(row, column)
const lineAfter = this.getDiffLineNumber(row, column)
``` [2](#0-1) 

Both calls pass the same `column` argument instead of the expected `DiffColumn.Before` for `lineBefore` and `DiffColumn.After` for `lineAfter` (the naming of the local variables strongly implies that was the intent, and is consistent with how `getDiffLineNumber` is used elsewhere with an explicit `DiffColumn` value, e.g. in `onStartSelection`) [3](#0-2) . Whatever `getDiffLineNumber(row, column)` resolves to is then applied twice via `selection.withLineSelection(...)`, once under the guise of "before" and once under the guise of "after" [4](#0-3) .

The `absoluteIndex` used by `formatPatch`/`formatPatchToDiscardChanges` when deciding, per line, whether it belongs in the final patch is exactly this `DiffSelection` index space [5](#0-4) . Any mismatch between what the UI displays as selected and what index actually gets flipped in `DiffSelection` therefore translates directly into a patch that differs from what the checkbox states show the user.

### Impact Explanation
If this code path resolves an index that does not correspond to the intended before/after line of a `Modified` row (side-by-side rows that pack a deletion and an addition into one visual row — see the `DiffRowType.Modified` handling in `getModifiedRows`) [6](#0-5) , the user could toggle a checkbox believing they are including/excluding one specific line, while the actual `DiffSelection` bit that gets flipped corresponds to a different line index. Because `formatPatch` blindly trusts `file.selection.isSelected(absoluteIndex)` to build the commit patch, this can result in the user silently committing/pushing content they did not intend to include (or omitting content they intended to include), which matches the "silent corruption of what the user commits or pushes" impact class.

### Likelihood Explanation
This path only requires the user to interact with a normal side-by-side diff for a `Modified` row — no unusual permissions or local access needed. An attacker who controls the contents of a cloned/fetched repository could craft files that reliably produce many adjacent `Modified` rows (paired add/delete lines) to increase the chance that a user's partial-selection clicks land on a mismatched index, making the corruption easier to trigger against an unsuspecting reviewer doing partial commits. That said, I was not able to fully confirm the internal behavior of `getDiffLineNumber` (its definition wasn't reachable in the remaining tool budget) to prove the exact index divergence conclusively — this should be verified against the live method before treating it as a confirmed, exploitable bug rather than a suspicious/duplicated-argument code smell.

### Recommendation
In `onLineNumberCheckedChanged`, compute `lineBefore` and `lineAfter` from their respective, explicit columns:
```ts
const lineBefore = this.getDiffLineNumber(row, DiffColumn.Before)
const lineAfter = this.getDiffLineNumber(row, DiffColumn.After)
```
and add a regression test (similar to the existing `side-by-side-diff-row-test.tsx` checkbox tests) [7](#0-6)  that specifically exercises a `Modified` row to confirm that toggling the "before" checkbox never mutates the "after" line's selection state and vice versa.

### Proof of Concept
Not independently reproducible from the index alone — reproducing this requires exercising `getDiffLineNumber` at runtime for a `Modified` row and comparing the resulting `DiffSelection` bit against the actually-generated patch via `formatPatch`. I recommend a Devin session with full repo access to instrument `onLineNumberCheckedChanged`/`getDiffLineNumber` and confirm whether toggling one column's checkbox on a `Modified` row flips the selection bit for the wrong absolute diff-line index, then verify whether the resulting patch (from `formatPatch`) diverges from what the UI displays as selected.

  private onLineNumberCheckedChanged = (
    row: number,
    column: DiffColumn,
    isSelected: boolean
  ) => {
    if (this.props.onIncludeChanged === undefined) {
      return
    }

    let selection = this.getSelection()
    if (selection === undefined) {
      return
    }

    const lineBefore = this.getDiffLineNumber(row, column)
    const lineAfter = this.getDiffLineNumber(row, column)

    if (lineBefore !== null) {
      selection = selection.withLineSelection(lineBefore, isSelected)
    }

    if (lineAfter !== null) {
      selection = selection.withLineSelection(lineAfter, isSelected)
    }

    this.props.onIncludeChanged(selection)
  }
