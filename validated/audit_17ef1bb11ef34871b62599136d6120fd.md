### Title
`isGitHubHost` misclassifies attacker-controlled domains as GitHub Enterprise, causing automatic OAuth sign-in prompts to attacker hosts - ([File: app/src/lib/api.ts])

### Summary
`isGitHubHost()` in `app/src/lib/api.ts` uses a loose hostname regex to decide whether an unknown remote host should be trusted as a GitHub/GitHub Enterprise server. Because the regex only checks for the literal substring `github.` at the start of the hostname or after a dot, any attacker-registered domain such as `github.attacker.com` or `sub.github.attacker.com` is classified as a GitHub Enterprise host. This classification feeds directly into the Git credential-helper trampoline, which decides whether to show a simple generic username/password prompt or to kick off Desktop's full GitHub/Enterprise **OAuth sign-in flow** bound to that attacker-controlled endpoint.

### Finding Description
The vulnerable heuristic: [1](#0-0) 

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```

This matches any hostname where the label `github` is immediately followed by a dot, at the start of the string or after another dot — e.g. `github.attacker.com`, `evil.github.attacker.io`, `github.corp-phish.net`. None of these need to be owned or controlled by GitHub; an attacker can freely register such a domain.

This function is consumed by `getEndpointKind` in the trampoline credential helper, which classifies a credential request's host before deciding what UI flow to trigger: [2](#0-1) 

If the endpoint is classified `'enterprise'` (as opposed to `'generic'`), `getCredential` does **not** fall back to the simple generic-git-auth dialog. Instead, when no matching account exists yet, it calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then automatically starts Desktop's full Enterprise **sign-in / OAuth** flow bound to the attacker's `origin`, without the user ever having gone through "File > Options > Enterprise sign-in": [4](#0-3) 

The broken invariant mirrors the report's pattern: a single trust decision ("is this a legitimate GitHub host that deserves the full account/OAuth-binding UI treatment?") is derived from an untrusted, attacker-influenced input (the credential request's `host`, which originates from the remote URL of a cloned/fetched repository, e.g. via a submodule URL or `git remote`) without any cryptographic or authoritative verification. There is no fallback verification (e.g., certificate pinning, GitHub-issued response header check) gating this classification before it is trusted; the network probe (`fetch(...).headers.has('x-github-request-id')`) is only reached if the regex check *fails*, so the regex bypass skips that stronger check entirely.

### Impact Explanation
This falls under "unauthorized OAuth or account binding" in the given valid-impact list. A repository the user clones or fetches (or a submodule inside it) can point a remote/submodule URL at an attacker-registered domain crafted to satisfy the regex (e.g. `https://github.attacker-domain.com/...`). When Desktop's Git operations reach that remote and Git invokes the credential helper, Desktop will treat it as a GitHub Enterprise instance and silently launch its Enterprise sign-in/OAuth flow scoped to that attacker origin, rather than the simple, clearly-labeled generic credential dialog a non-GitHub host should get. This blurs the trust boundary between "generic remote" and "GitHub account," and can be used to make an OAuth/account-binding flow appear as routine Desktop behavior triggered merely by a git fetch, increasing the chance a user completes an account-binding/OAuth dance with an attacker-controlled "enterprise" endpoint believing it's a legitimate GitHub flow.

### Likelihood Explanation
Triggering the credential helper does not require any special user action beyond a normal clone/fetch/pull of an attacker-supplied repository or submodule URL — an action GitHub Desktop users perform constantly. Domain registration matching the regex (`github.<anything>.<tld>` or `<sub>.github.<anything>.<tld>`) is trivial and entirely within attacker control, requiring no compromise of GitHub infrastructure, no admin rights, and no pre-existing malware or leaked credentials. The only remaining variable is that the endpoint UI (`credentialHelperUrl`) does display the raw URL, so an attentive user could notice, which is why this is best framed as an account-binding/trust-boundary flaw rather than a certain full compromise — but the automatic triggering of the full sign-in flow (versus the intended simple prompt) is a concrete, reproducible defect in the classification logic itself, independent of user attentiveness.

### Recommendation
- Do not use substring/regex heuristics on hostnames to decide GitHub Enterprise trust. Require either an exact match against configured/known enterprise endpoints, or a successful cryptographically-anchored verification (the existing `x-github-request-id` HEAD-request probe) before ever classifying a host as `'enterprise'`.
- Move the network-based `isGitHubHost` check earlier and treat the regex-based heuristic strictly as a *hint* used to decide whether to bother probing, never as a substitute for the probe result itself.
- Ensure `getEndpointKind` never returns `'enterprise'` for a host that hasn't been independently confirmed to be GitHub-operated, and require that hosts failing confirmation fall back to `'generic'` (the safe default with a plain username/password prompt, no OAuth flow).

### Proof of Concept
1. Attacker registers `github.attacker.com` (or any domain matching `/(^|\.)(github)\./`) and stands up an arbitrary HTTPS server there (no need to mimic GitHub's API).
2. Attacker publishes a public repository whose `.gitmodules` (or a remote `origin`) references `https://github.attacker.com/foo/bar.git`.
3. Victim clones the outer repository in GitHub Desktop (`git clone --recursive`, per `app/src/lib/git/clone.ts`), or later runs a fetch/pull that touches the submodule.
4. Git invokes the credential helper for `https://github.attacker.com`. `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` finds no exact dotcom/GHE match, but `isGitHubHost('https://github.attacker.com')` returns `true` due to the regex in `app/src/lib/api.ts` matching `github.attacker.com`.
5. `getCredential` sees `endpointKind !== 'generic'` and no existing account for that endpoint, so it calls `ui.promptForGitHubSignIn('https://github.attacker.com/...')`, which calls `dispatcher.beginEnterpriseSignIn` and `setSignInEndpoint(origin)` — launching Desktop's OAuth/Enterprise sign-in UI bound to the attacker's origin, instead of the intended lightweight generic-credentials dialog.

**Note on limitation:** I was not able to execute this end-to-end in a live Desktop instance (no filesystem/browser access in this mode), so the chain is verified by static code tracing across `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`, and `app/src/lib/trampoline/trampoline-ui-helper.ts`, not by dynamic reproduction.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {

        resolve(result.kind === 'success' ? result.account : undefined)

        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,

      })
