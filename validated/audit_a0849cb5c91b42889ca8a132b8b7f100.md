## Answer

### Title
Reward-sniping via instant vote reallocation into `delegatedPool` before reward distribution - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool` distributes newly harvested bribe rewards pro-rata over the **current** `totalSupply` at the moment `_manageRewards` runs, with no time-weighting of balances. Because voting weight into `delegatedPool` can be reallocated instantly via `WombatBribeManager.vote()` with no cooldown or lock, and both `getReward()` and `harvestAll()` are unrestricted public/external functions, an attacker can move vlMGP voting weight into `delegatedPool` immediately before a reward-notifying event and capture a disproportionate share of rewards that accrued from other users' pre-existing vote weight.

### Finding Description
`getReward(address _for)` has no access-control modifier beyond `updateRewards(_for, rewardTokens)` — anyone can call it for any account: [1](#0-0) 

`harvestAll()` is fully unrestricted (`external`, no modifiers) and pulls bribes into the pool's own accounting via `_manageRewards`: [2](#0-1) 

`_manageRewards` (shown as `_notifyRewardAmount`-style logic) increases `rewardInfo.rewardPerTokenStored` using the **current** `totalSupply`, not a time-weighted historical balance: [3](#0-2) 

Voting weight into `delegatedPool` is adjusted instantly through `WombatBribeManager.vote()`, which calls `stakeFor`/`withdrawFor` on the target rewarder with no cooldown, minimum-hold period, or epoch lock: [4](#0-3) 

Crucially, `castVotes()` — the function that actually forwards newly-harvested Wombat bribes into each pool's rewarder (`_forwardRewards`) — unconditionally triggers `delegatedPool.harvestAll()` at the end of the same transaction: [5](#0-4) 

This means a standalone `harvestAll()` call by the attacker, immediately after their own `vote()`/`getReward()` with no intervening `castVotes()`, sweeps zero new value — the underlying per-pool `BribeRewardPool.earned()` for `delegatedPool` was already zeroed by the previous `harvestAll()` call bundled into the last `castVotes()`. The real, exploitable window is: attacker front-runs a pending (mempool-visible) `castVotes()` transaction with `vote(delegatedPool, +X)`, lets `castVotes()` execute (which internally calls `_manageRewards`/`harvestAll` using the now-inflated `totalSupply`), then calls `getReward(attacker)` to claim a slice of rewards that accrued from other voters' pre-existing weight over the whole prior epoch — before the attacker had any stake. Afterward the attacker can `unvote`/reallocate away, since vlMGP votes carry no lockup at the `delegatedPool` allocation layer.

Existing checks do not stop this: `updateRewards` correctly updates `userRewardPerTokenPaid` on each interaction, but the underlying reward-per-token math is not duration-weighted, so a fresh depositor legitimately (per the code's own logic) earns a full pro-rata share of any reward notified after their deposit, regardless of how briefly they held that balance.

### Impact Explanation
This is a **theft of unclaimed yield** from existing `delegatedPool` voters: the attacker captures rewards attributable to bribe-earning vote weight accrued by other participants over the preceding voting epoch, diluting their share. Matches Immunefi's "theft of unclaimed yield" impact class. The magnitude scales with (attacker's injected weight) / (total delegatedPool weight at harvest time) × (bribe amount harvested).

### Likelihood Explanation
- Precondition: attacker must already hold vlMGP (locked MGP) with unused voting power — a real but modest capital requirement, not privileged access.
- Requires either (a) mempool front-running of a `castVotes()` call (feasible on BSC's public mempool) or (b) simply voting in a block preceding a scheduled/incentivized `castVotes()` call (callers are paid a fee to call it, so it happens regularly and is predictable).
- Fully repeatable every epoch; no owner/governance action needed.
- Not exploitable via a purely self-contained `vote → getReward → harvestAll → getReward` sequence in isolation, since `harvestAll()` alone yields nothing new absent a preceding bribe-forwarding (`castVotes`) event — this nuance should be reflected in likelihood as "moderate," dependent on timing around `castVotes()`.

### Recommendation
Introduce time-weighted reward accrual (e.g., a minimum holding/epoch-lock before newly staked weight becomes eligible for the next reward distribution) or snapshot eligible balances at the start of each bribe epoch rather than at `_manageRewards` time. Alternatively, disallow vote reallocation into `delegatedPool` within the same block/epoch as a pending `castVotes()`/`harvestAll()` call, or require a cooldown between `vote()` and `getReward()`/`unvote()`.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool` + `WombatBribeManager` with two existing voters, `A` and `B`, each with equal weight in `delegatedPool`, held for several epochs.
2. Let bribes accrue in underlying pool rewarders across an epoch (mock Wombat bribe contract).
3. Just before calling `castVotes()` (simulating mempool front-run), have attacker `C` call `vote([delegatedPool],[+X])` with `X` comparable to `A+B`'s combined weight.
4. Call `castVotes()` (or directly `harvestAll()` after simulating a bribe push into the per-pool rewarder to isolate the mechanic).
5. Have `C` call `getReward(C)` and record the payout.
6. Assert `C`'s payout ≈ `X/(A+B+X) × harvestedAmount` even though `C` held that weight for zero time relative to `A`/`B`'s full epoch, and assert this exceeds `C`'s time-weighted fair share (which should be ~0), demonstrating value transfer from `A`/`B` to `C`.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
