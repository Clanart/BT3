### Title
Delimiter-less concatenation of `kc_user`/`kc_service` in `KeychainServer.get_keychain_for_request()` allows cross-account keychain (private key) collision - (File: chia/daemon/keychain_server.py)

### Summary
`KeychainServer.get_keychain_for_request()` builds the cache key for its `_alt_keychains` map by directly string-concatenating the caller-supplied `kc_user` and `kc_service` values with no delimiter: `key = (user or "unnamed") + (service or "")`. Two distinct, legitimate `(user, service)` pairs can produce an identical concatenated string (e.g. `user="wallet1", service=""` and `user="wallet", service="1"` both yield `"wallet1"`). Because this key is used both to look up an already-cached `Keychain` instance and to decide whether to construct a new partitioned `Keychain(user=user, service=service)`, a caller that supplies a colliding pair reuses another party's already-instantiated `Keychain` object — reaching that other partition's private key material (mnemonics, private keys, labels) instead of its own. [1](#0-0) 

### Finding Description
The daemon exposes a remote keychain RPC surface (`KeychainServer`) reachable over the local daemon websocket by any client that can reach the daemon (any local service/RPC caller, including wallet processes, CLI, and any other locally-connected `kc_user`/`kc_service`-tagged clients such as multiple wallet instances or GUI sessions).

The partitioning logic is:
```
user = request.get("kc_user", self._default_keychain.user)
service = request.get("kc_service", self._default_keychain.service)
if user == self._default_keychain.user and service == self._default_keychain.service:
    keychain = self._default_keychain
else:
    key = (user or "unnamed") + (service or "")
    if key in self._alt_keychains:
        keychain = self._alt_keychains[key]
    else:
        keychain = Keychain(user=user, service=service)
        self._alt_keychains[key] = keychain
return keychain
``` [1](#0-0) 

`user` and `service` are attacker/caller-controlled strings taken straight from the incoming JSON request (`kc_user`, `kc_service`) forwarded through `KeychainProxy.format_request()`. [2](#0-1) 

Because the two fields are concatenated without a separator, the resulting cache key is not injective over `(user, service)` pairs — any caller who can predict or guess another caller's `user`/`service` combination (or who simply enumerates adjacent splits, e.g. shifting one character from `service` into `user`) can construct a request whose concatenated key collides with an already-cached entry, and `get_keychain_for_request()` will hand back that pre-existing `Keychain` object instead of creating an isolated one. Every command that operates "on behalf of" the resolved keychain — `get_all_private_keys`, `get_first_private_key`, `get_key_for_fingerprint`, `get_key`/`get_keys` (with `include_secrets=True`), `add_key`, `delete_all_keys`, `delete_key_by_fingerprint`, `set_label` — then acts against the wrong, colliding keychain partition. [3](#0-2) 

This is structurally the same bug class as the reported Grafana issue: a shared cache is keyed by a value that is supposed to identify/separate two different security principals, but the caching layer does not guarantee uniqueness of that key, so one principal's cached, sensitive state (there: session token in cached headers; here: another party's private-key-bearing `Keychain` instance) is returned to a different, unrelated principal.

### Impact Explanation
A successful collision returns raw private key material (mnemonic entropy and private keys via `get_all_private_keys`/`get_first_private_key`/`get_key`) belonging to a different `kc_user`/`kc_service` partition to an unrelated local caller, and also allows that caller to mutate/delete keys in the wrong partition (`add_key`, `delete_all_keys`, `delete_key_by_fingerprint`) — a concrete path to unauthorized coin movement once the private key is exfiltrated, since chia private keys directly control puzzle-hash ownership and signing. This is a High-impact key-custody/authorization boundary violation within the daemon/keychain RPC surface, one of the explicitly in-scope areas.

### Likelihood Explanation
Exploitation requires two conditions: (1) more than one non-default `kc_user`/`kc_service` partition must be active in the same daemon process (this is a supported, documented multi-keychain feature, not an edge case), and (2) the calling party must be able to supply/guess a `kc_user`/`kc_service` string that concatenates to the same key as a victim's. Because the daemon is a semi-trusted local admin surface (protected by mutual TLS using daemon certs) rather than fully untrusted network input, the realistic threat is a locally co-resident but lower-trust process/user (or a bug in a legitimate client that mis-serializes these fields) rather than a remote unauthenticated attacker — this keeps likelihood at Medium even though the root cause is a straightforward, always-present string-concatenation flaw.

### Recommendation
Use a collision-free composite key, e.g. a tuple `(user, service)` instead of string concatenation, or join with an unambiguous, escaped delimiter (e.g. `f"{user!r}:{service!r}"` after escaping any delimiter characters in the inputs) when indexing `_alt_keychains`. Additionally, validate/restrict which local principals may set arbitrary `kc_user`/`kc_service` values to avoid an untrusted local caller impersonating another partition's identifiers at all.

### Proof of Concept
1. Daemon has two active non-default keychain partitions already cached via prior requests:
   - Request A: `{"kc_user": "wallet1", "kc_service": ""}` → cached under key `"wallet1"`.
2. A second local caller (or a legitimate client with a subtly different configuration) sends: `{"kc_user": "wallet", "kc_service": "1"}`.
   - `get_keychain_for_request()` computes `key = "wallet" + "1" = "wallet1"`, matching the entry already cached for the *first* caller's partition.
3. The second caller then issues `{"command": "get_all_private_keys", "kc_user": "wallet", "kc_service": "1"}`.
4. `KeychainServer.get_all_private_keys()` resolves `self.get_keychain_for_request(request)` to the colliding cached `Keychain` object belonging to partition A, and returns partition A's private keys/entropy to the second caller instead of an empty/isolated result for partition `("wallet", "1")`.     def get_keychain_for_request(self, request: dict[str, Any]) -> Keychain:
        """
        Keychain instances can have user and service strings associated with them.
        The keychain backends ultimately point to the same data stores, but the user
        and service strings are used to partition those data stores. We attempt to
        maintain a mapping of user/service pairs to their corresponding Keychain.
        """
        user = request.get("kc_user", self._default_keychain.user)
        service = request.get("kc_service", self._default_keychain.service)
        if user == self._default_keychain.user and service == self._default_keychain.service:
            keychain = self._default_keychain
        else:
            key = (user or "unnamed") + (service or "")
            if key in self._alt_keychains:
                keychain = self._alt_keychains[key]
            else:
                keychain = Keychain(user=user, service=service)
                self._alt_keychains[key] = keychain
        return keychain

    async def add_key(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        mnemonic_or_pk = request.get("mnemonic_or_pk", None)
        label = request.get("label", None)
        private = request.get("private", True)

        if mnemonic_or_pk is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing key information"},
            }

        try:
            key = self.get_keychain_for_request(request).add_key(mnemonic_or_pk, label, private)
        except KeyError as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEYERROR,
                "error_details": {"message": f"The word '{e.args[0]}' is incorrect.'", "word": e.args[0]},
            }
        except ValueError as e:
            log.exception(e)
            return {
                "success": False,
                "error": str(e),
            }

        if isinstance(key, PrivateKey):
            fingerprint = key.get_g1().get_fingerprint()
        else:
            fingerprint = key.get_fingerprint()

        return {"success": True, "fingerprint": fingerprint}

    async def check_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        root_path = request.get("root_path", None)
        if root_path is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing root_path"},
            }

        check_keys(Path(root_path))

        return {"success": True}

        return {"success": True}

    async def run_request(self, request_dict: dict[str, Any], request_type: type[Any]) -> dict[str, Any]:
        keychain = self.get_keychain_for_request(request_dict)
        if keychain.is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        try:
            request = request_type.from_json_dict(request_dict)
        except Exception as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }

        try:
            return {"success": True, **request.run(keychain).to_json_dict()}
        except KeychainFingerprintNotFound as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEY_NOT_FOUND,
                "error_details": {"fingerprint": e.fingerprint},
            }
        except KeychainException as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }

    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}

    async def get_first_private_key(self, request: dict[str, Any]) -> dict[str, Any]:
        key: dict[str, Any] = {}
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        sk_ent = self.get_keychain_for_request(request).get_first_private_key()
        if sk_ent is None:
            return {"success": False, "error": KEYCHAIN_ERR_NO_KEYS}

        pk_str = bytes(sk_ent[0].get_g1()).hex()
        ent_str = sk_ent[1].hex()
        key = {"pk": pk_str, "entropy": ent_str}

        return {"success": True, "private_key": key}

    def format_request(self, command: str, data: dict[str, Any]) -> WsRpcMessage:
        """
        Overrides DaemonProxy.format_request() to add keychain-specific RPC params
        """
        if data is None:
            data = {}

        if self.keychain_user or self.keychain_service:
            data["kc_user"] = self.keychain_user
            data["kc_service"] = self.keychain_service

        return super().format_request(command, data)
