### Title
Withdrawer-controlled withdrawal UTXO key lets an attacker permanently orphan an honest operator's payout attribution - ([File: core/src/task/payout_checker.rs])

### Summary
The withdrawal UTXO spent in `create_payout_txhandler` is an ordinary single-key UTXO whose private key is held by the withdrawer, not by any bridge quorum. The withdrawer's `SinglePlusAnyoneCanPay` signature only commits their own UTXO to one specific output (index 0) in one specific transaction — it does not prevent the withdrawer from independently signing and broadcasting a *different* transaction spending the same outpoint. Because `PayoutCheckerTask::run_once` and the block-scanning logic that feeds it attribute a payout purely by "whichever confirmed transaction spends `withdrawal_utxo_txid:vout`" and an unauthenticated OP_RETURN inside it, an operator's genuinely broadcast, fee-paying payout can be permanently orphaned if the withdrawer's own competing spend confirms instead.

### Finding Description
The binding this exploit breaks: `withdrawals.payout_payer_operator_xonly_pk == operator_xonly_pk_that_actually_funded_and_broadcast_the_payout`, and by extension `PayoutCheckerTask.mark_payout_handled(citrea_idx, kickoff_txid) == reimbursement_for_the_operator_who_paid_output_script_pubkey/output_amount`.

Root cause and path:

1. The withdrawal UTXO is created and controlled solely by the withdrawer's own key: `generate_withdrawal_utxo` sends dust to `signer.address` (the user's key) [1](#0-0) , and the operator later derives `user_xonly_pk` directly from that UTXO's `script_pubkey` [2](#0-1) . No verifier/operator co-signature is required to spend this UTXO — it is not a covenant or a musig2 output.

2. `Operator::withdraw` verifies the user's `SinglePlusAnyoneCanPay` signature only against `sighash(input#0, output#0)` of the specific `create_payout_txhandler` it builds [3](#0-2) , then funds/broadcasts that transaction via RBF [4](#0-3) . `create_payout_txhandler` places the operator's identifying `OP_RETURN(operator_xonly_pk)` in output index 2, outside the sighash committed by the user's signature [5](#0-4) .

3. Nothing on-chain or in this repo prevents the withdrawer — who still holds the withdrawal UTXO's private key — from independently constructing and broadcasting a competing transaction that spends the exact same `input_outpoint` to an arbitrary `output_script_pubkey`, with no OP_RETURN (or a bogus one), and with higher fees to win the mempool/RBF race or a natural reorg.

4. Payout attribution is done purely from chain-scan results, not from the operator's own broadcast record: `update_finalized_payouts` looks at whichever transaction is found spending the tracked withdrawal UTXO in a confirmed block, and extracts `operator_xonly_pk` from that transaction's first OP_RETURN output; if it is missing or doesn't parse to a valid xonly key, `operator_xonly_pk` is set to `None` [6](#0-5) , and this is written unconditionally into the `withdrawals` table [7](#0-6) .

5. `PayoutCheckerTask::run_once` only picks up withdrawals where `payout_payer_operator_xonly_pk = <this operator's key>` [8](#0-7)  and then calls `handle_finalized_payout` / `mark_payout_handled` [9](#0-8) . If the confirmed spending transaction is the attacker's (not the operator's), the column is `NULL`, SQL equality against a concrete xonly key never matches, and the honest operator's payout is never recognized as "unhandled" — it is silently and permanently unreachable by this task, even though the operator's BTC has already left their control to pay the withdrawer.

Existing guards do not stop this: `SECP.verify_schnorr` only validates the withdrawer's own signature over their own intended output, `is_profitable`/`is_deposit_valid` are irrelevant to this race, and no presigned transaction graph, uniqueness constraint, or txid-pinning ties `withdrawals.idx` to the specific transaction the operator broadcast.

### Impact Explanation
An honest operator that funds a withdrawer's payout (paying real, fee-bearing BTC out of its own wallet, per `output_script_pubkey`/`output_amount` from `WithdrawParams`) can be made permanently unable to claim reimbursement if the withdrawer (who fully controls the withdrawal UTXO's private key) races or reorgs a competing spend of the same outpoint into confirmation before/instead of the operator's broadcast transaction. This matches the specified Critical severity category: "an honest operator that funded a payout being permanently unable to be reimbursed." The attack is repeatable for every withdrawal and against every operator, since it only depends on the universal fact that withdrawal UTXOs are plain single-key outputs owned by the withdrawer.

### Likelihood Explanation
No privileged role, key compromise, or majority hashrate is required — only the ability the withdrawer already has by design: to sign arbitrary transactions from their own withdrawal UTXO key, and pay competitive fees to win an RBF/first-seen race or benefit from an ordinary shallow reorg before finality. This is well within the stated attacker capability set ("choose the bytes of a withdrawal UTXO ... broadcast Bitcoin transactions and pay fees"). The only cost is the attacker's own transaction fees; the payoff (griefing an operator with no benefit to themselves) is a plausible motive for a malicious withdrawer or a bribed third party, and the bug is deterministic once the race is won — it does not depend on chance beyond the race itself.

### Recommendation
Do not attribute reimbursement eligibility purely from a chain scan of "whichever tx spends the UTXO" combined with an attacker-controllable OP_RETURN. Instead: (1) have each operator record the exact `payout_txid` (and ideally its full serialized transaction) they broadcast at `withdraw()` time, keyed by `(withdrawal_id, operator_xonly_pk)`, before funding; (2) when the chain-scan later finds a confirmed spend of the withdrawal UTXO, compare it against the operator's own recorded `payout_txid`/output rather than trusting the confirmed transaction's self-declared OP_RETURN; (3) if a different transaction confirms instead (the withdrawer's competing spend), have the operator detect this via bitcoin_syncer reorg/utxo-spent tracking and treat the funds as unrecoverable/refundable through a distinct governance path rather than silently orphaning the withdrawal row.

### Proof of Concept
`cargo test` plan (regtest, no mainnet, no live Citrea — use `MockCitreaClient` as in existing `core/src/test/manual_reimbursement.rs`):
1. Run a normal deposit + `insert_withdrawal_utxo` flow as in `deposit_and_get_reimbursement` (core/src/test/manual_reimbursement.rs) to obtain `withdrawal_utxo` controlled by `user_sk`.
2. Call `operator.withdraw(...)` to have the operator build, fund, and broadcast (but not yet mine) its `create_payout_txhandler` spending `withdrawal_utxo`.
3. Before that transaction confirms, use `user_sk` to independently sign and broadcast a second, higher-fee transaction spending the same `withdrawal_utxo` outpoint to a wallet-controlled address, with no OP_RETURN.
4. Mine blocks so the attacker's transaction confirms instead of the operator's (RBF replacement or reorg simulated via `invalidateblock`/regtest reorg).
5. Assert: `db.get_payout_info_from_move_txid(...)` shows `payout_payer_operator_xonly_pk == None` for this withdrawal (per `update_finalized_payouts`).
6. Assert: after running `PayoutCheckerTask::run_once` repeatedly (or waiting the poll delay), `db.get_handled_payout_kickoff_txid(None, <operator's original payout txid>)` never returns `Some(_)`, and `mark_payout_handled` is never invoked for `withdrawal_id` — proving the operator's already-spent BTC can never be bound to a `kickoff_txid`/reimbursement despite having funded the withdrawer.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
