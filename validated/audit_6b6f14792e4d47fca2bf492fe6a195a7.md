### Title
Spot-price manipulation of `IAsset(womAsset).cash()`/`liability()` bypasses depeg discount in `SmartWomConvert.smartConvert()` - (File: wombat/SmartWomConvert.sol)

### Summary
`SmartWomConvert.smartConvert()` decides how much WOM gets minted 1:1 into mWOM versus routed through the WOM/mWOM AMM pool (at real market price) by reading the *current, unprotected* spot values `cash()`/`liability()` of the Wombat pool asset. These values can be moved within the same transaction by an ordinary wallet performing a swap against the same pool, exactly the same "manipulate the reserve/accounting variable used for a critical financial decision, then reverse it" pattern used in the RADT-DAO exploit (there via `pair.sync()` after donating tokens to the pair; here via a swap that shifts `cash`/`liability` before/after calling `smartConvert`).

### Finding Description
`maxSwapAmount()` computes the amount of WOM the protocol is willing to route through the market (i.e., subject to a possible discount) purely from the *current* on-chain state of the Wombat pool asset: [1](#0-0) 

```
function maxSwapAmount() public view returns (uint256) {
    uint256 womCash = IAsset(womAsset).cash();
    uint256 womLiability = IAsset(womAsset).liability();
    if (womCash >= womLiability)
        return 0;
    return (womLiability - womCash) * ratio / DENOMINATOR;
}
```

`smartConvert()` uses this value, together with `currentRatio()` (also a live pool-derived spot price), to decide the `convertRatio` that is passed into `_convertFor`: [2](#0-1) 

```
function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
    ...
    uint256 mWomToWom = currentRatio();
    if (mWomToWom < buybackThreshold) {
        uint256 maxSwap = maxSwapAmount();
        uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
        uint256 convertAmount = _amountIn - amountToSwap;
        convertRatio = convertAmount * DENOMINATOR / _amountIn;
    }
    return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
}
```

`_convertFor` then mints mWOM 1:1 for the `convertAmount` portion via `IMWom(mWom).deposit(convertAmount)`, and only swaps the smaller `buybackAmount` at the actual (worse) market rate: [3](#0-2) 

Because `cash()`/`liability()` reflect the pool's instantaneous state (not a TWAP or any manipulation-resistant value), any unprivileged wallet can, within a single atomic transaction:
1. Swap WOM into the pool asset (or otherwise shift its `cash`/`liability`) so that `womCash >= womLiability`, forcing `maxSwapAmount() == 0`.
2. Call `smartConvert()` with `mWomToWom < buybackThreshold` still true (the manipulation only needs to affect `cash`/`liability`, not necessarily `currentRatio`, or both can be pushed simultaneously) so that `amountToSwap = 0` and `convertAmount = _amountIn`, i.e., `convertRatio = DENOMINATOR` (100%).
3. Receive `_amountIn` mWOM minted 1:1 through `mWom.deposit()`, completely bypassing the intended discount mechanism designed to only offer non-1:1, market-rate conversion for a depegged mWOM.
4. Reverse the initial swap (or simply sell the freshly minted mWOM back through the pool) in the same or a follow-up transaction, extracting the difference between the intended discounted rate and the 1:1 par rate as profit, funded by the mWOM backing/other holders.

This mirrors the RADT-DAO bug class: a contract makes a critical mint/accounting decision based on a live, single-block-manipulable reserve/ratio value read from an AMM-like pool, with no TWAP, no minimum-liquidity check, and no protection against same-block manipulation.

### Impact Explanation
`smartConvert()` is unprivileged and unrestricted (comment says "should mainly be used by wombat staking" but there is no access control enforcing this), so any wallet can call it. Exploiting the manipulable `cash()/liability()` and `currentRatio()` inputs allows minting mWOM at par (1:1) when the intended behavior is to apply a market-rate discount, diluting the backing of mWOM and directly harming existing mWOM/mWomSV holders — this is a direct value-extraction (theft) vector against protocol funds/backing, satisfying the "concrete direct theft of user funds / protocol insolvency" bar.

### Likelihood Explanation
The attack is executable by any unprivileged wallet in a single transaction (optionally with a flash loan of WOM to size the swap), requires no special permissions, and depends only on interacting with the public WOM/mWOM pool and calling the public `smartConvert()` function. Likelihood is high whenever pool liquidity is thin enough to move `cash()`/`liability()` cheaply relative to the profit obtainable from bypassing the discount.

### Recommendation
Do not use spot `cash()`/`liability()` or a single-block `currentRatio()` read as the sole basis for the discount decision. Use a time-weighted or otherwise manipulation-resistant price/reserve measure, add slippage/deviation checks against a trusted reference price, or require the swap and mint operations to be validated across multiple blocks (e.g., checkpointing) before allowing full 1:1 minting.

### Proof of Concept
1. Attacker takes/borrows a large amount of WOM.
2. Attacker swaps WOM into the `womAsset` Wombat pool (or performs an equivalent action) to push `cash() >= liability()`, making `SmartWomConvert.maxSwapAmount()` return 0.
3. In the same transaction, attacker calls `SmartWomConvert.smartConvert(_amountIn, _mode)` with `currentRatio() < buybackThreshold` still holding; `convertRatio` resolves to `DENOMINATOR`, so the entire `_amountIn` is minted 1:1 into mWOM via `mWOM.deposit()` [4](#0-3) [5](#0-4) .
4. Attacker reverses the initial swap / sells the minted mWOM back into the pool, realizing the arbitrage profit created by bypassing the intended market-rate discount.
