### Title
Missing freshness/replay check on signed Shopify App Proxy requests allows indefinite replay of captured signed URLs - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates an incoming app-proxy request solely by recomputing the HMAC signature over the query parameters and comparing it to the `signature` param. Although Shopify includes a `timestamp` query parameter in every signed app-proxy request (which is folded into the signed payload as an ordinary parameter), the code never checks that this timestamp is recent. This is directly analogous to the reported Chainlink bug class: a piece of externally-supplied, cryptographically "valid" data (a signed price / a signed request) is trusted without checking its age against any freshness bound, allowing stale (here: captured/leaked) authenticated data to be accepted indefinitely.

### Finding Description
`query_string_valid?` and `calculated_signature` only assert that the signature matches the given query string: [1](#0-0) 

There is no code path anywhere in `AppProxyVerification` that inspects `query_hash["timestamp"]` and rejects requests whose timestamp is older than some acceptable window. Once any signed app-proxy URL is observed by a third party — e.g. leaked via browser history, an HTTP `Referer` header, shared/forwarded links, proxy/CDN access logs, or a compromised iframe context — that exact URL remains a validly-signed, indefinitely-replayable request against the app's app-proxy endpoint, because the verification logic has no concept of "staleness" the same way `ChainlinkUtil::getPrice` had no concept of a stale price feed reading.

### Impact Explanation
Any state-changing or data-returning action reachable through an app's app-proxy route (protected only by `ShopifyApp::AppProxyVerification`) can be replayed by anyone who has obtained a previously valid signed URL, even long after the original request window, without needing the shared secret. Depending on what the app-proxy endpoint does, this can result in actions being repeated on behalf of a shop/customer or stale data being served/accepted as fresh — the same class of harm as trusting a stale oracle price (using outdated, no-longer-representative signed data as if it were current).

### Likelihood Explanation
Exploitation requires an attacker to first obtain a legitimately signed app-proxy URL (via logs, referrer leakage, shared links, etc.), which is a realistic occurrence in browser-based storefront contexts where app-proxy URLs are embedded in page requests. The verification code itself performs no work to prevent replay once such a URL is captured, so likelihood is driven entirely by URL exposure risk, not by any additional cryptographic weakness.

### Recommendation
In `query_string_valid?`, after computing the HMAC match, additionally validate `query_hash["timestamp"]` against `Time.now` with an acceptable tolerance window (e.g., a few minutes), rejecting requests whose timestamp is outside that window — mirroring the recommended fix pattern of checking a data source's `updatedAt`/heartbeat before trusting it.

### Proof of Concept
1. A legitimate app-proxy request is made by Shopify to the app, e.g. `GET /apps/my-proxy?shop=example.myshopify.com&timestamp=1700000000&signature=<valid_hmac>`.
2. This URL is captured by an attacker (e.g., via a shared link, browser history sync, or a logging proxy).
3. The attacker replays the exact same URL to the app days/weeks later.
4. `query_string_valid?` recomputes the HMAC over the same query parameters (timestamp included) and it still matches, so `verify_proxy_request` allows the request through, even though the original timestamp is long expired.

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
