### Title
Unbounded PlotNFT2 pool reward claim can permanently exceed the mempool transaction cost limit, freezing reward funds - ([File: chia/wallet/plotnft_wallet/plotnft_wallet.py])

### Summary
`PlotNFT2Wallet.claim_rewards()` fetches **all** unclaimed pool-reward coins for a plot NFT and packs every one of them into a single `CoinSpend`/`SpendBundle`, with no batching or upper bound on the number of coins processed. This mirrors the reported `withdrawUnstakedTokens` bug class: an operation that must iterate over an ever-growing, user-controlled list of pending items in one shot, with no cap, so the resulting transaction can grow unboundedly and become impossible to execute.

### Finding Description
`claim_rewards` retrieves the full list of unclaimed reward coins via `plotnft2_store.get_pool_rewards(plotnft_id=...)` with no `limit`/pagination parameter, then builds one `CoinSpend` per reward coin plus the singleton claim spend, all inside a single `WalletSpendBundle`: [1](#0-0) 

Compare this to the older `PoolWallet.claim_pool_rewards()`, which explicitly caps the number of reward spends per transaction via `max_spends_in_tx` / `DEFAULT_MAX_CLAIM_SPENDS`, breaking out of the loop once the limit is reached and logging that it is "truncating absorb to fit into block": [2](#0-1) 

`PlotNFT2Wallet.claim_rewards` has no equivalent cap. Every unclaimed reward coin recorded for the plot NFT (accumulated e.g. while self-pooling, or while a pool intermittently pays many small farming-reward coins) is included unconditionally: [3](#0-2) 

Each additional reward coin adds a `CoinSpend` (with its own puzzle reveal, `SendMessage`/announcement condition wiring back to the singleton spend, and solve). As the count grows, the aggregate CLVM execution cost of the resulting spend bundle grows correspondingly. The mempool enforces `max_tx_clvm_cost` (`MAX_BLOCK_COST_CLVM // 2` by default) as a hard per-transaction cost ceiling in `MempoolManager.validate_spend_bundle()`: [4](#0-3) 

Once the number of accumulated, unclaimed reward coins for a given plot NFT is large enough that the single combined claim spend bundle's cost exceeds `max_tx_clvm_cost`, `claim_rewards()` will always produce a spend bundle that is rejected with `Err.BLOCK_COST_EXCEEDS_MAX`. Because `claim_rewards()` has no batching, there is no way for the user to reduce the number of coins claimed per call (short of manual/低-level operator intervention). Unlike the legacy `PoolWallet`, the wallet RPC `pw_absorb_rewards` endpoint (`chia/wallet/wallet_rpc_api.py:3026`) passes through directly to `PlotNFT2Wallet.claim_rewards` for `PlotNFT2Wallet` instances without any max-spend parameter at all, so an ordinary wallet user has no built-in mechanism to shrink the claim batch: [5](#0-4) 

### Impact Explanation
If enough pool-reward coins accumulate for a `PlotNFT2Wallet` (self-pooling farmer, or slow/late claiming against a pool that pays many small reward coins), the user's `claim_rewards()`/`pw_absorb_rewards` call constructs one gigantic spend bundle that always exceeds the mempool's per-transaction CLVM cost cap. The transaction can never be admitted to the mempool, so the accumulated reward coins become practically unspendable through the normal wallet flow — the funds are stuck in exactly the sense described by the analog report ("if a user unstakes/accumulates many times, their tokens could become stuck"). This is a Medium-severity availability/fund-lockup issue: no funds are stolen or inflated, but legitimate reward coins become effectively unclaimable via the intended wallet code path.

### Likelihood Explanation
Likelihood is moderate: it requires the number of unclaimed reward coins for one plot NFT to grow large enough (self-pooling farmers or slow claim cadence against many small pool payouts), which is a realistic long-running usage pattern rather than an attacker-crafted edge case. No malicious peer, node, or privileged actor is needed — it's triggered purely by normal PlotNFT/pool participant usage of `claim_rewards`/`pw_absorb_rewards`.

### Recommendation
Add a bounded batching parameter to `PlotNFT2Wallet.claim_rewards()` (mirroring `PoolWallet.claim_pool_rewards()`'s `max_spends_in_tx`/`DEFAULT_MAX_CLAIM_SPENDS`) so it only claims up to a fixed number of reward coins per call/spend bundle, expose it through `PWAbsorbRewards`/`pw_absorb_rewards`, and allow repeated invocation to drain the remaining backlog in multiple transactions.

### Proof of Concept
1. Create a `PlotNFT2Wallet` in self-pooling mode.
2. Let it accumulate a very large number of pool-reward coins over time without ever calling `claim_rewards` (e.g., simulate many `farm_blocks_to_puzzlehash` calls targeting the plot NFT's p2-singleton puzzle hash, as in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py`, but without an intervening claim).
3. Call `PlotNFT2Wallet.claim_rewards()` (or the `pw_absorb_rewards` RPC) once enough reward coins have accumulated that the resulting `WalletSpendBundle`'s CLVM cost exceeds `max_tx_clvm_cost` (`MAX_BLOCK_COST_CLVM // 2`).
4. Observe that `MempoolManager.validate_spend_bundle()` rejects the bundle with `Err.BLOCK_COST_EXCEEDS_MAX` [6](#0-5) , and that no smaller/partial claim is possible because `claim_rewards()` always attempts to spend every pending reward coin at once.

    async def claim_pool_rewards(
        self, fee: uint64, max_spends_in_tx: int | None, action_scope: WalletActionScope
    ) -> None:
        # Search for p2_puzzle_hash coins, and spend them with the singleton
        if await self.have_unconfirmed_transaction():
            raise ValueError(
                "Cannot claim due to unconfirmed transaction. If this is stuck, delete the unconfirmed transaction."
            )

        if max_spends_in_tx is None:
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS
        elif max_spends_in_tx <= 0:
            self.log.info(f"Bad max_spends_in_tx value of {max_spends_in_tx}. Set to {self.DEFAULT_MAX_CLAIM_SPENDS}.")
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS

        unspent_coin_records = await self.wallet_state_manager.coin_store.get_unspent_coins_for_wallet(self.wallet_id)
        if len(unspent_coin_records) == 0:
            raise ValueError("Nothing to claim, no transactions to p2_singleton_puzzle_hash")
        farming_rewards: list[TransactionRecord] = await self.wallet_state_manager.tx_store.get_farming_rewards()
        coin_to_height_farmed: dict[Coin, uint32] = {}
        for tx_record in farming_rewards:
            height_farmed: uint32 | None = tx_record.height_farmed(
                self.wallet_state_manager.constants.GENESIS_CHALLENGE
            )
            assert height_farmed is not None
            coin_to_height_farmed[tx_record.additions[0]] = height_farmed
        history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
        assert len(history) > 0
        delayed_seconds, delayed_puzhash = get_delayed_puz_info_from_launcher_spend(history[0][1])
        current_state: PoolWalletInfo = await self.get_current_state()
        last_solution: CoinSpend = history[-1][1]

        all_spends: list[CoinSpend] = []
        total_amount = 0

        # The coins being claimed are gathered into the `SpendBundle`, :absorb_spend:
        # We use an announcement in the fee spend to ensure that the claim spend is spent in the same block as the fee
        # We only need to do this for one of the coins, because each `SpendBundle` can only be spent as a unit

        first_coin_record = None
        for coin_record in unspent_coin_records:
            if coin_record.coin not in coin_to_height_farmed:
                continue
            if first_coin_record is None:
                first_coin_record = coin_record
            if len(all_spends) >= max_spends_in_tx:
                # Limit the total number of spends, so the SpendBundle fits into the block
                self.log.info(f"pool wallet truncating absorb to {max_spends_in_tx} spends to fit into block")
                print(f"pool wallet truncating absorb to {max_spends_in_tx} spends to fit into block")
                break
            absorb_spend: list[CoinSpend] = create_absorb_spend(
                last_solution,
                current_state.current,
                current_state.launcher_coin,
                coin_to_height_farmed[coin_record.coin],
                self.wallet_state_manager.constants.GENESIS_CHALLENGE,
                delayed_seconds,
                delayed_puzhash,
            )
            last_solution = absorb_spend[0]
            all_spends += absorb_spend
            total_amount += coin_record.coin.amount
            self.log.info(
                f"Farmer coin: {coin_record.coin} {coin_record.coin.name()} {coin_to_height_farmed[coin_record.coin]}"
            )
        if len(all_spends) == 0 or first_coin_record is None:
            raise ValueError("Nothing to claim, no unspent coinbase rewards")

    async def pw_absorb_rewards(
        self,
        request: PWAbsorbRewards,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> PWAbsorbRewardsResponse:
        """Perform a sweep of the p2_singleton rewards controlled by the pool wallet singleton"""
        wallet = self.service.wallet_state_manager.wallets[request.wallet_id]

        if isinstance(wallet, PoolWallet):
            async with self.service.wallet_state_manager.lock:
                await wallet.claim_pool_rewards(request.fee, request.max_spends_in_tx, action_scope)
                state: PoolWalletInfo = await wallet.get_current_state()
        elif isinstance(wallet, PlotNFT2Wallet):
            await wallet.claim_rewards(action_scope=action_scope, fee=request.fee, extra_conditions=extra_conditions)
            state = await wallet.get_current_state()
        else:
            raise ValueError("`pw_absorb_rewards` called on a non-pooling wallet")
