### Title
Just-in-time vote/harvest/unvote sandwich lets an attacker steal a share of accrued Wombat bribes from `DelegateVoteRewardPool`, diluting long-term voters - ([File: rewards/DelegateVoteRewardPool.sol], [File: wombat/WombatBribeManager.sol])

### Summary
`DelegateVoteRewardPool` distributes newly harvested bribes using an instantaneous `rewardPerTokenStored += reward * 1e18 / totalSupply` formula with no time-weighting, minimum-stake duration, or checkpointing tied to when the reward accrued. Because `WombatBribeManager.vote`/`unvote` let any vlMGP holder instantly move voting power into/out of the pool acting as `delegatedPool`, and `castVotes()`/`harvestAll()` are permissionless, an attacker can stake right before a harvest, receive a pro-rata share of rewards that accrued over the entire prior voting period, and withdraw immediately afterward.

### Finding Description
`DelegateVoteRewardPool.harvestAll()` pulls all bribes accumulated by the delegate pool since the last cast and distributes them via `_manageRewards` → `_queueNewRewardsWithoutTransfer`: [1](#0-0) 

This updates `rewardPerTokenStored` using the **current** `totalSupply`, not a time-weighted or pre-harvest snapshot of `totalSupply`. Reward entitlement per user is computed purely from `userRewardPerTokenPaid` set by the `updateRewards` modifier, which stamps a user in at whatever `rewardPerTokenStored` is *right before* they stake: [2](#0-1) [3](#0-2) 

Staking into the delegate pool happens through `WombatBribeManager.vote()`, which is completely permissionless and instantaneous — no cooldown, no minimum lock, and it is reachable by any vlMGP holder for any pool including the one whose `rewarder == delegatedPool`: [4](#0-3) 

Withdrawal (`unvote`) is equally instantaneous and permissionless, and immediately claims/settles the caller's reward: [5](#0-4) 

`castVotes()` — which triggers `harvestAll()` on the delegate pool — is also a public, unprivileged function: [6](#0-5) 

Exploit flow (all steps callable by an unprivileged EOA/contract holding vlMGP):
1. Attacker calls `vote([delegatedPoolLp], [largeDelta])`, which calls `DelegateVoteRewardPool.stakeFor(attacker, largeDelta)`. `updateRewards` snapshots the attacker's `userRewardPerTokenPaid` at the pre-harvest value (0 owed so far), then `totalSupply` is inflated by `largeDelta`.
2. Attacker (or anyone, since it's permissionless) calls `castVotes()`, which triggers `harvestAll()`. The bribes accrued since the *last* cast (potentially days of accumulation from other, long-term voters) are distributed via `rewardPerTokenStored += reward * 1e18 / totalSupply`, using the now-inflated `totalSupply` that includes the attacker's just-added stake.
3. Attacker immediately calls `unvote(delegatedPoolLp)` (or `getReward`/`claimAllBribes`), which computes `earned()` based on the attacker's balance times the reward-per-token delta just created, and pays it out, then removes the attacker's stake/vote entirely.

Because reward accounting has no concept of "how long was this balance actually contributing to the vote that earned this bribe," the attacker earns a slice of a lump-sum harvest proportional to balance-at-harvest-time regardless of actual staking duration (effectively zero blocks), while simultaneously enlarging the denominator (`totalSupply`) that reduces the `rewardPerTokenStored` accrual available to the users who were staked for the entire accrual period. No modifier, reentrancy guard, or index update in `WombatBribeManager` or `BribeRewardPool`/`BaseRewardPoolV2` prevents this — `nonReentrant` is not even used on `vote`/`unvote`/`castVotes`, and there is no per-user minimum-duration check.

### Impact Explanation
This is theft of unclaimed yield: bribe rewards that would otherwise accrue entirely to genuine long-term delegated voters are partially redirected to a just-in-time attacker who contributes no meaningful voting duration, diluting `rewardPerTokenStored` growth for existing stakers permanently (their retroactive share of that harvest is reduced forever, as `rewardPerTokenStored` is monotonic and cannot be corrected). This matches the Immunefi impact class "theft of unclaimed yield."

### Likelihood Explanation
- Precondition: attacker must hold (or have previously locked) vlMGP — no fresh capital lock is required per attack since existing vlMGP voting power can be freely reallocated in and out of the delegated pool via `vote`/`unvote` with no cooldown.
- The attack is fully permissionless: `vote`, `castVotes`, and `unvote` have no access control beyond holding some vlMGP.
- It is atomically executable in a single transaction via an attacker-deployed contract (vote → castVotes → unvote), or split across the mempool to front-run someone else's `castVotes()`/`voteAndCast()` call.
- Repeatable every time bribes accumulate between casts (e.g., every epoch), scaling with the attacker's vlMGP voting power relative to `totalSupply` of the delegate pool at harvest time.

### Recommendation
Introduce time-weighted reward accounting for the delegate pool (or any pool subject to lump-sum bribe harvests), e.g.:
- Snapshot `totalSupply`/balances at the start of each voting epoch and distribute the harvested bribes based on that pre-harvest snapshot rather than post-stake `totalSupply`.
- Or require a minimum lock/cooldown between `vote` (stake) and `unvote` (withdraw) into `delegatedPool` so that a single-transaction/single-block stake cannot capture a full epoch's harvest.
- Or checkpoint rewards immediately before any stake change is applied and separately track "eligible" balance only from the next full accrual period onward (i.e., delay a newly staked balance's eligibility until after the next harvest), similar to a "pending stake" pattern used in many synthetix-style vaults with anti-flashloan protections.

### Proof of Concept
Hardhat test plan:
1. Deploy `WombatBribeManager`, `DelegateVoteRewardPool`, and mock `WombatVoter`/bribe contracts; register `delegatedPool` as a pool with `rewarder = delegatedPool`.
2. Have "honest" voter A lock vlMGP and call `vote([delegatedPoolLp], [1000e18])`. Advance several days/blocks and accrue mock bribe rewards inside the mocked Wombat voter (simulate pending bribes accumulating for A's stake period).
3. Just before calling `castVotes()`, have attacker B (with pre-existing vlMGP, but zero prior stake in `delegatedPool`) call `vote([delegatedPoolLp], [9000e18])` in the same block/transaction.
4. Call `castVotes()` (or have anyone call it), which triggers `DelegateVoteRewardPool.harvestAll()` and updates `rewardPerTokenStored`.
5. Immediately (same block) have B call `unvote(delegatedPoolLp)`.
6. Assert: B receives a non-zero reward payout (`RewardPaid` event / token balance increase) proportional to B's 90% share of `totalSupply`, despite B having staked for 0 blocks before the harvest.
7. Assert: A's `earned(A, rewardToken)` after the harvest is less than it would have been had B not front-run (i.e., compute expected reward for A assuming `totalSupply` = 1000e18 only, and show actual `rewardPerTokenStored`-derived earned amount for A is diluted by B's inflated `totalSupply`).
8. Compute `rewardPerTokenStored` delta attributable to B relative to B's zero staking duration in blocks vs. A's full staking duration, confirming disproportionate yield capture.

        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
