### Title
Unauthenticated SSRF via unvalidated on-chain mirror URLs in DataLayer subscription fetch - (File: `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`)

### Summary
Similar to CVE-2021-28941 (MagpieRSS `Snoopy.class.inc` issuing a `curl` request to an attacker-controlled URL with no validation, letting a low-privileged requester reach internal resources), Chia's DataLayer subscription/mirror sync feeds an unvalidated, attacker-controlled URL string directly into an outbound HTTP GET, allowing any unprivileged spend-bundle submitter to trigger SSRF from a DataLayer node.

### Finding Description
Any wallet holder can call `DataLayerWallet.create_new_mirror()` to spend a coin to the mirror puzzle and attach an arbitrary `launcher_id` and arbitrary URL bytes as memos, with no check that the caller owns or controls the target singleton/store: [1](#0-0) 

Because there is no ownership validation in `create_new_mirror`, an attacker can create a mirror for *any* existing DataLayer store id, pointing to any URL (e.g. `http://169.254.169.254/latest/meta-data/`, `http://127.0.0.1:<internal-port>/...`, or an internal-network hostname), by paying only a normal transaction fee and mirror amount. This on-chain mirror coin is picked up via `dl_get_mirrors` / `Mirror` records by any node's `DataLayer.update_subscriptions_from_wallet()`: [2](#0-1) 

Those URLs are persisted as subscription server URLs in `DataStore.update_subscriptions_from_wallet()` with no scheme/host validation: [3](#0-2) 

The periodic background loop `periodically_manage_data()` -> `update_subscription()` -> `fetch_and_validate()` then iterates these server URLs and issues outbound requests via `insert_from_delta_file()` / `download_file()` / `http_download()`, with the URL used verbatim in `session.get(server_info.url + "/" + filename, ...)`: [4](#0-3) [5](#0-4) 

There is no scheme allowlist (e.g., rejecting non-`http(s)`), and no check against private/link-local/loopback/metadata-service IP ranges before the request is made — mirroring the root cause in the CVE (no validation on the URL before the curl request). This is the exact bug class: unauthenticated third-party input drives a server-side outbound request to an attacker-chosen network destination.

### Impact Explanation
A DataLayer node that subscribes to (or owns, via the pseudo-subscription/auto-subscribe path) any store can be made to issue outbound HTTP requests to arbitrary internal addresses chosen by an unrelated, unprivileged party — cloud metadata endpoints, internal admin services, other localhost ports, or private-network hosts reachable only from the DataLayer host. This can be used for internal network reconnaissance/port scanning, potential credential/metadata exfiltration (e.g. cloud IMDS), or triggering unintended side effects on internal HTTP services that trust requests originating from the node's own network. Because DataLayer subscription and periodic syncing is automatic once a store is tracked, no interactive action by the victim operator is required beyond normal subscription/ownership of a store that an attacker also targets with a malicious mirror.

### Likelihood Explanation
High. Creating a mirror only requires calling the standard, publicly documented `dl_new_mirror` wallet RPC / `add_mirror` CLI/RPC and paying a small fee — it is intentionally permissionless (mirrors are meant to be created by third parties to help data availability) and there is no requirement to own the target store's singleton. The victim DataLayer node automatically discovers and uses these URLs via its periodic background sync loop without any operator interaction, so exploitation requires no phishing or social engineering, only knowledge of a target `launcher_id` for a store the victim subscribes to or owns.

### Recommendation
Validate mirror/subscription URLs before use: enforce an `http`/`https` scheme allowlist, resolve and reject destination addresses in private/loopback/link-local/multicast/metadata-service ranges (unless explicitly configured for local/dev use), and consider requiring mirrors to be created only by the store owner (or otherwise rate-limit/segregate untrusted mirror URLs) before they are placed in `DataStore.update_subscriptions_from_wallet()` / used in `http_download()`.

### Proof of Concept
1. Attacker identifies the `launcher_id` of a DataLayer store that a victim node tracks or owns.
2. Attacker runs `chia data add_mirror --id <victim_store_id> --url http://169.254.169.254/latest/meta-data/ --amount 1 --fee <fee>` (or calls `dl_new_mirror` RPC directly) using their own funds — no ownership of `victim_store_id` is required per `create_new_mirror()`.
3. Once the mirror coin confirms on-chain, the victim's `DataLayer.periodically_manage_data()` loop calls `update_subscriptions_from_wallet(victim_store_id)`, ingesting the attacker URL as a subscription server.
4. `fetch_and_validate()` subsequently calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim node to issue `GET http://169.254.169.254/latest/meta-data/.../victim_store_id-....dat` from its own network context, confirming SSRF against an internal/metadata target chosen entirely by the attacker.

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
