### Title

Coinbase outputs are reported spendable before Bitcoin maturity - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary

`Scanner::scan_block` scans every transaction in a block, including `block.txdata[0]`—the coinbase transaction—and returns matching outputs as ordinary `ReceivedOutput` values without recording or enforcing Bitcoin’s coinbase maturity requirement. An output created by a coinbase cannot be spent until it is 100 blocks deep, but the returned object is indistinguishable from a mature spendable output. [1](#0-0) 

### Finding Description

`Scanner::scan_transaction` identifies received funds solely by comparing each transaction output’s `script_pubkey` against the scanner’s registered scripts. [2](#0-1)  `scan_block` invokes that logic for every transaction in `block.txdata`, without excluding `txdata[0]` or otherwise marking its outputs as coinbase outputs. [3](#0-2) 

The returned `ReceivedOutput` contains only the spending offset, `TxOut`, and `OutPoint`; it has no field that distinguishes coinbase outputs or records when they become mature. [4](#0-3)  `SignableTransaction::new` then consumes these objects by copying their outpoints directly into unsigned transaction inputs, with no check that the referenced outpoint belongs to an immature coinbase. [5](#0-4) 

The analogous accounting failure is therefore that excess-looking funds are admitted into the spendable-balance ledger before their corresponding liability—the 100-block coinbase maturity restriction—has been discharged. A miner can trigger this using a normal public Bitcoin block whose coinbase pays to a script monitored by the wallet.

### Impact Explanation

The scanner reports value as received and structurally spendable even though Bitcoin consensus forbids spending it until the coinbase has matured. Wallet or accounting layers consuming `scan_block` can consequently overstate immediately available funds, select an immature coinbase UTXO, construct and sign a transaction around it, and have the resulting spend rejected by consensus.

This produces “funds reported received that are not spendable,” matching the permitted impact class. The impact is bounded to premature spendability/accounting and transaction-construction failure; it does not by itself allow theft of funds.

### Likelihood Explanation

Exploitation requires a miner to place a monitored P2TR script in its coinbase output. No validator privilege, malformed peer message, leaked key, or invalid curve input is required—the trigger is ordinary Bitcoin consensus data accepted from the public chain. If the wallet scans all confirmed blocks through `scan_block`, the first matching coinbase output is returned as soon as its block is scanned rather than after 100 confirmations.

### Recommendation

Track coinbase status explicitly and prevent immature coinbase outputs from entering the spendable-output set. For example:

- Have block scanning return a maturity marker or earliest-spendable height for outputs from `txdata[0]`.
- Delay admission of coinbase `ReceivedOutput`s until the scanned UTXO is at least 100 blocks old.
- Alternatively, require callers to scan mature blocks separately and enforce that invariant in the API, rather than documenting it only as a caller responsibility.
- Add a regression test in which a coinbase pays to a monitored script and `scan_block` must not expose it as immediately spendable.

### Proof of Concept

```rust
use bitcoin::{Block, ScriptBuf, Amount, TxOut};
use bitcoin_serai::wallet::{Scanner, SignableTransaction};

fn demonstrates_immature_coinbase(
  key: k256::ProjectivePoint,
  block: &Block,
  payment: (ScriptBuf, u64),
) {
  // Assume block.txdata[0] is a valid coinbase which contains:
  // TxOut {
  //   value: Amount::from_sat(50_000),
  //   script_pubkey: p2tr_script_buf(key).unwrap(),
  // }
  assert!(block.txdata[0].is_coinbase());

  let scanner = Scanner::new(key).unwrap();
  let received = scanner.scan_block(block);

  // The coinbase output is returned even though spending it now violates the
  // 100-block maturity rule.
  let coinbase_output = received
    .iter()
    .find(|output| output.outpoint().txid == block.txdata[0].compute_txid())
    .expect("scan_block returned the immature coinbase output");

  // The wallet accepts it as an ordinary spendable input.
  let _tx = SignableTransaction::new(
    vec![coinbase_output.clone()],
    &[payment],
    None,
    None,
    1,
  );
}
```

The decisive defect is that `scan_block` iterates over `block.txdata` wholesale and relies only on `scan_transaction`, while the produced `ReceivedOutput` carries no maturity information. [1](#0-0)
