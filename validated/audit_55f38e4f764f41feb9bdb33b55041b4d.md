## Title
`governance_vote` RPC exposes proposer-only, safety-critical vote injection with no caller authentication — (File: `kaiax/gov/headergov/impl/api.go`)

### Summary
The `governance_vote` JSON-RPC method, registered with `Public: true` under the `governance` namespace, lets any caller who can reach the node's RPC (HTTP/WS, not just IPC/local console) queue an arbitrary governance vote for that node to cast the next time it becomes a block proposer. The method's only "authorization" check compares the **node's own configured identity** (`api.h.nodeAddress`) against the current `GoverningNode`, not the identity of the RPC caller — there is no per-caller authentication analogous to `personal_*` account unlocking or IPC-only restriction. This mirrors CVE‑2024‑10109's root cause: a sensitive administrative endpoint that should require elevated/local privilege is instead reachable by any low-privilege caller, letting them modify sensitive protocol configuration (here, governance parameters/validator set) through the node.

### Finding Description
`headerGovModule.APIs()` registers the vote API as public: [1](#0-0) 

`Vote()` performs no check on the identity of the RPC caller. It only checks whether *this node* is the designated `GoverningNode` when in `single` mode: [2](#0-1) 

If the check passes (i.e., the target node happens to be the current single-mode governing node, or governance mode is not `single`), the vote is unconditionally queued via `PushMyVotes`, with no verification that the RPC caller is the node operator, a validator, or otherwise authorized to influence this specific node's voting behavior.

Once queued, the vote is automatically embedded into the next block header this node proposes: [3](#0-2) 

The header-level `VerifyVote` check (validating council membership, proposer identity, and value consistency) only guards against a *dishonest node* forging someone else's vote — it does nothing to prevent an *unauthenticated external RPC client* from causing an otherwise honest, legitimately-governing node to cast a vote it never intended to cast: [4](#0-3) 

Accepted vote names include highly sensitive parameters (unit price, minting amount, reward ratio, base fee bounds, and even `governance.addvalidator` / `governance.removevalidator`): [5](#0-4) 

Unlike `admin`/`personal` namespaces — which are either `IPCOnly` or require account unlocking — the `governance` namespace carries no such restriction, and other governance-related APIs (`contractgov`, `gov`) follow the identical `Public: true` pattern: [6](#0-5) [7](#0-6) 

### Impact Explanation
If the current single-mode `GoverningNode`'s (or any validator's, once in `none` mode) RPC endpoint is reachable by unprivileged callers — which is a routine operational configuration for monitoring/automation, and the `governance` module is explicitly designed to be called externally (its own README documents `curl`-based invocation over HTTP) — an attacker can silently inject governance votes into that node without the operator's consent. When the node next proposes a block, the malicious vote is embedded in `header.Vote` and, if ratified at the epoch boundary, permanently changes chain-wide governance parameters (fees, minting/reward economics, base-fee bounds) or the validator set (`addvalidator`/`removevalidator`). This is a direct, unauthorized state-divergence/DoS/governance-hijack vector consistent with "acceptance of an invalid transaction or block" and "governance parameters" abuse in scope.

### Likelihood Explanation
Likelihood is moderate-to-high in realistic deployments: the API is `Public: true` (no `IPCOnly` flag), requires zero authentication, and its documented usage pattern is a plain `curl` POST to the RPC port. Any operator who enables the `governance` module on an HTTP/WS listener (a common need since the module's entire purpose is remote governance operations) is exposed. The attack requires only that the target node is presently the acting `GoverningNode` — a fact publicly queryable via `governance_getParams`/`governance_status` — with no cryptographic proof of caller intent required to trigger the queued vote.

### Recommendation
- Do not expose `governance_vote` (and any state-mutating governance methods) as `Public: true` on network-reachable RPC transports; mark it `IPCOnly` or require the same authenticated/local-only guarantees `personal_*` methods use.
- If remote invocation must be supported, add real caller authentication (e.g., signed request, local admin auth) so the check is against the actual caller rather than only the node's own configured address.
- Consider requiring an explicit confirmation/allow-list flag (e.g., `--governance.rpc.enable-vote`) before allowing `governance_vote` on non-IPC transports.

### Proof of Concept
1. Identify a node that is the current `governance.governingnode` (via `governance_getParams`) and that exposes the `governance` module on its public HTTP/WS RPC (default `Public: true` registration allows this if the module is enabled).
2. Send, from an unauthenticated remote client:
```
curl "http://<victim-node>:8551" -X POST -H 'Content-Type: application/json' --data '
  {"jsonrpc":"2.0","id":1,"method":"governance_vote","params":[
    "reward.mintingamount",
    "999999000000000000000000"
  ]}'
```
3. The call succeeds (`headerGovAPI.Vote`, `kaiax/gov/headergov/impl/api.go:53-83`) and queues the vote via `PushMyVotes`, with no verification that the caller is the node operator.
4. When the victim node next proposes a block, `PrepareHeader` (`kaiax/gov/headergov/impl/header.go:30-55`) embeds the attacker-controlled vote into `header.Vote`, and it becomes eligible for ratification at the next epoch boundary — altering chain-wide economic/governance parameters without the node operator's authorization.

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}

func (h *headerGovModule) PrepareHeader(header *types.Header) error {
	// if this node has a vote waiting to be casted, put Vote field.
	if vote, ok := h.peekMyVote(); ok {
		voteBytes, err := vote.ToVoteBytes()
		if err != nil {
			return err
		}
		header.Vote = voteBytes
		logger.Debug("Prepare header with vote", "num", header.Number.Uint64(), "vote", hexutil.Encode(header.Vote))
	}

	// if epoch block & vote exists in the last epoch, put Governance field.
	if header.Number.Uint64()%h.epoch == 0 {
		gov := h.getExpectedGovernance(header.Number.Uint64())
		if len(gov.Items()) > 0 {
			govBytes, err := gov.ToGovBytes()
			if err != nil {
				return err
			}
			header.Governance = govBytes
			logger.Debug("Prepare header with governance", "num", header.Number.Uint64(), "governance", hexutil.Encode(header.Governance))
		}
	}

	return nil
}

// VerifyVote checks the following:
// (1) voter must be in valset,
// (2) integrity of the voter (the voter must be the block proposer),
// (3) the vote value must be consistent compared to the latest ParamSet.
func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
