### Title
Non-linear HEAD movement (branch checkout/reset) during a turn causes `compute_v2_review_set` to silently drop committed dangerous changes from Stop-hook security review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` builds the Stop-hook review set as `dirty_now & changed_since`, where `dirty_now` only includes commit-derived changes when `head_at_capture` is a **linear ancestor** of the current `HEAD` [1](#0-0) . If the working tree performs ordinary git operations that move `HEAD` sideways (e.g. checkout to another branch, `git reset`/rebase) before committing, the ancestor check fails, the committed-but-clean dangerous file never enters `dirty_now`, and the `&` intersection with `changed_since` zeroes it out of the review set even though `changed_since` (diff against the UPS-time baseline) would otherwise have caught it.

### Finding Description
`save_baseline_sha`/`capture_git_baseline` record `baseline_sha` (a `git stash create` snapshot) and `head_at_capture` (`HEAD` SHA) once per `UserPromptSubmit` [2](#0-1) [3](#0-2) .

At `Stop`, `compute_v2_review_set` computes:
- `tracked_dirty`/`untracked` from `git status --porcelain` (state vs current `HEAD`/index) [4](#0-3) 
- `dirty_now = tracked_dirty | new_untracked`, then unions in `head_at_capture..HEAD` **only if** `_is_ancestor(head_at_capture, current_head)` is true [1](#0-0) 
- `changed_since = _git_name_only(repo, baseline_sha)` — a plain `git diff --name-only <baseline_sha>` against the *current working tree*, independent of `HEAD` topology [5](#0-4) 
- `review_set = dirty_now & changed_since` [6](#0-5) 

If during a turn the agent checks out a different branch (or otherwise makes `HEAD` not a descendant of `head_at_capture`) and then commits the dangerous change so the working tree becomes clean, `tracked_dirty` is empty for that file and the `head_at_capture..HEAD` union is skipped because `_is_ancestor` returns false for a non-linear/sideways move. `dirty_now` therefore never contains the dangerous file. `changed_since` (baseline vs. current tree) still correctly contains it, but since `review_set` is an **intersection**, the empty membership in `dirty_now` wins and the file is dropped from `review_paths` entirely. `handle_stop_hook` then treats it as "no changes since baseline" and exits without invoking the LLM review [7](#0-6) , and the baseline is only advanced on the next capture — the dangerous content is never surfaced to the Stop-hook reviewer.

No existing guard compensates for this: `_is_ancestor` is used purely to decide whether to widen `dirty_now`, not as a signal to fall back to `changed_since` alone; the `&` semantics assume linear commit history within a turn, which ordinary git usage (branch switching, resets, rebases) violates.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths." A dangerous change (e.g. a hardcoded secret, backdoor, or exfiltration snippet) committed via ordinary, non-linear git operations is silently excluded from the Stop-hook LLM security review, so the review never runs and never flags it. The change can then be pushed or merged without ever being scanned, which is the vector for "sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" described in the target impact — the security-review safety net is bypassed for that specific commit.

### Likelihood Explanation
This requires only unprivileged, standard git commands available to any agent/session working in a cloned repo (checkout to another branch, reset, rebase, amend combined with topology changes) — no admin privileges, leaked keys, or social engineering are needed. Because Claude Code agents routinely perform exactly these operations as part of normal multi-branch workflows, the condition (`HEAD` not linearly descending from `head_at_capture` at Stop time) is realistically reachable, not a contrived edge case, making this moderately likely to occur, especially if repository content (e.g. a malicious README/instructions or prompt injection) nudges the agent toward such a workflow while embedding a dangerous change.

### Recommendation
Do not intersect `dirty_now` with `changed_since` when `HEAD` topology is non-linear relative to `head_at_capture`. Specifically:
- When `_is_ancestor` is false but `head_at_capture != current_head`, treat the review set as the union (not just intersection-gated) of `changed_since` and `dirty_now`, or fall back to `changed_since` alone (bounded by files under the repo) rather than silently excluding committed content.
- Alternatively, always compute the full diff between `baseline_sha` and current `HEAD`/working tree (`changed_since`) as the review set, and only use `dirty_now` to add newly dirtied/untracked files, never to gate out files already proven to differ from `baseline_sha`.

### Proof of Concept

1. Init a git repo, commit an initial file, capture `baseline_sha` via `capture_git_baseline` and `head_at_capture` via `_git_rev_parse_head` (simulating UPS).
2. Create and checkout a new branch `git checkout -b other`.
3. Write a dangerous file (e.g. containing a hardcoded secret / `eval(input())`), `git add` + `git commit` on the new branch — working tree is now clean, `HEAD` is a new commit whose parent is NOT `head_at_capture` in the ancestor sense relevant to the check (or use `git checkout --orphan`/`git reset --hard <unrelated-sha>` then commit, to guarantee `_is_ancestor(head_at_capture, HEAD)` is False).
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert: expected `review_paths` should contain the dangerous file's absolute path (it changed relative to `baseline_sha`), but actual behavior returns an empty `review_set` / omits the file, proving the file is dropped from review despite being a genuine post-baseline change.
6. Also assert the corresponding `handle_stop_hook` flow exits via `_skip(9)` ("empty review set") for this dangerous file, confirming no LLM review is triggered.

```python
def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}
```

```python
def _git_status_porcelain(cwd):
    """One `git status --porcelain=v1 -z` → (tracked_dirty, untracked) sets of
    repo-root-relative paths, or (None, None) on error. Replaces the
    `_temp_index + git diff HEAD --name-only` pair for the v2 dirty_now
    computation: faster in large repos, and yields the
    untracked set separately so the later get_git_diff can do a targeted
    `add -N -- <files>` instead of a whole-tree `add -N .`.

    -uall: list individual files inside untracked directories (default
    collapses to `dir/`). Required so the untracked set subtracts cleanly
    against the UPS-time `_list_untracked` snapshot, which uses ls-files and
    therefore always lists individual files."""
    try:
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "status",
             "--porcelain=v1", "-uall", "-z"],
            cwd=cwd, capture_output=True, text=True, timeout=30,
        )
        if r.returncode != 0:
            debug_log(f"_git_status_porcelain rc={r.returncode}: {r.stderr[:200]}")
            return None, None
        tracked, untracked = set(), set()
        entries = r.stdout.split("\0")
        i = 0
        while i < len(entries):
            e = entries[i]
            if not e:
                i += 1
                continue
            xy, path = e[:2], e[3:]
            if xy == "??":
                untracked.add(path)
            else:
                tracked.add(path)
                # Rename/copy entries are XY old\0new\0 — second NUL field is
                # the origin path; consume it so it isn't misparsed as a new
                # 2-char-status entry.
                if "R" in xy or "C" in xy:
                    i += 1
            i += 1
        return tracked, untracked
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_status_porcelain error: {e}")
        return None, None
```
