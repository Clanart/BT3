### Title
`HostManager.onAccept` validates only the source **chain**, not the source **module** — any ISMP-capable pallet on the Hyperbridge chain can trigger EVM host governance actions - (File: `evm/src/core/HostManager.sol`)

### Summary
`HostManager.onAccept` — the entry point that lets cross-chain "governance" mutate an `EvmHost`'s critical parameters (`admin`, `hostManager`, `handler`, `consensusClient`, `feeToken`) or withdraw bridge revenue — only checks that the incoming ISMP `PostRequest.source` equals the Hyperbridge state-machine id. It never checks `request.from`, i.e. it never verifies that the specific sending module on that chain is the intended `host-executive` pallet (`PALLET_ID = ModuleId::Pallet(PalletId(*b"hostexec"))`). This is the same ACL-over-broadness pattern as the RocketStorage report: instead of scoping authority to "the one namespace/module that owns this setting," the check is scoped to "anything coming from this generally-trusted origin (the whole chain)."

### Finding Description
On the EVM side, `HostManager.onAccept` is: [1](#0-0) 

The only authorization performed on the payload is:
```solidity
if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
```
This confirms the request originated from the *Hyperbridge parachain as a whole*, but does not check `request.from` against the specific pallet id that is supposed to be the sole authority for these actions (`hostexec`, defined here): [2](#0-1) 

Once past that single chain-level check, the raw `request.body` is decoded and dispatched straight into privileged setters: [3](#0-2) 

Those setters (`updateHostParams`, `withdraw`) are gated only by `restrict(_hostParams.hostManager)`, i.e. "caller is the `HostManager` contract" — which is satisfied unconditionally once `HostManager.onAccept` itself passed: [4](#0-3) [5](#0-4) 

`updateHostParams` can overwrite `admin`, `hostManager`, `handler`, `consensusClient`, and `feeToken` wholesale (only sanity-checking interface support, not the caller's legitimacy): [6](#0-5) 

The trust boundary that is supposed to prevent this is entirely on the Substrate side, where `host-executive` is the only pallet expected to construct these governance messages, hard-coding `from: PALLET_ID.to_bytes()`: [7](#0-6) 

However, the low-level dispatcher that every pallet on the chain uses (`pallet_ismp`'s `IsmpDispatcher::dispatch_request`) forwards the caller-supplied `from` field completely unvalidated into the outgoing `PostRequest`: [8](#0-7) 

Nothing in `dispatch_request` ties `from` cryptographically or structurally to the identity of the calling pallet/extrinsic — it is just a `Vec<u8>` passed through from `DispatchRequest::Post(dispatch_post)`. Because the ISMP dispatcher is a shared, generic service used by multiple pallets (`bandwidth`, `relayer`, `hyper-fungible-token`, `intents-coprocessor`, `demo`, etc.), the *entire* security of "only host-executive can reconfigure the EVM host" rests solely on every one of those pallets voluntarily never setting `from`/`to`/`body` to values that collide with the `HostManager` module binding — a convention, not an enforced invariant. `HostManager.onAccept` is the one place that should hard-fail on `request.from != PALLET_ID`, and it does not.

### Impact Explanation
If any other on-chain component that can reach `IsmpDispatcher::dispatch_request` (an existing pallet with a latent bug, a future pallet, or a misconfigured route) constructs a `PostRequest` whose `dest`/`to` target an `EvmHost`'s `HostManager` and whose `body` is prefixed with `OnAcceptActions.SetHostParam`, it is accepted as legitimate governance because only the chain of origin is checked. This lets an attacker:
- Replace `_hostParams.admin` and `_hostParams.hostManager` with attacker-controlled addresses, seizing full administrative control of the `EvmHost` (freeze/unfreeze, future param changes).
- Replace `_hostParams.consensusClient` or `_hostParams.handler` with a malicious contract that accepts forged consensus/state proofs, enabling false state acceptance for all subsequent bridge messages.
- Call `withdraw()` to drain the host's held fee-token/native-token balance to an arbitrary beneficiary.

This is a direct match to the bounty's "unauthorized transaction or execution," "false proof/state acceptance," and "stealing or loss of funds" categories, since it corrupts `HostParams.admin/hostManager/consensusClient/handler` and the withdrawal beneficiary — the exact class of "any registered entity can override settings belonging to another part of the system" from the seed report.

### Likelihood Explanation
The `source` (chain-id) check is real and does block cross-chain spoofing from other parachains/EVM chains — this is not exploitable by an arbitrary outside relayer. The residual risk is intra-chain: `HostManager.onAccept`'s authorization model implicitly assumes it is the *only* pallet routing traffic to it, but the actual enforcement point (module/pallet identity via `request.from`) is missing entirely. Given ISMP's generic dispatcher forwards `from` unchecked, this is a structural gap rather than a hypothetical one — it requires no malicious relayer, prover, or off-chain actor, only a legitimate-looking Post request dispatched by any code that has access to `IsmpDispatcher::dispatch_request` with attacker-influenced `from`/`to`/`body`. I could not fully enumerate every pallet's message-construction code within the available iterations to confirm a live, already-shippable extrinsic that lets an unprivileged end user set `from` directly; this should be verified against each pallet that calls `dispatch_request` (`bandwidth`, `relayer`, `hyper-fungible-token`, `intents-coprocessor`, `demo`) to see whether any exposes user-influenced `to`/`from`/`body` in a signed extrinsic. Regardless of which caller reaches it, the underlying defect — `HostManager.onAccept` never checking `request.from` — is a concrete, provable ACL gap in the current code.

### Recommendation
In `HostManager.onAccept`, in addition to the existing chain check, require `request.from` to equal the expected `host-executive` module id (`b"hostexec"` / `ModuleId::Pallet(PalletId(*b"hostexec"))` encoded as bytes) before decoding `OnAcceptActions`:
```solidity
if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
if (!request.from.equals(HOST_EXECUTIVE_MODULE_ID)) revert UnauthorizedAction();
```
This mirrors the RocketStorage recommendation: scope the ACL to the specific namespace/module that owns the setting, not to "anything from a generally trusted chain."

### Proof of Concept
1. On the Hyperbridge parachain, any pallet `P` (present or future) that has access to `T::IsmpHost: IsmpDispatcher` calls:
   ```rust
   T::IsmpHost::default().dispatch_request(
       DispatchRequest::Post(DispatchPost {
           dest: evm_state_machine,                 // target EVM chain
           from: b"attacker-or-other-pallet".to_vec(), // NOT hostexec's PALLET_ID
           to: host_manager_contract_address.to_vec(), // the HostManager on that EVM host
           timeout: 0,
           body: {
               let mut b = vec![OnAcceptActions::SetHostParam as u8];
               b.extend(evil_host_params.abi_encode());
               b
           },
       }),
       fee_metadata,
   );
   ```
2. This request's `source` field is set by the dispatcher to the Hyperbridge chain's own state-machine id, so it passes `request.source.equals(hyperbridge())` in `HostManager.onAccept`.
3. `request.from` is never checked, so `OnAcceptActions.SetHostParam` is decoded and `IHostManager(_params.host).updateHostParams(evil_host_params)` executes, overwriting `admin`, `hostManager`, `consensusClient`, `handler`, and `feeToken` on the target `EvmHost` — see `evm/src/core/HostManager.sol:95-109` and `evm/src/core/EvmHost.sol:573-645`.

```text
    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }
```

```text
    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;
```

```text
    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
```
