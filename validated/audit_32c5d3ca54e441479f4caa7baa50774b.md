### Title
Flash vote-then-unvote reward sniping via instantaneous (non-time-weighted) `rewardPerTokenStored` accounting - ([File: rewards/BaseRewardPoolV2.sol], [File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.vote()`/`unvote()` freely call `IBribeRewardPool.stakeFor`/`withdrawFor` with no minimum holding period, and the underlying `BaseRewardPoolV2._provisionReward` distributes newly harvested bribes as an instant lump-sum split by current `totalStaked()`, not by time-weighted stake. An attacker can front-run a pending `castVotes()` call with `vote()` to inflate their `userVotedForPoolInVlmgp`/pool stake, let `castVotes()` harvest and forward bribes (which bumps `rewardPerTokenStored` based on the now-inflated `totalStaked()`), then immediately call `unvote()` (which passes `claim=true`) to withdraw their stake and receive their proportional share of the reward instantly.

### Finding Description
`vote()` calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` [1](#0-0) , which increases `totalSupply`/`_balances` and checkpoints `userRewardPerTokenPaid[token][attacker] = rewardPerToken(token)` at the *pre-reward* value via the `updateRewards` modifier [2](#0-1) .

`castVotes()` computes `votes[i] = targetVote - currentVote` from `pool.totalVoteInVlmgp` vs the live Wombat vote, then calls `wombatStaking.vote(...)` (harvesting bribes) and `_forwardRewards(rewardTokens, feeAmounts)` in the same transaction [3](#0-2) . `_forwardRewards` ultimately calls `queueNewRewards` → `_provisionReward`, which instantly recomputes:
```
rewardPerTokenStored += (_amountReward * 10**decimals) / totalStaked();
```
with `totalStaked()` measured *at that instant* [4](#0-3) . This is not a time-streamed (rewardRate/periodFinish) model — the entire bribe amount is applied as a single atomic increment to the accumulator, à la MasterChef `accPerShare`.

Because the attacker's `userRewardPerTokenPaid` was frozen at the pre-reward value when they staked via `vote()`, calling `unvote()` afterward (`withdrawFor(msg.sender, currentVote, true)`) triggers `updateRewards`, which computes `_earned = balance * (new rewardPerToken - old paid) / decimals` and pays it out immediately via `claim=true` [5](#0-4) [6](#0-5) . The attacker thus captures a full share of the bribe proportional to their staked amount, despite having been staked for effectively zero time, diluting the share owed to genuinely time-weighted long-term voters. Neither `vote()` nor `unvote()` nor `stakeFor`/`withdrawFor` enforce any minimum holding duration, cooldown, or time-weighting — the only checks are `pool.isActive` and `userTotalVotedInVlmgp[msg.sender] <= getUserVotable(msg.sender)`, both of which the attacker trivially satisfies by holding vlMGP.

### Impact Explanation
This is a real theft-of-yield vector: an attacker with vlMGP can extract a disproportionate share of freshly harvested Wombat bribes from a `castVotes()` call by staking immediately before and withdrawing immediately after, without contributing time-weighted stake. This dilutes rewards owed to continuously-staked voters — matching the "theft of unclaimed yield" impact class.

### Likelihood Explanation
Feasible for any vlMGP holder: requires only (1) mempool visibility of a pending `castVotes()` transaction (public function, anyone can call it, so pending calls are visible), (2) a `vote()` transaction front-running it, and (3) an `unvote()` transaction back-running it. On a chain like BSC (short block times), this ordering is readily achievable via standard gas-price front-running, and is fully repeatable every time `castVotes()`/`harvestSinglePool` forwards non-trivial bribe amounts. No special privileges are needed beyond holding/locking vlMGP.

### Recommendation
Replace the instantaneous lump-sum `rewardPerTokenStored` update in `_provisionReward` with a time-streamed reward-rate model (e.g., `rewardRate` distributed linearly over a fixed duration, updated via `lastUpdateTime`/`periodFinish` as in Synthetix `StakingRewards`), so that `rewardPerToken` only accrues proportionally to elapsed time and current stake, preventing a single-block/flash stake from capturing a full share of a reward injection. Alternatively, enforce a minimum staking duration (cooldown) between `vote()` and `unvote()` for a given pool before rewards become claimable.

### Proof of Concept
Foundry test outline:
1. Deploy `WombatBribeManager`, a `BribeRewardPool` for a test pool, and mock `wombatStaking`/`voter` returning controllable bribe amounts on `vote()`.
2. Setup: Voter B locks vlMGP and calls `vote()` to stake into the pool well before the test (simulating a long-term voter), and time passes / `castVotes()` is called once to establish baseline `rewardPerTokenStored`.
3. Attacker A locks vlMGP and, in the transaction immediately preceding a pending `castVotes()` call, calls `vote()` with a large positive delta into the same pool.
4. Call `castVotes()` — configure the mock `wombatStaking.vote()` to return a nonzero bribe reward token amount, causing `_forwardRewards`/`queueNewRewards` to bump `rewardPerTokenStored` for the pool's rewarder.
5. Immediately after, Attacker A calls `unvote(pool)`.
6. Assert: `rewardToken.balanceOf(A)` after `unvote()` is nonzero and proportional to `A`'s staked delta / `totalStaked()` at provisioning time, despite A having been staked for 0 elapsed time; compare A's captured reward-per-unit-time-staked against Voter B's `earned()` to show A's yield-per-second is orders of magnitude higher — demonstrating disproportionate capture violating time-weighted reward conservation.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
