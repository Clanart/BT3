### Title
Blacklisted user's deposit principal (stablecoin) is permanently frozen in WombatStaking with no way to redirect withdrawal - (File: wombat/WombatStaking.sol, wombat/WombatPoolHelper.sol, wombat/WombatPoolHelperV2.sol, wombat/AnkrBNBPoolHelper.sol)

### Summary
`WombatStaking.withdraw()` unconditionally sends the underlying `depositToken` (an arbitrary ERC20 configured per pool, e.g. a stablecoin such as USDC/USDT/BUSD) to the `_sender` address that is hard-coded to `msg.sender` by every pool-helper entry point (`WombatPoolHelper.withdraw`, `WombatPoolHelperV2.withdraw`, `AnkrBNBPoolHelper.withdraw`). There is no parameter allowing the depositor to designate an alternate recipient. If the depositing wallet becomes blacklisted by the `depositToken` contract at any point between deposit and withdrawal, the principal held in `WombatStaking` becomes permanently unrecoverable.

### Finding Description
`WombatStaking.deposit()` pulls an arbitrary `poolInfo.depositToken` from the user and mints a receipt token to `msg.sender`. When the user later calls the corresponding pool helper's `withdraw()`, the helper always forwards `msg.sender` as the `_sender` argument: [4](#0-3) 

`WombatStaking.withdraw()` then transfers the redeemed `depositToken` directly to that `_sender` with `safeTransfer`, with no alternative recipient parameter available anywhere in the call chain (`PoolHelper.withdraw` → `WombatStaking.withdraw` → `_transfer`): [5](#0-4) 

Since `depositToken` is configured per pool via `addPool` and represents the actual stablecoin used in the underlying Wombat AMM pool (e.g. USDC/USDT/BUSD — tokens with real, currently-active blacklist functionality), the same root cause as the referenced Ajna finding applies: an ordinary wallet has no mechanism to move its principal to another address if it is later blacklisted by that token's issuer. Unlike `MasterMagpie`/`BaseRewardPool`, whose `getReward`/`getRewards` functions already carry a `_receiver` parameter, the withdrawal path for the underlying deposited asset is rigidly tied to `msg.sender`.

### Impact Explanation
If the depositor's address is blacklisted by the `depositToken` issuer after depositing but before withdrawing, the deposited principal held by `WombatStaking` is permanently frozen — it can never be transferred out to that address, and there is no owner/admin escape hatch or way for the user to specify a different destination. This is a genuine, non-privileged, direct freezing of user funds satisfying the "permanent freezing of funds" impact bar.

### Likelihood Explanation
Blacklisting is a low-probability event per address, matching the original report's own severity framing (medium). It requires no privileged actor or governance action — it is purely a consequence of the third-party stablecoin issuer's compliance actions against an ordinary user's wallet, which is squarely in scope as an unprivileged-wallet analog affecting WombatStaking's LP/asset custody.

### Recommendation
Add a `_recipient` parameter to the pool helper `withdraw()` functions and to `WombatStaking.withdraw()`, allowing the depositor (validated as the receipt-token owner/burn-caller) to specify the address that should receive the redeemed `depositToken`, mirroring the recommended fix pattern of adding a recipient argument rather than hard-coding `msg.sender`.

### Proof of Concept
1. User A deposits USDC into a Wombat pool via `WombatPoolHelper.deposit()`, which routes through `WombatStaking.deposit()`; a receipt token is minted to User A and staked in `MasterMagpie`.
2. Circle (USDC issuer) blacklists User A's address for an unrelated reason.
3. User A calls `WombatPoolHelper.withdraw(_liquidity, _minAmount)`, which calls `WombatStaking.withdraw(lpToken, _liquidity, _minAmount, msg.sender)` [4](#0-3) .
4. `WombatStaking.withdraw()` redeems the LP from the Wombat pool and attempts `IERC20(poolInfo.depositToken).safeTransfer(_sender, ...)` where `_sender == User A` [6](#0-5) ; the USDC `transfer` reverts because User A is blacklisted.
5. There is no alternate function or parameter allowing User A (or anyone) to redirect the withdrawal to a non-blacklisted address, so the principal remains permanently stuck in `WombatStaking`.

    /// @notice withdraw from a wombat Pool. Note!!! pool helper has to burn receipt token!
    /// @dev Only a PoolHelper can call this function
    /// @param _lpToken the address of the wombat pool lp token
    /// @param _liquidity wombat pool liquidity
    /// @param _minAmount The minimal amount the user accepts because of slippage
    /// @param _sender the address of the user
    function withdraw(
        address _lpToken,
        uint256 _liquidity,
        uint256 _minAmount,
        address _sender
    ) nonReentrant whenNotPaused _onlyPoolHelper(_lpToken) external {
        Pool storage poolInfo = pools[_lpToken];

        IERC20(poolInfo.lpAddress).safeApprove(poolInfo.depositTarget, _liquidity);
        _toMasterWomAndSendReward(_lpToken, _liquidity, false);

        uint256 beforeWithdraw = IERC20(poolInfo.depositToken).balanceOf(address(this));
        IWombatPool(poolInfo.depositTarget).withdraw(
            poolInfo.depositToken,
            _liquidity,
            _minAmount,
            address(this),
            block.timestamp
        );

        IERC20(poolInfo.depositToken).safeTransfer(
            _sender,
            IERC20(poolInfo.depositToken).balanceOf(address(this)) - beforeWithdraw
        );

        emit NewWithdraw(_sender, poolInfo.depositToken, _liquidity);
    }
