### Title
Git-history-rewrite (amend) blind spot in `compute_v2_review_set` lets a dangerous change bypass the Stop-hook security review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` derives the reviewable file set as the intersection `dirty_now & changed_since`, where `dirty_now` is computed relative to *current HEAD* and only includes commits made since baseline when `head_at_capture` is an ancestor of the current HEAD. When a turn contains `git commit` followed by `git commit --amend` (or any other history-rewriting operation), the resulting HEAD is no longer a descendant of `head_at_capture`, so `_is_ancestor` returns `False`, `diff_base` stays `"HEAD"`, and the working tree is clean — making `dirty_now` empty. Because `review_set = dirty_now & changed_since` and `changed_since` is never used alone when `dirty_now` is non-empty-but-computed, the amended dangerous content is silently dropped from the review set even though `changed_since` (which compares to the true `baseline_sha`) still correctly contains it.

### Finding Description
`compute_v2_review_set` in [1](#0-0)  computes:
- `dirty_now`: tracked+untracked files differing from **current HEAD**, extended with `_git_name_only(repo, f"{head_at_capture}..HEAD")` *only if* `head_at_capture` is an ancestor of current HEAD (`_is_ancestor` check).
- `changed_since`: files differing from the `baseline_sha` (the `git stash create` snapshot captured at `UserPromptSubmit` via `capture_git_baseline`, wired through `save_baseline_sha`).
- `review_set = dirty_now & changed_since`.

`_is_ancestor` in [2](#0-1)  uses `git merge-base --is-ancestor`, which is strictly a linear-history check. A `git commit` followed by `git commit --amend` produces a new HEAD that replaces (not descends from) the pre-amend commit, so `head_at_capture` is not an ancestor of the amended HEAD. This is a completely ordinary, unprivileged git operation reachable during any Claude Code session (e.g. "fix the commit message", "amend to include this file", or attacker-controlled repo content nudging Claude toward an amend workflow).

Exploit flow:
1. `UserPromptSubmit` fires `handle_user_prompt_submit` → `capture_git_baseline` → `save_baseline_sha` records the pre-turn stash SHA and `head_at_capture` (see [3](#0-2) ).
2. During the turn, Claude edits a dangerous file, runs `git commit` (HEAD advances linearly — still reviewable), then runs `git commit --amend` (e.g., to fold in a "final tweak" containing the dangerous payload, or to rewrite the message). This is normal, common git usage.
3. At Stop, `compute_v2_review_set` runs: current HEAD is the amend result, `_is_ancestor(head_at_capture, current_head)` is `False` because the amend rewrote history rather than extending it linearly.
4. `diff_base` remains `"HEAD"`; `dirty_now` is computed only from `git status` against current HEAD, which is empty (working tree is clean post-commit).
5. `review_set = dirty_now(∅) & changed_since(contains dangerous file) = ∅`.
6. The dangerous file is never passed to `get_git_diff`/`analyze_code_security`, so no LLM review, no `exit(2)` guard — the change is treated as "old"/non-existent and skipped entirely.

This breaks the stated invariant "the review set must stay bound to the right repo, baseline, and touched paths" — the `dirty_now` term, meant to be a *sanity/scoping* filter against a moved-but-linear HEAD, instead becomes a hard exclusion mask when history is rewritten, silently overriding the correct `changed_since` signal.

### Impact Explanation
This is a logic-level security-control bypass: the Stop-hook LLM vulnerability scan (`analyze_code_security`) and the guard `exit(2)` that forces Claude to address findings are the only enforcement mechanism the plugin provides. A dangerous change introduced via a normal `git commit --amend` sequence is completely excluded from the diff sent to the reviewer, so no warning is ever surfaced and no forced remediation loop is triggered. This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — the review pipeline's core security guarantee (every Claude-authored change in the turn gets reviewed) is defeated by ordinary, unprivileged git operations available in any session.

### Likelihood Explanation
- No special privileges needed: `git commit --amend` (or `git reset --soft` + recommit, `git rebase`, `git filter-branch`, etc. — any non-fast-forward HEAD movement) is routine and commonly used during coding sessions.
- Fully deterministic and repeatable: any commit+amend pair within a single turn (or an aborted/preserved-baseline multi-turn sequence) triggers the ancestor check to fail.
- Requires no cooperation from the user beyond normal agentic workflow (Claude itself, prompted by repo content or user instruction, performing an amend is enough).
- The bug is in pure git-state logic with no environmental dependencies, so it reproduces identically across all clones/OSes with `git` installed.

### Recommendation
Do not let a failed ancestor check collapse `dirty_now` back to "only clean-tree status." When `head_at_capture` and current HEAD diverge (amend/rebase/reset), still include files that differ between `head_at_capture` and current HEAD (a `git diff --name-only head_at_capture HEAD`, not restricted to a linear ancestor relationship), analogous to what `changed_since` already computes against `baseline_sha`. Practically:
- Replace the `_is_ancestor` gate with an unconditional union: `dirty_now |= _git_name_only(repo, head_at_capture) or set()` whenever `head_at_capture != current_head`, regardless of ancestry, so amended/rebased commits are still diffed.
- Alternatively, drop the `dirty_now & changed_since` intersection requirement when HEAD has moved non-linearly since capture, and fall back to `changed_since` alone (mirroring the existing "missing baseline → use dirty_now" fallback, but for the inverse case).
- Add a regression test asserting the review set still contains the dangerous file after a `commit` + `amend` sequence.

### Proof of Concept
Integration/unit test plan (extends the existing test suite for `compute_v2_review_set`):
1. Initialize a temp git repo with one commit.
2. Capture baseline: `baseline_sha = capture_git_baseline(repo)`, `head_at_capture = _git_rev_parse_head(repo)`.
3. Write a "dangerous" file (e.g. contains `eval(request.args['cmd'])`), `git add` + `git commit -m "wip"`.
4. Run `git commit --amend --no-edit` (simulating a fixup amend that still contains the dangerous line, or edits it further).
5. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture)`.
6. **Expected (currently failing) assertion**: the dangerous file path is present in the returned `review_paths`.
7. **Observed (vulnerable) behavior**: `review_paths` is empty / does not contain the dangerous file because `dirty_now` is empty (clean tree, non-ancestor HEAD) while `changed_since` correctly contains it, and the intersection zeroes it out. [1](#0-0)  is the exact code path to instrument/patch, and [2](#0-1)  is the ancestry check whose semantics must be relaxed for the non-linear-history case.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False

def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
    with_locked_state(session_id, _save)
