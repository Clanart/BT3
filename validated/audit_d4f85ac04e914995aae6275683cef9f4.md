### Title
Attacker can poison a wallet's scanned output set with an immature coinbase output, causing every aggregated spend to build a consensus-invalid transaction - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the OpenQ finding (where an attacker leaves a permanently-reverting token address in `tokenAddresses`, bricking `_claimAtomicBounty`'s loop), an unprivileged miner can leave an unspendable entry in the set of outputs a Bitcoin wallet believes it owns. `Scanner::scan_block` iterates **all** transactions including `block.txdata[0]` (the coinbase) and returns any output paying a registered script as a `ReceivedOutput`. A coinbase output is consensus-unspendable for 100 blocks (BIP-30 / coinbase maturity), yet it is reported identically to a normal output. When the wallet aggregates scanned outputs into `SignableTransaction::new`, that single poisoned input makes the entire constructed transaction consensus-invalid — the exact "stale/poisoned list entry bricks the whole batch" shape from the reference report.

### Finding Description
`scan_block` calls `scan_transaction` on every transaction in the block, including index 0 (the coinbase):

```rust
// networks/bitcoin/src/wallet/mod.rs
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
``` [1](#0-0) 

`scan_transaction` matches purely on `script_pubkey` — any output paying a registered script (external key or any registered offset) is returned with no check on whether it is spendable: [2](#0-1) 

A miner can place an output paying the victim's P2TR script inside their own coinbase transaction at zero marginal cost. The victim's `scan_block` then reports this as a received, spendable output. `SignableTransaction::new` consumes `Vec<ReceivedOutput>` and builds `tx_ins`/`prevouts` from every entry with no maturity or origin validation: [3](#0-2) 

The resulting transaction is signed with `Prevouts::All` covering all prevouts and is invalid on the Bitcoin network until the coinbase matures — any aggregation/consolidation spend built from the poisoned output set fails. This mirrors the reference bug: the attacker "deposits" an entry the protocol never validates or expires, and the batch operation (here, the aggregated spend; there, the claim loop) reverts/fails because of it. Unlike the reference fix (remove the token on refund), there is no code path that removes or filters this entry — only a doc comment noting callers "may" post-process, which is a documented warning, not enforcement.

### Impact Explanation
**Medium.** Funds are not stolen, but a miner can grief a wallet/multisig relying on `scan_block`: every spend transaction constructed from the scanned output set that includes the poisoned UTXO is consensus-invalid and will be rejected by the network (wasting at least one full FROST signing round per attempt, since `TransactionMachine` signs all inputs including the poisoned one). Recovery requires the caller to detect and exclude the output, which is possible (the attacker spends no real funds beyond forfeiting a coinbase payment to the victim — the funds remain spendable after maturity), so this is a temporary freeze/forced-fee-waste rather than permanent loss. The attack costs the miner the coinbase output value, which bounds the economic viability — a meaningful mitigation.

### Likelihood Explanation
Reachable only by a miner willing to direct coinbase output value at the victim's script. This limits practical exploitability: arbitrary users cannot craft coinbase transactions, and the attacker must sacrifice the output amount. However, any mined coinbase can pay an arbitrary script at no extra fee cost, and a hostile miner (or one mining a paying-block for a fee) can repeatedly poison the set.

### Recommendation
Filter coinbase transaction outputs in `scan_block` — iterate `block.txdata[1 ..]` — or annotate `ReceivedOutput` with a maturity flag / block height so callers can exclude immature outputs before passing them to `SignableTransaction::new`. Alternatively, record the coin height in `scan_block` and reject coinbase-sourced `ReceivedOutput`s in `SignableTransaction::new` (or require a `height`/`is_coinbase` field on `ReceivedOutput` so the check is enforceable rather than delegated to a doc comment).

### Proof of Concept
1. Victim creates `Scanner::new(key)` and consumes `scan_block` output as the spendable UTXO set.
2. Attacker mines a block whose coinbase transaction (`block.txdata[0]`) contains `TxOut { script_pubkey: p2tr_script_buf(key), value: 50_000_0000 }`.
3. `scan_block` returns a `ReceivedOutput` for that coinbase output (matches `self.scripts`).
4. Victim calls `SignableTransaction::new(vec![legit_output, poisoned_output], payments, change, None, fee)` — it succeeds and produces a transaction including the coinbase outpoint.
5. The multisig signs and broadcasts; the network rejects the transaction (coinbase spend before 100 confirmations). Every subsequent spend construction that pulls the poisoned output from the scanned set repeats the failure until the caller manually excludes it — matching the reference report's "claim tx always reverts until manual intervention" dynamic.

Note: the `scan_block` doc comment does disclose the maturity caveat, so this sits at the boundary of "documented misuse" — the argument for validity is that the in-scope API itself returns an unspendable output as indistinguishable from a spendable one, making the trap reachable from pure public input (a transaction the attacker causes to be mined) without any integrator error beyond calling the primary scanning API as documented.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
