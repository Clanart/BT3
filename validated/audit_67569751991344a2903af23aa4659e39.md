### Title
Gasless swap repayment amount relies on manipulable instantaneous AMM price, no oracle/TWAP protection - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless-transaction module (KIP-247) validates a user's `GaslessSwapTx` by calling the whitelisted `GaslessSwapRouter` contract's `getAmountIn(token, minAmountOut)`, which — per the contract's own bindings (`dexAddress`, `getDEXInfo` returning a Uniswap-V2-style `factory`/`router`) — derives the exchange rate purely from the instantaneous reserves of a DEX pool, with no Chainlink or TWAP-style external price reference. This is structurally the same bug class as the WooFi H-1 report: a swap settlement path whose "fair price" is computed only from an internally/AMM-derived spot price that a transaction sender can move within the same block, undermining the value guarantees (`minAmountOut`, `amountRepay`) the module relies on to protect the block proposer who has already lent gas to the user.

### Finding Description
`GaslessModule.checkBalanceForSwap` performs the following pre-admission checks on a `GaslessSwapTx`: [1](#0-0) 

Critically, `swapArgs.AmountIn` is only checked against `routerContract.GetAmountIn(nil, token, minAmountOut)` — a live call to the swap router contract that computes required input strictly from the paired DEX pool's current reserves: [2](#0-1) [3](#0-2) 

This is the exact analog of `maxNotionalSwap`/`maxGamma` in WooFi's `WooPPV2.sol`, which likewise trusted an internal formula instead of a robust, manipulation-resistant price feed — the WooFi report explicitly notes the exploit is feasible precisely for tokens without a Chainlink price feed. Here, gasless-whitelisted ERC20 tokens are paired with arbitrary DEX pools (`getDEXInfo`/`dexAddress`) and there is no evidence (in the indexed bindings/module code) of any Chainlink or TWAP cross-check — only the pool's own spot reserves are used both to gate mempool admission and (per `kaiax/gasless/README.md`) to size the `LendTxGenerator` value: [4](#0-3) 

The block-building flow prepends `LendTxGenerator` (which funds the user's account in native KAIA up-front, before the swap executes) ahead of `[GaslessApproveTx, GaslessSwapTx]` in one bundle. Because the mempool-time admission check (`GetAmountIn`) and the actual on-chain `swapForGas` execution happen at different points, and both are driven off the *same manipulable AMM reserves*, an unprivileged transaction sender who also controls (or bundles via the `auction` module, which lets an unprivileged bidder attach a call immediately after a target transaction — see `kaiax/auction/impl/bid_pool.go`) a large swap against the same DEX pool in the same block can skew reserves between the time the pool "validated" the required `amountIn`/`amountRepay` and the time `swapForGas` actually executes, exactly as the WooFi attacker split a large trade into pieces to walk the AMM price before extracting value on the reversed leg.

I was not able to obtain the actual Solidity source of `GaslessSwapRouter.sol` (only the compiled ABI/bytecode via Go bindings are indexed in this repo), so I cannot confirm line-by-line whether `swapForGas` re-checks `amountRepay` against a manipulation-resistant price at execution time, or simply trusts the router's live `getAmountsOut`/`getAmountsIn` from the paired Uniswap-V2 pool. This limits full root-cause certainty on the exact on-chain enforcement, though the Go-side admission logic and ABI surface confirm the pricing dependency is spot-AMM-only.

### Impact Explanation
If the on-chain `swapForGas` settlement also relies on the same DEX pool's spot price (as its own `getAmountIn`/`getDEXInfo` surface strongly suggests), a searcher/attacker can manipulate a thinly-liquid whitelisted token's pool within a single block (optionally paying for guaranteed ordering via the `auction` module) to:
- Cause the proposer to be repaid less than the KAIA gas it fronted via `LendTxGenerator` (fee-delegation/gasless settlement theft), or
- Extract excess swapped tokens/value from the pool itself relative to what the gasless flow's `minAmountOut`/`amountRepay` were meant to guarantee.

This is a direct "gasless ... settlement theft" scenario, reachable by any unprivileged gasless user or auction bidder, matching the escalation rationale accepted in the WooFi report (pool/settlement drain via unchecked AMM-only pricing).

### Likelihood Explanation
Medium-to-High if the paired DEX pools for whitelisted gasless tokens have shallow liquidity (plausible for a subset of KIP-247 whitelisted tokens, mirroring WOO's lack of a Chainlink feed). The attack requires only a single sender's ordinary transaction(s) within one block, optionally aided by the auction module for ordering guarantees — no privileged or node-level access is needed. Confidence is reduced by not being able to inspect the actual on-chain `swapForGas` re-validation logic, since the `.sol` source is not present in this indexed repo.

### Recommendation
- Require the `GaslessSwapRouter` to price whitelisted tokens using a manipulation-resistant reference (TWAP over the paired pool, or an external oracle) rather than the pool's instantaneous reserves, matching the "handle tokens without a robust price feed differently" recommendation from the original report.
- Re-validate `amountIn`/`amountRepay` against the price at actual execution time (inside `swapForGas`), not only at tx-pool admission time, and revert if reserves have moved beyond a bounded tolerance since admission.
- Restrict/limit maximum trade size relative to pool liquidity for gasless-whitelisted token pairs (analogous to `maxNotionalSwap`/`maxGamma`), and disallow whitelisting tokens whose only paired pool has low liquidity/no external price reference.

### Proof of Concept
Conceptual PoC (execution-time details for `swapForGas` could not be fully confirmed since `.sol` source isn't indexed in this repo):
1. Attacker identifies a whitelisted gasless token `T` paired with a low-liquidity Uniswap-V2-style pool via `GaslessSwapRouter.getDEXInfo(T)` / `dexAddress(T)`. [3](#0-2) 
2. Attacker submits an ordinary large swap against `T`'s pool to skew the reserves (optionally using the `auction` module to guarantee it lands immediately before their gasless bundle in the same block). [5](#0-4) 
3. Attacker submits `GaslessApproveTx` + `GaslessSwapTx` with `minAmountOut`/`amountRepay` computed to pass `checkBalanceForSwap`'s `GetAmountIn` check under the pre-skew (or post-skew, depending on ordering) reserve state. [6](#0-5) 
4. When the block is assembled, `LendTxGenerator` fronts KAIA gas to the attacker before `swapForGas` executes against the now-manipulated reserves, resulting in the proposer being repaid less value than lent, or the attacker extracting excess value from the pool — the same "drain via internal AMM pricing" mechanism as WooFi H-1.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (_GaslessSwapRouter *GaslessSwapRouterCaller) GetDEXInfo(opts *bind.CallOpts, token common.Address) (struct {
	Factory common.Address
	Router  common.Address
}, error) {
	var out []interface{}
	err := _GaslessSwapRouter.contract.Call(opts, &out, "getDEXInfo", token)

	outstruct := new(struct {
		Factory common.Address
		Router  common.Address
	})
	if err != nil {
		return *outstruct, err
	}

	outstruct.Factory = *abi.ConvertType(out[0], new(common.Address)).(*common.Address)
	outstruct.Router = *abi.ConvertType(out[1], new(common.Address)).(*common.Address)

	return *outstruct, err

}

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.

## Persistent schema

This module does not persist any data.

// AddBid adds a bid to the bid pool.
// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}
