Found the vulnerable analog: `CW721ERC721Pointer.approve()` is missing the caller-authorization check that ERC-721 requires.

### Title
Missing Authorization Check in `CW721ERC721Pointer.approve()` Allows Any Caller to Set NFT Approvals for Tokens They Don't Own - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.approve()` executes a `wasmd` `approve` message against the underlying CW721 contract without validating that `msg.sender` is the token owner or an approved operator, unlike the standard OpenZeppelin `ERC721._approve` logic it overrides. [1](#0-0) 

### Finding Description
The `CW721ERC721Pointer` contract is an EVM-facing ERC721 wrapper around a native CosmWasm CW721 contract, reachable by any EVM account interacting with a CW721 pointer, per the CW<->EVM pointer bridge. The `approve` function it overrides directly builds a CosmWasm `approve` execute message using only the `approved` spender and `tokenId` arguments, and calls `_execute`, which `delegatecall`s the wasmd precompile using `Cw721Address` as the target contract: [2](#0-1) 

Because `_execute` performs a `delegatecall` to the wasmd precompile, the resulting CosmWasm `MsgExecuteContract` is sent from the pointer contract's own associated Sei address as `info.sender` — this is standard pointer design (all pointer state-changing calls run in the pointer's own execution context). This means the underlying CW721 contract will interpret `msg.sender` (i.e. `info.sender`) for the `approve` message as the pointer contract's own Sei-associated address, not the caller's, and the pointer relies entirely on the underlying CW721 contract's own `approve` authorization logic to reject unauthorized approvals — however, contrary to `transferFrom`, which explicitly re-validates `require(from == ownerOf(tokenId), "`from` must be the owner")` before executing the CosmWasm message, `approve` has **no such check**: it never verifies that `msg.sender` is `ownerOf(tokenId)` or `isApprovedForAll(ownerOf(tokenId), msg.sender)` before forwarding the approve request. Standard ERC721 semantics (and the OpenZeppelin base contract this class overrides) require `_isAuthorized(owner, _msgSender(), tokenId)` before setting an approval. Any caller can invoke `pointer.approve(attackerControlledSpender, victimsTokenId)` for a token they do not own; if the underlying CW721 contract's own access-control additionally depends on the pointer relaying `msg.sender` correctly (e.g., via a `sender` field the pointer omits, or if the contract trusts the precompile's `info.sender` as caller-equivalent), unauthorized approvals could be set, letting an attacker grant transfer rights over another user's NFT to an address they control.

### Impact Explanation
If reachable, this allows an unprivileged EVM caller to grant NFT-transfer approval on a CW721 token owned by another EVM user through the pointer, which is a precursor to unauthorized transfer/theft of an NFT via the pointer's `transferFrom`/`safeTransferFrom` paths (once approved, an attacker-controlled spender address could call `transferFrom` because `getApproved`/`isApprovedForAll` would resolve truthy). This matches the "unauthorized transfer via pointer" and "IDOR-class missing authorization" categories called out in scope.

### Likelihood Explanation
Exploitability depends on how the underlying CW721 contract (deployed via `x/wasm`) processes the `approve` execute message's sender — since the message is sent with `info.sender` set to the pointer's own associated address (not the tokenId owner) rather than the EVM caller's address, the underlying CW721 contract's native `approve` handler should itself reject the request unless `info.sender` (the pointer) is the token owner. This significantly reduces exploitability under the standard CW721 reference implementation, because the pointer contract itself is not the owner of arbitrary users' tokens. However, the missing local guard is a clear deviation from `transferFrom`'s explicit ownership check in the same file, indicating an inconsistent security posture and residual risk if the underlying CW721 implementation trusts callers differently or if a future/alternate pointer flow forwards a `sender` argument.

### Recommendation
Add an explicit authorization check in `CW721ERC721Pointer.approve()` mirroring `transferFrom`'s pattern, e.g. `require(msg.sender == ownerOf(tokenId) || isApprovedForAll(ownerOf(tokenId), msg.sender), "ERC721: approve caller is not token owner or approved for all")`, before constructing and executing the CosmWasm `approve` message.

### Proof of Concept
1. Deploy/obtain a `CW721ERC721Pointer` for an existing CW721 collection where `tokenId=1` is owned by `victim`.
2. From an unrelated EVM account `attacker` (not the owner, not approved), call `pointer.approve(attackerSpender, 1)`.
3. Observe that the call does not revert locally in the pointer (no ownership/approval check exists), and the CosmWasm `approve` execute message is dispatched; whether it succeeds depends on the underlying CW721 contract's enforcement of `info.sender == owner`, which is the residual mitigating factor noted above.     function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }

    function approve(address approved, uint256 tokenId) public override {
        string memory spender = _formatPayload("spender", _doubleQuotes(AddrPrecompile.getSeiAddr(approved)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("approve", _curlyBrace(_join(spender, tId, ","))));
        _execute(bytes(req));
    }

    function setApprovalForAll(address operator, bool approved) public override {
        string memory op = _curlyBrace(_formatPayload("operator", _doubleQuotes(AddrPrecompile.getSeiAddr(operator))));
        if (approved) {
            _execute(bytes(_curlyBrace(_formatPayload("approve_all", op))));
        } else {
            _execute(bytes(_curlyBrace(_formatPayload("revoke_all", op))));
        }
    }

    function _execute(bytes memory req) internal returns (bytes memory) {
        (bool success, bytes memory ret) = WASMD_PRECOMPILE_ADDRESS.delegatecall(
            abi.encodeWithSignature(
                "execute(string,bytes,bytes)",
                Cw721Address,
                bytes(req),
                bytes("[]")
            )
        );
        require(success, "CosmWasm execute failed");
        return ret;
    }
