### Title
Unbounded `io.ReadAll(r.Body)` in APM tracing middleware bypasses JSON-RPC request size limit, enabling memory-exhaustion DoS of the Kaia node's public RPC endpoint - (File: `networks/rpc/http_newrelic.go` / `networks/rpc/http_datadog.go`)

### Summary
The Kaia node's HTTP JSON-RPC server enforces a body size cap (`common.MaxRequestContentLength`) via `validateRequest` and `io.LimitReader` inside `newHTTPServerConn`, but this protection is bypassed by the optional New Relic / Datadog APM tracing middleware, which reads the entire raw request body into memory with an unbounded `io.ReadAll` *before* the size-limited codec path is ever reached.

### Finding Description
`networks/rpc/http.go`'s `NewHTTPServer` builds the handler chain and, when APM tracing is enabled via environment variables, wraps the normal `srv.ServeHTTP` handler with `newNewRelicHTTPHandler` and/or `newDatadogHTTPHandler`, with the tracing handlers being the **outermost** layers that see the raw request first: [1](#0-0) 

Both tracing wrappers call the shared helper `getRPCRequests(r)` to extract the RPC method name for tagging/logging purposes, and this helper reads the *entire* HTTP body with `io.ReadAll` with no size limit whatsoever, then makes a second in-memory copy via `bytes.NewReader`: [2](#0-1) 

This is invoked unconditionally at the top of both `newNewRelicHTTPHandler` and `newDatadogHTTPHandler`: [3](#0-2) [4](#0-3) 

By contrast, the legitimate/normal request-processing path enforces a strict bound: `validateRequest` rejects requests whose `Content-Length` exceeds `common.MaxRequestContentLength`, and even for chunked/streamed bodies the codec created by `newHTTPServerConn` wraps `r.Body` in `io.LimitReader(r.Body, common.MaxRequestContentLength)`: [5](#0-4) [6](#0-5) 

However, because `getRPCRequests` runs *before* these checks (it is invoked in the outermost tracing wrapper, while `validateRequest`/`newHTTPServerConn` only execute later inside `s.ServeHTTP`), the size protections never apply to the tracing code path. Additionally, `validateRequest`'s check relies on `r.ContentLength`, which is `-1` (unknown) for chunked-encoded requests without a `Content-Length` header — meaning an attacker can stream an arbitrarily large chunked body that `io.ReadAll` will happily buffer in full regardless of any header-based limit.

This is the same bug class as the referenced WhoDB advisory (GHSA-5pf6-cq2v-23ww): an authentication/observability middleware layer performs `io.ReadAll(r.Body)` without a size cap and additionally duplicates the buffer (`r.Body = io.NopCloser(bytes.NewReader(reqBody))`), multiplying memory pressure per request.

### Impact Explanation
Any unauthenticated public RPC caller can send POST requests with very large (or chunked, unbounded) bodies to a Kaia node's JSON-RPC HTTP endpoint. If the node operator has enabled New Relic (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`) or Datadog (`DD_TRACE_ENABLED`) APM tracing — a supported, documented production observability feature, not a privileged/administrative action taken by the attacker — every such request causes the server to buffer the entire attacker-controlled body in memory (and duplicate it) with no upper bound, independent of the RPC layer's `MaxRequestContentLength` protections. Concurrent or repeated large requests can exhaust node memory and crash the process (OOM), producing a Denial of Service against the RPC endpoint used by transaction senders, dApps, and public callers — consistent with the "High" severity DoS impact of the referenced advisory.

### Likelihood Explanation
The trigger requires no authentication and no special privileges from the caller — a single HTTP POST with a large body suffices, matching the "unprivileged public RPC caller" threat model in scope. The only precondition is that the operator has enabled the New Relic or Datadog tracing feature, which is a normal, commonly-enabled operational configuration for production RPC/EN nodes and does not require the attacker to have any elevated access. Because the size check is entirely absent in this code path (not merely misconfigured), any node with tracing enabled is unconditionally exposed.

### Recommendation
1. Wrap the request body with `http.MaxBytesReader(w, r.Body, common.MaxRequestContentLength)` (or apply the same `io.LimitReader` used in `newHTTPServerConn`) in `getRPCRequests` before calling `io.ReadAll`.
2. Perform the `validateRequest`-equivalent Content-Length/size check in the outermost tracing wrappers (`newNewRelicHTTPHandler`, `newDatadogHTTPHandler`) before any body read occurs, or restructure the handler chain so `validateRequest` runs first regardless of tracing configuration.
3. Avoid duplicating the buffered body (`bytes.NewReader(reqBody)` copy) where possible; stream-parse using a size-limited reader instead of reading eagerly into memory just to extract the method name for tagging.
4. Explicitly reject/limit chunked-encoded requests with indeterminate `Content-Length` at the transport layer as well, since the existing `r.ContentLength` check does not protect against them.

### Proof of Concept
1. Deploy a Kaia node with the HTTP RPC server enabled and APM tracing turned on, e.g. `export NEWRELIC_APP_NAME=test NEWRELIC_LICENSE=test` (or `DD_TRACE_ENABLED=true`), then start the node so `NewHTTPServer` wraps the handler with `newNewRelicHTTPHandler`/`newDatadogHTTPHandler`.
2. From an unauthenticated client, send a POST request to the RPC endpoint (e.g. `/`) with a very large JSON body (hundreds of MB) or a chunked-encoded body with no `Content-Length` header, e.g.:
```python
import requests
big_payload = '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":["' + "A"*(512*1024*1024) + '"]}'
requests.post("http://<node>:8551", data=big_payload, headers={"Content-Type":"application/json"})
```
3. Because `getRPCRequests` (invoked first by the tracing wrapper) calls `io.ReadAll(r.Body)` unconditionally, the entire payload is buffered into memory (and copied again) before `validateRequest`'s size check is ever evaluated. Repeating this concurrently drives the node's memory usage up until the OS OOM-killer terminates the node process, matching the WhoDB PoC behavior.

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
