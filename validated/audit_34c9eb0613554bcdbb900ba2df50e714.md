### Title
Silent loss of `MaxGasPrice` bid-cap protection when a stale/unrecognized auction version is used for encoding - ([File: blockchain/system/auction.go], [File: kaiax/auction/eip712.go])

### Summary
This is the closest reachable analog to the reported bug class ("a caller-specified constraint parameter — LIMIT price — is silently discarded because the code hard-defaults to a mode/type that ignores it"). In Kaia's auction module, a searcher's bid can carry a `MaxGasPrice` field intended to cap the price the auction entry point is allowed to execute the bid at (v3.0 protocol feature). Both the EIP-712 signing code and the calldata-encoding code treat any version string other than the exact literal `"0.0.2"` as "v2.1", and the v2.1 path completely omits the `MaxGasPrice` field from both the signed struct hash and the on-chain calldata, exactly like the reported issue where `orderType` was hard-coded to `MARKET` regardless of the user's actual LIMIT intent.

### Finding Description
`EncodeAuctionCallData` in [1](#0-0)  only includes `MaxGasPrice` in the packed calldata when `version == auction.AuctionVersionV3`; for every other value — including an empty string, a stale cached version, or any unexpected string returned by `AUCTION_VERSION()` — it falls back to the v2.1 ABI, silently dropping `bid.MaxGasPrice` from the transaction sent to the auction entry point.

The same silent fallback happens in the EIP-712 signature path: `GetHashTypedData` in [2](#0-1)  only uses the `bidV3` struct (which includes `MaxGasPrice`) when `version == AuctionVersionV3`; any other version, including an unrecognized one, causes the code to compute the structHash using the v2.1 struct/typehash, dropping `MaxGasPrice` from what's signed.

The version value itself is fetched from the auction entry point contract via `ReadAuctionVersion` and cached in `AuctionModule`/`BidPool` state, refreshed once per block in `updateAuctionInfo` at [3](#0-2) . Because the cached version is only refreshed in `PostInsertBlock`, there is a window (e.g., right after an entry-point contract upgrade from v2.1 to v3.0, or if `ReadAuctionVersion` momentarily returns something other than the two expected literals) during which `GetBidTxGenerator` [4](#0-3)  will encode a bid that a searcher submitted with a non-nil `MaxGasPrice` using the v2.1 (no-cap) ABI and typehash — exactly mirroring the reported pattern of a user-specified execution constraint (LIMIT price) being silently coerced into the unconstrained (MARKET) behavior because of a hard string/enum comparison rather than validating that the intended constraint is actually honored.

### Impact Explanation
A searcher who explicitly sets `MaxGasPrice` on a v3.0 bid to protect themselves from being charged more than an agreed price ceiling can have that protection silently stripped if the module's cached `auctionEntryPointVersion` does not equal the exact literal `"0.0.2"` at encoding time. The resulting bid transaction executed on-chain (and the EIP-712 signature the searcher produced) no longer carries the price cap, so the auctioneer/proposer or the entry-point contract can process the bid without any enforced upper bound on gas price — an unauthorized value/fee exposure for the bidder that directly parallels the reported "LIMIT order silently becomes MARKET order" impact (Medium severity: user's stated price protection is not honored, exposing users to losses beyond what they authorized).

### Likelihood Explanation
This requires the on-chain `AUCTION_VERSION()` value and the node's locally cached `auctionEntryPointVersion` to diverge from the exact string `"0.0.2"` while a searcher submits a v3.0-style bid with `MaxGasPrice` set — most plausible during/around an entry-point contract migration/upgrade window, or if the contract reports any value the code doesn't recognize. It does not require a malicious peer, validator, or privileged actor — only an ordinary auction bidder relying on the advertised v3.0 price-cap feature during a version-transition period, keeping it within the reachable, unprivileged-caller scope required by the rules. I was not able to fully confirm from the available code how tightly the block-by-block refresh in `PostInsertBlock` bounds this window or whether additional validation elsewhere in `kaiax/auction/impl/bid_pool.go` mitigates it, so likelihood should be treated as conditional on that refresh timing, which merits further verification.

### Recommendation
- In `EncodeAuctionCallData` and `GetHashTypedData`, do not silently default to the v2.1 (no-cap) path for any version other than exactly `"0.0.2"`. Instead, explicitly branch on the two known versions and treat any other/unrecognized version as an error, refusing to encode or sign the bid rather than dropping the `MaxGasPrice` field.
- Reject or hold bids with a non-nil `MaxGasPrice` if the currently cached `auctionEntryPointVersion` is not `"0.0.2"`, rather than silently degrading them to the v2.1 format.
- Add an explicit consistency check tying bid encoding/signing to the exact on-chain version read at the time of bid execution, not a potentially stale cached value.

### Proof of Concept
Conceptual sequence (based on code review, not independently executed):
1. Auction entry point contract is at v2.1; `AuctionModule`'s cached `auctionEntryPointVersion` is `"0.0.1"`.
2. Entry point contract is upgraded on-chain to v3.0 mid-block (or version read returns something other than exactly `"0.0.2"` due to caching/race), while `PostInsertBlock`/`updateAuctionInfo` has not yet refreshed the cached version, per [5](#0-4) .
3. A searcher submits a bid intending v3.0 semantics with `MaxGasPrice` set to cap execution price.
4. `GetBidTxGenerator` calls `system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())` with the stale/unexpected version string, per [6](#0-5) ; since the version isn't exactly `AuctionVersionV3`, `EncodeAuctionCallData` [7](#0-6)  silently packs the v2.1 struct without `MaxGasPrice`.
5. The bid is executed on-chain and/or signed without the searcher's intended price cap ever being enforced, mirroring the reported LIMIT→MARKET downgrade.

// EncodeAuctionCallData encodes the bid as calldata for the active auction
// entry-point contract. version must match the on-chain AUCTION_VERSION of the
// active contract; "0.0.2" selects the v3.0 ABI (with maxGasPrice), any other
// value falls back to the v2.1 ABI.
func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {
	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}
		return abiV3.Pack("call", input)
	}

	// auction.AuctionVersionV2 or unknown version: default to v2.1 ABI.
	input := contracts.IAuctionEntryPointAuctionTx{
		TargetTxHash:  bid.TargetTxHash,
		BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
		Sender:        bid.Sender,
		To:            bid.To,
		Nonce:         new(big.Int).SetUint64(bid.Nonce),
		Bid:           bid.Bid,
		CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
		Data:          bid.Data,
		SearcherSig:   bid.SearcherSig,
		AuctioneerSig: bid.AuctioneerSig,
	}
	return abi.Pack("call", input)
}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	// 4. Read AUCTION_VERSION to pick the right EIP-712 typehash and ABI for bids targeting this entry point.
	auctionEntryPointVersion, err = system.ReadAuctionVersion(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	return true
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bid.Hash())
}
