### Title
PedPoP `Commitments::read` accepts identity commitments, making the Schnorr proof-of-knowledge vacuously forgeable - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
Analogous to `DODOApprove.claimTokens()` treating a call to a non-contract as success, `Commitments::<C>::read` in the PedPoP DKG deserializes commitment points with `Ciphersuite::read_G`, which enforces canonical encoding but does **not** reject the identity point. The round-1 proof of knowledge is then verified against `commitments[0]` — a null "callee" — where the Schnorr equation `s·G == R + c·A` degenerates to `s·G == R`, so any attacker can "prove knowledge" of a secret that does not exist.

### Finding Description
`Commitments::read` reads `t` points via `C::read_G` on the `Ciphersuite` trait (`crypto/dkg/pedpop/src/lib.rs:115-125`). The base `Ciphersuite::read_G` checks canonicity only (`crypto/ciphersuite/src/lib.rs:91-101`); the identity-rejecting variant lives on `frost::Curve::read_G` (`crypto/frost/src/curve/mod.rs:125-131`) and is not used here.

In `SecretShareMachine::verify_r1`, the PoK is batch-verified with the participant's first commitment as the public key (`crypto/dkg/pedpop/src/lib.rs:323-329`):

```rust
msg.sig.batch_verify(rng, &mut batch, l, msg.commitments[0],
  challenge::<C>(self.context, l, msg.sig.R.to_bytes().as_ref(), &msg.cached_msg));
```

`SchnorrSignature::batch_statements` checks `R + c·A − s·G == 0` (`crypto/schnorr/src/lib.rs:88-99`). With `A = identity`, the equation reduces to `R − s·G == 0`, satisfiable by anyone choosing nonce `r` and `s = r` — no discrete log of `A` is required, because `A` is null. This is the direct analog: a verification "call" against an empty target reported as success.

Downstream, `share_verification_statements` (`crypto/dkg/pedpop/src/lib.rs:430-449`) forces the attacker to send `share = 0` for the share check to pass, so the attacker completes the protocol contributing the zero polynomial — a participant counted in the threshold who bound themselves to nothing.

### Impact Explanation
The PoK is the mechanism ensuring each DKG participant is bound to a real committed polynomial. With identity commitments, a malicious participant passes the proof-of-knowledge check while proving knowledge of nothing, undermining the accountability guarantee the PoK is meant to provide (a forged proof reaching `batch_verify`/`verify`). All victim-facing paths are reachable with bytes the attacker supplies via `Commitments::read` over the DKG broadcast channel — no validator privileges required.

### Likelihood Explanation
An attacker only needs to transmit `t` identity encodings plus a trivially constructed signature (`R = r·G`, `s = r`) where the challenge is a public recomputation over `context`, `participant`, `nonce`, and `cached_msg`. Deterministic and cheap. The resulting damage is bounded — the attacker cannot cancel honest contributions (a rogue-key commitment `A0 = x·G − ΣA_j` still requires a real PoK) — consistent with Medium severity.

### Recommendation
Reject identity points in `Commitments::read`. Either require the FROST `Curve::read_G` semantics (identity rejected) for all `t` commitments, or add an explicit `is_identity` check per deserialized point in the `read_G` closure at `crypto/dkg/pedpop/src/lib.rs:115-121`.

### Proof of Concept
```rust
// Attacker (participant l) broadcasts, over the authenticated channel:
//   commitments[j] = identity encoding for all j in 0..t
//   sig = SchnorrSignature { R: C::generator() * r, s: r }  // for any r

// Honest participant executes SecretShareMachine::verify_r1:
//   challenge = challenge::<C>(context, l, R.to_bytes(), &cached_msg)
//   batch statements for the PoK:
//     (ONE, R), (challenge, commitments[0] = identity), (-s, G)
//   multiexp = R + challenge*identity - s*G = r*G - r*G = identity
//   => batch_verify returns success for a forged proof of knowledge

// In round 2 the attacker sends share = 0 (valid scalar repr) to each victim;
// share_verification_statements over all-identity commitments sums to
//   identity + (-0)*G = identity  =>  batch.verify_with_vartime_blame() passes
// KeyMachine completes; ThresholdKeys::new succeeds with the attacker holding
// a threshold share despite never committing a secret.
```
