### Title
Immature coinbase outputs bypass the maturity delay through `Scanner::scan_block` - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including `block.txdata[0]`, the coinbase transaction. [1](#0-0)  Coinbase outputs are reported as ordinary `ReceivedOutput` values, even though Bitcoin does not allow them to be spent until they are 100 blocks deep. [2](#0-1)  `SignableTransaction::multisig` validates only that the configured offset produces the received output's `script_pubkey`; it does not verify coinbase maturity. [3](#0-2) 

### Finding Description
`Scanner::scan_transaction` reports an output whenever its `script_pubkey` matches a registered script. [2](#0-1)  `Scanner::scan_block` invokes that routine for every transaction without skipping or marking the coinbase transaction. [4](#0-3) 

The resulting `ReceivedOutput` contains only an offset, `TxOut`, and `OutPoint`; it has no maturity or coinbase marker for downstream enforcement. [5](#0-4)  `SignableTransaction::new` accepts the reported outpoint and output as spendable input data. [6](#0-5)  `SignableTransaction::multisig` checks that the offset-derived key produces the prevout script, then creates a transaction-signing machine without checking whether the referenced prevout is an immature coinbase output. [3](#0-2) 

This is the same bug class as an unrestricted `withdraw` path bypassing an intended redemption delay: a public block-processing entry point exposes an immediate-use representation for funds that are subject to Bitcoin's coinbase maturity delay. [7](#0-6) 

### Impact Explanation
A block scanner or accounting component can treat an immature coinbase deposit as an available wallet output. [8](#0-7)  The wallet can then construct and threshold-sign a transaction spending that output, but Bitcoin consensus will reject the spend until the coinbase has matured for 100 blocks. [9](#0-8) 

This can cause funds to be reported as spendable when they are not, prematurely credit deposits, or make the coordinator produce transactions that cannot relay or confirm. [1](#0-0) 

### Likelihood Explanation
Any miner can create a valid coinbase output paying a scanner-tracked Taproot script, and integrations that scan new blocks will pass that transaction through `scan_block`. [1](#0-0)  The scanner's documentation acknowledges that a post-processing pass is needed, but the returned `ReceivedOutput` itself does not carry the information required to distinguish the coinbase output after it has been produced. [10](#0-9) 

### Recommendation
Make `Scanner::scan_block` skip `block.txdata[0]` by default, or make returned outputs carry spendability metadata and require maturity to be proven before `SignableTransaction` accepts them. [4](#0-3)  At a minimum, detect `Transaction::is_coinbase()` inside `scan_block` and withhold its `ReceivedOutput` until the block height confirms at least 100 additional blocks. [7](#0-6) 

### Proof of Concept
1. Register a Taproot scanner for a threshold key using `Scanner::new` or `Scanner::register_offset`. [11](#0-10) 
2. Mine or supply a block whose coinbase transaction sends value to the resulting tracked `script_pubkey`. [2](#0-1) 
3. Call `Scanner::scan_block(&block)`. [4](#0-3) 
4. `scan_block` returns a `ReceivedOutput` for the coinbase output indistinguishable from an ordinary spendable output. [8](#0-7) 
5. Pass that `ReceivedOutput` to `SignableTransaction::new` and then `multisig`; the latter accepts it when the offset-derived key matches the prevout script. [6](#0-5) [3](#0-2) 
6. The transaction-signing flow produces Taproot signature shares for the immature input, but the resulting transaction remains consensus-invalid until the coinbase matures. [9](#0-8)

  /// Construct a Scanner for a key.
  ///
  /// Returns None if this key can't be scanned for.
  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
