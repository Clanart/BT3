### Title
Distribution precompile's `rewards()` view accepts and permanently strands attached `msg.value` - ([File: precompiles/distribution/distribution.go])

### Summary
The `rewards` method of the distribution precompile (`0x...1007`) is dispatched without the `pcommon.ValidateNonPayable` guard that every other query/view method in the same `Execute` switch applies. Any caller who mistakenly (or through a poorly written integrating contract) attaches native value to a `rewards()` call will have that value pulled into the precompile's associated account by the EVM's standard value-transfer semantics, but the `rewards` handler never consumes, forwards, or refunds it — the coins are stuck. This mirrors the reported `Trading.sol openTrade` pattern: a payable-capable entry point silently swallows unexpected native-coin payments instead of reverting.

### Finding Description
In `precompiles/distribution/distribution.go`, the `Execute` dispatcher explicitly guards non-payable calls for other view/transaction paths (e.g. `WithdrawValidatorCommissionMethod` calls `pcommon.ValidateNonPayable(value)`), but the `RewardsMethod` case calls `p.rewards(ctx, method, args)` directly with no such check: [1](#0-0) [1](#0-0) 

The `rewards` implementation itself only reads and packs the query response; it never inspects or handles `value` at all: [2](#0-1) 

This omission is consistent (and explicitly documented as a known quirk) across every historical version of the precompile, including the current and all `legacy/*` snapshots, e.g. `legacy/v67/distribution.go`: [3](#0-2) 

The project's own integration-test suite documents this as a deliberate/known gap rather than an oversight that's covered by tests: [4](#0-3) [5](#0-4) 

By contrast, other precompiles apply `ValidateNonPayable` uniformly to their non-payment view methods — e.g. `pointer.AddNative` rejects any attached value even though its ABI marks the method `payable`: [6](#0-5) 

and `bank.balance`/other bank views are asserted to reject value in the integration tests: [7](#0-6) 

Functions that *do* intend to accept native payment route it through `pcommon.HandlePaymentUsei`, which explicitly refunds the payer before debiting again inside cosmos logic: [8](#0-7) 

`rewards()` has no equivalent call, so any usei/wei sent along with the call is never routed back to the caller.

### Impact Explanation
Any unprivileged EVM caller (EOA or contract) that sends native value alongside a `rewards(address)` call to the distribution precompile at `0x...1007` will have that value transferred into the precompile's backing account by the EVM's normal `CALL`-with-value handling, and it stays there — permanently lost to the sender, with no refund path in the `rewards` executor. This is a real, on-chain-reachable, concrete loss-of-funds condition for any caller who is unaware the ABI's mutability annotations for this method allow (do not reject) attached value, or who is redirected there by a buggy wallet/dApp/proxy contract.

### Likelihood Explanation
Low-to-moderate likelihood of accidental triggering (a caller has to deliberately or mistakenly set `msg.value` on a call that has no economic reason to carry value), but it requires zero privilege and no special conditions — a single `eth_sendRawTransaction` or contract-to-precompile `CALL` with nonzero value is sufficient. This exactly parallels the acknowledged severity/likelihood profile of the original `Trading.sol openTrade` finding: real but low-frequency, mitigated only by user care, not by contract logic.

### Recommendation
Add the same `pcommon.ValidateNonPayable(value)` guard to the `RewardsMethod` case in `precompiles/distribution/distribution.go` (and all other query methods that don't intend to accept payment), so that a `rewards()` call carrying nonzero `value` reverts instead of silently stranding funds — consistent with how `WithdrawValidatorCommissionMethod` and other views in the same switch, and other precompiles like `pointer.AddNative`, already behave.

### Proof of Concept
1. An associated EVM account calls the distribution precompile at `0x0000000000000000000000000000000000001007`, encoding `rewards(delegatorAddress)` with a nonzero `value` (e.g. via `eth_call`/`eth_sendRawTransaction` with `value: 10**18`).
2. The EVM's standard value-transfer step (executed before `RunAndCalculateGas`/`Execute`) credits that value to the precompile's associated Sei account balance.
3. `Execute` dispatches to `RewardsMethod` → `p.rewards(ctx, method, args)` with no `ValidateNonPayable` check, so the call succeeds and returns the rewards query result.
4. The sent value is never referenced by `rewards()`, never refunded via `HandlePaymentUsei`, and remains on the precompile's account — permanently inaccessible to the original sender through normal precompile flows.

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func HandlePaymentUsei(ctx sdk.Context, precompileAddr sdk.AccAddress, payer sdk.AccAddress, value *big.Int, bankKeeper putils.BankKeeper, evmKeeper putils.EVMKeeper, hooks *tracing.Hooks, depth int) (sdk.Coin, error) {
	usei, wei := state.SplitUseiWeiAmount(value)
	if !wei.IsZero() {
		return sdk.Coin{}, fmt.Errorf("selected precompile function does not allow payment with non-zero wei remainder: received %s", value)
	}
	coin := sdk.NewCoin(sdk.MustGetBaseDenom(), usei)
	// refund payer because the following precompile logic will debit the payments from payer's account
	// this creates a new event manager to avoid surfacing these as cosmos events
	if err := bankKeeper.SendCoins(ctx.WithEventManager(sdk.NewEventManager()), precompileAddr, payer, sdk.NewCoins(coin)); err != nil {
		return sdk.Coin{}, err
	}
	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		if hooks.OnEnter != nil {
			hooks.OnEnter(depth+1, byte(vm.CALL), evmKeeper.GetEVMAddressOrDefault(newCtx, precompileAddr), evmKeeper.GetEVMAddressOrDefault(newCtx, payer), []byte{}, GetRemainingGas(newCtx, evmKeeper), value)
		}
		if hooks.OnExit != nil {
			hooks.OnExit(depth+1, []byte{}, 0, nil, false)
		}
	}
	return coin, nil
}
