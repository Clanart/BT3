### Title
DataLayer Mirror Coins Allow Any Spend-Bundle Submitter to Force Server-Side Request Forgery via Node's HTTP Downloader - (File: chia/data_layer/data_layer_wallet.py)

### Summary
`chia/data_layer/data_layer_wallet.py`'s `create_new_mirror()` lets any wallet spend a coin to the unauthenticated `create_mirror_puzzle()` puzzle hash and attach arbitrary `urls` in the coin memo, with **no check that the caller owns or controls the referenced `launcher_id`** DataLayer store. [1](#0-0)  Any node that is merely *tracking* that store (as a non-owner subscriber) will ingest this coin's URLs into its local mirror table without validating provenance, purely because `is_launcher_tracked()` returns true. [2](#0-1)  Those attacker-supplied URLs are then merged into the node's live subscription list and used directly as the target of outbound `aiohttp` HTTP requests during background sync, with no scheme/host/port restriction (no blocking of internal/loopback/link-local addresses). [3](#0-2) [4](#0-3) 

### Finding Description
This mirrors CVE-2025-27817: an attacker-influenced URL/config value is fed unchecked into an HTTP client, resulting in SSRF. In Chia's DataLayer, the analogous untrusted "config" is the mirror-coin memo published on-chain:

1. `create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))` — a puzzle with no ownership binding to any specific `launcher_id`. [5](#0-4)  Any wallet, including one controlled by a completely unrelated party, can call `create_new_mirror(launcher_id, amount, urls, ...)` to spend one of its own coins to this puzzle hash, embedding **any store's `launcher_id`** and **any list of URLs** in the coin memo. [1](#0-0) 
2. When any full node processes this coin, `DataLayerWallet.coin_added()` extracts `launcher_id, urls = get_mirror_info(...)` from the memo and, if the local wallet is tracking that `launcher_id` (even as a passive subscriber who does not own the store), inserts the mirror record unconditionally — there is no signature, ownership, or reputation check tying the URLs to the actual store's operators. [2](#0-1) 
3. The DataLayer service's periodic sync loop calls `update_subscriptions_from_wallet()`, which pulls all such mirror URLs via `dl_get_mirrors` and writes them straight into the local `subscriptions` table as `ServerInfo` entries, with only a `rstrip("/")` string transform — no URL validation. [3](#0-2) [6](#0-5) 
4. `fetch_and_validate()` then randomly selects one of these `servers_info` entries and passes its `url` into `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a direct `aiohttp` HTTP GET/POST to that URL with no restriction on scheme, host, or port (loopback, RFC1918 private ranges, and cloud metadata endpoints like `169.254.169.254` are all reachable). [7](#0-6) [4](#0-3) 

The project's own internal documentation acknowledges mirror URLs are an "external trust input" that should never be treated as trustworthy, but confirms the enforcement boundary is limited to *content* validation (downloaded data must reconstruct the wallet-advertised root) — not to *destination* validation of the fetch itself. [8](#0-7) 

### Impact Explanation
A single spend bundle (any coin owner, no special privileges, no relationship to the target store) can force any node subscribed to/tracking a given DataLayer store to issue outbound HTTP requests to attacker-chosen destinations — internal admin endpoints, cloud metadata services, or other internal-network-only hosts reachable from the node's host. Because the request timing, target and repeated retries (with backoff via `num_consecutive_failures`/`ignore_till`) are attacker controlled, this can be used to probe internal network topology, exfiltrate limited information via response codes/headers, or pivot into services not otherwise reachable from outside — a classic SSRF impact matching CWE-918. This does not itself cause unsigned coin movement, but is a concrete network-reachable attack surface triggerable purely by an unprivileged spend.

### Likelihood Explanation
Likelihood is moderate-to-high for any operator running a DataLayer node that tracks/subscribes to third-party stores (a normal usage pattern for consuming public DataLayer data): the attack requires only a standard XCH coin spend to the known `create_mirror_puzzle()` puzzle hash with attacker-chosen memo contents, no coordination with the store owner, and is automatically picked up by the periodic `periodically_manage_data()` loop on any tracking node. [9](#0-8) 

### Recommendation
- Restrict outbound `http_download`/`get_downloader`/uploader requests to public, non-private/non-loopback/non-link-local destinations (or make this configurable and default-restrictive), analogous to Kafka's `-Dorg.apache.kafka.sasl.oauthbearer.allowed.urls` allow-list fix.
- Require mirror coin URLs to be authenticated/attributable to the store's actual controlling DID/singleton lineage before being merged into a tracking node's subscription table, or clearly separate "owner-published mirrors" from "third-party observed mirrors" with stricter vetting for the latter.
- Add an explicit URL scheme/host allow-list or SSRF-guard (e.g., resolve and reject RFC1918/loopback/link-local ranges) at the `download_data.py` HTTP client layer.

### Proof of Concept
1. Attacker (unrelated wallet, no store ownership) calls `create_new_mirror(launcher_id=<victim_store_id>, amount=1, urls=[b"http://169.254.169.254/latest/meta-data/", b"http://10.0.0.5:9999/admin"], action_scope, fee=...)`, which spends one of the attacker's own coins to `create_mirror_puzzle().get_tree_hash()` with the crafted memo, and pushes the resulting spend bundle to the mempool. [1](#0-0) 
2. Once confirmed, any node tracking `<victim_store_id>` observes the coin in `coin_added()` and stores the attacker URLs as a `Mirror` record, since only `is_launcher_tracked` is checked. [2](#0-1) 
3. On the next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` copies these URLs into the node's subscription table, and `fetch_and_validate()` eventually selects one and issues an outbound HTTP request via `http_download()` to the attacker-controlled internal target. [7](#0-6) [4](#0-3) 

Note: I was unable to fully inspect the body of `http_download()` (lines 298+ of `chia/data_layer/download_data.py`) within the available tool calls to confirm the exact aiohttp session/redirect configuration; the analysis above is based on the confirmed `download_file()` caller and the documented lack of destination validation. A Devin session with full file access would be needed to verify whether any implicit proxy/redirect restrictions exist in that function body.

    async def periodically_manage_data(self) -> None:
        manage_data_interval = self.config.get("manage_data_interval", 60)
        while not self._shut_down:
            # Add existing subscriptions
            async with self.subscription_lock:
                subscriptions = await self.data_store.get_subscriptions()

            # Track each subscription individually so one bad subscription can't block the
            # others or entry into the rest of the management cycle.
            await self.track_subscriptions(subscriptions)

            # pseudo-subscribe to all unsubscribed owned stores
            # Need this to make sure we process updates and generate DAT files
            try:
                owned_stores = await self.get_owned_stores()
            except (ValueError, aiohttp.client_exceptions.ClientConnectorError):
                # Sometimes the DL wallet isn't available, so we can't get the owned stores.
                # We'll try again next time.
                owned_stores = []
            except Exception as e:
                self.log.error(f"Exception while fetching owned stores: {type(e)} {e} {traceback.format_exc()}")
                owned_stores = []

            subscription_store_ids = {subscription.store_id for subscription in subscriptions}
            for record in owned_stores:
                store_id = record.launcher_id
                if store_id not in subscription_store_ids:
                    try:
                        # don't actually subscribe, just add to the list
                        subscriptions.insert(0, Subscription(store_id=store_id, servers_info=[]))
                    except Exception as e:
                        self.log.info(
                            f"Can't subscribe to owned store {store_id}: {type(e)} {e} {traceback.format_exc()}"
                        )

            # Optionally
            # Subscribe to all local non-owned store_ids that we can find on chain.
            # This is the prior behavior where all local stores, both owned and not owned, are subscribed to.
            if self.config.get("auto_subscribe_to_local_stores", False):
                local_store_ids = await self.data_store.get_store_ids()
                subscription_store_ids = {subscription.store_id for subscription in subscriptions}
                for local_id in local_store_ids:
                    if local_id not in subscription_store_ids:
                        try:
                            subscription = await self.subscribe(local_id, [])
                            subscriptions.insert(0, subscription)
                        except Exception as e:
                            self.log.info(
                                f"Can't subscribe to local store {local_id}: {type(e)} {e} {traceback.format_exc()}"
                            )

            work_queue: asyncio.Queue[Job[Subscription]] = asyncio.Queue()
            async with QueuedAsyncPool.managed(
                name="DataLayer subscription update pool",
                worker_async_callable=self.update_subscription,
                job_queue=work_queue,
                target_worker_count=self.subscription_update_concurrency,
                log=self.log,
            ):
                jobs = [Job(input=subscription) for subscription in subscriptions]
                for job in jobs:
                    await work_queue.put(job)

                await asyncio.gather(*(job.done.wait() for job in jobs), return_exceptions=True)

            # Do unsubscribes after the fetching of data is complete, to avoid races.
            async with self.subscription_lock:
                still_pending: list[UnsubscribeData] = []
                for unsubscribe_data in self.unsubscribe_data_queue:
                    try:
                        await self.process_unsubscribe(unsubscribe_data.store_id, unsubscribe_data.retain_data)
                    except Exception as e:
                        # A single failing unsubscribe (e.g. the wallet is unreachable) must not
                        # kill the loop or block the others; retry it on the next cycle.
                        self.log.warning(
                            f"Exception while processing queued unsubscribe for "
                            f"{unsubscribe_data.store_id}: {type(e)} {e}"
                        )
                        still_pending.append(unsubscribe_data)
                self.unsubscribe_data_queue[:] = still_pending
            await asyncio.sleep(manage_data_interval)

    async def track_subscriptions(self, subscriptions: list[Subscription]) -> None:
        for subscription in subscriptions:
            try:
                await self.wallet_rpc.dl_track_new(DLTrackNew(launcher_id=subscription.store_id))
            except aiohttp.client_exceptions.ClientConnectorError as e:
                # Wallet unreachable: retry the remaining subscriptions on the next cycle.
                self.log.warning(f"Cannot connect to the wallet to track subscriptions ({e}). Retrying next cycle.")
                return
            except Exception as e:
                # One subscription failing to track must not abort tracking of the others.
                self.log.warning(
                    f"Exception while requesting wallet track subscription {subscription.store_id}: {type(e)} {e}"
                )

    async def update_subscription(
        self,
        worker_id: int,
        job: Job[Subscription],
    ) -> None:
        subscription = job.input

        try:
            await self.update_subscriptions_from_wallet(subscription.store_id)
            await self.fetch_and_validate(subscription.store_id)
            await self.upload_files(subscription.store_id)
            await self.clean_old_full_tree_files(subscription.store_id)

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )

## Fragility Hotspots

- High-risk edits move work across DB writer transactions, `_update_confirmation_status()`, pending-root status changes, or wallet RPC calls. These boundaries encode publication and rollback assumptions.
- File-system writes for Merkle blobs, key/value blobs, and `.dat` files have TODOs around locking. Concurrent service/plugin/server access should be treated as a real consistency concern.
- Empty-root normalization is subtle and historically uneven. Audit any change touching `bytes32.zeros`, `None`, `Root.node_hash`, or proof roots with both empty and non-empty stores.
- Plugin and mirror URLs are external trust inputs. Downloaded data must continue to be verified against wallet-advertised roots, and file path/name validation must stay strict.
- DataLayer wallet code depends on singleton CLVM structure, odd singleton amounts, lineage proofs, and offer solver field names. Changes in wallet puzzle drivers or offer summaries can break this module without direct edits here.
