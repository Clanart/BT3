### Title
Unbounded stack recursion when serializing chained `google.protobuf.Any` messages to JSON - (File: `src/google/protobuf/json/internal/unparser.cc`)

### Summary
The jq CVE (`jv_dump_term` stack overflow) fails during the **dump/print** phase of a JSON document, not during initial lexing — recursive descent over an attacker-controlled tree with no depth counter. The invariant that failed was: *every recursive traversal of untrusted-depth structure must be bounded by an explicit counter, independent of any bound enforced elsewhere (e.g., at parse time)*. In this checkout, the modern C++ JSON serializer (`WriteMessage`/`WriteFields`/`WriteAny` in `src/google/protobuf/json/internal/unparser.cc`, used by `MessageToJsonStream` and `BinaryToJsonStream`) recurses through nested messages and `Any` payloads with **no depth/recursion counter at all** [1](#0-0) . Ordinary nested-message recursion is naturally bounded because the upstream binary parser enforces a recursion limit (default 100) on the whole message tree [2](#0-1) . However, each `Any` field's payload is decoded **independently**, as a brand-new top-level message with its own fresh 100-deep budget, via `WithDecodedMessage`, and then `WriteAny` immediately recurses into `WriteMessage` on that freshly decoded message [3](#0-2) . Because the parse-time recursion limit resets at every `Any` boundary, an attacker can chain many `Any`-wrapped messages (each individually shallow, e.g. depth < 100) to build an aggregate nesting depth that is effectively unbounded relative to input size, and the printer's C++ call stack grows by one frame per chained `Any` with no check to stop it.

### Finding Description
`WriteMessage<Traits>` dispatches well-known types and for `MessageType::kAny` calls `WriteAny`, which:
1. Reads the `type_url`/`value` fields of the `Any`.
2. Calls `Traits::WithDecodedMessage(any_desc, any_bytes, ...)` to parse the `value` bytes into a message of the resolved type.
3. Immediately recurses via `WriteMessage<Traits>(writer, unerased, any_desc)` on the decoded inner message [4](#0-3) .

Neither `WriteMessage`, `WriteFields`, `WriteAny`, nor the `JsonWriter`/`writer.Push()`/`writer.Pop()` indentation helpers track a recursion depth or budget — a full read of the file shows no `depth`/`recursion` symbol anywhere [5](#0-4) . The only depth control that exists in this pipeline is the parse-time `CodedInputStream` recursion limit, which is applied *per Any decode* (`Traits::WithDecodedMessage` invokes a fresh decode of just the `Any.value` bytes for that level), not across the aggregate chain. Compare this to the analogous, already-hardened C# `JsonParser`, where a `JsonReplayTokenizer` explicitly **inherits** the parent's recursion depth specifically "so that the `JsonParser.RecursionLimit` check applies across replayed Any bodies. Without this, deeply-nested `google.protobuf.Any` payloads can bypass the limit and cause a `StackOverflowException`" [6](#0-5) . That comment documents the exact bug class as previously identified and fixed for the C# *parser*; the C++ *printer* path traced above has no equivalent cross-Any depth propagation.

### Impact Explanation
Serializing a trusted-schema, well-formed protobuf `Any` chain (each level's message small and syntactically valid, individually well under any single decode's 100-frame limit) to JSON via `BinaryToJsonStream`/`MessageToJsonStream` recurses one native stack frame per `Any` level with no upper bound. A sufficiently long chain (each level requiring only a few dozen bytes to wrap the next) exhausts the process stack and crashes the consuming application — the same "stack consumption and application crash" impact class as CVE-2016-4074, occurring in a public, supported serialization API (ProtoJSON output) fed a bounded, attacker-controlled binary payload.

### Likelihood Explanation
High plausibility given the confirmed absence of any depth counter in `unparser.cc`, and given that this exact "depth resets across `Any` boundaries" pattern has already been identified and explicitly hardened against for the *parsing* direction in the C# implementation. It is very likely this asymmetry (parser hardened for chained Any, printer for chained Any left unguarded) is real, though full confirmation requires exercising the actual code path end-to-end with a concrete chained-`Any` message and a stack-overflow-detecting harness — a local reproduction was not run in this analysis (only static tracing).

### Recommendation
Thread an explicit recursion/depth budget through `WriteMessage`/`WriteFields`/`WriteAny` (and their Traits helpers) in `unparser.cc`, decrementing it at every message boundary — including at `Any` decode boundaries — and failing with an `absl::ResourceExhaustedError` (or similar) once the budget is exhausted, mirroring the fix already applied to the C# `JsonReplayTokenizer`. The same audit should be applied to `TextFormat::Printer::PrintAny` and Java's `JsonFormat.printAny`, since both recursively decode-and-print nested `Any` content without inheriting a caller-scoped depth budget across the `Any` boundary.

### Proof of Concept
Not executed against a live build in this analysis (no code-execution access here). Conceptually: construct `AnyN` = `Any{type_url: "type.googleapis.com/google.protobuf.Any", value: serialize(Any_{N-1})}`, nested to depth `N` (e.g., tens of thousands), each level only ~20–30 bytes, so total payload remains modest in size (well within normal message-size limits) while defeating any single-level 100-deep parse guard. Feed the resulting bytes to `google::protobuf::json_internal::BinaryToJsonStream` (or `MessageToJsonStream` on an equivalently constructed in-memory `Any` chain) and observe native stack growth proportional to `N` with no enforced ceiling, since `WriteAny`/`WriteMessage` recurse unconditionally per the code cited above.

template <typename Traits>
absl::Status WriteMessage(JsonWriter& writer, const Msg<Traits>& msg,
                          const Desc<Traits>& desc, bool is_top_level) {
  switch (ClassifyMessage(Traits::TypeName(desc))) {
    case MessageType::kAny:
      return WriteAny<Traits>(writer, msg, desc);
    case MessageType::kWrapper: {
      auto field = Traits::MustHaveField(desc, 1);
      if (Traits::GetSize(field, msg) == 0) {
        return WriteSingular<Traits>(writer, field);
      }
      return WriteSingular<Traits>(writer, field, msg);
    }
    case MessageType::kValue:
      return WriteValue<Traits>(writer, msg, desc, is_top_level);
    case MessageType::kStruct:
      return WriteStructValue<Traits>(writer, msg, desc);
    case MessageType::kList:
      return WriteListValue<Traits>(writer, msg, desc);
    case MessageType::kTimestamp:
      return WriteTimestamp<Traits>(writer, msg, desc);
    case MessageType::kDuration:
      return WriteDuration<Traits>(writer, msg, desc);
    case MessageType::kFieldMask:
      return WriteFieldMask<Traits>(writer, msg, desc);
    default: {
      writer.Write("{");
      writer.Push();
      bool first = true;
      RETURN_IF_ERROR(WriteFields<Traits>(writer, msg, desc, first));
      writer.Pop();
      if (!first) {
        writer.NewLine();
      }
      writer.Write("}");
      return absl::OkStatus();
    }
  }
}
