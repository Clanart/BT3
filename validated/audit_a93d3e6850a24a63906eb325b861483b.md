### Title
Frontrunning of DID sale allows seller to strip owned NFTs before/after buyer's purchase settles - ([File: chia/wallet/nft_wallet/nft_wallet.py])

### Summary
Chia's DID (Decentralized Identifier) singleton can nominally "own" a collection of NFT coins via the `owner_did` field on each NFT's ownership layer (analogous to Footium's "Club" NFT owning "player" NFTs in an escrow). When a DID is sold via an `Offer`, only the DID singleton coin itself is bundled into the atomic spend; the NFT coins that reference that DID as `owner_did` are separate coins that remain under the unilateral control of whoever holds the NFT's `p2_puzzle` key — normally the seller. This mirrors the reported FootiumEscrow issue: ownership of the "club" is checked/transferred independently from the assets it nominally holds, so the seller can move/strip the underlying assets out from under the sale.

### Finding Description
An NFT's DID association is stored as the `owner_did` field inside its `NFT_OWNERSHIP_LAYER` puzzle, set/cleared via the magic `-10` condition [1](#0-0) . Changing or clearing this association is driven by whoever controls the NFT's own `p2_puzzle`/inner puzzle spend authority — e.g. `bulk_transfer_nft`/`set_nft_did` simply issue a `generate_signed_transaction` with `new_owner=b""` (or a different DID) using the NFT coin's own signing key, not the DID coin's key [2](#0-1) . The DID coin's spend authority is a wholly separate coin/puzzle lineage (`did_wallet.py`), tracked and controlled independently of the NFTs that merely "point to" that DID's `launcher_id`.

When a DID is put up for sale through `TradeManager.create_offer_for_ids`/`respond_to_offer`, the resulting `Offer`/`WalletSpendBundle` bundles only the coin spends necessary to transfer the DID singleton (and any requested payment coins); the NFTs whose `owner_did` references that DID are not included in, or locked by, that same atomic spend bundle (see `test_nft_offer_sell_did_to_did` in `chia/_tests/wallet/nft_wallet/test_nft_1_offers.py`, which sets up a DID that owns an NFT and sells only the DID). `check_offer_validity` in `TradeManager` only verifies that the offer's own removals are unspent; it makes no assertion about the state of NFTs that are not part of the offer's coin set [3](#0-2) .

Because the seller retains full unilateral signing power over the NFT coins (their `p2_puzzle`) independent of the DID sale bundle, they can submit a separate spend bundle — before, concurrently with, or even racing the buyer's `respond_to_offer`/`take_offer` broadcast — that clears or reassigns `owner_did` on some or all of the "player" NFTs (via the `-10` magic condition, requiring no cooperation from the DID's own key). This is directly analogous to the Footium report: the "club" (DID) is transferred to the buyer as agreed, but the "players" (NFTs) that were supposed to come with it can be pulled out from under the trade by the seller's independent, unlocked control over those coins.

### Impact Explanation
A buyer who negotiates an off-chain/marketplace price for a DID under the belief that it currently is associated with (i.e., "owns") a specific set of NFTs can be scammed: the seller fulfills the on-chain offer for the DID coin alone, while frontrunning/racing a separate transaction that detaches the NFTs from that DID (setting `owner_did` to empty or to another DID they control) before the trade is observed as final. The buyer pays the full price but receives a DID identity with none (or fewer) of the expected associated NFTs. This is a concrete asset-theft/scam vector reachable by any wallet user acting as a malicious counterparty in a DID trade — no privileged access is required.

### Likelihood Explanation
Likelihood is Medium-High: it requires no special privileges — any DID owner who also independently controls the p2_puzzle keys of the NFTs "owned" by that DID (the normal, expected configuration for a single user's Club-style account) can execute this at will. It requires only that the marketplace/buyer relies on the DID→NFT association as a proxy for guaranteed bundled ownership, rather than an all-in-one atomic offer that explicitly includes all the NFT coin spends together with the DID transfer.

### Recommendation
- Marketplaces/wallets selling a "DID + its NFTs" bundle should construct a single atomic `Offer`/spend bundle that includes the DID coin spend **and** spends (or asserts non-spentness of, with matching `owner_did`) every NFT coin intended to be part of the sale, using `AssertCoinAnnouncement`/`AssertPuzzleAnnouncement` conditions tying the NFT transfers to the same bundle as the DID transfer, so the entire "club + players" package settles atomically or not at all.
- `TradeManager.check_offer_validity`/`respond_to_offer` should be extended (or documentation should clearly warn) that purchasing a bare DID singleton provides no guarantee about the current or future `owner_did` association of any NFT, since that association is mutable by whoever controls the NFT's own inner puzzle independent of DID coin control.
- Wallet UIs quoting a "DID sale" that is intended to convey a set of NFTs should require all of those NFT coins to be included as offered assets in the same `Offer`, not rely on the `owner_did` metadata as an implicit ownership guarantee.

### Proof of Concept
1. Seller creates a DID (`did_wallet.py`'s `DIDWallet`) and mints one or more NFTs with `owner_did` set to that DID (`NFTWallet.generate_new_nft` with `did_id`), as done in `test_nft_offer_sell_did_to_did`/`test_nft_offer_sell_nft` [4](#0-3) .
2. Seller lists the DID for sale to a buyer via `TradeManager.create_offer_for_ids` for the DID asset id only (no NFTs included in the offer's requested/offered payments).
3. Buyer signs and broadcasts `respond_to_offer` to take the DID.
4. Before that spend bundle is confirmed (or in the same block via a competing higher-fee bundle), the seller — who still controls the p2_puzzle keys of the "owned" NFTs — calls `NFTWallet.bulk_transfer_nft`/`set_nft_did` with `new_owner=b""` (or a different DID under seller control) on the NFTs, using the `-10` magic condition [2](#0-1) .
5. If the seller's detachment transaction confirms at or before the DID transfer, the buyer ends up owning the DID identity while the NFTs are no longer associated with it (or now belong to a different DID/wallet), even though the buyer paid the agreed price expecting the bundled NFTs.

```python
def get_new_owner_did(unft: UncurriedNFT, solution: Program) -> Literal[b""] | bytes32 | None:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(solution))
    new_did_id: Literal[b""] | bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.first().as_int() == -10:
            # this is the change owner magic condition
            atom = condition.at("rf").as_atom()
            if atom == b"":
                new_did_id = b""
            else:
                new_did_id = bytes32(atom)
    return new_did_id
```

```python
    async def check_offer_validity(self, offer: Offer, peer: WSChiaConnection) -> bool:
        all_removals: list[Coin] = offer.removals()
        all_removal_names: list[bytes32] = [c.name() for c in all_removals]
        non_ephemeral_removals: list[Coin] = list(
            filter(lambda c: c.parent_coin_info not in all_removal_names, all_removals)
        )
        coin_states = await self.wallet_state_manager.wallet_node.get_coin_state(
            [c.name() for c in non_ephemeral_removals], peer=peer
        )

        return len(coin_states) == len(non_ephemeral_removals) and all([cs.spent_height is None for cs in coin_states])
```
