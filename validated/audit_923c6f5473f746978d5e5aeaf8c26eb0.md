### Title
Unauthenticated `ReceivedOutput` deserialization permits forged deposits - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts a scalar offset, an entire claimed `TxOut`, and an arbitrary `OutPoint` from untrusted bytes without proving that the outpoint exists or that the output was discovered by `Scanner`. [1](#0-0) 

### Finding Description
The parser directly deserializes `offset` with `Secp256k1::read_F`, then consensus-decodes both `output` and `outpoint`, returning the combined object without consistency or provenance validation. [1](#0-0) 

The legitimate construction path in `Scanner::scan_transaction` only creates a `ReceivedOutput` when the transaction's `script_pubkey` matches a registered offset, and it binds the object to the containing transaction's actual TXID and output index. [2](#0-1) 

An attacker who can feed bytes to `ReceivedOutput::read` can therefore bypass that scanner-side binding and instantiate an output with a registered wallet script, an inflated amount, and a nonexistent or unrelated outpoint. [3](#0-2) 

### Impact Explanation
`ReceivedOutput::value` reports the attacker-supplied `TxOut` amount, so downstream deposit handling can report funds as received even though no corresponding spendable UTXO exists. [4](#0-3) 

`SignableTransaction::new` treats each supplied `ReceivedOutput`'s claimed value and outpoint as authoritative transaction input data. [5](#0-4) 

If the forged `script_pubkey` corresponds to the threshold key under the declared offset, `SignableTransaction::multisig` accepts the fake previous output and creates signing machines for it. [6](#0-5) 

### Likelihood Explanation
Any public interface that accepts serialized scanner outputs, synchronizes them between components, or restores them from attacker-influenced storage exposes this path directly through `ReceivedOutput::read`. [1](#0-0) 

The attack does not require compromising a validator, producing a valid Bitcoin transaction, or knowing secret material; the attacker only chooses the serialized offset, `TxOut`, and `OutPoint`. [7](#0-6) 

### Recommendation
Treat serialized `ReceivedOutput` values as authenticated trusted state, or change deserialization to require the originating `Scanner` and independently re-verify the referenced transaction output before exposing it as received funds. [8](#0-7) 

At minimum, callers should authenticate the byte stream and re-check the outpoint against confirmed chain data before using `value`, `outpoint`, or the output as a transaction input. [9](#0-8) 

### Proof of Concept
```rust
use bitcoin::{
  Amount, OutPoint, TxOut, Txid,
  consensus::Encodable,
  hashes::Hash,
};
use k256::Scalar;
use networks_bitcoin::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};

// Existing threshold keys whose group key has been TapTweak-adjusted.
let wallet_script = p2tr_script_buf(keys.group_key()).unwrap();

// Claim a nonexistent outpoint paid 10 BTC to the wallet.
let fake_outpoint = OutPoint::new(
  Txid::from_byte_array([0x42; 32]),
  0,
);
let fake_output = TxOut {
  value: Amount::from_sat(1_000_000_000),
  script_pubkey: wallet_script.clone(),
};

// ReceivedOutput serialization: scalar offset || TxOut || OutPoint.
let mut bytes = Vec::new();
bytes.extend_from_slice(Scalar::ZERO.to_bytes().as_ref());
fake_output.consensus_encode(&mut bytes).unwrap();
fake_outpoint.consensus_encode(&mut bytes).unwrap();

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 1_000_000_000);
assert_eq!(forged.outpoint(), &fake_outpoint);

// The forged object reaches transaction construction and passes the
// script/offset ownership check even though the outpoint is nonexistent.
let signable = SignableTransaction::new(
  vec![forged],
  &[],
  Some(wallet_script),
  None,
  1,
).unwrap();
assert!(signable.multisig(&keys).is_some());
```

This succeeds because deserialization accepts all three fields verbatim while the scanner path is what normally establishes that the script belongs to the wallet and that the outpoint identifies the containing transaction. [1](#0-0) [2](#0-1)
