### Title
Suspended validators remain reward-eligible in `StakingInfo` because `IsRewardEligible` ignores the `Suspended` flag - (File: kaiax/staking/impl/getter.go)

### Summary
In the permissionless-fork staking path, `parsePermissionlessCallResult` decides whether a validator's stake counts toward block/staking-reward distribution purely by `valset.NodeState(p.State).IsRewardEligible()`, which only checks `State == ValActive`. It never checks the separate `Suspended` boolean that the `valset` module maintains and uses to exclude a misbehaving/suspended validator from the consensus `Committee` (`{ValActive} - {Suspended}`). Consequently, a validator that has been `Suspended` for misbehavior (analogous to a "suspended partyB") is stripped from consensus duties but keeps receiving staking/reward allocations computed from `GetStakingInfo`, because that pipeline never subtracts the suspended set.

### Finding Description
The `valset` module explicitly models two independent concepts for a `ValActive` node: `State` and a `Suspended` boolean flag set via `MarkSuspended`. Consensus committee selection deliberately excludes suspended nodes: [4](#0-3) 

But the reward-eligibility predicate used by the staking module to build `StakingInfo` (which drives `GetRewardAddress`/`FinalizeState` reward distribution in `kaiax/reward`) only checks `State`: [2](#0-1) 

This predicate is directly consumed when parsing the AddressBookV2 multicall result to build the reward-eligible node list and their effective stake: [5](#0-4) 

The unit test `TestGetStakingInfo_Permissionless_OnlyValActive` demonstrates the filter keeps every profile whose `State == ValActive`, with no consideration of a `Suspended` flag (the mock profiles don't even carry it, since the ABv2 multicall payload used to build `StakingInfo` doesn't propagate `Suspended` at all): [6](#0-5) 

Meanwhile, the valset side treats `Suspended` as informational for violation/exiting logic but authoritative for committee/qualified-validator selection: [7](#0-6) 

`FinalizeState` in the reward module uses `ValsetModule.GetQualifiedValidators` (which does subtract `Suspended`) only to decide whether *this local node* should use a reward address for the current proposed block header, not to filter the stake-weighted reward allocation table itself, which is sourced from `StakingModule.GetStakingInfo`: [8](#0-7) 

Thus, once a validator is suspended (e.g. after a governance/violation-detection process penalizes it for misbehavior via `AddressBookV2`'s suspend mechanism), it is removed from the active `Committee` used for consensus signing, but the KIP-286/287 staking-reward calculation still lists it as a reward-eligible node with its full effective stake, letting it keep collecting staking rewards proportionally to its (unauthorized/misbehaving) stake — exactly the "restriction only partially enforced, other path still moves value" pattern from the reference report where a suspended actor keeps moving funds through a path the suspension check forgot to cover.

### Impact Explanation
A validator that has been suspended for a protocol violation (e.g. failing performance/fault thresholds tracked by the permissionless valset transition logic) is excluded from proposing/signing blocks, but continues to be counted as reward-eligible and receive staking rewards from `GetDeferredReward`/`FinalizeState`, which credits `state.AddBalance` to its reward address every block. This is an unauthorized/unintended value transfer to a sanctioned party — a form of reward-redirection/economic-penalty bypass reachable purely from state that is set by the on-chain permissionless valset transition (triggered by ordinary transaction activity feeding CFS/PFS/staking violation checks), with no privileged action required by the attacker beyond having been suspended.

### Likelihood Explanation
The `Suspended` flag is a first-class, actively maintained field (`MarkSuspended`, `ExcludeSuspended`, `Committee()`) exercised in unit tests (`TestSuspendedFallback`, `TestApplyViolationTransition_SuspendedNotExempt`), showing the suspension mechanism is a real, reachable part of the permissionless validator lifecycle. Since `IsRewardEligible` and the staking `getFromState`/`parsePermissionlessCallResult` path are the sole gate for reward eligibility and never reference `Suspended`, the discrepancy will manifest automatically any time a `ValActive` node is suspended — no special crafted transaction is needed; it is a deterministic gap in the eligibility logic.

### Recommendation
Make `IsRewardEligible` (or the call site in `parsePermissionlessCallResult`) also require `!Suspended`, or otherwise ensure the reward-eligible node set sourced by `kaiax/staking` is intersected with the `valset` module's qualified/committee set (`{ValActive} - {Suspended}`) before computing `StakingInfo.NodeIds`/`StakingAmounts`, so suspended validators lose staking rewards in the same block(s) they lose consensus duties.

### Proof of Concept
1. A `ValActive` validator accumulates a violation (e.g., low performance/fault score) that the permissionless valset transition logic (`kaiax/valset/impl/transition.go`) marks as `Suspended = true`, while its `State` remains `ValActive` (per `TestApplyViolationTransition_SuspendedNotExempt`, suspension does not immediately change `State`).
2. Consensus proceeds without this validator: `getQualifiedValidators`/`GetCommittee` exclude it via `Committee() = FilterByState(ValActive).ExcludeSuspended()`, so it cannot sign/propose blocks.
3. Each subsequent block, `RewardModule.FinalizeState` calls `GetDeferredReward`, which is built from `StakingModule.GetStakingInfo`, itself sourced via `getFromState -> MultiCallStakingInfoPermissionless -> parsePermissionlessCallResult`, filtering strictly by `State == ValActive` — the suspended validator's profile still satisfies this and is kept in `NodeIds`/`StakingAmounts` with its full effective stake.
4. `state.AddBalance(addr, amount)` in `FinalizeState` credits the suspended validator's `RewardAddr` every block, i.e. it keeps earning staking rewards while formally suspended from consensus — a concrete unauthorized value flow to a sanctioned account, analogous to the referenced partyB bypassing suspension via an unchecked path.

// parsePermissionlessCallResult converts ABv2 multicall results into StakingInfo,
// keeping only reward-eligible nodes (KIP-286); amounts are effective stake (KIP-287).
func parsePermissionlessCallResult(num uint64, profiles []multicall.Profile, amounts []*big.Int, kefAddr, kifAddr, kpfAddr common.Address, clRes clRegistryResult) (*staking.StakingInfo, error) {
	if len(profiles) == 0 {
		return emptyStakingInfo(num), nil
	}
	if len(profiles) != len(amounts) {
		logger.Error("length of profiles and amounts differ", "sourceNum", num, "profileLen", len(profiles), "amountLen", len(amounts))
		return nil, staking.ErrAddressBookResult
	}
	if len(clRes.NodeIds) != len(clRes.ClPools) || len(clRes.NodeIds) != len(clRes.StakingAmounts) {
		logger.Error("length of CL registry result fields differ", "sourceNum", num, "nodeLen", len(clRes.NodeIds), "poolLen", len(clRes.ClPools), "amountLen", len(clRes.StakingAmounts))
		return nil, staking.ErrCLRegistryResult
	}

	nodeIds := make([]common.Address, 0, len(profiles))
	stakingContracts := make([]common.Address, 0, len(profiles))
	rewardAddrs := make([]common.Address, 0, len(profiles))
	stakingAmounts := make([]uint64, 0, len(profiles))
	for i, p := range profiles {
		if !valset.NodeState(p.State).IsRewardEligible() {
			continue
		}
		nodeIds = append(nodeIds, p.NodeId)
		stakingContracts = append(stakingContracts, p.StakingContract)
		rewardAddrs = append(rewardAddrs, p.RewardAddress)
		stakingAmounts = append(stakingAmounts, new(big.Int).Div(amounts[i], big.NewInt(params.KAIA)).Uint64())
	}

// committeeWithFallback returns the committee at the given block.
// Committee = {VA} - {Suspended}.
//
// Safety fallback: when len(committee)=0 due to {ValActive} ⊆ SuspendedSet, fallback to all VA.
func committeeWithFallback(nodes valset.NodeMap) (committee valset.NodeMap, fellBack bool) {
	committee = nodes.Committee()
	if len(committee) > 0 {
		return committee, false
	}

	// ignore SuspendedSet
	return nodes.FilterByState(valset.ValActive), true
}

// getQualifiedValidators: qualified = committee = {VA} − {Suspended} (with safety fallback).
func (v *ValsetModule) getQualifiedValidators(num uint64) (*valset.AddressSet, error) {
	nodes, err := v.getNodes(num)
	if err != nil {
		return nil, err
	}
	committee, fellBack := committeeWithFallback(nodes)
	if fellBack && v.lastSuspendFallbackLog != num {
		logger.Warn("all ValActive are suspended, ignoring suspended set for committee", "num", num)
		v.lastSuspendFallbackLog = num
	}
	return valset.NewAddressSet(committee.Addresses()), nil
}

func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
}
