## Title
Wallet RPC `get_offer_summary` (default/non-advanced mode) silently hides all non-DataLayer value transfers when a DataLayer singleton is present in the offer - ([File: chia/wallet/wallet_rpc_api.py])

### Summary
The `get_offer_summary` RPC endpoint, when called with `advanced=False` (the default view intended for end users/GUI previews), returns *only* the `DataLayerSummary` if the offer's `driver_dict` contains any singleton/metadata puzzle whose `updater_hash == ACS_MU_PH`. In that case the full `OfferSummary` (offered/requested amounts, fees, additions, removals) is completely omitted from the response — analogous to CVE-2024-52271, where a document viewer displays only one rendering layer while other committed content (what actually gets executed/printed) is hidden from the user.

### Finding Description
`get_dl_offer_summary` in `chia/wallet/trade_manager.py` iterates `offer.driver_dict.values()` and returns a `DataLayerSummary` as soon as **any single** entry matches the DataLayer singleton/ACS_MU_PH pattern: [1](#0-0) 

`DataLayerWallet.get_offer_summary` only extracts information about DL singleton spends (`match_dl_singleton` + `GRAFTROOT_DL_OFFERS`) from the offer's coin spends; it does not look at, or report on, any other coin spends bundled in the same offer: [2](#0-1) 

`wallet_rpc_api.get_offer_summary` then wires this together: for the default (non-advanced) request, if `dl_summary is not None`, the response is built with **only** `data_layer_summary=dl_summary`, and the `summary` field (which would contain `offered`, `requested`, `fees`, `additions`, `removals` computed from `Offer.summary()`/`fees()`) is never populated: [3](#0-2) 

Because a single `Offer` object can bundle arbitrary numbers of asset spends (XCH, CAT, NFT, DID, DataLayer singleton) in one `WalletSpendBundle`/offer file (see `Offer.aggregate` and the general offer-construction path in `TradeManager._create_offer_for_ids`), a malicious offer maker can craft an offer that contains a legitimate-looking DataLayer store-root-update spend **plus** an unrelated large XCH/CAT payment request (or an NFT/DID transfer) in the same bundle. Any caller (local RPC client, wallet GUI, or automated script) that queries the default `get_offer_summary` (non-advanced) to preview "what am I agreeing to" before accepting will see *only* the DataLayer root/dependency information and will not be shown that the offer also moves other assets or charges a fee — the equivalent of a PDF viewer showing an unflattened preview layer while hiding the actually-committed content.

The taker can still avoid this by explicitly setting `advanced=True`, or by relying on the CLI `take_offer` path (`chia/cmds/wallet_funcs.py`), which calls `Offer.summary()` directly and is not gated by the DL check: [4](#0-3) 
But this makes the vulnerability purely a function of which UI/API surface the caller trusts — any GUI or third-party integration that uses the default `get_offer_summary` call for its "confirm before accepting" screen is exposed to the misrepresentation.

### Impact Explanation
A wallet user or offer counterparty who reviews an offer only through the default (`advanced=False`) `get_offer_summary` RPC response can be misled into accepting/taking an offer whose real economic effect (asset outflow, fee, NFT/DID transfer) is entirely undisclosed by that response, because the endpoint substitutes a narrow DataLayer-only view for the full offer summary. Since `take_offer` executes the underlying spend bundle exactly as constructed (unaffected by this display bug), a user who trusts the truncated summary can unknowingly authorize a coin movement they never saw represented — a content-spoofing-style deception leading to unauthorized/undisclosed asset transfer upon acceptance.

### Likelihood Explanation
Exploitation requires only that a malicious/careless offer maker aggregate a DataLayer offer with other asset movements into one `Offer` (bundling is directly supported via normal offer creation/aggregation flows) and that the counterparty's client queries the summary in non-advanced mode (the default value of `advanced` on `GetOfferSummary`). No privileged access, network position, or protocol-level exploit is required — it's reachable by any offer counterparty via the standard offer-review RPC path.

### Recommendation
Change `get_offer_summary` so that the DataLayer-only view is never used as a substitute for the full `OfferSummary`; either always populate `summary` alongside `data_layer_summary`, or only take the DL-only shortcut when the offer's `driver_dict` contains *exclusively* DataLayer-singleton drivers (verify there are no other non-DL asset ids/fees/additions before omitting the standard summary). At minimum, the RPC response should never hide fees or non-DL asset movement when a DL singleton is also present.

### Proof of Concept
1. Maker constructs an `Offer` via `create_offer_for_ids` that requests/offers a DataLayer singleton root update (`driver_dict` entry with `updater_hash == ACS_MU_PH`) **and** simultaneously requests, e.g., 1000 XCH or a CAT payment from the taker in the same offer (same `WalletSpendBundle`).
2. Taker receives the offer file and calls `get_offer_summary` with default parameters (`advanced` unset/False), per `wallet_rpc_api.get_offer_summary`.
3. Response contains only `data_layer_summary` (root hash/dependency info); `summary` (offered/requested/fees) is `None`, per lines 1985-2009 of `chia/wallet/wallet_rpc_api.py`.
4. Taker, seeing only the DataLayer information, accepts the offer via `take_offer`, unknowingly authorizing the additional 1000 XCH/CAT payment that was never surfaced in the default summary view.

```python
    async def get_dl_offer_summary(self, offer: Offer) -> DataLayerSummary | None:
        for puzzle_info in offer.driver_dict.values():
            if (
                puzzle_info.check_type(
                    [
                        AssetType.SINGLETON.value,
                        AssetType.METADATA.value,
                    ]
                )
                and puzzle_info.also()["updater_hash"] == ACS_MU_PH  # type: ignore
            ):
                return await DataLayerWallet.get_offer_summary(offer)
        return None
```

```python
    @staticmethod
    async def get_offer_summary(offer: Offer) -> DataLayerSummary:
        singleton_summaries = []
        for spend in offer.coin_spends():
            solution = Program.from_serialized(spend.solution)
            matched, curried_args = match_dl_singleton(spend.puzzle_reveal)
            if matched:
                try:
                    graftroot: Program = solution.at("rrffrf")
                except EvalError:
                    continue
                mod, graftroot_curried_args = graftroot.uncurry()
                if mod == GRAFTROOT_DL_OFFERS:
                    child_spend: CoinSpend = next(
                        cs for cs in offer.coin_spends() if cs.coin.parent_coin_info == spend.coin.name()
                    )
                    _, child_curried_args = match_dl_singleton(child_spend.puzzle_reveal)
                    _, singleton_structs, _, values_to_prove = graftroot_curried_args.as_iter()
                    dependencies = []
                    for struct, values in zip(singleton_structs.as_iter(), values_to_prove.as_iter()):
                        dependencies.append(
                            SingletonDependencies(
                                launcher_id=bytes32(struct.at("rf").as_atom()),
                                values_to_prove=[value.as_atom() for value in values.as_iter()],
                            )
                        )
                    singleton_summary = SingletonSummary(
                        launcher_id=bytes32(list(curried_args)[2].as_atom()),
                        new_root=bytes32(list(child_curried_args)[1].as_atom()),
                        dependencies=dependencies,
                    )
                    singleton_summaries.append(singleton_summary)
        return DataLayerSummary(offered=singleton_summaries)
```

```python
    async def get_offer_summary(self, request: GetOfferSummary) -> GetOfferSummaryResponse:
        dl_summary = None
        if not request.advanced:
            dl_summary = await self.service.wallet_state_manager.trade_manager.get_dl_offer_summary(
                request.parsed_offer
            )
        if dl_summary is not None:
            response = GetOfferSummaryResponse(
                data_layer_summary=dl_summary,
                id=request.parsed_offer.name(),
            )
        else:
            offered, requested, infos, valid_times = request.parsed_offer.summary()
            response = GetOfferSummaryResponse(
                summary=OfferSummary(
                    offered=offered,
                    requested=requested,
                    fees=uint64(request.parsed_offer.fees()),
                    infos=infos,
                    additions=[c.name() for c in request.parsed_offer.additions()],
                    removals=[c.name() for c in request.parsed_offer.removals()],
                    valid_times=valid_times.only_absolutes(),
                ),
                id=request.parsed_offer.name(),
            )
```
