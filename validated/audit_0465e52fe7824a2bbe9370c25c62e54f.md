### Title
Silent, unconfirmed rewrite of a repository's `origin` remote URL from GitHub API data enables push-target hijacking via repository renaming/reclaiming - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl` silently overwrites the local git remote URL with whatever `clone_url` the GitHub API returns for the owner/name pair it last resolved, with no user-visible event, log, or confirmation prompt. Because the owner/name used to query the API is derived purely from string-parsing the existing remote URL (not a stable repository ID), a renamed/deleted-and-recreated GitHub repository (or a reclaimed/renamed owner login) can cause Desktop to autonomously repoint the user's `origin` remote to a different, attacker-controlled repository — after which the user's future commits/pushes go to that repository without any warning.

### Finding Description
`matchGitHubRepository` in [1](#0-0)  resolves a "matched" GitHub repository purely by regex-parsing `owner`/`name` out of the current git remote URL and matching the hostname to a signed-in account — it has no notion of a stable repository identity (no repo ID comparison).

This match is used in `AppStore.matchGitHubRepository` / `repositoryWithRefreshedGitHubRepository`, which fetches the repository fresh from the GitHub API using that owner/name and then calls `updateRemoteUrl`: [2](#0-1) 

`updateRemoteUrl` then compares the freshly-fetched `apiRepo.clone_url` against the stored `gitHubRepository.cloneURL` and, if the protocol is unchanged and the local remote matches what was previously stored, silently rewrites the remote URL to whatever the API just returned — with no event, log entry, or user confirmation of any kind: [3](#0-2) 

`repositoryWithRefreshedGitHubRepository` runs automatically and frequently (on repository selection, background refresh after account changes, etc.), so the rewrite can happen without any explicit user action: [4](#0-3) 

Attack path: GitHub allows repository renames and username reclamation ("repojacking"). If the repository the user cloned is later renamed/deleted, and an attacker creates a new repository under the same now-free `owner/name` path (or GitHub itself resolves the old path to a different repo via its rename-redirect mechanism), `api.fetchRepository(owner, name)` will return the attacker's repository data, including its `clone_url`. `updateRemoteUrl` has no way to distinguish "the same repository was legitimately renamed" from "a different repository now occupies this owner/name slot" — it only checks that the *local* remote URL still matches what Desktop previously recorded, which it does, since nothing local changed. It then silently calls `gitStore.setRemoteURL(...)`, corrupting the repository's `.git/config` remote entry with the attacker's URL.

### Impact Explanation
Once the local `origin` remote is silently repointed, all subsequent `git push` operations initiated through Desktop's UI target the attacker's repository instead of the user's intended one. This is a silent corruption of the push destination — the exact class of "important state change with no notification" described in the seed report (missing events for a state-changing operation), except here the state is security-relevant (the destination of the user's code/commits). Depending on repository visibility, this can leak private source code/history to the attacker-controlled repository, and the user has no signal (no log, no event, no dialog) that the remote changed.

### Likelihood Explanation
No local access, no admin rights, and no leaked credentials are required — only that the attacker can register a GitHub repository/owner name that GitHub will resolve for the old `owner/name` path (a well-documented "repojacking" technique triggered by upstream renames or account deletion, entirely outside the victim's control). Desktop performs the vulnerable refresh routinely and non-interactively (background repository refresh, repository selection, sign-in state changes), so the victim doesn't need to take any unusual action beyond normal use of the app.

### Recommendation
- Do not silently rewrite the local remote URL from API data; at minimum, emit a user-visible notification/event and require explicit confirmation before changing `origin`, especially when the repository's identity (`id`) has changed rather than just its `clone_url`.
- Match repositories by their stable GitHub repository `id`, not just parsed `owner/name`, when deciding whether an API-fetched repository is "the same" repository the user originally added the remote for.
- Log/emit an event whenever `gitStore.setRemoteURL` is invoked as a result of an automatic background refresh, so this state change is auditable, addressing the same "missing event" gap flagged in the seed report but for a security-relevant mutation.

### Proof of Concept
1. Attacker creates a repo at `github.com/orig-owner/orig-repo` link that a victim clones with Desktop; `gitHubRepository.cloneURL` is stored as `https://github.com/orig-owner/orig-repo`.
2. `orig-owner` later deletes/renames their account or repo, freeing the `orig-owner/orig-repo` path (or the repo is renamed, and GitHub's rename-redirect returns a different owner's repo — either way this is outside the victim's control).
3. Attacker registers `orig-owner` (or `orig-repo` under the freed path) and creates a repository there.
4. Victim's Desktop periodically calls `repositoryWithRefreshedGitHubRepository` → `matchGitHubRepository` (owner/name parsed from the still-unchanged local remote) → `api.fetchRepository('orig-owner','orig-repo')`, which now returns the attacker's repo data.
5. `updateRemoteUrl` (app/src/lib/stores/updates/update-remote-url.ts:42-44) finds `protocolsMatch` true and `remoteUrlUnchanged` true (local remote still equals the previously-recorded clone URL) and `urlsMatch` false (attacker's clone_url differs, e.g. due to a different underlying repo ID even if the path string still matches, or subtly different casing/path), and calls `gitStore.setRemoteURL(...)`, rewriting `origin` to the attacker's clone URL with zero notification.
6. Victim continues working in Desktop, unaware `origin` changed, and their next push sends commits to the attacker's repository.

/** Try to use the list of users and a remote URL to guess a GitHub repository. */
export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
