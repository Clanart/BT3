### Title
Stale/renamed GitHub identity silently trusted and used to auto-rewrite the local git remote - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The bug-class from the C4 report is: a value that was valid *at creation time* (LOAN_TERM) is re-evaluated later against a *current, mutable* setting, and that current value silently drives a consequential state transition (liquidation) with no re-confirmation from the party who created the original state. The Desktop analog is `updateRemoteUrl` [1](#0-0) , which is invoked on every background/foreground fetch via `repositoryWithRefreshedGitHubRepository` [2](#0-1) . It re-derives the GitHub identity of a previously-cloned repository purely from `owner/name` strings parsed out of the existing git remote [3](#0-2) , fetches "the same" repo again from the API by that owner/name path, and — if the API's `clone_url` no longer textually matches the local remote but protocol and the previously cached `cloneURL` still line up — silently runs `git remote set-url` on `origin` with no user prompt [4](#0-3) .

### Finding Description
`matchGitHubRepository` matches solely on `hostname/owner/name` extracted from the *current* remote URL [3](#0-2) , never on GitHub's immutable numeric repository id. `urlMatchesRemote`/`urlsMatch` likewise only compare `hostname + owner + name` [5](#0-4) . Because GitHub allows both usernames/orgs and repository names to be renamed, and frees the old name for anyone to reclaim (the well-known "RepoJacking" pattern), an attacker who registers a previously-used `owner` (after the legitimate owner renamed their account) and creates a repository named identically to the original repo produces an `IAPIRepository` object that is string-identical in `owner/name` to what Desktop already has cached, yet is a completely different, attacker-controlled repository. `repositoryWithRefreshedGitHubRepository` has no guard that compares this freshly-fetched API object's stable id against the one it previously stored before accepting it via `repoStore.upsertGitHubRepository(endpoint, apiRepo)` and re-associating it with the local `Repository` [6](#0-5) . `updateRemoteUrl`'s own safety checks (`protocolsMatch`, `remoteUrlUnchanged`, `!urlsMatch`) are all string/heuristic comparisons of URLs derived from owner/name and therefore do not detect this class of substitution at all — they only guard against Desktop clobbering a *manually retargeted* remote, not against the API returning a different repository under the same name [7](#0-6) .

### Impact Explanation
Every time Desktop performs a fetch, push, or background indicator refresh (`_fetch`, `_fetchRemote`, `_fetchRefspec`, `fetchForRepositoryIndicator`, all of which call `withRefreshedGitHubRepository`/`repositoryWithRefreshedGitHubRepository`) [8](#0-7) , the app re-validates and can silently re-point which upstream is authoritative for the repository, and can rewrite `origin`'s URL with no dialog or confirmation [9](#0-8) . This satisfies the "silent corruption of what the user commits or pushes" category: the app can begin fetching/merging attacker-controlled history into the user's working copy, and — in the branch of the logic where owner/name has genuinely diverged (rename tracking) — will actually issue `git remote set-url` toward the attacker's URL without the user ever seeing or approving the new destination, after which subsequent `git push` from Desktop's UI goes to the attacker's repository.

### Likelihood Explanation
Exploitation requires a specific, narrow precondition outside Desktop's control: the original repository's `owner` (user or org) must be renamed/deleted and then reclaimed by an attacker, and the attacker must create a repository with the exact same name. This is a known, real-world attack class (RepoJacking) that has affected real repositories, so it is not purely theoretical, but it is not something an arbitrary attacker can trigger against an arbitrary victim on demand — it depends on the victim's specific tracked upstream becoming vacant. I could not confirm within the available searches whether `repositories-store.ts` (`upsertGitHubRepository`) has any additional identity check (e.g., on API `id`) that would already mitigate this before it reaches `updateRemoteUrl`; if such a check exists there, the practical severity of this specific path is significantly reduced.

### Recommendation
Track GitHub's immutable numeric repository `id` (already present on `IAPIRepository`/`IAPIFullRepository`) alongside `owner/name` when matching a local `GitHubRepository` record to freshly-fetched API data. In `repositoryWithRefreshedGitHubRepository` and `updateRemoteUrl`, refuse to auto-adopt a new `clone_url`/re-associate the `GitHubRepository` record if the returned repository's `id` differs from the previously stored `id` for that association, and instead surface a prompt asking the user to confirm the repository identity has changed before altering `origin`.

### Proof of Concept
1. Victim clones `https://github.com/originaluser/myrepo` in Desktop; Desktop stores `GitHubRepository.cloneURL = https://github.com/originaluser/myrepo` and `origin` remote points to the same URL.
2. `originaluser` renames their GitHub account (e.g., to `newname`), freeing the `originaluser` namespace.
3. Attacker registers the username `originaluser` and creates a new repository named `myrepo` (unrelated, attacker-controlled content) at `github.com/originaluser/myrepo`.
4. Victim's Desktop performs any fetch/push (`_fetch`, `_fetchRemote`, background indicator refresh). `matchGitHubRepository` re-derives `owner=originaluser, name=myrepo` from the still-unchanged local remote URL [3](#0-2) , and `api.fetchRepository('originaluser','myrepo')` now returns the attacker's repository object [10](#0-9) .
5. Because `owner/name` textually matches what Desktop already had cached, `updateRemoteUrl`'s checks pass trivially and `repoStore.upsertGitHubRepository`/`setGitHubRepository` silently re-associates the local repository with the attacker's GitHub repository object, with no numeric-id verification anywhere in the path [6](#0-5) .
6. Victim's next fetch/pull retrieves and can merge the attacker's history under the belief that it is the original, trusted upstream project.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

/**
 * Match a URL-like string to the Clone URL of a GitHub Repository
 *
 * @param url A remote-like URL to verify against the existing information
 * @param gitHubRepository GitHub API details for a repository
 */
export function urlMatchesCloneURL(
  url: string,
  gitHubRepository: GitHubRepository
): boolean {
  if (gitHubRepository.cloneURL === null) {
    return false
  }

  return urlsMatch(gitHubRepository.cloneURL, url)
}

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}
