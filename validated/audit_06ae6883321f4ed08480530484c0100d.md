### Title
DataLayer mirror URLs are attacker-controlled and fetched server-side by any subscribed node (SSRF) - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user can broadcast a spend bundle that creates a "mirror" coin tagged with an arbitrary `launcher_id` (any DataLayer store id) and arbitrary URL memos, with no requirement that the sender owns or controls that store. Every full/DataLayer node that subscribes to that store id will later read these attacker-supplied URLs from chain state and issue outbound HTTP GET requests to them automatically, with no scheme/host allow-listing. This mirrors the Whoogle SSRF bug class: user-controlled URL parameters passed unvalidated into a server-side HTTP client.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a standard coin spend to `create_mirror_puzzle()`'s puzzle hash with `memos=[[launcher_id, *(url for url in urls)]]` [1](#0-0) . Nothing in this path, in the RPC layer (`WalletRpcApi.dl_new_mirror`) [2](#0-1) , or in the CLI (`chia data add_mirror`) [3](#0-2)  requires the caller to own the `launcher_id`/store being tagged — `launcher_id` and `urls` are fully attacker-chosen values placed in on-chain coin memos.

Any node parses these mirror coins via `get_mirror_info()`, which extracts `launcher_id` and raw URL memos directly from the coin's `CREATE_COIN` condition with no validation of URL scheme, host, or target [4](#0-3) . These become `Mirror` records fetched via `dl_get_mirrors`, and `DataLayer.update_subscriptions_from_wallet()` copies the raw `mirror.urls` into the local subscription table with only a trailing-slash strip — no URL/IP validation at all [5](#0-4) .

When the periodic sync loop later downloads store data (`fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`), the DataLayer service issues an outbound `aiohttp` GET to `server_info.url + "/" + filename` with no destination restriction [6](#0-5) , and `get_downloader()` similarly POSTs to arbitrary plugin URLs derived from mirror data [7](#0-6) . This is functionally identical to the Whoogle bug: an unauthenticated/unprivileged actor supplies a URL, which a privileged server process fetches without validating destination, enabling requests against internal-only endpoints (localhost services, cloud metadata endpoints, internal admin panels) reachable from the DataLayer host.

### Impact Explanation
This is a Server-Side Request Forgery reachable by any actor who can submit a spend bundle (no special permission, no store ownership required) — they simply need to spend some XCH to create a mirror coin referencing a victim's `launcher_id`. Every node that runs a DataLayer service and subscribes to (or owns) that store will automatically perform outbound HTTP(S) requests to attacker-chosen URLs, including internal network addresses, cloud provider metadata services, or other locally-bound services (harvester/farmer/wallet RPC ports if unauthenticated ports exist), potentially exposing sensitive data or leveraging internal-only APIs. Because this touches network requests made by DataLayer operator infrastructure, this is a Medium-High severity issue.

### Likelihood Explanation
Likelihood is high: creating a mirror coin costs only a mempool fee and a coin of any amount (even 0), requires no relationship to the target store, and the DataLayer sync loop is fully automated (`periodically_manage_data()`), meaning victim nodes will fetch attacker URLs without any user interaction beyond having subscribed to (or owning) the targeted store id.

### Recommendation
- Validate mirror/subscription URLs before they are persisted or used for outbound requests: enforce an allow-list of schemes (`http`/`https` only, reject `file://`, etc.), and optionally block requests to private/loopback/link-local IP ranges (e.g., RFC1918, `169.254.0.0/16`, `127.0.0.0/8`) unless explicitly permitted via configuration for testing.
- Apply the same validation in `update_subscriptions_from_wallet()`, `http_download()`, and `get_downloader()`/plugin download requests before dispatching any outbound request.
- Consider requiring explicit operator opt-in/allow-listing of mirror URLs rather than trusting all on-chain mirror memos automatically.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (or `chia data add_mirror`) with `launcher_id` set to a victim's DataLayer store id and `urls=["http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<internal-port>/...`), paying only the coin amount/fee [2](#0-1) .
2. The transaction confirms on-chain; any DataLayer node subscribed to (or owning) that `launcher_id` calls `dl_get_mirrors`/`update_subscriptions_from_wallet` and stores the malicious URL as a valid server for that store [5](#0-4) .
3. On the next sync cycle, `fetch_and_validate()`/`http_download()` issues a GET request to the attacker-controlled URL from the victim node's network context [6](#0-5) , completing the SSRF.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```
