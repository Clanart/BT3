### Title
Reward transfers in `BaseRewardPool`/`BaseRewardPoolV2` can revert on blacklist-capable reward tokens, permanently blocking a user's withdrawal and unclaimed rewards - (File: `rewards/BaseRewardPool.sol`, `rewards/BaseRewardPoolV2.sol`, `rewards/MasterMagpie.sol`)

### Summary
`BaseRewardPool.getReward`/`BaseRewardPoolV2.getReward` unconditionally push-transfer every queued reward token to the caller's receiver address. These functions are invoked as part of the normal, unprivileged `withdraw`/`multiclaim` flow through `MasterMagpie`. If any registered reward token is a blacklist-capable token (e.g. a USDC-like token) and the staker's address gets blacklisted by that token, the `safeTransfer` reverts and reverts the entire enclosing transaction - including the user's staking-token withdrawal, which is bundled in the same call.

### Finding Description
`getReward` loops over all `rewardTokens` and calls `IERC20(rewardToken).safeTransfer(_receiver, reward)` unconditionally for any token with a nonzero pending balance: [1](#0-0) [2](#0-1) 

This function is `onlyMasterMagpie`-gated, so it is reached from `MasterMagpie`'s internal harvesting logic, which is exercised by ordinary user transactions such as withdrawing staked LP tokens. `_withdraw` calls `_harvestAndUnstake`, which harvests MGP and calls the base-rewarder before actually transferring the staking token back to the user: [3](#0-2) 

Because the reward-harvest call and the principal-transfer call are bundled in a single transaction with no isolation (no try/catch, no per-token skip), a revert on any single reward token's transfer reverts the whole transaction. If the protocol's reward-token list ever includes a token with blacklist functionality (USDC and several other real-world stablecoins implement this), any staker who is blacklisted by that token can never successfully call `withdraw`/`multiclaim` again, because the loop will always attempt (and fail) to transfer that token to them, even though they are only trying to withdraw an unrelated staking token or claim other reward tokens.

The same unconditional-transfer pattern also exists in `_multiClaim`'s per-pool reward claiming path in `MasterMagpie.sol`: [4](#0-3) 

### Impact Explanation
A blacklisted user is permanently unable to withdraw their staked principal (LP/staking tokens) and permanently unable to claim any of their other, non-blacklisted pending rewards, because the entire transaction (harvest + withdraw, or multi-token claim) reverts due to the one problematic reward-token transfer. This satisfies "permanent freezing of funds" and "permanent freezing of unclaimed yield" for the affected user, with no on-chain workaround exposed by the contracts (there is no reward-skip, no pull-based claim, and no way to exclude a single reward token from the atomic harvest-then-withdraw flow).

### Likelihood Explanation
This is triggered purely by normal, unprivileged usage (`withdraw`, `multiclaim`, `multiclaimFor`) combined with an external, pre-existing condition (the user being blacklisted by a reward token's issuer, such as USDC). No admin or governance misbehavior is required — the reward-token list is set through legitimate `queueNewRewards` configuration that is expected/likely to include popular stablecoins as reward tokens.

### Recommendation
Decouple reward distribution from the principal withdrawal/claim flow, or make each reward-token transfer fault-tolerant:
1. Wrap each `safeTransfer` in `getReward`/`_sendReward` in a low-level call with try/catch, and on failure, keep the reward accounted for the user (do not zero out `userRewards`) so failures for one token don't block others or the withdrawal.
2. Alternatively, switch to a pull-based claim pattern for rewards (separate from `withdraw`) so a failing reward-token transfer cannot block the return of the user's staked principal.

### Proof of Concept
1. Protocol registers a blacklist-capable stablecoin (e.g. USDC) as a reward token for a pool via `queueNewRewards`, and it accrues pending rewards for user Alice: [5](#0-4) .
2. Alice's address later gets blacklisted by the USDC contract (independent of the protocol).
3. Alice calls `MasterMagpie.withdraw`/`multiclaim` for her staking token. Internally this calls `_harvestAndUnstake` → `_harvestBaseRewarder` → `BaseRewardPool(V2).getReward`, which attempts `IERC20(USDC).safeTransfer(alice, pendingUSDC)`: [6](#0-5) [7](#0-6) .
4. The USDC transfer reverts because Alice is blacklisted, reverting the entire transaction — Alice's staking-token principal is never returned and none of her other pending rewards are paid, indefinitely, for as long as she remains blacklisted (or forever if she has no way to be unblacklisted).

    function getReward(address _account, address _receiver)
        override

        updateReward(_account)
        returns (bool)
    {
        uint256 length = rewardTokens.length;
        for (uint256 index = 0; index < length; ++index) {
            address rewardToken = rewardTokens[index];
            uint256 reward = userRewards[rewardToken][_account]; // updated during updateReward modifier
            if (reward > 0) {
                userRewards[rewardToken][_account] = 0;
                IERC20(rewardToken).safeTransfer(_receiver, reward);
                emit RewardPaid(_account, _receiver, reward, rewardToken);
            }
        }

        return true;
    }

        if (!_isVlMgp)

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
