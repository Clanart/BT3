Based on extensive searching across the sei-chain codebase, I could not find a valid reachable analog to CVE-2025-13654 (the `duc` `buffer_get` stack buffer overflow caused by an underflow condition evaluating true).

The relevant buffer/length-parsing code paths I examined in the in-scope attack surface are hardened against this exact bug class:

- The ABI decode-cost helpers in `precompiles/common/decode_cost.go` (`abiLengthPrefix`, `abiTuplePointsTo`, `walk`) explicitly use `big.Int` arithmetic and `BitLen() > 63` checks specifically to avoid the integer overflow/underflow trap that would let an offset+length calculation wrap and pass a subsequent bounds check. [1](#0-0) 
- The protobuf-generated `skip*`/`Unmarshal` functions across the codebase (bank, oracle, gov, EVM types, etc.) consistently guard length fields with `if length < 0`, `if (skippy < 0) || (iNdEx+skippy) < 0`, and post-index bounds checks before slicing, which is the exact defensive pattern that would have prevented the `duc`-style underflow. [2](#0-1) 
- Fixed-length precompile inputs (e.g., the P256 verify precompile) check `len(input) != p256VerifyInputLength` before any fixed-offset slicing, so there is no length-derived subtraction that can underflow.

func abiLengthPrefix(index int, output []byte) (start int, length int, ok bool) {
	if index < 0 || index+32 > len(output) {
		return 0, 0, false
	}
	bigOffsetEnd := new(big.Int).SetBytes(output[index : index+32])
	bigOffsetEnd.Add(bigOffsetEnd, big.NewInt(32))
	outputLength := big.NewInt(int64(len(output)))
	if bigOffsetEnd.Cmp(outputLength) > 0 || bigOffsetEnd.BitLen() > 63 {
		return 0, 0, false
	}
	offsetEnd := int(bigOffsetEnd.Uint64()) //nolint:gosec // bigOffsetEnd fits int64 (BitLen<=63 checked above)
	lengthBig := new(big.Int).SetBytes(output[offsetEnd-32 : offsetEnd])
	totalSize := new(big.Int).Add(bigOffsetEnd, lengthBig)
	if totalSize.BitLen() > 63 || totalSize.Cmp(outputLength) > 0 {
		return 0, 0, false
	}
	return offsetEnd, int(lengthBig.Uint64()), true //nolint:gosec // lengthBig <= totalSize, which is BitLen<=63 checked above
}
