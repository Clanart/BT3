Based on the investigation, I could not identify a valid Protobuf analog to CVE-2016-8596.

**Why the libcsp bug class doesn't transfer:**

CVE-2016-8596 is a classic embedded-C bug: `csp_can_process_frame` copies attacker-controlled CAN payload bytes into a fixed-size reassembly buffer without validating the cumulative length against the buffer's capacity, causing a stack/heap buffer overflow with attacker-controlled overwrite content — a missing length-vs-buffer-capacity check before a raw copy.

**What I checked in this checkout:**

Every place in Protobuf's parsing paths that performs a fixed-size-buffer copy driven by attacker-controlled length includes an explicit bounds check that either clamps the copy or rejects the input before the copy happens:

- In C++'s `EpsCopyInputStream`, the packed-varint patch buffer copy is guarded by `ABSL_CHECK_LE(size - chunk_size, kSlopBytes)` before the `memcpy` into `char buf[kSlopBytes + 10]`. [1](#0-0) 
- The general invariant of `EpsCopyInputStream`/`upb_EpsCopyInputStream` guarantees `kSlopBytes` of valid overlap so fixed-size reads never run past a validated boundary, by design. [2](#0-1) [3](#0-2) 
- `WireFormatLite::ReadPackedFixedSizePrimitive` explicitly checks `new_bytes <= buffer_size` before taking the fast pre-allocated `ReadRaw` path, and falls back to an unchecked-allocation-safe element-by-element loop otherwise.

// [---------------------------------------------------------------]

//                    [------------------------....] chunk 2
//                                    chunk 3 [------------------..**]
//                                                      chunk 4 [--****]
// Here '-' mean the bytes of the stream or chunk and '.' means bytes past the
// chunk that match up with the start of the next chunk. Above each chunk has
// 4 '.' after the chunk. In the case these 'overflow' bytes represents bytes
// past the stream, indicated by '*' above, their values are unspecified. It is
// still legal to read them (ie. should not segfault). Reading past the
// end should be detected by the user and indicated as an error.
//
// The reason for this, admittedly, unconventional invariant is to ruthlessly
// optimize the protobuf parser. Having an overlap helps in two important ways.

// importantly, the protobuf wireformat is such that reading a key/value pair is
