### Title
PedPoP reveals an ECDH blame key before authenticating the encrypted share - ([File: crypto/dkg/pedpop/src/lib.rs](crypto/dkg/pedpop/src/lib.rs))

### Summary
`KeyMachine::calculate_share` returns an `EncryptionKeyProof` when decrypted share bytes are not a canonical scalar, before it verifies the sender’s per-message proof of possession. The PoP is only queued for batch verification inside `Encryption::decrypt`, while the ECDH point and its DLEq proof are generated immediately and can escape through `PedPoPError::InvalidShare`. This allows a party supplying an untrusted `EncryptedMessage` to obtain the recipient’s ECDH key for an attacker-selected or replayed ephemeral key, then use that key to decrypt the corresponding ciphertext. [1](#0-0) [2](#0-1) 

### Finding Description
`EncryptedMessage` contains an ephemeral `key`, a Schnorr `pop`, and the encrypted payload. The comments explicitly note that the PoP is required to prevent an observer from reusing Alice’s ephemeral key and causing Bob to reveal `bX`, which would disclose Alice’s encrypted message. [3](#0-2) 

`Encryption::decrypt` does not synchronously authenticate that proof. It queues `msg.pop` into a `BatchVerifier`, immediately computes `ecdh(self.enc_key, msg.key)`, decrypts the ciphertext, and returns an `EncryptionKeyProof` containing the ECDH point and a DLEq proof that it was derived from the recipient’s static encryption key and `msg.key`. [4](#0-3) 

`calculate_share` then deserializes the decrypted bytes as a scalar. If deserialization fails, it returns `InvalidShare` with `Some(blame)` immediately; the batch verification containing the `Decryption(l)` PoP statement is not reached until after all shares have been decoded and queued. [5](#0-4) 

The security check therefore runs after the security-sensitive disclosure. A malformed or unauthenticated message can induce the recipient to produce a proof for `self.enc_key * msg.key` even though the sender has not proven knowledge of the ephemeral key or bound it to the submitted ciphertext. The intended failure behavior is observable later in `decrypt_with_proof`, which rejects an invalid PoP before accepting a decryption-key proof. [6](#0-5) 

### Impact Explanation
An attacker who can feed an `EncryptedMessage` to a participant’s `calculate_share` can obtain a valid serialized `EncryptionKeyProof` for an ephemeral key of their choosing. Since the ChaCha20 encryption key is deterministically derived from the ECDH point, disclosure of that point is sufficient to decrypt every ciphertext encrypted under that ephemeral key. [7](#0-6) 

If the attacker first observes an honest sender’s `EncryptedMessage` to the victim, they can submit a modified message that reuses the same `key` but has malformed ciphertext/PoP and decrypts to non-canonical scalar bytes. The victim returns the ECDH proof before detecting the invalid PoP. The attacker then derives the ChaCha20 stream from the disclosed ECDH point and decrypts the original honest share ciphertext, recovering another participant’s secret share. Recovery of a threshold participant’s share reduces the DKG’s threshold security; repeated use against distinct participants can contribute toward reconstructing the group secret.

This is a concrete key-share disclosure path, not merely an incorrect blame result. The returned `EncryptionKeyProof` exposes `key` and proves it is the ECDH output for the victim’s encryption key and the supplied `msg.key`. [8](#0-7) 

### Likelihood Explanation
The reachable input is a peer-supplied `EncryptedMessage` in the `shares` map accepted by `calculate_share`. `EncryptedMessage::read` parses all fields from untrusted bytes without authenticating them. [9](#0-8) 

The exploit does not require the attacker to know the victim’s static encryption secret, the sender’s ephemeral secret, or a valid PoP for the forged ciphertext. The only exploit-specific requirement is that decryption of the crafted ciphertext produce bytes rejected by `C::F::from_repr`, causing the early `InvalidShare` return before batch verification. For Ristretto-style scalar encodings, random decrypted bytes will commonly be non-canonical; the attacker can also retry with independent malformed ciphertexts.

### Recommendation
Authenticate `msg.pop` before deriving or exposing `EncryptionKeyProof`. In particular:

- Make `Encryption::decrypt` return `Result` and synchronously verify the PoP before computing `ecdh` or constructing `EncryptionKeyProof`; or
- Buffer the decrypted plaintext and proof internally, execute `batch.verify_with_vartime_blame()`, and only return an `EncryptionKeyProof` for a participant whose PoP has already passed; on a `BatchId::Decryption` failure, return no decryption key material.
- Keep the existing check that malformed plaintext does not expose blame, but order it after successful message authentication.
- Add a regression test where a forged `EncryptedMessage` reuses an honest `key`, has an invalid PoP and ciphertext that decrypts to non-canonical bytes, and assert that `calculate_share` returns `InvalidShare { blame: None }` or another error without serializable ECDH material.

### Proof of Concept
Conceptual reproduction for a Ristretto-backed PedPoP instance:

```rust
// honest_msg is an EncryptedMessage<C, SecretShare<C::F>> observed from sender S to victim V.
// The attacker controls the message supplied to V for participant S.

let mut forged = honest_msg.clone();

// Reuse S's ephemeral ECDH public key, but replace the ciphertext and PoP.
// The concrete mutation can be produced through EncryptedMessage::read/write or a
// serialization-level rewrite.
forged.key = honest_msg.key;
forged.msg = invalid_ciphertext_bytes; // decrypts under reused key to non-canonical F bytes
forged.pop = invalid_schnorr_pop;      // does not prove ownership/binding

let err = victim_key_machine
  .calculate_share(&mut rng, shares_with_forged_msg_for_sender_s)
  .unwrap_err();

// Current behavior:
let PedPoPError::InvalidShare { participant, blame: Some(proof) } = err else {
  panic!("expected premature blame disclosure");
};
assert_eq!(participant, sender_s);

// proof.key is now the ECDH output victim_enc_secret * honest_msg.key.
// Reconstruct the same cipher used by encryption.rs and decrypt the original payload:
let plaintext = cipher(context, &proof.key).apply_keystream(honest_msg.msg.clone());
let recovered_share = C::F::from_repr(plaintext.0).unwrap();
```

The decisive ordering is: `decrypt` queues the PoP and immediately returns the ECDH proof; `calculate_share` returns that proof on malformed scalar bytes before the queued PoP is verified. [4](#0-3) [10](#0-9)

```rust
  pub fn calculate_share<R: RngCore + CryptoRng>(
    mut self,
    rng: &mut R,
    mut shares: HashMap<Participant, EncryptedMessage<C, SecretShare<C::F>>>,
  ) -> Result<BlameMachine<C>, PedPoPError<C>> {
    validate_map(
      &shares,
      &self.params.all_participant_indexes().collect::<Vec<_>>(),
      self.params.i(),
    )?;

    let mut batch = BatchVerifier::new(shares.len());
    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {
      let (mut share_bytes, blame) =
        self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
      let share =
        Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0)).ok_or_else(|| {
          PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }
        })?);
      share_bytes.zeroize();
      *self.secret += share.deref();

      blames.insert(l, blame);
      batch.queue(
        rng,
        BatchId::Share(l),
        share_verification_statements::<C>(self.params.i(), &self.commitments[&l], share),
      );
    }
    batch.verify_with_vartime_blame().map_err(|id| {
      let (l, blame) = match id {
        BatchId::Decryption(l) => (l, None),
        BatchId::Share(l) => (l, Some(blames.remove(&l).unwrap())),
      };
      PedPoPError::InvalidShare { participant: l, blame }
    })?;
```

```rust
/// without side effects.
#[derive(Clone, Zeroize)]
pub struct EncryptedMessage<C: Ciphersuite, E: Encryptable> {
  key: C::G,
  // Also include a proof-of-possession for the key.
  // If this proof-of-possession wasn't here, Eve could observe Alice encrypt to Bob with key X,
  // then send Bob a message also claiming to use X.

  // While Eve can still reuse their own keys, causing Bob to leak all messages by revealing for
  // any single one, that's effectively Eve revealing themselves, and not considered relevant.
```

```rust
fn ecdh<C: Ciphersuite>(private: &Zeroizing<C::F>, public: C::G) -> Zeroizing<C::G> {
  Zeroizing::new(public * private.deref())
}

// Each ecdh must be distinct. Reuse of an ecdh for multiple ciphers will cause the messages to be
// leaked.
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
```

```rust
/// A proof that the provided encryption key is a legitimately derived shared key for some message.
#[derive(Clone, PartialEq, Eq, Debug, Zeroize)]
pub struct EncryptionKeyProof<C: Ciphersuite> {
  key: Zeroizing<C::G>,
  dleq: DLEqProof<C::G>,
}

impl<C: Ciphersuite> EncryptionKeyProof<C> {
  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<Self> {
    Ok(Self { key: Zeroizing::new(C::read_G(reader)?), dleq: DLEqProof::read(reader)? })
  }

  pub fn write<W: io::Write>(&self, writer: &mut W) -> io::Result<()> {
    writer.write_all(self.key.to_bytes().as_ref())?;
    self.dleq.write(writer)
  }

  pub fn serialize(&self) -> Vec<u8> {
    let mut buf = vec![];
    self.write(&mut buf).unwrap();
    buf
  }
```

```rust
  pub(crate) fn decrypt<R: RngCore + CryptoRng, I: Copy + Zeroize, E: Encryptable>(
    &self,
    rng: &mut R,
    batch: &mut BatchVerifier<I, C::G>,
    // Uses a distinct batch ID so if this batch verifier is reused, we know its the PoP aspect
    // which failed, and therefore to use None for the blame
    batch_id: I,
    from: Participant,
    mut msg: EncryptedMessage<C, E>,
  ) -> (Zeroizing<E>, EncryptionKeyProof<C>) {
    msg.pop.batch_verify(
      rng,
      batch,
      batch_id,
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    );

    let key = ecdh::<C>(&self.enc_key, msg.key);
    cipher::<C>(self.context, &key).apply_keystream(msg.msg.as_mut().as_mut());

      msg.msg,
      EncryptionKeyProof {
        key,
        dleq: DLEqProof::prove(
          rng,
          &mut encryption_key_transcript(self.context),
```
