### Title
Symlinked `.claude/hookify.*.local.md` bypasses repo workspace confinement, letting hook load/parse rules from arbitrary filesystem paths - ([File: plugins/hookify/core/config_loader.py])

### Finding Description
`load_rules()` discovers rule files with a plain glob over the working directory: `glob.glob(os.path.join('.claude', 'hookify.*.local.md'))`, and then calls `load_rule_file(file_path)` for each match [1](#0-0) . `load_rule_file` opens the path directly with `open(file_path, 'r')` and parses whatever content comes back as trusted rule frontmatter [2](#0-1) . Neither function calls `os.path.realpath`, checks `os.path.islink`, or otherwise verifies that the resolved target stays under the repository/`.claude` root. `glob.glob` matches on the symlink's *name* inside `.claude/`, not its target, so a symlink checked into the repository (e.g. `.claude/hookify.evil.local.md -> ../../other-repo/.claude/hookify.secret.local.md` or any absolute path readable by the victim's user) is picked up, opened, and followed by the standard `open()` call, which transparently dereferences symlinks. If the target content happens to have the same `---` frontmatter shape (very plausible if the attacker targets another `hookify.*.local.md` file from a sibling checkout, which is guaranteed to be in that format), `extract_frontmatter`/`Rule.from_dict` will successfully parse it into a fully-trusted `Rule`, including its `message`, `conditions`, and `action` (`warn`/`block`) [3](#0-2) . That `Rule` is then evaluated by `RuleEngine.evaluate_rules`, and on match its `message` is concatenated directly into the `systemMessage` (and, for blocking rules, into `permissionDecision: "deny"` / `reason`) returned by the hook [4](#0-3) . This output is produced by `userpromptsubmit.py` (and the analogous `pretooluse.py`/`posttooluse.py`/`stop.py` hooks) and fed back into Claude Code's hook pipeline / model context [5](#0-4) . There is no allowlist, no repo-root confinement check, and no rejection of symlinked rule files anywhere in this path.

### Impact Explanation
An attacker who can only contribute ordinary repository content (a committed symlink) can make the hookify hook read and trust content that lives entirely outside the cloned repository's boundary - e.g., another project's `.claude/hookify.*.local.md` checked out alongside, or any other world/user-readable file whose content happens to parse as frontmatter. The resulting `Rule.message`/`action` is injected into `systemMessage`/`permissionDecision` that Claude Code surfaces to the model/user, i.e., cross-workspace trust-boundary bypass and prompt-injection/content-disclosure via a rule engine that is supposed to be scoped to the current repository only. It can also be used to force spurious `permissionDecision: "deny"` (denial of unrelated tool actions) driven by content the current repo does not own.

### Likelihood Explanation
Exploitation only requires committing a single symlink file into the victim's cloned repository - no elevated privileges, no social engineering beyond a normal contribution/clone, and no dependency on any other bug. The main practical constraint is that the followed target must parse as valid `---` frontmatter for the disclosure/injection to manifest as a matched rule (trivially satisfiable by pointing at another `hookify.*.local.md`-style file, which is a realistic multi-repo/monorepo layout), but even a failed parse still proves the confinement bypass (arbitrary file read attempt via `open()`), which is reproducible deterministically.

### Recommendation
In `load_rules()`/`load_rule_file()`, resolve each candidate path with `os.path.realpath()` and reject (skip with a warning) any file whose resolved path is not a descendant of the resolved `.claude` directory / repo root. Additionally reject or refuse to follow symlinks outright (e.g., `os.path.islink(file_path)` check, or open with `O_NOFOLLOW` where supported) before parsing, so a `hookify.*.local.md` symlink pointing outside the workspace is never read.

### Proof of Concept
Integration test:
1. Create a temporary repo directory `repo/` with `repo/.claude/`.
2. Create an "external" file `outside/.claude/hookify.secret.local.md` containing valid frontmatter, e.g.:
```
---
name: leaked-rule
enabled: true
event: prompt
pattern: ".*"
action: block
---
SECRET CONTENT FROM OUTSIDE REPO
```
3. Inside `repo/.claude/`, create `hookify.evil.local.md` as a symlink to `../../outside/.claude/hookify.secret.local.md`.
4. `os.chdir('repo')` and call `config_loader.load_rules(event='prompt')`.
5. Assert either (a) the returned rule list is empty / the symlinked file is skipped, because `load_rule_file` refused a symlink resolving outside `repo/`, or (b) if a `Rule` is returned, assert its `message`/`action` cannot ever be attributed to `repo`'s own trusted content and does not reach `RuleEngine.evaluate_rules` output (`systemMessage`/`permissionDecision`) for inputs unrelated to `outside/`.
Current behavior: `load_rules()` returns a `Rule(name='leaked-rule', action='block', message='SECRET CONTENT FROM OUTSIDE REPO', ...)`, and feeding any prompt into `RuleEngine.evaluate_rules([rule], {...})` yields `{"hookSpecificOutput": {"permissionDecision": "deny"}, "systemMessage": "**[leaked-rule]**\nSECRET CONTENT FROM OUTSIDE REPO"}` — demonstrating the confinement bypass.

    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""

        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:

            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event

            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:

            )]

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule
