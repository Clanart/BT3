### Title
Gasless swap admission check relies on manipulable AMM spot price, enabling fee-delegation/lending abuse via same-block price manipulation - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `kaiax/gasless` module (KIP-247) validates a `GaslessSwapTx` by querying `GaslessSwapRouter.GetAmountIn(token, minAmountOut)`, which returns the token amount required based on the *live spot reserves* of the underlying DEX pool (Uniswap V2-style, no TWAP/oracle). This is the same bug class as the referenced report ("using spot price could lead to price manipulation") applied to Kaia's gasless fee-delegation flow: an attacker can shift the pool's reserves within the same block to affect the outcome of the swap that is supposed to repay the block proposer's advanced gas (`LendTx`), while the `LendTx` amount is fixed independently of the swap's real-time execution price.

### Finding Description
`GaslessModule.checkBalanceForSwap` (kaiax/gasless/impl/tx_pool.go:107-142) computes the “required” `amountIn` for a declared `minAmountOut` by calling the on-chain `GaslessSwapRouter.GetAmountIn`: [1](#0-0) 

`GetAmountIn` (bound via `contracts/bindings/kip247/GaslessSwapRouter.go`) is implemented by the `GaslessSwapRouter` contract, which looks up the DEX pair for the token via `GetDEXInfo`/`DexAddress` and computes the required input using the pool's *current* reserves (the classic `xy=k` spot-price formula used by Uniswap V2 style AMMs), exactly analogous to `StableOracleDAI`/`StableOracleWBGL` reading `ethOracle`'s spot price in the referenced report. There is no TWAP or external price feed involved.

Both:
1. `GetCheckBalance()` (used for tx-pool admission, `kaiax/gasless/impl/tx_pool.go:62-72`), and
2. the actual on-chain `swapForGas` execution (called by `GaslessSwapRouter`, which itself swaps through the underlying Uniswap V2 Router/Factory, `contracts/bindings/uniswap/router/UniswapV2Router02.go`), 

depend on the pool's spot reserves at the time each is evaluated. Meanwhile, the `LendTx` that funds the user's gas is generated deterministically from tx fees alone (`lendAmount`/`repayAmount`, kaiax/gasless/impl/getter.go:346-367) and does **not** depend on the swap's realized output: [2](#0-1) 

The block-building bundle is `[LendTxGenerator, ApproveTx?, SwapTx]` (kaiax/gasless/impl/builder.go:28-72, kaiax/gasless README lines 29-36). Execution of the bundle is fully atomic at commit time (`commitBundleTransaction`, work/worker.go:877-947): if `SwapTx` reverts (e.g., due to `minAmountOut` no longer being satisfiable because reserves were shifted), the whole bundle—including the already-generated `LendTx`—is rolled back via `env.state.Set(lastSnapshot)`. This atomicity prevents a *direct* loss of the lent KAIA in the base client itself.

However, this atomicity does not eliminate the exploitable window: `checkBalanceForSwap`'s `GetAmountIn`-based admission check (tx-pool admission time) and the swap's actual execution (block-building time, potentially a different block/state) are two *separate* evaluations of the same manipulable spot price, taken at different times/states. Because there is no TWAP and the price is read fresh each time from a pool that any unprivileged account can move via ordinary swaps in the same or an adjacent block, an attacker can:
- Manipulate the pool reserves to make `checkBalanceForSwap` accept a `SwapTx`/`amountIn` combination based on an artificially favorable spot price, then restore/move the price before the bundle is executed by the proposer, causing the bundle (and thus the proposer-funded `LendTx`) to repeatedly fail and be dropped/retried, wasting proposer compute and gasless-queue capacity (`ExtractTxBundles`, `IsReady`), or
- Coordinate (e.g., as an [auction](kaiax/auction) searcher able to place a transaction adjacent to the target block) to engineer a state where `GetAmountIn` under-reports the true required input at admission time due to a manipulated spot price, allowing a `SwapTx` with insufficient real value backing to be repeatedly accepted into the pool/bundle pipeline even though it will ultimately fail on-chain—amplifying griefing against the gasless fee-delegation subsystem that the base client and proposer rely on for the KIP-247 flow.

### Impact Explanation
This maps to the “fee-delegation / gasless settlement” category explicitly listed as in-scope. Because `GetAmountIn`/spot-price checks are used to gate an unprivileged user's fee-delegated (gasless) transaction admission and processing pipeline, and the price source is directly manipulable by any unprivileged transaction sender who can swap in the same underlying pool, this is a legitimate instance of the same bug class as the report (unprotected spot price → manipulation), reachable purely through normal transaction submission (no privileged role required). The concrete effect within the observed code is: unreliable/manipulable admission checks for gasless swap acceptance and repeated bundle construction/execution failures for the proposer, i.e., disruption of the gasless subsystem's guarantees rather than a state-divergence bug, since the worker's bundle execution is atomic and reverts consistently across honest nodes.

### Likelihood Explanation
Likelihood is Medium: manipulating a DEX pool's reserves within a block or across the tx-pool-admission-to-block-inclusion window is straightforward and requires no privileged access—any account with capital can submit ordinary swap transactions against the same pool used by `GaslessSwapRouter`. The condition depends on the specific pool used per allowed token having low liquidity/no TWAP protection, which is expected for at least some `AllowedTokens` in production deployments.

### Recommendation
- Have `GaslessSwapRouter.GetAmountIn` (and the underlying swap execution) use a TWAP-based or otherwise manipulation-resistant price for computing required `amountIn`/expected `amountOut`, rather than the pool's instantaneous reserves.
- Alternatively, re-validate `GetAmountIn` at the exact block/state used for `commitBundleTransaction` execution (not just at tx-pool admission) and reject/re-queue bundles whose gap between admission-time and execution-time spot price exceeds a safe bound, to reduce proposer-side griefing from repeated failed bundle construction.
- Consider bounding per-block price movement for tokens used in the gasless swap allow-list, or restricting `AllowedTokens` to pools with sufficient liquidity/TWAP oracles.

### Proof of Concept
Conceptual PoC (cannot be fully executed without deploying to a live/testnet Kaia node, but the code path is concretely traceable):
1. Attacker identifies a token `T` in `GaslessConfig.AllowedTokens` whose DEX pool (returned by `GaslessSwapRouter.GetDEXInfo(T)`) has low liquidity.
2. Attacker submits a large swap transaction against the same pool to shift reserves and change `GetAmountIn(T, minAmountOut)`'s output.
3. Victim (or attacker impersonating a gasless user) submits `ApproveTx`+`SwapTx` computed against the pre-manipulation price; `checkBalanceForSwap` (kaiax/gasless/impl/tx_pool.go:128-141) accepts it into the pool since `GetAmountIn` currently returns a value satisfied by `swapArgs.AmountIn`.
4. Attacker reverses/shifts the pool price again before the proposer includes the bundle in a block.
5. At block-building time, `commitBundleTransaction` (work/worker.go:877-947) executes `[LendTx, ApproveTx, SwapTx]`; `SwapTx` now reverts against the new spot price, causing the whole bundle (including the `LendTx` that was about to fund the user) to be rolled back and the transactions marked unexecutable (work/worker.go:887-935), repeatable at will by the attacker to grief the gasless subsystem and any proposer relying on the current spot-price-based admission check. func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut

		if g.getCurrentHasCode(swapArgs.Sender) {

		// tx.amountIn >= gsr.getAmountIn(minAmountOut)

			return err

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func (env *Task) commitBundleTransaction(bundle *builder.Bundle, bc BlockChain, nodeAddr common.Address, vmConfig *vm.Config) (error, *types.Transaction, []*types.Log) {
	lastSnapshot := env.state.Copy()
	gasUsedSnapshot := env.header.GasUsed
	blobGasUsedSnapshot := env.header.BlobGasUsed
	blobsSnapshot := env.blobs
	tcountSnapshot := env.tcount
	txs := []*types.Transaction{}
	receipts := []*types.Receipt{}
	logs := []*types.Log{}

	markAllTxUnexecutable := func() {
		for _, txOrGen := range bundle.BundleTxs {
			if txOrGen.IsConcreteTx() {
				tx, _ := txOrGen.GetTx(0)
				tx.MarkUnexecutable(true)
			}
		}
	}

	restoreEnv := func() {
		env.state.Set(lastSnapshot)
		env.header.GasUsed = gasUsedSnapshot
		env.tcount = tcountSnapshot
		// blob related env are restored to the snapshot
		env.header.BlobGasUsed = blobGasUsedSnapshot
		env.blobs = blobsSnapshot
	}

	var totalTxSize uint64 = 0
	for _, txOrGen := range bundle.BundleTxs {
		tx, err := txOrGen.GetTx(env.state.GetNonce(nodeAddr))
		if err != nil {
			logger.Error("TxGenerator error", "error", err)
			markAllTxUnexecutable()
			restoreEnv()
			return kerrors.ErrTxGeneration, nil, nil
		}

		env.state.SetTxContext(tx.Hash(), common.Hash{}, env.tcount)
		receipt, _, err := bc.ApplyTransaction(env.config, &nodeAddr, env.state, env.header, tx, &env.header.GasUsed, vmConfig)
		// Bundled tx will be rejected with any receipt.Status other than success.
		// There may be cases where a revert occurs within the EVM, which could result in an attack on a tx sender in an already executed bundle.
		if err != nil || receipt.Status != types.ReceiptStatusSuccessful {
			if err != vm.ErrInsufficientBalance && err != vm.ErrTotalTimeLimitReached {
				markAllTxUnexecutable()
			}
			receiptStatus := ""
			if receipt != nil {
				receiptStatus = strconv.FormatUint(uint64(receipt.Status), 10)
			}
			logger.Warn("ApplyTransaction error, restoring env",
				"blockNum", env.header.Number.String(), "txHash", tx.Hash().String(),
				"error", err, "receiptStatus", receiptStatus,
			)
			restoreEnv()
			if err == nil {
				err = kerrors.ErrRevertedBundleByVmErr
			}
			return err, tx, nil
		}
