### Title
PlotNFT `melt_plotnft` destroys the singleton without claiming outstanding self-pooled reward coins, permanently stranding those rewards - (File: chia/wallet/plotnft_wallet/plotnft_wallet.py)

### Summary
This mirrors the ALCX `VotingEscrow::merge` bug class: an operation destroys/burns an identity token (the singleton) without first sweeping value that is only claimable through that identity, permanently freezing it. In chia, self-pooled reward coins farmed to a PlotNFT's p2-singleton address (`RewardPuzzle`/`PoolReward`, curried with `SingletonMember`) can only be spent by presenting proof that the specific singleton (identified by `singleton_id` = `launcher_id`) is being spent alongside them via the `SEND_MESSAGE`/inner-puzzle mechanism used in `PlotNFT.claim_pool_rewards`.

### Finding Description
`PlotNFT2Wallet.melt_plotnft` builds a melt spend for the PlotNFT singleton and pushes it without any check for, or claim of, unswept self-pooled reward coins: [1](#0-0) 

The underlying driver `PlotNFT.melt` only guards against melting while actively pooling, but does not require that pending self-custody pool rewards be claimed first: [2](#0-1) 

Self-pooled rewards sit at a `RewardPuzzle`/`PoolReward` address that is curried with a `SingletonMember` puzzle bound to the PlotNFT's `singleton_id` (its `launcher_id`): [3](#0-2) 

Claiming those rewards requires an active spend of the *live* PlotNFT singleton that sends a matching `SEND_MESSAGE`/announcement authorizing the reward puzzle's spend, exactly as implemented in `PlotNFT.claim_pool_rewards`, which curries the claim into the singleton's own spend and pairs it with spends of each `PoolReward` coin: [4](#0-3) 

Once the singleton is melted (an `ESCAPE_VALUE`/`-113` melt condition burns the singleton coin, ending its lineage), there is no longer a live singleton coin whose spend can authorize the `SingletonMember` proof for any still-unswept `PoolReward` coins tied to that `launcher_id`. This is structurally identical to the ALCX report: `RewardsDistributor::claim` requiring `isVotingEscrow`/`approvedOrOwner` on a token that no longer exists after `VotingEscrow::merge` burns it — here, the `SingletonMember` check requires a still-spendable singleton with that `launcher_id`, which no longer exists after `melt`.

The `claim_rewards` path (`PlotNFT2Wallet.claim_rewards`) is the mechanism that would normally sweep such rewards, but it is a separate, optional call that a user (or the wallet code) is not forced to invoke before `melt_plotnft`: [5](#0-4) 

Note: the codebase does have an intentionally-tested "lose rewards while leaving" scenario (rewards forwarded to the pool are forfeited during the `LEAVING_POOL` window), but that is a distinct, deliberately-tested behavior — a fee for switching pools, not a total, non-recoverable loss of principal-owned reward value tied to identity destruction: [6](#0-5) 
The `melt_plotnft` path, by contrast, has no equivalent test coverage or safeguard asserting that outstanding self-pooled rewards are claimed or forfeited to a known destination before the singleton is irreversibly destroyed — I could not find any check or warning path preventing melt while rewards are outstanding, nor a test proving the melt path forces or blocks on an outstanding-rewards check.

### Impact Explanation
If a self-pooling PlotNFT owner farms blocks (accumulating unclaimed `PoolReward` coins at the p2-singleton address) and then calls `melt_plotnft` before calling `claim_rewards`, those unclaimed reward coins become permanently unspendable XCH, since the `SingletonMember` authorization can never again be satisfied for that `launcher_id`. This is a permanent freezing of funds, matching the "Permanent freezing of unclaimed yield" impact category from the source report.

### Likelihood Explanation
This requires no attacker and no privileged access — it is reachable by any local wallet user simply calling the `melt_plotnft` RPC/CLI operation while self-pooled rewards are still outstanding (e.g., from timing, forgetting to claim, or automation issuing melt immediately after leaving pooling). It is a straightforward, single-user sequence of ordinary wallet operations, not a malicious-peer or edge-case-only condition.

### Recommendation
In `PlotNFT2Wallet.melt_plotnft` (and/or `PlotNFT.melt`), check for any unclaimed self-pooled `PoolReward` coins (via `plotnft2_store.get_pool_rewards`) belonging to the PlotNFT before permitting a melt, and either: (1) refuse to melt until rewards are claimed, or (2) automatically fold a `claim_pool_rewards` spend into the same transaction/spend bundle as the melt, similar to how `claim_pool_rewards` already couples the singleton spend with reward-coin spends.

### Proof of Concept
Conceptual reproduction (cannot be fully executed without a live devin/test environment, but derivable directly from existing test infrastructure in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py` and `chia/_tests/pools/test_plotnft_v2_drivers.py`):
1. Create a self-custody PlotNFT via `PlotNFT2Wallet.create_new` (state = self-custody, per `mint_plotnft(desired_state="self_custody")` helper used in `test_plotnft_self_custody_claim`).
2. Farm blocks to the PlotNFT's p2-singleton puzzle hash to generate unclaimed `PoolReward` coins (same pattern as `mint_reward`/`farm_blocks_to_puzzlehash` in the existing tests).
3. Do **not** call `claim_rewards`.
4. Call `PlotNFT2Wallet.melt_plotnft(...)` and push the resulting spend bundle; the PlotNFT singleton coin is destroyed (melt condition `[CREATE_COIN, 0, -113]` per `PlotNFT.melt`).
5. Attempt `PlotNFT2Wallet.claim_rewards` (or manually construct `plotnft.claim_pool_rewards(...)`) for the previously-farmed `PoolReward` coin — this now fails/cannot be constructed because `get_current_plotnft()`/the singleton no longer exists, and the `SingletonMember` puzzle guarding the reward coin can never again be satisfied, leaving the reward coin permanently unspendable.

    def claim_pool_rewards(
        self,
        rewards_to_claim: list[PoolReward],
        reward_delegated_puzzles_and_solutions: list[DelegatedPuzzleAndSolution],
    ) -> list[CoinSpend]:
        if self.pooling:
            raise ValueError("Cannot claim rewards while pooling. If you're a pool, try `forward_pool_rewards`")
        if len(rewards_to_claim) != len(reward_delegated_puzzles_and_solutions):
            raise ValueError("Number of rewards and delegated puzzles and solutions must match")
        dpuz_and_solution = DelegatedPuzzleAndSolution(
            puzzle=Program.to(
                (
                    1,
                    [
                        CreateCoin(
                            puzzle_hash=self.inner_puzzle_hash(),
                            amount=self.coin.amount,
                            memos=[self.singleton_struct.struct_hash()],
                        ).to_program(),
                        *(
                            SendMessage(
                                msg=dpuz_and_sol.puzzle.get_tree_hash(),
                                sender=MessageParticipant(puzzle_hash_committed=self.puzzle_hash(nonce=0)),
                                receiver=MessageParticipant(coin_id_committed=reward.coin.name()),
                            ).to_program()
                            for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
                        ),
                    ],
                )
            ),
            solution=Program.to([]),
        )
        return [
            self.singleton_action_spend(
                inner_solution=self.puzzle_with_restrictions().solve(
                    member_validator_solutions=[],
                    dpuz_validator_solutions=[],
                    member_solution=self.bls_member.solve(),
                    delegated_puzzle_and_solution=dpuz_and_solution,
                )
            ),
            *(
                make_spend(
                    coin=reward.coin,
                    puzzle_reveal=reward.puzzle(),
                    solution=reward.solve(
                        self.inner_puzzle_hash(),
                        delegated_puzzle_and_solution=dpuz_and_sol,
                    ),
                )
                for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
            ),
        ]

@dataclass(kw_only=True, frozen=True)
class SingletonMember:
    singleton_id: bytes32
    singleton_mod_hash: bytes32 = SINGLETON_TOP_LAYER_MOD_HASH
    singleton_launcher_hash: bytes32 = SINGLETON_LAUNCHER_PUZZLE_HASH

    def memo(self, nonce: int) -> Program:
        return Program.to(0)

    def puzzle(self, nonce: int) -> Program:
        singleton_struct = (self.singleton_mod_hash, (self.singleton_id, self.singleton_launcher_hash))
        return SINGLETON_MEMBER_MOD.curry(singleton_struct)

    def puzzle_hash(self, nonce: int) -> bytes32:
        return self.puzzle(nonce).get_tree_hash()

    def solve(self, singleton_inner_puzzle_hash: bytes32) -> Program:
        return Program.to([singleton_inner_puzzle_hash])
