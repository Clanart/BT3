### Title
Missing domain-separation in `addr` precompile's `associate()` allows any signature-message pair to force address association and fund migration - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile's `associate()` method treats **any** valid ECDSA signature over an **attacker-supplied arbitrary message** as sufficient proof of intent to perform a permanent, fund-moving, security-sensitive action (binding an EVM address to a Sei address, migrating balances, and setting the account's on-chain pubkey). There is no canonical/purpose-bound message enforced on-chain, no nonce, and no chain-ID binding — mirroring the Logto flaw where a verification record obtained for one purpose (WebAuthn *registration*) was accepted as proof for an unrelated, more privileged action (MFA management step-up) because the check only verified "is this verification currently valid for this user," not "was this proof produced for *this* specific action."

### Finding Description
`PrecompileExecutor.associate` in `precompiles/addr/addr.go` takes `v, r, s` and a free-form `customMessage` string directly from calldata, hashes `customMessage` with `crypto.Keccak256Hash` and recovers a pubkey/address from the signature with no validation that `customMessage` matches the canonical association text (`"Please sign this message to link your EVM and Sei addresses..."`): [1](#0-0) 

The recovered pubkey is fed straight into `associateAddresses`, which only checks that the target Sei address isn't *already* associated — it performs no check that the caller (msg.sender of the EVM tx) has any relationship to the recovered address, nor that the signed message was ever intended to authorize association: [2](#0-1) 

`associateAddresses` then calls `AssociationHelper.AssociateAddresses`, which sets the address mapping, overwrites the account's pubkey, and unconditionally migrates **all spendable coins and wei balance** sitting at the "cast address" (`sdk.AccAddress(evmAddr[:])`) into the newly bound Sei account, then deletes the cast account: [3](#0-2) 

Because the precompile never binds the signature to a Sei-specific, single-purpose message, **any** `(v, r, s, message)` tuple ever produced by a victim's EVM key — for a completely unrelated purpose (e.g., a sign-in message on another dApp, an off-chain order signature, or any EIP-191 `personal_sign` payload that becomes publicly visible) — can be harvested and replayed by an unrelated third party as an EVM transaction calling `associate` on Sei. This forces the permanent on-chain binding, pubkey-overwrite, and balance sweep for a wallet holder who never intended to interact with Sei at all, exactly analogous to the Logto bug where a proof for one action was accepted to authorize a different, more sensitive action.

### Impact Explanation
Successful exploitation causes:
- **Unauthorized state-changing action without purpose-bound consent**: A victim's EVM address is permanently associated to a Sei address and the account's on-chain pubkey is set, without the victim ever intending or approving that specific action.
- **Forced fund migration**: Any `usei`/wei balance parked at the raw cast address (`sdk.AccAddress(evmAddr[:])`) is swept into the newly bound Sei account as an unconditional side effect, and the cast account is removed — an irreversible balance-location change triggered by a replayed, out-of-context signature.
- Because association is a one-way, non-reversible operation (`associateAddresses` rejects re-association once bound) and can be initiated by an unprivileged third party, this satisfies the "unauthorized transfer / fund relocation via precompile" and "fee/refund abuse of an account's own funds without consent" impact classes reachable from a public EVM RPC call.

### Likelihood Explanation
Any user of the `addr` precompile at `0x0000000000000000000000000000000000001004` is affected. Exploitation requires only:
1. Obtaining any valid ECDSA signature and its signed message from a victim's EVM key (widely available, since EVM signatures for off-chain purposes — logins, orders, attestations — are routinely produced and often published/leaked/observable by dApps or public records).
2. Submitting a standard, unprivileged EVM transaction calling `associate(v, r, s, message)` on Sei with that harvested tuple.

No special privileges, node compromise, or governance access are required — it is directly reachable via the public EVM JSON-RPC surface by any transaction sender, and the precompile itself performs no purpose binding.

### Recommendation
Enforce a canonical, Sei-specific, single-purpose message template inside `associate()` (and `associatePubKey`/legacy variants) rather than trusting caller-supplied `customMessage` verbatim. At minimum:
- Require `customMessage` to exactly match a fixed, contract-defined association string (already documented in tests as `"Please sign this message to link your EVM and Sei addresses..."`), rejecting any other content.
- Include chain-ID and a per-account nonce (or the target Sei address) inside the signed payload so a signature cannot be replayed across contexts or accounts.
- Consider requiring the transaction sender (`msg.sender`/tx signer) to match the recovered EVM address, ensuring the associating party is the same account performing the action, closing the "any harvested signature works" gap.

### Proof of Concept
1. Victim signs any unrelated off-chain message with their EVM key elsewhere (e.g., `personal_sign` on a third-party site), producing `(v, r, s, message)`.
2. Attacker/observer obtains this `(v, r, s, message)` tuple (commonly public in off-chain protocols).
3. Attacker submits a Sei EVM transaction calling:
   `addr.associate(v, r, s, message)`
   exactly as accepted by `precompiles/addr/addr.go` `associate()` — no check rejects `message` for not matching the intended association text.
4. `associateAddresses` → `AssociationHelper.AssociateAddresses` executes: the victim's EVM↔Sei addresses become permanently bound, the account pubkey is set, and any balance held at `sdk.AccAddress(evmAddr[:])` is swept to the new Sei account — all without the victim ever calling `associate` or approving this specific action. func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
