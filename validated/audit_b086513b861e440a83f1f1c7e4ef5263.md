## Analysis

The reported bug class — approving `type(uint256).max` to a spender for UX convenience, thereby exposing the full token balance to whatever that spender ends up doing — has a direct analog in the `kaiax/gasless` module (KIP‑247 gasless transactions).

### Root cause

`GaslessModule.isApproveTx()` explicitly *requires* the ERC-20 approval to be for the maximum possible amount before it will recognize/promote a `GaslessApproveTx`: [1](#0-0) 

The whitelisted spender (`g.swapRouter`) is not a fixed, immutable address — it is re-read from the on-chain `Registry` contract on every block and can be rotated by governance/owner action: [2](#0-1) 

`kaiax/gasless/impl/execution_test.go` demonstrates this rotation explicitly ("update gsr address" test case), confirming `g.swapRouter` changes at runtime based on `Registry.register`. [3](#0-2) 

The node-side checks (`checkBalanceForApprove`, `checkBalanceForSwap`) only validate balances/allowances *before accepting the tx into the mempool*; they do not, and cannot, limit what the on-chain unlimited ERC-20 allowance actually permits the spender contract to do afterward: [4](#0-3) 

Because `IsApproveTx` mandates `Amount == MaxUint256` (condition A4), every gasless user is forced into the exact "unlimited approval" pattern the external report flags, and this approval is granted to a router address that can later be swapped out by governance. The stale, unlimited allowance to the *former* router remains valid on the ERC-20 contract indefinitely — it is never revoked as part of router rotation. Any user who ever executed a `GaslessApproveTx` retains an unlimited, standing allowance to whatever address held the `GaslessSwapRouter` role at that time.

### Title
Forced Unlimited ERC-20 Approval to a Rotatable `GaslessSwapRouter` Enables Full Balance Drain by a Stale/Compromised Router - (File: `kaiax/gasless/impl/getter.go`)

### Summary
The gasless module's `IsApproveTx` validation (`kaiax/gasless/impl/getter.go`, condition A4) only recognizes a `GaslessApproveTx` when it approves `type(uint256).max` tokens to the currently whitelisted `swapRouter`. This design mirrors the "unlimited approval" anti-pattern from the external report: every gasless user must grant an unbounded, standing ERC-20 allowance to the router contract in order to use the KIP-247 flow.

### Finding Description
`isApproveTx` enforces `args.Amount.Cmp(abi.MaxUint256) == 0` as a strict requirement (A4) for a valid `GaslessApproveTx`, and `g.swapRouter` is not fixed — it is refreshed each block from the `Registry` system contract via `updateAddresses`, meaning it can be reassigned to a new contract address by governance/owner action at any time. Once a user submits a `GaslessApproveTx`, the resulting on-chain ERC-20 `allowance(sender, router) = MaxUint256` is permanent state on the token contract, independent of the kaiax module's in-memory whitelist. If `swapRouter` is later rotated (as exercised by the "update gsr address" test), the *old* router address is no longer recognized by the node's gasless logic, but the unlimited allowance previously granted to it is not revoked. That old contract remains capable of calling `transferFrom(sender, anyRecipient, senderBalance)` for the full token balance of every past gasless user, regardless of the intended per-swap `amountIn`.

### Impact Explanation
If the previously-whitelisted router contract is later found to be buggy, its owner key is compromised, or it is intentionally malicious after rotation, it can call `transferFrom` to drain the entire ERC-20 balance of any account that ever executed a `GaslessApproveTx` — not merely the amount involved in a specific swap. This is unauthorized value movement affecting an unbounded number of unprivileged gasless users, sourced directly from a protocol-mandated unlimited-approval requirement rather than user choice.

### Likelihood Explanation
Every ordinary gasless-swap user is forced through this exact approval pattern by design (A4 in `isApproveTx`), so the exposure is created continuously as a side effect of normal usage — no attacker action is needed to create the allowance. The only additional condition needed to realize the impact is a future rotation of `swapRouter` combined with the old router becoming compromised/malicious, which is a realistic operational scenario for any upgradeable/rotatable system-registered component.

### Recommendation
Avoid mandating `MaxUint256` approvals in the gasless flow. Require `GaslessApproveTx.amount` to be bounded to the specific `amountIn`/`amountRepay` needed for the paired `GaslessSwapTx` (matching the router's already-known repay/swap amounts), or require the module/router to consume and reset the allowance to zero after each swap. Additionally, on `swapRouter` rotation, the protocol should provide/require a mechanism to revoke standing allowances against the deprecated router address before it is considered fully retired.

### Proof of Concept
1. Router `R1` is registered as `GaslessSwapRouter` in the `Registry` contract; `updateAddresses` sets `g.swapRouter = R1`.
2. User Alice sends a `GaslessApproveTx` approving `R1` for `MaxUint256` tokens of token `T` (required by `isApproveTx` A4) followed by a normal `GaslessSwapTx`, both of which succeed and are accepted by the node per `IsApproveTx`/`IsSwapTx`/`VerifyExecutable`.
3. Governance/owner rotates the router in `Registry` to `R2`; `updateAddresses` updates `g.swapRouter = R2` on the next block (as shown in `execution_test.go`'s "update gsr address" case).
4. `R1`'s allowance from Alice (`T.allowance(Alice, R1) == MaxUint256`) is untouched by this rotation — it still exists on-chain.
5. If `R1`'s owner key is later compromised or `R1` contains an exploitable function that calls `transferFrom`, the attacker calls `T.transferFrom(Alice, attacker, T.balanceOf(Alice))` using the still-valid unlimited allowance, draining Alice's full balance of token `T`, far exceeding the small `amountIn` she ever intended to authorize via her original swap.

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
