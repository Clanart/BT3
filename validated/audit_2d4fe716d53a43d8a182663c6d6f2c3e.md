### Title
Gasless bundle atomicity allows a malicious swap to cause reverting of an already-valid ApproveTx, enabling repeated griefing of gasless users - (File: work/worker.go, kaiax/gasless/impl/builder.go)

### Summary
The Kaia gasless module (`kaiax/gasless`) bundles a user's `ApproveTx` and `SwapTx` together with a proposer-funded `LendTxGenerator` transaction into a single atomic `Bundle`. The block-building loop in `work/worker.go` executes every transaction of a bundle and, if **any single member fails** (non-success receipt or error), reverts and discards the **entire bundle**, including transactions that individually succeeded. This is the same "loop of otherwise-independent operations that reverts atomically on a single failure" bug class described in the external report (MerkleReserveMinter's `mintFromReserve`), where a griefer can deliberately cause one item of a batch to fail so the whole batch is discarded, forcing the victim to resubmit repeatedly and potentially never complete within a limited window.

### Finding Description
`GaslessModule.ExtractTxBundles` builds a bundle `[LendTxGenerator, ApproveTx(optional), SwapTx]` for a gasless user: [1](#0-0) 

This bundle is executed atomically in `Task.commitBundleTransaction`. Each transaction in the bundle is applied in sequence, but if the last one (`SwapTx`) fails (e.g., due to slippage/`minAmountOut` no longer being satisfiable because of price movement), the **entire bundle is reverted and marked unexecutable**, even though the `ApproveTx` executed successfully moments earlier: [2](#0-1) 

The code even documents the exact attack surface being exploited: [3](#0-2) 

Because `GaslessTx.SwapTx.AmountRepay`/`MinAmountOut` are fixed at signing time (`VerifyExecutable` checks `SP4`), an unprivileged actor who can influence the swap pool's price between the time the user signs the `SwapTx` and the time it is committed in a block (e.g., by submitting their own trade against the same pool right before the victim's bundle is processed) can make the victim's `SwapTx` revert on-chain. This causes `commitBundleTransaction` to discard the *whole* bundle — wiping out the valid, already-applied `ApproveTx` state change and marking both `ApproveTx` and `SwapTx` unexecutable, which drops them from the pool: [4](#0-3) 

Since the attacker only needs to see the pending gasless bundle (observable via mempool/`debug_isGaslessTx`) and can repeat the manipulation each time the victim retries, the victim can be prevented from ever completing their gasless swap.

### Impact Explanation
A malicious, unprivileged actor can repeatedly force reversion of legitimate, otherwise-successful gasless `ApproveTx` transactions bundled with a targeted `SwapTx`, by manipulating swap-router state so the swap's fixed `minAmountOut`/`amountRepay` condition fails. This denies gasless users the ability to have their approve+swap pair included, discards their `ApproveTx` state changes each time, and forces them to keep resubmitting (with new nonces/signatures), analogous to the reserved-token-minter DoS in the source report. This is a concrete availability/griefing impact on the gasless settlement path specifically called out as a known risk in the code comment itself.

### Likelihood Explanation
Any user monitoring the mempool for gasless bundles (which are readily identifiable via `IsApproveTx`/`IsSwapTx` heuristics or the `debug_isGaslessTx` RPC) can craft a transaction that shifts the swap-router's on-chain price just enough to invalidate the pending `SwapTx`'s fixed `AmountRepay`/`MinAmountOut`, and repeat this every block the victim retries. No special privileges (validator, proposer, or auctioneer role) are required — only the ability to submit an ordinary transaction that interacts with the same whitelisted token/router.

### Recommendation
Do not discard the entire bundle when only the last (or a non-lender) transaction of a gasless bundle fails. Options:
- Allow partial-bundle commitment: keep already-successful, independent transactions (e.g., `ApproveTx`) in the block and only drop/mark-unexecutable the failing transaction (`SwapTx`), provided the `LendTxGenerator` amount is adjusted or not disbursed for the failing portion.
- Alternatively, re-validate `VerifyExecutable`/`SP4` conditions against the latest state immediately before committing the bundle and skip inclusion pre-emptively rather than executing then rolling back, reducing the window for state manipulation.
- Consider tightening the gasless swap's tolerance/deadline handling so it is resistant to small last-block price shifts, and rate-limit/penalize repeated failed swap attempts from the same searcher-visible pattern.

### Proof of Concept
1. Victim submits `ApproveTx` (nonce n) and `SwapTx` (nonce n+1) forming a valid gasless pair; `GaslessModule.ExtractTxBundles` bundles them as `[LendTxGenerator, ApproveTx, SwapTx]`.
2. Attacker observes the pending bundle and submits an ordinary swap against the same whitelisted token/router just before block assembly, shifting the pool price so the victim's fixed `SwapArgs.MinAmountOut`/`AmountRepay` (computed via `repayAmount`) is no longer satisfiable.
3. During `Task.ApplyTransactions` → `commitBundleTransaction`, the `LendTxGenerator` and `ApproveTx` execute successfully, but `SwapTx` reverts (`receipt.Status != types.ReceiptStatusSuccessful`).
4. `commitBundleTransaction` calls `restoreEnv()` and `markAllTxUnexecutable()`, discarding the entire bundle — including the previously-successful `ApproveTx` — from the block: [5](#0-4) 
5. The victim's `ApproveTx`/`SwapTx` pair is dropped; the attacker repeats step 2 on every subsequent attempt, preventing the victim's gasless swap from ever being included.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)
