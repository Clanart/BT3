### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable received funds — (`File: networks/bitcoin/src/wallet/mod.rs`)

### Summary
`scan_transaction` is the "safe" primitive: it can be applied selectively to `block.txdata[1 ..]` so callers only ever see spendable outputs. `scan_block`, the convenience wrapper an integrator will actually call, iterates `block.txdata` including `txdata[0]` — the coinbase — without any maturity check. Outputs it returns are wrapped in `ReceivedOutput` and fed straight into `SignableTransaction::new`, which treats them as spendable inputs.

### Finding Description

pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}

`scan_transaction` matches `output.script_pubkey` against registered scripts and produces a `ReceivedOutput` carrying the outpoint and offset needed to spend it [2](#0-1) . A coinbase output paying the Scanner's P2TR script matches identically to any other output — there is no marker distinguishing it — so it is returned as a normal `ReceivedOutput`.

Downstream, `SignableTransaction::new` sums `input.output.value` as available funds and builds `TxIn`s from each `input.outpoint` with no coinbase/maturity validation [3](#0-2) , and `TransactionSignMachine::sign` produces BIP-341 key-spend sighashes over `Prevouts::All`, so the threshold group signs a transaction spending the immature coinbase [4](#0-3) . Such a transaction is consensus-invalid for 100 blocks (BIP-34/COINBASE_MATURITY) and will be rejected by every node.

The only protection is a doc comment noting "a post-processing pass is needed" — the same shape as the reference bug, where `depositERC20` carried the `onlyEOA` protection but `depositERC20To` exposed the unprotected path to the same accidental misuse.

### Impact Explanation
An unprivileged party only needs to send a Bitcoin transaction — which miners do by definition via the coinbase — paying the Serai P2TR script. Any coinbase output to the wallet key (or a registered offset) is reported by `scan_block` as a received, spendable output for ~100 blocks during which it is not. The wallet accounting over-reports balance, and threshold signing sessions can be triggered over transactions that can never confirm, burning the group's signing rounds and producing shares on a doomed message. Reorgs that replace the coinbase additionally orphan the reported outpoint entirely.

### Likelihood Explanation
Reachability is trivial: miner coinbases occur every block, and any party who can get a transaction mined paying the scanned script triggers it. Whether funds are actually lost depends on the caller ignoring the documented caveat, which keeps this Medium rather than High — analogous to the reference report, which was Medium because it required user error despite the missing guard.

### Recommendation
Remove the coinbase from `scan_block`'s scan set: iterate `block.txdata[1 ..]` internally (or return coinbase hits in a separately-flagged structure), rather than relying on every caller to perform the documented post-processing pass. Alternatively, have `scan_block` take the block height and filter coinbase outputs younger than `COINBASE_MATURITY` (100 blocks).

### Proof of Concept
1. Construct `Scanner::new(key)` for the wallet's tweaked even-Y group key.
2. Miner crafts a block whose coinbase (`txdata[0]`) contains a `TxOut` with `script_pubkey == p2tr_script_buf(key)`.
3. `Scanner::scan_block(&block)` returns a `ReceivedOutput` for that coinbase outpoint, indistinguishable from a mature payment.
4. Pass it to `SignableTransaction::new(vec![received], payments, ...)`, then `multisig(keys)` → `preprocess` → `sign(&[], commitments)` → `complete`. The group produces a fully-signed transaction spending an immature coinbase, which all Bitcoin nodes reject as non-consensus — funds "received" were never spendable, and the signing round is consumed on an invalid message.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),

    }
