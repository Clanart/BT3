### Title
Silent Acceptance of Corrupted Lazy-Extension Bytes Bypasses Integrity Check ("Legacy" Mode) - (File: `java/core/src/main/java/com/google/protobuf/InternalLazyField.java`)

### Summary
Zip4j's CVE-2023-22899 flaw is that a decryption path does not always verify the authentication tag (MAC) on ciphertext, so tampered/corrupted data can be silently accepted as if it decrypted correctly. The Protobuf analog is in Java's lazy-field extension handling: `InternalLazyField.getValue()` performs an integrity check (parsing the delayed bytes) but, depending on `ExtensionRegistryLite.lazyExtensionEnabled()`, one code path swallows the parse failure and returns the untouched default instance instead of surfacing the corruption to the caller.

### Finding Description
`InternalLazyField.ensureInitialized()` parses the raw, attacker-supplied bytes for a lazily-parsed extension/message-set field and marks the field `corrupted` if parsing throws `InvalidProtocolBufferException`, i.e. if the wire bytes fail to decode as a valid message of the expected type [1](#0-0) .

The caller-facing `getValue()` method branches on `extensionRegistry.lazyExtensionEnabled()`:
- New behavior: throw `InvalidProtobufRuntimeException`, correctly surfacing the failed integrity check.
- Old/legacy behavior: silently return `defaultInstance`, discarding the fact that the bytes did not parse as expected [2](#0-1) .

The same "silently swallow the parse failure" pattern also exists in the lite-runtime sibling `LazyFieldLite.ensureInitialized()`, `mergeFrom()`, and `mergeValueAndBytes()`, all of which catch `InvalidProtocolBufferException` and replace the lazy field's value with the default instance (or leave the prior value unchanged) with the explicit comment "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." [3](#0-2) [4](#0-3) 

Crucially, when a lazy field's bytes are corrupted but its `value` is never accessed, the corrupted raw bytes are preserved and re-serialized transparently on `toByteString()`/`writeTo()` without ever being validated [5](#0-4) . This mirrors the confirmed test behavior in `LazilyParsedMessageSetTest`, where a corrupted extension payload round-trips through parse → serialize → re-parse while never triggering a validation failure unless the corrupted extension is explicitly accessed [6](#0-5) .

The invariant that transfers from the Zip4j report: "a security-relevant check (MAC/authenticity) exists in the code but is not applied on every path, so a downstream consumer treats forged/corrupted input as valid." Here the analogous check is "the lazy-parsed bytes must successfully decode into the declared message type before being trusted as that message," and the missing-check path is the `lazyExtensionEnabled() == false` legacy branch (plus the parallel `LazyFieldLite` swallow sites), which accepts corrupted bytes and substitutes a default instance with no signal to the application that the data was tampered with or malformed.

### Impact Explanation
An attacker who controls a serialized Protobuf message containing a lazily-parsed extension or `MessageSet` item can supply intentionally malformed bytes for that sub-message. Depending on runtime configuration (`lazyExtensionEnabled()` false, the legacy/default-compatible mode), the corrupted payload is silently converted into the extension's default (empty) instance rather than raising an error. An application that relies on that extension being present/valid (e.g., an authorization or configuration extension) will instead silently observe "absent/default" data — a data-integrity bypass analogous to unauthenticated ciphertext being accepted. Because no exception propagates and no field is logged, the application has no signal that tampering/corruption occurred, which is a direct parallel to Zip4j's CWE-346 (origin validation error) impact: integrity loss without detection (`C:N/I:H` in the original CVSS vector). This is a Medium-severity integrity concern, not memory corruption or RCE.

### Likelihood Explanation
The corrupted-payload path is reachable via any public parse API that constructs a message containing lazy extensions/`MessageSet` items with an `ExtensionRegistry` in the legacy (`lazyExtensionEnabled() == false`) configuration, which is the compatibility-preserving default for existing callers per the code comments ("basically implies this can only be a MessageSet extension, and we should fall back to the old behavior of silently returning the default instance on corrupted extensions"). The attacker only needs to supply an ordinary bounded Protobuf payload with a malformed length-delimited sub-message for the extension field — no privileged access or malicious schema is required. However, this "no exception" legacy behavior is a documented, intentional fallback for backward compatibility, and the newer runtime-exception path exists specifically to close this gap, so the exposure is limited to callers still on the legacy extension registry mode.

### Recommendation
Ensure `lazyExtensionEnabled()` defaults to true (or is deprecated/removed) so that corrupted lazy-extension bytes always raise `InvalidProtobufRuntimeException` rather than silently substituting the default instance; apply the same fix to `LazyFieldLite.ensureInitialized()`, `mergeFrom()`, and `mergeValueAndBytes()`, which currently discard `InvalidProtocolBufferException` without any logging or exception propagation. At minimum, surface `isCorrupted()`/`corrupted` state to the caller in all code paths so applications can detect and reject messages containing tampered lazy fields instead of unknowingly treating them as valid defaults.

2. Parse it as `TestMessageSet` using an `ExtensionRegistry` configured with the legacy lazy-extension mode (`mode != LAZY_VERIFY_ON_ACCESS`).
3. Call `getExtension(...)` on the corrupted extension: per `testLoadCorruptedLazyField_getsReplacedWithEmptyMessage`, the call returns `TestMessageSetExtension1.getDefaultInstance()` with no exception thrown [8](#0-7) .

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }

  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }

  public void testLoadCorruptedLazyField_getsReplacedWithEmptyMessage() throws Exception {
    ExtensionRegistry extensionRegistry = ExtensionRegistry.newInstance();
    extensionRegistry.add(TestMessageSetExtension1.messageSetExtension);

    RawMessageSet inputRaw =
        RawMessageSet.newBuilder()
            .addItem(
                RawMessageSet.Item.newBuilder()
                    .setTypeId(TYPE_ID_1)
                    .setMessage(CORRUPTED_MESSAGE_PAYLOAD))
            .build();

    ByteString inputData = inputRaw.toByteString();

    // Re-parse as a TestMessageSet, so that all extensions are lazy
    TestMessageSet messageSet = TestMessageSet.parseFrom(inputData, extensionRegistry);

    if (mode == LazyExtensionMode.LAZY_VERIFY_ON_ACCESS) {
      assertThrows(
          InvalidProtobufRuntimeException.class,
          () -> messageSet.getExtension(TestMessageSetExtension1.messageSetExtension));
      return;
    }

    assertThat(messageSet.getExtension(TestMessageSetExtension1.messageSetExtension))
        .isEqualTo(TestMessageSetExtension1.getDefaultInstance());

    // Serialize. The first extension should be serialized as an empty message.
    ByteString outputData = messageSet.toByteString();

    // Round trip and confirm the corrupted payload is preserved.
    RawMessageSet actualRaw =
        RawMessageSet.parseFrom(outputData, ExtensionRegistry.getEmptyRegistry());
    assertThat(actualRaw).isEqualTo(inputRaw);
  }
