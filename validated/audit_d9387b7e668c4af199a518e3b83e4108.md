### Title
Permissionless registration of arbitrary ERC20 contracts as native token pairs allows minting Cosmos coins backed by fake token balances - ([File: x/erc20/keeper/msg_server.go])

### Summary
The external report flags that Napier Pools accept externally supplied token/pool parameters without on-chain enforcement of the invariants the system depends on (matching maturities, common factory, shared underlying), so a maliciously or carelessly configured pool can violate assumptions baked into pricing/accounting logic. The Cosmos EVM analog is `MsgRegisterERC20`, which by default (`PermissionlessRegistration = true`) lets *any* unprivileged account register *any* EVM contract address as a `TokenPair` backing a brand-new native Cosmos coin, with no on-chain verification that the contract actually implements correct, non-malicious ERC20 semantics beyond calling `name()`, `symbol()`, `decimals()`.

### Finding Description
`RegisterERC20` in `x/erc20/keeper/msg_server.go` only checks that registration is enabled and, if `PermissionlessRegistration` is on, requires no special authority at all: [1](#0-0) 

It then calls `k.registerERC20` → `k.CreateCoinMetadata` → `k.QueryERC20`, which merely does `eth_call`s to `name()`, `symbol()`, `decimals()` on the target contract and trusts whatever it returns to build bank denom metadata and a `TokenPair{ContractOwner: OWNER_EXTERNAL}`: [2](#0-1) [3](#0-2) 

Nowhere is the contract's `transfer`/`balanceOf` logic validated to be a faithful, non-malicious ERC20 implementation, nor is there any check that decimals are sane relative to the ERC20 minter/burner reference implementation used elsewhere, nor bytecode/behavioral verification of any kind - directly analogous to the Napier issue where pool creation parameters (maturity, factory, decimals, underlying) are trusted without on-chain verification.

Once registered, the "native ERC20" conversion flow in `ConvertERC20`/`convertERC20IntoCoinsForNativeToken` mints real, spendable native Cosmos coins based on the *token contract's own self-reported* balance changes: [4](#0-3) 

The only safety check is an invariant comparing `balanceOf(module)` before and after the `transfer` call: [5](#0-4) 

But `BalanceOf` calls `balanceOf` on the very same attacker-deployed contract: [6](#0-5) 

Because both the `transfer` call and the subsequent `balanceOf` check execute logic entirely controlled by the attacker's own contract code (it was permissionlessly registered by the attacker, with `OWNER_EXTERNAL`), the attacker can implement a contract whose `transfer()` returns `true` without any real value movement, and whose `balanceOf()` deterministically reports `previousBalance + amount` for the module address regardless of true state. The "balance invariance" check is self-referential and provides no real economic guarantee, since it is not backed by any independent (e.g. bank-module-tracked) escrow.

### Impact Explanation
This lets an unprivileged attacker permissionlessly register a malicious contract, call `MsgConvertERC20` with an arbitrary amount, and have `k.bankKeeper.MintCoins` mint real native Cosmos coins to their own receiver address backed by nothing: [7](#0-6) 

These freshly minted native coins are fully fungible, transferable, and spendable (including via IBC, staking, or conversion back through legitimate token pairs), constituting unauthorized minting / accounting corruption of spendable user value — a Critical impact under the allowed-impact gate.

### Likelihood Explanation
`PermissionlessRegistration` defaults to `true`: [8](#0-7) 
Any account can deploy a malicious ERC20 via ordinary EVM transactions and immediately submit `MsgRegisterERC20` and `MsgConvertERC20` with no governance/relayer/validator involvement, making this trivially and repeatably triggerable by any unprivileged user on a chain running with default parameters.

### Recommendation
Do not treat contract-reported balances as ground truth for minting native supply. Options:
- Track escrowed ERC20 balances independently (e.g., via internal accounting keyed off the actual state-diff observed in the EVM state transition/journal, not another self-reported call) rather than trusting `balanceOf`.
- Restrict permissionless registration to contracts that pass stricter, execution-trace-based verification (e.g. require observing an actual state change to storage slots consistent with a standard ERC20 layout, or require registration by governance for the native-mint pathway) similar to how the Napier report recommends adding explicit on-chain verification of pool parameters instead of trusting off-chain vetting.
- Consider disabling `PermissionlessRegistration` by default and/or adding a bytecode allow-list / audited-template check before contracts obtain minting-eligible `OWNER_EXTERNAL` token-pair status.

### Proof of Concept
1. Attacker deploys a malicious ERC20-like contract `Evil` where:
   - `transfer(to, amount)` always returns `true` and does not decrement `msg.sender`'s balance or increment `to`'s balance in real storage.
   - `balanceOf(module)` returns a value pre-computed to equal `lastQueriedBalance + amount` (tracked via a separate internal counter incremented on every `transfer` call, regardless of real transfer effects), so the pre/post invariant check in `convertERC20IntoCoinsForNativeToken` always passes.
   - `name()`, `symbol()`, `decimals()` return plausible values (e.g., "FakeUSD", "FUSD", 18).
2. Attacker submits `MsgRegisterERC20{Signer: attacker, Erc20Addresses: [Evil]}` — succeeds because `PermissionlessRegistration` is true by default (`x/erc20/keeper/msg_server.go:326-345`).
3. Attacker submits `MsgConvertERC20{ContractAddress: Evil, Amount: 1_000_000, Receiver: attacker}`.
4. `convertERC20IntoCoinsForNativeToken` calls `Evil.transfer(module, 1_000_000)` (no real value moved), then checks `Evil.balanceOf(module)` which returns the crafted value passing the invariant check (`x/erc20/keeper/msg_server.go:113-130`).
5. `k.bankKeeper.MintCoins` mints `1_000_000` new native coins of the fake denom and sends them to the attacker's receiver (`x/erc20/keeper/msg_server.go:132-140`).
6. Attacker now holds real, spendable native Cosmos coins with zero backing, repeatable at will.

func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

// QueryERC20 returns the data of a deployed ERC20 contract
func (k Keeper) QueryERC20(
	ctx sdk.Context,
	contract common.Address,
) (types.ERC20Data, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI

	// Name - with fallback support for bytes32
	name, err := k.queryERC20String(ctx, erc20, contract, "name")
	if err != nil {
		return types.ERC20Data{}, err
	}

	// Symbol - with fallback support for bytes32
	symbol, err := k.queryERC20String(ctx, erc20, contract, "symbol")
	if err != nil {
		return types.ERC20Data{}, err
	}

	// Decimals - standard uint8, no fallback needed
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, false, nil, "decimals")
	if err != nil {
		return types.ERC20Data{}, err
	}

	var decimalRes types.ERC20Uint8Response
	if err := erc20.UnpackIntoInterface(&decimalRes, "decimals", res.Ret); err != nil {
		return types.ERC20Data{}, errorsmod.Wrapf(
			types.ErrABIUnpack, "failed to unpack decimals: %s", err.Error(),
		)
	}

	return types.NewERC20Data(name, symbol, decimalRes.Value), nil
}

// BalanceOf queries an account's balance for a given ERC20 contract
func (k Keeper) BalanceOf(
	ctx sdk.Context,
	abi abi.ABI,
	contract, account common.Address,
) *big.Int {
	res, err := k.evmKeeper.CallEVM(ctx, abi, types.ModuleAddress, contract, false, nil, "balanceOf", account)
	if err != nil {
		return nil
	}

	unpacked, err := abi.Unpack("balanceOf", res.Ret)
	if err != nil || len(unpacked) == 0 {
		return nil
	}

	balance, ok := unpacked[0].(*big.Int)
	if !ok {
		return nil
	}

	return balance
}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}
