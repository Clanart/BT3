### Title
Unauthenticated OP_RETURN payer attribution in payout tx lets anyone frame an operator for a payout they never funded - (File: core/src/verifier.rs)

### Summary
`Verifier::update_finalized_payouts` attributes a withdrawal's payout to whichever operator's x-only pubkey appears in the payout transaction's OP_RETURN output, with zero validation that the named operator actually broadcast or funded that transaction. Because the user's withdrawal signature uses `SinglePlusAnyoneCanPay` (which only commits to the input and the same-index output), anyone holding the withdrawal UTXO's key — including the withdrawer themselves — can construct and broadcast a payout transaction naming an arbitrary, uninvolved operator in the OP_RETURN, without that operator ever calling `Operator::withdraw`.

### Finding Description
The broken binding: `payout_payer_operator_xonly_pk(withdrawal_id) == operator_who_actually_funded_and_broadcast(withdrawal_id)`. This is violated because attribution is derived purely from unauthenticated OP_RETURN bytes.

Path:
1. A withdrawer registers a withdrawal on the Citrea bridge contract, naming their own dust UTXO as `withdrawal_utxo` (only the outpoint is recorded on L2, per `collect_withdrawal_utxos` in [1](#0-0) ). This gets synced into `withdrawals.withdrawal_utxo_txid/vout` via `update_withdrawal_utxo_from_citrea_withdrawal` [2](#0-1) .
2. The user's off-chain signature for the payout input is required to be `TapSighashType::SinglePlusAnyoneCanPay`, enforced in `parse_withdrawal_sig_params` [3](#0-2) . This sighash type commits only to the input being spent and the output at the same index (output 0, the user payout) — it does **not** cover the anchor output or the OP_RETURN output that names the fronting operator, as built in `create_payout_txhandler` [4](#0-3) .
3. Since the withdrawer holds the private key for their own dust withdrawal UTXO and the SinglePlusAnyoneCanPay signature they generate, they can construct their own valid transaction spending that same UTXO with the same output[0] amount/script (satisfying the signature), but with an arbitrary OP_RETURN naming honest operator `H`'s x-only pubkey, and broadcast it directly to Bitcoin — completely bypassing any operator's `withdraw` RPC.
4. `Verifier::update_finalized_payouts` scans confirmed transactions spending tracked withdrawal UTXOs (`get_payout_txs_for_withdrawal_utxos`), parses the first OP_RETURN, and blindly writes it as the payer: [5](#0-4) . No check exists that this operator actually signed, funded, or even knew about the transaction.
5. This record is later trusted by `PayoutCheckerTask::run_once`, which queries `get_first_unhandled_payout_by_operator_xonly_pk` for operator `H` and, finding this forged record, automatically calls `Operator::handle_finalized_payout` on `H`'s behalf [6](#0-5) , producing a real kickoff transaction and eventually marking the withdrawal `is_payout_handled = true` for `H`.
6. When verifiers check this kickoff via `is_kickoff_malicious`, they only verify that the DB-recorded `operator_xonly_pk` equals the kickoff's operator and that the committed payout blockhash matches — both trivially true because the attacker's forged transaction is a real, confirmed Bitcoin transaction [7](#0-6) . There is no check that `H`'s own wallet contributed any funds to the payout transaction.

Root cause: the protocol treats the OP_RETURN operator-attribution field as authoritative while it is explicitly outside the coverage of the only signature required to spend the withdrawal UTXO.

### Impact Explanation
An honest operator `H` can be made to believe (and have their automation act on) a payout they never made, causing `Operator::handle_finalized_payout` to construct and broadcast a real kickoff transaction claiming reimbursement (the full bridge deposit amount) for a withdrawal that was never actually funded by `H`. If verifiers accept the kickoff (which they will, since the existing checks in `is_kickoff_malicious` pass), bridge/round funds are paid out to `H` for a service never rendered — "an operator reimbursed for a payout it never funded." Simultaneously, the withdrawal becomes permanently marked `is_payout_handled = TRUE` tied to a dust-value transaction, so the withdrawer never receives their real intended payout and no other operator can legitimately front it afterward — freezing the true reimbursement path. This is repeatable for every withdrawal a malicious withdrawer registers, and can target any operator whose public xonly key is known (all operator keys are public).

### Likelihood Explanation
Preconditions are minimal and fully within the declared attacker capability set: control of a withdrawal UTXO's private key (trivial — it's the withdrawer's own dust UTXO), knowledge of a target operator's public xonly key (public), and the ability to register a withdrawal and broadcast a Bitcoin transaction. Cost is a few hundred sats of dust plus mining fees — no operator, verifier, or aggregator cooperation is required. This is deterministically reproducible for every withdrawal.

### Recommendation
Do not treat the OP_RETURN operator field as authoritative attribution. Options:
- Require the payout transaction's OP_RETURN output (and/or anchor) to be covered by a signature from the claiming operator (e.g., require operator to co-sign an output committing to their own pubkey, or use `SIGHASH_ALL`/`SIGHASH_SINGLE` scoped to include the OP_RETURN via an additional operator-controlled input/output pair authenticated by the operator's key).
- Alternatively, cross-check in `update_finalized_payouts`/`is_kickoff_malicious` that the additional funding inputs of the payout transaction actually originate from the claimed operator's known address(es)/collateral wallet before trusting the OP_RETURN attribution.
- At minimum, require operators to independently attest (e.g., via a DB record populated only through the operator's own `withdraw` RPC call) rather than deriving payer identity solely from unauthenticated on-chain OP_RETURN bytes.

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;
