### Title
Flash-manipulable WOM/mWOM pool ratio lets any caller bypass `SmartWomConvert`'s buyback safeguard - (File: `wombat/SmartWomConvert.sol`)

### Summary
This mirrors the Tracer `Insurance.sol`/`Trader.sol` bug class: a rate that is supposed to reflect genuine market/pool state is computed on-the-fly from spot pool reserves and then immediately consumed to permanently record a favorable conversion outcome, all within a single, unprivileged transaction. In `SmartWomConvert.sol`, `smartConvert()` decides how much of an incoming WOM amount must be bought back on the open market (at real market price) versus minted directly 1:1 as `mWOM`, based on `currentRatio()` and `maxSwapAmount()` — both of which read live, flash-loan-manipulable state (`womMWomPool` spot price via `IWombatRouter.getAmountOut`, and `womAsset.cash()/liability()`). [1](#0-0) 

### Finding Description
`smartConvert()` is the "smart" fallback used (per its own comment) "mainly by wombat staking upon sending wom": [2](#0-1) 

It computes `convertRatio` from `currentRatio()`, the live spot exchange rate between `mWom` and `wom` fetched from the `womMWomPool` via the router's `getAmountOut`: [3](#0-2) 

If that live ratio is below `buybackThreshold` (90%), the contract is supposed to force a genuine market buyback of `mWOM` (protecting the peg) rather than freely minting new `mWOM` 1:1 via `IMWom(mWom).deposit()`. The size of that buyback is itself capped by `maxSwapAmount()`, which is derived from the live `cash`/`liability` of the `womAsset`: [4](#0-3) 

Both of these state reads (`getAmountOut` spot price, `cash()`/`liability()`) can be pushed in the same transaction by an attacker using a flash loan: performing a large swap through `womMWomPool` (or a large deposit/withdraw against the `womAsset`) immediately before the code path that triggers `smartConvert()` (via `WombatStaking`'s harvest/reward-conversion flow, which any unprivileged wallet can trigger by calling the public `harvest()` entry points on `WombatStaking`/pool helpers) will make `currentRatio() >= buybackThreshold`, forcing `convertRatio = DENOMINATOR` (i.e., zero buyback, 100% direct 1:1 mint) even though the "true" (post-manipulation) market price of `mWOM` is depegged. The attacker then reverses the swap/withdraws to repay the flash loan, having permanently locked in a favorable (fully-minted, no-buyback) conversion for that harvest cycle — exactly analogous to zeroing the Tracer insurance funding rate via a flash-filled pool immediately before `recordTrade`/`updateFundingRate`. [5](#0-4) 

### Impact Explanation
The buyback mechanism exists specifically to protect protocol solvency/peg integrity when `mWOM` trades below par — forcing the protocol to acquire real `mWOM` from the market rather than diluting supply via free 1:1 minting. By flash-manipulating the spot price/pool reserves at the exact moment `smartConvert()` executes, any unprivileged wallet can defeat this safeguard on every harvest cycle where they choose to intervene, causing the protocol to keep minting `mWOM` 1:1 during genuine depegs instead of performing the intended market buyback. This directly undermines protocol solvency/peg defense for the `mWOM` reserve — a repeated, cost-bounded (gas + flash-loan fee) exploit rather than a one-off grief, similar to the original finding's "repeatable via bot" concern that the judge flagged as Medium.

### Likelihood Explanation
Reachable entirely from an unprivileged wallet: no admin/governance role is needed to trigger a `WombatStaking` harvest, and Wombat pool swaps/deposits are permissionless. The economic viability depends on flash-loan fees and swap slippage versus the avoided buyback discount, mirroring the original report's caveat that viability is gas/fee dependent, but the mechanism itself is a genuine on-chain manipulation path, not a mocked-only or governance-only issue.

### Recommendation
Do not compute `convertRatio` from a single-block spot price/spot reserve read. Use a time-weighted average price (TWAP) for `currentRatio()`, and/or require `smartConvert()` calls to be non-atomic with any swap/deposit against `womMWomPool`/`womAsset` in the same transaction (e.g., disallow same-block interaction, or route conversions through a privileged/whitelisted relayer as Tracer ultimately did for `Trader.sol`).

### Proof of Concept
1. Attacker takes a flash loan of `WOM` (or `mWOM`).
2. Attacker swaps a large amount through `womMWomPool` (or deposits/withdraws against `womAsset`) to push `currentRatio()` above `buybackThreshold` (9000) and/or to widen `womLiability - womCash` favorably. [1](#0-0) 
3. Attacker (or the protocol's own scheduled harvest, which anyone can trigger) causes `WombatStaking` to call `smartConvert()`, which now computes `convertRatio = DENOMINATOR`, skipping the market buyback and minting 100% of the WOM as `mWOM` 1:1. [6](#0-5) 
4. Attacker reverses the swap/withdrawal and repays the flash loan, having captured the mispriced conversion.

Note: I was unable to fully trace, within the available tool budget, the exact call path/permission model connecting `WombatStaking.harvest()`/pool-helper `harvest()` to `smartConvert()` (grep found 6 references in `wombat/WombatStaking.sol` that I could not read in full before running out of iterations). If a background review confirms `smartConvert()` is only reachable by a privileged/whitelisted relayer (similar to Tracer's eventual fix of restricting `Trader.sol` to whitelisted relayers), this finding's likelihood should be downgraded accordingly.

    // should mainly used by wombat staking upon sending wom
    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
