## Finding [1](#0-0) 

### Title
Unbounded recursive `MofN` memo parsing in `PuzzleWithRestrictions.from_memo()` allows an attacker-crafted coin memo to crash wallet pool/plotNFT sync - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively re-parses nested `MofN` custody structures with no depth limit, size limit, or cycle/complexity guard. This memo blob is attacker-controlled data taken directly from a `CREATE_COIN` condition's memo on-chain, and it is fed into this recursive parser by `chia/pools/plotnft_drivers.py` during normal wallet sync of plotNFT/pool singletons.

### Finding Description
`PuzzleWithRestrictions.memo()` encodes a custody tree (potentially an `MofN` node whose members are themselves `PuzzleWithRestrictions` that can again be `MofN` nodes) into a CLVM `Program` blob attached as a coin memo [2](#0-1) . `from_memo()` is the inverse operation and recurses once per `MofN` member without any bound on nesting depth:

```
if further_branching:
    m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
    puzzle: MIPSComponent = MofN(
        m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
    )
``` [3](#0-2) 

Because `MofN.__post_init__` only validates `1 <= m <= n` and node uniqueness at the top of one level [4](#0-3) , nothing stops an attacker from constructing an arbitrarily deep chain of single-member `MofN(m=1, members=[...])` nodes, each one nested inside the previous member's memo. This produces a memo `Program` whose parse tree depth is fully attacker-controlled and unbounded by CLVM cost metering (memo parsing happens entirely in Python, off-chain, after the CLVM run already completed).

This memo is consumed by `PlotNFT.get_next_from_coin_spend()`, which reads the memo directly from an on-chain `CREATE_COIN` condition of a singleton spend during wallet sync:

```
unknown_inner_puzzle = PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())
``` [5](#0-4) 

The surrounding code only catches `ValueError` from this call, not `RecursionError`: [6](#0-5) 

A Python `RecursionError` raised deep inside `from_memo()`'s self-recursion is not a `ValueError` and will propagate up uncaught through the wallet's plotNFT/pool sync path.

This is conceptually analogous to CVE-2023-43645/GHSA-2hm9-h873-pgqh: OpenFGA lacked a cycle/depth bound on relationship-definition evaluation, letting a crafted authorization model exhaust resources on `Check`. Here, `from_memo()` lacks a depth/size bound on custody-tree evaluation, letting a crafted on-chain memo (fully attacker-controlled, embedded in any coin spend) exhaust the Python call stack during wallet-side parsing.

### Impact Explanation
Any coin spend that creates a coin whose puzzle hash matches (or is treated as matching, per the driver's heuristics) a tracked PlotNFT/pool singleton, with an attacker-crafted deeply-nested `MofN` memo, can trigger unbounded Python recursion in a wallet that is syncing/tracking that singleton. This is a spend-triggered halt of the affected wallet's plotNFT/pool-tracking logic (crash/`RecursionError` propagating out of `get_next_from_coin_spend`), which is reachable purely by submitting a spend bundle — no privileged position needed.

### Likelihood Explanation
Exploitation requires only the ability to submit a spend bundle that creates a coin with a crafted memo recognized by `get_next_from_coin_spend` as a candidate PlotNFT/pool singleton continuation; this is available to any wallet user or spend-bundle submitter tracking or receiving plotNFT-style coins. No special network position, key compromise, or consensus-level access is required, only knowledge of the memo encoding format (which is public, CHIP-0043 spec-namespaced) [7](#0-6) .

### Recommendation
Add an explicit maximum recursion depth (and/or total memo size/node count) check in `PuzzleWithRestrictions.from_memo()` before recursing into `MofN` members, raising a `ValueError` (not letting `RecursionError` occur) when the limit is exceeded. Additionally, broaden the exception handling in `PlotNFT.get_next_from_coin_spend()` to catch parsing failures (including `RecursionError`/`RuntimeError`) and convert them into the existing `GetNextPlotNFTError` path instead of letting them propagate.

### Proof of Concept
1. Construct a memo chain: start with a leaf `MemberHint`, wrap it in `PuzzleWithRestrictions(puzzle=UnknownMember(...))`, then wrap that in `MofN(m=1, members=[...])`, then wrap that whole structure again in another `PuzzleWithRestrictions` and `MofN(m=1, members=[...])`, repeating thousands of times.
2. Call `.memo()` on the outermost `PuzzleWithRestrictions` to produce the CLVM `Program` blob, per `custody_architecture.py:236-269`.
3. Embed that blob as the memo of a `CREATE_COIN` condition in a spend bundle for a coin whose singleton/launcher shape is recognized by `PlotNFT.get_next_from_coin_spend` (per `plotnft_drivers.py:415-513`), and submit the spend bundle.
4. Any wallet syncing that singleton and reaching the "look for memos" branch will call `PuzzleWithRestrictions.from_memo(...)` on the crafted blob, causing deep Python recursion (`RecursionError`) that is not caught by the surrounding `except ValueError` block, halting plotNFT/pool tracking for that wallet.

    @classmethod
    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(
                m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
            )
        else:
            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)

        return PuzzleWithRestrictions(
            nonce=nonce.as_int(),
            restrictions=[UnknownRestriction(hint) for hint in restriction_hints],
            puzzle=puzzle,
            additional_memos=additional_memos,
