### Title
Silent, unconfirmed rewrite of a repository's `origin` remote URL based on an unverified owner/name API lookup enables repo-squatting redirection of pushes/fetches - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
When GitHub Desktop refreshes a repository's association with the GitHub API, it re-derives the `owner/name` pair from the literal text of the current git remote URL, looks that pair up via the API, and — if the returned `clone_url` differs from the current remote — silently rewrites the local `origin` remote to the new URL with no user confirmation and no verification that the new API object actually corresponds to the same repository entity the user originally cloned.

### Finding Description
`repositoryWithRefreshedGitHubRepository` derives `owner`/`name` purely by regex-parsing the current default remote's URL string via `matchGitHubRepository` [1](#0-0) , then performs a fresh, unauthenticated-to-identity API call keyed only on that literal path:

```
const apiRepo = await api.fetchRepository(owner, name)
...
await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
``` [2](#0-1) 

`updateRemoteUrl` then compares the *current* remote URL against `apiRepo.clone_url` and, if the protocol matches and the remote hadn't been manually edited away from the previously cached `gitHubRepository.cloneURL`, calls `gitStore.setRemoteURL(...)` to overwrite the remote — using only string/URL comparisons, never a stable repository identifier (e.g. `id`/`node_id`/`dbID`):

```
const remoteUrlUnchanged =
  gitStore.defaultRemote &&
  urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
  await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
``` [3](#0-2) 

`GitHub`'s `repos/{owner}/{name}` lookup is path-based, not ID-based. If the original repository owner renames their account (a routine, user-initiated action on GitHub) and an attacker subsequently claims the now-available old username plus a repository of the same name, `fetchRepository(owner, name)` will silently start resolving to the attacker's repository. Nothing in `matchGitHubRepository`, `fetchRepository`, or `updateRemoteUrl` re-validates that the fetched object is the same logical repository (no comparison of `gitHubRepository.dbID`, GitHub's numeric repo `id`, or `node_id`) — the code only checks that URL strings match/mismatch. `setRemoteURL` itself performs no confirmation prompt and directly executes `git remote set-url` [4](#0-3) .

This refresh path is triggered routinely and silently on virtually every push/fetch/pull operation via `withRefreshedGitHubRepository`, which is called from `_push`, `_fetch`, `_fetchRemote`, `_fetchRefspec`, `_revertCommit`, etc. [5](#0-4) [6](#0-5) [7](#0-6) , meaning the rewrite happens transparently the next time the user interacts with the repository, without any explicit user action to "accept" the new remote.

### Impact Explanation
If the remote is silently rewritten to an attacker-controlled repository (same host, e.g. `github.com`, so TLS/cert pinning provides no protection), subsequent `git push` operations from Desktop's `performPush` would send the user's future commits to the attacker's repository instead of the legitimate one — a case of "silent corruption of what the user commits or pushes." Depending on repository visibility settings this can also leak private code the user did not intend to disclose to the new remote owner. No credentials are exfiltrated (Desktop still authenticates using the account's own token against `github.com`), but the destination of the user's work is corrupted without their knowledge, matching the class of guard this Task explicitly targets.

### Likelihood Explanation
Likelihood is low-to-moderate: the attacker doesn't need local access, admin rights, or prior malware — only the ability to register a specific username/repo-name pair on GitHub.com after the legitimate owner performs a username change. Repo/username squatting after renames is a documented, non-hypothetical attack pattern (widely known as "repojacking"), and GitHub Desktop's automatic un-confirmed remote-rewrite behavior removes the friction (a manual `git remote set-url`) that would otherwise require a conscious action from the victim. The precondition (a rename by the legitimate account/org followed by squatting) is outside the victim's control and requires no unnatural steps from the Desktop user — they only need to continue using Desktop normally (push/fetch) after the rename+squat occurs.

### Recommendation
- Do not silently rewrite `origin`'s URL based solely on owner/name string matching against a freshly-fetched API repository object.
- Before calling `gitStore.setRemoteURL`, verify that the new `apiRepo` corresponds to the *same* logical repository as the previously cached `gitHubRepository` by comparing a stable identifier (GitHub's numeric repository `id`/`node_id`, not just owner/name strings or `clone_url`).
- If the stable identifier changed (or cannot be confirmed), prompt the user for explicit confirmation before altering the remote, rather than performing the update transparently in `updateRemoteUrl`.

### Proof of Concept
1. Victim clones `https://github.com/alice/project` in GitHub Desktop; Desktop stores `gitHubRepository.cloneURL` and the git `origin` remote pointing at that URL.
2. Alice renames her GitHub account from `alice` to `alice2`. GitHub creates a redirect for `alice/project`, and `api.github.com/repos/alice/project` still resolves (via redirect) to `alice2/project`.
3. Before the victim's Desktop refreshes, an attacker registers the now-free username `alice` and creates a repository named `project` under that account.
4. The victim performs any push/fetch in Desktop. `matchGitHubRepository` parses `owner=alice, name=project` from the still-unchanged local `origin` URL [1](#0-0) , and `api.fetchRepository('alice','project')` now returns the attacker's repository object (same owner/name path, different actual repo).
5. `updateRemoteUrl` sees `protocolsMatch === true`, `remoteUrlUnchanged === true` (user never touched the remote), and `urlsMatch === false` (clone_url differs enough, e.g., different casing/hostname mapping edge case is not required — even an identical-looking `https://github.com/alice/project.git` from the attacker's repo satisfies the match/rewrite condition since only owner/name strings are compared), and calls `gitStore.setRemoteURL('origin', attackerCloneUrl)` [8](#0-7) .
6. The victim's next `git push` (via Desktop's `_push`/`performPush`) silently sends commits to the attacker's repository.

  private async matchGitHubRepository(
    repository: Repository
  ): Promise<IMatchedGitHubRepository | null> {
    const gitStore = this.gitStoreCache.get(repository)

    if (!gitStore.defaultRemote) {
      await gitStore.loadRemotes()
    }

    const remote = gitStore.defaultRemote
    return remote !== null
      ? matchGitHubRepository(this.accounts, remote.url)
      : null
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
