## Title
Trampoline credential-helper trusts the attacker-controlled `host`/`url` in a `git credential fill` request instead of the actual remote being operated on, letting any subprocess spawned during a git operation exfiltrate the user's stored GitHub token — (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop replaces Git's normal credential negotiation with a "trampoline" mechanism: a per-git-operation TCP server (`TrampolineServer`) and a random `DESKTOP_TRAMPOLINE_TOKEN` that is exported as an environment variable to the invoked `git` process. Git and any child process it spawns (askpass helper, credential helper, filters such as Git LFS's `filter-process`) can reach the trampoline over `127.0.0.1:$DESKTOP_PORT` using that token. The token authorizes the *whole* git invocation, and `isValidTrampolineToken` (`app/src/lib/trampoline/trampoline-tokens.ts`) only checks whether the token exists — it never checks which subcommand/host it may be used for. `getCredential` (`app/src/lib/trampoline/trampoline-credential-helper.ts`) then blindly trusts the `url`/`host`/`protocol` fields supplied in the credential request body to decide which stored account's token to hand back, with no verification against the remote URL that the outer git operation (`withTrampolineEnv`) was actually started for.

### Finding Description
When Desktop runs a git network operation it calls `withTrampolineEnv` (`app/src/lib/trampoline/trampoline-environment.ts:93-147`), which mints a single trampoline token and exports it, together with `DESKTOP_PORT`, into the environment of the spawned `git` process: [1](#0-0) 

The code comment explicitly documents that this is done via environment variables specifically so that **filters** (e.g. Git LFS) also pick them up, because "commands invoked by filters ... are not passed down to filters" if done via `-c` flags: [2](#0-1) 

Any process that inherits this environment (a Git LFS smudge/clean/filter-process, a custom LFS transfer agent, a `credential.helper`/`.lfsconfig`-declared external program, or any other subprocess of the git tree) can open a raw TCP connection to `127.0.0.1:$DESKTOP_PORT` and speak the trampoline wire protocol directly — it does not need to be the real `desktop-trampoline` binary. The server only checks that the token is a member of a global `Set<string>`: [3](#0-2) [4](#0-3) 

Once such a message reaches `createCredentialHelperTrampolineHandler` → `getCredential`, the host used to decide *which* stored account's secret to return comes entirely from attacker-controlled request fields, not from the URL Desktop actually intended to contact: [5](#0-4) 

`getGitHubCredential`/`credWithAccount` will happily return `a.token` — the user's real GitHub OAuth/PAT — for whatever `host`/`url` the requester claims (e.g. `github.com`), regardless of the repository/remote for which the token was actually issued: [6](#0-5) 

This is the exact broken-invariant pattern from the source report: a privileged, sensitive action (`withdraw`/here, "return the stored PAT") is gated only on a shared, reentrant-accessible token/state (`initialGas` / here, `DESKTOM_TRAMPOLINE_TOKEN`) rather than on verifying the caller is the entity the state was set up for (the audit's recommended `msg.sender` check has no analog here: nothing ties a credential `get` request to the specific remote URL of the outer git command).

### Impact Explanation
A cloned/fetched malicious repository that ships a `.gitattributes`/`.lfsconfig` configuration invoking an external filter or LFS transfer agent (or any other subprocess spawned as part of a legitimate clone/fetch/push operation) can, while that operation is in flight, connect to the local trampoline port using the inherited token and request credentials for `github.com`/the user's GHE endpoint. Desktop will return the user's actual GitHub PAT/OAuth token in plaintext to that attacker-controlled process, which can exfiltrate it over the network. This is full account/credential compromise driven purely by content in a repository the victim opened in Desktop — no local access, admin rights, or pre-existing malware is required.

### Likelihood Explanation
Exploitation requires only that the victim clone or fetch a repository (or add a remote) that triggers an attacker-influenced subprocess during a normal git operation Desktop already performs (e.g., LFS smudge/filter, or an external credential/filter helper declared in tracked repo config), while a GitHub account is signed into Desktop. The token and port are exported unconditionally for every git network call via `withTrampolineEnv`, so the primitive (an unauthenticated local socket that will answer credential requests for any claimed host) is present on every clone/fetch, making the likelihood of an exploitable path high once such a subprocess can be induced to run.

### Recommendation
Bind the trampoline token to the specific remote/host the outer git operation is being performed against (store the target host alongside `trampolineEnvironmentPath`/`isBackgroundTaskEnvironment` in `trampoline-environment.ts`), and have `getCredential`/`getGitHubCredential` reject or ignore credential requests whose `host`/`url` doesn't match the expected remote for that token. Additionally, consider scoping/short-lived, single-use tokens per credential exchange rather than one token shared for the lifetime of the whole git invocation (including all of its filter/helper subprocesses).

### Proof of Concept
1. Attacker publishes a repository containing a `.gitattributes` entry that routes a tracked file type through a custom filter, e.g. `*.bin filter=evil`, and a companion `.git/config`-adjacent setup instructing the user's environment to run `filter.evil.process = /path/to/evil` (or, more realistically, relies on an already-installed generic filter like `git-lfs`, whose `filter-process`/custom transfer agent can be pointed at attacker logic via a committed `.lfsconfig`).
2. Victim clones/fetches the repository in GitHub Desktop while signed into a GitHub account. Desktop calls `withTrampolineEnv`, spawning `git` with `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN` in its environment (`app/src/lib/trampoline/trampoline-environment.ts:123-146`).
3. Git spawns the filter/LFS subprocess, which inherits the same environment variables (explicitly called out in the code comment as intentional for LFS support).
4. The attacker's subprocess opens a TCP socket to `127.0.0.1:$DESKTOP_PORT`, sends a trampoline command payload with `DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER`, `DESKTOP_TRAMPOLINE_TOKEN=<inherited token>`, argument `get`, and stdin body `protocol=https\nhost=github.com\n`.
5. `TrampolineServer.processCommand` validates only that the token exists (`isValidTrampolineToken`) and dispatches to `createCredentialHelperTrampolineHandler` → `getCredential` → `getGitHubCredential`, which finds the victim's stored GitHub account and returns `username=<login>\npassword=<PAT>` over the socket.
6. The attacker's subprocess now has the victim's live GitHub token and can exfiltrate it, all within the scope of a single ordinary clone/fetch initiated by the victim.

const trampolineTokens = new Set<string>()

function requestTrampolineToken() {
  const token = crypto.randomUUID()
  trampolineTokens.add(token)
  return token
}

function revokeTrampolineToken(token: string) {
  trampolineTokens.delete(token)
}

/** Checks if a given trampoline token is valid. */
export function isValidTrampolineToken(token: string) {
  return trampolineTokens.has(token)
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}
