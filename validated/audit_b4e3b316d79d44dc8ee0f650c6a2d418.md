### Title
Attacker-manipulable AMM spot price in `_bullMGP` lets a self-sandwiched `incentiveDeposit(_bullMode=true)` call mint an inflated vlMGP lock from the campaign's own BUSD reserve - (File: `wombat/ArbWomUp2.sol`)

### Summary
`incentiveDeposit` with `_bullMode=true` swaps the contract's own BUSD reward budget for MGP via a single-hop PancakeSwap-style router call and locks `amounts[1]` (plus a bonus) directly into `vlMGP` for the caller. Since `amounts[1]` is taken straight from the spot AMM output with no oracle/TWAP check, and the caller fully controls both the trigger transaction and the `_minMGPRec` floor, an attacker can move the BUSD/MGP pool price in their favor immediately before calling `incentiveDeposit` and reverse it immediately after, causing the contract to buy MGP at an artificially depressed price and lock a disproportionately large MGP amount funded entirely by the campaign's BUSD reserve.

### Finding Description
In `_bullMGP`: [1](#0-0) 

`_busdAmount` is `rewardToSend`, computed by `getRewardAmount` purely from the caller's own tiered WOM deposit (not the attacker's BUSD), and pulled from the contract's own `busd` balance: [2](#0-1) [3](#0-2) 

`amounts[1]` is the router's raw swap output at current pool spot price, with no fair-value/oracle cross-check. The only bound is `_minRec`, the attacker-supplied minimum, which only prevents the attacker from getting *less* than they specify - it does not, and cannot, prevent the attacker from causing the swap to yield *more* MGP than fair value by manipulating the pool beforehand.

Exploit flow (single attacker-controlled bundle/atomic contract, no privileged role needed):
1. Attacker holds MGP and BUSD, and calls `incentiveDeposit` from a helper contract (or a bundled sequence of their own transactions) that first swaps MGP → BUSD on the same router/pool to depress the MGP price (increase MGP reserve, decrease BUSD reserve) in the pool used by `ROUTER`.
2. In the same block/bundle, attacker calls `incentiveDeposit(_amount, _minMGPRec, true)`. `_bullMGP` swaps the contract's `rewardToSend` BUSD into MGP at the depressed price, yielding an inflated `amounts[1]`; `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` is locked to the attacker via `vlMGP.lockFor`.
3. Attacker reverses the initial trade (BUSD → MGP) to restore the pool price and recover most of the round-trip cost, keeping the manipulation net-profitable if the extra locked MGP value exceeds pool fees/slippage cost.

No modifier in the reachable path stops this: `nonReentrant` only prevents re-entrant calls within one transaction, not a multi-transaction price manipulation; `whenNotPaused` is unrelated; there is no receipt-token or reward-index accounting that ties `mgpAmountToLcok` back to a fair BUSD value - the contract simply trusts the AMM's instantaneous quote.

### Impact Explanation
This is theft of unclaimed yield: the vlMGP position locked via `vlMGP.lockFor` is minted from the campaign's finite BUSD reserve (`busdleft` in `getRewardAmount`) and is meant to represent a fair-market MGP purchase for the user's WOM-deposit tier. By manipulating the spot price at the moment of the swap, the attacker extracts more locked MGP value than their real WOM contribution/tier entitles them to, directly depleting the shared BUSD reward pool available to other legitimate depositors, at the same real BUSD cost to the campaign.

### Likelihood Explanation
Feasibility depends on: (a) the depth/liquidity of the BUSD/MGP pool relative to `rewardToSend` (higher-tier deposits produce larger swaps, amplifying achievable price impact), (b) attacker capital sufficient to temporarily move the pool and absorb round-trip slippage/fees, and (c) ability to execute the three legs atomically or near-atomically (trivial via a single attacker-deployed contract performing pre-trade, `incentiveDeposit` call, and post-trade in one transaction, entirely with unprivileged EOA/contract calls). No admin/governance/oracle-manipulation rights are required - only ordinary AMM trading capability, which is a realistic and repeatable precondition for any attacker holding modest BUSD/MGP capital.

### Recommendation
Do not rely on the raw AMM `amounts[1]` output for reward sizing. Options: (1) cap `mgpAmountToLcok` by a protocol-computed fair value (e.g., TWAP-based oracle or a hard-coded/owner-set reference price) and take the minimum of that and the actual swap output; (2) split large swaps or use a private/atomic-protected execution path (e.g., only allow admin-triggered buybacks, not user-triggered swaps sized by user-controlled deposit tiers); (3) enforce a maximum acceptable output relative to a reference price, not just a caller-supplied minimum, so the contract itself bounds slippage in both directions.

### Proof of Concept
Foundry fork test against BSC mainnet state:
1. Fork at a block where the real BUSD/MGP PancakeSwap pool exists with realistic liquidity; deploy/attach `ArbWomUp2` with real `busd`, `mgp`, `vlMGP`, `ROUTER` addresses and fund it with a BUSD reward reserve.
2. Deploy an attacker contract holding MGP and BUSD.
3. Baseline: call `incentiveDeposit(_amount, 0, true)` from a neutral EOA with no pre-trade, record `mgpAmountToLcok` from the `VLMGPRewarded` event → "fair" locked amount.
4. Attack: from the attacker contract, atomically: (a) swap MGP → BUSD on the same pool to depress MGP price, (b) call `incentiveDeposit(_amount, 0, true)`, (c) swap BUSD → MGP to restore price.
5. Assert the attacker's locked MGP amount (step 4b) exceeds the baseline (step 3) for the same WOM deposit/tier, and that the attacker's net MGP+BUSD position after step 4c is profitable (extra locked MGP value minus round-trip cost > 0), demonstrating disproportionate extraction from the campaign's BUSD reserve.

    function getRewardAmount(uint256 _amount, address _account) external view returns (uint256) {
        if (_amount == 0 || rewardMultiplier.length == 0) return 0;
        uint256 accumulated = _amount + userWOMDeposited[_account];

        uint256 rewardAmount = 0;
        uint256 i = 1;
        while (i < rewardTier.length && accumulated > rewardTier[i]) {
            rewardAmount +=
                (rewardTier[i] - rewardTier[i - 1]) *
                rewardMultiplier[i - 1];
            i++;
        }
        rewardAmount += (accumulated - rewardTier[i - 1]) * rewardMultiplier[i - 1];

        uint256 busdReward = (rewardAmount / DENOMINATOR) - this.calDoubledCounted(_account);
        uint256 busdleft = IERC20(busd).balanceOf(address(this));

        return busdReward > busdleft ? busdleft : busdReward;
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
