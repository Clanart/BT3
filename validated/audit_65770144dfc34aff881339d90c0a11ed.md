## Analysis

The core broken invariant in the external report is: **an execution path that moves value/state (`_hooks`) is exposed without the same access-control/validation applied to the parallel path (`_interactions`)**, letting an unprivileged actor drive execution through the unguarded path.

The direct local analog is `CallDispatcher.sol`, the shared execution primitive used by `IntentGatewayV2` (predispatch/postdispatch order calldata) and other Hyperbridge apps (e.g. HyperFungibleToken calldata execution) for "arbitrary composable calldata."### Title
`CallDispatcher.dispatch()` has no caller/beneficiary validation, letting anyone drain any dust or ETH sitting on the shared dispatcher - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`IntentGatewayV2`'s order-calldata execution flow (`IntentsBase._execute`, `_fillSameChain`/`_fillCrossChain`, and the predispatch flow in `IntentGatewayV2.placeOrder`) validates and accounts for every "interaction" performed *on the gateway* (escrow accounting, dust events, beneficiary/protocol split), but the shared `CallDispatcher.sol` that actually executes the attached arbitrary calldata ("hooks") is a completely unauthenticated, stateless, permissionless singleton: `dispatch(bytes memory encoded) external` [1](#0-0)  has no `onlyGateway`/`msg.sender` check at all - anyone can call it directly with an arbitrary `Call[]` and force it to move out any ETH or ERC-20 balance it happens to hold at call time.

This mirrors the reported bug class exactly: the "interactions" path (`fillOrder` → escrow release → `_execute` sweep) is fully validated, while the parallel "hooks" execution surface (`CallDispatcher.dispatch`) is left open, letting an attacker bypass all of the gateway's accounting checks by acting directly on the dispatcher.

### Finding Description
`CallDispatcher` is documented as a shared, reusable execution primitive: "Existing `CallDispatcher` deployments are listed on the contract addresses page," and is used by both `IntentGatewayV2` (predispatch/postdispatch calldata) and other apps such as `HyperFungibleToken` for calldata execution. Its `dispatch()` function is `external` with zero access control: [2](#0-1) 

Every legitimate caller (`IntentGatewayV2`/`IntentsBase`) treats the dispatcher as a temporary escrow: it transfers funds in, calls `dispatch()`, then sweeps whatever remains back out via a second `dispatch()` call built from a "sweepCalls" array scoped only to the order's known `output.assets`/`predispatch.assets` [3](#0-2)  and [4](#0-3) .

Because `dispatch()` performs no `msg.sender` restriction and no validation that the caller is the intended gateway or that the target/beneficiary is the order's rightful party, any value that is not captured by the gateway's own sweep logic — for example:
- any token not listed in `order.output.assets`/`predispatch.assets` that the postdispatch/predispatch calldata itself causes to land on the dispatcher (e.g. a swap that returns a reward token, an airdrop, or unswept dust from a previous order due to a race/partial fill), or
- plain ETH sent to the dispatcher's `receive()` (also unrestricted) —

can be permissionlessly pulled out by *any* address, not just the `IntentGatewayV2` instance that funded it. An attacker simply calls `CallDispatcher.dispatch(abi.encode([Call({to: token, value: 0, data: transfer(attacker, balance)})]))` or, for ETH, `Call({to: attacker, value: address(dispatcher).balance, data: ""})`.

This is the direct analog of the reported `_hooks` bug: the `_interactions`-equivalent path (`fillOrder`/`_execute`/escrow accounting) enforces beneficiary correctness and one-time settlement, but the `_hooks`-equivalent path (raw `CallDispatcher.dispatch`) enforces nothing, so an attacker bypasses all of the gateway's invariants by hitting the dispatcher directly.

### Impact Explanation
Any residual balance held by `CallDispatcher` — dust from partial fills, reward/airdrop tokens produced by hook execution, native ETH sent to it — belongs to the protocol/beneficiaries per the documented dust-collection design (`DustCollected` events, protocol treasury sweep). Because `dispatch()` is unauthenticated, this value can be redirected to an arbitrary attacker-controlled address instead of the rightful beneficiary/protocol treasury. This is unauthorized transaction execution and theft/loss of funds on a shared, security-critical settlement component of the Intent Gateway, matching the bounty's "stealing or loss of funds" / "unauthorized transaction or execution" criteria.

### Likelihood Explanation
The vulnerability requires no privileged role, no relayer/prover compromise, and no front-running window — `dispatch()` is a plain public function with no guard, so exploitation is a single unprivileged transaction whenever the dispatcher holds any non-zero balance. The dispatcher is shared across order fills (predispatch and postdispatch use the same singleton), and it also holds ETH by design (`receive() external payable`), so any leftover value from any past interaction is persistently drainable until swept — the attacker only needs to win the race to call `dispatch()` before the legitimate sweep completes, or exploit any code path where the sweep is incomplete (e.g., a token not enumerated in `order.output.assets`).

### Recommendation
Add caller/ownership validation to `CallDispatcher`:
- Restrict `dispatch()` to a registered set of authorized callers (e.g., an `onlyGateway`/allowlist modifier configured at deploy time, analogous to `onlyHost` used elsewhere in the codebase), or
- Make `CallDispatcher` non-shared/ephemeral per order (deploy a minimal proxy per fill) so no cross-order balance can accumulate, or
- At minimum, restrict the `receive()` function and require `dispatch()` to assert `address(this).balance`/token balances are fully swept back to `msg.sender` (the calling gateway) atomically, and disallow arbitrary third-party calls to `dispatch()`.

### Proof of Concept
1. Any `IntentGatewayV2` order with postdispatch calldata (`order.output.call`) is filled; the attached calldata executes a swap on `CallDispatcher` that returns a secondary reward token not included in `order.output.assets` — this token remains stuck on `CallDispatcher` after `_execute`'s sweep (which only sweeps `order.output.assets`) [3](#0-2) .
2. An attacker (unrelated to the order) calls `CallDispatcher.dispatch(abi.encode([Call({to: rewardToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, rewardToken.balanceOf(dispatcher))})]))` directly.
3. Since `dispatch()` performs no caller check [2](#0-1) , the call succeeds and the reward tokens (which should have accrued to the protocol per the `DustCollected` design) are transferred to the attacker instead.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
