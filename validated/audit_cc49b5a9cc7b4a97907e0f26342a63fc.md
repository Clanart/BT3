### Title
Forged empty Schnorr aggregate accepted as valid signature - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::read` accepts an explicitly empty aggregate consisting only of a zero scalar, and `verify` accepts it against an empty key/challenge list because the final equation reduces to identity. [1](#0-0) [2](#0-1) 

### Finding Description
Deserialization reads the attacker-controlled `u32` nonce count, permits zero, and then reads `s` without rejecting zero. [1](#0-0)  Verification checks only that the aggregate length equals the supplied list length, contributes no statement pairs when both are empty, and evaluates `(-0) * G`, which is the group identity. [3](#0-2)  This is inconsistent with `SchnorrAggregator::complete`, which intentionally returns `None` rather than producing an aggregate when no signatures were supplied. [4](#0-3) 

### Impact Explanation
An unauthenticated party can submit 36 bytes encoding an empty `SchnorrAggregate` and cause `verify(dst, &[])` to return true without knowledge of any private key, nonce, or valid signature. [1](#0-0) [2](#0-1)  If aggregate verification is used as evidence that a nonempty authorization or signing operation occurred, this constitutes a forged proof/signature acceptance. [5](#0-4) 

### Likelihood Explanation
The malicious input is deterministic, canonical, short, and does not require control over keys, messages, RNG state, or other participants. [1](#0-0)  Exploitation requires a verifier to call `verify` with an empty `keys_and_challenges` list for an attacker-supplied aggregate; the API does not itself reject that inconsistent state. [6](#0-5) 

### Recommendation
Reject empty aggregates in both `SchnorrAggregate::read` and `SchnorrAggregate::verify`, or at minimum make `verify` return false when `keys_and_challenges.is_empty()`. [1](#0-0) [3](#0-2)  The deserialization format does not know the expected aggregate size, so the verifier-side check is the invariant that must be enforced. [1](#0-0) 

### Proof of Concept
```rust
// crypto/schnorr/src/aggregate.rs accepts a four-byte zero count
// followed by a canonical zero scalar.
let encoded = [0u8; 36];

let aggregate =
  SchnorrAggregate::<Secp256k1>::read(&mut encoded.as_slice()).unwrap();

// Currently passes even though no signature was supplied.
assert!(aggregate.verify(b"example aggregate DST", &[]));
```
`SchnorrAggregator::complete` cannot legitimately create this value because it returns `None` for an empty input set. [4](#0-3)
