### Title
DataLayer Mirror URLs Are Unvalidated Attacker-Controlled Outbound Request Targets, Enabling SSRF/Forced-Authentication Against Any Subscribing Node - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
The OpenBullet2 CVE-2026-39908 bug class is: an attacker supplies a path/URL that an application later uses, unvalidated, as the target of an *outbound authenticated network request* triggered automatically by a background job, disclosing/leaking credentials or forcing connections to attacker infrastructure. Chia's DataLayer mirror mechanism has the same structural flaw: any wallet user can publish an on-chain "mirror" record pointing at an *arbitrary* `launcher_id` (not necessarily their own store) with an *arbitrary URL string*, and any other node that subscribes to that store will automatically fetch from that attacker-chosen URL with no scheme/host validation.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a mirror coin whose puzzle memoizes `[launcher_id, *urls]` and is funded purely from the caller's own standard wallet balance — it performs no check that `launcher_id` is a store the caller owns: [1](#0-0) 

This is exposed via `dl_new_mirror` RPC without any ownership validation: [2](#0-1) 

and the underlying request type places no constraint on the `urls` field (plain `list[str]`): [3](#0-2) 

Any DataLayer node that is subscribed to (or owns) that `launcher_id` periodically calls `update_subscriptions_from_wallet()`, which pulls mirror URLs straight from chain state with no filtering of scheme or destination and feeds them into the local subscription table: [4](#0-3) 

The sync loop then uses these URLs to make live outbound HTTP requests via `fetch_and_validate()` → `http_download()`/`get_downloader()`, with no allow-list, scheme restriction, or SSRF protection: [5](#0-4) [6](#0-5) [7](#0-6) 

The project's own internal notes flag mirror/plugin URLs as an untrusted external input, but only in the context of *downloaded data* being verified against wallet roots — not in the context of the request itself being sent to an attacker-chosen destination: [8](#0-7) 

This is directly analogous to the UNC-path bug class: the vulnerable application (here, the DataLayer service, potentially any node subscribed to a public/shared store) makes an unconditioned outbound connection to a string supplied entirely by an unprivileged third party, exposing the requesting node's IP, HTTP headers, and (for downloader plugins reaching internal services or `file://`/loopback/metadata endpoints if the aiohttp session isn't restricted) potentially internal resources or credentials, and enabling SSRF against internal infrastructure of anyone who subscribes to a targeted store.

### Impact Explanation
An attacker who controls no infrastructure privilege beyond a funded wallet can:
1. Publish a mirror pointing any victim-owned/subscribed `launcher_id` at an attacker-controlled or internal-network URL.
2. Force every node subscribing to that store (a normal, unprivileged Data Layer client action) to issue outbound HTTP requests to that URL on its own periodic sync cadence, without any user interaction beyond the pre-existing subscription.
3. Use this to fingerprint/probe internal network services reachable from the victim node (SSRF), or to harvest connection metadata (IP, headers, timing) from victims, analogous to the credential-disclosure primitive in the reported CVE.

This does not create unsigned coin movement or consensus divergence by itself, but it is a concrete, remotely triggerable disclosure/SSRF primitive reachable by any unprivileged wallet/DataLayer participant against any other subscriber of a shared store.

### Likelihood Explanation
Likelihood is high: creating a mirror only requires paying the standard mirror-coin amount plus a fee from one's own wallet — no permission on the target store is checked, and DataLayer's periodic background sync (`periodically_manage_data()` → `update_subscription()`) automatically discovers and dereferences these URLs with no operator confirmation step.

### Recommendation
- Restrict mirror URL schemes to `http(s)` only and reject internal/loopback/link-local/metadata-service addresses before storing/using them (SSRF allow-listing), mirroring the `enforce_https`-style checks already used elsewhere (e.g., pool URL validation in `chia/cmds/plotnft_funcs.py`).
- Consider requiring store ownership (or explicit opt-in trust) before a mirror URL for a given `launcher_id` is added to the local subscription/download rotation, rather than trusting any on-chain mirror unconditionally.
- Apply DNS-rebinding-safe, redirect-restricted HTTP client configuration in `http_download()`/`get_downloader()`.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (RPC) with `launcher_id` set to a victim's/public store's launcher id, `urls=["http://attacker.example/callback"]`, and a minimal `amount`/`fee` — see `DLNewMirror` request and `dl_new_mirror` handler.
2. The transaction confirms on chain, creating a mirror coin memoized with the victim's `launcher_id` and the attacker URL (`create_new_mirror` in `chia/data_layer/data_layer_wallet.py`).
3. Any node already subscribed to that `launcher_id` runs its periodic `update_subscription()` job, calls `update_subscriptions_from_wallet()`, retrieves the attacker's URL via `dl_get_mirrors`, and stores it as an available server.
4. On the next `fetch_and_validate()` cycle, `http_download()` (or a configured downloader plugin) issues an outbound GET/POST to `http://attacker.example/callback`, letting the attacker log the victim node's IP/headers/timing without any action from the victim beyond having subscribed to the store.

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

```python
    server_info: ServerInfo,

    log: logging.Logger,
    max_delta_file_size: int,

    """

    """

        headers = {"accept-encoding": "gzip"}
        async with session.get(
```
