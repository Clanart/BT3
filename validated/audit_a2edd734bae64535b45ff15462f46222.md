### Title
Reward sniping in `DelegateVoteRewardPool` — depositing (voting) immediately before `harvestAll()` lets an attacker capture a full pro‑rata share of bribes accrued before their deposit - (File: rewards/DelegateVoteRewardPool.sol)

### Summary
`DelegateVoteRewardPool` distributes harvested bribes instantly into `rewardPerTokenStored` based on `totalSupply` at the moment `harvestAll()` executes, with no time-weighting or vesting period. Because `stakeFor`'s `updateRewards` modifier snapshots a new depositor's `userRewardPerTokenPaid` to the pre-harvest value using their balance *before* the deposit, any unprivileged vlMGP holder can vote into `delegatedPool` right before `harvestAll()` executes and immediately claim a full share of rewards that accrued entirely before their own stake existed.

### Finding Description
`harvestAll()` is `external` and callable by anyone: [1](#0-0) . It pulls bribes via `claimAllBribes` and pushes them into `_manageRewards`, which calls `_queueNewRewardsWithoutTransfer` [2](#0-1) . That function bumps `rewardPerTokenStored` **instantly and in full** based on `totalSupply` at that exact moment — there is no `rewardRate`/`periodFinish` linear-vesting mechanism like classic Synthetix `StakingRewards`: [3](#0-2) 

An attacker votes into `delegatedPool`, which routes through `stakeFor`, guarded by `updateRewards(_for, rewardTokens)`. That modifier computes `userShare = balanceOf(_account)` (the OLD balance, before the stake is added) and sets `userRewardPerTokenPaid[token][_account] = rewardPerToken(token)` at the **pre-harvest** value: [4](#0-3) . Then `totalSupply`/`_balances[_for]` are incremented with the new stake `X`: [5](#0-4) .

Once anyone (including the attacker) calls `harvestAll()`, `rewardPerTokenStored` jumps based on the harvested bribe amount and `totalSupply` (which now includes the attacker's freshly added `X`). Calling `getReward(attacker)` afterward computes `earned` via `_earned`, multiplying the **full** `X` balance by the **entire** `rewardPerTokenStored` delta since the attacker's low snapshot: [6](#0-5) , [7](#0-6) .

The attacker's `X` had zero time exposure to the bribe-accrual period that produced this harvest, yet captures a full pro-rata share of it, diluting the amount that legitimate long-term `delegatedPool` voters would otherwise receive. No modifier, cooldown, or time-weighted accounting in this codebase prevents this: `stakeFor` has no lockup before it starts earning against the *next* harvest, and `harvestAll()` has no access control or minimum holding-period check.

### Impact Explanation
This is a **theft of unclaimed yield**: rewards accrued by bribe activity attributable to time *before* the attacker's deposit are redirected, proportionally, to the attacker instead of to the pre-existing `delegatedPool` voters. This matches the Immunefi "theft of unclaimed yield" impact class. The magnitude scales with the size of the attacker's deposit relative to `totalSupply` at harvest time and the size of the harvested bribe batch — for large harvests this can be a substantial diversion of value away from long-term voters, with no time-weighted mitigation in place.

### Likelihood Explanation
- No special privileges are needed — any vlMGP holder can vote weight into `delegatedPool`, and `harvestAll()` is public.
- The attack only requires ordinary front-running (observing a pending `harvestAll()`/vote-cast transaction in the mempool and inserting a deposit before it), which is standard MEV capability, not a flash loan or reentrancy.
- It's fully repeatable every time a harvest cycle occurs, and capital requirements are minimal — the attacker just needs enough vlMGP votable weight to make the sniped share meaningful.
- The main uncertainty is whether the `vote()`/deposit path in `WombatBribeManager` enforces any cooldown between vote changes and `castVotes`/`harvestAll()`; the retrieved code did not show such a restriction, and `harvestAll()` on `DelegateVoteRewardPool` itself has no guard.

### Recommendation
Introduce time-weighted reward distribution instead of instant full crediting of `rewardPerTokenStored`:
- Stream newly harvested rewards linearly over a fixed duration (`rewardRate` + `periodFinish`, à la Synthetix `StakingRewards`), so a deposit made immediately before harvest can only earn a negligible fraction of the streamed reward, not the whole batch.
- Alternatively, enforce a minimum bonding/lock period on `stakeFor` in `DelegateVoteRewardPool` before a new deposit becomes eligible for the *next* harvest's rewards, or checkpoint the vote weight used for reward math from before the pending harvest snapshot.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool` with a reward token and a mock `WombatBribeManager` that can be triggered to return a fixed bribe amount via `claimAllBribes`.
2. Set up two "honest" voters, A and B, each staking `Y` vote-weight into `delegatedPool` via `stakeFor`, and let time pass (simulate several blocks/epochs) — this represents bribe accrual before the attacker's deposit.
3. Attacker calls `vote`/`stakeFor` equivalent to add `X` vote-weight to `delegatedPool` (front-running the next harvest).
4. Anyone (attacker) calls `harvestAll()`, which mocks a bribe payout `R`.
5. Assert:
   - `earned(attacker, rewardToken)` immediately after harvest equals `X * R / (X + 2Y)` even though attacker held stake for 0 blocks during the accrual window.
   - Compare against `earned(A, rewardToken)` and `earned(B, rewardToken)`, showing A and B's share of `R` is diluted below what a pure time-weighted allocation would give them (i.e., below `R/2` each if the harvest fully corresponds to their exclusive holding period).
   - Confirm `getReward(attacker)` successfully transfers this diluted-share reward to the attacker, proving realized profit disproportionate to duration staked.

    function _manageRewards(
        address[] memory rewardTokensList,
        uint256[] memory earnedRewards
    ) internal {
        uint256 length = rewardTokensList.length;
        for (uint256 index = 0; index < length; ++index) {
            uint256 fees = (protocolFee * earnedRewards[index]) / DENOMINATOR;
            if (fees > 0 && feeCollector != address(0)) {
                earnedRewards[index] = earnedRewards[index] - fees;
                IERC20(rewardTokensList[index]).safeTransfer(
                    feeCollector,
                    fees
                );
            }
            if (earnedRewards[index] > 0) {
                _queueNewRewardsWithoutTransfer(
                    earnedRewards[index],
                    rewardTokensList[index]
                );
            }
        }
    }

    /// @notice Sends new rewards to be distributed to the users staking.
    /// @param _amountReward Amount of reward token to be distributed
    /// @param _rewardToken Address reward token
    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        uint256 length = _rewards.length;
