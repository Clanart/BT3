### Title
Unvalidated CLVM atom length allows out-of-bounds buffer read / unhandled exception in `is_clvm_canonical` - (File: `chia/full_node/mempool_manager.py`)

### Summary
The Teeworlds CVE-2021-43518 root cause is that a length field (`m_Channels`) taken from untrusted map data is used to index/copy a buffer without validating it against the buffer's actual size. The Chia codebase contains a directly analogous pattern in `is_atom_canonical`/`is_clvm_canonical` in `chia/full_node/mempool_manager.py`: these functions read a CLVM atom's length prefix directly out of attacker-controlled bytes (`coin_spend.puzzle_reveal` / `coin_spend.solution`) and advance a byte `offset` by that value with no check that `offset` (or `offset + prefix_len`) stays within `len(clvm_buffer)`.

### Finding Description
`is_atom_canonical()` reads the first byte at `offset`, derives `prefix_len` and `atom_len` from its high bits, then loops `prefix_len` times reading `clvm_buffer[offset]` to build up `atom_len`, and finally returns `1 + prefix_len + atom_len` as the total atom size: [1](#0-0) 

`is_clvm_canonical()` then advances its own `offset` by that returned atom size and loops again, with no bounds check against `len(clvm_buffer)` anywhere in either function: [2](#0-1) 

This is called directly on attacker-supplied bytes in `validate_spend_bundle`, per coin spend in a submitted `SpendBundle`: [3](#0-2) 

By contrast, the project's own `chia/full_node/full_block_utils.py` demonstrates the correct, hardened pattern for exactly this class of bug — every length/count field read from a buffer is explicitly checked against the remaining buffer size before being used, and raises a `ValueError` otherwise: [4](#0-3) [5](#0-4) 

The `is_atom_canonical`/`is_clvm_canonical` code path lacks this same defensive check even though it, too, parses untrusted, attacker-supplied byte data (the puzzle reveal / solution of a submitted spend bundle) prior to trusting it. Since Python raises an `IndexError` on out-of-range byte access rather than corrupting memory (unlike the native C++ Teeworlds parser), the practical consequence is not memory corruption but an unhandled exception during spend bundle validation.

### Impact Explanation
If a crafted `coin_spend.puzzle_reveal` or `coin_spend.solution` causes `offset` to walk past the end of the buffer (e.g., a non-canonical/malformed atom length-prefix sequence at the tail of the buffer), `clvm_buffer[offset]` raises an unhandled `IndexError` inside `validate_spend_bundle`, which is on the path invoked for every spend bundle submitted to the mempool. An uncaught exception here can abort spend-bundle processing for that request/transaction, which maps to the "spend-triggered transaction-processing halt" impact category (Medium/High depending on how far the exception propagates and whether the calling RPC/protocol handler recovers gracefully).

### Likelihood Explanation
I could not fully verify, within this analysis, whether the Rust CLVM parser used earlier in `pre_validate_spendbundle` (`validate_clvm_and_signature`, backed by `chia_rs`) would reject exactly the same malformed byte layouts that could crash the pure-Python `is_clvm_canonical` re-parser, or whether such buffers can reach `is_clvm_canonical` without first being rejected upstream. This uncertainty affects the actual reachability/likelihood and should be validated with concrete fuzzing of `is_clvm_canonical` against buffers that pass `chia_rs` CLVM parsing.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` and `is_clvm_canonical` — mirroring the pattern already used in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`, `generator_from_block`) — verifying that `offset` and `offset + prefix_len` never exceed `len(clvm_buffer)` before indexing, and returning a definitive non-canonical result (or raising a caught `ValueError`) instead of allowing an `IndexError` to propagate out of spend-bundle validation.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) bytes end with a valid-looking large-length atom prefix (e.g., `0xF8` class 4-byte length prefix) but with insufficient trailing bytes to satisfy the declared length, such that `is_atom_canonical`'s loop pushes `offset` past `len(clvm_buffer)`. Submit this as part of a `SpendBundle` via the standard `push_tx` RPC path so it reaches `MempoolManager.validate_spend_bundle`, and observe whether `clvm_buffer[offset]` raises an unhandled `IndexError` (exact reachability past the earlier `chia_rs` CLVM parse step needs confirmation in a running node/test harness, which I was unable to execute here).

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
