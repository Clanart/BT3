### Title
Consensus-incentive rewards misattributed to a single relayer for all state machines updated in a batch, enabling reward theft via replayed public consensus proofs - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::FeeHandler::on_executed` recovers exactly one relayer identity — from `messages[0]` — and then pays the full per-block reward for **every** `StateMachineUpdated` event produced in that batch to that single recovered account, regardless of which consensus message actually produced which event. Because GRANDPA/consensus proofs are public and can be resubmitted by anyone once observed on-chain elsewhere, an unprivileged actor can build a batch whose first message is their own trivial, real consensus update and whose remaining messages are copies of already-public consensus proofs for other state machines, and collect the full treasury reward for all of them under their own account.

### Finding Description
`on_executed` derives the payee once: [1](#0-0) 

It then collapses *all* `StateMachineUpdated` events in the batch — potentially for many different `state_machine_id`s, each originating from a distinct `Message::Consensus` in the same extrinsic — into a map of highest heights per chain, and pays every one of them to that single `relayer_account`: [2](#0-1) 

`process_message`/`calculate_reward` compute the reward purely from the on-host `latest_commitment_height`/`previous_commitment_height`/`LastRewardedHeight` watermark for the *state machine*, with no linkage back to which message/signature actually advanced that specific chain: [3](#0-2) [4](#0-3) 

Consensus proofs (`consensus_msg.consensus_proof` + `consensus_msg.signer`) are self-contained, publicly observable data (once finalized on the source chain, a valid GRANDPA justification can be resubmitted by anyone) — this pallet's own design already relies on recovering the signer from the proof rather than authenticating the extrinsic sender, which is exactly what makes replay possible: nothing ties "who paid gas / who is the batch submitter" to "who actually discovered/generated the proof for chain X". The `LastRewardedHeight` watermark (added specifically to stop the *same* relayer double-claiming the *same* span) does not protect against a *different* attacker claiming a *legitimate* span using a proof they didn't need to originate — the watermark only tracks height, not identity, so the check passes as long as the height is new.

The broken invariant is: reward attribution assumes "signer of `messages[0]`" == "the entity that delivered every `StateMachineUpdated` event in this call", but nothing in `on_executed` enforces that relationship for messages beyond index 0.

### Impact Explanation
This lets any unprivileged actor drain the `TreasuryAccount` and mint themselves `ReputationAsset` for consensus updates they did not actually source — a direct "stealing of funds" / "unauthorized reward" outcome against the treasury, and a wrong-beneficiary settlement (the legitimate relayer whose proof was copied receives nothing). Because there is no per-message signer-to-event binding, the attack scales with however many state machines can be bundled into one batch, multiplying the treasury drain per transaction the attacker submits.

### Likelihood Explanation
The precondition is only that consensus proofs for other chains are publicly obtainable (they must be, since ISMP consensus proofs are broadcast and independently verifiable — that's the entire point of the light-client design) and that an attacker can submit their own extrinsic containing multiple `Message::Consensus` entries where message[0] is their own signed proof. No relayer collusion, no compromised key, and no admin/governance action is required — this is reachable from the standard `handle_messages`/dispatch entrypoint that any account can call by paying gas.

### Recommendation
Bind each `StateMachineUpdated` event to the specific `Message::Consensus` (and its recovered signer) that produced it, rather than defaulting to `messages[0]`'s signer for the whole batch. `pallet_ismp`'s message-handling pipeline should expose a mapping from processed message index/state-machine to the event(s) it produced so `on_executed` can pay each relayer individually for the events attributable to their own submitted proof.

### Proof of Concept
1. Attacker observes a publicly-broadcast, valid GRANDPA consensus proof that advances `StateMachine::B` (e.g. captured from a block explorer or another relayer's already-submitted extrinsic before it lands, or from a finalized source-chain justification not yet relayed to Hyperbridge).
2. Attacker submits a single extrinsic to `pallet-ismp`'s message handler containing `[Message::Consensus(attacker's real, minimal proof advancing StateMachine A by 1 block), Message::Consensus(copied proof advancing StateMachine B by N blocks)]`.
3. `pallet_ismp` processes both, emitting `StateMachineUpdated` for both A and B; `on_executed` is invoked once with both events.
4. `on_executed` recovers the relayer identity only from `messages[0]` (attacker's key) — [1](#0-0) .
5. The loop over `highest_per_state_machine` pays the attacker's account the full `blocks × cost_per_block` reward for **both** A and B — [5](#0-4) , even though the attacker did not originate the B proof.
6. `LastRewardedHeight` for B advances, so the legitimate relayer who later (or in parallel) submits the same B proof themselves gets `blocks = 0` and no reward, per `calculate_reward`'s watermark logic — [6](#0-5) .

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
