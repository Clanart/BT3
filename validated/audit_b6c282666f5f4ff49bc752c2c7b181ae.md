## Analysis

The report's broken invariant is: *a downstream security decision (whether the user can safely authenticate/operate) is derived from state that an attacker can manipulate or make unavailable, and the code has no fallback that fails safe.* The closest verifiable analog in GitHub Desktop is in the Git credential-helper trampoline, where the *kind* of endpoint (and thus which authentication path is used) is derived, in part, from attacker-controlled data returned by the remote server itself. [1](#0-0) 

### Title
Spoofed `WWW-Authenticate` realm from a Git remote/proxy downgrades GitHub Enterprise authentication to generic basic-auth - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's credential-helper trampoline classifies an unknown Git remote endpoint as `'generic'`, `'enterprise'`, `'github.com'` or `'ghe.com'` in `getEndpointKind()` before deciding how to authenticate. Part of that classification trusts the `WWW-Authenticate` header value that Git captured from the HTTP response of the remote server and forwarded to Desktop as `wwwauth[]` fields, with no validation that the header actually originates from a trustworthy source. [2](#0-1) 

### Finding Description
When Git needs credentials for an HTTPS remote it has not seen before, it invokes Desktop's credential helper (`get`) with the captured response headers. `getEndpointKind()` first checks known-safe hostnames (`isGist`, `isDotCom`, `isGHE`), which are string comparisons on the actual hostname and cannot be spoofed. It then inspects attacker-controlled header content: [3](#0-2) 

If the realm string is `"GitLab"`, `"Gitea"` or `"Atlassian Bitbucket"`, the function immediately returns `'generic'` — before the internal store is even consulted (`findGitHubTrampolineAccount`, the fallback exact-match lookup, runs afterward). Because the realm string is taken verbatim from the server's HTTP response, any server the user's Git client talks to (a malicious/compromised self-hosted GitHub Enterprise Server, a corporate MITM proxy, or an attacker sitting on the network path for a first-time connection) can inject this header to force the `'generic'` classification.

Downstream, `getCredential()` uses `endpointKind` to decide the authentication path: [4](#0-3) 

When `endpointKind === 'generic'`, Desktop skips the "prompt user to sign in to GitHub"/OAuth path entirely (`ui.promptForGitHubSignIn`) and instead falls into `getGenericCredential`/`getExternalCredential`, which prompt the user for or reuse a raw username/password rather than the GitHub/GHE OAuth token flow. [5](#0-4) 

The corrupted value is `endpointKind`, computed from attacker-influenceable HTTP response content, which controls whether Desktop treats an endpoint as a GitHub-family host requiring a scoped OAuth token, or as a "generic" host where a plaintext username/password is solicited and handed directly to Git for transmission to that same (attacker-influenced) endpoint. No guard revalidates the realm claim against the actual hostname or against a certificate/identity check — the string match on `realm=` is sufficient to flip the classification.

### Impact Explanation
Forcing the `'generic'` classification on a real GitHub Enterprise Server endpoint means Desktop bypasses its intended GitHub/GHE sign-in (OAuth) mechanism for that host on first authentication, and instead solicits/uses a raw, unscoped username and password that Git will submit directly to the (attacker-controlled or MITM'd) server. This is a credential-exposure primitive: the user's actual account password (rather than a revocable, scoped OAuth token) is sent over the wire to an endpoint the attacker has already demonstrated they can tamper with the responses of. This matches the report's core issue — a value the security logic depends on (endpoint trust classification) can be corrupted by an outside actor, defeating the intended protection path.

### Likelihood Explanation
This requires the victim to be authenticating to a GHES/self-hosted remote for the first time (no existing stored account, since `getGitHubCredential`'s exact-origin match takes priority when an account already exists) and requires the attacker to control or tamper with the HTTP response for that connection (a malicious/compromised server, or a network position such as a corporate/inline proxy). No local access, malware, or leaked credentials are needed, and no unnatural user steps are required beyond the normal "enter credentials" prompt Desktop would show anyway.

### Recommendation
Do not trust the `WWW-Authenticate` realm string as a downgrade signal to `'generic'`. At most, use it as a positive signal to *elevate* trust when it matches `realm="GitHub"` combined with hostname-based checks, and never let externally-supplied header content lower the required authentication strength for a host. Alternatively, gate the realm-based classification on TLS certificate validation of the actual GitHub Enterprise Server, or drop that heuristic in favor of relying solely on `isGitHubHost()`'s authenticated network probe.

### Proof of Concept
1. In GitHub Desktop, clone a repository from `https://ghes.example.com/org/repo.git` for the first time (no account for `ghes.example.com` yet configured in Desktop).
2. Have the server (or a MITM proxy in front of it) respond to Git's unauthenticated request with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitLab"`.
3. Git forwards this via the credential helper protocol; `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts` matches the `/realm="(GitLab|Gitea|Atlassian Bitbucket)"/` regex and returns `'generic'`.
4. `getCredential()` skips the GitHub/GHE sign-in path and instead prompts the user for a plain username/password via `promptForCredential`/`getGenericCredential`, which Git then submits directly to `ghes.example.com` in the clear HTTP(S) authentication exchange — exposing the user's actual account password to the tampering party instead of using a scoped OAuth token.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
