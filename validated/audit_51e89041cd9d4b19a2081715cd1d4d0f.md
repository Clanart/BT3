### Title
DataLayer Mirror-URL SSRF: Any Wallet User Can Force Peer DataLayer Nodes to GET Attacker-Chosen URLs - (File: chia/data_layer/download_data.py)

### Summary
Any wallet operator (no special privilege beyond normal spend authority) can publish a "mirror coin" for a Data Layer store containing arbitrary attacker-chosen URL strings in the coin memos via `create_new_mirror()`. Every other node that subscribes to that store's DataLayer will parse those on-chain URLs and issue outbound HTTP GET requests to them, with no scheme, hostname, or IP-range validation — a classic SSRF, directly analogous to the Jenkins Kanboard SSRF where any user with read access could make the Jenkins controller fetch an attacker-specified URL.

### Finding Description
`DataLayerWallet.create_new_mirror()` takes a `launcher_id` and a list of raw `urls: list[bytes]` and encodes them directly into the coin's memos with no validation: [1](#0-0) 

This is reachable from the public wallet RPC `dl_new_mirror`, which forwards the caller-supplied `urls` unchanged: [2](#0-1) 

Any node tracking that launcher id observes the mirror coin creation and extracts the URLs from the parent spend via `get_mirror_info()`, storing them as tracked mirrors: [3](#0-2) [4](#0-3) 

The DataLayer service periodically pulls these mirror URLs from the wallet and turns them into subscription server entries with `update_subscriptions_from_wallet()`, again with no URL filtering: [5](#0-4) [6](#0-5) 

When syncing a subscribed store, `fetch_and_validate()` iterates these server URLs and calls `insert_from_delta_file()` → `download_file()`, which — absent a configured downloader plugin — performs an unrestricted HTTP GET via `http_download()`: [7](#0-6) [8](#0-7) [9](#0-8) 

There is no scheme allowlist (e.g., http/https only), no check against loopback/link-local/private ranges (`169.254.169.254`, `127.0.0.1`, RFC1918 ranges), and no DNS-rebinding protection anywhere in this chain — confirmed by the absence of any `urlparse`/`ipaddress`/host-validation logic in `chia/data_layer/data_layer.py`, `download_data.py`, or `data_store.py` (such checks exist only in the optional, separate `s3_plugin_service.py`, which is not the default code path).

### Impact Explanation
Because mirror URLs are placed on-chain by ordinary wallet spends and consumed automatically by every peer subscribing to the store, an attacker can:
- Force victim full-node/DataLayer operators to issue GET requests to internal/cloud-metadata endpoints (e.g., `http://169.254.169.254/latest/meta-data/`), internal RPC ports, or other network-restricted services reachable only from the victim's host/network.
- Use victim nodes as a scanning/probing proxy against internal infrastructure.
- Potentially trigger request smuggling/side effects against internal HTTP services that react to arbitrary GET requests.

This satisfies "no-impact" exclusion criteria being *not* met — it is a genuine SSRF triggered by a normal, unprivileged wallet action (creating a mirror coin) reaching every peer's local DataLayer service, aligning with CWE-918 as in the reference advisory.

### Likelihood Explanation
Likelihood is high: creating a mirror coin requires only a standard signed transaction with a small fee/amount — no special permission, no consensus rule prevents it, and the URL content is fully attacker-controlled free text embedded in `CREATE_COIN` memos. Any node that subscribes to (or is auto-subscribed to, e.g. via `create_new_mirror`/DL browsing UX) an attacker's store will automatically perform the SSRF request during its normal sync loop (`periodically_manage_data()`), without any user interaction beyond subscribing.

### Recommendation
- Validate mirror/subscription URLs before use for HTTP downloads: enforce an `http`/`https` scheme allowlist, resolve and reject loopback, link-local, and private/reserved IP ranges, and disable following redirects to disallowed hosts.
- Apply the same validation both when persisting `Mirror` urls (`dl_wallet_store.add_mirror`) and, defense-in-depth, immediately before use in `http_download()`/`download_file()`.
- Consider requiring an explicit user opt-in/allowlist for mirror URL hosts rather than fully automatic fetch-on-subscribe.

### Proof of Concept
1. Attacker creates a DataLayer store and publishes a mirror coin using the wallet RPC:
   `dl_new_mirror(launcher_id=<attacker_store_id>, amount=1000, urls=["http://169.254.169.254/latest/meta-data/"], fee=...)` — accepted with no validation, per `create_new_mirror()`.
2. Victim node runs a DataLayer service and subscribes to the attacker's store (e.g., via `subscribe` CLI/RPC, or by following a shared store id in normal DL usage).
3. During the victim's next `periodically_manage_data()` cycle, `update_subscription()` calls `update_subscriptions_from_wallet()`, pulling the malicious URL into the subscription table, then `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues `session.get("http://169.254.169.254/latest/meta-data/" + "/" + filename, ...)` from the victim host — confirming SSRF against an internal/cloud-metadata target chosen entirely by the attacker.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
                {
                    "tree_id": store_id,
                },
            )

            additions = {url for url in new_urls if url not in old_urls}

                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,

                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
