### Title
`update_cost_per_block()` retroactively rewards the entire pre-enablement height span to whoever submits the next consensus proof - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::calculate_reward` derives the relayer's reward as `(latest_height - baseline) * block_cost`, where `baseline` falls back through two layers of storage that default to `0`/the pre-enablement height when no reward has ever been paid. When governance turns on incentives for a state machine that has already advanced far past height 0 (the common case — incentives are usually enabled after a chain has been live and relaying for a while), the very next relayer to submit *any* consensus proof collects a reward sized for the **entire historical block span since genesis**, not just the blocks produced after incentives were enabled. This is the same "unbounded lookback because of a missing baseline" defect as the reported `Minter.sol` bug, where `lastEvent == 0` let `totalAvailableToNow` be computed over 52 years of inflation instead of zero.

### Finding Description
`calculate_reward` in [1](#0-0)  computes:

```rust
let previous_height = host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`LastRewardedHeight` is `OptionQuery` and starts as `None` for every state machine [2](#0-1) . It is never seeded when `StateMachinesCostPerBlock` is set — `update_cost_per_block` only writes the cost map, nothing else [3](#0-2) .

`previous_commitment_height` reads `PreviousStateMachineHeight`, which is populated by `store_latest_commitment_height` as `LatestStateMachineHeight::get().unwrap_or_default()` *before* overwriting it [4](#0-3) [5](#0-4) . This value tracks the height of the *previous* state-update transaction only — it has no relation to when the incentive was enabled.

Consequence: if a state machine has been running (and its state-commitment height climbing) for a long time *before* governance calls `update_cost_per_block`, then the first `on_executed` after enablement computes `baseline = previous_height` (some old height, not "the height at enablement"), so `blocks = latest_height - previous_height` can span the entire distance the chain advanced in its last update — and repeated calls compound this because `LastRewardedHeight` is `None` on every state machine that has simply never been paid, regardless of whether incentives are brand new or have existed but simply missed a payout window. Any signed, permissionless relayer calling `submit_proof` (as in `beefy-consensus-proofs::submit_proof`, `ensure_signed(origin)` with no allow-list [6](#0-5) ) triggers `FeeHandler::on_executed` → `process_message` → `calculate_reward`, and receives `blocks * block_cost` transferred straight from the treasury account [7](#0-6) .

The pallet's own regression test only covers the "rollback" scenario (baseline correctly bounded by `PreviousStateMachineHeight`) [8](#0-7) , but no test exercises "incentives enabled after the chain has already advanced," which is the scenario that reproduces the Minter-style unbounded-lookback bug.

### Impact Explanation
This causes unauthorized/unbounded fund transfer from the treasury (`T::TreasuryAccount`) to an ordinary relayer account, with no admin, prover, or relayer compromise required — any address that races to submit the next valid consensus proof after governance enables (or re-enables after `remove_incentives`/`update_cost_per_block`) incentives for a state machine collects a reward computed over blocks it never delivered. Depending on `block_cost` and how far the state machine has already advanced, this can drain or significantly deplete the treasury in a single extrinsic — a direct "stealing/loss of funds" outcome matching the bounty's accepted impact class.

### Likelihood Explanation
Likelihood is high in normal operational flow: enabling incentives for an already-active state machine (or re-enabling them via `update_cost_per_block` after a period without incentives, i.e., after `remove_incentives`) is an expected governance action, not an edge case. The exploit requires no privileged access — the attacker only needs to be the relayer whose signed proof lands in the block right after (or as) the reward is enabled, which is entirely within reach of any observer watching the chain for the `StateMachineCostPerBlockUpdated` event.

### Recommendation
Seed `LastRewardedHeight` to the state machine's current `latest_commitment_height` at the moment `update_cost_per_block` first enables incentives for that `state_machine_id` (i.e., write `LastRewardedHeight::insert(state_machine_id, host.latest_commitment_height(state_machine_id))` when transitioning from `None` to `Some(cost)`), so rewards only ever accrue for blocks produced after incentivization begins. Alternatively, require `baseline` to fall back to `latest_height` (zero reward) rather than `previous_height`/`0` when `LastRewardedHeight` is `None`, forcing the first post-enablement update to establish the watermark without paying for pre-existing history.

### Proof of Concept
1. State machine `X` runs for a long time; through many honest `submit_proof` calls, `LatestStateMachineHeight[X]` reaches height `H = 500_000` while `StateMachinesCostPerBlock[X]` is unset (no incentives yet), so `process_message` is never invoked with a cost for `X`.
2. Governance calls `update_cost_per_block(X, cost_per_block)` to start incentivizing relaying for `X` going forward [3](#0-2) . This only sets `StateMachinesCostPerBlock[X]`; `LastRewardedHeight[X]` remains `None`.
3. Attacker (any signed relayer) submits the next valid consensus proof advancing `X` to height `H+1`. `on_executed` fires, `process_message` computes `calculate_reward`:
   - `latest_height = H+1`
   - `previous_height = previous_commitment_height(X)` — the height before this update (≈`H`), not the height at step 2.
   - `baseline = LastRewardedHeight::get(X).unwrap_or(previous_height) = H` (since `LastRewardedHeight` is `None`)
   - `blocks = (H+1) - H = 1` in the best case, but if the attacker instead controls/waits for a proof that jumps several heights at once (or if `previous_commitment_height` itself is `None`, e.g. right after `initialize_state` seeds only height `1` per [9](#0-8) ), `baseline` collapses to `0` and `blocks = H+1 ≈ 500_001`.
4. `reward = blocks * block_cost` is transferred from the treasury to the attacker's relayer account in one call [7](#0-6) , an amount representing the entire un-rewarded historical span rather than the single block actually relayed. [10](#0-9)

```rust
	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
```

```rust
			state_machine_id: StateMachineId,

		) -> DispatchResult {

				state_machine_id,
				cost_per_block,
			});

			Ok(())
```

```rust
// A relayer is paid once for advancing a state machine across a span of heights. When the latest
// height is rolled back and later resubmitted, the reward should still only cover the new blocks.
// The `LastRewardedHeight` watermark keeps each payout scoped to the span that has not been paid.
#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
```
