### Title
`mWOMSVBaseRewarder::_calExpireForfeit` never forfeits reward, letting users retain rewards from partially-unlocked mWOMSV that should be redistributed to other stakers - ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
`mWOMSVBaseRewarder::_calExpireForfeit` is meant to reduce a user's claimable reward based on how much of their mWOMSV position is still actively locked vs. in cool-down/unlocked, exactly like the analogous `vlMGPBaseRewarder::_calExpireForfeit`. Instead of computing this ratio, the mWOMSV version sets `rewardableAmount = _amount` unconditionally, so the forfeited portion is always zero, regardless of the user's actual lock/cool-down state.

### Finding Description
`vlMGPBaseRewarder::_calExpireForfeit` correctly queries the locker for the user's rewardable percentage and forfeits the rest: [1](#0-0) 

The mirror function in `mWOMSVBaseRewarder` should perform the equivalent calculation using `mWOMSV` (an `ILocker`), which exposes the same cool-down/unlock-slot mechanics as `VLMGP` (`startUnlock`, `cancelUnlock`, `forceUnLock`, penalty calculation) as seen in `wombat/mWomSV.sol`. Instead, it is a no-op: [2](#0-1) 

`rewardableAmount` is assigned `_amount`, so `forfeitAmount = _amount - rewardableAmount` is always `0`. The `if (rewardableAmount > _amount)` check can never trigger and the "ignore dust forfeits <0.1%" branch is dead code, confirming the intended formula (mirroring `vlMGPBaseRewarder`) was dropped. This function is invoked from `_sendReward`, which is reached by ordinary users calling `getReward`/`getRewards` through `MasterMagpie` (`onlyMasterMagpie` modifier, triggered by any staker's harvest/claim call): [3](#0-2) 

Forfeited amounts are supposed to be re-queued into the pool via `_queueNewRewardsWithoutTransfer`, redistributing them to remaining mWOMSV stakers pro-rata: [4](#0-3) 

Because forfeiture is permanently disabled, this redistribution path is unreachable — the yield that should flow to other mWOMSV holders (as designed by the protocol's early-unlock penalty mechanism) never accrues to them.

### Impact Explanation
Any unprivileged user who is in cool-down/has partially unlocked their mWOMSV can call `getReward`/`getRewards` (via `MasterMagpie`) and claim 100% of accrued reward tokens without the intended forfeiture, permanently denying the forfeited yield to other stakers in the pool. This is a direct, permanent misallocation of unclaimed yield among users — funds that should be redistributed to honest long-term lockers are instead retained by users who are exiting early, with no admin or governance action required to trigger it.

### Likelihood Explanation
High likelihood: this triggers automatically on every reward claim by any user with an active/expired cool-down slot in mWOMSV, requiring no special conditions, privileges, or timing — it is the default, unconditional behavior of the function.

### Recommendation
Fix `mWOMSVBaseRewarder::_calExpireForfeit` to mirror `vlMGPBaseRewarder::_calExpireForfeit`, i.e., query `mWOMSV` for the user's actual rewardable percentage (analogous to `getRewardablePercentWAD`) and compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18` before deriving `forfeitAmount`.

### Proof of Concept
1. User locks mWOMSV and starts a cool-down/unlock (per `mWomSV.sol`'s cool-down mechanics), which should reduce their "rewardable percent" below 100%.
2. Reward tokens accrue to the pool via `queueNewRewards`/`_provisionReward`, increasing `rewardPerTokenStored`.
3. User calls `getReward`/`getRewards` through `MasterMagpie`, which invokes `mWOMSVBaseRewarder::_sendReward`.
4. `_calExpireForfeit` returns `0` regardless of the user's cool-down state, so `toSend == userRewards[...]` — the user receives the full reward with no forfeiture, and no amount is re-queued to `_queueNewRewardsWithoutTransfer` for other stakers. [5](#0-4)

    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**mWOMSVDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;

    function _earned(address _account, address _rewardToken, uint256 _userMWOMSVShare) internal view returns (uint256) {
        return ((_userMWOMSVShare *
                (rewardPerToken(_rewardToken) -

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
