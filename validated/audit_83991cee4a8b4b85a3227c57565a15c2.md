### Title
Auction Module's Early Deadline (ED) Filter Is Bypassed for Gasless Bundle Transactions, Allowing Late-Arriving Non-Target Transactions Into the Block - (File: kaiax/auction/impl/builder.go)

### Summary
The auction module enforces an "early deadline" (ED) cutoff during block building so that transactions arriving too close to block-proposal time are excluded, which bounds how long the proposer/auctioneer window has to react and preserves the fairness assumptions of KIP-249 auction execution ordering. In `FilterTxs`, this cutoff check is combined with a bypass condition (`!a.isGaslessTx(tx)`) that completely exempts any transaction the gasless module recognizes as a bundle transaction (`IsApproveTx`/`IsSwapTx`) from the deadline check, regardless of how late it arrived, mirroring the reported pattern where one time-bound (`maxFundDur`) is skipped whenever another condition (`maxLoanDur`) is set instead of being enforced jointly.

### Finding Description
`FilterTxs` is supposed to remove/truncate transactions from each sender's queue that arrived after `deadline := now.Add(-edOffset)`, protecting the auction's target-transaction ordering guarantee: [1](#0-0) 

The filtering condition is `if tx.Time().After(deadline) && !a.isGaslessTx(tx)`. Because of the `&&!isGaslessTx(tx)` term, any transaction that `IsApproveTx`/`IsSwapTx` recognizes (i.e., any legacy tx calling ERC-20 `approve` to the configured router or `swapForGas` on the configured router with an allowed token) is entirely exempt from the ED cutoff — the bug pattern is structurally the same as the reported one: instead of applying both constraints together (arrival-time bound AND gasless-tx status), the code treats the second condition as an override that fully disables the first, even though the two conditions address independent concerns (an attacker-controllable transaction-type flag should not be allowed to nullify a timing/fairness guarantee).

`isGaslessTx` is implemented as: [2](#0-1) 

which merely calls `gaslessModule.IsBundleTx(tx)`, itself just `g.IsModuleTx(tx)` — a static ABI-signature check with no timing constraint of its own: [3](#0-2) 

Any unprivileged transaction sender can craft a transaction matching the `approve`/`swapForGas` ABI signature (a legacy tx to the configured router/token) and submit it arbitrarily late — right up to the block-proposal deadline — and it will never be pruned by the auction module's ED filter, unlike ordinary transactions from the same sender queue.

### Impact Explanation
This bypass undermines the auction module's block-building fairness/timing guarantee (KIP-249's `EDOffset` is explicitly documented as the mechanism ensuring transactions are received early enough for auction settlement to be reliable): [4](#0-3) 

Since gasless swap/approve transactions bypass the deadline entirely, a malicious sender can front-run/interject late transactions ahead of or alongside legitimate auction target transactions and bid settlement bundles at the very last moment before block assembly, disrupting expected transaction ordering that the ED offset was designed to guarantee (e.g., letting a same-sender queue keep a stale/duplicate item ahead of a target transaction, or altering the final composition of a block at the last possible instant). Because the auction module's fairness model relies on this ED cutoff to bound the time window auctioneers/searchers have relative to proposers, this is a state-divergence-adjacent/ordering-integrity issue in block assembly reachable purely by an unprivileged transaction sender submitting a single gasless-shaped transaction.

### Likelihood Explanation
Likelihood is high: no special privileges are required — any address can submit a transaction matching the gasless `approve`/`swapForGas` calldata signature to the configured router (this is a purely syntactic/ABI check, not a policy check tied to the sender's actual gasless intent), and the exemption is unconditional whenever the gasless module is registered, which occurs on production CN nodes running the auction and gasless kaiax modules together.

### Recommendation
Remove the `!a.isGaslessTx(tx)` bypass, or restrict it to bundle transactions that are actually the recognized target of a bid (mirroring how the target-tx bypass is already scoped via `targetTxHashMap`), so the ED deadline check applies uniformly to gasless-shaped transactions unless they are provably part of an in-flight bid-target bundle. Ensure the ED offset (`deadline := now.Add(-edOffset)`) is enforced jointly with, not overridden by, the gasless-tx classification, analogous to fixing the reported bug by checking `maxFundDur` even when `maxLoanDur` is set.

### Proof of Concept
1. Deploy/connect to a CN running both the `auction` and `gasless` kaiax modules with `auction.ed-offset` set to its default (200ms).
2. As an unprivileged sender, submit a legacy transaction whose calldata matches `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` targeting the configured `GaslessSwapRouter` and an allowed token (satisfying `IsSwapTx`), but submit it deliberately at/after the block's ED cutoff (i.e., `tx.Time()` is after `now.Add(-edOffset)` at block-building time) — verified by the existing test scaffold `TestFilterTxs_GaslessTx`, which shows that when `IsBundleTx` returns true, all 5 late transactions (each 55ms apart, exceeding the 200ms default ED offset for several of them) survive `FilterTxs` untouched: [5](#0-4) 
3. Compare against non-gasless transactions in the same test file (`TestFilterTxs_TargetTx`/base case), which are pruned once they cross the ED deadline — demonstrating that a normal transaction from the same sender queue submitted at the same late timestamp would be truncated, but the gasless-shaped transaction is not, confirming the selective bypass of the timing constraint.

func (a *AuctionModule) FilterTxs(txs map[common.Address]types.Transactions) {
	if atomic.LoadUint32(&a.bidPool.running) == 0 {
		return
	}

	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil {
		return
	}

	targetTxHashMap := a.bidPool.getTargetTxHashMap(curBlock.NumberU64() + 1)
	edOffset := a.AuctionConfig.EDOffset

	now := time.Now()
	deadline := now.Add(-edOffset)
	// filter txs that are after the auction early deadline
	for addr, list := range txs {
		for i, tx := range list {
			if tx.Time().After(deadline) && !a.isGaslessTx(tx) {
				// if the tx is a target tx, skip it
				if _, ok := targetTxHashMap[tx.Hash()]; ok {
					continue
				}

				if i == 0 {
					// if first transaction exceeds deadline, remove the address
					delete(txs, addr)
				} else {
					// keep only transactions before the deadline
					txs[addr] = list[:i]
				}
				break
			}
		}
	}

	edOffsetGauge.Update(int64(edOffset))
}

func TestFilterTxs_GaslessTx(t *testing.T) {
	mAuction := prep(t)
	txs := make(map[common.Address]types.Transactions)

	for i := range 5 {
		// tx.Time is set to current time
		tx := types.NewTransaction(uint64(i), tx1Sender, big.NewInt(1), 1000000, big.NewInt(1), nil)
		tx2 := types.NewTransaction(uint64(i), tx2Sender, big.NewInt(1), 1000000, big.NewInt(1), nil)

		time.Sleep(55 * time.Millisecond)
		txs[tx1Sender] = append(txs[tx1Sender], tx)
		txs[tx2Sender] = append(txs[tx2Sender], tx2)
	}

	mockCtrl := gomock.NewController(t)
	mockGasless := mock.NewMockGaslessModule(mockCtrl)
	mockGasless.EXPECT().IsBundleTx(gomock.Any()).Return(true).AnyTimes()

	mAuction.RegisterGaslessModule(mockGasless)
	mAuction.FilterTxs(txs)

	assert.Equal(t, 5, len(txs[tx1Sender]))
	assert.Equal(t, 5, len(txs[tx2Sender]))

	for i, tx := range txs[tx1Sender] {
		assert.Equal(t, uint64(i), tx.Nonce())
	}

	for i, tx := range txs[tx2Sender] {
		assert.Equal(t, uint64(i), tx.Nonce())
	}
}
