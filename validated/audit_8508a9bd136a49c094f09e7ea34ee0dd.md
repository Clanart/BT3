### Title
Remote-code-execution via unsanitized clone URL from `x-github-client://openrepo/` deep links reaching `git clone` (`ext::` transport injection) - (File: `app/src/lib/git/clone.ts`, `app/src/lib/parse-app-url.ts`)

### Summary
GitHub Desktop registers OS-level protocol handlers (`x-github-client://`, `github-mac://`, `github-windows://`) that any web page or file can invoke to make Desktop clone/open a repository. The `openrepo` action's `url` parameter is parsed with essentially no scheme validation and is later handed, largely unmodified, to `git clone`. Git's `ext::` remote helper transport allows a "URL" to actually be an arbitrary shell command, so if Desktop passes an attacker-chosen string as the clone target, it can result in command execution.

### Finding Description
`parseAppURL` extracts the repository `url` straight out of the deep-link path with only branch/PR/filepath validation — the `url` value itself is not scheme-checked: [1](#0-0) 

This action is dispatched to `openRepositoryFromUrl`, which (for the common case with no `pr`/`branch`) calls `openOrCloneRepository(url)`: [2](#0-1) 

Ultimately, when the URL doesn't match an existing local repository, Desktop's clone routine builds the `git clone` argument list and appends the raw URL after a `--` separator: [3](#0-2) 

The `--` prevents the URL from being parsed as a leading `-`-style CLI flag (argument injection), but it does **not** prevent Git from interpreting the URL's transport scheme. Git supports the `ext::<command>` remote helper, where the "URL" is actually a shell command Git will execute to establish the transport (e.g. `ext::sh -c "calc"`). None of the surrounding code (`envForRemoteOperation`/`envForProxy` in `app/src/lib/git/environment.ts`, or `clone.ts` itself) sets `protocol.ext.allow=never` or otherwise validates/allowlists the URL scheme before invoking `git`: [4](#0-3) 

`envForProxy` only pattern-matches `https?://` to decide whether to resolve an HTTP(S) proxy — any other scheme (including `ext::`) simply falls through unblocked and reaches `git clone` unmodified.

### Impact Explanation
This satisfies the "attacker controls ... a link or deep link the user clicks" category. A malicious webpage, email, or chat message can construct a link such as `x-github-client://openrepo/ext::sh%20-c%20%22calc%22` (or an equivalent OS command). If the victim has GitHub Desktop installed and clicks it, the OS invokes Desktop with that URL, `parseAppURL` returns an `open-repository-from-url` action with the raw `ext::...` string as `url`, and `clone()` shells out to `git clone -- 'ext::sh -c "calc"' <path>`, causing Git to execute the attacker's command. This is full unprivileged remote code execution triggered purely by a user clicking a link — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Likelihood depends on the exact behavior of the installed Git's `protocol.ext.allow` default for a directly invoked `git clone` (as opposed to nested submodule operations, where Git hardened defaults after CVE-2017-1000117-class issues). For user-initiated top-level clones, `ext::` is historically permitted by default. I was not able to fully verify, within the remaining tool budget, whether `openOrCloneRepository`/`matchExistingRepository` (referenced but not fully read) perform any additional scheme filtering before reaching `clone()`, nor whether some other layer (e.g., a global `GIT_ALLOW_PROTOCOL` env var) is set elsewhere in the main process. This is the residual uncertainty in this finding.

### Recommendation
- Validate the scheme of any URL originating from `parse-app-url.ts` (and any other externally-triggered clone path) against an allowlist (`https:`, `http:`, `ssh:`, `git:`) before it is ever passed to `git`.
- Alternatively/additionally, set `GIT_ALLOW_PROTOCOL=http:https:ssh:git` (or pass `-c protocol.ext.allow=never -c protocol.file.allow=never` as appropriate) in the environment/options used by `clone()` and any other function that clones/fetches a user- or link-supplied URL.
- Add regression tests in `app/test/unit/parse-app-url-test.ts` and clone tests asserting that `ext::`, `fd::`, and other non-network schemes are rejected.

### Proof of Concept
1. Attacker hosts/sends a link: `x-github-client://openrepo/ext::sh%20-c%20%22touch%20/tmp/pwned%22`.
2. Victim, with GitHub Desktop installed and registered as the handler for `x-github-client`, clicks the link.
3. OS launches Desktop with this URL; `handleAppURL`/`parseAppURL` produce `{ name: 'open-repository-from-url', url: 'ext::sh -c "touch /tmp/pwned"', branch: null, pr: null, filepath: null }` per [5](#0-4) .
4. `dispatcher.openRepositoryFromUrl` → `openOrCloneRepository(url)` fails to find a matching existing repo and proceeds to clone.
5. `clone()` executes `git -c init.defaultBranch=... clone --recursive -- 'ext::sh -c "touch /tmp/pwned"' <destPath>` per [3](#0-2) , and Git's `ext` transport runs the embedded shell command on the victim's machine.

```typescript
export async function envForProxy(
  remoteUrl: string,
  env: NodeJS.ProcessEnv = process.env,
  resolve: (url: string) => Promise<string | undefined> = resolveGitProxy
): Promise<Record<string, string | undefined> | undefined> {
  const protocolMatch = /^(https?):\/\//i.exec(remoteUrl)

  // We can only resolve and use a proxy for the protocols where cURL
  // would be involved (i.e http and https). git:// relies on ssh.
  if (protocolMatch === null) {
    return
  }

  // Note that HTTPS here doesn't mean that the proxy is HTTPS, only
  // that all requests to HTTPS protocols should be proxied. The
  // proxy protocol is defined by the url returned by `this.resolve()`
  const proto = protocolMatch[1].toLowerCase() // http or https

  // We'll play it safe and say that if the user has configured
  // the ALL_PROXY environment variable they probably know what
  // they're doing and wouldn't want us to override it with a
  // protocol-specific proxy. cURL supports both lower and upper
  // case, see:
  // https://github.com/curl/curl/blob/14916a82e/lib/url.c#L2180-L2185
  if ('ALL_PROXY' in env || 'all_proxy' in env) {
    log.info(`proxy url not resolved, ALL_PROXY already set`)
    return
  }

  // Lower case environment variables due to
  // https://ec.haxx.se/usingcurl/usingcurl-proxies#http_proxy-in-lower-case-only
  const envKey = `${proto}_proxy` // http_proxy or https_proxy

  // If the user has already configured a proxy in the environment
  // for the protocol we're not gonna override it.
  if (envKey in env || (proto === 'https' && 'HTTPS_PROXY' in env)) {
    log.info(`proxy url not resolved, ${envKey} already set`)
    return
  }

  const proxyUrl = await resolve(remoteUrl).catch(err => {
    log.error('Failed resolving Git proxy', err)
    return undefined
  })

  return proxyUrl === undefined ? undefined : { [envKey]: proxyUrl }
}
```
