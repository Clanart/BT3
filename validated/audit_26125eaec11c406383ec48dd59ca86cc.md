Based on my investigation, the `IsGaslessTx` divergent-decoding path validates gasless bundles based on a different transaction-type interpretation than the one used by the transaction pool / EVM execution path, mirroring the pip bug class of "the same byte payload is interpreted differently depending on which parser handles it."

### Title
Ambiguous Ethereum-envelope-prefix heuristic in `IsGaslessTx` causes gasless bundle validation to diverge from actual transaction decoding used elsewhere in the node - ([File: kaiax/gasless/impl/api.go])

### Summary
Multiple independent RPC/API entry points re-implement, inconsistently, a heuristic that decides whether a raw transaction byte-string is a "naked" EIP-2718 Ethereum-typed transaction (requiring the `0x78` `EthereumTxTypeEnvelope` prefix to be prepended before RLP decoding) or a Kaia-native/legacy transaction (decoded as-is). Each endpoint uses a different byte-range test, and one endpoint applies no heuristic at all, so the very same raw bytes can be parsed into structurally and semantically different `types.Transaction` objects depending on which code path decodes them — analogous to the pip issue where the same archive bytes are validly interpreted as either ZIP or tar depending on the parser.

### Finding Description
`GaslessAPI.IsGaslessTx` independently decodes attacker/user-supplied raw transaction bytes using its own copy of the envelope-detection heuristic: [1](#0-0) 

This heuristic (`0 < rawTx[0] && rawTx[0] < 0x7f`) is duplicated, with different bounds, across several independent RPC surfaces:
- `EthAPI.SendRawTransaction`: `0 < input[0] && input[0] < 0x7f` [2](#0-1) 
- `KaiaTransactionAPI.SendRawTransactions` (plural): `0 < input[0] && input[0] < 0x7f` [3](#0-2) 
- `KaiaTransactionAPI.RecoverFromTransaction`: `0 < encodedTx[0] && encodedTx[0] < 0x8`, explicitly annotated `// TODO: Add helper to distinguish eth vs Kaia txtypes` [4](#0-3) 
- `KaiaTransactionAPI.SendRawTransaction` (singular): **no heuristic at all** — decodes the bytes verbatim [5](#0-4) 

The underlying transaction encoding makes this heuristic load-bearing rather than cosmetic: Kaia-native typed transactions (e.g. `TxTypeValueTransfer = 8`, up through `TxTypeChainDataAnchoring`-family values) are RLP-encoded with the type as a raw small integer as the very first byte, exactly the same byte range (`0x01`–`0x7e`) that the various heuristics treat as a "naked Ethereum typed tx" needing an `0x78` prefix: [6](#0-5) [7](#0-6) 

Because each entry point (`eth_sendRawTransaction`, `kaia_sendRawTransactions`, `kaia_sendRawTransaction`, `kaia_recoverFromTransaction`, and the gasless module's `IsGaslessTx`) applies a different rule for whether to prepend `EthereumTxTypeEnvelope`, the *same* raw byte sequence can decode into a legacy/native Kaia transaction under one code path and into an Ethereum-typed transaction (or fail entirely) under another. This is structurally the same bug class as the pip advisory: a single artifact is not uniquely classifiable by format, and different consumers of that artifact silently disagree on its meaning.

### Impact Explanation
`IsGaslessTx` is meant to let a caller pre-validate that a set of raw bytes, once submitted, will be accepted and honestly settled as a gasless approve/swap bundle (recipient, calldata, amounts, gas parameters, `VerifyExecutable` checks) as defined in KIP-247. Because `IsGaslessTx` decodes the bytes with its own local, permissive heuristic rather than delegating to the canonical decode path that the transaction pool / EVM will use for admission and execution, a transaction whose leading byte falls in the ambiguous `0x01–0x7e` region can be validated by `IsGaslessTx` as one semantic transaction (e.g., a legitimate swap with acceptable `minAmountOut`/`amountRepay`/recipient) while ultimately being admitted to the pool and executed with a different interpretation of its fields, since the pool/EVM decode path is not guaranteed to apply the identical prefixing rule. This class of decode divergence can misrepresent what will actually execute relative to what was "verified executable," undermining the gasless settlement guarantees (fee/lend repayment correctness) that `VerifyExecutable`, `checkBalanceForSwap`, and `checkBalanceForApprove` are meant to enforce.

### Likelihood Explanation
Reachable by any unprivileged public-RPC caller: `IsGaslessTx` takes arbitrary `rawTxs []hexutil.Bytes` directly from the caller with no other admission control, and the divergent heuristics across `eth_sendRawTransaction` / `kaia_sendRawTransaction(s)` / `RecoverFromTransaction` are all also reachable by unauthenticated public RPC calls. Triggering the divergence requires crafting a byte sequence whose leading byte falls in `0x01–0x7e` such that it is *also* validly decodable as some real transaction type under both interpretations (RLP field-count mismatches will cause many crafted attempts to fail decode outright), so a working exploit requires careful, but ultimately not infeasible, byte-level RLP construction. I was not able to fully verify, given available context, whether the actual tx-pool admission path (`blockchain/tx_pool.go`) applies the exact same or a different envelope-prefixing rule as `IsGaslessTx`; confirming a concretely exploitable divergent-decode pair (bytes that decode two different, both-valid ways) would require deeper RLP-encoding-level testing than static review can settle.

### Recommendation
Replace all duplicated, inconsistent byte-range heuristics (`0 < b[0] < 0x7f`, `0 < b[0] < 0x8`, and the no-op case in singular `SendRawTransaction`) with a single shared helper (as already flagged by the `TODO: Add helper to distinguish eth vs Kaia txtypes` comment) that unambiguously classifies a raw transaction's type, and have every RPC entry point — including `GaslessAPI.IsGaslessTx` — use that single canonical decode path (ideally the same one used by the transaction pool for admission) rather than re-implementing local classification logic.

### Proof of Concept
Not independently confirmed with a concrete two-way-valid byte sequence; further work is needed to construct raw bytes whose leading byte lies in `0x01–0x7e` and that decode successfully both (a) directly as a Kaia-native `TxInternalDataSerializer` payload and (b) as an `EthereumTxTypeEnvelope`-prefixed EIP-2718 typed transaction, then compare the interpretation accepted by `IsGaslessTx` against the interpretation ultimately admitted/executed by the transaction pool.

func (s *KaiaTransactionAPI) SendRawTransactions(ctx context.Context, inputs []hexutil.Bytes) ([]common.Hash, error) {
	hash := []common.Hash{}
	errs := []error{}

	if len(inputs) == 0 {
		hash = append(hash, common.Hash{})
		return hash, errors.New("Empty input")
	}

	for i, input := range inputs {
		if len(input) == 0 {
			hash = append(hash, common.Hash{})
			errs = append(errs, fmt.Errorf("Index %d: empty input", i))
			break
		}
		// Allow naked Ethereum tx types
		if 0 < input[0] && input[0] < 0x7f {
			input = append([]byte{byte(types.EthereumTxTypeEnvelope)}, input...)
		}
		tx := new(types.Transaction)
		if err := rlp.DecodeBytes(input, tx); err != nil {
			hash = append(hash, common.Hash{})
			errs = append(errs, fmt.Errorf("Index %d: %w", i, err))
			break
		}
		if err := s.b.SendTx(ctx, tx); err != nil {
			hash = append(hash, common.Hash{})
			errs = append(errs, fmt.Errorf("Index %d: %w", i, err))
			break
		}
		hash = append(hash, tx.Hash())
	}

	return hash, errors.Join(errs...)
}

func (serializer *TxInternalDataSerializer) EncodeRLP(w io.Writer) error {
	// if it is the original transaction, do not encode type.
	if serializer.txType == TxTypeLegacyTransaction {
		return rlp.Encode(w, serializer.tx)
	}

	if serializer.txType.IsEthTypedTransaction() {
		ethType := byte(serializer.txType)
		if _, err := w.Write([]byte{byte(EthereumTxTypeEnvelope), ethType}); err != nil {
			return err
		}
	} else {
		if err := rlp.Encode(w, serializer.txType); err != nil {
			return err
		}
	}

	return rlp.Encode(w, serializer.tx)
}

func (serializer *TxInternalDataSerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.txType); err != nil {
		// fallback to the original transaction decoding.
		txd := newEmptyTxInternalDataLegacy()
		if err := s.Decode(txd); err != nil {
			return err
		}
		serializer.txType = TxTypeLegacyTransaction
		serializer.tx = txd
		return nil
	}

	if serializer.txType == EthereumTxTypeEnvelope {
		var ethType TxType
		if err := s.Decode(&ethType); err != nil {
			return err
		}
		serializer.txType = serializer.txType<<8 | ethType
	}

	var err error
	serializer.tx, err = NewTxInternalData(serializer.txType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.tx)
}
