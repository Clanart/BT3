### Title
App Proxy Verification accepts arbitrarily stale/replayed signed requests due to missing timestamp freshness check - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#verify_proxy_request` only checks that the HMAC `signature` query parameter matches the recomputed signature of the other query parameters; it never validates the `timestamp` parameter that Shopify includes in every signed app-proxy request. This mirrors the root cause of the reported oracle issue: data that is signed/sourced with a freshness indicator (Chainlink `roundId`/`updatedAt`, here Shopify's proxy `timestamp`) is accepted without any check that it is recent, so a stale/previously-valid signed payload is trusted indefinitely.

### Finding Description
`query_string_valid?` parses the query string, extracts `signature`, and compares it via `ActiveSupport::SecurityUtils.secure_compare` against `calculated_signature`, which is simply an HMAC-SHA256 over the sorted `key=value` pairs (including `timestamp`) using the app secret: [1](#0-0) 

The `timestamp` value is part of what gets signed, but the code never reads it back out to compare against the current time or enforce a validity window — it treats a signature as valid forever as long as the HMAC matches, exactly analogous to `_calculateAnswer()` trusting `baseAnswer` without checking `updatedAt`/`roundId` for staleness. Any request that was ever legitimately signed by Shopify's app proxy (and later observed by an attacker — e.g. via browser history, shared/bookmarked links, proxy/CDN logs, referrer leakage, or a compromised network intermediary) remains permanently replayable against `AppProxyController` and any other controller that includes this concern: [2](#0-1) 

The test suite itself demonstrates that fixed, long-expired `timestamp=1466106083` (year 2016) query strings are still treated as valid signed requests: [3](#0-2) 

### Impact Explanation
Any anonymous party who has captured a single valid app-proxy signed URL for a shop can replay that exact request against the merchant's app proxy endpoint at any time in the future — the signature never expires. Depending on what the app-proxy controller does with the request (e.g., triggering shop-scoped actions, returning liquid-rendered shop data, or performing side effects keyed off `shop` query param), this enables unauthorized repeated/forged-appearing requests attributed to a shop well beyond the original request's intended validity, which is the concrete "accepted forged/stale signed request" class described in the report.

### Likelihood Explanation
Likelihood is limited by the precondition that an attacker must first observe one valid signed app-proxy URL (e.g., via browser history, shared screenshots/logs, or MITM on a non-TLS hop), but once obtained, replay requires no further interaction with a merchant or Shopify — it works indefinitely, which is a meaningfully weaker guarantee than what Shopify's inclusion of `timestamp` in the signed payload is intended to provide.

### Recommendation
Parse and validate the `timestamp` query parameter in `verify_proxy_request`/`query_string_valid?`, rejecting requests whose timestamp is outside an acceptable freshness window (e.g., a few minutes), mirroring the report's recommendation to check `updatedAt`/`roundId` for staleness before trusting signed/sourced data: [4](#0-3) 

### Proof of Concept
1. Capture a legitimately Shopify-signed app-proxy request URL for a shop, e.g. `?shop=some-shop.myshopify.com&path_prefix=/apps/my-app&timestamp=1466106083&signature=<valid-hmac>` (as used in the existing test fixture).
2. At any later date, replay the exact same URL against the app's `AppProxyController` route.
3. `verify_proxy_request` recomputes the HMAC over the same parameters (including the old `timestamp`) and it matches, so the request passes verification and is processed as if freshly issued by Shopify — confirmed by the passing test using a 2016-era timestamp: [3](#0-2)

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
