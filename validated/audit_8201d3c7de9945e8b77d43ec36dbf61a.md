### Title
Data Layer client SSRF via unfiltered mirror-URL HTTP fetch enables internal network / cloud-IMDS reachability - ([File: chia/data_layer/download_data.py])

### Summary
Chia's `DataLayer` service fetches delta/full-tree files from URLs advertised by DataLayer mirror coins (published on-chain, attacker-controllable content) or manually-supplied subscription URLs, using a plain `aiohttp.ClientSession` with **no destination-IP filtering**, directly mirroring the Mailpit `newSafeHTTPClient` regression described in the report (dialer/client with no `safeDialContext`-style IP allowlist).

### Finding Description
`chia/data_layer/download_data.py::http_download` issues `session.get(server_info.url + "/" + filename, ...)` with a plain `aiohttp.ClientSession()` and only a `proxy` argument — there is no check that the resolved destination is not loopback/private/link-local/CGNAT before connecting: [1](#0-0) 

This is invoked from `download_file()` (used when no plugin `downloader` is configured), which is itself called from `insert_from_delta_file()` for each `server_info` entry: [2](#0-1) 

The `server_info` list comes from `DataStore.get_available_servers_for_store()`, populated by subscription URLs — either supplied directly via the `subscribe` RPC (`chia/data_layer/data_layer_rpc_api.py::subscribe`, `chia/data_layer/data_layer.py::subscribe`) with attacker-chosen arbitrary strings: [3](#0-2) [4](#0-3) 

or synchronized from on-chain DataLayer mirror coins that any wallet participant can publish (the mirror coin's memo carries the URL string, which is untrusted, adversary-controlled data by design — DataLayer explicitly documents "do not treat mirror URLs... as trusted data sources," see `.cursor/context/data-layer.md`): [5](#0-4) 

`DataLayer.fetch_and_validate()` iterates these `servers_info` entries and calls `insert_from_delta_file`, which drives the vulnerable `http_download`: [6](#0-5) 

Unlike Mailpit's `linkcheck`/`proxy` sister handlers (which the advisory contrasts against the vulnerable `htmlcheck` dialer), there is no analog of a `safeDialContext`/`tools.IsInternalIP` check anywhere in Chia's `download_data.py`, `data_layer.py`, or `s3_plugin_service.py` HTTP-fetch paths — every one of them (`http_download`, the plugin `download_file` POST, `get_uploaders`/`check_plugins` plugin calls) dials attacker-supplied URLs unconditionally: [7](#0-6) 

Chia's own peer-connection code (`chia/server/server.py`) does have IP/CIDR-aware helpers (`is_in_network`, `is_localhost`, `is_trusted_cidr`) used for trusted-peer/exempt-network checks, but these are not reused to gate the DataLayer mirror-fetch HTTP client: [8](#0-7) 

### Impact Explanation
Any Data Layer participant (the store owner, or any peer who subscribes to/mirrors a store) can cause the local DataLayer node to issue outbound HTTP GET requests to arbitrary URLs, including `127.0.0.1`, RFC1918 ranges, and cloud IMDS (`169.254.169.254`), by:
1. Publishing (or configuring) a mirror/subscription URL pointing at an internal service, or a public redirector that 302s into the internal network, and
2. Waiting for `periodically_manage_data()` / `fetch_and_validate()` to run its normal sync cycle, which unconditionally dials that URL via `http_download`.

This satisfies the "Data Layer client" reachable-actor allowance in scope. Consequences mirror the Mailpit report: SSRF-driven internal service probing/interaction (state-changing GETs against internal admin endpoints), cloud-IMDS credential-reachability oracle, and internal port-scan via timing — all triggerable by an unprivileged Data Layer subscriber without needing to compromise any peer or the network layer itself.

### Likelihood Explanation
Likelihood is Medium: reaching the vulnerable code only requires normal Data Layer usage (`subscribe` RPC with an attacker-influenced URL string, or waiting for the periodic sync loop to process a mirror coin's URL from chain), no authentication bypass or special privilege is required beyond running/operating a DataLayer node that subscribes to an untrusted store — a documented, expected usage pattern (subscribing to third-party stores/mirrors). Automatic, unattended periodic execution (`periodically_manage_data`) means the SSRF fires without user interaction once a malicious mirror URL is present.

### Recommendation
Add an IP-filtering dialer (equivalent to Mailpit's `safeDialContext`) to all outbound HTTP fetch paths driven by untrusted URLs in `chia/data_layer/download_data.py` (`http_download`, plugin POST calls) and `chia/data_layer/data_layer.py` (`get_uploaders`, `check_plugins`, `get_downloader`/plugin discovery). Concretely:
- Before connecting, resolve the URL's host and reject if the resolved IP is loopback, private (RFC1918), link-local (including `169.254.169.254`), CGNAT (`100.64.0.0/10`), or otherwise reserved — reuse/extend `chia/util/network.py` helpers (`is_in_network`, `is_localhost`) for this purpose, similar to how `chia/server/server.py` already gates peer connections.
- Apply the same filter to any HTTP redirect targets, not just the initial URL.
- Make this validation mandatory by default (with an explicit opt-out config flag for trusted/local test environments), rather than leaving mirror/plugin URLs fully trusted.

### Proof of Concept
1. Start a DataLayer node and create/own a store `store_id`.
2. As any Data Layer counterparty, call the `subscribe` RPC on a victim node with a URL pointing at an internal target, e.g.:
   ```
   POST /subscribe {"id": "<store_id_hex>", "urls": ["http://127.0.0.1:6379"]}
   ```
   (see `chia/data_layer/data_layer_rpc_api.py::subscribe`, `chia/data_layer/data_layer.py::subscribe`).
3. Wait for (or trigger) `periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`.
4. `insert_from_delta_file()` → `download_file()` → `http_download()` issues `session.get("http://127.0.0.1:6379" + "/" + filename, ...)` with no IP validation, completing a TCP connection to the internal service — identical in mechanism to the Mailpit `newSafeHTTPClient` SSRF (unfiltered dialer + redirect-following), confirmed at `chia/data_layer/download_data.py:298-319` and the call chain in `chia/data_layer/data_layer.py:642-694`.

    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()

def is_in_network(peer_host: str, networks: Iterable[IPv4Network | IPv6Network]) -> bool:
    try:
        peer_host_ip = ip_address(peer_host)
        return any(peer_host_ip in network for network in networks)
    except ValueError:
        return False


def is_trusted_cidr(peer_host: str, trusted_cidrs: list[str]) -> bool:
    try:
        ip_obj = ipaddress.ip_address(peer_host)
    except ValueError:
        return False

    for cidr in trusted_cidrs:
        network = ipaddress.ip_network(cidr)
        if ip_obj in network:
            return True

    return False


def is_localhost(peer_host: str) -> bool:
    return peer_host in {"127.0.0.1", "localhost", "::1", "0:0:0:0:0:0:0:1"}


def is_trusted_peer(
    host: str, node_id: bytes32, trusted_peers: dict[str, Any], trusted_cidrs: list[str], testing: bool = False
) -> bool:
    return (
        (not testing and is_localhost(host)) or node_id.hex() in trusted_peers or is_trusted_cidr(host, trusted_cidrs)
    )
