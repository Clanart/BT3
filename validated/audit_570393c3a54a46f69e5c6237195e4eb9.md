### Title
`ThresholdKeys::read`/`ThresholdKeys::new` validates only the first `t` verification shares, letting attacker-supplied keys deserialize to an attacker-controlled group key with unverifiable shares - (File: crypto/dkg/src/lib.rs)

### Summary
The external bug class: a confinement guard (`ScopedFs.within`) resolves a dangling symlink to its nearest *existing ancestor*, validates that ancestor instead of the leaf, and then lets the operation proceed on the unvalidated leaf — escaping the scope only when the target "does not exist". The analog in Serai is `ThresholdKeys` deserialization: `ThresholdKeys::new` performs its structural validation (`n` shares present, indexes `<= n`, threshold sane) and derives `group_key` from *only* participants `1..=t`, while the semantic property that actually matters — that `secret_share` corresponds to `verification_shares[i]` and that all `n` verification shares interpolate to the same group key — is never checked for any participant. An unprivileged party who can feed bytes to `ThresholdKeys::read` (a listed untrusted-input sink) obtains "validated" keys whose group key is attacker-chosen and whose shares cannot actually sign.

### Finding Description
`ThresholdKeys::read` parses `t`, `n`, `i`, the interpolation method, `secret_share`, and exactly `n` verification shares, then calls `ThresholdKeys::new` [1](#0-0) . `ThresholdKeys::new` checks only:

- `verification_shares.len() == n` and each index `<= n` [2](#0-1) ,
- that `Constant` interpolation only applies when `t == n` [3](#0-2) .

It then computes `group_key` as the Lagrange interpolation of shares `1..=t` only [4](#0-3) . Nothing verifies:

1. `secret_share * G == verification_shares[i]` — the holder's own share is never bound to the public data.
2. That participants `t+1..=n` lie on the same degree-`t-1` polynomial — shares beyond the first `t` are stored but contribute nothing to `group_key`.

This is exactly the dangling-symlink shape: the "existing ancestor" (the first `t` shares, which are always resolvable into a group key) is validated and used, while the "unresolved leaf" (the remaining shares and the secret share's consistency) is never inspected, yet the resulting object is used for address derivation and signing. The code even acknowledges the failure mode elsewhere: `complete()` notes "deserialize a semantically invalid FrostKeys" as the known cause of all-shares-valid-yet-invalid-signature [5](#0-4) .

### Impact Explanation
An attacker supplies serialized `ThresholdKeys` with `verification_shares[1..=t]` chosen to interpolate to a group key `Y` they control (any `t` points on a polynomial whose constant term is their secret), arbitrary points for `t+1..=n`, and an arbitrary `secret_share` for the victim's index `i`. A consumer that deserializes these bytes and derives a deposit address from `group_key()` (as the Bitcoin integration does via `Scanner::new(key)`/`p2tr_script_buf` [6](#0-5) ) reports funds as received to a key only the attacker can spend — theft of deposits ("funds reported received that are not spendable" by the group). Alternatively, with a correct-looking `secret_share` drawn from a different polynomial, signing sets other than `1..=t` interpolate to a different effective group key, producing shares that fail `verify_share` and wrongly blame honest participants.

### Likelihood Explanation
Requires the victim to load key material from an untrusted/peer-supplied source rather than a locally run DKG — e.g., key recovery, migration, or a coordinator distributing serialized keys. That is a plausible integration path (the type exposes `read`/`serialize` precisely for persistence/transport), and no authentication of the bytes is enforced inside the crate. Exploitation is deterministic once the bytes are consumed.

### Recommendation
In `ThresholdKeys::new` (or additionally in `read`), validate the leaf rather than the ancestor:

- Check `C::generator() * secret_share == verification_shares[&i]`.
- Verify all `n` verification shares are consistent: interpolate `group_key` from at least two disjoint size-`t` subsets (or check that every share lies on the degree-`t-1` polynomial defined by `1..=t`) so participants `t+1..=n` are bound to the same key.
- Reject any `Interpolation::Constant` vector length that doesn't match `t`/`n` expectations before indexing into it in `interpolation_factor` [7](#0-6) .

Add a regression test feeding `read` a serialized blob whose `t+1..=n` shares are inconsistent, asserting rejection.

### Proof of Concept
```rust
// Attacker crafts bytes accepted by ThresholdKeys::<C>::read:
//   C::ID header, t = 2, n = 3, i = 3, Lagrange,
//   secret_share = random garbage s',
//   verification_shares:
//     [1] = G*a, [2] = G*b          // chosen so Lagrange at 0 yields attacker key Y_att
//     [3] = arbitrary point          // never affects group_key
//
// ThresholdKeys::new computes:
//   group_key = v[1]*λ1 + v[2]*λ2 = Y_att   // attacker knows dlog(Y_att)
// and returns Ok — no check that G*s' == v[3], none that v[3] lies on
// the polynomial through (1,a),(2,b).
//
// Victim: Scanner::new(keys.group_key()) derives P2TR address for Y_att.
// Deposit to that address is reported received by scan_transaction
// (script match), but only the attacker holds dlog(Y_att) — funds stolen,
// and no signing set including participant 3 can ever produce a valid share.
```

  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
        num * denom.invert().unwrap()
      }
    }

    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
