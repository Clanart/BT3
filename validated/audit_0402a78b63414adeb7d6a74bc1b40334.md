### Title
Empty aggregate signatures bypass Schnorr authorization checks - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero signatures when `s == 0`, even though `SchnorrAggregator::complete` explicitly refuses to produce empty aggregates. This lets an unauthenticated byte string satisfy verification without any signer authorization. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrAggregate::read` permits the encoded signature count to be zero and then reads only the scalar `s`. [1](#0-0)  During verification, matching an empty `keys_and_challenges` list adds only `(-s) * G` to the verification equation. [3](#0-2)  For `s = 0`, that term is the identity and verification succeeds. The aggregator’s own completion path treats an empty aggregation as invalid by returning `None`, confirming that this input is not intended to verify. [2](#0-1) 

### Impact Explanation
An attacker can submit a serialized aggregate with zero `Rs` and a zero scalar to any caller that treats `verify(dst, &[])` as an authorization decision. The result is a forged aggregate signature created without knowledge of any private key or nonce. This is particularly dangerous if an empty authorization set is reached through malformed request decoding, missing configured signers, or another incomplete authorization path. [3](#0-2) 

### Likelihood Explanation
The malicious input is only four zero bytes for the signature count plus a canonical zero scalar. No signing capability, participant access, collusion, or secret information is required; the attacker only needs to feed bytes to `SchnorrAggregate::read` and have the resulting object passed to `verify` with an empty signer list. [1](#0-0) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify` before checking the multiexp result, and preferably reject them in `SchnorrAggregate::read` as well. The verifier should require `!self.Rs.is_empty()` and a non-empty `keys_and_challenges` list in addition to their lengths matching. [3](#0-2) 

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::aggregate::SchnorrAggregate;

fn empty_aggregate_bypasses<C: Ciphersuite>() {
    // Length = 0, followed by the canonical encoding of scalar zero.
    let mut bytes = 0u32.to_le_bytes().to_vec();
    bytes.extend(C::F::ZERO.to_repr().as_ref());

    let aggregate = SchnorrAggregate::<C>::read(&mut bytes.as_slice()).unwrap();

    // No public keys or challenges are supplied, yet verification succeeds because
    // the only remaining term is (-0) * G.
    assert!(aggregate.verify(b"example authorization domain", &[]));
}
```

The accepted bytes correspond to `Rs = []` and `s = 0`; the verification equation reduces to the identity point without evaluating any signer authorization. [4](#0-3)
