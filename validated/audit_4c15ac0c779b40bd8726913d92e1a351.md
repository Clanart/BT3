The reported issue is specific to Blast L2's native rebasing tokens (USDB/WETH) whose automatic-yield rebasing silently increases an ERC20 balance out-of-band from a Solidity staking contract's internal accounting variables (`stakingTokenBalance`, per-user balances) in `LockingMultiRewards.sol`. This bug class has no structural analog in `chia-blockchain`:

- Chia has no rebasing tokens or automatic-yield token standard; CATs represent fixed, explicit on-chain amounts encoded directly in coin amounts and enforced via TAIL programs, with no separate internal ledger that could diverge from an external token contract's actual balance [1](#0-0) .
- CAT supply changes only happen through explicit mint/melt deltas checked against the TAIL and coin amounts in the same spend, so there is no out-of-band balance drift mechanism analogous to Blast's automatic rebasing [2](#0-1) .
- Reward/yield distribution in Chia (e.g., pool rewards, plotnft claims) is coin-based and 1:1 with amounts actually created on-chain; there's no internal accounting layer separate from actual spendable coin amounts that could "lose" accrued yield the way an ERC20 staking contract's internal ledger can miss token-contract-level rebases [3](#0-2) .

Since Chia's coin-set/UTXO model with CATs, singletons, and pool rewards has no concept of an external rebasing asset contract whose balance can silently grow independent of the tracked accounting, this EVM/Blast-specific bug class does not have a valid reachable analog in scope.
