### Title
`aptos move verify-package` reports "Successfully verified source of package" without ever comparing on-chain bytecode to the locally-compiled bytecode - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
The Aptos CLI's `verify-package` command is meant to let a user confirm that the bytecode published on-chain under an address actually corresponds to a given source tree. In practice, `VerifyPackage::execute` in [1](#0-0)  fetches the on-chain `PackageRegistry` with `CachedPackageRegistry::create(client, self.account, false)` — the `with_bytecode` flag is `false` — and then calls `package.verify(&compiled_metadata)`. That `verify()` function, defined in [2](#0-1) , only compares `PackageMetadata` fields: `name`, `deps`, `modules` (which itself is just `name`/`source`/`source_map`/`extension`, see [3](#0-2) ), `manifest`, `upgrade_policy`, `extension`, and `source_digest`. None of these fields is the actual compiled module bytecode. The real bytecode is a separate `code: vector<vector<u8>>` argument that is never stored inside `PackageMetadata` — it's stored as ordinary account module bytecode, retrievable only through `get_account_module`/`CachedPackageRegistry::get_bytecode`, which is never populated or checked by the `verify-package` path.

### Finding Description
`code::publish_package` in [4](#0-3)  takes `pack: PackageMetadata` (name, deps, modules-with-source, manifest, policy, source_digest) and a separate `code: vector<vector<u8>>` containing the actual compiled bytecode, and forwards them independently to `request_publish`/`request_publish_with_allowed_deps`. The `PackageMetadata`/`ModuleMetadata` structures never carry a hash or digest of the compiled bytecode itself — only zipped *source* text (`ModuleMetadata::source`) and a package-level `source_digest` computed over the source files.

The CLI's `verify-package` command is documented (and named) as verifying that "the on-chain copy matches" a local compilation: "Build the package locally and verify that the on-chain copy matches" per [5](#0-4) . However, its implementation only diff-checks `PackageMetadata` structs (name/deps/modules-source/manifest/policy/extension/source_digest) as shown in `CachedPackageMetadata::verify` [2](#0-1) , and `VerifyPackage::execute` explicitly disables bytecode fetching by passing `false` to `CachedPackageRegistry::create` [1](#0-0) . There is no comparison anywhere in this path between the bytes actually loaded/executed on-chain for each module (fetchable via `get_account_module`) and the bytecode produced by the local `BuiltPackage::build_to` compilation.

This is a verified-bytes vs. committed-module-bytes mismatch: the tool asserts "verified source" but never inspects the committed bytecode that the VM actually loads and runs, only the human-readable source text and package/module metadata bundled voluntarily by the publisher inside `PackageMetadata`. A publisher can trivially submit accurate/benign source in `ModuleMetadata::source` (and thus a correct `source_digest`) while submitting different, malicious compiled bytecode in the `code` vector passed to `publish_package`/`publish_package_txn`, since nothing on-chain or in the CLI ties the declared source metadata to the actual bytecode hash.

### Impact Explanation
Users, auditors, and downstream tooling rely on `aptos move verify-package` to establish trust that "what you see (source) is what's deployed (bytecode)" before interacting with or depending on a package. Because the check silently ignores the actual bytecode, an attacker can publish a package whose declared/zipped source is benign (and matches `source_digest`) while the actual executable bytecode differs and contains malicious logic (backdoors, altered event emission, hidden privileged functions, etc.). Any party who runs `verify-package` and sees "Successfully verified source of package" will incorrectly conclude the deployed code matches the audited/reviewed source, and place trust (funds, permissions, further composability) in code that was never actually verified. This directly enables unauthorized/undetected malicious code being treated as verified, a code-safety/publish-trust violation with high impact for anyone relying on `verify-package` as a security signal.

### Likelihood Explanation
Likelihood is high for exploitation of the *verification gap* itself: the code path is unconditionally exercised any time `verify-package` is invoked, requires no special privilege beyond being the package publisher, and the discrepancy between "source, source_digest, manifest match" and "bytecode identical" is not otherwise checked anywhere in the framework (`code.move`'s Move spec explicitly notes upgrade/ownership/compat invariants are audited, but nothing claims the CLI verify tool checks bytecode identity). The main constraint is that this is a CLI-side trust tool rather than an on-chain enforcement mechanism, so the "victim" is anyone who trusts the CLI's verification result rather than the chain state itself.

### Recommendation
Modify `verify-package` (and `CachedPackageMetadata::verify`) to always fetch the on-chain module bytecode (`with_bytecode = true`) and to compile a reference bytecode from the local source, then compare the on-chain bytecode bytes (or their hash) module-by-module against the locally compiled artifacts, in addition to the existing metadata field comparisons. Consider adding an explicit bytecode hash field into `PackageMetadata`/`ModuleMetadata` (or deriving one from the module store) so that `source_digest` cannot diverge from what is actually executable, closing the gap between the declared/verified source and the committed module bytes.

### Proof of Concept
1. Compile package `Pkg` with benign module `m.move`, obtaining `PackageMetadata` containing zipped source of `m.move` and `source_digest = H(source files)`.
2. Before submitting the publish transaction, replace the compiled `code: vector<vector<u8>>` entry for `m` with a different, malicious bytecode blob (still self-addressed correctly and passing compatibility/verifier checks, e.g. same public API surface but different private/native logic) while leaving `PackageMetadata` (including `modules[i].source`, `source_digest`) unchanged.
3. Submit `code::publish_package_txn(owner, metadata_serialized, code)` — [6](#0-5)  — this succeeds because `PackageMetadata` is self-consistent and the bytecode is separately checked only for VM-level compatibility/verifier constraints (not against the source), see `AptosVM::validate_publish_request` [7](#0-6) .
4. Run `aptos move verify-package --account <addr>` against the local (benign) source directory. The command reports `"Successfully verified source of package"` because `VerifyPackage::execute` [1](#0-0)  never downloads or compares the actual bytecode; it only calls `package.verify(&compiled_metadata)`, which checks unrelated metadata fields [2](#0-1) .
5. Result: a reviewer trusting the "verified" result interacts with bytecode that does not correspond to the reviewed source, despite the tool's success message.

            ));

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    /// Publishes a package at the given signer's address. The caller must provide package metadata describing the
    /// package.
    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
