### Title
Flat-cost `sol_get_processed_sibling_instruction` syscall allows a program to force an O(instruction-trace-length) linear scan for a fixed 100 CU, decoupling compute charged from real work performed - (File: syscalls/src/lib.rs)

### Summary
`SyscallGetProcessedSiblingInstruction::rust` charges a single, size-independent `syscall_base_cost` and then performs a linear, reverse scan over a range of the transaction's instruction trace whose length depends on how many instructions/CPIs have already been recorded in the transaction (up to `max_instruction_trace_length`). A user program can maximize this scan length (e.g. by making many prior top-level instructions or CPI calls in the same transaction) and then repeatedly invoke this syscall, paying only the fixed base cost per call regardless of how much of the trace must be walked.

### Finding Description
The syscall implementation is: [1](#0-0) 

Cost accounting happens once, up-front, independent of the size of `range`: [2](#0-1) 

The loop then walks `range.rev()`, where `range` for the CPI case spans `start..end` derived from `number_of_cpis_in_trace()` — a value that grows with the number of CPIs a caller has already performed in the same transaction, and for the top-level case spans `0..next_top_level_instruction_index()` — growing with the number of already-processed top-level instructions: [3](#0-2) 

Both bounds are user-controlled up to `max_instruction_trace_length` (the SVM execution budget limit), which is materially larger than a single instruction: [4](#0-3) 

Every iteration performs non-trivial work: fetching the instruction context (`get_instruction_context_at_index_in_trace`), reading `get_index_of_caller()`, and comparing stack heights: [5](#0-4) 

Contrast this with other syscalls in the same file that loop over user-supplied data, which explicitly meter cost per iteration/byte, e.g. `SyscallHash` charging `hash_byte_cost` inside its loop: [6](#0-5) 
or CPI account-info translation charging `cpi_bytes_per_unit` proportional to work performed: [7](#0-6) 

`SyscallGetProcessedSiblingInstruction` breaks this pattern: it is the only trace-scanning syscall that charges a flat cost irrespective of the number of trace entries it must traverse.

### Impact Explanation
A malicious or just poorly-metered on-chain program can perform many CPIs (up to `max_instruction_trace_length`) within a single transaction and then call `sol_get_processed_sibling_instruction` repeatedly (once per CPI level or per instruction), each time only being charged the fixed 100 CU `syscall_base_cost` while the runtime does O(n) work walking the instruction trace on every call. Chained across many calls in one transaction, this produces O(n²) actual host-side work for O(n) charged compute units, allowing a transaction to consume disproportionately more validator CPU time per compute unit purchased than intended. This directly matches the "materially underpriced compute" acceptance criterion — it lets an unprivileged transaction submitter buy far more real execution time than the fee/CU budget reflects, which can be used to slow down block processing across the cluster.

### Likelihood Explanation
This is trivially reachable by any user-deployed BPF program invoking a standard, stable syscall (`sol_get_processed_sibling_instruction`) with no special privileges, and requires only building a transaction with many CPIs — well within `max_instruction_trace_length` and normal compute-unit budgets since the per-call charge stays flat. No validator/operator role or crafted snapshot is needed.

### Recommendation
Charge compute proportional to the number of trace entries actually scanned (e.g. `syscall_base_cost + mem_op_base_cost * iterations_scanned`, similar to how `SyscallHash` and CPI translation charge per unit of work), or cap/charge based on `range.len()` before entering the loop rather than a single flat `syscall_base_cost`.

### Proof of Concept
1. Deploy a program that performs `N` CPI invocations (e.g. into a no-op program) within a single transaction, driving `number_of_cpis_in_trace()` toward `max_instruction_trace_length`.
2. From deep inside the CPI stack (or from each CPI frame), call `sol_get_processed_sibling_instruction` with increasing `index` values, observing via `sol_remaining_compute_units()` (see test harness pattern in [8](#0-7)  and CU-usage tests in [9](#0-8) ) that CU consumption per call stays flat at `syscall_base_cost` regardless of `N`, while wall-clock time to execute the syscall scales with `N` (measurable via benchmarking or timing the transaction's execution as `N` grows).

declare_builtin_function!(
    /// Get a processed sigling instruction
    SyscallGetProcessedSiblingInstruction,
    fn rust(
        invoke_context: &mut InvokeContext<'_, '_>,
        index: u64,
        meta_addr: u64,
        program_id_addr: u64,
        data_addr: u64,
        accounts_addr: u64,
    ) -> Result<u64, Error> {
        let execution_cost = invoke_context.get_execution_cost();

        invoke_context.compute_meter.consume_checked(execution_cost.syscall_base_cost)?;

        let stack_height = invoke_context.get_stack_height();
        let mut reverse_index_at_stack_height = 0;
        let mut found_instruction_context = None;
        let current_ix_caller = invoke_context.transaction_context.get_current_instruction_context()?.get_index_of_caller();

        // Either we only search for top level instructions or CPIs, depending on the stack height.
        let range = if stack_height == 1 {
            0..invoke_context.transaction_context.next_top_level_instruction_index()
        } else {
            let end = invoke_context.transaction_context.get_instruction_trace_length();
            let start = end.saturating_sub(invoke_context.transaction_context.number_of_cpis_in_trace());
            start..end
        };

        for index_in_trace in range.rev() {
            let instruction_context = invoke_context
                .transaction_context
                .get_instruction_context_at_index_in_trace(index_in_trace)?;
            // If we are searching through CPIs, sibling instructions must have the same caller
            // but instructions from different callers are interspaced in the frame.
            if instruction_context.get_index_of_caller() != current_ix_caller {
                continue;
            }

            if instruction_context.get_stack_height() < stack_height {
                break;
            }
            if instruction_context.get_stack_height() == stack_height {
                if index.saturating_add(1) == reverse_index_at_stack_height {
                    found_instruction_context = Some(instruction_context);
                    break;
                }
                reverse_index_at_stack_height = reverse_index_at_stack_height.saturating_add(1);
            }
        }

    pub fn get_instruction_context_at_index_in_trace(
        &self,
        index_in_trace: usize,
    ) -> Result<InstructionContext<'_, '_>, InstructionError> {
        let instruction = self
            .instruction_trace
            .get(index_in_trace)
            .ok_or(InstructionError::CallDepth)?;

        // These commands will return a default empty slice if we are retrieving an instruction
        // that hasn't been configured yet.
        let instruction_accounts = self
            .instruction_accounts
            .get(index_in_trace)
            .map(|item| item.as_ref())
            .unwrap_or_default();
        let dedup_map = self
            .deduplication_maps
            .get(index_in_trace)
            .map(|item| item.as_ref())
            .unwrap_or_default();
        let instruction_data = self
            .instruction_data
            .get(index_in_trace)
            .map(|item| item.as_ref())
            .unwrap_or_default();
        Ok(InstructionContext {
            transaction_context: self,
            index_in_trace,
            nesting_level: instruction.nesting_level as usize,
            program_account_index_in_tx: instruction.program_account_index_in_tx as IndexOfAccount,
            instruction_accounts,
            dedup_map,
            instruction_data,
            index_of_caller_instruction: instruction.index_of_caller_instruction as usize,
        })
