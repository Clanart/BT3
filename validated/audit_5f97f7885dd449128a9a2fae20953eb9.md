## Title
JSON FieldMask Serialization Writes Raw Unescaped Characters, Permitting JSON Injection - (File: `src/google/protobuf/json/internal/unparser.cc`)

## Summary
The C++ ProtoJSON writer's `WriteFieldMask` function bypasses the library's own JSON string-escaping routine for `google.protobuf.FieldMask` path characters, writing certain attacker-controlled bytes—including `"`, `\`, and control characters such as `\n`/`\r`—directly to the output stream unescaped. This happens under the library's *default* `PrintOptions`, allowing a crafted `FieldMask.paths` value in an otherwise valid, bounded binary Protobuf message to break out of its intended JSON string literal when the message is serialized with `MessageToJsonString`/`MessageToJsonStream`, injecting attacker-controlled JSON structure into the output.

## Finding Description
Every other string field in ProtoJSON output goes through `JsonWriter::WriteEscapedUtf8` (`src/google/protobuf/json/internal/writer.cc:284-323`), which consults `MustEscape` (`writer.cc:198-269`) to escape quotes, backslashes, and all ASCII control characters (`\n`, `\r`, `\t`, etc., range `0x00-0x1f`) before they reach the output buffer.

`WriteFieldMask` (`src/google/protobuf/json/internal/unparser.cc:729-767`) does not use this path. It manually walks each character of a `FieldMask` path and, for any character that is not a lowercase letter, digit, `.`, or `_`, falls into:

```cpp
} else if (!writer.options().allow_legacy_nonconformant_behavior) {
  return absl::InvalidArgumentError("unexpected character in FieldMask");
} else {
  if (saw_under) {
    writer.Write('_');
  }
  writer.Write(c);
}
```
(`unparser.cc:753-759`)

`writer.Write(char c)` is `sink_.Append(&c, 1)` (`src/google/protobuf/json/internal/writer.h:100-102`)—a raw byte write with zero escaping. Crucially, `PrintOptions::allow_legacy_nonconformant_behavior` defaults to `true` (`src/google/protobuf/json/json.h:44-47`), so the *strict, safe* branch (which rejects the character) is not the default; the *raw-write* branch is. This is the same failure pattern as the rclone advisory: a reversible/escaping representation is trusted as the sole boundary protection for a framed output format, and a configuration state (here, the default) disables that protection.

External invariant that transfers: the FTP dependency assumed the caller's encoding step made CR/LF safe and did not itself validate the command argument; here the JSON writer's overall safety model assumes every field goes through `WriteEscapedUtf8`, but `WriteFieldMask` is a special-cased writer that skips it entirely for non-alphanumeric bytes.

Note: this is specific to the C++ implementation. The equivalent upb-based encoders (`upb/json/encode.c:433-459`, `php/ext/google/protobuf/php-upb.c:6972-6998`, `ruby/ext/google/protobuf_c/ruby-upb.c:5725-5751`) call `jsonenc_put_escaped_char` on every character of the field-mask path unconditionally, so they do not exhibit this gap.

## Impact Explanation
`FieldMask.paths` is a plain `repeated string` with no wire-level or semantic constraint on its bytes; any client sending valid, bounded binary Protobuf (a message containing a `FieldMask` field) fully controls its content. Any consuming application that (a) accepts such a message via a public parse API and (b) re-serializes it to JSON via `MessageToJsonString`/`BinaryToJsonString` with default options—an extremely common pattern for echoing, logging, or forwarding a request as JSON—will emit attacker-controlled raw `"`, `\`, and control bytes into what is expected to be a well-formed JSON string. This breaks the string's syntactic boundary and lets the attacker splice additional JSON keys/values into the surrounding document, i.e., JSON injection, with integrity impact on any downstream system that trusts the resulting JSON structure (config/log parsers, JSON-based routing, other services parsing the emitted JSON).

## Likelihood Explanation
High under the report's assumption of default settings: `allow_legacy_nonconformant_behavior` is `true` by default, so no explicit opt-in is required, unlike the rclone case which required a manual non-default FTP encoding. The only precondition is that the produced JSON message contains a `FieldMask` field and is serialized via the standard `PrintOptions` (or `PrintOptions()` default) using the C++ JSON writer.

## Recommendation
- Route `WriteFieldMask`'s fallback character writes through `JsonWriter::WriteEscapedUtf8`/`MustEscape` instead of calling `writer.Write(c)` directly, so quotes, backslashes, and control characters are always escaped regardless of `allow_legacy_nonconformant_behavior`.
- Treat `allow_legacy_nonconformant_behavior` as permission to accept nonconformant *characters* in a FieldMask path, not permission to skip escaping them on output.
- Add regression tests asserting that `FieldMask` paths containing `"`, `\`, `\n`, `\r`, and other control bytes are always escaped in ProtoJSON output, matching the upb encoders' behavior.

## Proof of Concept
Construct (via the binary wire format, a fully valid/bounded input) a message with a `google.protobuf.FieldMask` field whose `paths` entry is:
```
foo","injected":true,"bar":"x
```
Parse it with any standard binary parse API, then serialize with:
```cpp
google::protobuf::json::PrintOptions options;  // defaults: allow_legacy_nonconformant_behavior = true
std::string out;
google::protobuf::json::MessageToJsonString(msg, &out, options);
```
Tracing `WriteFieldMask` (`unparser.cc:743-762`): the space, `"`, `,`, `:` characters are not lowercase/digit/`.`/`_`, so with the default option they hit the `else` branch and are written via `writer.Write(c)` with no escaping, producing output where the literal `"` prematurely closes the FieldMask JSON string and the following `,"injected":true,"bar":"x` is emitted as raw, syntactically-live JSON content rather than an escaped string body—confirmed by reading `unparser.cc:753-759` and `writer.h:100-102` together; no code path re-escapes these bytes before they reach the sink.
