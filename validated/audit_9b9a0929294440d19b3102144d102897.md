### Title
Missing signature domain separation in `addr` precompile `associate()` allows replay of any secp256k1 signature to hijack address linkage and drain funds - (File: precompiles/addr/addr.go)

### Summary
The `associate` method of the `addr` precompile (address `0x1004`) recovers a pubkey from an attacker-supplied `(v, r, s, customMessage)` tuple and permanently binds the resulting EVM address to a Sei address, then migrates all balances from the EVM-derived account to the Sei account. Because `customMessage` is an arbitrary, unconstrained string chosen entirely by whoever calls the precompile, and the contract only hashes it with plain `keccak256` (no fixed prefix, no chain ID, no purpose tag, no nonce enforced on-chain), this mirrors the reported bug class: a signing/verification primitive that fails to bind a signature to its intended purpose, so a signature produced for one purpose can be reused/forged for a completely different, privileged action.

### Finding Description
`PrecompileExecutor.associate` in [1](#0-0)  takes `v`, `r`, `s`, and `customMessage` directly from EVM calldata, hashes `customMessage` with `crypto.Keccak256Hash` and recovers the signer via `helpers.GetAddresses` (`RecoverPubkey`/`Ecrecover`), as seen in [2](#0-1) . The client-side test harness wraps the message in an EIP-191 envelope before signing, e.g. `eip191Envelope` in [3](#0-2) , but this is purely a client-side convention — the on-chain precompile does not enforce any EIP-191 prefix, any domain separator, any chain ID, or any Sei-specific "intent" string. It signs (and thus authorizes) an association for *whatever bytes happen to hash to `customMessage`*.

This is directly analogous to the reported `signAppData` flaw: there, a signing endpoint validated only the presence of specific required fields (`nominator`, `nominee`, `stake`, `certExp`) but not the absence of unexpected ones, so a signature obtained for a legitimate purpose (`sign-stake-cert`) could be reused to authorize an entirely different, high-privilege action (`ApplyChangeConfig`) once extra fields were smuggled into the same signed object. Here, the precompile accepts *any* string as the signed payload with no restriction distinguishing "I intend to associate my EVM/Sei address" from any other message a user might sign (a permit, a login challenge, a message for an unrelated dApp, etc.), and no on-chain binding to the specific association action.

Once addresses are associated, `associateAddresses` -> `AssociationHelper.AssociateAddresses` -> `MigrateBalance` in [4](#0-3)  automatically:
- Sets a permanent Sei<->EVM address mapping via `SetAddressMapping`.
- Sets the account pubkey if none exists.
- Sweeps all spendable coins and wei balance from the EVM-derived cast account to the Sei account, and removes the empty cast account.

Since anyone who obtains a valid secp256k1 signature and the corresponding message from a victim (through any channel where the victim signs *something* with their EVM key over data whose keccak256 hash the attacker can present as `customMessage`) can submit it to `associate`, this can be leveraged to force an unwanted, irreversible address linkage and balance migration for the victim, provided the victim has not already associated (the code checks `_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr); if found { return error }` in [5](#0-4)  but only checks the *Sei* address side, not whether the *EVM* address is already associated elsewhere, meaning a victim's freshly-used-but-not-yet-associated EVM address is a valid target).

### Impact Explanation
If exploitable, this could result in unauthorized creation of an EVM<->Sei address association and an involuntary transfer ("MigrateBalance") of a victim's `usei`/wei balance to an address chosen by the attacker (the Sei address the attacker controls the private key/signature material for, paired arbitrarily with the victim's EVM-derived cast account), i.e., a direct loss-of-funds vector reachable purely through a public EVM RPC transaction to the `0x1004` precompile — no validator or node privileges required, satisfying the "unprivileged transaction sender" reachability requirement.

### Likelihood Explanation
Exploitability hinges on an attacker's ability to obtain (from some non-Sei channel or reused signing flow) a signature `(v, r, s)` and the exact `customMessage` bytes the victim signed, since `associate` will accept *any* string as long as the ECDSA recovery succeeds — there is no restriction tying the signed data to an "I want to associate" intent, no chain ID, and no domain separator enforced on-chain. This is a plausible but not proven-in-repo scenario (it would typically require signature reuse across contexts, e.g. via a malicious dApp tricking a user into `personal_sign`-ing an attacker-chosen payload, or reuse of a signature originally produced for another cross-chain/off-chain purpose). This is analogous to the reported bug's requirement of controlling at least one legitimately-signed payload with attacker-injected extra semantics, but here I could not find in-repo evidence of an existing legitimate flow that produces exactly the signature/message pair an attacker could intercept and replay against `associate` — this needs runtime verification beyond static code review.

### Recommendation
Bind the signed payload in `associate` to an explicit, Sei-specific, non-reusable domain: enforce an EIP-191 (or EIP-712) prefix/typed-data envelope on-chain rather than trusting the client, include the target Sei chain ID and the precompile address, and reject association if `customMessage` does not match a fixed, canonical "associate" template. Additionally, check both directions of association (reject if the EVM address is already associated to a different Sei address, not just the Sei-address side), and consider adding a nonce/expiry to prevent stale-signature replay.

### Proof of Concept
Not independently reproduced; conceptually, an attacker would need to obtain a `(v, r, s, customMessage)` tuple signed by a victim's EVM key where `customMessage`'s content was never intended for Sei's `associate` precompile (e.g. reused from a `personal_sign` interaction on an unrelated site), then submit it via a normal EVM transaction to `0x1004`'s `associate` method to force an association and balance migration on the victim's behalf. I was unable to find or execute a working PoC in this codebase; this analysis is based on static review of [6](#0-5)  and [4](#0-3) , and would require a background Devin session with terminal/browser access to confirm exploitability end-to-end.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func GetAddresses(V *big.Int, R *big.Int, S *big.Int, data common.Hash) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	pubkey, err := RecoverPubkey(data, R, S, V, true)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}

	return GetAddressesFromPubkeyBytes(pubkey)
}

func GetAddressesFromPubkeyBytes(pubkey []byte) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	evmAddr, err := PubkeyToEVMAddress(pubkey)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}
	seiPubkey := PubkeyBytesToSeiPubKey(pubkey)
	seiAddr := sdk.AccAddress(seiPubkey.Address())
	return evmAddr, seiAddr, &seiPubkey, nil
}

func RecoverPubkey(sighash common.Hash, R, S, Vb *big.Int, homestead bool) ([]byte, error) {
	if Vb.BitLen() > 8 {
		return []byte{}, ethtypes.ErrInvalidSig
	}
	V := byte(Vb.Uint64() - 27)
	if !crypto.ValidateSignatureValues(V, R, S, homestead) {
		return []byte{}, ethtypes.ErrInvalidSig
	}
	// encode the signature in uncompressed format
	r, s := R.Bytes(), S.Bytes()
	sig := make([]byte, crypto.SignatureLength)
	copy(sig[32-len(r):32], r)
	copy(sig[64-len(s):64], s)
	sig[64] = V

	// recover the public key from the signature
	return crypto.Ecrecover(sighash[:], sig)
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
