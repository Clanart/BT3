### Title
Unguarded IPC handlers bypass the `isTrustedIPCSender` check, allowing arbitrary file trash/open actions from a renderer-controlled context - (File: `app/src/main-process/main.ts`)

### Summary
GitHub Desktop implements a "trusted sender" guard for IPC messages, analogous in purpose to the missing `onlyGelatoRelay` modifier in the report: a wrapper (`safeListener` in `app/src/main-process/ipc-main.ts`) validates `isTrustedIPCSender(event.sender)` before invoking a channel handler [1](#0-0) . However, this guard is only applied to handlers registered through the wrapped `on`/`handle` exports of that module. The bulk of the application's IPC surface, including filesystem-affecting channels, is instead registered directly against Electron's raw `ipcMain` inside `app/src/main-process/main.ts`, completely bypassing the trusted-sender check, exactly like the "ForUser" methods in the report that used `_msgSender()` without the corresponding access-control modifier.

### Finding Description
`app/src/main-process/trusted-ipc-sender.ts` defines `isTrustedIPCSender`, intended to ensure "only IPC messages sent from trusted senders are handled" [2](#0-1) . This check is wired into `ipc-main.ts`'s `on`/`handle`/`once` wrappers [3](#0-2) , and `AppWindow`'s constructor registers the main window's `webContents` as trusted via `addTrustedIPCSender` [4](#0-3) .

`app/src/main-process/main.ts`, however, sets up dozens of channels directly on Electron's `ipcMain` (not the wrapped module), so `isTrustedIPCSender` is never consulted for them, for example:

```
ipcMain.handle('move-to-trash', (_, path) => shell.trashItem(path))
ipcMain.handle('show-item-in-folder', async (_, path) => shell.showItemInFolder(path))
ipcMain.on('unsafe-open-directory', async (_, path) => UNSAFE_openDirectory(path))
``` [5](#0-4) 

These handlers accept a caller-supplied `path` with no validation that it lies inside the currently open repository, and no verification of the calling `webContents`. `app-window.ts` additionally creates the `BrowserWindow` with `nodeIntegration: true` and `contextIsolation: false` [6](#0-5) , meaning any script execution achieved inside the renderer (e.g., through content rendered from repository data, diffs, or markdown that is not perfectly sanitized) has direct access to `require('electron').ipcRenderer` and can invoke these unguarded channels with attacker-chosen arguments — the same class of gap as calling the `ForUser` functions directly and supplying an arbitrary `_msgSender()`-equivalent value, because the intended authorization boundary (`isTrustedIPCSender`) simply isn't present on the path.

### Impact Explanation
If a renderer-side script executes with attacker influence, it can call `move-to-trash` or `unsafe-open-directory` with arbitrary filesystem paths, causing file deletion/movement or unintended directory traversal outside the user's repository — file write/read outside the repo scope, matching the accepted impact category. This defeats the security purpose of `isTrustedIPCSender`, which exists specifically to prevent exactly this class of untrusted-origin IPC abuse, per the Electron security guidance referenced in the code itself [7](#0-6) .

### Likelihood Explanation
Exploitation requires an initial script-execution primitive inside the renderer (e.g., via a crafted repository's rendered content triggering a script injection), which is consistent with the "attacker controls a cloned/fetched repository" valid-impact category. Given `nodeIntegration`/`contextIsolation` settings expose the full IPC API to any renderer content, and a large fraction of channels in `main.ts` are registered without the trusted-sender check, the attack surface is broad and the guard that should stop it is simply absent for these channels — not merely weak.

### Recommendation
Route all IPC registrations in `app/src/main-process/main.ts` (and other main-process files) through the wrapped `on`/`handle` functions exported from `app/src/main-process/ipc-main.ts` so that every channel is subject to `isTrustedIPCSender` validation, consistent with how `execute-menu-item-by-id`-style trusted flows are expected to work. Additionally, validate that any path-accepting handlers (`move-to-trash`, `show-item-in-folder`, `unsafe-open-directory`) constrain the target path to an expected scope.

### Proof of Concept
1. Achieve script execution in the renderer context (e.g., via a rendering path that fails to sanitize attacker-controlled repository content, feasible since `contextIsolation: false` and `nodeIntegration: true` are set in `app/src/main-process/app-window.ts`).
2. From that script, call:
```js
require('electron').ipcRenderer.invoke('move-to-trash', '/absolute/path/outside/repo')
```
3. Because `main.ts` registers `'move-to-trash'` directly on `ipcMain` rather than through the trusted-sender-checked wrapper, the call succeeds regardless of the sender's trust status, moving/deleting an arbitrary file on the user's system.

function safeListener<E extends IpcMainEvent | IpcMainInvokeEvent, R>(
  listener: (event: E, ...a: any) => R
) {
  return (event: E, ...args: any) => {
    if (!isTrustedIPCSender(event.sender)) {
      log.error(
        `IPC message received from invalid sender: ${event.senderFrame?.url}`
      )
      return
    }

    return listener(event, ...args)
  }
}

**File:** app/src/main-process/trusted-ipc-sender.ts (L1-16)
```typescript
import { WebContents } from 'electron'

// WebContents id of trusted senders of IPC messages. This is used to verify
// that only IPC messages sent from trusted senders are handled, as recommended
// by the Electron security documentation:
// https://github.com/electron/electron/blob/main/docs/tutorial/security.md#17-validate-the-sender-of-all-ipc-messages
const trustedSenders = new Set<number>()

/** Adds a WebContents instance to the set of trusted IPC senders. */
export const addTrustedIPCSender = (wc: WebContents) => {
  trustedSenders.add(wc.id)
  wc.on('destroyed', () => trustedSenders.delete(wc.id))
}

/** Returns true if the given WebContents is a trusted sender of IPC messages. */
export const isTrustedIPCSender = (wc: WebContents) => trustedSenders.has(wc.id)
```
