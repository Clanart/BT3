## Analysis

The Adena report's underlying broken invariant is: **a listener that receives input from an unauthenticated/untrusted external source processes that input as if it were trusted, without checking its origin/scheme.** In GitHub Desktop, the closest verified analog to this pattern is the handling of `x-github-client://openRepo/...` deep links.

### Title
Deep-link `open-repository-from-url` action forwards an unvalidated, attacker-controlled remote URL into the clone flow with no scheme/format check - (File: `app/src/lib/parse-app-url.ts`)

### Summary
Desktop registers itself as the handler for the `x-github-client://` (and `github-mac://`) custom protocol, so any web page or link the user clicks can trigger `app.on('open-url', ...)` in the main process, which calls `handleAppURL` → `parseAppURL(url)`. [1](#0-0)  The parser only validates the `hostname` (`oauth` vs `openrepo`), the `pr` format, and the `branch` format via `testForInvalidChars`; the actual remote `url` value embedded in the deep link's path is passed through completely unchecked — no scheme allow-list, no rejection of leading dashes, no validation against dangerous git transport syntax (e.g. `ext::`, `fd::`, or option-injection strings starting with `-`). [2](#0-1) 

### Finding Description
`parseAppURL` extracts `parsedPath` (the raw string after `openrepo/`) and returns it verbatim as `IOpenRepositoryFromURLAction.url` with only `pr` and `branch` sanitized. [3](#0-2)  This action flows to `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository(url)`, which — if no existing repository matches — pre-populates the Clone dialog with `initialURL: url` and shows it to the user. [4](#0-3) [5](#0-4)  When the user confirms the (already-filled) clone action, `Dispatcher.clone` calls `AppStore._clone(url, path, options)`, which hands the raw `url` directly to `cloningRepositoriesStore.clone(url, path, options)` for execution. [6](#0-5) 

The only sanitization present anywhere in this chain applies to `branch` (`testForInvalidChars`) and `filepath` (absolute-path rejection plus `resolveWithin` containment check in `openRepositoryFromUrl`) — the corrupted value that reaches the git-clone execution path, `url`, has no equivalent guard. [7](#0-6) 

This mirrors the report's bug class exactly: a message/event that originates from an arbitrary, unauthenticated source (any webpage capable of navigating to `x-github-client://openRepo/...`) is trusted and acted upon by a privileged listener (the app's protocol handler) without validating the content's origin or shape before it is used in a sensitive operation (invoking `git clone` with the raw string).

### Impact Explanation
If the underlying git invocation does not itself neutralize a leading `-` or the `ext::`/`fd::` transport helpers in the URL string (a well-known git argument-injection class, cf. CVE-2017-1000117), an attacker who gets a victim to click a crafted `x-github-client://openRepo/<malicious-url>` link could achieve arbitrary command execution on the victim's machine when the clone is triggered — this is impact well above simple "unauthorized action/event spoofing" since it operates over an OS-level custom-protocol boundary rather than a webpage `postMessage` boundary. Even absent full command execution, lack of scheme/format validation lets an attacker fully control which remote server Desktop will silently offer to clone/push to, undermining the integrity of what the user believes they are opening.

### Likelihood Explanation
Medium: exploitation requires the user to click an attacker-supplied `x-github-client://` link and then confirm the pre-filled Clone dialog — a two-step but entirely natural flow for this app feature (this is the exact intended "Open in Desktop" UX, so it is not an "unnatural" step). The scheme is registered as the default handler on the OS for all sites, matching the report's "any origin" pattern (`<all_urls>` in the extension analog). I was not able to inspect the exact git invocation inside `cloningRepositoriesStore.clone` in this session to confirm whether dugite/git itself blocks a leading `-` or `ext::` in the URL argument before this analog can be treated as a proven RCE — this is the one open verification gap.

### Recommendation
In `parseAppURL` (or immediately before `openOrCloneRepository`/`_clone` consumes `action.url`), validate the `url` against an allow-list of expected clone URL forms (`https://`, `ssh://`, `git://`, or `user@host:path` SCP-like syntax) and explicitly reject values starting with `-` or containing `ext::`/`fd::` transport prefixes, mirroring the existing `testForInvalidChars` guard already applied to `branch`.

### Proof of Concept
1. Host a link: `x-github-client://openRepo/ext::sh -c "touch /tmp/pwned"`.
2. Victim (with Desktop installed and registered as the protocol handler) clicks the link from any webpage or email client.
3. `main.ts`'s `open-url` handler fires → `handleAppURL` → `parseAppURL` returns `{ name: 'open-repository-from-url', url: 'ext::sh -c "touch /tmp/pwned"', branch: null, pr: null, filepath: null }` unchanged. [8](#0-7) 
4. `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository` opens the Clone dialog pre-filled with this string as `initialURL`. [9](#0-8) 
5. User clicks "Clone" (a natural next step believing they're cloning a normal repo) → `Dispatcher.clone` → `AppStore._clone` → `cloningRepositoriesStore.clone(url, path, options)` executes with the unsanitized string. [10](#0-9) 

Note: step 5's ultimate command-execution outcome depends on internals of `cloningRepositoriesStore`/dugite's git invocation, which I could not fully trace in this session — flagging this as the residual uncertainty in an otherwise locally-verified, unvalidated-untrusted-input chain.

```typescript
export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }
```

```typescript
  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
```

```typescript
  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
```

```typescript
  /** This shouldn't be called directly. See `Dispatcher`. */
  public _clone(
    url: string,
    path: string,
    options: { branch?: string; defaultBranch?: string } = {}
  ): {
    promise: Promise<boolean>
    repository: CloningRepository
  } {
    const promise = this.cloningRepositoriesStore.clone(url, path, options)
    const repository = this.cloningRepositoriesStore.repositories.find(
      r => r.url === url && r.path === path
    )!

    promise.then(success => {
      if (success) {
        this.statsStore.recordCloneRepository()
      }
    })

    return { promise, repository }
  }
```
