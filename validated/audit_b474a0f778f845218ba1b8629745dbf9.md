### Title
Unauthenticated OP_RETURN operator attribution in payout transactions lets an attacker frame any honest operator into self-crediting a reimbursement it never funded - (File: `core/src/verifier.rs`, `core/src/task/payout_checker.rs`)

### Summary
`Verifier::update_finalized_payouts` attributes `payout_payer_operator_xonly_pk` for a withdrawal purely from the OP_RETURN payload of whichever Bitcoin transaction happens to spend the tracked withdrawal UTXO, with no cryptographic proof that the named operator authored, signed, or funded that transaction. An attacker who controls the withdrawal UTXO's private key can self-spend it directly on Bitcoin, embed any honest operator's public xonly key in the OP_RETURN, and pay nothing meaningful to the withdrawer; that operator's own `PayoutCheckerTask` will then automatically pick this up and drive it through kickoff to `Reimburse`.

### Finding Description
Binding claimed: `payout_payer_operator_xonly_pk` (DB attribution) == the operator whose own signing key/funds actually produced and broadcast the payout transaction. This binding is **not enforced**.

Path:
1. Attacker calls `withdraw()` on the Citrea bridge contract choosing arbitrary `withdrawal_utxo` bytes (`core/src/test/withdraw.rs:133-138`, `core/src/citrea.rs:458-496`). If they choose a UTXO whose scriptPubkey key they control, they can spend it with any signature/sighash they like — the protocol never requires this UTXO to be spent through the operator's `create_payout_txhandler` flow (`core/src/builder/transaction/operator_reimburse.rs:407-436`); it merely requires the correct outpoint to be spent, checked later by `verify_storage_proofs`/`bridge_circuit` (`circuits-lib/src/bridge_circuit/mod.rs:182-204`, `circuits-lib/src/bridge_circuit/storage_proof.rs:44-133`).
2. Attacker crafts and broadcasts their own transaction spending this UTXO with a self-chosen output (paying themselves, or paying the withdrawer nothing) and a first OP_RETURN output containing the target honest operator's public, well-known x-only pubkey (`op_return_txout`/`parse_op_return_data` format, `circuits-lib/src/bridge_circuit/mod.rs:608-617`).
3. Once finalized, `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) finds this tx via `get_payout_txs_for_withdrawal_utxos` (join on `withdrawal_utxo_txid`/`vout`, `core/src/database/verifier.rs:170-196`), extracts the OP_RETURN via `get_first_op_return_output`/`parse_op_return_data`, and blindly writes it as `payout_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`) — with **no signature check, no output-amount check, no check that the named operator ever called `withdraw`/`internal_withdraw`**.
4. The framed operator's own `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-111`) queries `get_first_unhandled_payout_by_operator_xonly_pk` using its own key (`core/src/database/verifier.rs:282-313`), matches the forged row, and calls `Operator::handle_finalized_payout` (`core/src/operator.rs:839-885`), which creates and queues a `Kickoff` transaction using the operator's own signer/collateral.
5. `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1857-1915`) is the only gate that could stop this. It only checks that `operator_xonly_pk` (attacker-controlled OP_RETURN value) equals `kickoff_data.operator_xonly_pk`, and that the committed blockhash matches the actual (real, finalized) block containing the attacker's self-spend. Both trivially hold, since the attacker copied the real operator's public key and the tx is genuinely finalized — so the kickoff is judged non-malicious and unchallenged.
6. The kickoff proceeds through the presigned graph to `Reimburse` (`core/src/builder/transaction/operator_reimburse.rs:318-385`), paying the move-to-vault deposit value to the framed operator's reimbursement address.

Root cause: attribution of "who paid the withdrawal" is derived solely from unauthenticated OP_RETURN bytes chosen by whoever spends the withdrawal UTXO, with no proof of operator authorship (no operator signature on the payout tx at all — the payout tx uses only the withdrawer's own key-path signature) and no verification that the payout's actual output paid the amount/script the withdrawal committed to on the Citrea side.

### Impact Explanation
This breaks the "operator credited/reimbursed == operator who actually funded the payout" invariant. BTC/collateral value (`bridge_amount`, e.g. 10 BTC per deposit) leaves the move-to-vault UTXO and is paid out via `Reimburse` to an operator who never fronted the withdrawal — matching both Critical categories "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal" and "an operator reimbursed for a payout it never funded." The attack is repeatable for every withdrawal/deposit an attacker can register and self-spend, and can be aimed at any operator whose public xonly key is known (all operator keys are public protocol data). It also forces the targeted operator into an unwanted kickoff (fees, collateral round consumption) it did not initiate.

### Likelihood Explanation
Preconditions are minimal and match the stated attacker capabilities exactly: register/own a withdrawal UTXO, call `withdraw` on the Citrea bridge contract with a chosen outpoint, and broadcast a self-signed Bitcoin transaction with a crafted OP_RETURN. No verifier/operator/aggregator privilege, key share, or TLS access is needed. Cost is limited to the deposit's own bridge amount plus tx fees (funds the attacker already controls) and Bitcoin fees for the forged self-spend. This is deterministically reproducible in regtest and not dependent on hashrate, timing races, or mainnet conditions.

### Recommendation
Do not trust the OP_RETURN pubkey alone as proof of payer identity. Require the payout transaction to also carry a valid signature/commitment from the claimed operator's key (e.g., an operator-signed covenant/anchor input, or a required additional operator signature over the payout), and additionally verify in `update_finalized_payouts`/`is_kickoff_malicious`/the bridge circuit that the payout's non-OP_RETURN output actually pays the amount/script committed for that withdrawal on the Citrea contract side, before allowing that operator's kickoff to be treated as non-malicious/reimbursable.

```
#[tokio::test]
async fn attacker_frames_honest_operator_via_forged_op_return() {
    // 1. Set up regtest bridge with an honest operator O (never calls withdraw/internal_withdraw).

    // 3. Attacker builds and signs, with their own key, a self-spend transaction of that UTXO:

    //    Broadcast directly via rpc.send_raw_transaction (bypassing Operator::withdraw entirely).
    // 4. Mine to finality depth so Verifier::update_finalized_payouts processes the block.
    // 5. Assert: db.get_payout_info_from_move_txid(...).0 == Some(op0_xonly_pk)
    //    even though op0 never called withdraw/internal_withdraw.
    // 6. Run PayoutCheckerTask::run_once for operator O; assert it returns Ok(true)
    //    and db.get_handled_payout_kickoff_txid(...) becomes Some(kickoff_txid),
    //    proving O's automation claims the payout as its own.
    // 7. (Optional) continue through Verifier::is_kickoff_malicious with O's real kickoff witness
    //    and assert it returns false (not malicious), confirming the forged attribution
    //    survives the only guard and the kickoff would proceed unchallenged to Reimburse.
}
```
Binding assertions: BEFORE — `payout_payer_operator_xonly_pk` for this withdrawal is `NULL`/unset and operator O has no record of this withdrawal. AFTER — `payout_payer_operator_xonly_pk == op0_xonly_pk` and `is_payout_handled == true` for O, despite O never funding anything, demonstrating the broken binding.
