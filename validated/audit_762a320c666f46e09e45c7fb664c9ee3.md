### Title
Duplicate Schnorr aggregate entries allow one signature to satisfy multiple claims - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts duplicate `(public_key, challenge)` entries without checking that each represented signature or claim is unique. An attacker can aggregate the same valid Schnorr signature multiple times and produce an aggregate accepted for the same number of duplicate entries.

### Finding Description
`SchnorrAggregate::verify` checks only that the number of nonce commitments equals the number of `(key, challenge)` pairs, then derives each aggregation weight from the ordered challenge list and verifies the weighted equation. It does not reject duplicate pairs or otherwise require each pair to represent a distinct signature. [1](#0-0) 

`SchnorrAggregator::aggregate` similarly appends every supplied challenge and signature without a uniqueness check. [2](#0-1) 

Because the aggregation equation is linear, a signature satisfying `sG = R + cA` can be submitted `n` times under the same `(A, c)` pair. The resulting aggregate uses `Rs = [R, ..., R]` and `s = sum_i(z_i * s)`, which satisfies `sum_i(z_i * (R + cA)) = sG`.

### Impact Explanation
A verifier that treats each `(key, challenge)` entry as an independent approval can be presented with an aggregate proving only one actual signature while appearing to authorize multiple duplicate claims. This permits replay of a valid authorization within a single aggregate when the caller expects entry count to correspond to distinct signed operations.

### Likelihood Explanation
The attack requires only one valid signature and public knowledge of its `(public_key, challenge)` pair. No private key, malformed encoding, malicious signer, or protocol violation inside the primitive is required because both aggregation and verification expose duplicate inputs through their public APIs. [3](#0-2) 

### Recommendation
Reject duplicate `(public_key, challenge)` pairs in `SchnorrAggregate::verify` and reject aggregation of an already-used challenge/signature pair in `SchnorrAggregator::aggregate`. If duplicate challenges must be supported for distinct operations, require callers to include and consume a unique operation identifier inside each challenge.

### Proof of Concept
```rust
// A is the public key, c is the challenge, and sig is a valid Schnorr signature for (A, c).
let mut aggregator = SchnorrAggregator::<C>::new(DST);
aggregator.aggregate(c, sig);
aggregator.aggregate(c, sig);

let aggregate = aggregator.complete().unwrap();
let claims = vec![(A, c), (A, c)];

// This returns true despite only one distinct signature being supplied.
assert!(aggregate.verify(DST, &claims));
```

The verifier derives a fresh weight for each duplicate challenge and checks the sum equation, so the weighted copies of the same valid signature satisfy both entries. [4](#0-3)
