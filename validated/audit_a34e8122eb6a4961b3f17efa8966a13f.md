### Title
Out-of-bounds read in `is_atom_canonical()` due to missing length-prefix bounds validation on attacker-controlled spend bundle CLVM buffer - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` decodes CLVM atom length prefixes (1–6 byte variable-length encodings) by indexing directly into `clvm_buffer` at `offset` without ever checking that `offset` stays within the buffer bounds, analogous to the Wireshark DOF dissector bug (CVE-2017-9348) where a size value was used to read a buffer without validating it against the buffer's actual length.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` and then, based on the high bits of `b`, determines `prefix_len` (0–5 additional bytes) and loops `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` [1](#0-0) . There is no check anywhere in this function, or in its only caller `is_clvm_canonical()`, that `offset + prefix_len` stays within `len(clvm_buffer)` before indexing. `is_clvm_canonical()` walks the buffer token-by-token, calling `is_atom_canonical()` at each length-prefixed atom found while scanning attacker-controlled bytes [2](#0-1) . If a CLVM buffer ends with a truncated multi-byte atom length-prefix (e.g., the buffer ends right after a byte matching the 5-byte-prefix pattern `0b11111100`), the loop in `is_atom_canonical()` will index past the end of `clvm_buffer`, raising an unhandled `IndexError` instead of the `ValueError`/bounds-checked behavior used consistently elsewhere in the codebase for untrusted-buffer parsing (e.g., `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`, which explicitly check `n > len(buf)` before slicing [3](#0-2) , or `parse_bytes()` in `chia/util/streamable.py` which asserts the read length matches expectations [4](#0-3) ).

### Impact Explanation
Per project documentation, `is_clvm_canonical()` is used to determine DEDUP-eligibility for mempool spends (checking that a solution uses canonical/shortest-form CLVM atom encoding) [5](#0-4) . Because this function operates on the raw solution bytes taken from an incoming, attacker-submitted spend bundle before/alongside standard CLVM cost validation, a crafted solution buffer that is truncated immediately after a multi-byte atom-length-prefix marker byte can trigger an `IndexError` inside `is_atom_canonical()`. If this exception is not caught by the mempool manager's spend-bundle admission path, it can cause an unhandled exception during spend bundle processing — a transaction-processing halt/crash vector reachable by any unprivileged spend-bundle submitter, rather than a memory-disclosure bug (Python bounds-checks lists/bytes, so this manifests as an exception rather than true out-of-bounds memory access, unlike the C-based Wireshark dissector).

### Likelihood Explanation
I was unable to fully verify, within the available tool budget, whether the call site(s) that invoke `is_clvm_canonical()` (used for DEDUP eligibility checks) wrap this call in a try/except that would gracefully degrade to "not eligible for dedup" rather than propagate the exception up through spend bundle admission — the `_tests/core/mempool/test_mempool_manager.py` references to `is_clvm_canonical`/`is_atom_canonical` were found but not read in depth. This is a material uncertainty: if callers already catch broad exceptions around dedup-eligibility checks, the practical impact is limited to at most a per-item dedup-eligibility miscalculation rather than a mempool-manager crash.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing `clvm_buffer[offset]` inside the prefix-length loop (and before the initial `clvm_buffer[offset]` read in `is_clvm_canonical()`'s loop), raising a handled `ValueError` (consistent with the bounds-checking style already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`) when the remaining buffer is shorter than the required prefix length, and confirm the call site treats any such error as "not canonical"/"not dedup eligible" rather than letting it propagate.

### Proof of Concept
1. Construct a CLVM solution buffer that ends with a single byte matching the 5-byte length-prefix marker pattern, e.g. a buffer whose last byte is `0b11111101` (matches `(b & 0b11111110) == 0b11111100`), with no further bytes following it.
2. Submit a spend bundle whose coin spend solution serializes to this truncated buffer, routed through mempool admission such that `is_clvm_canonical()` is invoked on it for DEDUP-eligibility checking.
3. `is_atom_canonical()` will attempt to read `clvm_buffer[offset]` for `prefix_len = 5` additional bytes beyond the buffer's end, raising `IndexError: index out of range`.
4. Observe whether this exception propagates out of the mempool item processing path (unverified in this analysis) — if unhandled, it results in an exception during spend-bundle admission rather than a clean `MempoolInclusionStatus`/`Err` rejection.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
