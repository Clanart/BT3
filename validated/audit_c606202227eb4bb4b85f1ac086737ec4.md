### Title
Spoofed `WWW-Authenticate` realm header from a malicious git remote triggers Desktop's native "Sign in to GitHub Enterprise" flow, phishing GitHub credentials/tokens to an attacker-controlled host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`GenericOracle.getUSDPrice` in the seed report is broken because it consults a cheap, easily-outdated oracle (`_chainlinkOracle`) before consulting more authoritative sources, so the wrong price is always returned. The same "cheap and unreliable signal used first" pattern exists in GitHub Desktop's git-credential-helper endpoint classification: `getEndpointKind` trusts an attacker-supplied HTTP response header (`WWW-Authenticate: realm="GitHub"`) as ground truth for "is this a GitHub Enterprise server" *before* it does any real verification (matching a known account, or the actual network probe in `isGitHubHost`). A malicious git server can abuse this ordering to make Desktop treat an arbitrary host as a legitimate GitHub Enterprise endpoint and pop its own native sign-in UI pointed at that attacker host.

### Finding Description
When Git needs credentials for a remote, it invokes Desktop's trampoline credential helper (`createCredentialHelperTrampolineHandler` → `getCredential`) at [4](#0-3) . This calls `getEndpointKind(cred, store)` to decide whether the remote should be treated as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`.

Inside `getEndpointKind` at [5](#0-4) , before any real verification, the code iterates the credential map's `wwwauth[...]` entries — values that originate directly from the `WWW-Authenticate` HTTP response header sent by the remote git server (an attacker-controlled endpoint in the threat model, e.g. a malicious/compromised git host or a MITM proxy on an HTTP remote):

```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
```

This check runs *before* the only actual verification path available — `isGitHubHost(endpoint)` at [6](#0-5) , which makes a real HTTPS request and checks for the `x-github-request-id` response header. Because the header-based check is placed first and returns immediately, the network-verified check is never reached once an attacker supplies the magic string.

Once classified `'enterprise'`, back in `getCredential`, since no stored account matches the attacker's endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` at [7](#0-6) . This helper, shown at [8](#0-7) , starts the Enterprise sign-in flow using the raw attacker-controlled `endpoint`'s origin, and shows the native `SignIn` popup with `credentialHelperUrl` set to that URL — this is Desktop's own trusted-looking chrome, not a browser popup, making it far more convincing than a typical phishing page.

The user, having just run an ordinary `git fetch`/`clone`/`push` against what looks like an internal or third-party git server, is shown Desktop's native "Sign in to your GitHub Enterprise" dialog (`app/src/ui/welcome/sign-in-enterprise.tsx`, `app/src/ui/sign-in/sign-in.tsx`) prompting them to authenticate against that attacker-chosen origin. If they proceed (via the address-confirmation-free browser sign-in link, or Enterprise sign-in dialog), Desktop drives authentication (OAuth authorize request / device flow / basic auth, depending on GHE detection) against the attacker's origin, which can capture the resulting session state or any credentials entered, and/or bind an OAuth "GitHub" account object to the attacker's endpoint in Desktop's account store.

### Impact Explanation
This satisfies "unauthorized OAuth or account binding" and "credential/token exfiltration" from a purely attacker-controlled git remote/proxy response — no local access, admin rights, or prior malware needed. The `WWW-Authenticate` header is entirely attacker-controlled content returned in an HTTP response to a `git fetch`/`clone`/`push`, which is the normal, expected user action that triggers this code path.

### Likelihood Explanation
Any git server the user adds as a remote (self-hosted git server, artifact proxy, compromised third-party host, or a MITM on a plain `http://` remote) can return the crafted `WWW-Authenticate` header on a 401 response to trigger this classification, requiring no unusual user interaction beyond a normal fetch/clone/push against that remote.

### Recommendation
Reorder `getEndpointKind` so the untrusted `WWW-Authenticate` heuristic is either removed or only used as a last resort after the authoritative, network-verified `isGitHubHost` check (and existing-account match), mirroring the report's recommendation to "reprioritize" trusted sources ahead of unreliable ones. At minimum, do not let the header alone escalate an arbitrary host straight to a state that opens Desktop's native "Sign in to GitHub Enterprise" UI without an explicit, address-bar-visible confirmation of the exact host being authenticated against.

### Proof of Concept
1. Stand up a git-over-HTTP server (or MITM proxy) at `https://evil.example.com/repo.git`.
2. Configure it to respond to unauthenticated Git HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In Desktop, clone or fetch `https://evil.example.com/repo.git`.
4. Git captures the header and forwards it via `wwwauth[...]` to Desktop's credential helper; `getEndpointKind` ( [9](#0-8) ) returns `'enterprise'` for `evil.example.com`.
5. `getCredential` finds no matching account and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which opens Desktop's native "Sign in to your GitHub Enterprise" dialog targeting `evil.example.com`.
6. A user who proceeds with sign-in is authenticating against the attacker's origin inside Desktop's own trusted UI chrome.

  if (

      return undefined

    return undefined

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
