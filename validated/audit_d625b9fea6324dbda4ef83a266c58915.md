### Title
`smartConvert()`'s strict `_minRec = _amountIn` check can be forced to revert by AMM price/slippage manipulation, DoS-ing `deposit`, `depositLP`, `withdraw` and `harvest` - (File: wombat/SmartWomConvert.sol)

### Summary
`SmartWomConvert.smartConvert()` hard-codes `_minRec` to the full `_amountIn` regardless of which execution branch is taken, so any branch that routes some or all of the input through the `womMWomPool` AMM buyback leg can fail the `convertAmount + amountRec < _minRec` check whenever the swap returns less than 1:1 relative to the swapped-in amount. Because `smartConvert` is called synchronously from `WombatStaking._sendRewards`, which itself is invoked from `_toMasterWomAndSendReward` on every `deposit`, `depositLP`, `withdraw` and `harvest`, a revert here bubbles up and blocks all of those user-facing operations.

### Finding Description
In `smartConvert`, the buyback/convert split is decided by the live AMM price: [1](#0-0) 

- `currentRatio()` reads the instantaneous mWOM→WOM quote from `womMWomPool` via `IWombatRouter.getAmountOut`.
- If that quote is below `buybackThreshold` (default 9000/10000 = 0.9), the function computes `maxSwapAmount()` (derived from `IAsset(womAsset).cash()`/`liability()`) and routes `min(_amountIn, maxSwap)` through the AMM buyback leg. When `maxSwapAmount() >= _amountIn` (true for the typically small fee amounts routed here), `convertRatio` becomes `0`, meaning the entire `_amountIn` goes through the swap and `convertAmount` (the 1:1 `IMWom(mWom).deposit` leg) is `0`.
- `smartConvert` then calls `_convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode)` — note `_minRec` is fixed to the original `_amountIn`, not derived from any router quote or slippage tolerance.

In `_convertFor`: [2](#0-1) 

`amountRec` comes from `IWombatRouter.swapExactTokensForTokens(..., 0, ...)` (no router-level slippage protection either — `amountOutMin` is hardcoded `0`), and the outer check `convertAmount + amountRec < _minRec` reverts with `MinRecNotMatch` if the AMM leg does not return at least 1:1. Both `currentRatio()` and the actual execution price of `swapExactTokensForTokens` depend on the same manipulable `womMWomPool` cash/liability state (`IAsset(womAsset).cash()/liability()`), which any unprivileged actor can shift via ordinary swaps (or a flash loan) against the pool — no privileged role is required.

This function is not called by an EOA directly in the normal flow; it is invoked internally from `WombatStaking._sendRewards`: [3](#0-2) 

which is called unconditionally from `_toMasterWomAndSendReward`: [4](#0-3) 

and `_toMasterWomAndSendReward` is invoked from every principal-moving entrypoint: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

None of `nonReentrant`, `whenNotPaused`, or `_onlyActivePoolHelper`/`_onlyPoolHelper` protect against this: these modifiers gate *who* can call, not whether the internal fee-conversion swap succeeds. Once `smartWomConverter` is wired in (`WombatStaking.setSmartConvert`), any harvested WOM reward that is fee-routed to mWOM via `smartConvert` is subject to this all-or-nothing 1:1 check, and a revert there reverts the entire outer `deposit`/`depositLP`/`withdraw`/`harvest` transaction for any and all users, not just the harvester.

### Impact Explanation
An attacker who pushes `womMWomPool`'s cash/liability ratio so that (a) `currentRatio()` drops below `buybackThreshold`, forcing the full-buyback (`convertRatio = 0`) branch, and (b) the actual `swapExactTokensForTokens` execution price/slippage for the (now oversized relative to available liquidity/impact) swap returns strictly less than `_amountIn`, will cause `MinRecNotMatch` on every subsequent `deposit`, `depositLP`, `withdraw`, and `harvest` call that triggers a WOM→mWOM fee conversion. This freezes principal deposits and withdrawals for the whole pool for as long as the attacker (or organically volatile market conditions) keeps the pool in that state, or until an admin disables `smartWomConverter` / adjusts `ratio`/`buybackThreshold`. This matches "Temporary freezing of funds for at least 24 hours."

### Likelihood Explanation
- No privileged role is needed; `womMWomPool` is a normal AMM pool that any account can trade against.
- The attacker only needs enough capital (potentially via flash loan, since Wombat pools are asset-based and support large single-block swaps) to shift `cash`/`liability` such that `currentRatio() < buybackThreshold` and the buyback swap's realized output falls under 1:1.
- The condition is repeatable: the attacker can re-manipulate the pool each time it starts to normalize, sustaining the DoS indefinitely at some capital/opportunity cost.
- The bug is purely a logic/design flaw (hardcoded `_minRec = _amountIn` and `amountOutMin = 0` in the router call) independent of any admin misconfiguration, satisfying the "unprivileged" constraint.

### Recommendation
- Do not require 1:1 out on a market-priced AMM leg. Compute `_minRec` from a router quote (`getAmountOut`) with an explicit slippage tolerance, rather than assuming the buyback must return at least the input amount.
- Alternatively, decouple the internal fee-conversion call in `_sendRewards` from the outer deposit/withdraw/harvest transaction (e.g., wrap the `smartConvert` call in a try/catch and fall back to a direct `IMWom(mWom).deposit` or skip the conversion on failure) so a manipulable AMM buyback cannot block principal-affecting operations.
- Add real slippage protection to the `swapExactTokensForTokens` call inside `_convertFor` instead of passing `0`.

### Proof of Concept
Hardhat/Foundry fork test plan:
1. Fork BSC/Arbitrum state with `WombatStaking`, `SmartWomConvert` (with `smartWomConverter` set), `womMWomPool`, and an active pool registered.

Attacker account: flash-loan or hold enough WOM/mWOM to swap in `womMWomPool` such that `IAsset(womAsset).cash() < liability()` sufficiently to drive `SmartWomConvert.currentRatio() < buybackThreshold` and to leave the pool state such that a subsequent swap of the expected harvested-fee-sized WOM amount returns `< amountIn` mWOM.
3. Victim account: call `WombatStakingPoolHelper.deposit(...)` (or `withdraw`) on an active pool that has accrued WOM rewards subject to the mWOM fee conversion.

5. Assert: the victim's claimable/receipt-token balance is unchanged (transaction reverted), confirming funds are frozen; repeat over multiple blocks to demonstrate persistence beyond 24 hours as long as the attacker maintains the pool imbalance.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
