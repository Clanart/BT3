### Title
Deterministic CachedPreprocess reuse across signing attempts enables secret share recovery via nonce reuse - (File: crypto/frost/src/sign.rs)

### Summary
The external report describes a throttle counter scoped to a resettable session, giving an attacker unbounded guesses. The Serai analog lives in `crypto/frost`: a sign machine rebuilt `from_cache` deterministically regenerates the *same* nonces from the same 32-byte seed, and `sign` carries no attempt binding or seed ratchet. An unprivileged co-signer who can trigger repeated signing attempts (submitting fresh preprocess bytes and/or a different message each time, via `read_preprocess`/`sign`) obtains multiple signature shares computed over the *identical* nonce pair `(d, e)`. Each share is a linear equation in the three unknowns `(d, e, x)` where `x` is the honest party's secret share; three attempts suffice to solve for `x`.

### Finding Description
`AlgorithmMachine::seeded_preprocess` derives all nonces from `ChaCha20Rng::from_seed(*seed.0)` — a pure function of the `CachedPreprocess` seed only, with no contribution from the attempt, message, or peer set (crypto/frost/src/sign.rs:121-144). `SignMachine::from_cache` reconstructs a fully usable `AlgorithmSignMachine` from the same seed (sign.rs:268-274), so every retry produces identical `self.nonces`. In `sign`, the local nonce is folded into the share as `actual = base + rho_i * actual_i` (sign.rs:386-396) and `sign_share` emits `s = nonce + lambda_i * c * x`. The binding factors `rho` are recomputed per attempt from the attacker-influenced preprocess transcript (`BindingFactor::calculate_binding_factors`, crypto/frost/src/nonce.rs:161-173, fed by `sign` lines 361-371 which hash `msg` and all peer preprocesses), and the challenge `c` varies with the message and nonce sums. Therefore each reattempt yields `s_k = d + rho_k*e + lambda*c_k*x` with known `rho_k`, `c_k`, `lambda` — one fresh linear equation per attempt against fixed unknowns `(d, e, x)`. Nothing in `sign` or `from_cache` prevents or detects reuse of a seed across distinct messages/preprocess sets; the only protection is a doc-comment "MUST only be used once" (sign.rs:85-87, 211-219), which the natural retry-oriented consumer pattern (cache preprocess per context, re-derive machine per attempt) violates silently.

### Impact Explanation
Recovery of an honest participant's FROST secret share `x` (and their raw nonces `d`, `e`). Combined with `t-1` other shares — or used to eject/blame-frame honest participants — this leads to forgery of threshold signatures over arbitrary messages. The attacker needs only the ability to cause repeated `sign` invocations over attacker-selected preprocesses/messages while the victim's seed stays fixed, which is precisely the "reset the session, retry unbounded" shape of the phpMyFAQ bug: the safety-critical state (nonce freshness) is scoped to the seed/context, not to the attempt, so retries reset the counter that was never incremented.

### Likelihood Explanation
A co-signing participant is unprivileged and fully controls their own preprocess bytes (`Commitments::read`/`read_preprocess`) and typically influences `msg`. Each failed or restarted attempt gives them another equation at no cost. Deterministic seeds (the documented caching API) make nonce reuse guaranteed rather than probabilistic — no race or ROS-style parallelism is needed, just sequential retries. The system is solvable with as few as 3 distinct attempts.

### Recommendation
Ratchet the seed on every `sign` invocation (e.g., `seed = H(seed || transcript_hash)` before nonce generation, and return/store the evolved seed), or bind the attempt counter/message into `seeded_preprocess` nonce derivation so nonces are provably unique per `(seed, msg, preprocess set)`. Alternatively, make `from_cache` consume-and-invalidate semantics enforceable — e.g., cache the *nonce commitments* rather than the entropy seed, so re-attempts reuse the same committed preprocess (making reused nonces harmless because rho binds to the identical commitment set and a divergent msg still produces shares under unrelated challenges — the preferred fix is seed ratcheting).

### Proof of Concept
```rust
// crypto/frost sign flow, attacker = participant l_a, victim = participant i
// Attempt k (k = 1,2,3): attacker supplies preprocess bytes P_k and message m_k.
let (machine, _) = AlgorithmSignMachine::from_cache(alg.clone(), keys.clone(), seed.clone());
// seeded_preprocess: nonces = f(seed) only -> identical (d, e) every call (sign.rs:127-132)
let (_, share_k) = machine.sign(preprocesses_k, m_k).unwrap();
// share_k = (d + rho_k * e) + lambda_i * c_k * x   (sign.rs:386-398)
// rho_k, c_k, lambda_i are public/recomputable by the attacker (nonce.rs:161-191).
// Collect s_1, s_2, s_3 and solve the 3x3 linear system for (d, e, x):
//   [1  rho_1  lambda*c_1] [d]   [s_1]
//   [1  rho_2  lambda*c_2] [e] = [s_2]
//   [1  rho_3  lambda*c_3] [x]   [s_3]
// Generically invertible -> x (victim secret share) recovered.
```
Root cause: nonce derivation in `seeded_preprocess` ignores attempt/message context (crypto/frost/src/sign.rs:127-132) and `from_cache` permits unrestricted regeneration (sign.rs:268-274), so retry attempts — reachable via attacker-controlled `read_preprocess` bytes and `sign` messages — deterministically reuse the same nonce, mirroring the session-scoped counter reset that enabled unbounded guessing.
