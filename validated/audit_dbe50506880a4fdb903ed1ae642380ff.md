### Title
`associatePubKey` allows forced, signature-less account association using any observed public key - ([File: precompiles/addr/addr.go])

### Summary
The Grafana OAuth report describes an account-takeover bug class where an identity link (OAuth login → local account) is established without verifying that the requester actually controls the identity being bound. The sei-chain analog is the `addr` precompile's `associatePubKey` method, which binds a Sei address and an EVM address together purely from a supplied secp256k1 public key, with no signature/challenge proving the caller controls the corresponding private key.

### Finding Description
`AssociatePubKey` (precompile address `0x1004`) takes a raw compressed public key and derives both the EVM address and the Sei address directly from it, then calls `associateAddresses`, which persists the mapping and migrates balances: [1](#0-0) 

Compare this to `associate`, which requires an ECDSA signature (`v, r, s`) over a message, cryptographically proving possession of the private key before the address derivation is trusted: [2](#0-1) 

`associatePubKey` has no equivalent proof-of-possession step — a public key is, by definition, public (recoverable from any prior ECDSA signature made by the target, e.g. any Ethereum tx, any Cosmos tx, or any signed message that ever touched the network). Any unprivileged caller can supply someone else's public key and force the association to execute on their behalf: [3](#0-2) 

Once triggered, `AssociateAddresses` performs privileged side effects without the target's consent or transaction: it can silently reuse/replace an existing "direct-cast" account at `sdk.AccAddress(evmAddr[:])` and migrate its spendable balance and wei balance to the derived Sei address: [4](#0-3) [5](#0-4) 

The ante-handler code explicitly documents that this same "direct-cast mapping can later be remapped by an `associatePubKey` call," and that doing so can orphan staking/distribution state tied to the direct-cast identity, which "can then halt the chain via the distribution validator-removal hook." A targeted fix was added only for EIP-7702 authorization authorities immediately before EVM execution: [6](#0-5) 

That comment confirms the underlying bug class (unauthenticated re-association of a direct-cast identity) is a real, previously-identified hazard in this codebase, but the mitigation is scoped narrowly to the EIP-7702 authority path executed in the same ante decorator. `associatePubKey` remains reachable by any address, at any time, for any public key, independent of that specific EIP-7702 flow, and is not guarded by the same authority-specific pre-association logic.

### Impact Explanation
- **Unauthorized state mutation / forced fund migration**: An attacker who has observed a victim's public key (trivially obtainable from any ECDSA signature the victim has ever produced) can force-create the Sei↔EVM association for the victim without their consent, at a time of the attacker's choosing, migrating any balance sitting at the victim's "direct-cast" account address into the newly-associated Sei address and reassigning account number/sequence state (`utils/helpers/associate.go` `AssociateAddresses`/`MigrateBalance`).
- **Validator/distribution state orphaning → chain halt risk**: Per the codebase's own documented concern in `x/evm/ante/preprocess.go`, this "remap" pattern applied to an address holding validator/staking or distribution state can orphan that state and trigger the distribution validator-removal hook, which the comment states "can halt the chain." Because `associatePubKey` performs an unauthenticated remap outside the EIP-7702-specific guard, this risk is not fully closed for other addresses that separately accumulate a direct-cast identity with staking/distribution state before ever calling `associate`/`associatePubKey` themselves.
- Severity aligns with High: no fund theft to the attacker directly, but forced, non-consensual account/state mutation and potential validator-halt conditions triggered purely by public data (public key) satisfy the "unauthorized transfer/permanent freezing/validator halt" bar in scope.

### Likelihood Explanation
Public keys are exposed by any prior signature (transactions, message signing, `associate` calls by other users, EIP-7702 authorizations, tendermint validator pubkeys, etc.), so harvesting a target's pubkey requires no special access. Calling `associatePubKey` costs only the flat 50000 gas required by the precompile (`RequiredGas`), making it trivially reachable by any unprivileged EVM caller. The precompile has been in the ABI across many legacy versions (`v600` through current), all sharing the same unauthenticated derive-and-associate pattern.

### Recommendation
Require the caller to prove possession of the private key for `associatePubKey`, mirroring `associate`'s signature-based flow (e.g., require a signed challenge recoverable to the supplied public key, or drop `associatePubKey` in favor of signature-based association only). Additionally, extend the guard currently applied only to EIP-7702 authorities (`associateAuthorizationAuthorities` in `x/evm/ante/preprocess.go`) to cover any address that may hold a "direct-cast" identity with staking/distribution state before allowing `associatePubKey`/`associate` to remap it, or block re-association entirely once staking/distribution state exists at the direct-cast address.

### Proof of Concept
1. Observe any transaction or signed message from victim `V` (Sei or EVM), recover `V`'s uncompressed/compressed secp256k1 public key from the signature (standard ECDSA recovery, always public).
2. As an unrelated unprivileged account, call `addr.associatePubKey(V_pubkey_hex)` on precompile `0x1004` — no signature over any challenge is required, only the raw pubkey bytes.
3. The call succeeds and creates/overwrites `V`'s Sei↔EVM address mapping (`precompiles/addr/addr.go` `associatePublicKey` → `associateAddresses` → `AssociateAddresses`), migrates any spendable/wei balance sitting at `sdk.AccAddress(V_evmAddr[:])` into `V`'s Sei address, and mutates `V`'s account record (`utils/helpers/associate.go` lines 34-55), all without `V` submitting a transaction or granting consent.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
