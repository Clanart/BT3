### Title
`Scanner::scan_block` credits immature coinbase outputs, so reported funds cannot actually be spent - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to the Vault crediting `balance` measured *before* a fee-on-transfer rather than the amount actually received, `Scanner::scan_block` credits outputs based on what a transaction *declares* rather than what the key holder can actually spend. Coinbase outputs are consensus-locked for 100 blocks, yet `scan_block` returns them as ordinary `ReceivedOutput`s indistinguishable from spendable ones.

### Finding Description
`Scanner::scan_transaction` pushes a `ReceivedOutput` for every output whose `script_pubkey` matches a registered script, recording the actual `TxOut` and `OutPoint` but making no distinction about the transaction type [1](#0-0) . `scan_block` iterates over `block.txdata`, which includes `txdata[0]`, the coinbase transaction [2](#0-1) . Per Bitcoin consensus rules (`COINBASE_MATURITY = 100`), coinbase outputs cannot be spent until the block is 100 deep.

A `ReceivedOutput` obtained this way flows directly into `SignableTransaction::new`, which sums `input.output.value` as `input_sat`, builds `TxIn`s from the outpoints, and computes change/fee over them [3](#0-2) . Nothing in `SignableTransaction::new`, `multisig` [4](#0-3) , or the signing path [5](#0-4)  checks input maturity. The resulting fully-signed transaction spending an immature coinbase is rejected by every node's consensus validation, so the withdrawal fails after a complete FROST signing ceremony — exactly the "credited balance exceeds spendable balance → withdrawal always reverts" shape of the Vault bug.

The doc comment on `scan_block` acknowledges the issue but leaves the immature outputs in the returned set, so the library itself still produces the incorrect accounting.

### Impact Explanation
Any `ReceivedOutput` derived from `scan_block` is asserted spendable by the type system and the wallet pipeline, yet a coinbase-derived one is consensus-unspendable. A `SignableTransaction` containing it will be signed successfully (the BIP-341 sighash over `Prevouts::All` is computed fine) but rejected at relay/mempool acceptance, burning the signing session and reporting funds as received that cannot be moved. If the immature output is commingled with mature inputs, the entire transaction is invalid, blocking withdrawal of all included funds.

### Likelihood Explanation
Reachable by an unprivileged party with a public Bitcoin transaction: any miner can include a coinbase payout to a scanned script (the vault's tweaked key or any registered offset). Requiring a mined block limits frequency, but no permission or victim interaction is needed beyond sending the transaction, and credit is recorded automatically on the next `scan_block`.

### Recommendation
In `Scanner::scan_block`, skip `block.txdata[0]` or tag `ReceivedOutput`s derived from coinbase transactions with a maturity height (e.g., a `coinbase: bool` / `matures_at` field), and have `SignableTransaction::new` reject immature inputs. Alternatively, make `scan_block` take a block height/confirmation count so callers cannot inadvertently treat immature coinbase outputs as spendable.

### Proof of Concept
```rust
// A miner crafts a block whose coinbase pays to the vault's P2TR script.
let scanner = Scanner::new(vault_group_key).unwrap();
let block: Block = mined_block_with_coinbase_to(scanner_script);

// The immature coinbase output is returned as a normal ReceivedOutput.
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1); // credited, but consensus-unspendable for 100 blocks

// The wallet pipeline accepts it and produces a fully signed transaction...
let stx = SignableTransaction::new(outputs, &payments, change, None, fee_rate).unwrap();
let signed_tx = run_frost_ceremony(stx.multisig(&keys).unwrap());

// ...which every node rejects: "bad-txns-premature-spend-of-coinbase".
// Funds reported received are not spendable; withdrawal always reverts.
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
