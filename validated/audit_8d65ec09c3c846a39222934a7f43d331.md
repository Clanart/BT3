### Title
CW→ERC Pointer Registration Bypasses `RegisterPointerDisabled` via the EVM Pointer Precompile - (File: precompiles/pointer/pointer.go)

### Summary
The `x/evm` module exposes a governance-controlled kill switch, `RegisterPointerDisabled`, meant to stop creation of new CW→ERC pointer contracts. It is enforced in the Cosmos `MsgRegisterPointer` handler, but the equivalent EVM-facing entry point — the pointer precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` methods — never checks this flag, so any EVM caller can still create new pointers after the feature is "disabled."

### Finding Description
`x/evm/keeper/msg_server.go`'s `RegisterPointer` handler explicitly gates pointer creation: [1](#0-0) 
This is the only place in the codebase that calls `GetRegisterPointerDisabled` (confirmed via repo-wide grep — matches are limited to `msg_server.go`, `params.go`, `params.pb.go`, and their tests; `precompiles/` has zero matches).

However, the same underlying capability — minting a fresh CW20/CW721/CW1155 pointer contract for an arbitrary CosmWasm contract address — is also reachable through the EVM pointer precompile (`0x…100b`), whose executor dispatches to `AddCW20`, `AddCW721`, and `AddCW1155`: [2](#0-1) [3](#0-2) 
These call `p.evmKeeper.UpsertERCCW20Pointer` / `UpsertERCCW721Pointer` / `UpsertERCCW1155Pointer` in `x/evm/keeper/pointer_upgrade.go`, none of which check `GetRegisterPointerDisabled`. The precompile's `Execute` dispatcher only checks `readOnly` and delegatecall context — no params/disabled check: [4](#0-3) 

This is structurally identical to the referenced Zulip bug class: a global "disable" toggle (there: `enable_spectator_access`; here: `RegisterPointerDisabled`) is enforced on one access path (there: web endpoints for new spectator sessions; here: the Cosmos `MsgRegisterPointer` tx) but not on a second, still-reachable path that performs the same privileged action (there: direct attachment/topic fetch URLs; here: the EVM pointer precompile callable from any transaction, contract, or `eth_call`).

### Impact Explanation
`RegisterPointerDisabled` exists as an operational safety switch (e.g., to freeze pointer creation during an incident, migration, or to prevent proliferation of unreviewed/duplicate pointer contracts pointing at attacker-controlled CW20/CW721/CW1155 contracts). Because the precompile path ignores the flag, an attacker or any user can continue registering pointers for arbitrary (including malicious) CosmWasm contracts after governance has disabled the feature, undermining the intended chain-wide control. Newly created pointer contracts become live ERC20/ERC721/ERC1155 tokens integrated into the EVM ecosystem (wallets, DEXs, etc.), which can be used to spoof or shadow legitimate tokens/collections — a supply/asset-integrity concern reachable purely from an unprivileged EVM transaction.

### Likelihood Explanation
High reachability: this only requires an EVM transaction calling the pointer precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` method with an arbitrary CW contract address — no special privilege needed, and it works precisely in the scenario where governance has just disabled pointer registration expecting it to be blocked chain-wide.

### Recommendation
Add a `ctx` check for `p.evmKeeper.GetRegisterPointerDisabled(ctx)` (mirroring `msg_server.go`'s `RegisterPointer`) at the top of `AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` (and any legacy versioned copies under `precompiles/pointer/legacy/...` that remain reachable), returning an error identical in spirit to `"registering CW->ERC pointers has been disabled"` when the flag is set.

### Proof of Concept
1. Governance passes a parameter-change proposal setting `x/evm` param `RegisterPointerDisabled = true` (verifiable via the existing `TestRegisterPointerDisabled` test in `x/evm/keeper/msg_server_test.go`, which confirms `MsgRegisterPointer` now fails).
2. From an EVM account, call the pointer precompile at `0x...100b`, method `addCW20Pointer(cwAddress)` (or `addCW721Pointer`/`addCW1155Pointer`) for any existing CW20/CW721/CW1155 contract not yet pointed.
3. Observe the call succeeds: `AddCW20`/`AddCW721`/`AddCW1155` in `precompiles/pointer/pointer.go` proceeds to `UpsertERCCW20Pointer`/etc. and returns a new pointer contract address, with no error referencing `RegisterPointerDisabled`, in contrast to the identical operation attempted via `MsgRegisterPointer`.

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
