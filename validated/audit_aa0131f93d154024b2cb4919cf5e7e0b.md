## Analog Found

### Title
Credential-Helper "Endpoint Kind" Is Classified From an Attacker-Controlled `WWW-Authenticate` Header, Not From a Bound Host Identity - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The report's root cause is a decision (which "denomination" a payout belongs to) being derived from a value the attacker controls (`msg.sender`/`_amount` alone, with no binding to `token_address`), instead of from a value cryptographically tied to the correct context. The Desktop analog is `getEndpointKind()` in the git-credential trampoline: it decides whether a remote endpoint is a trusted GitHub/GHE host (and therefore eligible to trigger a GitHub sign-in flow) largely from a `WWW-Authenticate` response header that the remote git server supplies — a value fully controlled by whatever server the user's git process is talking to.

### Finding Description
`getEndpointKind()` is used by `getCredential()`, `storeCredential()`, and `eraseCredential()` to decide how to treat a remote's credential request: [1](#0-0) 

Concretely, if git forwards a header matching `realm="GitHub"`, the function returns `'enterprise'` without verifying that the host is actually a GitHub Enterprise instance: [2](#0-1) 

This "kind" then drives two distinct behaviors:
1. In `getCredential()`, when `endpointKind !== 'generic'` and no stored account matches the endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` and begins an enterprise sign-in flow bound to that (attacker-controlled) endpoint: [3](#0-2) [4](#0-3) 
2. In `storeCredential()`/`eraseCredential()`, when `endpointKind === 'generic'` (the "else" branch), Desktop persists the plaintext username/password credential to `localStorage`/keychain keyed only by the endpoint URL, with no verification that the endpoint really is a non-GitHub host: [5](#0-4) 

Just as the Merkle leaf `keccak256(sender, amount)` omits the denomination (`token_address`), letting `tokenDistribution` — an out-of-band, independently-set value — decide how funds are actually paid, `getEndpointKind()` omits any binding of the "trust class" decision to a verified identity of the host; it instead trusts a header string the remote server chooses to send. `isDotCom`/`isGHE` (real, hostname-based checks) are tried first, but they fall through to the spoofable header check for any host that isn't already a known GitHub domain, and only afterward (in the last branch) does the code fall back to `isGitHubHost(endpoint)`, an actual network check — meaning the header short-circuits that verification for any attacker who wants to force the `'enterprise'` branch.

### Impact Explanation
An attacker who controls the far end of an HTTP(S) git remote/proxy that a user's clone/fetch/push talks to (e.g., a malicious or compromised `.gitmodules` submodule URL, a redirected/MITM'd remote, or any custom remote the user adds) can respond with `WWW-Authenticate: Basic realm="GitHub"` to force Desktop's credential helper to treat that non-GitHub server as an `'enterprise'` GitHub endpoint. This can cause Desktop to surface an unexpected GitHub Enterprise sign-in prompt bound to the attacker's endpoint, and it changes which storage/lookup path (`generic` vs GitHub-account) is used for that host — the same class of confusion the report warns about: a security-relevant classification decided by an unauthenticated, attacker-suppliable signal rather than by a value bound to the true resource.

### Likelihood Explanation
Triggering the header requires only that the attacker control the server on the other end of a URL the user's git process talks to (a plausible unprivileged path: malicious repo with a submodule pointing at attacker infrastructure, or a manipulated/self-hosted remote) — no local access, admin rights, or prior malware is needed. However, I was not able to fully trace the downstream consequences of `promptForGitHubSignIn` → `dispatcher.beginEnterpriseSignIn` / the OAuth device-code exchange within the available search budget, so I cannot confirm whether the resulting sign-in flow could be abused to exfiltrate a real GitHub.com token versus merely mis-prompting the user for an endpoint they didn't intend to authenticate against. That part of the impact chain is uncertain and would need further code review of `app/src/lib/stores/sign-in-store.ts` and `app/src/ui/sign-in/sign-in.tsx` to fully confirm.

### Recommendation
Do not let a remote-supplied `WWW-Authenticate` realm string alone decide the "kind" of an endpoint for security-relevant branching. Bind the classification to a verified signal (e.g., always require the `isGitHubHost()` live check, or only honor the header hint after `isDotCom`/`isGHE` positively match a known GitHub domain), analogous to including the missing `token_address` field in the Merkle leaf so the payout path can't be redirected by an unrelated, attacker-influenced value.

### Proof of Concept
1. Add or fetch a repository whose `.gitmodules` (or a manually-added remote) points to `https://attacker.example/foo/bar.git`.
2. Stand up a server at `attacker.example` that, on the git smart-HTTP auth challenge, responds with `WWW-Authenticate: Basic realm="GitHub"`.
3. Trigger a git operation (fetch/clone/push) against that remote from GitHub Desktop.
4. Observe that `getEndpointKind()` returns `'enterprise'` for `attacker.example` purely from the header (bypassing the `isDotCom`/`isGHE` hostname checks), causing Desktop's credential helper (`getCredential` in `app/src/lib/trampoline/trampoline-credential-helper.ts:94-135`) to treat the attacker's server as a GitHub Enterprise endpoint and prompt an enterprise sign-in instead of falling back to the generic/username-password credential flow that a non-GitHub host should use.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)
  return approveCredential(cred, path, getGcmEnv(token))
}

/** Implementation of the 'erase' git credential helper command */
async function eraseCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? eraseExternalCredential(cred, token)
    : deleteGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username'))
      )
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
