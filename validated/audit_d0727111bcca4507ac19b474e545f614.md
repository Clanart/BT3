### Title
KIP71Config.NextMagmaBlockBaseFee divides by GasTarget without a zero-guard, causing a chain-halting panic when GasTarget=0 is set via governance - (File: params/kip71_config.go)

### Summary
`NextMagmaBlockBaseFee` computes the KIP-71 base-fee delta using `parentGasUsed - gasTarget` and then divides by `gasTarget` directly, with no zero check, unlike the sibling `BaseFeeDenominator` which is explicitly guarded against zero. This mirrors the "empty vault" class of bug in the reference report: a corner-case parameter (there, zero total supply/zero total value; here, zero `GasTarget`) is not defensively handled before being used as a divisor.

### Finding Description
Governance parameter `kip71.gastarget` is canonicalized by `uint64Canonicalizer` and validated by `noopFormatChecker`, which unconditionally returns `true` [3](#0-2) [1](#0-0) . There is no `v != 0` check as exists for the sibling `Kip71BaseFeeDenominator` parameter [4](#0-3) . This means a governance vote can legally set `GasTarget` to `0`.

`NextMagmaBlockBaseFee` explicitly special-cases `BaseFeeDenominator == 0` to avoid a panic:
```go
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
``` [5](#0-4) 

But `gasTarget` has no such guard, and is used directly as a divisor in both the "gas used above target" and "gas used below target" branches:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
``` [6](#0-5) 
```go
gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
``` [7](#0-6) 

Go's `math/big.Int.Div` panics on division by zero. If `gasTarget == 0` and `parentGasUsed != 0` (the overwhelmingly common case, since `parentGasUsed == gasTarget` only when `parentGasUsed == 0`), the `parentGasUsed > gasTarget` branch is taken and `y := x.Div(x, new(big.Int).SetUint64(0))` panics.

This function is invoked from consensus-critical paths — header verification (`VerifyMagmaHeader`) [8](#0-7)  and fee-history/base-fee estimation (`feehistory.go`) [9](#0-8) , both of which every full node and public-RPC-serving node executes for every new block once Magma is active.

### Impact Explanation
Once a governance vote sets `kip71.gastarget = 0` (or the parameter set otherwise resolves to `GasTarget = 0`, e.g. via `patchDeprecatedParams`/ParamSet flow feeding `ToKip71Config()` [10](#0-9) ), every node on the network that verifies the next Magma-era block header (i.e., practically every honest node, and any public-RPC node serving `eth_feeHistory`) will panic in `NextMagmaBlockBaseFee`. This is a network-wide denial-of-service / chain halt — all nodes crash identically at the same block height, rather than diverging, which is a severe availability failure of the consensus layer and of public RPC endpoints that call `feeHistory`.

### Likelihood Explanation
Reaching this requires a successful governance vote to set `GasTarget` to `0` (or the deployment/patch of an existing chain-config value of 0 for this field), which is gated by the governance module rather than by an arbitrary unprivileged transaction. However, per the given scope, "governance parameters" is an explicitly accepted analog category, and unlike `BaseFeeDenominator`, which the code authors clearly recognized needed a zero-value protection, `GasTarget` received no equivalent protection — an oversight rather than an intentional trust boundary. Any governance participant (or a misconfigured/malicious governing node under single-governance-node setups) can trigger this without any additional preconditions once the vote is accepted.

### Recommendation
Add an explicit `v != 0` (or `v > 0`) format checker for `Kip71GasTarget`, mirroring the check already present for `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```
Additionally, as defense-in-depth, guard `NextMagmaBlockBaseFee` against `gasTarget == 0` the same way it guards `BaseFeeDenominator == 0`, to prevent a panic even if an invalid/legacy `ChainConfig` is loaded.

### Proof of Concept
1. Governance sets (via vote or genesis/hardfork chain-config patch) `Governance.KIP71.GasTarget = 0` while `MaxBlockGasUsedForBaseFee`, `LowerBoundBaseFee`, `UpperBoundBaseFee` remain nonzero (default) values.
2. Any block after the Magma hardfork with `header.GasUsed > 0` is produced/received.
3. Header verification calls `KIP71Config.VerifyMagmaHeader` → `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)`.
4. Since `parentGasUsed (>0) > gasTarget (0)`, the code executes `y := x.Div(x, new(big.Int).SetUint64(0))`, which panics with "division by zero" in Go's `math/big` package, crashing the node process.
5. This occurs on every node validating the block (and every node serving `eth_feeHistory` for a range spanning that block via `processBlock`), producing a synchronized network-wide crash. [11](#0-10)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
