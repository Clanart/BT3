### Title
DataLayer mirror URLs are sent directly to `aiohttp` with no IP/host validation, enabling SSRF-style internal network probing via on-chain mirror coins - ([File: chia/data_layer/download_data.py])

### Summary
DataLayer's `DLNewMirror` wallet action lets any wallet owner publish an arbitrary list of URL strings on-chain in a mirror coin (via `create_new_mirror`), with no host/IP restriction. Every DataLayer node that subscribes to that store treats these attacker-controlled strings as literal server URLs and issues real outbound HTTP(S) requests to them from `download_file()`/`http_download()`, with no equivalent of the SSRF protections Chia already applies elsewhere in its networking stack (`chia/util/network.py`'s `is_localhost`, `is_trusted_cidr`, `resolve()` private-IP checks used for peer connections).

### Finding Description
A DataLayer store owner calls `dl_new_mirror` / `create_new_mirror`, which encodes an arbitrary `urls: list[str]` into the mirror coin's memos with no validation beyond "non-empty list" at the RPC layer (`add_mirror` in `chia/data_layer/data_layer.py:965-970` only checks `if not urls: raise RuntimeError(...)`). [1](#0-0) [2](#0-1) 

These mirror coins are on-chain, so any peer syncing the chain and reading the singleton/mirror data can discover them; a DataLayer client that subscribes to a store pulls the mirror URLs and stores them as candidate download servers via `update_subscriptions_from_wallet()`: [3](#0-2) 

When syncing, `fetch_and_validate()` picks a (randomized) server from these mirror-derived `servers_info` and passes the raw URL into `insert_from_delta_file()` → `download_file()`, which — when no downloader plugin is configured — calls `http_download()`, opening a genuine aiohttp connection to whatever host/port is embedded in the string: [4](#0-3) [5](#0-4) 

Unlike the peer/handshake path in `chia/server/server.py`, which resolves hostnames and can apply exempt/trusted-network checks (`is_localhost`, `is_in_network`), and unlike `chia/util/network.py`'s `is_trusted_cidr`/`is_localhost` helpers used elsewhere to gate trust, there is no analogous check anywhere in the DataLayer mirror/download path that blocks loopback, RFC1918/private, link-local, or cloud metadata addresses before `aiohttp.ClientSession` connects. [6](#0-5) [7](#0-6) 

Test code (`test_mirrors`, `test_server_http_ban`) even demonstrates mirror/subscription URLs pointed at `http://127.0.0.1/8000` being accepted and stored/used without complaint, confirming there is no host filtering: [8](#0-7) 

The plugin/downloader path (`get_downloader()` / `download_file()` downloader branch) similarly forwards the raw mirror `url` in a JSON POST body without validating it: [9](#0-8) 

### Impact Explanation
Any wallet holder can, for the cost of a small fee/mirror-amount transaction, publish mirror URLs pointing at internal-network addresses (e.g. `http://127.0.0.1:6379`, `http://169.254.169.254/latest/meta-data`, or addresses on a shared/cloud-hosted DataLayer operator's private network). Every DataLayer node that later subscribes to that store — a normal, unprivileged Data Layer client action — will connect outbound to that address on the operator's behalf. `download_file()`/`http_download()` catches only `asyncio.TimeoutError`, `aiohttp.ClientError`, and `MaxDeltaFileSizeExceededError`, and errors/failures are logged (`log.info`, `server_misses_file`) with the target URL and failure reason. This provides non-blind SSRF/port-scanning of internal services from any Data Layer node that subscribes to an attacker-controlled or attacker-influenced store — analogous in bug-class to the reported AutoGPT `SendEmailBlock` SSRF (user-controlled network target with no IP allow/deny-list, bypassing the platform's usual host-validation utilities). This is a Medium-severity issue: it enables internal reconnaissance/SSRF against DataLayer operators, not direct coin-set or consensus divergence, but it is a concrete unauthorized-network-access vector reachable from an ordinary wallet/Data-Layer-client action.

### Likelihood Explanation
Likelihood is moderate-to-high: creating a mirror coin with attacker-chosen URLs requires only a standard wallet spend (`dl_new_mirror`), no special privilege. Any node that operates a DataLayer service and subscribes to a store containing such a mirror will automatically attempt the connection during its periodic `update_subscription()` cycle without any user interaction beyond having subscribed to the store id (a normal DataLayer client action, e.g. to sync data offered in a trade).

### Recommendation
Before treating a mirror/subscription URL as a download target, validate and reject URLs that resolve to loopback, private/RFC1918, link-local, multicast, and cloud metadata address ranges — reusing the existing `is_localhost()` / `is_trusted_cidr()` / private-IP-aware `resolve()` logic already present in `chia/util/network.py`, applied consistently in `download_file()`/`http_download()` (and the plugin `get_downloader()` POST) prior to opening the connection. Consider also making this behavior configurable (e.g., an explicit opt-in for local/trusted testing) rather than defaulting to unrestricted outbound access.

### Proof of Concept
1. Wallet A creates a DataLayer store and calls `dl_new_mirror` (`chia/wallet/wallet_rpc_api.py` `dl_new_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/", "http://10.0.0.5:6379/"]`, publishing the mirror coin on-chain.
2. Wallet/DataLayer operator B subscribes to that store id via `data_rpc_api.subscribe`.
3. On the next `periodically_manage_data()` cycle, `update_subscription()` → `fetch_and_validate()` selects the malicious mirror URL from `servers_info` and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which opens a genuine TCP/HTTP connection from B's host to the internal/metadata address supplied by A.
4. Connection success/failure and any partial response/error text are logged via `log.info`/`log.warning` referencing the URL, giving A (via B's public store/logs, or via repeated timing/behavior probing across many mirror URLs) a way to fingerprint internal services reachable from B's DataLayer node — the same "reachable-target discovery via user-controlled server field, no IP validation" bug class as CVE-2026-33234.

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

def is_in_network(peer_host: str, networks: Iterable[IPv4Network | IPv6Network]) -> bool:
    try:
        peer_host_ip = ip_address(peer_host)
        return any(peer_host_ip in network for network in networks)
    except ValueError:
        return False


def is_trusted_cidr(peer_host: str, trusted_cidrs: list[str]) -> bool:
    try:
        ip_obj = ipaddress.ip_address(peer_host)
    except ValueError:
        return False

    for cidr in trusted_cidrs:
        network = ipaddress.ip_network(cidr)
        if ip_obj in network:
            return True

    return False


def is_localhost(peer_host: str) -> bool:
    return peer_host in {"127.0.0.1", "localhost", "::1", "0:0:0:0:0:0:0:1"}


def is_trusted_peer(
    host: str, node_id: bytes32, trusted_peers: dict[str, Any], trusted_cidrs: list[str], testing: bool = False
) -> bool:
    return (
        (not testing and is_localhost(host)) or node_id.hex() in trusted_peers or is_trusted_cidr(host, trusted_cidrs)
    )
