## Title
Spoofable `WWW-Authenticate` header lets any Git remote force GitHub Desktop into an "enterprise" sign-in flow, pre-populating the Enterprise sign-in endpoint with an attacker-controlled origin - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Git forwards any `WWW-Authenticate` response header it receives from a remote server to Desktop's credential helper. `getEndpointKind` in `trampoline-credential-helper.ts` treats the mere presence of `realm="GitHub"` in that attacker-controlled header as sufficient proof that the remote is a GitHub Enterprise host, without ever calling `isGitHubHost()` to actually verify it against the real API. This is analogous to the `AukiToken` bug in that a guard meant to gate a whole class of operations (only real GitHub/GHE hosts should trigger the GitHub sign-in flow) is skipped via a "fast path" that doesn't defend against the value it trusts.

### Finding Description
`getEndpointKind` classifies a credential request's host before deciding how to handle it: [1](#0-0) 

The `wwwauth[...]` map entries come directly from the `WWW-Authenticate` HTTP header sent by whatever server is on the other end of the `git` remote/proxy — fully attacker-controlled when the remote is malicious or a MITM proxy is involved. If the header contains `realm="GitHub"`, the function immediately returns `'enterprise'` as a "happy path... without having to resort to making a request ourselves" (per the code comment), bypassing the authoritative `isGitHubHost(endpoint)` network check that is only reached later, for hosts that didn't send this header.

Downstream, `getCredential` uses this classification to decide whether to prompt the user to sign in to GitHub: [2](#0-1) 

Because `endpointKind !== 'generic'` for any spoofed host, and no stored account will match `apiEndpoint` for an arbitrary attacker host, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which for a non-`github.com` hostname begins the **Enterprise sign-in flow** and sets the sign-in endpoint to the attacker's origin: [3](#0-2) 

This means a user cloning/fetching from (or being proxied through) an attacker-controlled remote can be shown Desktop's native "Sign in to GitHub Enterprise" dialog, pre-filled with the attacker's origin as the enterprise server, purely because the server sent a forged `WWW-Authenticate: realm="GitHub"` header — no real GHE API needs to exist there.

### Impact Explanation
If the user completes the resulting sign-in flow, the OAuth/PAT credentials they enter are bound to (and in the device/PAT flow, sent to) the attacker-supplied enterprise origin, which the user may reasonably believe is a legitimate corporate GHE instance because Desktop itself initiated the dialog. This satisfies "unauthorized OAuth or account binding" and enables credential exfiltration via a purely remote-controlled trigger (attacker-controlled git remote/proxy response) — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Likelihood is moderate: it requires the user to interact with a malicious/compromised remote (clone/fetch/push over HTTPS) and then to actually go through with the resulting sign-in prompt. The trigger itself (spoofing a header in a git HTTP response) is trivial for any attacker who controls the remote server or a MITM/proxy in the path, and requires no unusual local steps from the user beyond a normal `git fetch`/`clone`/`push` in Desktop.

### Recommendation
Do not trust the `WWW-Authenticate` realm alone to classify a host as GitHub/GHE. Either remove the header-based fast path entirely and always fall back to the authenticated `isGitHubHost(endpoint)` check, or treat a `wwwauth` match only as a hint that triggers verification (not a substitute for it) before invoking `promptForGitHubSignIn`/`beginEnterpriseSignIn` with the endpoint.

### Proof of Concept
1. Host an HTTPS git server (or MITM proxy) at `https://evil.example.com/repo.git`.
2. Configure it to respond to Git's credential probe with `WWW-Authenticate: Basic realm="GitHub"` on a 401.
3. In GitHub Desktop, add `evil.example.com` as a remote and perform `git fetch`/clone.
4. Observe `getEndpointKind` returns `'enterprise'` for `evil.example.com` without any real GHE API call, and `getCredential` invokes `ui.promptForGitHubSignIn('https://evil.example.com')`, which opens the Enterprise sign-in dialog pre-bound to the attacker's origin. [4](#0-3) [5](#0-4)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
