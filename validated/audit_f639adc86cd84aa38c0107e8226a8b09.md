### Title
Unhandled exception/assertion when parsing a crafted offer's inner puzzle output can crash offer processing - (File: chia/wallet/trading/offer.py)

### Summary
CVE-2016-7536 is a crash-on-crafted-input bug class: ImageMagick's `magick/profile.c` dereferences attacker-supplied profile data without adequate bounds/shape checking, causing a segfault (DoS) when a client merely opens a crafted file. The reachable analog in this codebase is `Offer._get_offered_coins()` in `chia/wallet/trading/offer.py`, which walks a counterparty-supplied offer's puzzle reveals/solutions and CLVM condition output, and relies on unguarded `assert` statements and unhandled `ValueError`/indexing paths to validate the shape of that untrusted data.

### Finding Description
`Offer._get_offered_coins()` [1](#0-0)  is invoked whenever a wallet parses an offer (maker or taker side, including Data Layer offer flows) to compute which coins are being offered. For any coin spend in the bundle whose puzzle matches a known outer-puzzle driver (CAT, CR-CAT, NFT, etc.), the code does:

```
inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
assert inner_puzzle is not None and inner_solution is not None
``` [2](#0-1) 

and later:
```
puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
assert cost_left >= puzzle_cost
``` [3](#0-2) 

and if amount/puzzle-hash heuristics fail to reconcile the coins:
```
raise ValueError("Could not properly guess offered coins from parent spend")
``` [4](#0-3) 

None of these are caught by the caller. `TradeManager.calculate_tx_records_for_offer()` and `check_offer_validity()` call into offer accessor methods that route through `get_offered_coins()`/`_get_offered_coins()` [5](#0-4)  during normal offer-taking, and `DataLayerWallet.get_offer_summary()` similarly parses raw offer puzzle/solution structure with only narrow exception handling (`except EvalError: continue`) around one specific access [6](#0-5) , leaving other malformed-structure paths (e.g., wrong tuple arity in `as_iter()` unpacking, missing driver args) to raise uncaught `ValueError`/`AssertionError`/`EvalError`.

This mirrors the ImageMagick class of bug: a counterparty (an "offer counterparty" per the reachable-actor list) constructs a spend bundle/offer whose puzzle reveal matches a known outer-puzzle signature but whose solution or curried-arg shape is malformed in a way that the shape-checking code doesn't anticipate, causing an unhandled exception instead of a graceful `None`/`False` result.

### Impact Explanation
An offer counterparty (or any user importing/reviewing an untrusted offer file, including through Data Layer offer flows) can supply a malformed offer that trips an `assert` or raises an unhandled `ValueError`/`EvalError` deep inside `_get_offered_coins()`. Because `AssertionError` and generic exceptions are not caught by the RPC/offer-processing call sites shown, this can abort the in-process request handling the offer (a spend-triggered transaction-processing halt for that wallet flow), a denial-of-service impact analogous to the referenced CVE's segfault-on-crafted-profile. This does not by itself cause fund loss or consensus divergence — the impact is limited to disrupting the wallet's ability to process/evaluate an offer, similar in severity class to the medium-rated upstream ImageMagick bug.

### Likelihood Explanation
Likelihood is moderate: crafting an offer with a matched outer-puzzle driver (CAT/CR-CAT/NFT) but an inner puzzle/solution shape that violates the heuristic assumptions in `_get_offered_coins()` is plausible for any party constructing offer bytes by hand (bech32-decoded and streamable-parsed via `Offer.from_bech32()`/`TakeOffer.parsed_offer`, [7](#0-6) ), without requiring network-level compromise, a leaked key, or malicious-peer capability — only an unprivileged, self-crafted offer.

### Recommendation
Wrap the puzzle-driver–assisted parsing in `Offer._get_offered_coins()` (`get_inner_puzzle`/`get_inner_solution`/`run_with_cost` calls and the subsequent `assert` statements) in explicit `try/except` blocks that convert malformed-shape failures into a clean `ValueError`/`OfferIntegrityError`-style rejection instead of letting `AssertionError`, `EvalError`, or arbitrary exceptions propagate uncaught. Apply the same hardening to `DataLayerWallet.get_offer_summary()`'s puzzle/solution traversal so any not-well-formed graftroot/singleton structure is rejected rather than raising unexpectedly.

### Proof of Concept
Construct a `WalletSpendBundle` whose single coin spend has a puzzle reveal that `match_puzzle()` recognizes as a CAT (or CR-CAT/NFT) outer puzzle, but whose solution's inner-solution slot is shaped so that `get_inner_solution()`/`get_inner_puzzle()` returns `None` (e.g., a solution missing the expected nested field) or whose inner puzzle execution yields a `CREATE_COIN` cost that violates the `cost_left >= puzzle_cost` invariant. Wrap this bundle into an `Offer` and call `offer.get_offered_coins()` (as done in `TradeManager.calculate_tx_records_for_offer()`/`check_offer_validity()`); the process raises an uncaught `AssertionError`/`ValueError` instead of returning a controlled error, since these code paths lack the surrounding `try/except` present elsewhere (e.g., in `Offer.__post_init__` for `compute_spend_hints_and_additions`). Note: I was unable to execute this against a live wallet instance in this environment, so the PoC is based on static code-path analysis of the cited functions; a Devin session with repo execution access would be needed to confirm the exact exception raised end-to-end.

    def _get_offered_coins(self) -> dict[bytes32 | None, list[Coin]]:
        offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")
            else:
                # It's much easier if the asset is bare XCH
                asset_id = None
                coins_for_this_spend.extend([a for a in additions if a.puzzle_hash == OFFER_MOD_HASH])

            # We only care about unspent coins
            coins_for_this_spend = [c for c in coins_for_this_spend if c not in self._bundle.removals()]

            if coins_for_this_spend != []:
                offered_coins.setdefault(asset_id, [])
                offered_coins[asset_id].extend(coins_for_this_spend)
        return offered_coins

    @staticmethod
    async def get_offer_summary(offer: Offer) -> DataLayerSummary:
        singleton_summaries = []
        for spend in offer.coin_spends():
            solution = Program.from_serialized(spend.solution)
            matched, curried_args = match_dl_singleton(spend.puzzle_reveal)
            if matched:
                try:
                    graftroot: Program = solution.at("rrffrf")
                except EvalError:
                    continue
                mod, graftroot_curried_args = graftroot.uncurry()
                if mod == GRAFTROOT_DL_OFFERS:
                    child_spend: CoinSpend = next(
                        cs for cs in offer.coin_spends() if cs.coin.parent_coin_info == spend.coin.name()
                    )
                    _, child_curried_args = match_dl_singleton(child_spend.puzzle_reveal)
                    _, singleton_structs, _, values_to_prove = graftroot_curried_args.as_iter()
                    dependencies = []
                    for struct, values in zip(singleton_structs.as_iter(), values_to_prove.as_iter()):
                        dependencies.append(
                            SingletonDependencies(
                                launcher_id=bytes32(struct.at("rf").as_atom()),
                                values_to_prove=[value.as_atom() for value in values.as_iter()],
                            )
                        )
                    singleton_summary = SingletonSummary(
                        launcher_id=bytes32(list(curried_args)[2].as_atom()),
                        new_root=bytes32(list(child_curried_args)[1].as_atom()),
                        dependencies=dependencies,
                    )
                    singleton_summaries.append(singleton_summary)
        return DataLayerSummary(offered=singleton_summaries)
