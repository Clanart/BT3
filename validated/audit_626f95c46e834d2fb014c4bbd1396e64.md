### Title
Unvalidated `ReceivedOutput` deserialization permits fabricated Bitcoin deposits - (File: `networks/bitcoin/src/wallet/mod.rs`) [1](#0-0) 

### Summary

`ReceivedOutput::read` accepts the spend offset, complete `TxOut`, and `OutPoint` as three independent serialized fields, without checking that the script corresponds to the offset or that the outpoint actually contains the supplied output. [1](#0-0) 

This differs from `Scanner::scan_transaction`, which only creates a `ReceivedOutput` after an on-chain `script_pubkey` matches a registered script and then copies the real transaction output and outpoint. [2](#0-1) 

### Finding Description

The normal scanner path establishes the invariant `output.script_pubkey == p2tr(base_key + offset * G)` and obtains both `output` and `outpoint` from the same transaction output. [3](#0-2) 

The deserializer discards that invariant: it reads an arbitrary scalar through `Secp256k1::read_F`, followed by arbitrary consensus-encoded `TxOut` and `OutPoint` values, then returns them directly. [1](#0-0) 

The processor-level parser compounds this by deserializing attacker-controlled `kind`, `presumed_origin`, embedded `ReceivedOutput`, and metadata without a final canonicality or source check. [4](#0-3) 

`Output::key` reconstructs the asserted owning key by parsing the supplied `TxOut` script and subtracting the supplied offset. [5](#0-4) 

`Output::balance` reports the value embedded in the supplied `TxOut`, not the value present at the referenced outpoint. [6](#0-5) 

The scheduler explicitly deserializes persisted `N::Output` entries into its spendable UTXO list. [7](#0-6) 

`SignableTransaction::new` then trusts the embedded `TxOut` as the prevout, uses the supplied outpoint as the transaction input, and records the attacker-controlled output in `prevouts`. [8](#0-7) [9](#0-8) 

Before signing, `multisig` only checks whether the supplied `prevouts[i].script_pubkey` equals the script for `group_key + offset * G`; it does not compare that `TxOut` with the actual UTXO referenced by `outpoint`. [10](#0-9) 

### Impact Explanation

An attacker who can supply bytes to the documented `ReceivedOutput::read`/`Output::read` boundary can make Serai report an arbitrary-value UTXO as owned by a chosen multisig key. [11](#0-10) 

Because `SignableTransaction` uses the fabricated output as the Taproot prevout committed by `Prevouts::All`, the resulting signatures commit to attacker-selected prevout data rather than the actual UTXO data. [12](#0-11) 

This can cause a nonexistent or misstated deposit to enter scheduling and signing, while the final transaction is unspendable because Bitcoin consensus uses the real referenced `TxOut`. [8](#0-7) [12](#0-11) 

### Likelihood Explanation

The required input is only a syntactically valid scalar, `TxOut`, and `OutPoint`; every field is independently controlled by the byte supplier. [1](#0-0) 

The attacker does not need a validator key or an invalid curve encoding because the exploit relies on a missing semantic cross-field check rather than malformed primitive encodings. [1](#0-0) [13](#0-12) 

Exploitability depends on an attacker reaching a serialized-output or serialized-plan ingestion point; the issue is not exploitable if these bytes are confined to a mutually trusted local database. [14](#0-13) 

### Recommendation

Do not deserialize `ReceivedOutput` into a trusted spendable state without re-establishing the scanner invariant. [1](#0-0) [2](#0-1) 

A contextual parser should accept the expected base key or `Scanner`, verify `p2tr_script_buf(base_key + G * offset) == output.script_pubkey`, and verify that the referenced outpoint exists and resolves to the supplied `TxOut`. [15](#0-14) [2](#0-1) 

Before scheduling or signing, reload the referenced UTXO from a trusted Bitcoin view and compare its complete `TxOut`—especially `script_pubkey` and value—to the serialized value. [8](#0-7) [10](#0-9) 

### Proof of Concept

```rust
use bitcoin::{
  Amount, OutPoint, TxOut,
  consensus::serialize,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput};
use frost::curve::Secp256k1;
use ciphersuite::Ciphersuite;
use k256::{ProjectivePoint, Scalar};

fn forged_output_bytes(
  multisig_key: ProjectivePoint,
  victim_or_other_utxo: OutPoint,
) -> Vec<u8> {
  // The real outpoint may contain 10_000 sats and/or a non-Serai script.
  // The parser has no access to that context and accepts this replacement.
  let fake_txout = TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: p2tr_script_buf(multisig_key).unwrap(),
  };

  let mut bytes = Vec::new();
  bytes.extend(Scalar::ZERO.to_bytes());
  bytes.extend(serialize(&fake_txout));
  bytes.extend(serialize(&victim_or_other_utxo));
  bytes
}

let forged =
  ReceivedOutput::read::<&[u8]>(&mut forged_output_bytes(key, outpoint).as_ref())
    .unwrap();
assert_eq!(forged.value(), 1_000_000);
```

When wrapped as an external `Output`—kind `0`, SCALE `None` for `presumed_origin`, the serialized `ReceivedOutput`, and a zero data length—the processor reports the embedded amount as received and derives the multisig key from the fabricated script-offset pair. [4](#0-3) [11](#0-10) 

A plan constructed from the forged output passes `SignableTransaction::multisig` because the supplied script was deliberately generated from the multisig key, even though the referenced UTXO does not contain that supplied `TxOut` or amount. [10](#0-9)

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {

          }

          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

      .ok_or_else(|| io::Error::other("invalid point"))?;
