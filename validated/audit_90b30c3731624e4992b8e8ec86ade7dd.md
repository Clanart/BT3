### Title
Token-factory allow-list restriction is not enforced on CosmWasm contract-initiated bank sends - ([File: sei-wasmd/x/wasm/keeper/keeper.go])

### Summary
The GitLab report describes a case where one enforcement path (email-verification gating for domain-restricted group access) is checked in one flow but not in an equivalent alternate flow, letting an unverified principal reach a permission-gated resource. In sei-chain, a structurally analogous gap exists between the two code paths that move `x/bank` coins: the native `MsgSend` handler enforces the token-factory denom allow-list for both sender and receiver, but the `BankCoinTransferrer` used by the CosmWasm module for contract-initiated `BankMsg::Send` execution does not.

### Finding Description
`sei-cosmos/x/bank/keeper/msg_server.go`'s `Send` handler builds an `allowListCache` and calls `k.IsInDenomAllowList` for both the sender and the recipient before calling `SendCoins`, and separately checks `k.BlockedAddr(to)`: [1](#0-0) 

However, `sei-wasmd`'s `BankCoinTransferrer.TransferCoins` — documented as replicating "the cosmos-sdk behaviour as in msg_server.go" — only checks `IsSendEnabledCoins` and `BlockedAddr(toAddr)` before calling `k.SendCoins` directly; it never calls `IsInDenomAllowList`: [2](#0-1) 

`IsInDenomAllowList` is the mechanism that enforces token-factory `AllowList` restrictions (only addresses on the list may send/receive a given restricted token-factory denom): [3](#0-2) 

`BankCoinTransferrer` is injected into the wasm keeper via `WithCoinTransferrer` as the `k.bank` field used to move funds for contract instantiate/execute deposits and for `BankMsg::Send` dispatched by a contract: [4](#0-3) 
The wasm message encoder converts a contract's `wasmvmtypes.BankMsg` into a native `banktypes.MsgSend`, but this message is dispatched through the SDK message handler chain which uses `k.bank.TransferCoins` (i.e., `BankCoinTransferrer`), not through `bank.msgServer.Send`, so the allow-list check that exists in the normal transaction path is skipped: [5](#0-4) 

This is functionally the same bug class as the GitLab report: an access-restriction check (allow-list membership / email verification) that is enforced on one entry point (`MsgSend` via HTTP/normal group-join flow) is missing on a semantically equivalent alternate entry point (contract-dispatched sends via wasm / domain-restricted group access via an alternate acceptance flow), letting unverified/unauthorized addresses reach a gated resource.

### Impact Explanation
Token-factory denom creators use `SetDenomAllowList`/allow-lists to restrict who may hold or transfer a given asset (e.g., for compliance-gated or permissioned tokens). A CosmWasm contract that receives or forwards such a denom (e.g., via a swap, vault, or vesting contract) can move the restricted coins to or from addresses that are not on the allow list, because `BankCoinTransferrer.TransferCoins` — the only checkpoint in that dispatch path — omits the `IsInDenomAllowList` check present in `msg_server.go`. This constitutes unauthorized transfer of a permissioned asset: an address explicitly excluded from a denom's allow-list can still receive/send that denom by routing the transfer through a contract's `BankMsg::Send`, undermining the access-control guarantee the allow-list is meant to provide.

### Likelihood Explanation
Any unprivileged wasm contract deployer/caller can trigger this: deploy (or use an existing) CosmWasm contract that issues a `BankMsg::Send` for the token-factory denom in question, with `to`/`from` addresses that are not on the denom's allow list. No special privilege beyond being able to instantiate/execute a contract and hold/receive the restricted denom is required, making this straightforward for any user interacting with CosmWasm contracts that move token-factory coins.

### Recommendation
Add the same `IsInDenomAllowList` check (for both sender and recipient) that `bank.msgServer.Send` performs into `BankCoinTransferrer.TransferCoins` in `sei-wasmd/x/wasm/keeper/keeper.go`, so contract-initiated bank transfers are subject to the identical token-factory allow-list enforcement as native `MsgSend` transactions.

### Proof of Concept
1. Denom admin creates a token-factory denom `factory/<admin>/restricted` and sets `SetDenomAllowList(ctx, denom, AllowList{Addresses: []string{addrA}})`, i.e. only `addrA` may hold/transfer it.
2. Deploy a simple CosmWasm contract whose `execute` handler, given any input, issues `CosmosMsg::Bank(BankMsg::Send { to_address: addrB, amount: [restricted denom] })` from a balance the contract itself holds (or one funded to it via `Instantiate`/`Execute` deposit, which also flows through `BankCoinTransferrer`).
3. `addrB` (not on the allow-list) calls `Execute` on the contract, or the contract sends to `addrB` directly.
4. Because `handler_plugin_encoders.go`'s `Bank` encoder produces a `MsgSend` that is applied via `k.bank.TransferCoins` (`BankCoinTransferrer`) rather than through `bank.msgServer.Send`, the transfer succeeds despite `addrB` not being in the denom's allow-list — whereas the same transfer attempted as a plain `MsgSend` transaction from a non-listed address would be rejected with `"is not allowed to receive funds"` as shown in the existing test: [6](#0-5)

// BankCoinTransferrer replicates the cosmos-sdk behaviour as in
// https://github.com/cosmos/cosmos-sdk/blob/v0.41.4/x/bank/keeper/msg_server.go#L26
type BankCoinTransferrer struct {
	keeper types.BankKeeper
}

func NewBankCoinTransferrer(keeper types.BankKeeper) BankCoinTransferrer {
	return BankCoinTransferrer{
		keeper: keeper,
	}
}

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
	for _, e := range em.Events() {
		if e.Type == sdk.EventTypeMessage { // skip messages as we talk to the keeper directly
			continue
		}
		parentCtx.EventManager().EmitEvent(e)
	}
	return nil
}

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (e MessageEncoders) Encode(ctx sdk.Context, contractAddr sdk.AccAddress, contractIBCPortID string, msg wasmvmtypes.CosmosMsg, info wasmvmtypes.MessageInfo, codeInfo types.CodeInfo) ([]sdk.Msg, error) {
	switch {
	case msg.Bank != nil:
		return e.Bank(contractAddr, msg.Bank)
	case msg.Custom != nil:
		return e.Custom(contractAddr, msg.Custom, info, codeInfo)
	case msg.Distribution != nil:
		return e.Distribution(contractAddr, msg.Distribution)
	case msg.IBC != nil:
		return EncodeIBCMsg(ctx, contractAddr, contractIBCPortID, msg.IBC)
	case msg.Staking != nil:
		return e.Staking(contractAddr, msg.Staking)
	case msg.Stargate != nil:
		return e.Stargate(contractAddr, msg.Stargate)
	case msg.Wasm != nil:
		return e.Wasm(contractAddr, msg.Wasm)
	case msg.Gov != nil:
		return EncodeGovMsg(contractAddr, msg.Gov)
	}
	return nil, sdkerrors.Wrap(types.ErrUnknownMsg, "unknown variant of Wasm")
}
