### Title
`update_finalized_payouts` trusts an unauthenticated OP_RETURN operator identity that is not covered by the withdrawal signature, letting an attacker mis-attribute reimbursement credit for a mined payout to a different, uninvolved operator - (File: core/src/verifier.rs)

### Summary
`Verifier::update_finalized_payouts` derives the "payer" operator solely from the OP_RETURN output of the mined payout transaction, and persists it via `update_payout_txs_and_payer_operator_xonly_pk` without checking that this pubkey corresponds to whoever actually supplied the funds that paid the withdrawal. The user's withdrawal authorization signature is `SIGHASH_SINGLE|ANYONECANPAY`, which covers only input 0 and output 0 (the user payout) - it leaves the OP_RETURN output (and any additional funding inputs added later by `TxSender`) completely unauthenticated, so any party able to observe/re-assemble the transaction can substitute an arbitrary xonly pubkey in the OP_RETURN.

### Finding Description
Binding claimed to hold: `payout_payer_operator_xonly_pk` recorded for withdrawal `idx` == the xonly pubkey of the operator whose funds actually paid `withdrawals[idx].output[0]`.

Trace:
- The withdrawal authorization signature is created with `TapSighashType::SinglePlusAnyoneCanPay` (see `sign_withdrawal_output` / `create_payout_txhandler`, `core/src/builder/transaction/operator_reimburse.rs:387-436`, `core/src/test/common/setup_utils.rs:499-543`). `SIGHASH_SINGLE` commits only to output index 0 (matching input index 0); `ANYONECANPAY` allows arbitrary extra inputs to be added. Consequently, neither the anchor output nor the OP_RETURN output (`op_return_txout(operator_xonly_pk)`, line 418) is covered by the user's signature. [1](#0-0) 
- The doc comment for `Operator::withdraw` explicitly states step 4 is "Funding the withdrawal transaction using TxSender RBF option," confirming that the actual BTC that pays the user's output amount is supplied by inputs added later by whichever party broadcasts/funds the transaction, not by the small pre-committed withdrawal UTXO alone. [2](#0-1) 
- When the payout is mined, `Verifier::update_finalized_payouts` parses only the chain-observed OP_RETURN bytes as the "payer_operator_xonly_pk" and writes it to the DB unconditionally - there is no check that this pubkey corresponds to the entity that funded the extra input(s) or otherwise has any provable relationship to the deposit/move-to-vault UTXO. [3](#0-2) 
- This value is persisted via `update_payout_txs_and_payer_operator_xonly_pk` and later consumed to determine which operator has an "unhandled payout" that should be reimbursed (`get_first_unhandled_payout_by_operator_xonly_pk`, `get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id`). [4](#0-3) 

Because the OP_RETURN bytes are not sighash-committed, an unprivileged attacker who observes a broadcast/mempool payout transaction (input 0 = the specific withdrawal UTXO, output 0 = the fixed user payout) can construct a modified transaction reusing the same signed input/output but substituting a different OP_RETURN xonly pubkey (naming operator B instead of the actual funder, operator A), and get it mined instead (e.g., by attaching a higher-fee funding input, exploiting `ANYONECANPAY`). `update_finalized_payouts` will then record operator B as the payer for this withdrawal even though B never funded it and has no relationship to the deposit.

The bridge circuit (`circuits-lib/src/bridge_circuit/mod.rs:206-229`) later re-extracts this same untrusted OP_RETURN value from the mined transaction and folds it into `deposit_constant`, which must match the value pre-committed for the *true* operator's presigned kickoff/round chain. Since the true funder's committed `operator_xonlypk` no longer matches what is now recorded on-chain, the true funder (A) can be locked out of reimbursement via this deposit while B is spuriously marked as the payer in the verifier's bookkeeping, even though B cannot actually complete a kickoff for a UTXO it does not control.

### Impact Explanation
- The DB linkage between a mined payout and its funding operator can be corrupted by any unprivileged attacker who can observe and re-broadcast a competing version of a payout transaction, because the OP_RETURN field is not covered by any signature.
- This can cause an honest operator (the true funder, A) to become permanently unable to be identified/reimbursed for a payout it fronted, since the on-chain OP_RETURN — which the bridge circuit and verifier both treat as authoritative — has been rewritten to name an unrelated operator (B). This matches the Critical impact category "an honest operator permanently unable to be reimbursed."
- It also pollutes the verifier's internal accounting (`get_first_unhandled_payout_by_operator_xonly_pk`) for operator B, who never touched this deposit/move UTXO.
- Repeatable across every deposit/withdrawal, limited only by the attacker's ability to win the propagation/fee race against the legitimate operator's broadcast.

### Likelihood Explanation
- Requires only mempool visibility (to see the withdrawal UTXO input/committed output before confirmation) and the ability to construct/broadcast a competing transaction with a higher fee (exploiting `ANYONECANPAY`) — well within the described unprivileged attacker capability set (can broadcast Bitcoin transactions, pay fees, craft scripts/OP_RETURN).
- No key compromise, no verifier/operator/aggregator privilege, and no majority hashrate needed — only a fee-based race to get the modified OP_RETURN version mined instead of (or racing) the operator's version.
- Cost is limited to Bitcoin transaction fees.

### Recommendation
Bind the OP_RETURN operator identity cryptographically to the actual funding of the payout, e.g., by requiring the operator to sign (with their own key, covering the OP_RETURN output) the full payout transaction, or by having `update_finalized_payouts`/the bridge circuit derive operator attribution from a value that is committed under the input signature (e.g., require `SIGHASH_ALL` for at least the OP_RETURN output, or bind operator identity via a separate presigned N-of-N/kickoff-linked commitment rather than an unauthenticated OP_RETURN).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_payout_info_from_move_txid(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        move_to_vault_txid: Txid,
    ) -> Result<Option<(Option<XOnlyPublicKey>, BlockHash, Txid, i32)>, BridgeError> {
        let query = sqlx::query_as::<_, (Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)>(
            "SELECT w.payout_payer_operator_xonly_pk, w.payout_tx_blockhash, w.payout_txid, w.idx
             FROM withdrawals w
             WHERE w.move_to_vault_txid = $1
               AND w.payout_txid IS NOT NULL
               AND w.payout_tx_blockhash IS NOT NULL",
        )
        .bind(TxidDB(move_to_vault_txid));

        let result: Option<(Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        result
            .map(|(operator_xonly_pk, block_hash, txid, deposit_idx)| {
                Ok((
                    operator_xonly_pk.map(|pk| pk.0),
                    block_hash.0,
                    txid.0,
                    deposit_idx,
                ))
            })
            .transpose()
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
