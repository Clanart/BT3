### Title
Silent, unconfirmed rewrite of a repository's remote URL from an attacker-controlled GitHub API response - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The bug-class in the Initia report is "a state-mutating operation was stripped of the guard/validation step that used to run before applying new parameters, so the mutation now blindly trusts new inputs and silently corrupts derived state." The closest verified Desktop analog is `updateRemoteUrl()`, which automatically rewrites a repository's Git `origin` remote URL based on the `clone_url` field of a `GitHubRepository` object fetched from the GitHub API, with only a loose owner/name/protocol equality check and no user confirmation.

### Finding Description
`updateRemoteUrl` is invoked from `repositoryWithRefreshedGitHubRepository()` every time Desktop refreshes the GitHub association for a repository (part of the routine background repository-indicator/refresh flow): [1](#0-0) 

The function itself performs the rewrite: [2](#0-1) 

The only checks gating the automatic call to `gitStore.setRemoteURL(...)` are:
1. `protocolsMatch` — a raw string comparison of `URL.parse().protocol` between the current remote and the new `apiRepo.clone_url`.
2. `remoteUrlUnchanged` — via `urlMatchesRemote`, which merely compares parsed `hostname`, `owner`, and `name` for case-insensitive equality: [3](#0-2) 

Neither check verifies that the new `clone_url` actually still points at the *same host* the user originally trusted — `urlMatchesRemote` is only used to confirm the *old* remote hasn't been manually changed, not to constrain the *new* URL. Once that passes, `gitStore.setRemoteURL` is called with `apiRepo.clone_url` verbatim, and the local `origin` remote is silently repointed: [4](#0-3) 

No dialog, confirmation, or diff of the change is shown to the user anywhere in this path.

### Impact Explanation
If an attacker can influence the `IAPIRepository.clone_url` value returned for a matched GitHub repository (e.g., a compromised or malicious GitHub Enterprise Server the user has already added as an account endpoint, or a MITM position capable of tampering with API responses over that endpoint), Desktop will automatically and silently repoint the user's `origin` remote to an attacker-chosen URL — as long as the URL scheme (`https`/`ssh`) matches. Because the rewrite happens transparently during routine background refresh, the user's next `git push`/`git fetch` will target the attacker's destination without any visual indication that the remote changed, satisfying the "silent corruption of what the user commits or pushes" impact class.

### Likelihood Explanation
This path triggers automatically on every periodic/background GitHub-repository refresh (`repositoryWithRefreshedGitHubRepository`), requiring no user action beyond having previously associated the repository with an account/endpoint that later serves a malicious API response. It does not require local access, admin rights, or prior malware — only that the attacker controls or can tamper with the GitHub API response for the matched repository (a condition explicitly allowed by the report's "attacker controls a GitHub API object" criterion). Likelihood is moderate: it depends on the attacker having sway over a GHES/API endpoint the victim already trusts, but the resulting mutation is entirely silent and unconfirmed.

### Recommendation
Reintroduce an explicit trust boundary before this kind of automatic mutation:
- Require the new `clone_url` to match the same hostname/origin as the existing remote (not just owner/name), rejecting cross-host rewrites outright.
- Surface a confirmation prompt to the user before silently changing `origin`'s URL, mirroring the manual "change remote URL" flow in `repository-settings.tsx`, rather than performing it unattended in `updateRemoteUrl`.
- Log/audit these automatic rewrites so users can detect unexpected remote changes.

### Proof of Concept
1. Add a GitHub Enterprise Server account in Desktop and clone a repository from it (`origin` → `https://ghes.example.com/org/repo.git`).
2. Compromise or MITM the GHES instance's `GET /api/v3/repos/org/repo` (or otherwise cause it to return) endpoint so the JSON response's `clone_url` is `https://ghes.example.com/attacker/evil-repo.git` (same host, same protocol, but different repo).
3. Wait for Desktop's periodic repository refresh to call `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`.
4. Because `protocolsMatch` is true and `remoteUrlUnchanged` (old clone URL vs. current remote) is true while `urlsMatch` (new clone URL vs. current remote) is false, `gitStore.setRemoteURL` fires automatically and silently rewrites `origin` to the attacker's URL.
5. The user's next push/fetch operates against `attacker/evil-repo` with no dialog ever having been shown. [5](#0-4) [6](#0-5)

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
