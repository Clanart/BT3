### Title
Unauthenticated force-association via `associatePubKey`/`associatePublicKey` allows any caller to remap a third party's direct-cast identity, orphaning staking/distribution state and risking a chain halt - (File: `precompiles/addr/addr.go`)

### Summary
The GitLab CVE allows an attacker to authenticate as another user by presenting only that user's *public key*, without proving possession of the corresponding private key. The `addr` precompile's `associatePublicKey` method (exposed on-chain as `associatePubKey`) has the analogous property: it derives an EVM/Sei address pair from a **raw public key supplied by the caller with no accompanying signature**, and then executes a full address-association / balance-migration flow for that address pair on behalf of the caller. Any transaction sender who merely *knows* someone else's public key (trivially obtainable from a broadcast Cosmos `AuthInfo.SignerInfos.PublicKey` or an ecrecover-able EVM signature) can trigger this state-mutating flow for a victim account they do not control.

### Finding Description
`PrecompileExecutor.associatePublicKey` in `precompiles/addr/addr.go` (mirrored in every `precompiles/addr/legacy/vXXX/addr.go`) takes a single hex-encoded compressed public key argument, parses it, and derives the corresponding `evmAddr`/`seiAddr` via `helpers.GetAddressesFromPubkeyBytes`, with **no signature check of any kind**: [1](#0-0) 

Contrast this with `associate` (the sibling method), which requires a v/r/s signature proving possession of the private key before performing the same derivation: [2](#0-1) 

Both paths funnel into `AssociationHelper.AssociateAddresses`, which performs privileged account mutations: it can overwrite the account record at `seiAddr` with the "cast address" account's number/sequence, sets the pubkey, and migrates balances from the direct-cast address (`sdk.AccAddress(evmAddr[:])`) to the pubkey-derived `seiAddr`, ultimately removing the cast-address account if its locked coins are zero: [3](#0-2) [4](#0-3) 

The codebase's own comments in `app/ante/evm_checktx.go` acknowledge exactly this danger class: an `associatePubKey` call can remap a "direct-cast" identity and **orphan staking/distribution state**, which can **halt the chain via the distribution validator-removal hook**. That risk was mitigated only for one specific path — EIP-7702 `SetCode` authorization authorities — by pre-associating them defensively before execution: [5](#0-4) 

However, `associatePublicKey`/`associatePubKey` is a **general-purpose, directly callable precompile method** reachable by any EVM transaction, for **any arbitrary public key** the caller chooses to supply — not limited to authorities inside the caller's own transaction. It is not gated by the same pre-association defense, and does not require the caller to prove ownership of the supplied key. This means the exact orphaning/chain-halt scenario the code explicitly guards against for `SetCode` authorities remains reachable through the general precompile entry point for any victim whose direct-cast address has accumulated staking/distribution-keeper state (e.g., used as a delegator or fee-distribution recipient before ever sending a native Sei or EVM tx that would self-associate).

### Impact Explanation
An unprivileged EVM caller can force an address association for any third-party account using only a public public key (no signature, no consent), triggering account/balance mutation logic (`AssociateAddresses`/`MigrateBalance`) that removes and reshapes account records at the cast address. Where that cast address carries staking/distribution state, the mutation can orphan state that the distribution module's validator-removal hook depends on, matching the chain-halt failure mode the maintainers explicitly identified and partially patched for `SetCode` authorities. A validator halt / chain split from an unhandled panic in the distribution hook constitutes a critical availability impact.

### Likelihood Explanation
Likelihood is moderate-to-high: public keys for Sei accounts are trivially public (broadcast in every Cosmos `AuthInfo`), and calling `associatePubKey` costs only normal EVM gas — no special privilege, no signature, no CosmWasm/tokenfactory permission is required. The main precondition (a victim's cast address holding staking/distribution-keeper state without ever self-associating) is a plausible, attacker-discoverable configuration and is exactly the scenario the project's own code comments call out as dangerous.

### Recommendation
Extend the existing pre-association defense pattern (used for `SetCode` authorities in `AssociateAuthorizationAuthorities`) to the general `associatePublicKey`/`associatePubKey` precompile path: either require a signature proving possession of the private key (as `associate` already does) before performing any state migration, or detect and safely handle the presence of staking/distribution state at the cast address before allowing `MigrateBalance`/`RemoveAccount` to proceed, so a chain halt cannot be triggered by remapping an account the caller does not control.

### Proof of Concept
1. Identify a victim Sei address `V` that has interacted only via its direct-cast EVM address (e.g., received a delegation reward or was set as a distribution withdraw address) but has never sent a native Cosmos or EVM tx to self-associate.
2. Obtain `V`'s Cosmos public key from any historical `AuthInfo.SignerInfos` on-chain (public data), or recover an EVM public key via `ecrecover` from any past signature.
3. As an unrelated attacker account, call `addr.associatePubKey(pubKeyHex)` on the `0x1004` precompile (`precompiles/addr/addr.go` `associatePublicKey`), supplying `V`'s public key bytes — no signature required.
4. `AssociateAddresses`/`MigrateBalance` executes, removing/remapping the cast-address account that held staking/distribution-keeper references, reproducing the orphaning condition the maintainers describe in `app/ante/evm_checktx.go` as capable of halting the chain via the distribution validator-removal hook.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// AssociateAuthorizationAuthorities pre-associates every EIP-7702 SetCode authorization
// authority in the transaction with its true (pubkey-derived) Sei address before EVM
// execution installs delegation code for it. Authorities are distinct accounts from the tx
// sender, so the sender association performed by the caller does not cover them. Without
// this, SetCode creates a mutable direct-cast EVM->Sei mapping that a later associatePubKey
// call can remap, orphaning any staking/distribution state created under the direct-cast
// identity (which can then halt the chain via the distribution validator-removal hook).
//
// This is the legacyabci counterpart of x/evm/ante's EVMPreprocessDecorator so both ante
// paths associate authorities identically. It is best-effort: only authorities whose
// authorization the EVM will actually apply are pre-associated — helpers.AuthorityToPreAssociate
// enforces the same chain-id/nonce/account-code checks go-ethereum uses, which also prevents
// replaying a publicly-visible authorization a user signed for another chain to force-associate
// them. Each association runs in its own cache context and is only committed on success, so an
// already-associated, skipped, or failing authority affects only itself and never rejects the
// transaction (matching go-ethereum, which would still accept it). Non-SetCode transactions
// carry no authorizations and are a no-op.
func AssociateAuthorizationAuthorities(ctx sdk.Context, ek *evmkeeper.Keeper, etx *ethtypes.Transaction) {
	auths := etx.SetCodeAuthorizations()
	if len(auths) == 0 {
		return
	}
	associateHelper := helpers.NewAssociationHelper(ek, ek.BankKeeper(), ek.AccountKeeper())
	for _, auth := range auths {
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, ek, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
}
