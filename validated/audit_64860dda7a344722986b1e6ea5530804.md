### Title
`ReceivedOutput::read`/`Output::read` deserialize a Bitcoin "received output" without ever checking the claimed key `offset` actually derives the output's `script_pubkey`, allowing fabricated/misattributed deposits - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class from the BurgerSwap report is a **missing consistency check on a state transition**: the pair contract removed the `x * y = k` invariant present in the upstream Uniswap code, so an attacker could trigger a swap whose "accounting" (the recorded reserves/output) did not correspond to any real transfer of value. Serai's Bitcoin scanner has the same shape: the binding between a key offset and a Taproot `script_pubkey` is only enforced inside `Scanner::register_offset`/`scan_transaction`, and is **never re-verified on the deserialization path** (`ReceivedOutput::read`, `Output::read`). An attacker who can feed bytes to that path can claim arbitrary balances are owned by arbitrary multisig keys.

### Finding Description
`Scanner::scan_transaction` is the only place a `ReceivedOutput` is legitimately produced: it looks up `output.script_pubkey` in the `scripts` map and attaches the `offset` that `register_offset` proved maps to that script (`key + offset*G → script_pubkey`) [1](#0-0) . `register_offset` guarantees that binding [2](#0-1) .

`ReceivedOutput::read`, however, deserializes `offset`, `output`, and `outpoint` completely independently, with no check that the offset is consistent with the script [3](#0-2) . The trust assumption is then consumed in `Output::key()`, which recomputes the owning multisig key as `script_key - offset*G` [4](#0-3) . `Output::read` likewise trusts the serialized `kind`, `presumed_origin`, `output`, and `data` fields [5](#0-4) , and downstream the scanner emits these as received balances (`balance()` returns `output.value()`) [6](#0-5) .

Because the offset is attacker-controlled on this path, an attacker can pick any scalar `o`, compute `K' = victim_multisig_key + o*G`, and encode `K'` into a fabricated `TxOut.script_pubkey`. `key()` then returns the victim multisig key, and `balance()`/`kind`/`data` report a deposit of arbitrary value and type under that key — funds that were never sent on-chain and whose `OutPoint` does not exist. This is exactly the BurgerSwap pattern: a "swap" (here, an output registration) accepted against reserves/state that were never verified.

### Impact Explanation
An unprivileged party able to supply bytes to `ReceivedOutput::read`/`Output::read` (a listed untrusted-bytes sink) can cause the processor to record a Bitcoin deposit that does not exist, attributed to a real multisig key with an arbitrary `OutputType`, presumed origin, value, and `data` payload. Depending on downstream handling, this fabricates credited balances / "funds reported received that are not spendable" (the outpoint is fake or unspendable by the claimed offset), or misattributes/griefs a real output by injecting a wrong offset so `key()` maps it to the wrong key — the scanner-side `assert_eq!(output.key(), key)` will then fault on otherwise honest data [7](#0-6) .

### Likelihood Explanation
Exploitation requires reaching the deserialization path rather than the scan path, so it is not open to a pure chain-only attacker who only sends Bitcoin transactions — a legitimately scanned output always carries a consistent offset. However, any path where these serialized outputs transit untrusted storage, network messages, or peer-supplied data exposes it; no authentication or MAC is present in the format. Within the Serai model where `read` sinks are treated as untrusted input, the fabrication cost is a single scalar multiplication and requires no private-key knowledge.

### Recommendation
Make the offset↔script binding intrinsic to `ReceivedOutput` rather than trusting the serialized offset:

- In `ReceivedOutput::read` (or a new `verify`/`check` method required before use), recompute `key + offset*G` for the expected base key and confirm `p2tr_script_buf(...) == output.script_pubkey`; alternatively store the base key inside `ReceivedOutput` and verify on read.
- In `Output::read` / `key()`, return `Option`/`Result` and reject offsets that do not reproduce the script for the claimed key instead of blindly subtracting `offset*G`.
- Derive `kind` from the offset via the `kinds` map at consumption time (as `get_outputs` already does) rather than trusting the serialized `kind` field [8](#0-7) .
- Consider authenticating persisted outputs (MAC or keyed hash) if they cross a trust boundary.

### Proof of Concept
1. Let `K_victim` be an even-parity registered multisig key (so `Scanner::new(K_victim)` succeeds).
2. Attacker chooses arbitrary `o ∈ F`, computes `K' = K_victim + o*G`, adjusts `o` until `p2tr_script_buf(K')` is `Some`, and builds `TxOut { script_pubkey: p2tr_script_buf(K'), value: <chosen amount> }` plus a fake `OutPoint`.
3. Serialize `ReceivedOutput { offset: o, output, outpoint }` and feed the bytes to `ReceivedOutput::read`, then wrap in `Output` with `kind = OutputType::External` and attacker `data`.
4. `output.key()` computes `K' - o*G = K_victim`, so the object presents as a deposit to `K_victim` of the chosen amount with attacker-controlled metadata — the scan-side consistency guarantee that would have prevented this (script lookup in `self.scripts`) was bypassed on the read path.

Note: I was not able to exhaustively verify every consumer of `Output::read` within the iteration budget; the finding holds wherever deserialized outputs are accepted without rescanning against a `Scanner` built from the registered key.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
