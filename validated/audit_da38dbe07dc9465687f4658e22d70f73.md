### Title
Gasless Swap Router Holds Unconditional, Node-Enforced Unlimited Token Approval That an Externally-Controlled Router Can Exploit to Siphon a Gasless User's Full Token Balance - (File: kaiax/gasless/impl/getter.go)

### Summary
The AAVE report describes an external, out-of-protocol contract (Aave's `RewardsController`) whose privileged party (the emission manager) can authorize third parties to withdraw value that the wrapping contract (`AaveV3YieldSource`) assumed only it could access, because the wrapper's own access-control checks are meaningless once bypassed at the external contract layer. The Kaia `kaiax/gasless` module has a structurally analogous trust dependency: the node's transaction-pool logic treats a `GaslessApproveTx` as valid/promotable specifically because it grants **unlimited (`MaxUint256`) ERC-20 allowance** to whatever address is currently recorded as `g.swapRouter`, and the node never re-validates how much of that allowance the router actually consumes beyond a single expected repay amount.

### Finding Description
`IsApproveTx`/`isApproveTx` require the approval's `spender` to equal the module's cached `g.swapRouter` and the `amount` to be exactly `abi.MaxUint256` before the tx pool will classify and promote it as part of a gasless bundle: [1](#0-0) 

The module refreshes `swapRouter` and `allowedTokens` by reading them from the on-chain `GaslessSwapRouter` system contract every block, i.e. these are externally-governed addresses outside of a single user's or the node's direct control: [2](#0-1) 

When the node validates the corresponding swap, it only checks amount/allowance/balance/deadline constraints for the `swapForGas` call itself, and computes the expected `AmountRepay`; it does not, and structurally cannot, constrain what the router contract does internally with the unlimited allowance once invoked: [3](#0-2)  and [4](#0-3) 

Because the on-chain `GaslessApproveTx` sets a real ERC-20 `approve(router, type(uint256).max)`, this approval remains active on-chain independent of the specific swap the node validated. Exactly as in the Aave case — where the yield-source contract's owner/manager restricted `claimRewards()` but the *external* `RewardsController`'s emission manager could designate any other authorized claimer, bypassing that restriction entirely — here the wrapping module (Kaia's gasless tx-pool logic) enforces careful checks on the *transaction it sees*, but the actual spending power over the user's full token balance is delegated to an external, protocol-governed `GaslessSwapRouter` contract. If that router's implementation/ownership is malicious, compromised, or is swapped to a different address by whatever authority manages the KIP-247 registry, it can call `transferFrom(user, router, fullBalance)` using the standing unlimited approval, independent of and unconstrained by the `AmountRepay`/`MinAmountOut` bounds the Kaia node validated at tx-pool level.

### Impact Explanation
A gasless user who signs a single `GaslessApproveTx` (required by protocol design to be `MaxUint256`) exposes their entire ERC-20 token balance to full-balance drainage by the swap router contract, not merely the intended swap/repay amount. This is a direct, unauthorized value-movement / theft vector reachable purely from an unprivileged, gasless end-user's own submitted transaction pair, matching the "gasless user" role explicitly permitted for this analog scan. The magnitude of loss (up to the user's entire token balance, since `amount == MaxUint256`) makes this a High-severity class of issue if the router address/ownership is ever compromised, misconfigured, or malicious governance is introduced — precisely the "malicious emission manager" scenario in the original report, transplanted to Kaia's router-authorization model.

### Likelihood Explanation
Likelihood is contingent on the security of the externally-governed `GaslessSwapRouter` contract and whoever can update or own it — this is not verifiable purely from the Kaia node repository, since the router's Solidity source and its access-control/upgrade mechanism live outside `kaiax/gasless` (only the ABI binding was found: `contracts/bindings/kip247/GaslessSwapRouter.go`). What is certain and verifiable in-repo is that the node protocol design mandates an unlimited (`MaxUint256`) approval as a hard precondition for gasless-tx recognition, with no cap tied to the actual swap amount, which is the root architectural condition enabling this class of attack once the router is compromised or misconfigured.

### Recommendation
- Do not require `amount == MaxUint256` for `GaslessApproveTx` classification; instead, require the approved amount to be tightly bounded (e.g., equal to or slightly above `AmountIn`/`AmountRepay` for the specific paired swap), so a compromised or malicious router can drain at most the intended swap amount.
- If unlimited approvals must remain supported for UX reasons, ensure the `GaslessSwapRouter` contract itself has hardened, ideally immutable or timelocked, ownership/upgrade paths, and that the KIP-247 registry governance changing `swapRouter` cannot be executed unilaterally by a single privileged key.
- Add a strict node-side re-check that any observed `transferFrom` executed by the router during block execution does not exceed the exact `AmountIn` declared in the paired `GaslessSwapTx`.

### Proof of Concept
1. A gasless user signs and submits `GaslessApproveTx = approve(swapRouter, type(uint256).max)` on token `T`, satisfying `IsApproveTx` conditions A1–A4 [1](#0-0) .
2. The user pairs it with a legitimate `GaslessSwapTx = swapForGas(T, amountIn, minAmountOut, amountRepay, deadline)`, which the node validates and bundles per `VerifyExecutable`/`checkBalanceForSwap` [3](#0-2) [4](#0-3) .
3. Both transactions execute; on-chain, token `T` now shows an unlimited (`MaxUint256`) live allowance from the user to `swapRouter`, independent of the one bundled swap.
4. At any later block, if the `swapRouter` address is a malicious/compromised contract (or the router that received governance authorization from the KIP-247 registry misbehaves), it calls `T.transferFrom(user, attacker, T.balanceOf(user))` directly, draining the user's entire balance of token `T` — far beyond the `amountIn`/`amountRepay` the Kaia gasless module validated.

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
