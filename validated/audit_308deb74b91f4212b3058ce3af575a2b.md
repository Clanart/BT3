I've confirmed the key comparison. The `PoolWallet.claim_pool_rewards` implementation explicitly limits reward claims per transaction via `max_spends_in_tx`/`DEFAULT_MAX_CLAIM_SPENDS`, while the newer `PlotNFT2Wallet.claim_rewards` has no such mechanism.

### Title
`PlotNFT2Wallet.claim_rewards` cannot claim pool rewards in batches, unlike `PoolWallet`, risking oversized transactions that exceed block cost limits - (File: chia/wallet/plotnft_wallet/plotnft_wallet.py)

### Summary
`PlotNFT2Wallet.claim_rewards` fetches every accumulated, unclaimed pool reward coin for a PlotNFT and builds a single spend bundle claiming all of them at once. It provides no parameter to limit the number of reward coins included per transaction, unlike the legacy `PoolWallet.claim_pool_rewards`, which explicitly supports batching via `max_spends_in_tx`.

### Finding Description
`PlotNFT2Wallet.claim_rewards` calls `get_pool_rewards(plotnft_id=self.plotnft_id)` to retrieve *all* outstanding reward coins for the PlotNFT, with no cap, and then builds one `coin_spends` list containing the singleton claim spend plus one `CoinSpend` per reward coin via `plotnft.claim_pool_rewards(rewards_to_claim=rewards_to_claim, ...)`. [1](#0-0) 

Compare this to the older, still-present `PoolWallet.claim_pool_rewards`, which explicitly caps the number of reward coins absorbed per transaction using `max_spends_in_tx` (defaulting to `DEFAULT_MAX_CLAIM_SPENDS`), and truncates/logs when the limit is hit so the resulting `SpendBundle` fits into a block: [2](#0-1) 

`PWAbsorbRewards` RPC dispatches to either implementation depending on wallet type, and only forwards `max_spends_in_tx` to `PoolWallet`, not to `PlotNFT2Wallet`: [3](#0-2) 

The design intent for pooling reward claims is explicitly to support batching so that a large backlog of reward coins does not overflow a single spend bundle's CLVM cost or transaction size (this is precisely the mechanism the `test_absorb_self_multiple_coins` test exercises with `max_spends_in_tx=uint16(1)`): [4](#0-3) 

`PlotNFT2Wallet.claim_rewards` has no equivalent safeguard. Every reward coin gets its own `AssertCoinAnnouncement`/`SendMessage`-linked spend chained off the singleton claim spend, so cost scales linearly with the number of unclaimed reward coins. If a PlotNFT accumulates enough farming rewards without being claimed (e.g., the owner is offline, has low liquidity to pay fees, or simply forgets), the resulting transaction can grow past the mempool/block CLVM cost limit, and there is no code path to claim only a subset — the caller cannot pass a smaller batch, since `claim_rewards` always claims everything returned by `get_pool_rewards`.

### Impact Explanation
This is a spend-triggered transaction-processing halt for the affected wallet's reward-claim path: once enough unclaimed reward coins accumulate on a `PlotNFT2Wallet`, `claim_rewards` produces a spend bundle whose CLVM execution cost can exceed `MAX_BLOCK_COST_CLVM`, causing the transaction to be permanently rejected by the mempool/consensus rules. Since there is no batching parameter, the user has no way to claim a subset of rewards to work around this — the reward coins become effectively unclaimable through the normal `pw_absorb_rewards` RPC / `claim_rewards` wallet API, unlike with `PoolWallet` where `max_spends_in_tx` allows recovery by claiming in smaller batches. This is a design regression relative to the legacy pool wallet and directly matches the reported bug class of "cannot settle/claim assets in pieces."

### Likelihood Explanation
Likelihood increases naturally over time for any actively self-pooled or pooled `PlotNFT2Wallet` whose owner does not claim promptly — reward coins accumulate automatically from block rewards, and no explicit adversarial action from another party is required. A user (or automation) that delays claiming, or that plots at scale, can passively reach the point where `claim_rewards` produces an oversized bundle purely through normal operation.

### Recommendation
Add a `max_spends_in_tx`-style parameter to `PlotNFT2Wallet.claim_rewards` (and the corresponding `pw_absorb_rewards` dispatch path in `wallet_rpc_api.py`) mirroring `PoolWallet.claim_pool_rewards`, so that reward coins can be claimed across multiple transactions when the accumulated count would otherwise produce a spend bundle exceeding safe block cost, and surface a limit/truncation similar to `DEFAULT_MAX_CLAIM_SPENDS`.

### Proof of Concept
1. Configure a `PlotNFT2Wallet` in self-custody or pooling mode and let it farm many blocks without ever calling `pw_absorb_rewards`, so `plotnft2_store` accumulates a large number of unclaimed `PoolReward` coins tied to `self.plotnft_id`.
2. Call `PlotNFT2Wallet.claim_rewards(action_scope=..., fee=...)` (or the `pw_absorb_rewards` RPC on a `PlotNFT2Wallet`); observe that `rewards_to_claim = get_pool_rewards(...)` returns the entire unclaimed set with no limit, and `plotnft.claim_pool_rewards` builds one `CoinSpend` per reward plus the singleton spend in a single `WalletSpendBundle` [5](#0-4) .
3. As the reward count grows, the resulting bundle's CLVM cost (singleton claim puzzle cost plus per-reward `claim_pool_rewards_dpuz`/message costs) will approach and eventually exceed `MAX_BLOCK_COST_CLVM`, causing mempool submission to fail with no way to retry a smaller batch, in contrast to `PoolWallet.claim_pool_rewards`'s `max_spends_in_tx` truncation behavior verified by `test_absorb_self_multiple_coins` [6](#0-5) .

    async def claim_pool_rewards(
        self, fee: uint64, max_spends_in_tx: int | None, action_scope: WalletActionScope
    ) -> None:
        # Search for p2_puzzle_hash coins, and spend them with the singleton
        if await self.have_unconfirmed_transaction():
            raise ValueError(
                "Cannot claim due to unconfirmed transaction. If this is stuck, delete the unconfirmed transaction."
            )

        if max_spends_in_tx is None:
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS
        elif max_spends_in_tx <= 0:
            self.log.info(f"Bad max_spends_in_tx value of {max_spends_in_tx}. Set to {self.DEFAULT_MAX_CLAIM_SPENDS}.")
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS

        unspent_coin_records = await self.wallet_state_manager.coin_store.get_unspent_coins_for_wallet(self.wallet_id)
        if len(unspent_coin_records) == 0:
            raise ValueError("Nothing to claim, no transactions to p2_singleton_puzzle_hash")
        farming_rewards: list[TransactionRecord] = await self.wallet_state_manager.tx_store.get_farming_rewards()
        coin_to_height_farmed: dict[Coin, uint32] = {}
        for tx_record in farming_rewards:
            height_farmed: uint32 | None = tx_record.height_farmed(
                self.wallet_state_manager.constants.GENESIS_CHALLENGE
            )
            assert height_farmed is not None
            coin_to_height_farmed[tx_record.additions[0]] = height_farmed
        history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
        assert len(history) > 0
        delayed_seconds, delayed_puzhash = get_delayed_puz_info_from_launcher_spend(history[0][1])
        current_state: PoolWalletInfo = await self.get_current_state()
        last_solution: CoinSpend = history[-1][1]

        all_spends: list[CoinSpend] = []
        total_amount = 0

        # The coins being claimed are gathered into the `SpendBundle`, :absorb_spend:
        # We use an announcement in the fee spend to ensure that the claim spend is spent in the same block as the fee
        # We only need to do this for one of the coins, because each `SpendBundle` can only be spent as a unit

        first_coin_record = None
        for coin_record in unspent_coin_records:
            if coin_record.coin not in coin_to_height_farmed:
                continue
            if first_coin_record is None:
                first_coin_record = coin_record
            if len(all_spends) >= max_spends_in_tx:
                # Limit the total number of spends, so the SpendBundle fits into the block
                self.log.info(f"pool wallet truncating absorb to {max_spends_in_tx} spends to fit into block")
                print(f"pool wallet truncating absorb to {max_spends_in_tx} spends to fit into block")
                break
            absorb_spend: list[CoinSpend] = create_absorb_spend(
                last_solution,
                current_state.current,
                current_state.launcher_coin,
                coin_to_height_farmed[coin_record.coin],
                self.wallet_state_manager.constants.GENESIS_CHALLENGE,
                delayed_seconds,
                delayed_puzhash,
            )
            last_solution = absorb_spend[0]
            all_spends += absorb_spend
            total_amount += coin_record.coin.amount
            self.log.info(
                f"Farmer coin: {coin_record.coin} {coin_record.coin.name()} {coin_to_height_farmed[coin_record.coin]}"
            )
        if len(all_spends) == 0 or first_coin_record is None:
            raise ValueError("Nothing to claim, no unspent coinbase rewards")

    async def pw_absorb_rewards(
        self,
        request: PWAbsorbRewards,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> PWAbsorbRewardsResponse:
        """Perform a sweep of the p2_singleton rewards controlled by the pool wallet singleton"""
        wallet = self.service.wallet_state_manager.wallets[request.wallet_id]

        if isinstance(wallet, PoolWallet):
            async with self.service.wallet_state_manager.lock:
                await wallet.claim_pool_rewards(request.fee, request.max_spends_in_tx, action_scope)
                state: PoolWalletInfo = await wallet.get_current_state()
        elif isinstance(wallet, PlotNFT2Wallet):
            await wallet.claim_rewards(action_scope=action_scope, fee=request.fee, extra_conditions=extra_conditions)
            state = await wallet.get_current_state()
        else:
            raise ValueError("`pw_absorb_rewards` called on a non-pooling wallet")

        return PWAbsorbRewardsResponse(
            unsigned_transactions=[],
            transactions=[],
            state=state,
            transaction=REPLACEABLE_TRANSACTION_RECORD,
            fee_transaction=REPLACEABLE_TRANSACTION_RECORD,
        )
