### Title
Scanner reports sub-dust / uneconomical outputs as spendable ReceivedOutputs, locking credited funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` matches outputs solely by `script_pubkey` and returns every matching output as a `ReceivedOutput` ("a spendable output"), with no check on the output's value. An unprivileged third party can send outputs to any of the scanner's registered P2TR script keys with a value below the dust threshold (or below the fee required to spend them). These outputs are reported as received/spendable funds, yet cannot actually be spent — they are either non-standard to relay as an input's economic basis or cost more in fees than they are worth, permanently locking the credited value with no benefit, analogous to the Illuminate premium being locked until maturity with no yield.

### Finding Description
`scan_transaction` iterates `tx.output`, looks up `output.script_pubkey` in `self.scripts`, and unconditionally pushes a `ReceivedOutput` for any match [1](#0-0) . `ReceivedOutput` is defined as "a spendable output" and exposes `value()` [2](#0-1) . There is no minimum-value or dust filter anywhere in the scan path, unlike `SignableTransaction::new` which does enforce a `DUST` floor for payments and change [3](#0-2) . When such an output is later fed into `SignableTransaction::new` as an input, its full value is counted into `input_sat` and consumed [4](#0-3) , while each input adds ~57 vbytes of fee cost — so a 546–~10k sat input (or a sub-546 sat input which standardness won't even relay spending) contributes less than it costs to include, effectively burning or locking the credited balance.

### Impact Explanation
Funds are reported received that are not spendable: an attacker dusts the wallet/registered offset addresses with tiny-valued outputs. The scanner credits them as spendable `ReceivedOutput`s, inflating the apparent balance, but spending them yields zero or negative net value — the credited amount is locked with no profit/benefit, exactly the Illuminate pattern (premium locked in the contract rather than refunded). At scale, forced inclusion of these inputs also inflates fees, transferring the loss to fee overpayment.

### Likelihood Explanation
Reachable by any unprivileged party: the P2TR script keys are public (derived from the public group key via `Scanner::new`/`register_offset`), and anyone can send a Bitcoin transaction paying to them [5](#0-4) . The cost to the attacker is only the dust amounts sent. Exploitation requires the integrator/processor to feed scanned outputs into transaction construction, which is the intended flow.

### Recommendation
In `Scanner::scan_transaction`, filter outputs whose `value.to_sat()` is below the spendable dust/economic threshold (mirroring the `DUST`/`N::DUST` constants used elsewhere), or expose the value check to callers and document that `ReceivedOutput`s below it are unspendable and must not be used as inputs. `SignableTransaction::new` should additionally reject or handle input values below the dust threshold rather than counting them toward `input_sat` and paying their inclusion cost.

### Proof of Concept
1. Wallet publishes its P2TR address; attacker learns `p2tr_script_buf(key)` script.
2. Attacker broadcasts a TX paying `output.script_pubkey = <registered script>` with `value = 400` sats (below `DUST = 546`) — minable but uneconomical to spend.
3. `Scanner::scan_transaction` returns `ReceivedOutput { offset, output(400 sats), outpoint }` — reported as spendable.
4. Wallet aggregates `input_sat` including the 400 sats; spending it requires ~57 vbytes of fee (≥ 57 sats at 1 sat/vb, more at realistic rates), and at 400 sats it is also non-standard as a created output — the credited balance can never be realized as profit; it is locked or burned as fee.

/// A spendable output.
#[derive(Clone, PartialEq, Eq, Debug)]
pub struct ReceivedOutput {
  // The scalar offset to obtain the key usable to spend this output.
  offset: Scalar,
  // The output to spend.
  output: TxOut,
  // The TX ID and vout of the output to spend.
  outpoint: OutPoint,
}

impl ReceivedOutput {
  /// The offset for this output.
  pub fn offset(&self) -> Scalar {
    self.offset
  }

  /// The Bitcoin output for this output.
  pub fn output(&self) -> &TxOut {
    &self.output
  }

  /// The outpoint for this output.
  pub fn outpoint(&self) -> &OutPoint {
    &self.outpoint
  }

  /// The value of this output.
  pub fn value(&self) -> u64 {
    self.output.value.to_sat()
  }

  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
