### Title
Identity group elements are accepted as encryption keys and Schnorr PoP public keys, enabling forged proofs and publicly decryptable DKG shares - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
PedPoP accepts canonical group encodings without rejecting the identity element. An unprivileged DKG participant can register the identity as its encryption public key, causing every sender's ECDH result to be the publicly known identity point. Separately, a sender can use an identity per-message key with the trivial forged Schnorr proof `(R = identity, s = 0)`, which always satisfies the verifier.

### Finding Description
`Ciphersuite::read_G` checks only that a supplied encoding is a valid, canonical group element; it does not reject the identity element. [1](#0-0)  `EncryptionKeyMessage::read` passes the attacker-controlled encryption key through `read_G`, and `Decryption::register` stores it without a non-identity check. [2](#0-1) [3](#0-2) 

During share encryption, the sender computes `msg_key * registered_key`; if the registered key is identity, the ECDH result is identity regardless of the random message key. [4](#0-3) [5](#0-4)  The ChaCha20 stream is deterministically derived from the public DKG context and that ECDH point, so identity produces a keystream computable by any observer. [6](#0-5) 

`EncryptedMessage::read` also accepts an attacker-controlled per-message key and Schnorr PoP without rejecting identity. [7](#0-6)  Schnorr verification accepts the statement `R + cA - sG = identity`; with `A = R = identity` and `s = 0`, it passes for every challenge. [8](#0-7)  `decrypt` queues this PoP and performs ECDH with the supplied message key, so the same identity point produces the decryption stream. [9](#0-8) 

### Impact Explanation
A participant who registers the identity encryption key causes all honest participants to encrypt that participant's polynomial shares under a publicly known ECDH point. Anyone who obtains the serialized DKG traffic can derive the cipher and recover each plaintext `SecretShare`, then sum them to recover that participant's final threshold key share. [10](#0-9) [11](#0-10) 

The identity PoP is additionally a forged proof-of-possession: it proves control of no scalar, yet is accepted by the Schnorr verification equation. [12](#0-11)  Since the PoP is intended to prevent parties from claiming encryption keys they do not control, accepting the trivial proof breaks that security property. [13](#0-12) 

### Likelihood Explanation
The attack only requires an unprivileged DKG participant to send malformed protocol bytes containing a canonical identity encoding. [2](#0-1)  No discrete logarithm, private key, validator privilege, or protocol collusion is needed: `identity` and scalar zero are fixed public values, and the forged Schnorr proof is valid for every challenge. [8](#0-7) 

### Recommendation
Reject identity and any other invalid low-order/non-canonical semantic encodings when reading public keys and proof points. Specifically:

- In `EncryptionKeyMessage::read`, reject `enc_key.is_identity()`.
- In `EncryptedMessage::read`, reject `key.is_identity()` and reject identity `R` or zero `s` in the Schnorr PoP where the scheme requires a non-trivial proof.
- Prefer enforcing non-identity public keys at the protocol layer rather than changing `Ciphersuite::read_G`, since identity is a valid group element and may be legitimate in other contexts.
- Add regression tests for identity registration keys and the forged `(R = identity, s = 0)` PoP through `EncryptedMessage::read` and `calculate_share`.

### Proof of Concept
For a target ciphersuite `C`, let `I = C::G::identity().to_bytes()` be its canonical identity encoding.

1. **Publicly decryptable share path:** A malicious participant sends an `EncryptionKeyMessage` whose final point field is `I`. `EncryptionKeyMessage::read` accepts it and `register` stores it. [2](#0-1) [3](#0-2)  Every honest sender computes `random_msg_key * I = I`, derives `cipher(context, I)`, and encrypts a secret share. An observer can derive the same `cipher(context, I)` and recover the plaintext share. [14](#0-13) 

2. **Forged per-message PoP:** Serialize an `EncryptedMessage` containing:
   - `key = I`
   - `pop.R = I`
   - `pop.s = 0`
   - any correctly sized encrypted `SecretShare`

   `EncryptedMessage::read` accepts the structure. [7](#0-6)  The queued verification statement becomes `I + cI - 0G = I`, so it passes for every `c`, including the transcript-derived challenge. [8](#0-7)  The recipient's ECDH is also `recipient_secret * I = I`, so both recipient and observer derive the same public cipher. [15](#0-14)

// leaked.
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {

  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);

  /// Return the series of pairs whose products sum to zero for a valid signature.
  /// This is intended to be used with a multiexp.
  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
  }

  /// Queue a signature for batch verification.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  pub fn batch_verify<R: RngCore + CryptoRng, I: Copy + Zeroize>(
    &self,
    rng: &mut R,
    batch: &mut BatchVerifier<I, C::G>,
    id: I,
    public_key: C::G,
    challenge: C::F,
  ) {
    batch.queue(rng, id, self.batch_statements(public_key, challenge));
