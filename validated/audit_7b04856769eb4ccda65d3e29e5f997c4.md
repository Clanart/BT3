### Title
Uncaught IndexError from missing bounds check in CLVM atom length-prefix parsing during DEDUP canonical-form validation - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` parses a CLVM atom's variable-length size prefix (1–6 bytes depending on the atom's leading byte) but never verifies that the buffer actually contains enough trailing bytes for the prefix length it decodes, mirroring the FRR BGP OPEN parser bug in CVE-2022-40302 where a boundary check assumed a smaller read (2 bytes) than what the 0xFF extended-length case actually required (3 bytes). [1](#0-0) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` inspects `clvm_buffer[offset]` and, based on the high bits, decides `prefix_len` (0 to 5 extra bytes) representing how many additional length bytes must be read: [2](#0-1) 

It then unconditionally loops `prefix_len` times, incrementing `offset` and reading `clvm_buffer[offset]` each time, without ever checking that `offset` stays within `len(clvm_buffer)`: [3](#0-2) 

This is invoked from `is_clvm_canonical()`, which walks a CLVM-serialized buffer token by token and calls `is_atom_canonical()` whenever it encounters an atom whose leading byte is `> 0x80`: [4](#0-3) 

If an attacker crafts a solution/puzzle-reveal buffer whose final bytes are, e.g., `0xFC` (the 6-byte / 5-extra-byte prefix marker) followed by fewer than 5 trailing bytes, `is_atom_canonical()` will index past the end of `clvm_buffer`. Unlike the C-array/pointer read in the FRR case, Python `bytes` indexing raises `IndexError` on out-of-range access rather than silently reading adjacent memory — but the effect on availability is the same class of bug: an inconsistent boundary check that does not account for the true number of bytes needed for the largest length-prefix encoding, leading to an unhandled exception instead of a graceful "not canonical" rejection.

Per the repository's own documentation, this canonical-form check gates DEDUP eligibility for mempool spends — i.e., it runs on buffers derived from attacker-supplied `CoinSpend.solution`/puzzle-reveal data during mempool processing of a submitted spend bundle: [5](#0-4) 

### Impact Explanation
An unhandled `IndexError` raised deep inside mempool spend-bundle processing (canonical-form/DEDUP-eligibility checking) is a spend-triggered transaction-processing halt: a single malicious but otherwise well-formed spend bundle can crash or abort the code path handling `pre_validate_spendbundle`/DEDUP eligibility determination for that mempool worker, denying service to the mempool/full node in a manner directly analogous to the FRR daemon crash triggered by the CVE's crafted BGP OPEN option.

### Likelihood Explanation
Any unprivileged spend-bundle submitter can construct a solution/puzzle-reveal CLVM buffer whose last atom uses the largest length-prefix encoding (`0xFC`..) truncated so that fewer than 5 trailing bytes remain, satisfying only the reachability requirement of getting the bundle far enough into mempool processing for DEDUP eligibility / canonical-form checking to run against it.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before reading each of the `prefix_len` extra bytes (verify `offset < len(clvm_buffer)` prior to each `clvm_buffer[offset]` access, mirroring the length-check pattern already used elsewhere in this codebase, e.g. `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`), and raise a caught/expected error (or return "not canonical") instead of letting an `IndexError` propagate out of mempool processing. [6](#0-5) 

### Proof of Concept
Construct a CLVM buffer ending in a truncated 6-byte atom-length prefix, e.g. a single top-level atom encoded as `b"\xfc\x01\x02"` (marker `0xFC` declares 5 additional length bytes must follow, but only 2 are present), and pass it to `is_clvm_canonical()`:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
is_clvm_canonical(b"\xfc\x01\x02")  # raises IndexError instead of returning False
```
This reproduces the out-of-bounds access pattern analogous to CVE-2022-40302's inconsistent 0xFF extended-length boundary check.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
