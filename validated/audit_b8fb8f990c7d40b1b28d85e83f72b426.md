### Title
Failed clawback claim leaves the incoming transaction permanently marked "sent", auto-claim stops retrying it - (File: chia/wallet/clawback_manager.py)

### Summary
`ClawbackManager.spend_clawback_coins` marks the *original incoming* clawback transaction record as "sent" before the actual claim spend bundle is confirmed, and this bookkeeping flag is never reset if the claim spend fails to reach the mempool or is never confirmed. This mirrors the reported bug class: a state counter/flag that is supposed to gate re-processing is updated too early (or not updated/reset at the right point), so a legitimate subsequent action (auto-claim / rebalance-equivalent) is permanently blocked without operator intervention.

### Finding Description
For each clawback coin being claimed, before the claim spend bundle is even built into a pushable transaction, the manager unconditionally calls: [1](#0-0) 

This sets `incoming_tx.sent = 1` and records a `PENDING` entry in `sent_to` on the *original* incoming clawback transaction record (the record created when the clawback coin was first observed, with `spend_bundle=None`): [2](#0-1) 

A brand-new, separate `TransactionRecord` (type `OUTGOING_CLAWBACK`) carrying the real `spend_bundle` is only created afterward and appended to the action-scope side effects: [3](#0-2) 

The wallet node's resend/retry machinery (`_messages_to_resend`, `get_not_sent`) only resends and retries records that have a non-null `spend_bundle` and `confirmed=0`: [4](#0-3) [5](#0-4) 

Because `incoming_tx.spend_bundle` is `None`, this "bookkeeping" record is never resent, never re-evaluated by `is_valid()`, and its `sent` counter is never reset by the retry loop, `tx_reorged`, or any other automatic mechanism found in the wallet code.

Meanwhile, every future automatic claim attempt (`auto_claim_coins`, which runs on a schedule) is explicitly gated by that same flag: [6](#0-5) [7](#0-6) 

If the constructed claim `spend_bundle` (built later in the same function, after `increment_sent` has already run) never gets included — e.g., it fails validation, is dropped from the mempool for insufficient fee, the wallet is restarted before the new `OUTGOING_CLAWBACK` transaction is pushed, or an exception occurs anywhere between `increment_sent()` and the actual push — `incoming_tx.sent` stays permanently `> 0`. Every subsequent `auto_claim_coins()` cycle will silently skip that coin forever (`self.log.error(...); continue`), and the funds become unclaimable through the automatic path. The user's only recourse is to notice this and manually call `spend_clawback_coins` with `force=True` via RPC/CLI.

This is structurally the same defect class as the reported EigenLayer issue: a "claimed/queued" state flag is set at the start of an operation that can subsequently fail, and nothing rolls that flag back or advances it correctly on failure, so the automatic reprocessing mechanism becomes permanently blocked for that item.

### Impact Explanation
A user relying on the auto-claim feature for received clawback coins can have those coins get stuck in limbo: the wallet believes it "already submitted" the claim and will not retry automatically, even though no spend was ever confirmed on-chain and the coin remains unspent and unclaimed. This effectively locks the user's funds behind a silent state desync until a manual, undocumented force-resubmit is performed — a self-inflicted denial of ordinary wallet functionality (auto-claim) reachable purely by a local wallet user's own normal-looking failed transaction (e.g. fee too low, node briefly disconnected, wallet restarted mid-flow).

### Likelihood Explanation
Moderately likely: any of several common, non-malicious conditions (fee too low causing repeated `INVALID_FEE_LOW_FEE` mempool rejections until `is_valid()` gives up marking the tx "confirmed but failed", a wallet restart between `increment_sent()` and the push of the built spend bundle, or an exception thrown mid-way through the batched claim loop) can leave `incoming_tx.sent > 0` without a corresponding confirmed on-chain spend. Because auto-claim runs unattended and periodically, this is a realistic operational hazard rather than a contrived edge case.

### Recommendation
Do not mark the incoming transaction as "sent"/pending until the actual claim spend bundle has been successfully constructed and is confirmed to have entered the mempool (or is being tracked by the standard resend/retry mechanism tied to a real `spend_bundle`). Alternatively, tie the "already claimed" gate to the state of the new `OUTGOING_CLAWBACK` transaction record (which does have a `spend_bundle` and is properly retried/invalidated) rather than to a synthetic increment on the spend-bundle-less incoming record, and add reconciliation logic so that if the outgoing claim transaction is marked invalid/failed (`is_valid() == False`) or never created, the incoming transaction's `sent` counter is reset so `auto_claim_coins` can retry it.

### Proof of Concept
1. Receive a clawback coin (recipient side); the wallet stores an `INCOMING_CLAWBACK_RECEIVE` `TransactionRecord` for it with `spend_bundle=None`, `sent=0`.
2. Trigger a claim, e.g. via `auto_claim_coins()` or `spend_clawback_coins` RPC, but arrange for the resulting `OUTGOING_CLAWBACK` spend bundle to fail to be included (e.g. submit with a fee below the mempool minimum, or kill/restart the wallet node right after `spend_clawback_coins` returns but before the transaction reaches the peer).
3. Observe that `incoming_tx.sent` is now `1` (set inside the loop in `spend_clawback_coins` at [8](#0-7) ) while the clawback coin remains unspent on-chain.
4. Call `auto_claim_coins()` again (or wait for its scheduled run): the coin is skipped because `incoming_tx.sent > 0 and not force` at [9](#0-8) , and it will be skipped on every future automatic cycle, requiring a manual `force=True` call to unstick it.

    async def auto_claim_coins(self, action_scope: WalletActionScope) -> None:
        # Get unspent clawback coin
        current_timestamp = self.blockchain.get_latest_timestamp()
        clawback_coins: dict[Coin, ClawbackMetadata] = {}
        unspent_coins = await self.coin_store.get_coin_records(
            coin_type=CoinType.CLAWBACK,
            wallet_type=WalletType.STANDARD_WALLET,
            spent_range=UInt32Range(stop=uint32(0)),
            amount_range=UInt64Range(
                start=action_scope.config.tx_config.coin_selection_config.min_coin_amount,
                stop=action_scope.config.tx_config.coin_selection_config.max_coin_amount,
            ),
        )

        for coin in unspent_coins.records:
            try:
                metadata = coin.parsed_metadata()
                assert isinstance(metadata, ClawbackMetadata)
                if await metadata.is_recipient(self.puzzle_store):
                    coin_timestamp = await self.timestamp_for_height(coin.confirmed_block_height)
                    if current_timestamp - coin_timestamp >= metadata.time_lock:
                        clawback_coins[coin.coin] = metadata
                        if len(clawback_coins) >= self.auto_claim_batch_size:
                            await self.spend_clawback_coins(clawback_coins, self.auto_claim_tx_fee, action_scope)
                            clawback_coins = {}
            except Exception as e:
                self.log.error(f"Failed to claim clawback coin {coin.coin.name().hex()}: %s", e)
        if len(clawback_coins) > 0:
            await self.spend_clawback_coins(clawback_coins, self.auto_claim_tx_fee, action_scope)

    async def _messages_to_resend(self) -> list[tuple[Message, set[bytes32]]]:
        if self._wallet_state_manager is None or self._shut_down:
            return []
        messages: list[tuple[Message, set[bytes32]]] = []

        current_time = int(time.time())
        retry_accepted_txs = False
        if self.last_wallet_tx_resend_time < current_time - self.wallet_tx_resend_timeout_secs:
            self.last_wallet_tx_resend_time = current_time
            retry_accepted_txs = True
        records: list[TransactionRecord] = await self.wallet_state_manager.tx_store.get_not_sent(
            include_accepted_txs=retry_accepted_txs
        )

        for record in records:
            if record.spend_bundle is None:
                continue
            msg = make_msg(ProtocolMessageTypes.send_transaction, SendTransaction(record.spend_bundle))
            already_sent = set()
            for peer, status, _ in record.sent_to:
                if status in {MempoolInclusionStatus.SUCCESS.value, MempoolInclusionStatus.FAILED.value}:
                    already_sent.add(bytes32.from_hexstr(peer))
            messages.append((msg, already_sent))

        return messages

    async def get_not_sent(self, *, include_accepted_txs=False) -> list[TransactionRecord]:
        """
        Returns the list of transactions that have not been received by full node yet.
        """
        current_time = int(time.time())
        async with self.db_wrapper.reader_no_transaction() as conn:
            rows = await conn.execute_fetchall(
                "SELECT transaction_record from transaction_record WHERE confirmed=0",
            )
        records = []

        for row in rows:
            record = (await self._get_new_tx_records_from_old([TransactionRecordOld.from_bytes(row[0])]))[0]
            if include_accepted_txs:
                # Reset the "sent" state for peers that have replied about this transaction. Retain errors.
                record = dataclasses.replace(record, sent=uint32(1), sent_to=filter_ok_mempool_status(record.sent_to))
                await self.add_transaction_record(record)
                self.tx_submitted[record.name] = current_time, 1
                records.append(record)
            elif record.name in self.tx_submitted:
                time_submitted, count = self.tx_submitted[record.name]
                if time_submitted < current_time - (60 * 10):
                    records.append(record)
                    self.tx_submitted[record.name] = current_time, 1
                elif count < minimum_send_attempts:
                    records.append(record)
                    self.tx_submitted[record.name] = time_submitted, (count + 1)
            else:
                records.append(record)
                self.tx_submitted[record.name] = current_time, 1

        return records
