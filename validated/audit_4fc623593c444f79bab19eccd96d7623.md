### Title
Removed oracle denoms retain their stale on-chain exchange rate, allowing reintroduced whitelist entries to reuse a stale price instead of a fresh one - (File: x/oracle/keeper/keeper.go, x/oracle/abci.go)

### Summary
This is the same bug class as the NFTFloorOracle report: a per-key aggregate value is deleted incompletely (or not at all) on "asset removal", so re-adding the asset lets stale, pre-removal data flow straight back into use. In sei-chain's oracle module, removing a denom from the vote-target whitelist does **not** delete its stored `OracleExchangeRate` (`BaseExchangeRate`). If that same denom is subsequently re-added to the whitelist, `market`/other consumers reading `GetBaseExchangeRate` for that denom will get the pre-removal price until the very next successful vote period recalculates it, with no timestamp/staleness check at all (worse than the NFT oracle case, which at least checked `expirationPeriod`).

### Finding Description
`ApplyWhitelist` only rewrites `VoteTarget` entries when the whitelist changes; it never deletes the `BaseExchangeRate` (price) entry for denoms removed from the whitelist: [1](#0-0) 

The actual cleanup of stale price entries is performed by `RemoveExcessFeeds`, which diffs `BaseExchangeRate` keys against current `VoteTarget`s and deletes anything not currently a target: [2](#0-1) 

Crucially, `RemoveExcessFeeds` is only invoked once per `SlashWindow` (not every vote period, and not immediately when the whitelist changes), from `EndBlocker`: [3](#0-2) 

`ApplyWhitelist` itself is invoked every `VotePeriod` from `MidBlocker`: [4](#0-3) [5](#0-4) 

`GetBaseExchangeRate`/`SetBaseExchangeRate` store the price keyed purely by denom, with no linkage to whether the denom is currently whitelisted, and no expiry mechanism is checked by callers other than the timestamp field which is not enforced anywhere on read: [6](#0-5) 

Putting this together: if governance (via `Params.Whitelist`) removes denom `X` (e.g., due to a price feed compromise/manipulation event necessitating removal) and then within the same `SlashWindow` re-adds `X` to the whitelist before the next `SlashWindow` boundary triggers `RemoveExcessFeeds`, the stale `BaseExchangeRate` for `X` (last computed before removal, potentially reflecting the very price disruption that caused the removal) remains readable via `GetBaseExchangeRate` and is used by any downstream consumer (e.g., market module pricing, or the EVM/CW callers of the oracle query endpoints) until the next successful vote-period tally overwrites it. Since `ApplyWhitelist` and vote-target churn is driven purely by `Params.Whitelist` (a governance parameter), and vote periods can pass without validators immediately restoring quorum for the reinstated denom (e.g., low validator participation, below-threshold votes get dropped per `MidBlocker`'s threshold logic), the window where the stale, potentially-corrupted price is served can persist for multiple vote periods.

### Impact Explanation
Any protocol code path that prices assets using `GetBaseExchangeRate` for a denom that was removed-then-restored can act on a stale exchange rate that is unrelated to current market conditions, exactly mirroring the "old prices reused after removal" bug class from the report. This can misprice transactions or valuations dependent on that exchange rate during the exposure window, which — depending on the consuming module — can cause fund-loss-adjacent outcomes (e.g., swaps/liquidations executed at a stale rate). This qualifies under "fee or refund abuse"/valuation-driven fund loss analog criteria, though the exact consumer of `GetBaseExchangeRate` for fund-moving decisions was not fully traced within the available context (this repo's `market` module usage of oracle rates was not inspected in this session due to iteration limits) — flagging this as **uncertain** and requiring further confirmation of a concrete fund-movement consumer before treating as definitively High severity.

### Likelihood Explanation
Likelihood is Medium: the trigger is entirely governance-driven (whitelist param changes), not an attacker-controlled transaction, and requires removal+re-addition of the same denom within one `SlashWindow` (which is on the order of `BlocksPerDay * 2` by default) without an intervening successful vote period recalculating the rate. This is a plausible but not attacker-forced operational sequence, matching the "conditional on expirationPeriod/SlashWindow being substantial" caveat in the original report.

### Recommendation
When `ApplyWhitelist` detects denoms removed from the whitelist, immediately delete their `BaseExchangeRate` entries (mirroring what `RemoveExcessFeeds` eventually does), rather than deferring cleanup to the next `SlashWindow` boundary. For example, in `ApplyWhitelist`, before/after calling `ClearVoteTargets`, compute the set difference between the old vote targets and the new whitelist and call `k.DeleteBaseExchangeRate(ctx, denom)` for each removed denom.

### Proof of Concept
1. Governance sets `Params.Whitelist` to include denom `uxyz`; validators vote and `SetBaseExchangeRateWithEvent` stores a price for `uxyz` (see `x/oracle/abci.go:97-99` in `MidBlocker`).
2. `uxyz` is found to have a manipulated/disrupted price feed; governance removes it from `Params.Whitelist`. `ApplyWhitelist` calls `ClearVoteTargets` + re-populates `VoteTarget`s for the remaining whitelist, but the previously stored `BaseExchangeRate` for `uxyz` is untouched [7](#0-6) .
3. Because `RemoveExcessFeeds` only runs at `SlashWindow` boundaries (`x/oracle/abci.go:155-158`), the stale rate for `uxyz` survives in the store.
4. Before the `SlashWindow` boundary is reached, governance re-adds `uxyz` to `Params.Whitelist`. `ApplyWhitelist` re-adds it as a `VoteTarget`.
5. Any caller of `k.GetBaseExchangeRate(ctx, "uxyz")` between steps 4 and the next successful vote-period tally for `uxyz` receives the stale, pre-removal (potentially manipulated) exchange rate with no staleness check.

func (k Keeper) GetBaseExchangeRate(ctx sdk.Context, denom string) (sdk.Dec, sdk.Int, int64, error) {
	store := ctx.KVStore(k.storeKey)
	b := store.Get(types.GetExchangeRateKey(denom))
	if b == nil {
		return sdk.ZeroDec(), sdk.ZeroInt(), 0, sdkerrors.Wrap(types.ErrUnknownDenom, denom)
	}

	exchangeRate := types.OracleExchangeRate{}
	k.cdc.MustUnmarshal(b, &exchangeRate)
	return exchangeRate.ExchangeRate, exchangeRate.LastUpdate, exchangeRate.LastUpdateTimestamp, nil
}

func (k Keeper) SetBaseExchangeRate(ctx sdk.Context, denom string, exchangeRate sdk.Dec) {
	store := ctx.KVStore(k.storeKey)
	currHeight := sdk.NewInt(ctx.BlockHeight())
	blockTimestamp := ctx.BlockTime().UnixMilli()
	rate := types.OracleExchangeRate{ExchangeRate: exchangeRate, LastUpdate: currHeight, LastUpdateTimestamp: blockTimestamp}
	bz := k.cdc.MustMarshal(&rate)
	store.Set(types.GetExchangeRateKey(denom), bz)
}

func (k Keeper) RemoveExcessFeeds(ctx sdk.Context) {
	// get actives
	excessActives := make(map[string]struct{})
	k.IterateBaseExchangeRates(ctx, func(denom string, rate types.OracleExchangeRate) (stop bool) {
		excessActives[denom] = struct{}{}
		return false
	})
	// get vote targets
	k.IterateVoteTargets(ctx, func(denom string, denomInfo types.Denom) (stop bool) {
		// remove vote targets from actives
		delete(excessActives, denom)
		return false
	})
	// compare
	activesToClear := make([]string, len(excessActives))
	i := 0
	for denom := range excessActives {
		activesToClear[i] = denom
		i++
	}
	sort.Strings(activesToClear)
	for _, denom := range activesToClear {
		// clear exchange rates
		k.DeleteBaseExchangeRate(ctx, denom)
	}
}

	start := time.Now()
	defer func() {
		oracleMetrics.midBlockerDuration.Record(ctx.Context(), time.Since(start).Seconds())
	}()

	params := k.GetParams(ctx)
	if utils.IsPeriodLastBlock(ctx, params.VotePeriod) {

		// Build claim map over all validators in active set
		validatorClaimMap := make(map[string]types.Claim)

		maxValidators := k.StakingKeeper.MaxValidators(ctx)
		iterator := k.StakingKeeper.ValidatorsPowerStoreIterator(ctx)
		defer func() { _ = iterator.Close() }()

		powerReduction := k.StakingKeeper.PowerReduction(ctx)

		i := 0

		k.IterateVoteTargets(ctx, func(denom string, denomInfo types.Denom) bool {
			voteTargets[denom] = denomInfo
			totalTargets++
			return false
		})

func EndBlocker(ctx sdk.Context, k keeper.Keeper) {
	start := time.Now()
	defer func() {
		oracleMetrics.endBlockerDuration.Record(ctx.Context(), time.Since(start).Seconds())
	}()

	params := k.GetParams(ctx)
	// Do slash who did miss voting over threshold and
	// reset miss counters of all validators at the last block of slash window
	if utils.IsPeriodLastBlock(ctx, params.SlashWindow) {
		k.SlashAndResetCounters(ctx)
		// Compare vote targets and actives and remove excess feeds
