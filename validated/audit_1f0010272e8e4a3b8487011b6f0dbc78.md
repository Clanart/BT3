### Title
Unchecked uint64 multiplication overflow in `IntrinsicGas` access-list/authorization-list gas surcharge - (File: blockchain/types/tx_internal_data.go)

### Summary
`IntrinsicGas()` computes intrinsic gas for a transaction, including extra charges for `AccessList` entries and EIP-7702 `authorizationList` (SetCode) entries. Unlike the payload-gas helpers it calls (`IntrinsicGasPayload`, `IntrinsicGasPayloadLegacy`), which carefully bound every multiplication/addition against `math.MaxUint64` before applying it, the access-list and authorization-list additions are raw, unchecked `uint64` arithmetic.

### Finding Description [2](#0-1) 

```go
if accessList != nil {
    gasPayloadWithGas += uint64(len(accessList)) * params.TxAccessListAddressGas
    gasPayloadWithGas += uint64(accessList.StorageKeys()) * params.TxAccessListStorageKeyGas
}

if authorizationList != nil {
    gasPayloadWithGas += uint64(len(authorizationList)) * params.CallNewAccountGas
}
```

Compare this with the sibling function that computes payload gas just above it, which is meticulous about overflow: [1](#0-0) 

`accessList.StorageKeys()` sums the storage-key counts across every entry of an access list supplied directly in the RLP-encoded transaction body by the sender. There is no upper bound enforced on the number of access-list entries or storage keys, or on `len(authorizationList)`, before this multiplication occurs — the only limits that exist are the block gas limit and RLP/tx-size limits, which are checked *after* (or independently of) this gas-cost computation, not before it. If `len(accessList) * params.TxAccessListAddressGas` (or the storage-key equivalent) were to overflow `uint64`, the result would silently wrap, producing an artificially low `gasPayloadWithGas`/`IntrinsicGas` value.

### Impact Explanation
If a maliciously crafted transaction (or bid/bundle) could supply an access list or authorization list large enough to wrap the `uint64` multiplication, `IntrinsicGas()` would return an incorrect (much smaller) gas value. This value gates transaction pool admission (`ErrIntrinsicGas` checks) and is subtracted from `st.gas` during state transition in `blockchain/state_transition.go`, meaning execution could proceed with insufficient gas actually charged to the sender — effectively bypassing minimum gas-fee accounting for the access-list/authorization-list portion of the transaction. This maps to the reportable class of "state transition and gas/burn accounting" abuse via unchecked arithmetic, directly analogous to the reported `Fixed18Lib.mul()` overflow (unchecked multiplication in a fee/value-relevant computation).

### Likelihood Explanation
Exploitability is bounded in practice: `TxAccessListAddressGas` (2400) and `TxAccessListStorageKeyGas` (1900) are the standard EIP-2930 constants, and `CallNewAccountGas` is a fixed small constant. To overflow `uint64` (max ≈1.8e19), an attacker would need roughly `1.8e19 / 2400 ≈ 7.7e15` access-list entries (or a comparably enormous authorization list) encoded in a single transaction. Given RLP transaction size limits (`txMaxSize`, ~128KB typically enforced in the tx pool) and per-entry RLP encoding overhead (at least 20+ bytes per address, 32+ bytes per storage key), it is not feasible to encode anywhere near 7.7e15 entries in one transaction under realistic size constraints. This significantly limits real-world reachability of the overflow condition, even though the code path itself lacks the explicit overflow check present in neighboring functions.

### Recommendation
Add the same overflow-safe pattern already used in `IntrinsicGasPayload`/`IntrinsicGasPayloadLegacy` to the access-list and authorization-list gas additions in `IntrinsicGas()`, e.g.:
```go
if accessList != nil {
    n := uint64(len(accessList))
    if (math.MaxUint64-gasPayloadWithGas)/params.TxAccessListAddressGas < n {
        return 0, ErrGasUintOverflow
    }
    gasPayloadWithGas += n * params.TxAccessListAddressGas
    // similarly for StorageKeys() and authorizationList
}
```
This closes the inconsistency and defensively guards against future constant changes or unexpected extremely large lists, even though current transaction-size limits make the overflow largely impractical today.

### Proof of Concept
Not independently reproducible within current size/gas limits of the tx pool (would require an access list/authorization list several orders of magnitude larger than any realistic RLP-encoded transaction can carry). The finding is presented as a defense-in-depth code-consistency issue rather than a demonstrated exploitable overflow, since `len(accessList)` and `len(authorizationList)` cannot practically reach the ~7.7×10¹⁵-entry threshold needed to wrap `uint64` given transaction size constraints enforced elsewhere in the tx pool.

// IntrinsicGas computes the 'intrinsic gas' for a message with the given data.
func IntrinsicGas(data []byte, accessList AccessList, authorizationList []SetCodeAuthorization, contractCreation bool, r params.Rules) (uint64, error) {
	// Set the starting gas for the raw transaction
	var gas uint64

	if contractCreation {
		gas = params.TxGasContractCreation
	} else {
		gas = params.TxGas
	}

	var gasPayloadWithGas uint64
	var err error
	if r.IsIstanbul {
		// tx types 1,2 only exist after istanbul; so they take this path.
		// tx types 8+ take this path as well.
		gasPayloadWithGas, err = IntrinsicGasPayload(gas, data, contractCreation, r)
	} else {
		// only for tx type 0 before istanbul.
		gasPayloadWithGas, err = IntrinsicGasPayloadLegacy(gas, data)
	}

	if err != nil {
		return 0, err
	}

	// We charge additional gas for the accessList:
	// ACCESS_LIST_ADDRESS_COST : gas per address in AccessList
	// ACCESS_LIST_STORAGE_KEY_COST : gas per storage key in AccessList
	if accessList != nil {
		gasPayloadWithGas += uint64(len(accessList)) * params.TxAccessListAddressGas
		gasPayloadWithGas += uint64(accessList.StorageKeys()) * params.TxAccessListStorageKeyGas
	}

	// We charge additional gas for the authorizationList:
	// PER_EMPTY_ACCOUNT_COST : gas per address in authorizationList
	// Since this is the same value as CallNewAccountGas, we will use this.
	if authorizationList != nil {
		gasPayloadWithGas += uint64(len(authorizationList)) * params.CallNewAccountGas
	}

	return gasPayloadWithGas, nil
}
