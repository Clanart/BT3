## Finding

### Title
Unauthenticated `CallDispatcher.dispatch()` lets any unprivileged caller drain funds parked in the shared dispatcher singleton - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The Coinbase report's broken invariant is: an unprivileged party gains control of execution inside a shared, temporarily-"unlocked" custody contract (`PoolManager`), and redirects funds that were only ever meant to move between two other parties, with zero capital of their own. `CallDispatcher` is Hyperbridge's structural analog to that shared "unlocked" custody point: it is a single, canonical, address-fixed contract reused by `IntentGatewayV2` (predispatch/postdispatch calldata) and by `HyperFungibleToken`/`WrappedHyperFungibleToken` (cross-chain calldata execution), and its `dispatch()` entrypoint has **no caller restriction whatsoever**.

### Finding Description
`CallDispatcher.dispatch(bytes)` is declared `external` with no modifier, no `onlyOwner`, no allowlist of calling contracts, and no reentrancy guard: [1](#0-0) 

Any address — an EOA or a contract — can call `dispatch()` directly and have the `CallDispatcher` execute `to.call{value: call.value}(call.data)` for arbitrary `to`/`data`, with `msg.sender` inside that call being the `CallDispatcher` itself. Because the dispatcher is a single shared, canonical deployment (its address is even the intended `to` target for cross-chain mints/unlocks, per the docs: "Existing `CallDispatcher` deployments are listed on the contract addresses page"), any balance the contract holds belongs to whichever flow last routed value through it.

Multiple legitimate flows route real user/solver funds through this exact contract as a temporary holding point:
- `IntentGatewayV2.placeOrder` transfers `order.predispatch.assets` to the dispatcher, executes `order.predispatch.call`, then sweeps a computed amount back to the gateway based only on `order.inputs`: [2](#0-1) 
- `IntentsBase._execute` (postdispatch) runs `order.output.call` via the dispatcher and then sweeps back only the balances for tokens present in `order.output.assets`: [3](#0-2) 
- `HyperFungibleToken`/`WrappedHyperFungibleToken` mint/unlock tokens directly to the `CallDispatcher` address before it forwards `data` to arbitrary DeFi calls (Uniswap swaps, etc.), per the documented pattern.

None of these sweep steps account for every token that could end up in the dispatcher: only tokens explicitly enumerated in `order.inputs` / `order.output.assets` are swept back. Any other asset that ends up in the dispatcher mid-flow — dust from an intermediate swap hop, fee-on-transfer residue, a partially-consumed `Call.value`, or (more critically) any balance the dispatcher is still holding at the moment an attacker-controlled `dispatch()` call executes — is retrievable by **anyone**, since `dispatch()` performs no ownership or reentrancy check before moving value out under its own identity. A `Call[]` in `order.predispatch.call` or `order.output.call` that routes through any external protocol with a callback (a Uniswap V2 flash-swap callback, an ERC-777 `tokensReceived` hook, etc.) hands execution to arbitrary code while the dispatcher still holds the escrowed assets; that code can re-enter `CallDispatcher.dispatch()` — a plain, unguarded external function — to sweep the currently-held balance to an attacker address before the legitimate sweep-back call runs.

### Impact Explanation
This is a direct fund-theft path: value that is supposed to move only between the order creator, the solver, and the gateway can instead be redirected to an arbitrary unprivileged third party who supplies no capital of their own — they simply call (or cause a callback into) `dispatch()` at the moment the shared dispatcher is holding someone else's escrowed assets. This satisfies the bounty's "stealing or loss of funds" / "unauthorized execution" criteria without requiring a malicious relayer, prover, or governance actor — only an ordinary caller (or an order whose predispatch/postdispatch calldata touches an external protocol with a callback).

### Likelihood Explanation
Medium: exploitation requires either (a) residual dust/balance being left in the shared dispatcher by an existing order flow (plausible with fee-on-transfer tokens, multi-hop swaps, or rounding, none of which are validated against), or (b) an order's `predispatch.call`/`output.call` routing through a protocol that grants a reentrant callback before the sweep-back executes. Both are realistic given that `_execute`/predispatch explicitly support arbitrary DEX/DeFi composition through this contract.

### Recommendation
- Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., only the `IntentGatewayV2`/HFT contracts that are expected to invoke it), or deploy a fresh, single-use dispatcher per call site instead of relying on one shared singleton with unauthenticated access.
- Add a reentrancy guard to `dispatch()` so a callback triggered by one of its own calls cannot re-enter and move funds before the outer sweep completes.
- After execution, sweep the dispatcher's *entire* balance for every token actually touched by the call array (not just the tokens enumerated in `order.inputs`/`order.output.assets`), or require the dispatcher to end each `dispatch()` invocation with a zero balance for any token it received.

### Proof of Concept
1. An order (or HFT `send`) with `predispatch.call`/`output.call` targeting a DEX router is placed, causing assets to be transferred into `CallDispatcher` before the router call executes.
2. The router call (or an ERC-777/fee-on-transfer token used along the way) invokes a callback into an attacker-deployed contract.
3. From within that callback, the attacker calls `CallDispatcher.dispatch(abi.encode(callsThatTransferCurrentBalanceToAttacker))` directly — this succeeds because `dispatch()` has no caller check.
4. The dispatcher's currently held balance (the escrowed predispatch assets or in-flight output tokens) is transferred to the attacker before the legitimate sweep-back call in `placeOrder`/`_execute` runs, causing the outer flow to under-collect or revert while the attacker keeps the drained funds.

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
