### Title
Unprivileged PR authors can force silent checkout of attacker-controlled branch/remote via `x-github-client://openRepo` deep link ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
The report's broken invariant is: *an identity/action selector (`delegatedSigner`) is set by an unprivileged, unrelated actor, and is then trusted implicitly by a privileged operation (`mint`/`redeem`) with no ownership check, letting that actor redirect the operation.* The GitHub Desktop analog is `openPullRequestFromUrl` in `app/src/ui/dispatcher/dispatcher.ts`, reached from the OS-registered `x-github-client://openRepo/...?pr=N` deep link. The `pr` number embedded in the link is fully attacker-chosen and is used to fetch a live pull request from the public API, whose `head.repo.clone_url` / `head.repo.owner.login` / `head.ref` (also entirely controlled by whoever opened that PR) are passed straight into `_checkoutPullRequest` → `_findPullRequestBranch`, which adds a new git remote and performs a real `checkout` — all without any confirmation dialog, and without verifying that the entity who triggered this (the link) or the entity who owns the head branch (the PR author) has any relationship to the repository owner or the user who clicks the link.

### Finding Description
`x-github-client`/`x-github-desktop-auth`/`github-mac` etc. are registered as OS-wide protocol handlers in `app/src/main-process/main.ts` [1](#0-0) , so any web page, chat message, or email link can invoke Desktop with an arbitrary `openRepo` URL, which `parseAppURL` turns into an `IOpenRepositoryFromURLAction` carrying an attacker-supplied `url`, optional `pr`, `branch`, `filepath` [2](#0-1) .

`Dispatcher.openRepositoryFromUrl` routes a request with a `pr` parameter to `openPullRequestFromUrl`: [3](#0-2) 

`openPullRequestFromUrl` fetches the PR (any PR number of any public repo, opened by any GitHub user), matches it to an already-tracked local repository purely by comparing the `htmlURL`/`parent.htmlURL` string to the PR's `clone_url` (`doesRepositoryMatchUrl`/`urlsMatch` — hostname+owner+name equality only, no account/permission check), and then immediately calls `_checkoutPullRequest` with the **PR head repo's clone URL and ref name taken from the API response of that specific PR**, i.e., values fully controlled by whoever authored that pull request: [4](#0-3) 

`AppStore._checkoutPullRequest` → `_findPullRequestBranch` then adds a new remote pointing at that attacker-controlled clone URL (with the `github-desktop-` prefix) if none exists, fetches it, creates a local `pr/<number>` branch tracking it, and returns it for checkout — with no additional confirmation step gating this deep-link-triggered flow: [5](#0-4) [6](#0-5) 

The existing guard that exists in this code path (`isAbsolute`/`resolveWithin` for `filepath`) only protects against path traversal for opening a file in the OS file browser [7](#0-6) ; it does not gate the branch/remote-add/checkout sequence, and no ownership or account-affiliation check exists between "who clicked the link" and "who authored the referenced PR" (unlike the report's recommended nested-mapping fix that ties the delegate to a specific benefactor).

### Impact Explanation
This lets any unprivileged GitHub user who can open a pull request against a public repository (i.e., essentially anyone) construct a link that, when clicked by a victim who already has that repository open in Desktop, silently:
1. Registers a new git remote in the victim's local working copy pointing at the attacker's fork.
2. Fetches from that attacker-controlled remote and creates/checks out a `pr/<n>` branch, replacing the working tree contents of the repository the victim is actively working in — without any per-click confirmation dialog.

This matches the "silent corruption of what the user commits or pushes" category in the Valid Impact criteria: if the victim doesn't notice the branch switch and continues working (staging/committing/building/running the project), attacker-authored content is what actually gets built, run, or committed on top of.

### Likelihood Explanation
The attacker primitive required — opening a pull request on a repository and getting a link clicked — needs no elevated access, no local/physical access, and no prior compromise; it only requires the target to have that public repository already open in Desktop and to click a crafted link (satisfying the "link/deep link the user clicks" allowed vector). The protocol handler is registered unconditionally at install/first-run, and PR numbers/branch names/clone URLs are trivially attacker-chosen by opening PRs against any public repository (including forks of the target). No dialog interrupts the deep-link-driven checkout flow, unlike the equivalent manual "Checkout" action a user takes from the in-app PR list.

### Recommendation
Before performing a deep-link-initiated checkout of a pull request (or any remote-adding operation triggered by `openRepositoryFromUrl`), require explicit user confirmation showing the PR author, source repository, and branch that will be checked out, and verify that the invoking `pr`/`branch`/`url` combination corresponds to a PR that is actually open against the *matched* repository (not merely a repository whose URL happens to match). Consider gating any remote add + fetch + checkout sequence triggered from an OS-level protocol handler behind a confirmation dialog analogous to the existing "Open in Desktop" flow's clone confirmation.

### Proof of Concept
1. Attacker (any GitHub user) opens a pull request (PR #N) against a public repository `owner/repo` that the victim already has cloned/tracked in GitHub Desktop, from the attacker's own fork with a branch containing malicious content.
2. Attacker crafts and distributes the link:
   `x-github-client://openRepo/https://github.com/owner/repo?pr=N`
3. Victim (who has `owner/repo` open in Desktop) clicks the link. The OS launches Desktop with this URL; `parseAppURL` produces `{ name: 'open-repository-from-url', url: 'https://github.com/owner/repo', pr: 'N', ... }`.
4. `Dispatcher.openRepositoryFromUrl` → `openPullRequestFromUrl` fetches PR #N via the API, matches it to the victim's already-open local repository, and calls `_checkoutPullRequest` with the attacker's fork `clone_url` and branch ref.
5. `_findPullRequestBranch` adds a `github-desktop-<attacker>` remote, fetches it, creates/checks out `pr/N` — with no confirmation prompt — silently switching the victim's working directory to attacker-controlled code.

Note: I was unable to fully verify (due to index/tool limits) whether any UI-level confirmation dialog wraps `dispatchURLAction`/`openRepositoryFromUrl` at a layer above `dispatcher.ts` (e.g., a global "trust this action" prompt in `app.tsx`); if such a prompt exists and blocks this specific flow, the severity would be reduced accordingly and should be confirmed with a full Devin session that can trace the complete call graph and exercise the flow end-to-end.

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,

    const prBranch = await this._findPullRequestBranch(

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    if (remote === undefined) {

      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
