## Analysis Summary

I investigated whether Kaia has an analogous "unauthorized value movement due to unverified/optional trust in an external contract" pattern reachable by an unprivileged transaction sender. The strongest analog is in the **`kaiax/gasless`** module (KIP-247 gasless transactions), where the txpool's decision to have the block proposer lend real KAIA is gated by a self-declared/optionally-verified value rather than an unconditionally enforced on-chain guarantee.

I was unable to fully confirm the exact atomicity semantics of the bundle's `false` revert flag in `builder.NewBundle` before running out of iterations — noted as an open uncertainty below.

### Title
Gasless LendTx Funding Depends on Optional/Self-Declared Swap Amount Validation - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module unconditionally issues a `LendTxGenerator`-produced transaction that transfers real KAIA from the block proposer to a gasless transaction sender *before* the corresponding `SwapTx` is verified to actually produce enough output to repay that loan. The only pre-execution guarantee that the swap will cover the loan is `tx.minAmountOut >= tx.amountRepay`, a comparison of two attacker-controlled fields [1](#0-0) , and the cross-check against the actual expected output — obtained by calling `GetAmountIn` on the externally-registered `GaslessSwapRouter` contract — is optional, gated behind `ShouldCheckSwapAmount()` / `BalanceCheckLevel` config [2](#0-1) [3](#0-2) .

### Finding Description
This mirrors the reported bug class (a contract that mints/burns value based on unconditional trust in an external party) in the following way: the proposer's `LendTxGenerator` transaction is prepended to the bundle and executed unconditionally, funding the sender with `LendAmount = ApproveTx.Fee() + SwapTx.Fee()` [4](#0-3) [5](#0-4) . The subsequent `SwapTx` is expected to repay `repayAmount = R1 + LendAmount` [6](#0-5) , but the txpool/block-building admission logic only checks:
1. `minAmountOut >= amountRepay` — both fields are declared by the (untrusted) transaction sender, with no default cross-validation against real reserves [1](#0-0) .
2. `amountIn >= gsr.GetAmountIn(token, minAmountOut)` — this quote is fetched from the `GaslessSwapRouter` contract address that is itself sourced from a `Registry`-controlled multicall (`getGaslessInfo` → `MultiCallGaslessInfo`) [7](#0-6) , and this check only runs when `BalanceCheckLevel >= BalanceCheckLevelSwapAmount` [2](#0-1) .

The `README.md` itself confirms the LendTx is prepended and funded before the swap executes, and that "sender balance check is omitted for gasless transactions" [8](#0-7) .

The `ExtractTxBundles` function builds the bundle as `[LendTxGenerator, ApproveTx?, SwapTx]` [9](#0-8) , but whether all three transactions revert together if the `SwapTx` fails to actually produce enough output (e.g., due to slippage, front-running, or a stale/incorrect `GetAmountIn` quote from the swap-router dependency) is not something I could conclusively verify from `builder.NewBundle(bundleTxs, targetTxHash, false)` in the time available.

### Impact Explanation
If the on-chain execution of the swap fails to actually produce `amountRepay` worth of value back to the block proposer — because the pre-checks rely on a self-declared value and/or an optionally-consulted external contract quote rather than a guaranteed atomic on-chain settlement — the block proposer's lent KAIA is not recovered. This is a direct "gasless settlement theft" scenario matching the excluded/accepted impact category ("gasless or auction settlement theft") in the validation rules, analogous to the reported issue's core theme: security depends entirely on the correctness/availability of an external, possibly-stale or misconfigured dependency (`GaslessSwapRouter.GetAmountIn`), with no enforced fallback.

### Likelihood Explanation
Likelihood depends heavily on:
- The node's configured `BalanceCheckLevel` (if below `BalanceCheckLevelSwapAmount`, the swap-router quote check is skipped entirely, leaving only the self-referential `minAmountOut >= amountRepay` check).
- Whether the `[LendTx, ApproveTx, SwapTx]` bundle is atomic (all-or-nothing) at the block-building/execution layer — I could not confirm this within available tool iterations, and it is the key factor determining whether an attacker submitting a `SwapTx` that reverts (or under-delivers) can still keep the already-executed `LendTx` funds.

This should be treated as a **candidate finding requiring confirmation** of bundle atomicity semantics (`builder.NewBundle`'s third boolean parameter) and the default `BalanceCheckLevel` used in production before being considered conclusively exploitable.

### Recommendation
- Verify and, if necessary, enforce that `[LendTx, ApproveTx, SwapTx]` bundles are executed atomically (all-or-nothing) at the block-execution level, so a reverted/under-delivering `SwapTx` also reverts the `LendTx`.
- Make the `GetAmountIn`-based cross-check (`ShouldCheckSwapAmount`) mandatory rather than opt-in via `BalanceCheckLevel`, or otherwise ensure `minAmountOut`/`amountRepay` are always validated against actual router-quoted values before a `LendTx` is generated.
- Add monitoring for gasless swap transactions where actual repayment fails to reach the declared `amountRepay`.

### Proof of Concept
1. An unprivileged sender crafts a `GaslessApproveTx` + `GaslessSwapTx` pair with `minAmountOut` and `amountRepay` set such that `minAmountOut >= amountRepay` holds trivially (self-declared), targeting a node/validator whose `BalanceCheckLevel` is below `BalanceCheckLevelSwapAmount` (or targeting a token/router pair for which the quoted `GetAmountIn` is manipulable/stale).
2. The gasless module's `IsExecutable`/`isReady` logic admits the pair into the pending pool [10](#0-9) .
3. `ExtractTxBundles` produces `[LendTxGenerator, ApproveTx, SwapTx]`, and the `LendTxGenerator` transfers real KAIA from the proposer to the sender [9](#0-8) [4](#0-3) .
4. If the `SwapTx` fails to deliver `amountRepay` back to the proposer (e.g., due to slippage/front-running or a stale quote) and the bundle is not enforced atomically, the sender retains the lent KAIA without full repayment.

Step 4's atomicity assumption is the unverified part of this analog — it should be confirmed against the actual bundle/`worker` execution code (`work/builder` package) before treating this as a confirmed, exploitable Medium-severity issue.

```go
func (g *GaslessModule) isReady(txs map[uint64]*types.Transaction, i uint64, ready types.Transactions) bool {
	tx := txs[i]

	if g.IsApproveTx(tx) && i < uint64(math.MaxUint64) {
		return g.isApproveTxReady(tx, txs[i+1])
	}

	if g.IsSwapTx(tx) {
		var prevTx *types.Transaction
		if len(ready) > 0 {
			prevTx = ready[len(ready)-1]
		}
		return g.isSwapTxReady(tx, prevTx)
	}

	return false
}

// isApproveTxReady assumes that the caller checked `g.IsApproveTx(approveTx)`
func (g *GaslessModule) isApproveTxReady(approveTx, nextTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, approveTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	if approveTx.Nonce() != nonce {
		return false
	}
	if nextTx == nil || !g.IsSwapTx(nextTx) {
		return false
	}

	return g.IsExecutable(approveTx, nextTx)
}

// isSwapTxReady assumes that the caller checked `g.IsSwapTx(swapTx)`
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}
```

```go
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
```

```go
func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}
```

```go
func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
```

```go
func getGaslessInfo(bc backends.BlockChainForCaller, header *types.Header) (common.Address, []common.Address, error) {
	statedb, err := bc.StateAt(header.Root)
	if err != nil {
		return common.Address{}, nil, err
	}

	// If Registry is not installed, do not query GaslessSwapRouter contract.
	if statedb.GetCode(system.RegistryAddr) == nil || bc.Config().IsRandaoForkBlockParent(header.Number) {
		return common.Address{}, nil, nil
	}

	caller, err := system.NewMultiCallContractCaller(statedb, bc, header)
	if err != nil {
		return common.Address{}, nil, err
	}

	opts := &bind.CallOpts{BlockNumber: header.Number}
	info, err := caller.MultiCallGaslessInfo(opts)

	return info.Gsr, info.Tokens, err
}
```

```markdown
Note that gasless transaction does not mean the gas prices of gasless transactions are zero, but it means that proposer will lend the user with gas fee and user will pay back during gasless swap.

The gas fee of gasless transaction's is funded by block proposer (i.e., lend transaction generated by `GetLendTxGenerator`), and user repays the lent amount during gasless swap.

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.

See ready condition [KIP-247](https://kips.kaia.io/KIPs/kip-247) and the implementation `IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool`.

#### Balance check

Sender balance check is omitted for gasless transactions (see `GetCheckBalance()`).

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
```
