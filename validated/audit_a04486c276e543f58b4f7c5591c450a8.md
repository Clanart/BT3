### Title
Out-of-range blame recipient crashes PedPoP verification - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`AdditionalBlameMachine::blame` accepts arbitrary non-zero `Participant` values but does not check that the alleged decryptor belongs to the `1..=n` participant set registered by `AdditionalBlameMachine::new`. A blame statement naming a non-member recipient and carrying `Some(EncryptionKeyProof)` reaches `self.enc_keys[&decryptor]`, whose missing-map-entry indexing panics. [1](#0-0) 

### Finding Description
`AdditionalBlameMachine::new` registers encryption keys only for participants `1..=n`. [2](#0-1)  `Participant::new` rejects only zero and therefore permits `n + 1` and larger indexes. [3](#0-2)  During blame evaluation, `decrypt_with_proof` first verifies the message PoP and then, whenever a proof is supplied, evaluates `self.enc_keys[&decryptor]` before checking the DLEq proof. [4](#0-3)  Because `AdditionalBlameMachine::blame` forwards the supplied recipient without a membership check, an unregistered recipient deterministically panics. [5](#0-4) 

### Impact Explanation
A single malformed accusation can terminate the thread or process performing PedPoP blame verification, matching the externally reported class of attacker-controlled assertion/panic denial of service. [1](#0-0)  The attacker needs only a canonically encoded `EncryptedMessage` with a valid key-PoP for the chosen sender and ciphertext, plus any canonically encoded `EncryptionKeyProof`; the invalid recipient index is reached before proof validity matters. [4](#0-3) 

### Likelihood Explanation
The vulnerability requires an integrator to pass accusation-controlled `sender`/`recipient` identifiers to `blame`; the PedPoP API itself does not enforce that they are members of the registered participant set. [5](#0-4)  Networks that fully validate both identifiers before invoking this API prevent the panic, but the library exposes a fallible-looking API while retaining an undocumented panic condition. [6](#0-5) 

### Recommendation
Validate `sender` and `recipient` against the registered participant set at the start of `BlameMachine::blame_internal` or `AdditionalBlameMachine::blame`, returning deterministic blame or an error instead of indexing `enc_keys`. [7](#0-6)  `Decryption::decrypt_with_proof` should also use `get(&decryptor)` and map `None` to `DecryptionError::InvalidProof`. [8](#0-7)

let proof = EncryptionKeyProof::<C>::read(&mut crafted_proof.as_slice())?;

// Panics on `self.enc_keys[&outsider]`.
