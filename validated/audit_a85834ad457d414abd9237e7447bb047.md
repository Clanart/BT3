### Title
Ignored `ParsePartialFromString` return value silently substitutes default field values for malformed map-value messages in JSON serialization - (File: `src/google/protobuf/json/internal/unparser_traits.h`)

### Summary
The Sherlock report's core invariant is: a fallible operation's boolean return value is discarded, so a failed operation is treated as successful, and the resulting (invalid/incomplete) state is then committed and exposed to the caller as if it were correct. The closest concrete analog found in this Protobuf checkout is in the ProtoJSON unparsing (`Message`/`Any` → JSON) code path, in `UnparseProto2Descriptor::WithDecodedMessage`: [1](#0-0) 

```cpp
template <typename F>
static absl::Status WithDecodedMessage(const Desc& desc,
                                       absl::string_view data, F body) {
  DynamicMessageFactory factory;
  std::unique_ptr<Message> unerased(factory.GetPrototype(&desc)->New());
  // TODO: Remove this suppression.
  (void)unerased->ParsePartialFromString(data);

  // Explicitly create a const reference, so that we do not accidentally pass
  // a mutable reference to `body`.
  const Msg& ref = *unerased;
  return body(ref);
}
```

### Finding Description
`ParsePartialFromString` returns `bool`, and per `MessageLite`'s documented contract, "If parsing fails (returns false), the message is left in an arbitrary but valid state" [2](#0-1) . The caller is expected to check this return value before trusting the resulting message's contents. In `WithDecodedMessage`, the return value is explicitly discarded via `(void)`, with a `// TODO: Remove this suppression.` comment acknowledging the gap, and the constructed `Message` is unconditionally passed to `body(ref)` — the JSON-serialization callback — regardless of whether parsing actually succeeded.

`data` here is the raw serialized bytes backing a message-typed map value obtained through reflection (`MapValueConstRef::GetMessageValue()`), as evidenced by the surrounding trait functions operating on `MapValueConstRef` (`GetInt32`, `GetBool`, `GetMessage`, etc.) in the same file [3](#0-2) . These bytes ultimately originate from a binary Protobuf payload that a client submitted and that was accepted by the trusted parser (`ParseFromString`/`ParseFromCodedStream` etc. succeeded for the top-level message), but the *sub-message* bytes for a particular map entry can still be malformed/truncated relative to the map's declared value type (e.g., due to a `MiniTable`/reflection mismatch, corrupted arena copy, or crafted byte content that only fails at the specific field level). When that inner parse fails, `WithDecodedMessage` does not propagate an error — it silently proceeds with whatever partial/default-initialized fields exist on `unerased`, and that message is fed straight into the JSON-writing callback.

### Impact Explanation
This is a direct structural analog to the Sherlock report: the failure signal from a fallible operation (`transfer()` returning `false` / `ParsePartialFromString` returning `false`) is discarded, and the surrounding logic proceeds exactly as though the operation succeeded, committing/emitting state that does not reflect what was actually processed. In the Protobuf case, the consequence is that `ProtoToJson`-style consumers of the public JSON serialization API can silently receive a map value rendered with default/zero field values instead of an accurate representation of the actual encoded submessage, with no error surfaced to the caller. This is a data-integrity issue in serialization output (silent misrepresentation of state) rather than a memory-safety or availability issue — it does not corrupt memory, leak out-of-bounds data, or crash the process, since `DynamicMessageFactory`-constructed messages are always safely default-initialized regardless of whether parsing completes.

### Likelihood Explanation
This code path is only reachable through the reflection-based (`kReflective`) JSON-unparse codec for messages containing map fields whose value type is itself a `Message`, and only when the map's underlying storage returns raw bytes for the value rather than a cleanly deserialized submessage. In this checkout, this appears to occur in a specific reflection-based map-access scenario, not the general steady-state case, and requires the trusted schema (the map's value message type) alongside a Protobuf payload that parses successfully at the top level but contains inner sub-message bytes that fail to validate as an instance of the value type. This narrows the attack surface considerably compared to a fully generic parsing bug.

### Recommendation
Check the return value of `ParsePartialFromString` in `WithDecodedMessage` and propagate a failure via `absl::Status` (consistent with the rest of the JSON unparser, which is written using `RETURN_IF_ERROR`/`absl::Status` throughout this file), rather than silently continuing with a possibly-incomplete `Message`. At minimum, this should surface as an internal error status from the JSON serialization call rather than emitting default field values without any indication to the caller.

### Proof of Concept
I was unable to construct and verify a concrete minimal binary payload plus assertion demonstrating the reflective-map-value code path invoking `WithDecodedMessage` with malformed inner bytes within the scope of this investigation — doing so would require confirming, in the map-field reflection implementation, the exact conditions under which `MapValueConstRef::GetMessageValue()` yields undecoded bytes that are then routed through this trait function (call sites are in `src/google/protobuf/json/internal/unparser.cc`, which I located but did not fully trace). This should be verified with a live build before treating the impact as confirmed; the finding here is scoped strictly to the ignored-return-value pattern and its documented contract violation, which is unambiguous from the source alone.

**Confidence caveat:** Given the narrow, reflection-specific reachability and the fact that the resulting `DynamicMessage` is always in a "valid but arbitrary" (never memory-unsafe) state per Protobuf's own parsing contract, I assess this analog as materially **lower severity** than the original Medium-rated Sherlock finding — it is a silent data-integrity defect in a specific JSON-serialization code path, not a state-corruption/fund-loss-class issue. I could not find a stronger analog (e.g., an ignored parse-return-value in the primary binary wire-format hot paths of C++/Java/upb/Python/Ruby/PHP) — all of the core `ParseFrom*`/`MergeFrom*`/`upb_Decode` paths I inspected correctly check and propagate their `bool`/`upb_DecodeStatus`/`absl::Status` results (see `MessageLite::MergeFromImpl`/`ParseFromCodedStream` [4](#0-3) , `WireFormatLite::SkipField` [5](#0-4) , and `upb_Decoder_Decode` [6](#0-5) ).

bool MessageLite::MergeFromImpl(io::CodedInputStream* input,
                                MessageLite::ParseFlags parse_flags) {
  ZeroCopyCodedInputStream zcis(input);
  const char* ptr;
  internal::ParseContext ctx(input->RecursionBudget(), zcis.aliasing_enabled(),
                             &ptr, &zcis);
  // MergePartialFromCodedStream allows terminating the wireformat by 0 or
  // end-group tag. Leaving it up to the caller to verify correct ending by
  // calling LastTagWas on input. We need to maintain this behavior.
  ctx.TrackCorrectEnding();
  ctx.data().pool = input->GetExtensionPool();
  ctx.data().factory = input->GetExtensionFactory();
  ptr = internal::TcParser::ParseLoop(this, ptr, &ctx, GetTcParseTable());
  if (ABSL_PREDICT_FALSE(!ptr)) return false;
  ctx.BackUp(ptr);
  if (!ctx.EndedAtEndOfStream()) {
    ABSL_DCHECK_NE(ctx.LastTag(), 1u);  // We can't end on a pushed limit.
    if (ctx.IsExceedingLimit(ptr)) return false;
    input->SetLastTag(ctx.LastTag());
  } else {
    input->SetConsumed();
  }
  return CheckFieldPresenceImpl(ctx, *this, parse_flags);
}

bool MessageLite::MergePartialFromCodedStream(io::CodedInputStream* input) {
  return MergeFromImpl(input, kMergePartial);
}

bool MessageLite::MergeFromCodedStream(io::CodedInputStream* input) {
  return MergeFromImpl(input, kMerge);
}

bool MessageLite::ParseFromCodedStream(io::CodedInputStream* input) {
  Clear();
  return MergeFromImpl(input, kParse);
}

bool MessageLite::ParsePartialFromCodedStream(io::CodedInputStream* input) {
  Clear();
  return MergeFromImpl(input, kParsePartial);
}

bool WireFormatLite::SkipField(io::CodedInputStream* input, uint32_t tag) {
  // Field number 0 is illegal.
  if (WireFormatLite::GetTagFieldNumber(tag) == 0) return false;
  switch (WireFormatLite::GetTagWireType(tag)) {
    case WireFormatLite::WIRETYPE_VARINT: {
      uint64_t value;
      if (!input->ReadVarint64(&value)) return false;
      return true;
    }
    case WireFormatLite::WIRETYPE_FIXED64: {
      uint64_t value;
      if (!input->ReadLittleEndian64(&value)) return false;
      return true;
    }
    case WireFormatLite::WIRETYPE_LENGTH_DELIMITED: {
      uint32_t length;
      if (!input->ReadVarint32(&length)) return false;
      if (!input->Skip(length)) return false;
      return true;
    }
    case WireFormatLite::WIRETYPE_START_GROUP: {
      if (!input->IncrementRecursionDepth()) return false;
      if (!SkipMessage(input)) return false;
      input->DecrementRecursionDepth();
      // Check that the ending tag matched the starting tag.
      if (!input->LastTagWas(
              WireFormatLite::MakeTag(WireFormatLite::GetTagFieldNumber(tag),
                                      WireFormatLite::WIRETYPE_END_GROUP))) {
        return false;
      }
      return true;
    }
    case WireFormatLite::WIRETYPE_END_GROUP: {
      return false;
    }
    case WireFormatLite::WIRETYPE_FIXED32: {
      uint32_t value;
      if (!input->ReadLittleEndian32(&value)) return false;
      return true;
    }
    default: {
      return false;
    }
  }
}
