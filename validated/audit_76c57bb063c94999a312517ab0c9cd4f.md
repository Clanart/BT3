### Title
Identity point accepted from untrusted bytes panics Taproot key handling - (File: networks/bitcoin/src/crypto.rs)

### Summary
`Secp256k1::read_G` accepts the canonical encoding of the identity point, while Bitcoin Taproot helper functions assume points have an x-coordinate; passing that decoded identity into `Scanner::new` or transaction setup causes a deterministic panic. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Ciphersuite::read_G` validates only that an encoding is a canonical group element and does not reject `G::identity()`. [1](#0-0)  `Scanner::new` passes its caller-provided key to `p2tr_script_buf`, which calls `x_only` for an even-Y encoded point. [4](#0-3) [2](#0-1)  `x_only` explicitly expects a non-infinity point and panics when x-coordinate extraction or x-only public-key construction fails. [3](#0-2) 

The same malformed key can be reached through `ThresholdKeys::read`, which accepts attacker-controlled verification shares and computes the group key as their interpolated sum without rejecting an identity result. [5](#0-4) [6](#0-5)  If those keys are used with a zero-valued `ReceivedOutput` offset, `SignableTransaction::multisig` again passes the identity group key into `p2tr_script_buf`. [7](#0-6) [8](#0-7) 

### Impact Explanation
A fixed canonical identity encoding can crash the thread or process handling scanner registration or transaction preparation instead of returning an error, producing a remotely triggerable availability failure wherever these APIs process untrusted bytes. [1](#0-0) [9](#0-8) 

### Likelihood Explanation
The input is deterministic, requires no secret material or protocol race, and directly reaches the panic through public deserialization and wallet APIs; the condition is limited to integrations that feed untrusted key material into `Scanner::new` or Bitcoin signing setup. [4](#0-3) [8](#0-7) 

### Recommendation
Reject `G::identity()` in Bitcoin-facing key entry points before calling `x_only`, and make `p2tr_script_buf` return `None` for identity or otherwise unencodable points rather than relying on panicking helpers. [2](#0-1) [3](#0-2)  Also reject identity group keys and zero secret shares when constructing or deserializing `ThresholdKeys` if those states are not valid for Bitcoin use. [10](#0-9) [5](#0-4) 

### Proof of Concept
```rust
use ciphersuite::{Ciphersuite, group::{Group, GroupEncoding}};
use frost::curve::Secp256k1;
use bitcoin_serai::wallet::Scanner;

let identity = <Secp256k1 as Ciphersuite>::G::identity();
let encoded = identity.to_bytes();

// Accepted as a canonical point.
let key = Secp256k1::read_G(&mut encoded.as_ref()).unwrap();

// Reaches x_only(&identity) and panics instead of returning None.
let _ = Scanner::new(key);
```

The parser accepts the canonical identity encoding because its validation stops after `from_bytes` and canonical re-encoding checks. [1](#0-0)  `Scanner::new` forwards the key into `p2tr_script_buf`, whose `x_only` helper documents and implements a panic on infinity or an invalid x-only key. [4](#0-3) [3](#0-2)

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)

    params: ThresholdParams,

    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })
