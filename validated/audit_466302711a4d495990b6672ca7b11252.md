## Analysis

The CVE describes an **undefined-behavior floating-point cast**: `tif_dirread.c` in LibTIFF converts a value that is outside the representable range of `float`, which the C/C++ standard treats as UB (not just "loses precision" — an out-of-range narrowing float conversion is UB per `[conv.double]`). The failed invariant is: *"validate magnitude before performing a narrowing float cast, never cast-then-check."*

Protobuf's own C++ tree shows the developers are aware of exactly this hazard and have a hardened helper for it: [1](#0-0) 

`SafeDoubleToFloat()` explicitly checks the magnitude of the `double` **before** calling `static_cast<float>`, with the comment *"static_cast<float> on a number larger than float can result in illegal instruction error, so we need to manually convert it to infinity or max."* This is the exact bug class from the LibTIFF report, already fixed once in this codebase.

However, the same protection is **missing** in the real, production ProtoJSON decoder (`google::protobuf::json::JsonStringToMessage`, exposed via `src/google/protobuf/json/json.h` / `util/json_util.h`) used for parsing attacker-controlled JSON into any message with a `float` field: [2](#0-1) 

Here `ParseFp()` parses the JSON number into a `double n` (fully attacker-controlled — e.g. `1e300` or `"1e300"`), and only *after* executing `static_cast<float>(n)` does it check `std::isfinite(...)` on the *result* to decide whether the value was out of range:

```cpp
if (Traits::Is32Bit(field)) {
  if (std::isfinite(n) && !std::isfinite(static_cast<float>(n))) {
    return lex.Invalid("float out of range");
  }
}
```

The cast `static_cast<float>(n)` is performed unconditionally, before the validity of the cast is known — i.e. the check occurs one step too late, exactly mirroring the `tif_dirread.c` pattern.

### Title
Out-of-range `double`-to-`float` narrowing cast before range check in ProtoJSON parser - (File: `src/google/protobuf/json/internal/parser.cc`)

### Summary
`ParseFp()` in the C++ ProtoJSON decoder converts an attacker-supplied JSON number to `float` via `static_cast<float>(n)` *before* verifying that `n` (a `double`) lies within the representable range of `float`. Per the C++ standard, converting a floating-point value that is outside the destination type's representable range is undefined behavior — the identical invariant violated by the LibTIFF CVE-2017-7597 `tif_dirread.c` bug.

### Finding Description
`ParseFp` (templated over field traits, used for every `float`/`double` scalar and repeated field parsed from JSON) reads a JSON number or numeric string into a `double n` with no bound on magnitude other than `absl::SimpleAtod`'s own overflow-to-infinity behavior. When the target proto field is 32-bit (`Traits::Is32Bit(field)`), the code performs `static_cast<float>(n)` directly inside the `isfinite` condition to detect overflow, e.g. `!std::isfinite(static_cast<float>(n))`. This means the (potentially UB) cast is *executed* to obtain the diagnostic, rather than being guarded by a pre-check on `n`'s magnitude as `SafeDoubleToFloat` does in `io/strtod.cc`. Contrast with the vetted, safe pattern already present in the codebase (`src/google/protobuf/io/strtod.cc:33-56`), which checks `value > std::numeric_limits<float>::max()` etc. *before* casting.

### Impact Explanation
The consuming application calls the public `JsonStringToMessage` API with any schema containing a `float` (or `Float` wrapper/`Any`-embedded) field. An attacker who controls the JSON body can supply a finite `double` literal whose magnitude exceeds `FLT_MAX` (e.g., `1e300`), which is passed unchanged into the guarded-but-too-late `static_cast<float>(n)`. On builds instrumented with `-fsanitize=float-cast-overflow` (UBSan) — commonly used in fuzzing/CI and in some hardened production configurations — this cast is a defined trap/abort, giving a remotely triggerable denial of service identical in class and root cause to the LibTIFF CVE (crash from float-cast-overflow UB on attacker-supplied data). On non-instrumented IEEE-754 targets the practical runtime effect is silent conversion to `±inf`, so the severity is bounded to sanitizer/hardened-build DoS rather than memory corruption.

### Likelihood Explanation
High reachability: any `float` field in any proto schema parsed via ProtoJSON is affected, and the triggering value (`1e300`, `"1e300"`, etc.) is trivial, bounded, and requires no special schema or privileges — only a normal JSON parse request. Actual observable impact is gated on the binary being built with `-fsanitize=float-cast-overflow` or a platform where the standard leaves the narrowing conversion truly undefined (not merely "produces inf"), which limits it to Medium overall severity rather than a universally exploitable crash.

### Recommendation
Guard the cast the same way `SafeDoubleToFloat` does: check `n`'s magnitude against `std::numeric_limits<float>::max()` (and the negative bound) before performing `static_cast<float>(n)`, and only cast once known to be within (or safely mappable to) representable float range/infinity. Ideally, route this logic through the existing `io::SafeDoubleToFloat` helper for consistency with the rest of the codebase.

### Proof of Concept
Using `google::protobuf::util::JsonStringToMessage` (or `json::JsonStringToMessage`) against any message with a `float` field `f`:
```json
{"f": 1e300}
```
Trace: `ParseFp` parses `n = 1e300` (finite double) → `Traits::Is32Bit(field)` is true for `f` → evaluates `static_cast<float>(1e300)`, a narrowing conversion of a value far outside `float`'s representable range, which is undefined behavior per `[conv.double]`. On a UBSan-instrumented build this reproducibly aborts the process (`runtime error: value ... is outside the range of representable values of type 'float'`), matching the LibTIFF CVE's crash signature; no assertion beyond building the JSON above and observing the sanitizer abort is required to reproduce.

float SafeDoubleToFloat(double value) {
  // static_cast<float> on a number larger than float can result in illegal
  // instruction error, so we need to manually convert it to infinity or max.
  if (value > std::numeric_limits<float>::max()) {
    // Max float value is about 3.4028234664E38 when represented as a double.
    // However, when printing float as text, it will be rounded as
    // 3.4028235e+38. If we parse the value of 3.4028235e+38 from text and
    // compare it to 3.4028234664E38, we may think that it is larger, but
    // actually, any number between these two numbers could only be represented
    // as the same max float number in float, so we should treat them the same
    // as max float.
    if (value <= MAX_FLOAT_AS_DOUBLE_ROUNDED) {
      return std::numeric_limits<float>::max();
    }
    return std::numeric_limits<float>::infinity();
  } else if (value < -std::numeric_limits<float>::max()) {
    if (value >= -MAX_FLOAT_AS_DOUBLE_ROUNDED) {
      return -std::numeric_limits<float>::max();
    }
    return -std::numeric_limits<float>::infinity();
  } else {
    return static_cast<float>(value);
  }
}

template <typename Traits>
absl::StatusOr<double> ParseFp(JsonLexer& lex, Field<Traits> field) {
  absl::StatusOr<JsonLexer::Kind> kind = lex.PeekKind();
  RETURN_IF_ERROR(kind.status());

  double n;
  switch (*kind) {
    case JsonLexer::kNum: {
      absl::StatusOr<LocationWith<double>> d = lex.ParseNumber();
      RETURN_IF_ERROR(d.status());
      n = d->value;
      break;
    }
    case JsonLexer::kStr: {
      absl::StatusOr<LocationWith<MaybeOwnedString>> str = lex.ParseUtf8();
      RETURN_IF_ERROR(str.status());

      if (str->value == "NaN") {
        n = NAN;
      } else if (str->value == "Infinity") {
        n = INFINITY;
      } else if (str->value == "-Infinity") {
        n = -INFINITY;
      } else if (!absl::SimpleAtod(str->value.AsView(), &n)) {
        return str->loc.Invalid("non-number characters in quoted number");
      }
      break;
    }
    default:
      return lex.Invalid("expected number or string");
  }

  if (Traits::Is32Bit(field)) {
    // Detect out-of-range 32-bit floats by seeing whether the conversion result
    // is still finite. Finite extreme values may have textual representations
    // that parse to 64-bit values outside the 32-bit range, but which are
    // closer to the 32-bit extreme than to the "next value with the same
    // precision".
    if (std::isfinite(n) && !std::isfinite(static_cast<float>(n))) {
      return lex.Invalid("float out of range");
    }
  }

  return n;
