### Title
Git pathspec magic in repo-controlled filenames lets `get_git_diff` escape its intended path scope - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`get_git_diff` restricts its diff to `review_paths` by turning them into a pathspec via `_diff_pathspec` and appending them after `--` to a `git diff` invocation. Git treats leading `:` in a pathspec element as the start of "magic" pathspec syntax (e.g. `:(exclude)`, `:(glob)`, `:!`) rather than a literal path, and neither `_diff_pathspec` nor the `GIT_CMD` base flags (`core.fsmonitor=false`, `core.hooksPath=/dev/null`) disable this or force literal interpretation, so a repo-controlled filename that happens to start with `:` can hijack the pathspec's meaning.

### Finding Description
`get_git_diff` in [1](#0-0)  builds its command as `[*GIT_CMD, "diff", ..., baseline_sha] + pathspec`, where `pathspec` comes from `_diff_pathspec(cwd, paths)`: [2](#0-1) 

`_diff_pathspec` only guards against paths that resolve (via `os.path.realpath`) outside `cwd` — it drops entries whose `relpath` starts with `..`. It does **not** sanitize the resulting relative-path *strings* for git's pathspec magic prefix `:`. Git interprets any pathspec argument beginning with `:` specially: short magic like `:!foo` / `:^foo` (exclude), or long magic like `:(exclude)foo`, `:(glob)foo`, `:(icase)foo`, `:(attr:...)foo`, `:(top)foo`. This is a git-level feature, unrelated to `--`, and is not disabled anywhere in this codebase (`GIT_CMD` sets `core.fsmonitor=false` and `core.hooksPath=/dev/null` only; there is no `--literal-pathspecs`, `--no-...-pathspec`, or `core.literalPathspecs=true`).

The `review_paths` fed into `get_git_diff` are themselves derived from `compute_v2_review_set`, which reads filenames straight out of `git status --porcelain` / `git diff --name-only` — i.e., attacker/repo-controlled filenames (untracked or tracked files present in the working tree) [3](#0-2) . Any of these can be an arbitrary valid git filename, including one starting with `:`.

Exploit flow: an attacker who can get a file with a name like `:(exclude)legit_change.py` (or `:!secret.py`, `:(top)...`) into the repo's working tree (e.g., via a crafted PR/branch checked out normally, or a file the agent itself creates during a session under repo-controlled instructions) causes it to be included in `review_set`/`review_paths` alongside other legitimately-touched files. When `get_git_diff` builds `-- ":(exclude)legit_change.py" other/real/path.py`, git no longer treats this as "diff only these files" — the `:(exclude)` magic turns the pathspec into an exclusion applied against the (now effectively unrestricted) match set, so the resulting diff can silently expand to include files that were never in `touched_paths`/`review_set` (e.g. arbitrary files elsewhere in the worktree, including files the user did not intend to have reviewed/exposed), or conversely can be crafted to suppress specific files from appearing in the diff sent for review. Because the diff text is what gets forwarded into `analyze_code_security` (the LLM review call) and error/debug logging paths, this both (a) can leak content of files outside the intended review scope into the LLM prompt/telemetry sink, and (b) can be abused to hide a malicious diff hunk from the security reviewer entirely by excluding it via pathspec magic — directly breaking "git path scoping must never escape the intended repo target."

Existing checks (`os.path.realpath` traversal/symlink guard in `_diff_pathspec`, the `-c core.quotePath=false -z` NUL-delimited parsing in `_git_name_only`/`_git_status_porcelain`) correctly handle path traversal via `..`, symlinks, and unicode/whitespace-in-filename parsing, but they do not address git's own pathspec magic-character semantics, which is a distinct and unguarded escape vector.

### Impact Explanation
This matches "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink": the LLM-facing diff (sent to `analyze_code_security`/agentic review, a remote sink) can be expanded beyond the intended per-turn review set to include arbitrary worktree files' content, or conversely be used to strip a malicious hunk from the reviewed diff so a real vulnerability slips past the Stop-hook/commit-review security gate undetected. Both are concrete violations of the repo-diff-scoping invariant.

### Likelihood Explanation
Requires only that a file with a `:`-prefixed name exist in the working tree and be part of `dirty_now`/`changed_since` at Stop-hook or commit-review time — fully reachable via an ordinary cloned-repo workflow (a malicious commit/PR checked out, or the agent creating such a file during normal Bash/file-edit tool use) with no elevated privilege needed. `:`, `(`, `)`, `!`, `^` are all valid in POSIX filenames, so crafting the trigger file is trivial on Linux/macOS. The only friction is that the filename must appear as a top-level pathspec token (which it will, since `_diff_pathspec` emits filenames verbatim), making this reliably reproducible.

### Recommendation
In `_diff_pathspec` (and any other place git pathspecs are built from filesystem-derived filenames, e.g. `_temp_index`'s `git add -- <paths>`), force literal interpretation: prefix each pathspec element with the `:(literal)` magic (e.g. `f":(literal){r}"`) or invoke git with `--literal-pathspecs` / set `GIT_LITERAL_PATHSPECS=1` in the subprocess environment for all commands that take user/repo-derived path lists (`get_git_diff`, `_temp_index`'s `add --intent-to-add`, `_git_name_only` if ever passed paths). Add a regression test asserting that a working-tree file literally named `:(exclude)x.py` or `:!x.py` is diffed as itself and does not alter the scope of the returned diff relative to the other `review_paths`.

### Proof of Concept
Integration test plan (to be run in a scratch git repo):
1. `git init`, create `a.py` with a benign line, commit, capture `baseline_sha` via `capture_git_baseline`.
2. Create a second file literally named `:(exclude)b.py` containing content that should NOT be exposed, and modify `a.py` (the "intended" reviewed file). Do not stage.
3. Call `compute_v2_review_set(repo, baseline_sha, ...)` — confirm `review_set` contains both `a.py` and `:(exclude)b.py` (as git legitimately reports both as dirty).
4. Call `get_git_diff(repo, baseline_sha, paths=[abs_path_to_a.py])` only (simulating a scenario where only `a.py` was intended to be reviewed but `_diff_pathspec` still receives/derives the malicious-name entry from `review_paths` in the real Stop-hook flow) — assert the returned diff text contains ONLY the hunk for `a.py`.
5. Repeat with `paths=[abs_path_to(":(exclude)b.py"), abs_path_to("a.py")]` as would occur when both are in `review_set` — assert (current buggy behavior) that the diff unexpectedly includes changes to files other than the two named `review_paths` (or unexpectedly excludes `a.py`), demonstrating the pathspec-magic escape. After the fix (`:(literal)` prefixing), assert the diff strictly contains exactly the two named files' hunks and nothing else.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

```python
def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
```
