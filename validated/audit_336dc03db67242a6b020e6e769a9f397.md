### Title
Fund freezing on EVM `SELFDESTRUCT`: address association deleted before its balance is read - ([File: x/evm/state/state.go])

### Summary
`DBImpl.SelfDestruct` deletes the EVM↔Sei address mapping *before* reading the account's balance and debiting it. Because the balance lookup (`GetBalance`/`SubBalance`) resolves the underlying `sdk.AccAddress` through that same mapping (falling back to a derived default address once the mapping is gone), the debit and refund end up operating on the wrong account after the association has been removed — mirroring the exact "delete object, then read data that depended on it" ordering bug fixed upstream for `inet6_addr_del()`.

### Finding Description
`SelfDestruct` in [1](#0-0)  executes in this order:

1. `s.k.GetSeiAddress(...)` + `s.k.DeleteAddressMapping(...)` — the explicit EVM↔Sei association is removed first.
2. `b := s.GetBalance(acc)` — balance is read *after* the mapping was deleted.
3. `s.SubBalance(acc, b, ...)` — the balance is debited using the same (now stale) lookup.

Both `GetBalance` and `SubBalance` resolve the underlying Cosmos account via `s.getSeiAddress(evmAddr)`, which calls `s.k.GetSeiAddressOrDefault(s.ctx, evmAddr)`: [2](#0-1) . `GetSeiAddressOrDefault` returns the real, explicitly-associated Sei address only while the mapping exists; once `DeleteAddressMapping` has run, it falls back to the deterministic default/pointer address derived directly from the EVM address instead of the account that actually held the funds.

Consequently, step 2's `GetBalance(acc)` no longer reads the balance of the address that really holds the contract's usei/wei — it reads the (almost always empty) default-derived address, so `b` comes back as (effectively) zero. Step 3's `SubBalance(acc, b, ...)` is then a no-op (amount-zero early return), so the real balance under the true, previously-associated Sei address is never debited, never swept to the fee collector, and never credited to the SELFDESTRUCT beneficiary via the returned `*b` (the caller in go-ethereum's opcode handling uses the returned value to credit the beneficiary, per the comment at line 83-85 in the same file). The subsequent sweep of destructed-account residuals, `handleResidualFundsInDestructedAccounts`/`clearAccountStateIfDestructed`, also runs against the account after the mapping is already gone, so it cannot recover the stranded funds either — this pattern is directly exercised in `TestSelfDestructAssociated` [3](#0-2) , which drives an associated address through `SelfDestruct6780`/`SelfDestruct`.

This is precisely the same bug class as the kernel CVE: an object/association is torn down before code that still needs the pre-teardown state runs, so the post-teardown code silently operates on the wrong (or nonexistent) target.

### Impact Explanation
Any EVM contract that executes `SELFDESTRUCT` while its EVM address is explicitly associated with a Sei address (a normal, common state for `associate`d accounts and pointer/CW-bridged accounts) will have its real usei/wei balance become unreachable: not transferred to the SELFDESTRUCT beneficiary, not burned, not swept to the fee collector. This is a permanent freezing-of-funds condition reachable by any unprivileged contract deployer/transaction sender simply by deploying and self-destructing a contract holding a balance.

### Likelihood Explanation
High likelihood: no special privileges or race conditions are required — a single EVM transaction that triggers `SELFDESTRUCT` on an address with an active Sei↔EVM association is sufficient to hit this code path deterministically every time.

### Recommendation
Reorder `SelfDestruct` so the balance is read and debited (using the still-valid mapping) *before* `DeleteAddressMapping` is invoked, mirroring the upstream kernel fix of moving the delete operation after the reads that depend on the pre-delete state.

### Proof of Concept
1. Associate an EVM address `E` with Sei address `S` (e.g., via the `associate` precompile), and fund `E`'s tracked EVM balance (backed by `S`'s usei/wei).
2. Deploy/execute a contract at `E` (or have `E` be a contract account) that calls `SELFDESTRUCT(beneficiary)`.
3. Observe that `SelfDestruct` in `x/evm/state/state.go` deletes the `E↔S` mapping first, then calls `GetBalance(E)`, which now resolves through `GetSeiAddressOrDefault` to the default derived address instead of `S`, returning near-zero balance.
4. `SubBalance(E, b)` is a no-op because `b` is zero; `beneficiary` never receives `S`'s actual balance, and `S`'s real balance is never cleared or swept — the value is permanently stranded/unaccounted for by the EVM logic, matching `TestSelfDestructAssociated`'s exercised path in `x/evm/state/state_test.go`.

func (s *DBImpl) SelfDestruct(acc common.Address) uint256.Int {
	s.k.PrepareReplayedAddr(s.ctx, acc)
	if seiAddr, ok := s.k.GetSeiAddress(s.ctx, acc); ok {
		// remove the association
		s.k.DeleteAddressMapping(s.ctx, seiAddr, acc)
	}
	b := s.GetBalance(acc)
	s.SubBalance(acc, b, tracing.BalanceDecreaseSelfdestruct)

	// mark account as self-destructed
	s.MarkAccount(acc, AccountDeleted)
	return *b
}

func (s *DBImpl) GetBalance(evmAddr common.Address) *uint256.Int {
	s.k.PrepareReplayedAddr(s.ctx, evmAddr)
	// Hook for mock balances (no-op in production builds)
	s.ensureMinimumBalance(evmAddr)
	seiAddr := s.getSeiAddress(evmAddr)
	res, overflow := uint256.FromBig(s.k.GetBalance(s.ctx, seiAddr))
	if overflow {
		panic("balance overflow")
	}
	if res == nil {
		return uint256.NewInt(0)
	}
	return res
}

func (s *DBImpl) SetBalance(evmAddr common.Address, amtUint256 *uint256.Int, reason tracing.BalanceChangeReason) {
	if !s.simulation {
		panic("should never call SetBalance in a non-simulation setting")
	}
	amt := amtUint256.ToBig()
	seiAddr := s.getSeiAddress(evmAddr)
	moduleAddr := s.k.AccountKeeper().GetModuleAddress(types.ModuleName)
	s.send(seiAddr, moduleAddr, s.GetBalance(evmAddr).ToBig())
	if s.err != nil {
		panic(s.err)
	}
	usei, _ := SplitUseiWeiAmount(amt)
	coinsAmt := sdk.NewCoins(sdk.NewCoin(s.k.GetBaseDenom(s.ctx), usei.Add(sdk.OneInt())))
	if err := s.k.BankKeeper().MintCoins(s.ctx, types.ModuleName, coinsAmt); err != nil {
		panic(err)
	}
	s.send(moduleAddr, seiAddr, amt)
	if s.err != nil {
		panic(s.err)
	}
}

func (s *DBImpl) getSeiAddress(evmAddr common.Address) sdk.AccAddress {
	if s.coinbaseEvmAddress.Cmp(evmAddr) == 0 {
		return s.coinbaseAddress
	}
	return s.k.GetSeiAddressOrDefault(s.ctx, evmAddr)
}

func TestSelfDestructAssociated(t *testing.T) {
	k := &testkeeper.EVMTestApp.EvmKeeper
	ctx := testkeeper.EVMTestApp.GetContextForDeliverTx([]byte{}).WithBlockTime(time.Now())
	seiAddr, evmAddr := testkeeper.MockAddressPair()
	k.SetAddressMapping(ctx, seiAddr, evmAddr)
	statedb := state.NewDBImpl(ctx, k, false)
	statedb.CreateAccount(evmAddr)
	key := common.BytesToHash([]byte("abc"))
	val := common.BytesToHash([]byte("def"))
	tkey := common.BytesToHash([]byte("jkl"))
	tval := common.BytesToHash([]byte("mno"))
	statedb.SetState(evmAddr, key, val)
	statedb.SetCode(evmAddr, []byte("code"))
	statedb.SetTransientState(evmAddr, tkey, tval)
	amt := sdk.NewCoins(sdk.NewCoin(k.GetBaseDenom(ctx), sdk.NewInt(10)))
	k.BankKeeper().MintCoins(statedb.Ctx(), types.ModuleName, amt)
	k.BankKeeper().SendCoinsFromModuleToAccount(statedb.Ctx(), types.ModuleName, seiAddr, amt)

	// Selfdestruct6780 should only act if the account is created in the same block
	statedb.MarkAccount(evmAddr, nil)
	statedb.SelfDestruct6780(evmAddr)
	require.Equal(t, val, statedb.GetState(evmAddr, key))
	statedb.MarkAccount(evmAddr, state.AccountCreated)
	require.False(t, statedb.HasSelfDestructed(evmAddr))

	// Selfdestruct6780 is equivalent to SelfDestruct if account is created in the same block
	statedb.SelfDestruct6780(evmAddr)
	require.Equal(t, tval, statedb.GetTransientState(evmAddr, tkey))
	require.NotEqual(t, common.Hash{}, statedb.GetState(evmAddr, key))
	require.Equal(t, uint256.NewInt(0), statedb.GetBalance(evmAddr))
	require.Equal(t, big.NewInt(0), k.BankKeeper().GetBalance(ctx, seiAddr, k.GetBaseDenom(ctx)).Amount.BigInt())
	require.True(t, statedb.HasSelfDestructed(evmAddr))
	require.False(t, statedb.Created(evmAddr))
	statedb.AddBalance(evmAddr, uint256.NewInt(1), tracing.BalanceChangeUnspecified)
	require.Equal(t, uint256.NewInt(1), statedb.GetBalance(evmAddr))
	statedb.Finalize()
	require.Equal(t, common.Hash{}, statedb.GetState(evmAddr, key))
	// association should also be removed
	_, ok := k.GetSeiAddress(statedb.Ctx(), evmAddr)
	require.False(t, ok)
	// balance in destructed account should be cleared and transferred to coinbase
	require.Equal(t, uint256.NewInt(0), statedb.GetBalance(evmAddr))
	fc, _ := k.GetFeeCollectorAddress(statedb.Ctx())
	require.Equal(t, uint256.NewInt(1), statedb.GetBalance(fc))
