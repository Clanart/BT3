### Title
Gas-fee rounding to zero in `SimplexPaymaster._tokenPrice`/`_fetchDetails` allows free-riding on paymaster-sponsored gas - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices ERC-20 gas payments via `tokenPrice = nativeUsd * 10^tokenDecimals * markup / (tokenUsd * 10000)`, then the base `PaymasterERC20` computes `erc20Cost = weiCost * tokenPrice / 1e18`. Exactly like the `ACC_PRECISION`/`accHaloPerShare` truncation in the external report, this is a fixed 1e18 scale applied across tokens/chains with heterogeneous decimals and gas-price magnitudes; when the product `weiCost * tokenPrice` is smaller than `1e18`, integer division truncates the charged amount to zero, letting the sponsored UserOp execute for free while the paymaster still pays the real gas cost from its EntryPoint deposit.

### Finding Description
`_tokenPrice` [1](#0-0)  computes a per-wei price scaled by `1e18`, and the contract's own doc comment states the downstream cost formula explicitly: `erc20Cost = weiCost * tokenPrice / 1e18` [2](#0-1) . Both `estimateTokenCost` (a view helper mirroring the real charge path) and the production `_fetchDetails` use the same `_tokenPrice(cfg)` value [3](#0-2) [4](#0-3) .

For a registered stablecoin at $1 with 6 decimals against a $600 native asset, `tokenPrice` resolves to `6e8` (confirmed by the test suite) [5](#0-4) . Any UserOp whose `weiCost` (`gasLimit * maxFeePerGas` plus the fixed `_postOpCost()` cushion) falls below `1e18 / tokenPrice` (~1.67e9 wei at this price) causes `erc20Cost` to truncate to exactly `0`. On chains/rollups with sub-gwei gas prices, or for a paymaster-sponsored UserOp deliberately constructed with a very low `maxFeePerGas`, this threshold is trivially reachable by an ordinary, unprivileged account — no relayer, prover, or governance actor is required.

This mirrors the HAL-08 root cause precisely: a fixed precision constant (`1e18`) combined with per-token decimal variance (`10^tokenDecimals` in the numerator) produces a division that rounds down to zero once the numerator is small relative to the denominator, silently zeroing out an amount that should have accrued/charged.

### Impact Explanation
Since the paymaster prefunds the UserOp from its EntryPoint deposit and only reclaims cost via `transferFrom` in `_postOp` (governed by the same `_erc20Cost` computation), a `0` result means the sender pays nothing while the paymaster's real ETH/native balance is spent covering gas. Repeated construction of such UserOps drains the paymaster's EntryPoint deposit — funded by governance/treasury — for free, which is a direct loss of protocol funds and unauthorized "free" execution sponsored by the bridge's paymaster infrastructure.

### Likelihood Explanation
Any account can submit an ERC-4337 UserOp through the public EntryPoint using `SimplexPaymaster` as paymaster and choose `maxFeePerGas`/`callGasLimit` low enough to push `weiCost` under the truncation threshold; this is entirely attacker-controlled and requires no privileged role, matching the "unprivileged attacker" and "no malicious peer/relayer" requirements. The exact threshold depends on the registered token's decimals and the live oracle-derived `tokenPrice`, so likelihood is highest on low-gas-price chains, but the underlying rounding defect exists in the formula for any deployment.

### Recommendation
Add a minimum-charge guard: revert (e.g., `InvalidPaymasterData`/a new `ZeroCost` error) when the computed `erc20Cost` (or `weiCost * tokenPrice`) is `0` or below a configured floor, so a UserOp cannot be validated/sponsored without a non-zero token debit. Alternatively increase internal precision (e.g., carry an extra scaling factor before the final division) so legitimate low-value gas costs still round to a non-zero minimum charge instead of zero.

### Proof of Concept
1. Governance registers a stablecoin with 6 decimals via `RegisterToken`, as already exercised in `testTokenPriceSixDecimals` (`tokenPrice == 6e8`) [5](#0-4) .
2. An attacker submits a UserOp with `paymasterData` selecting that token (mode `0x01`, pre-approved) and sets `callGasLimit`/`maxFeePerGas` such that `weiCost < 1e18 / 6e8 ≈ 1.67e9` wei (e.g., `maxFeePerGas = 1` wei on a low-fee chain, or a minimal `callGasLimit`).
3. `_fetchDetails` returns `tokenPrice = 6e8`; downstream `erc20Cost = weiCost * 6e8 / 1e18` evaluates to `0` per the documented formula [2](#0-1) .
4. `_postOp` (base `PaymasterERC20`) transfers `0` tokens from the sender while the EntryPoint has already deducted the real native gas cost from the paymaster's deposit — the UserOp executes fully sponsored and free, repeatable indefinitely to drain the paymaster's deposit.

    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @notice Estimate the token cost for a given gas amount and fee, mirroring
    ///         PaymasterERC20._erc20Cost (including its postOp gas cushion).
    function estimateTokenCost(
        address token,
        uint256 gasAmount,
        uint256 maxFeePerGas
    ) external view returns (uint256) {
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 weiCost = gasAmount * maxFeePerGas + _postOpCost() * maxFeePerGas;
        return (weiCost * _tokenPrice(cfg)) / _tokenPriceDenominator();
    }
