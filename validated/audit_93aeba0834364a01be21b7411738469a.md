### Title
Missing caller-authorization check in `CW721ERC721Pointer.transferFrom` allows anyone to steal any pointed CW721 NFT - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.transferFrom(address from, address to, uint256 tokenId)` verifies only that `from` is the current owner of `tokenId` (via a query to the underlying CosmWasm CW721 contract), but never checks that `msg.sender` is `from`, an approved spender for `tokenId`, or an approved operator for `from`. Any EVM account can therefore transfer any NFT out of its rightful owner's wallet through this pointer contract.

### Finding Description
The vulnerable code:
```solidity
function transferFrom(address from, address to, uint256 tokenId) public override {
    if (to == address(0)) {
        revert ERC721InvalidReceiver(address(0));
    }
    require(from == ownerOf(tokenId), "`from` must be the owner");
    string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
    string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
    string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
    _execute(bytes(req));
}
``` [1](#0-0) 

`_execute` performs a `delegatecall` into the wasmd precompile at address `0x1002`, calling `execute` on behalf of `Cw721Address` using the pointer contract's own Sei-mapped identity/authority, not `msg.sender`'s: [2](#0-1) 

Because the CosmWasm `execute` is sent as the pointer contract itself (which, per CW721 standard, is presumably granted operator/owner-equivalent trust as the sole ERC721 entry point), the `transfer_nft` message succeeds as long as `from` legitimately owns the token — it does not matter who actually invoked the EVM `transferFrom` call. This is unlike the local reference `ERC721.sol` implementation, which enforces `_isApprovedOrOwner(from, msg.sender, id)` before mutating state: [3](#0-2) 

The pointer's own `approve` and `setApprovalForAll` functions do forward authorization decisions to the CW721 contract (via `approve`/`approve_all` messages), but `transferFrom` never checks `getApproved(tokenId)` or `isApprovedForAll(from, msg.sender)` before executing the transfer, so those approvals provide no actual protection at the EVM entry point — a completely unrelated, unapproved caller can trigger the transfer directly.

### Impact Explanation
Any transaction sender or contract can call `transferFrom(victimOwner, attackerAddress, tokenId)` on any `CW721ERC721Pointer` instance and unconditionally move the NFT away from its rightful owner, causing direct and complete loss of that asset. This meets the "unauthorized transfer via precompile or pointer" and "concrete fund loss" criteria, since CW721 pointer contracts are a core CW↔EVM bridge component reachable by any public RPC/contract-call user.

### Likelihood Explanation
Likelihood is high: exploitation requires only a single unauthenticated EVM transaction calling `transferFrom` with a known token owner and token ID — both of which are publicly queryable via `ownerOf`/enumeration functions on the same pointer contract. No special privileges, approvals, or preconditions are needed.

### Recommendation
Add an authorization check in `transferFrom` mirroring standard ERC721 semantics before issuing the `transfer_nft` execute message, e.g.:
```solidity
require(
    msg.sender == from ||
    isApprovedForAll(from, msg.sender) ||
    getApproved(tokenId) == msg.sender,
    "not authorized"
);
```
placed immediately after the `from == ownerOf(tokenId)` check in `contracts/src/CW721ERC721Pointer.sol`.

### Proof of Concept
1. Deploy/identify a `CW721ERC721Pointer` for an existing CW721 collection where `victim` legitimately owns `tokenId = 1` (confirmable via `ownerOf(1)`).
2. From any unrelated EOA `attacker` (no approval, not `victim`), call:
   `pointer.transferFrom(victim, attacker, 1)`.
3. The call succeeds because the only check performed is `require(from == ownerOf(tokenId), ...)`, which passes trivially since `from` is set to the real owner `victim`.
4. `ownerOf(1)` now returns `attacker`; the NFT has been stolen without any signature, approval, or consent from `victim`. [1](#0-0) [4](#0-3) [5](#0-4)

    function getApproved(uint id) external view returns (address) {
        require(_ownerOf[id] != address(0), "token doesn't exist");
        return _approvals[id];
    }

    function _isApprovedOrOwner(
        address owner,
        address spender,
        uint id
    ) internal view returns (bool) {
        return (spender == owner ||
        isApprovedForAll[owner][spender] ||
            spender == _approvals[id]);
    }

    function transferFrom(address from, address to, uint id) public {
        require(from == _ownerOf[id], "from != owner");
        require(to != address(0), "transfer to zero address");

        require(_isApprovedOrOwner(from, msg.sender, id), "not authorized");

        _balanceOf[from]--;
        _balanceOf[to]++;
        _ownerOf[id] = to;

        delete _approvals[id];
