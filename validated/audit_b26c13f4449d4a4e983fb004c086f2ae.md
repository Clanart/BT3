### Title
Gasless bundle admission relies on an operator-configurable `BalanceCheckLevel` to validate swap economics, letting a malicious gasless sender extract the proposer's lent gas when the swap-amount check is skipped - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless (KIP-247) flow lets an ordinary, unprivileged transaction sender submit a `GaslessSwapTx` (optionally preceded by a `GaslessApproveTx`). Before the transaction is admitted/bundled, the node's gasless module performs an off-chain, self-configured "balance check" to decide whether the bundle is safe to build a `LendTxGenerator` around, which pre-funds the sender's gas from the block proposer's own balance. Whether the crucial swap-amount/exchange-rate check (`GetAmountIn` from `GaslessSwapRouter`) is even executed is controlled entirely by the node operator's `BalanceCheckLevel` setting, not by protocol consensus rules. This mirrors the audited "collateral values set manually" bug class: a privileged/operator-tunable, off-chain-validated parameter (here, a config flag rather than a script) that is trusted to guard fund-moving logic, is undocumented as a hard security boundary, and can silently degrade without on-chain enforcement, widening the attack surface for value extraction from block proposers.

### Finding Description
`GaslessConfig.BalanceCheckLevel` gates which validations are performed when the gasless module decides a bundle is `IsExecutable`/passes `GetCheckBalance` and is thus fronted gas by the proposer: [1](#0-0) 

At `BalanceCheckLevelTokenBalanceAndAllowance` (or lower), `ShouldCheckSwapAmount()` returns `false`, so `checkBalanceForSwap` never calls the router's `GetAmountIn` to verify the sender's claimed `amountIn`/`minAmountOut` actually reflects the live exchange rate: [2](#0-1) 

Because this check is entirely off-chain/mempool-admission logic (not enforced by the protocol's state-transition rules), a node whose operator has configured a lower `BalanceCheckLevel`, or any timing/version-mismatch scenario where this check is bypassed, will build and submit a `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` bundle for a swap that is not actually valid at the DEX's current price. The proposer's `LendTxGenerator` unconditionally transfers KAIA to the sender to cover gas as described in the module's own documentation: [3](#0-2) 

If the swap subsequently reverts or returns less than `minAmountOut` on-chain (because the off-chain amountIn/rate check was skipped), the sender still received the lent gas but the `swapForGas` repayment to the proposer fails, resulting in an uncompensated transfer of value from the proposer to the sender - precisely the kind of "manually configured, unreviewed process trusted to gate fund flows" pattern flagged in the source report, except here the trust anchor is an operator-tunable flag instead of an off-chain reconciliation script.

### Impact Explanation
If exploited, an unprivileged gasless-transaction sender can cause the block proposer to lend gas (real KAIA) without receiving proper repayment, resulting in direct value loss to the proposer/validator operating with a relaxed `BalanceCheckLevel`. This is a fee-delegation/gasless settlement theft matching the "unauthorized value movement" criterion. Severity depends on how widely operators run with reduced check levels, which is a deployment/documentation gap analogous to the original report's core complaint (undocumented, operator-controlled step with no enforced guarantee).

### Likelihood Explanation
Likelihood is contingent on node operator configuration: this is not a default vulnerable state (`DefaultGaslessConfig` uses `BalanceCheckLevelAll`, the safest level). The likelihood is Medium: the check is exposed as an operator-facing CLI flag (`gasless.balance-check-level`) rather than a hard-coded protocol requirement, so a misconfigured or intentionally weakened proposer node is a plausible, reachable path for any external gasless sender, without needing any special privilege beyond normal transaction submission.

### Recommendation
Short term, document explicitly that `BalanceCheckLevel` values below `BalanceCheckLevelAll` remove the exchange-rate safety check and expose the proposer to gas-lending loss; consider making the swap-amount check mandatory (non-configurable) since it is what prevents front-running or economically invalid swaps from consuming proposer-lent gas. Long term, move the amountIn/exchange-rate validation into an on-chain, protocol-enforced precondition (e.g., part of `swapForGas`'s revert conditions checked before the lend transaction is committed within the same bundle) rather than relying purely on a mempool-admission-time, operator-configurable heuristic.

### Proof of Concept
1. A node operator (or any deployment using a lowered `--gasless.balance-check-level`, e.g. `1`) runs a CN with `BalanceCheckLevel = BalanceCheckLevelTokenBalanceAndAllowance`.
2. An attacker crafts a `GaslessApproveTx` + `GaslessSwapTx` pair where `SwapArgs.MinAmountOut` and `AmountIn` do not correspond to the DEX's real exchange rate (e.g., `AmountIn` too low to actually satisfy `minAmountOut` at the current pool state) - `checkBalanceForSwap` only validates `minAmountOut >= amountRepay`, `token` and `sender code` checks (`ShouldCheckSwapAmount()` is `false`, so `GetAmountIn` is never called): [4](#0-3) 
3. The bundle passes `VerifyExecutable`/`IsExecutable` static checks (nonce, token match, `SP4` repay-amount arithmetic), so the module's `GetLendTxGenerator` builds and prepends a `LendTxGenerator` that pays the attacker's gas fee up front from the proposer's KAIA.
4. The block is built with `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]`; on execution, `swapForGas` in `GaslessSwapRouter` reverts or returns insufficient output because the actual DEX rate does not satisfy the declared parameters, so the repayment to the proposer fails while the lend transfer to the attacker already succeeded.
5. Repeating this against a proposer running a reduced `BalanceCheckLevel` drains value from that proposer over multiple blocks.

(Note: exploitation requires the proposer's own node to be configured below `BalanceCheckLevelSwapAmount`; this analog documents a config-dependent, unenforced trust boundary rather than a universally-exploitable default, similar to how the original finding's severity depended on an unreviewed and unenforced off-chain process.)

```go
func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
```

```markdown
Gasless transaction (GaslessTx) consists of two types: gasless approve transaction (GaslessApproveTX), and gasless swap transaction (GaslessSwapTx).

Note that gasless transaction does not mean the gas prices of gasless transactions are zero, but it means that proposer will lend the user with gas fee and user will pay back during gasless swap.

The gas fee of gasless transaction's is funded by block proposer (i.e., lend transaction generated by `GetLendTxGenerator`), and user repays the lent amount during gasless swap.

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.
```
