### Title
Scanner reports immature coinbase outputs as spendable `ReceivedOutput`s, crediting the multisig funds that cannot be spent for 100 blocks - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates every transaction in a block — including `txdata[0]`, the coinbase — and `scan_transaction` returns any output whose `script_pubkey` matches a registered script as a fully-formed, nominally-valued `ReceivedOutput`. A miner (an unprivileged external party whose transactions are attacker-controlled input to the scanner) can craft a coinbase paying to the multisig's P2TR script. The scanner then reports funds received at face value that are consensus-unspendable for `COINBASE_MATURITY` (100) blocks, and there is no marker on `ReceivedOutput` distinguishing a coinbase outpoint from a normal one.

### Finding Description
`scan_transaction` enumerates `tx.output`, matches `output.script_pubkey` against `self.scripts`, and pushes a `ReceivedOutput { offset, output, outpoint }` with no check on whether the containing transaction is a coinbase or how old it is. `scan_block` unconditionally extends results over `block.txdata`, i.e. including `block.txdata[0]`. `ReceivedOutput::value()` then reports `output.value.to_sat()` as the balance.

The doc comment on `scan_block` acknowledges coinbase outputs are "bound by maturity" and says "a post-processing pass is needed to remove those outputs", but the type carries no flag indicating immaturity, so any consumer that uses the returned `Vec<ReceivedOutput>` (or the persisted/serialized form via `ReceivedOutput::read`/`write`) has no way to perform that filtering correctly — an `OutPoint` does not reveal whether its tx is a coinbase without a second chain lookup the API does not provide.

This mirrors the reported bug class: just as `removeReserves` debits `reduceAmount` while the deliverable amount is reduced by a transfer fee, `Scanner` credits the full face value of an output while the actually-spendable value is zero (until maturity) — the reported balance does not equal the spendable balance.

### Impact Explanation
- **Funds reported received that are not spendable**: an accepted impact class. The scanner emits a `ReceivedOutput` whose `value()` counts toward the multisig's usable balance, yet spending it within 100 blocks produces a transaction that fails consensus (`bad-txns-premature-spend-of-coinbase`), not just relay policy.
- **Payout pipeline stall / wasted FROST sessions**: a consumer feeding these outputs into `SignableTransaction::new` and `TransactionMachine` will run a full threshold signing ceremony over a transaction that can never be broadcast, burning nonce material and operator resources each retry.
- **Accounting skew**: downstream balance tracking that trusts `scan_block` results overstates immediately-available reserves by the coinbase amount.

Likelihood of mis-crediting is bounded by requiring a miner to target the script, but mining is permissionless and the script pubkeys are public on-chain; a miner can also do this accidentally via pooled payout addresses colliding with a registered script is negligible, so the practical reach is a deliberate miner.

### Likelihood Explanation
Any Bitcoin miner can place arbitrary outputs in their coinbase transaction, including a P2TR output to the multisig's observed `script_pubkey` (which is public once the vault receives funds). The cost is only the coinbase's own subsidy value, which the miner would control anyway — they can even pay a minimal dust-adjacent amount. No key material, validator position, or collusion is needed. The triggering input is exactly "a Bitcoin transaction they send", per the reachable-inputs rule.

### Recommendation
- In `Scanner::scan_transaction` (or `scan_block`), detect `tx.is_coinbase()` and either skip `txdata[0]` entirely or tag the returned `ReceivedOutput` with a `coinbase`/maturity flag so consumers can enforce `COINBASE_MATURITY` before treating it as spendable.
- Prefer encoding this in the type: e.g. `ReceivedOutput { ..., kind: Normal | Coinbase }` or a `matures_at` field, so the invariant survives `serialize`/`read` round-trips rather than relying on a doc-comment contract for callers.

### Proof of Concept
Conceptual, against `networks/bitcoin/src/wallet/mod.rs`:

1. A miner observes a registered script, e.g. the base vault script `p2tr_script_buf(key)` (matched with `Scalar::ZERO` offset at `mod.rs:164`), or any registered offset script.
2. The miner mines a block whose coinbase `txdata[0].output[0] = TxOut { value: X, script_pubkey: <vault script> }`.
3. Any consumer calls `scanner.scan_block(&block)` (`mod.rs:221-227`), which calls `scan_transaction` on `txdata[0]` (`mod.rs:199-214`) and returns `ReceivedOutput { offset: ZERO, output, outpoint }` reporting `value() == X` (`mod.rs:116-118`).
4. The consumer treats it as a spendable UTXO and builds `SignableTransaction::new(vec![received], ...)`; the resulting signed transaction spends an immature coinbase and is rejected by consensus for 100 blocks — the reported `X` was never spendable.

Supporting code: `scan_transaction` performs no coinbase or maturity check before pushing `ReceivedOutput` [1](#0-0) ; `scan_block` iterates `block.txdata` including the coinbase [2](#0-1) ; `value()` reports the face value [3](#0-2) ; the only mitigation is a doc comment deferring maturity handling to callers [4](#0-3) ; the existing test itself has to mine 100 blocks to maturity before scanning precisely because the scanner doesn't handle this [5](#0-4) .

Note on confidence: I could not fully verify whether the downstream `processor` code (out of scope) applies its own coinbase-maturity filter inside `get_outputs`; if it does, the practical impact is reduced but the in-scope API defect in `bitcoin-serai`'s `Scanner` — reporting face-value, maturity-blind `ReceivedOutput`s — still stands on its own.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
