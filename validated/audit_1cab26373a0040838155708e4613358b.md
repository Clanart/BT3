### Title
Overly-permissive hostname regex in `isGitHubHost` lets an attacker-controlled remote be treated as a trusted GitHub Enterprise host - (File: app/src/lib/api.ts)

### Summary
`isGitHubHost()` uses a loose regex, `/(^|\.)(github)\./`, to decide whether an unknown host "looks like" a GitHub install. Because the regex only requires the substring `github.` to appear at the start of the hostname or immediately after a dot, any attacker-registered domain of the form `github.<attacker-domain>` or `<anything>.github.<attacker-domain>` satisfies it and is classified as a genuine GitHub host, exactly mirroring the Anchor bug class where a validation check meant to enforce "must be the specific trusted entity" instead accepts a broad, attacker-reachable set of values due to a loose equality/pattern check.

### Finding Description
`isGitHubHost` is meant to be a best-effort classifier that only returns `true` for actual GitHub.com/GHE/GHES hosts: [1](#0-0) 

The dangerous branch is:
```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```
This regex does not anchor to the end of the string or require that `github` be the *registrable domain*, only that `github.` appears at the very start of the hostname or right after a `.`. Consequently a hostname such as `github.attacker.com` or `x.github.attacker.com` — fully attacker-controlled, since the attacker owns `attacker.com` — matches and is classified as a GitHub-like host, even though `isKnownThirdPartyHost` and the exact `isDotCom`/`isGHE` checks that run earlier failed to recognize it as such.

This function is consumed directly by the git credential-helper flow, which decides whether an unknown remote should be treated as `'enterprise'` (i.e., a real, sign-in-worthy GitHub host) or `'generic'` (arbitrary git server, handled by plain username/password prompt with no OAuth): [2](#0-1) 

When `getEndpointKind` returns `'enterprise'` for a host the app has no existing account for, `getCredential` invokes `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

This flow is triggered purely by cloning/fetching from a crafted remote URL — the attacker fully controls the endpoint value that reaches `isGitHubHost`, satisfying the "attacker controls a git remote/proxy response" impact category. The "unset/default" collapsing into "trusted" pattern from the Anchor report is reproduced here as "loosely-matched hostname" collapsing into "trusted GitHub host."

### Impact Explanation
If a user adds/clones a remote pointing at `https://github.evil-domain.com` (or any subdomain matching the loose pattern), Desktop's credential helper will believe this is a legitimate GitHub Enterprise Server and prompt the user through `promptForGitHubSignIn`, which begins Desktop's normal GitHub sign-in/OAuth device flow but targets the attacker's endpoint. A user who completes this "GitHub Enterprise sign-in" believing it to be genuine can have their authentication code/token sent to and captured by the attacker-controlled host, leading to account takeover/credential exfiltration. This satisfies the "unauthorized OAuth" / "credential exfiltration" valid-impact categories, requires no local access or pre-existing malware, and results purely from a crafted, attacker-owned remote URL.

### Likelihood Explanation
Likelihood is moderate: it requires the user to add or clone a repository whose remote hostname matches the crafted pattern (e.g., via a malicious "clone this repo" link or an org invite pointing to `github.<attacker-domain>`), and then follow through the resulting sign-in prompt. Since GitHub Desktop routinely prompts credential/sign-in dialogs for unrecognized hosts as normal UX, a user is unlikely to be suspicious, especially given the domain visually contains "github." This is a realistic, low-effort spoofing setup for an attacker (registering a domain, hosting a git-accessible endpoint) rather than a purely theoretical edge case.

### Recommendation
Replace the loose substring regex with strict registrable-domain matching, e.g., verify the hostname's eTLD+1/apex matches an allow-listed GitHub domain suffix set (`endsWith('.github.com')`, exact `'github.com'`, or a properly parsed subdomain boundary check), and never classify a host as GitHub/enterprise based on a regex that can be satisfied by attacker-chosen domain suffixes. Additionally, consider not auto-elevating unknown hosts to the OAuth-capable "enterprise" sign-in path based solely on heuristic hostname matching — require an explicit, user-confirmed "Add Enterprise Server" action before triggering `promptForGitHubSignIn`.

### Proof of Concept
1. Attacker registers `attacker.com` and stands up a git server (or GitHub-Enterprise-Server-like mock) reachable at `https://github.attacker.com`.
2. Attacker sends the victim a link or repo README instructing them to add a remote/clone from `https://github.attacker.com/some/repo.git`.
3. Victim clones/fetches; git invokes Desktop's credential helper for host `github.attacker.com`.
4. `getEndpointKind` → `isGitHubHost('https://github.attacker.com')` → regex `/(^|\.)(github)\./.test('github.attacker.com')` returns `true` → classified `'enterprise'`.
5. Since no existing account matches this endpoint, `getCredential` calls `ui.promptForGitHubSignIn('https://github.attacker.com')`, launching what appears to be a legitimate "Sign in to GitHub Enterprise" flow that actually authenticates against the attacker's server, exfiltrating the resulting token/credentials. [4](#0-3)

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
