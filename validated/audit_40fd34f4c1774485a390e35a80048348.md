### Title
Empty aggregate Schnorr signatures verify as valid - (File: `crypto/schnorr/src/aggregate.rs`)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero nonces and a zero `s` scalar. The deserializer permits an empty `Rs` vector, `verify` only checks that the `Rs` length matches the supplied key/challenge list, and the verification equation then degenerates to `0 * G == identity`. This contradicts `SchnorrAggregator::complete`, which explicitly refuses to produce an aggregate when no signatures were supplied. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
An attacker-controlled byte string can be fed to `SchnorrAggregate::read` with a zero nonce count and a canonical zero scalar. When `verify` is called with an empty `keys_and_challenges` list, no aggregation weights or signer statements are generated. The only remaining statement is `-s * G`; with `s = 0`, the multiexponentiation result is the identity, so verification succeeds. [1](#0-0) [4](#0-3) 

The production aggregation path treats an empty aggregate as invalid and returns `None`, so the verifier accepting this encoding creates an inconsistent verification boundary. [3](#0-2) 

### Impact Explanation
A caller can produce a cryptographically accepted aggregate signature without any private key, nonce, or signer participation. Any consumer that interprets `SchnorrAggregate::verify(...) == true` as proof that the supplied signer list endorsed the associated challenges is vulnerable to accepting a forged empty-set signature. [5](#0-4) 

In the Tendermint integration, this does not by itself create a valid supermajority commit because `verify_commit` separately sums validator weights and requires the result to meet the configured threshold. [6](#0-5) 

### Likelihood Explanation
The forged encoding is deterministic and consists only of a four-byte zero length followed by a canonical zero scalar. No signing key, interaction, brute force, or protocol control is required. [1](#0-0) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify` and `SchnorrAggregate::read`, matching the explicit empty-set rejection in `SchnorrAggregator::complete`. The higher-level `verify_aggregate` implementation should also reject empty signer lists and ensure every claimed signer is a known validator before evaluating the aggregate. [3](#0-2) [7](#0-6) 

### Proof of Concept
For a ciphersuite with a 32-byte scalar encoding, such as the Ristretto ciphersuite used by Tendermint, construct a serialized aggregate containing no `R` values and `s = 0`, then verify it with an empty signer/challenge list. Verification returns `true` even though no signature was aggregated. [1](#0-0) [8](#0-7)
