### Title
Unbounded length-prefix read in `is_atom_canonical()` allows a crafted spend bundle to crash mempool validation - (File: `chia/full_node/mempool_manager.py`)

### Summary
The reported CVE describes a missing bounds check in a size-prefixed element accessor (BSON CodeWScope) that lets an attacker-controlled length value drive pointer arithmetic past the end of an allocated buffer. The analogous pattern in chia-blockchain is `is_atom_canonical()` in `chia/full_node/mempool_manager.py`, which decodes a CLVM atom's variable-length (1–6 byte) size prefix directly out of attacker-supplied `puzzle_reveal`/`solution` bytes without ever checking that enough bytes remain in the buffer before indexing into it.

### Finding Description
`is_atom_canonical()` inspects the tag byte to determine how many additional prefix bytes (`prefix_len`, 0–5) encode the atom length, then loops reading `clvm_buffer[offset]` that many times: [1](#0-0) 

Note the loop at lines 177–181 increments `offset` and dereferences `clvm_buffer[offset]` for `prefix_len` iterations with no check that `offset < len(clvm_buffer)`. If a crafted buffer ends immediately after (or within) the multi-byte size prefix — e.g. a single `\xfc` byte, which signals a 5-byte length prefix — the read walks past the end of the buffer.

This function is called from `is_clvm_canonical()`, which is invoked directly on unvalidated, attacker-controlled bytes for every coin spend during mempool admission: [2](#0-1) [3](#0-2) 

`bytes(coin_spend.puzzle_reveal)` and `bytes(coin_spend.solution)` come straight from a `SpendBundle` submitted over RPC/protocol by any unprivileged spend-bundle submitter, before any Rust CLVM parser has validated the shape of the buffer. This is the earliest point at which an attacker-controlled malformed length prefix hits an unbounded pointer-arithmetic-style access.

In this Python implementation, `bytes`/`memoryview` indexing is bounds-checked by the interpreter, so unlike the C/C++ CodeWScope bug this does not directly yield adjacent heap memory disclosure. Instead, an out-of-range index raises an uncaught `IndexError`. I was not able to confirm from the code I could inspect whether `validate_spend_bundle()` (or its caller in the mempool add path) wraps this call in a broad exception handler that converts it into a rejected/`FAILED` status, or whether the exception propagates and crashes/halts the coroutine processing that spend bundle. I could not locate the call site around `validate_spend_bundle`/`add_spend_bundle` and any surrounding `try/except` due to running out of tool iterations, so this is unverified and should be checked directly in the repository.

### Impact Explanation
If the `IndexError` is not caught somewhere in the mempool admission pipeline, a single unprivileged spend-bundle submission with a truncated/malformed atom length prefix in `puzzle_reveal` or `solution` could raise an unhandled exception during mempool validation, which matches the allowed "spend-triggered transaction-processing halt" impact class for this exercise. If it *is* caught elsewhere and safely converted to a rejection, this reduces to a non-issue (or at most a benign validation-order gap), so the severity is contingent on unverified exception-handling behavior in the caller.

### Likelihood Explanation
The trigger condition is simple and fully attacker-controlled: any spend bundle with a `puzzle_reveal` or `solution` whose bytes end with (or truncate immediately after) a high-bit-count size-prefix tag byte (e.g., `0xFC`, `0xF8`, `0xF0`, etc.) without the corresponding number of trailing bytes. No signature, special coin state, or privileged access is required — any wallet user, offer counterparty, or RPC caller who can submit a spend bundle can attempt it. This makes the trigger trivially reachable, but the actual impact hinges entirely on whether the surrounding code catches the resulting exception.

### Recommendation
Add an explicit bounds check inside `is_atom_canonical()` before dereferencing `clvm_buffer[offset]` in the prefix-parsing loop (mirroring the pattern already used elsewhere in the codebase, e.g. `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`, which explicitly validate `n > len(buf)` before slicing). If `offset >= len(clvm_buffer)` during prefix parsing, return early with a definitive "not canonical" / raise a well-defined `ValueError` rather than allowing an `IndexError` to propagate, and ensure the call site in `validate_spend_bundle()` treats any parsing failure as `Err.INVALID_COIN_SOLUTION` rather than letting an exception escape mempool admission. [4](#0-3) 

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) is exactly the single byte `b"\xfc"`. This tag byte indicates a 6-byte encoding (`(b & 0b11111110) == 0b11111100`) requiring 5 additional length-prefix bytes, but the buffer contains none:

```python

is_clvm_canonical(b"\xfc")  # attempts clvm_buffer[1] on a length-1 buffer -> IndexError
```

Submitting a `SpendBundle` whose `coin_spend.solution == b"\xfc"` (or similarly truncated) would cause `validate_spend_bundle()` to invoke `is_clvm_canonical(bytes(coin_spend.solution))` on this buffer during mempool admission at the cited call site. Because I could not confirm the exception-handling behavior of the caller within the available iterations, verifying whether this produces an unhandled exception (transaction-processing halt) versus a normal rejection requires direct testing against the running mempool code — this should be validated by actually invoking `MempoolManager.add_spend_bundle()` with this crafted solution.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
