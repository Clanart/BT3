### Title
Unredacted sensitive RPC data leaked to daemon log on unknown-command requests - (File: chia/daemon/server.py)

### Summary
`WebSocketServer.handle_message()` logs the full, unredacted incoming daemon message via `self.log.error(f"UK>> {message}")` whenever the `command` field doesn't match a known keychain command, `"ping"`, or an entry in `get_command_mapping()`. This bypasses the `redact_sensitive_data()` protection that is otherwise correctly applied earlier in `incoming_connection()` before the `DEBUG`-level "Received message" log.

### Finding Description
`incoming_connection()` decodes the JSON payload into `decoded` and separately computes a redacted copy (`redacted_data` / `redacted_message`) purely for the purpose of the `self.log.debug("Received message: %s", redacted_message)` call at `chia/daemon/server.py:296-298`. The original, un-redacted `decoded` dict is what gets passed into `handle_message(ws, decoded)` at line 300.

Inside `handle_message()` (`chia/daemon/server.py:408-449`), if the command doesn't match `keychain_commands`, isn't `"ping"`, and isn't present in `self.get_command_mapping()`, the code executes:
```python
self.log.error(f"UK>> {message}")
```
at line 445, printing the entire message dict — including the `data` sub-dictionary — with no redaction whatsoever. Since `ERROR` is a default-enabled log level (unlike `DEBUG`, which requires explicit configuration), any client already connected to the daemon's mTLS websocket (a legitimate local wallet/CLI/GUI client, or any other locally-authorized RPC caller) can send a made-up/unknown `command` string alongside a `data` object containing `mnemonic`, `private_key`, `password`, `passphrase`, or similar fields, and have them written verbatim into the daemon's log file.

### Impact Explanation
An unprivileged or partially-privileged local process with only daemon-websocket read access to log files (e.g., a lower-privileged co-tenant, a misconfigured log-shipping agent, or another local user able to read Chia's log directory) could recover sensitive secrets (mnemonics, private keys, passphrases) that a legitimate client transmitted with an unrecognized command name, mirroring the exact CVE-2021-3528 bug class ("internal RPC AuthTokens... leaked into log files... attacker with access to the log files could use this... to gain additional access"). Here, secrets logged could allow direct compromise of the wallet's keys/funds rather than just a service auth token.

### Likelihood Explanation
Likelihood is moderate: it requires (1) a client already able to connect to the local daemon websocket (which requires possession of daemon TLS client certs — the same access level assumed for other in-scope daemon/RPC threats), and (2) that client sending a command name that the daemon does not recognize while including sensitive data fields under a different key name than the ones caught by the `keychain_commands` allowlist. This could happen due to client/daemon version skew, custom/third-party tooling issuing malformed commands, or a bug/typo in a client. It's a logging bug, not something an attacker fully controls end-to-end, but the redaction mechanism explicitly built to prevent this exact class of issue does not cover this path, which is a genuine gap in an intentionally hardened function.

### Recommendation
Route the unknown-command log message through the same `redact_sensitive_data()` helper used in `incoming_connection()`, e.g.:
```python
self.log.error(f"UK>> {redact_sensitive_data(message)}")
```
or better, refactor so `handle_message()` receives (or has access to) the already-redacted message for any logging purposes, ensuring no code path logs raw request data. Additionally, consider adding a regression test analogous to `test_message_logging_redaction` that specifically targets the unknown-command branch.

def redact_sensitive_data(obj: Any, redaction_triggers: Collection[str] = ("pass", "key", "secret", "mnemonic")) -> Any:
    """Recursively redact sensitive data from nested dictionaries."""
    if isinstance(obj, dict):
        return {
            key: "***<redacted>***"
            if any(trigger.casefold() in key.casefold() for trigger in redaction_triggers)
            else redact_sensitive_data(value, redaction_triggers)
            for key, value in obj.items()
        }
    else:
        return obj

    async def handle_message(
        self, websocket: WebSocketResponse, message: WsRpcMessage
    ) -> tuple[str, set[WebSocketResponse]] | None:
        """
        This function gets called when new message is received via websocket.
        """

        command = message["command"]
        destination = message["destination"]
        if destination != "daemon":
            if destination in self.connections:
                sockets = self.connections[destination]
                return dict_to_json_str(message), sockets

            return None

        data = message["data"]
        commands_with_data = [
            "start_service",
            "start_plotting",
            "stop_plotting",
            "stop_service",
            "is_running",
            "register_service",
        ]
        if len(data) == 0 and command in commands_with_data:
            response = {"success": False, "error": f'{command} requires "data"'}
        # Keychain commands should be handled by KeychainServer
        elif command in keychain_commands:
            response = await self.keychain_server.handle_command(command, data)
        elif command == "ping":
            response = await ping()
        else:
            command_mapping = self.get_command_mapping()
            if command in command_mapping:
                response = await command_mapping[command](websocket=websocket, request=data)
            else:
                self.log.error(f"UK>> {message}")
                response = {"success": False, "error": f"unknown_command {command}"}

        full_response = format_response(message, response)
        return full_response, {websocket}
