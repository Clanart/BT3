I found a concrete, locally-provable vulnerability in the object ownership machinery that the publish/init flows depend on.### Title
Unbounded cycle in `object::root_owner()` lets any object owner permanently brick republish and lazy self-init on that object - ([File: aptos-move/framework/aptos-framework/sources/object.move])

### Summary
`code::publish_package` (used by both direct and object-based code publishing/upgrade flows) and `init::assert_may_self_initialize` (the lazy module self-init gate) both call `Object::root_owner()` to determine the transitive owner of a code object. Unlike the sibling ownership-traversal functions `owns()` and `verify_ungated_and_descendant()`, `root_owner()` has no bound on the number of hops it will traverse. Any object owner can trivially create a self-referencing ownership cycle with a single, unprivileged `object::transfer` call, after which every future call to `root_owner()` on that object loops until gas exhaustion, permanently blocking legitimate code republish/upgrade and module self-initialization on that object.

### Finding Description
`root_owner()` walks the owner chain without any depth limit: [1](#0-0) 

Compare this to the two other ownership-chain walkers in the same module, both of which explicitly bound iteration with `MAXIMUM_OBJECT_NESTING` and abort with `EMAXIMUM_NESTING` if exceeded: [2](#0-1) [3](#0-2) 

Critically, `transfer_raw`/`verify_ungated_and_descendant` permits a *direct self-transfer* of an object to its own address without hitting the depth check, because the check only walks up from the object's *current* owner toward the caller — and if the caller is already the current owner, the loop body never executes: [4](#0-3) 

This exact self-loop scenario is demonstrated (and expected to succeed on the first call) in the module's own test: [5](#0-4) 

Once `ObjectCore.owner == object_address` (a genuine cycle), `root_owner()`'s `while (is_object(obj_owner))` loop never terminates through normal means — it only stops via gas exhaustion, aborting the transaction that invoked it.

`root_owner()` is exactly the function relied upon by the publish path to record and validate code-object ownership for lazy initialization: [6](#0-5) 

and by the module self-init guard used at runtime by any module hosted on that object: [7](#0-6) 

Both `code::publish_package` (invoked by `object_code_deployment::publish`/`upgrade`, and therefore by `large_packages` chunked publishing) and `init::internal_maybe_initialize` are gated on this unbounded call whenever the object is address-hosted and lazy module initialization is enabled.

### Impact Explanation
Once an object hosting Aptos-framework code has a cyclic owner chain (trivially created by that object's own current owner with one `object::transfer` call), every subsequent transaction that:
- republishes/upgrades code on that object via `code::publish_package` → `object_code_deployment::upgrade` (and `large_packages::stage_code_chunk_and_upgrade_object_code`), or
- calls any entry function that triggers `init::internal_maybe_initialize` for a module hosted on that object,

will hang in the unbounded `root_owner()` loop until it runs out of gas and aborts. This permanently denies legitimate code upgrades/republishing and lazy self-initialization for that object — a direct analog of the seed report's "legitimate operation permanently blocked" pattern, but here rooted in an unbounded on-chain traversal in the object/code-ownership model rather than a governance-configurable threshold. Any user transaction that needs to invoke a self-initializing module on the bricked object is also denied service (their gas is consumed and the call fails), which extends the impact beyond the object owner to any third party depending on that module's functionality.

### Likelihood Explanation
Likelihood is high: creating the self-cycle requires only a single unprivileged `object::transfer(owner, obj, obj.object_address())` call by the object's current owner — no special permissions, no race condition, and it is demonstrated as a supported (non-reverting) first step in the framework's own test suite. An attacker who deploys code to an object (or acquires ownership of one) can immediately self-cycle it to prevent themselves or a future owner from ever upgrading/self-initializing it again, or to grief dependents of a shared/lazy-init module.

### Recommendation
Bound `root_owner()`'s traversal the same way `owns()` and `verify_ungated_and_descendant()` are bounded: track a hop counter against `MAXIMUM_OBJECT_NESTING` and abort with `EMAXIMUM_NESTING` (or return a best-effort owner) instead of looping unboundedly. This should be applied before any of `code::publish_package`'s or `init::assert_may_self_initialize`'s callers can be reached with a cyclic ownership graph.

### Proof of Concept
1. Publish a code object via `object_code_deployment::publish` with the `LAZY_MODULE_INITIALIZATION` feature enabled, producing object address `O` owned by account `A`.
2. `A` calls `object::transfer(A, O, O)` — this succeeds per `verify_ungated_and_descendant` because `O`'s current owner is already `A`, so the depth-check loop never executes; `ObjectCore.owner` at `O` is now set to `O` itself (self-cycle), matching the framework's own `test_cyclic_ownership_transfer_should_fail` first step.
3. `A` (or anyone) calls `object_code_deployment::upgrade` on `O`, which calls `code::publish_package`, which calls `object::address_to_object<ObjectCore>(O).root_owner()`.
4. `root_owner()`'s `while (is_object(obj_owner))` loop repeatedly resolves `O`'s owner to `O`, never terminating; the transaction runs until it exhausts its gas budget and aborts.
5. Any subsequent attempt to upgrade code on `O`, or to trigger `internal_maybe_initialize` for a module hosted at `O`, reproduces the same unbounded loop and fails — permanently.

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    /// Return true if the provided address has indirect or direct ownership of the provided object.
    ///
    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }
