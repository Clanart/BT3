### Title
`ManualCompound.compound()` lacks reentrancy protection while distributing live token balances - (File: rewards/ManualCompound.sol)

### Summary
`compound()` performs external calls (`multiclaimOnBehalf`, `convertFor`, `lockFor`, `depositFor`, `safeTransfer`) and then settles funds to `msg.sender` purely from `IERC20(...).balanceOf(address(this))` reads, with no `nonReentrant` guard. Because the settlement logic iterates the entire global `rewards` array (not the caller's specific claim) and sweeps whatever balance currently sits on the contract, a reward/transfer-hook token can be used to re-enter `compound()` mid-loop and drain balances belonging to tokens not yet processed by the outer call.

### Finding Description
`compound()` at [1](#0-0)  does two passes:
1. Claims rewards on behalf of `msg.sender` via `multiclaimOnBehalf` and forwards non-compoundable tokens back to the caller based on a live `balanceOf` read [2](#0-1) .
2. Iterates the entire global `rewards` array (configured by the owner, independent of what the caller actually claimed) and, for each configured token, reads `IERC20(_tokenAddress).balanceOf(address(this))` and forwards/convert/locks/deposits the *entire* balance to `msg.sender` [3](#0-2) .

No `nonReentrant` modifier exists anywhere in the contract, and none of `Ownable`'s inherited functionality provides reentrancy protection [4](#0-3) . Because settlement in the second loop is keyed only on live contract balance and iterates sequentially over `rewardTokensLength`, if any configured reward token has a transfer hook (e.g., ERC777-style, or a convertor/helper contract callback), a malicious caller can reenter `compound()` during the `safeTransfer`/`convertFor`/`lockFor`/`depositFor` call for token index `i`. In the reentrant call, tokens at index `> i` that already have a nonzero balance (left over from a previous compound's rounding, or from another in-flight claim not yet swept) will be swept in full to the attacker before the outer call reaches them, leaving the outer call with a zero balance for that token and no crediting owed to its rightful claimant.

This matches the stated precondition: a previous compound leaving residue of a configured reward token is sufficient for the outer/inner-call race to cause `balanceOf` at settlement time to diverge from the caller's actual entitled share.

### Impact Explanation
Whoever wins the race to consume the outstanding balance receives tokens that were not part of their own claim, i.e., direct theft of another user's (or the previous compounder's) unclaimed reward residue. Since settlement value is unbounded by any per-user accounting, this can scale with whatever residual balance accumulates on the contract, matching Critical - Direct theft of user funds.

### Likelihood Explanation
Exploitability requires: (1) at least one configured reward token in `rewards` supports a transfer/callback hook (or one of the configured `convertor`/`locker`/`tokenHelper` contracts calls back into the attacker's contract during its external call), and (2) a residual balance of a not-yet-processed reward token exists at the time of reentry. Reward-token selection and convertor/locker/helper wiring are controlled by the owner via `addReward`/`setConvertor`/`setLocker`/`setHelper` [5](#0-4) , so whether a hook-bearing token is ever configured is a deployment-specific condition, not something the attacker controls. No source in the current file confirms any deployed reward token has hook/callback behavior.

### Recommendation
Add `nonReentrant` (OpenZeppelin `ReentrancyGuard`) to `compound()`, and additionally track and settle per-call claimed amounts rather than sweeping the entire live `balanceOf(address(this))`, so unrelated residual balances cannot be attributed to an unrelated caller.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `ManualCompound` with `masterMagpie` mock, and configure two reward tokens: token A (mock ERC777-like token with `_beforeTokenTransfer`/receive hook that calls back into `compound()`) and token B (plain ERC20).
2. Seed the contract with a residual balance of token B (simulating leftover from a prior compound) without any corresponding claim.
3. Have `masterMagpie` mock's `multiclaimOnBehalf` mint/transfer token A to the `ManualCompound` contract as the attacker's legitimate claim.
4. Call `compound()` from the attacker; on token A's transfer-out at line 157/149/etc., trigger reentrancy into `compound()` again before token B is processed by the outer call.
5. Assert the attacker receives token B's residual balance in the reentrant call, and the outer call's iteration over token B settles to zero — i.e., `IERC20(tokenB).balanceOf(address(this))` no longer reconciles with the amount actually owed to the original depositor, demonstrating a withdrawal exceeding the attacker's rightful claim.

    function compound(address[] calldata _lps, address[][] calldata _rewards, uint256 _convertRatio, uint256 _minRec, bool _lockMgp) external {
        uint256 rewardTokensLength = rewards.length;        
        IMasterMagpie(masterMagpie).multiclaimOnBehalf(_lps, _rewards, msg.sender);
        // send none compoundable reward back to caller
        for(uint256 i; i < _lps.length; i++) {
            uint256 rewardLength = _rewards[i].length;
            if (rewardLength > 0) {
                for (uint j; j < rewardLength; j++) {
                    if (!compoundableRewards[_rewards[i][j]]) {
                        uint256 rewardBalance = IERC20(_rewards[i][j]).balanceOf(address(this));
                        if (rewardBalance > 0)
                            IERC20(_rewards[i][j]).safeTransfer(msg.sender, rewardBalance);
                    }
                }
            }
        }
        for (uint256 i; i< rewardTokensLength; i++) {
            address _tokenAddress = rewards[i].tokenAddress;
            address _helperAddress = rewards[i].tokenHelper;
            address _convertor = rewards[i].convertor;
            address _locker = rewards[i].locker;
            uint256 receivedBalance = IERC20(_tokenAddress).balanceOf(address(this));

            if (receivedBalance > 0) {
                if (_convertor != address(0)) {
                    IERC20(_tokenAddress).safeApprove(_convertor, receivedBalance);
                    IConverter(_convertor).convertFor(receivedBalance, _convertRatio, _minRec, msg.sender, 2);
                } else if (_locker != address(0) && _lockMgp) {
                    IERC20(_tokenAddress).safeApprove(_locker, receivedBalance);
                    ILocker(_locker).lockFor(receivedBalance, msg.sender);                        
                } else if (_helperAddress != address(0)) { 
                    IERC20(_tokenAddress).safeApprove(_helperAddress, receivedBalance);
                    ISimpleHelper(_helperAddress).depositFor(receivedBalance, msg.sender);
                } else {
                    IERC20(_tokenAddress).safeTransfer(msg.sender, receivedBalance);
                }
            }
        }

        emit Compounded(msg.sender, rewardTokensLength, _lockMgp);
    }
