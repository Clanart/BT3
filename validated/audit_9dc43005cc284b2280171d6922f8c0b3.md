### Title
Sideways `git checkout`/branch-switch defeats `compute_v2_review_set`, silently skipping security review of committed malicious code - (`plugins/security-guidance/hooks/diffstate.py`)

### Summary
The Stop hook's review set is computed purely from git state via `compute_v2_review_set`, which only includes commit-range diffs when the current `HEAD` is a *forward descendant* of `head_at_capture` (checked with `_is_ancestor`). A sideways `HEAD` move — e.g. `git checkout -b`/`git switch --orphan` to an unrelated ref, or checking out any pre-existing branch/commit that is not a descendant of the turn's captured baseline — followed by a commit there leaves the working tree clean, so `dirty_now` (derived only from `git status --porcelain`) is empty, and the intersection `dirty_now & changed_since` becomes empty regardless of what actually changed. The Stop hook then exits via the "empty review set" skip path without ever running the LLM security review.

### Finding Description
`handle_user_prompt_submit` in `security_reminder_hook.py` captures `head_at_capture` and a stash-based `baseline_sha` at the start of each turn [1](#0-0) . At Stop time, `compute_v2_review_set` builds the reviewable file set as:

```
review_set = dirty_now ∩ changed_since
```

where `dirty_now` starts from `git status --porcelain` (tracked+untracked dirt) and is only unioned with `head_at_capture..HEAD` commit-range files **when `_is_ancestor(head_at_capture, current_head)` is true** [2](#0-1) . `_is_ancestor` uses `git merge-base --is-ancestor`, which is only true when `HEAD` moved *forward* (commit/merge) from the captured baseline [3](#0-2) .

If, within the same turn, Claude (driven by attacker-controlled task text, e.g. prompt injection embedded in repo/task content) performs ordinary git operations that move `HEAD` sideways instead of forward — e.g. `git checkout -b newbranch <unrelated-ref>` or checking out an existing unrelated branch/commit, then commits the malicious file there — the sequence has this effect:
1. The malicious edit is committed, so the working tree becomes clean; `git status --porcelain` reports nothing dirty.
2. `current_head` is not a descendant of `head_at_capture`, so `_is_ancestor` returns `False`, and the commit-range term is never added to `dirty_now`.
3. `dirty_now` is therefore empty, so `review_set = dirty_now ∩ changed_since = ∅` regardless of `changed_since` (which is derived from the unrelated stash `baseline_sha` and could still show the file as different).

In `handle_stop_hook`, `compute_v2_review_set` is the sole source of `review_paths`; when it returns `[]` the hook takes the `_skip(9, touched_paths_count=len(touched_paths))` path and exits with code 0, never invoking the LLM vulnerability scan or the `exit(2)` forced-remediation gate [4](#0-3) . Note `touched_paths` (recorded per-edit at PostToolUse) is only surfaced as a metrics counter here, not used as a fallback review source, so pattern-hook coverage on that file is the only remaining layer, and pattern rules are narrower regex-only checks, not the LLM diff review.

### Impact Explanation
This breaks the stated invariant that the review set must stay bound to the right repo, baseline, and touched paths: a sideways branch move decouples the review set from the actual dangerous change even though the file was genuinely authored/modified in-session. Because the Stop hook's LLM review and its `exit(2)` continue-until-fixed enforcement is the plugin's primary control gating whether Claude Code treats a change as reviewed, an attacker able to steer the agent's Bash usage (via repo content, task instructions, or any other injected text reaching the model) can get dangerous code committed and have it treated as "no changes since baseline" — i.e., unreviewed — enabling unauthorized local command execution / malicious code to persist without triggering the plugin's approval-like remediation loop.

### Likelihood Explanation
This requires no special privilege beyond what any Claude Code session already has: normal `git checkout -b`/`git switch` plus `git commit` inside the working repo, both ordinary operations the agent performs routinely. It is deterministic and repeatable — the ancestor check is a straightforward reachability test, and any sequence that puts `HEAD` on a non-descendant commit while leaving the tree clean triggers it every time.

### Recommendation
Do not gate the commit-range term on `_is_ancestor`; instead always include `git diff --name-only <baseline_sha or head_at_capture>..HEAD` regardless of ancestry direction, or independently diff the *content* of `HEAD` (whatever it now is) against `baseline_sha`/`head_at_capture` without requiring a linear ancestor relationship. Additionally, fall back to `touched_paths` (already recorded at PostToolUse) as a union input to the review set rather than only using it for a metrics counter, so that files Claude is known to have edited/created this turn are never dropped purely because of `HEAD` topology changes.

### Proof of Concept
Integration test targeting `compute_v2_review_set` directly (bypassing LLM/API concerns):
1. Init a repo, create `initial.txt`, commit (`H0`). Capture `head_at_capture = H0`, `baseline_sha = capture_git_baseline(cwd)` (stash-create on clean tree returns `H0`).
2. `git checkout -b evil <some other unrelated existing commit or `git switch --orphan evil`>` (simulate sideways move away from `H0`).
3. Write `backdoor.py` with dangerous content (e.g. `os.system(user_input)`), `git add backdoor.py && git commit -m "evil"` → `H1`, clean tree afterward.
4. Call `compute_v2_review_set(cwd, baseline_sha=H0, head_at_capture=H0, untracked_at_baseline={})`.
5. Assert (expected/desired invariant): `backdoor.py` is present in the returned `review_paths`.
6. Actual (bug): `review_paths == []` because `dirty_now` is empty (`git status` clean) and `_is_ancestor(H0, H1)` is `False`, so the commit-range union never fires — demonstrating the review set silently drops a genuinely dangerous, session-authored file.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
