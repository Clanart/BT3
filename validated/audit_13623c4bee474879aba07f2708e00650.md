## Analog Identified

The Phala report's core failure pattern — a **validity/invalidation flag that is checked correctly by the "read" path but silently bypassed by a "write/merge" path**, letting previously-invalidated data be "reactivated" — has a structural analog in `InternalLazyField` (the Java lazy-extension-field cache introduced for lazy parsing of message-typed extensions).

### Title
Corrupted lazy-extension field can be silently "healed" and reparsed via `InternalLazyField.mergeFrom` bypassing the corruption gate - (File: `java/core/src/main/java/com/google/protobuf/InternalLazyField.java`)

### Summary
`InternalLazyField` caches the raw bytes of a lazily-parsed extension message and tracks a `corrupted` flag once a parse attempt fails, so that repeated access is guaranteed to keep failing (`ensureInitialized()` throws `"Repeat access to corrupted lazy field"` if `corrupted` is true) [1](#0-0) . However, `InternalLazyField.mergeFrom(InternalLazyField, CodedInputStream, ExtensionRegistryLite)` — invoked when a message-typed extension field appears more than once across `mergeFrom` calls with the same `ExtensionRegistry` — never checks `corrupted` before concatenating the new wire bytes onto the (potentially already-invalid) existing bytes and constructing a *brand-new* `InternalLazyField`, whose `corrupted` flag defaults back to `false` [2](#0-1) .

### Finding Description
The class's own invariant states the `corrupted` flag exists specifically "to avoid repeat parsing attempts on invalid bytes" [3](#0-2) , and `getValue()` treats a corrupted field as a permanent, non-recoverable error state when lazy-extension enforcement is on, throwing `InvalidProtobufRuntimeException` [4](#0-3) . This mirrors the Phala `LocalCache::get`, which checks `expire_at` before returning a value — i.e., the "read" path faithfully enforces the invalidation.

The bypass is in the "write/merge" path. `MessageReflection.mergeMessage()` routes a *second* occurrence of the same lazy extension field number (when `hasField(field)` is already true) straight into `InternalLazyField.mergeFrom(lazyField, input, extensionRegistry)` [5](#0-4) . Inside that method, the fast path only checks `lazyField.hasBytes()` and registry identity — not `lazyField.corrupted` — before concatenating and returning a fresh `InternalLazyField` object (whose constructor unconditionally sets `corrupted = false`) [6](#0-5) . This is the exact analog of `set_expire` calling only `maybe_clear_expired()` and then unconditionally resetting `expire_at` without checking whether the entry was already expired.

Concretely: if a caller merges bytes for an extension field, later triggers a parse failure on it (setting `corrupted = true`, e.g. via `getValue()`, `hashCode()`, `equals()`, or `toString()`), and then performs a further `mergeFrom` with additional wire bytes for the same field using the same `ExtensionRegistry`, the resulting field silently loses its `corrupted` marker and its stale, previously-rejected bytes are concatenated with new bytes and queued for a fresh parse attempt — exactly the "reactivation" pattern from the report.

### Impact Explanation
This does not lead to memory corruption; it is a data-integrity/consistency issue analogous to the Medium-severity Phala finding. The `corrupted` flag is documented as a hard guarantee against re-processing invalid bytes and against throwing `InvalidProtobufRuntimeException` on every subsequent access when `lazyExtensionEnabled()` is set. An application that relies on that guarantee (e.g., to detect and permanently reject a poisoned extension payload) can have that guarantee silently voided by a subsequent `mergeFrom` call, causing formerly-invalid bytes to be concatenated with new input and reparsed as if nothing was wrong — potentially producing a "successfully parsed" value assembled from a mix of a previously-rejected byte sequence and new attacker-supplied bytes.

### Likelihood Explanation
Reachability requires: (1) an extension field whose type is a message and for which `ExtensionRegistryLite.lazyExtensionEnabled()` is true, (2) the field is not part of `descriptor.proto` types, (3) two or more `mergeFrom`/`ParseFrom`-style merges of that field on the same builder with the same `ExtensionRegistry` instance, and (4) some intervening access (`getValue()`/`hashCode()`/`equals()`/`toString()`) that forces the first parse attempt to fail and set `corrupted = true` before the second merge occurs. This is a plausible but non-trivial multi-step sequence dependent on application-level merge/inspection patterns rather than a single-call `ParseFrom` reachable purely via wire bytes; likelihood is therefore moderate, not high.

### Recommendation
In `InternalLazyField.mergeFrom(InternalLazyField, CodedInputStream, ExtensionRegistryLite)`, check `lazyField.corrupted` before taking the byte-concatenation fast path; if the field is already corrupted, either force a full re-parse via `ensureInitialized()` (surfacing `InvalidProtobufRuntimeException` as designed) or propagate the `corrupted` state into the newly constructed `InternalLazyField` rather than silently resetting it.

### Proof of Concept
1. Enable lazy extension parsing (`ExtensionRegistry` with `lazyExtensionEnabled()` true) and register a message-typed extension field not part of `descriptor.proto`.
2. Build a message containing that extension with intentionally invalid nested-message bytes; merge these bytes into a `Builder` (creates an `InternalLazyField` with `delayedBytes`, `corrupted = false`).
3. Force initialization (e.g., call `builder.getExtension(...)` or serialize/compare the builder) so `ensureInitialized()` fails and sets `corrupted = true` per [7](#0-6) .
4. Merge a second occurrence of the same extension field (same `ExtensionRegistry`) into the same builder via `mergeFrom(CodedInputStream, ExtensionRegistry)`; observe that `MessageReflection.mergeMessage()` routes to `InternalLazyField.mergeFrom(lazyField, input, extensionRegistry)` [5](#0-4) .
5. Inspect the resulting `InternalLazyField`: its `corrupted` field is `false` (fresh object), and a subsequent `getValue()` call reparses the concatenated bytes rather than throwing `InvalidProtobufRuntimeException`, confirming the invalidation state was bypassed.

  static InternalLazyField mergeFrom(
      InternalLazyField lazyField, CodedInputStream input, ExtensionRegistryLite extensionRegistry)
      throws IOException {
    if (lazyField.isEmpty()) {
      return new InternalLazyField(lazyField.defaultInstance, extensionRegistry, input.readBytes());
    }

    if (lazyField.hasBytes()) {
      if (lazyField.extensionRegistry == extensionRegistry) {
        ByteString inputBytes = input.readBytes();
        if (inputBytes.isEmpty()) {
          return lazyField;
        }
        return new InternalLazyField(
            lazyField.defaultInstance, extensionRegistry, lazyField.bytes.concat(inputBytes));
      }

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.

        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
