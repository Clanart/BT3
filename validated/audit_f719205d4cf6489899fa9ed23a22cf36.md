### Title
`updateRemoteUrl` silently rewrites the trusted git remote based on an untrusted GitHub API `clone_url`, without validating the destination host - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
The bug-class in the report is: an invariant (the AMM price/parameter) that users assume changes gradually is instead flipped atomically and unconditionally from an external/decision input, and the guard rails that exist (precision-multiplier bookkeeping) never check whether the *new* value is actually safe relative to the real world — only that the arithmetic is internally consistent. The Desktop analog is `updateRemoteUrl()`, which silently overwrites the repository's `origin` remote URL — a value the user explicitly configured and that determines where every future `fetch`/`push`/credential exchange goes — using the `clone_url` field taken straight from a GitHub API repository object, with checks that validate internal consistency (protocol match, "hasn't been manually changed") but never validate that the *host/owner* the API is telling Desktop to push/pull from is still trustworthy.

### Finding Description
`updateRemoteUrl` is called during repository refresh (`withRefreshedGitHubRepository` flows in `app/src/lib/stores/app-store.ts`, which calls it via the git-store/repositories-store update path) whenever the associated `GitHubRepository` API record is re-fetched: [1](#0-0) 

The function computes `urlsMatch` (does the current `origin` remote match the incoming `clone_url`?) and `remoteUrlUnchanged` (does the current `origin` remote match the *previously cached* `clone_url`?), and if the protocol scheme matches and the remote hasn't diverged from the last known value, it directly calls `gitStore.setRemoteURL(...)` to rewrite the remote: [2](#0-1) 

The only guard is `protocolsMatch` (https vs https, or ssh vs ssh) — there is **no check that the hostname or owner is unchanged or expected**. `setRemoteURL` just runs `git remote set-url` unconditionally: [3](#0-2) 

This mirrors the reported flaw precisely: the "safety" logic (`protocolsMatch`, `remoteUrlUnchanged`) only protects against *drift/inconsistency bookkeeping*, exactly like the Swap contract's precision-multiplier logic only ensured internal price-formula consistency without validating that an instantaneous jump was economically safe. Here, the instantaneous jump is the remote endpoint that all future git network operations (and any embedded credentials via `envForRemoteOperation`) will be sent to.

### Impact Explanation
The GitHub API response object (`IAPIRepository`/`IAPIFullRepository.clone_url`) is exactly one of the attacker-controllable inputs the task scope calls out. Any actor capable of controlling API data returned for a repository the victim has added an account to — most plausibly a malicious/compromised GitHub Enterprise Server the user authenticated against, or a man-in-the-middle/compromised proxy on that GHES endpoint — can set `clone_url` to an attacker-controlled host with the same URL scheme as the user's real remote. Because `remoteUrlUnchanged` only compares against the *last cached* `clone_url` (not against a signed/pinned value), and there is no hostname allow-list, Desktop will call `git remote set-url origin <attacker-url>` silently, with no dialog, confirmation, or diff shown to the user. From that point on:
- Every subsequent `fetch`/`pull`/`push` (and the credentials Desktop injects via `envForRemoteOperation`) goes to the attacker's endpoint — silent corruption/exfiltration of what the user pushes and their push credentials.
- Any code the user believed was going to their real remote can be captured or replaced by the attacker's server.

### Likelihood Explanation
Exploitation requires the victim's account/endpoint to be one where the attacker controls (or can influence) API responses — realistic for a rogue/compromised GitHub Enterprise Server, but not for github.com itself absent a GitHub-side compromise. No local access, malware, or leaked credentials are needed; the attack fires purely from data the client already trusts and periodically re-fetches during normal repository refresh.

### Recommendation
Do not silently rewrite `origin` based solely on `clone_url` equality bookkeeping. At minimum:
- Validate that the hostname/owner of the incoming `clone_url` matches the account's known/pinned endpoint before calling `setRemoteURL`.
- Surface a confirmation prompt to the user when the remote host is about to change, rather than performing the rewrite silently.
- Treat `clone_url` changes as security-sensitive events subject to the same scrutiny as, e.g., changing a repository's owner/parent.

### Proof of Concept
1. Victim signs into a GitHub Enterprise Server account in Desktop and has a repository whose `origin` remote and cached `GitHubRepository.cloneURL` both point to `https://ghe.victim.example/org/repo.git`.
2. The (compromised/malicious) GHES server later returns an API repository object for that same `dbID` with `clone_url: "https://ghe.attacker.example/org/repo.git"` (same `https` scheme).
3. On the next background repository refresh, `updateRemoteUrl` computes `protocolsMatch = true`, `remoteUrlUnchanged = true` (matches previously cached value), `urlsMatch = false`, and calls: [4](#0-3) 
4. `gitStore.setRemoteURL('origin', 'https://ghe.attacker.example/org/repo.git')` runs `git remote set-url origin ...` with no user prompt. [3](#0-2) 
5. The victim's next push/fetch/pull silently targets the attacker's server.

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

/** Changes the URL for the remote that matches the given name  */
export async function setRemoteURL(
  repository: Repository,
  name: string,
  url: string
): Promise<true> {
  await git(['remote', 'set-url', name, url], repository.path, 'setRemoteURL')
  return true
}
