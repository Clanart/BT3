### Title
Missing zero-check on governance-controlled `GasTarget` causes division-by-zero panic in KIP-71 base fee calculation - (File: `params/kip71_config.go`)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without ever checking it for zero, unlike the sibling `BaseFeeDenominator` parameter which has an explicit zero-guard. Because `Kip71GasTarget`'s governance `FormatChecker` is `noopFormatChecker` (no validation), a governance vote setting `GasTarget = 0` will propagate into every node's per-block base-fee computation and panic with an integer division-by-zero, matching the JLSEC-2026-881 bug class (math division by zero in a value-processing routine leading to availability loss).

### Finding Description
`NextMagmaBlockBaseFee` computes the next block's base fee under KIP-71/Magma: [1](#0-0) 

The function explicitly guards against `BaseFeeDenominator == 0` ("To avoid panic, set the fluctuation range small"): [2](#0-1) 

But `gasTarget := kc.GasTarget` receives no equivalent guard, and is used directly as a divisor in both the increase and decrease branches: [3](#0-2) [4](#0-3) 

`big.Int.Div`/`DivMod` panics on a zero divisor in Go's `math/big` package, so whenever `parentGasUsed != gasTarget` (true for essentially any block once `GasTarget` is 0, since any nonzero gas usage differs from 0), the call to `x.Div(x, new(big.Int).SetUint64(gasTarget))` panics.

The root cause of reachability is that the governance parameter registry validates `Kip71BaseFeeDenominator` with an explicit non-zero `FormatChecker` but validates `Kip71GasTarget` with `noopFormatChecker`, which performs no validation at all: [5](#0-4) 

This asymmetry (one KIP-71 parameter is protected, the sibling one used identically as a divisor is not) demonstrates the developers were aware of the division-by-zero risk for this formula but missed applying the same protection to `GasTarget`.

### Impact Explanation
`NextMagmaBlockBaseFee` is called on the hot consensus/block-production path by every node, including header validation and block/base-fee generation (called from `blockchain/chain_makers.go`, `blockchain/tx_pool.go`, `work/worker.go`, and `node/cn/gasprice/gasprice.go` / `feehistory.go`). A governance-approved `GasTarget = 0` would cause every full node, CN, and RPC-serving node to panic simultaneously the moment they compute a base fee for a block with nonzero gas usage — i.e., a chain-wide halt/crash affecting block production, tx pool base-fee logic, gas price oracle, and `eth_feeHistory` RPC. This is a genuine availability impact consistent with the CVSS vector in the advisory (`C:N/I:N/A:H`).

### Likelihood Explanation
Exploitation requires a governance parameter change to `Kip71GasTarget` to reach the value `0`, which is gated by the governance/voting mechanism (privileged to governance council members, not an arbitrary unprivileged transaction sender). This weakens direct "any user" reachability, but it is squarely within the "governance parameters" category the scan explicitly treats as in-scope. Given `noopFormatChecker` performs no bound/non-zero validation, nothing in the vote-application path prevents this value from being accepted and canonicalized once a qualifying vote passes.

### Recommendation
Add an explicit non-zero `FormatChecker` for `Kip71GasTarget` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check) in `kaiax/gov/param.go`, and/or add a defensive zero-check with a safe fallback for `gasTarget` inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, analogous to the existing `BaseFeeDenominator == 0` guard.

### Proof of Concept
1. Governance council votes to set `Kip71GasTarget` (`GasTarget`) to `0` — accepted because `FormatChecker: noopFormatChecker` performs no validation (`kaiax/gov/param.go:324-334`).
2. The new `ParamSet` with `GasTarget = 0` is applied to `KIP71Config` and used by `NextMagmaBlockBaseFee` (`params/kip71_config.go:58-129`).
3. On the next block where `parentGasUsed > 0` (virtually guaranteed), the code executes `parentGasUsed > gasTarget` (since `gasTarget = 0`), reaching:
   ```go
   gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
   x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
   y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // gasTarget == 0 → panic: division by zero
   ```
4. Every node computing this header/base fee (block validators, block producers, gas price oracle, `eth_feeHistory`) panics simultaneously, halting the chain.
