## Title
`aptos move verify-package` never compares deployed bytecode, only self-reported metadata — publishers can present verified-looking source while different bytecode is on-chain - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
`code::publish_package_txn` takes `metadata_serialized` (containing `manifest`, per-module `source`, `source_map`, and `source_digest`) and `code` (the actual compiled bytecode) as two **independent** transaction arguments [1](#0-0) . The framework only checks that the module *names* in `code` match the names declared in `pack.modules` (via `expected_modules`/`request_publish`) [2](#0-1) . Nothing on-chain cryptographically binds `manifest`, `source`, `source_map`, or `source_digest` to the actual bytecode bytes stored for a module.

The CLI's `aptos move verify-package` command is the tool users rely on to confirm "on-chain bytecode matches a local source tree" [3](#0-2) . Its implementation fetches the on-chain `PackageRegistry` **without bytecode** (`with_bytecode = false`) and only calls `CachedPackageMetadata::verify`, which does a field-by-field comparison of self-reported metadata: `name`, `deps`, `modules` (name + gzipped `source` string + `source_map`), `manifest`, `upgrade_policy`, `extension`, and `source_digest` [4](#0-3) [5](#0-4) . It never fetches or diffs the actual on-chain module bytecode against the freshly-compiled bytecode.

### Finding Description
- `CachedPackageRegistry::create` accepts a `with_bytecode` flag; `VerifyPackage::execute` calls it with `false` [6](#0-5) , so `self.bytecode` (the `BTreeMap<module_name, Vec<u8>>`) stays empty [7](#0-6) .
- `VerifyPackage` then calls `package.verify(&compiled_metadata)` [8](#0-7) , which only compares `PackageMetadata` fields, never the module bytecode itself [4](#0-3) .
- The `modules` field being compared (`ModuleMetadata.source` and `.source_map`) is just gzipped source text and a source map — auxiliary, self-supplied artifacts, not the executable bytecode [9](#0-8) .
- On the publish path, `code::publish_package_txn` deserializes `metadata_serialized` and separately takes `code: vector<vector<u8>>` as the actual module bytes [1](#0-0) ; the only cross-check tying `code` to `pack` is module-name equality performed by the native layer [2](#0-1) . There is no requirement that `source`, `source_map`, or `source_digest` actually correspond to the bytes in `code`.
- Consequently, a publisher (or a supply-chain-compromised publish workflow) can submit metadata whose `manifest`/`source`/`source_digest` correspond to a benign, publicly-reviewed source tree, while submitting materially different bytecode for the module with the same name. `aptos move verify-package` will report `"Successfully verified source of package"` even though the deployed executable code differs from what was verified.

This is a direct analog of the reported bug class: the report's `Balance` struct silently diverges from ground truth, causing consumers to read/trust incorrect data due to a structural mismatch between two independently-maintained representations. Here, the CLI's "verified" package metadata silently diverges from the ground-truth deployed bytecode because they are two independent transaction fields with no on-chain binding, and the verification tool doesn't close that gap by fetching and diffing actual code.

### Impact Explanation
Downstream tooling, auditors, and integrators (including `move-package-cache`'s `fetch_on_chain_package`, which likewise only fetches bytecode without any content-hash-to-metadata binding beyond what's asserted at publish time [10](#0-9) ) treat a "verified" package as trustworthy proof that the deployed bytecode matches the reviewed/published source. Because `verify-package` never diffs actual bytecode, this trust is misplaced: it enables silent code-replacement/mismatch between what's advertised as verified and what's actually executed on protected state, matching "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes" and can facilitate unauthorized/undetected malicious code being accepted as verified on mainnet.

### Likelihood Explanation
The condition is trivially reachable by any account with publish rights to the package address (no special privilege needed beyond being the package owner) since `code`/`metadata_serialized` are independent arguments controllable by the same signer, and the disconnect exists in every invocation of `aptos move verify-package` (`--bytecode` isn't even an available flag on this subcommand, only on the separate `DownloadPackage`) [11](#0-10) . This makes the misleading "verified" result the default and unavoidable behavior of the tool, not an edge case.

### Recommendation
1. Have `VerifyPackage::execute` create the `CachedPackageRegistry` with `with_bytecode = true`, fetch each module's on-chain bytecode, and byte-compare it against the freshly compiled bytecode (`BuiltPackage::extract_code()`), in addition to the existing metadata comparison in `CachedPackageMetadata::verify`.
2. Consider strengthening `source_digest` (or introducing a dedicated bytecode digest field in `PackageMetadata`) that the framework's `code::publish_package` natively validates against the actual `code` bundle at publish time, closing the on-chain binding gap rather than relying purely on off-chain tooling.

### Proof of Concept
Conceptual (framework-level) reproduction, since the gap is structural rather than a single crashing input:
1. Compile a benign package `P` with genuine source; note its `manifest`, `source`, `source_map`, `source_digest`.
2. Publish `code::publish_package_txn(owner, metadata_serialized_of_P, malicious_bytecode_with_same_module_names)` — this succeeds because only module names are checked against `expected_modules`, per `native_request_publish` [12](#0-11) .
3. Run `aptos move verify-package --account <owner>` pointed at local package `P`'s source. `CachedPackageRegistry::create(..., false)` fetches only metadata; `package.verify(&compiled_metadata)` compares `name`, `deps`, `modules` (source/source_map text), `manifest`, `upgrade_policy`, `extension`, `source_digest` — all of which match `P` — and returns `Ok(())` [4](#0-3) .
4. The CLI prints `"Successfully verified source of package"` [8](#0-7)  even though the actually executing on-chain bytecode is `malicious_bytecode`, not the bytecode compiled from `P`'s source.

**Confidence note**: I verified the CLI code paths and framework publish/native code directly in this repo, but I did not have access to run the actual CLI or a live network to execute this PoC end-to-end; the trace is based on static code reading of `stored_package.rs`, `commands.rs`, `code.move`, and `natives/src/code.rs`.

fn native_request_publish(
    context: &mut SafeNativeContext,
    _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(matches!(args.len(), 4 | 5));
    let with_allowed_deps = args.len() == 5;

    context.charge(CODE_REQUEST_PUBLISH_BASE)?;

    let policy = safely_pop_arg!(args, u8);
    let mut code = vec![];
    for module in safely_pop_arg!(args, Vec<Value>) {
        let module_code = module.value_as::<Vec<u8>>()?;

        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_code.len() as u64))?;
        code.push(module_code);
    }

    let allowed_deps = if with_allowed_deps {
        let mut allowed_deps: BTreeMap<AccountAddress, BTreeSet<String>> = BTreeMap::new();

        for dep in safely_pop_arg!(args, Vec<Value>) {
            let (account, module_name) = unpack_allowed_dep(dep)?;

            let entry = allowed_deps.entry(account);

            if let Entry::Vacant(_) = &entry {
                // TODO: Is the 32 here supposed to indicate the length of an account address in bytes?
                context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(32))?;
            }

            context
                .charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_name.len() as u64))?;
            entry.or_default().insert(module_name);
        }

        Some(allowed_deps)
    } else {
        None
    };

    let mut expected_modules = BTreeSet::new();
    for name in safely_pop_arg!(args, Vec<Value>) {
        let str = get_move_string(name)?;

        // TODO(Gas): fine tune the gas formula
        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(str.len() as u64))?;
        expected_modules.insert(str);
    }

    let destination = safely_pop_arg!(args, AccountAddress);

    // Add own modules to allowed deps
    let allowed_deps = allowed_deps.map(|mut allowed| {
        allowed
            .entry(destination)
            .or_default()
            .extend(expected_modules.clone());
        allowed
    });

    let code_context = context.extensions_mut().get_mut::<NativeCodeContext>();
    if code_context.requested_module_bundle.is_some() || !code_context.enabled {
        // Can't request second time or if publish requests are not allowed.
        return Err(SafeNativeError::abort(EALREADY_REQUESTED));
    }
    code_context.requested_module_bundle = Some(PublishRequest {
        destination,
        bundle: ModuleBundle::new(code),
        expected_modules,
        allowed_deps,
        check_compat: policy != ARBITRARY_POLICY,
    });

    Ok(smallvec![])

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )

            bail!(
                "Source digests doesn't match {:?} : {:?}",

                self_metadata.source_digest
            )

#[async_trait]
impl CliCommand<&'static str> for VerifyPackage {
    fn command_name(&self) -> &'static str {
        "VerifyPackage"
    }

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }
