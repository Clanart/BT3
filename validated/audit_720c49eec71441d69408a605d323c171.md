### Title
Missing Git transport allow-list lets an attacker-controlled remote URL (deep link / PR fork) invoke dangerous Git transport helpers on clone/fetch/addRemote - (File: `app/src/lib/git/environment.ts`)

### Summary
The report's underlying issue is that an outcome-affecting parameter that is fully attacker-influenced (`amountOutMinimum`) is passed through to a sensitive operation (the swap) unchecked, allowing the attacker to manipulate the transaction's effect. In GitHub Desktop, the analogous unchecked, attacker-influenced value is the **remote/clone URL string** that flows from untrusted external inputs (a custom-protocol deep link handled by `parseAppURL`, or a PR's `head.repo.clone_url` from the GitHub API which is fully controlled by whoever opened the PR) straight into Git subprocess invocations (`clone`, `fetch`, `addRemote`) without any restriction on the Git transport/protocol.

### Finding Description
`parseAppURL` extracts the `url` query parameter from an `x-github-client://openrepo/...` (and legacy `github-mac://`, `github-windows://`) link with no protocol allow-list at all: [1](#0-0) 

That raw string is handed to `Dispatcher.openOrCloneRepository` → `AppStore._clone` → `CloningRepositoriesStore.clone` → `git/clone.ts`'s `clone()`, which only defends against the *destination path* being a sensitive location, not against the *source URL* being a malicious Git transport: [2](#0-1) 

Similarly, `_findPullRequestBranch` takes `headCloneUrl` verbatim from the GitHub API response (`pull_request.head.repo.clone_url`), a value fully controlled by the author of the fork that opened the PR, and passes it directly to `addRemote()`/`_fetchRemote()`: [3](#0-2) [4](#0-3) 

Before any of these Git subprocess calls, `envForRemoteOperation` builds the process environment but never sets `GIT_ALLOW_PROTOCOL` (or any protocol allow-list) — it only configures authentication and an optional HTTP(S) proxy: [5](#0-4) 

Git itself supports "remote helper" transports beyond `http(s)`/`ssh`, most notably `ext::<command>`, which invokes an arbitrary shell command as the transport, and other helpers (e.g. `fd::`) that can be abused to read arbitrary local files or execute processes when Git tries to fetch objects/tags/submodules. Upstream Git added `GIT_ALLOW_PROTOCOL` specifically to let callers of "clone/fetch untrusted URL" restrict this attack surface (this is the same class of vulnerability as CVE-2017-1000117 / GHSA advisories about the `ext::` helper). Because Desktop never sets this variable when shelling out for clone/fetch/addRemote-triggered fetches, a remote URL of the form `ext::sh -c "..."` (or another restricted-transport form) reaching these call sites is executed by the local `git` binary with no additional confirmation.

Compare this to `remote-parsing.ts`'s `parseRemote()`, which only recognizes `https`/`ssh`/`git` URL *shapes* for owner/name extraction — but a failure to match that regex does **not** block the URL from being used; it only affects metadata (`owner`/`name`) extraction, not whether the string is passed to `git clone`/`git fetch`/`git remote add`.

### Impact Explanation
If reachable, this results in local command execution as the user running Desktop, driven purely by:
- clicking an `x-github-client://openrepo/<url>` link (browser/webpage-triggered, matches the "link/deep link" attacker surface), or
- opening a pull request on a GitHub repository that the victim has open in Desktop and inducing them to use "Checkout via Desktop" or "Open in Desktop" from that PR (the "GitHub API object" attacker surface, since `head.repo.clone_url` is attacker-supplied fork data).

This maps directly to the report's "valid impact" categories: attacker controls a git remote/API object or a deep link, and the result is code execution outside the intended `git` operation.

### Likelihood Explanation
Exploitability depends on whether the locally-installed `git` binary still honors `ext::`/other remote helpers by default when `GIT_ALLOW_PROTOCOL` is unset (modern Git defaults to allowing `ext`/`file`/etc. unless explicitly restricted by the caller or a global/system Git config already sets `protocol.allow`). Since Desktop bundles/uses the user's or an embedded Git, and the code shows no explicit restriction being applied by Desktop itself, the guard that upstream Git recommends embedding applications add (`GIT_ALLOW_PROTOCOL=http:https:ssh:git`) is absent here. I could not verify from the available files whether Desktop's bundled Git config (`gitconfig`) or `dugite` sets `protocol.allow=never` by default elsewhere in the repo — that would need to be checked before treating this as a confirmed, currently-exploitable bug rather than a missing defense-in-depth control.

### Recommendation
Explicitly restrict allowed Git transports whenever a remote URL originates from an untrusted source (deep link `IOpenRepositoryFromURLAction.url`, PR `head.repo.clone_url`/`base.repo.clone_url`), e.g. set `GIT_ALLOW_PROTOCOL=http:https:ssh:git` (or an even tighter `http:https` list) in `envForRemoteOperation`, and/or validate the URL against `remoteRegexes` in `remote-parsing.ts` before calling `clone()`, `addRemote()`, or `_fetchRemote()`, rejecting anything that doesn't parse as a recognized `https`/`ssh`/`git` remote.

### Proof of Concept
Conceptual PoC (not run against the live app, since no filesystem/terminal access is available in ask-only mode):
1. Attacker hosts a page with `<a href="x-github-client://openrepo/ext::sh%20-c%20touch%20/tmp/pwned">Open in Desktop</a>`.
2. Victim (who has registered Desktop as the protocol handler, the default after first sign-in) clicks the link.
3. `handleAppURL` → `parseAppURL` returns `{ name: 'open-repository-from-url', url: 'ext::sh -c "touch /tmp/pwned"', branch: null, pr: null, filepath: null }` — note `testForInvalidChars` is only applied to `branch`, not `url`.
4. `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository(url)` eventually calls Desktop's `clone()` (`app/src/lib/git/clone.ts`) with that URL as the `git clone` remote argument, with an environment lacking `GIT_ALLOW_PROTOCOL`.
5. If the local Git build's default transport allow-list permits `ext::`, the shell command runs on the victim's machine. [6](#0-5) [5](#0-4) [2](#0-1)

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
