Confirmed in `parachain/runtimes/nexus/src/ismp.rs`, `ProxyModule::on_accept`: [1](#0-0) 

The bandwidth gate is applied unconditionally against `(request.source, request.from)` *before* the destination module is resolved from `request.to`: [2](#0-1) 

Only two module ids are matched afterward — `pallet_bandwidth` and `pallet_hyper_fungible_token`; any other `to`, including a near-miss byte pattern, falls into the trailing catch-all and returns `Err`: [3](#0-2) 

Notably, `pallet_intents_coprocessor` is registered in the runtime (`impl pallet_intents_coprocessor::Config for Runtime`) but has **no match arm at all** in this router, and I found no `PALLET_ID`/`ModuleId`/`IsmpModule` implementation for it in `modules/pallets/intents-coprocessor/src/lib.rs`: [4](#0-3) 

`pallet_bandwidth::try_consume` deducts from the `Allowance` FIFO immediately and irreversibly, and there is no compensating credit/refund path anywhere on an `Err` return from the module-resolution match: [5](#0-4) 

This structurally validates the "spend-then-reject" mechanics described in the question: bandwidth is decremented at line 378-389 regardless of whether the subsequent `to`-based routing at line 400-409 actually succeeds.

However, the specific griefing scenario as posed — an *unprivileged attacker* debiting a *different, legitimate user's* bandwidth balance by crafting a look-alike `to` — depends on the attacker being able to forge a request whose `(source, from)` pair matches the victim's real app identity while independently choosing an invalid `to`. In ISMP, `request.from`/`request.source` are not destination-chain-controllable fields; they are bound to the actual dispatching entity on the source chain and are only accepted here after consensus/state-proof verification. The allowance itself is keyed as a **shared per-(chain, app) pool** (per the pallet's own doc comment "Prepaid `(chain, app)` byte balances"), not a per-individual-user balance — so "the legitimate user's bandwidth" is really the app's shared pool, funded by whoever purchased tiers for that `(source, from)` key. Whether an unprivileged, non-infrastructure actor can trigger a dispatch carrying a genuine app's `from` value with an attacker-chosen malformed `to` depends entirely on the source-side dispatching contract/pallet (outside this repo's ISMP-runtime scope, and not something I could verify from the available files) — if that contract lets arbitrary callers pick the ISMP `to` field while the contract's own address is fixed as `from`, then any caller (not just infrastructure) could burn the shared allowance with malformed `to` values, which would fit the scope's "unprivileged input" criterion. Without visibility into that source-side dispatcher, I can't confirm the "attacker forges another identity" framing, but I can confirm the destination-side accounting flaw itself (non-atomic consume, no refund, and no route for `pallet_intents_coprocessor` at all) as a concrete broken-accounting condition on the destination chain.

### Title
Bandwidth is irrevocably consumed before destination-module resolution, with no refund on routing failure - (File: parachain/runtimes/nexus/src/ismp.rs)

### Summary
In `ProxyModule::on_accept`, `pallet_bandwidth::BandwidthGate::try_consume` debits the `(request.source, request.from)` allowance before the `request.to` module id is resolved. If resolution fails — either because the `to` bytes don't match any wired pallet id, or because a registered pallet (`pallet_intents_coprocessor`) simply has no match arm in this router — the call returns `Err` and the already-consumed bandwidth is never restored.

### Finding Description
The gate consumes bytes at [2](#0-1)  unconditionally for any non-purchase message. Only after that debit does the code decode `request.to` into a `ModuleId` and match it against the two wired pallets at [3](#0-2) . Any `to` value that isn't exactly `pallet_bandwidth::PALLET_BANDWIDTH` or `pallet_hyper_fungible_token::PALLET_ID` — including a byte-level near-miss, or a request destined for `pallet_intents_coprocessor` (which is configured in the runtime but never appears in this match at all) — falls to `_ => Err("Destination module not found")`. `pallet_bandwidth`'s `try_consume` has no compensating path on downstream failure: it mutates `Allowance` storage and emits `BandwidthConsumed` synchronously and permanently.

### Impact Explanation
This breaks the invariant that bandwidth balances must move exactly once for value received: bytes are spent for a request that produces zero settlement effect. Because the allowance is a shared `(chain, app)` pool, wasted consumption reduces capacity for the entire app, not just the malformed message's own sender, degrading or blocking future legitimate settlement/intent traffic once the pool is exhausted.

### Likelihood Explanation
The destination-side defect (non-atomic consume/route, no refund, missing `pallet_intents_coprocessor` arm) is deterministic and always reproducible on this chain. Whether it can be triggered *against a specific victim's* allowance by an unprivileged, non-infrastructure actor depends on the source-chain dispatcher's ability to let arbitrary callers pick `to` while `from` remains bound to a shared app identity — that dispatcher lives outside the files reviewed here and I could not verify it.

### Recommendation
Resolve and validate `request.to` into a known module id *before* calling `try_consume`, or reserve/consume bandwidth only after confirming the module dispatch will proceed; alternatively, add an explicit refund/credit-back path invoked whenever the post-consumption module match returns `Err`. Separately, add the missing `pallet_intents_coprocessor` arm to the `match pallet_id` block if it is intended to receive `on_accept` calls through this router.

### Proof of Concept
1. Register/fund a bandwidth allowance for `(source, from)` via `force_credit` or a purchase message.
2. Submit a `PostRequest` with that `source`/`from`, `dest == HostStateMachine`, and a `to` value that does not exactly equal `pallet_bandwidth::PALLET_BANDWIDTH` or `pallet_hyper_fungible_token::PALLET_ID` (e.g., a single-byte-flipped `pallet_intents_coprocessor` id, or the real `pallet_intents_coprocessor` id itself, which has no arm).
3. Call `ProxyModule::on_accept(request)`.
4. Assert the call returns `Err("Destination module not found")`.
5. Query `pallet_bandwidth::Pallet::<Runtime>::remaining(&app_chain, &app)` and confirm it decreased by the encoded request's byte length despite the `Err`, with no corresponding settlement effect.

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
