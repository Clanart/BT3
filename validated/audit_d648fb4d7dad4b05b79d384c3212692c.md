### Title
Improper Input Validation on NFT On-Chain Metadata Leads to Terminal Escape-Sequence Injection When Displaying NFT Info - ([File: chia/cmds/wallet_funcs.py])

### Summary
`chia.cmds.wallet_funcs.print_nft_info` prints the raw, attacker-controlled NFT metadata string (`nft.chain_info`) directly to the victim's terminal via `print()`, with no sanitization of non-printable or ANSI/terminal control-code bytes. This mirrors the topydo `ListFormatParser::parse` bug class (CWE-20: improper validation of untrusted text before it reaches the terminal), where a crafted line containing terminal escape sequences is echoed verbatim to the user's console.

### Finding Description
`nft.chain_info` is produced in `get_nft_info_from_puzzle` in `chia/wallet/nft_wallet/nft_puzzle_utils.py`: [1](#0-0) 
Here `disassemble(uncurried_nft.metadata)` renders the raw on-chain metadata `Program` (an arbitrary CLVM atom/string chosen entirely by whoever mints or updates the NFT) into a display string, with no restriction on which bytes may appear.

That string is stored in the `NFTInfo.chain_info` field: [2](#0-1) 

It is then printed unmodified to the terminal in `print_nft_info`: [3](#0-2) 
specifically:
```
print(f"{'On-chain data/info:'.ljust(26)} {nft.chain_info}")
```

`print_nft_info` is invoked from `list_nfts` and `get_nft_info`, both reachable by any wallet user running standard CLI commands (`chia wallet nft list`, `chia wallet nft get_info`) against any NFT their wallet holds: [4](#0-3) 

Because NFT minting/metadata-updating is attacker-controlled (any party can mint an NFT or, via the metadata updater puzzle, update metadata) and the NFT can subsequently be transferred/offered to a victim wallet, an attacker can embed raw ANSI/VT100 escape sequences (e.g., cursor movement, screen-clear, OSC sequences that rewrite terminal title, or in vulnerable terminal emulators arbitrary command injection via clipboard/paste sequences) inside the metadata atom. When the victim inspects the NFT with the CLI, the escape bytes are written straight to their terminal.

This is a close analog to GHSA-h6h9-pphv-m266: an untrusted, attacker-supplied text field (todo.txt line / NFT on-chain metadata) is passed through a formatter (`ListFormatParser::parse` / `disassemble`) that does not filter control/escape bytes, and the result is written directly to the terminal that the victim opened/queried.

### Impact Explanation
Terminal escape-sequence injection can be used to spoof terminal output (hide/alter subsequent CLI output such as balances, offer summaries, or confirmation prompts), manipulate terminal title/state, or — depending on the victim's terminal emulator — trigger more severe effects (e.g., some terminal emulators support OSC 52 clipboard writes or escape-sequence-triggered features that can be abused for further attacks). Since the attacker fully controls NFT metadata content and the victim only needs to run a normal wallet CLI command against an NFT they legitimately received (e.g., via a transfer or an accepted offer), this is reachable by any unprivileged NFT sender/offer counterparty without requiring any privileged access.

### Likelihood Explanation
Likelihood is High for exposure but the ultimate severity depends on the victim's terminal emulator capabilities. Any user who mints or updates an NFT can set its metadata field to arbitrary bytes; any wallet user who receives, is offered, or otherwise queries that NFT via `chia wallet nft list`/`get_info` will have the crafted bytes printed to their terminal. No signature bypass or protocol violation is needed — it's a pure output-sanitization gap in the CLI display path.

### Recommendation
Sanitize/escape all untrusted string fields (`nft.chain_info`, and similarly `data_uris`/`metadata_uris`/`license_uris`, plus any other CLVM-decoded text data displayed to the terminal) before printing — e.g., strip or escape non-printable bytes (`\x00-\x1f`, `\x7f`, and ANSI CSI/OSC sequences) using something like Python's `str.translate` to remove control characters, or gate the raw value behind a `--raw`/`-v` flag while printing a hex/backslash-escaped representation by default. This should be applied throughout `chia/cmds/wallet_funcs.py` wherever `disassemble()` output or other chain-derived strings are passed straight to `print()`.

### Proof of Concept
1. Attacker mints an NFT (or updates NFT metadata via the metadata updater puzzle) with a metadata atom containing bytes such as `\x1b[2J\x1b[H<fake balance text>` or an OSC escape sequence.
2. Attacker transfers the NFT to the victim's wallet, or includes it in an offer that the victim examines with `chia wallet take_offer --examine-only` or accepts.
3. Victim runs `chia wallet nft list -i <wallet_id>` or `chia wallet nft get_info -ni <nft_coin_id>`.
4. `print_nft_info` executes `print(f"{'On-chain data/info:'.ljust(26)} {nft.chain_info}")` with the raw attacker bytes, and the terminal interprets/executes the embedded escape sequences (e.g., clearing the screen or altering displayed text), exactly as the topydo advisory describes for todo.txt lines rendered by `ListFormatParser::parse`.

def print_nft_info(nft: NFTInfo, *, config: dict[str, Any]) -> None:
    indent: str = "   "
    owner_did = None if nft.owner_did is None else encode_puzzle_hash(nft.owner_did, AddressType.DID.hrp(config))
    minter_did = None if nft.minter_did is None else encode_puzzle_hash(nft.minter_did, AddressType.DID.hrp(config))
    print()
    print(f"{'NFT identifier:'.ljust(26)} {encode_puzzle_hash(nft.launcher_id, AddressType.NFT.hrp(config))}")
    print(f"{'Launcher coin ID:'.ljust(26)} {nft.launcher_id}")

    print(f"{'Current NFT coin ID:'.ljust(26)} {nft.nft_coin_id}")
    print(f"{'On-chain data/info:'.ljust(26)} {nft.chain_info}")
    print(f"{'Owner DID:'.ljust(26)} {owner_did}")
    print(f"{'Minter DID:'.ljust(26)} {minter_did}")
    print(f"{'Royalty percentage:'.ljust(26)} {nft.royalty_percentage}")

    print(f"{'NFT content hash:'.ljust(26)} {nft.data_hash.hex()}")
    print(f"{'Metadata hash:'.ljust(26)} {nft.metadata_hash.hex()}")

async def list_nfts(
    wallet_info: WalletClientInfo,
    wallet_id: int,
    num: int,
    start_index: int,
) -> None:
    try:
        response = await wallet_info.client.list_nfts(
            NFTGetNFTs(wallet_id=uint32(wallet_id), start_index=uint32(start_index), num=uint32(num))
        )
        nft_list = response.nft_list
        if len(nft_list) > 0:
            for nft in nft_list:
                print_nft_info(nft, config=wallet_info.config)
        else:
            print(f"No NFTs found for wallet with id {wallet_id} on key {wallet_info.fingerprint}")
    except Exception as e:
        print(f"Failed to list NFTs for wallet with id {wallet_id} on key {wallet_info.fingerprint}: {e}")


async def set_nft_did(
    *,
    wallet_info: WalletClientInfo,
    wallet_id: int,
    fee: uint64,
    nft_coin_id: str,
    did_id: str,
    push: bool,
    condition_valid_times: ConditionValidTimes,
    tx_config: TXConfig,
) -> list[TransactionRecord]:
    try:
        response = await wallet_info.client.set_nft_did(
            NFTSetNFTDID(
                wallet_id=uint32(wallet_id),
                did_id=did_id,
                nft_coin_id=bytes32.from_hexstr(nft_coin_id),
                fee=fee,
                push=push,
            ),
            tx_config=tx_config,
            timelock_info=condition_valid_times,
        )
        spend_bundle = response.spend_bundle.to_json_dict()
        print(f"Transaction to set DID on NFT has been initiated with: {spend_bundle}")
        return response.transactions
    except Exception as e:
        print(f"Failed to set DID on NFT: {e}")
        return []


async def get_nft_info(wallet_info: WalletClientInfo, nft_coin_id: str) -> None:
    try:
        response = await wallet_info.client.get_nft_info(NFTGetInfo(coin_id=nft_coin_id))
        print_nft_info(response.nft_info, config=wallet_info.config)
    except Exception as e:
        print(f"Failed to get NFT info: {e}")
