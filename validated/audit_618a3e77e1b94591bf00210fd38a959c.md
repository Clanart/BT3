### Title
Absolute Path Traversal in DataLayer `add_missing_files` RPC allows writing/overwriting files outside `server_files_location` - (File: chia/data_layer/data_layer.py)

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts a user-supplied `foldername`/`directory` parameter that is passed, unvalidated and unconfined, straight into filesystem write operations (`open(..., "wb"/"xb")` and `mkdir(parents=True)`). Any local RPC caller able to reach the DataLayer RPC service can redirect the service's `.dat` tree-file writes to an arbitrary absolute path on disk, exactly the CWE-36 "Absolute Path Traversal" pattern described in the reference advisory (attacker-controlled `filename`/`file_key` used to build a write path with no confinement to the intended upload directory).

### Finding Description
`DataLayer.add_missing_files()` accepts a caller-supplied `foldername: Path | None` and, if provided, uses it verbatim as the write directory instead of the server-managed `self.server_files_location`: [1](#0-0) 

That `foldername` originates directly from an RPC/CLI request field (`"foldername"`/`--directory`) with no root-path anchoring or canonicalization check: [2](#0-1) [3](#0-2) 

The value flows into `write_files_for_root()`, which builds the target file path via simple `Path.joinpath()` (no traversal/confinement checks) and then does `mkdir(parents=True, exist_ok=True)` followed by `open(filename, "wb"/"xb")`, i.e., it will create arbitrary intermediate directories and write/overwrite files at that attacker-chosen absolute location: [4](#0-3) [5](#0-4) 

Unlike the DataLayer HTTP file-serving endpoints (`data_layer_server.py`) and the S3 plugin's `upload`/`download` handlers, which strictly validate filenames via `is_filename_valid()` (round-trip equality check against a generated canonical name) before touching the filesystem, `add_missing_files`'s directory parameter has **no equivalent validation**: [6](#0-5) 

The only unvalidated input here is the directory component (the filename component is still generated from `store_id`/`node_hash`/`generation`), but that is sufficient to write/overwrite files at attacker-chosen absolute paths outside the intended `server_files_location` sandbox — directly analogous to the reported DB-GPT bug where an uploader-controlled path let files be written to unintended, potentially sensitive locations.

### Impact Explanation
A local caller with access to the DataLayer RPC/CLI (an "unprivileged" surface per the in-scope categories: Data Layer client / local RPC caller) can force the service to:
- Create arbitrary directories anywhere the DataLayer process has write permission (`mkdir(parents=True)`).
- Write new files (`xb` mode by default) at that attacker-chosen absolute directory.
- With `overwrite=True`, overwrite any existing file that happens to collide with the generated `{store_id}-{node_hash}-{full|delta}-{generation}-v1.0.dat` name at the target path.

While the exact filename is still template-generated (limiting arbitrary overwrite of a specific known file like an SSH key without brute-forcing the name), the ability to force directory creation and file writes to arbitrary locations outside the sandboxed `server_files_location` is itself a meaningful path-traversal/writing primitive that breaks the DataLayer file-serving trust boundary and can be used for disk exhaustion, planting files in unexpected locations (e.g., web-served directories, cron/service directories the process can write to), or corrupting other services' state.

### Likelihood Explanation
Reaching this requires only an authenticated/local call to the DataLayer RPC's `add_missing_files` endpoint (or the `chia data add_missing_files -d <path>` CLI, which is a thin RPC wrapper) — no on-chain action, signature, or elevated privilege is needed beyond RPC access, which matches the "local RPC caller" reachable-actor category in scope.

### Recommendation
Validate and canonicalize the `foldername`/`directory` parameter in `DataLayer.add_missing_files()` (and any other RPC-facing path parameter) by resolving it and asserting it is contained within (or equal to) an allow-listed base directory (e.g., `self.server_files_location`), rejecting absolute paths or `..` traversal outside that root before calling `write_files_for_root()`. This mirrors the strict `is_filename_valid()` confinement already used for filenames in `download_data.py`.

### Proof of Concept
1. Start the DataLayer RPC service and obtain access to its RPC port (same trust level required to call any other DataLayer RPC method).
2. Issue an `add_missing_files` RPC request (or `chia data add_missing_files -d /tmp/attacker_dir -o` CLI) with `foldername` set to an absolute path outside the intended `server_files_location`, e.g. `/tmp/attacker_dir` or a path under a directory the DataLayer process can write to.
3. Observe that `DataLayer.add_missing_files()` → `write_files_for_root()` creates `/tmp/attacker_dir` (via `mkdir(parents=True)`) and writes `.dat` tree files there, confirming the write path escapes the server-managed `server_files_location` sandbox entirely, driven solely by the caller-supplied `foldername` value.

    ) -> dict[str, Any]:

        if store_ids is not None:
            request["ids"] = [store_id.hex() for store_id in store_ids]

def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass

    return WriteFilesResult(written, filename_full_tree if written_full_file else None, filename_diff_tree)

def get_full_tree_filename_path(
    foldername: Path,
    store_id: bytes32,
    node_hash: bytes32,
    generation: int,
    group_by_store: bool = False,
) -> Path:
    if group_by_store:
        path = foldername.joinpath(f"{store_id}")
        return path.joinpath(f"{node_hash}-full-{generation}-v1.0.dat")
    return foldername.joinpath(f"{store_id}-{node_hash}-full-{generation}-v1.0.dat")
