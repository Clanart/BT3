### Title
Silent `origin` Remote Hijack via API `clone_url` — Protocol-Only Guard Fails to Check Hostname - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl()` automatically rewrites a repository's `origin` remote URL whenever the GitHub API reports a different `clone_url` for the associated `GitHubRepository`. The function contains a guard that is supposed to prevent this auto-update from clobbering a URL the user cares about, but the guard only checks that the **protocol** (`https:` vs `ssh:`) is unchanged — it never checks that the **hostname** is unchanged. Exactly like the Aave `validateBorrow()` bug, where the intended safety check (`vars.rateMode`) was checking the wrong/uninitialized value and therefore never actually gated the dangerous path, here the intended safety check (`protocolsMatch`) checks the wrong dimension of the URL and therefore never gates a cross-host remote change.

### Finding Description
The relevant logic:

```ts
// app/src/lib/stores/updates/update-remote-url.ts
const remoteUrl = gitStore.defaultRemote.url
const updatedRemoteUrl = apiRepo.clone_url
const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

const parsedRemoteUrl = URL.parse(remoteUrl)
const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
const protocolsMatch =
  parsedRemoteUrl.protocol !== null &&
  parsedUpdatedRemoteUrl.protocol !== null &&
  parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

const remoteUrlUnchanged =
  gitStore.defaultRemote &&
  urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
  await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
``` [2](#0-1) 

`urlMatchesRemote()` compares hostname, owner, and name; when hostnames differ it returns `false`. [3](#0-2) 

So the code path is:
1. `urlsMatch` becomes `false` whenever the new `clone_url`'s host, owner, or name differs from the current remote — including when the host is a completely different, attacker-controlled domain.
2. `protocolsMatch` only verifies both URLs use the same scheme (`https:`/`https:` or `ssh:`/`ssh:`); it never inspects `hostname`.
3. `remoteUrlUnchanged` only proves the user hasn't hand-edited the remote away from what Desktop last knew — it does not validate the new value at all.
4. If all three hold, `gitStore.setRemoteURL()` is invoked, running `git remote set-url origin <updatedRemoteUrl>` with **no user confirmation**, even though `updatedRemoteUrl` can point at an entirely different host than the one the repository was originally added from. [4](#0-3) 

The comment in the code even states the intent: *"Verify that protocol hasn't changed... in case they are relying on a specific one"* — but nothing verifies the **host** hasn't changed, which is the actually security-relevant property for where credentials and pushed code end up.

`apiRepo` is `IAPIRepository` data fetched from the GitHub API (or a GitHub Enterprise Server) for the repository. Any attacker who can influence the `clone_url` field returned for a repository object the user has already added to Desktop (e.g., a malicious/compromised GHES endpoint, a repository transfer/rename chain the user's fork tracks, or a manipulated API response) can point Desktop's `origin` remote at an attacker-controlled git server without any prompt.

### Impact Explanation
Once `origin` is silently repointed to an attacker-controlled URL:
- Every subsequent `git push` sends the user's code (and, over HTTPS with a stored credential helper, their auth token/credentials) to the attacker's server.
- Every subsequent `git fetch`/`pull` retrieves attacker-supplied history the user then works from, enabling supply-chain-style content corruption of what the user believes is the upstream repo.
- Because the change happens silently, without any dialog like "the remote URL for this repository has changed, would you like to update it," the user has no indication anything happened — matching the "silent corruption of what the user commits or pushes" and "credential exfiltration" impact classes.

### Likelihood Explanation
The trigger only requires the app to fetch updated repository metadata (a routine background refresh) where `apiRepo.clone_url` differs from the cached `gitHubRepository.cloneURL` while still matching the "unchanged since Desktop last set it" condition. No local access, admin rights, or social engineering step is required beyond the attacker's ability to influence the API-reported `clone_url` for a repository entity the victim already tracks (e.g., via a compromised/malicious GitHub Enterprise Server, or an attacker-controlled repository object surfaced through normal metadata refresh flows). The existing "protocol match" guard gives a false sense of safety while doing nothing to stop this exact primitive.

### Recommendation
Extend the guard in `updateRemoteUrl()` to also require hostname equality (or, more conservatively, an explicit user confirmation dialog) before calling `gitStore.setRemoteURL()`:

```ts
const hostsMatch =
  parsedRemoteUrl.hostname !== null &&
  parsedUpdatedRemoteUrl.hostname !== null &&
  parsedRemoteUrl.hostname === parsedUpdatedRemoteUrl.hostname

if (protocolsMatch && hostsMatch && remoteUrlUnchanged && !urlsMatch) {
  await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
```
Alternatively, never auto-update silently — surface a confirmation UI whenever the resolved hostname changes.

### Proof of Concept
1. Victim adds a repository in Desktop whose `GitHubRepository.cloneURL` and `origin` remote both point to `https://github.com/victim/repo.git`.
2. Through a controlled or compromised API response path (e.g., a GitHub Enterprise Server the victim is signed into, or a chain of repository renames/transfers reflected in the cached `GitHubRepository` record), the API begins returning `clone_url: "https://attacker.example/victim/repo.git"` for that same repository object.
3. On the next background metadata refresh, `updateRemoteUrl()` computes: `protocolsMatch = true` (both `https:`), `remoteUrlUnchanged = true` (user never touched the remote), `urlsMatch = false` (hostname differs).
4. The `if` condition passes and `gitStore.setRemoteURL('origin', 'https://attacker.example/victim/repo.git')` executes silently, rewriting the local git config.
5. Victim's next push/fetch operations are transparently redirected to `attacker.example`.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
