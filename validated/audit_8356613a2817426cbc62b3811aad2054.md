### Title
Unbounded length-prefix walk in CLVM canonical-serialization check causes unhandled `IndexError` on spend-bundle admission - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` decodes a CLVM atom's variable-length size prefix (1–6 bytes) by repeatedly indexing into the caller-supplied `clvm_buffer` at `offset += 1` for `prefix_len` iterations, with no check that `offset` stays within `len(clvm_buffer)`. [1](#0-0)  This function is invoked by `is_clvm_canonical()`, which walks a full CLVM-serialized buffer atom-by-atom without any bounds validation before dereferencing `clvm_buffer[offset]`. [2](#0-1)  Both functions are called directly on attacker-controlled bytes — the puzzle reveal and solution of every coin spend in a submitted `SpendBundle` — during mempool admission in `MempoolManager.validate_spend_bundle()`. [3](#0-2) 

This is structurally the same bug class as CVE-2022-43034: a bit/byte-skipping routine that trusts a length field embedded in untrusted input and advances a cursor/offset without verifying it stays inside the buffer, leading to an out-of-bounds read once the crafted length exceeds the remaining buffer.

### Finding Description
The high bits of the atom's first byte select one of six length-prefix encodings (`prefix_len` from 0 to 5), each requiring that many additional bytes to be present in `clvm_buffer` after `offset`. [4](#0-3)  The loop that consumes those extra bytes does:
```
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
with no `offset < len(clvm_buffer)` guard. [5](#0-4)  If a submitted puzzle reveal or solution contains a truncated atom — e.g. a single byte `0xfc` (which signals a 5-byte length prefix under the `0b11111110 == 0b11111100` branch) with no following bytes — the loop indexes past the end of `clvm_buffer` and Python's `bytes.__getitem__` raises `IndexError: index out of range`.

`is_clvm_canonical()`'s outer loop has the same unguarded pattern: it reads `clvm_buffer[offset]` on every iteration with no check that `offset < len(clvm_buffer)` before calling `is_atom_canonical`, and it advances `offset` based on values (`atom_len`) that are themselves attacker-supplied and can point arbitrarily far past the buffer end. [6](#0-5) 

These functions are reached from `validate_spend_bundle()`, which is on the direct path for any unprivileged spend-bundle submitter — mempool admission calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in the bundle. [3](#0-2)  No `try/except` wraps this call in `validate_spend_bundle()`; only a `ValidationError`/`ValueError` path from `validate_clvm_and_signature` (the Rust CLVM cost/signature validator, which runs earlier and would have already parsed/validated the bytes as legal CLVM) is handled in `pre_validate_spendbundle()`. [7](#0-6) 

The Rust-side `validate_clvm_and_signature()` executes the puzzle/solution as CLVM (a strict, self-describing format) and would normally reject malformed byte sequences (or accept and fully parse them) before this Python-side canonical check runs, so the exact reachability of a raw truncated atom that trips `is_atom_canonical`'s unguarded indexing specifically (as opposed to also being rejected earlier by the Rust CLVM parser) could not be fully confirmed from static review alone — this would need to be verified by constructing candidate byte sequences that pass Rust CLVM parsing yet still hit `is_atom_canonical`'s missing bound check (e.g., a legally-parsed atom whose non-canonical prefix bytes are consistent with CLVM's own atom grammar, since `is_atom_canonical` re-derives length independently of how the Rust parser consumed the same bytes).

### Impact Explanation
If reachable, an unhandled `IndexError` raised deep inside `validate_spend_bundle()` propagates up out of `add_spend_bundle()` uncaught (no exception handling wraps the canonical check), which the caller in `full_node.py` would need to tolerate. Depending on how the calling task/coroutine handles an unexpected exception, this could crash the spend-bundle processing task for a single submitted bundle (localized DoS) rather than the whole full-node process, since Python exceptions inside a specific `asyncio` task do not by default take down unrelated tasks. This matches the "spend-triggered transaction-processing halt" impact category, but only for the task handling that particular spend bundle — not the coin-set, consensus, or asset-identity categories.

### Likelihood Explanation
Medium-Low. The code path is reachable by any unprivileged spend-bundle submitter (RPC caller or peer relaying a transaction), and the missing bounds check is a genuine, unconditional gap in the `is_atom_canonical`/`is_clvm_canonical` implementation. However, the practical likelihood is limited by two unverified factors: (1) whether a byte sequence can simultaneously pass the Rust `validate_clvm_and_signature` CLVM parser (which runs first and validates the same bytes as legal CLVM) and still trigger the exact out-of-bounds index in `is_atom_canonical`, and (2) whether the caller-side exception handling in `full_node.py`/`full_node_api.py` already catches generic exceptions around spend-bundle processing, which would downgrade this from a crash to a handled error. Neither could be confirmed within the available exploration budget.

### Recommendation
Add explicit bounds checks in both functions before indexing into `clvm_buffer`:
- In `is_atom_canonical()`, before the prefix-consuming loop, verify `offset + prefix_len < len(clvm_buffer)` and raise a clear `ValueError`/return non-canonical instead of indexing unconditionally.
- In `is_clvm_canonical()`, check `offset < len(clvm_buffer)` at the top of each loop iteration before dereferencing `clvm_buffer[offset]`, and treat a truncated/out-of-range buffer as non-canonical (return `False`) or raise a well-defined error, rather than letting an `IndexError` escape.
- Wrap the canonical check call in `validate_spend_bundle()` (or catch `IndexError` inside `is_clvm_canonical`) so malformed input results in `Err.INVALID_COIN_SOLUTION` rather than an unhandled exception surfacing from mempool admission.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

                flags | MEMPOOL_MODE,
                nice=(5, -fee_per_cost),
            )
        # validate_clvm_and_signature raises a ValueError with an error code
        except ValueError as e:
            # Convert that to a ValidationError
            if len(e.args) > 1:
                error = Err(e.args[1])

            else:
                raise ValidationError(Err.UNKNOWN)  # pragma: no cover
        finally:

        if sbc.num_atoms > sbc.cost * 60_000_000 / self.constants.MAX_BLOCK_COST_CLVM:
