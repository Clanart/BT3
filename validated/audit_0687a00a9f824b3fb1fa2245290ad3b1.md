Confirmed: `app/src/lib/git/clone.ts` unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` for every clone operation, disabling Git's own defense-in-depth clone protections while cloning attacker-controlled repositories. This is a genuine, concrete finding rooted in local code.

### Title
Cloning disables Git's built-in clone-time protections (`GIT_CLONE_PROTECTION_ACTIVE=false`), re-exposing malicious-repository attacks - (File: `app/src/lib/git/clone.ts`)

### Summary
The zkSync report's core lesson is that a "safety" mechanism which is supposed to preserve the integrity of a call's parameters can be silently overridden by an intermediate layer, letting attacker-controlled input reach a sensitive operation unguarded. In GitHub Desktop, the analogous broken invariant is in the `clone()` function, which explicitly forces `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` for every single clone, unconditionally disabling Git's native protections against malicious repository content during clone, exactly the class of protection Git added after CVE-2024-32002/32004/32020/32021/32465 (symlinked `.git`, case-folding/short-name collisions letting a cloned repo write hooks into `.git/hooks` and get them auto-executed).

### Finding Description
`GIT_CLONE_PROTECTION_ACTIVE` is a Git-internal safety switch: Git sets it to `true` in the top-level `clone` process and children (e.g. submodule sub-clones) inherit it, so nested/recursive clone operations refuse to write directory entries that look like a `.git` reference on case-insensitive/short-name filesystems, and Git enforces symlink checks that prevent writing an object database entry outside the intended `.git` directory during the clone of an untrusted, attacker-controlled repository. [1](#0-0) 

GitHub Desktop's `clone()` builds the environment for every clone (regardless of source — user-typed URL, "Clone in Desktop" deep link, or CLI `--cli-clone`) and explicitly forces this variable off:

```
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
args.push('-b', options.branch)  // (if branch given)
args.push('--', url, path)
await git(args, __dirname, 'clone', opts)
```

The clone is also always run with `--recursive`, meaning any submodules referenced by the untrusted, attacker-controlled repository are cloned in the same process tree that has protections force-disabled. [2](#0-1) 

The `url` reaching `clone()` is attacker-influenced in multiple unprivileged paths: a `x-github-client://openRepo/<url>` deep link parsed by `parseAppURL` and dispatched via `openRepositoryFromUrl` → `openOrCloneRepository` → `dispatcher.clone`, or the "Clone Repository" dialog which accepts an arbitrary generic URL. [3](#0-2) [4](#0-3) [5](#0-4) 

Unlike the argument-injection class of bug (which Desktop does correctly mitigate here via the `'--'` separator before `url`/`path`), this is a deliberate suppression of Git's own upstream hardening, and none of Desktop's other guards (`isClonePathSensitive`, the trusted-IPC-sender allowlist, `parseAppURL`'s branch/PR validation) inspect or restrict what the remote repository's tree/tags/submodules contain once the clone begins, so nothing else in the call path compensates for the disabled protection. [6](#0-5) 

### Impact Explanation
If a Windows user (case-insensitive/short-name-generating filesystem) is lured into cloning or opening a crafted repository — via a deep link, a shared clone URL, or a malicious submodule reachable through `--recursive`, Git's own defense against writing hook/config files outside `.git` via crafted paths is disabled application-wide by Desktop. This can allow a hostile repository to plant executable content that later gets run as a Git hook or misplace files outside the intended checkout, i.e., code execution or file-write outside the expected repository boundary — squarely matching the "attacker controls a cloned/fetched repository... resulting in code execution or file write outside the repo" impact criteria.

### Likelihood Explanation
Likelihood is moderate-to-high: no admin rights, no local access, and no prior compromise are needed — only that the user clones or opens a URL/deep-link pointing at a repository the attacker controls (a very natural GitHub Desktop workflow, "Clone in Desktop" links are a first-class, actively marketed feature). The default `--recursive` flag further means the disabled protection also applies transitively to every submodule the malicious top-level repository references, widening the attack surface without any additional user action.

### Recommendation
Do not force `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. Determine why this override exists (e.g., to avoid a Git error on cases previously handled by Desktop's own checks) and either remove it entirely or scope it narrowly to a verified-safe case, since Git's clone protections are exactly the mechanism meant to protect against the untrusted-repository class of attack that Desktop's clone flow is directly exposed to.

### Proof of Concept
1. Prepare (or control) a Git repository whose tree, when cloned on a Windows machine with a case-insensitive/short-name filesystem, includes entries crafted to alias into `.git/hooks` (the class of payload Git's `GIT_CLONE_PROTECTION_ACTIVE` mechanism exists to reject).
2. Publish an `x-github-client://openRepo/<attacker-repo-url>` deep link, or simply share the HTTPS/SSH clone URL, and get the victim to click "Open in Desktop"/paste the URL into Desktop's Clone Repository dialog.
3. Desktop resolves the action through `openOrCloneRepository` → `dispatcher.clone` → `AppStore._clone` → `app/src/lib/git/clone.ts`'s `clone()`, which spawns `git clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment. [7](#0-6) 

4. Because Git's built-in clone-time protection is disabled by Desktop for this and every recursively-cloned submodule, the payload that would otherwise be rejected by Git is written to disk, resulting in unexpected file placement/hook execution outside of what the user intended to check out.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)

        type: PopupType.CloneRepository,
