Audit Report

## Title
Global QUIC connection rate limiter is stake/IP-agnostic and can be exhausted by distributed unstaked connections, starving staked TPU traffic - (File: streamer/src/nonblocking/quic.rs)

## Summary
`run_server` in `streamer/src/nonblocking/quic.rs` gates every incoming QUIC connection (TPU/TPU-forward) behind a single shared `TokenBucket` (`overall_connection_rate_limiter`, capacity `MAX_CONNECTION_BURST = 1000`, refill `TOTAL_CONNECTIONS_PER_SECOND = 2500.0`). This bucket is consumed identically for staked and unstaked peers, and the consumption in `setup_connection` happens strictly before `qos.try_add_connection` (the stake-weighted `SwQos::try_add_connection` in `streamer/src/nonblocking/swqos.rs`) ever runs, so stake-based prioritization cannot intervene once the shared bucket is drained.

## Finding Description
The connection admission order in `run_server` is: (1) `overall_connection_rate_limiter.current_tokens() == 0` check, (2) per-IP `rate_limiter.is_allowed(...)`, then handshake acceptance [1](#0-0) . After the handshake completes in `setup_connection`, the flow is: per-IP `rate_limiter.register_connection(&from.ip())`, then `overall_connection_rate_limiter.consume_tokens(1)`, and only afterward `qos.build_connection_context` + `qos.try_add_connection` (SwQoS) [2](#0-1) .

The per-IP `ConnectionRateLimiter` is constructed with `max_connections_per_ipaddr_per_min` and a 10x burst allowance, and is entirely independent of stake [3](#0-2) . Neither the global bucket nor the per-IP limiter is aware of stake; that logic lives only in `SwQos::try_add_connection`, which differentiates `ConnectionPeerType::Staked`/`Unstaked` via separate connection tables and pruning policies [4](#0-3) . Because SwQoS is invoked strictly after the global token bucket check, an attacker distributing handshake attempts across many source IPs (each individually staying under the per-IP cap) can drain the shared 1000-token/2500-per-second budget, causing `overall_connection_rate_limiter.consume_tokens(1)` to fail for legitimate staked peers' connection attempts, which are then closed with `CONNECTION_CLOSE_CODE_DISALLOWED` before any stake-based admission decision is made [5](#0-4) .

The existing guards — per-IP rate limiting and SwQoS stake prioritization — do not protect against this because both are subordinate to (checked after) the shared, identity-agnostic global bucket.

## Impact Explanation
This falls under "non-RPC remote exhaustion/crash" for QUIC/TPU: an attacker able to sustain distributed connection attempts above the global refill rate can deny new TPU connections cluster-wide (or per validator/RPC-forward node), preventing legitimate staked validators/RPC forwarders from submitting transactions during the attack window, which can cause missed execution windows for time-sensitive transactions.

## Likelihood Explanation
The attack requires no stake, no privileged role, and no trusted-peer assumption — only the ability to open QUIC connections from a large, IP-diverse pool (cloud IP churn, IPv6 diversity) while staying under the per-IP cap of `max_connections_per_ipaddr_per_min` individually [6](#0-5) . Sustaining an aggregate rate above `TOTAL_CONNECTIONS_PER_SECOND = 2500` from thousands of distinct IPs is resource-intensive but does not require any elevated capability, satisfying the "unprivileged, public input" requirement.

## Recommendation
Reserve a portion of the global connection budget for stake-verified connections, or reorder logic so that stake verification (post-handshake) occurs before or alongside global token consumption, e.g., splitting `overall_connection_rate_limiter` into staked/unstaked sub-buckets analogous to `max_staked_connections`/`max_unstaked_connections` in `SwQosConfig`.

## Proof of Concept
1. From N distinct source IPs (each under `max_connections_per_ipaddr_per_min`), continuously initiate QUIC handshakes against a validator's TPU port.
2. Each handshake passes `rate_limiter.register_connection` (per-IP cap not hit) then calls `overall_connection_rate_limiter.consume_tokens(1)` [7](#0-6) .
3. Once aggregate attempts exceed 2500/s sustained, the shared bucket empties.
4. A legitimate staked validator's new connection attempt then fails at `overall_connection_rate_limiter.consume_tokens(1).is_err()` and is closed with `CONNECTION_CLOSE_CODE_DISALLOWED`, before `qos.try_add_connection`'s stake-based logic in `SwQos::try_add_connection` [8](#0-7)  is ever consulted.
