### Title
Potential redaction bypass when Any-typed fields marked `debug_redact=true` are expanded by `TextFormat::Printer::PrintAny` - ([File: src/google/protobuf/text_format.cc])

### Summary
The Grav report's core failure pattern is: a value is nominally protected by a redaction/sandboxing layer (the Twig `config` facade), but an allow-listed "escape hatch" (`grav.offsetGet('config')` combined with object-dumping filters) reaches the raw, unredacted object and serializes it directly, bypassing the sandbox's method gate entirely. The closest structural analog in this Protobuf checkout is the `debug_redact` field-option mechanism in `TextFormat`/`DebugFormat`, specifically how `google.protobuf.Any`-typed fields marked `debug_redact = true` interact with `TextFormat::Printer::PrintAny`, which unpacks and recursively prints the *packed* message's fields. I could not fully confirm from the available index whether `PrintAny`'s recursive expansion path checks `TryRedactFieldValue`/`GetRedactionState` before or independently of unpacking, so this analog is presented with that caveat rather than as a proven vulnerability.

### Finding Description
Protobuf's `debug_redact` field option is enforced only inside `TextFormat::Printer` when `redact_debug_string_` is set (i.e., via `DebugFormat`/`AbslStringify`/safe debug printing paths), via `TryRedactFieldValue()`, which consults `TextFormat::GetRedactionState()` computed from the field's `FieldOptions.debug_redact` and any enum-based `debug_redact` meta-annotations [1](#0-0) [2](#0-1) .

The test schema explicitly exercises a `google.protobuf.Any any_field = 18 [debug_redact = true];` case [3](#0-2) , confirming that `Any`-typed fields are expected to be redactable. Separately, `Printer::SetExpandAny(true)` is enabled for the `AbslStringify`/`DebugString` code path, which causes `PrintAny` to unpack the `Any` and recursively print the *inner* message's fields under their own field options [4](#0-3) .

The Grav-analogous failure mode would be: the redaction check (`TryRedactFieldValue`) is applied to the *outer* field descriptor (the `Any` field itself, or a message field wrapping it), while `PrintAny`'s unpacking walks the reflection of the dynamically-resolved inner type via the type registry — a separate code path from the field-level redaction gate. If `PrintAny` is invoked without first consulting (or independently of) the outer field's `RedactionState`, the "redacted" `Any` field's true contents would be printed via the type-registry-driven unpack-and-print path, analogous to `offsetGet('config')` returning the raw object that downstream filters serialize without going through the sandbox's method allowlist.

I was not able to retrieve and directly inspect the `PrintAny` function body or the exact call ordering between `TryRedactFieldValue` and `PrintAny` inside `PrintField`/`Print` before running out of investigation budget, so I cannot confirm the check bypass is actually reachable in this codebase, only that the two independent mechanisms (per-field redaction gate vs. Any-unpacking via type registry) exist and are structurally similar to the "facade vs. raw-object escape hatch" pattern in the Grav report.

### Impact Explanation
If confirmed, this would allow attacker-influenced or application-serialized data marked as sensitive (`debug_redact=true`) inside an `Any`-typed field to leak through debug/logging output (e.g., `AbslStringify`, `DebugFormat`, crash/log dumps) instead of being redacted as `[REDACTED]`. This is a disclosure issue limited to debug-formatting output, not the wire/binary or ProtoJSON parsing surface, and `debug_redact` is explicitly documented as providing best-effort, unstable debug redaction rather than a security boundary.

### Likelihood Explanation
Low-to-uncertain. This requires (a) a schema author to mark an `Any`-typed field `debug_redact=true`, (b) `SetExpandAny(true)` to be active (true for `AbslStringify`/`DebugString` paths), and (c) the unresolved question of whether `PrintAny`'s recursion actually skips the outer field's redaction check. Given `unittest_redaction.proto` explicitly test-covers `any_field` redaction, it is plausible upstream tests already cover and guard this interaction, which would make this analog non-reproducible in the current codebase. I could not verify either way within the available tool budget.

### Recommendation
A background engineer should read `src/google/protobuf/text_format.cc`'s `PrintAny` implementation and its caller (`PrintField`/`Print`) to confirm whether `TryRedactFieldValue` is checked and short-circuits *before* `PrintAny` is invoked for a redacted `Any` field, and whether the unpacked inner message's own field-level `debug_redact` annotations (not the outer field's) are the only ones honored during expansion. If the outer field's redaction state is not checked prior to `PrintAny` expansion, add that check (mirroring the existing `RedactedFields`/`TestNestedMessageRedaction` test pattern) and add a regression test with a `debug_redact=true` `Any` field containing a message with non-redacted inner fields, asserting the entire `Any` payload prints as `[REDACTED]` rather than expanding.

### Proof of Concept
Not executed — I could not confirm the `PrintAny` call-order details before the iteration budget was exhausted, so no concrete reproduction is provided. A verifying engineer should build on the existing `unittest_redaction.proto` `any_field` test scaffold [3](#0-2)  together with `TextFormatTest`'s existing `PrintAny` coverage [1](#0-0)  to construct a message with a `debug_redact=true` `Any` field packing a message with a plainly-named (non-redacted) string field, call `DebugFormat.multiline().toString(...)` or the C++ `AbslStringify`/`google::protobuf::ShortFormat` equivalent, and check whether the inner string value appears in cleartext instead of `[REDACTED]`.

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}
