### Title
Calls to self-destructed/no-code module addresses trivially succeed in `dispatchIncoming(GetResponse)` / `dispatchTimeOut(...)`, finalizing delivery and paying relayer fees without any real callback execution - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(PostRequest, address)` guards against calling a destination with no deployed code by checking `extcodesize` before making the low-level `.call`, and early-returns (without deleting the receipt) if `size == 0` so the message can be retried later. `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` make the exact same kind of low-level `.call` to an address derived from `request.from`/`timeout.request.from`, but omit this `extcodesize` check entirely. ### Finding Description
In Solidity, a low-level `.call(...)` to an address that has no deployed contract code returns `success == true` unconditionally (the EVM treats it as a trivial no-op/value transfer), even though no actual callback logic ever ran. This is precisely the "call to zero/empty address executes without reverting" bug class described in the external report.

`dispatchIncoming(PostRequest, address)` explicitly defends against this: it computes `destination = _bytesToAddress(request.to)`, checks `extcodesize(destination)`, and returns early (without storing state as "handled") if the size is zero, treating the request as retryable: [3](#0-2) 

The sibling functions that dispatch **GET responses** and **timeouts** do not apply this same guard. `dispatchIncoming(GetResponse, address)` calls `_bytesToAddress(response.request.from).call(...)` directly: [4](#0-3) 

`dispatchTimeOut(GetRequestTimeout, ...)` and `dispatchTimeOut(PostRequestTimeout, ...)` follow the same unguarded pattern, additionally deleting the replay-protection `_requestCommitments[commitment]` entry *before* the call is made: [5](#0-4) 

A module's `from` address is set to `_msgSender()` at the time the original `GetRequest`/`PostRequest` was dispatched (see `dispatch(DispatchGet)` / `dispatch(DispatchPost)`), so it is a legitimate contract at dispatch time. However, nothing prevents that contract from later self-destructing (`SELFDESTRUCT`) before the response/timeout is delivered — a scenario entirely within the normal, permissionless lifecycle of any on-chain contract, requiring no malicious relayer, prover, or admin.

When the response/timeout is eventually delivered to a `from` address with no code:
- In `dispatchIncoming(GetResponse)`: the `.call` trivially "succeeds," so the function unconditionally proceeds to pay the relayer fee via `IERC20(feeToken()).safeTransfer(relayer, fee)` and emits `GetRequestHandled`, even though the destination module was never actually notified.
- In both `dispatchTimeOut` variants: the commitment is deleted up front (permanent replay protection), the trivial "success" means the retry/reversion branch (`_requestCommitments[commitment] = meta`) never executes, and the relayer/sender fee refund is unconditionally paid out as if the timeout callback ran successfully.

This breaks the same invariant the `PostRequest` path was specifically hardened to protect: that fee payment and receipt/commitment finalization should only happen after a real callback execution, with an early, non-finalizing return when the destination has no code.

### Impact Explanation
This causes false state acceptance and unauthorized fund movement in the relayer-fee escrow: relayer fees are paid out (`dispatchIncoming(GetResponse)`) and the request lifecycle is permanently finalized (both `dispatchTimeOut` variants) for messages that were never actually delivered to any executing code. Once a `from` module has no code, the protocol permanently loses the ability to retry the message (no retry sentinel is written, unlike the `PostRequest` path), while at the same time treating the fee/refund flow as successfully completed. This matches the required impact classes: incorrect fee/refund distribution and false "successful delivery" state acceptance in a production bridge contract (`EvmHost`), reachable without any privileged, colluding relayer/prover assumption — the vulnerable condition (destination no longer has code) can arise purely from ordinary contract lifecycle events (self-destruct) on the source chain, independent of hostile behavior by the message deliverer.

### Likelihood Explanation
Moderate. It requires a source-chain module (dApp) that dispatched a `GetRequest`/`PostRequest` via `EvmHost.dispatch(...)` to subsequently self-destruct (or otherwise become codeless) before the corresponding `GetResponse` or timeout is delivered. `SELFDESTRUCT` is an ordinary, permissionless EVM operation available to any contract owner, and the delay between dispatch and response/timeout delivery (which can span the full timeout window) gives ample opportunity for this to occur without any collusion from relayers or provers — the relayer delivering the (valid, correctly proven) response/timeout is acting entirely normally.

### Recommendation
Add the same `extcodesize`/zero-address sanity check used in `dispatchIncoming(PostRequest)` to `dispatchIncoming(GetResponse)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`: verify the resolved destination address has non-zero code size before issuing the low-level `.call`, and if it does not, return early without finalizing the receipt/commitment deletion or releasing/refunding fees, consistent with the retryable-failure semantics already implemented for `PostRequest` delivery.

### Proof of Concept
1. Contract `M` on chain A calls `EvmHost.dispatch(DispatchGet{...})`; `EvmHost` records `request.from = M` and escrows the relayer fee in `_requestCommitments[commitment]`. [6](#0-5) 
2. Contract `M` executes `SELFDESTRUCT`, so `extcodesize(M) == 0` from this point on.
3. A relayer submits a validly-proven `GetResponse` (or the request times out) referencing this commitment; `HandlerV2`/consensus verification passes because the underlying state proof is legitimate.
4. `EvmHost.dispatchIncoming(GetResponse, relayer)` executes `_bytesToAddress(response.request.from).call(...)` against the now-codeless `M`; the call returns `success == true` trivially. [7](#0-6) 
5. The relayer fee is paid out and `GetRequestHandled` is emitted, and/or (in the timeout path) the commitment is permanently deleted and the sender/relayer refund is paid — all despite the fact that no application logic was ever invoked to process the response/timeout, and with no retry path available (unlike the analogous `PostRequest` code path).

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)

            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;

        if (meta.fee != 0) {
