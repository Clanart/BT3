### Title
EncryptedMessage::read accepts an identity encryption key, letting a malicious DKG participant forge the proof-of-possession and control the decrypted plaintext - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The bug class in the reference report is a sanitization layer that exists but is silently bypassed: `react-markdown` ships `defaultUrlTransform`, yet `MarkdownBody` replaces it with a no-op. Serai has the same shape in the PedPoP DKG encryption layer. FROST's `Curve::read_G` adds an identity-point rejection on top of `Ciphersuite::read_G` (`crypto/frost/src/curve/mod.rs:123-131`), but `EncryptedMessage::read`, `EncryptionKeyMessage::read`, and `EncryptionKeyProof::read` in `crypto/dkg/pedpop/src/encryption.rs` all call `C::read_G` directly — the canonical-encoding check only — so an identity group element is accepted as an ECDH public key. An identity key makes the Schnorr PoP trivially forgeable and makes the ECDH shared point equal to the identity, whose encoding is public, so the ChaCha20 keystream is computable by anyone.

### Finding Description
`EncryptedMessage::read` reads `key`, `pop`, and `msg` from attacker-controlled bytes using `C::read_G`, which only enforces canonical encoding and never rejects the identity point (crypto/dkg/pedpop/src/encryption.rs:170-177, crypto/ciphersuite/src/lib.rs:91-101). For prime-order/torsion-free groups (Ristretto, Ed25519 via `is_torsion_free` in crypto/dalek-ff-group/src/lib.rs:470-478, Ed448 via crypto/ed448/src/point.rs:295-318), the identity passes `from_bytes` and re-encodes canonically, so it is accepted.

Two defenses collapse once `key = identity`:

1. The proof-of-possession check `msg.pop.verify(msg.key, pop_challenge(...))` (encryption.rs:374-377, also batched at 479-485) reduces to `R + c*identity - sG == 0`, i.e. `R == sG`. Any `s` with `R = s·G` verifies — no knowledge of a discrete log is needed. The PoP exists specifically to stop Eve from replaying/forging encryption keys (comment at encryption.rs:83-90); the identity key re-opens exactly that hole.

2. `ecdh(private, identity) = identity` (encryption.rs:95-97), so `cipher()` derives the ChaCha20 key from `to_bytes(identity)` — a constant known to everyone (encryption.rs:101-133). The "ciphertext" is therefore a publicly-computable keystream XOR, and the sender fully controls the plaintext the victim's `decrypt` produces.

The check that would prevent this already exists in the codebase — `Curve::read_G` rejects identity — but this module is generic over `Ciphersuite`, which has no such hook, so the defense is unreachable here, mirroring the report's `urlTransform` override that neutralizes `defaultUrlTransform`.

### Impact Explanation
An unprivileged DKG participant can send a "valid-looking" `EncryptedMessage` that (a) passes the PoP verification in both `decrypt` (batched) and `decrypt_with_proof`, and (b) decrypts to attacker-chosen bytes because the ECDH shared point is the publicly known identity encoding. Concretely, the attacker can deliver a share plaintext of their choosing that the victim will attribute to the attacker after `verify_share`, or deliberately craft a plaintext that fails share verification to steer the victim into the blame path — where `EncryptionKeyProof` will carry `key = enc_key * identity = identity` and a DLEq over `(G, identity) → (enc_keys[decryptor], identity)`, an invalid/wrong decryption "key" that corrupts blame attribution. The PoP's stated purpose — preventing forged/reused keys from poisoning decryption and blame — is defeated.

### Likelihood Explanation
The attacker only needs to send a DKG message with `key` set to the canonical identity encoding (32 zero bytes for Ed25519/Ristretto) plus a signature `(R = sG, s)` of their choosing — no discrete logs, no prerequisites beyond participating in the DKG and reaching `EncryptedMessage::read`/`decrypt`. Deterministic and trivially reachable from public inputs.

### Recommendation
Reject identity points wherever an ECDH/encryption key is deserialized in `crypto/dkg/pedpop/src/encryption.rs`: after `C::read_G` in `EncryptedMessage::read`, `EncryptionKeyMessage::read`, and `EncryptionKeyProof::read`, check `res.is_identity()` and error out, mirroring `Curve::read_G` (crypto/frost/src/curve/mod.rs:125-131). Additionally, in `decrypt`/`decrypt_with_proof`, reject `msg.key.is_identity()` (and `proof.key.is_identity()`) before computing the ECDH so a malicious peer cannot force the shared point to a public constant.

### Proof of Concept

// Forged PoP: pick any s, set R = s*G. Verification checks
//   R + c*key - s*G == 0  =>  s*G + c*identity - s*G == 0  =>  true
let s = <C as Ciphersuite>::hash_to_F(b"anything", b"x"); // arbitrary scalar
let forged_pop = SchnorrSignature::<C> { R: C::generator() * s, s };

// msg = chosen_plaintext XOR keystream, where the keystream is derived from
// to_bytes(identity) — publicly computable via cipher(context, &Zeroizing::new(identity))
let mut msg = Zeroizing::new(chosen_share_bytes);
cipher::<C>(context, &Zeroizing::new(identity)).apply_keystream(msg.as_mut().as_mut());

let evil = EncryptedMessage { key: identity, pop: forged_pop, msg };

// Victim side: EncryptedMessage::read accepts it (identity is canonical),
// Encryption::decrypt passes batch PoP verification, and ecdh(enc_key, identity) = identity
// reproduces the same keystream -> decrypts to attacker-chosen plaintext.
