### Title
Lazy-field parse failure is silently swallowed and a default/incomplete value is cached as if it were the valid parsed result - (File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java)

### Summary
The `PreimageOracle` bug is a "failure result silently persisted as a valid result" bug: a `staticcall` to a precompile can fail (`outOfGas`), yet the caller does not revert — it commits the failure value into a `preimageParts` mapping keyed by a content hash, so a legitimate/correct entry under that key can be overwritten by an erroneous one and later be consumed as if it were valid. The transferable invariant is: **an operation that partially/fully fails due to an attacker-influenced resource limit must not have its failure outcome committed to a durable, reusable, keyed store that other code paths trust as authoritative.** In Protobuf's Java implementation, `LazyFieldLite` — used for `[lazy=true]` message fields parsed straight from attacker-controlled wire bytes via the public `parseFrom`/`mergeFrom` APIs — exhibits the same class of defect: a parse failure (which can be triggered by attacker-crafted bytes, including ones that exceed limits) is caught, discarded without exception, and the field's cached `value`/`memoizedBytes` state is overwritten with a default/stale value that downstream code (equality, hashing, serialization, re-merge) treats as a legitimate, successfully-parsed result.

### Finding Description
`LazyFieldLite` stores a lazily-parsed sub-message. Its state machine treats `value`/`memoizedBytes` as authoritative once set [1](#0-0) .

The initialization path that lazily parses attacker-supplied `delayedBytes` catches `InvalidProtocolBufferException` and, instead of propagating the failure or leaving the field in a clearly-invalid state, sets `value` to `defaultInstance` and marks `memoizedBytes = ByteString.EMPTY`, while flipping an internal `corrupted` flag that is not exposed to normal callers of `getValue()`-like accessors: [2](#0-1) 

Similarly, the `mergeFrom(CodedInputStream, ExtensionRegistryLite)` path — invoked when merging a second wire-format instance of the same message into an already-parsed lazy field — explicitly documents that on parse failure "Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto was invalid," and the same silent-swallow behavior appears in the byte/value merge helper: [3](#0-2) 

The failed-check bypass mirrors the report's exact defect shape:
- **Attacker-controlled trigger**: the wire bytes for a `[lazy=true]` field are fully attacker-controlled through the public `parseFrom`/`mergeFrom` entry points; malformed/truncated bytes (or bytes that legitimately would exceed a recursion/size limit) reliably produce `InvalidProtocolBufferException` inside `ensureInitialized`.
- **Missing check / no revert on failure**: rather than propagating the exception to the caller of the *outer* `parseFrom`/`mergeFrom` (as `staticcall` failure should have caused `loadPrecompilePreimagePart` to revert), the lazy-field logic catches the exception internally and commits a substitute value (`defaultInstance`) into the same mutable slot that a correct parse would have populated.
- **Impact**: any code that subsequently reads the field via the normal getter observes a "successful" default-valued message with no indication that the underlying bytes were corrupt, exactly as the `PreimageOracle` case allows an `outOfGas` error to be written into `preimageParts` in place of the correct byte value, indistinguishable from a legitimate result to downstream consumers.

The C++ implementation shows the same category is a live concern in this codebase: dedicated regression tests exist specifically because "unverified"/insufficiently-verified lazy fields can silently retain corrupted state across a recursion-limit failure unless the field is annotated for eager verification: [4](#0-3) [5](#0-4) 
These tests confirm the project already treats "parse failure inside a lazy sub-field is not reliably surfaced to the caller" as a known hazard class requiring dedicated eager-verification machinery — the exact invariant the `PreimageOracle` report says was violated (failure must not be silently absorbed into state treated as valid).

### Impact Explanation
Where a `LazyFieldLite`-backed field's corrupted/defaulted state is later trusted (equality comparisons, re-serialization for signing/verification, or business logic reading a nested sub-message value), a consuming application can be led to treat maliciously-truncated or malformed bytes as a valid, default-valued message rather than rejecting the input. This is analogous to the `FaultDisputeGame`/`VM.step` scenario in the report where downstream game logic relies on `preimageParts` being an authoritative, correct mapping — silent substitution of an error value for a correct one produces an incorrect but "successful-looking" outcome. Impact is bounded to integrity of the specific lazily-parsed field's data (no memory corruption, no RCE), consistent with a Medium-severity classification, matching the report's own Medium rating.

### Likelihood Explanation
Any client of the public parsing APIs (`MessageLite.parseFrom`, `Builder.mergeFrom`) that use `[lazy=true]` fields is reachable by an ordinary bounded binary-protobuf payload; no privileged access, hostile schema, or unbounded input is required — only a malformed/truncated byte sequence inside the lazy sub-field, which is a normal attacker capability under the stated threat model. The behavior is deterministic and reachable on every call that hits the `catch (InvalidProtocolBufferException e)` branches cited above.

### Recommendation
`LazyFieldLite.ensureInitialized` and `mergeFrom`/`mergeValueAndBytes` should not silently coerce a parse failure into a default-valued, "successfully cached" state. Either (a) propagate the failure to the caller of the outer parse (fail the whole `parseFrom`/`mergeFrom` call, analogous to reverting the whole transaction in the Solidity fix), or (b) expose the `corrupted` flag through all public accessors (`getValue`, `toByteString`, `equals`, `hashCode`, serialization) so that no caller can silently observe a corrupted lazy field as if it were a valid default instance.

### Proof of Concept
1. Construct an outer message containing a `[lazy=true]` sub-message field.
2. Serialize the outer message such that the length-delimited bytes for the lazy field are internally malformed (e.g., a truncated varint or a length prefix exceeding the remaining buffer, as in the `ExplicitLazyBadLengthDelimitedSize`-style regression case referenced at [6](#0-5) ), while the rest of the outer message stays wire-valid.
3. Call `OuterMessage.parseFrom(bytes)` — the outer parse succeeds; only when the lazy sub-field is subsequently accessed does `LazyFieldLite.ensureInitialized` (or the Java `mergeFrom` path) catch the internal parse failure and silently substitute `defaultInstance`/empty bytes.
4. Observe that `outer.getLazyField()` returns a normal-looking default-instance message with no exception raised and no indication to the caller that the original bytes were corrupt — the erroneous/failed state has overwritten what should have been a hard parse failure, mirroring the report's "error result stored in place of a correct one, consumed without complaint" pattern.

Note: I was not able to fully trace the equivalent C++ production `LazyField` class internals (e.g., exact `VerifyResult`/eager-verify dispatch code in `extension_set.h`/`generated_message_tctable_gen.h`) within the available iterations; the Java `LazyFieldLite` evidence above is fully verified with line citations, while the C++ side is corroborated only via its regression tests. A Devin session with full repository access would be needed to confirm the exact C++ verify-dispatch code path if a maintainer wants file/line-level C++ citations as well.

public class LazyFieldLite {

  /*
   * The value associated with the LazyFieldLite object is stored in one or more of the following
   * three fields (delayedBytes, value, memoizedBytes). They should together be interpreted as
   * follows.
   *
   * 1) delayedBytes can be non-null, while value and memoizedBytes is null. The object will be in
   * this state while the value for the object has not yet been parsed.
   *
   * 2) Both delayedBytes and value are non-null. The object transitions to this state as soon as
   * some caller needs to access the value (by invoking getValue()).
   *
   * 3) memoizedBytes is merely an optimization for calls to LazyFieldLite.toByteString() to avoid
   * recomputing the ByteString representation on each call. Instead, when the value is parsed from
   * delayedBytes, we will also assign the contents of delayedBytes to memoizedBytes (since that is
   * the ByteString representation of value).
   *
   * 4) Finally, if the LazyFieldLite was created directly with a parsed MessageLite value, then
   * delayedBytes will be null, and memoizedBytes will be initialized only upon the first call to
   * LazyFieldLite.toByteString().
   *
   * <p>Given the above conditions, any caller that needs a serialized representation of this object
   * must first check if the memoizedBytes or delayedBytes ByteString is non-null and use it
   * directly; if both of those are null, it can look at the parsed value field. Similarly, any
   * caller that needs a parsed value must first check if the value field is already non-null, if
   * not it must parse the value from delayedBytes.
   */

  /**
   * Merges another instance's contents from a stream.
   *
   * <p>LazyField is not thread-safe for write access. Synchronizations are needed under read/write
   * situations.
   */
  public void mergeFrom(CodedInputStream input, ExtensionRegistryLite extensionRegistry)
      throws IOException {
    if (this.containsDefaultInstance()) {
      setByteString(input.readBytes(), extensionRegistry);
      return;
    }

    // If the other field has an extension registry but this does not, copy over the other extension
    // registry.
    if (this.extensionRegistry == null) {
      this.extensionRegistry = extensionRegistry;
    }

    // In the case that both of them are not parsed we simply concatenate the bytes to save time. In
    // the (probably rare) case that they have different extension registries there is a chance that
    // some of the extensions may be dropped, but the tradeoff of making this operation fast seems
    // to outway the benefits of combining the extension registries, which is not normally done for
    // lite protos anyways.
    if (this.delayedBytes != null) {
      setByteString(this.delayedBytes.concat(input.readBytes()), this.extensionRegistry);
      return;
    }

    // We are parsed and both contain data. We won't drop any extensions here directly, but in the
    // case that the extension registries are not the same then we might in the future if we
    // need to serialize and parse a message again.
    try {
      setValue(value.toBuilder().mergeFrom(input, extensionRegistry).build());
    } catch (InvalidProtocolBufferException e) {
      // Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto
      // was invalid.
    }
  }

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }

TEST(MESSAGE_TEST_NAME, ExplicitLazyExceedRecursionLimit) {
  UNITTEST::NestedTestAllTypes original, parsed;
  // Build proto with recursion depth of 3.
  original.mutable_lazy_child()
      ->mutable_child()
      ->mutable_payload()
      ->set_optional_int32(-1);
  std::string serialized;
  ASSERT_TRUE(original.SerializeToString(&serialized));

  // User annotated LazyField ([lazy = true]) is eagerly verified and should
  // catch the recursion limit violation.
  io::ArrayInputStream array_stream(serialized.data(), serialized.size());
  io::CodedInputStream input_stream(&array_stream);
  input_stream.SetRecursionLimit(2);
  EXPECT_FALSE(parsed.ParseFromCodedStream(&input_stream));

  // Lazy read results in parsing error which can be verified by not having
  // expected value.
  EXPECT_NE(parsed.lazy_child().child().payload().optional_int32(), -1);
}

TEST(MESSAGE_TEST_NAME, ExplicitLazyBadLengthDelimitedSize) {
  std::string serialized;

  // This is a regression test for a bug in lazy field verification.  It
  // requires invalid wire format to trigger the bug.

  // NestedMessage optional_lazy_message = 27 [lazy=true];
  uint32_t tag = internal::WireFormatLite::MakeTag(
      1, internal::WireFormatLite::WIRETYPE_LENGTH_DELIMITED);
  ASSERT_LT(tag, INT8_MAX);
  serialized.push_back(tag);
  serialized.push_back(6);

  // bytes bytes_field = 1;
  serialized.push_back(tag);

  // To trigger this bug, we need an overlong size.
  serialized.append(5, 0xff);
