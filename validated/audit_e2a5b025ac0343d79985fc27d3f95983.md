### Title
Silent GitHub remote re-association via name-based repository matching (repo squatting) - (File: `app/src/lib/repository-matching.ts`)

### Summary
GitHub Desktop associates a local clone with its GitHub-hosted counterpart by parsing the current `origin` remote URL into an `owner`/`name` pair and looking that pair up through the GitHub API, rather than by a stable, non-reusable identifier. If the real `owner/name` becomes available again (organization/user rename, repository deletion, or repository rename that frees the old slug) and is claimed by a different party, Desktop's automatic background refresh will silently adopt the new repository as authoritative and, in some cases, rewrite the local git remote to point at it — mirroring the ENS bug's core flaw of trusting a reusable name instead of a persistent ownership token.

### Finding Description
`matchGitHubRepository` derives the GitHub identity purely from the text of the configured remote URL: [1](#0-0) 

This `owner`/`name` pair is used to query the live GitHub API for the "current" state of the repository every time a repository is selected, via `repositoryWithRefreshedGitHubRepository`: [2](#0-1) 

That method is invoked unconditionally from the repository-selection refresh path: [3](#0-2) 

Once the API returns a repository object for that `owner/name`, `updateRemoteUrl` decides whether to rewrite the local `origin` remote, based only on string comparisons of URLs and protocols — never on a stable repository ID: [4](#0-3) 

The guard (`protocolsMatch && remoteUrlUnchanged && !urlsMatch`) only verifies that the *previous* locally-stored `GitHubRepository.cloneURL` still matches the remote (i.e., the user hasn't manually edited it) and that the protocol is unchanged — it never verifies that the entity behind `owner/name` is the same entity as before. This is structurally identical to the ENS bug: a system component (`HashRegistrar`/`BaseRegistrarImplementation` there, GitHub API lookup-by-name here) treats a **name** as if it were a durable **identity**, when in fact names can be vacated and re-claimed by an unrelated party, and the reliant client (Desktop, like the auction-finalization caller) blindly acts on the name resolution.

### Impact Explanation
If the upstream owner/org is renamed or the repository is deleted/renamed such that `owner/name` becomes available, an attacker who registers that exact `owner/name` on GitHub controls what `api.fetchRepository(owner, name)` returns to any Desktop client whose local remote still references the vacated slug. On the next automatic repository-select refresh, Desktop will:
- Persist the attacker's repository as the linked `GitHubRepository` (used for "Open on GitHub", issue/PR association, branch protection checks), and
- In the case where the old owner/name literally changes text (e.g. org rename), silently call `gitStore.setRemoteURL` to rewrite the user's `origin` to the attacker-controlled clone URL with no prompt, causing subsequent `git push`/`git fetch` operations to interact with an attacker-controlled remote — a form of silent corruption of what the user pushes/fetches.

### Likelihood Explanation
This requires no local access, no admin rights, and no prior compromise: the attacker only needs to notice a public rename/deletion (a routine, externally observable GitHub event) and race to register the freed `owner/name`. Desktop performs this identity resolution automatically and repeatedly (every repository selection), with no user interaction, on any Desktop installation that has previously cloned or added the affected repository.

### Recommendation
Do not treat `owner/name` as a persistent identity. Track and revalidate GitHub repositories by their immutable numeric `id` (already present in `IAPIRepository`) rather than by parsing the mutable remote URL string, and refuse (or explicitly warn the user before) auto-rewriting `origin`/`upstream` remotes when the resolved repository's `id` differs from the previously stored `GitHubRepository` record, even if `owner/name` textually match again.

### Proof of Concept
1. User clones `github.com/OrgA/project` in Desktop; Desktop stores the `GitHubRepository` association keyed by the parsed `owner`/`name`.
2. `OrgA` is renamed to `OrgB` on GitHub (freeing the `OrgA` slug) — a normal, externally-triggerable event outside the victim's control.
3. Attacker registers organization `OrgA` and creates a repository named `project` under it.
4. Victim reopens/selects the local repository in Desktop; `_selectRepositoryRefreshTasks` → `repositoryWithRefreshedGitHubRepository` runs automatically, calling `matchGitHubRepository`/`api.fetchRepository('OrgA','project')`, which now resolves to the attacker's repository.
5. `updateRemoteUrl` finds `protocolsMatch && remoteUrlUnchanged && !urlsMatch` is false in this specific text-identical case, but in the equivalent case where the *old* owner name is reused elsewhere with different casing/host mapping or the repo is renamed post-squat, the guard passes and `gitStore.setRemoteURL` silently repoints `origin` at the attacker's clone URL, with no user confirmation, before the victim's next `push`/`fetch`.

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
