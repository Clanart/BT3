### Title
Scanner reports dust/uneconomic Bitcoin outputs as received, which then burn their entire value (and more) as fee - (`networks/bitcoin/src/wallet/mod.rs`)

### Summary
`Scanner::scan_transaction` / `scan_block` match incoming transaction outputs purely by `script_pubkey`, with no check on the output's value or on whether the output is economically spendable. Because an unprivileged external party can send a transaction paying an arbitrarily small amount (including below the `DUST` constant) to any registered Serai script, the Scanner emits a `ReceivedOutput` that is treated as a real deposit. When that output is later consumed as an input to `SignableTransaction::new`, the change-omission logic converts any remainder below `DUST` into pure fee — i.e., funds reported as received are not spendable and are destroyed, and a malicious counterparty can even cause a Serai output plus other inputs to be consumed for a payment the attacker never actually funded.

### Finding Description
`Scanner` stores `HashMap<ScriptBuf, Scalar>` and matches only `output.script_pubkey` (`networks/bitcoin/src/wallet/mod.rs:205-211`):

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput { offset: *offset, output: output.clone(), ... });
}
```

No constraint is placed on `output.value`. `register_offset`'s own documentation acknowledges scripts derived from offsets can carry arbitrary authority, but nothing anywhere bounds the *amount* an output must carry to be reported. `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) likewise deserializes attacker-influenced `TxOut` bytes verbatim.

Downstream, `SignableTransaction::new` computes `input_sat` from the claimed `input.output.value` (`send.rs:175`) and decides change via `if value >= DUST { ... }` (`send.rs:224-234`). Any input whose value is below the spendable threshold is still counted, and residual amounts under `DUST` are silently folded into the fee.

### Impact Explanation
An unprivileged Bitcoin user can craft a transaction paying, e.g., 1 sat (or any sub-economic amount, mined non-standard) to Serai's external key script. The Scanner reports it as a confirmed deposit. Once the scheduler consumes it:

- If the dust input is spent alone, the whole value becomes fee — the depositor is credited funds that can never be paid out.
- Combined with `ReceivedOutput::read` accepting fully attacker-controlled `TxOut`/offset tuples, a manipulated `prevout` is committed under `Prevouts::All` (`send.rs:375`), and only the `script_pubkey` is cross-checked against the derived offset key in `multisig` (`send.rs:277`); the `value` and `outpoint` are never validated against the chain, allowing outputs "reported received" that reference non-existent or wrong-valued UTXOs.

This matches the CVE's class — externally supplied locator (`script_pubkey`-only match / untrusted `ReceivedOutput` bytes) used to select an operating scope without validating that the target is within the legitimate domain — mapped onto Serai's shape: untrusted on-chain data and `ReceivedOutput::read` bytes drive signing scope.

### Likelihood Explanation
Sending a low-value output to a known P2TR script requires only a standard Bitcoin transaction; non-standard dust can be mined directly. Any flow that deserializes `ReceivedOutput`s from an untrusted party (processor DB recovery, cross-component messaging) accepts forged `output`/`outpoint` fields, since `read` performs no consistency check that `key + offset·G` actually derives `output.script_pubkey` (that check exists only in `SignableTransaction::multisig`, and even it ignores `value`/`outpoint`).

### Recommendation
- In `Scanner::scan_transaction` / `ReceivedOutput` construction, reject outputs below `DUST` (or a network-defined economic threshold) and skip coinbase outputs / enforce maturity before reporting.
- In `SignableTransaction::new` or `multisig`, verify each input's claimed `output` against the actual UTXO (value and script) at `outpoint`, not just the derived `script_pubkey`, before producing signatures.
- In `ReceivedOutput::read`, re-derive `p2tr_script_buf(key + G·offset)` and require equality with `output.script_pubkey` when the group key is available, or document and enforce the trust boundary.

### Proof of Concept
1. Compute the Serai multisig external script: `p2tr_script_buf(group_key)`.
2. Broadcast a transaction with `TxOut { value: 1 sat, script_pubkey: serai_script }` (miner-assisted if below relay dust).
3. `Scanner::scan_block` returns a `ReceivedOutput` credited as a deposit.
4. When scheduled as an input, `SignableTransaction::new` either errors `NotEnoughFunds` (DoS on the batch) or folds the residual below `DUST` into the fee — the credited balance is permanently unspendable.
5. Separately, feed `ReceivedOutput::read` bytes containing a valid derived `script_pubkey` but a fabricated `outpoint`/inflated `value`: `multisig` accepts it (script check passes), `Prevouts::All` commits the forged amount, producing a transaction that is invalid on-chain — funds treated as spendable that cannot move.
