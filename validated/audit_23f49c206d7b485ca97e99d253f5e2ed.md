## Finding Summary

The upstream Fabric bug is a **race where a security-relevant value (the TLS configuration used to authenticate a connection) is derived from data that is not properly synchronized/validated with the actor that is supposed to control it**, letting a connection go through with the wrong trust material. The closest reachable analog in this Desktop codebase is not a literal memory race (Node/Electron is single-threaded), but the same broken invariant: **a value that gates a trust/authentication decision is derived from attacker-controlled data (an HTTP response header from the remote being cloned/fetched) instead of a validated, application-controlled source**, and that decision is then used to redirect Desktop's own OAuth sign-in flow (including its `client_secret`) to that attacker-controlled origin.

### Title
Attacker-controlled `WWW-Authenticate` response can redirect GitHub Desktop's Enterprise OAuth sign-in flow (and leak the OAuth client secret) to a malicious git remote - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
When Git needs credentials for a remote, it invokes Desktop's credential-helper trampoline. `getEndpointKind` classifies the target host as `'enterprise'` purely by inspecting the `wwwauth[...]` header values that the *remote server* returned in its `401` response, before any real validation of the host is done. [1](#0-0) 

### Finding Description
`getEndpointKind` runs the domain allowlist checks (`isGist`, `isDotCom`, `isGHE`) first, but if none match (i.e. the host is *not* a recognized GitHub domain), it falls back to trusting the `WWW-Authenticate` header content copied verbatim from the remote's own HTTP response: [2](#0-1) 

Any HTTP git server the user clones/fetches from — including a fully attacker-controlled server, or a MITM proxy on an `http://` remote — can simply answer with `WWW-Authenticate: Basic realm="GitHub"` to force `endpointKind` to `'enterprise'` for its own arbitrary origin.

In `getCredential`, once `endpointKind !== 'generic'` and no existing account matches that origin, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then binds the sign-in flow to the attacker's origin because the hostname isn't `github.com`: [4](#0-3) 

`setSignInEndpoint` → `SignInStore.setEndpoint` only checks URL *syntax* and that the scheme is `https`; it does not check that the host is actually a legitimate/known Enterprise/GHE instance: [5](#0-4) 

If the user proceeds with browser-based sign-in, `authenticateWithBrowser` opens the OAuth authorize URL built from the attacker's endpoint, and later `resolveOAuthRequest` exchanges the OAuth code by POSTing Desktop's `client_id`/`client_secret` to `${endpoint}/login/oauth/access_token` — i.e. to the attacker's server: [6](#0-5) [7](#0-6) [8](#0-7) 

### Impact Explanation
This lets an attacker who controls a cloned/fetched git remote (or MITMs a plaintext HTTP remote) achieve two things without any local access, admin rights, or pre-existing malware:
1. **OAuth client secret exfiltration** — Desktop's static `ClientSecret` is sent directly to the attacker's server as part of the (falsely believed to be) Enterprise OAuth token exchange.
2. **Unauthorized/spoofed OAuth account binding & phishing surface** — the user is shown Desktop's native "Sign in to GitHub" popup (`isCredentialHelperSignIn: true`) pointed at an attacker-chosen origin they never explicitly typed in, increasing the chance they complete authentication (OAuth or PAT) against the attacker's endpoint.

This matches the "unauthorized OAuth or account binding" / "credential exfiltration" categories in scope.

### Likelihood Explanation
The trigger requires only that the user performs an ordinary git operation (clone/fetch/push) against a remote the attacker controls, or that an HTTP (non-TLS) git remote is intercepted — no unusual user action beyond normal Desktop usage (adding/cloning a repo) is needed. The `wwwauth[...]` header content is entirely attacker-supplied server response data, so this is fully attacker-triggerable and not dependent on social engineering beyond hosting/serving a malicious repo, which is explicitly in scope.

### Recommendation
- Do not classify a host as `'enterprise'` (nor invoke the sign-in flow) based solely on an unauthenticated `WWW-Authenticate` header from the remote itself; require the positive network probe (`isGitHubHost`) or an explicit user action before treating an unknown host as a GitHub-branded endpoint.
- When initiating an Enterprise OAuth/credential-helper sign-in triggered implicitly from a git operation (`isCredentialHelperSignIn`), warn the user which exact host they are about to authenticate to, and avoid embedding/transmitting the shared `ClientSecret` to endpoints that haven't been explicitly confirmed by the user as their known Enterprise server.

### Proof of Concept
1. Host a git-over-HTTP server (or MITM an `http://` remote) that, on a credential-required request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or fetch from that server, e.g. `http://evil.example.com/repo.git`.
3. Git invokes the credential helper trampoline; `getEndpointKind` returns `'enterprise'` due to the spoofed header (`app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`).
4. Desktop shows the "Sign in to GitHub" popup bound to `https://evil.example.com` (`trampoline-ui-helper.ts:80-99`, `sign-in-store.ts:394-437`).
5. If the user proceeds with browser sign-in, Desktop's `client_id`/`client_secret` are POSTed to `https://evil.example.com/login/oauth/access_token` (`sign-in-store.ts:332-359`, `api.ts:2370-2395`), which the attacker's server can log.

**Uncertainty:** I could not fully trace the `sign-in.tsx` UI component in this pass to confirm which UI path (browser OAuth vs. basic-auth PAT entry) is presented by default when `isCredentialHelperSignIn` is true, since I've used all available tool iterations. This affects whether the OAuth-secret-leak path or a direct PAT-leak path is the one actually reachable by default; both are plausible given the code shown, but confirming the exact default UI flow would need further review of `app/src/ui/sign-in/sign-in.tsx`.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}
