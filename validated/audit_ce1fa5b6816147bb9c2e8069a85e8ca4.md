### Title
Empty aggregate Schnorr signature bypasses verification - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an aggregate containing zero `Rs`, and `SchnorrAggregate::verify` evaluates the resulting empty verification equation as identity when `s = 0`. [1](#0-0) [2](#0-1) 

### Finding Description
The deserializer accepts a serialized aggregate beginning with a zero length and containing only the scalar `s`. [1](#0-0)  Verification checks only that the serialized `Rs` count matches the supplied `keys_and_challenges` count, then creates one verification pair `(-s, G)`. [2](#0-1)  For `keys_and_challenges == []`, `Rs == []`, and `s == 0`, this reduces to `-0 * G == identity`, so verification returns true. [3](#0-2) 

The producer-side API explicitly refuses to construct an empty aggregate, establishing that empty aggregates are outside the intended signature domain. [4](#0-3) 

### Impact Explanation
An unauthenticated caller can forge a canonical aggregate signature byte string accepted by `SchnorrAggregate::verify` for an empty signer set without knowing any private key. [1](#0-0)  Any public-input path that feeds untrusted bytes to `SchnorrAggregate::read` and then calls `verify` with an empty signer/challenge list receives a positive authentication result for a signature no signer produced. [2](#0-1) 

### Likelihood Explanation
The attack is deterministic and requires only 36 bytes: a four-byte little-endian zero length followed by a canonical zero scalar. [1](#0-0)  Exploitation requires a verifier to authorize or authenticate using an empty signer set, which is degenerate but not rejected by this API. [2](#0-1) 

### Recommendation
Reject empty aggregate signatures in both `SchnorrAggregate::read` and `SchnorrAggregate::verify`, matching `SchnorrAggregator::complete`, which already returns `None` when no signatures were aggregated. [5](#0-4)  Add a regression test asserting that the zero-length aggregate with `s = 0` fails parsing or verification. [6](#0-5) 

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use dalek_ff_group::Ristretto;
use schnorr::aggregate::SchnorrAggregate;

// uint32_le(0) || canonical_scalar(0)
let mut encoded = Vec::from(0u32.to_le_bytes());
encoded.extend([0u8; 32]);

let aggregate =
  SchnorrAggregate::<Ristretto>::read(&mut encoded.as_slice()).unwrap();

// No signers, yet verification succeeds.
assert!(aggregate.verify(b"domain", &[]));
```

The parsed aggregate has `Rs.len() == 0` and `s == 0`; `verify` therefore evaluates only `-s * G`, which is identity. [3](#0-2)
