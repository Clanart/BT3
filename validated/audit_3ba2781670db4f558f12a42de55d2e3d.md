### Title
Queued rewards in `DelegateVoteRewardPool` are stolen by a staker who enters right after `totalSupply` drops to zero - ([File: rewards/DelegateVoteRewardPool.sol / rewards/BaseRewardPoolV2.sol])

### Summary
`DelegateVoteRewardPool` (and the base `_provisionReward`/`_queueNewRewardsWithoutTransfer` logic it inherits) buffers harvested bribe rewards into `queuedRewards` whenever `totalSupply == 0`, and only converts that buffer into `rewardPerTokenStored` (pro‑rata over the then-current `totalSupply`) on the *next* harvest that occurs while `totalSupply > 0`. Because `harvestAll()` is a permissionless external function and stake/unstake into the pool happens through the public `WombatBribeManager.vote()`/`unvote()` calls, any unprivileged user can time a tiny stake to land exactly when `totalSupply` transitions from 0 to non‑zero and capture the entire backlog of bribes that accrued while prior, larger stakers were voting.

### Finding Description
`DelegateVoteRewardPool.harvestAll()` has no access control: [1](#0-0)  It pulls bribes via `WombatBribeManager.claimAllBribes(address(this))`, which is also public, and forwards them to `_manageRewards` → `_queueNewRewardsWithoutTransfer`: [2](#0-1) 

If `totalSupply == 0` at the moment `_queueNewRewardsWithoutTransfer` runs, the entire harvested amount is parked in `rewardInfo.queuedRewards` without touching `rewardPerTokenStored`. The same pattern exists in the generic base pool's `_provisionReward`: [3](#0-2) 

`totalSupply` for `DelegateVoteRewardPool` is driven by `stakeFor`/`withdrawFor`, which are only callable by the `onlyOperator` (`WombatBribeManager`) but are reachable by any unprivileged user through the public `vote()`/`unvote()` entry points: [4](#0-3)  and [5](#0-4) . Each user's `unvote()`/negative `vote()` delta reduces their allocation into the delegate pool's `rewarder` (which for the delegated pool is `DelegateVoteRewardPool` itself), so `totalSupply` can legitimately reach 0 if all current stakers unvote.

The critical accounting gap: when a new staker enters via `stakeFor`, the `updateRewards` modifier only snapshots `userRewardPerTokenPaid` at the *current* `rewardPerTokenStored` value — it does **not** account for the pool's `queuedRewards` balance: [6](#0-5) . Consequently, any queued rewards accumulated during the zero-`totalSupply` window are still un-attributed to `rewardPerTokenStored` at the moment the new (tiny) staker's baseline is recorded. When `harvestAll()` is subsequently called again while `totalSupply > 0`, `_queueNewRewardsWithoutTransfer` folds the entire `queuedRewards` balance into `rewardPerTokenStored`, dividing by the current (now small) `totalSupply`. The new staker's `earned()` (`userShare * (new rewardPerToken - old paid)/decimals`) then captures nearly the whole backlog, even though that backlog was actually generated by bribes accrued from other stakers' votes in the prior period.

No existing modifier (`onlyOperator`, `updateRewards`) prevents this because they correctly gate *who* can change balances, not *when* the reward-per-token conversion happens relative to `totalSupply` transitions. There is no time-weighted or checkpointed accounting to attribute queued rewards to the historical stakers who earned them.

### Impact Explanation
This is a theft-of-unclaimed-yield bug: an unprivileged actor who is only briefly and cheaply staked in `DelegateVoteRewardPool` at the moment `harvestAll()` next fires with `totalSupply > 0` can claim reward tokens that economically belong to previous, larger stakers whose votes generated the underlying bribes. This directly matches the "theft or permanent freezing of unclaimed yield" impact class.

### Likelihood Explanation
- No privileged role is required; `harvestAll()`, `vote()`, and `unvote()` are all public.
- The precondition (`totalSupply` transiently at 0) can occur naturally whenever all current voters temporarily unvote the delegated pool, or be engineered/observed by a watching attacker (front-running the last unvoter's transaction, or simply monitoring for low-participation windows).
- The attacker's capital requirement is only whatever small amount of locked vlMGP they need to route into the delegated pool — no flash loan or large capital needed since payoff is independent of stake size once they are the (near-)sole staker when the backlog is flushed.
- It is repeatable every time the pool's `totalSupply` returns to zero and refills, since `harvestAll()` can always be invoked by anyone to trigger the payout at will.

### Recommendation
Attribute queued rewards to time-weighted historical stakers rather than to whoever is staked at the next non-zero `totalSupply` harvest. Options: (1) checkpoint/snapshot `queuedRewards` against the `totalSupply` and staker set present when the queue was populated (e.g., don't allow `totalSupply` to go fully to zero, or hold queued rewards until the *same* stakers return), (2) disallow immediate reward-eligibility for stake entered after a queuing event until a cooldown/vesting period elapses, or (3) require `harvestAll` to only flush `queuedRewards` proportionally as new bribes accrue rather than dumping the whole backlog onto instantaneous `totalSupply`.

### Proof of Concept
Foundry test plan:
1. Deploy `DelegateVoteRewardPool` wired to a mock `WombatBribeManager` (mocking `claimAllBribes`) and a reward token.
2. Stake a large amount from `userA` via mocked `stakeFor`, simulate bribe accrual/harvest so `rewardPerTokenStored` increases normally.
3. Have `userA` fully `withdrawFor` (unvote), driving `totalSupply` to 0.
4. Call `harvestAll()` (mock `claimAllBribes` returns a large pending bribe amount) — assert `rewards[token].queuedRewards` now holds the full harvested amount and `rewardPerTokenStored` unchanged.
5. Have attacker `stakeFor` a small amount (e.g., 1 wei-equivalent) — assert `userRewardPerTokenPaid[attacker]` snapshot equals pre-flush `rewardPerTokenStored`.
6. Call `harvestAll()` again with a small/zero new bribe — assert `queuedRewards` is folded into `rewardPerTokenStored` divided by the tiny `totalSupply`.
7. Call `getReward(attacker)` — assert attacker receives (approximately) the entire backlog reward token amount despite having contributed negligible stake/duration, while `userA` (who generated the bribes) can no longer claim any share of it.

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }
