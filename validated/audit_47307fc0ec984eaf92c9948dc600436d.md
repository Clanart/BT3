### Title
Client-supplied `kc_user`/`kc_service` fields let any local daemon caller pivot to another principal's keychain scope without authorization - ([File: chia/daemon/keychain_server.py])

### Summary
`KeychainServer.get_keychain_for_request()` selects which `Keychain` instance (i.e., which private-key store partition) to operate on purely from the `kc_user`/`kc_service` fields embedded in the *request payload* sent by the caller, with no verification that the connecting client is actually authorized for that scope.

### Finding Description
Every keychain RPC (`add_private_key`, `get_all_private_keys`, `delete_key_by_fingerprint`, `delete_all_keys`, `get_key`, `set_label`, etc.) is dispatched through `KeychainServer.handle_command()` to helper methods that all call `self.get_keychain_for_request(request)`: [1](#0-0) 

This function reads `user`/`service` straight from the untrusted request dict (`request.get("kc_user", ...)`, `request.get("kc_service", ...)`) and uses that pair as a cache key to select or lazily create a `Keychain(user=user, service=service)` instance, then performs the requested privileged operation (read private keys/entropy, delete keys, add keys, set/delete labels) against whichever keychain that pair resolves to: [2](#0-1) [3](#0-2) [4](#0-3) 

The only gate in front of this is daemon-level mutual TLS using the private CA, which is a coarse local/admin trust boundary shared by every locally configured client (wallet UI, CLI, other services) — not a per-user/per-scope authorization check. This is structurally the same class of bug as CVE-2017-7505: the "scope" that is supposed to constrain what a caller can touch (Foreman's organization scope, here the `kc_user`/`kc_service` keychain partition) is taken from a value the caller controls rather than being derived from and checked against the caller's actual authenticated identity/permission set. Any process that can open a daemon websocket connection can supply an arbitrary `kc_user`/`kc_service` pair to reach into a different keychain partition's private keys/entropy, add or delete keys, or wipe all keys in that partition — including ones that were never intended to be that caller's scope — the same way a Foreman org-scoped admin could reach into another org's admin accounts by supplying different scope parameters instead of being restricted to their own.

`KeychainProxy` (the normal client path) sets `kc_user`/`kc_service` from its own configured `user`/`service` fields when formatting requests, but nothing on the server enforces that a given websocket connection may only ever use the `kc_user`/`kc_service` values it was configured with; the values are per-request, attacker/caller controlled data, and `get_keychain_for_request()` trusts them unconditionally: [5](#0-4) 

### Impact Explanation
A caller that can reach the local daemon socket (any locally configured service holding a valid daemon private-CA client cert, e.g., a compromised or malicious component of `wallet_ui`, a rogue plotter/service integration, or any local process abusing an existing client cert) can specify `kc_user`/`kc_service` values belonging to another keychain partition and: read private keys/entropy (`get_all_private_keys`, `get_first_private_key`, `get_key`), delete keys/labels (`delete_key_by_fingerprint`, `delete_all_keys`), or add keys into a partition it should not control. This directly threatens custody of wallet private keys and key derivation state outside the caller's own intended scope — key-material disclosure and destructive key management performed outside the caller's authorized scope, mirroring the Foreman "administrator user object outside of their scope" pattern.

### Likelihood Explanation
Exploitation requires the ability to establish (or hijack) a local daemon websocket connection with a valid client certificate — the same connection any legitimate local service uses. Given that connection, forging `kc_user`/`kc_service` in the JSON request body is trivial (no cryptographic binding between the connection identity and these fields). Likelihood is bounded by needing local daemon access, but once present, the pivot across keychain scopes is unauthenticated and unrestricted.

### Recommendation
Bind `kc_user`/`kc_service` to the authenticated identity of the daemon connection instead of trusting caller-supplied request fields; if multiple keychain partitions must be reachable over one daemon socket, enforce an explicit allow-list per connection/service registration rather than accepting arbitrary values in `get_keychain_for_request()`.

### Proof of Concept
1. Establish a normal local daemon websocket connection with a valid daemon client certificate (as any locally configured service would).
2. Send `get_all_private_keys` (or `delete_all_keys` / `add_private_key`) with a JSON payload containing `kc_user`/`kc_service` values matching a *different* principal's keychain partition than the one the caller is meant to operate on, e.g. as exercised by the `daemon_connection_and_temp_keychain` test fixture pattern: [6](#0-5) 
3. Observe the daemon returns private keys/entropy or performs mutation for that scope, without verifying the caller was ever entitled to `kc_user`/`kc_service`.

    def get_keychain_for_request(self, request: dict[str, Any]) -> Keychain:
        """
        Keychain instances can have user and service strings associated with them.
        The keychain backends ultimately point to the same data stores, but the user
        and service strings are used to partition those data stores. We attempt to
        maintain a mapping of user/service pairs to their corresponding Keychain.
        """
        user = request.get("kc_user", self._default_keychain.user)
        service = request.get("kc_service", self._default_keychain.service)
        if user == self._default_keychain.user and service == self._default_keychain.service:
            keychain = self._default_keychain
        else:
            key = (user or "unnamed") + (service or "")
            if key in self._alt_keychains:
                keychain = self._alt_keychains[key]
            else:
                keychain = Keychain(user=user, service=service)
                self._alt_keychains[key] = keychain
        return keychain
```

    async def add_key(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        mnemonic_or_pk = request.get("mnemonic_or_pk", None)
        label = request.get("label", None)
        private = request.get("private", True)

        if mnemonic_or_pk is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing key information"},
            }

        try:
            key = self.get_keychain_for_request(request).add_key(mnemonic_or_pk, label, private)
        except KeyError as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEYERROR,
                "error_details": {"message": f"The word '{e.args[0]}' is incorrect.'", "word": e.args[0]},
            }
        except ValueError as e:
            log.exception(e)
            return {
                "success": False,
                "error": str(e),
            }

        if isinstance(key, PrivateKey):
            fingerprint = key.get_g1().get_fingerprint()
        else:
            fingerprint = key.get_fingerprint()

        return {"success": True, "fingerprint": fingerprint}

    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}
```

        if data is None:
