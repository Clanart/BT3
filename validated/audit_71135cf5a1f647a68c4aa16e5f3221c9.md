## Title
Unauthenticated `InternalSendTx` on the aggregator's gRPC server allows any network peer to force broadcast of an arbitrary signed transaction with aggregator fee-payer funding - ([File: core/src/rpc/aggregator.rs])

## Summary
`ClementineAggregator::internal_send_tx` is gated only by `is_internal()`/`only_aggregator_and_self`, but that gate is entirely bypassed whenever `Interceptors::Noop` is installed, which happens whenever `config.client_verification=false`. [1](#0-0)  Since the documented, supported deployment for the aggregator explicitly disables client-certificate verification ("The aggregator does not enforce client certificates but does use TLS for encryption"), any unauthenticated TCP peer that can reach the aggregator's gRPC port can call `InternalSendTx`. [2](#0-1) 

## Finding Description
The broken binding is: **caller identity == self-cert holder (`our_cert` in `only_aggregator_and_self`)**, which the interceptor is supposed to enforce for any method whose gRPC-method name starts with `Internal`. [3](#0-2) [4](#0-3) 

`create_grpc_server` chooses between `OnlyAggregatorAndSelf` and `Noop` purely based on `config.client_verification`, with no special-casing for "Internal" prefixed methods: if `client_verification` is `false`, `Noop` is installed and `Interceptor::call` simply returns `Ok(req)` for every request, performing no certificate comparison at all. [1](#0-0) [5](#0-4) 

This is not merely a misconfiguration risk — the project's own documentation states that the aggregator is *intended* to run with client-certificate verification disabled, because its public (deposit-related) methods must be reachable by any depositor/user, while claiming that "internal methods can only be called by the entity's own client certificate" applies to "the verifier/operator" only, explicitly carving the aggregator out of that protection. [2](#0-1)  There is no secondary authentication check inside `internal_send_tx` itself.

`internal_send_tx` takes an attacker-controlled `SendTxRequest` containing a `raw_tx` (already fully-formed/signed `bitcoin::Transaction` bytes) and a `fee_type`, deserializes it, and unconditionally inserts it into the tx-sender queue for the aggregator's automation to broadcast/fee-bump: [6](#0-5) 

```
async fn internal_send_tx(...) {
    ...
    let signed_tx: bitcoin::Transaction = send_tx_req.raw_tx...try_into()?;
    ...
    self.tx_sender.insert_try_to_send(&mut dbtx, None, &signed_tx, fee_type.try_into()?, ...).await...
}
```

Once queued, the tx-sender's CPFP logic will spend the aggregator/operator's own fee-payer UTXOs to pay for confirming whatever transaction was submitted (attaching a P2A-anchor child transaction funded from `tx_sender_fee_payer_utxos`). [7](#0-6) [8](#0-7) 

Why this matters for bridge-controlled inputs specifically: the claim that this lets an attacker "misdirect a move-to-vault UTXO" or spend N-of-N protocol UTXOs does **not** hold, because `raw_tx` must already carry a *valid* signature to be relayed/mined by Bitcoin. An unprivileged attacker holds no verifier key share and cannot produce a valid N-of-N MuSig2 signature over a round/kickoff/reimbursement/move-to-vault transaction, so they cannot submit a validly-signed transaction that spends a protocol-controlled UTXO. `SECP.verify_schnorr` and the presigned transaction graph still require a genuine aggregated signature that the attacker cannot produce, so no bridge-controlled input can actually be double-spent, frozen, or misdirected through this path.

What the attacker *can* do is submit any transaction they can validly sign themselves (spending only their own UTXOs) and have the aggregator's `insert_try_to_send`/CPFP machinery repeatedly spend the aggregator's fee-payer wallet UTXOs to pay for broadcasting/confirming it — an unauthenticated, state-changing, fee-fund-draining call.

## Impact Explanation
This is an unauthenticated state-changing/broadcasting gRPC call reachable by anyone who can connect to the aggregator's public port, matching the "High" impact category ("an unauthenticated state-changing or broadcasting call"). It lets an attacker repeatedly cause the tx-sender to consume the aggregator's own fee-payer BTC to CPFP-bump arbitrary attacker-supplied transactions, draining operational Bitcoin funds used for fee payment. It does **not**, however, allow spending, freezing, or misdirecting bridge protocol UTXOs (move-to-vault, kickoff, reimbursement, etc.), because those require an N-of-N aggregated Schnorr signature the attacker cannot produce; the "Critical/move-to-vault-frozen" framing in the question is not substantiated by the code. This is repeatable per-call (bounded by rate limiting/grpc concurrency limits, which are out of scope per the rules) and applies to any aggregator instance run with `client_verification=false`, which is the documented supported configuration.

## Likelihood Explanation
Precondition `client_verification=false` matches the documented default aggregator deployment. [2](#0-1)  `internal_send_tx` additionally requires the binary to be compiled with `--features automation`, which is the documented production build. [9](#0-8)  Given both, the attack only requires TCP connectivity to the aggregator's gRPC port and a self-signed, self-funded transaction — no BTC cost beyond normal transaction fees the attacker pays for their own tx, and no privileged key material.

## Recommendation
Do not rely solely on `config.client_verification` to gate "Internal" methods on the aggregator. Enforce the self-cert check for any method whose name is prefixed `Internal` regardless of the `client_verification` setting (i.e., always require the caller to present the aggregator's own client certificate for internal RPCs, while still allowing `Noop`-style open access for genuinely public methods). This requires splitting the interceptor logic so `is_internal` checks are never skipped, even under `Noop`.

    // BEFORE: caller == our_cert (should be required for any "Internal*" method)

    async fn internal_send_tx(
        &self,
        request: Request<clementine::SendTxRequest>,
    ) -> Result<Response<Empty>, Status> {
        #[cfg(not(feature = "automation"))]
        {
            Err(Status::unimplemented("Automation is not enabled"))
        }
        #[cfg(feature = "automation")]
        {
            let send_tx_req = request.into_inner();
            let fee_type = send_tx_req.fee_type();
            let signed_tx: bitcoin::Transaction = send_tx_req
                .raw_tx
                .ok_or(Status::invalid_argument("Missing raw_tx"))?
                .try_into()?;
            tracing::warn!(
                "Internal send tx rpc called with feetype: {:?}, tx hex: {}",
                fee_type,
                bitcoin::consensus::encode::serialize_hex(&signed_tx)
            );

            let mut dbtx = self.db.begin_transaction().await?;
            self.tx_sender
                .insert_try_to_send(
                    &mut dbtx,
                    None,
                    &signed_tx,
                    fee_type.try_into()?,
                    None,
                    &[],
                    &[],
                    &[],
                    &[],
                )
                .await
                .map_to_status()?;
            dbtx.commit()
                .await
                .map_err(|e| Status::internal(format!("Failed to commit db transaction: {e}")))?;
            Ok(Response::new(Empty {}))
        }

    /// Creates a Child-Pays-For-Parent (CPFP) child transaction.
    ///
    /// This transaction spends:
    /// 1.  The designated "P2A anchor" output of the parent transaction (`p2a_anchor`).
    /// 2.  One or more confirmed "fee payer" UTXOs (`fee_payer_utxos`) controlled by the `signer`.
    ///
    /// It calculates the total fee required (`required_fee`) to make the combined parent + child
    /// package attractive to miners at the target `fee_rate`. The `required_fee` is paid entirely
    /// by this child transaction.
    ///
    /// The remaining value (total input value - `required_fee`) is sent to the `change_address`.
    ///
    /// # Signing
    /// We sign the input spending the P2A anchor and all fee payer UTXOs.
    ///
    /// # Returns
    /// The constructed and partially signed child transaction.
    async fn create_child_tx(
        &self,
        p2a_anchor: OutPoint,
        anchor_sat: Amount,
        fee_payer_utxos: Vec<crate::SpendableUtxo>,
        parent_tx_size: Weight,
        fee_rate: FeeRateKvb,
    ) -> Result<Transaction> {
        let required_fee = Self::calculate_required_fee(
            parent_tx_size,
            fee_payer_utxos.len(),
            fee_rate,
            FeePayingType::CPFP,
        )?;

        let change_address = self
            .rpc
            .get_new_wallet_address()
            .await
            .wrap_err("Failed to get new wallet address")?;

        let total_fee_payer_amount = fee_payer_utxos
            .iter()
            .map(|utxo| utxo.txout.value)
            .sum::<Amount>()
            + anchor_sat;

        if change_address.script_pubkey().minimal_non_dust() + required_fee > total_fee_payer_amount
        {
            return Err(SendTxError::InsufficientFeePayerAmount);
        }

        self.build_and_sign_child_tx(
            p2a_anchor,
            anchor_sat,
            fee_payer_utxos,
            change_address,
            required_fee,
        )
    }

    /// Sends a transaction using the Child-Pays-For-Parent (CPFP) strategy.
    ///
    /// # Logic:
    /// 1.  **Check Unconfirmed Fee Payers:** Ensures no unconfirmed fee payer UTXOs exist
    ///     for this `try_to_send_id`. If they do, skips this transaction for now
    ///     as they need to confirm before being spendable by the child.
    /// 2.  **Get Confirmed Fee Payers:** Retrieves the available confirmed fee payer UTXOs.
    /// 3.  **Create Package:** Calls `create_package` to build the `vec![parent_tx, child_tx]`.
    ///     The `child_tx` spends the parent's anchor output and the fee payer UTXOs, paying
    ///     a fee calculated for the whole package.
    /// 4.  **Test Mempool Accept (Not implemented right now as testmempoolaccept didn't support TRUC package submission #1011):**
    ///     Uses `testmempoolaccept` RPC to check if the package is likely to be accepted by the network before submitting.
    /// 5.  **Submit Package:** Uses the `submitpackage` RPC to atomically submit the parent
    ///     and child transactions. Bitcoin Core evaluates the fee rate of the package together.
    /// 6.  **Handle Results:** Checks the `submitpackage` result. If successful or already in
    ///     mempool, updates the effective fee rate in the database. If failed, returns an error.
    ///
    /// # Arguments
    /// * `try_to_send_id` - The database ID tracking this send attempt.
    /// * `tx` - The parent transaction requiring the fee bump.
    /// * `tx_metadata` - Optional metadata associated with the transaction.
    /// * `fee_rate` - The target fee rate for the CPFP package.
    /// * `current_tip_height` - The current height of the tip of the chain.
    #[tracing::instrument(skip_all, fields(try_to_send_id, tx_meta=?tx_metadata))]
    pub async fn send_cpfp_tx(
        &self,
        try_to_send_id: u32,
        tx: Transaction,
        tx_metadata: Option<TxMetadata>,
        fee_rate: FeeRateKvb,
        current_tip_height: u32,
    ) -> Result<()> {
        let unconfirmed = self
            .db
            .get_unconfirmed_fee_payer_txs(None, try_to_send_id)
            .await
            .map_err(|e: BridgeError| SendTxError::Other(e.into()))?;
        if !unconfirmed.is_empty() {
            // Log that we're waiting for unconfirmed UTXOs
            tracing::debug!(
                try_to_send_id,
                "Waiting for {} UTXOs to confirm",
                unconfirmed.len()
            );

            let _ = self
                .db
                .update_tx_debug_sending_state(
                    try_to_send_id,
                    "waiting_for_utxo_confirmation",
                    true,
                )
                .await;
            return Ok(());
        }
