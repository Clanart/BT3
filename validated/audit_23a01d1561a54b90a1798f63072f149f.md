### Title
Unauthenticated Module Binding on Privileged Governance Messages Enables Full IntentGatewayV2 Takeover - (File: evm/src/apps/intentsv2/ExtrinsicIntents.sol)

### Summary
`IntentGatewayV2`'s `onAccept` handler authenticates the sending module (`request.from`) only for the `RedeemEscrow`/`RefundEscrow` request kinds. For the privileged governance kinds — `NewDeployment`, `UpdateParams`, `SweepDust`, and `UpgradeContract` — it checks only that `request.source` equals the Hyperbridge state machine id, never that `request.from` matches a specific authorized governance module on that chain [1](#0-0) . This is the same broken invariant the external report describes for factory/beacon patterns: a "single blanket check" (here, "is this from Hyperbridge chain at all") is substituted for the finer-grained authorization ("is this from the *specific authorized sender*") that the sensitive action actually requires.

### Finding Description
`_authenticate` correctly binds both chain and module identity for asset-moving `RedeemEscrow`/`RefundEscrow` requests: [2](#0-1) 

But the governance branch of `onAccept` drops the module check entirely and only verifies the source chain id: [3](#0-2) 

`request.source` is a **chain** identifier set by the local ISMP host to reflect which state machine a message originated from — it says nothing about *which module/pallet on that chain* dispatched it (`request.from` is the field that carries the module identity, as correctly used in `_authenticate`). Once a request clears the `onlyHost` modifier (i.e., it was proof-verified as genuinely originating from the Hyperbridge state machine), `onAccept` treats *any* module on that chain as equally entitled to:
- register a new peer gateway address for any state machine (`NewDeployment` → `_addDeployment`, which is fully unauthenticated by contents) [4](#0-3) 
- change `host`, `dispatcher`, `priceOracle`, fee parameters (`UpdateParams` → `_updateParams`) [5](#0-4) 
- sweep all accumulated protocol dust to an arbitrary beneficiary (`SweepDust` → `_sweepDust`) [6](#0-5) 
- **upgrade the ERC-1967 proxy to an arbitrary implementation with arbitrary init calldata** (`UpgradeContract`) [7](#0-6) 

This mirrors the report's core defect: dynamically-authorized entities (here, any current or future ISMP module registered/routable on the Hyperbridge chain) are treated as implicitly trusted for a privileged action, instead of that trust being scoped to one specific, explicitly-designated governance sender. The design intends only the intents-coprocessor governance pallet to send these messages, but the contract has no on-chain assertion of that — it is an unenforced assumption, exactly the "operationally complex and error-prone" configuration gap the report calls out for factory-managed allow-lists.

### Impact Explanation
`UpgradeContract` accepted from any module on the Hyperbridge chain is a complete contract takeover: an attacker-controlled implementation can drain every token escrowed by `IntentGatewayV2` across all chains, forge fills, or rewrite any state. `NewDeployment` lets an attacker register their own address as the "trusted peer gateway" for a chosen state machine — once installed, `_authenticate` (used for `RedeemEscrow`/`RefundEscrow`) will trust messages claiming to come from that forged peer, letting the attacker release escrowed input tokens to themselves without ever filling the corresponding order. `SweepDust` directly steals accumulated protocol fees. This satisfies the bounty's impact gate: unauthorized execution, false state acceptance (a forged peer gateway becomes "trusted state"), and outright fund theft — reachable through a wrong module binding rather than any relayer/admin compromise.

### Likelihood Explanation
Exploitation requires only that *some* ISMP module reachable on the Hyperbridge chain can be induced to dispatch a POST request whose destination `to`/body match `IntentGatewayV2`'s address and one of the four unguarded `RequestKind` values. Given Hyperbridge is a shared coprocessor hosting many pallets/apps (bandwidth market, token gateway, future third-party ISMP apps), and the contract itself provides no assertion narrowing "any Hyperbridge module" down to "the one specific intents-governance module," the security of the whole gateway rests entirely on operational assumptions outside the contract rather than on-chain enforcement — a fragile trust boundary that is straightforward to violate as the ecosystem of Hyperbridge-side modules grows.

### Recommendation
Store an explicit, admin-set `governanceModule` (module id / pallet address on Hyperbridge) in `Params`, and require `request.from` to match it for `NewDeployment`, `UpdateParams`, `SweepDust`, and `UpgradeContract`, exactly as `_authenticate` already does for the escrow-release paths:
```solidity
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
if (address(bytes20(incoming.request.from)) != _params.governanceModule) revert Unauthorized();
```
This closes the gap without weakening any other check, and mirrors the RBAC-style fix ("scope trust to the specific authorized sender, not the whole chain") recommended in the external report.

### Proof of Concept
1. `IntentGatewayV2` is deployed with `_params.host` set to the local `EvmHost`, whose `hyperbridge()` returns the Nexus/Hyperbridge state machine id.
2. Any pallet/module on the Hyperbridge chain (not the intents-coprocessor governance pallet) dispatches an ISMP POST request with `dest` = the EVM chain hosting `IntentGatewayV2`, `to` = the gateway's address, and `body = bytes.concat(bytes1(uint8(RequestKind.UpgradeContract)), abi.encode(attackerImpl, initCalldata))`.
3. A relayer submits proof of this genuinely-committed request (it *is* real, valid Hyperbridge-chain state — no consensus/state-proof forgery is needed).
4. `EvmHost` verifies the proof correctly (chain-of-custody is legitimate) and calls `IntentGatewayV2.onAccept`.
5. `onAccept` checks only `keccak256(incoming.request.source) == keccak256(hyperbridge)` — true — and executes `ERC1967Utils.upgradeToAndCall(attackerImpl, initCalldata)`, handing full control of the gateway (and all escrowed funds) to the attacker's implementation. [3](#0-2)

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            _authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return _withdraw(body, kind == RequestKind.RefundEscrow, true);
        }

        // only hyperbridge is permitted to perform these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            _addDeployment(abi.decode(incoming.request.body[1:], (Deployment)));
        } else if (kind == RequestKind.UpdateParams) {
            _updateParams(abi.decode(incoming.request.body[1:], (ParamsUpdate)));
        } else if (kind == RequestKind.SweepDust) {
            _sweepDust(abi.decode(incoming.request.body[1:], (SweepDust)));
        } else if (kind == RequestKind.UpgradeContract) {
            (address newImpl, bytes memory initData) = abi.decode(incoming.request.body[1:], (address, bytes));
            ERC1967Utils.upgradeToAndCall(newImpl, initData);
        }
    }

    function _sweepDust(SweepDust memory req) internal {
        uint256 outputsLen = req.outputs.length;
        for (uint256 i; i < outputsLen;) {
            TokenInfo memory info = req.outputs[i];
            address token = address(uint160(uint256(info.token)));
            uint256 amount = info.amount;

            if (token == address(0)) {
                (bool sent,) = req.beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransfer(req.beneficiary, amount);
            }
            unchecked {
                ++i;
            }
            emit DustSwept(token, amount, req.beneficiary);
        }
    }
