### Title
Tokenfactory `MsgSetDenomMetadata` lets any denom admin set an arbitrary `Name`/`Symbol` to impersonate an existing token, deceiving EVM/pointer consumers that trust these non-unique strings - ([File: x/tokenfactory/keeper/msg_server.go])

### Summary
The tokenfactory module lets the admin of any `factory/{creator}/{subdenom}` denom freely set the human-readable `Name` and `Symbol` fields of that denom's bank `Metadata` via `MsgSetDenomMetadata`, with no check that these strings are unique or tied to the denom's actual identity. Any downstream consumer that identifies/labels a token by its `Name`/`Symbol` string rather than its unique denom/address — notably the EVM `AddNativePointer` precompile, which mints an ERC20 pointer contract whose `name()`/`symbol()` come directly from this metadata — can be made to display an attacker-controlled denom as if it were a well-known token (e.g. "SEI", "USDC"). This mirrors the reported bug class: relying on a non-unique string instead of a fixed, whitelisted identifier to establish token authenticity.

### Finding Description
`MsgSetDenomMetadata` only requires the sender to be the tokenfactory admin of the denom named in `Metadata.Base`, and only validates that the `Metadata` struct is internally consistent (non-blank name/symbol, base/display present in denom units, exponents sorted, etc.) — it does not check that `Name`/`Symbol` are unique across the chain or match the actual subdenom: [1](#0-0) 

This is confirmed by the module's own test suite, where a tokenfactory-created denom (`suite.defaultDenom`, an ordinary `factory/{creator}/{subdenom}` denom) is successfully given `Name: "SEI"`, `Symbol: "SEI"` — identical to the chain's real native token display metadata — with the test asserting success: [2](#0-1) 

The `Metadata.Validate()` function invoked before persisting only checks that Name/Symbol are non-blank and that base/display denoms are well-formed and present among `DenomUnits` — it never cross-checks Name/Symbol against other denoms' metadata: [3](#0-2) 

Once this spoofed metadata is stored via `bankKeeper.SetDenomMetaData`, any EVM caller can invoke the `pointer` precompile's `addNativePointer` method for that denom. The precompile pulls `Name`/`Symbol` straight out of `GetDenomMetaData` and uses them, unmodified, as the constructor arguments for the deployed ERC20 pointer contract: [4](#0-3) 

The resulting ERC20 contract's `name()`/`symbol()` will therefore return the spoofed strings (e.g. "SEI"/"SEI" or "USDC"/"USDC") even though its underlying bank denom is an entirely different, attacker-controlled `factory/{attacker}/{subdenom}` token. Wallets, DEX front-ends, and any tooling that identifies "the SEI/USDC token" by symbol/name (rather than by the canonical denom string or contract address) can be tricked into treating this pointer contract as the genuine asset.

### Impact Explanation
This directly enables the phishing/impersonation pattern described in the external report: a malicious tokenfactory admin can create a worthless denom, mint an unlimited supply of it (since they control admin/mint rights on their own denom), set its display `Name`/`Symbol` to match a trusted asset, register an EVM pointer contract for it, and get it listed/displayed by any client that trusts `Name`/`Symbol` strings. Victims transacting against the fake pointer, or being shown its balance/price by wallets/DEXes assuming it's the real asset, can be deceived into accepting worthless tokens or approving unwanted allowances — a fund-loss vector via unauthorized/fraudulent token transfer through the pointer/EVM surface, reachable by any unprivileged tokenfactory denom creator using a normal transaction.

### Likelihood Explanation
The attack requires no privileged access: any account can call `tokenfactory CreateDenom` and then `SetDenomMetadata` on their own denom (they are automatically its admin), and any EVM account can then call the public `addNativePointer` precompile method on that denom. All the necessary steps are ordinary, permissionless transactions available to any user, matching the required "unprivileged sender / precompile caller" trust boundary.

### Recommendation
- Enforce that a tokenfactory denom's `Name`/`Symbol` metadata cannot collide with the `Name`/`Symbol` of any other existing denom's metadata (or reserve well-known strings like "SEI", "USDC", "USDT" from ever being settable by non-governance-approved denoms).
- Have the EVM `AddNativePointer`/`UpsertERCNativePointer` flow and any client-facing tooling identify/display tokens primarily by the canonical denom string or contract address, not by the mutable `Name`/`Symbol` metadata fields, or at minimum surface the underlying denom prominently alongside the symbol so users can distinguish `factory/{attacker}/...` tokens from the genuine `usei`/IBC assets.

### Proof of Concept
1. Attacker calls `MsgCreateDenom` to create `factory/{attacker}/fake`.
2. Attacker calls `MsgSetDenomMetadata` with `Base: factory/{attacker}/fake`, `Display: factory/{attacker}/fake`, but `Name: "USD Coin"`, `Symbol: "USDC"` — this passes `Metadata.Validate()` and the admin check in `SetDenomMetadata` (as demonstrated by the analogous "SEI" test case in `admins_test.go`). [1](#0-0) 
3. Attacker mints an arbitrary amount of `factory/{attacker}/fake` to themselves via `MsgMint` (they are the denom admin).
4. Attacker (or anyone) calls the EVM `pointer` precompile's `addNativePointer("factory/{attacker}/fake")`, which reads the spoofed `Name`/`Symbol` from bank metadata and deploys an ERC20 contract reporting `name() == "USD Coin"`, `symbol() == "USDC"`. [4](#0-3) 
5. Wallets/DEXes/users interacting with this ERC20 pointer contract by symbol/name see "USDC" and may treat it as the genuine stablecoin, enabling scams/fund loss.

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
}

func (m Metadata) Validate() error {
	if strings.TrimSpace(m.Name) == "" {
		return errors.New("name field cannot be blank")
	}

	if strings.TrimSpace(m.Symbol) == "" {
		return errors.New("symbol field cannot be blank")
	}

	if err := sdk.ValidateDenom(m.Base); err != nil {
		return fmt.Errorf("invalid metadata base denom: %w", err)
	}

	if err := sdk.ValidateDenom(m.Display); err != nil {
		return fmt.Errorf("invalid metadata display denom: %w", err)
	}

	var (
		hasDisplay      bool
		currentExponent uint32 // check that the exponents are increasing
	)

	seenUnits := make(map[string]bool)

	for i, denomUnit := range m.DenomUnits {
		// The first denomination unit MUST be the base
		if i == 0 {
			// validate denomination and exponent
			if denomUnit.Denom != m.Base {
				return fmt.Errorf("metadata's first denomination unit must be the one with base denom '%s'", m.Base)
			}
			if denomUnit.Exponent != 0 {
				return fmt.Errorf("the exponent for base denomination unit %s must be 0", m.Base)
			}
		} else if currentExponent >= denomUnit.Exponent {
			return errors.New("denom units should be sorted asc by exponent")
		}

		currentExponent = denomUnit.Exponent

		if seenUnits[denomUnit.Denom] {
			return fmt.Errorf("duplicate denomination unit %s", denomUnit.Denom)
		}

		if denomUnit.Denom == m.Display {
			hasDisplay = true
		}

		if err := denomUnit.Validate(); err != nil {
			return err
		}

		seenUnits[denomUnit.Denom] = true
	}

	if !hasDisplay {
		return fmt.Errorf("metadata must contain a denomination unit with display denom '%s'", m.Display)
	}

	return nil
}
