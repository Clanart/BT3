### Title
Unbounded `io.ReadAll` of RPC request body before content-type/size validation in NewRelic/Datadog HTTP handlers enables memory-exhaustion DoS - (File: `networks/rpc/http_newrelic.go`, `networks/rpc/http_datadog.go`)

### Summary
When a Kaia node enables the optional NewRelic or Datadog APM integrations (via `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or `DD_TRACE_ENABLED` environment variables), every public JSON-RPC HTTP request is first routed through `getRPCRequests(r)`, which reads the *entire* request body into memory with `io.ReadAll` before the normal content-type and content-length validation (`validateRequest`) is ever reached. This mirrors the Synapse GHSA-rfq8-j7rh-8hf2 bug class: request bodies are buffered in full regardless of declared/actual content type or size, before any rejection logic runs, allowing an unprivileged public RPC caller to force large memory allocations per request.

### Finding Description
The normal, size-bounded JSON-RPC HTTP path validates the request before touching the body: `validateRequest` rejects requests whose `Content-Length` exceeds `common.MaxRequestContentLength` or whose content-type is not one of the accepted JSON-RPC types, and only afterwards does `newHTTPServerConn` wrap the body in `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))`. [1](#0-0) [2](#0-1) 

However, when APM instrumentation is enabled, `NewHTTPServer` wraps the entire handler chain (which contains `validateRequest`) *inside* `newNewRelicHTTPHandler`/`newDatadogHTTPHandler`, which run first for every incoming request: [3](#0-2) 

Both wrapper handlers unconditionally call `getRPCRequests(r)` before invoking the inner `handler.ServeHTTP` (where `validateRequest` finally executes): [4](#0-3) [5](#0-4) 

`getRPCRequests` reads the whole body with `io.ReadAll(r.Body)` with no size cap and without checking `Content-Length` or `Content-Type` first: [6](#0-5) 

Because `http.Server` (constructed by `NewHTTPServer`) does not wrap `r.Body` with `http.MaxBytesReader`, and the size/type checks in `validateRequest` are only invoked later inside the wrapped `handler.ServeHTTP`, a caller can send an oversized body of any content type (including unsupported ones such as `multipart/form-data`, or simply omit/falsify `Content-Length`) and have it fully buffered in memory by `io.ReadAll` before it is ever rejected.

### Impact Explanation
This allows any unauthenticated public-RPC caller reaching a Kaia node with NewRelic or Datadog tracing enabled to send requests whose bodies are unconditionally fully read into memory, bypassing the intended `MaxRequestContentLength` gate and content-type allowlist that protect the standard path. Repeated or concurrent large requests can drive memory exhaustion / denial of service on the RPC node, degrading availability for all legitimate transaction senders, gasless users, and public RPC callers depending on that node.

### Likelihood Explanation
Exploitation requires no special privileges — any public RPC caller can trigger it — but is conditioned on the node operator having enabled the optional NewRelic (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`) or Datadog (`DD_TRACE_ENABLED`) integrations, which are commonly used in production monitoring setups (e.g., by RPC service providers such as KAS, referenced directly in this code via `parseKASHeader`/KAS attributes). Where enabled, the attack is trivial to perform with a single crafted HTTP request repeated at scale.

### Recommendation
Enforce `Content-Length`/content-type validation (or wrap `r.Body` with `http.MaxBytesReader(w, r.Body, common.MaxRequestContentLength)`) before `getRPCRequests` reads the body in `newNewRelicHTTPHandler` and `newDatadogHTTPHandler`, or move the tracing wrappers to run *after* `validateRequest` in the handler chain so oversized/invalid-content-type requests are rejected prior to any full-body read.

### Proof of Concept
1. Run a Kaia node with `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` (or `DD_TRACE_ENABLED=true`) set so `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` wrap the RPC HTTP server.
2. Send a POST request to the public RPC HTTP endpoint with a body far larger than `common.MaxRequestContentLength` (or with `Transfer-Encoding: chunked` and no/incorrect `Content-Length`), with any content type.
3. Observe that `getRPCRequests` → `io.ReadAll(r.Body)` buffers the entire body into memory before `validateRequest` in `ServeHTTP` gets a chance to reject it based on `ContentLength` or content-type — unlike the non-instrumented path where `validateRequest` and `io.LimitReader` bound memory use up front.
4. Repeating this concurrently causes elevated memory consumption on the node, analogous to the Synapse multipart/form-data memory-exhaustion issue.

// validateRequest returns a non-zero response code and error message if the
// request is invalid.
func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}
	// Allow OPTIONS (regardless of content-type)
	if r.Method == http.MethodOptions {
		return 0, nil
	}
	// Check content-type
	if mt, _, err := mime.ParseMediaType(r.Header.Get("content-type")); err == nil {
		if slices.Contains(acceptedContentTypes, mt) {
			return 0, nil
		}
	}
	// Invalid content-type
	err := fmt.Errorf("invalid content type, only %s is supported", contentType)
	return http.StatusUnsupportedMediaType, err
}

func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
