## Finding

Since Agave is Solana's Rust validator client, the closest structural analog to `ProxyLOB`'s "reserved fee not decremented when returned" bug is the SIMD-0123 delegator block-reward mechanism, where `pending_delegator_rewards` on a `VoteStateV4` account functions as a reserve/liability that is read to compute payouts but is never observed to be reduced once those payouts are made.

### Title
Vote account `pending_delegator_rewards` liability is never decremented after block-reward distribution, permanently overstating the escrowed reserve and enabling repeated draw-down without corresponding capitalization accounting - ([File: runtime/src/bank/partitioned_epoch_rewards/calculation.rs])

### Summary
`calculate_block_reward` reads `vote_state.pending_delegator_rewards()` from the vote account every rewarded epoch and uses it as the numerator/cap for the per-stake-account block reward payout, capping the result at `pending_delegator_rewards` itself [1](#0-0) . `add_pending_delegator_rewards` is the only mutator of this field found across `programs/vote/src/vote_state/mod.rs`, `programs/vote/src/vote_processor.rs`, and `programs/vote/src/vote_state/handler.rs`; it only ever increments the value when a delegator deposits via `DepositDelegatorRewards` [2](#0-1) [3](#0-2) . No corresponding "subtract" or "clear" operation on `pending_delegator_rewards` was found in the distribution path (`distribution.rs`), which only tallies `block_reward_lamports_distributed`/`block_reward_lamports_burned` for the epoch-rewards sysvar bookkeeping and capitalization deltas, but never writes back a reduced `pending_delegator_rewards` to the vote account itself [4](#0-3) [5](#0-4) .

### Finding Description
`pending_delegator_rewards` is the exact analog of `lobReservesByTokenId` in the report: it is a value tracked on-chain that represents lamports "reserved" for a specific future obligation (paying delegators their share of a block-revenue deposit). Just as `_claimOrder` computed the payout using `executedShares`/`price` without subtracting the returned/unclaimed portion from the reserve, `calculate_block_reward` computes and pays a proportional share of `pending_delegator_rewards` to each stake account every rewarded epoch, but the corresponding decrement of `pending_delegator_rewards` on the vote account is not present anywhere in the code paths I was able to inspect (`add_pending_delegator_rewards` is additive-only, and `withdraw()` explicitly treats `pending_delegator_rewards` as an untouched floor that must remain locked in the account [6](#0-5) ).

The existing guard in `withdraw()` prevents the *withdrawer* from pulling funds below the `pending_delegator_rewards` floor, and closing the account is blocked while `pending_delegator_rewards > 0` [7](#0-6) . That guard protects against the withdraw authority draining the reserve, but it does nothing to stop the reserve value itself from being paid out epoch after epoch through `calculate_block_reward`/`build_updated_stake_reward` without ever being reduced. If the field is never cleared after a distribution, the same nominal "pending" amount can be used as the basis for the block-reward calculation in every subsequent rewarded epoch, and the value is never zeroed to reflect funds that have already left the vote account's economic reserve.

### Impact Explanation
This breaks the invariant that `pending_delegator_rewards` (a reserve) should shrink by exactly the amount that flows out through payouts, mirroring the report's "inflated reserve calculation" concern. Practical consequences if the decrement is indeed absent:
- The vote account's tracked liability (`pending_delegator_rewards`) never converges to zero even though real lamports are being paid out to delegators each epoch, so `withdraw()`'s SIMD-0123 floor check permanently over-reserves funds that have already been distributed, locking legitimate vote-account balance indefinitely.
- Because `build_updated_stake_reward` credits `block_reward` lamports directly onto stake accounts [8](#0-7)  while capitalization accounting in `distribute_epoch_rewards_in_partition` only adds/subtracts `stake_reward_lamports_minted`/`block_reward_lamports_burned` [9](#0-8) , if the source-side debit against the vote account (and therefore against `pending_delegator_rewards`) is missing, `block_reward_lamports_distributed` lamports are effectively minted onto stake accounts without a corresponding capitalization increase or vote-account debit — an accounting break of exactly the "protocol insolvency" class flagged in the report.

### Likelihood Explanation
This path executes automatically and non-maliciously every rewarded epoch for any validator that has used `DepositDelegatorRewards` and has active Alpenglow/SIMD-0123 block-revenue sharing enabled — no attacker action, privileged access, or malicious peer assumption is required, satisfying the "unprivileged... runtime/accounts" criteria. The severity depends entirely on whether a decrement step exists elsewhere that my searches did not surface.

### Recommendation
Confirm (via full-repository access) whether `pending_delegator_rewards` is decremented anywhere outside the files searched (e.g., inside `store_stake_accounts_in_partition`, `distribute_epoch_rewards_in_partition`, or a vote-account-side mutation applied via `store_accounts`/`store_commission_accounts_partitioned`). If no such decrement exists, add logic to subtract `block_reward_lamports_distributed` (and any burned portion) from the vote account's `pending_delegator_rewards` field at the same time the stake accounts are credited, analogous to the report's fix of removing the unclaimed/returned amount from the tracked reserve.

### Proof of Concept
I could not construct a runnable PoC from the indexed slices alone; a concrete PoC would require running a local validator (or `runtime/src/bank/partitioned_epoch_rewards` test harness) to: (1) call `DepositDelegatorRewards` to set `pending_delegator_rewards = D`; (2) advance through two full rewarded epochs with Alpenglow block-revenue sharing active; (3) assert whether `pending_delegator_rewards` on the vote account decreases by the `block_reward` amount paid out in epoch 1, and whether the same nominal `D` is reused as the basis for epoch 2's `calculate_block_reward` computation.

**Caveat:** Due to the size limits on the indexed codebase, I was not able to exhaustively confirm the absence of a decrement/debit step across the entire `runtime/src/bank` and `programs/vote` trees — only that no such call appeared in the specific files and line ranges returned by search. I recommend starting a full Devin session with complete repository access to verify definitively whether `pending_delegator_rewards` (and the vote account's lamport balance) is actually reduced when block rewards are distributed, before treating this as a confirmed vulnerability rather than a strong candidate.

pub fn deposit_delegator_rewards<S: std::hash::BuildHasher>(
    invoke_context: &mut InvokeContext,
    vote_account_index: IndexOfAccount,
    sender_account_index: IndexOfAccount,
    deposit: u64,
    signers: &HashSet<Pubkey, S>,
) -> Result<(), InstructionError> {
    let transaction_context = &invoke_context.transaction_context;
    let instruction_context = transaction_context.get_current_instruction_context()?;

    let vote_address = *instruction_context.get_key_of_instruction_account(vote_account_index)?;
    let source_address =
        *instruction_context.get_key_of_instruction_account(sender_account_index)?;

    // Source account must sign the transfer.
    verify_authorized_signer(&source_address, signers)?;

    // SIMD-0123 states we must validate the vote account deserializes to a v4
    // *before* attempting CPI, then update the `pending_delegator_rewards`
    // field *last*.
    // We can deserialize it, and hold onto the deserialized payload in-memory.
    // This way, we can drop the account borrow but avoid re-deserializing
    // later, since we know only lamports will change.
    let mut vote_state = {
        let vote_account =
            instruction_context.try_borrow_instruction_account(vote_account_index)?;

        // Can't use `get_vote_state_handler_checked`, since it will convert
        // the underlying vote state to v4.
        // SIMD-0123 requires an *initialized v4*.
        let versioned = VoteStateVersions::deserialize(vote_account.get_data())?;
        if let VoteStateVersions::V4(vote_state_v4) = versioned {
            Ok(VoteStateHandler::new_v4(*vote_state_v4))
        } else {
            Err(InstructionError::InvalidAccountData)
        }
    }?;

    // CPI to System: Transfer from sender to vote account.
    invoke_context.native_invoke_signed(
        system_instruction::transfer(&source_address, &vote_address, deposit),
        &[],
    )?;

    // Update `pending_delegator_rewards`.
    let transaction_context = &invoke_context.transaction_context;
    let instruction_context = transaction_context.get_current_instruction_context()?;
    let mut vote_account =
        instruction_context.try_borrow_instruction_account(vote_account_index)?;

    vote_state.add_pending_delegator_rewards(deposit)?;
    vote_state.set_vote_account_state(&mut vote_account)
}

    fn distribute_epoch_rewards_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) {
        let pre_capitalization = self.capitalization();
        let (
            DistributionResults {
                stake_reward_lamports_minted,
                stake_reward_lamports_burned,
                block_reward_lamports_distributed,
                block_reward_lamports_burned,
                updated_stake_rewards,
            },
            store_stake_accounts_us,
        ) = measure_us!(self.store_stake_accounts_in_partition(partition_rewards, partition_index));

        // increase total capitalization by the distributed rewards
        self.capitalization
            .fetch_add(stake_reward_lamports_minted, Relaxed);

        // decrease total capitalization by burned block rewards
        self.capitalization
            .fetch_sub(block_reward_lamports_burned, Relaxed);

        // decrease distributed capital from epoch rewards sysvar
        self.update_epoch_rewards_sysvar(
            stake_reward_lamports_minted + stake_reward_lamports_burned,
            block_reward_lamports_distributed + block_reward_lamports_burned,
        );

        // update reward history for this partitioned distribution
        self.update_reward_history_in_partition(&updated_stake_rewards);

        let metrics = RewardsStoreMetrics {
            pre_capitalization,
            post_capitalization: self.capitalization(),
            total_stake_accounts_count: partition_rewards.all_stake_rewards.num_rewards(),
            total_num_partitions: partition_rewards.partition_indices.len(),
            partition_index,
            store_stake_accounts_us,
            store_stake_accounts_count: updated_stake_rewards.len(),
            distributed_rewards: stake_reward_lamports_minted,
            burned_rewards: stake_reward_lamports_burned,
            distributed_block_rewards: block_reward_lamports_distributed,
            burned_block_rewards: block_reward_lamports_burned,
        };

    }

    fn build_updated_stake_reward(
        distribution_epoch: u64,
        stake_history: &StakeHistory,
        new_warmup_cooldown_rate_epoch: Option<Epoch>,
        stakes_cache_accounts: &imbl::HashMap<Pubkey, StakeAccount<Delegation>>,
        partitioned_stake_reward: &PartitionedStakeReward,
        rent: &Rent,
        adjust_delegations_for_rent: bool,
        use_fixed_point_stake_math: bool,
    ) -> Result<StakeReward, DistributionError> {
        let stake_account = stakes_cache_accounts
            .get(&partitioned_stake_reward.stake_pubkey)
            .ok_or(DistributionError::AccountNotFound)?
            .clone();

        let (mut account, stake_state): (AccountSharedData, StakeStateV2) = stake_account.into();
        let StakeStateV2::Stake(meta, stake, flags) = stake_state else {
            // StakesCache only stores accounts where StakeStateV2::delegation().is_some()
            unreachable!(
                "StakesCache entry {:?} failed StakeStateV2 deserialization",
                partitioned_stake_reward.stake_pubkey
            )
        };
        account
            .checked_add_lamports(partitioned_stake_reward.inflation.stake_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;
        account
            .checked_add_lamports(partitioned_stake_reward.block_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;

        let mut new_stake = partitioned_stake_reward.inflation.stake;
        if adjust_delegations_for_rent {
            let minimum_balance = rent.minimum_balance(account.data().len());
            // The rewarded epoch is right before the distribution epoch
            let rewarded_epoch = distribution_epoch.saturating_sub(1);
            // The entry in `partitioned_stake_reward` contains the rewards,
            // calculated during the calculation phase
            let delegation_with_rewards = new_stake.delegation.stake;
            adjust_delegation_for_rent(
                &mut new_stake.delegation,
                rewarded_epoch,
                delegation_with_rewards,
                account.lamports(),
                minimum_balance,
            );
        } else {
            let expected_delegation = stake
                .delegation
                .stake
                .saturating_add(partitioned_stake_reward.inflation.stake_reward);
            assert_eq!(
                expected_delegation, new_stake.delegation.stake,
                "stake reward delegation must be consistent with the updated stake account \
                 lamport balance"
            );
        }
        account
            .set_state(&StakeStateV2::Stake(meta, new_stake, flags))
            .map_err(|_| DistributionError::UnableToSetState)?;

        let stake_at_distribution_epoch = delegation_effective_stake(
            &new_stake.delegation,
            distribution_epoch,
            stake_history,
            new_warmup_cooldown_rate_epoch,
            use_fixed_point_stake_math,
        );
        let reward_type = if stake_at_distribution_epoch == 0 {
            RewardType::DeactivatedStake
        } else {
            RewardType::Staking
        };
        Ok(StakeReward {
            stake_pubkey: partitioned_stake_reward.stake_pubkey,
            stake_reward_info: StakeRewardInfo {
                reward_type,
                lamports: i64::try_from(
                    partitioned_stake_reward.inflation.stake_reward
                        + partitioned_stake_reward.block_reward,
                )
                .unwrap(),
                post_balance: account.lamports(),
                commission_bps: partitioned_stake_reward.inflation.commission_bps,
            },
            stake_account: account,
        })
    }
