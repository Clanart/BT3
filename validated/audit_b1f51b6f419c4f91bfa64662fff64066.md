## Analysis Result

### Title
Unauthenticated SSRF via attacker-controlled DataLayer mirror URLs consumed by automatic HTTP fetch - (File: `chia/data_layer/data_layer.py`)

### Summary
Any party can create a tiny on-chain "mirror" coin for **any** DataLayer store whose `launcher_id` they know (launcher IDs are public), embedding arbitrary attacker-controlled URL strings in the coin's memos. Every DataLayer node that tracks that store treats those URLs as legitimate mirror servers and periodically issues unauthenticated outbound HTTP requests to them — with no scheme, host, or destination validation — mirroring the "Octo-STS" bug class (unauthenticated attacker fields driving internal network requests).

### Finding Description
A mirror coin is created by spending any coin to the mirror puzzle hash and putting `[launcher_id, url1, url2, ...]` in `CREATE_COIN` memos: [1](#0-0) 

`DataLayerWallet.coin_added` observes any such coin, decodes the memos, and — critically — only checks that the `launcher_id` is *tracked*, not that the caller owns or controls that store, before persisting the mirror URLs: [2](#0-1) 

`DataLayer.update_subscriptions_from_wallet` pulls these wallet-observed mirror URLs (`dl_get_mirrors`) and feeds them straight into the local subscription table with only trailing-slash trimming — no scheme allow-list, no host validation: [3](#0-2) 

`fetch_and_validate()` then periodically selects one of these attacker-supplied URLs and triggers a delta-file download from it: [4](#0-3) 

The actual outbound request is an unauthenticated `aiohttp` GET to `server_info.url + "/" + filename` (or a POST of `{"url": ..., ...}` to any configured downloader plugin), with no restriction preventing internal/loopback/link-local addresses: [5](#0-4) [6](#0-5) 

Failures and exceptions from these requests are logged, including the attacker-controlled URL and exception text, which can leak details about internal service responses (banners, error pages, headers reflected in exceptions): [7](#0-6) 

Per project documentation, the module explicitly does not restrict mirror/plugin URLs beyond what is described above — they are treated only as "external trust inputs" for the *data content* returned, not for the destination reachability itself:


### Impact Explanation
Any unprivileged wallet/spend-bundle submitter who knows a public DataLayer `launcher_id` (trivially discoverable on-chain or via offers) can force every node tracking that store to make repeated, unauthenticated outbound HTTP GET/POST requests to attacker-chosen destinations (e.g., cloud metadata endpoints, internal admin panels, other services on the operator's LAN, or a listener the attacker controls to fingerprint the victim's network). This is a server-side request forgery from a spend-bundle-reachable code path, consistent with CWE-918, and can leak internal network topology/service responses through logs and error propagation without requiring any node compromise or special privileges — only a small amount of XCH to spend and knowledge of a store's launcher id.

### Likelihood Explanation
High likelihood for any operator running a Data Layer node that tracks/subscribes to third-party stores (a normal, encouraged usage pattern for shared/public datasets). The attack requires only a standard spend (creating a mirror coin, potentially with `amount=0`) and public knowledge of the target `launcher_id`; no ownership of the store, no privileged RPC access, and no cooperation from the store owner is needed.

### Recommendation
- In `DataLayerWallet.coin_added` / `DataStore.update_subscriptions_from_wallet`, validate/sanitize mirror URLs before they become subscription servers: enforce an allow-listed scheme (`https://` only), reject `localhost`/loopback/link-local/private RFC1918 addresses and non-standard ports unless explicitly configured, and cap URL length.
- Perform DNS resolution and IP-range checks (and re-check on redirect) immediately before each outbound request in `http_download()`/`download_file()`, rejecting requests that resolve to internal address space.
- Avoid logging full attacker-controlled URLs/exception bodies at `info`/`warning` level without redaction, mirroring the "redact logging" remediation from the referenced advisory.
- Consider requiring explicit user opt-in (config flag) before automatically fetching from mirror URLs learned purely from on-chain memos rather than user-supplied `dl subscribe --url`.

### Proof of Concept
1. Attacker learns the public `launcher_id` of a DataLayer store that a victim's `data_layer` service tracks (e.g., because the victim publicly subscribes to/offers that store).
2. Attacker calls `create_new_mirror`/`dl_new_mirror` (or crafts an equivalent spend bundle) sending a coin to `create_mirror_puzzle()`'s puzzle hash with memos `[launcher_id, b"http://169.254.169.254/latest/meta-data/", b"http://<attacker-server>/"]`: [8](#0-7) 
3. Once the spend confirms, the victim's `DataLayerWallet.coin_added` records the mirror (no ownership check), and `dl_get_mirrors`/`update_subscriptions_from_wallet` surfaces the URLs into the victim's local subscription table.
4. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects the attacker's URL and issues an outbound `aiohttp` request to it via `http_download()`, causing the victim node to contact the internal/attacker-chosen endpoint and log the outcome — completing the SSRF.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
