## Analysis: TOCTOU in Gasless Module Enables Theft of Proposer-Funded Lend Amount

The Sonne Finance root cause was a **stale-state assumption**: code paths were executed later (governance execution) based on conditions (collateral factor safety) validated at an earlier point, and an attacker inserted a state change (VELO market activation) between validation and execution to drain funds atomically. The reachable analog in Kaia is in `kaiax/gasless`, where a similar time-of-check/time-of-use gap exists between when a `GaslessSwapTx`'s on-chain viability (exchange rate, allowance, balance) is validated and when the block proposer's `LendTx` unconditionally transfers KAIA to the user.

### Root Cause

The gasless flow works as: proposer prepends a `LendTx` (plain unconditional value transfer, [1](#0-0) ) before the user's `GaslessApproveTx`/`GaslessSwapTx`, expecting the user to "repay" the lent KAIA inside `swapForGas` via the token swap. [2](#0-1) 

The dynamic, state-dependent viability checks (exchange rate via `GetAmountIn`, token `Allowance`, token `Balance`) are only performed once, at tx-pool admission time, via `checkBalanceForSwap`: [3](#0-2) 

But once accepted into the pool, the swap transaction can remain pending for up to `PendingTimeout`/`QueueTimeout` (10 seconds) before actual block inclusion: [4](#0-3) [5](#0-4) 

Crucially, the re-validation performed right before block building (`IsReady`/`isSwapTxReady` → `IsExecutable`/`VerifyExecutable`) only checks **static, declared** values (`amountRepay` formula, nonce sequencing) — it does **not** re-run `checkBalanceForSwap`'s on-chain state checks (exchange rate, allowance, balance): [6](#0-5) [7](#0-6) 

The `LendTx` and `GaslessSwapTx` are **two independent top-level transactions** placed sequentially in the block bundle (not an atomic all-or-nothing unit at the EVM level) — `IncorporateBundleTx`/`incorporate` simply splices ordinary transactions into the tx list: [8](#0-7) 

If, between admission-time validation and actual block inclusion, the swap router's exchange rate/state changes (via the attacker's own subsequent transactions, other users' swaps, or any state-changing call reachable by an unprivileged sender) such that the on-chain `swapForGas` call reverts, the preceding `LendTx` — an unconditional plain value transfer — still succeeds and delivers KAIA to the user's address. The user keeps the lent KAIA with no repayment, since repayment logic lives entirely inside the reverted `swapForGas` call. This directly parallels Sonne: a value-releasing step (`LendTx`) executes on the assumption that a later step (`swapForGas`) will always enforce the invariant, but an unprivileged actor can invalidate that invariant in the intervening window.

### Assessment

This is a plausible High-severity finding reachable purely by an unprivileged gasless-transaction sender (a whitelisted-token holder submitting an approve+swap pair), fitting the allowed "gasless" module scope and the "fee-delegation abuse / gasless settlement theft" impact category.

However, I could **not fully verify** two things within available tool calls:
1. Whether the `GaslessSwapRouter` contract's `swapForGas` (Solidity, KIP-247 reference implementation) itself enforces a check that would prevent partial execution (e.g., pulling tokens from the sender before computing the exchange, or having its own slippage protections that make this window unexploitable in practice).
2. Whether there is an additional re-validation step at actual block-assembly/mining time (in `work/` worker code) that re-invokes `checkBalanceForSwap` right before including the bundle, which I did not have iterations left to inspect (e.g., `work/worker.go` or `blockchain/txpool` promotion logic beyond what's shown).

Given this residual uncertainty about whether a second, closer-to-execution-time check exists, I present this as a candidate finding rather than a fully certain one.

### Title
Stale exchange-rate/allowance validation allows theft of proposer-funded `LendTx` KAIA in gasless swap settlement - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module validates a `GaslessSwapTx`'s on-chain viability (required `amountIn` per current exchange rate, `Allowance`, `Balance`) only once, at tx-pool admission, in `checkBalanceForSwap`. The block proposer's `LendTx` — an unconditional KAIA transfer funding the user's gas — is generated and included as an independent transaction ahead of the swap, without re-checking these dynamic conditions at inclusion time. Because the swap can sit in the pool for seconds before inclusion, and the on-chain swap execution is not atomically tied to the `LendTx`, an unprivileged user/attacker can cause the actual `swapForGas` call to revert (by manipulating the swap router's exchange-rate state, allowance, or balance through their own or a colluding transaction) after the lending transaction has already unconditionally paid out KAIA.

### Finding Description
- `checkBalanceForSwap` performs one-time dynamic checks (`GetAmountIn`, `Allowance`, `BalanceOf`, deadline) against current chain state when the tx enters the pool: [3](#0-2) 
- Re-validation performed later, right before block inclusion (`isSwapTxReady`/`IsExecutable`/`VerifyExecutable`), checks only static/declared relationships, not current on-chain state: [6](#0-5) 
- `GetLendTxGenerator` builds an unconditional value-transfer transaction whose amount is purely a function of the transactions' declared gas fees, with no dependency on the swap's eventual success: [1](#0-0) 
- The bundle mechanism places `LendTx`, `ApproveTx`, `SwapTx` as ordinary sequential transactions, not as one atomic EVM call: [8](#0-7) 
- Pending/queue timeouts of 10 seconds create a real window for state to change between check and execution: [4](#0-3) 

### Impact Explanation
If a `swapForGas` call reverts after the preceding `LendTx` has executed, the block proposer's KAIA is transferred to the user with no repayment — direct fee-delegation/gasless-settlement theft from the block proposer, reachable by any unprivileged holder of a whitelisted gasless token.

### Likelihood Explanation
Likelihood depends on factors not fully confirmed (see caveats above): whether the `GaslessSwapRouter` contract itself is resistant to rate manipulation within the block, and whether a stricter re-check exists closer to block assembly. Assuming no such secondary check, exploitation only requires ordinary transactions from an unprivileged account and does not require any privileged role, making it plausible under normal network conditions (e.g., variable mempool latency, MEV/auction competition, or self-timed manipulation of the swap router's reserve/rate).

### Recommendation
Re-run `checkBalanceForSwap`'s dynamic on-chain checks (exchange rate, allowance, balance) at the moment the bundle is actually incorporated into the block (in `ExtractTxBundles`/`GetBidTxGenerator`/`GetLendTxGenerator`), not only at tx-pool admission. Alternatively, make the `LendTx` payout conditionally dependent on the swap's success (e.g., via router-mediated escrow) so that a reverted `swapForGas` cannot leave an already-paid-out `LendTx` unrecovered.

### Proof of Concept
Conceptual sequence (not verified end-to-end due to inability to inspect the `GaslessSwapRouter` Solidity contract's full guarantees or the worker's block-assembly re-validation path):
1. Attacker (or colluding account) submits `ApproveTx` + `SwapTx` for `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)`; `checkBalanceForSwap` passes against current router exchange rate.
2. Before the bundle is selected for inclusion (within the pending/queue window), attacker submits another transaction that shifts the router's exchange rate/reserves (or otherwise causes `swapForGas`'s on-chain slippage/allowance/balance check to fail) without invalidating the previously-computed static `VerifyExecutable` checks.
3. Proposer includes `[LendTx, ApproveTx, SwapTx]`: `LendTx` unconditionally pays out KAIA to the attacker; `SwapTx`/`swapForGas` reverts due to the manipulated state, so no repayment occurs.
4. Attacker retains the lent KAIA without repaying, at the block proposer's expense.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err

		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())

// isSwapTxReady assumes that the caller checked `g.IsSwapTx(swapTx)`
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// IncorporateBundleTx incorporates bundle transactions into the transaction list.
// Caller must ensure that there is no conflict between bundles.
func IncorporateBundleTx(txs []*types.Transaction, bundles []*Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, len(txs))
	for i, tx := range txs {
		ret[i] = NewTxOrGenFromTx(tx)
	}

	for _, bundle := range bundles {
		var err error
		ret, err = incorporate(ret, bundle)
		if err != nil {
			return nil, err
		}
	}
	return ret, nil
}

// incorporate assumes that `txs` does not contain any bundle transactions.
func incorporate(txs []*TxOrGen, bundle *Bundle) ([]*TxOrGen, error) {
	ret := make([]*TxOrGen, 0, len(txs)+len(bundle.BundleTxs))
	targetFound := false

	// 1. place bundle at the beginning
	if bundle.TargetTxHash == (common.Hash{}) {
		ret = append(ret, bundle.BundleTxs...)
		targetFound = true
	}

	// 2. place bundle after TargetTxHash
	for _, txOrGen := range txs {
		// if tx-in-bundle, the tx will be appended when target is found.
		if bundle.Has(txOrGen) {
			continue
		}
		ret = append(ret, txOrGen)
		if txOrGen.Id == bundle.TargetTxHash {
			targetFound = true
			ret = append(ret, bundle.BundleTxs...)
		}
	}

	if !targetFound {
		return nil, ErrFailedToIncorporateBundle
	}

	return ret, nil
}
