### Title
`WombatStaking.depositLP` mints receipt tokens based on nominal amount instead of actual transferred balance, unlike `deposit()` - ([File: wombat/WombatStaking.sol])

### Summary
`WombatStaking.depositLP` (called by any user through `WombatPoolHelper.depositLP`/`WombatPoolHelperV2.depositLP`/`AnkrBNBPoolHelper.depositLP`) transfers `_lpAmount` of `poolInfo.lpAddress` from the caller and then unconditionally mints `_lpAmount` of `receiptToken` and stakes `_lpAmount` into MasterWombat, without ever checking how much was actually received via `safeTransferFrom`. [1](#0-0)  This is the exact bug class described in the report: assuming a token transfer moves precisely the declared amount, rather than measuring the actual balance delta.

### Finding Description
The sibling function `deposit()` correctly guards against this by measuring the LP balance before and after the pool deposit call and minting/staking only the actual `lpReceived` delta: [2](#0-1) 

`depositLP`, however, skips this pattern entirely:
```solidity
IERC20(poolInfo.lpAddress).safeTransferFrom(_for, address(this), _lpAmount);
_toMasterWomAndSendReward(_lpAddress, _lpAmount, true);
IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount);
``` [3](#0-2) 

If `poolInfo.lpAddress` is any token whose `transferFrom` does not deliver exactly the declared amount to the recipient (fee-on-transfer, deflationary, or rebasing tokens — the same class as stETH in the referenced report), the contract will mint `receiptToken` and later attempt to stake to `masterWombat` for an amount larger than what it actually custodies. `receiptToken` is the internal accounting unit that other pool participants rely on 1:1 against the LP tokens actually held/staked by `WombatStaking` (used later in `withdraw()`/`burnReceiptToken()`), so an amount mismatch here breaks the solvency invariant between minted receipt tokens and actual backing LP tokens.

This is directly reachable by an ordinary wallet: any user can call the public `depositLP` entrypoint on any of the deployed pool helpers (`WombatPoolHelper.depositLP`, `WombatPoolHelperV2.depositLP`, `AnkrBNBPoolHelper.depositLP`), which forwards straight into `WombatStaking.depositLP` with no privileged role required. [4](#0-3) 

### Impact Explanation
If a pool's `lpAddress` token is not a strict 1:1 transferring token, `depositLP` over-mints `receiptToken`/staked-share accounting relative to actual custodied LP. Since `receiptToken` supply represents a claim against the pooled LP balance that other pool helpers' users share (via MasterMagpie staking and later `WombatStaking.withdraw`/`burnReceiptToken`), this mismatch causes protocol insolvency for the pool: subsequent legitimate withdrawers may be unable to redeem their proportional share because the actual LP custody balance is insufficient, permanently freezing funds for other users of the same pool.

### Likelihood Explanation
The bug is deterministic — it does not depend on any race condition or privileged actor — it triggers on every `depositLP` call for any pool whose underlying LP token has non-exact transfer semantics. It only requires the (owner-only) registration of a pool whose LP token exhibits such behavior; the actual exploitation trigger, `depositLP`, is called by unprivileged users as part of normal protocol usage.

### Recommendation
Apply the same balance-difference pattern used in `deposit()` to `depositLP`: capture `poolInfo.lpAddress` balance before/after the `safeTransferFrom`, and use the resulting delta (not the nominal `_lpAmount`) for `_toMasterWomAndSendReward` and for the `IMintableERC20(poolInfo.receiptToken).mint(...)` call.

### Proof of Concept
1. Owner registers a pool via `registerPool` whose `_lpAddress` is a fee-on-transfer or rebasing token (any token where `balanceOf(recipient)` after `transferFrom(amount)` is less than `before + amount`). [5](#0-4) 
2. An ordinary user calls `WombatPoolHelper.depositLP(_lpAmount)`, which calls `WombatStaking.depositLP(lpToken, _lpAmount, msg.sender)`. [4](#0-3) 
3. `WombatStaking.depositLP` transfers `_lpAmount` nominally but receives less due to the token's transfer semantics, yet mints exactly `_lpAmount` of `receiptToken` and attempts to stake `_lpAmount` to MasterWombat. [6](#0-5) 
4. Over time, `receiptToken` supply outpaces actual LP custodied by the contract, so later callers of `withdraw()` cannot be fully repaid, freezing funds for the last withdrawers of the pool. [7](#0-6)
