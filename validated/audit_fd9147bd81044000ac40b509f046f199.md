### Title
Identity (zero) verification shares accepted when deserializing `ThresholdKeys`, producing a null group key - (File: crypto/dkg/src/lib.rs)

### Summary
The external report's bug class — a missing zero-value check when registering a security-critical entity — maps onto Serai's `ThresholdKeys::read` / `ThresholdKeys::new`. `Ciphersuite::read_G` (`crypto/ciphersuite/src/lib.rs:91`) enforces canonicality and torsion-freedom but explicitly does not reject the identity point; the identity-rejecting variant `Curve::read_G` (`crypto/frost/src/curve/mod.rs:125`) exists but is not used here. `ThresholdKeys::read` deserializes all `n` verification shares via `C::read_G` (`crypto/dkg/src/lib.rs:620-623`), and `ThresholdKeys::new` checks only the count and the participant-index range (`crypto/dkg/src/lib.rs:355-365`), never checking that any verification share — or the resulting `group_key` computed at `crypto/dkg/src/lib.rs:376-378` — is non-identity. `ThresholdKeys::read` is invoked on stored/committed key material in `processor/src/key_gen.rs`.

### Finding Description
A serialized `ThresholdKeys` blob whose verification shares are all the identity point passes every check in `ThresholdKeys::read`/`ThresholdKeys::new`:

- `verification_shares.len() == n` and all `Participant` keys are `1..=n` (valid indexes).
- `Interpolation::Constant`/`Lagrange` constraints are satisfiable.
- `group_key = Σ verification_shares[i] * interpolation_factor(i)` is a weighted sum of identity points = identity.

The result is a structurally valid `ThresholdKeys` whose `group_key()` is the identity — the exact analog of a registered `address(0)` guardian: a security-critical group element equal to the group's "zero" was accepted without validation.

### Impact Explanation
An identity group key is a public key with known discrete logarithm zero. Any Schnorr/FROST verification `s·G == R + c·P` with `P = identity` reduces to `s·G == R`, which any party satisfies by picking arbitrary `s` and setting `R = s·G`. Any signature requirement, key confirmation, or chain-recorded `KeyPair`/group key derived from these shares is therefore forgeable by anyone — an unintended signature can be produced without any secret share, and any funds/policy gated on the group key are unprotected. This is a forged-signature / null-key analog, not a liveness issue.

### Likelihood Explanation
Reachability requires attacker-influenced bytes reaching `ThresholdKeys::read` — e.g., key material committed/agreed via the coordinator key-gen flow rather than produced locally by `dkg_dealer::key_gen` or `pedpop` (which generate real shares). Because honest DKG paths never emit identity shares, exploitation needs a flow where serialized `ThresholdKeys` are accepted from an untrusted source or a corrupted transcript of verification shares is deserialized. That path exists in `processor/src/key_gen.rs`, but whether it is reachable purely from unauthenticated public input depends on upstream validation not visible in the indexed code; severity is Medium conditional on that reachability. Within the crypto crates themselves, the missing check is unconditional and unambiguous.

### Recommendation
Reject identity verification shares at the deserialization and construction boundary, mirroring the zero-address check:

- In `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:355`), add `if bool::from(share.is_identity()) { Err(DkgError::...) }` over `verification_shares.values()`, and reject `group_key.is_identity()` after computing it.
- Alternatively/additionally, use an identity-rejecting point reader in `ThresholdKeys::read` (`crypto/dkg/src/lib.rs:622`), as `Curve::read_G` already does for FROST commitments.

```rust
// for a t-of-n group (e.g., t = 2, n = 3, Ristretto).
let mut serialized = vec![];
serialized.extend(u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes());
serialized.extend(Ristretto::ID);
serialized.extend(2u16.to_le_bytes());          // t
serialized.extend(3u16.to_le_bytes());          // n
serialized.extend(1u16.to_le_bytes());          // i = Participant(1)
serialized.push(1);                             // Interpolation::Lagrange
serialized.extend(Scalar::ONE.to_repr().as_ref()); // arbitrary secret_share
for _ in 0 .. 3 {
  serialized.extend(EdwardsPoint::identity().to_bytes()); // identity shares
}
let keys = ThresholdKeys::<Ristretto>::read(&mut serialized.as_slice()).unwrap();
assert!(bool::from(keys.group_key().is_identity())); // null group key accepted
// Any (R = s*G, s) pair now "verifies" as a signature under keys.group_key().
```
