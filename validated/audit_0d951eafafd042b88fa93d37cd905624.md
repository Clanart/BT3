## Title
Missing `--` end-of-options guard allows branch-name argument injection in `getBranchMergeBaseDiff` - (File: `app/src/lib/git/diff.ts`)

## Summary
`getBranchMergeBaseDiff` builds a `git diff --merge-base` argv where the two ref parameters (`baseBranchName`, `comparisonBranchName`) are inserted as bare, unguarded positional arguments before any `--` end-of-options marker is present in the argv. Git's option parser scans the whole argument vector (except tokens after a literal `--`) for anything starting with `-`, so a ref name beginning with `-`/`--` is interpreted as a flag rather than a revision.

## Finding Description
The function constructs its argv like this: [1](#0-0) 

`baseBranchName` and `comparisonBranchName` sit directly after `--merge-base`, with no preceding `--`. The only `--` in the array appears much later, right before `ensureRelativePath(file.path)` — it protects the *file path*, not the two ref arguments. Compare this with the safer pattern used two functions later in the same file, `getBranchMergeBaseChangedFiles`, which places the refs the same way (also unguarded) but at least the file path is protected the same way.

Both `baseBranchName` and `comparisonBranchName` ultimately originate from branch names that can be attacker-influenced (e.g., a branch fetched from a remote/PR, or a comparison target selected from repository refs). Git ref-name validation (`git check-ref-format`) does not forbid a ref component from beginning with `-`; branches such as `--output=/some/path` or `--anchored=...` can be created via `git branch -- --evil-name` and pushed/fetched like any normal branch. Because git's argument parser for `git diff` scans the whole argv for option-looking tokens regardless of position (it does not stop parsing options at the first positional token), a branch name like `--output=<path>` supplied as `baseBranchName` or `comparisonBranchName` would be interpreted as the `--output=<path>` option to `git diff`, redirecting the diff output to an arbitrary file path instead of being read from stdout.

## Impact Explanation
If an attacker can get a branch with a `-`-prefixed name into a repository the victim opens in GitHub Desktop (e.g., a fetched PR branch, or a branch created via a crafted clone/fetch), and the victim triggers a merge-base diff view against/with that branch, the resulting `git diff --merge-base <injected-flag> <other-ref> ... -- <file>` invocation can have git options injected. Notably `--output=<path>` allows writing the diff content to an arbitrary file on disk (a file write outside the intended scope), and other diff options (e.g., ones referencing external diff/textconv drivers if not otherwise disabled) could potentially be abused for more impact. This matches "file write ... outside the repo" in the valid-impact criteria.

## Likelihood Explanation
Exploitation requires the attacker to control a branch name that reaches this function as `baseBranchName`/`comparisonBranchName` and for the victim to perform a branch-comparison diff action in Desktop against that ref (e.g. via PR review / compare flows) — this is a plausible, no-privilege, one-click-ish flow (open a repo/PR, view diff), consistent with the "unprivileged repository content" attacker model in the review scope.

## Recommendation
Insert a `--` immediately after the two ref arguments (or before them, ahead of any user-controlled ref) to mark the end of git options, e.g.:
```ts
const args = [
  'diff',
  '--merge-base',
  '--',
  baseBranchName,
  comparisonBranchName,
  ...
]
```
Note: git's `--` only ends *option* parsing, not necessarily disambiguating revision vs. pathspec position for `--merge-base A B -- file`; the fix should ensure refs are never scanned as options — either by validating/rejecting ref names that begin with `-`, or by using `git rev-parse --verify` to resolve refs to SHAs before interpolating them into the diff argv (the more robust general fix, consistent with how other tools mitigate this class of git argument injection).

export async function getBranchMergeBaseDiff(
  repository: Repository,
  file: FileChange,
  baseBranchName: string,
  comparisonBranchName: string,
  hideWhitespaceInDiff: boolean = false,
  latestCommit: string
): Promise<IDiff> {
  const args = [
    'diff',
    '--merge-base',
    baseBranchName,
    comparisonBranchName,
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '--patch-with-raw',
    '-z',
    '--no-color',
    '--',
    ensureRelativePath(file.path),
  ]

  if (
    file.status.kind === AppFileStatusKind.Renamed ||
    file.status.kind === AppFileStatusKind.Copied
  ) {
    args.push(ensureRelativePath(file.status.oldPath))
  }

  const result = await git(args, repository.path, 'getBranchMergeBaseDiff', {
    encoding: 'buffer',
  })

  return buildDiff(result.stdout, repository, file, latestCommit, latestCommit)
}
