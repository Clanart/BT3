### Title
Unconfirmed automatic branch checkout via `x-github-client://openRepo` deep link bypasses uncommitted-changes safety checks - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop registers custom protocol handlers (`x-github-client`, `x-github-desktop-auth`, and the legacy `github-mac`/`github-windows`) that are parsed by `parseAppURL()` into an `open-repository-from-url` action carrying attacker-controlled `url`, `branch`, `pr`, and `filepath` fields taken directly from the query string. [1](#0-0)  When such a link is opened (e.g., a user clicking a malicious `x-github-client://openrepo/...` link), `Dispatcher.openRepositoryFromUrl` routes to `openBranchNameFromUrl`, which resolves the (possibly already-tracked) repository, fetches it, and immediately checks out the attacker-supplied `branchName` with no user prompt and no re-validation against the caller/context. [2](#0-1) 

### Finding Description
This is structurally analogous to the `reconcile()` bug class: a state-mutating operation (`GasAccounting.reconcile()` there, an automatic git checkout here) is driven entirely by caller-supplied parameters instead of being gated by an independently-verified context/phase check. In the Solidity report, `reconcile()` trusted `environment`/`solverFrom` values supplied by the caller rather than deriving them from the actual lock state, letting reconcile fire from unintended call sites. In Desktop, `openBranchNameFromUrl` trusts the `branch` string taken straight from an untrusted deep-link query parameter and drives a privileged, working-directory-mutating action (`_fetch` + `checkoutLocalBranch`) without going through the normal interactive checkout gate.

Contrast this with the interactive checkout path, `_checkoutBranch`, which explicitly checks for uncommitted changes and protected branches and, depending on `UncommittedChangesStrategy`, shows a `ConfirmOverwriteStash` or `StashAndSwitchBranch` popup before proceeding. [3](#0-2)  The deep-link-driven `checkoutLocalBranch` call in `openBranchNameFromUrl` bypasses this confirmation entirely, matching the "flags can be set / actions can happen in unintended call sites" pattern in the original report, where `reconcile()` could be invoked from phases (`PreOps`, `UserOp`, `AllocateValue`, `PostOps`) where it was never supposed to run.

The only validation applied to the deep link's `branch` parameter is a character-class check (`testForInvalidChars`) meant to reject invalid git ref characters — it does not verify that switching branches unprompted, from an attacker-controlled trigger, is a safe or expected action in the current application state. [4](#0-3) 

The matching of `url` to an existing tracked repository is done purely by comparing the origin/upstream `htmlURL`/`cloneURL` strings (`doesRepositoryMatchUrl` / `urlsMatch`), which is attacker-suppliable since the attacker crafts the `url` value in the link itself. [5](#0-4) [6](#0-5) 

### Impact Explanation
If a victim has a matching repository already tracked in Desktop, clicking a crafted link silently: (1) fetches from the remote, and (2) checks out a branch chosen entirely by the attacker — with no popup, no stash confirmation, and no check for uncommitted local changes that the normal UI checkout flow enforces. This can silently discard or hide the user's uncommitted local changes when the current branch differs from the target (the interactive `_checkoutBranch` path this bypasses is precisely the code that protects against that loss). It also means the user's working directory ends up on a branch they did not knowingly choose, which is the definition of "silent corruption of what the user commits or pushes" referenced in the qualifying impact criteria.

### Likelihood Explanation
The attacker only needs the victim to click one link (`x-github-client://openrepo/<url>?branch=<name>`), which is the exact "link or deep link the user clicks" attacker model called out in scope. No local access, malware, or leaked credentials are required — only that the victim has GitHub Desktop installed (protocol handler registered at app start via `setAsDefaultProtocolClient`) and has previously cloned the targeted repository, both very ordinary developer conditions. [7](#0-6) 

### Recommendation
Route deep-link-triggered branch checkouts through the same interactive, confirmation-gated `_checkoutBranch` logic (uncommitted-changes/stash prompts, protected-branch checks) instead of the more direct `checkoutLocalBranch` used by `openBranchNameFromUrl`, or at minimum surface an explicit user confirmation dialog before fetching/checking out a branch requested via an external protocol trigger. Note: I was unable to locate and fully inspect the body of `checkoutLocalBranch` itself in the indexed codebase (only its call sites were found), so I cannot confirm from code alone whether it internally re-applies any of the `_checkoutBranch` safety checks — a Devin session with full repository access should verify this before treating the impact as final.

### Proof of Concept
1. Attacker hosts a link: `x-github-client://openrepo/https%3A%2F%2Fgithub.com%2Fvictim-org%2Fvictim-repo?branch=malicious-branch`.
2. Victim, who already has `victim-org/victim-repo` cloned and tracked in Desktop, clicks the link (e.g., from an email, chat message, or compromised web page).
3. The OS invokes Desktop's registered protocol handler, which calls `handleAppURL` → `parseAppURL` → produces `{ name: 'open-repository-from-url', url, branch: 'malicious-branch', pr: null, filepath: null }`. [8](#0-7) 
4. `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl(url, 'malicious-branch')` executes `openOrCloneRepository`, `_refreshRepository`, `_fetch`, then `checkoutLocalBranch(repository, 'malicious-branch')` with zero user confirmation. [9](#0-8) [10](#0-9) 
5. The victim's working directory is now silently switched to `malicious-branch` without the stash/uncommitted-changes confirmation that the equivalent in-app checkout button would have shown.

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}
