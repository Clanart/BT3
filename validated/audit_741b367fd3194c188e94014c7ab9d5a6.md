### Title
Unescaped `Any.type_url` Injected Raw into ProtoJSON Output — JSON Structure Injection in Pure-PHP `Message::serializeToJsonStream` - ([File: php/src/Google/Protobuf/Internal/Message.php])

### Summary
The CXF advisory's failed invariant is: an attacker-controlled string (`realm`) is concatenated directly into a structured text protocol (an HTTP header) without neutralizing CR/LF, letting the attacker break out of the intended field and inject new structure (extra headers / a second response). The pure-PHP protobuf implementation has the same class of defect: when serializing a `google.protobuf.Any` message to ProtoJSON, `Message::serializeToJsonStream()` writes the `type_url` string field **raw**, with no JSON string escaping, directly between two literal `"` bytes: [1](#0-0) 

Every other string-valued field in the same file goes through `GPBJsonWire::serializeFieldToStream`, which for `GPBType::STRING` calls `json_encode($value, JSON_UNESCAPED_UNICODE)` before writing, i.e. it does perform proper escaping: [2](#0-1) 

The `Any` special-case in `serializeToJsonStream` bypasses that escaping path entirely and calls `$output->writeRaw($this->getTypeUrl(), strlen($this->getTypeUrl()))` directly.

### Finding Description
`type_url` is an ordinary `string` field (field #1) of `google.protobuf.Any`: [3](#0-2) 

It is fully attacker-controlled: any client can construct a binary-encoded `Any` submessage (or a message containing an `Any` field) with an arbitrary UTF-8 byte sequence for `type_url` — including `"`, `\`, `,`, newlines, or other JSON-structural characters — and send it through any of the public parse APIs (`mergeFromString`, `mergeFrom`, `Message::__construct` via wire decode). No length, charset, or content validation is performed on `type_url` during binary parsing; the field is stored verbatim in `$this->type_url` and returned by `getTypeUrl()`.

When the application later re-serializes that message to ProtoJSON (`serializeToJsonString()` / `serializeToJsonStream()`), the `Any` case:

```php
$output->writeRaw("\"@type\":", 8);
$output->writeRaw("\"", 1);
$output->writeRaw($this->getTypeUrl(), strlen($this->getTypeUrl()));
$output->writeRaw("\"", 1);
```

writes the raw bytes of `type_url` between the two quote characters with **no escaping of `"`, `\`, control characters, or Unicode line separators**. This is the direct analog of the CXF flaw: the WWW-Authenticate/`realm` concatenation problem is "attacker string embedded unescaped into structured text, allowing structural injection"; here the JSON string boundary/structure is the analogous "protocol" being violated, and `"` inside `type_url` breaks the intended `"@type":"..."` string, letting the attacker terminate the string early and inject arbitrary additional JSON keys/values (or malformed/ambiguous JSON) into the rest of the object, exactly as CRLF in `realm` lets an attacker terminate the header line and inject additional headers/response content.

Every other JSON-serialization code path in this same codebase (C++ `json/internal/writer.cc` `MustEscape`, upb `jsonenc_put_escaped_char` in C, Ruby, PHP-C-extension (`php-upb.c`), Java `JsonFormat.printStringEscapedAndQuoted`, C# `JsonFormatter.WriteString`, and even the pure-PHP `GPBJsonWire::escapedJson`/`jsonNiceEscape`) properly escapes `"`, `\`, and control characters before writing string field values into JSON output — confirming the invariant that *is* expected: every attacker-controlled string field must pass through an escaping routine before being embedded in the output. The pure-PHP `Any` type_url path is the one place found that violates this invariant. [4](#0-3) [5](#0-4) 

### Impact Explanation
Impact is confidentiality/integrity of the *output structure*, matching the CVSS vector for the CXF issue (`C:L/I:L`, no availability impact): a consuming application that treats `serializeToJsonString()` output as trusted, well-formed JSON (e.g., for logging, forwarding to another service, or embedding into a larger JSON/JS document) can have its output corrupted or manipulated by an attacker who controls only the `type_url` of an `Any` field inside an otherwise-valid protobuf message. Depending on how the downstream consumer parses/uses that JSON, this can enable JSON key/value injection (overwriting or adding fields the application did not intend to emit) or, if embedded in an HTML/JS context, script/markup injection via unescaped `<`, `>`, or other characters that are otherwise stripped by every other escaping path in this codebase (`<`,`>` are XSS-hardened in the Java/C#/C++/upb JSON writers but not here).

### Likelihood Explanation
High likelihood of reachability: `type_url` requires no special crafting beyond putting a `"` or control character in a UTF-8 string field of a bounded, otherwise well-formed `Any` submessage, then calling the standard public `serializeToJsonString()`/`ToJson` PHP API on a message containing that `Any`. No privileged access, malicious plugin, or schema tampering is required — only a normal client-controlled binary payload parsed through the supported public API, consistent with the assumption stated in the rules (attacker sends bounded binary protobuf through a supported public parse API; schemas/generated code trusted).

### Recommendation
In `php/src/Google/Protobuf/Internal/Message.php`, route the `type_url` write in the `Any` branch of `serializeToJsonStream()` through the same JSON string-escaping routine used for every other string field (i.e., `GPBJsonWire::escapedJson()` / `json_encode()`), rather than `writeRaw()`ing the field verbatim. Concretely, replace:
```php
$output->writeRaw($this->getTypeUrl(), strlen($this->getTypeUrl()));
```
with logic equivalent to what `GPBJsonWire::serializeFieldToStream` does for `GPBType::STRING` (`json_encode($value, JSON_UNESCAPED_UNICODE)` then write only the escaped payload between the quotes, or reuse `GPBJsonWire::escapedJson()`).

### Proof of Concept
1. Build a message `M` containing a `google.protobuf.Any` field `a`.
2. Set the wire bytes for `a.type_url` (field 1, wire type 2 for `string`) to a value containing a double quote and injected JSON, e.g. `type.googleapis.com/x","injected":"1` — this is a perfectly valid protobuf `string` field value (any byte sequence is legal at the wire level; no `"`-exclusion is enforced during binary decode).
3. Set `a.value` to the binary encoding of any registered/known type (or leave it minimal) so `unpack()`/decode succeeds.
4. Call `$M->serializeToJsonString()` on the pure-PHP implementation.
5. Expected (correct) output would escape the quote as `\"`; actual output (per the code at `Message.php:1493`) will emit the raw bytes, producing:
   ```json
   {"a":{"@type":"type.googleapis.com/x","injected":"1", ...}}
   ```
   i.e., a spurious `"injected":"1"` key/value pair injected into the JSON object that was not present in the original protobuf message — demonstrating that the escaping invariant enforced everywhere else in the codebase (verified in `GPBJsonWire.php`, `json/internal/writer.cc`, `upb/json/encode.c`, `JsonFormat.java`, `JsonFormatter.cs`) is bypassed specifically for `Any.type_url` in the pure-PHP path.

Note: I was not able to execute this PoC in a live PHP interpreter (no code-execution tool available in this session); the finding is based on static code-path analysis of `Message.php` compared against the escaping logic present in `GPBJsonWire.php` and all other language backends. A background agent with filesystem/terminal access should run this PoC against the pure-PHP runtime to confirm the exact malformed-JSON output before landing the fix.

    // Used for escaping control chars in strings.
    private static $k_control_char_limit = 0x20;

    private static function jsonNiceEscape($c)
    {
      switch ($c) {
          case '"':  return "\\\"";
          case '\\': return "\\\\";
          case '/': return "\\/";
          case '\b': return "\\b";
          case '\f': return "\\f";
          case '\n': return "\\n";
          case '\r': return "\\r";
          case '\t': return "\\t";
          default:   return NULL;
      }
    }

    private static function isJsonEscaped($c)
    {
        // See RFC 4627.
        return $c < chr($k_control_char_limit) || $c === "\"" || $c === "\\";
    }

    public static function escapedJson($value)
    {
        $escaped_value = "";
        $unescaped_run = "";
        for ($i = 0; $i < strlen($value); $i++) {
            $c = $value[$i];
            // Handle escaping.
            if (static::isJsonEscaped($c)) {
                // Use a "nice" escape, like \n, if one exists for this
                // character.
                $escape = static::jsonNiceEscape($c);
                if (is_null($escape)) {
                    $escape = "\\u00" . bin2hex($c);
                }
                if ($unescaped_run !== "") {
                    $escaped_value .= $unescaped_run;
                    $unescaped_run = "";
                }
                $escaped_value .= $escape;
            } else {
              if ($unescaped_run === "") {
                $unescaped_run .= $c;
              }
            }
        }
        $escaped_value .= $unescaped_run;
        return $escaped_value;
    }

}
