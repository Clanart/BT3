Confirmed: `SubUnlockedCoins` and `AddCoins` in `sei-cosmos/x/bank/keeper/send.go` never call `IsSendEnabledCoins`, and `SubWei`/`AddWei` don't either.

### Title
EVM value transfers (native SEI) bypass the bank module's `SendEnabled` pause mechanism - ([File: x/evm/state/balance.go])

### Summary
Cosmos-side transfers of `usei` (via `MsgSend`/the bank precompile's `send`) are gated by `BaseSendKeeper.IsSendEnabledCoins`, which governance can use to pause transfers of a denom. However, plain EVM-native value transfers (e.g. a simple `to.call{value: x}("")` or an ETH-style transaction with a nonzero `value` field) move `usei`/`wei` balances through the `StateDB` bridge, which never consults `IsSendEnabledCoins`. This mirrors the reported bug class: a pause check enforced on one deposit/transfer entry point can be trivially bypassed via a different entry point that manipulates the same underlying balance state.

### Finding Description
`sei-cosmos/x/bank/keeper/msg_server.go` `Send` explicitly checks `IsSendEnabledCoins` before moving coins: [1](#0-0) 

The bank precompile's `send` method similarly routes through `p.bankMsgServer.Send`, so it inherits this same `IsSendEnabledCoins` check: [2](#0-1) 

However, native EVM value transfers do not go through `MsgSend` or the bank precompile at all. They go through the EVM `StateDB` implementation's `SubBalance`/`AddBalance`, which directly call the bank keeper's low-level coin/wei primitives: [3](#0-2) 

These primitives — `SubUnlockedCoins`, `AddCoins`, `SubWei`, `AddWei` — perform no `IsSendEnabledCoins`/`SendEnabledDenom` check anywhere in their implementation: [4](#0-3) [5](#0-4) 

The only guard present in this path is `CanSendTo` (a blocked/recipient check), not `SendEnabled`: [6](#0-5) 

Any EVM transaction sender (an ordinary, unprivileged user) can move value between EVM addresses (including EOA-to-EOA transfers, or contract calls that forward `msg.value`) using the standard EVM value-transfer semantics implemented by `TransferWithoutEvents`/`SubBalance`/`AddBalance`, entirely independent of whether governance has set `usei`'s `SendEnabled` param to `false` via `x/bank`'s params.

### Impact Explanation
If governance or an emergency-pause proposal disables `SendEnabled` for `usei` (the base/native denom) intending to freeze all fund movement — e.g., during an incident response, security pause, or sanctions-style restriction — any user can continue to move `usei` value completely unimpeded by simply using ordinary EVM transactions with a `value` field, or via `call{value:}` inside a contract. This defeats the intended chain-wide transfer freeze, undermining an incident-response/pause control that other parts of the protocol (bank `MsgSend`, the bank precompile) rely on. This is a control-bypass leading to unauthorized fund movement against the operator's/governance's explicit pause intent, matching the "Medium" classification of the analogous finding (a pause flag enforced on one deposit/transfer path bypassable through another equivalent path).

### Likelihood Explanation
High likelihood of being reachable: EVM value transfers are a completely standard, default operation available to every EVM transaction sender on Sei — no special privilege, precompile access, or contract deployment tricks are needed. The bypass requires no interaction with any precompile; it is simply the default `vm.StateDB` balance-transfer code path (`x/evm/state/balance.go`) invoked by the EVM interpreter itself on every value-bearing call/transaction.

### Recommendation
Add a `SendEnabled`/`IsSendEnabledCoins` check for the base denom in `DBImpl.SubBalance`/`AddBalance` (or in the shared `send` helper) in `x/evm/state/balance.go`, mirroring the check already performed in `sei-cosmos/x/bank/keeper/msg_server.go`'s `Send` handler, so that governance-controlled pauses on the native denom apply uniformly to both the Cosmos-side bank paths and the EVM value-transfer path.

### Proof of Concept
1. Governance (or an authorized param-change actor) sets `x/bank` `Params.DefaultSendEnabled = false` (or explicitly disables `usei`) via `MsgUpdateParams`/`SetSendEnabledParam`, intending to freeze all native-token movement.
2. Confirm `MsgSend` of `usei` now fails with `ErrSendDisabled` (per `IsSendEnabledCoins` check in `sei-cosmos/x/bank/keeper/msg_server.go`).
3. From an EVM account, submit a plain EVM transaction with a nonzero `value` field to another EVM address (a standard native-SEI transfer), or call a contract that does `to.call{value: x}("")`.
4. Observe that this transaction succeeds and moves `usei`/`wei` balance between the sender and recipient sei-addresses, because `DBImpl.SubBalance`/`AddBalance` in `x/evm/state/balance.go` call `BankKeeper().SubUnlockedCoins`/`AddCoins`/`SubWei`/`AddWei` directly, none of which check `IsSendEnabledCoins`, unlike `MsgSend`.

// SubUnlockedCoins removes the unlocked amt coins of the given account. An error is
// returned if the resulting balance is negative or the initial amount is invalid.
// A coin_spent event is emitted after.
func (k BaseSendKeeper) SubUnlockedCoins(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {
	if !amt.IsValid() {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidCoins, amt.String())
	}

	lockedCoins := k.LockedCoins(ctx, addr)

	for _, coin := range amt {
		balance := k.GetBalance(ctx, addr, coin.Denom)
		if checkNeg {
			locked := sdk.NewCoin(coin.Denom, lockedCoins.AmountOf(coin.Denom))
			spendable := balance.Sub(locked)

			_, hasNeg := sdk.Coins{spendable}.SafeSub(sdk.Coins{coin})
			if hasNeg {
				return sdkerrors.Wrapf(sdkerrors.ErrInsufficientFunds, "%s is smaller than %s", spendable, coin)
			}
		}

		var newBalance sdk.Coin
		if checkNeg {
			newBalance = balance.Sub(coin)
		} else {
			newBalance = balance.SubUnsafe(coin)
		}

		err := k.setBalance(ctx, addr, newBalance, checkNeg)
		if err != nil {
			return err
		}
	}

	// emit coin spent event
	ctx.EventManager().EmitEvent(
		types.NewCoinSpentEvent(addr, amt),
	)
	return nil
}

// AddCoins increase the addr balance by the given amt. Fails if the provided amt is invalid.
// It emits a coin received event.
func (k BaseSendKeeper) AddCoins(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {
	if !k.CanSendTo(ctx, addr) {
		return sdkerrors.ErrInvalidRecipient
	}
	if !amt.IsValid() {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidCoins, amt.String())
	}

	for _, coin := range amt {
		balance := k.GetBalance(ctx, addr, coin.Denom)
		newBalance := balance.Add(coin)

		err := k.setBalance(ctx, addr, newBalance, checkNeg)
		if err != nil {
			return err
		}
	}

	// emit coin received event
	ctx.EventManager().EmitEvent(
		types.NewCoinReceivedEvent(addr, amt),
	)

	return nil
}

func (k BaseSendKeeper) SubWei(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Int) (err error) {
	if amt.Equal(sdk.ZeroInt()) {
		return nil
	}
	defer func() {
		if err == nil {
			ctx.EventManager().EmitEvent(
				types.NewWeiSpentEvent(addr, amt),
			)
		}
	}()
	currentWeiBalance := k.GetWeiBalance(ctx, addr)
	if amt.LTE(currentWeiBalance) {
		// no need to change usei balance
		return k.setWeiBalance(ctx, addr, currentWeiBalance.Sub(amt))
	}
	currentUseiBalance := k.GetBalance(ctx, addr, sdk.MustGetBaseDenom()).Amount
	currentAggregatedBalance := currentUseiBalance.Mul(OneUseiInWei).Add(currentWeiBalance)
	postAggregatedbalance := currentAggregatedBalance.Sub(amt)
	if postAggregatedbalance.IsNegative() {
		return sdkerrors.Wrapf(sdkerrors.ErrInsufficientFunds, "%swei is smaller than %swei", currentAggregatedBalance, amt)
	}
	useiBalance, weiBalance := SplitUseiWeiAmount(postAggregatedbalance)
	if err := k.setBalance(ctx, addr, sdk.NewCoin(sdk.MustGetBaseDenom(), useiBalance), true); err != nil {
		return err
	}
	return k.setWeiBalance(ctx, addr, weiBalance)
}

func (k BaseSendKeeper) AddWei(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Int) (err error) {
	if !k.CanSendTo(ctx, addr) {
		return sdkerrors.ErrInvalidRecipient
	}
	if amt.Equal(sdk.ZeroInt()) {
		return nil
	}
	defer func() {
		if err == nil {
			ctx.EventManager().EmitEvent(
				types.NewWeiReceivedEvent(addr, amt),
			)
		}
	}()
	currentWeiBalance := k.GetWeiBalance(ctx, addr)
	postWeiBalance := currentWeiBalance.Add(amt)
	if postWeiBalance.LT(OneUseiInWei) {
		// no need to change usei balance
		return k.setWeiBalance(ctx, addr, postWeiBalance)
	}
	currentUseiBalance := k.GetBalance(ctx, addr, sdk.MustGetBaseDenom()).Amount
	useiCredit, weiBalance := SplitUseiWeiAmount(postWeiBalance)
	if err := k.setBalance(ctx, addr, sdk.NewCoin(sdk.MustGetBaseDenom(), currentUseiBalance.Add(useiCredit)), true); err != nil {
		return err
	}
	return k.setWeiBalance(ctx, addr, weiBalance)
