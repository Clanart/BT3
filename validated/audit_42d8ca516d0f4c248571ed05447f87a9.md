## Title
`aptos move verify-package` never compares on-chain module bytecode, only package metadata, allowing bytecode/source mismatches to pass verification - (File: `aptos-move/cli/src/stored_package.rs`, `aptos-move/cli/src/commands.rs`)

### Summary
The external report's root cause is a mismatch between what a function *claims* to reconcile (cost vs. `msg.value`) and what it actually enforces, leaving a gap an attacker/observer can exploit or be misled by. The Aptos-native analog is in the CLI's package-verification path: `aptos move verify-package` is documented and named as checking that "on-chain bytecode matches a local source tree," but the implementation only compares `PackageMetadata` fields (name, deps, module metadata, manifest, upgrade policy, extension, source digest) and never fetches or diffs the actual compiled module bytecode stored on-chain.

### Finding Description
`VerifyPackage::execute` in `aptos-move/cli/src/commands.rs` builds the package locally, then does: [1](#0-0) 

Critically, `CachedPackageRegistry::create(client, self.account, false)` passes `with_bytecode = false`, so bytecode is never downloaded from chain: [2](#0-1) 

The subsequent `package.verify(&compiled_metadata)` call only compares metadata fields — name, deps, `ModuleMetadata` (name/source/source_map/extension), manifest, upgrade policy, extension, and `source_digest`: [3](#0-2) 

None of these fields is the actual compiled bytecode. `source_digest` is computed from the raw Move source files (per its doc comment: "constructed by first building the sha256 of each individual source... than sha256 them again"), and `ModuleMetadata.source`/`source_map` are optional, gzip-compressed source text/maps — not hashes or copies of the deployed bytecode: [4](#0-3) 

At the protocol/VM level, `code::publish_package` and the native `request_publish`/`request_publish_with_allowed_deps` calls only validate module *names* against `expected_modules` and structural compatibility between old/new bytecode; nothing binds the declared `ModuleMetadata.source` to the actual bytes in the `code: vector<vector<u8>>` bundle being published: [5](#0-4) [6](#0-5) 

As a result, a publisher can submit a package where the declared metadata (source, source digest, manifest) corresponds to legitimate, auditable source code, while the actual bytecode bundle passed to `request_publish` is different (e.g., hand-crafted or compiled from a different, malicious source). `aptos move verify-package` will report success because it never inspects the deployed bytecode at all — it only checks that the metadata self-reports match.

### Impact Explanation
This breaks the code-safety guarantee that operators, auditors, and governance reviewers rely on before trusting a deployed package. The tool and its documentation explicitly promise bytecode-to-source verification (`third_party/move/documentation/book/src/cli-deploy.md` line 12: "checks that on-chain bytecode matches a local source tree"), but the implementation provides no such guarantee — it is metadata-to-metadata comparison only. This is exactly the "mismatch between verified bytes, package metadata... and committed module bytes" class of issue, and can lead operators to approve/trust malicious bytecode that does not match displayed/audited source, i.e., a silent code-substitution/supply-chain risk with mainnet relevance whenever `verify-package` is used as a trust gate for permissionless or upgradeable publish flows.

### Likelihood Explanation
Exploitation requires a publisher (or compromised deployer key/CI pipeline) to intentionally publish bytecode that diverges from the declared source metadata while keeping the metadata internally self-consistent (matching source digest/text). Since nothing on-chain or in the CLI cross-checks metadata against actual bytecode, this is straightforward for any account with publish rights to their own package (including permissionless code-object/resource-account deployments), and the divergence would go undetected by anyone relying on `verify-package` for assurance.

### Recommendation
- Make `VerifyPackage::execute` always fetch on-chain bytecode (`with_bytecode = true`) and additionally recompile locally, then byte-for-byte compare (or hash-compare) the freshly compiled module bytecode against the bytecode actually stored on-chain, in addition to the existing metadata checks.
- Optionally, extend `PackageMetadata`/`ModuleMetadata` with a binding hash of the compiled bytecode (or reuse existing bytecode hashes) so that any consumer of the registry (not just the CLI) can cryptographically verify code-to-source correspondence without needing a separate bytecode fetch and local rebuild.

### Proof of Concept
1. Compile package `P` from legitimate source `S`, producing bytecode `B_good`.
2. Craft or compile a divergent, malicious bytecode `B_evil` for the same module names.
3. Publish on-chain using `code::publish_package_txn` (or `object_code_deployment::publish`) with `metadata_serialized` describing `S` (source text, source digest of `S`) but supplying `code = [B_evil]` instead of `B_good` as the `code` vector.
4. Since `code::publish_package` (aptos-framework/sources/code.move) never checks that `ModuleMetadata.source` corresponds to the actual bytes in `code`, and the VM's `validate_publish_request` (aptos_vm.rs) only checks module names/compatibility, publication succeeds with `B_evil` on-chain while metadata still shows `S`.
5. Run `aptos move verify-package --account <addr>`; because `CachedPackageRegistry::create(..., false)` never downloads bytecode and `verify()` only compares metadata (name/deps/modules-metadata/manifest/policy/extension/source_digest), the tool reports "Successfully verified source of package" even though the deployed bytecode is `B_evil`, not derived from `S`.

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
