### Title
Out-of-bounds read / unhandled `IndexError` in mempool CLVM canonical-encoding check crashes spend-bundle validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` decodes a CLVM atom's variable-length size prefix (1–6 bytes) by repeatedly indexing into the caller-supplied buffer without ever checking that the read stays within the buffer's bounds, mirroring the FFmpeg ASF demuxer class of bug (attacker-controlled length field driving reads past the end of a buffer). This function is invoked directly on the raw `puzzle_reveal` and `solution` bytes of every coin spend in every submitted `SpendBundle`, i.e. from a completely unauthenticated network/RPC input path.

### Finding Description
`is_atom_canonical()` decodes the size-prefix based on the high bits of the first byte and then loops `prefix_len` times reading subsequent bytes to build `atom_len`: [1](#0-0) 

Note that inside the `for i in range(prefix_len)` loop, `offset` is incremented and `clvm_buffer[offset]` is read with no bounds check against `len(clvm_buffer)`. This is called from `is_clvm_canonical()`: [2](#0-1) 

`is_clvm_canonical()` is called unconditionally on every coin spend's puzzle reveal and solution during mempool admission: [3](#0-2) 

That call sits inside `MempoolManager.validate_spend_bundle()`, which is invoked from `MempoolManager.add_spend_bundle()`: [4](#0-3) 

Neither `validate_spend_bundle()` nor `add_spend_bundle()` wrap this call in a `try/except` around `is_clvm_canonical`/`is_atom_canonical` specifically — the only exception handling nearby is for `MEMPOOL_CONFLICT` / pending-cache paths after `validate_spend_bundle` returns normally. If a crafted `puzzle_reveal` or `solution` byte string ends exactly where a multi-byte size prefix is still being consumed (e.g., a trailing `0xFC`, `0xF8`, `0xF0`, `0xE0`, or `0xC0`-class byte with insufficient trailing bytes), `clvm_buffer[offset]` raises an unhandled Python `IndexError` instead of returning `False`/raising a handled `ValueError`. Because this is a plain Python `bytes` object, the "out-of-array read" manifests as an uncaught exception rather than memory disclosure, but it is directly reachable and directly attacker-triggerable via one submitted spend bundle, analogous to how the ASF demuxer's crafted length field drove an out-of-bounds read in unmanaged memory.

### Impact Explanation
An unprivileged peer can submit a `SpendBundle` whose `puzzle_reveal` or `solution` is a canonically-invalid CLVM buffer that truncates in the middle of a multi-byte atom-length prefix. This triggers an unhandled `IndexError` inside the transaction-admission code path (`add_spend_bundle` → `validate_spend_bundle` → `is_clvm_canonical` → `is_atom_canonical`), rather than the intended, cleanly-rejected `Err.INVALID_COIN_SOLUTION`. Depending on how far up the call chain (full node RPC/API transaction-processing loop) this exception propagates without being caught, it can abort in-flight mempool processing for that bundle in an unexpected way, differing from the designed "reject with `Err`" contract, and represents a spend-triggered fault in the mempool admission pipeline rather than a graceful validation failure. This matches the "spend-triggered transaction-processing halt" acceptance criterion.

### Likelihood Explanation
Trivial to trigger: it requires only constructing a `puzzle_reveal`/`solution` byte string (no valid signature or successful CLVM execution required to reach the canonical check, since it runs unconditionally per coin spend before/alongside other checks) with a truncated multi-byte atom length-prefix byte at the very end of the buffer, and submitting it as part of an otherwise-normal `SpendBundle` via the standard transaction-submission RPC/gossip path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing `clvm_buffer[offset]` inside the prefix-decoding loop (and in `is_clvm_canonical()`'s outer loop before dereferencing `clvm_buffer[offset]`), raising/returning the same clean rejection (`False`/`Err.INVALID_COIN_SOLUTION`) instead of letting Python's `IndexError` escape uncaught. Alternatively, wrap the call site in `validate_spend_bundle()` in a `try/except (IndexError, ValueError)` that maps to `Err.INVALID_COIN_SOLUTION`.

### Proof of Concept
Construct a `solution` (or `puzzle_reveal`) buffer that ends immediately after an atom-length-prefix lead byte requiring extra bytes that are missing, e.g. a single trailing byte `0xFC` (which the code table maps to `prefix_len = 5`, requiring 5 more bytes) with no further bytes in the buffer:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
is_clvm_canonical(b"\xfc")   # raises IndexError instead of returning False
```
Embedding such a `solution`/`puzzle_reveal` in a `CoinSpend` inside a `SpendBundle` and submitting it via `MempoolManager.add_spend_bundle()` reaches `is_clvm_canonical(bytes(coin_spend.solution))` at [3](#0-2)  and raises the same unhandled `IndexError` inside the mempool admission pipeline.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
