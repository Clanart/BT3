### Title
Unauthenticated `send_citrea_tx` JSON-RPC Endpoint Allows Arbitrary DA Queue Injection and Operator Fee Drain — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The tx-sender JSON-RPC server registers the `send_citrea_tx` method on a plain HTTP listener with no authentication, no TLS, and no caller identity check. Any TCP-reachable client can call it and insert attacker-chosen `BatchProofMethodId` or `SequencerCommitment` bytes into `tx_sender_citrea_raw_tx_queue`. The tx-sender's background loop then creates and broadcasts Bitcoin commit+reveal transactions at the operator's expense, draining the operator's fee wallet and submitting attacker-controlled data to the Citrea DA layer.

### Finding Description

`start_jsonrpc_server` constructs the server with `ServerBuilder::default()` and sets only `max_request_body_size`: [1](#0-0) 

No TLS config, no bearer token, no IP allowlist, no tower middleware layer, and no per-method auth check are applied anywhere in the file. The `send_citrea_tx` handler goes directly from parameter deserialization to `TxSenderClient::send_citrea_tx`: [2](#0-1) 

`TxSenderClient::send_citrea_tx` unconditionally inserts the caller-supplied `CitreaTxRequest` into the database: [3](#0-2) 

The configuration explicitly supports binding to `0.0.0.0`, making the server network-accessible: [4](#0-3) 

The default is `127.0.0.1`, but `0.0.0.0` is a first-class supported value with no compensating auth requirement added by the code. The missing authentication is a code-level omission, not a config-only issue: the code provides no mechanism to authenticate callers regardless of bind address.

Once a row is in `tx_sender_citrea_raw_tx_queue`, the `sync_citrea_txs` background loop picks it up unconditionally: [5](#0-4) 

It creates a Bitcoin commit transaction (spending operator UTXOs for fees) and a reveal transaction embedding the attacker's bytes in a tapscript, then broadcasts both to the Bitcoin network.

### Impact Explanation

1. **Operator fee wallet drain**: Every injected row causes the tx-sender to create and broadcast a commit+reveal transaction pair. An attacker can flood the queue with large payloads (up to `MAX_CHUNK_SIZE` per row, chunked into multiple rows) to continuously drain the operator's Bitcoin fee wallet.
2. **Unauthorized DA submission**: Attacker-chosen `BatchProofMethodId` or `SequencerCommitment` bytes are broadcast to the Citrea DA layer under the operator's identity, violating the invariant that only the aggregator/verifier may submit DA payloads.
3. **Authorization bypass**: The trust boundary between the aggregator/verifier (the only intended callers) and the tx-sender is completely absent at the JSON-RPC layer, while the gRPC layer correctly enforces mTLS.

### Likelihood Explanation

Exploitability requires TCP access to the JSON-RPC port. With `TX_SENDER_JSONRPC_BIND=0.0.0.0` (a supported, documented value), any network-reachable attacker qualifies. With the default `127.0.0.1`, the attacker needs local process access on the same host. In either case, no credentials, state, or prior interaction are required.

### Recommendation

Add authentication to the JSON-RPC server. Options in order of strength:
1. Add a shared-secret bearer token check as a `jsonrpsee` middleware layer, validated on every request.
2. Enable TLS with client certificate verification on the `ServerBuilder`.
3. Restrict the bind address to loopback-only in code (remove `0.0.0.0` support) and document that the port must not be exposed externally.

Any of these must be enforced at the `start_jsonrpc_server` level so that both `send_tx` and `send_citrea_tx` are protected uniformly.

    pub async fn send_citrea_tx(&self, request: CitreaTxRequest) -> Result<i64, eyre::Report> {
        use crate::citrea::data_serialization::DataOnDa;
        use crate::citrea::MAX_CHUNK_SIZE;

        let mut dbtx = self.db.begin_transaction().await?;

        let insertion_id = match request {
            CitreaTxRequest::BatchProof { bytes, chunk_size } => {
                // Hash the original proof bytes so the same proof dedupes even if callers
                // retry it with a different chunk_size or as a non-chunked Complete body.
                let full_body_hash = crate::citrea::calculate_sha256(&bytes);
                let mut chunk_size = chunk_size.unwrap_or(MAX_CHUNK_SIZE);
                if chunk_size == 0 {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                if chunk_size > MAX_CHUNK_SIZE {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                let chunk_size = chunk_size as usize;

                if bytes.len() <= chunk_size {
                    let data = DataOnDa::Complete(bytes);
                    let blob = borsh::to_vec(&data).expect("zk::Proof serialize must not fail");
                    self.db
                        .insert_citrea_raw_tx_single_with_hash(
                            &mut dbtx,
                            TransactionKind::Complete,
                            &blob,
                            &full_body_hash,
                        )
                        .await?
                } else {
                    let chunks: Vec<Vec<u8>> = bytes
                        .chunks(chunk_size)
                        .map(|chunk| {
                            borsh::to_vec(&DataOnDa::Chunk(chunk.to_vec()))
                                .expect("zk::Proof serialize must not fail")
                        })
                        .collect();
                    self.db
                        .insert_citrea_raw_tx_chunks(&mut dbtx, &chunks, &full_body_hash)
                        .await?
                }
            }
            CitreaTxRequest::BatchProofMethodId(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea BatchProofMethodId DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::BatchProofMethodId,
                        &body,
                    )
                    .await?
            }
            CitreaTxRequest::SequencerCommitment(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea SequencerCommitment DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::SequencerCommitment,
                        &body,
                    )
                    .await?
            }
        };

        self.db.commit_transaction(dbtx).await?;
        Ok(insertion_id)
