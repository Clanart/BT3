## Finding

### Title
Path Traversal via Unvalidated `filepath` Query Parameter in `open-repository-from-url` Deep Links - (File: `app/src/lib/parse-app-url.ts`)

### Summary
`parseAppURL` validates the `pr` and `branch` query parameters of an `openrepo` deep link but performs **no validation whatsoever** on `filepath` before including it in the resulting `IOpenRepositoryFromURLAction`.

### Finding Description
In `parseAppURL`, the `branch` parameter is checked against `testForInvalidChars` and `pr` is checked against a strict digit regex, but `filepath` is read straight from the query string and returned unmodified: [1](#0-0) 

Specifically: [2](#0-1) 

There is no call to `testForInvalidChars`, no `path.normalize`/`path.resolve` containment check, and no rejection of values containing `..` or leading `/` for `filepath`, unlike what is done for `branch`. This is consistent with the interface definition documenting `filepath` as "the file to open after cloning the repository": [3](#0-2) 

The action produced here flows to `handleAppURL` in `app/src/main-process/main.ts`, which forwards it unmodified to the renderer via `window.sendURLAction(action)`: [4](#0-3) 

From there it reaches the dispatcher, which contains logic referencing `filepath` (`app/src/ui/dispatcher/dispatcher.ts` has 6 matches for `filepath`), presumably to join it against the freshly cloned repository's working directory and open it (e.g., via an external editor or `shell.openPath`/`shell.showItemInFolder`, both of which are wired to IPC handlers in `main.ts`: `show-item-in-folder` and `move-to-trash`). [5](#0-4) 

**Caveat / what I could not confirm:** I was unable to retrieve the exact lines in `app/src/ui/dispatcher/dispatcher.ts` that consume `filepath` within the available tool budget, so I cannot confirm the exact join/resolve logic (e.g., whether `path.join(repoPath, filepath)` is used without a containment check, or whether some other sanitization exists downstream that would neutralize the traversal before it reaches a filesystem API). This should be verified directly in that file before treating this as a confirmed end-to-end exploit chain.

### Impact Explanation
If the dispatcher does join `filepath` with the cloned repo path without resanitizing it (which is what the field's absence of validation in `parse-app-url.ts` implies is possible), a crafted `x-github-client://openrepo/...?filepath=..%2f..%2f..%2fetc%2fpasswd` deep link could cause Desktop to attempt to open an arbitrary file on the victim's filesystem outside the cloned repository, once the user clicks the link. This is a real, out-of-scope-boundary read primitive, but note the practical impact is bounded by what "open" does in the app (e.g., open in an external editor / OS default handler) — it does not by itself exfiltrate file contents to a remote attacker; it would require the app to also transmit or render that content somewhere reachable by the attacker to be a data-exfiltration bug rather than a local-file-open bug.

### Likelihood Explanation
An attacker only needs to get a victim to click a specially-crafted `x-github-client://openrepo/...` deep link, which is a normal top-level attack surface for GitHub Desktop's URL protocol handler covered by the review scope ("clicked links/deep links").

### Recommendation
Add the same class of validation applied to `branch` to `filepath` in `parseAppURL` — reject values containing `..` path segments, null bytes, or leading `/`/drive-letter prefixes, or better, resolve the eventual join path against the target repository root and verify it stays within that root before performing any file-open operation in the dispatcher.

### Proof of Concept
```
x-github-client://openrepo/some/repo?url=https://github.com/some/repo&filepath=..%2f..%2f..%2f..%2fetc%2fpasswd
```
Focused unit test idea (mirroring existing tests in `app/test/unit/parse-app-url-test.ts`): assert that `parseAppURL` returns `unknown` (or strips the traversal) when `filepath` contains `../` sequences — currently it does not, and the action is passed through with the raw traversal string. [6](#0-5)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
