### Title
Zero-valued `Kip71GasTarget` governance parameter causes division-by-zero panic in `NextMagmaBlockBaseFee` - ([File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base fee parameter `GasTarget` is used as a divisor in `NextMagmaBlockBaseFee`, but unlike its sibling parameter `BaseFeeDenominator`, it has no zero-value guard either at the governance-vote validation layer or at the point of use. A governance vote that sets `governance.kip71.gastarget` to `0` will pass all format/consistency checks and, once applied at the next epoch, will cause every node computing the next block's base fee to panic on integer division by zero.

### Finding Description
`NextMagmaBlockBaseFee` divides by `gasTarget` in both the "gas used above target" and "gas used below target" branches: [1](#0-0) 

Unlike `BaseFeeDenominator`, which has an explicit runtime fallback when zero (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = ... 64 }`), `GasTarget` has no such protection: [2](#0-1) 

The governance parameter registry defines a `FormatChecker` for `Kip71BaseFeeDenominator` that explicitly rejects zero (`v != 0`), but `Kip71GasTarget` uses `noopFormatChecker`, which performs no validation at all: [3](#0-2) 

At the header-governance vote-consistency layer, `Kip71GasTarget` is explicitly listed among parameters that require "no more checks here" beyond the generic format check performed in `NewVoteData()`, unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` which have dedicated cross-field consistency checks: [4](#0-3) 

Since no layer rejects `GasTarget == 0`, a validator (or the governing node in single-governance mode, or council majority in permissionless mode) can successfully vote this value into the governance parameter set. Once the vote is committed as of the next epoch, `NextMagmaBlockBaseFee` — called both when a proposer prepares a header and when every other node verifies that header's `baseFee` via `VerifyMagmaHeader` — will attempt `x.Div(x, new(big.Int).SetUint64(0))`, which panics.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked by every node (proposer during block assembly and all other nodes during header verification) for every block. A panic here is not a localized error — it will crash all conforming nodes uniformly once the zero `GasTarget` value takes effect, halting the network's block production. This is a "acceptance of an invalid transaction or block"/chain-liveness-failure class issue reachable purely through the governance voting mechanism, without requiring any privileged bypass beyond normal governance participation rights.

### Likelihood Explanation
Likelihood is low-to-medium: it requires a validator with voting rights (or the sole governing node in single mode) to cast a vote setting `governance.kip71.gastarget` to `0`, and for that vote to be accepted into governance at epoch boundary via the existing (and here-insufficient) validation pipeline. No cryptographic or protocol-level barrier prevents this specific value once a node has voting privileges, since neither `FormatChecker` nor `checkConsistency` rejects zero for this key.

### Recommendation
Add a zero-value rejection to the `FormatChecker` for `Kip71GasTarget` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check) in `kaiax/gov/param.go`, and/or add an explicit fallback/guard for `GasTarget == 0` inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, consistent with the existing `BaseFeeDenominator` zero-guard.

### Proof of Concept
1. As a validator with vote rights (or governing node in single mode), submit a header vote for `governance.kip71.gastarget = 0`.
2. Once the vote is accepted and becomes part of `GovData` for the next epoch (per `getExpectedGovernance`/`VerifyGov` in `kaiax/gov/headergov/impl/header.go`), the chain config's `KIP71Config.GasTarget` becomes `0`.
3. On the next block after the epoch transition, any node with `parentGasUsed != 0` calls `NextMagmaBlockBaseFee`, which executes `new(big.Int).SetUint64(parentGasUsed - gasTarget)` then `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, causing a runtime panic in `params/kip71_config.go` lines 100-102 (or 118-121 for the below-target branch), crashing block production/verification network-wide.
