### Title
`PlotNFT2Wallet.claim_rewards` builds one unbounded spend bundle for all unclaimed pool rewards, risking permanent claim failure and stuck rewards - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`)

### Summary
`PlotNFT2Wallet.claim_rewards` fetches every unclaimed pool-reward record for a self-custody plot-NFT and bundles all of them into a single `CoinSpend`/`SpendBundle`, with no cap on how many reward coins are included, unlike the legacy `PoolWallet.claim_pool_rewards` path which explicitly truncates the number of spends per transaction.

### Finding Description
`PlotNFT2Wallet.claim_rewards` retrieves the full unclaimed-reward list with no bound: [1](#0-0) 
and then builds a single spend that includes one `CoinSpend` per reward coin plus the singleton spend, with the number of `SendMessage`/reward-claim conditions and reward coin spends scaling 1:1 with `len(rewards_to_claim)`: [2](#0-1) [3](#0-2) 

This is pushed as one `WalletSpendBundle` with no truncation/batching: [4](#0-3) 

Contrast this with the legacy pooling implementation, `PoolWallet.claim_pool_rewards`, which explicitly limits the number of reward coins absorbed per spend bundle via a `max_spends_in_tx` parameter (default `DEFAULT_MAX_CLAIM_SPENDS`), breaking out of the loop and logging a truncation message once the limit is hit: [5](#0-4) 

`PlotNFT2Wallet.claim_rewards`, and the RPC entry point that calls it, have no equivalent `max_spends_in_tx`/batching parameter: [6](#0-5) [7](#0-6) 

This mirrors the `frxETHMinter.depositEther` bug class: the loop/condition count in the resulting spend is proportional to accumulated, self-growing on-chain state (unclaimed pool-reward coins accrue automatically every time the farmer wins a block), rather than to a bounded, caller-chosen value. If a self-custody plot-NFT farmer does not claim rewards for a long time (or accumulates many small partial rewards from a pool before switching to self-custody), the number of unclaimed reward coins can grow arbitrarily large. Because CLVM execution cost and the block's `MAX_BLOCK_COST_CLVM`/`MAX_SPENDS_PER_BLOCK`/`MAX_BLOCK_ATOMS`/`MAX_BLOCK_PAIRS` limits are enforced by the mempool and block validation (`chia/full_node/mempool_manager.py`, `chia/full_node/mempool.py`), a `claim_rewards` spend bundle whose cost/spend-count exceeds these bounds will always be rejected. Since `claim_rewards()` has no way to claim a subset of the accumulated rewards, the user cannot reduce the spend size — every subsequent call attempts to spend the same growing, oversized set of coins.

### Impact Explanation
Once the number of unclaimed p2-singleton reward coins for a self-custody plot-NFT grows large enough that the resulting `claim_rewards` spend bundle exceeds `MAX_BLOCK_COST_CLVM`, `MAX_SPENDS_PER_BLOCK`, or the atom/pair budgets enforced in mempool admission and block validation, the transaction can never be included in the mempool or a block. Because there is no partial-claim/batching mechanism, the farmer has no way to reduce the size of the claim and unlocks the rewards; the singleton and all its accumulated rewards become effectively unspendable via the normal wallet path, halting further reward absorption for that plot-NFT and requiring manual/out-of-band intervention (e.g., a custom transaction constructed outside the wallet) to recover. This is a spend-triggered transaction-processing halt and availability impairment, matching the class of impact the original report was rated Medium for.

### Likelihood Explanation
Likelihood is moderate: it requires either a long period without claiming (farmers may not run `pw_absorb_rewards`/`claim_rewards` frequently, especially with automated setups that batch claims infrequently to save fees) or a low-value chain state where individual reward coins are numerous relative to the cost budget — directly analogous to the "ETH at $1" scenario in the original report, where the CLVM-cost cost of a fixed reward-coin count becomes limiting sooner as more rewards accumulate before a claim.

### Recommendation
Add a `max_spends_in_tx`-style parameter (mirroring `PoolWallet.claim_pool_rewards`'s `DEFAULT_MAX_CLAIM_SPENDS`) to `PlotNFT2Wallet.claim_rewards`, truncating `rewards_to_claim` to a safe count per spend bundle and allowing repeated calls to progressively drain the backlog, instead of always attempting to claim the full unclaimed set in one transaction.

### Proof of Concept
Conceptual PoC (cannot be executed in this environment, described from source):
1. Create a `PlotNFT2Wallet` in self-custody mode.
2. Farm many blocks to the plot-NFT's `p2_singleton_puzzle_hash` without ever calling `claim_rewards`, accumulating N unclaimed reward coins (`get_pool_rewards`).
3. Call `PlotNFT2Wallet.claim_rewards()`; it builds `plotnft.claim_pool_rewards(rewards_to_claim=<all N rewards>, ...)` producing N reward `CoinSpend`s plus one singleton `CoinSpend` in a single `WalletSpendBundle`, per `chia/pools/plotnft_drivers.py:590-642` and `chia/wallet/plotnft_wallet/plotnft_wallet.py:163-226`.
4. For sufficiently large N (scaling with how long claims are deferred), the resulting bundle's CLVM cost/spend count exceeds mempool/block limits (`MempoolManager`/`Mempool` cost and `MAX_SPENDS_PER_BLOCK`/`MAX_BLOCK_ATOMS`/`MAX_BLOCK_PAIRS` checks), causing `push_tx` to fail permanently, since there is no mechanism in `claim_rewards` to request only a subset of rewards.

    def claim_pool_rewards(
        self,
        rewards_to_claim: list[PoolReward],
        reward_delegated_puzzles_and_solutions: list[DelegatedPuzzleAndSolution],
    ) -> list[CoinSpend]:
        if self.pooling:
            raise ValueError("Cannot claim rewards while pooling. If you're a pool, try `forward_pool_rewards`")
        if len(rewards_to_claim) != len(reward_delegated_puzzles_and_solutions):
            raise ValueError("Number of rewards and delegated puzzles and solutions must match")
        dpuz_and_solution = DelegatedPuzzleAndSolution(
            puzzle=Program.to(
                (
                    1,
                    [
                        CreateCoin(
                            puzzle_hash=self.inner_puzzle_hash(),
                            amount=self.coin.amount,
                            memos=[self.singleton_struct.struct_hash()],
                        ).to_program(),
                        *(
                            SendMessage(
                                msg=dpuz_and_sol.puzzle.get_tree_hash(),
                                sender=MessageParticipant(puzzle_hash_committed=self.puzzle_hash(nonce=0)),
                                receiver=MessageParticipant(coin_id_committed=reward.coin.name()),
                            ).to_program()
                            for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
                        ),
                    ],
                )
            ),
            solution=Program.to([]),
        )
        return [
            self.singleton_action_spend(
                inner_solution=self.puzzle_with_restrictions().solve(
                    member_validator_solutions=[],
                    dpuz_validator_solutions=[],
                    member_solution=self.bls_member.solve(),
                    delegated_puzzle_and_solution=dpuz_and_solution,
                )
            ),
            *(
                make_spend(
                    coin=reward.coin,
                    puzzle_reveal=reward.puzzle(),
                    solution=reward.solve(
                        self.inner_puzzle_hash(),
                        delegated_puzzle_and_solution=dpuz_and_sol,
                    ),
                )
                for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
            ),
        ]

    async def pw_absorb_rewards(
        self,
        request: PWAbsorbRewards,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> PWAbsorbRewardsResponse:
        """Perform a sweep of the p2_singleton rewards controlled by the pool wallet singleton"""
        wallet = self.service.wallet_state_manager.wallets[request.wallet_id]

        if isinstance(wallet, PoolWallet):
            async with self.service.wallet_state_manager.lock:
                await wallet.claim_pool_rewards(request.fee, request.max_spends_in_tx, action_scope)
                state: PoolWalletInfo = await wallet.get_current_state()
        elif isinstance(wallet, PlotNFT2Wallet):
            await wallet.claim_rewards(action_scope=action_scope, fee=request.fee, extra_conditions=extra_conditions)
            state = await wallet.get_current_state()
        else:
            raise ValueError("`pw_absorb_rewards` called on a non-pooling wallet")
