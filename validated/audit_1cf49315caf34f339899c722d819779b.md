### Title
Stale `userVotedForPoolInVlmgp` accounting after pool removal/re-add permanently freezes a user's voted vlMGP - (File: `wombat/WombatBribeManager.sol`)

### Summary
`WombatBribeManager.removePool()` only pops the pool address out of the `pools` iteration array; it never clears `poolInfos[_lp]` or any user's `userVotedForPoolInVlmgp[user][_lp]` balance. When the same pool address is later re-added with `addPool()`, `poolInfos[_lp].totalVoteInVlmgp` is reset to `0`, but the stale per-user `userVotedForPoolInVlmgp` mapping is left untouched. A user who voted for the pool before removal keeps a stale vote balance that is added on top of any new votes, causing `unvote()` to underflow and permanently revert, freezing part of the user's vlMGP voting power (and, transitively, blocking `VLMGP.startUnlock()`).

### Finding Description
`vote()` and `unvote()` gate on `pool.isActive`, but `removePool()` never sets `isActive = false`, nor does it reset `userVotedForPoolInVlmgp[user][lp]`: [1](#0-0) 

When the pool is reintroduced, `addPool()` overwrites `poolInfos[_lp]` with a fresh struct (`totalVoteInVlmgp: 0`), but again does not touch the stale `userVotedForPoolInVlmgp` mapping for any past voter: [2](#0-1) 

Sequence:
1. Alice calls `vote([poolA],[X])`. This sets `poolInfos[poolA].totalVoteInVlmgp += X` and `userVotedForPoolInVlmgp[Alice][poolA] += X`, and stakes `X` in the pool's `BribeRewardPool`. [3](#0-2) 
2. Owner calls `removePool(index of poolA)` — this is a normal operational action (e.g., swapping to a new rewarder or temporarily delisting a pool), not a malicious act. `poolInfos[poolA]` and `userVotedForPoolInVlmgp[Alice][poolA]` remain unchanged (still `X`).
3. Owner calls `addPool(poolA, newRewarder, name)` to reinstate the pool. `poolInfos[poolA].totalVoteInVlmgp` resets to `0`, but `userVotedForPoolInVlmgp[Alice][poolA]` is still `X` (stale).
4. Alice calls `vote([poolA],[Y])` again. Since `isActive` was never cleared, this succeeds: `pool.totalVoteInVlmgp` becomes `Y`, but `userVotedForPoolInVlmgp[Alice][poolA]` becomes `X + Y` (inflated).
5. Alice calls `unvote(poolA)`. `currentVote` reads the inflated `X + Y`: [4](#0-3) 
`pool.totalVoteInVlmgp -= (X+Y)` underflows against the real value `Y` (Solidity 0.8 checked arithmetic), and the transaction permanently reverts.

### Impact Explanation
Because `unvote()` always reverts for this pool, `userVotedForPoolInVlmgp[Alice][poolA]` can never be reduced back down, and `userTotalVotedInVlmgp[Alice]` remains permanently inflated by `X`. This value is consumed by `VLMGP.startUnlock()` to gate how much MGP a user may unlock: [5](#0-4) 
An inflated, un-reducible `userTotalVotedInVlmgp[Alice]` permanently blocks Alice from unlocking the corresponding portion of her locked MGP, constituting a permanent freeze of user funds/voting power triggered entirely by ordinary wallet calls (`vote`/`unvote`), following a routine (non-malicious) admin pool removal/re-add cycle — directly analogous to the referenced `ERC20Boost.updateUserBoost()` stale-boost bug class.

### Likelihood Explanation
Pool removal and re-addition (e.g., to change a rewarder contract or temporarily delist/relist a Wombat pool) is a normal, expected admin operation, not an attack. Any user who voted for a pool before it is removed and votes again after it is re-added will trigger the underflow the next time they call `unvote()` on that pool — this requires no special privilege or complex setup, only ordinary `vote()`/`unvote()` calls.

### Recommendation
In `removePool()`, either disallow re-adding a previously used pool address, or explicitly zero out affected accounting when a pool is removed/re-added. At minimum, `addPool()` should reject re-adding an address that still has non-zero legacy `userVotedForPoolInVlmgp` entries, or the contract should track total per-pool votes independent of address reuse (e.g., versioned pool IDs) so stale per-user vote balances can never be summed with fresh ones for the same pool address.

### Proof of Concept
See the 5-step sequence in Finding Description: `vote(poolA, X)` → owner `removePool` → owner `addPool(poolA, ...)` → `vote(poolA, Y)` → `unvote(poolA)` reverts on underflow at `pool.totalVoteInVlmgp -= uint256(currentVote)` in `wombat/WombatBribeManager.sol` line 229, since `currentVote = X+Y > pool.totalVoteInVlmgp = Y`. [6](#0-5)

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
