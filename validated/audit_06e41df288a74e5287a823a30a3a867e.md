### Title
`openPullRequestFromUrl` checks out an attacker-supplied fork branch into a repository chosen independently of the deep-link `url`, silently misdirecting the checkout target - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
The Sherlock report describes `GeneralRepay#repayJUSD` sending a refund to the `to` address instead of `msg.sender`, i.e., an asset is delivered to a party chosen by a field the caller does not fully control, rather than the party the invoking context implies. The Desktop analog is `openPullRequestFromUrl` in `app/src/ui/dispatcher/dispatcher.ts`, invoked from the `x-github-client://openRepo/<url>?pr=<n>` deep-link handler. The repository that ultimately receives the fetch + branch checkout is selected by `getRepositoryFromPullRequest`, which ignores the `url` parameter from the link and instead scans the user's already-open repositories for one whose origin/upstream matches the PR's `head` or `base` clone URL returned by the GitHub API.

### Finding Description
`parseAppURL` extracts `url` and `pr` from an `x-github-client://openRepo/...` link without validating that they describe the same repository [1](#0-0) . `dispatchURLAction` routes this to `openRepositoryFromUrl`, which for a `pr` parameter calls `openPullRequestFromUrl(url, pr)` [2](#0-1) .

Inside `openPullRequestFromUrl`, the PR object is fetched via `this.appStore.fetchPullRequest(url, pr)`, then the *actual target repository* is chosen by `getRepositoryFromPullRequest(pullRequest)` — which never re-checks the caller-supplied `url` at all, only the PR's own `head.repo.clone_url` / `base.repo.clone_url` fields returned by the API against the set of repositories already known to the local Desktop instance [3](#0-2) :

```
private getRepositoryFromPullRequest(pullRequest: IAPIPullRequest): RepositoryWithGitHubRepository | null {
  ...
  for (const repository of repositories) {
    if (this.doesRepositoryMatchUrl(repository, headUrl)) return repository
  }
  for (const repository of repositories) {
    if (this.doesRepositoryMatchUrl(repository, baseUrl)) return repository
  }
  return null
}
``` [4](#0-3) 

If a match is found, `selectRepository(repository)` is called and then `_checkoutPullRequest` runs against that repository — using `pullRequest.head.repo.clone_url` (the fork, fully attacker-chosen since the attacker created the PR) as the remote to add and fetch, and checking out `pr/<number>` into that repository's working tree [5](#0-4) . The remote-add/fetch/branch-creation logic in `_findPullRequestBranch` adds the attacker's `headCloneUrl` unconditionally when no existing remote matches it [6](#0-5) .

Because selection is driven purely by matching against *any* repository already tracked by the user's Desktop install (matched loosely by hostname/owner/name via `urlsMatch`/`urlMatchesRemote` in `app/src/lib/repository-matching.ts`), the `url` in the clicked link and the repository that actually gets a remote added, fetched, and checked out can diverge. An attacker only needs to open a public pull request against any repository the victim has locally (the PR's `base.repo` is the victim's real, already-cloned project) and get the victim to click a crafted `x-github-client://openRepo/<anything>?pr=<N>` link (e.g., embedded in a webpage, chat message, or malicious website registering the same custom protocol flow); Desktop will resolve, add, fetch and checkout the attacker's fork branch into the victim's real working repository regardless of what `url` the link nominally pointed to.

### Impact Explanation
This silently redirects a "PR checkout" action away from the ostensible target implied by the link's `url` and toward whatever local repository happens to match the PR metadata, mirroring the refund-misdirection root cause (destination chosen by attacker-influenced data instead of the caller/link's declared target). The victim's working directory in an existing, trusted repository is populated with unreviewed, attacker-authored code from a foreign fork, and a new remote is silently added. Because no confirmation dialog is required before this remote-add/fetch/checkout sequence and repository selection bypasses the `url` field's intent, the practical outcome is unsolicited execution-adjacent exposure (build scripts, editors, git hooks) to attacker-controlled fork content within a repo the user did not choose via the link.

### Likelihood Explanation
Requires only that the victim (a) already has the targeted base repository cloned in Desktop and (b) clicks an attacker-supplied deep link (a normal, low-friction browser/OS action, not local/admin access or malware). Opening a public PR against any repository is unauthenticated for the attacker. No additional user confirmation step blocks the remote-add + checkout once the deep link is triggered.

### Recommendation
Validate that `pullRequest.base.repo.clone_url` (and/or `head.repo.clone_url`) actually matches the `url` parameter supplied in the deep link before selecting/using a local repository via `getRepositoryFromPullRequest`, or otherwise require explicit user confirmation naming the repository and fork before adding a remote and checking out `pr/<n>`.

### Proof of Concept
1. Attacker forks `victim-owner/victim-repo` (a repo the target user has cloned in Desktop) and opens a public pull request from the fork.
2. Attacker crafts `x-github-client://openRepo/https://github.com/attacker/anything?pr=<PR_NUMBER>` and gets the victim to click it (webpage, chat, etc.).
3. `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` fetches the real PR object for `<PR_NUMBER>` (unrelated to the `url` path in the link) [7](#0-6) .
4. `getRepositoryFromPullRequest` matches `pullRequest.base.repo.clone_url` against the victim's already-cloned `victim-owner/victim-repo` and returns it, ignoring the link's `url` field [8](#0-7) .
5. `_checkoutPullRequest`/`_findPullRequestBranch` add the attacker's fork as a `github-desktop-*` remote, fetch it, and check out `pr/<PR_NUMBER>` into the victim's real repository working tree [9](#0-8) .

  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }
