### Title
Quadratic CPU exhaustion via attacker-controlled participant count in `ThresholdKeys::read` / `ThresholdKeys::new` Lagrange interpolation - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::<C>::read` accepts a serialized key-share blob containing attacker-chosen `t` and `n` (each up to `u16::MAX = 65535`). It forwards these to `ThresholdKeys::new`, which computes the group key by evaluating `interpolation_factor` for every participant `1..=t`. Under `Interpolation::Lagrange`, each `interpolation_factor` call iterates over all `t` included indexes, making group-key derivation O(t²) scalar multiplications — roughly 4.3 × 10⁹ field multiplications for `t = n = 65535` — triggered by a serialized input of only ~2 MB.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, and `i` directly from the untrusted byte stream (`crypto/dkg/src/lib.rs:591-602`), then reads `n` scalars/points and calls `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:620-631`). Inside `ThresholdKeys::new`, the group key is computed as:

```rust
let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
let group_key =
  t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();
``` [1](#0-0) 

For `Interpolation::Lagrange`, `interpolation_factor` performs a full inner loop over `included` (`crypto/dkg/src/lib.rs:234-246`), so each of the `t` outer evaluations costs O(t) field multiplications plus an inversion. `ThresholdParams::new` only enforces `t <= n` and `n != 0` (`crypto/dkg/src/lib.rs:166-178`), so `t = n = 65535` is accepted.

Unlike a linear deserialization cost, this is a quadratic amplification: the attacker's input size is O(n) (n point encodings ≈ 32 bytes each), but the victim's work is O(n²) ≈ 4.3 billion field multiplications. This is the Serai analog of the Nautobot ReDoS: a small attacker-controlled input selecting a parameter that drives disproportionate computation.

The same O(t²) blowup exists in `ThresholdKeys::view`, which calls `interpolation_factor` once per included participant (`crypto/dkg/src/lib.rs:500-507`), reachable whenever a signing set of size close to `n` is formed.

### Impact Explanation
An unprivileged party able to feed crafted bytes to `ThresholdKeys::read` (listed as an in-scope deserialization target) can pin a CPU core performing billions of field multiplications, stalling key loading. Any coordinator/processor path that deserializes `ThresholdKeys` from untrusted input — or calls `view` with a large attacker-influenced `included` set — suffers an application-level denial of service with no timeout, matching the CWE-400/CWE-1333 class of the reference advisory.

### Likelihood Explanation
`n` is bounded by `u16` (65535), so the maximum amplification is fixed: ~2 MB input → ~4.3e9 field multiplications (~seconds to tens of seconds of single-core time per call). Whether this is reachable depends on whether untrusted bytes ever reach `ThresholdKeys::read`/`view`; per the engagement rules, bytes fed to `ThresholdKeys::read` are in scope. The impact is availability-only (no secret leakage, no forgery), consistent with a Medium severity DoS analog.

### Recommendation
Cap `n`/`t` to the protocol's actual maximum validator-set size (e.g., `MAX_KEY_SHARES_PER_SET`) inside `ThresholdParams::new` or `ThresholdKeys::read` before any interpolation work is performed. Additionally, note that Lagrange interpolation over a fixed signer set can be computed in O(t) total via prefix/suffix products, which would remove the quadratic factor entirely.

### Proof of Concept
```rust
use std::io;
use dkg::{ThresholdKeys, Interpolation, Participant};
use ciphersuite::{Ciphersuite, group::GroupEncoding};
use ciphersuite_ristretto255::Ristretto;

fn malicious_blob() -> Vec<u8> {
    let t: u16 = u16::MAX;
    let n: u16 = u16::MAX;
    let i: u16 = 1;
    let mut buf = vec![];
    buf.extend(u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes());
    buf.extend(Ristretto::ID);
    buf.extend(t.to_le_bytes());
    buf.extend(n.to_le_bytes());
    buf.extend(i.to_le_bytes());
    buf.push(1); // Interpolation::Lagrange
    buf.extend(<Ristretto as Ciphersuite>::F::ONE.to_repr().as_ref()); // secret_share
    let g = Ristretto::generator().to_bytes();
    for _ in 0 .. n {
        buf.extend(g.as_ref()); // verification shares
    }
    buf
}

// ~2.1 MB input; ThresholdKeys::new then performs ~t^2 ≈ 4.3e9 field
// multiplications inside interpolation_factor while computing group_key.
let keys = ThresholdKeys::<Ristretto>::read(&mut malicious_blob().as_slice());
```
