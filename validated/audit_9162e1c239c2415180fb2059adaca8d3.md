### Title
Attacker-manipulable on-chain median fee rate causes the Bitcoin multisig to sign transactions with arbitrarily inflated fees - (File: processor/src/networks/bitcoin.rs)

### Summary
Analogous to the Index `AaveLeverageStrategyExtension` relying solely on oracle-derived prices to set slippage bounds, `Bitcoin::median_fee` derives the sole fee-rate parameter used to construct every `SignableTransaction` purely from unvalidated on-chain data: the fee rates of whatever transactions happen to be inside a single recent block. An unprivileged party who can get transactions mined into that block (anyone can send Bitcoin transactions) can skew the median, causing the processor to construct — and the FROST multisig to sign — transactions paying an attacker-influenced fee.

### Finding Description
`make_signable_transaction` obtains the fee rate for transaction construction via `self.median_fee(&block_for_fee)`, where `block_for_fee` is a single block (`block_number`) with no averaging or bounds [1](#0-0) . `median_fee` iterates over every non-coinbase transaction in that one block, computes each transaction's implied sat/vbyte rate as `(in_value - out_value) / tx.vsize()`, sorts the rates, and returns the middle element [2](#0-1) . The only sanity bound applied is a *floor* of 1 sat/vbyte (`fee.max(1)`); there is no upper bound [3](#0-2) .

The returned `fee.0` is passed as `fee_per_vbyte` to `BSignableTransaction::new` [4](#0-3) , which sets `needed_fee = fee_per_vbyte * vbytes` and treats the entire `input_sat - payment_sat - needed_fee` remainder as fee when there is no change output, or reduces the change output accordingly [5](#0-4) . Separately, in `prepare_send` the estimated `tx_fee` is *amortized across user payments*: `payment.balance.amount.0 -= subtractable` directly reduces the amounts recipients receive, and payments pushed below dust are dropped entirely [6](#0-5) .

An attacker can bias the median upward by ensuring more than half of the transactions in the sampled block carry an inflated fee rate. This requires only the ability to broadcast transactions that get mined — an unprivileged, public-input capability — and is cheap in low-activity periods, or free if the attacker mines a block. When Serai's transaction is mined into a block the attacker influenced (or that the attacker mined), the fee the attacker paid to skew the median is partially or fully recouped, since the inflated Serai fee goes to the block's miner.

This mirrors the reported bug class exactly: a security-critical bound (slippage tolerance / acceptable fee) is derived entirely from an externally influenced value (oracle price / on-chain median fee) with no margin check against an independent reference, and the deviation is systematically exploitable.

### Impact Explanation
Every sat/vbyte of artificial inflation is multiplied by the transaction's vsize and paid to miners from the multisig's inputs. Concretely:
- With a change output, the multisig's treasury directly loses `inflated_fee` satoshis per transaction [7](#0-6) .
- Without change (or during amortization), user payments are reduced by the inflated fee, so recipients are underpaid and payments can be silently dropped to zero via the dust filter [8](#0-7) .
- An attacker who mines the sampled block recaptures both their own padding fees and the inflated Serai fee, making the attack near-costless and repeatable across every outgoing Bitcoin transaction the processors sign.

Because the multisig signs whatever `SignableTransaction` is produced — committing to the inflated fee via `taproot_key_spend_signature_hash` with `Prevouts::All` [9](#0-8)  — this is concrete signing of a transaction whose economic parameters deviate from intent, not merely a liveness issue.

### Likelihood Explanation
Median-of-one-block is trivially manipulable: in a block with few transactions an attacker needs only a handful of self-funded high-fee transactions to control the median. The cost scales with the number of padding transactions and their sizes, not with the amount of damage inflicted — even one manipulated sampled block produces an inflated fee for the transaction built from it. The code's own `TODO` acknowledges the single-block sample is a stopgap [10](#0-9) .

### Recommendation
Mirror the report's suggested fix pattern — accept an externally supplied fee bound but validate it — concretely:
1. Derive the fee rate from a longer window (e.g., median over the last N blocks) or from `estimatesmartfee`/mempool data rather than a single block's contents, and upper-bound it with a configured maximum (`fee.min(MAX_FEE_RATE)`), dropping the plan if the estimate exceeds it rather than signing an unbounded fee.
2. Ensure `needed_fee` (used for amortization in `prepare_send`) and `signable_transaction` use the *same* sampled fee, so the amount amortized from payments always equals the fee the signed transaction actually commits to.

### Proof of Concept
1. Attacker observes (or anticipates) the block height the processor will pass as `block_number` to `make_signable_transaction` — e.g., by triggering a burn/payment and watching which block the processor samples.
2. Attacker broadcasts enough self-to-self transactions paying, say, 500 sat/vbyte so that they constitute a majority of `block.txdata[1 ..]` in that block. `median_fee` then returns ≥500 sat/vbyte [11](#0-10) .
3. `prepare_send` amortizes `tx_fee = 500 * vbytes` across the plan's payments; for a ~200-vbyte transaction that is ~100,000 sat extracted, and any payment pushed under `DUST = 10_000` is zeroed [6](#0-5) [12](#0-11) .
4. The multisig signs the resulting transaction; the inflated fee is paid to miners (potentially the attacker), and recipients receive less than their intended amounts — a direct, unprivileged-party-reachable loss of multisig funds caused by trusting a manipulable derived parameter as the sole bound.

    let mut fees = vec![];
    if block.txdata.len() > 1 {
      for tx in &block.txdata[1 ..] {
        let mut in_value = 0;
        for input in &tx.input {
          let mut input_tx = input.previous_output.txid.to_raw_hash().to_byte_array();
          input_tx.reverse();
          in_value += self
            .rpc
            .get_transaction(&input_tx)
            .await
            .map_err(|_| NetworkError::ConnectionError)?
            .output[usize::try_from(input.previous_output.vout).unwrap()]
          .value
          .to_sat();
        }
        let out = tx.output.iter().map(|output| output.value.to_sat()).sum::<u64>();
        fees.push((in_value - out) / u64::try_from(tx.vsize()).unwrap());
      }
    }
    fees.sort();
    let fee = fees.get(fees.len() / 2).copied().unwrap_or(0);
