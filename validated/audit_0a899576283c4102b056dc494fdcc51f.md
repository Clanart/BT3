### Title
Deep link `openRepo?pr=N` silently adds an attacker-controlled remote and checks out an attacker-controlled branch - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
Any unprivileged user can open a pull request from a fork they control against a public repository, then craft a `x-github-client://openRepo/<repoURL>?pr=<N>` deep link. When a victim who has that repository cloned in Desktop clicks the link, Desktop resolves the PR via the GitHub API and unconditionally uses attacker-controlled fields from the PR object (`head.repo.clone_url`, `head.repo.owner.login`, `head.ref`) to add a new git remote and fetch + checkout that ref into the victim's existing local repository, without any confirmation dialog naming the remote/URL being added.

### Finding Description
`parseAppURL` accepts a `pr` query parameter on the `openRepo` action and validates only that it's numeric and that `branch` (if present) matches `pr/\d+` [1](#0-0) . `dispatchURLAction` routes this to `openRepositoryFromUrl`, which calls `openPullRequestFromUrl(url, pr)` [2](#0-1) .

`openPullRequestFromUrl` fetches the PR object from the GitHub API and, if the target repository is already open in Desktop (a very common case — the victim already has the target repo cloned), immediately calls `_checkoutPullRequest` with `pullRequest.head.repo.owner.login`, `pullRequest.head.repo.clone_url`, and `pullRequest.head.ref` taken straight from the API response [3](#0-2) . These three fields are fully attacker-controlled: anyone can open a PR from their own fork with an arbitrary branch name against any public repository, which sets `head.repo` to their fork and `head.ref` to their branch.

`_findPullRequestBranch` then takes these values and, if no existing remote matches the URL, calls `addRemote(repository, forkRemoteName, headCloneUrl)` and fetches it, then checks out `pr/{prNumber}` tracking the attacker's ref — all without prompting the user or validating that `headCloneUrl`'s host is a known/trusted GitHub host [4](#0-3) .

This mirrors the TempusController pattern: a function trusts an externally-controlled object (there, an attacker-supplied AMM contract; here, an attacker-authored PR's `head` object returned by the API) to determine which resource gets pulled into/manipulated within the victim's trusted context (there, token transfers out of the controller; here, a new remote fetched and checked out into the victim's working repository) — with no independent verification that the supplied values originate from a trusted source.

### Impact Explanation
Silent checkout of attacker-controlled content into an existing, trusted local repository can corrupt what the user later builds, commits, or pushes, since the working tree now reflects the attacker's fork branch instead of the branch the user expects. Combined with any build/CI tooling that runs on checkout (pre-commit hooks, npm scripts, `.vscode` tasks, etc. shipped in the attacker's branch), this can lead to local code execution if the victim runs the checked-out project. This satisfies the "silent corruption of what the user commits/pushes" and potential "code execution" categories in the requested severity criteria.

### Likelihood Explanation
No local access, admin rights, or prior compromise is required — only that the victim has GitHub Desktop with a matching repository already open and clicks a link (e.g., embedded in a webpage, README, or issue comment) pointing to `x-github-client://openRepo/<public-repo-url>?pr=<attacker-PR-number>`. The PR itself is trivially creatable by any GitHub user against any public repository. The only gating factor is that the app must currently be handling this custom protocol and the victim must already have the target repository added in Desktop — both realistic conditions for active contributors, which is the primary audience for such deep links in the first place.

### Recommendation
Before adding a remote and checking out a PR ref reached via `openRepositoryFromUrl`, show an explicit confirmation dialog naming the fork owner/URL and branch to be added and checked out, mirroring the confirmation already shown elsewhere (e.g. `IExistingAccountWarning`) for other trust-boundary-crossing actions. Additionally, validate that `head.repo.clone_url`'s host belongs to the same GitHub host as the account/endpoint used to fetch the PR before invoking `addRemote`/`_fetchRemote` automatically.

### Proof of Concept
1. Attacker forks `victim-org/target-repo` on GitHub, pushes a branch `evil` containing a malicious `package.json`/hook script, and opens a PR from `attacker/target-repo:evil` against `victim-org/target-repo`.
2. Attacker crafts and distributes the link: `x-github-client://openRepo/https://github.com/victim-org/target-repo?pr=<PR_NUMBER>`.
3. Victim, who already has `victim-org/target-repo` cloned in GitHub Desktop, clicks the link.
4. Desktop's `handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openPullRequestFromUrl` fetches the PR via `appStore.fetchPullRequest` [5](#0-4)  and calls `_checkoutPullRequest` with the attacker's fork URL and branch [6](#0-5) .
5. `_findPullRequestBranch` silently adds remote `github-desktop-attacker` pointing at the attacker's fork, fetches it, and checks out `pr/<PR_NUMBER>` into the victim's existing local repository without confirmation [7](#0-6) .

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
