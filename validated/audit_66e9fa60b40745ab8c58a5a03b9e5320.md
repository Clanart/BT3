### Title
Unbounded buffer read in mempool CLVM-canonical-form check causes unhandled crash on submitted spend bundles - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` parses the length-prefix of a CLVM atom by indexing into the caller-supplied byte buffer without ever checking the buffer length against the number of prefix bytes it expects to read. It is invoked directly on the raw, attacker-controlled `puzzle_reveal` and `solution` bytes of every coin spend in a submitted `SpendBundle` before any other validation, with no bounds checking and no exception handling around the call.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine how many additional length-prefix bytes to consume (`prefix_len`, up to 5), then loops that many times, each time doing `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset < len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical()` calls this helper for any atom whose leading byte is `> 0x80`, again with no length checks before dereferencing: [2](#0-1) 

This is invoked directly on unvalidated, attacker-supplied bytes at the very start of `MempoolManager.validate_spend_bundle()`, which is the first per-coin-spend processing step for every spend bundle submitted by any peer/wallet, with no try/except guarding it: [3](#0-2) 

A `puzzle_reveal` or `solution` whose trailing bytes form a truncated multi-byte atom length prefix (e.g. a buffer ending exactly at a byte matching the `0b11111000` pattern, which declares 4 more prefix bytes follow) makes `is_atom_canonical` index past the end of the buffer, raising an unhandled `IndexError`. Nothing in `validate_spend_bundle()`/`add_spend_bundle()` catches this exception — the only nearby `except ValueError` block in this file guards the separate `validate_clvm_and_signature` Rust call, not this canonical-form check.

This mirrors the CVE-2016-5238 bug class: parsing an untrusted, length-prefixed buffer and reading past its bounds because the parser trusts the encoded length field without validating it against the actual buffer size.

### Impact Explanation
An unhandled exception raised while processing a submitted spend bundle in the mempool-admission path can abort the in-progress mempool add/validate operation for that transaction outside of the expected `Err`-based control flow used everywhere else in this function. Because the exception is not converted into a normal `MempoolInclusionStatus.FAILED` result (unlike every legitimate rejection path, which returns `Err.*` tuples), it escapes the function's designed error-handling contract. Depending on how the calling task/lock context handles this (not confirmed further up the stack), this can manifest as a crashed processing task for that peer connection or, in the worst case, disruption of mempool processing for subsequent transactions — i.e., a spend-triggered transaction-processing halt, consistent with what this scan accepts as impact.

### Likelihood Explanation
Trivially reachable: any unprivileged party that can submit a spend bundle to the mempool (wallet RPC caller, peer relaying a transaction, or an offer/transaction submitted through normal channels) fully controls the raw bytes of `puzzle_reveal` and `solution` on the `CoinSpend`, which are passed unmodified into `is_clvm_canonical()`. No signature or execution success is required to reach this code — the canonical-form check runs before puzzle execution results are otherwise used. Constructing the crafted trailing bytes requires no chialisp/CLVM knowledge, only appending a byte with a specific high-bit pattern near the end of the reveal/solution buffer.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before every `clvm_buffer[offset]` access (raise/return a definite non-canonical result instead of indexing out of range), and wrap the `is_clvm_canonical()` calls in `validate_spend_bundle()` in a try/except that maps any parsing exception to `Err.INVALID_COIN_SOLUTION` (or equivalent), matching the function's existing `Err`-based contract instead of letting exceptions propagate.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xF8 declares a 4-byte length prefix must follow ( (b & 0b11111100) == 0b11111000 ),
# but the buffer ends immediately after this byte.
malicious_buffer = bytes.fromhex("f8")

is_clvm_canonical(malicious_buffer)  # raises IndexError: index out of range
```
Embedding `malicious_buffer` (or a longer reveal/solution whose final bytes match this truncated-prefix pattern) as a `CoinSpend.puzzle_reveal` or `CoinSpend.solution` and submitting the resulting `SpendBundle` drives execution into `MempoolManager.validate_spend_bundle()` at [4](#0-3) , triggering the unhandled `IndexError` inside `is_atom_canonical`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
