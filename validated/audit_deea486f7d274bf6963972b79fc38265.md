### Title
Out-of-bounds panic (DoS) in auction bid signature recovery due to unvalidated signature length - (File: kaiax/auction/bid.go)

### Summary
`getSigner()` in the `kaiax/auction` module indexes into an attacker-supplied byte slice (`BidData.SearcherSig` / `BidData.AuctioneerSig`) at fixed offsets before validating its length, exactly mirroring the ImageMagick bug class: an unvalidated/unrecognized input value is used to index a buffer without a bounds check, causing an out-of-bounds access.

### Finding Description
`Bid.ValidateSearcherSig` and `Bid.ValidateAuctioneerSig` both call the shared helper `getSigner(sig, digest)`: [1](#0-0) 

```go

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	...
``` [2](#0-1) 

`sig` here is `b.SearcherSig` or `b.AuctioneerSig`, both raw `[]byte` fields of `BidData` that are populated directly from an externally-submitted, RLP/JSON-decoded auction bid: [3](#0-2) 

There is no length check on `sig` before `copiedSig[crypto.RecoveryIDOffset]` (offset 64) and `copiedSig[0:32]` / `copiedSig[32:64]` are accessed. `crypto.SignatureLength`/`RecoveryIDOffset` validation only happens later, inside `crypto.SigToPub` → `sigToPub`: [4](#0-3) 

but that check is reached only *after* `getSigner` has already indexed the slice unconditionally. If an unprivileged auction bidder (searcher) submits a `Bid` whose `SearcherSig` (or a malicious/compromised auctioneer submits an `AuctioneerSig`) is shorter than 65 bytes — e.g., empty, 1 byte, or 63 bytes — the slice indexing/slicing (`copiedSig[64]`, `copiedSig[0:32]`, `copiedSig[32:64]`) panics with "index out of range" / "slice bounds out of range" in Go, since a byte slice is not padded like a fixed C buffer. This is structurally identical to the ImageMagick root cause: an out-of-range/unrecognized value that should have been validated first is instead used directly to access memory.

### Impact Explanation
A panic triggered from an RPC-submitted or gossiped auction bid, if not recovered by an outer handler, crashes the goroutine processing bids (auction bid pool / bid validation path) on every node that processes the malformed bid. Because bids are attacker-controlled and processed by the auction pricing/matching pipeline used to build blocks, this can be used to reliably crash or destabilize block producers' auction handling, denying legitimate searchers' bids from being processed (denial of service against the auction/gasless settlement mechanism). Depending on whether validation happens uniformly on all nodes or only on some, this could also cause processing divergence between nodes (some crash/reject, others don't), which is a state-consistency risk for the auction settlement path.

### Likelihood Explanation
High: any unprivileged searcher can submit a `Bid` with a truncated `SearcherSig`/`AuctioneerSig` through the standard bid submission mechanism at essentially zero cost — this requires no special privileges, staking, or governance capability, only crafting a malformed signature field, which is trivial to construct.

### Recommendation
In `getSigner()` (`kaiax/auction/bid.go`), validate `len(sig) == crypto.SignatureLength` (65 bytes) before performing any indexing or slicing, returning `ErrInvalidSignature` (or similar) immediately if the length check fails, mirroring the existing check already present (but too late) in `crypto/signature_nocgo.go`'s `sigToPub`. Apply the same length validation to both `SearcherSig` and `AuctioneerSig` at the earliest point they are accepted (e.g., in `BidData` decoding/ingestion) so malformed bids are rejected before reaching signature-recovery code paths.

func main() {
	bid := &auction.Bid{
		BidData: auction.BidData{
			Sender:      common.HexToAddress("0x1"),
			SearcherSig: []byte{0x01, 0x02, 0x03}, // malformed: far shorter than 65 bytes
		},
	}
	// panics: slice bounds out of range [:32] with capacity 3
	err := bid.ValidateSearcherSig(big.NewInt(1), common.HexToAddress("0x2"), "1")
	fmt.Println(err)

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

func sigToPub(hash, sig []byte) (*secp256k1.PublicKey, error) {
	if len(sig) != SignatureLength {
		return nil, errors.New("invalid signature")
	}
	if len(hash) != DigestLength {
		return nil, fmt.Errorf("hash is required to be exactly %d bytes (%d)", DigestLength, len(hash))
	}
	// Enforce canonical Ethereum recovery id v ∈ {0, 1}.
	if sig[RecoveryIDOffset] >= 2 {
		return nil, errors.New("invalid signature recovery id")
	}
