### Title
ANSI/control-byte injection into JSON parse error `absl::Status` messages via unescaped attacker-controlled JSON tokens - ([File: src/google/protobuf/json/internal/lexer.cc])

### Summary
Git's CVE-2024-50349 fails because a URL is percent-decoded and then the raw, decoded bytes (potentially including ANSI escape sequences) are printed verbatim to the user's terminal, letting an attacker spoof what the user sees. Protobuf's JSON parser (`google::protobuf::json_internal`) has the same class of failure: when `JsonLexer`/`JsonLocation::Invalid()` builds the `absl::Status` returned by the public JSON-parsing API, several call sites interpolate the raw, already-Unicode-decoded attacker-controlled token text directly into the error message with no escaping/sanitization of control bytes. If the consuming application logs or prints that status message to a terminal, an attacker who fully controls the input JSON can embed ANSI/C0 control sequences (via `\u001b`-style JSON escapes, decoded to raw ESC bytes by `ParseUtf8`) that get echoed byte-for-byte into the diagnostic text.

### Finding Description
`JsonLocation::Invalid()` builds the returned status by hardening only against machine-parsing ("Hyrum's Law"), not against terminal-control-byte injection: [1](#0-0) 

This hardening function only randomly inserts extra ASCII spaces; it copies every other byte, including non-printable control bytes, verbatim: [2](#0-1) 

The `message` argument to `Invalid()` frequently embeds the raw attacker-supplied token content that has already been through Unicode-escape decoding (so `\u001b` becomes a literal ESC byte 0x1B), analogous to git's URL percent-decoding before printing. Concrete sites where attacker-controlled string content flows unescaped into the final status message:
- Invalid numeric string for an int/uint/float field: [3](#0-2) 
- Invalid boolean map key string: [4](#0-3) 
- Invalid raw number text: [5](#0-4) 

Because `ParseUtf8`/unicode-escape handling (`JsonLexer::ParseUnicodeEscape`) decodes `\uXXXX` sequences into raw UTF-8 bytes before these strings are placed into error text, an attacker fully controls the raw bytes that end up in the `absl::Status` message, including ESC (0x1B) and CSI sequences. This is the direct analog of git decoding a percent-encoded hostname before printing it un-sanitized to the terminal.

### Impact Explanation
The impact is display/terminal spoofing of diagnostic output, not memory corruption or code execution — matching the git CVE's own bounded impact (`C:N/I:L/A:N`, `UI:R`). A consuming application that calls the public JSON parsing API (e.g., `google::protobuf::json_internal`'s message-parsing entry points, exposed via `google::protobuf::util::JsonStringToMessage`) and then logs or `printf`s the returned `absl::Status::message()` to a terminal/console (a very common pattern for parse-failure diagnostics) can have its terminal manipulated: cursor repositioning, screen clearing, color changes, or crafted text that mimics trusted prompts/log lines, potentially confusing an operator inspecting logs interactively. This requires (a) attacker control of the JSON payload sent to a public parse API, and (b) the consuming application displaying the raw error text on an ANSI-interpreting terminal — an assumption explicit in the report itself and consistent with the "consuming-application exposure" caveat.

### Likelihood Explanation
Likelihood is Medium: reaching these code paths only requires sending malformed JSON (e.g., a non-boolean string as a map key of bool type, or a non-numeric string for an int/float field) with `\uXXXX`-escaped control bytes — no privileged access or special schema needed, just a bounded, well-formed-enough JSON payload through the standard public JSON parse API. The main precondition outside Protobuf's control is that the calling application prints/logs the status message to an ANSI-capable terminal, which is a common but not universal practice (many applications box the raw status in structured logs, HTTP responses, or files where no terminal renders escape codes).

### Recommendation
Sanitize/escape non-printable and control bytes (in particular ESC, 0x00–0x1F, and 0x7F) out of any attacker-controlled substring before interpolating it into `absl::Status` messages produced by `JsonLocation::Invalid()` and its callers in `parser.cc`/`lexer.cc` (e.g., render them as C-escaped literals such as `\x1b` the way `TextFormat::Printer::HardenedPrintString` already does for `DebugString()` output). This preserves human-readable diagnostics and "grep-ability" while eliminating raw control-byte pass-through.

### Proof of Concept
Send the following JSON to a public JSON-parsing entry point (e.g., `google::protobuf::util::JsonStringToMessage`) against a message with an `int32` field `foo`:
```json
{"foo": "\u001b[31mFAKE-ERROR\u001b[0m"}
```
`ParseUtf8` decodes `\u001b` to raw ESC (0x1B) bytes, `SimpleAtoi` fails, `ParseFloatStringAsInt` is reached, and `x.loc.Invalid(absl::StrFormat("invalid number: '%s'", x.value.AsView()))` is called with the attacker string containing raw ESC bytes: [3](#0-2) 
The resulting `absl::Status` message returned to the caller contains the literal ESC control bytes verbatim (only interspersed with occasional extra spaces from `HardenAgainstHyrumsLaw`), which will be interpreted by an ANSI-capable terminal if the caller logs/prints `status.message()`. I was not able to execute this in a sandbox to capture the literal terminal rendering (no build/run tool available in this session); the trace above is a static, code-level reproduction path through the cited functions and should be confirmed by a background agent with build/test access.

void HardenAgainstHyrumsLaw(absl::string_view to_obfuscate, std::string& out) {
  // Get some simple randomness from ASLR, which is enabled in most
  // environments. Our goal is to be annoying, not secure.
  static const void* const kAslrSeed = &kAslrSeed;
  // Per-call randomness from a relaxed atomic.
  static std::atomic<uintptr_t> kCounterSeed{0};

  constexpr uint64_t kA = 0x5851f42d4c957f2dull;
  constexpr uint64_t kB = 0x14057b7ef767814full;

  uint64_t state = absl::bit_cast<uintptr_t>(kAslrSeed) + kB +
                   kCounterSeed.fetch_add(1, std::memory_order_relaxed);
  auto rng = [&state, &kA, &kB] {
    state = state * kA + kB;
    return absl::rotr(static_cast<uint32_t>(((state >> 18) ^ state) >> 27),
                      state >> 59);
  };
  (void)rng();  // Advance state once.

  out.reserve(to_obfuscate.size() + absl::c_count(to_obfuscate, ' '));
  for (char c : to_obfuscate) {
    out.push_back(c);
    if (c != ' ' || rng() % 3 != 0) {
      continue;
    }

    size_t count = rng() % 2 + 1;
    for (size_t i = 0; i < count; ++i) {
      out.push_back(' ');
    }
  }
}

absl::Status JsonLocation::Invalid(absl::string_view message,
                                   SourceLocation sl) const {
  // NOTE: we intentionally do not harden the "invalid JSON" part, so that
  // people have a hope of grepping for it in logs. That part is easy to
  // commit to, as stability goes.
  //
  // This copies the error twice. Because this is the "unhappy" path, this
  // function is cold and can afford the waste.
  std::string status_message = "invalid JSON";
  std::string to_obfuscate;
  if (path != nullptr) {
    absl::StrAppend(&to_obfuscate, " in ");
    path->Describe(to_obfuscate);
    to_obfuscate.push_back(',');
  }
  absl::StrAppendFormat(&to_obfuscate, " near %zu:%zu (offset %zu): %s",
                        line + 1, col + 1, offset, message);
  HardenAgainstHyrumsLaw(to_obfuscate, status_message);

  return absl::InvalidArgumentError(std::move(status_message));
}

static absl::Status ParseFloatStringAsInt(
    const LocationWith<MaybeOwnedString>& x, T* out, double lo, double hi) {
  double d;
  if (!absl::SimpleAtod(x.value.AsView(), &d) || !std::isfinite(d)) {
    return x.loc.Invalid(
        absl::StrFormat("invalid number: '%s'", x.value.AsView()));
  }

  // Conversion overflow here would be UB.
  if (lo > d || d > hi) {
    return x.loc.Invalid("JSON number out of range for int");
  }
  *out = static_cast<T>(d);
  if (d - static_cast<double>(*out) != 0) {
    return x.loc.Invalid(
        "expected integer, but JSON number had fractional part");
  }

  return absl::OkStatus();
