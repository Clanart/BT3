### Title
Governance-settable `KIP71.GasTarget` can be set to zero, causing a division-by-zero panic in Magma base-fee calculation - (File: `params/kip71_config.go`)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` in `params/kip71_config.go` divides by the governance-configurable `GasTarget` parameter without checking that it is non-zero, unlike `BaseFeeDenominator`, which has an explicit zero-guard. The governance parameter definition for `Kip71GasTarget` in `kaiax/gov/param.go` uses `noopFormatChecker`, which accepts any `uint64` value including `0`. A governance vote (or `GovParamContract` update, depending on governance mode) setting `GasTarget` to `0` will pass validation and, once activated, cause every node computing or verifying the next block's base fee to hit a Go runtime panic on `big.Int.Div`.

### Finding Description
`NextMagmaBlockBaseFee` computes the base fee delta using `GasTarget` as a divisor in two branches: [1](#0-0) [2](#0-1) 

Both `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` calls will panic if `gasTarget == 0`, since Go's `big.Int.Div` panics on division by zero (unlike Solidity `require`, this is an unrecoverable runtime panic, not a revert). Notably, the function does guard `BaseFeeDenominator` against zero by substituting a fallback value of `64`: [3](#0-2) 
but performs no equivalent guard for `GasTarget`.

The `Kip71GasTarget` governance parameter's format checker permits any value, including zero: [4](#0-3) [5](#0-4) 

This `FormatChecker` is the gate used to validate governance votes before they are accepted into header-based governance state, as referenced in `kaiax/gov/headergov/vote.go`. Because `noopFormatChecker` always returns `true`, a vote proposing `GasTarget = 0` is accepted as syntactically valid and, if it gathers sufficient governance support (or is written via `GovParamContract` in contract-governance mode), becomes part of the active `ChainConfig`, propagated to `params.KIP71Config` used by `NextMagmaBlockBaseFee`.

### Impact Explanation
Once `GasTarget` is set to `0` and takes effect at the corresponding block, **every node** in the network computing the next block's base fee (block proposers building blocks and all other nodes verifying `VerifyMagmaHeader`) will panic when `parentGasUsed != gasTarget` (i.e., `0 != anyGasUsed`, true for essentially every block). This constitutes a network-wide chain halt / consensus-critical denial-of-service: honest nodes crash instead of reaching agreement, since the crash is deterministic and reproducible on all nodes processing the same block. This is a high-impact chain-halting bug that maps to the reported bug class "unsafe division without a zero-divisor check."

### Likelihood Explanation
Reaching this bug requires a valid governance parameter change to `kip71.gastarget = 0` to be enacted (via the governance voting mechanism reachable by governing node(s) or governance contract in contract-mode). No format-level validation blocks the zero value, so the vulnerability is only bounded by whatever governance/voting privilege model is in place; the code itself provides no defense-in-depth against a misconfigured or malicious governance actor, and the analogous denominator field is protected while this one is not, indicating this omission is an oversight rather than intentional design.

### Recommendation
Add a zero-guard for `GasTarget` in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator` fallback (e.g., reject/clamp to a safe minimum such as `1` before use as divisor), and/or add a proper `FormatChecker` for `Kip71GasTarget` (and `Kip71MaxBlockGasUsedForBaseFee`, which is also protected by `noopFormatChecker`) in `kaiax/gov/param.go` that rejects `0`.

### Proof of Concept
1. Submit/accept a governance vote (or governance-contract parameter update) setting `kip71.gastarget` to `0`; `Kip71GasTarget`'s `FormatChecker` (`noopFormatChecker`) accepts it unconditionally: [4](#0-3) 
2. Once the parameter activates at a subsequent epoch/block, every node computing the header for the next block calls `KIP71Config.NextMagmaBlockBaseFee` with `kc.GasTarget == 0`.
3. Because `parentGasUsed` (any real usage) will not equal `0`, execution enters the `parentGasUsed > gasTarget` branch (line 92) or the `else` branch (line 110) and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor: [6](#0-5) 
4. `big.Int.Div` panics with "division by zero," crashing the node process — reproducible identically on every node in the network, halting block production/verification network-wide.
