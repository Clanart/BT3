### Title
Unbounded bech32m offer-string length allows large memory allocation before validation - ([File: chia/util/bech32m.py])

### Summary
`chia.util.bech32m.bech32_decode()` enforces a `max_length` bound on the encoded string (BIP-173/350 specify 90 characters), but `Offer.from_bech32()` in `chia/wallet/trading/offer.py` calls it with `max_length=len(offer_bech32)`, i.e. no real bound at all. Any attacker-supplied offer string/file handed to a wallet (via `chia wallet take_offer`, the `take_offer`/`get_offer_summary` RPCs, or `TakeOffer.parsed_offer`) is fully decoded and base-32→base-8 converted before any size, checksum-context, or CLVM-cost limiting is applied. This mirrors the Pillow BLP bug pattern: the "container" (bech32m string) carries an attacker-chosen size that is trusted and used to drive allocation/parsing work with no upper bound.

### Finding Description
`bech32_decode()` is the generic bech32/bech32m decoder used across the wallet address/offer code: [1](#0-0) 

The default `max_length=90` is the standard bech32 safety bound. However, `Offer.from_bech32()` deliberately overrides it to the full length of the attacker-supplied string: [2](#0-1) 

Because `pos + 7 > len(bech) or len(bech) > max_length` is the only length gate and `max_length` is set to `len(bech)` itself, this check can never reject on length. The function then builds `data = [CHARSET.find(x) for x in bech[pos + 1:]]` (`chia/util/bech32m.py:85`) over the entire attacker string, and the caller subsequently runs `convertbits(list(data), 5, 8, False)` (`chia/wallet/trading/offer.py:702`), which iterates the whole list and materializes a full output byte list before any checksum, decompression-size, or CLVM cost checks occur. Both `bech32_decode`'s `data` construction and `convertbits`'s `ret` list scale linearly with attacker-controlled input length, with no cap analogous to `max_delta_file_size` in Data Layer or the 6 MiB cap enforced only after decompression in `decompress_object_with_puzzles` (`chia/_tests/clvm/test_puzzle_compression.py:63-69` shows decompression is capped, but that cap applies after this unbounded decode/convert step, not before it).

This is reachable purely from an unprivileged wallet user or RPC caller: `TakeOffer.parsed_offer` (`chia/wallet/wallet_request_types.py:2304-2312`) and `chia/cmds/wallet_funcs.py:828` (`Offer.from_bech32(offer_hex)`) call this path directly on user/file-supplied text before any signature/spend-bundle validation, cost accounting, or peer trust checks apply — unlike mempool/CLVM parsing, which is bounded by `MAX_BLOCK_COST_CLVM` and atom-size canonicalization (`chia/full_node/mempool_manager.py:144-182`, `.cursor/context/clvm-execution.md:75-93`).

### Impact Explanation
An attacker can craft an arbitrarily long, syntactically-valid-looking (or even invalid but long) "offer" string/file and get a wallet user or automation script to run `take_offer`, `get_offer_summary`, or open the file through `chia wallet take_offer <file>`. The decode/convert step allocates memory proportional to the attacker-chosen string length, with no server-side or client-side length cap prior to that work — a memory-consumption denial-of-service against the local wallet/RPC process (and, transitively, any automated service that processes untrusted offer text, e.g. marketplaces or bots that pass offers straight to `take_offer`). This does not create unauthorized coin movement, forged assets, or invalid consensus state; it is a resource-exhaustion condition triggered by a single spend/offer-processing action, consistent with the reachable/allowed impact classes (spend-triggered transaction-processing halt).

### Likelihood Explanation
High likelihood of triggerability: no authentication beyond normal RPC/CLI access is required, and offer strings/files are explicitly designed to be shared with and processed by third parties (that's the entire point of the offer file format). Any wallet or bot that accepts externally supplied offer text for `take_offer`/`get_offer_summary` is exposed without any additional attacker capability.

### Recommendation
Restore a real length cap in `Offer.from_bech32()` (e.g., use the library default `max_length=90` extended only to a bounded, explicitly-chosen maximum sized to the largest legitimate compressed offer, not `len(offer_bech32)`), and/or add an early length check in `Offer.from_bech32`/`bech32_decode` callers before performing `convertbits`/decompression work, so decode cost is bounded independent of attacker input size.

### Proof of Concept
1. Generate a very large string, e.g. `"offer1" + "q" * 50_000_000` (or any string ending with a valid bech32m checksum tail to pass `bech32_verify_checksum`, or simply a huge string to exercise the pre-checksum list-building cost).
2. Call `chia wallet take_offer <hugefile>` or the wallet RPC `take_offer`/`get_offer_summary` endpoint with this string as `offer`.
3. Observe `Offer.from_bech32()` → `bech32_decode(offer_bech32, max_length=len(offer_bech32))` building a Python list over tens of millions of characters, then `convertbits()` building another full-size list, before any checksum/decompression/cost validation rejects the value — all driven purely by the attacker-chosen string length.

```python
def bech32_decode(bech: str, max_length: int = 90) -> tuple[str | None, list[int] | None]:
    """Validate a Bech32 string, and determine HRP and data."""
    bech = bech.strip()
    if (any(ord(x) < 33 or ord(x) > 126 for x in bech)) or (bech.lower() != bech and bech.upper() != bech):
        return (None, None)
    bech = bech.lower()
    pos = bech.rfind("1")
    if pos < 1 or pos + 7 > len(bech) or len(bech) > max_length:
        return (None, None)
    if not all(x in CHARSET for x in bech[pos + 1 :]):
        return (None, None)
    hrp = bech[:pos]
    data = [CHARSET.find(x) for x in bech[pos + 1 :]]
    if not bech32_verify_checksum(hrp, data):
        return (None, None)
    return hrp, data[:-6]
```

```python
    @classmethod
    def from_bech32(cls, offer_bech32: str) -> Offer:
        _hrpgot, data = bech32_decode(offer_bech32, max_length=len(offer_bech32))
        if data is None:
            raise ValueError("Invalid Offer")
        decoded = convertbits(list(data), 5, 8, False)
        decoded_bytes = bytes(decoded)
        return cls.try_offer_decompression(decoded_bytes)
```
