## Confirmed: `getEndpointKind` trusts an unverified `WWW-Authenticate` header to trigger a GitHub sign-in prompt

### Title
Spoofable `WWW-Authenticate` realm value causes Desktop to prompt for GitHub/Enterprise OAuth sign-in against an attacker-chosen endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
Desktop's git credential helper classifies a remote endpoint as `'enterprise'` (i.e., "this is a GitHub host") based on an unauthenticated, attacker-controlled HTTP response header (`WWW-Authenticate: realm="GitHub"`) that git forwards into the credential helper input. This classification is used *without any further verification* to decide whether to launch the GitHub Enterprise sign-in/OAuth flow bound to the attacker's URL, bypassing the only real verification mechanism (`isGitHubHost`, which performs an actual `/meta`-style capability check) that exists later in the same function for the non-spoofed path.

### Finding Description
`getEndpointKind` determines how a git credential request should be handled: as GitHub.com, GitHub Enterprise ("enterprise"), or "generic" (used for arbitrary/self-hosted git servers, GitLab, Bitbucket, etc.): [1](#0-0) 

The `wwwauth[...]` credential fields originate directly from `WWW-Authenticate` HTTP headers returned by the remote git server (per git's http credential protocol, when git receives a `401` it forwards those headers to the credential helper as `wwwauth[N]=<header value>`). This mechanism is designed for git's own credential-helper convention, but Desktop uses the raw, attacker-suppliable header value as the sole check to decide `'enterprise'` classification when it contains `realm="GitHub"`:

```js
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
``` [2](#0-1) 

Unlike the fallback path a few lines below, which actually queries the endpoint to confirm it behaves like a GitHub host (`return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'`), the header-based shortcut performs **no verification at all** — any HTTP(S) server the user adds as a remote, or any man-in-the-middle/malicious proxy sitting on the path to a legitimate remote, can simply respond with `WWW-Authenticate: realm="GitHub"` on a 401 and be unconditionally classified as an "enterprise" (GitHub-like) endpoint.

That classification then flows into `getCredential`: [3](#0-2) 

If the endpoint is classified as non-`'generic'` and the user has no existing account bound to that host, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — for any non-`github.com` hostname — invokes `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)`, opening the full OAuth/browser sign-in flow scoped to the attacker-controlled `origin`: [4](#0-3) 

### Impact Explanation
This matches "unauthorized OAuth or account binding" triggered purely by a remote/proxy response the attacker controls, with no prior user consent step distinguishing a legitimate GHE server from a spoofing one. A user cloning/fetching from (or being MITM'd/proxied to) a malicious host that mimics this header gets an unexpected GitHub Enterprise sign-in dialog pinned to the attacker's URL. Because the sign-in flow subsequently performs OAuth device/browser authentication against that attacker-supplied endpoint URL, and any account the user completes sign-in with becomes bound to that endpoint in Desktop's account store (used later to auto-fill credentials for that same host on subsequent git operations), this can be used to social-engineer credential capture through a familiar, apparently-legitimate GitHub Enterprise dialog, or to seed a spoofed account binding that Desktop will trust for future operations against that host.

### Likelihood Explanation
Likelihood is moderate: it requires the user to interact with a repository whose remote (or an intercepting proxy) is attacker-controlled and returns a 401 with a crafted `WWW-Authenticate` header during a git network operation (fetch/pull/push/clone). This is a realistic scenario for "clone a malicious/compromised repo URL" or "corporate/public proxy MITM" threat models, and requires no local access, no admin rights, and no prior credential compromise — only a normal git network exchange that Desktop already performs transparently via the trampoline credential helper.

### Recommendation
Do not trust the `wwwauth[...]`/`realm=` value as sufficient evidence of a GitHub/Enterprise endpoint. Treat header-based hints as, at most, a prioritization signal, and require the same live verification (`isGitHubHost(endpoint)`) used in the non-header path before offering the GitHub sign-in flow, or otherwise clearly disclose to the user that the sign-in prompt is being triggered because of an unauthenticated header claim from the remote server, with the actual target endpoint prominently displayed and requiring explicit confirmation before initiating any OAuth/browser flow.

### Proof of Concept
1. Set up an HTTP(S) server at `https://evil.example.com` that, on any request needing auth, responds with `401` and header `WWW-Authenticate: realm="GitHub"`.
2. In GitHub Desktop, add this URL as a remote for a repository (or clone from it) and perform a fetch/pull.
3. Git invokes Desktop's credential-helper trampoline; the `get` request's `wwwauth[...]` field contains `realm="GitHub"`.
4. `getEndpointKind` returns `'enterprise'` for `evil.example.com` without ever confirming it is actually GitHub-compatible via `isGitHubHost`.
5. Since no account is bound to `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which opens the "Sign in to your GitHub Enterprise instance" dialog and initiates OAuth against `evil.example.com` — confirmed by code path `trampoline-credential-helper.ts:109-125` → `trampoline-ui-helper.ts:80-104` → `dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint`.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
