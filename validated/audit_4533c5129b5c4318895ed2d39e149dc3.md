### Title
Payout attribution (`withdrawals.payout_payer_operator_xonly_pk`) is derived from an unauthenticated OP_RETURN, letting the withdrawer attribute a self-funded payout to an arbitrary operator - ([File: core/src/verifier.rs])

### Summary
`update_finalized_payouts` sets `payout_payer_operator_xonly_pk` purely by reading the first OP_RETURN push of the on-chain payout transaction, with no cryptographic binding to whoever actually funded/signed the payout's inputs. Since the withdrawer holds their own `SinglePlusAnyoneCanPay` signature for the withdrawal input and can freely choose any funding input and any OP_RETURN payload for the remainder of the transaction, they can broadcast a self-funded payout tx that attributes reimbursement credit to an arbitrary operator's x-only pubkey.

### Finding Description
The broken binding is the implicit invariant:
`withdrawals.payout_payer_operator_xonly_pk == xonly_pk(party whose UTXO funded output_txout.value)`

Code path:
- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with a single witness-authorized input (the withdrawal UTXO, key-spend, `SinglePlusAnyoneCanPay`) and appends a plain `OP_RETURN(operator_xonly_pk)` output that is **not committed to by any signature** - it is just a data push, chosen by whoever assembles the transaction.
- `Operator::withdraw` (`core/src/operator.rs:560-637`) only verifies the *user's* signature over the withdrawal input (`SECP.verify_schnorr` at line 632); it never signs or otherwise authenticates the OP_RETURN payload itself.
- Because `TapSighashType::SinglePlusAnyoneCanPay` only commits to input 0 and output 0, an attacker who is the actual withdrawer (and thus always possesses this signature, since it is user-generated per `parse_withdrawal_sig_params`, `core/src/rpc/parser/operator.rs:162-203`) can construct their **own** payout transaction: reuse their own signed input/output 0, add any funding input of their choosing (e.g., their own BTC), and append an `OP_RETURN` containing any operator's x-only pubkey.
- `update_finalized_payouts` (`core/src/verifier.rs:2283-2354`) scans the block, finds this tx via `get_first_op_return_output`/`parse_op_return_data` (`circuits-lib/src/bridge_circuit/mod.rs:608-617`), and unconditionally writes that OP_RETURN value into `withdrawals.payout_payer_operator_xonly_pk` for the corresponding `idx` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:199-251`).
- Downstream, `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-47`) has the victim operator's own node query `get_first_unhandled_payout_by_operator_xonly_pk` keyed on its own xonly pubkey, finds the poisoned row, and proceeds to `handle_finalized_payout` and eventually kickoff/reimburse - claiming the deposit's move-to-vault funds. `is_kickoff_malicious` (`core/src/verifier.rs:1857-1915`) only checks `operator_xonly_pk (from DB) == kickoff_data.operator_xonly_pk`; since the attacker deliberately set the DB value equal to the victim operator's real pubkey, this check passes and does not flag anything malicious.

None of the existing guards (`is_deposit_valid`, `SECP.verify_schnorr` on the withdrawal input, `is_kickoff_malicious`) validate that the OP_RETURN pubkey corresponds to whoever actually supplied the funding input of the payout transaction - that binding simply does not exist in the protocol.

### Impact Explanation
An unprivileged attacker acting as their own withdrawer can self-fund their own withdrawal (trivial, since they already own the withdrawal UTXO and hold the required signature) and stamp the payout with any operator's public key. The targeted operator's own automation will then treat this as "I fronted this payout" and drive it through kickoff/reimburse, pulling the deposit's move-to-vault BTC as reimbursement even though that operator never funded anything - matching the Critical category "an operator reimbursed for a payout it never funded." The same unauthenticated attribution also lets an attacker race a genuine operator's broadcast for the same withdrawal UTXO (since the attacker, as withdrawer, always holds a spendable signature for input 0) and claim the DB row first with a different OP_RETURN, permanently blocking the honest operator that did front the payout, since `idx` is the unique row key. This is repeatable for every withdrawal the attacker itself initiates, and for every operator whose public key they choose to target, since operator pubkeys are public (`OperatorConfig`/`OperatorDetails`).

### Likelihood Explanation
No special access beyond being an ordinary withdrawer is needed: the attacker calls Citrea `withdraw()` for their own withdrawal, obtains their own valid `SinglePlusAnyoneCanPay` signature (they generate it themselves), and broadcasts a Bitcoin transaction they fully control, at the cost of only network fees. All target operator public keys are advertised over gRPC (`OperatorConfig`). This requires no majority hashrate, no key compromise, and no interaction with any verifier/operator/aggregator credentials - it is exploitable by any Bitcoin-fee-paying party at any time a withdrawal is registered.

### Recommendation
Bind the operator attribution cryptographically to the actual payout funding, e.g., require the operator to sign (or MuSig2-cosign) a commitment over the whole payout transaction (including the OP_RETURN and the funding input), or require the OP_RETURN pubkey to match the public key that signs the *additional* funding input(s) of the payout transaction, and have verifiers validate that signature during `update_finalized_payouts` before trusting the OP_RETURN value.

        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))
}

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}
