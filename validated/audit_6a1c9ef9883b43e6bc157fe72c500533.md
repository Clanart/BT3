## Title
`update_payout_txs_and_payer_operator_xonly_pk` attributes a withdrawal payout to whatever xonly pubkey is embedded in an unauthenticated OP_RETURN, letting an attacker credit (and trigger reimbursement for) an operator that never funded the payout - ([File: core/src/verifier.rs, core/src/database/verifier.rs, core/src/task/payout_checker.rs])

### Summary
The binding the protocol needs is: `withdrawals.payout_payer_operator_xonly_pk == the xonly pubkey of the party whose funds actually paid withdrawals.payout_txid`. In reality, `update_finalized_payouts` derives `operator_xonly_pk` purely by parsing an OP_RETURN output of whichever transaction happens to end up spending the registered `withdrawal_utxo` [1](#0-0) , and `update_payout_txs_and_payer_operator_xonly_pk` writes that value into the DB unconditionally, with no signature or funding check tying the OP_RETURN key to the actual source of funds [2](#0-1) . `PayoutCheckerTask`/`handle_finalized_payout` then trust this column alone to decide "I fronted this payout, spend my collateral and claim reimbursement" [3](#0-2) .

### Finding Description
The `payout_tx` created by `create_payout_txhandler` has a single input (the user's `withdrawal_utxo`, signed by the user with `SinglePlusAnyoneCanPay`) and outputs: user payout, anchor, and an `OP_RETURN` containing `operator_xonly_pk.serialize()` [4](#0-3) . Because the sighash flag is `SIGHASH_SINGLE | ANYONECANPAY`, the user's signature only commits to input 0 and output 0 (the payout output) - it does **not** commit to any other input or to the OP_RETURN output. Any party (operator, or an attacker who observes the broadcast/mempool transaction) can therefore construct a *different* transaction that:
- reuses the same signed input/output pair (satisfying the signature),
- adds its **own** funding input(s) to cover the real payout value,
- and writes an **arbitrary** xonly pubkey (e.g. a real, uninvolved operator's key, discoverable via `fetch_operator_keys`) into the OP_RETURN.

If this attacker transaction gets confirmed instead of the honest operator's (e.g. via a higher-fee RBF replacement while the legitimate tx is still unconfirmed), `update_finalized_payouts` will read that OP_RETURN and call:
```

```
which does an unconditional `UPDATE withdrawals SET payout_txid=..., payout_payer_operator_xonly_pk=..., payout_tx_blockhash=... WHERE w.idx = c.idx` [5](#0-4)  — with **no check that the value moved in `payout_txid` was actually funded by the credited xonly pubkey**, and no comparison against `output_amount` registered for that withdrawal on Citrea.

The framed operator's own `PayoutCheckerTask` then polls `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` [6](#0-5) , finds this row (because the DB says its own key is the payer), and automatically calls `handle_finalized_payout`, which allocates a kickoff connector and proceeds toward `Reimburse` [7](#0-6) . `validate_payer_is_operator`, used later for `get_reimbursement_txs`, performs the exact same trust-the-DB-column check with no cryptographic proof of funding [8](#0-7) .

None of the existing guards close this gap: `is_profitable` is only checked by the *legitimate* operator's own `withdraw()` call path before it broadcasts, not re-verified from chain data; the presigned N-of-N tx graph does not cover the `Payout` transaction (it is built ad hoc, signed only by the user); and the light-client/disprove machinery only proves that a payout transaction with a given OP_RETURN exists in a given block — it never proves that the credited xonly pubkey's key/funds signed the additional inputs.

### Impact Explanation
BTC can leave a move-to-vault UTXO (via the eventual `Reimburse` transaction) crediting an operator that never fronted the withdrawal — this is explicitly listed as Critical impact ("BTC leaving a move-to-vault UTXO without a matching fronted withdrawal" / "an operator reimbursed for a payout it never funded"). Secondary effects: the honestly-racing operator's broadcast attempt is displaced (their payout tx gets replaced on-chain), wasting their funding/fee attempt; if the attacker instead stamps a non-existent/garbage xonly pubkey, the withdrawal becomes permanently mis-attributed and never gets picked up by `get_first_unhandled_payout_by_operator_xonly_pk`, stalling reimbursement for that withdrawal indefinitely. This is repeatable per withdrawal and works against any operator whose xonly pubkey is public (`fetch_operator_keys`).

### Likelihood Explanation
The attacker needs no privileged role: they must (1) observe an unconfirmed payout transaction in the mempool (public), (2) know a target operator's xonly pubkey (public via `GetOperatorKeys`/config), and (3) rebroadcast a fee-bumped, RBF-eligible replacement reusing the `SinglePlusAnyoneCanPay`-signed input/output while substituting their own funding input and OP_RETURN. Cost is limited to the payout amount plus fees (which the attacker must front themselves) and a modest fee bump to win the RBF race — feasible for any party willing to pay the withdrawal amount, and repeatable across every withdrawal that goes through the operator-fronted (non-optimistic) payout path.

### Recommendation
Do not derive payer attribution solely from an unauthenticated OP_RETURN. Either (a) require the payout transaction's additional funding input(s) to be spendable only via a script/key tied to a specific registered operator's collateral/signer key, and verify that binding on-chain before crediting `payout_payer_operator_xonly_pk`, or (b) have the operator co-sign/commit to the full payout transaction (including the OP_RETURN output) as part of the withdrawal flow so a third party cannot swap in a different payer identity while reusing the user's `ANYONECANPAY` signature, or (c) restrict the input signature to `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY` binding all outputs including OP_RETURN) so the OP_RETURN payer tag cannot be altered without invalidating the user's signature.

    db.update_payout_txs_and_payer_operator_xonly_pk(

        .get_first_unhandled_payout_by_operator_xonly_pk(Some(&mut dbtx), framed_operator_pk)
        .await
        .unwrap();
    assert!(unhandled.is_some());

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn handle_finalized_payout<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        deposit_outpoint: OutPoint,
        payout_tx_blockhash: BlockHash,
    ) -> Result<bitcoin::Txid, BridgeError> {
        let (deposit_id, deposit_data) = self
            .db
            .get_deposit_data(Some(dbtx), deposit_outpoint)
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {
                return Err(eyre::eyre!(
                    "Internal error: Expected the current round ({:?}) to be equal to or 1 less than the round of the first available kickoff for deposit reimbursement ({:?}) for deposit {:?}. If the round is less than the current round, there is an issue with the logic of the fn that gets the first available kickoff. If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

        &self,

        deposit_id: u32,

        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self

        tracing::info!(

            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
