### Title
`Verifier::is_deposit_valid` accepts a ReplacementDeposit whose funding UTXO was never actually spent from the claimed `old_move_txid` via a security-council/nofn authorized spend - ([File: core/src/verifier.rs])

### Summary
`Verifier::is_deposit_valid` and `DepositData::get_deposit_scripts` for `DepositType::ReplacementDeposit` only verify that the `deposit_outpoint`'s output has the scriptPubKey and amount matching `ReplacementDepositScript(nofn_xonly_pk, old_move_txid) + Multisig(security_council)`. Neither function checks that the transaction containing `deposit_outpoint` actually spent an input from `old_move_txid`, nor that any security-council/old-nofn signature was ever produced. Since `nofn_xonly_pk`, `old_move_txid`, and `security_council` are all public information, anyone can construct this exact taproot address and self-fund it, then drive it through `deposit_sign`/`deposit_finalize`.

### Finding Description
Binding claimed: funds at a `ReplacementDepositScript` address == funds that moved there via a genuine, security-council-authorized spend of `old_move_txid`'s move-to-vault output.

Trace:
- `DepositData::get_deposit_scripts` for `ReplacementDeposit` builds only the destination scripts: `ReplacementDepositScript::new(nofn_xonly_pk, old_move_txid)` and `Multisig::from_security_council(...)` [1](#0-0) .
- `Verifier::is_deposit_valid` compares `deposit_data.security_council` to `self.config.security_council` [2](#0-1) , and later builds `expected_scriptpubkey` from `get_deposit_scripts` and checks it against the on-chain `deposit_txout_in_chain.script_pubkey`, plus the amount and confirmation height [3](#0-2) [4](#0-3) .
- At no point does `is_deposit_valid` fetch the *inputs* of the `deposit_outpoint` transaction, check that one of them is `old_move_txid:DepositInMove`, or verify a witness/signature proving the security council (or old nofn key) authorized the move. The legitimate flow (`create_replacement_deposit_txhandler` + `sign_replacement_deposit_tx_with_sec_council`, test-only code) enforces this via Bitcoin consensus by spending `old_move_txid`'s output through `CheckSig(old_nofn)`/`Multisig(security_council)` script paths [5](#0-4) [6](#0-5) , but this construction is never *checked for* by the verifier — an attacker can simply skip it and pay into the deterministic address directly with a normal wallet transaction.
- `ReplacementDepositScript`'s script itself only requires a signature from `nofn_xonly_pk` to spend (the `old_move_txid` bytes are embedded in an unexecuted `OP_FALSE OP_IF ... OP_ENDIF` branch, pure data commitment, not a consensus-enforced link) [7](#0-6) , so nothing about the address itself proves provenance from a real prior vault UTXO.

Exploit flow: attacker picks any existing (or even nonexistent — as long as amount matches, though a real one is more useful) `old_move_txid` seen on chain, computes `generate_replacement_deposit_address(old_move_txid, nofn_xonly_pk, network, security_council)` — all public inputs [8](#0-7)  — funds that taproot address from their own wallet for `bridge_amount`, then calls `new_deposit`/`deposit_sign`/`deposit_finalize` with `ReplacementDeposit{old_move_txid}` referencing that outpoint. `is_deposit_valid` passes because script/amount/height checks are satisfied; verifiers sign a new N-of-N move-to-vault transaction for this self-funded UTXO.

### Impact Explanation
The Bitcoin-side signing itself does not directly steal funds (the new move-to-vault output remains under nofn+security-council control, funded fully by the attacker's own BTC). The exploitable consequence is downstream: this repo is the trust boundary that the Citrea `replaceDeposit` contract call relies on — Clementine is expected to only sign/produce a `ReplacementDeposit` move-tx when a genuine security-council-authorized migration occurred. Because `is_deposit_valid` never verifies that binding, an attacker can obtain a validly N-of-N-signed move-to-vault transaction for an address that embeds an arbitrary, attacker-chosen `old_move_txid` (including txids belonging to other users' real deposits) without ever having spent that UTXO. If this attacker-obtained move-tx and its associated proof are then submitted via `replaceDeposit` on Citrea to remap `deposit_id → new_move_txid`, the original bridged UTXO at `old_move_txid` becomes permanently disassociated from any Citrea deposit record while still being locked under nofn+security-council script control — i.e., a move-to-vault UTXO becomes permanently frozen with no future protocol path to spend it (Critical category: "a move-to-vault UTXO permanently frozen"). This is repeatable for any/every existing move-to-vault UTXO on the chain.

Note: whether Citrea's `replaceDeposit` contract independently re-derives/enforces the old-UTXO-spend link from the SPV proof is outside this repository (`Citrea contract... defect with no path through this repository` is explicitly out of scope) and I could not verify its Solidity-side checks from this codebase. The root cause identified here — the missing binding check in `Verifier::is_deposit_valid`/`get_deposit_scripts` — is squarely within this repo's responsibility, since Clementine is the layer meant to guarantee that a `ReplacementDeposit` corresponds to a legitimate security-council spend before ever producing a signed move-tx for it.

### Likelihood Explanation
Preconditions: attacker needs only public data (nofn_xonly_pk, any move_to_vault txid, public security council config) and enough BTC to fund `bridge_amount` into the deterministic replacement address, plus normal aggregator/verifier gRPC access available to any depositor. No privileged role, key, or collateral required. Cost to the attacker is one `bridge_amount` UTXO plus fees; this is high in absolute BTC terms but not a security barrier since bridge_amount is a fixed deposit-sized cost and the attacker's UTXO isn't destroyed — it moves into an N-of-N controlled output. This is fully repeatable against any move_to_vault UTXO/deposit.

### Recommendation
In `Verifier::is_deposit_valid` (and/or in `get_deposit_scripts`), for `DepositType::ReplacementDeposit`, additionally verify that the transaction containing `deposit_outpoint` has an input whose previous outpoint is exactly `old_move_txid:DepositInMove`, and that that input's witness satisfies the `Multisig::from_security_council` (or old nofn `CheckSig`) script path of the old move-to-vault output (i.e., fetch the prevout being spent, confirm it matches the historical move-to-vault taproot scriptPubKey, and confirm the spend actually used the security-council/nofn script leaf). Reject the deposit if the funding transaction's input does not directly and provably spend the claimed `old_move_txid` output.

async fn test_self_funded_replacement_deposit_accepted_without_real_spend() {
    let mut config = create_test_config_with_thread_name().await;
    let regtest = create_regtest_rpc(&mut config).await;
    let rpc = regtest.rpc();
    let actors = create_actors::<MockCitreaClient>(&config).await;

    // 1. Create a legitimate base deposit -> old_move_txid (a real vault UTXO).
    let (_, old_move_txid, _, _) =
        run_single_deposit::<MockCitreaClient>(&mut config, rpc.clone(), None, &actors, None)
            .await.unwrap();

    let nofn_xonly_pk = actors.get_nofn_aggregated_xonly_pk().unwrap();

    // 2. ATTACKER (no keys, no council membership) computes the deterministic
    //    replacement address referencing old_move_txid, and funds it from
    //    their own wallet -- NOT by spending old_move_txid.
    let (replacement_address, _) = generate_replacement_deposit_address(
        old_move_txid,
        nofn_xonly_pk,
        config.protocol_paramset().network,
        config.security_council.clone(),
    ).unwrap();

    let attacker_funded_outpoint = rpc
        .send_to_address(&replacement_address, config.protocol_paramset().bridge_amount)
        .await
        .unwrap();
    rpc.mine_blocks(18).await.unwrap();

    // 3. Drive it through deposit_sign / deposit_finalize as a ReplacementDeposit.
    let deposit_info = DepositInfo {
        deposit_outpoint: attacker_funded_outpoint,
        deposit_type: DepositType::ReplacementDeposit(ReplacementDepositData { old_move_txid }),
    };
    let mut aggregator = actors.get_aggregator();
    let movetx = aggregator
        .new_deposit(deposit_info.clone().into())
        .await
        .expect("BUG: verifiers signed a replacement deposit whose funding tx never spent old_move_txid");

    // ASSERT (binding check): the funding tx of attacker_funded_outpoint has
    // NO input referencing old_move_txid:DepositInMove.
    let funding_tx = rpc.get_tx_of_txid(&attacker_funded_outpoint.txid).await.unwrap();
    assert!(
        !funding_tx.input.iter().any(|txin| txin.previous_output.txid == old_move_txid),
        "funding tx does not spend old_move_txid -- yet is_deposit_valid accepted it"
    );

    // If the assertion above holds (funding tx unrelated to old_move_txid) and
    // `new_deposit` still succeeded, is_deposit_valid failed to bind the
    // ReplacementDeposit to a genuine security-council spend of old_move_txid.
}

pub fn create_replacement_deposit_txhandler(
    old_move_txid: Txid,
    input_outpoint: OutPoint,
    old_nofn_xonly_pk: XOnlyPublicKey,
    new_nofn_xonly_pk: XOnlyPublicKey,
    paramset: &'static ProtocolParamset,
    security_council: SecurityCouncil,
) -> Result<TxHandler, BridgeError> {
    Ok(TxHandlerBuilder::new(TransactionType::ReplacementDeposit)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NoSignature,
            SpendableTxIn::from_scripts(
                input_outpoint,
                paramset.bridge_amount,
                vec![
                    Arc::new(CheckSig::new(old_nofn_xonly_pk)),
                    Arc::new(Multisig::from_security_council(security_council.clone())),
                ],
                None,
                paramset.network,
            ),
            crate::builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_scripts(
            paramset.bridge_amount,
            vec![
                Arc::new(ReplacementDepositScript::new(
                    new_nofn_xonly_pk,
                    old_move_txid,
                )),
                Arc::new(Multisig::from_security_council(security_council)),
            ],
            None,
            paramset.network,
        ))
        // always use 0 sat anchor for replacement deposit tx, this will keep the amount in replacement deposit tx exactly the bridge amount
        .add_output(UnspentTxOut::from_partial(anchor_output(Amount::from_sat(
            0,
        ))))
        .finalize())
}

fn sign_replacement_deposit_tx_with_sec_council(
    replacement_deposit: &TxHandler,
    config: &BridgeConfig,
    old_nofn_xonly_pk: XOnlyPublicKey,
) -> Result<Transaction, BridgeError> {
    let security_council = config.security_council.clone();
    let multisig_script = Multisig::from_security_council(security_council.clone()).to_script_buf();
    let sighash = replacement_deposit.calculate_script_spend_sighash(
        0,
        &multisig_script,
        bitcoin::TapSighashType::SinglePlusAnyoneCanPay,
    )?;

    // sign using first threshold security council members, for rest do not sign
    let signatures = config
        .test_params
        .sec_council_secret_keys
        .iter()
        .enumerate()
        .map(|(idx, sk)| {
            if idx < security_council.threshold as usize {
                let actor = Actor::new(*sk, config.protocol_paramset().network);
                let sig = actor
                    .sign_with_tweak_data(sighash, TapTweakData::ScriptPath, None)
                    .unwrap();
                Some(taproot::Signature {
                    signature: sig,
                    sighash_type: bitcoin::TapSighashType::SinglePlusAnyoneCanPay,
                })
            } else {
                None
            }
        })
        .collect::<Vec<_>>();

    let mut witness =
        Multisig::from_security_council(security_council).generate_script_inputs(&signatures)?;

    // calculate address in movetx vault
    let script_buf = CheckSig::new(old_nofn_xonly_pk).to_script_buf();
    let (_, spend_info) = create_taproot_address(
        &[script_buf.clone(), multisig_script.clone()],
        None,
        config.protocol_paramset().network,
    );
    // add script path to witness
    Actor::add_script_path_to_witness(&mut witness, &multisig_script, &spend_info)?;
    let mut tx = replacement_deposit.get_cached_tx().clone();
    // add witness to tx
    tx.input[0].witness = witness;
    Ok(tx)
}

/// Struct for deposit script that replaces an old move tx with a replacement deposit (to update bridge design on chain)
/// It commits to the old move txid inside the script.
#[derive(Debug, Clone)]
pub struct ReplacementDepositScript(pub(crate) XOnlyPublicKey, Txid);

impl SpendableScript for ReplacementDepositScript {
    fn as_any(&self) -> &dyn Any {
        self
    }

    fn kind(&self) -> ScriptKind {
        ScriptKind::ReplacementDepositScript(self)
    }

    fn to_script_buf(&self) -> ScriptBuf {
        let citrea_replace: [u8; 13] = "citreaReplace".as_bytes().try_into().expect("length == 13");

        Builder::new()
            .push_x_only_key(&self.0)
            .push_opcode(OP_CHECKSIG)
            .push_opcode(OP_FALSE)
            .push_opcode(OP_IF)
            .push_slice(citrea_replace)
            .push_slice(self.1.as_byte_array())
            .push_opcode(OP_ENDIF)
            .into_script()
    }
}

pub fn generate_replacement_deposit_address(
    old_move_txid: bitcoin::Txid,
    nofn_xonly_pk: XOnlyPublicKey,
    network: bitcoin::Network,
    security_council: SecurityCouncil,
) -> Result<(Address, TaprootSpendInfo), BridgeError> {
    let deposit_script =
        ReplacementDepositScript::new(nofn_xonly_pk, old_move_txid).to_script_buf();

    let security_council_script = Multisig::from_security_council(security_council).to_script_buf();

    let (addr, spend) =
        create_taproot_address(&[deposit_script, security_council_script], None, network);
    Ok((addr, spend))
}
