The bug class is a panic on malformed/untrusted input during decoding. Let me check the PedPoP share-decryption path and other read paths for index/unwrap panics reachable by unprivileged parties.### Title
Panic in PedPoP blame evaluation via out-of-set Participant indexes - (File: crypto/dkg/pedpop/src/lib.rs, crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the `loona-hpack` panic-on-malformed-input bug (GHSA-7vm6-qwh5-9x44, an index-out-of-bounds panic during decoding of untrusted input), Serai's PedPoP blame machinery panics — instead of returning an error — when a blame statement names a `Participant` index that is not a member of the DKG's `1..=n` set. The panic occurs in HashMap indexing inside `blame_internal`, which is reachable from public inputs (the accused/accuser indexes and the serialized `EncryptedMessage`).

### Finding Description
`AdditionalBlameMachine::new` registers encryption keys and commitments only for the participants enumerated `1..=n` (crypto/dkg/pedpop/src/lib.rs:656-660). Later, `AdditionalBlameMachine::blame` (lib.rs:674-682) forwards caller-supplied `sender` and `recipient` indexes into `blame_internal` (lib.rs:575-609) without checking membership. Two indexing sites then panic on a missing key:

- `self.enc_keys[&decryptor]` in `Decryption::decrypt_with_proof` (crypto/dkg/pedpop/src/encryption.rs:388) — panics if `recipient` is not a registered participant.
- `self.commitments[&sender]` in `share_verification_statements` call inside `blame_internal` (lib.rs:599) — panics if `sender` is not a registered participant, reached whenever the decrypted share parses as a canonical scalar.

`Participant` is only constrained to be a non-zero `u16` (crypto/dkg/src/lib.rs:29-35), so any index `> n` is a well-formed, deserializable value. This is reachable in production from `CoordinatorMessage::VerifyBlame` handling in `processor/src/key_gen.rs` (lines 504-549), where `accuser` and `accused` are taken from the incoming message and passed directly to `AdditionalBlameMachine::blame(accuser, accused, ...)`. A participant can therefore trigger blame verification with an index outside the validator set — e.g. by accusing `Participant(n+1)`, or by being accused with an index outside the registered set while the decrypted share bytes are canonical. Neither path validates set membership before the indexing operation.

### Impact Explanation
A single crafted blame message (public input: two `u16` participant indexes plus an `EncryptedMessage` blob, sent through the coordinator's `VerifyBlame` flow) panics the evaluating processor instead of cleanly attributing fault. This is a remote denial of service against every node evaluating the blame statement — matching the original advisory's crash-on-decode impact (CWE-754/CWE-755, availability). Depending on panic handling, this halts a processor mid-protocol or takes down the process, stalling key generation / slashing resolution.

### Likelihood Explanation
Low-cost to trigger: the attacker needs only a well-formed `Participant` index greater than `n` in an accusation. For the `sender` (accused) panic path, the accusation must additionally carry a validly signed `EncryptedMessage` whose ciphertext decrypts to a canonical scalar — an attacker in the DKG set can produce this trivially since they control messages they send. No cryptography needs to be broken; the panic precedes any validity determination. Severity is Medium, consistent with the original advisory's availability-limited score.

### Recommendation
Validate `sender` and `recipient` against the registered participant set at the top of `blame_internal` (and in `AdditionalBlameMachine::blame`/`BlameMachine::blame`), returning a defined `PedPoPError` variant (e.g. `InvalidParticipant`/`MissingParticipant`) instead of indexing. Concretely, replace `self.enc_keys[&decryptor]` and `self.commitments[&sender]` with `.get(...)` and map `None` to an error, or reject indexes not in `1..=n` before calling `decrypt_with_proof`.

### Proof of Concept
```rust
// In-scope: crypto/dkg/pedpop
// After a PedPoP DKG with params n = N, construct an AdditionalBlameMachine
// over the valid commitment messages for participants 1..=N.
let machine = AdditionalBlameMachine::<C>::new(context, n, commitment_msgs).unwrap();

// Accusation naming a participant outside the set. Participant is only
// constrained to be non-zero, so N+1 is accepted.
let outsider = Participant::new(n + 1).unwrap();

// Path 1: outsider as accuser -> self.enc_keys[&outsider] panics
// inside decrypt_with_proof (encryption.rs:388).
machine.blame(accused_in_set, outsider, msg, None);

// Path 2: outsider as accused with a message whose pop verifies and whose
// decrypted share is a canonical scalar ->
// self.commitments[&outsider] panics at lib.rs:599.
machine.blame(outsider, accuser_in_set, msg_with_canonical_share, Some(proof));
```

Both paths abort the process rather than returning `PedPoPError`, mirroring the hpack `Decoder::decode(&[0x3f])` panic on unvalidated input.
