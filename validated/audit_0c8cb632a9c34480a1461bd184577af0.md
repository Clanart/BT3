## Analysis

The reported authentik bug class is: a signed assertion is accepted without validating **timing** (`NotBefore`/`NotOnOrAfter`) or **audience** (intended recipient/domain) restrictions, enabling replay of expired/foreign-context signatures to gain unauthorized access.

The closest reachable analog in sei-chain is the `associate` method of the `addr` precompile (address `0x1004`), which recovers a signer's public key from an arbitrary caller-supplied message signature and uses it to permanently bind an EVM address to a Sei address and migrate the "direct-cast" account's funds — with **no timing** and **no audience/domain binding** on the signature at all. [1](#0-0) 

The signed payload is `customMessage`, fully controlled by whoever calls the precompile — there is no requirement that it reference the Sei chain ID, the `addr` precompile address, a nonce, or an expiration timestamp: [2](#0-1) 

Once recovered, `associateAddresses` only checks that the target Sei address is not *already* associated — it performs no check on when or for what purpose the signature was produced — before permanently writing the address mapping and migrating balances: [3](#0-2) [4](#0-3) 

This is the same bug class the codebase's own EIP-7702 `SetCodeAuthorization` handling was explicitly hardened against — chain-ID/audience binding was added there specifically to prevent a publicly observable, foreign-purpose signature from being replayed to force-associate a victim: [5](#0-4) [6](#0-5) 

But that fix was applied only to the `SetCode` authorization path, not to `addr.associate`/`associatePubKey`, which remains exposed.

### Title
Missing domain (audience) and timing binding on `addr` precompile `associate`/`associatePubKey` signatures enables forced, attacker-timed account association and balance migration - (File: precompiles/addr/addr.go)

### Summary
The `associate` method of the EVM `addr` precompile (`0x1004`) recovers a public key from a `v/r/s` signature over an arbitrary, caller-chosen `customMessage`. Unlike the SetCode/EIP-7702 authorization path, this signature carries no chain ID, no contract/domain separator, no nonce, and no expiration. Any signature a user has ever produced with their EVM key over any message — for any purpose, on any chain — can be extracted (e.g., from a public block explorer, another dApp's session, or a leaked signed message) and replayed by an unrelated third party to call `associate` on Sei at a time of the attacker's choosing.

### Finding Description
`associate` decodes `v`, `r`, `s` and hashes `customMessage`, then recovers `evmAddr`/`seiAddr`/`pubkey` purely from the signature and hash, with no restriction on what `customMessage` must contain: [2](#0-1) 

`associateAddresses` then unconditionally writes the address mapping (if not already associated) and migrates the legacy direct-cast account's spendable coins, wei balance, and can remove the old account, all triggered by this replayed signature: [3](#0-2) [7](#0-6) 

This mirrors exactly the SAML "no Conditions validation" bug class: no `NotBefore`/`NotOnOrAfter` equivalent (the signature never expires and can be replayed indefinitely) and no `AudienceRestriction` equivalent (the signature is not bound to Sei's chain ID or the `addr` precompile, so a signature meant for a different purpose/chain is accepted as valid proof of association intent).

### Impact Explanation
Any unprivileged EVM caller who obtains any historical signature from a victim's key can force that victim's EVM↔Sei address association and trigger `MigrateBalance` at an arbitrary, attacker-chosen block — an irreversible, one-way state transition (association cannot be undone or redone) that the victim did not consent to at that time. This directly affects fund/state handling for the associated account (balance migration from the direct-cast address, account removal) without the account owner's contemporaneous authorization, satisfying the "unauthorized transfer via precompile" and "permanent freezing/loss of expected control over timing of a fund-moving operation" impact bar.

### Likelihood Explanation
High reachability: the precompile is public, callable by any EVM transaction sender, and signatures over arbitrary messages are commonly produced by wallets (e.g., `personal_sign` for dApp logins) and often become publicly visible. No special privilege is required to submit the replay transaction.

### Recommendation
Bind the `associate`/`associatePubKey` message to the Sei chain ID and the `addr` precompile address (domain separation), and add a nonce or short-lived expiration to the signed payload, consistent with the chain-ID/nonce checks already enforced for EIP-7702 `SetCodeAuthorization` in `AuthorityToPreAssociate`/`RecoverAddressesFromAuthorization`.

### Proof of Concept
1. Victim signs any message `M` with their EVM private key for an unrelated purpose (e.g., logging into a dApp) via `personal_sign`; the resulting `v/r/s` is exposed (many apps display or log these signatures).
2. Attacker calls `addr.associate(v, r, s, M)` on Sei at `0x1004` from any account, at any later time.
3. `helpers.GetAddresses` recovers the victim's `evmAddr`/`seiAddr`/`pubkey` from `keccak256(M)` and the signature; since `M` was never bound to Sei/`addr` at signing time, the check passes.
4. `associateAddresses` associates the victim's addresses and immediately migrates the legacy direct-cast account's balances, executed entirely without the victim submitting or approving a Sei transaction at that time. [8](#0-7) [3](#0-2)

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey) error {
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	if acc := p.accountKeeper.GetAccount(ctx, seiAddr); acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	castAddrBalances := p.bankKeeper.SpendableCoins(ctx, castAddr)
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
