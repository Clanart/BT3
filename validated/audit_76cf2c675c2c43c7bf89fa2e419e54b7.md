## Title
Attacker-controlled remote/submodule URL can trigger an unauthorized "Sign in to GitHub Enterprise" OAuth flow bound to an attacker's server via `isGitHubHost` header spoofing - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The reentrancy report is not reproducible in Desktop as-is (no ERC777-style callback re-entrancy exists in this codebase), so per the task instructions I reduced it to its underlying bug class: an attacker-supplied external input that is trusted to make a security-relevant decision without adequate verification, letting the attacker cause the app to repeat/trigger a privileged internal flow it shouldn't. The closest concrete Desktop analog I could verify from local code is in the git-credential trampoline: a URL that Git tries to authenticate against - which can originate from an attacker-controlled clone/submodule remote - drives `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, and that classification decides whether Desktop automatically launches an OAuth "Sign in to GitHub/Enterprise" popup pointed at that attacker-controlled host.

### Finding Description
When Git needs credentials for any remote (main remote, or any submodule remote defined in an attacker-controlled `.gitmodules`), Desktop's credential helper handler `createCredentialHelperTrampolineHandler` (`app/src/lib/trampoline/trampoline-credential-helper.ts:220-260`) is invoked and calls `getCredential()` (lines 93-135), which in turn calls `getEndpointKind()` (lines 137-179) to classify the target host.

`getEndpointKind` walks through several increasingly weak heuristics:
1. `isGist` / `isDotCom` / `isGHE` string checks on the hostname.
2. `wwwauth[...]` header content forwarded by Git itself (attacker-controlled, since it's the response the attacker's own server sent to Git).
3. Finally, if none of the above match and the protocol is `https:`, it calls `isGitHubHost(endpoint)` (`app/src/lib/api.ts:2435-2491`), which makes a `HEAD` request to `${endpoint}/meta` and returns `true` if the response contains an `x-github-request-id` header.

Because the attacker fully controls the server behind the URL (their own remote/submodule host), they can simply have that server return an arbitrary `x-github-request-id` header on the `/meta` endpoint. `isGitHubHost` then returns `true`, and `getEndpointKind` returns `'enterprise'` for a host that has nothing to do with GitHub Enterprise.

Back in `getCredential()` (lines 107-125), once `endpointKind !== 'generic'` and there's no existing account for `getAPIEndpoint(endpoint)`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-104`). This directly calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` with the attacker's origin, and shows the `SignIn` popup with `isCredentialHelperSignIn: true` and `credentialHelperUrl: endpoint`. The corrupted value here is the trust boundary output of `getEndpointKind`/`isGitHubHost`: it is derived entirely from attacker-controlled network response headers, yet it gates whether Desktop silently kicks off a GitHub OAuth device/browser sign-in flow ("Sign in to your GitHub Enterprise") scoped to the attacker's chosen origin, without any confirmation that this really is a GitHub-compatible host.

### Impact Explanation
Nothing here directly hands the attacker the user's existing GitHub.com token (accounts are still matched by strict `origin` comparison in `findGitHubTrampolineAccount`, so an existing account's token is not leaked to a foreign origin). The concrete impact is a spoofed, automatically-triggered "unauthorized OAuth" flow: the user is shown a native Desktop "Sign in to your GitHub Enterprise" dialog (not a webpage, so normal phishing awareness cues are reduced) for an endpoint the user never entered, triggered purely by cloning/fetching a repository with a crafted submodule/remote URL. If the user completes the resulting browser-based OAuth/PAT step, the credentials they enter get bound as a new Desktop "account" for the attacker's origin (`app/src/lib/stores/sign-in-store.ts` endpoint entry flow) and that account's `login`/`token` are then handed back to Git's credential helper (`credWithAccount`, line 47) - i.e., sent to the attacker's own git server as HTTP Basic auth. If the attacker registers a domain resembling a real GHE instance the organization uses, or simply relies on the user not noticing the unfamiliar prompt, this becomes a credential-harvesting / unauthorized account-binding primitive triggered purely by cloning or fetching a hostile repository.

### Likelihood Explanation
The trigger condition is entirely within scope: an unprivileged attacker who controls a cloned/fetched repository (via a crafted submodule URL in `.gitmodules`, or as the origin remote itself) can passively cause any push/pull/fetch/submodule-update to invoke the credential helper against their server. Standing up a server that returns a `HEAD /meta` response with an `x-github-request-id` header is trivial. The remaining leg (user completing the sign-in dialog) requires normal user interaction with a dialog Desktop itself presented, which is a lower bar than “unnatural user steps” since the app-initiated popup is the expected UX for legitimate authentication prompts.

### Recommendation
- Do not let a passive/spoofable network heuristic (`isGitHubHost`'s single header check) authorize a privileged UI action (auto-launching the Enterprise sign-in flow). At minimum, require a second independent, harder-to-spoof signal (e.g., checking known GHES API discovery responses, or requiring explicit user confirmation naming the exact host before beginning any OAuth flow).
- Surface the destination host prominently in the `SignIn` popup before the user is asked to authenticate, and warn explicitly when the endpoint was inferred automatically from a git operation (as opposed to user-entered), given `credentialHelperUrl` is already tracked in `sign-in.tsx` for the message text (`app/src/ui/sign-in/sign-in.tsx:184-190`) but is not treated with extra suspicion.
- Consider gating automatic `promptForGitHubSignIn` calls originating from submodule URLs (i.e., URLs not equal to the top-level remote the user explicitly cloned) behind an additional confirmation step, since submodule URLs are attacker-controlled repository content rather than user input.

### Proof of Concept
1. Attacker creates a public repository containing a `.gitmodules` entry pointing a submodule at `https://evil.example.com/foo.git` (or simply serves the top-level remote from `evil.example.com` and gets the victim to add/clone it).
2. Attacker's server at `evil.example.com` responds to `HEAD https://evil.example.com/meta?...` with header `x-github-request-id: spoofed` (and to the actual git smart-HTTP requests) so `isGitHubHost` (`app/src/lib/api.ts:2472-2483`) returns `true`.
3. Victim clones/fetches the repository in GitHub Desktop; Desktop runs `git submodule update --init --recursive` / `fetch` against `evil.example.com`.
4. Git invokes the credential helper trampoline; `getEndpointKind` (`trampoline-credential-helper.ts:137-179`) classifies the host as `'enterprise'`.
5. `getCredential` (lines 107-125) finds no matching account and calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which calls `dispatcher.beginEnterpriseSignIn` + `setSignInEndpoint('https://evil.example.com')` and shows the native "Sign in to your GitHub Enterprise" dialog to the victim, unprompted by any user action other than cloning the repository. /** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
