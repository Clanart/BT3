### Title
Unmetered, unbounded EIP-7702 authorization-list processing in the EVM preprocess ante decorator enables a low-cost CPU/state-write DoS - (File: x/evm/ante/preprocess.go)

### Summary
`EVMPreprocessDecorator.AnteHandle` sets an **infinite gas meter** and then calls `associateAuthorizationAuthorities`, which iterates over every entry in a `SetCodeTx`'s EIP-7702 authorization list and performs a full address-association routine (signature/authority recovery via `AuthorityToPreAssociate`, a `CacheContext`, and `AssociateAddresses` state reads/writes) for each one — *before* the transaction's intrinsic-gas/size checks in `BasicDecorator` are evaluated and before the caller is charged any metered gas for this work. [1](#0-0) [2](#0-1) 

### Finding Description
The EVM ante pipeline processes `MsgEVMTransaction` through `EVMPreprocessDecorator` before `BasicDecorator` (which performs `core.IntrinsicGas` / init-code-size / gas-limit validation) runs: [3](#0-2) 

Inside `EVMPreprocessDecorator.AnteHandle`, the context's gas meter is switched to an *infinite* meter specifically because "EVM handles gas checking from within": [4](#0-3) 

Immediately after, for `SetCodeTx` (EIP-7702) transactions, `associateAuthorizationAuthorities` loops over `ethTx.SetCodeAuthorizations()` with no bound other than what the message-level `validateAuthList`/tx-size limits allow, invoking address recovery and a full `AssociateAddresses` write attempt (via a nested `CacheContext`) for every authorization tuple: [5](#0-4) 

Because this happens under the infinite gas meter and *before* `BasicDecorator`'s `core.IntrinsicGas(...)` check (which does account for `SetCodeAuthorizations` count) can reject an oversized/underfunded transaction, the resource cost of processing the entire authorization list is paid by the node regardless of whether the transaction is ultimately accepted: [6](#0-5) [7](#0-6) 

This mirrors the Designate bug class: a caller can supply an arbitrarily large "record set" (here, EIP-7702 authorization tuples) that the node processes without enforcing a per-message quota before doing the expensive work, at a point in the pipeline where gas metering — the mechanism that would normally bound and charge for such work — is deliberately disabled.

I was not able to confirm the exact numeric cap (if any) enforced by `validateAuthList` on the number of authorization entries per `SetCodeTx`, since that function's body was not inspected in this session; the analysis above is based on the ante-ordering and infinite-gas-meter evidence in `preprocess.go` and `basic.go`.

### Impact Explanation
Every full node — during both `CheckTx` (mempool admission) and `DeliverTx` — runs this same unmetered loop for any submitted `SetCodeTx`. A transaction crafted with a maximal authorization list (bounded only by the node's/consensus max tx-bytes, not by any EVM-gas-equivalent charge at this stage) forces every validator to perform a proportionally large amount of signature-recovery and store-read/write work for free, before the transaction can be rejected for insufficient gas or fee. If broadcast at scale (or repeatedly resubmitted, since CheckTx runs on every mempool re-validation), this can materially inflate per-block ante-processing time across the network, which is the CWE-400 resource-exhaustion pattern from the reference CVE (unbounded record processing without a quota check).

### Likelihood Explanation
Reachable by any unprivileged EVM transaction sender — no special privileges, precompile access, or validator role are required, only the ability to construct and sign a `SetCodeTx` with a large authorization list and broadcast it via the public JSON-RPC surface. The severity is bounded by whatever implicit cap `validateAuthList` (unverified) or max tx-bytes impose on the list size, which is the main source of uncertainty in this analysis.

### Recommendation
Move the authorization-authority association loop (and any other unmetered per-entry work in `EVMPreprocessDecorator`) to occur only after intrinsic-gas/size checks have passed, or charge metered gas for each authorization processed during preprocessing rather than running the loop under an infinite gas meter. Additionally, enforce and verify an explicit, low, protocol-level cap on the number of EIP-7702 authorization entries accepted per transaction, checked as the very first step of `associateAuthorizationAuthorities`.

### Proof of Concept
Conceptual (not executed): construct a signed EIP-7702 `SetCodeTx` whose `authorization_list` contains the maximum number of authorization tuples permitted by the node's max-tx-bytes limit, each authorizing a distinct dummy authority address with a valid signature but insufficient tx gas to pass `core.IntrinsicGas`. Submit it via `eth_sendRawTransaction`. Observe that `EVMPreprocessDecorator.AnteHandle` runs `associateAuthorizationAuthorities`, performing recovery + `AssociateAddresses` for every entry under the infinite gas meter, before `BasicDecorator` rejects the tx for `core.ErrIntrinsicGas` — meaning the full authorization-list processing cost is incurred on every node for a transaction that is guaranteed to ultimately fail and never pay any fee for this ante-time work.

func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
}
