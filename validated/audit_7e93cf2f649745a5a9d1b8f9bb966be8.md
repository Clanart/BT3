## Analysis

The external Ubiquity report's core broken invariant: **a price oracle that can be stale relative to the true market price, used to compute an exchange amount between a volatile/depegging asset and a "hard" asset, lets an attacker extract the hard asset at the oracle's stale (favorable) rate while the protocol absorbs the loss.** Ubiquity's flaw sat in collateral mint/redeem; the same pattern exists in Hyperbridge's on-chain `SimplexPaymaster`, which prices ERC‑20 stablecoin gas payments purely from Chainlink oracles bounded only by a staleness window, not a price-deviation/peg check. ### Title
Stale/unbounded Chainlink price in `SimplexPaymaster._tokenPrice`/`_getOraclePrice` lets attackers pay gas with a depegged stablecoin at stale par value, draining the paymaster's EntryPoint deposit - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` sponsors gas for any UserOp paid in a registered ERC‑20 (USDC/USDT/etc.), converting gas cost to token units via `_tokenPrice`, which multiplies/divides two Chainlink `latestRoundData()` reads (`nativeUsd`, `tokenUsd`) with no floor/ceiling sanity check on the token price itself — only a staleness bound (`maxOracleAge`, configurable up to `MAX_ORACLE_AGE = 7 days`). [3](#0-2) [4](#0-3)  If a registered token depegs (e.g., a stablecoin briefly trades at $0.80–$0.90, as USDC did in March 2023) while its Chainlink feed's last update is still within `maxOracleAge`, any unprivileged UserOp sender can pay for real ETH-denominated gas sponsorship using the depegged token priced at its stale $1.00 peg, extracting value from the paymaster's EntryPoint deposit.

### Finding Description
`_fetchDetails` (called by `PaymasterERC20` on every sponsored UserOp) computes `tokenPrice` via `_tokenPrice`, which is:
```
tokenPrice = nativeUsd * 10^tokenDecimals * (10000+markupBps) / (tokenUsd * 10000)
```
`nativeUsd` and `tokenUsd` both come from `_getOraclePrice`, whose only two guards are `answer <= 0` and `block.timestamp - updatedAt > maxOracleAge`. [5](#0-4)  There is no check that the reported price is within an expected band (e.g., $0.95–$1.05 for a stablecoin) — the exact "force chainlink feeds to stay within acceptable thresholds" mitigation the Ubiquity report proposed and Hyperbridge omits here as well.

This is a fully permissionless, unauthenticated path: any account can submit a UserOp through the ERC‑4337 EntryPoint specifying `paymasterData` referencing a registered depegging token, and `_validatePaymasterUserOp`/`_fetchDetails` will happily price it off the stale oracle answer. [6](#0-5)  No relayer, prover, admin, or governance actor is involved — the "attacker" is simply the UserOp sender who holds the depegging token, exactly mirroring the original report's "user holding a depegging asset" primitive.

Because `tokenUsd` is used in the *denominator*, a stale-high `tokenUsd` (oracle still reporting ~$1.00 while the token is really worth less) makes `tokenPrice` artificially *low* — the paymaster charges fewer token units than the token's real-market value would justify for the same amount of sponsored (real) ETH gas. Each UserOp that goes through drains real ETH value from the paymaster's `EntryPoint` deposit while crediting it with a token worth less than assumed. The code's own doc comment acknowledges this exact risk ("clients... keep allowances and permit amounts small... bounding exposure to the residual allowance even against a malicious oracle") [7](#0-6) , but that mitigation is a client-side convention, not an enforced on-chain bound — it does not stop the amount charged per UserOp from being mispriced, nor does it cap how many UserOps an attacker can submit during the depeg/staleness window.

### Impact Explanation
This directly causes loss of funds for the protocol: the paymaster (funded via treasury deposits into the ERC‑4337 `EntryPoint`) pays out real native-asset gas value in exchange for stablecoins priced above their true market value during a depeg, as long as the stale Chainlink answer remains within `maxOracleAge` (configurable up to 7 days). Repeated exploitation across many UserOps during the depeg window can materially drain the `EntryPoint` deposit that funds gas sponsorship — a genuine "stealing or loss of funds" outcome reachable by an ordinary UserOp sender, matching the bounty's accepted impact categories.

### Likelihood Explanation
Depeg events for major stablecoins (USDC, USDT, DAI) have occurred historically and can last from minutes to over a day. Chainlink heartbeats for stablecoin feeds are commonly 1h–24h (the code's own comment notes "Base/Ethereum stablecoins up to 24h" and allows a governance-set ceiling of 7 days), so there is a realistic window where the feed is "not stale" per this contract's only guard yet materially disagrees with the live market price. Exploitation requires no privileged access, no relayer collusion, and no governance action — only an attacker holding the depegging token and submitting ordinary UserOps, making this a directly reachable, unprivileged attack path once such a token is registered.

### Recommendation
Add a price-sanity bound in `_getOraclePrice` (or a wrapper used specifically for stablecoins), rejecting or clamping prices that fall outside a configurable band (e.g., reverting if a token's Chainlink price is below/above `$1 ± X%`) in addition to the existing staleness check. Consider also: (1) lowering `MAX_ORACLE_AGE` for stablecoin feeds, (2) rate-limiting/capping total token exposure per token within a rolling window so a depeg event bounds maximum drainage, and (3) triggering `_deactivateToken` automatically (or via a permissionless "circuit breaker" call anyone can invoke, gated purely by comparing oracle price to the band) rather than relying solely on a reactive governance `DeactivateToken` message that itself must go through Hyperbridge/host round-trip and may not arrive before losses accrue.

### Proof of Concept
1. Governance registers `USDT` in `SimplexPaymaster` with its Chainlink `USDT/USD` feed and `maxOracleAge = 24h` (allowed by `_setParams`, ceiling `MAX_ORACLE_AGE = 7 days`). [8](#0-7) 
2. `USDT` depegs on-chain (DEX price drops to $0.85) but the Chainlink feed's last `updatedAt` is, say, 2 hours old (within `maxOracleAge`), so `latestRoundData()` still reports ≈$1.00.
3. Attacker (any EOA) submits UserOps via the ERC‑4337 EntryPoint with `paymasterData` mode `0x01` (pre-approved) targeting the `USDT` token registered in `SimplexPaymaster`.
4. `_fetchDetails` → `_tokenPrice` computes `tokenPrice` using the stale ~$1.00 `tokenUsd`; `PaymasterERC20._postOp` charges the attacker `erc20Cost = weiCost * tokenPrice / 1e18` USDT, i.e., USDT at its stale $1.00 valuation even though it is only worth $0.85 on the open market. [1](#0-0) 
5. Attacker repeats across many UserOps during the staleness/depeg window, each time paying real gas in devalued USDT priced at par — net-extracting the ~15% mispricing margin from the paymaster's `EntryPoint` deposit, funded by the treasury, with no on-chain guard preventing it.

            if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
            if (!cfg.active) revert TokenNotActive(tokenAddr);
            _executePermit(userOp);
        }

        return super._validatePaymasterUserOp(userOp, userOpHash, maxCost);

    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    // ── Pricing ──────────────────────────────────────────────────────

    function _tokenPrice(TokenConfig memory cfg) internal view returns (uint256) {
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
