### Title
Amended commits with a clean working tree produce an empty Stop-hook review set, silently bypassing security review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` gates the Stop-hook review set on the intersection of `dirty_now` (from `git status`) and `changed_since` (diff against `baseline_sha`). When a turn's only change is a `git commit --amend` that leaves the working tree clean, `dirty_now` is empty and the `head_at_capture..HEAD` union is skipped because amend breaks the `_is_ancestor` linear-history check, so the intersection collapses to the empty set even though `changed_since` correctly shows the amended file differs from baseline. The Stop hook then reports "empty review set" and exits without ever sending the dangerous diff to the LLM reviewer.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:

```
dirty_now = tracked_dirty | new_untracked            # from `git status --porcelain`
if head_at_capture advanced *linearly* to current HEAD:
    dirty_now |= names changed in head_at_capture..HEAD
    diff_base = head_at_capture
changed_since = names changed vs baseline_sha (stash-derived pre-turn snapshot)
review_set = dirty_now & changed_since   (or dirty_now alone if no baseline)
``` [1](#0-0) 

`baseline_sha` is captured at `UserPromptSubmit` via `capture_git_baseline` (`git stash create`, falling back to `HEAD`), and `head_at_capture` is the pre-turn `HEAD` SHA. [2](#0-1)  Both are written by `handle_user_prompt_submit`'s inline `_save` closure (not the exported `save_baseline_sha` wrapper, which is otherwise unused in the plugin) each time a prompt is submitted, unless `touched_paths` from a prior aborted turn must be preserved. [3](#0-2) 

Attack flow: during a turn, Claude (or a Bash command run under attacker-influenced instructions) executes `git commit --amend` on an already-committed dangerous change, with no other pending edits. After the amend:
- The working tree is clean, so `_git_status_porcelain` returns empty `tracked_dirty`/`untracked` sets, making `dirty_now = ∅`.
- `head_at_capture` (pre-amend HEAD) is **not** an ancestor of the new post-amend HEAD (amend replaces the commit object rather than extending it linearly), so the `_is_ancestor` guard fails and the `head_at_capture..HEAD` union that would otherwise repopulate `dirty_now` with the amended files never executes.
- `changed_since = _git_name_only(repo, baseline_sha)` still correctly detects the amended file as different from the pre-turn stash baseline.
- `review_set = dirty_now (∅) ∩ changed_since (contains the dangerous file) = ∅`.

`handle_stop_hook` treats an empty `review_paths` as "nothing to review" and exits without calling the LLM analyzer: `if not review_paths: ... _skip(9, ...)` [4](#0-3) . The dangerous amended change is never diffed, never sent to `analyze_code_security`, and never flagged — it is silently treated as if it doesn't exist, even though `changed_since` (and thus the plugin's own git-derived signal) correctly identified it as new content since the baseline. This breaks exactly the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": the intersection logic assumes `dirty_now` is a superset of newly-introduced content, but that assumption fails whenever history is rewritten (amend, rebase, `commit --amend --no-edit`, etc.) and the tree ends up clean.

No existing guard catches this: `_is_ancestor` is a linear-history optimization, not a correctness fallback, and there is no code path that falls back to `changed_since` alone when `head_at_capture` isn't an ancestor of `HEAD`. The commit-review hook (`handle_commit_review_posttooluse` / `_resolve_amend_pre_sha`) does have dedicated amend-detection logic via reflog [5](#0-4) , but that is a separate PostToolUse[Bash] surface gated on detecting `git commit --amend` in the Bash command text; it does not backstop the Stop hook's `compute_v2_review_set`, and it only fires when the amend was invoked via a `Bash(git commit:*)` tool call that CC's matcher observes — a scripted/wrapped amend, or an amend performed with a clean tree from a different code path, still reaches Stop's empty-set skip.

### Impact Explanation
This is a Security-control bypass: a dangerous code change that is genuinely new relative to the reviewed baseline is never scanned by the LLM security reviewer and never triggers the exit-code-2 corrective loop, because the Stop hook's review-set computation zeroes out under an intersection with an empty `dirty_now`. An attacker (or a compromised/malicious instruction set steering Claude) can route a dangerous edit through `git commit` immediately followed by `git commit --amend` (or any amend that leaves the tree clean) within the same turn to make the Stop-hook diff review silently no-op, defeating the plugin's only end-of-turn security gate for that content.

### Likelihood Explanation
This requires no privilege beyond normal repository interaction: any turn that performs a commit and then amends it (a common, unremarkable git workflow — fixing a commit message, adding a forgotten `git add`, squashing via amend) with a resulting clean working tree reliably reproduces the empty review-set condition. It does not require race conditions, elevated permissions, or any interaction with locks/state files — it's a deterministic consequence of the `dirty_now ∩ changed_since` logic combined with `_is_ancestor` rejecting non-linear history.

### Recommendation
In `compute_v2_review_set`, do not require `dirty_now` to be a strict superset gate when `head_at_capture != current_head`. When the pre-turn `HEAD` is not an ancestor of the current `HEAD` (i.e., history was rewritten — amend, rebase, filter-branch, reset --hard + recommit, etc.), fall back to reviewing `changed_since` directly (or union it into `dirty_now` unconditionally rather than only in the linear-ancestor case), since `changed_since` is already the ground truth for "differs from the pre-turn stash baseline." At minimum, treat "HEAD moved but is not an ancestor of the new HEAD" as its own explicit branch that adds the `head_at_capture..HEAD` (or equivalent two-dot comparison against the pre-amend tree) diff into the review set instead of silently doing nothing.

### Proof of Concept
Integration test plan (pytest-style) against `compute_v2_review_set`:
1. Init a temp git repo, commit an initial file, capture `baseline_sha = capture_git_baseline(repo)` and `head_at_capture = _git_rev_parse_head(repo)`.
2. Write a dangerous change to a tracked file (e.g., a hardcoded secret / command-injection sink) and `git commit -m "wip"`.
3. Run `git commit --amend --no-edit` with no other pending changes so the working tree is clean afterward.
4. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
5. Assert `review_paths` is **not** empty and contains the dangerous file's absolute path — expected to currently **fail** (returns `[]`) because `dirty_now` is empty while `changed_since` is non-empty, demonstrating the bypass.
6. As a control, repeat steps 2-4 without the amend (leave the plain commit) and confirm the review set does contain the file when `_is_ancestor` succeeds, isolating amend/non-linear-history as the trigger.

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):

        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now

def _resolve_amend_pre_sha(repo_root, expected_post_sha=None):
    """For a `git commit --amend` we just ran, return the pre-amend SHA via
    reflog, or None if it can't be safely determined.

    expected_post_sha: the post-amend SHA the caller parsed from bash stdout
    (or reflog). If provided, HEAD@{0} of `repo_root` must match it (prefix
    compare — bash stdout SHAs are abbreviated, reflog %H is 40 chars) before
    we trust the reflog-derived pre-amend SHA. This guards against the
    cross-repo case (`cd ../other && git commit --amend && cd -`) where
    `repo_root` happens to have its own recent amend that's unrelated to
    the bash command we're reviewing.

    We require HEAD@{0}'s reflog subject to start with `commit (amend)` —
    otherwise our `--amend` regex matched something that didn't actually
    perform an amend (e.g., `git commit --amend --dry-run`, aliased commands,
    aborted amends), and HEAD@{1} would be the wrong commit. Also requires
    HEAD@{1} to NOT itself be an amend, since back-to-back amends would have
    HEAD@{1} as the previous-amend's post state — the original commit we
    want to compare against is then HEAD@{2}, but at that point we're
    reaching and fall back to a full review.

    Bytes + decode('utf-8', errors='replace'): reflog subjects embed commit
    subjects, which git stores as raw bytes (commit messages may be latin-1
    / cp1252 / etc.). text=True would raise UnicodeDecodeError (a
    ValueError, not OSError) on non-UTF8 bytes and crash the hook.
    """
    if not repo_root:
        return None
    try:
        r = subprocess.run(
            [*GIT_CMD, "log", "-g", "-2", "--format=%H|%gs", "HEAD"],
            cwd=repo_root, capture_output=True, timeout=5,
        )
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
    if r.returncode != 0:
        return None
    stdout_text = r.stdout.decode("utf-8", errors="replace")
    lines = [ln for ln in stdout_text.splitlines() if "|" in ln]
    if len(lines) < 2:
        return None
    head0_sha, _, head0_subj = lines[0].partition("|")
    head1_sha, _, head1_subj = lines[1].partition("|")
    if not head0_subj.startswith("commit (amend)"):
        return None
    if head1_subj.startswith("commit (amend)"):
        return None
    # Cross-repo guard: the post-amend SHA the caller is about to review must
    # match HEAD@{0} of repo_root. Otherwise the bash command was likely run
    # in a different repo than repo_root, and the reflog we just read is
    # unrelated. Prefix-compare: expected_post_sha is typically the 7-char
    # abbreviated SHA captured from bash stdout by _COMMIT_SHA_RE (git's
    # default core.abbrev floor), while head0_sha is the full 40-char %H —
    # strict equality would always fail and silently disable the delta path.
    if expected_post_sha and not head0_sha.startswith(expected_post_sha):
        return None
    return head1_sha or None
```
