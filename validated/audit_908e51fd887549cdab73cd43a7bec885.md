## Title
Missing zero-value validation on `Kip71GasTarget` governance parameter leads to a division-by-zero panic in KIP-71 base fee calculation - (File: `kaiax/gov/param.go`, `params/kip71_config.go`)

### Summary
The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker` that performs no validation, unlike the sibling `Kip71BaseFeeDenominator` parameter which explicitly rejects zero. If `GasTarget` is set to `0` through governance, `KIP71Config.NextMagmaBlockBaseFee` divides by this unchecked zero value, causing a runtime panic during base-fee computation for every block whose gas usage is non-zero.

### Finding Description
`Params[Kip71GasTarget]` is defined with `FormatChecker: noopFormatChecker`, meaning any `uint64` value including `0` passes validation when a governance parameter update is submitted via `PartialParamSet.Add`: [1](#0-0) 

Compare this with `Kip71BaseFeeDenominator`, which explicitly guards against zero: [2](#0-1) 

`PartialParamSet.Add` only rejects a value when the parameter's `FormatChecker` returns `false`; since `Kip71GasTarget`'s checker is a no-op, `GasTarget = 0` is accepted: [3](#0-2) 

The accepted `ParamSet` is later converted directly into a `KIP71Config` and used, unmodified, in consensus-critical base fee calculation: [4](#0-3) 

Inside `NextMagmaBlockBaseFee`, `gasTarget` is used as a divisor with no zero check (unlike `BaseFeeDenominator`, which has an explicit `== 0` fallback a few lines above): [5](#0-4) 

If `parentGasUsed == gasTarget == 0`, the function returns early without dividing. But once any block is produced with `parentGasUsed > 0` while `gasTarget == 0`, the code enters the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor, which panics per Go's `math/big` semantics ("division by zero"). The symmetric branch for `parentGasUsed < gasTarget` cannot occur when `gasTarget == 0`, but the `> ` branch is trivially reachable by any block with nonzero gas usage.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked in the header verification path (`VerifyMagmaHeader`) and in fee estimation (`node/cn/gasprice/feehistory.go`), both of which run on every full node while processing/verifying every post-Magma block. A governance-approved (or, depending on voting weight thresholds, a validator-controlled) update setting `GasTarget = 0` would cause every node to panic deterministically while computing/verifying the base fee for the very next block with nonzero gas usage — effectively halting block production and verification chain-wide once the parameter activates. This is analogous to the original report's "unchecked value causing an unreliable/incorrect calculation," except here the missing check on the governance-controlled divisor escalates from "wrong value" to a full consensus-halting panic in the KIP-71 pricing mechanism.

### Likelihood Explanation
The `Kip71GasTarget` parameter is a first-class, governance-tunable value (see `genKIP71Config` in `cmd/homi/setup/cmd.go`), part of the standard KIP-71/Magma configuration surface. Unlike malformed p2p messages or malicious-node scenarios, this requires only a normal governance vote/parameter update flow, which is explicitly in-scope ("governance parameters"). Because the sibling `BaseFeeDenominator` field already carries an explicit nonzero check, the omission on `GasTarget` looks like an oversight rather than an intentional design choice, making accidental (not just malicious) triggering plausible.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects zero, mirroring the existing check for `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, as defense in depth, add an explicit zero-guard inside `NextMagmaBlockBaseFee` before dividing by `gasTarget`, consistent with the existing `baseFeeDenominator == 0` fallback.

### Proof of Concept
1. Submit/approve a governance vote setting `kip71.gastarget = 0` (accepted because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`, see `kaiax/gov/param.go:324-334`).
2. Once the new `ParamSet` becomes active, `ToKip71Config()` propagates `GasTarget: 0` into the `KIP71Config` used by consensus (`kaiax/gov/paramset.go:199-207`).
3. Any subsequent block with `GasUsed > 0` causes `NextMagmaBlockBaseFee` to take the `parentGasUsed > gasTarget` branch and execute `x.Div(x, new(big.Int).SetUint64(0))` (`params/kip71_config.go:92-102`), which panics with "division by zero," crashing header verification/base fee computation on every node processing that block.

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
