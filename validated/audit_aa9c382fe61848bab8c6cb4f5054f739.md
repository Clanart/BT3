### Title
Webhook shop attribution relies on unverified `X-Shopify-Shop-Domain` header, enabling cross-shop replay confusion - ([File: lib/shopify_app/controller_concerns/webhook_verification.rb])

### Summary
`ShopifyApp::WebhookVerification#shop_domain` returns `request.headers["HTTP_X_SHOPIFY_SHOP_DOMAIN"]` directly, while `hmac_valid?` in `ShopifyApp::PayloadVerification` computes the HMAC only over `request.raw_post` (the body) using the app's single client secret. The shop-domain header is never part of the signed material, so any attacker who legitimately receives a webhook for their own installed shop can replay the same body+HMAC while substituting an arbitrary `X-Shopify-Shop-Domain` header, and the request still passes `verify_request`.

### Finding Description
- `verify_request` in `lib/shopify_app/controller_concerns/webhook_verification.rb:15-21` only checks `hmac_valid?(request.raw_post)`.
- `hmac_valid?` in `lib/shopify_app/controller_concerns/payload_verification.rb:13-23` recomputes `OpenSSL::HMAC.digest(digest, secret, data)` over the raw body using `ShopifyApp.configuration.secret`/`old_secret`, which is the app's single client secret shared across every shop that installs the app — it is not shop-specific and does not cover any HTTP headers.
- `shop_domain` (`webhook_verification.rb:23-25`) is read straight from the `HTTP_X_SHOPIFY_SHOP_DOMAIN` header with no cross-check against the HMAC-covered payload.
- The library's own documentation (`docs/shopify_app/webhooks.md:88-104`) explicitly instructs developers to build custom webhook controllers that call `SomeJob.perform_later(shop_domain: shop_domain, webhook: webhook_params.to_h)`, and the generated job/controller templates (`lib/generators/shopify_app/add_webhook/templates/webhook_job.rb.tt`, `add_app_uninstalled_job/templates/app_uninstalled_job.rb.tt`, `add_privacy_jobs/templates/*.rb.tt`) all do `shop = Shop.find_by(shopify_domain: shop_domain)` and then act on that shop (e.g., `shop.destroy`, `shop.with_shopify_session`) using exactly this attacker-influenceable value.
- Exploit flow: An attacker who controls Shop A (with the app installed) triggers or captures a legitimate webhook delivery (body + valid `X-Shopify-Hmac-Sha256`). They resend that exact body/HMAC pair to the app's webhook endpoint but replace the `X-Shopify-Shop-Domain` header with Shop B's domain (a shop unrelated to the payload, e.g. a real victim shop that also has the app installed). Because the signature only covers the body and matches the app-wide secret, `hmac_valid?` succeeds, and any consumer code trusting `shop_domain` attributes Shop A's webhook data/action to Shop B.
- None of the existing checks (`hmac_valid?`, `ActiveSupport::SecurityUtils.secure_compare`) verify that the claimed shop domain corresponds to the signing key or to the payload; there is no `ShopifyApp::Utils.sanitize_shop_domain` or database cross-check tying the header to the HMAC in this concern.

### Impact Explanation
This is a cross-shop data/session confusion vulnerability (Shopify HackerOne "broken authentication/authorization" or "cross-tenant data exposure" class). Depending on which webhook topic/job the host app wires up per the documented pattern, impact ranges from misattributed data updates to destructive actions on an unrelated shop's record (e.g., the generated `AppUninstalledJob`/`ShopRedactJob` templates call `shop.destroy` keyed only on this unverified `shop_domain`).

### Likelihood Explanation
Feasible and repeatable by any unprivileged attacker who has installed the app on their own shop (a normal, unprivileged install) — no host-app misconfiguration is required beyond following the library's documented custom-webhook pattern or generated templates, which are first-class supported usages of this concern. The attacker needs no app secret or session token, only a captured legitimate webhook from their own shop.

### Recommendation
Do not trust `X-Shopify-Shop-Domain` (or any header) for shop attribution unless it is cryptographically bound to the signed payload. Derive the shop from data actually covered by the HMAC (e.g., a shop identifier embedded in the JSON body, or use the `shopify_api` gem's `ShopifyAPI::Webhooks::Request`, which parses shop from the raw body) and/or verify that the claimed domain matches a shop whose specific webhook secret (if per-shop secrets are used) or an additional signed claim corresponds to the request. At minimum, update `shop_domain` and the accompanying documentation/generators to warn against using it as an authoritative shop identifier for security-sensitive actions.

### Proof of Concept
```ruby
# test/integration/webhook_shop_domain_spoof_test.rb
class CustomWebhooksController < ActionController::Base
  include ShopifyApp::WebhookVerification
  def carts_update
    render json: { shop: shop_domain }
  end
end

test "hmac_valid? passes even when X-Shopify-Shop-Domain is forged" do
  ShopifyApp.configure { |c| c.secret = "app_secret" }
  body = '{"id":1,"line_items":[]}'
  hmac = Base64.strict_encode64(OpenSSL::HMAC.digest("sha256", "app_secret", body))

  post "/custom_webhooks/carts_update",
    params: body,
    headers: {
      "HTTP_X_SHOPIFY_HMAC_SHA256" => hmac,
      "HTTP_X_SHOPIFY_SHOP_DOMAIN" => "victim-shop.myshopify.com", # attacker-controlled, unrelated to body/HMAC
      "CONTENT_TYPE" => "application/json",
    }

  assert_response :success
  assert_equal "victim-shop.myshopify.com", JSON.parse(response.body)["shop"]
  # HMAC was computed with attacker's own shop's payload, but shop_domain
  # is accepted as "victim-shop.myshopify.com" with no additional verification.
end

    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
```

class AppUninstalledJob < ActiveJob::Base
  extend ShopifyAPI::Webhooks::WebhookHandler

  def self.handle(topic:, shop:, body:, webhook_id:, api_version:)
    perform_later(topic: topic, shop_domain: shop, webhook: body)
  end

  def perform(topic:, shop_domain:, webhook:)
    shop = Shop.find_by(shopify_domain: shop_domain)

    if shop.nil?
      logger.error("#{self.class} failed: cannot find shop with domain '#{shop_domain}'")
      
      raise ActiveRecord::RecordNotFound, "Shop Not Found"
    end

    logger.info("#{self.class} started for shop '#{shop_domain}'")
    shop.destroy
  end
