### Title
Unauthenticated on-chain "mirror" URLs let any user trigger SSRF against DataLayer node HTTP fetches - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer service automatically fetches root/delta files from URLs it discovers on-chain via "mirror" coins. Mirror coin creation (`chia/wallet/db_wallet/db_wallet_puzzles.py::create_mirror_puzzle`) is a bare `P2_PARENT` puzzle spend with no ownership check tying the mirror to a specific `launcher_id`/store — any wallet user can spend their own coin to create a mirror announcing an arbitrary URL for **any** store id. Nodes subscribed to that store id pull these attacker-controlled URLs and pass them unvalidated into `http_download()` (`chia/data_layer/download_data.py:298-345`), which performs a raw `aiohttp` GET against the URL with no scheme/host/IP allow-listing. This is directly analogous to the reported Grav Twig SSRF class (attacker-controlled string reaching an outbound HTTP fetch with no destination restriction), except here the "attacker input" is a permissionless on-chain artifact rather than template content.

### Finding Description
- `create_new_mirror()` in `chia/data_layer/data_layer_wallet.py:687-703` builds a coin with `create_mirror_puzzle().get_tree_hash()` and stores `launcher_id` plus arbitrary `urls` as memos — nothing on-chain restricts which `launcher_id` a mirror creator can target or what the URL strings can be. [1](#0-0) 
- `create_mirror_puzzle()` is just `P2_PARENT.curry(Program.to(1))` — a generic passthrough puzzle, not gated by singleton/launcher ownership. [2](#0-1) 
- Any DataLayer node that is subscribed to a `store_id` periodically calls `update_subscriptions_from_wallet()`, which reads all mirrors for that `launcher_id` from the wallet and adds their URLs as candidate sync servers, with no filtering. [3](#0-2) 
- `fetch_and_validate()` then shuffles the discovered `servers_info` and calls `insert_from_delta_file()` → `download_file()` → `http_download()` for each candidate URL. [4](#0-3) 
- `http_download()` performs `session.get(server_info.url + "/" + filename, ...)` directly, with no validation that the URL isn't pointing at loopback/link-local/internal/cloud-metadata addresses, and no scheme restriction (e.g. `file://`, `http://169.254.169.254/`, internal RPC ports, etc.). [5](#0-4) 
- The E2E RPC test confirms mirrors take arbitrary URLs and are retrievable/settable via `add_mirror`/`get_mirrors` RPC and on-chain mirror coins, with no ownership enforcement asserted in the test. [6](#0-5) 

### Impact Explanation
An unprivileged chain participant can, for the cost of a single coin spend, force any DataLayer node subscribed to a targeted store to make outbound HTTP requests to attacker-chosen hosts/ports (SSRF). This can be used to probe or interact with internal-only services reachable from the DataLayer host (e.g., other localhost RPC ports, cloud metadata endpoints, internal admin panels), potentially disclosing internal network topology or, if the target service reacts to unauthenticated GET requests, causing side effects. It does not directly forge coin identity or move funds, so it falls short of causing supply inflation or unauthorized coin movement, but it is a real network-reachable attack surface reachable purely by submitting a spend and does not require compromising any peer, node, or key.

### Likelihood Explanation
High feasibility: creating a mirror coin only requires normal wallet spend capability (`dl_new_mirror` RPC / `create_new_mirror`), no special permission or ownership of the targeted store's launcher id is enforced. Any node operator who subscribes to a public/shared store (a routine DataLayer usage pattern) is automatically exposed once that store accumulates a malicious mirror, without any explicit user action to "visit" a URL.

### Recommendation
- Enforce that only the store owner (or an authorized signer for that launcher id) can create mirrors that affect subscription sync, or otherwise require operator confirmation before adding externally-discovered mirror URLs to the sync candidate list.
- Add SSRF hardening to `http_download()` / URL intake in `update_subscriptions_from_wallet()`: validate scheme (`http`/`https` only), resolve and reject private/loopback/link-local/multicast/metadata IP ranges, and optionally allow only URLs from an operator-configured allow-list.
- Consider treating on-chain mirror URLs as untrusted advisory data requiring explicit opt-in per store rather than being auto-merged into the active fetch list.

### Proof of Concept
1. Attacker (any wallet holder) calls `dl_new_mirror` (or DataLayer RPC `add_mirror`) targeting a victim's public `launcher_id`/store with `urls=["http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<internal-port>/...`), paying only the mirror coin amount/fee. [7](#0-6) 
2. Once the mirror coin confirms on-chain, any DataLayer node subscribed to that store id calls `update_subscriptions_from_wallet(store_id)` during its normal sync loop, pulling the attacker URL into its server list. [3](#0-2) 
3. On the next `fetch_and_validate()` cycle, the node's DataLayer process performs `http_download()` against the attacker-controlled URL, from the node's own network context — completing the SSRF request. [5](#0-4) 

Note: I was unable to fully confirm from the index whether any launcher-id ownership check exists elsewhere in the mirror-creation code path (e.g., enforced at wallet UI level rather than protocol/puzzle level) since only the puzzle and wallet RPC code were retrievable; the `P2_PARENT`/`create_mirror_puzzle` construction itself shows no such enforcement.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
