### Title
Multisig `StacksAddress::from_public_keys` and spending-condition `verify()` never reject duplicate public keys, letting one signer satisfy an m‑of‑n threshold alone - (File: `stacks-common/src/types/mod.rs`, `stacks-codec/src/transaction.rs`)

### Summary
The reported bug class is a missing duplicate-entry check in a list whose members are each supposed to represent one independent unit of authorization (`extraRewards` slots). In stacks-core, the analogous list is the public-key vector used to build a multisig `StacksAddress` and to verify a `MultisigSpendingCondition` / `OrderIndependentMultisigSpendingCondition`. Neither the address-construction routine nor the signature-verification routines check that the public keys supplied are pairwise distinct, so an m‑of‑n multisig account can be created (or exploited, if already misconfigured) such that fewer than `n` distinct keys are actually required to reach the `signatures_required` threshold.

### Finding Description
`StacksAddress::from_public_keys` only checks that there are at least `num_sigs` keys and that segwit modes use compressed keys; it performs no uniqueness check on `pubkeys` before hashing them into the address: [1](#0-0) 

The same absence of a distinctness check exists on the verification side. `MultisigSpendingCondition::verify` accumulates every recovered/declared public key into `pubkeys` without deduplication, counts `num_sigs`, and then re-derives the address from that same `pubkeys` vector via `StacksAddress::from_public_keys`, only checking that the resulting hash matches `self.signer`: [2](#0-1) 

`OrderIndependentMultisigSpendingCondition::verify` has the identical pattern, and is even more permissive because it accepts `num_sigs >= signatures_required` rather than requiring an exact match: [3](#0-2) 

Because address derivation (`public_keys_to_address_hash` / `to_bits_p2sh` / `to_bits_p2sh_p2wsh`) simply pushes whatever key bytes are given, in whatever order, into the script/hash, an address can legitimately be produced from a key list that contains the same public key twice (e.g., a "2-of-3" address whose 3 slots are `[keyA, keyA, keyB]`): [4](#0-3) 

If such an address is created — whether through operator error during a joint wallet setup, or through a malicious participant supplying their own key twice while other co-owners believe `n` distinct signers are required — the holder of `keyA` alone can produce two independent signatures over the sighash (ECDSA signing is not required to be deterministic; two signing sessions with different nonces yield two different valid signatures for the same key) and place them into two separate `TransactionAuthField::Signature` fields. `verify()` will recover `keyA` twice, count `num_sigs = 2`, satisfy `signatures_required == 2`, and re-derive the same address, since the address was built from the identical (duplicated) key list. The transaction is accepted with the funds moving on the authority of a single private key even though the account's nominal threshold implies two independent parties must agree — breaking the equality "signatures verified == distinct signers required."

### Impact Explanation
This falls under the Critical bucket: a transaction can be authorized and can move an asset without the authorization the multisig scheme was designed to require, because a duplicated key slot lets one party unilaterally reach the signature threshold that other co-owners believe requires their independent participation. Any Stacks account backed by a Multisig or OrderIndependentMultisig `TransactionSpendingCondition` with a duplicate public key among its slots is vulnerable to unilateral, unauthorized asset movement by whichever party holds the duplicated key.

### Likelihood Explanation
The likelihood is contingent on account configuration, similar to the original C4 finding's "Medium" rating for the analogous BaseRewardPool/VE3DLocker duplicate-entry issue: it requires an m-of-n multisig account to have been set up (accidentally or by a colluding participant) with a repeated public key across its `n` slots. Once such a misconfigured account exists, exploitation requires nothing more than the key-holder producing two signatures with their own key — no cryptographic break, no cooperation from other parties, and no detection mechanism exists anywhere in the codebase (`from_public_keys`, `MultisigSpendingCondition::verify`, `OrderIndependentMultisigSpendingCondition::verify`) to catch the duplication either at address-creation time or at spend time.

### Recommendation
Add an explicit uniqueness check on the `pubkeys` slice in `StacksAddress::from_public_keys` (reject if any two entries are byte-equal) so that duplicate-key multisig addresses can never be constructed, and add a matching uniqueness check inside `MultisigSpendingCondition::verify` and `OrderIndependentMultisigSpendingCondition::verify` over the recovered/declared `pubkeys` before deriving/comparing the address, so that even a pre-existing duplicate-key address cannot be exploited to satisfy the threshold with fewer distinct signers than intended.

### Proof of Concept
1. Construct an address via `StacksAddress::from_public_keys(version, &AddressHashMode::SerializeP2SH, 2, &vec![keyA, keyA, keyB])` — this succeeds and returns a valid 2-of-3 address, per [1](#0-0) , because only `pubkeys.len() < num_sigs` and compression rules are checked, never uniqueness.
2. Build a `MultisigSpendingCondition` with `signer` set to that address's hash160 and `signatures_required = 2`.
3. Using only `keyA`'s private key, sign the initial sighash twice (two independent ECDSA signing operations, or a single signature reused with the second field constructed via `TransactionAuthField::Signature`) and push both as separate fields, omitting `keyB` entirely.
4. Call `MultisigSpendingCondition::verify`; `num_sigs` reaches 2, `pubkeys = [keyA, keyA]`, and `StacksAddress::from_public_keys(0, hash_mode, 2, &[keyA, keyA])` reproduces the same signer hash, so `verify` returns `Ok`, per [5](#0-4) , authorizing the transaction with only one real private key despite the account being nominally "2-of-3."

    pub fn from_public_keys(
        version: u8,
        hash_mode: &AddressHashMode,
        num_sigs: usize,
        pubkeys: &Vec<StacksPublicKey>,
    ) -> Option<StacksAddress> {
        // must be sufficient public keys
        if pubkeys.len() < num_sigs {
            return None;
        }

        // address hash mode must be consistent with the number of keys
        match *hash_mode {
            AddressHashMode::SerializeP2PKH | AddressHashMode::SerializeP2WPKH
                // must be a single public key, and must require one signature
                if (num_sigs != 1 || pubkeys.len() != 1) => {
                    return None;
                }
            _ => {}
        }

        // if segwit, then keys must all be compressed
        match *hash_mode {
            AddressHashMode::SerializeP2WPKH | AddressHashMode::SerializeP2WSH => {
                for pubkey in pubkeys {
                    if !pubkey.compressed() {
                        return None;
                    }
                }
            }
            _ => {}
        }

        let hash_bits = public_keys_to_address_hash(hash_mode, num_sigs, pubkeys);
        StacksAddress::new(version, hash_bits).ok()
    }

    /// Authenticate a spending condition against an initial sighash.
    /// In doing so, recover all public keys and verify that they hash to the signer
    /// via the given hash mode.
    pub fn verify(
        &self,
        initial_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        mode: TransactionAuthVerificationMode,
    ) -> Result<Txid, AuthError> {
        let mut pubkeys = vec![];
        let mut cur_sighash = initial_sighash.clone();
        let mut num_sigs: u16 = 0;
        let mut have_uncompressed = false;
        for field in self.fields.iter() {
            let pubkey = match field {
                TransactionAuthField::PublicKey(ref pubkey) => {
                    if !pubkey.compressed() {
                        have_uncompressed = true;
                    }
                    pubkey.clone()
                }
                TransactionAuthField::Signature(ref pubkey_encoding, ref sigbuf) => {
                    if *pubkey_encoding == TransactionPublicKeyEncoding::Uncompressed {
                        have_uncompressed = true;
                    }

                    let (pubkey, next_sighash) = TransactionSpendingCondition::next_verification(
                        &cur_sighash,
                        cond_code,
                        self.tx_fee,
                        self.nonce,
                        pubkey_encoding,
                        sigbuf,
                        mode,
                    )?;
                    cur_sighash = next_sighash;
                    num_sigs = num_sigs
                        .checked_add(1)
                        .ok_or(AuthError::VerifyingError("Too many signatures".to_string()))?;
                    pubkey
                }
            };
            pubkeys.push(pubkey);
        }

        if num_sigs != self.signatures_required {
            return Err(AuthError::VerifyingError(
                "Incorrect number of signatures".to_string(),
            ));
        }

        if have_uncompressed && self.hash_mode == MultisigHashMode::P2WSH {
            return Err(AuthError::VerifyingError(
                "Uncompressed keys are not allowed in this hash mode".to_string(),
            ));
        }

        let addr = StacksAddress::from_public_keys(
            0,
            &self.hash_mode.to_address_hash_mode(),
            self.signatures_required as usize,
            &pubkeys,
        )
        .ok_or_else(|| {
            AuthError::VerifyingError("Failed to generate address from public keys".to_string())
        })?;

        if addr.bytes() != &self.signer {
            return Err(AuthError::VerifyingError(format!(
                "Signer hash does not equal hash of public key(s): {} != {}",
                addr.bytes(),
                self.signer
            )));
        }

        Ok(cur_sighash)
    }

/// Internally, the Stacks blockchain encodes address the same as Bitcoin
/// multisig address over p2sh (p2sh-p2wsh)
fn to_bits_p2sh_p2wsh<K: PublicKey>(num_sigs: usize, pubkeys: &Vec<K>) -> Hash160 {
    let mut bldr = Builder::new();
    bldr = bldr.push_int(num_sigs as i64);
    for pubk in pubkeys {
        bldr = bldr.push_slice(&pubk.to_bytes());
    }
    bldr = bldr.push_int(pubkeys.len() as i64);
    bldr = bldr.push_opcode(btc_opcodes::OP_CHECKMULTISIG);

    let mut digest = Sha256::new();
    let mut d = [0u8; 32];

    digest.update(bldr.into_script().as_bytes());
    d.copy_from_slice(&digest.finalize());

    let ws = Builder::new().push_int(0).push_slice(&d).into_script();
    Hash160::from_data(ws.as_bytes())
}

/// Convert a number of required signatures and a list of public keys into a byte-vec to hash to an
/// address.  Validity of the hash_flag vis a vis the num_sigs and pubkeys will _NOT_ be checked.
/// This is a low-level method.  Consider using StacksAdress::from_public_keys() if you can.
pub fn public_keys_to_address_hash<K: PublicKey>(
    hash_flag: &AddressHashMode,
    num_sigs: usize,
    pubkeys: &Vec<K>,
) -> Hash160 {
    match *hash_flag {
        AddressHashMode::SerializeP2PKH => to_bits_p2pkh(&pubkeys[0]),
        AddressHashMode::SerializeP2SH => to_bits_p2sh(num_sigs, pubkeys),
        AddressHashMode::SerializeP2WPKH => to_bits_p2sh_p2wpkh(&pubkeys[0]),
        AddressHashMode::SerializeP2WSH => to_bits_p2sh_p2wsh(num_sigs, pubkeys),
    }
}
