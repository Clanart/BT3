### Title
`Scanner::scan_block` returns immature coinbase outputs as spendable `ReceivedOutput`s - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The xtrlock bug is a filter that fails to block a class of input it was supposed to exclude (multitouch events reach programs despite the lock). The analog in Serai is `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs:221-227`: it scans `block.txdata` including `txdata[0]` — the coinbase transaction — so a miner can cause Serai to report a `ReceivedOutput` that is consensus-unspendable for 100 blocks. Serai's own processor avoids this only by deliberately slicing `&block.txdata[1 ..]` in `processor/src/networks/bitcoin.rs:691`, confirming the filter belongs at the library layer but was never applied there.

### Finding Description
`scan_transaction` matches any output whose `script_pubkey` is a registered script (`networks/bitcoin/src/wallet/mod.rs:205`). `scan_block` iterates `for tx in &block.txdata` unconditionally (`networks/bitcoin/src/wallet/mod.rs:223`). A coinbase transaction paying the registered P2TR script therefore produces a `ReceivedOutput` with a real outpoint and real value. The only mitigation is a doc comment (`networks/bitcoin/src/wallet/mod.rs:218-219`) telling callers to do "a post-processing pass" or use `scan_transaction` on `block.txdata[1 ..]` — exactly the "the lock exists but one input channel isn't blocked" shape of CVE-2016-10894.

### Impact Explanation
`ReceivedOutput` is the type consumed by `SignableTransaction`/`multisig` to fund transactions. An output reported by `scan_block` from a coinbase is unspendable until maturity (100 blocks). A wallet/service built on bitcoin-serai that trusts `scan_block` will count these funds as received and attempt to spend them, producing transactions the network rejects — funds reported received that are not spendable, an accepted impact class. Any miner can trigger this at will by directing a coinbase payout to a known registered script (external/branch/change/forward offsets are deterministic via `hash_to_F` in `processor/src/networks/bitcoin.rs:308-344`, so the scripts are publicly derivable).

### Likelihood Explanation
Any miner (unprivileged third party who wins a block) can set a coinbase `script_pubkey` to the scanner's registered P2TR script; no cooperation from Serai validators is needed. Exploitation requires the downstream integrator to call the public `scan_block` API rather than re-implementing Serai's internal skip — plausible, since scanning whole blocks is the API's stated purpose. Impact is bounded to accounting/DoS of one deposit rather than theft, hence Medium at most.

### Recommendation
In `scan_block`, skip `block.txdata[0]` (or check `tx.is_coinbase()`) before calling `scan_transaction`, mirroring `processor/src/networks/bitcoin.rs:691`. If scanning coinbases is genuinely desired, add maturity metadata to `ReceivedOutput` (e.g., the block height) so callers can enforce spendability instead of relying on a doc comment.

### Proof of Concept
```rust
// Regtest-style PoC, mirroring networks/bitcoin/tests/wallet.rs::send_and_get_output
let mut scanner = Scanner::new(even_group_key).unwrap();
// A miner crafts/uses a coinbase tx paying p2tr_script_buf(group_key)
let block: Block = rpc.get_block(&hash).await.unwrap();      // txdata[0] is the coinbase
let outputs = scanner.scan_block(&block);
// outputs contains a ReceivedOutput for the coinbase outpoint
assert_eq!(outputs[0].outpoint(), &OutPoint::new(block.txdata[0].compute_txid(), 0));
// SignableTransaction::new(vec![outputs[0]], ...) produces a tx any node rejects
// with "bad-txns-premature-spend-of-coinbase" until 100 confirmations pass,
// yet the scanner already reported the funds as received.
```
The existing test at `networks/bitcoin/tests/wallet.rs:65-70` already demonstrates the behavior — it asserts `scan_block` finds the coinbase output — it just never treats the result as a defect.
