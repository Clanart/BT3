## Title
Server-Side Request Forgery via DataLayer mirror URLs enabling internal network enumeration - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can create an on-chain "mirror" coin for **any** DataLayer store (even one they do not own), embedding arbitrary URLs as coin memos. A victim node that is subscribed to that store id will later pull those attacker-supplied URLs into its local subscription table and issue outbound HTTP GET requests to them from the DataLayer service process, with no scheme/host restriction. This lets an unauthenticated-relative-to-the-victim attacker (any chain participant who can fund a mirror coin) force a victim's node to probe arbitrary internal network addresses and observe differing outcomes (success/parse-failure vs. connection failure), exactly analogous to the memos `/api/resource` SSRF where authenticated users could enumerate the internal network.

### Finding Description
`DataLayerWallet.create_new_mirror()` creates a `P2_PARENT`-puzzle "mirror" coin whose memos are `[launcher_id, *urls]`, with no check that the sender owns `launcher_id`: [1](#0-0) 

When any node processes this coin and is already tracking that launcher, it stores the mirror record (`urls` included, unvalidated) via `coin_added()`: [2](#0-1) 

The DataLayer service periodically syncs subscription URLs directly from these wallet-sourced mirrors with no URL/scheme/host validation: [3](#0-2) [4](#0-3) 

`fetch_and_validate()` then randomly selects one of these server URLs and attempts to download delta files from it: [5](#0-4) 

The actual HTTP request is performed in `http_download()`, which concatenates the attacker-controlled `server_info.url` with a filename and issues a GET request with no allow-list, no restriction on private/loopback/link-local addresses, and no scheme restriction beyond what `aiohttp` accepts: [6](#0-5) 

The RPC/CLI path `add_mirror` confirms any wallet can publish a mirror coin for any store id with arbitrary URLs and no ownership check enforced server-side either: [7](#0-6) [8](#0-7) 

### Impact Explanation
A victim DataLayer node subscribed to any store (including well-known/public stores) can be induced to make outbound HTTP requests to attacker-chosen hosts/ports (e.g., `http://127.0.0.1:<port>/...`, cloud metadata endpoints, or other internal-only services) from the machine running the node. The response handling in `download_file`/`insert_from_delta_file` distinguishes connection failures (`ClientConnectionError`) from successful-but-invalid responses (banned via `server_misses_file`, different backoff), giving an attacker an oracle to enumerate reachable internal hosts/ports and probe internal services — a direct analog of the referenced memos SSRF via `/api/resource`.

### Likelihood Explanation
Likelihood is high for any operator running a DataLayer node with mirror subscriptions enabled: creating a mirror coin only costs the specified `amount` + `fee` and requires no special privilege or ownership of the target store, and the periodic `update_subscriptions_from_wallet`/`fetch_and_validate` loop runs automatically without user interaction once subscribed.

### Recommendation
- Restrict mirror/subscription URLs to an explicit allow-list of schemes (`http`/`https`) and reject requests to loopback, link-local, and private/internal address ranges before issuing `aiohttp` requests in `http_download()` and `download_file()`.
- Consider requiring operator confirmation or configuration opt-in before automatically following externally-supplied mirror URLs from unverified/foreign mirror coins.
- Add DNS-rebinding-resistant IP validation (resolve then re-check the connecting IP) since hostname-based allow/deny lists alone are insufficient.

### Proof of Concept
1. Attacker (any funded wallet) calls `dl_new_mirror` / `add_mirror` for a victim-subscribed `launcher_id` with `urls=["http://127.0.0.1:6001", "http://169.254.169.254/latest/meta-data/"]` and a nominal amount/fee; pushes the transaction on chain. [8](#0-7) 
2. Once confirmed, any DataLayer node that already tracks that `launcher_id` records the mirror via `coin_added()`. [2](#0-1) 
3. On its next `periodically_manage_data()` cycle, the victim node calls `update_subscriptions_from_wallet()`, adding the attacker URLs to its local subscription table. [3](#0-2) 
4. `fetch_and_validate()` selects the malicious server and `http_download()` issues a GET to the attacker-chosen internal URL, with observable success/failure differences leaking network reachability information. [6](#0-5)

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
