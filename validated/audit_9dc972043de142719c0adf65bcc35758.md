### Title
Forfeiture penalty in `queueMGP` is computed from current vlMGP lock state, not the state during emission accrual, allowing forfeiture avoidance via `cancelUnlock` before harvest - ([File: VLMGP.sol](VLMGP.sol), [rewards/vlMGPBaseRewarder.sol](rewards/vlMGPBaseRewarder.sol))

### Summary
`MasterMagpie._sendMGPForVlMGPPool` calls `queueMGP(_amount, _account, _receiver)` which determines the forfeited share of the harvested MGP using `vlMGP.getRewardablePercentWAD(_account)` evaluated at call time. Since MasterMagpie's staking balance for the vlMGP pool is unaffected by `startUnlock`/`cancelUnlock` (only the final `unlock` reduces it), and forfeiture is a single snapshot rather than a time-weighted integral over the accrual window, an attacker who spends part of the accrual period in cooldown can call `cancelUnlock` immediately before harvesting to zero out the forfeiture that should have applied to that period.

### Finding Description
MasterMagpie tracks MGP emissions for the vlMGP staking pool purely by `userInfo[address(vlmgp)][account].amount`, which is only changed by `depositVlMGPFor` (on `_lock`) and `withdrawVlMGPFor` (on final `_unlock`) [1](#0-0) . Calling `startUnlock` or `cancelUnlock` never touches this staked amount, so MGP continues to accrue at full rate in MasterMagpie's `accMGPPerShare` accounting regardless of whether the user is "locked" or "in cooldown" [2](#0-1) .

When the user later claims through `_multiClaim` -> `_sendMGPForVlMGPPool` -> `queueMGP`, the forfeiture percentage is computed from `vlMGP.getRewardablePercentWAD(_account)`, which only reflects the account's *current* split between `getUserTotalLocked` and `getUserAmountInCoolDown` [3](#0-2) [4](#0-3) [5](#0-4) . `cancelUnlock` simply zeroes `amountInCoolDown` for the given slot without touching MasterMagpie or the reward accounting at all [2](#0-1) .

Because the forfeiture calculation is a single point-in-time snapshot rather than a time-weighted average across the accrual period, an attacker who spent part of the emission window in cooldown can call `cancelUnlock` right before triggering harvest so that `getRewardablePercentWAD` reports 100% locked (`inCoolDown == 0`), making `_calExpireForfeit` return `forfeitAmount = 0` for the entire batch of pending MGP, including the portion that accrued while genuinely in cooldown and should have been penalized and routed to `_queueNewRewardsWithoutTransfer` for other vlMGP holders.

### Impact Explanation
This results in theft of unclaimed yield: MGP that should have been forfeited to the vlMGP reward pool (distributed to honest lockers via `_queueNewRewardsWithoutTransfer`) is instead paid in full to the attacker [6](#0-5) . This matches the "theft of unclaimed yield" impact class.

### Likelihood Explanation
No privileged role is required — `cancelUnlock` and MasterMagpie's harvest/claim entrypoints are both public/external functions callable by any vlMGP holder who is also staked in a MasterMagpie pool earning MGP [2](#0-1) . The attacker only needs to have previously called `startUnlock` (normal usage) and can freely call `cancelUnlock` at any time with no cooldown-lock restriction on cancellation itself, then immediately call the harvest function in the same transaction/block. This is fully repeatable each time MGP has accrued while the attacker was in cooldown.

### Recommendation
Compute forfeiture using a time-weighted integral of the account's lock/cooldown state over the actual accrual period (e.g., checkpoint the rewardable percent whenever `startUnlock`/`cancelUnlock`/`unlock` change state, and accumulate forfeiture incrementally per MasterMagpie `updatePool`/harvest call), rather than sampling `getRewardablePercentWAD` only at claim time in `_calExpireForfeit`.

### Proof of Concept
Foundry test outline:
1. Deploy MasterMagpie, VLMGP, `vlMGPBaseRewarder`; set MGP emission rate for the vlMGP pool.
2. Attacker locks `X` MGP (`VLMGP.lock`), which auto-stakes into MasterMagpie via `depositVlMGPFor`.
3. Attacker calls `startUnlock(X)` to move the full amount into cooldown.
4. Advance time so MGP emissions accrue substantially in MasterMagpie (`accMGPPerShare` increases) while the attacker is fully in cooldown.
5. Branch A (baseline): attacker calls harvest/claim directly while still in cooldown; assert `MGPHarvested` event / `queueMGP` forfeitAmount > 0 matching `getRewardablePercentWAD` at that time.
6. Branch B (exploit): reset state; attacker calls `VLMGP.cancelUnlock(slotIndex)` in the same block immediately before calling the harvest/claim entrypoint; assert `queueMGP`'s computed `forfeitAmount == 0` despite identical MGP accrual history, and that the attacker receives the full `_amount` with nothing routed to `_queueNewRewardsWithoutTransfer`.
7. Compare forfeited amounts between Branch A and Branch B for identical emission history to demonstrate the discrepancy and quantify the stolen yield.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function queueMGP(uint256 _amount, address _account, address _receiver) override external onlyManager nonReentrant returns (bool) {
        IERC20(vlMGP.MGP()).safeTransferFrom(msg.sender, address(this), _amount);
        
        uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
        uint256 rewardableAmount = _amount - forfeitAmount;
        
        if (forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));

        if (rewardableAmount > 0) {
            IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
            emit MGPHarvested(_account, rewardableAmount, forfeitAmount);
        }

        return true;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
