### Title
Missing forfeit-percentage calculation in `mWOMSVBaseRewarder._calExpireForfeit` permanently negates the early-unlock reward penalty for mWOMSV holders - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is supposed to reduce the reward paid to a user who has begun unlocking (is in cooldown) by applying the same "rewardable percent" ratio that `vlMGPBaseRewarder` and the lock contracts (`VLMGP.sol`, `wombat/mWomSV.sol`) implement, but the multiplication by that ratio was omitted, so the forfeit calculation always evaluates to zero.

### Finding Description
`vlMGPBaseRewarder._calExpireForfeit` correctly fetches the user's time-weighted rewardable ratio and scales the reward amount by it: [1](#0-0) 

`mWomSV.sol` implements the equivalent ratio getter used for this exact purpose, decreasing as a fraction of tokens is placed in cool-down for unlocking: [2](#0-1) 

However, `mWOMSVBaseRewarder._calExpireForfeit` never calls `mWOMSV.getRewardablePercentWAD(_account)` at all. It sets `rewardableAmount = _amount` directly, so `forfeitAmount = _amount - rewardableAmount` is always `0`: [3](#0-2) 

This function is invoked from `_sendReward`, which is called from the user-facing `getReward`/`getRewards` entry points (reachable by an ordinary staker through `MasterMagpie`'s harvest flow), and any forfeited amount would otherwise be redistributed to remaining stakers via `_queueNewRewardsWithoutTransfer`: [4](#0-3) [5](#0-4) 

Because the ratio is never applied, a user who has initiated an unlock (partially or fully in cool-down, with a `getRewardablePercentWAD` below `1e18`) still receives 100% of the accrued mWOMSV-pool reward with no penalty, and the portion that should have been forfeited back to the pool (`_queueNewRewardsWithoutTransfer`) is never generated.

### Impact Explanation
The forfeit-on-early-unlock mechanism is a core economic control that is supposed to compensate long-term lockers by redistributing part of an early-unlocker's yield back into the pool. With this calculation broken, that redistribution never happens: early-cooldown users always keep 100% of yield they were only entitled to a reduced share of, and the remaining long-term stakers permanently lose the extra yield they should have received from other users' forfeitures. This is a direct, ongoing theft/permanent loss of yield that would otherwise accrue to honest long-term lockers, mirroring the "incorrect ratio calculation breaking an economic invariant" bug class from the reference report (there, a missing/incorrect application of a percentage factor broke the intended buffer; here, a missing application of a percentage factor breaks the intended forfeit).

### Likelihood Explanation
This triggers on every single call to `getReward`/`getRewards` for the mWOMSV reward pool by any user who has ever partially or fully entered a cool-down/unlock slot — a completely ordinary, unprivileged action (lock, then unlock, then claim rewards). No special conditions, admin actions, or race conditions are required; the bug fires deterministically on every affected claim.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`: fetch `mWOMSV.getRewardablePercentWAD(_account)` and scale `_amount` by it before comparing/subtracting, e.g.:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }
    return forfeitAmount;
}
```
This requires that `ILocker` (the interface `mWOMSV` is typed as) exposes `getRewardablePercentWAD`, matching the `IVLMGP` interface used by `vlMGPBaseRewarder`.

### Proof of Concept
1. User locks mWOM into `mWomSV` and accrues mWOMSV rewards over time via `mWOMSVBaseRewarder`.
2. User calls the unlock function on `mWomSV`, moving a portion of their balance into a cool-down slot; per `getRewardablePercentWAD` (`wombat/mWomSV.sol:181-206`), their rewardable percent immediately drops below `1e18` (i.e., below 100%).
3. User calls `MasterMagpie`'s harvest path, which invokes `mWOMSVBaseRewarder.getReward`/`getRewards` → `_sendReward` → `_calExpireForfeit(_account, userRewards[...])`.
4. Because `_calExpireForfeit` never reads `getRewardablePercentWAD`, `rewardableAmount == _amount` and `forfeitAmount == 0` regardless of the user's actual cool-down ratio, so `toSend = userRewards[...] - 0` — the user receives their full reward with zero forfeiture.
5. Repeating this for any user who unlocks early confirms the forfeit mechanism never activates, and `_queueNewRewardsWithoutTransfer` (which would redistribute forfeited amounts to remaining stakers) is never invoked with a nonzero amount for this pool.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
