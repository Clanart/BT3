### Title
Unauthenticated identity DKG encryption keys publicly expose secret shares - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
`EncryptionKeyMessage::read` accepts any canonical group element as a participant's long-term encryption key, including the identity element, and `Decryption::register` stores it without validating that it is non-identity or proving possession of a corresponding private key. [1](#0-0) [2](#0-1) 

Because ECDH is computed as `msg_private * enc_public`, an identity registration makes every shared key equal to the public identity point. [3](#0-2) [4](#0-3) 

The identity encoding is not bound to the participant's PedPoP proof: the proof challenge commits only to the polynomial commitments, while `enc_key` is appended separately after the signed `Commitments` message. [5](#0-4) [6](#0-5) 

### Finding Description
A PedPoP registration message consists of `Commitments` followed by `enc_key`. [7](#0-6) 

`Commitments::read` preserves the encoded commitments in `cached_msg`, and the proof-of-knowledge challenge covers `context`, `participant`, `nonce`, and only those commitment bytes. [8](#0-7) [5](#0-4) 

Consequently, replacing the trailing `enc_key` encoding does not invalidate the PedPoP proof. [7](#0-6) 

`Ciphersuite::read_G` checks canonicity but does not reject the identity point. [9](#0-8) 

`Decryption::register` directly inserts the supplied point as that participant's encryption key. [2](#0-1) 

When a sender encrypts a secret share to that participant, it computes `ecdh(key, to)` where `to` is the registered public key. [10](#0-9) [11](#0-10) 

For `to = identity`, the ECDH output is always `identity`, independent of the sender's ephemeral private key and the recipient's registered scalar. [3](#0-2) 

The stream cipher key is then deterministically derived from the DKG context and the public encoding of that identity shared key, with a fixed IV. [12](#0-11) 

### Impact Explanation
Any observer can derive the ChaCha20 key for every share encrypted to a participant whose registration uses the identity point. [12](#0-11) 

This publicly exposes all `SecretShare<C::F>` plaintexts sent to that participant, allowing recovery of the participant's aggregated threshold secret share from the encrypted protocol messages. [13](#0-12) 

The issue is not merely malformed-input rejection: the malformed registration produces valid protocol state and causes honest senders to encrypt private shares under a publicly known key. [2](#0-1) [11](#0-10) 

This is a High-severity secret-share confidentiality failure when untrusted registration bytes can enter PedPoP.

### Likelihood Explanation
The attacker only needs to submit a syntactically valid `EncryptionKeyMessage` whose final encoded point is the canonical identity encoding. [7](#0-6) 

They do not need to know a private key for the identity point, forge the PedPoP Schnorr proof, or modify the signed commitment bytes. [14](#0-13) 

The proof remains valid because `enc_key` is outside `cached_msg` and outside the `challenge` input. [5](#0-4) [8](#0-7) 

### Recommendation
Reject identity and any other unusable/small-order group elements in `EncryptionKeyMessage::read` or `Decryption::register` before storing `enc_key`. [1](#0-0) [2](#0-1) 

Bind `enc_key` into the PedPoP proof transcript, or require a separate proof of possession for the registered encryption private key. [5](#0-4) 

Additionally reject identity `msg.key` values and require nonzero public keys before accepting an `EncryptedMessage`, since Schnorr verification against an identity public key reduces to `R == sG` and does not prove possession of a discrete logarithm. [15](#0-14) [16](#0-15) 

### Proof of Concept
The following test-shaped exploit demonstrates the public-key-substitution path for `Ristretto`, whose canonical identity encoding is `[0u8; 32]`:

```rust
use zeroize::Zeroizing;
use rand_core::OsRng;

use dalek_ff_group::Ristretto;
use ciphersuite::{group::GroupEncoding, Ciphersuite};

use dkg::{Participant, ThresholdParams};
use pedpop::{KeyGenMachine, EncryptionKeyMessage, Commitments};

let params =
  ThresholdParams::new(2, 2, Participant::new(2).unwrap()).unwrap();
let context = [7u8; 32];

// Generate an otherwise valid commitment message.
let (machine, msg) =
  KeyGenMachine::<Ristretto>::new(params, context)
    .generate_coefficients(&mut OsRng);

let mut bytes = msg.serialize();

// Replace only the trailing EncryptionKeyMessage::enc_key with identity.
// Commitments::cached_msg and its Schnorr PoK do not cover this field.
let point_len = <Ristretto as Ciphersuite>::G::generator()
  .to_bytes()
  .as_ref()
  .len();
let enc_key_offset = bytes.len() - point_len;
bytes[enc_key_offset..].copy_from_slice(&[0u8; 32]);

// Parsing succeeds because identity is a canonical group encoding.
let malicious =
  EncryptionKeyMessage::<Ristretto, Commitments<Ristretto>>::read(
    &mut bytes.as_slice(),
    params,
  )
  .unwrap();

// Another participant's SecretShareMachine registers this key.
// Subsequent Encryption::encrypt calls compute:
//   ecdh(ephemeral_private, identity) == identity
// and therefore encrypt the SecretShare under a publicly derivable key.
```

An observer can reconstruct the ChaCha20 keystream by running the public transcript in `cipher(context, identity)`: append `context`, domain-separate with `encryption_key`, append the identity point encoding as `shared_key`, take `challenge("key")[..32]`, and use the fixed `b"DKG IV v0.2\0"` IV. [12](#0-11) 

Applying that keystream to each `EncryptedMessage.msg` sent to the malicious participant reveals every scalar contribution addressed to them. [17](#0-16)
