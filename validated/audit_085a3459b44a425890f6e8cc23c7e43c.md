## Title
`check_metadata_format` gated by `RESOURCE_GROUPS` feature lets malformed `COMPILATION_METADATA_KEY` bytes pass publish verification and be silently swallowed by `get_compilation_metadata` - ([File: types/src/vm/module_metadata.rs])

### Summary
`verify_module_metadata_for_module_publishing` only invokes the strict, deserialization-enforcing `check_metadata_format` when the `RESOURCE_GROUPS` feature flag is enabled. When it is disabled, malformed `COMPILATION_METADATA_KEY` metadata bytes are never validated at publish time, and are stored on-chain as-is. Any later consumer of that metadata, such as `get_compilation_metadata`, uses `.ok()` to swallow deserialization errors, silently returning `None` instead of surfacing the corruption.

### Finding Description
`verify_module_metadata_for_module_publishing` gates the strict check behind the resource-groups feature flag: [1](#0-0) 

`check_metadata_format` is the only code path that performs strict `bcs::from_bytes::<CompilationMetadata>` deserialization and rejects the publish (`MalformedError::DeserializedError`) on bad bytes: [2](#0-1) 

If `RESOURCE_GROUPS` is disabled, this check is skipped entirely for the whole module — `get_metadata_from_compiled_code` (called unconditionally afterward) only reads `APTOS_METADATA_KEY`/`APTOS_METADATA_KEY_V1`, never `COMPILATION_METADATA_KEY`, so malformed compilation-metadata bytes never trigger any error and the publish succeeds: [3](#0-2) 

Downstream, `get_compilation_metadata` reads the same key but silently discards deserialization failures via `.ok()`: [4](#0-3) 

This function is relied upon by mainnet-gating logic in `reject_unstable_bytecode` / `reject_unstable_bytecode_for_script`, which treats `None` as "no compilation metadata present" (i.e., not unstable) rather than "corrupted metadata, reject": [5](#0-4) 

### Impact Explanation
The practical severity is limited to compiler-version/unstable-bytecode gating, not code-ownership, compatibility, or dependency integrity — the actual module bytes, ownership, and compatibility checks are unaffected. The impact is that an attacker with an intentionally malformed `COMPILATION_METADATA_KEY` blob can bypass the `unstable` bytecode rejection check on mainnet, since `get_compilation_metadata` treats corrupted metadata identically to "no metadata," allowing a module explicitly marked (in a differently-encoded but structurally-detectable way) unstable/dev-only to still be treated as safe to publish/execute — but this depends entirely on `RESOURCE_GROUPS` being disabled.

### Likelihood Explanation
This is **not currently exploitable on live mainnet**. `RESOURCE_GROUPS` is a long-standing, foundational feature (resource groups/tables) that has been enabled on Aptos mainnet since well before this repository snapshot — it is not an experimental/toggleable-off flag in current mainnet configuration. I was unable to fully confirm the exact current mainnet feature-flag state within the available tool budget (the search for `RESOURCE_GROUPS` default status in `aptos_features.rs`/genesis config did not return conclusive default-value data), but resource groups underpin core `#[resource_group]`/`#[resource_group_member]` attributes used pervasively by the Aptos Framework itself (e.g., `0x1::object`, `0x1::fungible_asset`), so it must be enabled for the framework/genesis to function. The described bypass is therefore a theoretical code-path inconsistency (a defense-in-depth gap tied to an unrelated feature flag) rather than an exploitable vulnerability under the current mainnet feature configuration described in the review scope ("current mainnet relevance").

### Recommendation
Decouple the `COMPILATION_METADATA_KEY` strict-format check from the `RESOURCE_GROUPS` feature flag — always validate `CompilationMetadata` deserializability in `verify_module_metadata_for_module_publishing`, or make `get_compilation_metadata` distinguish "absent" from "malformed" (e.g., propagate a `Result` and fail closed / reject publish, at least for `reject_unstable_bytecode`) so a decode failure can never be conflated with "not unstable."

### Proof of Concept
1. Construct a module with a metadata entry keyed `COMPILATION_METADATA_KEY` containing bytes that are valid BCS-length-prefixed garbage that fails `bcs::from_bytes::<CompilationMetadata>`.
2. Publish with `RESOURCE_GROUPS` disabled (if such a configuration were reachable on a given chain instance) — `verify_module_metadata_for_module_publishing` succeeds because `check_metadata_format` is skipped.
3. Call `get_compilation_metadata(module)` post-publish and observe it returns `None` despite the on-chain bytes being present and malformed, confirming `reject_unstable_bytecode` cannot detect the corruption.

Given the scope's mainnet-relevance gate, and the practical certainty that `RESOURCE_GROUPS` is enabled on mainnet (required by the Framework itself), this finding is reported for completeness but should be treated as low-confidence/low-priority under the "current mainnet relevance" standard rather than a confirmed exploitable vulnerability.

/// Check if the metadata has unknown key/data types
fn check_metadata_format(module: &CompiledModule) -> Result<(), MalformedError> {
    let mut exist = false;
    let mut compilation_key_exist = false;
    for data in module.metadata.iter() {
        if data.key == *APTOS_METADATA_KEY || data.key == *APTOS_METADATA_KEY_V1 {
            if exist {
                return Err(MalformedError::DuplicateKey);
            }
            exist = true;

            if data.key == *APTOS_METADATA_KEY {
                bcs::from_bytes::<RuntimeModuleMetadata>(&data.value)
                    .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
            } else if data.key == *APTOS_METADATA_KEY_V1 {
                bcs::from_bytes::<RuntimeModuleMetadataV1>(&data.value)
                    .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
            }
        } else if data.key == *COMPILATION_METADATA_KEY {
            if compilation_key_exist {
                return Err(MalformedError::DuplicateKey);
            }
            compilation_key_exist = true;
            bcs::from_bytes::<CompilationMetadata>(&data.value)
                .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
        } else {
            return Err(MalformedError::UnknownKey(data.key.clone()));
        }
    }

    Ok(())
}

pub fn get_metadata_from_compiled_code(
    code: &impl CompiledCodeMetadata,
) -> Option<RuntimeModuleMetadataV1> {
    if let Some(data) = find_metadata(code.metadata(), APTOS_METADATA_KEY_V1) {
        let mut metadata = bcs::from_bytes::<RuntimeModuleMetadataV1>(&data.value).ok();
        // Clear out metadata for v5, since it shouldn't have existed in the first place and isn't
        // being used. Note, this should have been gated in the verify module metadata.
        if code.version() == 5 {
            if let Some(metadata) = metadata.as_mut() {
                metadata.struct_attributes.clear();
                metadata.fun_attributes.clear();
            }
        }
        metadata
    } else if let Some(data) = find_metadata(code.metadata(), APTOS_METADATA_KEY) {
        // Old format available, upgrade to new one on the fly
        let data_v0 = bcs::from_bytes::<RuntimeModuleMetadata>(&data.value).ok()?;
        Some(data_v0.upgrade())
    } else {
        None
    }
}

pub fn verify_module_metadata_for_module_publishing(
    module: &CompiledModule,
    features: &Features,
) -> Result<(), MetaDataValidationError> {
    if features.is_enabled(FeatureFlag::SAFER_METADATA) {
        check_module_complexity(module)?;
    }

    if features.are_resource_groups_enabled() {
        check_metadata_format(module)?;
    }
    let metadata = if let Some(metadata) = get_metadata_from_compiled_code(module) {
        metadata
    } else {
        return Ok(());
    };

    /// Check whether the bytecode can be published to mainnet based on the unstable tag in the metadata
    fn reject_unstable_bytecode(&self, modules: &[CompiledModule]) -> VMResult<()> {
        if self.chain_id().is_mainnet() {
            for module in modules {
                if let Some(metadata) = get_compilation_metadata(module) {
                    if metadata.unstable {
                        return Err(PartialVMError::new(StatusCode::UNSTABLE_BYTECODE_REJECTED)
                            .with_message(
                                "code marked unstable is not published on mainnet".to_string(),
                            )
                            .finish(Location::Undefined));
                    }
                }
            }
        }
        Ok(())
    }
