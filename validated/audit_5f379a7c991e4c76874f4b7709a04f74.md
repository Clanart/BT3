### Title
Unauthenticated `auction_submitBid` RPC lets any caller occupy a searcher's per-block bid slot, causing legitimate higher bids to be rejected - ([File: kaiax/auction/impl/api.go])

### Summary
`AuctionAPI.SubmitBid` (exposed as the `auction_submitBid` RPC method) accepts a fully-formed, previously-signed `BidInput` from any caller and forwards it unchanged to `BidPool.AddBid`. The only checks performed are cryptographic (searcher/auctioneer signatures) and structural (block-number window, bid size, sig length). There is no check that the RPC caller is the registered `Auctioneer`, nor any binding between the call and a fresh, single-use bid. Because a valid `Bid` object (searcher signature + auctioneer signature) is portable data, anyone who has ever observed one (e.g., a bid that was broadcast, gossiped, or simply resent) can resubmit it through this endpoint to claim the `bidWinnerMap[blockNumber][sender]` slot for that searcher before the searcher's real, higher-value bid for a different target transaction in the same block arrives, causing the legitimate bid to be rejected with `ErrBidSenderExists`. This mirrors the reported `checkOrder`/`_useNonce` pattern: a permissionless call that consumes a per-trader resource (nonce/winner-slot) and makes a legitimate order/bid from that trader unusable.

### Finding Description
`SubmitBid` performs no authentication of the caller: [1](#0-0) 

It decodes and re-broadcasts the embedded target transaction, then calls `bidPool.AddBid(bid)` regardless of whether the caller is the auctioneer: [2](#0-1) 

`AddBid` -> `insertBid` enforces a one-winner-per-sender-per-block rule via `bidWinnerMap`/`senderHasDifferentWinner`: [3](#0-2) [4](#0-3) 

The same rule is checked pre-lock in `validateBid`: [5](#0-4) 

Because the bid object itself (searcher signature + auctioneer signature over the searcher signature) is the only thing validated — not the identity of whoever calls the RPC — any party holding a previously valid bid payload (e.g., one they observed being relayed, or one from an earlier, unconsummated auction round for the same upcoming block window) can call `auction_submitBid` and take the `bidWinnerMap` slot for that searcher first. A companion test confirms that only one bid per sender per block can ever be accepted and that this is a race that is explicitly not serialized by sender identity but by insertion order: [6](#0-5) 

This is structurally identical to the reported bug class: a public/unprivileged entry point consumes a scarce per-trader resource (there: `nonces[trader][nonce]`; here: `bidWinnerMap[blockNumber][sender]`) without verifying that the caller is authorized to act on behalf of that trader/searcher, letting anyone render a legitimate pending order/bid from that trader unusable for the round.

### Impact Explanation
If exploited, a legitimate searcher's real (higher-bid) submission for the target block is rejected with `ErrBidSenderExists`, so their intended auction transaction never enters the bid pool and is not executed by the block proposer. This is a direct denial-of-service against specific searchers/auction participants and can be used to censor or extort particular bidders, undermining KIP-249 auction fairness — a core MEV/auction-settlement guarantee of the module. It does not directly move funds, but it blocks legitimate auction settlement for the targeted party for that block, which is a concrete auction-settlement-denial impact.

### Likelihood Explanation
Exploitability requires: (1) the caller to reach the `auction` RPC namespace, which is registered as `Public: false` — i.e., it is not exposed over public HTTP by default and typically only enabled where the node operator opts in (as documented, only the CN talks to the Auctioneer); and (2) possession of a previously valid bid payload for the target sender (obtained via any relay/eavesdropping/re-send opportunity, not requiring the searcher's or auctioneer's private key). Given the namespace-gating, this is not trivially reachable from arbitrary public RPC on a default deployment, which lowers likelihood versus the original report's fully public `checkOrder`. However, wherever the `auction` namespace is enabled for the Auctioneer's use, there is no additional check binding the call to the Auctioneer's actual origin, so any process with access to that RPC endpoint (which may be shared infrastructure) can perform the replay.

### Recommendation
- Bind `SubmitBid` (and `bidPool.AddBid`) to a fresh, single-use commitment: include the current/target block number and a monotonic per-searcher sequence in the signed payload and reject bids whose sequence was already consumed or is not the latest observed for that (sender, blockNumber).
- Track and reject bids by hash of the searcher signature (not just full bid hash) so an already-seen searcher signature cannot be replayed as a "new" bid to squat the sender slot.
- Consider requiring the RPC caller to be an authenticated Auctioneer session (e.g., mTLS/allow-listed IP, not just relying on payload signatures) for the `auction` namespace, and/or make replacement of a sender's existing pending bid always allowed if strictly higher (already true) but disallow re-entry of a bid whose signature has already been observed/rejected/expired for that block.

### Proof of Concept
1. Attacker (or a compromised relay with access to the `auction` RPC namespace) observes/obtains any historical or in-flight valid `BidInput` for searcher `S` targeting block `N` (searcher signature + auctioneer signature are static, portable data).
2. Before searcher `S`'s genuine higher bid for a different target transaction in block `N` is submitted, the attacker calls `auction_submitBid` with the captured bid data.
3. `SubmitBid` → `bidPool.AddBid` → `insertBid` succeeds and sets `bp.bidWinnerMap[N][S] = attackerReplayedBidHash`: [7](#0-6) 
4. When searcher `S`'s real bid for block `N` arrives, `senderHasDifferentWinner` returns true (different bid hash for same sender/block) and `AddBid` returns `auction.ErrBidSenderExists`, so the legitimate bid is rejected and never enters the pool, denying `S`'s intended auction transaction execution for block `N`.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

// Two concurrent same-sender bids with different targets must not both succeed.
func TestBidPool_ConcurrentAddBid_OneWinnerPerSender(t *testing.T) {
	bidA, bidB := testBids[0], testBids[4]
	require.Equal(t, bidA.Sender, bidB.Sender)
	require.Equal(t, bidA.BlockNumber, bidB.BlockNumber)
	require.NotEqual(t, bidA.TargetTxHash, bidB.TargetTxHash)

	for i := 0; i < 10; i++ {
		func() {
			mockCtrl := gomock.NewController(t)
			defer mockCtrl.Finish()

			chain := chain_mock.NewMockBlockChain(mockCtrl)
			chain.EXPECT().CurrentBlock().Return(types.NewBlockWithHeader(&types.Header{Number: big.NewInt(1)})).AnyTimes()

			pool := NewBidPool(testChainConfig, chain, &auction.AuctionConfig{MaxBidPoolSize: 1024})
			require.NotNil(t, pool)
			pool.start()
			atomic.StoreUint32(&pool.running, 1)
			defer pool.stop()
			pool.auctioneer = testAuctioneer
			pool.auctionEntryPoint = testAuctionEntryPoint

			var (
				wg         sync.WaitGroup
				errA, errB error
			)
			startGate := make(chan struct{})

			wg.Add(2)
			go func() {
				defer wg.Done()
				<-startGate
				_, errA = pool.AddBid(bidA)
			}()
			go func() {
				defer wg.Done()
				<-startGate
				_, errB = pool.AddBid(bidB)
			}()
			close(startGate)
			wg.Wait()

			pool.bidMu.RLock()
			_, gotA := pool.bidMap[bidA.Hash()]
			_, gotB := pool.bidMap[bidB.Hash()]
			pool.bidMu.RUnlock()

			require.False(t, errA == nil && errB == nil && gotA && gotB,
				"iter %d: both same-sender bids accepted", i)
		}()
	}
}
