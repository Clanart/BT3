### Title
Unbounded Batch Size in PlotNFT Reward Claim Can Permanently DoS Fund Recovery - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`)

### Summary
`PlotNFT2Wallet.claim_rewards` builds a single spend bundle that spends **every** unclaimed pool-reward coin belonging to a PlotNFT in one transaction, with no cap on the number of reward coins included. If the number of accumulated, unclaimed reward coins grows large enough, the resulting spend bundle's CLVM cost exceeds `max_tx_clvm_cost` / `MAX_BLOCK_COST_CLVM`, and the claim transaction can never be accepted by the mempool or included in a block — mirroring the reported "gas exhaustion" pattern where an unbounded reward-transfer loop makes reward distribution unexecutable.

### Finding Description
`claim_rewards` fetches *all* pending rewards via `get_pool_rewards` and passes the full list straight into `PlotNFT.claim_pool_rewards`, which creates one `CoinSpend` per reward coin plus a `SendMessage` condition per reward inside the singleton's delegated puzzle: [1](#0-0) 

Each reward coin adds a `CREATE_COIN`+`SendMessage`+`AssertCoinAnnouncement` cost, and `PlotNFT.claim_pool_rewards` unconditionally builds a `CoinSpend` for every element of `rewards_to_claim`: [2](#0-1) 

There is no batching or size cap here. Contrast this with the legacy `PoolWallet.claim_pool_rewards`, which explicitly caps the number of coins claimed per transaction via `max_spends_in_tx` (`DEFAULT_MAX_CLAIM_SPENDS`) precisely to keep the spend bundle under the block cost limit: [3](#0-2) 

The mempool enforces `max_tx_clvm_cost = MAX_BLOCK_COST_CLVM / 2` on any single spend bundle, rejecting anything above it: [4](#0-3) 

Because `PlotNFT2Wallet.claim_rewards` has no equivalent cap, a PlotNFT (especially one left unclaimed for a long time in self-custody, accumulating one reward coin per farmed block) can reach a state where the only available "claim" transaction always exceeds the cost limit and is permanently rejected.

### Impact Explanation
This is not merely a resource/gas concern but a direct availability/fund-recovery issue: once the unclaimed reward set grows past the cost threshold, the wallet-level `claim_rewards` action becomes structurally unable to produce a valid spend bundle, since it always tries to claim the entire set atomically (the intermediate reward puzzle uses a `SendMessage`/announcement chain tying all reward-coin spends to the single singleton spend). Users' farmed XCH rewards become effectively stuck behind a transaction that can never be accepted — a spend-triggered halt of reward claiming for that coin set, requiring manual/low-level intervention (e.g., building a custom partial-claim spend bundle) that isn't exposed by the standard wallet API.

### Likelihood Explanation
Likelihood is moderate: it requires a PlotNFT accumulating many reward coins without being claimed (e.g., self-custody PlotNFT farming for an extended period, or a user who simply doesn't call `claim_rewards` often). Since block rewards accrue automatically to the PlotNFT's p2_singleton, this is a plausible and even expected usage pattern rather than an attacker-crafted edge case.

### Recommendation
Introduce a batching mechanism in `PlotNFT2Wallet.claim_rewards`/`PlotNFT.claim_pool_rewards` analogous to `PoolWallet.claim_pool_rewards`'s `max_spends_in_tx`/`DEFAULT_MAX_CLAIM_SPENDS`: cap the number of reward coins claimed per spend bundle, estimate cost before finalizing the bundle, and allow multiple sequential claim transactions to fully recover rewards when the pending set is large.

### Proof of Concept
1. Create a PlotNFT2Wallet in self-custody mode and let it farm/accumulate a large number of block rewards without calling `claim_rewards` (each farmed block adds one `PoolReward` via `coin_added`, see `chia/wallet/plotnft_wallet/plotnft_wallet.py` lines 651-657).
2. Once the number of unclaimed rewards is large enough that the combined `CREATE_COIN`+`SendMessage`+`AssertCoinAnnouncement` cost across all reward coins exceeds `max_tx_clvm_cost`, call `claim_rewards`.
3. The resulting `WalletSpendBundle` fails mempool admission (`ValueError`/`BLOCK_COST_EXCEEDS_MAX`-equivalent) because `claim_rewards` and `PlotNFT.claim_pool_rewards` include every pending reward with no batching, unlike `PoolWallet.claim_pool_rewards`'s `max_spends_in_tx` guard.

    def claim_pool_rewards(
        self,
        rewards_to_claim: list[PoolReward],
        reward_delegated_puzzles_and_solutions: list[DelegatedPuzzleAndSolution],
    ) -> list[CoinSpend]:
        if self.pooling:
            raise ValueError("Cannot claim rewards while pooling. If you're a pool, try `forward_pool_rewards`")
        if len(rewards_to_claim) != len(reward_delegated_puzzles_and_solutions):
            raise ValueError("Number of rewards and delegated puzzles and solutions must match")
        dpuz_and_solution = DelegatedPuzzleAndSolution(
            puzzle=Program.to(
                (
                    1,
                    [
                        CreateCoin(
                            puzzle_hash=self.inner_puzzle_hash(),
                            amount=self.coin.amount,
                            memos=[self.singleton_struct.struct_hash()],
                        ).to_program(),
                        *(
                            SendMessage(
                                msg=dpuz_and_sol.puzzle.get_tree_hash(),
                                sender=MessageParticipant(puzzle_hash_committed=self.puzzle_hash(nonce=0)),
                                receiver=MessageParticipant(coin_id_committed=reward.coin.name()),
                            ).to_program()
                            for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
                        ),
                    ],
                )
            ),
            solution=Program.to([]),
        )
        return [
            self.singleton_action_spend(
                inner_solution=self.puzzle_with_restrictions().solve(
                    member_validator_solutions=[],
                    dpuz_validator_solutions=[],
                    member_solution=self.bls_member.solve(),
                    delegated_puzzle_and_solution=dpuz_and_solution,
                )
            ),
            *(
                make_spend(
                    coin=reward.coin,
                    puzzle_reveal=reward.puzzle(),
                    solution=reward.solve(
                        self.inner_puzzle_hash(),
                        delegated_puzzle_and_solution=dpuz_and_sol,
                    ),
                )
