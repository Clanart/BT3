### Title
`GaslessSwapRouter` registry migration mid-flight strands lent gas and orphans ERC20 approvals for pending gasless swaps - (File: kaiax/gasless/impl/getter.go)

### Summary
The `gasless` (KIP-247) module caches a single, block-scoped `swapRouter` address that it re-reads from the `Registry` contract every block and uses to validate whether a pending `Approve`/`Swap` pair is still "gasless". If the `GaslessSwapRouter` address registered in `Registry` is changed while a user's `GaslessApproveTx` has already been executed (allowance granted to the *old* router) but the matching `GaslessSwapTx` has not yet executed, the swap becomes permanently un-executable as a gasless transaction, the user's ERC20 allowance is stranded on the old router, and any gas already advanced by the block proposer via the `LendTx` cannot be recovered because the repayment only happens inside a successful `swapForGas` call. This mirrors the `PaymentSettler::setStablecoin` bug class: an admin/governance-controlled address swap that is not gated on "no in-flight operations depending on the old address," causing stuck funds and inability for legitimate counterparties to complete their transaction.

### Finding Description
`GaslessModule` maintains `g.swapRouter` and `g.allowedTokens`, refreshed once per block from the `Registry` contract via `updateAddresses`/`getGaslessInfo`: [1](#0-0) 

Whether a signed transaction qualifies as a valid `GaslessApproveTx` or `GaslessSwapTx` is determined by comparing the tx's baked-in spender/router address against the **current** `g.swapRouter`, not the address that was active when the user signed the transaction: [2](#0-1) 

The full pairing check in `VerifyExecutable` re-validates both legs independently against the current router before treating them as a bundle and generating the `LendTx`: [3](#0-2) 

The `LendTx` (proposer-funded gas advance) and its repayment accounting are computed together, on the assumption that `Approve` + `Swap` execute atomically in the same bundle: [4](#0-3) [5](#0-4) 

If a `GaslessApproveTx` executes in one block (granting `token.approve(oldRouter, MaxUint256)` on-chain) but the paired `GaslessSwapTx` is not included in the same block (e.g., due to block gas limits, tx-pool timing, or simply arriving later), and the `Registry` record for `GaslessSwapRouterName` is updated to a new router address before the swap is processed (an admin-controlled, single-transaction/registry-write operation reachable at any time — the test harness itself demonstrates this exact operation), then: [6](#0-5) 

1. `isSwapTx` will fail (`g.swapRouter` is now the new address, but `args.Router` — baked into the user's signed calldata `tx.to` — is the old address), so the pending `GaslessSwapTx` is rejected as a gasless tx (`ErrSwapTxInvalid`) and is never promoted/bundled with a `LendTx`.
2. The sender typically holds no KAIA (that is the entire premise of "gasless"), so the tx cannot be processed as an ordinary self-funded transaction either — it is permanently stuck in the pool.
3. The `MaxUint256` allowance already granted by the user's executed `Approve` remains pointed at the now-abandoned old router, exactly analogous to stablecoins being "trapped" against a stale address in the report.
4. If a `LendTx` had already been issued for this pair in an earlier attempted bundle (proposer capital advanced in `LendAmount`), the compensating `repayAmount` collection inside `swapForGas` never occurs because the swap can never execute against the new router with the stale approval — the proposer's advanced KAIA is not recouped.

This is the direct on-chain analog of `PaymentSettler::setStablecoin`: a single administrative address-swap operation, performed without any check for in-flight two-phase operations that depend on the old address, breaks atomicity guarantees and results in stuck value.

### Impact Explanation
The impact is a denial-of-service on legitimate gasless swap settlement combined with potential loss of proposer-advanced gas funds (an unrecoverable value transfer) once a `LendTx` has been issued but repayment can no longer be triggered. It also results in permanently orphaned ERC20 approvals for affected users. This is a Medium-High impact given it can happen any time the `Registry` owner rotates the `GaslessSwapRouter` entry while gasless transactions are in flight — a legitimate, expected operational action (e.g., router upgrade or migration) rather than an attack requiring privileged compromise.

### Likelihood Explanation
Likelihood is Low-to-Medium: it requires the `Registry` owner to change `GaslessSwapRouterName`'s active address (a normal upgrade/maintenance action, not malicious by itself) while a `GaslessApproveTx` has been executed but its paired `GaslessSwapTx` has not yet landed in the same block — a realistic race given that pool promotion, bundling, and block inclusion do not happen atomically across the two legs, especially under network congestion or MEV/auction competition. The `Registry` activation mechanism (`activation` block, as seen in `TestPostInsertBlock`'s `Register(..., anotherGSR, big.NewInt(2))`) makes such changes explicit and schedulable, increasing the plausibility of overlapping windows.

### Recommendation
Snapshot the `swapRouter`/token-allowlist address used for validating a specific `Approve`/`Swap` pair at the time the `ApproveTx` executes (e.g., by reading the approved spender directly from the `Approve` calldata rather than re-deriving "current" router state), and honor that address for the corresponding `SwapTx` regardless of subsequent `Registry` updates, until the pair is either executed or expires. Alternatively, require an explicit migration path in `GaslessSwapRouter`/`Registry` governance that only rotates the active router once no address-approvals to the old router remain outstanding, or that lets an old router remain valid for a bounded grace window to allow in-flight approvals to settle.

### Proof of Concept
Conceptual PoC (Go, `kaiax/gasless/impl`):
1. Register `GaslessSwapRouterName -> routerA` in `Registry`, activate it, and let a user submit `GaslessApproveTx` (approves `routerA` for `MaxUint256`) and have it mined alone (e.g., its paired `GaslessSwapTx` is delayed/not yet broadcast).
2. Before the paired `GaslessSwapTx` is included, register `GaslessSwapRouterName -> routerB` in `Registry` with an activation block reachable by the next block, mirroring the exact call used in `TestPostInsertBlock`'s "update gsr address" case: `contract.Register(sender, GaslessSwapRouterName, anotherGSR, big.NewInt(2))`. [7](#0-6) 
3. Submit the previously-signed `GaslessSwapTx` (its `tx.to == routerA`) after the router rotation takes effect.
4. Observe that `isSwapTx` returns `false` because `g.swapRouter` (now `routerB`) no longer matches `args.Router` (`routerA`), per: [8](#0-7) 
5. The `GaslessSwapTx` is rejected from special gasless promotion/bundling and, lacking KAIA balance, cannot be processed as an ordinary transaction — it remains permanently stuck, while the user's `MaxUint256` allowance to `routerA` remains unused/stranded.

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1

		args.Amount.Cmp(abi.MaxUint256) == 0 // A4

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
