## Analysis

The external report's core lesson — a control-flow primitive (`transfer`) that silently diverges from what callers actually rely on (`call`), breaking an implicit contract between the interface and its real behavior — maps onto the Aptos publish path as: **does the "verified" data actually correspond to the bytes the protocol executes?**

Tracing this into `aptos-core`'s code-publishing stack surfaces a genuine mismatch between what `aptos move verify-package` claims to verify and what is actually checked on-chain.

### Root cause

`PackageMetadata` (on-chain) carries a `modules: vector<ModuleMetadata>` field where each `ModuleMetadata` stores the module's `name`, a gzipped `source`, a `source_map`, and a package-level `source_digest` "constructed by ... sha256 of each individual source" [1](#0-0) . These fields are supplied by the publisher as ordinary transaction arguments, alongside the actual bytecode in a *separate* `code: vector<vector<u8>>` argument [2](#0-1) .

Nothing in the publish path binds `metadata.modules[i].source`/`source_digest` to the corresponding bytecode blob. `validate_publish_request` only checks that each compiled module's *name* is present in `expected_modules` and that dependencies are on the allow-list — it never inspects or hashes the declared `source`/`source_map`/`source_digest` against the actual `CompiledModule` bytes: [3](#0-2) 

The native publish path (`native_request_publish`) likewise only forwards module bytes and enforces name/dependency/compat checks, never source correspondence [4](#0-3) .

On the verification side, `aptos move verify-package` (`VerifyPackage::execute`) fetches the on-chain `PackageRegistry` **without bytecode** (`with_bytecode = false`) and calls `package.verify(&compiled_metadata)`: [5](#0-4) 

`CachedPackageMetadata::verify` compares only metadata-to-metadata: `name`, `deps`, `modules` (which is itself just name/source/source_map, not bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest` [6](#0-5) . The `bytecode: BTreeMap<String, Vec<u8>>` field of `CachedPackageRegistry` — which is the only place actual on-chain module bytes are ever fetched — is never populated in this flow and is never referenced by `verify()` [7](#0-6) .

### Title
Publish-path metadata/bytecode binding gap lets declared source and `verify-package` diverge from deployed bytecode - (File: aptos-move/cli/src/stored_package.rs)

### Summary
`code::publish_package` stores publisher-supplied `source`/`source_map`/`source_digest` metadata that is never cryptographically tied to the bytecode published in the same transaction, and the CLI's `verify-package` command only compares this self-declared metadata against a local rebuild — it never fetches or diffs the actual on-chain module bytes.

### Finding Description
`PackageMetadata.modules[i]` carries `source`/`source_map` and a package `source_digest`, computed purely off-chain by the publisher's tooling [1](#0-0) . The on-chain `publish_package`/`request_publish` path validates module *names*, dependency allow-lists, and bytecode compatibility, but never checks that the declared `source`/`source_digest` were actually the input that produced the published bytecode [3](#0-2) [4](#0-3) . A publisher can therefore submit arbitrary bytecode in `code` while declaring unrelated, benign-looking source text/digest in `metadata`.

The `aptos move verify-package` command, whose entire purpose is to let a third party confirm "the package matches a local compilation of the Move code," only re-derives metadata from the reviewer's local source and diffs it against the on-chain *metadata* fields — it explicitly requests the registry with `with_bytecode: false` [5](#0-4) , and `verify()` never touches actual bytecode [6](#0-5) . Consequently, "verification" success only proves the reviewer's source hashes the same way the *publisher's declared* metadata does — it proves nothing about the bytecode actually stored and executed on-chain.

### Impact Explanation
Any tool or user (block explorers, auditors, downstream integrators) that treats a successful `verify-package` run — or the raw `source`/`source_digest` fields visible in on-chain package metadata — as proof that the deployed module bytecode matches the shown/audited source can be deceived: a malicious or compromised publisher can ship backdoored bytecode while "verifying" as trustworthy, benign source. This is a direct instance of the required impact category "mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes," undermining code-safety trust for any consumer relying on Aptos's source-verification story rather than raw bytecode diffing.

### Likelihood Explanation
High likelihood of occurrence in practice: any publisher fully controls both the `metadata` and `code` arguments to `publish_package_txn`/`object_code_deployment::publish`/`resource_account::create_resource_account_and_publish_package`, and no on-chain or CLI check ties them together beyond module names. No special privilege or race condition is needed — a single, ordinary publish transaction suffices, and the default `verify-package` invocation (`with_bytecode: false`) is the documented/only client-side verification path.

### Recommendation
Either (a) have the chain (or at minimum the CLI's `verify-package`) fetch actual on-chain bytecode (`CachedPackageRegistry::create(..., true)`) and compare it byte-for-byte (or via hash) against the bytecode the reviewer locally compiles from the claimed sources, rejecting/flagging mismatches, or (b) enforce on-chain that `source_digest`/per-module source is derived from (or otherwise bound to) the actual published module bytes, so that `source`/`source_digest` cannot be set independently of `code`.

### Proof of Concept
1. Compile package `A` (benign, reviewable source) and package `B` (malicious bytecode, e.g. containing a backdoored entry function) such that both declare the same module names.
2. Build `PackageMetadata` normally from package `A`'s sources (yielding legitimate `source`, `source_map`, `source_digest`), but pass package `B`'s compiled bytecode as the `code` argument to `code::publish_package_txn` (or `object_code_deployment::publish`).
3. `validate_publish_request` only checks that module names in `B`'s bytecode match `expected_modules` from metadata (`code.move`), so the transaction succeeds even though `code` was never derived from the declared `source`.
4. A reviewer runs `aptos move verify-package --account <addr>` against package `A`'s source tree; because `VerifyPackage::execute` calls `CachedPackageRegistry::create(..., false)` and `verify()` only diffs metadata fields, it prints "Successfully verified source of package," despite the deployed, executed bytecode being `B`, not `A`.

fn native_request_publish(
    context: &mut SafeNativeContext,
    _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(matches!(args.len(), 4 | 5));
    let with_allowed_deps = args.len() == 5;

    context.charge(CODE_REQUEST_PUBLISH_BASE)?;

    let policy = safely_pop_arg!(args, u8);
    let mut code = vec![];
    for module in safely_pop_arg!(args, Vec<Value>) {
        let module_code = module.value_as::<Vec<u8>>()?;

        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_code.len() as u64))?;
        code.push(module_code);
    }

    let allowed_deps = if with_allowed_deps {
        let mut allowed_deps: BTreeMap<AccountAddress, BTreeSet<String>> = BTreeMap::new();

        for dep in safely_pop_arg!(args, Vec<Value>) {
            let (account, module_name) = unpack_allowed_dep(dep)?;

            let entry = allowed_deps.entry(account);

            if let Entry::Vacant(_) = &entry {
                // TODO: Is the 32 here supposed to indicate the length of an account address in bytes?
                context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(32))?;
            }

            context
                .charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_name.len() as u64))?;
            entry.or_default().insert(module_name);
        }

        Some(allowed_deps)
    } else {
        None
    };

    let mut expected_modules = BTreeSet::new();
    for name in safely_pop_arg!(args, Vec<Value>) {
        let str = get_move_string(name)?;

        // TODO(Gas): fine tune the gas formula
        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(str.len() as u64))?;
        expected_modules.insert(str);
    }

    let destination = safely_pop_arg!(args, AccountAddress);

    // Add own modules to allowed deps
    let allowed_deps = allowed_deps.map(|mut allowed| {
        allowed
            .entry(destination)
            .or_default()
            .extend(expected_modules.clone());
        allowed
    });

    let code_context = context.extensions_mut().get_mut::<NativeCodeContext>();
    if code_context.requested_module_bundle.is_some() || !code_context.enabled {
        // Can't request second time or if publish requests are not allowed.
        return Err(SafeNativeError::abort(EALREADY_REQUESTED));
    }
    code_context.requested_module_bundle = Some(PublishRequest {
        destination,
        bundle: ModuleBundle::new(code),
        expected_modules,
        allowed_deps,
        check_compat: policy != ARBITRARY_POLICY,
    });

    Ok(smallvec![])
}

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }
