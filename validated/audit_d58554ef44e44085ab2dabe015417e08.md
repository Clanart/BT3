### Title
Payout transaction attribution is malleable via SinglePlusAnyoneCanPay: an unprivileged racer can permanently orphan a deposit's reimbursement - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` signs the payout transaction's input 0 and output 0 with `TapSighashType::SinglePlusAnyoneCanPay`, which only commits to input 0's outpoint/scriptPubKey and output 0's value/script — it never commits to the OP_RETURN output that carries `operator_xonly_pk`. An unprivileged attacker who observes the honest operator's payout transaction in the mempool can rebroadcast a variant that reuses the same input-0 witness and output-0, adds their own fee-bumping input, and substitutes any OP_RETURN (including a pubkey belonging to no registered operator). If this variant confirms first, on-chain "attribution" no longer matches the operator/party who actually funded the payout.

### Finding Description
The binding that should hold is:
`withdrawals.payout_payer_operator_xonly_pk` (the OP_RETURN xonly-pubkey recorded on-chain and read back by `update_finalized_payouts`, [1](#0-0) ) == the operator whose Bitcoin wallet actually funded output 0 of the confirmed payout transaction.

`create_payout_txhandler` builds the payout tx with input 0 = user's UTXO (key-spend, signed by the user with `SinglePlusAnyoneCanPay`), output 0 = user's payout, output 1 = anchor, output 2 = OP_RETURN(`operator_xonly_pk`), and sets the user's witness on input 0 only: [2](#0-1) .

`calculate_pubkey_spend_sighash`/`calculate_sighash_txin` compute a `Prevouts::One` sighash for `*PlusAnyoneCanPay` types, i.e. only input 0's prevout is committed, and `SIGHASH_SINGLE` commits only to output[0]: [3](#0-2) . `Operator::withdraw` verifies the user's `SinglePlusAnyoneCanPay` signature against exactly this sighash before funding/broadcasting: [4](#0-3) , then funds the rest of the transaction with `add_inputs: true` (unconstrained extra inputs) and broadcasts it, exposing it in the public mempool.

Because outputs 1 (anchor) and 2 (OP_RETURN) are outside the sighash, any party who sees the broadcast transaction (or its witness) can construct a new transaction that: reuses the same input-0 outpoint+witness, keeps the identical output-0 (value+script, required by SIGHASH_SINGLE), adds their own additional input(s) to pay fees/output funding (allowed by ANYONECANPAY), and replaces the OP_RETURN with an arbitrary or non-operator xonly-pubkey. If this transaction is mined first via `sendrawtransaction`, the honest operator's original tx becomes an unconfirmable double-spend.

Downstream, `update_finalized_payouts` blindly parses whatever OP_RETURN is in the confirmed payout tx and stores it as `payout_payer_operator_xonly_pk`: [5](#0-4) . `PayoutCheckerTask` only picks up payouts whose stored `payout_payer_operator_xonly_pk` equals the operator's own key (`get_first_unhandled_payout_by_operator_xonly_pk`): [6](#0-5) , and `validate_payer_is_operator`/`get_reimbursement_txs` hard-fail if the stored payer key doesn't match: [7](#0-6) , [8](#0-7) . `Verifier::is_kickoff_malicious` independently marks any kickoff as malicious if the recorded payer key doesn't match the kickoff's operator: [9](#0-8) .

Since Citrea assigns each withdrawal to one specific `move_to_vault_txid` (join on `d.move_to_vault_txid = w.move_to_vault_txid` in `get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id`, [10](#0-9) ), once the malleated payout tx confirms with a bogus/no-operator OP_RETURN, no operator (including the honest one who actually intended to front the withdrawal) can ever pass `validate_payer_is_operator` or produce a kickoff that isn't flagged malicious for that deposit. None of the existing guards (`SECP.verify_schnorr` on the user signature, `is_kickoff_malicious`, `validate_payer_is_operator`) prevent the substitution — they only detect the resulting mismatch after the fact, with no recovery path.

### Impact Explanation
The specific deposit's move-to-vault UTXO backing that withdrawal becomes permanently unreimbursable: no operator's `operator_xonly_pk` will ever match the bogus value recorded from the winning transaction, so `validate_payer_is_operator` always errors and `PayoutCheckerTask`/`is_kickoff_malicious` never let a kickoff for that deposit succeed. This matches the Critical categories "a move-to-vault UTXO permanently frozen" and "an honest operator permanently unable to be reimbursed." The user still receives their intended payout (output 0's value/script is committed by SIGHASH_SINGLE), but whoever funded the extra inputs (the racer) gets nothing back — this is a griefing primitive rather than a profit path, but it is repeatable against every withdrawal an operator broadcasts, and the honest operator is denied any recourse since their own transaction never confirms.

### Likelihood Explanation
The attacker needs: (1) visibility into the mempool once any operator broadcasts a payout tx (standard, no privileged access), (2) enough BTC to cover the exact value committed to output 0 plus fees to outbid the honest operator's transaction, and (3) a faster/higher-fee broadcast via `sendrawtransaction`. No verifier/operator/aggregator compromise, no key recovery, and no majority hashrate are required — it is a pure transaction-relay race exploiting the fact that `SinglePlusAnyoneCanPay` leaves the attribution OP_RETURN output outside the signed message. The attacker's cost equals the withdrawal amount, making this expensive per-attack but fully self-financed and repeatable for any withdrawal size the attacker is willing to fund; it does not scale to draining the bridge, but it does allow a well-funded griefer to permanently deny a specific operator's reimbursement.

### Recommendation
Bind the OP_RETURN/attribution output into what the user signs, e.g. have the user sign with `SIGHASH_ALL` (or `AllPlusAnyoneCanPay`) over a transaction template that already fixes the OP_RETURN operator commitment, or otherwise commit the operator's identity (and any other outputs) inside the signed sighash so a third party cannot swap outputs 1/2 without invalidating the user's signature. Alternatively, require the operator's own `sendrawtransaction` to be the one indexed via txid/first-seen tracking with additional protocol-level replace protection, but the sighash-commitment fix is the structural remedy.

### Proof of Concept
In `core/src/test/deposit_and_withdraw_e2e.rs`, extend a deposit+withdraw e2e test with `regtest` bitcoind RPC:
1. Perform a deposit and call `Operator::withdraw`/the gRPC `withdraw` to obtain the signed, funded honest payout transaction, but do not let the test harness broadcast/mine it yet (intercept the hex from `RawSignedTx`).
2. Decode it, extract input[0] (outpoint + witness) and output[0] (value/script) which are covered by the `SinglePlusAnyoneCanPay|SIGHASH_SINGLE` signature.
3. Build an "attacker" transaction: same input[0] witness/outpoint, an attacker-funded extra input (from a separate wallet) sized to cover output[0] + fees, output[0] identical, and OP_RETURN containing a freshly generated xonly pubkey not registered as any operator.
4. Broadcast the attacker's tx via `sendrawtransaction` and mine it before broadcasting the honest operator's original payout tx; assert the honest tx is now rejected by the node as a double-spend (`sendrawtransaction` error / not confirmed).
5. Run bitcoin sync so `update_finalized_payouts` processes the block; assert `withdrawals.payout_payer_operator_xonly_pk` equals the attacker's bogus key, not the operator's key.
6. Call `Operator::get_reimbursement_txs` (or wait for `PayoutCheckerTask`) for the honest operator and assert it errors with "Payer is not own operator for deposit" from `validate_payer_is_operator`, demonstrating the deposit's move-to-vault UTXO can never be reimbursed to any operator.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

            result.0.map(|pk| pk.0),
            result.1.map(|block_hash| block_hash.0),
