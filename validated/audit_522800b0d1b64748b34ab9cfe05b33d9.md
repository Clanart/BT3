### Title
Attacker-controlled `offset` in `ReceivedOutput::read` deserializes a scanner-derived privilege field, letting unprivileged bytes claim outputs under arbitrary key tweaks - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` reconstructs a spendable output by mass-assigning the `offset` scalar directly from the input byte stream, with no check that the offset actually corresponds to the output's `script_pubkey` under the multisig's group key. In honest operation, `offset` is a privileged, derived field: `Scanner::register_offset` / `Scanner::scan_transaction` only populate it from the `scripts` map keyed by the exact `p2tr` script (wallet/mod.rs:180-213). The deserializer silently discards that invariant, so any party able to supply serialized `ReceivedOutput` bytes can mint a `ReceivedOutput` claiming any outpoint/value while attributing it to an arbitrary tweaked key `key + G*offset`.

### Finding Description
- `Scanner` maintains the invariant `script_pubkey == p2tr(key + G*offset)` via `register_offset`, which refuses collisions and only registers offsets it computed (networks/bitcoin/src/wallet/mod.rs:180-196). `scan_transaction` therefore only ever emits `ReceivedOutput`s whose `offset` was derived from the registered script map (wallet/mod.rs:199-214).
- `ReceivedOutput::read` (wallet/mod.rs:122-134) reads `offset` via `Secp256k1::read_F` and the `TxOut`/`OutPoint` via consensus decode, then returns `Ok(ReceivedOutput { offset, output, outpoint })` with zero cross-validation. The type carries no base key, so the binding between `offset` and `output.script_pubkey` is never re-established.
- Downstream consumers treat `offset` as authoritative: `SignableTransaction::multisig` re-keys each signer's `ThresholdKeys` by `self.offsets[i]` and asserts the tweaked group key's `p2tr` script equals the prevout script (networks/bitcoin/src/wallet/send.rs:273-285), and the Serai processor's `Output::key()` recovers the owning group key as `read_G(script key) - G*offset` (processor/src/networks/bitcoin.rs:112-122), attributing the funds to whatever key the forged offset implies.

### Impact Explanation
A forged `ReceivedOutput` causes funds to be reported as received under a group key `key + G*offset` that does not match the key actually controlling the on-chain output — the "funds reported received that are not spendable" impact class. When spending is attempted, `multisig` either returns `None` (turning into a panic at `attempt_sign`'s `expect("used the wrong keys")`, processor/src/networks/bitcoin.rs:841), permanently DoS-ing the spend plan for that output, or — if the attacker picks an offset whose tweaked key matches a script of a *different* real output — the output is attributed to the wrong multisig/scheduler key. Because `kind`/`presumed_origin`/`data` are likewise deserialized wholesale in `Output::read` (processor/src/networks/bitcoin.rs:145-166), a forged record can additionally reclassify an `External` deposit as `Change`/`Branch`, bypassing the data-extraction and refund-origin logic in `get_outputs` (bitcoin.rs:686-739).

### Likelihood Explanation
Reachable whenever attacker-influenced bytes reach `ReceivedOutput::read`/`Output::read` — e.g., serialized outputs relayed between components, recovered from writable storage, or supplied through any integration that persists/transmits `ReceivedOutput`s. The attacker needs no key material; `read_F` accepts any canonical scalar, so the offset is fully attacker-chosen. The exploit requires a deserialization surface that trusts the bytes, which is the standard assumption under the listed sink model.

### Recommendation
Do not deserialize `offset` as a free field. Either (a) store the base group key alongside `ReceivedOutput` and verify `p2tr_script_buf(key + G*offset) == output.script_pubkey` inside `read`, returning an error on mismatch, or (b) make `offset` unserializable/`#[zeroize(skip)]`-style derived state, re-deriving it by re-scanning the output's script against a `Scanner` after deserialization. Apply the same revalidation to the privileged `kind` field in `Output::read` (derive `kind` from the offset via the scanner's `kinds` map rather than reading it).

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
