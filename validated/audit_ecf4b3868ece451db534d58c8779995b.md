### Title
Unauthenticated OP_RETURN in payout transaction lets anyone rewrite the credited operator via fee-bump replacement - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx` created by `create_payout_txhandler` is signed by the withdrawing user with a `SIGHASH_SINGLE | ANYONECANPAY` signature that only commits to the spent input and the single user-payout output. The output carrying the operator attribution (the `OP_RETURN` with `operator_xonly_pk`) is left completely unauthenticated. Because the transaction is broadcast as RBF-enabled, any unprivileged party who observes it in the mempool can rebroadcast a fee-bumped conflicting transaction that reuses the valid user signature/output but swaps out the `OP_RETURN`, breaking the binding between "operator that actually fronted the withdrawal" and "operator credited for reimbursement."

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
- Input 0: user's withdrawal UTXO, spent with `SpendPath::KeySpend` and the user's `taproot::Signature`.
- Output 0: user payout.
- Output 1: anchor.
- Output 2: `OP_RETURN` push of `operator_xonly_pk`. [1](#0-0) 

The signature is verified with the requirement that it use `SinglePlusAnyoneCanPay` sighash type: [2](#0-1) 

`SIGHASH_SINGLE | ANYONECANPAY` (0x83) only commits to input 0 and the output at the *same index* (output 0). It does not commit to output 1 (anchor) or output 2 (the `OP_RETURN` attribution output), nor to any other inputs. This is corroborated by the RBF signer's own recognition of SAP signatures (checking `sig[64] == 0x83`) and its logic for preserving/copying only that witness while letting the wallet add/rearrange other inputs/outputs: [3](#0-2) 

The payout tx is funded via the node wallet with RBF explicitly enabled (`replaceable: Some(true)`), so anyone who sees an unconfirmed payout tx in the mempool can build and broadcast a conflicting transaction: it reuses the same input and the identical (committed) output 0, but replaces output 2's `OP_RETURN` with a different or invalid `operator_xonly_pk`, and adds extra ANYONECANPAY-permitted inputs to pay a higher fee so it wins the RBF race. [4](#0-3) 

Once whichever version confirms, the verifier's block-processing logic derives the credited payer purely from the `OP_RETURN` of the *mined* transaction, with no cross-check against who actually funded the payout: [5](#0-4) 

Downstream, `validate_payer_is_operator` requires this recorded `payout_payer_operator_xonly_pk` to equal the calling operator's own key before it will return the kickoff/reimbursement transactions: [6](#0-5) 

If the attribution is rewritten to `None` (invalid pubkey) or to another operator's key, the operator that actually paid the user out of its own funds can never satisfy this check for that deposit, both through the automated `get_reimbursement_txs`/`internal_finalized_payout` path and equivalently through the manual `GetReimbursementTxs` RPC. [7](#0-6) 

The same `OP_RETURN` value is also what the bridge circuit uses to compute `deposit_constant` from the mined payout transaction, so tampering with it also breaks the binding the circuit relies on to prove which operator is entitled to reimbursement: [8](#0-7) 

### Impact Explanation
This breaks the custody binding "the operator credited versus the party that paid": an operator can front real BTC to a withdrawing user, yet an unprivileged third party can cause a replacement transaction to confirm instead, in which the attribution output either points to a different key or is invalid. The result is that the honest operator that fronted the withdrawal becomes permanently unable to claim reimbursement for that deposit (`validate_payer_is_operator` will never match), matching the explicit Critical impact "an honest operator permanently unable to be reimbursed." It can also corrupt the `deposit_constant` binding used by the bridge circuit for that deposit, undermining the circuit's operator-attribution guarantee.

### Likelihood Explanation
The attack requires no special role or trust — the attacker only needs to observe the payout transaction (public, broadcast to the Bitcoin mempool) and broadcast a fee-bumped replacement with a modified `OP_RETURN`, exploiting the fact that `SIGHASH_SINGLE | ANYONECANPAY` does not cover that output, and that the payout tx is RBF-enabled. This is reachable by any network participant who monitors the mempool and can pay a marginally higher fee, and does not require compromising a verifier, operator, watchtower, aggregator, security council, or sequencer key.

### Recommendation
Bind the operator attribution output to the signature the user provides, e.g. by having the operator (not just the user) co-sign a commitment that includes the `OP_RETURN` output, or by changing the sighash type/covenant so that the whole payout transaction (including the `OP_RETURN`) is committed by a signature that cannot be replaced by a third party, or by using `SIGHASH_ALL` for the funding/attribution portion so an unauthenticated replacement transaction cannot alter the operator attribution while keeping the user's payment output valid.

### Proof of Concept
1. Operator O broadcasts `payout_tx` (input: user's withdrawal UTXO signed `SIGHASH_SINGLE|ANYONECANPAY`; output0: user payout; output2: `OP_RETURN(O.xonly_pk)`), marked RBF (`replaceable=true`) per `create_funded_psbt`.
2. Attacker A observes `payout_tx` in the mempool, extracts the same input/witness (valid under ANYONECANPAY for that specific input) and the same output0 (required by SIGHASH_SINGLE commitment).
3. A constructs `payout_tx'` reusing that input+witness and output0, but replaces output2 with a bogus/invalid `OP_RETURN` (or a different xonly_pk), and adds A's own funding input/higher fee (permitted since ANYONECANPAY does not constrain other inputs).
4. A broadcasts `payout_tx'` with a higher feerate; it displaces `payout_tx` per standard RBF rules and confirms.
5. `update_finalized_payouts` parses the mined tx's `OP_RETURN`, finds no valid xonly pubkey, and stores `payout_payer_operator_xonly_pk = NULL` for this withdrawal [5](#0-4) .
6. Operator O calls `get_reimbursement_txs`/`internal_finalized_payout`; `validate_payer_is_operator` finds `payer_xonly_pk = None` and errors out permanently, even though O genuinely paid the user [6](#0-5) .

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Given a PSBT with inputs, fill in the existing witnesses from the original tx
    /// This allows us to create a finalized PSBT if
    /// the original tx had SinglePlusAnyoneCanPay signatures.  If the original
    /// tx did not have S+AP, these signatures will be added. The expected behavior is for them to be replaced using RbfSigningInfo.
    ///
    /// # Returns
    /// The PSBT as a base64-encoded string.
    pub async fn copy_witnesses(&self, psbt: String, initial_tx: &Transaction) -> Result<String> {
        let mut decoded_psbt = Psbt::from_str(&psbt).map_err(|e| eyre!(e))?;

        for (idx, input) in initial_tx.input.iter().enumerate() {
            if let Some(sig) = input.witness.nth(0) {
                if sig.len() == 65 && sig[64] == 0x83 {
                    // This is a S+AP signature, copy it over
                    decoded_psbt.inputs[idx].final_script_witness = Some(input.witness.clone());
                }
            }
        }

        Ok(decoded_psbt.to_string())
    }
