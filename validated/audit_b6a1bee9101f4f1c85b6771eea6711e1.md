### Title
Unauthenticated forced address association via `associatePubKey` migrates a victim's balance and orphans account state without their consent - (File: `precompiles/addr/addr.go`)

### Summary
The `addr` precompile at `0x0000000000000000000000000000000000001004` exposes two association entry points: `associate(v,r,s,customMessage)`, which requires a fresh ECDSA signature proving the caller currently controls the private key, and `associatePubKey(pubKeyHex)`, which accepts a raw (uncompressed/compressed) public key with **no signature at all**. [1](#0-0)  Since Cosmos SDK secp256k1 public keys are broadcast in the clear in every signed transaction's `SignerInfo`, any Sei address that has ever sent a transaction has a publicly-recoverable pubkey. Any third party can lift that pubkey and call `associatePubKey` on the victim's behalf, forcing an EVM<->Sei address association and balance migration that the victim never authorized.

### Finding Description
`associatePublicKey` parses the supplied compressed pubkey bytes, derives `evmAddr`, `seiAddr`, and the Cosmos pubkey object purely from that public key material, and passes them straight into `associateAddresses` — with no signature-based proof of possession/intent: [1](#0-0) 

Compare this to `associate`, which requires `v,r,s` — a signature over a `customMessage`, i.e., proof that the caller currently controls the private key at the time of the call: [2](#0-1) 

`associateAddresses` only guards against re-associating an address that is *already* associated; it performs no check that the transaction sender (`msg.sender`/EVM origin) is in any way related to the derived `seiAddr`/`evmAddr` being associated: [3](#0-2) 

Once through, `AssociateAddresses` performs an irreversible state migration: it may adopt an existing `BaseAccount`'s pubkey, sets the permanent EVM<->Sei mapping, and unconditionally migrates the direct-cast address's spendable and locked-adjacent balances (usei and wei) to the newly associated address, then removes the old cast account: [4](#0-3) 

This is structurally the same bug class as the authentik CVE: a security-sensitive, user-scoped action (permanently binding/altering account identity) is executed based on data that is merely *known* to the caller (a public key visible on-chain) rather than *proven* to be currently controlled/authorized by the acting party for that specific action. The codebase's own comments acknowledge the danger of force-association from a security perspective in the analogous EIP-7702 pre-association path, explicitly warning that force-associating an account can "migrate their direct-cast balance and orphan staking/distribution state ... which can then halt the chain via the distribution validator-removal hook": [5](#0-4) . That EIP-7702 path adds numerous mitigations (chain-ID check, nonce/code checks, cross-check against go-ethereum's authoritative recovery) precisely because forced association is recognized as dangerous — yet `associatePubKey` has none of those protections and requires no signature whatsoever.

### Impact Explanation
A forced, unsolicited association:
- Migrates the victim's usei/wei balance from their direct-cast address to the newly associated Sei address, which can move funds into an account the victim did not intend to use in this configuration for EVM interactions, and removes the pre-existing cast `BaseAccount`.
- Adopts the pubkey object into whatever `BaseAccount` currently sits at `seiAddr` if it had none, altering account state (sequence/pubkey) that later signing/verification logic may depend on.
- Is **irreversible**: `associateAddresses`/`associate` explicitly reject calls once an address is associated, so the victim cannot "undo" this forced binding, and any legitimate association attempt by the victim will subsequently fail.
- Per the codebase's own documented concern for the structurally similar EIP-7702 path, forcing association on an account with existing staking/distribution state can orphan that state and potentially trigger chain-halting behavior via the distribution validator-removal hook.

This satisfies "unauthorized transfer/permanent freezing/potential validator halt" categories called for in the validation criteria.

### Likelihood Explanation
Likelihood is high for the balance-migration/account-mutation impact: the pubkey needed is trivially obtainable from any past Sei transaction signed by the victim (it is embedded in `SignerInfo` on-chain), and the call itself is a single, ungated EVM precompile invocation costing only `RequiredGas` (50000) with no other preconditions. Any account that has ever transacted on Sei (nearly all active accounts) is a viable target.

### Recommendation
Require the caller to prove current possession of the private key for `associatePubKey`, mirroring `associate`'s signature-based flow, or remove/gate the pubkey-only entry point behind an explicit, freshly-signed authorization (e.g., require a signature over a nonce/challenge using the supplied pubkey, and/or require `msg.sender`'s own address to match the derived EVM address before allowing association). At minimum, apply the same defensive checks used in `AuthorityToPreAssociate` (chain-id binding, nonce/account-state consistency, and — most importantly — a genuine signature proving intent at call time) before allowing any address's association and balance migration to proceed.

### Proof of Concept
1. Observe any past Sei transaction from victim address `V` (e.g., via any public RPC or block explorer); extract the compressed secp256k1 public key from the transaction's `SignerInfo`.
2. Attacker calls the `addr` precompile at `0x...1004` with `associatePubKey(pubKeyHexOfV)` from any EVM account (no funds/signature from `V` required).
3. `associatePublicKey` derives `evmAddr`, `seiAddr` == `V`, and `pubkey` from the supplied bytes and calls `associateAddresses`, which — since `V` is not yet associated — proceeds to call `AssociateAddresses`. [6](#0-5) 
4. `AssociateAddresses` migrates `V`'s direct-cast usei/wei balances and removes the old cast account, all without any action or consent from `V`. [4](#0-3) 
5. `V` is now permanently associated (future association attempts by `V` will fail with "already associated"), and any staking/distribution state tied to the old cast identity is orphaned.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
