### Title
Auction bid's `MaxGasPrice` is signed but never enforced against the target transaction's gas price, allowing bid tx generation with an uncapped fee - ([File: kaiax/auction/impl/getter.go])

### Summary
KIP-249 v3.0 bids include a `MaxGasPrice` field that the searcher signs via EIP-712 as part of the bid data, intended to cap the gas price the searcher is exposed to for the bid transaction. However, neither `BidPool.validateBid` (bid admission) nor `GetBidTxGenerator` (bid transaction construction) ever compares `bid.MaxGasPrice` against the actual `GasFeeCap`/`GasTipCap` used to build the bid tx. This mirrors the Beedle `buyLoan()` pattern: a per-request risk parameter (`maxLoanRatio` / `MaxGasPrice`) is defined and signed/configured by the counterparty, but the code path that actually executes/settles the transaction never re-validates against it.

### Finding Description
`BidData.MaxGasPrice` is defined in [1](#0-0)  and is included in the EIP-712 v3 typehash that the searcher signs, per `auctionTypeV3` in [2](#0-1) .

`BidPool.validateBid` enumerates all admission checks (block number range, positive bid, data size, call gas limit, signatures) but contains no check comparing `bid.MaxGasPrice` to anything: [3](#0-2) .

When the bid is later turned into an actual transaction via `GetBidTxGenerator`, the gas fee cap/tip cap are copied directly from the *target* transaction (`tx.GasFeeCap()`, `tx.GasTipCap()`) with no reference to `bid.MaxGasPrice` at all: [4](#0-3) .

`EncodeAuctionCallData` does forward `bid.MaxGasPrice` into the on-chain call data passed to the `AuctionEntryPoint` contract for v3 bids [5](#0-4) , meaning the *on-chain* contract is expected to be the enforcement point. But the client-side bid pool and bid-tx generator, which are the code under audit in this repo, perform no corresponding validation, so a malicious block proposer (who runs `GetBidTxGenerator` and constructs the actual bid transaction) can freely set the bid transaction's `GasFeeCap`/`GasTipCap` to any value derived from the target tx, irrespective of what the searcher signed as `MaxGasPrice`. There is no assertion anywhere in `kaiax/auction` that `tx.GasFeeCap() <= bid.MaxGasPrice`.

### Impact Explanation
A block proposer (the entity that calls `GetBidTxGenerator` while assembling the block — reachable purely from block-building logic triggered by any publicly submitted bid/target tx pair) can construct and sign a bid transaction whose gas price exceeds the searcher's signed `MaxGasPrice` cap. Since the target transaction's `GasFeeCap`/`GasTipCap` are attacker/proposer-influenceable (the searcher chooses the target tx, but the proposer selects which target tx from the pool to pair with a given bid, and the bid tx's fee parameters are copied from that arbitrary target tx rather than clamped to the bid's own signed cap), the searcher's fee-protection guarantee is not enforced at the client level at all. This can result in the searcher's bid tx paying an unbounded fee (fee abuse / fee-delegation-like value extraction), silently violating the KIP-249 v3 protocol guarantee that `MaxGasPrice` limits searcher fee exposure — analogous to Beedle's `buyLoan()` allowing a lender's risk parameter to be bypassed by a downstream settlement path that never re-validates the original commitment.

### Likelihood Explanation
Medium: the vulnerable path (`GetBidTxGenerator` in `ExtractTxBundles`) is executed on every block a bid targets, and requires no privileged access beyond normal auction/bid submission (`auction_submitBid` is reachable by any bidder), and normal block building by the proposer. It only manifests for `AuctionVersionV3` bids (protocol version "0.0.2") that set `MaxGasPrice`, and the actual monetary impact depends on how much fee is ultimately charged/refunded by the on-chain `AuctionEntryPoint` contract logic, which is out of scope of this repo snapshot (the mock entry point in `contracts/testing/system_contracts/AuctionEntryPointMock.sol` has this logic commented out). This uncertainty limits confidence that it is directly exploitable for value extraction versus being enforced purely on-chain.

### Recommendation
In `kaiax/auction/impl/getter.go`'s `GetBidTxGenerator`, before constructing the bid transaction, validate that the resolved `GasFeeCap`/effective gas price does not exceed `bid.MaxGasPrice` (when non-nil), returning an error/skipping bundle inclusion otherwise. Additionally, add this check to `BidPool.validateBid` (or a dedicated validation step invoked at bundle-extraction time) so that bids violating their own committed cap are rejected consistently with rules 1–6 already enforced there, and add unit tests asserting a bid is rejected/excluded when the resolved bid tx's gas price exceeds `bid.MaxGasPrice`.

### Proof of Concept
Not independently reproducible from the available client-side code alone because on-chain enforcement (if any) lives in the `AuctionEntryPoint` contract logic, which was not fully available for this analysis (the reference mock has the fee/gas-charging logic commented out — see lines 58–71 of `AuctionEntryPointMock.sol`). Conceptually:
1. Searcher submits a v3 bid with `MaxGasPrice = X` via `auction_submitBid`, signed over the v3 EIP-712 typehash that includes `maxGasPrice` [6](#0-5) .
2. `BidPool.validateBid` admits the bid without checking `MaxGasPrice` against anything [3](#0-2) .
3. During block building, `GetBidTxGenerator` builds the bid tx using the target transaction's `GasFeeCap()`/`GasTipCap()` (which can be far greater than `X`), never consulting `bid.MaxGasPrice` [4](#0-3) .
4. The resulting bid transaction, signed by the proposer's node key, is included on-chain paying a fee exceeding the searcher's committed cap, with no client-side rejection.

Given the incomplete visibility into the production `AuctionEntryPoint` contract's on-chain enforcement (only a stripped-down mock is available in this repo), I cannot confirm with full certainty that this results in concrete fund loss versus being a defense-in-depth gap; a Devin session with full repository/contract access would be needed to confirm the on-chain `call()` function's fee-charging logic and settle whether client-side enforcement is required or redundant.

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {
	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}
		return abiV3.Pack("call", input)
	}
