## Title
`aptos move verify-package` never actually verifies on-chain bytecode against source, despite advertising bytecode/source parity - ([File: aptos-move/cli/src/stored_package.rs])

### Summary
The Aptos CLI's `verify-package` command is documented as checking "that on-chain bytecode matches a local source tree" [1](#0-0) [2](#0-1) . In reality, its implementation only compares self-reported `PackageMetadata` fields (name, deps, `ModuleMetadata` records, manifest, upgrade policy, extension, source digest) between a locally rebuilt package and the on-chain `PackageRegistry` resource — it never downloads or compares the actual on-chain compiled module bytecode. This is the publish-analog of the ibBTC `pricePerShare` bug class: a value that downstream code (and auditors/users) implicitly trust as an integrity/authenticity anchor is accepted without any sanity check tying it to the thing it's supposed to attest to.

### Finding Description
`CachedPackageMetadata::verify` compares only metadata-level fields: [3](#0-2) 

Note that `ModuleMetadata` only contains `name`, `source` (gzipped source text), `source_map`, and `extension` — not the compiled bytecode bytes: [4](#0-3) 

The `VerifyPackage` CLI command calls this `verify()` after building locally and pulling the on-chain registry, but explicitly requests the registry **without bytecode**: [5](#0-4) 

`CachedPackageRegistry::create` only fetches bytecode when `with_bytecode` is `true`, and `VerifyPackage` passes `false`: [6](#0-5) 

At the Move-language / VM level, the `source`, `source_map`, `manifest`, and `source_digest` fields of `PackageMetadata` are purely descriptive and are never cross-checked against the actual bytecode bundle (`code: vector<vector<u8>>`) that gets published. `publish_package` and the native `request_publish`/`request_publish_with_allowed_deps` only validate module names, dependency address/policy constraints, and Move-level compatibility — they do not tie the bytecode to the `source`/`manifest`/`source_digest` metadata at all: [7](#0-6) [8](#0-7) 

Because the `source_digest` is computed independently by hashing the *local build's* resolved source files during `extract_metadata`, and not derived from or checked against the published bytecode, a publisher can freely publish any bytecode `code` bundle alongside `PackageMetadata` whose `modules[i].source` and `source_digest` describe a completely different (benign-looking) source tree.

### Impact Explanation
Anyone relying on `aptos move verify-package` (developers, auditors, dependency consumers deciding whether to trust/depend on a package) receives a false assurance of code-safety: the command reports "Successfully verified source of package" even though the actual bytecode running on-chain was never compared to anything. A malicious or compromised package owner can publish backdoored bytecode while advertising (and having `verify-package` "confirm") an innocuous, audited source tree, enabling unauthorized/undetected malicious code to be treated as verified on mainnet. This directly matches the required impact class "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes."

### Likelihood Explanation
High likelihood: this is not a native-VM edge case, but the exact code path any user takes when running the officially documented `aptos move verify-package` command. No special privileges are needed to exploit — any account owner can publish a package with divergent metadata `source` vs. the real bytecode, since nothing enforces the linkage. The gap is deterministic and always reachable, not probabilistic or racy.

### Recommendation
- Update `VerifyPackage::execute` to always fetch bytecode (`with_bytecode: true`) and have `verify()` additionally recompile the local module bytecode (per `IncludedArtifacts`/build options) and byte-compare it against the fetched on-chain module bytecode for every module in the package, not just the metadata records.
- Consider deriving `source_digest` (or an additional field) from the actual bytecode bytes, or otherwise cryptographically binding `modules[i].source`/`source_map` to the published bytecode, so metadata cannot be presented independently of what is actually executable on-chain.
- Update user-facing documentation/messaging to accurately reflect what is verified until the bytecode check is implemented, to avoid misleading downstream trust decisions.

### Proof of Concept
1. Build package `P` locally with source `S_good` (benign), compute its `source_digest_good` via `BuiltPackage::extract_metadata`.
2. Hand-craft or use a modified compiler to produce bytecode `B_evil` that is Move-verifier legal and structurally/functionally compatible (satisfies `Compatibility::check`) with any prior version, but injects malicious logic (e.g., a backdoored `withdraw` function reachable behind a rarely-audited code path) while preserving the same public function signatures/visibility.
3. Call `code::publish_package_txn(owner, metadata_serialized, code)` where `metadata_serialized` encodes `PackageMetadata` with `modules[i].source = S_good` and `source_digest = source_digest_good`, but `code = [B_evil]` — nothing in `publish_package`/`request_publish_with_allowed_deps` cross-checks bytecode against `source`/`source_digest`. [9](#0-8) 
4. An auditor runs `aptos move verify-package --account <addr>` against local source `S_good`. `VerifyPackage::execute` rebuilds locally, fetches the on-chain registry with `with_bytecode=false`, and calls `package.verify(&compiled_metadata)`, which only compares metadata fields — all of which match `S_good`/`source_digest_good` — and reports "Successfully verified source of package," even though the deployed bytecode is `B_evil`. [10](#0-9)

    /// Publishes a package at the given signer's address. The caller must provide package metadata describing the
    /// package.
    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
