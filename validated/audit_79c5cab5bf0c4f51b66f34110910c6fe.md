No vulnerability found for this question.

**Rationale (brief):**

The `session` passed into `PostAuthenticateTasks.perform` / `install_webhooks` is never derived from an unverified `shop` query parameter — it comes from cryptographically verified sources in both flows:

- **OAuth callback flow**: `CallbackController#validated_auth_objects` passes the raw `shop`/`code`/`hmac`/`state` params to `ShopifyAPI::Auth::Oauth.validate_auth_callback`, which validates the HMAC signature (computed with the app secret) and the state/nonce cookie before returning a session. The `shop` attribute on the returned session reflects the domain validated by Shopify's own OAuth code-exchange endpoint, not the raw request param; an attacker cannot forge a matching HMAC without the app secret, and a code issued for the attacker's own shop cannot be redeemed against a different shop's token endpoint. [1](#0-0) 

- **Token exchange flow**: the shop used for exchange (`domain`) is extracted from the verified `id_token` claims via `ShopifyAPI::Auth::JwtPayload`, not from request params. [2](#0-1) 

  Additionally, the `TokenExchange` controller concern explicitly guards against shop/param mismatch: `reject_mismatched_requested_shopify_domain` compares the sanitized `shop` request param against the authenticated domain derived from the verified token/session and returns `:unauthorized` (short-circuiting before `activate_session` or any downstream webhook installation) if they differ. [3](#0-2) [4](#0-3) 

  This exact scenario is covered by existing tests asserting `TokenExchange.perform`/session activation never occurs on mismatch. [5](#0-4) 

`WebhooksManager.queue(session.shop, session.access_token)` in `PostAuthenticateTasks.install_webhooks` therefore always uses a `session.shop` that has already been bound to the verified token/HMAC-validated claim, not an attacker-controlled request parameter, so the described cross-shop webhook registration path is not reachable. [6](#0-5)

      filtered_params = request.parameters.symbolize_keys.slice(:code, :shop, :timestamp, :state, :host, :hmac)

      oauth_payload = ShopifyAPI::Auth::Oauth.validate_auth_callback(
        cookies: {
          ShopifyAPI::Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME =>
            cookies.encrypted[ShopifyAPI::Auth::Oauth::SessionCookie::SESSION_COOKIE_NAME],
        },
        auth_query: ShopifyAPI::Auth::Oauth::AuthQuery.new(**filtered_params),
      )
      api_session = oauth_payload.dig(:session)
      cookie = oauth_payload.dig(:cookie)

      [api_session, cookie]
    end

    def reject_mismatched_requested_shopify_domain
      requested_domain = requested_shopify_domain
      return false if requested_domain.blank?

      authenticated_domain = authenticated_shopify_domain_from_token
      return false if authenticated_domain.blank? || authenticated_domain == requested_domain

      ShopifyApp::Logger.debug("Shop context validation failed")
      head(:unauthorized)
      true
    end
