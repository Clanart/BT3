## Title
Credential helper trusts an unauthenticated `WWW-Authenticate` header to classify a git remote as "GitHub Enterprise," bypassing real host verification and misdirecting the GitHub sign-in flow - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
GitHub Desktop's git credential-helper trampoline decides whether a remote host is a genuine GitHub/GitHub Enterprise server (and therefore whether to launch the "Sign in to GitHub" OAuth flow and eventually store the resulting token as an `Account`) largely from a `WWW-Authenticate` HTTP response header that git forwards verbatim from the remote server. That header is fully attacker-controlled: any git server the victim happens to authenticate against (a self-hosted repo, a compromised/malicious remote, or a `.git/config` `url.<base>.insteadOf` rewrite planted in a cloned repository) can simply reply with `WWW-Authenticate: Basic realm="GitHub"` and be classified as `'enterprise'` without the normal network-based `isGitHubHost()` verification.

### Finding Description
In `getEndpointKind` [1](#0-0) , Desktop first checks whether the endpoint is dotcom or `.ghe.com` by string matching, and only then falls back to a real verification (`isGitHubHost(endpoint)`, an actual network probe) for HTTPS hosts it doesn't already recognize. However, before reaching that real check, it takes a documented "fast path": [2](#0-1) 

This loop inspects `wwwauth[...]` entries in the credential map that git populates directly from the remote server's HTTP response, and if the value contains `realm="GitHub"`, the function immediately returns `'enterprise'` — completely skipping the `isGitHubHost` network verification that would otherwise be performed for an unknown HTTPS host.

That classification then drives `getCredential`: since `endpointKind !== 'generic'` and there is no existing `Account` for that endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [3](#0-2) .

`promptForGitHubSignIn` unconditionally treats any non-`github.com` hostname as an Enterprise instance and starts the Enterprise sign-in flow scoped to that attacker-controlled origin: [4](#0-3) 

From there, `SignInStore.setEndpoint` / `authenticateWithBrowser` build and open an OAuth authorize URL and later exchange the code and fetch the "user" directly against that same attacker-controlled endpoint (`getOAuthAuthorizationURL`, `requestOAuthToken`, `fetchUser`) [5](#0-4) , and on success the resulting `Account` (login, token, avatar, etc. — all attacker-supplied) is persisted via `AccountsStore.addAccount`, which stores the attacker-supplied token in the OS keychain as a legitimate signed-in account [6](#0-5) .

The broken invariant is analogous to the Escrow bug: a value meant to gate a security-sensitive decision (here, "is this host trustworthy enough to run the GitHub sign-in flow against") is derived from attacker-controlled input (an unauthenticated header from the remote) and is accepted without the check (`isGitHubHost`) that exists specifically to validate it for the untrusted case. No cross-check ties the "GitHub" claim in the header back to any cryptographic or independently-verified property of the host.

### Impact Explanation
An attacker who controls (or can get a victim to add) any HTTPS git remote can cause Desktop to present its native "Sign in to GitHub Enterprise" experience against attacker infrastructure. Because the whole OAuth authorize/exchange/user-fetch loop is then carried out against that same attacker endpoint, a malicious server can harvest whatever the user submits during that flow and can also fabricate an arbitrary "successful" OAuth response, causing Desktop to store an attacker-fabricated `Account`/token as a legitimate signed-in identity. This matches the "unauthorized OAuth or account binding" / "credential/token exfiltration" impact categories, and it is reachable purely by an unprivileged party who controls a git remote/proxy response the victim happens to interact with — no local access, no prior compromise, and no unnatural steps beyond the victim adding/using an attacker-supplied git remote (a normal Desktop workflow).

### Likelihood Explanation
The trigger requires only that git, while authenticating to some HTTPS remote, receives a response containing `WWW-Authenticate: ... realm="GitHub"`. This is a single, trivially-set HTTP header with no verification, so any server the victim adds as a remote (including through an `insteadOf` URL rewrite embedded in a cloned repository's `.git/config`) can trigger it. The only user action required is Desktop attempting to authenticate to that remote (e.g., a normal `fetch`/`push`), which is routine.

### Recommendation
Do not let the unauthenticated `WWW-Authenticate` realm value short-circuit the `isGitHubHost` verification. At minimum, treat the header as a hint that should still be confirmed by the same network-based verification used for unrecognized HTTPS hosts before classifying an endpoint as `'enterprise'` and before invoking `promptForGitHubSignIn`/starting an OAuth flow against that origin.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://attacker.example/victim-repo.git` that, on any authentication challenge, responds with `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this remote in Desktop (e.g., clones it, or a cloned repository's `.git/config` contains `[url "https://attacker.example/"] insteadOf = https://github.com/some/repo`) and performs a fetch/push.
3. Git forwards the header to Desktop's credential helper; `getEndpointKind` (trampoline-credential-helper.ts:153-165) returns `'enterprise'` without calling `isGitHubHost`.
4. `getCredential` finds no existing account for `attacker.example` and calls `ui.promptForGitHubSignIn('https://attacker.example')` (trampoline-credential-helper.ts:118, trampoline-ui-helper.ts:80-104), which opens the GitHub Enterprise sign-in UI scoped to the attacker's origin.
5. The subsequent OAuth authorize/exchange/user-fetch calls (`app/src/lib/api.ts:2357-2396`) go directly to `attacker.example`, letting the attacker return arbitrary "account" data/token that Desktop stores as a real signed-in account (`accounts-store.ts:95-126`).

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export function getOAuthAuthorizationURL(
  endpoint: string,
  state: string
): string {
  const urlBase = getHTMLURL(endpoint)
  const scope = encodeURIComponent(oauthScopes.join(' '))

  return new window.URL(
    `/login/oauth/authorize?client_id=${ClientID}&scope=${scope}&state=${state}`,
    urlBase
  ).toString()
}

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}
