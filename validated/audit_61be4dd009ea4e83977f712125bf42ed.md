### Title
Unrestricted `WombatStaking.convertWOM` allows any wallet to permanently lock protocol WOM into multi-year veWom locks - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking.convertWOM(uint256 _amount)` has no access control beyond `whenNotPaused`, allowing any external wallet to force the contract to approve and lock an arbitrary amount of its own WOM balance into `veWom` for `lockDays` (default 1461 days), even though this function is intended to be called only internally via `mWOM._lockWom` / `lockAllWom`.

### Finding Description
`convertWOM` is declared `external` with no caller restriction: [1](#0-0) 

Compare with the intended internal call path from `mWOM.sol`, which calls `IWombatStaking(wombatStaking).convertWOM(_amount)` after first transferring the corresponding WOM into `wombatStaking`: [2](#0-1) 

Because `convertWOM` is public and unauthenticated, any wallet can call it directly, bypassing the WOM-transfer-in step that `mWOM._convert` performs. Inside `convertWOM`, `IVeWom(veWom).mint(_amount, lockDays)` is invoked with `msg.sender == WombatStaking`, so the mock/lock accounting attributes the resulting veWom lock to `WombatStaking` itself, and the underlying WOM is pulled from whatever balance `WombatStaking` currently holds (harvested WOM rewards pending distribution to rewarders, dust, or WOM in transit between deposit/withdraw operations), not from the caller: [3](#0-2) 

An attacker gains nothing from calling this (the lock benefit accrues to `WombatStaking`), but the call consumes and locks WOM tokens that were not intended to be locked, converting freely-available protocol WOM into an illiquid multi-year veWom position controlled by whichever `lockDays` value is currently set.

### Impact Explanation
Any wallet can trigger permanent (multi-year, default 1461-day) locking of WOM tokens held by `WombatStaking` at will, with zero cost beyond gas, whenever the contract holds any transient WOM balance (e.g., harvested rewards awaiting distribution via `_toMasterWomAndSendReward`, or WOM temporarily routed through `WombatStaking` during deposit/withdraw flows). This satisfies the "permanent freezing of funds" / "theft or permanent freezing of unclaimed yield" criteria, since the locked WOM becomes unavailable for reward distribution or protocol operations for years, well beyond the 24-hour threshold, and cannot be recovered by the legitimate owners of that value.

### Likelihood Explanation
High: the function requires no special permission, no flashloan, and no market conditions — any address can call `convertWOM` at any time `WombatStaking` is not paused and holds a nonzero WOM balance. The only precondition is that `WombatStaking` has some WOM sitting in it, which routinely happens as part of normal harvest/reward-distribution cycles.

### Recommendation
Restrict `convertWOM` to only be callable by trusted internal callers (e.g., `onlyOwner`, or a modifier allowing only `mWom`/the contract itself), mirroring the access pattern already used for `deposit`/`withdraw` via `_onlyPoolHelper`/`_onlyActivePoolHelper`.

### Proof of Concept
1. Wait for/observe `WombatStaking` holding a nonzero WOM balance (e.g., after `harvest()` is called for any pool, harvested WOM sits in the contract before `_toMasterWomAndSendReward` routes it).
2. From any unprivileged wallet, call `WombatStaking.convertWOM(amount)` directly with `amount` up to the contract's current WOM balance.
3. `convertWOM` approves `veWom` and calls `IVeWom(veWom).mint(amount, lockDays)`, pulling `amount` WOM from `WombatStaking`'s own balance and locking it for `lockDays` (~4 years), with the resulting veWom credited to `WombatStaking`'s own lock slot — permanently removing that WOM from availability to the reward/withdrawal flows it was meant for.

    /// @notice convert WOM to mWOM
    /// @param _amount the number of WOM to convert
    /// @dev the WOM must already be in the contract
    function convertWOM(uint256 _amount) whenNotPaused external returns(uint256) {
        uint256 veWomMintedAmount = 0;
        if (_amount > 0) {
            IERC20(wom).safeApprove(veWom, _amount);
            veWomMintedAmount = IVeWom(veWom).mint(_amount, lockDays);
        }

        emit WomLocked(_amount, lockDays, veWomMintedAmount);

        return veWomMintedAmount;
    }
