### Title
Missing non-payable check on `distribution.rewards()` allows value-bearing calls to strand sent wei at the precompile address - (File: precompiles/distribution/distribution.go)

### Summary
The `distribution` precompile's `rewards` query method is dispatched at [1](#0-0)  without validating that `value == 0`, unlike every sibling query in the same file, which explicitly guards via `p.validateInput` → `pcommon.ValidateNonPayable(value)` (e.g. [2](#0-1) , [3](#0-2) ). The `p.rewards` implementation at [4](#0-3)  never touches `value` at all — it purely queries `distrKeeper.DelegationTotalRewards` and packs a return value. No `pcommon.HandlePaymentUsei` or equivalent bookkeeping call is made to record/move/refund the wei that accompanies a value-bearing `CALL`.

### Finding Description
This is the same bug class as the Vyper `raw_call` advisory: a call path that superficially looks like it can carry `value` semantics silently drops/ignores that value instead of rejecting it outright. Whereas Vyper's issue is scoped to opcode-level impossibility (`delegatecall`/`staticcall` cannot move value), Sei's analog is a Go-level omission: a real `CALL` (not delegatecall/staticcall) to the `distribution` precompile invoking `rewards(address)` with nonzero `msg.value` is allowed through the delegatecall/staticcall guard at [5](#0-4)  (view methods skip the `readOnly` check entirely) and reaches `p.rewards` with the `value` parameter simply discarded — the function signature at [6](#0-5)  doesn't even accept a `value` argument. Because the underlying EVM `CALL` opcode performs the actual wei balance transfer from caller to the precompile's EVM address as part of normal EVM semantics (this happens irrespective of what the precompile logic does), any wei sent this way lands in the precompile address's EVM balance and is never converted to usei, refunded, or otherwise accounted for by the Cosmos-side bank keeper.

### Impact Explanation
Any externally owned account or contract that calls `rewards(address)` on the distribution precompile (0x...1007) with nonzero `msg.value` permanently strands that value at the precompile's EVM address — it is not credited to any usei balance and there is no code path to reclaim it. This is a direct, unrecoverable fund-loss/freezing bug reachable by any ordinary EVM transaction sender, satisfying the "permanent freezing of funds" impact criterion.

### Likelihood Explanation
Trivial to trigger: any account can call `distribution.rewards(delegatorAddress)` via `eth_call`/a real transaction with `value` set to a nonzero amount, exactly analogous to the PoC in the original Vyper report. The test suite (`integration_test/precompile_tests/precompiles/distribution.spec.ts`) even documents this quirk directly, confirming the maintainers are aware value-bearing calls to `rewards()` "would succeed and strand the funds" [7](#0-6) .

### Recommendation
Add a `pcommon.ValidateNonPayable(value)` check to the `RewardsMethod` case in `Execute` (or inside `p.rewards`), mirroring every other view method in the file, so that a value-bearing call to `rewards()` reverts instead of silently accepting and stranding the funds.

### Proof of Concept
1. Associate an EVM address with a Sei address and ensure it has a delegation with accrued rewards.
2. Send a transaction (or use a contract via the `PrecompileCaller.callTarget` pattern shown at [8](#0-7) ) to `0x0000000000000000000000000000000000001007` calling `rewards(delegatorAddress)` with `value: 1000000000000` (1 usei-equivalent wei) or more.
3. Observe the call succeeds and returns reward data, exactly as a zero-value call would.
4. Observe the sender's EVM balance decreased by the sent value, but no corresponding usei balance change occurs anywhere in the Cosmos bank module, and the precompile's address permanently holds the wei with no withdrawal path.

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
