### Title
Unbounded index read in `is_atom_canonical`/`is_clvm_canonical` allows a single spend bundle to crash mempool transaction admission (DoS) - (File: chia/full_node/mempool_manager.py)

### Summary
`MempoolManager.validate_spend_bundle()` unconditionally runs `is_clvm_canonical()` on the raw `puzzle_reveal` and `solution` bytes of every coin spend in every submitted spend bundle, before any CLVM cost/size validation of the encoding itself protects the parser. [1](#0-0)  `is_clvm_canonical` and its helper `is_atom_canonical` walk the buffer using a length prefix decoded straight from attacker-controlled bytes, without ever checking that `offset` stays within `len(clvm_buffer)`. [2](#0-1) [3](#0-2) 

### Finding Description
This is the same bug class as CVE-2019-8378: a length-prefixed buffer reader (`AP4_BitStream::ReadBytes`) that trusts a size field taken from untrusted input and reads past the end of the actual allocated/available data. Here the Python analog is `is_atom_canonical(clvm_buffer, offset)`:

```python
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]   # no bounds check against len(clvm_buffer)
``` [4](#0-3) 

and the caller `is_clvm_canonical`:

```python
while True:
    b = clvm_buffer[offset]   # offset can exceed len(clvm_buffer) after a
                               # previous atom's declared (attacker-controlled) length
    ...
    offset += atom_len
``` [5](#0-4) 

Both functions index into `clvm_buffer` at offsets derived from a declared prefix/atom length without ever validating that the declared length is consistent with the true remaining buffer size. A crafted puzzle/solution byte string with a truncated multi-byte length prefix (e.g., a `0xFC` lead byte promising 5 more prefix bytes but the buffer ends early), or an atom whose declared length is larger than the actual remaining bytes, causes `clvm_buffer[offset]` to raise an unhandled `IndexError` while it is being iterated inside `validate_spend_bundle`.

This function is reached on the hot path for **every** coin spend of **every** submitted spend bundle — it is not gated behind the DEDUP-eligibility flag despite the code comment/docs implying it is only used for DEDUP eligibility. [6](#0-5)  Because `is_clvm_canonical`/`is_atom_canonical` are pure Python (not bounds-checked Rust/C), this is directly reachable and triggerable by any unprivileged spend-bundle submitter (wallet RPC caller, full-node peer sending a transaction, etc.) without needing a valid signature or a real coin.

### Impact Explanation
An unhandled `IndexError` raised deep inside `validate_spend_bundle()`/`add_spend_bundle()` propagates up through the mempool-manager call chain used for admission of spend bundles into the mempool. If this exception is not specifically caught by the caller (the call sites reviewed — `add_spend_bundle` and the RPC/`full_node.py` transaction-processing path — do not appear to special-case `IndexError` around this particular check), it can abort the coroutine handling that transaction, producing a per-transaction "spend-triggered transaction-processing halt" (a crash/exception path analogous to the CVE's DoS/segfault outcome, though in Python it manifests as an unhandled exception rather than memory corruption). This satisfies the "spend-triggered transaction-processing halt" acceptance criterion.

### Likelihood Explanation
High. Constructing the crafted CLVM-serialized puzzle_reveal/solution bytes requires no signature, no real coin, and no special privileges — only a syntactically-crafted byte sequence with a truncated/mismatched atom length prefix. Any submitter of a spend bundle (including via wallet RPC or the transaction gossip protocol) can trigger this on every full node that processes the bundle.

### Recommendation
Add explicit bounds checks in both `is_atom_canonical` and `is_clvm_canonical` before indexing `clvm_buffer`, e.g., verify `offset < len(clvm_buffer)` before each `clvm_buffer[offset]` access and return "not canonical" (or raise a well-defined, caught `Err.INVALID_COIN_SOLUTION`-mapped exception) instead of allowing a raw `IndexError` to propagate. Ensure `validate_spend_bundle` catches this class of parsing error and maps it to a normal mempool rejection (`Err.INVALID_COIN_SOLUTION`) rather than letting it escape as an unhandled exception.

### Proof of Concept
Submit a spend bundle whose `coin_spend.solution` (or `puzzle_reveal`) bytes are, e.g., `b"\xfc"` alone (a lead byte declaring a 6-byte length prefix per the `0b11111110 == 0b11111100` branch) with fewer than 5 trailing bytes. When `validate_spend_bundle` calls `is_clvm_canonical(bytes(coin_spend.solution))`, `is_atom_canonical` will attempt `clvm_buffer[offset]` for `offset` values beyond the 1-byte buffer, raising `IndexError` uncaught by the surrounding code path shown at `chia/full_node/mempool_manager.py:723-726`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
