### Title
Instant reward crystallization in reward pools allows unpenalized flash-deposit reward skimming - ([File: rewards/BaseRewardPool.sol, rewards/BaseRewardPoolV2.sol, rewards/mWOMSVBaseRewarder.sol, rewards/vlMGPBaseRewarder.sol])

### Summary
Newly queued rewards (WOM staking rewards / bribes harvested by `WombatStaking`, MGP forfeits, or any `donateRewards` call) are immediately baked into `rewardPerTokenStored` based on `totalStaked()` at the instant `_provisionReward` executes, with no vesting, streaming, or epoch-based release. Because `MasterMagpie.deposit`/`withdraw` (and the pool-helper `depositFor`/`withdrawFor` wrappers) impose no lock-up or minimum holding period, any wallet can deposit into the pool immediately before a reward injection and withdraw immediately after, capturing a full pro-rata share of rewards that were earned by other stakers holding risk over the preceding period — the exact bug class described in the report ("premium/reward paid instantly to LPs", enabling withdrawal without taking on risk for the period).

### Finding Description
`_provisionReward` in `rewards/BaseRewardPool.sol` (lines 297-320), `rewards/BaseRewardPoolV2.sol` (lines 290-314), `rewards/mWOMSVBaseRewarder.sol` (lines 305-328), and `rewards/vlMGPBaseRewarder.sol` (lines 309-325) all follow the same pattern: [1](#0-0) 

```
rewardInfo.rewardPerTokenStored =
    rewardInfo.rewardPerTokenStored +
    (_amountReward * 10**stakingTokenDecimals) /
    totalStaked();
```

This instantly converts the entire incoming reward amount into `rewardPerTokenStored` divided by the *current* total staked amount — a single-block snapshot with no time-weighting. Any staker present at that moment (including one who deposited seconds earlier) is credited its full share via `earned()`/`_earned()`, which multiplies the user's current `balanceOf()` by the (now-updated) `rewardPerToken()` delta: [2](#0-1) 

Deposits and withdrawals from `MasterMagpie` have no cooldown: `deposit`/`withdraw` and `depositFor`/`withdrawFor` execute atomically with no vesting/lock window: [3](#0-2) [4](#0-3) 

The pool helpers (`wombat/WombatPoolHelper.sol`, `wombat/WombatPoolHelperV2.sol`, `wombat/AnkrBNBPoolHelper.sol`) let ordinary users deposit and withdraw LP positions in a single unprivileged transaction each: [5](#0-4) 

Additionally, `donateRewards` on all four reward-pool contracts is callable by *any* address (not `onlyManager`) for already-registered reward tokens, meaning even the reward-injection trigger itself is not privileged: [6](#0-5) 

Combining these: a user can (1) deposit a large amount of LP/staking tokens into the pool via the helper right before `WombatStaking.harvest()` (or any `queueNewRewards`/`donateRewards` call) executes, (2) receive `getRewards`/`getReward` crediting a full pro-rata share of the newly queued reward computed against `totalStaked()` at that instant, and (3) withdraw the principal immediately afterward — diluting the rewards legitimately earned by long-term stakers who bore exposure to the position/risk over the accrual period.

### Impact Explanation
This allows theft/dilution of unclaimed yield belonging to genuine long-term stakers: an attacker with sufficient capital can systematically front-run every `queueNewRewards`/harvest call, extracting a share of rewards proportional to their flash-deposited capital while contributing zero time-weighted exposure. Over repeated cycles this can materially reduce (steal) the yield due to honest liquidity/stake providers, which falls under "theft or permanent freezing of unclaimed yield."

### Likelihood Explanation
High. No privileged role or governance action is required — the attacker only needs capital to temporarily inflate `totalStaked()` and a straightforward transaction ordering around predictable/periodic reward injections (e.g., `WombatStaking.harvest`, MGP forfeit provisioning, or the fully public `donateRewards`). No lock-up, cooldown, or streaming mechanism currently prevents this.

### Recommendation
Do not crystallize the entire `_amountReward` into `rewardPerTokenStored` in a single step. Stream rewards over a fixed duration (e.g., epoch-based or `rewardRate`/`periodFinish` linear streaming as already used elsewhere in the codebase, e.g. `wombat/WomUp.sol`'s `rewardPerToken()`/`lastTimeRewardApplicable()` model) so that `rewardPerTokenStored` only increases gradually over elapsed time relative to `periodFinish`, and/or introduce a minimum staking duration or withdrawal delay in `MasterMagpie`/pool helpers to prevent same-block or near-instant deposit-then-withdraw reward extraction.

### Proof of Concept
1. Attacker monitors mempool/schedule for an upcoming `WombatStaking.harvest(lpToken)` call (or calls the unprivileged `donateRewards` themselves after front-running with a deposit).
2. Immediately before the reward-provisioning transaction, attacker calls `WombatPoolHelper.deposit()` → `MasterMagpie.depositFor()` with a large LP amount, inflating `totalStaked()`.
3. The reward transaction executes `_provisionReward`, computing `rewardPerTokenStored += (_amountReward * 10**decimals) / totalStaked()` using the now-inflated `totalStaked()` that includes the attacker's freshly deposited stake.
4. Attacker calls `getRewards`/`getReward` to claim their pro-rata share of `_amountReward`, computed via `earned()`/`_earned()` using their full `balanceOf()`.
5. Attacker calls `WombatPoolHelper.withdraw()` → `MasterMagpie.withdrawFor()` to immediately unstake principal, having borne no time-weighted exposure yet captured a full share of the reward meant for existing long-term stakers.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }
