## Analysis

The external report's core invariant: **a contract executes arbitrary calldata against an untrusted target, grants token approvals for that call, and fails to revoke them afterward — leaving funds it later holds exposed to theft by anyone holding the stale approval.**

The Hyperbridge analog is stronger than a "stale approval" issue: the shared `CallDispatcher` contract that IntentGatewayV2's predispatch/postdispatch flow relies on has **no caller restriction at all** on its fund-moving entrypoint. [1](#0-0) 

`dispatch()` is `external` with zero access control — no `onlyGateway`, no `onlyOwner`, nothing gating who can invoke it: [2](#0-1) 

This single `CallDispatcher` instance is the shared execution sink for **every** IntentGatewayV2 order's predispatch and postdispatch calldata, referenced via `_params.dispatcher`: [3](#0-2) [4](#0-3) 

It also has a bare `receive()` explicitly meant to accept ETH: [5](#0-4) 

Because `dispatch()` is public and unauthenticated, any external account can call `CallDispatcher.dispatch()` directly (bypassing IntentGatewayV2 entirely) with a `Call[]` that transfers out, or approves an attacker address for, any ERC20 balance the dispatcher currently holds, or drains its native ETH balance — no "stale approval" setup step is even required since `dispatch()` itself is the theft primitive.

### Title
Unauthenticated `CallDispatcher.dispatch()` allows anyone to drain any token/ETH balance the shared dispatcher holds - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch(bytes)` is `external` with no caller restriction. This contract is the single, shared execution sink used by `IntentGatewayV2` for all orders' predispatch and postdispatch calldata, and it accepts arbitrary ETH via a public `receive()`. Any account that manages to have the dispatcher transiently or persistently hold a token/ETH balance can have that balance stolen by anyone, since a random unprivileged caller can invoke `dispatch()` directly with a `Call[]` that transfers the balance to themselves, or grants themselves an approval over it — the exact bug class from the external report (untrusted-target approval/fund exposure not gated), except here the exposure requires no prior approval grant at all because the call-execution entrypoint itself is unauthenticated.

### Finding Description
`IntentGatewayV2` escrows/moves assets through `CallDispatcher` for predispatch (swap-then-escrow) and postdispatch (fill-then-act) flows: [3](#0-2) [6](#0-5) 

Within a single transaction, assets are pushed to the dispatcher, `dispatch()` runs order-supplied calldata, and residual balances are swept back to the gateway. This works safely only because these steps are atomic within one transaction. However, `CallDispatcher.dispatch()` itself has no modifier restricting the caller: [7](#0-6) 

and it exposes a `receive()` that accepts ETH from anyone at any time: [8](#0-7) 

Because the same `CallDispatcher` address is reused across every order and is documented as a standing, addressable deployment ("Existing `CallDispatcher` deployments are listed on the contract addresses page"), any ETH sent to it directly (accidental transfers, MEV-bot mistakes, or ETH left over from a reverted/partial flow) or any ERC20 dust that lands on it outside the atomic gateway flow is immediately exposed: an attacker calls `dispatch()` with `Call({to: token, data: transfer(attacker, balance)})` or `Call({to: attacker, value: balance, data: ""})` and takes it, since no `msg.sender` check exists.

### Impact Explanation
This directly matches the required impact class: unauthorized execution and theft/loss of funds through an unprivileged public entrypoint. Any value the dispatcher holds outside a single atomic gateway transaction — ETH sent to its `receive()`, or ERC20 dust — is claimable by any attacker calling `dispatch()`, with no order/proof/relayer/admin dependency.

### Likelihood Explanation
The attack requires no privileged role, no malicious relayer/prover, and no front-running: any account can call `dispatch()` on the known, standing `CallDispatcher` address at any time. The only precondition is that the dispatcher holds a nonzero balance outside of a single already-completed gateway transaction, which is plausible given the contract explicitly implements `receive()` for stray ETH and is a long-lived, address-stable, publicly known contract.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the `IntentGatewayV2` (or another explicitly whitelisted caller), e.g., via an `onlyAuthorizedCaller` modifier set at construction/configuration, mirroring the `onlyHost` pattern already used elsewhere in the codebase for privileged callbacks. Additionally, remove or guard the unconditional `receive()` so stray ETH cannot accumulate in a contract with an otherwise-arbitrary-call surface, and add a sweep/rescue function restricted to governance for any residual dust rather than leaving it reachable via unauthenticated `dispatch()`.

### Proof of Concept
```solidity
// Attacker contract needs no special setup — CallDispatcher has no access control.
// 1. Wait for (or induce) any ETH/token balance on CallDispatcher, e.g. someone
//    mistakenly sends ETH to the dispatcher's address (receive() accepts it).
// 2. Attacker calls dispatch() directly:
Call[] memory calls = new Call[](1);
calls[0] = Call({
    to: attacker,
    value: address(callDispatcher).balance,
    data: ""
});
callDispatcher.dispatch(abi.encode(calls)); // succeeds — no caller check
// Attacker has now drained CallDispatcher's ETH balance.
// The same works for any ERC20 balance via a `transfer(attacker, balance)` Call.
```

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
