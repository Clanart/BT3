### Title
EVM pointer precompile bypasses the `RegisterPointerDisabled` governance switch enforced on `MsgRegisterPointer` - (File: precompiles/pointer/pointer.go)

### Summary
The `RegisterPointerDisabled` chain parameter is meant to be a global kill-switch that blocks creation of new CW↔ERC pointer contracts. It is correctly enforced in the Cosmos `MsgRegisterPointer` message-server path, but the EVM pointer precompile (`0x...100b`), which exposes the equivalent `addNativePointer`/`addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` functionality to any EVM transaction sender, never checks this parameter at all. This is the same bug class as the GitLab report: a resource-gating setting is respected on one access path but silently bypassable through a parallel access path to the same underlying capability.

### Finding Description
`Keeper.GetRegisterPointerDisabled` reads the `RegisterPointerDisabled` param and is used to gate pointer registration [1](#0-0) . The Cosmos message handler for `MsgRegisterPointer` enforces this flag: when it is set, all four pointer types (`ERC20`, `ERC721`, `ERC1155`, native) are rejected with "registering CW->ERC pointers has been disabled", as confirmed by `TestRegisterPointerDisabled` [2](#0-1) .

However, the EVM pointer precompile executor — which implements the same registration capability (`AddNative`, `AddCW20`, `AddCW721`, `AddCW1155`) reachable via any EVM `CALL` to address `0x000000000000000000000000000000000000100b` — contains no reference to `RegisterPointerDisabled` / `GetRegisterPointerDisabled` anywhere in its dispatch or per-method logic [3](#0-2) . Each method only validates payability, argument length, and denom/contract-specific pre-conditions before calling `UpsertERCNativePointer` / `UpsertERCCW20Pointer` / `UpsertERCCW721Pointer` / `UpsertERCCW1155Pointer` directly [4](#0-3) [5](#0-4) .

The legacy precompile versions (`v552`, `v562`, `v580`, `v600`, `v605`, `v610`, `v614`, `v630`, `v640`, `v67`) exhibit the identical omission — none of them check `RegisterPointerDisabled` before performing the pointer upsert [6](#0-5) .

### Impact Explanation
Governance/operators disable pointer registration via `RegisterPointerDisabled` presumably to stop further CW↔ERC pointer creation (e.g., during an incident, to prevent spoofed/duplicate token pointers, or to freeze the pointer namespace). Any unprivileged EVM transaction sender can bypass this intended restriction simply by calling the pointer precompile instead of submitting `MsgRegisterPointer`, creating new native/CW20/CW721/CW1155 pointer contracts and permanently persisting them via `SetERC20NativePointer`/`SetCW*Pointer`-style keeper calls. This directly defeats a governance-controlled authorization boundary and can be used to register malicious or confusing pointer contracts (e.g. spoofing legitimate CW20/CW721 tokens as ERC pointers) at exactly the time operators intended to prevent it — an authorization bypass on a precompile-mediated CW↔EVM bridge resource.

### Likelihood Explanation
High likelihood of exploitation once discovered: the precompile is a standard public entry point reachable by any address with a `CALL`, requires no special privileges, and the missing check is a simple code omission (not requiring any race condition or complex setup) — a single transaction from any account suffices.

### Recommendation
Add a `k.evmKeeper.GetRegisterPointerDisabled(ctx)` check (mirroring the one in `msg_server.go`'s `RegisterPointer` handler) at the top of `PrecompileExecutor.Execute` (or individually in `AddNative`, `AddCW20`, `AddCW721`, `AddCW1155`) in `precompiles/pointer/pointer.go`, returning the same "registering CW->ERC pointers has been disabled" error when the flag is set. Apply the same fix to any still-reachable legacy precompile versions if they can be selected for currently active upgrade heights.

### Proof of Concept
1. Governance passes a param-change proposal (or operator sets via upgrade) setting `x/evm` param `RegisterPointerDisabled = true`.
2. Confirm the Cosmos path is blocked: sending `MsgRegisterPointer{PointerType: ERC20, ErcAddress: <addr>}` fails with "registering CW->ERC pointers has been disabled" (per `TestRegisterPointerDisabled`).
3. From any EVM account, call the pointer precompile at `0x000000000000000000000000000000000000100b` with `addNativePointer(<denom-with-metadata>)` (or `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` with a valid CW contract address).
4. The call succeeds and a new pointer contract is deployed and registered via `UpsertERCNativePointer`/`UpsertERCCW20Pointer`, even though `RegisterPointerDisabled` is `true` — demonstrating the governance-mandated restriction is bypassed through the EVM precompile path.

func (k *Keeper) GetRegisterPointerDisabled(ctx sdk.Context) bool {
	if !ctx.IsTracing() {
		return k.GetParams(ctx).RegisterPointerDisabled
	}
	switch {
	case semver.Compare(ctx.ClosestUpgradeName(), "v6.0.6") < 0:
		// Not present in pre-5.8.0 params; use default
		return types.DefaultRegisterPointerDisabled
	default:
		return k.GetParams(ctx).RegisterPointerDisabled
	}
}

func (p PrecompileExecutor) Execute(ctx sdk.Context, method *ethabi.Method, caller common.Address, callingContract common.Address, args []interface{}, value *big.Int, readOnly bool, evm *vm.EVM, suppliedGas uint64, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if readOnly {
		return nil, 0, errors.New("cannot call pointer precompile from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall pointer")
	}

	switch method.Name {
	case AddNativePointer:
		return p.AddNative(ctx, method, caller, args, value, evm, hooks)
	case AddCW20Pointer:
		return p.AddCW20(ctx, method, caller, args, value, evm, hooks)
	case AddCW721Pointer:
		return p.AddCW721(ctx, method, caller, args, value, evm, hooks)
	case AddCW1155Pointer:
		return p.AddCW1155(ctx, method, caller, args, value, evm, hooks)
	default:
		err = fmt.Errorf("unknown method %s", method.Name)
	}
	return
}

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

		return nil, 0, err

	}

	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)

}
