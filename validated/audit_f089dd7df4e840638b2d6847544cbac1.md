**Rationale:**

The described attack requires directly invoking `ContainerRef::write_ref` (an internal `move-vm-types` API) with a hand-crafted `Value::Container(Container::Struct(...))` whose field count differs from the target struct's shape. However, this internal function is never reachable with mismatched-shape data through any legitimate unprivileged entry point (publish, upgrade, script, or write-set), because two independent gates enforce nominal type/shape equality before a `WriteRef` bytecode instruction's value ever reaches this code:

1. **Static bytecode verifier** (`type_safety.rs`): the `Bytecode::WriteRef` case pops the operand and reference types and requires `ref_inner_signature.is_assignable_from(&val_operand)` — i.e., the value's static type must match the reference's pointee type exactly. [1](#0-0) 

2. **Runtime paranoid type checks** (`runtime_type_checks.rs`): `Instruction::WriteRef` calls `mut_ref_ty.paranoid_write_ref(&val_ty)`, which calls `val_ty.paranoid_check_assignable(inner_ty)` — again enforcing exact struct type equality at runtime. [2](#0-1) [3](#0-2) 

Because struct-typed `Value`s can only be constructed via `Pack`/`PackGeneric`/`PackVariant*` (which the verifier and `verify_pack` enforce to consume exactly `field_count` operands matching the struct definition) or by copying an existing value of that exact type via `read_ref`/`copy_value`, any `Container::Struct` value that survives to a `WriteRef` instruction is guaranteed to have the same field count as its destination. [4](#0-3) [5](#0-4) 

The value-layer `assign_nested!` macro inside `ContainerRef::write_ref` only checks that the `Container` *variant* (Struct vs. Vec vs. primitive-vec) matches, not the field count, and performs a wholesale replacement of the entire `NestedValues` rather than a per-field overwrite: [6](#0-5) 

This is a defense-in-depth gap in the value layer, but it is not reachable by unprivileged input (published bytecode, scripts, or write-sets) because such input is always mediated by the static verifier and, when paranoid mode is enabled, by the runtime type checker — both of which reject mismatched-shape writes before they can reach `ContainerRef::write_ref`. Constructing a mismatched `Container::Struct` value to pass into this internal API requires bypassing the verifier/type-checking layers entirely, i.e., assuming direct access to VM-internal Rust APIs rather than any exposed publish/execution surface. This does not satisfy the "unprivileged caller" requirement in the Decision Standard, so there is no valid PackageMetadata/`upgrade_policy` corruption path through this mechanism.

    field_tys: impl Iterator<Item = &'a Type>,

    // have store ability but not key ability.

    pub fn paranoid_write_ref(&self, val_ty: &Type) -> PartialVMResult<()> {
        if let Type::MutableReference(inner_ty) = self {
            val_ty.paranoid_check_assignable(inner_ty)?;
