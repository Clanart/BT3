### Title
Zero-of-zero multisig spending condition allows any address derived with `signatures_required = 0` to be spent with no signatures at all - (File: `stacks-codec/src/transaction.rs`, `stacks-common/src/types/mod.rs`, `stacks-common/src/address/mod.rs`)

### Summary
The reported bug class ("a threshold value of 0 makes the threshold check vacuously true, defeating the purpose of the check") has a direct analog in the Stacks auth code. `MultisigSpendingCondition::verify` and `OrderIndependentMultisigSpendingCondition::verify` compare the number of signatures collected against `self.signatures_required` with no lower bound enforced anywhere in the codec, the constructors, or `StacksAddress::from_public_keys`. If `signatures_required == 0`, both the wire-format decoder and the cryptographic verifier accept **zero signatures and zero public keys** as satisfying the spending condition, exactly mirroring how `quorumVotes == 0` in the Solidity report makes `forVotes < quorumVotes` vacuously false.

### Finding Description
`MultisigSpendingCondition::consensus_deserialize` only requires that the number of signature fields present equals `signatures_required`: [1](#0-0) 
If `signatures_required = 0` and `fields = []`, `num_sigs_given (0) != signatures_required (0)` is false, so deserialization succeeds with no fields at all.

`MultisigSpendingCondition::verify` performs the analogous check on the crypto-verification side: [2](#0-1) 
With an empty `fields` vector, `pubkeys` stays empty and `num_sigs` stays `0`, so `num_sigs (0) != self.signatures_required (0)` is false — the "incorrect number of signatures" branch is never taken.

The address binding check then calls `StacksAddress::from_public_keys(0, hash_mode, 0, &[])`: [3](#0-2) 

`StacksAddress::from_public_keys` only rejects the call if `pubkeys.len() < num_sigs`; for `num_sigs = 0` this is never true, so it happily proceeds to hash an empty public-key list into an address: [4](#0-3) 

The underlying script-hash builder `to_bits_p2sh` (and its segwit counterpart `to_bits_p2sh_p2wsh`) constructs a deterministic Bitcoin-style `0-of-0` `OP_CHECKMULTISIG` script and hashes it, with no rejection of `num_sigs == 0`: [5](#0-4) 

The constructor helper `new_multisig_p2sh` used to build such spending conditions likewise performs no minimum-threshold validation: [6](#0-5) 

The `OrderIndependentMultisigSpendingCondition::verify` path has the identical property (`num_sigs (0) < self.signatures_required (0)` is false): [7](#0-6) 

**Equality broken:** the auth code's implicit invariant is "number of signatures verified == signatures required to authorize spending from this account." When `signatures_required = 0`, this equality is satisfied by construction with zero signatures, zero public keys, and zero cryptographic verification work — i.e., the "signer" address is a well-known, publicly-computable hash that anyone can produce a valid, minimal spending condition for without ever holding a private key.

### Impact Explanation
Any Stacks address whose Hash160 equals `hash160(push_int(0) push_int(0) OP_CHECKMULTISIG)` (P2SH) or the P2WSH analog is permanently and trivially spendable by anyone who crafts a `MultisigSpendingCondition`/`OrderIndependentMultisigSpendingCondition` with `signatures_required = 0` and empty `fields`. Such an address is fully deterministic and computable offline by anyone (no private key material required at all), so if it is ever credited with STX or other fungible/non-fungible assets — whether through direct transfer, a contract computing/funding such a degenerate multisig address, or user error — those assets can be drained by an unprivileged attacker without providing any signature. This directly satisfies the Critical bar: "an asset moving without authorization," since the transaction's auth condition provides no real cryptographic proof of key ownership yet is accepted as fully verified by `TransactionSpendingCondition::verify` (`stacks-codec/src/transaction.rs:1783-1793` dispatches to the same vulnerable per-mode `verify`).

### Likelihood Explanation
Likelihood is Medium: nothing in the codebase prevents constructing or transmitting a `signatures_required = 0` multisig account, and the address is derivable and publicly known in advance (it does not depend on any secret). The condition requires that such a degenerate address actually hold assets before an attacker profits, which requires either a misconfigured signer/wallet setting `num_sigs = 0` at multisig creation time, or any code path (contract, tooling, integration) that computes/funds a multisig address from a threshold value without asserting `threshold >= 1`. There is no minimum-threshold assertion anywhere in `new_multisig_p2sh`, `new_multisig_order_independent_p2sh`, `StacksAddress::from_public_keys`, or the codec decoders to prevent this from ever occurring.

### Recommendation
Add an explicit minimum-threshold check (`signatures_required >= 1`) in:
- `MultisigSpendingCondition::consensus_deserialize` and `OrderIndependentMultisigSpendingCondition::consensus_deserialize` (reject `signatures_required == 0` at parse time),
- `MultisigSpendingCondition::verify` / `OrderIndependentMultisigSpendingCondition::verify` (defense in depth),
- `StacksAddress::from_public_keys` (reject `num_sigs == 0` regardless of hash mode), and
- the `new_multisig_p2sh` / `new_multisig_order_independent_p2sh` constructors, so a zero-of-zero multisig account can never be created, serialized, or verified as valid.

### Proof of Concept
1. Construct (in Rust, using the codec types directly, no private keys needed):
```rust
let signer_hash = to_bits_p2sh(0, &Vec::<Secp256k1PublicKey>::new()); // deterministic, publicly computable
let cond = MultisigSpendingCondition {
    hash_mode: MultisigHashMode::P2SH,
    signer: signer_hash,
    nonce: 0,
    tx_fee: 1,
    fields: vec![],           // no signatures, no public keys
    signatures_required: 0,
};
```
2. Serialize this as the origin `TransactionAuth::Standard` of a `StacksTransaction` and call `.verify(...)`.
3. `verify()` computes `num_sigs = 0`, compares `0 != 0` → false, skips the error; recomputes `addr = StacksAddress::from_public_keys(0, P2SH, 0, &[])`, which succeeds (since `pubkeys.len() (0) < num_sigs (0)` is false) and yields the same `signer_hash`; the `addr.bytes() != &self.signer` check passes. `verify()` returns `Ok(...)` — the transaction is fully "authenticated" with zero signatures and zero keys.
4. Any funds ever sent to the Stacks address corresponding to `signer_hash` can now be spent by constructing this same zero-field spending condition, without knowledge of any private key.

    pub fn from_public_keys(
        version: u8,
        hash_mode: &AddressHashMode,
        num_sigs: usize,
        pubkeys: &Vec<StacksPublicKey>,
    ) -> Option<StacksAddress> {
        // must be sufficient public keys
        if pubkeys.len() < num_sigs {
            return None;
        }

        // address hash mode must be consistent with the number of keys
        match *hash_mode {
            AddressHashMode::SerializeP2PKH | AddressHashMode::SerializeP2WPKH
                // must be a single public key, and must require one signature
                if (num_sigs != 1 || pubkeys.len() != 1) => {
                    return None;
                }
            _ => {}
        }

        // if segwit, then keys must all be compressed
        match *hash_mode {
            AddressHashMode::SerializeP2WPKH | AddressHashMode::SerializeP2WSH => {
                for pubkey in pubkeys {
                    if !pubkey.compressed() {
                        return None;
                    }
                }
            }
            _ => {}
        }

        let hash_bits = public_keys_to_address_hash(hash_mode, num_sigs, pubkeys);
        StacksAddress::new(version, hash_bits).ok()
    }

fn to_bits_p2sh<K: PublicKey>(num_sigs: usize, pubkeys: &Vec<K>) -> Hash160 {
    let mut bldr = Builder::new();
    bldr = bldr.push_int(num_sigs as i64);
    for pubk in pubkeys {
        bldr = bldr.push_slice(&pubk.to_bytes());
    }
    bldr = bldr.push_int(pubkeys.len() as i64);
    bldr = bldr.push_opcode(btc_opcodes::OP_CHECKMULTISIG);

    let script = bldr.into_script();
    Hash160::from_data(script.as_bytes())
}
