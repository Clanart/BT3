### Title
Bitcoin RPC Password Exposed as Plaintext CLI Argument in Bridge CPFP Tool - (File: `core/src/bin/cli.rs`)

---

### Summary

The `clementine-core` CLI binary's `Bitcoin SendTxWithCpfp` subcommand accepts `--bitcoin-rpc-password` as a plaintext command-line argument. Any user on the same machine can read the credential from shell history or a live `ps aux` listing, then authenticate to the Bitcoin Core RPC node and spend UTXOs from the wallet used to fee-bump bridge transactions.

---

### Finding Description

`BitcoinCommands::SendTxWithCpfp` is declared with `#[arg(long)]` on both `bitcoin_rpc_user` and `bitcoin_rpc_password`: [1](#0-0) 

The password is consumed directly as a `String` and passed to `Auth::UserPass`: [2](#0-1) 

A typical invocation looks like:

```
clementine-core bitcoin send-tx-with-cpfp \
  --raw-tx <hex> \
  --bitcoin-rpc-user admin \
  --bitcoin-rpc-password s3cr3t \
  --fee-payer-address <addr>
```

The full command string, including `--bitcoin-rpc-password s3cr3t`, is written to:
- The invoking shell's history file (`.bash_history`, `.zsh_history`, etc.)
- The kernel's `/proc/<pid>/cmdline` for the lifetime of the process, readable by any user with `ps aux` or `cat /proc/<pid>/cmdline`

This is the production binary path, not a test or script.

---

### Impact Explanation

The Bitcoin Core RPC password grants full wallet control over the node it authenticates to. In the Clementine bridge deployment, this wallet:

1. **Holds the CPFP fee-payer UTXOs** used to fee-bump stuck bridge transactions (kickoff, payout, reimbursement). An attacker who drains this wallet can permanently stall any in-flight bridge transaction, causing liveness failure and potential fund lock.

2. **May hold operator collateral or reimbursement UTXOs** if the same Bitcoin Core wallet is used for multiple purposes (common in single-node deployments). Spending these directly constitutes theft of bridged BTC or operator collateral.

3. **Enables unauthorized RPC calls** such as `sendrawtransaction`, `fundrawtransaction`, and `listunspent`, which can be used to front-run or interfere with bridge-critical transactions.

---

### Likelihood Explanation

- The `SendTxWithCpfp` command is an operator-facing maintenance tool invoked manually during bridge operation (e.g., to rescue a stuck kickoff or payout transaction).
- Operators share machines or use shared CI/CD environments in practice.
- Shell history is persistent by default; `/proc` is readable by co-tenants on the same host.
- No privilege escalation is required — any local user account suffices.

---

### Recommendation

**Short term:** Remove `bitcoin_rpc_password` (and `bitcoin_rpc_user`) from `#[arg(long)]` CLI arguments. Read them from the existing `BITCOIN_RPC_USER` / `BITCOIN_RPC_PASSWORD` environment variables instead, consistent with how every other Clementine binary handles these credentials: [3](#0-2) 

**Long term:** Adopt a secrets-manager or credential-file pattern (e.g., `--bitcoin-rpc-credentials-file`) so the credential never appears in any process argument list or shell history.

---

### Proof of Concept

```bash
# Operator runs the CPFP tool to rescue a stuck bridge payout tx:
clementine-core bitcoin send-tx-with-cpfp \
  --raw-tx 0200000001... \
  --bitcoin-rpc-user admin \
  --bitcoin-rpc-password hunter2 \
  --fee-payer-address bcrt1q...

# Attacker on the same machine reads shell history:
$ cat ~/.bash_history | grep bitcoin-rpc-password
  clementine-core bitcoin send-tx-with-cpfp --raw-tx 0200000001... \
    --bitcoin-rpc-user admin --bitcoin-rpc-password hunter2 ...

# Or reads it live from the process table:
$ ps aux | grep clementine-core
  operator  1234  ... clementine-core bitcoin send-tx-with-cpfp \
    --bitcoin-rpc-password hunter2 ...

# Attacker now authenticates to Bitcoin Core and drains the fee-payer wallet:
$ bitcoin-cli -rpcuser=admin -rpcpassword=hunter2 \
    -rpcport=18443 listunspent
# → lists all UTXOs including bridge fee-payer and potentially collateral outputs

$ bitcoin-cli -rpcuser=admin -rpcpassword=hunter2 \
    sendtoaddress <attacker_address> <full_balance>
# → drains the wallet; all pending CPFP fee bumps for bridge txs fail
```
