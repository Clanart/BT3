## Title
Users cannot unlock/withdraw matured VLMGP positions while the contract is paused, freezing already-unlocked MGP - (File: `VLMGP.sol`)

### Summary
`VLMGP.sol` gates every exit path for a user's locked MGP — `unlock()`, `cancelUnlock()`, and `forceUnLock()` — behind the `whenNotPaused` modifier, with no `whenPaused` emergency-exit function like the one `MasterMagpie` provides for its directly staked LP tokens. This means that once the owner pauses `VLMGP` (or the linked `MasterMagpie` contract), a user whose cooldown has already fully matured cannot retrieve their own MGP tokens, even though no debt, borrowing, or liquidation risk is involved — the tokens are simply the user's already-unlocked principal sitting in the contract.

### Finding Description
`unlock()`, which lets a user claim MGP after their cooldown slot's `endTime` has passed, is declared `external override whenNotPaused nonReentrant`: [1](#0-0) 

`cancelUnlock()` and `forceUnLock()`, the other two paths that manipulate/settle a cooldown slot, are similarly restricted: [2](#0-1) 

Internally, `unlock()`/`forceUnLock()` route through `_unlock()`, which calls `MasterMagpie.withdrawVlMGPFor()` — a function that is *itself* also `whenNotPaused`-gated on the `MasterMagpie` side: [3](#0-2) [4](#0-3) 

By contrast, `MasterMagpie` provides an explicit `emergencyWithdraw()` function callable specifically `whenPaused`, so users staking raw LP tokens can always retrieve their principal even during a pause: [5](#0-4) 

No equivalent `whenPaused` escape hatch exists anywhere in `VLMGP.sol`. Users who already went through `startUnlock()` and waited out the full `coolDownInSecs` period have a claim ready to be paid out — the funds are effectively theirs to withdraw — yet a pause (owner-triggered, a normal/expected operational action, not an attack) makes it impossible for them to retrieve it via any code path in the contract.

### Impact Explanation
This mirrors the referenced report's root cause: an unprivileged, otherwise-legitimate exit action (repaying a debt in the original report; withdrawing already-matured, unlocked principal here) is blocked purely by the pause switch, with no alternative recovery mechanism. If the pause persists for any extended duration (which is entirely plausible in an incident-response scenario, e.g. investigating an exploit elsewhere in the ecosystem), affected users' MGP remains completely inaccessible for the whole duration — a freeze of user funds with no way to trigger an exit through any admin-independent path.

### Likelihood Explanation
Pausing is a normal, expected operational lever already wired into this system (it exists precisely to be used defensively). Any user who has an unlock slot mature during or shortly before a pause window is immediately and unavoidably affected — no special conditions or attacker action are required, only the pre-existing (and reachable) combination of "cooldown finished" + "contract paused."

### Recommendation
Add a `whenPaused` emergency-exit function to `VLMGP.sol` (mirroring `MasterMagpie.emergencyWithdraw`) that lets a user pull out the `amountInCoolDown` of any slot whose `endTime` has already passed, without requiring the full `unlock()` reward-claim flow, and without depending on `MasterMagpie.withdrawVlMGPFor` also being pause-gated. Alternatively, remove `whenNotPaused` specifically from `unlock()` for already-matured slots, consistent with the recommendation applied to `repay()` in the referenced finding.

### Proof of Concept
1. User calls `startUnlock()` to begin cooldown on their locked MGP.
2. `coolDownInSecs` elapses; `slot.endTime` is now in the past — the user is entitled to withdraw.
3. Contract owner calls `pause()` on `VLMGP` (or on `MasterMagpie`) for operational/security reasons.
4. User calls `unlock(_slotIndex)` to claim their matured MGP — the call reverts due to `whenNotPaused`.
5. User also cannot use `forceUnLock()` or `cancelUnlock()` — both are equally paused-gated, and there is no `whenPaused` fallback function in `VLMGP.sol`.
6. The user's already-unlocked MGP remains frozen in the contract for the entire duration of the pause.
