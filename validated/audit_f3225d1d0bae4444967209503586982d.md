### Title
Missing lower-bound validation on `kip71.gastarget` allows division-by-zero panic in base fee computation - ([File: params/kip71_config.go])

### Summary
The Kaia governance parameter `Kip71GasTarget` has no format validation preventing a value of `0`. When set to `0` via governance (header-vote or GovParam contract), `KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` without a zero-check, causing a `math/big` division-by-zero panic on every node computing the next block's base fee — a chain-halting consensus DoS, directly analogous to the Kava fix that added checks to "prevent hard conversion factor being < 1" and "prevent cdp liquidation ratio being 0.0" for panic-causing param values.

### Finding Description
`gov.Params[Kip71GasTarget]` uses `noopFormatChecker`, which accepts any `uint64` value including `0`: [1](#0-0) 

Compare this to the sibling parameter `Kip71BaseFeeDenominator`, which explicitly rejects `0`: [2](#0-1) 

Governance votes for any parameter go through `NewVoteData`, which only enforces `param.Canonicalizer` and `param.FormatChecker` — since `Kip71GasTarget`'s checker is a no-op, `0` passes validation cleanly: [3](#0-2) 

The resulting `ParamSet.GasTarget` value is converted directly into `params.KIP71Config.GasTarget` via `ToKip71Config()` with no additional bound checks: [4](#0-3) 

In `NextMagmaBlockBaseFee`, unlike `BaseFeeDenominator` (which has an explicit `if kc.BaseFeeDenominator == 0 { ... fallback ... }` guard), `GasTarget` is used unguarded as a divisor: [5](#0-4) [6](#0-5) 

If `GasTarget == 0` and the parent block used any gas (`parentGasUsed > 0`, the overwhelmingly common case), the code enters the "gas used above target" branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`. Go's `math/big.Int.Div` panics on division by zero (there is no zero-guard as there is for `BaseFeeDenominator`).

`NextMagmaBlockBaseFee` is invoked during header/base-fee verification for every produced block (`VerifyMagmaHeader`) and in the RPC fee-history oracle (`node/cn/gasprice/feehistory.go`), so once the malicious/faulty parameter value takes effect at its activation block, **every full node, validator, and RPC server** that processes or serves the block panics, producing a chain-wide halt.

### Impact Explanation
This is a High severity issue: it enables a consensus-halting Denial-of-Service across the entire network from a single governance parameter change. All nodes computing/verifying the base fee for the corresponding block will panic and crash simultaneously (block validators during consensus, and any full/RPC node serving `eth_feeHistory`), matching the "state divergence between honest nodes / acceptance-of-invalid-transaction-or-block" class of impact the scan targets — in this case worse, since it's an unconditional crash rather than silent divergence.

### Likelihood Explanation
The likelihood depends on whether setting `Kip71GasTarget = 0` is reachable by an unprivileged actor or requires governing-node privilege. Governance votes are recorded in headers by the current block proposer/governing node structure, and the `GovParam` contract path (`contractgov`) applies values via `ParamSet.Set()`, which — as observed — performs only a type assertion and does **not** invoke `FormatChecker` at all, meaning even the contract-based governance path has no validation on this value. This makes the bug reachable through a normal, permitted governance parameter update mechanism (no bypass of authorization required), which is an explicitly in-scope category per the task rules ("governance parameters"). The zero-check being present for the sibling `BaseFeeDenominator` field but conspicuously missing for `GasTarget` strongly suggests this is an overlooked gap rather than an intentional design.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`) rejecting `0`, mirroring `Kip71BaseFeeDenominator`'s checker:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, apply a defensive runtime guard in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator == 0` fallback, so that even out-of-band/contract-set values of `0` cannot crash the node. Also ensure `contractgov`'s `ParamSet.Set()` path enforces the same `FormatChecker` validation as the header-vote path, since it currently bypasses format checking entirely.

### Proof of Concept
1. Governance sets `kip71.gastarget = 0` (via header-vote `NewVoteData(voter, "kip71.gastarget", uint64(0))`, which passes `noopFormatChecker`, or via the `GovParam` contract, which bypasses `FormatChecker` entirely in `ParamSet.Set()`).
2. Once the parameter activates, any block with `parentHeaderGasUsed > 0` (essentially any active chain) triggers `NextMagmaBlockBaseFee`:
   - `parentGasUsed (>0) > gasTarget (0)` → enters the "above target" branch.
   - `y := x.Div(x, new(big.Int).SetUint64(0))` panics with "division by zero".
3. This function is called from `VerifyMagmaHeader` during header verification of every subsequent block, and from `node/cn/gasprice/feehistory.go`'s `processBlock` for `eth_feeHistory` RPC calls — causing both consensus-path nodes and RPC nodes to panic/crash.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
