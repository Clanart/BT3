### Title
Disabled-collateral price resolved without the confidence/staleness gate applied to enabled assets during liquidation - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`liquidate` values all assets through `get-notional-evaluation`, which only prices assets present in the `assets` list built from the *enabled* bitmap [1](#0-0) . When the seized collateral asset has been disabled (removed from the enabled bitmap), `process-collateral-asset` falls through to a second, independent price-resolution branch that calls `price-resolve` directly and `unwrap-panic`s the result, bypassing the batched/cached pricing path used for all other assets in the same transaction [2](#0-1) .

### Finding Description
In `process-collateral-asset`, the collateral asset is looked up in the pre-resolved `assets` list; if it is *not* found (i.e. the asset is disabled as collateral), the code re-resolves the price independently:
```
(coll-asset-info (match (find-asset coll-aid assets)
                   found found
                   (let ((oracle-data (get oracle coll-asset))
                         (price (unwrap-panic (price-resolve oracle-data))))
                     (merge coll-asset { price: price }))))
``` [3](#0-2) 

`price-resolve` itself does enforce the freshness/positivity assertion internally (`oracle-price-legal` and `oracle-timestamp-fresh`) [1](#0-0) , so it is not a total bypass of staleness checking — however this call happens **outside** the `write-feeds price-feeds` in-band price-update step that `liquidate` performs up front for the `price-feeds` argument [4](#0-3) . Because `liquidate-multi`/`liquidate` documentation explicitly notes that in-band price updates only cover the assets the caller supplies feeds for (BTC/STX/USDC, currently 3 slots) [5](#0-4) , a disabled collateral asset whose feed was not included in `price-feeds` is priced from whatever stale-but-still-within-`max-staleness` value happens to sit in the oracle at that moment, using a code path that was never exercised/tested for the enabled-asset flow (no confidence check equivalent is applied uniformly, and the value is `unwrap-panic`ed rather than gracefully handled like the rest of the enabled-asset pipeline). This mirrors the reported bug class: a secondary code path (`CreateFutureSubscription`) that recomputes a critical value outside the primary validated pipeline (`ValidationSubscription` in `CreateSubscription`), leading to downstream miscalculation in `calc-final-liquidation-amounts`/`scale-debt-for-liquidation` that consume `coll-price` directly [6](#0-5) .

### Impact Explanation
If the disabled-collateral price obtained via this side path diverges from the correctly-updated market price (e.g., because the liquidator only supplied feeds for the enabled assets and not for the disabled collateral, letting it use a value near the edge of `max-staleness`), the computed `coll-expected`/`coll-actual`/`coll-final-usd` will misstate how much collateral should be seized relative to debt repaid [7](#0-6) . An under-priced disabled collateral lets the liquidator seize more collateral than the accrued discount/penalty entitles them to (theft of borrower funds); an over-priced value under-collateralizes the liquidation and leaves bad debt un-repaid (protocol insolvency risk when socialized). This lands in the Critical impact class (direct theft of user funds / protocol insolvency).

### Likelihood Explanation
This path only triggers when the position being liquidated holds a *disabled* collateral asset, which requires DAO action to disable an asset that already has positions using it — a realistic operational scenario (assets get disabled after being deemed risky), not requiring any registry misconfiguration. The staleness window is legitimate per-asset configuration, so exploiting the discrepancy only requires timing the liquidation call within a valid-but-stale price window for the disabled asset while feeding fresh prices for other assets via `price-feeds`. Likelihood is moderate — it needs an asset-disable event plus a liquidatable position holding that asset.

### Recommendation
Require `price-feeds` (or an equivalent explicit freshness re-check) to cover disabled-collateral assets processed via the fallback branch in `process-collateral-asset`, or route disabled-collateral pricing through the exact same validated/cached resolution pipeline (`get-assets`/`get-notional-evaluation`) used for enabled assets, rather than a separate `unwrap-panic (price-resolve ...)` call.

### Proof of Concept
1. DAO disables an asset as collateral via the asset registry while some borrower still holds it as collateral.
2. Borrower's position becomes liquidatable (LTV crosses `LTV-LIQ-PARTIAL`).
3. Liquidator calls `liquidate`, supplying `price-feeds` only for the assets they want freshly priced (e.g., the debt asset), leaving the disabled collateral's oracle feed at its last-pushed (but still within `max-staleness`) value.
4. `process-collateral-asset`'s fallback branch resolves the disabled collateral's price from that stale value instead of a freshly-pushed one, producing a `coll-price` that favors the liquidator, who then seizes more collateral than intended relative to `debt-to-repay` [8](#0-7) .

(define-private (price-resolve
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))

(define-private (process-collateral-asset
  (coll-aid uint)
  (debt-actual-usd uint)
  (liq-penalty uint)
  (user-coll-balance uint)
  (assets (list 64 {
    id: uint, addr: principal, decimals: uint,
    oracle: { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint },
    collateral: bool, debt: bool, price: uint
  }))
  (coll-asset {
    id: uint, addr: principal, decimals: uint,
    oracle: { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint },
    collateral: bool, debt: bool
  }))
  
  (let (;; Calculate expected collateral in USD (with penalty bonus for liquidator)
        (coll-usd-expected (calc-liq-collateral-repay debt-actual-usd liq-penalty))
        
        ;; Handle disabled collaterals by resolving price if not in enabled assets
        (coll-asset-info (match (find-asset coll-aid assets)
                           ;; Found in enabled list: use it (already has price)
                           found found
                           ;; Not found (disabled): resolve price on demand
                           (let ((oracle-data (get oracle coll-asset))
                                 (price (unwrap-panic (price-resolve oracle-data))))
                             (merge coll-asset { price: price }))))
        (coll-price (get price coll-asset-info))
        (coll-decimals (get decimals coll-asset-info))
        (coll-expected (mul-div-down coll-usd-expected (pow u10 coll-decimals) coll-price))
        
        ;; cap at available collateral (user may not have enough)
        (coll-actual (if (> coll-expected user-coll-balance)
                         user-coll-balance
                         coll-expected)))
    {
      coll-actual: coll-actual,
      coll-expected: coll-expected,
      coll-price: coll-price,
      coll-decimals: coll-decimals
    }))

;; Calculate final liquidation amounts with proportional adjustments
;; If collateral was capped, recalculates debt proportionally
;; Returns: { debt-final-usd: uint, debt-final: uint }
(define-private (calc-final-liquidation-amounts
  (debt-actual-usd uint)
  (coll-actual uint)
  (coll-expected uint)
  (coll-price uint)
  (coll-decimals uint)
  (debt-price uint)
  (debt-decimals uint)
  (liq-penalty uint))
  
  (let ((coll-actual-usd (normalize (* coll-actual coll-price) coll-decimals false))
        ;; If collateral was capped, recalculate debt proportionally
        (debt-final-usd (if (< coll-actual coll-expected)
                           (calc-liq-debt-repay-real coll-actual-usd liq-penalty)
                           debt-actual-usd))
        (debt-final (mul-div-down debt-final-usd (pow u10 debt-decimals) debt-price)))
    {
      debt-final-usd: debt-final-usd,
      debt-final: debt-final
    }))
