### Title
Git's clone-time repository-content protections are explicitly disabled for every recursive clone, re-enabling attacker-controlled-repo code execution - (File: app/src/lib/git/clone.ts)

### Summary
`clone()` unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the environment used to invoke `git clone --recursive` for every repository GitHub Desktop clones, no matter the source. [1](#0-0)  `GIT_CLONE_PROTECTION_ACTIVE` is Git's own runtime kill-switch for the "clone-time protections" that upstream Git introduced to stop maliciously crafted repositories from exploiting case-insensitive/case-confusable filesystems, NTFS short names, and symlinked/junctioned `.git` metadata paths during a recursive clone that also touches submodules. By forcing this protection off, Desktop reinstates the exact attacker-controlled-repository primitive that the corresponding upstream Git CVEs (the 2024 "clone protections" family) were designed to close, for every clone triggered from the UI, the CLI (`--cli-clone`), and the `x-github-client://openRepo/...` deep link handler that ultimately funnels into this same `clone()` function. [2](#0-1) [3](#0-2) 

### Finding Description
- `clone()` builds the git invocation as `clone --recursive ... -- <url> <path>` and merges `GIT_CLONE_PROTECTION_ACTIVE: 'false'` into the environment alongside the normal remote-operation env. [4](#0-3) 
- The `--recursive` flag causes Git to automatically initialize and check out every submodule listed in the attacker-supplied repository's `.gitmodules`/tree in the same operation, which is precisely the scenario the upstream clone-time protections were built to guard (nested/symlinked `.git` entries, case-collision attacks on case-insensitive file systems such as default macOS/Windows installs, and delayed/hostile checkout of submodule content).
- This code path is reachable purely by an unprivileged action: a user clicking "Clone repository" and pasting/selecting a malicious URL, opening a crafted `x-github-client://openRepo/<url>` deep link, or launching Desktop with `--cli-clone <url>`, all of which resolve to `openOrCloneRepository` → `dispatcher.clone()` → `appStore._clone()` → this `clone()` function. [3](#0-2) [2](#0-1) 
- Existing guards in the same file only cover a different concern — preventing the *destination path* from resolving to a sensitive local directory (`isClonePathSensitive`) — and do nothing to compensate for disabling Git's own in-repository content protections. [5](#0-4) 
- Elsewhere the code base does contain path-traversal protections (`resolveWithin`, `sanitizeCloneName`) and an "unsafe repository" warning for filesystem-ownership mismatches, but none of these address the class of attack that `GIT_CLONE_PROTECTION_ACTIVE` exists to stop, so they do not compensate here. [6](#0-5) 

### Impact Explanation
If the disabled protection is exploited via a crafted repository (or one of its submodules), the result can be files being written outside of the intended working directory (e.g., overwriting hook files or configuration under a colliding `.git` path) at clone time, which can lead to arbitrary code execution when subsequent Git operations run hooks, or silent corruption of the checked-out working tree contents that the user will later commit/push without realizing it was tampered with. This satisfies the "Valid Impact" criteria: the attacker only needs to control a git remote/URL that the victim clones — no local access, no leaked credentials, and no unnatural user steps beyond the normal "clone a repository" workflow.

### Likelihood Explanation
Likelihood is high for any Desktop user who clones a third-party or public repository containing a hostile submodule/tree layout, since:
1. `GIT_CLONE_PROTECTION_ACTIVE=false` and `--recursive` are applied unconditionally to every clone, with no per-repository trust decision.
2. Cloning is one of the most common, unprivileged actions in the app and is also reachable via deep links and CLI flags that can be embedded in a webpage or shared link.
3. There is no user-facing warning equivalent to the existing "unsafe repository ownership" dialog for this specific risk. [6](#0-5) 

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override so Desktop clones with Git's built-in clone-time protections enabled (the default/unset behavior). If the override was added to silence protection-related warnings or unblock some legitimate workflow, that workflow should be handled by allow-listing specific, already-trusted repositories rather than globally disabling the protection for all clones, and any such exception should be paired with explicit user consent similar to the existing "unsafe repository" trust flow.

### Proof of Concept
1. An attacker crafts a public git repository whose tree/submodule layout is designed to defeat Git's clone-time protections (e.g., a submodule path or nested tree entry that collides with `.git` on a case-insensitive filesystem, or a symlink placed to redirect `.git` metadata writes).
2. Attacker shares the repository URL (or a `x-github-client://openRepo/<url>` link, or a page that triggers `--cli-clone <url>`).
3. Victim opens the link or pastes the URL into GitHub Desktop's "Clone repository" dialog.
4. Desktop calls `clone(url, path, options)`, which executes `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` set. [7](#0-6) 
5. Because Git's clone-time safety check is disabled, the crafted repository/submodule content is written/executed as designed by the attacker instead of being rejected by Git, resulting in file writes outside the intended repository directory or execution of attacker-supplied hook content on subsequent Git operations.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)
