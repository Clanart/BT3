### Title
Wrong Price Feed Attached to `stSTXbtc` / `zstSTXbtc` Assets in Protocol Data Pricing Utility - (File: `mainnet/contracts/utility/v0-1-data.clar`)

### Summary
The `get-asset-price` helper in `v0-1-data.clar` prices `stSTXbtc` and `zstSTXbtc` using the `PYTH-STX` feed instead of the `PYTH-BTC` feed, despite the accompanying comments explicitly stating "BTC price". This is the same class of defect as the reported `splay_tree::prev_node_idx` copy/paste bug: a comparison/lookup branch that was copy-pasted from a sibling branch and never updated to reference the correct variable/constant, causing the wrong value to be resolved for a given key.

### Finding Description
In `get-asset-price`, each asset ID branch resolves a price from the correct Pyth/DIA feed and, where relevant, applies the correct liquidity index or ratio. Every other branch correctly matches asset to feed (e.g. `sBTC`→`PYTH-BTC`, `USDC`→`PYTH-USDC`). The `stSTXbtc` and `zstSTXbtc` branches are the exception: [1](#0-0) 

```clarity
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-STX))
;; zstSTXbtc - stSTXbtc price x liquidity index
(if (is-eq aid zstSTXbtc)
    (let ((btc-price (default-to u0 (get-pyth-price PYTH-STX)))
          (lindex (get-vault-liquidity-index stSTXbtc)))
      (mul-div-down btc-price lindex INDEX-PRECISION))
```

Both branches call `get-pyth-price PYTH-STX` — the STX/USD feed — while the surrounding comment and variable name (`btc-price`) make clear the intent was to use `PYTH-BTC`. This is a direct analog of the reported bug: a value meant for one key (BTC) is copy-pasted from, and left pointing at, a sibling key's source (STX), producing a systematically wrong price attached to the wrong asset. The same `get-asset-price` function feeds `sum-collateral-usd` / `sum-debt-usd`, which compute the USD notional of any position holding `stSTXbtc` or `zstSTXbtc`: [2](#0-1) 

### Impact Explanation
Since STX trades several orders of magnitude below BTC, substituting `PYTH-STX` for `PYTH-BTC` massively **understates** the USD value of any collateral or debt denominated in `stSTXbtc`/`zstSTXbtc`. Any consumer of this data contract's health/valuation output for `stSTXbtc`/`zstSTXbtc` positions (e.g. liquidation-eligibility checks, risk dashboards, or third-party integrations that price positions via this read-only utility) will compute a wrong health verdict — reporting genuinely healthy positions as under-collateralized. This falls squarely in the report's wrong-price/wrong-health-verdict class ("a price attached to the wrong asset") and can lead to improper liquidation of solvent positions, resulting in theft of collateral from affected users by the liquidator who acts on the erroneous verdict.

I was not able to fully confirm within the tool budget whether any state-changing liquidation path (e.g. inside `market-vault` or `v0-4-market.clar`) directly consumes `v0-1-data.clar::get-asset-price`/`sum-collateral-usd`/`sum-debt-usd`, or whether these functions are purely off-chain/dashboard read-only helpers with no on-chain state-changing consumer — the core `v0-4-market.clar` pricing path (`resolve-price-feed`/`resolve-callcode`) is config-driven from the asset registry and does not exhibit this hardcoded feed-mismatch. This should be verified before treating the impact as definitively on-chain-exploitable; if it is only used off-chain for display, actual fund-custody impact is limited, but if any permissioned/liquidation logic or third-party integrator relies on this contract's output, the impact is Critical (theft of collateral via wrongful liquidation).

### Likelihood Explanation
The bug is deterministic and always triggers for any query involving `stSTXbtc` or `zstSTXbtc` — no attacker action or oracle manipulation is required, only a query/valuation involving those two asset IDs while both feeds are live (which is the normal operating condition).

### Recommendation
Fix the copy/paste typo by pointing both branches at the correct constant:

```clarity
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-BTC))
;; zstSTXbtc - stSTXbtc price x liquidity index
(if (is-eq aid zstSTXbtc)
    (let ((btc-price (default-to u0 (get-pyth-price PYTH-BTC)))
          (lindex (get-vault-liquidity-index stSTXbtc)))
      (mul-div-down btc-price lindex INDEX-PRECISION))
```
Additionally, audit any other on-chain or off-chain consumer of `get-asset-price`/`sum-collateral-usd`/`sum-debt-usd` for the same asset to confirm whether liquidation or other financial decisions are gated on this value, and add a regression test asserting `get-asset-price(stSTXbtc)` tracks `PYTH-BTC` (not `PYTH-STX`).

### Proof of Concept
1. Call `.v0-1-data.get-asset-price(stSTXbtc)` (or `zstSTXbtc`) with live Pyth feeds where STX/USD ≈ $1 and BTC/USD ≈ $60,000.
2. Observe the returned price ≈ the STX/USD price (~100000000 in 8-decimals for $1) instead of the expected BTC/USD price (~6000000000000 for $60,000) — a ~60,000x undervaluation.
3. Any downstream call to `sum-collateral-usd`/`sum-debt-usd` for a position holding `stSTXbtc`/`zstSTXbtc` collateral will report the position's collateral value near-zero relative to its true worth, producing an incorrect (unhealthy) verdict for what is actually a well-collateralized position.
