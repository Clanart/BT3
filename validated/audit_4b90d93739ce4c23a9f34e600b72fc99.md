## Analysis

The WildFly report's failed invariant is: **a value flagged as sensitive/confidential must never be written into a diagnostic log**; WildFly bypassed this by having the resource adapter's connection-error handler log a raw JMS password at WARNING level.

Protobuf has an explicit, purpose-built analog to this invariant: the `debug_redact` field option, whose entire purpose is "the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials" [1](#0-0) . This is implemented via `TextFormat::Printer::TryRedactFieldValue`/`GetRedactionState`, which checks `debug_redact` and substitutes `[REDACTED]` before a value is written into `DebugString()`/`TextFormat` output [2](#0-1) , and it is exercised extensively by `DebugFormatTest` and `redaction_metric_test.cc`.

However, this redaction logic is applied **only to the printing path**. On the **parsing** path, `TextFormat::Parser::ParserImpl::ReportError`/`ReportWarning` unconditionally embed the raw token text the attacker supplied into the message, and — critically — when the caller does not supply an `io::ErrorCollector` (a very common, arguably default, usage pattern), the parser calls `ABSL_LOG(ERROR)`/`ABSL_LOG(WARNING)` directly, writing that raw content straight into the process's global log stream, without any consultation of `debug_redact`/`GetRedactionState`: [3](#0-2) [4](#0-3) 

Concretely, `ConsumeFieldValue`'s enum-handling branch builds an error/warning string that includes the literal value text taken straight from the tokenizer (`value`), then routes it through `ReportError`/`ReportWarning`: [5](#0-4) 

If the field being parsed is one annotated `debug_redact = true` (e.g. a credential field defined exactly like `RedactedFields.optional_redacted_string` in the test protos [6](#0-5) ) and the attacker supplies a malformed/unknown value for it (e.g., an unrecognized enum literal, or triggers `SkipFieldValue`'s "Invalid field value" / "Cannot skip field value, unexpected token" errors), the raw attacker-echoed token — which is the same bytes as whatever secret the field held or was being set to — is written into the application's log via `ABSL_LOG`, completely bypassing the `debug_redact` protection that was carefully built for the print path. The redaction feature protects `DebugString()`/`Print()`, but has no counterpart guarding `ReportError`/`ReportWarning` during `TextFormat::Parser::Merge/Parse`.

This differs from the JSON/binary parsing error paths (`JsonFormat.java`, `json_format.py`, `src/google/protobuf/json/internal/*`), which do embed raw values into thrown exception messages (`InvalidProtocolBufferException`, `ParseError`) but **return them to the caller** rather than writing directly to a log — that is a normal library contract (the calling application decides what to do with the exception), not an automatic disk/log write by the library itself. It is the *automatic, unconditional* `ABSL_LOG` call inside `TextFormat::Parser` with no `debug_redact` check that most closely mirrors WildFly's failure mode of an automatic warning-level log write exposing a secret.

### Title
TextFormat parser error/warning logging bypasses `debug_redact` field protection - (`src/google/protobuf/text_format.cc`)

### Summary
`TextFormat::Parser`'s error/warning reporting path (`ReportError`/`ReportWarning`) writes the raw, attacker-supplied token text for a field directly to the process log via `ABSL_LOG(ERROR)`/`ABSL_LOG(WARNING)` when no `io::ErrorCollector` is configured. This path does not consult the field's `debug_redact` annotation, unlike the `TextFormat::Printer`'s `TryRedactFieldValue`, meaning a value intended to be hidden from debug output can still be disclosed via parse-error logging.

### Finding Description
Protobuf provides `debug_redact` specifically to prevent sensitive field values (e.g., credentials) from being written to debug logs, and it is enforced when printing via `TryRedactFieldValue`/`GetRedactionState` [7](#0-6) . The parsing path has an entirely separate error-reporting mechanism (`ReportErrorImpl`, `ReportError`, `ReportWarning`) that logs directly to the process log stream when the caller has not supplied a custom `ErrorCollector` [3](#0-2) [4](#0-3) . These error messages embed the literal offending token/value (e.g. `value` in the enum-parsing branch) with no redaction check whatsoever [5](#0-4) . Thus a field marked `debug_redact = true` is protected on the print/serialize-to-string path but not on the parse/error-report path — an inconsistent enforcement of the same security invariant across two code paths in the same class.

### Impact Explanation
If an application parses attacker- or user-supplied TextFormat input (e.g., a config or protocol payload) into a message containing `debug_redact`-annotated fields, and a value for such a field is malformed (wrong enum literal, invalid token, etc.), the parser will, by default, write that raw value into the application's log via `ABSL_LOG`. Because operators typically rely on `debug_redact` to guarantee credentials never appear in logs (that being the option's entire stated purpose), this creates a disclosure of sensitive data to anyone with log access — directly matching CWE-532 (log of sensitive information) in the same manner as the WildFly analog, though scoped to Medium severity because it requires (a) TextFormat parsing of attacker-controlled input, (b) no custom `ErrorCollector`, and (c) a malformed value for a redacted field.

### Likelihood Explanation
Likelihood is moderate-to-low: exploitation requires TextFormat (not the more common binary/ProtoJSON) parsing of untrusted input with default error-collector configuration, and specifically an invalid value on a `debug_redact` field. TextFormat is less frequently used for high-volume, untrusted client-facing input than binary/ProtoJSON, which limits attacker reachability in typical services.

### Recommendation
Route `TextFormat::Parser::ReportError`/`ReportWarning` (and the analogous Java/Python `logger.warning` calls in `TextFormat.checkUnknownFields`/enum-value handling) through the same `GetRedactionState`/`debug_redact` check used by the printer, substituting `[REDACTED]` for any token associated with a redacted field before it is embedded in a log message, or omit the raw value from default (`ErrorCollector == nullptr`) log output entirely.

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}
bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}
