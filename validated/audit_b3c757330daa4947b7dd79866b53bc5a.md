### Title
Uncontrolled Recursion in Wallet Puzzle-Driver Matching Allows Attacker-Controlled RecursionError DOS via Deeply Nested Curried Puzzle Reveals - (File: chia/wallet/outer_puzzles.py, chia/wallet/trading/offer.py)

### Summary
The bug class in the external report is uncontrolled recursion driven by attacker-supplied nested/cyclic input with no depth or cycle limit, causing a `RecursionError` that halts processing (an application-level DOS). The closest reachable analog in this codebase is the wallet's puzzle-driver matching chain (`match_puzzle` → `CATOuterPuzzle.match` / `SingletonOuterPuzzle.match` / `OwnershipOuterPuzzle.match` / `MetadataOuterPuzzle.match` / `CROuterPuzzle.match`, defined in `chia/wallet/outer_puzzles.py` and the individual `*_outer_puzzle.py` files), which recurses once per curried puzzle layer with no maximum-depth guard. This is invoked on **untrusted, attacker-supplied `puzzle_reveal` data** in `Offer.from_spend_bundle()` (`chia/wallet/trading/offer.py:634-664`) and in `Offer.__post_init__()`/`_get_offered_coins()` (`chia/wallet/trading/offer.py:221-304`), both of which run when a wallet **parses an offer file received from an untrusted counterparty**, before any signature or on-chain validity check occurs.

### Finding Description
`match_puzzle()` in `chia/wallet/outer_puzzles.py:49-54` iterates the driver table and calls each driver's `match()`:
```python
def match_puzzle(puzzle: UnknownPuzzle) -> PuzzleInfo | None:
    for driver in driver_lookup.values():
        potential_info: PuzzleInfo | None = driver.match(puzzle)
        ...
```
Each outer-puzzle driver (`CATOuterPuzzle.match`, `SingletonOuterPuzzle.match`, `OwnershipOuterPuzzle.match`, `MetadataOuterPuzzle.match`, `CROuterPuzzle.match`) uncurries the puzzle reveal one layer, and, if the outer layer matches a known mod (e.g. `CAT_MOD`), recurses into the inner puzzle via `self._match(UnknownPuzzle(known_program=inner_puzzle))`, which is bound back to `match_puzzle` itself (see `function_args`/`driver_lookup` wiring at `chia/wallet/outer_puzzles.py:79-89`, and e.g. `chia/wallet/cat_wallet/cat_outer_puzzle.py:33-45`, `chia/wallet/nft_wallet/ownership_outer_puzzle.py:39-56`).

Because CLVM `curry()`/`uncurry()` (`chia/types/blockchain_format/program.py:177-219`) impose no limit on nesting depth, an attacker can construct a `puzzle_reveal` that is `CAT_MOD` curried around `CAT_MOD` curried around `CAT_MOD` … an arbitrary number of times. Each such layer is syntactically valid CLVM and will successfully uncurry and re-match, causing `match_puzzle` to recurse one Python stack frame per layer with **no depth limit and no cycle/visited-set tracking**, directly analogous to the `determine_depth`/fragment-spread recursion in the reported GraphQL bug.

This recursive matching runs on completely unvalidated data:
- `Offer.from_spend_bundle()` (`chia/wallet/trading/offer.py:634-664`) calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` for every `CoinSpend` in a deserialized offer, before checking the aggregated signature or submitting anything to the mempool.
- `Offer.__post_init__()` → `_get_offered_coins()` (`chia/wallet/trading/offer.py:150-175`, `221-304`) also calls `match_puzzle` on every coin spend's puzzle reveal as soon as an `Offer` object is constructed from a received/decoded offer file.

Since offer files are exchanged directly between untrusted counterparties (via bech32-encoded offer strings) and are parsed/inspected by the recipient's wallet *before* the recipient decides whether to accept, an attacker-crafted offer with thousands of nested curry layers in a bogus `puzzle_reveal` will exhaust the Python recursion limit as soon as the victim's wallet inspects the offer (e.g., via `get_offer_summary`, `check_offer_validity`, or `take_offer`), raising an unhandled `RecursionError`.

### Impact Explanation
This is a spend-triggered/offer-triggered processing halt: an unprivileged offer counterparty can craft a malicious offer that, when parsed by the victim wallet (a routine, low-trust operation performed before deciding to accept an offer), crashes the parsing call with an unhandled `RecursionError`. Depending on where this propagates (wallet RPC handler, CLI, GUI backend), this can crash or hang the wallet's offer-handling path, denying the wallet's ability to process offers/trades — a resource-exhaustion / processing-halt condition matching CWE-400/CWE-674, reachable purely through unsigned, unvalidated data supplied by a counterparty (no on-chain action or private key required).

### Likelihood Explanation
Likelihood is high for any wallet user who inspects offers from untrusted parties (a normal, expected workflow for CAT/NFT/DL trading). Constructing the malicious `puzzle_reveal` requires only building nested nested CLVM curry expressions using `CAT_MOD.curry(...)` repeated many times — no valid coin, signature, or spendability is required, since `Offer.from_spend_bundle`/`__post_init__` process the structure before any consensus validation. No special privileges or network position are needed; this is purely a client-side parsing bug triggered by offer-file content.

### Recommendation
- Add an explicit maximum recursion/nesting depth to the `match_puzzle`/outer-puzzle-driver chain (`chia/wallet/outer_puzzles.py` and each `*_outer_puzzle.py` match implementation), raising a controlled `ValueError` instead of recursing unboundedly.
- Alternatively, convert the recursive `match`/`get_inner_puzzle`/`construct`/`solve` traversal into an iterative loop with a bounded layer counter.
- Wrap offer parsing (`Offer.from_spend_bundle`, `Offer.__post_init__`) in a guard that catches `RecursionError` and converts it into a well-defined `ValidationError`/`ValueError` so a malicious offer cannot crash the wallet process/RPC thread.
- Consider adding a general maximum-curry-depth check when uncurrying externally supplied puzzle reveals, independent of the caller.

### Proof of Concept
Conceptual PoC (illustrative, not executed):
```python
from chia.types.blockchain_format.program import Program
from chia.wallet.cat_wallet.cat_utils import CAT_MOD
from chia.wallet.puzzles.puzzle_drivers import UnknownPuzzle
from chia.wallet.outer_puzzles import match_puzzle

# Build a puzzle reveal with N nested CAT_MOD curry layers
inner = Program.to(1)  # arbitrary terminal inner puzzle
puzzle = inner
N = 5000  # exceeds default Python recursion limit
tail_hash = bytes(32)
for _ in range(N):
    puzzle = CAT_MOD.curry(CAT_MOD.get_tree_hash(), tail_hash, puzzle)

# Simulate what Offer.from_spend_bundle()/__post_init__ does for every coin spend
match_puzzle(UnknownPuzzle(known_program=puzzle))  # raises RecursionError
```
An attacker embeds such a `puzzle_reveal` in a `CoinSpend` inside a crafted (unsigned) `SpendBundle`, encodes it as a bech32 offer file, and sends it to a victim. As soon as the victim's wallet parses the offer (`Offer.from_bech32` → `Offer.from_spend_bundle`/`__post_init__`), `match_puzzle` recurses one frame per curry layer and raises an unhandled `RecursionError`, crashing/erroring out the offer-inspection call.
