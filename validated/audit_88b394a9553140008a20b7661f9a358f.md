### Title
`safeTransferFrom` on `CW721ERC721Pointer` performs a phantom/no-op transfer that never touches the underlying CW721 contract, causing NFT ownership desync and double-spend of the CW-side asset - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
`CW721ERC721Pointer` is the EVM-side ERC721 pointer contract that wraps a native CW721 collection through the wasmd precompile [1](#0-0) . It overrides `transferFrom` to actually execute a `transfer_nft` message against the underlying CW721 contract [2](#0-1) , but it never overrides `safeTransferFrom` (nor the internal `_transfer`/`_safeTransfer` hooks that OpenZeppelin's `safeTransferFrom` relies on). All state-reading functions (`ownerOf`, `balanceOf`, `getApproved`, `isApprovedForAll`) are also overridden to query the live CW721 state via the precompile rather than reading OZ's local `_owners`/`_balances` storage [3](#0-2) .

### Finding Description
Because `transferFrom` is overridden but `safeTransferFrom` is not, calling `safeTransferFrom` invokes OpenZeppelin's inherited `_transfer`/`_safeTransfer` internals, which mutate the base contract's dead `_owners`/`_balances` mappings and emit a `Transfer` event — but they never call `_execute` against the wasmd precompile, so the actual CW721 ownership record is untouched. Since every public state getter (`ownerOf`, `balanceOf`, `getApproved`) is overridden to always query the live CW721 contract instead of the mutated local storage, the local mutation performed by `safeTransferFrom` is completely inert and invisible to any subsequent read. The net effect: `safeTransferFrom(from, to, tokenId)` returns success, emits a legitimate-looking `Transfer` event, and (if `to` implements `onERC721Received`) passes the receiver check — yet `ownerOf(tokenId)` immediately afterward still reports `from` as the owner, because the CW721 contract itself was never told to transfer the token.

This is the inverse/mirror of the report's `NFTExchange.buy()` bug (which uses `transferFrom` without a receiver-safety check and can permanently lock a token in a non-receiving contract). Here, in `CW721ERC721Pointer`, the safety-checked method (`safeTransferFrom`) is the one that is broken because it silently no-ops the real cross-VM transfer while looking successful.

### Impact Explanation
This desynchronizes on-chain truth (CW721 owner) from what EVM consumers observe transiently via the `Transfer` event, enabling a double-spend/no-op-transfer pattern: a caller can invoke `safeTransferFrom` against a marketplace, escrow, or receiver contract that trusts the emitted `Transfer` event or return value as proof of transfer, while actually retaining full ownership and control of the underlying CW721 NFT (they can still transfer/sell it again via `transferFrom` or the native CW721 `transfer_nft` message). Any EVM-side integration that relies on `safeTransferFrom` succeeding as proof of custody transfer for this pointer type is vulnerable to loss of funds/assets for the counterparty who believes they received the NFT.

### Likelihood Explanation
Any unprivileged EVM caller holding (or approved for) a CW721-pointer token can trigger this by simply calling the standard, widely-used `safeTransferFrom(address,address,uint256)` or `safeTransferFrom(address,address,uint256,bytes)` entry points — no special privilege or contract deployment needed, and `safeTransferFrom` is the OpenZeppelin-recommended, commonly used transfer method for ERC721, so integrators are likely to call it rather than `transferFrom`.

### Recommendation
Override `_transfer` (or both `safeTransferFrom` overloads) in `CW721ERC721Pointer` to route through the same `_execute`/`transfer_nft` precompile call used by `transferFrom`, followed by the standard `_checkOnERC721Received` safety check, so that `safeTransferFrom` and `transferFrom` are functionally consistent and both actually mutate CW721 state.

### Proof of Concept
1. Deploy/obtain a `CW721ERC721Pointer` for a CW721 collection; account `A` owns token `1` on the CW721 side.
2. `A` calls `pointer.safeTransferFrom(A, B, 1)` where `B` is any EOA or a contract implementing `onERC721Received`.
3. Call succeeds and emits `Transfer(A, B, 1)`.
4. Call `pointer.ownerOf(1)` — it still returns `A` (queried live from the CW721 contract), and querying the CW721 contract directly (`owner_of` query) also still shows `A` as owner, confirming no CW721 state changed.
5. `A` can independently call `transferFrom(A, C, 1)` (or execute `transfer_nft` natively) to actually move the real token elsewhere, proving `B` never received the asset despite the successful `safeTransferFrom` call and emitted event. [2](#0-1) [4](#0-3)

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }

    function ownerOf(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("owner_of", _curlyBrace(tId)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes memory owner_ = JsonPrecompile.extractAsBytes(response, "owner");
        return AddrPrecompile.getEvmAddr(string(owner_));
    }

    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }
