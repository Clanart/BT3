### Title
Symlink-following file write/read escape in `readGitIgnoreAtRoot`/`saveGitIgnore` - (File: app/src/lib/git/gitignore.ts)

### Summary
`readGitIgnoreAtRoot` and its sibling `saveGitIgnore` build the `.gitignore` path with a fixed literal filename joined onto the repository root, and then call Node's `fs` functions (`FS.readFile`, `writeFile`, `FS.unlink`) directly on that path without ever resolving or verifying that the final path is not a symlink pointing outside the working tree.

### Finding Description
```
const ignorePath = Path.join(repository.path, '.gitignore')
FS.readFile(ignorePath, 'utf8', ...)   // readGitIgnoreAtRoot
``` [1](#0-0) 
and
```
const ignorePath = Path.join(repository.path, '.gitignore')
FS.unlink(ignorePath, ...) / writeFile(ignorePath, fileContents)
``` [2](#0-1) 

`repository.path` is not attacker-controlled (it's the local working-directory path chosen by the user), and the joined literal `.gitignore` string is also not attacker-controlled, so this is not a classic path-traversal via string concatenation. The actual escape vector is the filesystem entry itself: an attacker-authored repository can commit a **symlink** named `.gitignore` at the repository root pointing to an arbitrary path outside the working tree (e.g. `../../../../home/victim/.ssh/authorized_keys` or an absolute path). On POSIX systems, `git clone`/`git checkout` will materialize that symlink as a real filesystem symlink when the checkout runs (subject to `core.symlinks`, which defaults to enabled on macOS/Linux) — Desktop's own checkout code (`checkoutBranch`, `checkoutCommit` in `app/src/lib/git/checkout.ts`) simply shells out to `git checkout`/`git clone` and performs no post-checkout symlink sanitization pass. Node's `fs.readFile`, `fs.writeFile`, and `fs.unlink` all follow symlinks by default (they do not `lstat`/verify the target), so any call into `readGitIgnoreAtRoot`/`saveGitIgnore` will transparently operate on the symlink's target file, which can live anywhere on the host filesystem.

This is a real regression relative to the rest of the codebase: the repo already contains a purpose-built utility, `resolveWithin`/`resolveWithinPosix` in `app/src/lib/path.ts`, that explicitly uses `realpath` to detect and reject symlink-based escapes [3](#0-2) , and it is actively used elsewhere for exactly this threat model (e.g. `buildConflictContext` in `app/src/lib/copilot-conflict-context.ts` guards file reads with `resolveWithin` before touching disk) [4](#0-3) . `gitignore.ts` was never updated to use this guard.

**Reachability without unusual user action:**
- `readGitIgnoreAtRoot` is invoked whenever the user opens the "Ignored Files" tab in Repository Settings [5](#0-4)  — a normal, low-friction action that would follow the symlink and leak the target file's contents into the gitignore editor UI (arbitrary file read outside the repo).
- `saveGitIgnore` (write/unlink) is reached through `appendIgnoreRule`/`appendIgnoreFile`, which are wired to the very common "Ignore File (Add to .gitignore)" / "Ignore Folder" context-menu actions on the Changes list [6](#0-5)  and to `Dispatcher.appendIgnoreFile`/`appendIgnoreRule` [7](#0-6) . A single right-click → "Ignore File" on any changed file in a hostile repo would follow the `.gitignore` symlink and overwrite the linked host file with new content (the appended ignore pattern plus whatever was already "read" through the same symlink).

### Impact Explanation
If confirmed on POSIX platforms, this allows an unprivileged attacker who authors a cloned repository to:
- Read the contents of an arbitrary file outside the repository (disclosed into the gitignore editor UI) by having the victim open Repository Settings → Ignored Files.
- Overwrite an arbitrary file outside the repository (e.g., shell rc files, SSH `authorized_keys`, git hooks elsewhere on disk) by having the victim use the ordinary "Ignore File" context-menu action, which is a very natural workflow when reviewing changes in a cloned project.

This matches the class of "Critical: content of a repository the user merely clones/fetches/checks out — paths, symlinks — causing file write/read outside the working tree" referenced in the target scope.

### Likelihood Explanation
Requires the attacker to ship a `.gitignore` symlink in the repository root and the victim to perform one of two very ordinary actions (open Repository Settings, or right-click "Ignore File"). No admin rights, no malware, and no unusual/unnatural steps are needed beyond normal Desktop usage of a hostile repo. The main uncertainty is platform-dependent: on Windows, checking out a symlink typically requires Developer Mode or admin privilege (otherwise Git for Windows converts it to a plain text file containing the link target rather than an actual filesystem symlink), so the practical impact is strongest on macOS/Linux. I was not able to find any code in this repo that normalizes or blocks symlink checkouts on Windows to confirm or rule this out definitively — that would need to be validated with an actual checkout test on Windows.

### Recommendation
In `app/src/lib/git/gitignore.ts`, resolve `ignorePath` through the existing `resolveWithin` (or `resolveWithinPosix`) helper from `app/src/lib/path.ts` before any `fs` read/write/unlink call, and abort (treat as "no gitignore" / raise an error) if the resolved real path escapes `repository.path`, consistent with the pattern already used in `app/src/lib/copilot-conflict-context.ts`.

### Proof of Concept
1. Attacker creates a repository whose root contains a symlink `.gitignore -> ../../../../home/victim/.bashrc` (or an absolute path to a sensitive file), commits it, and pushes it publicly.
2. Victim clones the repository with GitHub Desktop on macOS/Linux; the checkout creates the symlink on disk as-is.
3. Victim opens Repository Settings → Ignored Files: `readGitIgnoreAtRoot` follows the symlink and displays `~/.bashrc` contents in the ignore editor (read escape).
4. Victim right-clicks any changed file and selects "Ignore File (Add to .gitignore)": `appendIgnoreFile` → `appendIgnoreRule` → `saveGitIgnore` follows the symlink via `writeFile` and overwrites `~/.bashrc` with `<original content>\n<escaped pattern>\n` (write escape outside the repository working tree). export async function readGitIgnoreAtRoot(
  repository: Repository
): Promise<string | null> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  return new Promise<string | null>((resolve, reject) => {
    FS.readFile(ignorePath, 'utf8', (err, data) => {
      if (err) {
        if (err.code === 'ENOENT') {
          resolve(null)
        } else {
          reject(err)
        }
      } else {
        resolve(data)
      }
    })
  })
}

/**
 * Persist the given content to the repository root .gitignore.
 *
 * If the repository root doesn't contain a .gitignore file one
 * will be created, otherwise the current file will be overwritten.
 */
export async function saveGitIgnore(
  repository: Repository,
  text: string
): Promise<void> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  if (text === '') {
    return new Promise<void>((resolve, reject) => {
      FS.unlink(ignorePath, err => {
        if (err) {
          reject(err)
        } else {
          resolve()
        }
      })
    })
  }

  const fileContents = await formatGitIgnoreContents(text, repository)
  await writeFile(ignorePath, fileContents)
}

async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
}
