### Title
Auction V2 (`AuctionVersionV2`/`0.0.1`) bid signature excludes `MaxGasPrice`, allowing an unauthorized gas-price value to be injected into an otherwise validly-signed auction bid - ([File: kaiax/auction/eip712.go])

### Summary
The Kaia auction module (`kaiax/auction`), reachable via the `auction_submitBid` RPC from an unprivileged auction bidder/searcher, validates a bid by checking two signatures: the searcher's EIP-712 signature over the `AuctionTx` struct and the auctioneer's signature over the raw bytes of the searcher's signature. For the default/legacy version (`AuctionVersionV2`, `"0.0.1"`), the EIP-712 struct type (`auctionType`) and its `EncodeData()` implementation do not include the `MaxGasPrice` field, even though `BidData.MaxGasPrice` is a live, consumed field of the `Bid` object that is accepted and stored by `ToBid()`/`AddBid()`. Because the auctioneer's signature is computed over the fixed 65-byte `SearcherSig` blob rather than over the bid's field values, neither signature actually authenticates `MaxGasPrice` under the V2 path. This is directly analogous to the reported bug class: data that should be protected by a cryptographic authentication mechanism (here, EIP-712/ECDSA signatures) is instead trusted unauthenticated, similar to how TypeBot trusted unauthenticated webhook path parameters instead of verifying the HMAC signature over the full payload.

### Finding Description
- `auctionType` (V2 typehash) is defined without `maxGasPrice`: [1](#0-0) 
- `Bid.EncodeData()` (used for the default/V2 path) does not append `MaxGasPrice` to the EIP-712 struct encoding: [2](#0-1) 
- `GetHashTypedData` falls back to `EncodeEIP712(b)` (the V2 encoder without `MaxGasPrice`) whenever `version != AuctionVersionV3`, including empty/unknown version strings: [3](#0-2) 
- `ValidateSearcherSig` only recovers and checks the signer against this digest; it never separately checks `MaxGasPrice` consistency: [4](#0-3) 
- The auctioneer's signature is computed purely from the searcher's raw signature bytes (`GetEthSignedMessageHash`), which is not tied at all to `MaxGasPrice`: [5](#0-4) [6](#0-5) 
- `BidPool.validateBidSigs` calls exactly these two checks and, on success, accepts the bid as fully validated: [7](#0-6) 
- The public entry point `auction_submitBid` decodes attacker-supplied `BidInput` (including `MaxGasPrice`) into a `Bid` via `ToBid`, and passes it straight to `bidPool.AddBid`, which calls `validateBid` → `validateBidSigs`: [8](#0-7) [9](#0-8) 

Because `bp.auctionEntryPointVersion` is derived on-chain from the `AuctionEntryPoint` contract's reported version (README states the module tracks the `AuctionEntryPoint` address/version from `SystemRegistry`), any deployment still using (or defaulting/falling back to) the V2 auction entry point causes every accepted bid's `MaxGasPrice` to be effectively unauthenticated: a searcher's valid `SearcherSig`/`AuctioneerSig` pair can be resubmitted through `auction_submitBid` together with an attacker-modified `MaxGasPrice` value, and it will still pass both signature checks, since neither signature is a function of that field.

### Impact Explanation
`MaxGasPrice` is meant to cap/authorize the gas price the searcher will pay when their bid is converted into an actual on-chain bid transaction by the block proposer. If this value is not bound by the searcher's signature, an attacker who has observed (or intercepted, since bids are gossiped over the auction bid-gossip channel per the module's README/topology) a validly-signed V2 bid can resubmit it via the public `auction_submitBid` RPC with an arbitrary `MaxGasPrice`, causing the proposer to build a settlement transaction charging the searcher/bidder a gas price they never actually authorized. This is a concrete instance of "fee or fee-delegation abuse" / unauthorized value extraction against an auction bidder — one of the explicitly in-scope personas — without requiring the bidder's private key.

### Likelihood Explanation
The exploit only requires observing a validly-signed bid (bids are broadcast/gossiped as part of normal auction operation and are visible to peers/relayers) and resubmitting it through the standard `auction_submitBid` RPC with a modified `MaxGasPrice`. No private key, validator/node compromise, or special privilege is needed — only the standard "auction bidder" / public-RPC-caller capability explicitly allowed by scope. The main precondition is that the live `AuctionEntryPoint` reports/falls back to the V2 auction version (`"0.0.1"` or any non-`"0.0.2"` string), which the code treats as the default path.

### Recommendation
Include `MaxGasPrice` in the EIP-712 struct type/hash used for `AuctionVersionV2` (or reject/require it to be zero and unconditionally omitted for V2 while still binding all consumed fields), and/or have `ValidateSearcherSig` explicitly re-derive and check every field that downstream code (`GetTargetTxMap`, bid-to-transaction construction) actually consumes, ensuring no accepted `BidData` field can be varied post-signature without invalidating the searcher's signature.

### Proof of Concept
1. A legitimate searcher signs and submits a V2 bid (`MaxGasPrice` unset/nil) via `auction_submitBid`; the bid is broadcast and gossiped to peers, and `SearcherSig`/`AuctioneerSig` are valid for the `TargetTxHash, BlockNumber, Sender, To, Nonce, Bid, CallGasLimit, Data` fields (per `eip712.go` `EncodeData`).
2. An attacker observes this bid (via gossip, mempool P2P bid channel, or public API) and crafts a new `BidInput` JSON-RPC call to `auction_submitBid`, copying all original fields and signatures verbatim but adding/increasing `MaxGasPrice` to an arbitrary large value.
3. `ToBid()` copies `MaxGasPrice` into the `auction.Bid` object [8](#0-7) .
4. `bidPool.validateBidSigs` recomputes `GetHashTypedData(...)` with the V2 typehash, which does not include `MaxGasPrice` [2](#0-1) , so `ValidateSearcherSig` still succeeds; `ValidateAuctioneerSig` also succeeds since it only checks `SearcherSig` bytes [5](#0-4) .
5. The forged bid (with attacker-controlled `MaxGasPrice`) is inserted into the bid pool as if fully authorized by both the searcher and the auctioneer.

Note: I was unable to trace, within the available tool budget, the exact downstream code path that consumes `Bid.MaxGasPrice` when constructing the on-chain bid transaction (e.g., in the block-builder/bid-tx-generation logic), so the precise mechanics of the resulting fee/value-transfer impact could not be fully confirmed against that consuming code — this should be verified directly in a follow-up before remediation.

func (b *Bid) EncodeData() []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

	return nil

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func ToBid(bidInput BidInput) *auction.Bid {
	bidData := auction.BidData{

		BlockNumber:   bidInput.BlockNumber,
		Sender:        bidInput.Sender,
		To:            bidInput.To,
		Nonce:         bidInput.Nonce,
		Bid:           bidInput.Bid.ToInt(),
		CallGasLimit:  bidInput.CallGasLimit,
		Data:          bidInput.Data,
		SearcherSig:   bidInput.SearcherSig,
		AuctioneerSig: bidInput.AuctioneerSig,
	}
	if bidInput.MaxGasPrice != nil {
		bidData.MaxGasPrice = bidInput.MaxGasPrice.ToInt()
	}
	return &auction.Bid{BidData: bidData}
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
