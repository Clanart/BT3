### Title
Frozen RPC router forwards client Authorization headers to any backend selected by attacker-controlled block parameters - (File: cmd/frozen-rpc-router/router.go)

### Summary
`frozen-rpc-router` is a public-facing EVM JSON-RPC endpoint (see `cmd/frozen-rpc-router/README.md`) that fans requests out to a "live" node and any number of "frozen" archival nodes based on the block number/range embedded in the JSON-RPC call parameters. [1](#0-0)  Route selection is driven entirely by the client-supplied method and parameters (e.g. the `blockNumber` field of `eth_call`, or `fromBlock`/`toBlock` of `eth_getLogs`), which map to one of several operator-configured upstream URLs. [2](#0-1) [3](#0-2) 

### Finding Description
When building the outbound request to whichever upstream is chosen, `newUpstreamRequest` clones the entire inbound header set verbatim and only strips hop-by-hop headers (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `Te`, `Trailer`, `Transfer-Encoding`, `Upgrade`); `Authorization` is not in that list and is therefore forwarded unconditionally: [4](#0-3) [5](#0-4) 

This is structurally the same bug class as GHSA-j562-c3cw-3p5g: the proxy has no per-backend policy (analogous to the missing `forwardToken` setting) to decide whether the `Authorization` header should be forwarded to a given backend service. Here the "backend service" selected for a single client request is not fixed by the operator per-route — it is picked dynamically per JSON-RPC call from a pool of distinct upstream URLs (`live`, and any number of `frozen:<height>` nodes) using untrusted, client-supplied `blockNumber`/`fromBlock`/`toBlock` values. [6](#0-5) 

If an operator protects the live (canonical, most sensitive) node with an Authorization/API-key requirement but points the router at additional frozen archival nodes that are less trusted (e.g. third-party-hosted archive nodes, per the README's example of routing to `10.0.0.12:8545`), a single credentialed client request whose block parameter falls into a frozen interval will transparently carry that same `Authorization` header to the frozen upstream, without any way for the operator to scope the credential per backend. The frozen node need not be compromised for this to be a data-exposure problem — the credential is disclosed to infrastructure it was never intended for, purely because the router does not partition or drop the header based on the resolved backend.

### Impact Explanation
An operator's access-control secret (Authorization bearer token / API key intended for the live node) is disclosed to a different, potentially lower-trust backend chosen entirely by client-controlled input in the RPC call parameters. This is analogous to CWE-200 (sensitive information exposure) as in the referenced advisory. Because this component sits on the public JSON-RPC ingress path (`--listen-address 0.0.0.0:8545` per the README example) and any unprivileged RPC caller can pick the destination backend by choosing the block number in their request, this is directly reachable by a public-RPC client.

### Likelihood Explanation
High reachability: any unauthenticated/low-privilege RPC caller who already holds a valid `Authorization` header for the router can trivially trigger routing to a frozen backend by setting `blockNumber`/`fromBlock` to a historical height, with zero additional preconditions beyond the operator having configured at least one frozen node. The vulnerable code path (`route` → `upstreamForReference` → `newUpstreamRequest`) is exercised on every request that has an explicit block parameter. [2](#0-1) 

### Recommendation
Add a per-upstream policy (mirroring the `forwardToken` fix in the advisory) that controls whether `Authorization`/other sensitive headers are forwarded to a given `upstream` — e.g. an explicit `forwardAuth bool` field on the `upstream` struct set from `frozenNodeConfig`/CLI flags, defaulting to not forwarding to frozen nodes unless explicitly opted in, and strip `Authorization` in `newUpstreamRequest` when the resolved target does not opt in.

### Proof of Concept
1. Operator runs `frozen-rpc-router` with `--live-node` requiring `Authorization: Bearer <secret>` and `--frozen-node 1000000=archive.example.com:8545` (a separate, less trusted node).
2. Attacker/client sends: `POST /` with header `Authorization: Bearer <secret>` and body `{"jsonrpc":"2.0","id":1,"method":"eth_getBalance","params":["0x...","0x1"]}` (block `0x1` falls under the frozen interval).
3. `route()` resolves the target to the frozen upstream via `upstreamForReference` [3](#0-2) , and `newUpstreamRequest` clones the full header set, including `Authorization`, to `archive.example.com:8545`. [4](#0-3) 
4. The frozen node's operator (or anyone who can observe traffic/logs on that node) now has the caller's `Authorization` secret, which was intended only for the live node.

# Frozen RPC router

`frozen-rpc-router` exposes an HTTP EVM JSON-RPC endpoint backed by a live node
and any number of nodes running with `freeze-height`.

A freeze height is an exclusive boundary. A node started with
`freeze-height = 100` serves blocks through height 99, so the router sends
height 99 to that node and height 100 to the next configured interval (or the
live node).

func (r *router) route(call rpcCall) (*upstream, *rpcError) {
	switch call.method {
	case "eth_getLogs":
		return r.routeGetLogs(call.params)
	case "eth_feeHistory":
		return r.routeFeeHistory(call.params)
	default:
		parameterIndex, ok := blockParameterIndexes[call.method]
		if !ok {
			return r.live, nil
		}
		parameter, ok := positionalParameter(call.params, parameterIndex)
		if !ok {
			return r.live, nil
		}
		return r.upstreamForReference(r.parseBlockReference(parameter)), nil
	}
}

func (r *router) routeRange(from, to blockReference) (*upstream, *rpcError) {
	if (!from.known && !from.live) || (!to.known && !to.live) {
		return r.live, nil
	}
	if from.known && to.known && from.height > to.height {
		return r.live, nil
	}
	fromTarget := r.upstreamForReference(from)
	toTarget := r.upstreamForReference(to)
	if fromTarget != toTarget {
		return nil, &rpcError{
			Code:    jsonRPCUnsupportedError,
			Message: "block ranges spanning multiple frozen-node intervals are not supported",
		}
	}
	return fromTarget, nil
}

func (r *router) upstreamForReference(reference blockReference) *upstream {
	if !reference.known || reference.live {
		return r.live
	}
	for _, frozen := range r.frozen {
		if reference.height < frozen.freezeHeight {
			return frozen
		}
	}
	return r.live
}

func (r *router) newUpstreamRequest(request *http.Request, target *upstream, body []byte) (*http.Request, error) {
	endpoint := joinedURL(target.endpoint, request.URL)
	upstreamRequest, err := http.NewRequestWithContext(request.Context(), request.Method, endpoint.String(), bytes.NewReader(body)) //nolint:gosec // endpoint is rooted at an operator-configured upstream URL.
	if err != nil {
		return nil, err
	}
	upstreamRequest.Header = request.Header.Clone()
	removeHopByHopHeaders(upstreamRequest.Header)
	upstreamRequest.Header.Del("Accept-Encoding")
	if host := clientIP(request.RemoteAddr); host != "" {
		prior := upstreamRequest.Header.Get("X-Forwarded-For")
		if prior != "" {
			host = prior + ", " + host
		}
		upstreamRequest.Header.Set("X-Forwarded-For", host)
	}
	return upstreamRequest, nil
}

func removeHopByHopHeaders(header http.Header) {
	for _, name := range strings.Split(header.Get("Connection"), ",") {
		header.Del(strings.TrimSpace(name))
	}
	for _, name := range []string{
		"Connection",
		"Keep-Alive",
		"Proxy-Authenticate",
		"Proxy-Authorization",
		"Te",
		"Trailer",
		"Transfer-Encoding",
		"Upgrade",
	} {
		header.Del(name)
	}
}
