### Title
Symlink-following file write in `.claude/ralph-loop.local.md` allows arbitrary file overwrite via malicious repo - ([File: plugins/ralph-wiggum/scripts/setup-ralph-loop.sh])

### Summary
`setup-ralph-loop.sh`, invoked by the `/ralph-loop` slash command, writes the loop's state directly with `cat > .claude/ralph-loop.local.md` without checking whether that path is (or resolves through) a symlink. If a cloned repository ships `.claude/ralph-loop.local.md` as a symlink pointing outside the workspace, running `/ralph-loop` will overwrite the symlink's target file instead of a file inside the repo.

### Finding Description
The script builds `.claude` with `mkdir -p .claude` and then writes state via shell heredoc redirection: [1](#0-0) 
Shell `>` redirection opens the target path with the OS `open()` syscall, which transparently follows symlinks and truncates/writes the link's target — there is no `-L`/`readlink`/realpath boundary check anywhere in this script or in the companion `stop-hook.sh`, which also reads/writes the same path via `sed`/`mv` without validation: [2](#0-1) 
A malicious repository can commit `.claude/ralph-loop.local.md` as a symlink (git supports storing symlinks as `120000`-mode blobs, and these are recreated verbatim on `git clone` on Linux/macOS) pointing at a sensitive path such as `~/.bashrc`, `~/.ssh/authorized_keys`, or a file in a sibling repo/workspace. When the victim opens this repo in Claude Code and runs `/ralph-loop <prompt>`, the heredoc write in `setup-ralph-loop.sh` follows the symlink and overwrites the target file's contents with the Ralph state template (YAML frontmatter + prompt text), corrupting it. No approval prompt, allowlist, or workspace-confinement guard intercepts this write because it is a plain filesystem redirection performed by a shell script the plugin runs directly.

### Impact Explanation
This is a workspace-confinement escape: an attacker-controlled repository can cause arbitrary-file content destruction/overwrite outside the intended project directory purely by being cloned and having `/ralph-loop` invoked, with no additional privilege. Concrete impact ranges from denial-of-service (corrupting `~/.bashrc`, `~/.gitconfig`) to more severe outcomes if the victim also happens to have a followable symlink placed at a security-sensitive file the attacker can predict (e.g., overwriting a config file, or another project's file), since the write fully clobbers the target with fixed content rather than appending.

### Likelihood Explanation
Feasible and repeatable: the only precondition is that the victim clones/opens a repository containing the attacker's symlink and executes `/ralph-loop` at least once inside it — a normal usage flow for this plugin. Git faithfully preserves and recreates symlinks on checkout on Unix-like systems, so no special tooling is needed by the attacker beyond crafting the commit. The bug is deterministic (not racy) since the destructive path is a direct, unconditional `cat >` write.

### Recommendation
Before writing, verify `.claude/ralph-loop.local.md` is not a symlink (e.g., `if [[ -L .claude/ralph-loop.local.md ]]; then echo "refusing to write through symlink" >&2; exit 1; fi`), or unconditionally `rm -f` the path first, or write to a temp file and `mv` it only after confirming the destination directory/path resolves within the workspace via `realpath`/`readlink -f` comparison against the project root. Apply the same guard in `stop-hook.sh` before its `sed`/`mv` update.

### Proof of Concept
1. Create a sentinel file outside the test workspace, e.g. `/tmp/sentinel.txt` with known content `SENTINEL`.
2. In a temp repo directory, run `mkdir -p .claude && ln -s /tmp/sentinel.txt .claude/ralph-loop.local.md`.
3. Execute `bash plugins/ralph-wiggum/scripts/setup-ralph-loop.sh "test prompt"`.
4. Assert: `cat /tmp/sentinel.txt` no longer equals `SENTINEL` (it now contains the Ralph YAML frontmatter + "test prompt"), proving the write escaped through the symlink and corrupted a file outside the repo.
5. Expected secure behavior: the script should detect the symlink and abort/refuse without modifying `/tmp/sentinel.txt`.
