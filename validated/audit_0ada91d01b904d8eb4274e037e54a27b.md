### Title
Scanner accepts economically unspendable dust outputs, locking credited funds forever - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The `flash` overpayment bug class — funds accepted by a mechanism that has no bound or recovery path for amounts that should not have been accepted — maps onto Serai's `Scanner`/`ReceivedOutput` pipeline. `Scanner::scan_transaction` credits any output whose `script_pubkey` matches a registered key, regardless of the output's value. `ReceivedOutput` carries no value bound and `SignableTransaction::new` performs no per-input economic check. An output whose value is below the fee required to spend it (or below Bitcoin's dust relay threshold, which prevents it from ever being *created* again but not from being received) is reported as received yet can never be profitably spent: including it in a transaction costs more in fee than it contributes. The credited coins are stuck in the threshold wallet exactly as overpaid flash-loan tokens are stuck in the KyberSwap pool.

### Finding Description
`scan_transaction` matches solely on `output.script_pubkey` and pushes a `ReceivedOutput` for any match with no minimum-value check [1](#0-0) . `ReceivedOutput` stores only `offset`, `output`, and `outpoint` with no validity bound on `value` [2](#0-1) .

On the spend side, `SignableTransaction::new` sums inputs and checks `input_sat < payment_sat + needed_fee` globally, but never verifies that each individual input is worth more than the marginal fee its inclusion adds (~230 WU per Taproot input per the in-code analysis, i.e. 230–1150+ sats depending on fee rate) [3](#0-2) . The file's own `DUST` constant of 546 is only enforced on *payments*, never on inputs [4](#0-3) . There is no mechanism to reject or refund a received output that costs more to spend than it is worth — the wallet layer has no "upper bound" equivalent, just as the vulnerable `Pool.flash` had no overage bound.

Any unprivileged party can reach this with public input: they send a Bitcoin transaction paying e.g. 100 sats (or even 1 sat in a non-standard/miner-confirmable tx) to the multisig's P2TR address or to a registered offset address. The scanner reports it as a received, spendable output; it is in fact unspendable without net loss, so the value it represents is locked in the wallet permanently.

### Impact Explanation
Funds are reported received that are not spendable — the accepted impact criterion. A dust output credited by `scan_transaction` inflates the wallet's apparent balance while contributing negative marginal value to any transaction that includes it. If integrators/accounting treat the scanned value as real balance, the protocol credits deposits that can never be paid out, mirroring the original report's permanently-trapped excess tokens.

### Likelihood Explanation
Sending a dust payment to a known wallet address is trivially reachable by any external party at near-zero cost. Unlike the KyberSwap case (overpayment is typically accidental), here the sender has a direct incentive mismatch: a depositor credited for a dust amount extracts value from the system while the corresponding UTXO can never be economically redeemed.

### Recommendation
Enforce a minimum value in `Scanner::scan_transaction`/`ReceivedOutput` — reject (or flag as unspendable) outputs below a value safely above the marginal spend cost (`230 WU * max expected fee rate`, aligned with the 10,000-sat rationale documented at `networks/bitcoin/src` processor constants). Additionally, `SignableTransaction::new` should assert each input exceeds its marginal fee contribution so uneconomical inputs cannot be silently swept into the fee.

### Proof of Concept
1. Let `key` be the threshold group key; build `Scanner::new(key)` and `addr = p2tr_script_buf(key)`.
2. An attacker broadcasts a transaction with an output `{ script_pubkey: addr, value: 100 }` sats and gets it mined.
3. `scanner.scan_block(&block)` returns a `ReceivedOutput` with `value() == 100` — the wallet reports 100 sats received.
4. Attempt to spend: `SignableTransaction::new(vec![output], &[], Some(change), None, fee_per_vbyte)`. The input contributes 100 sats but its own inclusion costs ~230 WU ≈ 57 vbytes × `fee_per_vbyte`; at any `fee_per_vbyte ≥ 2` the transaction is `NotEnoughFunds` for any payment, and even at 1 sat/vbyte the recoverable amount is below the 546-sat `DUST` needed to create a change output [5](#0-4) . The 100 sats are permanently locked, yet were reported as received balance.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
