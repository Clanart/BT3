## Title
Malicious git remote can spoof a `WWW-Authenticate` header to trigger a spoofed "Sign in to GitHub Enterprise" OAuth flow pointed at the attacker's host - (`File: app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The external report is about hardcoded secrets in test scripts and repo history — that class of bug isn't reachable in GitHub Desktop's runtime code paths (`app-info.ts`'s dev OAuth client ID/secret is intentionally public/documented, not a leaked production secret) [1](#0-0) [2](#0-1) . A real, unprivileged analog exists in Desktop's git credential trampoline, where the *identity* of a remote host is derived from an attacker-controllable HTTP response header instead of verified server identity.

### Finding Description
When git needs credentials for a host it doesn't already recognize, Desktop's credential helper decides whether that host is GitHub Enterprise, GitHub.com, or a "generic" git host in `getEndpointKind`. For any hostname that isn't literally `github.com` or `*.ghe.com`, the function trusts a `WWW-Authenticate` header echoed back by git for that connection: if it contains `realm="GitHub"`, the endpoint is classified as `'enterprise'`, no server identity verification (like the `isGitHubHost` meta-endpoint probe) is performed in that branch: [3](#0-2) 

This value flows straight into `getCredential`, which — because no account exists for this made-up "enterprise" endpoint — calls `ui.promptForGitHubSignIn(endpoint)` with the attacker's own origin: [4](#0-3) 

`promptForGitHubSignIn` then starts the real Enterprise sign-in flow, but scoped to the attacker's origin, and shows it in a native Desktop `SignIn` popup: [5](#0-4) 

The corrupted value is the derived `endpointKind`/`endpoint` — the attacker (an HTTP server acting as a git remote, e.g. a malicious `http://`/`https://` clone/fetch URL, or a MITM proxy on an insecure/self-hosted remote) fully controls both the credential URL and the `wwwauth[...]` header content that git forwards to the trampoline helper, so it can make an arbitrary host look like GitHub Enterprise to Desktop's UI layer.

### Impact Explanation
A user who simply clones or fetches from an attacker-controlled remote (no unusual action required — just an ordinary `git fetch`/clone that Desktop performs) can have Desktop automatically pop a native "Sign in to GitHub Enterprise" dialog bound to the attacker's server. Since this dialog is rendered by the trusted GitHub Desktop process/UI, a user is far more likely to trust it and go through the OAuth/PAT entry flow than they would a random phishing page in a browser, potentially leading to credential or OAuth token exfiltration to a domain the user never intended to authenticate against.

### Likelihood Explanation
The trigger only requires the attacker to control the destination of a git operation (clone/fetch/push URL) and craft an HTTP response containing `WWW-Authenticate: ... realm="GitHub"`, both of which sit squarely on the "attacker controls a cloned/fetched repository ... or a git remote/proxy response" side of valid impact. It requires no local access, no prior compromise, and no unnatural user steps beyond adding/using an attacker-supplied remote.

### Recommendation
Do not classify an unknown host as `'enterprise'` (which triggers the OAuth/sign-in UI) based solely on a self-reported `WWW-Authenticate` realm string; require a positive server-side verification such as the existing `isGitHubHost` meta-endpoint probe (as already done at the bottom of `getEndpointKind`) before trusting a host enough to launch the sign-in flow, or at minimum clearly disclose the actual origin/host to the user inside the `SignIn` popup before starting any OAuth handshake.

### Proof of Concept
1. Host a git-over-HTTP server (or a local proxy) that responds to credential probes with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone/fetch from `https://attacker-host.example/some/repo.git`.
3. Git invokes the credential helper trampoline; `getEndpointKind` sees the spoofed header and returns `'enterprise'` for `attacker-host.example`.
4. `getCredential` finds no matching stored account for that made-up endpoint and calls `ui.promptForGitHubSignIn('https://attacker-host.example/...')`.
5. Desktop shows a native "Sign in to GitHub Enterprise" dialog scoped to `attacker-host.example`, letting the attacker collect whatever credentials/tokens the user enters, believing it's a legitimate Desktop-initiated GitHub sign-in. [6](#0-5)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
