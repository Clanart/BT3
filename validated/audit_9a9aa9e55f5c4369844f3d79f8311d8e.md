### Title
`ReceivedOutput::read` accepts an attacker-controlled spend-offset identifier that is never bound to the output's `script_pubkey` — ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The Khoj IDOR lets an attacker substitute an identifier (`state` user UUID) to claim and overwrite another party's resource without verifying the request was bound to that party. The analog in Serai is `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs:122-134`, which deserializes three attacker-controlled fields — a scalar `offset` (the "identifier" claiming which derived key can spend), a `TxOut` (the resource, including `script_pubkey`), and an `OutPoint` — and trusts them as a coherent spendable output without verifying that `p2tr_script_buf(group_key + offset * G) == output.script_pubkey`. Like the Khoj callback, a purely attacker-supplied binding is accepted as authoritative.

### Finding Description
`Scanner::scan_transaction` (`mod.rs:199-214`) is the only honest producer of `ReceivedOutput`s: it looks up `output.script_pubkey` in `self.scripts` and attaches the correct registered `offset`. `ReceivedOutput::read`, however, reconstructs the struct from raw bytes with zero consistency checks:

```rust
// networks/bitcoin/src/wallet/mod.rs:122-134
let offset = Secp256k1::read_F(r)?;
output = TxOut::consensus_decode(&mut buf_r)...;
outpoint = OutPoint::consensus_decode(&mut buf_r)...;
Ok(ReceivedOutput { offset, output, outpoint })
```

There is no group key in scope at `read` time, so the function *cannot* verify the binding — and never defers it either. The deserialized object then flows into `SignableTransaction::new` (`send.rs:150`), which reads `input.offset` and `input.output.value` to compute funding (`input_sat`, `send.rs:175-176`) and treats every input as spendable value. Only much later does `SignableTransaction::multisig` (`send.rs:273-285`) perform the missing check — `p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey → None?` — i.e., the binding failure surfaces as a silent `None` at signing-machine construction, after the output has already been counted as received funds.

### Impact Explanation
- **Funds reported received that are not spendable**: an attacker who can supply `ReceivedOutput` bytes (the documented untrusted-input sink) pairs a high-value `TxOut`/`OutPoint` paying to an arbitrary script with any `offset`. The output reports `value()` as spendable balance and passes `SignableTransaction::new` balance checks, but `multisig` returns `None` — the funds were credited yet can never be signed for. This mirrors the Khoj impact (attacker-poisoned state attributed to a victim) and matches the accepted "funds reported received that are not spendable" criterion.
- **Real funds committed to an unspendable graph**: `SignableTransaction::new` mixes the forged input with genuine inputs; the transaction selects outputs/change against an `input_sat` that includes phantom value, so a signed transaction can strand real co-spent inputs' change logic or produce a transaction whose claimed economics never settle.

### Likelihood Explanation
Medium. Exploitation requires the attacker to control serialized `ReceivedOutput` bytes reaching the victim (relayed/cached scanner output, DB, or any integration piping untrusted bytes to `ReceivedOutput::read` — explicitly in scope). No key material, validator status, or collusion is needed; the primitive is a one-shot identifier substitution, identical in reachability to the Khoj `state` swap. The `multisig` check limits impact to misattributed/unspendable funds rather than signature forgery, keeping severity at Medium.

### Recommendation
Bind the offset to the output at the earliest point the group key is known: have `Scanner` expose a `verify(ReceivedOutput)` / make `ReceivedOutput::read` take the scanner/key so that `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey` and `outpoint` references `output` are enforced at deserialization, and fail `SignableTransaction::new` (rather than deferring to `multisig`) when the invariant doesn't hold.

### Proof of Concept
```rust
// Attacker crafts bytes: offset=1, output paying to their own P2TR script,
// outpoint pointing at a real UTXO they own.
let mut bytes = vec![];
Scalar::ONE.write(&mut bytes).unwrap();           // claimed spend offset
bytes.extend(serialize(&attacker_txout));          // TxOut to attacker script
bytes.extend(serialize(&real_outpoint));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // accepted
// forged.value() reports full amount; SignableTransaction::new counts it;
// multisig(...) later returns None — funds reported, never spendable.
```
