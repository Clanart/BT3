## Finding

### Title
Server-Side Request Forgery via unauthenticated DataLayer mirror coins forcing arbitrary outbound HTTP requests - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
Any wallet that can send an XCH coin can forge a DataLayer "mirror" coin naming an arbitrary `store_id` (launcher id) it does not own and embedding arbitrary URLs in the coin memo. Any peer whose `DataLayerWallet` tracks that `store_id` will unconditionally record the attacker-chosen URL as a mirror, and the peer's `DataLayer` service will later issue outbound HTTP GET requests to that URL during its normal sync loop — a server-side request forgery analogous to CVE-2018-1000195, where an unprivileged actor causes the target process to issue an HTTP request to an attacker-controlled URL.

### Finding Description
`create_mirror_puzzle()` is a single, fixed, ownerless puzzle (`P2_PARENT.curry(Program.to(1))`) shared by the entire network — it has no dependency on who owns the `store_id`/launcher. [1](#0-0) 

`create_new_mirror()` lets any wallet spend value into this puzzle and set `memos=[[launcher_id, *urls]]` for any `launcher_id`, with no proof of ownership of that singleton: [2](#0-1) 

`get_mirror_info()` then blindly extracts `launcher_id = memos[0]` and the rest of the memos as URLs from any coin spend that creates a coin with the mirror puzzle hash, with no signature or authorization check binding the spender to the `launcher_id`: [3](#0-2) 

When a victim node observes this coin on chain, `DataLayerWallet.coin_added()` only checks whether the victim's wallet is *tracking* that `launcher_id` (i.e., subscribed to or owner of that store) — it does not check who created the mirror coin: [4](#0-3) 

The victim's `DataLayer` service periodically pulls these attacker-chosen URLs into its subscription table via `update_subscriptions_from_wallet()`: [5](#0-4) [6](#0-5) 

and then `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues an outbound `aiohttp` GET request to `server_info.url + "/" + filename` — i.e., directly to the attacker-supplied URL, with the node's own network context (potentially internal-network reachable): [7](#0-6) [8](#0-7) 

This exactly matches the SSRF bug class in CVE-2018-1000195: an unprivileged actor (any spend-bundle submitter with a small amount of XCH) supplies an arbitrary target and causes the server process to make an outbound HTTP request to it, without any authorization check tying the requester to the resource being probed.

### Impact Explanation
This gives any unprivileged chain participant a confused-deputy primitive against any DataLayer-enabled node that tracks a given store: it can force that node to send crafted GET requests to attacker-chosen hosts/ports (including internal-only addresses reachable from the victim's network position), enabling internal network reconnaissance/port scanning, abuse of internal HTTP APIs that act on GET, and repeated/forced connections that can be used for resource exhaustion against internal targets. It does not directly steal funds or forge assets, but it is a genuine unauthorized-action primitive reachable purely from an on-chain spend, consistent with the "Medium" SSRF classification of the source CVE.

### Likelihood Explanation
Likelihood is high for any node that subscribes to third-party DataLayer stores (a core, encouraged usage pattern) since mirror tracking and background sync (`periodically_manage_data`) run automatically without operator interaction, and creating a mirror coin only requires a minimal-value spend bundle with the fixed `MIRROR_PUZZLE_HASH` and desired memos — no special privilege, signature over the target store, or RPC access is required.

### Recommendation
Bind mirror-URL trust to store ownership/authorization rather than accepting any coin that merely names a tracked `launcher_id` in its memo. Concretely: require that mirror-announcing coins be created by (or otherwise cryptographically tied to) the current DataLayer singleton owner for that `launcher_id`, or otherwise sandbox/restrict outbound HTTP fetches triggered by third-party-supplied mirror URLs (e.g., block RFC1918/loopback/link-local destinations, enforce scheme allow-lists, and rate-limit/isolate the DataLayer HTTP client).

### Proof of Concept
1. Attacker wallet observes/decides on a victim-tracked DataLayer `store_id` (`launcher_id`), e.g., one being subscribed to by many nodes for a popular dataset.
2. Attacker calls `create_new_mirror(launcher_id=<victim's tracked store>, amount=0 or minimal, urls=[b"http://169.254.169.254/latest/meta-data/"], action_scope, fee=...)` from its own unrelated wallet — see the coin creation path in `chia/data_layer/data_layer_wallet.py:687-703`.
3. Attacker broadcasts the resulting spend bundle to the mempool; it is a standard XCH spend to `MIRROR_PUZZLE_HASH` and requires no interaction with the victim's singleton.
4. Once confirmed, every peer's `DataLayerWallet.coin_added()` (chia/data_layer/data_layer_wallet.py:775-800) that tracks that `launcher_id` records the attacker's URL as a legitimate mirror, with `ours=False`.
5. On the victim's next `periodically_manage_data()` cycle, `update_subscription()` → `update_subscriptions_from_wallet()` → `fetch_and_validate()` → `download_file()` → `http_download()` (chia/data_layer/download_data.py:298-319) issues an HTTP GET to the attacker-chosen URL from the victim node's process/network context.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
            )[0]

                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
