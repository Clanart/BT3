## Finding

### Title
Predispatch escrow sweep in `IntentGatewayV2` (Tron) derives the escrowed amount from a raw `balanceOf()` snapshot on the shared `CallDispatcher`, letting donated/stray tokens be swept and permanently stranded - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The external report's core defect is: deriving a financial value from `balanceOf()` at a single point in time instead of a delta since a known baseline, so a third party can inflate the observed balance and corrupt the derived amount. The Tron `IntentGatewayV2.placeOrder` predispatch path reproduces exactly this pattern when sweeping tokens out of the shared `ICallDispatcher` contract, whereas the canonical EVM contract (`evm/src/apps/IntentGatewayV2.sol`) fixes it with before/after delta accounting.

### Finding Description
In the Tron variant, the predispatch sweep step reads the dispatcher's live token balance directly and moves the *entire* balance, but only credits escrow with the order's own declared amount: [1](#0-0) 

```solidity
balance = IERC20(token).balanceOf(dispatcher);
if (balance < requiredAmount) revert InvalidInput();
transferCalls[i] = Call({
    to: token, value: 0,
    data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
});
uint256 dust = balance - requiredAmount;
if (dust > 0) emit DustCollected(token, dust);
_orders[commitment][token] += reducedInputs[i].amount;
```

`dispatcher` is `_params.dispatcher` - a single, fixed, publicly known contract shared across **every** `placeOrder` call that uses predispatch (the same address for all users, per [2](#0-1) ). The code transfers `balance` (the dispatcher's full current holding of `token`) into the gateway, but escrows only `reducedInputs[i].amount` under this order's commitment. The excess is only *logged* via `DustCollected` - there is no code path anywhere in `withdraw`/`fillOrder`/cancel logic that credits or returns this excess to anyone; it becomes a stranded balance sitting in `IntentGatewayV2` forever.

Because `balanceOf(dispatcher)` is read as an absolute snapshot rather than a before/after delta, **any address** can send tokens directly to the public `dispatcher` contract (accidentally or via a stray/partial predispatch interaction from an unrelated order) and have those tokens silently swept out and stranded the next time anyone places a predispatch order for that same token - with no way to recover them. This is the same broken invariant as the reported bug: a balance read that can be inflated by an uninvolved party corrupts a value that gates fund movement.

Contrast with the corrected pattern already present in the canonical EVM contract, which snapshots balance *before* the sweep and only credits the *actual delta received*, capping to the requested amount and treating any excess purely as dust without moving more than necessary: [3](#0-2) 

The Tron file does not use this before/after delta pattern for the ERC-20 branch of the sweep - it uses the raw, post-call `balanceOf()` value as the transfer amount.

### Impact Explanation
Tokens that land on the shared `CallDispatcher` address (via a misconfigured predispatch call, a partially-failed prior interaction, or a direct transfer) are swept in full by the next unrelated `placeOrder` predispatch call and permanently stranded inside `IntentGatewayV2` with no order backing them and no withdrawal path - a genuine, unrecoverable loss of funds reachable from a fully public, unprivileged entrypoint (`placeOrder`). No malicious relayer, prover, or admin is required.

### Likelihood Explanation
Exploitability depends on tokens actually being present on the dispatcher beyond `requiredAmount` at sweep time (e.g., from a prior partially-executed predispatch flow, a misbehaving predispatch call, or a direct/accidental transfer to the well-known dispatcher address). This is plausible but not guaranteed on every call, so likelihood is moderate rather than certain; it requires either an operational mishap or a deliberate donation that yields no attacker gain, only fund loss/lock. Because the Tron file appears to be a divergent/older port relative to the hardened main EVM contract, it is uncertain whether this file is actively deployed or exercised by tests versus the canonical `evm/src/apps/IntentGatewayV2.sol` used elsewhere in the repo (Foundry tests reference the main `evm/src/apps/...` path, not the Tron path) - this reduces confidence that this specific file is production-live.

### Recommendation
Apply the same before/after delta accounting used in `evm/src/apps/IntentGatewayV2.sol` to the Tron variant: snapshot `IERC20(token).balanceOf(address(this))` before the sweep, transfer only what's needed to satisfy `requiredAmount` (or transfer the full dispatcher balance but credit escrow with the actual received delta, not a fixed declared amount), and ensure any genuine excess/dust is either returned to a defined beneficiary or accounted for in a claimable ledger rather than being silently emitted as an event while the tokens vanish into unaccounted contract balance.

### Proof of Concept
1. Any address (attacker or accidental sender) transfers `X` extra units of `TOKEN` directly to the public `dispatcher` address (`_params.dispatcher`), or a prior predispatch interaction leaves `X` extra units stuck there.
2. A user (or the same attacker, for griefing) calls `placeOrder` with a predispatch order specifying `TOKEN` as an input with `requiredAmount = Y` where `Y <= currentDispatcherBalance`.
3. In the sweep loop, `balance = IERC20(TOKEN).balanceOf(dispatcher)` reads `Y + X` (or more) and the code issues `transfer(address(this), balance)`, moving the full `Y + X` into `IntentGatewayV2`.
4. `_orders[commitment][TOKEN] += reducedInputs[i].amount` only credits the order-declared amount (derived from `Y`), while `dust = balance - requiredAmount` is emitted via `DustCollected` but never transferred anywhere or made claimable.
5. The `X` extra tokens are now permanently held by `IntentGatewayV2` with no commitment referencing them and no function to withdraw untracked dust - a confirmed, irrecoverable loss. [1](#0-0)

            // Build sweep calls and snapshot gateway balances before the sweep.
            Call[] memory transferCalls = new Call[](inputsLen);
            uint256[] memory balancesBefore = new uint256[](inputsLen);
            for (uint256 i; i < inputsLen;) {
                if (order.inputs[i].amount == 0) revert InvalidInput();
                address token = address(uint160(uint256(order.inputs[i].token)));
                uint256 requiredAmount = order.inputs[i].amount;

                if (token == address(0)) {
                    uint256 balance = address(dispatcher).balance;
                    if (balance < requiredAmount) revert InsufficientNativeToken();
                    transferCalls[i] = Call({to: address(this), value: balance, data: ""});
                    balancesBefore[i] = address(this).balance;
                } else {
                    uint256 balance = IERC20(token).balanceOf(dispatcher);
                    if (balance < requiredAmount) revert InvalidInput();
                    transferCalls[i] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    balancesBefore[i] = IERC20(token).balanceOf(address(this));
                }

                unchecked {
                    ++i;
                }
            }

            ICallDispatcher(dispatcher).dispatch(abi.encode(transferCalls));

            // Measure actual received, emit dust for excess, update order.inputs.
            for (uint256 i; i < inputsLen;) {
                address token = address(uint160(uint256(order.inputs[i].token)));
                uint256 received;
                if (token == address(0)) {
                    received = address(this).balance - balancesBefore[i];
                } else {
                    received = IERC20(token).balanceOf(address(this)) - balancesBefore[i];
                }

                if (received > order.inputs[i].amount) {
                    uint256 dust = received - order.inputs[i].amount;
                    emit DustCollected(token, dust);
                } else {
                    order.inputs[i].amount = received;
                }

                unchecked {
                    ++i;
                }
            }
