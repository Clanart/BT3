### Title
Parser-differential OAuth callback open redirect due to unhardened host validation - (File: app/controllers/shopify_app/callback_controller.rb)

### Summary
`CallbackController#redirect_to_app` builds the post-OAuth redirect target from the untrusted `host` query parameter using a *different, weaker* validation path than the one `ShopifyApp::EmbeddedApp` uses for the same purpose elsewhere in the gem. This mirrors the reported bug class: two independent implementations of a security-critical check (there, `setRebateEstimator`/`getRebate` in `OasisSwapFactory` vs `OasisSwapRouter`; here, host/phishing validation in `CallbackController` vs `EmbeddedApp`) that can desync, letting one path stay hardened while the other remains exploitable.

### Finding Description
`EmbeddedApp#safe_embedded_app_url` sanitizes the `host` param through `unsafe_embedded_host?`, which explicitly rejects control characters, backslashes, and `userinfo@` segments before ever handing the value to `ShopifyApp::Utils.sanitize_shop_domain` or `ShopifyAPI::Auth.embedded_app_url`. [1](#0-0) 

The CHANGELOG confirms this hardening was added specifically to close a "parser-differential open redirect": *"Harden embedded app host validation to prevent parser-differential open redirects" (PR #2078)*. [2](#0-1) 

`CallbackController`, however, computes the equivalent trust decision independently, using Ruby's stdlib `URI()` parser directly on the decoded host, with **no** `unsafe_embedded_host?`-style character/userinfo sanitization: [3](#0-2) 

and uses that same unhardened `decoded_host` to construct the actual redirect string sent to the browser: [4](#0-3) 

Because `URI()` (a strict RFC3986 parser) and other consumers (browsers, `Addressable::URI`, or `ShopifyAPI::Auth.embedded_app_url`'s own decoding) can disagree on where the "host" boundary lies for a maliciously crafted string containing backslashes, control characters, or an `@`-delimited userinfo segment, `deduced_phishing_attack?` can conclude the host is trusted (i.e., `sanitize_shop_domain` returns a valid `*.myshopify.com` value) while the actual URL assembled in `redirect_to_app` (`"#{decoded_host}#{return_to}"`) points the browser somewhere else. This is precisely the class of "parser differential" the gem's own test suite exercises for `EmbeddedApp` (backslash + userinfo payloads) but that protection was never applied to `CallbackController`. [5](#0-4) 

### Impact Explanation
If exploitable, this allows an attacker-controlled `host` value to survive the `deduced_phishing_attack?` check and cause `CallbackController#redirect_to_app` to redirect the merchant's browser — immediately after a successful, trusted OAuth exchange — to an attacker-controlled origin (`allow_other_host: true` is passed to `redirect_to`), fitting the accepted "embedded-app redirect" bug class. This can be leveraged for phishing merchants inside what appears to be a legitimate post-install flow, or to funnel the embedded session context to an attacker page.

### Likelihood Explanation
Reachable by any party who can get a merchant to click a crafted install/authorize link carrying a malicious `host` param — the same delivery vector the gem's own maintainers anticipated when they patched `EmbeddedApp` in PR #2078. Because `CallbackController` was not updated with the equivalent hardening, the desync is concrete and structurally present, though I was not able to execute the code to confirm that Ruby's `URI()` parser actually diverges from the browser/Addressable parsing for a specific crafted payload (e.g., whether `URI()` raises `InvalidURIError` instead of silently producing a mismatched `.host`). This should be verified with a running instance/Devin session, as static reading of the code cannot fully confirm the parser-differential.

### Recommendation
Unify the two implementations: have `CallbackController#decoded_host` / `deduced_phishing_attack?` delegate to the same hardened routine used by `EmbeddedApp` (`unsafe_embedded_host?` + `sanitize_shop_domain`, or a shared utility) rather than re-implementing host trust validation with the plain `URI()` parser. This mirrors the OasisSwap fix of removing the duplicated `setRebateEstimator` logic and forcing `swapCalculatingRebate()` to depend on a single canonical source.

### Proof of Concept
1. Attacker crafts an OAuth authorize link where the eventual callback `host` parameter, once base64-decoded, is a value with a backslash + userinfo pattern (as used in `embedded_app_test.rb`, e.g. `"evil.com\\@shop.myshopify.com/admin"`) chosen so that Ruby's `URI(decoded_host).host` extracts `shop.myshopify.com` (passing `sanitize_shop_domain`) while browsers/other consumers of the same decoded string resolve the authority/host differently (to `evil.com`).
2. Merchant clicks the link and completes OAuth normally.
3. `CallbackController#redirect_to_app` builds `redirect_to = "#{decoded_host}#{return_to}"` and `deduced_phishing_attack?` passes (since `URI().host` sanitizes cleanly), so the guard does not fall back to `ShopifyApp.configuration.root_url`.
4. `redirect_to(redirect_to, allow_other_host: true)` sends the merchant's browser to the attacker-influenced URL immediately following a legitimate OAuth completion.
(Exact confirmation that `URI()` vs. browser parsing diverges for a specific payload requires running the code; this PoC outlines the structural path enabled by the missing hardening.)

    def safe_embedded_app_url(host)
      decoded_host = Base64.decode64(host.to_s)
      return if deduced_phishing_attack?(decoded_host)

      ShopifyAPI::Auth.embedded_app_url(Base64.strict_encode64(decoded_host))
    end

    def deduced_phishing_attack?(decoded_host)
      sanitized_host = ShopifyApp::Utils.sanitize_shop_domain(decoded_host) unless unsafe_embedded_host?(decoded_host)
      if sanitized_host.nil?
        message = "Host param for redirect to embed app in admin is not from a trusted domain, " \
          "redirecting to root as this is likely a phishing attack."
        ShopifyApp::Logger.info(message)
      end
      sanitized_host.nil?
    end

    def unsafe_embedded_host?(decoded_host)
      return true if decoded_host.empty? || !decoded_host.valid_encoding?
      return true if unsafe_embedded_host_characters?(decoded_host)

      embedded_host_authority(decoded_host).include?("@")
    end

    def redirect_to_app
      if ShopifyAPI::Context.embedded?
        return_to = session.delete(:return_to)
        redirect_to = if fully_formed_url?(return_to)
          return_to
        else
          "#{decoded_host}#{return_to}"
        end

        redirect_to = ShopifyApp.configuration.root_url if deduced_phishing_attack?
        redirect_to(redirect_to, allow_other_host: true)
      else
        redirect_to(return_address)
      end
    end
