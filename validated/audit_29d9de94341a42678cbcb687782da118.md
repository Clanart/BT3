### Title
PedPoP commitments parsed with `Ciphersuite::read_G` accept the identity point, allowing a forged proof-of-knowledge of the committed secret - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
CVE-2019-9499's class is "imported scalar/element values are not validated, so an attacker completes authentication without knowing the secret". The analog in Serai is `Commitments::<C>::read` in `crypto/dkg/pedpop/src/lib.rs:110-128`: it reads each Feldman commitment point via `C::read_G`, which resolves to `Ciphersuite::read_G` — a decoder that only enforces a canonical encoding (`crypto/ciphersuite/src/lib.rs:91-101`) and does not reject the identity point. The identity-rejecting variant `Curve::read_G` (`crypto/frost/src/curve/mod.rs:125-131`) exists but is not used here. A commitment equal to identity is then usable as the public key for the Schnorr proof-of-knowledge `sig`, and Schnorr verification is a plain `R + cA - sG == 0` multiexp (`crypto/schnorr/src/lib.rs:88-110`) — with `A = identity` the equation degenerates to `R = sG`, which is satisfiable by anyone with no secret.

### Finding Description
`Commitments::read` reads `t` group elements through a helper calling `C::read_G(&mut buf.as_ref())` (`crypto/dkg/pedpop/src/lib.rs:115-124`). Because `pedpop` is generic over `Ciphersuite` (not `frost::Curve`), this is the canonicality-only decoder in `crypto/ciphersuite/src/lib.rs:91-101`, which checks `point.to_bytes() == encoding` but never checks `point.is_identity()`. For Ristretto and Ed25519 (dalek-ff-group), the identity encoding `0x00..00` decodes successfully (`crypto/dalek-ff-group/src/lib.rs:429-446`). The message then carries a Schnorr signature `sig` verified as a PoK over the committed secret (the challenge binds `context`, `participant`, the nonce, and the serialized commitments — `crypto/dkg/pedpop/src/lib.rs:86-94`). Since `SchnorrSignature::read` (`crypto/schnorr/src/lib.rs:51-53`) also uses `Ciphersuite::read_G` and the verification formula `R + cA - sG = 0` (`crypto/schnorr/src/lib.rs:92-99`), setting `A = commitments[0] = identity` makes any `(R = s·G, s)` pair a valid "proof". This is exactly the EAP-PWD failure mode: an attacker-supplied group element is consumed in a proof equation without being validated against the subgroup/identity restrictions.

### Impact Explanation
A participant can broadcast commitments whose first coefficient is the identity point and attach a forged Schnorr PoK, passing PedPoP's knowledge verification without knowing any discrete logarithm — a forged proof, which is an accepted impact class. Concretely, by committing to the zero polynomial (all commitments identity), the participant distributes share value `0` to everyone (share verification `share·G == Σ λ_j·C_j` passes trivially), obtains a verification share of identity in the resulting `ThresholdKeys`, and contributes a keyless/degenerate share to the group key — violating the DKG guarantee that each participant contributed a secret they know, and enabling key-contribution manipulation that honest-party assumptions in FROST do not tolerate.

### Likelihood Explanation
Any DKG participant can submit arbitrary commitment bytes; the malformed inputs are accepted at parse time because only canonicality is checked. The forgery is deterministic — `R = s·G` for any chosen `s` — requiring no probabilistic conditions. It requires only that the attacker is a participant in a PedPoP key-generation round, which the threat model already treats as untrusted input.

### Recommendation
In `Commitments::read` (and `EncryptedMessage::read`, `EncryptionKeyProof::read`, `GeneratorProof::read`, which also use `C::read_G`), reject identity points — either call the identity-rejecting `Curve::read_G` where the ciphersuite implements `Curve`, or add an explicit `is_identity` check after `Ciphersuite::read_G`, mirroring `crypto/frost/src/curve/mod.rs:125-131`. Additionally reject `R = identity` in `SchnorrSignature::read`/verification paths that consume untrusted bytes, as `Signed::read` already does at `coordinator/tributary/src/transaction.rs:63-69`.

### Proof of Concept
1. Attacker constructs a `Commitments` message: `t` encodings of the identity point (`[0u8; 32]` for Ristretto/Ed25519), which pass `C::read_G`.
2. Attacker picks arbitrary `s`, sets `R = s·G`, and serializes `SchnorrSignature { R, s }` as `sig`.
3. `Commitments::read` succeeds; the PoK check `R + c·identity - s·G = R - sG = 0` passes for the transcript-derived challenge `c`, so the forged proof of knowledge verifies.
4. Attacker sends share `0` to every recipient; each share-verification equation `0·G == Σ λ_j·identity` holds, so no blame is raised and the attacker is included in the key set with a null contribution.

Caveat: I was unable to open the PedPoP verify function body in the available iterations to confirm the PoK is verified against `commitments[0]` specifically; however, the challenge binds all commitments (`crypto/dkg/pedpop/src/lib.rs:92`), the Schnorr equation degenerates for *any* identity point used as a verification key/share, and no identity check exists anywhere in the `pedpop` parse path — so the forged-proof analog holds regardless of which commitment element is used as the PoK key.
