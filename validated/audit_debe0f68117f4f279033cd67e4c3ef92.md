### Title
`ReceivedOutput::read` accepts an unrelated spend offset, causing unspendable funds to be reported as spendable - (File: `networks/bitcoin/src/wallet/mod.rs`) [1](#0-0) 

### Summary
Medium. `ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` but never verifies that the offset derives the output's `script_pubkey` from the wallet key. [2](#0-1) 

### Finding Description
`ReceivedOutput` is documented as a spendable output and stores the scalar offset required to spend it. [1](#0-0)  Its deserializer only checks that the scalar and Bitcoin structures parse; it has no wallet-key context and performs no semantic binding between `offset` and `output.script_pubkey`. [2](#0-1)  The resulting object still reports the serialized amount through `value()`. [3](#0-2)  The error is deferred until signing, where `SignableTransaction::multisig` derives `keys.offset(offset).group_key()` and returns `None` unless its P2TR script equals the serialized output's script. [4](#0-3) 

### Impact Explanation
An attacker who can supply serialized wallet outputs can copy a real received output but replace its offset with a different canonical scalar. [2](#0-1)  The forged `ReceivedOutput` reports the real amount as received even though the wallet cannot produce a compatible spend key for it. [3](#0-2)  `SignableTransaction::new` preserves the attacker-controlled offset and output without checking ownership, and `multisig` subsequently rejects the input as belonging to different keys. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
The reachable input is exactly an untrusted byte string passed to the public `ReceivedOutput::read` API. [2](#0-1)  Exploitation does not require solving a discrete logarithm or forging a signature; changing the serialized scalar is sufficient to violate the spendability invariant. [4](#0-3) 

### Recommendation
Do not treat raw `ReceivedOutput::read` results as validated spendable outputs. [2](#0-1)  Add a scanner-aware constructor or `Scanner::read_received_output` method which derives `p2tr_script_buf(self.key + GENERATOR * offset)` and rejects the record unless it equals `output.script_pubkey`. [7](#0-6) [8](#0-7) 

### Proof of Concept
```rust
// `real` is a legitimate output returned by Scanner::scan_transaction.
let mut encoded = real.serialize();

// Replace the scalar offset with another canonical scalar.
let bad_offset = if real.offset() == Scalar::ONE {
  -Scalar::ONE
} else {
  Scalar::ONE
};
encoded[.. bad_offset.to_bytes().len()]
  .copy_from_slice(bad_offset.to_bytes().as_ref());

// Deserialization succeeds despite the offset no longer matching the script.
let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();
assert_ne!(forged.offset(), real.offset());
assert_eq!(forged.value(), real.value());

// The amount is reported as received, but spend-key validation rejects it.
let signable =
  SignableTransaction::new(vec![forged], &valid_payments, None, None, 1).unwrap();
assert!(signable.multisig(&keys).is_none());
```

This fails because `multisig` requires the derived key's P2TR script to equal the serialized `prevouts[i].script_pubkey`. [4](#0-3)
