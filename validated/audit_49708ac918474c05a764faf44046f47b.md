## Finding

### Title
Missing Slippage Protection in `ArbWomUp3.incentiveDeposit` (mode 2) Enables Sandwich Attacks on WOM→mWOM Swap - (File: wombat/ArbWomUp3.sol)

### Summary
`ArbWomUp3.incentiveDeposit` is callable by any ordinary user and, when `_mode == 2`, routes half of the deposited WOM through `SmartWomConvert.convert` with a **hardcoded minimum-received value of `0`**, completely disabling the only slippage check that exists in the downstream swap logic. This mirrors the report's bug class ("lack of slippage checks in trading instructions" enabling front-running/sandwich attacks) and is directly reachable by an unprivileged wallet.

### Finding Description
`incentiveDeposit` is a public, unprivileged entry point: [1](#0-0) 

For `_mode == 2` it calls `_deposit`, which sends half of the WOM through `SmartWomConvert.convert` but hardcodes the `_minRec` (and `_convertRatio`? no, `_convertRatio` is user supplied, but `_minRec` argument) to `0`: [2](#0-1) 

`SmartWomConvert.convert` forwards this `0` value into `_convertFor`, which performs an on-chain router swap (`swapExactTokensForTokens`) and only validates the **aggregate** output against the caller-supplied `_minRec`: [3](#0-2) [4](#0-3) 

Because `ArbWomUp3` passes `0` as `_minRec`, the `if (convertAmount + amountRec < _minRec) revert MinRecNotMatch();` check can never fail — the swap executes at any price, no matter how unfavorable. In every other calling context found in the codebase (e.g. `ManualCompound.compound`, direct `SmartWomConvert.convert`/`convertFor` calls), the `_minRec` is supplied by the actual end-user and thus provides real slippage protection; `ArbWomUp3` is the one unprivileged code path where this protection is silently stripped out by the contract itself.

### Impact Explanation
An attacker monitoring the mempool can front-run a user's `incentiveDeposit(_amount, _convertRatio, _bullMode, 2)` call, manipulate the WOM/mWOM pool price via the underlying Wombat pool, let the victim's swap execute at the manipulated (unfavorable) price with zero floor, and then back-run to restore price and capture the difference. The victim receives substantially less mWOM than they should, and this converted (reduced) amount is what gets locked into `mWomSV` — a permanent, direct loss of user funds with no way to have prevented it, since the user-facing function does not even expose a slippage parameter for this path.

### Likelihood Explanation
High. This is trivially triggerable by any user calling a normal, documented deposit path (`incentiveDeposit` with `_mode == 2`), and exploitable by any MEV searcher/attacker who can see the pending transaction and manipulate the shared WOM/mWOM pool used by `SmartWomConvert`. No privileged role or governance action is required on either side.

### Recommendation
Do not hardcode `_minRec` to `0` in `ArbWomUp3._deposit`. Add a `_minRec` (or equivalent slippage-bound) parameter to `incentiveDeposit`/`_deposit` and thread the caller-supplied value through to `IConverter(smartWomConvert).convert(toSwap, _convertRatio, _minRec, 0)`, consistent with how `_minRec` is handled in `ArbWomUp2._bullMGP` and `ManualCompound.compound`.

### Proof of Concept
1. Attacker observes a pending `incentiveDeposit(amount, convertRatio, bullMode, 2)` transaction from a victim on `ArbWomUp3`.
2. Attacker front-runs with a large WOM→mWOM (or mWOM→WOM) swap against the pool used by `SmartWomConvert` (`womMWomPool`) to skew the price unfavorably for the upcoming buyback swap.
3. Victim's transaction executes `_deposit` → `SmartWomConvert.convert(toSwap, _convertRatio, 0, 0)` → `_convertFor`, whose internal `swapExactTokensForTokens` call passes `0` as the router's `minimumAmountOut` and whose only guard (`convertAmount + amountRec < _minRec`) is bypassed because `_minRec == 0`.
4. Victim receives a reduced `mWomBal`, which is what gets locked via `ILocker(mWomSV).lockFor(mWomBal, _account)` — permanently reflecting the attacker-manipulated, unfavorable rate.
5. Attacker back-runs to reverse their initial position, profiting from the spread extracted from the victim. [2](#0-1) [4](#0-3)
