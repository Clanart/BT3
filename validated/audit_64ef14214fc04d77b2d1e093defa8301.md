### Title
Identity encryption key accepted in PedPoP DKG lets an attacker nullify share confidentiality — anyone can decrypt secret shares sent to them - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The vm2 advisory is an incomplete-sandbox-bounds bug: protection checks exist but fail to cover an edge (host `Object` access), letting untrusted input escape the intended security boundary. The Serai analog is the PedPoP DKG's per-participant encryption-key registration. `EncryptionKeyMessage::read` and `EncryptedMessage::read` parse attacker-supplied points via `Ciphersuite::read_G`, which enforces only canonical encoding — it does *not* reject the identity point (unlike `frost::Curve::read_G`, which explicitly does). Registering `enc_key = identity` makes every ECDH shared point equal the identity, a publicly known value, so the ChaCha20 keystream protecting that participant's secret shares is computable by anyone.

### Finding Description
`EncryptionKeyMessage::read` reads the registration encryption key with `C::read_G` [1](#0-0) , and `EncryptedMessage::read` reads the per-message ephemeral `key` the same way [2](#0-1) . `Ciphersuite::read_G` checks only `from_bytes` success plus canonical re-encoding [3](#0-2) . The identity-rejecting variant `Curve::read_G` exists in the FROST crate [4](#0-3) , but PedPoP is generic over `Ciphersuite` and never calls it, so identity points sail through.

The ECDH is `public * private` [5](#0-4) , and the cipher key is a transcript hash of `ecdh.to_bytes()` plus the session `context` [6](#0-5) . If a participant registers `enc_key = identity`, then for every share encrypted to them (`Encryption::encrypt` → `ecdh(key, enc_keys[participant])` [7](#0-6) ), the shared point is `identity`, whose encoding is a known constant. The registration key is stored without any check in `Decryption::register` [8](#0-7) , reached via `verify_r1` for every round-1 message [9](#0-8) .

No PoK/PoP is ever required for `enc_key` — the Schnorr PoP covers only the per-message `EncryptedMessage::key`, not the registered key [10](#0-9) . So there is no mechanism that would even detect that the registrant cannot know a discrete log for an identity "key" (the discrete log of identity is 0 and trivially "known", but more importantly the resulting ECDH output is sender-independent and public).

### Impact Explanation
Secret shares in PedPoP are sent over channels required to be *authenticated* but not confidential; confidentiality rests entirely on this ECDH+ChaCha20 layer [11](#0-10) . A malicious participant registering an identity encryption key causes all honest parties to encrypt that participant's shares under a keystream anyone who observes the ciphertext can recompute (context is a known session constant; ecdh bytes are the identity encoding). An eavesdropper — or any party that later receives the ciphertext through blame/publication — recovers that participant's share value directly. Combined with shares the attacker legitimately receives, this reduces the effective threshold and can enable full group-key/share recovery below the intended `t`. This is a concrete key-share-recovery analog reachable purely by bytes an unprivileged DKG participant supplies to `read`/`calculate_share`.

### Likelihood Explanation
Any DKG participant can do this with a single crafted round-1 `EncryptionKeyMessage` — identity is a canonical encoding on every supported ciphersuite, so it always parses. No collusion, no honest-party misbehavior, and no rare hash output is needed. Whether the confidential leak materializes depends on whether the share channel is observable by a third party or later published (e.g., during blame, where ciphertexts are explicitly passed around [12](#0-11) ). Given the deployment model of threshold key generation for a bridge, treating DKG traffic as confidential-only is not guaranteed, so this is a realistic Medium/High.

### Recommendation
Reject identity at all PedPoP trust boundaries:
- In `EncryptionKeyMessage::read` (encryption.rs:58) and `EncryptedMessage::read` (encryption.rs:173), after `C::read_G`, return an error if the point `is_identity` (or require a `Curve`-style `read_G` behavior).
- Also reject identity in `EncryptionKeyProof::read` (encryption.rs:268) and `Commitments::read` (pedpop/lib.rs:115-125) so no attacker-controlled group element used in ECDH, share verification, or PoK verification can be the identity.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
