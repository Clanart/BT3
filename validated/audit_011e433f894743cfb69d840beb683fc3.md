## Title
Stale historical state-proof allows double payment of GET-request relayer fees via `handleGetRequestTimeouts` after the response was already delivered — (File: `evm/src/core/HandlerV2.sol`, `evm/src/core/EvmHost.sol`)

### Summary
The external report's core defect is that a protection is only checked **once** (at first unlock) and is never re-validated against the *current* state, so a stale, once-true condition (device unlocked) is trusted forever. The local analog is `EvmHost`'s handling of `GetRequest` timeouts: the timeout path never consults the host's own `_responseReceipts` record of whether a response was already delivered. It instead accepts *any* historical, still-stored `StateMachineHeight` commitment as proof that "no response exists yet," even one that predates an already-successful response delivery. Because `EvmHost` retains state commitments for every height indefinitely, an attacker can replay an old (but still valid and past-challenge-period) state snapshot to force a bogus timeout after the request has already been fulfilled — causing the relayer fee to be paid out twice.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse ...)` pays the GET-request relayer fee out of `_requestCommitments[commitment].fee` on successful delivery, but never deletes `_requestCommitments[commitment]`: [1](#0-0) 

`EvmHost._stateCommitments` and `_stateCommitmentsUpdateTime` are indexed by `(stateMachineId, height)` and keep **every** historical height that was ever finalized (they are only ever removed by an explicit fisherman veto, not superseded by newer heights): [2](#0-1) [3](#0-2) 

`HandlerV2.handleGetRequestTimeouts` (documented as permissionless) lets the caller pick an arbitrary already-known `message.height` for the destination state machine, and only checks:
1. the challenge period has elapsed for that height,
2. the request's `timeout()` is before that height's `state.timestamp`,
3. a non-membership proof of a response receipt key **at that height** on the remote chain. [4](#0-3) 

None of these checks reference `EvmHost._responseReceipts`, which is the local record proving the GET response was already delivered on this very host (set in `dispatchIncoming(GetResponse ...)` above). `EvmHost.dispatchTimeOut(GetRequestTimeout ...)` likewise never checks `_responseReceipts` — its only replay guard is deleting `_requestCommitments[commitment]`, and it unconditionally refunds `meta.fee` to `meta.sender` once the app callback succeeds: [5](#0-4) 

Because `_requestCommitments[commitment]` is never cleared after a successful response, and because any past finalized height's non-membership proof remains permanently valid and re-usable, an attacker can:
1. Wait for the destination to legitimately answer a `GetRequest` — the relayer is paid via `dispatchIncoming(GetResponse)`.
2. Submit `handleGetRequestTimeouts` referencing an **older** `StateMachineHeight` for the destination — one recorded *before* the response/read was produced there — with a valid non-membership proof of the (still-empty-at-that-height) response-receipt key.
3. This satisfies every check in `handleGetRequestTimeouts`/`dispatchTimeOut`, so `onGetTimeout` fires on the destination app (a second, contradictory callback for a request that already received `onGetResponse`) and the relayer fee is refunded a second time to `meta.sender`.

This is exactly analogous to the reported bug class: a security-relevant fact ("has this been unlocked/answered yet?") is checked once against a frozen, stale snapshot instead of being re-validated against current, canonical state, so the protection silently stops applying once time/state moves on.

### Impact Explanation
This directly causes **loss of protocol funds via double payment** of the same relayer fee (once to the relayer on delivery, once refunded to the payer on the forged timeout) — matching the required impact "stealing or loss of funds" and "replay/double-claim/double-settlement." It also causes **unauthorized execution**: an application module can be forced to run `onGetTimeout` for a request it already successfully processed via `onGetResponse`, an invariant violation that downstream intent/escrow logic is not designed to handle (e.g., an app that only guards against duplicate `onGetResponse` calls but assumes `onGetTimeout` is mutually exclusive with a delivered response could double-refund or corrupt escrowed state).

### Likelihood Explanation
The call is documented as permissionless and requires only a proof against a state commitment `EvmHost` itself still stores (nothing malicious, no relayer/prover/governance compromise needed). All the attacker needs is: (a) a `GetRequest` whose fee was already paid on response delivery, and (b) any older, still-challenge-period-elapsed state commitment for the destination chain recorded before the read was answered — both are ordinary artifacts of normal bridge operation, since `EvmHost` never prunes old heights on its own.

### Recommendation
In `handleGetRequestTimeouts`/`EvmHost.dispatchTimeOut(GetRequestTimeout ...)`, reject the timeout if `_responseReceipts[commitment]` is already set (i.e., check the host's own delivery record before honoring any remote non-membership proof), and/or require `message.height` to be at or above the latest known height for that state machine so stale snapshots cannot be replayed. Additionally, delete/zero `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse ...)` immediately after paying the relayer fee so `meta.sender == address(0)` in the timeout path naturally rejects any later timeout attempt for the same commitment.

### Proof of Concept
1. App on chain A dispatches a `GetRequest` (`DispatchGet`) with a nonzero fee via `EvmHost.dispatch`, creating `_requestCommitments[commitment] = {sender: payer, fee: F}`.
2. Destination answers the read; a relayer submits `handleGetResponses`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)` — pays `F` to `relayer`, sets `_responseReceipts[commitment]`, but leaves `_requestCommitments[commitment]` = `{payer, F}` untouched (`evm/src/core/EvmHost.sol:824-847`).
3. Later, using any already-stored, challenge-period-elapsed `StateMachineHeight` `H_old` for the destination chain that predates the response being recorded there, an attacker builds a non-membership proof of the `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` key at `H_old` and calls `handleGetRequestTimeouts(host, message)` with `message.height = H_old` (`evm/src/core/HandlerV2.sol:293-321`).
4. All checks pass (challenge period elapsed for `H_old`, request timed out relative to `H_old`'s timestamp, `meta.sender != 0`, non-membership proof valid at `H_old`), so `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes, calling `onGetTimeout` on the app and refunding `F` a second time to `payer` (`evm/src/core/EvmHost.sol:849-877`).
5. Net effect: fee `F` paid out twice from the fee token balance held by `EvmHost`, and the destination app receives two contradictory callbacks (`onGetResponse` then `onGetTimeout`) for the same request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
