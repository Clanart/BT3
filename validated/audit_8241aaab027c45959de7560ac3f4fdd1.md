## Finding

Report reduced to its core primitive: two independent passes over the **same untrusted, attacker-influenceable byte stream** must agree on where the "boundaries" are, but they use different scanning rules, and only one of the two counts is ever cross-checked. When they disagree, content meant for one location is spliced into another — exactly the "control flow determined by untrusted-input length/position, without treating all inputs uniformly" flaw from the report, just applied to Git conflict-marker parsing instead of SSZ Merkle proofs.

### Title
Divergent conflict-marker parsing between extraction and reassembly lets a malicious merge/PR branch cause Copilot conflict resolutions to be spliced into the wrong hunk, silently corrupting a committed file - (File: `app/src/lib/copilot-conflict-resolution.ts`)

### Summary
GitHub Desktop's Copilot-assisted conflict resolution reads a conflicted file, extracts "hunks" with `extractConflictHunks` [1](#0-0) , sends each hunk to the model, validates the response with `validateResolutionPaths` [2](#0-1) , and then re-parses the **same raw file content independently** with `reassembleResolvedFile` to splice the model's per-hunk output back in, matched purely by ordinal position ("matched by order, not by line number") [3](#0-2) . Extraction and reassembly use similarly-named but not identical marker-scanning loops, so content on either side of a real conflict (which is attacker-controlled if the attacker's branch/PR is one side of the merge) that happens to contain a line starting with 7 `<`, `=`, or `>` characters causes the two passes to disagree on where a block starts/ends.

### Finding Description
`extractConflictHunks`'s "collect ours" loop only stops on a base (`|||||||`) or separator (`=======`) marker — it never checks for a `>>>>>>>` line, so an embedded `>>>>>>>`-looking line inside legitimate ours-content is absorbed as content rather than treated as a boundary [4](#0-3) .

`reassembleResolvedFile`'s lookahead, by contrast, breaks the instant it finds *any* line matching the theirs-marker regex, regardless of whether a separator has been seen yet, and if no separator was found before that break it declares the whole block "malformed" and passes it through as literal, unmodified text [5](#0-4) .

So for a real conflict block whose "ours" content happens to contain a line beginning with seven `>` characters before the real `=======`/`>>>>>>>` pair:

- `extractConflictHunks` sees a well-formed hunk (real separator found later) and returns it as hunk *N* — this is what the model is asked to resolve, and it's what `validateResolutionPaths` counts against [6](#0-5) .
- `reassembleResolvedFile`, scanning the identical text, hits the embedded `>>>>>>>`-looking line first, finds `hasSeparator === false` at that point, and classifies the entire block as **not a conflict** — it copies every line of it (including the real `<<<<<<<`, `=======`, `>>>>>>>` markers) straight through untouched, without advancing `hunkIndex` [7](#0-6) .

If a second, ordinary conflict exists later in the same file, `reassembleResolvedFile` will then splice `hunkResolutions[0]` — the model's resolution that was actually written for the *first* (misclassified) conflict — into the *second* conflict's location, while silently dropping the resolution genuinely intended for hunk 2. The result is a file that (a) still contains raw, unresolved `<<<<<<<`/`=======`/`>>>>>>>` markers baked into committed source, and (b) has an unrelated AI-generated resolution merged into the wrong code location.

`validateResolutionPaths` only compares the hunk *count* returned by the LLM against the count produced by `extractConflictHunks`; it never validates against how `reassembleResolvedFile` will actually parse the same content, so this class of divergence is invisible to the existing guard.

### Impact Explanation
The corrupted `resolvedContent` is written directly to disk and staged with no further review gate: `writeFile(absolutePath, resolution.resolvedContent, 'utf8')` followed by `git add` [8](#0-7) . This is exactly the "silent corruption of what the user commits" impact class: a user merging/rebasing against a branch or PR authored by an unprivileged, malicious collaborator can end up committing (and pushing) a file containing leftover unresolved conflict markers spliced with an unrelated AI resolution, without any error or warning — because the only sanity check (`validateResolutionPaths`) never observes the mismatch.

### Likelihood Explanation
The trigger condition — a legitimate line of code/text on the "ours" or "theirs" side of a real conflict that happens to start with a run of 7 `<`, `=`, or `>` characters (e.g. ASCII banners, markdown horizontal rules, changelog separators, or literal quoted diff/conflict-marker text) — is not exotic; it is the kind of content a malicious contributor could deliberately plant in a branch/PR precisely to weaponize this divergence, and requires no special repository permissions beyond having a branch the victim later merges/rebases with Copilot conflict resolution enabled.

### Recommendation
- **Short term:** Make `reassembleResolvedFile` reuse the exact same block-boundary logic as `extractConflictHunks` (ideally by sharing one parsing function that returns both raw hunk boundaries and produces the reassembly indices), so the two never disagree on how many/which blocks exist in a given file.
- **Long term:** Extend `validateResolutionPaths` (or add a post-reassembly assertion) to verify that the number of conflict blocks actually consumed during `reassembleResolvedFile` for a given file equals the hunk count returned in the model's resolution before the resolved content is ever written to disk; if they diverge, fail closed and fall back to manual resolution for that file rather than silently writing the result.

### Proof of Concept
Construct a conflicted file where the first conflict's "ours" side contains a line starting with 7 `>` characters before the real closing marker, followed by a second, ordinary conflict:
```
<<<<<<< HEAD
some real code
>>>>>>> looks like a closer but is legitimate content
more real code
=======
their real content
>>>>>>> feature
normal line
<<<<<<< HEAD
our-2
=======
their-2
>>>>>>> feature
```
`extractConflictHunks` returns 2 hunks (as verified by the existing test suite's parsing model) [9](#0-8) ; Copilot is asked to resolve, and returns, 2 hunk resolutions, which pass `validateResolutionPaths` since counts match. Feeding the same raw content and the 2 resolutions into `reassembleResolvedFile` [10](#0-9)  shows the first block is copied through verbatim (still containing all its conflict markers) while `hunkResolutions[0]` (meant for conflict 1) is spliced into conflict 2's position instead of `hunkResolutions[1]`.

export function extractConflictHunks(
  fileContent: string,
  contextLines: number = 3
): ReadonlyArray<IConflictHunk> {
  const lines = fileContent.split(/\r?\n/)
  const hunks: Array<IConflictHunk> = []

  let i = 0
  while (i < lines.length) {
    if (!oursMarker.test(lines[i])) {
      i++
      continue
    }

    const oursStart = i + 1
    const oursLines: Array<string> = []
    const baseLines: Array<string> = []
    let hasBase = false
    const theirsLines: Array<string> = []
    let hunkEnd = -1

    i = oursStart
    // Collect ours content
    while (i < lines.length) {
      if (baseMarker.test(lines[i])) {
        hasBase = true
        i++
        break
      }
      if (separatorMarker.test(lines[i])) {
        i++
        break
      }
      oursLines.push(lines[i])
      i++
    }

    // If diff3, collect base content until separator
    if (hasBase) {
      while (i < lines.length) {
        if (separatorMarker.test(lines[i])) {
          i++
          break
        }
        baseLines.push(lines[i])
        i++
      }
    }

    // Collect theirs content until closing marker
    while (i < lines.length) {
      if (theirsMarker.test(lines[i])) {
        hunkEnd = i
        i++
        break
      }
      theirsLines.push(lines[i])
      i++
    }

    // If we never found the closing marker, skip this malformed hunk
    if (hunkEnd === -1) {
      continue
    }

    // The ours marker line is at oursStart - 1
    const markerStart = oursStart - 1
    const contextStart = Math.max(0, markerStart - contextLines)
    const contextEnd = Math.min(lines.length - 1, hunkEnd + contextLines)

    // Clamp context to not include conflict markers from adjacent hunks
    const contextBeforeLines: Array<string> = []
    for (let j = markerStart - 1; j >= contextStart; j--) {
      if (isConflictMarker(lines[j])) {
        break
      }
      contextBeforeLines.unshift(lines[j])
    }

    const contextAfterLines: Array<string> = []
    for (let j = hunkEnd + 1; j <= contextEnd; j++) {
      if (isConflictMarker(lines[j])) {
        break
      }
      contextAfterLines.push(lines[j])
    }

    const contextBefore = contextBeforeLines.join('\n')
    const contextAfter = contextAfterLines.join('\n')

    hunks.push({
      oursContent: oursLines.join('\n'),
      theirsContent: theirsLines.join('\n'),
      baseContent: hasBase ? baseLines.join('\n') : null,
      contextBefore,
      contextAfter,
    })
  }

  return hunks
}

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }
}

 * Reassemble a fully resolved file by splicing per-hunk resolutions into
 * the original file content (which still has conflict markers on disk).
 *
 * Walks the original file line-by-line. Non-conflicted lines are copied
 * through verbatim. Each conflict marker block (`<<<<<<<` through
 * `>>>>>>>`, with a `=======` separator in between) is replaced with the
 * corresponding entry from `hunkResolutions` (matched by order, not by
 * line number). This guarantees that all non-conflicted code is preserved
 * exactly, and the model's output is only responsible for the small
 * resolved sections.
 *
 * A `<<<<<<<` line that is not followed by both a `=======` separator and
 * a closing `>>>>>>>` before EOF is treated as regular file content (not a
 * conflict block) and copied through unchanged to avoid data loss from
 * malformed or stray markers.
 *
 * @param rawContent - The full file content on disk, including conflict markers
 * @param hunkResolutions - Per-hunk resolved content, in the order they appear in the file
 * @returns The reassembled file with all conflicts resolved
 */
export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}
