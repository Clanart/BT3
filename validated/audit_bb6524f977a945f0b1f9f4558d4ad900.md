### Title
`mWOMSVBaseRewarder._calExpireForfeit` never applies `getRewardablePercentWAD`, letting cooldown/unlocked mWomSV lockers keep 100% of rewards - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder` holds a reference to the `mWomSV` locker (`ILocker public mWOMSV`) which exposes `getRewardablePercentWAD`, a percentage meant to scale down rewards for users who are in cooldown or fully unlocked. Unlike the analogous `vlMGPBaseRewarder._calExpireForfeit`, which multiplies `_amount` by `vlMGP.getRewardablePercentWAD(_account)`, the `mWOMSVBaseRewarder._calExpireForfeit` sets `rewardableAmount = _amount` unconditionally, making the forfeiture mechanism a no-op.

### Finding Description
`vlMGPBaseRewarder._calExpireForfeit` correctly computes: [1](#0-0) 
```
uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
...
uint256 forfeitAmount = _amount - rewardableAmount;
```

`mWOMSVBaseRewarder._calExpireForfeit`, which is called from `_sendReward` in the exact same pattern (`getReward` → `updateReward` → `_sendReward` → `_calExpireForfeit`), instead does: [2](#0-1) 
```
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardableAmount = _amount;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();
    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }
    return forfeitAmount;
}
```
`rewardableAmount` is always equal to `_amount`, so `forfeitAmount` is always `0`. The contract does declare and initialize `ILocker public mWOMSV` in `__mWOMSVBaseRewarder_init` [3](#0-2) [4](#0-3) , and `mWomSV.sol` fully implements `getRewardablePercentWAD`, computing a reduced percentage for users in cooldown or fully unlocked slots [5](#0-4) , but `mWOMSVBaseRewarder` never calls it.

Attack path: an attacker calls `SmartWomConvert.convertFor` (mode that locks into mWomSV) to obtain mWomSV balance, then unprivileged-ly calls `mWomSV.startUnlock(fullAmount)` to enter cooldown [6](#0-5) . This does not reduce the user's `balanceOf` in the rewarder (mWomSV supply/balance-based staking continues to count cooldown/unlocked balances the same as locked balances for reward accrual), and when the user calls `MasterMagpie.multiclaimFor` / `mWOMSVBaseRewarder.getReward`, `_sendReward` computes `forfeitAmount = _calExpireForfeit(...)` which is always `0`, so the full reward is paid out with no redistribution to still-committed lockers.

### Impact Explanation
This breaks the intended reward-conservation invariant of the mWomSV lock system: rewards that should be forfeited by unlocking/cooling-down users and redistributed to fully committed lockers (via `_queueNewRewardsWithoutTransfer`) are instead paid in full to the unlocking user. This is a theft of unclaimed yield that should accrue to committed lockers — matching the Immunefi impact class "theft of unclaimed yield" / "permanent loss of protocol funds designated for other users." Every reward distribution cycle is affected as long as any user is in cooldown or fully unlocked, so the loss compounds continuously and is not a one-off edge case.

### Likelihood Explanation
This requires no privileged access, no capital beyond acquiring/locking mWom, and no timing tricks — it is the normal `startUnlock` → `getReward` flow available to any locker. It is fully repeatable by any account with mWomSV balance and will trigger on every reward harvest performed while the account is in cooldown or past cooldown (unlocked but not yet withdrawn).

### Recommendation
Fix `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder`'s logic by calling `mWOMSV.getRewardablePercentWAD(_account)` and scaling `rewardableAmount` accordingly:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();
    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }
    return forfeitAmount;
}
```

### Proof of Concept
Foundry test outline:
1. Deploy `mWomSV`, `mWOMSVBaseRewarder`, `MasterMagpie`, and a reward token; register the rewarder with `MasterMagpie` and queue a reward token via `queueNewRewards`.
2. Two users, Alice and Bob, each lock the same amount of mWom into `mWomSV` (via `lock`/`lockFor`), both minting equal mWomSV/rewarder balances.
3. Rewarder manager calls `queueNewRewards` to add reward tokens; both users accrue identical `rewardPerToken`.
4. Bob immediately calls `mWomSV.startUnlock(fullAmount)` to enter cooldown (or fast-forward past `coolDownInSecs` to simulate "fully unlocked but unclaimed").
5. Both call `MasterMagpie.multiclaimFor` (routing to `mWOMSVBaseRewarder.getReward`).
6. Assert: `rewardToken.balanceOf(alice) == rewardToken.balanceOf(bob)` and that `calExpireForfeit(bob, rewardToken)` returns `0` despite Bob being in cooldown — proving the forfeiture mechanism never fires and conservation of "rewardable yield redistribution to committed lockers" is violated (expected: Bob's payout should be reduced according to `getRewardablePercentWAD(bob) < 1e18`, with the difference redistributed via `_queueNewRewardsWithoutTransfer`).

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
