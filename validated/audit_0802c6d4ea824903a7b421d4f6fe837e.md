### Title
`MasterMagpie.emergencyWithdraw` skips `updatePool()`/reward checkpoint, permanently corrupting `accMGPPerShare` reward accounting - (File: `rewards/MasterMagpie.sol`)

### Summary
`MasterMagpie.emergencyWithdraw()` mutates a user's staked balance and `rewardDebt` without first calling `updatePool()` (or harvesting the base rewarder), unlike every other balance-mutating path (`_deposit`, `_withdraw`/`_harvestAndUnstake`). This mirrors the reported bug class: an emergency-exit path that bypasses the checkpoint step used by the normal deposit/withdraw flow to keep reward accounting flash-loan/manipulation resistant.

### Finding Description
In `_deposit` and `_harvestAndUnstake` (used by `_withdraw`), the contract always calls `updatePool(_stakingToken)` before touching `pool.accMGPPerShare` or `user.rewardDebt`: [1](#0-0) [2](#0-1) 

`emergencyWithdraw`, however, directly reads `pool.accMGPPerShare` and recomputes `user.rewardDebt` from a stale value, with no call to `updatePool` and no harvest of the base rewarder: [3](#0-2) 

Critically, `updatePool` itself is gated by `whenNotPaused`: [4](#0-3) 

while `emergencyWithdraw` is only callable `whenPaused`: [5](#0-4) 

This means the accrual checkpoint (`pool.accMGPPerShare`/`pool.lastRewardTimestamp`) is frozen for the entire duration the contract is paused, yet users can still call `emergencyWithdraw` to reduce the pool's staked/available token balance and lock in a `rewardDebt` based on the outdated `accMGPPerShare`. When the contract is later unpaused and `updatePool` is finally invoked, the full elapsed reward (`multiplier * mgpPerSec * pool.allocPoint / totalAllocPoint`) accrued over the whole paused interval is divided by the **post-emergency-withdrawal** (now lower) `_calLpSupply(_stakingToken)`, not the LP supply that actually existed during most of that interval: [6](#0-5) 

This retroactively inflates `accMGPPerShare` for remaining/new stakers using a supply figure that never actually applied for that period, permanently distorting reward distribution — remaining stakers receive rewards that were never properly earned relative to historical supply, while emergency-withdrawing users' `rewardDebt` was fixed against the stale, lower `accMGPPerShare`, misallocating pool-wide MGP emissions with no way to reconcile after the fact.

### Impact Explanation
The reward-per-share checkpoint desynchronization is permanent and unrecoverable once triggered: MGP emission accounting (`accMGPPerShare`) is corrupted for the pool, causing incorrect (over- or under-) reward allocation to legitimate stakers going forward. This constitutes a permanent freezing/misallocation of protocol yield accounting for a shared emission pool, matching the accepted "theft or permanent freezing of unclaimed yield" impact category.

### Likelihood Explanation
Any ordinary staker can call `emergencyWithdraw` once the pause condition is active — no privileged role is required to trigger the vulnerable code path itself (the pause state is a pre-existing contract condition, analogous to the "not killed" state check in the original report, not an attacker-controlled privileged action). Given `MasterMagpie` is a central emission-accounting contract used across all registered staking pools, any pause event followed by even one `emergencyWithdraw` call creates the corrupted checkpoint condition.

### Recommendation
Call an equivalent of `updatePool(_stakingToken)` (or capture/carry forward the correct historical LP supply) as part of `emergencyWithdraw`, or otherwise ensure `accMGPPerShare` is snapshotted using the LP supply that existed at pause-time rather than deferring the entire pause-period accrual to be divided by a post-withdrawal, reduced LP supply.

### Proof of Concept
Not executed; derived from static code comparison between `_deposit`/`_harvestAndUnstake` (checkpoint via `updatePool`) and `emergencyWithdraw` (no checkpoint), combined with the `whenNotPaused`/`whenPaused` modifier interaction described above. A dynamic PoC (pause → have some users `emergencyWithdraw` → unpause → trigger `updatePool` via any deposit/withdraw → compare `accMGPPerShare` progression against expected value using historical LP supply) would be needed to fully confirm the magnitude of the reward misallocation, which is beyond the scope of this static analysis.

    function updatePool(address _stakingToken) public whenNotPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        if (block.timestamp <= pool.lastRewardTimestamp || totalAllocPoint == 0) {
            return;
        }
        uint256 lpSupply = _calLpSupply(_stakingToken);
        if (lpSupply == 0) {
            pool.lastRewardTimestamp = block.timestamp;
            return;
        }        
        uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
        uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
        
        pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
        pool.lastRewardTimestamp = block.timestamp;

        emit UpdatePool(
            _stakingToken,
            pool.lastRewardTimestamp,
            lpSupply,
            pool.accMGPPerShare
        );
    }

    function emergencyWithdraw(address _stakingToken) external whenPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][msg.sender];
        uint256 availableaAmount = user.available;
        user.available = 0;
        IERC20(pool.stakingToken).safeTransfer(address(msg.sender), availableaAmount);
        emit EmergencyWithdraw(msg.sender, _stakingToken, availableaAmount);
        user.amount = user.amount - availableaAmount;
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
