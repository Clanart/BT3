### Title
Shared `BalanceHandler` instance in nested/recursive precompile calls causes `prevEventsLen` to be overwritten, desyncing EVM `StateDB` balances from actual `x/bank` balances - ([File: precompiles/common/balance_handler.go])

### Summary
This is a direct analog of the `creditedNodeETH` bug: a cached/offset accounting value (`prevEventsLen`) that is supposed to be updated in lock-step with an underlying balance-moving operation is instead shared and clobbered across nested calls, so the reconciliation step (`AfterBalanceChange`) computes balance deltas from the wrong window of events - producing a `StateDB` balance that diverges from the real `x/bank` balance.

### Finding Description
Every precompile embeds `cmn.Precompile`, which holds a single `BalanceHandler` instance created once via `BalanceHandlerFactory.NewBalanceHandler()` [1](#0-0) . The pattern used throughout every precompile's `Run`/`Execute` path (see e.g. `testutil/testdata/debug/debug.go`) is:

1. `BeforeBalanceChange(ctx)` — records `prevEventsLen = len(ctx.EventManager().Events())` [2](#0-1) .
2. Execute the precompile's native action (bank sends, staking, distribution, ICS20, etc.), which emits `EventTypeCoinSpent`/`EventTypeCoinReceived`/`EventTypeFractionalBalanceChange` events.
3. `AfterBalanceChange(ctx, stateDB)` — replays `events[prevEventsLen:]` and applies `stateDB.AddBalance`/`SubBalance` to keep the EVM-visible balance in sync with the real bank balance change [3](#0-2) .

Because the `BalanceHandler` (and its `prevEventsLen` field) is a single shared instance per precompile object rather than being scoped per call-frame, a contract that recursively/re-enters a precompile (e.g., a contract calling into the staking/distribution/ICS20/erc20 precompile, which itself calls back into the contract, which calls the precompile again) causes the inner call's `BeforeBalanceChange` to overwrite `prevEventsLen` set by the outer call. When the outer call later invokes `AfterBalanceChange`, it slices `events[prevEventsLen:]` using the *inner* call's offset instead of its own, causing it to either replay events that were already applied by the inner call (double counting) or skip/mis-slice events belonging to its own balance change (dropping updates). The bug is explicitly reproduced by a dedicated regression test, `BalanceHandlerTestSuite`, whose own doc comment states: "tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance, causing prevEventsLen to be overwritten. This leads to balance desync between native bank keeper and EVM stateDB" [4](#0-3) , exercised through a debug precompile and a caller contract triggering recursive `callback` invocations [5](#0-4) .

This exactly mirrors the reported bug class: a tracked accounting value (`creditedNodeETH` / here `prevEventsLen`) is not correctly maintained across a nested/second operation, corrupting a downstream balance reconciliation (`_startSnapshot()` underflow / here `StateDB` vs. bank balance desync).

### Impact Explanation
`StateDB` balance is the balance an EVM contract observes and can act on within the same transaction (e.g., for subsequent `CALL`/`transfer`/`require(balance >= X)` checks, or for computing further transfers before the transaction commits). If `AfterBalanceChange` under- or over-applies balance deltas due to the clobbered offset, a contract can end up with a `StateDB` balance that is higher than its real, spendable `x/bank` balance within the same transaction, or a counterparty ends up with the incorrect corresponding balance. An attacker-controlled contract that deliberately triggers reentrant/nested precompile calls (a pattern reachable by any unprivileged EVM user deploying and calling their own contract) can exploit this offset corruption to make the EVM-visible balance diverge from the real underlying `x/bank` balance, enabling further EVM-level transfers/calls against an inflated (fabricated) balance — i.e., extraction of value the account does not actually hold — or permanently losing (freezing) balance updates that should have been credited. Because balances are the core spendable-value invariant in the target's Critical impact list (unauthorized minting/duplication/theft of spendable value across native/EVM/bank balances), this rises to Critical if the desync can be leveraged to spend more than the true balance or to strand funds; the codebase's own regression test confirms the desync condition is real and reachable via ordinary contract logic.

### Likelihood Explanation
The trigger requires only deploying an ordinary smart contract that performs a reentrant call into a precompile from within a precompile-triggered callback (a "recursive precompile call" pattern), which is a normal, unprivileged EVM interaction pattern — no special permissions, validator/relayer control, or malicious node behavior needed. The existence of a purpose-built regression test (`TestRecursivePrecompileCallsWithDebugPrecompile`) demonstrates the maintainers themselves identified recursive precompile calls as a concrete, reachable trigger path for this exact behavior.

### Recommendation
Scope `prevEventsLen` (and the `BalanceHandler` state generally) per call-frame rather than as a single field shared across nested precompile invocations — e.g., use a stack of offsets pushed/popped around each precompile `Run`, or instantiate a fresh `BalanceHandler` per call and thread it through nested invocations so each call's `AfterBalanceChange` only ever consumes the exact slice of events it itself produced, regardless of intervening reentrant calls.

### Proof of Concept
The repository already contains a reproducing test: `evmd/tests/integration/balance_handler/balance_handler_test.go` deploys a "debug precompile caller" contract that recursively invokes a debug precompile through nested EVM `callback` calls sharing the same `BalanceHandler` instance, demonstrating the `prevEventsLen` overwrite and resultant balance-tracking desync [6](#0-5) . I was not able to fully trace whether this specific desync has been patched or is guarded elsewhere in this snapshot (e.g., whether `GetPrecompileInstance` always returns a fresh `BalanceHandler` per top-level EVM tx call versus a cached one across nested calls) due to index limits on `precompiles/common/precompile.go`; a Devin session with full repository access would be needed to confirm whether a per-call-frame guard already exists or whether this is still an open, exploitable path in production.

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

// TestRecursivePrecompileCallsWithDebugPrecompile demonstrates the balance handler bug
// by triggering recursive calls that share the same BalanceHandler instance.
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))
	s.Require().NoError(err)

	res, _, _, err := s.chain.SendEvmTx(
		s.chain.SenderAccounts[0],
		0,             // sender index
		callerAddr,    // to address
		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier
	)
	s.Require().NoError(err, "callback transaction should succeed")
	s.Require().False(res.IsErr(), "callback should not fail: %s", res.Events)

	s.Require().Equal(len(res.Events), 15, "callback should have 15 events")
	debug_count := 0
	for _, event := range res.Events {
		if event.Type == "debug_precompile" {
			debug_count++
		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")

	// Advance to next block to finalize state
	s.chain.NextBlock()
}
