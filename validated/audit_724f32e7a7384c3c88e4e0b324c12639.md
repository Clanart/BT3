### Title
DataLayer mirror/subscription URLs are followed without any SSRF-hardening, allowing arbitrary outbound requests to internal network hosts - (File: chia/data_layer/data_layer.py, chia/data_layer/download_data.py)

### Summary
`CVE-2026-48843` is about Roundcube insufficiently sanitizing CSS `url()`/stylesheet references in untrusted HTML e-mail, letting the mail server or client fetch attacker-chosen remote resources, enabling SSRF against local-network hosts. The chia-blockchain DataLayer module has an analogous bug class: mirror/subscription URLs that originate from another, unprivileged party (any store owner via `dl_new_mirror`) are propagated on-chain, pulled by `update_subscriptions_from_wallet()`, and then dereferenced by the local node's HTTP client with no validation that the target host/port is not on the local network or a cloud metadata endpoint.

### Finding Description
A DataLayer store owner can call the `add_mirror` RPC to publish arbitrary URLs for their singleton on-chain: [1](#0-0) 

Any other user's node that subscribes to that store id periodically calls `update_subscriptions_from_wallet()`, which fetches the on-chain-advertised mirror URLs via wallet RPC and inserts them into the local subscriptions table completely unvalidated (no scheme allowlist, no private/loopback/link-local address filtering): [2](#0-1) [3](#0-2) 

The same lack of URL validation exists on the `subscribe` RPC path, where a caller-supplied URL list is accepted and stored as-is: [4](#0-3) [5](#0-4) 

These stored URLs are later dereferenced automatically by the background sync loop. `fetch_and_validate()` iterates over `servers_info` and issues outbound HTTP requests (`insert_from_delta_file` → `download_file` → `http_download`) to whatever URL was stored, again with no destination-host validation: [6](#0-5) [7](#0-6) 

The project's own internal documentation explicitly flags this as an unresolved trust boundary: "Plugin and mirror URLs are external trust inputs... file path/name validation must stay strict" — but no equivalent statement or code exists for validating the destination *host* of the URL itself, only the downloaded file name/content. [8](#0-7) 

### Impact Explanation
Any unprivileged wallet/Data Layer participant who owns a DataLayer store (a normal, permissionless action) can advertise mirror URLs pointing at internal-network addresses (e.g. `http://127.0.0.1:<port>/...`, RFC1918 addresses, or cloud metadata services like `http://169.254.169.254/...`). Every other node that subscribes to that store — an ordinary, unprivileged Data Layer client action — will automatically and periodically issue outbound HTTP POST/GET requests to that address from its own network position, once per `manage_data_interval` cycle for as long as the subscription remains active. This is a server-side request forgery: it lets a remote unprivileged actor cause victim nodes to probe/interact with services on the victim's local network or cloud metadata endpoints that are otherwise unreachable from the internet, which can lead to internal service enumeration, port-scanning, or information disclosure depending on the deployment environment.

### Likelihood Explanation
The attack requires no special privilege: creating a DataLayer store and adding a mirror is a normal user-level wallet operation (`add_mirror`/`dl_new_mirror`), and getting a victim to subscribe to the attacker's store is the expected/intended DataLayer usage pattern (data replication via subscription). Because URL validation is entirely absent at both the RPC `subscribe` boundary and the wallet-mirror ingestion boundary, exploitation only requires publishing a crafted URL and waiting for a normal subscriber to sync.

### Recommendation
Before storing or dereferencing any mirror/subscription URL (`DataLayer.subscribe`, `DataLayer.update_subscriptions_from_wallet`, `DataStore.subscribe`, `DataStore.update_subscriptions_from_wallet`), validate the resolved hostname/IP against a deny-list of loopback, link-local, private (RFC1918), and cloud-metadata address ranges, and restrict allowed schemes/ports. Re-validate at request time (not just at insertion time) to avoid DNS-rebinding bypasses in `http_download` and the plugin `download_file`/`get_plugin_info` HTTP calls.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/"]` (or an internal IP known to be reachable from the target node's network), analogous to `dl_new_mirror` in [1](#0-0) .
2. Victim node subscribes to attacker's store id via the normal `subscribe` RPC flow in [4](#0-3) .
3. On the next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` pulls the attacker-controlled URL into the victim's subscriptions table unvalidated [2](#0-1) .
4. `fetch_and_validate()`/`download_file()`/`http_download()` cause the victim node to issue an outbound HTTP request to the attacker-chosen internal address [9](#0-8) , confirming SSRF against the victim's local network.

    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False
