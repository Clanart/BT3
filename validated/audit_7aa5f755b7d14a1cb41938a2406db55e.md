### Title
Forged `ReceivedOutput` amounts cause Bitcoin transactions to burn excess wallet funds as fees - (File: `networks/bitcoin/src/wallet/send.rs`)

### Summary
`ReceivedOutput::read` accepts a caller-supplied `TxOut` containing an arbitrary amount, script, and outpoint, and `SignableTransaction::new` trusts that amount for fee and change calculations. [1](#0-0)  When signing, `multisig` verifies only that the supplied `script_pubkey` belongs to the threshold key, not that the supplied amount matches the actual on-chain UTXO. [2](#0-1)  An understated amount therefore causes the transaction to sign a normal-looking output set while the real UTXO contributes the unreported remainder as an excessive miner fee.

### Finding Description
`ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` directly from untrusted bytes without validating the `TxOut` against a blockchain view. [3](#0-2)  `SignableTransaction::new` calculates `input_sat` by summing these supplied `TxOut` values and then uses that sum for the not-enough-funds check and change calculation. [4](#0-3)  If a change script is present, it derives the change amount as `input_sat - payment_sat - fee_with_change`, so reducing the recorded input value silently moves the difference from change into the actual transaction fee. [5](#0-4) 

The signing setup checks only that the offset-adjusted group key produces the claimed `script_pubkey`; it does not check the claimed value or query the referenced outpoint. [2](#0-1)  The Taproot sighash then commits to the forged `prevouts` vector, including the understated amount, while Bitcoin consensus calculates the fee from the actual UTXO value. [6](#0-5)  As a result, `fee()` reports the fee calculated from the forged input values rather than the much larger fee that will be paid on chain. [7](#0-6) 

### Impact Explanation
An attacker who can submit serialized `ReceivedOutput` values or a transaction built from them can cause the wallet to sign a transaction that burns nearly the entire value of selected real UTXOs as fees. [1](#0-0)  The attack works even when a change output is requested because the understated input is used to calculate a plausible change amount while the omitted value remains outside all outputs. [5](#0-4)  This produces a valid signature over an unintended transaction and results in a direct loss of wallet funds.

### Likelihood Explanation
The attacker only needs a real UTXO’s outpoint, its threshold-controlled script, and its scalar offset; for the wallet’s primary key, the offset is `Scalar::ZERO`. [8](#0-7)  The forged object can also be produced by scanning a valid output, serializing it, and modifying the eight-byte amount inside the encoded `TxOut`. [9](#0-8)  The resulting transaction remains consensus-valid and is signed because the implementation authenticates the key script but not the claimed amount. [2](#0-1) 

### Recommendation
Bind each `ReceivedOutput` to verified chain data before constructing or signing a transaction. At minimum, the signing path should resolve every `previous_output` and compare its on-chain `TxOut`, including both `value` and `script_pubkey`, with the supplied `prevouts` entry. [2](#0-1)  The constructor should additionally expose or enforce a maximum actual fee, rather than allowing arbitrary differences between actual input values and declared outputs.

### Proof of Concept
The following demonstrates how a valid scanned output can be copied with an understated amount and then signed while preserving the correct threshold script:

```rust
// networks/bitcoin/src/wallet/send.rs

let real: ReceivedOutput = scanner.scan_transaction(&funding_tx).remove(0);
let actual_value = real.value(); // e.g. 100_000 sats

let mut encoded = real.serialize();
// Layout: 32-byte offset, followed by consensus-encoded TxOut.
// The TxOut amount is the first eight bytes of that TxOut encoding.
let understated_value = 20_000u64;
encoded[32 .. 40].copy_from_slice(&understated_value.to_le_bytes());
let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

let signable = SignableTransaction::new(
  vec![forged],
  &[(payment_script, 10_000)],
  Some(change_script),
  None,
  fee_rate,
).unwrap();

// The key/script check succeeds because the forged TxOut retains the real
// threshold-controlled script_pubkey.
let machine = signable.multisig(&threshold_keys).unwrap();
```

If the transaction claims a 10,000-sat payment and roughly 9,700 sats of change from a forged 20,000-sat input, signing succeeds while the actual 100,000-sat UTXO pays approximately 80,300 sats plus the intended fee to miners. [10](#0-9)  The forged amounts are committed through `Prevouts::All`, and `complete` inserts the resulting Schnorr signatures into the final transaction. [6](#0-5) [11](#0-10)
