### Title
Payout tx OP_RETURN operator-attribution is unauthenticated and malleable under SIGHASH_SINGLE|ANYONECANPAY, letting anyone hijack reimbursement credit - (File: `core/src/verifier.rs`, `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` signs the withdrawal input with `SIGHASH_SINGLE|ANYONECANPAY`, which authenticates only input 0 and output 0 (the user payout). The anchor output and the OP_RETURN carrying the fronting operator's x-only pubkey (output indices 1 and 2) are completely unsigned. Once an honest operator broadcasts its `Payout` tx, anyone who observes it in the mempool can rebuild an equivalent transaction reusing the same signed input/output-0 pair, replace the OP_RETURN with a different registered operator's x-only pubkey, attach their own fee-paying inputs, and get it mined first — causing `Verifier::update_finalized_payouts` to record the wrong operator as the payer.

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk` (for withdrawal idx `i`) == the operator whose funds actually fronted the withdrawal. Before the attack this holds trivially (only the honest operator broadcasts anything). After the attack it breaks: the DB records operator B's key while the actual BTC funding the mined transaction came from the attacker (or from operator A's original attempt, now orphaned).

Code path:
1. `create_payout_txhandler` builds the payout with `SpendPath::KeySpend` on input 0 and `set_p2tr_key_spend_witness(&user_sig, 0)`, where `user_sig` is a `taproot::Signature` whose `sighash_type` is `SinglePlusAnyoneCanPay` (per design comment and precondition). This sighash type covers only input 0's signed data and the output at the same index (index 0), leaving output 1 (anchor) and output 2 (OP_RETURN with `operator_xonly_pk.serialize()`) completely outside the signed message: [1](#0-0) 
2. `Operator::withdraw` only verifies the user's signature against input 0 / output 0 via `calculate_sighash_txin` and `SECP.verify_schnorr`; it never authenticates or signs outputs 1/2: [2](#0-1) 
3. Verifiers determine the payout's spending tx purely by which tx spends the registered `withdrawal_utxo` on-chain, with no signature or origin check tying the tx to a specific operator's broadcast: [3](#0-2) 
4. `Verifier::update_finalized_payouts` blindly trusts whatever OP_RETURN payload is present in the mined tx, parsing it as the "payer" xonly pk with no cryptographic link between that pubkey and the actual funder of the tx: [4](#0-3) 
5. This is written straight into `withdrawals.payout_payer_operator_xonly_pk`: [5](#0-4) 
6. `PayoutCheckerTask::run_once` on the impersonated operator B's own node queries strictly by `operator_xonly_pk == self.operator.signer.xonly_public_key`, finds this withdrawal, and unconditionally calls `handle_finalized_payout`, which has no check that operator B ever actually broadcast/funded this specific payout — it only checks for an unused kickoff connector and proceeds to build/track the kickoff: [6](#0-5) [7](#0-6) 
7. Later, `validate_payer_is_operator` (used by `get_reimbursement_txs`) only checks that the recorded `payer_xonly_pk` equals the querying operator's own key — it re-derives from the same tainted DB column and cannot detect the forgery: [8](#0-7) 

Exploit flow: attacker watches the Bitcoin mempool/P2P network (unprivileged, no special access) for an unconfirmed `Payout` transaction. It extracts the witness (which contains `user_sig`) and the fixed input 0 / output 0 pair. It constructs a new transaction with the same input 0 (witness reused, valid because ANYONECANPAY permits changing other inputs) and same output 0 (required by SIGHASH_SINGLE), but supplies its own additional funding input(s) for fees/change and rewrites output 2's OP_RETURN to carry a different, currently-registered operator B's x-only pubkey (public via `get_compatibility_data_from_entities` or any prior on-chain payout OP_RETURN). It broadcasts with a higher fee so it confirms first, causing the original honest tx to be evicted/never confirm. No existing guard (`is_deposit_valid`, `SECP.verify_schnorr`, `only_aggregator_and_self`, presigned tx graph, DB uniqueness) checks that the OP_RETURN's claimed operator actually supplied funds — the whole scheme relies on unsigned data for a security-critical attribution field.

### Impact Explanation
Operator B is driven through the entire kickoff/BitVM process (round advancement, kickoff broadcast, challenge-timeout, ready-to-reimburse, and ultimately a `Reimburse` transaction spending bridge collateral) for a payout it never funded — this is bridge value (collateral) credited to the wrong party, matching the Critical category "operator reimbursed for a payout it never funded." Simultaneously the true funder (which may be the honest operator A whose original broadcast is now orphaned, or simply the attacker) is never attributed via `payout_payer_operator_xonly_pk`, and `validate_payer_is_operator` will forever reject their reimbursement attempts for that deposit id — "an honest operator permanently unable to be reimbursed." The attack is repeatable for every withdrawal index and against any operator whose pubkey is public (all of them, since operator keys are broadcast in every past payout's OP_RETURN or via `get_compatibility_data_from_entities`).

### Likelihood Explanation
Preconditions are modest and match real deployment: ≥2 registered operators, a withdrawal registered with a valid `SinglePlusAnyoneCanPay` signature (the standard, intended signature type for this transaction by design), and mempool visibility of the honest operator's unconfirmed broadcast (any Bitcoin full/relay node access, no privileged role). Attacker cost is only the fee premium needed to outbid the original tx (bounded, cheap) plus dust for their fee-paying input. No verifier/operator/aggregator compromise, no key theft, no majority hashrate required — this is pure transaction malleability exploitation of an unsigned output field used for security-critical bookkeeping.

### Recommendation
Do not rely on an unsigned OP_RETURN for operator attribution. Either (a) require the withdrawal off-chain signature to be full `SIGHASH_ALL` (or at minimum `SIGHASH_SINGLE` covering the OP_RETURN output as well, e.g. by moving/duplicating the operator pubkey commitment into an output actually protected by the sighash), or (b) have verifiers cross-check the recorded operator identity against an independently authenticated source — e.g., require the operator to co-sign a commitment (with their own key) binding themselves to the specific `withdrawal_idx`/outpoint before trusting the on-chain OP_RETURN, or track which operator's `TxSender` actually constructed/broadcast the exact confirmed txid rather than trusting `parse_op_return_data` alone.

Plan:
1. Spin up 2 operators (A, B) + verifiers with `MockCitreaClient`, register a withdrawal (idx `i`) with a valid `SinglePlusAnyoneCanPay` user signature.
2. Have operator A call `withdraw` to build+broadcast its `Payout` tx (`tx_A`) but intercept it before confirmation (don't mine yet).
3. From the raw hex of `tx_A`, extract input 0 (with witness) and output 0; build `tx_forged` with the same input 0/output 0, a new funding input/output pair from a throwaway wallet, and an OP_RETURN naming operator B's `xonly_public_key` (obtained from the operator's known signer key in the test config).
4. Broadcast `tx_forged` with higher fee, mine it (ensuring `tx_A` is evicted/never confirms).
5. Run the bitcoin syncer / verifier block processing so `update_finalized_payouts` executes.
6. Assert `db.get_first_unhandled_payout_by_operator_xonly_pk(operator_B_pk)` returns withdrawal `i` — i.e. `payout_payer_operator_xonly_pk == B` in the DB.
7. Assert operator B's `PayoutCheckerTask::run_once` proceeds to call `handle_finalized_payout` and produces a kickoff txid for deposit `i`.
8. Assert independently that operator A's `TxSender`/wallet never had `tx_forged`'s funding inputs (i.e., A's balance is unaffected / A's `withdraw` state shows `tx_A` never confirmed), proving A (or the attacker) funded the actually-mined transaction while B is credited.
9. Assert `Operator::validate_payer_is_operator` called from A's context for deposit `i` now returns an error ("Payer is not own operator"), demonstrating A is permanently locked out of reimbursement for a withdrawal it attempted to front.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        &self,

        deposit_id: u32,

        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,

                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }

    pub async fn get_payout_txs_for_withdrawal_utxos(

        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,

        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
