### Title
Cross-transaction deposit metadata overwrite for same-block Bitcoin outputs - ([File: processor/src/networks/bitcoin.rs](processor/src/networks/bitcoin.rs))

### Summary
`Bitcoin::get_outputs` accumulates scanned outputs across all transactions in a block, but after each transaction it assigns that transaction’s `presumed_origin` and `extract_serai_data(tx)` result to every output collected so far. An attacker who places their own deposit/instruction transaction after a victim’s deposit in the same block causes the victim’s `External` output to be emitted with the attacker’s origin and Serai instruction data. This maps the reported “many users send BTC to the same address concurrently” bug onto Serai: the UTXOs remain distinct, but their instruction metadata is not isolated per transaction.

### Finding Description
`scan_transaction` correctly returns every output paying to a registered script with its own outpoint, so simultaneous deposits are not inherently lost at the UTXO layer [1](#0-0) . The processor then keeps `outputs` outside the per-transaction loop and pushes every scanned output into that shared vector [2](#0-1) . If `outputs` is non-empty after any transaction, it computes that transaction’s input origin and `extract_serai_data(tx)`, then overwrites `data`/`presumed_origin` on all accumulated `External` outputs, including outputs created by earlier transactions [3](#0-2) .

`extract_serai_data` accepts attacker-controlled bytes from an `OP_RETURN` output or from a P2WSH witness satisfying the `OP_SHA256 <hash> OP_EQUALVERIFY` pattern [4](#0-3) . Those bytes are later decoded as `Shorthand`/`RefundableInInstruction` for `External` outputs, determining the instruction executed for the deposited balance [5](#0-4) .

### Impact Explanation
A victim deposit mined in transaction `T_v` can have its Serai instruction replaced by the data from attacker transaction `T_a` mined later in the same block. If `T_a` carries a valid `Shorthand::transfer`/refundable instruction naming the attacker as beneficiary/origin, `instruction_from_output` will build the victim output’s `InInstructionWithBalance` from attacker-controlled data rather than the victim’s data [6](#0-5) . The BTC itself is still spendable by Serai and becomes a UTXO, but the external deposit is accounted under the wrong instruction, enabling misdirection of the resulting bridged funds/instruction and breaking the expected binding between a Bitcoin deposit transaction and its declared intent [7](#0-6) .

### Likelihood Explanation
Likelihood is low-to-medium and conditional. The attacker cannot alter confirmed history; they must arrange for a transaction they control, paying to the same active Serai external address and carrying chosen data, to be ordered after the victim’s Serai-paying transaction within the same block [8](#0-7) . Ordinary wallet users cannot choose intra-block order, but miners or users able to observe a pending victim deposit and get a following transaction included in the same block can trigger it. No validator compromise, threshold collusion, leaked keys, malformed curves, or invalid signatures are required; only public Bitcoin transactions are needed.

### Recommendation
Track metadata per transaction, not per accumulated block output set. In `Bitcoin::get_outputs`, scan each `tx` into a fresh `tx_outputs` vector, populate `presumed_origin`/`data` only for outputs from that `tx`, and then extend the block-level `outputs` list. If multiple `External` outputs in one transaction share one data payload, that is consistent with a single transaction’s intent; the bug is applying it across earlier transactions. Also consider rejecting ambiguous deposits where the extracted data/origin cannot be unambiguously bound to the paying transaction.

### Proof of Concept
Let `K` be the active multisig group key and `E = p2tr_script_buf(K)` the external deposit script registered by `Scanner::new` with offset zero [9](#0-8) .

1. Victim broadcasts `T_v` with output `O_v` paying `X` sats to `E` and witness/`OP_RETURN` data `D_v` encoding `Shorthand` crediting the victim.
2. Attacker broadcasts `T_a` with output `O_a` paying `Y` sats to `E` and `D_a` encoding `Shorthand` crediting the attacker, arranged so `T_a` appears after `T_v` in block `B`.
3. `get_outputs(B, K)` scans `T_v`, appends `O_v`, and sets `O_v.data = D_v`, `O_v.presumed_origin = origin(T_v)`; it then scans `T_a`, appends `O_a`, recomputes `data = D_a`, `presumed_origin = origin(T_a)`, and applies them to both `O_v` and `O_a` because `outputs` was never reset [8](#0-7) .
4. The emitted block event contains `O_v` with attacker `D_a`. `instruction_from_output(O_v)` decodes `D_a` and creates an `InInstructionWithBalance` for `X - 2*COST_TO_AGGREGATE` under the attacker’s instruction, discarding `D_v` [6](#0-5) .

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }

  fn segwit_data_pattern(script: &ScriptBuf) -> Option<bool> {
    let mut ins = script.instructions();

    // first item should be SHA256 code
    if ins.next()?.ok()?.opcode()? != OP_SHA256 {
      return Some(false);
    }

    ins.next()?.ok()?.push_bytes()?;

    // next should be a equality check
    if ins.next()?.ok()?.opcode()? != OP_EQUALVERIFY {
      return Some(false);
    }

    Some(true)
  }

fn instruction_from_output<N: Network>(
  output: &N::Output,
) -> (Option<ExternalAddress>, Option<InInstructionWithBalance>) {
  assert_eq!(output.kind(), OutputType::External);

  let presumed_origin = output.presumed_origin().map(|address| {
    ExternalAddress::new(
      address
        .try_into()
        .map_err(|_| ())
        .expect("presumed origin couldn't be converted to a Vec<u8>"),
    )
    .expect("presumed origin exceeded address limits")
  });

  let mut data = output.data();
  let max_data_len = usize::try_from(MAX_DATA_LEN).unwrap();
  if data.len() > max_data_len {
    error!(
      "data in output {} exceeded MAX_DATA_LEN ({MAX_DATA_LEN}): {}. skipping",
      hex::encode(output.id()),
      data.len(),
    );
    return (presumed_origin, None);
  }

  let shorthand = match Shorthand::decode(&mut data) {
    Ok(shorthand) => shorthand,
    Err(e) => {
      info!("data in output {} wasn't valid shorthand: {e:?}", hex::encode(output.id()));
      return (presumed_origin, None);
    }
  };
  let instruction = match RefundableInInstruction::try_from(shorthand) {
    Ok(instruction) => instruction,
    Err(e) => {
      info!(
        "shorthand in output {} wasn't convertible to a RefundableInInstruction: {e:?}",
        hex::encode(output.id())
      );
      return (presumed_origin, None);
    }
  };

  let mut balance = output.balance();
  // Deduct twice the cost to aggregate to prevent economic attacks by malicious miners against
  // other users
  balance.amount.0 -= 2 * N::COST_TO_AGGREGATE;

  (
    instruction.origin.or(presumed_origin),
    Some(InInstructionWithBalance { instruction: instruction.instruction, balance }),
  )
