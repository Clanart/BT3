### Title
Permanent dilution of `vlMGP`/`mWomSV` bonus reward distribution because cooling-down/expired lock amounts are never excluded from `totalStaked()` and can only be removed by the position owner - ([File: wombat/mWomSV.sol], [File: rewards/mWOMSVBaseRewarder.sol], [File: rewards/vlMGPBaseRewarder.sol])

### Summary
`mWomSV`/`VLMGP` lock positions that have entered cooldown (via `startUnlock`) or have already fully cooled down keep their entire weight in `totalAmount` (`mWomSV.totalSupply()`) and in the `masterMagpie` staking record (`balanceOf()`), and they are only ever removed when the position owner personally calls `unlock()`. Because `mWOMSVBaseRewarder`/`vlMGPBaseRewarder` use these same, unadjusted values as the denominator (`totalStaked()`) for bonus-reward accrual, every stale (matured but un-withdrawn) position keeps diluting the `rewardPerTokenStored` growth that genuinely locked users receive, for as long as the owner chooses not to call `unlock()`. Unlike the referenced `BondNFT` report, there is no permissionless "anyone can release after N days" fallback here, so the dilution has no time bound and cannot be corrected by any other actor.

### Finding Description
`mWomSV.totalAmount` (i.e. `totalSupply()`) is increased on `_lock` and only decreased inside `_unlock`, which is only reachable from the owner-gated `unlock(uint256 _slotIndex)` function: [1](#0-0) [2](#0-1) 

`startUnlock` moves a user's balance into a cooldown slot but never touches `masterMagpie` staking amounts or `totalAmount`: [3](#0-2) 

`mWOMSVBaseRewarder` (and analogously `vlMGPBaseRewarder`) uses the raw, unadjusted `totalSupply()`/`stakingInfo` amount as `totalStaked()`/`balanceOf()` for reward-per-token accrual: [4](#0-3) [5](#0-4) 

The only place where the cooldown state is taken into account is the forfeiture calculation applied at claim time, using `getRewardablePercentWAD`, which reduces what the *individual* claiming account receives but does nothing to the shared `totalStaked()` denominator used for everyone's `rewardPerTokenStored` accrual: [6](#0-5) [7](#0-6) 

This mirrors the `BondNFT` root cause: a position that is no longer "active" (fully matured/cooled down) keeps consuming a full share of the denominator used to compute everyone's proportional bonus reward, so newly distributed rewards are split over an inflated total, permanently shrinking the share genuinely-locked users receive — except that, unlike `BondNFT.release()`, `mWomSV.unlock()`/equivalent VLMGP function is restricted to the position owner (`_checkIdexInBoundary(msg.sender, _slotIndex)`), so no third party can ever force the cleanup.

### Impact Explanation
Every additional day a user leaves a matured/cooling-down position un-withdrawn, all newly queued bonus rewards (`queueNewRewards`/`donateRewards`/`_queueNewRewardsWithoutTransfer`) get divided by an inflated `totalStaked()` that includes stale, non-earning-in-good-faith balances. Genuinely active `vlMGP`/`mWomSV` holders permanently receive a smaller `rewardPerTokenStored` increment for every distribution that occurs while the stale position remains unregistered, and this loss is not automatically fixed since only the position owner can call `unlock()`. This is a protocol-wide, unbounded-duration (well beyond 24 hours, as the owner has no incentive to unlock promptly) loss of yield/bonus rewards for currently active lockers — the theft/freeze of unclaimed yield the scope explicitly calls out as reachable impact.

### Likelihood Explanation
No malicious or privileged action is required — an ordinary wallet holder starts a cooldown via `startUnlock` and simply refrains from calling `unlock()`. Since `getRewardablePercentWAD` decays over time, an attacker gains no direct financial benefit for themselves from delaying, but the collateral damage to other active stakers' bonus reward growth occurs passively and automatically on every subsequent `queueNewRewards`/`donateRewards` call, making the dilution effect certain to occur whenever any lock sits idle post-cooldown, which is a common/expected user behavior (forgetting to withdraw, or waiting for gas/market conditions).

### Recommendation
Exclude cooled-down/matured amounts from `totalStaked()` (or equivalently from the `masterMagpie` staking record) as soon as the cooldown period ends, rather than only at explicit `unlock()`, and/or add a permissionless "anyone can finalize an expired cooldown slot" path (analogous to `BondNFT`'s 7-day open release) so stale weight cannot indefinitely dilute active lockers' bonus reward accrual.

### Proof of Concept
1. User A locks `X` mWOM into `mWomSV`/vlMGP; `totalAmount` includes `X`.
2. User A calls `startUnlock(X)`, moving `X` into a cooldown slot; `totalAmount`/`masterMagpie` staking record are untouched (`wombat/mWomSV.sol:247-277`).
3. Cooldown period fully elapses; user A never calls `unlock()`.
4. Manager repeatedly calls `queueNewRewards`/`donateRewards` on `mWOMSVBaseRewarder`/`vlMGPBaseRewarder`; each call computes `rewardInfo.rewardPerTokenStored += amountReward * 1e18 / totalStaked()` where `totalStaked()` still includes user A's stale `X` (`rewards/mWOMSVBaseRewarder.sol:138-149,305-328`).
5. Genuinely locked users (whose balance never left `totalStaked()`) receive a permanently smaller `rewardPerTokenStored` increment per distribution than they would if `X` had been excluded, for as long as user A withholds calling `unlock()` — indefinitely, since no other account can force it.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

            revert UnlockedAlready();

        address[][] memory mWomSVrewards = new address[][](1);
        lps[0] = address(this);
        IMasterMagpie(masterMagpie).multiclaimFor(lps, mWomSVrewards, msg.sender);

        uint256 unlockedAmount = slot.amountInCoolDown;
        _unlock(unlockedAmount);

        slot.amountInCoolDown = 0;
        IERC20(mWOM).safeTransfer(msg.sender, unlockedAmount);

        emit Unlock(msg.sender, block.timestamp, unlockedAmount);
    }

        uint256 forfeitAmount = _amount - rewardableAmount;

            forfeitAmount = 0;
