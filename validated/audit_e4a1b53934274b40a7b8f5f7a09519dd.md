## Title
GitHub Desktop leaks the Git-credential trampoline session (token + port) to untrusted repository hooks, enabling credential/token exfiltration - (File: `app/src/lib/git/core.ts`, `app/src/lib/trampoline/trampoline-environment.ts`, `app/src/lib/hooks/hooks-proxy.ts`)

### Summary
The external report's core invariant is: an untrusted, attacker-influenced execution path (a token transfer triggered during an external call) is not isolated from the privileged state-mutating operation (fee accounting), so the untrusted code can re-enter and repeat the privileged operation. The Desktop analog is that the **Git hook execution environment is not isolated from Desktop's privileged credential-trampoline session**. Every `git` invocation made through `git()`/`spawnGit` is wrapped with `withTrampolineEnv`, which injects `DESKTOP_PORT` and `DESKTOP_TRAMPOLINE_TOKEN` into the *entire process environment* of the spawned git command [1](#0-0) [2](#0-1) . Git hooks (`pre-commit`, `post-checkout`, `post-merge`, `pre-push`, etc.) run as native child processes of that same `git` invocation and, by normal OS process semantics, inherit that full environment — including the trampoline token/port — unless the (opt-in, per-command) hook-interception feature is both enabled and applicable to that hook [3](#0-2) . This lets an attacker-controlled hook connect directly to the local trampoline server and issue arbitrary `AskPass`/`CredentialHelper` trampoline commands, which resolve into the user's real GitHub credentials.

### Finding Description
`withTrampolineEnv` sets `DESKTOP_PORT`, `DESKTOP_TRAMPOLINE_TOKEN`, `GIT_ASKPASS`, and a `GIT_CONFIG_PARAMETERS` pointing `credential.helper` at Desktop, for every git command that Desktop runs (clone, fetch, push, pull, commit, merge, checkout, etc.) [4](#0-3) . These values are merged directly into the environment object passed to `dugite`'s `exec`/`spawn` in `core.ts`/`spawn.ts` [1](#0-0) [5](#0-4) , i.e. on the *whole* git process tree, not on a narrow sub-invocation.

Git hooks are executed by the `git` binary itself as ordinary child processes and inherit that process's environment. Desktop's hook-interception mechanism (`withHooksEnv`/`hooks-proxy.ts`), which deliberately filters environment variables down to a `GIT_`/`GITHEAD_` allow-list and explicitly excludes `GIT_ASKPASS`/`GIT_SSH_COMMAND` before handing them to a hook subprocess [6](#0-5) [7](#0-6) , is only applied when `opts.interceptHooks` is set by the caller **and** `getHooksEnvEnabled()` is true [3](#0-2) . `interceptHooks` is only wired up in `commit.ts`, `merge.ts`, `pull.ts`, and `push.ts`, and is disabled entirely unless the user has turned on "Load Git hook environment variables from shell" in preferences [8](#0-7) . For every other command (`clone.ts`, `checkout`, `reset`, `fetch`, etc.) and for the default configuration, hooks execute **natively**, with the trampoline token and port passed through unfiltered.

The trampoline server itself only validates a connecting client by matching the shared token (`DESKTOP_TRAMPOLINE_TOKEN`), not by verifying that the caller is genuinely `git` performing an askpass/credential-helper request rather than an arbitrary hook script [9](#0-8) . Once a process holds the token, it can issue a `CredentialHelper` `get` command; `createCredentialHelperTrampolineHandler` will call `getGitHubCredential`, which matches by URL **origin only** against the user's signed-in accounts and returns the real OAuth/PAT token in the credential response [10](#0-9) [11](#0-10) . Because the attacker chooses the `url`/`host`/`protocol` values sent in the fake credential request, they can simply ask for `github.com` credentials regardless of what repository or remote is actually in use.

This exactly mirrors the reentrancy bug class: the privileged "transfer" (returning/using the OAuth token) is reachable from an execution context (a hook, analogous to the token-callback in `collectFees`) that was never meant to have that access, because no guard scopes trampoline access to the legitimate git-invoked askpass/credential-helper call.

### Impact Explanation
A hook that runs during any Desktop-initiated git operation on a repository the user has cloned/fetched (post-checkout, post-merge, pre-commit, pre-push, etc., which Desktop lets run for "trusted" directories per the safe-directory check [12](#0-11) ) can connect to the local trampoline server and request the user's actual GitHub OAuth/PAT token for `github.com`/GHE, or any generic stored credential, entirely outside of Desktop's own git transport. This is credential/token exfiltration — a High-severity, directly attacker-actionable outcome, matching the "drain tokens" impact class of the source report.

### Likelihood Explanation
Requires only that the user clone/open/interact with a malicious repository that ships a working, executable hook (or that the repository is a "trusted"/already-approved directory) and that Desktop perform any git operation on it (clone/fetch/checkout/commit/merge/pull/push all qualify since they all go through `git()`/`spawnGit` and `withTrampolineEnv`). No local access, admin rights, or pre-existing malware is needed — the attacker only needs the victim to add/use their repository, which is exactly the "attacker-controlled cloned/fetched repository" trust boundary called out as valid impact.

### Recommendation
- Strip `DESKTOP_PORT`, `DESKTOP_TRAMPOLINE_TOKEN`, and any other Desktop-internal trampoline variables from the environment that git hands to hook subprocesses by default (not only when the opt-in hook-interception feature is enabled), the same way `hooks-proxy.ts` already does for the intercepted path.
- Alternatively/additionally, scope the trampoline token to the specific command context (askpass vs credential-helper) and require the connecting process to prove it is the actual git askpass/credential invocation (e.g., via a one-shot, per-invocation nonce that's consumed and invalidated after first use, and never exposed to child/hook processes), rather than a single long-lived token shared by the entire process environment.

### Proof of Concept
1. Attacker publishes a repository containing an executable hook, e.g. `hooks/post-checkout` (delivered via a repo the victim is asked to clone and later marks as trusted, or via `core.hooksPath` pointing at repo content where applicable):
```sh
#!/bin/sh
# runs as a child of the `git` process Desktop spawned, inherits its env
python3 - <<'EOF'
import os, socket
port = os.environ["DESKTOP_PORT"]
token = os.environ["DESKTOP_TRAMPOLINE_TOKEN"]
s = socket.create_connection(("127.0.0.1", int(port)))
# Speak the trampoline protocol used by desktop-trampoline.c:
# send DESKTOP_TRAMPOLINE_IDENTIFIER=CREDENTIALHELPER, token, args=["get"],
# stdin body: protocol=https\nhost=github.com\n\n
# receive back username=<login>\npassword=<real OAuth token>
...
EOF
```
2. Victim performs any Desktop git operation on this repository (checkout, pull, commit, merge). Desktop's `git()` call sets `DESKTOP_PORT`/`DESKTOP_TRAMPOLINE_TOKEN` on the whole process [2](#0-1) , git executes the hook as a child, inheriting them.
3. The hook connects to the trampoline server and issues a `CredentialHelper get` request for `host=github.com`. `getCredential` → `getGitHubCredential` finds the signed-in account by origin match and returns `username`/`password` (the real token) [13](#0-12) [11](#0-10) .
4. The hook exfiltrates the returned token to an attacker server.

```typescript
export async function withTrampolineEnv<T>(
  fn: (env: object) => Promise<T>,
  path: string,
  isBackgroundTask = false,
  customEnv?: Record<string, string | undefined>
): Promise<T> {
  const sshEnv = await getSSHEnvironment()

  return withTrampolineToken(async token => {
    isBackgroundTaskEnvironment.set(token, isBackgroundTask)
    trampolineEnvironmentPath.set(token, path)

    const existingGitEnvConfig =
      customEnv?.['GIT_CONFIG_PARAMETERS'] ??
      process.env['GIT_CONFIG_PARAMETERS'] ??
      ''

    const gitEnvConfigPrefix =
      existingGitEnvConfig.length > 0 ? `${existingGitEnvConfig} ` : ''

    // The code below assumes a few things in order to manage SSH key passphrases
    // correctly:
    // 1. `withTrampolineEnv` is only used in the functions `git` (core.ts)
    // 2. Those two functions always thrown an error when something went wrong,
    //    and just return a result when everything went fine.
    //
    // With those two premises in mind, we can safely assume that right after
    // `fn` has been invoked, we can store the SSH key passphrase for this git
    // operation if there was one pending to be stored.
    try {
      return await fn({
        DESKTOP_PORT: await trampolineServer.getPort(),
        DESKTOP_TRAMPOLINE_TOKEN: token,
        GIT_ASKPASS: '',
        // This warrants some explanation. We're configuring the
        // credential helper using environment variables rather than
        // arguments (i.e. -c credential.helper=) because we want commands
        // invoked by filters (i.e. Git LFS) to be able to pick up our
        // configuration. Arguments passed to git commands are not passed
        // down to filters.
        //
        // We're using the undocumented GIT_CONFIG_PARAMETERS environment
        // variable over the documented GIT_CONFIG_{COUNT,KEY,VALUE} due
        // to an apparent bug either in a Windows Python runtime
        // dependency or in a Python project commonly used to manage hooks
        // which isn't able to handle the blank environment variables we
        // need when using GIT_CONFIG_*.
        //
        // See https://github.com/desktop/desktop/issues/18945
        // See https://github.com/git/git/blob/ed155187b429a/config.c#L664
        GIT_CONFIG_PARAMETERS: `${gitEnvConfigPrefix}'credential.helper=' 'credential.helper=desktop'`,

        GIT_USER_AGENT: await GitUserAgent(),
        ...sshEnv,
      })
```

```typescript
export async function withHooksEnv<T>(
  fn: (env: Record<string, string | undefined> | undefined) => Promise<T>,
  path: string,
  opts: IGitExecutionOptions | undefined
): Promise<T> {
  if (!opts?.interceptHooks || !getHooksEnvEnabled()) {
    return fn(opts?.env)
  }

  const hooks = await Array.fromAsync(getRepoHooks(path, opts.interceptHooks))

  if (hooks.length === 0) {
    return fn(opts?.env)
  }
```

```typescript
export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
```
