### Title
Bid tx gas fee cap/tip cap are derived from the target transaction, not from the searcher's signed `MaxGasPrice`, silently dropping the KIP-249 v3 slippage-protection field - ([File: kaiax/auction/impl/getter.go])

### Summary
The auction bid struct (`auction.BidData`) carries an EIP-712–signed `MaxGasPrice` field, introduced specifically for v3.0 (`AuctionVersionV3`) auctions to cap how much gas price a searcher is willing to pay for their bid transaction — the auction analog of "slippage protection" against a dynamically changing base fee (KIP-71/Magma). However, `GetBidTxGenerator` — which builds and signs the actual `BidTx` submitted on-chain — never reads `bid.MaxGasPrice`. Instead it copies `GasFeeCap`/`GasTipCap` from the *target* transaction being bid on.

### Finding Description
`BidData.MaxGasPrice` is defined and is part of the EIP-712 typed-data hash for v3 bids (`auctionTypeV3` includes `maxGasPrice`), and is round-tripped through the RPC API (`BidInput.MaxGasPrice` in `kaiax/auction/impl/api.go`) and through `EncodeAuctionCallData`/`DecodeAuctionCallData` (`blockchain/system/auction.go`), which pass it into the v3 contract call (`contractsv3.IAuctionEntryPointAuctionTx.MaxGasPrice`). [1](#0-0) [2](#0-1) [3](#0-2) 

The searcher signs this value expecting it to bound the actual gas price of the resulting `BidTx` — analogous to `mintWithBudget`'s intent of bounding cost against a mechanism (there, `calculateMintPrice()`; here, KIP-71's dynamically-updated `NextMagmaBlockBaseFee`) that can move between signing time and inclusion time.

Instead, when the node actually constructs the `BidTx` to submit on-chain, `GetBidTxGenerator` sets `GasFeeCap`/`GasTipCap` from the target transaction `tx` (the transaction the bid piggybacks on), completely ignoring `bid.MaxGasPrice`: [4](#0-3) 

There is no validation anywhere in `BidPool.validateBid` (`kaiax/auction/impl/bid_pool.go`) that checks `bid.MaxGasPrice` against the pool's current/next base fee before admission, and no use of `MaxGasPrice` in `insertBid` either — it is stored purely as signed metadata and forwarded to the on-chain entry-point contract, but the client-side `BidTx` that the node itself constructs and pays gas for is priced according to the target tx's fee cap, not the searcher's declared maximum. [5](#0-4) 

### Impact Explanation
Because the locally generated `BidTx` fee cap tracks the target transaction's `GasFeeCap`/`GasTipCap` rather than the signed `MaxGasPrice`, a searcher's declared price ceiling is not enforced by the code path that actually spends KAIA on their behalf (the bid-tx generator funds/pays gas via the lending mechanism described in `kaiax/gasless`-style flows, and in auction the winning bid's execution/gas is drawn from the searcher's bid or lender balance). If the target transaction's fee cap is high (or is manipulated/chosen by an unrelated party) at the time the bid wins, the resulting `BidTx` can be built and broadcast with a gas price exceeding what the searcher explicitly capped and signed for in `MaxGasPrice`, defeating the entire purpose of the v3 field. This is a fee-delegation/fee-abuse class issue reachable by any auction bidder using v3 bids: the value they explicitly bounded via signature is not honored by the state-transition/tx-construction logic, resulting in unauthorized value movement (excess gas expenditure) relative to what they authorized.

### Likelihood Explanation
This triggers on every v3 (`AuctionVersionV3`) winning bid whenever the target transaction's `GasFeeCap`/`GasTipCap` differs from (particularly exceeds) the bidder's signed `MaxGasPrice` — a routine, easily reachable condition since bidders target arbitrary third-party transactions with independently chosen gas prices, and no code path cross-checks the two values before building/signing the `BidTx`.

### Recommendation
In `GetBidTxGenerator` (`kaiax/auction/impl/getter.go`), when `bid.MaxGasPrice` is set (v3 bids), cap the generated `BidTx`'s `GasFeeCap`/`GasTipCap` at `bid.MaxGasPrice` (e.g., `min(tx.GasFeeCap(), bid.MaxGasPrice)`), and add a `BidPool.validateBid` check rejecting bids whose current network base fee already exceeds `bid.MaxGasPrice`, so the searcher's signed slippage bound is actually enforced end-to-end.

### Proof of Concept
1. A searcher submits a `Bid` via `auction_submitBid` with `MaxGasPrice = 10 gwei` on a v3 auction entry point, targeting `TargetTx` whose own `GasFeeCap = 100 gwei`.
2. The bid passes `validateBid` (`kaiax/auction/impl/bid_pool.go:345-395`), which never inspects `MaxGasPrice`.
3. When the target tx is picked up in block building, `GetBidTxGenerator` (`kaiax/auction/impl/getter.go:49-59`) constructs `BidTx` with `GasFeeCap = tx.GasFeeCap() = 100 gwei`, `GasTipCap = tx.GasTipCap()`, ignoring the searcher's signed 10 gwei cap.
4. `BidTx` is signed and submitted paying up to 10x the price the searcher explicitly authorized, contradicting the v3 EIP-712 signed intent captured in `auctionTypeV3`.

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}
