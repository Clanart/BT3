## Confirmed

This is a global public constant, `create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))` with no signature/authority requirement [1](#0-0) . Anyone can create a coin with this puzzle hash and attach `CREATE_COIN` memos containing an arbitrary `launcher_id` and arbitrary URL strings, extracted verbatim by `get_mirror_info()` [2](#0-1) .

`DataLayerWallet.coin_added()` accepts *any* mirror coin as long as its embedded `launcher_id` happens to match a store the local wallet is already tracking — with no check that the mirror coin's creator is the store owner or has any relationship to the singleton — and stores the attacker-supplied `urls` verbatim into `dl_store` [3](#0-2) . These URLs then flow: `DataLayer.update_subscriptions_from_wallet()` reads mirrors and passes their raw URLs into `data_store.subscribe()` [4](#0-3) ; `fetch_and_validate()` then randomly selects one of these server URLs and calls `insert_from_delta_file()` [5](#0-4) , which calls `download_file()` → `http_download()`, issuing an unauthenticated `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` request with **zero validation of the target host** (no loopback/private/link-local/metadata-address blocking anywhere in `chia/data_layer/`) [6](#0-5) .

I was unable to find any redirect-target revalidation logic either (aiohttp follows redirects by default and this code doesn't disable/re-check them), consistent with the report's core bug class (unchecked redirect/attacker-controlled fetch target). I could not fully verify whether `is_launcher_tracked()` requires local ownership vs. mere subscription tracking — this determines whether the victim needs to have run `dl_track_new`/subscribed to the store first (likely, given DataLayer's design), which is a plausible but not extraordinary precondition for a Data Layer client.

### Title
Unauthenticated on-chain mirror coins let any spend-bundle submitter inject attacker-controlled URLs that the DataLayer service fetches (SSRF) - (File: `chia/data_layer/data_layer_wallet.py`)

### Summary
`DataLayerWallet.coin_added()` treats any coin matching the public, non-owner-specific `MIRROR_PUZZLE_HASH` as an authoritative mirror record for whatever `launcher_id` is embedded in its memos, with no verification that the creator is the DataLayer store owner. Because any wallet can spend any coin to create a `CREATE_COIN` output to that puzzle hash with arbitrary memos, an unprivileged spend-bundle submitter can inject arbitrary URLs (`http://127.0.0.1:<port>/...`, `http://169.254.169.254/...`, internal RPC ports, etc.) as "mirrors" for a store id that a victim DataLayer node is tracking/subscribed to.

### Finding Description
1. `create_mirror_puzzle()` is a fixed puzzle with no ownership binding [1](#0-0) ; anyone submitting a spend bundle can create a coin with this puzzle hash.
2. `get_mirror_info()` extracts `launcher_id` and `urls` purely from the `CREATE_COIN` condition memos of that coin's parent spend, with no cryptographic tie to the DataLayer singleton owner [2](#0-1) .
3. `DataLayerWallet.coin_added()` records this as a trusted `Mirror` for `launcher_id` as long as that launcher is "tracked" locally, without checking that the coin's spender owns or controls the corresponding singleton [3](#0-2) .
4. `DataLayer.update_subscriptions_from_wallet()` / `data_store.subscribe()` propagate these attacker URLs into the store's active server list with no scheme/host validation [4](#0-3) .
5. `fetch_and_validate()` picks one of these servers and triggers `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs an outbound `aiohttp` GET to `server_info.url + "/" + filename` with no destination-address validation (no rejection of loopback/private/link-local/metadata ranges) [6](#0-5) [5](#0-4) .

This mirrors the reported bug class: a network-facing fetch client that trusts an externally/attacker-influenced URL without validating the resolved destination before issuing the request.

### Impact Explanation
An attacker with no special privileges (any wallet able to submit a spend bundle) can cause a victim's DataLayer/full-node host to issue outbound HTTP requests to arbitrary internal/loopback/cloud-metadata addresses reachable from that host, and the response content (up to `max_delta_file_size`) is written to disk and parsed as delta-file content by `insert_into_data_store_from_file()`. Even absent successful parsing, this is a confirmed SSRF sink permitting probing/exfiltration of internal network services and metadata endpoints reachable from the node — satisfying the "coin-set divergence" adjacent impact category is not applicable here, but the SSRF/network-boundary-bypass impact class directly matches the analog report.

### Likelihood Explanation
Likelihood is high for any deployment running the DataLayer service with active subscriptions: creating a mirror coin with attacker-chosen memos requires only a standard spend bundle with a `CREATE_COIN` condition to `MIRROR_PUZZLE_HASH`, which is fully unprivileged and requires no interaction with the store owner.

### Recommendation
- In `DataLayerWallet.coin_added()`, only accept/track mirror coins whose parent spend's spender key or authorization matches the DataLayer singleton owner for `launcher_id`, or otherwise cryptographically bind mirror creation rights to store ownership.
- Independently, add destination validation (resolve and reject loopback/private/link-local/multicast/metadata addresses, and re-validate redirect targets) in `chia/data_layer/download_data.py::http_download()` before issuing any request to a mirror-supplied URL, regardless of the ownership fix above (defense in depth).

### Proof of Concept
1. Victim runs `chia data_layer` and subscribes/tracks `launcher_id L` (via `dl_track_new`/subscribe).
2. Attacker (any wallet, unprivileged) submits a spend bundle whose spend creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` and `CREATE_COIN` memos `[L, b"http://127.0.0.1:<victim-internal-port>"]` (or a cloud metadata / internal-service address).
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` stores this as a `Mirror` for `L` (`chia/data_layer/data_layer_wallet.py:775-800`).
4. On the next `update_subscriptions_from_wallet()`/`periodically_manage_data()` cycle, the victim's DataLayer service adds the attacker URL to `data_store` subscriptions and, during `fetch_and_validate()`, issues an HTTP GET to that attacker-chosen address via `http_download()` (`chia/data_layer/download_data.py:298-324`), with no host/IP validation.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
