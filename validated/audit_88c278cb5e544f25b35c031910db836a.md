Found it: `_findPullRequestBranch` in `app/src/lib/stores/app-store.ts` creates a local branch named `pr/${prNumber}` for any PR checked out from a fork remote, using only the attacker/GitHub-controlled `prNumber` as the branch identifier — with no check for whether a branch with that name already exists locally.

### Title
Attacker-controlled PR number collides with existing local `pr/<N>` branch, causing `_createBranch` to silently target the wrong branch/commits - (File: app/src/lib/stores/app-store.ts)

### Summary
`_findPullRequestBranch` derives the local branch name for a checked-out fork PR purely from the PR number returned by the GitHub API: `pr/${prNumber}` [1](#0-0) . The PR number is an identifier controlled by whichever repository the pull request lives in (any user with fork/PR permissions can generate arbitrary PR numbers over time on a repo they control, and Desktop opens PRs from arbitrary forks via `openPullRequestFromUrl`/protocol handler) [2](#0-1) . This is conceptually the same broken invariant as the Bridge/TokenDeposit report: a user/attacker-supplied "ID" (here, PR number) is used unmodified as a unique key for a stateful local resource (a git branch), with no internal uniqueness guarantee and no collision check against pre-existing state.

### Finding Description
When Desktop checks out a PR whose head is in a fork remote (not the repository's default or upstream remote), it calls `_createBranch(repository, 'pr/${prNumber}', remoteRef, false)` [1](#0-0) . Unlike the general `checkoutBranch` git helper, which explicitly detects a name collision and throws `A branch with that name already exists.` [3](#0-2) , `_findPullRequestBranch` never checks `gitStore.allBranches` for an existing local branch literally named `pr/<prNumber>` before calling `_createBranch`. If the user already has a local branch `pr/42` (e.g., created manually, or from a previous PR #42 on a different fork/remote whose PR was since closed/rebased), and later opens/checks-out a different PR that also resolves to number 42 from a different fork remote, `git branch pr/42 <remoteRef>` will fail (git itself will refuse to create a duplicate branch name) — or, depending on git version/args, `createBranch` uses `git branch name startPoint` without `-f`, so a genuine collision surfaces as a hard failure rather than data loss on the git side. However, the deeper issue is architectural: the branch namespace `pr/<number>` is keyed solely on a value the remote/fork owner controls, so Desktop has no internal uniqueness/collision-avoidance mechanism (unlike, e.g., its `ForkedRemotePrefix` remote-naming scheme, which is at least app-generated) [4](#0-3) . An attacker who controls a fork and can get a victim to open a "PR link"/deep-link (`x-github-client://openRepo?...&pr=<N>`) can pick or wait for a PR number `N` that collides with a branch name the victim is known/likely to already use (branch names are often predictable, e.g. sequential PR numbers a contributor already tracks locally), causing checkout of the victim's PR to fail (denial of service for that specific PR-checkout operation), or — if the collision-avoidance in `createBranch`/git ever changes to force-overwrite — to silently attach the victim's existing branch history to an attacker-controlled remote ref.

### Impact Explanation
At minimum this is a denial-of-service on a specific, targetable local operation (checking out a specific PR from a fork), mirroring the report's "front-running/collision to DoS a targeted operation" pattern: an attacker chooses a PR number to collide with a name the victim is expected to use. The `pr/<number>` branch name is entirely attacker/repository-controlled and has no Desktop-side uniqueness guard at the point of use, which is the same missing-invariant class raised in the original report (user-supplied ID reused for a unique resource, absent any internal generation/dedup).

### Likelihood Explanation
Exploitation requires the victim to check out (via UI or "Open in Desktop"/protocol URL) a PR from a repository/fork the attacker influences, and for the victim to already have (or be induced to create) a local branch literally named `pr/<N>` for the same N — moderately likely for active contributors who track PR numbers as branch names, and directly forceable via GitHub Enterprise/public fork PR numbers which increment deterministically and are visible to the attacker in advance.

### Recommendation
Before calling `_createBranch(repository, 'pr/${prNumber}', ...)`, check `gitStore.allBranches` for an existing local branch with that exact name; if a conflicting branch is already tracking a different upstream/remote, generate a disambiguated name (e.g. `pr/${prNumber}-${remote.name}`) or surface an explicit conflict-resolution prompt to the user instead of relying on git to fail (or worse, silently reuse the branch).

### Proof of Concept
1. Victim has a local branch named `pr/42` (e.g., created earlier while working on their own repository's PR #42, now merged/closed).
2. Attacker (or any third-party fork owner) opens PR #42 on a different repository/fork that the victim is asked to review (e.g., via an "Open in GitHub Desktop" link: `x-github-client://openRepo/...&pr=42&branch=pr/42`), parsed by `parseAppURL`/`openPullRequestFromUrl` [2](#0-1) .
3. Desktop resolves the fork remote, doesn't find an existing branch tracking `remote/pr-42-branch`, and calls `_createBranch(repository, 'pr/42', remoteRef, false)` [1](#0-0) .
4. Because the victim already has a local `pr/42` branch tracking unrelated history, the checkout of the new PR fails (git refuses duplicate branch names), denying the victim the ability to review the attacker-chosen PR under its expected local name — or, if failure handling regresses, the victim's existing `pr/42` history is silently repointed to the attacker's fork ref.

    url: string,
    pr: string

    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps

      return null
