### Title
Unbounded index read in CLVM canonical-encoding check on attacker-controlled puzzle/solution bytes causes an uncaught exception during spend-bundle validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a raw, attacker-supplied CLVM byte buffer (a submitted spend bundle's puzzle reveal / solution bytes) by indexing directly into the buffer at offsets derived from length-prefix bytes read from that same untrusted buffer, without ever checking that the computed offset stays within `len(clvm_buffer)`.

### Finding Description
`is_atom_canonical()` reads the first byte at `offset` and, depending on its high bits, decides a `prefix_len` of 0–5 additional bytes to consume in order to build up `atom_len`: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` performs no bounds check before indexing `clvm_buffer[offset]`. If the buffer ends exactly where a multi-byte atom-length prefix begins (e.g. the last byte is `0xFC`/`0xF8`/etc., which signals a 5/4/3/2/1-byte length prefix, but the buffer has fewer trailing bytes than the prefix requires), the loop indexes past the end of `clvm_buffer`.

The caller, `is_clvm_canonical()`, walks the same untrusted buffer token-by-token and calls `is_atom_canonical()` whenever it encounters a byte `> 0x80`: [2](#0-1) 

The only bounds guard present is `assert clvm_buffer != b""`, which does not protect against a truncated trailing length prefix. In CPython, indexing a `bytes`/`bytearray` past its end raises `IndexError` rather than silently reading adjacent memory — so the direct memory-safety consequence of the original CVE (raw OOB read) does not reproduce verbatim, but the analogous bug class (parsing a malformed/attacker-crafted binary blob with insufficient bounds checking on variable-length headers) is present and produces an unhandled exception deep inside transaction/consensus-adjacent code, rather than a clean validation error.

This function is documented as being used to gate DEDUP-eligible mempool spends (canonical-form CLVM check for solutions/puzzles): [3](#0-2) 

### Impact Explanation
`pre_validate_spendbundle()` only translates `ValueError` (from the Rust `validate_clvm_and_signature`) and `ValidationError` into a clean `MempoolInclusionStatus.FAILED` response: [4](#0-3) 

`FullNode.add_transaction()` mirrors this narrow exception handling, catching only `ValueError` and `ValidationError`; any other exception type propagates out of the coroutine: [5](#0-4) 

The test suite explicitly documents that unexpected exception types are *not* absorbed and are re-raised to the caller, confirming this is the observed/expected behavior for exceptions outside `ValueError`/`ValidationError`: [6](#0-5) 

Because `IndexError` is neither `ValueError` nor `ValidationError`, a spend bundle crafted with a truncated atom length-prefix at the very end of the puzzle reveal or solution buffer would raise an `IndexError` out of the canonical-form check, propagate past the intended error-handling boundary, and crash/interrupt the transaction-processing task for that submission. This is a spend-triggered transaction-processing halt reachable by any unprivileged spend-bundle submitter, matching the accepted impact class in the validation rules.

### Likelihood Explanation
Likelihood is high for reachability: any wallet user, RPC caller, or peer can submit a `SpendBundle` with an arbitrary puzzle reveal/solution byte string; DEDUP eligibility checks are part of ordinary mempool admission for spends attempting to use the dedup fast path, so no special privileges or race conditions are required to reach `is_clvm_canonical()`/`is_atom_canonical()`. Constructing the exact truncated tail byte sequence is straightforward (a handful of specific trailing bytes, no cryptographic material needed).

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before every `clvm_buffer[offset]` access (both the initial read and the length-prefix loop), returning "not canonical" (or raising a well-defined, caught exception type) instead of allowing an `IndexError` to escape. Additionally, either wrap the `is_clvm_canonical`/`is_atom_canonical` call sites in a `try/except` that converts any parsing failure into a normal validation rejection, or broaden the exception handling in `pre_validate_spendbundle()`/`add_transaction()` to safely convert unexpected parsing exceptions from untrusted-buffer processing into `Err.INVALID_SPEND_BUNDLE` rather than letting them propagate.

### Proof of Concept
Construct a `SpendBundle` whose puzzle reveal or solution bytes end with a length-prefix byte that declares more trailing length bytes than actually remain in the buffer, e.g. a buffer ending in `0xFC` (which requires 5 additional prefix bytes) with zero or fewer than 5 bytes following it — mirroring the shape already used in the "overflow atoms" tests but truncated instead of padded: [7](#0-6) 

Submit this bundle through `MempoolManager.pre_validate_spendbundle()` for a coin/path that triggers the dedup-eligibility canonical check; the resulting `clvm_buffer[offset]` access in `is_atom_canonical()` at the truncated tail raises `IndexError`, which is not caught by the `except ValueError` / `except ValidationError` handlers, per the confirmed unhandled-exception behavior in `chia/_tests/core/full_node/test_full_node.py`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```markdown
## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
```

```python
def serialized_atom_overflow(size: int) -> str:
    if size == 0:
        size_blob = b"\x80"
    elif size < 0x40:
        size_blob = bytes([0x80 | size])
    elif size < 0x2000:
        size_blob = bytes([0xC0 | (size >> 8), (size >> 0) & 0xFF])
    elif size < 0x100000:
        size_blob = bytes([0xE0 | (size >> 16), (size >> 8) & 0xFF, (size >> 0) & 0xFF])
    elif size < 0x8000000:
        size_blob = bytes(
            [
                0xF0 | (size >> 24),
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    elif size < 0x400000000:
        size_blob = bytes(
            [
                0xF8 | (size >> 32),
                (size >> 24) & 0xFF,
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    else:
        size_blob = bytes(
            [
                0xFC | ((size >> 40) & 0xFF),
                (size >> 32) & 0xFF,
                (size >> 24) & 0xFF,
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    extra_str = "01" * 1000
    return size_blob.hex() + extra_str
```
