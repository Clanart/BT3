## Title
Nil-pointer dereference panic in legacy EVM precompile error handlers when `state.GetDBImpl` returns nil - ([File: precompiles/pointer/legacy/v552/pointer.go])

### Summary
Multiple legacy, height-gated versions of Sei's EVM precompiles (still compiled into the binary and dispatched at runtime by `x/evm/keeper.Keeper.CustomPrecompiles`/`GetCustomPrecompilesVersions`) contain a deferred error handler that unconditionally dereferences the result of `state.GetDBImpl(evm.StateDB)`:

```go
defer func() {
    if err != nil {
        state.GetDBImpl(evm.StateDB).SetPrecompileError(err)
    }
}()
``` [1](#0-0) 

`GetDBImpl` returns `nil` whenever the supplied `vm.StateDB` is neither a `*state.DBImpl` nor a `*state.HookedStateDB` wrapping one:
```go
func GetDBImpl(vmsdb vm.StateDB) *DBImpl {
	if sdb, ok := vmsdb.(*DBImpl); ok {
		return sdb
	}
	if hdb, ok := vmsdb.(*state.HookedStateDB); ok {
		return GetDBImpl(hdb.StateDB)
	}
	return nil
}
``` [2](#0-1) 

The `Prepare` step already anticipates this and safely checks `ctxer == nil` before returning a plain error ("cannot get context from EVM") in these same legacy files, e.g.:
```go
ctxer := state.GetDBImpl(evm.StateDB)
if ctxer == nil {
    return sdk.Context{}, nil, nil, errors.New("cannot get context from EVM")
}
``` [3](#0-2) 

But once that error propagates back up to `RunAndCalculateGas`/`Run`, the deferred handler re-calls `state.GetDBImpl(evm.StateDB)` on the *same* `evm.StateDB` — which will again be `nil` — and immediately calls `.SetPrecompileError(err)` on it, causing a nil-pointer dereference panic instead of a handled error.

This exact bug-class (crash-on-error caused by calling a helper on a pointer that was never validated for nil on that specific error path) mirrors the reported Linux `gpiochip_get_ngpios()` CVE-2025-21783, where `chip_*()` logging macros dereferenced an uninitialized `gpiodev` pointer on the error path.

### Finding Description
This unguarded pattern (`state.GetDBImpl(evm.StateDB).SetPrecompileError(err)` with no nil check) is present in the deferred error handlers of:
- `precompiles/common/precompiles.go` legacy snapshots (v552, v555, v562, v575, v580, v600, and further duplicated per-precompile legacy trees) [4](#0-3) 
- `precompiles/pointer/legacy/v552/pointer.go` and `v555/pointer.go` [5](#0-4) 
- `precompiles/distribution/legacy/v552/distribution.go` [6](#0-5) 
- `precompiles/wasmd/legacy/v555/wasmd.go` [7](#0-6) 

These legacy packages are not dead code: they are wired into `GetVersioned` maps registered per-address (e.g. `precompiles/pointer/setup.go`, `precompiles/wasmd/setup.go`) and are selected at runtime by `Keeper.GetCustomPrecompilesVersions`/`CustomPrecompiles` based on the historical upgrade height recorded on-chain, when a transaction is executed under `ctx.IsTracing()` (e.g. historical trace/replay/debug RPC calls such as `debug_traceTransaction`, `debug_traceCall`, `debug_traceBlockByNumber`) [8](#0-7) .

The current/latest precompile code (`precompiles/common/precompiles.go`, v610+) has already been hardened with a nil check:
```go
func HandlePrecompileError(err error, evm *vm.EVM, operation string) {
	if err != nil {
		if sdb := state.GetDBImpl(evm.StateDB); sdb != nil {
			sdb.SetPrecompileError(err)
		}
		metrics.IncrementErrorMetrics(operation, err)
	}
}
``` [9](#0-8) 

confirming this is a known/previously-fixed defect class — but the fix was only applied going forward and was never backported into the frozen legacy version snapshots that remain reachable for historical-height execution paths.

### Impact Explanation
If `evm.StateDB` passed into one of these vulnerable legacy precompile calls is not a `*state.DBImpl`/`*state.HookedStateDB` (e.g. during trace/replay/simulation paths that may construct or wrap `vm.StateDB` differently, or any future/alternate StateDB implementation used for historical trace queries), `Prepare` returns a non-nil error and the deferred handler will panic on a nil pointer dereference. Because tracing/debug RPC endpoints (`debug_traceTransaction`, `debug_traceBlockByNumber`, etc.) are part of the default-configuration public JSON-RPC surface and explicitly route through `ctx.IsTracing()` → historical/legacy precompile selection, an attacker able to submit a request whose historical block/tx invoked one of the affected precompile addresses could trigger a crash of the RPC node process serving that request.

### Likelihood Explanation
Exploitability is capped by the specific condition needed to make `GetDBImpl` return `nil`: under the normal transaction execution path, `evm.StateDB` is always constructed as `*state.DBImpl` (or its `HookedStateDB` wrapper) by the EVM keeper, so this is not reachable during ordinary EVM transaction execution. It becomes reachable only through the `ctx.IsTracing()`/version-selection branch when replaying a historical block/tx that used one of the affected legacy precompile addresses and versions, combined with a `vm.StateDB` value that fails the type assertion in `GetDBImpl`. I was unable to fully confirm (due to iteration limits) whether any current, in-repo tracing/simulation code path actually constructs a `vm.StateDB` value that is not a `*DBImpl`/`*HookedStateDB` — this is the missing piece needed to escalate from "theoretically reachable defect" to "concretely triggerable crash." Given that uncertainty, likelihood should be treated as Low-to-Medium rather than confirmed-high.

### Recommendation
Backport the nil-check fix already applied in `precompiles/common/legacy/v614/precompiles.go` (and later versions) into all earlier legacy precompile packages that still contain the unguarded pattern — specifically `precompiles/common/legacy/{v552,v555,v562,v575,v580,v600}/precompiles.go`, `precompiles/pointer/legacy/{v552,v555}/pointer.go`, `precompiles/distribution/legacy/v552/distribution.go`, and `precompiles/wasmd/legacy/v555/wasmd.go` (and audit remaining `legacy/` trees for the same pattern). Replace:
```go
state.GetDBImpl(evm.StateDB).SetPrecompileError(err)
```
with:
```go
if sdb := state.GetDBImpl(evm.StateDB); sdb != nil {
    sdb.SetPrecompileError(err)
}
```

### Proof of Concept
Not independently reproduced within the available tool budget. The mechanical trigger requires calling `RunAndCalculateGas`/`Run` on an affected legacy precompile (`precompiles/pointer/legacy/v552`, `v555`; `precompiles/distribution/legacy/v552`; `precompiles/wasmd/legacy/v555`; or `precompiles/common/legacy/{v552,v555,v562,v575,v580,v600}`) with a `*vm.EVM` whose `StateDB` field is set to any `vm.StateDB` implementation other than `*state.DBImpl`/`*state.HookedStateDB`, which forces `Prepare` to return the "cannot get context from EVM" error and the deferred handler to panic on `nil.SetPrecompileError(err)`. Confirming a live, unprivileged trigger path (e.g. via `debug_traceTransaction` against a historical tx that used one of these precompile addresses/versions) requires further investigation into how the tracing/simulation code paths construct `evm.StateDB`, which I could not complete before the iteration limit.

func (p Precompile) Run(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, value *big.Int, readOnly bool, _ bool, hooks *tracing.Hooks) (bz []byte, err error) {
	operation := fmt.Sprintf("%s_unknown", p.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
	}()
	ctx, method, args, err := p.Prepare(evm, input)
	if err != nil {
		return nil, err
	}

	operation = method.Name
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	bz, err = p.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, hooks)
	if err != nil {
		return bz, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return bz, err
}

		state.GetDBImpl(evm.StateDB).SetPrecompileError(err)

	}
}
