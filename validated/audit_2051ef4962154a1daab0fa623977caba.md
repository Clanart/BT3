### Title
Untrusted `ThresholdKeys` bytes let an attacker declare an arbitrary `group_key`, causing funds to be reported received that are not spendable - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::new` / `ThresholdKeys::read` accept a fully attacker-controlled set of verification shares and derive `group_key` by interpolating only the first `t` of them, without checking that `secret_share * G == verification_shares[i]` for the local participant or that the interpolated shares are mutually consistent. This mirrors the `DaoVesting::claim` bug class: an unauthenticated, externally-supplied object (there, a fake `dao` contract; here, a forged serialized `ThresholdKeys`) is trusted to resolve which assets/keys the system operates on, letting an attacker substitute the identity under which real funds are accounted.

### Finding Description
`ThresholdKeys::read` deserializes `t`, `n`, `i`, the interpolation variant, a `secret_share`, and a map of `n` verification shares entirely from the input bytes, then passes them to `ThresholdKeys::new`. [1](#0-0) 

`ThresholdKeys::new` only validates the *count* of verification shares and that participant indexes are `<= n`. It never checks that the local `secret_share` corresponds to `verification_shares[params.i()]`, and it derives `group_key` exclusively from shares `1 ..= t`:

```rust
let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
let group_key =
  t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();
``` [2](#0-1) 

Because interpolation factors for indexes `1..=t` are public constants (Lagrange) or read straight from the bytes (`Interpolation::Constant`), an attacker can solve for `verification_shares` that interpolate to *any* group key — e.g. the group key of a real Serai multisig whose Bitcoin address (`p2tr_script_buf(group_key)`) has funds — while supplying a `secret_share` unrelated to those shares.

The `Scanner`/`SignableTransaction` pipeline trusts `group_key()` as the spendable identity: `Scanner::new(key)` / `register_offset` map `key`/`key + offset*G` to script_pubkeys and attribute matching on-chain outputs as `ReceivedOutput`s owned by these keys. [3](#0-2)  Spending is only rejected later, inside `SignableTransaction::multisig`, where `p2tr_script_buf(offset.group_key())` is compared to the prevout script — a check which *succeeds* for the forged keys since `group_key()` is exactly the attacker-chosen point, producing signature shares that fail `verify_share`/`complete` and a transaction that can never be published. [4](#0-3) 

### Impact Explanation
Funds are reported received (scanned as `ReceivedOutput`s for the forged `group_key`) that are not spendable: the `secret_share` does not correspond to the verification shares, so every signature share fails verification and the multisig can never produce a valid spend. Any accounting/deposit flow built on `ThresholdKeys::read` of untrusted input therefore credits deposits to an unspendable key — the Serai equivalent of the vesting contract transferring real tokens based on an unvalidated `dao` reference. Key/share consistency is a correctness invariant the type itself should enforce at deserialization, like the recommended "validate that the DAO contract is legitimate" fix.

### Likelihood Explanation
Reachable by any unprivileged party able to supply bytes to `ThresholdKeys::read` (explicitly an untrusted-input surface). Exploitation requires only solving a linear system over public interpolation coefficients — no secret material. Impact is bounded to false attribution/unspendability rather than theft (the attacker cannot move the victim key's funds), so severity is Medium.

### Recommendation
In `ThresholdKeys::new`, verify `C::generator() * *secret_share == verification_shares[&params.i()]` so a key set is only accepted if the local share is consistent with the declared verification shares. Additionally, for `t < n`, document or enforce that the group key is well-defined regardless of which `t`-subset signs (e.g., that all `n` shares lie on a consistent polynomial, as guaranteed by PedPoP/dealer flows but not by `read`).

### Proof of Concept
```rust
// Target: a real multisig's group key the victim will scan for
let target_group_key: ProjectivePoint = victim_keys.group_key();

// n = 3, t = 2. Lagrange factors for the set {1,2} evaluated at 0:
//   l1 = 2/(2-1) = 2,  l2 = 1/(1-2) = -1
// Choose V1 = target_group_key/2 (i.e. scalar 2^-1 * G * a for known a, or solve V1 = target - V2 with V2 = G)
// Simplest: V2 = G, V1 = target_group_key - G, so 2*V1... — pick instead:
//   V1 = (target_group_key + G) / 2  is awkward; use Constant interpolation for a trivial solve:
//   Interpolation::Constant(vec![ONE, ONE, ONE]) => group_key = V1 + V2.
//   Set V1 = target_group_key - G, V2 = G, V3 = arbitrary.
```
Serialize a `ThresholdKeys` blob: `C::ID`, `t=2`, `n=3`, `i=1`, interpolation tag `0` with three `ONE` coefficients, `secret_share = random`, `verification_shares = {1: target - G, 2: G, 3: G}`. `ThresholdKeys::read` accepts it, `group_key() == target_group_key`. Feeding these keys to `Scanner::new(group_key)` attributes the victim's outputs to this key set, while `SignableTransaction::multisig(&keys)` passes its script check yet can never produce a valid signature — deposits reported received are unspendable.

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
