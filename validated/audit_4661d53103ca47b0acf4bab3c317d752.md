### Title
Missing `extcodesize` check in `EvmHost.dispatchIncoming(GetResponse)` and `dispatchTimeOut` lets fee payouts and irreversible receipt finalization occur without any code executing at the destination - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly guards against delivering to a destination with no code: it checks `extcodesize(destination)` and, if zero, returns early *before* writing any receipt or moving funds, so the message stays retryable [1](#0-0) . The sibling functions that finalize **GetResponse** and **timeout** delivery — `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` — perform the exact same pattern (resolve an address from request bytes, then `.call()` into it) but contain **no such check** [2](#0-1) [3](#0-2) [4](#0-3) . A Solidity `.call()` into an address with no deployed code always returns `success == true` with empty returndata — the same core defect described in the RocketNodeDistributor report (silent, undetected "success" against an address with no code). Here it causes the host to treat un-executed callbacks as fully "Handled," irreversibly finalizing state and moving fee-token funds.

### Finding Description
`EvmHost` resolves the callback target from attacker/relayer-supplied request bytes via `_bytesToAddress(...)`, then does a low-level `.call()` into it:

- `dispatchIncoming(GetResponse memory response, address relayer)`: writes `_responseReceipts[commitment]` (replay-protection state) *before* the call, then calls `_bytesToAddress(response.request.from)`. If that address has no code, the call trivially succeeds, so the function proceeds to pay `relayer` the `fee` from `_requestCommitments[commitment]` and emits `GetRequestHandled` [2](#0-1) .
- `dispatchTimeOut(GetRequestTimeout, ...)` and `dispatchTimeOut(PostRequestTimeout, ...)`: delete `_requestCommitments[commitment]` (irreversible replay protection) *before* the call, call `_bytesToAddress(timeout.request.from)`, and on trivial success refund `meta.fee` to `meta.sender` and emit the "Handled" event [5](#0-4) .

This is the same broken invariant flagged in the external report: **a call into a target resolved dynamically from storage/state is not gated by an `extcodesize`/existence check**, so "no code executed" is indistinguishable from "successfully executed" at the protocol level. The codebase itself demonstrates the fix is known and used elsewhere:
- `dispatchIncoming(PostRequest, ...)` performs the `extcodesize` check *before* writing any receipt, explicitly to allow retry rather than false-finalize [1](#0-0) .
- `CallDispatcher.dispatch` reverts with `NotContract` if `extcodesize(to) == 0` [6](#0-5) .

The three unguarded functions break with that established pattern. The `from` address embedded in a `GetRequest`/`PostRequest` is fixed at dispatch time to `_msgSender()` of the original `dispatch()` call [7](#0-6) , and `dispatch(DispatchGet)`/`dispatch(DispatchPost)` are unrestricted public entrypoints callable by any EOA or contract [8](#0-7) . Consequently any account — including a plain EOA with no code, or a contract that is later removed/self-destructed/never deployed at the recorded address — can be the `from` on a GET request. When the corresponding `GetResponse` or timeout is later delivered by the (correctly proof-verified) handler, `EvmHost` will still treat the callback as "delivered," irreversibly consume the replay-protection state, and disburse relayer fee-token funds, even though zero application logic ran.

### Impact Explanation
- **Loss of funds**: `IERC20(feeToken()).safeTransfer(relayer, fee)` in the `GetResponse` path and `safeTransfer(meta.sender, meta.fee)` in the timeout paths execute even when the call target has no code, moving real fee-token value based on a false "success" signal rather than genuine callback execution.
- **False state acceptance / no retry path**: For `PostRequest`, a no-code destination causes an early return that leaves the request retryable. For `GetResponse` and both timeout kinds, the destination-has-no-code case is silently treated identically to a genuinely successful callback: the receipt/commitment is finalized (`_responseReceipts` written and kept, `_requestCommitments` deleted) and `GetRequestHandled`/`*TimeoutHandled` is emitted, permanently discarding the message with no way for the app to ever receive or retry it.
- This directly matches the required impact classes: unauthorized/incorrect finalization of cross-chain message state and movement of protocol funds (relayer fee, fee refund) that should be contingent on genuine execution but is not.

### Likelihood Explanation
The path is reachable by any unprivileged account: `dispatch(DispatchGet)` is a public, unrestricted entrypoint, and the resulting `from` field becomes the callback target used later in `dispatchIncoming(GetResponse)`/`dispatchTimeOut`. No relayer/prover/admin compromise is required — only a normal (but non-contract, or later-decommissioned-contract) caller of the standard GET-request flow, combined with the standard (legitimate) relayer delivering the proof through the already-verified handler/consensus path. The `restrict(_hostParams.handler)` modifier only ensures the *handler* invoked these functions with a valid proof — it does nothing to validate that the *destination* of the callback has code, which is exactly the gap.

### Recommendation
Apply the same `extcodesize` guard used in `dispatchIncoming(PostRequest, ...)` and `CallDispatcher.dispatch` to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`: resolve the destination address, check `extcodesize(destination) > 0` *before* writing/deleting any receipt or commitment state, and return early (without finalizing state or transferring fees) if the target has no code — leaving the message in a retryable state exactly as the POST-request path does.

```solidity
address destination = _bytesToAddress(response.request.from);
uint256 size;
assembly { size := extcodesize(destination) }
if (size == 0) {
    // leave state untouched; do not finalize or pay out
    return;
}
```

### Proof of Concept
1. An EOA (or a contract with no code deployed yet / later self-destructed) calls `EvmHost.dispatch(DispatchGet{...})` directly. `EvmHost` records `from = abi.encodePacked(_msgSender())` in the resulting `GetRequest`, per [7](#0-6) , and commits `_requestCommitments[commitment] = FeeMetadata({sender: msg.sender, fee: get.fee})`.
2. A relayer legitimately fetches the destination state and submits a valid `GetResponse` proof through `HandlerV2`, which after verification calls `EvmHost.dispatchIncoming(GetResponse, relayer)` per [2](#0-1) .
3. Inside `dispatchIncoming`, `_responseReceipts[commitment]` is set, then `_bytesToAddress(response.request.from).call(...)` is executed against the EOA/no-code address. Because the target has no code, the EVM `CALL` returns `success = true` with empty returndata.
4. `dispatchIncoming` proceeds past the `if (!success)` branch, transfers `fee` in fee-token to `relayer`, and emits `GetRequestHandled`, even though `onGetResponse` never actually executed any logic.
5. The response is now permanently marked handled (`_responseReceipts` stays set) with no possibility of re-delivery, and the fee-token transfer to the relayer has already occurred based purely on the trivial success of calling an address with no code — the same "extcodesize-missing" failure mode as the RocketNodeDistributor report, now finalizing protocol state and moving funds instead of silently delegate-calling a no-op.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
