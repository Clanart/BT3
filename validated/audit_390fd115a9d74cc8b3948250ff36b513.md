Found a direct local analog: the same "single-step, unrecoverable role transfer" pattern exists in `HostManager.sol`, and it is worse than the reported `MarketFactory` bug because it also destroys the only recovery path (`admin`) in the very same call.

### Title
`HostManager.setIsmpHost` performs an irreversible, single-step host binding that can permanently lock bridge revenue withdrawals - (File: `evm/src/core/HostManager.sol`)

### Summary
`HostManager` is the cross-chain governance relay that lets Hyperbridge (via ISMP `onAccept`) instruct the local `EvmHost` to `withdraw` bridge revenue or `updateHostParams`. The binding between `HostManager` and its `EvmHost` is set exactly once via `setIsmpHost`, which both writes the host address and unconditionally zeroes out the `admin` role in the same call, with no validation of the supplied address and no second-step confirmation.

### Finding Description
`setIsmpHost` is restricted to `_params.admin` and is documented as callable "only once": [1](#0-0) 

There is no check that `hostAddr` is non-zero, is a contract, or actually implements `IHostManager`/matches the `EvmHost` that was deployed to point back at this manager (compare with `DeployIsmp.s.sol`, where `HostManager` is deployed first with `host: address(0)` and then wired up post-hoc): [2](#0-1) 

Once `setIsmpHost` is called with any address other than the intended live `EvmHost`, `_params.admin` is already `address(0)`, so there is no remaining privileged caller who can invoke `setIsmpHost` again — the call is single-step and irrevocable: [3](#0-2) 

All subsequent cross-chain governance actions forwarded from Hyperbridge — `Withdraw` (bridge revenue payout) and `SetHostParam` — are dispatched to `IHostManager(_params.host)`, which now permanently points at the wrong (or unreachable) address: [4](#0-3) 

On the `EvmHost` side, `withdraw` is gated so only the registered `hostManager` may call it, and revenue physically sits in the host contract until that call succeeds: [5](#0-4) 

This is the exact bug class from the external report — a role/address is transferred in one step by whoever currently holds the role, with no validation that the recipient is reachable/correct, and no claim/second-step mechanism to correct a mistake. Here the blast radius is larger: the `MarketFactory` bug only bricked `collectFees`, but a bad `setIsmpHost` call bricks both fee/revenue withdrawal *and* all future `updateHostParams` governance for that chain, permanently, since the only actor who could re-run `setIsmpHost` (`admin`) is wiped in the same transaction.

### Impact Explanation
If `setIsmpHost` is called with an incorrect address (typo, wrong checksum, copy-paste from a different deployment/network, or a not-yet-deployed `EvmHost` placeholder left over from a redeploy), bridge revenue and fee-token balances accumulated in the real `EvmHost` become permanently unwithdrawable via the governance path, and `updateHostParams` can never be pushed cross-chain again for that host. This is a direct, irreversible loss/lock of protocol funds with no recovery mechanism, matching the "loss of funds" / "cross-chain admin effects unreachable" impact categories.

### Likelihood Explanation
`setIsmpHost` is explicitly documented as a one-time bootstrap call meant to be executed manually during deployment to break the `HostManager`/`EvmHost` cyclic dependency, as seen in the deployment script. Any deployment error, script misconfiguration, wrong `HOST_ADDRESS` env var, or executing this against a redeployed/upgraded host without updating the manager reproduces the exact single-step-role-transfer failure mode the external report flags — with no two-step claim/confirm gate to catch the mistake before it becomes permanent.

### Recommendation
Apply the same fix pattern already recommended for `MarketFactory`: make `setIsmpHost` (and ideally the initial `admin` assignment) a two-step process — `admin` proposes the host address, and the proposed `EvmHost` (or a fresh admin key controlled by it) must confirm/claim before `_params.host` is finalized and `_params.admin` is cleared. At minimum, validate `hostAddr != address(0)` and that it is a contract implementing `IHostManager`, and do not zero `_params.admin` in the same call that sets an unverified `_params.host`.

### Proof of Concept
1. Deploy `HostManager` with `HostManagerParams({admin: deployer, host: address(0)})`, per `DeployIsmp.s.sol`.
2. Deploy `EvmHost` and call `host.initialize(params)` with `hostManager = address(manager)`.
3. Deployer intends to call `manager.setIsmpHost(address(host))` but passes a stale/incorrect address (e.g., a previous testnet host address, or a typoed address) — this succeeds because there is no validation.
4. `_params.admin` is now `address(0)`; no account can call `setIsmpHost` again.
5. Hyperbridge later dispatches a `Withdraw` governance POST to `manager`; `onAccept` forwards `IHostManager(_params.host).withdraw(...)` to the wrong address — the real `EvmHost`'s accumulated revenue is never released, permanently, since `withdraw` on the real host can only be invoked by the correctly-registered `hostManager`, and the manager's `host` pointer can never be corrected.

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }

    /**
     * @dev withdraws host revenue to the given address, can only be called by cross-chain governance
     * @param params, the parameters for withdrawal
     */
    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }
