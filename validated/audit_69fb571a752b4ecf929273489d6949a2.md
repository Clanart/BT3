### Title
Non-greedy `<promise>` tag extraction picks the FIRST tag in assistant output, allowing quoted/echoed decoy promise text (from repo/issue content or the plugin's own setup instructions) to falsely satisfy `COMPLETION_PROMISE` and prematurely terminate the Ralph loop - (File: `plugins/ralph-wiggum/hooks/stop-hook.sh`)

### Summary
The Stop hook extracts the promise text with a non-greedy Perl regex `s/.*?<promise>(.*?)<\/promise>.*/$1/s` that always matches the **first** `<promise>...</promise>` occurrence in the assistant's last message, not the model's final/intended completion statement. If any earlier text in that same message contains a decoy or quoted `<promise>` tag whose content equals `COMPLETION_PROMISE`, the loop is judged "complete" and terminated even though the real task is unfinished.

### Finding Description
`stop-hook.sh` reads the last assistant message text (`LAST_OUTPUT`, line 90-95) and runs: [1](#0-0) 
The comment itself acknowledges the extraction "takes FIRST tag" due to the non-greedy `.*?`. This means the extraction is not scoped to the model's actual, final completion declaration - any earlier occurrence of a `<promise>...</promise>` substring in the same message content wins.

Two concrete reachable paths for this text to appear before a legitimate completion tag:
1. **Repo/issue/PR content echoed by the model** - if the model quotes or summarizes untrusted issue/PR text (as instructed in the audit scenario) that happens to contain a `<promise>PHRASE</promise>` string matching `COMPLETION_PROMISE` (e.g. a common phrase like `DONE` or `TASK COMPLETE`), that decoy tag is extracted instead of any real signal.
2. **The plugin's own setup output**, `setup-ralph-loop.sh`, prints the literal instruction text directly containing the tag: [2](#0-1) 
If the model ever echoes/quotes this instruction (a common behavior when restating task instructions) inside a later assistant message, the exact `<promise>$COMPLETION_PROMISE</promise>` substring is present verbatim, and the hook's first-match extraction will pick it up and match, regardless of whether the model intended it as a genuine completion declaration.

No validation exists to ensure the extracted tag is the last one, is the model's own generated statement (not a quotation), or is scoped away from quoted/injected content. The only check performed is a literal string equality on line 123, which the decoy text can trivially satisfy once extracted.

### Impact Explanation
This causes the automation to treat an incomplete or attacker-influenced repository state as "done," stopping the Ralph loop prematurely per the described scoped impact ("automation stops early, causing incomplete/incorrect repo state to be treated as final"). This violates the intended invariant that the loop must not exit until the completion promise is genuinely and deliberately asserted by the model as true.

### Likelihood Explanation
Feasible without special privilege: an attacker only needs to place a `<promise>...</promise>`-shaped decoy string containing (or matching) the configured completion phrase inside content the model is likely to read and echo (issue/PR body, file content, comments). This is heightened by the plugin's own instructional text embedding the exact tag+phrase, making accidental triggering plausible even without adversarial issue content, whenever the model quotes its own instructions.

### Recommendation
Change the extraction to use the **last** occurrence of the tag (e.g. greedy matching or reversing search), and additionally require the promise tag to appear in isolation (e.g. on its own line, not embedded in quoted/code-block content) before comparison. Consider requiring the assistant's final message to consist solely of the promise tag (trimmed) rather than allowing it to be extracted from anywhere in the larger free-text output.

```shellscript
  # Extract text from <promise> tags using Perl for multiline support
  # -0777 slurps entire input, s flag makes . match newlines
  # .*? is non-greedy (takes FIRST tag), whitespace normalized
  PROMISE_TEXT=$(echo "$LAST_OUTPUT" | perl -0777 -pe 's/.*?<promise>(.*?)<\/promise>.*/$1/s; s/^\s+|\s+$//g; s/\s+/ /g' 2>/dev/null || echo "")

  # Use = for literal string comparison (not pattern matching)
  # == in [[ ]] does glob pattern matching which breaks with *, ?, [ characters
  if [[ -n "$PROMISE_TEXT" ]] && [[ "$PROMISE_TEXT" = "$COMPLETION_PROMISE" ]]; then
    echo "✅ Ralph loop: Detected <promise>$COMPLETION_PROMISE</promise>"
    rm "$RALPH_STATE_FILE"
    exit 0
  fi
```
