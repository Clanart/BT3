### Title
`x-github-client://openrepo/...?pr=N` deep link silently adds an attacker-controlled fork remote and fetches it via `_checkoutPullRequest` - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
The C4 report's core invariant is: a component performs a privileged, funds/state-mutating action based on an *ambient* trust signal (`tx.origin`) rather than an explicit, user-verified authorization, and an attacker can manufacture the triggering object (a fake ERC20) that the victim is lured into touching via an untrusted surface (a token swap UI/link). The GitHub Desktop analog is structurally the same shape: an untrusted, attacker-clickable surface (a custom-protocol deep link) supplies a `pr` number and repository `url`; Desktop then trusts a **remote GitHub API response** for that PR (`pullRequest.head.repo.clone_url`) to automatically add a new git remote and fetch from it — without ever showing the user the URL that is about to be added and fetched.

### Finding Description
`parseAppURL` in `app/src/lib/parse-app-url.ts` accepts URLs of the form `x-github-client://openrepo/<url>?pr=<n>&branch=...` and only validates that `pr` is numeric and `branch` matches `pr/\d+` — it performs no validation of the referenced repository or its ownership. [1](#0-0) 

This action flows to `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl`, which calls `appStore.fetchPullRequest(url, pr)` to retrieve the PR object from the GitHub API and then unconditionally uses `pullRequest.head.repo.clone_url` (attacker-controlled if the PR's head repo is a fork owned by the attacker) as the source to checkout: [2](#0-1) 

`_checkoutPullRequest` → `_findPullRequestBranch` in `app-store.ts` then adds a brand-new git remote pointing at that attacker-supplied `clone_url` (if no existing remote matches) and immediately fetches it — all without any confirmation dialog showing the remote URL to the user: [3](#0-2) 

This is the same "confused deputy" pattern as the report: the trusted app (GitHub Desktop) performs a privileged network/remote-modifying operation (`addRemote` + `fetch`) based on data supplied through an untrusted channel (a link the user clicked, whose PR number is attacker-chosen, and whose `head.repo.clone_url` the attacker fully controls by opening the PR from their own fork) rather than requiring explicit, informed user consent to the specific remote URL being added.

### Impact Explanation
Adding an arbitrary remote and fetching from it exposes the user to a malicious git server: a hostile `clone_url` can serve crafted refs/objects, and once fetched, `_findPullRequestBranch` may create a local branch (`pr/<n>`) tracking it. This creates an integrating surface where, if the user later interacts with that branch (checkout, merge, or Desktop's own diff/log rendering), attacker-controlled tree content becomes visible/mergeable inside the user's real repository — this mirrors "silent corruption of what the user commits or pushes" if the user is later steered into merging/pushing that content. It also silently fetches network content from a server chosen entirely by the attacker (SSRF/tracking risk: any HTTPS/git URL the PR's fork points to), without ever disclosing the remote URL to the user.

### Likelihood Explanation
The attack requires only that the attacker: (1) open a pull request against any public repository from a fork they control (trivial, no privilege needed), and (2) send the victim a `x-github-client://openrepo/<base-repo>?pr=<n>` link (e.g., via chat, email, or a compromised webpage) that they click. `possibleProtocols` (including `x-github-client`) is registered as Desktop's default handler on all platforms, so clicking the link launches Desktop and triggers the flow automatically with no additional confirmation step shown to the user before the remote is added and fetched. [4](#0-3) [5](#0-4) 

### Recommendation
Before calling `addRemote`/fetching a PR's `head.repo.clone_url` sourced from a URL-action (as opposed to a PR checked out from within the app's own PR list UI), present the user with an explicit confirmation showing the exact remote URL and owner that will be added/fetched, and require consent. Alternatively, restrict URL-action-triggered PR checkouts to cases where the head repository is the same as, or a previously-trusted fork of, the already-added upstream/origin remotes, and require the standard "Open in Desktop"/clone confirmation dialog for genuinely new remotes exactly like `openOrCloneRepository` already does for the non-PR path (`CloneRepository` popup), rather than silently calling `addRemote` inside `_findPullRequestBranch`.

### Proof of Concept
1. Attacker forks a public GitHub repo (e.g. `github.com/victim/project`) and opens a pull request from `attacker/project:evil-branch` into `victim/project`.
2. Attacker crafts the link: `x-github-client://openrepo/https://github.com/victim/project?pr=<PR_NUMBER>` and sends it to the victim.
3. Victim (who already has `victim/project` open in GitHub Desktop) clicks the link.
4. `parseAppURL` parses it into an `open-repository-from-url` action with `pr` set; `handleAppURL` dispatches it to the renderer. [6](#0-5) 
5. `openPullRequestFromUrl` fetches the PR via the API, finds the existing `victim/project` repository, and calls `_checkoutPullRequest` with `pullRequest.head.repo.clone_url` pointing at the attacker's fork. [7](#0-6) 
6. `_findPullRequestBranch` silently runs `addRemote(repository, forkRemoteName, headCloneUrl)` and fetches it, with no dialog ever shown asking the victim to confirm the remote being added. [8](#0-7) 

Note: I could not fully trace what git operations occur after this point (e.g., whether Desktop's UI shows the new remote/branch prominently before any diff or merge action), since deeper UI-level confirmation flows for PR checkouts were not indexed in this session — a Devin session with full repo access would be needed to confirm whether any subsequent UI step mitigates this before the user can act on the fetched content.

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

function handleAppURL(url: string) {
  log.info('Processing protocol url')
  const action = parseAppURL(url)
  onDidLoad(window => {
    // This manual focus call _shouldn't_ be necessary, but is for Chrome on
    // macOS. See https://github.com/desktop/desktop/issues/973.
    window.focus()
    window.sendURLAction(action)
  })
}
