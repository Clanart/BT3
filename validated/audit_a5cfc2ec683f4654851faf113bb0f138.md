### Title
Attacker-created `ReceivedOutput` values can turn the wallet into a signing oracle - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts an offset, `TxOut`, and `OutPoint` without binding the `OutPoint` to a real blockchain output. A caller that deserializes attacker-controlled outputs can therefore be induced to sign a transaction whose input does not exist or whose committed amount is false. [1](#0-0) 

### Finding Description
`ReceivedOutput` is intended to represent a scanner result, with private fields tying a scalar offset to a Bitcoin output and its claimed outpoint. [2](#0-1) 

Normally, `Scanner::scan_transaction` creates that binding by only returning an output after matching its `script_pubkey` to a registered key and recording the actual transaction ID and `vout`. [3](#0-2) 

`ReceivedOutput::read` bypasses that provenance check: it accepts arbitrary scalar bytes followed by arbitrary consensus-encoded `TxOut` and `OutPoint` values. [4](#0-3) 

`SignableTransaction::new` trusts the supplied value and offset, uses the claimed `OutPoint` as the transaction input, and stores the attacker-controlled `TxOut` in `prevouts`. [5](#0-4) [6](#0-5) 

`SignableTransaction::multisig` only verifies that the claimed `prevouts[i].script_pubkey` corresponds to `group_key + offset * G`; it does not verify that `tx.input[i].previous_output` resolves to that `TxOut` on-chain. [7](#0-6) 

The signing path then commits to those forged prevouts through `Prevouts::All` when calculating each Taproot signature hash. [8](#0-7) 

### Impact Explanation
An attacker who knows the wallet's public group key can create a serialized `ReceivedOutput` with offset `0`, the wallet's P2TR script, an arbitrary nonexistent `OutPoint`, and an arbitrary amount. [9](#0-8) [1](#0-0) 

If that value is accepted and spent, the signer produces threshold signature shares—and potentially a complete Schnorr signature—for an attacker-selected transaction and attacker-selected prevout value. The resulting Bitcoin transaction is invalid if the claimed outpoint does not exist, but the wallet has still signed an unintended message. [10](#0-9) 

This is a Medium-severity signing-oracle issue rather than direct theft under Bitcoin consensus rules.

### Likelihood Explanation
Exploitation requires an integration to deserialize `ReceivedOutput` from an untrusted source or otherwise accept attacker-created outputs without confirming their outpoints against the blockchain. The fields are private and the scanner constructor is safe, so applications that only use values returned by `Scanner` are not exposed. [11](#0-10) 

When persisted or network-supplied outputs are used, the attack only needs the victim's public group key and arbitrary serialized bytes, matching the externally reachable `ReceivedOutput::read` path. [1](#0-0) 

### Recommendation
Treat `ReceivedOutput` as authenticated scanner state rather than an untrusted serializable structure. Before calling `SignableTransaction::new` or `multisig`, resolve every `OutPoint`, compare the chain's `TxOut` exactly—including value and `script_pubkey`—and reject mismatches. The `multisig` path should also verify the claimed prevout against a trusted UTXO source rather than relying solely on the script-to-offset check. [7](#0-6) 

### Proof of Concept
```rust
// group_key is the victim wallet's public, even-Y P2TR output key.
let forged_script = p2tr_script_buf(group_key).unwrap();

let forged_txout = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: forged_script,
};

// An outpoint not controlled by the group, or a nonexistent outpoint.
let forged_outpoint = OutPoint::default();

// ReceivedOutput serialization is:
//   Scalar || TxOut consensus encoding || OutPoint consensus encoding.
let mut bytes = Scalar::ZERO.to_bytes().to_vec();
bytes.extend(bitcoin::consensus::serialize(&forged_txout));
bytes.extend(bitcoin::consensus::serialize(&forged_outpoint));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// This accepts the fake value as spendable input value and places the fake
// TxOut in the sighash prevout commitment.
let tx = SignableTransaction::new(
  vec![forged],
  &[(attacker_script, 900_000)],
  None,
  None,
  fee_per_vbyte,
).unwrap();

// This passes because offset 0 and forged_txout.script_pubkey match the
// group key, despite forged_outpoint not resolving to forged_txout.
let machine = tx.multisig(&victim_threshold_keys).unwrap();
```

The resulting signature is calculated over `Prevouts::All`, which contains the forged `TxOut`; this is sufficient to make the wallet sign an unintended Bitcoin sighash. [8](#0-7)
