### Title
Deserialized `ThresholdKeys` bypasses all consistency validation, enabling misattributed blame / unspendable group key - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` deserializes `t`, `n`, `i`, interpolation factors, `secret_share`, and `n` verification shares, then reconstructs via `ThresholdKeys::new`. `ThresholdKeys::new` validates only structural invariants: share count == `n`, participant indexes ≤ `n`, and `t == n` for `Interpolation::Constant`. It never checks the *semantic* invariant that `verification_shares[i] == C::generator() * secret_share`, nor that the `Constant` interpolation coefficients actually interpolate the claimed group key, nor that `secret_share` is non-zero. A crafted serialized object therefore passes every check — the direct analog of the schema-inspector `validate()`/`sanitize()` bypass — while encoding keys that are internally inconsistent.

### Finding Description
`ThresholdKeys::new` checks only `verification_shares.len() == n`, `participant <= n`, and the `Constant`-implies-`t==n` rule [1](#0-0) . It then derives `group_key` purely from `verification_shares[1..=t]` and the interpolation factors [2](#0-1) . `ThresholdKeys::read` performs field/point canonicity checks via `read_F`/`read_G` and `ThresholdParams::new` bounds checks, then hands the data to this same `ThresholdKeys::new` [3](#0-2) . Nothing anywhere binds `secret_share` to `verification_shares[i]` or verifies the shares form a consistent polynomial/commitment set.

The codebase itself acknowledges this gap: `complete()` notes "The only known way to cause this, for valid parameters/algorithms, is to deserialize a semantically invalid FrostKeys" [4](#0-3) .

### Impact Explanation
When such keys enter `AlgorithmSignMachine::sign`/`complete`, `view()` interpolates the bogus share and verification shares normally [5](#0-4) . Two consequences:

- **Misattributed blame:** in `complete()`, the aggregate signature fails `algorithm.verify`, triggering per-share `verify_share` checks that flag the holder's own share as invalid [6](#0-5) . Where shares are routed to blame/slashing (as with PedPoP `InvalidShare`/blame proofs [7](#0-6) ), the holder of the crafted keys is blamed as faulty despite behaving honestly — a validation bypass that transfers fault.
- **Wrong group key accepted:** `group_key()` is fully attacker-controlled through the deserialized `verification_shares`, while `secret_share` is unrelated. Any downstream consumer trusting `group_key()` (e.g., address derivation, `GeneratedKeysDb` keyed on `group_key` [8](#0-7) ) registers a key whose shares cannot produce valid signatures — funds sent to it are received but not spendable.

### Likelihood Explanation
Reachable wherever serialized `ThresholdKeys` cross a trust boundary — `ThresholdKeys::read` is an explicitly in-scope untrusted-bytes sink. In Serai's processor, keys are loaded from a local DB (`read_keys` [9](#0-8) ), so exploitation requires an attacker-controlled serialized key blob reaching `read()` in an integrator or recovery/import path rather than the normal DKG flow — hence Moderate rather than High likelihood. The bypass itself is deterministic once reached: every check succeeds on crafted input.

### Recommendation
In `ThresholdKeys::new` (and thus `read`), assert `C::generator() * *secret_share == verification_shares[&params.i()]`, rejecting zero secret shares. For `Interpolation::Constant`, additionally verify the supplied coefficients have length `n` and are consistent with the shares (e.g., `Σ vs_i * c_i` already defines `group_key`; ensure callers can't supply coefficients that silently differ from what other parties computed, or recompute/verify against a known group key where available).

### Proof of Concept
```rust
// For any ciphersuite C, craft serialized ThresholdKeys where the secret
// share and verification shares are unrelated. All validation passes.
let t: u16 = 2; let n: u16 = 3; let i = 1u16;
let mut buf = vec![];
buf.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
buf.extend(C::ID);
buf.extend(t.to_le_bytes());
buf.extend(n.to_le_bytes());
buf.extend(i.to_le_bytes());
buf.push(1); // Interpolation::Lagrange
let bogus_share = C::F::from(42u64);
buf.extend(bogus_share.to_repr().as_ref());
for _ in 1..=n {
    // Arbitrary verification shares, none equal to G * bogus_share
    buf.extend((C::generator() * C::F::random(&mut OsRng)).to_bytes().as_ref());
}
// Succeeds: every read-time check passes despite semantic inconsistency
let keys = ThresholdKeys::<C>::read(&mut buf.as_slice()).unwrap();
assert!(C::generator() * *keys.original_secret_share()
    != keys.original_verification_share(Participant::new(1).unwrap()));
// Signing with these keys produces shares that fail aggregate verification,
// and blame resolves against the holder of the crafted keys.
```

    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
