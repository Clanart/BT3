Found the confirmed analog. `handle_unsigned` in `modules/pallets/ismp/src/lib.rs` is `#[frame_support::transactional]`, so a whole batch call reverts atomically — but `Pallet::<T>::execute` (`modules/pallets/ismp/src/impls.rs:40-51`) calls `handle_incoming_message` for **each** message via `.map()` and immediately errors the *entire* extrinsic (`Error::<T>::InvalidMessage`) if **any single message** in the batch returns `Err` from `on_accept`. Since `#[transactional]` wraps the whole `handle_unsigned` call, one bad message in a relayer-submitted batch rolls back bandwidth consumption too — so this specific path is safe. However, the router-level protocol documentation itself states the actual danger explicitly: [1](#0-0) 

That is: **the module (not pallet-ismp) is fully responsible for not making irreversible state changes before validating success**, because a `PostRequest` that returns `Err` from `on_accept` gets **no receipt persisted** and can be **replayed** indefinitely until timeout — the reverse-analog to the Kinetiq bug, but pointing at the same root cause: an accounting mutation performed before an operation's success is guaranteed.

### Title
`ProxyModule::on_accept` deducts bandwidth bytes before destination dispatch succeeds, permanently burning paid allowance on forward/dispatch failure - (File: `parachain/runtimes/gargantua/src/ismp.rs`, `parachain/runtimes/nexus/src/ismp.rs`)

### Summary
`ProxyModule::on_accept` calls `BandwidthGate::try_consume` — which mutates the `Allowance` FIFO subscription list and drains paid-for bytes — **before** it knows whether the subsequent forward dispatch (`Ismp::dispatch_request`) or destination-module dispatch (`match pallet_id { ... }`) will succeed. If that later step errors, the function returns `Err`, and per the documented ISMP replay model, **the request receipt is never persisted, so the request is retried on every subsequent relayer submission** — each retry re-runs `try_consume` and drains bytes again from the app's paid subscription, while the underlying message never actually lands. This is structurally identical to the Kinetiq `StakingManager` bug: an accounting balance (buffer / bandwidth bytes) is decremented optimistically in anticipation of a downstream action that has not yet been confirmed, and the decrement is never reverted or refunded when that downstream action fails.

### Finding Description
In `parachain/runtimes/gargantua/src/ismp.rs:375-422` (and the identical pattern in `nexus/src/ismp.rs:361-410`): [2](#0-1) 

The order of operations is:
1. `try_consume(source, from, bytes)` mutates `Allowance::<T>` and drains FIFO subscription bytes — this is a real, non-reversible-by-caller storage write via `pallet::Allowance::<T>::mutate` inside `try_consume` (`modules/pallets/bandwidth/src/lib.rs:509-565`).
2. *After* the gate succeeds, the function either forwards the request (`Ismp::dispatch_request`, which can itself return `Err` e.g. on duplicate commitment per `dispatch_request` in `modules/pallets/ismp/src/impls.rs:90-95`) or dispatches to a destination module lookup that can fail with `"Destination module not found"`.
3. If step 2 fails, `on_accept` returns `Err`.

Per ISMP's documented invariant (`docs/content/protocol/ismp/requests.mdx:111-113`), when `on_accept` returns `Err`, **no request receipt is stored**, meaning the exact same `PostRequest` can be resubmitted by any relayer (this is a permissionless, unsigned extrinsic per `handle_unsigned` in `modules/pallets/ismp/src/lib.rs:373-382`) and reprocessed from scratch — re-entering `ProxyModule::on_accept` and re-draining the bandwidth ledger again on every retry, since the bytes consumed in step 1 of the failed attempt are never restored (there is no compensating credit anywhere in the bandwidth pallet for a downstream-failed request).

This mirrors Kinetiq's flaw exactly: the buffer (accounting resource representing "already paid/available capacity") is spent based on an assumption that a subsequent action will succeed, and there is no reversal path when it doesn't — except here the "loss" compounds because the message is replayable, so an attacker or even a benign relayer retry storm can repeatedly re-invoke the same failing request and drain an app's entire prepaid bandwidth subscription without a single message ever being successfully delivered.

### Impact Explanation
An app that has paid real fee-token value for a bandwidth tier can have its entire prepaid byte allowance destroyed by a request that is destined to permanently fail forwarding or destination dispatch (e.g., a stale/misconfigured `to` module id, or a forward-dispatch collision). Since `handle_unsigned` is permissionless and unsigned (`ensure_none(origin)`), **any actor** can resubmit the same doomed `RequestMessage` repeatedly, draining the victim app's paid bandwidth to zero with no compensating credit — a direct loss of prepaid funds (the bandwidth allowance is the on-chain representation of money already paid via `BandwidthManager.purchase()`).

### Likelihood Explanation
Requires only a `PostRequest` whose `on_accept` fails after the gate check but is otherwise well-formed enough to pass proof verification and reach `ProxyModule::on_accept` — e.g., targeting an unregistered `pallet_id`, or a request whose commitment collides with an existing one on forward. No relayer/prover/admin collusion is needed: submission of `handle_unsigned` is fully permissionless, and the ISMP replay-on-failure design (documented, not incidental) guarantees the same message can be resubmitted indefinitely until timeout, multiplying the drain.

### Recommendation
Reorder the checks in `ProxyModule::on_accept` so the bandwidth gate is only consulted (or its consumption finalized) after the destination `pallet_id` is resolved / forward-dispatch success is confirmed — or add a bandwidth refund path mirroring `force_credit`/`ForceCredited` that restores consumed bytes when the wrapping `on_accept` ultimately errors, analogous to how Kinetiq was advised to either zero the buffer or use `redelegateWithdrawnHYPE` to reconcile stranded funds.

### Proof of Concept
1. App purchases a bandwidth tier via `BandwidthManager.purchase()`, crediting `N` bytes on `pallet-bandwidth`.
2. App (or an attacker impersonating/reusing its `from` address on a chain where `request.from` isn't independently authenticated for non-purchase messages) dispatches a `PostRequest` whose `to` field encodes a `pallet_id` not present in the `match pallet_id {...}` arms of `ProxyModule::on_accept` (e.g., garbage bytes), with `dest == HostStateMachine`.
3. Relayer submits this via `handle_unsigned`. `try_consume` succeeds and drains `bytes` from the app's subscription (`BandwidthConsumed` event fires), then `match pallet_id` falls to `_ => Err(anyhow!("Destination module not found"))`, so `on_accept` returns `Err`.
4. Per `execute()` in `modules/pallets/ismp/src/impls.rs:40-51`, the message result surfaces `Error::<T>::InvalidMessage`, but the request commitment/receipt is never stored (per documented ISMP semantics).
5. Any relayer resubmits the identical `RequestMessage` (same proof still valid, message not marked delivered) — step 3 repeats, draining another `bytes` from the same subscription.
6. Repeat until `Pallet::remaining(app_chain, app)` reaches 0, confirmed via `BandwidthConsumed { remaining: 0 }`, despite zero successful message deliveries — the app's entire paid balance is lost with no event indicating fund loss (unlike `SubscriptionEvicted`, there is no `BandwidthLost`-style event for this path).

impl IsmpModule for ProxyModule {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		// Bandwidth gate. Always-enforce unless the `no-bandwidth` flag
		// is set; skipped for purchase messages so the recharge flow
		// itself doesn't need bandwidth. With the flag on the gate is a
		// no-op and this block is compiled out entirely.
		#[cfg(not(feature = "no-bandwidth"))]
		if !pallet_bandwidth::Pallet::<Runtime>::is_purchase_message(&request) {
			let bytes = ismp::abi::encode_post_request(&request).len() as u32;
			<pallet_bandwidth::Pallet<Runtime> as pallet_bandwidth::BandwidthGate>::try_consume(
				&request.source,
				&request.from,
				bytes,
			)
			.map_err(|err| {
				anyhow!(
					"bandwidth gate: {err} (source={:?}, from={:x?})",
					request.source,
					request.from
				)
			})?;
		}

		if request.dest != HostStateMachine::get() {
			Ismp::dispatch_request(
				Request::Post(request),
				FeeMetadata::<Runtime> { payer: [0u8; 32].into(), fee: Default::default() },
			)?;
			return Ok(Weight::from_parts(0, 0));
		}

		let pallet_id =
			ModuleId::from_bytes(&request.to).map_err(|err| Error::Custom(err.to_string()))?;

		match pallet_id {
			pallet_ismp_demo::PALLET_ID =>
				pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_accept(request),

			#[cfg(not(feature = "no-bandwidth"))]
			id if id == ModuleId::Pallet(pallet_bandwidth::pallet::PALLET_BANDWIDTH) =>
				pallet_bandwidth::Pallet::<Runtime>::default().on_accept(request),

			pallet_hyper_fungible_token::PALLET_ID =>
				pallet_hyper_fungible_token::Pallet::<Runtime>::default().on_accept(request),

			_ => Err(anyhow!("Destination module not found")),
		}
	}
