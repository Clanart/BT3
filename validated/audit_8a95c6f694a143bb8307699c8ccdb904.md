## Title
Tokenfactory `Mint`/`Burn` bypass the bank module's denom allow-list, letting a denom admin move funds to/from unauthorized addresses - (File: `x/tokenfactory/keeper/bankactions.go`)

### Summary
This is the same bug class as the reported `BridgedERC20` issue: a privileged access-control check (there, the blacklist in `_beforeTokenTransfer`; here, the tokenfactory denom `AllowList`) is implemented only in one high-level entry point instead of the shared low-level transfer primitive, so any other caller of that primitive silently bypasses the restriction.

### Finding Description
In sei-chain, `x/bank` supports per-denom allow-lists for tokenfactory denoms via `BaseSendKeeper.IsInDenomAllowList` [1](#0-0) . This check is intended to restrict who may send/receive a tokenfactory denom that has an allow-list configured, as documented in the CLI allow-list flag description [2](#0-1) .

However, the check is only invoked from the `x/bank` `MsgServer.Send` and `MsgServer.MultiSend` handlers: [3](#0-2) [4](#0-3) 

The underlying keeper primitives that actually move balances — `SendCoins`, `SendCoinsFromModuleToAccount`, `SendCoinsFromAccountToModule`, `MintCoins`, `BurnCoins`, `InputOutputCoins` — do **not** perform this allow-list check themselves; it lives purely in the message-server wrapper, exactly like `BridgedERC20`'s `mint`/`burn` not going through the blacklist-checked `_beforeTokenTransfer`.

`x/tokenfactory`, whose `MsgMint`/`MsgBurn` are reachable by any permissionless denom admin (denom creation itself is permissionless per the module README) [5](#0-4) , calls these unchecked primitives directly: [6](#0-5) [7](#0-6) 

`mintTo` calls `bankKeeper.MintCoins` + `SendCoinsFromModuleToAccount`, and `burnFrom` calls `SendCoinsFromAccountToModule` + `BurnCoins` — none of which perform `IsInDenomAllowList`, as confirmed by the `BankKeeper` interface tokenfactory depends on (no allow-list check parameter/usage in these methods) [8](#0-7) . `msgServer.Mint`/`msgServer.Burn` only check that the caller is the denom admin, not the allow-list [9](#0-8) .

### Impact Explanation
An account that is the admin of a tokenfactory denom configured with an `AllowList` (a regulated/permissioned asset) can use `MsgMint` to deposit tokens directly into an address that is **not** in the allow list, or use `MsgBurn` to pull tokens out of a non-allow-listed address, entirely bypassing the access-control guarantee that `MsgSend`/`MsgMultiSend` enforce. This defeats the entire purpose of the denom allow-list feature (compliance/regulatory restriction on token holders) and lets tokens land in or be moved from addresses the allow-list was specifically designed to exclude — an unauthorized-transfer/access-control-bypass condition.

### Likelihood Explanation
High likelihood: any account can permissionlessly create a tokenfactory denom (becoming its admin) and immediately issue `MsgMint`/`MsgBurn` messages; no special privilege beyond being the denom's own admin is required, and the allow-list is meant to apply even to the admin's transfers under the `MsgSend` model.

### Recommendation
Move the `IsInDenomAllowList` enforcement into the shared bank keeper primitives (`SendCoins`, `SendCoinsFromModuleToAccount`, `SendCoinsFromAccountToModule`, `MintCoins`, `BurnCoins`, `InputOutputCoins`) rather than only in the `MsgSend`/`MsgMultiSend` handlers, so every caller — including `x/tokenfactory`, IBC, wasm bindings, and EVM precompiles — is subject to the same restriction.

### Proof of Concept
1. Create a tokenfactory denom with an `AllowList` that excludes address `B` (`MsgCreateDenom` with `allow_list`).
2. As the denom admin, call `MsgMint{Amount: coin, Sender: admin}` which internally calls `mintTo` → `MintCoins` + `SendCoinsFromModuleToAccount` (to the admin) [6](#0-5) .
3. Observe that `SendCoinsFromModuleToAccount`/`SendCoinsFromAccountToModule` never call `IsInDenomAllowList`, unlike `k.msgServer.Send` [3](#0-2) , so an admin-driven mint/burn workflow that routes funds to/from `B` succeeds even though a plain `MsgSend` to/from `B` would be rejected with `ErrUnauthorized`.

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

# Token Factory

The tokenfactory module allows any account to create a new token with
the name `factory/{creator address}/{subdenom}`. Because tokens are
namespaced by creator address, this allows token minting to be
permissionless, due to not needing to resolve name collisions. A single
account can create multiple denoms, by providing a unique subdenom for each
created denom. Once a denom is created, the original creator is given
"admin" privileges over the asset. This allows them to:

- Mint their denom to any account
- Burn their denom from any account
- Create a transfer of their denom between any two accounts
- Change the admin. In the future, more admin capabilities may be added. Admins
  can choose to share admin privileges with other accounts using the authz
  module. The `ChangeAdmin` functionality, allows changing the master admin
  account, or even setting it to `""`, meaning no account has admin privileges
  of the asset.

func (k Keeper) mintTo(ctx sdk.Context, amount sdk.Coin, mintTo string) error {
	// verify that denom is an x/tokenfactory denom
	_, _, err := types.DeconstructDenom(amount.Denom)
	if err != nil {
		return err
	}

	logger.Info("Minting amount for module", "amount", amount, "module", types.ModuleName)
	err = k.bankKeeper.MintCoins(ctx, types.ModuleName, sdk.NewCoins(amount))
	if err != nil {
		return err
	}

	addr, err := sdk.AccAddressFromBech32(mintTo)
	if err != nil {
		return err
	}

	logger.Info("Sending minted amount to addr", "amount", amount, "addr", addr)
	return k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName,
		addr,
		sdk.NewCoins(amount))
}

func (server msgServer) Mint(goCtx context.Context, msg *types.MsgMint) (*types.MsgMintResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// pay some extra gas cost to give a better error here.
	_, denomExists := server.bankKeeper.GetDenomMetaData(ctx, msg.Amount.Denom)
	if !denomExists {
		return nil, types.ErrDenomDoesNotExist.Wrapf("denom: %s", msg.Amount.Denom)
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Amount.GetDenom())
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	err = server.mintTo(ctx, msg.Amount, msg.Sender)
	if err != nil {
		return nil, err
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgMint,
			sdk.NewAttribute(types.AttributeMintToAddress, msg.Sender),
			sdk.NewAttribute(types.AttributeAmount, msg.Amount.String()),
		),
	})

	return &types.MsgMintResponse{}, nil
}

func (server msgServer) Burn(goCtx context.Context, msg *types.MsgBurn) (*types.MsgBurnResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Amount.GetDenom())
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	err = server.burnFrom(ctx, msg.Amount, msg.Sender)
	if err != nil {
		return nil, err
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgBurn,
			sdk.NewAttribute(types.AttributeBurnFromAddress, msg.Sender),
			sdk.NewAttribute(types.AttributeAmount, msg.Amount.String()),
		),
	})

	return &types.MsgBurnResponse{}, nil
}
