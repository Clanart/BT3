### Title
Unbounded WebGL texture allocation from attacker-controlled DDS width/height in diff image preview - ([File: app/src/ui/diff/image-diffs/dds-converter.ts])

### Summary
When GitHub Desktop renders a diff for a `.dds` image file, `convertDDSImage` parses the file with `parse-dds` and feeds the header-derived `width`/`height`/`offset`/`length` values directly into `gl.compressedTexImage2D` and a `Uint8Array` view over the raw blob bytes, with no validation that these values are sane relative to the actual repository blob size or to reasonable texture dimensions. [1](#0-0) 

### Finding Description
`convertDDSImage(contents)` is invoked by `ImageContainer.loadImage` whenever the diff viewer displays an image whose media type is `image/vnd-ms.dds`, and `contents` (an `ArrayBufferLike`) comes straight from `getBlobImage`/`getWorkingDirectoryImage`, which read the full git blob or working-directory file into memory via `getBlobContents`/`readFile` with **no size cap**, unlike the text-diff path which enforces `MaxDiffBufferSize`/`isValidBuffer` before ever touching the buffer. [2](#0-1) [3](#0-2) [4](#0-3) 

Once the raw blob is loaded, `convertDDSImage` trusts the mip-map header fields (`shape` → `imageWidth`/`imageHeight`, and `offset`/`length`) reported by `parse-dds` without any bound check against `contents.byteLength` or a maximum texture size:
```
const ddsData = parseDDS(contents)
const [image] = ddsData.images
const [imageWidth, imageHeight] = image.shape
const imageData = new Uint8Array(contents, image.offset, image.length)
...
canvas.width = width
canvas.height = height
...
gl.compressedTexImage2D(gl.TEXTURE_2D, 0, internalFormat, width, height, 0, imageData)
``` [5](#0-4) 

Because `width`/`height` are attacker-controlled integers taken directly from a file header that ships inside a cloned/fetched repository (a `.dds` blob is exactly the kind of object an attacker fully controls in a malicious repo), an attacker can craft a DDS header declaring an enormous width/height (e.g. tens of thousands of pixels per side) while keeping the actual pixel payload tiny. This forces:
- `canvas.width`/`canvas.height` to be set to attacker-chosen values, causing the renderer to attempt a large 2D canvas backing-store allocation, and
- `gl.compressedTexImage2D` to request GPU texture memory sized by the attacker-controlled `width`/`height`, independent of how much actual compressed data (`image.length`) was supplied.

This is the direct structural analog of the EVM `Memory::copy_large` bug referenced in the report: a size value taken from untrusted input is used to drive an allocation (GPU/canvas memory here, EVM memory there) before the code has verified that the size is actually needed/justified by the available data, allowing a small malicious input to trigger a disproportionately large allocation.

### Impact Explanation
Simply cloning/fetching a repository containing a crafted `.dds` file and viewing its diff in Desktop (which happens automatically when the user opens the Changes/History diff view or in some flows via auto-preview) triggers uncontrolled allocation of canvas/GPU memory sized by attacker-supplied header fields. This can exhaust renderer memory or GPU resources, crashing or hanging the renderer process — a denial-of-service against the Desktop UI triggered purely by viewing a diff of a file the attacker fully controls, with no local access, admin rights, or social engineering beyond having the user open a normal diff.

### Likelihood Explanation
Moderate-to-high: any `.dds` file is auto-detected via extension and rendered by this code path whenever its diff is viewed (`imageFileExtensions`/`getMediaType` map `.dds` to `image/vnd-ms.dds`), and the text-diff size guard (`MaxDiffBufferSize`) does not apply to the image/binary path, so there is no existing throttle on file size or declared texture dimensions before `convertDDSImage` runs. [6](#0-5) 

### Recommendation
Before calling `drawToCanvas`/`gl.compressedTexImage2D`, validate that `imageWidth`/`imageHeight` are within a sane maximum (e.g. matching `gl.getParameter(gl.MAX_TEXTURE_SIZE)` or a fixed cap like 8192×8192) and that `image.offset + image.length <= contents.byteLength`, rejecting/falling back to a "cannot preview" state otherwise. Additionally, apply an overall blob-size guard (similar to `MAX_CONFLICT_FILE_READ_SIZE`/`MaxDiffBufferSize`) before reading binary image blobs intended for DDS decoding.

### Proof of Concept
1. Attacker creates a repository containing a `.dds` file whose header (parsed by `parse-dds`) declares `width`/`height` of, e.g., 65536×65536 in the first mip level, while the actual payload bytes stored are minimal/truncated.
2. Attacker asks victim to clone/fetch this repository (or pushes to a shared repo the victim already has).
3. Victim opens GitHub Desktop and views the diff for the `.dds` file (new/modified image), which is auto-rendered as an image diff.
4. `ImageContainer.loadImage` → `convertDDSImage` sets `canvas.width/height` to the attacker-declared dimensions and calls `gl.compressedTexImage2D` with those dimensions, forcing a large allocation attempt purely from header data, potentially crashing/hanging the renderer. [1](#0-0)

function drawToCanvas(
  canvas: HTMLCanvasElement,
  format: string,
  width: number,
  height: number,
  imageData: ArrayBufferView
) {
  canvas.width = width
  canvas.height = height
  const gl = canvas.getContext('webgl2', { preserveDrawingBuffer: true })
  if (!gl) {
    throw new Error('Failed to get webgl2 context')
  }

  gl.bindTexture(gl.TEXTURE_2D, gl.createTexture())
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR)
  gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR)
  const ext = gl.getExtension('WEBGL_compressed_texture_s3tc')
  if (!ext) {
    throw new Error('Failed to get WEBGL_compressed_texture_s3tc extension')
  }

  const internalFormat = getFormat(ext, format)
  gl.compressedTexImage2D(
    gl.TEXTURE_2D,
    0,
    internalFormat,
    width,
    height,
    0,
    imageData
  )

  const program = compileProgram(gl, vert, frag)
  gl.useProgram(program)

  gl.viewport(0, 0, width, height)
  triangle(gl)
}

export function convertDDSImage(contents: ArrayBufferLike) {
  const ddsData = parseDDS(contents)

  // Get the first mipmap texture.
  const [image] = ddsData.images
  const [imageWidth, imageHeight] = image.shape
  const imageData = new Uint8Array(contents, image.offset, image.length)

  // Draw the DXT texture to the canvas using WebGL2.
  const canvas = document.createElement('canvas')
  drawToCanvas(canvas, ddsData.format, imageWidth, imageHeight, imageData)

 * @param buffer A buffer of binary text from a spawned process

function getMediaType(extension: string) {
  if (extension === '.png') {
    return 'image/png'
  }
  if (extension === '.jpg' || extension === '.jpeg') {
    return 'image/jpg'
  }
  if (extension === '.gif') {
    return 'image/gif'
  }
  if (extension === '.ico') {
    return 'image/x-icon'
  }
  if (extension === '.webp') {
    return 'image/webp'
  }
  if (extension === '.bmp') {
    return 'image/bmp'
  }
  if (extension === '.avif') {
    return 'image/avif'
  }
  if (extension === '.dds') {
    return 'image/vnd-ms.dds'
  }

  // fallback value as per the spec
  return 'text/plain'
}

export async function getBlobImage(
  repository: Repository,
  path: string,
  commitish: string
): Promise<Image> {
  const extension = Path.extname(path)
  const contents = await getBlobContents(repository, commitish, path)
  return new Image(
    contents.buffer,
    contents.toString('base64'),
    getMediaType(extension),
    contents.length
  )
}
/**
 * Retrieve the binary contents of a blob from the working directory
 *
 * Returns an image object containing the base64 encoded string,
 * as <img> tags support the data URI scheme instead of
 * needing to reference a file:// URI
 *
 * https://en.wikipedia.org/wiki/Data_URI_scheme
 */
export async function getWorkingDirectoryImage(
  repository: Repository,
  file: FileChange
): Promise<Image> {
  const contents = await readFile(Path.join(repository.path, file.path))
  return new Image(
    contents.buffer,
    contents.toString('base64'),
    getMediaType(Path.extname(file.path)),
    contents.length
  )
}
