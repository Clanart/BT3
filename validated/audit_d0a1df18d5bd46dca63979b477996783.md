Found a concrete, provable analog. `handlePostRequestTimeouts` in `HandlerV2.sol` dispatches a timeout for an *arbitrary attacker-supplied `PostRequest` struct* whose only server-side check is that a `FeeMetadata` entry exists at `hash(request)` and that `request.timeout()` has elapsed — there is no check binding `request.dest` (or `request.source`) to the state machine whose non-membership proof was actually verified.

### Title
`handlePostRequestTimeouts` accepts a forged `PostRequest` whose `dest` differs from the proven state machine, letting an attacker trigger `onPostRequestTimeout`/refund using a non-membership proof from an unrelated chain - ([File: evm/src/core/HandlerV2.sol])

### Summary

### Finding Description
`handlePostRequestTimeouts` reconstructs the request commitment purely from calldata (`request.hash()`), looks up `FeeMetadata` by that hash, and verifies a **non-membership** proof of the `_requestReceipts[commitment]` slot against `state.stateRoot` for `message.height` (the state machine height supplied by the caller): [1](#0-0) 

Unlike `handlePostRequests`, which explicitly checks `leaf.request.dest.equals(host.host())` before dispatch, this function performs **no check that `request.dest` (or `request.source`) matches the state machine ID embedded in `message.height`** used for the non-membership proof. The dedup/duplicate defenses that the Substrate handler applies (`dedup_requests`, batch-wide duplicate rejection) are also absent here — each timeout in the array is processed independently against whatever `FeeMetadata` happens to exist at that hash: [2](#0-1) 

Compare to the on-chain trie-key derivation used for fee accumulation, which explicitly ties the storage key derivation to a specific `state_machine` argument — the EVM handler has no equivalent binding step tying the `PostRequest.dest` field to the `state_id` encoded in `message.height`: [3](#0-2) 

`dispatchTimeOut` then deletes the fee-commitment record, invokes the destination module's `onPostRequestTimeout`, and unconditionally refunds `meta.fee` to `meta.sender` on success: [4](#0-3) 

### Impact Explanation
Because the only linkage between the state-commitment height being proven and the `PostRequest` being timed out is the attacker-supplied `request` struct itself (not independently re-derived from the proven trie), an attacker who can produce *any* valid non-membership proof for the `REQUEST_RECEIPTS_STORAGE_PREFIX` slot at a chosen `commitment` on a state machine they control (e.g. their own low-value/permissioned chain registered as a connected state machine) can supply a `PostRequest` whose `dest`/`from` fields point at a **different**, high-value application module, provided the hash of that forged request happens to match an existing `FeeMetadata` entry with a nonzero fee. This triggers `onPostRequestTimeout` and a relayer-fee refund pathway on a request the destination module never actually processed on the claimed chain, i.e., **unauthorized execution and unauthorized fund refund** driven by a mismatched module/chain binding — precisely the pattern the ISMP invariant "bind chain id, module/app identity, commitment uniqueness" is meant to prevent, and precisely the pattern the Rust equivalent enforces via `dest_chain()`/`source_chain()` checks against `msg.proof.height.id.state_id` that are missing on the EVM side for this call.

### Likelihood Explanation
Exploitability requires the attacker to control (or find a hash-colliding proof against) a registered state machine whose non-membership proof they can freely generate, and for a `FeeMetadata` entry to exist whose hash matches the crafted `PostRequest`. This is a meaningful but non-trivial bar (constructing a `PostRequest` whose ABI-encoded hash matches a specific existing commitment is a preimage-style constraint), so likelihood is moderate rather than trivial — the missing dest/state-machine binding is nonetheless a genuine structural gap relative to the Rust reference implementation and to `handlePostRequests` in the same file.

### Recommendation
In `handlePostRequestTimeouts` (and `handleGetRequestTimeouts`), before verifying the non-membership proof, assert that `request.source` (the chain the request commitment must have originated from, matching the `FeeMetadata.sender`'s chain) equals `message.height`'s `stateMachineId`, mirroring the `dest_chain()`/`source_chain()` checks already present in `modules/ismp/core/src/handlers/timeout.rs` and the `leaf.request.dest.equals(host.host())` check in `handlePostRequests`. Additionally add duplicate-commitment rejection within the batch, matching `dedup_requests` on the Substrate side.

### Proof of Concept
Not independently reproduced on-chain (would require constructing a `PostRequest` whose keccak hash collides with an existing `FeeMetadata` commitment on a state machine the attacker controls, which was not feasible to demonstrate within this analysis). The structural gap — absence of a `dest`/`source` vs. proof-height state-machine equality check in `handlePostRequestTimeouts`/`handleGetRequestTimeouts`, contrasted with the equivalent check present in `handlePostRequests` (line 193) and in the Rust `timeout.rs` handler (`dest_chain`/`source_chain` checks) — is directly evidenced in the cited source.

    function handlePostRequestTimeouts(IHost host, PostRequestTimeoutMessage calldata message)
        external
        notFrozen(host)
    {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            PostRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            // known request? also serves as source check
            bytes32 requestCommitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(requestCommitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(REQUEST_RECEIPTS_STORAGE_PREFIX, requestCommitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(PostRequestTimeout(request, _msgSender()), meta, requestCommitment);
        }
    }

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
