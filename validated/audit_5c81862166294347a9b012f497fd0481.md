### Title
Unvalidated `ReceivedOutput` deserialization permits attacker-controlled `outpoint`/`output`/`offset` rebinding, yielding funds reported received that are not spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` reconstructs a "received" output entirely from attacker-supplied bytes — an `offset` scalar, a `TxOut`, and an `OutPoint` — with no check that the three fields are consistent with each other or with anything the `Scanner` actually observed on-chain. This mirrors the CVE-2021-20671 class: an upload/deserialization path trusts attacker-shaped data in place of validated data, letting the attacker overwrite the binding between fields. Because `SignableTransaction::new` trusts `output.value` for accounting while signing commits to `outpoint`, a crafted `ReceivedOutput` makes the wallet account for value it does not control.

### Finding Description
`Scanner::scan_transaction` is the only trusted producer of `ReceivedOutput`: it pairs an `offset` it registered with the actual `TxOut` and `OutPoint` observed in a confirmed transaction [1](#0-0) . In contrast, `ReceivedOutput::read` deserializes all three fields independently from a byte stream with no integrity or consistency check: [2](#0-1) 

Nothing binds `outpoint` to `output`: the attacker can keep a genuine `outpoint` (a real UTXO paying to a scanned script, or any UTXO at all) while substituting an arbitrary `output` with an inflated `value`, or pair a real `output` with a different `outpoint` referencing a UTXO with a different amount.

Downstream, `SignableTransaction::new` uses `input.output.value` to compute `input_sat` for the `NotEnoughFunds` and change calculations [3](#0-2) , and embeds `input.outpoint` as the `TxIn::previous_output` [4](#0-3) . The only integrity check in `multisig` verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` [5](#0-4)  — it binds `offset` to `output.script_pubkey` but never checks `outpoint` ↔ `output` correspondence or that the claimed `value` matches the chain.

### Impact Explanation
- **Inflated balance / unspendable "received" funds**: a forged `ReceivedOutput` with a real scanned `script_pubkey`, a real (or registered) `offset`, an attacker's arbitrary `outpoint`, and an inflated `TxOut.value` passes `multisig`'s script check. The wallet reports those funds as received and builds a transaction spending them; the BIP-341 signature commits to the forged prevout amount via `Prevouts::All` [6](#0-5) , so the transaction fails consensus (amount/commitment mismatch or nonexistent UTXO). Funds are reported received that are not spendable — and honest participants may be induced to sign a doomed transaction repeatedly.
- **Value confusion**: two genuine outputs to the same script can have their `outpoint`/`output` fields cross-paired, making the wallet claim the larger value against the smaller UTXO.

### Likelihood Explanation
Reachable by any party able to deliver serialized `ReceivedOutput` bytes to a consumer of `ReceivedOutput::read` (e.g., a coordinator relaying scan results to signers, or corrupted stored scan data). No key material, validator status, or collusion is needed — only untrusted bytes into a `read` API explicitly in scope. Impact is bounded by consensus (forged amounts can't actually be stolen via the signed tx), so severity is Medium: integrity/availability loss and mis-accounting rather than direct theft.

### Recommendation
- Recompute and verify the binding at deserialization or spend time: confirm `output.script_pubkey == p2tr_script_buf(key + offset*G)` (already done in `multisig`) **and** fetch the referenced `outpoint` from the chain/RPC to verify its `TxOut` equals the claimed `output` before accounting or signing, rather than trusting serialized scan results.
- Alternatively, serialize only `(outpoint, offset)` and re-derive `output` from the chain, eliminating the attacker-controlled `TxOut` entirely.

### Proof of Concept
```rust
// Attacker constructs bytes for ReceivedOutput::read:
// offset = a legitimately registered offset o (script_pubkey passes multisig check)
// output = TxOut { value: 10 * COIN, script_pubkey: p2tr_script_buf(key + o*G) }
// outpoint = OutPoint of a real UTXO paying that script but worth only 0.01 * COIN
let mut bytes = o.to_bytes().to_vec();
bytes.extend(serialize(&forged_txout));
bytes.extend(serialize(&real_but_small_outpoint));
let ro = ReceivedOutput::read(&mut &bytes[..]).unwrap();

// Wallet accounting believes 10 BTC was received:
let stx = SignableTransaction::new(vec![ro], payments, change, None, fee).unwrap();
// multisig() succeeds since script_pubkey matches; signing commits to the forged
// prevout amount via Prevouts::All; the broadcast tx is rejected by consensus —
// the 10 BTC "received" is unspendable and the fee/signing work is wasted.
```

    }
