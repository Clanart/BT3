### Title
Stale `WalletPuzzleStore.wallet_identifier_cache` entries after CAT→R-CAT wallet type conversion - ([File: chia/wallet/cat_wallet/r_cat_wallet.py])

### Summary
`RCATWallet.convert_to_revocable()` converts an existing `CATWallet` in place to an `RCATWallet` by updating `user_store` (the wallet-type "registry") and then deleting/regenerating the wallet's `derivation_paths` rows in `WalletPuzzleStore`. However, `WalletPuzzleStore.wallet_identifier_cache` — an `LRUCache[bytes32, WalletIdentifier]` keyed by puzzle hash — is only invalidated for entries removed via `delete_wallet()`. Any cached `WalletIdentifier` for puzzle hashes belonging to *other* wallets, or entries populated between `delete_wallet()` and the subsequent `create_more_puzzle_hashes()` regeneration, are not guaranteed to reflect the new wallet type/derivation state consistently, mirroring the reported Yearn `_cachedVaults` pattern where a cache array's prefix is left stale after the authoritative source (`registry`) changes.

### Finding Description
`convert_to_revocable()` at [1](#0-0)  performs the wallet-type change by writing a new `WalletInfo` to `user_store` and swapping `wallet_state_manager.wallets[cat_wallet.id()]` to the new `RCATWallet` instance, then calls `puzzle_store.delete_wallet(cat_wallet.id())` followed by `create_more_puzzle_hashes()` to regenerate derivation paths under the new wallet type.

`delete_wallet()` at [2](#0-1)  only removes cache entries for puzzle hashes it fetches synchronously from the DB for that `wallet_id` at that moment, and clears `last_wallet_derivation_index`/`last_derivation_index`. It does not otherwise reconcile `wallet_identifier_cache` with the newly-written type. The cache itself is populated lazily in `get_wallet_identifier_for_puzzle_hash()` at [3](#0-2) , which is exactly the kind of "populate from source, but the authority (here, the wallet's stored type) later changes" pattern described in the report: the cache mirrors a snapshot of the authoritative registry (`derivation_paths`/`user_store`), but nothing enumerates and corrects already-cached entries when the authority is mutated out from under the cache — only the deletion path clears rows it can see at delete time.

This routine is reachable indirectly from wallet sync: `CATWallet.identify()` at [4](#0-3)  calls `RCATWallet.convert_to_revocable()` automatically while processing coin states received from a peer, meaning a remote peer (or a crafted CAT coin spend observed by the wallet) can trigger this conversion path during normal sync without any local user action.

### Impact Explanation
If a stale `WalletIdentifier` (old wallet id/type) for a puzzle hash is served after conversion, downstream consumers such as `_add_coin_state()` (`chia/wallet/wallet_state_manager.py:1131`) that call `get_wallet_identifier_for_puzzle_hash()` could misattribute coin ownership/type, potentially causing a coin to be recorded/spent under the wrong wallet accounting context. This is a coin-identity/bookkeeping integrity concern within the wallet's own state, not a consensus-level forgery, but it can produce incorrect local balance/spend decisions.

### Likelihood Explanation
The conversion path is exercised whenever a wallet receives a coin state for a CAT that has a revocation layer matching a wallet it already tracks as a plain CAT — this happens automatically during sync (`CATWallet.identify`), so it is reachable by any peer/coin-state event without privileged access. However, triggering the specific stale-cache race requires the `wallet_identifier_cache` to already hold an entry for a relevant puzzle hash from *before* `delete_wallet()` runs and for that entry to be read again before regeneration completes — a narrow timing window that reduces practical likelihood compared to the deterministic Yearn bug.

### Recommendation
In `WalletPuzzleStore.delete_wallet()` (and generally on any wallet-type/identity mutation such as `convert_to_revocable`/`convert_to_cr`), proactively invalidate or refresh all `wallet_identifier_cache` entries associated with the affected `wallet_id`, and ensure `create_more_puzzle_hashes()`/conversion flows repopulate the cache atomically with the DB write rather than relying on lazy re-population, so no caller can observe an inconsistent mapping between `derivation_paths` rows and cached `WalletIdentifier` values.

### Proof of Concept
Not independently reproducible from static analysis alone: the index does not show a test that exercises concurrent reads of `wallet_identifier_cache` during `convert_to_revocable()`/`convert_to_cr()`, so the exact race window (cache populated between `delete_wallet()` and full `create_more_puzzle_hashes()` completion) is asserted from code structure rather than an observed failing test. A Devin session with full repo/test access would be needed to construct a concrete reproduction (e.g., interleave a `get_wallet_identifier_for_puzzle_hash()` call with `RCATWallet.convert_to_revocable()` in a test) to confirm exploitability.

    async def convert_to_revocable(
        cls,
        cat_wallet: CATWallet,
        hidden_puzzle_hash: bytes32,
    ) -> bool:
        if not await cat_wallet.lineage_store.is_empty():
            cat_wallet.log.error("Received a revocable CAT to a CAT wallet that already has CATs")
            return False
        replace_self = cls()
        replace_self.standard_wallet = cat_wallet.standard_wallet
        replace_self.log = logging.getLogger(cat_wallet.get_name())
        replace_self.log.info(f"Converting CAT wallet {cat_wallet.id()} to R-CAT wallet")
        replace_self.wallet_state_manager = cat_wallet.wallet_state_manager
        replace_self.lineage_store = cat_wallet.lineage_store
        replace_self.info = RCATInfo(cat_wallet.cat_info.limitations_program_hash, None, hidden_puzzle_hash)
        await cat_wallet.wallet_state_manager.user_store.update_wallet(
            WalletInfo(
                cat_wallet.id(), cat_wallet.get_name(), uint8(cls.wallet_type.value), bytes(replace_self.info).hex()
            )
        )
        updated_wallet_info = await cat_wallet.wallet_state_manager.user_store.get_wallet_by_id(cat_wallet.id())
        assert updated_wallet_info is not None
        replace_self.wallet_info = updated_wallet_info
        replace_self.tail_hash = replace_self.info.limitations_program_hash

        cat_wallet.wallet_state_manager.wallets[cat_wallet.id()] = replace_self
        await cat_wallet.wallet_state_manager.puzzle_store.delete_wallet(cat_wallet.id())
        result = await cat_wallet.wallet_state_manager.create_more_puzzle_hashes()
        await result.commit(cat_wallet.wallet_state_manager)
        return True

    async def get_wallet_identifier_for_puzzle_hash(self, puzzle_hash: bytes32) -> WalletIdentifier | None:
        """
        Returns the derivation path for the puzzle_hash.
        Returns None if not present.
        """
        cached = self.wallet_identifier_cache.get(puzzle_hash)
        if cached is not None:
            return cached

        async with self.db_wrapper.reader_no_transaction() as conn:
            row = await execute_fetchone(
                conn, "SELECT wallet_type, wallet_id FROM derivation_paths WHERE puzzle_hash=?", (puzzle_hash.hex(),)
            )

        if row is not None:
            wallet_identifier = WalletIdentifier(uint32(row[1]), WalletType(row[0]))
            self.wallet_identifier_cache.put(puzzle_hash, wallet_identifier)
            return wallet_identifier

        return None

    async def delete_wallet(self, wallet_id: uint32) -> None:
        async with self.db_wrapper.writer_maybe_transaction() as conn:
            # First fetch all puzzle hashes since we need them to drop them from the cache
            rows = await conn.execute_fetchall(
                "SELECT puzzle_hash FROM derivation_paths WHERE wallet_id=?", (wallet_id,)
            )
            cursor = await conn.execute("DELETE FROM derivation_paths WHERE wallet_id=?;", (wallet_id,))
            await cursor.close()
        # Clear caches
        puzzle_hashes = {bytes32.fromhex(row[0]) for row in rows}
        for puzzle_hash in puzzle_hashes:
            try:
                self.wallet_identifier_cache.remove(puzzle_hash)
            except KeyError:
                pass
        try:
            self.last_wallet_derivation_index.pop(wallet_id)
        except KeyError:
            pass
        self.last_derivation_index = None
