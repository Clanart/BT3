### Title
Payout attribution via unsigned OP_RETURN output lets anyone attribute a fronted withdrawal to an operator that never funded it - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` builds the operator payout transaction with three outputs: the user payout output, an anchor, and an `OP_RETURN` output that records the "fronting" operator's x-only pubkey. The withdrawing user only signs with `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, which binds input 0 to output 0 only [1](#0-0) . Because `ANYONECANPAY` explicitly allows adding extra, unrelated inputs, and `SIGHASH_SINGLE` only commits to the single corresponding output, the `OP_RETURN` output containing the operator attribution is completely outside what the user's signature authenticates. Any party who obtains the withdrawal signature (e.g. by observing an operator's in-flight payout transaction in the mempool before it confirms, since the signature becomes public the moment it is broadcast) can rebuild an equivalent transaction that pays the user the exact same output, fund it themselves, and write an arbitrary operator's x-only pubkey into the unsigned `OP_RETURN` field.

### Finding Description
Downstream, the verifier's `update_finalized_payouts` blindly trusts this `OP_RETURN` field to decide who is credited as the payer for a withdrawal: it parses the operator x-only pubkey straight out of the confirmed payout transaction's `OP_RETURN` output with no further authentication [2](#0-1) .

That attribution is then consumed unconditionally by the credited operator's own automation. `PayoutCheckerTask::run_once` fetches "the first unhandled payout" keyed by the operator's own x-only pubkey and calls `handle_finalized_payout` for it, without verifying that this operator actually funded/broadcast the transaction [3](#0-2) . `validate_payer_is_operator` (used by the kickoff-sending logic) only re-checks that the DB's `payer_xonly_pk` equals the local operator's own key — again, that same DB field was itself populated purely from the unauthenticated `OP_RETURN` data [4](#0-3) . The verifier-side fraud check (`is_kickoff_malicious`) also only compares the recorded `OP_RETURN` operator against `kickoff_data.operator_xonly_pk` — i.e. whichever operator's automation was fooled into sending the kickoff — so it does not detect this attack; it is designed to catch a different case (operator lying about its own kickoff) [5](#0-4) .

The net effect is a broken binding between "the operator credited as having fronted a withdrawal" and "the party that actually paid the withdrawal." An unprivileged party who obtains the withdrawal signature can front the withdrawal with their own BTC while writing a victim operator's pubkey into the unsigned `OP_RETURN`, causing the victim operator's own automation to autonomously proceed through the kickoff/reimburse flow (`create_reimburse_txhandler`, which always pays out the full `bridge_amount` regardless of what was actually paid [6](#0-5) ) and claim reimbursement for a payout it never itself funded.

### Impact Explanation
This matches the Critical impact bucket "an operator reimbursed for a payout it never funded." The victim operator's own key is used to complete the reimbursement chain, but only because its automation was deceived by unauthenticated data it cannot distinguish from a genuine self-fronted payout. This can be used to force an operator to expend collateral/kickoff slots on payouts it never made, and/or to have the vault reimburse an operator for BTC that operator never actually paid to the user.

### Likelihood Explanation
The attack requires only observing a Bitcoin mempool for an in-flight Clementine payout transaction (any operator broadcasting a legitimate payout leaks the reusable `SIGHASH_SINGLE|ANYONECANPAY` signature the moment the transaction hits the network) and winning a fee race to get an equivalent, differently-attributed transaction confirmed instead/first. No verifier, operator, or aggregator role is required — it is exploitable by anyone monitoring the network with sufficient fee budget to front the withdrawal amount.

### Recommendation
Bind the operator attribution to the signed portion of the transaction (e.g., have the withdrawing user's signature cover the `OP_RETURN` output, or otherwise authenticate which operator is entitled to credit, such as requiring the credited operator's own signature over the OP_RETURN/operator-attribution data before `update_finalized_payouts`/`PayoutCheckerTask` treat it as trusted).

### Proof of Concept
1. Attacker observes an unconfirmed Clementine payout transaction in the mempool (or otherwise obtains a valid withdrawal `user_sig` for a given `withdrawal_utxo`/`output_txout`).
2. Attacker builds a new transaction spending the same `withdrawal_utxo` input with the identical `output_txout` (satisfied by the same `user_sig`, since `SIGHASH_SINGLE|ANYONECANPAY` only binds input 0 ↔ output 0), funds any additional required inputs with their own BTC, and sets the `OP_RETURN` output (`core/src/builder/transaction/operator_reimburse.rs:418,432`) to an arbitrary victim operator's x-only pubkey.
3. Attacker gets this transaction confirmed (with a higher fee, e.g. via RBF) instead of/before the legitimate operator's tx.
4. `update_finalized_payouts` records the victim operator as the payer solely from this `OP_RETURN` data.
5. The victim operator's `PayoutCheckerTask` automatically calls `handle_finalized_payout` and proceeds to kickoff and eventually sign `reimburse_tx`, receiving the full `bridge_amount` for a withdrawal it never funded.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
