### Title
Contract governance (`GovParam`) can set `governance.governingnode` and KIP-71 base-fee bounds without the consistency checks enforced by header governance, allowing an already-privileged governance actor to escalate beyond intended council-membership and fee-bound constraints - ([File: kaiax/gov/contractgov/impl/getter.go])

### Summary
Kaia has two governance channels that both write to the same effective `gov.ParamSet`: header governance (`kaiax/gov/headergov`) and contract governance (`kaiax/gov/contractgov`, backed by the on-chain `GovParam` contract). Header governance enforces `checkConsistency` on every vote (governing-node-in-council checks, KIP-71 lower/upper bound ordering, etc.) before a value is allowed to be ratified. Contract governance has no equivalent consistency layer: it only runs a per-parameter `Canonicalizer`/`FormatChecker` (`kaiax/gov/paramset.go` `PartialParamSet.Add`) and blindly accepts any combination of values returned by the `GovParam` contract's `getAllParamsAt`. This is directly analogous to CVE-2017-8032, where a legitimately-privileged actor (a zone admin) could use a secondary, less-restricted configuration path (external IdP attribute mapping) to escalate/assign permissions that the primary path (normal UI role assignment) would have blocked.

### Finding Description
`kaiax/gov/headergov/impl/header.go` `checkConsistency` (lines 156-224) enforces, among other things: [1](#0-0) 
- For `gov.GovernanceGoverningNode`: the new governing node must currently be a council member, and (post-Permissionless) must remain in the council.
- For `gov.Kip71LowerBoundBaseFee` / `gov.Kip71UpperBoundBaseFee`: the new lower bound must not exceed the current upper bound and vice versa.

These checks exist specifically to prevent a voting governance participant from pushing the chain into an inconsistent or self-serving state (e.g., naming a governing node outside the validator set, or setting base-fee bounds that are contradictory).

The contract-governance path (`kaiax/gov/contractgov/impl/getter.go`, `GetParamSet`/`contractGetAllParamsAtFromAddr`) reads the same parameter names straight from the `GovParam` contract and applies them via `gov.ParamSet.Set`/`PartialParamSet.Add`: [2](#0-1) [3](#0-2) 

`Add` only calls the per-field `Canonicalizer`/`FormatChecker` — there is no cross-parameter/council consistency check equivalent to `checkConsistency`. Whoever controls the `GovParam` contract (its `Ownable` owner, callable via `setParam`/`setParamIn`, see `contracts/bindings/gov/GovParam.go` `SetParam`/`SetParamIn`) can therefore set `governance.governingnode` to an address outside the current council, or set `kip71.lowerboundbasefee` > `kip71.upperboundbasefee`, values that the header-governance vote path would explicitly reject. Because `gov.GovernanceGovParamContract` itself is a governance-settable parameter that switches the active engine to "mixed"/contract mode, the entity with contract ownership is exactly the counterpart of the CVE's "zone admin": a legitimately-scoped governance participant that can use a secondary permission-setting surface to escalate beyond the boundaries the primary surface enforces.

### Impact Explanation
Setting an inconsistent KIP-71 base-fee bound pair can produce state divergence in the pricing logic derived from `ParamSet.ToKip71Config()` (`kaiax/gov/paramset.go` lines 199-207), used by the base-fee/pricing engine, and it may allow proposer-favorable, non-canonical fee computation that healthy nodes relying on header governance would never accept. Setting `governance.governingnode` to an address outside the council can desynchronize which node is treated as authorized to vote/ratify future parameters (single-mode governance authorization is keyed off `GoverningNode`), enabling further unauthorized governance takeover. Both are consensus-parameter integrity issues that can cause state/parameter divergence between nodes that trust contract-governance values versus nodes that would reject the same value via header-governance's `checkConsistency`.

### Likelihood Explanation
Exploitation requires control of the `GovParam` contract (ownership), which is itself a scoped/privileged governance capability rather than something any anonymous transaction sender can reach directly — this mirrors the original CVE's precondition that the attacker is already a "zone administrator." Given that contract governance is an officially supported and increasingly used path (mixed engine), and that the missing checks are asymmetric with the header-governance path for the exact same parameter names, the likelihood that this asymmetry is exploited by a governance-privileged actor is meaningful.

### Recommendation
Apply the same `checkConsistency`-style cross-parameter validation in `kaiax/gov/contractgov` (or centrally in `gov.ParamSet.SetFromMap`) that header governance already applies in `headerGovModule.checkConsistency`, specifically for `GovernanceGoverningNode` (council membership) and the KIP-71 lower/upper base-fee bound ordering, so that contract governance cannot set values that the header-governance voting path would reject.

### Proof of Concept
1. Governance votes `governance.govparamcontract` to point at an attacker-influenced `GovParam` contract instance (owned by the governance-privileged actor).
2. The owner calls `GovParam.setParamIn("governance.governingnode", true, <address not in council>, 1)` (see `contracts/bindings/gov/GovParam.go` `SetParamIn`).
3. `kaiax/gov/contractgov` `GetParamSet` (`kaiax/gov/contractgov/impl/getter.go` lines 17-32) accepts the value because only the format checker (address decodability) is applied, with no council-membership check as performed by `headergov`'s `checkConsistency` (`kaiax/gov/headergov/impl/header.go` lines 157-187).
4. The resulting `ParamSet.GoverningNode` is now outside the current validator council, something header governance's `VerifyVote`/`checkConsistency` path would have rejected with `ErrGovNodeNotInValSetList`.

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		council, err := h.ValSet.GetCouncil(blockNum)
		if err != nil {
			return err
		}

		if !slices.Contains(council, params.GoverningNode) {
			return ErrGovNodeNotInValSetList
		}
		if !h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) {
			return nil
		}

		// After Permissionless only the governing node may vote, so a successor outside the council could never vote again.
		newNode, ok := vote.Value().(common.Address)
		if !ok || common.EmptyAddress(newNode) {
			return ErrInvalidKeyValue
		}
		if !slices.Contains(council, newNode) {
			return ErrGovNodeNotInValSetList
		}
		return nil
	case gov.Kip71LowerBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) > params.UpperBoundBaseFee {
			return ErrLowerBoundBaseFee
		} else {
			return nil
		}
	case gov.Kip71UpperBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) < params.LowerBoundBaseFee {
			return ErrUpperBoundBaseFee
		} else {
			return nil
		}
	case gov.AddValidator, gov.RemoveValidator:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}
		if slices.Contains(vote.Value().([]common.Address), params.GoverningNode) {
			return ErrGovNodeInValSetVoteValue
		}
		return nil

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
}
