### Title
Debt asset ids are never excluded from `get-assets`/`price-multi-resolve`, so a disabled or oracle-broken debt asset permanently DOS's price/health resolution for any user still holding that debt — (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`user-safe-mask` filters *collateral* bits against the DAO-controlled enabled bitmap but passes the caller's *debt* bits through unconditionally. Because every health check, repay, collateral-remove, and liquidation path calls `get-assets` → `price-multi-resolve`, which reverts the entire call if **any** single feed in the requested set fails validity/staleness checks, a user with existing debt in an asset whose oracle becomes stale/broken (or whose debt has been disabled by the DAO) can never get a price resolution to succeed again — freezing that user's entire position, including unrelated healthy collateral. There is no mechanism to skip, force-remove, or gracefully degrade a single malfunctioning asset from this aggregate resolution, mirroring the SafEth "cannot remove malfunctioning derivative" bug class.

### Finding Description
`user-safe-mask` computes the mask used to decide which asset prices must be resolved for a position: [1](#0-0) 

Collateral bits are ANDed against `mask-enabled` (the DAO bitmap), but `user-debt` is derived straight from the user's own position mask and OR'd in with no filtering against enabled/disabled status. This combined `safe-mask` is fed into `get-assets`, which resolves prices for every resulting asset id via `price-multi-resolve`: [2](#0-1) 

`price-multi-resolve`/`iter-price-multi` fold over the requested oracle list and abort the *entire* batch (`ERR-ORACLE-MULTI`) the moment a single `price-resolve` call fails (stale timestamp, non-positive price, or oracle call error): [3](#0-2) 

Staleness/validity gating happens per feed in `oracle-price-legal`/`oracle-timestamp-fresh`, with no fallback path or per-asset skip: [4](#0-3) 

Meanwhile `assets.clar`/`v0-assets.clar` only lets the DAO toggle a bit in the global enabled bitmap; it never removes the asset's oracle from being referenced by users who already hold debt in it, and there is no way to exclude an asset id from a user's outstanding debt mask short of full repayment (which itself requires the same price/health resolution path in most flows): [5](#0-4) 

### Impact Explanation
Any user with debt in an asset whose oracle malfunctions (goes stale beyond `max-staleness`, returns zero/invalid price, or the DAO disables debt for it) can no longer resolve a valid `get-assets` list for their position. Since `collateral-remove`, borrow, and liquidation health checks all funnel through `get-assets`/`get-notional-evaluation`, the position becomes permanently unmanageable — collateral cannot be withdrawn, the user cannot be liquidated (protocol loses insolvency protection), and unrelated healthy collateral in the same position is frozen alongside the broken debt asset. This is a temporary/permanent freezing-of-funds impact (High/Critical depending on duration and whether the DAO can restore the feed before insolvency accrues).

### Likelihood Explanation
Requires only that an oracle feed used by a debt asset goes stale or the DAO disables that asset for debt while positions remain open — a realistic operational scenario, not requiring any privileged compromise beyond intended DAO asset-management actions or ordinary third-party oracle downtime. Given multiple oracle types (Pyth/DIA) and callcode-derived synthetic prices (`ztoken`/`ststx`) feeding into this same all-or-nothing resolution, the surface for one feed going stale while a position still has debt in it is broad.

### Recommendation
Decouple debt-asset price resolution failures from the aggregate batch: allow `price-multi-resolve`/`get-assets` to substitute a conservative worst-case valuation (or a dedicated "frozen asset" fallback) for a single failing feed instead of reverting the whole computation, and/or provide a DAO path to force-settle/isolate debt positions tied to a disabled/broken oracle so collateral belonging to unaffected assets in the same position can still be managed.

### Proof of Concept
1. User opens debt in Asset X and holds unrelated healthy collateral in Asset Y within the same position.
2. Asset X's oracle feed becomes stale past `max-staleness` (or DAO calls `disable(X, false)` after debt already exists).
3. User calls `collateral-remove` on Asset Y; the flow computes `position-mask` including the still-outstanding debt bit for X, calls `get-assets(position-mask)` → `price-multi-resolve`, which calls `price-resolve` for X's oracle and fails `oracle-timestamp-fresh`, returning `ERR-ORACLE-INVARIANT`/`ERR-ORACLE-MULTI` and reverting the whole transaction.
4. User cannot withdraw Asset Y despite it being fully healthy and unrelated to the broken oracle, and cannot be liquidated either since the same resolution path underlies liquidation health checks — funds are frozen with no on-chain recourse.

(define-private (price-resolve
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))

(define-private (price-multi-resolve
  (data (list 64 { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (aids (list 64 uint)))
  (let ((init { output: (list), valid: true, aids: aids, idx: u0 })
        (response (fold iter-price-multi data init)))
    (asserts! (get valid response) ERR-ORACLE-MULTI)
    (ok (get output response))))

(define-private (iter-price-multi
  (oracle-data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint })
  (acc { output: (list 64 uint), valid: bool, aids: (list 64 uint), idx: uint }))
  (let ((valid (get valid acc))
        (skip? (asserts! valid acc))
        (asset-ids (get aids acc))
        (idx (get idx acc))
        ;; resolve price - will use cache for ztokens
        (price (unwrap! (price-resolve oracle-data) (merge acc { valid: false })))
        (next (unwrap-panic (as-max-len? (append (get output acc) price) u64))))
    { output: next,
      valid: true,
      aids: asset-ids,
      idx: (+ idx u1) }))

(define-private (user-safe-mask (mask-user uint) (mask-enabled uint))
  (let ((enabled-collateral (bit-and mask-enabled MAX-U64))
        (user-collateral (bit-and mask-user MAX-U64))
        (user-debt (/ (bit-and mask-user DEBT-MASK) (pow u2 DEBT-OFFSET)))
        (collateral-match (bit-and user-collateral enabled-collateral)))
    (bit-or collateral-match user-debt)))
