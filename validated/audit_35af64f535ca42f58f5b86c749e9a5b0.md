## Title
Payout-tx operator attribution (OP_RETURN) is unauthenticated and malleable, letting anyone rewrite who gets credited/reimbursed for a withdrawal - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` signs only the withdrawal input with `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, which covers exactly one input and its corresponding output. The OP_RETURN output that records "which operator fronted this payout" is a later output and is therefore **not covered by any signature**. Anyone who observes a broadcast (unconfirmed) payout transaction can rebroadcast a conflicting, higher-fee double-spend of the same withdrawal input that reuses the valid user signature but substitutes an arbitrary `operator_xonly_pk` in the OP_RETURN output. This breaks the binding "the operator credited for a payout" == "the operator/party that actually funded it."

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
- Input 0: the user's withdrawal UTXO, spent with the user's `SinglePlusAnyoneCanPay` signature.
- Output 0: the user payout (protected by `SIGHASH_SINGLE`, tied to input 0).
- Output 1: anchor.
- Output 2: `op_return_txout` containing `operator_xonly_pk.serialize()` — the value later used to determine which operator gets credited/reimbursed. [1](#0-0) 

Because `SIGHASH_SINGLE|ANYONECANPAY` only commits input 0 to output 0, the OP_RETURN output (index 2) carrying the operator attribution is completely unsigned/uncommitted. Any party can add their own funding input (ANYONECANPAY allows arbitrary extra inputs) and rebuild the transaction with a different `operator_xonly_pk`, reusing the exact same valid user signature over input 0/output 0, and simply bump the fee to win the mempool double-spend race against the legitimately-broadcast tx.

Downstream, verifiers extract this OP_RETURN field as ground truth for "who is the payer": [2](#0-1) 

This is persisted and later used by `validate_payer_is_operator` to gate which operator's node is authorized to build the kickoff/reimburse chain and pull BTC out of the move-to-vault UTXO: [3](#0-2) [4](#0-3) 

The actual fee-funding of the payout tx (i.e., who really pays the bulk of the withdrawal amount, since the withdrawal UTXO itself is only a dust commitment) is done by whichever wallet calls `fund_raw_transaction`/RBF — there is no check that this wallet corresponds to the `operator_xonly_pk` embedded in the OP_RETURN: [5](#0-4) 

### Impact Explanation
Whoever ends up mining/winning the fee race controls the OP_RETURN, decoupling "who actually funded the payout" from "who gets attributed as payer and thus becomes eligible to draw reimbursement from the vault." A third party (not even necessarily a registered operator) can:
- Grief a competing operator by attributing a payout that operator never made, forcing them into (or blocking them from) the kickoff/reimbursement flow for a deposit they didn't front.
- Cause an honest operator who genuinely fronted the withdrawal from their own wallet to lose the ability to claim reimbursement entirely, because the winning (attacker-crafted) transaction on-chain carries a different or invalid `operator_xonly_pk`, permanently orphaning that operator's legitimate spend with no recorded attribution.

This matches "operator reimbursed for a payout it never funded" / "honest operator permanently unable to be reimbursed."

### Likelihood Explanation
Payout transactions are broadcast to the public mempool before confirmation (that's inherent to Bitcoin), so any observer can extract the witness/signature for input 0. Constructing a conflicting, higher-fee transaction with a different OP_RETURN using the same signature requires no privileged role, no key compromise, and no cooperation from any protocol participant — only mempool visibility and the ability to broadcast a transaction, which is the definition of an unprivileged attacker.

### Recommendation
Bind the operator attribution to the signature. Options: have the user sign with `SIGHASH_ALL` (or `SIGHASH_NONE`/`SIGHASH_SINGLE` extended to cover the OP_RETURN output) so the attribution output cannot be altered without invalidating the user's signature, or move the operator identity commitment out-of-band (e.g., require the reimbursement claim to independently prove, via a signature from the claiming operator's own key over the payout txid, that they funded the specific input actually spent to cover the payout amount) instead of trusting an unauthenticated OP_RETURN field.

### Proof of Concept
1. Operator A observes/creates a valid signed payout tx for withdrawal `W` (input 0 = dust UTXO with user's `SinglePlusAnyoneCanPay` sig, output 0 = user payment, OP_RETURN = A's xonly_pk), and broadcasts it via `withdraw()` (core/src/operator.rs `withdraw`).
2. Before it confirms, an attacker (or colluding party) copies input 0's witness (the user signature, publicly visible in the mempool tx), constructs a new transaction spending the same dust UTXO with the same output 0 (required to keep the SIGHASH_SINGLE signature valid), but with a different funding input, and an OP_RETURN containing operator B's (or an invalid) xonly_pk.
3. Attacker sets a higher fee so their transaction wins the double-spend race and gets mined instead of A's.
4. `update_finalized_payouts` in `verifier.rs` parses the confirmed tx's OP_RETURN and records operator B (not A) as the payer; `validate_payer_is_operator`/`PayoutCheckerTask` then only allow operator B to pursue the kickoff/reimburse chain, even though B never funded anything, while A's legitimate spend is left unattributed.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
