### Title
Permissionless registration of malicious "native ERC20" token pairs allows unbacked minting of native Cosmos coins via self-reported `balanceOf`/`transfer` results - ([File: x/erc20/keeper/msg_server.go], [File: x/erc20/keeper/evm.go], [File: x/erc20/keeper/proposals.go])

### Summary
The external report's bug class — code trusting an ERC20 contract's self-reported `transfer` success/return semantics instead of independently verifying state changes — maps onto `x/erc20`'s `ConvertERC20`/`ConvertCoin` flow. Unlike the report's stuck-funds scenario, here the trust is placed not just in the `transfer` return value/event but ultimately in the *same* untrusted contract's `balanceOf` return value used as the "independent" invariant check, which is fully attacker-controlled when the ERC20 contract is registered permissionlessly.

### Finding Description
`RegisterERC20` allows any user to register an arbitrary ERC20 contract as a token pair when `params.PermissionlessRegistration` is enabled [1](#0-0) , with only light validation of `name`/`symbol`/`decimals` in `CreateCoinMetadata`/`QueryERC20` [2](#0-1) [3](#0-2) . No check is done on the correctness of `transfer`/`balanceOf` semantics.

`convertERC20IntoCoinsForNativeToken` (invoked by `ConvertERC20`) then:
1. Reads `balanceToken = BalanceOf(module)` by calling the attacker's contract [4](#0-3) .
2. Calls `transfer(module, amount)` on the same attacker-controlled contract, and validates success either via the return value or, when the return is empty, merely via presence of a `Transfer` event with the correct emitting address — the event's `from`/`to`/`amount` fields are **never checked** [5](#0-4) [6](#0-5) .
3. Re-reads `balanceTokenAfter = BalanceOf(module)` from the **same malicious contract** and compares it to `balanceToken + amount` as an "invariant" check [7](#0-6) .
4. If the check passes, the keeper unconditionally `MintCoins` and sends them to the receiver [8](#0-7) .

Because `BalanceOf` simply executes an EVM `staticcall` to the attacker's contract and trusts whatever value it returns [9](#0-8) , this "invariant" is not an independent check at all — the same untrusted contract that controls whether the "transfer" actually happened also controls what `balanceOf` reports afterward. An attacker can deploy a contract whose `transfer()` is a no-op (or even reverts-then-catches at the EVM message level is not possible, but a no-op transfer that still returns `true`/emits a `Transfer` log) and whose `balanceOf(module)` always reports the previous value plus whatever `amount` was requested, regardless of actual token movement. This defeats the "check evm call response" / "check expected escrow balance" safeguards that the code comments describe as security invariants, and lets the attacker mint arbitrary native Cosmos coin (`erc20/<contract>` denom, and if later swapped/traded for other native assets, effectively unbacked value) without ever escrowing real tokens.

The identical pattern (self-reported balance used as the sole invariant) exists in `ConvertCoinNativeERC20`, where `balanceOf(receiver)` on the same untrusted contract is used to validate that "unescrow" succeeded before burning the corresponding native coin [10](#0-9) .

### Impact Explanation
This is a critical unauthorized minting / irreversible accounting corruption of spendable user value: an unprivileged attacker can register their own malicious ERC20 contract (permissionless registration) and repeatedly call `MsgConvertERC20` to mint native Cosmos coins under the `erc20/<contract>` denom with no real ERC20 backing, since the only "proof" of transfer is queried from the same contract that performs the fake transfer. These freshly minted coins are fully fungible native bank coins and can be transferred, IBC-transferred, or (if a pool/DEX or other precompile treats the denom as real value) exchanged for genuinely backed assets, resulting in a direct value-extraction / inflation vector.

### Likelihood Explanation
Likelihood is High if `PermissionlessRegistration` governance parameter is enabled (a standard configuration knob), since the entire attack requires only: (1) deploying a contract with a benign `name()`/`symbol()`/`decimals()` but malicious `transfer()`/`balanceOf()`, (2) registering it via `MsgRegisterERC20`, and (3) calling `MsgConvertERC20` — all unprivileged, ordinary transaction flows. If `PermissionlessRegistration` is disabled, only governance-approved contracts can be registered, which would require a malicious/compromised governance decision, moving this out of the "unprivileged user" trigger category (governance-only assumption is out of scope per the impact gate). Because the finding's exploitability is contingent on this parameter, likelihood should be treated as configuration-dependent.

### Recommendation
- Do not rely on the same untrusted contract's `balanceOf` as an independent invariant. Cross-validate the emitted `Transfer` event's decoded `from`, `to`, and `value` fields against the expected sender/recipient/amount instead of just checking event *presence* and emitting address in `validateTransferEventExists`.
- Consider requiring a stricter allowlist/validation step for "native ERC20" pairs when `PermissionlessRegistration` is enabled — e.g., requiring the contract bytecode to match a known-safe implementation (similar to `ERC20MinterBurnerDecimalsContract`) or running a standardized ERC20 conformance probe (mint/transfer/balance round-trip in a sandboxed, reverted simulation) before allowing registration.
- For registered pairs that fail stricter validation, disable `ConvertERC20`/`ConvertCoin` conversion (i.e., treat as non-convertible pairs) rather than trusting self-reported balances as proof of a legitimate transfer.

### Proof of Concept
Conceptual (not executed, requires local devnet with `PermissionlessRegistration=true`):
1. Deploy `EvilERC20` implementing `name()="Evil"`, `symbol()="EVL"`, `decimals()=18` (pass `QueryERC20` validation), `transfer(to, amt)` that does nothing but returns `true` and emits a `Transfer(msg.sender, to, amt)` log, and `balanceOf(addr)` that returns a mapping incremented every time `transfer` is "called" targeting that address (i.e., lies to always match `balanceToken + amount`).
2. Call `MsgRegisterERC20` with `EvilERC20` address — succeeds since `CreateCoinMetadata` only checks name/symbol/decimals.
3. Call `MsgConvertERC20{ContractAddress: EvilERC20, Amount: X, Sender: attacker, Receiver: attacker}`.
4. `convertERC20IntoCoinsForNativeToken` calls `EvilERC20.transfer(module, X)` (no real value moves), validates via the (unchecked) `Transfer` event, re-queries `balanceOf(module)` which EvilERC20 reports as `previous + X`, passes the invariant check, and the keeper `MintCoins` + sends `X` of denom `erc20/<EvilERC20>` to attacker — unbacked native coin created.

Note: I could not fully trace whether any downstream module treats `erc20/<contract>` bank denoms as fungible/tradeable against real assets (e.g., DEX precompiles, IBC transfer pathways) within the indexed portion of the repo, which would determine whether the unbacked coin can be laundered into real value; `x/ibc/transfer/keeper/msg_server.go` shows IBC transfers of such denoms are supported [11](#0-10) , which is sufficient to move the unbacked coin off-chain to another chain as a "real" IBC-denominated asset, confirming the critical impact.

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

// QueryERC20 returns the data of a deployed ERC20 contract
func (k Keeper) QueryERC20(
	ctx sdk.Context,
	contract common.Address,
) (types.ERC20Data, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI

	// Name - with fallback support for bytes32
	name, err := k.queryERC20String(ctx, erc20, contract, "name")
	if err != nil {
		return types.ERC20Data{}, err
	}

	// Symbol - with fallback support for bytes32
	symbol, err := k.queryERC20String(ctx, erc20, contract, "symbol")
	if err != nil {
		return types.ERC20Data{}, err
	}

	// Decimals - standard uint8, no fallback needed
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, false, nil, "decimals")
	if err != nil {
		return types.ERC20Data{}, err
	}

	var decimalRes types.ERC20Uint8Response
	if err := erc20.UnpackIntoInterface(&decimalRes, "decimals", res.Ret); err != nil {
		return types.ERC20Data{}, errorsmod.Wrapf(
			types.ErrABIUnpack, "failed to unpack decimals: %s", err.Error(),
		)
	}

	return types.NewERC20Data(name, symbol, decimalRes.Value), nil
}

// BalanceOf queries an account's balance for a given ERC20 contract
func (k Keeper) BalanceOf(
	ctx sdk.Context,
	abi abi.ABI,
	contract, account common.Address,
) *big.Int {
	res, err := k.evmKeeper.CallEVM(ctx, abi, types.ModuleAddress, contract, false, nil, "balanceOf", account)
	if err != nil {
		return nil
	}

	unpacked, err := abi.Unpack("balanceOf", res.Ret)
	if err != nil || len(unpacked) == 0 {
		return nil
	}

	balance, ok := unpacked[0].(*big.Int)
	if !ok {
		return nil
	}

	return balance
}

// validateTransferEventExists returns an error if the given transactions logs DO NOT include
// an expected `Transfer` event from the expected address
func validateTransferEventExists(logs []*types.Log, tokenAddress common.Address) error {
	if len(logs) == 0 {
		return errors.Wrapf(
			types2.ErrExpectedEvent, "expected Transfer event",
		)
	}
	found := false
	for _, log := range logs {
		if log.Topics[0] == logTransferSigHash.Hex() {
			if log.Address != tokenAddress.Hex() {
				return errors.Wrapf(
					types2.ErrUnexpectedEvent, "Transfer event from unexpected address",
				)
			}
			if found {
				return errors.Wrapf(
					types2.ErrUnexpectedEvent, "duplicate Transfer event",
				)
			}
			found = true
		}
	}

	if !found {
		return errors.Wrapf(
			types2.ErrExpectedEvent, "expected Transfer event",
		)
	}

	return nil
}
