### Title
`WombatBribeManager` voting and bribe-claim flows are entirely unguarded by any protocol pause mechanism - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager` has no `Pausable`/pause-flag checks at all on its state-changing entry points (`vote`, `unvote`, `claimBribeFor`, `claimAllBribes`, `castVotes`, `castVotesAndClaimBribes`), unlike `MasterMagpie`, `WombatStaking`, and `VLMGP`, which all guard their deposit/withdraw/claim/lock/unlock functions with `whenNotPaused`.

### Finding Description
`MasterMagpie` gates all of its state-mutating external functions (`deposit`, `withdraw`, `depositFor`, `withdrawFor`, `multiclaim`, `multiclaimFor`, `multiclaimOnBehalf`, `depositVlMGPFor`, etc.) with `whenNotPaused` [1](#0-0) , and `WombatStaking` similarly gates `deposit`, `withdraw`, `depositLP`, `harvest`, `convertWOM`, `convertAllWom` with `whenNotPaused` [2](#0-1) . `VLMGP` gates `lock`, `startUnlock`, `unlock`, `cancelUnlock`, `forceUnLock` the same way [3](#0-2) .

`WombatBribeManager`, however, has no pause mechanism whatsoever - grep for `whenNotPaused`/`Pausable`/`_pause()` across the file returns no matches. Its `vote()` function directly mutates `pool.totalVoteInVlmgp`, `userVotedForPoolInVlmgp`, `userTotalVotedInVlmgp`, `totalVlMgpInVote` and calls `IBribeRewardPool(pool.rewarder).stakeFor`/`withdrawFor` with no gating [4](#0-3) . `unvote()` behaves the same way [5](#0-4) . `claimBribeFor`/`claimAllBribes` transfer out reward tokens via `IBribeRewardPool.getReward` with no pause check [6](#0-5) .

These functions are reachable directly by any ordinary wallet holding vlMGP votes - none of them route through a `whenNotPaused`-guarded call in `MasterMagpie`, `WombatStaking`, or `VLMGP` (the only cross-contract call is to `IBribeRewardPool`, an operator-restricted, non-pausable rewarder contract). This matches exactly the reported bug class: a public/external function that mutates protocol state and moves funds but is unguarded by the emergency pause flags used elsewhere in the system, making it impossible to fully halt state changes during an emergency.

### Impact Explanation
While the global/market pause is meant to freeze all state mutation and fund movement across the protocol during an emergency, `WombatBribeManager.vote`/`unvote` continue to reallocate governance vote weight across pools (`totalVoteInVlmgp`, `userVotedForPoolInVlmgp`) and `claimBribeFor`/`claimAllBribes` continue to pay out bribe reward tokens, unaffected by pausing `MasterMagpie`, `WombatStaking`, or `VLMGP`. This undermines the intended purpose of the emergency pause (halting all state changes for safe recovery/investigation) and allows continued manipulation of voting-weight state and continued distribution of bribe rewards while the rest of the protocol believes it is fully frozen.

### Likelihood Explanation
Any wallet holding locked vlMGP with existing votes can call `vote`/`unvote`/`claimBribeFor` at any time, including immediately after the team pauses the rest of the protocol in response to an incident, since none of these calls depend on the paused contracts' state.

### Recommendation
Add an explicit pause check (e.g. a `whenNotPaused` modifier tied to the same pause authority used by `MasterMagpie`/`VLMGP`/`WombatStaking`, or `Pausable` inherited directly in `WombatBribeManager`) to `vote`, `unvote`, `claimBribeFor`, `claimAllBribes`, `castVotes`, and `castVotesAndClaimBribes`, and audit all other unguarded state/fund-moving entry points across the codebase to ensure pause coverage is comprehensive rather than function-specific.

### Proof of Concept
1. Governance/owner calls `pause()` on `MasterMagpie`, `WombatStaking`, and `VLMGP` in response to an incident.
2. A user who previously voted with vlMGP calls `WombatBribeManager.vote(_lps, _deltas)` to shift votes between pools - this succeeds because `vote()` has no pause check [4](#0-3) , even though the equivalent lock/unlock flows in `VLMGP` are frozen.
3. The same or another user calls `claimAllBribes(_for)`, which triggers `IBribeRewardPool(pool.rewarder).getReward(_for, _for)` and transfers bribe reward tokens out of the rewarder contracts [7](#0-6) , despite the global pause being active on the rest of the protocol.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
