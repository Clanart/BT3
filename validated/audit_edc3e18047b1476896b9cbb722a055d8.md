### Title
Challenge Transaction OP_RETURN Front-Running Steals Challenger Reimbursement Credit — (`core/src/builder/transaction/challenge.rs`, `core/src/builder/transaction/deposit_signature_owner.rs`)

---

### Summary

The `Challenge` transaction's pre-signed operator signature uses `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`. Under `SIGHASH_SINGLE`, the signature commits only to the output at the same index as the signed input (output 0 — the operator reimbursement). It does **not** commit to output 1, which is the `OP_RETURN` carrying the challenger's EVM address used to claim reimbursement from the operator's Citrea collateral. Any Bitcoin mempool observer can copy the pre-signed signature, substitute their own EVM address in the `OP_RETURN`, and broadcast the modified transaction with a higher fee, stealing the reimbursement credit while the original challenger bears the full `operator_challenge_amount` cost (2 BTC in the default paramset).

---

### Finding Description

**Sighash mapping — the root cause:**

`NormalSignatureKind::Challenge` is mapped in `deposit_signature_owner.rs`:

```rust
Challenge => Ok(OperatorSharedDeposit(SinglePlusAnyoneCanPay)),
``` [1](#0-0) 

`OperatorSharedDeposit(SinglePlusAnyoneCanPay)` means the operator pre-signs the Challenge UTXO spend during deposit setup with `TapSighashType::SinglePlusAnyoneCanPay`. Under BIP-341 `SIGHASH_SINGLE`, the signature commits to the output whose index equals the input index. The Challenge tx has one input (index 0), so the signature covers **output 0 only**.

**Challenge transaction structure:**

```rust
pub fn create_challenge_txhandler(…) {
    let mut builder = TxHandlerBuilder::new(TransactionType::Challenge)
        .add_input(
            NormalSignatureKind::Challenge,          // SIGHASH_SINGLE|ANYONECANPAY
            kickoff_txhandler.get_spendable_output(UtxoVout::Challenge)?,
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_partial(TxOut {   // output 0 — COVERED by sig
            value: paramset.operator_challenge_amount,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }));

    if let Some(challenger_evm_address) = challenger_evm_address {
        builder = builder.add_output(UnspentTxOut::from_partial(op_return_txout(
            challenger_evm_address.0,                // output 1 — NOT covered by sig
        )));
    }
``` [2](#0-1) 

The challenger's EVM address is placed in output 1 (OP_RETURN). Because `SIGHASH_SINGLE` only covers output 0, output 1 is entirely unconstrained by the pre-signed operator signature.

**Where the EVM address is embedded:**

The verifier's own EVM address is inserted at transaction-creation time in `creator.rs`:

```rust
let challenge_txhandler = builder::transaction::create_challenge_txhandler(
    get_txhandler(&txhandlers, TransactionType::Kickoff)?,
    &operator_data.reimburse_addr,
    context.signer.map(|s| s.get_evm_address()).transpose()?,  // verifier's EVM addr
    paramset,
)?;
``` [3](#0-2) 

**Attack path:**

1. Attacker monitors the Bitcoin mempool for a `Challenge` transaction (identifiable by spending `UtxoVout::Challenge` from a known kickoff txid).
2. Attacker extracts the pre-signed operator Schnorr signature from the witness.
3. Attacker constructs a new transaction with the same input and output 0 (operator reimbursement, unchanged), but replaces output 1's OP_RETURN data with their own EVM address.
4. Because `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` does not cover output 1, the copied signature remains valid over the modified transaction.
5. Attacker broadcasts with a higher fee (RBF is enabled — the transaction uses `NON_STANDARD_V3`).
6. The attacker's version is mined. The Citrea bridge contract reads the OP_RETURN EVM address from the on-chain Challenge tx and credits the attacker's address for reimbursement from the operator's collateral.

---

### Impact Explanation

- The original challenger paid `operator_challenge_amount` (default: 200,000,000 sat = 2 BTC) to the operator via output 0. This cost is irrecoverable.
- The Citrea bridge contract uses the EVM address in the on-chain OP_RETURN to determine who receives the challenger reimbursement from the operator's locked collateral. With the attacker's address substituted, the attacker receives the full reimbursement.
- The original challenger suffers a net loss equal to `operator_challenge_amount` (2 BTC at default paramset) with no compensation.
- Bridge safety is not broken (the challenge still fires), but the economic incentive for honest challengers is destroyed: any verifier who challenges a malicious operator will have their reward stolen, removing the rational incentive to challenge at all. This degrades liveness of the fraud-detection mechanism.

---

### Likelihood Explanation

The attack requires only passive mempool monitoring and the ability to broadcast a Bitcoin transaction with a higher fee. No privileged access, no key material, and no special protocol knowledge beyond reading the transaction structure is needed. The pre-signed operator signature is publicly visible in the mempool witness. The attack is deterministic and repeatable for every Challenge transaction broadcast.

---

### Recommendation

Change the sighash type for the Challenge input from `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` to `SIGHASH_ALL` (or `SIGHASH_DEFAULT`). This causes the signature to commit to all outputs, including the OP_RETURN at output 1, making it impossible to substitute the challenger's EVM address without invalidating the signature.

Concretely, in `deposit_signature_owner.rs`:

```rust
// Before:
Challenge => Ok(OperatorSharedDeposit(SinglePlusAnyoneCanPay)),

// After:
Challenge => Ok(OperatorSharedDeposit(SighashDefault)),
``` [1](#0-0) 

Because the operator pre-signs the Challenge tx during deposit setup (before the challenger's EVM address is known), the design must be reconsidered: either the operator signs a fixed output set that includes a placeholder for the EVM address (and the EVM address is committed via a hash in the script), or the challenge UTXO script is changed to require the challenger to provide their own signature (binding the EVM address to the spend). The simplest fix is to make the Challenge UTXO spendable only by a script that requires the challenger to sign with their own key, so the EVM address in the OP_RETURN is bound to the challenger's identity.

---

### Proof of Concept

1. Deploy Clementine in regtest with a malicious operator (set `disrupt_payout_tx_block_hash_commit = true` in test params).
2. Wait for a verifier to broadcast a `Challenge` transaction to the Bitcoin mempool.
3. Extract the transaction from the mempool. Observe that input 0 carries a 65-byte Schnorr signature with sighash byte `0x85` (`SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`).
4. Construct a new transaction: same version, same input (same outpoint, same sequence, same witness), same output 0 (operator reimbursement), but replace output 1's OP_RETURN data with an attacker-controlled 20-byte EVM address.
5. Verify the original signature is still valid over the new transaction (it is, because `SIGHASH_SINGLE` does not cover output 1).
6. Broadcast the modified transaction with a fee rate 1 sat/vbyte higher than the original.
7. Mine a block. Confirm the attacker's transaction is included.
8. Observe that the Citrea bridge contract records the attacker's EVM address as the challenger entitled to reimbursement from the operator's collateral, while the original verifier receives nothing.
