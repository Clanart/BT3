### Title
Unbounded recursive AccountKey decoding causes unrecoverable stack-overflow crash from a single submitted transaction - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively invokes `AccountKeySerializer.DecodeRLP` for every sub-key it contains, and that serializer will in turn call `AccountKeyRoleBased.DecodeRLP` again if the sub-key's declared type is also `AccountKeyTypeRoleBased`. There is no depth limit enforced anywhere in this decode chain, so a single crafted `TxTypeAccountUpdate` (or `TxTypeAccountCreation`/fee-delegated variants) transaction containing a deeply self-nested `AccountKeyRoleBased` structure can drive the decoder into unbounded recursion. This mirrors the CVE-2018-3133 bug class: a parser that accepts attacker-controlled, deeply nested/malformed input and crashes the server process before any semantic validation is performed.

### Finding Description
`AccountKeySerializer.DecodeRLP` dispatches purely on the RLP-decoded `keyType` byte and unconditionally calls `s.Decode(serializer.key)` for whatever `AccountKey` implementation `NewAccountKey` returns: [1](#0-0) 

When `keyType == AccountKeyTypeRoleBased`, this recurses into `AccountKeyRoleBased.DecodeRLP`, which decodes a list of raw byte strings and, for each one, allocates a *fresh* `AccountKeySerializer` and calls `rlp.DecodeBytes` on it — recursively re-entering the same dispatch logic with no depth counter or nesting guard: [2](#0-1) 

The only place nested/composite keys are rejected is `CheckInstallable`/`CheckUpdatable`, which explicitly reject nested composite (including `RoleBased`) keys via `IsCompositeType()`/`ErrNestedCompositeType`: [3](#0-2) 

Critically, these checks run *after* the entire structure has already been fully RLP-decoded — they do not bound the depth of the decode itself. The underlying `rlp` package also contains no generic recursion/depth limit for `Decoder`-implementing types (`rlp.Decode`/`DecodeBytes` simply dispatch to the registered `DecodeRLP` method): [4](#0-3) 

This decode path is reached the moment any node (validator or public RPC full node) attempts to decode a submitted transaction whose `TxInternalData` contains an `AccountKeySerializer` field — i.e., `TxInternalDataAccountUpdate`, `TxInternalDataAccountCreation`, `TxInternalDataFeeDelegatedAccountUpdate`, etc. Transaction decoding itself is unconditionally triggered for any transaction entering the mempool via `eth_sendRawTransaction`/`kaia_sendRawTransaction` or via `handleTxMsg`, since `TxInternalDataSerializer.DecodeRLP` calls `s.Decode(serializer.tx)` before any semantic validation: [5](#0-4) 

Because each nesting level only costs a small constant number of RLP bytes (list header + type byte + wrapped bytes), an attacker can encode many thousands of nesting levels within ordinary transaction size limits, driving Go's runtime into a stack-overflow condition. Unlike an ordinary `panic`, a Go stack-overflow is a *fatal* runtime error that cannot be intercepted by `recover()`, so it will crash the entire node process — not just the handling goroutine.

### Impact Explanation
A single unprivileged transaction submitted through public RPC (`eth_sendRawTransaction`) or received via the tx-propagation p2p path is decoded on every node that receives it (RPC node and, upon propagation, validator nodes) before any signature/semantic validation occurs. A successful stack-overflow abort would crash the receiving node process, producing a denial-of-service that can propagate network-wide as the transaction is gossiped, directly analogous to the "hang or frequently repeatable crash (complete DoS)" impact described in CVE-2018-3133.

### Likelihood Explanation
The attack requires only crafting a nested RLP byte-string structure and submitting it as a normal transaction — no privileged role, valid signature verification bypass, or contract deployment is needed (only the raw transaction bytes need to parse through `DecodeRLP`; signature validity is checked only after decode succeeds/fails). The main variable is confirming the exact recursion depth achievable within tx-size and gas-limit constraints before the runtime actually overflows the stack, which requires empirical testing (Go's stack can grow up to a large maximum before overflowing, so depth requirements could be significant but achievable given typical max transaction/RLP list sizes).

### Recommendation
Add an explicit recursion/nesting depth counter (or reject non-flat structures) in `AccountKeySerializer.DecodeRLP`/`AccountKeyRoleBased.DecodeRLP`, rejecting any `AccountKeyTypeRoleBased` value nested inside another `AccountKeyTypeRoleBased` (or beyond a small fixed depth) *during decode*, not only during later `CheckInstallable`/`CheckUpdatable` validation. Consider also imposing a general recursion depth limit in the `rlp` package's custom-`Decoder` dispatch path to defend other composite types against the same class of attack.

### Proof of Concept
1. Recursively build a byte-serialized `AccountKeySerializer` blob `B0` for a leaf key (e.g., `AccountKeyNil`).
2. Wrap `B0` in an `AccountKeyRoleBased`-typed serializer: `B1 = rlp.EncodeToBytes(AccountKeySerializer{keyType: RoleBased, key: RoleBased{decodeOf(B0)}})` — repeat this wrapping N times (`B1`, `B2`, ..., `Bn`), each time nesting the previous serialized bytes as the sole role-key entry of a new `AccountKeyRoleBased`.
3. Construct a `TxInternalDataAccountUpdate` (or `AccountCreation`) transaction whose `Key` field is the final `Bn` blob, sign it normally, RLP-encode the full transaction, and submit it via `eth_sendRawTransaction`.
4. On receipt, `Transaction.DecodeRLP` → `TxInternalDataSerializer.DecodeRLP` → `TxInternalDataAccountUpdate` decode → `AccountKeySerializer.DecodeRLP` → recursively unwinds all N nested `AccountKeyRoleBased.DecodeRLP` calls before any validation, driving Go's call stack to overflow once N is sufficiently large, crashing the node process.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (s *Stream) Decode(val interface{}) error {
	if val == nil {
		return errDecodeIntoNil
	}
	rval := reflect.ValueOf(val)
	rtyp := rval.Type()
	if rtyp.Kind() != reflect.Ptr {
		return errNoPointer
	}
	if rval.IsNil() {
		return errDecodeIntoNil
	}
	decoder, err := cachedDecoder(rtyp.Elem())
	if err != nil {
		return err
	}

	err = decoder(s, rval.Elem())
	if decErr, ok := err.(*decodeError); ok && len(decErr.ctx) > 0 {
		// Add decode target type to error so context has more meaning.
		decErr.ctx = append(decErr.ctx, fmt.Sprint("(", rtyp.Elem(), ")"))
	}
	return err
}

func (serializer *TxInternalDataSerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.txType); err != nil {
		// fallback to the original transaction decoding.
		txd := newEmptyTxInternalDataLegacy()
		if err := s.Decode(txd); err != nil {
			return err
		}
		serializer.txType = TxTypeLegacyTransaction
		serializer.tx = txd
		return nil
	}

	if serializer.txType == EthereumTxTypeEnvelope {
		var ethType TxType
		if err := s.Decode(&ethType); err != nil {
			return err
		}
		serializer.txType = serializer.txType<<8 | ethType
	}

	var err error
	serializer.tx, err = NewTxInternalData(serializer.txType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.tx)
}
