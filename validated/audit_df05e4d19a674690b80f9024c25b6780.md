## Analysis

The reported bug class — a "not found" sentinel (`0`) that collides with a legitimate value (index/address `0`) — has a direct, exploitable analog in the Tron variant of `IntentGatewayV2`.

### Title
Unregistered-instance fallback to `address(this)` lets an attacker forge cross-chain gateway authentication - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2` (Tron variant) resolves the trusted remote-gateway address for a source state machine via `_instances[keccak256(stateMachineId)]`, an `address` mapping whose default (unset) value is `address(0)`. Instead of treating `address(0)` as "no instance registered" and rejecting the message, `instance()` silently substitutes the *contract's own address* as the trusted counterpart: [1](#0-0) 

This is exactly the H-02 bug class: `0` (the mapping's zero-value / "not found" indicator) is conflated with a meaningful value — here, "trust myself" — instead of being reserved as a distinct not-found signal.

### Finding Description
`authenticate()` uses `instance(request.source)` to decide whether an incoming ISMP request came from a trusted `IntentGatewayV2` deployment on the claimed source chain: [2](#0-1) 

For any `stateMachineId` that governance has *not yet* registered via the admin-only instance-registration path, `_instances[keccak256(stateMachineId)]` is `address(0)` (Solidity's default), so `instance()` returns `address(this)` — the local gateway's own address — rather than reverting. `authenticate()` then only checks `request.from == address(this)`.

Since `IntentGatewayV2` (like other Hyperbridge apps in this codebase, e.g. `HyperbridgeLzEndpoint`, which explicitly documents "Assumes the same contract address on all chains (CREATE2 deployment)") is deployed at the *same address* across chains via CREATE2, an attacker can permissionlessly deploy an arbitrary malicious contract to that identical address on any EVM-compatible chain that Hyperbridge already has consensus/state proofs for but where the *official* `IntentGatewayV2` has not yet been deployed/registered as a known instance. From that malicious contract the attacker dispatches a forged ISMP `PostRequest` whose `from` field is that same address. On the destination chain, `instance(unregisteredSource)` returns `address(this)`, `module == request.from`, and `authenticate()` passes — even though no legitimate gateway exists on that source chain.

Contrast this with the (already-hardened) main EVM implementation, which explicitly documents and enforces the correct behavior — reverting instead of defaulting: [3](#0-2) 

The Tron variant did not receive this fix, leaving the "not found ⇒ trust self" fallback in place. This mirrors the reported "index != uint(-1)" flaw: the zero default is silently treated as a valid, trusted state instead of being an explicit not-found sentinel.

### Impact Explanation
Once `authenticate()` is bypassed, the attacker's forged request is routed to `onAccept`'s `RequestKind` dispatch, which includes highly privileged actions:
- `RedeemEscrow` — release escrowed solver/user funds to an attacker-chosen beneficiary.
- `RefundEscrow` — force refunds, potentially double-releasing already-settled escrow.
- `UpdateParams` — rewrite `Params` (dispatcher, fee config, price oracle, solver-selection toggle).
- `SweepDust` — sweep protocol dust to an attacker address.
- `UpgradeContract` — upgrade the ERC-1967 proxy implementation, i.e., full contract takeover. [4](#0-3) 

This satisfies the bounty's "unauthorized transaction/execution," "logic attacks," and potentially "stealing or loss of funds" / cross-chain admin reachability criteria — all reachable by an unprivileged attacker with no relayer/prover/governance collusion, only the ability to deploy a contract on a not-yet-onboarded source chain.

### Likelihood Explanation
Likelihood is high in any environment where the Tron `IntentGatewayV2` is live before every intended source chain has completed instance registration (the documented deployment workflow — deploy, then explicitly register via `NewDeployment`/admin call — implies a window where chains are consensus-supported but not yet registered as instances). Any such "not yet onboarded" chain becomes an open door for this authentication bypass; the attacker only needs the ability to CREATE2-deploy a contract to the predetermined gateway address on that chain, which is unprivileged.

### Recommendation
Change `instance()` to explicitly revert (mirroring the fixed main EVM contract) when no instance is registered, instead of defaulting to `address(this)`:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```
If self-trust for the local chain's own state machine ID is intentionally desired, gate that case explicitly (e.g., `stateMachineId == host().host()`) rather than using the zero-default of the mapping as an implicit "trust self" signal.

### Proof of Concept
1. Identify a state machine `S` that Hyperbridge has consensus support for (state proofs verifiable) but for which `IntentGatewayV2` (Tron) has no registered `_instances[keccak256(S)]` entry (governance hasn't called the registration path yet for `S`).
2. Compute the deterministic address `G` at which the Tron `IntentGatewayV2` would be deployed via CREATE2 (the same address used across chains).
3. On chain `S`, deploy an attacker-controlled contract to address `G` (no contract currently occupies it there) that can dispatch arbitrary ISMP `PostRequest`s with `from = G`.
4. From that contract, dispatch a `PostRequest` to the Tron gateway with `body` encoding a `RequestKind.RedeemEscrow` (or `UpgradeContract`) instruction targeting attacker-controlled parameters.
5. On the Tron destination, `authenticate()` calls `instance(S)`; since `_instances[keccak256(S)] == address(0)`, it returns `address(this) == G`; `request.from` decodes to `G`; the check `instance(request.source) != module` passes, and the forged instruction executes. [5](#0-4)

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
