## Confirmed Vulnerability

The proof concept is correct. Looking at `onAccept` in `evm/src/apps/BandwidthManager.sol`: [1](#0-0) 

The only authentication performed is `onlyHost` (verifying the call comes from the local `IsmpHost`) and `request.source.equals(IDispatcher(_host).hyperbridge())`. Critically, `request.from` — the field that identifies *which module on the source chain* dispatched the message — is never checked against `PALLET_BANDWIDTH_MODULE_ID` or any other expected sender identity.

`request.source` is a `StateMachineId` (chain identifier), not a module identity, and `hyperbridge()` is a public, non-secret constant readable via `IDispatcher(_host).hyperbridge()` [2](#0-1) . This is confirmed by the test suite itself, which builds governance requests with `source: h.hyperbridge()` and an arbitrary, unchecked `from: bytes("hyperbridge-governance")`: [3](#0-2) 

Since the `IsmpModule` routing on the substrate side dispatches to `onAccept` based on the destination module id (`to = PALLET_BANDWIDTH_MODULE_ID`) and the local host only checks `onlyHost` + `request.source`, **any module/pallet deployed on the hyperbridge parachain** can craft and dispatch a `PostRequest` with `to = "BWMARKET"` and an arbitrary `from`, and it will be routed to `BandwidthManager.onAccept`, pass the sole `source` check, and execute the `Withdraw` or `SetTiers` branch to completion — draining the contract's fee-token/native balance to an attacker-chosen beneficiary.

### Title
Missing `request.from` module-identity binding in `BandwidthManager.onAccept` allows any hyperbridge-chain module to trigger governance actions (Withdraw/SetTiers) - (`evm/src/apps/BandwidthManager.sol`)

### Summary
`onAccept` authenticates inbound governance messages solely by checking that `request.source` equals the (public, non-secret) `hyperbridge()` chain id. It never validates `request.from` against the expected pallet module id, so any module on the hyperbridge parachain — not just `pallet-bandwidth` — can dispatch a message with `to = PALLET_BANDWIDTH_MODULE_ID` and arbitrary `from`, satisfying the sole check and reaching the `Withdraw`/`SetTiers` branches.

### Finding Description
`onAccept` performs:
```solidity
if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();
```
This only binds the *chain* the message originated from, not the *module* that dispatched it. `request.from` (the sender module identity on the source chain) is decoded and used nowhere in the function. `PALLET_BANDWIDTH_MODULE_ID = bytes("BWMARKET")` is declared as the value the pallet must use on the *destination* side (`to` field on outbound `purchase()` dispatches from `BandwidthManager`), but there is no reciprocal check that inbound messages actually originate `from` that same pallet id on the hyperbridge chain. Because `hyperbridge()` is a public constant obtainable via `IDispatcher(_host).hyperbridge()`, an attacker's own on-chain module (any pallet/contract capable of dispatching an ISMP `PostRequest` on the hyperbridge parachain, addressed `to = "BWMARKET"`) can produce a request with `source == hyperbridge()` and `from = <attacker-controlled bytes>`, which will pass the single authentication check.

### Impact Explanation
This breaks module-identity binding on a shared governance channel, enabling unauthorized execution of privileged actions: draining the contract's ERC20/native balances via `Withdraw` to an attacker-chosen `beneficiary`/`amount`, or corrupting `tierPrice` via `SetTiers`. This is unauthorized transaction/execution and direct loss of funds, matching the bounty's "unauthorized execution" and "stealing or loss of funds" categories.

### Likelihood Explanation
Exploitability depends on whether an attacker can get an arbitrary module on the hyperbridge parachain to dispatch a `PostRequest` with `to = "BWMARKET"` and pass it through the standard ISMP relaying/proof-verification pipeline to the EVM host, which is a routing/identity-binding gap rather than requiring any compromised relayer or malicious infrastructure — the request itself, once correctly proven and relayed, is legitimate on the wire but illegitimate in module identity.

### Recommendation
Add an explicit check binding `request.from` to the expected pallet module id on the hyperbridge chain (analogous to `PALLET_BANDWIDTH_MODULE_ID` used for outbound `to`), e.g.:
```solidity
if (!request.from.equals(EXPECTED_PALLET_FROM_ID)) revert UnauthorizedAction();
```
so both chain (`source`) and module (`from`) identity are validated before acting on the message.

### Proof of Concept
Using the existing test harness pattern in `evm/tests/foundry/BandwidthManagerTest.t.sol`, construct an `IncomingPostRequest` where `request.source = host.hyperbridge()` (matches `_governanceRequestFor`) but `request.from` is set to arbitrary attacker bytes instead of the real pallet's module id, with a `Withdraw` body draining `feeToken`/native balance to an attacker address:
```solidity
IncomingPostRequest memory malicious = IncomingPostRequest({
    request: PostRequest({
        source: host.hyperbridge(),            // public constant, not secret
        dest: host.host(),
        nonce: 0,
        from: bytes("attacker-controlled"),      // never validated
        to: PALLET_TO,                           // routes to BandwidthManager
        timeoutTimestamp: 0,
        body: bytes.concat(
            bytes1(uint8(BandwidthManager.OnAcceptActions.Withdraw)),
            abi.encode(Withdrawal({token: address(feeToken), beneficiary: ATTACKER, amount: manager balance}))
        )
    }),
    relayer: address(0)
});
vm.prank(address(host));
manager.onAccept(malicious); // succeeds; funds sent to ATTACKER
```
This mirrors `testGovernanceCanWithdrawAcrossTokenSwap` but with `from` set to attacker-controlled bytes — the assertion that `Withdrawn`/transfer still executes would confirm the missing binding.

```text
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
```
