### Title
Payout attribution can be hijacked via SIGHASH_SINGLE|ANYONECANPAY replay, permanently freezing a vault UTXO's reimbursement path - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx` that fronts a Citrea withdrawal is authorized by a single user signature using `SIGHASH_SINGLE|ANYONECANPAY`. This sighash type binds only input #0 to output #0; it does not cover any additional funding inputs or the OP_RETURN output that records which operator's `xonly_pk` is credited for fronting the withdrawal. Because the transaction is broadcast with RBF enabled, its witness becomes publicly observable in the mempool before confirmation, letting anyone replace it with a competing transaction that pays the exact same user output but attaches arbitrary/garbage OP_RETURN data. Once that competing transaction confirms, the DB permanently records a broken payer attribution, and no operator can ever be validated as the payer for that deposit again — freezing the deposit's `MoveToVault` UTXO out of the normal reimbursement flow.

### Finding Description
`create_payout_txhandler` builds the payout transaction with three outputs — the user payout, an anchor, and an OP_RETURN carrying the fronting operator's `xonly_pk` — but signs only output #0 via the user's presigned signature: [1](#0-0) 

The RPC layer enforces that the user's signature must be `SinglePlusAnyoneCanPay`: [2](#0-1) 

`SIGHASH_SINGLE|ANYONECANPAY` semantics mean the signature commits to: (a) exactly one input (the one it's attached to), and (b) exactly one output — the one at the same index as that input (index 0, the user payout). It commits to nothing about any other input added to the transaction, and nothing about outputs at index ≥1 — including the OP_RETURN output that records `payout_payer_operator_xonly_pk`. The operator funds the transaction by adding extra inputs via `fund_raw_transaction`/RBF-funding: [3](#0-2) 

Payout transactions are explicitly queued with `FeePayingType::RBF`, and the tx-sender always funds/broadcasts RBF-eligible transactions with `replaceable: Some(true)`: [4](#0-3) [5](#0-4) 

This means the operator's original payout transaction sits in the public mempool, RBF-signaled, before confirmation. Any unprivileged observer can extract the witness (the `SIGHASH_SINGLE|ANYONECANPAY` signature over input #0/output #0 only) and construct their own conflicting transaction that: (1) spends the same withdrawal input, (2) reuses the identical, already-signed output #0 (satisfying the user, since that part is cryptographically fixed), but (3) supplies its own funding inputs and (4) sets an arbitrary or absent value in the OP_RETURN output — since neither is covered by the user's signature. If this attacker transaction confirms instead of the original (via higher fee / RBF), `update_finalized_payouts` will parse whatever OP_RETURN content is present (or `None` if invalid/absent) and persist it as the permanent payer attribution: [6](#0-5) [7](#0-6) 

`validate_payer_is_operator`, used by every reimbursement path (`get_reimbursement_txs`, `PayoutCheckerTask`), strictly requires `payout_payer_operator_xonly_pk == self.signer.xonly_public_key`: [8](#0-7) [9](#0-8) 

If the attribution is corrupted (wrong pubkey or `None`), this check fails for every operator, forever — there is no repair path in the codebase for a mis-attributed `payout_payer_operator_xonly_pk`. Because the deposit's `MoveToVault` UTXO can only be released via the `Reimburse` transaction that is gated behind a valid, matching kickoff for the payer operator, the vault funds become permanently unreachable through the intended protocol flow. This directly breaks the intended binding "the operator credited (OP_RETURN payer) versus the party that actually paid the user" — an unprivileged party observing the mempool can pay the user's fixed output themselves and dictate mismatched/garbage attribution, without ever needing an operator, verifier, or aggregator role.

### Impact Explanation
Critical: once a malicious replacement transaction with corrupted OP_RETURN attribution confirms, the affected deposit's `MoveToVault` UTXO is permanently frozen — no legitimate operator can ever satisfy `validate_payer_is_operator` for that deposit, so the reimbursement (`Reimburse` tx) can never be constructed/sent through the automated or manual (`GetReimbursementTxs`) flow. This is listed explicitly as a Critical impact category ("a vault UTXO permanently frozen").

### Likelihood Explanation
The attacker only needs to observe the Bitcoin mempool for the RBF-flagged `payout_tx` (a normal, expected event for every withdrawal) and win an RBF fee race with a transaction that pays the exact same fixed user output while substituting its own OP_RETURN content and funding inputs. No cryptographic secret, operator credential, or privileged role is required — only the ability to build and broadcast a standard Bitcoin transaction with sufficient fee, and the capital to cover the (fixed, unavoidable) user payout amount, which the attacker would need to pay in any case to win the race.

### Recommendation
Bind the OP_RETURN (operator attribution) output and all funding inputs to the same signature that authorizes the user payout, e.g. by having the user sign with `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY` if additional operator-controlled inputs must remain flexible but outputs must be fully committed), or by having the operator itself pre-commit/cosign the OP_RETURN output content so that no unrelated party can rewrite payer attribution while satisfying the same user-facing output. Additionally, add a DB-level and protocol-level recovery/dispute path so that a `withdrawals` row with `payout_payer_operator_xonly_pk` set to a non-operator or otherwise invalid value can still be reclaimed by the legitimate operator, rather than being permanently unreimbursable.

### Proof of Concept
Conceptual sequence (concrete field-level PoC would require constructing raw Bitcoin transactions against a regtest instance, which is outside static analysis but is directly supported by the cited code):
1. Operator A calls `withdraw`/`internal_withdraw`, producing and broadcasting a `payout_tx` funded via `fund_raw_transaction` with RBF enabled (per `core/src/operator.rs:639-674` and `core/src/tx_sender_queue.rs:92-104`), paying the user's fixed output #0 and OP_RETURN = Operator A's `xonly_pk`.
2. Attacker (no operator role) observes this tx in the mempool, extracts the `SIGHASH_SINGLE|ANYONECANPAY` witness for input #0/output #0.
3. Attacker constructs a replacement transaction: same input #0 (withdrawal UTXO) with the same extracted witness, same output #0 (user payout — unchanged since that's what's signed), but with attacker's own funding input(s) and either no OP_RETURN or an invalid/mismatched OP_RETURN payload, and broadcasts it with a higher fee (RBF).
4. Attacker's transaction confirms instead of Operator A's.
5. `update_finalized_payouts` (`core/src/verifier.rs:2312-2350`) records `operator_xonly_pk = None` (or an unrelated key) in the `withdrawals` table via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`).
6. Every subsequent call to `validate_payer_is_operator` (`core/src/operator.rs:1687-1740`) for this deposit fails for all operators, and `PayoutCheckerTask` (`core/src/task/payout_checker.rs:41-47`) never surfaces this withdrawal as "unhandled" for any operator — the `MoveToVault` UTXO is permanently unreachable via the reimbursement path.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
