### Title
`ReceivedOutput::read` accepts an arbitrary `(offset, script_pubkey)` pair, letting an attacker claim an output under an offset that does not correspond to its key — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput` couples a scalar `offset` (which defines the key able to spend the output via `key + offset·G`) with a `TxOut`/`OutPoint`. `ReceivedOutput::read` deserializes all three fields independently and performs no consistency check that `p2tr_script_buf(key + offset·G)` equals `output.script_pubkey`. This mirrors the report's bug class: an object that grants "ownership" of an asset (here, the spendable-key claim over a UTXO) can be constructed by anyone supplying raw bytes, because the deserialization path never validates that the claimed relationship actually holds on-chain.

### Finding Description
`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F` and then consensus-decodes an arbitrary `TxOut` and `OutPoint`, returning them as a coherent spendable output [1](#0-0) . Nothing in `read`, `write`, or the struct ties `offset` to `output.script_pubkey` [2](#0-1) .

The offset is the sole determinant of which tweaked key spends the input: `SignableTransaction::new` copies `input.offset` into `offsets` [3](#0-2) , and `multisig` builds the signing machine from `keys.clone().offset(self.offsets[i])`, returning `None` when the derived script doesn't match the prevout [4](#0-3) . Separately, `Output::key()` recovers the owning group key as `scriptKey − offset·G`, so a mismatched offset also misattributes the output to a different key [5](#0-4) .

Because `read` is the canonical ingestion point for untrusted bytes, an attacker (or corrupted/Forge-fed source) can submit a `ReceivedOutput` naming any real on-chain outpoint plus a forged offset. The output is accepted as a spendable input, but no `ThresholdKeys`/`offset` combination exists that satisfies `multisig`, so the funds are permanently unspendable through this wallet while still being reported as received — and may additionally be attributed to the wrong group key via `Output::key()`.

### Impact Explanation
Funds reported received that are not spendable: the wallet/scanner layer accepts the output and its value (`value()`, `balance()`), yet `SignableTransaction::multisig` can never produce a signing machine for it since `p2tr_script_buf(offset.group_key()) != prevout.script_pubkey` for any wrong offset [6](#0-5) . Outputs can also be misattributed across keys via `Output::key()`, causing spend plans to be built against the wrong multisig.

### Likelihood Explanation
Requires feeding crafted bytes into `ReceivedOutput::read` (or the `Output::read` path that wraps it [7](#0-6) ), which is a listed untrusted-bytes sink. Any channel deserializing received outputs (DB recovery, peer/processor messages, RPC-supplied data) without re-deriving the offset from a `Scanner` is exposed. Medium likelihood, Medium impact (fund liveness / misattribution, no key leakage).

### Recommendation
In `ReceivedOutput::read` (or a validating constructor), take the expected group `key` and verify `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)` before accepting the output; alternatively store only the `OutPoint`/`TxOut` and always re-derive `offset` via `Scanner::scan_transaction` so the offset is always computed, never claimed.

### Proof of Concept
```rust
// Given a real on-chain outpoint paying to script S for key K + o*G,
// craft bytes claiming it under offset o' != o:
let mut buf = vec![];
buf.extend(forged_offset.to_repr().as_ref());          // arbitrary scalar
buf.extend(serialize(&txout));                          // real TxOut (script_pubkey = S)
buf.extend(serialize(&outpoint));                       // real OutPoint
let ro = ReceivedOutput::read(&mut buf.as_slice()).unwrap(); // accepted — no check

// ro is now reported as a received output worth txout.value,
// but SignableTransaction::new(vec![ro], ...).multisig(&keys)
// returns None for every ThresholdKeys set, since
// p2tr_script_buf((keys.offset(o')).group_key()) != S.
// Output::key() additionally attributes it to key + (o'-o)*G.
```

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
