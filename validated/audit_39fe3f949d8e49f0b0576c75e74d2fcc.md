## Title
Server-Side Request Forgery via unauthenticated on-chain "mirror" coin URLs causes DataLayer node to make outbound HTTP requests to attacker-chosen hosts/ports - (File: `chia/data_layer/data_layer_wallet.py`)

### Summary
Any party who can submit a spend bundle can create a `create_mirror_puzzle()` coin whose `CREATE_COIN` memo encodes an arbitrary `launcher_id` and an arbitrary list of URL strings. If a victim's wallet is tracking that `launcher_id` (i.e., they subscribe to or own that DataLayer store — a normal, expected DataLayer use case), the wallet's `coin_added` handler unconditionally records those attacker-supplied URLs as a `Mirror`. The DataLayer service later pulls these URLs and uses them as download server endpoints, issuing `aiohttp` GET requests to them with no scheme/host/port restriction — a direct analog of the CVE-2020-24140 SSRF pattern where attacker-controlled URL input triggers server-initiated outbound requests, enabling internal port/host probing.

### Finding Description
`create_mirror_puzzle()` is a public, unrestricted puzzle (`P2_PARENT.curry(Program.to(1))`) that anyone can pay a coin to: [1](#0-0) 

`get_mirror_info()` extracts the `launcher_id` and raw URL bytes from the `CREATE_COIN` memo of *any* spend that creates a coin with this puzzle hash — there is no origin check, no signature requirement tying the memo to a particular launcher owner, and no URL validation (scheme, host, or otherwise): [2](#0-1) 

`DataLayerWallet.coin_added()` observes every coin on-chain matching this puzzle hash, and — as long as the local wallet is already tracking that `launcher_id` — decodes and stores the attacker-controlled URLs into the local `Mirror` table without any validation of the URL contents: [3](#0-2) 

The DataLayer service subsequently reads these wallet-reported mirrors and stages them as subscription server URLs: [4](#0-3) 

`fetch_and_validate()` iterates these `servers_info` entries (in randomized order) and attempts to download delta files from each `url`: [5](#0-4) 

The actual network call is made in `http_download()`, which performs an unrestricted `aiohttp` `session.get(server_info.url + "/" + filename, ...)` — no allow-list, no check against private/internal IP ranges (e.g. `127.0.0.1`, `169.254.169.254`, RFC1918 ranges), and no scheme restriction beyond what aiohttp itself supports: [6](#0-5) 

This mirrors the CVE's root cause exactly: a request-triggering parameter (`pagename`/URL) that is attacker-controlled flows unchecked into a server-side outbound HTTP request, letting the attacker use the victim's node as an SSRF proxy to probe internal hosts/ports or interact with local-only services.

### Impact Explanation
Any unprivileged actor who can submit a spend bundle (no keys, no special coin ownership required — a `create_mirror_puzzle()` coin can be created by anyone spending any coin) can:
- Cause a victim DataLayer node to issue outbound HTTP GET requests to arbitrary attacker-chosen hosts/ports, enabling internal network reconnaissance/port scanning (the primary impact class described in CVE-2020-24140).
- Potentially interact with internal-only HTTP services reachable from the node (e.g., local RPC-adjacent services, cloud metadata endpoints) depending on network placement.
- Repeatedly poison a target's mirror list with many distinct hostile URLs, given `add_mirror`/mirror tracking places no bound validation on URL count/content beyond non-emptiness.

This satisfies the "High" bar because it is a concrete SSRF that is reachable purely by submitting an on-chain spend (no privileged role) against any node that is a DataLayer participant tracking the targeted `launcher_id`, which is normal/expected operation for DataLayer offer/subscription flows. It does not directly cause fund loss but does provide network reconnaissance/pivot capability against operators.

### Likelihood Explanation
High reachability: creating the mirror coin requires only standard XCH and a spend bundle to a known, public puzzle hash (`create_mirror_puzzle().get_tree_hash()`), with no coordination with the victim needed beyond knowing a `launcher_id` the victim is already tracking — `launcher_id`s are inherently public (shared to enable subscription/offers in normal DataLayer usage). The victim's node processes any matching coin automatically via `coin_added()` and later automatically dequeues and fetches from the resulting URLs during its normal sync loop, requiring no user interaction.

### Recommendation
- Validate mirror URLs before persisting/using them: enforce `http(s)://` scheme only, and reject or explicitly flag URLs resolving to loopback, link-local, and private/internal address ranges before allowing the DataLayer service to issue requests to them.
- Consider restricting outbound mirror fetches behind an explicit opt-in/allow-list, or require the local operator to confirm new mirror URLs before they become active download targets.
- Apply DNS-rebinding-safe resolution (resolve then validate the resolved IP, not just the URL host string) at the point of request in `http_download()`.

### Proof of Concept
1. Attacker knows (or discovers) the `launcher_id` of a DataLayer store that a target node is subscribed to/tracking.
2. Attacker submits a standard coin spend creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and a `CREATE_COIN` condition whose memo is `[launcher_id, b"http://127.0.0.1:8555/", b"http://169.254.169.254/latest/meta-data/"]` (see memo layout consumed in `get_mirror_info`, `chia/wallet/db_wallet/db_wallet_puzzles.py:97-110`).
3. This spend is broadcast and confirmed on-chain like any ordinary transaction.
4. Target's `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) detects the coin, calls `get_mirror_info`, and stores the attacker URLs as a tracked `Mirror` since it is tracking `launcher_id`.
5. Target's `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) pulls these URLs into its subscription server list.
6. On the next sync cycle, `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues `GET http://127.0.0.1:8555/<filename>` and `GET http://169.254.169.254/latest/meta-data/<filename>` from the victim node (`chia/data_layer/download_data.py:298-320`), demonstrating SSRF against attacker-chosen internal targets.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope

            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
```
