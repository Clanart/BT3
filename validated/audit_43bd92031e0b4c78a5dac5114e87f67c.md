## Finding

### Title
`safe.directory` trust exception can never be revoked from Desktop, permanently disabling Git's ownership-mismatch guard for a path - (File: `app/src/lib/git/config.ts`)

### Summary
The reported NTT Manager bug is a one-way state transition: `pause()` exists but no `unpause()` does, so once triggered the guarded state can never be reverted through the application itself. The same broken-invariant pattern exists in GitHub Desktop's handling of Git's "dubious ownership" (`safe.directory`) protection: Desktop exposes `addSafeDirectory()` to permanently whitelist a path, but there is no corresponding "untrust"/remove function anywhere in the codebase.

### Finding Description
When Desktop detects a repository whose directory is owned by a different user than the current process, Git itself refuses to operate on it and reports it as "unsafe" (`getRepositoryType` returning `kind: 'unsafe'`). Desktop surfaces a "Trust Repository" action in `MissingRepository` and `AddExistingRepository` that calls `addSafeDirectory`: [1](#0-0) 

which permanently appends the path to the user's **global** `~/.gitconfig` `safe.directory` list: [2](#0-1) 

This call is reachable directly from `onTrustDirectory` in both `MissingRepository` and `AddExistingRepository`: [3](#0-2) [4](#0-3) 

A repository-wide search confirms there is **no** `removeSafeDirectory`, `untrustDirectory`, or any UI/menu affordance that removes an entry from `safe.directory` once added — the only match for "untrust" in the whole codebase is an unrelated feature (`untrusted-certificate.tsx`), and `addSafeDirectory` has exactly one producer and no reverse function. This is precisely the missing-`unpause` invariant: a permissioned/attacker-influenced action (an ownership mismatch) sets a global, permanent exception, and the exception is never re-evaluated or revocable by Desktop.

Once a path is in `safe.directory`, Git's ownership check is bypassed for that literal path forever, on every future invocation regardless of who now owns the directory contents. Trusting a path is a normal, expected user action (e.g., repos on network shares, WSL/Docker mounted paths, multi-account setups) — not an unusual or unsafe workflow by itself.

### Impact Explanation
After the one-time trust action, if the exact same path is later repopulated by different/attacker-controlled content — e.g. a shared drive, mounted network path, container volume, or any directory that is deleted and recreated by another local principal with attacker-controlled `.git/hooks/*` scripts — Desktop will never again show the "appears to be owned by another user" warning for that path, because the ownership check is unconditionally skipped by Git once `safe.directory` contains it. Desktop's hook interception pipeline (`interceptHooks` in `createCommit`, executed via `withHooksEnv`/`hooks-proxy.ts`) will then run any executable hook present in that directory automatically on the user's next commit/checkout/merge, with no re-confirmation step: [5](#0-4) [6](#0-5) 

This yields silent, unprompted code execution under the user's privileges — matching the report's "code execution" impact category — and there is no in-app remediation short of the user manually hand-editing their global `~/.gitconfig`, which is well outside Desktop's own security boundary/UX (directly analogous to needing a contract upgrade to fix the missing `unpause`).

### Likelihood Explanation
The trigger requires a normal, single click of "Trust Repository" on a path the user genuinely believed was safe at the time (common on shared drives, VMs, or WSL mounts) — not admin rights, malware, or leaked credentials. The persistence of the exception is entirely a Desktop design gap (missing reverse operation), so likelihood of the trust grant becoming stale/dangerous grows over time with any environment where paths get reused (shared machines, ephemeral cloud workstations, CI runners reusing home directories, synced folders).

### Recommendation
Add a reciprocal, discoverable "Untrust"/"Revoke trust" action (e.g., in Preferences or a per-repository context menu) that runs `git config --global --unset safe.directory <path>` (mirroring `addGlobalConfigValueIfMissing`), and consider re-validating trust when a previously-trusted directory's owner/inode/creation time changes rather than trusting the path unconditionally forever.

### Proof of Concept
1. On a machine where directory ownership can change (shared drive, WSL path, container mount, multi-user workstation), open a legitimate repository at path `P` owned by another local user; Desktop shows the "unsafe" warning.
2. Click "Trust Repository" — `addSafeDirectory(P)` runs, adding `P` to the global `safe.directory` list permanently (`app/src/lib/git/config.ts:181-189`).
3. At any later time, the content at `P` is replaced (deleted/recreated, another user regains write access, or a symlink/mount is redirected) with a repository containing a malicious `.git/hooks/post-checkout` or `pre-commit` script.
4. The user reopens Desktop, which still has `P` recorded, performs a commit/checkout — Desktop invokes `createCommit`/checkout hook interception without ever re-prompting about ownership, executing the attacker's hook script silently.
5. There is no menu item, setting, or code path in the repository that removes `P` from `safe.directory` to stop this — confirmed via repo-wide search for `removeSafeDirectory`/`untrust`.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}

export async function* getRepoHooks(path: string, filter?: string[]) {
  const hooksPath = await getConfigValue(path, 'core.hooksPath')
    .catch(() => getHooksPath(path))
    .then(p => resolve(path, p))

  const files = await readdir(hooksPath, { withFileTypes: true })
    .then(entries => entries.filter(x => x.isFile()))
    .catch(() => [])

  const matchAll = filter?.includes('*')

  for (const file of files) {
    const hookName = basename(file.name, '.exe')

    if (matchAll || filter?.includes(hookName) === false) {
      continue
    }

    if (!knownHooks.includes(hookName)) {
      continue
    }

    if (__WIN32__) {
      // On Windows we have to assume that any valid hook name is executable
      // because the executable bit is not used there. Git looks for a shebang
      // but that seems expensive to check here :shrug:
      yield hookName
    } else if (await isExecutable(join(file.parentPath, file.name))) {
      yield hookName
    }
  }
