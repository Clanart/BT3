### Title
Remote URL auto-rewrite trusts owner/name-matched GitHub API object instead of verifying repository identity, enabling silent push/fetch redirection (repo-jacking) - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
When Desktop refreshes a repository's metadata, it looks up the associated GitHub repository purely by parsing the existing git remote URL into `owner`/`name` and calling the GitHub API for that `owner/name` pair, then silently rewrites the local git remote URL to whatever `clone_url` the API returns for that pair — with no check that the returned repository is the *same* underlying repository (there is no comparison of a stable numeric GitHub repo ID). If the original `owner/name` combination becomes claimable by a third party (e.g., account rename/deletion followed by re-registration, a classic "repo-jacking" scenario), an attacker who registers that exact `owner/name` controls the GitHub API object Desktop consumes, and Desktop will automatically retarget the user's git remote — and therefore all future `git push`/`git fetch` — to the attacker's repository.

### Finding Description
`repositoryWithRefreshedGitHubRepository` (`app/src/lib/stores/app-store.ts:4874-4914`) resolves the GitHub repository association via `matchGitHubRepository`, which only uses the **current git remote URL's parsed owner/name** (`app/src/lib/stores/app-store.ts:4964-4977`, `app/src/lib/repository-matching.ts:29-46`), then calls `api.fetchRepository(owner, name)` and feeds the resulting `IAPIRepository` into `updateRemoteUrl` (`app/src/lib/stores/app-store.ts:4904-4906`).

`updateRemoteUrl` (`app/src/lib/stores/updates/update-remote-url.ts:7-45`) then:
1. Compares the *current* remote to the *previously stored* `gitHubRepository.cloneURL` (`remoteUrlUnchanged`, line 38-40) — this only detects if the user manually edited the remote, not whether the API-side repository identity changed.
2. Compares protocols (lines 29-34).
3. If protocols match, the remote is "unchanged" from what was last cached, and the new `apiRepo.clone_url` differs from the current remote (`!urlsMatch`), it calls `gitStore.setRemoteURL(...)` (line 43) — silently rewriting the remote to the attacker-controlled `clone_url`, with **no comparison of a stable GitHub numeric repository ID** between the previously known repo and the new `apiRepo`.

The broken invariant: Desktop treats "an API object returned for the same owner/name string" as proof of "the same underlying repository", exactly as the LP burn exploit treats "an LP balance sitting at the pair address" as proof of legitimate ownership/authorization — both substitute a spoofable, attacker-influenceable identifier for a durable identity check.

### Impact Explanation
If an attacker reclaims a deleted/renamed GitHub owner/repo name that a victim's Desktop client still references (this is the well-documented "repo-jacking"/"repository hijacking via retired namespace" class), the victim's next background refresh (`_refreshRepository`, triggered periodically and after most git operations) will silently repoint their `origin` remote to the attacker's `clone_url`. Subsequent pushes exfiltrate the victim's commits/code to the attacker-controlled repository, and subsequent fetches/pulls pull attacker-controlled content into the victim's working tree — a silent corruption of what the user pushes/fetches, matching the "silent corruption of what the user commits or pushes" impact category, without any prompt or confirmation shown to the user.

### Likelihood Explanation
Requires: (1) the original repository's owner/name combination becoming reclaimable (org/user deleted or renamed, or repo renamed/deleted) — a real, previously-exploited GitHub-wide issue class ("repo-jacking") outside Desktop's control; (2) the victim having previously cloned/tracked that repository in Desktop. No local access, no admin rights, and no user interaction beyond Desktop's normal periodic repository refresh is needed once the namespace is reclaimed by the attacker. This is a plausible but conditional path — it depends on an external GitHub-side precondition (namespace reclaim) rather than being purely local-code-triggerable.

### Recommendation
Persist and compare a stable GitHub numeric repository `id` (available on `IAPIRepository`) in addition to `owner`/`name` when deciding whether to auto-update a remote URL. If the `id` returned by the API differs from the previously stored `GitHubRepository`'s known id, treat it as a different repository and do not silently rewrite the remote — surface a warning to the user instead.

### Proof of Concept
1. User clones `https://github.com/some-org/some-repo` in Desktop; Desktop stores `GitHubRepository{owner: some-org, name: some-repo, cloneURL: ...}` keyed only by owner/name (no numeric id persisted, see `app/src/models/github-repository.ts:15-22`).
2. `some-org` is deleted/renamed on GitHub (namespace becomes available).
3. Attacker registers `some-org` and creates a repository named `some-repo`, setting its own `clone_url`.
4. On the victim's next repository refresh, `matchGitHubRepository` re-derives `owner=some-org, name=some-repo` from the unchanged local remote (`app/src/lib/stores/app-store.ts:4964-4977`) and calls `api.fetchRepository('some-org', 'some-repo')`, which now resolves to the attacker's repo object.
5. `updateRemoteUrl` (`app/src/lib/stores/updates/update-remote-url.ts:42-44`) finds `remoteUrlUnchanged === true` (local remote still matches the last cached clone URL) and `urlsMatch === false` (attacker's clone_url differs), and silently calls `gitStore.setRemoteURL('origin', attackerCloneUrl)`.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

  private async matchGitHubRepository(
    repository: Repository
  ): Promise<IMatchedGitHubRepository | null> {
    const gitStore = this.gitStoreCache.get(repository)

    if (!gitStore.defaultRemote) {
      await gitStore.loadRemotes()
    }

    const remote = gitStore.defaultRemote
    return remote !== null
      ? matchGitHubRepository(this.accounts, remote.url)
      : null
  }

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}
