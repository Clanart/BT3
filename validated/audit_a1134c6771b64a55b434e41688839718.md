### Title
Payout OP_RETURN operator attribution is unauthenticated, allowing reimbursement to be misattributed to a party that never funded the withdrawal - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The payout transaction's `OP_RETURN` output, which is used as the sole source of truth for "who fronted this withdrawal" (`payout_payer_operator_xonly_pk`), is raw unsigned data chosen by whoever assembles/broadcasts the payout transaction, not a value cryptographically bound to whoever actually supplied the BTC that pays the user. This breaks the intended binding `operator credited == party that paid`, letting a party who never funded a withdrawal cause an arbitrary operator to be credited as payer and subsequently claim the deposit's reimbursement.

### Finding Description
`create_payout_txhandler` builds the payout transaction with a user-signed input (`SIGHASH_SINGLE|ANYONECANPAY`) and appends an `OP_RETURN` output carrying `operator_xonly_pk`, the "operator's x-only public key that fronts the peg-out": [1](#0-0) 

Because the sighash type is `SIGHASH_SINGLE|ANYONECANPAY`, the user's signature only commits to input 0 and its corresponding output 0 (the user payout). Any party in possession of the user's withdrawal signature (which corresponds to a withdrawal already registered/public on the Citrea side) can independently assemble their *own* copy of this transaction, fund the remaining value from their own wallet via the standard `fund_raw_transaction` flow, and freely choose the bytes placed in the `OP_RETURN`: [2](#0-1) 

This `OP_RETURN` content is never re-validated against who actually supplied the funding inputs. On the verifier side, `update_finalized_payouts` extracts whatever pubkey is embedded in the confirmed payout transaction's `OP_RETURN` and stores it directly as the "payer" for that withdrawal, with no check that the corresponding operator's wallet or key was involved in constructing/funding the transaction: [3](#0-2) [4](#0-3) 

Later, `validate_payer_is_operator` treats this DB-recorded `payout_payer_operator_xonly_pk` as authoritative proof of who fronted the withdrawal, and if it matches an operator's own key, that operator is allowed to proceed through `get_reimbursement_txs` / kickoff and eventually receive the deposit's `DepositInMove` output value via `create_reimburse_txhandler`: [5](#0-4) [6](#0-5) 

Because nothing ties the `OP_RETURN` pubkey to the actual source of the funding UTXOs consumed by `fund_raw_transaction`, any party (an unauthenticated attacker, not necessarily a registered operator) who fronts the user's payout with their own BTC can embed a *different, real* operator's x-only public key in the `OP_RETURN`. That operator is then attributed as "payer" purely from on-chain OP_RETURN bytes, and — with zero funds of their own actually spent on the withdrawal — becomes eligible to claim the deposit's reimbursement through the normal kickoff/reimburse flow.

### Impact Explanation
This breaks the equality that should hold: `party recorded as payer == party whose BTC actually paid the user`. The deposit's `DepositInMove` collateral (the reimbursement value) ends up being handed to an operator who never fronted the corresponding withdrawal, while the actual funder of the withdrawal has no recourse and is not credited. This matches the Critical impact category "an operator reimbursed for a payout it never funded," since the reimbursement mechanism's core custody/attribution guarantee is subverted by unauthenticated OP_RETURN data.

### Likelihood Explanation
Exploitation requires only: (1) knowledge of a pending withdrawal's user-signed input (obtainable once any operator broadcasts/attempts the payout, or from mempool, since the signature only commits to the user's own output under `ANYONECANPAY`), and (2) the ability to fund and broadcast a competing version of the payout transaction before/instead of the legitimate operator's version, substituting an arbitrary `OP_RETURN` payload. No privileged role, key compromise, or majority hashrate is required — only being first to confirm a transaction with attacker-chosen ancillary data, which is within reach of any unprivileged actor monitoring the mempool/Citrea withdrawal registry.

### Recommendation
Bind the payer attribution cryptographically to the operator who actually funds the payout, rather than to unauthenticated `OP_RETURN` bytes. For example, require the additional funding input(s) of the payout transaction to be provably spent from that specific operator's known collateral/wallet key (verifiable on-chain), or require the operator to sign a commitment (e.g., include a Schnorr signature over the payout txid using the operator's registered key) that verifiers check before recording `payout_payer_operator_xonly_pk`, instead of trusting raw, unauthenticated OP_RETURN data as proof of who fronted the withdrawal.

### Proof of Concept
1. Watch for a registered withdrawal on Citrea (or an in-flight payout tx in the mempool) providing the user's `SIGHASH_SINGLE|ANYONECANPAY` signature and the fixed user-payout output.
2. Construct a payout transaction identical to `create_payout_txhandler`'s output (input 0 = user's withdrawal UTXO/signature, output 0 = user payout), but fund the extra inputs from the attacker's own wallet, and set the `OP_RETURN` output to contain the x-only public key of an arbitrary real, registered operator (`operator_xonly_pk` parameter), not the attacker's own key.
3. Broadcast and confirm this transaction before the legitimate operator's version.
4. When `update_finalized_payouts` runs (`core/src/verifier.rs:2283-2353`), it parses this OP_RETURN and records that arbitrary operator as `payout_payer_operator_xonly_pk` in the `withdrawals` table.
5. That operator can then call `get_reimbursement_txs`/proceed through the kickoff process (`validate_payer_is_operator` in `core/src/operator.rs:1686-1740`) and receive the deposit's reimbursement (`create_reimburse_txhandler`, `core/src/builder/transaction/operator_reimburse.rs:341-384`) despite never having funded the withdrawal.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
