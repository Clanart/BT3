### Title
Legacy Bank Precompile `send()` Bypasses `SendEnabled`/Blocklist/Allowlist Checks - ([File: precompiles/bank/legacy/v555/bank.go], [File: precompiles/bank/legacy/v600/bank.go])

### Summary
Multiple legacy versions of the Bank precompile (`v552` through at least `v600`) implement `send()` by calling `bankKeeper.SendCoins()` directly instead of routing through the bank `MsgServer.Send()` entry point. This skips the `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` checks that the canonical bank message-handling path enforces, mirroring the reported HiFi bug class where a config-level "is this action allowed" gate (`Fintroller.isRedeemHTokenAllowed`) exists but is not actually invoked by the code path that performs the privileged action (`HToken.redeem()`).

### Finding Description
The current (latest) bank precompile `send()` correctly delegates to `p.bankMsgServer.Send(...)`, which enforces `IsSendEnabledCoins`, `IsInDenomAllowList` for both sender and recipient, and `BlockedAddr` for the recipient before calling `SendCoins`: [1](#0-0) 

However, legacy precompile versions bypass this gate entirely by calling `p.bankKeeper.SendCoins(...)` directly: [2](#0-1) [3](#0-2) 

`BaseSendKeeper.SendCoins` itself performs no `SendEnabled`, denom-allowlist, or blocked-address checks — those checks live only in the `msgServer.Send` wrapper: [4](#0-3) 

These per-denom checks (`IsSendEnabledCoin`/`IsSendEnabledCoins`) are meant to let the chain disable transfers of specific denoms (e.g. paused/frozen tokenfactory denoms) via governance-set params: [5](#0-4) [6](#0-5) 

Both `IsSendEnabledCoins`/`IsInDenomAllowList` and `BlockedAddr` are dropped when a caller routes through the legacy precompile path instead of the canonical msg-server path.

Crucially, these legacy precompile implementations are not dead code: they remain live and dispatchable at runtime through `bank.GetVersioned`, which registers every legacy version keyed by chain upgrade name alongside the latest implementation: [7](#0-6) 

### Impact Explanation
If an operator or governance action ever disables sending for a specific denom (`SendEnabled=false`), adds a recipient/sender to `BlockedAddr`, or restricts a denom via `DenomAllowList` — for example to freeze a compromised or sanctioned account, or pause a tokenfactory denom during an incident — any caller can still move that denom by invoking the legacy bank precompile's `send`/`sendNative` entrypoint at the address it is registered under, since `SendCoins` is invoked directly without the enforcement wrapper. This defeats a security control intended to freeze/restrict fund movement, directly enabling unauthorized transfers of an otherwise-blocked or paused asset.

### Likelihood Explanation
Reaching this path requires only a normal EVM transaction calling the bank precompile contract address with the legacy ABI's `send`/`sendNative` selector — no special privileges are needed, only the ability to submit a transaction. The precompile version dispatch is upgrade-based (`utils.VersionedPrecompiles`), so whether a given legacy binary is reachable from current chain state depends on how `GetVersioned`/version dispatch selects among these registered implementations at runtime; this exact selection logic was not fully traceable within the available tool budget, so certainty about "currently active" reachability is limited to what is shown above (all legacy versions are registered in the same map returned to the EVM precompile registry).

### Recommendation
- Route every legacy `send`/`sendNative` implementation through `bankMsgServer.Send()` (or explicitly call `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` before `SendCoins`) rather than calling `BaseSendKeeper.SendCoins` directly, matching what the latest bank precompile already does.
- Audit all `precompiles/*/legacy/**` implementations across every precompile (bank, others) for the same "bypasses msg-server-level checks by calling the keeper directly" pattern, since this generated legacy-version scaffolding appears systematically vulnerable to the same class of missing-check bug.
- Add a regression test that sets `SendEnabled=false` for a denom (or adds a `BlockedAddr`) and confirms every registered precompile version (not just latest) rejects transfers of that denom/address.

### Proof of Concept
1. Chain governance/params sets `SendEnabled=false` for denom `foocoin` (or adds address `X` to the bank module's blocked-address list) via the bank module params, exactly as demonstrated in `TestSendEnabled`: [8](#0-7) 
2. An attacker holding `foocoin` submits an EVM transaction calling the legacy bank precompile (e.g. the `v6.0.0` implementation registered under key `"v6.0.0"` in `GetVersioned`) with method `send`, denom `foocoin`, from self to any recipient. [7](#0-6) 
3. The legacy `send()` function validates only that the caller is the registered ERC20 pointer for the denom, then calls `p.bankKeeper.SendCoins(...)` directly — no `IsSendEnabledCoins` check occurs. [3](#0-2) 
4. The transfer succeeds despite `SendEnabled=false`, whereas the same transfer via `MsgSend`/current precompile would fail with `types.ErrSendDisabled`.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)

func (p Precompile) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

// IsSendEnabledCoins checks the coins provide and returns an ErrSendDisabled if
// any of the coins are not configured for sending.  Returns nil if sending is enabled
// for all provided coin
func (k BaseSendKeeper) IsSendEnabledCoins(ctx sdk.Context, coins ...sdk.Coin) error {
	for _, coin := range coins {
		if !k.IsSendEnabledCoin(ctx, coin) {
			return sdkerrors.Wrapf(types.ErrSendDisabled, "%s transfers are currently disabled", coin.Denom)
		}
	}
	return nil
}

func (suite *IntegrationTestSuite) TestSendEnabled() {
	app, ctx := suite.app, suite.ctx
	enabled := true
	params := types.DefaultParams()
	suite.Require().Equal(enabled, params.DefaultSendEnabled)

	app.BankKeeper.SetParams(ctx, params)

	bondCoin := sdk.NewCoin(sdk.DefaultBondDenom, sdk.OneInt())
	fooCoin := sdk.NewCoin("foocoin", sdk.OneInt())
	barCoin := sdk.NewCoin("barcoin", sdk.OneInt())

	// assert with default (all denom) send enabled both Bar and Bond Denom are enabled
	suite.Require().Equal(enabled, app.BankKeeper.IsSendEnabledCoin(ctx, barCoin))
	suite.Require().Equal(enabled, app.BankKeeper.IsSendEnabledCoin(ctx, bondCoin))

	// Both coins should be send enabled.
	err := app.BankKeeper.IsSendEnabledCoins(ctx, fooCoin, bondCoin)
	suite.Require().NoError(err)

	// Set default send_enabled to !enabled, add a foodenom that overrides default as enabled
	params.DefaultSendEnabled = !enabled
	params = params.SetSendEnabledParam(fooCoin.Denom, enabled)
	app.BankKeeper.SetParams(ctx, params)

	// Expect our specific override to be enabled, others to be !enabled.
	suite.Require().Equal(enabled, app.BankKeeper.IsSendEnabledCoin(ctx, fooCoin))
	suite.Require().Equal(!enabled, app.BankKeeper.IsSendEnabledCoin(ctx, barCoin))
	suite.Require().Equal(!enabled, app.BankKeeper.IsSendEnabledCoin(ctx, bondCoin))

	// Foo coin should be send enabled.
	err = app.BankKeeper.IsSendEnabledCoins(ctx, fooCoin)
	suite.Require().NoError(err)

	// Expect an error when one coin is not send enabled.
	err = app.BankKeeper.IsSendEnabledCoins(ctx, fooCoin, bondCoin)
	suite.Require().Error(err)

	// Expect an error when all coins are not send enabled.
	err = app.BankKeeper.IsSendEnabledCoins(ctx, bondCoin, barCoin)
	suite.Require().Error(err)
}
