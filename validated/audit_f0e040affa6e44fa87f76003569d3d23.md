### Title
CW↔ERC Pointer Precompile Bypasses `RegisterPointerDisabled` Governance Flag - ([File: precompiles/pointer/pointer.go])

### Summary
`x/evm/keeper/msg_server.go`'s `RegisterPointer` message handler enforces `RegisterPointerDisabled` before creating/migrating any CW↔ERC pointer [1](#0-0) . However, the EVM precompile at `0x000000000000000000000000000000000000100b` (`precompiles/pointer/pointer.go`) exposes equivalent pointer-creation functionality (`addNativePointer`, `addCW20Pointer`, `addCW721Pointer`, `addCW1155Pointer`) that any unprivileged EVM caller can invoke, and none of these handlers check the `RegisterPointerDisabled` param before calling `UpsertERCNativePointer`/`UpsertERCCW20Pointer`/`UpsertERCCW721Pointer`/`UpsertERCCW1155Pointer` [2](#0-1) [3](#0-2) .

### Finding Description
The chain exposes two independent code paths to create ERC pointer contracts for CosmWasm assets:
1. `MsgRegisterPointer` → `x/evm/keeper/msg_server.go`'s `RegisterPointer`, which checks `server.GetRegisterPointerDisabled(ctx)` and rejects the request with `"registering CW->ERC pointers has been disabled"` if the governance param is set [1](#0-0) . This is confirmed by the regression test `TestRegisterPointerDisabled`, which asserts pointer registration fails for ERC20/ERC721/ERC1155 while the flag is set [4](#0-3) .
2. The `pointer` EVM precompile (`0x100b`), reachable by any EVM contract or EOA via a normal transaction, which implements `AddNative`, `AddCW20`, `AddCW721`, `AddCW1155` [5](#0-4) . None of these four handlers reference `RegisterPointerDisabled` or any equivalent gate — they proceed directly to `p.evmKeeper.UpsertERCCW20Pointer(...)` etc. and persist the new pointer mapping unconditionally.

Because both paths ultimately call into the same keeper-level pointer state (`SetCW20ERC20Pointer`/`SetERC20CW20Pointer` family in `x/evm/keeper/pointer.go`), a party that governance intended to lock out of pointer creation (by toggling `RegisterPointerDisabled`, e.g. during a pointer-code migration or to freeze the registry while a vulnerability in pointer contract code is investigated) can simply invoke the EVM precompile instead of submitting `MsgRegisterPointer`, completely circumventing the disable flag — mirroring the H1 report's pattern of reaching a privileged/gated action ("create store") through an alternate endpoint that omits the confirmation/gating check the primary endpoint enforces.

### Impact Explanation
While pointer creation itself is not directly a fund-transfer primitive, `RegisterPointerDisabled` is used as an emergency/administrative kill-switch for the CW↔ERC bridge (as evidenced by the dedicated migration `x/evm/migrations/disable_register_pointer.go` and the explicit test coverage asserting no pointer registration and no `EventTypePointerRegistered` events while disabled). If governance disables this flag to halt bridge activity (e.g., in response to a discovered pointer-contract bug enabling unauthorized transfers, or during an in-flight pointer-code upgrade where concurrent pointer creation with stale bytecode could corrupt bridge state), an attacker can still create new pointer contracts through the precompile, undermining the operational safeguard and potentially enabling continued exploitation of whatever issue motivated disabling the switch, or creating pointer contracts against inconsistent/incompatible bridge code during a migration window.

### Likelihood Explanation
Trivial to reach: any address can send a normal EVM transaction calling `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer`/`addNativePointer` on `0x100b` at any time, with no signature-quality requirements beyond a standard EVM tx. No special privileges, precompile allowlists, or governance access are required, so likelihood of triggering (accidentally or maliciously) once the flag is toggled is high.

### Recommendation
Add a `RegisterPointerDisabled` (or equivalent) check at the top of each of `AddNative`, `AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go`, mirroring the check already present in `x/evm/keeper/msg_server.go`'s `RegisterPointer`, so both entry points enforce the same governance-controlled invariant.

### Proof of Concept
1. Governance sets `RegisterPointerDisabled = true` via param change.
2. Confirm `MsgRegisterPointer` now fails with `"registering CW->ERC pointers has been disabled"` (as in `TestRegisterPointerDisabled`) [6](#0-5) .
3. From any EOA/contract, send an EVM transaction calling `addCW20Pointer(cwAddr)` (or `addCW721Pointer`/`addCW1155Pointer`/`addNativePointer`) on precompile address `0x000000000000000000000000000000000000100b`.
4. Observe the call succeeds and returns a newly deployed pointer contract address, and `p.evmKeeper.GetCW20ERC20Pointer`/`GetERC20CW20Pointer` now shows the new mapping — despite `RegisterPointerDisabled` being set, demonstrating the bypass of the intended administrative gate.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
