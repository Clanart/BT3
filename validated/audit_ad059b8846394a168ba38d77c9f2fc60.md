### Title
Auction bid pool is unconditionally wiped on `AuctionEntryPoint`/`Auctioneer` rotation, permanently losing all in-flight searcher bids - (File: kaiax/auction/impl/bid_pool.go)

### Summary
The `kaiax/auction` module tracks pending KIP-249 auction bids in an in-memory `BidPool`. Every block, `AuctionModule.PostInsertBlock` re-reads the `AuctionEntryPoint` address and `Auctioneer` address from the on-chain `SystemRegistry`/`AuctionEntryPoint` contract and calls `updateAuctionInfo`, which unconditionally destroys the entire bid pool (`bidMap`, `bidTargetMap`, `bidWinnerMap`) whenever either address (or version/gas buffer) differs from the previously cached value, with no mechanism to preserve or re-submit bids that were valid moments earlier.

### Finding Description
`BidPool.updateAuctionInfo` compares the newly read `auctioneer`/`auctionEntryPoint`/version/gas-buffer against the pool's cached values, and if any of them changed, calls `clearBidPool()` which resets all three maps to empty before storing the new values: [1](#0-0) 

This is driven every block from `AuctionModule.PostInsertBlock`/`updateAuctionInfo`, which reads the current `AuctionEntryPoint` address from the registry and the `auctioneer()` address from that contract, and unconditionally feeds them into `bp.updateAuctionInfo` via a `defer`: [2](#0-1) 

The behavior is explicitly documented and confirmed by unit tests: any change of `AuctionEntryPoint` address or `Auctioneer` address clears all bids that had already been accepted into the pool, including bids that target future blocks and had already passed the bid-pool validation rules (signature checks, bid amount, winner-list uniqueness, etc.): [3](#0-2) [4](#0-3) 

This mirrors the reported bug class: a manager-controlled setter (here, governance/registry-driven rotation of `AuctionEntryPoint`/`Auctioneer`, reachable indirectly by any actor that can trigger such a rotation, e.g. via `changeAuctioneer`/`changeDepositVault` on the entry point contract) causes previously "deposited" state (accepted, still-valid searcher bids awaiting execution) to become permanently inaccessible, since the client-side pool has no persistence, versioning-per-bid, or graceful migration path — it is a blunt wipe rather than a scoped invalidation of only the bids that are actually incompatible with the new configuration.

### Impact Explanation
When `AuctionEntryPoint` or `Auctioneer` is rotated (a normal governance/operational action, not an attack), every searcher's outstanding accepted bid — for the current and any future in-range blocks — is dropped without any signal to the searcher and without possibility of re-inclusion, even though the searcher already paid gas/committed resources (and, per KIP-249, backing deposits in the `DepositVault`) for that specific `AuctionEntryPoint` version. This directly parallels the reported issue: positions/commitments tied to an old manager address become permanently lost once the manager reference changes, since there is no tracking of "which bids belong to which entry-point version" and no requirement that the pool be empty before rotation. This can cause legitimate auction settlements to silently fail to include the winning bid transaction for the target block, denying the searcher the auction outcome and disrupting expected MEV/auction settlement for that block.

### Likelihood Explanation
Address rotation is a supported and expected governance operation for the auction system (KIP-249 explicitly anticipates registry updates and entry-point/auctioneer changes), and it is checked and acted upon by every consensus node on every block via `PostInsertBlock`. Any bids present in the pool at the moment of rotation are guaranteed to be wiped — this is not a rare edge case but a deterministic consequence of the current design, and the window in which searchers can lose already-accepted bids exists during every rotation event.

### Recommendation
Before clearing the bid pool on an `AuctionEntryPoint`/`Auctioneer` change, either (a) scope invalidation to only bids incompatible with the new configuration (e.g., only those addressed to the old `AuctionEntryPoint` version) instead of wiping the entire pool, or (b) tag each accepted bid with the `AuctionEntryPoint` address/version it was validated against, and retain/re-validate bids against the newly active configuration where still applicable, allowing valid outstanding bids to survive a rotation rather than being unconditionally destroyed.

### Proof of Concept
1. Searcher submits a valid bid via `auction_submitBid`; it is accepted into `BidPool.bidMap`/`bidTargetMap`/`bidWinnerMap` (see `TestBidPool_UpdateAuctionInfo` setup, lines 469-479 of `bid_pool_test.go`, which adds `testBids[:3]`).
2. Before the target block is produced, governance/operator rotates `AuctionEntryPoint` or calls `changeAuctioneer` on the entry point contract.
3. On the next `PostInsertBlock`, `AuctionModule.updateAuctionInfo` reads the new addresses and calls `bp.updateAuctionInfo(newAuctioneer, newAuctionEntryPoint, ...)`.
4. Because the addresses differ from the cached ones, `clearBidPool()` executes, and as shown in `TestBidPool_UpdateAuctionInfo` (lines 487-497), `bidTargetMap`, `bidWinnerMap`, and `bidMap` all become empty — the previously accepted, still time-valid bid is permanently gone with no notification or recovery path for the searcher. // clearBidPool clears the bid pool.
func (bp *BidPool) clearBidPool() {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	bp.bidMap = make(map[common.Hash]*auction.Bid)
	bp.bidTargetMap = make(map[uint64]map[common.Hash]*auction.Bid)
	bp.bidWinnerMap = make(map[uint64]map[common.Address]common.Hash)
}

// updateAuctionInfo updates the auction info if the auctioneer or auction entry point address is changed.
func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

func TestBidPool_UpdateAuctionInfo(t *testing.T) {
	var (
		mockCtrl = gomock.NewController(t)
		chain    = chain_mock.NewMockBlockChain(mockCtrl)
	)
	defer mockCtrl.Finish()

	block := types.NewBlockWithHeader(&types.Header{Number: big.NewInt(1)})
	chain.EXPECT().CurrentBlock().Return(block).AnyTimes()

	pool := NewBidPool(testChainConfig, chain, &auction.AuctionConfig{MaxBidPoolSize: 1024})
	require.NotNil(t, pool)

	// Start the auction
	pool.start()
	atomic.StoreUint32(&pool.running, 1)
	defer pool.stop()
	pool.auctioneer = testAuctioneer
	pool.auctionEntryPoint = testAuctionEntryPoint
	pool.auctionEntryPointVersion = auction.AuctionVersionV2
	pool.bidTxGasBuffer = 180_000

	// Add some bids
	for _, bid := range testBids[:3] {
		hash, err := pool.AddBid(bid)
		require.NoError(t, err)
		assert.Equal(t, bid.Hash(), hash)

		// Verify bid was added correctly
		assert.Equal(t, bid, pool.bidMap[hash])
		assert.Equal(t, bid, pool.bidTargetMap[bid.BlockNumber][bid.TargetTxHash])
		assert.Contains(t, pool.bidWinnerMap[bid.BlockNumber], bid.Sender)
	}

	// Update auction info with same addresses
	pool.updateAuctionInfo(testAuctioneer, testAuctionEntryPoint, auction.AuctionVersionV2, 180_000)
	assert.NotEmpty(t, pool.bidTargetMap)
	assert.NotEmpty(t, pool.bidWinnerMap)
	assert.NotEmpty(t, pool.bidMap)

	// Update auction info with different addresses
	newAuctioneer := common.HexToAddress("0x1234")
	newAuctionEntryPoint := common.HexToAddress("0x5678")
	pool.updateAuctionInfo(newAuctioneer, newAuctionEntryPoint, auction.AuctionVersionV2, 180_000)

	// Verify pool was cleared and addresses were updated
	assert.Empty(t, pool.bidTargetMap)
	assert.Empty(t, pool.bidWinnerMap)
	assert.Empty(t, pool.bidMap)
	assert.Equal(t, newAuctioneer, pool.auctioneer)
	assert.Equal(t, newAuctionEntryPoint, pool.auctionEntryPoint)
}
