## Analysis

The report's broken invariant is: **untrusted, externally-supplied data is trusted and acted upon without validation, creating a path for attacker-controlled input to corrupt a security-critical operation.** In `WrappedIbbtc`/`WrappedIbbtcEth`, the trusted-but-unverified value is a price feed. The GitHub Desktop analog I found is even more direct: the application **explicitly disables a hard-coded upstream Git security control** for every clone it performs, restoring a known remote-code-execution class that the control existed to close.

`clone()` in `app/src/lib/git/clone.ts` builds the clone environment as:

```ts
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = ['-c', `init.defaultBranch=${defaultBranch}`, 'clone', '--recursive']
...
args.push('--', url, path)
await git(args, __dirname, 'clone', opts)
``` [1](#0-0) [2](#0-1) 

`GIT_CLONE_PROTECTION_ACTIVE` is the environment variable Git itself introduced as part of the fix for the symlinked-`.git`/case-insensitive-filesystem clone RCE class (the family of issues fixed as CVE-2024-32002 and related advisories), where a crafted repository containing a submodule/nested directory that aliases the `.git` directory (via symlink or case-folding tricks) can cause arbitrary files to be written into `.git/hooks` or similar during a recursive clone, leading to code execution on next Git invocation. Desktop is not merely omitting the protection — it is **actively setting it to `'false'`**, which unconditionally disables Git's own hardening for every clone, including the `--recursive` submodule clone performed here. Because `url` and `path` are directly attacker/user-influenced (via "Clone repository", the `x-github-client://openRepo` deep link handled in `openOrCloneRepository` → `PopupType.CloneRepository`, and CLI `--cli-clone`), a malicious remote (or a git proxy/MITM response substituting repository content) can serve a crafted repository whose recursive clone writes outside the intended repository tree.

Other clone/URL-handling paths in the codebase show real, deliberate hardening for a similar bug class — `sanitizeCloneName` and `isClonePathSensitive` guard against path-traversal in derived clone destinations [3](#0-2) [4](#0-3) , and `openRepositoryFromUrl` uses `resolveWithin`/`isAbsolute` checks to keep `filepath` from a deep link inside the repo root [5](#0-4)  — which makes the explicit disabling of `GIT_CLONE_PROTECTION_ACTIVE` stand out as an intentional regression of an upstream Git safeguard rather than an oversight, and none of those other guards (name sanitization, sensitive-destination checks, path containment) mitigate what happens *inside* the clone process itself once the protection is turned off.

### Title
Git's `GIT_CLONE_PROTECTION_ACTIVE` symlink/case-folding clone protection is explicitly disabled for every clone - (File: app/src/lib/git/clone.ts)

### Summary
`clone()` sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the environment for every `git clone --recursive` invocation, unconditionally turning off Git's built-in defense against malicious repositories that abuse symlinked/case-folded paths to write files outside the intended clone target (e.g., into `.git/hooks`).

### Finding Description
Upstream Git added the `GIT_CLONE_PROTECTION_ACTIVE` safeguard to stop repositories (often via nested submodules) from tricking `git clone --recursive` into treating a symlinked or case-insensitively-aliased directory as `.git`, letting a crafted clone drop attacker files into hook locations that execute later. Desktop's `clone()` explicitly forces this variable to `'false'` in the spawn environment used for every clone, including the `--recursive` submodule clone it always performs: [6](#0-5) 

The `url`/`path` pair comes from user- and remote-influenced flows — the Clone dialog, the `x-github-client://openRepo` protocol handler (`parseAppURL` → `openRepositoryFromUrl` → `openOrCloneRepository`) [7](#0-6) [8](#0-7) , and the CLI (`--cli-clone`) [9](#0-8)  — meaning an attacker who controls the remote content served for a cloned URL (malicious repo, or a git proxy/MITM tampering with the fetched objects) fully controls what `git clone --recursive` processes with the protection disabled.

### Impact Explanation
If the disabled Git-side protection is what stands between a crafted submodule/symlink layout and writing files outside the intended repository directory (e.g., into `.git/hooks`), a subsequent Git operation Desktop performs automatically (status, fetch, commit) can execute attacker-supplied hook code, i.e., code execution on the victim's machine driven purely by cloning a malicious repository — matching the "attacker controls a cloned/fetched repository ... code execution / file write outside the repo" impact class.

### Likelihood Explanation
Likelihood is high for anyone using "Clone repository," an "Open in Desktop" deep link, or `github clone <url>` against a URL the attacker controls or can intercept (public repo submission, forked PR checkout flows, or a compromised/malicious proxy in the fetch/clone path), since no additional local access, admin rights, or social engineering beyond normal cloning is required — this is exactly the standard clone/open workflow Desktop exposes to arbitrary remotes.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `app/src/lib/git/clone.ts` so Desktop relies on upstream Git's built-in clone protection rather than disabling it, and audit whether any legitimate Desktop feature depends on this override; if so, replace it with a narrower, verified-safe mechanism instead of a blanket disable for all clones.

### Proof of Concept
1. Serve or MITM-substitute a repository at a URL that Desktop will clone (via Clone dialog, `x-github-client://openRepo/<url>` deep link, or `github clone <url>`), crafted with a submodule/path structure designed to exploit the symlink/case-folding clone weakness that `GIT_CLONE_PROTECTION_ACTIVE` exists to block.
2. User clones/opens the repository in Desktop; `clone()` runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` forced in the environment [1](#0-0) .
3. Because Git's protection is disabled, the crafted clone can place files outside the intended repository tree (e.g., a malicious hook), which fires on a subsequent Git invocation Desktop performs automatically, yielding code execution.

Note: I could not execute Git locally to confirm the exact write-primitive Git's `GIT_CLONE_PROTECTION_ACTIVE` guards against in this Git version, nor find in this codebase a code comment explaining *why* the override was added — that context (and confirmation this isn't compensated elsewhere) would need verification in a full environment/terminal session.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
