## Division-by-zero analog found in `google::protobuf::util::TimeUtil` Duration arithmetic

### Title
Division/modulo by zero in `Duration` operators when the divisor `Duration` is parsed with `seconds=0, nanos=0` - (File: `src/google/protobuf/util/time_util.cc`)

### Summary
The Linux `ad9832` bug divides by a value (`clk_get_rate()`) that can legitimately be zero and is never checked before being used as a divisor. The Protobuf analog is `operator%=`/`operator%` and `operator/` for `google::protobuf::Duration` in the `TimeUtil` library, which divide by a second `Duration` operand without ever checking that its normalized 128-bit value is non-zero.

### Finding Description
`Duration.seconds` (int64) and `Duration.nanos` (int32) are ordinary scalar fields populated directly by the standard binary/ProtoJSON parser — no wire-level rule prevents both from being `0` (the default, all-zero message is a completely valid, minimal-length `Duration`).

`TimeUtil` overloads arithmetic operators that treat one `Duration` as a divisor: [1](#0-0) [2](#0-1) 

The `%=` implementation converts both operands to `absl::uint128` and performs a raw `%` (and division `/` variants do the analogous `/`) with **no check that the divisor is non-zero**: [3](#0-2) 

`ToUint128` simply reflects whatever `seconds()`/`nanos()` the message currently holds — including an attacker-supplied, fully valid but zero-valued `Duration` obtained by parsing an empty/zero `Duration` submessage: [4](#0-3) 

This mirrors the kernel bug's failed invariant exactly: a value obtained from an external/attacker-influenced source (`clk_get_rate()` there, a parsed `Duration` message here) is used directly as a divisor with no `== 0` guard before the arithmetic operation.

### Impact Explanation
Dividing (or taking the modulo of) an `absl::uint128` (backed by compiler `unsigned __int128` on 64-bit targets, or software-emulated 128-bit arithmetic) by zero is undefined behavior; on hardware division instructions this raises `SIGFPE`/traps, crashing the consuming process. This is a Denial-of-Service via crash, consistent with the CVE's own CVSS impact (`A:H`, availability-only, no confidentiality/integrity impact). Only reachable when application code built on top of `TimeUtil` calls `duration_a % duration_b`, `duration_a %= duration_b`, or `duration_a / duration_b` where `duration_b` is a `Duration` whose value was populated from untrusted parsed input (binary or ProtoJSON) and never validated to be non-zero — this is the "consuming-application exposure assumption" since Protobuf itself has no RPC endpoint; the vulnerable code path lives in Protobuf's own `TimeUtil` utility, which is officially shipped and documented for exactly this kind of Duration arithmetic.

### Likelihood Explanation
Moderate. The trigger requires (a) an application to parse a `Duration` from attacker-controlled bytes/JSON and (b) pass that parsed `Duration` as the divisor to one of these operators without a prior zero-check — a pattern plausible in time/rate-limiting code that reads a `Duration` "interval" or "period" field from a request message and computes ratios/remainders against it. Unlike the kernel driver (where the zero-return path is fairly narrow — a specific clock misconfiguration), a `Duration` field defaults to zero and requires zero extra effort from an attacker to produce.

### Recommendation
Add explicit zero checks before the division/modulo in `operator/=(Duration&, Duration&... )`-style helpers and the free `operator/(const Duration&, const Duration&)`/`operator%` functions in `time_util.cc`/`time_util.h`, returning an error/`ABSL_CHECK`-fail with a clear message, or documenting (and `ABSL_DCHECK`ing) that callers must validate the divisor `Duration` is non-zero, analogous to fixes that add an explicit `if (divisor == 0)` guard before calling `ad9832_calc_freqreg()`.

void ToUint128(const Duration& value, absl::uint128* result, bool* negative) {
  if (value.seconds() < 0 || value.nanos() < 0) {
    *negative = true;
    *result = static_cast<uint64_t>(-value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(-value.nanos());
  } else {
    *negative = false;
    *result = static_cast<uint64_t>(value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(value.nanos());
  }
}

Duration& operator%=(Duration& d1, const Duration& d2) {  // NOLINT
  bool negative1, negative2;
  absl::uint128 value1, value2;
  ToUint128(d1, &value1, &negative1);
  ToUint128(d2, &value2, &negative2);
  absl::uint128 result = value1 % value2;
  // When negative values are involved in division, we round the division
  // result towards zero. With this semantics, sign of the remainder is the
  // same as the dividend. For example:
  //     -5 / 10    = 0, -5 % 10    = -5
  //     -5 / (-10) = 0, -5 % (-10) = -5
  //      5 / (-10) = 0,  5 % (-10) = 5
  ToDuration(result, negative1, &d1);
  return d1;
}
