## #Vulnerability found for this question.

### Title
Credential-host confusion via unescaped `host`/`path` fields in `getCredentialUrl` — (File: `app/src/lib/trampoline/trampoline-environment.ts`)

### Summary
`getCredentialUrl` reconstructs a URL string from raw git credential-helper fields (`protocol`, `host`, `path`, `username`) but only percent-encodes the `username` component. Because `host` and `path` are concatenated unescaped, a crafted `host` value containing an `@` character causes the resulting string to be re-parsed by `new URL()` with a different authority than the one git actually intended, letting Desktop match/return stored GitHub credentials for the wrong domain.

### Finding Description
When a git credential-helper `get` request does not include a full `url=` field, Desktop falls back to manually building one: [1](#0-0) 

Only `username` is passed through `encodeURIComponent`; `host` and `path` are inserted verbatim into the template string `` `${protocol}://${user}${host}/${path}` `` before being handed to `new URL(...)`. The WHATWG URL parser used by `new URL()` treats everything before the last unescaped `@` in the authority section as user-info and everything after it as the hostname. If `host` contains an embedded `@` (e.g. `real.com@evil.com`), the reconstructed string becomes `https://real.com@evil.com/...`, which `new URL()` parses with `.host === 'evil.com'`, even though the value the credential-helper protocol reported as the "host" was `real.com@evil.com`.

This mis-parsed URL is not just a display artifact — it feeds directly into the trust decisions of `trampoline-credential-helper.ts`:
- `getGitHubCredential` builds `endpoint` from `getCredentialUrl(cred)` and calls `findGitHubTrampolineAccount(store, endpoint)` to look up a stored account and merge its `username`/`token` into the credential response returned to git. [2](#0-1) 
- `getEndpointKind` uses the same mis-parsed URL (via `isDotCom`, `isGHE`, `credentialUrl.protocol`) to decide whether the request should be treated as a GitHub.com/GHE endpoint at all. [3](#0-2) 

Because the `host`/`path`/`protocol` fields originate from the credential-helper protocol driven by whatever remote/submodule/LFS URL is embedded in repository content the user cloned/fetched, an attacker who controls repository content (e.g., a malicious `.gitmodules` or LFS endpoint config) controls these raw field values that Desktop's trampoline receives and re-serializes.

### Impact Explanation
A mismatch between the host git believes it is authenticating and the host Desktop's `URL` parser derives from the same raw fields can cause Desktop to apply the wrong trust decision for a credential request — e.g., mis-attributing an endpoint-kind check or looking up/returning stored account credentials keyed to a different host than intended. This falls under "credential/token exfiltration" / "unauthorized... account binding" in the accepted impact categories, since GitHub account tokens stored by Desktop are involved in the lookup and response path.

### Likelihood Explanation
Exploitability depends on whether git itself can actually be made to emit a `host` field containing an embedded `@` to the credential helper for an attacker-influenced URL (e.g., via a crafted submodule/LFS remote). Git's own credential URL parser (`credential_from_url_1` in git core) typically splits `user@host` before invoking the helper, so producing a raw `host=` value containing `@` requires a URL shape git's parser accepts as valid but does not fully decompose in the same way `new URL()` does. This edge case was not independently confirmed against git's C source in this review (git core is out of scope of the Desktop repo), so likelihood is assessed as **uncertain/moderate** rather than definitively confirmed — the Desktop-side code defect (asymmetric escaping) is definite, but proving a real end-to-end trigger requires validating exact git credential-fill parsing behavior for adversarial URLs, which is outside what could be verified in this codebase.

### Recommendation
Apply `encodeURIComponent` (or a stricter host/path validator) to the `host` and `path` fields the same way it's already applied to `username` in `getCredentialUrl`, or reject/normalize any `host` value containing reserved URL delimiter characters (`@`, `/`, `\`, `?`, `#`) before constructing the URL, so that reconstruction can't shift the authority boundary.

const cred = new Map([
  ['protocol', 'https'],

console.log(url.host) // "evil.com" instead of the intended "real.com@evil.com"/"real.com"

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
```

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```
