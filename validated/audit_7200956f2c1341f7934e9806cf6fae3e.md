### Title
Unbounded name/symbol strings from bank denom metadata and CW20/CW721 `token_info` are embedded into permanently-stored EVM contract bytecode via the pointer precompile - ([File: precompiles/pointer/pointer.go])

### Summary
The Discourse Onebox bug let an attacker cause unbounded, permanently-cached memory growth (a very long favicon URL, cached with no length check) by controlling upstream content that gets fetched and stored without validation. The analogous pattern in sei-chain is the `pointer` precompile's `AddNative`/`AddCW20`/`AddCW721` handlers, which read a `Name`/`Symbol` string from user-controlled sources (bank/tokenfactory denom metadata, or a CosmWasm contract's own `token_info` query response) and splice them, unvalidated for length, into EVM contract-creation bytecode that is then committed to chain state permanently via `evm.Create`.

### Finding Description
`AddNative` in `precompiles/pointer/pointer.go` fetches `metadata.Name`/`metadata.Symbol` from `bankKeeper.GetDenomMetaData` and passes them straight into the pointer contract's constructor arguments, which get ABI-packed and appended to contract creation bytecode before `evm.Create`/`UpsertERCNativePointer` is called: [1](#0-0) 

`AddCW20` similarly queries the target CW20 contract's `token_info` and unmarshals `name`/`symbol` directly from the JSON response — a value fully controlled by whoever deployed that CW20 contract — before packing it into constructor bytecode for `evm.Create`: [2](#0-1) 

The bank `Metadata.Validate()` function used by `x/tokenfactory`'s `MsgSetDenomMetadata` only checks that `Name`/`Symbol` are non-blank — there is no maximum length check: [3](#0-2) 

The tokenfactory `SetDenomMetadata` message handler calls exactly this `Validate()` as its "defense in depth" and otherwise imposes no bound: [4](#0-3) 

For the CW20/CW721/CW1155 path, the name/symbol values originate entirely from the wasm contract's own query response (`token_info`), which an attacker fully controls since they deploy the CosmWasm contract: [5](#0-4) 

This is the same bug class as the Discourse advisory: attacker-controlled, effectively unbounded-length string data flows into a system-managed artifact (there: a Redis-cached favicon URL string; here: EVM contract init bytecode) with no upstream length validation.

### Impact Explanation
Unlike Discourse's transient Redis cache, the sei-chain analog is worse in kind: the oversized name/symbol string is embedded into contract *bytecode* and committed via `evm.Create`, so it becomes **permanent on-chain state** replicated to every full node (contract code storage, forever, unless pruned). A single `MsgSetDenomMetadata` (tokenfactory denom admin — an unprivileged, non-governance actor once they've created any tokenfactory denom) or a single CW20/CW721/CW1155 contract deployment plus one `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` call (any pointer-user, fully permissionless) can force multi-megabyte (bounded only by tx size / wasm response size limits, which are typically much larger than a reasonable token name) strings into every node's state trie and EVM bytecode store. Repeated across many denoms/contracts this is a state-bloat/resource-exhaustion vector across all full and RPC nodes, and each such deploy also inflates the gas/CPU cost of ABI-packing and `CREATE`'s memory-copy path.

### Likelihood Explanation
High. Creating a tokenfactory denom, setting arbitrary metadata via `MsgSetDenomMetadata`, and calling `addNativePointer` are all permissionless operations available to a normal transaction sender with no special privilege (`x/tokenfactory` denom creation is open, and the metadata admin is the denom creator itself). The CW20/CW721/CW1155 path is even simpler: a CosmWasm contract deployer can write `token_info` to return an arbitrarily long name/symbol, then anyone (including the deployer) calls `addCW20Pointer` on the EVM side to trigger the unbounded `evm.Create`.

### Recommendation
Enforce maximum length bounds on `Metadata.Name`/`Metadata.Symbol` in `sei-cosmos/x/bank/types/metadata.go` `Validate()` (and the tokenfactory-specific denom metadata path), and independently validate/truncate/reject the `name`/`symbol` fields decoded from CW20/CW721/CW1155 `token_info` responses inside `precompiles/pointer/pointer.go`'s `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155` (and their legacy versioned copies under `precompiles/pointer/legacy/`) before packing them into constructor bytecode and calling `evm.Create`.

### Proof of Concept
1. As any account, submit `MsgCreateDenom` to create a tokenfactory denom (e.g. `factory/<sender>/mycoin`).
2. As the denom admin, submit `MsgSetDenomMetadata` with `Name`/`Symbol` set to a very large string (e.g. several hundred KB, limited only by the node's tx-size/message-size limits) — this passes `Metadata.Validate()` unchanged (`sei-cosmos/x/bank/types/metadata.go:18-25`).
3. Call the `pointer` precompile's `addNativePointer(token)` for that denom from any EVM account (`precompiles/pointer/pointer.go:99-131`); the oversized `Name`/`Symbol` is packed into the constructor arguments and deployed via `evm.Create`, permanently storing the oversized string as part of the contract's on-chain bytecode/state on every node.
4. Alternatively, deploy a CW20 contract whose `token_info` query handler returns an arbitrarily large `name`/`symbol` string, then call `addCW20Pointer(cwAddr)`; the same unvalidated pack-and-`Create` occurs (`precompiles/pointer/pointer.go:132-164`).
5. Repeating steps 1–3 (or the CW20 variant) across many denoms/contracts accumulates unbounded permanent state growth on all full nodes at attacker-controlled cost.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
