### Title
Malicious FROST preprocess forces identity nonce-sum, panicking `x()` in BIP-340 HRaM and crashing the signer - (File: networks/bitcoin/src/crypto.rs)

### Summary
CVE-2018-19567 is a parser crash on attacker-controlled input (FPE in `dcraw`). The Serai analog is a reachable panic, not an arithmetic FPE: a signing participant supplies preprocess commitments crafted so the aggregate FROST nonce `R` is the point at infinity. During `sign`, `sign_share` invokes `Hram::hram(R, A, m)`, which calls `x(key)`; `x()` does `key.to_encoded_point(true)` then `.x().expect("point at infinity")`, panicking on identity (`networks/bitcoin/src/crypto.rs:13-16`, `:59-73`). The panic occurs inside `AlgorithmSignMachine::sign` (`crypto/frost/src/sign.rs:383-398`) on bytes the attacker fully controls via `read_preprocess` → `Commitments::read` (`crypto/frost/src/sign.rs:276-281`, `crypto/frost/src/nonce.rs:33-42`).

### Finding Description
- `read_preprocess` deserializes the peer's preprocess with `Commitments::read(reader, &self.params.algorithm.nonces())`; each `GeneratorCommitments` is two `read_G` points with no identity rejection (`crypto/frost/src/nonce.rs:34-36`, `crypto/frost/src/sign.rs:276-281`).
- In `sign`, `B.nonces(&nonces)` computes each session nonce point as `D_total + Σ rho_l * E_l` over `commitments.nonces[n].generators[g]` for every included participant (`crypto/frost/src/nonce.rs:194-212`).
- A malicious participant can set their `E` commitment to the identity, making their contribution `D + rho*E = D` independent of the (publicly computable) binding factor `rho`. After learning all other participants' preprocesses, the attacker chooses `D_attacker = -(Σ others' contributions)`, driving the nonce sum `R` to the identity.
- `sign_share` then evaluates `Hram::hram(&R, &A, msg)`, which hashes `x(R)`; `x()` panics with `"point at infinity"` when `R` is identity (`networks/bitcoin/src/crypto.rs:13-16`). The same panic is documented as possible for `x_only` (`networks/bitcoin/src/crypto.rs:20-23`) and acknowledged in `Hram`'s docstring ("If either `R` or `A` is the point at infinity, this will panic", `crypto.rs:54`), which assumes "negligible probability ... even with malicious participants" — that assumption is wrong because `E = identity` removes the attacker's dependence on `rho`, making the cancellation deterministic.

### Impact Explanation
An unprivileged cosigner/validator in a signing set can deterministically panic every honest signer during `sign`, aborting the Bitcoin Schnorr signing session on every attempt (each new session permits the same attack). This is a liveness/availability failure equivalent in class to the dcraw crash: untrusted peer-supplied bytes cause a crash in the host process. In `processor/src/cosigner.rs` and `processor/src/slash_report_signer.rs`, `read_preprocess` failures are handled as `InvalidParticipant`, but a panic unwinds/aborts instead, bypassing blame reporting (`processor/src/cosigner.rs:162`, `processor/src/slash_report_signer.rs:156`).

### Likelihood Explanation
Requires only membership in an authorized signing set and knowledge of peers' preprocesses, which are broadcast to all participants before `sign` is invoked. The attack needs no secret knowledge — `rho` values are derived from a public transcript (`crypto/frost/src/sign.rs:361-379`) — and is deterministic, not probabilistic, since `E = identity` yields `rho*E = identity`. It can be repeated every attempt, permanently stalling signing for the key.

### Recommendation
Reject identity points in `GeneratorCommitments::read`/`NonceCommitments::read` (or in `BindingFactor::nonces` before summation), and/or make `x()`/`x_only()`/`hram` return `Result`/`Choice` instead of panicking so `sign` surfaces `FrostError::InvalidPreprocess(l)` and the malicious participant is blamed rather than crashing the process (`crypto/frost/src/sign.rs:283-411`, `networks/bitcoin/src/crypto.rs:13-23`).

### Proof of Concept
```rust
// Attacker l in a t-of-n Bitcoin FROST signing session.
// 1. Collect every other participant's Preprocess messages.
// 2. Compute, for nonce index n:
//      D_att = -( sum over all other participants of (D_g + rho_g * E_g) )
//    by replaying `B.nonces`-equivalent math locally (rho is publicly derivable
//    from the rho_transcript over all preprocesses).
// 3. Submit a preprocess whose GeneratorCommitments are
//      [ D_att, ProjectivePoint::identity() ]   // E = identity
//    Both points pass `Secp256k1::read_G` (identity is a valid encoding).
// 4. Each honest signer's `sign` computes nonce sum R = identity, then
//    `Hram::hram(&R, &group_key, msg)` -> `x(&R)` ->
//    `encoded.x().expect("point at infinity")` -> panic, aborting the signer.
```
