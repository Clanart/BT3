### Title
Kip71GasTarget governance parameter accepts zero value, causing division-by-zero panic in base fee calculation - (File: params/kip71_config.go)

### Summary
The KIP-71 dynamic base-fee parameter `GasTarget` can be set to `0` through both header-vote governance and contract governance (`GovParam`), because its `FormatChecker` is `noopFormatChecker` (accepts any value). Unlike the sibling parameter `BaseFeeDenominator`, which has an explicit runtime guard against a zero value, `GasTarget` has no such guard where it is used as a divisor in `NextMagmaBlockBaseFee`. Setting `GasTarget = 0` via governance therefore causes a `big.Int` division-by-zero panic during base-fee computation, which is executed on every block by every node (validation and block building).

### Finding Description
`Kip71GasTarget` is declared in the parameter table with a no-op format checker, meaning any `uint64` value — including `0` — is accepted: [1](#0-0) 

Compare this with `Kip71BaseFeeDenominator`, which explicitly rejects zero: [2](#0-1) 

The header-vote consistency check (`checkConsistency`) does not add any additional validation for `Kip71GasTarget` either; it simply falls through to `return nil`: [3](#0-2) 

The value ultimately reaches `KIP71Config.NextMagmaBlockBaseFee`, where `BaseFeeDenominator` is defensively substituted with `64` if it is zero ("To avoid panic"), but `GasTarget` has no equivalent guard and is used directly as a divisor: [4](#0-3) 

If `GasTarget == 0` and the parent block's gas usage is non-zero (the overwhelmingly common case), execution enters the "`parentGasUsed > gasTarget`" branch:
```
gasUsedDelta := parentGasUsed - gasTarget   // == parentGasUsed
x := parentBaseFee * gasUsedDelta
y := x.Div(x, gasTarget)                    // gasTarget == 0 -> panic: division by zero
```
`big.Int.Div` panics on division by zero in Go, so this crashes the goroutine computing the next base fee — invoked both during header verification (`VerifyMagmaHeader`) and during block building — on every consensus node and RPC node that processes/serves the affected block.

### Impact Explanation
This is a governance-controlled, network-wide denial-of-service / consensus-halt bug: once `governance.kip71.gastarget` (or the corresponding contract-governance parameter) is set to `0` and becomes effective, all nodes (CN, PN, EN) panic while computing/verifying the base fee for the very next block that has non-zero gas usage. This halts block production and processing chain-wide, i.e., an invalid/impossible-to-process governance state is accepted with no recovery path other than an emergency governance re-vote or hotfix, which itself requires a working chain. This satisfies the "acceptance of an invalid governance parameter causing state divergence / chain halt" criteria.

### Likelihood Explanation
The parameter is a first-class documented governance parameter (`kip71.gastarget`) reachable through the standard, sanctioned governance-vote mechanism (`headergov` votes accumulated from council members, or `contractgov`/`GovParam` on-chain voting per KIP-81) — no malicious peer, node compromise, or leaked key is required. The bug requires only that a normally-permitted governance vote sets a bad value; no other repo-level validation exists between the vote acceptance and the panicking arithmetic. Given that `BaseFeeDenominator` already had a defensive zero-check added ("to avoid panic"), the omission for the structurally identical `GasTarget` field strongly indicates an inconsistent/incomplete fix rather than an intentional design choice.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`, which is also used as `upperGasLimit`/`min()` bound but not divided) that rejects `v == 0`, mirroring `Kip71BaseFeeDenominator`'s check:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, add a defensive zero-check directly in `NextMagmaBlockBaseFee` (analogous to the existing `BaseFeeDenominator == 0` fallback) so that even a value that slipped through governance validation (e.g., from historical/legacy chain data) cannot crash the node.

### Proof of Concept
1. A council member (or the governing node) casts a header vote (or a permitted contract-governance `setParam` call) for `governance.kip71.gastarget = 0`.
2. `NewVoteData`/`PartialParamSet.Add` accept the value because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`; `checkConsistency` performs no extra validation.
3. The vote is committed at the epoch governance block, so `GetParamSet` from that block onward returns `GasTarget = 0`.
4. On the very next block after the parameter becomes effective (post-Magma fork) with any non-zero `GasUsed`, `BlockValidator`/block builder calls `KIP71Config.NextMagmaBlockBaseFee(...)`, which executes:
   ```go
   gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - 0) // parentGasUsed
   x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
   y := x.Div(x, new(big.Int).SetUint64(0)) // panics: division by zero
   ```
   This can be reproduced directly by unit-testing `KIP71Config.NextMagmaBlockBaseFee` with `GasTarget: 0` and any non-zero `parentGasUsed`, using the same harness as `TestNextBlockBaseFee`/`TestEvenBaseFee`. [5](#0-4)
