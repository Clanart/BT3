### Title
Aggregate Schnorr verification succeeds for an empty signer set, so a "signature" with zero signers and `s = 0` authenticates any message - (File: crypto/schnorr/src/aggregate.rs)

### Summary

`SchnorrAggregate::verify` reduces the half-aggregate verification equation to a single multiexp whose result must be the identity. When the claimed signer list is empty, the only term is `(-s) * G`, which is the identity whenever `s == 0`. `SchnorrAggregate::read` accepts a length-prefixed `Rs` vector of length 0 followed by a scalar, so the constant byte string `0x00000000 || 0x00..00` deserializes to `SchnorrAggregate { Rs: [], s: 0 }` and verifies successfully against an empty `keys_and_challenges` list for *any* message/challenges context — the analog of CLIENT_CERT authentication succeeding when no certificate was presented.

### Finding Description

`verify` checks only `self.Rs.len() != keys_and_challenges.len()` before evaluating the equation:

```rust
// crypto/schnorr/src/aggregate.rs
pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }
    ...
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
}
```

There is no check that `keys_and_challenges` (equivalently `self.Rs`) is non-empty, and `read` happily produces the empty aggregate:

```rust
// crypto/schnorr/src/aggregate.rs
let mut len = [0; 4];
reader.read_exact(&mut len)?;
let mut Rs = vec![];
for _ in 0 .. u32::from_le_bytes(len) {
  Rs.push(C::read_G(reader)?);
}
Ok(SchnorrAggregate { Rs, s: C::read_F(reader)? })
```

With `len == 0` and `s == 0`, `pairs == [(0, G)]` — wait, `(-0) * G` is the identity — so `verify` returns `true`. Notably the producer side refuses this case: `SchnorrAggregator::complete` returns `None` when no signatures were aggregated (`if self.sigs.is_empty() { return None; }`), confirming an empty aggregate is not a legitimate output — yet the verifier accepts the forged encoding of exactly that impossible value.

### Impact Explanation

Any caller that treats `SchnorrAggregate::verify(...) == true` as "the listed signers endorsed this message" can be forced into the degenerate case where the endorsement set is empty: an unprivileged party submits untrusted bytes to `SchnorrAggregate::read` plus a signer list they influence to be empty, and obtains a positively-verifying "aggregate signature" over an arbitrary message without any private key. This is a forged signature accepted by the verifier — authentication succeeds on credentials that were never presented, mirroring the Tomcat bug class where CLIENT_CERT auth does not fail when soft-fail is disabled. Where the verifier is the sole gate (e.g., a signer-set supplied alongside the signature rather than fixed by the caller), it is a full authentication bypass; where a separate weight/threshold check exists it is still an incorrect verifier formula accepting a value the prover can never legitimately produce.

### Likelihood Explanation

The exploit requires a caller that (a) reads an aggregate from untrusted bytes and (b) lets the signers slice be empty or attacker-influenced. `read` takes a `u32` length, so 36 fixed bytes suffice; verification cost is trivial. The attack is deterministic — no probability, no key material needed. Likelihood hinges on integration: Serai's Tendermint `verify_aggregate`/`verify_commit` path additionally sums validator weights against a threshold, which would reject an empty signer set there, but the primitive itself is a public, documented verification API (`crypto/schnorr`, in scope) that fails open on the empty case it was clearly intended to exclude (per `complete()`'s explicit `None` for empty input).

### Recommendation

Reject empty aggregates in both `SchnorrAggregate::verify` (return `false` when `keys_and_challenges.is_empty()` / `self.Rs.is_empty()`) and optionally in `SchnorrAggregate::read` (error on `len == 0`), matching `SchnorrAggregator::complete`'s `None` for zero signatures. Callers should additionally enforce a minimum signer count rather than relying on the verifier.

### Proof of Concept

```rust
// Against crypto/schnorr (e.g., C = dalek_ff_group::Ed25519)
// Forged aggregate: 4-byte little-endian length 0, then scalar 0.

let agg = SchnorrAggregate::<Ed25519>::read(&mut forged.as_slice()).unwrap();
// Verifies for ANY message/challenge context, with zero signers and no keys:
assert!(agg.verify(b"Some DST", &[]));
```

```rust
  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
```

```rust
  /// Complete aggregation, returning None if none were aggregated.
  pub fn complete(mut self) -> Option<SchnorrAggregate<C>> {
    if self.sigs.is_empty() {
      return None;
    }

    let mut aggregate = SchnorrAggregate { Rs: Vec::with_capacity(self.sigs.len()), s: C::F::ZERO };
    for i in 0 .. self.sigs.len() {
      aggregate.Rs.push(self.sigs[i].R);
      aggregate.s += self.sigs[i].s * weight::<_, C::F>(&mut self.digest);
    }
    Some(aggregate)
  }
```
