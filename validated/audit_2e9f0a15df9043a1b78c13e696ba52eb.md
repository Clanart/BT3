## Analysis

The ZeroLend bug is a security predicate that is hard-coded/inverted so the protection can never actually engage for the exact scenario it was designed to guard. The closest real analog in this GitHub Desktop codebase is not a smart-contract-style `require`, but the equivalent pattern in the clone pipeline: a git security flag that Desktop unconditionally forces to the "disabled" value on every clone.

### Title
Recursive clone always disables Git's clone-time protection against malicious repository content (`GIT_CLONE_PROTECTION_ACTIVE=false`) - (File: app/src/lib/git/clone.ts)

### Summary
`clone()` in [1](#0-0)  builds the environment for every `git clone --recursive` invocation and unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'`. This is the same class of bug as the ZeroLend `_update` guard: a safety check that is supposed to be conditionally engaged is instead pinned to the value that disables it, for every call, regardless of the actual trust context of the remote being cloned.

### Finding Description
`GIT_CLONE_PROTECTION_ACTIVE` is the environment marker Git itself introduced (as part of the fixes for the 2024 clone-time RCE class, e.g. CVE‑2024‑32004/32020/32021/32465, which affected `--recursive`/submodule clones) to indicate that the top-level clone is running with its hardened checks active — checks that detect symlinked `.git` directories, embedded/nested repositories, and hook files smuggled in through a malicious submodule structure during a recursive clone. Git's own clone code consults this flag to decide whether the nested/submodule clone steps should re-validate for these attacks.

Here, Desktop explicitly sets this to `'false'` on the *outer* clone invocation: [2](#0-1) 

Combined with the fact that Desktop always passes `--recursive`: [3](#0-2) 

this means every clone performed via GitHub Desktop (from the "Clone repository" dialog, "Open in Desktop" deep links, or `--cli-clone`) runs with Git's own protection against maliciously-crafted nested repository content turned off, for both first-party and third-party/attacker-controlled URLs.

The existing guard in the same file, `isClonePathSensitive`, only validates the destination directory location on the local disk (blocking `~/.ssh`, `~/.gnupg`, etc.): [4](#0-3) 
It does nothing to validate the *contents* of the remote repository or its submodules, so it provides no protection against the attack class that `GIT_CLONE_PROTECTION_ACTIVE` exists to stop. Likewise, `envForRemoteOperation` (merged in via spread on line 82) only supplies auth/proxy environment and is unrelated to this check.

### Impact Explanation
An attacker who controls a Git remote (or a public repository a victim is lured into cloning via a normal URL or an "Open in Desktop" deep link, per `openOrCloneRepository`/`parseAppURL`, [5](#0-4) ) can craft a repository containing a submodule with the symlink/hook-injection payloads that Git's clone protection is designed to reject. Because Desktop always disables that protection for the recursive clone it performs, the attack that Git upstream fixed becomes reachable again through Desktop specifically. Depending on the exact payload this can result in files being written outside the intended clone directory or a hook being placed such that it executes during/after the clone — i.e., code execution or file write outside the repository, driven entirely by attacker-controlled repository content and no local/privileged access from the victim.

### Likelihood Explanation
Every single clone performed through GitHub Desktop's normal UI or CLI flag goes through this exact code path (`clone()` is the only clone implementation used by `CloningRepositoriesStore`/`AppStore._clone`, and by `--cli-clone`), so the disabling is unconditional and not gated by any trust/allowlist decision — there is no code path where `GIT_CLONE_PROTECTION_ACTIVE` is left enabled. The only requirement for exploitation is that the victim clones an attacker-supplied URL, which is the normal, expected use of the clone feature (including via deep links), not an unnatural user step.

### Recommendation
Do not force `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. If it was disabled to work around a specific compatibility issue, that should be scoped narrowly (e.g., only for known-safe/local sources) rather than applied globally to every recursive clone of arbitrary, potentially attacker-controlled URLs. At minimum, upgrade/verify the bundled Git version enforces the equivalent protections by default and remove the override so Desktop inherits Git's hardened recursive-clone behavior.

### Proof of Concept
Because this requires an actual malicious submodule payload (symlinked `.git`/hook file) to be crafted and served to reproduce the underlying Git RCE class, and I cannot execute code or fetch external repositories, a full working exploit cannot be produced from static analysis alone. The concrete, verifiable code evidence is:
1. `clone()` always sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the child-process environment: [6](#0-5) 
2. `clone()` always adds `--recursive`, so submodules are always fetched during the same operation: [3](#0-2) 
3. No other check in this file or `isClonePathSensitive` inspects the remote's content, submodule structure, or symlinks: [4](#0-3) 

A Devin agent with terminal access could complete verification by: building a test repository with a submodule containing a crafted `.git` directory (per the public advisories for the Git clone-time submodule RCE class) and cloning it via `app/src/lib/git/clone.ts`'s `clone()` function once with the current code (protection disabled) and once with `GIT_CLONE_PROTECTION_ACTIVE` unset, confirming the disabled case allows the payload through where the enabled case rejects it.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
