### Title
Out-of-bounds `IndexError` in CLVM canonical-encoding check crashes spend-bundle validation - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()`/`is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM length-prefix byte stream of every `puzzle_reveal` and `solution` in an incoming spend bundle, reading atom-length prefix bytes at increasing offsets without ever checking those offsets against the buffer length. A crafted, truncated CLVM buffer causes a Python `IndexError` (the analog of the C-level out-of-bounds heap read in CVE-2014-8355's PCX header parser) instead of a controlled `ValueError`/canonical-form rejection.

### Finding Description
`is_atom_canonical()` decodes a variable-length (1–6 byte) atom-length prefix directly from the buffer: [1](#0-0) 

The loop `atom_len |= clvm_buffer[offset]` increments `offset` for `prefix_len` iterations with no check that `offset < len(clvm_buffer)`. `is_clvm_canonical()` likewise advances `offset` by the attacker-declared `atom_len` and then re-indexes `clvm_buffer[offset]` on the next loop iteration without ever verifying `atom_len` stays inside the buffer: [2](#0-1) 

Both functions are invoked unconditionally, for **every** coin spend of **every** incoming spend bundle, inside `MempoolManager.validate_spend_bundle()`: [3](#0-2) 

This is reachable from a single unprivileged spend-bundle submitter: `FullNode.add_transaction()` calls `mempool_manager.add_spend_bundle()` → `validate_spend_bundle()` while holding `blockchain.priority_mutex`: [4](#0-3) 

A truncated buffer such as a single `0xc0` byte (a 5+8-bit length-prefix marker with no continuation byte) makes `is_atom_canonical` index one byte past the end of a 1-byte `bytes` object, raising `IndexError`, which is not a `ValueError`/`ValidationError` and is not specifically handled at this call site.

### Impact Explanation
The bug is a genuine unhandled-exception / out-of-bounds-index defect on attacker-controlled CLVM byte data, directly analogous to CVE-2014-8355's out-of-bounds-read DoS in a length-prefixed parser. Reachability tracing shows the blast radius is currently contained by outer exception handling: for peer-relayed transactions, `_handle_one_transaction()` catches generic `Exception`, bans the offending connection, and continues operating [5](#0-4) ; the async `with` block around the mutex acquisition guarantees the lock is released even on exception. I was not able to fully verify every call path (e.g., the wallet `send_transaction`/RPC `push_tx` handlers) within the remaining investigation budget, so it is possible some entry points propagate the `IndexError` without the same containment, which would upgrade this from a per-connection failure to a broader processing halt.

### Likelihood Explanation
Trivial to trigger: any spend bundle with a truncated puzzle_reveal or solution whose final byte is a multi-byte atom-length prefix marker exercises the unchecked read. No signatures, coin ownership, or special flags are required, since the canonical check runs on every coin spend unconditionally.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each prefix-byte read and in `is_clvm_canonical()` before advancing `offset` by `atom_len`, raising a normal "non-canonical"/`False` result (or a caught `ValueError`) instead of allowing an `IndexError` to escape, mirroring the bounds checks already present in `full_block_utils.py`'s `skip_bytes`/`skip_list` helpers.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xc0 signals a 1-extra-byte length prefix, but the buffer ends immediately.
truncated = bytes.fromhex("c0")
is_clvm_canonical(truncated)   # raises IndexError instead of returning False
```
Embedding such a byte string as a `solution` (or `puzzle_reveal`) in a `CoinSpend` and submitting it as a `SpendBundle` via `respond_transaction`/`push_tx` drives execution into `validate_spend_bundle()`, triggering the unhandled `IndexError`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
