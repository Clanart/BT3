### Title
Denial of Service via unbounded transaction signature count processed before gas/fee validation - (File: blockchain/types/transaction.go)

### Summary
`Transaction.ValidateSender()` recovers a public key for **every** entry in `TxSignatures` via `crypto.Ecrecover` before any gas-sufficiency check is performed, and the number of signatures a submitter may attach to a Kaia-typed transaction is not capped independently of the overall transaction byte-size limit. A crafted transaction with an excessive number of `TxSignature` (v, r, s) tuples forces every receiving node's mempool admission path (`TxPool.validateTx`) to perform a large, unmetered batch of expensive elliptic-curve recovery operations before the transaction is ever rejected for insufficient gas — the same "unbounded attacker input processed before cost is checked" bug class as CVE-2025-30151 (long password processed by an expensive hash routine before any length limit rejects it).

### Finding Description
In `Transaction.ValidateSender`: [1](#0-0) 
the sequence is:
1. `SenderPubkey(signer, tx)` is called, which internally invokes `TxSignatures.RecoverPubkey`, iterating over **all** entries in `t` and calling `crypto.Ecrecover` on each one: [2](#0-1) 
2. Only *after* this full recovery loop completes does the code compute `accKey.SigValidationGas(currentBlockNumber, ..., len(pubkey))` to determine how much gas the signature validation actually costs.

The gas sufficiency of the transaction (`tx.Gas() < intrGas+sigValGas`) is checked even later, in `TxPool.validateTx`, and only *after* `tx.ValidateSender` (and therefore the entire Ecrecover loop) has already executed: [3](#0-2) 

The only cap on the number of `TxSignature` entries in an outbound (locally-signed) transaction is enforced in the signing helper `NewTxSignaturesWithValues`, which limits the *signer* to `accountkey.MaxNumKeysForMultiSig` (10) keys: [4](#0-3) 
This limit, however, is a client-side signing convenience — it is not enforced when an arbitrary attacker crafts and RLP-encodes a raw transaction and submits it via public RPC (`eth_sendRawTransaction`) or via node gossip. The `accountkey.MaxNumKeysForMultiSig` bound is only applied to the *account's registered key set* (via `AccountKeyWeightedMultiSig.SigValidationGas`), not to the raw count of attacker-supplied signatures being recovered: [5](#0-4) 

The only size restriction applied earlier in `TxPool.validateTx` is the overall transaction byte-size cap (`ErrOversizedData` if `tx.SizeWithoutBlobTxSidecar() > MaxTxDataSize`): [6](#0-5) 
Because each `TxSignature` RLP-encodes to roughly 65-100 bytes, an attacker can pack many thousands of (invalid or valid-format) signatures into a single transaction while staying under the max transaction size, causing thousands of `crypto.Ecrecover` calls (an expensive secp256k1 operation) to execute on every node that receives the transaction — before the node ever determines the tx supplies enough gas to pay for that validation.

### Impact Explanation
This allows an unprivileged, unauthenticated transaction sender (anyone submitting a raw transaction via public RPC or p2p gossip) to force CPU-expensive signature-recovery work on every node's mempool-admission path without paying commensurate gas, since the recovery happens prior to the gas-sufficiency check. Because mempool validation runs on every full node that receives the broadcast transaction (not just the block producer), a small number of such crafted transactions can be used to degrade transaction-processing throughput and CPU availability network-wide — a Denial-of-Service condition matching CWE-20 (Improper Input Validation) and the impact class of the referenced advisory (:A in CVSS).

### Likelihood Explanation
Likelihood is high for any node that accepts raw transaction submissions from the public RPC or the p2p tx-gossip protocol, since:
- No authentication or balance/fee-sufficiency check occurs before the expensive Ecrecover loop.
- The only gate is the overall transaction byte-size limit (`MaxTxDataSize`), which does not meaningfully bound the achievable signature count.
- Crafting such a transaction (arbitrary signature bytes; they need not even be valid signatures — `Ecrecover` is called and only fails/succeeds after computation) requires no special privileges, funds, or account state.

### Recommendation
Enforce an upper bound on the number of `TxSignature` entries (e.g., `accountkey.MaxNumKeysForMultiSig`) at transaction decode/validation time, *before* `SenderPubkey`/`RecoverPubkey` performs any `Ecrecover` calls, in `blockchain/types/tx_signatures.go` and/or as an early check in `TxPool.validateTx` prior to calling `tx.ValidateSender`. This mirrors the fix pattern used by the referenced advisory: reject over-sized/over-count untrusted input before performing the expensive operation, rather than after.

### Proof of Concept
1. Construct a Kaia-typed transaction (e.g., `TxTypeValueTransfer`) targeting any `from` address.
2. Instead of a normally-signed `TxSignatures` (1 entry, or ≤10 for known multisig accounts), RLP-encode the transaction with an artificially large `TxSignatures` list (e.g., several thousand arbitrary 65-byte (v,r,s) tuples), keeping the total transaction size under `MaxTxDataSize`.
3. Submit the raw transaction via `eth_sendRawTransaction` (public RPC) or broadcast it over the p2p network.
4. On receipt, `TxPool.validateTx` → `tx.ValidateSender` → `SenderPubkey` → `TxSignatures.RecoverPubkey` performs one `crypto.Ecrecover` call per attached signature (potentially thousands) before the transaction is rejected for insufficient gas or invalid account key, consuming disproportionate CPU on every receiving node relative to the "cost" (none) paid by the attacker.

Note: I was unable to fully confirm the exact numeric value of `MaxTxDataSize` in this codebase snapshot within the available tool budget, nor whether any RLP-level decode limit on list length exists elsewhere in the codebase that might partially mitigate this; this should be verified directly in a Devin session with full repository access before remediation.

```go
// ValidateSender finds a sender from both legacy and new types of transactions.
// It returns the senders address and gas used for the tx validation.
func (tx *Transaction) ValidateSender(signer Signer, p AccountKeyPicker, currentBlockNumber uint64) (uint64, error) {
	if tx.IsEthereumTransaction() {
		addr, err := Sender(signer, tx)
		// Legacy transaction cannot be executed unless the account has a legacy key.
		if p.GetKey(addr).Type().IsLegacyAccountKey() == false {
			return 0, kerrors.ErrLegacyTransactionMustBeWithLegacyKey
		}
		tx.mu.Lock()
		if tx.validatedSender == (common.Address{}) {
			tx.validatedSender = addr
			tx.validatedFeePayer = addr
		}
		tx.mu.Unlock()
		return 0, err
	}

	pubkey, err := SenderPubkey(signer, tx)
	if err != nil {
		return 0, err
	}
	txfrom, ok := tx.data.(TxInternalDataFrom)
	if !ok {
		return 0, errNotTxInternalDataFrom
	}
	from := txfrom.GetFrom()
	accKey := p.GetKey(from)

	gasKey, err := accKey.SigValidationGas(currentBlockNumber, GetRoleTypeForValidation(tx.Type()), len(pubkey))
	if err != nil {
		return 0, err
	}
```

```go
func (t TxSignatures) RecoverPubkey(txhash common.Hash, homestead bool, vfunc func(*big.Int) *big.Int) ([]*ecdsa.PublicKey, error) {
	var err error

	pubkeys := make([]*ecdsa.PublicKey, len(t))
	for i, s := range t {
		pubkeys[i], err = s.RecoverPubkey(txhash, homestead, vfunc)
		if err != nil {
			return nil, err
		}
	}

	return pubkeys, nil
}
```

```go
	}

	// If module recognizes the tx, run an alternative balance check and then skip the default balance check later.
	shouldSkipBalanceCheck := false
	for _, module := range pool.modules {
		if module.IsModuleTx(tx) {
			if checkBalance := module.GetCheckBalance(); checkBalance != nil {
				shouldSkipBalanceCheck = true
				err := checkBalance(tx)
				if err != nil {
					logger.Trace("[tx_pool] invalid funds of module transaction sender", "from", from, "txhash", tx.Hash().Hex())
					return err
				}
			}
			break
		}
	}

	// Transactor should have enough funds to cover the costs
	// cost == V + GP * GL
	if tx.IsFeeDelegatedTransaction() {
		// balance check for fee-delegated tx
		gasFeePayer, err = tx.ValidateFeePayer(pool.signer, pool.currentState, pool.currentBlockNumber)
		if err != nil {
			return types.ErrFeePayer(err)
		}

		var (
			feePayer            = tx.ValidatedFeePayer()
			feePayerBalance     = pool.getBalance(feePayer)
			feeRatio, isRatioTx = tx.FeeRatio()
		)
		if isRatioTx {
			// Check fee ratio range
			if !feeRatio.IsValid() {
				return kerrors.ErrFeeRatioOutOfRange
			}

			feeByFeePayer, feeBySender := types.CalcFeeWithRatio(feeRatio, tx.Fee())

			if senderBalance.Cmp(new(big.Int).Add(tx.Value(), feeBySender)) < 0 {
				logger.Trace("[tx_pool] insufficient funds for feeBySender", "from", from, "balance", senderBalance, "feeBySender", feeBySender)
				return ErrInsufficientFundsFrom
			}

			if feePayerBalance.Cmp(feeByFeePayer) < 0 {
				logger.Trace("[tx_pool] insufficient funds for feeByFeePayer", "feePayer", feePayer, "balance", feePayerBalance, "feeByFeePayer", feeByFeePayer)
				return ErrInsufficientFundsFeePayer
			}
		} else {
			if senderBalance.Cmp(tx.Value()) < 0 {
				logger.Trace("[tx_pool] insufficient funds for cost(value)", "from", from, "balance", senderBalance, "value", tx.Value())
				return ErrInsufficientFundsFrom
			}

			if feePayerBalance.Cmp(tx.Fee()) < 0 {
				logger.Trace("[tx_pool] insufficient funds for cost(gas * price)", "feePayer", feePayer, "balance", feePayerBalance, "fee", tx.Fee())
				return ErrInsufficientFundsFeePayer
			}
		}
		// additional balance check in case of sender = feepayer
		// since a single account has to bear the both cost(feepayer_cost + sender_cost),
		// it is necessary to check whether the balance is equal to the sum of the cost.
		if from == feePayer && senderBalance.Cmp(tx.Cost()) < 0 {
			logger.Trace("[tx_pool] insufficient funds for cost(gas * price + value)", "from", from, "balance", senderBalance, "cost", tx.Cost())
			return ErrInsufficientFundsFrom
		}
	} else if !shouldSkipBalanceCheck {
		// balance check for non-fee-delegated tx
		if senderBalance.Cmp(tx.Cost()) < 0 {
			logger.Trace("[tx_pool] insufficient funds for cost(gas * price + value)", "from", from, "balance", senderBalance, "cost", tx.Cost())
			return ErrInsufficientFundsFrom
		}
	}

	sigValGas := gasFrom + gasFeePayer
	if err != nil {
		return err
	}
	if tx.Gas() < intrGas+sigValGas {
		return ErrIntrinsicGas
	}
```

```go
func (a *AccountKeyWeightedMultiSig) SigValidationGas(currentBlockNumber uint64, r RoleType, numSigs int) (uint64, error) {
	numKeys := uint64(len(a.Keys))
	if numKeys > MaxNumKeysForMultiSig {
		logger.Warn("validation failed due to the number of keys in the account is larger than the limit.",
			"account", a.String())
		return 0, kerrors.ErrMaxKeysExceedInValidation
	}
	if numKeys == 0 {
		logger.Error("should not happen! numKeys is equal to zero!")
		return 0, kerrors.ErrZeroLength
	}

	isIstanbul := fork.Rules(new(big.Int).SetUint64(currentBlockNumber)).IsIstanbul
	if isIstanbul {
		return uint64(numSigs-1) * params.TxValidationGasPerKey, nil
	}
	return (numKeys - 1) * params.TxValidationGasPerKey, nil
}
```
