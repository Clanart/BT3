### Title
Empty aggregate Schnorr signature is accepted as valid - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing no signatures when the supplied `keys_and_challenges` list is also empty and `s == 0`. [1](#0-0) 

### Finding Description
`SchnorrAggregator::complete` refuses to emit an aggregate when no signatures were aggregated, returning `None` for an empty input set. [2](#0-1)  However, `SchnorrAggregate::read` accepts a zero-length aggregate and a canonical zero scalar. [3](#0-2)  During verification, equal empty lengths pass, no signatures are processed, and the only multiexp term is `-0 * G`, which evaluates to identity and returns `true`. [4](#0-3) 

### Impact Explanation
An attacker can submit serialized bytes representing `len = 0` and `s = 0`, producing a forged `SchnorrAggregate` that verifies successfully against an empty `keys_and_challenges` slice. [3](#0-2)  This violates the aggregate API’s own semantics because legitimate aggregation explicitly represents an empty aggregate as `None`, not as a valid signature object. [5](#0-4) 

### Likelihood Explanation
The attack requires only control over bytes passed to `SchnorrAggregate::read` and a caller that invokes `verify` for an empty statement set. [3](#0-2)  No secret keys, valid signatures, private state, or protocol participation are needed. [1](#0-0) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify`, matching `SchnorrAggregator::complete`’s treatment of empty input. [6](#0-5)  Also consider rejecting `len == 0` in `SchnorrAggregate::read` so invalid empty encodings cannot enter downstream verification paths. [3](#0-2) 

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::SchnorrAggregate;

fn forged_empty_aggregate_verifies<C: Ciphersuite>() {
  // Serialization:
  // - u32 little-endian signature count: 0
  // - canonical scalar encoding of s: 0
  let mut bytes = 0u32.to_le_bytes().to_vec();
  bytes.extend(C::F::ZERO.to_repr().as_ref());

  let aggregate =
    SchnorrAggregate::<C>::read::<&[u8]>(&mut bytes.as_ref()).unwrap();

  // This unexpectedly returns true.
  assert!(aggregate.verify(b"example-domain", &[]));
}
```

The forged encoding parses because the reader permits `len == 0`, and verification succeeds because the resulting multiexp contains only the identity-producing `-0 * G` term. [3](#0-2) [4](#0-3)
