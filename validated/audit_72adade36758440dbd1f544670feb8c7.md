### Title
Divide-by-zero denial-of-service via unvalidated `kip71.gastarget=0` governance vote crashes block validation/production - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` in `params/kip71_config.go` divides by `GasTarget` without a zero-guard. The governance parameter `Kip71GasTarget` is registered with `FormatChecker: noopFormatChecker` in `kaiax/gov/param.go`, which accepts any `uint64` value including `0`, and `checkConsistency` in `kaiax/gov/headergov/impl/header.go` performs no additional validation for this parameter. A council member's vote setting `kip71.gastarget` to `0` is therefore accepted end-to-end, and once ratified it causes every node to panic (`runtime error: integer divide by zero`) inside `NextMagmaBlockBaseFee`, which is invoked from block validation (`blockchain/block_validator.go`), block production (`work/worker.go`), transaction pool base-fee derivation (`blockchain/tx_pool.go`), and the `eth_feeHistory` RPC path (`node/cn/gasprice/feehistory.go`). This is directly analogous to CVE-2014-9763 (imlib2 divide-by-zero on a crafted PNM file causing a crash): a value that should have been range/zero-checked is not, and the resulting division-by-zero crashes the program — here, crashing consensus-critical node logic network-wide.

### Finding Description
`NextMagmaBlockBaseFee` computes the next block's base fee using:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // divides by gasTarget
``` [1](#0-0) 

Unlike `BaseFeeDenominator`, which has an explicit zero-fallback (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = ...64... }`), `GasTarget` has no such fallback: [2](#0-1) 

`GasTarget` is settable via the `governance_vote` RPC / on-chain governance vote mechanism as `kip71.gastarget`. Its `Param` definition uses `noopFormatChecker`, which always returns `true`: [3](#0-2) [4](#0-3) 

Compare this to `Kip71BaseFeeDenominator`, which explicitly rejects `0`: [5](#0-4) 

The vote-acceptance path (`checkConsistency`) has special-case validation only for `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`; `Kip71GasTarget` falls into the default "no additional checks" bucket: [6](#0-5) 

Once a governing/council member casts and the network ratifies a `kip71.gastarget = 0` vote (via the documented `governance_vote` RPC API), the parameter is applied. On any subsequent block where `parentGasUsed != 0` (i.e. `parentGasUsed > gasTarget(=0)`), the code enters the "gas used above target" branch and executes the division above with divisor `0`, which panics in Go's `math/big` package.

### Impact Explanation
This function is not a peripheral utility — it sits directly in the consensus-critical block base-fee computation path, called during:
- block header validation (`blockchain/block_validator.go`),
- block production (`work/worker.go`),
- tx pool gas-price/base-fee bookkeeping (`blockchain/tx_pool.go`),
- `eth_feeHistory`-style gas price oracle logic (`node/cn/gasprice/feehistory.go`, `node/cn/gasprice/gasprice.go`).

A panic here would crash the node process (or, if recovered, corrupt block processing), effectively halting the chain for every node that processes a block with nonzero gas usage after the malicious parameter takes effect. This is a full network denial-of-service triggered by a governance-parameter misconfiguration/attack, matching the severity class of the referenced CVE (remote DoS via divide-by-zero on malformed/unchecked input).

### Likelihood Explanation
Requires a validator/council member with governance voting rights to submit `governance_vote("kip71.gastarget", 0)`. This is gated to council members (`VerifyVote` checks the voter is in the council and is the block proposer), so it is not reachable by a fully unprivileged external account — but it is reachable via a single RPC call / vote transaction from an already-participating validator, with **no protocol-level rejection** of the dangerous value `0` (unlike the sibling parameters `BaseFeeDenominator`, `LowerBoundBaseFee`, `UpperBoundBaseFee` which do have guards or explicit checks). The asymmetric validation strongly suggests this is an oversight rather than an intentional allowance, and it is trivially triggerable by any single validator vote once accepted.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and/or add a defensive zero-guard fallback inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` analogous to the existing `BaseFeeDenominator` zero-fallback, so that `GasTarget == 0` cannot reach the `Div` call.

### Proof of Concept
1. A council member calls the governance RPC:
   ```
   curl "http://localhost:8551" -X POST -H 'Content-Type: application/json' --data '
     {"jsonrpc":"2.0","id":1,"method":"governance_vote","params":[
       "kip71.gastarget", 0
     ]}'
   ```
   This passes `NewVoteData` (canonicalizes to `uint64(0)`, `noopFormatChecker` returns `true`) — see [7](#0-6) .
2. The vote is placed in `header.Vote` and validated by `VerifyVote` → `checkConsistency`, which performs no rejection for `Kip71GasTarget` — see [6](#0-5) .
3. After ratification at the next epoch, `ParamSet.GasTarget == 0` is used via `ToKip71Config()` — [8](#0-7) .
4. On the next block where `parentHeaderGasUsed > 0`, `NextMagmaBlockBaseFee` executes `x.Div(x, new(big.Int).SetUint64(0))`, panicking — [9](#0-8) .
5. This panic occurs inside block validation/production paths in `blockchain/block_validator.go` and `work/worker.go`, crashing/halting node processing across the network.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
