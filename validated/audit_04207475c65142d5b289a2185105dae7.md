### Title
Unbounded offset read in CLVM canonical-atom length-prefix parser causes uncaught `IndexError` on crafted spend-bundle solution bytes - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` parses the variable-length atom size prefix (1–6 bytes) of a raw CLVM buffer without ever checking that `offset` stays within `len(clvm_buffer)` while it walks the multi-byte length prefix. This mirrors the CVE-2016-5841 bug class: an untrusted length/offset field is consumed to walk further into a buffer without a bounds check, and a malicious/short input can push the read past the end of the buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` determines `prefix_len` (0–5) from the leading atom-header byte and then loops `prefix_len` times, incrementing `offset` and indexing `clvm_buffer[offset]` directly: [1](#0-0) 

There is no check that `offset + prefix_len < len(clvm_buffer)` before or during the loop at lines 178-181. If an attacker constructs (or truncates) a CLVM buffer so that a multi-byte length-prefix atom header (e.g. a 0xF8-0xFC lead byte requiring 4-5 trailing length bytes) sits at the very end of the buffer, `clvm_buffer[offset]` will raise an uncaught `IndexError` once `offset` exceeds the buffer bounds.

`is_clvm_canonical()`, which calls `is_atom_canonical()`, is documented as the canonical-serialization check gating **DEDUP-eligible spends** in mempool processing (`.cursor/context/clvm-execution.md`, "Canonical serialization" section, referencing `mempool_manager.py:185`): [2](#0-1) 

This function is invoked against solution bytes supplied inside an arbitrary, attacker-controlled spend bundle in order to decide dedup eligibility — i.e., it runs on untrusted, wallet/user-submitted data during mempool admission.

### Impact Explanation
An uncaught `IndexError` raised deep inside a CLVM-buffer canonicality check that runs on every submitted spend bundle's solution can propagate as an unhandled exception in the mempool-admission/dedup-eligibility code path. Because this path is reachable from any unprivileged spend-bundle submitter, a single crafted (truncated/malformed) solution buffer can trigger a spend-triggered exception in transaction processing, rather than a clean rejection (`Err`/`ValidationError`). Depending on where in the call chain this exception surfaces, it can interrupt processing of that mempool item or, if unguarded, the batching/dedup logic used when building blocks from the mempool — a transaction-processing halt triggered by a single spend.

### Likelihood Explanation
Likelihood is moderate: the bug is trivially reachable by constructing a CLVM solution whose canonical-form check runs into an atom header with a multi-byte length prefix located at (or very near) the end of the buffer. However, I could not fully verify within the available exploration budget the exact call site that invokes `is_clvm_canonical()`/dedup-eligibility checks nor whether an outer `try/except` (broad enough to catch `IndexError`, not just `ValueError`) wraps that specific call, so the ultimate blast radius (single-item rejection vs. broader processing halt) is not fully confirmed from the code visible here.

### Recommendation
Add explicit bounds checking in `is_atom_canonical()` before each `clvm_buffer[offset]` access in the length-prefix loop (lines 178-181), raising a well-defined `ValueError`/rejection instead of relying on Python's `IndexError`. Ensure the caller(s) of `is_clvm_canonical()` catch and convert any parsing exception into a normal mempool rejection (e.g., `Err.INVALID_SPEND_BUNDLE`) rather than letting it propagate as an unhandled exception.

### Proof of Concept
Construct a `clvm_buffer` whose last byte is an atom-header requiring a multi-byte length prefix (e.g. `0xF8`, which per `is_atom_canonical` requires 4 additional length bytes) but supply fewer trailing bytes than required, then call `is_clvm_canonical(buf)`:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xF8 signals a 4-byte trailing length prefix, but none follow
buf = b"\xff\xf8"
is_clvm_canonical(buf)  # raises uncaught IndexError instead of returning False
``` [3](#0-2)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
