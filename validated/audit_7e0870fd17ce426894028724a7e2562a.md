### Title
App Proxy signature verification never checks request `timestamp` freshness, allowing indefinite replay of captured signed requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
Shopify signs app-proxy requests with an HMAC over the full query string, which includes a `timestamp` parameter. `ShopifyApp::AppProxyVerification#query_string_valid?` recomputes the HMAC and compares it to the supplied `signature`, but never inspects or bounds the `timestamp` value itself. [1](#0-0) 

### Finding Description
`verify_proxy_request` is the only gate protecting app-proxy actions, and it delegates entirely to `query_string_valid?`, which strips `signature` from the query, recomputes an HMAC over the remaining sorted params (including `timestamp`), and does a constant-time comparison against the supplied signature. [2](#0-1) 
Because `timestamp` is treated as just another signed opaque parameter — never parsed and compared against the current time — a query string plus its valid signature captured from any past legitimate app-proxy request remains valid forever. This is structurally identical to the reported `GMPriceOracle.getPriceFromChainlink` bug: data is authenticated (signature valid / oracle round exists) but never checked for staleness, so old, no-longer-current data continues to be treated as trustworthy. [3](#0-2) 

### Impact Explanation
An attacker who observes or intercepts one valid app-proxy request (e.g., via browser history, logs, referrer leakage, or a shared/public link containing the signed query string) can replay that exact query string against the app-proxy endpoint at any time in the future, and it will still be accepted as an authentic, current request from Shopify — because signature validity is the only check performed, and it never expires. This can be used to trigger stale/one-time actions (e.g. state-changing proxy endpoints) repeatedly, since the module unconditionally trusts any request whose params+signature combination was ever valid.

### Likelihood Explanation
The vulnerable code path is reachable by anonymous requests to any controller that includes `ShopifyApp::AppProxyVerification` — the only precondition is that an attacker previously obtained one valid signed query string, which is likely given app-proxy URLs are visible client-side/browser-navigable and often logged or shared. No secret key or privileged access is required to exploit a captured request.

### Recommendation
Enforce a freshness window on the `timestamp` query parameter, similar to how the report recommends comparing Chainlink's `timeStamp` against a staleness threshold: parse `timestamp` from `query_hash` before/after signature validation and reject the request if `Time.now.to_i - timestamp.to_i` exceeds a configurable tolerance (e.g., a few minutes), in addition to the existing HMAC check.

### Proof of Concept
1. Capture a legitimately signed app-proxy request URL, e.g. `GET /app_proxy/basic?shop=some-random-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd` (this is precisely the fixture used in `test/shopify_app/controller_concerns/app_proxy_verification_test.rb:61-72`, timestamped 2016).
2. Replay the identical query string against a controller including `ShopifyApp::AppProxyVerification` today.
3. `query_string_valid?` recomputes the HMAC over the same params, matches the signature, and `verify_proxy_request` allows the request through with no check on how old `timestamp` is. [1](#0-0)

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
