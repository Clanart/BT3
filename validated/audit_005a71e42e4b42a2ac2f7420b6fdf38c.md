## Analysis

The reported bug class — reward distribution keyed to a *current* exchange rate/state, rather than the state under which the value was actually earned, letting a party redirect rewards it never legitimately accrued — has a structural analog in the chia-blockchain plot-NFT/pool-singleton module.

### Title
Pool reward absorb spends use the plot-NFT's *current* pool state instead of the state at reward-earning time, allowing reward redirection across a pool switch - (File: `chia/pools/pool_wallet.py`)

### Summary
`PoolWallet.claim_pool_rewards()` and `create_absorb_spend()` build the absorb spend using `current_state.current` — the wallet's *current* `PoolState` at the time of the claim — rather than the `PoolState` that was in effect when the p2-singleton reward coin was actually farmed. Because the p2-singleton puzzle hash is derived purely from `launcher_id` (fixed for the lifetime of the singleton) and does not depend on pool state, unclaimed reward coins remain claimable under whichever pool state is current at claim time, not the one active when the reward was earned.

### Finding Description
`PoolWallet.claim_pool_rewards()` iterates unspent p2-singleton coins matched to farming heights and calls `create_absorb_spend()` with `current_state.current`: [1](#0-0) 

`create_absorb_spend()` derives the inner puzzle purely from the *passed-in* `current_state`, not from any historical state tied to the reward's origin height: [2](#0-1) 

The p2-singleton puzzle hash used for the reward coin is a function of `launcher_id` only (via `launcher_id_to_p2_puzzle_hash`), and does not change between `SELF_POOLING`, `FARMING_TO_POOL`, or `LEAVING_POOL`: [3](#0-2) 

`join_pool()` and `self_pool()`/travel-transaction paths only guard against unconfirmed transactions and target-state conflicts; there is no check for unswept p2-singleton reward balance before permitting a state transition: [4](#0-3) 

The module's own doc comment acknowledges the exact hazard without describing an enforced mitigation: "If this wallet is in SELF_POOLING state, the coin ID associated with the current pool wallet contains the rewards gained while self-farming, so care must be taken to disallow joining a new pool while we still have money on the pooling singleton UTXO": [5](#0-4) 

This is directly analogous to the reported bug class: a value (reward) accrued under one state (validator's stale `exchangeRate` / plot-NFT's prior pool state) is later paid out using a *different, updated* state, letting the actor capture rewards it did not earn under the current arrangement.

### Impact Explanation
If a plot-NFT owner self-farms rewards to the p2-singleton address, then joins a pool before absorbing those self-farmed rewards, a subsequent `claim_pool_rewards`/absorb operation constructed with the *current* (pooled) state would forward those previously self-earned rewards to the pool's target puzzle hash instead of the owner's wallet — or the reverse: rewards earned while pooled could be redirected to self-pooling payout if the owner leaves the pool before the pool operator sweeps them. This is a reward-redirection issue matching the accepted impact category (reward redirection via a spend against a coin whose earned-context state no longer matches the claiming state).

### Likelihood Explanation
Likelihood requires a specific but reachable sequence: (1) unclaimed p2-singleton reward coin(s) pending for a plot-NFT, (2) the owner submits a state-changing pool spend (join/leave) before those coins are absorbed. Since the only current guards are "no unconfirmed transaction" and "no conflicting target state" — not "no outstanding reward balance" — an ordinary wallet user (unprivileged, no special access) can trigger this by simply timing a join/leave around block-reward receipt.

### Recommendation
Before allowing a pool state transition (`join_pool`, `self_pool`, or the final leave travel), check for and require absorption/claiming of any outstanding unspent p2-singleton reward coins tied to the current singleton lineage, or explicitly bind absorb-spend construction to the pool state recorded at the reward's farming height rather than the wallet's current state.

### Proof of Concept
1. Create a plot-NFT in `SELF_POOLING` state; farm one or more blocks so reward coins are created at the p2-singleton puzzle hash.
2. Before calling `pw_absorb_rewards`, call `join_pool` to switch the plot-NFT to `FARMING_TO_POOL` targeting an external pool puzzle hash; confirm the travel spend.
3. Call `pw_absorb_rewards` (or the underlying `claim_pool_rewards`) — `create_absorb_spend` is built with `current_state.current` now equal to the pool-member state, causing `PWAbsorbRewards`/absorb logic in [6](#0-5)  to forward the previously self-farmed reward coin to the pool's `target_puzzle_hash` rather than the owner's wallet, without any check that the reward predates the pool switch.

    async def join_pool(self, target_state: PoolState, fee: uint64, action_scope: WalletActionScope) -> uint64:
        if target_state.state != FARMING_TO_POOL.value:
            raise ValueError(f"join_pool must be called with target_state={FARMING_TO_POOL} (FARMING_TO_POOL)")
        if self.target_state is not None:
            raise ValueError(f"Cannot join a pool while waiting for target state: {self.target_state}")
        if await self.have_unconfirmed_transaction():
            raise ValueError(
                "Cannot join pool due to unconfirmed transaction. If this is stuck, delete the unconfirmed transaction."
            )

        current_state: PoolWalletInfo = await self.get_current_state()

        total_fee = fee
        if current_state.current == target_state:
            self.target_state = None
            msg = f"Asked to change to current state. Target = {target_state}"
            self.log.info(msg)
            raise ValueError(msg)
        elif current_state.current.state in {SELF_POOLING.value, LEAVING_POOL.value}:
            total_fee = fee
        elif current_state.current.state == FARMING_TO_POOL.value:
            total_fee = uint64(fee * 2)

        if self.target_state is not None:
            raise ValueError(
                f"Cannot change to state {target_state} when already having target state: {self.target_state}"
            )
        PoolWallet._verify_initial_target_state(target_state)
        if current_state.current.state == LEAVING_POOL.value:
            history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
            last_height: uint32 = history[-1][0]
            if (
                await self.wallet_state_manager.blockchain.get_finished_sync_up_to()
                <= last_height + current_state.current.relative_lock_height
            ):
                raise ValueError(
                    f"Cannot join a pool until height {last_height + current_state.current.relative_lock_height}"
                )

        self.target_state = target_state
        self.next_transaction_fee = fee
        self.next_tx_config = action_scope.config.tx_config
        await self.generate_travel_transactions(fee, action_scope)
        return total_fee

    async def claim_pool_rewards(
        self, fee: uint64, max_spends_in_tx: int | None, action_scope: WalletActionScope

            )

        if max_spends_in_tx is None:
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS
        elif max_spends_in_tx <= 0:
            self.log.info(f"Bad max_spends_in_tx value of {max_spends_in_tx}. Set to {self.DEFAULT_MAX_CLAIM_SPENDS}.")
            max_spends_in_tx = self.DEFAULT_MAX_CLAIM_SPENDS

        unspent_coin_records = await self.wallet_state_manager.coin_store.get_unspent_coins_for_wallet(self.wallet_id)

        farming_rewards: list[TransactionRecord] = await self.wallet_state_manager.tx_store.get_farming_rewards()
        coin_to_height_farmed: dict[Coin, uint32] = {}
        for tx_record in farming_rewards:
            height_farmed: uint32 | None = tx_record.height_farmed(
                self.wallet_state_manager.constants.GENESIS_CHALLENGE
            )
            assert height_farmed is not None
            coin_to_height_farmed[tx_record.additions[0]] = height_farmed
        history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
        assert len(history) > 0
        delayed_seconds, delayed_puzhash = get_delayed_puz_info_from_launcher_spend(history[0][1])

        all_spends: list[CoinSpend] = []
        total_amount = 0

        # The coins being claimed are gathered into the `SpendBundle`, :absorb_spend:
        # We use an announcement in the fee spend to ensure that the claim spend is spent in the same block as the fee
        # We only need to do this for one of the coins, because each `SpendBundle` can only be spent as a unit

        first_coin_record = None

                break

                last_solution,
                current_state.current,
                current_state.launcher_coin,

                self.wallet_state_manager.constants.GENESIS_CHALLENGE,
                delayed_seconds,

            )

            total_amount += coin_record.coin.amount
