### Title
Auction bid `MaxGasPrice` field excluded from the EIP-712 signed struct in V2 mode allows signature-valid tampering - ([File: kaiax/auction/eip712.go])

### Summary
The auction module's bid signature scheme mirrors the reported bug class ("signed message not validated against the full object included in the payload"): the `Bid.MaxGasPrice` field, which is part of `BidData` and consumed by the bid-processing pipeline, is silently excluded from the EIP-712 struct hash that `SearcherSig` and (transitively) `AuctioneerSig` are computed over whenever the active `auctionEntryPointVersion` is not `AuctionVersionV3` ("0.0.2").

### Finding Description
`Bid.GetHashTypedData` selects the struct encoder based on `version`: [1](#0-0) 

For any version other than `AuctionVersionV3`, it falls back to `EncodeEIP712(b)`, which uses `Bid.EncodeData()`: [2](#0-1) 

This V2 encoder hashes `TargetTxHash`, `BlockNumber`, `Sender`, `To`, `Nonce`, `Bid`, `CallGasLimit`, and `Data` — but **not** `MaxGasPrice`. Only the V3 encoder (`bidV3.EncodeData`) includes `MaxGasPrice` in the committed hash: [3](#0-2) 

`ValidateSearcherSig` recovers the signer from this digest and only checks it equals `b.Sender` (a field that *is* included in the hash for both versions), so it never independently binds `MaxGasPrice`: [4](#0-3) 

`ValidateAuctioneerSig` compounds the gap: the auctioneer's signature does not cover the bid content at all — it is computed only over the raw bytes of `SearcherSig`: [5](#0-4) [6](#0-5) 

Because `AuctioneerSig` only re-signs the opaque `SearcherSig` blob, its integrity guarantee is entirely inherited from whatever `SearcherSig` committed to. When the network's active auction entry point reports a non-V3 `AUCTION_VERSION` (read on-chain via `system.ReadAuctionVersion` in `updateAuctionInfo`), `MaxGasPrice` is outside that commitment: [7](#0-6) 

A bidder (the "auction bidder" role explicitly in scope) can therefore submit a `Bid` whose `MaxGasPrice` field differs from whatever was implicitly agreed with the auctioneer/searcher flow, while `bp.validateBidSigs` — the only signature check performed before the bid is admitted to the pool — still passes both checks unmodified: [8](#0-7) 

### Impact Explanation
`MaxGasPrice` is a value explicitly carried in `BidData` for the express purpose of bounding what the searcher is willing to pay/allow for gas, and it is used to build the on-chain auction calldata (`system.EncodeAuctionCallData`) that determines gas-limit accounting in `getBidTxGasLimit`: [9](#0-8) 

Because it is not covered by either signature in V2 mode, an unprivileged bidder can present a `MaxGasPrice` that neither the searcher's own signature nor the auctioneer's approval actually authorized, breaking the intended cryptographic guarantee that a bid accepted into the pool (and ultimately settled/executed on-chain) reflects exactly what both parties signed off on. This is the same root-cause pattern as the external report: a value in the authorization payload is not bound by the signature that is supposed to authorize the whole payload, enabling manipulation without invalidating the signature check.

### Likelihood Explanation
Any external party that can submit a bid (an "auction bidder", already an in-scope unprivileged actor) can trigger this as long as the live `auctionEntryPointVersion` on-chain is not `"0.0.2"` (V3). No special privileges, node compromise, or peer/consensus assumptions are required — only a single crafted bid submitted through the public bid-submission path (`BidPool.AddBid` / `HandleBid`).

### Recommendation
Include `MaxGasPrice` (normalized, e.g. zero-value when absent) unconditionally in the EIP-712 struct hash for all supported auction versions, or reject bids whose `MaxGasPrice` is set when the active version's typehash does not cover it. Additionally, consider having `ValidateAuctioneerSig` sign over the full canonical bid digest (as used for `SearcherSig`) rather than solely over the opaque `SearcherSig` bytes, so the auctioneer's approval is not entirely dependent on inheriting integrity from the searcher's own signature scope.

### Proof of Concept
1. Network's active auction entry point reports `AUCTION_VERSION` != `"0.0.2"` (V2 struct in use), confirmed via `system.ReadAuctionVersion` at `updateAuctionInfo`.
2. A searcher constructs `BidData{..., MaxGasPrice: X}`, computes `GetHashTypedData(chainId, entryPoint, "0.0.1")` (per `eip712.go:139-147`, which excludes `MaxGasPrice`), and signs it to produce `SearcherSig`.
3. The auctioneer independently signs `GetEthSignedMessageHash()` = `keccak256("\x19Ethereum Signed Message:\n"+len(SearcherSig)+SearcherSig)` to produce `AuctioneerSig` (`bid.go:52-55`), never inspecting `MaxGasPrice`.
4. Before submitting the bid to a node's `BidPool.AddBid`, the bidder swaps `MaxGasPrice` to an arbitrary value `Y`.
5. `bp.validateBidSigs` calls `ValidateSearcherSig` (recomputes the same V2 digest, still excludes `MaxGasPrice`, still matches) and `ValidateAuctioneerSig` (still matches, since it only checks `SearcherSig` bytes, unchanged) — both succeed despite `MaxGasPrice` having been altered post-signing.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil
}
