Confirmed: `JsonFormat.java`'s `Printer` in `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java` has zero references to `redact` — it never calls `FieldDescriptor.getRedactionState()` and prints every field returned by `message.getAllFields()` unconditionally via `printField`/`printSingleFieldValue`, unlike `TextFormat.Printer` which explicitly checks `shouldRedact`/`TryRedactFieldValue` before emitting a value.

### Title
`debug_redact` annotation is silently ignored by `JsonFormat.Printer`, exposing fields intended to be masked in debug/JSON output - (File: `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java`)

### Summary
Protobuf's `debug_redact` FieldOptions annotation (`src/google/protobuf/descriptor.proto`) is documented as marking a field so that "the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials." `TextFormat.Printer` honors this via `shouldRedact()`/`TryRedactFieldValue()`, replacing the value with `[REDACTED]`. `JsonFormat.Printer`, the ProtoJSON serializer used to render messages for logging/debugging/APIs, contains no equivalent check and always serializes the full field value.

### Finding Description
The failed invariant transferred from the Airflow CVE is: a masking/redaction mechanism that is supposed to hide sensitive values is bypassed by an alternate, but supported, code path that renders the same underlying data without applying the mask. In Airflow, crafting a specific URL bypassed UI masking of secret task configuration. In protobuf, the analogous "alternate code path" is `JsonFormat`, a supported, public serialization API, versus `TextFormat`/`DebugFormat`, where the masking annotation is defined and enforced.

Trace:
- `src/google/protobuf/descriptor.proto` defines `debug_redact` on `FieldOptions`/`EnumValueOptions` with the stated purpose of hiding sensitive credentials from debug output. [1](#0-0) 
- `TextFormat.Printer.printFieldValue` in Java checks `shouldRedact(field, generator)` and substitutes `REDACTED_MARKER` before printing any field value. [2](#0-1) 
- The equivalent redaction logic and state computation (`getRedactionState`, `isOptionSensitive`) exists in `Descriptors.java` specifically to support this masking. [3](#0-2) 
- C++'s `TextFormat::Printer::TryRedactFieldValue` performs the same substitution with `kFieldValueReplacement`. [4](#0-3) 
- In contrast, `JsonFormat.Printer`'s internal `print(MessageOrBuilder, String)` iterates `message.getAllFields()` and calls `printField`→`printSingleFieldValue` for every field with no redaction check anywhere in the file. [5](#0-4) [6](#0-5) 

### Impact Explanation
Applications that treat `debug_redact` as a general-purpose, schema-driven "this field is sensitive, never show it in logs/diagnostics/debug endpoints" marker (this is the field's documented purpose and is the exact expectation the Airflow CVE hinges on: a config value expected to be masked in one display surface but not in another) will have those values fully disclosed if the application uses `JsonFormat.print()`/`printToString` instead of, or in addition to, `TextFormat`/`DebugFormat`. This is an information-disclosure/confidentiality issue (CWE-200 analog) for any consuming application relying on this annotation uniformly across debug surfaces, matching the CVSS C:H/I:N/A:N profile of the source CVE.

### Likelihood Explanation
High, for any consumer that (a) marks credential/secret fields with `debug_redact = true`, and (b) also serializes messages to JSON for logging, admin UIs, or diagnostic APIs — a common pattern since `JsonFormat` is a standard, documented public API alongside `TextFormat`. No attacker privilege beyond normal use of a documented public serialization API is required to observe the un-redacted output; the discrepancy is deterministic and requires no error/exception path.

### Recommendation
Add a redaction check to `JsonFormat.Printer` (mirroring `TextFormat.Printer.shouldRedact`/`TryRedactFieldValue`) that consults `FieldDescriptor.getRedactionState()` before emitting a field's value in `printField`/`printSingleFieldValue`, and substitute a redacted marker (or omit/error, consistent with `TextFormat`'s behavior) when the field or an enum value inside its options is marked `debug_redact = true`. Document clearly in `JsonFormat` whether it is or is not redaction-aware so consuming applications do not rely on an incorrect cross-surface guarantee.

### Proof of Concept
1. Define a proto with a `debug_redact = true` string field, e.g. `RedactedFields.optional_redacted_string` as already present in `src/google/protobuf/unittest.proto` lines 2464-2467. [1](#0-0) 
2. Build a `RedactedFields` message setting `optional_redacted_string` to a secret value, e.g. `"top-secret-credential"`.
3. Call `DebugFormat.multiline().toString(message)` — output contains `optional_redacted_string: [REDACTED]`, matching the tested behavior in `DebugFormatTest.messageFormat_debugRedactFieldIsRedacted`. [7](#0-6) 
4. Call `JsonFormat.printer().print(message)` on the same message — the resulting JSON contains `"optionalRedactedString":"top-secret-credential"` in full, because `JsonFormat`'s printer pipeline never consults redaction state, as shown by the absence of any redact-related code in the file and the unconditional `printSingleFieldValue` call path. [8](#0-7)

    RedactionState getRedactionState() {
      RedactionState state = redactionState;
      if (state == null) {
        // If the field is directly marked with debug_redact=true, then it is sensitive.
        synchronized (this) {
          state = redactionState;
          if (state == null) {

            state = RedactionState.of(options.getDebugRedact());
            // Check if the FieldOptions contain any enums that are marked as debug_redact=true,

              }

      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}
