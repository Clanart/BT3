### Title
`clone()` disables Git's built-in clone-time hook-execution protection, enabling attacker-controlled repositories to run arbitrary hooks via nested/embedded `.git` directories - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` explicitly sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` when invoking `git clone --recursive` [1](#0-0) . This environment variable is the upstream Git safety mechanism (introduced after CVE-2024-32004) that prevents a maliciously crafted repository — via nested `.git` directories, symlinked hook paths, or crafted submodules pulled in by `--recursive` — from causing hook scripts to be written into and executed from the *cloned* repository's hook directory during the clone/checkout/submodule-init sequence. By force-disabling this protection for every clone Desktop performs, an attacker who controls the content of a repository (or any of its recursively-cloned submodules) that a victim clones through GitHub Desktop can get post-checkout/post-merge-style hook execution to fire as part of the clone itself, before the user ever interacts with the repository.

### Finding Description
Git added `GIT_CLONE_PROTECTION_ACTIVE` (and the related `clone.protectNTFS`/`protectHFS`/hook-path hardening) as defense-in-depth after CVE-2024-32004, where a repository crafted with a `.git` directory nested inside a tracked path (exploiting `--recursive` submodule handling) could smuggle an executable hook file into the resulting local repo and have Git run it automatically during the clone sequence, without any user action beyond "clone this repo." Desktop's `clone()` function unconditionally overrides this protection to `'false'` for every clone operation performed through the app's UI, CLI (`--cli-clone`), and protocol-handler flow (`x-github-client://openRepo`) [1](#0-0) , all of which route through `git(args, __dirname, 'clone', opts)` [2](#0-1) .

The repository content in this scenario is fully attacker-controlled: any public repo, fork, or link an attacker gets a victim to clone (including via the `x-github-client://` deep link / `open-repository-from-url` action handled in `main.ts`'s `handleAppURL` and `Dispatcher.dispatchURLAction`) [3](#0-2) [4](#0-3) . Desktop's own guard, `isClonePathSensitive()`, only checks that the *destination directory* isn't a sensitive host path — it does nothing to validate or sandbox the *contents* streamed in from the attacker-controlled remote [5](#0-4) . Desktop's own hooks-interception feature (`interceptHooks`, `withHooksEnv`) is explicitly opt-in per Git subcommand (`commit`, `merge`, `pull`, `push`) and is never applied to `clone()` at all [6](#0-5) , so there is no interception layer to catch or gate a hook fired during clone the way there is for `commit`/`pull`/`push` (see `interceptHooks` lists in `commit.ts`/`pull.ts`) [7](#0-6) [8](#0-7) . The only mitigation left standing is upstream Git's own protection — which Desktop has deliberately turned off.

### Impact Explanation
This is remote code execution triggered purely by cloning a repository the attacker controls (a normal, expected Desktop action — "Clone repository" from a URL or GitHub search result), with no additional unnatural steps required from the victim. Because clone happens before the user reviews any code, this bypasses any expectation that "the user reviewed what they cloned." Successful exploitation lets an attacker execute an arbitrary process on the victim's machine with the privileges of the Desktop app the moment the clone (with default `--recursive` submodule handling) completes.

### Likelihood Explanation
Likelihood is high for any victim who clones an untrusted or third-party repository/fork through Desktop — a completely ordinary workflow (searching GitHub, opening a "Clone in Desktop" link from a README, or following a malicious `x-github-client://openRepo` deep link). The attack requires no local access, no leaked credentials, and no social-engineering beyond convincing the victim to clone a repo, which is the exact scenario GitHub Desktop is designed to make easy. The `--recursive` flag used unconditionally by `clone()` also means malicious content can be delivered indirectly through a compromised or attacker-owned submodule [9](#0-8) .

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `clone()` and let Git's built-in clone-time hook protection remain active by default. If Desktop needs a specific carve-out (e.g., for its own hooks feature), it should be scoped narrowly and re-validated against the CVE-2024-32004 threat model rather than globally disabled for every clone. Additionally, apply the same `withHooksEnv`/`interceptHooks` gating used for `commit`/`pull`/`push` to the clone/submodule-init path so any hook invocation during clone goes through Desktop's own review/allow flow instead of running silently.

### Proof of Concept
1. Attacker crafts a Git repository containing a submodule (or nested `.git` directory) engineered per the CVE-2024-32004 technique so that cloning it with `--recursive` writes an executable file into `hooks/` of the resulting local repository (e.g., `post-checkout`).
2. Attacker publishes the repository/fork and shares a normal clone URL, or a `x-github-client://openRepo/...` deep link.
3. Victim clones the repository via GitHub Desktop's "Clone repository" dialog (`app/src/ui/clone-repository/clone-repository.tsx` `clone()` → `cloneImpl` → `lib/git/clone.ts`) [10](#0-9) , or via the deep-link flow.
4. Desktop executes `git -c init.defaultBranch=... clone --recursive ... -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment [1](#0-0) .
5. Because Git's protection is disabled, the crafted hook is installed and executed as part of the clone/submodule-checkout sequence, running attacker-chosen code on the victim's machine.

Note: I was not able to execute Git itself to empirically reproduce the CVE-2024-32004 hook-smuggling payload from this static index-only review; the finding is based on the explicit disabling of the named protection variable and the absence of any compensating control in Desktop's clone path.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
