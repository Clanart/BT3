### Title
Git argument injection via unsanitized branch name in `getMergedBranches` - (File: `app/src/lib/git/branch.ts`)

### Summary
`getMergedBranches` builds `git branch` arguments by appending an unvalidated `branchName` directly after `--merged` with no `--` end-of-options separator. If the branch name begins with `-`, git will interpret it as a command-line flag instead of the positional comparison target, changing the semantics of the merge query.

### Finding Description
```ts
const args = ['branch', ...formatArgs, '--merged', branchName]
...
const { stdout } = await git(args, repository.path, 'mergedBranches')
``` [1](#0-0) 

`branchName` is passed straight into the argv array with no `--` separator and no leading-dash sanitization. Git's ref-naming rules (`check-ref-format`) do **not** forbid a ref/branch name from starting with `-` (they forbid things like leading `.`, `..`, control characters, spaces, `~^:?*[`, trailing `.lock`, `@{`, and backslashes, but not a leading hyphen). A branch such as `-a`, `--all`, or `--sort=-committerdate` is a syntactically legal git ref that can exist in a repository the attacker controls (e.g., as the repository's default branch, surfaced via the GitHub API `default_branch` field or the checked-out `HEAD` of a maliciously crafted remote).

Because `git()` uses `execFile`-style invocation (no shell), the injection is limited to a single extra argv token — it cannot chain multiple flags/arguments — but a single leading-dash token following `--merged` is enough to be reinterpreted by git as an option rather than a value, since `--merged` takes an *optional* value only when attached via `=`. This silently changes the comparison target (e.g., falls back to comparing against `HEAD`) or adds a listing flag such as `--all` (which also lists remote-tracking branches), altering which branches are reported as "merged."

The only production caller is `branch-pruner.ts`, which calls `getMergedBranches(repository, defaultBranch.name)`: [2](#0-1) 
`defaultBranch` is derived from repository/branch state that is ultimately populated from the GitHub API/remote data, so its `name` can be influenced by whoever controls the remote repository's default branch.

### Impact Explanation
`pruneLocalBranches` uses the (potentially falsified) merged-branches map to decide which local branches to delete via `deleteLocalBranch`: [3](#0-2) 
If the `--merged` semantics are altered (e.g., silently defaulting to `HEAD` instead of the real default branch, or including additional remote refs), branches that are not actually merged into the intended default branch could be misclassified as "merged" and subsequently deleted by the automatic background pruner — resulting in silent, automated loss of local branch data the user did not intend to remove.

### Likelihood Explanation
Exploitation requires the victim to add/clone a repository whose default branch name (as reported by the GitHub API or the repository's HEAD) begins with `-`, and requires that repository to be recognized as `isRepositoryWithGitHubRepository` so the background pruner runs against it. This is plausible for an attacker who controls a public/malicious repository the victim adds to GitHub Desktop, but it is a narrow, low-frequency automatic background feature (runs at most every 4 hours) with limited argv-injection surface (only one extra token, no chained flags), which constrains severity.

### Recommendation
Add an explicit end-of-options separator before the user-controlled positional value, e.g.:
```ts
const args = ['branch', ...formatArgs, '--merged', '--', branchName]
```
This is the standard git mitigation for argv values that may start with `-`, and should be applied to all similar sinks in `app/src/lib/git/branch.ts` (and elsewhere) where branch names are appended without a `--` guard.

### Proof of Concept
1. Create/host a repository whose default branch is named `--all` (a valid git ref name).
2. Have GitHub Desktop add/clone this repository so it becomes the tracked repository with `defaultBranch.name === '--all'`.
3. Let the background `BranchPruner` run (or invoke `testPrune()`); it calls `getMergedBranches(repository, '--all')`, producing `git branch <formatArgs> --merged --all` instead of a comparison against the intended default branch.
4. Compare the resulting merged-branch set/pruning decisions against the ground truth obtained from `git branch <formatArgs> --merged -- --all` (correct behavior) to observe the discrepancy.
