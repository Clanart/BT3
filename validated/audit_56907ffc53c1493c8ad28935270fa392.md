### Title
Payout OP_RETURN operator attribution is unsigned, allowing misattribution of "who fronted the withdrawal" - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The payout transaction that fronts a user's withdrawal commits to the output amount/destination via a `SIGHASH_SINGLE|ANYONECANPAY` user signature, but the third output — the `OP_RETURN` that records *which operator* fronted the payout — is left completely outside that signature's commitment. Anyone who obtains the user's signed withdrawal input can broadcast a payout transaction that fronts the fixed payment to the user while writing an arbitrary operator's x-only public key into the unsigned `OP_RETURN`. The verifier's finalized-payout indexing trusts this `OP_RETURN` value verbatim to decide which operator gets credited (and thus which operator becomes eligible for on-chain reimbursement of the full bridge amount from the deposit UTXO), breaking the binding "operator credited == party that actually paid."

### Finding Description
`create_payout_txhandler` builds the payout tx with three outputs: the user payout output (index 0), an anchor output (index 1), and an `OP_RETURN` output carrying `operator_xonly_pk` (index 2). Only the witness for input 0 is set from the user's signature, and callers (e.g. `core/src/operator.rs:560-627`, `core/src/rpc/aggregator.rs`) explicitly require and check that this signature uses the `SinglePlusAnyoneCanPay` sighash type: [1](#0-0) [2](#0-1) 

`SIGHASH_SINGLE` only commits to the output at the same index as the signed input (index 0 here); it says nothing about the anchor output (index 1) or the `OP_RETURN` output (index 2). `ANYONECANPAY` additionally allows arbitrary other inputs to be added by whoever finalizes the transaction. Consequently, the operator identity written into the `OP_RETURN` is not cryptographically bound to the entity that actually constructs, funds, and broadcasts the payout transaction.

On the verifier side, `update_finalized_payouts` scans the confirmed payout tx for the withdrawal index, extracts whatever public key is present in the (unsigned) `OP_RETURN`, and persists it as the "payer" without any further authentication: [3](#0-2) [4](#0-3) 

`PayoutCheckerTask` then looks up unhandled payouts *by this stored operator key* and kicks off the reimbursement/kickoff flow for that operator: [5](#0-4) [6](#0-5) 

The reimbursement transaction eventually pays the full bridge amount (the deposit) to whichever operator's kickoff round is driven by this attribution: [7](#0-6) 

Because the `OP_RETURN` content is attacker-controllable, an unprivileged actor who observes a pending withdrawal (input outpoint + user's `SinglePlusAnyoneCanPay` signature, which must exist off-chain to be usable at all) can construct and broadcast their own payout transaction that: (a) pays the user the exact fixed amount/destination (satisfying the withdrawal on Citrea), and (b) attributes the payout to an arbitrary operator's x-only public key of the attacker's choosing — including an operator that did not fund the transaction at all, or omitting/mangling the true payer's identity.

### Impact Explanation
This breaks the "operator credited" == "party that paid" invariant that the whole reimbursement/kickoff/BitVM machinery depends on:
- An operator that never fronted a payout can be credited as the payer and subsequently drive the kickoff/reimburse flow to claim the deposited bridge amount it never spent ("an operator reimbursed for a payout it never funded").
- Conversely, the operator that genuinely spent its own BTC fronting the payout can have that payout misattributed to a different key (or an invalid/unregistered key), leaving it with no recorded unhandled payout to claim against — resulting in "an honest operator permanently unable to be reimbursed" and eventual loss of its posted collateral through the round timeout/slashing logic.

Both outcomes are explicitly listed Critical impacts (custody/attribution binding broken with concrete bridge value loss), reachable by any unprivileged party without needing verifier/operator/watchtower/aggregator/sequencer roles or key compromise — only visibility into a pending withdrawal's already-signed input.

### Likelihood Explanation
The withdrawal input and its `SinglePlusAnyoneCanPay` signature must be shared with at least one operator/aggregator to get a payout at all, but once that signed input exists it is not bound to a specific `OP_RETURN`/operator, and Bitcoin mempool/RBF visibility (or a compromised/malicious relay of the same signature to multiple operators, which the protocol design already anticipates by broadcasting the withdrawal request to all operators via the aggregator's `Withdraw`/`InternalWithdraw` RPCs and Citrea's public withdrawal registration) makes the raw signed input observable to more than the intended operator. Any party holding it can rebuild the transaction with a different `OP_RETURN` before the intended operator's broadcast confirms, and Bitcoin's mempool "first seen"/RBF fee-bidding rules determine which version confirms — the attacker only needs to also fund/relay a competing transaction with higher fee.

### Recommendation
Bind the operator attribution to the signature: e.g. use a sighash type that also commits to the `OP_RETURN` output (drop `SIGHASH_SINGLE` in favor of `SIGHASH_ALL`, or otherwise ensure all outputs including the `OP_RETURN` are covered by an authenticated commitment), or have verifiers cross-check that the operator named in the `OP_RETURN` matches an out-of-band signed claim from that operator (e.g., the operator's own signature over the payout txid) before crediting it as the payer in `update_finalized_payouts`/`update_payout_txs_and_payer_operator_xonly_pk`.

### Proof of Concept
1. Observe a withdrawal request forwarded to operators: a `WithdrawParams` containing `input_outpoint`, `input_signature` (Schnorr, `SinglePlusAnyoneCanPay`), `output_script_pubkey`, `output_amount` (per `core/src/rpc/clementine.proto` `WithdrawParamsWithSig`).
2. Build a payout transaction via the same construction as `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`), reusing the given input, output, and anchor, but set the `OP_RETURN` `PushBytesBuf` to an arbitrary target operator's `XOnlyPublicKey` instead of the actual broadcaster's key.
3. Set the witness on input 0 using the already-obtained `SinglePlusAnyoneCanPay` signature (valid because it only commits to output 0). Broadcast, paying required fees via an additional (unsigned/ANYONECANPAY-permitted) fee input if needed.
4. Once confirmed and finalized, `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) will parse the forged `OP_RETURN` and store the arbitrary operator's key as `payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-252`).
5. `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:31-113`) will find this "unhandled payout" for the named operator and proceed to drive that operator's kickoff/reimbursement flow, letting it claim the bridge amount it never paid, while the real payer (if any) has no corresponding credited record.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
