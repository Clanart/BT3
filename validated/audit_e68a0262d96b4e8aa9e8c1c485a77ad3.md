## Finding

### Title
`_requestCommitments` is never cleared after a successful GET response delivery, enabling a stale-proof `GetRequestTimeout` to double-pay the relayer fee (and re-trigger app-level timeout logic after the request already succeeded) - ([File: evm/src/core/EvmHost.sol])

### Summary
This is a direct local analog of the reported `killGaugeTotally` bug: a cleanup/"replay protection" step that exists in sibling code paths is missing in one specific path, leaving a stale mapping entry that later code incorrectly treats as still-valid state, enabling unintended reuse.

### Finding Description
`EvmHost.dispatchIncoming(GetResponse ...)` is the success path for delivering a GET response back to the requesting module. On success it pays the relayer the fee recorded in `_requestCommitments[commitment]`, but — unlike its sibling functions — it never deletes that entry: [1](#0-0) 

Compare this to the two `dispatchTimeOut` overloads, both of which explicitly `delete _requestCommitments[commitment]` "for replay protection" before invoking the module callback, and only restore it if the callback reverts: [2](#0-1) 

Because `dispatchIncoming(GetResponse ...)` never clears `_requestCommitments[commitment]`, the entry (containing `sender` and `fee`) remains readable indefinitely after a successful, fee-paid delivery.

`HandlerV2.handleGetRequestTimeouts` gates timeout processing solely on this same mapping still being "known": [3](#0-2) 

```solidity
FeeMetadata memory meta = host.requestCommitments(commitment);
if (meta.sender == address(0)) revert UnknownMessage();
...
if (entry.value.length != 0) revert InvalidProof();
host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
```

The non-membership proof only needs to show that, **at some previously committed destination height whose timestamp is ≥ `request.timeout()`**, no response had been recorded yet — it does not need to be the latest height and does not need to postdate the destination's eventual answer. Since the destination can commit blocks with old-but-past-timeout timestamps before it actually answers a slow GET, a relayer can hold (or later replay) a legitimately-obtained non-membership proof from *before* the destination answered, and submit it *after* the honest `GetResponse` has already been delivered and paid on the source chain.

### Impact Explanation
Because `_requestCommitments[commitment]` was never cleared by the successful `dispatchIncoming(GetResponse ...)` call, this stale-but-valid proof still passes the `meta.sender == address(0)` check in `handleGetRequestTimeouts`, and `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes a second time for a request that already succeeded: [4](#0-3) 

This causes:
1. **Double payment of the same fee** — `meta.fee` is transferred to `meta.sender` via the timeout refund, in addition to the fee already paid to the relayer in the success path.
2. **Double execution of application logic** — the app's `onGetTimeout` callback fires even though `onGetResponse` already fired for the same request. For apps like the intents GET-based cross-chain cancellation flow (`IntentsBase.sol`, which uses GET requests to check the `_filled` mapping on the destination before allowing escrow refunds), this can trigger a timeout-driven refund path after the fill was already confirmed — a double-settlement of escrowed funds.

This matches the bounty's "replay/double-claim/double-settlement" and "false proof/state acceptance" categories: the corrupted value is `_requestCommitments[commitment]`, which should have been deleted upon successful GET response delivery but is left intact, and no other guard (in either `EvmHost` or `HandlerV2`) checks whether the request's response was already delivered before permitting a timeout to be processed.

### Likelihood Explanation
No malicious relayer/prover/governance action is required beyond normal message submission order (deliver response, then submit a timeout proof referencing an earlier, honestly-obtained committed height). Both message types (`handleGetResponses` and `handleGetRequestTimeouts`) are public entry points reachable by any caller holding a valid state/membership proof, and the ordering condition (response delivered before an older non-membership proof is submitted) is entirely plausible whenever the destination chain answers a GET request slowly relative to its own timestamped block production.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` on successful delivery (mirroring the pattern already used in both `dispatchTimeOut` overloads), and/or have `HandlerV2.handleGetRequestTimeouts` additionally reject a timeout if `host.responseReceipts(commitment).relayer != address(0)` (i.e., a response was already delivered on this chain), closing the exact "delete-then-stale-read" gap the THENA report describes.

### Proof of Concept
1. App on chain A dispatches a `GetRequest` (fee `F`, sender `S`) targeting chain B's storage; `_requestCommitments[commitment] = {sender: S, fee: F}`.
2. Relayer answers honestly: `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)` succeeds, pays `F` to `relayer`, but leaves `_requestCommitments[commitment]` untouched (evm/src/core/EvmHost.sol:824-847).
3. Any party (including the same relayer) later submits `HandlerV2.handleGetRequestTimeouts` with a valid non-membership proof taken from an earlier committed height on chain B whose `timestamp >= request.timeout()` but which predates chain B's actual answer.
4. `meta.sender != address(0)` (never cleared) → check passes → `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` runs, calling `onGetTimeout` on the app and transferring `F` a second time to `S` (evm/src/core/EvmHost.sol:856-877).
5. Net result: fee `F` paid twice, and the app processes both success and timeout callbacks for the same logical request.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
