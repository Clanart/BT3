### Title
SSRF via permissionless DataLayer mirror-coin URLs fetched by `http_download` with no protection - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer mirror mechanism lets *any* party create an on-chain "mirror coin" for *any* store/launcher id, embedding arbitrary URL strings in the coin's memos. Once created, every node that tracks that launcher id automatically ingests the URLs into its local mirror table with no validation, and the DataLayer sync loop later performs plain HTTP GET requests to those URLs to fetch delta/full-tree files. This is structurally the same bug class as GHSA-g66v-54v9-52pr (Vikunja SSRF via unvalidated third‑party URLs fed into an internal HTTP client): a value fully controlled by an unprivileged remote party (Todoist API response / Chia mirror coin memo) is passed straight into an outbound `http.Client`/`aiohttp.ClientSession` request with no SSRF protections (no private-IP blocklist, no scheme/redirect restriction, no host allowlist).

### Finding Description
Mirror coins are created via `create_mirror_puzzle()` (`P2_PARENT.curry(Program.to(1))`), and the launcher id + URL list are stored as memos on a `CREATE_COIN` condition: [1](#0-0) 

Any wallet can spend to that puzzle hash for any `launcher_id`, because `create_new_mirror` in `DataLayerWallet` places attacker-chosen `urls` into the transaction memos with no ownership check on `launcher_id`: [2](#0-1) 

When any node is *tracking* that launcher id (which merely requires subscribing to a public store id — an unprivileged, local action any Data Layer client can request), `coin_added` decodes the mirror coin's memos and blindly inserts the URLs into the local `mirrors` table, gated only on `is_launcher_tracked()`, not on whether the mirror coin's creator is trusted or related to the store owner: [3](#0-2) [4](#0-3) 

The DataLayer service periodically pulls these mirror URLs unmodified via `update_subscriptions_from_wallet`: [5](#0-4) 

and then uses them in `fetch_and_validate` → `insert_from_delta_file` → `download_file` → `http_download`, which issues a plain `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` request with **no URL validation, no private/link-local IP blocklist, and no restriction on redirect targets**: [6](#0-5) [7](#0-6) 

This is the same root cause pattern as the Vikunja advisory: attacker-controlled URL string → straight into an outbound HTTP client → fetched by the victim service → response persisted/inserted into local state (here, into the local DataLayer store rather than a downloadable attachment, but the SSRF primitive — forcing the server to make arbitrary outbound requests to internal/metadata endpoints — is identical). The `.cursor/context/data-layer.md` documentation explicitly confirms this is treated only as an integrity concern, not a network-egress concern: "Mirror URLs, plugins, or static file names" are documented as untrusted for *data* purposes, but no mitigation exists for the request itself hitting internal hosts: [8](#0-7) 

### Impact Explanation
An unprivileged attacker (any wallet holder able to spend a coin) can force any Chia full-node/wallet operator running the DataLayer service, who is merely subscribed to a public store id, to issue outbound HTTP GET requests to attacker-chosen URLs — including cloud metadata endpoints (`169.254.169.254`), internal RFC1918 services, or other local-network resources reachable from the node's network position. Because `http_download` has a size cap tied to `max_delta_file_size`, direct data exfiltration back to the attacker is constrained by that cap and requires the response to pass validation as a delta/full-tree file (`insert_into_data_store_from_file`) before being retained, but the SSRF request itself — with all its side effects (probing internal services, triggering internal side-effecting GET endpoints, DNS rebinding, etc.) — occurs unconditionally regardless of whether the downloaded content later validates. This satisfies CWE-918 with attacker-controlled outbound requests originating from the victim node.

### Likelihood Explanation
Likelihood is high for any node operator who has enabled the DataLayer service and subscribed to at least one store: mirror-coin creation requires no special privilege — any wallet can spend a small amount to the mirror puzzle for any known `launcher_id` — and the periodic sync loop (`periodically_manage_data`) automatically fetches newly discovered mirror URLs without operator interaction or confirmation.

### Recommendation
Apply SSRF protections (private/link-local IP blocklist, restricted redirect handling, and/or an explicit URL allowlist for mirrors) to the HTTP client used in `http_download` (`chia/data_layer/download_data.py`), mirroring how the report recommends applying `daenney/ssrf`-style protection to `DownloadFileWithHeaders` in the Vikunja codebase. Additionally, consider requiring explicit operator opt-in/allowlisting of mirror URLs before they are used for outbound requests, rather than auto-trusting any on-chain mirror coin memo.

### Proof of Concept
1. Attacker creates a mirror coin for a `launcher_id` that a victim node already tracks (any public store id), using `create_new_mirror`/`dl_new_mirror` RPC semantics, setting `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]`.
2. Victim node's `DataLayerWallet.coin_added` sees the new mirror coin (puzzle hash matches `create_mirror_puzzle()`), decodes memos via `get_mirror_info`, and stores the URL because the launcher id is tracked: [3](#0-2) 
3. Victim's `DataLayerService.update_subscriptions_from_wallet` pulls the malicious URL into `data_store` subscriptions.
4. On the next `fetch_and_validate` cycle, `download_file`→`http_download` issues a GET to the attacker-supplied internal URL from the victim node's network: [6](#0-5) 
5. The response is inserted as a delta/full-tree file attempt; even if validation later rejects malformed content, the outbound SSRF request to the internal resource has already completed.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:

            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )

        Add a mirror coin to the DB
        """

        async with self.db_wrapper.writer_maybe_transaction() as conn:
            await conn.execute_insert(
                "INSERT OR REPLACE INTO mirrors VALUES (?, ?, ?, ?, ?)",

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
