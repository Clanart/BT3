### Title
Gasless module's "sender with code is not allowed" check can be bypassed by EIP-7702 delegated EOAs, letting smart-contract-wallet logic act as a proxy for proposer-subsidized gasless swaps - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `gasless` (KIP-247) module is designed to subsidize gas for plain EOAs only. It explicitly rejects any sender with code so that arbitrary smart-contract logic cannot piggyback on proposer-funded `LendTx`/`GaslessSwapTx` execution. This "no code" check is performed only once, at mempool admission time, against the state at admission — not re-validated at block-building/execution time against transactions that execute earlier in the same block. Since Kaia supports EIP-7702-style `SetCodeAuthorization` (`applyAuthorization` in `blockchain/state_transition.go`), an EOA can submit a `SetCode` transaction that installs delegated (and potentially upgradeable/arbitrary) contract logic in the same block, sequenced before its gasless approve/swap transactions. This mirrors the reported bug class: an account that looks unprivileged ("not a smart contract wallet") at the time it is checked/verified can later acquire delegatecall-driven logic and use the granted privilege (here, gasless subsidized swap execution) as a proxy for arbitrary, policy-bypassing exchanges.

### Finding Description
The gasless module's sender-code gate is implemented in `checkBalanceForApprove`/`checkBalanceForSwap`: [1](#0-0) [2](#0-1) 

This check is gated by `ShouldCheckSenderCode`, which is only enabled at the highest `BalanceCheckLevelAll`: [3](#0-2) 

`GetCheckBalance()` is invoked once, at the point the transaction is validated for pool admission (`checkBalanceForApprove`/`checkBalanceForSwap`), using the chain's *current* head state at that moment: [4](#0-3) 

Kaia's state transition supports EIP-7702-like account delegation via `SetCodeAuthorization`, which installs delegated code onto an EOA's account when the authorizing transaction is executed: [5](#0-4) 

Because the delegation is only installed when the `SetCode` transaction actually executes on-chain, and the gasless sender-code check runs earlier (at mempool admission, before block assembly), an EOA can pass the "no code" gate while its code is still empty, and then have a `SetCodeAuthorization` transaction execute earlier in the same block (before the bundled `LendTx`/`GaslessApproveTx`/`GaslessSwapTx`), installing delegated logic just in time for the subsidized swap to execute against a fully "smart-contract-wallet"-like account. The bundling logic (`ExtractTxBundles`) only orders the gasless approve/swap sequence relative to each other and checks for bundle conflicts; it performs no additional check that the sender remains code-free at execution time: [6](#0-5) 

This is directly analogous to the reported issue: the "attestation"/admission check (verifying the actor is not — and should never become — an arbitrary smart contract) is performed once, and the underlying account can later acquire delegatecall-based logic and continue to enjoy the granted privilege (in this case, proposer-funded gasless execution) for policy-violating purposes.

### Impact Explanation
If exploited, a delegated EOA (functionally a smart-contract wallet via EIP-7702) can consume proposer-subsidized gas (`LendTx` funds via `GetLendTxGenerator`) while executing arbitrary contract logic disguised as a plain gasless swap, defeating the explicit design intent that gasless subsidies are restricted to non-contract senders (`BalanceCheckLevelAll`'s sender-code check exists specifically to prevent this). This can be used to drain proposer-funded gas lending to fund arbitrary contract execution, circumventing an intentional access-control/anti-abuse boundary of the KIP-247 gasless mechanism, an economic-abuse vector with direct value implications for block proposers who fund `LendTx`.

### Likelihood Explanation
Medium: it requires only a single account with (a) knowledge of the `SetCodeAuthorization`/EIP-7702 transaction format available in Kaia, and (b) the ability to craft/sequence a `SetCode` transaction ahead of the standard gasless approve/swap transactions in the same block — both of which are permissionlessly reachable by any ordinary transaction sender, requiring no special privileges, validator collusion, or leaked keys.

### Recommendation
Re-validate `ShouldCheckSenderCode` (i.e., re-check `GetCode(sender)`) at block-building/execution time — immediately before executing the bundled `GaslessApproveTx`/`GaslessSwapTx` — rather than only at mempool admission time, so that any code installed by an intervening `SetCodeAuthorization` transaction within the same block is detected before subsidized gas is disbursed. Alternatively, reject bundling a gasless approve/swap transaction in the same block as any `SetCode` transaction authorizing the same sender.

### Proof of Concept
1. Attacker EOA `A` (no code) submits `SetCodeTx` delegating `A` to attacker-controlled contract `C` (arbitrary/upgradeable swap-proxy logic), nonce `n`.
2. In parallel, `A` submits `GaslessApproveTx` (nonce `n+1`) and `GaslessSwapTx` (nonce `n+2`) per KIP-247 format.
3. At mempool admission, `checkBalanceForApprove`/`checkBalanceForSwap` call `getCurrentHasCode(A)` against the pre-block state, where `A` still has no code — the checks pass.
4. During block assembly, `SetCodeTx` executes first via `applyAuthorization`, installing delegated code on `A`.
5. The gasless bundle (`LendTx`, `GaslessApproveTx`, `GaslessSwapTx`) executes next in the same block, now against an account `A` that carries delegated smart-contract logic, using proposer-funded gas to execute the delegated contract's logic instead of a plain EOA swap — bypassing the sender-code restriction that was supposed to gate this exact scenario.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")

func (st *StateTransition) applyAuthorization(auth *types.SetCodeAuthorization, rules params.Rules) (err error) {
	authority, err := st.validateAuthorization(auth)
	if err != nil {
		return err
	}

	// If the account already exists in state, refund the new account cost
	// charged in the initrinsic calculation.
	if st.state.Exist(authority) {
		// If the account is not AccountKeyTypeLegacy, setcode is not allowed.
		accountKeyType := st.state.GetKey(authority).Type()
		if !accountKeyType.IsLegacyAccountKey() {
			return fmt.Errorf("%w: %v", ErrAuthorizationNotAllowAccountKeyType, accountKeyType)
		}
		st.state.AddRefund(params.CallNewAccountGas - params.TxAuthTupleGas)
	}

	// Update nonce and account code.
	st.state.IncNonce(authority)
	delegation := types.AddressToDelegation(auth.Address)
	if common.EmptyAddress(auth.Address) {
		// Delegation to zero address means clear.
		st.state.SetCodeToEOA(authority, []byte{}, rules)
		return nil
	}

	// Otherwise install delegation to auth.Address.
	// We treat EOA and SCA as separate objects and therefore need to use
	// distinct methods.
	st.state.SetCodeToEOA(authority, delegation, rules)

	return nil

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
