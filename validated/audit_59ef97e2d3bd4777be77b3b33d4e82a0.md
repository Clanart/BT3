### Title
Unanchored `issueUrl` regex allows link-spoofing: attacker-controlled URLs are relabeled as trusted `#N` issue references while the real click destination remains fully attacker-controlled - (File: `app/src/lib/markdown-filters/issue-link-filter.ts`)

### Summary
`issueUrl()` builds a `RegExp` from `escapeRegExp(gitHubURL) + '/' + nameWithOwner + '/' + (issues|pull|discussions) + '/' + refNumber` with **no `^`/`$` anchors**. [1](#0-0) 
Because the regex is unanchored, `String.prototype.test`/`match` will succeed if the pattern occurs **anywhere** inside the string, not only when the whole string is a canonical GitHub issue/PR/discussion URL.

### Finding Description
`IssueLinkFilter` is only supposed to rewrite an autolinked raw URL (where `marked`/GFM has produced `<a href="URL">URL</a>`, i.e. `href === innerText`) into a short `#N` reference. The safety of that rewrite depends entirely on the assumption that the matched substring **is** the whole href.

The tree walker only checks `el.href !== el.innerText` (equality, not that the whole string matches the issue-URL shape): [2](#0-1) 

`isGitHubIssuePullDiscussionLink` then applies `issueUrl(repository).test(anchor.href)`, an unanchored test, after a couple of narrow negative filters (pull-request-tab suffix, `.ext`-style suffix) that don't prevent extra content **before** or **elsewhere around** the match: [3](#0-2) 

Finally, `filter()` re-runs the same unanchored regex against the *text*, extracts `refNumber`/`anchor` from the matched substring, and replaces the visible text with `#refNumber (...)`, **while leaving the anchor's `href` attribute untouched** (the node is cloned, not recreated): [4](#0-3) 

Because the regex has no start/end anchors, an attacker can craft a raw URL such as:

```
https://evil.example/redirect?to=https://github.com/owner/repo/issues/1
```

When this literal string appears as plain text in attacker-controlled markdown (issue body, PR description/comment, review, Copilot conflict-resolution summary, etc.), `marked`'s GFM autolinker wraps it as `<a href="https://evil.example/redirect?to=https://github.com/owner/repo/issues/1">https://evil.example/redirect?to=https://github.com/owner/repo/issues/1</a>` — href and innerText are identical, so the tree walker accepts the node. `issueUrl(repository)` matches the embedded `https://github.com/owner/repo/issues/1` substring, so `isGitHubIssuePullDiscussionLink` returns true, and `filter()` rewrites the visible text to `#1`, while `href` remains the full `https://evil.example/...` URL.

Note: because the `nameWithOwner` owner segment is restricted to `\w+(?:-\w+)*` (no dots), a classic subdomain-confusable host like `github.com.evil.com/...` does **not** match (the `/` immediately after the escaped host literal fails). The exploitable variant is embedding the canonical GitHub URL as a *substring later in the string* (e.g. inside a query parameter or path segment of an attacker-controlled host), not a host-prefix collision at position 0.

When the user later clicks the now-innocuous-looking `#1` link, `SandboxedMarkdown`'s click interceptor forwards the anchor's real, unmodified `href` to `onMarkdownLinkClicked`, which callers wire to `dispatcher.openInBrowser(url)` / `shell.openExternal(url)`: [5](#0-4) [6](#0-5) [7](#0-6) 

So the browser is opened at the attacker's chosen `https://evil.example/...` URL even though the rendered UI told the user this was reference `#1` to a legitimate GitHub issue — a mismatch between the trust signal presented to the user and the true navigation target.

### Impact Explanation
This is a link-spoofing / trust-indicator-forgery bug: an attacker who can post content rendered through `SandboxedMarkdown` (PR/issue body or comments, PR review body, Copilot conflict-resolution summaries) can disguise an arbitrary external URL as a benign, in-repo `#N` issue reference. The very purpose of the original raw-URL text (which a cautious user could visually inspect before clicking) is destroyed by the rewrite, making the link's real destination invisible in the UI. This can be leveraged to drive users to credential-phishing pages (e.g., a fake GitHub sign-in) or malware-download pages, all opened via `shell.openExternal`, satisfying the "unauthorized OAuth or account binding" / phishing-enabling impact category listed as valid.

### Likelihood Explanation
The attack requires nothing more than the attacker being able to author markdown content that a victim views in GitHub Desktop (issue/PR comment, PR description, review body) — pure unprivileged, attacker-controlled repository/API content, matching the in-scope threat model. No admin rights, local access, or unnatural user interaction beyond a single normal-looking click are required.

### Recommendation
Anchor the `issueUrl` regex with `^` and `$` (or use `.match`/`.test` against the full trimmed string with explicit start/end assertions), and additionally verify in `filter()` that the *entire* text/href — not merely a substring — matches the canonical issue/PR/discussion URL shape before rewriting the display text, e.g. `^${escapeRegExp(gitHubURL)}/...\d+(#...)?$`.

### Proof of Concept
```ts
import { issueUrl } from '../../../src/lib/markdown-filters/issue-link-filter'
import { GitHubRepository } from '../../../src/models/github-repository'

// repository.endpoint resolves gitHubURL to "https://github.com"
const regex = issueUrl(fakeRepository)

const spoofedHref =
  'https://evil.example/redirect?to=https://github.com/owner/repo/issues/1'

// Unanchored regex matches a substring embedded in an unrelated attacker URL
expect(regex.test(spoofedHref)).toBe(true)

const match = spoofedHref.match(regex)
expect(match?.groups?.refNumber).toBe('1')
// -> filter() will render text as "#1", while href stays fully attacker-controlled
```
This demonstrates that `issueUrl(repository)` matches (and `IssueLinkFilter.filter` will relabel) a URL whose true destination is `https://evil.example/...`, not the GitHub issue implied by the rendered `#1` text.

export function issueUrl(repository: GitHubRepository): RegExp {
  const gitHubURL = getHTMLURL(repository.endpoint)
  return new RegExp(
    escapeRegExp(gitHubURL) +
      '/' +
      /** A regexp that searches for the owner/name pattern in issue href */
      /(?<nameWithOwner>\w+(?:-\w+)*\/[.\w-]+)/.source +
      '/' +
      /(?:issues|pull|discussions)/.source +
      '/' +
      /** A regexp that searches for the number and #anchor of an issue reference */
      /(?<refNumber>\d+)(?<anchor>#[\w-]+)?\b/.source
  )
}

  private isGitHubIssuePullDiscussionLink(anchor: HTMLAnchorElement) {
    const isIssuePullOrDiscussion = /(issue|pull|discussion)/.test(anchor.href)
    if (!isIssuePullOrDiscussion) {
      return false
    }

    const isPullRequestTab = /\d+\/(files|commits|conflicts|checks)/.test(
      anchor.href
    )
    if (isPullRequestTab) {
      return false
    }

    const isURlCustomFormat = /\.[a-z]+\z/.test(anchor.href)
    if (isURlCustomFormat) {
      return false
    }

    return issueUrl(this.repository).test(anchor.href)
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const { textContent: text } = node
    if (!isElement(node, 'a') || text === null) {
      return null
    }

    const match = text.match(issueUrl(this.repository))
    if (match === null || match.groups === undefined) {
      return null
    }

    const { refNumber, anchor } = match.groups
    const newNode = node.cloneNode(true)
    newNode.textContent = this.getConsistentIssueReferenceText(
      refNumber,
      anchor
    )

    return [newNode]
  }
