## Analysis

The Sherlock report's core broken invariant: two independent settlement paths for the same underlying claim (Pyth on-chain price vs. Chainlink fallback) are not mutually exclusive/consistent, so a value that should be resolved exactly once (a valid liquidation price) can end up permanently blocked because the "recovery" path doesn't actually reconcile state with the primary path.

The closest local analog in Hyperbridge is a **state-consistency gap between the two terminal outcomes of a `GetRequest`** — a successful `GetResponse` delivery and a `GetRequestTimeout` — which are supposed to be mutually exclusive but share fee-bearing state (`_requestCommitments[commitment]`) that only one of the two paths clears.

### Title
Escrowed relayer fee for a `GetRequest` can be paid out twice via `dispatchIncoming(GetResponse)` and a later `dispatchTimeOut(GetRequestTimeout)` for the same commitment - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse memory response, address relayer)` pays the relayer fee out of `_requestCommitments[commitment].fee` on a successful response delivery, but — unlike every sibling dispatch function — never deletes the `_requestCommitments[commitment]` entry afterward. `dispatchTimeOut(GetRequestTimeout, ...)`, the mutually-exclusive terminal path for the same request, explicitly deletes that same mapping *before* invoking the module callback specifically "so that it can be retried" / for "replay protection," and unconditionally refunds `meta.fee` again if the callback succeeds. Because the response path never clears the entry, the timeout path's only guard (`meta.sender == address(0)` ⇒ `UnknownMessage`) does not fire for an already-responded-to request, allowing the same escrowed fee to be paid out twice.

### Finding Description
Compare the two terminal handlers in `evm/src/core/EvmHost.sol`: [1](#0-0) 

```solidity
function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
    // replay protection
    bytes32 commitment = response.request.hash();
    _responseReceipts[commitment] = ResponseReceipt({...});
    (bool success,) = ...call(onGetResponse...);
    if (!success) { delete _responseReceipts[commitment]; return; }
    // reward the relayer fee
    uint256 fee = _requestCommitments[commitment].fee;
    if (fee != 0) { IERC20(feeToken()).safeTransfer(relayer, fee); }
    emit GetRequestHandled(...);
}
```

versus [2](#0-1) 

```solidity
function dispatchTimeOut(GetRequestTimeout memory timeout, FeeMetadata memory meta, bytes32 commitment)
    external restrict(_hostParams.handler)
{
    // replay protection
    delete _requestCommitments[commitment];
    (bool success,) = ...call(onGetTimeout...);
    if (!success) { _requestCommitments[commitment] = meta; return; }
    if (meta.fee != 0) { IERC20(feeToken()).safeTransfer(meta.sender, meta.fee); }
    emit GetRequestTimeoutHandled(...);
}
```

`dispatchTimeOut` itself labels its `delete _requestCommitments[commitment]` as "replay protection." `dispatchIncoming(GetResponse)`, which reads the exact same fee bookkeeping structure to pay the relayer, does no equivalent deletion. The caller-side guard in `HandlerV2.handleGetRequestTimeouts` relies on this mapping being cleared once a request is settled: [3](#0-2) 

```solidity
FeeMetadata memory meta = host.requestCommitments(request.hash());
if (meta.sender == address(0)) revert UnknownMessage();
...
host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
```

Because `_requestCommitments[commitment]` still holds a non-zero `sender`/`fee` after a successful `GetResponse` was already delivered and paid, this `UnknownMessage` check does not detect that the request was already settled. The only remaining barrier is the non-membership proof against `RESPONSE_RECEIPTS_STORAGE_PREFIX` at `message.height` on the counterparty state — but that proof authenticates the *destination* chain's own local receipt bookkeeping, not the source-chain `_requestCommitments` fee-escrow entry that `dispatchIncoming(GetResponse)` already consumed. The two state machines (source-chain fee escrow vs. destination-chain response receipt) are not bound to each other by this check, so a request whose response has already been paid out on the source chain remains eligible, from the source host's point of view, to also be timed out and refunded — as long as a (stale, expired, or divergent) state commitment for the destination height can still produce a non-membership proof for that key (e.g., an old/pruned/never-yet-updated commitment, or a state root where the module never wrote a receipt under that particular prefix for this commitment).

### Impact Explanation
This breaks the "moves exactly once" invariant explicitly required for bridged relayer rewards. The escrowed `fee` for a single `GetRequest` can be transferred out twice from the host contract — once to the relayer who delivered the valid `GetResponse` (`dispatchIncoming`), and a second time to whoever submits a `GetRequestTimeout` message with a non-membership proof against a state commitment that doesn't reflect that the response was ever recorded there. This is a double-payment/double-settlement of protocol funds, directly matching the "replay/double-claim/double-settlement" impact category and the requirement that relayer rewards "move exactly once."

### Likelihood Explanation
The missing deletion is unconditional code, not a race condition or timing edge case — every successful `dispatchIncoming(GetResponse)` leaves `_requestCommitments[commitment]` intact. The remaining question is whether an attacker can obtain a valid non-membership proof for the `RESPONSE_RECEIPTS_STORAGE_PREFIX + commitment` key at *some* state-machine height after the response was already paid (e.g., an older, still-unexpired commitment height that predates when a receipt would have been written on the destination, or any destination state at a height where the module simply never persisted a receipt under that key/prefix). This does not require a malicious relayer, prover, or admin — only a normal relayer submitting a legitimately-verifiable (per current on-chain checks) timeout message for a request whose fee was already paid via the response path.

### Recommendation
Delete `_requestCommitments[commitment]` inside `dispatchIncoming(GetResponse, ...)` immediately after (or as part of) paying out the relayer fee, mirroring the "replay protection" pattern already used in `dispatchTimeOut`. Additionally, `HandlerV2.handleGetRequestTimeouts` should independently check that no `_responseReceipts` entry exists for the commitment on the *source* host (not only a destination-side non-membership proof), so a locally-recorded successful response can never be followed by a timeout refund for the same commitment.

### Proof of Concept
1. A `GetRequest` is dispatched from the source chain; `_requestCommitments[commitment] = FeeMetadata{sender, fee}` is stored, escrowing `fee`.
2. A relayer delivers a valid `GetResponse` via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`. `onGetResponse` succeeds, `fee` is transferred to `relayer`, but `_requestCommitments[commitment]` is left untouched with `sender != address(0)` and `fee` still non-zero.
3. Later, a relayer submits `HandlerV2.handleGetRequestTimeouts` for the same request with a state commitment/height whose non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX + commitment` still passes (e.g., an earlier committed destination height, or a destination storage layout where this specific prefix/key was never populated for the request in question).
4. `meta.sender == address(0)` check passes (it is non-zero from step 1), so `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes, calls `onGetTimeout`, and on success refunds `meta.fee` a second time to `meta.sender` — double-paying the same escrowed fee that was already paid out in step 2.     /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
