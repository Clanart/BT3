### Title
Division by Zero panic in `NextMagmaBlockBaseFee` via ungated `kip71.gastarget` governance vote - ([File: params/kip71_config.go])

### Summary
The `Kip71GasTarget` governance parameter uses `noopFormatChecker` (no validation) while `checkConsistency` in `kaiax/gov/headergov/impl/header.go` also performs no bounds check on it, allowing the governing node to ratify `GasTarget = 0`. This value then flows unguarded into `NextMagmaBlockBaseFee`, which performs `big.Int.Div` using `GasTarget` as divisor, causing a runtime panic (division by zero) executed by every full node during header verification and fee computation.

### Finding Description
`Kip71GasTarget`'s parameter descriptor uses `FormatChecker: noopFormatChecker`, accepting any `uint64` including `0`: [1](#0-0) 

Unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which have explicit consistency checks (`ErrLowerBoundBaseFee`/`ErrUpperBoundBaseFee`) in `checkConsistency`, `gov.Kip71GasTarget` falls into the no-op branch that unconditionally returns `nil`: [2](#0-1) 

The unit test explicitly confirms `Kip71GasTarget` is accepted with no validation of non-zero: [3](#0-2) 

Once ratified, `GasTarget` flows into `params.KIP71Config.GasTarget` via `ParamSet.ToKip71Config()` and is used as a divisor in `NextMagmaBlockBaseFee` whenever `parentGasUsed != gasTarget`: [4](#0-3) 

If `GasTarget == 0` and any block uses gas (`parentGasUsed > 0`), the `parentGasUsed > gasTarget` branch executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor. In Go's `math/big`, `Int.Div`/`Int.Quo` panics with "division by zero" when the divisor is zero — unlike the referenced Solidity report, this is a Go runtime panic, not a revert.

Only `BaseFeeDenominator` has an explicit workaround for the zero case (falling back to `64`): [5](#0-4) 
No equivalent guard exists for `GasTarget`.

### Impact Explanation
`NextMagmaBlockBaseFee` is called during block header verification (`VerifyMagmaHeader`) which every syncing/validating node executes for every block after the Magma fork, and also from RPC fee-history logic (`node/cn/gasprice/feehistory.go`). A panic here crashes the node process handling block import/verification. Since this is deterministic based on chain state (ratified governance parameter + block gas usage), it would crash all full nodes/validators simultaneously — a chain halt / consensus-wide denial of service, not merely a single node issue. This satisfies "state divergence between honest nodes" / chain-halting DoS categories, warranting Medium/High severity.

### Likelihood Explanation
Requires the governing node (single-mode) to cast a `kip71.gastarget=0` vote, which is a legitimate, unauthenticated-by-value-check governance action reachable through the public `governance_vote` RPC and included via normal header voting/ratification flow — there is no format or consistency check blocking a zero value, unlike the sibling `LowerBoundBaseFee`/`UpperBoundBaseFee` parameters which are explicitly protected. Once ratified at an epoch boundary, virtually any subsequent block with non-zero gas usage triggers the panic on all nodes simultaneously.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` rejecting zero (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and/or add an explicit `GasTarget == 0` guard/consistency check in `checkConsistency` (`kaiax/gov/headergov/impl/header.go`) similar to the `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` cases. Defensively, `NextMagmaBlockBaseFee` in `params/kip71_config.go` should also guard against `gasTarget == 0` (e.g., fallback similar to `BaseFeeDenominator`'s zero-fallback) to avoid a panic even if an invalid value is ever set.

### Proof of Concept
1. Governing node calls `governance_vote("kip71.gastarget", 0)`; `NewVoteData` accepts it since `noopFormatChecker` returns true for any uint64.
2. The vote is included in `header.Vote`, and `VerifyVote`/`checkConsistency` return `nil` for `gov.Kip71GasTarget` unconditionally.
3. At the next epoch boundary, the vote is ratified into `header.Governance`, and `GetParamSet` returns `GasTarget = 0` for subsequent blocks.
4. On the following block, if `parentHeaderGasUsed > 0`, `NextMagmaBlockBaseFee` computes `gasUsedDelta := SetUint64(parentGasUsed - 0)`, then `x.Div(x, new(big.Int).SetUint64(0))` — this panics with "division by zero", crashing every node that verifies or builds this header (`params/kip71_config.go:100-103`).
