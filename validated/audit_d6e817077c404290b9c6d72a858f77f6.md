### Title
Unbounded `io.ReadAll` of the JSON-RPC HTTP body in NewRelic/Datadog tracing middleware bypasses `MaxRequestContentLength`, enabling memory-exhaustion DoS - (File: `networks/rpc/http_newrelic.go`, `networks/rpc/http_datadog.go`)

### Summary
The Consul advisory (CVE-2025-11374) is a case where Content-Length header validation did not actually bound the amount of data read for the KV endpoint, allowing a DoS via oversized request bodies. Kaia's JSON-RPC HTTP server has an analogous gap: the size-limiting logic (`validateRequest` + `io.LimitReader`) only applies inside `Server.ServeHTTP`, but the optional NewRelic/Datadog tracing middlewares read the entire request body with `io.ReadAll` *before* that check/limit is ever applied.

### Finding Description
The primary JSON-RPC HTTP handler enforces a body-size cap two ways: `validateRequest` rejects requests whose declared `r.ContentLength` exceeds `common.MaxRequestContentLength`, and `newHTTPServerConn` wraps the body in `io.LimitReader(r.Body, MaxRequestContentLength)` regardless of the declared Content-Length (defense-in-depth against chunked/unset Content-Length). [1](#0-0) [2](#0-1) 

However, when NewRelic or Datadog tracing is enabled (via env vars `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or `DD_TRACE_ENABLED`), an extra middleware layer wraps the handler *outside* the size-limited codec path: [3](#0-2) 

Both `newNewRelicHTTPHandler` and `newDatadogHTTPHandler` call `getRPCRequests(r)` to extract the method name for tracing purposes before invoking the inner handler: [4](#0-3) [5](#0-4) 

`getRPCRequests` reads the entire body via `io.ReadAll(r.Body)` with **no size limit whatsoever**, unlike the downstream `newHTTPServerConn` which caps reads with `io.LimitReader`: [6](#0-5) 

Because `r.ContentLength` validation (`validateRequest`) is not consulted at this layer at all, and because Go's `net/http` server does not itself cap body size for chunked-encoded or unset-Content-Length requests, a caller can stream an arbitrarily large body (e.g. chunked transfer-encoding, so `r.ContentLength == -1`) directly into memory via this unguarded `io.ReadAll`, entirely bypassing `common.MaxRequestContentLength` (default 512 KiB). [7](#0-6) 

### Impact Explanation
Each request that reaches `getRPCRequests` is fully buffered in memory with no upper bound, regardless of the operator-configured `MaxRequestContentLength`/`maxRequestContentLength` flag. A public RPC caller can repeatedly send large (or slow, chunked, unbounded) POST bodies to the JSON-RPC HTTP endpoint, causing unbounded memory allocation per request and, with modest concurrency, node-wide memory exhaustion/crash — a denial of service against the node's public RPC interface, consistent with CWE-770 (Allocation of Resources Without Limits).

### Likelihood Explanation
This path is only active when an operator has enabled NewRelic or Datadog tracing for the RPC server (setting the relevant environment variables), which is a supported, documented production observability feature and not itself a privileged/malicious-operator action. Once enabled, the vulnerable code path is reached by any ordinary, unauthenticated HTTP JSON-RPC request — no special privileges are required from the caller. The likelihood is therefore conditioned on this optional-but-common deployment configuration.

### Recommendation
Apply the same `io.LimitReader(r.Body, common.MaxRequestContentLength)` bound (and/or the `validateRequest` Content-Length check) inside `getRPCRequests` before calling `io.ReadAll`, so the tracing middlewares cannot read more than the configured maximum regardless of how the body is transferred (fixed Content-Length, chunked, or otherwise).

### Proof of Concept
1. Start a Kaia node with the HTTP RPC endpoint enabled and NewRelic tracing enabled (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` set), which wraps the handler with `newNewRelicHTTPHandler`. [8](#0-7) 
2. Send an HTTP POST to the RPC endpoint using chunked transfer-encoding (no `Content-Length` header) with an extremely large streamed body (many GB), e.g. via `curl -X POST --data-binary @- -H "Transfer-Encoding: chunked" http://node:8551 < /dev/urandom`.
3. Because `getRPCRequests` calls `io.ReadAll(r.Body)` unconditionally before any size check, the server buffers the entire streamed body in memory, exceeding `common.MaxRequestContentLength` many times over and exhausting node memory, while a normal (non-traced) request of the same size would be rejected/truncated by `validateRequest`/`io.LimitReader` in `Server.ServeHTTP`. [6](#0-5)

func NewHTTPServer(cors []string, vhosts []string, timeouts HTTPTimeouts, srv http.Handler) *http.Server {
	timeouts = sanitizeTimeouts(timeouts)
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")

	// If os environment variables for NewRelic exist, register the NewRelicHTTPHandler
	nrApp := newNewRelicApp()
	if nrApp != nil {
		handler = newNewRelicHTTPHandler(nrApp, handler)
	}

	// If os environment variables for Datadog exist, register the NewDatadogHTTPHandler
	ddTracer := newDatadogTracer()
	if ddTracer != nil {
		handler = newDatadogHTTPHandler(ddTracer, handler)
	}

	return &http.Server{
		Handler:      handler,
		ReadTimeout:  timeouts.ReadTimeout,
		WriteTimeout: timeouts.WriteTimeout,
		IdleTimeout:  timeouts.IdleTimeout,
	}
}

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}
