### Title
Gasless swap price validated only at tx-pool admission, not re-verified against DEX pool state at block-build time — stale price allows an under-collateralized gas repayment - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
Kaia's gasless-transaction module (KIP-247) fronts gas fees to a user via a `LendTxGenerator` and expects the user's `GaslessSwapTx` to repay the proposer in KAIA obtained by swapping an ERC-20 token through the whitelisted `GaslessSwapRouter`/DEX pool. The sufficiency of the repayment is checked once, at tx-pool admission time, by comparing `swapArgs.AmountIn` against `routerContract.GetAmountIn(nil, token, minAmountOut)` — a live view call into the DEX pool's current reserves. This is directly analogous to the reported bug class: an assumed stable exchange rate (in the original report, USDC≈$1) is used as collateral backing without safeguards against the price moving between assumption-time and settlement-time.

### Finding Description
In `checkBalanceForSwap` [1](#0-0) , the module fetches the *current* pool exchange rate via `routerContract.GetAmountIn(nil, token, minAmountOut)` and requires `swapArgs.AmountIn >= requiredAmountIn`. This check happens when the transaction is validated for pool admission/promotion (`GetCheckBalance`, `IsReady`), using the state at that moment. The bundle (`[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]`) is only assembled later in `ExtractTxBundles` [2](#0-1) , and actually executed on-chain during block building, potentially many pool state changes (or even same-block reordering) later.

Because `AmountIn`/`MinAmountOut`/`AmountRepay` are all pre-signed, fixed transaction fields taken from the token/KAIA quote read once at admission, if the pool's reserves shift before inclusion (natural price movement, a large trade landing earlier in the same block, or a searcher/validator-favorable reordering since gasless bundles are proposer-composed), the swap executed inside `swapForGas` on-chain could yield fewer KAIA than the value the proposer already fronted via `LendTxGenerator`. Unlike a normal transaction where the sender bears slippage risk against their own funds, here the *proposer* has already extended value (gas lent) based on a stale, unverified assumption that the swap will yield `amountRepay` in KAIA — i.e., the value of the token collateral backing the gas loan is assumed fixed but is not re-verified at settlement.

This mirrors the disclosed bug class precisely: a protocol treats a token's exchange value as reliable collateral (in Perennial, USDC↔$1 via `MultiInvoker._handleWrap`/`_handleUnwrap`; here, ERC-20 token↔KAIA via `GaslessSwapRouter.GetAmountIn`), performing the collateral-sufficiency check at one point in time without re-validating it at the point the assumption is actually relied upon (block inclusion / settlement).

### Impact Explanation
If the DEX-quoted price used for admission diverges from the price realized at inclusion (e.g., due to a legitimate price move, or reserve manipulation via a preceding trade within the block that a searcher or the proposer itself controls), the gasless swap can settle for less KAIA than `amountRepay`, meaning the block proposer that already fronted gas via the lend transaction is not fully repaid — a direct value-extraction/fee-delegation abuse vector reachable by any unprivileged transaction sender who can construct a gasless swap around a moment of unfavorable pool pricing. This is a Medium-severity fee/value-abuse risk consistent with the rules' required "fee or fee-delegation abuse" or "unauthorized value movement" categories.

### Likelihood Explanation
Likelihood is Medium: the gasless flow is reachable by any public sender submitting a normal `GaslessApproveTx`/`GaslessSwapTx` pair; no privileged access is required. Exploitation requires the attacker (or an unrelated market event) to move the DEX pool price between the tx-pool admission check and on-chain execution — feasible for low-liquidity whitelisted tokens or via same-block trade ordering, but requires enough price movement to erode the margin between `minAmountOut` and `amountRepay`, which the current design does allow to be set with a very small buffer (the `IsExecutable`/admission logic does not enforce a mandatory slippage buffer beyond `minAmountOut >= amountRepay`).

### Recommendation
- Re-validate the swap's expected repayment amount against the DEX pool state immediately before/during block inclusion (not only at pool-admission time), and drop or re-bundle the gasless transaction if the repayment would fall short.
- Enforce a mandatory minimum slippage buffer between `minAmountOut` and `amountRepay` (rather than allowing users to set `minAmountOut` arbitrarily close to `amountRepay`).
- Consider requiring the DEX quote check to be performed using the state at the point the bundle is actually simulated/executed within `ExtractTxBundles`, so stale price checks from tx-pool time cannot be relied upon for settlement guarantees.

### Proof of Concept
1. Attacker approves a low-liquidity whitelisted token to `GaslessSwapRouter` and submits a `GaslessApproveTx` + `GaslessSwapTx` with `AmountIn` computed from `GetAmountIn(token, minAmountOut)` at time T0, where `minAmountOut` is set only marginally above `amountRepay` (checked in `checkBalanceForSwap`, `kaiax/gasless/impl/tx_pool.go:107-142`).
2. Both transactions pass the tx-pool admission checks (`IsApproveTx`/`IsSwapTx`/`checkBalanceForSwap`) and are promoted to pending.
3. Before the proposer includes the bundle (`ExtractTxBundles`, `kaiax/gasless/impl/builder.go:28-72`), the pool's reserves shift unfavorably (e.g., another trade lands first in the same block, or natural price drift occurs since there is no re-check at inclusion time).
4. The bundle executes: `LendTxGenerator` has already fronted the gas fee to the user; the `swapForGas` call now returns less than `amountRepay` in KAIA (or reverts if it fails contract-level minAmountOut check, denying the proposer any repayment for gas already fronted).
5. Result: the block proposer suffers value loss (either received insufficient repayment or none), demonstrating that the gasless module's value-backing check is not safe against price movement between validation and settlement.

Note: I was unable to locate and inspect the actual `GaslessSwapRouter.sol` / DEX pool source (only Go bindings were indexed), so the precise on-chain enforcement of `minAmountOut` inside `swapForGas` (i.e., whether the contract itself reverts on insufficient output) could not be fully confirmed from the indexed content. If the on-chain contract strictly enforces `amountOut >= minAmountOut` before repaying, the practical impact narrows to reverted/wasted gasless bundles (proposer's lent gas not recovered) rather than a full value shortfall; a Devin session with full repository access would be needed to confirm this contract logic.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
