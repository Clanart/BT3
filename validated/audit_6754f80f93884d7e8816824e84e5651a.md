### Title
Untrusted `ReceivedOutput` can reassign the spendable `OutPoint` while retaining the multisig-controlled script - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts the `offset`, `TxOut`, and `OutPoint` entirely from serialized input instead of deriving the `OutPoint` from a scanned transaction. [1](#0-0)  `SignableTransaction::new` uses that serialized `outpoint` as the transaction input and the serialized `TxOut` as the Taproot prevout data. [2](#0-1) [3](#0-2)  The only ownership check occurs later in `multisig`, and it verifies only that `offset` derives the claimed `script_pubkey`; it does not prove that the supplied `outpoint` was the output discovered by `Scanner`. [4](#0-3) 

### Finding Description
`Scanner::scan_transaction` constructs a trustworthy `ReceivedOutput` by deriving the offset from its registered script map and calculating `OutPoint::new(tx.compute_txid(), vout)` from the actual transaction. [5](#0-4)  The mass-assignment analog is that `ReceivedOutput::read` bypasses that construction and accepts all three fields from caller-controlled bytes. [1](#0-0) 

A crafted serialized `ReceivedOutput` can therefore pair:

- a valid multisig `offset`,
- a `TxOut` containing the corresponding registered P2TR `script_pubkey`,
- an unrelated attacker-chosen `OutPoint`.

`SignableTransaction::multisig` will accept the object whenever the serialized script equals `p2tr_script_buf(keys.offset(offset).group_key())`. [4](#0-3)  During signing, the threshold signers use `Prevouts::All(&self.tx.prevouts)` and sign the Taproot key-spend digest for the transaction containing the supplied `OutPoint`. [6](#0-5) 

### Impact Explanation
If the assigned `outpoint` identifies a real unspent output paying the same multisig script and carrying the same serialized `TxOut` data, the resulting signature is valid and authorizes spending that different UTXO. [7](#0-6)  This can cause the threshold wallet to sign a spend that was not the scanned output intended by the caller, satisfying the unintended-signing impact class. [8](#0-7) 

The attacker cannot choose an arbitrary script and still pass the `multisig` check; the strongest practical target is another same-script output or output metadata accepted from an untrusted source. [9](#0-8) 

### Likelihood Explanation
The attack requires an untrusted party to supply bytes to `ReceivedOutput::read` that are subsequently passed through `SignableTransaction::new` and `multisig`. [1](#0-0) [10](#0-9)  It also requires the chosen `outpoint` to refer to a real output matching the serialized prevout data for the signature to be consensus-valid. [6](#0-5)  Because neither restriction is enforced inside deserialization or signing setup, an implementation that treats serialized scanner results as request input is directly exposed. [1](#0-0) [3](#0-2) 

### Recommendation
Do not deserialize authority-bearing fields as independent values when they must remain bound to scanner observations. Either make `ReceivedOutput::read` internal-only/trusted-state deserialization or reconstruct and validate it against the chain by:

1. checking that `outpoint` exists and is unspent,
2. fetching its actual `TxOut`,
3. requiring equality with the serialized `TxOut`, and
4. recomputing/authorizing `offset` through the same script registration path used by `Scanner::scan_transaction`. [5](#0-4) 

At minimum, `SignableTransaction::new` should reject externally supplied `ReceivedOutput` values unless their `outpoint`/`TxOut` binding was authenticated or chain-verified. [2](#0-1) 

### Proof of Concept
Conceptually, serialize a `ReceivedOutput` whose `outpoint` has been changed to another UTXO paying the same P2TR script and carrying the same value:

```rust
// Controlled by an untrusted caller.
let mut forged_bytes = legitimate_received_output.serialize();

// Parse normally.
let mut forged = ReceivedOutput::read(&mut forged_bytes.as_slice())?;

// Equivalent attacker intent:
// forged.offset    = offset_for_registered_script
// forged.output    = TxOut { value, script_pubkey: multisig_p2tr_script }
// forged.outpoint  = victim's other UTXO with that same script/value

let stx = SignableTransaction::new(
  vec![forged],
  &payments,
  change,
  data,
  fee_per_vbyte,
)?;

// This succeeds because only output.script_pubkey is compared with the key
// derived from offset; victim's supplied OutPoint is already embedded in tx.
let machine = stx.multisig(&threshold_keys).unwrap();
```

The important distinction is that `multisig` authenticates the `TxOut` script against the threshold key but never authenticates that `previous_output` is the scanner-produced identifier for that same output. [11](#0-10) [4](#0-3)
