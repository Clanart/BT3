### Title
Malformed `ReceivedOutput` bytes create unspendable wallet inputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without proving that the output exists or that the offset actually derives the output’s Taproot key. [1](#0-0)  This lets a crafted byte string represent funds as wallet-owned when they are not spendable.

### Finding Description
The deserializer reads `offset` with `Secp256k1::read_F`, then independently deserializes `output` and `outpoint`, and returns all three without checking `p2tr_script_buf(key + offset * G) == output.script_pubkey` or validating the outpoint against chain state. [2](#0-1)  The consistency check occurs only later inside `SignableTransaction::multisig`, after the malformed object has already been accepted as a received output. [3](#0-2) 

An attacker can pair a real wallet-controlled script with a fabricated value or nonexistent outpoint. [4](#0-3)  Because transaction construction trusts `input.output.value` and `input.outpoint`, the forged object contributes its claimed value and UTXO directly to the spend. [5](#0-4) 

### Impact Explanation
A wallet consuming untrusted serialized outputs can report attacker-chosen balances as received even though no corresponding spendable UTXO exists. [6](#0-5)  If that object reaches `SignableTransaction::new`, the wallet constructs and signs a transaction spending a fabricated or mismatched outpoint; the resulting transaction is invalid on-chain, while accounting has already credited the claimed amount. [7](#0-6) 

### Likelihood Explanation
The input is only bytes passed to `ReceivedOutput::read`, so no private key, validator privilege, network control, or malformed elliptic-curve encoding is required. [8](#0-7)  The attacker only needs a Taproot script the scanner associates with an offset; the normal scanner already stores the base-key script with offset zero and registered-offset scripts with their offsets. [9](#0-8) [10](#0-9) 

### Recommendation
Make `ReceivedOutput` prove its semantic invariant during deserialization or remove trust in serialized output provenance. At minimum, pass the expected wallet key into `ReceivedOutput::read`, recompute `p2tr_script_buf(key + G * offset)`, reject mismatched `script_pubkey`s, and reject offsets not registered with the scanner. [11](#0-10)  Before transaction construction, also verify each `outpoint` and `TxOut` against confirmed chain data rather than trusting the serialized tuple. [5](#0-4) 

### Proof of Concept
Conceptually, for base wallet point `K`, construct:

```text
offset    = 0 serialized as a canonical Secp256k1 scalar
TxOut     = { value: attacker-chosen amount,
              script_pubkey: p2tr_script_buf(K) }
OutPoint  = { txid: arbitrary/nonexistent txid, vout: 0 }
```

Feeding `offset || consensus(TxOut) || consensus(OutPoint)` to `ReceivedOutput::read` succeeds because all three fields are independently decoded and immediately returned. [2](#0-1)  Calling `value()` reports the attacker-chosen amount, and `outpoint()` reports the fabricated UTXO. [12](#0-11)  Since the chosen script matches `keys.offset(0).group_key()`, `SignableTransaction::multisig` accepts it and creates a signing machine for the nonexistent input. [3](#0-2)

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
