## Analog Found: Attacker-controlled commit metadata used as an implicit trust signal (identity spoofing), analogous to `tx.origin` misuse

### Title
Commit committer identity spoofing via unauthenticated name/email fields lets attackers impersonate GitHub's "web flow" - (File: `app/src/lib/web-flow-committer.ts`)

### Summary
The reported Curve issue is a generic instance of a broader bug class: trusting an *implicit, unauthenticated* context value as a proxy for real identity/authorization instead of an explicit, verified input. `tx.origin` is spoofable by any intermediary contract; the same class of flaw exists in GitHub Desktop's `isWebFlowCommitter` check, which infers a trusted "GitHub" identity purely from the plaintext `name`/`email` fields of a Git commit object — fields that are 100% attacker-controlled in any cloned or fetched repository.

### Finding Description
`isWebFlowCommitter` decides whether a commit was produced by GitHub's own web UI (e.g. a PR merge button) solely by string-matching the committer's `name` and `email`: [1](#0-0) 

These values come directly from `git log`'s `%cn <%ce>` format, i.e. the raw committer identity embedded in the commit object by whoever authored it: [2](#0-1) 

There is no cryptographic verification (no GPG/SSH signature check, no correlation with the GitHub API) tying this identity to the real GitHub platform — it is exactly like relying on `tx.origin`/an ambient signal instead of an explicit, authenticated parameter. Anyone who controls a commit (in a cloned, fetched, or locally crafted malicious repository) can simply set `committer.name = "GitHub"` and `committer.email = "noreply@github.com"` with an ordinary `git commit --author=... GIT_COMMITTER_NAME=... GIT_COMMITTER_EMAIL=...` invocation.

This boolean is then consumed by `getAvatarUsersForCommit` to *suppress* the real committer's avatar/identity from being shown to the user, on the theory that "this must be GitHub's automated merge commit, so we don't need to show a separate committer": [3](#0-2) 

### Impact Explanation
A malicious repository author can craft a commit whose committer identity spoofs GitHub's official web-flow committer. When a victim clones/fetches this repository and views commit history in Desktop (e.g. `commit-list-item.tsx`, `expandable-commit-summary.tsx`), the UI will hide the true (attacker) committer and render the commit as if it came through GitHub's trusted merge flow, since `webFlowCommitter` short-circuits the fallback avatar addition: [4](#0-3) [5](#0-4) 

This is a UI-trust-indicator spoof: a user reviewing history before merging/pushing/cherry-picking is misled about who actually produced a commit, undermining a signal (`isWebFlowCommitter`) whose entire purpose is to communicate provenance/trust.

### Likelihood Explanation
Exploitation requires nothing beyond normal repository authorship — no privileged access, no compromised credentials, no local/physical access. Any contributor to (or maintainer of) a repository that a victim clones/fetches can set committer name/email freely via standard Git tooling (`GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, or `git commit --author`). The comment in the code itself acknowledges the heuristic is "best-effort" and can already mismatch for GHES branding differences, underscoring that it was never meant to be a strong authentication mechanism, yet it's used to suppress identity display.

### Recommendation
Do not treat committer `name`/`email` string matches as proof of GitHub-web-flow provenance. Either drop the avatar-suppression behavior entirely (always show the real committer) and instead label a commit as GitHub Web Flow only when it can be corroborated via an authenticated source (e.g., the GitHub REST/GraphQL API's `commit.committer.login` merge/verification metadata, or an actual verified signature), or otherwise clearly caveat in the UI that this label is a heuristic, not a guarantee, so users don't use it as a trust anchor.

### Proof of Concept
1. Clone or create a git repository.
2. Create a commit with a spoofed committer identity:
   ```
   git commit --allow-empty -m "legit-looking change" \
     --author="Attacker <attacker@example.com>"
   GIT_COMMITTER_NAME="GitHub" GIT_COMMITTER_EMAIL="noreply@github.com" \
     git commit --amend --no-edit
   ```
3. Push/host this repository and have the victim clone/fetch it into GitHub Desktop and connect it to a GitHub-hosted `gitHubRepository` (endpoint `getDotComAPIEndpoint()`).
4. Open the commit in Desktop's history view. `isWebFlowCommitter` returns `true` per [6](#0-5) , so `getAvatarUsersForCommit` never adds the true committer's avatar, and the commit is rendered without any indication that "Attacker" (as committer) produced it outside of GitHub's official merge flow.

export function isWebFlowCommitter(
  commit: Commit,
  gitHubRepository: GitHubRepository
) {
  if (!gitHubRepository) {
    return false
  }

  const endpoint = gitHubRepository.owner.endpoint
  const { name, email } = commit.committer

  if (
    endpoint === getDotComAPIEndpoint() &&
    name === 'GitHub' &&
    email === 'noreply@github.com'
  ) {
    return true
  }
```

export function getAvatarUsersForCommit(
  gitHubRepository: GitHubRepository | null,
  commit: Commit
) {
  const avatarUsers = []

  avatarUsers.push(getAvatarUserFromAuthor(commit.author, gitHubRepository))
  avatarUsers.push(
    ...commit.coAuthors.map(x => getAvatarUserFromAuthor(x, gitHubRepository))
  )

  const coAuthoredByCommitter = commit.coAuthors.some(
    x => x.name === commit.committer.name && x.email === commit.committer.email
  )

  const webFlowCommitter =
    gitHubRepository !== null && isWebFlowCommitter(commit, gitHubRepository)

  if (
    !commit.authoredByCommitter &&
    !webFlowCommitter &&
    !coAuthoredByCommitter
  ) {
    avatarUsers.push(
      getAvatarUserFromAuthor(commit.committer, gitHubRepository)
    )
  }
```
