### Title
Deep-link/API-driven `git clone` accepts arbitrary transport URLs (`file://`, `ext::`) with no scheme allowlist, enabling local repo exfiltration or command execution - (File: `app/src/lib/git/clone.ts`)

### Summary
`isClonePathSensitive` in `app/src/lib/git/clone.ts` validates only the destination `path` argument against a hardcoded list of sensitive directories; it performs no validation whatsoever on the `url` argument's transport scheme before it is placed into `args.push('--', url, path)` and executed via `git(args, ...)`. [1](#0-0) [2](#0-1) 

### Finding Description
The `clone()` function is the sink for a deep-link-controlled data flow: the app's custom URL protocol handler parses `x-github-client://openRepo/<url>` into an `IOpenRepositoryFromURLAction` and passes the raw `url` string through `dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository(url)`. [3](#0-2) [4](#0-3) 

That `url` is used to pre-populate the `CloneRepository` dialog's `initialURL`, which flows into the `Generic` tab's free-text URL field with no scheme validation - `CloneGenericRepository` is a plain text box that accepts any string. [5](#0-4) 

When the user clicks "Clone", `cloneImpl` forwards the untouched `url` to `dispatcher.clone(url, path, ...)` and ultimately to `clone()` in `app/src/lib/git/clone.ts`, which only checks `path` via `isClonePathSensitive` and never inspects `url`'s protocol. [6](#0-5) [7](#0-6) 

No allowlist of protocols is enforced anywhere in the codebase: there is no `GIT_ALLOW_PROTOCOL` environment variable, no `core.protocol`/`protocol.allow` config, and `envForProxy` only special-cases `http(s)://` for proxy resolution without rejecting other schemes. [8](#0-7) 

By default, Git treats a URL passed directly to an explicit `git clone` invocation (as opposed to a URL discovered indirectly, e.g. via a submodule) as "user-provided," and its transport allowlist (`file`, `git`, `ssh`, `http(s)`, and `ext`) permits it unless `GIT_ALLOW_PROTOCOL` is explicitly restricted. Since Desktop sets no such restriction, `ext::<command>` and `file://` URLs reach `git` unfiltered.

### Impact Explanation
- `ext::sh -c '<command>'` as a clone URL causes Git's `ext` transport to spawn the specified command as the remote helper, achieving arbitrary command execution outside the intended repo/network-git sandbox.
- `file:///path/to/local/repo` causes Git to perform a local clone, which can be used to exfiltrate the contents of arbitrary local Git repositories the victim has filesystem access to (source code, potentially embedded secrets) into a new working directory, which the application may then display, sync, or push - all without any network git protocol involved.

This breaks the intended invariant (stated by the reviewer) that clone sources should be constrained to legitimate network git protocols, and matches the "Valid Impact" criteria: code execution / file read outside the repo sandbox, reachable via a clicked deep link that the attacker fully controls.

### Likelihood Explanation
Exploitation requires the victim to click an attacker-supplied `x-github-client://openRepo/<url>` link and then click "Clone" in the resulting dialog — a single, ordinary confirmation step that is part of the app's normal deep-link-to-clone flow, not an "unnatural" or unusual step. The URL is fully attacker-controlled and reaches `git()` unmodified through `clone()`, so likelihood is high given a user clicks through the (legitimately expected) flow.

### Recommendation
In `app/src/lib/git/clone.ts`, validate the `url` parameter's scheme before constructing `args` and calling `git()`. Reject or reject-by-default any scheme not in an explicit allowlist (e.g., `https:`, `http:`, `ssh:`, `git:`, plus bare `user@host:path` SCP-like syntax), explicitly rejecting `file:`, `ext:`, and any other Git "user" transport helper syntax. Alternatively/additionally, set `GIT_ALLOW_PROTOCOL` in the environment passed to `git()` (via `envForRemoteOperation`/execution options) to an explicit safe list (`http:https:ssh:git`) for all clone/fetch/push invocations, which centrally blocks `file` and `ext` (and any future risky transports) at the Git layer regardless of caller.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void

  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
