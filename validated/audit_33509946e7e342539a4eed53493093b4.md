## Title
Daemon `register_service` destination-name collision lets any local WS client hijack the reserved `"wallet_ui"` broadcast channel - (File: `chia/daemon/server.py`)

### Summary
The Apache Airflow FAB bug arose because a user-controlled resource name (`DAGs`) collided with the string produced for the global "all-DAGs" permission, so a narrow per-object grant was silently promoted to a global grant. Chia's local daemon has the same class of bug: the `service` name that any locally-connected websocket client supplies to `register_service` is an arbitrary, unauthenticated string that is used verbatim as a routing key, and it collides with the hardcoded, privileged destination name `"wallet_ui"` that the daemon uses to fan out sensitive state and keyring events. Any client that can open a websocket to the daemon can request registration under the literal string `"wallet_ui"` and thereby receive every broadcast intended for the trusted GUI/wallet-ui consumer.

### Finding Description
`WebSocketServer.register_service()` accepts any caller-supplied `service` string and adds the connecting websocket into `self.connections[service]` with no check that the name is reserved or already has special routing semantics: [1](#0-0) 

The daemon uses the literal string `"wallet_ui"` as a hardcoded, privileged destination for two broadcast paths: `state_changed()` (fans out every registered service's state changes) and `keyring_status_changed()` (fans out keyring/passphrase status transitions): [2](#0-1) 

Delivery of these broadcasts is destination-name based, with no distinction between the "real" wallet UI and any other client that has registered under the same name: [3](#0-2) 

Additionally, `handle_message()` treats any `destination != "daemon"` as pure forwarding to whichever websockets are registered under that destination string, with no ownership/authorization check on the name itself: [4](#0-3) 

This is structurally identical to the CVE: `"wallet_ui"` functions like the FAB provider's global all-DAGs resource name, and `register_service`'s caller-controlled `service` parameter functions like the DAG's `dag_id`. Because there is no separate namespace or authorization check distinguishing "the privileged wallet_ui consumer" from "any client that names itself wallet_ui," an unprivileged local registrant silently inherits the global broadcast privilege. The project's own internal documentation flags this exact behavior as a known fragility hotspot, confirming the collision is real and unmitigated: "registered service names become routing authorities for all local daemon clients." [5](#0-4) 

Test code demonstrates the exact registration pattern that any client can perform to claim the `wallet_ui` name and subsequently receive `keyring_status_changed` events: [6](#0-5) 

### Impact Explanation
A local process that can open a websocket to the daemon (the same reachability level as any other local daemon/RPC client, e.g., a Data Layer client, wallet CLI helper, or third-party integration running under the same TLS trust domain) can register as `"wallet_ui"` and passively receive: every other registered service's `state_changed` payloads (wallet balances/sync state, farmer reward-target/harvester plot updates, full-node state), plus `keyring_status_changed` events describing passphrase/keyring lock state transitions. This is an unauthorized information-disclosure/privilege-escalation primitive on the local daemon authorization boundary — a lower-trust local caller obtains the same broadcast visibility as the trusted GUI, purely by colliding with a hardcoded resource/destination name, mirroring the FAB `resource_name()` collision that let a per-DAG grant become an all-DAGs grant.

### Likelihood Explanation
Exploitation requires only the ability to open a websocket to the local daemon (an in-scope "local RPC caller" per the daemon/RPC trust model) and send a single `register_service` command with `{"service": "wallet_ui"}` — no additional authorization step gates the specific destination-name string, and the collision is trivially reachable and reproducible, as shown directly in the project's own test suite.

### Recommendation
Reserve `"wallet_ui"` (and any other hardcoded broadcast-destination names) from being claimable via `register_service`, or bind the privileged destination to an authenticated/consented identity separate from the arbitrary user-supplied `service` string, so that a colliding name cannot silently inherit the global broadcast privilege — analogous to how the FAB provider fix disambiguates the all-DAGs resource name from any single DAG's `resource_name()`.

### Proof of Concept
1. Start the chia daemon with a valid local client cert (as any local process is expected to do to use the RPC/daemon API).
2. Open a websocket to the daemon and send `register_service` with `data={"service": "wallet_ui"}`, as shown in the test harness pattern: [7](#0-6) 
3. Trigger any keyring/passphrase action (`set_keyring_passphrase`, `unlock_keyring`, etc.) from a separate legitimate client.
4. Observe that the attacker's websocket, having registered under `"wallet_ui"`, receives the `keyring_status_changed` push intended for the trusted wallet UI: [8](#0-7) 
5. Similarly, any other service's `state_changed()` calls will also be delivered to the attacker's connection because `state_changed()` unconditionally targets `destination="wallet_ui"`: [9](#0-8)

    async def _state_changed(self, message: StatusMessage) -> None:
        """If id is None, send the whole state queue"""
        if message.service not in self.connections:
            return None

        websockets = self.connections[message.service]
        for websocket in websockets.copy():
            try:
                await websocket.send_str(message.create_payload())
            except Exception as e:
                tb = traceback.format_exc()
                self.log.error(f"Unexpected exception trying to send to websocket: {e} {tb}")
                websockets.remove(websocket)
                await websocket.close()

    async def register_service(self, websocket: WebSocketResponse, request: dict[str, Any]) -> dict[str, Any]:
        self.log.info(f"Register service {request}")
        service = request.get("service")
        if service is None:
            self.log.error("Service Name missing from request to 'register_service'")
            return {"success": False}
        if service not in self.connections:
            self.connections[service] = set()
        self.connections[service].add(websocket)

        response: dict[str, Any] = {"success": True}
        if service == service_plotter:
            response = {
                "success": True,
                "service": service,
                "queue": self.extract_plot_queue(),
            }
        elif self.ping_job is None:
            self.ping_job = create_referenced_task(self.ping_task())
        self.log.info(f"registered for service {service}")
        log.info(f"{response}")
        return response
