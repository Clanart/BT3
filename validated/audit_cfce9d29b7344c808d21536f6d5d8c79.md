### Title
Missing-participant panic in `GeneratorPromotion::complete` via a proof map containing the caller's own index - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` validates only the length and upper bound of the attacker-influenced `proofs` map, then unconditionally unwraps `proofs.get(&i)` for every participant index `i` in `1 ..= n`. A proof map of the correct size (`n - 1`) whose keys are all `<= n` but which contains the verifier's own index (or any duplicate displacement) omits a required participant and causes an `unwrap()` on `None`, panicking the node — an availability failure analogous to the MySQL hang/crash class of CVE-2017-3317, reachable through the in-scope `complete` API with untrusted, participant-keyed inputs.

### Finding Description
In `crypto/dkg/promote/src/lib.rs:120-156`, `complete` performs two checks on `proofs: &HashMap<Participant, GeneratorProof<C1>>`:

1. `proofs.len() == n - 1` (line 125)
2. every key `i` satisfies `u16::from(i) <= params.n()` (line 133)

Neither check ensures the map contains every index `1 ..= n` except `params.i()`. Because `Participant` admits any nonzero `u16`, a map can satisfy both checks while omitting some `j != params.i()` — the simplest construction includes the caller's own index `params.i()` as a key, filling one of the `n - 1` slots, so some other required index `j` is absent. The loop at lines 140-146 then does `proofs.get(&i).unwrap()` for every `i != params.i()` in `1 ..= n`, and `proofs.get(&j)` returns `None`, producing a panic.

Relevant code (crypto/dkg/promote/src/lib.rs):

```rust
for i in proofs.keys().copied() {
  if u16::from(i) > params.n() {
    Err(PromotionError::InvalidParticipant { n: params.n(), participant: i })?;
  }
}
// ... no check that proofs covers all of 1..=n except params.i()
let proof = proofs.get(&i).unwrap(); // line 146: panics on missing participant
```

The contrast with sibling code confirms the gap: `pedpop`'s `validate_map` explicitly rejects maps containing `ours` and enforces presence of every other included participant (crypto/dkg/pedpop/src/lib.rs:57-83), and frost's `validate_map` does the same (crypto/frost/src/lib.rs:50-73). `promote::complete` skips the `MissingParticipant`/own-index validation entirely.

### Impact Explanation
A single malformed `proofs` map deterministically panics the thread running `complete`. In an async executor this can abort the whole task/node performing generator promotion (key rotation), which must complete for the validator set to migrate keys — a repeatable, remotely triggerable crash/stall of the promotion flow, matching the CVE's availability-only impact profile (complete DoS of the affected component with no confidentiality/integrity loss).

### Likelihood Explanation
Triggering requires the caller to build `proofs` from untrusted per-participant submissions keyed by claimed `Participant` index — the natural integration pattern (each peer submits a `GeneratorProof` tagged with its index). Any peer that submits its proof under the victim's index, or the victim's own proof being included in the map, collapses the `n - 1` sized map to omit a required participant. The check that would catch this (`proofs.get(&i).ok_or(MissingParticipant)`) is simply absent. Likelihood is moderate: it requires a key-rotation ceremony and an index-collision in the proofs map, but no special privilege beyond participating in the protocol's message flow.

### Recommendation
Replace the unconditional unwrap with presence validation, mirroring `validate_map` in pedpop: reject if `proofs` contains `params.i()` or if any `i` in `1 ..= params.n()` with `i != params.i()` is missing, returning a `MissingParticipant`-style error instead of panicking. A minimal fix is `let proof = proofs.get(&i).ok_or(PromotionError::MissingParticipant(i))?;` plus an explicit rejection of a proof keyed as `params.i()`.

Uncertain: whether a deployed integrator actually keys `proofs` from unauthenticated peer claims rather than session-bound indices; the panic itself is unconditional once the map omits a required index.
