## Analysis Result

### Title
Missing sender/module-identity binding in `HostManager.onAccept` allows unauthorized cross-chain withdrawal and host-param hijack - (File: `evm/src/core/HostManager.sol`)

### Summary
The external report's core pattern is "a state-changing entry point is missing a check that should gate/attest its effect" (there, a missing event for traceability; here, a missing authorization check for a privileged cross-chain action). The Hyperbridge analog is in `HostManager.onAccept`, the single entry point that lets Hyperbridge-side messages trigger fund withdrawal and host-parameter overwrite on every EVM host.

### Finding Description
`HostManager.onAccept` is `restrict`ed to `msg.sender == _params.host` (only the local `EvmHost` can call it), and inside it validates only the **chain-level** origin of the incoming ISMP request: [1](#0-0) 

```solidity
function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
    PostRequest calldata request = incoming.request;
    // Only the Hyperbridge parachain can send requests to this module.
    if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

    OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
    if (action == OnAcceptActions.Withdraw) {
        WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
        IHostManager(_params.host).withdraw(withdrawParams);
    } else if (action == OnAcceptActions.SetHostParam) {
        HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
        IHostManager(_params.host).updateHostParams(hostParams);
    }
}
```

Note what is checked and what is *not*: `request.source` (the source **chain id**, i.e. "is this the Hyperbridge parachain") is verified, but `request.from` (the **module/pallet identity** on that chain that actually dispatched the message) is never checked. Compare this with `BandwidthManager`'s equivalent governance path, which similarly only checks `_host` binding and not per-message module identity [2](#0-1) . This is exactly the invariant the task's pivots call out: *"Request, response, and timeout paths must bind chain id, module/app identity, commitment uniqueness..."* — here only chain id is bound.

Once `onAccept` accepts the message body as legitimate, it is decoded directly into `WithdrawParams{beneficiary, amount, token}` and forwarded to `EvmHost.withdraw`, which is `restrict`ed only to `_hostParams.hostManager` (i.e., it trusts anything `HostManager` hands it) and unconditionally transfers funds: [3](#0-2) 

Similarly, `SetHostParam` flows into `updateHostParamsInternal`, which can rewrite `feeToken`, `admin`, `handler`, `consensusClient`, and the whitelisted `stateMachines` for the entire host [4](#0-3) .

### Impact Explanation
If any entity able to dispatch an ISMP POST request from the Hyperbridge parachain to `HostManager`'s registered module id (not necessarily the intended governance/host-executive pallet) can craft `body` bytes, it can:
- Drain the host's accumulated bridge revenue to an arbitrary `beneficiary` via `Withdraw` (direct loss of funds), or
- Overwrite `HostParams` (`admin`, `handler`, `consensusClient`, `feeToken`) via `SetHostParam`, hijacking the entire EVM host's trust model and downstream proof verification / fee accounting.

This maps directly onto the bounty's "stealing or loss of funds" and "cross-chain admin or host-management effects... reachable through... unauthenticated message flow" categories.

### Likelihood Explanation
Exploitability hinges entirely on whether the Hyperbridge parachain enforces that only a specific privileged pallet (e.g. `host-executive`) can dispatch messages with `to = HOST_MANAGER_MODULE_ID`, or whether any pallet/extrinsic that can set an arbitrary destination module id could reach this path. I was not able to fully trace the Substrate-side dispatch authorization for this module id within the available investigation to confirm an unprivileged trigger exists, so likelihood is uncertain pending that verification — but the EVM-side control itself is verifiably incomplete: `onAccept` has no code-level guard on `request.from`, meaning the safety of this function currently rests entirely on an assumption enforced elsewhere (or not enforced at all), rather than on an explicit, auditable check in the contract that is supposed to gate privileged cross-chain governance actions.

### Recommendation
Add an explicit check in `HostManager.onAccept` binding `request.from` to a known/expected governance module id (mirroring how peer/module allow-lists are enforced elsewhere, e.g. `HyperFungibleToken`'s registered-peer check [5](#0-4) ), rather than relying solely on chain-id equality.

### Proof of Concept
Conceptual, given code evidence:
1. Some sender on the Hyperbridge parachain dispatches an ISMP POST request with `dest = <this chain>`, `to = HOST_MANAGER_MODULE_ID`, `body = [OnAcceptActions.Withdraw, abi.encode(WithdrawParams{beneficiary: attacker, amount: hostBalance, token: feeToken})]`.
2. The relayer delivers it; `EvmHost` verifies the state/consensus proof (valid, since the message really was posted on the Hyperbridge chain) and calls `HostManager.onAccept`.
3. `onAccept` only checks `request.source == hyperbridge chain id` — true — and does not check which module/pallet on that chain actually sent it.
4. `IHostManager(_params.host).withdraw(withdrawParams)` executes, transferring the host's fee-token/native balance to `attacker`.

Confirming step 1's feasibility (i.e., whether an unprivileged/non-governance pallet can set `to = HOST_MANAGER_MODULE_ID`) requires further verification on the Substrate/pallet side that I could not complete in this pass.

    /**
     * @dev Updates the HostParams. Will reset all fishermen accounts and initialize any new state machines.
     * @param params, the new host params.
     */
    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;

        // add whitelisted state machines
        for (uint256 i = 0; i < stateMachinesLen; ++i) {
            // create if it doesn't already exist
            if (_latestStateMachineHeight[params.stateMachines[i]] == 0) {
                _latestStateMachineHeight[params.stateMachines[i]] = 1;
            }
        }
    }

     * @dev withdraws host revenue to the given address, can only be called by cross-chain governance
     * @param params, the parameters for withdrawal

    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }
