### Title
Ed448 point decoding never rejects torsion components, enabling related-key signature forgery - (File: crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` is a tautology: it evaluates `(-1)P + P`, which is the identity for every point. Consequently, `Point::from_bytes` accepts Ed448 encodings containing a non-trivial cofactor component even though the type is declared as a `PrimeGroup`. `Ciphersuite::read_G` and downstream signature/proof APIs therefore operate on points outside the intended prime-order subgroup.

### Finding Description
The intended torsion check is:

```rust
((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
```

`Scalar::ZERO - Scalar::ONE` is `-1`, so the expression is always `P - P = identity`. The check can never fail. `GroupEncoding::from_bytes` gates acceptance on this always-true result, and `Ciphersuite::read_G` only checks decoding and canonical re-encoding.

The accepted point can be represented as `A + T`, where `A` is in the prime-order subgroup and `T` is a non-identity Ed448 torsion point. Schnorr verification checks the equation `R + c(A + T) - sG = 0`. An attacker can search over the four possible torsion residues of `R` until the challenge satisfies `c ≡ j (mod 4)`, constructing a valid signature for a crafted related public key `A + T` without knowing a discrete logarithm for it.

### Impact Explanation
An unauthenticated party can submit non-prime-order Ed448 points through `read_G`, `SchnorrSignature::read`, or other public deserialization paths and obtain acceptance of signatures/proofs for crafted keys that do not have a normal discrete logarithm relative to the generator. This breaks the `PrimeGroup` invariant relied on by Schnorr, DLEq, FROST, and DKG consumers.

### Likelihood Explanation
The malicious input is only attacker-controlled encoded bytes. The related-key search has only four cases and can be repeated with different `s` values until a challenge has the needed value modulo 4.

### Recommendation
Replace the tautological check with multiplication by the prime subgroup order, for example:

```rust
(*self * Scalar::ORDER).is_identity()
```

or the crate’s equivalent scalar constant for the prime-order subgroup. Also reject the identity in APIs that require non-identity group elements, and add negative tests for every low-order Ed448 point and for prime-order points shifted by each torsion point.
