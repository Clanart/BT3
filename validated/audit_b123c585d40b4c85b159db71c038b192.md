### Title
Unbounded length-prefix read in CLVM canonical-encoding check causes uncaught `IndexError` on spend-bundle admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`MempoolManager.validate_spend_bundle()` runs `is_clvm_canonical()` on the raw, attacker-controlled `puzzle_reveal` and `solution` bytes of every coin spend in a submitted `SpendBundle`, before any other structural validation. `is_clvm_canonical()` delegates atom-length decoding to `is_atom_canonical()`, which reads a multi-byte length prefix from the buffer without ever checking that the buffer actually contains that many bytes. A short/truncated atom header triggers an out-of-bounds `bytes` index, raising an unhandled `IndexError` deep in the mempool admission path. This mirrors the CVE-2017-10971 bug class: a length/size field taken from untrusted, variable-length input is used to walk further into a buffer without a bounds check before the reads happen.

### Finding Description
`is_atom_canonical()` decodes CLVM atom length prefixes with 0–5 continuation bytes based on the leading byte's high bits: [1](#0-0) 

The decode loop (lines 177–181) increments `offset` and indexes `clvm_buffer[offset]` for `prefix_len` iterations with **no check that `offset < len(clvm_buffer)`**:
```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
If the buffer ends before all prefix bytes are present (e.g., the buffer is just `b"\xfc"`, which selects the 5-continuation-byte encoding but supplies none of them), `clvm_buffer[offset]` raises `IndexError` for a `bytes` object.

This function is invoked directly on attacker-controlled data during mempool admission, for every coin spend in a submitted spend bundle, prior to any cost/signature validation: [2](#0-1) 

`is_clvm_canonical()` itself also indexes `clvm_buffer[offset]` in its main loop (line 199) without checking `offset < len(clvm_buffer)` after advancing past atoms/pairs, compounding the same bug class: [3](#0-2) 

This is inconsistent with the rest of the untrusted-buffer parsing code in the same codebase, which explicitly bounds-checks length prefixes before reading (e.g. `skip_bytes`/`skip_list` in `full_block_utils.py` raise `ValueError` when a declared length exceeds the remaining buffer): [4](#0-3) 

That defensive pattern is absent from `is_atom_canonical`/`is_clvm_canonical`.

### Impact Explanation
An unprivileged spend-bundle submitter (any wallet client, RPC caller, or peer relaying a transaction) can craft a `CoinSpend` with a truncated non-canonical atom length prefix in `puzzle_reveal` or `solution`. This raises an uncaught `IndexError` inside `MempoolManager.validate_spend_bundle()`, the core transaction-admission routine that runs for every incoming spend bundle. Because the exception is not one of the `Err` codes the function is designed to return, it propagates instead of producing a clean `INVALID_COIN_SOLUTION` rejection, disrupting the mempool admission pipeline for that transaction path. This matches the accepted "spend-triggered transaction-processing halt" impact category — a single crafted, unsigned-cost spend bundle can interrupt normal spend-bundle processing logic without any special node privilege.

### Likelihood Explanation
High likelihood of triggering: the malformed input requires only 1–6 attacker-chosen bytes (a truncated atom header) placed in `puzzle_reveal` or `solution` of any coin spend, and `is_clvm_canonical()` is called unconditionally and early in `validate_spend_bundle()` for every coin spend in every submitted bundle — no signature validity, coin existence, or prior CLVM execution is required to reach it. `solution`/`puzzle_reveal` bytes are entirely attacker-controlled and are not otherwise length-validated before being handed to this function.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` read (raise a caught `ValueError`/return "not canonical" instead of indexing past the buffer), mirroring the pattern already used in `full_block_utils.py`'s `skip_bytes`/`skip_list`. Also bounds-check `offset` in the main loop of `is_clvm_canonical()` before dereferencing `clvm_buffer[offset]`. Ensure `validate_spend_bundle()` (or its caller) converts any residual parsing exception on attacker-supplied puzzle/solution bytes into `Err.INVALID_COIN_SOLUTION` rather than letting it propagate.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# Leading byte 0xFC selects a 5-continuation-byte length prefix
# (mask 0b00000001, prefix_len=5), but the buffer supplies none of
# the required continuation bytes.
truncated_atom = bytes([0xFC])

is_clvm_canonical(truncated_atom)  # raises uncaught IndexError
```
Embedding `truncated_atom` as the `solution` (or `puzzle_reveal`) of a `CoinSpend` inside a `SpendBundle` and submitting it via `push_tx`/mempool admission reaches `MempoolManager.validate_spend_bundle()` line 723-725, which calls `is_clvm_canonical(bytes(coin_spend.solution))` directly on this crafted buffer, raising the same uncaught `IndexError`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
