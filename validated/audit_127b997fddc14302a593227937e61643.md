### Title
Gasless swap deadline validated against stale block timestamp at tx-pool admission, allowing lend funds to be irrecoverably disbursed for a swap that later expires - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The reported bug class is a timestamp-boundary mismatch between two independently-timed checks (deposit-window check vs. null-epoch trigger) that share an inclusive/exclusive inconsistency at `block.timestamp == epochBegin`, letting funds get locked with no recovery path. The closest reachable analog in Kaia is in the gasless-transaction (KIP-247) admission path: `checkBalanceForSwap` validates `swapArgs.Deadline` against `g.Chain.CurrentBlock().Time()` — the timestamp of the **current head block** — at the moment the transaction is accepted into the pool, not against the timestamp of the block in which it will actually be executed.

### Finding Description
`GetCheckBalance()` wraps `checkBalanceForSwap`, which performs the deadline check as: [1](#0-0) 

This check runs once, at tx-pool admission time, using `g.Chain.CurrentBlock().Time()` — the timestamp of the last sealed block — as a proxy for "now". Kaia block times are not fixed to real time deterministically for tx-pool purposes; the actual block that eventually includes the swap can be produced an arbitrary (attacker-influenceable, e.g. via low fees, congestion, or `IsReady`/promotion gating) number of blocks later. The module's own README documents that promotion into `ready` is gated by nonce sequencing, not by re-checking the deadline at promotion/build time: [2](#0-1) 

Separately, the bundling code irreversibly prepends a `LendTxGenerator` transaction that pays the sender KAIA out of the proposer's balance **before** the `ApproveTx`/`SwapTx` are executed in the same bundle: [3](#0-2) [4](#0-3) 

Because the deadline check only happens once at admission (comparing against the stale head-block time) and is never re-validated against the actual timestamp of the block being built, a swap transaction can sit in the pool past its intended deadline and still be selected for bundling/execution in a later block whose real `block.timestamp` has moved past `deadline`. If the on-chain `GaslessSwapRouter.swapForGas` (bindings only available; source not indexed) reverts on an expired deadline, the swap tx fails inside the atomic bundle, but the preceding `LendTxGenerator` tx that transferred KAIA to the sender is a *separate*, already-signed and already-included transaction in the bundle — its success is not conditioned on the swap tx succeeding (nothing in `ExtractTxBundles` marks lend+swap as revert-atomic at the EVM level; they are distinct transactions in the block, only "bundled" for ordering/inclusion purposes). This mirrors the reported bug's core defect: a single control (a timestamp boundary check performed once, against the wrong reference clock) is trusted by a downstream irreversible fund-transfer action, and the two are not re-validated against each other at the moment that matters.

### Impact Explanation
If the lend transaction's success is not strictly coupled to the swap transaction succeeding, an attacker (or an unlucky ordinary gasless user under load) could have KAIA lent to them by the proposer for a swap that fails at execution time because its deadline lapsed between admission and inclusion, since the pool-level check compared against a stale head-block timestamp rather than the future block's timestamp. This is a proposer-fund-loss / gasless-settlement-integrity issue (unauthorized value movement from the proposer to the gasless sender without repayment), matching the "gasless or auction settlement theft" category. The severity is High if the lend disbursement is not reversible/refundable in the same execution, since the proposer's KAIA would be spent while `amountRepay` (in tokens) required by `swapForGas` is never actually collected.

### Likelihood Explanation
This requires only a naturally-occurring race: a `SwapForGas` transaction submitted close to its `deadline`, combined with normal block-production delay or backlog in the pending pool (governed by `PendingTimeout`/`QueueTimeout` in `PreReset`, which are much longer than typical block intervals). No malicious peer, validator, or node compromise is needed — a single unprivileged transaction sender submitting a swap with a deadline near the current time is sufficient to trigger the race, satisfying the "reachable by unprivileged transaction sender" constraint. However, without visibility into the `GaslessSwapRouter.sol` source (only bindings are indexed) it cannot be confirmed with certainty whether the contract-level `swapForGas` execution also reverts the corresponding lend value transfer atomically at the EVM transaction level, which would neutralize this specific loss scenario. This uncertainty should be explicitly flagged.

### Recommendation
- Re-validate the gasless swap `deadline` against the timestamp of the block actually being assembled (not `CurrentBlock().Time()`) immediately before including the transaction in a bundle, inside `ExtractTxBundles` / `IsReady`, in addition to the pool-admission check in `checkBalanceForSwap`.
- Confirm and, if necessary, enforce that the `LendTxGenerator` transaction and the `SwapTx` are executed with equivalent all-or-nothing semantics (e.g., by having `swapForGas` itself perform the disbursement/repayment atomically rather than relying on a separately signed, independently-mined lend transaction).
- Drop or refuse to bundle any gasless swap whose `deadline` has already elapsed relative to the next block's expected timestamp, mirroring the underlying report's fix of tightening a boundary check (`>` vs `>=`) so that admission-time and execution-time timestamp references cannot diverge.

### Proof of Concept
1. An unprivileged user submits `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` with `deadline = currentHeadBlock.Time() + N` where `N` is small.
2. The tx passes `checkBalanceForSwap`'s deadline check (`deadline.Cmp(CurrentBlock().Time()) < 0` is false) and is admitted to the pool: [1](#0-0) .
3. Due to normal network/mempool delay (or the sender deliberately delaying propagation/using low gas price), the transaction is not selected for bundling until several blocks later, whose real timestamp now exceeds `deadline`.
4. `ExtractTxBundles` still builds the bundle `[LendTxGenerator, ApproveTx, SwapTx]` because it only checks `IsExecutable`/`VerifyExecutable`, which does not re-check the deadline against the new block's timestamp: [3](#0-2) [5](#0-4) .
5. The `LendTxGenerator` transaction sends KAIA to the sender; if `swapForGas` subsequently reverts due to the expired deadline while the lend transaction still succeeds independently, the proposer's KAIA is disbursed without the expected token repayment.

Note: Step 5's exact outcome depends on the unindexed `GaslessSwapRouter.sol` contract logic, which could not be retrieved from the codebase index; a Devin session with full repository access would be needed to confirm whether the lend and swap effects are coupled atomically at the EVM level.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
