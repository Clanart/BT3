Deterministic `CachedPreprocess` seeds allow nonce reuse across signing attempts, enabling key-share recovery via a ROS-style attack — (File: crypto/frost/src/sign.rs)

### Summary
Like the auction's refund callback that let one transaction perform N mints under a per-caller cap, Serai's FROST `SignMachine::from_cache` lets a single cached preprocess seed be consumed an unbounded number of times: every call deterministically regenerates the *same* nonces from the same 32-byte seed (`ChaCha20Rng::from_seed`) and emits the *same* preprocess message, with no consumed/invalidated marker. Any driver that signs more than once from one cache entry — which the in-scope API does not prevent and the surrounding Serai code does by design (`coordinator/src/tributary/signing_protocol.rs` re-pulls `CachedPreprocesses::get(txn, &context)` and calls `preprocess_internal`/`share_internal` per attempt) — produces multiple signature shares over the same nonce. An unprivileged co-signer who can force a retry/abort (e.g., by feeding malformed bytes to `read_preprocess`, which surfaces as `InvalidPreprocess`) obtains two shares with the same nonce under different binding factors/challenges and recovers the victim's secret key share — the exact "third-party recovery of your private key share" the comments warn of.

### Finding Description
`AlgorithmMachine::seeded_preprocess` (crypto/frost/src/sign.rs:121-144) derives all nonces, the addendum, and `blame_entropy` deterministically:

```rust
let mut rng = ChaCha20Rng::from_seed(*seed.0);
let (nonces, commitments) = Commitments::new::<_>(&mut rng, ..., &params.algorithm.nonces());
```

`SignMachine::from_cache` (sign.rs:268-274) rebuilds a full signing machine from `CachedPreprocess` with no flag recording that the seed was already used, and `cache()` (sign.rs:264-266) hands the seed back out. `sign()` consumes `self` per call but nothing binds a seed to a single use; two `from_cache(cache.clone())` calls produce byte-identical preprocesses and identical `self.nonces`. In `sign` (sign.rs:383-398) the effective nonce is `base + ρ·actual` where `ρ` is the per-participant binding factor; two sessions with different signer sets/messages give different `ρ` and different challenge `e`, so `s₁ = d₁ + ρ₁·e₁...` style shares leak the nonce scalar and hence `original_secret_share`. The coordinator's `preprocess_internal` (signing_protocol.rs:123-147) caches the seed under `context` and re-decrypts/reuses it on every `share_internal` call for that context, emitting an identical preprocess each time — meaning an abort-and-retry within one context (triggered by a malicious participant's preprocess bytes, i.e. untrusted input to `read_preprocess` at sign.rs:276-281) reuses the nonce deterministically.

### Impact Explanation
Critical: recovery of a threshold secret key share. With `t` shares recovered (or combined with a malicious participant's own share(s) in a small `t` set, e.g. `t=2`), the group key is compromised and arbitrary signatures/bitcoin spends can be forged.

### Likelihood Explanation
Medium-High. The trigger requires only that the node sign twice from one cached seed — an abort path already reachable by any co-signer sending malformed/invalid preprocess bytes (`FrostError::InvalidPreprocess` → blame → new attempt). No privileged access, collusion of the full threshold, or leaked keys are required; the attacker only needs to be a signing participant supplying public preprocess messages.

### Recommendation
Enforce single-use inside the primitive: (a) mark `CachedPreprocess` consumed at `sign()` time and expose no path to re-derive a preprocess from a previously used seed — e.g., take `cache: &mut Option<CachedPreprocess>` or persist a spent bit alongside the ciphertext so `preprocess_internal` rotates the seed after each attempt; (b) never emit two identical preprocess messages — bind the produced preprocess to a monotonically increasing attempt counter in the seed derivation (`seed || attempt`) so retries inherently produce fresh nonces; (c) fail closed: if `sign` is invoked with a preprocess that does not match the one produced alongside the cached seed for *this* attempt, abort rather than reuse.

### Proof of Concept
Conceptual test against `crypto/frost`:

```rust
// Same keys, same cached seed
let cache = sign_machine.cache();            // CachedPreprocess(seed)
let (m1, pp1) = AlgorithmSignMachine::from_cache(algo.clone(), keys.clone(), CachedPreprocess(Zeroizing::new(*cache.0)));
let (m2, pp2) = AlgorithmSignMachine::from_cache(algo.clone(), keys.clone(), CachedPreprocess(Zeroizing::new(*cache.0)));
assert_eq!(pp1, pp2);                        // identical nonce commitments

// Session 1: sign with participant set {attacker1, victim}, message m
let (_, s1) = m1.sign(preps_set_1, msg1).unwrap();
// Session 2 (retry/abort): same seed, different participant set or message
let (_, s2) = m2.sign(preps_set_2, msg2).unwrap();

// s_i = d_i + rho_i * e_i + lam * share * c_i  with the SAME (d_i, e_i);
// two equations, two unknowns -> solve for `share` (and lam-adjusted share),
// recovering the victim's secret key share.
```

Key supporting code: deterministic derivation at `crypto/frost/src/sign.rs:127` (`ChaCha20Rng::from_seed(*seed.0)`); unguarded reuse at `sign.rs:220-224`/`268-274`; nonce combination `base + rho * actual` at `sign.rs:386-396`; reuse-by-context in `coordinator/src/tributary/signing_protocol.rs:123-147` (evidence of reachability only; the root cause is in-scope).
