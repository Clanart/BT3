## Analysis

`expandTargetPathArgument` in `app/src/lib/custom-integration.ts` performs an unconditional string substitution of `%TARGET_PATH%` with the raw `repoPath`/`fullPath` value, with no check for a leading `-`/`--` and no attempt to neutralize it as an option token (e.g. by inserting a `--` end-of-options marker or refusing dash-prefixed paths): [1](#0-0) 

This function is called from `launchCustomExternalEditor`, which spawns the user-configured custom-editor binary directly via `spawn(customEditor.path, args, opts)` (no shell involved on the non-macOS-app path): [2](#0-1) 

The `fullPath` fed into this call originates from repository/file path data that is under attacker influence when a malicious repository is cloned (a committed file whose name begins with `-`, or, in principle, a repository path). `app/src/ui/history/selected-commits.tsx` builds such paths with `Path.join(...)` before invoking the "Open with editor" flow; I confirmed the two `Path.join` call sites exist there, but ran out of tool budget to display the exact lines confirming the precise `Path.join(repository.path, file.path)` composition asserted in the question — this specific line should be double-checked in a follow-up session.

The dialog in `app/src/ui/open-with-external-editor/open-with-external-editor.tsx` is where the user opts into a custom editor and where the default `%TARGET_PATH%` placeholder argument is set: [3](#0-2) 

### Title
Argument injection via unsanitized dash-prefixed file paths substituted into custom-editor arguments - (`app/src/lib/custom-integration.ts`)

### Summary
`expandTargetPathArgument` substitutes the target path into the custom editor's argv without checking whether the resulting token begins with `-`/`--`. If a malicious repository contains a file whose path begins with a dash, opening that file with a configured custom external editor produces an argv element that the launched binary's own CLI parser will interpret as an option/flag rather than a positional path.

### Finding Description
`launchCustomExternalEditor` builds `args` by calling `expandTargetPathArgument(argv, fullPath)`, which does a literal `replaceAll` of the placeholder with `fullPath` [4](#0-3) . No validation rejects or escapes a `fullPath` that starts with `-`. The resulting array is passed straight to Node's `spawn` (no shell) [5](#0-4) , so the vulnerability is argument-parsing corruption in the launched process rather than shell injection. Whether this is exploitable to something worse than argument corruption depends entirely on the CLI semantics of whatever binary the user configured as their custom editor (e.g., editors that support `-`/`+`-prefixed positional arguments as commands, or flags with side effects).

### Impact Explanation
Impact is bounded by the specific custom-editor binary's flag semantics; in the worst case (an editor whose flags allow command execution or arbitrary file access when passed as the "path" argument) this could escalate to code execution, but in general it corrupts the intended "open this exact path" behavior with attacker-chosen flag semantics.

### Likelihood Explanation
Requires the user to have explicitly configured a custom external editor (an opt-in, feature-flagged capability, `enableCustomIntegration()`) [6](#0-5)  and to then choose "Open with editor" on an attacker-crafted file/path from a cloned malicious repository. This is a plausible, natural user action, but it is gated behind an optional feature not everyone uses.

### Recommendation
In `expandTargetPathArgument`, reject or normalize target paths that begin with `-` (e.g. prefix with `./` for relative paths, or insert a `--` end-of-options separator before the substituted argument) before substituting into the argv array.

### Proof of Concept
Not independently re-verified end-to-end in this session (tool budget exhausted before confirming the exact `selected-commits.tsx` join site), but the mechanics: commit a file named `--something` (or `-x`) in a repository, configure a custom external editor with `%TARGET_PATH%` in its arguments, and use "Open in <custom editor>" on that file — the substituted argv element will begin with `-`/`--` and be parsed as an option by the target editor binary. This should be validated with a focused unit/integration test against `expandTargetPathArgument`/`launchCustomExternalEditor` and the exact call path from `selected-commits.tsx`.

```typescript
export function expandTargetPathArgument(
  args: ReadonlyArray<string>,
  repoPath: string
): ReadonlyArray<string> {
  // Only strip quotes when the entire argument is the quoted placeholder.
  // Otherwise preserve any user-provided quoting and replace the placeholder
  // in place.
  return args.map(arg => {
    if (
      arg === `'${TargetPathArgument}'` ||
      arg === `"${TargetPathArgument}"`
    ) {
      return repoPath
    }

    return arg.replaceAll(TargetPathArgument, repoPath)
  })
}
```

```typescript
export const launchCustomExternalEditor = (
  fullPath: string,
  customEditor: ICustomIntegration
) => {
  const argv = parseCustomIntegrationArguments(customEditor.arguments)

  // Replace instances of RepoPathArgument with fullPath in customEditor.arguments
  const args = expandTargetPathArgument(argv, fullPath)

  // In macOS we can use `open` if it's an app (i.e. if we have a bundleID),
  // which will open the right executable file for us, we only need the path
  // to the editor .app folder.
  const spawnAsDarwinApp = __DARWIN__ && customEditor.bundleID !== undefined
  const editorName = `custom editor at path '${customEditor.path}'`

  return launchEditor(customEditor.path, args, editorName, spawnAsDarwinApp)
}
```
