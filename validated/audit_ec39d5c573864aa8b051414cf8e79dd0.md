The main reachable call site for `match_puzzle` on untrusted data is `Offer.from_spend_bundle()`, which is invoked by wallet code (e.g. `TradeManager`) whenever a wallet parses an offer file or an incoming spend bundle from a counterparty [1](#0-0) .

### Title
Unbounded recursive puzzle-layer matching in wallet offer/driver parsing causes stack-overflow DoS - (File: chia/wallet/outer_puzzles.py)

### Summary
The Jettison advisory describes unbounded recursive parsing of untrusted structured input leading to a stack overflow / DoS. Chia's wallet-side "outer puzzle driver" system has an analogous unbounded-recursion pattern: `match_puzzle()` and each outer-puzzle driver's `match`/`get_inner_puzzle`/`construct`/`solve` methods recurse once per curried puzzle layer found in an attacker-controlled `puzzle_reveal`, with no depth limit.

### Finding Description
`match_puzzle()` dispatches a puzzle to the first matching driver (CAT, singleton, metadata, ownership, CR, etc.) and stores nested layer info under `PuzzleInfo["also"]` [2](#0-1) . Each driver's `match()` recurses into its inner puzzle via `self._match(...)`, which is `match_puzzle` again, e.g. `CATOuterPuzzle.match()` [3](#0-2) , `SingletonOuterPuzzle.match()` [4](#0-3) , `MetadataOuterPuzzle.match()` [5](#0-4) , `OwnershipOuterPuzzle.match()` [6](#0-5) , and `CROuterPuzzle.match()` [7](#0-6) . `PuzzleInfo.also()`/`check_type()` similarly recurse over the same attacker-controlled nesting depth [8](#0-7) .

Because CLVM currying lets a puzzle reveal wrap the same known mod (e.g. `CAT_MOD`, singleton mod, ownership/metadata layer) thousands of times cheaply, an attacker can craft a `CoinSpend`/offer whose `puzzle_reveal` has thousands of nested layers of a recognized outer puzzle. `Offer.from_spend_bundle()` calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` on every coin spend in an untrusted bundle [1](#0-0) , and `Offer.get_offered_coins()`/`to_valid_spend()` further call `get_inner_puzzle`/`get_inner_solution`/`construct_puzzle`, which recurse the same way [9](#0-8) . There is no recursion-depth guard anywhere in this chain, unlike `sha256_treehash`, which the codebase deliberately made iterative specifically to avoid "blowing out the python stack" on deeply nested CLVM [10](#0-9) . This shows the project is aware of the exact bug class but the outer-puzzle-driver code path does not apply the same mitigation.

### Impact Explanation
Parsing an attacker-supplied offer file or received spend bundle whose puzzle reveal has enough nested recognized layers will exhaust the Python call stack and raise an uncaught `RecursionError` deep inside `TradeManager`/`Offer` processing. This can crash or hang the wallet's async task handling offers/spend bundles, i.e. a spend-triggered transaction-processing halt for the wallet reachable by a normal offer counterparty or by receiving a maliciously constructed spend bundle to inspect/complete — no privileged access required.

### Likelihood Explanation
Constructing deeply curried, cheap CAT/singleton/ownership layers is inexpensive with CLVM currying, and an unprivileged offer counterparty fully controls the `puzzle_reveal` of the coins offered in an `Offer`. Any wallet user who opens/inspects/accepts such an offer (a normal wallet workflow) triggers the vulnerable recursive matching code.

### Recommendation
Bound the recursion depth in `match_puzzle`/`PuzzleInfo.also()`/`check_type()` and in each outer-puzzle driver's `match`, `get_inner_puzzle`, `construct`, and `solve` methods (e.g., convert to an iterative loop over layers, similar to `sha256_treehash`'s iterative design, or enforce a maximum nesting count and reject/park with a normal error instead of recursing unboundedly). Apply the fix uniformly across `chia/wallet/outer_puzzles.py`, `chia/wallet/puzzle_drivers.py`, and all files implementing `DriverProtocol` (`cat_outer_puzzle.py`, `singleton_outer_puzzle.py`, `metadata_outer_puzzle.py`, `ownership_outer_puzzle.py`, `cr_outer_puzzle.py`, `transfer_program_puzzle.py`).

### Proof of Concept
1. Build an inner puzzle `ACS = (q . 1)`.
2. Repeatedly wrap it N times (N large enough to exceed Python's default recursion limit, e.g. thousands) using `construct_cat_puzzle(CAT_MOD, tail, inner)` in a loop, as demonstrated for two layers in the existing test `test_cat_outer_puzzle` [11](#0-10) , but extended to thousands of layers instead of two.
3. Put this deeply nested puzzle as the `puzzle_reveal` of a `CoinSpend` inside an `Offer`/`SpendBundle` sent to a victim wallet.
4. When the victim wallet calls `Offer.from_spend_bundle()` (or `TradeManager` calls `match_puzzle`) on the received bundle, the recursive `match()`/`also()` chain overflows the Python stack, raising `RecursionError` and halting offer/transaction processing in that wallet task.

Note: I could not confirm from the indexed code whether full-node/mempool code paths (as opposed to wallet-only code) invoke `match_puzzle` on arbitrary untrusted spend bundles during normal sync; my searches only surfaced wallet-side call sites (`Offer`, `TradeManager`, `NFTWallet`). If a full node/consensus-level call path exists, it would raise the severity further; this could not be fully verified given index coverage limits, and confirming it may require a Devin session with full repository access.

def test_cat_outer_puzzle() -> None:
    ACS = Program.to(1)
    tail = bytes32.zeros
    cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, ACS)
    double_cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)
    uncurried_cat_puzzle = UnknownPuzzle(known_program=double_cat_puzzle)
    cat_driver: PuzzleInfo | None = match_puzzle(uncurried_cat_puzzle)

    assert cat_driver is not None
    assert cat_driver.type() == "CAT"
    assert cat_driver["tail"] == tail
    inside_cat_driver: PuzzleInfo | None = cat_driver.also()
    assert inside_cat_driver is not None
    assert inside_cat_driver.type() == "CAT"
    assert inside_cat_driver["tail"] == tail
    assert construct_puzzle(cat_driver, ACS) == double_cat_puzzle
    assert get_inner_puzzle(cat_driver, uncurried_cat_puzzle) == ACS
