### Title
Aggregate Schnorr verifier accepts duplicated signers, letting one signature count as many — (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` never checks that the claimed signer list contains distinct public keys. Because the aggregate's scalar `s` is supplied by the prover and the per-entry weights `z_i` are deterministically derived from public data, an attacker can take a single valid Schnorr signature `(R, s_sig)` from key `K` and construct an aggregate that verifies as if `k` copies of `K` all signed — the direct analog of one pool manager casting arbitrarily many votes to force an outcome. [1](#0-0) 

### Finding Description
The reported bug class is a missing "already voted" check: an action that should count once per participant can be replayed to accumulate unlimited weight. In Serai, `SchnorrAggregate::verify` proves "every key in `keys_and_challenges` produced a signature", but it enforces only `self.Rs.len() == keys_and_challenges.len()` — there is no deduplication of keys (or of the `Rs` themselves). [2](#0-1) 

The verification equation is a multiexponentiation `Σ z_i·R_i + Σ z_i·c_i·K_i − s·G = 0`, where each `z_i = weight(digest)` is computed from a transcript over the challenges, and `s` is read directly from attacker-controlled bytes in `SchnorrAggregate::read`. [3](#0-2) [4](#0-3) 

Since `z_i` values are fully public and reproducible, an attacker holding one valid signature `s_sig = r + c·x` under key `K` with nonce `R` can submit `keys_and_challenges = [(K, c); k]` and `Rs = [R; k]`, then set `s = (Σ_{i} z_i)·s_sig`. The check collapses to `(Σz_i)·R + (Σz_i)·c·K − s·G = (Σz_i)(R + c·K) − s·G = 0`, which holds exactly. One signature is thus counted `k` times — identical to a manager replaying `reviewRecipients` to stack votes. [5](#0-4) 

The callers of this API reinforce the "weight per entry" semantics: `Validators::verify_aggregate` in `coordinator/tributary/src/tendermint/mod.rs` zips a signer list with `aggregate.Rs()` and passes each `(key, challenge)` pair through without any uniqueness check, while `Weights::weight` credits weight per listed validator ID — so a duplicated entry would be double-counted by any weight-based consumer of `verify`. [6](#0-5) [7](#0-6) 

### Impact Explanation
An unprivileged party who obtains (or produces) one valid Schnorr signature for a public key and message can forge a `SchnorrAggregate` claiming arbitrary many signers participated. Any consumer that treats `verify` success as "each listed key contributed" — e.g., counting validator weight per signer entry — will accept commits/aggregates backed by a single signature, breaking the one-signer-one-contribution invariant. This is a forged signature accepted by an in-scope verifier, reachable purely through untrusted bytes to `SchnorrAggregate::read`/`verify`. [4](#0-3) 

### Likelihood Explanation
Requires one genuine signature for the target key/message pair (publicly observable for any signer) plus computing the deterministic `weight` scalars, which are derivable offline. No collusion, no key compromise, no timing constraints. Exploitation depends on a consumer attributing per-entry weight to the signer list, which is exactly the documented usage pattern of this API (aggregating votes/commit signatures). Medium severity: a verifier accepting a forged multi-signer claim, gated on downstream weight accounting rather than being universally exploitable alone.

### Recommendation
Reject duplicate public keys in `SchnorrAggregate::verify` (and `SchnorrAggregator::aggregate`): sort/hash the keys and error or return `false` if any repeats. Alternatively, bind each key to a unique position by including the key bytes in the weight transcript alongside the challenge, so duplicated entries cannot reuse one signature — though explicit dedup is simpler and matches the "one vote per participant" fix in the source report. [8](#0-7) 

### Proof of Concept
```rust
// crypto/schnorr context: signer with key x, K = x*G signs msg -> sig (R, s_sig)
// c = challenge binding (K, R, msg), publicly computable
let mut digest = DigestTranscript::<C::H>::new(DST);
digest.domain_separate(b"signatures");
// Reproduce the verifier's weight schedule for k duplicate entries
for _ in 0..k { digest.append_message(b"challenge", c.to_repr()); }
let mut z_sum = C::F::ZERO;
for _ in 0..k { z_sum += weight::<_, C::F>(&mut digest.clone()); } // per-index weights
// Forge: Rs = [R; k], s = z_sum * s_sig
let forged = SchnorrAggregate { Rs: vec![R; k], s: z_sum * s_sig };
// keys_and_challenges = [(K, c); k]
assert!(forged.verify(DST, &vec![(K, c); k])); // passes with only ONE real signature
```
The forgery satisfies `Σ z_i·R + Σ z_i·c·K = (Σz_i)(r + c·x)·G = s·G` because `s_sig = r + c·x`, requiring no knowledge of `x` beyond the single valid signature.

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res
}

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
