### Title
Out-of-bounds array read in CLVM canonical-encoding check via crafted atom length prefix - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` decodes a CLVM atom's variable-length size prefix (1–6 bytes) and reads successive bytes from `clvm_buffer` using an `offset` that is incremented `prefix_len` times inside a loop, with no bounds check against `len(clvm_buffer)` before each read. [1](#0-0) 

### Finding Description
The function reads `b = clvm_buffer[offset]` to classify the atom's length-prefix format, then for `prefix_len` in `{0,1,2,3,4,5}` loops, incrementing `offset` and indexing `clvm_buffer[offset]` again without ever checking that `offset < len(clvm_buffer)`: [2](#0-1) 

This is called from `is_clvm_canonical()`, which walks a caller-supplied serialized CLVM buffer token by token, dispatching to `is_atom_canonical` whenever it encounters a byte `> 0x80` (i.e., a multi-byte-length atom), including for the last token in the buffer: [3](#0-2) 

If an attacker crafts a spend bundle whose serialized puzzle-reveal/solution CLVM ends with a truncated multi-byte length-prefix atom (e.g., the last byte of the buffer is `0b11111100`-class, signaling a 5-byte length prefix that is not actually present), `is_atom_canonical` will attempt to read past the end of `clvm_buffer`, raising an unhandled `IndexError`.

This is the direct functional analog of `ALPINE-CVE-2016-2213` (FFmpeg `jpeg2000_decode_tile` OOB array read on crafted length-prefixed data): both bugs parse a length-prefixed/variable-size field from attacker-controlled input and index into a buffer using an offset derived from that field without validating it stays within the buffer bounds before the read.

### Impact Explanation
`is_clvm_canonical` / `is_atom_canonical` are invoked as part of canonical-serialization checks used to determine DEDUP-eligibility for spends during spend-bundle validation (`is_clvm_canonical(clvm_buffer)`), per the checked-in design notes describing this check as being used in `pre_validate_spendbundle()` under `MEMPOOL_MODE`. [4](#0-3) 
This makes the code reachable from a normal, unprivileged spend-bundle submission path (mempool admission), not requiring a malicious peer or node — an ordinary wallet/RPC caller can submit a crafted spend bundle. An unhandled `IndexError` here can abort/crash the validation call for that spend bundle; if this exception is not caught by a broad handler somewhere in the mempool add path, it constitutes a spend-triggered halt/exception in transaction processing for that call, which is a legitimate DoS-class impact analogous to the FFmpeg CVE.

### Likelihood Explanation
Reaching this code only requires submitting one spend bundle with a puzzle reveal/solution whose raw CLVM serialization is intentionally non-canonical/truncated in a specific way (ending on an incomplete multi-byte atom length prefix) — a low-cost, fully client-controlled action requiring no special privileges, timing, or race condition.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` (and in the `is_clvm_canonical` loop) before every `clvm_buffer[offset]` access, e.g., verify `offset < len(clvm_buffer)` before each read in the `for i in range(prefix_len)` loop, and raise/return a well-defined "non-canonical"/parse-error result rather than letting Python raise an uncaught `IndexError`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
