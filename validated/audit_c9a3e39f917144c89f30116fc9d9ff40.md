## Finding: `isGitHubHost` classifies arbitrary attacker-controlled hosts as GitHub Enterprise via a trivially forgeable HTTP header — (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost` (`app/src/lib/api.ts`) is used by `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` to decide whether a git credential-helper request belongs to a GitHub host or a "generic" host. Its final fallback check only verifies the *presence* of an `x-github-request-id` response header on a HEAD request that Desktop itself makes to the target host — a value fully controlled by whatever server answers that request. Any DNS-controlled or attacker-hosted HTTPS server can add this header and be misclassified as `enterprise`, which changes credential-helper behavior for that host.

### Finding Description
`getEndpointKind` runs several checks in order and only calls `isGitHubHost` as a last resort: [1](#0-0) 

`isGitHubHost` does hostname pattern heuristics first, then, if none match, performs a HEAD request to `${endpoint}/meta` and bases its verdict purely on whether the response contains an `x-github-request-id` header: [2](#0-1) 

Because the HEAD request (line 2473-2479) goes directly to the attacker's own host/domain (an "enterprise" endpoint is derived from the target URL itself via `getEnterpriseAPIURL`), the server that answers is entirely attacker-controlled. Setting the response header `x-github-request-id: anything` on any HTTP response causes `isGitHubHost` to return `true` — there is no validation of the header's value, no TLS certificate check tied to a known GitHub CA/cert pin, and no cross-check against a real GitHub-signed response.

This directly flows into credential-helper logic:
- `storeCredential` and `eraseCredential` both call `getEndpointKind` and skip all storage/erasure logic whenever the result is not `'generic'`: [3](#0-2) 
- `getCredential` treats a non-`'generic'` classification specially: if no existing account matches, it invokes `ui.promptForGitHubSignIn(endpoint)` instead of the generic credential flow: [4](#0-3) 

### Impact Explanation
Two distinct consequences follow a successful spoof:
1. **Silent credential drop**: for `store`/`erase` git credential-helper invocations against the attacker's host, Desktop silently skips saving or clearing the generic credential entirely (`storeCredential`/`eraseCredential` early-return), because it now believes the host is GitHub Enterprise and that "GitHub.com/GHE creds are only stored internally." The credential the user just typed for that host is dropped rather than cached, and stale generic entries are never erased on failed auth.
2. **Potential credential exfiltration**: on `get`, since the spoofed host now looks like an unrecognized GitHub Enterprise endpoint, Desktop prompts the user via `ui.promptForGitHubSignIn(endpoint)` rather than the normal generic-auth prompt. If the user completes that GitHub sign-in flow, the resulting `Account`'s real GitHub login/token is merged into the credential (`credWithAccount`) and handed back to git, which will then send it as Basic Auth to the attacker's host — i.e., the user's genuine GitHub OAuth token could be transmitted to an attacker-controlled server. I was not able to inspect `trampoline-ui-helper.ts`'s `promptForGitHubSignIn` implementation to fully confirm this secondary chain (index coverage did not surface that file's contents), so this part should be verified directly in a Devin session before being treated as fully confirmed.

### Likelihood Explanation
The primary bypass (case 1, silent credential drop) requires no user interaction beyond visiting/cloning from an attacker-controlled HTTPS remote — the credential helper runs automatically as part of normal git operations. It is straightforwardly reachable: an attacker just needs a domain and TLS certificate they control (DNS-controlled remote) and to add one arbitrary header to their HTTP responses. The secondary chain (case 2) additionally requires the user to accept a "sign in to GitHub" prompt, which is a plausible, in-band UI step rather than an "unnatural" one, since Desktop presents it as expected behavior for legitimate GHE hosts.

### Recommendation
`isGitHubHost` should not trust an arbitrary response header from the host being probed as proof of GitHub identity. Consider validating against a signed/verifiable property (e.g., cross-checking multiple independent signals, verifying TLS certificate chain against known GitHub Enterprise issuance patterns, or requiring the header combined with additional GitHub-specific response characteristics that are harder to forge), and ensure `storeCredential`/`eraseCredential` fail safe (i.e., default to treating unknown/ambiguous hosts as generic) rather than fail open into the GitHub-only credential path.

### Proof of Concept
1. Stand up an HTTPS server for a domain the attacker controls (e.g., `attacker-host.example`), with a valid TLS certificate.
2. Configure the server so any request to `/meta` (and `/api/meta`, matching `getEnterpriseAPIURL`) returns `HTTP 200` with header `x-github-request-id: fake-id`.
3. Clone/fetch from `https://attacker-host.example/some/repo.git` in GitHub Desktop, entering credentials when prompted by the underlying git credential-helper (`git-credential-manager`/trampoline).
4. Observe that `getEndpointKind` classifies the host as `'enterprise'` (confirmed by mocking/instrumenting `isGitHubHost`'s `fetch` call against the non-GitHub host and observing it returns `true` due solely to the injected header), and that `storeCredential`/`eraseCredential` silently no-op for this host instead of persisting/clearing the generic credential.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
