### Title
Unchecked type assertion on attacker-controlled CW20 `token_info` response causes panic in the pointer precompile's `AddCW20` - (File: precompiles/pointer/pointer.go and all `precompiles/pointer/legacy/v6xx/pointer.go` variants)

### Summary
The `AddCW20` handler in the EVM pointer precompile queries an arbitrary, caller-supplied CW20 contract's `token_info` response and blindly type-asserts the `"name"` and `"symbol"` JSON fields as Go `string`, without checking existence or type, mirroring the CVE-2024-56629 bug class (dereferencing/using an externally-supplied field that the code assumes is always present/valid).

### Finding Description
`AddCW20` accepts any bech32 address from the caller, runs `QuerySmart`/`QuerySmartSafe` against it with `{"token_info":{}}`, JSON-unmarshals the arbitrary response into `map[string]interface{}{}`, and then does: [1](#0-0) 
```go
res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
...
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
This pattern is repeated verbatim across every version directory (`v552` through the current `precompiles/pointer/pointer.go`), [2](#0-1) . Any CosmWasm contract that a user deploys and passes to `addCW20Pointer` is fully attacker-controlled: it can respond to `token_info` with a JSON object where `name`/`symbol` are absent (map lookup yields untyped `nil`), or return them as numbers/booleans/objects instead of strings. In Go, `nil.(string)` or `float64.(string)` with the unchecked, non-comma-ok type assertion form panics with "interface conversion: interface {} is nil, not string" (or the equivalent for the wrong concrete type).

### Impact Explanation
Precompile execution panics are not converted to a graceful revert at this layer: `DynamicGasPrecompile.RunAndCalculateGas`'s deferred `HandlePrecompileError` only runs for returned errors, not for panics, and the framework's own regression test explicitly documents that "a non-gas panic must propagate rather than be masked" [3](#0-2) . Because every honest validator executes the same transaction against the same malicious CW20 contract, the panic is deterministic and reproducible across the whole validator set. Depending on how far up the call stack the panic is ultimately caught (Cosmos SDK's `runTx` recover boundary vs. an uncaught panic that reaches ABCI), this ranges from a rejected/failing transaction to a full node crash/halt if any layer between the EVM interpreter and `runTx`'s recover does not catch it before unwinding into state you don't want touched. I could not fully verify, within the exploration budget, whether `sei-cosmos/baseapp`'s `runTx` panic-recovery wraps the entire EVM message execution path used to reach this precompile (i.e., whether the panic is guaranteed to be caught before it destabilizes block processing), so the exact blast radius (rejected tx vs. validator halt) is not confirmed with certainty.

### Likelihood Explanation
High reachability: any unprivileged account can deploy a trivial CW20-shaped CosmWasm contract that replies to `token_info` with `{"decimals":0,"total_supply":"0"}` (omitting `name`/`symbol`, or returning them as non-strings) and then call the pointer precompile's `addCW20Pointer(address)` with that contract's address — no special privileges, gas, or timing constraints are required. This is a single-transaction attack requiring no cooperation from validators or governance.

### Recommendation
Replace the unchecked type assertions with the comma-ok form and return a normal error on mismatch, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, errors.New("CW20 token_info response missing or invalid name field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, errors.New("CW20 token_info response missing or invalid symbol field")
}
```
Apply this fix to `precompiles/pointer/pointer.go` and to every `precompiles/pointer/legacy/v*/pointer.go` copy that contains the same pattern, and audit `precompiles/pointer/*` more broadly for other unchecked `.(string)`/`.(type)` assertions on data sourced from arbitrary CW20/CW721/CW1155 contract query responses.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` query handler returns `{"decimals":0,"total_supply":"0"}` (no `name`/`symbol` keys), or `{"name":123,"symbol":123,"decimals":0,"total_supply":"0"}`.
2. From an EVM transaction, call the pointer precompile's `addCW20Pointer(<cw20_contract_address>)` (selector for `AddCW20`) with the deployed contract's Cosmos address as the argument.
3. `p.wasmdKeeper.QuerySmartSafe(...)` succeeds and returns the crafted JSON; `json.Unmarshal` succeeds; `formattedRes["name"].(string)` panics because the map value is `nil` (or the wrong concrete type).
4. Observe the panic propagating out of `AddCW20`/`Execute`, bypassing the executor's error-based revert path, as confirmed by the precompile framework's own test asserting that non-gas panics are not masked (`TestDynamicGasPrecompileRepanicsNonGas`) [3](#0-2) .
