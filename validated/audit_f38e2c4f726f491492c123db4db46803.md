### Title
Payout attribution output is unauthenticated, letting anyone forge which operator is credited for a withdrawal fronted by someone else - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the payout transaction with the user's `SinglePlusAnyoneCanPay` signature covering only input 0 and output 0 (the user's payout output). The OP_RETURN output that identifies which operator "fronted" the withdrawal (and is later used by the verifier network to attribute reimbursement rights) is not covered by that signature at all. Because `SIGHASH_SINGLE | ANYONECANPAY` lets anyone add inputs and any additional outputs, whoever obtains the user's off-chain-shared payout signature can construct and broadcast their own version of the payout transaction, fund the required user output themselves, and stamp an arbitrary operator's x-only public key into the OP_RETURN output — crediting an operator who never funded the withdrawal.

### Finding Description
`create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436) builds:
- input 0: the withdrawal UTXO, spent with the user's `taproot::Signature` (`SpendPath::KeySpend`)
- output 0: the user's payout
- output 1: anchor
- output 2: OP_RETURN containing `operator_xonly_pk` [1](#0-0) 

The operator-side `withdraw()` flow requires the sighash type to be `SinglePlusAnyoneCanPay` and verifies the user's Schnorr signature against that sighash (core/src/operator.rs:614-637, core/src/rpc/parser/operator.rs:162-203). `SIGHASH_SINGLE` only commits the signature to the input being spent and the output at the *same index* (index 0 — the user output); `ANYONECANPAY` additionally allows arbitrary other inputs to be added. Consequently, the signature never authenticates output 1 (anchor) or output 2 (the OP_RETURN operator-attribution output). [2](#0-1) [3](#0-2) 

The verifier network's block scanner determines which operator is credited for a withdrawal purely by parsing the OP_RETURN of whatever transaction is found on-chain spending the withdrawal UTXO — with no check that this operator actually funded/broadcast the transaction: [4](#0-3) 

This is written into the `withdrawals` table via `update_payout_txs_and_payer_operator_xonly_pk` as `payout_payer_operator_xonly_pk`: [5](#0-4) 

Because the same user signature is shared "off-chain" with operators to allow them to front the payout (per the docstring), and because it does not bind the OP_RETURN output, any entity in possession of that signature (any operator, or anyone the signature is leaked to) can build a competing payout transaction that pays the user (satisfying the `SIGHASH_SINGLE` commitment) but attaches an arbitrary/different operator's x-only public key in the OP_RETURN, funding the withdrawal from their own funds while attributing the "payer" credit to a victim operator who never sent anything.

This breaks the required binding "the operator credited versus the party that paid" — the identity recorded as the payer (`payout_payer_operator_xonly_pk`) is decoupled from the entity that actually funded the payout.

### Impact Explanation
Downstream, `validate_payer_is_operator` (core/src/operator.rs:1686-1740) and `is_kickoff_malicious` (core/src/verifier.rs:1857-1915) gate the reimbursement/kickoff flow strictly on `payout_payer_operator_xonly_pk` matching the operator attempting to kick off. If a griefer fronts a withdrawal but stamps a victim (honest) operator's x-only pubkey into the OP_RETURN:
- The victim operator never actually made this payment, so it will never submit a matching kickoff for it, and `is_payout_handled` for that withdrawal index remains `FALSE` indefinitely.
- `get_first_unhandled_payout_by_operator_xonly_pk` (core/src/database/verifier.rs:282-313) always looks up the *lowest-index unhandled* payout attributed to a given operator (`ORDER BY idx ASC LIMIT 1`), which is used by the operator's own reimbursement/kickoff automation (`payout_checker` task) to decide what to process next. [6](#0-5) 

Since this forged, unhandled, permanently-stuck entry can be placed at a low index (or simply becomes the oldest unresolved entry over time), it can permanently occupy the "first unhandled payout" slot for the victim operator, blocking their automation from ever advancing to genuine withdrawals they did front — an honest operator being permanently unable to be reimbursed for withdrawals they actually paid.

### Likelihood Explanation
Exploitation requires only possession of the user's `SinglePlusAnyoneCanPay` withdrawal signature — which is explicitly designed to be shared "off-chain" with operators to allow front-running payouts, per the docstring on `create_payout_txhandler`. Any operator (or any party the signature leaks to, since ANYONECANPAY signatures are inherently combinable/forwardable) can broadcast a competing payout transaction crafted this way with no cryptographic barrier, no special role beyond "possesses the signature", and no additional signing required. No verifier/aggregator collusion is needed — a single unprivileged actor holding the signature is sufficient.

### Recommendation
Bind the OP_RETURN operator-attribution output to the same authenticated commitment as the payout output, e.g., by using a sighash type that commits to all outputs (`SIGHASH_ALL`) for the withdrawal input, or alternatively require the operator to co-sign the OP_RETURN output with their own key so that the attribution field cannot be substituted by a third party holding only the user's signature. Additionally, verifiers should reject/ignore attribution to an operator xonly pk that did not itself broadcast or fund the transaction (e.g., by requiring the operator's own signature over the full payout transaction, not just the user's partial signature).

### Proof of Concept
1. A withdrawal request is issued for user U with signature `sig_U` using `SIGHASH_SINGLE|ANYONECANPAY` over input 0 / output 0, shared off-chain with operators per the intended protocol flow (`parse_withdrawal_sig_params` in core/src/rpc/parser/operator.rs enforces this sighash type).
2. Attacker A (any party in possession of `sig_U`, e.g., a malicious operator) builds their own version of the payout transaction using `create_payout_txhandler`-equivalent logic: input 0 = withdrawal UTXO with `sig_U`, output 0 = the exact user payout (satisfies `SIGHASH_SINGLE` commitment), additional inputs funded by A to cover fees, output 2 = OP_RETURN containing victim honest Operator V's `xonly_pk` instead of A's own.
3. A broadcasts this transaction on Bitcoin, funding the withdrawal entirely themselves.
4. The verifier's `update_finalized_payouts` scan (core/src/verifier.rs:2283-2353) parses the OP_RETURN and records `payout_payer_operator_xonly_pk = V` in the `withdrawals` table, even though V never signed, funded, or broadcast anything.
5. `get_first_unhandled_payout_by_operator_xonly_pk` for operator V now returns this bogus, permanently-unhandled entry ahead of V's genuine withdrawals, and `validate_payer_is_operator`/`is_kickoff_malicious` prevent any other operator from claiming reimbursement for this specific withdrawal index, since only V's kickoff would match — but V never actually paid, so it stalls V's automation on this index indefinitely.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
