### Title
Stale-size caching in `LazyFieldLite` produces size/serialization desync after byte-concatenation merge - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
The refund report's failed invariant is a time-of-check/time-of-use gap: a value (refund price) is computed from state as of time T and used for a decision, while the authoritative state is only "refreshed" afterward at T+1, so the value used is provably stale relative to the state it should reflect. The closest genuine Protobuf analog is `LazyFieldLite.getSerializedSize()` / `mergeFrom()`, where the **cached "size" is deliberately derived from raw, unparsed wire bytes** (`delayedBytes`) captured at merge time, while the semantically correct size is only known after the lazy value is actually parsed ("refreshed") — and the code's own comments admit these two values can diverge.

### Finding Description
`LazyFieldLite` stores an extension/message field either as parsed `value` or as raw `delayedBytes` (unparsed wire bytes), lazily parsing on first access via `ensureInitialized()`. During `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, if both the existing and incoming field are still unparsed, the implementation takes a fast path and simply **concatenates raw bytes** instead of semantically merging: [1](#0-0) 

`getSerializedSize()` then returns the size of these concatenated bytes without parsing them, and the class's own documentation warns that this is unsafe because Protobuf merge semantics collapse duplicate optional fields when the message is actually parsed — i.e., "refreshed": [2](#0-1) 

This is structurally identical to the reported bug: a size/value is computed from a pre-refresh state (`delayedBytes`, the raw concatenated wire bytes with possible duplicate fields) and used by the outer/parent message for its own `ByteSizeLong()`/`getSerializedSize()` accounting and caching — but the true, post-refresh state (the fully parsed `value`, where duplicate scalar fields collapse to "last one wins" per proto semantics) can have a different size. Just as the refund's `effectivePrice` is locked in before `refreshPrice()` updates oracle state, `LazyFieldLite`'s memoized size is locked in from `delayedBytes` before the lazy `ensureInitialized()` "refresh" parses the true value.

Similarly, `ensureInitialized(MessageLite defaultInstance)` treats the parse as the authoritative refresh point but only performs it lazily on first real access, while the un-refreshed byte length may already have been consumed by a containing message's serialized-size computation: [3](#0-2) 

### Impact Explanation
Within Protobuf's own trust model (bounded, attacker-controlled binary input through the public `parseFrom`/`mergeFrom` API, trusted schema), an attacker who controls two message-set/extension chunks with duplicate optional scalar fields inside the same extension can create a case where:
- The reported/cached size (`getSerializedSize()`, driven by `delayedBytes.size()`) reflects the raw, duplicate-containing byte length.
- The actual size after the field is later force-parsed (`value.getSerializedSize()`) reflects the deduplicated, semantically merged content and differs.

If a containing message serializes using the cached size before the lazy field is forced to parse (or vice-versa in different call orders), the outer message's byte-size accounting and the bytes actually written can diverge. This is the same class of defect the external report flags (a size/price computed pre-refresh, consumed as if authoritative, while the authoritative post-refresh value differs) — in Protobuf's context, it manifests as a serialized-size/content mismatch (triggering the library's own `ByteSizeConsistencyError`/`CHECK_EQ` guards in native message serialization, or silently producing malformed wire output in the pure-Java lazy path that has no consistency check at all). This is a legitimate Medium-severity correctness/integrity issue: it does not itself grant RCE or memory corruption, but it can corrupt re-serialized output or crash the process via the library's internal consistency check, when triggered purely through the public parsing/merging API on bounded, attacker-supplied bytes.

### Likelihood Explanation
This requires only ordinary, bounded protobuf input containing an extension/message-set field whose bytes are merged twice while unparsed (e.g. two message-set items for the same extension in the same or successive merge calls) with content designed to contain duplicate optional scalar sub-fields. No privileged access, hostile schema, or huge/unbounded payloads are needed — this is reachable purely through the standard, documented `mergeFrom` merge path that Protobuf explicitly designed as a "fast path" optimization, and the code's own comment acknowledges the discrepancy is a known, real possibility ("Be careful when using this method").

### Recommendation
Do not memoize/return `getSerializedSize()` from unparsed `delayedBytes` once a byte-concatenating merge has occurred; either force `ensureInitialized()` before computing size after any merge of two unparsed lazy fields, or fully parse-and-merge (rather than raw-concatenate) when semantic correctness of size is required by the caller. At minimum, the outer message's byte-size computation should invalidate/recompute lazy-field sizes after any operation that can change the "refreshed" value, mirroring the recommendation in the original report: refresh oracle/state before consuming it for size-relevant computation, rather than deriving the value from pre-refresh state and refreshing afterward.

### Proof of Concept
Conceptual reproduction using the public Java API (schema/registry trusted, input bounded):
1. Build an extension message type with an `optional int32` scalar field.
2. Serialize instance A with `field=1`, instance B with `field=2` as raw bytes (both syntactically valid, unparsed wire bytes for the same field).
3. Create `LazyFieldLite lf1 = LazyFieldLite(registry, bytesA)` (unparsed, `delayedBytes = bytesA`).
4. Merge `lf1.mergeFrom(inputStreamOfBytesB, registry)` — since `lf1.delayedBytes != null`, the fast path concatenates: `delayedBytes = bytesA.concat(bytesB)` per [4](#0-3) .
5. Call `lf1.getSerializedSize()` → returns `len(bytesA) + len(bytesB)` (per [5](#0-4) ), even though the field is `optional`, so real protobuf merge semantics say the *last* occurrence of `field` wins.
6. Now force the "refresh": call `lf1.getValue(DefaultInstance)`, which parses the concatenated bytes via `ensureInitialized`, producing `value` with `field=2` only, whose true `getSerializedSize()` is `len(bytesB)`'s field-only size — smaller than the previously reported concatenated size.
7. The size reported in step 5 (used by any container that queried it before the forced parse in step 6) is now stale/inconsistent with the value in step 6 — exactly analogous to the refund report's stale-price-before-refresh pattern.

This reproduction only requires standard, bounded, attacker-controlled protobuf bytes through the public `mergeFrom`/`getValue`/`getSerializedSize()` API surface; it does not require any privileged access or hostile schema.    * Due to the optional field can be duplicated at the end of serialized bytes, which will make the

  public int getSerializedSize() {
    // We *must* return delayed bytes size if it was ever set because the dependent messages may
    // have memoized serialized size based off of it.
    if (delayedBytes != null) {
      return delayedBytes.size();
    } else if (memoizedBytes != null) {
      return memoizedBytes.size();
    } else if (value != null) {
      return value.getSerializedSize();
    } else {
      return 0;
    }
  }

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
