### Title
Silent git remote URL rewrite from unvalidated GitHub API `clone_url` field - (`app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl` automatically rewrites the local `origin` remote URL whenever the GitHub API reports a different `clone_url` for a repository (e.g. after a repo rename/transfer is detected). The function only checks that the *protocol* of the old and new URL match and that the old remote pointed at the previously known clone URL — it never validates that the new URL's **hostname** matches the repository's configured endpoint/account. This mirrors the reported smart-contract bug class: a branch of logic (the "safety check" before mutating state) is missing a condition, so a case that should be rejected is silently accepted.

### Finding Description [1](#0-0) 

The function computes:
- `urlsMatch` — whether `apiRepo.clone_url` already equals the current remote (via `urlMatchesRemote`, which compares hostname/owner/name).
- `protocolsMatch` — compares `URL.parse(remoteUrl).protocol` vs `URL.parse(updatedRemoteUrl).protocol`, i.e. only `https:` vs `https:` vs `ssh` (null).
- `remoteUrlUnchanged` — whether the *old* remote still matches the previously stored `gitHubRepository.cloneURL`.

If `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, it calls `gitStore.setRemoteURL(...)` with the **new** `apiRepo.clone_url` — no matter what host that URL points to. Nowhere is the new URL's hostname compared against `gitHubRepository.endpoint` (i.e., the account/enterprise host the repository is supposed to belong to). `urlMatchesRemote` (`app/src/lib/repository-matching.ts:90-118`) does compare hostnames, but it's only used to detect "no-op" cases (`urlsMatch`, `remoteUrlUnchanged`) — never to constrain what host the *new* URL is allowed to point to.

`apiRepo` (an `IAPIRepository`/`IAPIFullRepository`) is data fetched from the GitHub API for the associated endpoint. If that API response is attacker-influenced — for example a compromised/malicious GitHub Enterprise Server the user is authenticated against, or a network-level tamperer able to modify API responses for that endpoint — the `clone_url` field can be set to an arbitrary URL with the same scheme (`https://attacker.example/...`) as the legitimate remote. The existing guards (`protocolsMatch`, `remoteUrlUnchanged`, `!urlsMatch`) do nothing to stop this because none of them check the new URL's host.

### Impact Explanation
If exploited, Desktop silently repoints the user's `origin` remote to an attacker-controlled server without any prompt or confirmation. Subsequent `git fetch`/`git pull`/`git push` operations (which Desktop performs using the rewritten remote) would:
- Send the user's Git credentials/OAuth-derived tokens (via `envForAuthentication`/trampoline) to the attacker host during authentication.
- Fetch attacker-supplied objects into the user's local repository (supply-chain risk), or
- Push the user's code/commits to an attacker-controlled destination.

This satisfies the "silent corruption of what the user commits/pushes" and "credential exfiltration" impact classes, driven entirely by an attacker-controlled GitHub API object, without any unusual user action.

### Likelihood Explanation
This path is only reachable through control of GitHub API responses for a configured endpoint (e.g., a rogue/compromised GitHub Enterprise Server, or an on-path attacker able to tamper with API traffic for that host) — the caller of `updateRemoteUrl` is part of the normal repository-refresh flow (`withRefreshedGitHubRepository` in `app/src/lib/stores/app-store.ts`), which runs periodically without user interaction. No local access, malware, or leaked credentials are required beyond the attacker being able to answer as the trusted API endpoint the user already uses.

### Recommendation
In `updateRemoteUrl`, before calling `gitStore.setRemoteURL`, verify that the new `clone_url`'s hostname matches `gitHubRepository.endpoint`'s hostname (the same check `urlMatchesRemote` already performs for other comparisons). Reject the update if the hostname changes.

### Proof of Concept
1. Configure Desktop against a GitHub Enterprise endpoint (or intercept API traffic for `api.github.com`/GHE host).
2. Have the API respond to the repository lookup with `clone_url: "https://attacker.example/user/my-repo.git"` while keeping the same protocol as the existing remote.
3. On the next background refresh, `updateRemoteUrl` (`app/src/lib/stores/updates/update-remote-url.ts:42-44`) sees `protocolsMatch = true`, `remoteUrlUnchanged = true` (old remote still matches the old stored clone URL), `urlsMatch = false`, and calls `gitStore.setRemoteURL('origin', 'https://attacker.example/user/my-repo.git')`, silently repointing the user's remote.
4. The next fetch/push from Desktop now targets `attacker.example`. [2](#0-1)

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
