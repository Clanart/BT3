### Title
`SimplexPaymaster._getOraclePrice` accepts Chainlink circuit-breaker-pinned answers, letting a depegged token drain treasury-sponsored gas - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice` validates only that a Chainlink answer is positive and not stale; it never checks the answer against the feed's `minAnswer`/`maxAnswer` circuit-breaker bounds [1](#0-0) . When an underlying asset (e.g. a sponsored stablecoin) crashes far below the aggregator's configured floor, Chainlink freezes the reported answer at `minAnswer` instead of reflecting the true collapsed price — exactly the class of bug that caused the Venus/LUNA incident referenced in the external report.

### Finding Description
`_tokenPrice` and `_getOraclePrice` are the sole pricing path used by `_fetchDetails` (called from `_validatePaymasterUserOp`) to compute how many ERC-20 tokens a UserOp sender must pay for sponsored gas [2](#0-1) [3](#0-2) . It is also used by the permissionless-adjacent `swapAndDeposit` fee-recycling path to bound acceptable slippage against the oracle price [4](#0-3) .

`_getOraclePrice` reads `latestRoundData()` and only reverts when `answer <= 0` or when `updatedAt` is stale relative to `maxOracleAge` [5](#0-4) . There is no check that `answer` is strictly inside the feed's `minAnswer`/`maxAnswer` band. Chainlink aggregators clamp reported answers to that band as a circuit breaker; during an extreme depeg or crash the feed will keep returning `updatedAt = block.timestamp` (so the staleness check passes) with `answer == minAnswer`, even though the true market price has fallen well below that floor.

Since `tokenPrice = nativeUsd * 10^tokenDecimals * (10000+markupBps) / tokenUsd`, an inflated (pinned-high) `tokenUsd` for a token whose real value has collapsed makes the paymaster charge fewer token units per unit of gas than the token's real worth requires. The paymaster/treasury ends up sponsoring real, valuable native gas in exchange for a stablecoin that is actually worth a fraction of the price the contract believes.

### Impact Explanation
Every UserOp sponsored via the depegged/crashed token undercharges the true economic cost, draining value from the paymaster's `EntryPoint` deposit and accumulated treasury balance to whichever attacker holds the crashed asset — a direct, unauthorized transfer of value away from the rightful beneficiary (treasury), matching the "stealing or loss of funds" and "logic attacks" categories in the bounty scope. Because `SimplexPaymaster` is described as governance-administered but permissionlessly usable by any UserOp sender presenting a registered token, an unprivileged attacker can trigger this without needing a malicious relayer, prover, or admin.

### Likelihood Explanation
This requires only that one of the governance-registered token/USD Chainlink feeds experiences a real-world de-peg or crash event severe enough to hit its `minAnswer` floor (as has occurred historically, e.g. depeg events on major stablecoins). No malicious peer, relayer, or oracle operator collusion is needed — the attacker simply submits ordinary UserOps paying with the depegged token while the feed is pinned. The bug is a straightforward missing-bound-check identical to the referenced report's root cause.

### Recommendation
In `_getOraclePrice`, fetch and cache each aggregator's `minAnswer`/`maxAnswer` (or configure conservative governance-set bounds per token/native oracle) and revert when `answer` is at or outside those bounds, e.g.:
```solidity
require(answer > minAnswer && answer < maxAnswer, "circuit-breaker: invalid price");
```
This should apply to both `nativeOracle` and every registered `tokenOracle` in `_getOraclePrice`.

### Proof of Concept
1. Governance registers `TokenX` with a Chainlink feed whose `minAnswer` is `$0.90` (8 decimals).
2. `TokenX` experiences a real depeg crash to `$0.01`; the aggregator's circuit breaker clamps and continues reporting `answer = 0.90e8` with a fresh `updatedAt`.
3. `_getOraclePrice` passes both the `answer <= 0` check and the staleness check [5](#0-4) , returning the stale-but-"fresh" `0.90e8`.
4. An attacker acquires large amounts of near-worthless `TokenX` cheaply and submits UserOps whose `paymasterData` selects `TokenX`; `_fetchDetails` → `_tokenPrice` prices gas at the pinned `$0.90` rate [2](#0-1) .
5. The paymaster's `EntryPoint` deposit pays real gas while receiving `TokenX` worth ~1% of the assumed value, repeatable until the treasury/deposit is drained.

```text
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
