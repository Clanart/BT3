### Title
PR checkout via `_checkoutPullRequest` never pins/verifies the reviewed head commit SHA — attacker-controlled fork branch content is silently checked out - (File: `app/src/lib/stores/app-store.ts`)

### Summary
Github Desktop stores a pull request's `head.sha` when syncing PR metadata from the API [1](#0-0) , but this SHA is never passed to, or verified by, the checkout path. When a user checks out a pull request, `Dispatcher.checkoutPullRequest` forwards only the PR's `cloneURL` and `head.ref` (branch name) — not the `head.sha` — to `AppStore._checkoutPullRequest` [2](#0-1) . `_findPullRequestBranch` then fetches the fork remote and checks out whatever commit currently sits at the tip of that branch name, with no comparison to the previously-fetched `head.sha` [3](#0-2) .

### Finding Description
This mirrors the reported Uniswap issue's root cause: an operation is executed using a live, attacker-influenceable value with no bound/expectation check (no `amountOutMinimum`, no `deadline`). Here, the "price" is the commit content of a fork branch, and the missing guard is a SHA/deadline check pinning the checkout to the commit the user actually reviewed.

Flow:
1. Desktop fetches and stores PR metadata, including `head.sha`, via `pull-request-store.ts` [1](#0-0) .
2. A user reviews the PR diff (as of that SHA) and decides to check it out.
3. `checkoutPullRequest` in the dispatcher discards the SHA entirely and only passes `cloneURL`/`ref` [2](#0-1) .
4. `_findPullRequestBranch` fetches the remote (`_fetchRemote`) and resolves `existingBranch` purely by ref name against whatever the remote currently reports, then checks it out via `_createBranch`/`_checkoutBranch` [4](#0-3) .

Because a PR's head branch lives in a fork controlled entirely by the (unprivileged, potentially malicious) PR author, that author can force-push new content to the branch between the time the PR/diff was reviewed and the time the victim clicks "Checkout PR" (or the time Desktop's fetch resolves). Desktop has no mechanism to detect that the fetched tip no longer matches `head.sha` and silently checks out and opens the new, unreviewed content.

### Impact Explanation
An attacker who controls a PR's head fork branch (a low-privilege, standard capability — anyone can open a PR from a fork) can swap in arbitrary/malicious commits after a reviewer has approved the diff shown in the GitHub UI, and before/at the moment the victim performs "Checkout PR" in Desktop. Since Desktop does not compare or pin against the reviewed `head.sha`, the victim's working directory silently receives different code than what they inspected, potentially leading to execution of malicious build scripts, hooks, or code once the victim runs/opens the project.

### Likelihood Explanation
Moderate. It requires the attacker to time a force-push to the fork branch to occur after PR review but before/at Desktop's checkout-time fetch — an achievable race for any PR author, especially in automated review workflows where checkout happens some time after the PR was opened/reviewed. No local access, credentials, or social engineering beyond normal PR review workflows is needed.

### Recommendation
Thread `pullRequest.head.sha` through `checkoutPullRequest` → `_checkoutPullRequest` → `_findPullRequestBranch`, and after fetching the remote branch, verify the resolved branch tip SHA equals the expected `head.sha` before checking out. If it differs, warn the user that the PR branch has changed since it was last reviewed/fetched and require explicit confirmation before proceeding (analogous to enforcing `amountOutMinimum`/`deadline` bounds rather than accepting whatever the counterparty currently offers).

### Proof of Concept
1. Attacker opens PR #1 from fork `attacker/repo` branch `feature`, with an innocuous diff at commit `S1`.
2. Victim reviews PR #1 in GitHub/Desktop, sees benign diff for `S1`.
3. Victim opens Desktop and selects "Checkout PR" for PR #1 (some time later — e.g., after CI passes).
4. Immediately before Desktop's `_findPullRequestBranch` fetch call completes [5](#0-4) , attacker force-pushes malicious commit `S2` (e.g., adding a malicious `.git/hooks` script or build step) to `attacker/repo:feature`.
5. Desktop fetches, finds the remote branch now at `S2`, and checks it out via `_createBranch`/`_checkoutBranch` with no SHA comparison against the `S1` the victim reviewed [6](#0-5) .
6. Victim's working directory now silently contains attacker's malicious `S2` content, believed to be the reviewed `S1`.

  public async checkoutPullRequest(

    if (pullRequest.head.gitHubRepository.cloneURL === null) {
      return
    }

      repository,
      pullRequest.pullRequestNumber,
      pullRequest.head.gitHubRepository.owner.login,
      pullRequest.head.gitHubRepository.cloneURL,

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
