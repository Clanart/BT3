### Title
Contract governance (`GovParam` / KIP-81) can set `kip71.lowerboundbasefee` > `kip71.upperboundbasefee` without a consistency check, breaking the KIP-71 base-fee invariant - (File: `kaiax/gov/contractgov/impl/getter.go`)

### Summary
The `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` governance parameters are only validated independently (each via `noopFormatChecker`), with the cross-field invariant `lower <= upper` enforced solely in the header-governance vote path. Contract governance (the `GovParam` contract, KIP-81) bypasses that check entirely, so GC members can leave the chain in a state where `LowerBoundBaseFee > UpperBoundBaseFee`, corrupting the base-fee computation used for every block.

### Finding Description
Each governance parameter is declared with a `Canonicalizer` and a `FormatChecker` in [1](#0-0)  Both `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` use `noopFormatChecker`, which always returns `true` [2](#0-1) , i.e. there is no per-parameter range restriction and, more importantly, no check relating the two values to each other.

The only place that enforces `lower <= upper` is `headerGovModule.checkConsistency`, invoked exclusively during header-vote verification (`VerifyVote`) for **header governance**: [3](#0-2) 

Contract governance, however, reads parameters from the on-chain `GovParam` contract via `contractGetAllParamsAtFromAddr`, which calls `ParseContractCall` and, in turn, `PartialParamSet.Add`: [4](#0-3)  `Add` only applies the per-field `Canonicalizer`/`FormatChecker` pair for the individual parameter being set — no cross-parameter consistency logic exists here: [5](#0-4) 

The merged `GetParamSet` in `contractGovModule` then simply calls `ret.Set(k, v)` for every retrieved key/value with no additional validation: [6](#0-5)  and the top-level `gov` module merges contract-governance values on top of header/fallback values whenever the block is post-Kore: [7](#0-6) 

Consequently, GC members can submit two independent KIP-81 votes through the `GovParam` contract — e.g. `kip71.lowerboundbasefee = 100000000000` and `kip71.upperboundbasefee = 50000000000` — each of which passes its own (no-op) format check, resulting in an effective `ParamSet` with `LowerBoundBaseFee > UpperBoundBaseFee`. This value flows straight into `ParamSet.ToKip71Config()` [8](#0-7)  and from there into the consensus-critical base-fee formula `NextMagmaBlockBaseFee`: [9](#0-8) 

### Impact Explanation
`NextMagmaBlockBaseFee` assumes `lowerBoundBaseFee <= upperBoundBaseFee`. When that invariant is violated, the parent-fee clamping logic (`if parentBaseFee >= upperBoundBaseFee ... elif parentBaseFee <= lowerBoundBaseFee ...`) misbehaves: a `parentBaseFee` between the (swapped) bounds gets clamped to the (now numerically lower) "upper" bound, and increases in gas usage cannot push the fee past that artificially-low ceiling, while decreases in gas usage cause a large discontinuous jump straight to the (now numerically higher) "lower" bound. This produces base fees that are economically meaningless (stuck at unintended levels or jumping unpredictably), which:
- Lets transactions be systematically underpriced relative to the intended minimum fee for extended periods (fee-mechanism/value-extraction impact), or
- Causes sudden large base-fee jumps that invalidate/strand users' pending signed transactions (DoS on already-broadcast transactions and on KIP-71-based admission pricing).

Because `NextMagmaBlockBaseFee` is a pure deterministic function of chain state, all honest nodes compute the same (corrupted) value, so this is not a consensus split, but it directly corrupts fee/gas-pricing invariants relied upon by the pool admission and KIP-71 pricing logic, causing genuine fee-market and value-movement harm at the protocol level — analogous to the referenced `setPlotsAvailablePerSize` bug where an unchecked admin-settable parameter combination silently violates an invariant relied upon elsewhere in the system.

### Likelihood Explanation
Reaching this requires only GC-member-level KIP-81 votes through the deployed `GovParam` contract (not privileged node/validator internals), which is an intended, reachable governance interface. No exploitation of memory-unsafety or consensus messaging is needed — merely two ordinary parameter votes with values that are individually "valid" per the no-op format checkers. The header-governance path already recognizes this exact risk and defends against it (`checkConsistency`), but the equally-reachable contract-governance path does not, making the omission clearly a gap rather than a defense-in-depth choice.

### Recommendation
Apply the same `lower <= upper` consistency check used in `headerGovModule.checkConsistency` to values coming from contract governance — e.g., validate the merged `ParamSet` (or the relevant subset) after `contractGovModule.GetParamSet`/`kaiax/gov/impl.GetParamSet` assembles the final parameter set, rejecting or falling back to defaults if `LowerBoundBaseFee > UpperBoundBaseFee` (and similarly re-review other cross-field invariants such as `GasTarget` vs `MaxBlockGasUsedForBaseFee` for the same gap).

### Proof of Concept
1. Deploy/enable the `GovParam` contract as `governance.govparamcontract` post-Kore fork.
2. Submit KIP-81 governance transactions through the `GovParam` contract to set:
   - `kip71.lowerboundbasefee = 100000000000`
   - `kip71.upperboundbasefee = 50000000000`
3. Both values pass individually through `PartialParamSet.Add` (`noopFormatChecker` for each) in [5](#0-4) ; no code path checks `lower <= upper` for contract-sourced parameters (contrast with [3](#0-2) , which is header-vote-only).
4. Once effective, `gov.GetParamSet` (post-Kore) merges these contract values into the final `ParamSet` [7](#0-6) , and `ToKip71Config()` feeds them into `NextMagmaBlockBaseFee` [9](#0-8) , producing a corrupted, economically-invalid base-fee trajectory for every subsequent block.

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
