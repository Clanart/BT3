### Title
Unbounded length-prefix read in `is_atom_canonical()` can raise an uncaught `IndexError` on attacker-supplied spend bundle CLVM data - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` decodes the CLVM atom length-prefix encoding by reading up to 5 additional bytes from `clvm_buffer` starting at `offset` [1](#0-0) , without ever checking that `offset + prefix_len` stays within the bounds of `clvm_buffer`. This mirrors the libgphoto2 `ptp_unpack_Sony_DPD()` bug: a multi-byte length/count field is parsed by advancing an offset and indexing into a buffer with no bounds check before each read, while a sibling/standard code path enforces bounds correctly.

### Finding Description
`is_atom_canonical()` is called from `is_clvm_canonical()`, which walks a CLVM-serialized buffer token-by-token to decide whether it uses shortest-form (canonical) encoding [2](#0-1) . For every atom byte `b > 0x80`, the code computes a `prefix_len` (0–5) from the high bits of `b`, then loops `prefix_len` times, each time doing `offset += 1; atom_len |= clvm_buffer[offset]` [3](#0-2) . There is no check anywhere in `is_atom_canonical()` that `offset + prefix_len < len(clvm_buffer)` before these reads are performed — unlike the length-prefixed parsers elsewhere in the codebase (e.g. `skip_bytes()` and `skip_list()` in `chia/full_node/full_block_utils.py`, which explicitly validate `len(buf) < 4` and `n > len(buf)` before consuming) [4](#0-3) . This is exactly the same defect pattern as the reported CVE: one code path (`ptp_unpack_DPD`) validates remaining buffer length before reading a multi-byte count, while the analogous path (`ptp_unpack_Sony_DPD`) omits the check.

In Python, reading past the end of a `bytes` object with `clvm_buffer[offset]` raises `IndexError` rather than performing a true out-of-bounds memory read, so the direct memory-safety consequence from the C bug does not apply. The reachable consequence in this codebase is an unhandled exception during CLVM canonical-encoding validation of an untrusted, submitter-controlled buffer.

### Impact Explanation
`is_clvm_canonical()` is documented as being used to gate DEDUP eligibility for spend bundle solutions during mempool processing of a submitted spend bundle [5](#0-4) . A crafted solution buffer whose last atom byte declares a multi-byte length prefix (`prefix_len` up to 5) but is truncated right at the buffer boundary drives `offset` past the end of `clvm_buffer` inside the read loop, raising an uncaught `IndexError`. If this exception is not caught by the caller in `MempoolManager`, it can abort processing of that specific spend bundle submission (a localized transaction-processing halt triggered by a single crafted, unprivileged spend bundle), rather than a broader OOB memory corruption.

### Likelihood Explanation
Likelihood is limited by the precondition that the buffer must already look like partially-valid CLVM serialization up to the point of truncation (a normal atom marker followed by a short/missing length-prefix tail), which is a well-defined, easily constructed byte pattern that an unprivileged spend-bundle submitter fully controls in the coin spend's `solution` field. No special privileges, network position, or timing are required to trigger it, matching the report's "any submitter reachable" bar.

### Recommendation
Add an explicit bounds check in `is_atom_canonical()` before reading the length-prefix bytes, e.g. verify `offset + prefix_len < len(clvm_buffer)` (or `len(clvm_buffer) - offset > prefix_len`) prior to the `for i in range(prefix_len)` loop, mirroring the checks already used in `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`. Raise a handled `ValueError`/return non-canonical instead of allowing an `IndexError` to propagate, and ensure the caller in `chia/full_node/mempool_manager.py` treats malformed buffers as a normal validation failure rather than an unhandled exception.

### Proof of Concept
Construct a `clvm_buffer` whose final byte is an atom marker requiring the maximum length prefix, e.g. `b"\xfc"` (which per the mask table sets `prefix_len = 5`), with no following bytes:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
is_clvm_canonical(b"\xfc")  # raises IndexError: index out of range
```
Embedding such a truncated atom as the trailing bytes of a spend's `solution` in a submitted spend bundle drives `is_atom_canonical()`'s read loop past the buffer end when `is_clvm_canonical()` is invoked during mempool admission's DEDUP-eligibility check [6](#0-5) .

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```

```markdown
### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes

- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.
```
