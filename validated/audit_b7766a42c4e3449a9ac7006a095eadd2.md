### Title
Unbounded recursion in `AccountKeyRoleBased.DecodeRLP` allows stack-overflow DoS via a deeply nested composite `AccountKey` in a submitted transaction - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively RLP-decodes each sub-key of a role-based account key by calling `rlp.DecodeBytes` on every element, and each of those sub-keys can itself be another `AccountKeyRoleBased`. The "no nested composite key" rule is enforced only *after* decoding completes (in `CheckInstallable`/`CheckUpdatable`/state-transition validation), so an attacker can submit a single `TxTypeAccountUpdate` (or `TxTypeFeeDelegatedAccountUpdate...`) transaction via the public RPC `sendRawTransaction`/`kaia_sendRawTransaction` whose `AccountKey` field is a chain of thousands of nested `AccountKeyRoleBased` wrappers. Decoding that single transaction exhausts the goroutine stack and crashes the node with `SIGABRT`/`SIGSEGV`, the same bug class as the reported `lopdf` RUSTSEC-2026-0187 issue (unbounded recursive parsing of untrusted, deeply nested input causing an unrecoverable process abort rather than a catchable panic).

### Finding Description
`AccountKeyRoleBased.DecodeRLP` decodes the RLP list into `[][]byte`, and then, for every element, decodes a nested `AccountKeySerializer` (which itself allocates a fresh `AccountKey` of whatever type is declared, including `AccountKeyTypeRoleBased` again) via a fresh recursive call to `rlp.DecodeBytes`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` dispatches purely on the declared `keyType` byte and recurses into `s.Decode(serializer.key)`, with no depth tracking at all: [2](#0-1) 

The only defense against nested composite keys — `ErrNestedCompositeType` — is applied in `CheckInstallable`/`CheckUpdatable`, which run only after the whole `AccountKey` tree has already been fully decoded from bytes into Go values: [3](#0-2) [4](#0-3) 

Public entry points that trigger this decode on fully untrusted, attacker-supplied bytes before any nesting check runs include the transaction RLP decoder used by `SendRawTransaction`/`SendRawTransactions`: [5](#0-4) [6](#0-5) 

and the dedicated `DecodeAccountKey` RPC method, which decodes an arbitrary caller-supplied byte blob directly: [7](#0-6) 

Both paths call `rlp.DecodeBytes`, whose generic reflection-based decoder (`decodeListSlice`/`decodeListArray`) also recurses per nesting level with no depth cap of its own: [8](#0-7) 

There is no `ErrNestedCompositeType`, `MaxNestLevel`, or any recursion-depth guard anywhere inside `rlp` package or inside `DecodeRLP`/`UnmarshalBinary` of `Transaction`, `TxInternalDataSerializer`, `AccountKeySerializer`, or `AccountKeyRoleBased` — the check only exists in `blockchain/state_transition.go` and in `CheckInstallable`/`CheckUpdatable`, both of which run strictly after decoding.

### Impact Explanation
Because Go's stack-overflow-on-exhaustion aborts the process (it is not a recoverable `panic`), a single crafted `sendRawTransaction`/`kaia_sendRawTransaction` call (or a call to `kaia_decodeAccountKey`) from any unprivileged, unauthenticated public-RPC caller can crash the entire node process. This is a network-wide denial-of-service primitive reachable with a single transaction submission, satisfying the "gasless user / public RPC caller" reachability criterion, and matches the severity class of the referenced advisory (process abort, not catchable).

### Likelihood Explanation
High likelihood: the attack requires no special privileges, funds, signature validity (an unsigned/garbage-signed decode still exercises the recursive decoder up to the signature check step), or network position — just a crafted byte string reaching `rlp.DecodeBytes`/`UnmarshalBinary` for a `TxTypeAccountUpdate`-family transaction or the `DecodeAccountKey` API. Building a several-thousand-level-deep nested `AccountKeyRoleBased` RLP blob is straightforward and small (similar order of magnitude to the ~21 KB PDF PoC in the report).

### Recommendation
Add an explicit recursion/nesting depth limit enforced *during* decoding, not only after decoding completes:
- Track and bound nesting depth in `AccountKeySerializer.DecodeRLP` / `AccountKeyRoleBased.DecodeRLP` (e.g., pass a depth counter or use `rlp.Stream`'s list nesting count) and return an error once a small max depth (e.g., 1, since role-based keys are documented as non-nestable) is exceeded.
- Alternatively/also, add a generic maximum list-nesting depth to the `rlp` decoder itself (`Stream.List`) so any consumer benefits from bounded recursion regardless of call type.

### Proof of Concept
Conceptually: construct RLP bytes for an `AccountKeySerializer` where `keyType = AccountKeyTypeRoleBased` and its `key` payload is itself `[[<AccountKeyTypeRoleBased-encoded-blob>]]`, nested N (~10,000+) times, i.e. `RoleBased([RoleBased([RoleBased([...])])])`. Wrap this as the `AccountKey` field of a `TxTypeAccountUpdate` transaction (unsigned bytes are sufficient to reach the decoder), RLP-encode the transaction, and submit it via:
```
kaia_sendRawTransaction(<encoded_tx_hex>)
```
or directly via:
```
kaia_decodeAccountKey(<encoded_accountkey_hex>)
```
Decoding recurses once per nesting level through `AccountKeyRoleBased.DecodeRLP` → `AccountKeySerializer.DecodeRLP` → `rlp.DecodeBytes`, exhausting the goroutine stack and aborting the node process before `ErrNestedCompositeType` validation is ever reached.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (a *AccountKeyRoleBased) CheckUpdatable(newKey AccountKey, currentBlockNumber uint64) error {
	if newKey, ok := newKey.(*AccountKeyRoleBased); ok {
		lenOldKey := len(*a)
		lenNewKey := len(*newKey)
		// If no key is to be replaced, it is regarded as a fail.
		if lenNewKey == 0 {
			return kerrors.ErrZeroLength
		}
		// Do not allow undefined roles.
		if lenNewKey > (int)(RoleLast) {
			return kerrors.ErrLengthTooLong
		}
		for i := range lenNewKey {
			switch {
			// A composite key is not allowed.
			case (*newKey)[i].IsCompositeType():
				return kerrors.ErrNestedCompositeType
			// If newKey is longer than oldKey, init the new attributes.
			case i >= lenOldKey:
				if err := (*newKey)[i].CheckInstallable(currentBlockNumber); err != nil {
					return err
				}
			// Do nothing for AccountKeyTypeNil
			case (*newKey)[i].Type() == AccountKeyTypeNil:

			// Check whether the newKey is replacable or not
			default:
				if err := CheckReplacable((*a)[i], (*newKey)[i], currentBlockNumber); err != nil {
					return err
				}
			}
		}
		return nil
	}
	// Update is not possible if the type is different.
	return kerrors.ErrDifferentAccountKeyType
}

	if err := s.Decode(&serializer.keyType); err != nil {

func decodeListArray(s *Stream, val reflect.Value, elemdec decoder) error {
	if _, err := s.List(); err != nil {
		return wrapStreamError(err, val.Type())
	}
	vlen := val.Len()
	i := 0
	for ; i < vlen; i++ {
		if err := elemdec(s, val.Index(i)); err == EOL {
			break
		} else if err != nil {
			return addErrorContext(err, fmt.Sprint("[", i, "]"))
		}
	}
	if i < vlen {
		return &decodeError{msg: "input list has too few elements", typ: val.Type()}
	}
	return wrapStreamError(s.ListEnd(), val.Type())
}
