### Title
Serialized `ReceivedOutput` trusts an unauthenticated offset/outpoint pair, enabling signing of spends never authorized by the scanner - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to relying on a cookie without integrity checking, `ReceivedOutput::read` deserializes an attacker-malleable `(offset, TxOut, OutPoint)` triple with no binding between them and no proof the output was ever produced by `Scanner::scan_transaction`. Downstream, `SignableTransaction::multisig` authenticates only the *internal consistency* of the tuple (`p2tr_script_buf(key + offset·G) == prevouts[i].script_pubkey`), never that the `outpoint`/`TxOut` corresponds to a real UTXO the scanner actually reported. An untrusted serialized `ReceivedOutput` therefore drives the FROST `TransactionSignMachine` to sign Taproot spends the wallet pipeline never legitimately observed.

### Finding Description
`ReceivedOutput` is the value a `Scanner` produces when it sees a matching `script_pubkey`. It stores the spend offset, the `TxOut`, and the `OutPoint` as three independent fields [1](#0-0) . `ReceivedOutput::read` accepts all three verbatim — `offset` via `Secp256k1::read_F`, then `TxOut` and `OutPoint` via consensus decode — with no checksum, MAC, key commitment, or re-verification that `offset` matches the key whose script is in `output` [2](#0-1) . The scanner itself only ever populates these coherently via `scan_transaction` [3](#0-2) , but the serialized form is a plain byte blob (`serialize`/`write` emit raw fields with no authentication tag) [4](#0-3) .

On the spend side, `SignableTransaction::multisig` checks per input `i` that `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey` [5](#0-4) . This proves the forged `offset` and forged `script_pubkey` are consistent with each other — it does **not** prove the `outpoint` exists, that the `TxOut` (amount/script) matches the real prevout, or that the scanner produced this record. `TransactionSignMachine::sign` then signs `taproot_key_spend_signature_hash(i, Prevouts::All(&prevouts), Default)` for every supplied input [6](#0-5) .

An unprivileged party who can feed bytes to `ReceivedOutput::read` (the format is trivially constructible: `offset || TxOut || OutPoint`) can therefore:

1. Pick offset `o` and compute `script = p2tr_script_buf(group_key + o·G)` — all public.
2. Set `outpoint` to a **real, still-unspent UTXO** paying that script (e.g., a known Serai deposit they want re-spent/diverted, or a low-value Serai output), with `TxOut` forged to match consensus reality or not, as needed.
3. Supply this blob where the wallet expects a scanner-produced `ReceivedOutput`.

Because `multisig()`'s check passes for such a tuple, the threshold signers produce a valid FROST signature authorizing a spend of that UTXO under whatever payments/change the surrounding call specified — a signature on a spend the scan/authorization layer never vouched for. This is exactly the cookie pattern: a stored/untrusted value consumed as if it were authentic because nothing verifies its provenance.

### Impact Explanation
The wallet treats the serialized record's claims (which output, which key offset, what value) as authoritative. Where `ReceivedOutput` bytes cross a trust boundary — persisted scans reloaded on reboot, records relayed between components, or any integration feeding externally-supplied bytes into `read` — an attacker gains the ability to enqueue spends of arbitrary known Serai UTXOs (consensus-valid signatures the threshold will emit), or to poison the spend set so honest plans fail (mismatched prevouts → invalid TXs, or `NotEnoughFunds`/fee distortions from forged `value`s). In the Serai processor pipeline specifically, outputs scanned on one network feed `prepare_send`/`signable_transaction`; a forged offset in a persisted record also corrupts `Output::key()` derivation (`key = script_key − offset·G`), which is used to decide which multisig owns an output [7](#0-6) .

### Likelihood Explanation
Medium. Exploitation requires attacker-controlled bytes reaching `ReceivedOutput::read`, which is plausible wherever scan results are persisted or transported (it is a `std`-gated serialization API explicitly meant for storage/transfer), but not reachable purely from on-chain data — the on-chain scan path constructs `ReceivedOutput` internally. Impact when reachable is high (unauthorized valid signatures on multisig spends), and the missing integrity binding is unconditional.

### Recommendation
Bind the fields cryptographically at creation time: have `Scanner::scan_transaction` produce a commitment/MAC over `(offset, TxOut, outpoint, group_key)` (e.g., `H(dst || key || offset || serialize(output) || serialize(outpoint))` stored in `ReceivedOutput`), and verify it in `read` before returning. Additionally, in `SignableTransaction::new`/`multisig`, re-derive `p2tr_script_buf(key + offset·G)` and compare against the *scanned* script — the current check only enforces self-consistency of attacker-chosen fields, so it should be complemented by checking the `outpoint` against the actual UTXO set (or at minimum hashing the prevout into the signed-message transcript as a sanity layer).

### Proof of Concept
```rust
// Attacker-known: multisig group key K (public), a real unspent Serai UTXO
// at outpoint P paying p2tr(K + o*G) for offset o (e.g., registered offset
// script, or the base script p2tr(K) with o = 0).
let offset = Scalar::ZERO;                       // base-address output
let forged = {
    let mut buf = offset.to_bytes().to_vec();    // Secp256k1::read_F input
    buf.extend(serialize(&TxOut {                // the real prevout's TxOut
        value: real_utxo_value,
        script_pubkey: p2tr_script_buf(group_key).unwrap(),
    }));
    buf.extend(serialize(&real_outpoint));       // OutPoint the attacker chose
    buf
};
let ro = ReceivedOutput::read(&mut forged.as_slice()).unwrap(); // accepted unchecked

// multisig() check passes: p2tr_script_buf(offset(o).group_key()) == script_pubkey
let stx = SignableTransaction::new(vec![ro], &payments, change, None, fee).unwrap();
let machine = stx.multisig(&keys).unwrap();      // Some(...) — forged input accepted
// sign() emits valid FROST signature shares over the attacker-selected spend.
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
