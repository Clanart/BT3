### Title
Unauthenticated tx-sender JSON-RPC `send_tx` Endpoint Allows Any Reachable Caller to Inject Arbitrary Transactions and Exhaust Operator Fee Wallet — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The tx-sender JSON-RPC server (`start_jsonrpc_server`) exposes `send_tx` (and `send_citrea_tx`) with **zero authentication**. When the server is bound to `0.0.0.0` — as configured in the provided Docker deployment files — any process that can reach the port can inject arbitrary Bitcoin transactions into the tx-sender queue. The tx-sender will then attempt to broadcast and fee-bump those transactions using the operator's fee-paying UTXOs. Sustained injection exhausts the fee wallet, causing legitimate bridge transactions (kickoff, payout, challenge, watchtower-challenge) to fail to confirm within their timelocked windows, which exposes the operator to slashable collateral loss.

---

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds a plain `jsonrpsee` HTTP server with no authentication layer:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
    ...
module.register_async_method("send_tx", |params, client, _| async move {
    let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;
    ...
    client.insert_try_to_send(...).await
``` [1](#0-0) 

There is no token, IP allowlist, mTLS, or any other caller-identity check before `insert_try_to_send` is called. The bind address is configurable as `127.0.0.1` or `0.0.0.0`: [2](#0-1) 

The Docker deployment configurations set `TX_SENDER_JSONRPC_BIND=0.0.0.0`, making the server reachable from any container on the Docker network (and potentially from the host if the port is mapped): [3](#0-2) 

The `InsertTryToSendParams` struct accepted by `send_tx` includes `fee_paying_type` (CPFP or RBF), `rbf_signing_info`, `cancel_outpoints`, and `activate_outpoints`: [4](#0-3) 

When `fee_paying_type = CPFP`, the tx-sender creates a child transaction spending one of the operator's fee UTXOs to bump the injected transaction. When `fee_paying_type = RBF`, it re-signs the transaction at a higher fee rate using the operator's key. Both paths consume operator-controlled UTXOs.

The gRPC servers for verifier and operator are protected by mTLS with the `OnlyAggregatorAndSelf` interceptor when `client_verification = true`: [5](#0-4) [6](#0-5) 

No equivalent protection exists for the JSON-RPC server.

---

### Impact Explanation

The tx-sender manages all time-sensitive bridge transactions: `Kickoff`, `Challenge`, `WatchtowerChallenge`, `Payout`, `Reimburse`, `AssertTimeout`, `DisproveTimeout`, and others: [7](#0-6) 

Each of these has a Bitcoin timelock deadline. If the fee wallet is exhausted by attacker-injected garbage transactions, the tx-sender cannot fee-bump legitimate bridge transactions. Specifically:

- **Kickoff / Challenge / WatchtowerChallenge**: If the operator's kickoff or challenge transaction does not confirm before the `OPERATOR_CHALLENGE_TIMEOUT_TIMELOCK` (144 blocks in regtest, ~1 day on mainnet), the operator's collateral UTXO becomes claimable by the challenger path, resulting in direct loss of operator collateral.
- **Payout / Reimburse**: Failure to confirm the payout transaction within the reimbursement window means the operator does not recover the BTC it fronted for the withdrawal.

The `cancel_outpoints` and `cancel_txids` fields in `InsertTryToSendParams` are dependency conditions for the *newly inserted* transaction (they do not directly cancel existing queued transactions), so the primary attack vector is fee-wallet exhaustion rather than direct cancellation of existing entries. [8](#0-7) 

---

### Likelihood Explanation

The JSON-RPC feature is explicitly documented and shipped with a standalone binary and Docker compose files. The `0.0.0.0` binding appears in the provided Docker deployment configurations. Any process co-located on the Docker network — including a compromised co-tenant container, a misconfigured service, or a directly exposed port — can reach the endpoint with a plain HTTP POST. No credentials, certificates, or prior knowledge of bridge state are required. The attacker only needs to know the port number (default `3030` per `run.sh`) and the JSON-RPC method name `send_tx`. [9](#0-8) 

---

### Recommendation

1. **Add authentication to the JSON-RPC server.** The simplest approach is a shared-secret bearer token checked in a middleware layer before any method dispatch. Alternatively, restrict the server to Unix-domain sockets (filesystem permissions provide access control) and remove the `0.0.0.0` binding option entirely.
2. **Enforce `127.0.0.1`-only binding in production.** Remove `0.0.0.0` as a valid value for `TX_SENDER_JSONRPC_BIND` in production Docker configurations, or add a firewall rule that blocks external access to the JSON-RPC port.
3. **Rate-limit and validate inserted transactions.** Even with auth, add a per-caller rate limit and reject transactions whose inputs are not owned by the operator's wallet.

---

### Proof of Concept

With the tx-sender running and `TX_SENDER_JSONRPC_BIND=0.0.0.0`, `TX_SENDER_JSONRPC_PORT=3030`, an attacker on the same Docker network executes:

```bash
# Craft a minimal syntactically valid transaction (any hex-encoded Bitcoin tx)
RAW_TX_HEX="<hex of any valid Bitcoin transaction>"

# Flood the queue — no credentials required
for i in $(seq 1 10000); do
  curl -s -X POST http://<tx-sender-ip>:3030 \
    -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":$i,\"method\":\"send_tx\",\"params\":[{
      \"tx_metadata\": null,
      \"signed_tx_hex\": \"$RAW_TX_HEX\",
      \"fee_paying_type\": \"CPFP\",
      \"rbf_signing_info\": null,
      \"cancel_outpoints\": [],
      \"cancel_txids\": [],
      \"activate_txids\": [],
      \"activate_outpoints\": []
    }]}" &
done
```

Each accepted call inserts a row into `tx_sender_try_to_send_txs` and schedules a CPFP child transaction. The tx-sender loop processes all queued entries on each tick, spending a fee UTXO per entry. After the fee wallet UTXOs are exhausted, legitimate bridge transactions stop receiving fee bumps and fail to confirm within their timelock windows. [10](#0-9) [11](#0-10)

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

pub fn spawn_txsender_loop(config: TxSenderConfig) -> tokio::task::JoinHandle<()> {
    tokio::spawn(async move {
        let poll_delay = Duration::from_millis(config.poll_delay_ms);
        #[cfg(feature = "json-rpc")]
        let mut jsonrpc_handle: Option<crate::jsonrpc::server::TxSenderJsonRpcServer> = None;

        loop {
            let init_res: Result<TxSender, BridgeError> = async {
                let tx_sender = TxSender::new(config.clone()).await?;

                #[cfg(feature = "json-rpc")]
                if let Some(rpc_cfg) = config.jsonrpc.clone() {
                    // If we previously had a server, stop it before re-binding.
                    if let Some(old) = jsonrpc_handle.take() {
                        let handle = old.stop();
                        let _ = handle.stop();
                    }

                    let bind: std::net::IpAddr = rpc_cfg.bind.parse().map_err(|e| {
                        BridgeError::ConfigError(format!("Invalid TX_SENDER_JSONRPC_BIND: {e}"))
                    })?;
                    let addr = std::net::SocketAddr::new(bind, rpc_cfg.port);

                    let server =
                        crate::jsonrpc::server::start_jsonrpc_server(tx_sender.client(), addr)
                            .await?;
                    jsonrpc_handle = Some(server);
                }

                Ok(tx_sender)
            }
            .await;

            let tx_sender = match init_res {
                Ok(x) => x,
                Err(e) => {
                    tracing::error!("txsender init failed (will retry): {e:?}");
                    tokio::time::sleep(Duration::from_secs(5)).await;
                    continue;
                }
            };

            let mut internal = TxSenderTaskInternal::new(tx_sender);
            loop {
                if let Err(e) = internal.run_once().await {
                    tracing::error!("txsender loop iteration failed: {e:?}");
                }
                tokio::time::sleep(poll_delay).await;
            }
        }
    })
