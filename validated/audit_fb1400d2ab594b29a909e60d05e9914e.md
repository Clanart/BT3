### Title
Background GitHub-repository refresh silently rewrites the local `origin` remote based on API `clone_url` - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
Similar to the Tap contract silently updating its `Controller` reference without a properly gated permission, GitHub Desktop silently rewrites a repository's `origin` remote URL as a side effect of a routine background refresh, using data returned by the GitHub API — without ever asking the user to confirm the change. The only manual, user-consented path for changing a remote URL is the Repository Settings dialog [1](#0-0) , but `updateRemoteUrl` bypasses this UI entirely and calls the exact same underlying primitive (`gitStore.setRemoteURL`) automatically.

### Finding Description
`repositoryWithRefreshedGitHubRepository` is invoked as part of normal background repository refresh flows (e.g. after account changes, periodic refresh). It matches the repo's current remote to a GitHub account purely by hostname via `matchGitHubRepository`, then fetches fresh repository data from the API for that `owner/name`: [2](#0-1) 

If a `GitHubRepository` association already exists, it unconditionally calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`, which will overwrite the local `origin` remote's URL with `apiRepo.clone_url` whenever:
- the URL protocol is unchanged, and
- the previously-known GitHub `cloneURL` still matches the current remote, and
- the new `clone_url` from the API differs from the current remote [3](#0-2) 

The actual URL mutation is performed through `gitStore.setRemoteURL` → `setRemoteURL` (git plumbing `remote set-url`), the exact same function used by the manual settings-dialog flow: [4](#0-3) [5](#0-4) 

The matching logic in `urlMatchesRemote` only requires the **hostname** to stay the same; it does not require the **owner** to remain the same: [6](#0-5) 

This means any actor with the ability to change a repository's `owner/name` on the API side (e.g. an org admin renaming/transferring a repository, or a repository being renamed by any user with admin rights on that specific GitHub repo — not on the victim's machine) causes every Desktop client tracking that repo to have its `origin` remote silently redirected to the new location on the next background refresh, with zero user prompt or confirmation. The invariant broken is: "changing where the user's commits get pushed requires explicit user consent," which the app enforces in the Settings UI but not in this background-triggered path — mirroring the Tap bug where the update capability existed but wasn't gated behind a proper authorization/consent boundary.

### Impact Explanation
Silently redirecting `origin` corrupts the destination of future `git push`/`git fetch` operations without the user's knowledge, matching the explicitly in-scope impact category "silent corruption of what the user commits or pushes." A user could unknowingly push commits, including private code or credentials embedded in history, to a repository location they never approved, or could later be fetching from/merging code from an unexpected source. Because the change happens transparently during a routine background refresh, users have no visual indication their remote has moved (aside from re-opening the settings dialog after the fact).

### Likelihood Explanation
The trigger only requires an actor to control the GitHub API's repository object for the endpoint the app is already authenticated against (rename/transfer a repository), not any local or credential compromise — this fits the allowed "attacker controls a GitHub API object" primitive. It does not require admin rights on the victim's machine, malware, or leaked credentials. Whether this reaches full "attacker-controlled arbitrary host" severity is limited by the hostname check in `urlMatchesRemote`, so the practical impact is scoped to same-host owner/name redirection (e.g., cross-account repository transfers on the same GitHub instance), which somewhat reduces severity but does not eliminate the silent-consent bypass.

### Recommendation
Do not silently rewrite `origin`/tracked remote URLs from background API refreshes. When `updateRemoteUrl` detects a legitimate `clone_url` change from the API, surface a confirmation dialog (reusing the existing Repository Settings remote-change UI/dispatcher path) so the user explicitly approves before `setRemoteURL` is invoked, consistent with how manual remote changes are already gated in `repository-settings.tsx`.

### Proof of Concept
1. User A clones `https://github.com/org/repo` in GitHub Desktop; Desktop records `GitHubRepository.cloneURL` for that repo.
2. An org admin (or the repo owner) renames/transfers the repository to `https://github.com/org/repo-renamed` (or a different owner under the same GitHub host) via the GitHub website/API.
3. On the next background refresh (e.g. app restart, account-change refresh, or periodic refresh calling `repositoryWithRefreshedGitHubRepository`), Desktop calls `api.fetchRepository(owner, name)`, obtains the new `clone_url`, and — because `protocolsMatch` and `remoteUrlUnchanged` hold and `urlsMatch` is false — invokes `updateRemoteUrl` → `gitStore.setRemoteURL` → `git remote set-url origin https://github.com/org/repo-renamed`, all without any prompt shown to User A.
4. User A's next `git push`/`git fetch` silently targets the new location, with no dialog ever having asked for consent, unlike the explicit user-driven flow in `repository-settings.tsx`.

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
