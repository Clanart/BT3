## Finding: Valid

### Title
Reward misattribution — `on_executed` credits every `StateMachineUpdated` event in a batch to the signer of `messages[0]` only - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`Pallet::on_executed` derives the sole reward beneficiary for an entire batch from `messages[0]`, then pays out for *every* `StateMachineUpdated` event produced by the batch — including events produced by other, independently-verified `Message::Consensus` entries in the same batch that were not signed by that account.

### Finding Description
`pallet_ismp::Pallet::execute` processes every `Message` in a submitted batch independently via `handle_incoming_message`, accumulates the resulting events from *all* messages into a single flat `Vec<Event>`, and calls the configured `FeeHandler::on_executed` exactly once for the whole batch: [1](#0-0) 

Each `Message::Consensus` is verified on its own merits by `update_client`/`verify_consensus` (e.g. GRANDPA/BEEFY signature checks) — the `signer` field on `ConsensusMessage` is not cryptographically tied to that verification at all; it is only checked later, and only for reward bookkeeping: [2](#0-1) 

In `pallet-consensus-incentives`, `on_executed` looks *only* at `messages[0]` to recover a `relayer_account`, then folds every `StateMachineUpdated` event across the entire batch (regardless of which message produced it) into `highest_per_state_machine`, and pays out a reward per distinct `StateMachineId` — all to that single account derived from `messages[0]`: [3](#0-2) 

Because `handle_unsigned` is a permissionless, unsigned extrinsic accepting an arbitrary `Vec<Message>`, and because the `signer` field of any `ConsensusMessage` beyond index 0 is never consulted, an attacker can:
1. Craft their own self-signed `Message::Consensus` for state machine A as `messages[0]`.
2. Append any other independently-valid `Message::Consensus` for an unrelated state machine B (e.g. a proof observed as public, not-yet-included data) as `messages[1]`.
3. Submit the batch via `handle_unsigned`.

Both A's and B's `StateMachineUpdated` events land in the same `events` vector passed to `on_executed`, and both rewards are paid to the account recovered from `messages[0]`'s signature alone, even though the attacker did not sign/produce B's message.

### Impact Explanation
This breaks the intended invariant that the `relayer_account` passed into `process_message` must correspond to the specific relayer who produced that state machine's update. An attacker can siphon the treasury-funded `RelayerRewarded` payout and `ReputationAsset` mint for state machines they did not genuinely deliver a signed contribution for, simply by bundling additional valid consensus messages into their own batch. This is a wrong-beneficiary accounting break in a live incentive/treasury flow.

### Likelihood Explanation
Likelihood is bounded by two practical requirements: (1) the batch must contain more than one `Message::Consensus`, each independently valid on its own proof-verification terms, and (2) the attacker must be the one to get the bundled transaction included first (i.e., include a not-yet-processed valid proof for the other state machine). Requirement (2) overlaps with inclusion/ordering ("who submits first") dynamics, but the underlying defect — `on_executed` never checking anything beyond `messages[0]` — is a pure logic bug independent of any race, and is trivially exploitable whenever a batch bundles more than one consensus update.

### Recommendation
`on_executed` should attribute each `StateMachineUpdated` event to the relayer account recovered from the specific `Message::Consensus` that produced it (e.g. by keeping the events grouped per source message during `execute`, or by having `handle_incoming_message`/`MessageResult::ConsensusMessage` carry the originating message's signer alongside its events) rather than assuming a single signer for the whole batch.

### Proof of Concept
1. Configure `StateMachinesCostPerBlock` for state machines A and B.
2. Build `messages = vec![msg_A (Message::Consensus, valid proof for A, signer = attacker_key), msg_B (Message::Consensus, valid but unrelated proof for B, signer = some_other_key or irrelevant)]`.
3. Call `<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(messages, events)` where `events` contains `StateMachineUpdated` for both A and B (as produced by `execute`).
4. Assert: `RelayerRewarded` is emitted twice, both with `relayer == attacker_account` (derived solely from `msg_A`'s signature), even though `msg_B` was not signed by the attacker — as shown by `messages.get(0)` being the only message inspected in `impls.rs` lines 112-122, while the reward loop at lines 147-156 iterates over `highest_per_state_machine` (built from the full `events` vector) unconditionally using that single `relayer_account`. [4](#0-3)

/// This function handles verification of consensus messages for consensus clients
pub fn update_client<H>(host: &H, msg: ConsensusMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,
{
	let consensus_client_id = host.consensus_client_id(msg.consensus_state_id).ok_or(
		Error::ConsensusStateIdNotRecognized { consensus_state_id: msg.consensus_state_id },
	)?;
	let consensus_client = host.consensus_client(consensus_client_id)?;
	let trusted_state = host.consensus_state(msg.consensus_state_id)?;
	host.is_consensus_client_frozen(msg.consensus_state_id)?;
	host.is_expired(msg.consensus_state_id)?;

	let (new_state, intermediate_states) = consensus_client.verify_consensus(
		host,
		msg.consensus_state_id,
		trusted_state,
		msg.consensus_proof,
	)?;
	host.store_consensus_state(msg.consensus_state_id, new_state)?;

				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted

			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
