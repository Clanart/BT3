### The broken equality

`recoverPolynomialCoeffs` only enforces a **lower bound** on the number of supplied cells: [3](#0-2) 

There is no upper bound / consistency check. It then places attacker-controlled cell values at the corresponding positions of `extendedBlob` and hands it to `RecoverPolynomialCoefficients`: [4](#0-3) 

### Why the invariant fails

`RecoverPolynomialCoefficients` implements erasure decoding via the vanishing-polynomial trick: it builds `Z(x)` with roots at exactly the *missing* indices, computes `E(x) = data(x)·Z(x)` in evaluation form, inverse-FFTs, divides out `Z(x)` on a coset, and then **unconditionally truncates** the result to `numScalarsInDataWord` coefficients: [5](#0-4) 

Mathematically, `Z | E` always holds (since `E` has zeros exactly at `Z`'s roots), so `Q = E/Z` has degree `≤ N-1-e` where `e` = number of missing scalars. When the attacker supplies **more cells than the minimum threshold** (`e < N-k`, which is legal since only `len(cellIDs) < NumBlocksNeededToReconstruct()` is rejected — see the lower-bound-only check above), `deg(Q)` can exceed `k-1 = ScalarsPerBlob-1`. The blind truncation at line 146 then discards genuine high-order coefficients of `Q`.

For honest/consistent cell data (real evaluations of a degree-`<ScalarsPerBlob` polynomial) this truncation is provably lossless, because `deg(D) < k` regardless of `e`. But for **attacker-crafted cell bytes that pass field-element deserialization but are not evaluations of any degree-`<ScalarsPerBlob` polynomial**, `Q`'s true degree generically exceeds `k-1` whenever `e < N-k`, so truncation corrupts the polynomial, and re-evaluating it (via `computeCellsFromPolyCoeff`) no longer reproduces the attacker's originally supplied cells at their own `cellIDs` positions.

Concretely: an attacker can call `RecoverCells` with **all `CellsPerExtBlob` cell IDs supplied** (`e = 0` missing). Then `missingCellIds` is empty, `Z(x) = 1` (a constant), so `RecoverPolynomialCoefficients` degenerates into simply IFFT-ing the raw attacker-supplied evaluations and keeping only the first half of the coefficients — an arbitrary lossy truncation with no error, no consistency check, and no re-verification against the supplied cells before returning. [6](#0-5) [7](#0-6) 

None of the deserialization guards (`deserializeCell`, `isAscending`, the `cellID >= CellsPerExtBlob` check, or the minimum-cell-count check) verify that the supplied cells are actually consistent with a degree-`<ScalarsPerBlob` polynomial, so the divergence is never caught.

### Title
`recoverPolynomialCoeffs` truncates the reconstructed polynomial without verifying `recovered[cellIDs[i]] == cells[i]`, allowing crafted over-threshold cell sets to silently diverge from supplied cells - (File: `api_eip7594.go`, `internal/erasure_code/erasure_code.go`)

### Summary
`Context.RecoverCells`/`RecoverCellsAndComputeKZGProofs` call `recoverPolynomialCoeffs`, which only checks a lower bound on the number of supplied cells and never verifies that the reconstructed polynomial actually reproduces the caller-supplied cell values. When an attacker supplies more cells than the minimum required threshold with field-element-valid but polynomial-inconsistent contents, `DataRecovery.RecoverPolynomialCoefficients`'s unconditional truncation to `numScalarsInDataWord` coefficients silently discards information, so `recovered[cellIDs[i]] != cells[i]` for the supplied indices, with no error returned.

### Finding Description
The broken equality is `recovered[cellIDs[i]] == cells[i]` for all supplied `cellIDs[i]`. The reachable path is `Context.RecoverCells(cellIDs, cells, numGoroutines)` (`api_eip.go:8`) → `ctx.recoverPolynomialCoeffs(cellIDs, cells)` (`api_eip7594.go:97`) → `ctx.dataRecovery.RecoverPolynomialCoefficients(extendedBlob, missingCellIds)` (`internal/erasure_code/erasure_code.go:110`). The only length guard is `len(cellIDs) < ctx.dataRecovery.NumBlocksNeededToReconstruct()` (a lower bound), with no upper bound or cross-consistency check on the cell contents themselves. `RecoverPolynomialCoefficients` computes `Q(x) = E(x)/Z(x)` where `Z(x)` vanishes exactly at the missing indices, and always truncates the result to `numScalarsInDataWord` coefficients regardless of `Q`'s true degree. This truncation is lossless only when the input evaluations are consistent with a genuine degree-`<ScalarsPerBlob` polynomial. If the attacker supplies more cells than the minimum threshold (e.g. all `CellsPerExtBlob` cells, giving zero erasures, `Z(x)=1`) with arbitrary/inconsistent field elements, `Q`'s true degree exceeds `ScalarsPerBlob-1`, and the naive truncation drops real information, so `Q` evaluated back at the attacker's own supplied cell positions no longer equals the supplied cell values.

### Impact Explanation
`RecoverCells` and `RecoverCellsAndComputeKZGProofs` return a `polyCoeff`/derived cells and proofs that do not satisfy the documented invariant that recovered data must match supplied cells at the supplied indices. This is exactly the "emitted ... recovered data for the same input" mismatch class in the Immunefi High bucket: since c-kzg/consensus-spec implementations of the same recovery routine may reject or behave differently for over-threshold, inconsistent cell sets, this creates a client-split risk, and any downstream consumer trusting `RecoverCells`'s output as consistent with attacker-supplied cells (e.g. gossip validation, cell-level messaging per `api_eip.go`'s header comment) receives silently wrong data. The call is fully repeatable and deterministic per crafted input.

### Likelihood Explanation
No special privileges are required: any caller of the public `Context.RecoverCells`/`RecoverCellsAndComputeKZGProofs` API can supply `cellIDs`/`cells` of their choosing. The only precondition is supplying more cells than `NumBlocksNeededToReconstruct()` (i.e., more than 50% of `CellsPerExtBlob`) with cell contents that are valid field elements (pass `deserializeCell`) but not evaluations of a common low-degree polynomial — trivial to construct (e.g., all-cells-supplied with arbitrary/random per-cell scalars). Cost is a single library call; the bug reproduces every time.

### Recommendation
After computing the recovered polynomial coefficients, re-evaluate them at the supplied `cellIDs` and assert the recovered evaluations equal the caller-supplied `cells` before returning success; alternatively, bound `len(cellIDs)` so that the reconstruction is only attempted with exactly the erasure count needed for the truncation to be lossless, or perform an explicit degree check on `Q` before truncating and error out if `deg(Q) >= numScalarsInDataWord`.

func TestRecoverCellsInvariantBreaks(t *testing.T) {
    ctx, err := NewContext4096Secure()
    if err != nil {
        t.Fatal(err)
    }

    // Supply ALL CellsPerExtBlob cells (zero missing -> e=0, more than the
    // NumBlocksNeededToReconstruct() lower bound), with cell contents that are
    // valid field elements but NOT evaluations of a real degree<ScalarsPerBlob
    // polynomial (e.g., all-ones cells).
    cellIDs := make([]uint64, CellsPerExtBlob)
    cells := make([]*Cell, CellsPerExtBlob)
    for i := range cellIDs {
        cellIDs[i] = uint64(i)
        var c Cell
        for j := 0; j < scalarsPerCell; j++ {
            // fill with a fixed nonzero byte pattern that is a valid field element
            // but inconsistent across cells with any single low-degree polynomial
            c[j*32+31] = byte(i + j + 1)
        }
        cells[i] = &c
    }

    recovered, err := ctx.RecoverCells(cellIDs, cells, 0)
    if err != nil {
        t.Fatalf("guard rejected input unexpectedly: %v", err)
    }

    // Assert both sides of the claimed invariant: recovered[cellIDs[i]] == cells[i]
    mismatch := false
    for i, id := range cellIDs {
        if *recovered[id] != *cells[i] {
            mismatch = true
            t.Logf("mismatch at cellID %d: recovered != supplied cell", id)
        }
    }
    if !mismatch {
        t.Fatal("expected invariant violation, but recovered cells matched supplied cells")
    }
}

func (ctx *Context) recoverPolynomialCoeffs(cellIDs []uint64, cells []*Cell) ([]fr.Element, error) {
	if len(cellIDs) != len(cells) {
		return nil, ErrNumCellIDsNotEqualNumCells
	}

	// Check that the cell Ids are ordered (ascending)
	if !isAscending(cellIDs) {
		return nil, ErrCellIDsNotOrdered
	}

	// Check that each CellId is less than CellsPerExtBlob
	for _, cellID := range cellIDs {
		if cellID >= CellsPerExtBlob {
			return nil, ErrFoundInvalidCellID
		}
	}

	// Check that we have enough cells to perform reconstruction
	if len(cellIDs) < ctx.dataRecovery.NumBlocksNeededToReconstruct() {
		return nil, ErrNotEnoughCellsForReconstruction
	}

	// Find the missing cell IDs and bit reverse them
	// So that they are in normal order
	missingCellIds := make([]uint64, 0, CellsPerExtBlob)
	for cellID := uint64(0); cellID < CellsPerExtBlob; cellID++ {
		if !slices.Contains(cellIDs, cellID) {
			missingCellIds = append(missingCellIds, (domain.BitReverseInt(cellID, CellsPerExtBlob)))
		}
	}

	// Convert Cells to field elements
	extendedBlob := make([]fr.Element, scalarsPerExtBlob)
	// for each cellId, we get the corresponding cell in cells
	// then use the cellId to place the cell in the correct position in the data(extendedBlob) array
	for i, cellID := range cellIDs {
		cell := cells[i]
		// Deserialize the cell
		cellEvals, err := deserializeCell(cell)
		if err != nil {
			return nil, err
		}
		// Place the cell in the correct position in the data array
		copy(extendedBlob[cellID*scalarsPerCell:], cellEvals)
	}
	// Bit reverse the extendedBlob so that it is in normal order
	domain.BitReverse(extendedBlob)

	return ctx.dataRecovery.RecoverPolynomialCoefficients(extendedBlob, missingCellIds)
}

func NewDataRecovery(blockErasureSize, numScalarsInDataWord, expansionFactor int) *DataRecovery {
	// Compute the number of scalars that will be in the codeword
	numScalarsInCodeword := numScalarsInDataWord * expansionFactor

	// Compute the total number of blocks that we will need to
	// represent the codeword
	totalNumBlocks := numScalarsInCodeword / blockErasureSize

	rootsOfUnityBlockErasureIndex := domain.NewDomain(uint64(totalNumBlocks))
	domainExtended := domain.NewDomain(uint64(numScalarsInCodeword))

	fftCoset := domain.FFTCoset{}
	fftCoset.CosetGen = fr.NewElement(7)
	fftCoset.InvCosetGen.Inverse(&fftCoset.CosetGen)
	domainExtendedCoset := domain.NewCosetDomain(domainExtended, fftCoset)

	return &DataRecovery{
		rootsOfUnityBlockErasureIndex: rootsOfUnityBlockErasureIndex,
		domainExtended:                domainExtended,
		domainExtendedCoset:           domainExtendedCoset,
		blockErasureSize:              blockErasureSize,
		numScalarsInCodeword:          numScalarsInCodeword,
		numScalarsInDataWord:          numScalarsInDataWord,
		expansionFactor:               expansionFactor,
		totalNumBlocks:                totalNumBlocks,
	}
}

func (dr *DataRecovery) constructVanishingPolyOnIndices(missingBlockErasureIndices []BlockErasureIndex) []fr.Element {
	// Collect all of the roots that are associated with the missing block erasure indices
	missingBlockErasureIndexRoots := make([]fr.Element, len(missingBlockErasureIndices))
	for i, index := range missingBlockErasureIndices {
		missingBlockErasureIndexRoots[i] = dr.rootsOfUnityBlockErasureIndex.Roots[index]
	}

	shortZeroPoly := vanishingPolyCoeff(missingBlockErasureIndexRoots)

	zeroPolyCoeff := make([]fr.Element, dr.numScalarsInCodeword)
	for i, coeff := range shortZeroPoly {
		zeroPolyCoeff[i*dr.blockErasureSize] = coeff
	}

	return zeroPolyCoeff
}

func (dr *DataRecovery) RecoverPolynomialCoefficients(data []fr.Element, missingIndices []BlockErasureIndex) ([]fr.Element, error) {
	zX := dr.constructVanishingPolyOnIndices(missingIndices)

	// Compute zX evaluations without mutating zX since we need zX later for a coset FFT
	zXForEval := make([]fr.Element, len(zX))
	copy(zXForEval, zX)
	dr.domainExtended.FftFr(zXForEval)
	zXEval := zXForEval

	if len(zXEval) != len(data) {
		return nil, errors.New("length of data and zXEval should be equal")
	}

	eZEval := make([]fr.Element, len(data))
	for i := 0; i < len(data); i++ {
		eZEval[i].Mul(&data[i], &zXEval[i])
	}

	dr.domainExtended.IfftFr(eZEval)
	dzPoly := eZEval

	dr.domainExtendedCoset.CosetFFtFr(zX)
	cosetZxEval := zX
	dr.domainExtendedCoset.CosetFFtFr(dzPoly)
	cosetDzEVal := dzPoly

	cosetQuotientEval := make([]fr.Element, len(cosetZxEval))
	cosetZxEval = fr.BatchInvert(cosetZxEval)

	for i := 0; i < len(cosetZxEval); i++ {
		cosetQuotientEval[i].Mul(&cosetDzEVal[i], &cosetZxEval[i])
	}

	dr.domainExtendedCoset.CosetIFFtFr(cosetQuotientEval)

	// Truncate the polynomial coefficients to the number of scalars in the data word
	polyCoeff := cosetQuotientEval[:dr.numScalarsInDataWord]
	return polyCoeff, nil
}
