### Title
Unbounded O(t²) Lagrange interpolation in `ThresholdKeys::read`/`new` enables small-input CPU DoS - (File: crypto/dkg/src/lib.rs)

### Summary
The Protego advisory is a CWE-1333/CWE-400 bug: an attacker-controlled string (`Disallow:` wildcards) is compiled into a computation whose cost is exponential in input size, freezing the caller. The structural analog in Serai is `ThresholdKeys::read` → `ThresholdKeys::new` → `Interpolation::interpolation_factor`, where a small serialized blob (bounded only by `u16`) triggers an O(t²) group-key computation — effectively a polynomial-time "backtracking" equivalent reachable purely from untrusted bytes.

### Finding Description
`ThresholdKeys::read` accepts `t`, `n`, and `i` as raw `u16`s and then constructs `ThresholdKeys::new` [1](#0-0) . `ThresholdKeys::new` computes `group_key` by summing `verification_shares[i] * interpolation_factor(i, &t)` for all `t` participants [2](#0-1) . For `Interpolation::Lagrange`, each `interpolation_factor` call is itself an O(t) loop over `included` (a scalar multiply, subtraction, and inversion per participant) [3](#0-2) . Total: O(t²) field operations plus `t` group multiplications, with `t = n` up to 65535 — roughly 4×10⁹ field operations and 65535 point multiplications, plus `t` modular inversions of O(t)-computed denominators, all from a ~2 MB serialized input (n × 32-byte scalars/points). Unlike the Protego regex this is quadratic rather than exponential, but it is the same class: attacker bytes control the iteration bound of a nested computation with no cap.

### Impact Explanation
Per the rules, `ThresholdKeys::read` is an accepted untrusted-bytes entry point. Any component that deserializes attacker-supplied `ThresholdKeys` (a coordinator/processor loading keys from a message or storage written by an untrusted source) can be stalled for a wall-clock period growing quadratically with `n`, with a single ~2 MB input — analogous to `can_fetch` freezing on a 60-byte URL in the report.

### Likelihood Explanation
Requires the serialized-keys path to accept attacker-controlled bytes; where that holds, trigger is trivial (one crafted input, `t = n = 0xFFFF`, interpolation tag `1`). No key knowledge or validator status is needed — only the ability to supply the bytes.

### Recommendation
Cap `n`/`t` at a protocol-meaningful bound inside `ThresholdParams::new`/`ThresholdKeys::read` (e.g., the actual validator-set size limit), or compute the group key via a single multiexponentiation over precomputed Lagrange denominators (O(t) field work + one multiexp), mirroring Protego's fix of eliminating the nested-backtracking structure rather than bounding input length alone.
