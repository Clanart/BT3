### Title
Unauthenticated OP_RETURN operator identity in Payout transactions permanently blocks honest-operator reimbursement - (File: `core/src/builder/transaction/operator_reimburse.rs`, `core/src/verifier.rs`)

### Summary
The `operator_xonly_pk` written into a `Payout` transaction's OP_RETURN output is never cryptographically bound to the party who actually funds the payout, nor is it validated against the withdrawal's registered operator set when synced from Bitcoin. Since the user's withdrawal signature uses `SinglePlusAnyoneCanPay` (committing only input 0 + output 0), any party who can obtain that signature/outpoint and front the fixed output amount can construct and broadcast their own `Payout` tx with an arbitrary `operator_xonly_pk`, permanently poisoning the withdrawal's DB record so no real operator's kickoff can ever match it.

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk` for withdrawal `i` is supposed to equal `kickoff_data.operator_xonly_pk` of the operator who actually funded output 0 of the mined payout tx. In practice, nothing enforces this equality.

- `create_payout_txhandler` builds the payout tx from an attacker-suppliable `operator_xonly_pk` parameter and signs only input 0 with `set_p2tr_key_spend_witness(&user_sig, 0)` [1](#0-0) . Because `in_signature.sighash_type` is `SinglePlusAnyoneCanPay`, the witness for input 0 stays valid no matter who appends extra funding inputs to cover the (fixed) output 0 amount — this is confirmed in `Operator::withdraw`, which relies on `fund_raw_transaction` with `add_inputs: Some(true)` to top up the tx after the single input/output is signed [2](#0-1) [3](#0-2) .
- The signature is verified only against `user_xonly_pk` and the sighash of input 0 — there is no check binding `operator_xonly_pk` in the OP_RETURN to the signer of any input, nor to a registered operator [4](#0-3) .
- When Bitcoin sync later observes any transaction spending the withdrawal UTXO, `update_finalized_payouts` blindly parses whatever 32 bytes sit in the first OP_RETURN as `XOnlyPublicKey::from_slice(...)` with no check that this key belongs to `deposit_data.get_operators()` [5](#0-4) , and persists it via `update_payout_txs_and_payer_operator_xonly_pk` [6](#0-5) .
- `Verifier::is_kickoff_malicious` then compares this stored key to `kickoff_data.operator_xonly_pk` of whichever real operator later sends a kickoff for that deposit; on mismatch it unconditionally returns `true` (malicious) [7](#0-6) .

Because the withdrawal outpoint can only be spent once, once any transaction with a bogus/self-chosen `operator_xonly_pk` is mined for it, the DB record for that withdrawal index is permanently fixed to that value, and no real operator's subsequent kickoff for that deposit can ever satisfy `operator_xonly_pk == kickoff_data.operator_xonly_pk`. The threat model explicitly grants the attacker the ability to "choose the bytes of a withdrawal UTXO, a Schnorr signature and its sighash flag, an OP_RETURN", which is exactly what this exploit uses.

None of the listed guards prevent this: `SECP.verify_schnorr` only authenticates input 0's spend by the user, not the OP_RETURN payload or funding inputs; `is_kickoff_malicious` is the mechanism that gets fooled, not a guard against it; there is no DB uniqueness/authorization constraint tying `payout_payer_operator_xonly_pk` to a member of `deposit_data.get_operators()`.

### Impact Explanation
The affected withdrawal's real operator (or any honest operator who fronts it) becomes permanently unable to pass `is_kickoff_malicious` for that deposit, meaning their `Reimburse` path is unreachable and their kickoff will be treated as malicious/challengeable, risking their bond/collateral being contested and their payout funds being unrecoverable via the intended reimbursement flow. This matches the Critical category "an honest operator permanently unable to be reimbursed." The blast radius is per-withdrawal: each exploited withdrawal index/deposit is poisoned independently, and the attack is repeatable across withdrawals if the attacker is willing to front the payout amount each time.

### Likelihood Explanation
The attacker must possess the user's `SinglePlusAnyoneCanPay` signature and withdrawal outpoint. The most direct instance of the attacker is the withdrawing user themselves (fully unprivileged, matches the threat model), who trivially has both. A third party could also obtain them via leakage from the off-chain hand-off to operators/aggregator. The attacker must front the full committed output-0 amount in BTC plus fees to win the race against honest operators — a real but bounded cost, and one explicitly allowed under the stated attacker capabilities (funding transactions, choosing signature/outpoint/OP_RETURN bytes). No verifier, operator, or aggregator privilege is required.

### Recommendation
Do not trust the OP_RETURN payload as operator identity proof. Either (a) require the operator's payout-crediting input itself to carry a signature under `operator_xonly_pk`, cryptographically binding the funder to the claimed identity, or (b) restrict `update_finalized_payouts`/`is_kickoff_malicious` to only credit an `operator_xonly_pk` that is a member of `deposit_data.get_operators()` for that deposit, and treat any other spend of the withdrawal UTXO explicitly as a "no eligible operator funded this withdrawal" case with a defined non-punitive resolution path (rather than flagging every subsequent honest kickoff as malicious).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
