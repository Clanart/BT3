### Title
Poisoned `ReceivedOutput` permanently bricks an entire `SignableTransaction` — an input whose stored offset doesn't reconstruct its `script_pubkey` makes `multisig()` return `None` forever, locking all inputs in the transaction - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The reported bug class is a two-part lockout: a privileged/special-cased check permanently denies a category of inputs (`_vestingCheck` returns 0 for team members), and a separate entry point fails to prevent those inputs from entering the denied state (`stake()` doesn't block team members). Serai's Bitcoin wallet exhibits the same shape: `ReceivedOutput::read` accepts any `(offset, script_pubkey)` pair without checking consistency (the missing guard), while `SignableTransaction::multisig` hard-fails the *entire* transaction — returning `None` — the first time a single input's offset fails to reproduce its `script_pubkey` (the permanent denial). One malformed input irreversibly locks every input in the transaction.

### Finding Description
`ReceivedOutput` is the unit of spendable funds: it stores a scalar `offset`, the `TxOut`, and the `OutPoint` (`networks/bitcoin/src/wallet/mod.rs:90-97`). Its deserializer performs no validation whatsoever — it reads an arbitrary scalar via `Secp256k1::read_F`, then a raw `TxOut` and `OutPoint`, and returns the pair verbatim (`networks/bitcoin/src/wallet/mod.rs:122-134`). Nothing establishes that `p2tr_script_buf(key + G * offset) == output.script_pubkey`, or even that the script is P2TR at all.

`SignableTransaction::new` ingests a `Vec<ReceivedOutput>` and stores the offsets and prevouts verbatim (`networks/bitcoin/src/wallet/send.rs:175-185,245-255`). The only consistency check happens later, inside `multisig`:

```rust
// networks/bitcoin/src/wallet/send.rs:273-285
pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
  let mut sigs = vec![];
  for i in 0 .. self.tx.input.len() {
    let offset = keys.clone().offset(self.offsets[i]);
    if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
      None?;
    }
    sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
  }
  Some(TransactionMachine { tx: self, sigs })
}
```

Two denial modes exist here, both permanent and both triggered by a single bad input:

1. `offset` doesn't reproduce the script → `None?` aborts construction of the machine for *all* inputs, not just the bad one. The transaction can never be signed; every `ReceivedOutput` bundled with the poisoned input is frozen, even though the honest inputs are perfectly spendable.
2. `offset` reproduces a point whose Y is odd → `p2tr_script_buf` returns `None` (`networks/bitcoin/src/wallet/mod.rs:80-86`) and the `?` on `Option` again bricks the whole transaction.

This mirrors the original bug exactly: just as `_vestingCheck` unconditionally returns 0 for team allocations, `multisig` unconditionally returns `None` for any transaction containing an inconsistent input; and just as `stake()` failed to prevent team members from entering the locked state, `ReceivedOutput::read` and `scan_transaction` fail to prevent inconsistent inputs from entering the `SignableTransaction` pipeline — `scan_transaction` admits outputs purely by `script_pubkey` lookup (`networks/bitcoin/src/wallet/mod.rs:199-214`) and `ReceivedOutput::read` admits arbitrary bytes with no consistency check.

### Impact Explanation
Any consumer that reconstructs `ReceivedOutput`s from serialized data (the documented purpose of `read`/`write`/`serialize`, e.g. DB round-trips or network-supplied bytes) can end up with an input set that can never be turned into a `TransactionMachine`. Because `multisig` aborts on the *first* mismatch rather than skipping or quarantining the bad input, one inconsistent `ReceivedOutput` permanently denies signing for every other input in the same transaction — funds the scanner reported as received become unspendable through the only signing path the crate provides. There is no recovery: `SignableTransaction` consumes the inputs at construction (`inputs.drain(..)`, send.rs:253) and the `None` result gives no indication of which input was faulty. This is "funds reported received that are not spendable," reachable by an unprivileged party feeding untrusted bytes to `ReceivedOutput::read`.

### Likelihood Explanation
The trigger requires only a `ReceivedOutput` whose `offset` field doesn't match its `script_pubkey` — a 32-byte scalar plus a serialized `TxOut`/`OutPoint`, fully attacker-controlled since `read` places no constraint linking them (`networks/bitcoin/src/wallet/mod.rs:122-134`). No threshold collusion, no malicious validator, and no protocol deviation is needed; the crash-by-`None` is deterministic whenever such an input is included in a spend. Whether a deployment exposes `ReceivedOutput::read` to untrusted data determines practical likelihood; the sink itself is in scope.

### Recommendation
Validate consistency at the boundary instead of at signing time: `ReceivedOutput` should carry, or be constructed with, the base key so that `read` (or a checked constructor) can verify `p2tr_script_buf(key + G * offset) == output.script_pubkey` and reject mismatches — the same guard `multisig` applies too late. Separately, `multisig` should identify the offending input (return an error rather than `None`) and callers should be able to exclude a single bad input without forfeiting the rest of the transaction.

// Conceptual PoC (no_std-compatible core types)
use k256::Scalar;
use bitcoin::{OutPoint, TxOut, Amount, ScriptBuf, consensus::serialize};
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction};

// Attacker-controlled bytes: a valid-looking TxOut paying to *any* P2TR script,
// paired with an offset that does NOT derive that script for the wallet's key.
let mut bytes = Vec::new();
bytes.extend(Scalar::from(0xdeadbeefu64).to_bytes());            // bogus offset
bytes.extend(serialize(&TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: victim_script_pubkey,                          // arbitrary P2TR script
}));
bytes.extend(serialize(&OutPoint { txid: some_txid, vout: 0 }));

// Accepted unconditionally — no consistency check
let poisoned = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// Bundled with honest inputs; construction succeeds
let tx = SignableTransaction::new(
    vec![honest_output_1, honest_output_2, poisoned],
    &payments, Some(change), None, fee_per_vbyte,
).unwrap();

// Permanent denial: p2tr_script_buf(key + G*0xdeadbeef) != victim_script_pubkey
// => entire transaction can never produce a TransactionMachine;
// honest_output_1 and honest_output_2 are locked with it.
assert!(tx.multisig(&keys).is_none());

    let mut res = Vec::new();

      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {

          offset: *offset,
          output: output.clone(),

        });
      }
    }
