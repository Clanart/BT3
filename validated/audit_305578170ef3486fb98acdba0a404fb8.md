### Title
`SignableTransaction` trusts attacker-supplied `ReceivedOutput` values/outpoints, signing transactions that spend non-existent or mis-valued UTXOs - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` builds a transaction and the BIP-341 sighash entirely from the `TxOut` value and `OutPoint` carried inside each `ReceivedOutput`. `ReceivedOutput::read` accepts arbitrary bytes with no validation, and `SignableTransaction::multisig` only checks that `prevouts[i].script_pubkey` matches the offset group key — it never checks that the outpoint exists on-chain or that the claimed `value` equals the real UTXO's amount. A malicious participant feeding crafted `ReceivedOutput` bytes can therefore get the threshold group to produce valid FROST signatures over a transaction the Bitcoin network will reject.

### Finding Description
The analog to "trusting `token.balanceOf()`" is trusting the self-reported `TxOut` inside `ReceivedOutput`:

- `ReceivedOutput::read` deserializes `offset`, `output` (a full `TxOut` including `value`), and `outpoint` from untrusted bytes with no consistency check — the three fields are completely independent [1](#0-0) .
- `SignableTransaction::new` sums `input.output.value` as `input_sat` for the funds check, uses `input.outpoint` as the tx inputs, and stores the attacker-controlled `TxOut`s as `prevouts` [2](#0-1) .
- `multisig` verifies only `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey`; the `value` and the `outpoint` are never bound to the key or to chain state [3](#0-2) .
- `sign` computes `taproot_key_spend_signature_hash(i, &Prevouts::All(&self.tx.prevouts), Default)`, so the forged `value`/`script_pubkey` pair is what every participant's signature commits to [4](#0-3) .

Because BIP-341 commits to the prevout amounts, any mismatch between the reported `value` and the true UTXO amount makes the resulting signature invalid at consensus level, and any fabricated `outpoint` makes the input unspendable.

### Impact Explanation
An attacker can cause the threshold multisig to produce a fully signed transaction that can never confirm: either the `outpoint` doesn't exist / was already spent, or the committed `value` doesn't match the real UTXO so the sighash is wrong. Funds the protocol believes it received (the reported `ReceivedOutput`) are not spendable, and the multisig's real funds can be locked or burned in fees by a transaction whose inputs were misrepresented. This matches "funds reported received that are not spendable" — the protocol's bookkeeping (`input_sat`, `fee()`, `needed_fee`) is driven entirely by the unverified reported value.

### Likelihood Explanation
Requires an untrusted party to supply `ReceivedOutput` bytes (e.g., a coordinator or peer relaying claimed deposits via `ReceivedOutput::read`) rather than outputs produced by the local `Scanner::scan_transaction`, which derives `TxOut`/`outpoint` from actual chain data. This is a reachable path but depends on the deployment plumbing attacker-controlled inputs into `SignableTransaction::new`, so Medium likelihood / Medium severity.

### Recommendation
Bind `ReceivedOutput` to verified chain data: either accept only outputs produced by `Scanner` (which populates `TxOut` and `outpoint` from the real transaction), or have `SignableTransaction::new`/`multisig` verify each input's `outpoint` resolves on-chain and that its actual `value` and `script_pubkey` equal the supplied `prevout`. At minimum, authenticate `ReceivedOutput`s (e.g., a MAC or signed scanner event) before they reach `read` → `SignableTransaction::new` so the reported balance cannot be fabricated.

### Proof of Concept
```rust
// Attacker crafts a ReceivedOutput claiming 10 BTC at a fake outpoint,
// with the real p2tr script of the multisig's offset key.
let fake = ReceivedOutput {
    offset: Scalar::ZERO,
    output: TxOut {
        value: Amount::from_sat(1_000_000_000),          // fabricated "balance"
        script_pubkey: p2tr_script_buf(group_key).unwrap(), // passes the multisig check
    },
    outpoint: OutPoint::null(),                          // non-existent UTXO
};

let mut bytes = vec![];
fake.write(&mut bytes).unwrap();
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // accepted unchecked

// SignableTransaction::new treats input_sat = 1 BTC and succeeds.
let tx = SignableTransaction::new(vec![forged], &payments, Some(change), None, 20).unwrap();
// multisig() passes: script_pubkey matches the offset group key.
let machine = tx.multisig(&keys).unwrap();
// sign() commits to Prevouts::All containing the forged value;
// every participant produces a valid FROST share for a tx Bitcoin will reject.
```
