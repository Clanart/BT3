## Title
Single global `maxOracleAge` bound cannot correctly gate staleness for every registered token's Chainlink oracle, allowing stale/mispriced gas payments in `SimplexPaymaster` - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices every ERC-20 gas payment using two Chainlink feeds — the fixed `nativeOracle` and each token's `tokenOracle` — but staleness for *both* is checked against a single, contract-wide `maxOracleAge` value [1](#0-0) . The contract's own comments acknowledge that Chainlink heartbeats vary drastically per token/chain ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h") [2](#0-1) , yet the contract stores exactly one `maxOracleAge` for all tokens simultaneously, capped only by `MAX_ORACLE_AGE = 7 days` [3](#0-2) . This is the same broken invariant as the referenced DSC report: one staleness window cannot be simultaneously correct for oracles with second-scale heartbeats and oracles with day-scale heartbeats.

### Finding Description
`_getOraclePrice` is the sole staleness guard used for both `nativeOracle` and every `tokenConfigs[token].tokenOracle`: [4](#0-3) 

`_tokenPrice`, called from the permissionless `_fetchDetails` hook that runs on every UserOp during `postOp`/prefund settlement, invokes `_getOraclePrice` for both feeds using this single bound: [5](#0-4) [6](#0-5) 

`_setParams`, the only place `maxOracleAge` can be changed, validates only that it is non-zero and below the 7-day ceiling — it has no per-token granularity at all: [7](#0-6) 

Because `maxOracleAge` is a single scalar shared by `nativeOracle` and every `TokenConfig.tokenOracle` registered via `_registerToken`/`RegisterToken` governance requests [8](#0-7) , any bound wide enough to tolerate the slowest legitimate oracle (per the contract's own documentation, up to 24h) is simultaneously wide enough to accept a fast-heartbeat oracle (e.g., a ~27s BSC stablecoin feed) that has silently stalled for many hours (oracle malfunction, sequencer/chain issue, depeg event suppressing deviation-triggered updates) without ever tripping `StaleOraclePrice`. There is no per-token override, no way to tighten the bound only for the fast oracle without also breaking every other legitimately slow oracle registered on the same deployment.

Any unprivileged UserOp sender selects `tokenAddr` in `paymasterData` (byte 0 = mode, bytes 1–20 = token) and thereby chooses which `TokenConfig` (and its oracle) is priced against the shared `maxOracleAge` at `_fetchDetails`/`_tokenPrice` time — no relayer, prover, admin, or governance compromise is needed to trigger the flawed check; it fires on ordinary transaction flow.

### Impact Explanation
When a registered token's oracle stalls (a stale-but-within-bound price), `_tokenPrice` returns a mispriced `tokenPrice` that PaymasterERC20 uses to compute `erc20Cost = weiCost * tokenPrice / 1e18`. If the stale price is higher than the true current price, users pay too much (loss for users); if it's lower (e.g., a depegging stablecoin whose deviation-based updates stopped firing before drop, price reported stale-high relative to true value, or vice versa for the native asset), the paymaster is under-compensated in ERC-20 terms for the native gas it actually spent via the EntryPoint, draining paymaster/treasury value — a real loss of funds for the protocol's treasury with no admin or malicious-actor precondition beyond normal UserOp submission.

### Likelihood Explanation
The bug is deterministic given the deployment's design (single `maxOracleAge` for heterogeneous heartbeats explicitly acknowledged in the code comments), and triggering it only requires an oracle to stall within the configured window plus a normal UserOp using that token — no privileged actor, front-running, or governance misbehavior is required. Likelihood scales with the number of registered tokens/chains and any real-world oracle incident (a common occurrence for lower-liquidity or exotic stablecoin feeds).

### Recommendation
Store `maxOracleAge` per token (and separately for `nativeOracle`) in `TokenConfig` / `Params`, mirroring the CodeHawks recommendation of using a mapping keyed by oracle/token instead of one shared scalar, and validate each bound against that specific oracle's known heartbeat when registered via `RegisterToken`/`UpdateParams`.

### Proof of Concept
1. Governance registers two tokens: `USDC_BSC` (oracle heartbeat ~27s) and `USDT_ETH` (oracle heartbeat ~24h), and sets `maxOracleAge = 24 hours` via `UpdateParams` so the ETH token's legitimate feed isn't perpetually flagged stale — this is a normal, non-malicious configuration necessitated by the single-parameter design [9](#0-8) .
2. `USDC_BSC`'s Chainlink feed stalls (contract bug, sequencer outage, or thin-market deviation suppression) for 6 hours while its true USD value drifts.
3. A user submits a UserOp with `paymasterData` selecting `USDC_BSC`. `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` checks `block.timestamp - updatedAt (6h) > maxOracleAge (24h)` → false, so the stale price is accepted [1](#0-0) .
4. PaymasterERC20 charges the user based on this stale/incorrect price; if the stale price undervalues the true USD cost of gas, the paymaster/treasury systematically loses value on every such UserOp until the oracle recovers or is re-registered, with no revert or alert triggered by the contract's staleness guard.

```text
    /// @dev Registers or updates a supported ERC-20 token with its token/USD feed.
    ///      Re-registering is also the recovery path for a misbehaving oracle.
    function _registerToken(address token, AggregatorV3Interface oracle) internal {
        if (token == address(0) || address(oracle) == address(0)) revert ZeroAddress();

        bool isNew = !tokenConfigs[token].active && address(tokenConfigs[token].tokenOracle) == address(0);

        tokenConfigs[token] = TokenConfig({
            tokenOracle: oracle,
            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }
```

```text
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }
```

```text
    }
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
