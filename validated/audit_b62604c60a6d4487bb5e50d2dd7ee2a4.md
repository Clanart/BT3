This confirms the SSRF analog: `create_mirror_puzzle()` is a fixed, uncurried `P2_PARENT` puzzle with **no owner/authorization check** — any party can create a coin with this puzzle hash and any memo payload, and `get_mirror_info()` extracts `launcher_id` and arbitrary `urls` straight from the coin's `CREATE_COIN` memos with zero validation.

### Title
DataLayer Mirror URLs Are Attacker-Controlled and Fetched Unvalidated by Peer DataLayer Nodes (SSRF) - (File: chia/data_layer/dl_wallet_store.py / chia/data_layer/download_data.py)

### Summary
The DataLayer mirror mechanism lets **anyone** publish a coin on-chain with the fixed, unowned `create_mirror_puzzle()` puzzle hash whose memos encode an arbitrary `launcher_id` (any store id) plus an arbitrary list of URL strings. Every wallet tracking that `launcher_id` ingests these memos as legitimate "mirror" server URLs. When a DataLayer node subsequently syncs that store, it iterates `get_available_servers_for_store()`/`get_mirrors()` and performs outbound HTTP requests (`http_download`, `get_downloader`) directly against attacker-supplied URLs with no allow-list, scheme restriction, or private-IP/loopback filtering — a direct analog of phpThumb's SSRF via an uncontrolled `src` parameter.

### Finding Description
`create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))` [1](#0-0) . This puzzle hash is not tied to any specific launcher/store owner — it is a global constant. `get_mirror_info()` reads the `CREATE_COIN` condition targeting that puzzle hash and pulls `launcher_id = memos[0]` and `urls = memos[1:]` verbatim, with no signature, ownership, or authenticity check against the target store's singleton: [2](#0-1) .

Because creating such a coin only requires spending funds you control to a known, fixed puzzle hash with a chosen memo, any wallet/spend-bundle submitter can announce mirror URLs for **any** `launcher_id`, including stores they do not own. These records are persisted verbatim into the `mirrors` table via `DataLayerStore.add_mirror()`/`get_mirrors()` [3](#0-2) .

`DataLayer.update_subscriptions_from_wallet()` pulls these attacker-controlled URLs straight from wallet RPC and feeds them into the local subscription/server list: [4](#0-3) . `fetch_and_validate()` then shuffles through `servers_info` and issues live outbound requests to those URLs via `insert_from_delta_file()`/`get_downloader()` [5](#0-4)  and [6](#0-5) . The actual HTTP GET/POST happens in `http_download()` and `download_file()`, which build request URLs by simple string concatenation (`server_info.url + "/" + filename`, `downloader.url + "/download"`) with no host/IP validation, proxy allow-list, or scheme restriction beyond default aiohttp behavior: [7](#0-6)  and [8](#0-7) .

The project's own internal notes acknowledge this as an explicit trust boundary weakness: "Plugin and mirror URLs are external trust inputs" and "Mirrors and plugins can improve availability, but they are never trust anchors" [9](#0-8) , and the "Fragility Hotspots" section explicitly flags that downloaded data is verified against wallet-advertised roots but the URL *sources themselves* are not authenticated [10](#0-9) .

### Impact Explanation
An attacker with no relationship to a given DataLayer store can force any peer's DataLayer service/S3 plugin process to send outbound HTTP(S)/POST requests to attacker-chosen hosts (e.g., `http://127.0.0.1:<internal-port>/...`, cloud metadata endpoints like `169.254.169.254`, or internal-network services), by merely broadcasting a cheap on-chain mirror-creation spend bundle referencing a victim's `launcher_id`. This is classic SSRF: the requester (the victim's DataLayer node) is tricked into probing/attacking internal infrastructure, can leak internal service responses through DataLayer logs/errors, or can be used to conduct port scanning/DoS against internal endpoints from a trusted machine. Because the S3 plugin's `download`/`handle_download` handlers also trust the `url` field from the (attacker-influenced) mirror record when deciding what to fetch [11](#0-10) , the blast radius extends to any downloader plugin the operator has configured.

### Likelihood Explanation
Likelihood is Medium: the attack requires only a standard, unprivileged wallet transaction (a coin spend to the fixed `MIRROR_PUZZLE_HASH` with a chosen memo) and knowledge of a target `launcher_id`, both of which are public on-chain information. No privileged access, malicious peer, or protocol-layer exploit is needed — this is reachable purely through a normal spend bundle from any wallet user.

### Recommendation
- Require mirror coins to be provably associated with the store owner (e.g., verify the mirror-creating coin's origin/authority against the DL singleton's current owner key, or require an owner signature/announcement binding the mirror to the singleton) rather than accepting any coin matching the fixed `MIRROR_PUZZLE_HASH`.
- Independently of on-chain trust, add SSRF hardening at the network layer in `http_download()`/`download_file()`/`get_downloader()`: enforce an allow-list of schemes (https only), resolve and reject private/loopback/link-local/metadata IP ranges before connecting, and cap redirects.
- Treat mirror/plugin URLs strictly as untrusted input in the S3 plugin `download`/`handle_download` handlers as well, applying the same network-layer restrictions there.

### Proof of Concept
1. Attacker crafts a spend bundle that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memo `[victim_launcher_id, b"http://127.0.0.1:19999/admin"]` (or an internal-network/cloud-metadata URL), paying only the coin amount + fee. This mirrors exactly the legitimate `create_new_mirror()` flow [12](#0-11)  but is not restricted to store owners.
2. Broadcast the spend bundle; once confirmed, any node tracking `victim_launcher_id`'s wallet ingests the coin as a `Mirror` record via `get_mirror_info()`.
3. The victim's DataLayer service, during its periodic `update_subscriptions_from_wallet()`/`fetch_and_validate()` cycle, adds this URL to `servers_info` and issues an outbound HTTP request to `http://127.0.0.1:19999/admin/<filename>` via `http_download()`, demonstrating SSRF against the victim's own internal network from their trusted DataLayer process.

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def handle_download(self, request: web.Request) -> web.Response:
        self.update_instance_from_config()
        try:
            data = await request.json()
        except Exception as e:

        return web.json_response({"handle_download": False})

    async def download(self, request: web.Request) -> web.Response:
        try:
            data = await request.json()
            url = data["url"]
            filename = data["filename"]
            group_files_by_store = data.get("group_files_by_store", False)
            max_delta_file_size = data.get("max_delta_file_size")
            if not isinstance(max_delta_file_size, int) or max_delta_file_size <= 0:
                max_delta_file_size = 250

            # filename must follow the DataLayer naming convention
            if not is_filename_valid(filename, group_files_by_store):
                return web.json_response({"downloaded": False})

            # Pull the store_id from the filename to make sure we only download for configured stores

            parse_result = urlparse(url)
            should_download = False
            for store in self.stores:
                if store.id == filename_store_id and parse_result.scheme == "s3" and url in store.urls:
                    should_download = True
                    break

            if not should_download:
                return web.json_response({"downloaded": False})
