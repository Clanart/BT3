## Answer

Valid finding. The Cygwin branch of `launch()` in `app/src/lib/shells/win32.ts` builds a POSIX shell command line by string interpolation, and the interpolated value (`path`, which ultimately comes from `repository.path`, i.e. the local clone/worktree directory name) is not restricted to characters that are safe inside nested single/double bash quoting.

### Title
Command injection via repository path in Cygwin shell launch — (File: `app/src/lib/shells/win32.ts`)

### Summary
`launch()` spawns Cygwin's `mintty.exe` with an argument that itself is a `bash -lc` script:

```ts
case Shell.Cygwin:
  const cygwinPath = `"${foundShell.path}"`
  return spawn(
    cygwinPath,
    [`/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash'`],
    { shell: true, cwd: path }
  )
``` [1](#0-0) 

`path` is user-facing repository/worktree path text, ultimately `repository.path` passed from `App.openInShell` → `Dispatcher.openShell` → `AppStore._openShell` → `launchShell`/`launch`. [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
This directory name is derived from the attacker-controlled GitHub repository name during clone (`sanitizeCloneName`) or typed/selected by the user (`safeDirectoryName`), neither of which strips shell metacharacters such as `'`, `` ` ``, `$`, `(`, `)`, `;`, `#` — they only strip characters NTFS itself forbids (`<>:"|?*`) or path separators. [5](#0-4) [6](#0-5) 

The Cygwin command template mixes single quotes (outer) and double quotes (inner, for `cygpath "${path}"`). Since the path is placed *inside* double quotes within a single-quoted bash string:
- If `path` contains a single quote `'`, it terminates the outer `'...'` string early, and any text following becomes literal bash syntax that gets executed.
- Even without breaking out of the quoting, because the value sits inside double quotes, bash still performs command substitution: a path segment containing `$(...)` or backtick sequences is executed by the shell when `cygpath "${path}"` is evaluated.

None of these characters are rejected before reaching this string-interpolated shell command, so the invariant ("attacker text reaches a child process only as an inert operand, never as a shell token") is violated specifically for the Cygwin code path.

### Impact Explanation
If a victim clones/opens an attacker-named repository (e.g. named so its sanitized folder name contains `'; calc.exe #` or `$(calc.exe)`) and has Cygwin installed, then chooses "Open in Shell" (or GitHub Desktop auto-selects Cygwin as `selectedShell`), the injected bash fragment executes with the user's privileges — arbitrary command execution.

### Likelihood Explanation
Requires: (1) victim has Cygwin installed and available as a shell choice, (2) victim opens the malicious repo in shell. This is a normal, expected user action ("Open in Shell" is a core feature), and repo names are fully attacker-controlled up to filesystem constraints, which do allow `'`, `$`, `` ` ``, `(`, `)`.

### Recommendation
Do not build the Cygwin (or any) shell command via string interpolation with mixed quoting. Instead, pass `path` as a genuinely inert argument, e.g. invoke Cygwin's `bash` directly with `-lc` and pass the `cd`/exec logic without embedding untrusted text inside nested quotes, or use `mintty.exe`'s native working-directory flag if available, or escape single quotes using the standard `'\''` technique and forbid embedding any `$()`/backtick expansion context. More generally, sanitize repository/worktree directory names to a safe character set before they are ever used to build shell command strings, not just to satisfy NTFS.

### Proof of Concept
1. Create (or simulate) a repository whose sanitized local folder name is: `demo'; calc.exe #`
2. Clone it via GitHub Desktop so `repository.path` ends with that folder name.
3. With Cygwin installed and selected, choose "Open in Shell".
4. Observe that `calc.exe` (or any injected command) executes, confirming the single-quote breakout in the Cygwin `launch()` branch of `app/src/lib/shells/win32.ts`. [1](#0-0)

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
