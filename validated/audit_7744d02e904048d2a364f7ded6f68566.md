Found a concrete analog. The mass-assignment bug class in the FreeScout report — an update path that trusts *all* fields from the incoming payload without allowlisting them against what was actually authorized/signed — maps to a similarly-shaped gap in Kaia's KIP-249 auction bid pipeline: the `ValidateAuctioneerSig` check does not bind to the full bid content, allowing a field (`MaxGasPrice`) to be silently mutated after signature checks pass.

### Title
Auctioneer signature covers only the raw searcher signature bytes, not the bid content, allowing an auctioneer to mass-mutate bid fields (e.g. `MaxGasPrice`) post-hoc without invalidating validation - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.validateBidSigs()` verifies the searcher's EIP-712 signature over the bid struct, but the auctioneer signature is validated by `Bid.ValidateAuctioneerSig()`, which hashes only `b.SearcherSig` (via `GetEthSignedMessageHash`) rather than the full `BidData`. This means any field in `BidData` that is not itself part of the EIP-712-signed struct — most notably `MaxGasPrice` in the V2→V3 auction upgrade path — can be attached or altered by whoever constructs the final `Bid` object (the RPC caller / auctioneer relay) without being caught by either signature check, similarly to how FreeScout's `fill($request->all())` let hidden fields ride along on an otherwise-legitimate authenticated request.

### Finding Description
`kaiax/auction/impl/api.go`'s `SubmitBid` accepts a `BidInput` from any public-RPC caller via `auction_submitBid`, converts it with `ToBid()` into a `*auction.Bid`, and hands it to `BidPool.AddBid()`. [1](#0-0) 

`AddBid()` calls `validateBid()`, which in turn calls `validateBidSigs()`: [2](#0-1) 

`ValidateSearcherSig` recomputes the EIP-712 typed-data digest from the bid's fields and checks it against `b.SearcherSig`: [3](#0-2) 

For V3 bids, `bidV3.EncodeData()` does include `MaxGasPrice` in the struct hash, so the searcher's own signature *does* bind `MaxGasPrice` when the V3 typehash path is used: [4](#0-3) 

However, `ValidateAuctioneerSig` only signs/verifies `GetEthSignedMessageHash()`, which hashes `b.SearcherSig` alone — not the bid's other fields (`Sender`, `To`, `Bid`, `MaxGasPrice`, `CallGasLimit`, `Data`, etc.): [5](#0-4) [6](#0-5) 

This means the auctioneer's signature does not independently attest to the bid content — it only attests "I saw this searcher signature." Combined with `ToBid()`, which is a mass-assignment-style, un-allowlisted field copy from attacker-controlled `BidInput` JSON-RPC input directly into `BidData` (including the optional `MaxGasPrice` pointer that is silently defaulted to zero when absent, and conditionally populated when present): [7](#0-6) 

there is no code path in `BidPool` that cross-checks the raw `bidInput.MaxGasPrice` (or any V3-specific field) against what was actually signed by the searcher under the V2 typehash — `auctionType` (used when `version == AuctionVersionV2` or unknown) omits `maxGasPrice` from its signed struct entirely: [8](#0-7) 

So if the on-chain `AuctionEntryPoint` is momentarily reporting version `"0.0.1"` (V2) — e.g. during/around a version transition, or via `ReadAuctionVersion`'s fallback semantics ("any other value falls back to the v2.1 ABI") — a searcher's V2-signed bid (which never committed to `maxGasPrice`) can have an arbitrary `MaxGasPrice` value spliced in by whoever submits the RPC call, and `ValidateSearcherSig` will still pass because the V2 digest never covered that field. The mutated bid then flows into `EncodeAuctionCallData`, which packs `MaxGasPrice` into the calldata sent to the on-chain `AuctionEntryPoint` for gas-limit computation and settlement: [9](#0-8) 

### Impact Explanation
`MaxGasPrice` is a security-relevant parameter used to bound how much gas price the searcher is willing to accept for settlement of the winning auction bid on-chain. Silently splicing/mass-assigning this field into a bid whose EIP-712 signature did not cover it (V2 path) — or before the auctioneer's coarse signature (which never covers it in either version) — lets an unprivileged RPC caller who relays the bid manipulate the effective gas-price ceiling used for on-chain settlement without the searcher's true consent, potentially causing unauthorized value movement in bid settlement or state divergence between nodes disagreeing on which version/field-set is authoritative for a given bid. This satisfies the "fee or fee-delegation abuse / gasless or auction settlement theft" impact category from a single submitted RPC bid.

### Likelihood Explanation
Medium. Exploitation requires either (a) submitting a bid while the auction entry point is at/near a version boundary such that the searcher's signature was computed under the V2 typehash (which doesn't cover `MaxGasPrice`) while the pool/contract still processes `MaxGasPrice`, or (b) any caller positioned between searcher signing and `auction_submitBid` RPC submission tampering with the `BidInput.MaxGasPrice` field, since neither the searcher's V2 signature nor the auctioneer's signature (in either version) binds this field end-to-end. Any unprivileged party can call the public `auction_submitBid` RPC endpoint.

### Recommendation
- Make `ValidateAuctioneerSig` sign/verify the full `BidData` content (or at minimum a hash including all monetary/execution-relevant fields: `Bid`, `MaxGasPrice`, `CallGasLimit`, `Data`, `Sender`, `To`) rather than only `b.SearcherSig`.
- Reject V2-typed bids that carry a non-zero `MaxGasPrice`, or require all bids destined for a V3 entry point to be signed under the V3 typehash only, with no fallback ambiguity in `ReadAuctionVersion`.
- Explicitly allowlist/validate every field copied in `ToBid()` against the fields actually committed to by `ValidateSearcherSig`'s digest for the resolved version, rejecting bids where unsigned-but-present fields are non-default.

### Proof of Concept
1. Deploy/observe `AuctionEntryPoint` reporting `AUCTION_VERSION() == "0.0.1"` (V2).
2. Have a searcher sign a bid using `GetHashTypedData(chainId, verifyingContract, AuctionVersionV2)`, which excludes `maxGasPrice` from the digest (`auctionType` in `kaiax/auction/eip712.go:27`).
3. An RPC-submitting party constructs `BidInput` with the searcher's valid `SearcherSig`/`AuctioneerSig` but sets `MaxGasPrice` to an attacker-chosen value before calling `auction_submitBid`.
4. `ToBid()` copies `MaxGasPrice` into `BidData` unconditionally when present (`kaiax/auction/impl/api.go:101-103`).
5. `BidPool.validateBidSigs()` calls `ValidateSearcherSig`, which recomputes the V2 digest (still excluding `maxGasPrice`) and successfully matches `b.Sender` — validation passes despite the tampered field.
6. `ValidateAuctioneerSig` similarly passes since it only ever hashes `SearcherSig`, never bid content.
7. The bid, now carrying attacker-controlled `MaxGasPrice`, is admitted to the bid pool and used in `EncodeAuctionCallData`/on-chain settlement (`blockchain/system/auction.go:83-119`).

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b bidV3) EncodeData() []byte {
	maxGasPrice := b.MaxGasPrice
	if maxGasPrice == nil {
		maxGasPrice = new(big.Int)
	}
	encoded := make([]byte, 0, 10*32)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.BidData.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(maxGasPrice.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}
