### Title
Silent, unconfirmed remote-URL rewrite from untrusted GitHub API data can redirect pushes/fetches - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl()` overwrites the tracked repository's git remote URL using data taken directly from a GitHub API response (`apiRepo.clone_url`), with no user confirmation and only loose string-based validation. This mirrors the C4N report's core flaw — a security-critical, trust-bearing value (there: the vetoer address; here: the git remote a user pushes to and fetches from) can be silently reassigned without a zero-value/sanity check or a two-step, user-confirmed change process.

### Finding Description
`updateRemoteUrl` is invoked from `app-store.ts` as part of routine repository refresh logic, and calls `gitStore.setRemoteURL()` — which runs `git remote set-url <name> <url>` — whenever it decides the tracked GitHub repository's clone URL differs from the local remote: [1](#0-0) 

The only guards are:
- `protocolsMatch`: confirms the scheme string (`https`/`ssh`) is unchanged.
- `remoteUrlUnchanged`: confirms the *previous* value of `gitHubRepository.cloneURL` still loosely matches the current local remote via `urlMatchesRemote`.

`urlMatchesRemote` only compares the parsed hostname/owner/name components extracted by a permissive regex-based `parseRemote`, not the literal URL or any cryptographic/identity proof of the destination: [2](#0-1) [3](#0-2) 

There is no zero/empty-URL check, no allowlist of trusted hosts, and no user-facing confirmation step before `setRemoteURL` is applied — the change happens silently in the background as part of a routine refresh: [4](#0-3) 

Because `apiRepo` is a GitHub API object (`IAPIRepository`), any source capable of influencing that object's `clone_url` — a compromised/malicious GitHub Enterprise endpoint the user has signed into, a tampered/MITM'd API response, or a server-side rename/ownership change on an untrusted host — can cause Desktop to silently repoint the user's trusted git remote to an attacker-controlled URL.

### Impact Explanation
The remote URL is the value that determines where `git push` sends the user's code and credentials (via HTTP Basic/token or SSH) and where `git fetch`/`pull` retrieves objects from. Silently corrupting it is directly comparable to losing veto power over a critical operation in the original report: once the value is quietly repointed, the user has no natural signal that subsequent pushes are being sent to a different destination, and pushes can leak commit contents/credentials to that destination, or fetches can pull attacker-supplied objects into the user's next operations.

### Likelihood Explanation
This path requires the user to already have an authenticated account against a hostile or compromised endpoint (a GitHub Enterprise server, or an intercepted API channel) supplying repository metadata for a repo already tracked in Desktop — no local access, malware, or credential theft is needed, matching the "GitHub API object" attacker model allowed by the task. The comparison logic (`urlMatchesRemote`) is weak (structural only, not full-URL or identity based), and the update runs automatically during normal background refresh with no user prompt, so exploitation does not require unnatural user steps beyond normal app usage while connected to the hostile/compromised endpoint.

### Recommendation
- Do not silently call `setRemoteURL` based on API-supplied data; require explicit user confirmation before changing a remote's URL, especially when the new hostname differs at all from the previously trusted value.
- Compare full normalized URLs (not just structurally parsed owner/name/hostname) and reject changes where the resulting hostname isn't the same trusted account endpoint the repository was originally associated with.
- Treat this similar to the C4 recommendation: add explicit "reject empty/invalid URL" and a two-step (propose-then-confirm) UX for remote URL changes triggered by non-user-initiated (API-driven) code paths.

### Proof of Concept
1. User signs into a GitHub Enterprise (or otherwise attacker-influenced) endpoint in Desktop and has a repository tracked whose `GitHubRepository.cloneURL` matches the local `origin` remote.
2. The API server (compromised, MITM'd, or malicious Enterprise instance) returns a repository object whose `clone_url` field points to an attacker-controlled host while the scheme (`https`) is preserved.
3. On the next background refresh, `updateRemoteUrl` in `app/src/lib/stores/updates/update-remote-url.ts` computes `protocolsMatch = true` and `remoteUrlUnchanged = true` (since the local remote still matches the previously cached `cloneURL`), and `urlsMatch = false` (new host differs) — satisfying the condition at line 42, calling `gitStore.setRemoteURL(name, attackerURL)`.
4. Desktop silently rewrites `origin` to the attacker's URL via `git remote set-url` [4](#0-3) ; the next push/fetch the user performs is silently redirected without any prompt or warning.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

const remoteRegexes: ReadonlyArray<{ protocol: GitProtocol; regex: RegExp }> = [
  {
    protocol: 'https',
    regex: new RegExp(
      '^https?://(?:.+@)?(.+)/([^/]+)/([^/]+?)(?:/|\\.git/?)?$'
    ),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^git@(.+):([^/]+)/([^/]+?)(?:/|\\.git)?$'),
  },
  {
    protocol: 'ssh',
    regex: new RegExp(
      '^(?:.+)@(.+\\.ghe\\.com):([^/]+)/([^/]+?)(?:/|\\.git)?$'
    ),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^git:(.+)/([^/]+)/([^/]+?)(?:/|\\.git)?$'),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^ssh://git@(.+)/(.+)/(.+?)(?:/|\\.git)?$'),
  },
]

/** Parse the remote information from URL. */
export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}
