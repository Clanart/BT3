### Title
Payout transaction's OP_RETURN operator-attribution output is unsigned, allowing RBF-based reimbursement hijack - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx`'s user-provided input signature only covers input 0 and output 0 (`SIGHASH_SINGLE|ANYONECANPAY`), leaving the OP_RETURN output — which records which operator "fronted" the withdrawal — completely unauthenticated and replaceable. Combined with RBF-enabled sequence numbers, any party who observes a broadcast (but unconfirmed) payout transaction can replace it with their own version carrying the same user payment but a different OP_RETURN operator pubkey, hijacking the reimbursement credit.

### Finding Description
`create_payout_txhandler` builds a `Payout` transaction with three outputs: (1) the user's payout, (2) an anchor, and (3) an OP_RETURN encoding `operator_xonly_pk`, the identity that will later be reimbursed [2](#0-1) . The only witness is the user's Taproot signature over input 0, enforced to be `SinglePlusAnyoneCanPay` [3](#0-2) . That sighash type binds only input 0 and output 0 — the OP_RETURN (output index 2) and the anchor are not covered by the signature.

The input's sequence is set to `DEFAULT_SEQUENCE = Sequence::ENABLE_RBF_NO_LOCKTIME`, explicitly signaling replace-by-fee [1](#0-0) [4](#0-3) .

The verifier later trusts whichever payout transaction actually confirms: `update_finalized_payouts` parses the OP_RETURN from the confirmed transaction and assigns `operator_xonly_pk` — used as `payout_payer_operator_xonly_pk` in the DB — from that data alone, with no cross-check against who supplied the transaction's funding inputs or fee [5](#0-4) . This value directly drives `get_first_unhandled_payout_by_operator_xonly_pk` and the reimbursement pipeline (`PayoutCheckerTask` → `handle_finalized_payout` → `get_reimbursement_txs` → `create_reimburse_txhandler`), which spends the `MoveToVaultTx` deposit UTXO to the address of whichever operator is recorded as payer [6](#0-5) [7](#0-6) [8](#0-7) .

This breaks the intended binding: `payer_operator (OP_RETURN) == operator who actually funded/fronted the withdrawal`. Because the OP_RETURN is unsigned and RBF is enabled, an attacker who observes the legitimate operator's unconfirmed `payout_tx` in the mempool can construct a new transaction reusing the same signed input/output-0 pair, add their own funding input(s) with a higher fee, and substitute the OP_RETURN with a different xonly public key (their own operator identity, or any registered operator's identity), then broadcast it to replace the original. The user still receives their exact requested payment (protected by the signature), but the credit for "fronting" the withdrawal — and thus the reimbursement of the full bridge amount from the vault — goes to whoever won the fee race and controlled the OP_RETURN, not to the entity whose off-chain checks (`is_profitable`, Citrea withdrawal-state validation, verification signature) were actually run in `Operator::withdraw` [9](#0-8) .

### Impact Explanation
This matches the Critical category "an operator reimbursed for a payout it never funded." An attacker can win the reimbursement credit for a withdrawal by only paying a small RBF fee bump, while the deposit UTXO in `MoveToVaultTx` is ultimately spent via `create_reimburse_txhandler` to the attacker-controlled operator's reimbursement address, instead of the operator that ran the legitimate profitability/verification checks. This is a direct bridge-custody/attribution binding violation.

### Likelihood Explanation
Exploitation requires observing an operator's `payout_tx` while unconfirmed in the mempool (a public, unauthenticated action) and broadcasting an RBF replacement with higher fee before it confirms — no privileged role, key compromise, or insider access is needed, only network-visibility of the mempool and the ability to broadcast a competing transaction, both routinely available to any unprivileged actor.

### Recommendation
Bind the operator-attribution OP_RETURN output to the user's signature by using a sighash type that commits to all outputs (e.g. `SIGHASH_ALL` variant, or restructure so the OP_RETURN commitment is embedded in the same taproot leaf/witness the user signs), or otherwise make the payer's identity a signed/authenticated field rather than an unauthenticated malleable output. Alternatively, disable RBF on this input (`Sequence::MAX` or `Sequence::ZERO`) so a broadcast payout cannot be replaced with an alternate OP_RETURN before confirmation, and additionally verify at settlement time that the confirmed transaction's funding inputs correspond to the operator identified in the OP_RETURN.

### Proof of Concept
1. Legitimate operator `A` runs `Operator::withdraw`, which passes all checks, builds `payout_tx` via `create_payout_txhandler` (input 0 signed `SinglePlusAnyoneCanPay`, output 0 = user payment, output 2 = OP_RETURN with `A`'s xonly pk), funds it via `fund_raw_transaction` with `replaceable: None` (RBF eligible since sequence < 0xfffffffe), and broadcasts it.
2. Attacker `B` (who also runs/registers an operator identity) observes this unconfirmed transaction in the mempool. Because the signature only covers input 0/output 0, `B` copies input 0 (with `A`'s valid signature) and output 0 unchanged, but constructs a new transaction with `B`'s own fee-paying input(s), a higher fee rate, and an OP_RETURN carrying `B`'s xonly pk instead of `A`'s.
3. `B` broadcasts this replacement; due to RBF signaling it evicts `A`'s original transaction from mempool and eventually confirms.
4. `update_finalized_payouts` reads `B`'s xonly pk from the confirmed OP_RETURN and stores it as `payout_payer_operator_xonly_pk` [10](#0-9) .
5. `PayoutCheckerTask`/`get_reimbursement_txs` subsequently reimburse `B` from the `MoveToVaultTx` deposit UTXO, even though `A` performed and paid for all the legitimate withdrawal validation and fronted the original transaction attempt.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn withdraw(
        &self,
        withdrawal_index: u32,
        in_signature: taproot::Signature,
        in_outpoint: OutPoint,
        out_script_pubkey: ScriptBuf,
        out_amount: Amount,
    ) -> Result<Transaction, BridgeError> {
        tracing::info!(
            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",
            withdrawal_index,
            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        // Check Citrea for the withdrawal state.
        let withdrawal_utxo = self
            .db
            .get_withdrawal_utxo_from_citrea_withdrawal(None, withdrawal_index)
            .await?;

        if withdrawal_utxo != input_utxo.outpoint {
            return Err(eyre::eyre!("Input UTXO does not match withdrawal UTXO from Citrea: Input Outpoint: {0}, Withdrawal Outpoint (from Citrea): {1}", input_utxo.outpoint, withdrawal_utxo).into());
        }

        let operator_withdrawal_fee_sats =
            self.config
                .operator_withdrawal_fee_sats
                .ok_or(BridgeError::ConfigError(
                    "Operator withdrawal fee sats is not specified in configuration file"
                        .to_string(),
                ))?;
        if !Self::is_profitable(
            input_utxo.txout.value,
            output_txout.value,
            self.config.protocol_paramset().bridge_amount,
            operator_withdrawal_fee_sats,
        ) {
            return Err(eyre::eyre!("Not enough fee for operator").into());
        }

        let user_xonly_pk = &input_utxo
            .txout
            .script_pubkey
            .try_get_taproot_pk()
            .wrap_err("Input utxo script pubkey is not a valid taproot script")?;

        let payout_txhandler = builder::transaction::create_payout_txhandler(
            input_utxo,
            output_txout,
            self.signer.xonly_public_key,
            in_signature,
            self.config.protocol_paramset().network,
        )?;
