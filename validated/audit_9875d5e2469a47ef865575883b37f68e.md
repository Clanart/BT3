### Title
Coinbase outputs are reported as immediately spendable despite Bitcoin maturity rules - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching coinbase outputs as ordinary `ReceivedOutput` values without recording maturity or excluding them until they become spendable. [1](#0-0) 

### Finding Description
`Scanner::scan_transaction` converts any transaction output whose `script_pubkey` matches a registered scanner script into a `ReceivedOutput`. [2](#0-1)  `scan_block` then calls it for every `block.txdata` entry, including `block.txdata[0]`, which is the coinbase transaction. [3](#0-2) 

The returned `ReceivedOutput` contains only an offset, `TxOut`, and outpoint; it has no flag, height, or maturity metadata distinguishing an immature coinbase output from a normally spendable output. [4](#0-3)  Although the function documentation acknowledges that coinbase outputs are maturity-bound, the API still returns them in the same trusted result set unless the caller performs an additional filtering pass. [5](#0-4) 

This is analogous to the referenced instant-unwrap issue: a state transition emits an asset representation before the protocol-required delay has elapsed. In Serai's Bitcoin wallet shape, the delayed operation is spending a coinbase output, and the premature representation is a normal `ReceivedOutput`.

### Impact Explanation
A caller that treats `scan_block` results as spendable can select an immature coinbase output as a transaction input, causing transaction construction, signing, or broadcast failure. [5](#0-4)  More significantly for the accepted impact class, the scanner reports funds as received in a form indistinguishable from spendable funds even though Bitcoin consensus prevents spending them for the coinbase maturity period. [4](#0-3) 

The processor's Bitcoin adapter avoids this in its own scanning path by skipping `block.txdata[0]`, which confirms that the distinction is operationally necessary rather than theoretical. [6](#0-5) 

### Likelihood Explanation
An unprivileged miner can create a coinbase output paying a known scanned address, and every caller invoking `scan_block` on that block will receive it as a normal `ReceivedOutput`. [7](#0-6)  The issue requires the caller to use the block-level API directly rather than the processor adapter's filtered path, so it is a Medium-severity API correctness issue rather than a critical protocol failure. [6](#0-5) 

### Recommendation
Change `scan_block` to skip `block.txdata[0]`, matching the production Bitcoin adapter behavior. [8](#0-7)  If scanning coinbase outputs is required for observability, return a distinct output representation or include coinbase/maturity metadata so callers cannot confuse it with an immediately spendable output. [4](#0-3) 

### Proof of Concept
```rust
use bitcoin::{Block, Transaction};
use serai_bitcoin::wallet::Scanner;

fn scan(block: &Block, scanner: &Scanner) {
  // A miner places an output paying `scanner`'s P2TR script in
  // block.txdata[0]. Bitcoin consensus makes that output immature.
  //
  // `scan_block` nevertheless returns it as an ordinary ReceivedOutput.
  let outputs = scanner.scan_block(block);

  // There is no maturity marker on ReceivedOutput, so this value is
  // indistinguishable from a spendable non-coinbase output.
  let immature_coinbase_output = outputs
    .iter()
    .find(|output| output.outpoint().txid == block.txdata[0].compute_txid());

  assert!(immature_coinbase_output.is_some());
}
```

The vulnerable behavior is directly implemented by `scan_block` iterating over all transactions without excluding the coinbase transaction. [3](#0-2)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
