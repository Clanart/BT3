## Title
Attacker-controlled `WWW-Authenticate` header spoofs GitHub Enterprise identity and triggers unauthorized OAuth sign-in flow bound to a malicious endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The unguarded `getReward` accounting flaw in the report reduces to: a value derived from an **attacker-influenced external signal** (contract balance delta) is trusted to decide who a shared resource (rewards) is allocated to, without verifying the signal actually corresponds to the caller's own context. The Desktop analog is `getEndpointKind()` in `trampoline-credential-helper.ts`, which trusts an attacker-controlled `WWW-Authenticate` HTTP header returned by a git remote to decide that the remote is "GitHub Enterprise," and then hands off the user to a real GitHub sign-in/OAuth flow scoped to that attacker-chosen `endpoint`.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`) and forwards any `WWW-Authenticate` headers the *remote server* returned as `wwwauth[...]` fields. `getEndpointKind()` classifies the endpoint purely from the content of that server-supplied header: [1](#0-0) 

If the string `realm="GitHub"` appears in that header, the function unconditionally returns `'enterprise'` — regardless of whether the actual host is a GitHub Enterprise server or an arbitrary attacker-controlled server the user cloned/fetched from. This value flows into `getCredential()`: [2](#0-1) 

Because there is no existing account matching the attacker's `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, where `endpoint` is the attacker-controlled remote URL: [3](#0-2) 

This begins a real enterprise sign-in flow (`beginEnterpriseSignIn` / `setSignInEndpoint(origin)`), presenting the user a legitimate-looking Desktop "Sign in to your GitHub Enterprise" dialog whose endpoint is entirely attacker-supplied: [4](#0-3) [5](#0-4) 

The corrupted value is the classification result of `getEndpointKind()` (`'enterprise'` vs `'generic'`), which is derived from unauthenticated, attacker-supplied header text rather than from anything Desktop actually verifies (e.g., a known account, a hardcoded GHE domain list, or a real API probe). This is structurally identical to `_calcRewardIntegral` trusting `bal - reward.remaining` as if it reflected only the caller's own pool, when in fact any actor can pollute the shared signal.

### Impact Explanation
An attacker who controls a git remote/HTTP proxy that the user clones or fetches from (no local access, no prior credentials needed) can force Desktop to initiate an OAuth/enterprise sign-in flow whose `endpoint` is entirely attacker-chosen. This matches the "unauthorized OAuth or account binding" and "credential/token exfiltration" impact classes: the user is led through a genuine-looking Desktop sign-in dialog against an attacker-controlled origin, and depending on the enterprise OAuth/device flow used, tokens or authorization codes could be delivered to the attacker's server instead of a legitimate GHE instance. Even absent full token capture, this is a strong phishing primitive baked into normal, unprompted git operations (clone/fetch), not requiring any unnatural user action beyond adding/using an untrusted remote — something Desktop explicitly supports (arbitrary HTTPS remotes).

### Likelihood Explanation
Likelihood is meaningful: the only requirement is that the user performs a normal git operation (clone, fetch, push) against a remote controlled or MITM'd by the attacker, and the server responds with a `401` including a spoofed `WWW-Authenticate: realm="GitHub"` header — trivial for anyone running the origin server. Existing guards (`isDotCom`, `isGHE`, checking for an already-signed-in account matching the endpoint) do not stop this path because they only short-circuit when the endpoint already matches a *known* GitHub domain or account; for any unknown host, the header-based heuristic is the deciding factor and is fully attacker-controlled.

### Recommendation
Do not trust the `WWW-Authenticate` realm string alone to classify a host as GitHub Enterprise. At minimum, corroborate the header claim with an authenticated API probe (the code already has `isGitHubHost(endpoint)` for this) before offering to sign the user into it, and surface the actual remote host prominently (not just as a caption) so users can recognize spoofed enterprise prompts. Consider rate-limiting/deduplicating sign-in prompts per unknown host and warning explicitly when a host is not a previously-trusted GHE server.

### Proof of Concept
1. Attacker stands up an HTTPS git server (e.g., a custom smart-HTTP git backend) at `https://evil.example.com/some/repo.git`.
2. Victim runs `git clone`/fetch against that URL in Desktop (e.g., adds it as a remote, or clones a link the attacker sent).
3. When Git requests credentials, the attacker's server responds with `401` and header `WWW-Authenticate: realm="GitHub"`.
4. Desktop's `getCredential` → `getEndpointKind` classifies the endpoint as `'enterprise'` purely from that string match: [6](#0-5) 
5. Since no account exists for `evil.example.com`, Desktop calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, opening a "Sign in to your GitHub Enterprise" dialog bound to the attacker's origin: [7](#0-6) 
6. The victim, believing this is a legitimate corporate GHE prompt (since Desktop itself surfaced it during a routine clone), proceeds through the sign-in flow scoped to the attacker's endpoint.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
