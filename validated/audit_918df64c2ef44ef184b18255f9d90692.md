### Title
`Debug` impls on `ThresholdKeys`/`ThresholdView` leak secret key material via `Interpolation::Constant` coefficients - (File: crypto/dkg/src/lib.rs)

### Summary
The bug class in CVE-2026-64315 is "sensitive key material emitted through debug/diagnostic output." Serai's in-scope `crypto/dkg` crate has a direct analog: `ThresholdKeys` derives `Debug`, and both `ThresholdCore::fmt` and `ThresholdView::fmt` print the `interpolation` field. `Interpolation` itself derives `Debug`, so `Interpolation::Constant(Vec<F>)` pretty-prints its raw scalar coefficients — which are documented as "one for each of the secret key shares." The author clearly intended to redact secrets (`secret_share` is omitted via `finish_non_exhaustive`), but the interpolation coefficients — which *are* the secret shares when `t == n` — are printed in cleartext.

### Finding Description
`Interpolation` derives `Debug` at crypto/dkg/src/lib.rs:211-222, with `Constant(Vec<F>)` documented as "a list of constant coefficients, one for each of the secret key shares." `ThresholdCore::fmt` includes `.field("interpolation", &self.interpolation)` (crypto/dkg/src/lib.rs:266-275), and `ThresholdKeys` derives `Debug` over `core`, `scalar`, and `offset` (crypto/dkg/src/lib.rs:291-301). `ThresholdView::fmt` also prints `interpolation`, `scalar`, and `offset` (crypto/dkg/src/lib.rs:316-328).

`Interpolation::Constant` is accepted whenever `t == n` (crypto/dkg/src/lib.rs:367-374), and `interpolation_factor` returns `c[i - 1]` directly — i.e., each participant's interpolated share equals their coefficient (crypto/dkg/src/lib.rs:226-249). Therefore:

- `format!("{keys:?}")` on `ThresholdKeys` using Constant interpolation dumps **all n secret shares** plus `scalar`/`offset`, enabling immediate reconstruction of the full group private key.
- `format!("{view:?}")` on `ThresholdView` leaks the same coefficients, plus the tweak `scalar`/`offset` applied on top of `secret_share` (crypto/dkg/src/lib.rs:494-498, 518-521) — the same scalars whose knowledge, combined with other data, recovers the effective signing key.

Notably, `secret_share` is deliberately excluded from both `fmt` bodies (`finish_non_exhaustive()`), proving the intent to keep secrets out of debug output — the interpolation coefficients were simply missed.

### Impact Explanation
Any `{:?}`/`{keys:?}` formatting of `ThresholdKeys` or `ThresholdView` — in a `log::debug!`/`info!` call, an error message (`io::Error::other(format!("{e:?}"))`-style paths exist in the same crate), a panic message, or an RPC/IPC diagnostic — writes every participant's secret share (for `t == n` multisigs) into logs readable by unprivileged parties, exactly mirroring the kernel leaking key material to `dmesg`. Recovery is trivial: the printed coefficients are the shares themselves, no cryptanalysis needed. For Lagrange keys the coefficients aren't present, but `scalar`/`offset` still leak ephemeral tweaks that may be secret (e.g., output/tweak scalars).

### Likelihood Explanation
`Debug` formatting of key material is the standard way these structs appear in logs and error chains, and the crate itself uses `{e:?}` formatting for errors. The exposure requires nothing from an attacker beyond access to logs/diagnostics — the same reachability model as the original CVE (unprivileged local reader of debug output). Likelihood is gated on (a) a `t == n` multisig using `Interpolation::Constant`, and (b) any formatting site existing in a consumer; both are plausible but deployment-dependent, which tempers the rating.

### Recommendation
- Implement `fmt::Debug` manually for `Interpolation` that emits `Constant(..)` / `Lagrange` without the scalar values, or wraps coefficients in a redacted marker.
- Remove `scalar` and `offset` from the derived `Debug` on `ThresholdKeys` and the manual `ThresholdView::fmt` (or gate them behind a `debug-secret` feature).
- Audit the other machine `Debug` impls (`SecretShareMachine`, `EncryptionKeyMessage`, algorithm machines) for the same pattern — `pedpop` already uses `finish_non_exhaustive` correctly (crypto/dkg/pedpop/src/lib.rs:285-294).

### Proof of Concept
```rust
// crypto/dkg/src/lib.rs semantics, t == n
let n = 3;
let shares: Vec<F> = (0..n).map(|_| F::random(rng)).collect();
let verification = shares.iter().map(|s| C::generator() * s).collect();
let keys = ThresholdKeys::new(
  ThresholdParams::new(n, n, Participant::new(1).unwrap()).unwrap(),
  Interpolation::Constant(shares.clone()),      // coefficients == secret shares
  Zeroizing::new(shares[0]),
  verification,
).unwrap();

let debug = format!("{keys:?}");
// `debug` contains the canonical repr of every share in `shares`
// → full group private key = sum of printed coefficients
```

Each printed `F` element equals `shares[i]` because `interpolation_factor` for `Constant` returns `c[i-1]` verbatim (crypto/dkg/src/lib.rs:228), so the debug string is a complete share set.
