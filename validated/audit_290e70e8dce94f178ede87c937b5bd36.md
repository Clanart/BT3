### Title
Uncaught `InvalidProtobufRuntimeException` from lazy MessageSet extension access causes DoS in Java runtime - (File: `java/core/src/main/java/com/google/protobuf/InternalLazyField.java`)

### Summary
CoAPthon3's `Serialize.deserialize()` mishandled certain exceptions during message decoding, so a crafted-but-bounded input caused an exception type the calling application did not (and per the library's contract could not reasonably) catch, crashing the CoAP server. The Protobuf Java runtime has an analogous failure mode: `InternalLazyField` (used for lazily-parsed `MessageSet` extensions) defers validation of an inner sub-message's bytes until the field is *accessed*, not when the outer message is parsed. If that lazily-held payload is corrupted, accessing it later throws an unchecked `InvalidProtobufRuntimeException` — a `RuntimeException` — from a call site (`getExtension()`, `toString()`, `hashCode()`, `equals()`, `getSerializedSize()`, etc.) that application code does not wrap in try/catch, unlike the well-known `InvalidProtocolBufferException` thrown by `parseFrom()`.

### Finding Description
`InternalLazyField.getValue()` defers full validation of a sub-message's bytes until first access: [1](#0-0) 

If the lazily-stored bytes fail to parse or fail post-parse checks, `ensureInitialized()` throws the checked `InvalidProtocolBufferException`, but `getValue()` — reachable from many normal read-only getters/serialization paths (`FieldSet.getField`, `LazyEntry.getValue`, `toString`, `getSerializedSize`) — converts it into an **unchecked** `InvalidProtobufRuntimeException` when the registry is in `LAZY_VERIFY_ON_ACCESS` mode: [2](#0-1) [3](#0-2) 

The failed invariant is the standard `Parser` contract documented for the library: "All methods may throw `InvalidProtocolBufferException`" at parse time — callers are expected to guard `parseFrom()` calls, not every subsequent field accessor: [4](#0-3) 

Because the outer `parseFrom()` call succeeds (the outer message's wire bytes for the `MessageSet` item are structurally well formed length-delimited bytes; only the embedded sub-message content is corrupted and not validated eagerly), the exception is deferred past the point where application code normally has exception handling, matching the CoAPthon3 pattern of "exception raised at an unexpected place in the deserialization flow, not caught by the caller." The attacker only needs to control a bounded, syntactically-valid outer message with a `MessageSet` extension item whose inner message payload is invalid bytes (e.g., a raw type-id/length header followed by malformed content) — no privileged access or malicious schema is required, only an ordinary client submitting a crafted Protobuf message through the public `parseFrom` API.

`lazyExtensionEnabled()` is governed by a process-wide static mode: [5](#0-4) 

The default is `EAGER` (`lazyExtensionMode = LazyExtensionMode.EAGER`), so this behavior is opt-in and does not affect out-of-the-box configurations — I could not find code enabling `LAZY_VERIFY_ON_ACCESS` by default anywhere in the reviewed core runtime, and this mode is explicitly flagged in-source as "unsafe as it postpones parsing errors such as required fields missing until first access."

### Impact Explanation
Where `LAZY_VERIFY_ON_ACCESS` is explicitly enabled (an opt-in, documented-as-unsafe configuration), a crafted message causes a `RuntimeException` to surface from routine, unguarded read paths (extension getters, `toString`, `equals`, `hashCode`, size computation) instead of from `parseFrom()`. Applications following the documented pattern of catching `InvalidProtocolBufferException` only around parsing will not catch this exception at the point it is thrown, potentially crashing a request-handling thread and causing denial of service for that request/thread, mirroring the CoAPthon3 CWE-502 impact (DoS via mishandled exception on crafted input). It does not provide confidentiality or integrity impact, matching CVE-2018-12679's `C:N/I:N/A:H` profile.

### Likelihood Explanation
Likelihood is Low-to-Medium and conditional: this analog only manifests when an application has explicitly enabled `LAZY_VERIFY_ON_ACCESS` (not the default), uses `MessageSet`-style lazy extensions, and does not wrap every downstream accessor of that field in try/catch. Given the code comment explicitly warns this mode is "unsafe," it is a known/acknowledged tradeoff rather than a silent bug, which reduces its severity as a novel finding compared to the original CoAPthon3 issue (which had no safe default at all).

### Recommendation
- Ensure `LAZY_VERIFY_ON_ACCESS` remains opt-in and is clearly documented as requiring callers to wrap all accessors of lazy/MessageSet extension fields (not just `parseFrom`) in exception handling for `InvalidProtobufRuntimeException`.
- Consider having `getValue()` cache/short-circuit repeated failures without needing callers to special-case a distinct unchecked exception type, or provide a "safe" accessor variant that returns a `Result`/default instance without throwing, for callers who cannot audit every call site.
- Audit other lazily-parsed/deferred-validation code paths (e.g., `LazyFieldLite`) for similar unchecked-exception-at-access-time patterns.

### Proof of Concept
Conceptual reproduction (based on code inspection; not executed in this environment):
1. Enable the unsafe mode: `ExtensionRegistryLite.setLazyExtensionMode(LazyExtensionMode.LAZY_VERIFY_ON_ACCESS)` (mirrors the test setup in `InternalLazyFieldTest`) [6](#0-5) 
2. Build a `RawMessageSet` with an `Item` whose `message` bytes are corrupted/invalid, as done in `LazilyParsedMessageSetTest`: [7](#0-6) 
3. Call `TestMessageSet.parseFrom(inputData, extensionRegistry)` — this succeeds without throwing.
4. Later, unrelated application code calls `messageSet.getExtension(TestMessageSetExtension1.messageSetExtension)` (or `toString()`, `equals()`, etc.) — this throws `InvalidProtobufRuntimeException`, an unchecked exception not anticipated by code that only guards the initial `parseFrom` call.

I was unable to confirm within this index whether any first-party server/RPC framework code path in this checkout enables `LAZY_VERIFY_ON_ACCESS` by default; this is stated as an assumption/limitation rather than a confirmed default-exposure vector.

    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }

  enum LazyExtensionMode {
    EAGER,
    // Caution: This mode is unsafe as it postpone parsing errors such as required fields missing
    // until first access.
    LAZY_VERIFY_ON_ACCESS;
  }

  private static volatile LazyExtensionMode lazyExtensionMode = LazyExtensionMode.EAGER;

  // Override for the lazy extension mode for this specific registry.
  // -1 means fallback to the static lazyExtensionMode
  // 0 means eager
  // 1 means LAZY_VERIFY_ON_ACCESS
  private byte lazyExtensionModeOverride = -1;

  static void setLazyExtensionMode(LazyExtensionMode mode) {
    lazyExtensionMode = mode;
  }

  static LazyExtensionMode getLazyExtensionMode() {
    return lazyExtensionMode;
  }

  boolean lazyExtensionEnabled() {
    if (lazyExtensionModeOverride == 1) {
      return true;
    } else if (lazyExtensionModeOverride == 0) {
      return false;
    }
    return lazyExtensionMode == LazyExtensionMode.LAZY_VERIFY_ON_ACCESS;
  }
