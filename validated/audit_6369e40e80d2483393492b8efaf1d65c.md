### Title
Silent block-rule bypass via unvalidated `field`/`operator` in explicit `conditions`, while legacy `pattern` form always resolves a valid field - (File: `plugins/hookify/core/config_loader.py`)

### Summary
`Rule.from_dict` treats the legacy `pattern` frontmatter field and the newer explicit `conditions` list as semantically equivalent ways to express a rule, but only the legacy path guarantees a valid, matchable field. A `conditions` entry that is missing/misspells `field` or `operator` — reachable via a repo-shipped `.claude/hookify.*.local.md` file or via `/hookify` rule-generation output — silently produces a condition that can never match, which silently neutralizes an `action: block` rule with no load-time error.

### Finding Description
In `Rule.from_dict` [1](#0-0) , the legacy path always derives a non-empty `field` from the `event` (`command`, `new_text`, or `content`) and hardcodes `operator='regex_match'`, guaranteeing the resulting `Condition` is well-formed and functional: [2](#0-1) 

The explicit `conditions` path performs no such validation — it blindly maps whatever dict entries are present via `Condition.from_dict`, which defaults `field` to `''` and `pattern` to `''` if absent: [3](#0-2) [4](#0-3) 

At evaluation time in `rule_engine.py`, `_extract_field` has no handling for `field == ''` for any tool type (`Bash`, `Write`/`Edit`, `MultiEdit`), so it falls through and returns `None`: [5](#0-4) 

`_check_condition` returns `False` when `field_value is None`, and `_rule_matches` requires *all* conditions to match, so a single malformed condition (missing/blank `field`, or an unrecognized `operator`, which also returns `False` at line 178-180) makes the rule permanently non-matching: [6](#0-5) [7](#0-6) 

Critically, `load_rule_file`/`load_rules` only warn on `IOError`/`ValueError`/`KeyError`/`AttributeError`/`TypeError` exceptions, but `.get()` defaults never raise, so a malformed `conditions` entry loads "successfully" with no warning at all: [8](#0-7) . The custom hand-rolled YAML mini-parser in `extract_frontmatter` (inline comma-splitting for dict list items, indentation-based state machine) is also fragile and can drop/misplace keys (e.g., a `pattern` value containing a comma corrupts the inline dict split) [9](#0-8) , providing an additional path for a `field`/`operator` key to be dropped or mis-populated without the rule author (or `/hookify` generation) noticing.

The result: a rule file declaring `action: block` with an explicit `conditions:` list that omits or misspells `field` (or uses a typo'd `operator`) will load without error and will never trigger, while the *same intended policy* expressed via the legacy `pattern:` field would have worked reliably. This is the "same effective security semantics" invariant violation between legacy and explicit rule forms.

### Impact Explanation
A block rule intended to stop a dangerous action (e.g., writing/reading outside an approved path, or a destructive Bash command) can be silently rendered inert by a repo-shipped rule file or a subtly malformed `/hookify`-generated rule, with the user believing protection is active (frontmatter shows `action: block`) when it is not. This directly enables the unauthorized file read/write the block rule was meant to prevent, since `RuleEngine.evaluate_rules` will treat the malformed rule as non-matching and allow the tool call through unimpeded [10](#0-9) .

### Likelihood Explanation
Feasibility is high and requires no special privilege beyond what the attacker model already grants: shipping a rule file in a repository (`.claude/hookify.*.local.md`) or supplying frontmatter that flows through `/hookify` rule generation. No validation anywhere in the loader/engine catches an empty/invalid `field` or unrecognized `operator`, and the failure is completely silent (no warning printed, no exception raised), making it easy to overlook and reliably reproducible.

### Recommendation
- In `Condition.from_dict`, validate that `field` is non-empty and is one of the recognized field names, and that `operator` is one of the supported operators; raise a `ValueError` (which `load_rule_file` already catches and warns about) instead of defaulting to `''`.
- In `Rule.from_dict`, after building `conditions` from the explicit list, verify each condition resolves to a valid field/operator combination for the rule's `event`, mirroring the guarantees of the legacy `pattern` path.
- Emit a load-time warning (or refuse to load) any `action: block` rule that has zero effectively-matchable conditions, so misconfigured/malicious block rules cannot silently pass as active.

### Proof of Concept
Unit test in `plugins/hookify/core/config_loader.py`/`rule_engine.py` test scope:
1. Construct frontmatter A (legacy): `{"name":"r1","enabled":True,"event":"bash","pattern":"rm -rf","action":"block"}` → `Rule.from_dict` → assert `conditions[0].field == "command"`.
2. Construct frontmatter B (explicit, malformed): `{"name":"r1","enabled":True,"event":"bash","conditions":[{"operator":"regex_match","pattern":"rm -rf"}],"action":"block"}` (missing `field`) → `Rule.from_dict` → `conditions[0].field == ""`.
3. Run `RuleEngine().evaluate_rules([rule_A], {"tool_name":"Bash","tool_input":{"command":"rm -rf /"}})` → expect blocking result (`permissionDecision: deny`).
4. Run `RuleEngine().evaluate_rules([rule_B], {"tool_name":"Bash","tool_input":{"command":"rm -rf /"}})` → expect `{}` (no block) despite identical intended policy and `action: block`, demonstrating the differential and the silent bypass.

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
    except Exception as e:
        print(f"Error: Unexpected error parsing {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
        return None

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
