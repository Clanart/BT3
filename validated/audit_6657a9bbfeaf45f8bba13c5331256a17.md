The claimed binding can be restated precisely as an equality that the code is supposed to (but does not) enforce:

`withdrawals.payout_payer_operator_xonly_pk == i` should hold **only if** operator `i` is the one who actually broadcast/funded the payout transaction for that withdrawal. In reality, that column is populated purely by parsing an unsigned OP_RETURN output that the funder of the payout tx can set to *any* value.

### Title
Unauthenticated OP_RETURN payer attribution lets anyone frame an operator into consuming its own finite round/kickoff budget for withdrawals it never funded - (File: `core/src/verifier.rs`, `core/src/database/verifier.rs`, `core/src/task/payout_checker.rs`)

### Summary
`update_finalized_payouts` derives `payout_payer_operator_xonly_pk` solely from the OP_RETURN of a payout transaction, an output that is not covered by the withdrawing user's `SinglePlusAnyoneCanPay` signature and thus fully attacker-controllable. `get_first_unhandled_payout_by_operator_xonly_pk` then blindly trusts this attribution to select which withdrawal an operator's `PayoutCheckerTask` processes next, letting anyone who creates and self-funds their own withdrawal impersonate a target operator as its "payer."

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk = X` should imply "operator X funded this payout," but the code only checks that some transaction spending that withdrawal's fixed UTXO happened to carry `X`'s xonly pubkey bytes in an OP_RETURN output.

- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with output 0 = user payout, output 2 = OP_RETURN containing `operator_xonly_pk`. The only signature on the input (`user_sig`, `SinglePlusAnyoneCanPay`) commits to input 0 and output 0 only — it never commits to the OP_RETURN output, so **anyone who can spend the withdrawal UTXO can put any operator's xonly_pk in the OP_RETURN**, not just the operator who actually pays.
- The withdrawal UTXO's scriptPubkey belongs to whoever calls Citrea `withdraw()`/`safeWithdraw()` for their own withdrawal (`core/src/operator.rs:560-637`, `core/src/citrea.rs:458-496`); an attacker who deposits their own funds and withdraws them can legitimately sign this input themselves.
- On-chain, `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses this OP_RETURN and writes it as `payout_payer_operator_xonly_pk` with **no signature or authorization check** tying the attribution to the named operator (`core/src/verifier.rs:2319-2321`).
- `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) then returns the lowest unhandled `idx` matching that attacker-forged attribution.
- `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-111`) unconditionally trusts this idx, calls `Operator::handle_finalized_payout` (`core/src/operator.rs:839-`), consumes an unused kickoff connector and calls `end_round` — advancing the operator's on-chain `RoundIndex`, a **strictly bounded resource** (`num_round_txs`, enforced in `create_round_nth_txhandler`, `core/src/builder/transaction/operator_collateral.rs:220-236`, which errors past `RoundIndex::Round(paramset.num_round_txs)`).

Because rounds are finite and monotonically advancing (`update_current_round_index(... .next_round())`, `core/src/operator.rs:1219-1225`), an attacker can repeatedly self-fund cheap/self-owned withdrawals and forge OP_RETURNs naming operator X as payer for each, inserting arbitrarily many lower-idx forged entries ahead of X's real, legitimately-fronted withdrawal. Each forged entry burns one of X's finite rounds. If the number of forged entries exceeds X's remaining `num_round_txs`, X's genuine withdrawal reimbursement becomes permanently unprocessable — `is_payout_handled` for that real idx can never be set because X has run out of rounds to ever reach it, meeting "an honest operator permanently unable to be reimbursed."

No existing guard closes this gap: `SECP.verify_schnorr` in `Operator::withdraw` only checks the payout's input signature against the *withdrawing user's* key, never that the OP_RETURN attribution matches the caller; `Verifier::is_kickoff_malicious`/challenge logic only cross-checks kickoff vs. payout operator match (`core/src/operator.rs:1290-1295`), which trivially passes since the forged OP_RETURN and the operator doing the kickoff are the same X; there is no DB uniqueness constraint or signature requirement binding `payout_payer_operator_xonly_pk` to an action actually performed by that operator.

### Impact Explanation
An unprivileged attacker (who only needs to deposit and withdraw their own funds, i.e., pay normal deposit/withdrawal amounts and fees, no operator/verifier privilege) can permanently deny reimbursement to any specific target operator by exhausting that operator's finite round budget with self-funded, falsely-attributed withdrawals. This is repeatable against any operator and, since it doesn't require compromising keys or majority hashrate, is fully within scope of an unprivileged Bitcoin-broadcasting/Citrea-withdrawing attacker. This matches the Critical category "an honest operator permanently unable to be reimbursed."

### Likelihood Explanation
Preconditions are minimal: the attacker needs an existing bridge deposit and withdrawal cycle (attacker pays normal deposit/bridge amounts, largely self-funded and mostly recoverable minus fees), and knowledge of the target operator's public xonly_pk (public information). No majority hashrate, no key compromise, no privileged role is required — only the ability to build and broadcast a standard payout transaction with an arbitrary OP_RETURN, which is explicitly within the stated attacker capability set. The number of rounds (`num_round_txs`) is a fixed, typically modest paramset value, making exhaustion feasible with a bounded, repeatable number of forged withdrawals.

### Recommendation
Bind `payout_payer_operator_xonly_pk` to cryptographic proof that the named operator actually authorized/funded the payout — e.g., require the payout tx's OP_RETURN commitment to be covered by an operator signature (change sighash or add a second operator-signed input/output), or require operators to co-sign/commit to their own payout broadcasts via a channel verifiers can authenticate, rather than trusting unsigned OP_RETURN bytes.

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
