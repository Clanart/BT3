### Title
Attacker-controlled `WWW-Authenticate` realm spoofs GitHub/Enterprise sign-in prompt and account binding - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The Solidity report's broken invariant is that a privileged action ("withdraw") is authorized based on the wrong/attacker-influenced identity (`msg.sender`'s approval acting on `owner`'s escrowed request), letting an attacker manufacture a false trust relationship and drain value that should have stayed segregated per-account. The closest reachable analog in GitHub Desktop is in the trampoline credential helper's endpoint-classification logic, where a value that is fully controlled by the remote server (the `WWW-Authenticate` HTTP header content forwarded by Git) is used to decide whether Desktop should treat an arbitrary host as a "GitHub/Enterprise" endpoint and initiate the GitHub sign-in / account-binding UI for it.

### Finding Description
When Git needs credentials for a remote, it invokes Desktop's credential helper, which classifies the target host via `getEndpointKind`: [1](#0-0) 

This function trusts `wwwauth[...]` header content that Git captured from the **remote server's own HTTP response** and forwarded verbatim to the credential helper: [2](#0-1) 

If the header contains `realm="GitHub"`, the endpoint is classified as `'enterprise'` — with no verification of TLS identity, no check that the host is a real GitHub Enterprise Server, and no confirmation against any allow-list; a plain HTTP(S) server the attacker fully controls can emit this header on a 401 response to any Git request Desktop makes to it (e.g. from `git fetch`/`clone`/`push` against a remote the attacker supplied, or a submodule URL embedded in a cloned repository).

That classification then drives `getCredential`, which — for any endpoint classified as non-`'generic'` where no existing account already matches — automatically shows the user the native "Sign in to GitHub Enterprise" dialog for the **attacker's arbitrary URL**: [3](#0-2) 

If the user completes this Desktop-initiated sign-in (a very ordinary action in this app whenever pushing/pulling from an unauthenticated private-looking remote), a real `Account` gets created and persisted with `endpoint` equal to the attacker-controlled host, via `credWithAccount`/`ui.promptForGitHubSignIn`. On subsequent credential lookups for that same origin, `findGitHubTrampolineAccount` matches purely by origin equality: [4](#0-3) 

so the stored token/PAT for that "account" will be handed back to Git (and thus to the attacker's server) for that origin on any future request — this is functionally credential exfiltration to an attacker-chosen host, achieved purely by controlling the git remote/proxy HTTP response, exactly the class of attacker capability called out as valid in the task's threat model.

### Impact Explanation
A malicious or compromised git remote/proxy (including one reached via a submodule URL embedded in an otherwise-innocuous cloned repository, since Desktop performs `--recurse-submodules` fetches automatically) can trigger Desktop's GitHub/Enterprise sign-in and account-binding flow for a host it fully controls, and can subsequently receive whatever credential/PAT the user enters or that Desktop attaches to that account on later requests to the same origin. This is a credential/token exfiltration and unauthorized-account-binding primitive, matching "unauthorized OAuth or account binding" / "credential exfiltration" in the accepted impact categories.

### Likelihood Explanation
Medium. Exploitation requires the victim to run an ordinary Desktop operation (clone/fetch/push, including transitive submodule fetches) against an attacker-controlled remote or a remote reachable through an attacker-controlled/MITM proxy, and then to interact with what looks like a legitimate, Desktop-native "Sign in to GitHub Enterprise" prompt — a normal and expected flow in this application, not an unnatural step. No local access, prior malware, or leaked credentials are required; the header value is entirely attacker-supplied over the network path Desktop already establishes for the git operation.

### Recommendation
Do not classify a host as `'enterprise'`/GitHub based solely on the `wwwauth[...]` header content forwarded from the remote's HTTP response. At minimum:
- Require confirmation via an actual authenticated API probe (e.g. successfully calling a known GitHub/GHE metadata endpoint over TLS with certificate validation) before treating a host as GitHub-capable, rather than trusting a self-reported `realm=` string.
- Scope any auto-triggered sign-in prompts to hosts explicitly added by the user (e.g. via Preferences > Accounts) rather than any host encountered during a git network operation, or clearly surface the exact origin being authenticated in a way that cannot be spoofed by realm text alone.
- Ensure `findGitHubTrampolineAccount`/credential issuance for enterprise accounts additionally validates that the endpoint was explicitly configured by the user, not merely "an origin we've seen before that responded with a particular header."

### Proof of Concept
1. Attacker sets up an HTTP(S) server and gives the victim a URL to clone/fetch (directly, or as a submodule referenced from an otherwise normal-looking public repo).
2. Attacker's server responds to Git's credential probe with `WWW-Authenticate: Basic realm="GitHub"` on a 401.
3. Victim runs a normal Desktop operation (`clone`/`fetch`/`pull`, which triggers `--recurse-submodules` fetches) against this remote.
4. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-165`) classifies the attacker's host as `'enterprise'`.
5. `getCredential` (`trampoline-credential-helper.ts:93-125`) finds no existing account for that endpoint and calls `ui.promptForGitHubSignIn(endpoint)` with the attacker's URL — Desktop shows its native "Sign in to GitHub Enterprise" dialog pointed at the attacker's server.
6. If the victim signs in (a routine, expected action in this flow), an `Account` bound to the attacker's endpoint is stored; subsequent `findGitHubTrampolineAccount` origin matches (`find-account.ts:20-29`) cause Desktop to hand the associated token back to that same attacker-controlled origin on future requests.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
