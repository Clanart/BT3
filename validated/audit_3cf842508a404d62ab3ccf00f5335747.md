### Title
Quadratic-complexity option-set-check during FileDescriptorProto option interpretation - (File: `src/google/protobuf/option_interpreter.cc`)

### Summary
`OptionInterpreter::ExamineIfOptionIsSet` performs a full linear scan over an `UnknownFieldSet`'s fields (`unknown_fields.field_count()`) for every single option field being interpreted, in order to detect "option already set" duplicates. Because this check runs once per `UninterpretedOption` while options/unknown-fields accumulate across the whole options message, a `.proto`/`FileDescriptorProto` with many repeated custom-option entries drives this into O(n²) behavior, structurally analogous to the js-yaml `!!omap` `addItem()` O(n) per-insertion duplicate check that produced O(n²) total parse time.

### Finding Description
`ExamineIfOptionIsSet` is explicitly documented as doing linear work: [1](#0-0) 
which loops `for (int i = 0; i < unknown_fields.field_count(); i++)` to find whether `innermost_field->number()` (or an intermediate field) is already present, and recurses into sub-`UnknownFieldSet`s the same way: [2](#0-1) 

The comment right above the function states the failed invariant explicitly: *"We do linear searches of the UnknownFieldSet and its sub-groups. This should be fine since it's unlikely that any one options structure will contain more than a handful of options."* This is precisely the same false assumption underlying the js-yaml bug (`omapTag.addItem()`'s linear scan "should be fine" for small n) — an unbounded, attacker-influenced count of entries invalidates the assumption.

`ExamineIfOptionIsSet` is called (via `InterpretSingleOption`, driven by `OptionInterpreter::InterpretOptionExtensions` / `InterpretNonExtensionOptions`, per [3](#0-2) ) once for every `UninterpretedOption` entry present in a message's `options` field. Each such call scans the entire `UnknownFieldSet` already accumulated for that options message (which grows by one field per successfully-interpreted prior option). A `FileDescriptorProto`/`.proto` source containing `n` repeated custom-option entries on the same options message (e.g. many entries of a repeated custom option, or many distinct extension options on the same declaration) therefore costs 1+2+…+n ≈ O(n²) total scanning work, matching the js-yaml pattern exactly (linear per-insertion scan → quadratic total).

### Impact Explanation
Exposure assumption: this is not reachable from the core binary/ProtoJSON wire-format parsing APis (`ParseFrom*`/`MergeFrom*`), which for maps/extensions/unknown-fields use hashed/sorted/O(1)-amortized structures (`ExtensionSet`'s sorted flat array with `Insert`, `UnknownFieldSet`'s simple append, and the JSON map parser's `absl::flat_hash_set` for duplicate key checks) — I verified these do **not** suffer from the linear-per-insert defect and are not vulnerable analogs. The exposure here is instead through **descriptor building**: any consuming application that builds `Descriptor`s/`FileDescriptor`s from untrusted `.proto` text or untrusted `FileDescriptorProto` (e.g. schema-registry services, reflection-based dynamic message tooling, plugins that call `DescriptorPool::BuildFile`) triggers `OptionInterpreter` on the file's options. A crafted schema with many repeated custom-option entries in one options block can multiply the cost of this specific check quadratically, producing a CPU stall proportional to the square of the option count. Impact is bounded to CPU-time DoS (CWE-407/770) during descriptor construction, matching the Medium severity of the original report; there is no memory-safety, corruption, or disclosure impact since the container is only read, never overrun.

### Likelihood Explanation
Likelihood is limited by the fact that the attacker-controlled input must be a `.proto` file or `FileDescriptorProto`, not the mainstream `ParseFrom`/`ProtoJSON` public parse APIs referenced in the analog rules — descriptor-building from arbitrary/untrusted schemas is a narrower, less common attack surface than parsing untrusted message bytes against a trusted schema. It requires an application to accept attacker-supplied schemas (protoc-like services, dynamic reflection registries) and run them through `DescriptorPool::BuildFile`/`compiler::Parser`. Where that surface exists, triggering the quadratic path only requires a normal, valid, bounded-size `.proto` payload with many repeated custom-option entries under one options message — no malformed input or privilege is needed.

### Recommendation
Replace the linear field_count() scans in `ExamineIfOptionIsSet` with an O(1) lookup keyed by field number (e.g., an `absl::flat_hash_set<int>`/`flat_hash_map<int, index>` populated as fields are added to each `UnknownFieldSet` used for option interpretation), mirroring the recommended js-yaml fix of replacing the array scan with a `Set`. Since `UnknownFieldSet` field numbers can repeat by wire-format design, the tracking structure should be maintained specifically for the "already set" check in the option-interpretation path (not necessarily on `UnknownFieldSet` itself), so ordinary repeated/unknown-field parsing semantics are unaffected.

### Proof of Concept
Not independently executed (no code-execution tool available in this environment); this is a static-analysis-derived finding. A reproduction would consist of:
1. Constructing a `.proto` (or `FileDescriptorProto`) declaring a message/field/etc. with `n` repeated entries of a single custom (extension) option applied to the same declaration (each occurrence being a distinct `UninterpretedOption` in the source `options` field).
2. Feeding this to `google::protobuf::compiler::Parser` / `DescriptorPool::BuildFile`, which invokes `OptionInterpreter::InterpretOptionExtensions`/`InterpretNonExtensionOptions` → `InterpretSingleOption` → `ExamineIfOptionIsSet` once per entry.
3. Measuring wall-clock time for increasing `n` (e.g., 1k/5k/10k/20k) and confirming superlinear (≈quadratic) growth, analogous to the reported js-yaml timings (9ms→73ms→255ms→997ms).

bool OptionInterpreter::ExamineIfOptionIsSet(
    std::vector<const FieldDescriptor*>::const_iterator
        intermediate_fields_iter,
    std::vector<const FieldDescriptor*>::const_iterator intermediate_fields_end,
    const FieldDescriptor* innermost_field, const std::string& debug_msg_name,
    const UnknownFieldSet& unknown_fields) {
  // We do linear searches of the UnknownFieldSet and its sub-groups.  This
  // should be fine since it's unlikely that any one options structure will
  // contain more than a handful of options.

  if (intermediate_fields_iter == intermediate_fields_end) {
    // We're at the innermost submessage.
    for (int i = 0; i < unknown_fields.field_count(); i++) {
      if (unknown_fields.field(i).number() == innermost_field->number()) {
        return AddNameError([&] {
          return absl::StrCat("Option \"", debug_msg_name,
                              "\" was already set.");
        });
      }
    }
    return true;
  }

  for (int i = 0; i < unknown_fields.field_count(); i++) {
    if (unknown_fields.field(i).number() ==
        (*intermediate_fields_iter)->number()) {
      const UnknownField* unknown_field = &unknown_fields.field(i);
      FieldDescriptor::Type type = (*intermediate_fields_iter)->type();
      // Recurse into the next submessage.
      switch (type) {
        case FieldDescriptor::TYPE_MESSAGE:
          if (unknown_field->type() == UnknownField::TYPE_LENGTH_DELIMITED) {
            UnknownFieldSet intermediate_unknown_fields;
            if (intermediate_unknown_fields.ParseFromString(
                    unknown_field->length_delimited()) &&
                !ExamineIfOptionIsSet(intermediate_fields_iter + 1,
                                      intermediate_fields_end, innermost_field,
                                      debug_msg_name,
                                      intermediate_unknown_fields)) {
              return false;  // Error already added.
            }
          }
          break;

        case FieldDescriptor::TYPE_GROUP:
          if (unknown_field->type() == UnknownField::TYPE_GROUP) {
            if (!ExamineIfOptionIsSet(intermediate_fields_iter + 1,
                                      intermediate_fields_end, innermost_field,
                                      debug_msg_name, unknown_field->group())) {
              return false;  // Error already added.
            }
          }
          break;

        default:
          ABSL_LOG(FATAL) << "Invalid wire type for CPPTYPE_MESSAGE: " << type;
          return false;
      }
    }
  }
  return true;
}
