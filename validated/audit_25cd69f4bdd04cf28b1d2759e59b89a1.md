Confirmed recursion chain: `AccountKeySerializer.DecodeRLP` (`blockchain/types/accountkey/account_key_serializer.go:61-73`) dispatches to the concrete key's `DecodeRLP`. When the key type is `AccountKeyTypeRoleBased`, this calls `AccountKeyRoleBased.DecodeRLP` (`blockchain/types/accountkey/account_key_role_based.go:120-138`), which for every sub-key element calls `rlp.DecodeBytes(b, &serializer)` on a fresh `AccountKeySerializer`, which can again resolve to `AccountKeyTypeRoleBased` and recurse into `AccountKeyRoleBased.DecodeRLP` again — this decode-time recursion has no depth limit at all, unlike the `RoleLast`/`IsCompositeType`/`ErrNestedCompositeType` checks in `CheckInstallable`/`CheckUpdatable` (`account_key_role_based.go:211-269`) and `checkAccountKeyZeroValues` (`api/api_kaia.go:176-199`), which only run **after** decoding has already succeeded.

### Title
Unbounded recursive RLP decoding of nested `AccountKeyRoleBased` causes stack-overflow DoS - (File: blockchain/types/accountkey/account_key_role_based.go)

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively decodes each sub-key through `AccountKeySerializer.DecodeRLP`, which can itself resolve to another `AccountKeyRoleBased`, and so on, with no depth limit enforced during decoding.

### Finding Description
`AccountKeySerializer.DecodeRLP` reads a key type then calls `s.Decode(serializer.key)`, which for `AccountKeyTypeRoleBased` invokes `AccountKeyRoleBased.DecodeRLP` [1](#0-0) . `AccountKeyRoleBased.DecodeRLP` decodes an array of raw-encoded sub-keys and, for each one, allocates a new `AccountKeySerializer` and calls `rlp.DecodeBytes` on it, which can again dispatch into `AccountKeyRoleBased.DecodeRLP` [2](#0-1) . The only defense against nested `RoleBased` keys — `IsCompositeType()`/`ErrNestedCompositeType` in `CheckInstallable`/`CheckUpdatable` [3](#0-2)  and `checkAccountKeyZeroValues` in the JSON-based `EncodeAccountKey` API [4](#0-3)  — are only executed after the RLP payload has been fully decoded into Go structures. This is structurally the same bug class as CVE-2025-70955: a nesting/recursion primitive (there, VM continuations/jumps; here, RLP-encoded account-key structures) that is only bounded by a *post-hoc* semantic check rather than being bounded at decode time, allowing an attacker to grow the native call stack far beyond any intended logical limit using a compact, low-cost input, independent of gas/computation-cost accounting.

### Impact Explanation
A crafted `TxTypeAccountUpdate` / `TxTypeFeeDelegatedAccountUpdate` (or any transaction type carrying an `AccountKey` field) with a deeply nested chain of `AccountKeyRoleBased` sub-keys, or a raw RLP blob submitted to the public `kaia_decodeAccountKey` RPC method [5](#0-4) , will drive `AccountKeyRoleBased.DecodeRLP` into unbounded Go-level recursion during transaction pool admission, block validation, or the RPC call itself. Because each recursion level is decoded before any composite-type rejection occurs, an attacker can exhaust the native stack of a validator/full node processing the transaction or serving the RPC call, causing a process crash (goroutine stack-overflow panic is unrecoverable in Go) — a Denial-of-Service impact consistent with the "High/Critical, unauthorized state divergence or availability loss from a single submitted transaction/RPC call" criteria.

### Likelihood Explanation
The RLP payload for a deeply nested `AccountKeyRoleBased` chain is small (each level of nesting is a few bytes of key-type tag plus a length-prefixed byte string), so an attacker can achieve very deep recursion (thousands of levels) cheaply, well before any gas-related or size-related transaction limits (e.g., `MaxNumKeysForMultiSig`, tx size caps) would stop the encoding. This is reachable by any unprivileged transaction sender (`TxPool.AddRemote`) or public RPC caller (`kaia_decodeAccountKey`), requiring no special privileges, making likelihood high once such a payload is crafted.

### Recommendation
Enforce an explicit recursion/nesting depth limit inside `AccountKeySerializer.DecodeRLP` / `AccountKeyRoleBased.DecodeRLP` (e.g., pass a depth counter through decoding and reject once a `RoleBased` key is encountered inside a nested decode, mirroring the semantic `ErrNestedCompositeType` check but applied *during* decode rather than after), and likewise guard the JSON `UnmarshalJSON` path similarly to prevent unbounded recursion prior to validation.

### Proof of Concept
Construct nested `AccountKeySerializer` RLP bytes recursively (conceptually):
```
level0 = RLP([keyType=RoleBased, RLP([ RLP(AccountKeySerializer(level1)) ])])
level1 = RLP([keyType=RoleBased, RLP([ RLP(AccountKeySerializer(level2)) ])])
...
levelN (base case) = RLP([keyType=Public, RLP(pubkey)])
```
Repeat nesting thousands of times, then submit `level0` bytes either as the `AccountKey` field of a `TxTypeAccountUpdate` transaction via `TxPool.AddRemote`, or as the argument to `kaia_decodeAccountKey`. Decoding will recurse through `AccountKeyRoleBased.DecodeRLP` → `AccountKeySerializer.DecodeRLP` → `AccountKeyRoleBased.DecodeRLP` for each nesting level before any `ErrNestedCompositeType` check is reached, exhausting the goroutine stack and crashing the node process.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func checkAccountKeyZeroValues(key accountkey.AccountKey, isNested bool) error {
	switch key.Type() {
	case accountkey.AccountKeyTypeWeightedMultiSig:
		multiSigKey, _ := key.(*accountkey.AccountKeyWeightedMultiSig)
		if multiSigKey.Threshold == 0 {
			return errors.New("invalid threshold of the multiSigKey")
		}
		for _, weightedKey := range multiSigKey.Keys {
			if weightedKey.Weight == 0 {
				return errors.New("invalid weight of the multiSigKey")
			}
		}
	case accountkey.AccountKeyTypeRoleBased:
		if isNested {
			return errors.New("roleBasedKey cannot contains a roleBasedKey as a role key")
		}
		roleBasedKey, _ := key.(*accountkey.AccountKeyRoleBased)
		for _, roleKey := range *roleBasedKey {
			if err := checkAccountKeyZeroValues(roleKey, true); err != nil {
				return err
			}
		}
	}
	return nil
