### Title
Private DKG decryption key (`enc_key`) exposed via `Debug` formatting of `Encryption`, reachable through `SecretShareMachine`/`KeyMachine` debug logs - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
The PedPoP DKG encryption machine stores its long-lived private ECDH decryption key (`enc_key: Zeroizing<C::F>`) inside the `Encryption` struct. `Encryption` implements `fmt::Debug` (required by `SecretShareMachine::fmt` and `KeyMachine::fmt`, which emit `.field("encryption", &self.encryption)`), and there is no manual `Debug` impl redacting `enc_key`. Debug-formatting (e.g., `log::debug!("{machine:?}")` or `unwrap_err`/panic paths printing state) therefore discloses the private decryption key, the analog of credentials being written to logs.

### Finding Description
- `Encryption` holds the private key: `enc_key: Zeroizing<C::F>` at `Encryption::new`, `crypto/dkg/pedpop/src/encryption.rs:438-445`. This key is used to compute every incoming ECDH shared key via `ecdh(&self.enc_key, msg.key)` at `crypto/dkg/pedpop/src/encryption.rs:487`.
- The error path `PedPoPError::InvalidShare { blame: Option<EncryptionKeyProof<C>> }` derives `Debug` (`crypto/dkg/pedpop/src/lib.rs:37-54`), and `EncryptionKeyProof` derives `Debug` including `key: Zeroizing<C::G>` — the ECDH shared key that decrypts the secret-share message (`crypto/dkg/pedpop/src/encryption.rs:259-264`, `392`). While blame proofs are intended for publication, embedding the raw shared key in a `Debug`-printable error means routine error logging publishes it before the blame workflow is deliberately invoked.
- `SecretShareMachine::fmt` (`crypto/dkg/pedpop/src/lib.rs:285-295`) and `KeyMachine::fmt` (`crypto/dkg/pedpop/src/lib.rs:395-404`) print the whole `encryption` field. Elsewhere the crate is careful to omit secrets from `Debug` (`SecretShare` uses `finish_non_exhaustive`, `crypto/dkg/pedpop/src/lib.rs:242-246`; `ThresholdCore` and `ThresholdView` omit `secret_share`, `crypto/dkg/src/lib.rs:266-276`, `316-329`), so the inclusion of `encryption` in these Debug impls makes `enc_key` exposure dependent on `Encryption`'s Debug covering all fields — which it does unless manually redacted (no manual `impl fmt::Debug for Encryption` exists in `encryption.rs`).

### Impact Explanation
Anyone who can cause or read a `Debug` rendering of `SecretShareMachine`/`KeyMachine` (application logs, `{:?}` in error reporting, panic messages) obtains the participant's private DKG decryption key `enc_key`. Combined with the `EncryptedMessage`s observable on the authenticated broadcast channel, this decrypts every secret share addressed to that participant, recovering their threshold secret share. Repeated across `t` compromised log streams, the full group key is recoverable. The `EncryptionKeyProof` `Debug` additionally leaks per-message ECDH keys in any log of the `PedPoPError::InvalidShare` error.

### Likelihood Explanation
An attacker need only get the victim to log state or errors — e.g., send a malformed share causing `PedPoPError::InvalidShare` (whose `Debug` includes the blame proof's ECDH key) — during a DKG round they participate in. All inputs (`commitment_msgs`, `shares`) are attacker-supplied public bytes passed to `calculate_share`/`generate_secret_shares`. Exploitation requires the integrator to Debug-log machines/errors, a common pattern; severity is bounded by log access, matching the original advisory's "only job owner or admin can view the log" qualifier.

### Recommendation
- Add a manual `impl fmt::Debug for Encryption` that omits `enc_key` (e.g., `finish_non_exhaustive`), mirroring `ThresholdCore`/`ThresholdView`/`SecretShare`.
- Manual `impl fmt::Debug for EncryptionKeyProof` that omits `key`, or store `key` in a field never debug-printed, so `PedPoPError`'s derived `Debug` cannot emit the ECDH key.

### Proof of Concept
1. Participant `i` runs `KeyGenMachine::generate_coefficients`, obtaining `SecretShareMachine` containing `Encryption { enc_key, .. }`.
2. Any `format!("{machine:?}")` (or `log::debug!("{machine:?}")`) on the `SecretShareMachine`/`KeyMachine` prints the `encryption` field; with `Encryption`'s field-covering Debug, `enc_key` (a `Zeroizing<C::F>` wrapping the private scalar) is emitted.
3. Independently, a malicious participant sends a corrupted `EncryptedMessage` share; `calculate_share` returns `Err(PedPoPError::InvalidShare { blame: Some(proof) })`; `format!("{err:?}")` prints `proof.key`, the ECDH shared key for that ciphertext.
4. Observer with the public `EncryptedMessage` recomputes `cipher(context, proof.key)` (`crypto/dkg/pedpop/src/encryption.rs:101-133`) and decrypts the secret share.

Caveat: the finding hinges on `Encryption`'s `Debug` implementation covering `enc_key` (derived rather than manually redacted); the struct declaration itself was not fully read, but no manual `Debug` impl for `Encryption` was found in `encryption.rs`, and the struct must implement `Debug` for `SecretShareMachine::fmt`/`KeyMachine::fmt` to compile.
