### Title
`SignableTransaction` ignores the caller-supplied `data` (OP_RETURN) output in its weight, fee, and standardness calculations — transactions can be signed that are unbroadcastable or underpay the requested feerate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` accepts a user-controlled `data: Option<Vec<u8>>` parameter (up to 80 bytes) that is appended as an OP_RETURN `TxOut`. However, `calculate_weight_vbytes` is only ever invoked with `payments` and `change` — the OP_RETURN output is never included in the transaction built inside that function. As a result, `weight`, `vbytes`, `needed_fee`, the `TooLowFee` minimum-relay check, and the `MAX_STANDARD_TX_WEIGHT` standardness check are all computed on a transaction that is smaller than the one actually signed.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, the `data` output is pushed to `tx_outs` (lines 193–202) before the weight/feerate calculations, but the helper `calculate_weight_vbytes(inputs, payments, change)` reconstructs a transaction containing only `payments` and the optional `change` output (lines 68–99) — it has no knowledge of `data` at all:

- Line 204: `let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);` — excludes the ~8 + 1 + 1 + 80 ≈ 90-byte OP_RETURN output.
- Line 206/227: `needed_fee` / `fee_with_change` are `fee_per_vbyte` times an undercounted `vbytes`.
- Line 211: the `TooLowFee` check compares against `DEFAULT_MIN_RELAY_TX_FEE` using the undercounted size, so a transaction can pass the check while its true feerate is below the relay minimum.
- Line 241: `if weight > MAX_STANDARD_TX_WEIGHT` uses the undercounted `weight`, so a transaction whose actual weight exceeds the 400,000 WU standardness limit is accepted and signed.
- Line 215: `NotEnoughFunds` is checked against the understated `needed_fee`.

The class maps directly onto the reported bug shape: a fixed/under-scoped resource bound is used while a caller-supplied parameter that increases the real cost (analogous to `_minGasLimit`) is ignored, and — like the non-replayable deposit — the produced artifact is executed once: the FROST ceremony signs `Prevouts::All` sighashes for a transaction the Bitcoin network may refuse to relay (`send.rs` lines 373–390), with no mechanism to bump the fee since `change` (when present) consumes everything above `needed_fee`.

### Impact Explanation
Medium. If `data` is supplied near the size or feerate boundaries, the signed transaction is either (a) non-standard (`weight > MAX_STANDARD_TX_WEIGHT` on the real tx) or (b) below the minimum relay feerate, so it cannot be broadcast. The inputs are not burned, but they are committed to a FROST-produced transaction that is dead on arrival — the spends are effectively locked until a fresh multisig ceremony is run, and any caller relying on `needed_fee()` underpays the fee they requested. When no change output exists the mismatch is small, but with change the entire remainder is captured by the understated fee computation.

### Likelihood Explanation
Reachable only by an unprivileged party who can cause a `SignableTransaction::new` call with attacker-chosen `data` while inputs sit near the weight limit (up to ~520 inputs/outputs per `processor/src/networks/bitcoin.rs` `MAX_INPUTS`/`MAX_OUTPUTS`) or near the minimum relay feerate. Serai's own processor always passes `None` for `data` (`processor/src/networks/bitcoin.rs` lines 446–452), so exploitation requires an integrator exposing the `data` parameter. The coding error is deterministic whenever `data` is used.

### Recommendation
Include the OP_RETURN output in `calculate_weight_vbytes` — e.g., append `TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) }` to the reconstructed transaction (or accept `data` as a parameter), so `vbytes`, `needed_fee`, `TooLowFee`, and the `MAX_STANDARD_TX_WEIGHT` check all reflect the transaction actually signed. Also recompute `needed_fee`/`weight` on the final `tx_outs` before constructing `SignableTransaction` as a sanity check.

let stx = SignableTransaction::new(

    Some(change_script),

// The `TooLargeTransaction` check passed using weight WITHOUT the OP_RETURN

// the signed transaction is unbroadcastable.
