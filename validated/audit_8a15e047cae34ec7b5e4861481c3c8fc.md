### Title

Untrusted `ReceivedOutput` deserialization bypasses the scanner-derived offset/output invariant - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary

`ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without proving that they form a wallet-controlled output. `Scanner` normally establishes this invariant by selecting only transaction outputs whose `script_pubkey` maps to a registered offset and by computing their true outpoint. [1](#0-0)  Deserialization reconstructs the same type without any equivalent authentication or consistency check. [2](#0-1) 

`SignableTransaction::multisig` only verifies that the claimed offset derives the claimed script; it does not verify that the claimed `OutPoint` exists or that its on-chain value matches the decoded `TxOut`. [3](#0-2) 

### Finding Description

An attacker-controlled serialization can set `offset` to zero and set `output.script_pubkey` to the wallet's base Taproot script. This satisfies the only consistency check performed later by `SignableTransaction::multisig`, because the wallet key offset by zero derives exactly that script. [3](#0-2) 

The attacker can simultaneously use a nonexistent outpoint or the outpoint of a lower-value output and claim an arbitrarily larger value in the embedded `TxOut`. `SignableTransaction::new` trusts that embedded value when calculating available funds and trusts the supplied outpoint when constructing transaction inputs. [4](#0-3) 

During signing, the forged `TxOut` is also committed through `Prevouts::All`, so the wallet can produce a signature for a transaction whose stated prevout amount or outpoint does not correspond to a spendable chain output. [5](#0-4) 

### Impact Explanation

An attacker who can supply serialized `ReceivedOutput` data can cause the wallet to report nonexistent or inflated funds as received. The wallet will accept the object as spendable, construct a transaction, and can produce signatures for it, but consensus validation will reject the transaction because the referenced output is absent or the prevout value committed in the Taproot sighash is incorrect. [6](#0-5) [5](#0-4) 

This can poison wallet balance/accounting state and trigger unnecessary threshold-signing rounds for outputs that cannot actually be spent.

### Likelihood Explanation

Exploitation requires an application to deserialize attacker-controlled bytes through `ReceivedOutput::read`; the issue is not reachable merely by sending a Bitcoin transaction to a `Scanner`. [2](#0-1)  If such bytes can be written into a wallet cache, database, synchronization message, or other persisted scan result, no cryptographic work or wallet secret is required.

The base-script bypass is deterministic because the scanner registers the wallet's base key with `Scalar::ZERO`. [7](#0-6) 

### Recommendation

Do not treat deserialized `ReceivedOutput` values as scanner-authenticated facts. Either:

- keep `ReceivedOutput` construction private to authenticated scan results and serialize it only through integrity-protected storage/messages; or
- expose a scanner-aware decoder that re-derives `p2tr_script_buf(scanner_key + G * offset)`, compares it with the embedded `TxOut`, and validates that the `OutPoint` resolves to that exact `TxOut` through authenticated chain data.

`ReceivedOutput::read` should also be documented or typed as syntax-only deserialization, not proof of receipt.

### Proof of Concept

```rust
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut, Txid,
  hashes::Hash,
};
use k256::Scalar;
use serai_bitcoin::wallet::{
  p2tr_script_buf, ReceivedOutput, SignableTransaction,
};

// `keys` is the victim's ThresholdKeys<Secp256k1>.
let wallet_script = p2tr_script_buf(keys.group_key()).unwrap();

let fake = TxOut {
  // The wallet did not necessarily receive this amount.
  value: Amount::from_sat(100_000),
  // Still passes the later multisig check because offset 0 derives this script.
  script_pubkey: wallet_script,
};

let fake_outpoint = OutPoint::new(Txid::all_zeros(), 0);

let mut serialized = Vec::new();
serialized.extend(Scalar::ZERO.to_bytes());
serialized.extend(bitcoin::consensus::serialize(&fake));
serialized.extend(bitcoin::consensus::serialize(&fake_outpoint));

let forged = ReceivedOutput::read(&mut serialized.as_slice()).unwrap();

// Attacker-controlled payment destination and amount.
let attacker_script = ScriptBuf::new_op_return(&[]);
let spend = SignableTransaction::new(
  vec![forged],
  &[(attacker_script, 546)],
  None,
  None,
  1,
).unwrap();

// The only local ownership check succeeds because offset zero derives
// the wallet script embedded in the forged TxOut.
assert!(spend.multisig(&keys).is_some());
```

The resulting transaction attempts to spend `Txid::all_zeros():0`; signing commits to the forged `100_000`-sat prevout through `Prevouts::All`, but the claimed funds are not spendable unless a matching on-chain output actually exists.
