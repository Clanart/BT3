### Title
`MasterMagpie.emergencyWithdraw()` skips reward harvesting, causing permanent loss of pending MGP and bonus-token rewards - (File: rewards/MasterMagpie.sol)

### Summary
`emergencyWithdraw()` in `MasterMagpie.sol` reduces a user's `user.amount`/`user.available` and recomputes `user.rewardDebt` without first snapshotting the user's already-accrued MGP and bonus-token rewards, unlike the normal withdrawal path. This permanently erases yield the user had already earned but not yet claimed at the moment of the emergency exit.

### Finding Description
The normal withdrawal path (`_withdraw` → `_harvestAndUnstake`) always harvests pending rewards **before** mutating `user.amount`/`user.available`: [1](#0-0) 

Specifically it calls `_harvestMGP` (which credits `unClaimedMgp[_stakingToken][_account]` based on the user's balance *before* the withdrawal) and `_harvestBaseRewarder` (which calls the rewarder's `updateFor(_account)` to snapshot `userRewards[rewardToken][_account]` using the pre-withdrawal `balanceOf`), and only afterwards decrements `user.amount`/`user.available` and recomputes `rewardDebt`.

`emergencyWithdraw()`, however, skips both of these harvest calls entirely: [2](#0-1) 

It directly zeroes `user.available`, decrements `user.amount`, and recomputes `rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12` using the **already-reduced** `user.amount`. Any MGP reward accrued between the user's last checkpoint and the emergency withdrawal (which should have been the difference between old `user.amount * accMGPPerShare` and old `rewardDebt`) is silently discarded because the debt is recalculated post-decrement instead of being harvested first.

The same problem affects bonus-token rewards. `BaseRewardPoolV2.balanceOf()` reads live from `MasterMagpie.stakingInfo()`: [3](#0-2) 

Since `emergencyWithdraw()` never calls `rewarder.updateFor(_account)` before reducing the user's staked amount, the next time `_updateFor`/`earned()` runs for that account it computes `_earned(_account, rewardToken, userShare)` using the user's now-reduced `balanceOf`, `_earned` being: [4](#0-3) 

Because `userRewardPerTokenPaid` was never updated at the higher pre-withdrawal balance, the bonus-reward accrual since the user's last checkpoint is computed against a smaller share than what actually earned it, permanently understating (losing) rewards that had already accrued to the user's larger balance up to the point of emergency withdrawal.

### Impact Explanation
Any user who calls `emergencyWithdraw()` permanently loses MGP rewards accrued since their last deposit/withdraw/claim checkpoint, and permanently loses (or has understated) bonus-token rewards tracked by the pool's `BaseRewardPoolV2`/`vlMGPBaseRewarder`/`mWOMSVBaseRewarder`. This is unclaimed yield that becomes permanently unrecoverable for the user, since `user.rewardDebt` and the rewarder's `userRewardPerTokenPaid` checkpoints are advanced past the accrual without crediting it anywhere (no `unClaimedMgp` credit, no `userRewards` credit).

### Likelihood Explanation
The function is directly callable by any regular user with a pool balance and requires no privileged role — only that the contract is paused (a normal operational state, not an admin attack), which is explicitly the intended use case for `emergencyWithdraw()`. Any user who has partially accrued rewards and calls this function during a pause will trigger the loss deterministically, every time.

### Recommendation
Call `_harvestMGP(_stakingToken, msg.sender)` and `_harvestBaseRewarder(_stakingToken, msg.sender)` (or the rewarder's `updateFor`) inside `emergencyWithdraw()` **before** mutating `user.amount`/`user.available`, mirroring the order used in `_harvestAndUnstake`, so that already-accrued rewards are properly checkpointed/credited prior to reducing the user's staked balance.

### Proof of Concept
1. User deposits `stakingToken` into a `MasterMagpie` pool via `deposit()`; `user.amount`/`user.available` set, `rewardDebt` recorded, pool has a bonus rewarder receiving `queueNewRewards`.
2. Time passes; `accMGPPerShare` and the rewarder's `rewardPerTokenStored` both increase, so the user has real pending MGP and bonus-token rewards (visible via `pendingTokens`/`allPendingTokens`), but the user has not called `multiclaim*`.
3. Owner pauses the contract (`pause()`), which is a normal emergency procedure, not an admin exploiting the user.
4. User calls `emergencyWithdraw(_stakingToken)`:
   - `user.available` and `user.amount` are reduced without calling `_harvestMGP`/`_harvestBaseRewarder`.
   - `user.rewardDebt` is recomputed as `(new smaller amount) * accMGPPerShare / 1e12`, discarding the previously accrued MGP delta.
   - The rewarder's `userRewardPerTokenPaid` for this user is stale relative to its `rewardPerTokenStored`, and the next `earned()` calculation uses the user's now-lower `balanceOf`, so the reward that had accrued against the higher pre-withdrawal balance is never paid out.
5. User calls `multiclaim`/`getReward` afterward and receives strictly less MGP and bonus tokens than what `pendingTokens`/`allPendingTokens` showed immediately before the emergency withdrawal — the difference is permanently lost.

    /// @notice Withdraw all available tokens without caring about rewards. EMERGENCY ONLY. 
    ///         Locked Token can not be emergent withdraw.
    /// @param _stakingToken Staking token of the pool
    /// @dev withdrawFor of the rewarder with the third param at false is an emergency withdraw
    function emergencyWithdraw(address _stakingToken) external whenPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][msg.sender];
        uint256 availableaAmount = user.available;
        user.available = 0;
        IERC20(pool.stakingToken).safeTransfer(address(msg.sender), availableaAmount);
        emit EmergencyWithdraw(msg.sender, _stakingToken, availableaAmount);
        user.amount = user.amount - availableaAmount;
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
