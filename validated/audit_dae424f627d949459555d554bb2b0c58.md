## Analog Identified

### Title
Silent Git remote rewrite from unvalidated GitHub API `clone_url` allows redirecting push/fetch to attacker-controlled host - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The Chainlink report's core issue is "trust an external data feed without validating a freshness/authenticity precondition before acting on it." The closest Desktop analog is `updateRemoteUrl`, which rewrites the local `origin` remote URL using the `clone_url` field of a `IAPIRepository` object returned by the GitHub API, without ever validating that the new URL's **hostname** is consistent with the previously trusted host [1](#0-0) . Just as the sequencer-uptime check was missing before consuming Chainlink price data, here there is no "same-origin" check before consuming and applying the API-provided URL to the user's local git configuration.

### Finding Description
`updateRemoteUrl` is invoked from `AppStore.repositoryWithRefreshedGitHubRepository`, which runs automatically during routine background refresh flows (e.g. account switching, periodic repository refresh), calling `api.fetchRepository(owner, name)` and then applying the result to the local git remote without user interaction [2](#0-1) .

Inside `updateRemoteUrl`, the guard logic only checks:
1. That the **protocol** (`https:` vs `ssh:`) of the old and new URL match.
2. That the current local remote still matches the *previously stored* `gitHubRepository.cloneURL` (i.e., the user hasn't manually customized the remote).
3. That the new URL differs from the current remote (`!urlsMatch`). [3](#0-2) 

Crucially, none of these checks compare the **hostname** of the old remote URL against the hostname of `apiRepo.clone_url`. `urlMatchesRemote` is only used to detect whether URLs are identical (owner+name+hostname), not to validate that a *changed* URL still points at the same trusted host [4](#0-3) . As long as the protocol scheme matches and the user hasn't hand-edited the remote, any hostname supplied via `apiRepo.clone_url` is accepted and written directly into the repository's git config via `gitStore.setRemoteURL(...)`.

This is exactly analogous to the oracle bug: the code consumes an externally-supplied value (`clone_url` from a `IAPIRepository` object, i.e., an untrusted "GitHub API object" per the valid-impact criteria) and acts on it (rewriting the authoritative push/fetch destination) without validating the one invariant that actually matters here — that the host is the same trusted host the repository was associated with.

### Impact Explanation
If a user is signed into a malicious or compromised GitHub Enterprise Server (a legitimate, in-scope trust boundary for Desktop, since GHE support is a first-class feature), that server can return a repository JSON object whose `clone_url` points to a completely different, attacker-controlled domain, using the same protocol scheme (`https://`). Desktop will silently rewrite the user's `origin` remote to the attacker's host during a routine background refresh — no dialog, no confirmation. Subsequent `git push` operations by the user will silently exfiltrate the user's source code (including proprietary/private code) to the attacker's server instead of the legitimate remote, and subsequent `git fetch`/`pull` operations will silently merge attacker-supplied history and files into the user's local repository, corrupting what the user believes they are committing/pushing/pulling. This matches the report's "silent corruption of what the user commits or pushes" impact class.

Note: because `findGitHubTrampolineAccount` matches credentials strictly by request `origin` [5](#0-4) , stored GitHub OAuth tokens are not automatically handed to the new, unrelated host — but for an "enterprise"-classified unknown host, the user could still be prompted to sign in against the attacker's endpoint via `getCredential`'s sign-in prompt path [6](#0-5) , which is a secondary phishing-style credential risk layered on top of the primary silent-redirect issue.

### Likelihood Explanation
Exploitation requires the attacker to control (or compromise) an API server the user has already added as a Desktop account — i.e., a rogue/compromised GitHub Enterprise Server, which is squarely within Desktop's intended remote/API trust boundary rather than requiring local access, admin rights, or pre-existing malware. The refresh path (`repositoryWithRefreshedGitHubRepository`) runs automatically and periodically without any special user action, so once the account is connected, the rewrite can occur unattended.

### Recommendation
In `updateRemoteUrl`, before applying `apiRepo.clone_url`, verify that the hostname of the new URL matches the hostname of the existing remote (or the account's known endpoint hostname), in addition to the existing protocol check. Only allow owner/name changes (renames) under the same host; reject or explicitly prompt the user for confirmation when the hostname itself changes.

### Proof of Concept
1. Add a GitHub Enterprise account in Desktop pointing at a server the attacker controls (or a legitimate GHE instance later compromised).
2. Clone/track a repository from that server; Desktop stores `gitHubRepository.cloneURL` = `https://ghe.evil-corp.com/acme/secret-repo`.
3. On a later background refresh (e.g. app restart, account switch, or periodic refresh calling `api.fetchRepository`), the malicious server responds to `GET repos/acme/secret-repo` with `clone_url: "https://attacker-exfil.com/acme/secret-repo"`.
4. `updateRemoteUrl` sees: protocols match (`https:`/`https:`), `remoteUrlUnchanged` is true (local remote still equals the previously stored clone URL), and `urlsMatch` is false → it silently calls `gitStore.setRemoteURL('origin', 'https://attacker-exfil.com/acme/secret-repo')`.
5. The next `git push` from Desktop silently sends the user's commits to `attacker-exfil.com`. [7](#0-6)

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
