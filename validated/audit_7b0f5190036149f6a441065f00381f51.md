Based on the investigation, the strongest analog found is in `app/src/lib/parse-app-url.ts`, in the deep-link handler for the `x-github-client://openRepo/...` protocol.

### Title
Unvalidated `filepath` parameter in deep-link `openRepo` action allows unbounded/unsanitized path input to reach post-clone file-open logic - (File: `app/src/lib/parse-app-url.ts`)

### Summary
`parseAppURL` is the function that turns an attacker-controlled protocol URL (`x-github-client://openRepo/...`, `github-mac://openRepo/...`, etc.) into a structured `URLActionType` that the rest of the app trusts and acts on [1](#0-0) . For the `openrepo` action it explicitly validates two of the four query parameters — `pr` must match `/^\d+$/` and `branch` is rejected via `testForInvalidChars` — but the `filepath` query parameter is extracted with `getQueryStringValue` and passed through completely unvalidated into the returned `IOpenRepositoryFromURLAction` [2](#0-1) .

### Finding Description
This mirrors exactly the report's bug class: a governance/attacker-influenced parameter (`filepath`) has no defined bounds/validation, while structurally identical sibling parameters (`branch`, `pr`) on the same code path *do* have bounds enforced. The `IOpenRepositoryFromURLAction.filepath` field is documented as "the file to open after cloning the repository" [3](#0-2) , meaning it is expected to be consumed later (in `dispatcher.ts`, which has multiple references to `filepath`) to locate and open a file relative to the freshly cloned repository. Because no bounds check (e.g. rejecting `..`, absolute paths, drive letters, or the `testForInvalidChars` check applied to `branch`) is applied to `filepath`, a malicious deep link such as:

```
x-github-client://openRepo/https://github.com/attacker/repo?filepath=..%2F..%2F..%2F..%2F.ssh%2Fauthorized_keys
```

would parse successfully and propagate an unsanitized, traversal-capable string all the way to whatever file-open logic in `dispatcher.ts` consumes `filepath`. This is invoked entirely by "a link or deep link the user clicks" — the exact attacker primitive called out as valid impact.

### Impact Explanation
If the downstream consumer in `dispatcher.ts` joins `filepath` with the cloned repository path without normalizing/bounding it (which I was not able to fully confirm before running out of investigation budget — see caveat below), the result could be a file read/open operation resolving outside the intended repository directory, matching the "file write or read outside the repo" impact category. Even in the more conservative case where it's only used to open a file in an editor, unsanitized path traversal via a clickable link still represents unauthorized access to arbitrary file paths on disk under the privileges of the Desktop app/editor process.

### Likelihood Explanation
Likelihood is limited primarily by whatever the actual consumer in `dispatcher.ts` does with `filepath` (join+normalize vs. raw open). The asymmetry in validation between `branch`/`pr` (bounded) and `filepath` (unbounded) strongly suggests this was simply overlooked, consistent with the report's core thesis of inconsistent parameter bounding, but I could not confirm the exact sink behavior in `dispatcher.ts` within the available tool budget.

### Recommendation
Apply the same class of validation used for `branch` (via `testForInvalidChars` or a dedicated path-traversal check) to `filepath` in `parseAppURL`, rejecting values containing `..`, absolute path prefixes, or drive letters, and ensure any downstream consumer resolves `filepath` against the repository root with a strict containment check before opening it.

### Proof of Concept
1. Attacker crafts a deep link: `x-github-client://openRepo/https://github.com/attacker/repo?branch=main&filepath=..%2F..%2F..%2F..%2F.ssh%2Fid_rsa`
2. Victim clicks the link; the OS invokes GitHub Desktop's registered protocol handler, routing to `handleAppURL` → `parseAppURL` [4](#0-3) .
3. `parseAppURL` validates `branch` but passes `filepath` through unchecked, returning `{ name: 'open-repository-from-url', url, branch, pr, filepath: '../../../../.ssh/id_rsa' }` [5](#0-4) .
4. This action is dispatched to the file-open logic in `dispatcher.ts` (unconfirmed exact sink) after the repository clones.

**Caveat / uncertainty:** I was unable to inspect the exact lines in `app/src/ui/dispatcher/dispatcher.ts` that consume `filepath` before running out of tool iterations, so I cannot confirm whether that sink already performs its own path-containment check that would neutralize this issue. Given this gap, treat this as a probable-but-unconfirmed finding rather than a fully verified vulnerability — a follow-up read of `dispatcher.ts` around its `filepath` references is needed to confirm exploitability.

```typescript
export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }
```
