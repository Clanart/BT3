### Title
Centralized `owner` of `GaslessSwapRouter` can drain all native KAIA held by the router via `claimCommission()` - ([File: contracts/bindings/kip247/GaslessSwapRouter.go])

### Summary
The `GaslessSwapRouter` contract (KIP-247 gasless-transaction module) exposes a single privileged `owner` role that can call `claimCommission()` to sweep the router's *entire* native KAIA balance, not merely the accrued commission fee. This mirrors the reported `AirdropFactory` bug class: a centralized owner with unchecked withdrawal rights over funds that transiently belong to end users (here, block proposers/gasless-swap users), enabling rug-pull-style theft of in-flight KAIA.

### Finding Description
`GaslessSwapRouter` is the on-chain counterpart of the `kaiax/gasless` module, used to let users pay gas in ERC-20 tokens: a proposer lends KAIA gas up front, and the user's `swapForGas()` call swaps tokens for KAIA to repay the proposer and keep the remainder [1](#0-0) . During execution, `swapForGas` receives KAIA from the underlying swap (e.g., unwrapped WKAIA), repays the proposer, and forwards `finalUserAmount` to the user, as observed in the `SwappedForGas` event fields `AmountRepaid`, `FinalUserAmount`, `Commission` [2](#0-1) .

The contract's decompiled runtime bytecode shows `claimCommission()` (selector `0xfad99f98`) reads `SELFBALANCE` (`47` opcode) and forwards the *entire current balance* of the contract to the address stored in slot 0 (the `owner`), rather than a tracked/accrued commission variable: [3](#0-2) 

This is exposed publicly as a normal `owner`-gated transaction: [4](#0-3) 

Because `swapForGas` momentarily routes swap proceeds through the router contract before forwarding the user's `finalUserAmount` (visible via the `SwappedForGas` event and the balance assertions in the integration test `tests/gasless_test.go`), any KAIA sitting in the router's balance at the moment `claimCommission()` is invoked — whether due to reentrancy, pending forwarding, dust, or accounting drift — is swept entirely to `owner`, not limited to the commission share. `owner` is a single EOA/multisig address set at construction and changeable via `transferOwnership`, with no timelock, multisig enforcement, or decentralized governance check [5](#0-4) . There is no on-chain mechanism restricting `claimCommission()` to only the commission portion of the balance, and no separation between "router operating balance" and "commission-owed balance."

This directly parallels the reported `AirdropFactory` issue: a single privileged owner has unrestricted withdrawal rights over a contract balance that legitimately belongs, even momentarily, to unprivileged third parties (users/proposers participating in gasless transactions reachable via ordinary `swapForGas` transactions).

### Impact Explanation
If `owner` is malicious, compromised, or its key is leaked, it can call `claimCommission()` at any block to drain 100% of the router's KAIA balance — including any user funds transiently routed through the contract during `swapForGas` execution — rather than only the fee owed to the protocol. This is a direct, unauthorized value-movement/theft vector reachable by a privileged (but externally facing, non-consensus) actor, impacting the gasless transaction ecosystem's users and proposers who rely on the router holding funds correctly during a single-transaction swap-and-repay flow.

### Likelihood Explanation
Medium likelihood: exploitation requires control of the `owner` key, which is an operational/trust assumption rather than a permissionless attack vector. However, since `owner` is a single address (no multisig/timelock enforced on-chain) and the withdrawal function sweeps the *full* balance instead of a tracked commission ledger, any compromise of this key, or any state where user funds are transiently present in the contract, immediately becomes a total-loss event rather than a bounded one.

### Recommendation
- Track accrued commission in a dedicated state variable incremented only by the commission portion taken during `swapForGas`, and have `claimCommission()` transfer only that tracked amount, not `address(this).balance`.
- Ensure the router never retains user or proposer principal balances beyond the scope of a single atomic `swapForGas` call (i.e., there should be no residual balance for `owner` to claim beyond commission).
- Require multisig/timelock governance for `owner`-controlled actions (`claimCommission`, `transferOwnership`, `updateCommissionRate`) on this system-adjacent contract, consistent with the recommendation to decentralize privileged withdrawal paths.

### Proof of Concept
1. A user submits a valid gasless `GaslessApproveTx` + `GaslessSwapTx` pair; the proposer's `LendTxGenerator` fronts KAIA gas per the module's block-building rules [6](#0-5) .
2. During `swapForGas`, the router receives swap proceeds in KAIA and computes `finalUserAmount`/`Commission`, forwarding funds onward as shown by the `SwappedForGas` event and balance checks in the integration test [7](#0-6) .
3. Before the forwarding step completes in the same transaction, or due to any leftover/dust KAIA in the contract, `owner` calls `claimCommission()`.
4. Per the decompiled bytecode, this call transfers `SELFBALANCE` (the router's *entire* KAIA balance) to `owner` [3](#0-2) , not just the commission fee — draining any user/proposer funds present at that moment.

**Note on verification limits**: I could not locate the router's Solidity source (`GaslessSwapRouter.sol`) in the indexed codebase — only the generated Go bindings and decompiled bytecode were available. The exact accounting logic inside `swapForGas` (whether user funds could ever coexist with `claimCommission()`'s full-balance sweep within the same block) could not be fully confirmed from the available bytecode alone. If a full audit of the exact commission-tracking logic is needed, a Devin session with full repository/source access would be required to confirm whether commission is tracked separately in storage or computed as `address(this).balance` at call time.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
