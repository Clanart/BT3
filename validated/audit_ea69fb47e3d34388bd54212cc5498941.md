### Title
Unbounded `pools` Array Iteration in `castVotes()`/`claimAllBribes()` Can Permanently Freeze Bribe Rewards - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.castVotes()` and `WombatBribeManager.claimAllBribes()` both iterate over the entire `pools` array, performing external calls to each pool's rewarder/bribe contract on every iteration. The `pools` array only ever grows (via `addPool`) as the protocol adds support for more Wombat LP pools, and is never bounded in size, mirroring the exact bug class described in the `DepositerRewardDistributor.distribute()` report: an unbounded loop with per-element external calls that can exceed the block gas limit.

### Finding Description
`castVotes()` builds three parallel in-memory arrays sized to `pools.length` and loops over every pool to compute vote deltas before calling `wombatStaking.vote(...)`: [1](#0-0) 

`claimAllBribes()` similarly loops over the full `pools` array, calling `IWombatBribe(bribesContract).rewardTokens()` and `IBribeRewardPool(pool.rewarder).earned()`/`getReward()` for every pool: [2](#0-1) 

The `pools` array is appended to in `addPool()` with no cap, and only ever shrinks via `removePool()`: [3](#0-2) 

Both `castVotes()` and `claimAllBribes()` are public/external functions callable by any unprivileged wallet, so the growth of the `pools` array through normal protocol operation (adding new supported LP pools over time, not a malicious admin action) is the sole trigger — no attacker input or malicious governance action is required to eventually make the loop exceed the block gas limit. This is precisely the same root cause identified in the external report: an unbounded array iterated with expensive per-element external calls (`IBaseRewardPool`, `IBribeRewardPool`, `IWombatBribe`), lacking any enforced upper bound (unlike the fix applied to `extraRewards`, which was capped at `12`).

### Impact Explanation
If `pools.length` grows large enough that a full iteration of `castVotes()` or `claimAllBribes()` cannot fit within the block gas limit, then:
- No user can ever cast votes again through `castVotes()`/`voteAndCast()`, which is also the only path that forwards harvested bribe rewards from `WombatStaking` into the individual pool rewarders (`_forwardRewards`).
- No user can call `claimAllBribes()` to harvest their voting rewards across all pools.

Because there is no mechanism to iterate over a subset of `pools` in these two functions (unlike `claimBribeFor`/`harvestSinglePool`, which take an explicit LP list), and the pools array is not designed to shrink under normal operation, this results in a permanent, protocol-wide freeze of the bribe/voting reward distribution pipeline and of user's unclaimed voting yield — satisfying the "permanent freezing of unclaimed yield" impact bar.

### Likelihood Explanation
Likelihood grows organically as the protocol legitimately adds more Wombat pools over time via `addPool()` — this is routine, expected protocol administration, not a malicious or adversarial action, and requires no cooperation from an attacker. Any ordinary user calling `castVotes()` or `claimAllBribes()` after the pool count crosses the gas-limit threshold will experience permanent failure.

### Recommendation
Enforce an upper bound on `pools.length` in `addPool()`, analogous to the fix applied to `extraRewards` (capped at 12), or refactor `castVotes()`/`claimAllBribes()` to operate over caller-supplied subsets/pages of `pools` (as already done in `claimBribeFor`/`harvestSinglePool`) so no single transaction is forced to process the entire pool list.

### Proof of Concept
1. Protocol owner calls `addPool()` repeatedly (legitimate protocol growth, not malicious) until `pools.length` is large enough that a full iteration of `castVotes()`/`claimAllBribes()` (each iteration performing multiple external calls: `getVoteForLp`, `IBribeRewardPool.earned`, `IWombatBribe.rewardTokens`, `IBribeRewardPool.getReward`, `IBaseRewardPool.queueNewRewards`) exceeds the block gas limit.
2. Any unprivileged wallet calls `castVotes(false)` or `claimAllBribes(user)`.
3. The transaction reverts with an out-of-gas error every time, regardless of gas provided (bounded by block gas limit), permanently freezing voting and unclaimed bribe reward distribution for all users.

    function addPool(
        address _lp,
        address _rewarder,
        string memory _name
    ) external onlyOwner {
        // it seems we have no way to check that the LP exists
        if(_lp == address(0))
        revert ZeroAddressError();
        Pool memory pool = Pool({
            poolAddress: _lp,
            rewarder: _rewarder,
            totalVoteInVlmgp: 0,
            name: _name,
            isActive: true
        });
        if (_lp != delegatedPool) {
            pools.push(_lp); // we don't want the delegatedPool in this array
        }
        poolInfos[_lp] = pool;
        emit AddPool(_lp, _rewarder);
    }

    function removePool(uint256 _index) external onlyOwner {
        uint256 length = pools.length;
        if(_index >= length) revert OutOfPoolIndex();
        pools[_index] = pools[length - 1];
        pools.pop();
    }
