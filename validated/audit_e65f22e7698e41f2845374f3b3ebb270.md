Confirmed: `mWomSV.sol` implements a full `getRewardablePercentWAD(address _user)` function [1](#0-0)  that computes a rewardable percentage based on lock/cooldown status (mirroring `VLMGP`'s equivalent used by `vlMGPBaseRewarder`). However, `mWOMSVBaseRewarder._calExpireForfeit` never calls this function — it just sets `rewardableAmount = _amount` unconditionally [2](#0-1) , whereas the analogous `vlMGPBaseRewarder._calExpireForfeit` calls `vlMGP.getRewardablePercentWAD(_account)` to compute the actual forfeitable amount [3](#0-2) .

### Title
Missing forfeiture logic in `mWOMSVBaseRewarder._calExpireForfeit` allows fully expired-cooldown mWomSV holders to claim 100% of rewards with zero forfeiture, permanently denying redistribution to remaining lockers - (File: `wombat/rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is dead code that always returns `forfeitAmount = 0` regardless of a user's lock/cooldown state, unlike the analogous `vlMGPBaseRewarder._calExpireForfeit`, which queries `getRewardablePercentWAD` from the locker to compute forfeiture for users who let their cooldown expire without unlocking. Since `mWomSV.sol` already implements `getRewardablePercentWAD` with the exact same semantics as `VLMGP`, this is a genuine integration gap: any mWomSV holder whose cooldown has fully expired (without calling `unlock()`) can harvest 100% of rewards via `MasterMagpie.multiclaimFor` → `getReward`/`getRewards`, with no forfeiture ever applied.

### Finding Description
The reward-claim path is `MasterMagpie.multiclaimFor` → `mWOMSVBaseRewarder.getReward`/`getRewards` (`onlyMasterMagpie`) → `_sendReward` → `_calExpireForfeit(_account, userRewards[...])` [4](#0-3) . `_calExpireForfeit` sets `rewardableAmount = _amount`, so `forfeitAmount = _amount - rewardableAmount` is always `0`, and the `if (rewardableAmount > _amount) revert` check is unreachable dead code [2](#0-1) .

In `vlMGPBaseRewarder`, the equivalent function instead computes `rewardableAmount = _amount * vlMGP.getRewardablePercentWAD(_account) / 1e18` [5](#0-4) , meaning users whose lock has fully expired without formally exiting still forfeit a proportional share, which is redistributed via `_queueNewRewardsWithoutTransfer` (`ForfeitRewardAdded`) to users still actively locked [6](#0-5) .

Critically, `mWomSV.sol` already implements the exact locker-side function needed, `getRewardablePercentWAD(address _user)`, which computes a percentage that decays for cooldown slots that have passed `endTime` without a completed `unlock()` call [1](#0-0) . This confirms the forfeiture mechanism was intended for mWomSV holders but the wiring into `mWOMSVBaseRewarder._calExpireForfeit` was never done — no modifier, `nonReentrant` guard, or reward-index update in the claim path substitutes for this missing check.

### Impact Explanation
Any mWomSV holder can call `startUnlock`, wait past `coolDownInSecs` without calling `unlock()`, and continue accruing/harvesting 100% of bonus reward tokens from `mWOMSVBaseRewarder` indefinitely, exactly as if fully locked. This is a direct theft of yield that should have been forfeited and redistributed as `ForfeitRewardAdded` to users who remain genuinely locked, matching the Immunefi "theft of unclaimed yield" impact class. It does not affect principal (the underlying mWOM can only be withdrawn via `unlock()`, which is unaffected), but the documented forfeiture design for expired-cooldown reward-sharing never functions for this reward pool.

### Likelihood Explanation
This requires no privilege beyond being a normal mWomSV holder: `lock()` mWOM, `startUnlock()`, wait past `coolDownInSecs`, and call `multiclaimFor` (or let rewards accrue and later claim) without ever calling `unlock()`. It is fully repeatable by any holder and costs no more than normal gas and the cost of acquiring mWOM tokens already needed to participate.

### Recommendation
Wire `mWOMSVBaseRewarder._calExpireForfeit` to `mWOMSV.getRewardablePercentWAD(_account)` the same way `vlMGPBaseRewarder._calExpireForfeit` uses `vlMGP.getRewardablePercentWAD(_account)`, replacing the dead `rewardableAmount = _amount` assignment with `rewardableAmount = _amount * mWOMSV.getRewardablePercentWAD(_account) / 1e18`.

### Proof of Concept
Foundry test plan:
1. Deploy `mWomSV`, `MasterMagpie`, and `mWOMSVBaseRewarder`; register a bonus reward token in the rewarder via `queueNewRewards`.
2. User A locks mWOM via `mWomSV.lock(amount)`.
3. User A calls `startUnlock(amount)` to move 100% of their balance into cooldown.
4. Warp time past `coolDownInSecs` (do NOT call `unlock()`).
5. Manager calls `queueNewRewards` on the bonus token to accrue rewards for User A (whose `balanceOf` still counts cooldown amount per `mWomSV.balanceOf` [7](#0-6) ).
6. User A calls `MasterMagpie.multiclaimFor` to harvest via `mWOMSVBaseRewarder.getReward`.
7. Assert: `RewardPaid` amount equals 100% of `earned()` pre-claim, `forfeitAmount == 0` (no `ForfeitRewardAdded` event emitted), despite `getRewardablePercentWAD(userA)` computing a value less than `1e18` (partially/fully expired) — demonstrating the mismatch between the locker's intended forfeiture percentage and the rewarder's actual (always-zero) forfeiture.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

                rewardInfo.queuedRewards = 0;

                rewardInfo.rewardPerTokenStored +
