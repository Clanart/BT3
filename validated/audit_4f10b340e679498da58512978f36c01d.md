### Title
Duplicate withdrawal UTXO across two `idx` rows causes a single payout to be attributed to two unrelated deposits, letting an operator be reimbursed for a payout it never funded - ([File: core/src/database/verifier.rs])

### Summary
The `withdrawals` table has no uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, only a primary key on `idx`. `get_payout_txs_for_withdrawal_utxos` joins purely on the UTXO columns, so if two different withdrawal indices end up recording the same withdrawal outpoint, a single Bitcoin spend of that outpoint gets attributed by `update_finalized_payouts` to *both* `idx` rows, crediting the same operator payer for two unrelated deposits' `move_to_vault_txid`.

### Finding Description
The binding that should hold is: **for every row in `withdrawals`, `(withdrawal_utxo_txid, withdrawal_utxo_vout)` uniquely identifies at most one `idx`/`move_to_vault_txid`**. This binding is not enforced anywhere in the schema or code.

- `core/src/database/schema.sql:269-281` defines `withdrawals` with `idx int primary key` and plain, unconstrained `withdrawal_utxo_txid bytea`, `withdrawal_utxo_vout int` columns — no `UNIQUE` constraint on the UTXO pair.
- `update_withdrawal_utxo_from_citrea_withdrawal` (invoked from `update_citrea_deposit_and_withdrawals`, `core/src/verifier.rs:2248-2262`) writes whatever `(idx, outpoint)` pairs `collect_withdrawal_utxos` reports from Citrea (`core/src/citrea.rs:458-496`), with no cross-check against UTXOs already used by other `idx` values.
- `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`) joins `withdrawals w` to `bitcoin_syncer_spent_utxos bsu` purely `ON bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout`. If two rows `idx=d` and `idx=d'` share the same UTXO, a single spending event returns **both** `(d, txid)` and `(d', txid)`.
- `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) then calls `update_payout_txs_and_payer_operator_xonly_pk` for every returned `(idx, payout_txid)`, writing the same `payout_txid`, `payout_payer_operator_xonly_pk` (parsed from the real payout tx's OP_RETURN), and `payout_tx_blockhash` into **both** `idx=d` and `idx=d'` rows.
- `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs`) and `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) then pick up `idx=d'` as an unhandled payout attributed to the honest operator and call `Operator::handle_finalized_payout` against **deposit d''s own `move_to_vault_txid`**, an entirely unrelated deposit the operator never fronted a withdrawal for.

Existing guards fail to catch this:
- `is_utxo_spent` in `sign_optimistic_payout`/`optimistic_payout` only prevents a second live-signing request against the same outpoint; it does not run at attribution time.
- `Aggregator::optimistic_payout`/`Verifier::sign_optimistic_payout` reject reusing a spent UTXO for new *signing*, but the exploit does not need new signing — it exploits the already-recorded payout via `get_payout_txs_for_withdrawal_utxos`'s bulk join.
- The bridge circuit's `verify_storage_proofs` (`circuits-lib/src/bridge_circuit/storage_proof.rs`) reads the withdrawal UTXO/vout/move-txid **at storage index `d'`** directly from Citrea's contract, and `bridge_circuit` (`circuits-lib/src/bridge_circuit/mod.rs:182-204`) only asserts that the payout tx's input at `payout_input_index` matches that recorded UTXO. If Citrea's own storage for index `d'` also records the reused UTXO (which is a precondition outside this repo's control), this check is trivially satisfied and does not verify that the payout tx's *output* actually matches what withdrawal `d'` requested.

### Impact Explanation
If exploited, the operator ends up reimbursed via the pre-signed kickoff/round transaction graph for deposit `d'`'s `move_to_vault_txid` without ever having fronted a payout for `d'` — BTC leaves an unrelated depositor's move-to-vault UTXO without a matching fronted withdrawal, matching the Critical category "an operator reimbursed for a payout it never funded" / "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal." This is repeatable for every additional duplicate-UTXO withdrawal record that can be created, and the harm falls on the unrelated depositor whose collateral gets drained, and/or the protocol's collateral accounting.

### Likelihood Explanation
The DB-level precondition (two `idx` rows sharing a `withdrawal_utxo_txid`/`withdrawal_utxo_vout`) is trivially demonstrable purely within this repository, since neither the schema nor `update_withdrawal_utxo_from_citrea_withdrawal` prevents it. However, turning this into the full Critical chain (operator reimbursed for a deposit it never funded) additionally requires that Citrea's bridge contract itself allow a second `withdraw`/`safeWithdraw` call to register the *same*, already-spent UTXO bytes for a new withdrawal index — a precondition on the Citrea contract, which is outside this repository's control and not verifiable here. Within this repo alone, the reachable, reproducible fact is the DB-level lack of uniqueness and the resulting double-match in `get_payout_txs_for_withdrawal_utxos`.

### Recommendation
Add a partial unique constraint on `withdrawals(withdrawal_utxo_txid, withdrawal_utxo_vout) WHERE withdrawal_utxo_txid IS NOT NULL`, reject/upsert-guard in `update_withdrawal_utxo_from_citrea_withdrawal` against reusing a UTXO already assigned to a different `idx`, and change `get_payout_txs_for_withdrawal_utxos`'s join to also validate that the payout tx's OP_RETURN/committed data is unique per `idx` before crediting `payout_payer_operator_xonly_pk`.

// core/src/database/verifier.rs test module (cargo test)
#[tokio::test]
async fn duplicate_withdrawal_utxo_across_idx_double_credits_payout() {
    let config = create_test_config_with_thread_name().await;
    let db = Database::new(&config).await.unwrap();
    let mut dbtx = db.begin_transaction().await.unwrap();

    let shared_utxo = bitcoin::OutPoint {
        txid: bitcoin::Txid::from_byte_array([0xAA; 32]),
        vout: 0,
    };
    let move_txid_d  = Txid::from_byte_array([0x01; 32]); // deposit d's own vault
    let move_txid_dp = Txid::from_byte_array([0x02; 32]); // unrelated deposit d'
    let payout_txid  = Txid::from_byte_array([0xBB; 32]);
    let operator_pk  = generate_random_xonly_pk();

    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.insert_txid_to_block(&mut dbtx, block_id, &payout_txid).await.unwrap();
    db.insert_spent_utxo(&mut dbtx, block_id, &payout_txid, &shared_utxo.txid, shared_utxo.vout.into()).await.unwrap();

    // idx d and d' both get the SAME withdrawal UTXO
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), 10, &move_txid_d).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), 10, shared_utxo, block_id).await.unwrap();

    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), 20, &move_txid_dp).await.unwrap();
    // THIS MUST NOT SUCCEED if a uniqueness constraint existed - assert it currently does succeed:
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), 20, shared_utxo, block_id).await.unwrap();

    // one spend event now matches BOTH idx rows
    let txs = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();
    assert_eq!(txs.len(), 2); // proves double-match precondition
    assert!(txs.iter().any(|(idx, _)| *idx == 10));
    assert!(txs.iter().any(|(idx, _)| *idx == 20));

    db.update_payout_txs_and_payer_operator_xonly_pk(
        Some(&mut dbtx),
        vec![(10, payout_txid, Some(operator_pk), BlockHash::all_zeros()),
             (20, payout_txid, Some(operator_pk), BlockHash::all_zeros())],
    ).await.unwrap();

    let info_d  = db.get_payout_info_from_move_txid(Some(&mut dbtx), move_txid_d).await.unwrap().unwrap();
    let info_dp = db.get_payout_info_from_move_txid(Some(&mut dbtx), move_txid_dp).await.unwrap().unwrap();
    // Same operator credited for TWO unrelated deposits from ONE real payout tx
    assert_eq!(info_d.0, Some(operator_pk));
    assert_eq!(info_dp.0, Some(operator_pk));
}

```rust
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(

             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",

        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
```

```rust
    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }
```

```rust
    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;

            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
```
