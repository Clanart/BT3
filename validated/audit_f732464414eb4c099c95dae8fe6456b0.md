### Title
Deep-link `x-github-client://openRepo` action silently checks out attacker-specified branches/PRs on already-known repositories, bypassing the confirmation gate - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
GitHub Desktop registers custom protocol handlers (`x-github-client`, `x-github-desktop-auth`, plus legacy `github-mac`/`github-windows`) that any external process, webpage, or link the user clicks can invoke without any prior trust relationship. When the resulting `open-repository-from-url` action names a repository the user has *already* added to Desktop, the dispatcher skips the normal "confirm before acting" step (the Clone/Add popup) and instead immediately fetches and checks out an attacker-chosen branch or pull request. This mirrors the "initializer front-run" bug class: the step that is supposed to gate/initialize trust (explicit user confirmation before Desktop touches a repository) can be bypassed by an attacker who supplies the deep-link parameters that drive that same code path for repos that already satisfy the match condition.

### Finding Description
`app.on('open-url', ...)` / `handleAppURL` in `app/src/main-process/main.ts` parses any externally supplied URL with `parseAppURL` [1](#0-0)  and, once the main window has loaded, forwards it straight into the renderer via `window.sendURLAction(action)` [2](#0-1) . `parseAppURL` accepts an `openrepo` host and, after light validation of `pr`/`branch`/`filepath` characters, returns an `open-repository-from-url` action built entirely from attacker-controlled query parameters [3](#0-2) .

`Dispatcher.dispatchURLAction` routes this straight into `openRepositoryFromUrl` [4](#0-3) , which branches on whether a `pr` or `branch` was supplied and ultimately calls `openOrCloneRepository(url)` [5](#0-4) . `openOrCloneRepository` looks up whether any already-opened repository's GitHub `htmlURL` (or parent/upstream `htmlURL`) matches the attacker-supplied `url` [6](#0-5) . If it matches, the "initializer" gate — `_startOpenInDesktop` showing a `CloneRepository`/`AddRepository` popup that requires explicit user action — is **never invoked**; that popup path only runs for repos the user has *not* already added [7](#0-6) .

For an existing match, `openBranchNameFromUrl` silently runs `_refreshRepository`, `_fetch`, and `checkoutLocalBranch(repository, branchName)` with the attacker-supplied branch name and no confirmation dialog [8](#0-7) . Similarly, `openPullRequestFromUrl` will fetch the PR via the API and, if it corresponds to an already-open repository, call `_checkoutPullRequest` directly using the head repo's `clone_url`/`ref` taken from the API response, again without a user confirmation step [9](#0-8) .

The only remaining guard on this path is `testForInvalidChars` on the branch string in `parseAppURL`, which filters obviously malformed refs but does not gate on user intent [10](#0-9) ; the `filepath` parameter is separately hardened with `resolveWithin`/`isAbsolute` checks [11](#0-10) , but that only protects against path traversal for the "reveal in Finder/Explorer" side-effect — it does nothing to stop the silent fetch+checkout itself.

I was not able to fully inspect `urlsMatch` in `app/src/lib/repository-matching.ts` (tool budget exhausted before retrieving its body), so the exact leniency of the URL-matching comparison (e.g., whether it's strict host+owner+name equality or something looser) is unconfirmed and should be verified by a follow-up session before treating this as fully proven.

### Impact Explanation
An attacker who gets a victim to click a single link (a natural web/email interaction, not requiring local access, malware, or leaked credentials) can force Desktop to silently:
- Switch the working directory of an already-open, trusted repository to an attacker-chosen branch, or
- Fetch and check out an attacker-chosen fork/PR ref into that repository,

all without any confirmation dialog. Since this changes what files are on disk and what HEAD points to, any subsequent build, test run, commit, or push by the victim operates on attacker-influenced content — this is the "silent corruption of what the user commits or pushes" impact class, achieved purely through a deep link the attacker controls.

### Likelihood Explanation
The custom protocol handlers (`x-github-client://`, `github-mac://`, `github-windows://`) are registered globally at OS level via `setAsDefaultProtocolClient` [12](#0-11) , so any webpage, email client, or IM app that renders a clickable link can trigger `open-url`. The only precondition is that the victim has previously added/cloned the target repository in Desktop — a common state for active GitHub Desktop users. No credentials, elevated privileges, or prior compromise are required, making this a realistic, low-effort attacker path.

### Recommendation
Require explicit user confirmation before performing branch checkout or PR checkout that originates from an `open-repository-from-url` deep-link action, even when the target repository already exists in Desktop's known repository list. Concretely, route `openBranchNameFromUrl` and `openPullRequestFromUrl` through a confirmation popup (mirroring the popup already shown in `openOrCloneRepository` for new repositories) before calling `_fetch`/`checkoutLocalBranch`/`_checkoutPullRequest`, and treat the "trust" established by matching an existing repository as insufficient authorization for state-changing git operations triggered by untrusted, attacker-supplied deep-link parameters.

### Proof of Concept
1. Victim has previously cloned/added `https://github.com/acme/webapp` in GitHub Desktop.
2. Attacker sends the victim a link (email, chat, malicious webpage):
   `x-github-client://openRepo/github.com/acme/webapp?branch=attacker-branch`
3. Victim clicks the link. The OS invokes GitHub Desktop with this URL; `app.on('open-url')` → `handleAppURL` → `parseAppURL` produces `{ name: 'open-repository-from-url', url: 'github.com/acme/webapp', branch: 'attacker-branch', pr: null, filepath: null }`.
4. `Dispatcher.dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl` finds the existing repository via `doesRepositoryMatchUrl`, skips the popup entirely, and runs `_refreshRepository`, `_fetch`, and `checkoutLocalBranch(repository, 'attacker-branch')` — silently switching the victim's working copy to `attacker-branch` with no confirmation prompt [8](#0-7) .

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }
