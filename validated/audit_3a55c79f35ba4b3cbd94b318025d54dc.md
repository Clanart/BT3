### Title
Payout OP_RETURN operator-attribution is unauthenticated, letting anyone attribute a self-funded payout to an arbitrary victim operator - ([File: core/src/verifier.rs])

### Summary
`update_finalized_payouts` writes `withdrawals.payout_payer_operator_xonly_pk` purely from `parse_op_return_data(get_first_op_return_output(payout_tx))`, with no check that the named operator actually contributed funds or signed anything. Because the withdrawer's `SinglePlusAnyoneCanPay` payout signature only commits to the input and the output at the same index (index 0), any party (including the withdrawer themselves) can construct and broadcast the payout transaction with an arbitrary OP_RETURN naming a victim operator's xonly_pk, causing that operator's own node to later claim reimbursement for a payout it never funded.

### Finding Description
The intended binding is: `withdrawals.payout_payer_operator_xonly_pk == the operator that actually fronted/paid the withdrawal`. In practice the code establishes: `withdrawals.payout_payer_operator_xonly_pk == whatever 32 bytes follow OP_RETURN in the mined payout tx`, with zero cryptographic tie to who funded the transaction.

- `core/src/verifier.rs` `update_finalized_payouts` (`~2283-2353`) locates the payout tx in a finalized block, extracts the first OP_RETURN output via `get_first_op_return_output`, and parses it via `parse_op_return_data`, treating the bytes as the payer operator's xonly public key with no further validation: [1](#0-0) 
- That value is persisted verbatim by `Database::update_payout_txs_and_payer_operator_xonly_pk` into `withdrawals.payout_payer_operator_xonly_pk`: [2](#0-1) 
- The legitimate payout transaction is built by `create_payout_txhandler`: input 0 is the withdrawal UTXO spent via `SpendPath::KeySpend` with the withdrawer's signature; output 0 is the user payout; output 2 is the OP_RETURN carrying the operator's xonly_pk: [3](#0-2) 
- The withdrawer's signature is required (and enforced) to use `TapSighashType::SinglePlusAnyoneCanPay`: [4](#0-3)  and is verified against `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` before being funded/broadcast: [5](#0-4) 

Root cause: under BIP341, `SIGHASH_SINGLE | ANYONECANPAY` commits only to the single input being signed and the output at the *same index* as that input (output 0); it does not commit to the number, content, or existence of any other outputs (the anchor output or the OP_RETURN at output index 2). Consequently, once a withdrawer produces this signature to get their withdrawal fronted, *anyone* who obtains that valid `(input, output0)` pair can build a completely different transaction: same signed input and output 0, but a fully attacker-chosen OP_RETURN and fee-paying input(s). Nothing in the withdrawal/payout path (`Operator::withdraw`, `parse_withdrawal_sig_params`, `update_finalized_payouts`, `is_kickoff_malicious`) verifies that the entity named in the OP_RETURN actually supplied the funding input or possesses any relationship to the fee-paying UTXO.

Attacker exploit flow (fully off-band, no privileged access needed):
1. Attacker deposits into the bridge and calls `withdraw` on the Citrea Bridge contract for their own withdrawal, registering a withdrawal UTXO they control the private key for.
2. Attacker signs the payout input themselves with `SinglePlusAnyoneCanPay` (they must do this anyway to withdraw at all - no operator or aggregator interaction is required for signing).
3. Instead of sending this to any operator/aggregator gRPC endpoint, the attacker directly assembles a Bitcoin transaction spending the withdrawal UTXO with this same signature, output 0 paying themselves (as already signed), and appends an OP_RETURN containing a chosen **victim** operator's xonly_pk (any registered operator's public key, obtainable from `OperatorConfig`/known operator lists). They fund/pay fees themselves.
4. Attacker broadcasts this transaction directly to the Bitcoin network - no Clementine RPC involvement at all is required for this step.
5. Once finalized, every verifier's and every operator's own node independently runs `update_finalized_payouts`, parses the forged OP_RETURN, and writes `payout_payer_operator_xonly_pk = victim`.
6. The victim operator's own `PayoutCheckerTask` (`core/src/task/payout_checker.rs`) queries `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)`, finds the forged entry matching its own key, and automatically calls `handle_finalized_payout`, driving a kickoff and eventually a `Reimburse` transaction that pays the victim operator `bridge_amount` from the deposit's move-to-vault UTXO — for a payout the victim never made. `is_kickoff_malicious` does not catch this because it only checks that `operator_xonly_pk == kickoff_data.operator_xonly_pk` (both are the victim, since the victim's own software issues its own kickoff using its own identity) and that the committed blockhash matches: [6](#0-5) 

None of the existing guards defend against this: `Operator::is_profitable` and the Schnorr signature check in `Operator::withdraw` only run when a legitimate operator processes a withdrawal via gRPC, which this attack bypasses entirely; `is_kickoff_malicious` only checks self-consistency between the DB entry and the kickoff sender, not who funded the payout.

### Impact Explanation
This directly matches the enumerated Critical impact: "an operator reimbursed for a payout it never funded" and "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal." The bridge's deposit-backed move-to-vault UTXO pays out an extra `bridge_amount` (minus fees) to a party (the named victim operator) that never fronted the corresponding withdrawal, while the true funder (the attacker, who was entitled to receive their own withdrawal anyway) gains nothing extra beyond their normal entitlement. This is repeatable per withdrawal/operator: an attacker can perform this once per withdrawal they initiate, and can target any operator whose xonly_pk they know (public information), draining bridge funds equal to `bridge_amount` per exploited withdrawal to arbitrary operators. Blast radius scales with the number of withdrawals an attacker is willing to fund themselves; each exploited withdrawal frames one operator for one improper reimbursement.

### Likelihood Explanation
Preconditions are minimal: the attacker needs to be an ordinary bridge user able to deposit, withdraw via Citrea, sign their own withdrawal input, and broadcast Bitcoin transactions - all explicitly within the unprivileged attacker capability set. No TLS interception, key compromise, or insider access is required, since the attacker generates and controls their own withdrawal signature. Cost is limited to the attacker's own deposit/withdrawal amount (which they recover) plus Bitcoin transaction fees. The attack is deterministic given the BIP341 sighash semantics (`SIGHASH_SINGLE|ANYONECANPAY` not committing to non-corresponding outputs), so it is highly feasible and fully repeatable across withdrawals and operators.

### Recommendation
Do not derive payer/operator attribution solely from an unauthenticated OP_RETURN. Either (a) require the operator's own signature over the OP_RETURN/fee-paying input (e.g., have the operator co-sign or commit to the whole transaction, not just accept whatever appears on-chain), or (b) bind attribution cryptographically to the actual funding input(s) — e.g., verify that the additional input(s) beyond the withdrawer's signed input are controlled by/attributable to the operator named in the OP_RETURN (such as requiring that input to come from a known operator-controlled address/UTXO set, or requiring the operator to pre-register the exact payout transaction/txid before broadcast, matching it against the finalized on-chain tx before crediting `payout_payer_operator_xonly_pk`).

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
