### Title
Missing cooldown-penalty enforcement in `_calExpireForfeit` allows theft of forfeited yield - ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` unconditionally sets `rewardableAmount = _amount`, never consulting `mWOMSV.getRewardablePercentWAD(_account)` as its sibling contract `vlMGPBaseRewarder._calExpireForfeit` does. This means users with partially-locked/cooling-down `mWomSV` positions always receive 100% of their accrued bonus rewards instead of a prorated share, and the forfeited portion that should be redistributed to fully-locked holders via `_queueNewRewardsWithoutTransfer` is never generated.

### Finding Description
`ILocker.getRewardablePercentWAD` (implemented in `mWomSV.sol` at [1](#0-0) ) computes a WAD-scaled percentage that reflects how much of a user's rewards should be honored based on how much of their stake is fully locked vs. in cooldown/unlocking. The correct pattern, used in `vlMGPBaseRewarder._calExpireForfeit`, is: [2](#0-1) 

In contrast, `mWOMSVBaseRewarder._calExpireForfeit` never fetches this percentage and instead sets `rewardableAmount = _amount` directly: [3](#0-2) 

Because `rewardableAmount` always equals `_amount`, `forfeitAmount = _amount - rewardableAmount` is always `0`. This function is invoked from `_sendReward`, which is called by `getReward`/`getRewards`, both reachable by any unprivileged caller through `MasterMagpie.multiclaim`/`getReward` routed to this rewarder (`onlyMasterMagpie` modifier just requires the call to go through `MasterMagpie`, not that the caller is privileged) [4](#0-3) . As a result, a user who calls `mWomSV.startUnlock` (entering a cooldown slot that should be partially penalized per `getRewardablePercentWAD`) still receives their full bonus reward with zero forfeiture, and the `ForfeitRewardAdded` redistribution mechanism intended to move forfeited value to fully-locked holders is never triggered for this rewarder.

### Impact Explanation
This is a theft/misallocation of unclaimed yield: value that should be forfeited by users in cooldown and redistributed to fully-locked `mWomSV` holders (via `_queueNewRewardsWithoutTransfer`) is instead retained in full by the cooldown user. Every claim by a partially-unlocking user permanently deprives other stakers of their entitled redistributed share — matching the "theft of unclaimed yield" impact class.

### Likelihood Explanation
This requires no special privileges — any user who deposits `mWOM`, calls `mWomSV.lock`, then `startUnlock` for any nonzero amount, is deterministically affected/benefited on every subsequent claim (`getReward`/`getRewards` via `MasterMagpie`). The bug fires on 100% of calls for any account with a nonzero cooldown balance and is trivially repeatable, requiring only ordinary transaction fees.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`: fetch `mWOMSV.getRewardablePercentWAD(_account)`, compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18`, and derive `forfeitAmount` from that, forwarding the forfeited portion to `_queueNewRewardsWithoutTransfer` as already wired in `_sendReward`.

### Proof of Concept
Foundry test plan:
1. Deploy `mWomSV`, `MasterMagpie`, `mWOMSVBaseRewarder` and a reward token; register the rewarder with `MasterMagpie`.
2. User A: `mWOM.approve` + `mWomSV.lock(1000e18)`.
3. Have the reward manager `queueNewRewards` a bonus reward amount `R` to `mWOMSVBaseRewarder`.
4. User A calls `mWomSV.startUnlock(600e18)` (60% into cooldown, 40% still fully locked) — this triggers `getRewardablePercentWAD` to be less than 100%.
5. Advance time partway through the cooldown period (still within `coolDownInSecs`, so slot is "still in cool down").
6. Call `MasterMagpie.multiclaimFor` (or equivalent) routing to `mWOMSVBaseRewarder.getReward(userA, userA)`.
7. Assert: expected behavior is `toSend = R * getRewardablePercentWAD(userA) / 1e18` and `forfeitAmount = R - toSend` should be queued via `ForfeitRewardAdded` event and reflected in `rewards[token].rewardPerTokenStored` for other lockers.
8. Actual observed behavior: `userRewards` paid out equals full `R`, no `ForfeitRewardAdded` event emitted, `calExpireForfeit(userA, token)` returns `0` despite `getRewardablePercentWAD(userA) < 1e18`, proving the forfeiture logic is bypassed.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
