### Title
Malformed per-input preprocess vector panics Bitcoin transaction signing - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`TransactionSignMachine::sign` trusts every participant-supplied preprocess vector to contain one `Preprocess` per transaction input. A participant can pass an empty or truncated vector directly to the public `sign` API, causing an out-of-bounds index panic and aborting the signing operation.

### Finding Description
`SignableTransaction::multisig` creates one `AlgorithmMachine` for every transaction input, so `TransactionSignMachine.sigs.len()` equals the number of inputs. [1](#0-0)  During signing, the implementation iterates `0 .. self.sigs.len()` and indexes `commitments[c]` for each participant without first checking `commitments.len()`. [2](#0-1)  Although `read_preprocess` produces a correctly sized vector, `sign` itself accepts attacker-constructed `HashMap<Participant, Vec<Preprocess<Secp256k1, ()>>>` values and performs no equivalent validation. [3](#0-2) 

### Impact Explanation
A malformed preprocess vector smaller than the transaction input count triggers a Rust bounds-check panic before signature shares are generated. In a service that invokes this API on participant-controlled inputs, this can terminate the signing task, thread, or process and prevents the threshold transaction from completing.

### Likelihood Explanation
The trigger requires no valid signature, nonce ownership, brute force, or malformed curve encoding: only an empty or truncated vector supplied as a participant’s preprocess. Any transaction with at least one input reaches the vulnerable indexing path.

### Recommendation
Validate every participant preprocess vector before indexing it. Reject vectors whose length differs from `self.sigs.len()` and return a structured `FrostError` identifying the faulty participant rather than panicking. Apply the same length validation before signature-share vectors are consumed during completion.

### Proof of Concept
```rust
use std::collections::HashMap;

use frost::{Participant, sign::SignMachine};

// `sign_machine` is obtained from a transaction with at least one input:
// let (sign_machine, _our_preprocesses) =
//     signable.multisig(&keys).unwrap().preprocess(&mut rng);

let participant = Participant::new(1).unwrap();
let mut preprocesses = HashMap::new();

// A well-formed value must contain one Preprocess per transaction input.
// This malformed value is empty.
preprocesses.insert(participant, Vec::new());

// Panics at `commitments[c]` while processing input 0.
let _ = sign_machine.sign(preprocesses, b"");
```

The panic occurs because `self.sigs.len() >= 1` causes `c = 0`, after which `commitments[0]` is evaluated on the empty vector. [4](#0-3)
