### Title
Payout OP_RETURN operator attribution is unauthenticated, allowing reimbursement to be assigned to an arbitrary operator - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
`update_finalized_payouts` derives `operator_xonly_pk` (the party to be credited/reimbursed for a withdrawal) purely from an OP_RETURN output in the confirmed payout transaction, parsed by `get_first_op_return_output`/`parse_op_return_data`. That OP_RETURN output is not covered by the withdrawer's `SinglePlusAnyoneCanPay` signature, so anyone possessing the withdrawal's signed input (which is by design not bound to a specific operator) can construct and broadcast a payout transaction naming an arbitrary xonly pubkey as the "payer," independent of who actually funds the payout amount.

### Finding Description
The intended binding is: `operator_xonly_pk` credited by `update_payout_txs_and_payer_operator_xonly_pk` (core/src/verifier.rs) == the entity that actually funded the withdrawal's output amount.

In `create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436), the payout transaction has three outputs: the user payout, an anchor, and an OP_RETURN containing `operator_xonly_pk.serialize()`. Only input 0 is signed by the withdrawer's `taproot::Signature user_sig` via `set_p2tr_key_spend_witness`, and `Operator::withdraw` (core/src/operator.rs:630-637) verifies this signature with `sighash_type` being whatever the withdrawer chose — per the rules, `SIGHASH_SINGLE|ANYONECANPAY`. That sighash flag commits only to input 0 and the output at the same index (output 0, the user payout); it does **not** commit to output 1 (anchor) or output 2 (OP_RETURN), nor to any additional inputs added for fee-funding.

Consequently, any party holding the withdrawal's `input_signature`/`input_outpoint`/`output_script_pubkey`/`output_amount` (all visible via the `WithdrawParams` on Citrea) can independently rebuild `create_payout_txhandler`'s transaction, attach their own fee-funding inputs, set the OP_RETURN to an arbitrary xonly pubkey (of a real, victim operator, e.g. a competitor operator's known public key), and broadcast it — all without needing that operator's cooperation or private key, since the operator-key check only occurs later, at kickoff-broadcast time, not at attribution time.

`update_finalized_payouts` (core/src/verifier.rs:2311-2342) then reads whichever payout transaction confirms first for that withdrawal, extracts the OP_RETURN xonly pubkey with no additional validation that this pubkey corresponds to the party who supplied the payout funds, and persists it via `update_payout_txs_and_payer_operator_xonly_pk`. This record is subsequently the sole basis (via `get_payout_info_from_move_txid`) that verifiers/operators use to determine which operator is authorized to proceed with the kickoff/reimbursement flow for that deposit.

None of the guards enumerated in the audit rules intervene here: `SECP.verify_schnorr` only checks the withdrawer's signature against the committed input/output (not the OP_RETURN), and there is no cross-check anywhere in `update_finalized_payouts` that the credited xonly pubkey's operator wallet actually supplied the funding inputs of the payout transaction.

### Impact Explanation
Two critical outcomes follow, matching listed severity categories:
- An arbitrary xonly pubkey (a real operator's public key, requiring no cooperation) can be recorded as the payer for a withdrawal it never funded, potentially enabling that operator to later claim reimbursement (`Operator::handle_finalized_payout`, core/src/operator.rs:839-970) for BTC it did not spend — "an operator reimbursed for a payout it never funded."
- If the honest operator's own payout transaction (spending the same `input_outpoint`) has not yet confirmed when the attacker's forged-attribution transaction confirms, the withdrawal UTXO is consumed by the attacker's transaction first; the honest operator's payout is pre-empted/double-spent and it can never be credited or reimbursed for that withdrawal — "an honest operator permanently unable to be reimbursed."

This is repeatable per pending withdrawal (any withdrawal registered on Citrea before its payout confirms) and is not bound to a specific deposit or operator — every open withdrawal window is exploitable.

### Likelihood Explanation
Preconditions are exactly those stated: a withdrawal registered on Citrea with no payout yet broadcast/confirmed, and possession of the withdrawer's `SinglePlusAnyoneCanPay` signature and outpoint data — all of which are attacker-visible per the rules (`WithdrawParams` fields are not secret to the general public once the withdrawal is registered). The attacker's cost is only Bitcoin fees for fee-funding a race transaction; no operator key, verifier key, or aggregator privilege is needed. The race against the legitimate operator's broadcast is feasible since operators typically wait for withdrawal detection before funding and broadcasting.

### Recommendation
Bind the OP_RETURN attribution to the sighash committed by the withdrawer, or otherwise authenticate the payer: e.g., require the withdrawer's signature to use `SIGHASH_ALL` (covering all outputs) so the operator identity in the OP_RETURN cannot be altered post-hoc, or require operators to separately co-sign/commit to the payout transaction (e.g., via a second signature over the whole transaction) before `update_finalized_payouts` accepts the OP_RETURN attribution. Additionally, `update_finalized_payouts` should cross-check that the party named in the OP_RETURN actually supplied the additional funding input(s) of the payout transaction (e.g., verify an input belongs to that operator's known collateral/wallet key) before crediting them.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn handle_finalized_payout<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        deposit_outpoint: OutPoint,
        payout_tx_blockhash: BlockHash,
    ) -> Result<bitcoin::Txid, BridgeError> {
        let (deposit_id, deposit_data) = self
            .db
            .get_deposit_data(Some(dbtx), deposit_outpoint)
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {
                return Err(eyre::eyre!(
                    "Internal error: Expected the current round ({:?}) to be equal to or 1 less than the round of the first available kickoff for deposit reimbursement ({:?}) for deposit {:?}. If the round is less than the current round, there is an issue with the logic of the fn that gets the first available kickoff. If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

        // get signed txs,
        let kickoff_data = KickoffData {
            operator_xonly_pk: self.signer.xonly_public_key,
            round_idx,
            kickoff_idx,
        };

        let payout_tx_blockhash = payout_tx_blockhash.as_byte_array().last_20_bytes();

        #[cfg(test)]
        let payout_tx_blockhash = self
            .config
            .test_params
            .maybe_disrupt_payout_tx_block_hash_commit(payout_tx_blockhash);

        let context = ContractContext::new_context_for_kickoff(
            kickoff_data,
            deposit_data,
            self.config.protocol_paramset(),
        );

        let signed_txs = create_and_sign_txs(
            self.db.clone(),
            &self.signer,
            self.config.clone(),
            context,
            Some(payout_tx_blockhash),
            Some(dbtx),
        )
        .await?;

        let tx_metadata = Some(TxMetadata {
            tx_type: TransactionType::Dummy, // will be replaced in add_tx_to_queue
            operator_xonly_pk: Some(self.signer.xonly_public_key),
            round_idx: Some(round_idx),
            kickoff_idx: Some(kickoff_idx),
            deposit_outpoint: Some(deposit_outpoint),
        });

        // try to send them
        for (tx_type, signed_tx) in &signed_txs {
            match *tx_type {
                TransactionType::Kickoff
                | TransactionType::OperatorChallengeAck(_)
                | TransactionType::WatchtowerChallengeTimeout(_)
                | TransactionType::ChallengeTimeout
                | TransactionType::DisproveTimeout
                | TransactionType::Reimburse => {
                    #[cfg(feature = "automation")]
                    self.tx_sender
                        .add_tx_to_queue(
                            dbtx,
                            *tx_type,
                            signed_tx,
                            &signed_txs,
                            tx_metadata,
                            self.config.protocol_paramset(),
                            None,
                        )
                        .await?;
                }
                _ => {}
            }
        }

        let kickoff_txid = signed_txs
            .iter()
            .find_map(|(tx_type, tx)| {
                if let TransactionType::Kickoff = tx_type {
                    Some(tx.compute_txid())
                } else {
                    None
                }
            })
            .ok_or(eyre::eyre!(
                "Couldn't find kickoff tx in signed_txs".to_string(),
            ))?;

        // mark the kickoff connector as used
        self.db
            .mark_kickoff_connector_as_used(Some(dbtx), round_idx, kickoff_idx, Some(kickoff_txid))
            .await?;

        Ok(kickoff_txid)
    }
