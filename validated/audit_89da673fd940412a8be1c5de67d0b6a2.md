The submitted question's specific proof idea (crafting a spoofed `/meta` response) doesn't quite match how the code behaves — the actual bug is more direct than that. [1](#0-0) 

The regex check `/(^|\.)(github)\./.test(hostname)` at line 2452 executes **before** any `/meta` request is made and returns `true` unconditionally on a match — the certificate-suppressed HEAD request to `/meta` and its `x-github-request-id` check (lines 2467–2490) are only reached for hostnames that fail this earlier regex test. ### Title
Naive `github.` substring/label regex in `isGitHubHost()` lets an attacker-controlled subdomain be classified as a trusted GitHub/Enterprise host, triggering an unsolicited sign-in prompt against the attacker's server - (File: app/src/lib/api.ts)

### Summary
`isGitHubHost()` trusts any hostname matching `/(^|\.)(github)\./` as a GitHub Enterprise host without performing the `/meta` verification request that exists later in the same function for other hosts. Since subdomain labels are fully attacker-controlled for any domain the attacker owns, this heuristic can be satisfied trivially (e.g. `github.attacker.com`), causing GitHub Desktop's git-credential trampoline to treat the attacker's host as a trusted GitHub Enterprise endpoint and to automatically prompt the user to sign in to it.

### Finding Description
`isGitHubHost()` short-circuits with `return true` on line 2452-2454 purely from a regex test of the hostname string, before ever contacting the server. This bypasses the intended verification mechanism (the `x-github-request-id` header check against `/meta`) that is only reached for hostnames that don't match this naive pattern. An attacker only needs control of any domain to create a subdomain containing the label `github` adjacent to a dot or the start of the hostname. [6](#0-5) 

`isGitHubHost()`'s only call site, `getEndpointKind()`, uses this misclassification to decide the credential-helper treats the host as `'enterprise'` rather than `'generic'`. [7](#0-6) 

That in turn causes `getCredential()` to call `ui.promptForGitHubSignIn(endpoint)` automatically (no user-initiated navigation to Preferences needed) whenever git attempts to authenticate to the attacker's URL and no existing account matches. [8](#0-7) 

`promptForGitHubSignIn` then drives the real "Enterprise sign in" popup/flow (`beginEnterpriseSignIn` + `setSignInEndpoint(origin)`) with the attacker's origin as the sign-in target. [5](#0-4) 

### Impact Explanation
A user who adds/clones a remote whose host matches this naive pattern (fully achievable via an attacker-owned domain) will see GitHub Desktop automatically present what looks like a legitimate "Sign in to GitHub Enterprise" dialog for that attacker host. This is a credential/account-binding trust confusion: the app is vouching (via the "enterprise" endpoint kind) for a host that was never actually verified as running GitHub Enterprise software. Depending on how the sign-in step ultimately submits credentials/tokens to `endpoint`/`origin` (which I could not fully trace within available tool calls), this could result in credential or token exfiltration to the attacker, or at minimum unwanted OAuth/account-binding to an attacker-controlled "enterprise" endpoint. I did not find evidence this affects clone/checkout git-command argument construction directly.

### Likelihood Explanation
Low additional user interaction is required beyond adding a git remote or clicking a link pointing at an attacker-owned domain with a `github.` labeled subdomain — something fully within attacker control (no DNS/certificate spoofing of GitHub itself required, no MITM needed). The regex bypass is deterministic and does not depend on race conditions or timing.

### Recommendation
Remove the unauthenticated regex short-circuit at `app/src/lib/api.ts:2452-2454` (and the `bitbucket|gitlab` negative-match heuristic) and require every non-known-endpoint hostname to pass the authenticated `/meta` + `x-github-request-id` verification before being classified as a GitHub/Enterprise host. If a fast-path heuristic is desired, treat it only as a hint and still perform the network/header verification before elevating trust (e.g., before invoking `promptForGitHubSignIn` or classifying credentials as `'enterprise'`).

### Proof of Concept
1. Register/control a domain, e.g. `attacker.com`, and create the DNS record `github.attacker.com` pointing to any server (does not need to speak GitHub API).
2. In GitHub Desktop, add/clone a repository using a remote URL on that host, e.g. `https://github.attacker.com/foo/bar.git`.
3. When git invokes the credential helper for `github.attacker.com`, `getEndpointKind()` calls `isGitHubHost('https://github.attacker.com/...')`; the hostname matches `/(^|\.)(github)\./` and `isGitHubHost` returns `true` immediately (confirmable by adding a log statement or breakpoint at `app/src/lib/api.ts:2452`) without any request ever reaching `github.attacker.com/api/v3/meta`.
4. `getEndpointKind` returns `'enterprise'`, and since no account exists for this endpoint, `getCredential()` calls `ui.promptForGitHubSignIn('https://github.attacker.com')`, which opens the Enterprise sign-in popup targeting the attacker's origin.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {

        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)

        await this.dispatcher.setSignInEndpoint(origin)
      }

        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
