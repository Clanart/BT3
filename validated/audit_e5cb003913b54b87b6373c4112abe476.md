### Title
`getRewardablePercentWAD` treats a fully-in-cooldown balance as 100% rewardable when the balance is held in a single unexpired cooldown slot, allowing forfeiture-free yield extraction - ([File: VLMGP.sol])

### Summary
`getRewardablePercentWAD` in `VLMGP.sol` computes the rewardable percentage by summing a locked-balance term and a per-slot cooldown term, but the "still in cool down" branch adds `amountInCoolDown * 1e18 / userTotalVlmgp` unconditionally, without any time-decay factor. If a user moves their entire `userTotalVlmgp` into one still-cooling slot, `fullyInLock` is 0, so the function returns exactly `1e18` (100%), even though 100% of the balance is unvested and locked in cooldown.

### Finding Description
`getRewardablePercentWAD` (`VLMGP.sol:193-218`) computes:
- `percent = fullyInLock * 1e18 / userTotalVlmgp` for the still-locked portion [1](#0-0) 
- For each unlocking slot still in cooldown (`block.timestamp <= endTime`), it adds `amountInCoolDown * 1e18 / userTotalVlmgp` with no discount whatsoever, unlike the "fully unlocked" branch which scales by `(endTime - startTime) / (timeNow - startTime)` [2](#0-1) .

When an attacker calls `lock(amount)` then `startUnlock(amount)` for their entire balance, `getUserTotalLocked` becomes 0 and `getUserAmountInCoolDown` becomes the full amount, all held in one slot (`VLMGP.sol:275-311`). Then `fullyInLock = 0`, `inCoolDown = userTotalVlmgp`, so `percent = 0 + amountInCoolDown * 1e18 / userTotalVlmgp = 1e18` — a 100% rewardable result despite the account holding zero non-cooldown balance.

This percent feeds directly into `_calExpireForfeit` in `rewards/vlMGPBaseRewarder.sol:386-400`, called from `_sendReward` (`vlMGPBaseRewarder.sol:363-377`) whenever rewards are paid out: `rewardableAmount = _amount * rewardablePercentWAD / 1e18`, and `forfeitAmount = _amount - rewardableAmount`. With `rewardablePercentWAD == 1e18`, `forfeitAmount` is always 0, so no forfeiture is ever applied to a fully-in-cooldown attacker, defeating the intended penalty for holding rewards while withdrawing/cooling down.

No modifier, reentrancy guard, or reward-index update prevents this — it is a pure arithmetic/logic flaw in the rewardable-percent formula reachable via ordinary unprivileged calls (`lock`, `startUnlock`, followed by normal reward distribution/claim flow).

### Impact Explanation
This is a theft-of-unclaimed-yield issue (Immunefi "theft of unclaimed yield" class). Any unprivileged holder can, at zero extra cost beyond gas, always keep their full balance in a single non-expired cooldown slot and receive 100% of vesting/forfeitable rewards distributed while their tokens are in cooldown, which should instead be partially or fully forfeited back into the reward pool for other stakers (via `_queueNewRewardsWithoutTransfer`). This directly undermines the forfeiture invariant meant to discourage claiming full rewards while exiting the lock, resulting in economic loss to the reward pool/other stakers.

### Likelihood Explanation
Preconditions are trivial and fully within attacker's control: hold MGP, call `lock(amount)`, then `startUnlock(amount)` for the entire balance into one slot before `endTime`. No special role or capital beyond the locked MGP itself is required, and the exploit is repeatable indefinitely (attacker can re-lock/re-start-unlock or maintain the cooldown state to always benefit whenever rewards are distributed/claimed).

### Recommendation
Apply the same linear time-decay discount used in the "fully unlocked" branch to the "still in cool down" branch, e.g. scale by elapsed time relative to `coolDownInSecs` (`(timeNow - startTime) / (endTime - startTime)`) rather than granting full 1e18 weight for any amount sitting in an unexpired cooldown slot. Additionally consider capping total rewardable percent contributions from cooldown slots so it can never reach 100% while `fullyInLock == 0`.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder` with a reward token.
2. Attacker calls `lock(1000e18)`.
3. Attacker calls `startUnlock(1000e18)` — entire balance goes into unlock slot 0, `endTime = now + coolDownInSecs`.
4. Assert `vlMGP.getRewardablePercentWAD(attacker) == 1e18` (before `endTime`).
5. Fund the rewarder with reward tokens and trigger reward distribution/claim path (`_sendReward` via the manager/claim flow) for the attacker.
6. Assert `_calExpireForfeit`/`forfeitAmount == 0` and `toSend == full accrued reward amount`, confirming zero forfeiture despite 100% of the balance being in an unexpired cooldown. [3](#0-2) [4](#0-3)

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
