### Title
Missing Validation of Critical `ProtocolParamset` Fields Allows Deposit Signing Ceremony to Silently Produce Zero Signatures — (`crates/clementine-config/src/protocol.rs`, `core/src/config/protocol.rs`, `core/src/config/mod.rs`)

---

### Summary

`ProtocolParamset` is a plain public struct with all fields public. The only validation that exists is `finality_depth >= 1`, checked in `from_env()` and `from_toml_file()`. The startup helper `check_general_requirements()` — the Clementine analog of the Atlendis `deployLoan` factory — also only checks genesis hash, `start_height`, and `finality_depth`. Critical parameters `num_signed_kickoffs`, `num_kickoffs_per_round`, and `num_round_txs` are **never validated to be non-zero**, and the invariant `num_signed_kickoffs <= num_kickoffs_per_round` is **never enforced anywhere**. When `num_signed_kickoffs = 0`, the N-of-N deposit signing ceremony silently produces zero required signatures, the verifier's count check passes (0 == 0), and deposits are finalized with no signatures stored — permanently locking bridged BTC.

---

### Finding Description

`ProtocolParamset` is defined as a plain struct with public fields and no constructor-level validation: [1](#0-0) 

The two construction paths — `from_toml_file()` and `from_env()` — each validate only `finality_depth`: [2](#0-1) [3](#0-2) 

The startup validation helper `check_general_requirements()` — called in `main.rs` before any actor starts — also only checks genesis hash, `start_height >= genesis_height`, and `finality_depth >= 1`: [4](#0-3) [5](#0-4) 

No code path validates:
- `num_signed_kickoffs > 0`
- `num_kickoffs_per_round > 0`
- `num_round_txs > 0`
- `num_signed_kickoffs <= num_kickoffs_per_round`

`get_kickoff_utxos_to_sign` builds the list of kickoff indices to sign using `take(num_signed_kickoffs)` on a shuffled range of `num_kickoffs_per_round` items: [6](#0-5) 

When `num_signed_kickoffs = 0`, this returns an empty vec. `get_num_required_nofn_sigs` multiplies by `num_signed_kickoffs`, so it returns 0: [7](#0-6) 

The verifier's post-signing count check compares `kickoff_txids[operator_idx][round_idx].len()` against `num_signed_kickoffs`: [8](#0-7) 

When both are 0, the check `0 != 0` is false — no error is raised. The deposit proceeds to DB insertion with no signatures stored.

Additionally, `ProtocolParamset` can be constructed via `serde_json::from_str` in the gRPC compatibility conversion with no validation: [9](#0-8) 

---

### Impact Explanation

With `num_signed_kickoffs = 0`, the entire N-of-N signing ceremony for deposits is silently skipped. No signatures are stored in the DB. The move transaction — which requires N-of-N signatures to spend the deposit UTXO — cannot be constructed or broadcast. All deposits processed under this configuration are permanently locked. This breaks the core bridge safety invariant (N-of-N covenant) and causes permanent loss of bridged BTC.

The same class of silent failure applies to `num_round_txs = 0` (no round transactions, no kickoff UTXOs, no payout path) and `num_kickoffs_per_round = 0` (round transactions built with zero kickoff outputs, making all kickoff-dependent state transitions unreachable).

---

### Likelihood Explanation

This requires a developer or operator to set `num_signed_kickoffs = 0` in the TOML or environment config. The code bug is that this value is accepted without error at every construction path. The pattern is identical to the Atlendis finding: a developer adding a new paramset construction path (e.g., from a database snapshot, a migration script, or a test fixture using struct literal syntax) would bypass even the partial `finality_depth` check, since `ProtocolParamset { num_signed_kickoffs: 0, ..REGTEST_PARAMSET }` is valid Rust and compiles without warning. The `check_general_requirements()` call in `main.rs` would not catch it. [10](#0-9) 

---

### Recommendation

**Short term:** Add validation for `num_signed_kickoffs > 0`, `num_kickoffs_per_round > 0`, `num_round_txs > 0`, and `num_signed_kickoffs <= num_kickoffs_per_round` inside both `from_toml_file()` and `from_env()`, immediately after the struct is populated — mirroring the existing `finality_depth` check.

**Long term:** Enforce these invariants as close as possible to where the values are declared and used. Consider making `ProtocolParamset` construction go through a validated constructor (e.g., a `new()` or `try_new()` method) rather than allowing direct struct literal construction of a type whose fields have non-trivial cross-field invariants. The `check_general_requirements()` function should also be extended to cover all structural invariants, not just the subset it currently checks.

---

### Proof of Concept

1. Set `NUM_SIGNED_KICKOFFS=0` in the environment (or `num_signed_kickoffs = 0` in the TOML paramset file).
2. Start any actor. `from_env()` / `from_toml_file()` accept the value; `check_general_requirements()` does not reject it.
3. Initiate a deposit. `get_kickoff_utxos_to_sign` returns `[]`. The sighash stream inner loop (`for &kickoff_idx in &utxo_idxs`) never executes. Zero sighashes are generated.
4. `get_num_required_nofn_sigs` returns `0`. The verifier's count check `0 != 0` is false; no error is raised.
5. `insert_deposit_signatures_if_not_exist` is never called. The deposit is marked finalized with no signatures in the DB.
6. The move transaction cannot be signed or broadcast. The deposit UTXO is permanently locked. [11](#0-10) [7](#0-6) [8](#0-7)

    pub async fn check_general_requirements(&self) -> Result<(), BridgeError> {
        // check genesis state hash
        let rpc = ExtendedBitcoinRpc::connect(
            self.bitcoin_rpc_url.clone(),
            self.bitcoin_rpc_user.clone(),
            self.bitcoin_rpc_password.clone(),
            None,
        )
        .await
        .wrap_err("Failed to connect to Bitcoin RPC while checking general requirements")?;

        let genesis_chain_state = HeaderChainProver::get_chain_state_from_height(
            &rpc,
            self.protocol_paramset().genesis_height.into(),
            self.protocol_paramset().network,
        )
        .await
        .wrap_err("Failed to get genesis chain state while checking general requirements")?;

        let mut reasons = Vec::new();

        if genesis_chain_state.to_hash() != self.protocol_paramset().genesis_chain_state_hash {
            reasons.push(format!(
                "Genesis chain state hash mismatch, state hash generated from Bitcoin RPC ({}) does not match value in config ({})",
                hex::encode(genesis_chain_state.to_hash()),
                hex::encode(self.protocol_paramset().genesis_chain_state_hash)
            ));
        }

        if self.protocol_paramset().start_height < self.protocol_paramset().genesis_height {
            reasons.push(format!(
                "Start height is less than genesis height: {} < {}",
                self.protocol_paramset().start_height,
                self.protocol_paramset().genesis_height
            ));
        }

        if self.protocol_paramset().finality_depth < 1 {
            reasons.push(format!(
                "Finality depth ({}) cannot be less than 1",
                self.protocol_paramset().finality_depth
            ));
        }

        if !reasons.is_empty() {
            return Err(BridgeError::ConfigError(format!(
                "Invalid configuration due to: {}",
                reasons.join(" - ")
            )));
        }

        Ok(())
    }

pub fn get_kickoff_utxos_to_sign(
    paramset: &'static ProtocolParamset,
    op_xonly_pk: XOnlyPublicKey,
    deposit_blockhash: BlockHash,
    deposit_outpoint: bitcoin::OutPoint,
) -> Vec<usize> {
    let deposit_data = [
        op_xonly_pk.serialize().to_vec(),
        deposit_blockhash.to_byte_array().to_vec(),
        deposit_outpoint.txid.to_byte_array().to_vec(),
        deposit_outpoint.vout.to_le_bytes().to_vec(),
    ]
    .concat();

    let seed = bitcoin::hashes::sha256d::Hash::hash(&deposit_data).to_byte_array();
    let mut rng = ChaCha12Rng::from_seed(seed);

    let mut numbers: Vec<usize> = (0..paramset.num_kickoffs_per_round).collect();
    numbers.shuffle(&mut rng);

    numbers
        .into_iter()
        .take(paramset.num_signed_kickoffs)
        .collect()
}
