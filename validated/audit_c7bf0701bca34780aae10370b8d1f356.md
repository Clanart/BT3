### Title
Malformed offer/CR-CAT puzzle driver causes AssertionError (process crash / DoS) instead of clean rejection in `Offer._get_offered_coins()` - (File: chia/wallet/trading/offer.py)

### Summary
`chia/wallet/trading/offer.py`'s `Offer._get_offered_coins()` uses bare `assert` statements to validate data derived from an externally-supplied, untrusted offer file's `driver_dict` and coin spends, rather than raising a handled exception. This mirrors the TensorFlow `DrawBoundingBoxes` CHECK-fail bug class: attacker-controlled input reaches a `CHECK`/`assert`-style invariant instead of a graceful `OP_REQUIRES`/`raise ValueError` style validation path.

### Finding Description
`Offer._get_offered_coins()` matches each coin spend's puzzle reveal against a driver dictionary supplied by the offer counterparty, then does: [1](#0-0) 
```
puzzle_driver = match_puzzle(parent_puzzle)
if puzzle_driver is not None:
    ...
    inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
    inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
    assert inner_puzzle is not None and inner_solution is not None
    ...
    puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
    assert cost_left >= puzzle_cost
```
`get_inner_puzzle`/`get_inner_solution` are outer-puzzle-driver dispatch functions (e.g. `CATOuterPuzzle.get_inner_puzzle`/`get_inner_solution` in `chia/wallet/cat_wallet/cat_outer_puzzle.py`) that can legitimately return `None` when the puzzle structure doesn't match the recursive layer described by `constructor.also()` (CR-CAT/VC/singleton layering), or `raise ValueError` for other mismatches. `match_puzzle()` only performs a shallow structural match of the top puzzle layer; a crafted offer where the outer puzzle matches but the inner/`also()` layer is inconsistent (e.g., a CAT/CR-CAT layer whose curried arguments don't align with the claimed inner puzzle, or a coin spend whose declared `driver_dict` type doesn't correspond to the actual solution shape) can make `get_inner_puzzle`/`get_inner_solution` return `None`, tripping the bare `assert` and raising an unhandled `AssertionError` instead of a `ValueError`/`ValidationError` that calling code is prepared to catch.

This differs from the CVE root cause only in mechanism (Python `assert` vs. C++ `CHECK_*`), but is the same class: attacker-controlled structured input reaching a "should never happen" invariant check instead of `OP_REQUIRES`-style input validation.

### Impact Explanation
`_get_offered_coins()` backs `Offer.get_offered_coins()`, which is used by `TradeManager.calculate_tx_records_for_offer()` and other offer-processing paths reached when a wallet user opens or accepts an offer file received from an untrusted counterparty (`respond_to_offer`, offer summary/inspection RPCs, CLI `chia wallet` offer commands). An `AssertionError` raised here is not the intended `ValueError`/`ValidationError` control-flow that `Offer.__post_init__` and callers otherwise use for malformed input (see the `except ValidationError` / `except ValueError` handling in `__post_init__`), so it can propagate as an unhandled exception through wallet RPC/CLI code paths that only catch `ValueError`-family exceptions, crashing the wallet process or the request handler when a user merely inspects/attempts to take a maliciously crafted offer. This is a spend-triggered/offer-triggered denial of service reachable by any offer counterparty, matching the "Medium" severity class of the reference CHECK-fail bug (crash via malformed input, no direct fund theft).

### Likelihood Explanation
Likelihood is moderate: constructing an offer whose driver_dict/coin-spend puzzle structure passes `match_puzzle()`'s shallow match but fails the deeper `get_inner_puzzle`/`get_inner_solution` reconstruction requires crafting a CLVM puzzle reveal/solution with valid outer-layer curry parameters but an inconsistent inner layer — feasible for an attacker with CLVM tooling, since offers are fully attacker-controlled binary/bech32 blobs with no additional cryptographic gating before this code runs. I was not able to construct or verify a concrete byte-level Proof-of-Concept offer within this investigation (no sandbox/CLVM execution available here), so exploitability should be confirmed by actually building such an offer and feeding it through `Offer.from_bytes()`/`get_offered_coins()`.

### Recommendation
Replace the bare `assert` statements in `Offer._get_offered_coins()` (and any other `assert`-based invariant checks in this method reachable from untrusted `driver_dict`/coin-spend data) with explicit checks that raise `ValueError` (consistent with the rest of `Offer.__post_init__`'s error handling), so malformed/adversarial offers are cleanly rejected instead of crashing the process with an `AssertionError`.

### Proof of Concept
Not independently verified in this session — I could not execute CLVM/build a concrete malicious offer blob with the tools available (read-only code search only).         offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")
            else:
                # It's much easier if the asset is bare XCH
                asset_id = None
                coins_for_this_spend.extend([a for a in additions if a.puzzle_hash == OFFER_MOD_HASH])

            # We only care about unspent coins
            coins_for_this_spend = [c for c in coins_for_this_spend if c not in self._bundle.removals()]

            if coins_for_this_spend != []:
                offered_coins.setdefault(asset_id, [])
                offered_coins[asset_id].extend(coins_for_this_spend)
        return offered_coins

    def get_inner_puzzle(
        self, constructor: PuzzleInfo, puzzle_reveal: UnknownPuzzle, solution: Program | None = None
    ) -> Program | None:
        args = match_cat_puzzle(puzzle_reveal)
        if args is None:
            raise ValueError("This driver is not for the specified puzzle reveal")
        _, _, inner_puzzle = args
        also = constructor.also()
        if also is not None:
            deep_inner_puzzle: Program | None = self._get_inner_puzzle(
                also,
                UnknownPuzzle(known_program=inner_puzzle),
                solution.first() if solution is not None else None,
            )
            return deep_inner_puzzle
        else:
            return inner_puzzle

    def get_inner_solution(self, constructor: PuzzleInfo, solution: Program) -> Program | None:
        my_inner_solution: Program = solution.first()
        also = constructor.also()
        if also:
            deep_inner_solution: Program | None = self._get_inner_solution(also, my_inner_solution)
            return deep_inner_solution
        else:
            return my_inner_solution
