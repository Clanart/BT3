### Title
ReceivedOutput deserialization pairs an arbitrary scalar offset with an arbitrary script_pubkey, letting an output be claimed/spent under a key context that does not own it - ([File: crypto/../networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` deserializes three independent fields — `offset` (a scalar), `output` (a `TxOut` carrying the `script_pubkey`), and `outpoint` — without verifying that the supplied offset actually derives the key committed to by `script_pubkey`. This is the same bug class as the RDS report: a lookup/pairing keyed on insufficient context (`script_pubkey` ↔ `offset` pair delivered as a bundle, with no `net_eq`-style consistency check) lets an object produced under one key context be consumed under another. The consistent pairing is normally guaranteed only inside `Scanner::scan_transaction`, which maps `script_pubkey` → `offset` via the `scripts` table built by `Scanner::new`/`register_offset`. `ReceivedOutput::read` bypasses that table entirely and trusts the serialized pair. [1](#0-0) 

### Finding Description
`Scanner` maintains `scripts: HashMap<ScriptBuf, Scalar>` and `scan_transaction` only ever emits a `ReceivedOutput` when `self.scripts.get(&output.script_pubkey)` succeeds, so any output it produces has an offset `o` satisfying `script_pubkey == p2tr(key + G·o)` (modulo the even-Y increment loop in `register_offset`). [2](#0-1) 

`ReceivedOutput::read` performs no such check: it reads `Secp256k1::read_F` for the offset, then `TxOut::consensus_decode` and `OutPoint::consensus_decode`, and returns the triple verbatim. There is no `Scanner` or base key in scope, and no recomputation of `p2tr_script_buf(key + GENERATOR * offset)` against `output.script_pubkey`. [1](#0-0) 

Downstream, the spending path trusts `output.offset()` as "the scalar offset to obtain the key usable to spend this output" (the documented contract at lines 91–92 and used by `SignableTransaction::multisig`/FROST via `ThresholdKeys::offset`, which adds the offset to the lowest-ID participant's share in `ThresholdKeys::view`). [3](#0-2) 

### Impact Explanation
A `ReceivedOutput` whose offset does not correspond to its `script_pubkey` causes the signing flow to tweak the group key by the wrong scalar. The resulting Schnorr signature is produced for `group_key + offset·G`, which does not match the key committed in the prevout's `script_pubkey`, so the spend is invalid. An output reported as received and spendable therefore is not spendable: funds credited by scanning/deserialization cannot be moved, and any batch `SignableTransaction` including the poisoned input produces a transaction that fails Bitcoin consensus validation. Because offsets are surjective in `register_offset` (offsets are incremented until the derived key is even), even honestly round-tripped data is the only safe source — any byte-level injection, cross-context replay of a serialized `ReceivedOutput` from a different base key/scanner, or corrupted storage silently crosses the "namespace" boundary. [4](#0-3) 

### Likelihood Explanation
Reachable wherever serialized `ReceivedOutput`s cross a trust boundary (reloaded from disk, transmitted between components, or reconstructed after the originating `Scanner` — with its base `key` — is gone, exactly the dangling-context shape of the RDS bug). `ReceivedOutput::read` is explicitly listed as an untrusted-bytes sink. The check is cheap and its absence is a real correctness gap; however, exploitation requires an attacker to influence the serialized bytes consumed by a wallet/processor instance, and the result is funds becoming unspendable (integrity/availability loss) rather than theft, since the attacker cannot redirect the script_pubkey to a key they control while keeping a valid signature. Severity: Medium. [5](#0-4) 

### Recommendation
Bind the offset to its key context at deserialization or spend time. Two options:
- Include the expected base key (or the scanner) when reconstructing: add a `Scanner::read_output(reader)` / `ReceivedOutput::read_with(key, reader)` that recomputes `p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset)` and rejects the input unless it equals `output.script_pubkey` (the `net_eq` check analogue).
- Alternatively, have `SignableTransaction::new`/`multisig` re-derive the tweaked key from `output.offset()` and assert it matches `output.output().script_pubkey` before building the sighash/commitment machines, so a mismatched pair fails loudly instead of producing an invalid signature.

### Proof of Concept
```rust
// networks/bitcoin: demonstrates the missing offset<->script_pubkey binding
let key = even_key();                       // Serai group key
let scanner = Scanner::new(key).unwrap();
let real = scanner.register_offset(Scalar::random(&mut OsRng)).unwrap();

// Attacker-controlled bytes: offset from one context, script_pubkey from another
let mut foreign_offset = Scalar::random(&mut OsRng);
while p2tr_script_buf(key + (ProjectivePoint::GENERATOR * foreign_offset)).is_none() {
  foreign_offset += Scalar::ONE;
}
let foreign_script =
  p2tr_script_buf(key + (ProjectivePoint::GENERATOR * foreign_offset)).unwrap();

// ReceivedOutput::read accepts the mismatched pair without any check:
let mut buf = Vec::new();
buf.extend(real.to_repr().as_ref());          // offset for context A
buf.extend(serialize(&TxOut {                 // script_pubkey for context B
  script_pubkey: foreign_script,
  value: Amount::from_sat(100_000),
}));
buf.extend(serialize(&OutPoint::new(Txid::all_zeros(), 0)));
let forged = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
// forged.offset() == real, but script_pubkey commits to key + foreign_offset*G.
// Signing the spend tweaks by `real`; the signature fails for the prevout's
// committed key -> input reported received is unspendable, poisoning the TX.
```

Root cause: `ReceivedOutput::read` reconstructs a context-bound pair (offset is only meaningful relative to a specific base `key`/`Scanner`) from a context-free byte string and never re-verifies the binding — the direct analog of `rds_find_bound` keying on `(addr, port, scope_id)` while omitting the netns, fixed upstream by a `net_eq` check at delivery time. [6](#0-5)

    let output;
    let outpoint;

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
