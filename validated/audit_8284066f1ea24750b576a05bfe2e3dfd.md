### Title
Empty DLEq proofs verify without proving any statement - (File: crypto/dleq/src/lib.rs)

### Summary
`DLEqProof::verify` accepts zero-length `generators` and `points` arrays because it only checks that their lengths match, iterates over no statements, and compares the submitted challenge with the transcript challenge. [1](#0-0) 

### Finding Description
The verifier does not require at least one generator/point pair. Consequently, an adversary can provide a proof whose `c` equals the deterministic challenge produced from an otherwise empty DLEq transcript; `s` is never used in a verification equation. [2](#0-1)  Publicly reachable deserialization via `DLEqProof::read` only parses two canonical scalars and does not establish that any statement was proven. [3](#0-2)  The same empty-statement pattern exists in `MultiDLEqProof::verify`, which checks only outer and per-series lengths before accepting the challenge. [4](#0-3) 

### Impact Explanation
If an integration derives the generator or point list from an adversarial protocol message and permits it to be empty, the adversary can obtain `Ok(())` from `verify` without proving knowledge of any discrete logarithm. This is a forged proof for the API’s expected precondition that a DLEq proof commits to at least one statement.

### Likelihood Explanation
The attack requires the calling protocol to accept a zero-length statement list. The vulnerable API itself does not document or enforce a non-empty list, while both proof creation and verification proceed normally with empty inputs. [5](#0-4) [2](#0-1) 

### Recommendation
Reject empty `generators` and `points` in `DLEqProof::verify`, and reject empty outer or inner statement lists in `MultiDLEqProof::verify`. Ideally, `prove` should also reject empty statement sets so invalid proofs cannot be constructed through the public API.

### Proof of Concept

```rust
use rand_core::OsRng;
use zeroize::Zeroizing;
use transcript::RecommendedTranscript;
use ciphersuite::group::ff::Field;
use k256::{ProjectivePoint, Scalar};
use dleq::DLEqProof;

let scalar = Zeroizing::new(Scalar::ONE);

let mut prover_transcript = RecommendedTranscript::new(b"protocol context");
let proof = DLEqProof::<ProjectivePoint>::prove(
    &mut OsRng,
    &mut prover_transcript,
    &[],
    &scalar,
);

let mut verifier_transcript = RecommendedTranscript::new(b"protocol context");
assert!(proof.verify(&mut verifier_transcript, &[], &[]).is_ok());
```

`prove` performs no per-generator transcript operation for the empty slice, while `verify` performs no verification equation and accepts the matching empty-transcript challenge. [6](#0-5) [7](#0-6)
