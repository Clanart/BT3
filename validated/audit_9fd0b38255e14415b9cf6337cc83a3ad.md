### Title
Payout attribution is not covered by the user's `SIGHASH_SINGLE|ANYONECANPAY` signature, letting anyone front-run and redirect an operator's reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The bridge attributes a peg-out payout to "whichever operator's x-only pubkey is written in the payout transaction's `OP_RETURN` output." That attribution is later used by verifiers/operators to decide who is entitled to claim reimbursement from the vault. However, the only cryptographic authorization on the payout transaction is the withdrawing user's signature over input 0 using `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, which — by Bitcoin sighash semantics — does not commit to the `OP_RETURN` output (index 2) or to any additional funding inputs. This is the same class of defect as the referenced report: the mechanism meant to bind "who legitimately did the work" to "who gets the credit/benefit" is insufficient, letting an unprivileged party take over that attribution.

### Finding Description
`create_payout_txhandler` builds the payout tx with:
- input 0: the user's withdrawal UTXO, spent via key-path with the user's own signature [1](#0-0) 
- output 0: the user's payout
- output 2: an `OP_RETURN` carrying whichever `operator_xonly_pk` the constructor chooses [2](#0-1) 

The operator's `withdraw()` explicitly requires the user's signature to use `SinglePlusAnyoneCanPay`, and only verifies that signature against the sighash of input 0 [3](#0-2) . Under `SIGHASH_SINGLE`, only the output at the *same index as the signed input* (i.e. output 0, the user payout) is committed to; under `ANYONECANPAY`, other inputs are excluded from commitment. Neither clause covers the `OP_RETURN` output that records who "fronted" the payout, nor does it prevent adding arbitrary extra funding inputs.

Consequently, once the user's signature for input 0 is observable (e.g. relayed in the Bitcoin mempool by the legitimate operator attempting to front the withdrawal, or otherwise obtained off-chain), any unprivileged third party can build a *different* valid payout transaction that:
- reuses the same signed input/output-0 pair (so it is still valid and still pays the user correctly),
- supplies its own funding inputs, and
- writes an `OP_RETURN` crediting a different `operator_xonly_pk` of the attacker's choosing.

If this substitute transaction confirms instead of the original operator's transaction, `update_finalized_payouts` parses the `OP_RETURN` and records that (attacker-chosen) key as the payer [4](#0-3) . `validate_payer_is_operator` and the reimbursement pipeline (`PayoutCheckerTask` → `handle_finalized_payout` → kickoff/Reimburse) then treat that attacker-chosen operator as the legitimate payer entitled to claim reimbursement from the vault [5](#0-4) [6](#0-5) , even though the operator originally set up to front that specific withdrawal never got credited or reimbursed.

This directly breaks the binding "the operator credited versus the party that paid": the credited operator is not necessarily the one whose transaction actually confirmed, and the original front-runner's transaction (and thus their entitlement to reimbursement) can be pre-empted without their consent.

### Impact Explanation
This lets an unprivileged network observer redirect which operator is attributed as the payer of a specific withdrawal, without needing any privileged role, key, or majority-hashrate assumption — merely visibility into the unconfirmed payout transaction and the ability to broadcast a competing one with equal or higher fee. The party whose credit is stolen loses the ability to claim reimbursement for a withdrawal it was legitimately servicing, and the vault instead reimburses whichever `operator_xonly_pk` the attacker chose to write into `OP_RETURN` — i.e. reimbursement can be misattributed to a party that did not do the work the credit implies. This matches the Critical class "an operator reimbursed for a payout it never funded" / "an honest operator permanently unable to be reimbursed" once its fronting transaction is pre-empted.

### Likelihood Explanation
The only prerequisite is observing the user's signed input before confirmation (visible in the Bitcoin mempool once any operator broadcasts it) and being able to fund a replacement transaction and get it mined first — no special role, key compromise, or protocol privilege is required.

### Recommendation
Bind the `OP_RETURN` attribution output (and ideally disallow arbitrary extra funding inputs) to the user's signature, e.g. by having the user sign with `SIGHASH_ALL` (or a sighash flavor that commits to all outputs) over a transaction template that already fixes the crediting operator's pubkey, or by moving the attribution commitment into data the verifiers already authenticate (e.g., have the user's off-chain authorization message itself specify/commit to the intended operator's xonly pubkey and reject payouts whose on-chain `OP_RETURN` operator does not match the pre-agreed one).

### Proof of Concept
1. Legitimate Operator A calls `withdraw()` for withdrawal index `w`; this constructs and broadcasts a payout tx `T_A` with input 0 = user's UTXO (signed `SinglePlusAnyoneCanPay`), output 0 = user's payout, `OP_RETURN` = A's xonly pk [7](#0-6) .
2. `T_A` propagates to the Bitcoin mempool before confirmation; an unprivileged observer extracts the witness for input 0 (the user's key-path signature over the fixed input/output-0 pair).
3. The observer constructs `T_B`: reuses input 0 with the same signature/witness, keeps output 0 identical (required by `SIGHASH_SINGLE`), adds its own funding input(s) (`ANYONECANPAY` permits this), and sets `OP_RETURN` to a different `operator_xonly_pk` (e.g. its own registered operator identity), per the unconstrained construction in `create_payout_txhandler` [1](#0-0) .
4. `T_B` is broadcast with a competitive fee and confirms instead of `T_A`.
5. `update_finalized_payouts` parses `T_B`'s `OP_RETURN` and records the attacker-chosen operator as payer [4](#0-3) ; that operator's node subsequently passes `validate_payer_is_operator` and proceeds through kickoff/Reimburse to claim vault funds [8](#0-7) , while Operator A — who actually intended to front the withdrawal — receives no credit for `T_A`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,

            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator

            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
