### Title
`SchnorrAggregate::verify` vacuously accepts a zero-length aggregate with `s = 0`, forging "consensus" of an empty signer set — ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
The external report describes an empty-state edge case (`0/0`) collapsing to a sentinel value (`1e18`) that the surrounding invariant mishandles. The same bug class exists in `crypto/schnorr/src/aggregate.rs`: when the aggregate signature contains zero `R` values and the caller verifies against an empty `keys_and_challenges` list, the verification equation degenerates to `-s·G == identity`, which is satisfied by the trivially forgeable `s = 0`. `SchnorrAggregate::read` accepts a serialized aggregate with `Rs.len() == 0` and `s == 0`, so an unprivileged party can craft bytes that pass verification for any empty signer set without knowing any private key.

### Finding Description
`SchnorrAggregate::verify` checks only that `self.Rs.len() == keys_and_challenges.len()` and then evaluates a single multiexp:

```rust
// crypto/schnorr/src/aggregate.rs:127-146
pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }
    ...
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
}
```

When both lists are empty, `pairs` contains only `(-self.s, generator)`, so `verify` returns `true` whenever `s == 0`. The length check passes because `0 == 0`. Deserialization places no lower bound on `Rs`:

```rust
// crypto/schnorr/src/aggregate.rs:77-87
let mut len = [0; 4];
reader.read_exact(&mut len)?;
let mut Rs = vec![];
for _ in 0 .. u32::from_le_bytes(len) { Rs.push(C::read_G(reader)?); }
Ok(SchnorrAggregate { Rs, s: C::read_F(reader)? })
```

A `len = 0` prefix followed by the encoding of `0` produces a "valid" aggregate. Note the asymmetry with the honest path: `SchnorrAggregator::complete` explicitly returns `None` when nothing was aggregated (`crypto/schnorr/src/aggregate.rs:175-178`), showing the authors recognized empty aggregates are meaningless to produce — but the verifier does not mirror that guard, so the edge case is only reachable through attacker-controlled deserialized input.

### Impact Explanation
Any code path that feeds untrusted bytes to `SchnorrAggregate::read` and then calls `verify` with a signer list that can be empty (e.g., a list derived from attacker-supplied or dynamically filtered data) will accept a proof the "aggregate" was produced by that set — i.e., a forged signature/attestation over a set that never signed anything. This mirrors the report's root cause: the degenerate empty case yields a sentinel-true result that the invariant (`is_identity`) treats as success, when the correct behavior is rejection.

### Likelihood Explanation
Exploitation requires a caller that verifies aggregates over a possibly-empty `keys_and_challenges` list. The verifier-side list is caller-supplied, so this is an edge-case forgery rather than a universally reachable break of non-empty aggregates — consistent with Medium severity. `read` itself is explicitly listed as an untrusted-bytes sink, and there is no documented `MUST` on the API requiring a non-empty verification set (the only documented requirements concern challenge/DST binding).

### Recommendation
Mirror the aggregator's own guard in `verify`: return `false` when `keys_and_challenges` is empty (or equivalently when `self.Rs` is empty), before evaluating the multiexp. Optionally also reject `Rs.len() == 0` in `SchnorrAggregate::read`, matching the fact that `SchnorrAggregator::complete` can never legitimately emit such an aggregate.

### Proof of Concept
```rust
// Conceptual PoC against crypto/schnorr (requires the `aggregate` feature)
use ciphersuite::{group::ff::Field, Ciphersuite};
use dalek_ff_group::Ed25519;
use schnorr::aggregate::SchnorrAggregate;

// Attacker-controlled bytes: u32 len = 0, then s = 0 (32 zero bytes for Ed25519)
let mut bytes = 0u32.to_le_bytes().to_vec();
bytes.extend([0u8; 32]);

let agg = SchnorrAggregate::<Ed25519>::read::<&[u8]>(&mut bytes.as_slice()).unwrap();

// Verifier supplies an empty (untrusted-influenced) signer list
assert!(agg.verify(b"Some DST", &[])); // forged: passes with no private keys
```

No secret key, nonce, or signature participation is needed; verification reduces to `-0 · G == identity` and returns `true`.
