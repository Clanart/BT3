### Title
Malicious identity nonce commitments panic Taproot signing - (File: networks/bitcoin/src/crypto.rs)

### Summary
A participant can encode both generator commitments in a FROST preprocess as the point at infinity. `Commitments::read` accepts the serialized points without rejecting the identity element, while `BindingFactor::nonces` later combines those commitments into an identity nonce sum. The Bitcoin `Hram::hram` implementation unconditionally extracts the nonce's x-coordinate and panics when it is infinity, turning a malformed public preprocess message into a remotely triggerable signing-path denial of service.

### Finding Description
`Commitments::read` only enforces the structural number of nonce/generator commitments and delegates each element to `C::read_G`; it performs no semantic rejection of the identity point. [1](#0-0)  Each nested nonce commitment likewise reads exactly two group elements without checking whether either is identity. [2](#0-1) 

During `AlgorithmSignMachine::sign`, those attacker-controlled commitments are bound and aggregated into `Rs` through `B.nonces(&nonces)`. [3](#0-2)  If a participant supplies `(D, E) = (infinity, infinity)`, the calculated bound nonce contribution is `infinity + infinity * rho`, which remains infinity. [4](#0-3)  When all commitments in that nonce position are identity encodings, the resulting `nonce_sums[0][0]` passed to `Schnorr::sign_share` is therefore the point at infinity. [5](#0-4) 

The Bitcoin Schnorr HRAM calls `x(R)` before producing the Fiat-Shamir challenge. [6](#0-5)  `x` serializes the point and then executes `expect("point at infinity")`, so an identity nonce triggers an unconditional panic rather than returning a signing error. [7](#0-6) 

### Impact Explanation
A participant able to submit a preprocess message can abort every signing attempt in which its malicious preprocess is selected. If the process uses `panic = abort`, this terminates the signer; under unwinding, it still unwinds the signing task and prevents the transaction signature from being produced. This is an availability failure reachable through untrusted protocol input rather than an internal invariant failure.

### Likelihood Explanation
The attack does not require controlling the secret share, producing a valid proof, or guessing a rare value. It only requires submitting two encoded identity points in place of the two expected nonce commitments, which `read_preprocess` accepts structurally. Because preprocesses are intentionally read from other participants, the input path is exposed to an unprivileged protocol participant.

### Recommendation
Reject identity nonce commitments during `Commitments::read` or before binding/aggregation, and return an `InvalidPreprocess` error identifying the offending participant. Additionally, make the Taproot HRAM return a `Result` or otherwise propagate an invalid-nonce error instead of panicking on the point at infinity.

### Proof of Concept
```rust
use frost::{curve::{Ciphersuite, Secp256k1}, sign::PreprocessMachine};
use rand_core::OsRng;

// `keys` is a locally generated ThresholdKeys<Secp256k1> for a multisig
// which includes `attacker` as another participant.
let (machine, _our_preprocess) =
    frost::sign::AlgorithmMachine::new(bitcoin_serai::crypto::Schnorr::new(), keys)
        .preprocess(&mut OsRng);

let identity = <Secp256k1 as Ciphersuite>::G::identity().to_bytes();
let mut malicious_preprocess = Vec::new();
malicious_preprocess.extend_from_slice(identity.as_ref()); // D
malicious_preprocess.extend_from_slice(identity.as_ref()); // E

let malicious =
    machine.read_preprocess(&mut malicious_preprocess.as_slice()).unwrap();

let mut preprocesses = std::collections::HashMap::new();
preprocesses.insert(attacker, malicious);

// The malicious participant's bound nonce is infinity. Hram::hram calls
// x(R), which hits `expect("point at infinity")` and panics.
let _ = machine.sign(preprocesses, b"transaction sighash");
```
