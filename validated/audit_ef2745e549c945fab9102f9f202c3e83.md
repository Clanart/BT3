### Title
`isGitHubHost()` uses a substring/prefix regex instead of a proper domain-suffix check, causing attacker-controlled hosts like `github.<attacker>.com` to be misclassified as GitHub Enterprise, triggering unintended sign-in prompts and enterprise credential-helper behavior - (File: `app/src/lib/api.ts`)

### Summary
The external report's broken invariant is: *a naive prefix/substring string check on an untrusted identifier is used to make a trust decision that should require exact/structured matching*. In `OracleUtils.ethLeftSide()`, checking the first 3 characters of a description string ("ETH") instead of a properly delimited match ("ETH/") let unrelated assets (`ETHx/ETH`) be misclassified as ETH. The same class of bug exists in GitHub Desktop's host-classification logic in `isGitHubHost()`, where a loosely-anchored regex is used to decide whether an arbitrary, attacker-influenced hostname (from a git remote URL) "is GitHub", instead of checking that it is exactly `github.com`/`*.ghe.com` or a validated subdomain relationship.

### Finding Description
`isGitHubHost()` classifies a URL's hostname as GitHub-owned using several fast-path heuristics before falling back to a network probe: [1](#0-0) 

The relevant heuristic is:
```
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```
This regex matches whenever the substring `github.` occurs either at the very start of the hostname or immediately after a `.`. That means a hostname such as `github.evil.com` (or `sub.github.evil.com`) satisfies `(^|\.)(github)\.` even though it is not a github.com/GHE subdomain relationship at all — it's simply a third-party domain whose registrable domain starts with the label `github`. This is structurally identical to the audited bug: matching a *fixed prefix in the wrong position* of an untrusted string, rather than validating the full/anchored structure (equivalent of requiring `ETH/` vs. just `ETH`).

This function is consumed by the trampoline credential helper's `getEndpointKind()`: [2](#0-1) 

`getEndpointKind()` is invoked by Git itself (via the credential helper protocol) whenever Git needs credentials for a remote host — the hostname comes directly from the remote URL that Desktop is operating against (`getCredentialUrl(cred)`), which is attacker-controllable if the user clones/adds/fetches from a repository whose remote (or a redirect/submodule URL) points at `github.<attacker-domain>`. If `isGitHubHost()` wrongly returns `true` for such a host, `getEndpointKind()` returns `'enterprise'` instead of `'generic'`: [3](#0-2) 

The downstream effect in `getCredential()`:
- Desktop treats the attacker's host as if it were a legitimate GitHub Enterprise endpoint and will prompt the user with `ui.promptForGitHubSignIn(endpoint)`, i.e. **initiate a GitHub OAuth/Enterprise sign-in flow against an endpoint the attacker chose**, instead of falling back to the normal generic-git-credential prompt/external helper path.
- It skips the generic credential-manager route (`useExternalCredentialHelper()... : getGenericCredential`) entirely, since that only runs when `endpointKind === 'generic'`.
- On `storeCredential`/`eraseCredential`, credentials for that attacker-controlled host would similarly bypass generic storage because `getEndpointKind()` returns non-`'generic'`.

None of the existing guards stop this: `isDotCom()` and `isGHE()` (exact-hostname / `.ghe.com`-suffix checks) correctly reject `github.evil.com`, but the code falls through to the loosely-anchored regex specifically meant to catch legitimate self-hosted-looking GitHub Enterprise names like `github.example.com` — and it does not distinguish that from `github.<attacker-tld>`. [4](#0-3) 

### Impact Explanation
An attacker who controls (or can lure a user to add) a git remote/proxy hostname of the form `github.<attacker-domain>` (fully valid, purchasable domain names, e.g. `github.attacker.io`) can cause Desktop to:
1. Misclassify the host as GitHub Enterprise, triggering the app's GitHub sign-in / OAuth flow pointed at an attacker-influenced endpoint context rather than the safe generic-credential prompt, and
2. Alter how Desktop's credential helper stores/erases/fetches credentials for that host (enterprise path vs. generic-credential path), which is a silent behavioral corruption of the trust decision the credential helper is supposed to make about who it's authenticating with.

This matches the "unauthorized OAuth binding" / "credential handling corruption" category in the valid-impact list: an attacker-controlled git remote causes an incorrect trust/authentication decision without any local access, admin rights, or social engineering beyond a normal clone/add-remote action.

### Likelihood Explanation
The trigger requires only that the user open/clone/fetch a repository whose remote host is `github.<attacker-domain>` — a fully attacker-purchasable domain, no privileged network position or MITM needed. The `wwwauth[...]` and `findGitHubTrampolineAccount` fast paths ahead of the regex do not prevent this (they only short-circuit for hosts the app already recognizes or has a stored account for); a new/unknown host with a domain like `github.attacker.io` falls straight into the vulnerable regex check.

### Recommendation
Replace the substring-prefix regex in `isGitHubHost()`'s `github.` heuristic with a proper domain-suffix/label check equivalent to a full domain match — e.g., only match if the hostname is exactly `github.com`/`*.github.com`, or use a public-suffix-aware check that validates `github` is a top-level registrable-domain label of a *known* enterprise pattern, not merely a substring following a dot or the start of the string. At minimum, anchor to end-of-string with proper label boundaries (e.g. `hostname === 'github.<tld>'` only against an allow-listed enterprise config) rather than `(^|\.)(github)\.` which accepts arbitrary suffixes after the matched label.

### Proof of Concept
1. Add a git remote (or clone) with URL `https://github.attacker.io/foo/bar.git`.
2. Trigger a Git operation requiring credentials (e.g., `git fetch`) so the credential helper trampoline is invoked with this URL.
3. In `getEndpointKind()` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`), execution reaches `isGitHubHost(endpoint)` for `endpoint = 'https://github.attacker.io/...'`.
4. In `isGitHubHost()` (`app/src/lib/api.ts:2447-2459`), `hostname = 'github.attacker.io'` matches `/(^|\.)(github)\./` (matches at start-of-string), returning `true` and short-circuiting before the legitimate network probe/meta-endpoint verification.
5. `getEndpointKind()` returns `'enterprise'`, causing `getCredential()` to invoke `ui.promptForGitHubSignIn(endpoint)` for `github.attacker.io` instead of the generic credential flow. [5](#0-4)

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
```

```typescript
export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'
}

export const isGist = (ep: string) => {
  const { hostname } = new URL(ep)
  return hostname === 'gist.github.com' || hostname === 'gist.ghe.io'
}

/** Whether or not the given endpoint URI is under the ghe.com domain */
export const isGHE = (ep: string) => new URL(ep).hostname.endsWith('.ghe.com')
```
