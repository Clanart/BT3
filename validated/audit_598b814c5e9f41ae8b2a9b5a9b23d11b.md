### Title
Direct token donation to `MasterMagpie` permanently dilutes reward emissions for legitimate stakers - (File: `rewards/MasterMagpie.sol`)

### Summary
`MasterMagpie` computes the LP supply used in its per-share reward accounting via `_calLpSupply`, which for ordinary staking-token pools falls back to `IERC20(_stakingToken).balanceOf(address(this))` rather than an internally tracked total-deposited amount. [1](#0-0) 

### Finding Description
For any pool whose staking token is not `vlmgp` or `mWomSV`, `_calLpSupply` returns the raw ERC20 balance of the `MasterMagpie` contract instead of a pool-tracked deposit total. [1](#0-0) 
An unprivileged wallet can simply call `transfer()` on the pool's staking token to send tokens directly to `MasterMagpie` without going through the legitimate `deposit`/`depositFor` flow. Because no `UserInfo.amount` is credited for this donation, the tokens are never attributable to any account and can never be withdrawn back out through the normal accounting path, yet they are counted in `lpSupply` for every subsequent `updatePool`-style reward-rate calculation (as seen in the equivalent mock's `updatePool`, `pool.accRewardPerShare = pool.accRewardPerShare + (mgpReward * 1e12) / lpSupply`). [2](#0-1) 
This mirrors exactly the "balance inflation via `balanceOf(address(this))`" bug class from the external report: the emission-rate math trusts the live token balance of the contract as a supply denominator, which is directly manipulable by any wallet through a plain token transfer, with no compensating `farm`/sweep mechanism to remove the donated, unattributed tokens from the denominator.

### Impact Explanation
Once the phantom balance is donated, it permanently and irreversibly deflates `accMGPPerShare`/`accRewardPerShare` increments for that pool on every future `updatePool` call, since the denominator is inflated but no corresponding legitimate depositor exists to ever reduce it. This results in a permanent reduction/freezing of unclaimed emission yield for every current and future staker in that pool, satisfying the "theft or permanent freezing of unclaimed yield" impact bar. The attacker gains nothing directly (their donated tokens are unrecoverable too), but they can grief any pool's reward stream permanently and cheaply (cost equal to a minimal token transfer, e.g. dust amount of the staking token), which is disproportionate to the resulting protocol-wide, permanent yield degradation for all other depositors.

### Likelihood Explanation
The attack requires only owning or acquiring a small amount of the staking token for a targeted pool and calling `IERC20.transfer(masterMagpie, amount)` — a completely unprivileged, single-transaction action with no special timing, oracle, or governance requirement. Any pool using a standard (non-`vlmgp`/`mWomSV`) LP/staking token is exposed.

### Recommendation
Track a pool-level `totalStaked` accumulator that is incremented/decremented only on legitimate `deposit`/`withdraw` calls, and use that value instead of `balanceOf(address(this))` in `_calLpSupply` for reward-rate math. Alternatively, add a permissioned `farm`/sweep function that lets the owner recover any staking-token balance in excess of the tracked `totalStaked`, so donated dust cannot permanently distort the emission math.

### Proof of Concept
1. Attacker picks a pool `P` in `MasterMagpie` whose staking token is not `vlmgp`/`mWomSV`.
2. Attacker calls `stakingToken.transfer(address(masterMagpie), X)` directly (bypassing `deposit`/`depositFor`), where `X` is arbitrary and can be dust.
3. On the next `updatePool(pid)` (or equivalent reward-accrual call triggered by any user's deposit/withdraw/harvest), `_calLpSupply` returns `balanceOf(address(this))`, which now includes `X`, permanently lowering `accMGPPerShare` increments relative to what legitimate depositors would have earned.
4. `X` remains stuck forever (no `UserInfo` entry references it and there is no owner-side path shown in-scope to remove it from the balance used by `_calLpSupply`), so the dilution is permanent for the pool's lifetime.

    function _calLpSupply(address _stakingToken) internal view returns (uint256) {
        if (_stakingToken == address(vlmgp)) {
            return IERC20(address(vlmgp)).totalSupply();
        }
        if (_stakingToken == address(mWomSV)) {
            return IERC20(address(mWomSV)).totalSupply();
        }
        return IERC20(_stakingToken).balanceOf(address(this));
    }
