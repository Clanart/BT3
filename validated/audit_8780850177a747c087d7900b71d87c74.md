### Title
Unbounded in-memory read of RPC request body via NewRelic/Datadog HTTP instrumentation bypasses `MaxRequestContentLength` - (File: networks/rpc/http_newrelic.go, networks/rpc/http_datadog.go)

### Summary
Kaia's JSON-RPC HTTP server enforces a global body-size cap (`common.MaxRequestContentLength`, default 512KiB) at the transport layer via `r.ContentLength` pre-check and `io.LimitReader` wrapping in `newHTTPServerConn` [1](#0-0) , and the same limit is enforced consistently for `validateRequest` [2](#0-1) , WebSocket (`SetReadLimit`) [3](#0-2) , fasthttp (`MaxRequestBodySize`) [4](#0-3) , and gRPC readers [5](#0-4) . However, when NewRelic (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`) or Datadog (`DD_TRACE_ENABLED`) APM instrumentation is enabled, the outer handler wraps the entire request pipeline and calls `getRPCRequests(r)` **before** the body ever reaches the size-limited codec.

### Finding Description
`getRPCRequests` reads the full HTTP body with an unbounded `io.ReadAll(r.Body)`, with no cap tied to `common.MaxRequestContentLength`: [6](#0-5) 

This function is invoked directly inside both instrumentation wrappers, which sit as the outermost handler in the chain built by `NewHTTPServer`: [7](#0-6) 

`newNewRelicHTTPHandler` calls `getRPCRequests(r)` before delegating to the inner `handler.ServeHTTP(dupW, r)`, which is where the actual `validateRequest`/`ContentLength` check and `io.LimitReader`-bounded codec live: [8](#0-7) 

The Datadog wrapper has the identical pattern — it calls `getRPCRequests(r)` unconditionally at the top of its handler, before any size check occurs: [9](#0-8) 

Because `io.ReadAll` has no limit and is called against the raw `r.Body` (not `io.LimitReader`-wrapped), and because Go's `http.Server` does not itself cap body size when the client uses chunked transfer-encoding (no `Content-Length` header, so `r.ContentLength == -1`, bypassing the header-based pre-check in `validateRequest` too), a single unauthenticated caller can send an arbitrarily large HTTP POST body to the public RPC endpoint. The entire payload is buffered into memory in `getRPCRequests` before any size validation takes place, directly mirroring the Rancher advisory's root cause: request bodies "fully loaded into memory during processing" without an enforced size limit.

### Impact Explanation
This is a memory-exhaustion Denial of Service vector reachable from a single, unauthenticated public-RPC HTTP request. The `MaxRequestContentLength` protection that Kaia otherwise carefully applies uniformly across HTTP/WS/fasthttp/gRPC transports (analogous to the size caps the advisory cites as *good* practice, e.g. Norman's `read_input.go`) is defeated whenever operators enable NewRelic or Datadog APM tracing — a common production observability configuration, not a privileged/operator-only attack path but a config state reachable by any external caller hitting the exposed RPC port. Repeated large-body requests can exhaust server memory and crash or hang the Kaia node process, taking down the public RPC endpoint (and, on a CN, the node availability generally), satisfying CWE-770 (Allocation of Resources Without Limits).

### Likelihood Explanation
High whenever APM tracing is enabled (a supported, documented feature — see env var checks in `newNewRelicApp`/`newDatadogTracer`). No authentication, special privileges, or valid JSON-RPC payload is required: attacker only needs to open a TCP connection to the public HTTP-RPC port and stream a large body (optionally with chunked encoding to avoid the `Content-Length` pre-check entirely). This matches the reachable-surface criteria (public-RPC caller) required by the validation rules.

### Recommendation
Wrap `r.Body` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or equivalently reuse `newHTTPServerConn`'s reader) before calling `io.ReadAll` in `getRPCRequests`, and enforce this cap independent of the `Content-Length` header (i.e., don't rely solely on `r.ContentLength` checks, since chunked requests have `r.ContentLength == -1`). Apply the same bound to any other body-consuming logic added ahead of `validateRequest`/`newHTTPServerConn` in the handler chain (both NewRelic and Datadog paths).

### Proof of Concept
1. Start a `kcn`/`ken` node with `NEWRELIC_APP_NAME` and `NEWRELIC_LICENSE` env vars set (or `DD_TRACE_ENABLED=true`) so `NewHTTPServer` installs the NewRelic/Datadog wrapper.
2. From an unauthenticated client, send an HTTP POST to the RPC endpoint with `Transfer-Encoding: chunked` and a very large streamed body (e.g., several GB of arbitrary bytes), omitting `Content-Length`.
3. `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` calls `getRPCRequests(r)`, which executes `io.ReadAll(r.Body)` with no size bound, buffering the entire multi-GB payload into memory before `validateRequest`'s `ContentLength` check (which is bypassed anyway since `r.ContentLength == -1` for chunked requests) or the `io.LimitReader`-wrapped codec is ever reached.
4. Repeating this from multiple connections exhausts node memory, causing process OOM/crash and denial of service to the public RPC interface.

```go
func newNewRelicHTTPHandler(nrApp *newrelic.Application, handler http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if err := recover(); err != nil {
				logger.ErrorWithStack("NewRelic http handler panic", "err", err)
			}
		}()

		reqMethod := ""

		// parse RPC requests
		reqs, isBatch, err := getRPCRequests(r)
		if err != nil || len(reqs) < 1 {
			// The error will be handled in `handler.ServeHTTP()` and printed with `printRPCErrorLog()`
			logger.Debug("failed to parse RPC request", "err", err, "len(reqs)", len(reqs))
		} else {
			reqMethod = reqs[0].Method
			if isBatch {
				reqMethod += "_batch"
			}
		}

		// new relic transaction name contains the first API method of the request
		txn := nrApp.StartTransaction(r.Method + " " + r.URL.String() + " " + reqMethod)
		defer txn.End()

		w = txn.SetWebResponse(w)
		txn.SetWebRequestHTTP(r)
		r = newrelic.RequestWithTransactionContext(r, txn)

		// duplicate writer
		dupW := &dupWriter{
			ResponseWriter: w,
			body:           bytes.NewBufferString(""),
		}

		// serve HTTP
		handler.ServeHTTP(dupW, r)
```

```go
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
```
