### Title
Harvest reward distribution can be permanently DoS'd via zero-value fee transfers to weird ERC20 tokens - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking._sendRewards` unconditionally attempts to transfer/queue a fee amount for every active `feeInfos` entry, even when the computed `feeTosend` is `0`. Unlike every other reward-distribution path in this codebase, this one lacks a `> 0` guard before the transfer, so if a fee tier's `value` is `0` (a legitimate, admin-configurable state) and the reward/bonus token is an ERC20 that reverts on zero-value transfers, every harvest touching that reward token permanently reverts.

### Finding Description
`_sendRewards` iterates `feeInfos` and for each active fee computes:
```solidity
uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
...
uint256 feeTosend = feeAmount;
...
if (!feeInfo.isAddress) {
    IERC20(rewardToken).safeApprove(feeInfo.to, 0);
    IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
    IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
} else {
    IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
    emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
}
``` [1](#0-0) 

Neither branch checks `feeTosend > 0` before calling `safeTransfer`/`queueNewRewards` (which itself calls `_provisionReward` → `safeTransferFrom` unconditionally, see `BaseRewardPool._provisionReward`) [2](#0-1) . This is inconsistent with every other reward path in the protocol, which all guard zero amounts before transferring, e.g.:
- `BaseRewardPool.getReward`: `if (reward > 0) { ... safeTransfer ... }` [3](#0-2) 
- `WombatStaking.vote` (bribe path): `if (protocolFee > 0) { safeTransfer... }` [4](#0-3) 
- `DelegateVoteRewardPool._manageRewards`: `if (fees > 0 && feeCollector != address(0)) { safeTransfer... }` [5](#0-4) 
- `mWOMSVBaseRewarder._sendReward`: `if (toSend > 0) { safeTransfer... }` [6](#0-5) 

Since `feeInfo.value` is an admin-settable percentage (`AddFee`/`SetFee`) and can legitimately be `0` while `isActive` remains `true`, and `assetToBonusRewards` / reward tokens can include arbitrary ERC20 bonus tokens configured per pool [7](#0-6) , any bonus/reward token that reverts on zero-value transfers (a well-known ERC20 weirdness, e.g. some LEND-style or deflationary tokens) combined with a zero-value fee tier will cause `_sendRewards` to revert every time it processes that token — halting harvest and reward accrual for that pool's stakers entirely.

### Impact Explanation
Because `_sendRewards` is the terminal step of the harvest flow that distributes real wombat/bribe rewards into the `BaseRewardPool` for stakers [8](#0-7) , an unconditional revert here freezes yield distribution for all stakers of the affected pool indefinitely (until governance removes/adjusts the offending fee entry). This is a freeze of unclaimed yield for an unbounded/24h+ duration, consistent with the accepted impact classes.

### Likelihood Explanation
This requires an admin-set fee value of `0` (a normal, allowed configuration state, not a malicious admin action — the same precondition as the original Aave Lens finding where treasury fee could simply be set to `0`) plus a reward/bonus token that reverts on zero-value transfer. Both conditions are plausible in normal operation since fee values and bonus reward tokens are freely configurable and Wombat bonus reward tokens are not guaranteed to be "safe" ERC20s.

### Recommendation
Guard all fee-forwarding transfers in `_sendRewards` with a `> 0` check before calling `queueNewRewards`/`safeTransfer`, mirroring the pattern already used elsewhere in the codebase:
```solidity
if (feeTosend > 0) {
    if (!feeInfo.isAddress) {
        ...
        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
    } else {
        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
    }
}
```

### Proof of Concept
1. Owner adds a fee entry via `addFee`/`setFee` with `value = 0`, `isActive = true` (legitimate zero-fee configuration).
2. A pool has a bonus reward token registered in `assetToBonusRewards` that reverts on zero-value `transfer`/`transferFrom`.
3. Any user calls the pool's harvest path, which eventually calls `_sendRewards(_lpToken, _rewardToken, _rewarder, _amount)` for that bonus token.
4. Inside the fee loop, `feeAmount = (originalRewardAmount * 0) / DENOMINATOR = 0`, so `feeTosend = 0`.
5. The code unconditionally executes `IERC20(rewardToken).safeTransfer(feeInfo.to, 0)` (or `queueNewRewards(0, rewardToken)` → `safeTransferFrom(..., 0)`), which reverts against a zero-value-transfer-reverting token.
6. Every subsequent harvest for that pool/token reverts, permanently freezing reward distribution until the fee configuration is changed by governance. [9](#0-8)

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }
```
