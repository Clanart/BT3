### Title
`Scanner::scan_block` reports coinbase outputs as spendable before maturity, enabling indefinite lock of recognized funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes a permissionless `notify()` that keeps resetting a vesting timer so rewards never unlock — a DoS where legitimately-owned funds are perpetually reported but not spendable. The Serai analog lives in `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs`: it scans `block.txdata` including `txdata[0]`, the coinbase transaction, and returns any outputs paying to a registered script as `ReceivedOutput`s. Coinbase outputs are bound by Bitcoin's 100-block maturity rule, so the scanner reports funds as received that the `SignableTransaction`/`TransactionMachine` pipeline will happily try to spend immediately — and any transaction spending them is consensus-invalid. An unprivileged miner can repeat this every block it mines, continuously injecting fresh immature outputs, mirroring the attacker's repeated timer resets.

### Finding Description
`scan_block` iterates over every transaction in the block without excluding the coinbase:

```rust
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
``` [1](#0-0) 

`scan_transaction` has no maturity concept: any output whose `script_pubkey` matches a registered script is returned as a `ReceivedOutput` carrying the spendable `offset` and `outpoint`. [2](#0-1) 

Downstream, `SignableTransaction::new` treats every supplied `ReceivedOutput` as a spendable input (`input_sat` sums them, `prevouts` commits to them), and `TransactionSignMachine::sign` produces BIP-340 key-spend signatures over `Prevouts::All` — none of which checks coinbase maturity. [3](#0-2) [4](#0-3) 

Notably, the library's own consumers already had to work around this: `Bitcoin::get_outputs` in the processor deliberately skips `block.txdata[1 ..]`'s index 0 with the comment "Skip the coinbase transaction which is burdened by maturity" — proving the misreporting is real and that callers must manually compensate for `scan_block`'s behavior. [5](#0-4) 

### Impact Explanation
Any caller that feeds `scan_block` results into `SignableTransaction::new` and signs the result produces a transaction that Bitcoin consensus rejects (BIP-30/COINBASE_MATURITY = 100 blocks). All other honest inputs bundled into the same transaction are blocked alongside the immature one, so the invalid coinbase output poisons the entire spend — analogous to how `lockedProfit` poisons `totalAssets` for all stakers. A miner who pays Serai's group key (or a registered offset script) in its coinbase can repeat this in every block it mines, and any miner on the network can do it permissionlessly; the polluted output remains immature for 100 blocks, and new ones keep arriving — the "keep resetting the timer" mechanic. Severity: Medium — funds reported received that are not spendable, with no secret leakage.

### Likelihood Explanation
Reachable by any Bitcoin miner: constructing a coinbase paying to Serai's P2TR script requires only knowledge of the (public) group-key-derived script and costs nothing beyond the mining reward the miner already controls. Unlike the audit's attacker who pays 1 wei, the miner actually sacrifices no extra funds — the coinbase output to Serai is a genuine deposit. The trigger condition is a caller using `scan_block` rather than skipping `txdata[0]`; the doc comment notes a "post-processing pass is needed" but the API still defaults to the unsafe behavior.

### Recommendation
- In `Scanner::scan_block` (`networks/bitcoin/src/wallet/mod.rs`), either skip `block.txdata[0]` entirely, or annotate `ReceivedOutput`s derived from the coinbase with an `immature`/`maturity_height` marker so callers cannot silently treat them as spendable.
- Alternatively, have `scan_block` take the block height and only return coinbase outputs once `height >= coinbase_height + 100`, matching the recommendation in the report to enforce the vesting period in-code rather than trusting callers to wait.
- Add a test asserting `scan_block` on a block whose coinbase pays the scanned key does not yield an unmarked spendable output.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
