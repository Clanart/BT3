### Title
Unbounded relayer-controlled message size lets an attacker self-mint disproportionate `ReputationAsset` rewards - (`modules/pallets/messaging-incentives/src/lib.rs`)

### Summary
`pallet-messaging-incentives` mints `ReputationAsset` tokens to the relayer who delivered an ISMP message, scaled linearly by the message's payload size (`bytes * MintPerByte`). The byte count comes directly from `PostRequest.body.len()` [1](#0-0) , a value fully controlled by whoever dispatches the original request. Because there is no cap on body size, no cap on the total minted amount, and no relationship between the size used for pricing and any real cost incurred by the protocol, an attacker who both dispatches a request (with an arbitrarily large body) and self-relays it to Hyperbridge can inflate their own `ReputationAsset` mint arbitrarily — the same "willingly increase a caller-controlled cost/size parameter to drain a protocol-side value pool" primitive as the original ShortHintArray/TAPP report, just applied to a reward-mint pool instead of a gas-refund pool.

### Finding Description
`on_executed` is the `FeeHandler` hook invoked after a batch of ISMP messages is successfully processed [2](#0-1) . For every `Message::Request` in the batch it:
1. Computes `bytes = sum(max(request.body.len(), 32))` across the requests in the message [1](#0-0) .
2. Computes `amount = MintPerByte * bytes` [3](#0-2) .
3. Recovers the relayer's account from the sr25519 signature on the message and mints `amount` of `ReputationAsset` directly to that account [4](#0-3) [5](#0-4) .

There is no upper bound on `bytes` (only a 32-byte floor), no relationship enforced between body size and any real relayer cost (gas, bandwidth, computation), and no check that the request actually carries useful application payload. `request.body` is set entirely by whoever calls `dispatch()`/`IDispatcher.dispatch` on the source chain — the same actor is free to also act as the delivering relayer and sign the resulting message. This mirrors the audited bug class exactly: the caller supplies a parameter (`shortHintArray` length there, `body.length` here) that directly and linearly drives a payout/cost from a protocol-controlled pool (`TAPP` there, `ReputationAsset` supply here), with no bound or sanity check on that parameter.

### Impact Explanation
An attacker can dispatch a POST request carrying an arbitrarily large, useless body (bounded only by the source chain's extrinsic/calldata size limits, which can still be tens of KB), relay it to Hyperbridge themselves, and collect a `ReputationAsset` mint proportional to that padding rather than to real relaying work performed. Since `MintPerByte` scales linearly with size, this allows self-dealing unauthorized minting/inflation of a protocol reward asset at will, diluting or draining the intended value of the reputation program and giving an unprivileged actor outsized, unearned rewards — a direct "unauthorized minting"/fund-manipulation outcome against protocol-controlled value, matching the required "stealing or loss of funds"/"logic attack" bounty categories.

### Likelihood Explanation
The only actors required are: (1) an address able to dispatch an ISMP POST request (permissionless on any Hyperbridge-connected chain), and (2) the ability to relay/deliver that same message and have `relayer_for` recover their own account from the signature — also permissionless, since Hyperbridge relaying is open. No admin, prover, or governance role is needed; the only prerequisite is that governance has set a non-zero `MintPerByte` via `set_mint_per_byte` [6](#0-5) , which is the pallet's normal operating mode. This makes the attack straightforward and repeatable for any account willing to pay the (comparatively small) source-chain calldata cost to pad request bodies.

### Recommendation
Cap the per-message/per-batch bytes eligible for minting (e.g., a governance-configured maximum bytes-per-request or per-block mint ceiling), and/or decouple the reward calculation from attacker-supplied `body.len()` — for example basing it on a fixed per-message reward, or requiring the body to correspond to an actually-consumed bandwidth/fee charge elsewhere in the protocol (e.g., cross-check against `pallet-bandwidth` consumption) rather than trusting raw payload length as a proxy for relayer effort.

### Proof of Concept
1. Governance sets `MintPerByte = R > 0` via `set_mint_per_byte`.
2. Attacker, controlling an account on any connected source chain, calls `dispatch()`/`IDispatcher.dispatch` with a `PostRequest.body` padded to the maximum allowed calldata/extrinsic size (e.g., tens of KB of zero bytes), targeting any destination module that will accept the request.
3. Attacker (or a colluding/self-operated relayer) delivers/relays this message to Hyperbridge and signs it, so `relayer_for` in `messaging-incentives::lib.rs` resolves the signer to the attacker's account [4](#0-3) .
4. On successful execution, `on_executed` computes `bytes = body.len()` and mints `R * bytes` of `ReputationAsset` to the attacker [7](#0-6) , far exceeding what a normal, minimally-sized message of equivalent relaying effort would earn.
5. Repeating this with maximally-padded bodies across many messages lets the attacker mint an outsized share of `ReputationAsset` relative to real relaying work, at the cost of only source-chain calldata fees.

	fn relayer_for(message: &Message) -> Option<T::AccountId> {
		let (signer, signed) = match message {
			Message::Request(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			Message::Response(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			_ => return None,
		};
		Signature::decode(&mut &signer[..])
			.ok()?
			.verify_and_get_sr25519_pubkey(&signed, None)
			.ok()
			.map(T::AccountId::from)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		_events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let rate = MintPerByte::<T>::get();
		if !rate.is_zero() {
			for mw in &messages {
				let bytes = Self::message_bytes(&mw.message);
				let bytes_balance: BalanceOf<T> = (bytes as u128).saturated_into();
				let amount = rate.saturating_mul(bytes_balance);
				if amount.is_zero() {
					continue;
				}
				if let Some(relayer) = Self::relayer_for(&mw.message) {
					match T::ReputationAsset::mint_into(&relayer, amount) {
						Ok(_) =>
							Self::deposit_event(Event::ReputationMinted { relayer, bytes, amount }),
						Err(err) => log::warn!(
							target: "messaging-incentives",
							"reputation mint failed for {bytes}b: {err:?}",
						),
					}
				}
			}
		}
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
