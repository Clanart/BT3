### Title
Kickoff-connector usage state is keyed only by `(round_idx, kickoff_connector_idx)` and is not scoped per operator - ([File: core/src/database/operator.rs])

### Summary
`used_kickoff_connectors` records whether a round's kickoff connector has been spent, but the primary key omits `operator_xonly_pk`. Since every operator independently iterates the same `round_idx`/`kickoff_connector_idx` space (`RoundIndex::iter_rounds(paramset.num_round_txs)` and the same kickoff-index range for every operator), usage records from one operator's round/kickoff-connector pair collide with another operator's identical pair, exactly mirroring the reported bug class of a mapping missing the discriminating index (there, `marketIndex`; here, `operator_xonly_pk`).

### Finding Description
`mark_kickoff_connector_as_used` inserts into `used_kickoff_connectors` keyed by `(round_idx, kickoff_connector_idx)` only, with `ON CONFLICT (round_idx, kickoff_connector_idx) DO NOTHING`: [1](#0-0) 

`round_idx` and `kickoff_connector_idx` are not globally unique identifiers - they are per-operator loop counters. Both `create_nofn_sighash_stream` and `create_operator_sighash_stream` iterate `RoundIndex::iter_rounds(paramset.num_round_txs)` and the same `utxo_idxs` set identically for every operator in the system: [2](#0-1) [3](#0-2) 

Because the table's key does not include `operator_xonly_pk`, two different operators reaching the same `(round_idx, kickoff_connector_idx)` pair share one row:
1. Whichever operator marks the connector "used" first wins the row (via `ON CONFLICT DO NOTHING`), silently discarding the second operator's `kickoff_txid` for that key.
2. `get_kickoff_connector_for_kickoff_txid` and `get_kickoff_txid_for_used_kickoff_connector` then return the *other* operator's `kickoff_txid`/round-connector mapping when queried for that pair: [4](#0-3) 
3. `get_unused_and_signed_kickoff_connector`, used to find a free connector for an operator to kick off a reimbursement, filters `deposit_signatures` by `deposit_id`/`operator_xonly_pk`, but excludes rows via `NOT EXISTS (... FROM used_kickoff_connectors ukc WHERE ukc.round_idx = ds.round_idx AND ukc.kickoff_connector_idx = ds.kickoff_idx)` — with no operator filter on the `used_kickoff_connectors` side: [5](#0-4) 

So an honest operator's free-connector search can be blocked by another (unrelated) operator's usage of the numerically identical `round_idx`/`kickoff_connector_idx` pair, and cross-operator writes to the same row corrupt the txid bookkeeping used to resolve kickoffs back to their real transaction.

### Impact Explanation
This breaks the binding "the kickoff connector marked used vs. the operator that actually spent it." In a multi-operator deployment the round/kickoff-index space is small and shared identically by every operator, so collisions are not a remote edge case. Consequences:
- An honest operator can have its available kickoff-connector slots exhausted by other operators' independent, unrelated activity, since `get_unused_and_signed_kickoff_connector` treats another operator's used slot as its own being used — potentially leaving the operator with no free connector to broadcast a kickoff for reimbursement (honest operator permanently unable to be reimbursed).
- `get_kickoff_txid_for_used_kickoff_connector` / `get_kickoff_connector_for_kickoff_txid` can return a `kickoff_txid` belonging to a different operator for the same `(round_idx, kickoff_connector_idx)` key, corrupting downstream bookkeeping that resolves which kickoff transaction corresponds to which round/connector.

### Likelihood Explanation
No special privilege is required to trigger this — it occurs purely from the normal, expected operation of multiple operators independently using their round/kickoff-connector state machines, since every operator iterates the identical `round_idx`/`kickoff_connector_idx` ranges (`RoundIndex::iter_rounds`, `utxo_idxs`). The larger the number of active operators, the more likely a collision.

### Recommendation
Add `operator_xonly_pk` (or an operator-scoped column) to the `used_kickoff_connectors` primary key and to all read/write queries (`mark_kickoff_connector_as_used`, `get_kickoff_connector_for_kickoff_txid`, `get_kickoff_txid_for_used_kickoff_connector`, and the `NOT EXISTS` join in `get_unused_and_signed_kickoff_connector`), so that connector-usage state is scoped per operator instead of colliding across operators sharing the same numeric round/connector indices.

### Proof of Concept
1. Operator A and Operator B both have deposit signatures for `round_idx = R`, `kickoff_idx = K` (guaranteed to exist since every operator uses the same round/kickoff-index ranges).
2. Operator A calls `mark_kickoff_connector_as_used(round_idx=R, kickoff_connector_idx=K, kickoff_txid=TX_A)` — row `(R, K, TX_A)` is inserted. [6](#0-5) 
3. Operator B later calls `mark_kickoff_connector_as_used(round_idx=R, kickoff_connector_idx=K, kickoff_txid=TX_B)` — due to `ON CONFLICT (round_idx, kickoff_connector_idx) DO NOTHING`, this is silently dropped; the stored `kickoff_txid` remains `TX_A`.
4. Any subsequent lookup via `get_kickoff_txid_for_used_kickoff_connector(round_idx=R, kickoff_connector_idx=K)` performed in Operator B's context returns `TX_A`, not `TX_B`. [7](#0-6) 
5. Separately, Operator B's `get_unused_and_signed_kickoff_connector` query treats `(R, K)` as already used (because the `NOT EXISTS` check against `used_kickoff_connectors` ignores which operator used it), even though Operator B never used that connector, incorrectly skipping it as a candidate slot. [8](#0-7)

    pub async fn get_unused_and_signed_kickoff_connector(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(RoundIndex, u32)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, i32)>(
            "WITH current_round AS (
                    SELECT round_idx
                    FROM current_round_index
                    WHERE id = 1
                )
                SELECT
                    ds.round_idx as round_idx,
                    ds.kickoff_idx as kickoff_connector_idx
                FROM deposit_signatures ds
                CROSS JOIN current_round cr
                WHERE ds.deposit_id = $1  -- Parameter for deposit_id
                    AND ds.operator_xonly_pk = $2
                    AND ds.round_idx >= cr.round_idx
                    AND NOT EXISTS (
                        SELECT 1
                        FROM used_kickoff_connectors ukc
                        WHERE ukc.round_idx = ds.round_idx
                        AND ukc.kickoff_connector_idx = ds.kickoff_idx
                    )
                ORDER BY ds.round_idx ASC
                LIMIT 1;",
        )
        .bind(i32::try_from(deposit_id).wrap_err("Failed to convert deposit id to i32")?)
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let result = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        match result {
            Some((round_idx, kickoff_connector_idx)) => Ok(Some((
                RoundIndex::from_index(
                    usize::try_from(round_idx).wrap_err("Failed to convert round idx to u32")?,
                ),
                u32::try_from(kickoff_connector_idx)
                    .wrap_err("Failed to convert kickoff connector idx to u32")?,
            ))),
            None => Ok(None),
        }
    }
