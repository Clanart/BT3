**Analysis:** `deleteMostRecentSSHCredential` does not perform any host comparison at all — loose, substring, or otherwise. It simply looks up an entry in the `mostRecentSSHCredentials` `Map` by exact `operationGUID` key and, if found, deletes the exact `store`/`key` pair that was previously stored for that same operation via `setMostRecentSSHCredential`. [1](#0-0) 

The `operationGUID` used as the map key is not a hostname — it's documented as "in practice ... always the trampoline token for the ongoing git operation" [2](#0-1) , and trampoline tokens are cryptographically random UUIDs generated per-operation via `crypto.randomUUID()`, tracked in a `Set`, and revoked after use [3](#0-2) .

The stored "key" for SSH key passphrases is a SHA-256 hash of the local SSH key file path, not a host or URL string [4](#0-3) . Since there is no substring, prefix, or partial string comparison of hosts/origins anywhere in this function or its call chain, an attacker cannot forge a matching `operationGUID` to trigger deletion (or retrieval) of a credential belonging to a different, legitimate operation — the lookup is an exact `Map.get()` against a random, non-guessable, single-use token. The premise of the question (loose host matching enabling credential leakage to an attacker host) does not apply to this code.

export async function deleteMostRecentSSHCredential(operationGUID: string) {
  const entry = mostRecentSSHCredentials.get(operationGUID)
  if (entry) {
    log.info(
      `SSH auth failed, deleting credential for ${entry.store}:${entry.key}`
    )

    await TokenStore.deleteItem(entry.store, entry.key)
  }
}

const trampolineTokens = new Set<string>()

function requestTrampolineToken() {
  const token = crypto.randomUUID()
  trampolineTokens.add(token)
  return token
}

function revokeTrampolineToken(token: string) {
  trampolineTokens.delete(token)
}

/** Checks if a given trampoline token is valid. */
export function isValidTrampolineToken(token: string) {
  return trampolineTokens.has(token)
}
