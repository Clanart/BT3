### Title
Gasless swap commission rate can be front-run by the GaslessSwapRouter owner to steal user funds despite `minAmountOut` check - ([File: contracts/bindings/kip247/GaslessSwapRouter.go])

### Summary
The `GaslessSwapRouter` contract (KIP-247 gasless module) charges a `commissionRate` that is applied at execution time inside `swapForGas`, not committed to by the user's signed transaction. The owner can call `updateCommissionRate` to raise the commission and front-run a pending `swapForGas` transaction, extracting more value from the swap output than the user expected, analogous to the Teller market-fee front-running bug where a fee percentage fetched at execution time (not locked at submission time) is used to split value between the actor and a privileged fee recipient.

### Finding Description
`GaslessSwapRouter` exposes an owner-controlled `updateCommissionRate(uint256)` function [1](#0-0) , and the `commissionRate` is read live within `swapForGas` (a `SwappedForGas` event even reports the `commission` value computed at execution time, alongside `finalUserAmount`) [2](#0-1) .

The user's gasless swap transaction only commits to `minAmountOut` (the total output floor covering `amountRepay` to the proposer plus margin) - it does not commit to a maximum commission or a minimum `finalUserAmount` after commission is deducted [3](#0-2) . The gasless module's own balance check (`checkBalanceForSwap`) only validates `minAmountOut >= amountRepay` and that `amountIn` is sufficient for the router's exchange rate; it never checks or bounds the commission rate applied by the router [4](#0-3) . Because `commissionRate` is a mutable owner-controlled state variable fetched at execution time (analogous to `marketRegistry.getMarketplaceFee(bid.marketplaceId)` fetched at `lenderAcceptBid` runtime in the Teller report), the router owner can submit `updateCommissionRate` immediately before the victim's `swapForGas` transaction is executed, in the same block, to increase the commission and capture a larger share of the swapped-out value, reducing `finalUserAmount` delivered to the user.

Unlike the Teller case, there is a partial mitigating factor: `minAmountOut` still enforces that `amountRepay` (the amount owed to the proposer for gas lending) is covered, so the transaction won't revert; but any output between `minAmountOut` and the true swap output beyond `amountRepay` is subject to commission-rate manipulation without any user-side floor on `finalUserAmount`.

### Impact Explanation
A malicious/rogue owner of the deployed `GaslessSwapRouter` (a system-registered gasless-swap contract used by every gasless user on the chain) can unilaterally and repeatedly raise the commission rate to capture most or nearly all of the delta between a user's swap output and their `minAmountOut` floor, redirecting funds intended for the end user to the router owner. This is a concrete unauthorized value-extraction / fee-abuse path reachable by any account that owns/administers the whitelisted `GaslessSwapRouter`, directly affecting every gasless-swap transaction sender on Kaia.

### Likelihood Explanation
Likelihood depends on the router owner being malicious or compromised, and on the owner's ability to front-run (submit `updateCommissionRate` in a preceding transaction/block before a pending `swapForGas`). Since the owner is a privileged/trusted role (akin to the "market owner" in the original Teller report) and gasless transactions are publicly visible in the pool before block inclusion, front-running is straightforward for the router owner, making this feasible whenever an untrusted or compromised owner controls the registered router.

### Recommendation
Do not fetch `commissionRate` freshly inside `swapForGas` without user consent. Instead, have the user commit to an acceptable commission (or a minimum `finalUserAmount`) at signing time, and revert if the actual commission exceeds what the user authorized — mirroring the `minAmountOut` pattern already used for output/repay amounts. Alternatively, enforce a rate-change delay (timelock) on `updateCommissionRate` so it cannot affect already-signed/pending transactions.

### Proof of Concept
1. Router owner observes a pending `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` transaction from a gasless user in the transaction pool (public before inclusion).
2. Owner submits `updateCommissionRate(newHigherRate)` with a higher gas price/priority so it executes first in the same block [5](#0-4) .
3. The pending `swapForGas` executes afterward using the now-inflated `commissionRate`; since only `minAmountOut >= amountRepay` is validated on-chain [6](#0-5) , the transaction still succeeds but the resulting `finalUserAmount` (as emitted in `SwappedForGas`) is reduced by the increased commission, transferring the difference to the router owner's claimable commission balance.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
