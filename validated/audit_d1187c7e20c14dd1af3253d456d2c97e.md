### Title
Unauthenticated OP_RETURN operator identity in `payout_tx` lets any unprivileged attacker redirect vault reimbursement to an arbitrary operator - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The `payout_tx`'s OP_RETURN output that names the "fronting" operator is not covered by the user's withdrawal signature (`TapSighashType::SinglePlusAnyoneCanPay`), and the verifier/operator pipeline (`update_finalized_payouts` → `get_first_unhandled_payout_by_operator_xonly_pk` → `PayoutCheckerTask::run_once` → `handle_finalized_payout`) trusts that OP_RETURN field as the sole proof of who fronted the withdrawal. An attacker who can broadcast a competing transaction that reuses input 0/output 0 of any in-flight `payout_tx` but rewrites the OP_RETURN and re-funds the payout with their own money can get an arbitrary registered operator credited and reimbursed from the vault for a payout that operator never made.

### Finding Description
Binding claimed by the protocol: `payout_payer_operator_xonly_pk` for withdrawal `i` (used to select who gets reimbursed) == the xonly public key of the operator whose own funds actually paid `output 0` of the mined payout transaction for withdrawal `i`.

Root cause: this binding is enforced by nothing more than an OP_RETURN byte string written by whoever builds the final `payout_tx`, and the *only* cryptographic signature present on the transaction — the user's — does not cover that OP_RETURN output.

- `create_payout_txhandler` builds the payout tx with input 0 = user's withdrawal UTXO (key-spend), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator_xonly_pk) — the operator field is plain, unsigned data. [1](#0-0) 
- The user's signature over input 0 is required to use `TapSighashType::SinglePlusAnyoneCanPay`, both enforced and documented: [2](#0-1) [3](#0-2) 
SIGHASH_SINGLE|ANYONECANPAY only commits to input 0 and output 0; it places **no constraint** on any other input or on output 1/2 (anchor, OP_RETURN).
- The additional funding input(s) that actually supply the payout amount are added via `fund_raw_transaction`/wallet-signed with standard sighash, so they are entirely separate from and unrelated to the OP_RETURN operator identity.
- When a payout tx confirms, the verifier extracts the operator identity purely from parsing whatever OP_RETURN happens to be in the mined transaction, with no signature check tying it to the funding party: [4](#0-3) 
- This is written straight into the DB as `payout_payer_operator_xonly_pk` and later consumed by `get_first_unhandled_payout_by_operator_xonly_pk`: [5](#0-4) 
- `PayoutCheckerTask::run_once`, running independently for each operator, picks up any withdrawal whose stored `payout_payer_operator_xonly_pk` equals its own signer key and immediately calls `handle_finalized_payout`, which allocates a kickoff connector and drives the reimbursement flow — with no re-verification that this operator actually broadcast/funded anything: [6](#0-5) [7](#0-6) 

Exploit flow: an unprivileged attacker observes an in-flight `payout_tx` (from operator A or their own self-initiated withdrawal) in the mempool. They construct a new transaction that reuses input 0 (the ANYONECANPAY-signed user witness) and keeps output 0 byte-for-byte identical (mandated by SIGHASH_SINGLE), but replaces the OP_RETURN in output 2 with victim operator B's xonly pubkey, and supplies their own funding input(s) (since the original operator's funding inputs were signed with a full sighash over the original outputs and cannot be reused once output 2 changes). They broadcast this with a higher fee to win the race. Because input 0's signature never covered output 2 or the extra inputs, this new transaction is fully valid and can be mined instead of A's. Once confirmed, the verifier's `update_finalized_payouts` records B — who never signed, broadcast, or funded anything — as the payer, and B's own `PayoutCheckerTask` later drives the kickoff/Reimburse flow that pays B out of the N-of-N vault.

Existing guards do not catch this: `is_kickoff_malicious` only checks that the OP_RETURN operator matches the kickoff's claimed operator — it never checks that operator actually funded the payout on-chain (there is no such check anywhere in the codebase, since none of the mentioned guard functions verify payer identity against the operator's wallet/funding inputs). [8](#0-7) 

### Impact Explanation
This breaks the "operator credited == operator who funded" binding and matches the Critical category "an operator reimbursed for a payout it never funded." The vault's `move-to-vault` UTXO still only pays out `bridge_amount` once (matching the withdrawal), but to the wrong operator: a legitimate, uninvolved operator B receives a full `bridge_amount` reimbursement to their own `reimburse_addr` for work they never performed, while the party that actually funded the user's payout (the attacker or operator A) gets nothing. This is repeatable for every withdrawal and against any registered operator whose xonly pubkey is public (all operator keys are public/discoverable). It also corrupts an operator's kickoff/round bookkeeping (consumes a kickoff connector, advances round state) for a payout it never issued.

### Likelihood Explanation
No privileged role, key share, or TLS access is required — only the ability to see a pending payout transaction (or initiate one's own withdrawal) and to broadcast a competing Bitcoin transaction with a higher fee, both explicitly within the unprivileged attacker's capabilities. The economic cost to the attacker is fronting the withdrawal's payout amount themselves (since SIGHASH_SINGLE|ANYONECANPAY does not let them reuse the original funding inputs), so this is not "free" for the attacker, but it is a real, self-financeable griefing/misdirection primitive against any specific operator, requiring only standard Bitcoin fee-bumping/mempool tactics and no protocol-level bypass.

### Recommendation
Bind the operator identity cryptographically to the payout, e.g. require the operator to sign a message committing to the OP_RETURN output (or require the OP_RETURN output to be covered by a SIGHASH_ALL/SIGHASH_SINGLE (non-ANYONECANPAY) signature that only the crediting operator can produce), and/or verify on the verifier side that the additional funding inputs of the mined payout tx belong to the operator named in the OP_RETURN before recording `payout_payer_operator_xonly_pk`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

            .await?

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {

If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;
