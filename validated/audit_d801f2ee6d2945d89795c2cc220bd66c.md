### Title
Missing validation of DKG encryption keys allows public recovery of a participant's secret share - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
Analogous to CVE-2023-3739 (insufficient validation of untrusted input enabling unintended execution/effects), PedPoP registers each participant's ECDH encryption key (`enc_key`) with no validation: `Decryption::register` inserts whatever group element the participant broadcast in their `EncryptionKeyMessage`, with no proof of possession, no identity rejection, and no binding to the participant beyond the authenticated-channel assumption. A malicious participant who broadcasts `enc_key = identity` causes every honest party to encrypt that participant's secret shares under the publicly-known ECDH secret `identity`, making the shares decryptable by anyone and leaking the participant's aggregated secret share.

### Finding Description
- `EncryptionKeyMessage::read` deserializes `enc_key` via `C::read_G` (canonical-point check only) and `Decryption::register` stores it unconditionally (`crypto/dkg/pedpop/src/encryption.rs:57-59`, `351-362`).
- `verify_r1` calls `self.encryption.register(l, msg)` for every participant's commitments message; only the Schnorr PoK over `commitments[0]` and the message count are checked — the encryption key is never checked (`crypto/dkg/pedpop/src/lib.rs:313-334`).
- During share generation, `encrypt` computes `ecdh(key, to)` where `to = enc_keys[participant]` (`encryption.rs:460-467`, `95-97`). If `to` is the identity point, the shared secret is the identity point for every sender — a constant, publicly computable value.
- `cipher` derives the ChaCha20 key solely from `context` (public) and the ECDH bytes, with a fixed IV (`encryption.rs:101-133`). Therefore a share ciphertext addressed to a participant who registered `enc_key = identity` is a keystream anyone can reproduce, and the plaintext `SecretShare` scalar is recovered.
- Since each honest participant's share-to-`j` is encrypted to `j`'s registered key, all `n` shares destined for `j` are publicly decryptable, revealing `j`'s full aggregated secret share `sum_i f_i(j)` (`lib.rs:358-379`).

### Impact Explanation
The DKG's confidentiality guarantee is that each participant's secret share is known only to them. An unprivileged protocol participant can register a degenerate encryption key, causing all shares routed to them to be encrypted under a public key — broadcasting one participant's threshold share to all observers. This is direct secret-key-material leakage from untrusted input that was never validated (no PoP on `enc_key`, no identity/low-order rejection).

### Likelihood Explanation
Any DKG participant can include an arbitrary `enc_key` (including the identity encoding, which passes `read_G`'s canonical check) in their own commitments message. The attack requires no collusion and only a single crafted broadcast message. Impact is bounded to the malicious participant's own incoming share (one of `t` shares needed), so it does not alone recover the group key — but it destroys per-share confidentiality and, combined with compromise of `t-1` other shares by any means, enables full key recovery.

### Recommendation
In `Decryption::register` / `verify_r1`, reject `enc_key` values that are the identity (and enforce a proof of possession of the discrete log of `enc_key`, e.g., a Schnorr signature over `context || participant` with public key `enc_key`, verified in the existing round-1 batch verifier). This binds each encryption key to a known discrete log and prevents degenerate-key encryption.

### Proof of Concept
```rust
// Attacker (participant j) runs KeyGenMachine::generate_coefficients as normal,
// then mutates the produced EncryptionKeyMessage before broadcast:
let mut msg = EncryptionKeyMessage::<C, Commitments<C>>::read(
    &mut honest_msg.serialize().as_ref(), params).unwrap();
// Overwrite the encryption key with the identity point (passes read_G canonical check)
// by rewriting the trailing point encoding:
let mut raw = msg.serialize();
let enc_len = <C::G as GroupEncoding>::Repr::default().as_ref().len();
let n = raw.len();
raw[n - enc_len ..].copy_from_slice(C::G::identity().to_bytes().as_ref());
// Broadcast `raw`. Every honest i then computes:
//   ecdh(k_ij, identity) = identity
//   cipher(context, identity) -> publicly derivable ChaCha20 keystream
// Any observer decrypts each EncryptedMessage<C, SecretShare> addressed to j,
// recovering f_i(j) for all i, hence j's secret share = sum_i f_i(j).
```

Rationale: the only gate on `enc_key` is `C::read_G` (`encryption.rs:58`), which accepts the canonical identity encoding; `register` (`encryption.rs:351-362`) and `verify_r1` (`lib.rs:313-334`) perform no semantic validation, so the identity key reaches `encrypt`/`ecdh` and produces a public shared secret.
