### Title
`Scanner::scan_block` reports immature coinbase rewards as spendable outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching coinbase outputs as `ReceivedOutput` values without tracking their maturity. [1](#0-0)  The Bitcoin processor correctly skips `txdata[0]`, confirming that coinbase outputs require special handling rather than being treated like ordinary deposits. [2](#0-1) 

### Finding Description
`ReceivedOutput` is defined as a spendable output containing the key offset, `TxOut`, and outpoint needed for spending. [3](#0-2)  `scan_transaction` accepts any output whose `script_pubkey` matches a registered scanner script and creates that spendable object. [4](#0-3)  `scan_block` passes `block.txdata[0]` through the same path, so a valid block whose coinbase pays the vault script produces a `ReceivedOutput` immediately. [5](#0-4)  `SignableTransaction::new` has no maturity metadata available and blindly converts each supplied `ReceivedOutput` into a transaction input. [6](#0-5) 

### Impact Explanation
An external miner can place the vault’s Taproot script in a valid coinbase output, cause the scanner to report it after the normal Bitcoin confirmation threshold, and receive accounting credit before the vault can legally spend the output. Bitcoin coinbase outputs remain unspendable until 100 confirmations, while the Bitcoin integration treats six confirmations as finalized. [7](#0-6)  If downstream code consumes the returned output, it can construct and threshold-sign a transaction that Bitcoin rejects as immature. [8](#0-7)  If the block is reorganized before coinbase maturity, the credited output disappears entirely rather than merely remaining delayed. [9](#0-8) 

### Likelihood Explanation
The attacker must control or influence the coinbase transaction of an accepted Bitcoin block, which requires mining capability but no Serai privilege, private key, validator access, or malformed input. [4](#0-3)  Once such a block exists, exploitation is deterministic because `scan_block` performs no coinbase or maturity check. [5](#0-4)  The in-repository processor avoids the issue by explicitly skipping the coinbase transaction, so the vulnerable path is the public `scan_block` API or any equivalent integration using it directly. [2](#0-1) 

### Recommendation
Change `Scanner::scan_block` to skip coinbase transactions by default, preferably by checking `tx.is_coinbase()` rather than relying on transaction position. [5](#0-4)  Alternatively, return a distinct immature-output type and extend `ReceivedOutput` with sufficient block-height metadata for callers to enforce coinbase maturity. [3](#0-2)  Add a regression test asserting that a block whose coinbase pays a registered script returns no ordinary spendable `ReceivedOutput`. [10](#0-9) 

### Proof of Concept
PoC against `networks/bitcoin/src/wallet/mod.rs`:

```rust
let scanner = Scanner::new(vault_key).unwrap();
let vault_script = p2tr_script_buf(vault_key).unwrap();

// Mine or receive a valid block whose coinbase pays `vault_script`.
assert!(block.txdata[0].is_coinbase());
assert_eq!(block.txdata[0].output[0].script_pubkey, vault_script);

// At Bitcoin::CONFIRMATIONS == 6, the scanner reports the coinbase output.
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].outpoint().txid, block.txdata[0].compute_txid());

// The result is accepted as a spendable input even though consensus rejects
// spending it until the coinbase reaches 100 confirmations.
let spend = SignableTransaction::new(
    vec![outputs[0].clone()],
    &[(payment_script, DUST)],
    None,
    None,
    fee_per_vbyte,
).unwrap();
assert_eq!(spend.transaction().input[0].previous_output, *outputs[0].outpoint());
```

The decisive issue is that `scan_block` iterates all transactions rather than starting after the coinbase. [5](#0-4)  The transaction builder then preserves the reported outpoint as a normal input without any maturity check. [6](#0-5)
