### Title
Hardcoded 10-second gasless bundle timeouts (`QueueTimeout`/`PendingTimeout`) are too short and cause proposer-funded lend transactions to be lost, exposing the block proposer to fee-lending losses - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `kaiax/gasless` module lends gas fees to users via a proposer-funded `LendTx` (`GetLendTxGenerator`) that is bundled with the user's `GaslessApproveTx`/`GaslessSwapTx` and later repaid by the user inside the swap (`repayAmount`/`lendAmount`). Promotion of these bundle transactions from `queue`→`pending` and eventual inclusion is gated by hardcoded, very short timers: `QueueTimeout = 10 * time.Second`, `PendingTimeout = 10 * time.Second`, `KnownTxTimeout = 30 * time.Second` [1](#0-0) . This mirrors the analog bug class in the report: a hardcoded, too-short time window for reacting to/confirming a state (there: liquidation grace period; here: gasless bundle promotion/inclusion window) that becomes unsafe during network congestion.

### Finding Description
`PreAddTx` tracks bundle transactions in `knownTxs` with a `TxStatusQueue`/`TxStatusPending` state and timestamps (`addedTime`, `promotedTime`) [2](#0-1) . The 10-second `QueueTimeout`/`PendingTimeout` constants gate re-submission and pool bookkeeping of these bundle transactions [1](#0-0) . A gasless swap can only be promoted/executed together with its preceding approve tx per KIP-247 ready-check logic (`isReady`/`isApproveTxReady`/`isSwapTxReady`) [3](#0-2) , and the block-building logic in `ExtractTxBundles` prepends a proposer-signed `LendTxGenerator` ahead of the approve/swap pair, meaning the proposer's KAIA is committed to fund the user's gas as soon as the bundle is built [4](#0-3) . The lend amount equals the approve/swap tx fees, and is repaid by the user's swap only when that specific bundle executes in the same block [5](#0-4) .

Because `QueueTimeout`/`PendingTimeout` are hardcoded at 10 seconds (with no configuration flag, unlike other kaiax modules whose timing parameters are configurable, e.g. `auction.ed-offset` bounded 0–1s via CLI [6](#0-5) ), during periods of high network congestion or block-time variance a legitimately-submitted gasless approve/swap pair can sit in the pool past these windows before the swap's readiness conditions are satisfied and the bundle is built, causing the module to treat the bundle transaction as stale/re-submittable or evict it (per `ErrUnableToAddKnownBundleTx`/timeout eviction logic gated by `elapsedPromotedOrAddedTime() < KnownTxTimeout`) [2](#0-1) .

### Impact Explanation
If a `LendTx` is generated and included in a block (committing proposer funds) but the corresponding `GaslessApproveTx`/`GaslessSwapTx` bundle subsequently gets dropped, reorged, or fails to re-promote within the short 10s windows during congestion (e.g. because sender nonce state changed or the bundle conflicts with a competing bundle after a reorg per `PreReset`/`PostReset` in the shared tx pool), the proposer's lent KAIA is not repaid by the expected swap transaction, resulting in unrecovered value for the block proposer — an unauthorized value-transfer/loss analogous to the borrower losing the 5% incentive in the original report due to an unrealistically short reaction window. This is a Medium-severity fee-delegation/gasless-settlement risk reachable purely by a normal user submitting gasless approve/swap transactions during high network load; no privileged or malicious-node access is required.

### Likelihood Explanation
Likelihood is tied directly to network congestion/high transaction volume — the same condition flagged in the original report as amplifying the risk of short hardcoded windows. Since `QueueTimeout`/`PendingTimeout` are fixed Go constants (not CLI-configurable), operators cannot tune them to network conditions the way `auction.ed-offset` is tunable, making this more likely to manifest during congestion spikes, chain reorgs, or degraded block production.

### Recommendation
Make `QueueTimeout`, `PendingTimeout`, and `KnownTxTimeout` configurable (similar to `auction.ed-offset`) with a floor recommended by the KIP-247 designers, or dynamically scale them based on recent block time volatility. Additionally, tie proposer `LendTx` inclusion strictly to atomic bundle execution (already partially enforced via bundle conflict checks in `ExtractTxBundles`) and ensure the pool's eviction/promotion logic cannot separate a `LendTx` from its unrepaid approve/swap pair across the timeout boundary.

### Proof of Concept
Concrete exploitation requires reproducing sustained high network congestion (queue/pending backlog >10s) while gasless bundles are pending — this depends on runtime network conditions not verifiable purely from static code, so the exact loss magnitude cannot be demonstrated without a live/simulated congested network. The root-cause code paths supporting the finding (hardcoded `QueueTimeout`/`PendingTimeout`/`KnownTxTimeout`, lend/repay accounting, and bundle-building order) are cited above.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

// Check promotion condition.
func (g *GaslessModule) isReady(txs map[uint64]*types.Transaction, i uint64, ready types.Transactions) bool {
	tx := txs[i]

	if g.IsApproveTx(tx) && i < uint64(math.MaxUint64) {
		return g.isApproveTxReady(tx, txs[i+1])
	}

	if g.IsSwapTx(tx) {
		var prevTx *types.Transaction
		if len(ready) > 0 {
			prevTx = ready[len(ready)-1]
		}
		return g.isSwapTxReady(tx, prevTx)
	}

	return false
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
