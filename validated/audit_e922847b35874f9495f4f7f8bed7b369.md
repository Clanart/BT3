### Title
Overpaid miner fee when a `ReceivedOutput` understates the real on-chain value - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` computes payments, change, and the implied fee entirely from the **claimed** `TxOut` values carried inside each `ReceivedOutput`, not from the actual values of the UTXOs being spent. `ReceivedOutput::read` deserializes both the `TxOut` and `OutPoint` from untrusted bytes with no consistency check against the chain. If the claimed input value is lower than the real UTXO value, the difference is neither sent to a payment nor to change: Bitcoin's consensus rules make it part of the transaction fee, permanently donating it to miners. This is the same bug class as H-17: accounting (what is paid out) is derived from a nominal/cached quantity (`input_sat` from serialized bytes) rather than the actual collateral available (the true UTXO value), so the residual claimant (the change output / the protocol's own funds) absorbs the loss.

### Finding Description
`ReceivedOutput::read` accepts an attacker-controlled `Scalar` offset, `TxOut`, and `OutPoint` with no validation that the `TxOut` matches the real on-chain output referenced by the `OutPoint` [1](#0-0) .

In `SignableTransaction::new`, `input_sat` is the sum of these claimed values, and payments plus change are allocated only up to that claimed sum: [2](#0-1) [3](#0-2) 

The change output is `input_sat - payment_sat - fee_with_change`. Consensus, however, computes the fee as `sum(real input values) - sum(outputs)`. `fee()` itself already exposes the discrepancy silently: it subtracts output values from the *claimed* prevout values [4](#0-3) , so `fee()` reports `needed_fee` even when the real fee is higher.

The mirrored case (claimed value *higher* than real) only produces an invalid transaction — but understated values produce a fully valid, signable, broadcastable transaction whose excess becomes an unintentional miner fee. In the processor flow, `Output`s are wrapped `ReceivedOutput`s that pass through `Output::read`-style serialization and `BSignableTransaction::new` in `make_signable_transaction` without re-fetching the on-chain value [5](#0-4) .

### Impact Explanation
Any gap between the real UTXO value and the claimed `TxOut.value` is burned as a miner fee. Like the Lend finding, the nominal figure (claimed input sum / exchange rate) is used to allocate payouts, and the shortfall is socialized onto the residual claim — here the multisig's own change/fee budget rather than the last redeemer. This is a direct, unrecoverable loss of funds proportional to the understatement; it is not bounded by dust or the declared fee rate.

### Likelihood Explanation
Exploitation requires an untrusted `ReceivedOutput` (or bytes parsed by `ReceivedOutput::read`) whose `OutPoint` references a real output but whose `TxOut.value` is smaller than the real one to reach `SignableTransaction::new`. The library provides `ReceivedOutput::read` as a public deserialization entry point for exactly such untrusted bytes, and `SignableTransaction::new` performs no on-chain or `Prevouts`-level cross-check — `Prevouts::All` in the sighash commits to the *claimed* `TxOut`s, so the signature is valid and the overpaid fee is consensus-legal. Severity is bounded by how the integrator sources outputs; if outputs come only from `Scanner::scan_transaction` over verified blocks the values are accurate, but the API permits, and the serialization format round-trips, arbitrary values [6](#0-5) .

### Recommendation
When constructing the `SignableTransaction`, verify each `ReceivedOutput`'s claimed `TxOut` against the actual prevout (e.g., have callers supply verified prevouts, or document/enforce at the `Prevouts` layer that claimed values must equal chain values). Alternatively, after computing `fee()`, compare it against `needed_fee` and reject when `fee() > needed_fee` plus a tolerance, so understated inputs produce an error instead of a silent donation to miners.

### Proof of Concept
1. Create a real 100,000-sat P2TR UTXO paying to the multisig key.
2. Feed `ReceivedOutput::read` bytes encoding that `OutPoint` but a `TxOut` with `value = 60_000`.
3. Call `SignableTransaction::new(vec![crafted], &[(addr, 50_000)], Some(change), None, fee_rate)`. It succeeds: `input_sat = 60_000` covers `50_000 + needed_fee`, and change ≈ `60_000 - 50_000 - needed_fee`.
4. Sign and broadcast. Consensus computes the fee as `100_000 - (50_000 + change)` ≈ `40_000 + needed_fee` sats — the ~40,000-sat discrepancy is paid to miners while `needed_fee()`/`fee()` report only the intended rate.
