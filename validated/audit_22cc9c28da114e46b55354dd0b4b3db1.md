### Title
Unbounded, Domain-Unseparated Signature Replay in `addr` Precompile `associate()` Enables Forced Address Association and Fund Migration Without Owner Consent - (File: precompiles/addr/addr.go)

### Summary
The `addr` precompile's `associate` method recovers a signer's public key from a raw `(v, r, s)` ECDSA signature over `keccak256(customMessage)`, where `customMessage` is an arbitrary attacker-supplied string and the signature has no purpose-binding, domain separator, chain ID, or nonce. [1](#0-0)  This mirrors the openpgp `Message Signature Bypass` bug class: a signature is accepted for verification without confirming it was produced for the specific purpose being checked, allowing any previously observed signature (over a publicly-known preimage) to be replayed into a security-sensitive action it was never intended for.

### Finding Description
`associate()` takes four caller-supplied strings — `v`, `r`, `s`, `customMessage` — decodes them, and calls `helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)` to `ecrecover` an address/pubkey pair purely from the hash of `customMessage`: [2](#0-1) 

There is no EIP-191 personal-message prefix, no chain ID binding, no nonce, and no "this signature is for Sei association" tag embedded in what gets hashed and verified — unlike the EVM ante-handler path, which always hashes a full, protocol-specific Ethereum transaction via a proper `ethtypes.Signer` before recovering an address. [3](#0-2)  `RecoverPubkey`/`GetAddresses` just do raw ECDSA recovery over whatever hash is handed in, with no context validation. [4](#0-3) 

Because `customMessage` and the signature components are all attacker-controlled inputs to a public, unpermissioned precompile call, anyone who can obtain **any** ECDSA `(v, r, s)` signature from a victim key over a preimage whose bytes are knowable (e.g., a `personal_sign` message the victim signed for an unrelated dApp, a signed off-chain order, a raw message signed for any other protocol that doesn't itself add a domain separator) can submit that exact `(v, r, s, message)` tuple to `associate()`. The precompile will recover the victim's EVM/Sei address pair and force an association the victim never consented to for this specific purpose, since no check exists that the message was ever intended to authorize a Sei address association.

Once recovery succeeds, `associateAddresses` calls `AssociateAddresses`, which unconditionally migrates the cast address's spendable balance and wei balance to the newly associated Sei address and removes the cast account: [5](#0-4)  This means the attacker doesn't just create an unwanted association — they can trigger an automatic, one-time fund migration from the victim's default cast address to their now-associated address, which is irreversible (`AssociateAddresses` refuses to run again once `GetEVMAddress` returns found, per `associateAddresses`'s existing-association guard). [6](#0-5) 

### Impact Explanation
This qualifies as unauthorized state change and fund manipulation reachable directly from a public, unprivileged EVM precompile call (the `addr` precompile at `0x0000000000000000000000000000000000001004`), matching the "unauthorized transfer via precompile" and "permanent freezing/loss of funds" impact classes. A victim who has ever produced a plain ECDSA signature over a publicly-reconstructable message (which is extremely common: any `personal_sign`, order signature, or unrelated protocol signature not using a domain-separated scheme) can have their addresses force-associated and their cast-address balance swept without ever calling `associate()` themselves or intending this action.

### Likelihood Explanation
Likelihood is high for any victim who has signed messages with their key outside of Sei's own transaction format — a routine occurrence for active EVM users (dApp logins, off-chain orders, `permit`-style signatures, etc.). The attacker needs no special privileges: `associate` is a plain, non-payable public method callable by any EVM transaction sender, and once a compatible signature/message pair is observed (e.g., leaked in a public blockchain log, a dApp backend, or an off-chain marketplace), calling `associate()` requires only standard calldata construction.

### Recommendation
Bind the signed message to a fixed, unambiguous purpose and context before hashing, e.g., require `customMessage` to start with (or the precompile to internally construct) a domain-separated prefix such as `"Sei Association:" || chainID || callerSeiAddress || nonce`, so a signature can only be valid for this specific association action and cannot be replayed from any other signing context. Additionally, consider requiring the caller to prove intent to associate on behalf of themselves specifically (e.g., the tx sender must equal the recovered EVM address, or the message must embed a value only the current caller could set), preventing third-party front-running of any previously observed signature.

### Proof of Concept
1. Victim signs an arbitrary message `M` for an unrelated purpose with their secp256k1 key (e.g., a `personal_sign` request from some dApp, or a raw-hash signature for an off-chain protocol) — producing `(v, r, s)` over `keccak256(M)` (or over `M` itself if a scheme without a message prefix is used, matching this precompile's raw hashing).
2. Attacker observes `(v, r, s)` and reconstructs the exact byte sequence `M` (often public — e.g., posted in an order book, mempool, or dApp UI).
3. Attacker calls the `addr` precompile's `associate(v, r, s, M)` function directly via a public EVM transaction, with `M` passed as `customMessage`.
4. `crypto.Keccak256Hash([]byte(customMessage))` reproduces the exact hash the victim originally signed, so `helpers.GetAddresses` successfully recovers the victim's `evmAddr`/`seiAddr`/`pubkey`. [7](#0-6) 
5. `associateAddresses` proceeds (since no prior association exists) and calls `AssociateAddresses`, which sweeps the cast address's `usei`/wei balance into the newly-associated Sei address and removes the cast account. [5](#0-4) 
6. The victim's addresses are now associated and their cast-address funds moved, without the victim ever intending to call `associate()`.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

// first half of go-ethereum/core/types/transaction_signing.go:recoverPlain
func RecoverPubkey(sighash common.Hash, R, S, Vb *big.Int, homestead bool) ([]byte, error) {
	if Vb.BitLen() > 8 || Vb.Uint64() < 27 {
		return []byte{}, ethtypes.ErrInvalidSig
	}
	V := byte(Vb.Uint64() - 27) //nolint:gosec // the bit-length and lower-bound checks make the subtraction fit in one byte.
	if !crypto.ValidateSignatureValues(V, R, S, homestead) {
		return []byte{}, ethtypes.ErrInvalidSig
	}
	// encode the signature in uncompressed format
	r, s := R.Bytes(), S.Bytes()
	sig := make([]byte, crypto.SignatureLength)
	copy(sig[32-len(r):32], r)
	copy(sig[64-len(s):64], s)
	sig[64] = V

	// recover the public key from the signature
	return crypto.Ecrecover(sighash[:], sig)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
