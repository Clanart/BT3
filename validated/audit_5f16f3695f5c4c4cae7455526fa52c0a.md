### Title
Out-of-bounds atom-length-prefix read in `is_atom_canonical`/`is_clvm_canonical` reachable from unvalidated spend-bundle bytes - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical` and `is_clvm_canonical` in [1](#0-0)  parse a raw CLVM serialization buffer byte-by-byte to decide whether a spend bundle's encoding is "canonical" (used to reject non-canonical/back-reference serializations before/while admitting a transaction to the mempool). Like the NTPsec `ctl_getitem` bug (a length/size value taken from attacker-controlled input is used to index into a buffer without verifying it stays within bounds), this code reads a variable-length size prefix out of `clvm_buffer` and advances `offset` for up to 5 additional bytes without ever checking `offset < len(clvm_buffer)`.

### Finding Description
`is_atom_canonical` decodes the top bits of the atom's leading byte to determine `prefix_len` (0–5 extra bytes) and then loops: [2](#0-1) 
For each iteration it does `clvm_buffer[offset]` after incrementing `offset`, with no bound check against `len(clvm_buffer)`. The caller, `is_clvm_canonical`, walks the whole buffer token-by-token and also indexes `clvm_buffer[offset]` at the top of its loop without checking `offset < len(clvm_buffer)`: [3](#0-2) 
Because a spend bundle's serialized CLVM bytes are attacker-controlled (submitted directly by any unprivileged sender through the mempool), a malformed/truncated buffer whose final atom declares a long length-prefix but is cut short before all prefix bytes are present will drive `offset` past the end of `clvm_buffer`. In Python this triggers an `IndexError` rather than classic memory corruption, but it is the direct structural analog of the CVE: a size/length field taken from untrusted input is used to advance a read cursor without validating it against the actual buffer length.

### Impact Explanation
If this uncaught `IndexError` is not handled by whatever call site invokes `is_clvm_canonical` during transaction validation/mempool admission, it would propagate as an unexpected exception in the transaction-processing path, which matches the "spend-triggered transaction-processing halt" impact category explicitly accepted for this analog exercise. I was not able to locate and confirm the exact call site within `mempool_manager.py` that invokes `is_clvm_canonical` (only test references were found in `chia/_tests/core/mempool/test_mempool_manager.py`) before running out of tool iterations, so I cannot confirm whether the call is wrapped in a try/except that safely converts this into a rejection rather than crashing/halting the node's processing loop. This is a material gap that should be verified before treating this as a confirmed, exploitable Critical/High finding.

### Likelihood Explanation
Likelihood is high in the sense that constructing a byte buffer with a truncated multi-byte atom-length prefix is trivial and fully within an unprivileged spend-bundle submitter's control; no cryptographic material or special coin/puzzle state is required. However, since I could not verify whether the exception is caught at the call site, I cannot confirm the practical exploitability/impact with certainty.

### Recommendation
- Add explicit bounds checks in `is_atom_canonical` (`chia/full_node/mempool_manager.py:177-183`) before each `clvm_buffer[offset]` access, raising a well-defined validation error (e.g. returning "not canonical"/rejecting the bundle) instead of letting an `IndexError` propagate.
- Add the same bound check in `is_clvm_canonical`'s main loop (`chia/full_node/mempool_manager.py:199`) before indexing `clvm_buffer[offset]`.
- Verify (and if necessary add) that all call sites of `is_clvm_canonical` used during spend-bundle/mempool admission catch and convert any such exception into a normal `INVALID_SPEND_BUNDLE`-style rejection instead of allowing it to bubble up.

### Proof of Concept

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
