Based on my investigation, I found a genuine analog to the InsuranceFund `syncDeps()` bug class in the `kaiax/gasless` module.

### Title
Gasless module caches `swapRouter`/`allowedTokens` per-block, allowing GaslessSwapRouter registry changes to desynchronize bundle admission from settlement, causing lender (CN) fund loss - (File: kaiax/gasless/impl/getter.go, kaiax/gasless/impl/execution.go)

### Summary
The Kaia gasless flow lends KAIA to a swap sender via a `LendTx` (from the CN's own key) with the expectation that the sender's swap will repay exactly `lendAmount()` back through the currently-registered `GaslessSwapRouter` (`GSR`) contract. The address of that trusted router (`g.swapRouter`) is cached in memory and only refreshed once per block, in `PostInsertBlock` [1](#0-0) , via `updateAddresses()` which re-reads the router/token allow-list from the `Registry`/`MultiCall` contract [2](#0-1) . This is structurally the same pattern as `InsuranceFund.syncDeps()`: a privileged party (Registry owner / governance) can register a new `GaslessSwapRouter` address, and the value used to validate/build a lending transaction (`g.swapRouter`, read at admission time) can be stale relative to the value in effect when the swap is actually executed on-chain.

### Finding Description
`IsApproveTx`/`IsSwapTx`/`VerifyExecutable` gate admission solely on the in-memory cached `g.swapRouter` matching `tx.To()`/`spender` [3](#0-2) . The lender's `LendTx` amount and the expected `AmountRepay` are computed purely from the transaction fields (`swapTx.Fee()`, `swapTx.GasPrice()`) with no requirement that the router contract used for repayment is unchanged at inclusion time [4](#0-3) . The `LendTx` is generated and signed by the CN/proposer's key, sending `lendAmount()` KAIA directly to the sender before the swap executes [5](#0-4) .

Because `g.swapRouter` is refreshed only in `PostInsertBlock` (i.e., once per block after insertion) [1](#0-0) , there is a window—between a Registry owner calling `register(GaslessSwapRouterName, newAddr, activation)` and the next `PostInsertBlock` refresh—during which the module continues to treat an old (possibly now-unregistered, drained, or reconfigured) router address as trusted for bundling `[LendTx, ApproveTx, SwapTx]`. The project's own test explicitly demonstrates that `g.swapRouter` changes to a new address only after the registering transaction is committed and processed through `PostInsertBlock` (see the "update gsr address" test case) [6](#0-5) , confirming the address is a mutable, governance-controlled value cached with block-granularity latency—exactly the "changeable dependency address" hazard flagged in the original report.

### Impact Explanation
If the registered `GaslessSwapRouter` is changed (e.g., migrated to `GSRv2`, deprecated, or its allow-listed tokens rotated) while the node's cached `g.swapRouter`/`allowedTokens` are stale, the module will continue to build and bundle `LendTx + ApproveTx/SwapTx` sets against the outdated router. The CN advances real KAIA via `LendTx` before the swap runs; if the swap then executes against a router that no longer performs the expected repayment logic (e.g., it was deprecated, its liquidity/allowance state changed, or it's simply not the router the sender actually intended), the swap may still pass local pool checks (`checkBalanceForSwap`) yet fail to genuinely repay the lender, or repay an amount inconsistent with the real on-chain router state used to compute `GetAmountIn` at validation vs. execution time. This results in unauthorized value movement / fund loss for the CN lender, analogous to Alice's fund loss in the original `InsuranceFund` report — the "vusd" analog here is `g.swapRouter`, and "Alice's deposit" analog is the CN's advanced KAIA via `LendTx`.

### Likelihood Explanation
This requires the Registry owner (a governance-authorized on-chain actor, reachable by any account with owner rights on the `Registry` contract, not a network-level attacker) to register a new `GaslessSwapRouter` address — a normal, expected operational action (e.g., router upgrade) rather than an attack requiring privilege escalation. Any unprivileged sender can then race the address-change block with a crafted approve/swap bundle that gets validated against the stale cached address in the mempool/tx-pool admission path (`GetCheckBalance`, `IsApproveTx`, `IsSwapTx`) before `PostInsertBlock` refreshes `g.swapRouter`. Because gasless admission and lending both happen inside the txpool/bundling pipeline prior to block finalization, this is reachable purely from transaction submission timing, matching the "single submitted transaction/bundle" reachability required by the scan rules.

### Recommendation
Re-validate the router/token addresses against the *current* state (not the block-granularity cache) at bundle execution/settlement time, or bind the `LendTxGenerator`/repayment check to the specific router address snapshot used for admission and abort/refund if it no longer matches the currently active `Registry` record at execution. Alternatively, apply the same defensive pattern recommended for `syncDeps()`: verify that CN's advanced balance is fully recovered (`AmountRepay` actually received from the router in effect at execution) before finalizing the bundle, rather than trusting a value cached prior to block insertion.

### Proof of Concept
1. Registry owner calls `Registry.register("GaslessSwapRouter", GSR_v2, activationBlock)`, effective immediately/soon, analogous to `syncDeps()` changing `vusd`.
2. Before the node's `PostInsertBlock` → `updateAddresses()` runs for the block containing that registration, the node's `g.swapRouter` still equals the old `GSR_v1` address [7](#0-6) .
3. A user submits `[ApproveTx(spender=GSR_v1), SwapTx(router=GSR_v1)]`; `IsApproveTx`/`IsSwapTx` pass because they compare against the stale cached `g.swapRouter` [3](#0-2) .
4. `GetLendTxGenerator` signs and includes a `LendTx` sending real KAIA from the CN's key to the sender [5](#0-4) .
5. The swap executes against `GSR_v1`, which — since it was just deprecated/replaced by governance — may no longer hold the expected liquidity/config, causing the repayment to the lender to fail or be incorrect, resulting in a net loss of the lent KAIA to the CN.

Note: I could not fully trace the on-chain `kip247`/`GaslessSwapRouter` Solidity contract's repayment enforcement logic (e.g., whether it independently reverts on stale `AmountRepay` mismatches) within the available index; a Devin session with full repo access would be needed to confirm whether on-chain contract-side checks fully mitigate this timing gap.

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1
		g.allowedTokens[args.Token] // S3
}

func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
