## Analog Identified [1](#0-0) 

### Title
Automatic remote-URL rewrite trusts an unvalidated `clone_url` field from the GitHub API, enabling silent push/fetch redirection (repo-jacking) - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The reported bug class is "trust an external data source's field without validating it still refers to the same, current, legitimate entity." In `FeeTokenRegistry` this was `latestRoundData()`'s price being consumed without checking `updatedAt`/`roundId`. The Desktop analog is `updateRemoteUrl()`, which consumes the `clone_url` field of an `IAPIRepository` object returned by the GitHub API and silently rewrites the local `origin` remote to that value, using only a string-equality check against the *previously cached* URL — never verifying that the underlying repository identity (its stable numeric id) is unchanged.

### Finding Description
`updateRemoteUrl` [2](#0-1)  is invoked from repository refresh flows in `app-store.ts` whenever the GitHub API returns updated repository metadata (`IAPIRepository`/`IAPIFullRepository`, produced by `Api.fetchRepository`/`fetchRepositoryCloneInfo` via `parsedResponse`, which itself performs no shape/identity validation of the JSON body [3](#0-2) ).

The function's only guards are:
- `protocolsMatch` — the URL scheme (https/ssh) hasn't changed.
- `remoteUrlUnchanged` — the *current* remote URL still matches the previously cached `gitHubRepository.cloneURL` (i.e., the user hasn't manually edited it).
- `!urlsMatch` — the new `clone_url` differs from the current remote.

If all three hold, it calls `gitStore.setRemoteURL(...)` to silently rewrite `origin` to the new URL [4](#0-3) . Nowhere is the repository's stable identity (the GitHub API's numeric `id`) checked before accepting the new URL as authoritative — the code trusts that "same string previously, different string now" always means "same repo, legitimately renamed," which is exactly the missing-freshness/authenticity check pattern from the oracle report (no `roundId`/`updatedAt` equivalent check on the API object).

### Impact Explanation
This enables classic "repo-jacking": if a repository is deleted, transferred, or its owner account renamed and the old `owner/name` slug becomes claimable, an attacker can register that slug and stand up a repository whose API-reported `clone_url` now differs from what Desktop has cached for the user's local clone. Desktop's background refresh will then silently repoint the user's `origin` remote to the attacker's repository, with no confirmation dialog. Subsequent `git push` operations from the victim can send private commits/history to attacker-controlled infrastructure, and subsequent `git fetch`/`pull` will merge attacker-supplied history into the user's working repository without warning — matching the task's valid-impact category of "silent corruption of what the user commits or pushes" driven purely by an attacker-controlled GitHub API object.

### Likelihood Explanation
Medium. It requires no local access, no admin rights, and no credential theft — only that the attacker gain control of a namespace previously used by a repository the victim has cloned (a well-documented, real-world technique for org/user renames and repository transfers). It is fully automatic once the refresh runs; the user need not click anything.

### Recommendation
Do not rely solely on URL string comparison to decide whether an automatic remote-URL update is safe. Pin repository identity using the GitHub API's immutable numeric `id` (already available on `IAPIRepository`/stored `GitHubRepository`) and only auto-update the remote URL when the `id` matches the previously stored value. When the `id` differs (or cannot be verified), require explicit user confirmation before rewriting `origin`, and surface a warning that the underlying repository identity has changed — analogous to validating `updatedAt`/`roundId` before trusting a new price in the original report.

### Proof of Concept
1. Victim clones `github.com/orig-owner/some-repo` in Desktop; `origin` is set to its `clone_url`, and `gitHubRepository.cloneURL` is cached.
2. `orig-owner` renames their account or the repo is deleted/transferred, freeing the `orig-owner/some-repo` slug.
3. Attacker registers `orig-owner` and creates a repository named `some-repo`.
4. On Desktop's next background refresh, `Api.fetchRepository`/`fetchRepositoryCloneInfo` returns an `IAPIRepository` object whose `clone_url` differs from the currently configured remote (e.g., due to the underlying repo now being a different entity, or a genuine transfer path) [5](#0-4) .
5. `updateRemoteUrl` sees `protocolsMatch === true`, `remoteUrlUnchanged === true` (matches the old cached `cloneURL`), and `!urlsMatch === true`, so it calls `gitStore.setRemoteURL(...)`, silently repointing `origin` to the attacker's repository [6](#0-5) .
6. The victim's next push/pull is silently directed against attacker infrastructure without any prompt.

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export async function parsedResponse<T>(response: Response): Promise<T> {
  if (response.ok) {
    return deserialize<T>(response)
  } else {
    let apiError: IAPIError | null
    // Deserializing the API error could throw. If it does, we'll throw a more
    // general API error.
    try {
      apiError = await deserialize<IAPIError>(response)
    } catch (e) {
      throw new APIError(response, null)
    }

    throw new APIError(response, apiError)
  }
}

  public async fetchRepositoryCloneInfo(
    owner: string,
    name: string,
    protocol: GitProtocol | undefined
  ): Promise<IAPIRepositoryCloneInfo | null> {
    const response = await this.ghRequest('GET', `repos/${owner}/${name}`, {
      // Make sure we don't run into cache issues when fetching the repositories,
      // specially after repositories have been renamed.
      reloadCache: true,
    })

    if (response.status === HttpStatusCode.NotFound) {
      return null
    }

    const repo = await parsedResponse<IAPIRepository>(response)
    return {
      url: protocol === 'ssh' ? repo.ssh_url : repo.clone_url,
      defaultBranch: repo.default_branch,
    }
  }
