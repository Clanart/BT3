### Title
Negative reward amounts from Validate() cause block FinalizeState to error out, halting block processing/import - ([File: kaiax/reward/impl/blockstate.go])

### Summary
`StateProcessor.FinalizeState` propagates any error returned by a registered `BlockStateModule.FinalizeState` directly up to `StateProcessor.Process`, aborting the block entirely. The `RewardModule.FinalizeState` calls `spec.Validate()`, which returns `ErrNegativeRewardAmount` if any computed reward recipient amount is negative. Because reward computation performs several `big.Int` subtractions to distribute minting rewards, transaction fees, and staking rewards, an unexpected negative intermediate value (analogous to the `SafeCast.toUint256` revert on negative `perpNetValue` in the reported JOJO bug) turns into a hard error that prevents the block from being finalized — a Denial-of-Service on block processing/import rather than a graceful fallback.

### Finding Description
This mirrors the reported bug-class: an unsigned/positive-only invariant is assumed on a value that is derived via subtraction and can, under certain inputs, go negative, and the code chooses to hard-fail rather than clamp/handle the negative case.

- `RewardSpec.Validate()` iterates `spec.Rewards` and returns `errNegativeRewardAmount` if `amount.Sign() < 0`: [1](#0-0) 

- `RewardModule.FinalizeState` calls `Validate()` and returns the error directly, which is invoked from `StateProcessor.FinalizeState` for every block: [2](#0-1) 

- `StateProcessor.FinalizeState` (called from `Process`, which is invoked for every block during import/insertion) treats any `BlockStateModule.FinalizeState` error as fatal and aborts the entire block: [3](#0-2) [4](#0-3) 

- The reward computation contains several `Sub` operations on `*big.Int` whose results are only implicitly assumed non-negative, e.g. `distributableFee := new(big.Int).Sub(execFee, burntFee)` and `stakers.Sub(stakers, kip82Remainder)`: [5](#0-4) [6](#0-5) 

- `assignStakingRewards`/`assignStakingRewardsFlex` compute per-validator rewards from staking amounts (which change via normal staking transactions/deposits reachable by any staker) and subtract each allocated reward from a running `remaining` budget, relying on integer division rounding to keep `remaining` non-negative: [7](#0-6) [8](#0-7) 

The existing unit test `sanityCheckRewardSpec` explicitly asserts that `Proposer`, `Stakers`, `KIF`, `KEF`, `KPF`, and every reward recipient amount must have `Sign() >= 0`, confirming that the developers are aware negative values are a real risk that must be actively guarded against in every code path, and that any unguarded path (e.g., a not-yet-covered combination of governance ratios, staking configuration, or rounding edge case) would trip `Validate()`: [9](#0-8) 

Whereas the JOJO bug caused user-facing `deposit`/`withdraw` calls to revert (a localized DoS reachable by any caller), the Kaia analog is structurally worse: the same "unsigned cast/assert on a subtraction result" pattern sits inside consensus-critical block finalization (`FinalizeState`), which runs on every node for every block. If any combination of staking amounts (adjustable by any validator via ordinary staking transactions) and governance-configured reward/staking ratios produces a negative reward component that isn't caught by existing tests, `Validate()` aborts finalization for that block on all full nodes simultaneously — a chain-wide halt, not merely a single-user revert.

### Impact Explanation
If a negative reward amount is produced (e.g., due to a rounding/ordering edge case in the multi-step ratio splitting and staking-reward assignment functions not covered by current tests, or due to a future/edge governance parameter combination), `RewardModule.FinalizeState` returns `ErrNegativeRewardAmount`. This error propagates through `StateProcessor.FinalizeState` → `StateProcessor.Process`, which is called from block insertion (`BlockChain.insertChain` path) for every node validating that block. The block cannot be finalized, so it cannot be imported/validated — a full chain halt/DoS affecting all honest nodes, which is far more severe than the fee-delegation/user-level impact in the original report.

### Likelihood Explanation
Likelihood is speculative/uncertain: I could not construct or confirm a concrete input (specific staking amounts, governance ratios, CL staking split) that actually drives one of the `Sub` calls in `getter.go` negative, given the mitigations already in place (guards like `if excessInt[cn.RewardAddr] <= 0`, min/threshold checks, and integer-division rounding toward proposer/KIF remainders). The presence of the `Validate()` safety net and the extensive `sanityCheckRewardSpec` test coverage suggests the maintainers already treat this as a residual risk they explicitly test against, rather than an unmitigated bug. Without reproducing a concrete negative-value scenario (which was not feasible within the scope of this analysis), this should be treated as a lower-confidence, defense-in-depth finding rather than a proven exploitable path.

### Recommendation
- Instead of hard-erroring the entire block finalization when `Validate()` finds a negative reward amount, consider clamping to zero with an alert/metric, or proving via exhaustive invariant checks (fuzzing the ratio-splitting and staking-assignment functions with adversarial staking-amount/ratio combinations) that negative values are mathematically impossible for all valid governance configurations.
- Add fuzz/property-based tests around `assignStakingRewards`, `assignStakingRewardsFlex`, `getDeferredRewardFullKore`, and `getDeferredRewardFullFlex` specifically targeting the `Sub` calls, to increase confidence that `Validate()` can never trigger during real block finalization.
- If `Validate()` is intended purely as a last-resort consensus safety check, ensure there is monitoring/alerting on any occurrence in production distinct from silently halting the chain.

### Proof of Concept
Not established. I was unable to derive concrete staking-amount/governance-ratio inputs within the scope of this analysis that drive any of the `Sub` operations in `kaiax/reward/impl/getter.go` (e.g., `distributableFee`, `stakers.Sub(...)`, `remaining.Sub(...)`) to a negative value that survives existing guards and reaches `RewardSpec.Validate()`'s error path. Confirming exploitability would require either fuzzing these functions against the full space of `reward.ratio`/`reward.kip82ratio`/staking-amount combinations, or a deeper audit of the rounding/remainder arithmetic across `getDeferredRewardFullKore`, `getDeferredRewardFullFlex`, `assignStakingRewards`, and `assignStakingRewardsFlex`.

```go
func getDeferredRewardFullFlex(config *reward.RewardConfig, execFee, burntFee, blobFee *big.Int, si *staking.StakingInfo) (*reward.RewardSpec, error) {

		spec             = reward.NewRewardSpec()

	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.

	proposer, stakers := config.Kip82Ratio.Split(validators)
	ratioRemainder := calcRemainder(minted, proposer, stakers, kif, kef, kpf)
	kif.Add(kif, ratioRemainder)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.
	stakersAlloc, kip82Remainder := assignStakingRewardsFlex(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)
	stakers.Sub(stakers, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}

	spec = specWithProposerAndFundsFlex(spec, config, proposer, kif, kef, kpf, si)
	return spec, nil
}
```

```go
// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}

	// Distribute the budget to the CNs based on the excess stakes.
	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(budget)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		if excessInt[cn.RewardAddr] <= 0 {
			continue
		}
		excess := new(big.Int).SetUint64(excessInt[cn.RewardAddr])

		// The KAIA unit will cancel out:
		// reward (kei) = excess (KAIA) * budget (kei) / totalExcess (KAIA)
		reward := new(big.Int).Div(new(big.Int).Mul(excess, budget), totalExcess)
		if reward.Sign() <= 0 {
			continue
		}

		// If Prague and CL is configured for this CN, split the reward between CN and CL.
		if isPrague && cn.CLStakingInfo != nil {
			cnAmount, clAmount := cn.Split(reward)
			alloc[cn.RewardAddr] = cnAmount
			alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
		} else {
			alloc[cn.RewardAddr] = reward
		}
		remaining.Sub(remaining, reward)
	}
	return alloc, remaining
```

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
```

```go
func sanityCheckRewardSpec(t *testing.T, spec *reward.RewardSpec, msg interface{}) {
	sumSummary := new(big.Int).Add(spec.Minted, spec.TotalFee)
	sumSummary.Sub(sumSummary, spec.BurntFee)
	assert.True(t, spec.Minted.Sign() >= 0, msg)
	assert.True(t, spec.TotalFee.Sign() >= 0, msg)
	assert.True(t, spec.BurntFee.Sign() >= 0, msg)

	sumParts := new(big.Int).Add(spec.Proposer, spec.Stakers)
	sumParts.Add(sumParts, spec.KIF)
	sumParts.Add(sumParts, spec.KEF)
	sumParts.Add(sumParts, spec.KPF)
	assert.True(t, spec.Proposer.Sign() >= 0, msg)
	assert.True(t, spec.Stakers.Sign() >= 0, msg)
	assert.True(t, spec.KIF.Sign() >= 0, msg)
	assert.True(t, spec.KEF.Sign() >= 0, msg)
	assert.True(t, spec.KPF.Sign() >= 0, msg)

	sumRewards := new(big.Int)
	for _, amount := range spec.Rewards {
		sumRewards.Add(sumRewards, amount)
		assert.True(t, amount.Sign() >= 0, msg)
	}

	assert.Equal(t, sumSummary, sumParts, msg)
	assert.Equal(t, sumSummary, sumRewards, msg)
}
```
