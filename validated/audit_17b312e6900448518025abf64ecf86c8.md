### Title
Missing zero-value check on `bid.TargetTxHash` allows bypass of bid uniqueness/replacement rules in the auction bid pool - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool.validateBid` and `BidPool.insertBid` key bids by `(BlockNumber, TargetTxHash)` in `bidTargetMap` and use `TargetTxHash` as part of `Bid.Equals` to decide whether a same-sender bid is a "replay" of a prior one, but neither function rejects a zero-value `TargetTxHash` (`common.Hash{}`), mirroring the reported class of bug where a special/default value (`0`) is treated as an ordinary valid value in root/hash verification logic.

### Finding Description
`Bid.TargetTxHash` is attacker-supplied field of `BidData` submitted via `auction_submitBid` [1](#0-0) . In `AuctionAPI.SubmitBid`, `TargetTxHash` is only cross-checked against `targetTx.Hash()` when the caller sends the target transaction directly in the same call, so it is possible to shape a request where `TargetTxHash` is `common.Hash{}` (zero) if the caller is submitting a bid without a directly attached, verifiable target tx path, or more generally because `validateBid` itself performs no defense-in-depth check on the field.

In `validateBid`, the six enumerated checks (block-number range, positive bid, data size, gas limit, signatures) never verify `bid.TargetTxHash != common.Hash{}` [2](#0-1) . `insertBid` then stores the bid keyed by the literal `targetTxHash` value in `bidTargetMap[blockNumber][targetTxHash]` [3](#0-2) , and `Bid.Equals` compares `TargetTxHash` fields directly with no zero-value exclusion [4](#0-3) . `senderHasDifferentWinner` relies on `Equals` to permit a sender's bid to be treated as a no-op replay when `TargetTxHash` values match [5](#0-4) .

Because zero is never excluded, multiple distinct bids (potentially from different flows, or a bid submitted before/without a resolvable target transaction) can collide on the `common.Hash{}` slot in `bidTargetMap[blockNumber]`, exactly as the `SpokeConnector` root-tracking mappings collide/alias state at the reserved value `0`.

### Impact Explanation
A zero `TargetTxHash` slot means the "target" the bid is supposed to attach to is undefined/absent. Because bids are looked up in block building by `GetTargetTxMap(num)` (returning `bidTargetMap[num]`) and matched against the actual target transaction detected in the pool [6](#0-5) , a bid keyed at the zero hash could be replaced/overwritten by unrelated zero-hash bids via the FCFS/"replace if higher" logic in `insertBid` (lines 294-309), letting an attacker with a lower true valid bid squeeze out or reset auction state associated with the reserved key, or cause bid-selection logic elsewhere that treats "no target hash found" as equivalent to "hash == 0" to incorrectly match. This is a fee/auction-settlement integrity issue (auction winner selection), matching the "unauthorized value movement / auction settlement theft" impact category in the rules.

### Likelihood Explanation
`auction_submitBid` is a public, unprivileged (though non-public API flag) RPC endpoint reachable by any bidder/searcher who can reach the CN's auction API [7](#0-6) ; forming a `BidData` with `TargetTxHash: common.Hash{}` requires no special privilege — only a validly signed searcher/auctioneer signature pair, which the auctioneer/searcher relationship already presumes an attacker can obtain (searcher role). Given `validateBid` performs no explicit rejection, the exploit path is a single RPC call away, making likelihood moderate-to-high assuming attacker controls a valid searcher/auctioneer signature pair (which is the same threat model the rest of `validateBid`'s checks defend against).

### Recommendation
In `BidPool.validateBid`, add an explicit check that `bid.TargetTxHash != (common.Hash{})`, returning a dedicated error (e.g. `auction.ErrInvalidTargetTxHash`, which already exists and is used elsewhere in `api.go`) before the bid is inserted into `bidTargetMap`.

### Proof of Concept
1. Construct a `BidInput`/`Bid` with `TargetTxHash = common.Hash{}` (all-zero), a valid future `BlockNumber`, `Bid > 0`, valid `Data`/`CallGasLimit`, and valid `SearcherSig`/`AuctioneerSig` recovering to the expected `Sender`/`auctioneer`.
2. Call `auction_submitBid` (or directly `BidPool.AddBid`) with this bid.
3. Observe that `validateBid` passes all six checks (block range, positive bid, data size, gas limit, signatures) since none reference `TargetTxHash`, and `insertBid` stores it at `bidTargetMap[blockNumber][common.Hash{}]`.
4. Submit a second, unrelated bid also using `TargetTxHash = common.Hash{}` for the same block; per the FCFS/replace logic at `kaiax/auction/impl/bid_pool.go` lines 294-309, this second bid can overwrite/evict the first purely by having marginally higher `Bid` value, despite the two bids having no logical relationship (no genuine shared target transaction) — demonstrating the zero-value aliasing collision described in the reported bug class.

Note: I could not fully verify whether `auction_submitBid`'s outer flow (`toTx`/`SendTx` path in `api.go`) always forces a non-zero, cross-checked `TargetTxHash` for every code path that reaches `bidPool.AddBid` (e.g., bids arriving via P2P `HandleBid` from peers bypass `SubmitBid`'s `toTx` check entirely) [8](#0-7) ; this P2P path clearly has no target-hash cross-check at all, reinforcing that `validateBid` is the only enforcement point and currently lacks the zero-check.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

		return
	}

		logger.Trace("Rate limit exceeded for peer", "peerID", peerID)
		return
	}

	select {
	case bp.bidMsgCh <- bid:
	default:
		logger.Trace("Bid queue is full, dropping bid", "peerID", peerID)
	}
}
