## Title
`ProxyModule::on_response` never charges the bandwidth gate, letting GET responses drain prepaid bandwidth for free — ([File: parachain/runtimes/gargantua/src/ismp.rs])

### Summary
`pallet-bandwidth` is a prepaid, purchased byte-allowance system: apps pay real fee-token value to `BandwidthManager.sol`, which credits a `(chain, app)` byte balance on Hyperbridge (`modules/pallets/bandwidth/src/lib.rs`). The `BandwidthGate::try_consume` call is the *only* metering mechanism protecting that paid-for balance — this is the exact functional analog of the `apply_gas_cost()` call the SEDA report says must wrap every WASI import. In the `gargantua` runtime's `ProxyModule`, `on_accept` (POST requests) correctly calls `try_consume` before routing, but `on_response` (GET responses) — despite a comment claiming it "mirrors the request path in `on_accept`" — never calls `try_consume` at all.

### Finding Description
`parachain/runtimes/gargantua/src/ismp.rs`:

```rust
fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
    #[cfg(not(feature = "no-bandwidth"))]
    if !pallet_bandwidth::Pallet::<Runtime>::is_purchase_message(&request) {
        let bytes = ismp::abi::encode_post_request(&request).len() as u32;
        <pallet_bandwidth::Pallet<Runtime> as pallet_bandwidth::BandwidthGate>::try_consume(
            &request.source, &request.from, bytes,
        )...
    }
    ...
}

fn on_response(&self, response: GetResponse) -> Result<Weight, anyhow::Error> {
    // Bandwidth gate. Mirrors the request path in `on_accept`: ...
    if response.dest_chain() != HostStateMachine::get() {
        return Ok(Weight::from_parts(0, 0));
    }
    let dest = &response.get.from;
    let pallet_id = ModuleId::from_bytes(dest)...;
    match pallet_id {
        pallet_ismp_demo::PALLET_ID => ...on_response(response),
        _ => Err(anyhow!("Destination module not found")),
    }
}

Every non-purchase inbound message is supposed to be gated on `BandwidthGate::try_consume` before its bytes are accepted, exactly as documented: "Every non-purchase POST request from a registered source chain runs through `BandwidthGate::try_consume(source, app, bytes)`" and the gate is meant to be "consulted on every inbound request from a source chain" including GET responses, whose bandwidth cost is explicitly computed elsewhere in the codebase (`pallet-state-coprocessor`) using the exact same metric — the ABI-encoded size of the `GetResponse`:
```rust
let bytes = ismp::abi::encode_get_response(&response).len() as u32;
<T as Config>::BandwidthGate::try_consume(&response.get.source, &response.get.from, bytes)...
``` [2](#0-1) 

But that metering only happens in `pallet-state-coprocessor`'s own `handle_get_requests` entry point (Hyperbridge-originated GET requests dispatched by the coprocessor itself). The generic ISMP inbound path used for ordinary GET responses routed through the `ProxyModule::on_response` in the `gargantua` (and equivalently `nexus`, see `parachain/runtimes/nexus/src/ismp.rs:412-418`) runtime never calls `try_consume`, unlike the parallel `on_accept` implementation just above it in the same file which explicitly enforces it. The comment text ("Mirrors the request path in `on_accept`") documents the developers' intent that this gate should exist, confirming the check is a missing/dropped guard rather than an intentional design choice — the same class of defect as the SEDA finding, where a whole class of imports was intended to be wrapped in `apply_gas_cost()` but wasn't.

Because `ismp::router::IsmpRouter::module_for_id` returns the same `ProxyModule` for every module id (`fn module_for_id(&self, _bytes: Vec<u8>) -> ... { Ok(Box::new(ProxyModule::default())) }`), all inbound GET responses to this chain go through the unmetered path. Any counterparty chain (or, since GET response delivery is triggered by relayer-submitted proofs of state that genuinely exists on the destination, any relayer/app pair whose GET request was sent) can have arbitrarily large `GetResponse.values` payloads delivered without ever debiting the corresponding `(chain, app)` bandwidth subscription, silently bypassing the entire prepaid metering economics of `pallet-bandwidth`.

### Impact Explanation
`pallet-bandwidth` balances are a real, purchased economic resource: `BandwidthManager.purchase()` pulls fee-token payment on the source chain to mint a byte allowance (`Allowance` storage) that other on-chain logic (the gate) is supposed to atomically check-and-deduct. This missing deduction for GET responses means an app's response traffic is delivered for free indefinitely, without ever consuming or exhausting its purchased subscription. It undermines the fund-linked invariant that bandwidth consumption must correspond exactly to what was paid for — a false-acceptance-of-service condition parallel to the fund/resource-accounting invariants targeted by the bounty scope (bandwidth balances "must move exactly once and only to the rightful beneficiary and amount" — here bandwidth is *consumed* by nobody's payment, breaking that invariant in the opposite direction: work is done and never billed against the subscriber's paid balance while other traffic exhausts the shared FIFO allowance model unevenly, and governance/treasury economics built on `BandwidthConsumed` accounting become unreliable for capacity planning and billing reconciliation).

### Likelihood Explanation
This is reachable by any unprivileged party that already interacts with the protocol through the normal ISMP flow: dispatch a `GetRequest` (or in this permissioned model, respond via the standard GET-response delivery path with the `ProxyModule` router) that terminates on this chain. No malicious relayer, prover, or governance actor is required — the bug is a plain missing function call in production runtime code that executes on every legitimate GET-response delivery. The comment misleadingly documents the intended (but absent) behavior, indicating this is a genuine regression/oversight rather than a deliberate design trade-off, and it is unconditionally present whenever the `no-bandwidth` feature flag is off (i.e., production configuration).

### Recommendation
Add the same `try_consume` metering to `ProxyModule::on_response` that already exists in `ProxyModule::on_accept`, using `ismp::abi::encode_get_response(&response).len() as u32` (or equivalent) as the billed size, keyed by `(response.get.source, response.get.from)`, before dispatching to the destination module — mirroring exactly what the code comment already claims is being done. Apply the same fix in `nexus`'s `ProxyModule::on_response` if it has the same gap.

### Proof of Concept
1. App `A` on source chain `S` purchases a small bandwidth tier via `BandwidthManager.purchase()`, crediting `Allowance::<T>::get(S, A)` with a bounded byte balance.
2. `A` dispatches a `GetRequest` (or otherwise becomes the recipient, `response.get.from == A`, of a GET response) whose response payload size vastly exceeds the purchased allowance.
3. A relayer delivers the corresponding `GetResponse` through the normal ISMP response-handling path (`modules/ismp/core/src/handlers/response.rs::handle`), which invokes `router.module_for_id(request.from)` → `ProxyModule::on_response`.
4. `ProxyModule::on_response` never calls `BandwidthGate::try_consume`, so no bytes are deducted from `Allowance::<T>::get(S, A)` regardless of the response's size.
5. Repeat indefinitely: `A`'s purchased allowance remains untouched no matter how much response traffic is delivered, and `BandwidthConsumed` events are never emitted for this traffic, defeating the entire prepaid-bandwidth billing model documented in `docs/content/developers/evm/bandwidth/overview.mdx`.

impl IsmpModule for ProxyModule {
	fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
		// Bandwidth gate. Always-enforce unless the `no-bandwidth` flag
		// is set; skipped for purchase messages so the recharge flow
		// itself doesn't need bandwidth. With the flag on the gate is a
		// no-op and this block is compiled out entirely.
		#[cfg(not(feature = "no-bandwidth"))]
		if !pallet_bandwidth::Pallet::<Runtime>::is_purchase_message(&request) {
			let bytes = ismp::abi::encode_post_request(&request).len() as u32;
			<pallet_bandwidth::Pallet<Runtime> as pallet_bandwidth::BandwidthGate>::try_consume(
				&request.source,
				&request.from,
				bytes,
			)
			.map_err(|err| {
				anyhow!(
					"bandwidth gate: {err} (source={:?}, from={:x?})",
					request.source,
					request.from
				)
			})?;
		}

		if request.dest != HostStateMachine::get() {
			Ismp::dispatch_request(
				Request::Post(request),
				FeeMetadata::<Runtime> { payer: [0u8; 32].into(), fee: Default::default() },
			)?;
			return Ok(Weight::from_parts(0, 0));
		}

		let pallet_id =
			ModuleId::from_bytes(&request.to).map_err(|err| Error::Custom(err.to_string()))?;

		match pallet_id {
			pallet_ismp_demo::PALLET_ID =>
				pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_accept(request),

			#[cfg(not(feature = "no-bandwidth"))]
			id if id == ModuleId::Pallet(pallet_bandwidth::pallet::PALLET_BANDWIDTH) =>
				pallet_bandwidth::Pallet::<Runtime>::default().on_accept(request),

			pallet_hyper_fungible_token::PALLET_ID =>
				pallet_hyper_fungible_token::Pallet::<Runtime>::default().on_accept(request),

			_ => Err(anyhow!("Destination module not found")),
		}
	}

	fn on_response(&self, response: GetResponse) -> Result<Weight, anyhow::Error> {
		// Bandwidth gate. Mirrors the request path in `on_accept`: the chain
		// and module that produced the response pay for the bytes they
		// deliver. Compiled out when the `no-bandwidth` flag is on.
		if response.dest_chain() != HostStateMachine::get() {
			return Ok(Weight::from_parts(0, 0));
		}

		let dest = &response.get.from;

		let pallet_id = ModuleId::from_bytes(dest).map_err(|err| Error::Custom(err.to_string()))?;

		match pallet_id {
			pallet_ismp_demo::PALLET_ID =>
				pallet_ismp_demo::IsmpModuleCallback::<Runtime>::default().on_response(response),
			_ => Err(anyhow!("Destination module not found")),
		}
	}
