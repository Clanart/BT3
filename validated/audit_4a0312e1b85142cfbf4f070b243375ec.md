### Title
Missing bounds check in `is_atom_canonical` allows attacker-controlled buffer over-read via truncated CLVM length prefix - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a variable-length CLVM atom size prefix (1–6 bytes) directly out of an attacker-supplied `puzzle_reveal`/`solution` buffer without ever checking that the buffer is long enough to contain the full prefix, mirroring the class of bug in CVE-2021-3402 (YARA `macho.c`): a size/length field is read and used to index into the buffer before validating it against the buffer's actual remaining length.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` determines the length-prefix width (`prefix_len`, 0–5 extra bytes) from the leading byte, then loops reading `clvm_buffer[offset]` for each prefix byte: [1](#0-0) 

No comparison is made between `offset + prefix_len` and `len(clvm_buffer)` before indexing. `is_clvm_canonical()`, which drives this, similarly walks the buffer byte-by-byte via `clvm_buffer[offset]` with no length check per token: [2](#0-1) 

If a spend bundle's `puzzle_reveal` or `solution` bytes end exactly at (or before) a multi-byte length-prefix boundary — e.g. a trailing byte like `0xFC`, `0xF8`, `0xF0`, `0xE0`, or `0xC0` with insufficient trailing bytes — `clvm_buffer[offset]` raises an uncaught `IndexError` instead of returning `False`/failing validation cleanly. This is directly analogous to the CVE's "buffer overflow reads" from insufficiently-bounded size fields during untrusted binary parsing.

This code is reachable from an unprivileged spend-bundle submitter: `is_clvm_canonical` is used by the mempool's DEDUP-eligibility path to validate canonical encoding of `puzzle_reveal`/`solution` bytes coming straight from a submitted `SpendBundle`, as confirmed by mempool tests exercising non-canonical/truncated atom prefixes (`test_atom_not_canonical`, `test_clvm_not_canonical`, `test_mempool_requires_canonical_clvm`): [3](#0-2) [4](#0-3) 

### Impact Explanation
An `IndexError` raised inside `is_clvm_canonical`/`is_atom_canonical` during mempool admission is not a memory-safety issue (Python bounds-checks lists/bytes), but if it propagates uncaught through the mempool-admission path (as opposed to being converted into a handled `ValidationError`/`Err`), it would crash or abort the transaction-processing call for that code path — a spend-triggered halt in transaction processing, one of the accepted impact classes for this analysis. I was not able to fully trace, within the tool budget, whether every call site of `is_clvm_canonical`/`is_atom_canonical` in the DEDUP-eligibility logic is wrapped in a broad `try/except` that would already swallow this exception; that must be verified directly in the surrounding mempool code before treating this as confirmed-exploitable.

### Likelihood Explanation
Constructing a truncated multi-byte atom length prefix (e.g., ending a `puzzle_reveal` or `solution` byte string exactly on a `0xC0`/`0xE0`/`0xF0`/`0xF8`/`0xFC` prefix byte) is trivial for any spend-bundle submitter and requires no special privileges, network position, or cryptographic material.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` (and the byte-walk loop in `is_clvm_canonical`) verifying `offset + prefix_len < len(clvm_buffer)` (and similarly that `offset < len(clvm_buffer)` before each token read) before indexing, returning a non-canonical/invalid result instead of raising `IndexError`. Additionally, confirm and, if needed, harden the call sites so any residual parsing exception from these helpers is converted into a normal `Err.INVALID_COIN_SOLUTION`/similar rejection rather than an unhandled exception.

### Proof of Concept
1. Construct a `puzzle_reveal` or `solution` byte string whose final byte is a multi-byte atom prefix marker with insufficient trailing bytes, e.g. `bytes.fromhex("fc")` (a 6-byte length prefix marker with zero trailing bytes) or `bytes.fromhex("f807")` (5-byte prefix marker with only 1 of 4 needed trailing bytes).
2. Submit a `SpendBundle` whose `CoinSpend.puzzle_reveal`/`solution` is one of these buffers, following the pattern in `test_mempool_requires_canonical_clvm`: [5](#0-4) 
3. When the mempool's DEDUP-eligibility check calls `is_clvm_canonical`/`is_atom_canonical` on this buffer, `clvm_buffer[offset]` indexes past the end of the byte string, raising `IndexError` inside `chia/full_node/mempool_manager.py`'s helper functions at [6](#0-5) .

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
