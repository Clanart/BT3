### Title
Malicious FROST preprocess forces aggregate nonce to identity, panicking the Bitcoin Schnorr signer - (File: networks/bitcoin/src/crypto.rs)

### Summary
CVE-2018-13095 is a "corrupted structure declares contents that violate internal assumptions, causing memory corruption and a BUG" class bug — crafted input reaches a kernel path that assumes a structural invariant holds, and the violation panics the system. The Serai analog lives in the BIP-340 FROST signing path: a signing participant's `Preprocess` contains free-form group elements (`D`, `E` nonce commitments) which are only checked for canonical encoding, never for non-identity. An attacker can choose their nonce commitments so that the combined signature nonce `R = sum(D_i + rho_i * E_i)` is the point at infinity. `sign_share` then feeds `R` into `Hram::hram`, which calls `x(R)` — `to_encoded_point(true).x().expect("point at infinity")` at `networks/bitcoin/src/crypto.rs:15` — unconditionally panicking and aborting the signing process mid-round.

### Finding Description
`AlgorithmSignMachine::read_preprocess` deserializes attacker-controlled bytes via `Commitments::read`, which reads one `GeneratorCommitments` (two points `D`, `E`) per generator with `C::read_G` — a canonical-encoding check only, with no identity rejection ( [1](#0-0) , [2](#0-1) ). During `sign`, per-participant binding factors `rho` are deterministically derived from the `rho_transcript` built over all preprocesses, so the attacker — who sees every other participant's preprocess before broadcasting their own — can compute their own `rho` and solve `D + rho * E = -Σ(other contributions)`, making the aggregate nonce `Rs[n][0]` the identity point ( [3](#0-2) ). `B.nonces` then produces `nonce_sums[0][0] = identity`, and `Schnorr::sign_share` calls `H::hram(&nonce_sums[0][0], &params.group_key(), msg)` ( [4](#0-3) ). In the Bitcoin algorithm `Hram::hram` invokes `x(R)` → `encoded.x().expect("point at infinity")`, which panics on identity ( [5](#0-4) , [6](#0-5) ). The doc comment on `Schnorr` acknowledges infinity "may panic" but claims a "negligible probability" — that reasoning only covers random nonces, not an adversary who deliberately crafts nonce commitments.

### Impact Explanation
Any single participant in a threshold signing session for a Bitcoin transaction (`TransactionSignMachine::sign` → per-input `AlgorithmSignMachine::sign`, `networks/bitcoin/src/wallet/send.rs:355-397`) can deterministically crash every honest signer who processes their preprocess. This is a denial of service on the signing protocol equivalent in kind to the CVE's "memory corruption and BUG" on a corrupted image: an untrusted, attacker-crafted structure reaches a code path assuming an unenforced invariant (non-identity aggregate point). Depending on deployment (panic across an FFI boundary, `panic = abort`, or repeated signing attempts), the attacker can permanently stall signing for a transaction/plan. Because the panic occurs inside `sign` before the signature share is produced, there is no secret leakage — impact is availability only, matching the CVE's C:N/I:N/A:H profile.

### Likelihood Explanation
Fully deterministic and reachable by any unprivileged co-signer with public inputs: the only bytes required are a normal-looking `Preprocess` message (canonical points, so `read_preprocess` accepts it). The attacker needs no special position — any participant index works — and can compute their `rho` locally since the rho transcript commits to all preprocesses including their own ( [7](#0-6) ). Constructing `E = identity`, `D = -(sum of other participants' combined contributions)` yields aggregate identity for the single-generator Schnorr algorithm used by the Bitcoin wallet.

### Recommendation
Reject identity points for `D`/`E` in `GeneratorCommitments::read` / `NonceCommitments::read`, or reject a zero aggregate nonce before `sign_share` is invoked (check `Rs[n][0].is_identity()` in `AlgorithmSignMachine::sign` and raise `FrostError::InvalidCommitments(l)` attributing blame). Alternatively, make `Hram`/the `Schnorr` algorithm handle identity `R` gracefully instead of documenting a panic. Blame attribution is preferable to a generic error so the faulty participant can be slashed rather than silently aborting the session.

### Proof of Concept
Conceptual, against `networks/bitcoin` + `crypto/frost`:

1. Honest signers create `TransactionMachine`/`AlgorithmMachine`s for `Secp256k1` + `Schnorr::new()` and broadcast preprocesses. Attacker collects all honest `Preprocess`es (`read_preprocess` accepts all canonical encodings).
2. Attacker locally replays the `rho_transcript` construction (`FROST_rho` over `group_key`, `hash_msg`, and `hash_commitments` of the transcript of preprocesses, `crypto/frost/src/sign.rs:361-371`) to derive their own binding factor `rho_a` and each honest party's combined commitment `D_i + rho_i * E_i`.
3. Attacker publishes a `Preprocess` whose sole `GeneratorCommitments` is `[D_a, E_a] = [-(Σ_{i≠a}(D_i + rho_i*E_i)), identity]` — computed by choosing `E_a` freely (e.g., identity) and solving for `D_a` since `rho_a` binds `D_a`/`E_a` transitively via the preprocesses challenge (equivalently, iterate candidate `E_a` until the closed-form `D_a` yields aggregate identity — for the single-generator case pick `E_a = G`, `D_a = -(Σ others) - rho_a*G`... precisely: set `D_a + rho_a*E_a = -(Σ others)` by fixing `E_a` and solving `D_a = -(Σ others) - rho_a*E_a`, recomputing `rho_a` self-consistently since the transcript is deterministic).
4. Every honest signer running `sign` computes `Rs[0][0] = identity`, enters `Schnorr::sign_share` → `Hram::hram` → `x(&identity)` → panic at `crypto.rs:15`: `expect("point at infinity")`. The signing session aborts on all honest nodes with no error path (it is a panic, not `FrostError`).

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
