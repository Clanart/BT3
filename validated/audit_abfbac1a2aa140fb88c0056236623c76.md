## Finding: `githubAssetVideoRegex` uses substring/prefix matching without hostname anchoring, allowing lookalike-domain bypass - (File: `app/src/lib/markdown-filters/video-url-regex.ts`)

### Summary
The regex used by `VideoTagFilter` (and `VideoLinkFilter`) to decide whether a `<video src="...">` element is a legitimate GitHub asset is built by literal-prefix-matching the string `https://user-images.githubusercontent.com`, with no boundary character (like `/` or an anchored hostname parse) separating the domain from the rest of the URL. This lets an attacker use a lookalike domain such as `https://user-images.githubusercontent.com.attacker.io/x.mp4` and have it incorrectly classified as a trusted GitHub asset URL.

### Finding Description
`githubAssetVideoRegex` is constructed as: [1](#0-0) 

```
^https://user-images\.githubusercontent\.com .+ (mp4|webm|ogg|...|)$
```

Because the pattern is `^` + escaped literal domain string + `.+` + extension group, it only checks that the URL *starts with* that literal string — it never verifies that the domain actually ends there (e.g. via a following `/` or proper URL parsing). A string like:

```
https://user-images.githubusercontent.com.attacker.io/video.mp4
```

still has `https://user-images.githubusercontent.com` as a literal prefix, so `.+` simply consumes `.attacker.io/video.mp4`, and the trailing extension alternation matches `mp4$`. The regex therefore returns `true` for this attacker-controlled hostname.

This regex is consumed directly by `el.src`/`node.src` checks in `VideoTagFilter`: [2](#0-1) 

and by `VideoLinkFilter`, which additionally *creates* a `<video>` tag from an auto-linked href once this same flawed check passes: [3](#0-2) 

The markdown body rendered through this pipeline comes from untrusted content (PR/issue/commit bodies, review comments, etc.) and is only run through `DOMPurify.sanitize(marked(markdown, ...))` before these custom node filters run — DOMPurify's default allow-list permits `<video>`/`src` by default, so the tag survives sanitization and reaches `VideoTagFilter`: [4](#0-3) [5](#0-4) 

The resulting HTML is then loaded into an iframe sandboxed only with `sandbox="allow-same-origin"` (no `allow-scripts`): [6](#0-5) 

### Impact Explanation
Because scripts are not allowed in the sandbox, this does not directly yield script execution or IPC/credential exfiltration. What it does allow is: an attacker-controlled repository, PR, issue, or commit body containing a `<video src="https://user-images.githubusercontent.com.attacker.io/...">` tag (or a bare auto-linked URL of that form) will be retained by `VideoTagFilter`/`VideoLinkFilter` and rendered as a live `<video>` element, causing the Electron renderer to make an unprompted outbound network request to attacker infrastructure whenever the user views that content (PR description, PR quick view, commit message, comment, etc.). This leaks the viewing user's IP address and request metadata (a passive-tracking/beacon primitive) to a domain the user never intended to trust, and could be paired with the `videoExtensionRegex`'s trailing empty alternative (`|`) — which effectively makes the extension check optional — to point at arbitrary attacker-controlled resources, not just video files, since the "extension" match can be satisfied by nothing.

Under the stated bounty scope, this does not clearly rise to "code execution, file read/write outside the repo, credential/token exfiltration, unauthorized OAuth, renderer-sandbox/IPC escape, or silent corruption of commits" — it is best characterized as an unauthorized outbound network beacon / minor tracking issue inside a script-disabled sandbox, which is at most borderline against the listed valid-impact categories (closest to none of them cleanly). I flag this rather than assert a fully in-scope impact, since it does not produce code execution or credential exfiltration and the sandbox blocks script execution.

### Likelihood Explanation
High likelihood of the regex being bypassable exactly as described — this is a simple, reliably reproducible string-prefix flaw, not a probabilistic condition. The attacker fully controls the necessary input (markdown body of a PR/issue/commit/comment) and needs no special user interaction beyond the user viewing that content.

### Recommendation
Fix `githubAssetVideoRegex` (`app/src/lib/markdown-filters/video-url-regex.ts`) to validate the actual URL origin/hostname rather than doing prefix string matching — e.g. `new URL(src).hostname === 'user-images.githubusercontent.com'` — and remove the empty alternative from `videoExtensionRegex` so the extension check cannot be trivially satisfied.

### Proof of Concept
```js
const { githubAssetVideoRegex } = require('./video-url-regex')
githubAssetVideoRegex.test('https://user-images.githubusercontent.com.attacker.io/video.mp4')
// => true (should be false)
```
Embedding `<video src="https://user-images.githubusercontent.com.attacker.io/video.mp4"></video>` (or an auto-linked plain URL of that form) in a PR/issue/commit body causes `VideoTagFilter`/`VideoLinkFilter` to retain/emit the tag, and it will be rendered inside the sandboxed markdown iframe, triggering a request to attacker infrastructure.       // If it is video element with a valid source, we return null to leave it alone.
      // This is different than dotcom which regenerates a video tag because it

      return null
    }

    // Return empty array so that video tag is removed
    return []
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const videoSrc = this.getGithubVideoLink(node)
    if (videoSrc === null) {
      return null
    }

    const videoNode = document.createElement('video')
    videoNode.src = videoSrc
    return [videoNode]
  }

  /**
   * If the give node is a video url post markdown parsing, it returns the video
   * url, else return null.
   *
   * Video url post markdown parsing looks like:
   * <p>
   *  <a href="https://user-images.githubusercontent.com/7559041/1234.mp4">
   *    https://user-images.githubusercontent.com/7559041/1234.mp4
   *  </a>
   * </p>
   * */
  private getGithubVideoLink(node: Node): string | null {
    if (
      isElement(node, 'p') &&
      node.childElementCount === 1 &&
      node.firstChild &&
      isElement(node.firstChild, 'a') &&
      githubAssetVideoRegex.test(node.firstChild.href)
    ) {
      return node.firstChild.href
    }

    return null
  }

  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
