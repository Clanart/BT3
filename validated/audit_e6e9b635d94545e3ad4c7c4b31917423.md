### Title
Bank Precompile's `sendNative` Bypasses the Bank Module's Send-Enabled Circuit Breaker and Blocked-Address Checks - (File: precompiles/bank/bank.go)

### Summary
The bank precompile's `send` method correctly routes native token transfers through `bankMsgServer.Send`, which enforces the `x/bank` module's send-enabled circuit breaker and blocked-address checks. However, the `sendNative` method — reachable by any EVM caller sending native `value` to the precompile — bypasses this msg-server path entirely and calls `BankKeeper.SendCoinsAndWei` directly, skipping the same admission checks. This mirrors the reported `DaoFactory.create()` issue: an emergency-pause / access-control mechanism exists in the codebase but is not applied uniformly across all state-mutating entry points.

### Finding Description
`PrecompileExecutor.send` (the ERC20-pointer path) builds a `banktypes.MsgSend` and executes it via `p.bankMsgServer.Send(...)`: [1](#0-0) 

`msgServer.Send` enforces both the module's send-enabled circuit breaker and address restrictions before moving any funds: [2](#0-1) 

In contrast, `PrecompileExecutor.sendNative` — invoked whenever an EVM transaction/contract call sends non-zero `value` to the bank precompile address `0x1001` — never calls the msg server. It computes the usei/wei split and calls `p.bankKeeper.SendCoinsAndWei` directly: [3](#0-2) 

`SendCoinsAndWei` and the underlying `AddCoins`/`AddWei` only consult the pluggable `CanSendTo` recipient-checker hook; they do not call `IsSendEnabledCoins`, do not check `BlockedAddr`, and do not consult `IsInDenomAllowList`: [4](#0-3) [5](#0-4) 

The governance-controlled `SendEnabled`/`DefaultSendEnabled` params are exactly the chain's "pause" mechanism for coin transfers, documented as a way to "start a network without enabling transfers while ensuring critical network functionality is operating as expected," and are the sole gate checked in `IsSendEnabledCoins`: [6](#0-5) 

Just as `DaosFactory.create()` inherited `PausableUpgradeable` but omitted `whenNotPaused` on one function, the bank precompile implements the send-enabled/blocked-address gate on `send()` but omits it on the `sendNative()` entry point that is equally reachable by any EVM transaction sender.

### Impact Explanation
If governance disables sends for the base denom (e.g., `DefaultSendEnabled = false` or an explicit `SendEnabled{Denom: "usei", Enabled: false}` entry) during an incident — the exact "pause" scenario the report calls out — native usei transfers can still be executed by any EVM caller through `sendNative`, defeating the intended circuit breaker. It also bypasses the `BlockedAddr` check that the `MsgSend` path enforces, meaning restricted/module addresses that should never directly receive funds via a user-initiated transfer can still receive them through this precompile path. This is a fund-movement admission-control bypass reachable from ordinary EVM transactions, not a cosmetic gap.

### Likelihood Explanation
Any account can trigger this by sending an EVM transaction with non-zero `value` to the bank precompile (`0x0000000000000000000000000000000000001001`) calling `sendNative`; no special privileges are required. The bypass is deterministic and always occurs since `sendNative` never touches `IsSendEnabledCoins`/`BlockedAddr`, regardless of network configuration, so it will manifest immediately whenever governance relies on `SendEnabled`/`BlockedAddr` as a safety control.

### Recommendation
Add the same admission checks used in `msgServer.Send` to `PrecompileExecutor.sendNative` before moving funds: call `p.bankKeeper.IsSendEnabledCoins` for the base denom and `p.bankKeeper.BlockedAddr(receiverSeiAddr)` (and, if applicable, `IsInDenomAllowList`), returning an error and reverting the call if either check fails — mirroring the fix pattern of adding the missing guard (`whenNotPaused`) to the previously unguarded entry point.

### Proof of Concept
1. Governance (or the equivalent emergency authority) sets bank module params with `DefaultSendEnabled = false` (or explicitly disables `usei`), intending to halt all native transfers as an emergency pause.
2. An attacker deploys/uses any contract that calls the bank precompile's `sendNative(string receiver)` payable method at `0x0000000000000000000000000000000000001001`, attaching non-zero `value`.
3. Trace the call: `PrecompileExecutor.sendNative` → `pcommon.HandlePaymentUseiWei` → `p.bankKeeper.SendCoinsAndWei` (precompiles/bank/bank.go:280-287) → `BaseSendKeeper.SendCoinsAndWei` (sei-cosmos/x/bank/keeper/send.go:440-459), none of which call `IsSendEnabledCoins` or `BlockedAddr`.
4. The transfer of native usei succeeds despite the module-level pause, and funds can even be sent to addresses that `BlockedAddr` would normally reject via `MsgSend`.

func (p PrecompileExecutor) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
	}
	accExists := p.accountKeeper.HasAccount(ctx, receiverSeiAddr)
	if !accExists {
		defer metrics.RecordBankNewAccount(ctx.Context())
		p.accountKeeper.SetAccount(ctx, p.accountKeeper.NewAccountWithAddress(ctx, receiverSeiAddr))
	}

	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		remainingGas := pcommon.GetRemainingGas(newCtx, p.evmKeeper)
		if hooks.OnEnter != nil {
			hooks.OnEnter(evm.GetDepth()+1, byte(vm.CALL), caller, p.evmKeeper.GetEVMAddressOrDefault(newCtx, receiverSeiAddr), []byte{}, remainingGas, value)
		}
		defer func() {
			if hooks.OnExit != nil {
				hooks.OnExit(evm.GetDepth()+1, []byte{}, 0, nil, false)
			}
		}()
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

// AddCoins increase the addr balance by the given amt. Fails if the provided amt is invalid.
// It emits a coin received event.
func (k BaseSendKeeper) AddCoins(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {
	if !k.CanSendTo(ctx, addr) {
		return sdkerrors.ErrInvalidRecipient
	}
	if !amt.IsValid() {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidCoins, amt.String())
	}

	for _, coin := range amt {
		balance := k.GetBalance(ctx, addr, coin.Denom)
		newBalance := balance.Add(coin)

		err := k.setBalance(ctx, addr, newBalance, checkNeg)
		if err != nil {
			return err
		}
	}

	// emit coin received event
	ctx.EventManager().EmitEvent(
		types.NewCoinReceivedEvent(addr, amt),
	)

	return nil
}

// IsSendEnabledCoins checks the coins provide and returns an ErrSendDisabled if
// any of the coins are not configured for sending.  Returns nil if sending is enabled
// for all provided coin
func (k BaseSendKeeper) IsSendEnabledCoins(ctx sdk.Context, coins ...sdk.Coin) error {
	for _, coin := range coins {
		if !k.IsSendEnabledCoin(ctx, coin) {
			return sdkerrors.Wrapf(types.ErrSendDisabled, "%s transfers are currently disabled", coin.Denom)
		}
	}
	return nil
}

func (k BaseSendKeeper) SendCoinsAndWei(ctx sdk.Context, from sdk.AccAddress, to sdk.AccAddress, amt sdk.Int, wei sdk.Int) error {
	if err := k.SubWei(ctx, from, wei); err != nil {
		return err
	}
	if err := k.AddWei(ctx, to, wei); err != nil {
		return err
	}
	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.EventTypeWeiTransfer,
			sdk.NewAttribute(types.AttributeKeyRecipient, to.String()),
			sdk.NewAttribute(types.AttributeKeySender, from.String()),
			sdk.NewAttribute(sdk.AttributeKeyAmount, wei.String()),
		),
	})
	if amt.GT(sdk.ZeroInt()) {
		return k.SendCoinsWithoutAccCreation(ctx, from, to, sdk.NewCoins(sdk.NewCoin(sdk.MustGetBaseDenom(), amt)))
	}
	return nil
}
