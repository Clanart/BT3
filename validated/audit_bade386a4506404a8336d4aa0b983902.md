I found a direct analog in `HyperbridgeLzEndpoint.sol`. The pause mechanism is consistently applied to `send`, `onAccept`, and ERC20 transfer overrides in the `HyperFungibleToken` family, but in the LayerZero adapter contract, the `retryPayload` function — which performs the *exact same privileged action* as `onAccept` (delivering a stored cross-chain payload to an OApp via `lzReceive`) — is missing the `whenNotPaused` modifier.

### Title
Missing `whenNotPaused` on `retryPayload` allows bypassing emergency pause in `HyperbridgeLzEndpoint` - (File: sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol)

### Summary
`HyperbridgeLzEndpoint` is `Pausable`, and its `onAccept` function (the ISMP callback that delivers inbound cross-chain messages to destination OApps via `lzReceive`) correctly enforces `whenNotPaused`. However, `retryPayload`, which performs the identical delivery action for previously failed/stuck payloads, has no pause guard at all, and is explicitly documented as permissionless.

### Finding Description
`onAccept` calls `ILayerZeroReceiver(receiverAddr).lzReceive(...)` and is gated by `whenNotPaused`: [1](#0-0) 

`retryPayload` performs the same `lzReceive` delivery for stuck inbound payloads, but omits `whenNotPaused` and is callable by anyone: [2](#0-1) 

The `pause()`/`unpause()` functions are intended to halt all cross-chain message delivery in an emergency: [3](#0-2) 

Because `retryPayload` reads directly from `_inboundPayloadHashes` and calls `lzReceive` on the target OApp without checking `paused()`, any payload that failed delivery and was retained via `onAccept`'s catch block can still be forced through by any caller even while the endpoint is paused. This mirrors the reported `LockZap.zapAlternateAsset` bug exactly: one code path that performs the sensitive state-changing action (`onAccept`) is correctly protected, while a second, functionally equivalent path (`retryPayload`) that reaches the same execution effect is not.

### Impact Explanation
If the owner pauses the endpoint in response to a discovered issue (e.g., a malicious or buggy OApp `lzReceive` implementation, a bad payload queued from a compromised or misbehaving peer, or a bug requiring an emergency freeze of all cross-chain delivery), an unprivileged actor can still call `retryPayload` to force execution of any already-stored inbound payload. This defeats the purpose of the pause and allows unauthorized execution/fund-moving side effects on the destination OApp during what is meant to be a fully halted state — matching the "unauthorized transaction or execution" and "logic attacks" categories in the impact gate.

### Likelihood Explanation
The path requires no privileged role, malicious relayer, or governance actor: any address can call `retryPayload` for any `(receiver, origin, guid, message)` combination whose hash matches an already-stored (previously failed) inbound payload. The precondition — a payload existing in `_inboundPayloadHashes` — is a normal, expected operational state (any `lzReceive` revert during `onAccept` creates one), not an attacker-engineered condition, so this is straightforward to trigger the moment the contract is paused while such a payload exists.

### Recommendation
Add the `whenNotPaused` modifier to `retryPayload` (and consider whether `skip`, `nilify`, and `burn` should also respect the pause state, depending on intended emergency semantics), so that no inbound message delivery can occur once the contract has been paused.

### Proof of Concept
1. An OApp's `lzReceive` reverts during a normal inbound delivery; `onAccept` catches this and stores the payload hash, emitting `InboundPayloadStored`.
2. The owner discovers a critical issue and calls `pause()`.
3. An attacker (or any user) calls `retryPayload(receiver, origin, guid, message)` with the matching stored payload — this succeeds because `retryPayload` has no `whenNotPaused` check, executing `lzReceive` on the destination OApp despite the pause.
4. Cross-chain message delivery/execution proceeds even though the protocol operator believed all delivery was halted.

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        // Verify source is this adapter on another chain
        if (keccak256(request.from) != keccak256(abi.encodePacked(address(this)))) revert UnknownSource();

        // Decode the LZ message from the ISMP body
        (
            bytes32 guid,
            uint32 srcEid,
            bytes32 sender,
            uint64 nonce,
            bytes32 receiver,
            bytes memory message
        ) = abi.decode(request.body, (bytes32, uint32, bytes32, uint64, bytes32, bytes));

        // Reject `expectedEid == 0` so unconfigured sources don't collide with `srcEid = 0`.
        uint32 expectedEid = _stateMachineToEid[keccak256(request.source)];
        if (expectedEid == 0 || expectedEid != srcEid) revert UnknownSource();

        // Validate and advance the nonce. The nonce is committed BEFORE (and independently of)
        // OApp execution: a reverting `lzReceive` must not roll back this write. Otherwise the
        // message would be retried forever at the same nonce and every later nonce would be
        // permanently rejected, bricking the (receiver, srcEid, sender) channel.
        address receiverAddr = address(uint160(uint256(receiver)));
        uint64 expectedNonce = _inboundNonce[receiverAddr][srcEid][sender] + 1;
        if (nonce != expectedNonce) revert InvalidNonce(expectedNonce, nonce);
        _inboundNonce[receiverAddr][srcEid][sender] = nonce;

        // Deliver to the OApp. Isolate the external call so a deterministic revert (zero
        // recipient, over-cap mint, blocklisted recipient, malformed payload, paused OApp, etc.)
        // does not revert `onAccept`. On failure the payload is retained for later retry/recovery
        // via retryPayload/clear/skip/nilify/burn.
        Origin memory origin = Origin({srcEid: srcEid, sender: sender, nonce: nonce});
        try ILayerZeroReceiver(receiverAddr).lzReceive(origin, guid, message, address(0), "") {
            // delivered successfully
        } catch {
            bytes32 payloadHash = keccak256(abi.encode(guid, message));
            _inboundPayloadHashes[receiverAddr][srcEid][sender][nonce] = payloadHash;
            emit InboundPayloadStored(receiverAddr, srcEid, sender, nonce, payloadHash);
        }
    }

     * @notice Retries an inbound delivery whose OApp `lzReceive` previously reverted in {onAccept}.
     * @dev Mirrors {onAccept}'s direct call to the OApp (the adapter is the caller, so the OApp's
     * `onlyEndpoint` check still passes). Permissionless: anyone may push a stuck payload through
     * once it is executable again. On success the stored payload hash is cleared; if delivery
     * reverts again the whole call reverts and the payload remains recoverable.
     * @param receiver The destination OApp
     * @param origin The (srcEid, sender, nonce) of the stored payload
     * @param guid The original message guid
     * @param message The original message payload (must match the stored hash)
     */
    function retryPayload(
        address receiver,
        Origin calldata origin,
        bytes32 guid,
        bytes calldata message
    ) external payable {
        bytes32 stored = _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];
        if (stored == bytes32(0) || stored == NIL_PAYLOAD_HASH || stored != keccak256(abi.encode(guid, message))) {
            revert InvalidPayloadHash();
        }

        // Clear first; if the retry reverts, this deletion rolls back with the rest of the tx and
        // the payload remains recoverable.
        delete _inboundPayloadHashes[receiver][origin.srcEid][origin.sender][origin.nonce];

        ILayerZeroReceiver(receiver).lzReceive{value: msg.value}(origin, guid, message, msg.sender, "");
        emit InboundPayloadResolved(receiver, origin.srcEid, origin.sender, origin.nonce);
    }
