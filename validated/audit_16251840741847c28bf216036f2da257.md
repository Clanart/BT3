## Finding: Unvalidated/Unescaped DID Metadata Decoding Causes Wallet-Sync Crash on Malicious DID Transfer

The mistune report describes a pattern where a value pulled directly from untrusted input is threaded through a serialization/formatting function with no validation or escaping, and the resulting malformed value breaks a downstream consumer. The reachable analog in chia-blockchain is `did_program_to_metadata()`, which decodes attacker-controlled on-chain bytes as UTF-8 with no error handling, in a code path that a normal wallet reaches automatically when it receives a DID coin. [1](#0-0) 

### Title
Unhandled `UnicodeDecodeError` in DID metadata decoding halts wallet sync on receipt of a crafted DID coin - (File: `chia/wallet/did_wallet/did_wallet_puzzles.py`)

### Summary
`did_program_to_metadata()` converts the curried `metadata` argument of a DID inner puzzle into a `dict[str, str]` by calling `str(key, "utf-8")` / `str(val, "utf-8")` on each key/value atom with no `errors="strict"` handling, no length checks, and no `try/except`. The metadata `Program` is fully attacker-controlled: it comes straight from whatever puzzle reveal an attacker curries when creating or spending a DID coin. This function is invoked directly (uncaught) from `DIDWallet.coin_added()` and `WalletStateManager.find_lost_did()` whenever a wallet's sync logic determines that an incoming DID coin belongs to it. [2](#0-1) [3](#0-2) 

### Finding Description
`did_program_to_metadata` decodes raw bytes from an untrusted, attacker-supplied `Program` with strict UTF-8 decoding and no fallback:
```python
def did_program_to_metadata(program: Program) -> dict[str, str]:
    metadata = {}
    for key, val in program.as_python():
        metadata[str(key, "utf-8")] = str(val, "utf-8")
    return metadata
``` [1](#0-0) 

This contrasts with the CAT-memo decoding path elsewhere in the codebase, which explicitly wraps the same kind of decode in `try/except UnicodeError` and treats failure as a benign empty string:
```python
try:
    memo = condition[3][1].decode("utf-8", errors="strict")
except UnicodeError:
    pass  # ignore this error which should leave memo as empty string
``` [4](#0-3) 

The DID metadata path has no such guard. It is called from `DIDWallet.coin_added()`, the callback invoked by `WalletStateManager` whenever a DID coin's puzzle is uncurried and resolved to belong to a wallet the user controls:
```python
new_info = DIDInfo(
    ...
    metadata=json.dumps(did_wallet_puzzles.did_program_to_metadata(did_data.metadata)),
)
await self.save_info(new_info)
``` [5](#0-4) 

`did_data.metadata` originates from `match_did_puzzle()` uncurrying the on-chain puzzle reveal of whatever coin was received — this is fully controlled by whoever created/spent the DID coin, not by the receiving wallet:
```python
did_curried_args = match_did_puzzle(uncurried.mod, Program.to(uncurried.curried_args))
...
p2_puzzle, recovery_list_hash, num_verification, _, metadata = did_curried_args
did_data: DIDCoinData = DIDCoinData(p2_puzzle, ..., metadata, ...)
``` [6](#0-5) 

The same unguarded call also exists in `WalletStateManager.find_lost_did()`, which similarly decodes attacker-supplied on-chain metadata during DID recovery. [3](#0-2) 

An attacker can curry a DID inner puzzle (`DID_INNERPUZ_MOD.curry(...)`) directly with a `metadata` `Program` containing key/value atoms that are not valid UTF-8 (e.g., a lone continuation byte such as `0x80`), then send that DID coin (with the usual create-coin hint) to a victim address — a completely ordinary wallet-to-wallet transfer that any unprivileged spend-bundle submitter can construct. `Program.to()`/CLVM place no constraint that curried atoms be valid text.

### Impact Explanation
When the victim wallet syncs and identifies the incoming coin as belonging to it, `did_program_to_metadata()` raises an uncaught `UnicodeDecodeError`. This propagates out of `coin_added()`/`find_lost_did()` into the wallet's coin-state processing loop (`_add_coin_state` / `determine_coin_type`), which is not defensively wrapped for this exception. This is a spend-triggered halt of wallet transaction/coin-state processing: a single malicious, unsigned-nothing-special DID transfer can stop a targeted wallet's sync pipeline from advancing, since the offending coin state will keep being reprocessed on every sync attempt.

### Likelihood Explanation
High reachability: creating and sending a DID coin with an arbitrary curried metadata program requires no special privileges — any wallet user or spend-bundle submitter can do it, and DID transfers are a standard, expected operation (e.g., via offers, wallet-to-wallet sends, or NFT/DID interactions). No cooperation is needed from the victim beyond accepting a DID coin sent to one of their derived addresses, which is normal wallet behavior.

### Recommendation
Wrap `did_program_to_metadata()`'s decode calls in `try/except (UnicodeDecodeError, ValueError)`, mirroring the existing pattern used for CAT memo decoding, and treat malformed keys/values as skipped or replaced with a safe placeholder rather than raising. Additionally, guard callers (`coin_added`, `find_lost_did`, `manual_did_search`) so a metadata-parsing failure cannot abort wallet sync/coin-state processing for the entire batch.

### Proof of Concept
1. Attacker builds a DID inner puzzle via `did_wallet_puzzles.create_innerpuz(..., metadata=Program.to([(b"\x80", b"\x80")]))` — the key/value bytes are not valid UTF-8. [7](#0-6) 
2. Attacker creates/spends this DID coin normally (standard DID mint/spend flow) and sends it (with hint) to a victim's puzzle hash.
3. Victim's `WalletStateManager` syncs the new coin, resolves ownership via `determine_coin_type`/`DIDWallet.identify`, and calls `DIDWallet.coin_added()`. [8](#0-7) 
4. `coin_added()` calls `did_wallet_puzzles.did_program_to_metadata(did_data.metadata)`, which executes `str(b"\x80", "utf-8")`, raising `UnicodeDecodeError` uncaught, halting that portion of wallet sync. [2](#0-1)

def create_innerpuz(
    p2_puzzle_or_hash: Program | bytes32,
    recovery_list: list[bytes32],
    num_of_backup_ids_needed: uint64,
    launcher_id: bytes32,
    metadata: Program = Program.to([]),
    recovery_list_hash: Program | None = None,
) -> Program:
    """
    Create DID inner puzzle
    :param p2_puzzle_or_hash: Standard P2 puzzle or hash
    :param recovery_list: A list of DIDs used for the recovery
    :param num_of_backup_ids_needed: Need how many DIDs for the recovery
    :param launcher_id: ID of the launch coin
    :param metadata: DID customized metadata
    :param recovery_list_hash: Recovery list hash
    :return: DID inner puzzle
    Note: Receiving a standard P2 puzzle hash wouldn't calculate a valid puzzle, but
    that can be useful if calling `.get_tree_hash_precalc()` on it.
    """
    backup_ids_hash: Program | bytes32 = Program.to(recovery_list).get_tree_hash()
    if recovery_list_hash is not None:
        backup_ids_hash = recovery_list_hash
    singleton_struct = Program.to((SINGLETON_TOP_LAYER_MOD_HASH, (launcher_id, SINGLETON_LAUNCHER_PUZZLE_HASH)))
    return DID_INNERPUZ_MOD.curry(
        p2_puzzle_or_hash, backup_ids_hash, num_of_backup_ids_needed, singleton_struct, metadata
    )
```
