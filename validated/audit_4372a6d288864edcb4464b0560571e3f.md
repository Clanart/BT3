## Answer

Valid vulnerability. Tag names that reach `tagsToPush` are never validated against the ref-name-sanitization logic that already exists in the codebase, and they are spliced verbatim into `git push`'s argv, allowing an attacker-controlled ref name to be interpreted as a flag instead of a refspec.

### Title
Argument/flag injection into `git push` via unsanitized tag names in `tags-to-push-storage.ts` / `push.ts`

### Summary
`getAllTags()` in [1](#0-0)  derives local tag names by parsing raw `git show-ref --tags -d` output with only a `refs/tags/` prefix strip and a `^{}` suffix strip — no character-set validation is applied. `fetchTagsToPush()` similarly extracts tag names straight from `git push --dry-run --porcelain` output [2](#0-1) . These names are persisted verbatim by `storeTagsToPush()` and returned verbatim by `getTagsToPush()` [3](#0-2) , and finally consumed by `push()`, which appends them directly into the `git push` argv with `args.push(...tagsToPush)` [4](#0-3) , with no `--` refspec terminator separating them from potential option flags.

Git's own ref-name grammar (`git-check-ref-format`) does not forbid a ref/tag name from starting with a hyphen — the project's own `sanitize-ref-name.ts` acknowledges this class of risk by explicitly stripping leading `-`/`+` characters from user-typed ref names: [5](#0-4) . However, that sanitizer is only applied to names typed by the user through Desktop's own "create tag" UI flow (`createTag`), not to tag names that already exist in the repository because they were fetched/cloned from a remote. A tag such as `--upload-pack=/tmp/evil` or `--receive-pack=/tmp/evil` is a syntactically legal git ref and can be shipped by a malicious remote.

### Impact Explanation
If such a tag is present locally (via clone/fetch from an attacker-controlled remote or fork) and Desktop's automatic "unpushed tags" detection (`fetchTagsToPush`, wired through `git-store.ts` and the tags-to-push storage helpers) queues it into `tagsToPush`, the next `push()` call inserts the raw string as an argv token to `git push`. Because there is no `--` separator before the tag arguments in `push.ts`, git will parse a leading-dash string as an option rather than a refspec. Options like `--receive-pack=<path>` instruct git which program to invoke as the "remote" receive-pack process (relevant for local/file and some ssh transports), which is a known argument-injection-to-RCE vector in the same family as CVE-2017-1000117. This can result in arbitrary command execution on the user's machine during a push.

### Likelihood Explanation
Requires that (a) a malicious/compromised remote ships a tag with a crafted name, (b) the user clones/fetches that repository in Desktop, and (c) Desktop's tag auto-push detection queues the malicious tag for push (or the user pushes with that tag already staged). All three conditions are within scope (attacker controls fetched repository content) and do not require local access, admin rights, or leaked credentials. The exact automatic-queueing trigger path (which caller populates `_tagsToPush` from `fetchTagsToPush` results without going through the UI's `sanitizedRefName` check) could not be fully traced within available tool iterations, so likelihood should be validated by confirming that code path in `app/src/lib/stores/git-store.ts`.

### Recommendation
- Validate/sanitize every tag name before it is stored via `storeTagsToPush` and before it is spliced into `git push` argv, rejecting or escaping names beginning with `-`.
- Insert an explicit `--` separator in `push.ts` between the branch refspec/tag list and any subsequent flags, e.g. `args.push(...tagsToPush, '--')`, so git never interprets a ref-like argument as an option.
- Apply the existing `testForInvalidChars`/`sanitizedRefName` (or a push-safe variant that also rejects leading dashes) uniformly to all tag names sourced from git output (`getAllTags`, `fetchTagsToPush`), not just to user-typed names in the tag-creation UI.

### Proof of Concept
1. Set up a malicious remote repository containing a tag literally named `--upload-pack=/tmp/evil` (a valid git ref).
2. Clone/fetch this repository with GitHub Desktop.
3. Trigger a scenario where Desktop queues that tag for push (e.g., via `fetchTagsToPush` detecting it as an unpushed tag after a branch push, or having it queued in `tagsToPush` state) and call `storeTagsToPush`/`getTagsToPush` to confirm the string is round-tripped unmodified.
4. Trigger `push()` and assert that the spawned `git` process receives `--upload-pack=/tmp/evil` (or `--receive-pack=/tmp/evil`) as a literal argv flag rather than a tag refspec, per [6](#0-5) .

export async function getAllTags(
  repository: Repository
): Promise<Map<string, string>> {
  const args = ['show-ref', '--tags', '-d']

  const tags = await git(args, repository.path, 'getAllTags', {
    successExitCodes: new Set([0, 1]), // when there are no tags, git exits with 1.
  })

  const tagsArray: Array<[string, string]> = tags.stdout
    .split('\n')
    .filter(line => line !== '')
    .map(line => {
      const [commitSha, rawTagName] = line.split(' ')

      // Normalize tag names by removing the leading ref/tags/ and the trailing ^{}.
      //
      // git show-ref returns two entries for annotated tags:
      // deadbeef refs/tags/annotated-tag
      // de510b99 refs/tags/annotated-tag^{}
      //
      // The first entry sha correspond to the blob object of the annotation, while the second
      // entry corresponds to the actual commit where the tag was created.
      // By normalizing the tag name we can make sure that the commit sha gets stored in the returned
      // Map of commits (since git will always print the entry with the commit sha at the end).
      const tagName = rawTagName
        .replace(/^refs\/tags\//, '')
        .replace(/\^\{\}$/, '')

      return [tagName, commitSha]
    })

  return new Map(tagsArray)
}

export async function fetchTagsToPush(
  repository: Repository,
  remote: IRemote,
  branchName: string
): Promise<ReadonlyArray<string>> {
  const args = [
    'push',
    remote.name,
    branchName,
    '--follow-tags',
    '--dry-run',
    '--no-verify',
    '--porcelain',
  ]

  const result = await git(args, repository.path, 'fetchTagsToPush', {
    env: await envForRemoteOperation(remote.url),
    successExitCodes: new Set([0, 1, 128]),
  })

  if (result.exitCode !== 0 && result.exitCode !== 1) {
    // Only when the exit code of git is 0 or 1, its stdout is parseable.
    // In other cases, we just rethrow the error so our memoization layer
    // doesn't cache it indefinitely.
    throw result.gitError
  }

  const lines = result.stdout.split('\n')
  let currentLine = 1
  const unpushedTags = []

  // the last line of this porcelain command is always 'Done'
  while (currentLine < lines.length && lines[currentLine] !== 'Done') {
    const line = lines[currentLine]
    const parts = line.split('\t')

    if (parts[0] === '*' && parts[2] === '[new tag]') {
      const [tagName] = parts[1].split(':')

      if (tagName !== undefined) {
        unpushedTags.push(tagName.replace(/^refs\/tags\//, ''))
      }
    }

    currentLine++
  }

  return unpushedTags
}

export function storeTagsToPush(
  repository: Repository,
  tagsToPush: ReadonlyArray<string>
) {
  if (tagsToPush.length === 0) {
    clearTagsToPush(repository)
  } else {
    setStringArray(getTagsToPushKey(repository), tagsToPush)
  }
}

/**
 * Get from local storage the tags to push for the given repository
 *
 * @param repository the repository object
 */
export function getTagsToPush(repository: Repository) {
  return getStringArray(getTagsToPushKey(repository))
}

const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}
