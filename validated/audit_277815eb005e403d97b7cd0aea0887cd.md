### Title
NULL/Type-Assertion Panic in Pointer Precompile via Malicious CW20/CW721/CW1155 Query Response - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query an attacker-controlled CosmWasm contract and then perform unchecked Go type assertions (`.(string)`) on the JSON response fields `name`/`symbol` without verifying they exist or are strings, mirroring the CVE-2023-49275 pattern of dereferencing an object field fetched from external input without a NULL/type check.

### Finding Description
`AddCW20` calls `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))` against a caller-supplied CosmWasm address, unmarshals the raw response into `map[string]interface{}{}`, then does: [1](#0-0) 
The same unchecked pattern exists in `AddCW721` and `AddCW1155`: [2](#0-1) [3](#0-2) 

In Go, a non-comma-ok type assertion `v.(string)` panics if `v` is `nil` (missing key returns `nil` from the map) or is any non-string JSON type (number, bool, object, array). Since `cwAddr` is a fully attacker-controlled bech32 address (any deployed CosmWasm contract, including one crafted purely to respond to `token_info`/`contract_info` queries with a JSON object omitting `name`/`symbol` or using non-string values), any EVM caller (contract or EOA) can trigger this panic by invoking `addCW20Pointer`, `addCW721Pointer`, or `addCW1155Pointer` with the address of such a contract.

Tracing the call path: `DynamicGasPrecompile.RunAndCalculateGas` (`precompiles/common/precompiles.go:156-215`) invokes `d.executor.Execute(...)` directly with no `recover()` wrapping that call — only `chargeDecodeGas` has a narrowly-scoped recover limited to gas-meter panics: [4](#0-3) 
A panic from the type assertion therefore propagates up out of the precompile into the EVM's `vm.Call`/message execution and further up the Cosmos SDK message-handling stack.

### Impact Explanation
Whether this crashes the node depends on which execution path processes the transaction. The legacy/V2 delivery path (`app/legacyabci/deliver_tx.go`) and the giga executor (`app/app.go` `makeGigaDeliverTx`/`ProcessTxsSynchronousGiga`) both install `recover()` around per-transaction execution and convert unexpected panics into an `ErrPanic`/`Codespace` ABCI response rather than crashing the node: [5](#0-4) [6](#0-5) 
Because these recovery layers exist above the precompile, a single malicious `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` call likely results in a failed/reverted transaction (with an `ErrPanic` code) rather than a validator crash or chain halt — this significantly reduces severity relative to the original wazuh advisory's unrecovered `analysisd` crash. I could not verify from the available index whether every possible caller of this precompile (e.g., `eth_call`/`eth_estimateGas` JSON-RPC simulation paths, ante-handler-level static calls, or any tracer/query path that invokes precompiles outside the recovered `DeliverTx`/giga executor wrappers) also has panic recovery; if such a path exists without a `recover()`, it could crash a public RPC node process on `eth_call`, which would meet the "crash of default-configuration RPC nodes" bar in the validation rules.

### Likelihood Explanation
Trivial to trigger: any address can deploy a CosmWasm contract that responds to `token_info`/`contract_info` queries with a JSON object lacking `name`/`symbol` string fields (or deploy no such contract and instead target an existing wasm contract with a compatible but malformed response), then call the `pointer` precompile at `0x000000000000000000000000000000000000100b` with `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` and that address as argument. No special privileges are required.

### Recommendation
Replace the unchecked type assertions with the comma-ok form and return an error instead of panicking, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract response missing string \"name\" field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract response missing string \"symbol\" field")
}
```
Apply this fix in all three handlers (`AddCW20`, `AddCW721`, `AddCW1155`) in `precompiles/pointer/pointer.go`, and audit legacy pointer precompile versions (`precompiles/pointer/legacy/v552` through `v67`) which contain the identical pattern, in case they remain reachable via any activation-height/upgrade-handler dispatch. Additionally, confirm and, if missing, add a `recover()` boundary around any precompile invocation path used by `eth_call`/`eth_estimateGas`/JSON-RPC simulation that is not already covered by the `DeliverTx`/giga-executor panic recovery, so a malformed CW contract response cannot crash a public RPC node.

### Proof of Concept
1. Deploy (or identify) a CosmWasm contract at address `cwAddr` that responds to the smart query `{"token_info":{}}` (for CW20) or `{"contract_info":{}}` (for CW721/CW1155) with a JSON object that omits the `name`/`symbol` keys, e.g. `{}`.
2. From an EVM account, call the `pointer` precompile (`0x000000000000000000000000000000000000100b`) method `addCW20Pointer(string cwAddr)` with `cwAddr` set to the contract's bech32 address.
3. Execution reaches `AddCW20` in `precompiles/pointer/pointer.go:134-164`; `p.wasmdKeeper.QuerySmartSafe` succeeds and returns `{}`; `formattedRes["name"].(string)` panics with `interface conversion: interface {} is nil, not string`.
4. Observe the transaction result: depending on the execution path, this either surfaces as an `ErrPanic`-coded failed transaction (recovered path) or, if invoked through an unrecovered code path (e.g. certain `eth_call`/query paths not covered by the `DeliverTx`/giga executor recovery), causes a runtime panic in the serving process — this latter case would need direct confirmation against the live RPC/query call stack, which was not fully traceable from the indexed code.
