### Title
Automatic branch fast-forwarding silently incorporates attacker-supplied commits from any remote into local branches - ([File: app/src/lib/stores/app-store.ts])

### Summary
The Balancer report's underlying flaw is that `finalize()`/`returnFunds()` acts on whatever pool state exists at execution time, with no way for the caller to pin/verify an expected outcome, letting an attacker who can influence pool state between decision and execution corrupt what the caller receives. The Desktop analog is `AppStore.fastForwardBranches()`, invoked from `performPull` and `performFetch` (including unattended background fetches), which silently fast-forwards *every* local branch that has diverged from its upstream — not just the currently checked-out branch — using data supplied by whatever remote is configured, with no user review, confirmation, or SHA pinning.

### Finding Description
`getBranchesDifferingFromUpstream()` [1](#0-0)  enumerates all local branches with an upstream and compares their SHA against the corresponding remote-tracking ref SHA, excluding only the currently checked-out branch. The resulting list is passed to `fastForwardBranches()` [2](#0-1) , which runs `git fetch . --stdin` with refspecs of the form `${upstreamRef}:${ref}`, directly moving each local branch ref to match the remote-tracking branch.

This is invoked unconditionally after both user-initiated pulls/fetches and unattended background fetches in `AppStore.performPull` and `AppStore.performFetch`: [3](#0-2)  and the private helper [4](#0-3) . There is no gating on `fetchType` (`FetchType.BackgroundTask` vs `FetchType.UserInitiatedTask`), no diff shown to the user, and no confirmation dialog — the update happens as a side effect of what looks like a routine, harmless "refresh."

The broken invariant mirrors the report exactly: the operation trusts the *current* state of an external, attacker-influenceable source (a git remote) at execution time instead of anything the user actually reviewed. If the remote (e.g., a compromised or malicious `origin`, or an added fork remote) has had commits pushed to any branch that a local branch tracks, the next fetch — even a silent, periodic background fetch the user never triggered — will fast-forward the local branch to include those attacker commits, with no warning.

### Impact Explanation
This produces "silent corruption of what the user commits or pushes": if the user later checks out the affected branch and continues work, any subsequent commit is built on top of attacker-supplied history, and a push will carry that attacker content into the remote history the user believes they authored/reviewed. Because the update happens to branches other than the one currently checked out, the user has no visual cue (no diff, no changed-files indicator) that the branch content changed at all — they would discover it only by manually inspecting history after the fact. Existing guards do not stop this path: `getBranchesDifferingFromUpstream` explicitly *includes* any branch with an upstream (excluding only the current branch) as "eligible," and `fastForwardBranches` performs the update without prompting; none of `_checkoutBranch`, `_checkoutCommit`, or `_pull`/`_fetch` verify or surface the resulting SHA to the user before or after the operation.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to have push access to a remote that a victim's local branch tracks (a compromised/malicious `origin`, an org member with push rights, or a fork remote added for PR review per `docs/technical/pull-requests.md`). No local access, admin rights, or social engineering beyond normal collaboration is required — a background fetch runs periodically regardless of user action [5](#0-4) , so the attacker doesn't even need the victim to manually pull.

### Recommendation
- Do not silently fast-forward non-current local branches without confirmation, or at minimum surface a notification summarizing which branches changed and to what SHAs.
- Restrict automatic fast-forwarding to branches whose upstream is a trusted/verified remote, or require it to be opt-in per remote.
- When fast-forwarding occurs, log/display the before/after SHA so the change is auditable, analogous to allowing the "caller to specify and enforce the minimum/expected value" recommended in the original report.

### Proof of Concept
1. Victim clones a repository and has a local branch `feature` tracking `origin/feature`, while currently checked out on `main`.
2. Attacker (owner or collaborator with push rights on the remote referenced by `origin`, or a fork remote added via PR checkout flow) pushes new commits to `feature` on the remote.
3. Desktop's periodic background fetch fires (`FetchType.BackgroundTask`), calling `performFetch` → `fastForwardBranches` [6](#0-5) , which calls `getBranchesDifferingFromUpstream` and then `fastForwardBranches(repository, eligibleBranches)` [7](#0-6) .
4. The victim's local `feature` ref silently moves to the attacker's new commits, with no dialog or diff shown.
5. Victim later checks out `feature`, adds a commit, and pushes — propagating the attacker's injected commits as part of what appears to be the victim's own push, with no indication anything was altered underneath them.

export async function getBranchesDifferingFromUpstream(
  repository: Repository
): Promise<ReadonlyArray<ITrackingBranch>> {
  const { formatArgs, parse } = createForEachRefParser({
    fullName: '%(refname)',
    sha: '%(objectname)', // SHA
    upstream: '%(upstream)',
    symref: '%(symref)',
    head: '%(HEAD)',
  })

  const prefixes = ['refs/heads', 'refs/remotes']

  const result = await git(
    ['for-each-ref', ...formatArgs, ...prefixes],
    repository.path,
    'getBranchesDifferingFromUpstream',
    { expectedErrors: new Set([GitError.NotAGitRepository]) }
  )

  if (result.gitError === GitError.NotAGitRepository) {
    return []
  }

  const localBranches = []
  const remoteBranchShas = new Map<string, string>()

  // First we need to collect the relevant info from the command output:
  // - For local branches with upstream: name, ref, SHA and the upstream.
  // - For remote branches we only need the sha (and the ref as key).
  for (const ref of parse(result.stdout)) {
    if (ref.symref.length > 0 || ref.head === '*') {
      // Exclude symbolic refs and the current branch
      continue
    }

    if (ref.fullName.startsWith('refs/heads')) {
      if (ref.upstream.length === 0) {
        // Exclude local branches without upstream
        continue
      }

      localBranches.push({
        ref: ref.fullName,
        sha: ref.sha,
        upstream: ref.upstream,
      })
    } else {
      remoteBranchShas.set(ref.fullName, ref.sha)
    }
  }

export async function fastForwardBranches(
  repository: Repository,
  branches: ReadonlyArray<ITrackingBranch>
): Promise<void> {
  if (branches.length === 0) {
    return
  }

  const refPairs = branches.map(branch => `${branch.upstreamRef}:${branch.ref}`)

  await git(
    [
      'fetch',
      '.',
      // Make sure we don't try to update branches that can't be fast-forwarded
      // even if the user disabled this via the git config option
      // `fetch.showForcedUpdates`
      '--show-forced-updates',
      // Prevent `git fetch` from touching the `FETCH_HEAD`
      '--no-write-fetch-head',
      // Take branch refs from stdin to circumvent shell max line length
      // limitations (mainly on Windows)
      '--stdin',
    ],
    repository.path,
    'fastForwardBranches',
    {
      // Fetch exits with an exit code of 1 if one or more refs failed to update
      // which is what we expect will happen
      successExitCodes: new Set([0, 1]),
      env: {
        // This will make sure the reflog entries are correct after
        // fast-forwarding the branches.
        GIT_REFLOG_ACTION: 'pull',
      },
      stdin: refPairs.join('\n'),
    }
  )
}
