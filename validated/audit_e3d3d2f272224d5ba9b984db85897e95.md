### Title
Attacker-fabricated `ReceivedOutput` injects phantom inputs into the Bitcoin wallet signing path — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes a scalar offset, a `TxOut`, and an `OutPoint` purely from the byte stream, with no binding to any actual chain data. The only consistency check downstream is in `SignableTransaction::multisig`, which verifies that `output.script_pubkey` equals the P2TR script of `group_key + offset*G` — a value any unprivileged party can compute from the public group key. This is the analog of CVE-2023-34059's file-descriptor hijack: an attacker substitutes the "input descriptor" the trusted component operates on, causing it to treat fabricated data as a genuine spendable output.

### Finding Description
`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F`, then consensus-decodes `output` (`TxOut`) and `outpoint` (`OutPoint`) — all attacker-controlled — and returns them as a spendable output [1](#0-0) .

`Scanner::scan_transaction` is the intended producer of `ReceivedOutput` and gets the outpoint/value from real blocks [2](#0-1) , but nothing in the type distinguishes scanned from deserialized outputs.

The sole validation is in `multisig`: `p2tr_script_buf(offset.group_key()) != self.prevouts[i].script_pubkey` causes rejection [3](#0-2) . Since `offset` and `script_pubkey` both come from the same untrusted buffer, an attacker simply sets `script_pubkey = p2tr(group_key + G*offset)` — computable from the public group key — and the check passes for *any* fabricated `outpoint` and *any* fabricated `value`.

`SignableTransaction::new` then trusts `input.output.value` for the funds sufficiency check (`input_sat < payment_sat + needed_fee`) and for computing change (`input_sat - payment_sat - fee_with_change`) [4](#0-3) , and `sign` commits to the attacker-supplied prevout values via `Prevouts::All` [5](#0-4) .

### Impact Explanation
A fabricated `ReceivedOutput` claiming a nonexistent or already-spent `outpoint` is reported and consumed as spendable funds. Downstream effects:

- **Phantom balance / unspendable funds:** the system treats attacker-invented UTXOs as inputs, satisfying `NotEnoughFunds` with value that does not exist.
- **Invalid threshold signature (burned signing round):** because BIP-341 commits to all prevout amounts, a forged `TxOut.value` makes the produced Schnorr signature invalid on-chain; the group completes a full FROST signing ceremony producing an unbroadcastable transaction.
- **Value manipulation:** an attacker can inflate `value` on a *real* group UTXO outpoint to drive `fee()`/`change` math to arbitrary outcomes (e.g., oversized change output or fee), again yielding an invalid transaction after a real signing round.

This maps to the accepted impact of "funds reported received that are not spendable" plus coerced signing of an attacker-influenced sighash.

### Likelihood Explanation
Reachable wherever serialized `ReceivedOutput`/`Output` bytes cross a trust boundary — the processor's output deserialization (`Output::read` embeds `ReceivedOutput::read` [6](#0-5) ) consumes stored/transmitted output bytes that an unprivileged party can influence, and the constructor performs no on-chain existence or amount check. Exploitation requires only public knowledge of the group key. It does not yield key recovery or forge a valid signature on a *valid* transaction, so the impact is bounded to phantom-fund accounting and invalid-transaction signing (Medium).

### Recommendation
Bind `ReceivedOutput` to chain reality before use: record the block/tx source at scan time and re-verify the `outpoint`'s actual `TxOut` (value and script_pubkey) via RPC or an SPV proof before admitting it into `SignableTransaction::new`; alternatively, carry a witness of provenance in the type (e.g., only construct `ReceivedOutput` via `Scanner` and make `read` produce an `UnverifiedReceivedOutput` that must be confirmed against the chain).

// Attacker knows only the public group key `key` (e.g., from a public address).
let offset = Scalar::ONE; // arbitrary
let script = p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset).unwrap();

// Fabricate a ReceivedOutput: nonexistent outpoint, 21 BTC of fake value.
let fake = ReceivedOutput::read::<&[u8]>(&mut {
    let mut b = offset.to_bytes().to_vec();
    b.extend(serialize(&TxOut { value: Amount::from_sat(2_100_000_000), script_pubkey: script }));
    b.extend(serialize(&OutPoint::new(Txid::from_byte_array([0xAA; 32]), 0)));
    b
}.as_ref()).unwrap();

// Passes all validation; multisig() accepts since script matches derived key.
// SignableTransaction::new treats the phantom 2.1 BTC as spendable input.
let tx = SignableTransaction::new(vec![fake], &payments, Some(change), None, fee).unwrap();
// The group signs a tx spending a nonexistent outpoint -> unbroadcastable,
// and any change computation was driven by the fabricated value.

    let offset = Secp256k1::read_F(r)?;
    let output;

      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
