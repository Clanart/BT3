### Title
Unbounded atom-length trust in CLVM canonical-form parser causes out-of-bounds buffer access on crafted spend bundle - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py:144-227` parse the CLVM byte-serialization length-prefix of atoms in an untrusted `puzzle_reveal`/`solution` buffer to decide DEDUP/fast-forward eligibility for a submitted spend bundle. Like `JBIG2Stream::readGenericBitmap` in the CVE, which trusted an attacker-controlled dimension field to compute buffer offsets without checking it against the actual buffer size, this code trusts the atom's declared length field to advance the parse offset without ever validating that the declared length is within the bounds of the actual `clvm_buffer`.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` [1](#0-0)  decodes a variable-length atom-size prefix (1–6 bytes) purely from the header bits and returns `1 + prefix_len + atom_len` as the total atom size — it never checks that `atom_len` bytes actually exist in `clvm_buffer` beyond the header.

`is_clvm_canonical(clvm_buffer)` [2](#0-1)  then does `offset += atom_len` (line 221) using that unchecked value and loops back to `b = clvm_buffer[offset]` (line 199) on the next iteration. If a submitter crafts a puzzle reveal or solution where an atom's length prefix claims a size far larger than the bytes remaining in the buffer, `offset` is advanced past the end of `clvm_buffer`, and the next `clvm_buffer[offset]` access goes out of bounds.

This is the direct structural analog of the xpdf bug: an attacker-supplied length/size field is trusted to compute a read position/extent without validating it against the real buffer bounds, producing an out-of-bounds access when the parser next dereferences that position. In Python this manifests as an uncaught `IndexError` rather than C++ heap corruption, but the same "attacker-controlled length field drives an out-of-bounds read" root cause is present. Note by contrast that `chia/full_node/full_block_utils.py`'s `skip_bytes()`/`skip_list()` explicitly guard `if n > len(buf): raise ValueError(...)` before consuming declared-length data [3](#0-2)  — the mempool canonical-form checker is missing this same bound check that exists elsewhere in the codebase for equivalent length-prefixed parsing.

### Impact Explanation
`is_clvm_canonical()` runs against attacker-supplied `puzzle_reveal`/`solution` bytes from any submitted spend bundle to compute DEDUP/fast-forward eligibility flags, as shown by the mempool test suite exercising both canonical and non-canonical CLVM buffers against real coin spends [4](#0-3) , including a dedicated mempool-admission test that submits non-canonical atom-length-prefix puzzle/solution bytes through `add_spend_bundle()` [5](#0-4) . An unprivileged spend-bundle submitter can reach this code path with an ordinary transaction submission. If the crafted length-prefix causes an out-of-bounds `IndexError` that isn't caught along the call chain into `add_spend_bundle`, this could crash or abort mempool processing for that bundle — a spend-triggered transaction-processing halt.

### Likelihood Explanation
Constructing a puzzle_reveal/solution atom with a length prefix claiming more bytes than are actually present is straightforward and requires no special privileges — it is exactly the shape of buffer the `test_mempool_requires_canonical_clvm` test already exercises, just with a length-prefix value large enough to overrun the buffer rather than merely being non-minimal. Likelihood is Medium: the bug class (unchecked length-prefix trust) is confirmed by direct code reading, but I was unable to confirm within available tool iterations whether an exception raised from `is_clvm_canonical()` is caught by an enclosing `try/except` somewhere in the `add_spend_bundle`/eligibility-computation call chain, which would downgrade impact to a benign rejection rather than a processing halt. This is a genuine open question that requires further tracing of the exact call sites of `is_clvm_canonical` within `MempoolManager` and its exception handling.

### Recommendation
In `is_atom_canonical()`/`is_clvm_canonical()`, validate that `atom_len` (and the multi-byte prefix bytes themselves) do not exceed `len(clvm_buffer) - offset` before advancing the offset, mirroring the explicit bounds checks already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`. Additionally, verify (and if necessary add) exception handling around any call site that invokes `is_clvm_canonical` on untrusted spend-bundle bytes so a malformed buffer is rejected as an ordinary validation error (`Err.INVALID_COIN_SOLUTION`) instead of raising an uncaught exception.

### Proof of Concept
Construct a `puzzle_reveal` or `solution` byte string starting with an atom-size prefix byte pattern (e.g. `0xC0`-class 2-byte prefix) that declares an atom length larger than the number of bytes actually following it in the buffer, matching the `serialized_atom_overflow`-style overflow construction used in `chia/_tests/clvm/test_chialisp_deserialization.py:12-52` [6](#0-5)  but sized so the header's declared length exceeds the remaining physical buffer instead of just being tested for CLVM-execution overflow. Submit this as a `CoinSpend`'s `puzzle_reveal`/`solution` in a `SpendBundle` via `MempoolManager.add_spend_bundle()`, following the same harness pattern as `test_mempool_requires_canonical_clvm` [7](#0-6) , and observe whether `is_clvm_canonical()` raises an unhandled `IndexError` instead of a clean `Err.INVALID_COIN_SOLUTION` rejection.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]

def serialized_atom_overflow(size: int) -> str:
    if size == 0:
        size_blob = b"\x80"
    elif size < 0x40:
        size_blob = bytes([0x80 | size])
    elif size < 0x2000:
        size_blob = bytes([0xC0 | (size >> 8), (size >> 0) & 0xFF])
    elif size < 0x100000:
        size_blob = bytes([0xE0 | (size >> 16), (size >> 8) & 0xFF, (size >> 0) & 0xFF])
    elif size < 0x8000000:
        size_blob = bytes(
            [
                0xF0 | (size >> 24),
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    elif size < 0x400000000:
        size_blob = bytes(
            [
                0xF8 | (size >> 32),
                (size >> 24) & 0xFF,
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    else:
        size_blob = bytes(
            [
                0xFC | ((size >> 40) & 0xFF),
                (size >> 32) & 0xFF,
                (size >> 24) & 0xFF,
                (size >> 16) & 0xFF,
                (size >> 8) & 0xFF,
                (size >> 0) & 0xFF,
            ]
        )
    extra_str = "01" * 1000
    return size_blob.hex() + extra_str
