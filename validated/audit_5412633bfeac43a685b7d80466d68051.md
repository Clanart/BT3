## Finding: Deep-link PR checkout resolves by branch name, not by the reviewed commit SHA (TOCTOU / front-run of the reviewed PR head)

### Title
Deep-link/PR checkout flow resolves the fork's branch tip by name instead of pinning to the reviewed commit SHA, letting a PR author silently swap in different code between review and checkout — (File: `app/src/lib/stores/app-store.ts`)

### Summary
The Sherlock report is a TOCTOU/front-run: a value is validated (address not yet blacklisted) and then, before the state-changing action executes, an attacker races to change the underlying state so the check no longer reflects reality. The equivalent broken invariant in GitHub Desktop is in the pull-request checkout path: Desktop fetches PR metadata (including a specific head SHA) from the GitHub API, but the actual `git fetch` + `checkout` operation resolves the *live branch tip by name* rather than the SHA that was reviewed/validated, and this path is reachable from an external, attacker-authored deep link.

### Finding Description
When a PR is opened (via the in-app UI or via a `x-github-client://openrepo/<url>?pr=<n>` deep link parsed in `parseAppURL`), Desktop calls `openPullRequestFromUrl`, which fetches the PR object from the API and then calls `_checkoutPullRequest`: [1](#0-0) 

`_checkoutPullRequest` / `_findPullRequestBranch` add a remote pointing at `headCloneUrl` (the PR author/fork-controlled clone URL) and then look up the branch **by ref name** (`headRefName`), fetching it if not already known, and creating a local branch tracking `${remote.name}/${headRefName}` — never comparing against `pullRequest.head.sha`: [2](#0-1) 

The PR object stored/consulted elsewhere (e.g. for the diff, commit list, and check-run/status validation shown to the user) does carry a specific head SHA: [3](#0-2) 

but the checkout logic never pins to it — it always fetches and checks out whatever the remote branch currently points to at execution time, not what the user reviewed. `changelog.json` even documents a prior, related bug class ("Potential race condition when opening a fork pull request"), confirming this code path has known timing hazards: [4](#0-3) 

### Impact Explanation
Because the head repo/branch of a pull request is entirely attacker-controlled (the PR author owns the fork and can force-push to it at any time), an attacker can:
1. Open a PR whose diff/checks look benign, or wait for reviewer approval / a shared "Open in Desktop" deep link to be sent.
2. Race to push new, malicious commits to the fork branch referenced by `headCloneUrl`/`headRefName` right before (or during) the moment the victim's Desktop client performs the fetch+checkout.
3. Desktop silently checks out the *new* branch tip rather than the previously reviewed/validated SHA, since the checkout is resolved by name, not by SHA.

This is a silent corruption of what the user actually checks out relative to what they reviewed/trusted, satisfying the "silent corruption of what the user commits or pushes"/checks-out impact bucket. If the victim then builds/runs the checked-out code (a normal workflow after "checking out a PR to test it locally"), this becomes arbitrary code execution on the victim's machine, entirely under control of an unprivileged PR author — no admin rights, no local access, no leaked credentials required.

### Likelihood Explanation
The attacker only needs to be capable of opening a pull request (or being the head of one) against a repository the victim has cloned in Desktop, and to time a push of new commits close to when the victim triggers a PR checkout (via UI or a shared deep link). This requires no special privileges and is directly analogous to the reported mempool-front-run pattern: watch for an impending trusted action and race to invalidate the assumption it was based on before it executes.

### Recommendation
Pin the PR checkout to the specific `pullRequest.head.sha` that was validated/displayed to the user, rather than resolving `headRefName` to whatever the remote branch currently points to. Concretely, after fetching the remote in `_findPullRequestBranch`, verify (or checkout) the exact SHA recorded in the `PullRequest`/`IAPIPullRequest` object, and surface a warning/re-confirmation to the user if the live branch tip has diverged from the SHA they last reviewed — mirroring how `StakingModule.sol`-style guards prevent action based on stale state.

### Proof of Concept
1. Attacker forks `victim/repo`, opens PR #N with an innocuous-looking commit A, and gets it into a state where its checks/diff have been reviewed (or simply shares a link like `x-github-client://openrepo/https://github.com/victim/repo?pr=N`).
2. Victim clicks the link (or the "Open in Desktop" button) — Desktop calls `openPullRequestFromUrl` → `fetchPullRequest` (returns PR object with `head.sha = A`).
3. Immediately before Desktop's `_checkoutPullRequest` → `_findPullRequestBranch` executes its `git fetch`, the attacker force-pushes malicious commit B to the same fork branch (`headRefName`).
4. `_findPullRequestBranch` fetches the remote and resolves `remote.name/headRefName`, which now points at B, and creates local branch `pr/N` tracking it — Desktop checks out B, not the reviewed A, with no SHA comparison or user warning. [5](#0-4)

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<void> {
    const prBranch = await this._findPullRequestBranch(
      repository,
      prNumber,
      headRepoOwner,
      headCloneUrl,
      headRefName
    )
    if (prBranch !== undefined) {
      await this._checkoutBranch(repository, prBranch)
      this.statsStore.increment('prBranchCheckouts')
    }
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
