### Title
Unbounded `io.ReadAll(r.Body)` in APM request-tracing wrappers allows memory-exhaustion DoS on the public JSON-RPC HTTP endpoint - ([File: networks/rpc/http_newrelic.go])

### Summary
When the Kaia node's HTTP JSON-RPC server is run with NewRelic APM or Datadog APM tracing enabled, every incoming HTTP RPC request is first passed through `getRPCRequests(r)`, which reads the *entire* request body into memory with `io.ReadAll(r.Body)` **before** the server's own size-limiting logic ever executes. This is functionally the same bug class as the reported Litestar CVE-2024-52581: a request-body parser that buffers the whole body in memory with no size cap, allowing any unauthenticated caller to exhaust node memory with a single oversized (or chunked, `Content-Length: -1`) POST request.

### Finding Description
The normal (non-APM) request path enforces `common.MaxRequestContentLength` in two independent ways:
- `validateRequest` rejects requests whose `Content-Length` exceeds the limit [1](#0-0) 
- Even when the check passes (or is bypassed, e.g. via chunked transfer-encoding without a `Content-Length` header), the actual body reader is wrapped in `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` inside `newHTTPServerConn`, capping how many bytes are ever read into memory [2](#0-1) 

However, `NewHTTPServer` optionally wraps the handler chain with APM handlers when the corresponding environment variables are set: [3](#0-2) 

Both APM wrappers call `getRPCRequests(r)` unconditionally, at the very start of request handling, before the inner handler (which contains `validateRequest`/`newHTTPServerConn`) ever runs:
- NewRelic: [4](#0-3) 
- Datadog: [5](#0-4) 

`getRPCRequests` itself performs the unbounded read: [6](#0-5) 

`io.ReadAll(r.Body)` has no size cap and no `Content-Length` pre-check — it will keep growing a `[]byte` buffer until the client stops sending data or the process runs out of memory. Since `getRPCRequests` runs *before* `handler.ServeHTTP(dupW, r)` (which is where `validateRequest`'s `Content-Length` check and the `io.LimitReader`-bounded codec actually live), the size enforcement that exists for the "plain" HTTP RPC path is completely bypassed whenever the APM instrumentation is active. A caller can send a POST to any exposed JSON-RPC HTTP endpoint (e.g. `eth_call`, `eth_sendRawTransaction`, etc. — any method at all, since the body doesn't even need to parse successfully) with an arbitrarily large or chunked body, and the node will buffer the entire payload in memory for every such request, independent of the configured `MaxRequestContentLength` flag.

### Impact Explanation
This is an unauthenticated, public-RPC-caller-reachable memory-exhaustion vector (CWE-770), matching the analog bug class in the reported advisory. On a node with NewRelic or Datadog tracing enabled (a realistic production configuration for RPC/API providers, evidenced by the KAS-specific header parsing code alongside it: `parseKASHeader`/`x-chain-id` [7](#0-6) ), an attacker can send a small number of large or slow/chunked POST requests to exhaust available memory and crash or severely degrade the RPC node, causing denial of service to all legitimate transaction senders, dApps, and public RPC consumers relying on that endpoint. This does not directly cause fund loss or consensus divergence, but it is a High-severity availability impact on a component in the direct request path of every public JSON-RPC caller.

### Likelihood Explanation
Likelihood is high whenever APM tracing is enabled, since the vulnerable code path is unconditionally invoked for every request and requires no authentication, no special headers, and no valid RPC payload — an attacker only needs to open a connection to the public HTTP-RPC port and stream a large/chunked body. No rate limiting or per-connection memory cap exists in `getRPCRequests`.

### Recommendation
Enforce the same size cap in `getRPCRequests` as in `newHTTPServerConn`: replace `io.ReadAll(r.Body)` with `io.ReadAll(io.LimitReader(r.Body, int64(common.MaxRequestContentLength)+1))` and reject/short-circuit before invoking APM tracing logic if the read exceeds the limit (mirroring `validateRequest`'s behavior), so the APM wrapper never buffers more than `common.MaxRequestContentLength` bytes regardless of whether NewRelic/Datadog tracing is active.

### Proof of Concept
1. Run a Kaia node's HTTP JSON-RPC server with NewRelic APM enabled (`NEWRELIC_APP_NAME` and `NEWRELIC_LICENSE` env vars set) or Datadog tracing enabled (`DD_TRACE_ENABLED=true`).
2. Send a POST request to the RPC endpoint using chunked transfer-encoding (no `Content-Length` header) or a very large `Content-Length` body, e.g.:
   `curl -X POST -H "Transfer-Encoding: chunked" -H "Content-Type: application/json" --data-binary @- http://<node>:8551/ < /dev/zero`
3. Observe that `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` calls `getRPCRequests(r)` → `io.ReadAll(r.Body)`, which keeps allocating memory as data streams in, well beyond `common.MaxRequestContentLength` (512 KiB by default), since the `validateRequest` `Content-Length` check and `io.LimitReader` cap in `newHTTPServerConn` are only reached later in `handler.ServeHTTP`.
4. Repeating with multiple concurrent connections exhausts node memory, causing OOM/crash or severe latency for all other RPC clients.

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}

func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
