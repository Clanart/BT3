Audit Report

## Title
Stake-weighted QUIC/TPU privilege (peer type/stake) is captured once at connection establishment and never re-validated, letting fully-unstaked identities retain elevated throughput and eviction-immunity indefinitely - ([File: streamer/src/nonblocking/swqos.rs])

## Summary
`SwQos::build_connection_context` and `SimpleQos::build_connection_context` call `get_connection_stake()` exactly once, at connection acceptance, to derive `ConnectionPeerType`/`total_stake` and bake them into an immutable `ConnectionContext` for the life of the connection [1](#0-0) . Although the authoritative `staked_nodes` table is refreshed independently every 5 seconds by `StakedNodesUpdaterService` [2](#0-1) , nothing in `handle_connection`'s stream-accept loop or elsewhere re-derives the connection's stake/peer type against that live table, so a connection's elevated QoS entitlement (max concurrent uni-streams, throttling budget, and `prune_random` eviction immunity) persists even after the backing stake is fully withdrawn.

## Finding Description
`get_connection_stake()` reads the live `staked_nodes` table only when invoked [3](#0-2) . Both `SwQos::build_connection_context` and `SimpleQos::build_connection_context` invoke it a single time, at connection setup, and store the resulting `peer_type`/`total_stake` in `SwQosConnectionContext`/`SimpleQosConnectionContext`, which have no logic to refresh these fields later [4](#0-3) . `cache_new_connection` uses this one-time snapshot to compute and permanently set `max_concurrent_uni_streams` via `connection.set_max_concurrent_uni_streams(max_uni_streams)` [5](#0-4) , and `max_streams_per_throttling_interval`/`available_load_capacity_in_throttling_duration` size the ongoing per-interval throughput budget directly proportional to that same frozen stake value [6](#0-5) [7](#0-6) . `handle_connection` runs the connection's entire stream-accept loop using the context captured at admission (`let peer_type = context.peer_type();`) with no re-check against `staked_nodes` [8](#0-7) . Eviction via `prune_random` similarly compares against the stake value stored in the `ConnectionEntry` at insertion time, not a fresh lookup, and skips eviction entirely if the sampled connections' recorded stakes exceed `threshold_stake` [9](#0-8) . Since stake derivation is fully decoupled from connection lifetime and no mechanism closes/downgrades a connection when its backing stake account is deactivated, a connection admitted while staked keeps its elevated grant and eviction immunity indefinitely, as long as the socket is kept alive past the QUIC idle timeout.

## Impact Explanation
This breaks the invariant that TPU/QUIC bandwidth and connection-table capacity are proportional to *current* stake. A briefly-staked attacker can occupy staked connection-table slots (up to `max_connections_per_staked_peer`) and, after unstaking, those connections remain immune to `prune_random` because the comparison uses the stale, high `stake` recorded in the `ConnectionEntry` rather than the current (zero) stake in `staked_nodes`. This can starve slots and disproportionate stream/throughput allowance from currently, legitimately staked validators once `max_staked_connections` is reached — a non-RPC remote exhaustion/degradation of the TPU/QUIC ingestion path, consistent with the allowed impact category.

## Likelihood Explanation
Medium. The attack requires only the ability to transiently acquire stake sufficient to pass the `min_stake_ratio` gate in `SwQos::build_connection_context` [10](#0-9) , open connections while staked, then unstake while keeping the sockets alive with sparse traffic to avoid the QUIC idle timeout. No signature forgery, consensus bug, or privileged access is required, but it does require sustained activity and the economic cost of holding stake temporarily, bounding but not eliminating feasibility.

## Recommendation
- Periodically re-evaluate each open connection's `peer_type`/stake against the live `staked_nodes` table (e.g., on the same 5s cadence as `StakedNodesUpdaterService`), downgrading or closing connections whose backing stake has fallen below the admission threshold.
- Make `prune_random`'s eviction comparison use a freshly looked-up stake value rather than the value captured in `ConnectionEntry` at connection creation.
- Alternatively, bound the lifetime of the elevated grant by re-deriving `max_uni_streams`/throttling budget at fixed intervals per connection.

## Proof of Concept
1. Attacker delegates stake sufficient to pass the `min_stake_ratio` check in `SwQos::build_connection_context` (`streamer/src/nonblocking/swqos.rs:314-331`) and waits for it to be reflected via `StakedNodesUpdaterService`.
2. Attacker opens `max_connections_per_staked_peer` QUIC connections to the validator's TPU; `build_connection_context` captures `peer_type = Staked(stake)`/`total_stake`, and `cache_new_connection` sets an elevated `max_uni_streams` (`streamer/src/nonblocking/swqos.rs:181-232`).
3. Attacker fully deactivates stake. After the next `StakedNodesUpdaterService` refresh, `staked_nodes.get_node_stake(&attacker_pubkey)` returns `None`/0 for any *new* lookup, but the attacker's already-open connections keep the originally captured `ConnectionEntry`/`peer_type`/`total_stake`.
4. Attacker sends sparse traffic to reset the QUIC idle timer, keeping the connections open indefinitely with the original elevated `max_uni_streams`/throttling budget, and immune from `prune_random(sample_size, threshold_stake)` (`streamer/src/nonblocking/quic.rs:982-1006`) since the compared stake is the stale, high value.
5. This can be validated by extending existing tests such as `simple_qos.rs`'s `test_try_add_connection_max_staked_connections_no_pruning_possible`-style harness to simulate a stake reduction in `staked_nodes` after connection admission and assert the connection remains un-pruned and retains its original `max_uni_streams`.

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,

        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
