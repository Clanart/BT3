### Title
Unhandled `IndexError` from out-of-bounds atom-length parsing in `is_atom_canonical`/`is_clvm_canonical` — attacker-controlled spend halts mempool processing - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical` and `is_clvm_canonical` parse the raw CLVM byte buffer of an attacker-supplied `puzzle_reveal`/`solution` during mempool admission, indexing into the `bytes` buffer based on length-prefix fields read from that same untrusted buffer, with no bounds check against the buffer length before each index access.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine a variable-length atom-length prefix (1–6 bytes), then loops `prefix_len` times incrementing `offset` and reading `clvm_buffer[offset]` again, with no check that `offset < len(clvm_buffer)` at any point: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this in a `while True:` loop, unconditionally reading `b = clvm_buffer[offset]` on every iteration and advancing `offset` by the atom length returned from `is_atom_canonical`, again without any bounds validation before the next read: [2](#0-1) 

This is called directly on attacker-supplied bytes at mempool admission time, in `validate_spend_bundle`, before any other structural validation of the spend's canonical form: [3](#0-2) 

A crafted `puzzle_reveal`/`solution` whose final bytes encode an atom-length prefix or a `0xFF` pair byte that claims more bytes than remain in the buffer causes `offset` to advance past `len(clvm_buffer)`. The next `clvm_buffer[offset]` access in Python raises an unhandled `IndexError` (Python's bounds-checked equivalent of the C-level "invalid read" described in the CVE analog — sam2p's `parse_rgb` in `in_xpm.cpp` read past a buffer based on unvalidated length fields from attacker-controlled image data). Tracing the call chain (`validate_spend_bundle` → `add_spend_bundle`) shows no `try/except` around the `is_clvm_canonical` calls to catch this specific exception type; only `Err`-based control flow is handled, so an `IndexError` would propagate as an unhandled exception out of `add_spend_bundle`.

### Impact Explanation
This matches the CVE's bug class — insufficient bounds validation of a length-prefixed field read from untrusted binary input, causing an out-of-bounds buffer access. In this Python context it manifests as an unhandled `IndexError` rather than memory corruption, but it is directly reachable by any unprivileged spend-bundle submitter and occurs during mempool admission, the hot path for every incoming transaction. An uncaught exception here in `validate_spend_bundle`/`add_spend_bundle` risks aborting whatever task/coroutine processes the transaction, which can degrade or halt transaction-processing for that spend and, depending on caller-level exception handling upstream (not confirmed within available context), other in-flight mempool operations.

### Likelihood Explanation
Trivial to trigger: the attacker only needs to submit a spend bundle whose `puzzle_reveal` or `solution` bytes are crafted so the last encoded atom/pair claims a length prefix that overruns the buffer. No signature validity or coin ownership is required to reach this code path, since `is_clvm_canonical` runs before/alongside removal/coin validation in `validate_spend_bundle`.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access (validate `offset < len(clvm_buffer)`, and validate `offset + prefix_len < len(clvm_buffer)` before entering the prefix-reading loop), and similarly bound-check `offset` in the `is_clvm_canonical` main loop before dereferencing `clvm_buffer[offset]`. On failure, return `False`/raise a handled `ValueError` rather than allowing `IndexError` to propagate, and ensure `validate_spend_bundle` treats any parsing failure as `Err.INVALID_COIN_SOLUTION` rather than an unhandled exception.

### Proof of Concept
Construct a `solution`/`puzzle_reveal` byte string ending in an atom marker whose declared length prefix bytes are absent, e.g. a buffer ending in a lone `0xC0` byte (5+8-bit length-prefix marker) with no following length byte — `is_atom_canonical` will attempt `clvm_buffer[offset]` for the missing prefix byte and raise `IndexError`, or a buffer ending in `0xFF` (pair token) with no subsequent content — `is_clvm_canonical`'s loop will read `clvm_buffer[offset]` past the end. Submitting either as `coin_spend.puzzle_reveal`/`solution` in a `SpendBundle` via the standard `push_tx`/RPC path reaches `validate_spend_bundle` at line 723 and triggers the unhandled exception, as no bounds check exists in either function. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
