### Title
Gasless swap repayment fixed to `GasLimit`-based fee instead of actual `GasUsed` lets a sender siphon unused-gas refund from the block proposer - (File: `kaiax/gasless/impl/getter.go`)

### Summary
KIP-247 gasless transactions let the block proposer "lend" a user the KAIA needed to pay for a `GaslessApproveTx`/`GaslessSwapTx` pair, expecting the user to repay the exact lent amount from swap proceeds inside `swapForGas`. The lent amount and the required repayment are both computed from the transactions' **`GasLimit * GasPrice`** (i.e. `tx.Fee()`), not from the **actual gas consumed**. Because Kaia's EVM state transition refunds unused gas (`GasLimit - GasUsed`) directly to the transaction sender via `returnGas()`, and because the gasless sender/fee-payer for `ApproveTx`/`SwapTx` is the user itself, any unused-gas margin becomes a permanent, unrepaid profit taken from the proposer's lent funds. This is conceptually the same class of bug as the Vegas Town "hard_fail" incident: a settlement amount is computed from a nominal/expected value (full gas budget) instead of the actual executed outcome (gas used), letting an attacker extract the difference.

### Finding Description
`GetLendTxGenerator` computes the amount lent to the user as: [1](#0-0) 

and the amount the `SwapForGas` call must repay to the proposer is: [2](#0-1) 

Both `lendAmount` and `repayAmount` are derived purely from `tx.Fee()` (`GasLimit * GasPrice`) of the `ApproveTx`/`SwapTx`, verified only for equality at pool-admission time in `VerifyExecutable` (`SP4.`): [3](#0-2) 

However, at actual execution time, `TransitionDb` refunds the sender for any gas not consumed: [4](#0-3) 

Since `ApproveTx` and `SwapTx` are ordinary (non-fee-delegated) transactions signed by the user, `validatedFeePayer == validatedSender`, so this refund credits the user's own EOA — the same account that received the lent KAIA. The bundle-atomicity mechanism (`commitBundleTransaction`) only guarantees that the whole bundle succeeds or is rolled back together; it does not reconcile the fixed `amountRepay` against actual gas usage: [5](#0-4) 

Consequently, whenever the user sets `GasLimit` for `ApproveTx`/`SwapTx` with margin above the actual gas cost (a very ordinary practice, and not something `VerifyExecutable` restricts to an exact/tight value), the difference `(GasLimit - GasUsed) * GasPrice` for each of the two transactions is refunded to the user's balance by the EVM, on top of the swap's `FinalUserAmount`. The `amountRepay` paid back to the proposer inside `swapForGas` never accounts for this unused-gas margin, so the proposer effectively subsidizes it. Because `lendAmount`/`repayAmount` calculations depend only on values the unprivileged sender fully controls (`GasLimit`, `GasPrice` of their own signed transactions), an attacker can repeatedly construct approve/swap pairs with inflated `GasLimit` to maximize the unrepaid refund on every gasless cycle.

### Impact Explanation
This is a **fee-delegation/gasless settlement abuse**: value (KAIA) is unconditionally extracted from the block proposer's lent funds without a corresponding, accurate repayment, on every gasless swap performed by any unprivileged sender. Repeated over many blocks/senders, this constitutes systematic value drain from proposers who support the gasless feature, i.e. unauthorized value movement enabled by a KIP-247/gasless settlement design flaw — directly matching the "Validate" criteria (fee/fee-delegation abuse via a public, self-submittable transaction sequence).

### Likelihood Explanation
High feasibility for any user able to submit `GaslessApproveTx`/`GaslessSwapTx` pairs (a normal, unprivileged, public capability of KIP-247): the attacker fully controls `GasLimit` on their own signed approve/swap transactions, and `VerifyExecutable`'s `SP4` check only ties `amountRepay` to the nominal `GasLimit*GasPrice` value, not to the true gas consumed on execution. No special timing, node, or validator collusion is required — it is reachable purely from crafting the swap/approve pair and choosing a generous gas limit.

### Recommendation
Compute `lendAmount`/`repayAmount` (or reconcile after execution, similar to `AdjustFeesByReceipts` used elsewhere in the codebase for regular fee-delegated transactions) based on the **actual `GasUsed`** reported in the `ApproveTx`/`SwapTx`/`LendTx` receipts rather than the nominal `GasLimit`. Alternatively, require the proposer/module to recover any residual/unused-gas refund credited to the gasless sender back to the proposer before finalizing the bundle, or clamp `GasLimit` for gasless transactions to a tightly metered value that cannot leave meaningful slack.

### Proof of Concept
1. Attacker holds test tokens but zero KAIA (satisfies gasless preconditions, as demonstrated in `tests/gasless_test.go`).
2. Attacker crafts `GaslessApproveTx` and `GaslessSwapTx` with `GasLimit` set comfortably above the actual gas the calls will consume (both remain within `IsExecutable`/`VerifyExecutable` constraints, since those checks validate `AmountRepay` against the nominal `GasLimit*GasPrice`, not against actual usage).
3. Proposer builds the bundle `[LendTxGenerator, ApproveTx, SwapTx]` per `ExtractTxBundles`; `LendTx` transfers `lendAmount = ApproveTx.Fee() + SwapTx.Fee()` (full `GasLimit`-based amount) to the attacker.
4. `ApproveTx` and `SwapTx` execute using less than their full `GasLimit`; `TransitionDb.returnGas()` refunds the unused portion `(GasLimit-GasUsed)*GasPrice` for each tx directly to the attacker's balance.
5. `SwapForGas` inside `SwapTx` repays the proposer exactly `amountRepay = repayAmount(...)` (still based on full `GasLimit`), leaving the EVM-refunded unused-gas margin permanently in the attacker's wallet in addition to `FinalUserAmount` from the swap — net drain from the proposer equal to the unused-gas margin, repeatable every gasless cycle.

Note: I was not able to fully verify whether `isApproveTx`/`isSwapTx` in `kaiax/gasless/impl/getter.go` enforce an exact (non-discretionary) `GasLimit` value for these transactions before this analysis concluded (file read calls failed in the final iteration due to tool errors). If such an exact-`GasLimit` constraint exists and leaves no slack between `GasLimit` and worst-case `GasUsed`, the practical exploitable margin could be smaller than described; a Devin session with full file access should confirm this constraint in `kaiax/gasless/impl/getter.go` (functions `isApproveTx`, `isSwapTx`, and `kaiax/gasless/impl/constant.go`) before treating the magnitude of this issue as unbounded.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

// returnGas returns KAIA for remaining gas, exchanged at the original rate.
func (st *StateTransition) returnGas() {
	remaining := new(big.Int).Mul(new(big.Int).SetUint64(st.gas), st.gasPrice)

	validatedFeePayer := st.msg.ValidatedFeePayer()
	validatedSender := st.msg.ValidatedSender()
	feeRatio, isRatioTx := st.msg.FeeRatio()
	if isRatioTx {
		feePayer, feeSender := types.CalcFeeWithRatio(feeRatio, remaining)

		st.state.AddBalance(validatedFeePayer, feePayer)
		st.state.AddBalance(validatedSender, feeSender)
	} else {
		// To make a short circuit, the below routine processes when feeRatio == 100.
		st.state.AddBalance(validatedFeePayer, remaining)
	}
}

func (env *Task) commitBundleTransaction(bundle *builder.Bundle, bc BlockChain, nodeAddr common.Address, vmConfig *vm.Config) (error, *types.Transaction, []*types.Log) {
	lastSnapshot := env.state.Copy()
	gasUsedSnapshot := env.header.GasUsed
	blobGasUsedSnapshot := env.header.BlobGasUsed
	blobsSnapshot := env.blobs
	tcountSnapshot := env.tcount
	txs := []*types.Transaction{}
	receipts := []*types.Receipt{}
	logs := []*types.Log{}

	markAllTxUnexecutable := func() {
		for _, txOrGen := range bundle.BundleTxs {
			if txOrGen.IsConcreteTx() {
				tx, _ := txOrGen.GetTx(0)
				tx.MarkUnexecutable(true)
			}
		}
	}

	restoreEnv := func() {
		env.state.Set(lastSnapshot)
		env.header.GasUsed = gasUsedSnapshot
		env.tcount = tcountSnapshot
		// blob related env are restored to the snapshot
		env.header.BlobGasUsed = blobGasUsedSnapshot
		env.blobs = blobsSnapshot
	}

	var totalTxSize uint64 = 0
	for _, txOrGen := range bundle.BundleTxs {
		tx, err := txOrGen.GetTx(env.state.GetNonce(nodeAddr))
		if err != nil {
			logger.Error("TxGenerator error", "error", err)
			markAllTxUnexecutable()
			restoreEnv()
			return kerrors.ErrTxGeneration, nil, nil
		}

		env.state.SetTxContext(tx.Hash(), common.Hash{}, env.tcount)
		receipt, _, err := bc.ApplyTransaction(env.config, &nodeAddr, env.state, env.header, tx, &env.header.GasUsed, vmConfig)
		// Bundled tx will be rejected with any receipt.Status other than success.
		// There may be cases where a revert occurs within the EVM, which could result in an attack on a tx sender in an already executed bundle.
		if err != nil || receipt.Status != types.ReceiptStatusSuccessful {
			if err != vm.ErrInsufficientBalance && err != vm.ErrTotalTimeLimitReached {
				markAllTxUnexecutable()
			}
			receiptStatus := ""
			if receipt != nil {
				receiptStatus = strconv.FormatUint(uint64(receipt.Status), 10)
			}
			logger.Warn("ApplyTransaction error, restoring env",
				"blockNum", env.header.Number.String(), "txHash", tx.Hash().String(),
				"error", err, "receiptStatus", receiptStatus,
			)
			restoreEnv()
			if err == nil {
				err = kerrors.ErrRevertedBundleByVmErr
			}
			return err, tx, nil
		}

		env.tcount++
		totalTxSize += uint64(tx.Size())
		txs = append(txs, tx)
		receipts = append(receipts, receipt)
		logs = append(logs, receipt.Logs...)
		if tx.Type() == types.TxTypeEthereumBlob {
			env.blobs += len(tx.BlobHashes())
			*env.header.BlobGasUsed += tx.BlobGas()
		}
	}
