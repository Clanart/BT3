### Title
`ReceivedOutput::read` accepts outputs the group key cannot spend, producing "received" funds that are unspendable and aborting transaction construction - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

Analogous to the Telcoin bridge that accepts deposits with no withdrawal path, `bitcoin-serai`'s wallet deserialization path produces `ReceivedOutput`s — the type the scanner/wallet treats as received, spendable funds — without verifying that the declared `offset` actually maps the group key to the output's `script_pubkey`. Any `ReceivedOutput` built from attacker-influenced bytes (an allowed input surface per `ReceivedOutput::read`) can claim an output is spendable by the threshold key when it is not, so downstream transaction construction silently fails, leaving the funds stuck.

### Finding Description

`ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs` decodes three independent fields with no cross-field consistency check:

- `offset` via `Secp256k1::read_F` (line 123)
- `output` via `TxOut::consensus_decode` (lines 128–129)
- `outpoint` via `OutPoint::consensus_decode` (lines 130–131)

```rust
// networks/bitcoin/src/wallet/mod.rs
let offset = Secp256k1::read_F(r)?;
output = TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
outpoint = OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
Ok(ReceivedOutput { offset, output, outpoint })
```

A legitimately-produced `ReceivedOutput` only exists when `output.script_pubkey == p2tr_script_buf(group_key + GENERATOR * offset)` — that invariant is established by `Scanner::register_offset`/`scan_transaction` (lines 185–211) but is never re-checked on deserialization. The only place it is enforced is `SignableTransaction::multisig` in `networks/bitcoin/src/wallet/send.rs` (lines 273–284), where a mismatch causes `multisig` to return `None`:

```rust
// networks/bitcoin/src/wallet/send.rs
let offset = keys.clone().offset(self.offsets[i]);
if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
  None?;
}
```

So a crafted `ReceivedOutput` whose `script_pubkey` is a P2TR output under a different key — or not P2TR at all — is accepted by `read`, carries a `value()` the wallet counts as received funds, enters `SignableTransaction::new` as an input without complaint (the constructor only checks amounts/dust, never key ownership), and then makes the entire signing machine unobtainable (`multisig` returns `None`) or produces a transaction whose signature cannot authorize the spend.

Additionally, `read` accepts arbitrary `TxOut.value` and arbitrary `outpoint` values. Since `SignableTransaction::new` computes `input_sat` from the decoded `output.value` (send.rs line 175) and the sighash commits to `Prevouts::All(&self.tx.prevouts)` (send.rs line 375), an inflated `value` yields fee arithmetic and a signed message that do not correspond to the real on-chain prevout — the resulting transaction is consensus-invalid even where a key match exists.

### Impact Explanation

Funds reported as received by the wallet are not spendable: a poisoned `ReceivedOutput` is treated as balance (its `value()` is exposed), is accepted into `SignableTransaction::new`, and then either (a) blocks creation of the multisig machine entirely via the `None` return in `multisig`, stalling every other input bundled in the same transaction, or (b) produces a transaction committing to nonexistent/incorrect prevouts that the network will reject. There is no recovery or filtering path — exactly the "deposit without withdrawal" shape: value enters the wallet's accounting but cannot leave.

### Likelihood Explanation

Reachability depends on attacker-influenced bytes reaching `ReceivedOutput::read` / `Output::read` (e.g., persisted or relayed output records in downstream consumers); the read path itself performs zero validation beyond scalar canonically and syntactic decoding, so no further conditions are needed once untrusted bytes are supplied. Where `ReceivedOutput`s only ever come from `Scanner::scan_transaction`, the invariant holds — the vulnerability is that the type's deserialization does not enforce the invariant its consumers rely on.

### Recommendation

Bind the offset to the output at read time: have `ReceivedOutput::read` (or a validating constructor) reject any output where `output.script_pubkey` is not a P2TR script equal to `p2tr_script_buf(expected_key + GENERATOR * offset)`, or store the key/offset commitment and verify it in `SignableTransaction::new` rather than deferring the check to `multisig`. Rejecting non-P2TR `script_pubkey`s and zero/invalid outpoints at deserialization prevents unspendable entries from ever entering the input set.

### Proof of Concept

```rust
use bitcoin::{
  script::ScriptBuf, transaction::Transaction, OutPoint, TxOut, Amount, Txid, hashes::Hash,
};
use k256::Scalar;
use frost::{curve::Secp256k1, ThresholdKeys};
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction, p2tr_script_buf};

// Attacker-controlled bytes: a valid scalar offset paired with a script_pubkey
// that is NOT p2tr(group_key + offset*G) — e.g. someone else's P2TR output.
let offset = Scalar::from(1u64); // canonical, passes read_F
let foreign_script = ScriptBuf::new_p2tr_tweaked(/* arbitrary 32-byte x-only key */);

let mut bytes = Vec::new();
bytes.extend(offset.to_bytes());
bytes.extend(bitcoin::consensus::serialize(&TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: foreign_script,
}));
bytes.extend(bitcoin::consensus::serialize(&OutPoint {
  txid: Txid::all_zeros(), vout: 0,
}));

// 1) Deserialization succeeds — no key/script consistency check
let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(received.value(), 100_000); // wallet now "has" 100k sats it cannot spend

// 2) Accepted as an input — constructor never verifies key ownership
let tx = SignableTransaction::new(
  vec![received],
  &[(p2tr_script_buf(group_key).unwrap(), 50_000)],
  None, None, 10,
).unwrap();

// 3) Signing is impossible — multisig returns None; funds are stuck
assert!(tx.multisig(&keys).is_none());
```
