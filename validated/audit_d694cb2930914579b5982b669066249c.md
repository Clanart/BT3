## Analysis

The Otter Audits finding is fundamentally about a **stale/mismatched external read**: the contract records credits at one point (mint) but re-derives “ground truth” (`balanceOf`) at a later point (fee/exchange-rate calc), and the two views can diverge because a third party can mutate the read target in between, without the code detecting the drift.

The closest structural analog in GitHub Desktop is in the **partial-commit (line-by-line staging) pipeline**, where the diff used to build the user's *line selection* and the diff used to *build the actual patch applied to the index* are fetched at two different times from two different reads of the working-tree file, with no consistency check between them.

### Title
Partial-commit line selection is applied against a re-fetched diff, allowing stale line indices to stage unintended content - (File: `app/src/lib/git/apply.ts`)

### Summary
When a user makes a partial (line/hunk-level) selection in the Changes view, GitHub Desktop stores that selection as a set of *absolute line indices* computed against the diff that was rendered at selection time (`updateChangesWorkingDirectoryDiff`, cached in `state.selection.diff`) [1](#0-0) . When the commit is actually performed, `stageFiles` calls `applyPatchToIndex` for every file with a partial selection, and that function fetches an **independent, fresh** diff via `getWorkingDirectoryDiff(repository, file)` right before building the patch [2](#0-1) . `formatPatch` then walks the *new* diff's hunks and decides what to include using `file.selection.isSelected(absoluteIndex)` — i.e., the *old* index set applied to the *new* hunk layout [3](#0-2) .

### Finding Description
The broken invariant: "the set of selected line indices is only valid relative to the diff it was computed from." Nothing enforces that the diff consulted in `applyPatchToIndex`/`formatPatch` at staging time is the same diff object that produced `file.selection`. `app-store.ts` does contain logic that tries to keep the *displayed* selection valid when the diff is reloaded (`updateChangesWorkingDirectoryDiff` recomputes `selectableLines` and calls `withSelectableLines`) [4](#0-3) , but this reconciliation only runs when the UI proactively reloads the diff for display — it is not invoked, and provides no guarantee, at the moment `_finishCommitCreation`/`stageFiles`/`applyPatchToIndex` runs its own independent `getWorkingDirectoryDiff` call [5](#0-4) .

If the working-tree file's content changes between the last diff render the user reviewed and the moment `git commit` is actually executed (e.g., because a build/watch/format tool that ships with the cloned repository — a `postinstall`/`prepare` script, a watch-mode formatter, a lint-staged/husky hook, or any tool the repository's own tooling launches — rewrites the file), the hunk boundaries and absolute line indices shift. The stale index set is then reinterpreted against the new hunk structure, so `formatPatch` can silently include lines the user never saw/selected or exclude lines the user did select, without any error, warning, or diff re-confirmation before the commit is created.

This mirrors the audit report's core defect: relying on a live, externally-mutable read (`balanceOf` / `getWorkingDirectoryDiff`) as if it were consistent with an internal record captured earlier (LP credits / line selection), with no reconciliation before the value is used to produce a final, consequential state change (fee calc / committed patch).

### Impact Explanation
The result is silent corruption of what the user actually commits and (eventually) pushes: content can enter the permanent git history that the user did not review or explicitly select, or content the user intended to commit can be silently dropped. Since a repository the user clones can legitimately bundle tooling that mutates tracked files in the background (formatters, generators, build watchers configured via package.json scripts, `.vscode` recommended extensions, etc.), the attacker-controlled repository can create the conditions for this race without needing local/admin access or any unnatural user action beyond normal review-then-commit workflow.

### Likelihood Explanation
This requires a timing window between the diff render used for selection and the commit action, and a file-mutating process running during the review — plausible for larger diffs where users deliberate over hunk selection, or where autosave/format-on-save is active. It is not trivial to reliably trigger from a purely passive attacker standpoint, so likelihood is moderate rather than high, but the underlying design gap (no diff/selection consistency check at apply time) is a clear, exploitable structural flaw rather than a purely theoretical one.

### Recommendation
Persist and reuse the exact diff object (or a content hash/generation token of it) associated with a `WorkingDirectoryFileChange`'s selection, and pass that same diff into `applyPatchToIndex`/`formatPatch` instead of re-fetching a new one. If the file has changed on disk since the selection was captured (detected via mtime/hash/hunk-shape comparison), the commit flow should invalidate the stale partial selection and force the user to re-review before staging, analogous to how the audit's remediation requires reconciling the internal ledger with any observed external balance change before it's trusted for a downstream calculation.

### Proof of Concept
1. Clone a repository containing a large tracked file and a bundled tool that rewrites that file shortly after it's touched (e.g., a `chokidar`/`nodemon`-style watcher declared in the repo's own `package.json`, started via a normal `npm install && npm run watch` the repo's README asks the user to run).
2. In GitHub Desktop, open the file's diff and select only specific lines/hunks to include in the commit (leaving others unselected), captured via `state.selection.diff` at that moment [6](#0-5) .
3. Before clicking "Commit", let the watcher rewrite the file (adding/removing lines earlier in the file so hunk offsets shift).
4. Click "Commit". `stageFiles` → `applyPatchToIndex` fetches a brand-new diff for the file and calls `formatPatch`, which reinterprets the old absolute line indices against the new hunk layout [7](#0-6) [8](#0-7) .
5. Inspect the resulting commit: it contains lines the user never selected (or omits lines that were selected), with no warning shown to the user.

```typescript
  private async updateChangesWorkingDirectoryDiff(
    repository: Repository
  ): Promise<void> {
    const stateBeforeLoad = this.repositoryStateCache.get(repository)
    const changesStateBeforeLoad = stateBeforeLoad.changesState

    if (
      changesStateBeforeLoad.selection.kind !==
      ChangesSelectionKind.WorkingDirectory
    ) {
      return
    }

    const selectionBeforeLoad = changesStateBeforeLoad.selection
    const selectedFileIDsBeforeLoad = selectionBeforeLoad.selectedFileIDs

    // We only render diffs when a single file is selected.
    if (selectedFileIDsBeforeLoad.length !== 1) {
      if (selectionBeforeLoad.diff !== null) {
        this.repositoryStateCache.updateChangesState(repository, () => ({
          selection: {
            ...selectionBeforeLoad,
            diff: null,
          },
        }))
        this.emitUpdate()
      }
      return
    }

    const selectedFileIdBeforeLoad = selectedFileIDsBeforeLoad[0]
    const selectedFileBeforeLoad =
      changesStateBeforeLoad.workingDirectory.findFileWithID(
        selectedFileIdBeforeLoad
      )

    if (selectedFileBeforeLoad === null) {
      return
    }

    const diff = await getWorkingDirectoryDiff(
      repository,
      selectedFileBeforeLoad,
      this.hideWhitespaceInChangesDiff
    )

    const stateAfterLoad = this.repositoryStateCache.get(repository)
    const changesState = stateAfterLoad.changesState

    // A different file (or files) could have been selected while we were
    // loading the diff in which case we no longer care about the diff we
    // just loaded.
    if (
      changesState.selection.kind !== ChangesSelectionKind.WorkingDirectory ||
      !arrayEquals(
        changesState.selection.selectedFileIDs,
        selectedFileIDsBeforeLoad
      )
    ) {
      return
    }

    const selectedFileID = changesState.selection.selectedFileIDs[0]

    if (selectedFileID !== selectedFileIdBeforeLoad) {
      return
    }

    const currentlySelectedFile =
      changesState.workingDirectory.findFileWithID(selectedFileID)
    if (currentlySelectedFile === null) {
      return
    }

    const selectableLines = new Set<number>()
    if (diff.kind === DiffType.Text || diff.kind === DiffType.LargeText) {
      // The diff might have changed dramatically since last we loaded it.
      // Ideally we would be more clever about validating that any partial
      // selection state is still valid by ensuring that selected lines still
      // exist but for now we'll settle on just updating the selectable lines
      // such that any previously selected line which now no longer exists or
      // has been turned into a context line isn't still selected.
      diff.hunks.forEach(h => {
        h.lines.forEach((line, index) => {
          if (line.isIncludeableLine()) {
            selectableLines.add(h.unifiedDiffStart + index)
          }
        })
      })
    }

    const newSelection =
      currentlySelectedFile.selection.withSelectableLines(selectableLines)
    const selectedFile = currentlySelectedFile.withSelection(newSelection)
    const updatedFiles = changesState.workingDirectory.files.map(f =>
      f.id === selectedFile.id ? selectedFile : f
    )
    const workingDirectory = WorkingDirectoryStatus.fromFiles(updatedFiles)

    const selection: ChangesWorkingDirectorySelection = {
      ...changesState.selection,
      diff,
    }
```

```typescript
export function formatPatch(
  file: WorkingDirectoryFileChange,
  diff: ITextDiff | ILargeTextDiff
): string {
  let patch = ''

  diff.hunks.forEach((hunk, hunkIndex) => {
    let hunkBuf = ''

    let oldCount = 0
    let newCount = 0

    let anyAdditionsOrDeletions = false

    hunk.lines.forEach((line, lineIndex) => {
      const absoluteIndex = hunk.unifiedDiffStart + lineIndex

      // We write our own hunk headers
      if (line.type === DiffLineType.Hunk) {
        return
      }

      // Context lines can always be let through, they will
      // never appear for new files.
      if (line.type === DiffLineType.Context) {
        hunkBuf += `${line.text}\n`
        oldCount++
        newCount++
      } else if (file.selection.isSelected(absoluteIndex)) {
        // A line selected for inclusion.

        // Use the line as-is
        hunkBuf += `${line.text}\n`

        if (line.type === DiffLineType.Add) {
          newCount++
        }
        if (line.type === DiffLineType.Delete) {
          oldCount++
        }

        anyAdditionsOrDeletions = true
      } else {
        // Unselected lines in new files needs to be ignored. A new file by
        // definition only consists of additions and therefore so will the
        // partial patch. If the user has elected not to commit a particular
        // addition we need to generate a patch that pretends that the line
        // never existed.
        if (
          file.status.kind === AppFileStatusKind.New ||
          file.status.kind === AppFileStatusKind.Untracked
        ) {
          return
        }

        // An unselected added line has no impact on this patch, pretend
        // it was never added to the old file by dropping it.
        if (line.type === DiffLineType.Add) {
          return
        }

        // An unselected deleted line has never happened as far as this patch
        // is concerned which means that we should treat it as if it's still
        // in the old file so we'll convert it to a context line.
        if (line.type === DiffLineType.Delete) {
          hunkBuf += ` ${line.text.substring(1)}\n`
          oldCount++
          newCount++
        } else {
          // Guarantee that we've covered all the line types
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }
      }

      if (line.noTrailingNewLine) {
        hunkBuf += '\\ No newline at end of file\n'
      }
    })

    // Skip writing this hunk if all there is is context lines.
    if (!anyAdditionsOrDeletions) {
      return
    }

    patch += formatHunkHeader(
      hunk.header.oldStartLine,
      oldCount,
      hunk.header.newStartLine,
      newCount
    )
    patch += hunkBuf
  })
```
