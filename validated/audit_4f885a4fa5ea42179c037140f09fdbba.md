### Title
SignableTransaction trusts the claimed value in `ReceivedOutput`, producing signatures over a false prevout amount — `networks/bitcoin/src/wallet/send.rs`

### Summary
The fee-on-transfer bug class — "the amount assumed received/available differs from the amount actually received/available" — has a direct analog in Serai's Bitcoin wallet. `SignableTransaction::new` computes payments, change, and fees entirely from `input.output.value`, and `TransactionSignMachine::sign` commits to those values via `Prevouts::All`. `multisig()` only verifies the prevout's `script_pubkey` matches the offset key — it never checks that the `TxOut` value (or even the `outpoint`) corresponds to the real on-chain UTXO. A `ReceivedOutput` whose `value` doesn't match the chain output (e.g. parsed from untrusted bytes via `ReceivedOutput::read`, or reconstructed by a coordinator) causes the threshold group to produce signatures committing to a false amount, yielding a transaction that is permanently invalid on-chain.

### Finding Description
- `SignableTransaction::new` sums `inputs.iter().map(|input| input.output.value.to_sat())` into `input_sat` and uses it for the `NotEnoughFunds` check and change calculation (`networks/bitcoin/src/wallet/send.rs:175-235`).
- `multisig()` only checks `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey` — no outpoint/value validation (`send.rs:277`).
- `sign()` uses `Prevouts::All(&self.tx.prevouts)`, so the Taproot key-spend sighash commits to every claimed prevout value (`send.rs:375-386`).
- `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) deserializes `offset`, `TxOut`, and `OutPoint` independently from a byte stream, with no binding between the outpoint and the claimed output value.

Unlike the Solidity original where the fix is a `balanceOf` delta, Bitcoin consensus does provide the real prevout — but this code never consults it; the claimed `TxOut` is trusted wholesale.

### Impact Explanation
If the declared prevout value exceeds the real UTXO value, `NotEnoughFunds` and the change computation pass on phantom sats: change is inflated, fee accounting is wrong, and all `t` honest participants sign a transaction that every Bitcoin node rejects (the sighash commits to amounts that don't match the chain). The outputs are reported as spendable inputs but the resulting transaction is unspendable, stalling the multisig's signing pipeline (each failed attempt burns a FROST signing round and, for a coordinator, can repeatedly poison the queue). If the declared value is lower, real funds are silently diverted into fee/change miscalculation. This is the same "assumed amount ≠ actual amount" failure as fee-on-transfer: the arithmetic downstream (change, fee, sighash commitment) is built on an unverified quantity.

### Likelihood Explanation
Reachable whenever a `ReceivedOutput`/`SignableTransaction` is assembled from bytes or state not freshly verified against the chain — e.g. `ReceivedOutput::read` output, a coordinator-provided input list, or a stale/re-orged scan. It requires an untrusted party to influence the input set, which fits Serai's model where transaction construction consumes externally supplied data. It does not require key compromise or validator misbehavior.

### Recommendation
Before signing, verify each `ReceivedOutput`'s `output` (value and script_pubkey) against the actual prevout fetched via RPC for `input.outpoint`, or reject inputs whose origin isn't a trusted `Scanner` result. At minimum, in `multisig()`/`sign()`, document and enforce that `prevouts` must be chain-verified, and treat a post-signing broadcast rejection as a blame-worthy mismatch. Mirroring the audit's fix: derive the effective input amount from the verified chain UTXO, not from the self-reported `TxOut`.

### Proof of Concept
```rust
// Attacker-controlled bytes fed to ReceivedOutput::read:
// real UTXO at outpoint P has value 10_000 sats; the serialized TxOut claims 1_000_000.
let forged = ReceivedOutput { offset, /* TxOut{ value: 1_000_000, script_pubkey: <matching P2TR> } */ , outpoint: P };
let tx = SignableTransaction::new(vec![forged], &payments, Some(change), None, fee).unwrap();
// multisig() succeeds: script_pubkey check passes
// sign() computes sighash over Prevouts::All claiming 1_000_000 sats
// resulting signed TX is rejected by every node (amount/commitment mismatch);
// inputs remain unspent — funds reported spendable are not.
```
