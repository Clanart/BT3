### Title
Unauthenticated access to `Internal*` gRPC methods (e.g. `InternalGetEmergencyStopTx`) when `client_verification=false` - ([File: core/src/servers.rs], [File: core/src/rpc/interceptors.rs])

### Summary
The `Internal*` method authorization binding (`CALLER_AUTHORITY`: only a caller presenting the entity's own certificate may invoke `Internal*`-prefixed RPCs) is enforced solely inside `only_aggregator_and_self`'s `is_internal` check. When the server is configured with `client_verification=false`, `create_grpc_server` installs the `Noop` interceptor instead, which unconditionally passes every request through with no certificate or method-name check at all, so `InternalGetEmergencyStopTx` becomes reachable by any unauthenticated network peer.

### Finding Description
The claimed binding is: `caller reaches Internal* method ⇔ caller's leaf TLS cert == our_cert`. This equality is only evaluated inside `only_aggregator_and_self`, via `is_internal(&req)` at [1](#0-0)  combined with the `leaf_cert == our_cert` comparison.

In `create_grpc_server`, the interceptor to install is chosen based on `config.client_verification`: if true, `OnlyAggregatorAndSelf` is used (which contains the `is_internal` check); if false, `Noop` is used [2](#0-1) . The `Noop` variant's `call` implementation is `Ok(req)` — it never inspects `grpc-method`, peer certs, or anything else [3](#0-2) .

Consequently, when `client_verification=false`, the left side of the binding (any caller reaching `Internal*`) is no longer constrained to equal the right side (holder of `our_cert`) — the check that enforces the equality simply does not run. An attacker with network access to the aggregator's gRPC port can call `InternalGetEmergencyStopTx` (which returns the decrypted emergency-stop transaction for a given `move_to_vault_txid`, persisted via `insert_signed_emergency_stop_tx_if_not_exists` at [4](#0-3) ) without presenting any certificate.

Note that `client_verification=false` still keeps server-side TLS identity active (`ServerTlsConfig::new().identity(server_identity)` with no `client_ca_root`) [5](#0-4) , meaning the connection is encrypted but the client is never authenticated — exactly the scenario `Noop` is meant to represent, and exactly the scenario where the `Internal*` guard is dropped entirely rather than degraded gracefully.

### Impact Explanation
The emergency-stop transaction is a fully-signed, broadcastable N-of-N-signed Bitcoin transaction tied to a specific `move_to_vault_txid` [6](#0-5) . Premature disclosure lets an unprivileged attacker obtain and broadcast it ahead of its intended controlled-disclosure schedule, which can freeze the disposal path of the associated move-to-vault UTXO — matching the listed High-severity category "premature disclosure of a protocol commitment." This is repeatable for every deposit that has completed finalize and is not scoped to a single deposit or operator; the blast radius covers the entire deployment for as long as `client_verification=false`.

### Likelihood Explanation
Exploitation requires only network access to the aggregator's gRPC port and `client_verification=false` in the deployed `BridgeConfig`. No BTC cost, no key material, no privileged role, and no race condition are needed — a single unauthenticated gRPC call with `grpc-method: InternalGetEmergencyStopTx` (or any way of omitting/spoofing the header, since with `Noop` the header isn't even checked) suffices. The only gating factor is whether `client_verification=false` is used in a live deployment (a legitimate, supported configuration value, not a test-only artifact), so likelihood is directly tied to that operational choice.

### Recommendation
Enforce the `Internal*` authority check independent of the `client_verification` interceptor variant — e.g., always reject requests whose `grpc-method` starts with `Internal` unless the peer certificate equals `our_cert`, even in the `Noop` path, or refuse to start the server with `Internal*`-exposing services when `client_verification=false`.

#[tokio::test]
async fn internal_method_unauthenticated_with_noop_interceptor() {
    // 1. Build a BridgeConfig with client_verification = false.
    // 2. Start create_aggregator_grpc_server(config) (or create_grpc_server directly
    //    with the aggregator service) so that Interceptors::Noop is installed.
    // 3. Complete a deposit through finalize so that
    //    insert_signed_emergency_stop_tx_if_not_exists has stored an encrypted
    //    emergency-stop tx for a known move_to_vault_txid.
    // 4. From a bare tonic Channel with NO client certificate/identity configured,
    //    call InternalGetEmergencyStopTx(GetEmergencyStopTxRequest { move_to_vault_txid }).
    //
    // Assert (binding check):
    //   LHS = "caller reached Internal* method" == true (call succeeded)
    //   RHS = "caller presented cert == our_cert" == false (no cert presented)
    // Expected (secure) behavior: LHS should imply RHS, so the call must fail with
    // Status::unauthenticated(...).
    // Actual (vulnerable) behavior: response is Ok(GetEmergencyStopTxResponse { .. })
    // containing the decrypted emergency-stop transaction bytes.
    assert!(response.is_err(), "expected unauthenticated error, got successful GetEmergencyStopTxResponse");
}
