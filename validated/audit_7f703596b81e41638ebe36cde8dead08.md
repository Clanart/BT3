### Title
Unauthenticated `ReceivedOutput` bytes can report non-existent wallet funds - ([File: `networks/bitcoin/src/wallet/mod.rs`](https://github.com/serai-dex/serai/blob/018/networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts three independent claims from attacker-controlled bytes: the scalar offset, the declared `TxOut`, and the declared `OutPoint`. It performs no consistency check that the offset derives the output’s script and no check that the outpoint exists or contains that output. [1](#0-0) 

### Finding Description
Normally, `Scanner::scan_transaction` creates this invariant by selecting an offset only when it finds a matching `script_pubkey`, and by binding the returned output to the actual transaction’s txid and output index. [2](#0-1) 

The deserializer bypasses that derivation: it reads `offset`, `output`, and `outpoint` sequentially and immediately returns `Ok(ReceivedOutput)`. [1](#0-0)  As a result, bytes can describe a valid wallet script and a large value while naming a non-existent `OutPoint`; `ReceivedOutput::value` will then report the fabricated amount as spendable input value. [3](#0-2) 

`SignableTransaction::new` trusts the supplied `ReceivedOutput` when summing input funds and assigning prevouts. [4](#0-3)  `SignableTransaction::multisig` only checks that the offset-derived spend key matches the serialized `script_pubkey`; it does not verify that the referenced `OutPoint` exists or contained that exact output. [5](#0-4)  The signing machine then commits to those fabricated prevouts and outpoints in each Taproot sighash. [6](#0-5) 

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` can make the wallet report funds that are not spendable and cause threshold signers to produce a transaction spending a non-existent output. [7](#0-6)  This is a Medium-severity accounting integrity issue: the resulting transaction is invalid and cannot directly steal existing wallet funds, but it can corrupt balance accounting, consume signing rounds, and create apparently valid signatures over an unspendable transaction. [4](#0-3) 

### Likelihood Explanation
The attack only requires knowledge of a wallet script, which is normally public or otherwise observable, and the ability to supply serialized `ReceivedOutput` bytes. [1](#0-0)  It does not require controlling a validator, peer, RPC endpoint, private key, or an existing UTXO. [5](#0-4)  If `ReceivedOutput::read` is only used over authenticated local storage produced by `Scanner`, exploitability is reduced, but the API itself does not authenticate or re-establish the scanner’s invariant. [2](#0-1) 

### Recommendation
Do not deserialize `ReceivedOutput` objects as authoritative observations from untrusted bytes. Re-derive them with `Scanner::scan_transaction` or `Scanner::scan_block`, authenticate persisted scanner output, or pass sufficient context to validate that the encoded offset produces the encoded `script_pubkey`. [2](#0-1)  Existence and spendability must additionally be established from validated chain data rather than from the serialized `OutPoint` and `TxOut` fields themselves. [8](#0-7) 

### Proof of Concept
The following constructs bytes for a fake base-offset output paying to the wallet’s Taproot script but referencing a non-existent outpoint; deserialization succeeds and reports the fabricated value. [1](#0-0) 

```rust
// networks/bitcoin/src/wallet/mod.rs
use bitcoin::{
  consensus::encode::serialize,
  hashes::Hash,
  Amount, OutPoint, Transaction, TxOut, Txid,
};
use k256::Scalar;

// `group_key` is the even Taproot key passed to `Scanner::new`.
let script = p2tr_script_buf(group_key).unwrap();

let fake_txout = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: script.clone(),
};

let fake_outpoint = OutPoint::new(Txid::from_byte_array([0x41; 32]), 0);

let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes()); // offset 0
bytes.extend(serialize(&fake_txout));
bytes.extend(serialize(&fake_outpoint));

let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(received.value(), 1_000_000);
assert_eq!(received.output().script_pubkey, script);
assert_eq!(received.outpoint(), &fake_outpoint);
```

The fabricated object is accepted as an input by `SignableTransaction::new`, and `multisig` accepts it because the offset-derived key matches the script even though the outpoint does not exist. [4](#0-3) [5](#0-4)
