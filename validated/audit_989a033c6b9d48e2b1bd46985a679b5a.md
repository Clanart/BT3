### Title
SignableTransaction trusts attacker-supplied `ReceivedOutput` prevout data — TOCTOU-style check/use gap lets unverified UTXO claims be signed - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The Calibre CVE is a check-time/use-time race: the helper validated the requested mount at check time, but a different device was actually mounted. The analog in Serai's in-scope code is a validation/binding gap of the same shape in `SignableTransaction`: a `ReceivedOutput` — which can be built from raw attacker bytes via `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs:122` — asserts a triple `(offset, TxOut, OutPoint)`. `SignableTransaction::new` uses `input.output` (the claimed `TxOut`) for value accounting and later for `Prevouts::All`, and `input.outpoint` for the actual spend — but nothing verifies the `OutPoint` actually references a UTXO carrying the claimed `TxOut`. The only check, in `SignableTransaction::multisig`, confirms the *claimed* `prevouts[i].script_pubkey` matches the offset group key — i.e., it validates the claim against itself, not against the chain state. ### Finding Description
- `ReceivedOutput::read` (mod.rs:122) deserializes `offset`, `TxOut`, and `OutPoint` independently from untrusted bytes; there is no consistency or existence check.
- `SignableTransaction::new` (send.rs:175–185) sums `input.output.value` into `input_sat` (authorizing payments/fees against it) and sets each `TxIn.previous_output` to the claimed `outpoint`.
- `SignableTransaction::multisig` (send.rs:273–285) checks `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey`. This binds the *claimed script* to the offset key — the outpoint, and the claimed `value`, are never verified against any real UTXO.
- `TransactionSignMachine::sign` (send.rs:373–391) then produces FROST signature shares over `taproot_key_spend_signature_hash(i, &Prevouts::All(&self.tx.prevouts), Default)`, committing every signer to the fabricated prevout set.

The race-condition analog: validation ("check") is performed against one object (the self-claimed `TxOut`/`script_pubkey`), while the signature ("use") commits to a different reality (the actual chain UTXO set, which nobody consulted). The check and the use are satisfied by different states, exactly as the mount helper checked one device path and mounted another. [4](#0-3) 

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (an explicitly in-scope entry point) can:

1. Inflate `input_sat` with a fabricated prevout value, causing `SignableTransaction::new` to authorize payments/fees exceeding real funds — funds are reported received that are not spendable.
2. Cause the threshold signing group to emit valid shares and a completed transaction that can never confirm, because BIP-341 commits to `Prevouts::All`: the claimed `TxOut` value/script must match the real UTXO, and it does not. Every signing attempt built on the fabricated output produces an unconfirmable transaction, locking up whatever real inputs were co-spent in the same transaction until the plan is abandoned.
3. Point `previous_output` at an outpoint that doesn't pay the multisig at all (e.g., a nonexistent or foreign outpoint carrying the claimed Serai script), again yielding a signed-but-invalid transaction — signing of an unintended message in the sense that the produced signature is only meaningful for a transaction that cannot exist on-chain.

### Likelihood Explanation
`ReceivedOutput` is the currency of the scanner → scheduler → signer pipeline, and `read`/`serialize` exist precisely to transport it across trust boundaries (DB, network messages). Any path where a peer or untrusted store supplies these bytes reaches the bug with a single crafted blob; no collusion or validator status is needed. Severity is bounded to Medium: the signatures remain valid only for the fabricated sighash (no key recovery, no theft of confirmed funds), and the worst outcome is balance inflation plus unconfirmable-plan DoS rather than direct fund loss.

### Recommendation
Bind the check to reality at use time, not to the claim: before creating a `TransactionMachine`, verify each input's `OutPoint` resolves on-chain (or in the confirmed-output set maintained by `ScannerDb`) to a `TxOut` exactly equal to `input.output`. Equivalently, reconstruct `prevouts` from the canonical scanned-output record keyed by `outpoint` instead of trusting the `TxOut` carried inside `ReceivedOutput`. If deserialization is the boundary, `ReceivedOutput::read` should only produce a pending claim that is resolved (outpoint → TxOut) against verified chain data before `SignableTransaction::new` consumes it.

### Proof of Concept
```rust
use bitcoin::{absolute::LockTime, transaction::Version, Transaction, TxIn, TxOut, OutPoint, Amount, Sequence, Witness, ScriptBuf};
use frost::curve::Secp256k1;
use k256::{Scalar, ProjectivePoint};
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction, p2tr_script_buf};
use std::io::Write;

// Given the multisig group key `key`, craft bytes for ReceivedOutput::read:
// offset = 0, TxOut = { value: 100_000_000, script_pubkey: p2tr(key) },
// outpoint = arbitrary/foreign (e.g., attacker-controlled txid:vout or a fake one).
let mut bytes = Scalar::ZERO.to_bytes().to_vec();
bytes.extend(bitcoin::consensus::serialize(&TxOut {
  value: Amount::from_sat(100_000_000),
  script_pubkey: p2tr_script_buf(key).unwrap(),
}));
bytes.extend(bitcoin::consensus::serialize(&OutPoint { txid: fake_txid, vout: 0 }));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// SignableTransaction::new accepts it; input_sat is inflated by 1 BTC that doesn't exist.
let tx = SignableTransaction::new(
  vec![forged, real_small_output], // real_small_output is a genuine scanner output
  &[(payment_script, 50_000_000)], // a payment the real balance can't cover
  Some(change_script),
  None,
  fee_rate,
).unwrap();

// multisig() succeeds: prevouts[i].script_pubkey matches offset key for BOTH inputs,
// because the forged entry claims Serai's own script.
let machine = tx.clone().multisig(&keys).expect("multisig accepts forged prevout");

// Signing completes; the resulting transaction commits via Prevouts::All to the
// fabricated 1-BTC prevout and is rejected by every Bitcoin node.
```
No colluding signer is required — the poisoned input data alone makes every honest participant sign an unconfirmable transaction while the system accounts 1 BTC as received.

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
