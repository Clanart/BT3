### Title
DataLayer mirror URLs allow attacker-controlled SSRF via `dl_new_mirror` and `http_download`/`get_downloader` fetch pipeline - (File: chia/data_layer/data_layer_wallet.py, chia/data_layer/data_layer.py, chia/data_layer/download_data.py)

### Summary
Any wallet user can publish an arbitrary list of URLs on-chain for *any* DataLayer `launcher_id` (store id) via `create_new_mirror()`/`dl_new_mirror`, without proving ownership of that singleton. Other honest full-node/DataLayer services that subscribe to or mirror that same store will later read these attacker-supplied URLs from chain state and automatically issue outbound HTTP requests (or hand the URL to a downloader plugin) to fetch delta/full-tree files, with no validation that the URL points to a legitimate/expected host. This is the same bug class as CVE-2024-2057 (LangChain `TFIDFRetriever.load_local`): an untrusted, remotely-influenced string is used directly as a network fetch target, enabling SSRF.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a standard coin spend whose memo encodes `launcher_id` plus a caller-supplied list of URL bytes, with no check that the caller owns or controls that `launcher_id`'s singleton: [1](#0-0) 

This is invoked directly from wallet RPC `dl_new_mirror`, reachable by any authenticated wallet caller, and ultimately anyone who can submit a signed spend bundle for a coin they own: [2](#0-1) 

When any peer observes the resulting mirror coin on-chain, `DataLayerWallet.coin_added()` decodes `launcher_id, urls` from the parent spend and, if that launcher_id is a tracked/subscribed store, unconditionally stores the mirror record — there is no filtering of URL scheme or destination: [3](#0-2) 

The DataLayer service later pulls these attacker-controlled URLs (`update_subscriptions_from_wallet()` → `data_store.update_subscriptions_from_wallet()`) as the list of server URLs to try for that store: [4](#0-3) 

During the periodic sync loop, `fetch_and_validate()` shuffles the mirror server list and calls `insert_from_delta_file()` → `download_file()`, which either does an in-process `http_download()` GET request straight to `server_info.url + "/" + filename` or forwards the URL to a plugin's `/download`/`handle_download` endpoint: [5](#0-4) [6](#0-5) [7](#0-6) 

None of these layers validate the URL's host/scheme against an allowlist (e.g., blocking `localhost`, RFC1918 ranges, cloud metadata addresses like `169.254.169.254`, or non-http(s) schemes); the only checks are on the requested *filename* format (`is_filename_valid()`), not the destination host: [8](#0-7) 

Because publishing a mirror only costs the standard coin amount + fee and requires no relationship to the target store's owner, an attacker can force any node that subscribes/mirrors a given store to issue outbound requests to internal-network or metadata endpoints of their choosing, mirroring the SSRF pattern in the reported CVE where an untrusted path/URL is passed straight into a network-fetch primitive.

### Impact Explanation
This is a genuine server-side request forgery: an unprivileged wallet user (spend-bundle submitter) can cause other participants' full-node/DataLayer processes to make arbitrary outbound HTTP(S) requests. Depending on network topology this can be used to probe/exfiltrate internal services, hit cloud metadata endpoints (credential theft), or pivot into otherwise-unreachable internal admin/RPC interfaces exposed on the victim host or its private network. It does not directly produce unauthorized coin movement or consensus divergence, but it is a concrete confidentiality/network-boundary violation reachable purely through a normal wallet action (adding a mirror), which is why it is rated Medium.

### Likelihood Explanation
Likelihood is moderate-to-high for any deployment where operators run DataLayer with mirror subscriptions enabled and their own network is reachable from the process (which is common, since DataLayer services often run alongside other local services/RPC ports). The attack requires only: (1) spending an XCH coin to create a mirror transaction for a targeted `launcher_id` that some victim node subscribes to, and (2) waiting for the victim's periodic `periodically_manage_data()`/`fetch_and_validate()` cycle to select that mirror server. No special privilege beyond normal wallet spend capability is needed.

### Recommendation
- Validate mirror/server URLs before storing and before fetching: enforce `http`/`https` scheme, and reject requests to loopback, link-local (including `169.254.169.254`), and private/internal address ranges unless explicitly allowlisted by the operator.
- Consider requiring mirror URLs to be restricted at fetch time (in `http_download()` and `get_downloader()`) via DNS resolution + IP-range checks performed just before connecting, to prevent DNS-rebinding bypass of any earlier string-based checks.
- Optionally require operator opt-in per store id (or per URL domain) before DataLayer will automatically fetch from an unrecognized mirror URL discovered on-chain.

### Proof of Concept
1. Attacker identifies a `store_id` (launcher_id) that a victim's DataLayer node subscribes to/mirrors.
2. Attacker calls wallet RPC `dl_new_mirror` (`chia/wallet/wallet_rpc_api.py:3255`) with `launcher_id=<victim's tracked store>`, `urls=["http://169.254.169.254/latest/meta-data/", "..."]`, and a minimal `amount`/`fee`, then broadcasts the resulting spend bundle.
3. Once confirmed, victim's `DataLayerWallet.coin_added()` records the mirror (`chia/data_layer/data_layer_wallet.py:775-799`), and `update_subscriptions_from_wallet()` propagates the URL into `data_store` subscriptions (`chia/data_layer/data_layer.py:979-985`).
4. On the next `periodically_manage_data()`/`fetch_and_validate()` cycle, the victim's node calls `download_file()`/`http_download()` and issues an HTTP GET to the attacker-chosen URL (`chia/data_layer/download_data.py:110-168, 298-324`), completing the SSRF.

def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False
```

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
