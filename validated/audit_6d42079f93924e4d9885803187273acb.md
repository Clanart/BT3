### Title
Universal forgery of aggregated Schnorr signatures - (File: `crypto/schnorr/src/aggregate.rs`)

### Summary
`SchnorrAggregate::verify` accepts attacker-selected nonce points `Rs` and scalar `s`, but derives each aggregation weight only from the supplied signature challenges and not from the corresponding public keys or nonce points. [1](#0-0) 

### Finding Description
An aggregate is deserialized as an arbitrary length-prefixed vector of group elements followed by a scalar. [2](#0-1) 

During verification, only each challenge is appended to the transcript before `weight` is calculated. [3](#0-2) 

The verifier then checks `sum(z_i * R_i) + sum((z_i * c_i) * P_i) - sG == 0`. [4](#0-3) 

Because `z_i` does not bind `R_i` or `P_i`, an attacker can independently set every `R_i = -c_i * P_i` and `s = 0`, making every pair of terms cancel exactly. [5](#0-4) 

### Impact Explanation
An unprivileged party can create an aggregate signature that verifies for arbitrary public keys and challenges without knowledge of any corresponding private key. [2](#0-1) 

Any caller relying on `SchnorrAggregate::verify` as proof that the listed Schnorr signatures existed can therefore accept a forged aggregate for messages or transactions the listed keys never signed. [1](#0-0) 

### Likelihood Explanation
The attack requires only public keys, publicly computable Schnorr challenges, the verification DST, and arithmetic on public group elements. [6](#0-5) 

No nonce preimage, private key, validator cooperation, malformed encoding, or protocol edge case is needed. [2](#0-1) 

### Recommendation
Bind each complete verification statement—`R_i`, public key `P_i`, and challenge `c_i`—into the transcript used to derive its aggregation weight, or replace this aggregate verifier with the randomized `BatchVerifier` construction. [6](#0-5) 

Reject identity nonce points and add a regression test asserting that `R_i = -c_i * P_i, s = 0` does not verify. [1](#0-0) 

### Proof of Concept
For every supplied pair `(P_i, c_i)`, choose:

```rust
let R_i = -(P_i * c_i);
let s = C::F::ZERO;
```

Serialize these attacker-generated `R_i` values and `s` with `SchnorrAggregate::read`, then call:

```rust
forged.verify(dst, &keys_and_challenges)
```

Each queued pair contributes `z_i * (-c_i * P_i) + (z_i * c_i) * P_i = 0`, while `s = 0` contributes the identity, so `multiexp_vartime` returns identity and verification succeeds. [4](#0-3)
