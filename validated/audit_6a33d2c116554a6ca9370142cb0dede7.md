### Title
Missing zero-check on KIP-71 `GasTarget` causes big.Int divide-by-zero panic in `NextMagmaBlockBaseFee` - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` explicitly guards against `BaseFeeDenominator == 0` ("To avoid panic, set the fluctuation range small") but performs no equivalent guard for `GasTarget == 0`. When the parent block's gas usage exceeds the (zero) gas target, the function divides a `big.Int` by `SetUint64(gasTarget)` (i.e. zero), which panics, crashing any node that executes this code path — directly analogous to the CVE-2017-16650 divide-by-zero pattern (an unguarded divisor derived from configuration/input reaches a raw division operation).

### Finding Description
In `params/kip71_config.go`: [1](#0-0) 
the denominator is explicitly defaulted to `64` if zero to avoid a panic, but `gasTarget := kc.GasTarget` at line 77 is used unguarded: [2](#0-1) 
When `parentGasUsed > gasTarget` (true for any nonzero `parentGasUsed` if `gasTarget == 0`), the code computes:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // divide by zero -> panic
```
`math/big.Int.Div` panics on a zero divisor (there is no soft-fail return), so this crashes the calling goroutine/process.

This function is invoked from two reachable contexts:
1. Consensus header validation via `VerifyMagmaHeader`, called for every block: [3](#0-2) 
2. Public RPC-triggered fee estimation: `Oracle.processBlock` in `node/cn/gasprice/feehistory.go` calls `kip71Config.NextMagmaBlockBaseFee(...)` to compute `nextBaseFee` when serving `eth_feeHistory`/gas price RPC requests: [4](#0-3) 

`GasTarget` is a KIP-71/Magma governance parameter (`reward.ratio`-style parameter set via governance voting, `kaiax/gov`), so if a `GasTarget = 0` value is ever accepted into the effective parameter set (e.g., through a governance proposal, misconfiguration, or a validation gap not fully confirmed in this pass), **every full node and every RPC endpoint serving fee-history queries or validating the next Magma block header will panic and crash** as soon as a block with `gasUsed > 0` is processed or as soon as any public RPC caller invokes `eth_feeHistory` with reward percentiles for a range including such a block.

### Impact Explanation
A crash triggered on all nodes that adopt the corrupted parameter is a consensus-halting denial of service: block processing (`VerifyMagmaHeader`) and public RPC service (`eth_feeHistory`) both panic identically on every honest node, since the divide-by-zero is deterministic and not node-specific. This matches the "state divergence between honest nodes" / total-service-denial criteria (crash, not merely resource exhaustion).

### Likelihood Explanation
The trigger requires `GasTarget == 0` to be the active governance value. I could not confirm within this pass whether `kaiax/gov/param.go`'s parameter validation rejects `GasTarget = 0` when a governance vote is cast (the code references were found but not fully inspected). If validation elsewhere in `kaiax/gov` prevents `GasTarget == 0` from ever being committed, this bug is unreachable in production; if not, it is trivially triggerable by any governance vote (or a bug in the default/test config path), and subsequently by any ordinary transaction/block or any unprivileged RPC caller invoking `eth_feeHistory`.

### Recommendation
Add the same defensive guard used for `BaseFeeDenominator` to `GasTarget` in `NextMagmaBlockBaseFee` (e.g., default to a safe nonzero value or return an error/lower-bound base fee when `kc.GasTarget == 0`), and additionally enforce `GasTarget > 0` in the KIP-71 governance parameter validation path so this value can never reach consensus code as zero.

### Proof of Concept
1. Set (or allow, via a governance vote or misconfiguration) `KIP71Config.GasTarget = 0` while `BaseFeeDenominator` and other fields remain nonzero.
2. Produce/observe a block whose `GasUsed > 0` (any block with at least one transaction).
3. Any node calling `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` for that block, or any RPC client calling `eth_feeHistory` with `rewardPercentiles` covering that block, triggers:
```go
y := x.Div(x, new(big.Int).SetUint64(0))  // panics: division by zero
```
causing the node process to crash.

	}
	return nil
}
