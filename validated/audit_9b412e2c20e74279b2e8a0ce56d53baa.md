### Title
Payout Transaction OP_RETURN Not Covered by User's `SinglePlusAnyoneCanPay` Signature Allows Frontrunning to Steal Operator Reimbursement — (File: `core/src/builder/transaction/operator_reimburse.rs`)

---

### Summary

The payout transaction uses `TapSighashType::SinglePlusAnyoneCanPay` for the user's withdrawal signature. This sighash type commits only to the signed input (the withdrawal UTXO) and the output at the **same index** (output 0, the user's payout). It does **not** commit to the OP_RETURN output (output 2) that encodes the operator's xonly public key. A malicious registered operator can observe a pending payout transaction in the Bitcoin mempool, extract the user's valid signature, and rebroadcast a modified transaction with their own xonly public key in the OP_RETURN. If this transaction is mined first, the verifier records the attacker's operator as the payer, the attacker's operator claims the bridge vault reimbursement (`bridge_amount` BTC), and the legitimate operator who actually paid the user receives nothing.

---

### Finding Description

**Step 1 — Payout transaction construction**

`create_payout_txhandler` builds the payout transaction with three outputs:

```
Output 0: user's payout TxOut          ← covered by user's SinglePlusAnyoneCanPay sig
Output 1: anchor output                ← NOT covered
Output 2: OP_RETURN(operator_xonly_pk) ← NOT covered
``` [1](#0-0) 

The user's signature is enforced to be `SinglePlusAnyoneCanPay` in the parser: [2](#0-1) 

`SinglePlusAnyoneCanPay` = `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`. Under BIP-341 Taproot sighash rules, `SIGHASH_SINGLE` commits only to the output at the same index as the signed input; `SIGHASH_ANYONECANPAY` commits only to that one input. Outputs at other indices — including the OP_RETURN at index 2 — are **not** part of the signed digest.

**Step 2 — Operator broadcasts; attacker frontruns**

The legitimate operator (A) calls `withdraw()`, which funds the transaction with its own wallet inputs (signed `SIGHASH_ALL`) and broadcasts: [3](#0-2) 

A malicious registered operator (B) monitors the mempool, finds the pending payout transaction, and:

1. Extracts the user's `SinglePlusAnyoneCanPay` signature from input 0.
2. Constructs a new transaction:
   - Input 0: same withdrawal UTXO + copied user signature (valid, since `SinglePlusAnyoneCanPay` allows new inputs/outputs at other positions)
   - Input 1+: attacker's own fee inputs
   - Output 0: same user payout TxOut (unchanged — required for signature validity)
   - Output 1: anchor output
   - Output 2: `OP_RETURN(operator_B_xonly_pk)` ← **replaced**
3. Broadcasts with a higher fee rate.

**Step 3 — Verifier records attacker as payer**

When the attacker's transaction is mined, `update_finalized_payouts` parses the first OP_RETURN output and stores operator B's xonly pk as `payout_payer_operator_xonly_pk` in the `withdrawals` table: [4](#0-3) 

**Step 4 — Legitimate operator is locked out**

Operator A calls `get_reimbursement_txs`. `validate_payer_is_operator` reads `payout_payer_operator_xonly_pk` from the DB and finds operator B's key, not A's: [5](#0-4) 

Operator A receives `"Payer is not own operator for deposit"` and cannot proceed with any reimbursement flow.

**Step 5 — Attacker's kickoff passes maliciousness check**

Operator B sends a kickoff transaction using its own pre-signed kickoff connector (pre-signed by NofN during deposit). The verifier's `is_kickoff_malicious` check compares the OP_RETURN xonly pk against the kickoff's operator xonly pk: [6](#0-5) 

Since both are operator B's key, the check passes. The verifier does not challenge the kickoff.

**Step 6 — Attacker claims bridge vault**

Operator B waits for the challenge timeout, then sends the reimburse transaction. This transaction was pre-signed by the NofN during the deposit phase for every registered operator's kickoff connector: [7](#0-6) 

The reimburse transaction spends the move-to-vault UTXO (containing `bridge_amount` BTC) and sends it to operator B's `reimburse_addr`. Operator A, who actually paid the user, receives nothing.

---

### Impact Explanation

- **Operator A** loses `bridge_amount` BTC (paid the user, receives no reimbursement).
- **Operator B** steals `bridge_amount` BTC from the bridge vault (the deposited BTC).
- The bridge vault UTXO is drained to the wrong party.
- The user is unaffected (output 0 is unchanged).

With `BRIDGE_AMOUNT = 1_000_000_000` sats (1 BTC) per deposit, each successful frontrun costs the legitimate operator 1 BTC and drains 1 BTC from the bridge vault. The attack is repeatable for every pending payout transaction.

---

### Likelihood Explanation

- The attacker must be a **registered operator** (to possess pre-signed NofN reimburse transactions for the target deposit).
- The attacker must monitor the **Bitcoin mempool** for payout transactions (trivial with a full node).
- The attacker must be able to **outbid** the legitimate operator's fee rate (standard RBF).
- No cryptographic secret is required beyond what is publicly visible on-chain.
- The `aggregator_verification_address` check protects the gRPC call to `withdraw()` but does not protect the on-chain OP_RETURN content.

Likelihood: **Medium** (requires a malicious registered operator, but no privileged key compromise).

---

### Recommendation

1. **Bind the operator identity to the user's signed digest.** Include the operator's xonly public key as part of the output the user signs — for example, encode it in the `script_pubkey` of output 0 (e.g., a P2TR address derived from the operator's key), so that `SinglePlusAnyoneCanPay` covers it. Any substitution of the operator key would invalidate the user's signature.

2. **Alternatively, derive operator identity from the kickoff transaction**, not the payout OP_RETURN. The kickoff transaction is signed by the operator's key (spending a round UTXO specific to that operator), so it is unforgeable. The verifier's `is_kickoff_malicious` check could verify that the kickoff's operator key matches the operator who spent the withdrawal UTXO, rather than trusting the OP_RETURN.

3. **Short-term mitigation:** Require the user's signature to use `SIGHASH_ALL` (committing to all outputs including the OP_RETURN). This prevents adding fee inputs without re-signing, but the operator can pre-fund the transaction before requesting the user's signature.

---

### Proof of Concept

```
1. Deposit: bridge_amount = 1 BTC. NofN pre-signs reimburse txs for both Operator A and Operator B.

2. User creates withdrawal UTXO (dust), signs payout output with SinglePlusAnyoneCanPay.
   sig = sign(input=withdrawal_utxo, output=payout_txout, sighash=SinglePlusAnyoneCanPay)

3. User sends (withdrawal_id, sig, withdrawal_utxo, payout_txout) to Operator A.

4. Operator A calls withdraw():
   - Builds payout_tx:
       in[0]: withdrawal_utxo  (sig = user's SinglePlusAnyoneCanPay)
       in[1]: operator_A_fee_utxo  (sig = operator_A wallet SIGHASH_ALL)
       out[0]: payout_txout  (user receives BTC)
       out[1]: anchor
       out[2]: OP_RETURN(operator_A_xonly_pk)
   - Broadcasts to mempool.

5. Operator B observes mempool, extracts user's sig from in[0].

6. Operator B constructs replacement_tx:
       in[0]: withdrawal_utxo  (sig = copied user's SinglePlusAnyoneCanPay — still valid)
       in[1]: operator_B_fee_utxo  (sig = operator_B wallet SIGHASH_ALL)
       out[0]: payout_txout  (unchanged — required for sig validity)
       out[1]: anchor
       out[2]: OP_RETURN(operator_B_xonly_pk)  ← REPLACED
   - Broadcasts with higher fee rate.

7. replacement_tx mines first. Operator A's tx is rejected (withdrawal_utxo already spent).

8. Verifier's update_finalized_payouts:
   - Reads OP_RETURN → operator_B_xonly_pk
   - Stores: withdrawals[W].payout_payer_operator_xonly_pk = operator_B_xonly_pk

9. Operator A calls get_reimbursement_txs:
   - validate_payer_is_operator: payer=operator_B ≠ self=operator_A → ERROR

10. Operator B sends kickoff (using its own kickoff connector, pre-signed by NofN).
    - is_kickoff_malicious: OP_RETURN xonly_pk == kickoff operator_xonly_pk → NOT malicious
    - No challenge sent.

11. Operator B sends reimburse_tx (pre-signed by NofN):
    - Spends move_to_vault UTXO (1 BTC) → operator_B_reimburse_addr

Result: Operator B steals 1 BTC from bridge vault. Operator A loses 1 BTC.
```

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))

    /// Checks if the operator who sent the kickoff matches the payout data saved in our db
    /// Payout data in db is updated during citrea sync.
    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
