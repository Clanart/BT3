## Title
Git's recursive-clone protection is force-disabled when cloning untrusted URLs, exposing Desktop to the recursive-submodule-clone hook/config attack class (CVE-2024-32004-style) - (File: `app/src/lib/git/clone.ts`)

## Summary
`app/src/lib/git/clone.ts`'s `clone()` function unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` while invoking `git clone --recursive` for every repository URL the app clones — including URLs supplied through the `x-github-client://openRepo/...` protocol handler and `--cli-clone`, both of which are reachable by an attacker who controls only a link or a repository. This deliberately turns off the git core protection intended to stop a nested/recursive clone from acting on configuration, hooks, or paths supplied by an untrusted, attacker-controlled repository (the same trust-boundary class fixed upstream for recursive submodule clone attacks).

## Finding Description
Upstream Git ships defenses against a class of vulnerabilities where a malicious top-level repository, via `.gitmodules`, embeds a submodule whose URL/path is crafted so that a `git clone --recursive` operation is coerced into treating the untrusted, just-fetched repository as if it were locally trusted — e.g., picking up its `core.hooksPath`/hook scripts, or writing/overwriting files via crafted submodule paths that escape the intended clone root. `GIT_CLONE_PROTECTION_ACTIVE` is one of the internal signal points git uses to recognize and refuse these nested, potentially-hostile clone states.

Desktop's `clone()` overrides this signal to `'false'` on every single clone, regardless of whether the URL is a URL the user typed manually or one it received from an untrusted source (a deep link crafted by an attacker, or a URL passed via `--cli-clone`). The broken invariant mirrors the Particle report exactly: a safety check that is supposed to gate a dangerous operation on genuine trust/custody (here: "is this submodule content something we can safely act on with hooks/paths") is instead bypassed for convenience, and the surrounding guard that *does* exist (`isClonePathSensitive`) only protects the top-level destination directory, not the content pulled in recursively from the attacker's own repository.

## Impact Explanation
If exploitable end-to-end, this reduces Desktop's posture to the same one Git had before the recursive-clone/submodule hardening: an attacker who gets a victim to open an "Open in Desktop" deep link or clone a crafted URL (e.g., linked from a README, issue, or website — no local access, no admin rights, no leaked credentials required) can supply a repository whose submodule configuration is designed to escape the intended clone boundary. Depending on which specific check `GIT_CLONE_PROTECTION_ACTIVE` gates in the installed git version, disabling it could translate into hook execution or file writes tied to the untrusted nested repository during the clone — i.e., code execution or file write outside the intended repo root, matching the "Valid Impact" criteria (attacker controls a cloned/fetched repository; result is code execution or file write outside the repo).

## Likelihood Explanation
Likelihood is bounded by uncertainty over exactly which protection this specific environment variable disables in the bundled git version, and whether current git additionally enforces the same protection through means Desktop doesn't override (e.g., `protocol.file.allow`, `core.hooksPath` sandboxing already used elsewhere in the codebase via `with-hooks-env.ts`/`get-repo-hooks.ts`). What is certain from local code alone is that Desktop explicitly and unconditionally disables a git safety flag whose name directly signals "clone protection," for every clone including ones sourced from attacker-controlled URLs — this is a concrete, reachable code path, not a hypothetical.

## Recommendation
- Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override, or scope it narrowly with justification and an accompanying explicit test that documents exactly which upstream check is being bypassed and why it is safe.
- If the override exists for compatibility (e.g., avoiding a hard failure on legitimate recursive clones), fail closed instead: keep the protection enabled and only relax it after independently validating that all resolved submodule URLs/paths stay within the clone root (comparable to the `resolveWithin`/`sanitizeCloneName` guards already used elsewhere in this codebase).
- Add a regression test analogous to `app/test/unit/clone-path-safety-test.ts` that exercises a crafted `.gitmodules` submodule attempting to escape the clone root or reference `core.hooksPath`-executable content during `--recursive` clone, and assert it is rejected.

## Proof of Concept
Not independently verified end-to-end (would require constructing a submodule payload against the exact bundled git/dugite version and confirming the specific protection `GIT_CLONE_PROTECTION_ACTIVE` toggles). The concrete, verifiable evidence from local code is the unconditional override itself:
1. Host a public repository with a crafted `.gitmodules` entry designed to exploit the recursive-clone submodule hook/path-escape class that `GIT_CLONE_PROTECTION_ACTIVE` is meant to guard against.
2. Send the victim a link of the form `x-github-client://openRepo/<attacker-repo-url>` (handled by `parse-app-url.ts` → `dispatcher.ts` `openOrCloneRepository`) or have them run `GitHubDesktop.exe --cli-clone <attacker-repo-url>`.
3. Desktop calls `clone()` in `app/src/lib/git/clone.ts`, which clones `--recursive` with `GIT_CLONE_PROTECTION_ACTIVE` forced to `'false'`, disabling the protection that would otherwise stop the crafted submodule payload from taking effect. [5](#0-4) [6](#0-5)

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(

  options: CloneOptions,
