### Title
FROST cached preprocess (nonce seed) is never invalidated — repeat `sign` under the same context reuses nonces and leaks the validator's MuSig key share - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The kernel bug class here is "a state flag causes a check/cleanup path to be skipped, leaving a stale condition that corrupts a later operation" (`md_check_recovery` early-returns on `suspended`, so `MD_RECOVERY_RUNNING` is never cleared). The Serai analog lives in `SigningProtocol::preprocess_internal`: the FROST preprocess seed is stored in `CachedPreprocesses` keyed only by `context`, is reused on every call, and is never deleted or versioned by what was actually signed. Every call to `share_internal` rebuilds a deterministic `AlgorithmSignMachine` from the same seed, so `machine.sign(...)` runs with identical nonces each time the context repeats.

### Finding Description
`preprocess_internal` computes a `CachedPreprocess` seed once per `context` and persists it:

```rust
if CachedPreprocesses::get(self.txn, &self.context).is_none() {
  let (machine, _) = AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);
  ...
  CachedPreprocesses::set(self.txn, &self.context, &cache.0);
}
let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
...
let (machine, preprocess) =
  AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached));
``` [1](#0-0) 

`from_cache` → `seeded_preprocess` derives the nonces deterministically via `ChaCha20Rng::from_seed(*seed.0)`, so the same context always yields the same FROST nonces. [2](#0-1) 

`share_internal` then feeds attacker-influenced `serialized_preprocesses` and `msg` into `machine.sign(preprocesses, msg)` on every invocation — there is no check that the preprocess set or message matches the one already signed under this context, and the cached seed is never consumed/cleared. [3](#0-2) 

The concrete instantiation is `DkgConfirmer`, whose context is `(b"DkgConfirmer", self.attempt)` — only the attempt number, not the preprocess set or `key_pair` being confirmed. `DkgConfirmer::share` is invoked from `handle_application_tx` when processing `DkgConfirmer`-related signed transactions, with `preprocesses` and `key_pair` taken from the on-chain transaction data; `complete` also re-enters `share_internal`, calling `sign` a second time under the same context. [4](#0-3) 

The file's own safety argument (lines 25–55) explicitly acknowledges this is "explicitly unsafe to reuse nonces across signing sessions" and relies on BFT finality to guarantee the preprocess set and message are identical on every re-execution. But the messages fed to `sign` are not purely BFT-finalized constants: `DkgConfirmer::share` receives the `HashMap<Participant, Vec<u8>>` of preprocesses and the `KeyPair` from the transaction being handled. If two distinct signed transactions for the same `attempt` carry different preprocess sets (e.g., a different subset of participants, or different commitment bytes from the same participants) or a different `key_pair`, the coordinator signs twice with identical nonces under different binding factors/messages — exactly the "distinct received messages" condition the comment says must never happen, with no code-level guard enforcing it.

### Impact Explanation
FROST signature shares are linear in the nonce: `share = d + b·ρ + λ·s·c`-style relations mean two shares produced with the same nonce commitments but different binding factors `ρ` / challenges `c` (different participant sets or different `key_pair` messages) let an observer solve for `λ·s`, the validator's threshold secret share of the MuSig validator key. Since these keys are the root of trust used to confirm DKG results on-chain (`set_keys_message`), recovery of `t` validators' shares compromises the validator set's signing key. This is full key-share recovery, satisfying the critical impact criterion.

### Likelihood Explanation
Reachability requires two signed tributary transactions under the same DKG attempt that cause `share()`/`complete()` to be driven with distinct preprocess maps or distinct `key_pair`s. An unprivileged party cannot directly author tributary transactions — they must come from a validator — but a single validator publishing a malformed or second `DkgCommitments`/share transaction for the same attempt is within the model these routines defend against (the surrounding code already fatal-slashes misbehaving signers, showing signed txs are adversary-controlled inputs). Additionally, `complete()` unconditionally re-runs `share_internal` and `.expect`s it succeeds; any path where `share` succeeded for one preprocess set and `complete` is later driven by a transaction carrying a different set hits the reuse. The nonce is never marked spent, so the failure is deterministic once triggered. Medium likelihood, high-to-critical impact.

Uncertainty: I was not able to fully trace `handle_application_tx`'s `DkgConfirmer` call sites in `handle.rs` to confirm whether the preprocess map and `key_pair` are pinned to a single finalized value per attempt before `share`/`complete` run. If the tributary layer strictly enforces one canonical preprocess set per attempt, the exposure narrows to reorg/rebuild edge cases the comments already discuss (partial rebuilds reusing the same DB seed).

### Recommendation
- In `share_internal`, record a digest of `(sorted participants, preprocesses, msg)` alongside `CachedPreprocesses` on first use and fatal-slash / refuse to sign if a subsequent call under the same `context` presents different bytes — implement the "on-chain-preprocess-matches-presumed-preprocess check" the TODO at line 51–54 already calls for.
- Alternatively, delete (`take`) the `CachedPreprocesses` entry after a successful `sign`/`complete` for that context, and bind `key_pair` into the context tuple so a distinct confirmation target cannot share a nonce seed.
- Add a regression test that calls `share()` twice for one attempt with differing preprocess sets and asserts the second call errors rather than re-signing.

### Proof of Concept
Conceptual (requires a coordinator harness):

1. Validator `V` runs `DkgConfirmer::new(key, spec, txn, attempt=0)`; `share(preprocesses_A, key_pair_X)` is invoked during handling of one signed transaction. `preprocess_internal` stores seed `S` under `("DkgConfirmer", 0)` and `sign` emits share `σ₁` using nonces `d, e` derived from `S`.
2. A second signed transaction for the same attempt delivers `preprocesses_B` (a different participant subset or altered commitment bytes). `share(preprocesses_B, key_pair_X)` rebuilds the machine from the same `S` → identical `d, e` — but binding factors `ρ_i` (and possibly the challenge `c`) differ.
3. From the two published shares, compute `s·λ = (σ₁ − σ₂ − (d₁−d₂) − Σ ρ-differences) / (c₁ − c₂)` — with identical nonces this is a linear solve yielding the validator's key share.
4. Repeat against `t` validators to reconstruct the MuSig validator key and forge `set_keys` confirmations.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))

type DkgConfirmerSigningProtocol<'a, T> = SigningProtocol<'a, T, (&'static [u8; 12], u32)>;

pub(crate) struct DkgConfirmer<'a, T: DbTxn> {
  key: &'a Zeroizing<<Ristretto as Ciphersuite>::F>,
  spec: &'a TributarySpec,
  removed: Vec<<Ristretto as Ciphersuite>::G>,
  txn: &'a mut T,
  attempt: u32,
}

impl<T: DbTxn> DkgConfirmer<'_, T> {
  pub(crate) fn new<'a>(
    key: &'a Zeroizing<<Ristretto as Ciphersuite>::F>,
    spec: &'a TributarySpec,
    txn: &'a mut T,
    attempt: u32,
  ) -> Option<DkgConfirmer<'a, T>> {
    // This relies on how confirmations are inlined into the DKG protocol and they accordingly
    // share attempts
    let removed = crate::tributary::removed_as_of_dkg_attempt(txn, spec.genesis(), attempt)?;
    Some(DkgConfirmer { key, spec, removed, txn, attempt })
  }
  fn signing_protocol(&mut self) -> DkgConfirmerSigningProtocol<'_, T> {
    let context = (b"DkgConfirmer", self.attempt);
    SigningProtocol { key: self.key, spec: self.spec, txn: self.txn, context }
  }

  fn preprocess_internal(&mut self) -> (AlgorithmSignMachine<Ristretto, Schnorrkel>, [u8; 64]) {
    let participants = self.spec.validators().iter().map(|val| val.0).collect::<Vec<_>>();
    self.signing_protocol().preprocess_internal(&participants)
  }
  // Get the preprocess for this confirmation.
  pub(crate) fn preprocess(&mut self) -> [u8; 64] {
    self.preprocess_internal().1
  }

  fn share_internal(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let participants = self.spec.validators().iter().map(|val| val.0).collect::<Vec<_>>();
    let preprocesses =
      threshold_i_map_to_keys_and_musig_i_map(self.spec, &self.removed, self.key, preprocesses).1;
    let msg = set_keys_message(
      &self.spec.set(),
      &self.removed.iter().map(|key| Public::from(key.to_bytes())).collect::<Vec<_>>(),
      key_pair,
    );
    self.signing_protocol().share_internal(&participants, preprocesses, &msg)
  }
  // Get the share for this confirmation, if the preprocesses are valid.
  pub(crate) fn share(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
  ) -> Result<[u8; 32], Participant> {
    self.share_internal(preprocesses, key_pair).map(|(_, share)| share)
  }

  pub(crate) fn complete(
    &mut self,
    preprocesses: HashMap<Participant, Vec<u8>>,
    key_pair: &KeyPair,
    shares: HashMap<Participant, Vec<u8>>,
  ) -> Result<[u8; 64], Participant> {
    let shares =
      threshold_i_map_to_keys_and_musig_i_map(self.spec, &self.removed, self.key, shares).1;

    let machine = self
      .share_internal(preprocesses, key_pair)
      .expect("trying to complete a machine which failed to preprocess")
      .0;

    DkgConfirmerSigningProtocol::<'_, T>::complete_internal(machine, shares)
  }

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
