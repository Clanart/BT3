### Title
Stop-hook `consume_stop_state` unconditionally clears `touched_paths` on non-transient skips, letting a broken commit-ancestor / git-rebase chain permanently absorb a dangerous change into the next baseline without review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`consume_stop_state` always clears `touched_paths` as part of its locked read-then-clear snapshot, regardless of whether the Stop hook actually performs a review. For most "skip" outcomes in `handle_stop_hook` (empty review set, no source files, pathological diff, etc.) `restore_unreviewed_stop_state` is deliberately *not* called, so the emptied `touched_paths` causes the next `UserPromptSubmit` to treat the turn as "already reviewed" and overwrite `baseline_sha` with the current working-tree state — silently folding any unreviewed dangerous change into the new baseline.

### Finding Description
`consume_stop_state` snapshots and clears `touched_paths` unconditionally at the very start of every non-recursive Stop fire: [1](#0-0) 

`handle_stop_hook` calls it first, then computes the git-derived review set via `compute_v2_review_set` and, on most skip paths, exits without calling `restore_unreviewed_stop_state`: [2](#0-1) [3](#0-2) [4](#0-3) 

`restore_unreviewed_stop_state`'s own docstring states it exists only for "transient" reasons (API unreachable, HTTP error) — i.e. `_skip(10, restore=True)` is the *only* call site with `restore=True`: [5](#0-4) 

The key gap is in `compute_v2_review_set`: committed changes are only merged into `dirty_now` when `head_at_capture` is a strict git ancestor of the current HEAD: [6](#0-5) [7](#0-6) 

Normal git operations that rewrite history during a turn — `git rebase`, `git reset --hard` + `cherry-pick`, or a squash — make `head_at_capture` no longer an ancestor of the resulting HEAD. In that case the dangerous commit's files are excluded from `dirty_now` even though `changed_since` (diff against `baseline_sha`) still shows them as different, so `review_set = dirty_now ∩ changed_since` can end up empty despite a real dangerous change existing. `handle_stop_hook` then hits `_skip(9, ...)` ("empty review set") with `restore=False`.

At that point `touched_paths` has already been cleared by `consume_stop_state`. The next `UserPromptSubmit` checks only `state.get("touched_paths")` to decide whether to preserve the old baseline: [8](#0-7) 

Since `touched_paths` is empty, the preservation guard does not trigger, and `baseline_sha`/`head_at_capture` are overwritten with a fresh `git stash create` snapshot that already contains the dangerous, never-reviewed change. From that point on, every future Stop-hook diff is computed relative to this new baseline, so the dangerous change looks like pre-existing code and is never surfaced again.

The same failure mode applies to `_skip(8)` (pathological diff >`10*MAX_DIFF_FILES`, e.g. a large auto-generated/vendored diff burying one dangerous file) and `_skip(6)`/`_skip(7)` in less direct ways — none of these restore `touched_paths`, so all of them permit baseline advancement over unreviewed content on the very next prompt.

### Impact Explanation
This breaks the core invariant of the security-guidance Stop-hook review: "an attacker must not hide a dangerous change by shifting it outside the computed review window." Once the baseline silently advances past an unreviewed dangerous change (e.g., an injected shell command, unsafe deserialization, or backdoor), the LLM-based Stop-hook review — the mechanism that forces Claude to fix and exits with code 2 to block further progress — will never see that diff again. This is a direct, local, unauthorized-command-execution-adjacent bypass of Claude Code's automated review/deny gate, matching the "Unauthorized local command execution that bypasses Claude Code approval or deny controls" impact class.

### Likelihood Explanation
The precondition is limited to ordinary git operations available to anyone driving Claude in a cloned repo (rebase, reset+cherry-pick, squash-amend, or a single very large commit/diff) — no elevated privilege, credentials, or social engineering is required beyond getting Claude to perform (or being induced via repo content/prompt injection to perform) a history-rewriting git action during a turn. It is deterministically reproducible: any sequence that breaks `_is_ancestor(head_at_capture, current_head)` while leaving the working tree clean (or that produces a diff above the `10 * MAX_DIFF_FILES` bail threshold) reliably reaches `_skip(9)`/`_skip(8)` with `restore=False`, guaranteeing baseline capture of the unreviewed change on the next `UserPromptSubmit`.

### Recommendation
Only advance/overwrite `baseline_sha` in `handle_user_prompt_submit` when the previous Stop hook actually completed a real review (or determined there was truly nothing to review), not merely because `touched_paths` happens to be empty. Concretely:
- Have `consume_stop_state` return a distinguishing marker, or have `handle_stop_hook` call `restore_unreviewed_stop_state` (or an equivalent baseline-preserving call) for every skip reason where `review_paths`/`changed_since` indicate real content differs from baseline but wasn't reviewed — not just the "transient" (`_skip(10)`) case.
- In `compute_v2_review_set`, fall back to including `changed_since`-only files (not just `dirty_now`) when history was rewritten (`_is_ancestor` false) so committed-but-rewritten diffs aren't silently dropped from the review set.
- Treat `_skip(8)` (pathological diff) as "unreviewed" (restore=True) rather than a final skip, since it discards review of real changes rather than confirming there are none.

### Proof of Concept
Integration test in the Stop-hook test suite:
1. Initialize a git repo with one commit; capture `baseline_sha`/`head_at_capture` via `capture_git_baseline`/UPS simulation.
2. Add a dangerous line (e.g. `os.system(user_input)`) to a tracked file, `git commit`, then `git reset --hard <head_at_capture-unrelated-branch>` followed by `git cherry-pick` of the dangerous commit onto a divergent tip (or simply `git rebase --onto` another root) so that `_is_ancestor(head_at_capture, current_head)` is `False`.
3. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})` and assert `review_set` is empty even though `git diff baseline_sha -- <file>` shows the dangerous line as changed.
4. Invoke `handle_stop_hook` (or directly call `consume_stop_state` then simulate the `_skip(9)` path) and assert `touched_paths` is cleared and `restore_unreviewed_stop_state` was NOT called.
5. Simulate the next `handle_user_prompt_submit` call and assert `baseline_sha` in session state changed to a SHA that already contains the dangerous commit.
6. Run `compute_v2_review_set` again with the new baseline and assert the dangerous file is absent from the review set — proving the dangerous change is permanently unreviewable, which should fail (i.e., the fixed code must keep the dangerous file in the review set across this sequence).

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
