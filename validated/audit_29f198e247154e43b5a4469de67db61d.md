### Title
Permissionless `depositFor` in `WombatPoolHelperV2` allows griefing that permanently locks staked funds and rewards to an uncontrollable account - (File: wombat/WombatPoolHelperV2.sol)

### Summary
`WombatPoolHelperV2.depositFor()` lets **any caller** stake LP tokens on behalf of an **arbitrary `_for` address**, with no restriction on who that address is. Because withdrawal from this contract is always tied to `msg.sender` rather than an explicit account parameter, only the exact `_for` address can ever retrieve the staked principal and its accrued rewards. This mirrors the reported `HookTargetStakeDelegator` bug class: stake (and future rewards) gets attributed to an account whose ability to actually claim was never verified, so if that account cannot itself originate the specific withdrawal call, the funds and rewards become permanently stuck.

### Finding Description
`depositFor` pulls `depositToken` from `msg.sender`, deposits it into Wombat, and stakes the resulting LP receipt tokens into `MasterMagpie` on behalf of `_for`, with zero access control: [1](#0-0) 

The only way to later unwind that stake through this helper is `withdraw()`, which is hard-coded to use `msg.sender` as both the wombat-staking withdrawal beneficiary and the `MasterMagpie` unstake account: [2](#0-1) 

`_stake`/`_unstake` simply forward to `MasterMagpie.depositFor` / `withdrawFor` using the `_for`/`_sender` address supplied by the pool helper: [3](#0-2) 

`MasterMagpie.depositFor` only checks that the caller is a registered pool helper (`_onlyPoolHelper`); it never validates that the `_for` account is actually capable of interacting with the system to withdraw or harvest later: [4](#0-3) 

Compare this with `SimplePoolHelper.depositFor`, which restricts the caller with an `onlyAuthorized` modifier before staking on behalf of `_for`: [5](#0-4) 

`WombatPoolHelperV2` has no equivalent guard, so any unprivileged wallet can call `depositFor` and force a stake to be recorded for any address it chooses — including a contract address that has no function capable of calling `WombatPoolHelperV2.withdraw()` itself (e.g., a token contract, a non-EOA precompile-like address, or any contract lacking arbitrary call/proxy functionality). Rewards continue to accrue to that `_for` account inside `BaseRewardPool`/`MasterMagpie`'s `accMGPPerShare` accounting, but since the withdrawal path is bound to `msg.sender == _for`, nobody can ever trigger `MasterMagpie.withdrawFor` for that stake through this helper. This is the exact analog of the reported bug class: stake attributed to an account whose ability to reclaim it was never verified, resulting in principal and rewards permanently stuck.

### Impact Explanation
Any unprivileged wallet can force-stake tokens on behalf of an address that can never call `withdraw()` itself, permanently freezing both the deposited principal and all future MGP/bonus rewards that accrue to that stake inside `MasterMagpie` and its `BaseRewardPool`. This satisfies the "permanent freezing of funds" / "permanent freezing of unclaimed yield" impact bar, since there is no recovery path once locked to an unreachable `_for` account.

### Likelihood Explanation
The attack requires only calling a public, unauthenticated function (`depositFor`) with attacker-supplied tokens and an arbitrary `_for` address — no privileged role, no governance action, and no reliance on external/mocked components. It is directly reachable from an ordinary wallet transaction.

### Recommendation
Restrict `WombatPoolHelperV2.depositFor` the same way `SimplePoolHelper` does (e.g., an `onlyAuthorized`/allowlist modifier, or require `_for == msg.sender` unless caller is a trusted integrator contract), and/or decouple withdrawal authorization from `msg.sender` so that the true owner recorded at deposit time can always reclaim their stake and rewards regardless of which contract calls the helper.

### Proof of Concept
1. Attacker calls `WombatPoolHelperV2.depositFor(amount, victimContract)` supplying their own `depositToken`, where `victimContract` is a contract with no function able to call `WombatPoolHelperV2.withdraw()` (e.g., a plain ERC20 token contract or an immutable contract with no generic call capability).
2. `_deposit` stakes the resulting LP tokens via `MasterMagpie.depositFor(stakingToken, amount, victimContract)`, recording the stake under `victimContract`'s address. [6](#0-5) 
3. Rewards begin accruing to `victimContract` in `MasterMagpie`/`BaseRewardPool`.
4. Because `withdraw()` only ever unstakes for `msg.sender`, and `victimContract` cannot call it, the staked principal and all future rewards remain permanently locked with no recovery mechanism.
