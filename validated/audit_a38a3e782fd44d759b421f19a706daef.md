### Title
Duplicate GET-request fee payout: `dispatchTimeOut(GetRequestTimeout)` can pay the same relayer fee twice after a response was already delivered - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse,...)` pays the relayer fee out of `_requestCommitments[commitment]` on a successful GET response but never clears that commitment entry. `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` and `HandlerV2.handleGetRequestTimeouts` can later be executed for the *same commitment*, paying `meta.fee` a second time to the original payer, because neither function checks the host's local `_responseReceipts[commitment]` before honoring the timeout - only a non-membership proof against a possibly stale Hyperbridge state height. This lets fee-token funds escrowed in `EvmHost` be paid out twice for one GET request.

### Finding Description
`EvmHost.sol` stores GET request fee metadata in `_requestCommitments[commitment]` at dispatch time. Two independent code paths can drain that same fee:

1. On a successful response delivery, the fee is transferred to the relayer, but the commitment entry is **not deleted**: [1](#0-0) 

2. On timeout, the same `meta.fee`/`meta.sender` value is transferred again, and the commitment is only deleted for "replay protection" *before* the callback runs, then restored if the callback fails: [2](#0-1) 

The permissionless entrypoint `HandlerV2.handleGetRequestTimeouts` gates the timeout solely on: (a) `request.timeout() <= state.timestamp` at some *arbitrary previously-finalized* `message.height`, and (b) a non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX` for that commitment **against that specific past Hyperbridge state height**: [3](#0-2) 

Nowhere in this path is `host.responseReceipts(commitment)` (the origin/destination chain's own local record that the response was already delivered via `handleGetResponses` → `dispatchIncoming(GetResponse,...)`) consulted. Compare this to the Substrate ISMP timeout handler, which explicitly guards against exactly this by checking the local response receipt before allowing a timeout: [4](#0-3) 

Because Hyperbridge only stores/finalizes state at discrete heights, it is entirely possible for an already-elapsed request (`request.timeout() <= state.timestamp`) to still show a valid non-membership proof at an **earlier finalized height** than the height at which the response was actually recorded and later delivered to the origin chain. Any permissionless caller holding that older, still-retrievable state commitment (`host.stateMachineCommitment(height)`) and a corresponding non-membership proof can submit `handleGetRequestTimeouts` for a commitment whose response has *already* been delivered and rewarded on the origin EVM host.

### Impact Explanation
This is a direct double-settlement/fund-loss bug: the same escrowed `feeToken()` fee for one GET request is paid out twice from `EvmHost` - once to the delivering relayer via `dispatchIncoming(GetResponse,...)`, and again to `meta.sender` via `dispatchTimeOut(GetRequestTimeout,...)`. Because `_requestCommitments[commitment]` is never cleared on the successful-response path, and no cross-check against `_responseReceipts[commitment]` exists in the timeout path, `EvmHost`'s feeToken balance is drained by the extra payout, and the "one-time receipt handling" invariant required for request/response/timeout paths is broken. This falls squarely under "stealing or loss of funds" and "replay/double-claim/double-settlement" per the bounty scope.

### Likelihood Explanation
No malicious relayer, prover, or governance actor is required - a permissionless caller only needs to submit a valid, honestly-generated Merkle/non-membership proof against a real (older) finalized Hyperbridge state height, something that occurs naturally whenever GET response processing on Hyperbridge lags behind a request's nominal timeout (a realistic and even common condition under network congestion). Both `handlePostRequestTimeouts`... err specifically `handleGetRequestTimeouts` and `dispatchIncoming(GetResponse,...)` are public/permissionless entrypoints restricted only to `IHost`'s handler role, which any relayer can invoke.

### Recommendation
- Delete (or zero out) `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse,...)` immediately after paying the relayer fee, mirroring the replay-protection pattern already used in `dispatchTimeOut`.
- Additionally, have `HandlerV2.handleGetRequestTimeouts` (or `EvmHost.dispatchTimeOut(GetRequestTimeout,...)`) explicitly reject the timeout if `host.responseReceipts(commitment).relayer != address(0)`, matching the Substrate host's `GetResponseAlreadyReceived` guard.

### Proof of Concept
1. Dispatch a GET request with `fee > 0`; `_requestCommitments[commitment] = {sender: payer, fee: F}` is stored (`evm/src/core/EvmHost.sol` dispatch path).
2. Hyperbridge answers slowly: it finalizes state height `H1` (timestamp already ≥ `request.timeout()`) before it has processed/stored the GET response commitment, then later at height `H2 > H1` records and finalizes the response.
3. A relayer delivers the response via `handleGetResponses` → `dispatchIncoming(GetResponse,...)` proven against `H2`; fee `F` is paid to the relayer, but `_requestCommitments[commitment]` remains set (`sender: payer, fee: F`).
4. Any caller (can be the same relayer) now submits `handleGetRequestTimeouts` using the still-available, previously finalized height `H1` together with a non-membership proof of the response receipt at `H1` (valid, since the response wasn't recorded yet at that height) and `request.timeout() <= state(H1).timestamp` holds.
5. `dispatchTimeOut(GetRequestTimeout,...)` executes `onGetTimeout` successfully and pays `F` again to `payer` (`meta.sender`), completing a second payout of the same escrowed fee from `EvmHost`'s `feeToken()` balance.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
