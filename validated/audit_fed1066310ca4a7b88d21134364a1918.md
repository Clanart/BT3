### Title
`sendNative` in the EVM Bank precompile bypasses `SendEnabled`, denom allow-list, and blocked-address checks enforced by `MsgSend` - (File: precompiles/bank/bank.go)

### Summary
The externally reported bug describes a pattern where one code path checks a pause/restriction flag before moving funds while a functionally equivalent path omits that same check. Sei-chain's EVM Bank precompile exhibits the same class of bug: the `send` method correctly routes through the bank `MsgServer`, which enforces `SendEnabled`, denom allow-list, and blocked-address protections, but the `sendNative` method calls the bank keeper's low-level transfer function directly and skips all of these checks.

### Finding Description
The bank module's `MsgServer.Send` handler enforces three security checks before moving coins: `IsSendEnabledCoins` (governance-controlled pause of transfers per-denom or globally), `IsInDenomAllowList` (sender/receiver allow-list enforcement), and `BlockedAddr` (protection of module/reserved accounts) — all performed before calling `k.SendCoins`. [1](#0-0) 

The EVM Bank precompile's `send` method (ERC20-style transfer) correctly routes through this same `MsgServer.Send`, inheriting all three protections. [2](#0-1) 

However, the precompile's `sendNative` method — used to move native `usei`/wei value attached to an EVM call — calls `p.bankKeeper.SendCoinsAndWei` directly, never going through `MsgServer.Send` and never invoking `IsSendEnabledCoins`, `IsInDenomAllowList`, or `BlockedAddr`. [3](#0-2) 

This mirrors exactly the reported bug class: a security gate (pause/allow-list/blocklist) is implemented in one transfer function (`send`/`MsgSend`) but omitted in a parallel transfer function (`sendNative`) that reaches the same underlying fund-movement primitive.

### Impact Explanation
If governance or the chain disables sending of `usei` (or any denom) via `SendEnabled=false`, restricts transfers via the denom allow-list, or protects specific addresses (e.g., module accounts) via `BlockedAddr`, any EVM transaction sender can still bypass all of these restrictions by calling the Bank precompile's `sendNative` function with attached value, since it talks to `SendCoinsAndWei` directly instead of through `MsgServer.Send`. This is an unauthorized-transfer-via-precompile bypass of an admin/governance-configured pause and address-restriction mechanism, reachable from a plain EVM transaction.

### Likelihood Explanation
Any unprivileged EVM transaction sender can trigger this by calling the Bank precompile at `0x0000000000000000000000000000000000001001`'s `sendNative` method with a non-zero `msg.value`, so it is highly reachable — it requires no special privileges, only that governance has (or will) pause/restrict transfers via the standard bank module mechanisms that are expected to apply uniformly.

### Recommendation
Update `sendNative` in `precompiles/bank/bank.go` to perform the same `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` checks (or route through the bank `MsgServer`/an equivalent guarded keeper call) before invoking `SendCoinsAndWei`, so that governance-level pause and address restrictions apply consistently across all fund-movement entry points.

### Proof of Concept
1. Governance sets `bank` module params with `DefaultSendEnabled=false` (or blocks a specific denom/pauses transfers), intending to halt all native-token transfers.
2. An attacker calls the Bank precompile (`0x1001`) `sendNative(receiver)` with non-zero `msg.value` from any EVM account.
3. `precompiles/bank/bank.go`'s `sendNative` calls `p.bankKeeper.SendCoinsAndWei` directly [4](#0-3) , which does not check `IsSendEnabledCoins`/`IsInDenomAllowList`/`BlockedAddr`, so the transfer succeeds despite the governance-enacted pause/restriction — whereas the same transfer attempted via the regular `send` method or a native `MsgSend` would be rejected.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)

func (p PrecompileExecutor) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
	}
	accExists := p.accountKeeper.HasAccount(ctx, receiverSeiAddr)
	if !accExists {
		defer metrics.RecordBankNewAccount(ctx.Context())
		p.accountKeeper.SetAccount(ctx, p.accountKeeper.NewAccountWithAddress(ctx, receiverSeiAddr))
	}

	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		remainingGas := pcommon.GetRemainingGas(newCtx, p.evmKeeper)
		if hooks.OnEnter != nil {
			hooks.OnEnter(evm.GetDepth()+1, byte(vm.CALL), caller, p.evmKeeper.GetEVMAddressOrDefault(newCtx, receiverSeiAddr), []byte{}, remainingGas, value)
		}
		defer func() {
			if hooks.OnExit != nil {
				hooks.OnExit(evm.GetDepth()+1, []byte{}, 0, nil, false)
			}
		}()
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
