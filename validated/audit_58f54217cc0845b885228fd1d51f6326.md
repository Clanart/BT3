### Title
Data Layer mirror-URL fetch (`http_download`) has no host/IP allowlisting and follows redirects blindly — SSRF from an untrusted store owner into any subscribing DataLayer node's network - (File: chia/data_layer/download_data.py)

### Summary
`DataLayer.fetch_and_validate()` pulls the list of mirror URLs for a subscribed store from `DataStore.get_available_servers_for_store()` and, for each `ServerInfo.url`, calls `insert_from_delta_file()` → `download_file()` → `http_download()`. These URLs originate from on-chain `Mirror` coin data that any wallet can publish for a store id (`DLNewMirror`), i.e. they are attacker-controlled input from the perspective of every other node that subscribes to that store. `http_download()` issues the request with a plain `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` with no scheme/host/IP validation whatsoever, and aiohttp's default `allow_redirects=True` is left in effect, so even if a URL filter existed it would be bypassed by a redirect the same way GHSA-9qhg-99ww-9mqc describes for `utcp-http`. This is a stronger variant of that bug class: there is no first-hop validation at all, not just a missing redirect re-check.

### Finding Description
`chia/data_layer/download_data.py::http_download()` performs the outbound fetch: [1](#0-0) 
There is no check of `server_info.url`'s scheme, hostname, or resolved IP before the request is made, and no re-validation of the `Location` header before aiohttp auto-follows a redirect.

This URL is not operator-configured; it comes from `DataLayer.fetch_and_validate()`, which enumerates mirror servers per store from local storage: [2](#0-1) 

Mirror URLs are populated on-chain by the store owner via the `DLNewMirror`/mirror-coin mechanism in `chia/data_layer/data_layer_wallet.py` (the `Mirror` coin carries the URL data that propagates to any node tracking/subscribing to that store id), meaning any Chia Data Layer participant who owns (or forges data for) a store can set the mirror URL other users' nodes will fetch from — a completely untrusted, remote-attacker-controlled string reaching `http_download()`. A benign-looking `https://` URL passes trivially (there's no check at all), and the attacker's server can then `30x`-redirect the victim's DataLayer node to an internal/link-local/metadata address; aiohttp follows it automatically.

The downloaded bytes are then written to disk and handed to `DataStore.insert_into_data_store_from_file()` for parsing: [3](#0-2) 
Even when the resulting content fails to validate as a proper delta file against the wallet-advertised root (which it normally would, since it's not real delta-file content), the outbound HTTP GET to the internal target has already fired, and any information leakable via timing/exceptions/logs from the attempted parse is a secondary exposure. The primary, concrete impact is the SSRF request itself being made against the victim node's internal network on attacker command.

### Impact Explanation
Any Data Layer client subscribing to a store controlled (or previously controlled/re-mirrored) by an attacker can be made to issue arbitrary outbound HTTP requests — including to cloud metadata services, internal admin endpoints, or other loopback/link-local services reachable from the victim's host — with zero URL filtering and automatic redirect-following. This is a High-severity SSRF primitive reachable purely by an unprivileged Data Layer participant setting a mirror URL for a store that other honest nodes subscribe to; no privileged network position or protocol-level attack is required.

### Likelihood Explanation
Likelihood is high for any node that runs Data Layer and subscribes to stores whose mirrors are not fully trusted (the entire point of DataLayer mirror/subscription is to fetch from third-party-supplied URLs). `periodically_manage_data()` runs this fetch loop automatically in the background for all subscribed stores, so exploitation requires no additional user action beyond subscribing to (or already being subscribed to) an attacker-influenced store id.

### Recommendation
Before issuing any `http_download()`/`get_downloader()` request, validate `server_info.url`/`downloader.url` (reject non-HTTPS to non-loopback hosts, resolve and reject private/link-local/loopback/metadata IP ranges unless explicitly local), and disable aiohttp's automatic redirect following (`allow_redirects=False`), re-applying the same validation to every `Location` header before manually following it (capping the number of hops), mirroring the fix pattern used by `utcp-http` 1.1.4's `safe_request_with_redirects`.

### Proof of Concept
1. Attacker creates/owns a DataLayer store and registers a mirror whose URL is `https://attacker.example/x` (passes because there is no validation at all).
2. A victim node subscribes to that store id and periodically calls `fetch_and_validate()` → `download_file()` → `http_download()`, issuing `GET https://attacker.example/x/<delta-filename>`.
3. Attacker's server responds `302 Location: http://169.254.169.254/latest/meta-data/...` (or any victim-internal LAN address).
4. aiohttp (default `allow_redirects=True`) transparently follows the redirect from the victim node and fetches the internal resource; the response bytes are written to `target_filename_path` and fed into `insert_into_data_store_from_file()` on the victim's machine — the outbound SSRF request against the victim's internal network has already been executed regardless of downstream validation outcome. async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
