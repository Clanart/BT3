# Analog Assessment: Missing Redaction Enforcement in `MessageDifferencer`'s `StreamReporter::PrintValue`

### Title
Sensitive Fields Marked `debug_redact=true` Are Not Redacted in `MessageDifferencer::StreamReporter` Diff Output - (File: `src/google/protobuf/util/message_differencer.cc`)

### Summary
The Liferay report's failed invariant is: a value the application intends to protect from exposure (an LDAP credential) reaches a diagnostic/logging-adjacent channel (a paginated URL, subject to being recorded in server/proxy logs) because one specific code path failed to apply the same protection guaranteed elsewhere. The Protobuf analog is `google.protobuf.FieldOptions.debug_redact`/`TextFormat`'s redaction mechanism, whose entire purpose is to keep annotated sensitive fields out of human-readable diagnostic output such as logs [1](#0-0) . `TextFormat::Printer::PrintFieldValue` (the path used by `DebugString()`/`ShortDebugString()`/`StringifyMessage`) unconditionally calls `TryRedactFieldValue` before emitting a field's value [2](#0-1) . However, `MessageDifferencer::StreamReporter::PrintValue` — the reporter used by `MessageDifferencer::ReportDifferencesToString`/`ReportDifferencesTo` to render human-readable diffs of two messages — calls the standalone static `TextFormat::PrintFieldValueToString(message, field, index, &output)` directly [3](#0-2) , bypassing the `Printer`-instance redaction check entirely.

### Finding Description
`debug_redact` is documented and tested (`RedactedFields`, `DebugFormatTest`, `AbslStringifyTest`) as the mechanism protecting sensitive fields (e.g., credentials, PII) from appearing in debug/diagnostic text output [4](#0-3) . The core check lives in `TextFormat::Printer::TryRedactFieldValue`, gated by the `redact_debug_string_` flag on a `Printer` instance, and is invoked from `Printer::PrintFieldValue` [5](#0-4)  as well as from the Java equivalent `shouldRedact`/`printFieldValue` [6](#0-5) .

`MessageDifferencer::StreamReporter::PrintValue`, which is invoked from `ReportAdded`, `ReportDeleted`, `ReportModified`, `ReportMoved`, and `ReportMatched` [7](#0-6) , prints scalar field values via `TextFormat::PrintFieldValueToString` — a free-standing static utility declared separately from the `Printer` class and not wired through `TryRedactFieldValue` or any `redact_debug_string_`-equivalent flag [8](#0-7) . Message-typed fields are rendered via `PrintShortTextFormat`, which similarly is not shown here to go through a `Printer` configured with redaction enabled. As a result, when application code compares two protobuf messages containing `debug_redact=true` fields (e.g., request/response snapshots containing credentials or tokens) and logs the resulting diff via `ReportDifferencesToString`/`StreamReporter`, the sensitive values are emitted in plaintext — exactly the class of failure in the Liferay report: a value protected in one presentation channel (there: the normal auth flow; here: `DebugString()`/`AbslStringify`) leaks through an adjacent, less-scrutinized channel (there: the paginated URL/logs; here: the diff reporter) that developers reasonably assume shares the same protection.

### Impact Explanation
If an application uses `debug_redact` to mark sensitive fields (credentials, tokens, PII) trusting that this annotation universally suppresses their appearance in diagnostic/log output, and separately uses `MessageDifferencer` (e.g., for audit-diffing configuration or request objects, a common pattern) with `ReportDifferencesToString`/`StreamReporter` piped into logs, the sensitive values are disclosed in log output despite the redaction annotation. This matches CWE-200/CWE-522 (information exposure of credential/sensitive data), consistent with the Medium severity of the original report.

### Likelihood Explanation
This requires: (1) a message schema marking sensitive fields `debug_redact=true`; (2) application code that both relies on this redaction guarantee and separately uses `MessageDifferencer`'s human-readable reporting on messages containing such fields; (3) that diff output being logged/retained. This is a plausible but non-default combination — it depends on the consuming application choosing to diff and log messages that carry `debug_redact`-annotated fields, rather than being reachable purely through binary/ProtoJSON parsing of attacker-controlled input. No attacker-controlled bypass of a wire-format check is involved; the gap is an inconsistency between two separate "print message" code paths within the library.

### Recommendation
Route `MessageDifferencer::StreamReporter::PrintValue` (and any other internal helper printing field values for human consumption, e.g., `PrintShortTextFormat` calls within it) through a `TextFormat::Printer` instance with redaction enabled (equivalent to `redact_debug_string_ = true`), so that fields marked `debug_redact=true` are consistently redacted across every diagnostic-output code path in the library, not only `DebugString()`/`AbslStringify()`. Alternatively, explicitly document that `MessageDifferencer` diff reports are not covered by `debug_redact` and must not be used on messages containing sensitive fields, or add a client-visible option to opt into redacted diff output.

### Proof of Concept
This is a code-path/logic analysis rather than an executed reproduction (no test run was performed, consistent with the tool limitations of this review). A concrete verification would involve, given the trusted schema `RedactedFields` (`optional_redacted_string` marked `debug_redact = true`) [9](#0-8) :
1. Construct two `RedactedFields` messages differing only in `optional_redacted_string` (e.g., `"secret1"` vs `"secret2"`).
2. Call `util::MessageDifferencer differencer; differencer.ReportDifferencesToString(&output); differencer.Compare(msg1, msg2);`.
3. Inspect `output` and confirm it contains the literal values `"secret1"`/`"secret2"` rather than `[REDACTED]`, contrasted with `DebugFormat.multiline().toString(message)` on the same message, which is asserted in existing tests to redact the field [10](#0-9) .

I could not directly inspect the body of `TextFormat::PrintFieldValueToString` in `text_format.cc` (only its call sites and declaration were retrieved) to confirm with certainty that it never applies redaction internally; this should be verified by a background agent with full file access before treating this as a confirmed, fixable defect.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

void MessageDifferencer::StreamReporter::ReportModified(
    const Message& message1, const Message& message2,
    const std::vector<SpecificField>& field_path) {
  if (!report_modified_aggregates_ && field_path.back().field == nullptr) {
    if (field_path.back().unknown_field_type == UnknownField::TYPE_GROUP) {
      // Any changes to the subfields have already been printed.
      return;
    }
  } else if (!report_modified_aggregates_) {
    if (field_path.back().field->cpp_type() ==
        FieldDescriptor::CPPTYPE_MESSAGE) {
      // Any changes to the subfields have already been printed.
      return;
    }
  }

  printer_->Print("modified: ");
  PrintPath(field_path, true);
  if (CheckPathChanged(field_path)) {
    printer_->Print(" -> ");
    PrintPath(field_path, false);
  }
  printer_->Print(": ");
  PrintValue(message1, field_path, true);
  printer_->Print(" -> ");
  PrintValue(message2, field_path, false);
  printer_->Print("\n");  // Print for newlines.
}
