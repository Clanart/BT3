## Finding [1](#0-0) 

### Title
Reward Accounting Relies on Manipulable Raw Token Balance, Allowing Permanent Dilution of Unclaimed Yield via Direct Token Donation - (File: rewards/MasterMagpie.sol)

### Summary
`MasterMagpie._calLpSupply()` computes the pool's share denominator for MGP-emission accrual as the raw ERC20 balance of the staking/receipt token held by the contract, rather than the sum of tracked user deposits (`user.amount`). This mirrors the class of bug in the Spartan Protocol exploit, where LP share accounting trusted a manipulable pool-state value instead of an internally tracked accounting variable, allowing an attacker to distort share math with a plain token transfer/swap rather than through the intended deposit path.

### Finding Description
`updatePool()` accrues MGP rewards per pool using: [2](#0-1) 

`lpSupply` is obtained from `_calLpSupply(_stakingToken)`, which for any staking token other than `vlmgp`/`mWomSV` returns `IERC20(_stakingToken).balanceOf(address(this))`: [1](#0-0) 

This balance is not gated behind `deposit()`/`depositFor()` — it is the literal ERC20 balance of MasterMagpie. Because the receipt tokens minted by `WombatStaking` (and other staking tokens registered in MasterMagpie) are standard transferable ERC20 tokens returned to depositors, [3](#0-2)  any unprivileged wallet holding such a receipt token can call `transfer()` directly to the MasterMagpie contract address, inflating `balanceOf(address(this))` without incrementing any `user.amount` in `userInfo`. The subsequent `updatePool()` call then divides the fixed per-second MGP emission (`mgpReward`) by this artificially inflated `lpSupply`, permanently reducing `accMGPPerShare` growth for that time window for every legitimately staked user in the pool — with no compensating mechanism to recover the "lost" emission later, since `accMGPPerShare` only ever increases monotonically based on elapsed time and the (poisoned) `lpSupply` at each `updatePool()` call.

### Impact Explanation
Any legitimate staker's future MGP (and MGP-denominated) yield accrual is permanently and irrecoverably diminished each time this donation occurs, because the affected time-window's `mgpReward` is diluted across an inflated denominator and never re-computed. This is a permanent freeze/loss of a portion of unclaimed yield for all depositors in the targeted pool, repeatable indefinitely by any wallet holding transferable receipt tokens, at low cost to the attacker (a simple `transfer()` — no flashloan or governance privilege needed).

### Likelihood Explanation
The attack requires only an unprivileged wallet holding the standard, transferable receipt/staking ERC20 token registered with MasterMagpie and a plain `transfer()` call to the MasterMagpie contract address — no special permissions, no external protocol dependency, and it is repeatable at will by anyone.

### Recommendation
Track `lpSupply` internally (e.g., a `pool.totalStaked` counter incremented/decremented only inside `_deposit`/`_withdraw`) instead of deriving it from the live ERC20 `balanceOf(address(this))`, so that unsolicited direct token transfers cannot affect reward-per-share accounting.

### Proof of Concept
1. Pool `P` has staking token `S` (a transferable receipt token) registered in MasterMagpie with some legitimate stakers holding `user.amount` totaling `X`.
2. An attacker who holds `S` (e.g., previously deposited and later acquired more via transfer/DEX, or simply owns some `S` without ever calling `deposit`) calls `IERC20(S).transfer(masterMagpieAddress, Y)` directly, bypassing `deposit()`/`depositFor()`.
3. `balanceOf(address(this))` for `S` is now `X + Y`, but no `userInfo` entry changed.
4. On the next `updatePool(S)` call (triggered by any subsequent deposit/withdraw/harvest by any user), `lpSupply = X + Y`, and `pool.accMGPPerShare` accrues at a diluted rate: `mgpReward * 1e12 / (X + Y)` instead of `mgpReward * 1e12 / X`.
5. This dilution is permanent for that elapsed time window; legitimate stakers' `_calNewMGP` yields based on the diluted `accMGPPerShare` forever after, with no path to recover the difference.
