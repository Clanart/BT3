### Title
Unhandled `NoMethodError` crash in HMAC verification when `X-Shopify-Hmac-Sha256` header is omitted - (File: lib/shopify_app/controller_concerns/payload_verification.rb)

### Summary
`ShopifyApp::PayloadVerification#hmac_valid?`, used by both `ShopifyApp::WebhookVerification` and `ShopifyApp::ExtensionVerificationController`, passes the raw (possibly `nil`) `X-Shopify-Hmac-Sha256` header directly into `ActiveSupport::SecurityUtils.secure_compare` without checking presence first. When an anonymous caller omits the header entirely, this raises an unhandled `NoMethodError` instead of returning `401`/`403`, matching the reported bug class of "invalid input causes an unhandled crash instead of a controlled rejection."

### Finding Description
`hmac_valid?` reads the HMAC header via `shopify_hmac`: [1](#0-0) 

`shopify_hmac` simply returns `request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]`, which is `nil` if the header is not sent at all: [2](#0-1) 

`hmac_valid?` then calls `ActiveSupport::SecurityUtils.secure_compare(shopify_hmac, ...)`. That method's implementation computes `a.bytesize == b.bytesize && ...`; when `a` is `nil`, calling `.bytesize` on `nil` raises `NoMethodError: undefined method 'bytesize' for nil`. Neither `WebhookVerification#verify_request` nor `ExtensionVerificationController#verify_request` rescues this: [3](#0-2) [4](#0-3) 

Both endpoints are reachable by anonymous/unrelated HTTP callers — the webhook receiver and extension verification controller are designed to be called by unauthenticated external parties (Shopify servers normally, but nothing prevents any client from POSTing) prior to any authentication check, since HMAC validation is itself the authentication gate: [5](#0-4) 

The existing test suite only exercises the "wrong HMAC value present" case, not the "header absent" case, so this gap is untested: [6](#0-5) 

### Impact Explanation
An anonymous attacker can repeatedly send POST requests to any endpoint mixing in `WebhookVerification`, `PayloadVerification`, or `ExtensionVerificationController` (e.g. the default `/webhooks` route, `/extension_verification` route, or any custom controller built on these concerns) with no `X-Shopify-Hmac-Sha256` header. Each such request raises an unhandled server-side exception instead of a clean `401`/`403`. This is directly analogous to the reported bug class: instead of gracefully rejecting malformed/invalid input, the verification path crashes with an unhandled exception on every malicious request, which — under repeated/automated submission — degrades application performance (exception + backtrace generation on every hit, potential error-tracker flooding, and 500 responses returned to Shopify which can affect delivery retry/backoff behavior) and can produce a denial-of-service-like condition.

### Likelihood Explanation
High. No authentication or prior state is required; a single crafted HTTP POST without the HMAC header triggers the crash, and the affected code path is on the primary route explicitly intended to accept unauthenticated external input.

### Recommendation
- Short term: In `ShopifyApp::PayloadVerification#hmac_valid?`, explicitly check `return false if shopify_hmac.blank?` before calling `secure_compare`, ensuring malformed/missing header input is always handled with a controlled `401`/`403` rather than raising.
- Long term: Add test coverage for the "header entirely absent" case (not just "header present but wrong") across `WebhookVerification`, `PayloadVerification`, and `ExtensionVerificationController`, and review other places that feed raw/untrusted attacker-controlled values into third-party crypto/comparison utilities without input validation.

### Proof of Concept
```
POST /webhooks HTTP/1.1
Host: victim-app.example.com
Content-Type: application/json
X-Shopify-Topic: orders/create
X-Shopify-Shop-Domain: any-shop.myshopify.com
Content-Length: 2

{}
```
(No `X-Shopify-Hmac-Sha256` header is sent.)

Result: `WebhookVerification#verify_request` calls `hmac_valid?(request.raw_post)`, which calls `ActiveSupport::SecurityUtils.secure_compare(nil, <base64 digest>)`, raising `NoMethodError: undefined method 'bytesize' for nil:NilClass` and returning an unhandled 500 error instead of the intended `401 Unauthorized`.

```ruby
    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
```
