### Title
Spoofable `WWW-Authenticate` realm heuristic lets a malicious remote force GitHub Desktop into an "Enterprise sign-in" flow pointed at an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Popcorn's `M-11` finding is about a downstream `execute()` result being trusted/used without validating success. The Desktop analog is a similarly unchecked trust decision: `getEndpointKind()` in the git credential-helper trampoline treats an attacker-supplied `WWW-Authenticate` header value as authoritative evidence that a remote host is "GitHub Enterprise," without any cross-check against the actual host. That unverified classification is then used by `getCredential()`/`promptForGitHubSignIn()` to launch a real GitHub Enterprise sign-in flow with `setSignInEndpoint(origin)` set to the attacker's own origin.

### Finding Description
When Git performs an HTTP(S) authentication attempt against a remote, it forwards any `WWW-Authenticate` response headers it receives to the credential helper as `wwwauth[N]` fields. `getEndpointKind()` uses these caller-supplied strings as a "happy path" to avoid a network round trip: [1](#0-0) 

Crucially, this loop only runs for hosts that already failed `isGist`, `isDotCom`, and `isGHE` checks - i.e., for arbitrary, non-GitHub-owned hosts. The value of `wwwauth[...]` is entirely controlled by whatever server the remote URL points to; a malicious git server (or a MITM/malicious proxy in the path of an HTTPS git operation) can simply return `WWW-Authenticate: Basic realm="GitHub"` to make Desktop classify it as `'enterprise'`.

That classification then flows into `getCredential()`: [2](#0-1) 

Since there is no existing account whose `endpoint` equals the attacker's fabricated API endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` being the attacker's own remote URL. [3](#0-2) 

Because `hostname !== 'github.com'`, this takes the `else` branch: it calls `dispatcher.beginEnterpriseSignIn(cb)` and then `dispatcher.setSignInEndpoint(origin)` where `origin` is derived directly from the attacker-controlled URL - not from any GitHub-verified value. `setSignInEndpoint` maps to `SignInStore.setEndpoint()`, which only checks URL syntax/HTTPS (`validateURL`) before transitioning the sign-in dialog into the `Authentication` step against that exact attacker endpoint: [4](#0-3) 

The broken invariant: the code assumes a `wwwauth[...]` header claiming `realm="GitHub"` is trustworthy proof that the peer is a legitimate GitHub Enterprise instance, and uses that unchecked claim to select the sign-in target endpoint. Unlike the `isDotCom`/`isGHE` checks (which compare against Desktop's own known-good endpoint list), this heuristic has no such anchor - it's exactly the kind of "unchecked return/result used downstream" pattern in the seed report, just manifesting as an unchecked/unauthenticated classification rather than an unchecked boolean.

### Impact Explanation
If a user adds or is redirected to a malicious/compromised git remote (attacker controls the server or a proxy in the connection path) and Desktop performs any HTTPS git operation against it (clone/fetch/push, or LFS operations that go through the credential helper), the server can trick Desktop's UI into opening a "Sign in to GitHub Enterprise" dialog whose underlying OAuth/token exchange endpoint is the attacker's own server. If the user proceeds to authenticate (enter PAT, or complete OAuth/device flow) believing this is a legitimate Enterprise sign-in prompted by Desktop, the credential/token material is sent to the attacker-controlled endpoint (`requestOAuthToken(endpoint, ...)`, `fetchUser(endpoint, ...)` in `sign-in-store.ts`), and/or a bogus Account tied to that attacker endpoint may be persisted in Desktop's account store. This matches "unauthorized OAuth or account binding" / "credential/token exfiltration" from a git-remote-controlled trigger.

### Likelihood Explanation
Likelihood is moderate: it requires (a) an HTTPS git operation against an attacker-controlled or compromised remote/proxy, and (b) the user to complete a sign-in prompt. No local access, no leaked credentials, and no unnatural steps are required beyond adding/using a remote that could plausibly be presented to the user as legitimate (e.g., a compromised self-hosted git server the user is told to clone from) and responding to Desktop's own native sign-in dialog. The `origin` naturally being displayed in the dialog (`credentialHelperUrl: endpoint` is only used for prompt text, but the dialog itself doesn't strongly foreground "this is not github.com") reduces detectability for a distracted user.

### Recommendation
Do not trust the `wwwauth[...]` realm string alone to decide GitHub-Enterprise-ness for hosts that are not already verified via `isDotCom`/`isGHE`/an existing account. Either:
- Require an additional network-verifiable check (e.g., probing `/api/v3/meta` or similar authoritative GitHub API signal) before treating the realm hint as trustworthy, matching how `isGitHubHost(endpoint)` already does a real network check further down in the same function; or
- At minimum, surface the exact host clearly and require explicit user confirmation ("This site claims to be GitHub Enterprise - continue only if you trust <host>") before calling `setSignInEndpoint` with an unverified origin, and avoid auto-elevating trust purely from a header the remote server fully controls.

### Proof of Concept
1. Stand up a git server (or an SSL-terminating proxy) at `https://evil.example.com/somerepo.git`.
2. Configure it so that, on an unauthenticated HTTPS request for `git-upload-pack`/`info/refs`, it returns HTTP 401 with header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, add `https://evil.example.com/somerepo.git` as a remote (or clone it) and trigger a fetch/push.
4. Git invokes the credential helper; `command.stdin` includes `wwwauth[0]=Basic realm="GitHub"` and `url=https://evil.example.com/...`.
5. `getEndpointKind()` matches the `realm="GitHub"` regex and returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-161`).
6. No existing account has `endpoint === apiEndpoint`, so `ui.promptForGitHubSignIn('https://evil.example.com/...')` runs, calling `beginEnterpriseSignIn` + `setSignInEndpoint('https://evil.example.com')` (`app/src/lib/trampoline/trampoline-ui-helper.ts:87-93`).
7. Desktop shows its native "Sign in to GitHub Enterprise" dialog with the authentication/OAuth flow now pointed at `evil.example.com`; if the user proceeds, their PAT/OAuth code is sent to `requestOAuthToken('https://evil.example.com', ...)` (`app/src/lib/stores/sign-in-store.ts:349`).

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
