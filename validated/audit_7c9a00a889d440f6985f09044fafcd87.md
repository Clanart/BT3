## Finding

### Title
Missing zero-address/validity check on `HostParams.admin` in `updateHostParamsInternal` permanently disables bridge freeze/unfreeze protection - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.updateHostParamsInternal` validates `hostManager`, `handler`, and `consensusClient` for zero address, contract code presence, and interface support before committing new `HostParams`, but performs **no validation whatsoever on `params.admin`** before overwriting `_hostParams.admin`. [1](#0-0) 

### Finding Description
`admin` is documented as the sole account with rights to freeze/unfreeze the bridge: [2](#0-1) 

This single field gates the critical emergency-stop mechanism `setFrozenState`, which is the only tool that can halt incoming/outgoing message processing when a consensus fault, exploit, or bad state commitment is detected: [3](#0-2) 

Unlike `hostManager`, `handler`, and `consensusClient` — each explicitly checked for `address(0)`, empty code, and correct `IERC165` interface support (`InvalidHostManager`, `InvalidHandler`, `InvalidConsensusClient`) — `params.admin` is copied directly with zero checks: [4](#0-3) 

`updateHostParamsInternal` is reachable from two entrypoints:
1. `EvmHost.updateHostParams`, restricted to `_hostParams.hostManager`, driven by cross-chain governance requests decoded and forwarded verbatim in `HostManager.onAccept`. [5](#0-4) [6](#0-5) 

2. `TestnetHost.updateHostParams`, callable directly by the current `admin` itself (no proof/governance round-trip required). [7](#0-6) 

In both paths, a malformed/mistaken `HostParams.admin` value (e.g., `address(0)`, a non-existent EOA, or a contract with no owner recovery) is accepted and permanently written to storage. Because `setFrozenState` and `setConsensusState` are gated by `restrict(_hostParams.admin)`, once `admin` is corrupted there is no recovery path — the bridge can never again be frozen by an admin (the `handler` alone remains, but that is driven purely by proof-verified consensus/state updates, not discretionary emergency action), nor can consensus state be reinitialized if ever needed. [8](#0-7) 

This is a direct structural analog to the reported `Ownable.transferOwnership` issue: every other privileged address field in the same struct received a defensive zero/validity check specifically "to prevent the host from getting bricked" (per the code's own comment), yet the `admin` field — arguably the most operationally critical one for incident response — was omitted.

### Impact Explanation
If `admin` is ever set to an invalid or inaccessible address (via an errant governance proposal processed through `HostManager`, or a fat-fingered self-call on `TestnetHost`), the protocol permanently loses its only discretionary emergency-freeze capability. During an active exploit (e.g., a bad consensus client, malicious state commitment, or an in-progress fund-draining attack detected off-chain), operators would have no way to halt the bridge via `setFrozenState`, directly enabling continued unauthorized execution and fund loss that a working freeze mechanism exists specifically to prevent.

### Likelihood Explanation
Low-to-moderate: this requires either (a) a mistake in the ABI-encoded `HostParams` payload of a legitimate governance proposal routed through `HostManager.onAccept`, or (b) an errant direct call from the current admin on `TestnetHost`. No malicious actor, relayer, or attacker is needed — this is the same "honest mistake with catastrophic and irreversible consequence" scenario as the original report, which is why the analogous fields (`hostManager`, `handler`, `consensusClient`) already carry equivalent guards.

### Recommendation
Add the same class of guard already applied to `hostManager`/`handler`/`consensusClient` to `params.admin` inside `updateHostParamsInternal`, e.g. reject `address(0)` (and optionally require it differ from `address(this)` or other host-owned addresses), reverting with a new `InvalidAdmin` error before committing the new params.

### Proof of Concept
1. Governance (or the current admin, via `TestnetHost`) submits `HostParams` with `admin = address(0)` (or any address with no operable key), keeping `hostManager`, `handler`, `consensusClient` valid so the existing checks pass.
2. `updateHostParamsInternal` accepts and stores `_hostParams.admin = address(0)`. [4](#0-3) 
3. Any subsequent call to `setFrozenState` or `setConsensusState` reverts with `UnauthorizedAction` for every caller, since `restrict(_hostParams.admin)` / the admin check in `setFrozenState` can never be satisfied again. [9](#0-8) 
4. The host is permanently unable to be frozen by any admin action, removing the emergency stop during an active incident.

    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;

        address caller = _msgSender();
        if (caller != _hostParams.hostManager && caller != _hostParams.admin) {
            revert UnauthorizedAction();
        }

        if (caller == _hostParams.admin) {
            uint256 whitelistLength = params.stateMachines.length;
            for (uint256 i = 0; i < whitelistLength; ++i) {
                delete _latestStateMachineHeight[params.stateMachines[i]];
            }
