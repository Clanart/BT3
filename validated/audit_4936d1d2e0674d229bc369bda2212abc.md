### Title
Ed448 accepts torsion points, enabling forged Schnorr signatures - (File: crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` is mathematically ineffective: it evaluates `(-P) + P`, which is always identity for every Edwards point. Consequently, Ed448 `GroupEncoding::from_bytes` accepts canonical encodings of small-order and mixed-subgroup points as if they were prime-order points. [1](#0-0) 

`Ciphersuite::read_G` performs only decoding and canonical-encoding checks, so these torsion-bearing points pass byte deserialization. [2](#0-1) 

### Finding Description
The intended subgroup check is:

```rust
((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
```

Because `Scalar::ZERO - Scalar::ONE` is `-1`, this computes `-P + P`, which is identity unconditionally. It therefore does not test whether `P` lies in Ed448's prime-order subgroup. [3](#0-2) 

`from_bytes` relies on that predicate before accepting a decoded point. [4](#0-3) 

Schnorr verification then uses the uncofactored equation `R + cA - sG = 0`. [5](#0-4) 

An attacker can therefore submit a public key whose encoding represents an Ed448 torsion point, such as an order-4 point with `y = 0`, and construct a signature whose transcript challenge cancels the torsion component.

### Impact Explanation
For a torsion public key `A` of order 4, there is no secret scalar `a` satisfying `A = aG` over the prime-order generator. Nevertheless, an attacker can produce `(R, s)` such that:

```text
R + cA - sG = identity
```

They do this by selecting `s = r`, placing `rG + kT` in `R`, and iterating `r` and the four torsion coefficients `k` until the Fiat-Shamir challenge satisfies `k + c = 0 mod 4`. This requires only a handful of trials on average and produces a signature accepted by `SchnorrSignature::verify` for a malformed public key which no private key exists. [6](#0-5) 

This yields forged Schnorr signatures/proofs wherever attacker-controlled Ed448 public keys or signature bytes are accepted through the in-scope decoding path. It does not recover keys associated with ordinary prime-order public keys.

### Likelihood Explanation
The malformed key only needs one valid canonical point encoding. Order-2 and order-4 Ed448 points are easy to construct; for example, a `y = 0` encoding is an order-4 point. Since the subgroup predicate always returns true, no exceptional deserialization path or race is required. The attack is deterministic apart from iterating a small set of nonce candidates until the challenge has the needed value modulo 4.

### Recommendation
Implement a real prime-order subgroup check for Ed448 points instead of `-P + P`. Use the underlying Edwards implementation's audited `is_torsion_free` operation, or multiply by the full prime group order using an integer representation that is not reduced modulo that order. Reject identity where the consuming protocol requires nonzero points.

Additionally, add negative tests for:

- order-2 and order-4 Ed448 encodings;
- mixed prime-order/torsion points;
- negative-zero encodings;
- identity inputs to every `read_G`, `SchnorrSignature::read`, and proof-deserialization path.

### Proof of Concept
Conceptual Rust-style procedure for an order-4 public key:

```rust
// Ed448 encodings are 57 bytes. y = 0 with either sign bit denotes a
// point of exact order 4.
let mut encoded_torsion = [0u8; 57];
let T = Ed448Point::from_bytes(&encoded_torsion).unwrap();

// This malformed public key has no discrete logarithm relative to G.
let A = T;

for r in 0.. {
    for k in 0..4 {
        let R = (G * Scalar::from(r)) + (T * Scalar::from(k));
        let c = fiat_shamir_challenge(R, A, message);

        // T has order 4, so cA depends only on c mod 4.
        if bool::from((R + (A * c) - (G * Scalar::from(r))).is_identity()) {
            // Accepted by SchnorrSignature::verify(A, c), despite A having
            // no corresponding private key.
            return SchnorrSignature { R, s: Scalar::from(r) };
        }
    }
}
```

The root cause is that `from_bytes` should have rejected `T`, but its subgroup test is vacuous. [7](#0-6)
