### Title
Unsigned OP_RETURN operator-attribution output lets any unprivileged party rewrite a payout's fronting operator, falsely triggering `is_kickoff_malicious` and burning the honest operator's collateral — ([File: core/src/verifier.rs], [File: core/src/builder/transaction/operator_reimburse.rs], [File: core/src/rpc/parser/operator.rs])

### Summary
The payout transaction's OP_RETURN output (which records the operator's x-only pubkey used later to attribute the payout) is never covered by the user's mandatory `SinglePlusAnyoneCanPay` signature, so any unprivileged party who observes the broadcast, unconfirmed payout tx can rebroadcast a fee-bumped variant with a different (or missing) OP_RETURN while keeping the same signed input/output. `Verifier::is_kickoff_malicious` trusts this on-chain OP_RETURN value verbatim and rejects the real, honest operator O purely because `operator_xonly_pk_opt != kickoff_data.operator_xonly_pk` — independent of, and prior to, the truncated-blockhash check.

### Finding Description
The claimed binding is: `kickoff_data.operator_xonly_pk` (O, the operator who actually funded the withdrawal and is honestly recorded in `used_kickoff_connectors`/round data) **should equal** `operator_xonly_pk_opt` derived from the mined payout tx's OP_RETURN, whenever O in fact broadcast that payout.

`create_payout_txhandler` builds the payout tx with three outputs: user payout (index 0), anchor (index 1), and OP_RETURN carrying `operator_xonly_pk` (index 2) [1](#0-0) . The only signature present is the user's, and `parse_withdrawal_sig_params` strictly enforces `TapSighashType::SinglePlusAnyoneCanPay` [2](#0-1) . `SinglePlusAnyoneCanPay` only commits to the single input being spent and the output at the same index (index 0); outputs 1 (anchor) and 2 (OP_RETURN) are completely outside the signed message, confirmed by `calculate_pubkey_spend_sighash`'s `Prevouts::One` handling for that sighash flag [3](#0-2) . Anyone who sees the broadcast (still unconfirmed) payout tx can therefore construct and confirm an alternative transaction that reuses the identical signed input/output-0, but replaces the OP_RETURN's operator pubkey with an arbitrary value (or removes it), then wins the race onto the chain (e.g. via a higher-fee replacement/CPFP), all funded from their own UTXOs — no operator or verifier key material is needed.

Once mined, `update_finalized_payouts` blindly parses the OP_RETURN of whichever tx actually spent the withdrawal UTXO and stores it as `payout_payer_operator_xonly_pk` with no signature check on that payload [4](#0-3) . `Verifier::is_kickoff_malicious` then reads this value and short-circuits:
```
if operator_xonly_pk != kickoff_data.operator_xonly_pk {
    tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
    return Ok(true);
}
``` [5](#0-4)  — this check runs and returns `true` (malicious) before the truncated-blockhash comparison at lines 1902–1913 is ever reached [6](#0-5) . This confirms the two guard clauses are independent AND-ed conditions: an attacker only needs to break the OP_RETURN attribution; no blockhash grinding is required to flip the result for an honest, protocol-compliant O.

`handle_kickoff` treats a `true` result as malicious and queues a `Challenge` tx against O's kickoff [7](#0-6) . During the resulting challenge/disprove flow, O must submit a BitVM proof; but the risc0 circuit itself derives `operator_xonlypk` (and thus `deposit_constant`) from the payout tx's on-chain OP_RETURN — now the attacker-forged value — via `parse_op_return_data`/`deposit_constant` [8](#0-7) , while the disprove script's expected `deposit_constant` was pre-committed using the real operator's pubkey from DB at kickoff-creation time [9](#0-8) . The mismatch causes disprove to succeed regardless of O's actual correctness, burning O's collateral.

No existing guard prevents this: `is_deposit_valid`, `SECP.verify_schnorr` (which only validates output 0), and the enforced sighash type all operate correctly per their own scope but none of them binds the OP_RETURN payload to the signature or to O's identity.

### Impact Explanation
An honest operator who genuinely fronted a withdrawal has their identity misattributed by a third party with zero privileges, causing:
- A false Challenge against a legitimate kickoff.
- A successful Disprove due to circuit/committed-constant mismatch, permanently burning O's collateral — the Critical category "an honest operator's collateral burned."
This is repeatable against any operator, any deposit, and any withdrawal, as long as the attacker can observe a payout tx in the mempool before it confirms and outbid it with a variant differing only in the unsigned outputs.

### Likelihood Explanation
No privileged role, key share, or majority hashrate is required — only mempool visibility (public) and the ability to fund and broadcast a competing/higher-fee Bitcoin transaction, which is explicitly within the unprivileged attacker's granted capabilities. The cost is limited to Bitcoin transaction fees. The attack is deterministic (no blockhash grinding needed) given the code's check ordering, and is repeatable per-payout.

### Recommendation
Bind the OP_RETURN (and any other output relevant to attribution/fee) into the user-signed message, e.g. require `SIGHASH_ALL` (or at least `SIGHASH_SINGLE` without `ANYONECANPAY`, plus explicit inclusion/commitment of the OP_RETURN output in the signed payload), or otherwise cryptographically commit the operator identity to something the user (or the protocol) actually signs so it cannot be altered post-broadcast. Alternatively, verify a separate operator-signed attestation for the OP_RETURN payload before trusting it in `update_finalized_payouts`/`is_kickoff_malicious`.

### Proof of Concept
```
cargo test -p core is_kickoff_malicious_op_return_forgery -- --nocapture
```
Plan:
1. Construct a payout tx via `create_payout_txhandler` for a real operator O, sign the single input with `SinglePlusAnyoneCanPay` per `parse_withdrawal_sig_params`.
2. Build a second transaction reusing the identical signed input and output-0, but with an OP_RETURN containing a different xonly pubkey X != O, and verify it passes `SECP.verify_schnorr` for the same signature/sighash (proving output 1/2 are unconstrained).
3. Feed X into the DB via `update_payout_txs_and_payer_operator_xonly_pk` in place of O's real pubkey (simulating `update_finalized_payouts` observing the attacker's mined variant), matching truncated blockhash correctly.
4. Call `Verifier::is_kickoff_malicious` with `kickoff_data.operator_xonly_pk == O` and assert it returns `Ok(true)`, asserting the equality `operator_xonly_pk_opt (X) != kickoff_data.operator_xonly_pk (O)` is what triggers the `true` result at core/src/verifier.rs:1887-1890, independent of a correct/matching blockhash.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
