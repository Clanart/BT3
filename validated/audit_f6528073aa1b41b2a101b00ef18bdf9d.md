### Title
Unauthenticated SSRF via on-chain DataLayer mirror URLs consumed by `fetch_and_validate`/`download_file` - ([File: chia/data_layer/data_layer.py])

### Summary
Chia's DataLayer subsystem lets any wallet owner publish "mirror" server URLs on-chain for a store, and every other DataLayer client that subscribes to (or owns/pseudo-subscribes to) that store will automatically fetch data from those URLs over plain outbound HTTP with no validation of the destination host/scheme. This mirrors the Homarr SSRF bug class: an unauthenticated (from the DataLayer service's perspective) attacker supplies an arbitrary URL that is fetched server-side, which can be pointed at loopback/private-network addresses reachable from the DataLayer host.

### Finding Description
DataLayer stores are singletons whose owner can register mirror URLs on-chain (via the mirror coin flow in `chia/data_layer/data_layer_wallet.py` and `chia/data_layer/dl_wallet_store.py`). Any node's DataLayer service periodically syncs subscription URLs from these on-chain mirrors and stores them as `ServerInfo` entries (see `.cursor/context/data-layer.md` step "sync subscription URLs from wallet mirrors" in `update_subscription()`).

`DataLayer.fetch_and_validate()` then iterates these `ServerInfo` URLs and passes them directly into the download pipeline:
<cite repo="Annirich/chia-blockchain--005" path="chia/data_layer/data_layer.py" start="642="647" /> [1](#0-0) 

`insert_from_delta_file()` -> `download_file()` in `chia/data_layer/download_data.py` performs an unauthenticated outbound HTTP GET (`http_download`) directly against the attacker-supplied URL when no downloader plugin is configured: [2](#0-1) 

There is no allowlist/denylist check on the host (no rejection of `127.0.0.1`, link-local, or RFC1918 ranges) before the request is issued — the code and tests explicitly exercise URLs like `http://127.0.0.1/8003` as legitimate mirror targets, confirming no destination filtering exists: [3](#0-2) 

The project's own internal documentation acknowledges mirror URLs are an "external trust input" but only calls out data-content verification against wallet roots, not destination-network restriction: [4](#0-3) 

### Impact Explanation
Any wallet user who creates a DataLayer store and registers a mirror URL controls a value that is fetched, server-side, by every peer's DataLayer service that later subscribes to (or auto-tracks) that store. Because the fetch happens from the DataLayer host/container network context with no destination validation, this can be used to reach loopback and internal-network HTTP endpoints (e.g., local RPC services, cloud metadata endpoints) from any node running the DataLayer service — the same SSRF primitive described in the Homarr advisory. This is limited to the DataLayer service network context (not general node RPC/wallet key material), and does not by itself grant read access to responses (the response body is expected to be validated data-layer content, not reflected to the attacker), which keeps the practical impact bounded to internal-network reachability/probing and potential internal-service side effects, consistent with the CVSS 5.3/Medium rating of the reference report.

### Likelihood Explanation
Likelihood is fairly high for anyone running DataLayer: publishing a mirror pointing at an internal address requires only a normal DL wallet mirror-creation spend (an unprivileged DL store owner action), and any other node subscribing to (or discovering/auto-tracking) that store's mirrors will trigger the fetch automatically during the periodic sync loop (`periodically_manage_data()` / `update_subscription()` / `fetch_and_validate()`), with no operator interaction required.

### Recommendation
Add destination validation to the DataLayer mirror/download URL handling: resolve and reject URLs whose host resolves to loopback, link-local, multicast, or private/reserved IP ranges (and disallow non-http(s) schemes) before calling `http_download()`/`download_file()` in `chia/data_layer/download_data.py`, and apply the same validation when mirrors are registered/synced in `chia/data_layer/data_layer.py` and `data_layer_wallet.py`. Consider making this check configurable (e.g., an allowlist for legitimate local testing) but secure-by-default for mainnet.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `create_new_mirror` (via `data_layer_rpc_api.py`/`data_layer_wallet.py`) registering a mirror URL such as `http://169.254.169.254/latest/meta-data/` or `http://127.0.0.1:<internal-port>/...`, publishing it on-chain as a normal, unprivileged transaction.
2. A victim's DataLayer node subscribes to (or auto-tracks, if it later interacts with) the attacker's store id.
3. During the victim's periodic sync (`update_subscription()` -> `fetch_and_validate()`), the victim's DataLayer service enumerates the attacker's mirror `ServerInfo.url` and calls `insert_from_delta_file()` -> `download_file()` -> `http_download()`, causing the victim host to issue an outbound HTTP request to the attacker-chosen internal address, exactly as demonstrated by the test harness using `ServerInfo("http://127.0.0.1/8003", ...)` in `chia/_tests/core/data_layer/test_data_store.py`.

Note: I was unable to view the full body of `http_download()` itself (only its call sites and signature via test mocks) or the exact `create_new_mirror`/`add_mirror` implementation contents due to index truncation; a Devin session with full repo access should confirm there is no destination-host filtering inside `http_download()` before implementing the fix.

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
