### Title
Spoofable `WWW-Authenticate` header lets an attacker-controlled remote be misclassified as a trusted GitHub Enterprise host, bypassing the real host-verification check - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind` in `trampoline-credential-helper.ts` classifies the host Git is authenticating against (`github.com`, `ghe.com`, `enterprise`, or `generic`) before the credential helper decides whether to silently return a stored GitHub token or prompt a fresh GitHub sign-in. One of its checks trusts an attacker-fully-controlled value — the `WWW-Authenticate` header Git forwards from the remote server — as a "happy path" shortcut that short-circuits the one check that actually verifies the host is GitHub (`isGitHubHost`, which performs a real network probe for the `x-github-request-id` response header). [1](#0-0) 

### Finding Description
`getEndpointKind` runs a chain of checks in this order: `isGist`, `isDotCom`, `isGHE`, then the `wwwauth[]` header heuristic, then an exact-origin lookup against known accounts, then a protocol check, and only as the final fallback does it call `isGitHubHost`, which makes an actual network request and validates the `x-github-request-id` response header before deciding a host is a genuine GitHub/Enterprise endpoint. [2](#0-1) 

The `wwwauth[]` heuristic sits ahead of that real verification and short-circuits it: if any `wwwauth[N]` value contains `realm="GitHub"`, the function immediately returns `'enterprise'` — no origin check, no HTTPS requirement, and no server-verification network call.

```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      }
```

This value comes directly from a `WWW-Authenticate` response header sent by whatever server Git is talking to — i.e., it is fully attacker-controlled when the remote is attacker-controlled (a malicious clone/fetch/push target, or a MITM/proxy response). `isGitHubHost`, by contrast, exists specifically to make this a *hard* determination via a live request and header check: [3](#0-2) 

By placing the trivially-spoofable heuristic before the real verification (and before the HTTPS-only assumption is even applied), the function grants an untrusted host the same "trusted GitHub endpoint" classification that is normally reserved for something that survived the network probe.

That classification directly drives `getCredential`'s behavior: for any endpoint classified as not `'generic'` with no existing matching account, Desktop automatically pops a native "Sign in to GitHub" dialog scoped to the attacker's endpoint. [4](#0-3) 

`promptForGitHubSignIn` then wires this straight into the real Enterprise sign-in flow, binding it to the attacker's origin: [5](#0-4) 

### Impact Explanation
An attacker who controls a git remote (e.g., a repository the user clones/fetches/pushes to, or a proxy/MITM response) can cause GitHub Desktop to auto-launch a "Sign in to GitHub Enterprise" flow bound to the attacker's server, purely by returning a spoofed `WWW-Authenticate: Basic realm="GitHub"` header — no HTTPS, no valid TLS cert, and no real GitHub API response are required, since this path runs before the HTTPS-only check and before the actual `isGitHubHost` network probe. If the user, believing this is a legitimate corporate/Enterprise credential prompt triggered by Desktop itself, enters a PAT or completes OAuth, that credential is exchanged directly with the attacker's endpoint — resulting in credential/token exfiltration and an account binding to an attacker-controlled endpoint, both explicitly in-scope impact categories.

### Likelihood Explanation
The only capability required is control over a git server/remote's HTTP responses (adding a malicious remote, cloning an attacker repo hosted on the attacker's own git server, or a network-position MITM), which is one of the explicitly allowed attacker primitives. No local access, no prior compromise, and no unnatural user steps beyond normal Desktop usage (fetch/push/clone) are needed to reach the vulnerable code path; the only additional step is the user interacting with a dialog Desktop itself opened, which is the expected result of the vulnerable classification logic, not an out-of-band social-engineering precondition.

### Recommendation
Remove (or drastically deprioritize) the `wwwauth[]`-based realm heuristic as an authority for trusting a host as `'enterprise'`. At minimum:
- Require the `wwwauth` heuristic to still be confirmed by `isGitHubHost`'s real network check (or an existing verified account's origin) before granting `'enterprise'`/`'github.com'` classification, mirroring the recommended fix pattern of always falling through to the authoritative check rather than trusting a cheap, spoofable signal.
- Enforce the HTTPS-only assumption before evaluating the `wwwauth` heuristic, since GitHub hosts are documented as HTTPS-only elsewhere in the same function.

### Proof of Concept
1. Attacker stands up a plain HTTP(S) git server (any git server implementation), and configures it to answer unauthenticated HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this server as a remote in GitHub Desktop (e.g., clones a repo hosted there, or it's added as a second remote) and performs a fetch/push.
3. Git invokes Desktop's credential helper trampoline with the credential map including `wwwauth[0]=Basic realm="GitHub"` and the attacker's URL as `getCredentialUrl(cred)`.
4. `getEndpointKind` matches the `realm="GitHub"` substring and returns `'enterprise'` without ever calling `isGitHubHost` or checking the account origin.
5. `getCredential` finds no existing account for the attacker's `apiEndpoint` and calls `ui.promptForGitHubSignIn(endpoint)`, which opens a native "Sign in to GitHub Enterprise" dialog bound to the attacker's origin via `setSignInEndpoint(origin)`.
6. If the victim completes the sign-in (PAT entry or OAuth) believing it's a legitimate Desktop-initiated Enterprise prompt, the credential is sent to the attacker-controlled server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
