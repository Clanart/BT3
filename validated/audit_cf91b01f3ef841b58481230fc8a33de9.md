## Analysis

The ZeroLend report's underlying pattern is: **a value that should only be derivable from a verified/trusted source is instead accepted from an unauthenticated, attacker-controlled input, and that value is then used to make an authorization/trust decision that bypasses an existing guard.** In ZeroLend, `OmnichainStaking` correctly blocks direct token transfers, but the *voting weight* it computes is still driven by attacker-controlled unstake/restake sequencing, defeating the SBT-style invariant.

The closest verified analog in this GitHub Desktop checkout is in the git-credential trampoline, where the classification of a remote host as a trusted "GitHub"/"GitHub Enterprise" endpoint — which gates whether Desktop's built-in Sign-In UI is shown for that host — is derived from an **attacker-controlled `WWW-Authenticate` header**, completely bypassing the app's own network-verification guard (`isGitHubHost`).

### Title
Attacker-controlled `WWW-Authenticate` realm spoofs GitHub-host classification and triggers Desktop's trusted Sign-In flow for an arbitrary host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` decides whether a git remote host should be treated as `'enterprise'` (a genuine GitHub/GHE host) purely by inspecting `wwwauth[]` credential-helper fields, which are copied verbatim from the HTTP `WWW-Authenticate` response header sent by whatever server git is talking to. Any git server the user's Desktop instance talks to during a normal operation (clone, fetch, submodule update, LFS) fully controls this header and can claim `realm="GitHub"`, which short-circuits and bypasses the legitimate network-based verification (`isGitHubHost`) that is used everywhere else in the same function.

### Finding Description
`getEndpointKind` is invoked from the credential-helper trampoline handler every time git needs credentials for any host: [1](#0-0) 

The relevant branch trusts the `wwwauth[...]` fields at face value:
```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } ...
```
These `wwwauth[]` entries originate from the git credential-helper protocol, which git populates from the server's `WWW-Authenticate` response header when an HTTPS request is challenged — see `parseCredential`, which simply splits `key=value` lines coming from git's stdin without any validation of provenance: [2](#0-1) 

Contrast this with the *only* legitimate way the app is supposed to determine "is this really a GitHub host": an outbound network probe to `/meta` that checks for the `x-github-request-id` response header, explicitly documented as best-effort: [3](#0-2) 

That check (`isGitHubHost`) is only reached in `getEndpointKind` as a last resort — the `wwwauth[]` shortcut at lines 153-165 returns `'enterprise'` (or `'generic'`) before that verification ever runs, so a hostile server can force the "enterprise" classification unconditionally.

Once `endpointKind !== 'generic'` and no existing account matches that host's derived API endpoint, `getCredential` calls the UI helper to show Desktop's official GitHub sign-in dialog for that (attacker-chosen) endpoint: [4](#0-3) 

`promptForGitHubSignIn` then actually starts the enterprise OAuth binding flow using the attacker-supplied host as the target endpoint: [5](#0-4) 

### Impact Explanation
This breaks the invariant that only network-verified GitHub/GHE hosts can trigger Desktop's built-in, trusted "Sign in to GitHub Enterprise" account-binding flow. An attacker who controls any git server that Desktop talks to during a routine operation — e.g., a malicious `origin`, a malicious submodule URL referenced from `.gitmodules` in a cloned repository, or an LFS/proxy endpoint — can respond to the HTTPS auth challenge with `WWW-Authenticate: Basic realm="GitHub"` and force Desktop into the "enterprise" code path for a host of their choosing. This results in Desktop presenting its trusted first-party GitHub sign-in chrome (`beginEnterpriseSignIn`/`setSignInEndpoint`) for an arbitrary, attacker-chosen origin the user never explicitly entered — i.e., an unauthorized account-binding flow initiated against a spoofed endpoint, satisfying the "unauthorized OAuth or account binding" impact category. It also completely defeats the app's own `isGitHubHost` safety check, which exists specifically to make this determination safely.

### Likelihood Explanation
No local access, malware, or leaked credentials are required. The only precondition is that the user performs an ordinary git operation (clone/fetch/submodule update/LFS fetch) against a repository whose remote — or a nested submodule/LFS remote referenced by that repository — is controlled by the attacker. Emitting a custom `WWW-Authenticate` header on an HTTP 401 response is trivial for any server operator and requires no unusual client behavior; it is a standard part of HTTP Basic auth challenges that git itself forwards unmodified to the credential helper.

### Recommendation
Do not use the client-supplied `wwwauth[]` header content as authoritative evidence of a GitHub/GHE host. Either remove this shortcut entirely and always rely on the verified `isGitHubHost` network check (with appropriate caching to avoid repeated network calls), or treat the `wwwauth[]` hint only as a soft signal that still requires the `isGitHubHost` verification to pass before classifying an endpoint as `'enterprise'` and before surfacing the sign-in UI / performing any account binding.

### Proof of Concept
1. Stand up an HTTPS git server (`git-http-backend` or any HTTP handler) at `https://evil.example.com/repo.git`.
2. Configure it so that unauthenticated requests to the git smart-HTTP endpoints return `401` with header: `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone/add `https://evil.example.com/repo.git` as a repository (or make it a submodule/LFS remote of an otherwise-legitimate repository the victim opens).
4. Trigger any git network operation against it (clone, fetch, submodule update).
5. Git surfaces the 401 + `WWW-Authenticate` header to Desktop's credential helper via `cred['wwwauth[0]']`.
6. `getEndpointKind` matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost`.
7. `getCredential` finds no existing account for `https://evil.example.com`, and — instead of failing safe as a "generic"/unknown host — calls `ui.promptForGitHubSignIn('https://evil.example.com')`, launching Desktop's trusted "Sign in to GitHub Enterprise" flow bound to the attacker's endpoint.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
