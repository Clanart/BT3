## Finding: Missing module-identity binding in `BandwidthManager.onAccept` — `source` chain-id check does not validate `from`

### Summary
`onAccept` in `BandwidthManager.sol` authenticates the inbound governance message solely by comparing `request.source` to `IDispatcher(_host).hyperbridge()` [1](#0-0) . It never checks `request.from` against `PALLET_BANDWIDTH_MODULE_ID`, even though that constant is defined and used as the `to` field when *dispatching* outbound purchase messages [2](#0-1) [3](#0-2) .

### Finding Description
`PostRequest.source` is the **source chain identifier** (e.g. `"POLKADOT-1000"`), while `PostRequest.from` is the **source application/module address on that chain** [4](#0-3) . These are semantically distinct fields: `source` proves *which chain* originated the message, `from` proves *which module on that chain* originated it.

`onAccept` only performs:
```solidity
if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();
```
This proves the message came from the hyperbridge chain, but it does **not** bind the message to `pallet-bandwidth` specifically. Any other module/pallet on the hyperbridge chain capable of dispatching an ISMP POST request destined for `BandwidthManager` (with `to = address(this)` on the EVM side, which is enforced by the host's routing, not by this contract) can freely choose the `from` field's bytes, since the contract performs no comparison against `PALLET_BANDWIDTH_MODULE_ID`. `HyperApp.onlyHost` only restricts the caller to the local EVM host contract [5](#0-4) ; it says nothing about which chain-side module the payload logically came from.

As a result, both governance-only branches — `SetTiers` (rewrites tier pricing) and `Withdraw` (transfers arbitrary `token`/`amount` to arbitrary `beneficiary`) — are reachable by any message whose `source` equals the hyperbridge chain id, regardless of the actual originating module [6](#0-5) .

### Impact Explanation
If any module other than `pallet-bandwidth` on the hyperbridge chain can dispatch a POST request to `BandwidthManager` (which is the normal, permissionless design of ISMP — modules self-declare `from`), an attacker in control of such a module can:
- Trigger `Withdraw` to drain the entire fee-token/native balance held by `BandwidthManager` to an attacker-chosen `beneficiary`.
- Trigger `SetTiers` to rewrite pricing, e.g., to zero, enabling free purchases or griefing legitimate buyers.

This is unauthorized cross-chain execution and potential loss of funds, matching the "cross-chain admin/host-management effects reachable through wrong module bindings" pivot.

### Likelihood Explanation
Likelihood depends on one unverified fact I could not confirm from the indexed contract code alone: whether the Substrate-side ISMP dispatch API lets an arbitrary pallet/module self-declare the `from` bytes in a `DispatchPost` sent to `BandwidthManager`, or whether the router/host enforces that `from` always equals the calling module's own canonical, non-forgeable identifier. If `from` is attacker-influenceable by any module (which is the typical, permissionless ISMP dispatch pattern), the finding is directly exploitable exactly as described in the question. Regardless of that Substrate-side detail, the EVM-side code is unambiguously missing the `from == PALLET_BANDWIDTH_MODULE_ID` check that the contract's own naming/comments imply should exist — this is a genuine authorization gap independent of exploit likelihood nuances.

### Recommendation
Add the missing module-identity check in `onAccept`:
```solidity
if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();
if (!request.from.equals(PALLET_BANDWIDTH_MODULE_ID)) revert UnauthorizedAction();
```
This binds both the source chain and the source module, closing the gap between "message came from hyperbridge chain" and "message came from `pallet-bandwidth` specifically."

### Proof of Concept
1. Deploy `BandwidthManager` with a mock host (`_host`) whose `hyperbridge()` returns a fixed constant chain id, e.g. `bytes("POLKADOT-3367")`.
2. Craft an `IncomingPostRequest` with:
   - `request.source = bytes("POLKADOT-3367")` (equals `hyperbridge()`),
   - `request.from = bytes("ATTACKER_MODULE")` (anything other than `"BWMARKET"`),
   - `request.body = abi.encodePacked(uint8(1), abi.encode(Withdrawal({token: address(0), beneficiary: attacker, amount: contractBalance})))` (action `Withdraw`).
3. Call `onAccept(incoming)` from the mock host address (satisfying `onlyHost`).
4. Observe the `Withdraw` branch executes to completion, transferring `contractBalance` to `attacker`, despite `request.from` never being validated against `PALLET_BANDWIDTH_MODULE_ID`. [7](#0-6)

```text
    /// @notice Inbound governance from `pallet-bandwidth`. The first
    /// body byte selects `OnAcceptActions`; the remainder is the
    /// action's ABI-encoded payload.
    /// @dev Only the configured host may invoke (`onlyHost`); the
    /// request's `source` must additionally equal hyperbridge.
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
```
