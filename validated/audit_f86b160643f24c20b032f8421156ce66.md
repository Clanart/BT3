## Title
JSON parser field-identity collision between an extension and a regular field with the same JSON name causes silent data misattribution / drop — (File: `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java`)

## Summary
The OpenVM finding's failed invariant is: **the verifier assumes a 1:1 mapping between a semantic "slot" (AIR position/type) and the value it validates, but the underlying bus/consumption mechanism treats all entries with that identity uniformly, so a prover-supplied duplicate can be validated by the checker while a different (or the "wrong") instance is what actually gets used/propagated.** The transferable pattern is: *a de-duplication/"has-been-seen" check keyed on one identity (field number/oneof index) can be silently bypassed when two logically distinct fields collide under a single external name, letting attacker input decide which internal identity "wins," while the check believes uniqueness was enforced.*

In protobuf's Java JSON implementation, `JsonFormat` supports printing extensions using their *short* (non-fully-qualified) name via the deprecated `printingDeprecatedNonConformantShortExtensionNames()` option. When an extension's short name collides with a regular field's JSON name, printing emits **two JSON object entries with the identical key**. This is a real, reachable code path in the shipped library (not a hypothetical), and the project's own test explicitly documents that re-parsing this JSON "results possibly the wrong value being assigned to the regular field and the extension field to be dropped."

## Finding Description
`JsonFormat.Printer` builds JSON output by iterating over `ListFields()`/reflection and writing `field.getJsonName()` (or the short name for extensions when the deprecated flag is set) as the object key: [1](#0-0) . When the extension name equals a regular field's JSON name, this printer produces:
```json
{
  "extensionSameName": "Field entry",
  "extensionSameName": "Extension entry"
}
``` [2](#0-1) 

When this JSON is parsed back with `JsonFormat.Parser`, the C++/Java JSON parsers key their duplicate-field detection (`SeenState` / "has already been set" checks) by **field identity** (field number / oneof index), not by the JSON string key that arrived on the wire: [3](#0-2) . The `ParseField` dispatcher resolves the JSON member name to a field via `FieldByName`/`ExtensionByName` and only *then* records it as seen per-field: [4](#0-3) . Because the regular field and the extension are two *different* `FieldDescriptor` objects, the "already seen" logic never fires for the collision — each of the two identical-looking JSON keys resolves to a *different* internal field identity, so both get processed independently, and whichever the underlying JSON tokenizer/map resolves last for that string key silently determines what data ends up where. The project's own test confirms the outcome is nondeterministic/incorrect: `assertThat(parsedMessage.toString()).isNotEqualTo(message.toString())` [5](#0-4) .

This exactly mirrors the OpenVM bug class: a checker (`RecordAsSeen`/oneof-seen tracking, analogous to the recursive verifier's "check only air_id 0/1/3") assumes each externally-visible slot (air_id / JSON key) maps to exactly one semantic entity, but the actual underlying representation (the bus / distinct `FieldDescriptor`s) permits two different entities to share that external identity. An attacker who controls the raw JSON payload (not just a benign re-serialization) can send `{"extensionSameName": <maliciousValue>, "extensionSameName": <benignValue>}` directly to any consuming application's public JSON parse API that has extensions registered whose short name aliases a regular field name, and cause the parser to non-deterministically apply the wrong field, or silently drop the extension's data, without any parse error.

## Impact Explanation
A consuming application that relies on JSON parsing of protobuf messages containing extensions (e.g., policy/authorization extensions, feature flags, or custom metadata layered via proto2 extensions) could have the extension value silently dropped or overwritten by an unrelated field's value, or vice versa — an integrity failure analogous to the OpenVM scenario where a state-transition check is satisfied while the "wrong" (attacker-chosen) value is actually the one that persists. Since no `InvalidProtocolBufferException` is raised, the application has no signal that anything unusual occurred, unlike the standard "duplicate field" rejection path that normally protects against this pattern [6](#0-5) .

## Likelihood Explanation
Exploitability requires: (1) the target schema to define both a regular field and an extension whose JSON/short names collide (achievable by design since extension short names are not required to be unique against sibling field names across the extending message), and (2) the consuming application's registry to include that extension (as `TypeRegistry`/`ExtensionRegistry` are trusted per the threat model, but the *collision* itself is a schema property, not a registry misuse). The vulnerable printing option is explicitly named/marked `Deprecated`/`NonConformant`, indicating limited but real-world usage for legacy interop with proto1-era extension naming. This constrains likelihood to Medium: it requires a specific (if not contrived) schema shape, but no privileged access, and the attacker only needs to submit ordinary bounded JSON to a public parse API.

## Recommendation
Duplicate-key detection in the JSON parser (`RecordAsSeen`/`SeenState`, and the analogous Java `JsonFormat.Parser` merge loop) should track and reject **collisions on the raw JSON member-name string** in addition to (or instead of, when short-name extension parsing is enabled) tracking by resolved field identity, so that two JSON keys with the same textual name always trigger the existing "already set" rejection regardless of which underlying `FieldDescriptor` they happen to resolve to. At minimum, `printingDeprecatedNonConformantShortExtensionNames()` should refuse to print when a name collision with a sibling field/extension is detected, since it currently produces syntactically valid but semantically ambiguous JSON that the corresponding parser cannot safely round-trip.

## Proof of Concept
1. Define a proto2 message with a regular field `extension_same_name` (JSON name `extensionSameName`) and register an extension `extensionSameName` of the same message that has the identical JSON/short name (as in `TestAllTypesProto2` / `JsonTestProto2.extensionSameName` used by the existing test) [7](#0-6) .
2. As an attacker, without needing the deprecated printer at all, directly submit the following bounded JSON to any application's `JsonFormat.parser().usingTypeRegistry(registry).merge(json, builder)` call: `{"extensionSameName": "malicious", "extensionSameName": "benign"}`.
3. Because the parser's seen-tracking is keyed by field identity, not JSON name, no `InvalidProtocolBufferException` for a "duplicate field" is thrown, and the final message state depends on internal resolution order rather than the documented "last JSON key wins" contract — reproducing the same class of outcome the shipped test demonstrates: `assertThat(parsedMessage.toString()).isNotEqualTo(message.toString())` [8](#0-7) .

**Note on verification limits:** I was not able to fully confirm, within the available index, whether the *default* (non-deprecated) `JsonFormat.Parser` path can resolve a bare (non-bracketed) JSON key to an extension field at all — the grep for `isExtension`/`ExtensionRegistry` usage inside `JsonFormat.java` returned matches but I could not retrieve their surrounding logic before the session ended. If short-name extension resolution during *parsing* is only reachable via a non-default/deprecated configuration symmetric to the printer flag, this narrows the finding to that legacy configuration only (still a valid, reachable code path, but with more limited default exposure than stated above). I recommend a Devin session with full file access to `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java` to confirm the exact parse-side extension name resolution logic and pin down the precise line ranges before filing this as a final report.

enum class SeenState {
  kFirstSeen,
  kOneofAlreadySeen,
  kFieldAlreadySeen,
};

using ::google::protobuf::internal::WireFormatLite;

// See the comment in json_util2_parser.cc for more information.
//
// The type traits in this file  describe how to parse to a protobuf
// representation used by the JSON API, either via proto reflection or by
// emitting wire format to an output stream.

// Helper alias templates to avoid needing to write `typename` in function
// signatures.
template <typename Traits>
using Msg = typename Traits::Msg;

struct ParseProto2Descriptor : Proto2Descriptor {
  // A message value that fields can be written to, but not read from.
  class Msg {
   public:
    explicit Msg(Message* msg) : msg_(msg) {}

   private:
    friend ParseProto2Descriptor;
    Message* msg_;
    // Because `msg` might already have oneofs set, we need to track which were
    // set *during* the parse separately.
    absl::flat_hash_set<int> parsed_oneofs_indices_;
    absl::flat_hash_set<int> parsed_fields_;
  };

  /// Functions for writing fields. ///

  // Marks a field as having been "seen". This will return a SeenState
  // indicating whether it is first seen, duplicate field seen, or oneof
  // conflict seen.
  static SeenState RecordAsSeen(Field f, Msg& msg) {
    if (f->real_containing_oneof() != nullptr) {
      int oneof_index = f->real_containing_oneof()->index();
      bool oneof_inserted =
          msg.parsed_oneofs_indices_.insert(oneof_index).second;
      if (!oneof_inserted) {
        // Oneof takes precedent over Field in the case of "this is in a oneof
        // and the field is set"
        return SeenState::kOneofAlreadySeen;
      }
    }

    bool field_inserted = msg.parsed_fields_.insert(f->number()).second;
    if (!field_inserted) {
      return SeenState::kFieldAlreadySeen;
    }

    return SeenState::kFirstSeen;
  }

absl::Status ParseField(JsonLexer& lex, const Desc<Traits>& desc,
                        absl::string_view name, Msg<Traits>& msg) {
  absl::optional<Field<Traits>> field;
  if (absl::StartsWith(name, "[") && absl::EndsWith(name, "]")) {
    absl::string_view extn_name = name.substr(1, name.size() - 2);
    field = Traits::ExtensionByName(desc, extn_name);

    if (field.has_value()) {
      // The check for whether this is an invalid field occurs below, since it
      // is combined for both extension and non-extension fields.
      auto correct_type_name = Traits::TypeName(desc);
      if (Traits::TypeName(Traits::ContainingType(*field)) !=
          correct_type_name) {
        return lex.Invalid(absl::StrFormat(
            "'%s' is a known extension name, but is not an extension "
            "of '%s' as expected",
            extn_name, correct_type_name));
      }
    }
  } else {
    field = Traits::FieldByName(desc, name);
  }

  if (!field.has_value()) {
    if (!lex.options().ignore_unknown_fields) {
      return lex.Invalid(absl::StrFormat("no such field: '%s'", name));
    }
    return lex.SkipValue();
  }

  auto pop = lex.path().Push(name, Traits::FieldType(*field),
                             Traits::FieldTypeName(*field));

  // Any `null` values eagerly no-op, except for exactly the special cases of
  // google.protobuf.Value message and google.protobuf.NullValue enum.
  // Note that spec behavior is that we should do duplicate key checking in the
  // case of a null value, but this implementation currently does not
  // (b/519557203).
  if (lex.Peek(JsonLexer::kNull)) {
    MessageType type = ClassifyMessage(Traits::FieldTypeName(*field));
    if (type != MessageType::kValue && type != MessageType::kNull) {
      return lex.Expect("null");
    }
  }

  SeenState seen = Traits::RecordAsSeen(*field, msg);

  // Legacy nonconformant behavior only enforces duplicate key checking for
  // fields within the same oneof, otherwise enforce duplicate keys for all
  // fields.
  if (seen == SeenState::kOneofAlreadySeen ||
      (seen == SeenState::kFieldAlreadySeen &&
       !lex.options().allow_legacy_nonconformant_behavior)) {
    return lex.Invalid(absl::StrFormat(
        "'%s' has already been set (either directly or as part of a oneof)",
        name));
  }
