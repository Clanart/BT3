### Title
Unauthenticated `associatePubKey` precompile call lets anyone force-associate a victim's address, remapping/orphaning validator-removal-hook state and enabling a chain halt - (File: precompiles/addr/addr.go)

### Summary
The Bluetooth mesh CVE class is "a value the protocol expects to be secret/self-attested (a key) is accepted back from an untrusted party without proof of possession, causing the peer to be authenticated as someone it is not." The `addr` precompile's `associatePubKey` method has the analogous flaw: unlike `associate`, which requires a valid ECDSA signature to prove the caller controls the private key behind the address, `associatePubKey` accepts a raw, unauthenticated public key from *any* caller and immediately uses it to rewrite the victim's Sei⇄EVM address mapping.

### Finding Description
`PrecompileExecutor.associatePublicKey` takes a single argument — a hex-encoded compressed public key — with **no signature, no challenge, and no proof that the transaction sender owns the corresponding private key**: [1](#0-0) 

Compare this to `associate`, which requires v/r/s over a signed message to cryptographically derive the pubkey, proving possession: [2](#0-1) 

Both methods funnel into `associateAddresses`, which only checks that the *target* seiAddr isn't already associated — it does not check anything about the caller's identity or intent of the pubkey owner: [3](#0-2) 

`AssociateAddresses` then rewrites the EVM↔Sei address mapping and migrates all balances from the "direct-cast" address (`sdk.AccAddress(evmAddr[:])`) to the pubkey-derived Sei address: [4](#0-3) 

Because ECDSA public keys are recoverable from any signature the victim has ever produced (any prior EVM tx, Cosmos tx, or even an off-chain signed message), an attacker does not need the victim's cooperation or a leaked private key — only a previously-observed public key or signature, both of which are public blockchain data. The attacker can submit `associatePubKey(victimPubKeyHex)` from any address, at any time, to force the mapping change for the victim.

The codebase's own comments confirm this exact bug class was already identified as dangerous for one specific caller path (EIP-7702 `SetCode` authorities) and was partially remediated there, but the underlying precompile method itself remains callable directly and unauthenticated: [5](#0-4) [6](#0-5) 

The fix that was applied (`AssociateAuthorizationAuthorities` in the ante handler) only pre-associates SetCode authorization authorities before EVM execution — it does not restrict or authenticate calls to the `associatePubKey` precompile method itself, which remains reachable by any EVM caller for any Sei/EVM address pair whose pubkey is publicly known.

### Impact Explanation
If a victim already has protocol state anchored under their "direct-cast" identity (e.g., staking delegations, validator self-bond, distribution rewards, vesting, or any account state created against `sdk.AccAddress(evmAddr[:])` before ever calling `associate`/`associatePubKey` themselves), an attacker forcing an unsolicited `associatePubKey` re-derives and reassigns the canonical Sei address for that EVM address to the "true" pubkey-derived address instead of the cast address the victim's other on-chain state (delegations, validator records) is keyed to. The code's own inline comment states this orphaning "can then halt the chain via the distribution validator-removal hook," i.e., a state inconsistency that can crash validator nodes or halt block production — a chain-halt-class impact reachable purely from a public precompile call with no privileged access required.

Even setting aside the halt scenario, this is an authentication bypass: the "associate" flow's entire security model rests on proving key possession via signature, and `associatePubKey` circumvents that proof, letting an unrelated third party dictate the address-mapping timing and target for a victim's account.

### Likelihood Explanation
High reachability: `associatePubKey` is a standard, permissionless method on the `addr` precompile at `0x1004`, callable by any EVM transaction sender with 50000 gas, requiring only a previously-observed public key (recoverable from any signature the target has ever produced). No governance, validator, or operator privileges are needed. The specific halt condition requires the victim to have pre-existing state tied to their cast address, which is a common occurrence for delegations/vesting funded before EVM association — a realistic and not-yet-fully-mitigated scenario, since the applied fix (`AssociateAuthorizationAuthorities`) is scoped narrowly to SetCode authorization authorities rather than to the `associatePubKey` precompile call path itself.

### Recommendation
Require proof of key possession before honoring `associatePubKey`, e.g., mirror `associate`'s signature-based flow (derive the pubkey from a v/r/s signature over a domain-separated challenge) rather than accepting a raw, self-declared public key. Alternatively, restrict `associatePubKey` to only be invocable when `msg.sender`/tx origin matches the EVM address derived from the supplied pubkey, and audit/guard the general address-remap path (not just the SetCode-authority case) against orphaning delegation/vesting/distribution state tied to the cast address before allowing an association-driven remap.

### Proof of Concept
1. Observe any historical transaction (Cosmos or EVM) signed by victim V; recover V's uncompressed secp256k1 public key (via `ecrecover` on an EVM tx signature, or directly from a Cosmos tx's `pub_key` field).
2. Before V calls `associate`/`associatePubKey` themselves, and while V has state (e.g., staking delegation, vesting account, or pending distribution rewards) anchored at `castAddr = sdk.AccAddress(V_evmAddr[:])`, submit, from any unrelated address:
   `addr.associatePubKey(V_pubKeyHexUncompressed)`
   at precompile `0x0000000000000000000000000000000000001004`.
3. `associatePublicKey` parses the pubkey, derives `evmAddr`/`seiAddr`, and calls `associateAddresses` → `AssociateAddresses`, which sets the EVM↔Sei mapping to the pubkey-derived seiAddr and migrates balances from `castAddr` to the new seiAddr — all without any signature or consent from V.
4. If V had delegation/validator/distribution state tied to `castAddr`, that state becomes orphaned relative to the newly-mapped canonical address, which per the codebase's own documented concern can trigger the distribution module's validator-removal hook in a way that halts the chain. func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}
