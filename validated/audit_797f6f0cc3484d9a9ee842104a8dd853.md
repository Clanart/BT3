### Title
Unverified L2 Height from RPC Metadata Used for Deposit/Withdrawal Collection Instead of Cryptographically Verified Journal Value — (`core/src/citrea.rs`)

### Summary

In `get_light_client_proof`, the `l2_height` returned to all callers is taken from the **unverified** RPC response metadata field `proof_result.light_client_proof_output.last_l2_height`, while the cryptographically verified value `proof_output.last_l2_height` (deserialized from the receipt journal that is then verified via `receipt.verify(lc_image_id)`) is computed but never cross-checked against it. This unverified height propagates into `get_citrea_l2_height_range` and then into `update_citrea_deposit_and_withdrawals`, controlling which L2 blocks are scanned for deposits and withdrawals. A Citrea light client prover that returns a valid proof but a mismatched `last_l2_height` in its RPC envelope can silently shift the deposit/withdrawal collection window, causing the verifier to miss valid withdrawals or to recognize withdrawals from L2 blocks that are ahead of the current L1 block's state root.

### Finding Description

```rust

`proof_output.last_l2_height` (the verified value) is never compared to `proof_result.light_client_proof_output.last_l2_height` (the unverified value). The unverified `l2_height` is what gets returned as the third tuple element. [1](#0-0) 

`get_citrea_l2_height_range` then uses this unverified value directly:

```rust

let l2_height_start: u64 = proof_previous.2; // unverified
Ok((l2_height_start, l2_height_end))
``` [2](#0-1) 

These heights are passed to `update_citrea_deposit_and_withdrawals` in the verifier: [3](#0-2) 

Which calls `collect_deposit_move_txids(last_deposit_idx, l2_height_end)` and `collect_withdrawal_utxos(last_withdrawal_idx, l2_height_end)`, querying the bridge contract at `BlockId::Number(l2_height_end)`: [4](#0-3) [5](#0-4) 

The inconsistency is confirmed by the operator code in `send_asserts`, which correctly reads `l2_height` from the **verified** journal:

```rust
let proof_output: LightClientCircuitOutput = borsh::from_slice(&lcp_receipt.journal.bytes)?;
let l2_height = proof_output.last_l2_height;  // ← verified value used here
``` [6](#0-5) 

### Impact Explanation

If the Citrea light client prover returns a cryptographically valid proof for L1 block N but sets `last_l2_height = M` in the RPC response envelope where M ≠ the actual L2 height committed in the proof journal:

- **M inflated (M > actual):** `collect_withdrawal_utxos` queries the bridge contract at L2 block M. If M corresponds to a real L2 block that is ahead of the state root committed in the LCP for L1 block N, the verifier collects withdrawal UTXOs from L2 blocks that have not yet been anchored to the current L1 block. These UTXOs are stored in the DB and become eligible for `sign_optimistic_payout`. The verifier would then co-sign optimistic payout transactions for withdrawals that are not yet finalized under the current L1 state root, potentially causing the operator to pay out BTC for withdrawals that could later be invalidated.

- **M deflated (M < actual):** The verifier misses deposits and withdrawals from L2 blocks between M and the actual height. Missed deposits mean the bridge does not recognize valid peg-in events; missed withdrawals mean the verifier never stores the withdrawal UTXO and will refuse to sign the optimistic payout, breaking liveness for those users.

### Likelihood Explanation

The trigger requires the Citrea light client prover to return a valid ZK proof whose journal commits to the correct L2 state root, but with a different `last_l2_height` in the outer RPC response struct. This can occur if:

1. The light client prover service has a bug that populates the metadata field from a different source than the journal.
2. The RPC transport is intercepted and the metadata field is tampered with (the proof bytes themselves are not re-signed at the transport layer).
3. The prover is operated by a party that is incentivized to shift the deposit/withdrawal window (e.g., to front-run or suppress specific withdrawals).

Because the code already deserializes `proof_output` from the verified journal and has `proof_output.last_l2_height` available, the fix is a one-line change with no cryptographic cost.

### Recommendation

Replace the unverified RPC metadata value with the value extracted from the verified journal in `get_light_client_proof`:

```rust
// Before (line 520):
let l2_height = u64::try_from(proof_result.light_client_proof_output.last_l2_height)
    .wrap_err("Failed to convert l2 height to u64")?;

// After — move this line to after receipt.verify() and use the verified output:
let l2_height = u64::try_from(proof_output.last_l2_height)
    .wrap_err("Failed to convert l2 height to u64")?;
```

This matches the pattern already used correctly in `operator.rs` (`send_asserts`, line 1327) and eliminates the divergence between the verified and unverified sources.

### Proof of Concept

1. Citrea light client prover returns a valid RISC Zero receipt for L1 block N (journal commits to state root S at actual L2 height 900) but sets `light_client_proof_output.last_l2_height = 1000` in the RPC response envelope.
2. `get_light_client_proof(N, ...)` passes `receipt.verify(lc_image_id)` (proof is valid), but returns `l2_height = 1000` (unverified).
3. `get_citrea_l2_height_range(N, ...)` sets `l2_height_end = 1000`.
4. `update_citrea_deposit_and_withdrawals` calls `collect_withdrawal_utxos(last_idx, 1000)`.
5. The bridge contract is queried at L2 block 1000; it returns withdrawal UTXOs from L2 blocks 900–1000 that are not yet anchored to L1 block N's state root.
6. These UTXOs are written to the DB via `update_withdrawal_utxo_from_citrea_withdrawal`.
7. When the operator calls `sign_optimistic_payout` for one of these UTXOs, the verifier finds it in the DB and co-signs the payout.
8. The operator broadcasts the payout transaction, paying out BTC for a withdrawal that has not been finalized under the current L1 state root. [7](#0-6) [8](#0-7) [9](#0-8)

    async fn get_citrea_l2_height_range(
        &self,
        block_height: u64,
        timeout: Duration,
        paramset: &'static ProtocolParamset,
    ) -> Result<(u64, u64), BridgeError> {
        let start = std::time::Instant::now();
        let proof_current = loop {
            if let Some(proof) = self.get_light_client_proof(block_height, paramset).await? {
                break proof;
            }

            if start.elapsed() > timeout {
                return Err(eyre::eyre!(
                    "Light client proof not found for block height {} after {} seconds",
                    block_height,
                    timeout.as_secs()
                )
                .into());
            }

            tokio::time::sleep(Duration::from_secs(1)).await;
        };

        let proof_previous = self
            .get_light_client_proof(block_height - 1, paramset)
            .await?
            .ok_or(eyre::eyre!(
                "Light client proof not found for block height: {}",
                block_height - 1
            ))?;

        let l2_height_end: u64 = proof_current.2;
        let l2_height_start: u64 = proof_previous.2;

        Ok((l2_height_start, l2_height_end))
    }
