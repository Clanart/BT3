### Title
Payout OP_RETURN attribution trusted without verifying operator funded the payout - (`core/src/verifier.rs::update_finalized_payouts`)

### Summary
`update_finalized_payouts` sets `withdrawals.payout_payer_operator_xonly_pk` purely from the first OP_RETURN push of whichever confirmed transaction spends the registered withdrawal UTXO, with no check that the named operator's own wallet supplied any of the transaction's value. Because the withdrawal's key-spend signature uses `SinglePlusAnyoneCanPay`, an unprivileged attacker (acting as their own withdrawing user) can fully self-fund the payout and stamp an arbitrary honest operator's x-only pubkey into the OP_RETURN, and that operator's own automated node will later spend its collateral to claim a `Reimburse` payout it never actually funded.

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk == the party whose Bitcoin actually funded the payout output`. Before the bug this should always hold; after the attack, the DB records an operator X who contributed no value.

Trace:
1. `create_payout_txhandler`/`create_optimistic_payout_txhandler` construct a payout tx whose only *signed* input is the withdrawal UTXO (`input_utxo`), key-path spent with the user's `taproot::Signature` under `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) . `SinglePlusAnyoneCanPay` only commits to input 0 and output 0 — an OP_RETURN output (containing whichever operator pubkey the fronting party chooses) and any additional funding inputs are entirely unconstrained by the user's signature.
2. The user-controlled `withdraw()` gRPC path enforces this sighash type explicitly [2](#0-1) , and the withdrawal UTXO itself is a taproot output controlled by the withdrawing party's own key [3](#0-2) . An attacker who is the withdrawing user (deposits into the bridge, calls Citrea's `withdraw`) fully controls this UTXO's value and its own signature.
3. Because of `SinglePlusAnyoneCanPay`, the attacker can independently build and broadcast a payout tx that: (a) reuses the same signed input 0/output 0 pair (self-funded, sized to cover the withdrawal amount), (b) adds an OP_RETURN naming an arbitrary honest operator X's x-only pubkey instead of their own, with no cryptographic binding of X to the transaction.
4. When this tx confirms, `update_finalized_payouts` extracts the operator pubkey solely via `parse_op_return_data`/`XOnlyPublicKey::from_slice` and writes it to the DB with no check of who funded the tx's inputs [4](#0-3) , backed by `update_payout_txs_and_payer_operator_xonly_pk` [5](#0-4) .
5. Operator X's own automated `PayoutCheckerTask` periodically polls `get_first_unhandled_payout_by_operator_xonly_pk(X)` [6](#0-5)  and, finding this poisoned row, automatically calls `handle_finalized_payout` and eventually `end_round`/kickoff flow [7](#0-6)  — no human action or consent from operator X is required.
6. `is_kickoff_malicious` only checks `operator_xonly_pk == kickoff_data.operator_xonly_pk` and the committed payout blockhash — it never re-derives who funded the payout tx's inputs [8](#0-7) , so the forged attribution sails through unchallenged.
7. `create_reimburse_txhandler` then spends the deposit's vault UTXO (`UtxoVout::DepositInMove`) and pays the reimbursement directly to X's `operator_reimbursement_address` [9](#0-8) , funded from X's own kickoff/round collateral chain that X's node spent based purely on the forged DB row.

Existing guards checked and found insufficient: `Verifier::is_kickoff_malicious` (only compares pubkeys/blockhash, no funding check), `SECP.verify_schnorr` (only verifies the user's own signature over input 0/output 0, which is untouched by the forged OP_RETURN under `AnyoneCanPay`), and the presigned transaction graph (does not constrain the payout tx's OP_RETURN or extra inputs at all, since the payout tx is not part of the N-of-N presigned graph).

### Impact Explanation
Operator X's node autonomously consumes one of its limited per-round kickoff slots and its own round/collateral chain to claim a `Reimburse` transaction paying `bridge_amount` from the deposit's vault UTXO to X's reimbursement address, for a withdrawal X never funded — this is exactly the Critical category "an operator reimbursed for a payout it never funded." The party that actually funded the payout (the attacker, self-funding their own withdrawal) receives no reimbursement credit, so bridge value earmarked to reimburse the true funder is diverted to an uninvolved operator. This is repeatable per withdrawal/deposit and against any operator whose x-only pubkey is public (all operator pubkeys are public protocol data), so the blast radius spans every operator and every future withdrawal.

### Likelihood Explanation
No verifier/operator/aggregator privilege, collateral, or key share is required — only the ability to deposit, call Citrea's `withdraw`, sign with `SinglePlusAnyoneCanPay`, and broadcast a Bitcoin transaction, all of which are explicitly in the unprivileged attacker's capability set. The only cost is normal Bitcoin fees plus the withdrawal's own value (which the attacker recovers to themselves in the same transaction). Feasibility is high because `SinglePlusAnyoneCanPay` is a required sighash flag in this protocol specifically to allow flexible funding of the payout, and nothing else constrains the OP_RETURN content or additional inputs.

### Recommendation
Do not derive `payout_payer_operator_xonly_pk` solely from an unauthenticated OP_RETURN push. Either (a) require operators to co-sign or otherwise cryptographically commit (e.g., via a musig2/tweaked-output binding or an operator-authenticated ACK) to fronting a specific withdrawal before `update_finalized_payouts` attributes it to them, or (b) verify that the named operator's inputs (or a change/anchor output under their control) actually contributed value to the payout transaction before recording attribution, and re-validate this funding-source binding inside `is_kickoff_malicious` before allowing a kickoff/reimbursement to proceed.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,

    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {

            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
