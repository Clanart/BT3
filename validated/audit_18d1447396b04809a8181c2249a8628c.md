### Title
Spoofed `WWW-Authenticate` realm on a malicious/proxied remote triggers unsolicited GitHub Enterprise sign-in and account binding to an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
When Git needs credentials for a remote, GitHub Desktop's trampoline credential helper decides whether the target host should be treated as a GitHub/GitHub Enterprise endpoint by inspecting the `WWW-Authenticate` header that the *remote server* returned during the failed auth attempt. That header value is fully attacker-controlled (it comes from whatever server a malicious or spoofed/MITM'd remote/proxy responds with) and is used as a "happy path" shortcut that bypasses the actual network verification (`isGitHubHost`) normally used to confirm a host is a real GitHub Enterprise instance.

### Finding Description
`getEndpointKind` in [1](#0-0)  classifies a credential request's target endpoint as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`. For hosts that aren't literally `github.com`/`ghe.com`, it relies on the `WWW-Authenticate` header Git forwards from the remote's HTTP response:

```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
```

This header is set entirely by the remote server (or any proxy sitting in front of it) that the user's repository points to — the same class of attacker described as controlling "a git remote/proxy response" in the task's valid-impact list. Unlike the fallback path, which calls `isGitHubHost` and performs an actual `/meta` request with `x-github-request-id` verification ( [2](#0-1) ), the header-based shortcut performs **no verification at all** that the host is a genuine GitHub Enterprise server.

Once `getEndpointKind` returns `'enterprise'`, `getCredential` in the same file checks whether an account already exists for that endpoint; if not (which is the normal case for a first-time malicious remote), it calls `ui.promptForGitHubSignIn(endpoint)` ( [3](#0-2) ).

`promptForGitHubSignIn` in [4](#0-3)  then unconditionally starts the real Enterprise sign-in flow bound to the attacker-controlled origin:

```
this.dispatcher.beginEnterpriseSignIn(cb)
await this.dispatcher.setSignInEndpoint(origin)
this.dispatcher.showPopup({ type: PopupType.SignIn, isCredentialHelperSignIn: true, credentialHelperUrl: endpoint })
```

This is invoked from a background git operation (fetch/pull/push/clone) — no explicit "add account" action by the user — and results in the full GitHub Enterprise sign-in dialog (username/password or OAuth) being shown for a host the attacker chose, purely because the attacker's server echoed a specific header string.

### Impact Explanation
This breaks the invariant that GitHub account/endpoint bindings in Desktop are only created deliberately by the user through "Add Account" flows for hosts the user trusts. Here, an attacker who controls the git remote (or a MITM/proxy in front of it) that the victim has cloned/added can force Desktop to spontaneously open a GitHub Enterprise sign-in dialog scoped to a host of the attacker's choosing, during an otherwise routine `fetch`/`pull`/`push`. If the user completes the flow (which will appear to be a normal part of using Desktop, e.g. "connect your GitHub Enterprise account"), Desktop registers/binds an account for that attacker-controlled endpoint via `AccountsStore`. This matches the explicitly listed valid impact "unauthorized OAuth or account binding" — the app is coerced into creating an account association the user never intended to create, tied to infrastructure the attacker controls, using nothing but a forged HTTP header in a `401` response.

### Likelihood Explanation
The trigger condition requires only that the victim performs a normal git network operation against a repository whose remote (or an on-path proxy for that remote) is attacker-controlled — a scenario explicitly permitted by the task's threat model ("attacker controls...a git remote/proxy response"). No local access, malware, or leaked credentials are needed; the attacker merely needs to serve a `401` response with `WWW-Authenticate: Basic realm="GitHub"` for the credential fill request. The existing guard (`isGitHubHost`'s network-based verification) is bypassed entirely by design for this code path, so there is no check that stops it.

### Recommendation
Do not trust the `WWW-Authenticate` realm string alone to classify a host as GitHub/Enterprise for accounts the app has never seen before. At minimum, require the `isGitHubHost` network verification (with its `x-github-request-id` check) to succeed before offering to start a sign-in flow for an unknown endpoint, and/or surface the actual remote hostname prominently in the sign-in prompt so users can recognize an unexpected/unfamiliar domain before authenticating.

### Proof of Concept
1. Attacker hosts a git-over-HTTP(S) remote (or sits as a MITM/proxy in front of one) at `https://evil.example.com/repo.git`.
2. Victim adds/clones this remote in GitHub Desktop and performs a `fetch`/`pull`/`push`.
3. Git issues an unauthenticated request; the attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Desktop's trampoline credential helper (`getEndpointKind`) sees this header, matches `realm="GitHub"`, and classifies `evil.example.com` as `'enterprise'` without any real verification.
5. `getCredential` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which calls `dispatcher.beginEnterpriseSignIn` + `setSignInEndpoint(origin)` and shows the `SignIn` popup scoped to that attacker-chosen origin — all without any explicit "Add account" action from the user.
6. If the victim completes the sign-in dialog (believing it's a legitimate part of connecting to their repository's host), Desktop stores/binds a GitHub Enterprise account for `evil.example.com`.

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

```typescript
/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }
```

```typescript
  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
```
