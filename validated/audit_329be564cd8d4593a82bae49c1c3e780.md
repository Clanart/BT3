### Title
Uncontrolled Recursive Decoding of `AccountKeyRoleBased` Enables Stack-Overflow DoS via Nested Account Keys - (File: `blockchain/types/accountkey/account_key_role_based.go`)

### Summary
The ImageMagick advisory describes an unbounded-recursion stack overflow (CWE-674) reachable from a single crafted input to an expression parser. Kaia's `AccountKeyRoleBased` RLP/JSON decoding contains the same bug class: it recursively re-enters the generic `AccountKeySerializer` decoder for each nested key without any depth limit or type restriction, and nothing prevents a `RoleBased` key from containing another `RoleBased` key. A single crafted, deeply-nested `AccountKey` byte blob — reachable via the public `kaia_decodeAccountKey` RPC or via a submitted `AccountUpdate`/`FeeDelegatedAccountUpdate` transaction — can drive unbounded recursive decoding and crash the node process.

### Finding Description
`AccountKeyRoleBased.DecodeRLP` decodes a list of raw byte blobs and, for every element, calls `rlp.DecodeBytes` into a fresh `AccountKeySerializer`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` reads a key type tag, instantiates the corresponding `AccountKey` via `NewAccountKey`, and decodes into it: [2](#0-1) 

`NewAccountKey` maps `AccountKeyTypeRoleBased` straight back to `NewAccountKeyRoleBased()`: [3](#0-2) 

There is no check anywhere in this decode path that rejects a `RoleBased` key type nested inside another `RoleBased` key, and no depth counter is threaded through `DecodeRLP`. This means the call chain
`AccountKeyRoleBased.DecodeRLP → rlp.DecodeBytes → AccountKeySerializer.DecodeRLP → s.Decode(key) → AccountKeyRoleBased.DecodeRLP → …`
can be driven to arbitrary depth purely by the byte content supplied by the caller — the classic uncontrolled-recursion pattern (CWE-674) described in the ImageMagick advisory, just expressed through nested RLP-encoded account keys instead of nested FX expressions.

This decoder is directly reachable from unprivileged input in two ways:
1. The public RPC method `KaiaAPI.DecodeAccountKey`, which takes arbitrary hex bytes from any RPC caller and feeds them straight into `rlp.DecodeBytes(encodedAccKey, &dec)` with no size/depth guard: [4](#0-3) 
2. Any `AccountUpdate`/`FeeDelegatedAccountUpdate` transaction submitted by a normal sender, whose `Key` field is unmarshalled the same way before any `CheckInstallable` validation occurs: [5](#0-4) 

Because decoding happens before `CheckInstallable`/`Validate` are ever invoked, any nesting-depth restrictions that might exist at the semantic-validation layer do not protect the decode step itself — the recursive decode executes fully (or until the stack overflows) regardless of whether the resulting key would later be rejected as invalid.

### Impact Explanation
Go does not support catching a stack-overflow condition (it is a fatal, unrecoverable runtime error, not a `panic` that can be `recover()`-ed), so triggering this condition kills the entire node process. Since this is reachable via a public JSON-RPC call (`kaia_decodeAccountKey`) with no fee, no signature, and no state change required, an unauthenticated remote caller can crash any Kaia node/RPC endpoint that exposes this API — a straightforward availability (crash/DoS) impact, matching the original advisory's `A:H, C:N, I:N` characterization.

### Likelihood Explanation
High likelihood: the payload is trivially constructible by wrapping an `AccountKeyRoleBased` serializer around another `AccountKeyRoleBased` serializer, repeated to whatever depth is needed to exhaust the goroutine stack (Go stacks grow but are still bounded, and each recursion level here involves multiple nested calls through `rlp` reflection machinery, `DecodeRLP`, and `AccountKeySerializer`, consuming non-trivial stack per level). No authentication, gas payment, or special network position is needed — a single RPC call with a hex string suffices.

### Recommendation
- Enforce a maximum recursion/nesting depth in `AccountKeySerializer.DecodeRLP` / `AccountKeyRoleBased.DecodeRLP` (e.g., reject decoding if `AccountKeyTypeRoleBased` is encountered while already decoding inside a `RoleBased` context, since role-based keys should never legitimately nest).
- Add an explicit check in `NewAccountKey`/`AccountKeySerializer.DecodeRLP` disallowing `AccountKeyTypeRoleBased` as a member type of `AccountKeyRoleBased`.
- Apply the same nesting guard to the JSON decode path (`AccountKeyRoleBased.UnmarshalJSON`) since it is equally recursive and reachable from RPC/tx submission.
- Add a global recursion-depth counter/limit to `rlp.Stream` decoding for `Decoder`-implementing types, so any future composite/recursive type is protected by default.

### Proof of Concept
1. Construct `leaf = AccountKeySerializer{keyType: AccountKeyTypePublic, key: <valid pubkey>}`, RLP-encode it.
2. Build `inner = AccountKeyRoleBased{leaf-as-bytes, leaf-as-bytes, leaf-as-bytes}`, RLP-encode via `AccountKeyRoleBased.EncodeRLP`, wrap as an `AccountKeySerializer{keyType: AccountKeyTypeRoleBased, key: inner}`.
3. Repeat step 2, using the previous serializer's bytes as one of the three "role" slots, N times (e.g., N = 100,000), producing a deeply right-nested `RoleBased(RoleBased(RoleBased(...)))` byte blob.
4. Call the public RPC:
   ```
   curl -X POST --data '{"jsonrpc":"2.0","method":"kaia_decodeAccountKey","params":["0x<nested_blob>"],"id":1}' http://<node>:8551
   ```
5. `rlp.DecodeBytes` recurses through `AccountKeyRoleBased.DecodeRLP → AccountKeySerializer.DecodeRLP` N times; sufficiently large N crashes the node process with a fatal stack-overflow error rather than returning a JSON-RPC error.

```go
func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}
```

```go
func (serializer *AccountKeySerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.keyType); err != nil {
		return err
	}

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.key)
}
```

```go
func NewAccountKey(t AccountKeyType) (AccountKey, error) {
	switch t {
	case AccountKeyTypeNil:
		return NewAccountKeyNil(), nil
	case AccountKeyTypeLegacy:
		return NewAccountKeyLegacy(), nil
	case AccountKeyTypePublic:
		return NewAccountKeyPublic(), nil
	case AccountKeyTypeFail:
		return NewAccountKeyFail(), nil
	case AccountKeyTypeWeightedMultiSig:
		return NewAccountKeyWeightedMultiSig(), nil
	case AccountKeyTypeRoleBased:
		return NewAccountKeyRoleBased(), nil
	}

	return nil, errUndefinedAccountKeyType
}
```
