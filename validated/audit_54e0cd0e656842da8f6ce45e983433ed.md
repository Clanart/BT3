### Title
Melting a PlotNFT with unclaimed pool rewards permanently strands those rewards - ([File: chia/wallet/plotnft_wallet/plotnft_wallet.py])

### Summary
`PlotNFT2Wallet.melt_plotnft()` and the underlying `PlotNFT.melt()` allow a user to permanently destroy their plot-NFT singleton without any check for outstanding, unclaimed pool rewards recorded in `PlotNFTStore.pool_reward2s`. Because `claim_rewards()` requires spending the live singleton coin (`self.singleton_action_spend(...)`) to sweep any `PoolReward` coins recorded for that `singleton_id`, once the singleton is melted there is no longer a coin capable of producing the spend needed to claim those funds, and any reward coins not yet claimed become permanently unspendable to the user. This mirrors the reported bug class: an action that ends the "staking" relationship (`withdrawStake`/melt) can be invoked without first requiring/forcing a claim of pending rewards, silently and permanently forfeiting them.

### Finding Description
`PlotNFT.melt()` in [1](#0-0)  only guards against melting while `self.pooling` is true; it performs no check on whether there are unclaimed `PoolReward` coins associated with this singleton's `launcher_id`.

`PlotNFT2Wallet.melt_plotnft()` calls `plotnft.melt(...)` directly and pushes the melt spend without ever consulting `plotnft2_store.get_pool_rewards(...)`: [2](#0-1) .

Meanwhile, `claim_rewards()` is the only path that can sweep pending pool rewards, and it fundamentally requires spending the current live plotnft singleton coin via `plotnft.claim_pool_rewards(...)` (which internally builds a `singleton_action_spend`): [3](#0-2)  and [4](#0-3) .

Pending pool rewards are tracked independently of singleton liveness in `pool_reward2s`, keyed only by `singleton_id`, with no linkage that blocks deletion/melt of the parent PlotNFT while such rows remain unclaimed: [5](#0-4) .

The existing test suite even documents that failing to sweep rewards before advancing/forwarding state results in permanent loss ("LOSE REWARDS (while pooling)"), confirming the code's behavior is that un-swept reward coins tied to a prior singleton state are gone once the singleton state moves past them: [6](#0-5) . The `melt` command/RPC path (`MeltPlotNFTCMD` → `melt_cmd` → `PWSelfPool`/`PlotNFTMelt` RPC → `melt_plotnft`) reaches this code from a normal, unprivileged wallet-owner action: [7](#0-6) , [8](#0-7) .

### Impact Explanation
If a user (or their wallet UI/CLI, if it does not always enforce claim-before-melt) calls `melt` while there are still unabsorbed/forwarded pool reward coins sitting at the `p2_singleton_puzzle_hash` for that PlotNFT's `launcher_id`, those coins can never be recovered by the user again: melting removes the singleton coin the claim spend needs, deletes the wallet record (`delete_self`), and there is no other code path in `chia/pools/` or `chia/wallet/plotnft_wallet/` that can produce a valid spend to sweep coins tied to a defunct singleton. This is a direct, permanent loss of farming/pooling rewards — real XCH value — for an honest user performing a supported wallet action.

### Likelihood Explanation
Medium: the CLI's `melt_cmd` may include a UX check, but this could not be fully verified in the available index; regardless, the underlying wallet method `melt_plotnft()` and the RPC endpoint `plotnft_melt` (`PlotNFTMelt`/`PlotNFTMeltResponse`) impose no protocol-level restriction, so any direct RPC caller, third-party wallet frontend, or future CLI change bypassing a client-side check can trigger irreversible reward loss. As with the analog report, the risk stems specifically from the front-end being the only safety net rather than the wallet/RPC layer enforcing correctness.

### Recommendation
In `PlotNFT2Wallet.melt_plotnft()` (and/or `PlotNFT.melt()`), query `plotnft2_store.get_pool_rewards(plotnft_id=self.plotnft_id)` before constructing the melt spend, and raise a `ValueError` (mirroring the pattern already used in `claim_rewards()` for `"No rewards to claim"`) if any unclaimed rewards exist, e.g. `"Cannot melt PlotNFT: N unclaimed pool rewards must be claimed first"`. Alternatively, automatically call `claim_rewards()` as part of `melt_plotnft()` before emitting the melt spend, analogous to the report's second suggested fix of auto-claiming inside `withdrawStake`.

### Proof of Concept
Conceptual PoC (not directly executable from the index, but derivable from the cited code paths):
1. Create a PlotNFT2 wallet, join a pool or self-pool, and farm blocks so that one or more pool reward coins are created and recorded via `PlotNFTStore.add_pool_reward()` (as exercised in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py:288-301`, where the last unforwarded reward is deliberately left unclaimed to demonstrate loss).
2. Transition to self-custody (leave pool / finish leaving) as shown in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py:406-513`, without first calling `claim_rewards()` for the outstanding reward coin(s).
3. Call `PlotNFT2Wallet.melt_plotnft()` (or the `plotnft melt` CLI/RPC) as in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py:556-559`.
4. Observe that the plotnft wallet is deleted (`delete_self`) and the singleton coin is destroyed; the previously recorded `pool_reward2s` rows for that `singleton_id` can no longer be swept by any remaining wallet code path, since `claim_pool_rewards`/`claim_rewards` require an active, spendable singleton coin that no longer exists.

        self,

        if len(rewards_to_claim) == 0:

        total_reward_amount = uint64(sum(reward.coin.amount for reward in rewards_to_claim))
        if fee > total_reward_amount:

                            CreateCoin(

                        if len(rewards_to_claim) > 1
                        else extra_conditions,
                    ).at("rf"),  # strips away to just the delegated puzzle (bit of a hack)

    async def melt_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        coin_spends = plotnft.melt(extra_conditions=(fee_hook, *extra_conditions))
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
        async with action_scope.use() as interface:
            interface.side_effects.transactions.append(
                self.wallet_state_manager.new_outgoing_transaction(
                    wallet_id=self.id(),
                    puzzle_hash=bytes32.zeros,
                    amount=uint64(1),
                    fee=fee,
                    spend_bundle=spend_bundle,
                    additions=[],
                    removals=[plotnft.coin],
                    name=spend_bundle.name(),
                    extra_conditions=extra_conditions,
                )
            )

    async def get_pool_rewards(
        self,
        *,
        plotnft_id: bytes32,
        max: int = DEFAULT_POOL_REWARDS_PER_CLAIM,
        include_spent: bool = False,
    ) -> list[PoolReward]:
        async with self.db_wrapper.reader() as conn:
            rows = await conn.execute_fetchall(
                (
                    "SELECT * from pool_reward2s WHERE singleton_id = ?"
                    + (" AND spent_height IS NULL" if not include_spent else "")
                    + " ORDER BY spent_height ASC LIMIT ?"
                ),
                (plotnft_id, max),
            )
            pool_rewards_selected = [
                PoolReward(
                    coin=Coin(
                        parent_coin_info=bytes32(row[1]), puzzle_hash=bytes32(row[2]), amount=uint64.from_bytes(row[3])
                    ),
                    singleton_id=bytes32(row[4]),
                )
                for row in rows
            ]
            return pool_rewards_selected
