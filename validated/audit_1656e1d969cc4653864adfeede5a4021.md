### Title
Ed448 deserializes non-prime-order points, enabling Schnorr signature forgeries - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary
`Point::is_torsion_free` is a tautology: it computes `(*self * -1) + self` and checks identity, which is true for every Ed448 point, so `GroupEncoding::from_bytes` accepts small-order/full-curve points as `PrimeGroup`. [1](#0-0)  `Ciphersuite::read_G` only checks `from_bytes` plus canonical round-trip encoding, so attacker-supplied Ed448 bytes for torsion points are accepted. [2](#0-1) 

### Finding Description
The intended subgroup check is ineffective because `is_torsion_free` always returns `Choice::from(true)`: multiplying any point by `-1` and adding itself yields the identity. [3](#0-2)  Decoding therefore reduces to curve-equation validity, negative-zero rejection, and canonical encoding checks, not prime-order subgroup membership. [4](#0-3)  These invalid points can then flow into `SchnorrSignature::read` / `verify`, whose equation is `R + cA - sG = 0` without rejecting non-prime-order `A` or `R`. [5](#0-4) 

### Impact Explanation
For an Ed448 public key `A = T` of order 2, a forged signature `(R, s)` satisfies verification whenever the torsion component of `R` equals `cT`; since `sG` is prime-order, matching the order-2 component makes the whole equation hold. This produces a forged Schnorr signature under a deserialized public key that callers believe is a valid `PrimeGroup` key; the same deserialization path is reachable through `read_G`, `SchnorrSignature::read`, and PedPoP `EncryptedMessage`/`pop` verification inputs. [6](#0-5) [7](#0-6) 

### Likelihood Explanation
The attacker only needs to submit byte encodings to an API accepting Ed448 points/signatures; no secret, validator collusion, unsafe code, or malformed curve implementation is required. For an order-2 key, success requires searching a few `s`/`R` candidates until `u == parity(H(R, A, msg))` for `R = sG + uT`, an expected constant number of public trials.

### Recommendation
Implement a real subgroup check for Ed448 points in `GroupEncoding::from_bytes` / `from_bytes_unchecked`, reject identity and small-order points at `Ciphersuite::read_G` or at signature/PoP verification boundaries, and add Ed448 torsion encodings as negative deserialization tests. [8](#0-7) [9](#0-8)

impl Point {
  fn is_torsion_free(&self) -> Choice {
    ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
  }
}

impl GroupEncoding for Point {
  type Repr = <FieldElement as PrimeField>::Repr;

  fn from_bytes(bytes: &Self::Repr) -> CtOption<Self> {
    // Extract and clear the sign bit
    let sign = Choice::from(bytes[56] >> 7);
    let mut bytes = *bytes;
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] &= !(1 << 7);

    // Parse y, recover x
    FieldElement::from_repr(bytes).and_then(|y| {
      recover_x(y).and_then(|mut x| {
        x.conditional_negate(x.is_odd().ct_eq(&!sign));
        let not_negative_zero = !(x.is_zero() & sign);
        let point = Point { x, y, z: FieldElement::ONE };
        CtOption::new(point, not_negative_zero & point.is_torsion_free())
      })
    })
  }

  fn from_bytes_unchecked(bytes: &Self::Repr) -> CtOption<Self> {
    Point::from_bytes(bytes)
  }

  fn to_bytes(&self) -> Self::Repr {
    let z = self.z.invert().unwrap();
    let x = self.x * z;
    let y = self.y * z;

    let mut bytes = y.to_repr();
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] |= x.is_odd().unwrap_u8() << 7;
    bytes
  }
}

impl PrimeGroup for Point {}

  /// Sign a Schnorr signature with the given nonce for the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[allow(clippy::needless_pass_by_value)] // Prevents further-use of this single-use value
  pub fn sign(
    private_key: &Zeroizing<C::F>,
    nonce: Zeroizing<C::F>,
    challenge: C::F,
  ) -> SchnorrSignature<C> {
    SchnorrSignature {
      // Uses deref instead of * as * returns C::F yet deref returns &C::F, preventing a copy
      R: C::generator() * nonce.deref(),
      s: (challenge * private_key.deref()) + nonce.deref(),
    }
  }

  /// Return the series of pairs whose products sum to zero for a valid signature.
  /// This is intended to be used with a multiexp.
  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
  }
