### Title
Unix Socket gRPC Server Bypasses mTLS Authentication, Allowing Any Local Process to Call Privileged Bridge Operations — (File: `core/src/servers.rs`)

### Summary
`create_grpc_server` applies TLS and the `OnlyAggregatorAndSelf` certificate-pinning interceptor only on the TCP transport branch. The Unix socket branch omits both, leaving every gRPC method — including internal operator, verifier signing, and aggregator deposit/withdrawal endpoints — callable by any local process that can reach the socket file, with no certificate check whatsoever.

### Finding Description
`create_grpc_server` in `core/src/servers.rs` dispatches on `ServerAddr`:

**TCP branch** (lines 79–176): loads server TLS identity, optionally loads the CA for client verification, wraps the service with `InterceptedService::new(service, OnlyAggregatorAndSelf { aggregator_cert, our_cert })`, and configures `.tls_config(tls_config)` on the server builder.

**Unix socket branch** (lines 178–222): builds the server with no TLS config and calls `.add_service(service)` directly on the raw, unwrapped service — no `InterceptedService`, no interceptor of any kind.

```rust
// TCP branch — authentication applied
let service = InterceptedService::new(
    service,
    if config.client_verification {
        OnlyAggregatorAndSelf { aggregator_cert, our_cert: client_cert }
    } else { Noop },
);
// ...
.tls_config(tls_config)?
.add_service(service);

// Unix socket branch — NO authentication
let server_builder = tonic::transport::Server::builder()
    .layer(AddMethodMiddlewareLayer)
    // ... rate-limit, buffer, timeout ...
    .add_service(service);   // raw service, no interceptor
```

The `OnlyAggregatorAndSelf` interceptor in `core/src/rpc/interceptors.rs` is the sole authentication gate. It reads `req.peer_certs()` and rejects any request whose leaf certificate is not the pinned aggregator cert or the entity's own cert. Without this interceptor, the gate is absent entirely.

The `socket_path` configuration key appears in the production deployment config `scripts/docker/configs/testnet4/bridge_config.toml` (`socket_path = "/"`), confirming Unix socket mode is a supported production deployment path. The `ServerAddr::Unix` variant and its handling in `create_grpc_server` are compiled under `#[cfg(unix)]`, not `#[cfg(test)]`, so the code path is present in production binaries.

### Impact Explanation
Any process on the same host (or sharing the same filesystem namespace in a container deployment) that can open the socket file can call:

- `internal_end_round` / `internal_create_new_operator_deposit` on the operator — forcing premature round advancement, corrupting the operator's UTXO chain, and potentially causing slashable collateral loss.
- `deposit_sign` / `deposit_finalize` on a verifier — obtaining partial MuSig2 signatures over attacker-chosen deposit data, enabling construction of a fraudulent move-tx.
- `set_operator` on a verifier — registering a malicious operator with attacker-controlled xonly public key, Winternitz keys, and reimbursement address, redirecting future reimbursement outputs.
- `new_deposit` / `withdraw` / `optimistic_payout` on the aggregator — initiating unauthorized deposit or withdrawal flows.

All of these map directly to the "Authentication or authorization bypass in gRPC, mTLS, actor roles, signer flow" allowed impact class, with potential for theft, permanent lock, or slashable exposure of bridged BTC and operator collateral.

### Likelihood Explanation
In containerized deployments (Docker Compose, Kubernetes with shared volumes), multiple processes share the same filesystem namespace. A compromised sidecar, monitoring agent, log collector, or any other co-located process can connect to the socket. The `socket_path` field in the testnet4 production config confirms this mode is actively used. No special privileges are required beyond filesystem read/write access to the socket path.

### Recommendation
Apply the `OnlyAggregatorAndSelf` interceptor to the Unix socket branch as well. Since Unix sockets carry no TLS peer certificates, `req.peer_certs()` will always return `None`. Two options:

1. **Token-based metadata auth**: Require a shared secret in gRPC request metadata for Unix socket connections, verified inside the interceptor when `peer_certs()` is `None` and `cfg!(not(test))`.
2. **`SO_PEERCRED` / UCred**: Use the Unix socket peer credential (UID/PID) to restrict connections to the expected process identity.

At minimum, the interceptor should be applied so that the `cfg!(test)` bypass in `only_aggregator_and_self` is the only relaxation, not a complete absence of the interceptor.

### Proof of Concept
```bash
# Attacker is any local process with access to the socket file.
# No certificate required. Calls the internal operator method directly:
grpcurl -plaintext \
  -unix /path/to/operator.sock \
  clementine.ClementineOperator/InternalEndRound

# Or calls set_operator on a verifier with attacker-controlled keys:
grpcurl -plaintext \
  -unix /path/to/verifier.sock \
  clementine.ClementineVerifier/SetOperator \
  < attacker_operator_params.json
```

The server accepts the connection and processes the request because `create_grpc_server`'s Unix socket branch adds the raw service with no interceptor, so `OnlyAggregatorAndSelf::call` is never invoked.

```rust
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
```
