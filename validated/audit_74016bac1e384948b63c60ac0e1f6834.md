### Title
Untrusted blame indexes allow an unauthenticated panic abort - ([File: crypto/dkg/pedpop/src/lib.rs])

### Summary
`AdditionalBlameMachine::blame` accepts caller-selected `sender` and `recipient` `Participant` values, then indexes the commitment map without checking that either participant exists. A caller can therefore crash the host by asking for blame on a participant outside the DKG set.

### Finding Description
`AdditionalBlameMachine::new` builds `commitments` only for `1 ..= n` and stores one entry per participant. [1](#0-0)  `blame` forwards user-controlled `sender` and `recipient` identifiers to `blame_internal`. [2](#0-1)  `blame_internal` can reach `self.commitments[&sender]` when evaluating whether the decrypted share is valid, and `HashMap` indexing panics for an absent key. [3](#0-2)  Since `Participant::new` accepts every nonzero `u16`, any `sender > n` is representable and reaches this path. [4](#0-3) 

### Impact Explanation
This is a remotely influenceable availability failure analogous to CVE-2021-3502: public protocol input drives an assertion/panic instead of a protocol error. Any service that exposes blame arbitration to untrusted accusation data can be terminated rather than returning `PedPoPError`.

### Likelihood Explanation
The trigger requires only calling `AdditionalBlameMachine::blame` with a valid nonzero `Participant` absent from the configured `1 ..= n` map, together with otherwise plausible encrypted-message/proof inputs. No secret access, malformed curve encoding, collusion, or privileged validator role is needed beyond access to the blame API.

### Recommendation
Validate that both `sender` and `recipient` exist in `self.commitments` before decryption or share evaluation, returning `PedPoPError::MissingParticipant` or a dedicated invalid-participant error. Also validate commitment vector lengths in `AdditionalBlameMachine::new`, since it documents invalid commitments as potentially panic-causing. [5](#0-4) 

### Proof of Concept
```rust
let mut msgs = HashMap::new();
// Populate msgs for participants 1..=n.
let machine = AdditionalBlameMachine::<Ed25519>::new(context, n, msgs).unwrap();

// n + 1 is a valid nonzero Participant, but has no commitments entry.
machine.blame(
  Participant::new(n + 1).unwrap(),
  Participant::new(1).unwrap(),
  msg,
  proof,
);
```

If execution reaches the share-validity check, `self.commitments[&sender]` indexes a missing key and panics. [3](#0-2)
