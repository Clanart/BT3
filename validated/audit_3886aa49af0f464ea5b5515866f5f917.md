### Title
Unbounded owner-scoped token enumeration in CW721→ERC721 pointer `balanceOf` allows consent-free griefing to DoS the pointer for a victim address - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
`CW721ERC721Pointer.balanceOf(address)` computes an owner's ERC721 balance by repeatedly querying the underlying CosmWasm CW721 contract in pages of 1000 tokens via `WasmdPrecompile.query`, looping until an empty-page terminator is returned [1](#0-0) . Because CW721 `transfer_nft`/`send_nft` execute unconditionally against the sender's own tokens with no recipient consent check [2](#0-1) , any account that owns (or mints, for permissionless CW721 collections) many token IDs can transfer an unbounded number of dust NFTs into a victim's Sei address, growing the number of tokens the victim "owns" on that collection without any action or approval from the victim, exactly mirroring how Ajna's `memorializePositions` let a third party attach dust positions to someone else's position NFT.

### Finding Description
`balanceOf` has no upper bound on the number of pagination round trips it performs — it keeps calling `WasmdPrecompile.query` with `start_after` cursors until the CW721 contract returns an empty `tokens` array [3](#0-2) . Each iteration is a real Wasm smart-query dispatched through the `wasmd` precompile from EVM execution, consuming EVM gas for the call plus the underlying CosmWasm query gas. An attacker who transfers (or, for open-mint collections, mints) thousands of token IDs to the victim's Sei-derived address inflates the number of pages `balanceOf` must walk. This is directly analogous to the Ajna bug: a third party can attach arbitrary amounts of "positions" (here, dust NFTs) to a target identity without the target's consent, degrading a function that other logic depends on.

### Impact Explanation
Once enough dust tokens are pushed onto a victim address, any call to `balanceOf(victim)` — used by ERC721 marketplace integrations, ERC721Enumerable-style consumers, or other contracts/off-chain tooling built on top of the pointer — requires proportionally more `wasmd` query round-trips and CosmWasm gas. Past a certain token count this exceeds the caller's available gas (for view/eth_call contexts) or, if invoked from a state-changing transaction path that reads `balanceOf`, can push the transaction over the block gas limit, permanently DoS'ing that function for the victim's address on the pointer contract with no way for the victim to remove or reject the unwanted tokens (CW721 has no analog to "reject incoming transfer"). This matches the accepted impact category of a crash/DoS of a specific on-chain capability caused entirely by an unprivileged third party.

### Likelihood Explanation
Likelihood is moderate to high wherever the underlying CW721 collection allows either open minting or the attacker already holds many token IDs they are free to transfer, since `transfer_nft`/`send_nft` impose no recipient-side consent check [2](#0-1) , and the attack is a plain sequence of ordinary wasm `MsgExecuteContract` transactions (`transfer_nft`) fully reachable by any unprivileged user.

### Recommendation
Bound `balanceOf`'s pagination loop (e.g., cap total pages/tokens scanned and revert or return a best-effort/capped value beyond that), and/or maintain an incrementally updated balance counter in pointer/contract state instead of re-deriving it via unbounded CW721 enumeration on every call.

### Proof of Concept
1. Deploy/identify a CW721 collection with an `ERC721Pointer` and an attacker-controlled account holding (or able to mint) N token IDs.
2. Attacker submits N `MsgExecuteContract{"transfer_nft":{"recipient":"<victim>","token_id":"<id>"}}` calls, each succeeding unconditionally per `transfer_nft` in `example/cosmwasm/cw721/src/contract.rs` lines 175-192, with no victim signature or approval required.
3. Call `CW721ERC721Pointer.balanceOf(victim)`; observe that gas cost scales with `ceil(N/1000)` `WasmdPrecompile.query` round trips per the loop at `contracts/src/CW721ERC721Pointer.sol` lines 65-77.
4. For sufficiently large N, `balanceOf(victim)` reverts out-of-gas for any caller/context with a bounded gas budget, denying that view to the victim indefinitely.

fn transfer_nft(
    deps: DepsMut<EvmQueryWrapper>,
    info: &MessageInfo,
    recipient: &str,
    token_id: &str,
) -> Result<Response<EvmMsg>, ContractError> {
    deps.api.addr_validate(recipient)?;

    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
    let payload = querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new().add_message(msg);

    Ok(res)
}
