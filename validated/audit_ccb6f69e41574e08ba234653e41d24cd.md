## Analysis

The Salty.IO report's broken invariant is: **an action is authorized/reviewed against one state (expected pool ratio) but executed against whatever state exists at transaction time, with no check that the two match.** The Desktop analog with the strongest local-code support is the pull request checkout flow, which resolves and checks out a PR branch **by ref name only**, never verifying that the commit actually checked out matches the `head.sha` the user reviewed when they decided to check out the PR. [1](#0-0) [2](#0-1) [3](#0-2) 

### Title
Pull request checkout resolves by branch name with no head-SHA pinning, allowing a fork owner to silently redirect "Checkout PR" to attacker-controlled content - (File: `app/src/lib/stores/app-store.ts`)

### Summary
`Dispatcher.checkoutPullRequest` and `AppStore._checkoutPullRequest`/`_findPullRequestBranch` take a `PullRequest` GitHub API object's `head.repo.clone_url`/`cloneURL` and `head.ref` (a branch name), add/reuse a remote for the fork, fetch it, and check out whatever the named ref resolves to at that moment [4](#0-3) . The `head.sha` that was associated with the PR when the user viewed/selected it in the PR list is never passed into this call chain and never compared against the commit that ends up checked out.

### Finding Description
The call chain is:
1. `PullRequestList.onItemClick` → `dispatcher.checkoutPullRequest(repository, pullRequest)` [5](#0-4) 
2. `Dispatcher.checkoutPullRequest` forwards `pullRequest.head.gitHubRepository.owner.login`, `.cloneURL`, and `.head.ref` — but not `.head.sha` — to `AppStore._checkoutPullRequest` [1](#0-0) 
3. `_findPullRequestBranch` finds/creates a remote pointing at `headCloneUrl`, fetches it, and builds `remoteRef = ${remote.name}/${headRefName}` — a symbolic ref, not a commit — then checks out whatever local/remote branch currently tracks that name [3](#0-2) .

Because the fork's owner (the PR author) fully controls that remote, they can force-push new commits to the head branch at any time between when the user viewed the PR (and its diff/summary) and when Desktop actually performs the fetch+checkout triggered by the click. The code re-fetches the remote fresh (`_fetchRemote`) right before resolving the branch [6](#0-5) , so whatever is on the branch *at fetch time* — not at review time — is what gets silently checked out into the user's working directory, with no diff/comparison against the previously displayed `head.sha`.

This mirrors the sandwich-attack root cause in the Salty.IO report exactly: the "price" (PR content) shown to the user when they take an action is not the "price" (commit) that is actually executed, because the system trusts a mutable pointer (AMM pool ratio / git ref) instead of an immutable, pinned value (oracle-checked ratio / commit SHA) at execution time.

### Impact Explanation
An attacker who opens a pull request against a repository the victim has open in Desktop can wait for the victim to review the PR, then force-push different content to the head branch just before (or in response to seeing) the victim click "Checkout this PR" / "Checkout in new worktree". Desktop will fetch and check out the new, unreviewed content without any warning that it differs from what was shown in the PR list/diff. If the victim subsequently builds, runs, or blindly trusts files from that checkout, or commits/pushes on top of it, this is a form of "silent corruption of what the user commits or pushes" driven purely by attacker-controlled data reachable through the GitHub API and a git remote, requiring no local access, admin rights, or prior malware.

### Likelihood Explanation
Moderate. It requires the victim to have (or be about to) view/interact with a specific PR from a repository where the attacker's fork is untrusted, and requires precise timing of a force-push relative to the click, but no other cooperation from the victim and no unnatural steps — checking out a PR is a normal, encouraged Desktop workflow for reviewing contributions.

### Recommendation
Capture `pullRequest.head.sha` at the time the checkout action is initiated and thread it through to `_checkoutPullRequest`/`_findPullRequestBranch`. After fetching the remote and resolving the branch, verify that the resolved commit's SHA matches the expected `head.sha`; if it doesn't, surface a warning to the user (similar to the existing `WarnForcePush` pattern used elsewhere) instead of silently checking out the new tip.

### Proof of Concept
1. Attacker forks the target repo and opens PR #123 from branch `feature` at commit `A` (benign diff).
2. Victim opens the PR list in Desktop; UI shows PR #123 with head sha `A`.
3. Victim clicks "Checkout this PR" (`PullRequestList.onItemClick`).
4. Immediately before Desktop's fetch completes, attacker force-pushes `feature` to point at commit `B` (malicious).
5. `_findPullRequestBranch` fetches the fork remote and resolves `remoteRef` to whatever `feature` now points to — commit `B` — with no comparison to `A` [7](#0-6) .
6. Victim's working directory is silently populated with commit `B`'s content, which was never reviewed.

Note: I was not able to fully verify whether any downstream code (e.g., notification or "PR changed" checks in `pull-request-store.ts`, which does reference `head.sha` in 2 places) performs a comparable SHA check elsewhere in the notification/refresh path; if such a check exists but is not wired into the direct checkout path shown above, it would not close this specific gap. A Devin session with full-repo access would be needed to confirm this with certainty.

```typescript
  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
```
