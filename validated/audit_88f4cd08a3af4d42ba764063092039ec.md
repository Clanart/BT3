### Title
Missing bounds check in `is_atom_canonical()` CLVM length-prefix parsing causes unhandled out-of-bounds read / spend-triggered crash - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` decodes a CLVM atom's variable-length size prefix (1–6 bytes) by repeatedly indexing into the raw `bytes` buffer based on a prefix length derived from the buffer's first byte, without ever checking that enough bytes remain in the buffer before reading them [3](#0-2) . This function is invoked directly on attacker-controlled `puzzle_reveal`/`solution` bytes from every coin spend in a submitted `SpendBundle`, with no length or bounds validation performed beforehand, via `is_clvm_canonical()` inside `validate_spend_bundle()` [4](#0-3) .

### Finding Description
The bug class mirrors CVE-2026-56002's `pcfReadFont()` flaw: a parser reads a length/size field from untrusted input and then reads further bytes based on that field without checking the buffer actually contains that many bytes. In `is_atom_canonical()`:

```python
elif (b & 0b11111100) == 0b11111000:
    mask = 0b00000011
    prefix_len = 4
    ...
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]   # no bounds check against len(clvm_buffer)
``` [5](#0-4) 

If `clvm_buffer` ends right after (or shortly after) a header byte that encodes a 2-, 3-, 4-, 5-, or 6-byte length prefix (e.g. a single `0xF8` byte with no trailing bytes), `clvm_buffer[offset]` indexes past the end of the buffer, raising an unhandled `IndexError`. This is reachable from `is_clvm_canonical()`, which is called unconditionally on `bytes(coin_spend.puzzle_reveal)` and `bytes(coin_spend.solution)` for every coin spend in `validate_spend_bundle()`, before any other structural validation of those blobs [6](#0-5) .

`add_transaction()` in `full_node.py` only catches `ValueError` and `ValidationError` around the call chain that leads to `validate_spend_bundle()`; any other exception type, including `IndexError`, is not handled and propagates out of the `try/except` block [1](#0-0) . The project's own tests confirm this design: `test_add_transaction_remove_seen_on_unexpected_exception` explicitly documents that "unexpected exception[s]" raised in this call path are re-raised rather than converted into a `FAILED` status [7](#0-6) .

### Impact Explanation
This is not a memory-corruption heap overflow (Python's bounds-checked `bytes` indexing prevents true heap corruption), so it cannot yield code execution as in the original libXfont2 CVE. However, it is a spend-triggered, unhandled-exception path reachable by any unprivileged spend-bundle submitter (wallet user, peer relaying a transaction, or RPC caller) that can crash or destabilize transaction processing in the full node — an uncaught exception raised from within the `blockchain.priority_mutex`-guarded critical section of transaction processing risks leaving in-flight/seen-cache state inconsistent or crashing the task handling that connection, which affects mempool availability for all callers.

### Likelihood Explanation
High reachability: any single crafted `puzzle_reveal` or `solution` byte string with a truncated CLVM atom length-prefix (e.g., a lone `0xF8`, `0xC0`, `0xE0`, `0xFC`, etc. byte with insufficient trailing bytes) triggers this path as soon as it's included in a `SpendBundle` and submitted to `add_transaction`/`pre_validate_spendbundle`. No signature validity or coin state is required to reach `is_clvm_canonical()`, since it's called early in `validate_spend_bundle()` on the raw serialized bytes [4](#0-3) .

### Recommendation
Add explicit remaining-length checks in `is_atom_canonical()` before each indexed read (mirroring the bounds checks already present in `full_block_utils.py`'s `skip_bytes`/`generator_from_block`, e.g. `if length > len(buf): raise ValueError(...)` [8](#0-7) ), and raise a `ValueError`/`ValidationError` instead of letting an `IndexError` propagate. Additionally, harden `full_node.add_transaction()`'s exception handling around `pre_validate_spendbundle` to catch broader parsing-related exceptions defensively so malformed attacker-supplied CLVM blobs cannot escape as unhandled exceptions.

### Proof of Concept
1. Construct a `puzzle_reveal` (or `solution`) `SerializedProgram` whose bytes are a single `0xF8` byte (or any header byte requiring a multi-byte length prefix longer than the remaining buffer), e.g. `SerializedProgram.fromhex("f8")`.
2. Build a `CoinSpend` using this puzzle_reveal/solution and wrap it in a `SpendBundle`.
3. Submit it via `full_node.add_transaction(spend_bundle, spend_bundle.name())` (or the equivalent wallet/RPC `push_tx` path).
4. Execution reaches `validate_spend_bundle()` → `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` → `is_atom_canonical()`, which indexes `clvm_buffer[offset]` past the 1-byte buffer, raising an uncaught `IndexError` that is not caught by the `except ValueError`/`except ValidationError` handlers in `add_transaction()`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len
```
