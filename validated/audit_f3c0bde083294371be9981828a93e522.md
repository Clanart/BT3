### Title
`SignableTransaction` omits the OP_RETURN output from fee and standardness-weight calculations, producing under-priced or non-standard transactions - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The Notional M-16 pattern is a bound/tolerance computed over a fixed set of components that stops being correct once more components are added, breaking a critical operation. In `bitcoin-serai`, `SignableTransaction::new` computes the transaction weight and `needed_fee` from only `inputs`, `payments`, and `change`. An OP_RETURN output created from the `data` argument is pushed into the final transaction's output list before those calculations, but is never included in them. The signed transaction therefore pays less than the requested fee rate and can exceed `MAX_STANDARD_TX_WEIGHT` while still passing the in-function standardness check.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is appended to `tx_outs` first: [1](#0-0) 

Then weight/vbytes are computed from `payments` only, ignoring the OP_RETURN output entirely: [2](#0-1) 

`calculate_weight_vbytes` builds a dummy `Transaction` containing only `payments` (and optionally `change`), so the ~80-byte `script_pubkey` OP_RETURN output contributes nothing to `weight` or `vbytes`: [3](#0-2) 

Both bound checks run against that incomplete weight:
- `TooLowFee` compares `needed_fee` (from OP_RETURN-free vbytes) against the minimum relay fee.
- `TooLargeTransaction` compares the OP_RETURN-free `weight` against `MAX_STANDARD_TX_WEIGHT`. [4](#0-3) 

Like M-16's hardcoded `REBALANCING_UNDERLYING_DELTA` failing once multiple holdings' deltas accumulate, the bound here is computed over a subset of outputs and silently breaks once an extra output (`data`) is included. The actual signed transaction carries the OP_RETURN output, so its real vsize is larger than what the fee was priced for.

### Impact Explanation
- The effective fee rate of the produced transaction is lower than `fee_per_vbyte` requested, by `fee_per_vbyte * vbytes(OP_RETURN_output)` satoshis. If the resulting real fee rate drops below the node's minimum relay fee (e.g. caller requests ~1 sat/vB and supplies ~80 bytes of data), the fully-signed transaction is rejected by relay/mempool policy and will not confirm — the spend is stuck despite `SignableTransaction` having "succeeded".
- A transaction at the `MAX_STANDARD_TX_WEIGHT` boundary can pass the `TooLargeTransaction` check while its real weight exceeds the standardness limit, again producing a transaction the network will not accept.
- Callers relying on `needed_fee()`/`fee()` for accounting (as the processor's scheduler does when amortizing fees) get a value that does not reflect the true signed transaction.

### Likelihood Explanation
Triggering requires only calling `SignableTransaction::new` with a `data` argument — bytes fully under the caller's control, up to 80 bytes. The miscalculation is deterministic whenever `data.is_some()`. Whether the transaction is actually rejected depends on the fee rate and how close the transaction is to policy limits, but the fee shortfall occurs on every call that includes data.

### Recommendation
Include the OP_RETURN output in `calculate_weight_vbytes` (e.g. pass the full `tx_outs`/output list rather than `payments` alone, or add the data output to the dummy transaction), and recompute `weight`/`vbytes`/`needed_fee` after all outputs — payments, OP_RETURN, and change — are known. Perform both the `TooLowFee` and `MAX_STANDARD_TX_WEIGHT` checks against that complete weight.

### Proof of Concept
```rust
// networks/bitcoin — conceptual PoC
let tx = SignableTransaction::new(
  vec![input],                       // any ReceivedOutput
  &[(payment_script, DUST)],         // one minimal payment
  None,                              // no change
  Some(vec![0u8; 80]),               // OP_RETURN data
  1,                                 // fee_per_vbyte = 1 sat/vB (minimum)
).unwrap();

// needed_fee was priced for the tx WITHOUT the OP_RETURN output.
let priced_vbytes = tx.needed_fee(); // fee_per_vbyte == 1
let real_vbytes = u64::try_from(tx.tx().vsize()).unwrap(); // includes OP_RETURN
assert!(real_vbytes > priced_vbytes);
// Real fee rate = needed_fee / real_vbytes < 1 sat/vB → below
// DEFAULT_MIN_RELAY_TX_FEE; the signed tx is rejected by relay policy
// despite the TooLowFee check passing.

```rust
  pub fn new(
    mut inputs: Vec<ReceivedOutput>,
    payments: &[(ScriptBuf, u64)],
    change: Option<ScriptBuf>,
    data: Option<Vec<u8>>,
    fee_per_vbyte: u64,
  ) -> Result<SignableTransaction, TransactionError> {
    if inputs.is_empty() {
      Err(TransactionError::NoInputs)?;
    }

    if payments.is_empty() && change.is_none() && data.is_none() {
      Err(TransactionError::NoOutputs)?;
    }

    for (_, amount) in payments {
      if *amount < DUST {
        Err(TransactionError::DustPayment)?;
      }
    }

    if data.as_ref().map_or(0, Vec::len) > 80 {
      Err(TransactionError::TooMuchData)?;
    }

    let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
    let offsets = inputs.iter().map(|input| input.offset).collect();
    let tx_ins = inputs
      .iter()
      .map(|input| TxIn {
        previous_output: input.outpoint,
        script_sig: ScriptBuf::new(),
        sequence: Sequence::MAX,
        witness: Witness::new(),
      })
      .collect::<Vec<_>>();

    let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();
    let mut tx_outs = payments
      .iter()
      .map(|payment| TxOut { value: Amount::from_sat(payment.1), script_pubkey: payment.0.clone() })
      .collect::<Vec<_>>();

    // Add the OP_RETURN output
    if let Some(data) = data {
      tx_outs.push(TxOut {
        value: Amount::ZERO,
        script_pubkey: ScriptBuf::new_op_return(
          PushBytesBuf::try_from(data)
            .expect("data didn't fit into PushBytes depsite being checked"),
        ),
      })
    }

    let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);

    let mut needed_fee = fee_per_vbyte * vbytes;
    // Technically, if there isn't change, this TX may still pay enough of a fee to pass the
    // minimum fee. Such edge cases aren't worth programming when they go against intent, as the
    // specified fee rate is too low to be valid
    // bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE is in sats/kilo-vbyte
    if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * vbytes) / 1000) {
      Err(TransactionError::TooLowFee)?;
    }

    if input_sat < (payment_sat + needed_fee) {
      Err(TransactionError::NotEnoughFunds {
        inputs: input_sat,
        payments: payment_sat,
        fee: needed_fee,
      })?;
    }

    // If there's a change address, check if there's change to give it
    if let Some(change) = change {
      let (weight_with_change, vbytes_with_change) =
        Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
      let fee_with_change = fee_per_vbyte * vbytes_with_change;
      if let Some(value) = input_sat.checked_sub(payment_sat + fee_with_change) {
        if value >= DUST {
          tx_outs.push(TxOut { value: Amount::from_sat(value), script_pubkey: change });
          weight = weight_with_change;
          needed_fee = fee_with_change;
        }
      }
    }

    if tx_outs.is_empty() {
      Err(TransactionError::NoOutputs)?;
    }

    if weight > u64::from(bitcoin::policy::MAX_STANDARD_TX_WEIGHT) {
      Err(TransactionError::TooLargeTransaction)?;
    }

    Ok(SignableTransaction {
      tx: Transaction {
        version: Version(2),
        lock_time: LockTime::ZERO,
        input: tx_ins,
        output: tx_outs,
      },
      offsets,
      prevouts: inputs.drain(..).map(|input| input.output).collect(),
      needed_fee,
    })
  }
