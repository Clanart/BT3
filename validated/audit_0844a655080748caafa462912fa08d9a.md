### Title
Data Layer mirror URLs are fetched via unauthenticated, unvalidated HTTP GET, enabling attacker-triggered SSRF — (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can create an on-chain "mirror" coin advertising an arbitrary URL for *any* Data Layer store id, including stores that are not theirs. Any DataLayer node that tracks that store id ingests the URL with no scheme/host validation and later issues a raw `aiohttp` GET request to it in `http_download()`, exactly mirroring the whisperX bug class: an attacker-controlled URL is handed straight to an HTTP client with no SSRF guard before the request happens.

### Finding Description
The mirror-creation path lets an unprivileged spend-bundle submitter attach arbitrary URL bytes as CREATE_COIN memos to a mirror coin for any `launcher_id`, without proving ownership of that store: [1](#0-0) 

The victim's `DataLayerWallet.coin_added()` accepts this mirror as long as it is already tracking the referenced `launcher_id` (e.g. because it subscribed to or owns that public store) — there is no check that the mirror creator is affiliated with the store: [2](#0-1) 

`DataLayer.update_subscriptions_from_wallet()` then pulls these attacker-controlled URLs straight from the wallet and stores them as subscription server URLs with no filtering: [3](#0-2) 

During `fetch_and_validate()`, one of these attacker URLs is selected and, when no downloader plugin is configured, `http_download()` performs a direct, unauthenticated `aiohttp` GET to `server_info.url + "/" + filename` with zero URL validation (no scheme allowlist, no private/internal-address blocking) before the request is issued: [4](#0-3) [5](#0-4) 

This is structurally identical to the whisperX flaw: the URL is attacker-supplied, comes from an untrusted source (any on-chain spend), and is used in an outbound HTTP request before any validation of destination occurs. Unlike the `S3Plugin.download()`/`handle_download()` path, which restricts scheme to `s3://` and checks the URL against a configured allowlist (`chia/data_layer/s3_plugin_service.py`), the plain HTTP downloader path in `download_data.py` has no equivalent restriction.

### Impact Explanation
A DataLayer node operator who merely subscribes to or owns a public store can be forced by any third party (via a cheap on-chain mirror-coin spend) to issue outbound HTTP requests to attacker-chosen destinations, including internal/private network addresses (e.g. cloud metadata endpoints, internal admin services, localhost ports). This is a server-side request forgery against the DataLayer service host, reachable purely from a submitted spend bundle with no authentication and no interaction beyond the victim already tracking the targeted store — a normal, expected Data Layer workflow.

### Likelihood Explanation
Likelihood is high: creating a mirror coin only requires a minimal-value spend plus fee (tests show mirror creation with amount `0`), the `launcher_id` and URL memos are entirely attacker-chosen, and no ownership or allowlist check gates which URLs get ingested and fetched by `http_download()`.

### Recommendation
Validate mirror/server URLs before use in `download_data.py`'s `http_download()`/`download_file()`: enforce an explicit scheme allowlist (e.g. only `http`/`https`), resolve and reject requests targeting private/loopback/link-local addresses (mirroring the SSRF protections that should exist wherever untrusted URLs are dereferenced), and consider requiring operator opt-in/allowlisting of mirror URLs similar to the scheme+URL-membership checks already present in `s3_plugin_service.py`.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (`chia/wallet/wallet_rpc_api.py:3255`) with `launcher_id` set to a public store id the victim already tracks, and `urls=["http://169.254.169.254/latest/meta-data/"]` (or any internal victim-reachable address), paying only the mirror amount + fee.
2. This spend creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` and CREATE_COIN memos `[launcher_id, url...]` (`chia/wallet/db_wallet/db_wallet_puzzles.py:90-109`).
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` decodes the memos and records the mirror for the tracked `launcher_id` (`chia/data_layer/data_layer_wallet.py:775-800`).
4. Victim's `DataLayer.update_subscriptions_from_wallet()` picks up the malicious URL into its subscription server list (`chia/data_layer/data_layer.py:979-985`).
5. On the next `fetch_and_validate()` cycle, `http_download()` issues `session.get("http://169.254.169.254/latest/meta-data/" + filename, ...)` from the victim's DataLayer host with no validation (`chia/data_layer/download_data.py:298-319`), completing the SSRF.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
