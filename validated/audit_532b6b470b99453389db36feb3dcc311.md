### Title
SSRF in Data Layer mirror sync — arbitrary server-controlled HTTP fetch via unvalidated on-chain mirror URLs - (File: `chia/data_layer/download_data.py`, `chia/data_layer/data_layer_wallet.py`)

### Summary
Any wallet user can register an arbitrary URL as a "mirror" for **any** DataLayer store (not just their own), with no scheme/host/IP validation. Any other node that subscribes to (or owns/tracks) that store id will later have its DataLayer service issue an unauthenticated, unrestricted outbound HTTP `GET`/download request to that attacker-chosen URL — a direct analog to the edx-enterprise SSRF via an unvalidated externally-supplied metadata/fetch URL.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a `CREATE_COIN` to the mirror puzzle with `memos=[[launcher_id, *urls]]` and does not verify that `launcher_id` is owned by the caller, nor validate the `urls` list at all [1](#0-0) . Any user can therefore create a mirror coin for a `launcher_id` belonging to someone else's store, with attacker-chosen URL strings (e.g. `http://169.254.169.254/...` or an internal RFC1918 address).

When any node syncs and observes this mirror coin, `DataLayerWallet.coin_added()` decodes the URL memos via `get_mirror_info()` — which itself performs no validation on the URL content — and stores them as a mirror if the launcher is tracked locally [2](#0-1) [3](#0-2) .

The DataLayer service later reads these attacker-controlled URLs from `get_available_servers_for_store()` and iterates them in `fetch_and_validate()`, passing the raw URL into `insert_from_delta_file()` → `download_file()` → `http_download()` with no scheme allow-list and no private/link-local IP blocking [4](#0-3) [5](#0-4) [6](#0-5) .

The RPC-facing `add_mirror` endpoint simply forwards the caller-provided `urls` list to the wallet with the only guard being non-empty list, again with no ownership or URL validation at the DataLayer/RPC layer [7](#0-6) [8](#0-7) .

### Impact Explanation
Any wallet user who can submit a spend bundle can force any DataLayer node that tracks/subscribes to the targeted store to make outbound HTTP requests to an attacker-chosen URL/host/port, including cloud metadata endpoints (`169.254.169.254`) or internal-only services, enabling credential theft or internal network reconnaissance from the victim's DataLayer host — the same impact class described in the reference edx-enterprise SSRF advisory. This is a CWE-918 SSRF reachable purely from a signed transaction (mirror-coin creation), requiring no special privilege beyond being able to submit a spend bundle for a `create_mirror_puzzle()` coin.

### Likelihood Explanation
High. Creating a mirror coin for an arbitrary `launcher_id` with arbitrary URL memos requires only a standard spend the attacker can construct and broadcast themselves via `create_new_mirror`/`add_mirror`; no cooperation from the store owner or victim node operator is needed. Any node that already tracks the targeted store (subscriber or owner) will process the mirror and, on its next sync cycle, attempt the HTTP fetch automatically.

### Recommendation
- Validate mirror URLs at creation/ingestion time (`create_new_mirror`, `get_mirror_info`, `add_mirror`) — enforce `https://` scheme and reject loopback/link-local/RFC1918 targets, consistent with the fix pattern (`validate_saml_metadata_url`) referenced in the analogous advisory.
- Add DNS/IP resolution checks (and re-check on redirect) before `http_download()`/`aiohttp` requests execute, plus enforce a request timeout.
- Consider requiring mirror creation to only be accepted from nodes that already own/track the targeted `launcher_id`, or at minimum flag/quarantine unverified mirrors before they are used for fetches.

### Proof of Concept
1. Attacker wallet calls `create_new_mirror(launcher_id=<victim_store_id>, amount=..., urls=[b"http://169.254.169.254/latest/meta-data/iam/security-credentials/"], ...)` (reachable via RPC `add_mirror` / `dl_new_mirror`) and broadcasts the resulting spend bundle — no ownership of `launcher_id` is required [1](#0-0) .
2. Once the coin confirms, any node tracking `victim_store_id` ingests the mirror via `coin_added()`/`get_mirror_info()` with the malicious URL and no validation [2](#0-1) .
3. On its next `periodically_manage_data()`/`update_subscription()` cycle, that node's `fetch_and_validate()` selects the malicious server URL and issues an HTTP request via `download_file()`/`http_download()`, reaching the internal/metadata endpoint from the victim node's network context [4](#0-3) [5](#0-4) .

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
    if group_files_by_store:
```
