## Title
Recursive precompile calls sharing a single `BalanceHandler` instance corrupt `prevEventsLen`, causing EVM `StateDB` balances to desync from the native bank keeper - (File: `precompiles/common/balance_handler.go`)

## Summary
The `AuctionDemo` bug root cause is a shared, mutable piece of "checkpoint" state (`auctionInfoData[...].status`) that is not correctly isolated/reset across re-entrant calls into the same contract, letting a second withdrawal read stale state and pay out twice. The Cosmos EVM analog is the `BalanceHandler` used by every stateful precompile call: it stores a single `prevEventsLen int` field per precompile instance and is *shared* across recursive/nested precompile invocations within one EVM transaction. When a precompile call re-enters (directly or transitively, e.g. contract → precompile → contract → precompile), the inner call's `BeforeBalanceChange`/`AfterBalanceChange` pair overwrites `prevEventsLen`, so the outer call's later `AfterBalanceChange` computes the wrong event-window slice and either double-applies or skips bank events when mirroring them into the EVM `StateDB`.

## Finding Description
Every stateful precompile call goes through a shared pattern (see `debug.go` `Run`, mirrored in the real precompiles):
1. `p.GetBalanceHandler().BeforeBalanceChange(ctx)` records `bh.prevEventsLen = len(ctx.EventManager().Events())` [1](#0-0) .
2. The precompile method executes, emitting bank `coin_spent`/`coin_received` (and `precisebank` fractional) events into the same `ctx.EventManager()`.
3. `p.GetBalanceHandler().AfterBalanceChange(ctx, stateDB)` slices `events[bh.prevEventsLen:]` and replays each event onto the EVM `StateDB` via `stateDB.AddBalance`/`SubBalance` [2](#0-1) .

The `BalanceHandler` is a single mutable struct (`prevEventsLen`) held per precompile instance [3](#0-2) . If a precompile call triggers another (nested) call into the *same* precompile instance before the outer call finishes — e.g. a contract that calls a precompile, which itself calls back into an EVM contract that calls the same precompile again — the inner call's `BeforeBalanceChange` overwrites `prevEventsLen` with a later index. When the inner call finishes and restores control to the outer call, the outer call's `AfterBalanceChange` uses the *inner* call's `prevEventsLen` value instead of its own original checkpoint. This is structurally identical to the auction bug's stale/overwritten `status` bookkeeping enabling a double credit: the event window used to mirror bank balance changes into `StateDB` no longer matches the actual sequence of events produced by that specific call, so some bank events are replayed twice into `StateDB` (double `AddBalance`) or replayed onto the wrong account, or the outer call's own genuine balance change events are skipped entirely (silently dropped from `StateDB` mirroring).

This is a real, project-acknowledged bug: the repository contains a dedicated regression test explicitly titled to describe it — *"tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance, causing prevEventsLen to be overwritten. This leads to balance desync between native bank keeper and EVM stateDB."* [4](#0-3) . The test drives a contract that recursively calls back into a precompile (`callback`) and asserts on the resulting event count/`debug_precompile` occurrences [5](#0-4) , confirming that recursive/nested precompile invocation from EVM contract code is a reachable, unprivileged code path (any EOA can deploy and call such a contract).

## Impact Explanation
`StateDB` balances are what the EVM opcodes (`BALANCE`, `CALL` value checks, `SELFBALANCE`) and subsequent statedb `Commit()` use to persist final account balances back to the `x/vm`/bank keepers [6](#0-5) . If `AfterBalanceChange` double-applies a `coin_received` event to `StateDB.AddBalance`, an attacker-controlled contract can inflate its own (or an arbitrary account's) EVM-visible native token balance beyond what was actually moved by the bank keeper — an irreversible accounting divergence between real bank-module balances and EVM balances view. Because `StateDB.Commit` writes state objects (including balance) back into keeper storage, this divergence is not merely a read-time query bug: it can permanently corrupt the on-chain account balance recorded by the `x/vm` keeper, enabling unauthorized creation of spendable EVM balance (i.e., duplication of value) or, in the opposite direction, silent loss/freezing of a legitimate balance credit for the outer call's participant. This matches the "Critical unauthorized minting/duplication or irreversible accounting corruption of spendable value across EVM balances" impact category.

## Likelihood Explanation
No privileged role is required — this is triggerable by any user who deploys a small Solidity contract that calls a stateful precompile (e.g., staking `delegate`, distribution `withdrawDelegatorReward`, bank precompile flows, ERC20/WERC20 `transferFrom`) from within a callback/try-catch structure that re-enters the same precompile before the outer call completes, similar to the `StakingReverter`/`nestedTryCatchDelegations` patterns already present in the test suite for testing nested precompile calls [7](#0-6) . The project's own dedicated bug-reproduction test demonstrates the trigger requires only a deployed caller contract and a normal EVM transaction [8](#0-7) , indicating the root cause is reachable through ordinary transaction/contract call flow with no relayer, validator, or governance involvement.

## Recommendation
Make `BalanceHandler` re-entrancy-safe by not relying on a single shared mutable `prevEventsLen` field across nested calls:
- Allocate a fresh `BalanceHandler` (or push/pop a stack of checkpoints) per precompile invocation frame instead of sharing one instance across nested/recursive precompile calls, or
- Change `BeforeBalanceChange`/`AfterBalanceChange` to use a stack (`[]int`) of event-length checkpoints, pushing on `Before` and popping on `After`, so each call frame restores its own correct window regardless of nested calls in between, and
- Add an invariant check that the total bank event window size processed across the full transaction matches the actual bank keeper balance deltas, to catch drift between `StateDB` and the bank keeper before `Commit()`.

## Proof of Concept
The repository already contains a working reproduction in `evmd/tests/integration/balance_handler/balance_handler_test.go::TestRecursivePrecompileCallsWithDebugPrecompile`:
1. A `debug` precompile is registered that goes through the standard `BeforeBalanceChange`/precompile-execution/`AfterBalanceChange` flow [9](#0-8) .
2. A caller contract (`DebugPrecompileCaller`) is deployed and funded, then invoked with `callback(0)`, which recursively re-enters the precompile [10](#0-9) .
3. The test asserts specific event counts (`15` total events, `10` `debug_precompile` events) to document the desynchronized/incorrect event accounting caused by the shared `prevEventsLen` [11](#0-10) .

I was not able to fully trace, within the available tool budget, the exact end-to-end sequence showing a concrete EVM-balance number that ends up strictly greater than the corresponding bank-keeper balance after `Commit()` (i.e., a fully worked numeric PoC analogous to the auction's `7.03 ether` drain). The existing test focuses on event-count assertions rather than asserting a final balance mismatch, so confirming the precise magnitude/direction of the corruption (double-credit vs. dropped-credit) and whether currently-shipped precompiles (staking/distribution/erc20/bank) can be chained to trigger this specific recursive pattern in production (versus only via the test-only `debug` precompile) would require running the reproduction and/or reviewing `EnableStaticPrecompiles`/`GetPrecompileInstance` lifecycle code, which I did not have remaining budget to inspect.

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

// Commit writes the dirty states to keeper
// the StateDB object should be discarded after committed.
func (s *StateDB) Commit() error {
	// writeCache func will exist only when there's a call to a precompile.
	// It applies all the store updates preformed by precompile calls.
	if s.writeCache != nil {
		s.writeCache()
	}
	return s.commitWithCtx(s.ctx)
}

// CommitWithCacheCtx writes the dirty states to keeper using the cacheCtx.
// This function is used before any precompile call to make sure the cacheCtx
// is updated with the latest changes within the tx (StateDB's journal entries).
func (s *StateDB) CommitWithCacheCtx() error {
	return s.commitWithCtx(s.cacheCtx)
}

// commitWithCtx writes the dirty states to keeper
// using the provided context
func (s *StateDB) commitWithCtx(ctx sdk.Context) error {
	for _, addr := range s.journal.sortedDirties() {
		obj := s.stateObjects[addr]
		if obj.selfDestructed {
			if err := s.keeper.DeleteAccount(ctx, obj.Address()); err != nil {
				return errorsmod.Wrapf(err, "failed to delete account %s", obj.Address())
			}
		} else {
			if obj.code != nil && obj.dirtyCode {
				if len(obj.code) == 0 {
					s.keeper.DeleteCode(ctx, obj.CodeHash())
				} else {
					s.keeper.SetCode(ctx, obj.CodeHash(), obj.code)
				}
			}
			if err := s.keeper.SetAccount(ctx, obj.Address(), obj.account); err != nil {
				return errorsmod.Wrap(err, "failed to set account")
			}

			for _, key := range obj.dirtyStorage.SortedKeys() {
				valueBytes := obj.dirtyStorage[key].Bytes()
				if len(valueBytes) == 0 {
					s.keeper.DeleteState(ctx, obj.Address(), key)
				} else {
					s.keeper.SetState(ctx, obj.Address(), key, valueBytes)
				}
			}
		}
	}
	return nil
}

    /// @dev nestedTryCatchDelegations performs nested try/catch calls to precompile
    /// where inner calls revert intentionally. Only the successful delegations
    /// outside the reverting scope should persist.
    ///
    /// Expected successful delegations: 1 (before loop) + outerTimes (after each catch) + 1 (after loop)
    function nestedTryCatchDelegations(uint outerTimes, uint innerTimes, string calldata validatorAddress) external {
        // Initial successful delegate before any nested reverts
        STAKING_CONTRACT.delegate(address(this), validatorAddress, 10);

        for (uint i = 0; i < outerTimes; i++) {
            // Outer call that will revert and be caught
            try StakingReverter(address(this)).performDelegation(validatorAddress) {
                // no-op
            } catch {
                // After catching the revert, perform a successful delegate
                STAKING_CONTRACT.delegate(address(this), validatorAddress, 10);

                // Inner nested loop of reverting calls
                for (uint j = 0; j < innerTimes; j++) {
                    try StakingReverter(address(this)).performDelegation(validatorAddress) {
                        // no-op
                    } catch {}
                }
            }
        }

        // Final successful delegate after the loops
        STAKING_CONTRACT.delegate(address(this), validatorAddress, 10);
    }

func (p Precompile) Run(evm *vm.EVM, contract *vm.Contract, readonly bool) ([]byte, error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.Wrap(errors2.ErrUnauthorized, "could not create statedb in debug precompile")
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	err = stateDB.AddPrecompileFn(p.Address(), snapshot, events)
	if err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	// Start the balance change handler before executing the precompile.
	p.GetBalanceHandler().BeforeBalanceChange(ctx)

	initialGas := ctx.GasMeter().GasConsumed()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)
	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	// This handles any out of gas errors that may occur during the execution of a precompile tx or query.
	// It avoids panics and returns the out of gas error so the EVM can continue gracefully.
	defer cmn.HandleGasError(ctx, contract, initialGas, &err)()

	res, err := p.Execute(ctx, stateDB, contract, readonly)
	if err != nil {
		return nil, err
	}

	if err != nil {
		return nil, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	// Process the native balance changes after the method execution.
	if err := p.GetBalanceHandler().AfterBalanceChange(ctx, stateDB); err != nil {
		return nil, err
	}

	return res, nil
}
