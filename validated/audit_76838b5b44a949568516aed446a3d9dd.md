### Title
Baseline overwrite race in `restore_unreviewed_stop_state` lets an already-touched dangerous file permanently escape Stop-hook review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`restore_unreviewed_stop_state` only restores `baseline_sha` when the current state has none set (`if baseline_sha and not state.get("baseline_sha")`), so if a concurrent `UserPromptSubmit` (UPS) wins the state lock first and writes a *new* baseline captured after the dangerous edit, the restore call silently keeps that newer baseline instead of the pre-edit one it was supposed to preserve. Because `capture_git_baseline` uses `git stash create`, which snapshots the *current* working tree (already containing the unreviewed dangerous edit), the next Stop hook's `git diff <new_baseline>` shows no change for that file even though it was never reviewed, causing the dangerous content to be treated as "old" and dropped from `compute_v2_review_set`'s result.

### Finding Description
`handle_stop_hook` snapshots session state via `consume_stop_state`, which clears `touched_paths` on disk under lock [1](#0-0) . Stop then may hit a transient failure (`ensure_anthropic_reachable()` fails, or `llm._last_call_claude_http_error`) and calls `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` to put the cleared paths back and re-arm the baseline-preservation guard [2](#0-1) [3](#0-2) .

`restore_unreviewed_stop_state` itself only conditionally restores the baseline: [4](#0-3) 

Meanwhile, `handle_user_prompt_submit` runs concurrently (asyncRewake — the user can submit a new prompt before Stop finishes) and re-baselines unless it sees non-empty `touched_paths` *and* an existing `baseline_sha` at the moment it acquires the lock: [5](#0-4) 

Since `consume_stop_state` already cleared `touched_paths` to `[]` before Stop's slow work (network check, LLM call) even runs, a UPS that wins the lock race during that window observes `touched_paths=[]` and unconditionally overwrites `baseline_sha` with a fresh `git stash create` SHA that already contains the unreviewed dangerous edit. If this UPS write lands *before* Stop's later `restore_unreviewed_stop_state` call, `state.get("baseline_sha")` is now truthy, so the `not state.get("baseline_sha")` guard fails and the stale/newer baseline is kept — the pre-edit baseline is never restored. `touched_paths` is correctly merged back in, but `compute_v2_review_set`'s `changed_since = _git_name_only(repo, baseline_sha)` now diffs against a baseline that already contains the dangerous file's content, so the file is excluded from `changed_since` and thus from `review_set` (`dirty_now & changed_since`) [6](#0-5) , even though it remains in `touched_paths` and was never actually diffed/reviewed.

No existing guard checks whether the baseline being kept is "newer" than the snapshot the restore call was issued for — the code only checks presence/absence of a baseline, not its provenance or whether it already absorbed the unreviewed change.

### Impact Explanation
A file edited by Claude that contains a real vulnerability (e.g., injected via repo content that steers Claude to write insecure code) can be permanently excluded from the Stop-hook LLM security review after a transient API failure coincides with the normal asyncRewake next-turn UPS race. This breaks the stated invariant that the review set stay bound to the correct baseline/touched paths, resulting in security-relevant code changes silently skipping review — a control-bypass on the plugin's core "unreviewed edits must eventually be reviewed" guarantee, i.e., unauthorized code changes proceeding outside the intended review/approval boundary.

### Likelihood Explanation
The trigger requires two ordinary, non-privileged conditions that both occur in normal operation: (1) a Stop-hook transient failure path (`ensure_anthropic_reachable` false, or an LLM HTTP error) — both are documented as expected/common occurrences in the code comments, and (2) the next-turn UPS racing ahead of the async Stop hook, which the code's own comments describe as a "meaningful share" of real-world occurrences. No special privilege is needed; it only requires ordinary git operations (edits, commits) and normal Claude Code usage timing, making it a realistic, repeatable race rather than a purely theoretical one.

### Recommendation
Make `restore_unreviewed_stop_state` authoritative rather than conditional: always restore `baseline_sha` to the pre-Stop snapshot value passed in (`snap_baseline`) whenever `paths` is non-empty, instead of only when no baseline currently exists. Alternatively, have `consume_stop_state` defer clearing `touched_paths` until the Stop hook's outcome is known, or version/tag baseline writes so a UPS-originated baseline can be detected and not blindly trusted over the pending-review snapshot.

### Proof of Concept
Integration test plan (extends existing Stop-hook/UPS state tests):
1. Initialize a git repo with one commit; capture `baseline_sha=B0` via `save_baseline_sha`, `record_touched_path(session_id, "dangerous.py")`.
2. Simulate the async race: call `consume_stop_state(session_id)` (clears `touched_paths`, snapshot returns `touched_paths=["dangerous.py"]`, `baseline_sha=B0`).
3. Before calling `restore_unreviewed_stop_state`, simulate the racing UPS: write `dangerous.py` with vulnerable content, run `capture_git_baseline(cwd)` to get `B1` (which now contains the dangerous content), and call `save_baseline_sha(session_id, B1)` directly (mirroring `handle_user_prompt_submit`'s unconditional overwrite when it observes empty `touched_paths`).
4. Now call `restore_unreviewed_stop_state(session_id, ["dangerous.py"], B0)`.
5. Assert `load_baseline_sha(session_id) == B1` (not restored to `B0`) — confirms the bug.
6. Call `compute_v2_review_set(cwd, B1, head_at_capture, {})` and assert `"dangerous.py"` is **absent** from the returned review set even though it's still in `touched_paths` — demonstrating the dangerous change is treated as old and silently skipped from review.

def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap

    return with_locked_state(session_id, _snap) or {
        "touched_paths": [], "baseline_sha": None, "head_at_capture": None,
        "untracked_at_baseline": {},
        "fire_count": 0, "fire_count_expired": False, "previous_findings": [],
    }
