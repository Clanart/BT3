### Title
IDOR in `associatePublicKey` allows unauthenticated front-running association without private-key proof - (File: precompiles/addr/addr.go)

### Summary
The `addr` precompile's `associatePublicKey` method links an EVM address and a Sei (Cosmos) address by only accepting a raw public key, with no proof (signature) that the caller controls the corresponding private key, unlike its sibling method `associate`.

### Finding Description
`addr.go`'s `Execute` dispatches `AssociatePubKey` to `associatePublicKey`, which parses an attacker-supplied compressed public key and derives both the EVM and Sei addresses from it, then calls `associateAddresses` directly — with no signature check tying the caller to that key: [1](#0-0) 

By contrast, the `associate` method requires the caller to submit an ECDSA signature (`v`,`r`,`s`) over a custom message, cryptographically proving possession of the private key before the pubkey/addresses are derived: [2](#0-1) 

`associatePublicKey` skips this proof-of-possession step entirely, only requiring that the address pair is not already associated: [3](#0-2) 

Because any observer of a public key (e.g., harvested from any historical Cosmos tx signature, from a compressed pubkey shared elsewhere, or from block data) can call this precompile to force-associate that identity, this is a direct-object-reference issue: the resource being manipulated (a specific victim's address-mapping and account) is referenced purely by an object ID (the public key bytes) supplied by the caller, with no ownership/authorization check that the caller possesses the associated private key.

The actual state mutation triggered on association can move funds: `AssociateAddresses`/`MigrateBalance` unconditionally transfers all `SpendableCoins` and any wei balance sitting at the "cast" address (`sdk.AccAddress(evmAddr[:])`) to the newly-associated Sei address, and can delete/replace the cast BaseAccount: [4](#0-3) 

### Impact Explanation
While the derived Sei/EVM address pair is fully determined by the supplied public key (so an attacker cannot redirect a victim's funds to an address the attacker controls), being able to force an association for an arbitrary victim without their signature is still a violation of authorization boundaries expected by the precompile's threat model (the sibling method deliberately demands a signature for this exact reason). This enables:
- Front-running a victim's own association transaction with attacker-supplied gas/timing, forcibly triggering `MigrateBalance` at a time/block the victim does not control, and consuming any pre-existing cast-address vesting/locked-coins edge cases handled by that code path.
- Potential unexpected interaction with account state (pubkey being fixed on the account, account number/sequence reuse from the cast BaseAccount) before the victim ever transacts, which can interfere with expected account initialization flows and any logic gated on "already associated" checks elsewhere in the EVM ante pipeline.

This does not, by itself, appear to directly redirect funds to an attacker-controlled address, since the target addresses are cryptographically fixed by the pubkey. Given the CVSS-Medium/IDOR classification of the analog report and the inability to fully confirm a fund-loss primitive without deeper analysis of every downstream consumer of the association state (e.g., ante-handler assumptions about signature-verified association), I rate confidence as Medium rather than definitively High-severity fund loss.

### Likelihood Explanation
High likelihood of exploitation feasibility: obtaining a target public key requires no privileged access — any Cosmos-style signed transaction from the victim reveals their public key (which is included/derivable from most signature schemes), and `associatePublicKey` is a public, unauthenticated function reachable by any EVM caller.

### Recommendation
Require the same proof-of-possession used in `associate` for `associatePublicKey` — e.g., require a signature over a nonce/message from the corresponding private key, or restrict `associatePublicKey` to be an internal helper invoked only after signature verification elsewhere, rather than exposing it as a directly-callable, unauthenticated precompile method.

### Proof of Concept
1. Observe any Sei (Cosmos) transaction broadcast by victim V; extract V's compressed secp256k1 public key from the tx (or acquire it via any public source).
2. Attacker (unrelated to V) calls the `addr` precompile's `associatePubKey(pubKeyHex)` with V's public key bytes, before V ever calls `associate`/`associatePubKey` themselves.
3. `associatePublicKey` succeeds because there is no signature check — it only checks the derived Sei address is not already associated: [5](#0-4) 
4. This forcibly executes `AssociateAddresses`, migrating any balance held at V's "cast" address and mutating V's account state, without V's authorization or knowledge, at a block/time chosen by the attacker.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
