#No vulnerability found for this question.

The rescue block in `redirect_to_splash_page` logs a fixed, generic message that never interpolates the attacker-supplied shop string: `ShopifyApp::Logger.warn("Redirecting to login: [#{error.class}] Could not determine current shop domain")` [1](#0-0) . This is confirmed by the corresponding test's expectation of the exact log text, which contains only the exception class name, not any shop value [2](#0-1) .

`ShopifyApp::Utils.sanitize_shop_domain` correctly rejects unified-admin paths without a shop name and empty-subdomain hosts by returning `nil` before any raw value is logged [3](#0-2) , and `ShopifyDomainNotFound` is only ever raised (e.g., from `fullpage_redirect_to` in `LoginProtection`/`TokenExchange`) without embedding the raw attacker string in its message [4](#0-3) [5](#0-4) . Since no attacker-controlled value ever reaches the log statement in the rescue path, there is no information-disclosure/log-leak vector as described.

      def sanitize_shop_domain(shop_domain)
        uri = uri_from_shop_domain(shop_domain)
        return if uri.nil? || uri.host.nil?

        trusted_domains.each do |trusted_domain|
          no_shop_name_in_subdomain = uri.host == trusted_domain
          from_trusted_domain = trusted_domain == uri.domain

          return myshopify_domain_from_unified_admin(uri) if unified_admin?(uri) && from_trusted_domain
          return nil if no_shop_name_in_subdomain || uri.host&.empty?
          return uri.host if from_trusted_domain
        end
        nil
      end
