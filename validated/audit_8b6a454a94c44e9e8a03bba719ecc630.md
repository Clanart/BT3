No vulnerability found for this question.

**Reasoning:**

The `getAllMenuItems` generator does recurse into submenus without an explicit depth or cycle guard, relying purely on the call stack to unwind naturally: [1](#0-0) 

However, the premise that a "compromised trusted sender" can submit `MenuLabelsEvent` data that produces a circularly-referencing or deeply nested submenu structure does not hold, because:

1. **`MenuLabelsEvent` is a flat, strictly-typed data object** consisting only of primitive strings/booleans (`selectedShell`, `selectedExternalEditor`, `contributionTargetDefaultBranch`, several boolean flags). It has no `submenu` or array-of-items fields that could carry attacker-controlled menu structure: [2](#0-1) 

2. **`buildDefaultMenuTemplate` builds a hardcoded menu template in source code.** The values from `MenuLabelsEvent` are only ever interpolated as string content into labels (e.g. `` `Open in ${selectedShell ?? 'Shell'}` ``) or used to pick between two static label strings, never used to construct or extend `submenu` arrays: [3](#0-2) [4](#0-3) 

3. `contributionTargetDefaultBranch`, the only "free text" field, is explicitly truncated before use: [5](#0-4) 

4. Since the menu shape (depth and item count) is fixed entirely by the source code of `buildDefaultMenuTemplate`, no value in `MenuLabelsEvent` can grow the submenu nesting depth beyond the fixed handful of levels already present in the code (main menu → e.g. `Repository`/`Branch` submenus, at most 2 levels deep, confirmed by the template snippets reviewed). There is no loop or recursive template construction driven by input data that could be abused to create thousands of nested submenus or a circular reference — `Menu.buildFromTemplate` builds from a plain object literal graph defined in code, not from externally supplied recursive JSON.

5. Additionally, this premise requires "a compromised trusted sender" — i.e., a renderer process that has already been compromised to send arbitrary IPC payloads — which falls outside the stated valid-impact scope (excludes findings requiring prior malware/compromise of the host or app process) and is not itself an unprivileged, externally-reachable input path (repository content, API object, deep link, or remote/proxy response).

Given the fixed, hardcoded menu template shape and the flat primitive structure of `MenuLabelsEvent`, there is no reachable path for an attacker (privileged or unprivileged) to inject a deeply nested or cyclic submenu structure into `buildDefaultMenu`, so `getAllMenuItems`'s lack of an explicit depth guard is not exploitable here.

export function* getAllMenuItems(menu: Menu): IterableIterator<MenuItem> {
  for (const menuItem of menu.items) {
    yield menuItem

    if (menuItem.type === 'submenu' && menuItem.submenu !== undefined) {
      yield* getAllMenuItems(menuItem.submenu)
    }
  }
