### Title
Cached FROST preprocess reused across distinct validator sets/sessions due to cache key omitting set/genesis - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` caches the FROST preprocess seed (`CachedPreprocess`, a 32-byte ChaCha20 seed from which both binomial nonces `d, e` are deterministically derived) in `CachedPreprocesses`, keyed solely by `self.context`. For the `DkgConfirmer` instantiation, `context` is `(b"DkgConfirmer", self.attempt)`. Neither the tributary `genesis`, the `NetworkId`/`session` (`self.spec.set()`), the participant list, nor the message being signed are part of the cache key. This is the Serai analog of CVE-2023-27535: a cached security context (authenticated connection there; nonce-generating preprocess here) is reused even though the parameters distinguishing the session — the validator set being confirmed — are not part of the reuse decision.

### Finding Description
In `preprocess_internal`, the cache lookup `CachedPreprocesses::get(self.txn, &self.context)` returns a prior seed whenever any earlier call used the same `context` tuple. The seed is then fed to `AlgorithmSignMachine::from_cache` → `AlgorithmMachine::seeded_preprocess`, which runs `ChaCha20Rng::from_seed(*seed.0)` and calls `Commitments::new(&mut rng, params.keys.original_secret_share(), ...)`. `Commitments::new` calls `C::random_nonce(secret_share, rng)` twice per nonce, and `random_nonce` computes `hash_to_F(b"nonce", seed || secret_share)`. Since `self.key` (the coordinator's Ristretto validator key) is the same across all `TributarySpec`s the coordinator serves, identical `(context, key)` ⇒ identical `(d, e)` nonces.

`dkg_confirmation_nonces` and `generated_key_pair`/`DkgConfirmed` handling instantiate `DkgConfirmer` per `spec` with the same `SigningProtocolDb`. A coordinator participating in DKG confirmations for two or more validator sets/networks (each with its own `TributarySpec`, genesis, `musig_context`, participant set, and `set_keys_message`) at the same `attempt` number will therefore:

- publish byte-identical `confirmation_nonces` (the same `Commitments` / `Preprocess`) on multiple tributaries, and
- emit signature shares whose effective nonce is `d + rho_i·e` for each session `i`, where `rho_i` is the per-session binding factor derived from the other participants' preprocesses (`BindingFactor::calculate_binding_factors` over `FROST_rho` transcript including `group_key`, `hash_msg(msg)`, and hashed preprocesses).

Each confirmation share has the form `s_i = d + rho_i·e + c_i·λ_i·x` (Schnorrkel `sign_share`), with `rho_i`, `c_i`, `λ_i` all publicly computable from on-chain data (`DkgShares`/`DkgConfirmed` transactions carry the preprocesses and shares). Unknowns are `d`, `e`, `x` — three scalars. Every colliding session contributes one independent equation, so three distinct sets sharing attempt `n` yield a solvable linear system revealing the validator's secret key `x`. The file's own safety argument (lines 25–48) only covers reuse *within* a BFT-finalized context where the message and preprocesses are identical; it does not account for cross-set reuse, since the authors assumed `context` uniquely identifies a session — it does not, because the set/genesis is missing from the key.

### Impact Explanation
Third-party recovery of the coordinator's validator private key (`self.key`), which is the MuSig root-of-trust key used to confirm DKG results and authorize `set_keys` on Substrate. Compromise lets an attacker forge DKG confirmations / validator-set key authorizations. Per the in-scope acceptance criteria this is "key share recovery"/"concrete signing of unintended state," reachable purely from publicly published preprocess and share bytes (unprivileged observer of multiple tributaries). This is a High-severity analog.

### Likelihood Explanation
Requires the same coordinator key to run `DkgConfirmer` under the same `(b"DkgConfirmer", attempt)` context for multiple specs — i.e., DKG attempt numbers aligning across distinct sets/networks sharing the coordinator DB. Initial launches and session rotations make attempt `0`/`1` collisions realistic; each additional colliding set increases exploitable equations. Not guaranteed on every deployment, hence Medium-High likelihood rather than certain.

### Recommendation
Bind all parameters that distinguish the signing session into the cache key, mirroring the CVE remediation ("don't reuse if the distinguishing parameters differ"). Concretely, extend `context` for `DkgConfirmer` to include `self.spec.genesis()` (or `musig_context(self.spec.set())`), the sorted `participants` list, and the `removed` set, e.g. `context = (b"DkgConfirmer", spec.genesis(), attempt)`. Additionally, hash the `participants` slice into the `CachedPreprocesses` key inside `preprocess_internal` so any change to the MuSig participant set forces a fresh seed, and zeroize/delete the cached seed after `share_internal` completes rather than retaining it indefinitely.

### Proof of Concept
1. Coordinator `C` with Ristretto key `x` is a validator in sets `S1`, `S2`, `S3`, each running a DKG confirmation at `attempt = 0`.
2. For `S1`, `preprocess_internal` stores `CachedPreprocesses[("DkgConfirmer", 0)] = seed`. For `S2` and `S3` the same entry is returned; `seeded_preprocess` regenerates identical `d, e` (since `random_nonce` hashes `seed || x`) and identical published `Commitments`.
3. Each set's confirmation produces an on-chain share `s_i = d + rho_i·e + c_i·λ_i·x`, signed over `set_keys_message(S_i.set, removed_i, key_pair_i)`.
4. An observer collects the three published preprocesses and shares, computes each `rho_i`, `c_i`, `λ_i` from public data, and solves the 3×3 linear system over the scalar field for `(d, e, x)`, recovering `x`.

struct SigningProtocol<'a, T: DbTxn, C: Encode> {
  pub(crate) key: &'a Zeroizing<<Ristretto as Ciphersuite>::F>,
  pub(crate) spec: &'a TributarySpec,
  pub(crate) txn: &'a mut T,
  pub(crate) context: C,
}

impl<T: DbTxn, C: Encode> SigningProtocol<'_, T, C> {
  fn preprocess_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
  ) -> (AlgorithmSignMachine<Ristretto, Schnorrkel>, [u8; 64]) {
    // Encrypt the cached preprocess as recovery of it will enable recovering the private key
    // While the DB isn't expected to be arbitrarily readable, it isn't a proper secret store and
    // shouldn't be trusted as one
    let mut encryption_key = {
      let mut encryption_key_preimage =
        Zeroizing::new(b"Cached Preprocess Encryption Key".to_vec());
      encryption_key_preimage.extend(self.context.encode());
      let repr = Zeroizing::new(self.key.to_repr());
      encryption_key_preimage.extend(repr.deref());
      Blake2s256::digest(&encryption_key_preimage)
    };
    let encryption_key_slice: &mut [u8] = encryption_key.as_mut();

    let algorithm = Schnorrkel::new(b"substrate");
    let keys: ThresholdKeys<Ristretto> =
      musig(musig_context(self.spec.set().into()), self.key.clone(), participants)
        .expect("signing for a set we aren't in/validator present multiple times")
        .into();

    if CachedPreprocesses::get(self.txn, &self.context).is_none() {
      let (machine, _) =
        AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);

      let mut cache = machine.cache();
      assert_eq!(cache.0.len(), 32);
      #[allow(clippy::needless_range_loop)]
      for b in 0 .. 32 {
        cache.0[b] ^= encryption_key_slice[b];
      }

      CachedPreprocesses::set(self.txn, &self.context, &cache.0);
    }

    let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
    let mut cached: Zeroizing<[u8; 32]> = Zeroizing::new(cached);
    #[allow(clippy::needless_range_loop)]
    for b in 0 .. 32 {
      cached[b] ^= encryption_key_slice[b];
    }
    encryption_key_slice.zeroize();
    let (machine, preprocess) =
      AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached));

    (machine, preprocess.serialize().try_into().unwrap())
  }

  fn random_nonce<R: RngCore + CryptoRng>(
    secret: &Zeroizing<Self::F>,
    rng: &mut R,
  ) -> Zeroizing<Self::F> {
    let mut seed = Zeroizing::new(vec![0; 32]);
    rng.fill_bytes(seed.as_mut());

    let mut repr = secret.to_repr();

    // Perform rejection sampling until we reach a non-zero nonce
    // While the IETF spec doesn't explicitly require this, generating a zero nonce will produce
    // commitments which will be rejected for being zero (and if they were used, leak the secret
    // share)
    // Rejection sampling here will prevent an honest participant from ever generating 'malicious'
    // values and ensure safety
    let mut res;
    while {
      seed.extend(repr.as_ref());
      res = Zeroizing::new(<Self as Curve>::hash_to_F(b"nonce", seed.deref()));
      res.ct_eq(&Self::F::ZERO).into()
    } {
      seed = Zeroizing::new(vec![0; 32]);
      rng.fill_bytes(&mut seed);
    }
    repr.as_mut().zeroize();

    res
  }

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
