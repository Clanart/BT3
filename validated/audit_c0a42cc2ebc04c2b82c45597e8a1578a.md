## Analysis

The Nibiru report's core defect is: **a fallible decode/lookup is invoked, its error is silently discarded, and the resulting (wrong/default) value is fed directly into a fund-affecting calculation instead of aborting.**

Searching Hyperbridge for the same anti-pattern — a `Result`-returning lookup whose error is swallowed via `unwrap_or_default()`/`.ok()` and then used to compute a value that moves funds — the strongest match is in `pallet-consensus-incentives`, which pays relayers a per-block reward out of the treasury for delivering consensus updates. [1](#0-0) 

```rust
fn calculate_reward(
	state_machine_id: &StateMachineId,
	block_cost: <T as pallet_ismp::Config>::Balance,
) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
	let host = <T::IsmpHost>::default();
	let latest_height = host
		.latest_commitment_height(state_machine_id.clone())
		.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
	let previous_height =
		host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

	let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

	let blocks = latest_height.saturating_sub(baseline);

	let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
	let reward = blocks_as_balance.saturating_mul(block_cost);

	Ok(reward)
}
```

Unlike `latest_commitment_height`, whose `Err` is properly propagated with `?`, the sibling call `host.previous_commitment_height(...)` has its `Result` collapsed with `.unwrap_or_default()` — exactly the `bankBalance`-style pattern of decoding/looking up a value, discarding a failure, and proceeding with a default (likely `0`) instead of erroring out. That value feeds `baseline`, which is then subtracted from `latest_height` to compute `blocks`, which is directly multiplied into the treasury payout in `process_message`: [2](#0-1) 

```rust
fn process_message(...) -> Result<(), Error<T>> {
	if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
		let reward = Self::calculate_reward(&state_machine_id, block_cost)?;
		...
		T::Currency::transfer(&T::TreasuryAccount::get().into_account_truncating(), &relayer_account, reward, Preservation::Expendable)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;
		...
		T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())...
		LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| { *watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height)); });
	}
	Ok(())
}
```

`LastRewardedHeight` is only ever populated *after* a successful `process_message` call, so on the very first reward for any given `state_machine_id` the code falls back to `previous_height` — the value that was silently defaulted on lookup failure. If `previous_commitment_height` errors on that first call (a very plausible condition, since a "previous" commitment may legitimately not exist yet for a state machine that already advanced past height 0 before the incentive pallet was configured, or under any transient host-storage read failure), `baseline` becomes `0` while `latest_height` reflects the chain's already-advanced height. `blocks = latest_height - 0` is then multiplied by `block_cost` and paid out in full from the treasury — a payout for the entire historical height range instead of only the newly delivered span.

Because I could not fully load `modules/pallets/ismp/src/host.rs`'s `previous_commitment_height` implementation within the available budget, I cannot state with certainty every condition under which it returns `Err` (versus `Ok(0)`) on a fresh state machine. That is the one open verification gap in this analysis; the swallowed-`Result`-into-fund-calculation pattern itself, however, is directly visible and unambiguous in the code shown above.

### Title
Silently-defaulted `previous_commitment_height` lookup inflates relayer consensus rewards - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`calculate_reward` computes a relayer's per-block consensus-update reward as `(latest_height - baseline) * block_cost`. `baseline` falls back to `previous_commitment_height(...).unwrap_or_default()` whenever no `LastRewardedHeight` watermark exists yet (i.e., the very first reward for a state machine). Any failure of `previous_commitment_height` is discarded rather than propagated, silently substituting `0` as the baseline.

### Finding Description
`latest_commitment_height`'s error is correctly propagated with `?`, but the adjacent `previous_commitment_height` call is collapsed with `.unwrap_or_default()`, discarding the error the way the Nibiru `bankBalance` bug discarded `parseArgsBankBalance`'s error before calling `GetBalance`. The defaulted `previous_height` is used as `baseline` on the first-ever reward computation for a state machine (`LastRewardedHeight` is `None` at that point), meaning `blocks = latest_height - 0 = latest_height`, i.e. the reward is computed as if the relayer delivered the state machine's *entire* height history in one batch.

### Impact Explanation
`process_message` transfers the resulting `reward` from `T::TreasuryAccount` to the submitting relayer and mints a proportional amount of `T::ReputationAsset`. An inflated `blocks` value (driven by the discarded lookup error rather than the actual number of blocks delivered) directly translates into an inflated, unauthorized treasury payout and an inflated reputation-asset mint — a "wrong amount" fund-movement bug matching the bounty's stated impact classes (loss of funds / unauthorized transaction).

### Likelihood Explanation
The trigger requires no privileged actor: any relayer whose consensus update is the first one processed for a given `state_machine_id` under this incentive pallet exercises the `LastRewardedHeight == None` branch. Whether `previous_commitment_height` actually errors in that situation depends on `pallet_ismp::host.rs`'s implementation, which was not fully verified in this pass — this is the residual uncertainty in confirming exploitability end-to-end.

### Recommendation
Propagate the error from `previous_commitment_height` with `?` (mirroring the `latest_commitment_height` call) instead of `.unwrap_or_default()`, so a failed lookup aborts reward computation rather than silently substituting `0` as the baseline.

### Proof of Concept
1. Configure `StateMachinesCostPerBlock` for a new `state_machine_id` whose `latest_commitment_height` is already large (e.g., the chain has been running/relaying for a long time before consensus-incentives tracked it, or `previous_commitment_height` errors for any other reason on the pallet's first invocation for that id).
2. Submit any consensus/message batch that triggers `FeeHandler::on_executed` → `process_message` for that `state_machine_id`.
3. `LastRewardedHeight::get(state_machine_id)` is `None`, so `baseline` falls back to `previous_commitment_height(...).unwrap_or_default()`.
4. If that call errs, `baseline = 0`; `blocks = latest_height - 0 = latest_height`; `reward = latest_height * block_cost` is transferred from the treasury to the relayer in one shot, instead of the reward for only the blocks actually just delivered. [3](#0-2)
