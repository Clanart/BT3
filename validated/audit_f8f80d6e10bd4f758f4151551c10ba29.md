### Title
Malformed `ThresholdKeys` can deserialize an identity group key and crash Bitcoin signing - (File: `crypto/dkg/src/lib.rs`)

### Summary
`ThresholdKeys::read` accepts an identity verification share because `crypto/dkg` uses the base `Ciphersuite::read_G`, which validates canonical encodings but does not reject identity points. For a `1-of-1` key, this makes `group_key` the point at infinity. Passing the resulting keys to Bitcoin’s FROST Schnorr algorithm reaches `Hram::hram`, which calls `x(A)`; `x` explicitly expects an x-coordinate and panics when `A` is infinity. A malformed serialized key can therefore trigger an unexpected process crash during signing. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`ThresholdKeys::read` deserializes `n` verification shares with `<C as Ciphersuite>::read_G`, then passes them to `ThresholdKeys::new`. [4](#0-3) 

`Ciphersuite::read_G` rejects invalid or non-canonical encodings, but accepts the canonical identity encoding. [5](#0-4) 

`ThresholdKeys::new` checks only the number of shares and participant bounds before calculating the group key from shares `1..=t`; it does not reject identity shares or an identity aggregate. [6](#0-5) 

For serialized parameters `t = n = i = 1` with Lagrange interpolation and an identity verification share, the interpolation factor is `1`, so the accepted group key is identity. During signing, `ThresholdKeys::view` preserves that identity group key in `ThresholdView`. [7](#0-6) 

The Bitcoin Schnorr algorithm’s `sign_share` delegates to the generic Schnorr implementation, which computes `Hram::hram(&nonce_sums[0][0], &params.group_key(), msg)`. [8](#0-7) [9](#0-8) 

`Hram::hram` unconditionally extracts the x-coordinate of `A`, and `x` panics on the point at infinity. [10](#0-9) [11](#0-10) 

### Impact Explanation
An attacker-controlled serialized `ThresholdKeys` blob can cause the process to panic as soon as the malformed key is used for Bitcoin transaction signing. This is a remotely triggerable denial of service where untrusted key material reaches `ThresholdKeys::read` and then the Bitcoin `Schnorr` signing machine. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The payload is deterministic and does not require brute force, secret knowledge, timing, or threshold collusion. A `1-of-1` serialized key with an identity verification share is sufficient, provided the application accepts that serialized key from an unprivileged source and subsequently uses it to sign. [14](#0-13) [15](#0-14) 

### Recommendation
Reject identity verification shares and an identity `group_key` in `ThresholdKeys::new`, or use an identity-rejecting point decoder when deserializing key material. Additionally, make Bitcoin’s `x`/`x_only` helpers return an error rather than panic, and propagate that error through the signing algorithm. [16](#0-15) [17](#0-16)

```rust
use k256::{ProjectivePoint, Scalar};
use rand_core::OsRng;

let mut encoded = Vec::new();

// Ciphersuite ID length and ID for Secp256k1.
encoded.extend_from_slice(&9u32.to_le_bytes());
encoded.extend_from_slice(b"secp256k1");

// t = 1, n = 1, i = 1.
encoded.extend_from_slice(&1u16.to_le_bytes());
encoded.extend_from_slice(&1u16.to_le_bytes());
encoded.extend_from_slice(&1u16.to_le_bytes());

// Interpolation::Lagrange.
encoded.push(1);

// Any canonical secret share.
encoded.extend_from_slice(Scalar::ONE.to_repr().as_ref());

// Canonical secp256k1 identity encoding.
encoded.extend_from_slice(ProjectivePoint::IDENTITY.to_bytes().as_ref());

let keys =
  ThresholdKeys::<Secp256k1>::read(&mut encoded.as_slice()).expect("malformed key was accepted");
assert!(bool::from(keys.group_key().is_identity()));

let (machine, _preprocess) =
  AlgorithmMachine::new(BitcoinSchnorr::new(), keys).preprocess(&mut OsRng);

// For t = 1, the local participant alone satisfies the signing set.
// This reaches Hram::hram(..., A = identity, ...) and panics in x().
let _ = machine.sign(HashMap::new(), b"");
```

The important behavior is that `ThresholdKeys::read` accepts the object, while the later signing path assumes the resulting group key cannot be infinity. [18](#0-17) [19](#0-18)
