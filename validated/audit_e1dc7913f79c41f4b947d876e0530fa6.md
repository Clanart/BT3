## Analog Found

### Title
Data Layer SSRF via unauthenticated mirror URLs in `http_download` - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer mirror/subscription mechanism lets any user register arbitrary URLs on-chain for a store (via a `MIRROR_PUZZLE_HASH` coin spend reachable through the `dl_new_mirror` wallet RPC), and every DataLayer node that syncs/subscribes to that store's singleton history will automatically fetch those attacker-chosen URLs with no destination validation — the same "accept and fetch an arbitrary attacker-supplied URL" pattern as the TorchServe `allowed_urls` SSRF (CVE-2023-43654).

### Finding Description
A DataLayer store's mirror URLs are fully attacker-controlled strings stored on-chain in a `Mirror` coin and are not validated for scheme, host, or destination (no blocklist for loopback/link-local/private ranges, no scheme allowlist). Anyone can add a mirror for any `launcher_id` via `add_mirror()`/`dl_new_mirror`, which is only gated by owning enough XCH to pay the coin `amount`/`fee`, not by ownership of the store itself: [1](#0-0) 

Any peer's DataLayer service that subscribes to that store pulls the mirror URL list purely from wallet RPC state and stores it as subscription servers without any validation: [2](#0-1) [3](#0-2) 

During the periodic sync loop, `fetch_and_validate()` randomly selects one of these attacker-registered server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which issues an unrestricted `aiohttp` GET request to `server_info.url + "/" + filename`: [4](#0-3) [5](#0-4) 

There is no check that the URL points to a public, non-internal host, and the response body is written directly to a local file: [6](#0-5) 

This is architecturally the same flaw as the TorchServe advisory: the service accepts and blindly dereferences a third-party-supplied URL for a "download" feature, without an `allowed_urls`-style restriction, letting an unprivileged party force the victim service to make outbound requests to arbitrary hosts (including internal-only or cloud-metadata endpoints) chosen by the attacker.

### Impact Explanation
An unprivileged Data Layer participant (any wallet holder able to create a mirror coin, or the `subscribe` RPC/CLI accepting arbitrary user-supplied URLs directly) can force any node that subscribes to their store to issue outbound HTTP requests to attacker-chosen internal/private network destinations (e.g., cloud metadata services, internal admin panels, localhost-bound RPC ports on the victim host). Combined with the write-to-disk behavior of `http_download`, this is a genuine SSRF affecting availability/confidentiality of the DataLayer host's internal network reachability, matching CWE-918 and the reachable, medium/high severity bar requested.

### Likelihood Explanation
High reachability: creating a mirror or calling `dl_subscribe`/`data subscribe` with an arbitrary URL requires no special privilege beyond normal wallet spend capability, and any other node choosing to subscribe/sync that store will automatically dereference the URL during its normal periodic `fetch_and_validate` background loop — no additional user interaction needed on the victim side beyond subscribing.

### Recommendation
Validate mirror/subscription URLs before use in `http_download`/`download_file`: enforce an allowed scheme list (http/https only), resolve and reject requests targeting private/loopback/link-local/multicast IP ranges and cloud metadata addresses (mirroring the intent of TorchServe's `allowed_urls`), and optionally require explicit operator opt-in/allowlisting of external mirror hosts before the DataLayer service will auto-fetch from them.

### Proof of Concept
1. Attacker creates (or controls) a DataLayer store and calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount, fee)`, which spends a `MIRROR_PUZZLE_HASH` coin on-chain via `dl_new_mirror`. [1](#0-0) 
2. Victim's DataLayer node subscribes to (or already tracks) that `store_id`. Its background loop calls `update_subscriptions_from_wallet()`, which pulls the malicious URL from wallet mirror state into local subscription server list without validation. [2](#0-1) 
3. `fetch_and_validate()` selects that server and calls `insert_from_delta_file` → `download_file` → `http_download`, causing the victim node to issue an unauthenticated GET request to the attacker-chosen internal URL. [5](#0-4)

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
