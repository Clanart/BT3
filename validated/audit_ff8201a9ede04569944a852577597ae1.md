### Title
Unbounded attacker-controlled allocation in `ThresholdKeys::read` — deserialization size is driven by a 2-byte length field before any validation - (File: crypto/dkg/src/lib.rs)

### Summary
The Absinthe advisory is an unauthenticated resource-exhaustion bug: attacker-controlled tokens in parsed input are converted into fresh atoms without a cap, letting a small request consume a global resource proportional to attacker-chosen counts. The analog in Serai is deserialization paths where an attacker-controlled length field drives work/allocation before validation. The strongest in-scope instance is `ThresholdKeys::read`, which trusts the serialized `n` field (a `u16` read straight from the input) to size a `Vec` and drive `n` field-element and group-element deserializations before `ThresholdParams::new` is ever consulted.

### Finding Description
`ThresholdKeys::read` at crypto/dkg/src/lib.rs reads `t`, `n`, `i` verbatim from the stream, then:

- For `Interpolation::Constant` (`interpolation[0] == 0`), it executes `Vec::with_capacity(usize::from(n))` and then loops `n` times calling `C::read_F` (lines 604–613).
- Independently of the interpolation tag, it loops `for l in (1 ..= n)` calling `C::read_G` into a `HashMap` (lines 620–623).
- Only after all of that does it call `ThresholdParams::new(t, n, i)` — the first point at which `t`/`n`/`i` are validated (lines 625–630).

```rust
// crypto/dkg/src/lib.rs:604-613
let mut interpolation = [0];
reader.read_exact(&mut interpolation)?;
let interpolation = match interpolation[0] {
  0 => Interpolation::Constant({
    let mut res = Vec::with_capacity(usize::from(n));
    for _ in 0 .. n {
      res.push(C::read_F(reader)?);
    }
    res
  }),
```

Because `n` is a raw `u16` from the wire, a blob roughly a dozen bytes long — curve ID + `t=0`/`n=0xFFFF`/`i=1` + tag `0x00` — forces an immediate `Vec::with_capacity(65535)` (≈2 MiB of contiguous heap for a 32-byte `Scalar`/`FieldElement`) before the first `read_F` fails on a short input. Nothing in `read` bounds `n` against the actual stream length, and the cheap "allocate-then-fail" path can be repeated arbitrarily. `ThresholdKeys::read` is a public API explicitly in the exposed surface (it is used to load keys received/stored per-deployment and is one of the listed untrusted-byte entry points). The same shape exists in `Commitments::read` (crypto/dkg/pedpop/src/lib.rs:110-127, `Vec::with_capacity(params.t().into())` driven by caller-supplied-but-untrusted params) and `SchnorrAggregate::read` (crypto/schnorr/src/aggregate.rs:77-88, loops `u32` times reading points — linear in supplied bytes, weaker).

### Impact Explanation
Unauthenticated memory-pressure denial of service: each tiny crafted blob forces a multi-MiB contiguous heap reservation plus initialization overhead before erroring. Sustained requests amplify allocation traffic far beyond input bandwidth, degrading or crashing the process holding the threshold key material — precisely the CWE-770 (allocation without limits) shape of the original advisory, where a short input minted a large permanent resource.

### Likelihood Explanation
Any deployment path that passes externally-obtained bytes (key packages transmitted between validators, coordinator-supplied blobs, recovery data) into `ThresholdKeys::read` exposes this. The cost is a few bytes and zero state, so it is trivially repeatable; severity is capped at Medium because the peak allocation is bounded by `u16::MAX` (≈2 MiB per attempt for typical 32-byte fields) rather than truly unbounded, and the memory is freed on error.

### Recommendation
Validate `t`/`n`/`i` with `ThresholdParams::new` *before* allocating or looping; do not call `Vec::with_capacity(n)` (or use a sane cap such as the maximum plausible validator-set size) until the header is checked; cap element counts against remaining input length (e.g., `reader` size hint / explicit limit) before iterating. Apply the same ordering fix to `Commitments::read` and `SchnorrAggregate::read`.

bytes.extend(&u16::MAX.to_le_bytes());       // n = 65535 -> Vec::with_capacity(65535)
bytes.extend(&1u16.to_le_bytes());           // i = 1
bytes.push(0);                               // Interpolation::Constant
// read() allocates ~65535 * size_of::<C::F>() before failing on read_F
let _ = ThresholdKeys::<Ristretto>::read(&mut bytes.as_slice());
