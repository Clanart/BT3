### Title
Insecure offer cancellation does not invalidate the on-chain spendability of offered coins, allowing a counterparty to complete a "cancelled" offer - ([File: chia/wallet/trade_manager.py])

### Summary
The reported CVE describes Mattermost failing to invalidate an OAuth2 authorization code when the app is deauthorized, letting a holder of the still-valid code redeem it for an access token later. The Chia analog is `TradeManager.cancel_pending_offers()` when called with `secure=False`: it only flips the trade's local DB status to `CANCELLED` and fires a `offer_cancelled` websocket event — it never spends the coins offered on-chain. [1](#0-0)  The underlying coins and the offer bytes (which the maker already shared with a counterparty) remain fully valid and spendable, exactly like an un-revoked authorization code.

### Finding Description
`cancel_pending_offers` branches on the `secure` flag. When `secure=True`, it builds a real spend of the `cancellation_coins` (via `Offer.get_cancellation_coins()`) so that the coins backing the offer are consumed and the offer can no longer be completed. [2](#0-1)  When `secure=False`, the function simply dispatches a local UI event and marks the trade as `CANCELLED` in the trade store, then `continue`s to the next trade — no coin spend is created at all: [1](#0-0) 

This `secure` flag is exposed all the way up through the RPC `cancel_offer`/`cancel_offers` endpoints: [3](#0-2) [4](#0-3) 

Because an `Offer` is just a serialized, fully-signed/aggregatable `SpendBundle` that the maker already handed to (or published for) a counterparty, "cancelling" it locally with `secure=False` does nothing to prevent that counterparty (or anyone who obtained the offer file) from calling `push_tx`/`take_offer` on the original, still-valid offer bytes. The maker's wallet UI shows the trade as cancelled, but the coins it thinks are freed are still encumbered by the original offer's puzzle/solution and can be swept by the counterparty at any time before the maker's coins are otherwise spent. This mirrors the OAuth bug precisely: revocation intent is recorded, but the actual authorizing artifact (offer bundle / authorization code) is never invalidated at the source of truth (the coin set / mempool).

### Impact Explanation
If a user (or any GUI/CLI/RPC caller) cancels an offer without the `secure`/`--transaction` on-chain path — which is a legitimate, documented option, not a malicious action — the coins offered remain claimable by whoever holds the offer file. A counterparty who has already received the offer (e.g., over a marketplace or DM) can later push the original spend bundle and take assets the maker believed were "cancelled" and safe to reuse elsewhere. This can result in double-spend races, unintended coin/asset transfer, and loss of the offered assets if the maker also re-spends the same coins expecting them to be free.

### Likelihood Explanation
High reachability: any wallet user or RPC caller can trigger this by choosing the non-secure cancel option (`secure=False`), which is a first-class, exposed feature (`CancelOffer.secure`, `cancel_offer` RPC). No adversarial peer or protocol-level attack is required — it only requires a counterparty who already legitimately possesses the offer bytes and chooses to push them after the maker "cancels."

### Recommendation
Either remove/deprecate the insecure (`secure=False`) cancellation path, or make its semantics explicit and enforce that offers cannot be treated as inert until an on-chain cancellation spend (or the maker's coins are otherwise consumed) is confirmed. At minimum, the wallet should track offered coins as "still encumbered" (not spendable/reusable) until a secure, on-chain cancellation transaction confirms, closing the gap where local DB status diverges from actual chain-enforced spendability.

### Proof of Concept
1. Wallet A creates an offer via `create_offer_for_ids`, offering coin `C`, and shares the resulting offer file with Wallet B.
2. Wallet A calls `cancel_offer` (RPC) with `secure=False`. `cancel_pending_offers` sets the trade status to `CANCELLED` locally and does not spend `C`. [1](#0-0) 
3. Wallet A's UI reports the offer as cancelled and Wallet A may treat coin `C` as free/reusable.
4. Wallet B, still holding the original offer bytes, calls `take_offer`/pushes the original `SpendBundle` to the mempool. Because coin `C` was never spent by a real cancellation transaction, the take succeeds and Wallet B receives the offered asset — despite the maker's belief that the offer was revoked.

    def get_cancellation_coins(self) -> list[Coin]:
        # First, we're going to gather:
        dependencies: dict[bytes32, list[bytes32]] = {}  # all of the hashes that each coin depends on
        announcements: dict[bytes32, list[bytes32]] = {}  # all of the hashes of the announcement that each coin makes
        coin_names: list[bytes32] = []  # The names of all the coins
        additions = self.additions()
        for spend in [cs for cs in self._bundle.coin_spends if cs.coin not in additions]:
            name = bytes32(spend.coin.name())
            coin_names.append(name)
            dependencies[name] = []
            announcements[name] = []
            conditions: Program = run_with_cost(spend.puzzle_reveal, INFINITE_COST, spend.solution)[1]
            for condition in conditions.as_iter():
                if condition.first() == 60:  # create coin announcement
                    announcements[name].append(
                        AssertCoinAnnouncement(asserted_id=name, asserted_msg=condition.at("rf").as_python()).msg_calc
                    )
                elif condition.first() == 61:  # assert coin announcement
                    dependencies[name].append(bytes32(condition.at("rf").as_python()))

        # We now enter a loop that is attempting to express the following logic:
        # "If I am depending on another coin in the same bundle, you may as well cancel that coin instead of me"
        # By the end of the loop, we should have filtered down the list of coin_names to include only those that will
        # cancel everything else
        while True:
            removed = detect_dependent_coin(coin_names, dependencies, announcements)
            if removed is None:
                break
            removed_coin, provider = removed
            removed_announcements: list[bytes32] = announcements[removed_coin]
            remove_these_keys: list[bytes32] = [removed_coin]
            while True:
                for coin, deps in dependencies.items():
                    if set(deps) & set(removed_announcements) and coin != provider:
                        remove_these_keys.append(coin)
                removed_announcements = []
                for coin in remove_these_keys:
                    dependencies.pop(coin)
                    removed_announcements.extend(announcements.pop(coin))
                coin_names = [n for n in coin_names if n not in remove_these_keys]
                if removed_announcements == []:
                    break
                else:
                    remove_these_keys = []

        return [cs.coin for cs in self._bundle.coin_spends if cs.coin.name() in coin_names]

    async def cancel_offers(
        self,
        request: CancelOffers,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> CancelOffersResponse:
        trade_mgr = self.service.wallet_state_manager.trade_manager
        log.info(f"Start cancelling offers for  {'all' if request.cancel_all else 'asset_id: ' + request.asset_id} ...")
        # Traverse offers page by page
        for start in count(0, request.batch_size):
            records = {
                record.trade_id: record
                for record in await trade_mgr.trade_store.get_trades_between(
                    start,
                    start + request.batch_size,
                    reverse=True,
                    exclude_my_offers=False,
                    exclude_taken_offers=True,
                    include_completed=False,
                )
                if request.cancel_all
                or (record.offer != b"" and request.query_key in Offer.from_bytes(record.offer).arbitrage())
            }

            if records == {}:
                break

            async with self.service.wallet_state_manager.lock:
                await trade_mgr.cancel_pending_offers(
                    list(records.keys()),
                    action_scope,
                    request.batch_fee,
                    request.secure,
                    records,
                    extra_conditions=extra_conditions,
