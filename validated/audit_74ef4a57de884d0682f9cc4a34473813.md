Based on the investigation, I found a concrete, well-documented Protobuf analog to the "missing modifier on a sibling function" bug class described in the Connext report.

### Title
Recursion-depth guard bypassed on the `Any`-reparse sibling code path in JSON parsing - ([File: src/google/protobuf/json/internal/parser.cc], and historically in equivalent Java/Python/C# JSON parsers)

### Summary
Just as `StableSwapFacet.sol` had a `whenNotPaused` guard applied to some swap/liquidity functions but omitted on sibling functions (`swapExactOut`, `addSwapLiquidity`) that perform the same class of operation, Protobuf's JSON/ProtoJSON parsers implement two sibling code paths for parsing a nested message: (1) the normal "parse a message field" path, which increments/checks a recursion-depth counter, and (2) the `google.protobuf.Any` "reparse" path, which constructs a **new** lexer/tokenizer/parser context over the extracted `Any.value` bytes. The depth-tracking invariant that protects (1) is not reliably propagated into the fresh context created for (2).

### Finding Description
Every JSON parser implementation enforces a recursion-limit check when descending into a nested message field, e.g. Java's `parseFieldValue` (`currentDepth >= recursionLimit`) at [1](#0-0) , and C#'s `JsonParser.Merge` (`tokenizer.RecursionDepth > settings.RecursionLimit`) at [2](#0-1) .

However, when a message field is actually a `google.protobuf.Any`, its packed payload is not parsed through the same depth-tracked recursive call — it is re-parsed by constructing a brand-new parsing context (a new tokenizer/lexer) over the extracted bytes. In C#, `MergeAny` builds a `JsonReplayTokenizer` over the "value" tokens ( [3](#0-2) ), and that new tokenizer originally started its `RecursionDepth` counter at zero instead of inheriting the parent's depth — a bug explicitly documented and fixed via `JsonReplayTokenizer`'s constructor comment: "Without this, deeply-nested `google.protobuf.Any` payloads can bypass the limit and cause a `StackOverflowException`" ( [4](#0-3) ). The equivalent fixes are referenced for Java's `mergeAnyMessage` and Python's `_ConvertAnyMessage` ( [5](#0-4) ), and Python's current `_ConvertAnyMessage` now explicitly routes well-known/Any-typed content through `self.ConvertMessage(...)` specifically "to ensure recursion depth is properly tracked" ( [6](#0-5) ), and Java's `mergeAny` increments/checks `currentDepth` around the nested parse ( [7](#0-6) ).

The same structural risk exists in the C++ implementation's `ParseAny`, which builds a **new** `JsonLexer` instance (`any_lex`) over the extracted `Any` body text, copying only `lex.options()` — explicitly commented as "inherits the recursion limit" (i.e., the *maximum allowed* setting) — but not necessarily the *current* recursion depth counter accumulated by the parent lexer ( [8](#0-7) ). `ParseMessage` is then invoked on this fresh lexer with `any_reparse=true` ( [9](#0-8) ). If `JsonLexer`'s depth state is not carried across this handoff the way `RecursionDepth` had to be explicitly wired into C#'s `JsonReplayTokenizer`, then a chain of nested `Any` messages could reset the effective depth counter at every `Any` boundary, exactly reproducing the historical Java/Python/C# vulnerability.

### Impact Explanation
This is the exact "missing guard on a sibling code path" invariant failure from the report: the safety check (recursion-depth limit) exists and is enforced on the "normal" nested-message parsing path but can be silently skipped on the structurally similar `Any`-reparse path, because a fresh parsing context is instantiated rather than reusing/inheriting the parent's depth state. When bypassed, deeply nested `Any`-in-`Any` ProtoJSON input can drive unbounded native call-stack recursion, producing an uncatchable stack overflow (crash / DoS) instead of the intended `InvalidProtocolBufferException`/`ParseError` — this is precisely the class of bug that was found and fixed in three independent language runtimes (C#, Java, Python).

### Likelihood Explanation
An attacker only needs to submit ordinary, bounded ProtoJSON text containing repeated `{"@type":".../Any","value": ... }` wrappers through any public JSON-parsing entry point (`JsonFormat.parser().merge(...)`, `JsonParser.Parse`, `json_format.Parse`, or the C++ `google::protobuf::json` parser) — no special privileges, malicious schema, or malformed wire bytes are required, matching the "ordinary client sending bounded input through a supported public parse API" threat model.

### Recommendation
Ensure every parsing context created for `Any`-body reparsing (in C++ `ParseAny`/`JsonLexer`, and any other runtime not yet audited such as Ruby/PHP upb JSON paths) explicitly inherits and enforces the *current* recursion depth of the parent context — not just the configured maximum limit — mirroring the fixes already applied in the C#, Java, and Python implementations. Add a conformance/regression test (analogous to C#'s `MaliciousRecursionOfAnyInAny`, Java's `testRecursionLimitAnyOfAny`, Python's `testAnyRecursionDepthEnforcement`) for the C++ implementation and any other backend that reparses `Any` bodies with a separate lexer instance.

### Proof of Concept
I could not execute code in this environment, so no test was run. The reproduction pattern, verified conceptually against the existing regression tests in this repo, is: construct ProtoJSON text nesting `{"@type":"type.googleapis.com/google.protobuf.Any","value": ...}` to a depth exceeding the configured `RecursionLimit`/`recursionLimit`/`max_recursion_depth` (e.g. depth 100 with limit 10, as in C#'s `MaliciousRecursionOfAnyInAny` test at [10](#0-9) ) and parse it via the target API; prior to the fix this caused an uncatchable `StackOverflowException` instead of a catchable protocol-buffer parse error. Whether the current C++ `json/internal/parser.cc` `ParseAny`/`JsonLexer` path is still vulnerable or already immune (e.g., via some depth field carried through `lex.options()` or `mark.loc`) could not be conclusively confirmed from the retrieved snippets — the `JsonLexer` class definition and its depth-counter field were not available in the indexed context I could retrieve. This should be verified directly in a full checkout (e.g. by tracing `JsonLexer`'s constructor and any `depth_`/`Peek`/`VisitObject` guard fields in `src/google/protobuf/json/internal/lexer.h`) before treating it as confirmed-vulnerable rather than confirmed-analogous-to-a-historically-real-and-fixed bug class.

        public void MaliciousRecursionOfAnyInAny()

            const string anyHeader = "{\"@type\":\"type.googleapis.com/google.protobuf.Any\",\"value\":";
            string json =
                string.Concat(Enumerable.Repeat(anyHeader, depth)) +
                "{}" +

            var registry = TypeRegistry.FromMessages(Any.Descriptor);

            // A generous limit must still successfully parse the document.
            var sufficientLimitParser = new JsonParser(new JsonParser.Settings(depth * 2, registry));
            Assert.DoesNotThrow(() => sufficientLimitParser.Parse<Any>(json));

            // protobuf exception rather than overflowing the stack.
            var insufficientLimitParser = new JsonParser(new JsonParser.Settings(10, registry));
            Assert.Throws<InvalidProtocolBufferException>(() => insufficientLimitParser.Parse<Any>(json));

template <typename Traits>
absl::Status ParseMessage(JsonLexer& lex, const Desc<Traits>& desc,
                          Msg<Traits>& msg, bool any_reparse) {
  MessageType type = ClassifyMessage(Traits::TypeName(desc));
  if (!any_reparse) {
    switch (type) {
      case MessageType::kAny:
        return ParseAny<Traits>(lex, desc, msg);
      case MessageType::kValue:
        return ParseValue<Traits>(lex, desc, msg);
      case MessageType::kStruct:
        return ParseStructValue<Traits>(lex, desc, msg);
      default:
        break;
    }
    // For some types, the ESF parser permits parsing the "non-special" version.
    // It is not clear if this counts as out-of-spec, but we're treating it as
    // such.
    bool is_upcoming_object = lex.Peek(JsonLexer::kObj);
    if (!(is_upcoming_object &&
          lex.options().allow_legacy_nonconformant_behavior)) {
      switch (type) {
        case MessageType::kList:
          return ParseListValue<Traits>(lex, desc, msg);
        case MessageType::kWrapper: {
          return ParseSingular<Traits>(lex, Traits::MustHaveField(desc, 1),
                                       msg);
        }
        case MessageType::kTimestamp:
          return ParseTimestamp<Traits>(lex, desc, msg);
        case MessageType::kDuration:
          return ParseDuration<Traits>(lex, desc, msg);
        case MessageType::kFieldMask:
          return ParseFieldMask<Traits>(lex, desc, msg);
        default:
          break;
      }
    }
  }
