### Title
Unbounded length-prefix parsing in `is_atom_canonical` can raise an uncaught `IndexError` from an attacker-supplied spend bundle - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` decodes a CLVM atom's variable-length size prefix (1–6 bytes) directly from a caller-controlled `bytes` buffer without ever checking that `offset` stays within the buffer bounds. This is structurally analogous to CVE-2016-5315 in libtiff's `setByteArray`, where a length value taken from untrusted input was used to index/read a buffer without a bounds check, causing an out-of-bounds read and a crash.

### Finding Description
`is_atom_canonical` reads the first byte at `offset` to determine the size of a length prefix (`prefix_len` up to 5 extra bytes), then loops reading `prefix_len` more bytes to build `atom_len`: [1](#0-0) 

There is no check anywhere in this function (or in its caller `is_clvm_canonical`) that `offset + prefix_len < len(clvm_buffer)` before indexing `clvm_buffer[offset]` in the loop: [2](#0-1) 

`is_clvm_canonical` itself also indexes `clvm_buffer[offset]` in its main loop with no bound check other than the top-level `assert clvm_buffer != b""`: [3](#0-2) 

This function is invoked directly on attacker-supplied bytes: every `coin_spend.puzzle_reveal` and `coin_spend.solution` in a submitted `SpendBundle` are passed through `is_clvm_canonical()` during mempool admission, in `MempoolManager.validate_spend_bundle()`: [4](#0-3) 

Because Python `bytes` indexing raises `IndexError` when the index is out of range (rather than silently returning garbage as in the C libtiff case), a crafted puzzle reveal or solution whose trailing bytes encode a length-prefix byte (e.g. `0xFC`–`0xFE`) that claims more prefix bytes than actually remain in the buffer will cause `clvm_buffer[offset]` to raise an unhandled `IndexError` inside `validate_spend_bundle()`. I was not able to fully trace, within the remaining tool budget, whether every call path from the p2p `transaction`/`respond_transaction` handlers in `chia/full_node/full_node.py` wraps `add_spend_bundle`/`validate_spend_bundle` in a broad exception handler that would turn this into a harmless rejection versus an unhandled exception that aborts spend-bundle processing for that request; this should be verified before treating the impact as confirmed at High severity.

### Impact Explanation
If the `IndexError` is not caught by a surrounding handler, a single malicious spend bundle sent to a full node (or found in a pool) can crash or abort the mempool validation task processing it, potentially disrupting transaction admission for that request/connection — a spend-triggered transaction-processing halt. Even if it is ultimately caught somewhere and converted into a rejection, the missing bounds check is a real robustness defect matching the CVE's bug class (untrusted length value used without validating remaining-buffer length before reading).

### Likelihood Explanation
Reaching this code path only requires submitting a spend bundle to a full node's mempool — this is exactly the kind of action available to a normal, unprivileged wallet/RPC/network transaction submitter, with no special permissions required. The crafted puzzle_reveal/solution can be built in pure Python bytes without any signing (the bytes only need to be malformed CLVM, not valid/executable), since `is_clvm_canonical` runs on the raw serialized bytes before/alongside consensus CLVM execution.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` (and in `is_clvm_canonical`'s main loop) before indexing `clvm_buffer[offset]`, returning "not canonical" (or raising a domain-specific, caught exception/`ConsensusError`) whenever the length prefix would extend past the end of the buffer, mirroring the bounds checks already present in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`, `generator_from_block`) which explicitly compare claimed lengths against `len(buf)` before slicing.

### Proof of Concept
Conceptually: construct a `coin_spend.solution` (or `puzzle_reveal`) bytes buffer that ends with a byte matching the `0b11111100`/`0b11111110` masks (5-byte length prefix) but has fewer than 5 bytes remaining afterward, e.g. `bytes([0xFC])` alone, or `bytes([0xFE, 0x01])` — wait, `0xFE` is the back-reference marker handled separately; use `bytes([0xFC])` truncated. Passing such a buffer to `is_clvm_canonical(buf)` (directly, or via a `SpendBundle` whose `coin_spend.solution` ends with these truncated bytes, submitted to `MempoolManager.validate_spend_bundle`) causes `is_atom_canonical` to execute `clvm_buffer[offset]` with `offset >= len(clvm_buffer)`, raising `IndexError: index out of range` instead of returning a "not canonical"/error result.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
