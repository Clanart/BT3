### Title
Double-clicking a conflicted file in the Copilot Conflicts "Changes" view bypasses the restricted-extension guard and opens attacker-controlled files with `shell.openExternal` - ([File: app/src/ui/multi-commit-operation/dialog/copilot-conflicts-changes.tsx])

### Summary
The bug-class from the GoGoPool report is an admin/security guard (`whenNotPaused`) that is enforced on some entry points but not on sibling functions that reach the same sensitive operation, letting the guard be bypassed. The GitHub Desktop analog is `isSafeFileExtension`, the guard that is supposed to gate "open this file with the OS default handler" so that dangerous executable extensions (`.cmd`, `.exe`, `.bat`, `.sh` on Windows) are never launched directly. It is correctly checked before every context-menu "Open with Default Program" action in `filter-changes-list.tsx`, `selected-commits.tsx`, and `pull-request-files-changed.tsx`, but the sibling entry point `onRowDoubleClick` in the Copilot Conflicts dialog's changes list calls `openFile()` unconditionally, with no extension check at all.

### Finding Description
`isSafeFileExtension` is the single guard in the codebase meant to stop native execution of files opened via `shell.openExternal(file://...)`: [1](#0-0) 

Every other call site that ends up invoking `openFile()`/`shell.openExternal` for "Open with Default Program" is gated by this check, e.g. in `selected-commits.tsx`: [2](#0-1) 
and `pull-request-files-changed.tsx`: [3](#0-2) 

`openFile()` itself performs no extension validation — it just forwards straight to `shell.openExternal`: [4](#0-3) 

However, in `CopilotConflictsChanges` (the file list shown in the AI merge-conflict resolution dialog), double-clicking a row calls `openFile()` directly, bypassing `isSafeFileExtension` entirely: [5](#0-4) 

Contrast this with the equivalent double-click handlers elsewhere in the app, which route through the external-editor path (not the raw OS "open" path) instead of `openFile`: [6](#0-5) [7](#0-6) 

`file.path` in this dialog comes from a real merge/rebase/cherry-pick's conflicted-file list, which is directly influenced by the content of the branch/fork being merged in — i.e., attacker-controlled if the user merges a hostile branch or accepts a hostile PR/fork. The corrupted value is the guard-bypass itself: `isSafeFileExtension(extension)` is never evaluated before `shell.openExternal(file://fullPath)` is invoked on double-click, so a maliciously named conflicted file (e.g., `payload.cmd`, `payload.bat`) can be launched via a single double-click gesture that the user reasonably believes is just "preview this conflicting file," exactly as it does for every other file row in every other list in the app.

### Impact Explanation
On Windows, double-clicking a conflicted file named with a `.cmd`/`.bat`/`.exe` extension in the Copilot Conflicts changes list executes it via the OS shell instead of merely opening/previewing it, because the one guard designed to stop this (`isSafeFileExtension`) is not applied on this specific code path. This is code execution triggered by content that originates from a git merge of attacker-influenced branches — a stronger and more directly actionable impact than the original report's inconsistency finding, though the class of bug (an inconsistently-applied guard across "sibling" functions performing the same sensitive action) is identical.

### Likelihood Explanation
Likelihood is moderate: it requires the user to (a) encounter a merge/rebase/cherry-pick conflict against attacker-controlled content, (b) open the Copilot Conflicts dialog, and (c) double-click the malicious file's row instead of using the (safely-gated) context menu. Double-clicking a row to preview/inspect a conflicting file is a completely natural interaction in this UI — it is the exact same gesture that safely opens a diff/editor everywhere else in Desktop — so no unusual or "unnatural" steps are required once the user is looking at the conflicts list.

### Recommendation
Add the same `isSafeFileExtension` gate to `CopilotConflictsChanges.onRowDoubleClick` (and any other direct `openFile()`/`shell.openExternal(file://...)` call site) that is already applied to every "Open with Default Program" context-menu item, or better, route double-click in this dialog through the external-editor / diff-preview path instead of the raw OS-open path, consistent with `selected-commits.tsx` and `pull-request-files-changed.tsx`.

### Proof of Concept
1. Attacker prepares a branch/fork that, when merged/rebased/cherry-picked against the victim's branch, produces a merge conflict on a file literally named `update.cmd` (or `.bat`/`.exe` on Windows) containing an arbitrary payload as its conflicted content.
2. Victim uses GitHub Desktop's AI-assisted "Resolve conflicts with Copilot" flow, which renders the conflicted files in `CopilotConflictsChanges`'s `FileList`.
3. Victim double-clicks the `update.cmd` row expecting to preview/inspect the conflicting file (as they would in any other file list in the app).
4. `onRowDoubleClick` fires `openFile(fullPath, dispatcher)` unconditionally — [8](#0-7)  — invoking `shell.openExternal('file://' + fullPath)` with no `isSafeFileExtension` check, causing Windows to execute the `.cmd` file instead of merely showing it in the file list.

```typescript
import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
```
