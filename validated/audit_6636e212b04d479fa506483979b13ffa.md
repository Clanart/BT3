Confirmed: the current `AddNative`/`UpsertERCPointer` flow allows any unprivileged caller to re-invoke the pointer precompile for an already-registered native ERC20 pointer, and it will unconditionally overwrite the deployed contract's bytecode (including the immutable `ddecimals` value) using whatever bank denom metadata exists *at call time* — with no version gate and no admin restriction on the caller.

### Title
Permissionless re-registration of a native ERC20 pointer redeploys its code with new decimals/name/symbol, breaking downstream accounting - ([File: x/evm/keeper/pointer_upgrade.go], [File: precompiles/pointer/pointer.go])

### Summary
The `addNativePointer` precompile method lets any EVM caller create (and, critically, re-create) an ERC20 pointer contract for a Sei native/tokenfactory denom. `PrecompileExecutor.AddNative` reads the *current* bank `DenomMetaData` (name/symbol/decimals) for the token and passes it into `Keeper.UpsertERCNativePointer` → `UpsertERCPointer`, which redeploys code at the *existing* pointer address whenever one already exists, with no version or authorization check comparable to the one used for CW20/CW721/CW1155 `RegisterPointer` flow.

### Finding Description
`UpsertERCPointer` in [1](#0-0)  looks up whether a pointer already exists for the token; if it does, it simply calls `evm.GetDeploymentCode` with freshly-packed constructor args and overwrites the contract's code in place via `k.SetCode(writeCtx, contractAddr, ret)` — it never checks a "pointer version" the way `RegisterPointer` does for CW-based pointers (`existingVersion >= currentVersion` gate in [2](#0-1) ).

The constructor args for the native pointer are `token, metadata.Name, metadata.Symbol, metadata.Decimals` ( [3](#0-2) ), and `AddNative` derives these directly from the live `bankKeeper.GetDenomMetaData` at call time ( [4](#0-3) ). The compiled `NativeSeiTokensERC20` contract stores `ddecimals` as an immutable field set only in the constructor and returned forever after by `decimals()` ( [5](#0-4) ).

A tokenfactory denom's admin can change that denom's bank metadata — including its decimal exponent — at any time via `MsgSetDenomMetadata`, which is admin-gated only at the tokenfactory layer, not at the EVM/pointer layer ( [6](#0-5) ). After that change, *any* unprivileged EVM account can call `addNativePointer(token)` again; because the pointer already exists, `UpsertERCPointer` will redeploy the pointer's bytecode at the same address with the new decimals baked in, while every unit of the underlying native balance in the bank module (and every already-computed on-chain value derived from the old decimals) is untouched.

This mirrors the reported bug class: a critical, balance-scaling parameter of a token (its "collateral"/decimals) is changed after the token has already been integrated by third parties (DEXs, vaults, lending markets, price oracles) that read `decimals()` once and cache it, or that compute exchange rates assuming a fixed decimals value. Changing decimals underneath live balances silently rescales the effective value represented by every unit, exactly as changing an audited protocol's "collateral" address changes the effective value of stored balances without adjusting accounting.

### Impact Explanation
Any DeFi contract (AMM pool, lending market, price oracle, wrapper) integrated with a native-token ERC20 pointer that reads `decimals()` — either at pool-creation/deployment time or cached — will silently become mispriced once the pointer is redeployed with different decimals (e.g., moving from a token with `decimals()==6` to `decimals()==18`, or vice versa). Because `balanceOf` continues to return the same raw bank-balance integer (`BankPrecompile.balance`), and only the reported decimals metadata changes, exchange-rate math done by any consumer using the two together decouples from real value by orders of magnitude, enabling fund-loss/drain scenarios in AMMs or lending platforms (e.g., under/over-collateralization, mispriced swaps) — a concrete fund-loss impact reachable purely by a normal user transaction (calling `addNativePointer` after an admin's routine `MsgSetDenomMetadata` call).

### Likelihood Explanation
Reachable with two ordinary transactions from independent, unprivileged actors: (1) the tokenfactory denom admin calling `MsgSetDenomMetadata` to alter decimals/name/symbol (a routine, permitted admin action with no restriction tied to whether an ERC20 pointer already exists for the denom), and (2) any EVM user calling `addNativePointer(token)` again, which is unauthenticated/permissionless by design. No governance, no validator collusion, and no special privilege beyond a tokenfactory denom's own admin role (an ordinary permissionless role granted to any address that created the denom) is required.

### Recommendation
Add a pointer-version/decimals-lock check to the native pointer path analogous to the `existingVersion >= currentVersion` guard already used in `RegisterPointer` for CW pointers: once a native ERC20 pointer has been created for a denom, either (a) disallow silently overwriting immutable metadata (`name`/`symbol`/`decimals`) on re-registration unless the pointer version is being intentionally upgraded via the governance-gated pointer-upgrade flow, or (b) snapshot and freeze the decimals used at first pointer creation, ignoring subsequent bank metadata changes for that pointer instance. Consider also validating/locking `DenomMetaData.Decimals` at tokenfactory denom-metadata-update time when an ERC20 pointer already exists for that denom.

### Proof of Concept
1. Attacker or normal user creates a tokenfactory denom `factory/{addr}/token` with initial `DenomMetaData` decimals = 6 (`MsgCreateDenom` + `MsgSetDenomMetadata`).
2. Any EVM user calls `addNativePointer("factory/{addr}/token")`; `PrecompileExecutor.AddNative` deploys `NativeSeiTokensERC20` with `ddecimals = 6` at address `P`.
3. A DeFi pool/vault integrates with pointer `P`, reading `decimals()==6` and computing price/exchange-rate logic on that basis, and users deposit/trade against it.
4. The denom admin calls `MsgSetDenomMetadata` again, this time submitting metadata with decimals = 18 for the same base denom (admin action, no pointer-awareness check in [6](#0-5) ).
5. Any unprivileged user calls `addNativePointer("factory/{addr}/token")` again. Because `GetERC20NativePointer` finds `P` already registered, `UpsertERCPointer` redeploys code at `P` with `ddecimals = 18` ( [7](#0-6) ), while all existing bank balances (and any pool reserves priced against `decimals()==6`) remain numerically unchanged.
6. `P.decimals()` now returns 18 while every consumer contract that cached `decimals()==6` (or hasn't re-queried) mis-prices `P`'s balance by a factor of 10^12, enabling arbitrage/drain against any integrated pool or lending market.

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}

contract NativeSeiTokensERC20 is ERC20 {

    address constant BANK_PRECOMPILE_ADDRESS = 0x0000000000000000000000000000000000001001;

    string public denom;
    string public nname;
    string public ssymbol;
    uint8 public ddecimals;
    IBank public BankPrecompile;

    constructor(string memory denom_, string memory name_, string memory symbol_, uint8 decimals_) ERC20("", "") {
        BankPrecompile = IBank(BANK_PRECOMPILE_ADDRESS);
        denom = denom_;
        nname = name_;
        ssymbol = symbol_;
        ddecimals = decimals_;
    }

    function name() public view override returns (string memory) {
        return nname;
    }

    function symbol() public view override returns (string memory) {
        return ssymbol;
    }

    function balanceOf(address account) public view override returns (uint256) {
        return BankPrecompile.balance(account, denom);
    }

    function decimals() public view override returns (uint8) {
        return ddecimals;
    }

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
