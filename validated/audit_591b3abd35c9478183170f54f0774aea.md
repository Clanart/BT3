## Analysis

The Sherlock bug is fundamentally a **"two subsystems compute the same value through different paths, and an in-protocol state change causes them to diverge, corrupting a safety-critical calculation."** Searching Cosmos EVM for an analogous dual-tracking mechanism surfaces the `BalanceHandler` in the precompile execution pipeline, which tracks EVM `StateDB` balances against native `x/bank`/`x/precisebank` ledger changes using an event-offset bookmark (`prevEventsLen`) that is shared and mutable across recursive precompile invocations — exactly the same "diverging source of truth" shape as the oracle mismatch, but with a directly Critical impact (native/EVM balance desync).

### Title
Shared `BalanceHandler` instance corrupts `prevEventsLen` bookmark during recursive/reentrant precompile calls, causing EVM `StateDB` balances to desync from native `x/bank` balances - (File: precompiles/common/balance_handler.go)

### Summary
`BalanceHandler.prevEventsLen` is a single mutable field on a `BalanceHandler` instance that is reused across all invocations of a given precompile. When a precompile call recursively/reentrantly triggers another call into the *same* precompile instance during its execution (e.g. via `CallEVMWithData` back into a contract that calls the precompile again), the inner call's `BeforeBalanceChange` overwrites `prevEventsLen`, invalidating the outer call's bookmark for `AfterBalanceChange`.

### Finding Description
`BeforeBalanceChange` records the current event count as a bookmark: [1](#0-0) 

`AfterBalanceChange` later slices `events[bh.prevEventsLen:]` to determine exactly which bank events to translate into `StateDB.AddBalance`/`SubBalance` calls: [2](#0-1) 

Because `bh` (the `*BalanceHandler`) is a single struct instance obtained via `p.GetBalanceHandler()` on the precompile receiver, and the same registered precompile instance is invoked for every call in the same or nested execution context, a recursive/reentrant call sequence produces this ordering:
1. Outer precompile call: `BeforeBalanceChange` sets `prevEventsLen = N`.
2. During outer execution, a nested/reentrant call reaches the same precompile again (demonstrated by the debug precompile's `Call0` calling back into the caller contract via `CallEVMWithData`, which itself invokes the precompile again): `BeforeBalanceChange` sets `prevEventsLen = M` (`M > N`), overwriting the outer bookmark. [3](#0-2) 
3. Inner call finishes, `AfterBalanceChange` correctly consumes `events[M:]`.
4. Outer call's `Run()` resumes and finishes; but its `AfterBalanceChange` now reads `bh.prevEventsLen`, which is still `M`, not the original `N`. Any bank events emitted between `N` and `M` (belonging to the outer call, or to a different logical scope) are permanently skipped and never mirrored to `StateDB`, while events from `M` onward may be re-applied to `StateDB` a second time. [1](#0-0) [4](#0-3) 

This is a direct analog to the oracle-mismatch bug class: the "true" value (native bank ledger, backed by escrowed/minted coins) and the "derivative" value used for further calculation (EVM `StateDB` balance, which governs all subsequent EVM-level transfers/checks in the same block/tx) are computed by two different mechanisms that are supposed to stay 1:1 synchronized, and an ordinary, unprivileged, in-protocol event (recursive precompile call) breaks that synchronization — corrupting the derived value while the underlying accounting silently diverges.

A dedicated regression test explicitly documents this class of bug and exercises it with a debug precompile and a caller contract that performs recursive calls: [5](#0-4) [6](#0-5) 

### Impact Explanation
If a production precompile that moves value (e.g. the `bank` precompile, `erc20` precompile, `distribution`/`staking` precompiles, or `werc20`) can be invoked recursively/reentrantly within a single EVM call context — either by calling back into an EVM contract that re-enters the same precompile, or via nested precompile-to-precompile calls that trigger bank events — the skipped/duplicated event window means `StateDB.AddBalance`/`SubBalance` can apply an incorrect amount relative to the actual `x/bank` coin movement. Since `StateDB` balances are what govern EVM-visible balances (used for subsequent transfers, `balanceOf` reads, and ultimately persisted back to the ledger on commit), this can result in:
- EVM-visible balance greater than the backing native coin balance (duplication of spendable value, enabling a user to spend/transfer tokens not actually backed by `x/bank`), or
- EVM-visible balance permanently lower than actual native balance (irrecoverable freezing of funds from the EVM's perspective).

Both outcomes are in-scope Critical impacts: unauthorized duplication of spendable value / permanent freezing of user funds, triggered purely by ordinary (unprivileged) contract/precompile call flow.

### Likelihood Explanation
This requires only a value-moving precompile to be reachable in a call path where the *same precompile instance* is invoked more than once within one outer `Run()` — i.e., recursion/reentrancy through the EVM's own call mechanism (a contract calling the precompile, which itself calls back into EVM code that re-invokes the precompile). No relayer, validator, or admin privilege is required; any user deploying a contract that orchestrates such a call sequence can trigger it. The repository's own test suite explicitly demonstrates this exact call pattern is reachable and produces balance-tracking irregularities, indicating high likelihood assuming a value-moving precompile is exposed with a similarly reentrant call path (this needs to be confirmed for the shipped `bank`/`erc20`/`distribution` precompiles specifically, since the demonstration uses a test-only `debug` precompile).

### Recommendation
Do not store `prevEventsLen` as instance state shared across nested/recursive invocations. Instead:
- Use a call-stack-scoped (not precompile-instance-scoped) bookmark, e.g. pass the bookmark value explicitly through the call and restore the caller's bookmark after the nested call returns (stack/LIFO semantics), or
- Create a new `BalanceHandler` per `Run()` invocation instead of reusing one bound to the precompile instance, ensuring `prevEventsLen` cannot be clobbered by a nested call using the same instance.
- Add reentrancy guards/depth tracking so `BeforeBalanceChange`/`AfterBalanceChange` pairs are correctly nested regardless of call depth.

### Proof of Concept
The repository's own test at `evmd/tests/integration/balance_handler/balance_handler_test.go` (`TestRecursivePrecompileCallsWithDebugPrecompile`) constructs exactly this scenario: it registers a `debug` precompile whose `Call0` method recursively calls back into the calling contract, which in turn calls the precompile again, sharing the single `BalanceHandler` instance and overwriting `prevEventsLen` across nested invocations, as shown in [7](#0-6)  and asserted against event counts in [8](#0-7) . To weaponize this against real funds, the same recursive pattern would need to be demonstrated against a production value-moving precompile (e.g. `bank`, `erc20`, or `werc20`) with an actual bank-balance assertion (comparing `x/bank` `GetBalance` vs. EVM `stateDB.GetBalance`) before and after the reentrant sequence, which was not directly verifiable from the indexed code alone; this should be validated with a live Devin session against the actual precompile implementations.

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case precisebanktypes.EventTypeFractionalBalanceChange:
			addr, err := ParseAddress(event, precisebanktypes.AttributeKeyAddress)
			if err != nil {
				return fmt.Errorf("failed to parse address from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}
			if bh.bankKeeper.BlockedAddr(addr) {
				// Bypass blocked addresses
				continue
			}

			delta, err := ParseFractionalAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}

			deltaAbs, err := utils.Uint256FromBigInt(new(big.Int).Abs(delta))
			if err != nil {
				return fmt.Errorf("failed to convert delta to Uint256: %w", err)
			}

			if delta.Sign() == 1 {
				stateDB.AddBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			} else if delta.Sign() == -1 {
				stateDB.SubBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			}

		default:
			continue
		}
	}

	return nil
}

func (p Precompile) Execute(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {

	case 0: // callback()
		return p.Call0(ctx, stateDB, contract, readOnly)
	case 1: // call1()
		return p.Call1(ctx, stateDB, contract, readOnly)
	}
	return nil, fmt.Errorf("unknown method: %x", contract.Input[0])
}

func (p Precompile) Call0(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {

	counter := new(big.Int).SetBytes(contract.Input[1:])
	counter = new(big.Int).Add(counter, big.NewInt(1))

	args := math.U256Bytes(counter)
	selector := []byte{0xff, 0x58, 0x5c, 0xaf}

	fmt.Println("callback response:", rsp.Ret, err)
	if err != nil {
		return nil, err
	}
	return nil, nil
}

// TestRecursivePrecompileCallsWithDebugPrecompile demonstrates the balance handler bug
// by triggering recursive calls that share the same BalanceHandler instance.
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))
	s.Require().NoError(err)

	res, _, _, err := s.chain.SendEvmTx(
		s.chain.SenderAccounts[0],
		0,             // sender index
		callerAddr,    // to address
		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier
	)
	s.Require().NoError(err, "callback transaction should succeed")
	s.Require().False(res.IsErr(), "callback should not fail: %s", res.Events)

	s.Require().Equal(len(res.Events), 15, "callback should have 15 events")
	debug_count := 0
	for _, event := range res.Events {
		if event.Type == "debug_precompile" {
			debug_count++
		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")
