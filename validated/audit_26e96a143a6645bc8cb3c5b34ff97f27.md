### Title
Forged `ReceivedOutput` (untrusted offset not bound to `script_pubkey`) poisons threshold spending — funds reported received are not spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an attacker-controlled `(offset, TxOut, OutPoint)` triple from untrusted bytes with no verification that `offset` actually maps the group key to `output.script_pubkey`. This mirrors the Grafana BOLA class: an object is referenced by an identifier (here, the scalar `offset` — the "key" authorizing spend of the output) that is never checked for ownership/consistency with the object it claims to control, so an unprivileged party can submit claims over resources they do not own.

### Finding Description
`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F` and the `TxOut`/`OutPoint` via consensus decoding, returning them unconditionally. Nowhere in `read` is the invariant checked that `p2tr_script_buf(group_key + offset * G) == output.script_pubkey`. This mirrors the Grafana BOLA class: an object is referenced by an identifier (here, the scalar `offset` — the "key" authorizing spend of the output) that is never checked for ownership/consistency with the object it claims to control, so an unprivileged party can submit claims over resources they do not own. [1](#0-0) 

The inconsistency is only detected later, in `SignableTransaction::multisig`, which returns `None` for the *entire* transaction if any single input's offset does not reproduce the prevout's script: [2](#0-1) 

Two consequences follow:

1. **Forged-ownership claims are accepted as received funds.** `SignableTransaction::new` sums `input.output.value` over all supplied `ReceivedOutput`s to decide affordability (`input_sat`) and copies attacker-chosen `TxOut`s into `prevouts`, which are committed via `Prevouts::All` in the Taproot sighash: [3](#0-2) [4](#0-3) 

2. **A single mismatched offset aborts the whole multisig.** Because `multisig` returns `None` on the first inconsistent input, one forged `ReceivedOutput` injected into the input list makes a transaction containing legitimate, spendable inputs unsignable — the wallet reports funds received that cannot be spent through this machine.

### Impact Explanation
An unprivileged party who can feed serialized `ReceivedOutput` bytes into a wallet/processor pipeline (the format is explicitly designed to cross trust boundaries via `read`/`write`) can either inflate the reported received balance with outputs nobody can spend, or permanently abort signing for a batch of inputs by supplying an `offset` that does not match the output's script. The sighash over `Prevouts::All` also commits to attacker-chosen prevout amounts, so any signature produced over mismatched data is invalid on-chain, wasting a full FROST signing round (consumed nonces, coordinator round-trip) before failing.

### Likelihood Explanation
**Medium.** `ReceivedOutput` is a wire/storage format consumed via `read`; nothing in the API forces callers to obtain it only from `Scanner::scan_transaction`. Any path where these bytes come from a peer, queue, or untrusted store is exploitable with trivial effort (no cryptographic break needed — just inconsistent fields). The damage is bounded to fund-reporting integrity and signing availability, not key recovery, matching a Medium severity.

### Recommendation
Either verify consistency at deserialization — have `read` take the group key and reject outputs where `p2tr_script_buf(key + offset * G) != output.script_pubkey` — or move the check into `SignableTransaction::new` so forged inputs are rejected individually at construction time rather than silently counted toward `input_sat` and aborting `multisig` for the entire batch. Document that `prevouts` values must be sourced from chain-verified `TxOut`s.

### Proof of Concept
```rust
use blackvul_serai_bitcoin::wallet::{ReceivedOutput, SignableTransaction};
use k256::{Scalar, ProjectivePoint};
use bitcoin::{OutPoint, TxOut, Amount, ScriptBuf, Txid, hashes::Hash};

// Honest scanner produced `honest: ReceivedOutput` for key K with offset o.
// Attacker injects a forged ReceivedOutput claiming ownership of someone
// else's output (or a fabricated prevout value):
let forged_bytes = {
    let mut v = Vec::new();
    // offset that does NOT map K to the script_pubkey below
    v.extend((Scalar::from(0xdeadbeefu64)).to_bytes());
    v.extend(bitcoin::consensus::encode::serialize(&TxOut {
        value: Amount::from_sat(1_000_000_000), // fabricated 10 BTC
        script_pubkey: ScriptBuf::new_p2tr_tweaked(
            bitcoin::key::TweakedPublicKey::dangerous_assume_tweaked(
                bitcoin::key::XOnlyPublicKey::from_slice(&[0x42; 32]).unwrap(),
            ),
        ),
    }));
    v.extend(bitcoin::consensus::encode::serialize(&OutPoint {
        txid: Txid::all_zeros(), vout: 0,
    }));
    v
};

// Wallet deserializes attacker bytes: no offset<->script check occurs.
let forged = ReceivedOutput::read(&mut &forged_bytes[..]).unwrap();

// input_sat is inflated by the fabricated value; multisig() returns None for
// the whole transaction, so even the honest input cannot be spent.
let tx = SignableTransaction::new(vec![honest, forged], &payments, change, None, 1)?;
assert!(tx.multisig(&keys).is_none()); // entire spend aborted by one forged claim
```
