### Title
Attacker-crafted Payout transaction attributes an arbitrary, non-participating operator via a spoofable OP_RETURN, allowing that operator to claim a Citrea withdrawal it never funded - ([File: core/src/verifier.rs])

### Summary
`Operator::withdraw` is the only code path that ties a Payout transaction to a specific operator's own signing/funding flow, but nothing in that transaction's Bitcoin encoding is cryptographically bound to that call. Because the withdrawal's authorizing signature uses `SIGHASH_SINGLE|ANYONECANPAY`, it commits only to the input UTXO and the user's output — not to the OP_RETURN output that names the "paying" operator — so any party who controls the withdrawal-registration key (the withdrawing user themself, per the attacker capability list) can build and broadcast their own Payout-shaped transaction, attribute the OP_RETURN to any operator O, and have `update_finalized_payouts`/`get_payout_txs_for_withdrawal_utxos` bind O to that withdrawal without O ever invoking `create_payout_txhandler`.

### Finding Description
Binding claimed: `payout_payer_operator_xonly_pk` written for withdrawal `i` (read later by `Verifier::is_kickoff_malicious` and by `PayoutCheckerTask::get_first_unhandled_payout_by_operator_xonly_pk`) == the operator that actually called `Operator::withdraw`/produced `create_payout_txhandler` for that withdrawal.

Trace:
- `Operator::withdraw` (`core/src/operator.rs:560-637`) checks `withdrawal_utxo != input_utxo.outpoint` and verifies the user's Schnorr signature over `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)` — but the parser (`core/src/rpc/parser/operator.rs:161-203`) enforces `sighash_type == SinglePlusAnyoneCanPay`.
- `SinglePlusAnyoneCanPay` restricts the taproot key-spend sighash to `Prevouts::One(txin_index, ...)` and, per `SIGHASH_SINGLE` semantics, only the output at the same index as the signed input is committed (the user payout output, output 0). `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) appends an anchor output and an OP_RETURN with `operator_xonly_pk` *after* the signed output — these are **not covered by the signature**.
- The input UTXO itself is a small "dust" UTXO owned and signed by the withdrawing user (see `generate_withdrawal_utxo`/`sign_withdrawal_output`, `core/src/test/common/setup_utils.rs:430-543`), not an operator-controlled UTXO; the operator only contributes additional funding inputs via `fund_raw_transaction` at broadcast time (`core/src/operator.rs:639-674`).
- Consequently, the withdrawing user (an unprivileged attacker per the rules — they may call Citrea's `withdraw` and choose the UTXO/signature bytes) can independently construct a transaction spending their own dust UTXO with their own valid `SinglePlusAnyoneCanPay` signature, fund any remaining value themselves, and attach an OP_RETURN naming an arbitrary operator O's `xonly_pk` — without ever calling any operator's `internal_withdraw`/`withdraw` RPC.
- `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2352`) discovers this transaction purely via `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`), which matches solely on the spent outpoint (`bsu.txid`/`bsu.vout` = the registered withdrawal UTXO), then blindly parses whichever OP_RETURN is present and writes it as `payout_payer_operator_xonly_pk` with no signature or authorization check tying it to O.
- `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`) and O's own `PayoutCheckerTask` (`core/src/task/payout_checker.rs:31-111`, keyed by `self.operator.signer.xonly_public_key`) subsequently trust this DB attribution unconditionally: they check only that `operator_xonly_pk == kickoff_data.operator_xonly_pk` and that the committed payout blockhash matches — never checking who signed/funded the payout, and never checking the payout output's value against the withdrawal amount registered on Citrea (confirmed absent in `circuits-lib/src/bridge_circuit/mod.rs` and `storage_proof.rs`, which only assert outpoint/vout equality, never amount).
- `core/src/tx_sender_queue.rs:92-105` further shows the txsender treats `Payout` and `Challenge` identically (`FeePayingType::RBF`, no outpoint dependencies), so there is no queue-level linkage forcing a Payout tx to originate from a specific operator's signing session either.

Exploit flow: attacker registers a Citrea withdrawal (index i, dust UTXO U, target address), signs U with `SinglePlusAnyoneCanPay` for a (possibly minimal) output amount, funds the remaining value themselves, appends OP_RETURN = O's `xonly_pk` (any currently active operator, chosen adversarially), and broadcasts directly to Bitcoin. Once finalized, the verifier's chain scan attributes the payout to O. O's own automation (`PayoutCheckerTask`) then treats withdrawal i as self-funded, proceeds to `handle_finalized_payout`, sends a `Kickoff`, and — since no amount check exists anywhere in `is_kickoff_malicious` or the bridge circuit — is treated as non-malicious and eligible for the full `bridge_amount` `Reimburse`, regardless of how little the attacker actually paid the withdrawing address.

### Impact Explanation
This breaks "an operator reimbursed for a payout it never funded" (Critical) and, because the bridge circuit/`is_kickoff_malicious` never validate the payout output's amount against the Citrea-registered withdrawal amount, it also enables "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal" (Critical): the attacker can pay an arbitrary (even near-zero) amount to the withdrawal destination while still causing an uninvolved operator O to become eligible to claim the full `bridge_amount` reimbursement from the vault. The attack is repeatable across every withdrawal index and every operator xonly pubkey (public, fetchable via `fetch_operator_keys`), and requires no operator, verifier, or aggregator collusion — only the attacker's own withdrawal-registration key.

### Likelihood Explanation
No special privileges are required beyond what any Citrea withdrawal-initiating user already has: the ability to sign their own dust UTXO with `SinglePlusAnyoneCanPay`, fund the rest of the transaction with their own BTC, and broadcast directly to the network. Operator xonly pubkeys are public. Attacker cost is limited to on-chain fees plus whatever (arbitrarily small) amount they choose to send to the withdrawal destination. This is deployable on any regtest/testnet/mainnet deployment of this exact code without needing majority hashrate, key compromise, or social engineering.

### Recommendation
Bind the OP_RETURN operator attribution to the actual signing/funding party, e.g. by requiring the OP_RETURN output to also be covered by the withdrawal signature (use a sighash type that commits to all outputs, or add a second signature/commitment from the operator over the full transaction including OP_RETURN), and additionally enforce that the payout output amount matches (within tolerance) the withdrawal amount registered on Citrea before crediting any operator in `update_finalized_payouts`/`is_kickoff_malicious`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

fn sign_withdrawal_output(
    config: &BridgeConfig,
    dust_utxo: &UTXO,
    withdrawal_address: &bitcoin::Address,
    withdrawal_amount: bitcoin::Amount,
) -> (bitcoin::TxOut, taproot::Signature) {
    let signer = Actor::new(config.secret_key, config.protocol_paramset().network);
    let txin = builder::transaction::input::SpendableTxIn::new(
        dust_utxo.outpoint,
        dust_utxo.txout.clone(),
        vec![],
        None,
    );
    let txout = bitcoin::TxOut {
        value: withdrawal_amount,
        script_pubkey: withdrawal_address.script_pubkey(),
    };
    let unspent_txout = builder::transaction::output::UnspentTxOut::from_partial(txout.clone());

    let tx = builder::transaction::TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            builder::transaction::DEFAULT_SEQUENCE,
        )
        .add_output(unspent_txout.clone())
        .finalize();

    let sighash = tx
        .calculate_sighash_txin(0, sighash::TapSighashType::SinglePlusAnyoneCanPay)
        .expect("Failed to calculate sighash");

    let sig = signer
        .sign_with_tweak_data(sighash, builder::sighash::TapTweakData::KeyPath(None), None)
        .expect("Failed to sign");

    let sig = taproot::Signature {
        signature: sig,
        sighash_type: sighash::TapSighashType::SinglePlusAnyoneCanPay,
    };

    (txout, sig)
}

            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,

            self.config.protocol_paramset(),

                return Ok(true);
            }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,

            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {

                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];

            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());

                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk

                idx,
                payout_txid,

                block_hash,
            ));

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}
