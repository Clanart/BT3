### Title
`get_first_op_return_output` lets any output that spends the withdrawal UTXO decide reimbursement credit, decoupling `payout_payer_operator_xonly_pk` from the party that actually funded the payout - ([File: core/src/verifier.rs -> fn update_finalized_payouts]; also `core/src/builder/transaction/operator_reimburse.rs -> fn create_payout_txhandler`)

### Summary
The Payout transaction's user authorization uses `SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0 [1](#0-0) . Nothing constrains the number, order, or content of any outputs beyond index 0, so any party who observes the signed input (in the mempool or via `withdraw`/`internal_withdraw` gRPC responses) can build a completely different transaction that still satisfies that signature, spends the same withdrawal UTXO, and carries an attacker-chosen OP_RETURN at any position. `update_finalized_payouts` blindly trusts `get_first_op_return_output` on whatever transaction actually spent the withdrawal UTXO on-chain to determine `payout_payer_operator_xonly_pk`, with no check that this transaction has the exact 3-output shape (`payout`, `anchor`, `OP_RETURN`) produced by `create_payout_txhandler`.

### Finding Description
The binding that must hold is:
`payout_payer_operator_xonly_pk(withdrawal_i)` (recorded in DB by `update_finalized_payouts`) `== operator who actually funded output 0 of the tx that spent withdrawal_utxo_i`.

`create_payout_txhandler` builds the payout tx with a fixed 3-output layout: `[output_txout, anchor_output, op_return_txout(operator_xonly_pk)]` [2](#0-1) . The user's signature is verified with `SECP.verify_schnorr` against the sighash of *this specific, operator-constructed* transaction in `Operator::withdraw` [3](#0-2) . Because the sighash type is `SinglePlusAnyoneCanPay` (enforced in `parse_withdrawal_sig_params`) [4](#0-3) , the resulting witness signature over input 0 commits **only** to input 0 and to the single output at index 0 — it says nothing about outputs 1..N. The operator then funds the transaction further via `rpc.fund_raw_transaction(add_inputs: true, ...)` [5](#0-4) , broadcasting a transaction whose non-index-0 inputs/outputs are entirely unauthenticated by the user.

An unprivileged attacker who observes the broadcast payout transaction (public mempool, or via the `withdraw`/`internal_withdraw` RPC response containing `RawSignedTx`) can extract the witness for input 0 and construct an alternative transaction: same input 0 (same prevout, satisfying the signature), identical output 0 (script+amount, required to match the SIGHASH_SINGLE binding), but with their own fee-paying input(s) and an arbitrary OP_RETURN output carrying any operator's x-only pubkey (including a legitimate registered operator who did not fund this withdrawal). If this attacker-shaped variant is the one that confirms on-chain (paying a competitive/RBF fee), `get_payout_txs_for_withdrawal_utxos` finds it purely by "who spent `withdrawal_utxo`" (no content check) [6](#0-5) , and `update_finalized_payouts` calls `get_first_op_return_output`, which returns the **first** OP_RETURN output regardless of index or transaction shape [7](#0-6) , feeding it into `parse_op_return_data` to set `payout_payer_operator_xonly_pk` in the DB [8](#0-7) .

This DB value is then trusted, without re-derivation from the true funder, by:
- `PayoutCheckerTask` via `get_first_unhandled_payout_by_operator_xonly_pk`, which picks up the framed operator's "own" payout and drives it through `handle_finalized_payout` [9](#0-8) .
- `is_kickoff_malicious`, whose sole check is `operator_xonly_pk != kickoff_data.operator_xonly_pk` read from this same DB column [10](#0-9)  — it never checks that the framed operator's own funds paid output 0.
- `send_asserts`, whose only validation is `payout_op_xonly_pk != kickoff_data.operator_xonly_pk` [11](#0-10)  — again comparing DB value to itself, not to actual funding.

None of `Verifier::is_deposit_valid`, `verify_storage_proofs`, `SPV::verify`, or `lc_proof_verifier` re-derive who funded output 0; they operate on citrea-side data or on whatever transaction is presented as `payout_spv.transaction`, which is exactly the attacker-malleated transaction once it is confirmed and SPV-provable. The bridge circuit itself uses the identical unconstrained `get_first_op_return_output`/`parse_op_return_data` pair to bind `operator_xonlypk` into `deposit_constant` [12](#0-11) , so the same forged attribution propagates all the way into the on-chain-verifiable disprove/assert path.

### Impact Explanation
A registered operator can be credited (in the verifier/operator DB, and ultimately via the `is_kickoff_malicious` gate and the bridge circuit's `deposit_constant`) as the payer of a withdrawal it never funded, while the withdrawal's output 0 is actually paid by unrelated funds (the attacker's own added input). That operator can then legitimately proceed through Kickoff → Assert/Disprove → Reimburse and pull `bridge_amount` out of the move-to-vault UTXO to its own `operator_reimbursement_address`, having fronted nothing. This is "an operator reimbursed for a payout it never funded," an explicitly listed Critical impact, and it decouples BTC leaving the move-to-vault UTXO from any real corresponding fronted payment by that operator. The attack is repeatable per withdrawal/deposit and requires no operator, verifier, or aggregator privilege — only observation of a broadcast payout transaction and the ability to submit a competing/replacing Bitcoin transaction.

### Likelihood Explanation
Preconditions: the attacker must be able to see a payout transaction's signed input-0 witness before it is buried (mempool visibility, or the `RawSignedTx` returned by `withdraw`/`internal_withdraw`), and must get an alternative transaction spending the same withdrawal UTXO confirmed instead of (or racing) the operator's own broadcast — a normal transaction-replacement/RBF-pinning capability requiring only fee-paying BTC, well within the stated attacker capabilities. No majority hashrate, key compromise, or privileged role is required.

### Recommendation
Do not trust `get_first_op_return_output` on an arbitrary on-chain transaction that merely spends the withdrawal UTXO. Either (a) require and check that the confirmed payout transaction has exactly the canonical 3-output shape produced by `create_payout_txhandler` (output0=payout, output1=anchor, output2=OP_RETURN) before accepting the OP_RETURN as authoritative, or (b) bind the operator's identity into something the user's `SinglePlusAnyoneCanPay` signature *does* cover (e.g., require `SIGHASH_ALL` for a template that includes the OP_RETURN, or otherwise cryptographically tie output-0 funding to the OP_RETURN operator key), so that the recorded payer can only be the entity whose funds actually satisfied output 0.

//    parse_op_return_data on the result; assert the returned pk == OP_B, not OP_A,
//    even though OP_A/no one funded output0's origin as intended, demonstrating
//    operator_xonly_pk_recorded != party whose funds actually satisfied output0.

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    /// Returns the withdrawal indexes and their spending txid for the given

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
