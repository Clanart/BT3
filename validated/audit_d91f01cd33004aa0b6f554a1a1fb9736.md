### Title
Unchecked type assertion on CW20/CW721/CW1155 query response causes panic in `pointer` precompile - (File: precompiles/pointer/pointer.go)

### Summary
`precompiles/pointer/pointer.go` implements the `pointer` precompile that lets any EVM caller register an ERC20/ERC721/ERC1155 "pointer" contract for an existing CosmWasm CW20/CW721/CW1155 contract. `AddCW20`, `AddCW721`, and `AddCW1155` each query the target CW contract, unmarshal the JSON response into a `map[string]interface{}`, and then extract `name`/`symbol` with unchecked, non-comma-ok type assertions: `formattedRes["name"].(string)`.

### Finding Description
In `AddCW20`:
```go
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
``` [1](#0-0) 

The same pattern repeats in `AddCW721` and `AddCW1155`: [2](#0-1) [3](#0-2) 

If the `token_info`/`contract_info` query response from the target CW contract does not contain a `"name"` or `"symbol"` key as a JSON string (e.g., the key is absent, is `null`, or the value is a number/object), `formattedRes["name"]` evaluates to `nil` (an `interface{}` holding no concrete type) or a non-string type. The single-value type assertion `.(string)` on such a value panics at runtime with `interface conversion: interface {} is nil, not string` (or the equivalent for a wrong concrete type). This is structurally the same defect class as the reported GStreamer CVE: a value that is expected to be present/non-nil is dereferenced/converted without validation, producing a crash instead of a graceful error.

The CW contract targeted by `AddCW20Pointer`/`AddCW721Pointer`/`AddCW1155Pointer` is fully attacker-controlled: any address can deploy a CW20/CW721/CW1155-labeled contract (or any contract answering the `token_info`/`contract_info` query) that returns a JSON object omitting `name`/`symbol` or setting them to `null`/non-string types, and then call the `pointer` precompile (`0x000000000000000000000000000000000000100b`) with that contract's bech32 address as `args[0]`.

### Impact Explanation
The `pointer` precompile is reachable by any unprivileged EVM transaction sender or contract via a direct call to the precompile address. A crafted CW contract that returns a malformed `token_info`/`contract_info` response (missing/non-string `name` or `symbol`) will cause a Go panic during EVM execution of that transaction. Whether this panic is caught depends on whether panic-recovery wraps precompile execution in `RunAndCalculateGas` (`precompiles/common/precompiles.go`); no `recover()` call was found in `precompiles/common/precompiles.go` for this dynamic-gas execution path in the parts examined, meaning the panic could propagate up through the EVM message execution. If it is not recovered at a sufficiently high layer, it can crash the block-processing goroutine for that node/validator when processing the transaction, resulting in a validator halt / node crash — a High-severity availability issue for a permissionless, transaction-triggered code path. Even if a higher-level recover exists elsewhere in the ante/msg-service pipeline, this is still an unhandled-error/incorrect-type-assertion bug that turns a routine "malformed remote data" case into a runtime panic rather than a clean revert, differing from Cosmos SDK/EVM's expected transaction-revert semantics.

### Likelihood Explanation
High likelihood: no privileges are required. An attacker only needs to (1) instantiate a CosmWasm contract that answers `token_info` (for CW20) or `contract_info` (for CW721/CW1155) queries with a JSON body lacking string `name`/`symbol` fields, and (2) call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the `pointer` precompile with that contract's address. This requires only a CosmWasm deploy (universally permissioned in sei-chain) and a single EVM transaction.

### Recommendation
Replace the unchecked type assertions with comma-ok checks and return an error (not panic) when the expected fields are missing or not strings, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid token_info response: missing or non-string 'name'")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid token_info response: missing or non-string 'symbol'")
}
```
Apply this fix to all three call sites (`AddCW20`, `AddCW721`, `AddCW1155`) in `precompiles/pointer/pointer.go`, and audit the legacy versioned copies (`precompiles/pointer/legacy/v6xx/pointer.go`, etc.) for the same pattern, since they mirror the same unsafe assertions.

### Proof of Concept
1. Deploy a CosmWasm contract `C` whose `QuerySmart` handler responds to `{"token_info":{}}` with a JSON object that omits `name`/`symbol` (or sets them to `null`), e.g. `{"decimals":6,"total_supply":"0"}`.
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b`, method `addCW20Pointer(string cwAddr)`, passing `C`'s bech32 address.
3. Execution reaches: [4](#0-3) 
`formattedRes["name"]` is `nil`; `.(string)` panics, crashing the goroutine handling this transaction if not recovered above this call stack.
