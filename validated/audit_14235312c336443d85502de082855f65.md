### Title
Attacker-Controlled Git Host Response Header Poisons the "Is This GitHub" Trust Decision Used to Route Credentials/OAuth - (File: app/src/lib/api.ts)

### Summary
GitHub Desktop's credential helper must decide, for every HTTPS host Git talks to, whether that host is a trusted GitHub endpoint (in which case Desktop's own stored token / the OAuth "sign in to GitHub" flow is used) or an untrusted "generic" host (in which case a plain username/password dialog or external credential manager is used). This decision is derived from data the remote server itself controls — HTTP response headers — and, once made, is cached indefinitely and reused for future validations without re-verification, exactly the "value bearing/validation decision based on externally influenced state that can change or be spoofed independently" pattern described in the EIP-4337 report.

### Finding Description
`getEndpointKind` in [2](#0-1)  classifies a credential-helper request as `'generic'`, `'github.com'`, `'ghe.com'`, or `'enterprise'`. Two of the signals it trusts are fully attacker-controlled:

1. The `WWW-Authenticate` header realm captured by Git and forwarded to the helper as a `wwwauth[...]` credential field — any HTTPS server can send `WWW-Authenticate: Basic realm="GitHub"` and be classified `'enterprise'`: [3](#0-2) 

2. `isGitHubHost`, which performs a `HEAD /meta` probe and treats the presence of an `x-github-request-id` response header (trivially spoofable, since the attacker's own server sets its own headers) as proof of being a GitHub host: [4](#0-3) 

Crucially, this same function also unconditionally caches any `x-github-enterprise-version` header from that same attacker-controlled response into `localStorage` via `updateEndpointVersion`: [1](#0-0) 

On every *subsequent* call to `isGitHubHost` for that endpoint, the cached version short-circuits the check and returns `true` without ever re-contacting the server or checking `x-github-request-id` again: [5](#0-4) 

This is the TOCTOU-style flaw: the "is this GitHub" validation is performed once, its (attacker-supplied) result is persisted as ground truth, and all later validations for the same host skip the check entirely — the invariant "only genuine GitHub/GHE hosts are treated as GitHub" is broken by a single spoofed response, and there is no mechanism that revalidates or invalidates the cached classification later.

### Impact Explanation
An attacker who controls a git remote/proxy that a user clones or fetches from (e.g., a malicious repository whose `.gitmodules` points a submodule to `https://evil.example.com`, or a malicious main remote) can make Desktop misclassify that host as `'enterprise'` instead of `'generic'`. Per `getCredential` in the same file: [6](#0-5) 
this changes credential handling: no generic username/password dialog or external Git Credential Manager is used, and instead the "Sign in to GitHub Enterprise" flow (`promptForGitHubSignIn` → `beginEnterpriseSignIn` + browser-based OAuth) is triggered against the attacker's endpoint: [7](#0-6) 
This causes GitHub Desktop to present what looks like a legitimate first-party "Sign in with GitHub" UI for an attacker-chosen host, and — separately — `storeCredential`/`eraseCredential` silently refuse to persist or clear credentials for a host the user believes is generic, corrupting expected credential-storage behavior for the true site the user intended to authenticate with.

### Likelihood Explanation
Triggering the misclassification requires nothing beyond running an HTTPS server that returns a crafted header — no local access, no admin rights, no pre-existing malware, and no credential leakage is needed to set it up. The only user action required is cloning/fetching a repository containing a submodule/remote pointing at the attacker's host, which is squarely within "attacker controls a cloned/fetched repository" / "git remote/proxy response" as an in-scope primitive. However, the ultimate payoff (an OAuth sign-in attempt against the attacker's endpoint) still requires the user to proceed through the sign-in dialog, which limits severity somewhat.

### Recommendation
Do not trust unauthenticated response headers (`WWW-Authenticate` realm text, `x-github-request-id`, `x-github-enterprise-version`) as sole proof of GitHub/GHE identity. At minimum:
- Stop persisting `x-github-enterprise-version` (or any classification) from hosts that haven't been explicitly registered as GHE endpoints by the user via the sign-in flow.
- Re-validate `isGitHubHost` on a cadence or bind the cached result to a host that has an actual registered `Account`, rather than trusting the network probe indefinitely.
- Treat the `wwwauth[]` realm heuristic as advisory only, not sufficient on its own to move a host out of the `'generic'` bucket.

### Proof of Concept
1. Attacker sets up `https://evil.example.com` and configures it to respond to any request with `WWW-Authenticate: Basic realm="GitHub"` on a 401, and/or serve a `HEAD /meta` response containing header `x-github-request-id: 1234` and `x-github-enterprise-version: 3.9.0`.
2. Attacker publishes a repository with `.gitmodules` containing `url = https://evil.example.com/foo.git` (or simply hosts a plain remote there).
3. Victim clones/fetches the repository in GitHub Desktop; Git contacts `evil.example.com`, gets a 401 with the crafted `WWW-Authenticate` header (or Desktop's own `isGitHubHost` probe hits `/meta` and caches the spoofed enterprise version).
4. `getEndpointKind` returns `'enterprise'` for `evil.example.com` — [8](#0-7)  — and Desktop shows a "Sign in to GitHub Enterprise" dialog pointed at `evil.example.com` instead of a generic credential prompt.
5. All later credential-helper calls for `evil.example.com` short-circuit through the cached `getEndpointVersion` in `localStorage`, permanently treating the attacker host as GitHub without re-checking anything — [5](#0-4) .

export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
