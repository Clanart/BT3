This confirms the exploitable path: `purchase()` is fully permissionless with an arbitrary `app` byte-string, and the pallet's `push_subscription` evicts strictly by FIFO position, not by value or ownership.

### Title
Unprivileged FIFO-eviction griefing destroys a victim app's prepaid bandwidth — permanent loss of paid-for allowance (`File: modules/pallets/bandwidth/src/lib.rs`)

### Summary
`BandwidthManager.purchase()` on any registered EVM source chain lets **any caller** credit bandwidth to **any `(chain, app)` pair** they choose — `app` is attacker-supplied calldata with no ownership check [1](#0-0) . On the pallet side, `push_subscription` appends every purchase to a `BoundedVec` capped at `MAX_SUBSCRIPTIONS` (1024) and evicts strictly the **oldest** entry once full, regardless of who paid for it or how much of it is unused [2](#0-1) . This is the same broken-invariant class as the Ajna report: an unprivileged actor can cheaply and repeatedly trigger a state-mutating action that has no protection against griefing another party's economically meaningful, already-paid-for position, with no reset/undo mechanism.

### Finding Description
`Allowance` is keyed by `(app_chain, app)`, and `app_chain`/`app` come entirely from attacker-controlled purchase message fields, not from `request.source` or `msg.sender` [3](#0-2) . Anyone can call `purchase()` targeting a victim's `app` identifier by simply passing the victim's app bytes as the `app` parameter — there's no binding between `msg.sender` and the `app` being credited [4](#0-3) .

The eviction logic in `push_subscription` is a pure FIFO: when the list length equals `MAX_SUBSCRIPTIONS`, `list.remove(0)` unconditionally evicts the single oldest subscription, independent of its remaining bytes, tier value, or who paid for it:

```rust
let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
    let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
        Some(list.remove(0))
    } else {
        None
    };
    let _ = list.try_push(new_sub);
    evicted
});
``` [5](#0-4) 

An attacker can therefore:
1. Buy the cheapest configured tier (e.g. `TierOne`, months=1) 1024 times, targeting the victim's exact `app` bytes on the victim's `app_chain`.
2. Each purchase is a legitimate, protocol-accepted credit — `on_accept` has no rate limit, no minimum-value floor, and no check that the caller is the app's operator [6](#0-5) .
3. Once the victim's `(app_chain, app)` list reaches 1024 entries, every subsequent attacker purchase evicts the oldest surviving entry — which will eventually be the victim's own large, high-value, still-unconsumed subscription — emitting `SubscriptionEvicted` with the victim's lost bytes [7](#0-6) .

The existing guard rails do not stop this: the "no mutation on insufficient" property protects the *consuming* gate path, but there is no analogous protection for the *credit* path against griefing by a non-owner. The docs even acknowledge the mechanism exists ("pushing onto a full list evicts the oldest entry") but frame it purely as a "pathological repeat-buy" edge case by the app's own owner, not as an attack surface open to any third party [8](#0-7) .

### Impact Explanation
This directly causes **loss of funds already paid**: a victim app that legitimately purchased a large/expensive tier (e.g. the $1000 8MB/30-day tier) can have that paid-for allowance evicted and destroyed by an attacker who only needs to buy 1024 units of the cheapest tier ($50/100KB) targeting the victim's identifier — a cost asymmetry that makes griefing cheap relative to the damage inflicted. Once evicted, the bandwidth is unrecoverable except via a privileged `force_credit` from governance [9](#0-8) . This also produces denial of service: the victim app's messages are rejected by `BandwidthGate::try_consume` once its allowance is drained via eviction rather than legitimate consumption [10](#0-9) , satisfying the "logic attack" / "loss of funds" impact categories in scope.

### Likelihood Explanation
High. The attack requires no special privileges, no relayer/prover/admin collusion, and no front-running — only the ability to call the public `purchase()` function 1024 times with attacker-chosen `app` bytes matching the victim's identifier, paid entirely in the attacker's own funds at the cheapest configured tier. This is a fully public entry point reachable by any unprivileged EVM account.

### Recommendation
- Bind `Allowance` credits to a verified app-owner registration rather than accepting an arbitrary `app` byte-string from any payer, or require the purchaser to prove authorization for the target `app`.
- Change eviction policy to evict by remaining-value or protect large/high-value subscriptions from eviction by lower-value ones (e.g., evict smallest-remaining-bytes entry first, or increase `MAX_SUBSCRIPTIONS` dynamically / merge same-tier entries instead of queuing unboundedly).
- Add a minimum per-purchase value floor or per-source-account rate limiting on credits to a given `(chain, app)` to make griefing economically infeasible.
- Emit a way for the affected app owner to reclaim or dispute an unauthorized credit before it can evict legitimate high-value subscriptions.

		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(

			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,

			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

					Some(list.remove(0))

					None
				};

					app: app.clone(),

					lost_bytes: old.remaining_bytes,
				});

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
