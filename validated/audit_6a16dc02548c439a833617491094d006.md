### Title
Missing uniqueness enforcement on `withdrawal_utxo` binding allows one physical payout to be credited to two withdrawal indices/deposits - ([File: core/src/database/verifier.rs])

### Summary
`update_withdrawal_utxo_from_citrea_withdrawal` writes an attacker-controlled `withdrawal_utxo` `OutPoint` into the `withdrawals` table keyed only by `idx`, with no check that the outpoint is not already bound to a different `idx`. Because `get_payout_txs_for_withdrawal_utxos` joins on the `(withdrawal_utxo_txid, withdrawal_utxo_vout)` columns rather than a 1:1 idx-to-spend mapping, one physical Bitcoin payout transaction spending a shared outpoint can be matched to multiple withdrawal rows/deposits, allowing an operator's single real payment to be credited as fulfillment for more than one deposit's reimbursement flow.

### Finding Description
The broken binding: `withdrawals.idx == withdrawal_utxo` should be an injective mapping (one Bitcoin outpoint used for at most one withdrawal index, ever). This is never enforced.

- `Verifier::update_citrea_deposit_and_withdrawals` (`core/src/verifier.rs:2248-2262`) iterates results from `collect_withdrawal_utxos` (`core/src/citrea.rs:458-496`), which simply reads the Citrea Bridge contract's `withdrawalUTXOs(idx)` mapping. The `withdraw()` call on the Citrea Bridge contract lets an unprivileged caller choose the `(txId, outputId)` bytes freely for each sequential withdrawal index it creates - nothing prevents the same bytes being submitted for two different indices `N` and `M`.
- `update_withdrawal_utxo_from_citrea_withdrawal` (`core/src/database/verifier.rs:108-135`) performs a blind `UPDATE withdrawals SET withdrawal_utxo_txid=…, withdrawal_utxo_vout=… WHERE idx=$1`, with no `SELECT`/uniqueness check against other rows and no DB `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`.
- Later, `update_finalized_payouts` calls `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`), which is a `JOIN` on `withdrawals w ... ON bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout`. If rows for idx `N` and idx `M` share the identical outpoint, and that outpoint is spent by one physical payout transaction, the join returns **two** rows: `(N, payout_txid)` and `(M, payout_txid)`.
- `update_payout_txs_and_payer_operator_xonly_pk` is then called with both `(N, payout_txid, operator_pk, block_hash)` and `(M, payout_txid, operator_pk, block_hash)`, writing the same operator's payer identity and the same payout/block info into **both** withdrawal rows, even though the operator only made one real BTC payment.
- Downstream, `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:31-111`) repeatedly calls `get_first_unhandled_payout_by_operator_xonly_pk`, which will surface both `N` and `M` as separate "unhandled payouts" for the same operator, each triggering `Operator::handle_finalized_payout` and a full kickoff for each deposit's move-to-vault. `is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`) validates the kickoff by checking `get_payout_info_from_move_txid(move_txid)` per deposit (keyed by each deposit's distinct `move_to_vault_txid`), so it independently finds a "valid" `payout_txid`/`operator_xonly_pk`/blockhash for *both* deposit N and deposit M - because both rows were populated with the same (single, real) payout evidence. The check has no way to detect that the underlying physical payout only happened once.

### Impact Explanation
This lets a single physical operator payment satisfy the payout-verification bar for two (or more) distinct deposits' Reimburse flows. Each deposit's Reimburse tx spends bridge/round collateral tied to *that specific* deposit's move-to-vault BTC. If the operator gets reimbursed for both N and M using one real payment, the collateral/vault path for the "extra" deposit is drained without a matching fronted withdrawal for that depositor - i.e., BTC leaves a move-to-vault UTXO via Reimburse without a corresponding real withdrawal payout having been made for that specific deposit. This matches the Critical category "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal" / "an operator reimbursed for a payout it never funded." The attack is repeatable across any number of withdrawal indices the attacker chooses to alias to the same outpoint, and across any operator who processes the aliased withdrawal (no operator complicity required - the double-crediting happens purely from the automated `update_finalized_payouts` / `PayoutCheckerTask` logic).

### Likelihood Explanation
The attacker only needs: (1) an outpoint they control the private key for (any BTC UTXO, standard taproot, used purely as the withdrawal "handle" per `sign_optimistic_payout`/`withdraw` checks), and (2) the ability to call `withdraw()` on the Citrea Bridge contract twice with the same `(txId, outputId)` bytes for two different withdrawal indices - both of which are explicitly permitted to an unprivileged caller per the threat model. No verifier/operator/aggregator privilege, no key compromise, and no majority hashrate are needed. The only requirement is that an operator eventually processes the withdrawal (pays it out once) - a normal operation the automation performs regardless of the aliasing. Feasibility is high and reproducible in a `cargo test` using two DB rows with an identical outpoint plus one `insert_spent_utxo` record.

### Recommendation
Enforce uniqueness of the withdrawal-utxo binding: add a partial `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table (where non-null), and make `update_withdrawal_utxo_from_citrea_withdrawal` reject/alert if the outpoint is already bound to a different `idx`. Additionally, `get_payout_txs_for_withdrawal_utxos` and `update_payout_txs_and_payer_operator_xonly_pk` should be changed so that a given payout `Txid`/outpoint can only ever satisfy exactly one withdrawal `idx` (e.g., by tracking "already consumed" outpoints/payout txids and refusing to assign the same payout evidence to a second `idx`), and `is_kickoff_malicious`/`send_asserts` should independently confirm that the specific outpoint spent by the payout transaction was uniquely reserved for that deposit's withdrawal index before accepting it as valid payout proof.

async fn double_bind_withdrawal_utxo_to_two_indices() {
    let config = create_test_config_with_thread_name().await;
    let db = Database::new(&config).await.unwrap();
    let mut dbtx = db.begin_transaction().await.unwrap();

    let shared_utxo = bitcoin::OutPoint {
        txid: bitcoin::Txid::from_byte_array([0xAA; 32]),
        vout: 0,
    };
    let move_txid_n = Txid::from_byte_array([0x01; 32]);
    let move_txid_m = Txid::from_byte_array([0x02; 32]);
    let idx_n = 10u32;
    let idx_m = 20u32;

    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_n, &move_txid_n).await.unwrap();
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_m, &move_txid_m).await.unwrap();

    // Attacker-controlled: same outpoint bound to two different withdrawal indices.
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_n, shared_utxo, 100).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_m, shared_utxo, 100).await.unwrap();

    // Assert the binding is broken: two idx map to the identical outpoint.
    let utxo_n = db.get_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_n).await.unwrap();
    let utxo_m = db.get_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_m).await.unwrap();
    assert_eq!(utxo_n, utxo_m); // <-- should be impossible if uniqueness were enforced

    // Simulate ONE physical payout tx spending shared_utxo.
    let payout_txid = Txid::from_byte_array([0xFF; 32]);
    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.insert_txid_to_block(&mut dbtx, block_id, &payout_txid).await.unwrap();
    db.insert_spent_utxo(&mut dbtx, block_id, &payout_txid, &shared_utxo.txid, shared_utxo.vout.into()).await.unwrap();

    // Show that ONE payout tx is credited to BOTH withdrawal indices.
    let txs = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();
    assert_eq!(txs.len(), 2);
    assert!(txs.iter().any(|(idx, txid)| *idx == idx_n && *txid == payout_txid));
    assert!(txs.iter().any(|(idx, txid)| *idx == idx_m && *txid == payout_txid));
    // Demonstrates double-crediting: the same physical payment satisfies two independent
    // deposit reimbursement lookups (get_payout_info_from_move_txid(move_txid_n) and
    // get_payout_info_from_move_txid(move_txid_m)) after update_payout_txs_and_payer_operator_xonly_pk
    // is invoked with both (idx_n, payout_txid, ...) and (idx_m, payout_txid, ...).
}

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

impl<C> Task for PayoutCheckerTask<C>
where
    C: CitreaClientT,
{
    type Output = bool;
    const VARIANT: TaskVariant = TaskVariant::PayoutChecker;

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;

            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db

            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
