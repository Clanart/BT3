### Title
Coinbase outputs are reported as spendable before maturity - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` scans every transaction in a Bitcoin block, including `block.txdata[0]`. A miner can therefore pay a Serai-controlled Taproot script in a coinbase output, and the scanner will emit it as a normal `ReceivedOutput` once the containing block is scanned. Bitcoin consensus forbids spending that output until it reaches coinbase maturity, but neither the scanner's dust check nor transaction construction enforces this restriction.

### Finding Description
`scan_transaction` returns a `ReceivedOutput` solely because an output's `script_pubkey` matches a registered scanner script. [1](#0-0)  `scan_block` then applies that logic to every transaction without skipping or marking the coinbase transaction. [2](#0-1) 

The upstream processor accepts every output returned by `network.get_outputs` whose amount exceeds the dust threshold. [3](#0-2)  For Bitcoin, those outputs are subsequently passed directly into `BSignableTransaction::new` as spendable inputs. [4](#0-3)  `SignableTransaction::new` accounts for their declared `TxOut` value and places the supplied outpoint in the transaction input, but performs no coinbase-maturity check. [5](#0-4) 

### Impact Explanation
A Serai multisig can report and account for Bitcoin funds that are not currently spendable under consensus rules. If the scheduler selects an immature coinbase output, the resulting threshold-signed transaction will be rejected by the Bitcoin network until maturity. This can stall the associated payment plan and cause processors to produce signatures for a transaction that cannot yet be broadcast.

The impact is bounded because the output becomes spendable after maturity, but it still creates externally triggerable consensus-invalid transaction plans and temporary availability failure.

### Likelihood Explanation
Any miner can trigger this behavior by directing a coinbase output to a currently scanned Serai address. Unlike an ordinary payment, this does not require the miner to already control a UTXO payable to Serai. Once Serai's confirmation depth is reached but before the Bitcoin coinbase maturity period expires, the output is eligible for scanning and scheduling.

### Recommendation
When scanning a block, exclude `block.txdata[0]` from spendable `External` outputs, or return coinbase outputs with a distinct immature status and retain the coinbase height. Do not make them eligible for scheduling until `current_height >= coinbase_height + COINBASE_MATURITY`.

If delayed tracking is desired, record the outpoint as pending and transition it to spendable after maturity. Do not merely filter it out permanently without persistence, since that would lose a valid output after it matures.

### Proof of Concept
1. A miner creates a valid Bitcoin block whose coinbase transaction pays the P2TR script produced by `Scanner::new(key)` or by a registered Serai offset.
2. The block reaches Serai's normal confirmation depth while remaining below Bitcoin's coinbase maturity requirement.
3. `Scanner::scan_block` iterates over all `block.txdata`, including the coinbase transaction, and emits the matching output as a `ReceivedOutput`. [6](#0-5) 
4. The processor scanner accepts it because only `amount >= N::DUST` is checked. [7](#0-6) 
5. The scheduler passes the output into `BSignableTransaction::new`, which converts its outpoint into a transaction input and commits to its declared value as a prevout. [4](#0-3) [8](#0-7) 
6. Threshold signing succeeds because the script and offset match, but Bitcoin consensus rejects the broadcast transaction because the referenced coinbase output is immature.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
