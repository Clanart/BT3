## Title
Unvalidated mirror URLs let any wallet user trigger outbound HTTP requests from other users' DataLayer nodes to attacker-chosen hosts (SSRF) - (File: `chia/data_layer/download_data.py`)

## Summary
Any wallet holder can publish a DataLayer "mirror" coin with an arbitrary list of URL strings memoed onto the coin, with no validation of scheme or destination host. Other nodes that subscribe to that store pull these URLs into their subscription list and, on the next sync cycle, their DataLayer service issues outbound HTTP GET requests to those attacker-chosen URLs, mirroring the Tautulli `pms_image_proxy` pattern where an unauthenticated user-supplied URL is forwarded verbatim to an internal service that then makes the outbound request.

## Finding Description
A mirror is created by spending a normal coin to `create_mirror_puzzle()` with a memo of `[launcher_id, *urls]`: [1](#0-0) 

`create_mirror_puzzle`/`get_mirror_info` place no constraints on the URL strings whatsoever — any bytes memo is accepted as a "URL": [2](#0-1) 

This mirror can be created by any wallet user through the `dl_new_mirror` RPC / `add_mirror` DataLayer RPC, which only checks that the URL list is non-empty — no scheme or host validation: [3](#0-2) 

Once the mirror coin is confirmed on chain, any DataLayer node that is subscribed to (or owns) that store pulls the mirror URLs directly into its local subscription server list via `update_subscriptions_from_wallet`, with no filtering: [4](#0-3) 

During the periodic sync loop, `fetch_and_validate` iterates these server URLs and calls `insert_from_delta_file`, passing the raw URL through untouched: [5](#0-4) 

`download_file`/`http_download` then issue an `aiohttp` GET directly to `server_info.url + "/" + filename` with no scheme allow-list and no check against private/internal address ranges: [6](#0-5) [7](#0-6) 

This is the same bug class as the Tautulli CVE: a low-privilege actor supplies a URL that is trusted at face value and forwarded to an internal HTTP client, letting the actor drive that internal client's networking (host, port, path) to arbitrary destinations, including RFC-1918/loopback/link-local addresses reachable from the victim's DataLayer host.

## Impact Explanation
Any wallet operator running a DataLayer node that subscribes to (or owns/auto-subscribes to) a store containing an attacker-created mirror will have their DataLayer service issue outbound HTTP requests to attacker-chosen hosts/ports/paths. This can be used to probe/attack the victim's internal network (e.g., cloud metadata endpoints, internal admin panels, other localhost services) from the victim's own node — a classic SSRF pivot. It is Medium severity: no direct fund loss or consensus impact, but it grants an unauthenticated attacker a foothold to reach internal network services through the victim's DataLayer process.

## Likelihood Explanation
Creating a mirror coin only requires spending a small amount of XCH plus a fee — no special permission, no DID, no offer counterparty cooperation. Any wallet user can create a mirror for any existing store id, and DataLayer nodes automatically discover mirrors for stores they are subscribed to or own (`periodically_manage_data` runs this on every management cycle), making exploitation straightforward and low-cost.

## Recommendation
- Validate mirror/subscription URLs before persisting or using them: restrict scheme to `http`/`https`, and reject or block requests to loopback, link-local, and RFC-1918 address ranges (and any DNS names resolving to them) before calling `aiohttp` in `http_download`.
- Consider requiring explicit operator opt-in/allow-listing for automatically-discovered mirror URLs rather than trusting on-chain memos verbatim, since `update_subscriptions_from_wallet` currently merges them without review.
- Add the same validation to the `add_mirror`/`subscribe` RPC entry points so obviously malformed/dangerous URLs are rejected at creation time as well as at consumption time.

## Proof of Concept
1. Attacker (any funded wallet) creates a DataLayer store subscription target, or targets an existing store id, and calls `dl_new_mirror` (or the `add_mirror` DataLayer RPC) with `urls=["http://169.254.169.254/latest/meta-data/", ...]` and a small `amount`/`fee`.
2. The resulting mirror coin is confirmed on chain, memoing the launcher id and attacker URL(s) via `create_mirror_puzzle`.
3. A victim's DataLayer node, already subscribed to (or owning) that store, calls `update_subscriptions_from_wallet` on its next `periodically_manage_data` cycle, pulling in the attacker URL as a subscription server (`data_layer.py:979-985`).
4. On the next `fetch_and_validate` pass, the victim node's `http_download` issues a GET request to the attacker-controlled URL (`download_data.py:298-324`), causing the victim's machine to make an outbound request to whatever internal/external endpoint the attacker specified.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
