### Title
Unprotected `updateEndRemainingAllocation()` allows denominator manipulation to steal disproportionate bonus share - (File: rewards/Airdrop.sol)

### Summary
`updateEndRemainingAllocation()` is a `public` function with no access control and no "already-set" guard, so it can be called repeatedly by anyone after `periodsEndTime[4]`, each time overwriting `totalEndRemainingAllocation` with the current (shrinking) `totalRemainingAllocation`. An attacker who waits for other beneficiaries to claim first can re-invoke it to artificially shrink the bonus denominator right before their own `claim()`, capturing a disproportionate (up to 100%) share of `totalBonus` at the expense of remaining unclaimed beneficiaries.

### Finding Description
`getBonusAmount()` computes `bonusAmount = userAllocation * totalBonus / totalEndRemainingAllocation`, where `totalEndRemainingAllocation` is meant to be a fixed, one-time snapshot of `totalRemainingAllocation` taken exactly at `periodsEndTime[4]`: [1](#0-0) 

`claim()` only calls `updateEndRemainingAllocation()` conditionally, when `totalEndRemainingAllocation == 0`, implicitly assuming the snapshot happens only once (on the first claim after period 4): [2](#0-1) 

However, `updateEndRemainingAllocation()` itself has no guard preventing repeated calls and no access control - it simply re-executes `totalEndRemainingAllocation = totalRemainingAllocation` any time `block.timestamp >= periodsEndTime[4]`. Since `totalRemainingAllocation` is decremented by `userAllocation` on every `claim()` call, an attacker can call `updateEndRemainingAllocation()` directly (not through `claim()`) after several other beneficiaries have already claimed and shrunk `totalRemainingAllocation`, overwriting the snapshot to a much smaller value. When the attacker then calls `claim()`, `getBonusAmount()` divides their `userAllocation` by this artificially shrunk `totalEndRemainingAllocation` instead of the true total that existed at `periodsEndTime[4]`, inflating their bonus share - in the extreme case (attacker is the last remaining claimant), `userAllocation == totalEndRemainingAllocation`, so the attacker claims the entire `totalBonus` rather than their fair pro-rata slice. Because `totalBonus` is never decremented as bonuses are paid out, this breaks the conservation invariant that the sum of all bonus payouts should equal `totalBonus`; the excess is paid out of the contract's real token balance, at the expense of other beneficiaries who have not yet claimed (their subsequent `claim()` calls can revert on `InsufficientBalance`, freezing/stealing their allocation).

### Impact Explanation
This directly enables theft of user funds: the attacker extracts more than their fair share of the shared bonus pool, drawing down the airdrop contract's real token balance beyond what should be allocable, which can cause remaining legitimate beneficiaries' `claim()` calls to revert due to insufficient balance, permanently freezing/losing their entitled principal and bonus. This matches "direct theft of user funds" / "theft or permanent freezing of unclaimed yield."

### Likelihood Explanation
Requires no privilege - `updateEndRemainingAllocation()` is `public` and callable by any EOA/contract. The only precondition is holding a nonzero `allocations[msg.sender]` (attacker must already be a registered beneficiary) and simply waiting until other users have claimed after `periodsEndTime[4]`, which is a natural, expected state of the contract over time (claiming is first-come, and later claimants naturally see a smaller `totalRemainingAllocation`). No capital or flash loans needed; fully repeatable/observable on-chain.

### Recommendation
Snapshot `totalEndRemainingAllocation` exactly once, guarded by a boolean flag (e.g., `bool public endAllocationSet`) rather than re-checking `totalEndRemainingAllocation == 0` (which can legitimately be zero, or become stale/manipulable). Restrict `updateEndRemainingAllocation()` so it can only ever set the value a single time, e.g.:
```solidity
bool public endAllocationSet;
function updateEndRemainingAllocation() public {
    if (block.timestamp >= periodsEndTime[4] && !endAllocationSet) {
        totalEndRemainingAllocation = totalRemainingAllocation;
        endAllocationSet = true;
    }
}
```
Also consider decrementing `totalBonus` proportionally as it's claimed, or tracking cumulative bonus payouts to enforce the conservation invariant explicitly.

### Proof of Concept
Foundry test outline:
1. Deploy `Airdrop` with `startTime = block.timestamp + 1`, fund contract with tokens covering `sum(allocations)`.
2. `register()` three users: A, B (attacker) each with allocation `100e18`, and have one or more earlier users forfeit part of their allocation pre-period-4 to build up `totalBonus` (or simply have a user with a partial early claim before period 4 to seed `totalBonus`).
3. Warp to `periodsEndTime[4]`.
4. User A calls `claim()` - this internally calls `updateEndRemainingAllocation()` (since `totalEndRemainingAllocation == 0`), snapshotting `totalEndRemainingAllocation = totalRemainingAllocation` (e.g. `200e18` if only A and attacker remain), then A's allocation is subtracted, reducing `totalRemainingAllocation` to `100e18` (attacker's amount only).
5. Attacker calls `updateEndRemainingAllocation()` directly (not via `claim()`), overwriting `totalEndRemainingAllocation` from `200e18` down to `100e18`.
6. Attacker calls `claim()`; assert `getBonusAmount(attacker) == totalBonus` (100% of the bonus pool) instead of the fair `totalBonus * 100e18 / 200e18` (50%).
7. Assert contract's `aidropToken` balance is now insufficient to cover any additional legitimate unclaimed beneficiary's fair bonus share, demonstrating fund theft/freezing. [3](#0-2)

```text
    function getBonusAmount(address _user)
        public
        view
        returns (uint256 bonusAmount)
    {
        bonusAmount = 0;
        uint256 userAllocation = allocations[_user];
        if (
            block.timestamp >= periodsEndTime[4] &&
            totalEndRemainingAllocation != 0
        ) {
            bonusAmount =
                ((userAllocation * 10**9) * totalBonus) /
                totalEndRemainingAllocation /
                10**9;
        }
    }

    /// @notice This will store the ending remaining amount for the bonus.
    function updateEndRemainingAllocation() public {
        if (block.timestamp >= periodsEndTime[4]) {
            totalEndRemainingAllocation = totalRemainingAllocation;
        }
    }

    /// @notice Claim MGP and forfeit remaining allocation
    function claim() external {
        if (totalEndRemainingAllocation == 0) {
            updateEndRemainingAllocation();
        }
        uint256 claimableAmount = getClaimableAmount(msg.sender);
        
        if(claimableAmount == 0) revert NothingToClaim();
        if(claimableAmount > aidropToken.balanceOf(address(this))) revert InsufficientBalance();

        uint256 userAllocation = allocations[msg.sender];
        allocations[msg.sender] = 0;
        totalRemainingAllocation -= userAllocation;
        if (claimableAmount <= userAllocation) {
            uint256 forfeited = userAllocation - claimableAmount;
            totalBonus += forfeited;
        }
        aidropToken.safeTransfer(msg.sender, claimableAmount);
    }
```
