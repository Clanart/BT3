### Title
`ReceivedOutput::read` accepts an arbitrary `TxOut` value that `SignableTransaction`/`TransactionMachine` never validates against the real UTXO, producing consensus-invalid signed transactions — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The audited bug class is "a caller-supplied amount exceeding/diverging from the authoritative recorded value is not validated, so the operation proceeds and then fails downstream." In Serai's `bitcoin-serai` wallet, `ReceivedOutput` — explicitly deserializable from untrusted bytes via `ReceivedOutput::read` — carries a `TxOut` whose `value` is trusted unconditionally. `SignableTransaction::multisig` only verifies that the offset key's `script_pubkey` matches the prevout; it never checks the claimed satoshi value against the actual on-chain output. Because Taproot `SighashType::Default` with `Prevouts::All` commits every input amount into the sighash, any divergence between the serialized `output.value` and the real UTXO produces a fully signed transaction that Bitcoin consensus will reject.

### Finding Description
`ReceivedOutput::read` deserializes `offset`, `output: TxOut`, and `outpoint` with no validation beyond encodings [1](#0-0) . When the output is spent, `SignableTransaction::new` computes `input_sat`, fee sufficiency, and the change amount purely from the attacker-controlled `input.output.value` fields [2](#0-1) . The only consistency check in `multisig` is `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey`, which binds the key to the script but not the value [3](#0-2) . At signing time, `TransactionSignMachine::sign` builds `Prevouts::All(&self.tx.prevouts)` and calls `taproot_key_spend_signature_hash(i, &prevouts, TapSighashType::Default)` [4](#0-3) . Under BIP-341 the sighash commits to `sha_amounts` over all prevouts; Bitcoin Core verifies each committed amount against the spent UTXO, so a forged value yields an invalid transaction.

### Impact Explanation
An unprivileged party who can feed crafted bytes to `ReceivedOutput::read` (e.g., a corrupted/malleated output record consumed by a signer) can cause the threshold group to run a complete FROST signing round and emit a valid BIP-340 signature over a sighash that commits to wrong input amounts. The resulting transaction is unbroadcastable — the claimed funds are "received" but not spendable. Additionally, an inflated `output.value` inflates `input_sat`, so `SignableTransaction::new` will happily attach a change output or oversized fee that doesn't exist, and a deflated value corrupts the change/fee math. This mirrors the report's impact: the invalid amount isn't rejected at validation time; the claim/spend simply fails after the work is done.

### Likelihood Explanation
Reachability is limited: it requires an attacker to control the serialized `ReceivedOutput` bytes consumed by a signer (the intended producers are `Scanner::scan_transaction`/`scan_block`, which copy real `TxOut`s [5](#0-4) ). Within the stated scope — untrusted bytes fed to `ReceivedOutput::read` — the path is direct and deterministic. The consequence is failed spends / wasted signing rounds rather than key leakage or theft, matching Medium severity.

### Recommendation
Treat the deserialized `TxOut` value as untrusted and bind it to an authoritative source: either have `ReceivedOutput::read`/`SignableTransaction::new` reject outputs whose `outpoint`/`script_pubkey`/`value` cannot be confirmed against the chain record (e.g., require outputs to originate from `Scanner` and carry a witness of provenance), or in `multisig()`/`sign()` verify `prevouts[i]` equals the scanner-recorded output for `outpoint`, not just the `script_pubkey`. Absent an in-library chain lookup, document and enforce at the API boundary that `SignableTransaction` must only be built from `Scanner`-produced outputs, and add a `debug_assert` comparing `output.value` against a supplied expected-amount parameter.

### Proof of Concept
```rust
// Construct a ReceivedOutput claiming 10x the real UTXO value
let mut bytes = real_received_output.serialize();
// Patch the serialized TxOut value field (offset-bytes || value(8 LE) || spk || outpoint)
bytes[32 .. 40].copy_from_slice(&(10_000_000u64).to_le_bytes());
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 10_000_000);

// SignableTransaction accepts it: input_sat is computed from the forged value,
// fee/change are miscomputed, and multisig() succeeds because only
// script_pubkey is checked.
let tx = SignableTransaction::new(vec![forged], &payments, change, None, fee_rate).unwrap();
let signed = sign(&keys, &tx); // FROST round completes, signatures are valid BIP-340
// Broadcast fails: sha_amounts in the sighash commits to 10_000_000 but the
// real UTXO holds a different amount -> consensus rejects the transaction.
```

```rust
      outpoint =
```

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
