### Title
Spoofable server-side signals cause the credential-helper trampoline to misclassify a malicious host as a GitHub Enterprise endpoint, triggering a GitHub sign-in prompt for an attacker-controlled remote - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
The abstracted invariant in the SynthVault report is: *a value that is trivially manipulable by an untrusted counterparty (spot price) is trusted at a critical decision point (weight/reward calculation) with no corroborating, tamper-resistant signal.* The closest Desktop analog is `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, which decides whether a git remote should be treated as a GitHub/GHE host (and therefore whether Desktop should prompt the user to authenticate with a GitHub account for it) based on signals that are fully controlled by the remote server itself: the `WWW-Authenticate` header's `realm` value, and the `x-github-request-id` HEAD-response header used by `isGitHubHost()`.

### Finding Description
`getEndpointKind()` classifies the host behind a git remote URL as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'` [1](#0-0) . For hosts that are not literally `github.com`/`*.ghe.com`, the function falls back to two attacker-influenceable heuristics:

1. It inspects the `wwwauth[...]` credential fields captured by git from the server's `WWW-Authenticate` response header, and treats `realm="GitHub"` as proof of an "enterprise" GitHub host: [2](#0-1) 

2. Failing that, it calls `isGitHubHost(endpoint)`, which performs a `HEAD` request to `${endpoint}/meta` and treats the mere presence of an `x-github-request-id` response header as confirmation that the host is GitHub: [3](#0-2) 

Both signals are values chosen entirely by the remote server (or a MITM/malicious proxy sitting on that connection) — exactly like the manipulable spot price in the original report — and neither is cryptographically bound to the actual identity of GitHub/GHE (no certificate pinning, no signature, no TOFU check tied to a previously-established GHES fingerprint). Any HTTP server that a user adds as a git remote can simply respond with `WWW-Authenticate: Basic realm="GitHub"` or return an `x-github-request-id` header on `/meta` to be classified as `'enterprise'`.

Once classified as `'enterprise'` (or `'github.com'`) and no existing account matches (`findGitHubTrampolineAccount` matches by URL origin only [4](#0-3) ), `getCredential()` invokes `ui.promptForGitHubSignIn(endpoint)`: [5](#0-4) 

This routes the user into Desktop's normal GitHub OAuth/PAT sign-in UI for what the user believes, based on the prompt, is a legitimate GitHub/Enterprise remote — while the underlying transport is actually the attacker's endpoint. The `storeCredential`/`eraseCredential` paths use the exact same spoofable classification to decide whether to withhold generic credential storage, and `updateEndpointVersion`/`getEndpointVersion` in `app/src/lib/endpoint-capabilities.ts` similarly persist an unauthenticated `x-github-enterprise-version` header value into `localStorage`, permanently affecting capability checks (`supportsAvatarsAPI`, `supportsRepoRules`, etc.) for that endpoint on every future session: [6](#0-5) 

Existing guards do not stop this path: there is no TLS certificate identity check tying the `WWW-Authenticate` realm or `/meta` response to a known GitHub/GHE TLS chain, `isKnownThirdPartyHost` only denylists a fixed set of well-known non-GitHub SaaS hostnames [7](#0-6) , and any host not on that list is presumed innocent until it self-reports otherwise via headers the attacker fully controls.

### Impact Explanation
An attacker who controls a git HTTP remote (e.g., a malicious mirror URL, a compromised/typosquatted git hosting service, or a MITM proxy on a network path a user clones/fetches through) can trick Desktop into believing the remote is a GitHub Enterprise Server. This surfaces the native "Sign in to GitHub" prompt for that host, socially engineering the user into entering credentials/PATs or completing an OAuth device flow that the attacker did not need to compromise separately — this is a credential-phishing primitive baked into the trust decision, not a generic phishing page. It also poisons the persistent `endpoint-capabilities` cache (`localStorage`) with attacker-supplied version data that other, later, legitimate connections to that same endpoint string will trust.

### Likelihood Explanation
Moderate. The attacker only needs to control (or proxy) an HTTP git remote and respond to Desktop's outgoing `HEAD /meta` or Basic-Auth challenge with crafted headers — no local access, no prior compromise of the user's machine, and no unnatural user steps beyond adding/cloning a remote and going through the resulting (seemingly legitimate) sign-in prompt, matching the valid-impact criteria (attacker controls a git remote/proxy response, resulting in unauthorized credential flow).

### Recommendation
Do not classify a host as GitHub/GHE based solely on self-reported headers (`WWW-Authenticate` realm, `x-github-request-id`, `x-github-enterprise-version`). Require a stronger, harder-to-forge corroborating signal before offering the GitHub sign-in flow or persisting capability data — e.g., cross-check against the enterprise server's known/pinned identity established during explicit "Add Enterprise Server" onboarding (`validateURL` in `app/src/ui/lib/enterprise-validate-url.ts`) rather than opportunistic per-request headers, and never persist unauthenticated version headers into `localStorage`/`versionCache` without the endpoint being an already-registered, user-confirmed enterprise account.

### Proof of Concept
1. Attacker stands up an HTTP(S) server (or transparent proxy) at `https://evil.example.com/team/repo.git`.
2. Victim adds it as a git remote in Desktop and performs a `fetch`/`pull`.
3. Git invokes Desktop's credential helper trampoline; the attacker's server responds to the unauthenticated request with `WWW-Authenticate: Basic realm="GitHub"`.
4. `getEndpointKind()` matches the `realm="GitHub"` regex and returns `'enterprise'` [8](#0-7) .
5. No account exists for `evil.example.com`, so `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, presenting the victim with Desktop's native GitHub sign-in dialog [5](#0-4) .
6. Alternatively, if the server instead answers the `isGitHubHost` `/meta` HEAD probe with an `x-github-request-id` header, the same `'enterprise'` classification is reached without ever sending a `WWW-Authenticate` challenge [3](#0-2) .

Note: I was not able to fully trace the exact contents/behavior of `ui.promptForGitHubSignIn` (trampoline-ui-helper.ts) or confirm whether any additional confirmation dialog names the actual remote host before the OAuth flow starts; this would need to be verified in a live session to determine exact user-facing wording and whether it sufficiently discloses the untrusted host to the user.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

const knownThirdPartyHosts = new Set([
  'dev.azure.com',
  'gitlab.com',
  'bitbucket.org',
  'amazonaws.com',
  'visualstudio.com',

const isKnownThirdPartyHost = (hostname: string) => {
  if (knownThirdPartyHosts.has(hostname)) {
    return true
  }

  for (const knownHost of knownThirdPartyHosts) {
    if (hostname.endsWith(`.${knownHost}`)) {
      return true
    }
  }

  return false
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}

/**
 * Update the known version number for a given endpoint

export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}
