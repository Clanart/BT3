## Analysis

The external report's core broken invariant: a reward-accrual function computes payout using only a partial view of "what actually happened" in the relevant window, so the wrong party captures value that belongs to (or was earned in participation with) someone else. The closest verifiable local analog in Hyperbridge is in `pallet-consensus-incentives`, where the relayer reward attribution for a batch of ISMP messages is derived from only the *first* message in an attacker-controlled batch, while the payout is computed by scanning **all** state-machine-advance events produced by the *entire* batch — not just those produced by that first message. [1](#0-0) 

`handle_unsigned` on `pallet-ismp` is a fully permissionless, unsigned extrinsic that executes an arbitrary attacker-supplied `Vec<Message>` for free, as long as every message carries a valid proof/signature: [2](#0-1) 

`Pallet::execute` runs every message in the batch, collects **all** resulting events (including `StateMachineUpdated` events from every `Message::Consensus` entry in the batch), and hands the full events list plus the full messages list to `FeeHandler::on_executed`: [3](#0-2) 

Inside `on_executed`, the relayer identity is extracted **only** from `messages.get(0)` and its embedded self-attested signature, then that single signer is credited for *every* `StateMachineUpdated` event in the batch, deduplicated only per `state_machine_id`: [4](#0-3) 

The comment on lines 125-132 documents that the pallet was patched to avoid paying the *same* signer multiple times for the *same* state machine within one batch — but it never addresses the case where the batch contains **multiple distinct `Message::Consensus` entries with different embedded signers**. Since `messages[0]`'s signer is used for the reward on *every* state machine advanced anywhere in the batch, an unprivileged caller who assembles the batch (order and contents are fully attacker-controlled, because `handle_unsigned` takes an arbitrary `Vec<Message>` from `ensure_none` origin) can place their own trivially-signed `Message::Consensus` first, followed by any number of separately-signed, independently-valid `Message::Consensus` entries for other state machines. Every reward computed by `calculate_reward` for those other chains is paid to the attacker's account instead of the actual signer who produced/discovered that state advance, and the attacker's account is also minted the matching `ReputationAsset`. [5](#0-4) 

This is a genuine batch-composition/transaction-manipulation defect distinct from a passive front-run: the vulnerable code path itself (message[0]-only signer extraction combined with all-events reward scanning) is what allows reward misattribution across unrelated `Message::Consensus` entries bundled by an attacker into a single call, regardless of how the attacker obtained the other valid consensus proof (self-generated for multiple chains, or copied from any publicly-available proof source — proofs "can be generated by anyone" per the protocol design). `LastRewardedHeight` prevents double-payment for the *same* chain, but does nothing to prevent misattribution of the *first* payment to the wrong account.

### Title
Consensus-incentives reward misattribution via multi-message unsigned batches - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`FeeHandler::on_executed` in `pallet-consensus-incentives` derives the relayer account to reward from only the first message (`messages[0]`) in a `handle_unsigned` batch, but then pays that single account for the state-machine advance of *every* `Message::Consensus` entry present anywhere in the batch. Because `handle_unsigned` is a permissionless, unsigned extrinsic that accepts an arbitrary attacker-composed `Vec<Message>`, an attacker can prepend a trivially self-signed consensus message and bundle in additional, independently-valid `Message::Consensus` entries (for other state machines, produced by anyone) to have the entire multi-chain reward and `ReputationAsset` mint attributed to their own account.

### Finding Description
- `pallet_ismp::Pallet::execute` runs every `Message` in the caller-supplied batch, collects the union of all emitted events, and forwards the full `messages` + `events` to `T::FeeHandler::on_executed` in one call. [3](#0-2) 
- `on_executed` extracts the relayer's public key exclusively from `messages[0]`'s embedded `signer` field (a self-attested signature over the message's own consensus proof, not tied to the extrinsic submitter) via `Signature::decode`/`verify_and_get_sr25519_pubkey`. [1](#0-0) 
- It then iterates the **entire** `events` vector (spanning all messages in the batch, not just `messages[0]`), collapses `StateMachineUpdated` events per `state_machine_id` to the highest height, and pays out a `RelayerRewarded` transfer plus a `ReputationAsset` mint to the single identified account for each distinct state machine advanced anywhere in the batch. [6](#0-5) 
- `handle_unsigned` is `ensure_none` — anyone can submit any `Vec<Message>` as long as each message's proof validates independently; there is no requirement that all messages in a batch share the same signer or origin. [7](#0-6) 
- The only existing guard, `LastRewardedHeight`, is a per-`state_machine_id` monotonic watermark that stops the *same* chain from being paid twice; it provides no protection against the *first* payout for a chain being attributed to the wrong signer. [8](#0-7) 

### Impact Explanation
This is a fund-theft / logic-attack vector on the treasury-funded relayer-incentive payout: value that should be credited to whichever account actually produced/delivered each individual consensus update instead flows entirely to whoever controls `messages[0]` in the submitted batch, for every other consensus message bundled alongside it. This is a direct "stealing of funds" and "transaction manipulation" scenario against `TreasuryAccount`, matching the accepted impact classes (unauthorized transaction, logic attack, false-beneficiary fund movement).

### Likelihood Explanation
`handle_unsigned` is permissionless by design (`ensure_none`), and nothing in `on_executed` or `handle_unsigned`'s validation constrains a batch to contain messages from a single signer. Any actor able to observe or independently produce more than one valid `Message::Consensus` (proofs are explicitly described in the docs as freely generatable by anyone) can construct a qualifying batch without needing any relayer/operator/governance privilege.

### Recommendation
Attribute rewards per-message rather than batch-wide: extract the signer from the specific `Message::Consensus` entry that produced each `StateMachineUpdated` event (matching on `consensus_state_id`/`state_machine_id`) instead of using `messages[0]` for the whole batch, or reject batches containing more than one `Message::Consensus` with differing signers before reward processing.

### Proof of Concept
1. Attacker A holds a keypair and produces (or observes publicly available) a minimal valid `Message::Consensus` for `state_machine_id = X` with negligible height advance, self-signed with A's key (`signer` field is self-attested, not tied to the extrinsic submitter — see `consensus_msg.signer` decode in `on_executed`).
2. Attacker A also obtains a second, independently-valid `Message::Consensus` for `state_machine_id = Y` (large height advance, e.g. authored/discoverable by relayer B, or self-produced by A for another registered state machine).
3. A submits `handle_unsigned(vec![msg_for_X_signed_by_A, msg_for_Y])` as a single unsigned extrinsic.
4. `execute` processes both messages, producing `StateMachineUpdated` events for both `X` and `Y`. [9](#0-8) 
5. `on_executed` extracts the relayer identity solely from `messages[0]` (A), then loops over `highest_per_state_machine` covering both `X` and `Y`, calling `process_message` with A's account for **both** — crediting A the treasury payout and `ReputationAsset` mint for chain `Y`'s advance despite A not being the one who produced/signed that update. [6](#0-5)

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

impl<T: Config> Pallet<T> {
	/// Execute the provided ISMP datagrams, this will short circuit if any messages are invalid.
	/// This also charges fee on valid message delivery
	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;
