### Title
Attacker-controlled `_minMGPRec` combined with unprotected spot-price AMM swap in bull mode allows manipulation of `mgpAmountToLcok`, draining `ArbWomUp2`'s pre-funded MGP bonus reserve - ([File: wombat/ArbWomUp2.sol])

### Summary
`ArbWomUp2._bullMGP()` swaps a fixed, legitimately-earned `busdReward` amount through `ROUTER.swapExactTokensForTokens` using the caller-supplied `_minMGPRec` as the only slippage guard, then computes `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` and locks that amount via `vlMGP.lockFor`. Because the caller fully controls `_minMGPRec` (setting it to 0) and can manipulate the BUSD/MGP pool reserves within the same transaction/block (flash loan or their own capital), `amounts[1]` can be inflated far above the fair-market MGP value of `busdReward`, causing the contract to lock an inflated `mgpAmountToLcok` that is paid out of the contract's own pre-funded MGP balance rather than tokens actually purchased at fair value.

### Finding Description
`incentiveDeposit(_amount, _minMGPRec, true)` at [1](#0-0)  is public/external, gated only by `whenNotPaused` and `nonReentrant`, and reachable directly by any unprivileged EOA holding WOM.

Inside, `rewardToSend` (a deterministic BUSD amount based on the attacker's own WOM tier deposit) is passed to `_bullMGP`: [2](#0-1) 

`_minRec` here is exactly the attacker-supplied `_minMGPRec` parameter from `incentiveDeposit`. Since the attacker is both the caller and the party who benefits from `amounts[1]` being large, `_minMGPRec` provides zero real slippage protection — the attacker simply sets it to `0` (or a low value they know will still be satisfied after they manipulate the pool). The router performs `swapExactTokensForTokens` against the live, spot reserves of the BUSD/MGP pool with no TWAP or external fair-price check.

An attacker can, within the same transaction (or via front-run/back-run in the same block), temporarily depress the MGP price in the BUSD/MGP pool (e.g., by first dumping MGP into the pool, or using a flash loan) immediately before triggering `incentiveDeposit`. The depressed price causes the fixed `busdReward` to buy an inflated `amounts[1]` of MGP from the pool. `mgpAmountToLcok` is then computed as `amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR`, and `vlMGP.lockFor(mgpAmountToLcok, _account)` is called.

Critically, `vlMGP.lockFor` executes `_lock`, which does `MGP.safeTransferFrom(spender, address(this), _amount)` where `spender = msg.sender` (i.e., the `ArbWomUp2` contract itself, since it calls `lockFor`): [3](#0-2) . This means the `bullBonusRatio` portion of `mgpAmountToLcok` (and any inflation of `amounts[1]` beyond what fair-value busdReward should have purchased) must come from `ArbWomUp2`'s own pre-funded MGP balance, not from the swap proceeds. Inflating `amounts[1]` via spot-price manipulation directly inflates the amount of the contract's own MGP reserve that gets locked for the attacker, disproportionate to the real BUSD value they contributed.

No existing check (`whenNotPaused`, `nonReentrant`, tier accounting) validates that `amounts[1]` reflects a fair BUSD-to-MGP conversion; the contract fully trusts the instantaneous AMM output.

### Impact Explanation
This breaks the backing invariant that locked vlMGP bonus should correspond to a genuine BUSD-to-MGP purchase at fair market price. Each exploited call over-locks MGP for the attacker at the expense of `ArbWomUp2`'s own MGP reserve (used to fund `bullBonusRatio` bonuses and any pool depth used for the swap itself), which can be repeated across multiple WOM deposits/tiers and drained until the contract's MGP/BUSD balances are exhausted — an insolvency of the bull-mode reward pool (Immunefi: "Protocol Insolvency" / "theft of unclaimed yield/reserve").

### Likelihood Explanation
Feasibility depends on the depth/liquidity of the specific BUSD/MGP `IPancakeRouter02` pool that `ROUTER` points to (set by `onlyOwner` via `setup`). If that pool is shallow relative to the reward amounts being swapped, an attacker with a flash loan or even modest capital can materially move the spot price within one transaction, since `_minMGPRec` is entirely attacker-chosen and offers no protection against self-sandwiching. The attack is repeatable per deposit/tier increment and scales with available liquidity depth and the size of `bullBonusRatio`.

### Recommendation
Do not let the caller's `_minMGPRec` be the only protection for a swap whose output directly determines how much of the protocol's own MGP reserve gets locked as bonus. Add an internal fair-value check (e.g., compare `amounts[1]` against a TWAP/oracle price or a protocol-configured max-deviation bound from a reference price) before computing `mgpAmountToLcok`, and/or cap the swap size relative to available pool liquidity depth to bound price impact.

### Proof of Concept
Foundry fork test plan:
1. Fork BSC at a block with the real BUSD/MGP pool used by `ArbWomUp2.ROUTER`.
2. Deploy/attach to `ArbWomUp2`, fund it with WOM reward tiers and MGP/BUSD reserve as in production `setup()`.
3. As attacker EOA: obtain WOM, call `incentiveDeposit` normally first to record baseline `mgpAmountToLcok` for a fixed `_amount` at unmanipulated pool price.
4. Reset fork; before calling `incentiveDeposit(_amount, 0, true)`, execute a large MGP->BUSD swap (attacker capital or flash loan) against the same pool to depress MGP price.
5. Call `incentiveDeposit(_amount, 0, true)` and capture `VLMGPRewarded` event's `_vlMGPAmount`.
6. Assert `_vlMGPAmount` (manipulated) is significantly greater than the baseline from step 3 for the identical `_amount`/`busdReward`, and assert the delta locked is drawn from `ArbWomUp2`'s pre-existing MGP balance rather than swap proceeds (check `ArbWomUp2` MGP balance before/after).
7. Repeat the manipulate-then-deposit sequence across multiple attacker addresses/tiers to show cumulative drain of the contract's MGP reserve.

    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
