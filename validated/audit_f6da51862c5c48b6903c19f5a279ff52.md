### Title
Migration funds designated to a smart-contract claimer are permanently unclaimable via the `solo` precompile - (File: precompiles/solo/solo.go)

### Summary
The `solo` precompile's `claim`/`claimSpecific` methods let a legacy (pre-EVM) Cosmos account holder sign a `MsgClaim`/`MsgClaimSpecific` naming an EVM address (`claimer`) that should receive the migrated funds. The precompile enforces that the EVM `caller` of the transaction must equal that named `claimer` address, and additionally enforces that the call must come directly from an EOA (`evm.GetDepth() > 1` is rejected). Because a smart contract address can never itself be `tx.origin`/top-level `caller` of an EVM transaction, any `MsgClaim` that names a contract address as `claimer` can never be satisfied, permanently freezing the migrated assets (usei, CW20, CW721) still held by the old Cosmos account.

### Finding Description
In `precompiles/solo/solo.go`, `Execute` rejects any call where the call depth into the precompile is greater than 1: [1](#0-0) 

and `validate` requires the EVM `caller` to exactly equal the `claimer` address encoded in the signed Cosmos `MsgClaim`/`MsgClaimSpecific`: [2](#0-1) 

`Claim`/`ClaimSpecific` then move the old account's native coins, CW20, and CW721 balances to the Sei address derived from `caller`: [3](#0-2) [4](#0-3) 

The combination of "`caller` must equal `claimer`" and "call depth must be exactly 1" means the only entity that can ever successfully execute a claim for a given `claimer` address is an EOA whose private key controls that exact address — i.e. the top-level transaction signer. There is no way for a smart contract to be the top-level `msg.sender`/`tx.origin` of an EVM transaction (transactions must originate from EOAs), and the depth check additionally blocks any indirect invocation (e.g., an EOA calling through an intermediary contract, or a contract self-executing on behalf of a designated claimer). Consequently, once a legacy Cosmos account holder signs a `MsgClaim` naming a smart-contract address (e.g. a multisig, AA wallet, or any other contract they control on the EVM side) as the `claimer`, that claim can never be executed by anyone, and the assets in the old Cosmos-native account remain permanently stuck.

This mirrors the reported bug class: a cross-domain/migration claim flow is designed so "anyone" can trigger a claim on behalf of a beneficiary, but the actual implementation hard-restricts the beneficiary to be the literal `msg.sender`, so a beneficiary that is a contract (which cannot itself be `msg.sender` of a top-level call) can never claim.

### Impact Explanation
Funds (native `usei`, CW20 tokens, CW721 NFTs) belonging to a legacy account are permanently locked if the account owner signs a claim naming any smart-contract address as the recipient. This is a permanent freezing of user funds with no recovery path through the intended precompile interface, satisfying the "permanent freezing of funds" impact category for a Medium-severity finding.

### Likelihood Explanation
Likelihood is moderate to high in practice: any user who wants their migrated assets to end up in a smart-contract wallet (multisig, account-abstraction wallet, DeFi vault, etc.) rather than a plain EOA will hit this restriction, and once the `MsgClaim`/`MsgClaimSpecific` is signed and the sequence number consumed on `sigverify`, there is no ability to correct the intended `claimer`. Since sequence numbers are incremented on signature verification, even attempts and failures may not be trivially reversible if the account can no longer produce another valid signature for a different claimer (e.g., sequence exhaustion concerns aside, the assets simply remain in place, but the specific signed claim is now dead if the contract address is unreachable by any EOA claim).

### Recommendation
Decouple the "who is authorized to submit the claim transaction" check from "who receives the funds." Allow the `claimer` field to designate a Sei/EVM address (including contract addresses) as the fund *destination*, while allowing the actual EVM transaction to be submitted by any authorized party (e.g., verified via the underlying Cosmos signature on `MsgClaim` alone, similar to how `initiateClaim`'s recommendation suggested passing the beneficiary explicitly rather than inferring it from `msg.sender`). At minimum, relax the `caller == claimer` and depth-1 restrictions so that a contract can be validly named as the fund recipient even though it cannot itself submit the top-level transaction.

### Proof of Concept
1. A legacy pre-EVM Sei account `sender` holds `usei`/CW20/CW721 balances.
2. `sender` signs a `MsgClaim` (or `MsgClaimSpecific`) with `claimer` set to a smart-contract address `C` deployed on the Sei EVM (e.g., a Safe-style multisig `C` that the user controls).
3. Any party attempts to call the `solo` precompile's `claim(payload)`/`claimSpecific(payload)` with this signed transaction as `payload`.
   - If called directly by an EOA `X != C`, `validate` at [5](#0-4)  rejects because `caller (X) != claimer (C)`.
   - It is impossible for `C` itself to be the top-level `caller`/`tx.origin`, since only EOAs can originate EVM transactions.
   - Any attempt to route the call through another contract to make `C` appear as an intermediate caller is rejected by the depth check at [1](#0-0) .
4. As a result, the signed `MsgClaim` naming contract `C` can never be successfully executed, and `sender`'s legacy balances remain frozen indefinitely.

```go
func (p PrecompileExecutor) ClaimSpecific(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, readOnly bool) (ret []byte, remainingGas uint64, err error) {
	claimMsg, sender, err := p.validate(ctx, caller, args, readOnly)
	if err != nil {
		return nil, 0, err
	}
	claimSpecificMsg, ok := claimMsg.(claimSpecificMsg)
	if !ok {
		return nil, 0, errors.New("message is not MsgClaimSpecific type")
	}
	callerSeiAddr := p.evmKeeper.GetSeiAddressOrDefault(ctx, caller)
	for _, asset := range claimSpecificMsg.GetIAssets() {
		if asset.IsNative() {
			denom := asset.GetDenom()
			balance := p.bankKeeper.GetBalance(ctx, sender, denom)
			if !balance.IsZero() {
				if err := p.bankKeeper.SendCoins(ctx, sender, callerSeiAddr, sdk.NewCoins(balance)); err != nil {
					return nil, 0, err
				}
			}
			continue
		}
		contractAddr, err := sdk.AccAddressFromBech32(asset.GetContractAddress())
		if err != nil {
			return nil, 0, fmt.Errorf("failed to parse contract address %s: %w", asset.GetContractAddress(), err)
		}
		switch {
		case asset.IsCW20():
			res, err := p.wasmViewKeeper.QuerySmartSafe(ctx, contractAddr, CW20BalanceQueryPayload(sender))
			if err != nil {
				return nil, 0, fmt.Errorf("failed to query CW20 contract %s for balance: %w", contractAddr.String(), err)
			}
			balance, err := ParseCW20BalanceQueryResponse(res)
			if err != nil {
				return nil, 0, fmt.Errorf("failed to parse CW20 contract %s balance response: %w", contractAddr.String(), err)
			}
			_, err = p.wasmKeeper.Execute(ctx, contractAddr, sender, CW20TransferPayload(callerSeiAddr, balance), sdk.NewCoins())
			if err != nil {
				return nil, 0, fmt.Errorf("failed to transfer on CW20 contract %s: %w", contractAddr.String(), err)
			}
		case asset.IsCW721():
			allTokens := []string{}
			if token := asset.GetDenom(); token != "" {
				allTokens = append(allTokens, token)
			} else {
				startAfter := ""
				for {
					res, err := p.wasmViewKeeper.QuerySmartSafe(ctx, contractAddr, CW721TokensQueryPayload(sender, startAfter))
					if err != nil {
						return nil, 0, fmt.Errorf("failed to query CW721 contract %s for all tokens: %w", contractAddr.String(), err)
					}
					tokens, err := ParseCW721TokensQueryResponse(res)
					if err != nil {
						return nil, 0, fmt.Errorf("failed to parse CW20 contract %s balance response: %w", contractAddr.String(), err)
					}
					if len(tokens) == 0 {
						break
					}
					allTokens = append(allTokens, tokens...)
					startAfter = tokens[len(tokens)-1]
				}
			}
			for _, token := range allTokens {
				_, err := p.wasmKeeper.Execute(ctx, contractAddr, sender, CW721TransferPayload(callerSeiAddr, token), sdk.NewCoins())
				if err != nil {
					return nil, 0, fmt.Errorf("failed to transfer token %s on CW721 contract %s: %w", token, contractAddr.String(), err)
				}
			}
		}
	}
	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
```
