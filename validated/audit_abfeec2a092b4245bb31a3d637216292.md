### Title
Empty `SchnorrAggregate` verifies as a valid signature for any message — authentication/forgery bypass - (File: crypto/schnorr/src/aggregate.rs)

### Summary
Analogous to CVE-2018-17552 (a check that trivially passes on a crafted, degenerate input instead of authenticating the party), `SchnorrAggregate::verify` reduces verification to `multiexp_vartime(&pairs).is_identity()` where the only unconditional pair is `(-s, G)`. When the aggregate contains zero nonces (`Rs` empty) and `s == 0`, the sum is trivially the identity point, so verification returns `true` for any DST and any set of `keys_and_challenges` of length zero — a forged "aggregate signature" over arbitrary messages.

### Finding Description
`SchnorrAggregate::read` parses a `u32` count of `Rs` points followed by a single scalar `s` (crypto/schnorr/src/aggregate.rs:77-88). An attacker supplies the bytes `00 00 00 00 || 0x00..0x00` (36 bytes), yielding `Rs = []` and `s = 0`. In `verify` (aggregate.rs:127-146), `self.Rs.len() != keys_and_challenges.len()` is `0 != 0` → false, so the challenge digest loop appends nothing, the pair-building loop pushes nothing, and the only pair pushed is `(-self.s, C::generator()) = (0, G)`. `multiexp_vartime` of `0·G` is the identity, so `verify` returns `true` for *any* message and *any* key list of length 0.

The aggregator itself refuses to produce such an object (`SchnorrAggregator::complete` returns `None` when `sigs` is empty, aggregate.rs:175-178), so the verifier is strictly weaker than the signer — the verifier accepts a forgery the honest aggregation path can never create. The canonical FROST-facing readers also reject degenerate input (`Curve::read_G` rejects identity points, crypto/frost/src/curve/mod.rs:125-131), but `C::read_G`/`C::read_F` used here impose no such semantic check on the aggregate as a whole.

The reachable consumer is `Validators::verify_aggregate` in coordinator/tributary/src/tendermint/mod.rs:200-229: it reads an attacker-supplied `AggregateSignature` blob, checks only `signers.len() == aggregate.Rs().len()`, and calls `aggregate.verify(...)`. Any caller that passes an empty `signers` slice — or any future integrator relying on this API to gate an action on "the aggregate signature verified" — accepts a forged signature bound to no public key and no message.

### Impact Explanation
The verifier's formula is incorrect: it authenticates nothing when the signer set is empty, yet reports success. This is a signature forgery primitive — an unauthenticated party produces bytes that `verify` accepts as a valid aggregate Schnorr signature over arbitrary messages. Where an aggregate signature is used to authorize an action (e.g., a Tendermint commit or a cross-network approval), acceptance of the trivial empty aggregate can bypass the intended authentication for any code path that reaches the call with an empty signer list rather than rejecting it upstream.

### Likelihood Explanation
Exploitation requires a caller to invoke `verify`/`verify_aggregate` with an empty signer set. `Validators::verify_aggregate` does not itself reject `signers.is_empty()`, and `weights` are checked only inside the per-validator `verify`, not for the aggregate. Whether the surrounding consensus logic separately enforces a minimum number of signers determines real-world exploitability; within the in-scope crypto API the forged acceptance is unconditional and requires only 36 attacker-controlled bytes.

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify` (return `false` when `Rs.is_empty()`, matching `SchnorrAggregator::complete`'s refusal to emit one), and have `verify_aggregate` in coordinator/tributary/src/tendermint/mod.rs reject an empty `signers` list before calling `verify`. Optionally also reject `s == 0` with empty `Rs` at read time.

### Proof of Concept
```rust
// crypto/schnorr/src/aggregate.rs — forged acceptance
use ciphersuite::dalek_ff_group::Ed25519; // any Ciphersuite
use schnorr::aggregate::SchnorrAggregate;

// 4-byte len = 0, then scalar s = 0
let mut bytes = vec![0u8; 4];
bytes.extend([0u8; 32]);

let agg = SchnorrAggregate::<Ed25519>::read(&mut bytes.as_slice()).unwrap();

// Empty signer set: forged signature verifies for ANY message/DST
assert!(agg.verify(b"any dst", &[]));
```
In `verify`, `Rs.len() (0) == keys_and_challenges.len() (0)`, no challenges are hashed, `pairs == [(-0, G)]`, and `multiexp_vartime` returns the identity — `verify` returns `true` for a signature no signer produced.
