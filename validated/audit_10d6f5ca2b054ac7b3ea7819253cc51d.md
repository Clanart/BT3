### Title
CosmWasm contract `BankMsg::Send` bypasses tokenfactory denom allow-list restriction - (File: sei-wasmd/x/wasm/keeper/keeper.go)

### Summary
`x/bank`'s standard `MsgSend` handler enforces `IsInDenomAllowList` for both sender and receiver whenever a token-factory denom has a restricted allow list configured, in addition to `IsSendEnabledCoins` and `BlockedAddr`. The `BankCoinTransferrer.TransferCoins` function used by the wasm module to dispatch `BankMsg::Send` from CosmWasm contract execution replicates the `IsSendEnabledCoins`/`BlockedAddr` checks but omits the `IsInDenomAllowList` check entirely, allowing a CosmWasm contract to move an allow-listed token-factory denom to/from an address that is not on the denom's allow list.

### Finding Description
`sei-cosmos/x/bank/keeper/msg_server.go`'s `Send` handler is the sanctioned entry point for `MsgSend`: it checks `IsSendEnabledCoins`, then requires both the sender and receiver to be present in the denom's `AllowList` via `IsInDenomAllowList` (for token-factory-prefixed denoms with a configured allow list) before calling `SendCoins`. [3](#0-2) 

The CosmWasm `BankMsg::Send` variant, however, is not routed through this `msgServer.Send` handler. It is encoded to a plain `banktypes.MsgSend` and dispatched by the wasm module's message handler chain via `BankCoinTransferrer.TransferCoins`, which is the `CoinTransferrer` wired into the wasm keeper (`sei-wasmd/x/wasm/keeper/options.go` `WithCoinTransferrer`). `TransferCoins` only checks `IsSendEnabledCoins` and `BlockedAddr`, then calls `keeper.SendCoins` directly — it never calls `IsInDenomAllowList`. [1](#0-0) 

`BaseSendKeeper.SendCoins`/`sendCoinsWithoutAccCreation` themselves perform no allow-list enforcement either — that check exists solely in the `msgServer.Send` wrapper, not in the keeper's `SendCoins` method. [4](#0-3) 

Since a CosmWasm smart contract holding (or receiving) a restricted denom can freely issue `BankMsg::Send` messages, this internal transfer path bypasses the allow-list restriction the same way the JOJO `_withdraw`/internal-transfer bug bypassed `isDepositAllowed` — the "internal" transfer surface reuses the raw keeper primitive instead of the message-level guarded entry point.

### Impact Explanation
A token-factory denom creator can configure an `AllowList` to restrict who may hold/receive a compliance-sensitive or permissioned denom (e.g., KYC-gated tokens). Any CosmWasm contract that holds such a denom (e.g., received as `info.funds` during instantiation/execution, or minted to it) can route it to an address outside the allow list purely by emitting a `BankMsg::Send`, defeating the denom owner's access-control guarantee. This is an unauthorized-transfer / access-control-bypass condition on a permissioned asset, distinct from a simple accounting bug, and can be used to launder restricted tokens outside their intended distribution set.

### Likelihood Explanation
Reachable directly by any unprivileged user: deploy or interact with a CosmWasm contract that receives an allow-listed denom and issue an `Execute` that triggers a `BankMsg::Send` (as demonstrated by the reflect-contract test helpers already present in the codebase, e.g. `sei-wasmd/x/wasm/keeper/reflect_test.go`). No special privilege, governance, or validator collusion is required — only that a token-factory denom with an active allow list exists and a contract obtains a balance of it.

### Recommendation
Add the same `IsInDenomAllowList` check (for both `fromAddr` and `toAddr`) inside `BankCoinTransferrer.TransferCoins` in `sei-wasmd/x/wasm/keeper/keeper.go`, mirroring the logic in `sei-cosmos/x/bank/keeper/msg_server.go`'s `Send` handler, before calling `keeper.SendCoins`. Alternatively, route wasm bank-send dispatch through the bank module's `MsgServer.Send` rather than directly through the `SendKeeper.SendCoins` primitive so that all guarded checks stay centralized.

### Proof of Concept
1. Create a token-factory denom `factory/{creator}/restricted` and call `SetDenomAllowList` restricting it to a small set of addresses (excluding a target contract or a third-party recipient).
2. Fund a CosmWasm contract with `restricted` coins (e.g., via `MsgSend` from an allow-listed account to the contract, or via `Instantiate`/`Execute` with `info.funds`).
3. Have the contract execute a message that emits `wasmvmtypes.CosmosMsg{Bank: &wasmvmtypes.BankMsg{Send: {ToAddress: <address not in allow list>, Amount: [...]}}}` — as in the pattern used by `sei-wasmd/x/wasm/keeper/reflect_test.go`'s `TestReflectCustomMsg`.
4. Observe the transfer succeeds and funds land at the non-allow-listed address, whereas an equivalent plain `MsgSend` from a regular account to the same address is rejected with `"is not allowed to receive funds"` per `sei-cosmos/x/bank/app_test.go`'s `TestSendReceiverNotInAllowList`.

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
	for _, e := range em.Events() {
		if e.Type == sdk.EventTypeMessage { // skip messages as we talk to the keeper directly
			continue
		}
		parentCtx.EventManager().EmitEvent(e)
	}
	return nil
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

func (k BaseSendKeeper) sendCoinsWithoutAccCreation(ctx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {
	err := k.SubUnlockedCoins(ctx, fromAddr, amt, checkNeg)
	if err != nil {
		return err
	}

	err = k.AddCoins(ctx, toAddr, amt, checkNeg)
	if err != nil {
		return err
	}

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.EventTypeTransfer,
			sdk.NewAttribute(types.AttributeKeyRecipient, toAddr.String()),
			sdk.NewAttribute(types.AttributeKeySender, fromAddr.String()),

		),

			sdk.EventTypeMessage,
			sdk.NewAttribute(types.AttributeKeySender, fromAddr.String()),
		),
	})

	return nil
}
