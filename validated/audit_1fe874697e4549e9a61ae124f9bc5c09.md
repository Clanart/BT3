### Title
GaslessSwapRouter's `swapForGas()` Allows an Attacker-Controlled `minAmountOut` to Enable Sandwich Extraction of the Gasless User's Swap - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
`GaslessModule.checkBalanceForSwap()` only enforces that a `GaslessSwapTx`'s `minAmountOut` is `>= amountRepay` and that `amountIn >= gsr.GetAmountIn(token, minAmountOut)` at admission time [1](#0-0) . Nothing enforces that `minAmountOut` reflects a fair market rate for the declared `amountIn`; a gasless-tx sender (or a party crafting the swap payload) can set `minAmountOut` just above `amountRepay`, discarding the rest of the swap's actual output as "slippage." This mirrors the reported `VoltBurn.buyNSendToVoltTreasury()` bug class: a swap function that swaps a caller-controlled amount through an AMM with a caller-controlled, non-market minimum-output parameter is directly exploitable by a classic sandwich attack.

### Finding Description
The KIP-247 gasless flow bundles `[LendTx, ApproveTx?, SwapTx]` and the block proposer executes `GaslessSwapRouter.swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` on behalf of the user, whose "leftover" after repay becomes `FinalUserAmount` emitted in `SwappedForGas` [2](#0-1) . The transaction-pool-level readiness check `checkBalanceForSwap` requires only:
- `minAmountOut >= amountRepay`
- `amountIn >= GetAmountIn(token, minAmountOut)` (i.e., enough input to realize *at least* `minAmountOut`, evaluated against current on-chain reserves) [3](#0-2) 

There is no check that `minAmountOut` is close to the swap's fair-value output for the given `amountIn` (e.g., no bound like `getAmountOut(amountIn) * (1 - maxSlippage) <= minAmountOut`). A user (or anyone crafting a swap payload for execution, since the swap is executed by the router contract itself using AMM reserves at execution time) can pick `amountIn` large and `minAmountOut` barely above `amountRepay`. Because `GetAmountIn`/`GetAmountOut` are evaluated dynamically against the AMM's live reserves inside `GaslessSwapRouter`, an attacker who front-runs the swap (moving the pool price against the user) and back-runs it (reverting the pool price) can extract nearly all of the value between the "fair" output for `amountIn` and the degraded `minAmountOut` floor — exactly the sandwich mechanic described in the external report for `VoltBurn.buyNSendToVoltTreasury()`, where the caller-settable minimum-output amount is the only protection and can be set arbitrarily close to the repay/incentive floor instead of to the market rate.

### Impact Explanation
This is a Medium-risk MEV/value-extraction issue: an attacker with mempool visibility of pending `GaslessSwapTx`s can sandwich the router's internal AMM swap, extracting the difference between the fair-market output of `amountIn` and the degraded `minAmountOut`, which is meant to belong to the gasless user as `FinalUserAmount`. Since the router repays the proposer's lent gas from swap proceeds first [4](#0-3) , worst case the user's leftover token amount is squeezed toward the bare repay amount, effectively transferring value from the gasless-tx sender to the sandwiching party — an unauthorized value movement reachable from a single unprivileged transaction sender.

### Likelihood Explanation
Likelihood is Medium: any account can submit a `GaslessSwapTx` observed in the public mempool/tx pool, and the amount-in/minAmountOut relationship is only validated against pool reserves at admission time, not pinned to a slippage bound. A searcher watching the tx pool for gasless swaps with generous `amountIn`/`minAmountOut` gaps can systematically sandwich them without needing special privileges, similarly to how the original report's attacker sandwiches `VoltBurn.buyNSendToVoltTreasury()`.

### Recommendation
Enforce a bounded maximum slippage between the router's fair-value `GetAmountOut(amountIn)` and the declared `minAmountOut` in `checkBalanceForSwap` (and ideally inside `GaslessSwapRouter.swapForGas` itself), e.g., reject swap transactions where `minAmountOut < GetAmountOut(amountIn) * (1 - maxSlippageBps)`, so the router cannot be exploited via an artificially low `minAmountOut` while still nominally passing all current invariant checks.

### Proof of Concept
1. Attacker monitors the tx pool for a pending `GaslessSwapTx` where `swapArgs.MinAmountOut` is only marginally above `swapArgs.AmountRepay` (both values pass `checkBalanceForSwap` since only `minAmountOut >= amountRepay` and `amountIn >= GetAmountIn(minAmountOut)` are checked) [1](#0-0) .
2. Before the block containing the bundle `[LendTx, ApproveTx?, SwapTx]` is produced, attacker swaps into the pool to move reserves against the victim's swap direction.
3. Proposer executes the bundle; `GaslessSwapRouter.swapForGas` performs the AMM swap under the manipulated reserves, and since actual output only needs to clear the deflated `minAmountOut`, the router accepts a much worse rate; `FinalUserAmount` shrinks toward `amountRepay` [2](#0-1) .
4. Attacker swaps back immediately after, extracting the difference between the fair-value output and the degraded `minAmountOut` that the victim tolerated.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
