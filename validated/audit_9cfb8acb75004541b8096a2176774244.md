## Title
Blind SSRF to internal/loopback network via attacker-controlled remote credential URL in `isGitHubHost` - (File: `app/src/lib/api.ts`)

### Summary
When Git needs credentials for a remote (e.g. while fetching/cloning a repository whose submodule or remote points to an attacker-chosen host), GitHub Desktop's trampoline credential helper calls `getEndpointKind`, which — for unrecognized hosts — calls `isGitHubHost(endpoint)`. That function issues an outbound HTTP `HEAD` request to `${endpoint}/meta` built directly from the attacker-supplied host, with no allowlist/denylist for private, loopback, or link-local IP ranges. This mirrors the CCIP-Read pattern in the report: a contract/repository-controlled value (here, a git remote/submodule URL) drives an unsanitized outbound HTTP request from a trusted process.

### Finding Description
`isGitHubHost` in `app/src/lib/api.ts` builds a request straight from the caller-supplied `url`/`endpoint` without any destination policy: [1](#0-0) 

It is reached from the credential helper's `getEndpointKind`, whose `endpoint` is `getCredentialUrl(cred)` — populated from the `protocol`/`host`/`path` fields Git sends to the credential helper for whatever remote it's about to contact: [2](#0-1) [3](#0-2) 

The only gates before the network call are: known GitHub/gist hosts, known third-party hosts (bitbucket/gitlab), a hostname regex test, and a check for HTTPS protocol. If none of those apply, the code falls straight through to a live network request to `${endpoint}/meta` — the attacker only needs to pick an HTTPS-looking hostname/IP that doesn't match the `github`/`bitbucket`/`gitlab` regexes (e.g. an internal hostname, or an HTTPS listener on a private/loopback address) to trigger the fetch.

This request is triggered automatically, without user interaction, whenever Desktop performs a Git network operation (`clone --recursive`, `fetch --recurse-submodules=on-demand`, etc.) against a repository containing a submodule or remote pointing at an attacker-controlled host, since Git recurses into submodules and requests credentials per remote: [4](#0-3) [5](#0-4) 

### Impact Explanation
This gives an attacker a primitive to make GitHub Desktop's main process issue an outbound HTTPS request to a destination of their choosing (via a malicious `.gitmodules`/remote URL in a cloned or fetched repository), including hosts on the victim's internal network or loopback interface. The mitigations that exist (no credential attachment, `redirect: 'error'`, 2-second timeout, `HEAD` method, and only reading a single response header) constrain this to a **blind SSRF / internal network probing** primitive rather than full response exfiltration — the attacker learns at most a boolean signal (whether `x-github-request-id` header is present / whether the request succeeded within 2s), which can still be used for internal service/port discovery or as a building block for more severe issues (e.g., probing cloud metadata endpoints, triggering side effects on internal HTTP services that respond to `HEAD /meta`).

### Likelihood Explanation
Reaching this path only requires the victim to clone or fetch a repository that contains a submodule, or has a remote configured, pointing at an attacker-chosen HTTPS host — an unprivileged, entirely repository-driven action, consistent with the "attacker controls a cloned/fetched repository" impact category. `git fetch --recurse-submodules=on-demand` and `git clone --recursive` are used unconditionally by Desktop's fetch/clone code, so submodule remotes are contacted as part of normal, expected user workflows (opening/cloning a repo, pulling updates) without any extra unnatural steps.

### Recommendation
- In `isGitHubHost` (`app/src/lib/api.ts`), before issuing the `/meta` request, resolve and validate the destination is not a private/loopback/link-local address (RFC1918, 127.0.0.0/8, 169.254.0.0/16, ::1, fc00::/7, etc.), similar to SSRF guards used elsewhere.
- Consider gating this discovery request behind an explicit allowlist model or a user-visible prompt rather than silently probing arbitrary hosts derived from repository content.
- Ensure any future widening of this code path (e.g., following redirects, sending credentials, or reading response bodies) is done only after such validation is added.

### Proof of Concept
1. Attacker creates/publishes a public repository with a `.gitmodules` entry (or a remote) pointing to an internal-network HTTPS endpoint the victim can reach but the attacker cannot, e.g. `https://169.254.169.254/latest/meta-data/` or `https://internal-service.corp.local/`.
2. Victim clones or fetches this repository in GitHub Desktop, triggering `git clone --recursive` / `git fetch --recurse-submodules=on-demand`.
3. Git, needing credentials for the submodule host, invokes Desktop's credential helper (`getCredential` → `getEndpointKind`) with that host.
4. Since the host doesn't match `github`, `bitbucket`, or `gitlab` patterns and isn't a known account endpoint, `isGitHubHost` is called and issues a `HEAD` request to `https://<attacker-chosen-host>/meta` from the victim's machine/network position — confirming the SSRF primitive (reachability/response-header signal about an internal or otherwise attacker-inaccessible host).

**Note on verification limits:** I could not fully trace the exact conditions of `getIsBackgroundTaskEnvironment` or confirm whether this path also fires for background/scheduled fetches without any user-visible prompt (which would raise likelihood further), due to index size limits on some referenced files. A Devin session with full repository access would be needed to confirm end-to-end reachability including background fetch scheduling.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
