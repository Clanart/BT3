### Title
`Scanner::scan_block` reports coinbase outputs as received funds that are not yet spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over `block.txdata` including `txdata[0]` (the coinbase transaction) and returns every matched output as a `ReceivedOutput`. Outputs created by a coinbase transaction are encumbered by the 100-block coinbase maturity rule and cannot be spent until maturity. The returned `ReceivedOutput` carries no flag distinguishing an immature coinbase output from a normal spendable one, so a downstream consumer treating the scan result as "funds received" will register funds that are not actually spendable — an analogue of a withdrawal request being created without the step that actually releases the funds.

### Finding Description
`Scanner::scan` matches solely on `script_pubkey` in `scan_transaction` [1](#0-0) , and `scan_block` calls it over **all** transactions in the block, including the coinbase [2](#0-1) . A `ReceivedOutput` produced for a coinbase output is indistinguishable from a spendable one: same `offset`, `output`, `outpoint` fields [3](#0-2) .

The doc comment itself acknowledges the issue — "This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed" [4](#0-3)  — yet the function still returns the immature output with no marker and no enforcement. This is confirmed to be a real hazard in practice: the only production-style consumer, the processor's `get_outputs`, had to explicitly add `// Skip the coinbase transaction which is burdened by maturity` via `block.txdata[1 ..]` [5](#0-4) , proving the library's raw result is unsafe when used directly.

Like the reported bug (request created, actual fund movement omitted), the library performs the "receipt" half of the operation but omits the maturity gate required for the reported funds to be usable.

### Impact Explanation
An unprivileged party capable of mining a block (or any miner directing a coinbase output to the scanned address — e.g., an attacker pool miner paying to the victim's watch-only address) causes the scanner to report a `ReceivedOutput` for value that consensus rejects if spent for 100 blocks. Any downstream accounting/crediting logic built on `scan_block` (the natural API to call when scanning a block) records funds as received that cannot be moved — the "funds reported received that are not spendable" impact. If such an output is fed to `SignableTransaction::new`, the constructed spend will be invalid on-chain, and the funds remain stuck/uncreditable for the maturity window.

### Likelihood Explanation
Triggering requires only that a coinbase transaction pays to a registered script — something any miner can do unilaterally without victim cooperation. The vulnerable path (`scan_block` over `txdata` including index 0) is the default, documented call path; correctness depends entirely on every caller performing an undocumented-in-signature post-processing filter.

### Recommendation
Skip `txdata[0]` inside `scan_block` (mirroring the `block.txdata[1 ..]` guard already used downstream), or mark `ReceivedOutput` with an immaturity flag so consumers can defer crediting until the coinbase matures.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs
// A miner crafts a coinbase paying to `p2tr_script_buf(key)`.
let outputs = scanner.scan_block(&block);
// outputs[0] is a ReceivedOutput for the coinbase output.
// SignableTransaction::new(vec![outputs[0]], ...) builds a spend whose
// input consensus-invalid for 100 blocks — reported received, not spendable.
```
Contrast with the downstream fix already present: `for tx in &block.txdata[1 ..] { // Skip the coinbase transaction which is burdened by maturity }` [5](#0-4) .

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
