### Title
Peer-supplied identity nonce commitments force point-at-infinity panic in BIP-340 FROST signing - (File: networks/bitcoin/src/crypto.rs)

### Summary
The NimBLE bug class — a missing/NULL object dereferenced because a precondition was assumed rather than checked — maps onto Serai's Bitcoin FROST algorithm: the code assumes the aggregated nonce point `R` (and the group key `A`) are never the point at infinity, and unconditionally unwraps their x-coordinate. A malicious signing participant can send crafted `Commitments` (deserialized via `SignMachine::read_preprocess` / `Commitments::read`) that make the aggregated `R` the point at infinity, causing a panic in `x()`/`x_only()` during `sign_share`. No check rejects identity or adversarial commitments before this point.

### Finding Description
`Commitments::read` in `crypto/frost/src/nonce.rs:133-139` reads a fixed number of `(D, E)` generator commitments via `read_G`, which only enforces canonical encoding — the identity point is a canonical, accepted encoding. In `AlgorithmSignMachine::sign` (`crypto/frost/src/sign.rs:322-396`), per-participant binding factors `rho` are computed deterministically over all collected preprocesses, then `B.nonces(&nonces)` computes `R_n = Σ_l (D_l + rho_l·E_l)` at `crypto/frost/src/nonce.rs:194-211`. Because an attacker who transmits their preprocess last knows every other participant's `D_l, E_l` and can compute every `rho_l` themselves, they can solve for `D_att = -(Σ_{l≠att} bound_l) - rho_att·E_att`, forcing `R_n` to the identity. `sign_share` then calls `Hram::hram`, which calls `x(R)` at `networks/bitcoin/src/crypto.rs:65`, where `x()` does `encoded.x().expect("point at infinity")` (`crypto.rs:13-16`), panicking. The same panic exists in `x_only` (`crypto.rs:21-23`). The doc comments acknowledge the panic but claim "negligible probability" — true for random nonces, false for adversarially chosen commitments.

### Impact Explanation
A single malicious signing-set participant can deterministically crash every honest signer that calls `sign` on a preprocess map containing the attacker's preprocess, aborting the signing session and killing the signer process (panic, not a returned `Err`). This is a remotely triggerable denial of service against threshold signing availability using only public protocol messages fed to `read_preprocess`/`sign`.

### Likelihood Explanation
Requires the attacker to be one of the included signing participants and to deliver their preprocess after learning the others' (feasible when preprocess collection is not simultaneous). The attacker's preprocess is exactly the "untrusted bytes fed to read_preprocess / sign" reachability class. Deterministic once positioning is achieved.

### Recommendation
Reject identity (and optionally low-order) points in `Commitments::read`/`GeneratorCommitments::read` (`crypto/frost/src/nonce.rs:34-36`), or check the computed `R` for identity in `BindingFactor::nonces`/`sign_share` and return a `FrostError` instead of reaching `x()`. Additionally, `Hram::hram` should handle infinity gracefully (e.g., `Option`-returning `x`) rather than `expect`.
