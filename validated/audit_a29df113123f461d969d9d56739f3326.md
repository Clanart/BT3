### Title
Unbounded Python recursion in offer/CAT/singleton puzzle-driver matching enables wallet-crashing stack overflow via a malicious offer file - (File: chia/wallet/outer_puzzles.py)

### Summary
`chia/wallet/outer_puzzles.py`'s `match_puzzle()` recurses into itself indirectly through each outer-puzzle driver's `.match()` method whenever a puzzle reveal has an `also()` layer (CAT, singleton, ownership, metadata, credential-restricted/CR, revocation). There is no depth limit on this recursion, and Python (unlike the Rust CLVM interpreter) has a small default call-stack recursion limit (~1000 frames), with no `sys.setrecursionlimit` adjustment anywhere in the codebase.

### Finding Description
`match_puzzle()` iterates the driver table and calls `driver.match(puzzle)`: [1](#0-0) 

Each driver's `match()` (e.g. `CATOuterPuzzle.match`, `OwnershipOuterPuzzle.match`, `SingletonOuterPuzzle.match`, `CROuterPuzzle.match`) uncurries the puzzle and, if there is an inner layer, calls `self._match(UnknownPuzzle(known_program=inner_puzzle))`, which is bound back to `match_puzzle` (see `function_args = (match_puzzle, ...)` and `driver_lookup` construction): [2](#0-1) [3](#0-2) 

This creates unbounded mutual recursion: `match_puzzle → driver.match → match_puzzle → driver.match → ...`, one Python stack frame per curried layer in the puzzle reveal. An attacker can construct a puzzle with an arbitrarily deep chain of nested outer layers (e.g. `CAT(CAT(CAT(...(ACS))))`, or nested singleton/ownership layers), which is cheap to construct because `construct_cat_puzzle`/curry only adds a small constant amount of bytes per layer: [4](#0-3) 

Critically, this recursive matching happens purely at the Python structural/uncurry level — it does **not** run any CLVM and is **not** bounded by `MAX_BLOCK_COST_CLVM` or any mempool cost accounting. Unlike `sha256_treehash`, which was deliberately rewritten as an iterative stack-machine specifically "to avoid blowing out the python stack" for deeply nested CLVM trees: [5](#0-4) 
the outer-puzzle-driver matching code has no equivalent protection.

The reachable path is via untrusted offer files. `Offer.from_spend_bundle()` calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` for every coin spend in an offer supplied by a counterparty, before the offer is validated, signed, or pushed to the mempool: [6](#0-5) 
The same call happens again in `Offer._get_offered_coins()` when summarizing an offer: [7](#0-6) 
And offer parsing is triggered from the RPC endpoint `get_offer_summary` (`chia/wallet/wallet_rpc_api.py`) whenever a local RPC caller/UI loads an offer file (e.g. `request.parsed_offer.summary()`), or when a user runs `GetOffersCMD` / views a received `.offer` file: [8](#0-7) 

### Impact Explanation
Recursing past the Python interpreter's stack limit raises `RecursionError`, which in a CPython process running close to the C stack boundary can in some circumstances (deep enough recursion, small C stack, certain platforms/threads) cause a native stack overflow rather than a catchable Python exception, crashing the wallet process (`chia start wallet`) or the daemon serving it. Even in the milder case, `RecursionError` is unhandled at these call sites (no `try/except RecursionError` guarding `match_puzzle`, `from_spend_bundle`, `_get_offered_coins`, or `get_offer_summary`), so a single crafted offer causes an unhandled exception that aborts offer parsing/summary generation for the wallet — a transaction-processing halt for that wallet (equivalent to the CWA-2024-005 "unprivileged submitter triggers a stack overflow that halts processing" bug class, adapted from wasmd's contract-recursion case to chia's puzzle-driver recursion case). This matches the offer/trade-flow reachable analog explicitly permitted by scope ("offers and trades").

### Likelihood Explanation
High likelihood of reachability: any wallet user, offer counterparty, or local RPC caller who loads/imports an untrusted `.offer` file or receives an offer via RPC (`get_offer_summary`, `take_offer`, `GetOffersCMD`) triggers this code path automatically, with no signature or on-chain validation required first. Constructing the malicious puzzle reveal requires only curry-nesting standard CAT/singleton/ownership/CR modules, which is inexpensive and requires no special privileges — well within the "unprivileged wallet user / offer counterparty" threat model specified in scope.

### Recommendation
- Convert `match_puzzle` (and the corresponding `get_inner_puzzle`/`get_inner_solution`/`construct_puzzle` recursive chains through `also()`) to an iterative implementation that walks curried layers using an explicit loop/stack rather than Python call recursion, mirroring the approach already used in `sha256_treehash`.
- Alternatively, impose and enforce an explicit maximum nesting depth (e.g., a small constant reflecting realistic puzzle-stack depths used in production: CAT, singleton, ownership/metadata, CR, revocation ≈ 5–6 layers) and reject/raise a controlled error for puzzle reveals nested beyond that depth, before recursing.
- Wrap offer-parsing entry points (`Offer.from_spend_bundle`, `Offer.summary`, `get_offer_summary` RPC handler) to catch `RecursionError` and convert it into a normal validation failure instead of letting it propagate/crash the process.

### Proof of Concept
1. Build a deeply nested CAT (or singleton/ownership) puzzle reveal programmatically:
   ```python
   inner = Program.to(1)  # ACS
   for _ in range(5000):
       inner = construct_cat_puzzle(CAT_MOD, bytes32.zeros, inner)
   ```
   (`construct_cat_puzzle` used exactly as in `test_cat_outer_puzzle`.)
2. Place this puzzle reveal into a `CoinSpend` used to build an `Offer`/`SpendBundle` (e.g. as one of the `coin_spends` in a `WalletSpendBundle`), and serialize it to a `.offer` file / bech32 offer string.
3. Have a victim wallet call `GetOfferSummary` RPC (or `GetOffersCMD`, or `take_offer`) on the crafted offer:
   ```python
   await client.get_offer_summary(GetOfferSummary(offer=offer.to_bech32()))
   ```
4. Internally this reaches `Offer.from_spend_bundle` → `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))`, recursing once per curried CAT layer (5000 layers ≫ default recursion limit ~1000), producing an unhandled `RecursionError` / potential native stack overflow that aborts offer parsing in the wallet process.
