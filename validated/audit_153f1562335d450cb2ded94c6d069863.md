### Title
`ReceivedOutput::read` accepts an unvalidated `offset`/`TxOut` pair, letting untrusted bytes register credited-but-unspendable inputs — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput` couples three fields — a scalar `offset`, a `TxOut` (which carries the `value` and the `script_pubkey`), and an `OutPoint` — but `ReceivedOutput::read` deserializes all three without ever checking that `offset` is consistent with the output's `script_pubkey`. The class mirrors the Mango Markets incident: Mango treated a manipulable, attacker-influenced value (the MNGO price) as trustworthy collateral and credited borrowing power against it; here, an attacker-influenced serialization is treated as a trustworthy claim that "this UTXO, worth `value` sats, is spendable under `key + offset·G`". The value is credited unconditionally, while the spendability claim is false.

### Finding Description
`ReceivedOutput::read` reads the scalar via `Secp256k1::read_F`, then consensus-decodes the `TxOut` and `OutPoint`, and returns them verbatim with no consistency check. [1](#0-0)  The honest producer, `Scanner::scan_transaction`, only ever inserts an `offset` that genuinely satisfies `script_pubkey == p2tr(key + offset·G)`. [2](#0-1)  Nothing in the deserialization path enforces that invariant for bytes that did not come from `Scanner`.

Downstream, `ReceivedOutput::value()` returns `output.value` unconditionally, so the amount is credited to the wallet balance before spendability is ever tested. [3](#0-2)  The consistency check only happens at signing time in `SignableTransaction::multisig`, which recomputes `p2tr_script_buf(offset.group_key())` and returns `None` if it differs from `prevouts[i].script_pubkey`. [4](#0-3)  Meanwhile `SignableTransaction::new` sums `input.output.value` into `input_sat` for the funding/change/fee decision purely from the deserialized, unvalidated `TxOut`. [5](#0-4) 

### Impact Explanation
Any consumer that accepts `ReceivedOutput::read` output as a deposit/available-balance record will report funds as received that can never be spent: `balance`/`value` reflects the claimed amount, while `multisig()` can never produce a machine for the mismatched offset (returns `None`), so the "received" funds are phantom. Worse, a forged `ReceivedOutput` whose `TxOut.value` is inflated relative to the real on-chain output at `outpoint` inflates `input_sat`, causing `SignableTransaction::new` to compute change and payments against funds that don't exist — producing transactions that are either unspendable or consensus-invalid, directly analogous to Mango crediting $115M of borrow capacity against a manipulated collateral value. This is a reachable public-input path: `ReceivedOutput::read` is an untrusted-bytes entry point used for persisted/transported outputs.

### Likelihood Explanation
Exploitation requires an attacker to get malicious bytes into a `ReceivedOutput::read` call consumed by a wallet/scanner pipeline (e.g., untrusted serialized output records). No cryptographic break is needed — only the ability to supply crafted bytes, exactly the threat model `read` APIs on untrusted input must withstand. Severity is bounded because the signing-time check in `multisig()` prevents actually signing with the wrong key — the damage is phantom crediting and denial of spend, not theft — warranting Medium.

### Recommendation
Make `ReceivedOutput` self-validating: either (a) have `read` recompute `p2tr_script_buf(key + offset·G)` against the decoded `script_pubkey` — requiring the base `key` to be carried or supplied — or (b) store only the `OutPoint`/`TxOut` plus the offset's relation to a known key and verify on read that `output.script_pubkey` is in the `Scanner`'s registered `scripts` map, reusing the `HashMap<ScriptBuf, Scalar>` lookup instead of trusting the serialized scalar. [6](#0-5)  At minimum, verify the claimed `outpoint`/`value` against chain data before crediting `value()` to balance.

### Proof of Concept
```rust
// networks/bitcoin — concept demonstration
let real = scanner.scan_transaction(&tx).remove(0); // honest ReceivedOutput, offset s

// Attacker crafts bytes: same outpoint, TxOut with inflated value and/or
// an offset s' that does not correspond to the script_pubkey
let mut forged = real.clone().serialize();
// overwrite the scalar field with an arbitrary s' (e.g. s + 1), and/or
// bump TxOut.value — consensus_decode accepts any u64
let ro = ReceivedOutput::read(&mut forged.as_slice()).unwrap(); // accepted

ro.value();        // credited balance per the (possibly inflated) TxOut
// SignableTransaction::new(vec![ro], ...) uses the inflated value for
// input_sat, change, and fee math.
// SignableTransaction::multisig(&keys) returns None ->
// the credited output can never be signed for: funds reported received
// that are not spendable.
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
