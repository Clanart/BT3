### Title
Empty DLEq proof bypasses verification - (File: crypto/dleq/src/lib.rs)

### Summary
`DLEqProof::verify` checks only that `generators.len() == points.len()` and then iterates over their zipped entries. When both lists are empty, no statement is appended after the `dleq` domain separator, and the supplied proof only needs `c` to equal a deterministic, publicly computable challenge. [1](#0-0)  The same empty-statement acceptance exists in `MultiDLEqProof::verify`. [2](#0-1) 

### Finding Description
Neither `verify` implementation rejects an empty proof statement. `DLEqProof::read` also accepts arbitrary canonical `c` and `s` values without any semantic checks. [3](#0-2)  Consequently, an attacker can submit serialized proof bytes whose `c` equals `challenge(transcript.domain_separate(b"dleq"))`; verification succeeds without proving knowledge of any discrete logarithm.

### Impact Explanation
A verifier that accepts an empty generator/point list will accept a universally forgeable proof. Callers relying on a successful `verify` as evidence that at least one supplied point is bound to a known scalar can be given an affirmative result without any witness. [4](#0-3) 

### Likelihood Explanation
The proof requires no private key or secret share. Reachability depends on a verifier exposing or constructing an empty generator/point list for an untrusted `DLEqProof`; the in-scope PedPoP and generator-promotion callers use fixed non-empty lists, limiting the practical path. [5](#0-4) 

### Recommendation
Reject empty proof statements in `DLEqProof::prove`, `DLEqProof::verify`, `MultiDLEqProof::prove`, and `MultiDLEqProof::verify`. Also reject empty per-statement generator/point vectors in `MultiDLEqProof::verify`. [6](#0-5) [7](#0-6) 

### Proof of Concept
```rust
// crypto/dleq/src/lib.rs
let mut transcript = RecommendedTranscript::new(b"application transcript");
let scalar = Zeroizing::new(G::Scalar::random(&mut rng));

// prove() accepts an empty statement list.
let proof = DLEqProof::prove(&mut rng, &mut transcript, &[], &scalar);
let bytes = proof.serialize();
let received = DLEqProof::<G>::read(&mut bytes.as_slice()).unwrap();

// Verification succeeds even though no discrete-log statement was proven.
assert!(received
  .verify(&mut RecommendedTranscript::new(b"application transcript"), &[], &[])
  .is_ok());
```

```rust
  pub fn verify<T: Transcript>(
    &self,
    transcript: &mut T,
    generators: &[Vec<G>],
    points: &[Vec<G>],
  ) -> Result<(), DLEqError> {
    if points.len() != generators.len() {
      Err(DLEqError::InvalidProof)?;
    }
    if self.s.len() != generators.len() {
      Err(DLEqError::InvalidProof)?;
    }

    transcript.domain_separate(b"multi_dleq");
    for (i, (generators, points)) in generators.iter().zip(points).enumerate() {
      if points.len() != generators.len() {
        Err(DLEqError::InvalidProof)?;
      }

      transcript.append_message(b"discrete_logarithm", i.to_le_bytes());
      for (generator, point) in generators.iter().zip(points) {
        DLEqProof::verify_statement(transcript, *generator, *point, self.c, self.s[i]);
      }
    }

    if self.c != challenge(transcript) {
      Err(DLEqError::InvalidProof)?;
    }
```
