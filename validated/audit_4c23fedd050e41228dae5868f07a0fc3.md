## Title
Ignore-file feature fails to escape trailing whitespace in filenames, causing the generated `.gitignore` rule to silently not match the file — ([File: `app/src/lib/git/gitignore.ts`])

### Summary
`escapeGitSpecialCharacters` only escapes the glob metacharacters `[`, `]`, `!`, `*`, `#`, `?`, but does not escape (or reject) trailing whitespace in the filename before it is written into `.gitignore`. Git's own `.gitignore` parser strips trailing whitespace from each pattern unless it is escaped with a backslash. As a result, a file whose basename ends in a space (a filesystem-valid name that can be freely created by content shipped in a cloned/fetched repository or generated by a build step) will produce a `.gitignore` entry that no longer matches that file, defeating the very "Ignore file" action the user just performed in the UI.

### Finding Description
`escapeGitSpecialCharacters` is defined as: [1](#0-0) 

It is invoked by `appendIgnoreFile`, which is the function backing the "Ignore file" (and "Ignore file extension") context-menu actions in Changes sidebar: [2](#0-1) 

The escaped pattern is appended verbatim as a new line to the repository's `.gitignore` via `appendIgnoreRule` → `formatGitIgnoreContents` → `saveGitIgnore`: [3](#0-2) 

Git's gitignore pattern-matching rules ("gitignore(5)") specify that trailing spaces are trimmed from each line unless the last space is escaped with a backslash (`\ `). Since `escapeGitSpecialCharacters`'s regex `/[\[\]!\*\#\?]/g` does not match whitespace, a filename such as `secret ` (trailing space) is written to `.gitignore` unmodified as `secret \n`. When git parses this line, it strips the trailing space, producing the effective pattern `secret`. That pattern does not match the literal file `secret ` (exact match required for a name with no other glob characters), so the ignore rule is a no-op against the actual file.

### Impact Explanation
This directly matches the "silent loss/misrepresentation of what will be committed" impact category described in scope: after using the UI's "Ignore file" action, GitHub Desktop reports and persists a `.gitignore` entry that the user reasonably believes now excludes the file, but `git status`/`git add .`/commit will still pick the file up. In a supply-chain-relevant scenario, an attacker who controls repository content (e.g. via a cloned/fetched malicious repo, or a generated artifact with a crafted trailing-space name) can rely on this silent mismatch to get the user to unintentionally commit and push a file they explicitly tried to exclude.

### Likelihood Explanation
Trailing-space filenames are trivially creatable on the filesystems GitHub Desktop supports (they are rejected on Windows Explorer for some operations, but valid via most APIs, and definitely valid on macOS/Linux, and can be produced by tools/scripts extracted from a cloned repo). The user only needs to perform the completely ordinary action of right-clicking the file in the Changes list and choosing "Ignore file" — no unusual steps are required.

### Recommendation
- Escape trailing whitespace (and any other characters requiring escaping per `gitignore(5)`, such as a leading `!`, `#`, or trailing `/` ambiguity) in `escapeGitSpecialCharacters`, e.g. by escaping the final space(s) with a backslash (`pattern.replace(/ +$/, m => m.replace(/ /g, '\\ '))`), or by anchoring the pattern differently.
- Add a regression test mirroring the existing `appendIgnoreFile` special-character test but using a trailing-space filename, asserting that `git status` no longer reports the file after the ignore rule is applied.

### Proof of Concept
1. In a test repository, create a file named `secret ` (note trailing space): `touch "secret "`.
2. In GitHub Desktop, right-click the untracked file `secret ` in the Changes sidebar and choose "Ignore file".
3. Inspect `.gitignore`: it now contains a line `secret ` (trailing space preserved, since `escapeGitSpecialCharacters` does not touch it).
4. Run `git check-ignore -v "secret "` or `git status` — the file is still reported as untracked, because git trims the trailing space from the pattern when reading `.gitignore`, effectively ignoring `secret` and not `secret `.
5. Run `git add .` / commit — `secret ` is staged and committed despite the user having explicitly told GitHub Desktop to ignore it.

The relevant existing unit tests confirm only glob-metacharacter escaping is exercised, with no coverage for whitespace: [4](#0-3)  and [5](#0-4) .

```typescript
/** Add the given pattern or patterns to the root gitignore file */
export async function appendIgnoreRule(
  repository: Repository,
  patterns: string | string[]
): Promise<void> {
  const text = (await readGitIgnoreAtRoot(repository)) || ''

  const currentContents = await formatGitIgnoreContents(text, repository)

  const newPatternText =
    patterns instanceof Array ? patterns.join('\n') : patterns
  const newText = await formatGitIgnoreContents(
    `${currentContents}${newPatternText}`,
    repository
  )

  await saveGitIgnore(repository, newText)
}
```

```typescript
export async function appendIgnoreFile(
  repository: Repository,
  filePath: string | string[]
): Promise<void> {
  if (filePath instanceof Array) {
    const escapedFilePaths = filePath.map(path =>
      escapeGitSpecialCharacters(path)
    )

    return appendIgnoreRule(repository, escapedFilePaths)
  }

  const escapedFilePath = escapeGitSpecialCharacters(filePath)
  return appendIgnoreRule(repository, escapedFilePath)
}
```

```typescript
/** Escapes a string from special characters used in a gitignore file */
export function escapeGitSpecialCharacters(pattern: string): string {
  const specialCharacters = /[\[\]!\*\#\?]/g

  return pattern.replaceAll(specialCharacters, match => {
    return '\\' + match
  })
}
```
