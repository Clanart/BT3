## Title
Committer identity spoofing bypasses `isWebFlowCommitter` provenance check, hiding the true committer of a cloned/fetched commit - (File: `app/src/lib/web-flow-committer.ts`)

### Summary
GitHub Desktop uses a heuristic, `isWebFlowCommitter`, to decide whether a commit's `committer` field represents a trustworthy proxy — GitHub's own web-flow merge/squash service — as opposed to a real, distinct human committer. This check is based purely on plain-text git commit metadata (`committer.name` / `committer.email`) that ships inside any repository the user clones, fetches, or pulls. Because that metadata is fully attacker-controlled, anyone can forge a commit whose committer looks like GitHub's official web-flow identity, causing Desktop to suppress the real committer's identity from the UI.

### Finding Description
`isWebFlowCommitter` treats a commit as "committed via GitHub's web UI" purely based on the committer name/email strings baked into the commit object: [1](#0-0) 

This is the same class of flaw as the `CreatorStory` issue: a value that is supposed to represent an authoritative, trusted actor ("GitHub itself performed this merge") is derived from data the untrusted party (whoever authored/pushed the commit) fully controls, with no cryptographic or server-side verification (no GPG/SSH signature check, no confirmation against the GitHub API). Just as any NFT owner could impersonate the Creator by emitting `CreatorStory`, any git user can impersonate GitHub's web-flow bot by simply setting `committer.name = 'GitHub'` and `committer.email = 'noreply@github.com'` (or `'GitHub Enterprise'` for GHES) via `GIT_COMMITTER_NAME`/`GIT_COMMITTER_EMAIL` (or `git commit --author`/rebase with committer date env overrides) before pushing/sharing the repository.

`isWebFlowCommitter`'s result feeds directly into `getAvatarUsersForCommit`, which decides whether to show the committer as a separate identity in the UI: [2](#0-1) 

When `webFlowCommitter` is `true`, Desktop suppresses the committer avatar entirely — even though `authoredByCommitter` is `false` (i.e., there really is a distinct committer identity attached to the commit). This function is called from multiple provenance-display surfaces: the commit list row tooltip and the expanded commit summary: [3](#0-2) [4](#0-3) 

No existing guard revalidates this against server-side truth: there is no signature check, no correlation with `repository.gitHubRepository`'s actual API data about who performed the merge, and the endpoint-name match for GHES is explicitly documented as a "best-effort" heuristic that can't verify authenticity.

### Impact Explanation
An attacker who controls a cloned/fetched repository (or a fork a victim adds as a remote) can craft commits that spoof GitHub's web-flow committer identity. This silently corrupts what the user is shown as the provenance of a commit — hiding the real committer identity from the avatar/author list in commit history views, making a manually-crafted, potentially malicious commit look like it came through GitHub's trusted, automated merge flow (e.g., a "clean" squash-merge) rather than from an arbitrary human. This can be used to make socially-engineered or supply-chain-tainted commits appear more legitimate/trustworthy in Desktop's UI, undermining a user's ability to judge commit provenance before reviewing, checking out, or pushing further work on top of it.

### Likelihood Explanation
Trivial to exploit: forging committer name/email requires only standard git plumbing (`GIT_COMMITTER_NAME`/`GIT_COMMITTER_EMAIL` env vars, `git commit-tree`, or interactive rebase with `--committer-date-is-author-date` style tooling) — no special access, no server compromise, and no interaction beyond the victim cloning/fetching/opening the repository in Desktop. The check is purely client-side string matching against two hardcoded literal identity strings, so bypassing the intended trust boundary is deterministic and repeatable.

### Recommendation
Do not rely solely on locally-controlled commit metadata to assert that a commit was produced by GitHub's web-flow. Either drop the visual distinction entirely, or corroborate the claim against a value the attacker cannot control — e.g., cross-check against the GitHub API's pull request/merge event metadata for that specific SHA (via `gitHubRepository`) before suppressing the committer avatar, or require a valid GPG/SSH commit signature verifiable against GitHub's known web-flow signing key before treating a commit as GitHub-authored.

### Proof of Concept
1. Clone or add as a remote an attacker-controlled repository.
2. Attacker crafts a commit locally with:
   ```
   GIT_COMMITTER_NAME="GitHub" GIT_COMMITTER_EMAIL="noreply@github.com" \
     git commit --author="Mallory <mallory@evil.example>" -m "Legit-looking change"
   ```
3. Attacker pushes this branch/PR or otherwise shares the ref; victim fetches/pulls it into GitHub Desktop.
4. In Desktop's commit history, `isWebFlowCommitter` (`app/src/lib/web-flow-committer.ts:15-49`) returns `true` for this commit against a `dotcom` `gitHubRepository`, so `getAvatarUsersForCommit` (`app/src/models/avatar.ts:53-79`) omits the "committer" identity from the author list — the commit displays as if it were authored and merged through GitHub's own web flow, hiding the fact that `Mallory` independently forged the committer field to imitate GitHub.

```typescript
export function isWebFlowCommitter(
  commit: Commit,
  gitHubRepository: GitHubRepository
) {
  if (!gitHubRepository) {
    return false
  }

  const endpoint = gitHubRepository.owner.endpoint
  const { name, email } = commit.committer

  if (
    endpoint === getDotComAPIEndpoint() &&
    name === 'GitHub' &&
    email === 'noreply@github.com'
  ) {
    return true
  }

  if (endpoint !== getDotComAPIEndpoint() && name === 'GitHub Enterprise') {
    // We can't assume that the email address will match any specific format
    // here since the web flow committer email address on GHES is the same as
    // the noreply email which can be configured by domain administrators so
    // we'll just have to assume that for a GitHub hosted repository (but not
    // GitHub.com) a commit author of the name 'GitHub Enterprise' is the web
    // flow author.
    //
    // Hello future contributor: Turns out the web flow committer name is based
    // on the "flavor" of GitHub so it's possible that you're here wondering why
    // this isn't working and chances are it's because we've updated the
    // GHES branding or introduced some new flavor.
    return true
  }

  return false
```

```typescript
export function getAvatarUsersForCommit(
  gitHubRepository: GitHubRepository | null,
  commit: Commit
) {
  const avatarUsers = []

  avatarUsers.push(getAvatarUserFromAuthor(commit.author, gitHubRepository))
  avatarUsers.push(
    ...commit.coAuthors.map(x => getAvatarUserFromAuthor(x, gitHubRepository))
  )

  const coAuthoredByCommitter = commit.coAuthors.some(
    x => x.name === commit.committer.name && x.email === commit.committer.email
  )

  const webFlowCommitter =
    gitHubRepository !== null && isWebFlowCommitter(commit, gitHubRepository)

  if (
    !commit.authoredByCommitter &&
    !webFlowCommitter &&
    !coAuthoredByCommitter
  ) {
    avatarUsers.push(
      getAvatarUserFromAuthor(commit.committer, gitHubRepository)
    )
  }
```
