## Analog Found

### Title
Single, unauthenticated `WWW-Authenticate` heuristic in `getEndpointKind()` misclassifies an arbitrary host as GitHub Enterprise, triggering an OAuth sign-in prompt for an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The seed report flags a single hardcoded choice (`poolFee`) that is trusted without validating it against the real, variable conditions (liquidity/fee tiers per pair), making the outcome unreliable/exploitable. The Desktop analog is `getEndpointKind()`, which makes a single, cheap, attacker-influenced heuristic decision — "does any `wwwauth[...]` credential field contain `realm="GitHub"`?" — and treats that as authoritative proof that a remote host is a GitHub Enterprise endpoint, without ever verifying it the way the code's own fallback path does (`isGitHubHost`, which performs an actual `/meta` probe and checks for the `x-github-request-id` response header).

### Finding Description
`getEndpointKind()` in [1](#0-0)  classifies the endpoint that Git's credential helper is being asked about into `'github.com' | 'ghe.com' | 'enterprise' | 'generic'`. Before falling back to the network-verified `isGitHubHost()` probe, it inspects `wwwauth[...]` credential fields — values that originate directly from the `WWW-Authenticate` HTTP response header sent by whatever server Git is talking to: [2](#0-1) 

This header is fully attacker-controlled: any server that Git's HTTP transport connects to (a malicious clone/fetch URL, a hostile submodule URL discovered inside an untrusted cloned repository, a malicious LFS endpoint, or a MITM/corporate proxy in the request path) can respond `401 WWW-Authenticate: Basic realm="GitHub"` for literally any hostname. Git captures this header and forwards it verbatim to the trampoline credential helper (documented in the same comment block), and `getEndpointKind()` treats a single string match (`v.includes('realm="GitHub"')`) as sufficient to short-circuit and return `'enterprise'` — skipping the actual verification (`isGitHubHost`, which does a real HTTPS request and checks for the `x-github-request-id` header) entirely.

That classification feeds directly into `getCredential()`: [3](#0-2) 

Because the attacker's host is not a known account endpoint, `accounts.some(a => a.endpoint === apiEndpoint)` is `false`, and since `endpointKind !== 'generic'` (it's `'enterprise'`), Desktop calls `ui.promptForGitHubSignIn(endpoint)` — prompting the user to sign in to what the UI presents as a GitHub Enterprise instance, using the attacker-controlled `endpoint` value, instead of falling back to the generic-credential/external-credential-helper path that would be used for a non-GitHub host.

### Impact Explanation
This corrupts the trust decision "is this a GitHub Enterprise host that deserves an OAuth sign-in flow and stored account binding?" The corrupted value is the return of `getEndpointKind()` (`'enterprise'` instead of `'generic'`), and by extension the `endpoint` string passed into `ui.promptForGitHubSignIn()`. The consequence matches the "unauthorized OAuth or account binding" impact category: a user cloning/fetching from, or being redirected through, an attacker-operated Git host can have Desktop initiate and complete an OAuth/device sign-in flow and persist a resulting `Account` bound to the attacker's endpoint in the account store, and subsequently route stored GitHub credentials/tokens toward requests scoped to that endpoint via the credential helper's account-lookup logic (`findGitHubTrampolineAccount`/`credWithAccount`).

### Likelihood Explanation
The attacker primitive required is exactly one of the accepted classes: control of a git remote/proxy response. No local access, admin rights, or pre-existing malware is needed — an attacker only needs Git to make an HTTP(S) request to a server they control (e.g., via a cloned repo's submodule URL, an LFS endpoint, or a network path they can intercept) and to answer with a crafted `WWW-Authenticate` header. The existing guard that should prevent this — an actual network-verified check like `isGitHubHost()` — is bypassed by design (`return 'enterprise'` happens before `isGitHubHost` is ever called), so the guard does not stop this path.

### Recommendation
Do not treat the `WWW-Authenticate: realm="GitHub"` heuristic as authoritative for granting `'enterprise'` classification (which gates the GitHub sign-in prompt and account-endpoint checks). At minimum, corroborate it with the same network verification used in the fallback branch (`isGitHubHost`) before triggering `ui.promptForGitHubSignIn`, or treat the heuristic only as a hint that lowers the timeout/skips redundant checks rather than as a substitute for verification.

### Proof of Concept
1. Attacker hosts a Git-over-HTTPS server (or MITM proxy) at `https://evil.example.com/x/y.git`, or gets a victim to add/fetch a submodule pointing there.
2. Victim runs a Git network operation against it (`clone`, `fetch`, `pull`) through Desktop.
3. Attacker's server responds to Git's authentication probe with `401 WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this as a `wwwauth[...]` field to Desktop's credential helper (`createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`), which matches `v.includes('realm="GitHub"')` and returns `'enterprise'` without ever calling `isGitHubHost`.
5. Since no account exists for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, presenting the user a GitHub-style sign-in prompt for the attacker's host.
6. If the user proceeds (e.g., believing it's a legitimate internal GHE instance), the account gets created/bound to `evil.example.com`, and future credential lookups for that origin will be treated as first-party GitHub credentials rather than generic/unauthenticated ones.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
