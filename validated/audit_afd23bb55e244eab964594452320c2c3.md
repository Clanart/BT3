## Title
`_paused` flag in IntentGatewayV2 is declared but never enforced on `fillOrder`/`cancelOrder`/escrow release - (File: `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
`IntentsBase.sol` declares a `bool public _paused` storage slot, explicitly commented as "Appended last to preserve existing storage slots" — i.e., it was added after initial deployment specifically to serve as an emergency-pause switch. However, no function in the Intent Gateway (`IntentGatewayV2.sol`, `IntrinsicIntents.sol`, `ExtrinsicIntents.sol`, `IntentsBase.sol`) ever reads this variable. This is the same bug class as the OrangeLayer report: a pause flag exists and can be set, but the critical fund-moving entry points do not check it, so pausing has no effect.

### Finding Description
`_paused` is declared at [1](#0-0) . Searching the entire intents app surface (`fillOrder`, `cancelOrder`, `select`, `_fillSameChain`, `_fillCrossChain`, `_cancelSameChain`, `_cancelFromSource`, `_cancelFromDest`, `_withdraw`, `onAccept`) shows zero references to `_paused` outside its declaration.

The public entry points that move escrowed funds have no pause guard at all:
- `fillOrder()` — validates deadline, chain routing, `_filled` state, and solver-selection, but never checks `_paused`: [2](#0-1) 
- `cancelOrder()` — same absence of any pause check: [3](#0-2) 
- `_withdraw()`, the internal function that releases escrowed tokens to a beneficiary on fill/refund/settlement, also has no pause check: [4](#0-3) 

Compare this to other Hyperbridge apps in the same repo, which correctly gate every fund-moving/cross-chain entry point behind `whenNotPaused`, e.g. `HyperFungibleToken.send/onAccept/onPostRequestTimeout/transfer/transferFrom` [5](#0-4) [6](#0-5) , and `HyperbridgeLzEndpoint.send/onAccept` [7](#0-6) . The Intent Gateway is the odd one out: it has the storage variable for a pause switch but never wires it into the guarded functions.

### Impact Explanation
The Intent Gateway custodies user escrow (input tokens) and settles cross-chain swaps by releasing that escrow to solvers or refunding users. `_paused` is clearly intended as an emergency kill-switch (comment: "Appended last to preserve existing storage slots" implies it was added post-deployment as a safety mechanism). If governance ever flips `_paused = true` in response to a discovered issue (e.g., a price-oracle manipulation, a solver-selection bypass, or any other actively-exploited bug in the fill/cancel/settlement logic), solvers and users can keep calling `fillOrder()`, `cancelOrder()`, and triggering escrow release via `onAccept()`/`_withdraw()` completely unaffected. This directly matches the required impact class: unauthorized execution / continued fund movement during a state that the protocol explicitly intended to block, defeating the incident-response mechanism and enabling continued draining of escrow through whatever vector prompted the pause.

### Likelihood Explanation
This requires no privileged actor, relayer, or prover compromise — it is a pure missing-guard bug reachable by any ordinary solver or user through the standard, permissionless `fillOrder`/`cancelOrder` entry points. It is only "triggered" the moment governance attempts to use the pause switch, at which point the bug guarantees the protection is completely ineffective — identical in structure and severity to the referenced OrangeLayer finding.

### Recommendation
Add a `whenNotPaused` modifier (checking `_paused`) to `fillOrder()`, `cancelOrder()`, `select()`, and the settlement/withdraw code paths (`_withdraw`, and the `onAccept` dispatch handling `RedeemEscrow`/`RefundEscrow`), and add governance-only `pause()`/`unpause()` setters if none currently exist for `_paused`.

### Proof of Concept
1. Governance calls the (currently unimplemented/unused) pause mechanism, setting `_paused = true` in `IntentsBase` storage, intending to halt all order activity.
2. A solver calls `IntentGatewayV2.fillOrder(order, options)`: [2](#0-1)  — none of the checks in this function reference `_paused`, so execution proceeds normally, `_fillSameChain`/`_fillCrossChain` runs, and escrowed input tokens are released to the solver.
3. Similarly, `cancelOrder()` can still be called and will process refunds via `_withdraw()`, which also never checks `_paused`: [4](#0-3) .
4. Result: the pause has zero effect on fund movement, exactly reproducing the "pausing claims does not work" bug class from the external report, but for order fills/refunds/escrow release in the Intent Gateway.

        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});

        }

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        if (order.deadline < _blockNumber()) revert Expired();
        bytes32 commitment = keccak256(abi.encode(order));

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain && orderSource != currentChain) revert WrongChain();
        if (!isSameChain && orderDest != currentChain) revert WrongChain();

        if (_filled[commitment] != address(0)) revert Filled();

        if (_params.solverSelection) {
            bytes32 storedSelectionHash;
            assembly {
                storedSelectionHash := tload(commitment)
            }

            bytes32 expectedSelectionHash = keccak256(abi.encode(msg.sender, order.session));
            if (storedSelectionHash != expectedSelectionHash) revert Unauthorized();
        }

        uint256 outputsLen = order.output.assets.length;
        if (options.outputs.length != outputsLen) revert InvalidInput();
        if (order.inputs.length != outputsLen) revert InvalidInput();

        if (isSameChain) {
            _fillSameChain(order, options, commitment);
        } else {
            _fillCrossChain(order, options, commitment);
        }

        if (_params.priceOracle != address(0)) {
            IIntentPriceOracle(_params.priceOracle)
                .recordSpread(commitment, order.source, order.inputs, options.outputs);
        }
    }

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable nonReentrant {
        bytes32 commitment = keccak256(abi.encode(order));

        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            _cancelSameChain(order, commitment);
        } else if (currentChain == orderSource) {
            _cancelFromSource(order, options, commitment);
        } else if (currentChain == orderDest) {
            _cancelFromDest(order, options, commitment);
        } else {
            revert WrongChain();
        }
    }
}
