### Title
Aggregator disables self-only enforcement for `Internal`-prefixed RPCs when `client_verification=false`, exposing `InternalGetEmergencyStopTx` to unauthenticated callers - (File: core/src/servers.rs, core/src/rpc/interceptors.rs)

### Summary
`create_grpc_server` selects the `Interceptors::Noop` interceptor instead of `Interceptors::OnlyAggregatorAndSelf` whenever `config.client_verification == false` [1](#0-0) . `create_aggregator_grpc_server` merely logs a warning if `client_verification` is enabled and never forces it to `true` for the aggregator [2](#0-1) , so on any aggregator deployed with `client_verification=false` the `is_internal()`/self-cert check in `only_aggregator_and_self` is never invoked, letting an unauthenticated caller reach `Internal`-prefixed RPCs such as `InternalGetEmergencyStopTx`.

### Finding Description
The security binding the code intends to enforce is: `caller reaching a method whose grpc-method starts with "Internal"` ⟺ `leaf_cert == our_cert`, implemented in `only_aggregator_and_self` [3](#0-2) . This check is only reached when the server is wrapped with `Interceptors::OnlyAggregatorAndSelf`. `create_grpc_server` picks that interceptor only `if config.client_verification` is `true`; otherwise it wraps the service in `Interceptors::Noop`, which passes every request through untouched [4](#0-3) [5](#0-4) . `create_aggregator_grpc_server` does not override or force `client_verification`; it only emits a `tracing::warn!` when the flag happens to be `true`, and unconditionally calls the shared `create_grpc_server` with whatever `config.client_verification` was set to [6](#0-5) . Thus, once an operator deploys the aggregator with `client_verification=false` (which also disables the TLS `client_ca_root` requirement, meaning no client certificate is required at the TLS layer at all [7](#0-6) ), the `is_internal` gate is structurally unreachable: an attacker can open a plain HTTP/2 TLS connection with no client cert and call `/clementine.ClementineAggregator/InternalGetEmergencyStopTx` directly. There is no other authorization check on the aggregator's `InternalGetEmergencyStopTx` handler itself; the only gate for "Internal" methods is the interceptor.

### Impact Explanation
Whether this rises to a listed impact category depends on what `InternalGetEmergencyStopTx` actually returns/does, which I could not fully inspect (`core/src/rpc/aggregator.rs` handler body and `core/src/rpc/clementine.rs`/`clementine.proto` message semantics for emergency-stop were only partially retrieved before the budget ran out). Based on the naming convention ("Get..."), this is most plausibly a read/query call that returns the (partially or fully) signed emergency-stop transaction/signature material rather than one that itself broadcasts a Bitcoin transaction or mutates verifier/operator state. If so, the concrete impact is premature disclosure of a protocol commitment (the emergency-stop transaction and/or its signature) to an unauthenticated party, which is explicitly listed as a High-severity category. I cannot confirm from the code inspected here whether calling it also triggers broadcast or any state change, which would be required to classify it under "unauthenticated state-changing or broadcasting call" instead — that classification is not proven with the evidence gathered.

### Likelihood Explanation
The precondition is a deployment-configuration choice: the aggregator's `client_verification` field must be `false`. The code does not force `client_verification=true` for the aggregator and only warns when it is enabled, which is the opposite of enforcement, so this is a real, reachable misconfiguration rather than a purely theoretical one — but it is configuration-dependent, not a default-independent code defect. Given that precondition, the attack costs nothing (no BTC, no fees) and is trivially repeatable — the attacker just needs network access to the aggregator's gRPC port and can send the raw HTTP/2 request without any TLS client certificate.

### Recommendation
Have `create_aggregator_grpc_server` unconditionally require `client_verification` (or otherwise unconditionally construct `Interceptors::OnlyAggregatorAndSelf` for `Internal`-prefixed methods) instead of only warning, so the self-only guarantee for `Internal` RPCs cannot be disabled by configuration. Alternatively, enforce the `Internal` check independent of `client_verification`/TLS peer certs (e.g., reject all `Internal`-prefixed calls at the service layer when TLS client verification is off, rather than relying solely on the interceptor selection).

async fn test_internal_rpc_bypass_when_client_verification_disabled() {
    // 1. Build a BridgeConfig with client_verification = false, matching the
    //    aggregator's own only-warns-but-never-forces behavior in
    //    create_aggregator_grpc_server (core/src/servers.rs).
    let mut config = create_test_config().await;
    config.client_verification = false;

    let (addr, _shutdown) = create_aggregator_grpc_server(config).await.unwrap();

    // 2. Connect with a bare, uncertified TLS/H2 channel (no client cert supplied).
    let channel = tonic::transport::Channel::from_shared(format!("https://{}", addr))
        .unwrap()
        .tls_config(tonic::transport::ClientTlsConfig::new()) // no identity()
        .unwrap()
        .connect()
        .await
        .unwrap();

    let mut client = ClementineAggregatorClient::new(channel);

    // 3. Call the Internal-prefixed RPC directly.
    let resp = client.internal_get_emergency_stop_tx(EmergencyStopRequest { .. }).await;

    // Binding under test: is_internal(req) => leaf_cert == our_cert.
    // With client_verification=false, Interceptors::Noop is used, so is_internal
    // is never evaluated and the call must succeed despite presenting no certificate.
    assert!(resp.is_ok(), "Internal RPC should be reachable without any client cert when client_verification=false");

    // 4. Contrast: repeat with config.client_verification = true and the same
    //    no-cert channel; per only_aggregator_and_self this must fail with
    //    Status::unauthenticated("Failed to verify peer certificate, is TLS enabled?").
}

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;
