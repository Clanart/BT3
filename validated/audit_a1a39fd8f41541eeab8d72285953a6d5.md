### Title
Schnorr half-aggregation weights do not bind the prover-supplied nonces `Rs`, enabling universal forgery of `SchnorrAggregate` - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` derives the per-signature aggregation weights `z_i` solely from a transcript of the externally-supplied challenges. The prover-supplied nonces `Rs` and the aggregate scalar `s` are never hashed into the weight derivation. Because the weights are fully predictable before the attacker chooses `Rs`, anyone can forge an aggregate signature that verifies for an arbitrary set of public keys and messages — the exact analog of the reported bug class, where values influencing verification come from prover-supplied data rather than from data bound into the verified statement.

### Finding Description
In `verify` (crypto/schnorr/src/aggregate.rs:127-146), the digest transcript is seeded with only `dst` and the list of challenges:

```rust
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
```

Then for each `(key, challenge)` pair the weight `z = weight(&mut digest)` is drawn and the statements `(z, Rs[i])` and `(z * challenge, key)` are queued, closing with `(-s, generator)`. The checked equation is:

```
Σ_i z_i·R_i + Σ_i z_i·c_i·A_i − s·G == 0
```

`z_i` depends only on the challenges and `i`. An attacker who picks `s` and the `R_i` values last can satisfy this equation for keys they do not control: choose `s` freely, compute all `z_i` publicly, then set `R_i = t_i·G − c_i·A_i` for any scalars `t_i` with `Σ z_i·t_i = s` (e.g., `t_0 = s·z_0⁻¹`, `t_i = 0` for `i > 0`; in the negligible case `z_0 = 0`, distribute over several indices). Substitution yields `Σ z_i(t_i·G − c_i·A_i) + z_i·c_i·A_i − s·G = (Σ z_i t_i − s)·G = 0`, so `multiexp_vartime(&pairs).is_identity()` returns true.

The honest aggregation path (`SchnorrAggregator::aggregate`/`complete`, lines 169-185) uses the identical weight derivation, so this is a verifier-side soundness failure, not a prover/verifier mismatch. The half-aggregation scheme (eprint 2021/350) requires the randomizing weights to be unpredictable to the party fixing `R`; making them a deterministic function of public inputs while leaving `Rs` unbound removes that property entirely.

### Impact Explanation
`SchnorrAggregate` is deserializable from untrusted bytes via `SchnorrAggregate::read` (lines 77-88), and `verify` is reachable by any unprivileged party supplying `(keys_and_challenges, Rs, s)`. The result is a forged aggregate Schnorr signature accepted under public keys whose private keys the attacker does not know — a direct signature forgery, matching the "forged proof or signature" acceptance criterion.

### Likelihood Explanation
Exploitation requires no secret material, no interaction, and no special position: the attacker only needs the victim public keys and the challenges that would legitimately be computed for the target messages (both public). The weight function `weight` is pure transcript output over attacker-known data, so the forgery is deterministic and always succeeds (modulo the negligible all-`z_i`-zero edge case, avoided by choosing multiple nonzero `t_i`). Certain exploitability whenever an application accepts `SchnorrAggregate` proofs from untrusted parties.

### Recommendation
Bind every signature component into the weight transcript before deriving weights. Concretely, append each `Rs[i]` (and the public keys, or a commitment to the full statement list) to `digest` before calling `weight`, so `z_i` commits to the very `R_i` it multiplies — matching the paper, where weights hash the fixed signature list. Both `SchnorrAggregate::verify` and `SchnorrAggregator::new`/`aggregate`/`complete` must be updated in lockstep so honest aggregates remain verifiable, and the on-wire weight function version should be bumped to avoid cross-version collisions.

### Proof of Concept
Reachable via `SchnorrAggregate::read` on attacker bytes followed by `verify(dst, &keys_and_challenges)`:

1. Rebuild the weight transcript locally: `DigestTranscript::<C::H>::new(dst)`, `domain_separate(b"signatures")`, append each `challenge.to_repr()` — all inputs are public.
2. Compute `z_i = weight::<_, C::F>(&mut digest)` for `i = 0..n` by cloning the digest, exactly as `verify` does at crypto/schnorr/src/aggregate.rs:139-143.
3. Pick arbitrary `s`. Choose `t_0 = s · z_0⁻¹` (if `z_0 == 0`, split `s` across two indices with nonzero `z`), `t_i = 0` otherwise.
4. Set `R_i = t_i·G − c_i·A_i` where `A_i` are the victim public keys and `c_i` the challenges.
5. Serialize `{ Rs, s }` and submit. `verify` computes `Σ z_i·R_i + z_i·c_i·A_i − s·G = 0` and returns `true` — a valid aggregate signature for the victim keys without knowledge of any private key.

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res
}

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }

  pub fn aggregate(&mut self, challenge: C::F, sig: SchnorrSignature<C>) {

  }

  /// Complete aggregation, returning None if none were aggregated.
  pub fn complete(mut self) -> Option<SchnorrAggregate<C>> {
    if self.sigs.is_empty() {
      return None;
    }

    let mut aggregate = SchnorrAggregate { Rs: Vec::with_capacity(self.sigs.len()), s: C::F::ZERO };
    for i in 0 .. self.sigs.len() {
      aggregate.Rs.push(self.sigs[i].R);
      aggregate.s += self.sigs[i].s * weight::<_, C::F>(&mut self.digest);
    }
    Some(aggregate)
  }
