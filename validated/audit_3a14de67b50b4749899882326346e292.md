### Title
Cached FROST preprocess bound to `(domain, attempt)` instead of the message being signed — nonce reuse across distinct `set_keys_message`s leaks the validator's key share - ([File: coordinator/src/tributary/signing_protocol.rs](coordinator/src/tributary/signing_protocol.rs))

### Summary
The upstream bug (CVE-2022-49359) is a stale-reference class: the job referenced `panfrost_priv` (which can die) instead of the `MMU` context it actually needed. The Serai analog lives in `SigningProtocol::preprocess_internal` / `share_internal`: the deterministic preprocess seed is cached and re-derived keyed **only** by `context` (`(b"DkgConfirmer", attempt)`), while the actual object that must pin the nonce — the message being signed (`set_keys_message(set, removed, key_pair)`) and the effective participant set — is *not* part of the cache identity. The nonce seed therefore references the wrong (coarser) object: the attempt, not the signing session.

### Finding Description
`preprocess_internal` stores a 32-byte ChaCha20 seed under `CachedPreprocesses::set(self.txn, &self.context, ...)` where `self.context` for the DKG confirmer is `(b"DkgConfirmer", self.attempt)` [1](#0-0) . `share_internal` calls `preprocess_internal` again, which reads the same cached seed and deterministically regenerates the *identical* FROST nonces via `AlgorithmMachine::seeded_preprocess` (`ChaCha20Rng::from_seed(*seed.0)` → `Commitments::new`) [2](#0-1) . The message passed to `machine.sign` is `set_keys_message(&self.spec.set(), &removed..., key_pair)` [3](#0-2)  — i.e., it varies with `key_pair` and `removed`, neither of which is in the cache key.

The preprocess seed/nonce is thus bound to a container that can outlive and out-span the actual signing object: if `share()` is invoked more than once under the same `attempt` with a different `key_pair` (or a different `removed` set, since `removed_as_of_dkg_attempt` is re-evaluated at call time [4](#0-3) ), the same `d, e` nonces sign two different messages. Two Schnorr shares `s = d + b·e + ρ·λ·x·c` over the same nonce with different challenges `c` yield `x` (the MuSig private key / secret share) by linear combination — the classic FROST nonce-reuse key recovery explicitly warned about in the FROST spec ("Reusing preprocesses would enable a third-party to recover your private key share") [5](#0-4) .

### Impact Explanation
Recovery of a validator's MuSig/Ristretto signing key, or at minimum its FROST secret share. In the DKG-confirmation context this key is the validator's Substrate signing key used by the tributary signing protocol; compromise enables forging that validator's participation in set-keys confirmations and any other signing under the same attempt-scoped cache. This matches the accepted impact class: key share recovery from publicly-observed shares.

### Likelihood Explanation
The determinism is structural: `share_internal` unconditionally re-derives nonces from the attempt-keyed cache, so *any* code path that reaches `DkgConfirmer::share` twice within one attempt with differing `(set, removed, key_pair)` triggers reuse. Whether the coordinator ever legitimately confirms two distinct `KeyPair`s per attempt, or whether a peer can induce a second `share` call (e.g., across a reboot where `removed_as_of_dkg_attempt` returns a changed set, or via a second confirmation transaction), could not be fully verified — `handle.rs`/`transaction.rs` call sites were not exhaustively confirmed. The vulnerability is real at the primitive level (the seed cache does not commit to the message); exploitability depends on a second differing-message `share` being reachable, which the code does not prevent (no `assert!(already_shared)` guard, no message binding in `CachedPreprocesses`).

### Recommendation
Bind the cached-preprocess context to the full signing session: extend `context` to include a hash of the message (`set_keys_message` output) and the participant/`removed` set, or key `CachedPreprocesses` by `(domain, attempt, message_hash)`. Alternatively, record `SharedFor(context)` on first `share` and refuse a second `share` under the same context with different `msg`, mirroring the kernel fix — reference exactly the object needed (the message-bound signing session), not a coarser ancestor (the attempt).

### Proof of Concept
1. `DkgConfirmer::preprocess()` caches seed `S` under `("DkgConfirmer", attempt)` and emits nonce commitments `D = d·G, E = e·G` [6](#0-5) .
2. `share(preprocesses, key_pair_A)` signs `m_A = set_keys_message(set, removed, key_pair_A)`, emitting `s_A = d + b·e + ρ·λ·x·c_A`.
3. Trigger `share(preprocesses', key_pair_B)` for the same `attempt` (distinct key pair, or changed `removed` → distinct `m_B`). `preprocess_internal` returns the same `S`, regenerating identical `d, e`, so `s_B = d + b·e + ρ·λ·x·c_B`.
4. With `c_A ≠ c_B` (different `hash_msg`/`bound` transcript), solve `x = (s_A − s_B) / (ρ·λ·(c_A − c_B))` — recovering the secret share, and for the MuSig aggregate context, the validator's signing key contribution.

The nonce-reuse step is guaranteed by the deterministic `seeded_preprocess` path [7](#0-6) ; only the triggering of step 3 depends on coordinator call-site behavior that was not fully verified.
