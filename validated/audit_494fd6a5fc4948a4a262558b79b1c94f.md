### Title
Duplicate signer entries in `SchnorrAggregate` let one signature count multiple times — (`File: crypto/schnorr/src/aggregate.rs`)

### Summary
`SchnorrAggregate::verify` iterates the caller-supplied `keys_and_challenges` and self-supplied `Rs` without checking that signers (or their `R` values) are distinct. Because the per-index weight `z_i` multiplies the *entire* verification statement (`z_i·R_i + z_i·c_i·A_i - s_i·G`), any valid single contribution can be replayed under multiple indexes: the attacker simply folds the sum of weights into the aggregate `s`. This is the direct analog of the YOLO `findUpperBound` bug: a zero-marginal-cost duplicate entry is treated as an additional real participant, letting an attacker steal slots/weight belonging to the honest set.

### Finding Description
`SchnorrAggregate::read` accepts an arbitrary list of `Rs` with no uniqueness check [1](#0-0) . `verify` then checks only `Rs.len() == keys_and_challenges.len()` and builds one weighted statement per index, where `z_i` is derived from a digest over *all* challenges [2](#0-1) .

Verification succeeds iff `Σ_i z_i·R_i + Σ_i z_i·c_i·A_i − s·G == 0`. Given one valid signature `(R, s₀)` under key `A` with challenge `c` (i.e. `s₀·G = R + c·A`), an attacker submits `signers = [A, A, …, A]` (k copies) and `Rs = [R, …, R]`. Every `c_i` is identical (challenge binds key+nonce+msg), so the statement reduces to `(Σ z_i)·(R + c·A) − s·G`. The attacker computes `s = (Σ z_i)·s₀` — all `z_i` are public functions of the fully attacker-chosen transcript — and verification passes. One real signature is counted k times.

The same holds for mixed replay: any subset of already-valid contributions can be duplicated at zero additional signing cost, since duplication just rescales each term.

### Impact Explanation
The primitive's contract — "this aggregate proves each listed signer produced a signature" — is violated: an unprivileged party with a single observed signature (e.g., one validator's vote relayed publicly) can produce an `AggregateSignature` that verifies as though that signer appeared multiple times. Any consumer that counts entries, weights quorum by list length, or attributes participation per index (the natural use, as in the tendermint `verify_aggregate` caller which builds `signers`/`challenges` per index) will overcount the duplicated party — the same "duplicate index steals the slot" shape as the reference bug, where a zero-value deposit duplicated a `currentEntryIndex` and stole a win. This yields a forged/forgery-equivalent aggregate verification result reachable purely from untrusted bytes via `SchnorrAggregate::read` + `verify`.

### Likelihood Explanation
Any party that observes one valid Schnorr signature for a known key/challenge (publicly relayed signatures are the norm) can forge the inflated aggregate; no secret, no collusion, and no control over the challenge is needed since `s` is free-form attacker input and all weights are deterministic given the attacker's chosen `Rs`/signer list. Exploitation requires a downstream consumer that treats each index as a distinct endorsement without its own dedup — which `verify`'s API shape invites, since the function itself enforces nothing beyond length equality [3](#0-2) .

### Recommendation
Reject duplicates in `verify`: before/while building `pairs`, check that neither `Rs` nor the `keys_and_challenges` keys (ideally the `(key, R)` pair, and arguably each `key` alone since one signer should contribute one nonce) contain repeats, e.g. insert each `key.to_bytes()`/`R.to_bytes()` into a `HashSet` and return `false` on collision — mirroring the dedup already performed in `musig`'s `check_keys` [4](#0-3) . Alternatively, document-and-enforce signer uniqueness by keying contributions on a deduplicated signer set rather than trusting positional `signers`/`Rs` arrays.

### Proof of Concept
```rust
// Attacker knows a valid signature (R, s0) for (A, c): s0*G = R + c*A.
// Forge an aggregate "proving" A signed k times.
let k = 3;
let signers = vec![A_bytes; k];               // same validator key, k times
let rs = vec![R; k];                          // same nonce point, k times

// challenges are public: c_i = challenge(genesis, A, R, msg) — all equal
let challenges: Vec<F> = signers.iter().map(|_| c).collect();

// weights z_i are deterministic over the transcript of challenges
let mut digest = DigestTranscript::<C::H>::new(DST);
digest.domain_separate(b"signatures");
for c_i in &challenges { digest.append_message(b"challenge", c_i.to_repr()); }
let z_sum: F = (0..k).map(|_| weight::<_, F>(&mut digest)).sum();

let forged = SchnorrAggregate { Rs: rs, s: z_sum * s0 };
assert!(forged.verify(DST, &vec![(A, c); k])); // passes: (Σz)(R + cA) - s*G == 0
```

The library-level flaw — no uniqueness enforcement despite a positional, index-counted API — stands on its own.

fn weight<D: Send + Clone + SecureDigest, F: PrimeField>(digest: &mut DigestTranscript<D>) -> F {
  let mut bytes = digest.challenge(b"aggregation_weight");
  debug_assert_eq!(bytes.len() % 8, 0);
  // This should be guaranteed thanks to SecureDigest
  debug_assert!(bytes.len() >= 32);

  let mut res = F::ZERO;
  let mut i = 0;

  // Derive a scalar from enough bits of entropy that bias is < 2^128
  // This can't be const due to its usage of a generic
  // Also due to the usize::try_from, yet that could be replaced with an `as`
  #[allow(non_snake_case)]
  let BYTES: usize = usize::try_from((F::NUM_BITS + 128).div_ceil(8)).unwrap();

  let mut remaining = BYTES;

  // We load bits in as u64s
  const WORD_LEN_IN_BITS: usize = 64;
  const WORD_LEN_IN_BYTES: usize = WORD_LEN_IN_BITS / 8;

  let mut first = true;
  while i < remaining {
    // Shift over the already loaded bits
    if !first {
      for _ in 0 .. WORD_LEN_IN_BITS {
        res += res;
      }
    }
    first = false;

    // Add the next 64 bits
    res += F::from(u64::from_be_bytes(bytes[i .. (i + WORD_LEN_IN_BYTES)].try_into().unwrap()));
    i += WORD_LEN_IN_BYTES;

    // If we've exhausted this challenge, get another
    if i == bytes.len() {
      bytes = digest.challenge(b"aggregation_weight_continued");
      remaining -= i;
      i = 0;
    }
  }
  res

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
