### Title
Unix Socket gRPC Server Omits `OnlyAggregatorAndSelf` Interceptor, Allowing Any Local Process to Call Privileged `Internal*` Methods — (`File: core/src/servers.rs`)

---

### Summary

`create_grpc_server` in `core/src/servers.rs` wraps the gRPC service with the `OnlyAggregatorAndSelf` mTLS interceptor **only** on the TCP code path. The Unix domain socket code path adds the service directly, with no interceptor at all. Any process that can reach the Unix socket can therefore call every gRPC method — including `Internal*` methods that are supposed to be restricted to self-calls — without presenting any certificate.

---

### Finding Description

`core/src/servers.rs` contains two branches inside `create_grpc_server`:

**TCP path** (lines 114–139): wraps the service in `InterceptedService` before registering it:

```rust
let service = InterceptedService::new(
    service,
    if config.client_verification {
        OnlyAggregatorAndSelf { aggregator_cert, our_cert: client_cert }
    } else {
        Noop
    },
);
// ...
.add_service(service)   // interceptor is active
```

**Unix socket path** (lines 179–222): adds the raw service with no interceptor:

```rust
let server_builder = tonic::transport::Server::builder()
    .layer(AddMethodMiddlewareLayer)
    // ...
    .add_service(service);   // ← no InterceptedService wrapper
```

The `OnlyAggregatorAndSelf` interceptor (`core/src/rpc/interceptors.rs`) enforces two invariants:

| Method class | Allowed callers |
|---|---|
| Non-`Internal*` | aggregator cert **or** self cert |
| `Internal*` | self cert **only** |

Because the Unix socket path never instantiates `InterceptedService`, neither invariant is checked. Any process that can open the socket file calls any method unconditionally.

The `Internal*` methods exposed on the operator and verifier servers include:

- `InternalWithdraw` — executes a payout transaction **without** the `verification_signature` check that guards the public `Withdraw` RPC
- `InternalEndRound` — terminates the current operator round
- `InternalHandleKickoff` — triggers kickoff-state processing for an arbitrary txid
- `InternalFinalizedPayout` — records a payout as finalized in the DB
- `InternalCreateAssertCommitmentTxs` — builds BitVM assert-commitment transactions

---

### Impact Explanation

An attacker with local access (compromised co-located container, sidecar process, or any process running as the same OS user) can:

1. **Call `InternalWithdraw` directly** — bypasses the `aggregator_verification_address` ECDSA check that the public `Withdraw` path enforces. The operator will queue a payout transaction for any withdrawal that is already registered in Citrea, without the aggregator's authorisation. This lets an attacker force the operator to spend its own funds on a withdrawal the aggregator has not approved.

2. **Call `InternalFinalizedPayout` or `InternalEndRound` prematurely** — corrupts the round/kickoff state machine. If the operator's DB records a payout as finalized before the kickoff is complete, the operator will not broadcast the kickoff transaction and will forfeit its reimbursement connector (collateral recovery path).

3. **Call `InternalHandleKickoff` with a crafted txid** — triggers verifier challenge logic against an arbitrary transaction, potentially wasting challenge collateral or disrupting the watchtower state.

These map directly to the allowed impact categories: *unauthorized state transition in payout/reimbursement/round flow that breaks bridge safety/liveness with material fund impact* and *authentication bypass in gRPC that grants privileged bridge actions to the wrong party*.

---

### Likelihood Explanation

Unix domain sockets are a standard deployment option on Linux (the `#[cfg(unix)]` branch is compiled in all production Linux builds). In containerised deployments (Docker, Kubernetes), any process in the same pod or with a volume mount to the socket path can connect. No mTLS certificate is required — the OS file-permission model is the only barrier, and that is not enforced by the Clementine code itself.

---

### Recommendation

Apply the same `InterceptedService` wrapper in the Unix socket branch as in the TCP branch:

```rust
#[cfg(unix)]
ServerAddr::Unix(ref socket_path) => {
    // Build the interceptor the same way as the TCP path
    let intercepted = InterceptedService::new(service, /* OnlyAggregatorAndSelf or Noop */);
    let server_builder = tonic::transport::Server::builder()
        .layer(AddMethodMiddlewareLayer)
        // ...
        .add_service(intercepted);   // ← wrap before registering
```

For Unix sockets, peer-credential authentication (`SO_PEERCRED`) or a shared-secret token in metadata can substitute for mTLS if certificate exchange is impractical over a local socket.

---

### Proof of Concept

1. Start a Clementine operator configured with a Unix socket address (e.g. `/tmp/clementine-operator.sock`).
2. From any local process (no certificate needed):

```rust
// pseudocode — standard tonic Unix socket client
let channel = Endpoint::from_static("http://[::]:50051")
    .connect_with_connector(tower::service_fn(|_| {
        tokio::net::UnixStream::connect("/tmp/clementine-operator.sock")
    }))
    .await?;

let mut client = ClementineOperatorClient::new(channel);

// Call an Internal method — no mTLS cert presented, no interceptor runs
client.internal_end_round(Empty {}).await?;   // succeeds

// Or force an operator payout without aggregator approval:
client.internal_withdraw(WithdrawParams {
    withdrawal_id: <valid_citrea_withdrawal_id>,
    input_signature: <valid_user_taproot_sig>,
    input_outpoint: Some(<withdrawal_utxo>),
    output_script_pubkey: <attacker_scriptpubkey>,
    output_amount: <bridge_amount>,
}).await?;   // operator queues payout tx, no aggregator signature required
```

The `OnlyAggregatorAndSelf` interceptor is never invoked because `InterceptedService` is never constructed for the Unix socket path.

use tonic::{service::Interceptor, transport::CertificateDer, Request, Status};

#[derive(Debug, Clone)]
pub enum Interceptors {
    OnlyAggregatorAndSelf {
        aggregator_cert: CertificateDer<'static>,
        our_cert: CertificateDer<'static>,
    },
    Noop,
}

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware
    let Some(path) = req.metadata().get("grpc-method") else {
        // No grpc method? this should not happen
        tracing::error!("Missing grpc-method header in request");
        return false;
    };
    path.as_bytes().starts_with(b"Internal")
}

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
}

    async fn withdraw(
        &self,
        request: Request<WithdrawParamsWithSig>,
    ) -> Result<Response<RawSignedTx>, Status> {
        tracing::info!("Withdraw rpc called");
        let params = request.into_inner();
        let withdraw_params = params.withdrawal.ok_or(Status::invalid_argument(
            "Withdrawal params not found for withdrawal",
        ))?;
        let (withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount) =
            parser::operator::parse_withdrawal_sig_params(withdraw_params)?;

        tracing::warn!(
            "Parsed withdraw rpc params, withdrawal id: {:?}, input signature: {:?}, input outpoint: {:?}, output script pubkey: {:?}, output amount: {:?}, verification signature: {:?}", withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount, params.verification_signature
        );

        // if verification address is set in config, check if verification signature is valid
        if let Some(address_in_config) = self.operator.config.aggregator_verification_address {
            let verification_signature = params
                .verification_signature
                .map(|sig| {
                    PrimitiveSignature::from_str(&sig).map_err(|e| {
                        Status::invalid_argument(format!("Invalid verification signature: {e}"))
                    })
                })
                .transpose()?;
            // check if verification signature is provided by aggregator
            if let Some(verification_signature) = verification_signature {
                let address_from_sig =
                    recover_address_from_ecdsa_signature::<OperatorWithdrawalMessage>(
                        withdrawal_id,
                        input_signature,
                        input_outpoint,
                        output_script_pubkey.clone(),
                        output_amount,
                        verification_signature,
                    )?;

                // check if verification signature is signed by the address in config
                if address_from_sig != address_in_config {
                    return Err(BridgeError::InvalidECDSAVerificationSignature).map_to_status();
                }
            } else {
                // if verification signature is not provided, but verification address is set in config, return error
                return Err(BridgeError::ECDSAVerificationSignatureMissing).map_to_status();
            }
        }

        let payout_tx = self
            .operator
            .withdraw(
                withdrawal_id,
                input_signature,
                input_outpoint,
                output_script_pubkey,
                output_amount,
            )
            .await?;

        tracing::info!(
            "Withdraw rpc completed successfully for withdrawal id: {:?}",
            withdrawal_id
        );

        Ok(Response::new(RawSignedTx::from(&payout_tx)))
    }
