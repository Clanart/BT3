## Title
Trampoline credential helper trusts a spoofed `WWW-Authenticate: realm="GitHub"` header to classify an arbitrary remote as a GitHub host, auto-launching an Enterprise sign-in flow scoped to that attacker endpoint - (`app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The reported Beedle bug is about a function trusting a fixed/assumed parameter (`fee: 3000`) instead of validating it against the real, pool-specific value, silently misdirecting funds. The Desktop analog is `getEndpointKind()`, which classifies a Git remote as an "enterprise" GitHub host by trusting a value fully controlled by the remote server (the `WWW-Authenticate` realm string) instead of verifying the host's identity, then uses that unverified classification to automatically drive a trust-sensitive sign-in flow.

### Finding Description
`getEndpointKind()` is used by the credential-helper trampoline to decide how to treat an unknown Git remote host during `get`/`store`/`erase` credential operations [1](#0-0) . After the fast, well-founded checks (`isGist`, `isDotCom`, `isGHE`), it falls back to a "happy path" that trusts whatever `WWW-Authenticate` header the remote server returned: [2](#0-1) 

This header is attacker-controlled content coming straight from the HTTP response of the Git remote (Git forwards `wwwauth[]` values from any 401 response it receives during `fetch`/`clone`/`push`). Unlike the legitimate fallback path a few lines below — which performs an actual network probe with certificate-error handling via `isGitHubHost()` [3](#0-2)  — the `wwwauth[]` shortcut does zero verification: any server that returns `realm="GitHub"` is immediately classified `'enterprise'`.

That classification feeds directly into `getCredential()`, which — when no existing account matches the endpoint — calls `ui.promptForGitHubSignIn(endpoint)` automatically, with no explicit user request to "sign in" beyond performing an ordinary git operation against the remote: [4](#0-3) 

`promptForGitHubSignIn()` then begins a full Enterprise OAuth sign-in flow scoped to the attacker's endpoint: [5](#0-4) 

That flow ultimately calls `authenticateWithBrowser()`, which opens the user's browser directly to `getOAuthAuthorizationURL(endpoint, csrfToken)` at the attacker-controlled endpoint: [6](#0-5) 

### Impact Explanation
This lets any Git remote or MITM proxy the user fetches/clones/pushes to unilaterally decide, via a single unauthenticated response header, that Desktop should treat it as a trusted "GitHub Enterprise" host and proactively launch a native-looking Desktop sign-in dialog pointed at the attacker's own domain (`credentialHelperUrl` shown verbatim to the user in `sign-in.tsx`) [7](#0-6) . Because the resulting OAuth authorize page is loaded from the attacker's endpoint rather than a verified GitHub host, this can be used to stage credential-harvesting/OAuth-binding against the user, satisfying the "unauthorized OAuth or account binding" impact category — triggered purely by the contents of a server response to a routine `git` network operation, with no other required user action, prior compromise, or malware.

### Likelihood Explanation
Likelihood is moderate-to-high in the class of scenarios described: it activates automatically the first time Desktop needs credentials for an unknown remote that returns this header (e.g., adding/fetching an untrusted remote, following a malicious "clone this repo" link, or a compromised/rogue proxy sitting on the network path), and requires no cooperation from the victim beyond the normal act of fetching. The check that should gate this trust decision (an actual `isGitHubHost()` network probe, already implemented and used elsewhere in the same file) is skipped entirely for any server that happens to send this specific header string.

### Recommendation
Do not treat the `wwwauth[]` "realm" hint as sufficient to classify a host as GitHub/Enterprise. At minimum:
- Require the same host-identity verification (`isGitHubHost()`/known TLS certificate) used in the final fallback before trusting `realm="GitHub"`.
- Only allow the header-based shortcut to *narrow down* candidates for an existing configured account (as `findGitHubTrampolineAccount` already safely does via origin match), never to originate a brand-new, auto-launched sign-in flow to an arbitrary endpoint.
- Surface a clear, unmistakable warning before opening any Enterprise sign-in/browser flow triggered indirectly by a Git operation instead of an explicit user click on "Sign in".

### Proof of Concept
1. Attacker sets up a Git-over-HTTPS server (or a proxy sitting in front of any remote) that, for any unauthenticated request, replies `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this remote in GitHub Desktop (e.g., clones a repo whose `origin` points at the attacker's URL, or adds it as an additional remote) and performs a `fetch`.
3. `dugite`/git forwards the `WWW-Authenticate` header to the trampoline credential helper as `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind()` returns `'enterprise'` for the attacker's host without any real verification [8](#0-7) .
5. Since no existing account matches this endpoint, `getCredential()` calls `ui.promptForGitHubSignIn(attackerEndpoint)`, and Desktop shows its native "Sign in" dialog referencing the attacker's URL and, on proceeding, opens the browser to an OAuth authorize page hosted at the attacker's domain.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
