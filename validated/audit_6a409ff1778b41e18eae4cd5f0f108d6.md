The strongest local candidate is a mismatch between what `aptos move verify-package` reports as "verified" and what is actually enforced on-chain: **the `source` bytes and `source_digest` in `PackageMetadata` are never checked against the compiled module bytecode**, neither by the Move VM at publish time nor by the CLI's verification tool.

### Title
On-chain `PackageMetadata.source`/`source_digest` is never bound to the published bytecode, so `aptos move verify-package` can falsely attest that on-chain code matches trusted source - (File: `aptos-move/cli/src/stored_package.rs`)

### Summary
`code::publish_package` stores a `PackageMetadata` struct containing a `source_digest` and per-module `source`/`source_map` blobs alongside the actual executable `code: vector<vector<u8>>` bundle. Nothing in the Move framework or in the Aptos VM publish validation path checks that the declared `source`/`source_digest` actually correspond to the bytecode being published. The CLI's `aptos move verify-package` command, which is the tool operators/auditors are told to use to confirm on-chain code matches a trusted source tree, only compares `PackageMetadata` fields (name, deps, modules list, manifest, upgrade_policy, extension, source_digest) — it never fetches or diffs the actual on-chain bytecode against a fresh local compilation.

### Finding Description
`PackageMetadata` is defined with a `source_digest: String` and each `ModuleMetadata.source: vector<u8>` purely as informational/user-supplied blobs: [1](#0-0) 

The publish path (`code::publish_package`) enforces upgrade-policy, dependency, coexistence, and event/metadata-attribute checks, but never validates `source`/`source_digest` against `code`: [2](#0-1) 

On the VM side, `validate_publish_request` performs bytecode complexity checks, native validation, expected-module/dependency checks, resource-group/event validation, and `verify_module_metadata_for_module_publishing` — none of which touch the `source`/`source_digest` fields at all, since those never even reach the VM (only `code: vector<vector<u8>>` and the module names do): [3](#0-2) 

Client-side, `CachedPackageRegistry::verify` (invoked by the `aptos move verify-package` CLI command) only compares `PackageMetadata` struct fields, including `source_digest`, but never re-derives or compares the actual on-chain bytecode: [4](#0-3) 

Confirming this, `VerifyPackage::execute` explicitly creates the registry with `with_bytecode = false`, so bytecode is never even downloaded for comparison: [5](#0-4) 

`source_digest` itself is computed purely from local source `.move`/`Move.toml` files via SHA-256, independent of the compiled module bytes: [6](#0-5) 

Because a publisher supplies `metadata` (with `source`, `source_digest`, `manifest`) and `code` (raw bytecode) as two independent, unlinked arguments to `code::publish_package_txn` / `object_code_deployment::publish` / `object_code_deployment::upgrade` / `resource_account::create_resource_account_and_publish_package`, a publisher can attach arbitrary "verified-looking" source metadata (matching a benign, audited source tree, and even a `source_digest` that a victim will compute identically over that benign tree) while shipping semantically different — even malicious — compiled bytecode. Since `verify-package`/`verify()` compares only the *metadata* record (which the attacker fully controls), the check trivially passes, even though the actual executing bytecode differs from what was "verified."

### Impact Explanation
This directly matches the "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes" publish-impact category. Wallets, block explorers, auditors, and other on-chain consumers that rely on `aptos move verify-package` (or directly on `code::PackageRegistry.source_digest`/`modules[].source`) to establish that the deployed bytecode corresponds to a specific, reviewed source tree can be misled into trusting malicious bytecode as "verified." This is a code-safety/trust invariant break with high real-world relevance, since source verification is the primary mechanism by which the ecosystem (and end users) establish that on-chain code does what its published source claims.

### Likelihood Explanation
Likelihood is high: any account (including a permissionless resource account or object-code deployment, which are explicitly designed to be usable by arbitrary unprivileged callers) can call `publish_package_txn`/`object_code_deployment::publish`/`upgrade` with metadata and code that are unrelated to each other — there is no cryptographic or verifier-level binding required between them, and no additional privilege is needed beyond ordinary publish rights.

### Recommendation
Bind `PackageMetadata.source_digest` (or a hash of the full `source`/`manifest` blobs) cryptographically to the actual `code` bytes at publish time — e.g., have the native `request_publish`/`request_publish_with_allowed_deps` validate that a digest derived from the metadata's source material is consistent with the compiled bytecode (as far as is feasible, e.g., recompiling and hash-checking off-chain is unreliable, so at minimum the CLI's `verify-package`/`stored_package::verify` should also fetch and byte-compare the actual on-chain module bytecode against a fresh local build, not just metadata fields), and clearly document that `source_digest`/`source` fields are purely advisory unless independently reproduced by re-downloading and diffing bytecode (as `DownloadPackage --bytecode` does, but `VerifyPackage` currently does not).

### Proof of Concept
1. Compile a benign, "safe-looking" Move package `P_good` and note its `source_digest` (`digest.rs::compute_digest` over its `.move`/`Move.toml` files).
2. Compile a malicious package `P_evil` whose Move sources produce identical file names but functionally malicious bytecode (or simply hand-craft a `code: vector<vector<u8>>` bundle independent of any source), while manually constructing a `PackageMetadata` whose `source`, `manifest`, and `source_digest` fields exactly reproduce those of `P_good` (these fields are plain BCS-encoded arguments to the entry function, fully attacker-controlled, e.g. via `object_code_deployment::publish(metadata_serialized, code)` at [7](#0-6) ).
3. Submit this transaction on-chain — `code::publish_package` and `validate_publish_request` accept it since neither checks `source`/`source_digest` against `code`.
4. A victim runs `aptos move verify-package --account <addr>` against the local, benign `P_good` source tree: `VerifyPackage::execute` rebuilds `P_good` locally, computes the same `source_digest`, and calls `CachedPackageMetadata::verify`, which only compares metadata (including the attacker-forged `source_digest`) and reports `"Successfully verified source of package"` even though the deployed bytecode is `P_evil`'s malicious code, not `P_good`'s.

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }

        // First build the package locally to get the package metadata

        let client = self.rest_options.client(&self.profile_options)?;

            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")

pub fn compute_digest(paths: &[PathBuf]) -> Result<PackageDigest> {
    let mut hashed_files = Vec::new();
    let mut hash = |path: &Path| {
        let contents = std::fs::read(path)?;
        hashed_files.push(format!("{:X}", Sha256::digest(&contents)));
        Ok(())
    };
    let mut maybe_hash_file = |path: &Path| -> Result<()> {
        match path.extension() {
            Some(x) if MOVE_EXTENSION == x => hash(path),
            _ if path.ends_with(SourcePackageLayout::Manifest.path()) => hash(path),
            _ => Ok(()),
        }
    };

    for path in paths {
        if path.is_file() {
            maybe_hash_file(path)?;
        } else {
            for entry in walkdir::WalkDir::new(path)
                .follow_links(true)
                .into_iter()
                .filter_map(|e| e.ok())
            {
                if entry.file_type().is_file() {
                    maybe_hash_file(entry.path())?
                }
            }
        }
    }

    // Sort the hashed files to ensure that the order of files is always stable
    hashed_files.sort();

    let mut hasher = Sha256::new();
    for file_hash in hashed_files.into_iter() {
        hasher.update(file_hash.as_bytes());
    }

    Ok(PackageDigest::from(format!("{:X}", hasher.finalize())))
}
