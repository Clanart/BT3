### Title
Unbounded index read in mempool `is_atom_canonical`/`is_clvm_canonical` allows a single spend bundle to crash transaction validation - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw `puzzle_reveal` and `solution` bytes of every coin spend in a submitted `SpendBundle` to enforce canonical CLVM atom-length-prefix encoding, but they read the declared length-prefix bytes without first checking that enough bytes remain in the buffer, exactly the same bug class as CVE-2018-20615 (HAProxy's HTTP/2 HEADERS/PRIORITY parser skipping bytes whose presence was never checked against the remaining frame length).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` determines a length-prefix size (`prefix_len`, 0–5 extra bytes) from the leading byte, then unconditionally loops `prefix_len` times indexing `clvm_buffer[offset]` to build `atom_len`, with no check that `offset` stays within `len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical(clvm_buffer)` drives this loop over the whole buffer and likewise reads `clvm_buffer[offset]` at the top of each iteration without verifying `offset < len(clvm_buffer)` before dereferencing it, mirroring the HAProxy pattern of skipping bytes that were never confirmed to exist in the frame: [2](#0-1) 

This function is called unconditionally (not only for DEDUP-eligible spends, despite the docstring/comment framing) on every coin spend of any submitted spend bundle, directly in the hot mempool admission path `validate_spend_bundle()`: [3](#0-2) 

Because `coin_spend.puzzle_reveal` and `coin_spend.solution` bytes are fully attacker-controlled (any unprivileged submitter can craft a `SpendBundle` with an atom whose length-prefix byte claims a large multi-byte length near the end of the buffer, e.g. a trailing `0xFC` "6-byte prefix" marker with fewer than 5 following bytes), calling `is_clvm_canonical()`/`is_atom_canonical()` on such a buffer causes Python to raise an uncaught `IndexError` when indexing past the end of `bytes`. There is no bounds check equivalent to the `n > len(buf)` checks used elsewhere in the codebase (e.g. `skip_bytes()`/`skip_list()` in `chia/full_node/full_block_utils.py`), which explicitly validate remaining buffer length before consuming declared lengths: [4](#0-3) 

`add_spend_bundle()`, which calls `validate_spend_bundle()`, has no `try/except` around this call, so an `IndexError` raised deep inside `is_clvm_canonical` propagates uncaught out of `add_spend_bundle()`: [5](#0-4) 

### Impact Explanation
An unprivileged spend-bundle submitter can craft a puzzle_reveal or solution whose trailing bytes end mid-atom-length-prefix (a non-canonical atom near the very end of the buffer, using a multi-byte prefix marker like `0xC0`-`0xFE` followed by fewer bytes than the prefix requires). When such a bundle reaches `validate_spend_bundle()`/`add_spend_bundle()`, the resulting `IndexError` is not caught by the mempool admission code path, causing an unhandled exception during transaction processing rather than a clean `INVALID_COIN_SOLUTION` rejection. This is a spend-triggered transaction-processing halt/DoS analog to the CVSS 7.5 HAProxy bug: a single crafted, unprivileged input can crash or destabilize the request-processing task that handles mempool admission for all subsequent transactions.

### Likelihood Explanation
High likelihood of reachability: any wallet, RPC caller, or peer that can submit a `SpendBundle` (e.g., via `push_tx`) reaches `MempoolManager.add_spend_bundle()` → `validate_spend_bundle()` → `is_clvm_canonical()` on fully attacker-controlled `puzzle_reveal`/`solution` bytes, with no upstream sanitization that guarantees a well-formed atom length prefix before this check runs.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before indexing `clvm_buffer[offset]`, following the same pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes()`/`skip_list()` (i.e., verify `offset + prefix_len < len(clvm_buffer)` before reading prefix bytes, and treat a short/truncated buffer as non-canonical rather than raising). Additionally, wrap the canonical-serialization checks (or the whole `validate_spend_bundle` call site) with an exception boundary that converts unexpected parsing exceptions into `Err.INVALID_COIN_SOLUTION` instead of letting them propagate uncaught.

### Proof of Concept
Construct a `SpendBundle` whose `coin_spend.solution` (or `puzzle_reveal`) bytes end with a multi-byte atom length-prefix marker but insufficient trailing bytes, e.g.:
```
solution_bytes = b"\xfc\x03\xff\xff"   # 0xFC declares a 6-byte prefix (5 extra bytes) but only 3 extra bytes follow
```
Submitting a coin spend with this `solution` via the normal wallet/RPC `push_tx` path causes `MempoolManager.add_spend_bundle()` to call `is_clvm_canonical(bytes(coin_spend.solution))`, which calls `is_atom_canonical()`; the loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` (`chia/full_node/mempool_manager.py:178-181`) indexes past the end of the 4-byte buffer, raising an uncaught `IndexError` inside the mempool admission path rather than a graceful validation error. [6](#0-5)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
