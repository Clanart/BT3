### Title
Later transaction in a block overwrites `presumed_origin` and `data` of unrelated earlier deposits - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::get_outputs` accumulates matched `Output`s in a single `outputs` vector across all transactions in a block, but the "populate origin and data" pass is executed per-transaction over the entire accumulated vector. An attacker whose transaction appears anywhere in the same block as a victim's deposit can overwrite the victim output's `data` (the InInstruction / Serai mint payload) and `presumed_origin` — even though the attacker's transaction pays Serai nothing, or pays a dust-adjacent unrelated output.

### Finding Description
The bug class of CVE-2018-1000600 is an attacker-specified identifier causing the wrong credential/metadata to be applied. The analog lives in `get_outputs` (processor/src/networks/bitcoin.rs:686-740):

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) {
    ...
    outputs.push(output);
  }
  if outputs.is_empty() { continue; }
  // populate the outputs with the origin and data
  let presumed_origin = { let input = &tx.input[0]; ... };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs {          // <-- iterates ALL accumulated outputs
    if output.kind == OutputType::External {
      output.data.clone_from(&data);
    }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
```

Two distinct defects:
1. `outputs` is never scoped to the current `tx`. Once any earlier transaction in the block produced a match, **every subsequent transaction** — including transactions with zero outputs to Serai — enters the populate block (the `if outputs.is_empty()` guard only checks the accumulated vector) and rewrites `data`/`presumed_origin` for all previously collected outputs.
2. `tx.input[0]` is fully attacker-controlled, so `presumed_origin` is derived from whatever the attacker spends, and `extract_serai_data(tx)` returns whatever payload the attacker embeds.

### Impact Explanation
`data` on an `External` output carries the Serai `InInstruction` (e.g. a `transfer`/`mint` destination). Overwriting it means a victim's real Bitcoin deposit is processed with attacker-chosen instruction data — minted funds can be redirected to an attacker's Serai address, or the deposit's metadata can be corrupted so the credited balance is wrong/unclaimable. This is loss of funds/integrity reachable purely from public Bitcoin transactions an unprivileged attacker broadcasts, matching "funds reported received that are not spendable" / wrong-data-signed acceptance criteria.

### Likelihood Explanation
The attacker only needs their transaction confirmed in the same block as a victim deposit — trivially achievable by monitoring the mempool and broadcasting a cheap self-transfer that touches `tx.input[0]` with chosen `extract_serai_data` content. No key material, no validator collusion, no threshold assumptions required. Miners/relayers ordering is not even necessary to win every time — any block containing both transactions after the victim's suffices.

### Recommendation
Scope the populate pass to the per-transaction results: collect `let tx_outputs = scanner.scan_transaction(tx)` into a fresh vector, skip if that (not the accumulated vector) is empty, apply `presumed_origin`/`data` only to `tx_outputs`, then extend `outputs` with them. Also consider binding `data` to the specific output that carries the instruction commitment rather than broadcasting it to every `External` output of the tx.

### Proof of Concept
1. Victim broadcasts tx V in block B paying Serai's external address with `InInstruction` data crediting victim's Serai account.
2. Attacker broadcasts tx A (later position in B than V) with any input and an OP_RETURN/script path `extract_serai_data` payload crediting the attacker's Serai address; A pays Serai nothing.
3. `get_outputs` scans V, pushes the victim `Output` into `outputs`. On reaching A, `scan_transaction(A)` pushes nothing, but `outputs` is non-empty, so the populate block runs: `presumed_origin` = A's `input[0]` source, `data` = attacker's payload, applied to the victim's `External` output.
4. The victim's deposit is emitted with the attacker's `InInstruction`, redirecting the mint.

```rust
  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
```
