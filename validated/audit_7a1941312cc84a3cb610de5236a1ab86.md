### Title
Silent block-rule bypass via missing `field` default in `Condition.from_dict` - ([File: plugins/hookify/core/config_loader.py])

### Summary
`Condition.from_dict` defaults the `field` attribute to an empty string (`''`) whenever a `conditions:` entry in rule frontmatter omits (or the hand-rolled YAML parser drops) the `field` key, unlike the legacy `pattern:` path in `Rule.from_dict`, which always infers a valid, non-empty field from `event`. Because `RuleEngine._extract_field` returns `None` for an unrecognized empty field name, and `_check_condition` treats `None` as "condition not satisfied," a single malformed condition silently makes the entire rule (including `action: block` rules) permanently inert without any warning.

### Finding Description
`Rule.from_dict` has two parsing paths that behave inconsistently:

- Legacy `pattern:` path always assigns a valid, non-empty `field` (`command`, `new_text`, or `content`) inferred from `event`: [1](#0-0) 
- Explicit `conditions:` path calls `Condition.from_dict`, which defaults a missing `field` key to `''` with no validation: [2](#0-1) 

At evaluation time, `RuleEngine._rule_matches` requires *all* conditions to match, and `_check_condition` short-circuits to `False` whenever `_extract_field` returns `None`: [3](#0-2) [4](#0-3) 

`_extract_field('', ...)` does not match any of the `tool_input`, Stop-event, or per-tool special-case branches, so it falls through and returns `None`: [5](#0-4) 

The net effect: a repo-shipped `.claude/hookify.*.local.md` file (or output from `/hookify` generation) that declares `action: block` with a `conditions:` list missing a `field:` key — either intentionally, or accidentally due to the custom frontmatter parser's fragile indentation handling in `extract_frontmatter` (e.g., continuation lines requiring `indent > 2` under a list dict item) — silently produces a `Rule` object that is enabled, looks correct, but can **never match** any input. `load_rule_file`/`load_rules` perform no semantic validation on parsed conditions and load the rule successfully: [6](#0-5) 

This is precisely the differential described: the legacy pattern path guarantees enforcement via mandatory field inference, while the explicit-conditions path has no such guarantee and silently degrades to a no-op rule, violating the invariant that default field inference (or its absence) must not weaken enforcement.

### Impact Explanation
A user relying on a `.claude/hookify.*.local.md` "block" rule (e.g., blocking edits to `.env`/secrets, or blocking dangerous `rm -rf`/`curl | sh` commands) believes the guardrail is active because the file loads without error and is `enabled: true`. If the rule's `conditions:` block is malformed (missing `field`), the rule is parsed successfully but never blocks anything — `PreToolUse`/`Stop` hooks always return `{}` (allow) for that rule. This directly enables the dangerous bash command or sensitive file edit that the rule was supposed to prevent, matching "Unauthorized file read or write outside the user-approved workspace or target scope."

### Likelihood Explanation
This requires only that the attacker (or an unwitting contributor) can get a rule file into `.claude/` with a subtly malformed `conditions:` block — via a PR adding an example rule file, or via `/hookify` generation producing frontmatter that omits `field` in an edge case. No parser errors or warnings are emitted (`load_rule_file` logs nothing for this case, since `Condition.from_dict` never raises), so the defect is not surfaced to reviewers or the hook operator. This is fully deterministic and repeatable.

### Recommendation
- In `Condition.from_dict`, reject/raise instead of silently defaulting `field` to `''` when the key is absent or empty, and propagate the error so `load_rule_file` logs a clear parsing failure instead of loading a permanently-inert rule.
- In `RuleEngine._rule_matches`/`_check_condition`, treat a condition with an unrecognized/empty `field` as a hard load-time validation error rather than a silent non-match, or at minimum emit a `stderr` warning distinguishing "field not found in this input" from "field is structurally invalid."
- Harden `extract_frontmatter`'s indentation handling (the `indent > 2` check for dict-item continuation lines) so common alternate valid YAML indentation styles do not get silently dropped.

### Proof of Concept
Unit test in `plugins/hookify/core/config_loader.py` / `rule_engine.py` context:

```python
from hookify.core.config_loader import Rule, extract_frontmatter
from hookify.core.rule_engine import RuleEngine

content = """---
name: block-secrets
enabled: true
event: file
action: block
conditions:
  - operator: contains
    pattern: API_KEY
---
Blocked: secret write attempt.
"""

frontmatter, message = extract_frontmatter(content)
rule = Rule.from_dict(frontmatter, message)

assert rule.action == "block"
assert len(rule.conditions) == 1
assert rule.conditions[0].field == ""  # missing field silently defaults

engine = RuleEngine()
input_data = {
    "hook_event_name": "PreToolUse",
    "tool_name": "Write",
    "tool_input": {"file_path": "secrets.env", "content": "API_KEY=abcd1234"},
}
result = engine.evaluate_rules([rule], input_data)

# Expected (bug): block never triggers despite action=block and matching content
assert result == {}, "Block rule silently bypassed due to missing 'field' default"
```

This demonstrates that a syntactically valid, enabled `action: block` rule with a missing `field` key never blocks the dangerous write, confirming the enforcement-weakening differential between the legacy `pattern` path (always infers a valid field) and the explicit `conditions` path (`Condition.from_dict`, which silently defaults to an unmatchable empty field).

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
