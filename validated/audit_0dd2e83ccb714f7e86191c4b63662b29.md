Based on my investigation, I found a concrete analog to the reported reentrancy bug class in `sei-chain`'s CW↔EVM bridge.

### Title
EVM→CW→EVM reentrancy allowed via `wasmd` precompile's `execute`, letting a CosmWasm contract invoked from an ERC20/ERC721/ERC1155 pointer call back into arbitrary EVM contracts mid-transaction - ([File: x/evm/keeper/evm.go])

### Summary
The `CallEVM` function that services `MsgInternalEVMCall`/`MsgInternalEVMDelegateCall` from CosmWasm explicitly blocks the "EVM->CW->EVM" pattern only when the entry was **not** via the wasmd precompile. When an EVM contract (e.g. `CW20ERC20Pointer`, `CW721ERC721Pointer`, `CW1155ERC1155Pointer`) calls the wasmd precompile's `execute()` to run a CW20/CW721/CW1155 message, and that CosmWasm contract issues a `CallEVM`/`DelegateCallEVM` custom wasm message back into the EVM, the guard `ctx.EVMEntryViaWasmdPrecompile()` is true, so the call is **permitted** — giving an attacker-controlled CW contract a synchronous callback into EVM state before the calling pointer contract's `_execute` call returns.

### Finding Description
`CW20ERC20Pointer.transfer/transferFrom/approve`, `CW721ERC721Pointer.transferFrom/approve/setApprovalForAll`, and `CW1155ERC1155Pointer` all funnel through `_execute()`, which does a `delegatecall` to the wasmd precompile's `execute(string,bytes,bytes)`: [1](#0-0) [2](#0-1) 

Inside the precompile, `execute()` calls `p.wasmdKeeper.Execute(...)`, which runs the target CosmWasm contract's `execute` entry point synchronously as part of the same EVM call stack: [3](#0-2) 

A CosmWasm contract can issue a custom wasm message (`CallEVM`/`DelegateCallEVM`) that is routed to `HandleInternalEVMCall`/`HandleInternalEVMDelegateCall`: [4](#0-3) [5](#0-4) 

These handlers call `Keeper.CallEVM`, whose reentrancy guard is:
```go
if ctx.IsEVM() && !ctx.EVMEntryViaWasmdPrecompile() {
    return nil, errors.New("sei does not support EVM->CW->EVM call pattern")
}
``` [6](#0-5) 

Because the wasmd precompile's execute path is exactly what sets `ctx` up so that `EVMEntryViaWasmdPrecompile()` is true (the precompile is invoked from an EVM tx and `ctx.IsEVM()`/entry flags flow through), this check does **not** stop an EVM contract → wasmd precompile → CW contract → `CallEVM` → back into EVM contracts round-trip. The only other defense is the *opposite* direction check in the wasmd precompile (`method.Name != QueryMethod && !ctx.IsEVM()` returns "sei does not support CW->EVM->CW call pattern"), which stops CW-originated wasmd-precompile reentry, not EVM-originated reentry through a CW hop: [7](#0-6) 

This mirrors the reported bug class exactly: an externally-triggered callback (here, a CW contract's synchronous EVM callback instead of `onERC721Received`) fires **before** the calling pointer contract (e.g. `CW20ERC20Pointer.transferFrom`, `CW721ERC721Pointer.transferFrom`) has finished its own state bookkeeping, and none of the pointer contracts implement `nonReentrant` guards on their `_execute`-calling functions.

### Impact Explanation
Any user can deploy or point to a malicious CosmWasm contract (a "CW20"/"CW721"/"CW1155" that is registered as a pointer target, or any wasm contract invoked through the wasmd precompile from an EVM contract) that, on receiving a transfer/approve message, issues a `CallEVM` custom message back into the calling EVM contract or any other EVM contract, before the original CW execution (and thus the calling pointer's external call) has returned. This breaks the "interactions after effects" invariant relied on by any EVM contract that calls into a pointer's `transfer`/`transferFrom`/`approve`/`safeTransferFrom` and expects no reentry mid-call. Composability with DeFi-style contracts on Sei (lending, vaults, marketplaces) that hold ERC20/721/1155 pointers as collateral/settlement assets is at risk of classic reentrancy-driven fund loss or state corruption (double-spend of allowance, double-withdraw, drainage) if such contracts do not independently guard against this documented but narrow-cased protection gap.

### Likelihood Explanation
Reachable by any unprivileged user: deploy a CosmWasm contract, have it registered/used as the target of a pointer or the target of any `wasmd` precompile `execute()` call from a victim EVM contract, and have that CW contract emit a `CallEVM` custom message during its own execution. No special privilege, validator collusion, or governance action is required — only the ability to submit a normal EVM transaction that triggers a `wasmd.execute` call into an attacker-controlled CW contract, which is a directly reachable path for any pointer or CW-integration user.

### Recommendation
Tighten the reentrancy guard in `CallEVM` (`x/evm/keeper/evm.go`) so that `EVMEntryViaWasmdPrecompile()` cannot be used to bypass the EVM→CW→EVM restriction once an EVM call has already entered a CW context via the wasmd precompile from within an EVM-originated call stack — i.e., track call depth/origin more strictly (e.g., a one-shot flag that is cleared once consumed, or explicit call-stack tracking) rather than a boolean that stays true for the whole CW invocation. Additionally, add `nonReentrant`-style guards (or at least ensure CEI ordering) to the pointer contracts' externally-callable functions (`CW20ERC20Pointer.transfer/transferFrom/approve`, `CW721ERC721Pointer.transferFrom/approve/setApprovalForAll`, `CW1155ERC1155Pointer` equivalents) so that no invariant-dependent state is left inconsistent across the `_execute` external call boundary.

### Proof of Concept
Conceptual PoC (cannot be fully executed without a live devnet, but the code path is concretely traceable):
1. Deploy a CosmWasm contract `Evil.wasm` implementing a CW20/CW721-compatible `execute` entry point (e.g., responding to `transfer`/`transfer_nft`) that, instead of just updating its own ledger, returns a `CustomMsg` encoding `CallEVM` (per `wasmbinding/message_plugin.go` / `x/evm/client/wasm/encoder.go`) targeting an EVM victim contract (e.g., the same pointer, or another EVM contract holding funds keyed off pointer balances).
2. From an EVM transaction, call a pointer contract (e.g., `CW20ERC20Pointer.transferFrom`) that is registered against `Evil.wasm` as its `Cw20Address`.
3. `_execute()` delegatecalls `WASMD_PRECOMPILE_ADDRESS.execute(...)` (`contracts/src/CW20ERC20Pointer.sol:98-109`), which runs `Evil.wasm`'s `execute` synchronously (`precompiles/wasmd/wasmd.go:206-290`).
4. `Evil.wasm`'s response message triggers `MsgInternalEVMCall` → `HandleInternalEVMCall` → `Keeper.CallEVM` (`x/evm/keeper/evm.go:30-45,79-82`). Because `ctx.EVMEntryViaWasmdPrecompile()` is true at this point, the call is not rejected, and the reentrant EVM call executes against the still-in-flight pointer transaction's state.
5. Observe that the reentrant call can read/mutate EVM state (e.g., pointer allowance/balance views, or a victim DeFi contract's accounting) before the original `transferFrom` call in step 2 completes, analogous to the BvbProtocol `settleContract`/`withdrawToken` reentrancy pattern in the referenced report.

func (p PrecompileExecutor) execute(ctx sdk.Context, method *abi.Method, caller common.Address, callingContract common.Address, args []interface{}, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()
	if readOnly {
		rerr = errors.New("cannot call execute from staticcall")
		return
	}
	if err := pcommon.ValidateArgsLength(args, 3); err != nil {
		rerr = err
		return
	}

	// type assertion will always succeed because it's already validated in p.Prepare call in Run()
	contractAddrStr := args[0].(string)
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		erc20pointer, _, erc20exists := p.evmKeeper.GetERC20CW20Pointer(ctx, contractAddrStr)
		erc721pointer, _, erc721exists := p.evmKeeper.GetERC721CW721Pointer(ctx, contractAddrStr)
		erc1155pointer, _, erc1155exists := p.evmKeeper.GetERC1155CW1155Pointer(ctx, contractAddrStr)
		if (!erc20exists || erc20pointer.Cmp(callingContract) != 0) && (!erc721exists || erc721pointer.Cmp(callingContract) != 0) && (!erc1155exists || erc1155pointer.Cmp(callingContract) != 0) {
			return nil, 0, fmt.Errorf("%s is not a pointer of %s", callingContract.Hex(), contractAddrStr)
		}
	}
	// addresses will be sent in Sei format
	contractAddr, err := sdk.AccAddressFromBech32(contractAddrStr)
	if err != nil {
		rerr = err
		return
	}
	senderAddr, found := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !found {
		rerr = types.NewAssociationMissingErr(caller.Hex())
		return
	}
	msg := args[1].([]byte)
	coins := sdk.NewCoins()
	coinsBz := args[2].([]byte)
	if err := json.Unmarshal(coinsBz, &coins); err != nil {
		rerr = err
		return
	}
	coinsValue := coins.AmountOf(sdk.MustGetBaseDenom()).Mul(state.SdkUseiToSweiMultiplier).BigInt()
	if (value == nil && coinsValue.Sign() == 1) || (value != nil && coinsValue.Cmp(value) != 0) {
		rerr = errors.New("coin amount must equal value specified")
		return
	}

	// Run basic validation, can also just expose validateLabel and validate validateWasmCode in sei-wasmd
	msgExecute := wasmtypes.MsgExecuteContract{
		Sender:   senderAddr.String(),
		Contract: contractAddr.String(),
		Msg:      msg,
		Funds:    coins,
	}

	if err := msgExecute.ValidateBasic(); err != nil {
		rerr = err
		return
	}

	useiAmt := coins.AmountOf(sdk.MustGetBaseDenom())
	if value != nil && !useiAmt.IsZero() {
		useiAmtAsWei := useiAmt.Mul(state.SdkUseiToSweiMultiplier).BigInt()
		coin, err := pcommon.HandlePaymentUsei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderAddr, useiAmtAsWei, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
		if err != nil {
			rerr = err
			return
		}
		// sanity check coin amounts match
		if !coin.Amount.Equal(useiAmt) {
			rerr = errors.New("mismatch between coins and payment value")
			return
		}
	}
	res, err := p.wasmdKeeper.Execute(ctx, contractAddr, senderAddr, msg, coins)
	if err != nil {
		rerr = err
		return
	}
	ret, rerr = method.Outputs.Pack(res)

func EncodeCallEVM(rawMsg json.RawMessage, sender sdk.AccAddress, info wasmvmtypes.MessageInfo) ([]sdk.Msg, error) {
	encodedCallEVM := bindings.CallEVM{}
	if err := json.Unmarshal(rawMsg, &encodedCallEVM); err != nil {
		return []sdk.Msg{}, err
	}
	decodedData, err := base64.StdEncoding.DecodeString(encodedCallEVM.Data)
	if err != nil {
		return []sdk.Msg{}, err
	}
	internalCallEVMMsg := types.MsgInternalEVMCall{
		Sender: sender.String(),
		To:     encodedCallEVM.To,
		Value:  encodedCallEVM.Value,
		Data:   decodedData,
	}
	return []sdk.Msg{&internalCallEVMMsg}, nil
}
