**Why the described attack path does not hold:**

`get_code_object_signer` enforces `assert!(object::is_owner(code_object, publisher_address), ...)` on every invocation, regardless of whether it is called directly or through an intermediate module, since Move re-evaluates this check against current on-chain storage at the exact point of the call. [1](#0-0) 

The "flash-owned object pattern" premise requires the attacker to first transfer the victim's code object to themselves within the same transaction. `object::transfer` / `transfer_raw` require the signer to already be the current owner (or an ancestor in the ownership chain via `verify_ungated_and_descendant`) — the function does not create ownership, it only moves ownership that the caller already legitimately possesses. [2](#0-1) 

Since an unprivileged attacker is by definition *not* the current owner of the victim's `code_object`, they cannot call `transfer`/`transfer_raw` on it in the first place — the call itself would abort with `ENOT_OBJECT_OWNER`/`ENO_UNGATED_TRANSFERS`/ownership-chain failure before any "transient ownership" state could exist. There is no mechanism (no reentrancy, no async callback, no stale read) in Move's sequential, single-threaded execution model that would let a `is_owner` check observe an ownership state the caller never legitimately established. [3](#0-2) 

Being `public fun` rather than `public entry fun` makes no difference here: the guard is re-checked inline at call time no matter which module (attacker-authored intermediate or not) invokes it, and the guard is identical to the one used by `upgrade` and `freeze_code_object`. [4](#0-3) 

The proof-of-concept idea (transfer to self, call `get_code_object_signer`, transfer back) fails at step one because "transfer to self" is not possible for an address that isn't already the owner/ancestor-owner. This finding assumes prior ownership authority to demonstrate the exploit, which the decision standard explicitly requires rejecting.

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }
