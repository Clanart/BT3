Audit Report

## Title
Vote program's `update_commission_bps` accepts unbounded `u16` commission values with no upper-bound check, corrupting stake/vote reward splits - (File: `programs/vote/src/vote_state/mod.rs`)

## Summary
`update_commission_bps` in `programs/vote/src/vote_state/mod.rs` (L827-859) stores a caller-supplied `commission_bps: u16` directly into vote state via `set_inflation_rewards_commission_bps`/`set_block_revenue_commission_bps` after only checking the `block_revenue_sharing` feature gate and the withdrawer signature — no check that `commission_bps <= 10_000` (100%) exists. This unbounded value is later consumed unchanged by `redeem_rewards`/`redeem_stake_rewards` in `runtime/src/inflation_rewards/mod.rs` (L35-94) to compute the staker/voter reward split, so a value above 10,000 breaks the complementary-bps arithmetic (`10_000 - commission_bps` or equivalent) that assumes the value is a valid fraction.

## Finding Description
The function signature and body confirm the missing bound: after the `BlockRevenue`/feature-gate check and `verify_authorized_signer`, the code proceeds directly to `vote_state.set_inflation_rewards_commission_bps(commission_bps)` or `set_block_revenue_commission_bps(commission_bps)` with no `commission_bps <= 10_000` assertion anywhere in the path [1](#0-0) . This contrasts with the legacy `update_commission` path, which is bounded implicitly by its `u8` percentage type and gated by `is_commission_update_allowed`'s same-epoch timing rule [2](#0-1) ; the bps path has neither a value-range check nor (per the comment) a timing rule. The stored `commission_bps: u16` field can therefore hold values up to 65,535 (655.35%), and this value is passed unchanged into `redeem_rewards`, which uses it directly in the reward-split computation and in tracer emission [3](#0-2) .

## Impact Explanation
This corrupts the staker/voter reward split for every epoch's inflation and block-revenue reward distribution tied to the affected vote account, since `redeem_rewards`/`redeem_stake_rewards` run unconditionally during epoch reward calculation. An out-of-range `commission_bps` breaks the invariant that the voter and staker shares are complementary fractions summing to the total reward, leading to fund misallocation between the validator and its delegated stakers. This matches the "fund theft/loss" and "accounting correctness" impact categories for `runtime`/accounts reward distribution.

## Likelihood Explanation
The action requires only the vote account's ordinary `authorized_withdrawer` signature — an authority that already legitimately calls `UpdateCommissionBps` in normal validator operation, requiring no elevated privilege, no malicious peer/node assumption, and no leaked keys. This is an unprivileged, publicly-reachable instruction path.

## Recommendation
Add an explicit invariant in `update_commission_bps` enforcing `commission_bps <= 10_000` before calling `set_inflation_rewards_commission_bps`/`set_block_revenue_commission_bps`, returning `InstructionError::InvalidInstructionData` otherwise. Additionally, use checked/saturating arithmetic defensively in `redeem_rewards`/`redeem_stake_rewards` and add regression tests asserting rejection of `commission_bps > 10_000`.

## Proof of Concept
1. A validator's withdraw-authority signer submits `VoteInstruction::UpdateCommissionBps(20000, CommissionKind::InflationRewards)` for its vote account.
2. `update_commission_bps` only checks the feature gate and withdrawer signature, then unconditionally stores `commission_bps = 20000` (200%) into vote state [1](#0-0) .
3. On the next epoch reward distribution, `redeem_rewards` passes this `voter_commission_bps` into the split calculation [3](#0-2) , producing a staker/voter split that no longer sums to the total reward.

Note: the exact downstream arithmetic in `runtime/src/inflation_rewards/points.rs` that consumes `commission_bps` (saturating vs. checked subtraction, and whether it panics or silently over-allocates) could not be fully retrieved/verified within the available tool budget in this session; this detail should be confirmed directly against that file before finalizing severity, though the missing bound in `update_commission_bps` itself is clearly confirmed in the code shown above.

/// Update the vote account's commission in basis points (SIMD-0291, SIMD-0123).
pub fn update_commission_bps<S: std::hash::BuildHasher>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    commission_bps: u16,
    kind: CommissionKind,
    signers: &HashSet<Pubkey, S>,
    block_revenue_sharing_enabled: bool,
) -> Result<(), InstructionError> {
    // Per SIMD-0291: BlockRevenue returns InvalidInstructionData unless
    // SIMD-0123 (block_revenue_sharing) is enabled.
    if matches!(kind, CommissionKind::BlockRevenue) && !block_revenue_sharing_enabled {
        return Err(InstructionError::InvalidInstructionData);
    }

    let mut vote_state = get_vote_state_handler_checked(vote_account, target_version)?;

    // No commission update rule, per SIMD-0249 and SIMD-0291.

    // Require authorized withdrawer to sign.
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;

    match kind {
        CommissionKind::InflationRewards => {
            vote_state.set_inflation_rewards_commission_bps(commission_bps);
        }
        CommissionKind::BlockRevenue => {
            vote_state.set_block_revenue_commission_bps(commission_bps);
        }
    }

    vote_state.set_vote_account_state(vote_account)
}

/// Given the current slot and epoch schedule, determine if a commission change
/// is allowed
pub fn is_commission_update_allowed(slot: Slot, epoch_schedule: &EpochSchedule) -> bool {
    // always allowed during warmup epochs
    if let Some(relative_slot) = slot
        .saturating_sub(epoch_schedule.first_normal_slot)
        .checked_rem(epoch_schedule.slots_per_epoch)
    {
        // allowed up to the midpoint of the epoch
        relative_slot.saturating_mul(2) <= epoch_schedule.slots_per_epoch
    } else {
        // no slots per epoch, just allow it, even though this should never happen
        true
    }
}

pub(crate) fn redeem_rewards<'a>(
    mut stake: Stake,
    voter_commission_bps: u16,
    vote_state: DelegatedVoteState,
    calculation_environment: CalculationEnvironment<'a>,
    inflation_point_calc_tracer: Option<impl Fn(&InflationPointCalculationEvent)>,
    ag_epoch_type: &AlpenglowEpochType,
    current_lamports: u64,
    minimum_lamports: u64,
) -> Result<(u64, u64, Stake), InstructionError> {
    if let Some(inflation_point_calc_tracer) = inflation_point_calc_tracer.as_ref() {
        let CalculationEnvironment {
            rewarded_epoch,
            stake_history,
            new_rate_activation_epoch,
            commission_rate_in_basis_points,
            use_fixed_point_stake_math,
            ..
        } = calculation_environment;
        let effective_stake_at_rewarded_epoch = effective_stake(
            &stake,
            rewarded_epoch,
            stake_history,
            new_rate_activation_epoch,
            use_fixed_point_stake_math,
        );
        inflation_point_calc_tracer(
            &InflationPointCalculationEvent::EffectiveStakeAtRewardedEpoch(
                effective_stake_at_rewarded_epoch,
            ),
        );
        inflation_point_calc_tracer(&InflationPointCalculationEvent::PriorTotalLamports(
            current_lamports,
        ));
        // Choose which trace to emit based on the `commission_rate_in_basis_points` feature.
        if commission_rate_in_basis_points {
            inflation_point_calc_tracer(&InflationPointCalculationEvent::CommissionBps(
                voter_commission_bps,
            ));
        } else {
            inflation_point_calc_tracer(&InflationPointCalculationEvent::Commission(
                (voter_commission_bps / 100) as u8,
            ));
        }
    }

    if let Some((stakers_reward, voters_reward)) = redeem_stake_rewards(
        &mut stake,
        voter_commission_bps,
        vote_state,
        calculation_environment,
        inflation_point_calc_tracer,
        ag_epoch_type,
        current_lamports,
        minimum_lamports,
    ) {
        Ok((stakers_reward, voters_reward, stake))
    } else {
        Err(StakeError::NoCreditsToRedeem.into())
    }
