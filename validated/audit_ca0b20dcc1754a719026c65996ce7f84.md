### Title
Reward and Stake-Weight Calculations Trust the Raw Native KAIA Balance of Staking Contracts, Allowing Anyone to Inflate a Validator's Measured Stake via a Plain Transfer - (File: kaiax/staking/impl/getter.go)

### Summary
The `kaiax/staking` module derives each validator's `StakingAmount` — the value used to compute KIP-82/Kore/Flex staking-reward splits, minimum-stake eligibility, and the Gini coefficient — directly from the native KAIA balance of the validator's staking contract address, rather than from an internally tracked "staked principal" ledger. Because a plain KAIA transfer to any address is unrestricted, an unprivileged transaction sender can inflate the measured stake of any known staking contract simply by sending it KAIA, in the exact same manner the external report's attacker inflated `Aggregator.totalAssets()` by transferring tokens directly into the contract.

### Finding Description
`StakingModule.getFromState` (`kaiax/staking/impl/getter.go`) calls the system `MultiCallContract` to fetch `(typeList, addressList, stakingAmounts, ...)` and passes the resulting `stakingAmounts` straight into `parseCallResult`/`parsePermissionlessCallResult`, which just divides by `params.KAIA` and stores them as `StakingInfo.StakingAmounts`: [1](#0-0) [2](#0-1) 

The test `TestGetStakingInfo_Uncached` proves that these `stakingAmounts` are sourced from the plain native balance of the staking contract addresses: the genesis allocation sets `Balance` directly on the staking addresses (`0x...0F01`, `0x...0f04`) with no staking-specific setup, and the resulting `StakingInfo.StakingAmounts` equal exactly those balances (divided into whole KAIA units): [3](#0-2) 

This `StakingAmount` (and its consolidated form, `consolidatedNode.StakingAmount`) is the sole input to the reward-splitting logic in `kaiax/reward`, e.g. `assignStakingRewards`/`assignStakingRewardsFlex`, which allocate the staker reward budget proportionally to each validator's stake in excess of `MinimumStake`/`StakingRewardThreshold`: [4](#0-3) [5](#0-4) 

The `staking()`/`unstaking()` view functions exposed by the `CnStakingV4` contract binding show that the contract does maintain its own internal accounting of staked/unstaked amounts: [6](#0-5) 

Yet the block-processing/reward path never consults this internal ledger — it reads the contract's raw `.balance` via `MultiCallStakingInfo(Permissionless)`. Any account, including one with no relationship to the validator, can therefore increase a target staking contract's `.balance` with an ordinary value-transfer transaction (the staking contract addresses are public, published in the on-chain AddressBook/AddressBookV2), which is picked up verbatim as additional "staking amount" for that validator in the very next block that samples `StakingInfo`.

### Impact Explanation
Because reward allocation among validators (`assignStakingRewards`, `assignStakingRewardsFlex`), minimum-stake reward eligibility, weighted-random proposer selection weight, and the Gini coefficient all depend on `StakingInfo.StakingAmounts`, an attacker can:
- Push a validator over `MinimumStake`/`minstake` to make it reward-eligible when its genuinely locked stake would not qualify.
- Skew the proportional split of the staker reward budget (and potentially proposer-selection weighting) toward a target reward address by inflating the balance of its staking contract with an unstructured donation that was never actually committed through the staking/delegation flow.
- Redirect block-reward distribution among validators (a concrete "reward redirection" outcome), the same value-movement class flagged as Medium risk in the source report, because the distribution no longer reflects real committed capital-at-risk.

This mirrors the root cause of the referenced finding exactly: a share/distribution calculation trusts `balanceOf(address(this))`/`.balance` instead of an authoritative internal accounting variable, letting an unprivileged sender manipulate the outcome via a direct transfer.

### Likelihood Explanation
Likelihood is high for the mechanical trigger (a plain KAIA transfer to a public, known contract address requires no special privilege, no contract interaction, and no timing window — it is a single ordinary transaction), but the net economic benefit to the attacker depends on whether the CnStakingV4 contract lets the donor later reclaim the donated balance; this could not be fully confirmed since the CnStakingV4 Solidity source was not present in the indexed subset of this repository (only the Go bindings were available). Even without fund recovery, the finding stands as a state-integrity/reward-fairness issue: it lets a third party unilaterally and cheaply distort validator reward shares, minimum-stake eligibility, and Gini-based parameters that are core governance/reward invariants of the chain.

### Recommendation
Compute `StakingAmount` from the staking contract's own internally tracked `staking`/`unstaking` accounting (already exposed via `staking()`/`unstaking()`), or have the system `MultiCallContract` read that accounting field instead of the raw address balance, so that unsolicited transfers to a staking contract cannot influence reward distribution, eligibility thresholds, or the Gini coefficient computed in `kaiax/staking` and consumed by `kaiax/reward`.

### Proof of Concept
Not executable from the indexed context alone (no local devnet/CnStakingV4 source available here), but the mechanism is directly demonstrated by the existing test fixture, which shows that setting `Balance` on a staking address in isolation (with no staking/delegation calls) fully determines `StakingInfo.StakingAmounts`: [3](#0-2) 
An attacker reproduces this in production by sending a plain value transfer (`to = councilStakingAddr`, no data) to any address published in `councilStakingAddrs`/`AddressBookV2`; the very next block's `StakingInfo` (and subsequent `FinalizeState` reward allocation in `kaiax/reward/impl/blockstate.go`) will reflect the inflated balance as additional stake. [7](#0-6)

// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}

	// Distribute the budget to the CNs based on the excess stakes.
	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(budget)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		if excessInt[cn.RewardAddr] <= 0 {
			continue
		}
		excess := new(big.Int).SetUint64(excessInt[cn.RewardAddr])

		// The KAIA unit will cancel out:
		// reward (kei) = excess (KAIA) * budget (kei) / totalExcess (KAIA)
		reward := new(big.Int).Div(new(big.Int).Mul(excess, budget), totalExcess)
		if reward.Sign() <= 0 {
			continue
		}

		// If Prague and CL is configured for this CN, split the reward between CN and CL.
		if isPrague && cn.CLStakingInfo != nil {
			cnAmount, clAmount := cn.Split(reward)
			alloc[cn.RewardAddr] = cnAmount
			alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
		} else {
			alloc[cn.RewardAddr] = reward
		}
		remaining.Sub(remaining, reward)
	}
	return alloc, remaining
}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining

// Distribute the deferred rewards at the end of block processing.
func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
}
