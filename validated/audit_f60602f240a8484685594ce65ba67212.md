Based on my research, I found a legitimate analog to the reported bug class, but it appears to have been remediated in the current codebase and only survives in frozen legacy version snapshots.

### Title
Bank precompile `sendNative`/`send` bypasses `IsSendEnabledCoins`/`BlockedAddr`/allowlist checks enforced by `MsgSend` in legacy precompile versions - (`precompiles/bank/legacy/v555/bank.go`)

### Summary
The reported bug class is "a pausable/gated wrapper entrypoint can be bypassed by calling the underlying privileged function directly." In sei-chain, the analogous gate is the bank module's `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` checks, which are only enforced inside `msgServer.Send` (the `MsgSend` handler) — not inside `BaseSendKeeper.SendCoins` itself. Legacy versions of the EVM bank precompile call `p.bankKeeper.SendCoins(...)` directly instead of going through the message-server path, so an EVM user can move funds while bypassing the checks a normal `MsgSend` transaction would enforce.

### Finding Description
`sei-cosmos/x/bank/keeper/msg_server.go` enforces the "pause"-like gates before transferring funds: [1](#0-0) 

These checks (`IsSendEnabledCoins`, `IsInDenomAllowList`, `BlockedAddr`) are not part of `BaseSendKeeper.SendCoins` itself: [2](#0-1) 

The legacy bank precompile's `send` function (used for pointer-based ERC20 transfers of native denoms) calls `p.bankKeeper.SendCoins` directly, skipping the `IsSendEnabledCoins` and allowlist/blocked-address checks that `MsgSend` performs: [3](#0-2) 

Similarly, `sendNative` in the same legacy version calls `p.bankKeeper.SendCoinsAndWei` directly, again without routing through the msg server's gates: [4](#0-3) 

This mirrors versions v552 through v620 based on the grep results, all of which call `bankKeeper.SendCoins(...)` directly rather than `bankMsgServer.Send(...)`.

Later versions (v630, v640, and the current `precompiles/bank/bank.go`) fixed this by routing through `p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg)`, which re-enters `msgServer.Send` and enforces `IsSendEnabledCoins`/allowlist/`BlockedAddr`: [5](#0-4) 

### Impact Explanation
If a denom's transfers are disabled via governance (`SendEnabled=false`) or an address/denom is placed on an allowlist/blocklist as an emergency safety control, users interacting with the affected token's ERC20 pointer contract via the legacy bank precompile paths could still move funds, bypassing the module-level "pause"/restriction control — analogous to the reported ArrakisV2 issue where the router's `whenNotPaused` protection is bypassed via a direct call. This could allow continued unauthorized transfers during an emergency freeze of a specific denom.

### Likelihood Explanation
Exploitability depends on whether the legacy precompile version paths (`v552`–`v620`) are still live/selectable code paths on the current chain (e.g., through height-gated precompile dispatch used for replay/upgrade compatibility) versus purely retained as frozen historical snapshots no longer reachable by new transactions. I could not confirm from the available index whether these legacy folders are still dispatched to for current block heights or are dead code retained only for historical state replay — this determines whether the issue is currently live or already fully remediated by the `v630`+ fix.

### Recommendation
Confirm whether the legacy precompile versions (`v552` through `v620`) are still reachable for current/future block execution. If they are, backport the `bankMsgServer.Send` fix (as done in v630/v640) to route all fund-moving precompile paths through the bank module's message server so `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` are consistently enforced regardless of entrypoint. If the legacy versions are provably unreachable dead code, this issue has no current impact.

### Proof of Concept
1. Governance/admin sets `SendEnabled=false` for a specific denom (or adds an address to the denom's blocklist/allowlist restriction) via bank params, intending to halt transfers of that asset.
2. A user holding the corresponding ERC20 pointer contract for that denom calls the pointer contract's `send`/`transfer`, which invokes the bank precompile's `send` (or `sendNative`) function.
3. In the legacy precompile code path (`v552`–`v620`), this calls `p.bankKeeper.SendCoins` (or `SendCoinsAndWei`) directly, which does not check `IsSendEnabledCoins`/`IsInDenomAllowList`/`BlockedAddr`.
4. The transfer succeeds despite the denom being marked disabled — bypassing the intended chain-level restriction, exactly as the reported Arrakis issue bypasses the router's `whenNotPaused` state via direct vault calls.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

func (p Precompile) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

func (p Precompile) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call sendNative from staticcall")
	}
	if caller.Cmp(callingContract) != 0 {
		return nil, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, err
	}

	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		remainingGas := pcommon.GetRemainingGas(newCtx, p.evmKeeper)
		if hooks.OnEnter != nil {
			hooks.OnEnter(evm.GetDepth()+1, byte(vm.CALL), caller, p.evmKeeper.GetEVMAddressOrDefault(newCtx, receiverSeiAddr), []byte{}, remainingGas, value)
		}
		defer func() {
			if hooks.OnExit != nil {
				hooks.OnExit(evm.GetDepth()+1, []byte{}, 0, nil, false)
			}
		}()
	}

	return method.Outputs.Pack(true)
}
