This confirms the analog. The tests explicitly cover rollback protection via the `LastRewardedHeight` watermark, but there is no test or guard for a rate change mid-backlog — the reward calculation always uses whatever `cost_per_block` is stored *at execution time*, applied to the *entire* unpaid block span, regardless of what rate was actually in effect while those blocks accrued.

### Title
Consensus relayer reward retroactively priced at current `cost_per_block`, allowing backlog rate-arbitrage that drains the treasury - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::process_message` computes relayer rewards as `(latest_height - LastRewardedHeight) * current_cost_per_block`, where `current_cost_per_block` is the value read from `StateMachinesCostPerBlock` at the moment `on_executed` runs, not the rate(s) that were actually in force while each of those blocks accrued. This mirrors the BMX Deli Swap `Voter::finalize()` bug: a stale/backlogged quantity (elapsed blocks, analogous to un-transferred WETH) gets priced at whatever rate is active *when settlement finally happens*, rather than the rate that should have applied to each portion of the backlog.

### Finding Description
`calculate_reward` in [1](#0-0)  computes `blocks = latest_height.saturating_sub(baseline)` where `baseline` is `LastRewardedHeight` (or `previous_height` on first reward), then multiplies the *entire* span by the `block_cost` argument. That `block_cost` is passed in by `process_message` as `StateMachinesCostPerBlock::<T>::get(state_machine_id)` — the rate stored in the pallet's storage **right now**, at [2](#0-1) .

The rate is governance-settable at any time via `update_cost_per_block`, which simply overwrites `StateMachinesCostPerBlock` with no interaction with `LastRewardedHeight` or any historical-rate bookkeeping: [3](#0-2) .

Because `LastRewardedHeight` only advances when a relayer actually submits a `ConsensusMessage` for that state machine (see `on_executed`/`process_message` at [4](#0-3) ), the unpaid backlog can grow arbitrarily large simply by *no relayer submitting an update* for that state machine — a fully permissionless, non-malicious condition (light client updates for a chain can legitimately go unsubmitted for a while, or a relayer can simply choose not to submit).

The exploit: an ordinary, unprivileged relayer withholds submitting `ConsensusMessage`s for a state machine while `cost_per_block` is low. Once governance later raises `cost_per_block` for that state machine (a routine parameter tuning operation, not an adversarial admin act), the relayer submits a single consensus update that advances the height by the entire backlog. `calculate_reward` then pays `backlog_blocks * new_higher_cost_per_block` out of the treasury — a reward far larger than the sum of what should have been paid under the rates actually in force during accrual. This is the same broken invariant as H-8: applying a *new* rate to a quantity that accumulated under a stale rate, letting an ordinary participant arbitrage the mismatch and drain funds meant for the correct distribution.

The `reward_covers_only_unpaid_heights_after_rollback` test at [5](#0-4)  only validates that a *rolled-back* height span isn't double-paid; it never varies `cost_per_block` between the accrual period and the payout, so the rate-arbitrage path is untested and unguarded.

### Impact Explanation
This directly drains `T::TreasuryAccount` funds via `T::Currency::transfer` at [6](#0-5) , paying an inflated amount to a relayer for backlog blocks that should have been priced at the lower historical rate(s). This is unauthorized/incorrect fund transfer from the treasury — the exact "stealing or loss of funds" / "transaction manipulation" class the bounty targets — achievable by any address capable of relaying (submitting) a signed `ConsensusMessage`, with no compromised keys, no malicious node/prover assumptions, and no governance collusion required.

### Likelihood Explanation
Likelihood is moderate-to-high wherever `cost_per_block` is periodically re-tuned by governance (an expected, normal operational activity for any incentive parameter) and where a state machine's consensus updates aren't perfectly continuous — both realistic conditions. The attacker only needs to observe the public `StateMachineCostPerBlockUpdated` event/extrinsic and time their (otherwise completely legitimate) relay submission to fall right after a rate increase while a backlog exists.

### Recommendation
Do not price the entire unpaid backlog at the rate read at settlement time. Either: (1) require `update_cost_per_block` to first settle/flush all pending rewards at the old rate for every affected state machine before installing the new rate (analogous to calling `setTokensPerInterval` before, not after, transferring funds in the referenced report), or (2) record a rate-effective-height history and split `calculate_reward`'s block span across the applicable historical rate segments instead of applying a single current rate to the whole span.

### Proof of Concept
1. Governance sets `StateMachinesCostPerBlock[SM] = 1` via `update_cost_per_block`.
2. No relayer submits a `ConsensusMessage` for `SM` for a long period; the remote chain's `latest_commitment_height` advances far beyond `LastRewardedHeight[SM]` off-chain (light client is simply not fed).
3. Governance raises the rate: `update_cost_per_block(SM, 1000)`.
4. A relayer now submits a single `ConsensusMessage` advancing `SM` to its current (backlogged) height.
5. `process_message`/`calculate_reward` pays `backlog_blocks * 1000` from the treasury in one transfer — as shown by the existing test pattern at [7](#0-6) , which can be trivially modified to call `update_cost_per_block` with a higher value between accrual and the `on_executed` call to demonstrate the inflated payout.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {

						.and_modify(|h| {

								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),

fn reward_covers_only_unpaid_heights_after_rollback() {

	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();

			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);

				state_machine_id,
				latest_height: height,
			})]

		host.store_state_machine_commitment(

		.unwrap();

			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })

		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();

			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
