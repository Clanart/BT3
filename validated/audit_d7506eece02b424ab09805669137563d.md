## Title
Spoofable `WWW-Authenticate` realm triggers GitHub Enterprise sign-in prompt for an attacker-controlled remote, enabling credential/OAuth binding to a malicious endpoint - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
The Git credential-helper trampoline decides whether a remote host should be treated as a "GitHub"/"GitHub Enterprise" endpoint (and thus routed to Desktop's trusted GitHub sign-in flow) partly based on the `WWW-Authenticate` HTTP header value that the *remote server itself* returns during authentication. This header is fully attacker-controlled by any git remote/proxy the user fetches from, allowing that remote to impersonate a GitHub Enterprise host and cause Desktop to display its native "Sign in to GitHub" dialog and bind resulting credentials to the attacker's endpoint.

The comment itself acknowledges the values come from the network peer: *"When Git attempts to authenticate with a host it captures any WWW-Authenticate headers and forwards them to the credential helper."* Any git remote (including an attacker-controlled server the user simply clones/fetches from, or a malicious proxy on the network path for a plain-HTTP or MITM'd HTTPS clone) can respond to Git's authentication probe with a header like `WWW-Authenticate: Basic realm="GitHub"`. There is no verification that the responding host is actually `github.com`/`*.ghe.com`/a known GHES instance — the classification is a purely self-asserted string match.

Once classified as `'enterprise'`, `getCredential()` in [3](#0-2)  takes the trusted path: if no existing account matches the endpoint, it calls `ui.promptForGitHubSignIn(endpoint)` (line 118) instead of falling back to the generic/external credential helper. `promptForGitHubSignIn()` in [4](#0-3)  then opens Desktop's native GitHub/GitHub Enterprise sign-in UI, pointed at the attacker-supplied `endpoint`/`origin` (derived straight from the untrusted remote URL), via `dispatcher.setSignInEndpoint(origin)` and `beginEnterpriseSignIn`.

This breaks the invariant that Desktop's "trusted, first-party GitHub sign-in" UI (and the credential storage path reserved for GitHub/GHE accounts) is only reachable for endpoints that are actually verified to be GitHub hosts. Instead, that determination is made from a network-supplied header with no cryptographic or authoritative binding to the real identity of the host — analogous to the original report's flaw where a boolean mode flag (`useUnderlying`) was hard-set without checking the actual state of the object it was being applied to, causing behavior mismatched to reality.

Secondary effect: because `storeCredential()`/`eraseCredential()` (lines 182-213) also gate on `getEndpointKind(cred, store) !== 'generic'`, a spoofed `realm="GitHub"` response also *suppresses* normal generic credential-helper storage/erasure for that (actually non-GitHub) host, silently changing how credentials for that remote are persisted.

### Impact Explanation
An attacker who controls a git remote/proxy that the victim clones or fetches from (no local access, no prior malware, no leaked credentials needed) can:
- Force Desktop to display its trusted-looking native "Sign in to GitHub Enterprise" dialog for the attacker's arbitrary host, which is a UI/trust-boundary violation initiated purely by a spoofed protocol header from an untrusted peer.
- Cause the resulting sign-in flow (`beginEnterpriseSignIn` / `setSignInEndpoint`) to bind an account entry to the attacker-chosen endpoint if the user completes it, i.e., unauthorized account binding driven by attacker-controlled remote data — the endpoint that ends up stored is not validated to be a genuine GitHub Enterprise Server.
- Suppress or bypass the generic credential-helper storage path for a non-GitHub host, silently altering how Git handles authentication material for that remote.

This matches the "unauthorized OAuth or account binding" category in the accepted impact list, and is reachable purely by the attacker controlling a git remote/proxy response — no elevated privileges or user missteps beyond a normal `clone`/`fetch`/`push` against a hostile remote.

### Likelihood Explanation
Triggering the header is trivial for anyone who controls a git server (or a MITM/plain-HTTP proxy) that the user interacts with — sending an HTTP `401` with `WWW-Authenticate: Basic realm="GitHub"` is standard server behavior, requiring no exploit of Git or Desktop internals. The only additional condition is that the user has no existing signed-in account whose origin already matches the endpoint (the common case for a first interaction with a new/malicious remote), and that they proceed with the resulting sign-in prompt — a realistic scenario since the prompt is styled as Desktop's own trusted GitHub sign-in UI rather than a third-party warning.

### Recommendation
Do not use the self-reported `WWW-Authenticate` realm string as sufficient evidence that a host is GitHub/GitHub Enterprise. At minimum:
- Require the `isGitHubHost()` authoritative check (an actual API probe/certificate-based verification) before trusting a `realm="GitHub"` header, rather than treating the header as a standalone "happy path" that bypasses that check.
- Never call `promptForGitHubSignIn()`/bind a sign-in endpoint based solely on unauthenticated data returned by the remote itself; visually distinguish and independently confirm hosts before offering the trusted GitHub sign-in surface.

### Proof of Concept
1. Attacker hosts a git-over-HTTP server (or a MITM proxy for an HTTP remote) at `https://evil.example.com/victim/repo.git`.
2. Victim adds this URL as a remote and runs `fetch`/`clone`/`push` in GitHub Desktop.
3. When Git performs its normal auth probe, the attacker's server responds with `WWW-Authenticate: Basic realm="GitHub"` on the `401` response.
4. Git forwards this via the credential-helper protocol as a `wwwauth[N]` field; `trampoline-credential-helper.ts`'s `getEndpointKind()` matches `realm="GitHub"` (line 159) and returns `'enterprise'` without checking that `evil.example.com` is a real GitHub Enterprise instance [2](#0-1) .
5. `getCredential()` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')` [5](#0-4) , which opens Desktop's native Enterprise sign-in flow bound to that attacker-chosen origin [6](#0-5) .

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
