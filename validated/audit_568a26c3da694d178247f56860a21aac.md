### Title
Unbounded index parsing in `is_clvm_canonical()`/`is_atom_canonical()` on attacker-controlled spend-bundle bytes - (File: `chia/full_node/mempool_manager.py`)

### Summary
`chia/full_node/mempool_manager.py` contains `is_clvm_canonical()` and its helper `is_atom_canonical()`, which manually walk a raw CLVM-serialized byte buffer to determine whether a solution's serialization is in canonical (dedup-eligible) form [1](#0-0) . This mirrors the Shim CVE-2023-40549 bug class: a custom binary-format parser advances an offset and reads length-prefix bytes from an untrusted buffer without first verifying that the offset is still within the buffer bounds at each step.

### Finding Description
`is_atom_canonical()` reads `clvm_buffer[offset]` and then, based on the high bits of that byte, reads `prefix_len` (up to 5) additional bytes at increasing offsets to reconstruct the atom's length, incrementing `offset` in a loop with no bounds check against `len(clvm_buffer)`: [2](#0-1) 

`is_clvm_canonical()` similarly walks the buffer with an `offset` cursor, advancing it by 1 for pair/small-atom tokens or by `atom_len` for larger atoms, again with no length check before dereferencing `clvm_buffer[offset]` on each iteration: [3](#0-2) 

Both functions assume the buffer is well-formed and long enough to satisfy every length-prefix and payload they claim to encode. A crafted, truncated CLVM buffer (e.g., a length-prefix byte claiming a multi-byte prefix or large atom length that exceeds the actual buffer size) causes `clvm_buffer[offset]` to be indexed past the end of the buffer. In CPython this raises `IndexError` rather than reading adjacent heap memory (unlike the C-based Shim parser), so the "out-of-bounds read" here manifests as an unhandled exception rather than a memory-safety violation — the underlying root cause (parsing a length-prefixed binary format without validating remaining-buffer length before advancing/dereferencing) is analogous.

Per the accompanying context notes, this canonical-form check is used to gate DEDUP-eligible spends, i.e., it processes solution bytes taken directly from a submitted `CoinSpend`/`SpendBundle`, meaning the buffer content is attacker-controlled from the perspective of a single spend-bundle submitter [4](#0-3) .

### Impact Explanation
If the exception raised by an out-of-range index is not caught by the caller in the mempool-admission path, an attacker who submits a spend bundle with a malformed/truncated solution buffer for a fast-forward/dedup-eligible spend could trigger an unhandled `IndexError` during mempool processing of that single transaction, causing spend-bundle admission logic to fail unexpectedly. This is a potential spend-triggered transaction-processing disruption, consistent with the report's "Medium" bug class of parser boundary-verification failures leading to a processing halt, rather than any fund-loss or consensus-divergence primitive.

### Likelihood Explanation
Likelihood is contingent on whether this canonical check is reached with fully untrusted, attacker-crafted bytes before any other well-formedness validation of the solution (e.g., prior CLVM deserialization) would already reject a malformed buffer, and whether the call site wraps this check in exception handling. I was not able to confirm the exact call site(s) invoking `is_clvm_canonical()` from `pre_validate_spendbundle()` or the fast-forward/dedup eligibility path within the available indexed context, so I cannot fully confirm end-to-end reachability with unvalidated raw bytes versus already-parsed/well-formed `Program` objects.

### Recommendation
Add explicit bounds checks in both `is_atom_canonical()` and `is_clvm_canonical()` before each buffer dereference/offset advance (verify `offset < len(clvm_buffer)` and that `offset + prefix_len`/`offset + atom_len` do not exceed `len(clvm_buffer)`), returning `False` (non-canonical) or raising a well-defined `ValidationError`/`Err` instead of allowing a raw `IndexError` to propagate. Ensure the mempool-admission call site wraps this parsing in the same exception handling used for other malformed-spend-bundle paths so a crafted buffer degrades to bundle rejection, not an unhandled exception.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```markdown
## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
```
