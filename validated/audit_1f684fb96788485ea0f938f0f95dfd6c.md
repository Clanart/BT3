### Title
Payout OP_RETURN operator attribution is not covered by the withdrawal signature, allowing third-party RBF replacement to break `payout_txid`/`payout_payer_operator_xonly_pk` attribution - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The user's withdrawal signature enforced by `parser::operator::parse_withdrawal_sig_params` uses `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) , which under BIP341 only commits to the single spent input and the output at the same index (output 0, the user payout output). The OP_RETURN output (index 2) carrying the funding operator's `xonly_pk` in `create_payout_txhandler` is never covered by this signature [2](#0-1) . Any party who observes the operator's broadcast (unconfirmed, RBF-replaceable) payout transaction can therefore build an alternative, still-validly-signed transaction spending the same withdrawal UTXO with the same output-0 payout, a higher fee, and a different OP_RETURN operator field, and get it mined instead via RBF.

### Finding Description
Binding claimed to hold: `payout_txid` and `payout_payer_operator_xonly_pk` recorded by `update_finalized_payouts` == the txid/operator that the real funding operator actually broadcast.

Trace:
1. `Operator::withdraw` verifies the user's `in_signature` against the sighash computed over the specific `payout_txhandler`, and rejects anything other than `SinglePlusAnyoneCanPay` [3](#0-2) . This sighash type, per BIP341, commits to: nVersion, nLockTime, the single ANYONECANPAY-selected input (prevout, amount, scriptPubkey, sequence), and the output at the same index as that input (output 0 only). It does **not** commit to output 1 (anchor) or output 2 (OP_RETURN with operator xonly_pk), nor to the total output count.
2. `Operator::withdraw` funds and RBF-broadcasts this transaction via `fund_raw_transaction`/`sign_raw_transaction_with_wallet`/`send_raw_transaction` [4](#0-3) .
3. Because the same `in_signature`, `in_outpoint`, `out_script_pubkey`, and `out_amount` are public (readable from the Citrea withdrawal event / passed to the public `Aggregator::withdraw` gRPC endpoint and to `Verifier`'s `create_optimistic_payout_txhandler` equivalent flow) [5](#0-4) , an unprivileged attacker can reconstruct an equivalent `create_payout_txhandler` with the identical signed input and output 0, but a different OP_RETURN (pointing to no operator, an unrelated public operator xonly_pk, or garbage), add their own fee-paying inputs, and pay a higher fee than the operator's broadcast tx.
4. Because the operator's payout tx used default sequence (not final, i.e. RBF opt-in is implied by ordinary broadcast/fund_raw_transaction, and the tx is unconfirmed), the attacker's replacement can validly replace it per BIP125 in the mempool, and later get mined with a different txid and different OP_RETURN.
5. `update_finalized_payouts` reads whichever transaction actually confirmed spending the withdrawal outpoint (via `get_payout_txs_for_withdrawal_utxos` joined on `bitcoin_syncer_spent_utxos`) and parses the OP_RETURN of that confirmed transaction to set `payout_payer_operator_xonly_pk` [6](#0-5) . It has no way to distinguish the "real" funding operator's intended attribution from the attacker's substituted OP_RETURN, since nothing in the protocol binds the OP_RETURN to the signature.
6. Downstream, `Verifier::is_kickoff_malicious` compares the DB-recorded `operator_xonly_pk` (now the attacker's chosen value) against `kickoff_data.operator_xonly_pk` (the real funding operator's own key) and, on mismatch, flags the kickoff as malicious, triggering a `Challenge` [7](#0-6) . In the BitVM `additional_disprove` path, `deposit_constant` for the operator's own kickoff/assert scripts is computed using the operator's **own** `xonly_pk` (set at kickoff-creation time via `operator_data.xonly_pk` / `kickoff_data.operator_xonly_pk`) [8](#0-7) , while the bridge circuit later recomputes `deposit_constant` for the *proof* using the operator xonly_pk parsed from the **actual on-chain payout tx's OP_RETURN** [9](#0-8) . If the attacker swapped the OP_RETURN, these two `deposit_constant` values diverge, meaning the honest operator can never construct a valid disprove-resisting BitVM assertion for that specific kickoff — the true claim becomes unprovable and/or the operator gets disproven/challenged.

No existing guard prevents this: `SECP.verify_schnorr` only validates the SIGHASH_SINGLE|ANYONECANPAY sighash (excludes OP_RETURN), `update_finalized_payouts` blindly trusts whichever tx confirms, and `is_kickoff_malicious` / the bridge circuit's `deposit_constant` computation trust the on-chain OP_RETURN rather than any signed/committed value.

### Impact Explanation
This breaks the "an honest operator permanently unable to be reimbursed" / "a true claim made unprovable by the bridge...circuit" / "an honest operator's collateral burned" Critical categories: the honest operator fully funds the user's withdrawal (their BTC leaves their control to pay the user) but the on-chain attribution used both by verifiers' automatic malicious-kickoff detection and by the BitVM disprove circuit points to a different/no operator, causing the honest operator's kickoff to be treated as malicious/unprovable, exposing them to challenge/disprove and loss of reimbursement/collateral. This is repeatable per-withdrawal by any unprivileged party who monitors the mempool and outbids the operator's payout tx fee (the fee delta is bounded by mempool minimum relay-fee increments, so the cost is low), and applies to every operator and every withdrawal that Clementine processes, since the SIGHASH_SINGLE|ANYONECANPAY design is systemic.

### Likelihood Explanation
Preconditions: the operator's payout tx must be unconfirmed at the moment of attack (routine, since confirmation is not instantaneous), it must be RBF-eligible (opt-in RBF is implied by the way `TxSender`/`fund_raw_transaction` constructs it and by BIP125 replaceability defaults used by clementine-tx-sender), and the attacker must be able to outbid the current fee with their own BTC for fees only (they do not need to pay the withdrawal amount itself, since output 0 is fixed by the signature). This is fully within reach of an unprivileged attacker who only needs to watch the Bitcoin mempool/Citrea withdrawal events and have modest BTC for fee-bumping.

### Recommendation
Bind the OP_RETURN operator attribution into the signed message so it cannot be altered without invalidating the user's signature — e.g., require the withdrawal `in_signature` to use `SIGHASH_ALL|ANYONECANPAY` (committing to all outputs) rather than `SinglePlusAnyoneCanPay`, or otherwise cryptographically bind the operator's `xonly_pk` and full output set into what the user signs (e.g., have the user's off-chain agreement include the operator identity as part of a covenant/commitment verified separately from the on-chain OP_RETURN). Alternatively, disallow attribution derived purely from an unauthenticated OP_RETURN and instead require the operator to separately, verifiably commit (e.g. via a Winternitz/pre-signed disprove-time commitment bound to the specific payout txid) to which payout tx they funded, independent of mempool RBF races.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }
