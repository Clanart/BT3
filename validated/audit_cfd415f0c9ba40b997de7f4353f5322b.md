## Analysis

The external report's bug class is: a value that is contractually bounded by a caller-supplied maximum (`maximumPrice` in the crowdfund) is used without ever validating it against that maximum, so it can "settle" above what the counter-party (contributor) authorized.

In `blackvul/kaia--002` the KIP-249 auction module (`kaiax/auction`) has an directly analogous field: `BidData.MaxGasPrice`, which is part of the EIP-712 struct the searcher signs (v3.0 bids) as the ceiling gas price they authorize for their auction transaction [1](#0-0) , and which is included in the v3.0 EIP-712 typehash the searcher cryptographically commits to [2](#0-1) .

However, tracing every place `MaxGasPrice` is used in the Go client:
- `validateBid()`, the single gatekeeping function for admitting a bid into the pool, checks sender/block-number/bid-amount/data-size/gas-limit/signatures — but never reads or checks `bid.MaxGasPrice` at all [3](#0-2) .
- `GetBidTxGenerator()`, which actually constructs and signs the `BidTx` that the CN broadcasts/includes in the bundle on the searcher's behalf, sets the fee fields from the **target transaction**, not from the searcher's signed `MaxGasPrice`: `types.TxValueKeyGasFeeCap: tx.GasFeeCap()` and `types.TxValueKeyGasTipCap: tx.GasTipCap()` [4](#0-3) .

So exactly like the Party report — where `settledPrice_` is derived from an unrelated quantity (`totalContributions`) without ever being clamped to the caller-declared `maximumPrice` — the Kaia auction client derives the `BidTx`'s actual gas price from an unrelated transaction (the arbitrary target tx submitted by anyone via `auction_submitBid` → `SubmitBid` [5](#0-4) ) without ever clamping it to the searcher's signed `MaxGasPrice` ceiling.

### Title
Auction BidTx gas price is never capped by the searcher-signed `MaxGasPrice` - (File: kaiax/auction/impl/getter.go)

### Summary
The KIP-249 v3.0 auction bid format lets a searcher sign a `MaxGasPrice` ceiling as part of the EIP-712 `AuctionTx` they authorize. The bid pool's validation logic and the `BidTx` generator never check the resulting transaction's gas price against this signed value.

### Finding Description
`BidData.MaxGasPrice` is decoded from RPC input [6](#0-5) , embedded in the EIP-712 struct hash that the searcher signs for v3.0 bids [7](#0-6) , and forwarded on-chain to the `AuctionEntryPoint` contract call [8](#0-7) . Despite being a security-relevant field the searcher explicitly authorizes, the CN-side bid admission logic `validateBid()` never inspects it, and `GetBidTxGenerator()` — the function that actually builds and signs the wrapper `BidTx` sent by the node's own key — populates `GasFeeCap`/`GasTipCap` from the unrelated target transaction's fee fields instead of clamping to `bid.MaxGasPrice` [4](#0-3) . Because the target transaction is attacker-controlled (any account can submit any target tx via `auction_submitBid`), an attacker can craft a target transaction with an arbitrarily high `GasFeeCap`/`GasTipCap`, causing the auto-generated `BidTx` for a completely unrelated, previously-signed bid to inherit that high fee cap — a value the searcher never authorized and that is never checked against the `MaxGasPrice` the searcher actually signed.

### Impact Explanation
This breaks the searcher's expected fee ceiling analogous to the `maximumPrice` guarantee in the referenced report: the searcher signs a bid expecting the entry-point call to never be charged more than `MaxGasPrice`, but the client-side transaction that is actually broadcast/paid for (using the node operator's `NodeKey`/`AuctionLenderMinBal` funds per the module README [9](#0-8) ) can carry a fee cap set by an unrelated, attacker-influenced target transaction rather than the bounded value the searcher committed to. This is reachable purely by an unprivileged transaction sender/auction bidder submitting a bid and target transaction pair via the public `auction_submitBid` RPC, matching the in-scope "gasless and auction modules" surface.

### Likelihood Explanation
Any user can call `auction_submitBid` with a `targetTxRaw` they fully control, including its `GasFeeCap`/`GasTipCap`. Since `GetBidTxGenerator` unconditionally copies these values into the `BidTx` for every accepted bid with no independent validation against `bid.MaxGasPrice`, the condition is trivially reachable on every block containing a bid.

### Recommendation
In `GetBidTxGenerator` (and/or `validateBid`), clamp/validate the derived `GasFeeCap`/`GasTipCap` against `bid.MaxGasPrice` when it is set (v3.0 bids), rejecting or capping the value before signing and broadcasting the `BidTx`, mirroring the fix pattern from the referenced report (`if maximumPrice_ != 0 && settledPrice_ > maximumPrice_ { settledPrice_ = maximumPrice_ }`).

### Proof of Concept
1. Searcher signs a v3.0 bid with `MaxGasPrice = X` for `targetTxHash = H`.
2. Attacker (or searcher's counterparty) crafts and broadcasts the target transaction `H` with an artificially high `GasFeeCap`/`GasTipCap` (`Y >> X`).
3. When block-building extracts the bundle via `ExtractTxBundles` → `GetBidTxGenerator(tx, bid)`, the generated `BidTx` sets `GasFeeCap = tx.GasFeeCap() = Y` and `GasTipCap = tx.GasTipCap() = Y`, ignoring the signed `MaxGasPrice = X` entirely [4](#0-3) .
4. No code path in `validateBid` or elsewhere rejects this mismatch [3](#0-2) .

Note: I was not able to locate the on-chain `AuctionEntryPoint` v3.0 Solidity source in the indexed codebase (only its Go binding `contracts/bindings/auctionv3/Kip249V3.go` was available) to confirm whether the contract independently re-validates `maxGasPrice` at execution time and reverts the mismatched call; if it does, the impact is limited to wasted/reverted `BidTx` gas rather than fund loss. Due to index size limits, some contract source files may not be available — starting a full Devin session would allow inspecting the actual `AuctionEntryPoint` v3.0 Solidity implementation to confirm whether on-chain enforcement mitigates this client-side gap.

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
