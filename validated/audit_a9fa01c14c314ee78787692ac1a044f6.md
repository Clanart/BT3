### Title
`SignableTransaction` signs spends of unverified prevouts — fabricated `ReceivedOutput` bytes produce an invalid transaction spending funds never received — (File: networks/bitcoin/src/wallet/send.rs)

### Summary
Analogous to "approving a DEX adapter to spend vault collateral that was never transferred, so the swap reverts with `ERC20InsufficientBalance`", `SignableTransaction::new` consumes `ReceivedOutput`s and treats their claimed `TxOut.value`/`OutPoint` as spendable balance without any on-chain verification. `ReceivedOutput::read` deserializes `offset`, `TxOut`, and `OutPoint` entirely from untrusted bytes (`networks/bitcoin/src/wallet/mod.rs:122-133`), so an attacker who can feed bytes into `ReceivedOutput::read` can cause the FROST multisig to produce a fully-signed transaction whose inputs do not exist or whose committed prevout values do not match the chain — the exact "insufficient balance" failure mode: the transaction references funds that were never actually transferred/received.

### Finding Description
`Scanner::scan_transaction` produces `ReceivedOutput`s by matching only `output.script_pubkey` against registered scripts (`networks/bitcoin/src/wallet/mod.rs:205-211`). The resulting `ReceivedOutput` is then trusted wholesale:

- `ReceivedOutput::read` accepts arbitrary `offset`, `TxOut` (including `value`), and `OutPoint` from the reader with zero cross-checks (`networks/bitcoin/src/wallet/mod.rs:122-133`).
- `SignableTransaction::new` sums `input.output.value` into `input_sat` for the fee/funds check and stores the claimed `TxOut`s as `prevouts` (`networks/bitcoin/src/wallet/send.rs:175-185`, `253`).
- `multisig()` verifies only that `prevouts[i].script_pubkey == p2tr_script_buf(group_key + offset)` (`networks/bitcoin/src/wallet/send.rs:276-281`). It cannot verify the `OutPoint` exists or that the claimed `value` matches the real UTXO — the same class of flaw as `approve(ctx.dexAdapter, assetInputNative)` approving spend of tokens never deposited.
- `TransactionSignMachine::sign` commits to `Prevouts::All(&self.tx.prevouts)` (`networks/bitcoin/src/wallet/send.rs:373-390`), i.e., the attacker-chosen values.

Because BIP-341 key-path sighashes commit to every prevout's value and outpoint, if either is wrong relative to the real UTXO set, the produced Schnorr signatures are invalid on-chain and the transaction can never be confirmed — directly mirroring `ERC20InsufficientBalance` reverting the swap. All other (legitimate) inputs batched into the same `SignableTransaction` are likewise unspendable, and the FROST preprocess/signing session is consumed.

### Impact Explanation
An unprivileged party able to supply serialized `ReceivedOutput`s (the rules' explicit `ReceivedOutput::read` sink — e.g., a coordinator/peer distributing scanned outputs to signers) reports funds as received that are not spendable. Concretely:

- Inflate `output.value` or set a bogus `outpoint` → the signing round completes, yielding a transaction that is invalid at consensus (bad prevout commitment / nonexistent input). The spend is permanently DoS'd for that session and any honest outputs bundled into the same transaction are blocked with it.
- Point `outpoint` at a real output paying the same `script_pubkey` but with less value → fee and change are computed from the inflated `input_sat`, and the signed tx is still invalid.

This is "funds reported received that are not spendable" plus signature-session DoS — Medium.

### Likelihood Explanation
Triggering requires an attacker in a position to inject or corrupt `ReceivedOutput` bytes consumed by a signer (malicious coordinator, compromised output distribution channel, or an output crafted to alias a scanned `script_pubkey`). The check in `multisig()` does bind the script to `group_key + offset`, so the attacker cannot redirect the spend to arbitrary keys; but nothing binds `value`/`outpoint`, making fabrication cheap whenever the byte channel is untrusted. Medium likelihood wherever `ReceivedOutput::read`/`write` is used over an untrusted transport; lower if outputs only ever flow straight from a trusted local `Scanner`.

### Recommendation
Bind the `ReceivedOutput` to reality before signing, mirroring "transfer the vault asset to the engine before the swap":

1. In `multisig()` or a pre-sign validation step, require each `ReceivedOutput` be accompanied by SPV-style evidence, or have signers re-derive `value`/`outpoint` from their own `Scanner` view rather than trusting serialized fields.
2. At minimum, treat `ReceivedOutput::read` output as a claim and verify `output.script_pubkey == p2tr_script_buf(group_key + offset)` *and* the outpoint/value against the local UTXO view before `SignableTransaction::new` is invoked; reject inputs that fail verification instead of signing them.
3. Consider including a hash/TXID-of-record inside `ReceivedOutput` construction so that a mismatched `TxOut` cannot silently disagree with the scanned chain state.

### Proof of Concept
```rust
use bitcoin::{
  hashes::Hash, transaction::Version, OutPoint, TxOut, Txid, Amount, ScriptBuf,
};
use frost::curve::Secp256k1;
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction, tweak_keys, p2tr_script_buf};
use k256::{Scalar, ProjectivePoint};

// Simulate an attacker feeding forged bytes into ReceivedOutput::read:
// outpoint points to a real (or fabricated) UTXO, but `value` is inflated
// vs. the actual on-chain amount — or the outpoint does not exist at all.
fn forge_received_output(real_script: ScriptBuf) -> ReceivedOutput {
  let mut bytes = Vec::new();
  bytes.extend(Scalar::ZERO.to_bytes()); // offset = 0 (external address)

  // TxOut: script_pubkey must match key+offset (checked by `multisig`),
  // but `value` is fully attacker-controlled.
  let fake_txout = TxOut { value: Amount::from_sat(100_000_000), script_pubkey: real_script };
  bytes.extend(bitcoin::consensus::serialize(&fake_txout));

  // OutPoint: arbitrary — nonexistent txid, or a spent/different-valued UTXO.
  let fake_outpoint =
    OutPoint { txid: Txid::from_raw_hash(bitcoin::hashes::sha256d::Hash::all_zeros()), vout: 0 };
  bytes.extend(bitcoin::consensus::serialize(&fake_outpoint));

  ReceivedOutput::read(&mut bytes.as_slice()).unwrap()
}

// In SignableTransaction::new, input_sat = 100_000_000 sats is treated as real
// (send.rs:175), fee/change are computed against it, and prevouts commits the
// forged value (send.rs:253, 375). `multisig()` passes because the
// script_pubkey check (send.rs:277) does not cover value/outpoint.
// The resulting FROST-signed transaction commits (Prevouts::All) to a prevout
// value/outpoint that does not match the UTXO set → every input's Taproot
// signature is invalid → the transaction can never be confirmed:
// the on-chain equivalent of ERC20InsufficientBalance.
```
