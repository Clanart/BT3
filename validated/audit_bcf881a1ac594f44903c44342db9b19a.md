### Title
Attacker can fabricate a `VerifyBlame` accusation to get an honest DKG participant blamed/slashed by supplying an `EncryptedMessage` with an invalid proof-of-possession - (File: crypto/dkg/pedpop/src/encryption.rs, crypto/dkg/pedpop/src/lib.rs, processor/src/key_gen.rs)

### Summary
The Movary CVE is a missing-authorization flaw: an endpoint meant for benign self-editing writes the sensitive `isAdmin` field without checking the caller is an admin. The Serai analog is a blame-evaluation path meant to adjudicate faults between authenticated DKG participants that instead attributes fault based on an attacker-chosen field (`sender`/`accused`) and attacker-supplied bytes, with no check that the accused party actually authored the message. An accuser can fabricate an `EncryptedMessage` whose Schnorr proof-of-possession fails; `blame_internal` then deterministically returns the `sender` (i.e., the innocent accused) as the faulty party.

### Finding Description
`BlameMachine::blame` / `AdditionalBlameMachine::blame` take `sender`, `recipient`, a serialized `EncryptedMessage<C, SecretShare<C::F>>`, and an optional `EncryptionKeyProof`. Inside `blame_internal`, the first step is `decrypt_with_proof`, which verifies the embedded PoP signature via `msg.pop.verify(msg.key, pop_challenge(context, msg.pop.R, msg.key, from, msg))`. On `DecryptionError::InvalidSignature`, `blame_internal` returns `sender` — the accused — as faulty. [1](#0-0) 

The problem: PoP verification *failing* does not authenticate anything about the message's origin. `pop_challenge` binds the claimed `sender` index into the transcript, but a failing verification is indistinguishable between "the accused sent a malformed message" and "the accuser fabricated arbitrary bytes and labeled them with the accused's index". The API docs acknowledge this — "This message must have been authenticated as actually having come from the sender in question" — but the in-scope consumer does not enforce it. [2](#0-1) 

In `processor/src/key_gen.rs`, the `CoordinatorMessage::VerifyBlame` handler reads `share` bytes supplied by the accuser, deserializes them as `EncryptedMessage` for both the Ristretto (substrate) and network curves, then calls `AdditionalBlameMachine::new(...).blame(accuser, accused, substrate_share, substrate_blame)`. No check confirms the share bytes were the ones `accused` actually transmitted; `accused` is a free field chosen by the accuser. If deserialization succeeds and the PoP is invalid, blame falls on `accused`. [3](#0-2) 

Even constructing the fabricated message is trivial: `EncryptedMessage::read` accepts any bytes parseable as `key`, `pop` (`SchnorrSignature`), and `msg` — none of which need to correspond to anything the accused produced. [4](#0-3) 

### Impact Explanation
Blame outcomes in this system are fatal: the code comments note "this being called means *someone* is getting fatally slashed". [5](#0-4)  A malicious participant (or any party able to emit `CoordinatorMessage::VerifyBlame`) can cause an honest validator to be adjudicated faulty and slashed by forging the share bytes. This is a forged adjudication with economic/security consequences, not a mere DoS: it converts the blame mechanism — intended to punish cheaters — into a weapon against honest nodes, directly paralleling the report's "unprivileged user flips a sensitive field" class where the sensitive field is the fault attribution.

### Likelihood Explanation
Reachable by any party able to submit a `VerifyBlame` message (an accuser role, i.e., a participant in the DKG whose own share decryption failed — or who merely claims it did). Requirements: knowledge of the session `id` and the ability to craft a syntactically valid `EncryptedMessage` with an invalid PoP — trivially done by generating a random Schnorr signature for the wrong key or mutating one byte of `pop.s`. No collusion, no threshold control, and no honest-party misbehavior is needed. Success is deterministic: every honest node running `blame_internal` on the fabricated input returns `sender` = accused.

### Recommendation
Make the invalid-PoP branch unforgeable as attribution evidence. Concretely: before `blame()` returns `sender` for `DecryptionError::InvalidSignature`, require proof the message originated from `sender` — e.g., verify the PoP verifies *validly* under a signature or MAC from `sender` over the full ciphertext (not just the per-message key), or have the coordinator store the exact share bytes each participant broadcast (keyed by `sender`) and have `VerifyBlame` compare the accuser-supplied share against the recorded bytes before running blame. Absent such authentication, `InvalidSignature` should abort the session without attributing fault to `sender`, since the message's provenance is unproven. The API contract ("must have been authenticated") should also be enforced in the processor handler, not just documented.

### Proof of Concept
```rust
// Attacker's perspective: they are `accuser` = Participant::A, victim is `accused` = Participant::V.
// During a DKG session with known `context` and `params`:

// 1. Fabricate an EncryptedMessage that parses but whose PoP fails.
//    EncryptedMessage::read just needs a valid point (key), a SchnorrSignature, and a SecretShare.
let mut fabricated = Vec::new();
fabricated.extend(C::generator().to_bytes());            // arbitrary msg.key
SchnorrSignature::<C> {
    R: C::generator(),                                    // arbitrary R
    s: C::F::ONE,                                         // garbage s -> pop.verify fails
}
.write(&mut fabricated).unwrap();
SecretShare(C::F::ONE.to_repr()).write(&mut fabricated).unwrap(); // arbitrary msg

// 2. Submit CoordinatorMessage::VerifyBlame { id, accuser: A, accused: V, share: fabricated, blame: None }

// 3. Every honest node runs:
//    AdditionalBlameMachine::new(ctx, n, commitment_msgs)
//      .blame(accuser = A, accused = V, share, None)
//    -> blame_internal: decrypt_with_proof -> pop.verify fails (s is garbage)
//    -> DecryptionError::InvalidSignature -> returns `sender` = V
// Honest participant V is returned as the faulty party and slashed.
```

The fabricator doesn't need V's encryption key, V's commitments, or any secret — `blame_internal` short-circuits to `return sender` on the very first check ( [6](#0-5) ), and the processor passes the accuser-controlled `accused` and `share` directly into it ( [7](#0-6) ).
