### Title
Unvalidated hunk-count mismatch causes silent code loss in Copilot conflict resolution reassembly - (File: `app/src/lib/copilot-conflict-resolution.ts`)

### Summary
The original Polkadot fix added a bounds check so a caller-provided index that didn't match the array's real size returned an explicit error instead of silently corrupting/crashing. The Desktop analog is the opposite failure mode of the *same broken invariant*: `reassembleResolvedFile` walks the original conflicted file counting conflict-marker blocks and consumes one entry from `hunkResolutions` per block, but never verifies that `hunkResolutions.length` equals the number of conflict blocks actually present in the file. When the model-returned hunk array is shorter than the number of real conflict blocks, the mismatch is silently swallowed rather than surfaced as an error.

### Finding Description
`reassembleResolvedFile` is the bridge that splices the AI model's per-hunk JSON output back into the original on-disk file content that still contains `<<<<<<<`/`=======`/`>>>>>>>` markers: [1](#0-0) 

For every conflict block found (`i` walks the marker), the code does `if (hunkIndex < hunkResolutions.length) { … splice resolved[hunkIndex] … }` and otherwise pushes nothing at all for that block — the entire conflict block (both `oursContent` and `theirsContent`) is dropped from the reassembled file with no warning, no error, and no fallback to either side's original content.

Nothing upstream guarantees `raw.hunks.length` matches the real hunk count for that file. `parseCopilotConflictResolution` only validates that `hunks` is a non-empty array of objects with string `resolvedContent` that doesn't still contain conflict markers — it never cross-checks the count against `IFileConflictContext.hunks.length` for the corresponding file: [2](#0-1) 

`reassembleResolutions` then does the splice, throwing only when `rawContent` is entirely missing — not when the hunk *count* is wrong: [3](#0-2) 

The final write path does correctly confine the destination path via `resolveWithin(repository.path, resolution.path)`, which blocks the separate path-traversal concern: [4](#0-3) 

but that guard says nothing about the *content* being written — `resolution.resolvedContent` is written verbatim once the user clicks "Continue Merge": [5](#0-4) 

### Impact Explanation
Since the conflict content that reaches the LLM prompt (commit messages, PR titles/bodies, and the actual conflicting code) originates from a remote repository/PR that an attacker can fully control, a crafted repository can be constructed so that, on encountering conflicts, the model's structured JSON response omits hunks for a targeted file (e.g., via prompt-injection text embedded in a commit message, PR description, or code comment instructing the assistant to "summarize" or skip a hunk). Because the count mismatch is never validated, Desktop will silently delete an entire conflict region — including code the user's own branch added — from the file it writes to disk and `git add`s before the merge/rebase/cherry-pick commit is finalized. The user sees a "resolved" file and a reasoning blurb claiming the conflict was handled, then commits and potentially pushes silently corrupted code. This matches the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
This requires the attacker to control repository content that ends up conflicting with the victim's branch and to reliably manipulate the LLM's structured output count — a probabilistic, not fully deterministic, primitive (unlike the original Rust bug, which was a deterministic index check). No existing code path validates hunk-count parity, so once the model under-returns hunks, nothing in the pipeline detects or blocks it before the write; the failure is silent by design (`resultLines.push(...)` for extras just doesn't happen). Likelihood is therefore moderate: it depends on LLM behavior under adversarial prompting rather than a hard invariant violation, but there is zero defense-in-depth (no hunk-count assertion, no per-file diff/size sanity check before write).

### Recommendation
In `reassembleResolutions` (or `reassembleResolvedFile`), count the conflict-marker blocks in `ctx.rawContent` up front and assert `raw.hunks.length` equals that count before splicing; if it doesn't match, throw `CopilotValidationError` (mirroring how `Error::ChunkIndexOutOfBounds` was surfaced instead of silently misbehaving) so the file falls back to the "skipped, resolve manually" path rather than being silently overwritten with missing content.

### Proof of Concept
1. Attacker crafts a branch/PR with a file containing two conflict-marker blocks and injects a prompt-injection instruction (in a commit message or code comment inside the conflicting hunk) telling the assistant to "only return one resolution object" or similar.
2. Victim runs "Resolve with Copilot" on the merge; the model returns `hunks: [{ resolvedContent: "..." }]` (length 1) for a file that actually has 2 conflict blocks — `parseCopilotConflictResolution` accepts this because it only checks `hunks.length === 0`, not the real count.
3. `reassembleResolvedFile` (`app/src/lib/copilot-conflict-resolution.ts:585`) drops the second conflict block entirely (no `ours`, no `theirs`, no content).
4. `_applyCopilotConflictResolutions` writes the truncated file via `writeFile(absolutePath, resolution.resolvedContent, 'utf8')` and stages it with `git add`.
5. The user commits/pushes a file silently missing an entire code section, with no error or warning shown.

export function reassembleResolutions(
  rawResolutions: ReadonlyArray<IRawFileResolution>,
  fileContexts: ReadonlyArray<IFileConflictContext>
): ReadonlyArray<IFileResolution> {
  const contextByPath = new Map(fileContexts.map(f => [f.path, f]))

  return rawResolutions.map(raw => {
    // Delete-vs-modify resolutions carry an action, not hunk content.
    // Pass through without reassembly — the resolution is applied as a
    // ManualConflictResolution, not a file write.
    if (raw.action !== undefined) {
      return {
        path: raw.path,
        resolvedContent: '',
        reasoning: raw.reasoning,
        deleteConflictAction: raw.action,
      }
    }

    const ctx = contextByPath.get(raw.path)
    if (ctx?.rawContent === undefined) {
      throw new CopilotValidationError(
        `Cannot reassemble resolution for "${raw.path}": original file content is unavailable`
      )
    }

    const resolvedContent = reassembleResolvedFile(ctx.rawContent, raw.hunks)
    return {
      path: raw.path,
      resolvedContent,
      reasoning: raw.reasoning,
    }
  })
}
