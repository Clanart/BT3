### Title
Anyone can force a PedPoP DKG abort by falsely blaming an honest participant, without proving they received an invalid share - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`BlameMachine::blame` accepts a `(sender, recipient, msg, proof)` tuple from any caller and unconditionally marks `recipient` as faulty when `proof` is `None`. There is no check that the accusing party actually holds the decryption key for the message or is the `recipient` — mirroring the Mattermost bug class of "acting on resources belonging to another party without authorization."

### Finding Description
`Decryption::decrypt_with_proof` returns `Err(DecryptionError::InvalidProof)` whenever `proof` is `None`, provided the message's per-message PoP is valid (`msg.pop.verify(...)` at `crypto/dkg/pedpop/src/encryption.rs:374-396`). In `blame_internal` (`crypto/dkg/pedpop/src/lib.rs:582-588`), `InvalidProof` maps to returning `recipient` as the faulty party:

```rust
// Decryption will fail if the provided ECDH key wasn't correct for the given message
Err(DecryptionError::InvalidProof) => return recipient,
```

The `recipient` parameter is attacker-controlled and unauthenticated. `msg` only needs a valid `pop` Schnorr signature bound to `sender` (via `pop_challenge`, `encryption.rs:302-324`) — which every honestly generated `EncryptedMessage` has, and which `EncryptedMessage::read` makes a public-input type. The `EncryptionKeyProof` (the DLEq over `[G, msg.key]` and `[enc_keys[decryptor], proof.key]`) is the only evidence that ties a real accusation to the actual recipient's decryption key. When it is absent, the protocol should reject the blame attempt; instead it convicts the recipient.

### Impact Explanation
Any party that obtains a valid `EncryptedMessage` from `sender` to `recipient` (e.g., relayed/copied protocol bytes, or a sender colluding-free replay) can call `blame(sender, victim_recipient, msg, None)` and cause the machine to identify `victim_recipient` as faulty. The docstring states `blame` "prevent[s] completion of the machine, forcing an abort of the protocol," so this both aborts the DKG and attributes the fault to an innocent participant — an availability (protocol abort) plus false-accusation primitive, reachable entirely from public message bytes with no secret material. This is the direct analog of "a team member can soft delete other teams": an unprivileged actor triggers a destructive action scoped to a party they are not.

### Likelihood Explanation
The call requires only a syntactically valid `EncryptedMessage<C, SecretShare<C::F>>` (readable via `EncryptedMessage::read`), a `sender`, and a `recipient` — all public inputs. No valid ECDH proof or key material is needed. It succeeds whenever invoked before `complete()` is called, i.e., during the open blame window the library explicitly models. The only mitigating factor is that blame adjudication is run by each participant locally, so exploitation depends on integrators feeding untrusted blame statements into `BlameMachine::blame` — which is exactly its documented purpose ("This message must have been authenticated as actually having come from the sender in question" — note it says sender, not the accuser/recipient).

### Recommendation
When `proof` is `None`, treat the blame statement itself as malformed rather than blaming `recipient` — e.g., return an error/`Option<Participant>` or blame the submitter, since a legitimate accusation must be accompanied by the recipient's `EncryptionKeyProof` proving they could not decrypt. Alternatively, only allow `blame` for `recipient == params.i()`'s own accusations unless a valid proof is attached, so a third party cannot cause an honest party to be marked faulty.

### Proof of Concept
1. Run a PedPoP DKG (`t=2, n=3`); collect a valid serialized `EncryptedMessage` that honest `sender = 2` generated for `recipient = 1` (passed through `EncryptedMessage::read`).
2. On any participant's `BlameMachine` (obtained from `KeyMachine::calculate_share`), call `blame(sender, recipient, msg, None)`.
3. `decrypt_with_proof` verifies the valid `pop`, sees `proof == None`, returns `InvalidProof`; `blame_internal` returns `recipient` (`crypto/dkg/pedpop/src/lib.rs:587`).
4. Result: participant `1` is declared faulty and the DKG aborts, despite participant `1` never having made any accusation and the message being perfectly valid.
