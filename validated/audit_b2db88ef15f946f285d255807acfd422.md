I found a concrete match: `getSigner` in `kaiax/auction/bid.go` performs an out-of-bounds/nil-unsafe access on attacker-supplied signature bytes before validating their length, in a function reachable from a public auction bid submission path.

### Title
Out-of-bounds index panic (denial of service) on malformed auction bid signature - (File: kaiax/auction/bid.go)

### Summary
`getSigner`, used by `Bid.ValidateSearcherSig` and `Bid.ValidateAuctioneerSig` to recover a signer address from a bidder-supplied signature, indexes into the raw `sig`/`copiedSig` byte slice (`copiedSig[crypto.RecoveryIDOffset]`, `copiedSig[0:32]`, `copiedSig[32:64]`) before checking that the slice has the expected length. A gasless-auction bidder who submits a `BidData.SearcherSig` or `AuctioneerSig` shorter than `crypto.RecoveryIDOffset+1` bytes (e.g., empty or a few bytes) causes an out-of-bounds slice access, panicking the goroutine that processes the bid. This is analogous to the reported CWE-395 pattern where malformed/invalid input reaches unguarded low-level decode logic and triggers a crash instead of a clean validation error.

### Finding Description
`getSigner` is called with attacker-controlled bytes: [1](#0-0) 

The `Bid` struct carries `SearcherSig` and `AuctioneerSig` as raw `[]byte` fields decoded straight from RLP with no length constraint: [2](#0-1) 

`ValidateSearcherSig`/`ValidateAuctioneerSig` invoke `getSigner(b.SearcherSig, digest)` / `getSigner(b.AuctioneerSig, digest)` directly on the decoded bytes without a prior length check: [3](#0-2) 

Inside `getSigner`, the code immediately indexes `copiedSig[crypto.RecoveryIDOffset]` (offset 64) and slices `copiedSig[0:32]` / `copiedSig[32:64]` without first verifying `len(sig) == crypto.SignatureLength` (65 bytes), unlike the analogous transaction-signature paths in `blockchain/types/transaction_signing.go`, which explicitly check `len(sig) != crypto.SignatureLength` and `panic`/return an error in a controlled manner before indexing (`decodeSignature`, `modernSigner.SignatureValues`): [4](#0-3) [5](#0-4) 

In `getSigner`, no such guard exists before the indexing operations occur, so a short or empty signature causes an unrecovered Go runtime panic (`index out of range`) rather than a graceful error return.

### Impact Explanation
Bids are submitted by unprivileged searchers/bidders through the gasless auction module and are decoded via `Bid.DecodeRLP` with attacker-controlled `SearcherSig`/`AuctioneerSig` content and length. Because `getSigner` performs unchecked slice indexing on this data, any external bidder can trigger a panic during signature verification of a submitted bid. If this panic is not recovered somewhere higher up the call stack (auction bid ingestion / RPC handler), it can crash the node process or, at minimum, abort auction/bid processing for that request path, denying service to the auction/gasless module — a concrete availability impact reachable from a single externally submitted bid, consistent in class with a NULL/invalid-pointer dereference style crash from insufficiently validated externally supplied data (CWE-395/CWE-476 family).

### Likelihood Explanation
High likelihood: the bug is trivially triggerable by any external, unprivileged party who can submit an auction bid (e.g., via the bid submission RPC/API) with a `SearcherSig` or `AuctioneerSig` shorter than 65 bytes (including a zero-length byte slice). No special privileges, timing, or race conditions are required — a single malformed bid submission reaches the vulnerable `getSigner` code path via `ValidateSearcherSig`/`ValidateAuctioneerSig`.

### Recommendation
Add an explicit length check (`len(sig) != crypto.SignatureLength`) at the start of `getSigner` in `kaiax/auction/bid.go`, returning `ErrInvalidSignature` (or a similar error) before any indexing/slicing, mirroring the guard used in `blockchain/types/transaction_signing.go`'s `decodeSignature`/`SignatureValues`. Additionally, consider validating `SearcherSig`/`AuctioneerSig` length immediately after RLP decoding in `Bid.DecodeRLP` to reject malformed bids early.

### Proof of Concept
1. Craft a `BidData` where `SearcherSig` is set to an empty byte slice (or fewer than 65 bytes), with otherwise arbitrary valid fields, and encode it via RLP to produce a `Bid`.
2. Submit this bid through the gasless auction bid ingestion path so that `Bid.ValidateSearcherSig` is invoked (this is the standard verification step for any incoming bid).
3. `ValidateSearcherSig` calls `getSigner(b.SearcherSig, digest)`.
4. Inside `getSigner`, `copiedSig[crypto.RecoveryIDOffset]` (or `copiedSig[0:32]`/`copiedSig[32:64]`) is accessed on the too-short slice, causing an index-out-of-range panic.
5. Observe the panic/crash (or forced goroutine termination) in the node handling the bid, unless caught by an outer `recover()` that is not present in this call chain based on the code reviewed.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

	pub, err := crypto.SigToPub(digest, copiedSig)
	if err != nil {
		return common.Address{}, err
	}
	return crypto.PubkeyToAddress(*pub), nil

func decodeSignature(sig []byte) (r, s, v *big.Int) {
	if len(sig) != crypto.SignatureLength {
		panic(fmt.Sprintf("wrong size for signature: got %d, want %d", len(sig), crypto.SignatureLength))
	}
	r = new(big.Int).SetBytes(sig[:32])
	s = new(big.Int).SetBytes(sig[32:64])
	v = new(big.Int).SetBytes([]byte{sig[64] + 27})
