### Title
`depositLP` mints receiptToken based on requested amount instead of actual LP received, enabling unbacked receipt tokens for fee-on-transfer/rebasing LP tokens - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking.depositLP` pulls `_lpAmount` via `safeTransferFrom` but never measures the actual balance received by the contract before staking and minting, unlike the sibling `deposit()` function which explicitly computes `lpReceived = balanceOf(after) - beforeBalance`. If `poolInfo.lpAddress` is a fee-on-transfer or rebasing token, the contract mints the full pre-fee `_lpAmount` of `receiptToken` while backing less LP, creating unbacked receipt tokens.

### Finding Description
In `depositLP` [1](#0-0) , the flow is:
1. `IERC20(poolInfo.lpAddress).safeTransferFrom(_for, address(this), _lpAmount)` — for a fee-on-transfer token, the actual amount received by `WombatStaking` is `_lpAmount - fee`.
2. `_toMasterWomAndSendReward(_lpAddress, _lpAmount, true)` stakes `_lpAmount` (the pre-fee amount) to `masterWombat`, which will revert or under-collateralize depending on `masterWombat`'s own accounting for that token.
3. `IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount)` mints the full pre-fee `_lpAmount`, not the actual received amount.

This directly contrasts with the `deposit()` function [2](#0-1)  which correctly measures `lpReceived` via a balance-diff pattern before minting. `depositLP` lacks this safeguard entirely.

At the `WombatPoolHelper` layer [3](#0-2) , the helper measures `afterDeposit - beforeDeposit` on the `stakingToken` (receipt token) balance — but since the receipt token minted amount is itself decoupled from actual LP received in `WombatStaking.depositLP`, this downstream check does not catch the discrepancy; it only correctly forwards whatever (unbacked) amount was minted.

The `_onlyActivePoolHelper` modifier only restricts `msg.sender` to the registered helper and checks pool activity [4](#0-3)  — it does not protect against the fee-on-transfer accounting gap.

### Impact Explanation
If a registered `poolInfo.lpAddress` behaves as fee-on-transfer or rebasing (down), each `depositLP` call mints more `receiptToken` than actual LP backing added to `WombatStaking`/`masterWombat`. Repeated deposits compound the shortfall between `receiptToken.totalSupply()` and real LP backing, ultimately causing protocol insolvency when receipt holders attempt to withdraw en masse (later withdrawers cannot be made whole) — matching the "protocol insolvency" / "permanent freezing/theft of funds" Immunefi impact class.

### Likelihood Explanation
Exploitability requires that the registered `poolInfo.lpAddress` for a given pool is fee-on-transfer or negatively rebasing. Standard Wombat LP tokens (`IAsset`) are typically not fee-on-transfer, so this is conditional on an atypical/registered LP token. Given that only the owner can call `registerPool`, the attacker cannot introduce the malicious token themselves, but they can freely exploit any existing eligible pool with unlimited capital (deposit/withdraw is fully public and repeatable, no special privileges needed) once such a pool exists. This is a genuine code defect (missing balance-diff check) independent of any specific pool's current configuration.

### Recommendation
Mirror the pattern used in `deposit()`: measure `IERC20(poolInfo.lpAddress).balanceOf(address(this))` before and after `safeTransferFrom`, stake and mint based on the actual received delta rather than the caller-supplied `_lpAmount`.

### Proof of Concept
Foundry test plan:
1. Deploy a mock fee-on-transfer ERC20 (e.g., 5% fee) as `lpAddress`.
2. `registerPool` (as owner) with this token as `lpAddress`/`depositToken` in `WombatStaking`.
3. Fund attacker with the fee-on-transfer LP token; approve `WombatStaking`.
4. Call `WombatPoolHelper.depositLP(1000)` (or directly `WombatStaking.depositLP(lpToken, 1000, attacker)` from the helper).
5. Assert: `IERC20(lpAddress).balanceOf(WombatStaking) < 1000` (e.g., only 950 received) while `IMintableERC20(receiptToken).totalSupply()` increased by full `1000`.
6. Assert backing invariant broken: `receiptToken.totalSupply() delta (1000) > actual LP balance delta (950)`.
