### Title
Missing Authorization in `CW721ERC721Pointer.transferFrom` allows any address to transfer NFTs it does not own or control - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.transferFrom` only validates that the `from` argument matches the token's on-chain owner; it never checks that `msg.sender` (the transaction caller) is the token owner, an approved spender, or an approved-for-all operator before issuing the underlying CW721 `transfer_nft` message.

### Finding Description
`transferFrom` is: [3](#0-2) 

The only guard is `require(from == ownerOf(tokenId), ...)`. There is no `require(msg.sender == from || isApprovedForAll(from, msg.sender) || getApproved(tokenId) == msg.sender)` as OpenZeppelin's standard `ERC721._isAuthorized`/`_update` normally enforces. Any caller can therefore supply the real owner as `from` and an attacker-controlled address as `to`.

The call is dispatched to CosmWasm via `_execute`, which `delegatecall`s the wasmd precompile: [4](#0-3) 

Because this is a `delegatecall`, EVM semantics preserve `msg.sender` from the original external call. Inside the wasmd precompile, the wasm message's `Sender` is derived directly from that preserved `caller`: [5](#0-4) 

The only authorization check performed for delegatecall-invoked `execute` is that the *calling contract* (the pointer) is a registered pointer for the target CW721 contract — it does not check that the *caller* (attacker EOA) is authorized to move `from`'s token: [2](#0-1) 

So the resulting `MsgExecuteContract{Sender: <owner's Sei address>, ...}` executed against the CW721 contract is `transfer_nft` signed/attributed as coming from the real owner's Sei address, satisfying the underlying CosmWasm contract's own owner check — even though the actual caller had no approval at all. This exactly mirrors the Backend.AI bug class: a resource-access/transfer capability ("session") that is supposed to require the resource owner's authorization is instead granted to any caller who merely supplies the correct owner identifier, because the intermediate layer conflates "who owns/controls X" with "who is allowed to invoke the transfer of X."

### Impact Explanation
Any unprivileged EVM caller can force-transfer any CW721-backed NFT away from its rightful owner to an address of the attacker's choosing, without any approval, by calling `transferFrom(ownerAddr, attackerAddr, tokenId)` on the pointer contract. This is unauthorized transfer via a CW<->EVM pointer, resulting in concrete fund/asset loss for NFT holders whose CW721 collections are exposed through this pointer contract — matching the CVSS High severity and the CWE-862 (Missing Authorization) class of the reported advisory.

### Likelihood Explanation
High. The bug is directly reachable by any public RPC client / contract deployer with no privileged access: they only need to know the `tokenId` and the current owner's address (both are trivially queryable via `ownerOf`). No signature, approval, or race condition is needed — a single `transferFrom` call from any account fully exploits it.

### Recommendation
Add the standard ERC721 authorization check in `transferFrom` (and any other pointer function that moves value/ownership) before calling `_execute`, e.g.:
```solidity
require(
    msg.sender == from ||
    isApprovedForAll(from, msg.sender) ||
    getApproved(tokenId) == msg.sender,
    "ERC721: caller is not token owner or approved"
);
```
Additionally, review other pointer contracts (`CW1155ERC1155Pointer`, `CW20ERC20Pointer`) for the same missing-authorization pattern, since the wasmd precompile's delegatecall path only authenticates the *pointer contract identity*, never the underlying EVM caller's rights over the specific asset — that responsibility is left entirely to each pointer's Solidity logic.

### Proof of Concept
1. Owner O holds CW721 token `id=1` via `CW721ERC721Pointer` (verifiable via `ownerOf(1) == O`).
2. Attacker A (no approval from O) calls `pointer.transferFrom(O, A, 1)` directly.
3. `require(from == ownerOf(tokenId))` passes because `from == O` is correct.
4. `_execute` delegatecalls the wasmd precompile with `execute(Cw721Address, {"transfer_nft":{"recipient":"<A's Sei addr>","token_id":"1"}}, "[]")`.
5. Inside the precompile, `caller` (preserved via delegatecall) resolves to O's associated Sei address via `GetSeiAddress`, so `MsgExecuteContract.Sender = O`.
6. The underlying CW721 contract sees a valid `transfer_nft` from its recorded owner O and executes it, transferring token `id=1` to A.
7. `ownerOf(1)` now returns A — token stolen with zero approval from O.

        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));

        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
