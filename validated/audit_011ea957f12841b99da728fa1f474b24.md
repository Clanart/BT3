## Analog Identified

The report's "broken invariant" is: a security-relevant identity value is populated from an untrusted/self-referential source instead of a value that has actually been validated, and no code path later corrects it — silently defeating the intended protection. The closest concrete GitHub Desktop analog is in the git-credential trampoline: Desktop decides whether a remote host is a trusted "GitHub"/"GitHub Enterprise" endpoint (and therefore whether to route the user into the branded GitHub sign-in flow) based on an HTTP `WWW-Authenticate` realm string that is entirely controlled by the remote server/proxy Desktop is talking to.

### Title
Desktop trusts an attacker-controlled `WWW-Authenticate` realm to classify a host as "GitHub", triggering the GitHub sign-in flow against an arbitrary attacker endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper via the trampoline. `getEndpointKind` classifies the target host by inspecting `wwwauth[]` fields that Git forwards from the server's HTTP response headers, and if the value contains `realm="GitHub"` it unconditionally returns `'enterprise'` without any further verification. [1](#0-0) 

This is different from the fallback path a few lines below, which actually makes a network probe (`isGitHubHost`) and only trusts the target once it observes the `x-github-request-id` response header from a real GitHub instance: [2](#0-1) 

The `wwwauth[]` shortcut bypasses that verification entirely.

### Finding Description
`getCredential` first tries to match a stored account by origin, and if that fails, it calls `getEndpointKind` to decide if the remote "appears as if" it's a GitHub host: [3](#0-2) 

`getEndpointKind`'s `wwwauth[]` heuristic is a comment-documented shortcut ("without having to resort to making a request ourselves") that trusts a header value supplied by whatever server answered the HTTP request for the remote — this is exactly the header any HTTP server (a malicious/compromised git remote, a malicious HTTP(S) proxy, or a corporate-network MITM box) can set at will: [4](#0-3) 

Once `endpointKind !== 'generic'` and no existing account matches the derived `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which, for any non-`github.com` hostname, drives the enterprise sign-in flow and sets the sign-in endpoint to the attacker-controlled `origin`: [5](#0-4) 

The `endpoint`/`origin` used here comes straight from `getCredentialUrl(cred)`, which is built from the `protocol`/`host`/`path` fields Git passes to the credential helper for whatever remote is currently being contacted: [6](#0-5) 

So the "address" that gets treated as a trustworthy "GitHub Enterprise" endpoint is not validated against any allow-list, TLS identity, or genuine GitHub response fingerprint — it is simply whatever host the user's git operation happened to be talking to when that host chose to send back a `WWW-Authenticate: ... realm="GitHub"` header. This mirrors the disclosed bug's root cause: a security-relevant identity/destination value being populated from an unverified/attacker-influenced source rather than a validated one.

### Impact Explanation
An attacker who controls a git remote a victim clones/fetches from (e.g., a malicious repo hosting a submodule pointing to an attacker HTTPS server, or a network-position attacker/proxy that can answer Git's HTTP requests) can make that server respond to Git's authentication probe with `WWW-Authenticate: Basic realm="GitHub"`. Desktop will then classify the attacker's arbitrary host as `'enterprise'` and, having no matching account, pop the trusted-looking "Sign in to GitHub Enterprise"/browser OAuth UI scoped to the attacker's `origin`. A user who completes that flow (entering a PAT, or completing the OAuth browser hand-off) sends their credentials/token to the attacker's endpoint rather than a real GitHub instance — i.e., credential/token exfiltration and unauthorized account binding, achieved purely by controlling a remote's response, satisfying the "attacker controls...a git remote/proxy response" criterion.

### Likelihood Explanation
The `wwwauth[]` check requires no user interaction beyond a normal `fetch`/`clone`/`pull` against an attacker-influenced remote (directly, via a malicious submodule URL, or via a network proxy/MITM answering the HTTPS auth challenge). No unusual local access, admin rights, or pre-existing malware is required — only that Git perform an authenticated HTTP request against a host the attacker controls, which is a routine outcome of cloning or fetching. It bypasses the stronger `isGitHubHost` network-verification path entirely, so no defense-in-depth check catches the spoof once the `wwwauth[]` shortcut matches.

### Recommendation
Do not treat the `wwwauth[]` `realm="GitHub"` value as sufficient proof of a genuine GitHub/GHE endpoint. At minimum, require the same verification used in the fallback path (`isGitHubHost`, which checks for `x-github-request-id`) before routing the user into the branded sign-in flow, or require an explicit user confirmation that clearly discloses the actual hostname being signed into before beginning the enterprise sign-in/OAuth flow.

### Proof of Concept
1. Host an HTTPS server (e.g., `https://evil.example.com`) that, for any request lacking credentials, responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Have the victim add/clone a repository whose remote (or a submodule URL inside a cloned/fetched repo) points at `https://evil.example.com/some/path`.
3. Trigger a fetch/clone in Desktop; Git calls the credential trampoline, forwarding the `wwwauth[]` header.
4. `getEndpointKind` returns `'enterprise'` for `evil.example.com` purely from the spoofed header (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`), no matching account is found, and `ui.promptForGitHubSignIn` starts an enterprise sign-in flow bound to `https://evil.example.com` (`app/src/lib/trampoline/trampoline-ui-helper.ts:87-93`).
5. Victim, seeing Desktop's "Sign in to GitHub Enterprise" UI, enters a PAT or completes browser OAuth, sending it to the attacker-controlled server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

    return new Promise<Account | undefined>(async resolve => {

        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {

    })

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
