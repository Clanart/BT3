### Title
Plot NFT pending pool rewards are lost to the pool operator when `leave_pool` is called before pending rewards are settled - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`)

### Summary
When a Plot NFT (v2 pooling singleton) owner calls `PlotNFT2Wallet.leave_pool()` to exit a pool, the wallet transitions the singleton into the exiting/waiting-room state without first claiming any pool rewards that have already accrued to the user's p2-singleton reward coins. Once the singleton is in this state, `PlotNFT2Wallet.claim_rewards()` still refuses to run because the puzzle's `pooling` flag (`pool_config is not None`) stays true throughout the whole leaving process, forcing the user to use `forward_pool_reward()` instead, which pays the reward to the pool operator's puzzle hash rather than to the user.

### Finding Description
`PlotNFT2Wallet.leave_pool()` builds the exit-to-waiting-room spend and updates local pending-state info, but never checks for or claims any outstanding `PoolReward`s belonging to the plot NFT before performing the transition: [1](#0-0) 

After this call, the `PlotNFT` object still has `pool_config` set (only `exiting` becomes `True`), so `pooling` remains `True`: [2](#0-1) 

Both the wallet-level `claim_rewards()` and the underlying `PlotNFT.claim_pool_rewards()` explicitly reject claiming while `pooling` is `True`: [3](#0-2) [4](#0-3) 

The only remaining option while `pooling` is `True` is `forward_pool_reward()`, whose delegated puzzle sends the reward coin's value to the pool's `pool_puzzle_hash`, not to the user's own wallet: [5](#0-4) [6](#0-5) 

This is functionally the same bug class as the reported `Vault.liquidate` issue: a state-transition action ("leave the pool", analogous to "liquidate the position") is performed without first invoking the "claim" logic for the user, and once the transition happens the normal claim path is permanently gated off for any reward that was already pending, forcing it to be routed away from the user instead.

### Impact Explanation
Any pool reward that the plot NFT owner has already earned (farmed to the pool's p2-singleton reward address) but not yet forwarded/claimed at the moment they call `leave_pool` is subsequently forced through `forward_pool_reward`, which pays that value to the pool operator's `pool_puzzle_hash` instead of the user's wallet. The wallet's own regression test explicitly documents this outcome under the comment "LOSE REWARDS (while leaving)", confirming that a user who calls `leave_pool` loses ownership of any pending, already-earned reward amount: [7](#0-6) 
This is a direct, concrete loss of user funds triggered purely by the user's own unprivileged wallet action, matching the "Impact" criteria of concrete unauthorized coin movement.

### Likelihood Explanation
This is trivially reachable by any Plot NFT owner: simply have an unclaimed/unforwarded pool reward pending (which is the normal, expected state between farmed blocks and periodic reward sweeps) and call `pw_self_pool` / `leave_pool` via the wallet RPC. No special timing, race condition, or privileged access is required.

### Recommendation
Before (or as part of) the `leave_pool` transition, the wallet should first claim/forward all currently pending `PoolReward`s to the user's own wallet (i.e., treat rewards accrued prior to initiating the exit as already belonging to the user), rather than deferring them to a state where `claim_rewards()` is disabled and only `forward_pool_reward()` (which pays the pool) remains available. Alternatively, `pooling` gating for `claim_rewards()`/`claim_pool_rewards()` should distinguish rewards earned before the exit was initiated from rewards that could still legitimately be owed to the pool.

### Proof of Concept
1. Create a Plot NFT and join a pool (`FARMING_TO_POOL`).
2. Farm a block that produces a pool reward coin to the plot NFT's p2-singleton puzzle hash, without immediately claiming/forwarding it.
3. Call `leave_pool` (`pw_self_pool` RPC / `PlotNFT2Wallet.leave_pool`) to begin exiting the pool.
4. Attempt `claim_rewards()` — it raises `"Cannot claim rewards while pooling. If you're a pool, try forward_pool_rewards"` because `pool_config` is still set.
5. The only way to dispose of the pending reward is `forward_pool_reward()`, whose spend pays the reward amount to `guaranteed_pool_config.pool_puzzle_hash` (the pool), not the user, as shown in the existing test `test_plotnft_lifecycle` under the `# LOSE REWARDS (while leaving)` section: [8](#0-7)

    def forward_pool_reward(self, reward: PoolReward) -> list[CoinSpend]:
        if not self.pooling:
            raise ValueError("Cannot forward pool reward while self pooling. Try `claim_pool_rewards`")
        return [
            self.singleton_action_spend(inner_solution=self.forward_pool_reward_inner_solution(reward)),
            make_spend(
                coin=reward.coin,
                puzzle_reveal=reward.puzzle(),
                solution=reward.solve(
                    self.inner_puzzle_hash(),
                    delegated_puzzle_and_solution=DelegatedPuzzleAndSolution(
                        puzzle=self.forward_pool_reward_dpuz(),
                        solution=Program.to([reward.coin.amount]),
                    ),
                ),
            ),
        ]
