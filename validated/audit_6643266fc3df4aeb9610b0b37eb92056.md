### Title
Unauthenticated OP_RETURN in payout tx lets anyone attribute a payout to an arbitrary operator, breaking withdrawal attribution - ([File: core/src/verifier.rs])

### Summary
The payout transaction's OP_RETURN output, which names the operator credited for reimbursement, is not covered by the withdrawer's `SinglePlusAnyoneCanPay` signature, so anyone who broadcasts the payout transaction can name any operator as the payer. `Verifier::is_kickoff_malicious` trusts this unauthenticated field verbatim, and `Operator`'s `PayoutCheckerTask` automation blindly polls the DB for "unhandled payouts" attributed to its own xonly_pk and automatically drives a kickoff/reimbursement for them—crediting a reimbursement to an operator that never funded the payout.

### Finding Description
The binding claimed by ATTRIBUTION is: `payout_payer_operator_xonly_pk == the operator whose funds paid output_txout of the payout tx`. This binding is violated because the OP_RETURN carrying `payout_payer_operator_xonly_pk` is outside the signed message of the only cryptographically-verified input.

- `create_payout_txhandler` builds the payout tx with the user's `SinglePlusAnyoneCanPay` signature on input 0 and adds an OP_RETURN output (index 2) containing an arbitrary `operator_xonly_pk` chosen by whoever builds the transaction: [1](#0-0) 
- `calculate_pubkey_spend_sighash`/`calculate_script_spend_sighash` use `Prevouts::One` for `SinglePlusAnyoneCanPay`, i.e. the sighash only commits to input 0 and (per SIGHASH_SINGLE) the matching output index — never the OP_RETURN output or any additional funding inputs: [2](#0-1) 
- `update_finalized_payouts` derives `operator_xonly_pk` purely by parsing whatever bytes are in the payout tx's OP_RETURN, with no check that those bytes correspond to whoever actually supplied the funding input(s): [3](#0-2) 
- `is_kickoff_malicious` then compares this unauthenticated DB value only against `kickoff_data.operator_xonly_pk`, never against who funded the tx: [4](#0-3) 
- Critically, `PayoutCheckerTask::run_once` for every operator's automation independently and automatically queries `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` and, if it finds a match, immediately drives `handle_finalized_payout` toward a kickoff/reimbursement — with no verification that the operator itself broadcast or funded that payout tx: [5](#0-4) 

Exploit flow: the attacker (as the withdrawer) calls Citrea `withdraw()` themselves, producing a valid `SinglePlusAnyoneCanPay` signature over `output_txout` at index 0 (per protocol design this signature is disclosed to whoever constructs the payout — in this case the attacker themselves, since they created it). The attacker then constructs and broadcasts their own payout transaction: input 0 = the withdrawal UTXO with the valid user signature, output 0 = the committed payout, one or more additional attacker-funded inputs to cover the amount (permitted by `ANYONECANPAY`), and an OP_RETURN naming any registered operator X's xonly_pk — none of which is covered by the signature or otherwise authenticated. Once mined, `update_finalized_payouts` records `payout_payer_operator_xonly_pk = X`. Operator X's own `PayoutCheckerTask` then autonomously picks this up as "its" unhandled payout and drives the kickoff/reimbursement flow. Verifiers' `is_kickoff_malicious` sees `operator_xonly_pk (X) == kickoff_data.operator_xonly_pk (X)` and returns `false` (not malicious), so the kickoff is not challenged and the reimbursement proceeds — crediting operator X for a payout X never funded.

The remaining check in `is_kickoff_malicious` (the committed payout blockhash matching the Winternitz commitment) does not stop this, since the payout block/hash is public once mined and can be correctly committed by whoever eventually submits the kickoff — it authenticates *which block* the payout landed in, not *who funded it*.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded." Concretely: BTC leaves the bridge's reimbursement/collateral machinery to credit operator X, while the party who actually fronted `output_txout` was the attacker (or nobody the protocol recognizes), not X. The attack is fully repeatable per withdrawal and can target any registered operator, and is not gated by any operator-specific secret (the attacker only needs public chain data plus their own withdrawal signature, which they legitimately possess as the withdrawer). Repeated abuse can force multiple operators' automation to consume kickoff/round resources and receive reimbursements they never earned, draining the bridge's reimbursement pool and corrupting the attribution ledger that downstream code (`send_asserts`, `validate_payer_is_operator`, `get_reimbursement_txs`) relies on as ground truth.

### Likelihood Explanation
Preconditions are minimal and entirely within the unprivileged attacker's stated capabilities: call Citrea `withdraw()`, choose the withdrawal UTXO/signature, and broadcast a Bitcoin transaction with attacker-chosen OP_RETURN bytes and extra funding inputs. No verifier/operator/aggregator privilege, key share, or collateral is required. The attacker's cost is the withdrawal amount they must front themselves (paid via `ANYONECANPAY`-added inputs); no fee-race or double-spend trickery is even necessary — a normally-confirmed, fully self-funded payout tx with a forged OP_RETURN suffices. This is deployable against mainnet-equivalent configurations with no need for majority hashrate, malicious peers, or Citrea sequencer control.

### Recommendation
Bind the OP_RETURN operator attribution to the actual signer/funder of the payout transaction, e.g. require the additional funding input(s) to be signed/spent from a taproot output tied to the claimed operator's key (verified on-chain), or have verifiers additionally check that the funding UTXO(s) beyond the withdrawal input belong to (are controlled by) the operator named in the OP_RETURN before accepting `payout_payer_operator_xonly_pk` as ground truth in `update_finalized_payouts`/`is_kickoff_malicious`. Alternatively, require the operator to co-sign the payout tx (e.g. an additional signature covering the OP_RETURN and all outputs) so the attribution is cryptographically bound rather than derived from unauthenticated OP_RETURN bytes.

### Proof of Concept
`cargo test` plan (core/src/test, e2e or unit level):
1. Run a single deposit and register a withdrawal (`run_single_deposit` + `get_new_withdrawal_utxo_and_register_to_citrea`), obtaining `withdrawal_utxo`, `payout_txout`, and the withdrawer's `SinglePlusAnyoneCanPay` `sig`.
2. Instead of calling operator `withdraw()`, manually build a payout transaction using `create_payout_txhandler` with `input_utxo = withdrawal_utxo`, `output_txout = payout_txout`, `user_sig = sig`, but pass `operator_xonly_pk = <Operator B's xonly_pk>` even though Operator B never called `withdraw` for this UTXO and never funded anything; add an extra attacker-controlled funded input via RPC (`fund_raw_transaction`/manual input) to cover fees/value, sign that extra input with the attacker's own key, and broadcast it via `rpc.send_raw_transaction`.
3. Mine `DEFAULT_FINALITY_DEPTH` blocks and let verifier sync (`update_finalized_payouts`) run.
4. Assert `db.get_payout_info_from_move_txid(...)` returns `operator_xonly_pk == Operator B's pk` for this move_txid, and that `Operator B`'s `PayoutCheckerTask::run_once` (or `get_first_unhandled_payout_by_operator_xonly_pk`) returns this payout as unhandled.
5. Trigger/allow Operator B's kickoff flow and call `Verifier::is_kickoff_malicious` (or its equivalent RPC path) with `kickoff_data.operator_xonly_pk == Operator B` and the correctly committed payout blockhash; assert it returns `false`, proving the verifier accepts Operator B as legitimate payer despite Operator B never funding `output_txout`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
