### Title
Nested/recursive precompile calls cause the `BalanceHandler` to double-process bank events, desyncing EVM `StateDB` balances from native bank balances - (File: `precompiles/common/balance_handler.go`, `precompiles/common/precompile.go`)

### Summary
The report’s theme — an unprivileged actor abusing a stateful "before/after" accounting window that is naively shared or overlapped across nested/recursive calls — maps to the `BalanceHandler` mechanism used by every stateful Cosmos EVM precompile (staking, distribution, gov, slashing, erc20, ics20). This component records an event-index checkpoint (`prevEventsLen`) before a native action executes and replays all bank events emitted after that checkpoint into the EVM `StateDB` once the action completes. When a precompile call is entered recursively (e.g., a precompile call that internally triggers another precompile call, or an EVM contract that calls a precompile which in turn calls back into a contract that calls a precompile again within the same transaction), the event windows captured by the inner and outer calls overlap, causing the same underlying bank events to be translated into `StateDB.AddBalance`/`SubBalance` calls more than once. The Cosmos EVM repository itself contains a dedicated regression test package (`evmd/tests/integration/balance_handler`) whose own doc comment states it "tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance, causing `prevEventsLen` to be overwritten... leading to balance desync between native bank keeper and EVM stateDB," confirming this is a recognized bug class in this exact code path.

### Finding Description
Every stateful precompile call in this codebase is routed through `Precompile.RunNativeAction` → `runNativeAction` in [1](#0-0) . For each call, a `BalanceHandler` is obtained from `p.BalanceHandlerFactory.NewBalanceHandler()`, and its lifecycle is:

1. `BeforeBalanceChange(ctx)` records `prevEventsLen = len(ctx.EventManager().Events())` [2](#0-1) .
2. The native `action(ctx)` executes, potentially emitting bank `coin_spent`/`coin_received`/precisebank fractional-balance events, and — critically — potentially invoking further precompile calls (nested `RunNativeAction` invocations) that create their *own* `BalanceHandler` and consume/replay the same trailing slice of `ctx.EventManager().Events()` into the `StateDB`.
3. `AfterBalanceChange(ctx, stateDB)` iterates `events[bh.prevEventsLen:]` — i.e., *all* events appended to the shared `ctx.EventManager()` since step 1 — and applies every `CoinSpent`/`CoinReceived`/`FractionalBalanceChange` event to `stateDB.AddBalance`/`SubBalance` [3](#0-2) .

Because `ctx.EventManager()` is a single, transaction-wide, monotonically-growing event log, an outer precompile call's window `[prevEventsLen_outer : final_len]` necessarily contains all events also captured and already applied by any inner/nested precompile call's window `[prevEventsLen_inner : inner_final_len]`. The outer call has no way to know which sub-ranges were already consumed and already reflected into `StateDB` by a nested call. Consequently, the same coin-spent/coin-received (or precisebank fractional) events are re-parsed and re-applied to the EVM `StateDB` balance a second time in the outer scope, on top of the already-applied inner-scope changes.

This is precisely the invariant targeted by "Asset-representation path" guidance: `x/erc20`, bank, and precompile-mediated flows must preserve 1:1 accounting between native coins and EVM/precompile-visible balances. Here that invariant is broken: the EVM-visible balance (`StateDB`) can diverge from the actual native bank balance because of an event double-count, not because of any actual double transfer of native coins (the bank keeper's own ledger is correct — only the `StateDB` mirror used for subsequent EVM balance reads/transfers within the same execution, and thus for the EVM's post-tx state root, becomes wrong).

The repository's own test, `TestRecursivePrecompileCallsWithDebugPrecompile` in [4](#0-3) , exists specifically to reproduce recursive precompile calls (`callback` → debug precompile invoked 10 times within one tx, producing 15 total events) and its class-level doc comment explicitly names the "balance handler bug" and "balance desync between native bank keeper and EVM stateDB" [5](#0-4) .

### Impact Explanation
If the double-application inflates a user's or contract's `StateDB` balance beyond what the bank keeper actually holds, that inflated EVM balance is directly spendable within the same and subsequent EVM calls (e.g., transferring native coin via `msg.value`/EVM transfer opcodes, which are backed by `StateDB` balance, not a live bank query). This constitutes unauthorized minting/duplication of spendable value in the EVM balance representation — a Critical accounting-corruption impact per the allowed-impact gate ("Critical unauthorized minting, burning, duplication ... of spendable user value across native balances, EVM balances ... precompile-mediated assets"). Even if the corruption is transient and reconciled at block commit, any intra-block/intra-tx logic (further calls, precompile-mediated transfers, contract logic gating on balance) can be exploited to extract value that doesn't exist in the bank ledger, or conversely could brick balances via double-subtraction (denial of use of legitimate funds).

### Likelihood Explanation
Reachability is plausible but not fully proven from static reading alone: it requires a code path where a precompile's native action itself triggers another precompile call that shares the *same* `ctx` event manager as the outer scope (e.g., ICS20/erc20/gov/staking precompiles that internally call `CallEVM`/`CallEVMWithData` which can re-enter a precompile, as seen in the IBC callback and erc20 approve/execute flows in `x/ibc/callbacks/keeper/keeper.go`). Whether the currently-released code has already patched this (e.g., by threading the checkpoint through nested calls, or by having the fix already baked into `runNativeAction`'s per-call factory instantiation) could not be conclusively determined from the available index: the presence of a dedicated, currently-passing-looking regression test could mean either "this reproduces the still-live bug" or "this is a guard test that now passes because the bug was fixed elsewhere." This uncertainty should be resolved by running the test suite and by tracing all call sites where a precompile’s native action itself performs a further precompile/EVM call within the same `ctx`.

### Recommendation
- Do not rely on a per-call local snapshot of `len(ctx.EventManager().Events())`; instead, thread a shared, monotonically-advancing cursor (e.g., stored on the `StateDB` or passed through nested `RunNativeAction` invocations) so that any event index already consumed by an inner call is excluded from the outer call's window.
- Alternatively, have nested precompile calls append a marker/journal entry noting the exact event range they consumed, and have the outer `AfterBalanceChange` skip already-consumed sub-ranges.
- Add an invariant check (e.g., at the end of `ApplyTransaction`) comparing the native bank keeper's balance for touched accounts against the `StateDB`'s final balance, panicking or reverting on mismatch, as a defense-in-depth safety net.
- Extend `TestRecursivePrecompileCallsWithDebugPrecompile` to assert exact native-bank-vs-StateDB balance equality after the recursive call (not just event counts), which appears to be the actual missing assertion needed to conclusively catch this regression.

### Proof of Concept
A concrete PoC requires exercising a precompile call whose native action performs a further nested precompile call using the *same* `sdk.Context`/`EventManager` (e.g., via `CallEVM`/`CallEVMWithData` re-entering a stateful precompile as in `x/ibc/callbacks/keeper/keeper.go` lines 195-225 and 270-439, or via the existing debug-precompile caller contract pattern in `evmd/tests/integration/balance_handler/balance_handler_test.go`). The existing test scaffolding (`DebugPrecompileCaller` contract + `debug` precompile) already provides the harness to reproduce nested precompile calls in one transaction; extending its assertions to directly compare `stateDB` balance vs. `bankKeeper.GetBalance` for the caller/debug-precompile accounts after the call would confirm whether double-counting currently occurs in the deployed code. This step (running the test and adding the balance-equality assertion) could not be completed with the available read-only tooling and should be performed in a live/dynamic environment.

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	var balanceHandler *BalanceHandler
	if p.BalanceHandlerFactory != nil {
		balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()
	}

	if balanceHandler != nil {
		balanceHandler.BeforeBalanceChange(ctx)
	}

	bz, err = action(ctx)
	if err != nil {
		return bz, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	if balanceHandler != nil {
		if err := balanceHandler.AfterBalanceChange(ctx, stateDB); err != nil {
			return nil, err
		}
	}

	return bz, nil
}

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case precisebanktypes.EventTypeFractionalBalanceChange:
			addr, err := ParseAddress(event, precisebanktypes.AttributeKeyAddress)
			if err != nil {
				return fmt.Errorf("failed to parse address from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}
			if bh.bankKeeper.BlockedAddr(addr) {
				// Bypass blocked addresses
				continue
			}

			delta, err := ParseFractionalAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}

			deltaAbs, err := utils.Uint256FromBigInt(new(big.Int).Abs(delta))
			if err != nil {
				return fmt.Errorf("failed to convert delta to Uint256: %w", err)
			}

			if delta.Sign() == 1 {
				stateDB.AddBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			} else if delta.Sign() == -1 {
				stateDB.SubBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			}

		default:
			continue
		}
	}

// TestRecursivePrecompileCallsWithDebugPrecompile demonstrates the balance handler bug
// by triggering recursive calls that share the same BalanceHandler instance.
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))
	s.Require().NoError(err)

	res, _, _, err := s.chain.SendEvmTx(
		s.chain.SenderAccounts[0],
		0,             // sender index
		callerAddr,    // to address
		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier
	)
	s.Require().NoError(err, "callback transaction should succeed")
	s.Require().False(res.IsErr(), "callback should not fail: %s", res.Events)

	s.Require().Equal(len(res.Events), 15, "callback should have 15 events")
	debug_count := 0
	for _, event := range res.Events {
		if event.Type == "debug_precompile" {
			debug_count++
		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")

	// Advance to next block to finalize state
	s.chain.NextBlock()
}
