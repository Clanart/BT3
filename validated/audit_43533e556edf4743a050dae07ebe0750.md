### Title
Scanner reports immature coinbase outputs as received, crediting funds that cannot yet be spent - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Burve M-3 bug class is: a routine assumes an external precondition holds (the vault allows withdrawals), silently does nothing when it doesn't, and downstream accounting then transfers funds that should not move. In Serai's `networks/bitcoin` wallet, `Scanner::scan_block` iterates `block.txdata` in full — including the coinbase transaction — and emits `ReceivedOutput`s for it. Coinbase outputs are encumbered by the 100-block maturity rule, so the scanner reports funds as received which are not yet spendable, the same "credited-but-unavailable" shape.

### Finding Description
`scan_block` loops over every transaction in `block.txdata` and pushes matching outputs into the result set [1](#0-0) . `scan_transaction` matches purely on `script_pubkey` and builds a `ReceivedOutput` with the outpoint, with no maturity or coinbase check [2](#0-1) . The only guard is a doc comment on `scan_block` noting that a post-processing pass is needed [3](#0-2) . Any downstream consumer that treats `ReceivedOutput`s as spendable UTXOs can feed a coinbase output into `SignableTransaction::new`, which sums `input.output.value` and constructs inputs unconditionally [4](#0-3) . The transaction is then signed via `taproot_key_spend_signature_hash` over `Prevouts::All` with no maturity validation [5](#0-4) .

### Impact Explanation
Analogous to the Burve case where the protocol fee was paid out because a presumed-successful vault withdrawal silently no-oped, here the wallet layer can produce (and the FROST network can sign) a transaction spending an immature coinbase output. Such a transaction is consensus-invalid and will be rejected by the network, so "received" funds are effectively unspendable: the outputs selected for it are burned as inputs in a transaction that can never confirm, forcing re-selection and potentially stalling the signing pipeline. It also opens crediting of deposits that cannot actually be moved.

### Likelihood Explanation
The trigger is passive: any coinbase transaction paying a scanned script (i.e., a miner paying the Serai address directly) produces a `ReceivedOutput` indistinguishable from spendable ones. Reachability is via normal Bitcoin transactions/blocks an unprivileged miner can create.

### Recommendation
Have `scan_block` skip `block.txdata[0]` (or return coinbase outputs marked as immature), matching the existing suggestion to use `scan_transaction` on `block.txdata[1 ..]`; or check `tx.is_coinbase()` inside `scan_block` and exclude/tag those outputs so callers cannot mistake them for spendable UTXOs.

### Proof of Concept
```rust
// Miner mines a block whose coinbase pays Serai's p2tr script.
// Scanner::new(group_key) -> scanner
let outputs = scanner.scan_block(&block);
// outputs[0] is the coinbase output; no field distinguishes it as immature.
// Caller builds a spend:
let stx = SignableTransaction::new(outputs, &payments, change, None, fee_rate).unwrap();
// Signing machine produces a tx spending an immature coinbase input;
// the tx is consensus-invalid for 100 blocks and will never relay/confirm.
```
The maturity caveat exists only as a doc comment; nothing in `scan_block`, `scan_transaction`, or `SignableTransaction::new` enforces it.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
