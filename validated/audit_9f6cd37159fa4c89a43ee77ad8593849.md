Confirmed: `RunAndCalculateGas` in `precompiles/common/precompiles.go` has **no `recover()`** around the `d.executor.Execute(...)` call itself (the only `recover()` is scoped narrowly to `chargeDecodeGas`, purely for gas-meter panics). ### Title
Unchecked type assertion on malicious CosmWasm contract query response causes precompile panic - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query an arbitrary, attacker-supplied CosmWasm contract address and then blindly type-assert the JSON-decoded `name` and `symbol` fields of the response as `string`, with no `ok` check or recovery. This mirrors the CVE-2021-3578 bug class: an unchecked type/pointer assumption applied to attacker/peer-controlled response data, reachable without any privilege.

### Finding Description
`AddCW20`/`AddCW721`/`AddCW1155` call `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, ...)` against a CW address fully controlled by the calling EVM account (any address can be passed as `cwAddr` in `args[0]`, and anyone can deploy a CosmWasm contract with a custom `token_info`/`contract_info` query handler). The response is JSON-unmarshaled into `map[string]interface{}{}`, then:
```go
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
``` [1](#0-0) [2](#0-1) [3](#0-2) 

If the queried contract returns `name` or `symbol` as any non-string JSON value (number, bool, array, object, or omits the key entirely so the map lookup yields `nil`), this type assertion panics with `interface conversion: interface {} is nil, not string` (or similar). The identical unchecked pattern also exists in every legacy pointer version. The `Execute` entrypoint for `pointer` has no `recover()` [4](#0-3) , and the caller `DynamicGasPrecompile.RunAndCalculateGas` in `precompiles/common/precompiles.go` only wraps a narrow, separate `recover()` around `chargeDecodeGas` (gas-meter panics only) [5](#0-4) ; the actual `d.executor.Execute(...)` call at line 206 has no panic recovery around it [6](#0-5) .

### Impact Explanation
A panic inside precompile execution during EVM message processing that is not recovered at any layer up to the ante/msg handler will crash/halt the node processing that transaction (or, if recovered elsewhere in the EVM execution stack, could cause divergent behavior between nodes depending on recovery timing), which can lead to validator halt or non-determinism across the network — satisfying the "validator halt" / "permanent chain split" bar. Because this is trivially reachable by any transaction sender who deploys a trivial CosmWasm contract and calls `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against it, it requires no privilege.

### Likelihood Explanation
High reachability: any account can deploy a CosmWasm contract (a `token_info` or `contract_info` query handler returning a non-string `name`/`symbol`, e.g. `{"name": 123, "symbol": null}`) and then call the `pointer` precompile at `0x000000000000000000000000000000000000100b` with `addCW20Pointer(cwAddr)`. No association, no special permission, no gas-limit trick needed — purely a data-shape issue in the query response.

### Recommendation
Replace the unchecked assertions with safe, checked extraction (`v, ok := formattedRes["name"].(string); if !ok { return nil, 0, fmt.Errorf(...) }`) in `precompiles/pointer/pointer.go` (`AddCW20`, `AddCW721`, `AddCW1155`) and all legacy variants under `precompiles/pointer/legacy/*/pointer.go`, or wrap the whole `Execute`/`RunAndCalculateGas` path with a `recover()` that converts any panic into a reverted EVM call rather than letting it propagate.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` query handler returns `{"name": 123, "symbol": 456, "decimals": 6, "total_supply": "0"}` (non-string name/symbol).
2. From any EVM account, call the `pointer` precompile (`0x...100b`) method `addCW20Pointer(<contract_bech32_address>)`.
3. Execution reaches `formattedRes["name"].(string)` in `precompiles/pointer/pointer.go:154`, which panics because the underlying value is `float64`, not `string`.
4. The panic propagates uncaught through `RunAndCalculateGas` (no recover around the `Execute` call), crashing/halting transaction processing for that block.
