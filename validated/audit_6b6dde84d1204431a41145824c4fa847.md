## Confirmed: analog found in `checkConsistency` (KIP-71 bound validation)

### Title
Governance vote consistency check validates against stale ratified `ParamSet` instead of pending same-epoch votes, allowing `LowerBoundBaseFee > UpperBoundBaseFee` - (File: kaiax/gov/headergov/impl/header.go)

### Summary
`checkConsistency` for `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` votes only compares the new vote value against the currently-ratified `ParamSet` (`h.GetParamSet(blockNum)`), not against other votes already cast (but not yet ratified) within the same epoch. This mirrors the CVX `setBoost` bug class: the check validates a stale/unrelated stored value rather than the actual pending values that will be committed together, letting the two related bounds end up inconsistent once ratified.

### Finding Description
`checkConsistency` in [1](#0-0)  implements the cross-field validation:
```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee { return ErrLowerBoundBaseFee }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee { return ErrUpperBoundBaseFee }
```
`GetParamSet(blockNum)` returns the parameter set ratified from **previous epochs only** — per the module's own documentation, "Parameter change ratified at `k*epoch` block takes effect starting from `(k+1)*epoch` block" [2](#0-1) . Votes accumulate throughout the current epoch and are all ratified together at the epoch boundary, with only the last vote per parameter name in the epoch taking effect [3](#0-2) .

Consequently, in `single` governance mode (used on Mainnet/Kairos), the governing node can cast two votes within the same epoch:
1. Vote `Kip71LowerBoundBaseFee = X` (checked against the *old* `UpperBoundBaseFee`, which is still high — passes).
2. Vote `Kip71UpperBoundBaseFee = Y < X` (checked against the *old* `LowerBoundBaseFee`, which is still low — passes).

Both votes pass `VerifyVote`/`checkConsistency` individually because each is checked against the stale, not-yet-updated counterpart value — exactly like `CvxLocker.setBoost` checking already-set storage instead of the incoming parameter. At epoch ratification, both new values are applied simultaneously with `ParamSet.SetFromMap` [4](#0-3) , producing a final state where `LowerBoundBaseFee > UpperBoundBaseFee`, an invariant the code never re-validates after ratification.

### Impact Explanation
The resulting inverted bounds are fed directly into `KIP71Config.NextMagmaBlockBaseFee`, which assumes `lowerBoundBaseFee <= upperBoundBaseFee` [5](#0-4) . With bounds inverted, the clamping logic (`if parentBaseFee >= upperBoundBaseFee ... else if parentBaseFee <= lowerBoundBaseFee ...`) can produce a computed next-block base fee that lies **outside** the newly configured bounds (e.g., ending up equal to the wrongly-lower `upperBoundBaseFee`, effectively bypassing the intended floor). This corrupts the KIP-71 dynamic base-fee mechanism used for every block's fee computation and gas price suggestions (`SuggestPrice`/`UpperBoundGasPrice`/`LowerBoundGasPrice` in `node/cn/api_backend.go`), which is reachable by any public-RPC caller/transaction sender relying on correct fee bounds, and can only be corrected by another governance vote cycle once the inconsistency is noticed (mirroring the "cannot be set to new correct values" bricking effect described in the original report).

### Likelihood Explanation
Requires two governance votes within a single epoch by the entity permitted to vote (the `governance.governingnode` in `single` mode, or any GC member in `none` mode) — this is a "governance parameters" pathway explicitly permitted in scope. No special validator/consensus/network-layer capability is needed beyond the existing `governance_vote` RPC API [6](#0-5) , making it directly reachable via a standard RPC call and straightforward to trigger accidentally or intentionally within one epoch (604800 blocks on Mainnet).

### Recommendation
When checking `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` votes, compare against the tentative/pending value that would be ratified for the counterpart parameter within the current epoch (i.e., merge the current epoch's already-cast votes on top of `GetParamSet(blockNum)` before comparing), not solely against the last-ratified `ParamSet`. Additionally, re-validate the full pending `ParamSet` for `LowerBoundBaseFee <= UpperBoundBaseFee` at ratification time (`HandleGov`/epoch-boundary processing) as a final consistency backstop.

### Proof of Concept
1. Assume current ratified state: `LowerBoundBaseFee = 25e9`, `UpperBoundBaseFee = 750e9`, `GovernanceMode = "single"`, governing node = `V`.
2. Within the current epoch, `V` casts vote `Kip71LowerBoundBaseFee = 700e9`. `checkConsistency` compares `700e9 > params.UpperBoundBaseFee(750e9)` → false → vote accepted [7](#0-6) .
3. Later in the same epoch, `V` casts vote `Kip71UpperBoundBaseFee = 690e9`. `checkConsistency` compares `690e9 < params.LowerBoundBaseFee(25e9)` → false → vote accepted [8](#0-7)  (it is checked against the stale `25e9`, not the pending `700e9`).
4. At the epoch boundary, both votes are ratified via `getExpectedGovernance`/`SetFromMap`, producing `LowerBoundBaseFee = 700e9 > UpperBoundBaseFee = 690e9` [3](#0-2) [4](#0-3) .
5. From the next epoch onward, `NextMagmaBlockBaseFee` computes base fees using these inverted bounds, producing values that violate the intended `[Lower, Upper]` invariant [9](#0-8) .

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

The ratification condition is determined by the `governance.governancemode` parameter. Mainnet and Kairos both operate in `single` mode. There are two governance modes:

- `none` mode: all members of the GC can vote. For each governance parameter, the last vote in the epoch will be ratified.

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
