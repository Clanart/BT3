### Title
Untrusted `ReceivedOutput` bytes are accepted without binding the claimed key offset to the output's `script_pubkey` — ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to the Juicebox `changeTokenFor` bug — where anyone could bind a token to their project without proving control over the token — `ReceivedOutput::read` accepts an untrusted serialization that claims a Bitcoin `TxOut` belongs to the Serai threshold key under a caller-supplied scalar `offset`, without ever checking that the output's `script_pubkey` actually equals `P2TR(group_key + offset·G)`. The legitimately produced `ReceivedOutput` (via `Scanner::scan_transaction`) carries this binding implicitly through `scripts: HashMap<ScriptBuf, Scalar>` lookup, but the deserialization path drops that invariant entirely.

### Finding Description
`Scanner::scan_transaction` produces a `ReceivedOutput` only when `self.scripts.get(&output.script_pubkey)` returns a registered offset, so scanned outputs are guaranteed spendable under `key + offset·G` [1](#0-0) . However, `ReceivedOutput::read` deserializes `offset`, `output`, and `outpoint` independently from a `Read` source with zero cross-validation [2](#0-1) . An attacker can therefore hand any downstream consumer bytes of the form `(arbitrary_offset, TxOut paying to the attacker's own P2TR script, outpoint of a real UTXO they control)` and the structure is accepted as a received output.

Additionally, `Scanner::register_offset` documents that arbitrary offsets "may introduce a script path into the output, allowing the output to be spent by satisfaction of an arbitrary script (not by the signature of the key)" — i.e., the library itself acknowledges offsets must be securely generated — yet `read` applies no such constraint to the supplied offset [3](#0-2) .

### Impact Explanation
When a consumer feeds attacker-crafted bytes to `ReceivedOutput::read`, the result is a `ReceivedOutput` reporting funds "received" that the threshold key cannot actually spend: the spend key derived via `key + offset·G` does not correspond to the output's `script_pubkey` (or corresponds to a script the attacker also controls a path on). This mirrors the Juicebox impact — an unprivileged party hijacks an asset binding they do not control — here producing funds reported received that are not spendable, and potentially causing the wallet to commit attacker-chosen inputs to a `SignableTransaction` that can never confirm, or worse, that pays change/aggregation outputs under offsets the attacker selected.

### Likelihood Explanation
Reachability: the rules explicitly admit untrusted bytes fed to `ReceivedOutput::read`, and `ReceivedOutput` is the currency unit of the scanner → `SignableTransaction` → `multisig` pipeline. Any path where a serialized `ReceivedOutput` is persisted or transmitted and later re-read (the `serialize`/`read` round-trip exists precisely for this purpose) exposes this. The attacker only needs to control the serialized bytes; no key material, validator status, or collusion is required. Likelihood is bounded by whether deserialization of peer-supplied `ReceivedOutput`s occurs in production, which lives outside the in-scope crate (processor) — hence Medium rather than High.

### Recommendation
`ReceivedOutput` should not be deserializable into an invalid state. Either:
- Make `read` take the `Scanner` (or at minimum the group key + registered offset table) and verify `p2tr_script_buf(key + offset·G) == output.script_pubkey`, rejecting otherwise; or
- Remove `ReceivedOutput::read` entirely and require re-derivation of the offset via `Scanner::scan_transaction` on the referenced transaction, so the script↔offset binding is always established by scanning rather than claimed by the byte stream.

### Proof of Concept
```rust
// Attacker-controlled bytes
let mut buf = Vec::new();
// offset chosen so key + offset*G is even (or a script the attacker has a path to)
buf.extend(Scalar::ONE.to_bytes());
// TxOut paying to the ATTACKER's own script, not key + offset*G
buf.extend(&serialize(&TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: attacker_p2tr_script,
}));
// OutPoint of a real, attacker-owned UTXO
buf.extend(&serialize(&attacker_outpoint));

// Accepted unconditionally — no binding check exists
let forged: ReceivedOutput = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
// forged.value() == 100_000 reported received; forged.offset() == 1,
// but key + 1*G does not control attacker_p2tr_script → unspendable / attacker-spendable
```
