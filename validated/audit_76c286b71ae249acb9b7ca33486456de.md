### Title
Push-based fee/reward transfer in `WombatStaking._sendRewards` allows a blacklisted or reverting fee address to permanently DoS `harvest()` for an entire pool - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking.harvest()` is a permissionless, unprivileged function that any wallet can call for an active pool to pull WOM/bonus rewards from the Wombat exchange and route them to configured fee recipients and the pool's rewarder. The internal routing function `_sendRewards` pushes tokens directly to `feeInfo.to` via `safeTransfer`, exactly the push-model pattern described in the external report. If any configured fee recipient becomes blacklisted by a stablecoin issuer (USDT/USDC) or otherwise reverts on receipt, the push reverts and blocks the entire `harvest()` call for that pool for every caller, indefinitely.

### Finding Description
`harvest()` is reachable by any ordinary wallet: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which for the base WOM reward and every configured bonus token calls `_sendRewards`: [2](#0-1) 

Inside `_sendRewards`, the function iterates over all registered `feeInfos` and, for fee entries flagged as a plain address (`feeInfo.isAddress == true`), pushes tokens directly with `safeTransfer` before finally forwarding the remainder to the pool's rewarder: [3](#0-2) 

This is the same push-funds pattern flagged in the report: a `safeTransfer`/`safeTransferFrom` to a fixed, shared address executed unconditionally in a loop, with no `try/catch` and no pull-based fallback. Fee recipients are configured once via `addFee`/`Fees.to` and then reused by every subsequent `harvest()` call for that pool: [4](#0-3) 

If any such recipient address is later blacklisted by a stablecoin used as a reward/bonus token (a condition external to and independent of admin action, exactly as in the original report where `creator`/`beneficiary` become blacklisted after being legitimately configured), the `safeTransfer` at line 760 reverts, and because it sits inside the same external call as the rewarder's `queueNewRewards`, the entire `harvest()` transaction for that pool reverts.

### Impact Explanation
Because `feeInfo.to` is shared state used by every `harvest()` invocation for every pool that isn't fee-free, a single blacklisted or reverting fee address permanently blocks reward harvesting (and thus reward accrual delivery to `BaseRewardPool`/rewarder via `queueNewRewards`) for that pool for all stakers, not just the fee recipient itself. This freezes newly-earned, unclaimed yield for every user staking in the affected pool until an admin notices and calls a fee-removal function — mirroring the "denial of service on all future executeAutomation() calls" impact described in the report, here manifesting as denial of harvest/reward-forwarding for an entire staking pool.

### Likelihood Explanation
`harvest()` has no caller restriction beyond the pool being active, so any wallet triggers the vulnerable code path. The only precondition is that one of the (previously legitimate) fee addresses becomes non-functional for a token used as a reward (e.g., blacklisted by Tether/Circle, or a contract that starts reverting), which is realistic given fee recipients can be arbitrary addresses/contracts set once and reused indefinitely.

### Recommendation
Replace the push transfer in `_sendRewards` for address-type fees with a pull/claim pattern (accumulate balances in a mapping and let the fee recipient withdraw), or wrap the `safeTransfer` call in a `try/catch` so a single failing recipient cannot block reward routing for the rest of the pool's stakers.

### Proof of Concept
1. Owner calls `addFee(value, feeAddr, false, true)` registering `feeAddr` as a legitimate address-type fee recipient for a pool that pays WOM or a bonus token that is a stablecoin (USDT/USDC).
2. `feeAddr` is later blacklisted by the stablecoin issuer (or is/becomes a contract that reverts).
3. Any user calls `harvest(_lpToken)` for that pool; `_toMasterWomAndSendReward` → `_sendRewards` reaches the loop iteration for `feeAddr` and calls `IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend)` at [5](#0-4) , which reverts.
4. The whole `harvest()` transaction reverts, and every subsequent call to `harvest()` for that pool reverts identically, blocking reward delivery to the pool's `BaseRewardPool` for all stakers until an admin removes the fee.

```text
    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }
```
