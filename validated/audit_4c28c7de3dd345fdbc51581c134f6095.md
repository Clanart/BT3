### Title
Unbounded indexing into the encryption-key registry panics on attacker-chosen participant index in PedPoP blame/decrypt paths - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The PedPoP encryption layer keeps per-participant encryption public keys in a `HashMap<Participant, C::G>` (`Decryption.enc_keys`) that is populated exclusively by `register`. Both message-producing paths dereference this map with the `[]` indexing operator using a `Participant` value derived from an untrusted DKG/blame message. Any reference to a participant that never registered (or an out-of-set / not-yet-registered index) panics the entire process, giving an unprivileged protocol peer a denial-of-service primitive analogous to the eazy-logger report's class: a crafted input mutating/querying shared keyed state causes a crash (CWE-400 consequence of a CWE-1321-style "pollute/lookup shared object by attacker key" pattern).

### Finding Description
`Decryption::register` is the only writer of `enc_keys`, and it asserts that a participant registers exactly once: `assert!(!self.enc_keys.contains_key(&participant), "Re-registering encryption key for a participant")` at `crypto/dkg/pedpop/src/encryption.rs` (register). Two readers then index the map unchecked:

- `decrypt_with_proof` resolves the shared key via `self.enc_keys[&decryptor]` inside the DLEq verification that justifies releasing a decryption key for a blamed message (`encryption.rs`, `decrypt_with_proof`).
- `Encryption::encrypt` uses `self.decryption.enc_keys[&participant]` to pick the recipient's public key (`encryption.rs`, `encrypt`).

In both cases the `Participant` index comes from a deserialized protocol message (`EncryptionKeyMessage::read` / `EncryptedMessage::read` take attacker-controlled bytes and a `params: ThresholdParams`, and callers route per-sender messages keyed by the sender's claimed/derived index). There is no bounds check against `params.n()` or membership check against `enc_keys` before indexing. A `HashMap` index miss in Rust is an unconditional `panic!`, unwinding/aborting the host — a remote, input-triggered crash.

### Impact Explanation
An attacker who can emit a DKG/blame-protocol message referencing a `Participant` index that was never inserted into `enc_keys` (e.g., an accusation naming a `decryptor` who has not yet registered, a duplicate-registration sequence that desynced the map, or an index validly parseable but absent) causes an unconditional panic in the victim processor at `self.enc_keys[&decryptor]` / `enc_keys[&participant]`. This halts the victim's key-generation or signing pipeline — a denial of service of the threshold protocol. Because PedPoP runs inside the processor's DKG for every validator set, crashing a participant mid-protocol can stall set rotation and all dependent signing. Severity: Medium (DoS only; no secret leakage shown).

### Likelihood Explanation
Reachability requires only sending a well-formed protocol message whose associated participant index is absent from the receiver's `enc_keys` map — e.g., an early `EncryptionKeyProof`/blame against a party whose `EncryptionKeyMessage` was not processed, or a message routed under an index outside the registered set. The panic sites are on the normal decryption/blame code path, not behind authentication of the index's prior registration. Likelihood is moderate: it needs a protocol-speaking peer, which is exactly the assumed PedPoP adversary.

### Recommendation
Replace all `enc_keys[&participant]` / `enc_keys[&decryptor]` indexing with `enc_keys.get(&i).ok_or(...)` returning a typed error, and validate `u16::from(participant) <= params.n()` on every `Participant` deserialized from the wire (in `EncryptionKeyMessage::read`, `EncryptedMessage::read`, and the blame entry points). Keep `register`'s duplicate assert but surface duplicates as a `FrostError`-style blame-able error rather than a panic, so malformed senders are identified instead of crashing the node.

### Proof of Concept
```rust

// An attacker emits a blame/accusation naming Participant(2) who
// never sent an EncryptionKeyMessage, so enc_keys is empty.
let msg: EncryptedMessage<Ristretto, Share> =

let proof = EncryptionKeyProof::read(&mut attacker_proof_bytes).unwrap();
```
