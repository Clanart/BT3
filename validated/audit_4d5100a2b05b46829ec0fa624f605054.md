### Title
Insufficient Bid Equality Check Allows Winner-List Bypass to Submit a Different Bid Under an Existing Sender Slot - (File: kaiax/auction/bid.go)

### Summary
`Bid.Equals()` only compares `BlockNumber` and `TargetTxHash`, ignoring `Bid` (amount), `Data`, `CallGasLimit`, `Nonce`, `Sender`, and the signatures. This function backs `senderHasDifferentWinner()`, which gates both `AddBid`/`validateBid` in the `BidPool`, so a bid with materially different content but the same `(BlockNumber, TargetTxHash)` pair is treated as "the same bid" as the one already recorded in `bidWinnerMap`.

### Finding Description
`Bid.Equals` is defined as: [1](#0-0) 

It is used in `senderHasDifferentWinner`, which is the sole safeguard preventing a sender from having two different winning bids recorded for the same block: [2](#0-1) 

This check gates both `validateBid` (rule 1) and the `AddBid` path: [3](#0-2) [4](#0-3) 

Because `Equals` does not check `Bid.Bid` (the deposit/bid amount), `Bid.Data`, `Bid.CallGasLimit`, or `Bid.Sender`/signatures, any searcher who already has a winning bid for `(BlockNumber, TargetTxHash)` recorded in `bidWinnerMap` can submit a second bid over the P2P `HandleBid` path with the same `BlockNumber`/`TargetTxHash` but a completely different `Bid` amount, `Data` payload, or `CallGasLimit`, and the pool will treat it as equal to the existing winner rather than rejecting/replacing it through the FCFS `bidMap[blockNumber][targetTxHash]` comparison logic that normally requires a strictly higher bid (`existingBid.Bid.Cmp(bid.Bid) >= 0` in the replace path). This is directly analogous to the report's root cause: an identifier (`transferId` in Nomad, `(BlockNumber, TargetTxHash)` here) is used as a proxy for "same logical operation," while the parameters that actually determine value/execution semantics (`_amount`/`_localToken` there, `Bid`/`Data`/`CallGasLimit` here) are not included in the equality/authenticity check.

### Impact Explanation
If a lower/zero bid amount, or arbitrary `Data`/`CallGasLimit`, can be substituted for the sender's real winning bid without being rejected as "different," the actual auction settlement executed via `GetBidTxGenerator` can end up executing calldata/gas limits that were never validated against the higher bid amount that won the FCFS race. This can result in fee/bid abuse (winning at a high stated bid while the value that ultimately gets recorded/settled corresponds to a differently-parameterized bid) — the same class of harm as in the report: acceptance of an operation whose value-bearing parameters diverge from what was actually authorized/paid for.

### Likelihood Explanation
Reachable from an unprivileged network participant: any searcher submitting bids over the auction P2P gossip/`HandleBid` path can trigger this once they already hold a winner slot for a given `(BlockNumber, TargetTxHash)`, requiring no special privilege beyond being a registered searcher.

### Recommendation
Make `Bid.Equals` compare all economically/execution-relevant fields (`Bid`, `Data`, `CallGasLimit`, `Nonce`, `Sender`, and ideally the full EIP-712 hash) instead of only `BlockNumber` and `TargetTxHash`, so `senderHasDifferentWinner` correctly rejects any bid whose value-bearing content differs from the one already recorded as the sender's winner.

### Proof of Concept
1. Searcher A submits Bid1 = `{BlockNumber: N, TargetTxHash: H, Bid: 100, Data: D1, CallGasLimit: G1}`; it wins and is stored in `bidWinnerMap[N][A] -> hash(Bid1)`.
2. Searcher A crafts Bid2 = `{BlockNumber: N, TargetTxHash: H, Bid: 1, Data: D2 (malicious), CallGasLimit: G2}` with a valid signature.
3. `validateBid(Bid2)` calls `senderHasDifferentWinner(Bid2)`, which calls `Bid2.Equals(Bid1)`; since only `BlockNumber`/`TargetTxHash` are compared, it returns `true` ("equal"), so the sender-exists check is bypassed even though `Bid`, `Data`, and `CallGasLimit` differ.
4. Depending on downstream handling (e.g., `AddBid`'s FCFS branch at [5](#0-4) ), Bid2 with a much lower value or malicious payload can be processed instead of the originally validated/settled Bid1.

```go
// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}
```
