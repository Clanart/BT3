This confirms the vulnerability. In `extract_frontmatter`'s "simple key-value pair" branch [1](#0-0) , the parser only checks for empty lines and full-line comments (lines starting with `#`) at line 118, but does not strip trailing `#` comments on a value line. So `pattern: rm -rf # safe` yields `value = "rm -rf # safe"` verbatim (only quote-stripping is applied), unlike real YAML which treats unquoted trailing `# comment` as a comment and would parse the value as `rm -rf`.

This tainted string flows unchanged through `Rule.from_dict` into a `Condition(pattern="rm -rf # safe")` [2](#0-1) , and then `RuleEngine._regex_match` compiles it directly as a regex via `compile_regex(pattern)` and calls `regex.search(text)` [3](#0-2) . Since Python's `re` module does not treat `#` as a comment character unless `re.VERBOSE` is used (it isn't — only `re.IGNORECASE` is passed at compile_regex line 24), the literal string `# safe` becomes part of the required regex match. The real dangerous command text (e.g. `rm -rf /important/data`) does not contain the literal substring `# safe`, so `regex.search(text)` returns `False` and the rule silently never matches — completely defeating a `block`/deny rule while looking, to a human reading the `.local.md` file, like a normal commented pattern.

### Title
Trailing `#` comments in hookify frontmatter values are parsed as literal regex text, silently defeating deny rules - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter`'s hand-rolled YAML parser only strips full-line comments, not trailing inline comments on `key: value` lines, so a rule author who writes `pattern: rm\s+-rf\s+/ # dangerous!` gets a compiled regex containing the literal comment text. The resulting regex almost never matches real dangerous commands, silently turning an intended `action: block` rule into a no-op while the rule file still visually looks correct and enabled.

### Finding Description
The parser's top-level key-value branch [1](#0-0)  does `value.strip('"').strip("'")` and boolean coercion, but never removes an inline `#...` comment suffix. Only whole-line comments (`stripped.startswith('#')`) are skipped, at [4](#0-3) . Real YAML/PyYAML strips unquoted trailing comments after whitespace, so `pattern: rm -rf # safe` would parse to `pattern: "rm -rf"` in standard YAML but parses to `pattern: "rm -rf # safe"` here.

This value flows through `Rule.from_dict` unchanged into a `Condition.pattern` [5](#0-4) , then into `RuleEngine._regex_match`, which compiles it with `re.compile(pattern, re.IGNORECASE)` (no `re.VERBOSE`) and does `regex.search(text)` [3](#0-2) . Since `#` has no special meaning in default Python regex mode, the compiled pattern requires the literal substring `# safe` (or whatever comment text) to appear in the command, which it won't for the actual dangerous command being matched. No allowlist, approval prompt, or sanity check exists anywhere in `load_rules` → `load_rule_file` → `RuleEngine.evaluate_rules` [6](#0-5)  that would catch this divergence from real YAML semantics or verify the compiled pattern behaves as the rule author intended.

### Impact Explanation
A hookify `.claude/hookify.*.local.md` rule with `action: block` intended to deny a dangerous Bash command (e.g. `rm -rf`) silently fails to trigger if the rule author (or an attacker who supplies/modifies such a rule file in a cloned repository) includes a trailing `#` comment on the `pattern:` line. This is a false sense of security: the user/operator believes a dangerous command class is blocked by their PreToolUse hook, but `RuleEngine.evaluate_rules` returns `{}` (allow) for the actual dangerous command, letting it execute as if no rule existed at all [7](#0-6) .

### Likelihood Explanation
This requires only that a `.claude/hookify.*.local.md` rule file with a `pattern:` line containing a trailing `#` comment be loaded from the repository the user has as CWD — no admin privilege, no social engineering beyond an attacker being able to place/modify a rule file in a cloned repo (a normal, expected way hookify rules are authored/shared). It is entirely reachable through the documented `load_rules → load_rule_file → extract_frontmatter → Rule.from_dict → RuleEngine.evaluate_rules` path used by every hookify hook script (`pretooluse.py`, `posttooluse.py`, `stop.py`).

### Recommendation
In `extract_frontmatter`, strip inline `#` comments from unquoted scalar values before assignment (mirroring YAML semantics: only strip `# ...` when preceded by whitespace and the value isn't inside quotes), e.g. after splitting `key, value = line.split(':', 1)`, apply a helper that finds an unquoted ` #` and truncates the value there, then continue with existing quote-stripping. Additionally, consider adding a self-test/differential fixture that compiles every loaded rule's pattern and validates it against a corpus of known-dangerous command strings for `action: block` rules, so behavioral drift from intended blocking is caught in CI rather than silently at runtime.

### Proof of Concept

```python
import yaml
from hookify.core.config_loader import extract_frontmatter, Rule
from hookify.core.rule_engine import RuleEngine

RULE_MD = """---
name: block-rm-rf
enabled: true
event: bash
action: block
pattern: rm\\s+-rf # dangerous recursive delete
---
Blocked!
"""

def test_extract_frontmatter_matches_pyyaml_semantics():
    fm, _ = extract_frontmatter(RULE_MD)
    yaml_fm = yaml.safe_load(RULE_MD.split('---')[1])
    # PyYAML strips the comment; hand-rolled parser does not -> divergence
    assert fm['pattern'] != yaml_fm['pattern']  # documents the parsing bug

def test_block_rule_still_matches_dangerous_command():
    fm, msg = extract_frontmatter(RULE_MD)
    rule = Rule.from_dict(fm, msg)
    engine = RuleEngine()
    input_data = {
        "tool_name": "Bash",
        "tool_input": {"command": "rm -rf /important/data"},
        "hook_event_name": "PreToolUse",
    }
    result = engine.evaluate_rules([rule], input_data)
    # Expect block, but bug causes {} (allow) instead
    assert result.get("hookSpecificOutput", {}).get("permissionDecision") == "deny"
```
