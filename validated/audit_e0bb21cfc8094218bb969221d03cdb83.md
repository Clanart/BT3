## Finding

### Title
First BEEFY authority-set rotation (`epoch == 0`) can never be attributed on-chain, permanently locking its `OutboundConsensusDeliveryReward` - (File: `evm/src/core/HandlerV2.sol`)

### Summary
`HandlerV2.handleConsensus` computes the just-ended authority-set epoch as `nextAuthoritySetId - 1` and only credits the delivering relayer via `EvmHost.recordEpoch` when that epoch is strictly greater than the host's current epoch. Both `epoch` and the host's default `_currentEpoch` can legitimately be `0` — the very first authority-set rotation on any freshly deployed `EvmHost` — so the strict `>` comparison against an uninitialized-but-valid zero value silently drops attribution forever, exactly the `Factory.sol` `templateVersion > latestVersion[templateName]` bug class from the external report (a real, non-zero value of `0` is indistinguishable from "never set").

### Finding Description
In `handleConsensus`: [1](#0-0) 

`_currentEpoch` is a `uint256` that defaults to `0` and is only mutated inside `recordEpoch`: [2](#0-1) 

When the destination `EvmHost` observes its first ever BEEFY authority-set rotation (genesis set `0` → set `1`), `nextAuthoritySetId == 1`, so `epoch = nextAuthoritySetId - 1 = 0`. The guard evaluates `epoch > host.currentEpoch()` → `0 > 0` → `false`, so `recordEpoch(0, relayer)` is never called. `_epochs[0]` therefore remains `address(0)` permanently — indistinguishable from "no relayer has ever been recorded for this epoch" — even though a legitimate rotation genuinely occurred and a relayer genuinely delivered it.

This is architecturally identical to the reported bug: `latestImplementation[templateName]` staying `address(0)` when `templateVersion == 0`, because the code cannot tell apart "value is validly zero" from "value was never set."

### Impact Explanation
`_epochs[set_id]` is the sole on-chain attribution mechanism consumed by `pallet-ismp-relayer::process_outbound_consensus_delivery_claim` on Hyperbridge to pay out `OutboundConsensusDeliveryReward`. The pallet proves the value at slot `keccak256(set_id || EVM_HOST_EPOCHS_SLOT)` via a state proof and explicitly treats a decoded zero address as "not yet proven": [3](#0-2) [4](#0-3) 

Because `_epochs[0]` can never become non-zero, no relayer can ever satisfy this proof for `set_id == 0`, so `claim_outbound_consensus_delivery_reward` will always fail with `OutboundDeliveryNotProven` for the first rotation on every destination `EvmHost`. The `OutboundConsensusDeliveryReward` configured for that destination is permanently unclaimable for that specific (and unavoidable) rotation — funds that should be paid to whichever relayer legitimately delivers the first mandatory consensus proof are stuck in the treasury with no code path to release them, matching the bounty's "loss of funds" / stuck-reward impact category (the reward-claims domain named in the gate).

Note: the bug is isolated to relayer attribution/reward bookkeeping — `storeConsensusState`/`storeStateMachineCommitment` still execute correctly beforehand, so consensus state itself is not corrupted; the loss is confined to the epoch-0 reward.

### Likelihood Explanation
This triggers deterministically and unconditionally the first time any `EvmHost` instance processes its first authority-set rotation proof — a completely normal, permissionless, non-adversarial code path (any relayer submitting the first valid consensus proof hits it). It requires no malicious peer, prover, relayer, or governance actor, and no crafted input — it is a pure off-by-one/default-collision logic defect that fires on ordinary usage.

### Recommendation
Track whether an epoch has ever been recorded separately from its value (e.g., a `bool _hasEpoch` flag, or initialize `_currentEpoch` to a sentinel like `type(uint256).max` that is impossible for a real epoch, or use `epoch >= _currentEpoch` combined with an explicit "epoch 0 already recorded" guard) so that `epoch == 0` is not conflated with "never set," mirroring the `>=` fix applied to `Factory.sol`'s `latestVersion` check in the referenced report.

### Proof of Concept
1. Deploy a fresh `EvmHost`; `_currentEpoch` defaults to `0`, `_epochs[0] == address(0)`.
2. Relayer R submits the destination chain's first-ever consensus proof that rotates the authority set from genesis (`set 0`) to `set 1`. `IConsensusV2.verify` returns `nextAuthoritySetId == 1`.
3. In `handleConsensus`: `epoch = 1 - 1 = 0`; `host.currentEpoch() == 0`; `epoch > host.currentEpoch()` is `0 > 0` → `false` → `recordEpoch` is skipped.
4. `_epochs[0]` remains `address(0)` forever (no future call can set it: subsequent rotations only ever raise `_currentEpoch` further via `epoch = nextAuthoritySetId - 1 >= 1`, never revisiting `0`).
5. Relayer R (or anyone) calls Hyperbridge's `claim_outbound_consensus_delivery_reward` with `set_id = 0` for this destination; `decode_epochs_slot_address` decodes the proven zero-address slot and returns `None`, so the call reverts with `OutboundDeliveryNotProven` — permanently, since step 4 can never be reversed.     function handleConsensus(IHost host, bytes calldata proof) external notFrozen(host) {
        uint256 delay = block.timestamp - host.consensusUpdateTime();
        if (delay >= host.unStakingPeriod()) revert ConsensusClientExpired();

        bytes memory previousState = host.consensusState();
        (bytes memory verifiedState, IntermediateState[] memory intermediates, uint256 nextAuthoritySetId) =
            IConsensusV2(host.consensusClient()).verify(previousState, proof);

        if (keccak256(previousState) == keccak256(verifiedState)) return;
        host.storeConsensusState(verifiedState);

        uint256 intermediatesLen = intermediates.length;
        for (uint256 i = 0; i < intermediatesLen; i++) {
            IntermediateState memory intermediate = intermediates[i];
            uint256 latestHeight = host.latestStateMachineHeight(intermediate.stateMachineId);
            if (latestHeight != 0 && intermediate.height > latestHeight) {
                StateMachineHeight memory stateMachineHeight =
                    StateMachineHeight({stateMachineId: intermediate.stateMachineId, height: intermediate.height});
                host.storeStateMachineCommitment(stateMachineHeight, intermediate.commitment);
            }
        }

        // `nextAuthoritySetId` identifies the upcoming set; the relayer that delivered the proof
        // is credited as the relayer for the just-ended epoch (`nextAuthoritySetId - 1`).
        // If `nextAuthoritySetId == 0` no rotation has occurred, so there is nothing to record.
        if (nextAuthoritySetId == 0) return;
        uint256 epoch = nextAuthoritySetId - 1;
        if (epoch > host.currentEpoch()) {
            host.recordEpoch(epoch, _msgSender());
        }
    }

        if (authoritySetId <= _currentEpoch) return;
        _currentEpoch = authoritySetId;
        _epochs[authoritySetId] = relayer;
        emit NewEpoch({authoritySetId: authoritySetId, relayer: relayer});
