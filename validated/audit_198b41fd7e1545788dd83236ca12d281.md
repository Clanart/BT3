### Title
`get-asset-price` prices `stSTXbtc`/`zstSTXbtc` using the STX Pyth feed instead of the BTC Pyth feed - ([File: mainnet/contracts/utility/v0-1-data.clar])

### Summary
`get-asset-price` in `v0-1-data.clar` resolves the USD price of `stSTXbtc` and `zstSTXbtc` by calling `get-pyth-price PYTH-STX`, even though the surrounding comments and the asset's semantics ("BTC price") indicate it should use `PYTH-BTC`. This is the same class of bug reported for `AttestationIndexer.sol` (a hardcoded identifier constant that was copy-pasted from the wrong sibling case), except here the wrong identifier feeds directly into the protocol's core collateral/debt USD valuation used for health checks.

### Finding Description
`get-asset-price` computes USD values for every asset type used in collateral/debt accounting: [1](#0-0) 

```clarity
;; stSTXbtc - BTC price (liquid staked STX with BTC yield)
(if (is-eq aid stSTXbtc) (default-to u0 (get-pyth-price PYTH-STX))
;; zstSTXbtc - stSTXbtc price x liquidity index
(if (is-eq aid zstSTXbtc)
    (let ((btc-price (default-to u0 (get-pyth-price PYTH-STX)))
          (lindex (get-vault-liquidity-index stSTXbtc)))
      (mul-div-down btc-price lindex INDEX-PRECISION))
;; Unknown asset - return 0
u0)))))))))))))
```

Both branches call `get-pyth-price PYTH-STX`, and even name the local binding `btc-price`, confirming the intent was to call `PYTH-BTC` (the constant correctly used for `sBTC`/`zsBTC` two branches earlier at line 544/561). `stSTXbtc` and its receipt token `zstSTXbtc` are described everywhere else (comments, vault name `v0-vault-ststxbtc`) as BTC-denominated assets, so they must be priced off `PYTH-BTC`, not `PYTH-STX`. [2](#0-1) 

This price feed function is the same one used for both collateral valuation (`sum-collateral-usd`) and debt valuation (`sum-debt-usd`), which drive every health-factor and liquidation decision in the market: [3](#0-2) [4](#0-3) 

### Impact Explanation
STX and BTC trade at wildly different price levels (BTC price >> STX price). Using the STX feed for a BTC-denominated asset drastically **understates** the USD value of any `stSTXbtc`/`zstSTXbtc` position:

- As **debt**: A borrower who takes on `stSTXbtc` debt has their real (BTC-scale) liability priced as if it were STX-scale, so the health check drastically understates their debt-to-collateral ratio. The borrower can withdraw far more real value than the protocol's accounting reflects, leaving the vault holding real BTC-denominated debt that is unbacked once the mispricing is corrected or the position is unwound — protocol insolvency / bad debt.
- As **collateral**: The reverse effect (undervaluing collateral) mainly restricts legitimate users, but combined with the debt-side effect, an attacker can structure a position that maximizes borrowing of other, correctly priced assets against understated `stSTXbtc`/`zstSTXbtc` debt exposure, or extract value from the vault before liquidation logic (which relies on the same mispriced value) can react correctly.

This lands squarely on the in-scope **Critical** impact class: protocol insolvency / theft of funds at rest via undercollateralized borrowing, since liquidation thresholds and LTV checks are computed on the wrong (STX-scale) USD value for a BTC-scale asset.

### Likelihood Explanation
This is not a hypothetical config issue or third-party oracle problem — it is a hardcoded constant bug in the pricing function itself (`PYTH-STX` instead of `PYTH-BTC`), reachable any time `stSTXbtc` or `zstSTXbtc` is enabled as a collateral or debt asset in the `v0-assets`/DAO asset registry (a standard supported configuration per the vault contract `v0-vault-ststxbtc.clar`, not an "accidental" registry misconfiguration). Every call to health checks, borrow, liquidation, or interest accrual for this asset triggers the mispriced code path deterministically.

### Recommendation
Change both occurrences of `get-pyth-price PYTH-STX` in the `stSTXbtc` and `zstSTXbtc` branches of `get-asset-price` (lines 582 and 585) to `get-pyth-price PYTH-BTC`, matching the pattern already used correctly for `sBTC`/`zsBTC`.

### Proof of Concept
1. DAO registers `stSTXbtc` (or `zstSTXbtc`) as a debt-enabled asset in `v0-assets`.
2. Attacker supplies correctly priced collateral (e.g., USDC).
3. Attacker borrows `stSTXbtc` up to the amount that `get-asset-price` (using the STX feed) reports as within the LTV limit — but because BTC price >> STX price, this quantity is actually worth far more in real USD terms than the health check believes.
4. Health check (`sum-debt-usd`) passes since it under-prices the debt using `PYTH-STX`.
5. Attacker withdraws/holds the real BTC-value `stSTXbtc` while the protocol's books show a tiny debt — resulting in bad debt for the vault once true value is realized (e.g., during liquidation attempts, which will also mis-price using the same buggy function).
