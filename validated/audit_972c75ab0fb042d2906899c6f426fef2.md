### Title
Unvalidated Mirror/Subscription URLs Enable SSRF via DataLayer HTTP Downloader - ([File: chia/data_layer/download_data.py])

### Summary
Any DataLayer store owner can publish a `mirror` coin (or any client can register a `subscribe` server URL) containing an arbitrary, attacker-chosen HTTP(S) URL. This URL is later dereferenced automatically by every other Data Layer node that subscribes to (or mirrors/replicates) that store, with no validation that the URL does not point to internal/private network resources — the same bug class as CVE-2021-39195 ("Upload from URL"/attachment SSRF in Misskey).

### Finding Description
`DataLayerRpcApi.add_mirror()` and `DataLayerRpcApi.subscribe()` accept a raw `urls: list[str]` field from the caller with no host/scheme allow-listing: [1](#0-0) [2](#0-1) 

`add_mirror` pushes these URLs on-chain via `dl_new_mirror`, i.e. they become publicly visible/replicated data attached to the store's mirror coin: [3](#0-2) 

Any other Data Layer node that later subscribes to that store (`update_subscriptions_from_wallet`) picks these attacker-controlled URLs directly from the chain-registered mirrors and stores them as candidate server URLs: [4](#0-3) 

During normal sync, `fetch_and_validate()` randomly selects one of these server URLs and calls `insert_from_delta_file()`/`http_download()` on it — an unauthenticated, attacker-influenced network request issued by the victim node itself: [5](#0-4) 

The actual HTTP request is made with `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` with no restriction on scheme, host, or IP range (no blocking of loopback, link-local/metadata addresses such as `169.254.169.254`, or RFC1918 ranges): [6](#0-5) 

The design notes even acknowledge that mirror/plugin URLs are "external trust inputs," but only downstream data content is verified against wallet-advertised roots — the destination of the outbound HTTP request itself is never validated: [7](#0-6) 

### Impact Explanation
Because mirror URLs are propagated on-chain and consumed automatically by every peer's Data Layer service that subscribes to the store, a single unprivileged store owner can force arbitrary remote Data Layer nodes to issue outbound HTTP(S) requests to internal-only hosts (localhost services, cloud metadata endpoints, internal RPC/administrative ports, etc.) that would otherwise be unreachable from the public internet. This is a server-side request forgery against every subscribing node's internal network, matching the reachable-impact class required (internal-network disclosure / request forgery from an unprivileged spend/RPC-adjacent action), even though downloaded content is separately hash-verified before being trusted as tree data.

### Likelihood Explanation
Likelihood is high: creating a store, adding a mirror with an attacker URL, and having any peer subscribe/replicate the store is a normal, unprivileged Data Layer workflow (`add_mirror`, `subscribe` RPCs), requiring no elevated permissions beyond running a Data Layer client and paying a fee for the mirror coin.

### Recommendation
Validate and restrict destination URLs before they can be persisted as mirror/subscription server URLs and before `http_download()`/`download_file()` dereferences them — e.g., enforce an allow-listed scheme (http/https), resolve and reject loopback/link-local/private/multicast/metadata IP ranges (with re-validation after DNS resolution to prevent DNS-rebinding), and make this policy configurable/opt-in for trusted deployments. Apply the same validation to plugin `downloader.url` and S3 plugin `url` fields.

### Proof of Concept
1. Attacker creates a Data Layer store and calls `add_mirror` (or `subscribe`) with `urls=["http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<internal-port>/...`).
2. The mirror coin/subscription URL is committed on-chain / stored locally.
3. A victim node later calls `subscribe`/`update_subscriptions_from_wallet` for the same store id, ingesting the attacker URL as a `ServerInfo`.
4. On the next sync cycle, `DataLayer.fetch_and_validate()` selects that server and `http_download()` issues `GET http://169.254.169.254/latest/meta-data/...` from the victim's process, probing/interacting with internal-only services.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
