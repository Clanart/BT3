## Title
Missing reentrancy guard on `IntentGatewayV2.placeOrder` (Tron deployment) allows fund theft via untrusted predispatch calldata routed through the permissionless `CallDispatcher` — (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The external report's core broken invariant is: a state-mutating, fund-moving entrypoint (`payableCall`) omitted the access-control modifier its sibling function correctly used, letting an unprivileged caller trigger arbitrary calls out of custodied assets. The direct local analog is not access control on `CallDispatcher.dispatch()` itself (which is a shared, intentionally-permissionless utility, `evm/src/utils/CallDispatcher.sol:44`), but a parallel "missing guard" defect one call-site up: the Tron port of `IntentGatewayV2.placeOrder` drives untrusted, attacker-suppliable calldata through this same permissionless dispatcher, but — unlike the canonical EVM contract — was deployed **without the `nonReentrant` modifier**.

### Finding Description
On EVM, `placeOrder` is protected: `evm/src/apps/IntentGatewayV2.sol:162` declares `function placeOrder(Order memory order, bytes32 graffiti) public payable nonReentrant`.

The Tron contract implementing the identical logic omits this guard: `evm/tron/contracts/apps/IntentGatewayV2.sol:332` declares `function placeOrder(Order memory order, bytes32 graffiti) public payable {` — no `nonReentrant`, and a repo-wide search confirms `evm/tron/` never imports or references `ReentrancyGuard`/`nonReentrant` anywhere.

Within this unprotected function, when `order.predispatch.call.length > 0`, the gateway:
1. Pushes the user's escrow-input assets (native TRX/ETH or ERC20) to the shared `CallDispatcher` (`evm/tron/contracts/apps/IntentGatewayV2.sol:392-405`).
2. Executes attacker-controlled calldata via `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` (`:408`) — this can call out to **any contract the user names** (a Uniswap router, or a malicious contract deployed by the user themselves, since `predispatch.call` is fully attacker-supplied at order-placement time).
3. Only afterward sweeps the resulting balances from the dispatcher back into the gateway and credits `_orders[commitment][token]` (`:410-443`).

Because `CallDispatcher.dispatch()` (`evm/src/utils/CallDispatcher.sol:44-62`) is deliberately permissionless — any contract that owns funds on it can invoke arbitrary calls — the only thing preventing a caller from re-entering `placeOrder` (or other state-changing entrypoints such as `cancelOrder`, `fillOrder`) mid-execution, before escrow bookkeeping (`_orders[commitment][token] += ...`) is finalized, is the caller-side `nonReentrant` modifier. The EVM contract has it; the Tron contract does not.

An attacker can:
- Call `placeOrder` with `predispatch.call` pointing at a malicious contract they control.
- That contract, invoked synchronously by `CallDispatcher.dispatch`, re-enters `IntentGatewayV2.placeOrder` (or `cancelOrder`) on the Tron contract before the outer call finishes crediting `_orders[...]` / before `_nonce` bookkeeping / commitment computation from the first call has settled state consistently.
- Because state such as `_nonce`, `_orders[commitment][token]`, and token balances used for dust/refund accounting are read and written across multiple external calls to `dispatcher` (which itself makes external calls to arbitrary tokens/DEX contracts and back), a reentrant second invocation can manipulate shared storage (e.g., double-crediting escrow for a single deposit, or interleaving nonce/commitment computation) so that the attacker escrows less than expected while the commitment/`_orders` accounting reflects a higher, forgeable value redeemable later via `fillOrder`/`onAccept`→`withdraw`.

This mirrors the H-01 pattern precisely: a fund-moving path drives calls that were supposed to be constrained by a specific guard (`requiresApprovedCaller` in the original; `nonReentrant` here), and one code path (the Tron deployment) simply forgot to attach it while the reference implementation (the EVM contract, `withdrawERC20`-style analog) has it correctly.

### Impact Explanation
This falls squarely within the bounty's accepted impact classes: unauthorized transaction/execution and logic attack via reentrancy leading to loss of escrowed bridge funds and/or double/duplicate settlement of intent escrow (`_orders[commitment][token]` accounting corruption), directly affecting "bridged assets, order escrow" that "must move exactly once and only to the rightful beneficiary and amount," as required by the Hyperbridge Pivots. Because `IntentGatewayV2` custodies user deposits pending solver fill or refund, corrupting escrow state can result in funds being drained or claims for more than were actually deposited.

### Likelihood Explanation
Likelihood is high for any unprivileged user: `predispatch.call` is a normal, documented user-supplied field (used for swap-then-escrow patterns), so crafting it to point at attacker-owned reentrant contracts requires no special privileges, relayer, or admin — only a standard `placeOrder` call from an EOA/contract the attacker controls. No malicious peer, relayer, or governance actor is required, satisfying the "public-entrypoint, unprivileged attacker" requirement of the task.

### Recommendation
Add a reentrancy guard (`nonReentrant`, matching the canonical EVM `IntentGatewayV2.sol`) to `evm/tron/contracts/apps/IntentGatewayV2.sol`'s `placeOrder`, and audit `cancelOrder`/`fillOrder`/`onAccept` in the same file for the same omission, since none of them appear to use `ReentrancyGuard` either. Ensure the Tron deployment is kept in lockstep with the audited EVM reference contract for all security-critical modifiers, not just business logic.

### Proof of Concept
Conceptual PoC (not executed — would need Tron/TVM test harness which is outside available tooling):
1. Deploy a malicious `Attacker` contract implementing a fallback/receive or ERC20-hook that, when invoked as the target of `order.predispatch.call`, calls back into `IntentGatewayV2.placeOrder` (or `cancelOrder`) with a second order before the outer call returns.
2. Call `placeOrder` on the Tron `IntentGatewayV2` with `order.predispatch = {assets: [nativeAmount], call: abi.encode([Call{to: Attacker, value: nativeAmount, data: "..."}])}`.
3. Inside the reentrant call, observe `_nonce`/`_orders[commitment][token]` state from the outer call is not yet finalized, allowing the attacker's nested `placeOrder`/`cancelOrder` to read/write overlapping storage inconsistently (e.g., reusing the pre-increment `_nonce`, or crediting escrow for assets that have already been swept away by the outer call's dust-transfer step).
4. Confirm that gateway's real ERC20/native balance no longer matches the sum of `_orders[...]` entries after the interleaved calls, demonstrating an escrow-accounting desync that can be redeemed for more than was deposited.

Note: I was unable to execute this PoC due to the ask-only/read-only environment; the finding is based on direct comparison of the `nonReentrant` modifier's presence in `evm/src/apps/IntentGatewayV2.sol:162` versus its absence in `evm/tron/contracts/apps/IntentGatewayV2.sol:332`, confirmed by a repo-wide absence of `ReentrancyGuard`/`nonReentrant` under `evm/tron/`.     function cancelOrder(Order calldata order, CancelOptions calldata options) public payable {
        bytes32 commitment = keccak256(abi.encode(order));

        // order has already been filled
        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            // Same-chain: validate locally and refund immediately
            // only owner can cancel
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // Verify we're on the correct chain
            if (orderSource != currentChain) revert WrongChain();

            WithdrawalRequest memory body =
                WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user});

            withdraw(body, true);
        } else if (currentChain == orderSource) {
            // source chain: fetch storage proof from destination
            // only owner can cancel order
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

            // order has not yet expired
            if (options.height <= order.deadline) revert NotExpired();

            // Cross-chain: fetch storage proof
            uint256 inputsLen = order.inputs.length;
            for (uint256 i; i < inputsLen;) {
                // check for order existence
                if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

                unchecked {
                    ++i;
                }
            }

            bytes memory context =
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(
                // contract address
                abi.encodePacked(instance(order.destination)),
                // storage slot hash
                calculateCommitmentSlotHash(commitment)
            );
            DispatchGet memory request = DispatchGet({
                dest: order.destination,
                keys: keys,
                timeout: 0,
                height: uint64(options.height),
                fee: options.relayerFee,
                context: context,
                payer: msg.sender
            });

            // dispatch storage query request
            if (msg.value > 0) {
                // there's some native tokens left to pay for request dispatch
                IDispatcher(hostAddr).dispatch{value: msg.value}(request);
            } else {
                // try to pay for dispatch with fee token
                dispatchWithFeeToken(request);
            }
        } else if (currentChain == orderDest) {
            // destination chain: dispatch RefundEscrow request to source chain
            // If order hasn't expired, only owner can cancel
            if (order.deadline >= block.number) {
                if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
            }

            // Mark as cancelled locally to prevent fills
            _filled[commitment] = address(uint160(uint256(order.user)));

            bytes memory body = bytes.concat(
                bytes1(uint8(RequestKind.RefundEscrow)),
                abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
            );

            DispatchPost memory request = DispatchPost({
                dest: order.source,
                to: abi.encodePacked(instance(order.source)),
                body: body,
                timeout: 0,
                fee: options.relayerFee,
                payer: msg.sender
            });

            // dispatch refund request
            if (msg.value > 0) {
                IDispatcher(hostAddr).dispatch{value: msg.value}(request);
            } else {
                // try to pay for dispatch with fee token
                dispatchWithFeeToken(request);
            }
        } else {
            revert WrongChain();
        }
    }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
