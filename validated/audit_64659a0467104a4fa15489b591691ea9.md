### Title
`git commit --amend` during a session lets amended changes bypass `compute_v2_review_set`, hiding dangerous edits from Stop-hook review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`capture_git_baseline` snapshots `HEAD` + uncommitted changes via `git stash create` at `UserPromptSubmit`, and `compute_v2_review_set` later intersects "currently dirty vs HEAD" (`dirty_now`) with "changed vs baseline" (`changed_since`) to build the review set. The `dirty_now` term only picks up committed work when `head_at_capture` is a linear ancestor of the current `HEAD`; a plain `git commit --amend` breaks that ancestor relationship, so a dangerous edit committed via amend is silently excluded from `review_set` even though `changed_since` (diff vs. baseline) would show it.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163`) records the pre-turn tree state as a stash SHA, and `handle_user_prompt_submit` (`security_reminder_hook.py:446`) stores it plus `head_at_capture = _git_rev_parse_head(cwd)`.

At Stop, `compute_v2_review_set` (`diffstate.py:353`) builds:
- `dirty_now = tracked_dirty | new_untracked` from `git status --porcelain` against current `HEAD` [1](#0-0) 
- If `head_at_capture` differs from current `HEAD` **and** `_is_ancestor(head_at_capture, current_head)` holds, `dirty_now` is unioned with `_git_name_only(repo, f"{head_at_capture}..HEAD")` and `diff_base` becomes `head_at_capture` [2](#0-1) 
- `changed_since = _git_name_only(repo, baseline_sha)` — files differing from the pre-turn stash baseline [3](#0-2) 
- `review_set = dirty_now & changed_since` (only intersected when `changed_since` isn't `None`) [4](#0-3) 

`git commit --amend` replaces the tip commit rather than advancing linearly from it: the new `HEAD` and `head_at_capture` share the same parent, so `head_at_capture` is **not** an ancestor of the new `HEAD` (`_is_ancestor` in `gitutil.py:377` returns `False`). The special "commits landed" branch is therefore skipped, `diff_base` stays `"HEAD"`, and — because the working tree is clean right after the amend — `git status --porcelain` reports no tracked dirt, so `dirty_now` is empty (or contains only unrelated untracked files). Since `review_set = dirty_now & changed_since`, an empty `dirty_now` zeroes out the review set for the amended file even though `changed_since` (diff against `baseline_sha`) would correctly show it as changed. The dangerous change committed via `--amend` is thus dropped from `review_paths` and never reaches the LLM diff review or the Stop-hook enforcement path.

This is reachable purely through "normal git operations": a session that edits a file, commits it, then runs `git commit --amend` to rewrite that same commit (a routine developer workflow, and one an attacker-controlled repo/prompt-injection could nudge Claude toward, e.g. "please tidy up your last commit message/amend it") ends up with the amended dangerous content unreviewed. No admin/maintainer privilege, leaked keys, or malicious tooling is required — just ordinary `git commit`/`git commit --amend` sequencing inside the cloned repo, which is explicitly within the declared attacker capability.

### Impact Explanation
The Stop-hook LLM review (`analyze_code_security`/`agentic_review`) and the pattern-based warnings are the plugin's core enforcement mechanism for catching vulnerabilities Claude introduces (hardcoded secrets, injection, unsafe deserialization, etc.). If the dangerous edit is silently excluded from `review_set`, the file is never diffed to the reviewer and the Stop hook cannot flag it or force `exit(2)` remediation. A vulnerable change (e.g. one that exfiltrates secrets/tokens/diff content to an attacker-controlled sink) introduced via commit+amend persists in the repo unreviewed, directly matching the stated impact class: sensitive code/prompt/token/diff/local-file disclosure to an unintended sink, because the security gate that should have caught and blocked it never sees the change.

### Likelihood Explanation
- Preconditions: a git repo with at least one commit (baseline capture requires `HEAD`), and a session where Claude (i) edits a file, (ii) commits it, then (iii) amends that commit — a very common, non-privileged sequence that requires no special access.
- Feasibility: purely deterministic git mechanics (`merge-base --is-ancestor` correctly reports `False` for amended commits since they are siblings, not descendants, of the pre-amend commit) — this isn't a race condition, it fires every time an amend is the operation that introduces/finalizes the dangerous change.
- Repeatability: 100% reproducible with the exact commit→amend sequence; no timing dependency.

### Recommendation
In `compute_v2_review_set`, don't gate the "commits landed" union solely on `_is_ancestor(head_at_capture, current_head)`. Additionally detect the amend case (e.g., via reflog: `HEAD@{0}`'s reflog subject starts with `commit (amend)`, similar to the existing `_resolve_amend_pre_sha` helper already used for commit-review) and, when detected, diff against the pre-amend SHA (`HEAD@{1}`) instead of only current `dirty_now`. More generally, when `head_at_capture != current_head` and it is *not* a simple ancestor relationship, fall back to unioning `dirty_now` with `_git_name_only(repo, head_at_capture)` (a direct diff between the captured HEAD and current HEAD) rather than silently keeping `diff_base = "HEAD"` with an empty `dirty_now` contribution — this covers amend, rebase, and reset-then-recommit cases uniformly.

### Proof of Concept
Unit/integration test in the existing test suite for `compute_v2_review_set`:
1. Init a temp git repo, commit an initial safe file, capture `baseline_sha = capture_git_baseline(cwd)` and `head_at_capture = _git_rev_parse_head(cwd)`.
2. Write a dangerous line into a tracked file (e.g. `os.system(user_input)`), `git add` + `git commit -m "add feature"`.
3. Run `git commit --amend --no-edit` (simulating a routine amend of the same commit, no content change needed to trigger the bug — or optionally add more dangerous content in the amend).
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert: expected/desired behavior — the dangerous file path is present in the returned `review_paths`.
6. Actual behavior (bug): `review_paths` is empty (or missing the dangerous file), because `dirty_now` is empty and `diff_base` remained `"HEAD"` — demonstrating the review set is not bound to the amended dangerous change, violating the stated invariant.
