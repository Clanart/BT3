Based on tracing `record_touched_path` through to its consumer `compute_v2_review_set`, I found a real logic gap tied to non-linear HEAD movement (e.g. `git commit --amend`, rebase, filter-branch), which matches the "commit, amend" scenario called out in the question's validation guidance.

### Title
Non-ancestor HEAD advancement (git amend/rebase) drops committed dangerous changes from the v2 review set - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only folds committed changes into the reviewed set when `head_at_capture` is a strict ancestor of the current HEAD [1](#0-0) . Any ordinary git operation that rewrites history during a turn (`git commit --amend`, rebase, `reset --hard` + recommit, cherry-pick with a different parent) breaks that ancestor relationship, so the newly-committed dangerous file is excluded from `dirty_now` and consequently from `review_set = dirty_now & changed_since`, even though `changed_since` (diff vs. the stash baseline) still contains it.

### Finding Description
`record_touched_path` (`plugins/security-guidance/hooks/diffstate.py:57`) simply appends any file path touched via `Edit`/`Write`/`MultiEdit` to session state [2](#0-1) ; this touched_paths list is largely redundant with git state, since the Stop hook actually derives what to review from `compute_v2_review_set`, not from `touched_paths` directly (per its own docstring: "review_set = derive from git state alone") [3](#0-2) .

The bug is in that derivation. `dirty_now` starts from `git status --porcelain` (tracked-dirty + new-untracked) and is only unioned with the committed-diff term `head_at_capture..HEAD` when `_is_ancestor(repo, head_at_capture, current_head)` holds [1](#0-0) . If a turn does: edit dangerous file → `git commit` → `git commit --amend` (or any rebase/rewrite), the final HEAD is not a descendant of `head_at_capture` in the simple linear sense expected, so this union is skipped. Since the file is now committed (clean working tree), it is absent from `git status --porcelain` too, so `dirty_now` ends up **not containing the dangerous file at all**. The final `review_set = dirty_now & changed_since` intersects with the empty set for that path and drops it, even though `changed_since` (`_git_name_only(repo, baseline_sha)`, diffed against the pre-turn stash) correctly still lists it as changed [4](#0-3) .

The consumer, `handle_stop_hook`, trusts this review set completely: if `review_paths` is empty for that file it never appears in `diff_files`, is never sent to `analyze_code_security`, and the Stop hook exits 0 as "no security issues found" instead of exit(2) forcing Claude to fix it [5](#0-4) . `record_touched_path`'s list is not used as a fallback safety net for this case — it's only consulted for metrics/telemetry, not to force files back into the diff.

### Impact Explanation
This breaks the plugin's core enforcement invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a dangerous change that is genuinely new since the turn's baseline can be silently excluded from review by nothing more than an ordinary `git commit --amend` or rebase performed during the same turn (by Claude itself, a subagent, or a repo-provided git hook/Makefile that runs `git commit --amend` as part of a normal build/lint step). Because the Stop hook is the mechanism that forces Claude to continue and remediate flagged vulnerabilities (`sys.exit(2)` + guidance text) [6](#0-5) , a review-set that silently omits the dangerous file means that mandatory-fix gate never fires — the equivalent of the plugin's deny/must-fix control being bypassed for that specific change, letting an unreviewed dangerous edit reach disk/history without triggering the fix-loop.

### Likelihood Explanation
Fully repeatable and requires no special privilege: any sequence of `git commit` followed by `git commit --amend` (or rebase/cherry-pick that produces a non-ancestor HEAD) within one Claude Code turn triggers it. This can occur from completely ordinary developer/agent workflow (fixing a commit message, squashing) or be nudged via prompt injection embedded in repo content (e.g. a README/AGENTS.md instructing "always amend your last commit before finishing"), with no admin/maintainer/credential requirement.

### Recommendation
Don't gate the committed-diff term on strict ancestry. When `head_at_capture != current_head` and ancestry fails (history rewritten), fall back to unioning `dirty_now` with the full symmetric diff between `head_at_capture` and current `HEAD` (e.g. `git diff --name-only head_at_capture...HEAD` or comparing tree objects directly) rather than skipping the term entirely. Alternatively, always union `dirty_now` with `changed_since` instead of intersecting when non-linear history is detected, so a file present in `changed_since` is never silently dropped just because it is currently clean in the working tree.

### Proof of Concept
Integration test in the existing diffstate/hook test suite:
1. Init a temp git repo, create `HEAD` commit.
2. Call `capture_git_baseline(cwd)` to get `baseline_sha`, record `head_at_capture = git rev-parse HEAD`.
3. Write a dangerous pattern into `vuln.py`, `git add`, `git commit -m "add vuln"`.
4. Run `git commit --amend -m "add vuln (amended)"` (or `git rebase -i` no-op) so new `HEAD` is not a descendant of `head_at_capture` via simple ancestry (amend always breaks strict ancestor check against the pre-amend commit's child relationship — verify with `_is_ancestor`).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. Assert `vuln.py` (absolute path) is present in the returned `review_paths` — expected to FAIL currently (file silently dropped), demonstrating the bypass.

def record_touched_path(session_id, file_path):
    """Append a file path to the touched_paths list (deduped, capped at 200).

    Stop is the consumer and clears under the same lock it reads with; UPS
    no longer wipes. The cap is a defensive bound for sessions where Stop
    never fires (disabled mid-session, abort) — git diff naturally filters
    stale paths so over-retention is harmless, just wasteful.
    """
    def _record(state):
        paths = state.setdefault("touched_paths", [])
        if file_path not in paths:
            paths.append(file_path)
            if len(paths) > 200:
                del paths[:len(paths) - 200]
    with_locked_state(session_id, _record)
