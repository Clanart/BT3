### Title
Gasless SwapTx admission relies on live, single-block-manipulable DEX reserve pricing (`GetAmountIn`) - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless (meta-transaction) module admits a user-submitted `SwapTx` into the tx pool and, later, executes it on-chain by trusting a spot-price quote (`GetAmountIn`) fetched live from the `GaslessSwapRouter` contract, which is backed by a Uniswap-V2-style DEX pair. Exactly like ElevateFi's `getPriceUSD()` reading raw pair reserves, an attacker can transiently distort the pair's reserves within the same block/bundle to manipulate the returned quote, letting an undercollateralized `SwapTx` satisfy the sponsor-repayment check.

### Finding Description
`checkBalanceForSwap` validates a gasless `SwapTx` by calling the router's live view function to determine how much input token is required for the user's declared `MinAmountOut`: [1](#0-0) 

The comment above the function states the invariant the module relies on: [2](#0-1) 

`GetAmountIn` is a live call into the `GaslessSwapRouter` contract (`kip247` bindings), which is deployed on top of a Uniswap-V2-compatible DEX (factory/router/pair), as shown by the integration test that wires a `GaslessSwapRouter` to `UniswapV2Factory`/`UniswapV2Router02` pairs and drives the sponsor-repayment flow (`ammontRepay`, `minAmountOut`, `swapExpectedOutput`) directly off `GetAmountsOut`/reserve-derived pricing: [3](#0-2) 

Uniswap-V2-style reserves (`getReserves`, `quote`, `getAmountsOut`/`getAmountsIn`) are computed purely from the two token balances held by the pair contract at call time, with no TWAP or external oracle protection, as evidenced by the vendored router/pair bindings: [4](#0-3) [5](#0-4) 

Because `GetAmountIn` is queried fresh — both at tx-pool admission time (`checkBalanceForSwap`) and presumably again by the on-chain router at execution — any actor who can shift the pair's reserves immediately before the `SwapTx` executes (e.g., via a preceding transaction/bundle entry that trades against the same pair) changes the quoted `requiredAmountIn` for the attacker's declared `MinAmountOut`. This mirrors the ElevateFi bug class: a price computed directly from spot AMM reserves is used to gate value transfer (there: staking-package sizing; here: minimum acceptable `AmountIn` for a gasless swap that must cover `AmountRepay`, the gas-sponsor's fee).

### Impact Explanation
If an attacker can push the pair's reserves so that `GetAmountIn(token, minAmountOut)` returns an artificially low value, they can submit a `SwapTx` with an `AmountIn` that is insufficient at the pair's undistorted/fair price but still passes the `swapArgs.AmountIn.Cmp(requiredAmountIn) < 0` check. If the swap subsequently executes (either before reserves revert, or if the router itself computes the actual swap price from the same manipulated reserves at execution), the gasless relayer/sponsor is repaid `AmountRepay` in output tokens whose real market value is less than what was fronted for gas, resulting in fee-delegation/gasless-sponsorship value loss — a direct value-extraction/theft analogous to ElevateFi's underpriced package stakes.

### Likelihood Explanation
Likelihood is moderate-to-high for an unprivileged actor: the `SwapTx`/`ApproveTx` bundle mechanism explicitly allows sequencing of the user's own transactions in the pool (`IsBundleTx`, `isSwapTxReady`), and nothing in `checkBalanceForSwap` or the visible execution path re-checks the quote against a manipulation-resistant reference price (e.g., TWAP) or requires atomicity guarantees preventing a same-block reserve shift between the pool-admission check and on-chain settlement. However, without the on-chain `GaslessSwapRouter.sol` source (only Go bindings were indexed), it is not fully confirmed whether the router performs its own real-time reserve read at settlement (compounding the issue) or instead settles using a value snapshotted earlier in a way that would make this unexploitable; this should be verified against the actual contract source before treating this as conclusively exploitable.

### Recommendation
- Have `GaslessSwapRouter.getAmountIn`/execution-time pricing use a manipulation-resistant price source (TWAP, oracle, or a reserve snapshot taken atomically with sponsor repayment) rather than instantaneous pair reserves.
- Re-validate `AmountIn` against the actual on-chain swap output at execution time (not just at tx-pool admission), and revert if slippage/manipulation caused an under-collateralized repayment.
- Consider bounding per-block reserve deviation or requiring the gasless swap and any reserve-affecting trade to be mutually exclusive within a block/bundle.

### Proof of Concept
Not fully constructible from the indexed files: the `GaslessSwapRouter.sol` source (pricing/settlement logic) was not present in the index — only its Go bindings (`contracts/bindings/kip247/GaslessSwapRouter.go`) were available, so the exact on-chain settlement path could not be directly inspected. A conclusive PoC would require: (1) deploying/registering a `GaslessSwapRouter` over a Uniswap-V2 pair as in `tests/gasless_test.go`, (2) submitting a transaction that shifts the pair's reserves, (3) immediately submitting a `SwapTx` bundle exploiting the resulting `GetAmountIn` distortion, and (4) confirming the sponsor/relayer receives less value than `AmountRepay` should represent at the fair price.

func (_UniswapV2Pair *UniswapV2PairCaller) GetReserves(opts *bind.CallOpts) (struct {
	Reserve0           *big.Int
	Reserve1           *big.Int
	BlockTimestampLast uint32
}, error,
) {
	var out []interface{}
	err := _UniswapV2Pair.contract.Call(opts, &out, "getReserves")

	outstruct := new(struct {
		Reserve0           *big.Int
		Reserve1           *big.Int
		BlockTimestampLast uint32
	})
	if err != nil {
		return *outstruct, err
	}

	outstruct.Reserve0 = *abi.ConvertType(out[0], new(*big.Int)).(**big.Int)
	outstruct.Reserve1 = *abi.ConvertType(out[1], new(*big.Int)).(**big.Int)
	outstruct.BlockTimestampLast = *abi.ConvertType(out[2], new(uint32)).(*uint32)

	return *outstruct, err
}
