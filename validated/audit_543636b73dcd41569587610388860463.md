### Title
Data Layer mirror URLs are unauthenticated SSRF vectors — outbound HTTP fetches to attacker-chosen hosts with no internal/metadata-IP blacklist - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can publish a "mirror" coin for **any** DataLayer store's `launcher_id` — including stores they do not own — containing arbitrary URLs. Every node that subscribes to that store id (a normal, permissionless DataLayer client action) will periodically pull all published mirror URLs and issue outbound `aiohttp` GET requests to them via `http_download()`, with no validation that the host is not a link-local/private/cloud-metadata address. This is directly analogous to the CC-Tweaked SSRF (CVE-2023-37262): a low-privilege actor supplies a URL that a service unconditionally fetches, and cloud metadata endpoints (e.g. `169.254.169.254`) are not blacklisted by default.

### Finding Description
- `DataLayerWallet.create_new_mirror()` / RPC `dl_new_mirror` lets any wallet spend a coin that publishes a `Mirror` (launcher_id, urls) on-chain. There is no check that the caller owns or controls the target `launcher_id` — the mirror mechanism is designed to let third parties announce mirrors for stores they don't own [1](#0-0) .
- When any coin is created with `create_mirror_puzzle()`'s puzzle hash, `DataLayerWallet.coin_added()` decodes the URLs from the spend and stores the mirror if the `launcher_id` is a tracked store — regardless of who created it or whether it's "ours" — via `dl_store.add_mirror(...)` [2](#0-1) .
- `DataLayer.get_mirrors()`/`update_subscriptions_from_wallet()` collects **all** mirror URLs for a subscribed store (not filtered to `ours=True`) and feeds them into the local subscription table used for downloads [3](#0-2) .
- `DataLayer.fetch_and_validate()` picks a random server URL from that set and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs `session.get(server_info.url + "/" + filename, ...)` with **no scheme/host validation, no private-network or link-local blocklist, and no restriction on the URL's target** [4](#0-3) ; the calling loop in `fetch_and_validate()` shows the URL is taken straight from `server_info.url` without any filtering [5](#0-4) .
- The `.cursor/context/data-layer.md` design notes explicitly acknowledge mirror/plugin URLs are untrusted inputs for *data* integrity, but nothing in the code enforces destination-IP restrictions for the *request itself* [6](#0-5) .

Any Data Layer client subscribing to a store is thus forced to make an outbound HTTP request to a URL fully controlled by an arbitrary unprivileged chain participant (the mirror publisher), with no SSRF protections. If the Data Layer service runs on a cloud VM (AWS/GCP/Azure), the attacker can set the mirror URL to the instance metadata service address to have the victim node fetch and (partially) expose metadata-service response behavior (timing, error differences, or content indirectly logged), or pivot the request to internal-only network services reachable from the host.

### Impact Explanation
This is a genuine SSRF primitive reachable by an unprivileged, on-chain actor (anyone who can spend a small amount of XCH to create a mirror coin) against any subscriber's Data Layer node. Impact:
- Outbound requests to cloud metadata endpoints or other internal-only services from the victim's infrastructure, which is the exact bug class in the referenced CVE.
- Potential internal network reconnaissance/pivoting via the Data Layer service acting as an unauthenticated request proxy.
- No direct fund loss/consensus divergence is proven here, so this sits below "Critical" chain-safety bugs, but it is a legitimate Medium/High-severity SSRF given the given bug-class hint and reachable, unprivileged trigger.

### Likelihood Explanation
High likelihood of reachability: creating a mirror for any store requires no ownership of that store (only a fee-paying spend), and any node that subscribes to that store (a common, expected DataLayer client action) will automatically fetch all published mirrors' URLs on a periodic loop (`periodically_manage_data()`/`update_subscription()`), with randomized server selection [7](#0-6) . No user interaction beyond normal subscription is required once a malicious mirror is confirmed on-chain.

### Recommendation
- Validate resolved mirror/server URLs before requesting them in `http_download()`/`download_file()`: reject link-local (169.254.0.0/16), loopback, private RFC1918 ranges, and other non-routable/metadata addresses unless explicitly allowed by local configuration (mirroring the CC-Tweaked fix pattern of a default-deny address predicate).
- Consider requiring DNS resolution + IP check at request time (to prevent DNS-rebinding bypass of a hostname-based blocklist).
- Optionally restrict mirror URL fetches to `https://` and known non-local schemes, and allow operators to opt into private-network mirrors explicitly via config for local/dev use.

### Proof of Concept
1. Attacker (unprivileged wallet) calls `dl_new_mirror` / `chia data add_mirror` for a victim's `launcher_id` (a store the attacker does not own) with `urls=["http://169.254.169.254/latest/meta-data/"]` (or any internal target) and pushes the transaction — confirmed by `test_mirrors` showing `add_mirror` accepts arbitrary URLs for a store id without ownership checks [8](#0-7) .
2. Once confirmed, any victim node that is subscribed to (or later subscribes to) that same `launcher_id` picks up this mirror via `update_subscriptions_from_wallet()` and treats it as an eligible download server.
3. On the victim's next `fetch_and_validate()` cycle, `http_download()` performs `session.get("http://169.254.169.254/latest/meta-data/" + filename, ...)` from the victim's own network context, with no blocklist preventing the request [4](#0-3) .

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
