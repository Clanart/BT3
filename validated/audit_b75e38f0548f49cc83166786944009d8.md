Based on the code I was able to verify, here is the strongest local analog to the FloodPlain access-control bypass.

### Title
`CallDispatcher.dispatch` has no caller restriction, allowing anyone to drain any token balance left on the shared dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
The FloodPlain report's core flaw is that a contract meant to execute privileged, order-bound calldata (`preHooks`/`postHooks`) performs no binding/authorization on who may trigger it or what it may act upon, letting an attacker invoke the hook execution path directly and redirect funds. The IntentGateway's `CallDispatcher` — the contract that executes attacker-supplied `order.output.call` / predispatch calldata on behalf of `IntentsBase._execute` — has the exact same shape of flaw: its public `dispatch()` entrypoint is callable by literally anyone, not just the IntentGatewayV2 contract that is supposed to own it.

### Finding Description
`IntentsBase._execute` sends escrowed/output tokens to a single shared `CallDispatcher` instance (`_params.dispatcher`), executes the order's arbitrary `call` array through it, and then sweeps back only the tokens explicitly listed in `order.output.assets` (or the native balance): [1](#0-0) 

`CallDispatcher.dispatch` itself has **no access-control modifier at all** — it's a bare `external` function that any EOA or contract can call directly: [2](#0-1) 

Because the dispatcher is a **single shared singleton** used across every order (predispatch swap-then-escrow, and postdispatch fill-then-act calldata), and the sweep in `_execute` only iterates over `order.output.assets` (the tokens the *current* order declared), any token that ends up on the dispatcher that is *not* part of that specific order's declared output-asset list — e.g., an intermediate swap-path token, a leftover approval-triggered transfer, or ETH sent via the dispatcher's `receive()` — is never swept back to the gateway and remains on the dispatcher's balance indefinitely.

Since `dispatch()` is unauthenticated, any unprivileged third party can then call `CallDispatcher.dispatch()` directly with an arbitrary `Call[]` (e.g., `IERC20(token).transfer(attacker, balance)`) to sweep that residual balance to themselves — precisely the same "insert an arbitrary call into the hook-execution path because access control on the hook executor is ineffective" primitive described in the FloodPlain report, where the hook executor doesn't validate the caller or bind the hook to a specific authorized invoker.

### Impact Explanation
Any token balance that accumulates on the shared `CallDispatcher` (from calldata side effects such as an intermediate swap producing a token not declared in `order.output.assets`, or residual dust from a failed/partial sweep enumeration) can be stolen outright by any unprivileged caller, since `dispatch()` performs no `msg.sender` check tying execution back to `IntentGatewayV2`. This is a direct loss-of-funds path matching the bounty's "stealing or loss of funds" / "unauthorized execution" category, and it is reachable by any unprivileged actor with no relayer, prover, or governance dependency.

### Likelihood Explanation
Likelihood depends on funds actually residing on the dispatcher outside the current order's `output.assets` sweep set at the time of the attacker's call — e.g., composable postdispatch/predispatch calldata that routes through a DEX and yields an intermediate or unlisted token, or plain ETH sent to the dispatcher's `receive()`. Given that the gateway explicitly documents composable calldata execution "through DEXes, lending protocols, or other DeFi primitives" as an intended use case, non-enumerated residual balances are a realistic and recurring occurrence, and the unauthenticated `dispatch()` makes exploitation trivial (a single unrestricted call) once such a balance exists.

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the registered `IntentGatewayV2`/`IntentsBase` gateway contract(s) (e.g., an `onlyGateway` modifier set at construction), and additionally ensure `_execute`'s post-call sweep enumerates the dispatcher's *actual* token balances involved in the call graph (or is followed by a permissionless "sweep-to-protocol-dust" call restricted to the gateway) rather than only the order's declared `output.assets`, so no token can be silently orphaned on a contract with an open `dispatch` entrypoint.

### Proof of Concept
1. A solver fills a cross-chain or same-chain order whose `order.output.call` performs a DEX swap through the `CallDispatcher` where the swap path produces `TokenX` as an intermediate/residual output that is **not** listed in `order.output.assets`.
2. `IntentsBase._execute` calls `ICallDispatcher(dispatcher).dispatch(order.output.call)`, then only sweeps balances for tokens enumerated in `order.output.assets`; `TokenX`'s balance remains on the `CallDispatcher`. [3](#0-2) 
3. An attacker, with no relationship to the gateway, calls `CallDispatcher.dispatch(abi.encode([Call({to: TokenX, value: 0, data: transfer(attacker, balance)})]))` directly — this succeeds because `dispatch()` has no caller restriction. [2](#0-1) 
4. `TokenX`'s balance is transferred to the attacker instead of being swept as protocol dust to `IntentGatewayV2`, demonstrating unauthorized fund extraction through the unrestricted hook-execution entrypoint.

**Note on verification limits:** I was not able to fully trace the predispatch flow (`Order.predispatch` / `DispatchInfo.assets`) inside `evm/src/apps/IntentGatewayV2.sol` due to tool/iteration limits — that code path may introduce additional or different residual-balance scenarios worth checking directly. I recommend a Devin session with full repository access to confirm the exact conditions under which non-enumerated tokens accumulate on the `CallDispatcher` in production order flows.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
