### Title
Instruction data from one Bitcoin transaction is copied to every scanned output in the same block - (File: `processor/src/networks/bitcoin.rs`)

### Summary
`Bitcoin::get_outputs` accumulates `outputs` outside the per-transaction loop. When a later transaction in the same block contains at least one Serai output, the code applies that transaction’s `presumed_origin` and `extract_serai_data(tx)` to every accumulated output, including outputs created by earlier unrelated transactions. [1](#0-0) 

### Finding Description
`get_outputs` initializes `let mut outputs = vec![]` before iterating `block.txdata[1 ..]`, appends matching outputs from each transaction, and only skips metadata extraction when the accumulated vector is empty. [2](#0-1)  Because `outputs` is not scoped to the current `tx`, the later transaction’s `extract_serai_data(tx)` is assigned to all prior `External` outputs in the block. [3](#0-2) 

The downstream scanner treats `OutputType::External` data as an instruction: `instruction_from_output` decodes `output.data()` as `Shorthand`, converts it to `RefundableInInstruction`, and creates an `InInstructionWithBalance` using the output’s balance. [4](#0-3)  It also derives the refund origin from the misassigned `presumed_origin` when the instruction has no explicit origin. [5](#0-4) 

### Impact Explanation
An unprivileged Bitcoin user can include two transactions in one confirmed block:

1. A victim or attacker-controlled funding transaction pays the multisig but carries no Serai instruction.
2. A later attacker transaction pays the multisig and embeds a valid instruction, such as `Shorthand::transfer(...)` to an attacker-chosen `SeraiAddress`.

The scanner associates the later transaction’s instruction and presumed origin with the earlier deposit as well. That can cause funds from a deposit that never authorized an instruction to be processed under attacker-selected semantics, or corrupt refund attribution. The scanner does emit every output independently, so this is not merely a display issue; the contaminated `Output` objects proceed to instruction conversion and batch construction. [6](#0-5) 

### Likelihood Explanation
Exploitation only requires controlling a Bitcoin transaction included later in the same finalized block as another transaction paying a scanned Serai address. The vulnerable ordering is directly determined by `block.txdata`, and no validator compromise, malformed encoding, or invalid signature is needed. [7](#0-6) 

### Recommendation
Keep scanned outputs transaction-scoped. For each `tx`, collect its matches into a fresh `tx_outputs`, derive that transaction’s origin/data once, mutate only `tx_outputs`, then extend the block-level result after processing that transaction. Additionally consider binding `Output` to its containing transaction ID during instruction decoding and asserting every output being annotated belongs to the current `tx`.

### Proof of Concept
Conceptual reproduction:

```rust
// tx_victim: pays Serai external address, no Serai data witness/script.
// tx_attack: later in block.txdata, pays Serai external address and embeds
// Shorthand::transfer(None, attacker_serai_address).encode() as Serai data.

let outputs = bitcoin.get_outputs(&block, group_key).await;

// Expected:
// outputs[0].data() == b""
// outputs[1].data() == attacker_instruction

// Actual:
// outputs[0].data() == attacker_instruction
// outputs[1].data() == attacker_instruction
```

The defect is the unconditional mutation of the accumulated `outputs` vector after processing each subsequent transaction. [1](#0-0)

fn instruction_from_output<N: Network>(
  output: &N::Output,
) -> (Option<ExternalAddress>, Option<InInstructionWithBalance>) {
  assert_eq!(output.kind(), OutputType::External);

  let presumed_origin = output.presumed_origin().map(|address| {
    ExternalAddress::new(
      address
        .try_into()
        .map_err(|_| ())
        .expect("presumed origin couldn't be converted to a Vec<u8>"),
    )
    .expect("presumed origin exceeded address limits")
  });

  let mut data = output.data();
  let max_data_len = usize::try_from(MAX_DATA_LEN).unwrap();
  if data.len() > max_data_len {
    error!(
      "data in output {} exceeded MAX_DATA_LEN ({MAX_DATA_LEN}): {}. skipping",
      hex::encode(output.id()),
      data.len(),
    );
    return (presumed_origin, None);
  }

  let shorthand = match Shorthand::decode(&mut data) {
    Ok(shorthand) => shorthand,
    Err(e) => {
      info!("data in output {} wasn't valid shorthand: {e:?}", hex::encode(output.id()));
      return (presumed_origin, None);
    }
  };
  let instruction = match RefundableInInstruction::try_from(shorthand) {
    Ok(instruction) => instruction,
    Err(e) => {
      info!(
        "shorthand in output {} wasn't convertible to a RefundableInInstruction: {e:?}",
        hex::encode(output.id())
      );
      return (presumed_origin, None);
    }
  };

  let mut balance = output.balance();
  // Deduct twice the cost to aggregate to prevent economic attacks by malicious miners against
  // other users
  balance.amount.0 -= 2 * N::COST_TO_AGGREGATE;

  (
    instruction.origin.or(presumed_origin),
    Some(InInstructionWithBalance { instruction: instruction.instruction, balance }),
  )
