## Title
Attacker-Controlled Mirror URLs in DataLayer Enable Authenticated Server-Side Request Forgery (SSRF) - (File: chia/data_layer/download_data.py)

### Summary
DataLayer stores "mirror" URLs on-chain as coin memos so that other nodes can discover where to download a store's delta/full-tree files. Any wallet user can create such a mirror coin for **any** `launcher_id` (not just stores they own) by broadcasting a spend, and any node tracking that `launcher_id` will ingest the memo URL and later have its DataLayer service issue a raw, unvalidated `aiohttp` HTTP GET to that URL. This mirrors the "New API" bug class (any user-supplied URL is fetched server-side with no validation of scheme/host, allowing internal service reachability).

### Finding Description
A mirror coin is a plain "anyone can spend to create" puzzle: `create_mirror_puzzle()` is `P2_PARENT.curry(Program.to(1))` [1](#0-0) , and its memo layout is simply `[launcher_id, *urls]`, extracted by `get_mirror_info()` from any `CREATE_COIN` condition matching the mirror puzzle hash [2](#0-1) . Nothing in the puzzle or in `DataLayerWallet.create_new_mirror()` binds the `launcher_id` memo to ownership of that singleton — it is simply passed through into the memos of a standard coin creation [3](#0-2) . Any spend-bundle submitter can therefore construct their own `CREATE_COIN` to the mirror puzzle hash with an arbitrary `launcher_id` memo pointing at a victim's store and an arbitrary URL memo.

When a peer node observes this coin and is tracking that `launcher_id` (`is_launcher_tracked()` only checks that the launcher exists in `singleton_records`, regardless of ownership), it unconditionally records the mirror and its URL into the local mirrors table via `coin_added()` → `dl_store.add_mirror()` [4](#0-3) [5](#0-4) .

The DataLayer service's periodic sync then treats these attacker-supplied URLs as legitimate servers: `fetch_and_validate()` pulls `servers_info` (which include mirror URLs) and, when no downloader plugin handles the URL, falls through to `http_download()` [6](#0-5) . `http_download()` performs an unrestricted `aiohttp` GET directly against `server_info.url + "/" + filename` with no scheme allow-list, no DNS/IP validation, and no protection against loopback, link-local, or private-network addresses: [7](#0-6) .

This is structurally the same bug class as CVE-2025-59146: an authenticated (here, "authenticated" by the ability to submit a spend bundle and pay the mirror coin cost) user supplies a URL that the server fetches without validating destination, enabling SSRF against internal services (cloud metadata endpoints, internal RPC/admin interfaces, etc.) reachable from the DataLayer host.

### Impact Explanation
Any node running the DataLayer service and following (or even just tracking) a targeted store can be coerced into issuing outbound HTTP requests to attacker-chosen destinations, including internal/private network addresses (e.g., cloud instance metadata services) or arbitrary external hosts, purely by the attacker publishing a cheap on-chain mirror coin. This can be used to probe or attack internal infrastructure behind the DataLayer host, exfiltrate cloud credentials via metadata endpoints, or perform request smuggling against internal services — all without the attacker owning the targeted store or having any special privilege beyond submitting a low-value transaction.

### Likelihood Explanation
Likelihood is high for any deployment running the DataLayer service with mirror-following enabled: mirror coins are permissionless, cheap (`amount`/`fee` fully attacker-controlled), and the URL field is free-form text with no server-side validation before the outbound request is issued. No special node configuration is required beyond running DataLayer and syncing/following the targeted store id, which is the default operating mode for DataLayer participants.

### Recommendation
Introduce a mandatory, on-by-default SSRF protection layer for mirror/plugin URLs before they are used in `http_download()` and `get_downloader()`/uploader flows: restrict schemes to `http`/`https`, resolve and reject requests to private/loopback/link-local/multicast/reserved IP ranges (including after redirect resolution), and allow administrators to configure an explicit allow-list/deny-list of destinations, similar to the patch introduced upstream for New API. Additionally, consider requiring that mirror memos only be trusted when correlated with the actual store owner's signature/authority, rather than any arbitrary spend bundle.

### Proof of Concept
1. Attacker identifies a victim `launcher_id` for a DataLayer store that other nodes track/subscribe to.
2. Attacker calls `create_new_mirror(launcher_id=victim_launcher_id, amount=1, urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"], ...)` from their own wallet (or crafts an equivalent raw spend creating a coin to `create_mirror_puzzle().get_tree_hash()` with memos `[victim_launcher_id, url]`) and broadcasts it — see `chia/data_layer/data_layer_wallet.py:687-703`.
3. Once confirmed, any node tracking `victim_launcher_id` picks up the mirror via `coin_added()` (`chia/data_layer/data_layer_wallet.py:775-799`) and stores it (`chia/data_layer/dl_wallet_store.py:308-325`).
4. On the next `periodically_manage_data()` cycle, that node's `fetch_and_validate()` selects the malicious server info and calls `http_download()`, causing the node to issue a GET request to `http://169.254.169.254/latest/meta-data/iam/security-credentials/` (`chia/data_layer/download_data.py:298-320`), demonstrating unauthenticated-destination SSRF triggered by an unprivileged, low-cost on-chain action.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
```
