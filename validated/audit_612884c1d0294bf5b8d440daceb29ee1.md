### Title
Gasless swap deadline is enforced only at tx-pool admission, not re-checked at block-inclusion, allowing execution of expired `swapForGas` transactions - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`, `kaiax/gasless/impl/builder.go`)

### Summary
The reported bug class is a commented-out/ineffective `deadline` check on a DEX swap call, which lets a swap execute at an arbitrarily later (and worse) price. In `kaiax/gasless`, the KIP-247 `swapForGas` transaction carries a `deadline` field, but that field is validated only once, at tx-pool admission time in `checkBalanceForSwap`, using the current block timestamp at that moment. The bundling logic used at actual block-construction time, `ExtractTxBundles` → `IsExecutable` → `VerifyExecutable`, never re-checks the deadline. A `GaslessSwapTx` that was valid when it entered the pool can therefore be executed many blocks later, well past its stated `deadline`, at a materially different AMM price.

### Finding Description
`checkBalanceForSwap` documents and enforces `tx.deadline >= currentTimestamp` only when the tx is validated for pool admission: [1](#0-0) 

This function is wired into the tx pool through `GetCheckBalance`, which is invoked at transaction validation/admission time: [2](#0-1) 

However, the function actually used to decide whether a `GaslessSwapTx` (with or without a preceding `GaslessApproveTx`) is bundled and included in a block is `VerifyExecutable`, called via `IsExecutable` from `ExtractTxBundles`: [3](#0-2) 

`VerifyExecutable` checks decode validity, router/token whitelisting, sender/token/amount/nonce consistency between the approve and swap legs, and the repay amount — but contains **no check of `swapArgs.Deadline`** against the current block time: [4](#0-3) 

Since the deadline field is decoded as part of `SwapArgs` but is used exclusively inside `checkBalanceForSwap` (an admission-time-only check) and never inside `VerifyExecutable`/`IsExecutable` (the check that gates bundling into a block), a `GaslessSwapTx` that sits in the pending pool (e.g., due to network congestion, low gas price relative to other pending gasless bundles, or simply the time it takes to become "ready") can be picked up and bundled into a block long after its `deadline` has elapsed. The test suite confirms the deadline is only exercised as a pool-admission error path ("insufficient deadline...") and never exercised at the bundling/inclusion step: [5](#0-4) 

This is functionally the same defect described in the reported issue: a `deadline` parameter exists on a swap operation but is not enforced at the point the swap is actually executed on-chain, so the transaction can be delayed and executed at a stale/worse price.

### Impact Explanation
The `GaslessSwapRouter.swapForGas` call performs an on-chain AMM swap (via `GetDEXInfo`/`GetAmountIn` and the underlying Uniswap-V2-style router) to convert a whitelisted ERC-20 token into KAIA to repay the block proposer's lent gas and give the remainder to the user. If the deadline is not enforced at the time of actual execution, an expired gasless swap can still execute at the AMM's then-current price. In volatile market conditions this can produce sender/protocol value loss: the swap can execute at a far worse rate than the user intended when they signed the transaction, since `minAmountOut` protects only against gas-repayment shortfall (`minAmountOut >= amountRepay`), not full price movement over an arbitrarily extended waiting period. Because the gasless flow also involves proposer-fronted gas (`LendTxGenerator`) and a bundle repay mechanism, mispriced/delayed execution also affects the correctness of the fee-delegation/repayment accounting that the module is designed to guarantee.

### Likelihood Explanation
Medium. It does not require a malicious validator; it only requires that a `GaslessSwapTx` remain pending across enough blocks for its declared `deadline` to elapse before it becomes part of a produced block (e.g., under congestion, or simply due to normal pool/promotion delays), since `checkBalanceForSwap`'s deadline check runs once at admission and is not re-verified by `VerifyExecutable`/`IsExecutable` at bundling time.

### Recommendation
Add an explicit deadline check inside `VerifyExecutable` (or equivalently in `IsExecutable`/`ExtractTxBundles`) that compares `swapArgs.Deadline` against the timestamp of the block currently being assembled, rejecting/excluding the bundle if the swap's deadline has already elapsed, mirroring the check already present in `checkBalanceForSwap`.

### Proof of Concept
1. A user submits a valid `GaslessSwapTx` with `deadline = currentBlockTime + N` and a `minAmountOut` computed against the current AMM price; it passes `checkBalanceForSwap` and is admitted to the pool.
2. Due to congestion / low relative priority / any delay in promotion-to-inclusion, the transaction stays in the pending pool for more than `N` seconds, i.e., past its `deadline`.
3. When a later block is built, `ExtractTxBundles` iterates pending transactions and calls `g.IsExecutable(approveTxs[addr], tx)` (`kaiax/gasless/impl/builder.go:40`), which internally calls `VerifyExecutable` (`kaiax/gasless/impl/getter.go:214-266`). Since that function never inspects `swapArgs.Deadline`, the bundle is still created and included.
4. The `swapForGas` call executes on-chain at the current (potentially far worse) AMM price despite the transaction's `deadline` having elapsed, since block-inclusion time enforcement of the deadline never happens.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
