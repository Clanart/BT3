### Title
Missing forfeit calculation in `mWOMSVBaseRewarder._calExpireForfeit` allows full reward capture during mWomSV cooldown - ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` never queries `mWomSV.getRewardablePercentWAD(_account)` the way the analogous `vlMGPBaseRewarder._calExpireForfeit` queries `vlMGP.getRewardablePercentWAD(_account)`. Instead it sets `rewardableAmount = _amount` unconditionally, so `forfeitAmount` is always `0`, meaning any staker with mWOMSV in cooldown still receives 100% of accrued `rewardPerToken` on every `getReward`/`getRewards` call reachable via `MasterMagpie.multiclaim*`, instead of the decayed portion that should be forfeited back to remaining lockers.

### Finding Description
In `rewards/mWOMSVBaseRewarder.sol`: [1](#0-0) 

```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardableAmount = _amount;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;
    ...
    return forfeitAmount;
}
```

Compare this to the sibling contract `rewards/vlMGPBaseRewarder.sol`, which correctly implements the decay by consulting the locker's cooldown percent: [2](#0-1) 

```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    ...
}
```

`mWomSV.sol` (the locker paired with `mWOMSVBaseRewarder`) implements the identical decay function `getRewardablePercentWAD`, which reduces the rewardable percentage of `balanceOf` (which is `getUserTotalLocked + getUserAmountInCoolDown`) as a function of cooldown-slot progress, intending the un-decayed remainder to be forfeited back into the pool via `_queueNewRewardsWithoutTransfer`: [3](#0-2) 

But `mWOMSVBaseRewarder` never calls it. As a result, `_sendReward` (called from `getReward`/`getRewards`, both gated by `onlyMasterMagpie`) always computes `forfeitAmount = 0`: [4](#0-3) 

This function is reachable by any unprivileged account via `MasterMagpie.multiclaim`/`multiclaimFor`/`multiclaimSpec`, which route to `_claimBaseRewarder` → `rewarder.getReward(_account, _receiver)`: [5](#0-4) 

No other check (no `nonReentrant`-related gate, no receipt-token accounting) restores the intended forfeiture, since `balanceOf` for `mWOMSVBaseRewarder` still counts the full cooldown+locked balance as reward-earning principal, and `_calExpireForfeit` is the sole place forfeiture is supposed to be applied.

Note on the "loop across many blocks" framing in the question: because `forfeitAmount` is unconditionally `0`, no looping or timing trick is actually required — a single `getReward`/`multiclaim` call after `mWomSV.startUnlock` already captures 100% of accrued rewards with zero forfeiture, and this holds true for every subsequent claim throughout the entire cooldown period (and even after cooldown, since `balanceOf` never shrinks until `unlock()` is called). This is a straightforward missing-implementation bug rather than a reentrancy or timing race, but the effect matches the described scoped impact.

### Impact Explanation
Every user who starts an mWomSV cooldown (via `mWomSV.startUnlock`, which any mWomSV holder can call permissionlessly) permanently receives 100% of the reward-per-token accrual on their full cooldown+locked balance, instead of the decayed percentage intended by `getRewardablePercentWAD`. The intended forfeited remainder — which should flow back to `rewardPerTokenStored` via `_queueNewRewardsWithoutTransfer` and thus be redistributed to remaining (non-cooling) mWomSV lockers — is never captured. This is a sustained, protocol-wide theft/misallocation of unclaimed yield away from long-term lockers to anyone using cooldown, degrading the reward pool's economics versus the documented design and potentially causing the pool's payable reward obligations (based on `historicalRewards`/`rewardPerTokenStored`) to exceed what should have accrued under the intended decay curve. This matches the Immunefi "theft or permanent loss of unclaimed yield" impact class.

### Likelihood Explanation
Preconditions are trivial and require no special capital: any address holding mWOMSV (obtained via normal deposit) can call `mWomSV.startUnlock` and then repeatedly call `MasterMagpie.multiclaim`/`multiclaimFor` to harvest via `mWOMSVBaseRewarder.getReward`. The bug fires unconditionally on every call, so it is 100% reliable and repeatable by every user, not just a sophisticated attacker — this is a systemic implementation gap rather than a narrow edge case.

### Recommendation
Fix `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount) revert InvalidRewardableAmount();
    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) { forfeitAmount = 0; }
    return forfeitAmount;
}
```
This requires `ILocker`/`mWOMSV` (already declared as `ILocker public mWOMSV` in the contract) to expose `getRewardablePercentWAD`, matching the interface used by `vlMGP`.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
