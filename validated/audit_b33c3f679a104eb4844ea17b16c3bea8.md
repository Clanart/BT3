### Title
Address association only migrates bank coin/wei balances, permanently stranding CW721/CW1155 NFTs and other contract-tracked assets held at the pre-association cast address - ([File: utils/helpers/associate.go])

### Summary
When a user first sends value or NFTs to a Sei address that is the raw byte-cast of an unassociated EVM address (`sdk.AccAddress(evmAddr[:])`), and that EVM address later performs "association" (either explicitly via the `addr` precompile's `associate`, or implicitly via `UpdateSigners` in `app/ante/cosmos_checktx.go`), only bank-module `usei`/wei balances are moved from the cast address to the user's "true" pubkey-derived Sei address. Any asset whose ownership is tracked inside a CosmWasm contract's own storage (e.g., a native CW721/CW1155 NFT `owner` field keyed by the cast address's bech32 string) is never migrated and is permanently orphaned, mirroring the referenced report's "smart wallet may not control the same address on the destination system" bug class.

### Finding Description
Sei maps every Sei (`sdk.AccAddress`) identity to an EVM (`common.Address`) identity via `SetAddressMapping`/`GetSeiAddress`/`GetEVMAddress` [1](#0-0) . Until an EVM address is associated, any Cosmos-side asset addressed "to" that EVM address is recorded under the deterministic direct byte-cast address, `sdk.AccAddress(evmAddr[:])` (`GetSeiAddressOrDefault`) [2](#0-1) .

Association happens either explicitly (self-signed message recovering `v,r,s` over a `customMessage`, e.g. via the `addr` precompile's `associate`) [3](#0-2) , or implicitly the first time the EVM-derived key signs a native Cosmos tx, in `UpdateSigners` [4](#0-3) . Both paths funnel into `AssociationHelper.AssociateAddresses` → `MigrateBalance`, which explicitly only moves `SpendableCoins`/`GetWeiBalance` from the cast address to the newly associated true Sei address, then deletes the cast address's account if its `LockedCoins` are zero: [5](#0-4) 

There is no code path that inspects or migrates state owned by other modules or CosmWasm contracts that reference the cast address as an owner/holder — for example a CW721 NFT contract's internal `owner` map keyed by the cast address's bech32 string, or a CW1155 balance map. The batch migration helper used for other scenarios has the exact same limitation (bank/wei only) [6](#0-5) .

Once the association completes, the cast address's account object is removed (`RemoveAccount`) if it holds no locked coins [7](#0-6) , and critically the user has no way to author a valid Cosmos-signed message *as* that cast address afterward: subsequent EVM interactions with CosmWasm contracts (via the `wasmd` precompile) always resolve the caller to the user's *associated* Sei address, not the stale cast address [8](#0-7) , and the cast address's raw bytes do not correspond to any real secp256k1-derived Cosmos pubkey (it was constructed by directly relabeling the EVM address bytes as a bech32 Sei address), so no native `MsgExecuteContract` can be validly signed from it either. Any CW721/CW1155 NFT still recorded as owned by that cast address is therefore permanently unreachable.

### Impact Explanation
This is a concrete, permanent-loss-of-funds scenario for an ordinary, unprivileged user: any NFT (or other CW-contract-tracked, non-bank asset) sent to a not-yet-associated user's Sei address is stranded forever the moment that user associates their EVM key, because the association/migration logic in `utils/helpers/associate.go` only accounts for bank coins/wei. This qualifies as concrete permanent freezing/loss of user-owned assets reachable purely from unprivileged transactions (a mint/transfer to a cast address, followed by a normal association flow that any wallet or dApp would trigger).

### Likelihood Explanation
Likelihood is realistic though it requires a specific ordering: (1) an asset (e.g., NFT mint/transfer via `MsgExecuteContract` on a CW721 contract) is sent to the bech32-encoded cast address of a user's EVM key before that key has ever been associated, and (2) the user later associates (which happens automatically the first time they sign *any* native Cosmos tx, per `UpdateSigners`, or explicitly via the `addr` precompile). Since association is an extremely common, often invisible/automatic step for any EVM-first user who later touches the Cosmos side (or vice versa), and NFT platforms/bridges frequently pre-fund/pre-mint to a counterparty's Sei address before the counterparty has associated, this ordering is plausible in normal usage, not just a contrived edge case.

### Recommendation
Extend the association/migration flow (`AssociationHelper.AssociateAddresses`/`MigrateBalance` and `MigrateCastAddressBalances`) to also migrate or otherwise safely reconcile non-bank state tied to the cast address before it is deleted — e.g., expose a generic "address migration" hook that CW721/CW1155/other modules can register to transfer ownership records from the cast address to the newly associated true address, or refuse to `RemoveAccount`/finalize association while the cast address still holds recognized CW contract-tracked assets (analogous to the existing `LockedCoins` check). At minimum, do not silently delete the cast address account when non-bank assets it owns cannot be verified to be empty.

### Proof of Concept
1. Attacker/dApp mints or transfers a CW721 NFT via `MsgExecuteContract` to `owner = bech32(sdk.AccAddress(evmAddr[:]))` — the deterministic cast address for a victim's EVM address that has not yet been associated.
2. Victim later associates their EVM key with their true Sei address — either explicitly by calling `associate` on the `addr` precompile [3](#0-2) , or implicitly by signing any native Cosmos tx (triggering `UpdateSigners`) [4](#0-3) .
3. `AssociateAddresses`/`MigrateBalance` runs, moving only `usei`/wei balances, and removes the cast address's account since it holds no locked coins [5](#0-4) .
4. The CW721 contract's internal `owner` record still lists the cast address's bech32 string as owner. The victim cannot sign a valid Cosmos message from that cast address (no corresponding private key under Cosmos's secp256k1→address derivation), and any subsequent EVM interaction with the CW721 contract via the `wasmd` precompile resolves the victim's identity to their newly associated true Sei address, not the cast address [8](#0-7) . The NFT is permanently unreachable.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) ([]byte, error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, err
	}

	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey)
	if err != nil {
		return nil, err
	}

	return method.Outputs.Pack(seiAddr.String(), evmAddr)
}

func UpdateSigners(ctx sdk.Context, tx sdk.Tx, accountKeeper authkeeper.AccountKeeper, evmKeeper *evmkeeper.Keeper) (sdk.Events, error) {
	signers := tx.(authsigning.SigVerifiableTx).GetSigners()
	var events sdk.Events
	for _, signer := range signers {
		acc := accountKeeper.GetAccount(ctx, signer)
		if err := acc.SetSequence(acc.GetSequence() + 1); err != nil {
			panic(err)
		}

		accountKeeper.SetAccount(ctx, acc)
		if evmAddr, associated := evmKeeper.GetEVMAddress(ctx, signer); associated {
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey, likely due to the fact that it isn't on secp256k1 curve", "pub-key", acc.GetPubKey(), "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(evmKeeper, evmKeeper.BankKeeper(), accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return nil, err
		}
	}
	return events, nil
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil

func MigrateCastAddressBalances(ctx sdk.Context, k *keeper.Keeper) (rerr error) {
	k.IterateSeiAddressMapping(ctx, func(evmAddr common.Address, seiAddr sdk.AccAddress) bool {
		castAddr := sdk.AccAddress(evmAddr[:])
		if balances := k.BankKeeper().SpendableCoins(ctx, castAddr); !balances.IsZero() {
			if err := k.BankKeeper().SendCoins(ctx, castAddr, seiAddr, balances); err != nil {
				logger.Error("error migrating balances from cast to real for address", "address", evmAddr, "err", err)
				rerr = err
				return true
			}
		}
		if wei := k.BankKeeper().GetWeiBalance(ctx, castAddr); !wei.IsZero() {
			if err := k.BankKeeper().SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), wei); err != nil {
				logger.Error("error migrating wei from cast to real for address", "address", evmAddr, "err", err)
				rerr = err
				return true
			}
		}
		return false
	})
	return
}
