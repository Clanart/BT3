### Title
Attacker-controlled `x-github-client://openrepo` deep link forces a new modal popup onto the shared, global `PopupManager` stack, overlaying/replacing whatever dialog the user is currently confirming - ([File: app/src/lib/popup-manager.ts])

### Summary
The Uniswap report's broken invariant is: a single, shared UI surface (the sidebar) stacks the newest untrusted-triggered request on top and shows only the last one, so an attacker in another context can swap out a confirmation button the instant before the user clicks it. GitHub Desktop has the same architecture at the application level: `PopupManager` keeps one global, last-on-top stack of dialogs for the entire app [1](#0-0) , and `App.allPopupContent()`/`Dialog` mark only the newest popup as `isTopMost`, which makes it the active `showModal()` dialog and grabs focus/click handling [2](#0-1) [3](#0-2) . Unlike the Uniswap sidePanel case, Desktop is a single window rather than multiple tabs, but Desktop exposes an equivalent untrusted trigger: the `x-github-client://` custom protocol handler, which any website can invoke via a link the user clicks.

### Finding Description
`main.ts` registers `x-github-client` (and legacy `github-mac`/`github-windows`) as OS-level protocol handlers [4](#0-3) . When a URL is opened, `handleAppURL` parses it and forwards the action to the renderer, explicitly focusing the Desktop window in the process [5](#0-4) . `parseAppURL` accepts `openrepo` URLs carrying an attacker-supplied clone `url`, `branch`, `pr`, and `filepath` [6](#0-5) .

On the renderer side, `Dispatcher.dispatchURLAction` routes `open-repository-from-url` to `openRepositoryFromUrl`, which — with no user confirmation step first — calls `openOrCloneRepository`. If the repository isn't already known, this directly calls `showPopup({ type: PopupType.CloneRepository, initialURL: url })` [7](#0-6) . That `showPopup` call reaches `AppStore._showPopup`, which unconditionally pushes the new popup onto `PopupManager`'s single global stack [8](#0-7) . `PopupManager.addPopup` places the new popup at the end of the stack (`insertBeforeErrorPopups`), and `currentPopup`/`isTopMost` always resolve to the most recently added popup [9](#0-8) .

Because there is exactly one popup surface for the whole app, and the topmost popup is whichever was added last regardless of *why* it was added, this new dialog will be layered directly on top of any dialog the user is already interacting with — e.g. a "Discard Changes," "Force push," or commit-confirmation dialog the user was about to confirm. All of Desktop's modal dialogs use the same `Dialog`/`DialogFooter`/`OkCancelButtonGroup` layout with the primary action button in the same bottom-right screen position, so a click or Enter keypress timed for the prior dialog's confirm button can land on the new dialog's default button instead — the same "sudden layer switch under the cursor" primitive as the Uniswap sidebar bug. There is no user-gesture check before `showPopup` is invoked from the URL-handler path, and `Dialog`'s only timing guard (`dismissGracePeriodMs`) only delays *dismissal* via backdrop click, not enabling of the primary action button, so a rapid-fire popup swap immediately becomes clickable.

Additionally, if the target repository is already known to Desktop, `openOrCloneRepository` skips the popup entirely and silently calls `selectRepository`, then (for the `branch`/`pr` variants) `openBranchNameFromUrl`/`openPullRequestFromUrl` perform `_refreshRepository`, `_fetch`, and `checkoutLocalBranch`/`_checkoutPullRequest` with **no popup at all** [10](#0-9) . This means a malicious link can silently switch the active repository and checkout to an attacker-named branch in the background while the user believes they are looking at their existing repository state, compounding the risk if they then confirm a subsequent stage/commit/push dialog without noticing the switch.

### Impact Explanation
An attacker who controls a link (embedded on a webpage, in an email, in a chat message, or in a malicious/compromised remote's README) can time-trigger a Desktop popup (Clone Repository dialog, or a silent repository/branch switch) at the moment a Desktop user is mid-click on an unrelated confirmation dialog. This can cause the user to unintentionally confirm the attacker's dialog (e.g. initiating a clone of an attacker-controlled repository to an attacker-influenced local path) or unknowingly operate on a different, attacker-selected branch/repository than the one they believe they're confirming, which can lead to committing/pushing to the wrong ref, checking out attacker-controlled code, or writing attacker-controlled files (`filepath`/`shell.showItemInFolder` path, though that specific parameter is path-validated) into an unexpected local location. This matches the "silent corruption of what the user commits or pushes" and "code execution/file write via attacker-controlled fetched repository" impact classes.

### Likelihood Explanation
Moderate-to-low. It requires: (1) the user to have GitHub Desktop already running with an unrelated dialog open, (2) the user's browser to be configured/permitted to open `x-github-client://` links without an additional OS prompt confirmation (many browsers show a one-time "open GitHub Desktop?" prompt, which reduces but does not eliminate exploitability for users who have "always allow" set, similar to the original report's own admission that its bug requires precise timing), and (3) precise timing of the click, similar in difficulty to the original Uniswap PoC which also relied on a timed `visibilitychange`/delay trick. This is a real, reachable code path (no local access, no prior malware, no admin rights, no leaked credentials required) and is architecturally identical to the reported bug class: a single shared, last-writer-wins modal stack driven by an externally triggerable event.

### Recommendation
- Do not allow deep-link-originated popups (`PopupType.CloneRepository` from `openOrCloneRepository`, or any popup from `dispatchURLAction`) to silently jump to the top of the global popup stack while another popup is open; queue them behind the current popup or require an explicit user acknowledgment/gesture before they become interactive/topmost.
- Add a short input-disable window (similar to `dismissGracePeriodMs`) on a dialog's primary action button after it becomes `isTopMost`, so a click that was queued for a previous dialog cannot immediately trigger the new dialog's default action.
- For `openBranchNameFromUrl`/`openPullRequestFromUrl`, require explicit user confirmation before performing `_fetch`/checkout on an already-known repository triggered via a deep link, rather than performing it silently.
- Consider scoping `PopupManager` so protocol-handler-originated popups cannot pre-empt/overlay popups the user is actively engaged with, mirroring the report's long-term recommendation that UI surfaces should not change unexpectedly without direct user interaction.

### Proof of Concept
1. Attacker hosts (or embeds in a compromised GitHub repo README/webpage) a link:
   `x-github-client://openrepo/https://github.com/attacker/malicious-repo?branch=attacker-branch`
2. Victim has GitHub Desktop open with an unrelated confirmation dialog visible (e.g. "Discard Changes" or a commit confirmation), and is about to click the confirm button.
3. Victim (in a browser, potentially in another tab/window) clicks the attacker's link at that moment (or the attacker times an automatic navigation/redirect based on `visibilitychange` similar to the original report's PoC).
4. The OS invokes Desktop's registered protocol handler; `handleAppURL` focuses the Desktop window and dispatches the action; `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository` → `showPopup({ type: PopupType.CloneRepository, ... })` pushes a new modal on top of `PopupManager`'s stack.
5. Because the new `CloneRepository` dialog's primary button occupies the same screen position as the previous dialog's confirm button, the victim's already-in-flight click lands on the new dialog, initiating the clone action the victim never intended to confirm.   public addPopup(popupToAdd: Popup): Popup {
    if (popupToAdd.type === PopupType.Error) {
      return this.addErrorPopup(popupToAdd.error)
    }

    const existingPopup = this.getPopupsOfType(popupToAdd.type)

    const popup = { id: ++this.popupCounter, ...popupToAdd }

    if (existingPopup.length > 0) {
      log.warn(
        `Attempted to add a popup of already existing type - ${popupToAdd.type}.`
      )
      return popupToAdd
    }

    this.insertBeforeErrorPopups(popup)
    this.checkStackLength()
    return popup
  }

  /** Adds a non-Error type popup before any error popups. */
  private insertBeforeErrorPopups(popup: Popup) {
    if (this.popupStack.at(-1)?.type !== PopupType.Error) {
      this.popupStack = this.popupStack.concat(popup)
      return
    }

    const errorPopups = this.getPopupsOfType(PopupType.Error)
    const nonErrorPopups = this.popupStack.filter(
      p => p.type !== PopupType.Error
    )
    this.popupStack = [...nonErrorPopups, popup, ...errorPopups]
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
