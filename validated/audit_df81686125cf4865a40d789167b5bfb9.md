### Title
Empty deserialized aggregate Schnorr signatures verify as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts a vector containing zero nonce commitments, and `SchnorrAggregate::verify` does not reject an empty aggregate when given an empty `keys_and_challenges` slice. An attacker can therefore provide serialized bytes representing `Rs = []` and `s = 0`, producing a valid aggregate verification result for no signatures.

### Finding Description
`SchnorrAggregate::read` reads a 32-bit length, iterates that many times to decode `Rs`, and then reads `s`; when the length is zero, `Rs` remains empty and zero is accepted as a canonical scalar for `s`. [1](#0-0) [2](#0-1) 

`verify` only checks that `self.Rs.len() == keys_and_challenges.len()` before constructing the multiexp. [3](#0-2)  For two empty slices, no `R` or key terms are queued, and the only statement is `(-s) * G`; with `s = 0`, this evaluates to identity and returns `true`. [4](#0-3) 

The honest aggregation API prevents this state by returning `None` when no signatures were aggregated, but that invariant is not enforced during deserialization. [5](#0-4) 

### Impact Explanation
Any caller that treats `SchnorrAggregate::verify(dst, &[])` as authorizing a batch can accept an attacker-supplied aggregate signature that proves nothing. This is a forged signature acceptance condition reachable entirely through public serialized bytes passed to `SchnorrAggregate::read`.

### Likelihood Explanation
An unprivileged party only needs to submit a four-byte zero length followed by the canonical encoding of scalar zero. No secret key, signature, nonce, collision, or malformed encoding is required.

### Recommendation
Reject empty aggregates in both `SchnorrAggregate::read` and `SchnorrAggregate::verify`, or make `verify` explicitly return `false` when `keys_and_challenges.is_empty()`. Enforcing the check during deserialization alone is safer if empty aggregate values are never semantically valid.

### Proof of Concept
Conceptually, for any ciphersuite `C` with a canonical zero-scalar encoding:

```rust
let mut bytes = vec![];
bytes.extend(0u32.to_le_bytes());       // zero Rs
bytes.extend(C::F::ZERO.to_repr());     // s = 0

let aggregate = SchnorrAggregate::<C>::read(&mut bytes.as_slice()).unwrap();
assert!(aggregate.verify(b"some-valid-dst", &[]));
```

This succeeds because the length comparison passes with `0 == 0`, the resulting multiexp contains only the identity term `0 * G`, and `verify` returns `true`. [1](#0-0) [6](#0-5)
