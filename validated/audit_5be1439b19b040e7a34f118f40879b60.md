### Title
Oneof-switch during `MergeFrom`/`MergeFromString` could delete an in-use submessage while a live Python wrapper still referenced it (fixed via explicit release/detach step) - ([File: python/google/protobuf/pyext/message.cc])

### Summary
The Vader report's failed invariant is: an operation that updates existing per-holder state (`deposit()`) implicitly discards/replaces prior live state (the unclaimed vesting) without first detaching or preserving references to it, so a subsequent read of that "old" state observes silently-corrupted data (a reset vesting clock) instead of a safe, defined outcome. The closest verifiable Protobuf analog with the same shape — "merging new attacker-controlled data into an existing object silently destroys a live sub-object that a caller still holds a reference to, without release/detach" — is the (now-mitigated) C++/Python `pyext` oneof-switch-during-merge issue in `python/google/protobuf/pyext/message.cc`.

### Finding Description
When a Python `Message` object is merged with new wire bytes via `CMessage.MergeFromString`, the underlying C++ oneof implementation frees the previous oneof member as soon as the new payload activates a different member of the same `oneof` (see `Reflection::ClearOneof` in `src/google/protobuf/generated_message_reflection.cc:3403-3448`, which explicitly `delete`s the old `Message*`/string on arena-less messages, and the fast-table equivalent `TcParser::ChangeOneof` in `src/google/protobuf/generated_message_tctable_lite.cc:1989-2053`, which also disposes the previous oneof payload before installing the new one). [1](#0-0) [2](#0-1) 

In the Python C-extension binding (`pyext`), a Python wrapper object (`CMessage`) can hold a long-lived reference to a nested submessage obtained via `msg.oneof_nested_message`. If the wrapped C++ message is later merged with wire data that activates a *different* member of that same `oneof`, the C++ oneof-clear logic deletes the C++ object backing the Python wrapper, while the Python wrapper (and any Python code holding `sub_ref = msg.oneof_nested_message`) is unaware and still points at freed memory — a classic use-after-free triggered purely by parsing bounded, attacker-supplied bytes into an existing message via the public `MergeFromString`/`MergeFrom` API. [3](#0-2) 

This is precisely analogous to the Vader bug's invariant violation: "update existing state" (`deposit()` / `MergeFromString()`) silently discards/frees state that a live reference depends on (`unclaimed vesting` / `sub_ref` Python wrapper), producing observable corruption instead of a defined, safe error.

### Impact Explanation
The impact is memory corruption/use-after-free reachable purely from parsing untrusted, bounded bytes via the public `MergeFromString`/`MergeFrom` API on a message that (a) has a `oneof` containing a message-typed field, and (b) the caller previously obtained a submessage handle for that oneof member and retains it across a subsequent merge call. This is an integrity/memory-safety violation of the "no vulnerability from parsing trusted-schema, bounded bytes" invariant, not merely an allowed API-documented data-overwrite. In native C++, an equivalent unprotected use of a stale pointer to a deleted oneof submessage after `MergeFrom`/`ParseFromString` on the same target message would produce the same UAF at the application level; the specific consuming-application exposure assumption here is that user code exposes `MergeFrom`/`ParseFrom` on a persistent message object to attacker-controlled bytes while retaining references to prior oneof submessages (a common pattern, e.g. long-lived server-side proto builders or caches).

### Likelihood Explanation
This checkout already contains a fix in the exact code path being exercised: `MergeFromStringImpl` in `python/google/protobuf/pyext/message.cc` explicitly parses into a temporary message first, then calls `MaybeReleaseOneofBeforeMerge` to detach/release Python wrappers for oneof members that are about to be switched, *before* invoking the real C++ `MergeFrom` that frees the old member — precisely to prevent the UAF demonstrated by `testOneofSwitchMergeUAF`. [4](#0-3) [5](#0-4) 

Because the mitigation is present and actively tested (`testOneofSwitchMergeUAF`, `testOneofMergePreservesExisting`, `testOneofMergeMergesSameField`), the vulnerability as originally described is **not currently exploitable in this codebase's Python `pyext` binding** — it is a fixed/hardened historical bug class, not a live one. I could not confirm within this investigation whether every other binding (e.g., pure-Python implementation, upb-backed Python/Ruby/PHP bindings inspected via `python/message.c`, `php/ext/google/protobuf/message.c`) applies an equivalent release-before-merge step for oneof submessage wrappers; the upb-backed `PyUpb_Message_Reify`/`PyUpb_Message_AssureWritable` machinery in `python/message.c` was inspected but no oneof-merge-specific release logic analogous to `MaybeReleaseOneofBeforeMerge` was found in the reviewed excerpts, so this remains **unverified** and should be treated as an open question rather than a confirmed finding.

### Recommendation
Given the mitigation already present in `pyext`, the actionable recommendation for the analog is to (1) confirm the same "release wrapper before oneof switch during merge" pattern is applied consistently across all Python/Ruby/PHP bindings that wrap upb or C++ kernels (particularly the upb-backed `python/message.c` and `php/ext/google/protobuf/message.c`, which were not confirmed to have the same protection during this review), and (2) add regression tests analogous to `testOneofSwitchMergeUAF` for each binding/kernel combination to lock in the invariant that a live submessage handle must never dangle across a `MergeFrom`/`MergeFromString` call that switches oneof membership.

void Reflection::ClearOneof(Message* message,
                            const OneofDescriptor* oneof_descriptor) const {
  if (oneof_descriptor->is_synthetic()) {
    ClearField(message, oneof_descriptor->field(0));
    return;
  }
  // TODO: Consider to cache the unused object instead of deleting
  // it. It will be much faster if an application switches a lot from
  // a few oneof fields.  Time/space tradeoff
  uint32_t oneof_case = GetOneofCase(*message, oneof_descriptor);
  if (oneof_case > 0) {
    const FieldDescriptor* field = descriptor_->FindFieldByNumber(oneof_case);
    if (message->GetArena() == nullptr) {
      switch (field->cpp_type()) {
        case FieldDescriptor::CPPTYPE_STRING: {
          switch (field->cpp_string_type()) {
            case FieldDescriptor::CppStringType::kCord:
              delete *MutableRaw<absl::Cord*>(message, field);
              break;
            case FieldDescriptor::CppStringType::kView:
            case FieldDescriptor::CppStringType::kString:
              if (IsMicroString(field)) {
                MutableField<MicroString>(message, field)->Destroy();
              } else {
                // Oneof string fields are never set as a default instance.
                // We just need to pass some arbitrary default string to make it
                // work. This allows us to not have the real default accessible
                // from reflection.
                MutableField<ArenaStringPtr>(message, field)->Destroy();
              }
              break;
          }
          break;
        }

        case FieldDescriptor::CPPTYPE_MESSAGE:
          delete *MutableRaw<Message*>(message, field);
          break;
        default:
          break;
      }
    }

    *MutableOneofCase(message, oneof_descriptor) = 0;

void TcParser::ChangeOneof(const TcParseTableBase* table,
                           const ClassData* class_data,
                           const TcParseTableBase::FieldEntry& entry,
                           uint32_t field_num, ParseContext* ctx,
                           MessageLite* msg) {
  // The _oneof_case_ value offset is stored in the has-bit index.
  uint32_t* oneof_case = &TcParser::RefAt<uint32_t>(msg, entry.has_idx);
  uint32_t current_case = *oneof_case;
  *oneof_case = field_num;

  // If the member is already active, then it should be merged. We're done.
  if (current_case == field_num) return;

  if (current_case == 0) {
    // If the member is empty, we don't have anything to clear.
    // We must create a new member object.
    InitOneof(table, class_data, entry, msg);
    return;
  }

  // Look up the value that is already stored, and dispose of it if necessary.
  const FieldEntry* current_entry = FindFieldEntry(table, current_case);
  uint16_t current_kind = current_entry->type_card & field_layout::kFkMask;
  uint16_t current_rep = current_entry->type_card & field_layout::kRepMask;
  if (current_kind == field_layout::kFkString) {
    switch (current_rep) {
      case field_layout::kRepAString: {
        auto& field = RefAt<ArenaStringPtr>(msg, current_entry->offset);
        field.Destroy();
        break;
      }
      case field_layout::kRepMString: {
        if (msg->GetArena() == nullptr) {
          RefAt<MicroString>(msg, current_entry->offset).Destroy();
        }
        break;
      }
      case field_layout::kRepCord: {
        if (msg->GetArena() == nullptr) {
          delete RefAt<absl::Cord*>(msg, current_entry->offset);
        }
        break;
      }
      case field_layout::kRepSString:
      case field_layout::kRepIString:
      default:
        internal::Unreachable();
        return;
    }
  } else if (current_kind == field_layout::kFkMessage) {
    switch (current_rep) {
      case field_layout::kRepMessage:
      case field_layout::kRepGroup: {
        auto& field = RefAt<MessageLite*>(msg, current_entry->offset);
        if (!msg->GetArena()) {
          delete field;
        }
        break;
      }
      default:
        internal::Unreachable();
        return;
    }
  }
  InitOneof(table, class_data, entry, msg);

int MaybeReleaseOneofBeforeMerge(CMessage* self, const Message& other) {
  CMessage::CompositeFieldsMap* composite_fields =
      self->composite_fields.TryGet();
  if (!composite_fields) {
    return 0;
  }

  Message* message = AssureWritable(self);
  if (message == nullptr) return -1;
  const Reflection* reflection = message->GetReflection();
  PyMessageFactory* factory = GetFactoryForMessage(self);
  std::vector<const FieldDescriptor*> fields_to_release;
  std::vector<std::pair<const FieldDescriptor*, ScopedPyObjectPtr>>
      nested_message_fields;
  composite_fields->ForEach([&](const void* key, PyObject* value) {
    const FieldDescriptor* descriptor =
        reinterpret_cast<const FieldDescriptor*>(key);
    if (descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE &&
        // For normal repeated message, MergeFrom will append the messages.
        // For message map with same keys, it is overwrite
        !descriptor->is_repeated() &&
        reflection->HasField(*message, descriptor)) {
      if (reflection->HasField(other, descriptor)) {
        Py_INCREF(value);
        nested_message_fields.emplace_back(descriptor, value);
      } else {
        // Release oneof message if the other message has set a different oneof
        const OneofDescriptor* oneof = descriptor->containing_oneof();
        if (oneof && reflection->HasOneof(other, oneof)) {
          fields_to_release.push_back(descriptor);
        }
      }
    }
  });

  for (const auto& [field, value] : nested_message_fields) {
    if (MaybeReleaseOneofBeforeMerge(
            reinterpret_cast<CMessage*>(value.get()),
            reflection->GetMessage(other, field, factory->message_factory)) <
        0) {
      return -1;
    }
  }

  for (const FieldDescriptor* field : fields_to_release) {
    if (InternalReleaseFieldByDescriptor(self, field) < 0) {
      return -1;
    }
  }
  return 0;
}

static PyObject* MergeFromStringImpl(CMessage* self, PyObject* arg,
                                     bool is_cleared) {
  Py_buffer data;
  if (PyObject_GetBuffer(arg, &data, PyBUF_SIMPLE) < 0) {
    return nullptr;
  }
  auto cleanup_data = absl::MakeCleanup([&data] { PyBuffer_Release(&data); });

  Message* message = AssureWritable(self);
  if (message == nullptr) {
    return nullptr;
  }

  // We parse into a temporary message first to detect oneof switches before
  // modifying the target message. This allows us to release the wrappers
  // for switching oneof fields in the target message before they are deleted
  // by C++ during the merge, preventing use-after-free bugs.
  // We use heap allocation (nullptr arena) for the temporary message so that
  // it is collected immediately after the merge, avoiding wasting arena memory.
  std::unique_ptr<Message> temp_message;
  Message* merge_dst;

  if (is_cleared) {
    // Check that it is really empty.
    ABSL_DCHECK_EQ(message->ByteSizeLong(), 0);
    merge_dst = message;
  } else {
    temp_message.reset(message->New(nullptr));
    merge_dst = temp_message.get();
  }

  PyMessageFactory* factory = GetFactoryForMessage(self);
  int depth = allow_oversize_protos
                  ? INT_MAX
                  : io::CodedInputStream::GetDefaultRecursionLimit();
  const char* ptr;
  internal::ParseContext ctx(
      depth, false, &ptr,
      absl::string_view(static_cast<const char*>(data.buf), data.len));

  ctx.data().pool = factory->pool->pool->get();
  ctx.data().factory = factory->message_factory;

  ptr = merge_dst->_InternalParse(ptr, &ctx);

  if (is_cleared) {
    // If we merged into the final destination, fix up now before we might have
    // an early exit.
    FixupMessageAfterMerge(self);
  }
