### Title
Untrusted `ReceivedOutput` bytes can inject a forged prevout value that poisons the shared sighash, invalidating every signature in the transaction - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to the Treasury report — where `deposit()` accepts any token and any `amount`, letting an attacker inflate `_totalValue` so all subsequent legitimate operations fail — `ReceivedOutput::read` accepts attacker-controlled bytes including an arbitrary `TxOut` with an arbitrary satoshi `value`, and `SignableTransaction::new`/`TransactionSignMachine::sign` then fold that unvalidated value into `Prevouts::All` for every input. Since BIP-341 key-spend sighashes commit to *all* prevout amounts, one forged `ReceivedOutput` invalidates the signatures of all co-spent legitimate inputs, denying the protocol's spend.

### Finding Description
`ReceivedOutput::read` deserializes an offset, a `TxOut`, and an `OutPoint` from a byte stream with no validation of the output's value, its script relationship to the offset, or its existence on-chain (`networks/bitcoin/src/wallet/mod.rs:122-134`). The only consistency check performed later is in `SignableTransaction::multisig`, which verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` — i.e., the *script* is bound to the offset, but the *value* is not bound to anything (`networks/bitcoin/src/wallet/send.rs:275-282`).

When `TransactionSignMachine::sign` computes sighashes it uses `Prevouts::All(&self.tx.prevouts)` (`send.rs:375`), so the attacker-chosen `value` field is committed into `taproot_key_spend_signature_hash(i, ...)` for *every* input index `i`. Under BIP-341, each input's signature commits to the amounts of all spent outputs; if any single prevout amount differs from the real UTXO amount, all key-spend signatures in the transaction fail consensus validation. An attacker who can feed crafted bytes to `ReceivedOutput::read` (a path explicitly reachable with untrusted bytes) therefore injects a "deposit" whose inflated amount corrupts the shared accumulator — exactly the `_totalValue += amount` class — except here the corrupted aggregate is the sighash preimage, and the failed operation is the signature over every legitimate input in the batch.

Additionally, `input_sat` is computed with `sum::<u64>()` (`send.rs:175`) and `fee()` computes `sum(prevouts) - sum(outputs)` with plain subtraction (`send.rs:139-140`); a crafted value near `u64::MAX` can drive these sums to overflow/panic.

### Impact Explanation
- A single malformed `ReceivedOutput` causes the produced transaction to be consensus-invalid: BIP-341 requires `SIGHASH_ALL`/`Default` to commit to the true amounts of all prevouts, so every input's Schnorr signature is rejected by the network. This mirrors the report's impact — one unvalidated deposit DoSes all dependent operations — with the denial applying to the entire transaction, not just the malicious input.
- Overflow of `input_sat`/payment sums or the subtraction in `fee()` panics the signing flow (a correctness/DoS fault).
- If the byte path is used for reporting received funds, a forged value makes funds *appear* received at amounts they were not, satisfying the "funds reported received that are not spendable" acceptance criterion.

### Likelihood Explanation
Reachability requires an attacker to supply bytes deserialized via `ReceivedOutput::read` into transaction construction — a path the scan rules explicitly classify as attacker-reachable. No cryptographic break is needed; the attacker only chooses the `TxOut` value. However, the offset/script binding check in `multisig` limits forgery to the value field, and exploitation is per-transaction rather than persistent, so this rates Medium.

### Recommendation
- Bind each `ReceivedOutput` end-to-end: derive outputs only from `Scanner::scan_transaction` results (which carry real on-chain `TxOut`s), or re-verify each prevout against chain data before signing rather than trusting deserialized values.
- In `SignableTransaction::new`, use `checked_add`/`checked_sub` for `input_sat`, `payment_sat`, and `fee()`, returning `TransactionError` instead of panicking.
- In `multisig`, extend the existing script-binding check to also sanity-bound `prevouts[i].value` (e.g., `<= 21M BTC`) and reject deserialization of values that cannot be valid prevouts.

  5,
