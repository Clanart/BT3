### Title
Unauthenticated blame adjudication lets any observer brand an honest DKG participant faulty - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
The PedPoP DKG verifies a Schnorr proof-of-possession on every encrypted secret share to confirm the *sender* authored the message (`crypto/dkg/pedpop/src/encryption.rs:374-379`), and when the share itself is invalid the recipient produces an `EncryptionKeyProof` (a DLEq over their ECDH key) to adjudicate blame. However, `BlameMachine::blame` / `AdditionalBlameMachine::blame` accept arbitrary attacker-chosen `sender` and `recipient` indexes with `proof: Option<EncryptionKeyProof>` — and when `proof` is `None`, `decrypt_with_proof` returns `DecryptionError::InvalidProof`, which `blame_internal` maps to faulting the `recipient`. There is no check that the accusation actually originated from the recipient, nor that a proof is present. Analogous to the OpenClaw advisory (reaction ingress skipped the `dmPolicy`/`allowFrom` gate enforced on message ingress), the blame-adjudication ingress skips the "the accuser must be the recipient holding a decryption-key proof" gate that the real share-verification path enforces in `calculate_share` (where blame proofs are only produced for shares the local recipient itself decrypted).

### Finding Description
`calculate_share` only emits `PedPoPError::InvalidShare { participant: l, blame: Some(proof) }` after the *local* party decrypted its own share and verified it — the accusation is inherently bound to the genuine recipient (`crypto/dkg/pedpop/src/lib.rs:476-499`). The standalone blame path drops this binding:

- `BlameMachine::blame(self, sender, recipient, msg, proof)` → `blame_internal` (`lib.rs:623-632`).
- `AdditionalBlameMachine::blame(&self, sender, recipient, msg, proof)` is explicitly usable "regardless of if the caller was a member in the DKG protocol" (`lib.rs:639-682`).
- In `blame_internal`, `decrypt_with_proof(sender, recipient, msg, proof)` first verifies `msg.pop` bound to `sender` (`encryption.rs:374-379`), then, `if let Some(proof)` fails when `proof` is `None`, returning `Err(DecryptionError::InvalidProof)` (`encryption.rs:381-396`).
- `blame_internal` translates `InvalidProof` into `return recipient` — declaring the recipient faulty (`lib.rs:586-588`).

So any party holding a copy of participant A's authentic `EncryptedMessage` to participant B (whose PoP verifies) can call `blame(A, B, msg, None)` — or `AdditionalBlameMachine::blame` as a non-participant — and the machine returns honest B as the faulty party. No proof of an actual accusation by B is required. The PoP transcript binds `sender` but nothing binds the accuser (`encryption.rs:302-324`).

### Impact Explanation
`BlameMachine::blame` consumes the machine and forces abort; `AdditionalBlameMachine::blame` always identifies a faulty party by design. Mis-attributing fault to an honest, non-accusing participant corrupts the DKG adjudication result. In Serai's usage, DKG blame/fault outcomes feed participant removal and slashing (e.g., `RemoveParticipantDueToDkg`/`fatal_slash` flows in `coordinator/src/tributary/handle.rs`), so a third party can cause an honest validator to be marked faulty and the DKG attempt aborted using only a relayed copy of a legitimately-authenticated encrypted share. This is an authorization-omission on a reachable adjudication path, not a validator-collusion or networking assumption.

### Likelihood Explanation
Reachable by any unprivileged party that obtains one authentic `EncryptedMessage<C, SecretShare>` — the API documentation itself contemplates third-party arbiters (`AdditionalBlameMachine::new` takes commitment messages and is callable by non-members, `lib.rs:639-662`). The attacker controls `sender`, `recipient`, `msg`, and `proof`; choosing `proof: None` deterministically yields `recipient` as faulty whenever `msg`'s PoP verifies, which it does for any genuine intercepted/relayed share message. No threshold collusion, key knowledge, or malformed-curve inputs are needed.

### Recommendation
In `blame_internal` (or `decrypt_with_proof`), require `proof` to be `Some` before attributing fault to `recipient` — a missing proof should fault the *sender* of the accusation path or return an error, never the accused `recipient`. Additionally validate that `sender`/`recipient` are distinct participants present in `self.commitments`/`self.enc_keys` before indexing (out-of-set indexes currently panic at `self.enc_keys[&decryptor]`, `encryption.rs:388`), and consider binding the recipient into the PoP/decryption transcript so an accusation cannot be replayed against an arbitrary target.

### Proof of Concept
```rust
// Any party (including a non-DKG-member via AdditionalBlameMachine) holding a copy
// of participant A's authentic encrypted share to participant B:
let msg: EncryptedMessage<C, SecretShare<C::F>> = /* A -> B share, relays/copies it */;

// A's PoP verifies (msg.key, pop_challenge(context, R, key, A, ciphertext)).
// proof = None => decrypt_with_proof returns Err(InvalidProof)
// => blame_internal returns `recipient` (B) as faulty.
let faulty = blame_machine.blame(
    Participant::new(A).unwrap(),
    Participant::new(B).unwrap(),
    msg,
    None,            // no EncryptionKeyProof: no evidence B ever accused anyone
).1;
assert_eq!(faulty, Participant::new(B).unwrap()); // honest B declared faulty
```
