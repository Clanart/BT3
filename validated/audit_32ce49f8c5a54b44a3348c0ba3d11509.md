### Title
Payout OP_RETURN operator attribution is not covered by the user's payout signature, allowing payout credit to be redirected away from the operator who actually fronted it - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the payout transaction with a `NotStored`/`KeySpend` signature from the withdrawing user over input 0, but the OP_RETURN output that records *which operator fronted the withdrawal* (`operator_xonly_pk`) is a separate, third output. If the user's signature type only commits to the corresponding output index (single-input/single-output binding, as used elsewhere in the protocol for withdrawal-type payouts), the OP_RETURN payload is not bound by the same signature that authorizes spending the withdrawal UTXO. Whoever finally assembles/broadcasts the confirmed payout transaction chooses the OP_RETURN's `operator_xonly_pk`, and that value is what `verifier.rs::update_finalized_payouts` (`core/src/verifier.rs:2313-2342`) trusts to attribute the fronting operator, which later drives `payout_payer_operator_xonly_pk`, `validate_payer_is_operator` (`core/src/operator.rs:1687-1740`), `PayoutCheckerTask` (`core/src/task/payout_checker.rs:41-79`), and ultimately who is allowed to run the kickoff/reimbursement flow and collect the reimburse-connector payout (`core/src/builder/transaction/operator_reimburse.rs:341-385`).

### Finding Description
The equality that must hold for correct custody attribution is:
`operator credited for reimbursement == operator whose funds actually left their wallet to pay the user`

The flow is:
1. `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds a transaction with: output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN containing `operator_xonly_pk`. The witness for input 0 is a single Schnorr signature from the user (`txhandler.set_p2tr_key_spend_witness(&user_sig, 0)`), and `aggregator.rs` comments explicitly require this signature to use the `SinglePlusAnyoneCanPay` sighash type (`core/src/rpc/aggregator.rs:1120-1126`).
2. A `SIGHASH_SINGLE|ANYONECANPAY` signature only commits to the single input being spent and to the *output at the same index* (index 0). It does **not** commit to any other output, including output 2 (the OP_RETURN carrying the operator attribution).
3. This means the OP_RETURN payload can be swapped for any other `operator_xonly_pk` after the user signs, without invalidating the signature, as long as the swap happens before the transaction confirms.
4. On confirmation, `verifier.rs::update_finalized_payouts` parses whatever OP_RETURN ends up on-chain and stores it as `payout_payer_operator_xonly_pk` (`core/src/verifier.rs:2319-2342`), with no cross-check that the party who broadcast the tx or who is named in OP_RETURN is the one whose keys/wallet actually funded output 0.
5. `validate_payer_is_operator` (`core/src/operator.rs:1687-1740`) and `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:41-79`) then trust this DB column to authorize the named operator's kickoff/round/reimburse flow, ultimately paying out the reimburse-connector UTXO to that operator's `operator_reimbursement_address` in `create_reimburse_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:341-385`).

This is analogous to the Atlas `reconcile()` bug: a value (here, "credit for having funded a payout") is attributed/registered based on unauthenticated data (the OP_RETURN) that is not actually bound to the economic action that is supposed to justify it (the user's authorization to spend their withdrawal UTXO to a specific operator).

### Impact Explanation
If this path is exploitable as described, an operator that never fronted a withdrawal could have themselves credited as the payer by substituting the OP_RETURN before the payout transaction confirms, and subsequently claim the reimbursement (BTC from the reimburse-connector output) that is meant to compensate the operator who genuinely paid the user. This matches the "operator reimbursed for a payout it never funded" and "honest operator permanently unable to be reimbursed" impact categories (the honest operator who paid the user would find their claim rejected by `validate_payer_is_operator` because the DB now names a different `payer_xonly_pk`).

### Likelihood Explanation
I could not fully verify, within the available tool budget, that:
- output 2 (OP_RETURN) is genuinely excluded from the signed message for every payout signature variant (`Payout`, `OptimisticPayout`, `Withdraw`) used in this codebase — I found strong circumstantial evidence (comment in `aggregator.rs` mandating `SinglePlusAnyoneCanPay`, and the payout tx's OP_RETURN being a third output while only a single-input keyspend signature exists), but did not directly inspect `parse_withdrawal_sig_params` (`core/src/rpc/parser/operator.rs`) or the exact sighash construction in `actor.rs`/`txhandler.rs` to confirm the sighash flags actually used at signing/verification time.
- whether there is a separate consensus-level check (e.g., in the bridge circuit or in `is_kickoff_malicious`, `core/src/verifier.rs:1859-1915`) that cross-validates the OP_RETURN operator against something signed by the user, which would neutralize the attack. `is_kickoff_malicious` only checks that the kickoff's operator matches the OP_RETURN operator and the committed blockhash — it does not independently verify that the named operator's own funds paid for output 0.
- exploiting this requires the attacker to already be a registered operator with valid pre-signed round/kickoff/reimburse-connector transactions bound to their own `xonly_pk` (produced by the N-of-N verifier signing ceremony during operator setup). This is a significant precondition; per the scope rules, findings requiring an "operator" role are explicitly out of scope. This substantially weakens or disqualifies the finding as a genuinely "unprivileged-attacker" analog, since only an already-registered operator (not an arbitrary outsider) can realize the reimbursement payoff.

Given this unresolved role precondition and the unconfirmed sighash detail, I cannot assert with confidence that this rises to a valid, in-scope, unprivileged-attacker finding under the stated rules.

### Recommendation
If confirmed that the OP_RETURN output is not covered by the user's payout signature: bind the operator attribution to the signed data (e.g., require the user's payout signature to use `SIGHASH_ALL` or otherwise cover all outputs including the OP_RETURN), or have the aggregator/verifiers independently attest (via their own signature over the specific `operator_xonly_pk`) which operator is authorized to claim reimbursement for that specific payout, rather than trusting an arbitrary on-chain OP_RETURN value parsed post-hoc by `update_finalized_payouts`.

### Proof of Concept
Not constructed — doing so would require confirming the exact sighash flags used for the `Payout`/`OptimisticPayout`/`Withdraw` transaction variants (in `core/src/actor.rs` and `core/src/rpc/parser/operator.rs`) and confirming that malleating output 2 before confirmation does not invalidate the witness, which I was unable to verify within the remaining tool budget. pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }
