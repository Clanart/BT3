### Title
`AppProxyVerification` signature validation has no timestamp/replay-window check, allowing indefinite replay of captured signed App Proxy requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#verify_proxy_request` validates that the `signature` query parameter matches an HMAC computed over the other query parameters, but never validates the `timestamp` parameter against the current time. [1](#0-0) 

### Finding Description
Shopify signs App Proxy requests with an HMAC signature computed from the sorted query parameters (including a `timestamp` field), and forwards them to the app. `AppProxyVerification#query_string_valid?` recomputes the signature and does a `secure_compare` against the supplied `signature`, but it deletes `timestamp` from the hash only to include it in the signed payload — it never checks that `timestamp` is recent. [2](#0-1) 

This is directly analogous to the ChainlinkAdapterOracle bug class: the report's root cause is that a value considered "verified" (the aggregator's returned price) continues to be trusted by downstream logic without checking it against a valid bound (min/max price, or in this case, a valid time window), letting stale/out-of-bound data be treated as fresh and correct. Here, a signed query string with an old `timestamp` is treated exactly the same as a freshly-issued one — the code never enforces the "valid bound" (freshness) it was supposed to check.

Any request whose full query string (including `signature` and `timestamp`) is captured once — e.g. leaked via browser history, shared links, logs, Referer headers, proxies, or a malicious embedded script on the storefront page — remains a permanently valid, replayable request against any controller including this concern (e.g. `AppProxyController`, generated via `rails generate shopify_app:app_proxy_controller`). [3](#0-2) 

### Impact Explanation
An attacker who obtains one valid, previously-issued signed App Proxy URL for a shop can replay it forever to any endpoint that only relies on `AppProxyVerification` for authorization, since the concern accepts old timestamps identically to new ones. Depending on what the app-specific App Proxy controller does with the verified `shop` parameter (e.g. reading/writing shop-scoped data), this can enable unauthorized/anonymous access to shop-scoped functionality outside of the request's intended validity window, effectively a forged/accepted "stale signed request" issue analogous to the oracle continuing to trust stale bounded data.

### Likelihood Explanation
Requires the attacker to have observed one legitimately signed App Proxy request for the target shop (e.g., via browser network logs, a shared/reflected URL, or non-HTTPS transport/logging along the path) — this is a realistic, unprivileged capture vector since App Proxy requests are plain GET query strings, not one-time-use tokens, and there is no built-in expiry enforcement in the gem.

### Recommendation
In `query_string_valid?`, extract and validate the `timestamp` parameter (e.g., reject if it's missing, non-numeric, or older than a configurable threshold such as a few minutes) before/alongside the signature comparison, mirroring Shopify's guidance that App Proxy signatures should be treated as time-bound.

### Proof of Concept
1. Capture a valid, fully-formed App Proxy request URL for a shop (e.g., from a shared link, browser history, or logs), including its `signature` and `timestamp` query parameters.
2. Wait past any reasonable freshness window (minutes, hours, days).
3. Replay the exact same query string against the App Proxy controller endpoint.
4. Observe that `query_string_valid?` still returns `true` and the request is processed as authorized, because only signature correctness — not timestamp freshness — is checked. [4](#0-3)

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
