### Title
No Mechanism to Remove a Registered Operator from Verifier DB, Permanently Blocking Deposits When Operator Must Be Excluded — (File: `core/src/verifier.rs`, `core/src/database/operator.rs`)

---

### Summary

The `Verifier::set_operator` function (exposed via the `SetOperator` gRPC) permanently writes an operator into the verifier's PostgreSQL `operators` table. No production RPC, no database function, and no SQL `DELETE FROM operators` path exists anywhere in the codebase to undo this registration. The only off-ramp is the operator voluntarily spending their own collateral UTXO on-chain. Because `is_deposit_valid` enforces that every operator in the DB whose collateral is still live **must** appear in every new deposit, a compromised or misbehaving operator that refuses to exit cannot be excluded, permanently blocking all new deposits until the operator cooperates.

---

### Finding Description

`Verifier::set_operator` in `core/src/verifier.rs` calls `db.insert_operator_if_not_exists`, which issues:

```sql
INSERT INTO operators (xonly_pk, wallet_reimburse_address, collateral_funding_outpoint)
VALUES ($1, $2, $3)
ON CONFLICT (xonly_pk) DO NOTHING
``` [1](#0-0) 

There is no corresponding `delete_operator`, `remove_operator`, or any `DELETE FROM operators` query anywhere in the codebase. A grep for `DELETE FROM operators` returns zero results. The proto service definition exposes `SetOperator` but no `RemoveOperator` or `UnsetOperator` RPC. [2](#0-1) 

At deposit-signing time, `is_deposit_valid` iterates every operator row in the DB and calls `collateral_check` on each. If an operator's collateral UTXO is still unspent on-chain, the verifier **rejects** any deposit that omits that operator:

```rust
// if operator is not in deposit but its collateral is still on chain, return false
if !operators_in_deposit_data.contains(xonly_pk) && is_collateral_usable {
    return Err(BridgeError::InvalidDeposit(reason));
}
``` [3](#0-2) 

The test suite explicitly documents this invariant and its consequence:

```
// remove an operator and try a deposit, it should fail because the operator is still in verifiers DB.
// to make it not fail, operator data needs to be removed from verifiers DB.
``` [4](#0-3) 

The only documented workaround is for the operator to spend their own collateral UTXO outside the protocol, which `collateral_check` detects and treats as protocol exit: [5](#0-4) 

---

### Impact Explanation

If an operator's signing key is compromised, or an operator simply refuses to cooperate:

1. **All new deposits are permanently blocked.** The aggregator cannot construct a deposit that excludes the operator, because every verifier will call `is_deposit_valid`, find the operator in its DB with live collateral, and return `BridgeError::InvalidDeposit`. No new BTC can be bridged to Citrea until the operator exits.

2. **Forced inclusion of a compromised operator.** If the aggregator instead keeps the compromised operator in the deposit to avoid the rejection, the compromised operator participates in every new deposit's N-of-N signing ceremony and can produce fraudulent kickoffs against any of those deposits. Verifiers must then spend resources on BitVM disprove challenges for every affected deposit.

3. **No administrative escape hatch.** Unlike the collateral-spending path (which requires the operator's private key), there is no privileged admin RPC that verifiers or the aggregator can call to purge the stale DB row.

---

### Likelihood Explanation

Operator key compromise is a realistic operational risk for any long-running bridge. The scenario also arises non-maliciously: an operator that loses access to their key material cannot spend their collateral to exit, leaving the bridge permanently deadlocked. The test suite already exercises this exact failure mode and confirms it is reachable in production.

---

### Recommendation

Add a `remove_operator` function to the `Database` layer:

```sql
DELETE FROM operators WHERE xonly_pk = $1;
```

Expose it through a new `RemoveOperator` gRPC on `ClementineVerifier`, callable only by the aggregator (or a designated admin key), with a guard that prevents removal while any deposit signed by that operator still has an open kickoff/challenge window. This mirrors the `blacklist()` fix applied to `BondBaseCallback` in the referenced report.

---

### Proof of Concept

1. Start the bridge with operators A and B registered in all verifiers' DBs.
2. Operator B's key is compromised. Operator B refuses to spend their collateral.
3. The aggregator updates its config to exclude operator B and calls `new_deposit`.
4. The aggregator calls `SetOperator` on each verifier for operator A only, then initiates a deposit signing session that lists only operator A.
5. Each verifier's `is_deposit_valid` calls `db.get_operators()`, finds operator B with a live collateral UTXO, and hits the guard at `core/src/verifier.rs:630`, returning `BridgeError::InvalidDeposit("Operator B is still in protocol but not in the deposit data from aggregator")`.
6. The deposit fails. No new BTC can be bridged until operator B voluntarily spends their collateral — which a compromised or uncooperative operator will not do. [6](#0-5) [1](#0-0)

    pub async fn insert_operator_if_not_exists(
        &self,
        mut tx: Option<DatabaseTransaction<'_>>,
        xonly_pubkey: XOnlyPublicKey,
        wallet_address: &bitcoin::Address,
        collateral_funding_outpoint: OutPoint,
    ) -> Result<(), BridgeError> {
        let query = sqlx::query(
            "INSERT INTO operators (xonly_pk, wallet_reimburse_address, collateral_funding_outpoint)
             VALUES ($1, $2, $3)
             ON CONFLICT (xonly_pk) DO NOTHING",
        )
        .bind(XOnlyPublicKeyDB(xonly_pubkey))
        .bind(AddressDB(wallet_address.as_unchecked().clone()))
        .bind(OutPointDB(collateral_funding_outpoint));

        let result = execute_query_with_tx!(self.connection, tx.as_deref_mut(), query, execute)?;

        // If no rows were affected, data already exists - check if it matches
        if result.rows_affected() == 0 {
            let existing = self.get_operator(tx, xonly_pubkey).await?;
            if let Some(op) = existing {
                if op.reimburse_addr != *wallet_address
                    || op.collateral_funding_outpoint != collateral_funding_outpoint
                {
                    return Err(BridgeError::OperatorDataMismatch(xonly_pubkey));
                }
            }
        }

        Ok(())
    }

    pub async fn set_operator(
        &self,
        collateral_funding_outpoint: OutPoint,
        operator_xonly_pk: XOnlyPublicKey,
        wallet_reimburse_address: Address,
        operator_winternitz_public_keys: Vec<winternitz::PublicKey>,
        unspent_kickoff_sigs: Vec<Signature>,
    ) -> Result<(), BridgeError> {
        tracing::info!("Setting operator: {:?}", operator_xonly_pk);
        let operator_data = OperatorData {
            xonly_pk: operator_xonly_pk,
            collateral_funding_outpoint,
            reimburse_addr: wallet_reimburse_address,
        };

        let kickoff_wpks = KickoffWinternitzKeys::new(
            operator_winternitz_public_keys,
            self.config.protocol_paramset().num_kickoffs_per_round,
            self.config.protocol_paramset().num_round_txs,
        )?;

        if !self
            .rpc
            .collateral_check(
                &operator_data,
                &kickoff_wpks,
                self.config.protocol_paramset(),
            )
            .await?
        {
            return Err(eyre::eyre!(
                "Collateral utxo of operator {:?} does not exist or is not usable in bitcoin, cannot set operator",
                operator_xonly_pk,
            )
            .into());
        }

        let tagged_sigs = self.verify_unspent_kickoff_sigs(
            collateral_funding_outpoint,
            operator_xonly_pk,
            operator_data.reimburse_addr.clone(),
            unspent_kickoff_sigs,
            &kickoff_wpks,
        )?;

        let operator_winternitz_public_keys = kickoff_wpks.get_all_keys();
        let mut dbtx = self.db.begin_transaction().await?;
        // Save the operator details to the db
        self.db
            .insert_operator_if_not_exists(
                Some(&mut dbtx),
                operator_xonly_pk,
                &operator_data.reimburse_addr,
                collateral_funding_outpoint,
            )
            .await?;

        self.db
            .insert_operator_kickoff_winternitz_public_keys_if_not_exist(
                Some(&mut dbtx),
                operator_xonly_pk,
                operator_winternitz_public_keys,
            )
            .await?;

        let sigs_per_round = self.config.get_num_unspent_kickoff_sigs()
            / self.config.protocol_paramset().num_round_txs;
        let tagged_sigs_per_round: Vec<Vec<TaggedSignature>> = tagged_sigs
            .chunks(sigs_per_round)
            .map(|chunk| chunk.to_vec())
            .collect();

        for (round_idx, sigs) in tagged_sigs_per_round.into_iter().enumerate() {
            self.db
                .insert_unspent_kickoff_sigs_if_not_exist(
                    Some(&mut dbtx),
                    operator_xonly_pk,
                    RoundIndex::Round(round_idx),
                    sigs,
                )
                .await?;
        }

        #[cfg(feature = "automation")]
        {
            StateManager::<Self>::dispatch_new_round_machine(&self.db, &mut dbtx, operator_data)
                .await?;
        }
        dbtx.commit().await?;
        tracing::info!("Operator: {:?} set successfully", operator_xonly_pk);
        Ok(())
    }
