### Title
Spoofable `WWW-Authenticate` realm allows an untrusted git remote to trigger a GitHub Enterprise sign-in flow bound to an attacker-controlled origin - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The credential-helper trampoline decides whether a git remote "looks like" a GitHub/GHE host by inspecting the `wwwauth[]` values Git forwards from the server's `WWW-Authenticate` header, specifically searching for the substring `realm="GitHub"`. This value is fully attacker-controlled: it comes verbatim from the HTTP response of whatever git server/proxy Desktop is talking to. When the derived "endpoint kind" is not `generic` and no existing account matches the endpoint, Desktop calls `trampolineUIHelper.promptForGitHubSignIn(endpoint)`, which for any non-`github.com` hostname invokes `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` using the attacker-controlled `origin` taken directly from the credential URL.

### Finding Description
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` classifies a git remote's authentication realm by scanning the `wwwauth[]` credential fields for a matching realm string: [1](#0-0) 

These `wwwauth[]` entries are populated by Git itself from the server's HTTP `WWW-Authenticate` header and passed through the standard git credential-helper protocol, which `parseCredential` decodes without any validation of origin/trust: [2](#0-1) 

`getCredential` uses this classification to decide the sign-in path when no existing account is bound to the endpoint: [3](#0-2) 

Finally, `promptForGitHubSignIn` treats any hostname other than `github.com` as an Enterprise server and initiates the enterprise sign-in flow, seeding it with the attacker-supplied `origin`: [4](#0-3) 

The broken invariant: Desktop's decision to present its trusted "Sign in to GitHub Enterprise" UI (and bind the resulting account to that origin) is driven by an unauthenticated string echoed from a remote HTTP response, not by any cryptographic or allowlist verification that the target really is a GitHub Enterprise Server instance. A malicious or compromised git server (or a MITM proxy on a plain-HTTP remote) can respond to a git fetch/clone/push request with a header such as `WWW-Authenticate: Basic realm="GitHub"` to force this code path even though the host has nothing to do with GitHub.

### Impact Explanation
Because the endpoint classification only requires no pre-existing account for that host, any first-time interaction with a malicious remote (adding it, fetching, cloning) can cause Desktop's native sign-in dialog to open and silently target the attacker's origin as if it were a legitimate GitHub Enterprise Server, per `setSignInEndpoint(origin)`. Since this UI is otherwise indistinguishable from a genuine Enterprise sign-in prompt, a user who enters personal credentials/PAT there would be submitting them to the attacker-controlled host. This falls under "unauthorized OAuth or account binding" — an untrusted git remote response is able to steer where Desktop's authenticated sign-in flow points, without the user ever navigating to that host directly.

### Likelihood Explanation
The trigger requires nothing beyond the user performing an ordinary git operation (fetch/clone/push) against a remote controlled by, or in the network path of, the attacker (e.g. a self-hosted/forked repo the user is invited to add, or a MITM on an HTTP — not HTTPS — remote). No local access, admin rights, or prior compromise of the host is required, and the substring match on `realm="GitHub"` is trivial to include in an HTTP response header.

### Recommendation
Do not derive "this is a GitHub/GHE host" trust decisions from attacker-controlled `WWW-Authenticate` header contents alone. Require corroboration, e.g. only trust `wwwauth[]` realm hints for hosts already present in an explicit user-configured Enterprise endpoint list, or perform a server-side capability/API probe (already used elsewhere via `isGitHubHost`) before offering the sign-in flow, rather than accepting the header hint at face value in `getEndpointKind`.

### Proof of Concept
1. Stand up an HTTP git server (or MITM proxy in front of an HTTP git remote) that, on any request, adds the response header:
   `WWW-Authenticate: Basic realm="GitHub"`
2. In GitHub Desktop, clone or fetch from `http://attacker.example/repo.git` for the first time (no existing account bound to `attacker.example`).
3. Git forwards the header to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind` returns `'enterprise'`; since no account matches `attacker.example`, `getCredential` calls `ui.promptForGitHubSignIn('http://attacker.example/...')`.
5. `promptForGitHubSignIn` sees hostname !== `github.com`, calls `beginEnterpriseSignIn` and `setSignInEndpoint('http://attacker.example')`, opening Desktop's native GitHub Enterprise sign-in dialog scoped to the attacker's origin.

Note: I could not fully trace, within the remaining tool budget, whether the downstream Enterprise sign-in flow (`sign-in-store.ts`/`app-store.ts`) performs any additional server validation (e.g., checking `/meta` or a real GHE API) before accepting credentials against `origin`; if such validation exists it may reduce (but not eliminate, since the origin is still attacker-controlled and the popup itself is misleading) the practical impact. This should be verified in a full Devin session with complete file access.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
