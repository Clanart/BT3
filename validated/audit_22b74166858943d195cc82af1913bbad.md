### Title
Identity public keys enable universal Schnorr signature forgeries - (File: crypto/schnorr/src/lib.rs)

### Summary
`SchnorrSignature::verify` does not reject the identity public key, and `SchnorrSignature::read` does not reject identity nonces. A signature whose nonce commitment is `R = sG` therefore verifies for the identity public key under every challenge, allowing an attacker to forge signatures whenever an identity key can be supplied or decoded.

### Finding Description
`SchnorrSignature::read` accepts any canonical point for `R` and any canonical scalar for `s`. [1](#0-0)  The generic `Ciphersuite::read_G` implementation validates only that the point decodes and has canonical serialization; unlike the FROST-specific `Curve::read_G`, it does not reject identity. [2](#0-1) [3](#0-2) 

Verification checks `R + cA - sG == 0`. [4](#0-3) [5](#0-4)  If `A` is identity, the challenge term disappears and the equation becomes `R == sG`. An attacker can therefore choose any scalar `s`, set `R = sG`, and satisfy verification for every challenge and message.

### Impact Explanation
Any verifier that accepts attacker-selected public keys, or decodes an identity public key through the generic canonical point reader, will accept a valid-looking Schnorr signature without knowledge of a discrete logarithm. This is a signature forgery for the invalid identity key rather than merely a malformed-input acceptance issue.

### Likelihood Explanation
The attack is deterministic once an identity public key reaches `SchnorrSignature::verify`. No secret, randomness, or protocol participation is required. Systems that reject identity keys before calling this API are not affected, but the signature type itself is documented as strict while leaving this domain validation to callers.

### Recommendation
Reject identity in `SchnorrSignature::verify`, including the identity public key and identity nonce commitment. Rejecting `R = identity` in `SchnorrSignature::read` would additionally prevent canonical bytes for a zero nonce from reaching verification. If identity keys must remain representable internally, expose an explicit verified-key constructor or verifier API that enforces non-identity public keys.

### Proof of Concept
For any challenge `c`, choose a nonzero scalar `s` and set `R = sG` and `A = 0`. Verification computes:

```text
R + cA - sG
= sG + c·0 - sG
= 0
```

A Rust-shape demonstration is:

```rust
let s = C::F::from(42);
let signature = SchnorrSignature::<C> {
    R: C::generator() * s,
    s,
};

let public_key = C::G::identity();
let arbitrary_challenge = C::F::from(1337);

assert!(signature.verify(public_key, arbitrary_challenge));
```

This succeeds because `batch_statements` forms `R + cA - sG`, and `cA` is identity when `A` is identity. [6](#0-5)
