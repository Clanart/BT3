### Title
`SignableTransaction::new` omits the OP_RETURN output from the fee/weight calculation, producing transactions that underpay the requested fee rate — ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to the wfCash report (value silently stranded with no recovery path), `SignableTransaction::new` computes the transaction weight, vbytes, `needed_fee`, and the change amount from a transaction template that contains *only* the payment outputs — the OP_RETURN data output is pushed onto `tx_outs` before the weight calculation but is never included in it. The result is a transaction that pays a lower absolute fee than `fee_per_vbyte` requires, can fall below the mempool minimum relay fee despite passing the `TooLowFee` check, and can strand the inputs it spends.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is appended to `tx_outs` first, then the weight/vbytes are computed from `payments` alone:

```rust
// networks/bitcoin/src/wallet/send.rs
194:    if let Some(data) = data {
195:      tx_outs.push(TxOut { ... ScriptBuf::new_op_return(...) })
202:    }
204:    let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
206:    let mut needed_fee = fee_per_vbyte * vbytes;
```

`calculate_weight_vbytes` builds its template transaction from `payments`, not `tx_outs`, so the ~10–80-byte OP_RETURN output (plus its 9-byte `TxOut` overhead) is excluded from `vbytes`. The same omission propagates into the change path: `fee_with_change` is computed with `Some(&change)` but still over `payments`, so the change output is credited `input_sat - payment_sat - fee_with_change` where `fee_with_change` undershoots the true size:

```rust
226:      let (weight_with_change, vbytes_with_change) =
227:        Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
228:      let fee_with_change = fee_per_vbyte * vbytes_with_change;
228-234:      // change = input_sat - payment_sat - fee_with_change
```

The effective fee `input_sat - sum(outputs)` equals `needed_fee` (or `fee_with_change`), which is `fee_per_vbyte * (true_vbytes - ~13–89)`. The signed transaction therefore pays a lower sat/vbyte rate than requested. Because the `TooLowFee` guard at lines 211–213 also uses the underestimated `vbytes`, a caller-specified fee rate at or near `DEFAULT_MIN_RELAY_TX_FEE` can produce a transaction whose real fee rate is below the relay minimum — unbroadcastable, with the spent outputs appearing "consumed" by the produced `Transaction` yet never confirming.

### Impact Explanation
Any `SignableTransaction` built with `data: Some(_)` silently pays less than the configured fee rate. In the worst case the transaction is below `DEFAULT_MIN_RELAY_TX_FEE`, is rejected by the mempool, and the `ReceivedOutput` inputs it references are effectively locked: the threshold signing round already bound `Prevouts::All` commitments to this exact tx, so the produced transaction cannot confirm and the funds are stuck until a new signing round is coordinated. Even when relayable, it can languish unconfirmed (no RBF is signaled — `sequence: Sequence::MAX`), freezing funds. This mirrors the report's "assets accumulated but unrecoverable" class: value enters a state with no path to spend it.

### Likelihood Explanation
Medium. Triggering requires only constructing a transaction with `data` set — a normal, documented use of the API (`data` of up to 80 bytes is explicitly supported). The shortfall is proportional to the OP_RETURN output size (~13–89 vbytes ≈ 4–30% of a typical small transaction), so transactions built near the minimum fee rate will reliably land below the relay floor.

### Recommendation
Compute weight/vbytes from the actual output set. Change `calculate_weight_vbytes` to accept the full `tx_outs` (payments + OP_RETURN), or move the OP_RETURN insertion before the initial `calculate_weight_vbytes` call and pass `&tx_outs` — likewise for the `fee_with_change` computation so change accounts for the data output's real cost.

### Proof of Concept
```rust
// One input of 100_000 sats, one payment, OP_RETURN data of 80 bytes, fee rate at minimum
let inputs = vec![received_output_100k];
let payments = vec![(dest_script, 50_000u64)];
let tx = SignableTransaction::new(
    inputs, &payments, Some(change_script), Some(vec![0xaa; 80]),
    fee_per_vbyte /* = 1 sat/vbyte */,
).unwrap();

// needed_fee() was computed on a template lacking the ~89-byte OP_RETURN output.
// tx.transaction().vsize() > (needed_fee / fee_per_vbyte), so the true rate is < 1 sat/vb,
// below DEFAULT_MIN_RELAY_TX_FEE despite TooLowFee not being raised.
assert!(tx.transaction().vsize() as u64 > tx.needed_fee());
// Realized fee rate = tx.fee() / tx.transaction().vsize() < requested fee_per_vbyte.
```
