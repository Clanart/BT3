### Title
`transfer_outpoints_to_wallet` Fails to Guard `ReimburseInRound` UTXOs, Enabling Operator to Permanently Forfeit Reimbursement and Lock Bridged BTC — (`File: core/src/operator.rs`)

---

### Summary

`transfer_outpoints_to_wallet` (exposed as the `TransferToBtcWallet` gRPC) protects only collateral UTXOs from being swept to the operator's wallet. It does not protect `ReimburseInRound` UTXOs, which share the exact same script pubkey (operator plain taproot, no scripts) as collateral but are equally critical to the reimbursement flow. Sweeping one of these UTXOs makes the pre-signed `reimburse_tx` permanently unbroadcastable, locking the full bridge amount inside the vault UTXO and forfeiting the operator's reimbursement.

---

### Finding Description

`get_all_collateral_outpoints` enumerates three categories of protected outpoints:

1. `collateral_funding_outpoint` (initial collateral)
2. `CollateralInRound` (output 0 of every round tx)
3. `CollateralInReadyToReimburse` (output 0 of every ready-to-reimburse tx) [1](#0-0) 

`ReimburseInRound` UTXOs — the per-kickoff reimburse connector outputs in the round tx — are **not** in this set.

In `create_round_txhandler`, these outputs are created with empty scripts and the operator's xonly key as the internal key:

```rust
for _ in 0..paramset.num_kickoffs_per_round {
    builder = builder.add_output(UnspentTxOut::from_scripts(
        paramset.default_utxo_amount(),
        vec![],
        Some(operator_xonly_pk),
        paramset.network,
    ));
}
``` [2](#0-1) 

This produces the identical `script_pubkey` as the operator's signer address. The `transfer_to_btc_wallet` RPC handler accepts any outpoint whose `script_pubkey` matches `self.operator.signer.address.script_pubkey()`: [3](#0-2) 

Because `ReimburseInRound` outpoints pass this check and are absent from `get_all_collateral_outpoints`, they can be swept without error.

The `reimburse_tx` requires three inputs:

1. `DepositInMove` — the vault UTXO holding the full bridge amount
2. `ReimburseInKickoff` — signed by nofn
3. `ReimburseInRound` — signed by the operator (key-spend path) [4](#0-3) 

If `ReimburseInRound` is spent by `transfer_to_btc_wallet`, the pre-signed `reimburse_tx` becomes permanently invalid (double-spend of its third input). The vault UTXO (`DepositInMove`) — holding `bridge_amount` of bridged BTC — is then unreachable via the normal reimbursement path.

---

### Impact Explanation

- **Operator reimbursement is permanently lost.** The operator already fronted the payout to the user; without `reimburse_tx` they cannot recover the bridge amount.
- **Bridged BTC is locked in the vault.** The `DepositInMove` UTXO can only be spent by `reimburse_tx` (now broken), `optimistic_payout_tx` (requires a pending withdrawal + nofn cooperation), or the security council multisig. In the absence of a concurrent optimistic payout or security council action, the BTC is effectively frozen. [5](#0-4) 

---

### Likelihood Explanation

The `TransferToBtcWallet` RPC is operator-authenticated. The operator must supply the exact `ReimburseInRound` outpoint. This can happen accidentally (e.g., sweeping all plain-taproot UTXOs at the operator address without distinguishing their protocol role) or intentionally. The missing guard makes the error silent and irreversible once the sweep transaction confirms.

---

### Recommendation

Extend `get_all_collateral_outpoints` to also enumerate all `ReimburseInRound` outpoints for every round, mirroring the existing loop that collects `CollateralInRound` and `CollateralInReadyToReimburse`:

```rust
let reimburse_outpoint = OutPoint {
    txid: *round_tx.get_txid(),
    vout: UtxoVout::ReimburseInRound(kickoff_idx, paramset.num_kickoffs_per_round).get_vout(),
};
outpoints.insert(reimburse_outpoint, (round_idx, TransactionType::Round));
```

Add a corresponding rejection message in `transfer_outpoints_to_wallet` consistent with the existing collateral guard. [6](#0-5) 

---

### Proof of Concept

1. Complete a deposit so that a round tx is on-chain. The round tx has `num_kickoffs_per_round` `ReimburseInRound` outputs at vouts `num_kickoffs_per_round + 1` through `2 * num_kickoffs_per_round`, each paying to the operator's plain taproot address.
2. Operator calls `TransferToBtcWallet` with one of those outpoints (e.g., `round_txid:vout=num_kickoffs_per_round+1`).
3. The RPC passes the `script_pubkey` check and the collateral check (outpoint is absent from `get_all_collateral_outpoints`).
4. The sweep transaction confirms, spending `ReimburseInRound`.
5. Operator later attempts to broadcast `reimburse_tx`; Bitcoin rejects it because its third input is already spent.
6. The vault UTXO (`DepositInMove`) holding the full bridge amount is now unreachable via the reimbursement path. [7](#0-6) [8](#0-7)
