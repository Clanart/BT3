### Title
FieldMask path/comma-delimiter injection in `FieldMaskUtil.toJsonString` / `JsonFormat.printFieldMask` allows path smuggling - (File: `java/util/src/main/java/com/google/protobuf/util/FieldMaskUtil.java`)

### Summary
`google.protobuf.FieldMask.paths` is an ordinary `repeated string` field, so binary `FieldMask.parseFrom()` (or parsing of any message that embeds a `FieldMask`) accepts arbitrary attacker-controlled byte content in each path entry, including a literal comma (`,`) or `.`-delimiter characters, with no validation. When such a message is later serialized to ProtoJSON via `JsonFormat.Printer.print()`, `printFieldMask()` at `java/util/src/main/java/com/google/protobuf/util/JsonFormat.java:1111-1115` calls `FieldMaskUtil.toJsonString(value)`, which case-converts each path (`lowerUnderscoreToLowerCamel`, lines 137-152) and joins them with `String.join(",", paths)` (line 179) without ever checking that an individual path doesn't itself contain the `,` separator. A single attacker-supplied path such as `"a,b"` is therefore emitted as the two-element JSON field-mask string `"a,b"`, which is indistinguishable from two independent paths `a` and `b` to any downstream consumer that treats FieldMask JSON per spec (i.e. calls `FieldMaskUtil.fromJsonString` or an equivalent split-on-comma routine, `java/util/src/main/java/com/google/protobuf/util/FieldMaskUtil.java:186-197`).

### Finding Description
This is the structural analog of the reported bug class: the Spring AI `doKey()` function builds a backtick-delimited Cypher identifier from an attacker-controlled string but strips only double quotes, not the backtick delimiter itself, letting an attacker-controlled value "close" the identifier boundary early and inject additional Cypher syntax. In protobuf's `FieldMaskUtil`, the invariant that fails is analogous: the code assumes path segments never contain the `,` (or `.`) characters that are used as the *structural delimiter* when serializing/deserializing the FieldMask to its canonical string/JSON representation, but nothing enforces that invariant on the attacker-controlled `paths` values that arrive via ordinary binary/ProtoJSON parsing of the `FieldMask` message (or of any containing message) [1](#0-0) . `SnakeCaseToCamelCase`/`CamelCaseToSnakeCase` and their Java/Python counterparts only special-case uppercase letters and underscores; every other byte (comma, dot, control characters, backslash) passes straight through unchanged into the joined/split output [2](#0-1) [3](#0-2) . The join operation itself never checks for an embedded delimiter before emitting it [4](#0-3) , and `printFieldMask` in `JsonFormat` invokes this unguarded path directly from a parsed message with no additional validation [5](#0-4) .

### Impact Explanation
`FieldMask` is widely used by consuming applications (e.g., gRPC/REST APIs modeled on Google Cloud AIP conventions) to restrict which fields of a message may be read or updated — an "update mask" or "read mask" is a field-level access-control boundary. If an application accepts a `FieldMask`-bearing message from an untrusted binary/ProtoJSON source, re-serializes it with `JsonFormat` for logging, auditing, or forwarding to another service, and that second service re-parses the field mask with `FieldMaskUtil.fromJsonString` (the officially documented ProtoJSON round-trip), a single attacker-crafted path segment containing an embedded comma is split into multiple, unintended field paths on the receiving side. This is a data-integrity/authorization-boundary confusion: the intended path is silently reinterpreted as two different (and possibly unauthorized) field paths, matching CWE-943/CWE-89's "improper neutralization of special elements used in a downstream interpreter" bug class, without requiring memory corruption or crashes.

### Likelihood Explanation
The precondition — an application constructing/forwarding a `FieldMask` from data supplied by an ordinary client and later re-serializing/re-parsing it through the standard `JsonFormat`/`FieldMaskUtil` round trip — is a common, documented usage pattern for FieldMask in RPC APIs, so the trigger conditions are realistic. The `paths` field of the binary/ProtoJSON `FieldMask` message accepts arbitrary string bytes with zero validation at parse time, so no crafted schema or special permissions are needed; only a bounded client-supplied `FieldMask` value is required. However, unlike the Cypher case (where the delimiter injection directly rewrites a query the attacker never sees the result of), the impact here is entirely dependent on a specific application-level round-trip usage pattern, which is not universal to all FieldMask consumers, so likelihood is moderate rather than certain.

### Recommendation
In `FieldMaskUtil.toJsonString` (Java: `java/util/src/main/java/com/google/protobuf/util/FieldMaskUtil.java:171-180`), C++ `FieldMaskUtil::ToJsonString` (`src/google/protobuf/util/field_mask_util.cc:100-114`), and Python `FieldMask.ToJsonString` (`python/google/protobuf/internal/field_mask.py:17-22`), reject (or fail loudly on) any path segment containing the `,` separator character before joining, mirroring the existing rejection of uppercase letters in `SnakeCaseToCamelCase`/`lowerCamelToLowerUnderscore`. Apply the same check in `JsonFormat.printFieldMask` before delegating to `FieldMaskUtil.toJsonString`, and consider validating `FieldMask.paths` entries against the field-path grammar (letters, digits, underscore, dot only) at the point where a `FieldMask` is accepted from an untrusted `ParseFrom`.

### Proof of Concept
Conceptual reproduction (not run in this session — see caveat below):
1. Construct a binary-encoded `google.protobuf.FieldMask` message whose single `paths` repeated-string entry is the literal bytes `"secret_field,public_field"` — this is valid wire data for a `repeated string`; no proto-level constraint rejects the embedded comma.
2. Parse it with `FieldMask.parseFrom(bytes)` — succeeds, `mask.getPathsList()` == `["secret_field,public_field"]`, a single path.

4. Feed that string into `FieldMaskUtil.fromJsonString("secretField,publicField")` — returns a `FieldMask` with **two** paths: `secret_field` and `public_field`, differing from the originally-parsed single-path mask.

bool FieldMaskUtil::SnakeCaseToCamelCase(absl::string_view input,
                                         std::string* output) {
  output->clear();
  bool after_underscore = false;
  for (char input_char : input) {
    if (input_char >= 'A' && input_char <= 'Z') {
      // The field name must not contain uppercase letters.
      return false;
    }
    if (after_underscore) {
      if (input_char >= 'a' && input_char <= 'z') {
        output->push_back(input_char + 'A' - 'a');
        after_underscore = false;
      } else {
        // The character after a "_" must be a lowercase letter.
        return false;
      }
    } else if (input_char == '_') {
      after_underscore = true;
    } else {
      output->push_back(input_char);
    }
  }
  if (after_underscore) {
    // Trailing "_".
    return false;
  }
  return true;
}

bool FieldMaskUtil::CamelCaseToSnakeCase(absl::string_view input,
                                         std::string* output) {
  output->clear();
  for (const char c : input) {
    if (c == '_') {
      // The field name must not contain "_"s.
      return false;
    }
    if (c >= 'A' && c <= 'Z') {
      output->push_back('_');
      output->push_back(c + 'a' - 'A');
    } else {
      output->push_back(c);
    }
  }
  return true;
}

  /** Converts a lower_underscore to lowerCamelCase style. */
  private static String lowerUnderscoreToLowerCamel(String str) {
    StringBuilder sb = new StringBuilder();
    boolean capitalizeNext = false;
    for (int i = 0; i < str.length(); i++) {
      char c = str.charAt(i);
      if (c == '_') {
        capitalizeNext = true;
      } else if (capitalizeNext) {
        sb.append(Character.toUpperCase(c));
        capitalizeNext = false;
      } else {
        sb.append(Character.toLowerCase(c));
      }
    }
    return sb.toString();
  }

  /** Converts a lowerCamelCase string to lower_underscore style. */
  private static String lowerCamelToLowerUnderscore(String str) {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < str.length(); i++) {
      char c = str.charAt(i);
      if (c >= 'A' && c <= 'Z') {
        sb.append('_');
      }
      sb.append(Character.toLowerCase(c));
    }
    return sb.toString();
  }
