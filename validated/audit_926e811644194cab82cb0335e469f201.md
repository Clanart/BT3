### Title
Gasless swap deadline is only enforced at tx-pool admission, not at bundle-execution time, allowing expired `swapForGas` transactions to be included in a block - (File: kaiax/gasless/impl/getter.go, kaiax/gasless/impl/tx_pool.go)

### Summary
This mirrors the reported bug class: a restriction that is properly enforced in one validation path (`borrow()`'s 365-day check / here, `checkBalanceForSwap`'s deadline check) is missing from a second, combined execution path (`leverage()` / here, `VerifyExecutable`/`IsExecutable`, used for actual bundle assembly and promotion), allowing the restriction to be bypassed.

### Finding Description
The gasless module has two independent validators for a `GaslessSwapTx`:

1. `checkBalanceForSwap`, wired via `GetCheckBalance()`, which is run once when the transaction is admitted to the tx pool. This function explicitly enforces `tx.deadline >= currentTimestamp`: [1](#0-0) 

2. `VerifyExecutable` (used by `IsExecutable`), which is the authoritative check for whether a swap can actually be bundled and executed. It validates sender consistency, token match, approval amount, nonce sequencing, and repay amount, but never checks `swapArgs.Deadline` against the current block time: [2](#0-1) 

`VerifyExecutable`/`IsExecutable` is the function actually invoked at block-assembly/promotion time — from `ExtractTxBundles` (which builds the bundle placed into the block) and from `isSwapTxReady`/`isApproveTxReady` (tx-pool promotion gating): [3](#0-2) [4](#0-3) 

Because `checkBalanceForSwap` runs only once at admission, a swap transaction that is valid (deadline not yet passed) when submitted can remain in the queue (e.g., waiting for an approve tx to be sequenced, network congestion, or being deliberately delayed by the sender/searcher) and later have its deadline lapse. When it is finally promoted and bundled, the only re-validation performed is `VerifyExecutable`, which does not re-check the deadline, so the transaction bundle is still constructed and forwarded to `LendTxGenerator`/block building for execution.

No Solidity contract in the repository was found enforcing `deadline` on-chain either (`grep` for `deadline` in `*.sol` returned no matches), meaning the deadline guarantee for `swapForGas` relies entirely on this Go-level check — exactly the kind of restriction that, per the report's bug class, must be duplicated in every code path that can trigger execution, or a bypass results.

### Impact Explanation
An expired gasless swap can still be admitted into a block bundle and executed via the `LendTxGenerator`/router flow, bypassing the deadline safety guarantee that the gasless-swap price/quote calculation and `minAmountOut`/`amountRepay` accounting assumed to be fresh. This can lead to a sender being forced into (or a searcher exploiting) stale-price swap execution and repayment amounts that no longer reflect current market/gas conditions, i.e., fee-delegation/gasless settlement abuse and unauthorized value movement for the gasless sender.

### Likelihood Explanation
This requires no special privilege — any user submitting a `GaslessApproveTx`/`GaslessSwapTx` pair (or a third party observing pending gasless txs) can craft or wait for a scenario where the swap sits in the queue past its `deadline` due to normal network conditions (pending approve tx, congestion, bundle conflicts causing exclusion/retry) before being promoted, satisfying the "reachable from a single submitted transaction/bundle" bar.

### Recommendation
Add the same deadline check (`swapArgs.Deadline.Cmp(currentBlockTime) >= 0`) inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, so it is enforced consistently across both the admission path (`checkBalanceForSwap`) and the bundling/execution-readiness path (`IsExecutable`/`ExtractTxBundles`), matching the pattern of adding the missing restriction check to the combined function as recommended in the original report.

### Proof of Concept
1. Submit `GaslessApproveTx` (nonce N) and `GaslessSwapTx` (nonce N+1, `deadline = now + 5s`) as a valid pair; `checkBalanceForSwap` passes since `deadline >= currentTimestamp` at admission.
2. Delay promotion (e.g. because prior pending bundle conflicts exclude it per `ExtractTxBundles`'s conflict check, or the approve tx is momentarily not head-of-queue) until `now > deadline`.
3. When promotion/bundling occurs, `isSwapTxReady`/`ExtractTxBundles` call `IsExecutable`/`VerifyExecutable`, which validates sender/token/nonce/repay-amount but never re-checks `Deadline` — the bundle is built and forwarded for execution despite the swap being expired, confirmed by the absence of any deadline comparison in `VerifyExecutable`'s code path shown above.

// isSwapTxReady assumes that the caller checked `g.IsSwapTx(swapTx)`
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
