### Title
Overly broad hostname heuristic in `isGitHubHost` causes malicious remotes to be classified as GitHub Enterprise, triggering credential prompts / token exposure risk - ([File: app/src/lib/api.ts])

### Summary
`isGitHubHost()` uses a loose regular expression, `/(^|\.)(github)\./`, to decide whether an arbitrary remote hostname should be treated as a GitHub (Enterprise) host. Any hostname that merely contains a dot-delimited label `github` — e.g. `github.attacker.com` or `sub.github.attacker.com` — satisfies this check even though it has no relationship to the user's real GitHub or GHES accounts. This mirrors the "incorrect calculation → security check wrongly passes" bug class from the report: a check meant to gate a privileged code path (deciding a host is a *trusted* GitHub endpoint) is satisfied by attacker-controlled input due to an imprecise condition. [1](#0-0) 

### Finding Description
`isGitHubHost` is used exclusively by `getEndpointKind()` in the trampoline credential helper to decide whether a git remote should be handled as `'enterprise'` (GitHub) or `'generic'` (any other host): [2](#0-1) 

The classification order is:
1. Known GitHub.com/GHE endpoints (`isDotCom`/`isGHE`) — exact hostname matches, safe.
2. `WWW-Authenticate` header realm sniffing — requires server cooperation, not attacker-controlled alone.
3. An existing stored account matching the same origin.
4. Finally, if none of the above apply and the URL is HTTPS, it falls back to `isGitHubHost(endpoint)`, whose loose regex `/(^|\.)(github)\./.test(hostname)` returns `true` for any hostname containing a `github` label, e.g. `github.attacker.com`, without making a network round trip at all (that branch is reached before the runtime `/meta` HEAD-request check). [3](#0-2) 

Once `getEndpointKind` returns `'enterprise'` for such a malicious host, `getCredential()` takes the GitHub-specific branch instead of the generic-credential-helper/GCM branch: [4](#0-3) 

Specifically:
- If the user does not already have an account for that spoofed host, Desktop calls `ui.promptForGitHubSignIn(endpoint)` — presenting the user with a "Sign in to GitHub" flow for a host that is not actually GitHub, potentially setting up an OAuth/enterprise account binding to an attacker-controlled server under the guise of a trusted GitHub sign-in.
- Critically, because the check is done by hostname string alone and not validated against a truly registered/known-good GHE endpoint, this misclassification happens **silently**, with no user action other than adding/fetching from a repository whose remote URL contains a `github`-labeled hostname (e.g. cloning a repo that a user is social-engineered into adding as a remote, or a malicious fork/mirror advertised with such a hostname).
- Even in the branch where `endpointKind !== 'generic'` is true and an account *does* already exist for that endpoint (matched purely by `origin` equality in `findGitHubTrampolineAccount`), the generic/external-credential-helper path used for normal (non-GitHub) hosts is skipped entirely, which changes how credentials for that host are sourced and stored (internal Desktop-managed store vs. OS keychain/GCM), an unexpected and silent behavior change driven entirely by the substring-based hostname heuristic.

Existing guards do not stop this path: `isKnownThirdPartyHost` only excludes a fixed allow-list of unrelated hosts (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`); it has no denylist entry preventing `github.<attacker-domain>` from falling through to the vulnerable regex, and the regex itself is evaluated *before* the network-based `/meta` HEAD-request verification that would otherwise catch spoofed hosts.

### Impact Explanation
This does not itself exfiltrate an existing OAuth token to the attacker's server (the design intentionally keeps GitHub.com/GHE credentials in the internal store, matched by exact `origin`), but it:
- Misclassifies attacker-controlled infrastructure as a trusted "GitHub Enterprise" endpoint using only a naive string heuristic.
- Triggers an unsolicited "Sign in to GitHub" prompt for a host that is not GitHub, which can be leveraged for phishing/OAuth-binding attacks against unsuspecting users who trust the Desktop-native sign-in dialog.
- Silently diverts credential handling away from the generic/external credential helper path that would otherwise apply, an unexpected trust decision driven by attacker-chosen hostnames.

Given the valid-impact criteria (unauthorized OAuth/account binding via attacker-controlled remote), this reaches the "unauthorized OAuth or account binding" category, though it requires the victim to add/interact with a remote using a `github`-labeled hostname and to accept the resulting sign-in prompt — it is not a fully silent, no-user-interaction compromise.

### Likelihood Explanation
Moderate-low. The attacker must get the victim to configure or fetch/push against a git remote whose hostname contains a `github` label (e.g. `github.attacker.tld`), which is a plausible but non-trivial social-engineering step (domain squatting on "github"-branded hostnames is a well-known phishing technique). No local access, malware, or leaked credentials are required — only that Desktop performs a git credential lookup against that attacker-controlled remote, which happens automatically on clone/fetch/push.

### Recommendation
- Replace the substring/label heuristic in `isGitHubHost` with a strict allow-list/known-endpoint check (e.g., require that the endpoint was explicitly registered as a GHE endpoint by the user, or require successful verification via the authenticated `/meta` HEAD request with `x-github-request-id` for *every* unknown host rather than short-circuiting on the hostname pattern).
- At minimum, do not treat the regex match as authoritative for the `'enterprise'` classification without independent network verification (e.g., always require the `x-github-request-id` check for hosts not already known to the user).
- Log/telemetry and require explicit user confirmation before storing or reusing GitHub-flavored authentication flows for any endpoint discovered only through hostname pattern matching.

### Proof of Concept
1. Attacker sets up a GHES-look-alike server at `https://github.attacker.example` (any HTTPS server; it does not need to emulate the GitHub API).
2. Victim adds a remote/clones a repository whose URL is `https://github.attacker.example/foo/bar.git` (e.g., embedded in a malicious fork link or deep link).
3. On fetch, Desktop's git credential trampoline calls the credential `get` command; `getEndpointKind` runs through: not dotcom, not `.ghe.com`, no `WWW-Authenticate` header yet, no existing matching account, protocol is `https:` → falls to `isGitHubHost('https://github.attacker.example')`.
4. `isGitHubHost` computes `hostname = 'github.attacker.example'`; regex `/(^|\.)(github)\./.test('github.attacker.example')` evaluates to `true` (matches at the start), so the function returns `true` without ever reaching the `/meta` HTTP verification step. [3](#0-2) 
5. `getEndpointKind` returns `'enterprise'`; `getCredential` sees no account exists for `apiEndpoint` and calls `ui.promptForGitHubSignIn('https://github.attacker.example')`, presenting the native "Sign in to GitHub" dialog for the attacker's host. [5](#0-4)

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
