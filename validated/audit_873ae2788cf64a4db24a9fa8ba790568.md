## Analog Found: Division by zero in `google::protobuf::util` `Duration` operators [1](#0-0) [2](#0-1) [3](#0-2) 

### Title
Division by zero when dividing/modding by an attacker-supplied zero `Duration` - (File: `src/google/protobuf/util/time_util.cc`)

### Summary
The public, exported `TimeUtil`/`Duration` arithmetic operators `operator/(const Duration&, const Duration&)` and `operator%=(Duration&, const Duration&)` divide by the raw 128-bit integer representation of a second `Duration` operand without checking whether that operand is zero. Because `google.protobuf.Duration{}` (all-default/zero fields) is a perfectly valid, minimal wire-format message, any consuming application that parses an attacker-supplied `Duration` and uses it as the divisor in these operators triggers an unchecked integer division by zero.

### Finding Description
`operator/=(Duration&, int64_t)` guards against `r` being used unsafely only insofar as `int64_t` division semantics go, but the two operators that take a second `Duration` as the divisor never validate it:

```cpp
Duration& operator%=(Duration& d1, const Duration& d2) {  // NOLINT
  ...
  ToUint128(d1, &value1, &negative1);
  ToUint128(d2, &value2, &negative2);
  absl::uint128 result = value1 % value2;   // divide-by-zero if d2 == 0
  ...
}

int64_t operator/(const Duration& d1, const Duration& d2) {
  ...
  ToUint128(d1, &value1, &negative1);
  ToUint128(d2, &value2, &negative2);
  int64_t result = absl::Uint128Low64(value1 / value2);  // divide-by-zero if d2 == 0
  ...
}
``` [4](#0-3) 

`ToUint128` simply converts the `Duration`'s `seconds()`/`nanos()` fields into an `absl::uint128` magnitude with no zero-check:
```cpp
void ToUint128(const Duration& value, absl::uint128* result, bool* negative) {
  if (value.seconds() < 0 || value.nanos() < 0) {
    *negative = true;
    *result = static_cast<uint64_t>(-value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(-value.nanos());
  } else {
    *negative = false;
    *result = static_cast<uint64_t>(value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(value.nanos());
  }
}
``` [5](#0-4) 

These operators are declared `PROTOBUF_EXPORT` and are part of the public `time_util.h` API surface intended for use by any application handling `Duration` well-known-type values: [3](#0-2) [6](#0-5) 

**Failed invariant / analog to the M-19 report:** just as `sharesToTokenAmount` assumed `totalSharesMinted[_tokenAddress]` is always non-zero and never validated it before dividing, `operator/` and `operator%=` assume the `Duration` divisor is non-zero and never validate it before performing `value1 / value2` / `value1 % value2`. A `Duration{seconds:0, nanos:0}` is the *default*, fully-valid instance of this well-known type — it requires no malformed encoding, oversized buffer, or schema abuse to produce; an ordinary client can simply send an empty/zero-valued `Duration` submessage (or omit the fields entirely) through any standard `ParseFromString`/ProtoJSON parse call.

### Impact Explanation
Whereas the Solidity bug caused a Solidity `revert` (a catchable, contained failure), the C++ analog is worse: unsigned/`absl::uint128` integer division by zero is undefined behavior and on essentially all real hardware/compilers manifests as a `SIGFPE` hardware trap that terminates the process — it cannot be caught with a C++ `try`/`catch`. Any service that computes ratios or remainders between two `Duration` values derived from untrusted input (e.g., "elapsed / interval" rate calculations, quota/throttling logic keyed off an attacker-supplied interval `Duration`) is exposed to an unrecoverable denial-of-service crash from a single, entirely valid, minimal-size protobuf message.

### Likelihood Explanation
High likelihood of misuse: `Duration` is a documented well-known type specifically intended to represent spans like intervals/timeouts, and dividing/modding one `Duration` by another (e.g., to compute a count of intervals, or a phase within a period) is an expected, encouraged usage pattern of these exported operators. No adversarial schema, plugin, or deep nesting is required — the attacker only needs to supply a `Duration` field that is zero, which is the default/empty encoding on the wire.

### Recommendation
Add an explicit check in `operator/(const Duration&, const Duration&)` and `operator%=(Duration&, const Duration&)` (and any other place `ToUint128` is used as a divisor) that rejects or defines behavior for a zero-valued `Duration` divisor — e.g., `ABSL_CHECK`/documented precondition failure, or returning an error/optional rather than performing the raw division, mirroring how the recommended Solidity fix returns a defined value instead of dividing by zero.

### Proof of Concept
1. Parse (or construct) two `google.protobuf.Duration` messages from otherwise-trusted application logic where `d2` is populated from attacker-controlled input, e.g. `Duration d2; d2.ParseFromString(attacker_bytes);` where `attacker_bytes` is an empty byte string (0 bytes) — this is a fully valid encoding of `Duration{seconds:0, nanos:0}`.
2. Application code executes `int64_t ratio = d1 / d2;` or `d1 %= d2;` as documented usage of the exported `TimeUtil` operators [7](#0-6) .
3. Inside `operator/`/`operator%=`, `ToUint128(d2, &value2, &negative2)` yields `value2 == 0`, and the subsequent `value1 / value2` / `value1 % value2` on `absl::uint128` performs an integer division by zero, triggering undefined behavior (a `SIGFPE` crash on typical x86/ARM+GCC/Clang targets) — terminating the process that is parsing/handling the untrusted `Duration` input.

Duration& operator%=(Duration& d1, const Duration& d2) {  // NOLINT
  bool negative1, negative2;
  absl::uint128 value1, value2;
  ToUint128(d1, &value1, &negative1);
  ToUint128(d2, &value2, &negative2);
  absl::uint128 result = value1 % value2;
  // When negative values are involved in division, we round the division
  // result towards zero. With this semantics, sign of the remainder is the
  // same as the dividend. For example:
  //     -5 / 10    = 0, -5 % 10    = -5
  //     -5 / (-10) = 0, -5 % (-10) = -5
  //      5 / (-10) = 0,  5 % (-10) = 5
  ToDuration(result, negative1, &d1);
  return d1;
}
