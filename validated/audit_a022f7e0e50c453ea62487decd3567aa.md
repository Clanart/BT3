## Title
Ambiguous `WWW-Authenticate` Realm Heuristic Lets an Attacker-Controlled Git Server Trigger GitHub Sign-In Binding for a Spoofed Endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The underlying bug class in EL-2025-24 is that a single byte-level artifact (an "ambiguous" encoding) is accepted as authoritative evidence of a specific semantic meaning ("this is the point at infinity") without a canonical, unambiguous check, causing consumers to disagree about what entity they are dealing with. The same class of flaw exists in Desktop's git-credential trampoline: it classifies a remote endpoint as a trusted "GitHub"/"enterprise" host purely because the *attacker-controlled* HTTP response contains the substring `realm="GitHub"` in a `WWW-Authenticate` header, with no cryptographic or DNS-based verification of the claim.

## Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline, which calls `getEndpointKind` to decide how to treat the request: [1](#0-0) 

The relevant branch:
```
// When Git attempts to authenticate with a host it captures any
// WWW-Authenticate headers and forwards them to the credential helper. We
// use them as a happy-path to determine if the host is a GitHub host without
// having to resort to making a request ourselves.
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```
This header value (`wwwauth[...]`) originates entirely from the remote server's HTTP response — i.e., from an attacker who controls the git remote (a cloned/fetched repository's origin, or a proxy/MITM sitting on the connection). The string `realm="GitHub"` requires no proof of identity: any server can emit `WWW-Authenticate: Basic realm="GitHub"` on a 401 response.

Once `getEndpointKind` returns `'enterprise'`, `getCredential` treats the endpoint as a legitimate (though currently un-added) GitHub Enterprise host: [2](#0-1) 
```
const endpointKind = await getEndpointKind(cred, store)
...
if (
  endpointKind !== 'generic' &&
  !accounts.some(a => a.endpoint === apiEndpoint)
) {
  ...
  const account = await ui.promptForGitHubSignIn(endpoint)
  ...
  return credWithAccount(cred, account)
}
```
Because `endpointKind !== 'generic'`, Desktop skips the safer "generic host" credential-prompt path (`promptForCredential`, which shows the raw endpoint and lets the user store an arbitrary username/password) and instead invokes `ui.promptForGitHubSignIn(endpoint)`, Desktop's dedicated GitHub OAuth/PAT sign-in flow, using the attacker-supplied `endpoint` value as the target. This is a materially different, higher-trust UI path than the correct "generic git host" fallback, and it associates the resulting GitHub account object with the attacker's hostname (`credWithAccount`).

The invariant that's broken: "an endpoint is only treated as a GitHub/GHE host if it is verifiably one" — here it is decided solely from an attacker-controlled string comparison (`includes('realm="GitHub"')`) with no host validation (no check against `isGitHubHost`'s network probe, no TLS/cert check on the realm claim itself). This mirrors the EIP-2537 root cause: accepting a non-canonical/ambiguous representation as proof of a specific semantic without an unambiguous, verifiable check, letting different code paths (here: "generic" vs "enterprise" credential handling) diverge on the same untrusted input.

## Impact Explanation
An attacker who controls a git remote (e.g., a malicious origin the victim adds/clones, or a network position able to answer with a crafted 401 response during a fetch/push) can force Desktop to:
- Route the credential request into the GitHub sign-in flow instead of the generic-host flow, misrepresenting the endpoint's trust classification to the user.
- Cause `credWithAccount` to bind a real GitHub `Account` (login + real OAuth/PAT `password`/token) to the attacker-chosen `endpoint` string inside the credential map that is then formatted and returned to Git via `formatCredential`.
- Since the returned credential's `password` field is the user's actual GitHub token/PAT (see `credWithAccount`, `app/src/lib/trampoline/trampoline-credential-helper.ts:47-48`), and this credential is subsequently sent by Git to the attacker's server as part of Basic auth, this results in **credential/token exfiltration** to a host that never legitimately proved it was GitHub.

This satisfies the stated valid-impact category "unauthorized OAuth or account binding" / "credential/token exfiltration," driven purely by attacker-controlled response content (a git remote/proxy response), matching the required attacker model.

## Likelihood Explanation
Exploitation only requires the victim to perform a normal Desktop operation (fetch/push/clone) against a remote the attacker controls or can intercept, and for that server to answer an authentication challenge with a crafted `WWW-Authenticate` header. No local access, no malware, and no unnatural user steps beyond adding/using a remote are needed — this is within the explicitly allowed threat model ("attacker controls ... a git remote/proxy response").

## Recommendation
Do not classify a host as GitHub/Enterprise based solely on attacker-suppliable `WWW-Authenticate` realm text. Require an independent trust anchor before elevating trust: only accept the `wwwauth` heuristic as a *hint* to prefetch UI copy, but always fall back to (or double-check with) `isGitHubHost(endpoint)`'s explicit network-based verification (already used later in the function) before deciding to use the GitHub sign-in flow or binding an account to that endpoint.

## Proof of Concept
1. Attacker stands up an HTTPS git server at `https://attacker.example/victim/repo.git` (or intercepts traffic to any HTTP git remote the victim uses) and configures it to answer unauthenticated `git-upload-pack`/`git-receive-pack` requests with:
   `WWW-Authenticate: Basic realm="GitHub"`
2. Victim adds this URL as a remote in GitHub Desktop and performs a `fetch`/`push`.
3. Git invokes Desktop's credential trampoline; the `wwwauth[...]` value containing `realm="GitHub"` reaches `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`, returning `'enterprise'`.
4. `getCredential` (lines 93-125) sees no existing account for `apiEndpoint` and calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint = https://attacker.example`.
5. If the victim completes the GitHub sign-in prompt (believing it's tied to a legitimate GHE instance), the resulting `Account`'s token is bound via `credWithAccount` to the attacker's endpoint and returned as the Basic-auth password to the attacker's server on the next request, exfiltrating the victim's GitHub credential/token. /** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
