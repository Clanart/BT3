## Title
Forged CW20/CW721/CW1155 pointer contracts can emit fabricated wasm-event attributes that are mapped into synthetic ERC20/721/1155 EVM `Transfer`/`Approval` logs without any verification the underlying token action occurred - ([File: app/receipt.go])

### Summary
`AddCosmosEventsToEVMReceiptIfApplicable` translates raw `wasm` module event attributes (`action`, `amount`, `from`, `to`, `sender`, `recipient`, `owner`, `spender`, `token_id`, ...) emitted by *any* contract that has a registered CW→EVM pointer into synthetic ERC20/721/1155 log entries that are served on the public EVM JSON-RPC surface (`eth_getLogs`, `eth_getTransactionReceipt`, `eth_getBlockReceipts`). The attribute values are read verbatim from the contract's own `Response::add_attribute()` output with no check that they correspond to an actual balance change inside the contract. This is the same bug class as the reported Camel-Knative issue: attacker-controlled structured fields (there: CloudEvent JSON extensions; here: wasm event attributes) are copied straight into a trusted downstream representation (there: Camel message headers; here: canonical EVM logs) without any filter/validation strategy tying them to trustworthy data.

### Finding Description
`app.GetActionsFromWasmEvent` [1](#0-0)  walks every attribute of a `wasm`-typed event and blindly assigns `action`, `amount`, `from`, `to`, `sender`, `recipient`, `owner`, `spender`, `token_id` values into an `Action` struct with no cross-check against the contract's actual state transition. `AddCosmosEventsToEVMReceiptIfApplicable` calls this for every `wasm` event whose `_contract_address` matches a contract that has a registered ERC20/721/1155 pointer, and unconditionally builds synthetic `ethtypes.Log` entries (ERC20 `Transfer`/`Approval`, ERC721 `Transfer`/`Approval`/`ApprovalForAll`, ERC1155 `TransferSingle`/`TransferBatch`/`ApprovalForAll`) from whatever `action` string is present [2](#0-1) .

Registering a pointer is permissionless: `AddCW20`/`AddCW721`/`AddCW1155` on the `pointer` precompile only checks that no pointer exists yet and that a `token_info` query succeeds — there is no vetting of the contract's bytecode or behavior [3](#0-2) .

The wasm module's own event-attribute filter only rejects the reserved `_`-prefixed keys (e.g. `_contract_address`); every other attribute name/value, including `action`, `amount`, `from`, `to`, is passed through verbatim from the contract's `Response` [4](#0-3) . There is no equivalent of a `HeaderFilterStrategy`/allow-list restricting which attribute keys a pointed contract may use, nor any verification that an `action=transfer` attribute was accompanied by a genuine balance mutation.

Consequently, an attacker can deploy a trivial CW20-labeled contract, register an ERC20 pointer for it via the permissionless precompile, then call an arbitrary execute message on that contract that does nothing except emit `action=transfer`, `from=<victim>`, `to=<attacker>`, `amount=<huge>` as event attributes. `AddCosmosEventsToEVMReceiptIfApplicable` will fabricate a fully-formed ERC20 `Transfer` log for the pointer address and inject it into the transaction's EVM receipt, indistinguishable from a genuine token movement to any JSON-RPC consumer.

The system explicitly documents and tests that these synthetic logs are meant to be a faithful 1:1 mirror of real CW20 activity for EVM consumers, e.g. the CW20↔ERC20 pointer parity test asserts `eth_getLogs`/`eth_getTransactionReceipt` return the synthetic `Transfer` log matching the real balance change [5](#0-4) , and the docs describe this dual-VM log translation as a core, relied-upon feature [6](#0-5) .

### Impact Explanation
Any off-chain consumer of the public EVM JSON-RPC surface — bridges, exchanges, wallets, or indexers — that watches `eth_getLogs`/`eth_getTransactionReceipt` for ERC20/721/1155 `Transfer`/`Approval` events on a CW pointer address can be deceived into believing a deposit or transfer occurred when no real CW20/721/1155 balance change took place. Because pointer registration is permissionless and reachable by any transaction sender/contract deployer, and the log-forging contract requires no special privilege, this enables fund-loss scenarios (e.g., an exchange crediting a fabricated "deposit" it observed via `eth_getLogs`) purely from a public RPC client's perspective — matching the "unauthorized transfer via precompile or pointer" / fee-or-refund/fund-loss impact bar.

### Likelihood Explanation
High: pointer registration requires only a normal EVM transaction to the `pointer` precompile and a CW20-token-info-compatible contract; forging the wasm event attributes requires only an ordinary `MsgExecuteContract` call that the attacker's own contract handles. No validator collusion, governance action, or privileged key is needed — it is fully reachable by an unprivileged CosmWasm/EVM user.

### Recommendation
Do not trust arbitrary `wasm` event attribute names/values from pointed contracts as authoritative for synthetic EVM log construction. Either (a) derive the synthetic Transfer/Approval/etc. events from verified pre/post CW20/721/1155 state queries (balance/owner/allowance diff) rather than free-form event attributes, or (b) restrict which attribute keys a pointer-eligible contract may emit and validate them against the contract's actual state changes before emitting a synthetic log, applying the same kind of allow-list/filter strategy that is missing today in `GetActionsFromWasmEvent`/`contractSDKEventAttributes`.

### Proof of Concept
1. Deploy a minimal CosmWasm contract exposing `token_info` (to pass the pointer precompile's compliance probe) but whose `execute` handler, for a custom message (e.g. `{"fake_transfer": {...}}`), performs no real balance mutation and instead returns a `Response` with attributes `action=transfer`, `from=<victim-evm-hash-source-sei-addr>`, `to=<attacker-sei-addr>`, `amount=<large>`.
2. Call `pointer.AddCW20Pointer` (permissionless EVM tx to the `pointer` precompile) to register an ERC20 pointer for this contract.
3. Send a `MsgExecuteContract` invoking `fake_transfer` on the malicious contract.
4. Query `eth_getLogs`/`eth_getTransactionReceipt` for the pointer address: observe a fully-formed ERC20 `Transfer(from, to, amount)` log was synthesized even though no CW20 balance changed, matching the exact translation path in `app.translateCW20Event`/`GetActionsFromWasmEvent`.

func (app *App) translateCW20Event(ctx sdk.Context, wasmEvent abci.Event, pointerAddr common.Address, contractAddr string) (res []*ethtypes.Log) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[Error] Panic caught during translateCW20Event: type=%T, value=%+v\n", r, r)
		}
	}()

	for _, action := range app.GetActionsFromWasmEvent(ctx, wasmEvent) {
		switch action.Type {
		case "mint", "burn", "send", "transfer", "transfer_from", "send_from", "burn_from":
			if action.Amount == nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC20TransferTopic,
					action.From,
					action.To,
				},
				Data: common.BigToHash(action.Amount).Bytes(),
			})
		case "increase_allowance", "decrease_allowance":
			topics := []common.Hash{
				ERC20ApprovalTopic,
				action.Owner,
				action.Spender,
			}
			ret, err := app.WasmKeeper.QuerySmart(
				ctx,
				sdk.MustAccAddressFromBech32(contractAddr),
				[]byte(fmt.Sprintf(
					"{\"allowance\":{\"owner\":\"%s\",\"spender\":\"%s\"}}",
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Owner[:])).String(),
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Spender[:])).String())),
			)
			if err != nil {
				continue
			}
			allowanceResponse := &AllowanceResponse{}
			if err := json.Unmarshal(ret, allowanceResponse); err != nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics:  topics,
				Data:    common.BigToHash(allowanceResponse.Allowance.BigInt()).Bytes(),
			})
		}
	}
	return
}

func (app *App) GetActionsFromWasmEvent(ctx sdk.Context, event abci.Event) (actions []*Action) {
	for _, attr := range event.Attributes {
		key := string(attr.Key)
		value := string(attr.Value)
		if key == "action" {
			actions = append(actions, &Action{Type: value})
			continue
		}
		if len(actions) == 0 {
			continue
		}
		curAction := actions[len(actions)-1]
		switch key {
		case "amount":
			curAction.Amount = safeBigIntFromString(value)
		case "amounts":
			curAction.Amounts = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "token_id":
			curAction.TokenId = safeBigIntFromString(value)
		case "token_ids":
			curAction.TokenIds = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "sender":
			curAction.Sender = app.GetEvmAddressHash(ctx, value)
		case "recipient":
			curAction.Recipient = app.GetEvmAddressHash(ctx, value)
		case "spender":
			curAction.Spender = app.GetEvmAddressHash(ctx, value)
		case "operator":
			curAction.Operator = app.GetEvmAddressHash(ctx, value)
		case "owner":
			curAction.Owner = app.GetEvmAddressHash(ctx, value)
		case "from":
			curAction.From = app.GetEvmAddressHash(ctx, value)
		case "to":
			curAction.To = app.GetEvmAddressHash(ctx, value)
		}
	}
	return
}

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func contractSDKEventAttributes(customAttributes []wasmvmtypes.EventAttribute, contractAddr sdk.AccAddress) ([]sdk.Attribute, error) {
	attrs := []sdk.Attribute{sdk.NewAttribute(types.AttributeKeyContractAddr, contractAddr.String())}
	// append attributes from wasm to the sdk.Event
	for _, l := range customAttributes {
		// ensure key and value are non-empty (and trim what is there)
		key := strings.TrimSpace(l.Key)
		if len(key) == 0 {
			return nil, sdkerrors.Wrap(types.ErrInvalidEvent, fmt.Sprintf("Empty attribute key. Value: %s", l.Value))
		}
		value := strings.TrimSpace(l.Value)
		// TODO: check if this is legal in the SDK - if it is, we can remove this check
		if len(value) == 0 {
			return nil, sdkerrors.Wrap(types.ErrInvalidEvent, fmt.Sprintf("Empty attribute value. Key: %s", key))
		}
		// and reserve all _* keys for our use (not contract)
		if strings.HasPrefix(key, types.AttributeReservedPrefix) {
			return nil, sdkerrors.Wrap(types.ErrInvalidEvent, fmt.Sprintf("Attribute key starts with reserved prefix %s: '%s'", types.AttributeReservedPrefix, key))
		}
		attrs = append(attrs, sdk.NewAttribute(key, value))
	}
	return attrs, nil

### Synthetic Receipts and Logs
There are several types of synthetic receipts/logs on Sei.
- **CW->EVM** - if a Cosmos transaction calls an EVM contract, a synthetic receipt is created to carry any logs emitted on the EVM side.
- **CW Pointee** - if a Cosmos transaction calls a CosmWasm contract that has an EVM pointer, a synthetic receipt is created and synthetic logs are emitted to represent activities from EVM lens.
- **EVM->CW** - if an EVM transaction calls a CosmWasm contract that has an EVM pointer, synthetic logs are emitted and stored on the EVM transaction's receipt.
