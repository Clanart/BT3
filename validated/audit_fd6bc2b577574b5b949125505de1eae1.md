### Title
Missing enforcement of `WhitelistedCwCodeHashesForDelegateCall` in `HandleInternalEVMDelegateCall` allows unrestricted CW→EVM delegatecalls - (File: x/evm/keeper/evm.go)

### Summary
`x/evm/types/params.go` and the `Params` proto define `WhitelistedCwCodeHashesForDelegateCall`, an allowlist of CosmWasm code hashes that are meant to be permitted to trigger EVM delegatecalls via `MsgInternalEVMDelegateCall`. [1](#0-0)  The message itself carries a `CodeHash` field populated from the calling contract's `codeInfo.CodeHash` at encode time. [2](#0-1)  However, `Keeper.HandleInternalEVMDelegateCall` never reads `req.CodeHash` or the `WhitelistedCwCodeHashesForDelegateCall` param — it only checks that `FromContract` is a registered pointer contract and that `to` matches its registered EVM pointer address. [3](#0-2) 

### Finding Description
The delegate-call path is reachable by any CosmWasm contract via the `delegate_call_evm` custom Sei-Wasm message, dispatched through `CustomEncoder` → `EncodeDelegateCallEVM` → `MsgInternalEVMDelegateCall`, which is handled by `CustomRouter.Handler` in `wasmbinding/message_plugin.go`. [4](#0-3) [5](#0-4)  The only gate enforced in `HandleInternalEVMDelegateCall` is that the calling CW contract (`FromContract`) is a registered pointer contract and that the delegatecall target matches its own registered EVM pointer address: `k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(...))`. [6](#0-5)  This is a much weaker condition than a code-hash allowlist: any bytecode deployed at/instantiated as a registered pointer address (including through pointer migrations or upgrades that only require matching the deterministic pointer artifact addressing) can invoke delegatecalls, since the `CodeHash` field and the whitelist param that was clearly designed for this check are dead code in this path.

### Impact Explanation
Because the code-hash allowlist is never enforced, the intended defense-in-depth restricting which CW code is trusted to perform EVM delegatecalls is completely bypassed. If a pointer contract's code can ever diverge from the originally-audited/whitelisted pointer implementation (via migration, or a bug elsewhere that lets a non-canonical contract register/occupy a pointer slot), that contract gains full delegatecall access into the associated EVM contract with the calling user's `senderEvmAddr` state context (`k.CallEVM(ctx, senderEvmAddr, to, &zeroInt, req.Data)`). This can allow unauthorized manipulation of an ERC20/721/1155 pointer contract's storage under a user's identity, i.e., unauthorized token transfer/mint/burn-equivalent state corruption for pointer/wrapped assets, which is fund loss / unauthorized transfer via a CW↔EVM pointer bridge.

### Likelihood Explanation
Reaching `HandleInternalEVMDelegateCall` requires only deploying/controlling a CosmWasm contract that becomes registered at a pointer address and issuing a `delegate_call_evm` custom message — no validator or governance privilege is required, matching the "CosmWasm user / pointer user" reachable-actor class. The remaining gate (`FromContract` must be a registered pointer, `to` must equal its associated EVM address) still constrains exploitation to the pointer-registration surface, so full exploitability depends on whether an attacker can get non-canonical code onto a pointer address (e.g. via pointer migration bugs); that dependency could not be fully verified in this investigation given index limits, so likelihood is best characterized as gated-but-plausible rather than confirmed trivial.

### Recommendation
In `HandleInternalEVMDelegateCall`, validate `req.CodeHash` against `k.GetParams(ctx).WhitelistedCwCodeHashesForDelegateCall` before performing `k.CallEVM(...)`, rejecting the call if the hash is not present in the allowlist, restoring the intended defense that the `CodeHash` field and whitelist param were designed to provide.

### Proof of Concept
1. Deploy/obtain a CW contract instance whose address is registered as a pointer contract (via the standard `RegisterPointer` flow) for some EVM address `to`.
2. From that contract, emit the custom Sei-Wasm message `{"delegate_call_evm": {"to": "<pointer EVM address>", "data": "<base64 payload>"}}`.
3. This is encoded into `MsgInternalEVMDelegateCall{FromContract: <contract>, To: to, CodeHash: <actual code hash>, Sender: info.Sender, Data: data}` and routed to `HandleInternalEVMDelegateCall`. [3](#0-2) 
4. Observe that the handler never inspects `req.CodeHash` or any whitelist parameter — it only checks the pointer-registry match — before executing `CallEVM` with the calling user's associated EVM address as the effective caller, demonstrating the missing allowlist enforcement.

```go
func EncodeDelegateCallEVM(rawMsg json.RawMessage, sender sdk.AccAddress, info wasmvmtypes.MessageInfo, codeInfo wasmtypes.CodeInfo) ([]sdk.Msg, error) {
	encodedCallEVM := bindings.DelegateCallEVM{}
	if err := json.Unmarshal(rawMsg, &encodedCallEVM); err != nil {
		return []sdk.Msg{}, err
	}
	decodedData, err := base64.StdEncoding.DecodeString(encodedCallEVM.Data)
	if err != nil {
		return []sdk.Msg{}, err
	}
	s := sender
	if origSender, err := sdk.AccAddressFromBech32(info.Sender); err == nil {
		s = origSender
	}
	internalCallEVMMsg := types.MsgInternalEVMDelegateCall{
		Sender:       s.String(),
		To:           encodedCallEVM.To,
		CodeHash:     codeInfo.CodeHash,
		Data:         decodedData,
		FromContract: sender.String(),
	}
	return []sdk.Msg{&internalCallEVMMsg}, nil
```

```go
func (k *Keeper) HandleInternalEVMDelegateCall(ctx sdk.Context, req *types.MsgInternalEVMDelegateCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	} else {
		return nil, errors.New("cannot use a CosmWasm contract to delegate-create an EVM contract")
	}
	addr, _, exists := k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(common.BytesToAddress([]byte(req.FromContract))))
	if !exists || common.BytesToAddress(addr).Cmp(*to) != 0 {
		return nil, errors.New("only pointer contract can make delegatecalls")
	}
	zeroInt := sdk.ZeroInt()
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	// delegatecall caller must be associated; otherwise any state change on EVM contract will be lost
	// after they asssociate.
	senderEvmAddr, found := k.GetEVMAddress(ctx, senderAddr)
	if !found {
		err := types.NewAssociationMissingErr(req.Sender)
		evmKeeperMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "evm_handle_internal_evm_delegate_call"), attribute.String("type", err.AddressType())))
		return nil, err
	}
	ret, err := k.CallEVM(ctx, senderEvmAddr, to, &zeroInt, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}
```

```go
func CustomEncoder(sender sdk.AccAddress, msg json.RawMessage, info wasmvmtypes.MessageInfo, codeInfo wasmtypes.CodeInfo) ([]sdk.Msg, error) {
	var parsedMessage SeiWasmMessage
	if err := json.Unmarshal(msg, &parsedMessage); err != nil {
		return []sdk.Msg{}, sdkerrors.Wrap(err, "Error parsing Sei Wasm Message")
	}
	switch {
	case parsedMessage.CreateDenom != nil:
		return tokenfactorywasm.EncodeTokenFactoryCreateDenom(parsedMessage.CreateDenom, sender)
	case parsedMessage.MintTokens != nil:
		return tokenfactorywasm.EncodeTokenFactoryMint(parsedMessage.MintTokens, sender)
	case parsedMessage.BurnTokens != nil:
		return tokenfactorywasm.EncodeTokenFactoryBurn(parsedMessage.BurnTokens, sender)
	case parsedMessage.ChangeAdmin != nil:
		return tokenfactorywasm.EncodeTokenFactoryChangeAdmin(parsedMessage.ChangeAdmin, sender)
	case parsedMessage.SetMetadata != nil:
		return tokenfactorywasm.EncodeTokenFactorySetMetadata(parsedMessage.SetMetadata, sender)
	case parsedMessage.CallEVM != nil:
		return evmwasm.EncodeCallEVM(parsedMessage.CallEVM, sender, info)
	case parsedMessage.DelegateCallEVM != nil:
		return evmwasm.EncodeDelegateCallEVM(parsedMessage.DelegateCallEVM, sender, info, codeInfo)
	default:
		return []sdk.Msg{}, wasmvmtypes.UnsupportedRequest{Kind: "Unknown Sei Wasm Message"}
	}
```
