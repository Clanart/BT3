### Title
`SigningProtocol::share_internal` deterministically reuses a cached FROST preprocess across all calls sharing a context, enabling nonce reuse and private key share recovery — (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The LibSwap bug class is "a function silently pulls additional value to cover a shortfall instead of failing" — an implicit, counterintuitive second draw on a resource the caller assumed was consumed once. The Serai analog lives in `SigningProtocol::preprocess_internal` / `share_internal` in `coordinator/src/tributary/signing_protocol.rs`. The first time a signing context is used, a random `CachedPreprocess` is generated and stored keyed only by `context`. On every subsequent call with the same `context`, the *same* cached 32-byte seed is decrypted and fed to `AlgorithmSignMachine::from_cache`, which deterministically regenerates the identical nonces via `ChaCha20Rng::from_seed`. There is no consumption, rotation, or attempt-binding of the cached preprocess — the machine silently "pulls" the same nonce again whenever a second signature is requested under a repeated context, exactly the implicit top-up pattern of the original bug.

### Finding Description
- `crypto/frost/src/sign.rs:121-144` — `seeded_preprocess` derives `nonces` deterministically from `ChaCha20Rng::from_seed(*seed.0)`. Identical seed → identical nonce scalars.
- `coordinator/src/tributary/signing_protocol.rs:123-135` — the cache is written only when `CachedPreprocesses::get(self.txn, &self.context).is_none()`; it is never deleted or advanced.
- `coordinator/src/tributary/signing_protocol.rs:137-147` — every call decrypts the same `cached` seed and calls `AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached))`, producing the same commitments/nonces.
- `coordinator/src/tributary/signing_protocol.rs:150-180` — `share_internal` invokes `preprocess_internal` fresh on each call and then `machine.sign(preprocesses, msg)`, so a second `share_internal` for the same `context` signs a new `(preprocesses, msg)` pair with the *same* nonce.
- `crypto/frost/src/sign.rs:209-224` — the `SignMachine` contract explicitly states a cached preprocess "MUST only be used once. Reuse of it enables recovery of your private key share"; the coordinator code violates this whenever `context` repeats.

With two shares `s₁ = r + c₁λᵢxᵢ` and `s₂ = r + c₂λᵢxᵢ` under the same nonce `r` but different binding factors/challenges (attainable by varying the submitted preprocess set or message), `xᵢ = (s₁ − s₂)/(λᵢ(c₁ − c₂))` — full private share recovery.

### Impact Explanation
Recovery of a validator's MuSig/FROST secret share collapses the threshold security of the tributary signing key: combined with other shares or used to forge participation, it enables signing of unintended tributary messages (e.g., `set_keys_message`, slashes) and, in the worst case, reconstruction of the multisig secret securing bridged funds. This is a concrete secret-leakage / unintended-signature impact, not a best-practice issue.

### Likelihood Explanation
Reachable by an unprivileged party able to cause a second signing attempt under an identical `context` — e.g., a peer/coordinator message that re-triggers `share_internal` for a repeated context value with different `serialized_preprocesses` or `msg` (retry paths, `attempt` handling, or rebooted/reissued sign orders). The code does not bind `attempt` or the participant set into the cache key, nor does it delete the entry after `complete_internal`; safety relies entirely on an undocumented assumption that `context` is unique per signature — the same counterintuitive "implicit pull" hazard as the LibSwap finding. If every call site does embed a unique attempt in `context`, severity drops accordingly; that uniqueness is not enforced or documented at this layer.

### Recommendation
- Make the cached preprocess single-use: delete `CachedPreprocesses::get` entry (or store a consumed flag) before `from_cache`, and refuse to sign if a cached entry already exists for a context rather than regenerating identical nonces.
- Or derive the signing seed as `H(stored_seed || attempt || Hash(msg, preprocesses))` so retries produce fresh nonces while remaining recoverable across reboot.
- At minimum, document and assert at call sites that `context` is unique per signature (including attempt), matching the explicit MUST in `SignMachine::cache`/`from_cache`.

### Proof of Concept
1. Trigger a tributary signature under context `C` with participant set `P₁` and message `m₁`; the node generates and caches seed `s`, emits share `σ₁ = r + c₁λx`.
2. Submit/coax a second `CoordinatorMessage::SubstratePreprocesses` for the same `C` (same session/id/attempt path where `context` does not include the attempt or signers) with a different participant set `P₂` or message `m₂`. `share_internal` reloads `s`, regenerates the same `r`, and emits `σ₂ = r + c₂λx`.
3. Compute `x = (σ₁ − σ₂) / (λ(c₁ − c₂))` using the public preprocesses/message to derive `c₁, c₂` — the signer's private key share is recovered, enabling forgery under the recovered share.
