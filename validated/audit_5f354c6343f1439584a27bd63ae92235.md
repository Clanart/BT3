## Title
Unprivileged clients can indefinitely evade `ConnectionTable::prune_oldest` eviction by refreshing `last_update` via trivial streams, enabling QUIC/TPU connection-slot exhaustion - (File: streamer/src/nonblocking/quic.rs)

## Summary
`ConnectionTable::prune_oldest` selects connections to evict under capacity pressure based solely on the minimum `last_update` value, which is an `Arc<AtomicU64>` refreshed on every stream completion via `on_stream_finished` in both QoS implementations. Because any connected peer can trivially refresh this timestamp by opening and closing a cheap unidirectional stream, an unprivileged attacker can guarantee their connections are never selected for eviction, causing legitimate/idle connections to be pruned instead or preventing capacity reclamation entirely.

## Finding Description
`ConnectionTable::prune_oldest` chooses the connection group with the minimum `last_update` for eviction when a table is over capacity: [1](#0-0) 

`last_update` is stored per `ConnectionEntry` as an `Arc<AtomicU64>`: [2](#0-1) 

It is updated on every stream completion in both QoS backends: [3](#0-2) [4](#0-3) 

`prune_oldest` is invoked from `prune_unstaked_connection_table` when the unstaked table nears/exceeds capacity, pruning down to 90% via the `last_update`-based selection: [5](#0-4) 

The connections-per-minute/per-peer limiters govern only new connection *establishment* (`max_connections_per_unstaked_peer` / `max_connections_per_staked_peer` in `try_add_connection`), not the rate of stream activity on already-established connections: [6](#0-5) 

No age-independent signal (e.g., connection creation time) factors into `prune_oldest`'s selection — only the activity-refreshable `last_update` is used, so an attacker's periodic trivial-stream traffic on already-open connections perpetually protects those connections from eviction while other, genuinely idle connections (or the attacker's own connections if legitimately outbid) are pruned instead.

## Impact Explanation
This falls under the "non-RPC remote exhaustion/crash" impact category against the TPU/QUIC ingestion path. An unprivileged attacker who opens a modest number of unstaked connections (bounded by per-IP connection limits, multipliable via multiple source IPs) and periodically completes trivial streams on each can occupy a persistent share of the unstaked (or low-stake staked) `ConnectionTable` slots indefinitely, degrading legitimate clients'/validators' ability to establish TPU connections and submit transactions.

## Likelihood Explanation
The exploit requires only standard unprivileged QUIC client behavior — opening a connection and periodically opening/closing a minimal unidirectional stream — well within existing per-IP/per-pubkey connection limits and stream throttling bounds, since stream throttling limits *volume* of streams but does not prevent a low-rate refresh cadence sufficient to keep `last_update` fresher than other idle connections. No stake, trust, or privileged role is required, making this a low-cost, repeatable degradation vector.

## Recommendation
Track connection age (creation time) independently from `last_update`/stream-activity refresh, and incorporate it into `prune_oldest`/`prune_random` selection (e.g., combine an activity-independent creation timestamp with the activity-based signal, or cap the extent to which continued activity can indefinitely postpone eviction) so that an attacker cannot indefinitely evade pruning purely by refreshing `last_update`.

## Proof of Concept
1. Open N unstaked QUIC connections to a validator's TPU endpoint (bounded by `max_connections_per_unstaked_peer`, more via multiple source IPs).
2. On each connection, periodically open a minimal unidirectional stream, send a few bytes, and close it immediately — this triggers `on_stream_finished`, storing `timing::timestamp()` into `last_update` (`streamer/src/nonblocking/swqos.rs:490-494`).
3. As other legitimate clients connect and the unstaked table approaches `max_unstaked_connections`, `prune_unstaked_connection_table` invokes `ConnectionTable::prune_oldest` (`streamer/src/nonblocking/quic.rs:964-980`), which selects the group with minimum `last_update`.
4. Because the attacker's connections are continuously refreshed, they are never selected; other idle/legitimate connections are evicted instead, or capacity cannot be reclaimed from the attacker, denying/degrading TPU connection slots for legitimate traffic. This can be verified with a unit/integration test asserting that repeatedly calling `on_stream_finished` on attacker-controlled `ConnectionEntry` instances causes `prune_oldest` to select a different (legitimate, non-refreshed) entry for eviction under capacity pressure.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
