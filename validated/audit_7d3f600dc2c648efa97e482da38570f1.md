### Title
Unbounded length-prefix parsing in `is_atom_canonical` causes out-of-bounds read / unhandled exception when checking CLVM canonicity of untrusted spend-bundle data - (File: chia/full_node/mempool_manager.py)

### Summary
`chia/full_node/mempool_manager.py`'s `is_atom_canonical()` parses the CLVM atom length-prefix of a caller-supplied byte buffer without validating that the buffer actually contains as many bytes as the prefix claims, and without validating that the leading control byte matches one of the expected bit patterns. [1](#0-0)  This is the same bug class as CVE-2023-48298: a length/skip-count value taken directly from attacker-controlled serialized data is used to index into a buffer without a preceding bounds check, so malformed input drives the parser past the end of the buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the control byte at `offset`, derives `mask`, `prefix_len`, and `min_value` from one of six bit-pattern branches, then walks `prefix_len` additional bytes to build `atom_len`:

```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
``` [2](#0-1) 

There is no check that `offset + prefix_len` stays within `len(clvm_buffer)` before this loop executes. If `is_clvm_canonical()`'s caller passes a buffer where a multi-byte atom length prefix appears at (or near) the end of the buffer — i.e., the buffer is truncated relative to what the length prefix claims — `clvm_buffer[offset]` will index past the end of the buffer.

`is_clvm_canonical()` itself walks the whole buffer token-by-token using the `atom_len` computed by `is_atom_canonical()` to advance `offset`, and only detects trailing garbage / truncation *after* the loop via `return offset == len(clvm_buffer)`. [3](#0-2)  There is no early bounds check before dereferencing `clvm_buffer[offset]` on each iteration, so a crafted buffer whose length-prefix byte sequence is truncated causes an unhandled Python `IndexError` rather than a controlled "not canonical" result.

This function is exercised against CLVM byte buffers derived from spend-bundle data (puzzle reveal / solution bytes) as part of mempool eligibility checks (fast-forward/dedup canonicalization), i.e., data supplied directly by an unauthenticated spend-bundle submitter, not by a trusted/validated block.

### Impact Explanation
An `IndexError` raised out of `is_atom_canonical()`/`is_clvm_canonical()` during spend-bundle processing is not caught anywhere in the shown code path. If the exception propagates uncaught through mempool admission, it can abort the eligibility check / mempool-add workflow, denying processing of the specific submission and, depending on how the caller handles unexpected exceptions from this helper, risk broader disruption of transaction-processing for the node — i.e., a spend-triggered transaction-processing halt, matching the validation criteria and mirroring the ClickHouse FPC decompression crash where an attacker-controlled length field led to an out-of-bounds read and abrupt failure.

### Likelihood Explanation
Medium-to-high likelihood of triggering the crash path: because the routine operates purely on caller-supplied bytes (puzzle reveal / solution content of a submitted `SpendBundle`), an unauthenticated party can construct a buffer whose final serialized atom has a multi-byte length prefix but is truncated exactly at the buffer boundary, forcing `clvm_buffer[offset]` out of range on the last prefix byte read. No special privileges, mining power, or prior mempool state are required — only the ability to submit a spend bundle whose puzzle/solution bytes are shaped this way.

### Recommendation
Add an explicit bounds check in `is_atom_canonical()` before consuming the length-prefix bytes and before returning `atom_len`, e.g. verify `offset + prefix_len < len(clvm_buffer)` prior to entering the loop, and propagate a "not canonical" (or explicit error) result instead of allowing an `IndexError` to escape. Similarly, harden `is_clvm_canonical()` to check `offset < len(clvm_buffer)` before every `clvm_buffer[offset]` access, mirroring the defensive length checks already used in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`, `generator_from_block`), which explicitly compare declared lengths against remaining buffer size before slicing. [4](#0-3) 

### Proof of Concept
1. Construct a CLVM buffer whose last atom uses the 4-byte length-prefix form (`0xF0`-class control byte, e.g. `0xF3`) but truncate the buffer so that fewer than the required 3 following length bytes are present (e.g. supply the control byte plus only 1 trailing byte instead of 3).
2. Pass this buffer to `is_clvm_canonical()` (as exercised by the mempool's canonicalization check on a submitted spend bundle's puzzle reveal/solution bytes).
3. Execution reaches `is_atom_canonical()`, which enters `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]`; on the iteration where `offset` exceeds `len(clvm_buffer) - 1`, Python raises `IndexError: index out of range`, which is not caught within `is_atom_canonical`/`is_clvm_canonical`, propagating to the caller performing spend-bundle admission.

Note: I could not fully trace, within the available tool budget, the exact call site(s) in `mempool_manager.py` that invoke `is_clvm_canonical()` on live spend-bundle data (grep showed the definitions plus references in tests and `.cursor/context/clvm-execution.md`, but the direct production call line was not retrieved before the iteration limit). This should be confirmed against `chia/full_node/mempool_manager.py`'s eligibility-for-fast-forward/dedup logic to fully validate the exception's blast radius on the mempool-admission thread.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
