### Title
`_getClaimable` in ArbitrumMWomAirdrop ignores vesting schedule, allowing immediate full claim of unvested tokens - (File: rewards/ArbitrumMWomAirdrop.sol)

### Summary
`ArbitrumMWomAirdrop._getClaimable` hardcodes `vested = totalAmount` instead of computing a linear vesting amount based on `startVestingTime`, `vestingPeriodCount`, and `intervals`, making the `if (vested > totalAmount)` branch permanently dead code. Any holder of a valid merkle leaf can call `claim()` the instant `block.timestamp >= startVestingTime` and receive their entire `totalAmount` in one transaction, bypassing the intended gradual vesting.

### Finding Description
In `rewards/ArbitrumMWomAirdrop.sol`:

```solidity
function _getClaimable(address account, uint256 totalAmount) internal view returns (uint256) {
    uint256 claimed = getClaimed(account);
    if (claimed >= totalAmount) {
        return 0;
    }
    uint256 vested = totalAmount;
    if (vested > totalAmount) {
        return totalAmount - claimed;
    }
    return vested - claimed;
}
``` [1](#0-0) 

Compare this to the sibling contract `Airdrop2.sol`, which computes a genuine linear vesting curve:
```solidity
uint256 vested = (totalAmount * 5 / 100) + (totalAmount * 95 / 100) * ((block.timestamp - startVestingTime) / intervals) / (vestingPeriodCount);
``` [2](#0-1) 

This confirms the intended design for `ArbitrumMWomAirdrop` was a time-based vesting schedule using `vestingPeriodCount` and `intervals` (both declared state variables that are otherwise unused after being set) [3](#0-2) , but the implementation was replaced/left as `vested = totalAmount`, so the `if (vested > totalAmount)` guard can never be true and the entire vesting formula is dead code.

The reachable exploit path requires no privilege: any address with a valid merkle leaf calls `claim(totalAmount, proof, isStake, isLock)` [4](#0-3)  once `block.timestamp >= startVestingTime` (checked at line 86), which calls `_getClaimable` and receives `claimable == totalAmount` immediately instead of a fraction proportional to elapsed vesting periods. Existing modifiers (`whenNotPaused`, `nonReentrant`, merkle proof verification) do not stop this because they don't validate the vesting math itself — they only gate pause state, reentrancy, and leaf authenticity.

### Impact Explanation
This breaks the accrual/vesting invariant: tokens meant to unlock gradually over `vestingPeriodCount * intervals` become withdrawable/lockable in full on day one. This matches the "theft of unclaimed yield" / accrual-entitlement impact class — recipients (or any of them) can extract full allocations far earlier than the vesting schedule intends, defeating the purpose of vesting (e.g., preventing immediate sell pressure or aligning long-term incentives, and enabling `isLock=true` to front-load voting/lock power in `locker.lockFor()` before the schedule would have permitted it).

### Likelihood Explanation
Trivial and 100% reproducible: requires only being (or becoming) one of the merkle-tree recipients with `totalAmount > 0` and waiting until `startVestingTime` — no capital, front-running, or special access needed. Every eligible claimant can exploit this deterministically.

### Recommendation
Fix `_getClaimable` in `ArbitrumMWomAirdrop.sol` to implement the same (or intended) linear-vesting formula as `Airdrop2.sol`, using `startVestingTime`, `intervals`, and `vestingPeriodCount`, e.g.:
```solidity
uint256 vested = totalAmount * (block.timestamp - startVestingTime) / (intervals * vestingPeriodCount);
```
with proper capping via the `if (vested > totalAmount)` branch, and ensure `vestingPeriodCount`/`intervals` are set to nonzero meaningful values in the constructor before deployment.

### Proof of Concept
Foundry test plan:
1. Deploy `ArbitrumMWomAirdrop` with `startVestingTime = block.timestamp + 1 days`, `vestingPeriodCount = 10`, `intervals = 30 days`, and a merkle root containing leaf `(alice, 1000e18)`.
2. Fund the contract with `1000e18` reward tokens.
3. Warp to exactly `startVestingTime`.
4. Call `getClaimable(alice, 1000e18, proof)` and assert it returns `1000e18` (full amount) instead of the expected `~5%` or `1/10` proportional first-interval amount.
5. Call `claim(1000e18, proof, false, true)` from alice with `isLock=true`; assert `locker.lockFor` is invoked with the full `1000e18`, and `reward.balanceOf(airdrop)` drops by the full amount in a single transaction, confirming zero vesting enforcement.

    function claim(
        uint256 totalAmount,
        bytes32[] calldata merkleProof,
        bool isStake,
        bool isLock
    ) external whenNotPaused nonReentrant {
        require(block.timestamp >= startVestingTime, "ArbitrumMWomAirdrop: Drop dose not start.");
        // isStake & isLock cannot be true at the same time
        require(!(isStake && isLock), "ArbitrumMWomAirdrop: Operation error.");
        //Verify the merkle proof.
        require(verifyProof(msg.sender, totalAmount, merkleProof), "ArbitrumMWomAirdrop: Invalid proof.");

        uint256 claimable = _getClaimable(msg.sender, totalAmount);
        require(claimable > 0, "ArbitrumMWomAirdrop: Insufficient claimable.");

        // Mark it claimed and send the token.
        if (isStake) {
            reward.safeApprove(address(helper), claimable);
            helper.depositFor(claimable, address(msg.sender));
        } else if (isLock) {
            reward.safeApprove(address(locker), claimable);
            locker.lockFor(claimable, address(msg.sender));
        } else {
            reward.safeTransfer(msg.sender, claimable);
        }

        uint256 userClaimedAmount = claimedAmount[msg.sender];
        claimedAmount[msg.sender] = userClaimedAmount + claimable;
        emit ClaimEvent(msg.sender, claimable, isStake, isLock);
    }
