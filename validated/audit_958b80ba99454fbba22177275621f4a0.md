Audit Report

## Title
Ed25519 shred-signature verification uses non-strict `verify` (malleable), bypassing shred dedup and duplicate-shred budget - (File: `ledger/src/shred.rs`, `ledger/src/shred/merkle.rs`, `ledger/src/sigverify_shreds.rs`)

## Summary
Shred leader-signature verification in `ledger/src/shred.rs` and `ledger/src/shred/merkle.rs` calls the non-strict `Signature::verify` rather than `verify_strict`, which the codebase itself demonstrates (in `precompiles/src/ed25519.rs`) is required to reject malleable ed25519 signature encodings. Because the ledger's shred dedup (`turbine/src/retransmit_stage.rs::ShredDeduper::dedup`) and the sig-verify LRU cache in `ledger/src/sigverify_shreds.rs` both key on raw signature bytes, an attacker who observes one valid shred can synthesize additional byte-distinct but cryptographically-equivalent signatures that evade the fast header-hash dedup and consume slots in the bounded `MAX_DUPLICATE_COUNT` budget reserved for genuine leader equivocation evidence.

## Finding Description
`ledger/src/shred.rs` (`Shred::verify`) and `ledger/src/shred/merkle.rs` (`fn verify`) both call `self.signature().verify(pubkey.as_ref(), data.as_ref())` [1](#0-0) , and `ledger/src/sigverify_shreds.rs::verify_shred_cpu` similarly calls `key.0.verify(key.1.as_ref(), key.2.as_ref())` after first checking an LRU cache keyed on `(Signature, Pubkey, Hash)` [2](#0-1) . This is the plain, cofactored ed25519 `verify`, which does not reject non-canonical `S` encodings, unlike `verify_strict`, whose necessity for rejecting malleable signatures is proven by the codebase's own `test_ed25519_malleability` in `precompiles/src/ed25519.rs`.

`turbine/src/retransmit_stage.rs::ShredDeduper::dedup` dedups first on `get_common_header_bytes` (which embeds the raw signature bytes) and falls back to a bounded `shred_id_filter` sized by `max_duplicate_count`, explicitly intended to allow only a small number of genuinely different (equivocated) shreds through per `ShredId` for duplicate-block detection [3](#0-2) . A malleated signature produces different header bytes for the same underlying signed payload, so it bypasses the header-hash fast-path and consumes one of the limited `shred_id_filter` slots meant for real equivocation evidence.

## Impact Explanation
This matches the "non-RPC remote exhaustion/crash" and weakened duplicate-block detection impact categories for the shreds/repair subsystem. An unprivileged attacker who intercepts a single valid turbine shred can, without any private key, produce several additional signature encodings for the identical shred, forcing redundant ed25519 verification (guaranteed cache misses in `verify_shred_cpu`'s LRU) and exhausting the `MAX_DUPLICATE_COUNT`-bounded `shred_id_filter` budget that is meant to preserve room for genuinely equivocated shreds used in duplicate-block detection.

## Likelihood Explanation
The attack requires only observation of one legitimately signed shred (trivial via turbine sniffing) and the ability to send crafted UDP packets to a validator's shred ingestion path, with no validator/leader collusion or private key access. The amplification factor is bounded (~8x per captured shred), and the byte-level `S` arithmetic is cheap relative to the receiving validator's verification cost, making the attack easily automatable and repeatable across many shreds/slots.

## Recommendation
Switch shred signature verification in `ledger/src/shred.rs`, `ledger/src/shred/merkle.rs`, and `ledger/src/sigverify_shreds.rs` to `verify_strict` (as already used in `precompiles/src/ed25519.rs`), and change the dedup/verify-cache keys in `ledger/src/sigverify_shreds.rs` and `turbine/src/retransmit_stage.rs::ShredDeduper` to use a canonicalized `(pubkey, message)` fingerprint rather than raw signature bytes, so malleated encodings of an already-verified signature are recognized as duplicates.

## Proof of Concept
1. Capture one valid leader-signed shred `(header || S || payload)` from turbine.
2. Compute `S' = (S_int + k*L) mod 2^256` for small `k` while the result stays 32 bytes, producing additional signature encodings; `precompiles/src/ed25519.rs::test_ed25519_malleability` demonstrates the underlying primitive that plain `verify` accepts these while `verify_strict` rejects them.
3. Replace the signature in the captured packet with each `S'`, keeping slot/index/payload identical, and send to a validator's shred ingestion socket.
4. Observe repeated full ed25519 verification (LRU cache miss in `ledger/src/sigverify_shreds.rs`) and each variant consuming a slot in `ShredDeduper`'s `shred_id_filter` (`turbine/src/retransmit_stage.rs`) instead of being dropped as duplicate.

#[must_use]
pub fn verify_shred_cpu(
    packet: PacketRef,
    slot_leaders: &SlotPubkeys,

    if packet.meta().discard() {
        return false;
    }
    let Some(shred) = shred::layout::get_shred(packet) else {
        return false;

        return false;

        return false;
    };

        return false;

        return false;

        true
    } else if key.0.verify(key.1.as_ref(), key.2.as_ref()) {
        cache.write().unwrap().put(key, ());

    // Returns true if the shred is duplicate and should be discarded.
    #[must_use]
    fn dedup(&self, key: ShredId, shred: &[u8], max_duplicate_count: usize) -> bool {
        // Shreds in the retransmit stage:
        //   * don't have repair nonce (repaired shreds are not retransmitted).
        //   * are already resigned by this node as the retransmitter.
        //   * have their leader's signature verified.
        // Therefore in order to dedup shreds, it suffices to compare:
        //    (signature, slot, shred-index, shred-type)
        // Because ShredCommonHeader already includes all of the above tuple,
        // the rest of the payload can be skipped.
        // In order to detect duplicate blocks across cluster, we retransmit
        // max_duplicate_count different shreds for each ShredId.
        shred::layout::get_common_header_bytes(shred)
            .map(|header| self.deduper.dedup(header))
            .unwrap_or(true)
            || (0..max_duplicate_count).all(|i| self.shred_id_filter.dedup(&(key, i)))
    }
