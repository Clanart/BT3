The structural validation of the AI's ("oracle's") output never inspects semantic correctness against the original `ours`/`theirs`/`base` hunk content.

### Title
Copilot AI conflict-resolution content is written to disk and staged with no bound-checking against original hunk content, allowing prompt-injection to silently corrupt committed code - ([File: app/src/lib/copilot-conflict-resolution.ts])

### Summary
GitHub Desktop's "Resolve with Copilot" feature treats the Copilot SDK's JSON response as an oracle for merge-conflict resolutions. Like the GMX Chainlink price feed, the response is structurally validated (JSON shape, correct file paths, correct hunk counts, no literal conflict-marker strings) but never validated against the semantic content it is supposed to represent — the original `ours`/`theirs`/`base` hunk text. The resolved content is written straight to disk and `git add`-ed.

### Finding Description
`parseCopilotConflictResolution` only enforces structural shape: JSON parses, `resolutions` is a non-empty array, each entry has a string `path`/`hunks`/`reasoning`, and `resolvedContent` doesn't literally contain `<<<<<<<`/`=======` markers [2](#0-1) . `validateResolutionPaths` only checks that returned paths match the expected file set 1:1 and hunk counts match [3](#0-2) . At no point is `resolvedContent` checked against the actual `oursContent`/`theirsContent`/`baseContent` of the corresponding hunk — there is no diff-bound, size-bound, or content-similarity check analogous to a staleness/sanity threshold.

`reassembleResolvedFile` then splices this unchecked `resolvedContent` verbatim into the original file [4](#0-3) , and `_applyCopilotConflictResolutions` writes it straight to disk and stages it with `git add` when the user clicks "Continue Merge" [5](#0-4) .

The model's prompt explicitly ingests attacker-influenceable inputs: "recent commit messages and/or PR title/description for intent" [6](#0-5) , plus the conflicting hunks themselves, which in a merge/rebase/cherry-pick against a hostile fork/branch are entirely attacker-controlled. Since there is no ground-truth check between what the model was told to produce (a merge of `ours`/`theirs`) and what it actually returns, a prompt-injection payload embedded in a commit message, PR description, or the conflicting hunk content can steer the model into emitting attacker-chosen code for `resolvedContent` that has nothing to do with either side of the conflict, and the validation layer has no mechanism to catch this because it never compares content, only shape/counts.

The dialog does provide a "Changes" tab with a real diff (`CopilotConflictsChanges` using `SeamlessDiffSwitcher`) [7](#0-6) , but it defaults to the "Summary" tab which only shows the AI's self-reported `reasoning` text per file [8](#0-7) [9](#0-8)  — the reasoning is also model-authored and cannot be trusted to accurately describe injected content, so a user relying on the default tab has no reliable signal that the resolution deviates from the actual conflict.

### Impact Explanation
This maps to "silent corruption of what the user commits or pushes": a merge/rebase/cherry-pick against an attacker-influenced branch, PR, or set of commit messages can cause GitHub Desktop's AI-assisted conflict resolution to write and stage attacker-chosen file content without the structural validators ever detecting it, since those validators check file identity and hunk counts, not code provenance or bounds relative to the original conflicting text.

### Likelihood Explanation
Requires the victim to (1) have Copilot conflict resolution enabled, (2) hit a real conflict against attacker-influenced branch/commit/PR content, and (3) click "Continue" without reviewing the opt-in diff tab — a plausible but non-trivial combination of conditions, and it also depends on how susceptible the underlying Copilot model actually is to prompt injection, which could not be verified from the local codebase alone.

### Recommendation
Add a content-bound validation step analogous to the recommended "staleness threshold" for oracle prices: verify each `resolvedContent` stays within a reasonable similarity/length bound relative to the union of that hunk's `oursContent`/`theirsContent`/`baseContent` (e.g., diff-based similarity check, rejecting resolutions that introduce large blocks of code absent from either side), and make the diff review (`CopilotConflictsChanges`) the default/mandatory view before "Continue" is enabled, rather than an opt-in tab behind "Summary".

### Proof of Concept
Not independently reproducible from static code alone — this requires an actual Copilot SDK session with a real conflict scenario. The evidence trail is: attacker-controlled context (commit messages/PR body/conflicting hunks) → Copilot session output → structural-only validation (`parseCopilotConflictResolution`, `validateResolutionPaths`) → verbatim splice (`reassembleResolvedFile`) → disk write + `git add` (`_applyCopilotConflictResolutions`) with no content-provenance check at any stage. Full confirmation of exploitability (i.e., that the underlying model is actually steerable via injected instructions in commit/PR text) would require live testing of the Copilot SDK integration, which is outside the scope of static code review.

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }
}
