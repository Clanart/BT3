### Title
Unbalanced recursion-depth/limit accounting on parse failure corrupts `CodedInputStream` accounting for subsequent reads — ([File: src/google/protobuf/wire_format_lite.h])

### Summary
The external report describes a state-accounting bug where an "increment" operation (`triggerDefaultWarning` adding `netLateInterest_` to `unrealizedLosses`) is not matched by an equivalent "decrement" on the corresponding revert path (`_revertDefaultWarning`), leaving a permanent, attacker-triggerable discrepancy in shared accounting state that corrupts future unrelated operations (withdrawals). The Protobuf analog is `WireFormatLite::ReadGroup`/`ReadMessage` in [1](#0-0) , where `CodedInputStream::recursion_budget_` (and, for `ReadMessage`, the byte limit) is decremented/pushed unconditionally, but the compensating decrement/pop is skipped whenever the nested parse fails — leaving the shared `CodedInputStream` object's recursion accounting permanently off-balance for any later use of that same stream.

### Finding Description
`CodedInputStream` maintains `recursion_budget_` as a member field that is intended to be symmetrically incremented and decremented (or pushed/popped for limits) around every nested message/group parse, exactly as documented in [2](#0-1) .

In `ReadGroup`:
```
if (!input->IncrementRecursionDepth()) return false;
if (!value->MergePartialFromCodedStream(input)) return false;   // <-- early return, no decrement
input->UnsafeDecrementRecursionDepth();
``` [3](#0-2) 
If the nested `MergePartialFromCodedStream` fails (e.g. because the attacker supplies a truncated/malformed group payload — fully attacker-controlled bytes on a public parse path), the function returns `false` without ever calling `UnsafeDecrementRecursionDepth()`. The recursion depth increment performed by `IncrementRecursionDepth()` is never undone.

In `ReadMessage` the analog is worse because it also affects the byte-limit stack:
```
std::pair<io::CodedInputStream::Limit, int> p =
    input->IncrementRecursionDepthAndPushLimit(length);
if (p.second < 0 || !value->MergePartialFromCodedStream(input)) return false;   // <-- limit never popped, budget never restored
return input->DecrementRecursionDepthAndPopLimit(p.first);
``` [4](#0-3) 
`IncrementRecursionDepthAndPushLimit` unconditionally does `PushLimit(byte_limit)` and `--recursion_budget_` per [5](#0-4) . If the budget check (`p.second < 0`) fails or the nested `MergePartialFromCodedStream` fails, the function returns immediately: the pushed limit is never popped and the decremented budget is never restored via `DecrementRecursionDepthAndPopLimit` (which does `ConsumedEntireMessage()`, `PopLimit()`, and `++recursion_budget_` together) per [6](#0-5) .

This is the direct structural analog of the reported bug: an accounting field (`unrealizedLosses` / here `recursion_budget_` and the limit stack) is mutated on entry unconditionally, but the compensating mutation on the "abort/revert" path is missing, leaving persistent, silently-wrong shared state.

### Impact Explanation
`CodedInputStream` is a stream object that consuming applications commonly reuse to read multiple length-delimited messages sequentially from one connection/buffer (the common “parse N delimited messages from one stream” pattern), or is passed down through recursive/extension parsing where the same object backs many message boundaries within one input. If any nested group/message inside that stream fails to parse (fully attacker-controlled by supplying a truncated or malformed nested field), the stream's `recursion_budget_` (and, for `ReadMessage`, its limit stack) is left corrupted for the remainder of that stream's lifetime. Because the recursion budget defaults to `100` and is never restored, an attacker can force spurious `RecursionLimitExceeded` failures on subsequent, entirely well-formed messages/fields parsed from the same stream, or — for `ReadMessage`'s unpopped limit — cause later reads on the stream to be bounded by the wrong (stale, inner) byte limit, misinterpreting or truncating legitimate downstream field data. This is an integrity failure of the parser's internal accounting reachable purely by a client sending bounded binary protobuf through the public `MergePartialFromCodedStream`/`ReadGroup`/`ReadMessage` surface, analogous to the reported pool accounting corruption that persists and affects unrelated future operations.

### Likelihood Explanation
`ReadGroup`/`ReadMessage` in `wire_format_lite.h` are reached by the lite-runtime (proto2 lite generated code, and any code path using `WireFormatLite` for parsing `TYPE_GROUP`/`TYPE_MESSAGE` fields) whenever a nested field's bytes are malformed or truncated — a trivially attacker-craftable, bounded input. No privileged access or special schema is needed; only a nested field encoded with a length/tag that causes its inner parse to fail partway through. Likelihood of triggering the imbalance is high; the additional precondition for observable impact (stream reuse across multiple message boundaries after a failure) depends on the consuming application's usage pattern, which is common but application-specific.

### Recommendation
Ensure `ReadGroup`/`ReadMessage` restore the recursion budget (and pop the pushed limit) on every exit path, not just the success path — e.g. wrap the nested parse in a scope guard/RAII that always calls `UnsafeDecrementRecursionDepth()`/`DecrementRecursionDepthAndPopLimit()` regardless of whether `MergePartialFromCodedStream` succeeded, mirroring how `ParseContext::ParseMessage` unconditionally restores `depth_` after the nested `_InternalParse` call in [7](#0-6) . Add fuzz/unit tests that parse a stream containing a malformed nested group/message followed by additional valid messages on the same `CodedInputStream`, asserting the recursion budget and limit stack are unchanged after the failed parse.

### Proof of Concept
1. Construct a bounded binary payload for a lite message containing:
   - Field A: a `TYPE_MESSAGE` (or `TYPE_GROUP`) field whose declared length exceeds the actual remaining bytes (truncated), causing the inner `value->MergePartialFromCodedStream(input)` in `ReadGroup`/`ReadMessage` to return `false`.
   - Field B (following, well-formed): a normal scalar/message field.
2. Feed this payload through a single `CodedInputStream` wrapping a `ZeroCopyInputStream`, and after the top-level parse call reports failure for the first message, reuse the same `CodedInputStream` object to attempt to parse Field B or a subsequent independent message from the remaining buffer (a pattern used by code that tries to skip/recover from malformed sub-messages, or reads back-to-back delimited messages off one stream).
3. Observe that `recursion_budget_` on the reused `CodedInputStream` is now permanently lower (or the limit stack contains a stale, unpopped limit) than it should be, because `UnsafeDecrementRecursionDepth()`/`DecrementRecursionDepthAndPopLimit()` in [8](#0-7)  was skipped on the failing path — subsequent legitimate, non-malicious nested messages read from the same stream can now spuriously hit `RecursionLimitExceeded` or be parsed against the wrong byte-limit boundary, confirming the persistent accounting corruption analogous to the reported `unrealizedLosses` discrepancy.

template <typename MessageType>
inline bool WireFormatLite::ReadGroup(int field_number,
                                      io::CodedInputStream* input,
                                      MessageType* value) {
  if (!input->IncrementRecursionDepth()) return false;
  if (!value->MergePartialFromCodedStream(input)) return false;
  input->UnsafeDecrementRecursionDepth();
  // Make sure the last thing read was an end tag for this group.
  if (!input->LastTagWas(MakeTag(field_number, WIRETYPE_END_GROUP))) {
    return false;
  }
  return true;
}
template <typename MessageType>
inline bool WireFormatLite::ReadMessage(io::CodedInputStream* input,
                                        MessageType* value) {
  int length;
  if (!input->ReadVarintSizeAsInt(&length)) return false;
  std::pair<io::CodedInputStream::Limit, int> p =
      input->IncrementRecursionDepthAndPushLimit(length);
  if (p.second < 0 || !value->MergePartialFromCodedStream(input)) return false;
  // Make sure that parsing stopped when the limit was hit, not at an endgroup
  // tag.
  return input->DecrementRecursionDepthAndPopLimit(p.first);
}

bool CodedInputStream::DecrementRecursionDepthAndPopLimit(Limit limit) {
  bool result = ConsumedEntireMessage();
  PopLimit(limit);
  ABSL_DCHECK_LT(recursion_budget_, recursion_limit_);
  ++recursion_budget_;
  return result;
}

const char* ParseContext::ParseMessage(MessageLite* msg, const char* ptr) {
  LimitToken old;
  ptr = ReadSizeAndPushLimitAndDepth(ptr, &old);
  if (ptr == nullptr) return ptr;
  auto old_depth = depth_;
  ptr = msg->_InternalParse(ptr, this);
  if (ptr != nullptr) ABSL_DCHECK_EQ(old_depth, depth_);
  depth_++;
  if (!PopLimit(std::move(old))) return nullptr;
  return ptr;
}
