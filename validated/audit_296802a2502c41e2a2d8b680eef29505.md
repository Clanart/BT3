### Title
`EnsureInstalled#check_shop_domain` binds the request's shop context purely to the unauthenticated `shop` param, allowing cross-shop offline session loading — ([File: app/controllers/concerns/shopify_app/ensure_installed.rb])

### Finding Description
In the legacy (non `use_new_embedded_auth_strategy`) branch, `EnsureInstalled` wires up only three `before_action`s: `check_shop_domain`, `check_shop_known`, and `validate_non_embedded_session` [1](#0-0) .

`current_shopify_domain` derives the "installed shop" identity solely from `params[:shop]`, passed through `ShopifyApp::Utils.sanitize_shop_domain` [2](#0-1) . That sanitizer only normalizes/validates that the string resolves to a *trusted domain suffix* (`myshopify.com`, `shopify.com`, etc.) — it performs no cryptographic or session-based proof that the current requester actually controls that shop [3](#0-2) .

`installed_shop_session` then blindly loads the offline session for whatever domain came out of that sanitizer [4](#0-3) , and `check_shop_known` assigns it to `@shop` for use by the controller action [5](#0-4) .

Crucially, `validate_non_embedded_session` — the only check that touches Shopify's API to validate anything — is skipped entirely whenever `loaded_directly_from_admin?` (i.e. `params[:embedded] == "1"`) is true [6](#0-5) [7](#0-6) . Even when it does run (non-embedded case), it only pings the Admin API with the *already loaded* victim token to confirm the token is still valid — it does not verify that the current requester is the merchant who owns that token. A valid, unrevoked victim token will simply pass this check.

There is no HMAC verification, no signed session cookie check, and no ID-token/JWT verification anywhere in this legacy code path (that verification only exists in the separate `use_new_embedded_auth_strategy` branch, via `ShopifyApp::TokenExchange#current_shopify_domain`, which derives the shop from a verified JWT rather than from `params[:shop]` [8](#0-7) ). Consequently, in the legacy configuration, an unauthenticated attacker can supply `shop=<victim>.myshopify.com&embedded=1` (or `embedded=0` with a still-valid victim token) to any controller action that includes `EnsureInstalled`, causing `@shop`/`installed_shop_session` to be populated with the victim merchant's real offline session/access token for the duration of that request.

### Impact Explanation
Any downstream controller logic that uses `@shop` / `installed_shop_session` (e.g., to call the Admin API or render shop-specific data) will operate using another merchant's offline access token purely because the attacker supplied that merchant's domain string in a request parameter. This is a cross-shop/session confusion vulnerability — unauthorized use of another store's offline session/token — matching Shopify's in-scope "cross-shop data or token access" impact class.

### Likelihood Explanation
This requires only knowledge of a target shop's `*.myshopify.com` domain (public/guessable/enumerable) and use of the legacy, non-token-exchange configuration of `shopify_app` (`use_new_embedded_auth_strategy?` false), which remains a supported configuration in this gem. No secrets, valid tokens, or victim interaction are required — a single crafted GET request is sufficient; concurrency is not needed to trigger it deterministically, since the flaw is a straightforward authorization-binding gap rather than a race condition.

### Recommendation
In the legacy path, do not trust `params[:shop]` as the sole source of shop identity for loading a session that will be used to act on Shopify's API. Either require verification (HMAC/ID token) binding the requester to the claimed shop before `installed_shop_session` is used for anything beyond an initial unauthenticated redirect, or deprecate/disable the legacy branch in favor of the token-exchange strategy, which already derives `current_shopify_domain` from a verified JWT (`authenticated_shopify_domain_from_token`) rather than from a raw param.

### Proof of Concept
```ruby
# Controller including ShopifyApp::EnsureInstalled, legacy config
# (ShopifyApp.configuration.use_new_embedded_auth_strategy? == false)

class HomeController < ApplicationController
  include ShopifyApp::EnsureInstalled
end

# Attacker request (no session, no token, no HMAC):
get "/", params: { shop: "victim-shop.myshopify.com", embedded: "1" }

# Expected (buggy) behavior:
# - check_shop_domain passes (sanitize_shop_domain accepts victim-shop.myshopify.com)
# - check_shop_known loads victim's real offline session into @shop
# - validate_non_embedded_session is skipped (loaded_directly_from_admin? == true)
# - controller action executes with @shop bound to the victim's offline session/token
```
Assertion: `@shop.shop == "victim-shop.myshopify.com"` and `@shop.access_token` equals the victim's stored token, despite the request originating from an unrelated, unauthenticated attacker.

      def sanitize_shop_domain(shop_domain)
        uri = uri_from_shop_domain(shop_domain)
        return if uri.nil? || uri.host.nil?

        trusted_domains.each do |trusted_domain|
          no_shop_name_in_subdomain = uri.host == trusted_domain
          from_trusted_domain = trusted_domain == uri.domain

          return myshopify_domain_from_unified_admin(uri) if unified_admin?(uri) && from_trusted_domain
          return nil if no_shop_name_in_subdomain || uri.host&.empty?
          return uri.host if from_trusted_domain
        end
        nil
      end
