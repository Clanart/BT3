### Title
Static ChaCha20 IV combined with missing validation of registered DKG encryption keys enables key-share recovery by any observer - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
The PedPoP DKG encrypts every secret share with ChaCha20 under a key derived from an ECDH between a random per-message scalar and the *recipient's registered encryption key*, using a hard-coded static IV `b"DKG IV v0.2\0"`. The code asserts this is safe because "the key is single-use," but that invariant only holds if the recipient's encryption key is a legitimate, non-identity group element. `EncryptionKeyMessage::read` / `Decryption::register` accept the encryption key with only a canonical-encoding check and no proof-of-possession or identity rejection, so a participant can register the group identity as their `enc_key`. Every share encrypted to that participant then uses the identical, publicly computable ChaCha20 key/IV pair, so the ciphertexts are recoverable by any unprivileged observer of the DKG transcript.

### Finding Description
`cipher()` builds the ChaCha20 instance with a transcript-derived key and a constant IV:

```rust
// crypto/dkg/pedpop/src/encryption.rs
let mut iv = Cc20Iv::default();
iv.copy_from_slice(b"DKG IV v0.2\0");
let res = ChaCha20::new(&key, &iv);
```

The key comes from `transcript(context, ecdh)`, where `ecdh = per_message_scalar * recipient_enc_pub_key` (`ecdh()` at line 95, used by `encrypt()` at line 154 and `decrypt()` at line 487). The safety comment ("If we never reuse the key, we can't have the opportunity to reuse a nonce") is only true when `recipient_enc_pub_key` is non-identity: with `enc_key = identity`, `ecdh` is the identity point for *every* message regardless of the random per-message scalar, collapsing every ciphertext to that recipient to the same keystream — worse, a keystream computable by anyone who knows `context`, since `identity.to_bytes()` is public.

Nothing prevents this. `EncryptionKeyMessage::read` parses `enc_key` via `C::read_G` (encryption.rs line 58), and `Ciphersuite::read_G` (crypto/ciphersuite/src/lib.rs lines 91-101) only enforces a canonical encoding — the identity point is canonical on Ristretto/ed25519. `Decryption::register` (encryption.rs lines 351-362) stores `msg.enc_key` with no identity check and no PoP on the encryption key (the PoP only exists on the *per-message* key, per the spec's own description). `Encryption::encrypt` (line 466) then indexes `self.decryption.enc_keys[&participant]` directly.

### Impact Explanation
A participant who registers `enc_key = identity` causes all `n-1` honest dealers' `EncryptedMessage<C, SecretShare<C::F>>` addressed to them (`generate_secret_shares` → `self.encryption.encrypt`, lib.rs line 369) to be encrypted under a keystream any observer can recompute as `ChaCha20(H_transcript(context || identity_bytes), static_IV)`. An unprivileged party who only sees the on-wire messages recovers that participant's full set of secret shares `s_j(i)` and thus their aggregated threshold share — i.e., recovery of a private key share from purely public data. The same effect occurs for any `enc_key` with publicly known discrete log to a point whose ECDH an attacker can compute, and for small-subgroup/torsion points on suites where `read_G` admits them.

### Likelihood Explanation
The attack requires a DKG participant (or anyone able to inject an `EncryptionKeyMessage` for a participant on the assumed-authenticated channel) to register a malformed `enc_key`. This is a single crafted field in the round-1 commitment message, with no check anywhere in `verify_r1`/`register` to stop it. Any network observer — not a participant — then performs the recovery offline. Medium likelihood.

### Recommendation
Validate `enc_key` in `Decryption::register` / `EncryptionKeyMessage` handling: reject the identity (and any non-prime-order point where applicable), and require a Schnorr proof-of-possession bound to `(context, participant, enc_key)` at registration, mirroring the per-message PoP already implemented. Belt-and-suspenders, bind the per-message public key (`msg.key`) or a random nonce into `cipher()`'s transcript so the keystream is unique even if the ECDH result repeats.

### Proof of Concept
1. Malicious participant `i` runs PedPoP round 1, publishing `EncryptionKeyMessage { msg: valid Commitments, enc_key: C::G::identity() }`. `C::read_G` accepts the canonical identity encoding; `register` stores it unchecked.
2. Every honest dealer `j` calls `encrypt(rng, context, j, to = identity, share_j_i)`. `ecdh = identity * k_j = identity`; `cipher()` derives the same key `H(context || identity)` and IV `"DKG IV v0.2\0"` for all `j`.
3. Observer computes `ks = ChaCha20(key, iv)` keystream once and recovers `share_j_i = ct_j XOR ks` for every sender, then sums them to obtain participant `i`'s complete secret share — a private threshold key share recovered from public transcript bytes alone.
