### Title
Permissionless sends to deterministically-derived internal offset addresses are misclassified and never credited, locking funds in the multisig - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the Salty `VestingWallet.release()` issue — where an unprivileged party could force funds into a contract whose accounting path assumed it was the sole mover — Serai's Bitcoin `Scanner` matches outputs purely by `script_pubkey`, and the offset addresses it recognizes (`Branch`, `Change`, `Forwarded`) are deterministically derived from the public group key via `hash_to_F`. Any external party can compute these "internal-only" addresses and send BTC to them. The scanner will classify such an output as `Change`/`Forwarded`/`Branch` rather than `External`, so the downstream logic that only credits `OutputType::External` outputs drops it. The funds sit in the multisig but are never turned into a deposit/instruction — effectively locked, exactly like SALT released into `Upkeep` outside the `performUpkeep` flow.

### Finding Description
`Scanner::new` registers the base key's P2TR script, and `register_offset` registers `key + G*offset` scripts keyed by script alone [1](#0-0) . `scan_transaction` reports any output whose `script_pubkey` matches, with no authentication of the sender or transaction context [2](#0-1) . The `Branch`/`Change`/`Forwarded` offsets are fixed, publicly computable `hash_to_F(KEY_DST, ...)` values, so any unprivileged party can derive these internal addresses from the known group key [3](#0-2) . `get_outputs` then tags each scanned output by offset kind, and the multisig event handler retains only `OutputType::External` for instruction creation; `Forwarded` outputs not matching a registered forwarded plan are left to "die out" [4](#0-3) . No path reconciles a `Change`/`Branch`/`Forwarded`-classified output back into accounting, and `key()` just strips the offset, so the output is spendable only by the group key yet no spend plan is ever created for it [5](#0-4) .

### Impact Explanation
An attacker sends BTC directly to a multisig's change/branch/forward address. The output is reported and persisted but classified as internal, never converted to an `InInstruction` or scheduled payment, and never credited to any depositor. Funds are locked in the multisig until manual intervention — the same "released but unaccounted" loss class as H-01. Denial-of-crediting of real deposits is also possible: a legitimate user sending to the wrong (deterministic) offset address loses the deposit with no refund path.

### Likelihood Explanation
Medium. Reachable by any unprivileged party using only the public group key and the public `KEY_DST` constants — no key material, collusion, or privileged access required. Exploitation cost is one Bitcoin transaction.

### Recommendation
Bind internal-kind classification to provenance, not just `script_pubkey`: e.g., only treat an output as `Change`/`Branch`/`Forwarded` when the spending transaction was created by the multisig itself (eventuality/known-txid check), and classify all other matched outputs as `External` so they are credited or refunded. Alternatively, derive internal offsets from a secret seed so external parties cannot compute the internal addresses.

### Proof of Concept
1. Observe the current multisig group key `K` (public, e.g. via `set_keys`).
2. Compute `forward_offset = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"forward")` (incrementing per `register_offset` until `K + G*offset` is even) and build `p2tr_script_buf(K + G*forward_offset)` [6](#0-5) .
3. Broadcast a transaction paying ≥ `N::DUST` to that script.
4. `Scanner::scan_transaction` returns a `ReceivedOutput`; `get_outputs` tags it `OutputType::Forwarded` (or `Change`/`Branch` for the other offsets); the event handler retains only `External` outputs, so no instruction or plan is created and the BTC is never credited or spent [7](#0-6) [8](#0-7) .

    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

fn scanner(

) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),

    OutputType::Change,
