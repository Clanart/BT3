### Title
SSRF via attacker-controlled DataLayer mirror/server URLs in delta-file sync - ([File: chia/data_layer/download_data.py])

### Summary
DataLayer's subscription sync path fetches delta/full-tree files by issuing outbound HTTP requests to server URLs that are sourced from on-chain DataLayer "mirror" records rather than from a fixed, operator-controlled allowlist. `http_download()` builds the request target directly from `server_info.url` with no restriction on scheme, host, or destination network range, mirroring the "fetch content from a user-supplied URL" bug class in CVE-2025-44594 (Halo's `upload-from-url` SSRF).

### Finding Description
`DataLayer.fetch_and_validate()` pulls candidate server URLs for a store id from `self.data_store.get_available_servers_for_store()` and, per the module's own documented invariants, these subscription server URLs are populated by syncing "subscription URLs from wallet mirrors" during `update_subscription()` [1](#0-0) , and are explicitly called out as an *external, untrusted* trust boundary: "Plugin and mirror URLs are external trust inputs... file path/name validation must stay strict" [2](#0-1) .

For each server candidate, `fetch_and_validate()` calls `insert_from_delta_file()` [3](#0-2)  which in turn calls `download_file()` [4](#0-3) . When no plugin downloader is configured, `download_file()` calls `http_download()` directly:

```
async with aiohttp.ClientSession() as session:
    async with session.get(
        server_info.url + "/" + filename,
        headers=headers,
        timeout=timeout,
        proxy=proxy_url,
    ) as resp:
``` [5](#0-4) 

`server_info.url` is not validated against local/internal address ranges, non-HTTP schemes, or an operator allowlist anywhere in `http_download()`, `download_file()`, or `insert_from_delta_file()` [6](#0-5) . The same untrusted-URL pattern also drives `get_downloader()`, which POSTs the untrusted `url` value to configured downloader plugins [7](#0-6) . Because mirror/server URL records are documented as external, on-chain-sourced trust inputs rather than operator-configured values, any actor able to register a mirror URL for a store id that a victim node subscribes to can cause the victim's DataLayer process to issue outbound HTTP requests to an arbitrary attacker-chosen target (e.g., loopback services, cloud metadata endpoints, or internal-network hosts) as soon as that node runs its periodic `fetch_and_validate`/`update_subscription` sync loop.

### Impact Explanation
An attacker who can get a malicious mirror/server URL associated with a store id a victim DataLayer node subscribes to can force that node to make server-side HTTP requests to arbitrary internal or local network destinations (SSRF). Depending on what is reachable from the victim's DataLayer host (cloud metadata service, internal admin APIs, other loopback-bound RPC ports), this can be used for internal network reconnaissance, unauthorized reads of otherwise unreachable services, or as a pivot for further compromise — a network-reachable, unauthenticated-triggerable server-side request forgery consistent with the reachable Medium/High severity bar for this scan.

### Likelihood Explanation
DataLayer's periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) runs automatically for every subscribed store without additional user interaction beyond having subscribed to (or owning/mirroring) the store id, and mirror/server URLs are explicitly documented in this codebase as untrusted external input rather than a trusted, operator-set list. This makes the SSRF trigger a normal, expected part of DataLayer's replication behavior rather than a rare edge case — as long as the attacker can get their URL into the mirror/server list for a store the victim node processes.

### Recommendation
Validate and restrict mirror/server URLs before dereferencing them in `http_download()`/`download_file()`/`get_downloader()`: enforce an allowlist of schemes (http/https only), resolve and reject requests targeting loopback, link-local, private/internal (RFC1918/RFC4193), and cloud-metadata address ranges, and consider requiring explicit operator opt-in/allowlisting of mirror hosts rather than trusting on-chain-sourced URLs implicitly. This should be applied consistently across `http_download`, `download_file`'s plugin POST path, and `get_downloader`/`get_uploaders`/`get_plugin_info`.

### Proof of Concept
1. Register (or otherwise cause to exist) a mirror/server URL record for a DataLayer store id that the victim node subscribes to or mirrors, pointing at an attacker-chosen destination such as `http://127.0.0.1:<internal-port>/` or a cloud metadata IP.
2. Wait for the victim's `periodically_manage_data()` loop to run `update_subscription()` for that store id, which calls `fetch_and_validate()` [8](#0-7) .
3. `fetch_and_validate()` selects the malicious server entry and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim's DataLayer process to issue an outbound GET to the attacker-controlled URL [9](#0-8) .

Note: I was not able to fully confirm within available tool calls whether creating/registering a DataLayer mirror record for an arbitrary store id is restricted to the store owner or is open to any chain participant (the mirror-coin creation/authorization logic lives in `chia/wallet/db_wallet/db_wallet_puzzles.py` and `chia/data_layer/data_layer_wallet.py`, which I could not finish reviewing in depth). If mirror registration turns out to require store ownership, the practical attacker set narrows to a malicious/compromised store owner or mirror operator rather than any unprivileged chain participant; the underlying missing-URL-validation SSRF sink in `http_download()` itself is confirmed regardless.

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
