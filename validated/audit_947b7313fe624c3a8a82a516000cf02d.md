### Title
Wrong field passed to `deposit_constant` in `host_deposit_constant` causes permanent journal hash mismatch, blocking operator proof generation and enabling collateral slashing — (`bridge-circuit-host/src/structs.rs`)

---

### Summary

`host_deposit_constant` in `bridge-circuit-host/src/structs.rs` passes `deposit_value_bytes` (the raw deposit amount from the EIP-1186 storage proof) as the `move_txid` argument to `deposit_constant()`. The actual bridge circuit guest passes the correct `move_txid` (the move-to-vault transaction ID from the same storage proof). Because the host-side journal hash is computed from the wrong `deposit_constant`, the check `if *journal_hash.as_bytes() != succinct_receipt_journal` in `prove_bridge_circuit` always fails for any real withdrawal. An honest operator challenged on-chain can never produce a valid proof, causing their collateral to be slashed.

---

**How the wrong value propagates to a fatal check:**

---

### Impact Explanation

When a challenger spends the challenge connector on-chain, the operator must call `send_asserts`, which calls `prove_bridge_circuit`. Because `prove_bridge_circuit` always returns `Err("Journal hash mismatch")`, the operator can never post valid assert transactions. After the assert timeout elapses, the challenger can spend the disprove connector and burn the operator's collateral — even though the operator is honest and the withdrawal is legitimate. [9](#0-8) 

This is a **permanent, unconditional liveness failure** of the challenge-response path: every challenged operator loses their collateral regardless of correctness.

---

### Likelihood Explanation

The bug is triggered on every invocation of `prove_bridge_circuit` for a real withdrawal (non-regtest, non-dev-mode). No adversarial input is required — a normal on-chain challenge by any party is sufficient. The `deposit_value_bytes` (a bridge amount like `0x00000000000F4240` for 1,000,000 sat) is structurally different from a 32-byte txid, so the mismatch is guaranteed.

---

### Recommendation

In `host_deposit_constant`, replace `deposit_value_bytes` with the actual `move_txid` extracted from the storage proof, mirroring what the guest circuit does:

```rust
// Correct: extract move_txid from deposit storage proof value
let move_txid: [u8; 32] = deposit_storage_proof.value.to_be_bytes::<32>();

Ok(deposit_constant(
    operator_xonlypk,
    input.watchtower_challenge_connector_start_idx,
    &input.all_tweaked_watchtower_pubkeys,
    move_txid,   // ← now matches what the guest circuit uses
    round_txid,
    kickoff_round_vout,
    input.hcp.genesis_state_hash,
))
```

Note: the storage proof value for the deposit slot *is* the move txid (as confirmed by `verify_storage_proofs` returning `MoveTxid(deposit_storage_proof.value.to_be_bytes())`), so the bytes are correct — only the variable name and semantic intent were confused with `deposit_value_bytes`. [10](#0-9)

### Proof of Concept

1. Operator is challenged on-chain (challenge connector spent).
2. Operator calls `send_asserts` → `prove_bridge_circuit(bridge_circuit_host_params, bridge_circuit_elf)`.
3. Inside `prove_bridge_circuit`:
   - `SuccinctBridgeCircuitPublicInputs::new(...)` calls `host_deposit_constant`.
   - `host_deposit_constant` computes `deposit_constant` using `deposit_value_bytes` (e.g., `[0,0,...,0,0x0F,0x42,0x40]` for 1,000,000 sat) as `move_txid`.
   - `host_journal_hash()` = `blake3(deposit_constant_wrong || blake3(payout_hash || latest_hash || wt_flags))`.
4. The circuit runs with the correct `move_txid` (a 32-byte txid like `[ab,cd,...]`) and commits `journal_hash_correct`.
5. Check: `journal_hash_wrong ≠ journal_hash_correct` → `Err("Journal hash mismatch")`.
6. `send_asserts` fails; operator cannot post assert transactions.
7. After `assert_timeout_timelock` blocks, challenger executes disprove, burning operator collateral. [11](#0-10) [12](#0-11)

```rust
        .ok_or(BridgeCircuitHostParamsError::InvalidOperatorPubkey)?;

    let deposit_storage_proof: EIP1186StorageProof =

    let round_txid = input.kickoff_tx.input[0]
        .previous_output
        .txid
        .to_byte_array();

        round_txid,
```

```rust
pub fn journal_hash(
    payout_tx_blockhash: PayoutTxBlockhash,
    latest_blockhash: LatestBlockhash,
    challenge_sending_watchtowers: ChallengeSendingWatchtowers,
    deposit_constant: DepositConstant,
) -> blake3::Hash {
    let concatenated_data = [
        payout_tx_blockhash.0,
        latest_blockhash.0,
        challenge_sending_watchtowers.0,
    ]
    .concat();

    let binding = blake3::hash(&concatenated_data);
    let hash_bytes = binding.as_bytes();

    let concat_journal = [deposit_constant.0, *hash_bytes].concat();

    blake3::hash(&concat_journal)
}
```
