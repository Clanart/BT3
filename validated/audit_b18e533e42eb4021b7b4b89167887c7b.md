### Title
Unvalidated `ReceivedOutput` deserialization reports attacker-selected Bitcoin outputs as wallet-controlled - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Medium severity. `ReceivedOutput::read` constructs a wallet output record from an attacker-controlled scalar, `TxOut`, and `OutPoint` without checking that the output’s `script_pubkey` corresponds to `key + offset * G`. [1](#0-0) 

### Finding Description
The unsafe-deserialization analog is the construction of a semantically privileged `ReceivedOutput` object directly from untrusted bytes. [2](#0-1)  The parser accepts any canonical scalar offset, any consensus-valid `TxOut`, and any consensus-valid `OutPoint`, then returns them as a coherent wallet output. [3](#0-2) 

The missing invariant is established by `Scanner`: it maps scripts generated as `p2tr_script_buf(key + generator * offset)` back to their offsets. [4](#0-3)  During scanning, a `ReceivedOutput` is produced only when the transaction output’s `script_pubkey` exists in that map. [5](#0-4) 

`ReceivedOutput::read` bypasses that ownership check entirely. [1](#0-0) 

### Impact Explanation
An attacker can supply serialized bytes describing an output paying an unrelated script while assigning it an arbitrary wallet offset. [1](#0-0)  Downstream code that trusts the returned object will expose `value()`, `output()`, `outpoint()`, and `offset()` as though the output were spendable by the wallet. [6](#0-5) 

This causes funds to be reported as received when they are not controlled by, or spendable through, the claimed wallet key. [5](#0-4) 

### Likelihood Explanation
The trigger requires only attacker-controlled bytes passed to `ReceivedOutput::read`; no private key material, validator privilege, or malformed consensus encoding is needed. [1](#0-0)  The deserialized `TxOut` can be perfectly valid on Bitcoin consensus while being unrelated to the wallet’s scanner key. [3](#0-2) 

### Recommendation
Bind deserialization to the wallet key or scanner context and verify `output.script_pubkey == p2tr_script_buf(key + generator * offset)` before returning `ReceivedOutput`. [4](#0-3)  Prefer rescanning the referenced transaction through `Scanner::scan_transaction` instead of trusting a serialized wallet-output claim. [7](#0-6) 

### Proof of Concept
```rust
// Attacker-controlled script and output, not generated for the victim's
// scanner key or any registered offset.
let mut blob = Scalar::ZERO.to_bytes().to_vec();
attacker_txout.consensus_encode(&mut blob).unwrap();
attacker_outpoint.consensus_encode(&mut blob).unwrap();

// Accepted as a wallet output despite scanner.scan_transaction rejecting the
// same script as unrecognized.
let claimed = ReceivedOutput::read(&mut blob.as_slice()).unwrap();
assert_eq!(claimed.value(), attacker_txout.value.to_sat());
```

`Scalar::ZERO` is canonically decoded by `Secp256k1::read_F`, while the following `TxOut` and `OutPoint` are only consensus-decoded, not authenticated as belonging to the wallet. [1](#0-0)
