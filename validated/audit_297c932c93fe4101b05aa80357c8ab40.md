### Title
Untrusted `WWW-Authenticate` realm header lets an attacker-controlled git remote/proxy force GitHub Desktop to treat it as a trusted GitHub Enterprise host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` classifies a git-remote endpoint as `'enterprise'`, `'github.com'`, `'ghe.com'`, or `'generic'` in order to decide whether GitHub Desktop should hand out account tokens or prompt the user to sign in with GitHub credentials. One of its checks trusts a header (`wwwauth[...]`) that is fully controlled by the remote server/proxy the git process is talking to, with no verification that the host is actually GitHub-owned infrastructure.

### Finding Description
When Desktop performs a git network operation (clone/fetch/push, including for submodules), git relays any `WWW-Authenticate` challenge headers it receives from the remote HTTP(S) server to the credential helper as `wwwauth[N]=...` fields. `getEndpointKind` uses this content as a "happy path" signal: [1](#0-0) 

```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```

This value is attacker-supplied server output, not something verified against GitHub's actual API (e.g. the `x-github-enterprise-version` header check used elsewhere in `endpoint-capabilities.ts` is at least a GitHub-specific response header, whereas here any HTTP server can set `WWW-Authenticate: Basic realm="GitHub"` on a 401 response). Any git server the victim connects to — a malicious remote the user adds/clones, a compromised or spoofed proxy sitting on the path to a real host, or an attacker-controlled submodule URL embedded in `.gitmodules` of a cloned repository — can send this header and be classified as `'enterprise'` purely because of a string match, with no ownership check of the domain.

Downstream in `getCredential`, this classification directly controls behavior: [2](#0-1) 

If the endpoint is misclassified as `'enterprise'` and no stored account exists for that exact `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` — presenting the user with what looks like a legitimate "Sign in to GitHub Enterprise" flow, but pointed at the attacker's host, purely because the attacker's server sent a spoofed header. This is the same class of bug as the Vault `_settle` issue: a piece of state that should only be derived from a verified, privileged source (the real global/`0` account in Vault; a genuinely GitHub-owned endpoint here) is instead computed from attacker-influenced input and used to drive security-relevant behavior (fee accounting there; credential/sign-in routing here).

### Impact Explanation
Successful misclassification turns an untrusted host into one Desktop treats as "GitHub-like," causing the app to initiate its GitHub Enterprise sign-in UX against an attacker-chosen endpoint. This is a phishing amplification vector built entirely into the app's own trusted UI chrome ("Sign in to GitHub Enterprise") rather than a browser address bar the user might scrutinize, increasing the odds that a user enters credentials or approves an OAuth/device-flow authorization intended for their real account against the attacker's endpoint. It does not itself exfiltrate an existing stored token (the earlier `findGitHubTrampolineAccount` origin match still gates that), but it is a real, code-verifiable divergence from expected trust boundaries: classification of "is this GitHub" should never be derived from response content the peer controls.

### Likelihood Explanation
This path is reached on ordinary git network operations (clone/fetch/push/submodule update) whenever the server the git subprocess talks to returns a 401 with a crafted `WWW-Authenticate` header — no unusual user action beyond a normal clone/fetch of an attacker-hosted or MITM'd/proxied remote is required. The report explicitly allows "a git remote/proxy response" as an attacker-controlled input, which matches this exactly.

### Recommendation
Do not trust the `wwwauth[]` realm value as a standalone signal of GitHub identity. Either remove this heuristic entirely and rely only on `isDotCom`/`isGHE` (verified hostnames) plus the authenticated `isGitHubHost` HTTP probe, or require it to be corroborated by a second GitHub-specific signal (e.g. a valid `x-github-request-id`/`x-github-enterprise-version` response header, as already used in `endpoint-capabilities.ts`) before returning `'enterprise'`. At minimum, gate the sign-in prompt so that a first-seen "enterprise" classification derived only from `wwwauth` cannot silently open the GitHub Enterprise sign-in dialog without additional confirmation of host identity.

### Proof of Concept
1. Attacker sets up an HTTP(S) git server (or a MITM proxy on a network path, or a `.gitmodules` submodule URL) at `https://evil.example.com/some/repo.git`.
2. Victim adds/clones this remote (or clones a repository containing a submodule pointing at it) in GitHub Desktop.
3. Git performs the HTTPS handshake; the attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this as `wwwauth[0]=Basic realm="GitHub"` to Desktop's credential helper via `createCredentialHelperTrampolineHandler`.
5. `getEndpointKind` matches `v.includes('realm="GitHub"')` and returns `'enterprise'` for `evil.example.com`.
6. Since no account exists for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, and the victim is shown Desktop's native "Sign in to GitHub Enterprise" dialog for the attacker's domain. [3](#0-2)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
