### Title
Automatic Silent Remote URL Rewrite Based on Untrusted GitHub API Response Enables Push/Fetch Redirection - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
Desktop periodically refreshes a repository's associated GitHub metadata and, as a side effect, silently rewrites the local git remote's URL to whatever `clone_url` the GitHub API currently returns for the previously-associated `owner/name` pair. The identity check used to decide whether this rewrite is "safe" only compares parsed hostname/owner/name strings, not any durable repository identity (e.g. GitHub repository ID). This mirrors the Aave bug class: a security-relevant configuration value (here, the trusted push/fetch destination) is mutated automatically from an external, attacker-influenceable input, without re-validating the invariant the rest of the system depends on (that `origin` still points at the repo the user actually intends to work with).

### Finding Description
`repositoryWithRefreshedGitHubRepository` in `app-store.ts` runs as part of the repository refresh flow, calls `api.fetchRepository(owner, name)` to get the latest `IAPIRepository`, and when it succeeds, immediately calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`: [1](#0-0) 

`updateRemoteUrl` decides to overwrite the local `origin` remote with the API-provided `clone_url` if the protocol matches, the current remote still matches what was previously cached from the GitHub API, and the current remote doesn't already equal the new URL: [2](#0-1) 

The "safety" checks (`urlMatchesRemote`, `urlsMatch`) are purely structural string comparisons of hostname/owner/name parsed out of the URLs — they carry no notion of persistent repository identity: [3](#0-2) 

When the check passes, `gitStore.setRemoteURL` executes `git remote set-url` unconditionally, with no user confirmation dialog, and immediately emits an update: [4](#0-3) 

Because `owner`/`name` are the only keys used to re-fetch the GitHub repository record on each refresh, and because the "is this a safe rewrite" test only checks string equality of hostname/owner/name (not a stable ID), any actor who can cause the GitHub API to return a *different* repository object for the same `owner/name` pair the user is tracking (e.g. via a rename race / "repo-jacking" style takeover of a freed owner or repo name, or via a malicious/compromised GHE endpoint's API responses for self-hosted installs) can get Desktop to silently retarget the user's `origin` remote — an attacker-controlled `IAPIRepository` object flows directly into a git config mutation with no user prompt. This changes what `git push`/`git fetch` operate against without the user's knowledge, corrupting the destination of what the user believes they are pushing/pulling.

### Impact Explanation
If the rewrite succeeds, subsequent pushes from the user go to a repository the attacker controls (credential/commit exfiltration, or the attacker can serve back malicious refs on fetch/pull that the user then reviews/merges under a false sense of provenance). This is a silent corruption of push/fetch destination — squarely in the requested impact category ("silent corruption of what the user commits or pushes") — and requires no local access, no admin rights, and no prior host compromise; it is driven entirely by an attacker-influenced GitHub API object returned during a routine background refresh.

### Likelihood Explanation
The refresh path (`repositoryWithRefreshedGitHubRepository`) runs automatically/periodically for any tracked GitHub repository, not just on explicit user action, so the window of exposure is continuous as long as Desktop is open with the repository selected. The precondition (attacker able to make the GitHub API return a different repo for the same `owner/name`, e.g. by re-registering a name freed by rename/deletion, or a compromised/malicious GHE server for enterprise users) is a realistic "attacker controls a GitHub API object" scenario per the task's valid-impact criteria, though it does depend on the original owner/name becoming available for reuse, which somewhat limits likelihood versus a fully unprompted client-side bug.

### Recommendation
Do not silently rewrite `origin` (or any tracked remote) based on API-fetched `clone_url` alone. At minimum:
- Key the GitHub association on a stable, non-reusable identifier (GitHub repository `id`) rather than `owner/name`, and refuse to treat an API response as the "same" repository if the ID differs from what was last recorded.
- Require explicit user confirmation before calling `setRemoteURL` as a result of an automatic background refresh, exactly as `repository-settings.tsx` already requires for manual edits.
- Treat a mismatch between the previously known repository ID and the one returned for `owner/name` as a signal to warn the user rather than silently trust the new metadata.

### Proof of Concept
1. User adds/clones a GitHub repository `owner/repo` in Desktop; Desktop stores the `GitHubRepository` record (`owner`, `name`, `cloneURL`) tied to that `owner/name`.
2. The original repository is later renamed or deleted (e.g., owner renames their account or the repo), freeing `owner/repo`.
3. An attacker registers a new repository at the same `owner/repo` path (or, for GHE users, controls/compromises the API endpoint) and sets its `clone_url` to an attacker-controlled remote with matching `owner`/`name`/`hostname` parse results.
4. On the next background refresh, `repositoryWithRefreshedGitHubRepository` calls `api.fetchRepository(owner, name)` [5](#0-4) , receives the attacker's `apiRepo`, and passes it to `updateRemoteUrl`.
5. `updateRemoteUrl`'s checks (`protocolsMatch`, `remoteUrlUnchanged`) pass because they only inspect hostname/owner/name text, and `setRemoteURL` is invoked, silently rewriting the user's `origin` to the attacker's `clone_url` with no dialog or confirmation [6](#0-5) .
6. Subsequent `git push`/`git fetch` operations in Desktop now target the attacker's repository.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

/**
 * Match a URL-like string to the Clone URL of a GitHub Repository
 *
 * @param url A remote-like URL to verify against the existing information
 * @param gitHubRepository GitHub API details for a repository
 */
export function urlMatchesCloneURL(
  url: string,
  gitHubRepository: GitHubRepository
): boolean {
  if (gitHubRepository.cloneURL === null) {
    return false
  }

  return urlsMatch(gitHubRepository.cloneURL, url)
}

export function urlsMatch(url1: string, url2: string) {
  const firstIdentifier = parseRepositoryIdentifier(url1)
  const secondIdentifier = parseRepositoryIdentifier(url2)

  return (
    firstIdentifier !== null &&
    secondIdentifier !== null &&
    firstIdentifier.hostname === secondIdentifier.hostname &&
    firstIdentifier.owner === secondIdentifier.owner &&
    firstIdentifier.name === secondIdentifier.name
  )
}
