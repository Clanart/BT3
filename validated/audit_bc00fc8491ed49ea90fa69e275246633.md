## Analog Found

### Title
Unbounded Memory Growth via Public `AddrLocker` Mutex Map in `kaia_sendTransaction`/`eth_sendTransaction` - (File: api/addrlock.go)

### Summary
`api.AddrLocker` maintains a `map[common.Address]*sync.Mutex` that is populated on every call to `LockAddr` but is **never pruned** — there is no `delete`, TTL, or size cap anywhere in the type. [1](#0-0)  This map is keyed directly by the attacker-controlled `from` field of a publicly reachable RPC transaction-submission call, made **before** the node validates that the address corresponds to a real, held account.

### Finding Description
`AddrLocker.lock()` lazily creates and permanently stores a `*sync.Mutex` for every distinct address ever passed to `LockAddr`, with no corresponding removal path in `UnlockAddr` or elsewhere in the file. [2](#0-1) 

Both `KaiaTransactionAPI.SendTransaction` and `EthAPI.SendTransaction` call `nonceLock.LockAddr(args.From)`/`args.from()` unconditionally (when nonce is unset) *before* any account-ownership check occurs: [3](#0-2) [4](#0-3) 

The actual validation that the address maps to a real, held wallet key only happens afterward, inside `sign()`/`SignTransaction`, via `s.b.AccountManager().Find(account)`, which fails for any address the node does not manage. [5](#0-4) 

Because the lock is acquired for `args.From` regardless of whether that address is ever valid, an attacker does not need to own or control the address at all — any arbitrary 20-byte value works. Since `KaiaTransactionAPI` (`kaia` namespace) is registered with `Public: true`, and it shares the same `nonceLock *AddrLocker` instance created once per node in `node/cn/backend.go`, every unique `from` value ever submitted accumulates a permanent entry in `AddrLocker.locks`. [6](#0-5) 

### Impact Explanation
An unauthenticated public-RPC caller can repeatedly call `kaia_sendTransaction` (or `eth_sendTransaction`) with a freshly generated, never-before-seen `from` address on each call. Each call permanently adds one `common.Address -> *sync.Mutex` entry to the process-global `AddrLocker.locks` map — even though the transaction itself will subsequently fail with "unknown account" since the node cannot find a wallet for that address. Because the map is unbounded and never evicts entries, sustained abuse causes continuous, permanent heap growth, eventually exhausting node memory and degrading or crashing the node — an availability impact matching the CVE-2026-85585 bug class (unbounded resource consumption via a per-key lock structure with no eviction).

### Likelihood Explanation
High. `kaia_sendTransaction`/`eth_sendTransaction` are standard, publicly exposed JSON-RPC endpoints (`Public: true`) requiring no authentication beyond RPC access. [7](#0-6)  Generating unique 20-byte addresses is trivial and free for an attacker, and the lock is taken unconditionally whenever `args.Nonce`/`AccountNonce` is omitted, which is a normal, common request shape (nonce auto-assignment).

### Recommendation
Do not create/store a per-address lock before verifying the address corresponds to a wallet the node actually manages, or bound `AddrLocker` with an LRU/TTL eviction policy (similar to the `common/lru.Cache` or `knownHashSet`-style bounded structures already used elsewhere in the codebase) so that entries for invalid/unowned addresses are reclaimed rather than retained forever.

### Proof of Concept
1. Connect to the node's public RPC endpoint (no credentials required).
2. Repeatedly call `kaia_sendTransaction` (or `eth_sendTransaction`) with a `from` field set to a newly generated random address each time, omitting `nonce`, e.g.:
   ```
   curl -X POST -H "Content-Type: application/json" \
     --data '{"jsonrpc":"2.0","method":"kaia_sendTransaction","params":[{"from":"0x<random-address>","to":"0x0000000000000000000000000000000000dead","value":"0x0"}],"id":1}' \
     http://localhost:8551
   ```
3. Each call triggers `s.nonceLock.LockAddr(args.From)` and inserts a new entry into `AddrLocker.locks` before the subsequent `AccountManager().Find` failure is returned.
4. Repeating with millions of distinct addresses causes `AddrLocker.locks` to grow without bound, since no code path ever calls `delete` on it, leading to continuously increasing process memory.

type AddrLocker struct {
	mu    sync.Mutex
	locks map[common.Address]*sync.Mutex
}

// lock returns the lock of the given address.
func (l *AddrLocker) lock(address common.Address) *sync.Mutex {
	l.mu.Lock()
	defer l.mu.Unlock()
	if l.locks == nil {
		l.locks = make(map[common.Address]*sync.Mutex)
	}
	if _, ok := l.locks[address]; !ok {
		l.locks[address] = new(sync.Mutex)
	}
	return l.locks[address]
}

// LockAddr locks an account's mutex. This is used to prevent another tx getting the
// same nonce until the lock is released. The mutex prevents the (an identical nonce) from
// being read again during the time that the first transaction is being signed.
func (l *AddrLocker) LockAddr(address common.Address) {
	l.lock(address).Lock()
}

// UnlockAddr unlocks the mutex of the given account.
func (l *AddrLocker) UnlockAddr(address common.Address) {
	l.lock(address).Unlock()
}

	// Look up the wallet containing the requested signer
	account := accounts.Account{Address: addr}

	wallet, err := s.b.AccountManager().Find(account)

		return nil, err
	}
	// Request the wallet to sign the transaction

	if args.AccountNonce == nil {
		// Hold the addresse's mutex around signing to prevent concurrent assignment of
		// the same nonce to multiple accounts.
		s.nonceLock.LockAddr(args.From)
		defer s.nonceLock.UnlockAddr(args.From)
	}

	signedTx, err := s.SignTransaction(ctx, args)
	if err != nil {
		return common.Hash{}, err
	}

}

// SendTransaction creates a transaction for the given argument, sign it and submit it to the
// transaction pool.
func (api *EthAPI) SendTransaction(ctx context.Context, args EthTransactionArgs) (common.Hash, error) {
	if args.Nonce == nil {
		// Hold the addresses mutex around signing to prevent concurrent assignment of
		// the same nonce to multiple accounts.
		api.kaiaTransactionAPI.nonceLock.LockAddr(args.from())
		defer api.kaiaTransactionAPI.nonceLock.UnlockAddr(args.from())
	}
	if err := args.setDefaults(ctx, api.kaiaTransactionAPI.b); err != nil {
		return common.Hash{}, err
	}
	tx, _ := args.toTransaction()
	signedTx, err := api.kaiaTransactionAPI.sign(args.from(), tx)
	if err != nil {
		return common.Hash{}, err
	}
	// Check if signedTx is RLP-Encodable format.
	_, err = rlp.EncodeToBytes(signedTx)
	if err != nil {
		return common.Hash{}, err
	}
	return submitTransaction(ctx, api.kaiaTransactionAPI.b, signedTx)
}
