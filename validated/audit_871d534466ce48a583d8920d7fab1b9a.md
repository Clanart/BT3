## Title
No incentive to vote early enables last-second vote manipulation of bribe/gauge weight allocation - (File: `wombat/WombatBribeManager.sol`)

### Summary
`WombatBribeManager.vote()` lets any vlMGP holder freely add or remove votes to any pool at any time, and every party's current vote weight is fully public on-chain. There is no commit-reveal scheme, no time-locked voting window, and no decreasing-weight incentive to reward early voters. This is the same "GaugeController" bug class described in the report: since all votes and running totals are visible, a rational actor can wait, watch the public tallies, and cast (or retract) just enough vlMGP at the last possible moment to flip the outcome of the vote before it is locked in by `castVotes()`.

### Finding Description
`vote()` is fully public/permissionless and mutates the publicly-readable state `pool.totalVoteInVlmgp` and `userVotedForPoolInVlmgp` on every call, with no restriction on how often or how close to a "cast" a user may change their allocation: [1](#0-0) 

Anyone can read the exact live totals via `getVoteForLp`/`getVlmgpVoteForPools`/`poolInfos`, so the current standing of any vote is fully transparent at every block: [2](#0-1) 

`castVotes()`, which converts the accumulated vlMGP-weighted deltas into the actual Wombat gauge votes (and thereby fixes the bribe distribution for the period), is itself permissionless and can be called by anyone at any time — there is no fixed epoch cut-off enforced in this contract, only a `lastCastTime` bookkeeping variable: [3](#0-2) 

Because a voter who commits earlier (e.g., "Bob" putting in half of a pool's weight, expecting to win) has their position broadcast on-chain, a later voter ("Eve") can observe this exact figure and submit a transaction with the minimum vlMGP delta necessary to overturn the outcome, either by reallocating from another pool or by unvoting/re-voting via `unvote()`/`vote()`, right before `castVotes()` executes: [4](#0-3) 

This mirrors the report's exact exploit scenario: since all votes are public and there is no cost or penalty for voting late, the party who commits vlMGP capital earliest is strictly disadvantaged relative to a party who waits and reacts to the visible tally just before the vote is cast.

### Impact Explanation
The outcome of the vote directly determines the gauge weight sent to `wombatStaking.vote()` and therefore how WOM bribes/emissions are split across pools and staked into each pool's `IBribeRewardPool`. An attacker exploiting the lack of an early-voting incentive can redirect bribe rewards away from the pool that earlier, honest voters intended and expected to win, causing those voters' committed vlMGP to earn less or no bribe yield than anticipated for that voting round — a direct governance-voting-result manipulation with a corresponding misallocation of unclaimed bribe yield.

### Likelihood Explanation
The attack requires no privileged role — any wallet holding vlMGP (i.e., any user who has locked MGP) can call `vote()`/`unvote()`. All state needed to compute the minimal manipulative delta is available through public view functions, and `castVotes()` can be triggered by anyone (including the attacker) right after placing the manipulative vote, making the attack straightforward and repeatable every voting round.

### Recommendation
As in the original report, introduce a mechanism that removes the last-mover advantage: e.g., enforce a fixed voting window with a hard deadline after which no more `vote()`/`unvote()` calls are accepted before `castVotes()` executes, and/or apply a decreasing-weight/time-decay factor that rewards earlier commitments, and/or use a commit-reveal (blind) voting scheme so vote totals are not fully known until the round closes.

### Proof of Concept
1. Bob calls `vote([poolA], [+X])` where `X` is half of poolA's target weight; the call updates the public `pool.totalVoteInVlmgp` value readable via `getVoteForLp(poolA)` — `wombat/WombatBribeManager.sol:182-220`.
2. Eve monitors `getVoteForLp`/`getVlmgpVoteForPools` and computes the minimal vlMGP delta needed to make poolB win instead of poolA.
3. Just before anyone calls `castVotes()`, Eve calls `vote([poolB], [+Y])` (or unvotes from poolA if she previously voted there) with the minimal `Y` needed to flip the relative weighting captured in `totalVlMgpInVote`/`pool.totalVoteInVlmgp` — `wombat/WombatBribeManager.sol:182-220`.
4. Eve (or anyone) immediately calls `castVotes()`, which computes `targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote` from the now-manipulated totals and casts it to `wombatStaking.vote()`, permanently fixing poolB (not poolA) as the winner for that round — `wombat/WombatBribeManager.sol:241-276`.
5. Bob's earlier, publicly-committed vote is overturned with no possibility to react, and the bribe yield he expected for poolA is redirected to poolB.

    /// @notice Vote on pools. Need to compute the delta prior to casting this.
    /// @param _deltas delta amount in vlMGP
    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
