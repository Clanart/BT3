### Title
Payout attribution via OP_RETURN is unauthenticated and can be hijacked using SIGHASH_SINGLE|ANYONECANPAY malleability of the payout input, misattributing reimbursement to an uninvolved operator - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` embeds the caller-supplied `operator_xonly_pk` in a plain OP_RETURN output with no cryptographic binding to who actually funds/broadcasts the payout transaction, and the only signed input (the withdrawal UTXO) is signed with `SinglePlusAnyoneCanPay`, which commits only to input 0 and output 0. Anyone who observes this signature in a mempool transaction can rebuild an equally valid payout transaction with their own fee-paying inputs and an arbitrary `operator_xonly_pk` in the OP_RETURN, and race it into a block ahead of the original broadcaster, causing `update_finalized_payouts` to attribute the reimbursement credit to whichever pubkey the winning broadcaster chose.

### Finding Description
The claimed binding is: `payout_payer_operator_xonly_pk` (recorded in the `withdrawals` table from the mined payout tx's OP_RETURN, [1](#0-0) ) == the operator whose own bitcoin wallet funded/signed the specific mined transaction instance.

- `Operator::withdraw` verifies only that the *user's* Schnorr signature over the withdrawal input is valid for `SinglePlusAnyoneCanPay`: [2](#0-1) . This sighash flag commits to input 0 and output 0 only; it says nothing about who funds the remaining inputs, the anchor output, or the OP_RETURN output/value.
- `create_payout_txhandler` builds the OP_RETURN purely from the caller-supplied `operator_xonly_pk` parameter with no proof this key funded anything: [3](#0-2) .
- `Operator::withdraw` then funds the tx from the *local* operator's own bitcoin wallet via `fund_raw_transaction`/`sign_raw_transaction_with_wallet` and broadcasts it: [4](#0-3) . Because the S+AP signature only covers input 0/output 0, this transaction (and its witness containing the S+AP signature) becomes public in the mempool before confirmation.
- Once any variant of this transaction (same input 0 signature, arbitrary extra inputs, arbitrary OP_RETURN) is mined, `Verifier::update_finalized_payouts` parses whichever OP_RETURN happens to be in the confirmed tx and writes it as the payer, unconditionally: [5](#0-4) , [6](#0-5) .
- `Verifier::is_kickoff_malicious` only checks that the OP_RETURN pubkey equals the kickoff sender's pubkey and that the committed blockhash matches — it never checks that the named operator actually funded the payout's extra inputs/fees: [7](#0-6) .
- `PayoutCheckerTask` on the named operator's node polls for "first unhandled payout" matching its own xonly_pk and automatically proceeds to claim reimbursement via kickoff, with no check that it actually paid for the winning transaction: [8](#0-7) .

Exploit flow: Attacker (unprivileged) watches the mempool for a payout transaction an honest operator A broadcasts for a withdrawal (or triggers a withdrawal themselves via Citrea and waits for any operator to front it). The attacker extracts the S+AP-signed input, constructs a near-identical transaction with the same input/output 0, adds their own funding input(s) signed with their own key to cover fees, replaces the OP_RETURN with any registered operator B's (public) xonly_pk, and broadcasts with a higher fee rate to win the confirmation race. When mined, `update_finalized_payouts` credits B, and B's own automation (`PayoutCheckerTask`) will claim reimbursement for a payout B never funded, while A's broadcast conflicts and never confirms, permanently losing the ability to be reimbursed for that specific withdrawal (the withdrawal UTXO is already consumed).

No existing guard prevents this: `SECP.verify_schnorr` only authenticates the withdrawer, not the fee-payer/operator identity; `is_kickoff_malicious` checks pubkey equality against whatever ended up on-chain, not against who funded the transaction; there is no uniqueness/ownership constraint tying the winning transaction's extra inputs to the OP_RETURN pubkey.

### Impact Explanation
This breaks "an operator reimbursed for a payout it never funded" (operator B, credited purely by an attacker writing B's public key into an OP_RETURN of a transaction the attacker funded) and simultaneously "an honest operator permanently unable to be reimbursed" (operator A, whose legitimately-funded broadcast is invalidated by the winning race and whose withdrawal UTXO is now already spent, with no path to re-claim credit for that deposit). This is repeatable for every withdrawal any operator attempts to front, across all deposits and all operators, since the flaw is structural to how attribution is derived (unauthenticated OP_RETURN + malleable ANYONECANPAY input) rather than tied to a specific deposit or operator instance.

### Likelihood Explanation
The attacker needs only: (1) ability to observe Bitcoin mempool transactions (public), (2) enough BTC to fund a competing input and outbid on fees, and (3) the target operator's public xonly_pk (published/known to all deposit participants and typically public protocol metadata). No collateral, key share, or operator/verifier privilege is required — the attacker's own capabilities (broadcast transactions, pay fees, choose signature/sighash/OP_RETURN bytes) suffice per the stated threat model. This is repeatable for every payout race and does not require majority hashrate, only fee-rate/latency advantage, which is a realistic and cheap capability for any well-funded mempool participant.

### Recommendation
Cryptographically bind the payout's fee-funding/attribution to the claiming operator, e.g. by requiring the operator's own signature (or a MuSig2/committed script path involving the operator's key) over the full transaction including the OP_RETURN and all inputs, or by having the operator pre-commit (e.g., via a presigned kickoff-linked covenant) which specific payout txid it is entitled to claim before broadcasting, rather than deriving attribution purely from a mutable OP_RETURN in the mined transaction.

### Proof of Concept
```
cargo test proof outline (regtest, no mainnet/live Citrea):
1. Set up two operators A and B with valid deposit/kickoff presignatures (existing e2e harness).
2. Trigger a Citrea withdrawal; call Operator A's withdraw() to obtain the signed payout tx (RawSignedTx),
   capturing its witness before broadcast/confirmation.
3. Build a second transaction reusing the same input (outpoint + S+AP witness) and output 0, but with:
   - a different funding input signed with a locally-controlled key (attacker wallet, regtest faucet coins)
   - OP_RETURN containing operator B's xonly_pk instead of A's
4. Broadcast attacker's tx with higher fee rate before A's original tx confirms; mine a block so attacker's
   tx is included instead of A's.
5. Run the verifier's block sync (update_finalized_payouts) and assert:
   - db.get_payout_info_from_move_txid(...) returns operator_xonly_pk == B (not A)
   - Operator A's subsequent handle_finalized_payout/kickoff attempt for this deposit fails or is flagged
     malicious (is_kickoff_malicious returns true) because attribution no longer matches A
   - Operator B's PayoutCheckerTask picks up the "unhandled payout" and proceeds to send a kickoff claiming
     reimbursement, despite B never funding/broadcasting the winning transaction.
```

            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;

            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"

            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");

            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),

            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
