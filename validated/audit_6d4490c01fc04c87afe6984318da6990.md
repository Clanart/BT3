### Title
ReceivedOutput / SignableTransaction bind spendability to `script_pubkey` only; untrusted offset, value, and outpoint are never verified — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the reported bug (permissions keyed on `hostname` instead of full `origin`), Serai's Bitcoin wallet identifies a spendable received output by a single partial field. `Scanner::scan_transaction` matches only `output.script_pubkey` (`networks/bitcoin/src/wallet/mod.rs:205`), and `ReceivedOutput::read` deserializes a raw `(offset, TxOut, OutPoint)` triple with no consistency check that the offset actually derives the script, or that the claimed `value`/`outpoint` corresponds to a real UTXO (`mod.rs:122-133`). Downstream, `SignableTransaction::new` takes `input.offset`, `input.output.value`, and `input.outpoint` verbatim (`send.rs:175-185`), and `multisig()` re-checks only that `p2tr_script_buf(keys.offset(o).group_key()) == prevout.script_pubkey` (`send.rs:276-279`) — the analog of checking hostname but not protocol/port. The UTXO's existence and its true amount are never verified.

### Finding Description
- `ReceivedOutput::read` (`mod.rs:122-133`) is a listed untrusted-byte sink. It accepts any scalar offset plus any `TxOut`/`OutPoint` encoding; there is no binding `offset → script_pubkey` and no notion that the outpoint exists.
- `SignableTransaction::new` (`send.rs:150-256`) builds `TxIn`s from `input.outpoint`, computes `input_sat` from the claimed `input.output.value`, and stores the claimed `TxOut`s as `prevouts`.
- `TransactionSignMachine::sign` (`send.rs:373-390`) signs `taproot_key_spend_signature_hash(i, Prevouts::All(&self.tx.prevouts), Default)`, i.e., the threshold group produces a BIP-341 signature committing to attacker-chosen prevout values/outpoints.
- `multisig()`'s sole integrity check is the `script_pubkey` match; a fabricated value or a nonexistent/misattributed outpoint passes it.

### Impact Explanation
An unprivileged party who can feed crafted bytes to `ReceivedOutput::read` (e.g., via processor `Output::read`, which wraps it at `processor/src/networks/bitcoin.rs:156`) can cause the validator set to (a) treat nonexistent or mis-valued outputs as received multisig funds — "funds reported received that are not spendable" — and (b) expend a FROST signing session producing a signature over a sighash that commits to fabricated prevout data. The resulting transaction is invalid on-chain (BIP-341 commits the claimed prevout amounts, which nodes verify against the real UTXO set), so the signature is wasted and the reported balance inflates accounting that cannot be spent.

### Likelihood Explanation
Reachability requires attacker-controlled bytes reaching `ReceivedOutput::read`/`Output::read` rather than bytes produced by a local `Scanner`. In the processor, outputs are serialized through `Output::write`/`read`, so any untrusted deserialization path (message relay, DB poisoning by a malicious participant's view) reaches it. The `script_pubkey`-only check in `multisig()` then fails to reject value/outpoint forgery. Likelihood is moderate: it does not require compromising the Bitcoin node or a threshold of validators, only the deserialization channel; the impact is bounded to invalid spends/accounting inflation rather than key recovery — Medium.

### Recommendation
- In `ReceivedOutput` construction/`read`, or in `SignableTransaction::new`/`multisig()`, verify the full identity of the input: that `p2tr_script_buf(group_key + G*offset) == output.script_pubkey` (already done in `multisig`, but too late to reject malformed stored outputs) and that `outpoint` resolves on-chain to a `TxOut` equal to `output` (script and value).
- Store/transport only `(offset, outpoint)` and hydrate the `TxOut` from the chain, so value can never be attacker-asserted.
- Do not credit a scanned `ReceivedOutput` as balance until the outpoint is confirmed to exist with the recorded value.

### Proof of Concept
```rust
// Attacker crafts bytes fed to ReceivedOutput::read claiming a 100 BTC output
// paying to Serai's key under offset ZERO, at a fake outpoint.
let mut buf = Vec::new();
buf.extend(Scalar::ZERO.to_bytes());                       // offset = 0 (valid for group key)
TxOut {
    value: Amount::from_sat(10_000_000_000),               // fabricated amount
    script_pubkey: p2tr_script_buf(group_key).unwrap(),    // real Serai script
}.consensus_encode(&mut buf).unwrap();
OutPoint::new(Txid::from_byte_array([0xAA; 32]), 0)        // nonexistent outpoint
    .consensus_encode(&mut buf).unwrap();

let forged = ReceivedOutput::read(&mut &buf[..]).unwrap(); // accepted: no binding checks
let stx = SignableTransaction::new(vec![forged], &payments, change, None, fee).unwrap();
// multisig() passes: script_pubkey matches group_key + 0*G.
// The FROST session signs a sighash committing to the fake 100 BTC prevout;
// the signed tx is invalid on-chain and the output was credited as received.
```
