### Title
Missing offset/output consistency check in `ReceivedOutput::read` allows a misattributed deposit to be reported under an unspendable key - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The ElasTest advisory class is a missing authorization/consistency check: attacker-controlled parameters are accepted and used without verifying they belong to the identity they are claimed for. The Serai analog is `ReceivedOutput::read` / `Output::read`, which deserialize an `offset` scalar and a `TxOut`/`OutPoint` independently and never verify that `offset` actually derives the `script_pubkey` from the intended group key. The only consistency guarantee exists in `Scanner::scan_transaction`, which produces the pair atomically; the byte-deserialization path drops that invariant entirely.

### Finding Description
`Scanner::scan_transaction` constructs a `ReceivedOutput` only when `self.scripts.get(&output.script_pubkey)` returns the registered offset, so an on-chain output is always paired with the offset that yields its script key (`networks/bitcoin/src/wallet/mod.rs:199-214`). `ReceivedOutput::read`, however, accepts `offset`, `output`, and `outpoint` as three independent attacker-controlled fields with no cross-check (`networks/bitcoin/src/wallet/mod.rs:122-134`). Downstream, `Output::key()` reconstructs the supposed spend key as `x_only(script_pubkey) - G * offset` (`processor/src/networks/bitcoin.rs:112-122`), and `Output::read` feeds `ReceivedOutput::read` directly (`processor/src/networks/bitcoin.rs:145-166`). Nothing in this deserialization path requires `x_only(group_key + G*offset) == script_pubkey`, nor that the reconstructed `key()` equals any expected validator-set group key. The reportable balance (`balance() -> output.value()`, line 128-130) is therefore detached from the key the funds are attributed to.

### Impact Explanation
A serialized `ReceivedOutput`/`Output` pairing a real deposit's `script_pubkey`/`TxOut`/`OutPoint` with an arbitrary `offset` passes deserialization, reports a nonzero `balance()`, and yields a `key()` pointing at `group_key + (offset - offset_real)` — a key no validator set controls. The result is funds reported received (and attributed to a signing set/session) that are not spendable under that attribution: any FROST signing attempt uses `tweak_keys`/offset bookkeeping inconsistent with the real spend key, producing signatures invalid for the actual output. This matches the advisory's pattern — a privilege/consistency check omitted on attacker-supplied linkage — mapped onto Serai's untrusted-byte entry point `ReceivedOutput::read`.

### Likelihood Explanation
Reachability requires untrusted bytes to reach `ReceivedOutput::read`/`Output::read` (e.g., output records relayed between processors or loaded from data an attacker influences), which the in-scope rules grant for these `read` APIs. The script_pubkey is constrained to a registered/known P2TR script, but the offset is fully attacker-chosen, so constructing a mispaired record is trivial. Impact is bounded to misattribution/unspendability of the claimed output rather than direct theft, consistent with Medium.

### Recommendation
Either (a) enforce the invariant at `ReceivedOutput::read` by requiring callers to supply the expected base `key` and verifying `p2tr_script_buf(key + G*offset) == Some(output.script_pubkey)`, or (b) make `ReceivedOutput` unconstructible except via `Scanner` (remove public deserialization of arbitrary offsets), and have `Output::key()`/callers assert the reconstructed key equals the expected group key for the session before accounting the balance.

### Proof of Concept
```rust
// Given a real deposit output (script_pubkey, TxOut, OutPoint) scanned honestly:
let honest: ReceivedOutput = scanner.scan_transaction(&tx).swap_remove(0);

// Attacker crafts bytes with the same TxOut/OutPoint but a bogus offset:
let mut buf = vec![];
Secp256k1::write_F(&mut buf, &Scalar::random(&mut OsRng)).unwrap(); // wrong offset
buf.extend(serialize(honest.output()));  // real script_pubkey/value
buf.extend(serialize(honest.outpoint()));

let forged = ReceivedOutput::read(&mut buf.as_slice()).unwrap(); // succeeds, no check

// Downstream: balance() reports the real value, but
// Output::key() = x_only(script) - G*offset != group_key,
// so the output is accounted yet unspendable under the attributed key.
```
