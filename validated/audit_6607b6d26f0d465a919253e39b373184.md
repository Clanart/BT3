### Title
Bank precompile `sendNative` bypasses `IsSendEnabledCoins`/`IsInDenomAllowList`/`BlockedAddr` checks enforced by the native bank `Send` path - (File: precompiles/bank/bank.go)

### Summary
The analog bug class from the Illuminate report ("critical safety check present in one code path but missing in another path that reaches the same state-mutating operation") maps to the Sei bank precompile's `sendNative` function, which moves usei/wei directly via `SendCoinsAndWei` without any of the guard checks (`IsSendEnabledCoins`, `IsInDenomAllowList`, `BlockedAddr`) that the canonical `x/bank` `MsgSend`/`MsgMultiSend` message-server handlers enforce for every native coin transfer.

### Finding Description
The Cosmos bank module's `Send` and `MultiSend` message handlers are the enforcement point for chain-level transfer restrictions: send-enabled flags, tokenfactory denom allow-lists, and blocked (module) addresses. [1](#0-0) 

These checks (`IsSendEnabledCoins`, `IsInDenomAllowList`, `BlockedAddr`) are the intended "pause"/restriction mechanism for coin movement — analogous to Illuminate's market-pause check that was supposed to gate `mint`.

The EVM bank precompile's `send` method for ERC20-native-pointer-backed denoms correctly routes through `p.bankMsgServer.Send`, inheriting all of these checks: [2](#0-1) 

However, `sendNative`, which is reachable directly by any EVM caller sending native `usei`/`wei` value to the bank precompile at `0x0000000000000000000000000000000000001001`, calls `p.bankKeeper.SendCoinsAndWei` directly — bypassing the message-server entirely and therefore skipping `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr`: [3](#0-2) 

Because `usei` is the base denom and not typically wrapped by a send-enabled=false flag or an allow-list, this specific instance is low-impact for `usei` itself. But the underlying pattern is exactly the reported bug class: a state-mutating operation (coin transfer) has two entry points, and only one of them re-implements the safety checks that the other enforces. If any base-denom-level restriction (send-enabled=false, governance-imposed freeze, or blocked recipient address) is ever relied upon as a safety/pause mechanism, `sendNative` provides an unchecked bypass.

### Impact Explanation
If `usei`'s `SendEnabled` param is set to `false` (a legitimate mechanism to halt native-denom transfers, e.g., during an incident) or if a recipient address is added to `BlockedAddr` (e.g., module accounts, or addresses blacklisted via governance), a caller can still move `usei`/`wei` value into/out of those addresses through the bank precompile's `sendNative` path, because it never calls `IsSendEnabledCoins` or `BlockedAddr` before invoking `SendCoinsAndWei`. This defeats the intended halt/blocklist protection for native-token movement in the EVM path while it remains enforced in the Cosmos-native `MsgSend` path, i.e., the same "pause bypass" class as the H-09 finding.

### Likelihood Explanation
Reachable by any unprivileged EVM transaction sender calling the bank precompile with `value` set (`sendNative`); no special privilege is required. Likelihood of the restriction actually being relied upon by chain operators (disabling `SendEnabled` for `usei`, or blocking specific addresses) determines whether this manifests as an exploitable freeze/fund-movement bypass, but the missing check itself is unconditional and always present in the code path.

### Recommendation
In `precompiles/bank/bank.go`'s `sendNative`, before calling `p.bankKeeper.SendCoinsAndWei`, add the same guard checks used by `msgServer.Send`/`MultiSend`: verify `IsSendEnabledCoins` for the base denom, verify the receiver is not `BlockedAddr`, and apply `IsInDenomAllowList` consistently, so that EVM-originated native transfers are subject to the same restrictions as Cosmos-native `MsgSend` transfers.

### Proof of Concept
1. Governance/operator sets `SendEnabled=false` for `usei` (or adds a target address to `BlockedAddr`) intending to halt native transfers chain-wide (e.g., during an incident).
2. An attacker calls the bank precompile (`0x...1001`) method `sendNative(receiver)` with EVM `value` set to move `usei`/`wei`.
3. `sendNative` calls `p.bankKeeper.SendCoinsAndWei` directly (`precompiles/bank/bank.go:285`) without ever invoking `IsSendEnabledCoins` or `BlockedAddr`, so the transfer succeeds despite the intended restriction, while the equivalent native `MsgSend` would have been rejected at `sei-cosmos/x/bank/keeper/msg_server.go:29-49`.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

func (p PrecompileExecutor) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
	}
	accExists := p.accountKeeper.HasAccount(ctx, receiverSeiAddr)
	if !accExists {
		defer metrics.RecordBankNewAccount(ctx.Context())
		p.accountKeeper.SetAccount(ctx, p.accountKeeper.NewAccountWithAddress(ctx, receiverSeiAddr))
	}

	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		remainingGas := pcommon.GetRemainingGas(newCtx, p.evmKeeper)
		if hooks.OnEnter != nil {
			hooks.OnEnter(evm.GetDepth()+1, byte(vm.CALL), caller, p.evmKeeper.GetEVMAddressOrDefault(newCtx, receiverSeiAddr), []byte{}, remainingGas, value)
		}
		defer func() {
			if hooks.OnExit != nil {
				hooks.OnExit(evm.GetDepth()+1, []byte{}, 0, nil, false)
			}
		}()
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
