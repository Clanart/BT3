### Title
Attacker-supplied `ReceivedOutput` bytes are trusted without binding the claimed UTXO to the chain, allowing fake/unspendable outputs to be reported as received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an `offset`, a `TxOut`, and an `OutPoint` from untrusted bytes with no validation that the output exists on-chain, that the `script_pubkey` actually corresponds to `group_key + offset * G`, or that the claimed `value` is real. Downstream, `SignableTransaction::new` trusts `output.value` for fee/change accounting, and `multisig` only checks the self-consistent relation between the attacker-chosen `offset` and attacker-chosen `script_pubkey` — not any on-chain fact. This is the analog of the Splits `depositToWarehouse`/`withdraw` issue: a permissionlessly reachable input path lets an untrusted party inject state that the wallet layer treats as authoritative, causing the multisig to schedule and sign for funds that were never received.

### Finding Description
`ReceivedOutput` bundles three attacker-controlled fields when read from the wire: `offset` (`Secp256k1::read_F`), `output` (`TxOut::consensus_decode`, including `value` and `script_pubkey`), and `outpoint` [1](#0-0) .

Nothing in `read` binds these fields to each other or to the blockchain:

- `offset` can be any scalar.
- `output.script_pubkey` can be any script. An attacker can set it to `p2tr_script_buf(group_key + offset * G)` for their chosen `offset`, which is exactly the self-referential check `SignableTransaction::multisig` performs before producing a signing machine [2](#0-1) . The check passes for a completely fabricated output.
- `output.value` feeds `input_sat` in `SignableTransaction::new`, driving the `NotEnoughFunds` check and the change computation [3](#0-2) , and feeds `Prevouts::All` which is committed to in the taproot sighash [4](#0-3) .
- `outpoint` is never verified against a real UTXO; it is placed verbatim into `previous_output` [5](#0-4) .

The honest path (`Scanner::scan_transaction`) does produce the binding — the `script_pubkey` is looked up in `self.scripts` and the `outpoint`/`output` come from a real transaction [6](#0-5) . But `ReceivedOutput::read` accepts bytes from a reader without reproducing that binding, and nothing downstream re-verifies it. A serialized `ReceivedOutput` therefore functions like the permissionless `depositToWarehouse`/`withdraw` pair: anyone who can supply these bytes can make the wallet layer believe it holds a spendable output it does not, and can steer fee/change math with a fabricated `value`.

### Impact Explanation
Two concrete consequences:

1. **Funds reported received that are not spendable / phantom balance.** A crafted `ReceivedOutput` (fake `outpoint`, real-looking `script_pubkey` matching the supplied `offset`) passes `multisig`'s consistency check. The transaction built over it will sign cleanly and then fail on broadcast (the sighash commits to the fabricated prevout, and the outpoint doesn't exist), but until that point the output is scheduled, counted as input value, and may crowd out real outputs in coin selection or inflate reported holdings.
2. **Fee/change manipulation.** Because `needed_fee`, `input_sat`, and the change output are computed from `output.value` before any on-chain check [7](#0-6) , a forged high `value` shifts real funds into fees or mis-sizes the change output. Combined with a mixture of real and forged inputs, the transaction is doomed to fail after consuming signing rounds — and any automatic retry (the codebase explicitly supports rebroadcast/re-issue of sign orders) repeats the cycle, mirroring the report's repeated withdraw/redeposit drain loop in resource terms.

### Likelihood Explanation
Likelihood depends on whether untrusted peers can feed serialized `ReceivedOutput`s into a wallet/`SignableTransaction` context — the rules for this review enumerate `ReceivedOutput::read` as an untrusted-byte entry point, and the `#[cfg(feature = "std")]` read/write pair exists precisely to move these structures across a process or network boundary [8](#0-7) . No secret material, collusion, or privileged position is required: the attacker only needs to supply bytes and to know the group key (public) to compute a matching `offset`/`script_pubkey` pair. Severity is bounded by the sighash/commitment layer — the forged input cannot produce a *valid* spend of a nonexistent output — so the realistic ceiling is fabricated "received" funds and wasted/denied signing capacity rather than direct theft, placing this at Medium.

### Recommendation
At deserialization or first use, re-derive the expected script: store the group key alongside the serialized form and check `output.script_pubkey == p2tr_script_buf(group_key + offset * G)` inside `ReceivedOutput::read` (or a `verify` method), rather than letting each consumer decide. Additionally, the consumer that schedules a `SignableTransaction` should confirm the `outpoint` resolves to a UTXO whose `TxOut` matches the claimed `output` (value and script) before entering coin selection — the same fix class as the report's recommendation to permission `depositToWarehouse`: the implicit trust boundary between "produced by `scan_transaction`" and "produced by `read`" should be made explicit, either by separating the types or by validating on read.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(&self.offset.to_bytes())?;
    w.write_all(&serialize(&self.output))?;
    w.write_all(&serialize(&self.outpoint))
  }

  /// Serialize a ReceivedOutput to a `Vec<u8>`.
  pub fn serialize(&self) -> Vec<u8> {
    let mut res = Vec::new();
    self.write(&mut res).unwrap();
    res
  }
}

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
