### Title
Unauthenticated `OP_RETURN` operator-attribution field in payout transactions permits third-party attribution hijacking, permanently orphaning honest operators' reimbursements - (File: `core/src/builder/transaction/operator_reimburse.rs`, `core/src/verifier.rs`)

### Summary
The `payout_tx`'s output 2 (`OP_RETURN` operator attribution) is not covered by the withdrawer's Schnorr signature because the withdrawal input is signed with `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, which only commits to input 0 and output 0. Any third party who observes the unconfirmed `payout_tx` can rebroadcast a variant that preserves the legitimate withdrawer payout (output 0) but swaps the `OP_RETURN` operator xonly pubkey to an arbitrary value, including one not registered as any real operator, permanently orphaning the honest operator's reimbursement claim.

### Finding Description
The claimed binding is:
`payout_payer_operator_xonly_pk` (recorded in DB by `Verifier::update_finalized_payouts`) == the operator whose funds actually paid `output[0]` of the confirmed `payout_tx`.

Tracing the code:
- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds output 0 (user payout), output 1 (anchor), output 2 (`OP_RETURN` with `move_txid || operator_xonly_pk`), and signs only input 0 via `set_p2tr_key_spend_witness(&user_sig, 0)`.
- In `Operator::withdraw` (`core/src/operator.rs:560-637`), the sighash is computed as `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)`, i.e., the sighash flag comes from the user-supplied signature, which per the doc comment is expected to be `SinglePlusAnyoneCanPay`. Under `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, only input 0 and output 0 are committed; outputs 1 (anchor) and 2 (`OP_RETURN`) are **not** covered by the signature.
- Since the tx is funded via `fund_raw_transaction`/RBF (`core/src/operator.rs:652-674`), any observer can construct a competing, still-validly-signed transaction that spends the same withdrawal outpoint with the same signature/witness on input 0, keeps output 0 identical (to keep the signature valid), but rewrites output 2's `OP_RETURN` pubkey to an arbitrary value `C`, and rebroadcasts it with a higher fee to replace operator A's transaction in mempool.
- On confirmation, `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) blindly extracts the attribution from the confirmed tx via `parse_op_return_data` and stores `operator_xonly_pk = C` with no validation that `C` corresponds to a real, registered operator for this deposit (`core/src/verifier.rs:2319-2342`).
- Reimbursement is only ever triggered per-operator via `PayoutCheckerTask::run_once`, which polls `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` (`core/src/task/payout_checker.rs:41-47`, query in `core/src/database/verifier.rs:282-296` filtered by `payout_payer_operator_xonly_pk = $1`). Since `C` matches no running operator's key, no operator will ever discover or claim this withdrawal. Operator A, who actually funded output 0, is never queried because the DB row is keyed to `C`, not `A`.
- The comment in `update_finalized_payouts` ("This can happen ... if an operator constructs the payout tx wrong") shows the code only anticipated operator self-error, not third-party attribution hijacking enabled by the permissive sighash type.

No existing guard (`is_deposit_valid`, `SECP.verify_schnorr`, `is_kickoff_malicious`, DB uniqueness constraints) checks that the `OP_RETURN` pubkey corresponds to a real operator or to the party that funded output 0, because the signature deliberately does not cover output 2.

### Impact Explanation
The withdrawal becomes permanently unreimbursable: the honest operator (A) who fronted the withdrawer's funds can never be paid back because no automated or manual polling path attributes the withdrawal to A, and the attacker-chosen key `C` corresponds to no real operator/kickoff, so nobody can ever claim it either. This matches the Critical category "an honest operator permanently unable to be reimbursed." The attack is repeatable for every payout transaction while it is unconfirmed and uses the standard `SinglePlusAnyoneCanPay` sighash (the intended/only supported sighash for this flow), so it is not limited to a single deposit or operator.

### Likelihood Explanation
Preconditions are minimal and match normal operation: any payout tx built by `create_payout_txhandler` uses `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`, which is the documented, expected signature type for this flow (needed so the operator can add fee inputs via `fund_raw_transaction`). An attacker only needs mempool visibility of the unconfirmed `payout_tx`, the ability to construct and broadcast a competing transaction (with a higher fee, to win a replace-by-fee race or otherwise get preferentially mined) spending the same outpoint, and no privileged role. This is feasible for any unprivileged actor with basic node/wallet access and some BTC for fees.

### Recommendation
Cover the `OP_RETURN` operator attribution output with the committed signature data, e.g., have the withdrawer/user sign with `SIGHASH_ALL` (or `SIGHASH_ALL|SIGHASH_ANYONECANPAY` if additional operator-funded inputs are still required) so all outputs, including the attribution `OP_RETURN`, are covered; alternatively, bind the attribution cryptographically (e.g., require the OP_RETURN pubkey to be committed inside the SIGHASH_SINGLE-covered output or add an operator signature over the whole transaction) and have `update_finalized_payouts` validate that the extracted `operator_xonly_pk` corresponds to a currently registered operator before persisting it.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
