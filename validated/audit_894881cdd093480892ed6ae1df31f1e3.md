### Title
`EncryptionKeyProof` derives `Debug`, leaking the ECDH shared decryption key into logs/diagnostics - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to GHSA-qx7g-fx8q-545g (a secret access token written to a WARN log in Para's `FacebookAuthFilter`), `EncryptionKeyProof` in PedPoP derives `fmt::Debug` over a field holding the ECDH shared key used to decrypt per-participant DKG messages. Any `{:?}`/`format!("{proof:?}")`/`log::debug!`/`unwrap_err`-style formatting of this proof emits the shared key in plaintext. [1](#0-0) 

### Finding Description
`EncryptionKeyProof<C>` is defined as:

```rust
#[derive(Clone, PartialEq, Eq, Debug, Zeroize)]
pub struct EncryptionKeyProof<C: Ciphersuite> {
  key: Zeroizing<C::G>,
  dleq: DLEqProof<C::G>,
}
``` [1](#0-0) 

`key` is the ECDH shared point produced by `ecdh::<C>(&self.enc_key, msg.key)` inside `Encryption::decrypt` — i.e., `enc_key * msg.key`, the exact value fed into `cipher()` to derive the ChaCha20 keystream that decrypts the message (a secret share). [2](#0-1) [3](#0-2) 

Because `Zeroizing<T>` forwards `Debug` transparently to the inner type and `C::G` implements `fmt::Debug` (it is required by `group::GroupEncoding`/`Group`), the derived `Debug` prints the full elliptic-curve point encoding of the shared key. The enclosing type is `pub`, so any consumer formatting it (structured logging, error paths in the blame protocol, `assert_eq!` failure output in non-test code, `expect`/`unwrap` diagnostics) writes the shared decryption key to wherever logs go.

This stands in contrast to the neighboring `Encryption` type, which has a hand-written `Debug` impl that deliberately omits `enc_key` via `finish_non_exhaustive()`, showing the codebase's own convention is to exclude secret material from `Debug`. [4](#0-3) 

### Impact Explanation
Whoever obtains the printed `key` (log files, crash reports, error aggregation pipelines — typically accessible to operators and third parties, exactly as in the Para CVE) can recompute `cipher(context, key)` with the public `context` and decrypt the corresponding `EncryptedMessage` offline, recovering the encrypted secret share of a DKG participant without running the blame-verification path. `decrypt_with_proof` shows the shared key alone is sufficient for decryption once `context` is known. [5](#0-4)  This converts a Medium-severity information-exposure primitive into threshold-key-share compromise, matching the CWE-532 class of the report.

### Likelihood Explanation
`EncryptionKeyProof` is a `pub` type returned by `decrypt` and consumed in `decrypt_with_proof`; it is the kind of value naturally logged or embedded in error messages during the DKG blame flow. The accidental exposure requires only that downstream code format it — a common pattern — and, per the prompt's threat model, only needs to be reachable via ordinary protocol operation by an unprivileged participant triggering the blame path. No malicious validator, collusion, or key leak is assumed; the leak is a consequence of the type's derived trait.

### Recommendation
Replace `#[derive(Debug)]` on `EncryptionKeyProof` with a manual `fmt::Debug` impl mirroring `Encryption`'s: print only the public `dleq` field (or nothing) and end with `finish_non_exhaustive()` so `key` is never emitted. Audit other secret-bearing types for the same pattern (e.g., verify `ThresholdKeys`/`ThresholdCore` in `crypto/dkg/src/lib.rs` and nonce/`Nonce` types in `crypto/frost/src/nonce.rs` do not derive `Debug` over secret fields).

### Proof of Concept
```rust
// In code holding an EncryptionKeyProof (e.g., blame handling):
let proof: EncryptionKeyProof<C> = ...;           // returned by Encryption::decrypt
let leaked = format!("{proof:?}");                // derived Debug prints `key: <point>`
// leaked now contains the serialized ECDH shared point `enc_key * msg.key`.
// Anyone with `leaked` and the public `context` reconstructs the ChaCha20 cipher
// via `cipher::<C>(context, &shared_point)` and decrypts the EncryptedMessage
// to recover the secret share, bypassing DLEq verification entirely.
```
Root cause is the derived `Debug` at `crypto/dkg/pedpop/src/encryption.rs:260-263` combined with `Zeroizing`'s transparent `Debug` delegation — the same "secret placed into a diagnostic/log channel" shape as Para logging `PROFILE_URL + accessToken` at WARN level.
