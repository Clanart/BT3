### Title
Missing contract-existence check in `EvmHost.dispatchIncoming(GetResponse)`/`dispatchTimeOut(GetRequestTimeout)` causes false success and fee payout without callback execution - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, address)` explicitly checks that the destination has code (`extcodesize`) before invoking `onAccept`, and returns early — leaving no receipt — if the target has no code [1](#0-0) . The GET-request counterparts, `dispatchIncoming(GetResponse, address)` and `dispatchTimeOut(GetRequestTimeout, FeeMetadata, bytes32)`, omit this check entirely and instead rely solely on the boolean returned by a raw `.call()` to `response.request.from` / `timeout.request.from` [2](#0-1) [3](#0-2) . Per EVM semantics (the exact warning cited in the external report), a `.call()` to an address with no code always returns `success = true`, so if the originating app contract has been destroyed (e.g., via `selfdestruct`) between dispatching a GET request and the response/timeout arriving, the host will treat the (never-executed) callback as successful.

### Finding Description
`dispatch(DispatchGet)` records the calling contract as `request.from = abi.encodePacked(_msgSender())` at dispatch time [4](#0-3) . That address is trusted to still be a live contract when the response/timeout eventually arrives, potentially much later after the challenge period and relay delay.

When the response arrives, `dispatchIncoming(GetResponse, address)`:
1. Immediately persists `_responseReceipts[commitment]` (replay protection) [5](#0-4) .
2. Makes a raw `.call()` to `_bytesToAddress(response.request.from)` without any `extcodesize` check [6](#0-5) .
3. If `from` is now a destroyed/non-existent address, the call trivially returns `success = true`, so the `if (!success)` retry/rollback branch is skipped [7](#0-6) .
4. The code then unconditionally pays out the relayer fee from `_requestCommitments[commitment].fee` and emits `GetRequestHandled` as if the callback executed correctly [8](#0-7) .

The same pattern repeats in `dispatchTimeOut(GetRequestTimeout, ...)`: the commitment is deleted up front, the call to `timeout.request.from` has no existence check, and on the trivially-true `success` the relayer fee is refunded and `GetRequestTimeoutHandled` is emitted [3](#0-2) .

This is the exact bug class from the external report (missing contract-existence check before a call whose result gates subsequent state changes), but it lands in the host's fee-settlement / receipt-finalization logic rather than a static delegatecall proxy. The existing `handlePostRequests`/`dispatchIncoming(PostRequest)` path shows the protocol is aware of this exact hazard and guards against it with `extcodesize` [9](#0-8) ; the GET-response and GET-timeout paths simply lack the same guard.

### Impact Explanation
Because a false-success `.call()` is treated identically to a real successful `onGetResponse`/`onGetTimeout` execution, the host permanently finalizes the request (receipt stored / commitment deleted) and pays the relayer fee out of protocol-held fee-token balance, even though the destination app's callback logic never ran. This is a fund-movement correctness bug in the reward/fee-payout path directly gated by an unreliable "success" signal — the exact invariant the bounty scope calls out ("bridged assets... relayer rewards... must move exactly once and only to the rightful beneficiary"). It also causes false finalization of GET request/response state (the response is marked delivered on-chain even though the module never received it), which can silently desynchronize downstream application accounting that depends on `onGetResponse`/`onGetTimeout` actually firing.

### Likelihood Explanation
Triggering this requires only that the dispatching application contract be destroyed (self-destructed or otherwise made codeless) after it fetches a GET request but before the response/timeout is delivered — a condition entirely under the control of the app owner/deployer, not a privileged relayer, prover, or admin. No malicious peer, relayer collusion, or governance action is needed; it only needs an unprivileged application (or a proxy pattern with `selfdestruct`) that dispatches a `Get` and is later destroyed, or is upgraded/replaced such that the recorded `from` address transiently has no code. Given SELFDESTRUCT usage is uncommon but not prohibited (and the protocol already documents concern over exactly this scenario per the referenced TOB-NESTED-1 finding cited in the external report), this is a realistic, low-complexity path.

### Recommendation
Add the same `extcodesize` existence check used in `dispatchIncoming(PostRequest)` to `dispatchIncoming(GetResponse)` and `dispatchTimeOut(GetRequestTimeout)` before making the low-level call, and early-return (or explicitly treat as an undeliverable request) if the target has no code, instead of relying purely on the boolean returned by `.call()`.

### Proof of Concept
1. Contract `A` calls `EvmHost.dispatch(DispatchGet{...})`; `request.from = abi.encodePacked(address(A))` is recorded and `A`'s relayer fee is escrowed in `_requestCommitments`.
2. Before the response/timeout is relayed back, `A` executes `selfdestruct` (or is otherwise emptied of code), so `address(A).code.length == 0`.
3. A relayer submits the GET response (or the request times out and a timeout proof is submitted) via `HandlerV2`, which calls `EvmHost.dispatchIncoming(GetResponse, relayer)` (or `dispatchTimeOut`).
4. Inside `EvmHost`, `_bytesToAddress(response.request.from).call(...)` targets the now-codeless `A` and returns `success = true` per EVM semantics, even though `onGetResponse` never executed.
5. The `if (!success)` branch is skipped; `_responseReceipts[commitment]` remains permanently set, the relayer fee is transferred out of the fee-token balance, and `GetRequestHandled` is emitted — finalizing a request whose destination callback never ran [10](#0-9) .

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
