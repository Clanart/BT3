### Title
Forfeiture-percent bypass via `cancelUnlock` front-running `getReward`/`queueMGP` lets any cooldown-locker claim rewards with zero forfeiture - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`vlMGPBaseRewarder._calExpireForfeit` computes the forfeiture on a reward amount by reading `vlMGP.getRewardablePercentWAD(_account)` live, at claim time, instead of using a value snapshotted when the reward accrued. Because `VLMGP.cancelUnlock` can instantly and costlessly reset a user's cooldown-in-progress slot back to "fully locked" (percent = 100%), a user can accrue rewards while partially in cooldown and then erase the entire forfeiture tax right before claiming, capturing yield that the tokenomics designed to redistribute to non-cooldown lockers.

### Finding Description
`vlMGPBaseRewarder.balanceOf` returns the user's full staked amount from `MasterMagpie.stakingInfo`, which is unaffected by whether part of that balance is "in cooldown" — cooldown only changes internal `VLMGP` bookkeeping, not the amount staked in `MasterMagpie` (that only changes on final `unlock()`/`forceUnLock()`via `withdrawVlMGPFor`). Consequently `_earned`/`rewardPerToken` accrual is computed on the user's **full** balance regardless of cooldown state: [1](#0-0) .

The only place the cooldown status matters is at claim time, in `_calExpireForfeit`, which reads `vlMGP.getRewardablePercentWAD(_account)` live: [2](#0-1) . `getRewardablePercentWAD` computes the percentage of the user's vlMGP that is fully locked vs. in cooldown, based on the **current** `userUnlockings` array state: [3](#0-2) .

`VLMGP.cancelUnlock` lets the user zero out `amountInCoolDown` for a slot at any time while still in cooldown, with no penalty, no delay, and no forced reward settlement: [4](#0-3) . This immediately restores `getUserTotalLocked` to the full staked balance (since `getUserTotalLocked = stakingInfo - getUserAmountInCoolDown`), making `getRewardablePercentWAD` return `1e18` instantly.

Exploit flow:
1. Attacker locks MGP into `VLMGP`.
2. Attacker calls `startUnlock(X)` on part of their position (percent now < 100%).
3. Rewards accrue in full via `queueNewRewards` (accrual is balance-based, not percent-based) while the attacker sits in cooldown.
4. Immediately before claiming, attacker calls `cancelUnlock(slotIndex)` — a `whenNotPaused`-only, permissionless, no-nonReentrant function.
5. Attacker (via `MasterMagpie`) calls `getReward`/`getRewards`, which computes forfeiture through `_sendReward` → `_calExpireForfeit`, now reading `percent = 1e18`, so `forfeitAmount = 0`: [5](#0-4) .
6. Attacker can immediately `startUnlock(X)` again to resume their original position, having paid nothing.

The same applies to `queueMGP`, which also calls `_calExpireForfeit` live at the moment MGP is queued to a user: [6](#0-5) .

Existing checks do not stop this: `cancelUnlock` has no cooldown-of-its-own, no fee, and is not rate-limited; `_calExpireForfeit` has no snapshot/timelock protection; and there is no requirement that the percent used for forfeiture reflect the percent that was active while the reward accrued.

### Impact Explanation
This breaks the intended forfeiture/redistribution mechanism: users who never actually complete an unlock (i.e., who game `startUnlock`/`cancelUnlock` cycles) can accrue the full reward-weighted share while nominally "in cooldown" and then always claim it forfeiture-free, at the expense of the pool of forfeited rewards that `_queueNewRewardsWithoutTransfer` would otherwise route to genuinely-non-cooldown lockers. This is a direct redirection/theft of yield that other, honest lockers are economically entitled to under the protocol's designed tokenomics — matching "theft of unclaimed yield."

### Likelihood Explanation
Fully feasible with no special privileges: any vlMGP holder can `startUnlock`, wait for reward accrual, `cancelUnlock`, and claim, repeating indefinitely at only the cost of gas. No capital beyond normal locking is required, and the exploit is trivially repeatable every reward cycle.

### Recommendation
Do not use a live, mutable `getRewardablePercentWAD` at claim time. Instead, snapshot the rewardable percent (or accrue rewards separately for locked vs. cooldown balances) at the time rewards are earned/accrued (i.e., inside `_updateFor`/`updateRewards`, or by tracking per-user accrued-while-in-cooldown amounts), so that `cancelUnlock` cannot retroactively change the forfeiture applied to already-accrued rewards. Alternatively, apply a time-weighted average of the percent over the accrual period rather than the instantaneous value.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder` with a reward token, set `coolDownInSecs` to a nonzero value.
2. Attacker locks `N` MGP; `MasterMagpie`/`VLMGP` records full stake.
3. Attacker calls `startUnlock(N/2)` to put half in cooldown.
4. `rewardManager` calls `queueNewRewards(reward, token)` to accrue rewards across the full staked balance.
5. Assert `vlMGPBaseRewarder.calExpireForfeit(attacker, token) > 0` (forfeiture currently non-zero because attacker is 50% in cooldown).
6. In the same block, call `VLMGP.cancelUnlock(0)`.
7. Assert `vlMGPBaseRewarder.calExpireForfeit(attacker, token) == 0` immediately after, despite `earned()` being unchanged.
8. Call `MasterMagpie` claim path → `getReward`, assert attacker receives the full `earned` amount with `forfeitAmount == 0` in the `RewardPaid`/`MGPHarvested` events.
9. Compare against a baseline where `cancelUnlock` is not called before claiming — assert the baseline forfeits `>0` tokens routed via `_queueNewRewardsWithoutTransfer`, while the exploit path forfeits `0`.

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```

```text
    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
```
