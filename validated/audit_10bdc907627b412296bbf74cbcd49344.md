### Title
Spoofed `WWW-Authenticate: realm="GitHub"` header lets an attacker-controlled remote trigger a GitHub Enterprise sign-in flow for an arbitrary host - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
`getEndpointKind` in [1](#0-0)  classifies a remote host as `'enterprise'` if the HTTP `WWW-Authenticate` header Git forwards to the credential helper merely contains `realm="GitHub"`, bypassing the real network-based `isGitHubHost(endpoint)` probe that would normally be used to determine this. This is analogous to the reported ERC721 flaw: the contract trusted a self-reported property (an approval) instead of verifying the true, authoritative state (actual ownership). Here, Desktop trusts a self-reported header value from an untrusted remote instead of verifying the host is truly GitHub/GHE.

### Finding Description
When Git performs an HTTP(S) request to a remote and receives a `401` with a `WWW-Authenticate` header, it forwards that header to Desktop's credential helper as `wwwauth[...]` entries [2](#0-1) . `getEndpointKind` treats a header containing `realm="GitHub"` as sufficient proof that the host is a genuine GitHub Enterprise instance, entirely skipping the legitimate `isGitHubHost(endpoint)` network check that is only reached as a last resort [3](#0-2) .

In `getCredential`, when the classified `endpointKind !== 'generic'` and no existing account matches that endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [4](#0-3) . That function, for any non-`github.com` hostname, calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` using the attacker-supplied `endpoint`/`origin` directly, then shows the native `SignIn` popup [5](#0-4) . Nothing here re-validates that this arbitrary attacker-controlled host is a legitimate GitHub Enterprise Server before initiating the sign-in / OAuth flow against it.

The broken invariant: "a host is treated as trusted GitHub Enterprise API endpoint" should require actual verification (the same real check `isGitHubHost` performs), but the header shortcut allows an attacker to self-declare this property.

### Impact Explanation
A malicious or compromised git server can respond to an authenticated HTTP git operation (clone/fetch/push) with a `401` and `WWW-Authenticate: Basic realm="GitHub"`. This causes Desktop to present its native "Sign in to GitHub Enterprise" popup pointed at the attacker's origin. If the user completes this flow believing it is a legitimate GHE sign-in (since the UI is Desktop's own trusted native dialog), the resulting authentication material/OAuth flow is directed at the attacker-controlled origin — leading to credential/token exfiltration or an account being unauthorizedly bound to phished credentials, both explicitly valid impacts.

### Likelihood Explanation
Exploitation only requires an attacker to control the HTTP responses of a git remote or an intercepting proxy that a victim clones/fetches/pushes to (e.g., a malicious "contribute" or third-party fork URL, or a compromised self-hosted git server) — no local access, no prior credential leak. The header value is fully attacker-controlled and requires no unnatural user steps beyond a normal git operation that already prompts for credentials, which victims coming from unfamiliar hosts already generally expect.

### Recommendation
Do not treat the `WWW-Authenticate` `realm="GitHub"` header as authoritative proof of a GitHub Enterprise host. Always confirm via the genuine `isGitHubHost` (or equivalent authenticated API probe) check before classifying an endpoint as `'enterprise'`/`'github.com'` and before invoking `promptForGitHubSignIn`, mirroring the BAB-2 fix pattern of validating the real authoritative state (true ownership/true host identity) rather than a self-asserted claim.

### Proof of Concept
1. Set up a malicious HTTPS git server at `https://evil.example/repo.git`.
2. Configure it to respond to Git's authentication probe with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone/fetch this URL. Git forwards the header as `wwwauth[]=Basic realm="GitHub"` to the credential helper.
4. `getEndpointKind` returns `'enterprise'` for `evil.example` without any real verification [6](#0-5) .
5. `getCredential` finds no matching stored account for `evil.example` and calls `ui.promptForGitHubSignIn('https://evil.example')` [7](#0-6) .
6. Desktop shows its native Enterprise sign-in popup bound to `evil.example`'s origin [8](#0-7) , and any credentials/tokens the user submits are sent to the attacker's server.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
