### Title
Untrusted `ThresholdKeys` deserialization never binds the secret share to the verification shares, allowing attacker-substituted group keys - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` accepts a fully attacker-controlled `(t, n, i, interpolation, secret_share, verification_shares)` tuple, and `ThresholdKeys::new` derives the `group_key` solely from the attacker-supplied `verification_shares` of participants `1..=t`, without ever checking that the deserialized `secret_share` actually corresponds to `verification_shares[i]` (i.e. `C::generator() * secret_share == verification_shares[&i]`). A tampered key file — the Serai analog of BitKeep's hijacked APK download — silently swaps the wallet's group key for an attacker-chosen key.

### Finding Description
`ThresholdKeys::read` parses the curve ID, threshold params, interpolation variant, the secret share, and `n` verification shares from raw bytes, then passes them straight into `ThresholdKeys::new` ( [1](#0-0) ). `ThresholdKeys::new` only validates the *shape* of the inputs: the count of `verification_shares` equals `n`, participant indexes are `<= n`, and `Constant` interpolation requires `t == n`. It then computes `group_key` as the interpolation over `verification_shares[1..=t]` ( [2](#0-1) ) — using only the first `t` shares — and stores everything without a single consistency check between `secret_share` and `verification_shares`.

Two concrete mismatches are accepted silently:

1. `secret_share` does not match `verification_shares[i]` — the loaded keys are corrupt and every signature the node produces is invalid, yet `read`/`new` succeed. More critically, the other direction: an attacker who substitutes the serialized blob controls all `verification_shares`, and hence fully controls `group_key()`. If they choose shares interpolating to a key whose discrete log they know, `group_key()` returns an attacker-owned key while the victim's software believes it is operating its own threshold key.
2. With `Interpolation::Constant`, the `t` binding factors are attacker-chosen scalars read via `C::read_F`, giving even finer control over which linear combination defines the group key ( [3](#0-2) ).

Nothing downstream re-derives or challenges the group key against the local share: `Scanner::new(key)` / `register_offset` happily scan for deposits to whatever `group_key()` reports ( [4](#0-3) ), and signing proceeds to produce shares that won't verify, or worse, for a key the attacker can sign for alone.

### Impact Explanation
This mirrors the BitKeep incident class: attacker-substituted wallet material (there, a hijacked APK; here, a hijacked/attacker-supplied serialized `ThresholdKeys` blob, e.g. a backup/restore file or keys file shipped with a compromised distribution) causes funds to be directed to keys the attacker controls. Because the local `secret_share` is never bound to `verification_shares[i]`, the substitution is undetectable at load time: deposits scan against the attacker's `group_key`, and any funds sent there are immediately spendable by the attacker while being unspendable by the victim — "funds reported received that are not spendable" plus outright theft of subsequently received funds. In the weaker variant (only some fields tampered), the node silently signs garbage, causing loss of funds/DoS of the validator's signing ability.

### Likelihood Explanation
Exploitation requires an attacker to supply the serialized key blob — the same precondition as the external incident (compromised distribution channel/backup). It requires no valid participant credentials, no collusion, and no on-chain interaction; the malformed blob parses cleanly through `read_F`/`read_G` canonicality checks since all values are canonical. The missing check is unconditional in the code path, so any deployment that restores keys from untrusted or tamperable storage is affected.

### Recommendation
In `ThresholdKeys::new` (or at minimum in `ThresholdKeys::read`), verify `C::generator() * *secret_share == verification_shares[&params.i()]` after scaling, and reject otherwise. Optionally also verify that `verification_shares` lie on a consistent polynomial of degree `t-1` where feasible, so a tampered share set cannot yield an attacker-controlled `group_key`. Deserialization should fail closed rather than construct a usable-but-attacker-owned key set.

### Proof of Concept
1. Victim holds valid `ThresholdKeys<C>` and calls `keys.serialize()` to a file.
2. Attacker replaces the file with a crafted blob: same `C::ID`, valid `(t, n, i)`, `Interpolation::Lagrange` tag `1`, any canonical `secret_share`, and `n` canonical `read_G` points chosen so that `sum(verification_shares[1..=t] * lambda_j) == attacker_key` where the attacker knows `log_G(attacker_key)` (e.g., set `verification_shares[1] = attacker_key`, `verification_shares[2..=t] = identity`-free points with crafted combination, or use `Constant` interpolation with all factors `0` except one `1` applied to `attacker_key` when `t == n`... more simply: choose `t` shares equal to a known-secret polynomial).
3. `ThresholdKeys::read` succeeds; `keys.group_key() == attacker_key`.
4. Downstream `Scanner::new(keys.group_key())` reports deposits to attacker-controlled P2TR outputs; attacker spends them immediately while victim cannot produce a valid signature share (their `secret_share` doesn't match `verification_shares[i]`), yet nothing ever errored.

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }

  /// Construct a Scanner for a key.
  ///
  /// Returns None if this key can't be scanned for.
  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
