### Title
Unbounded recursion in `PuzzleWithRestrictions.from_memo()` when reconstructing nested `MofN` custody memos - (File: `chia/wallet/puzzles/custody/custody_architecture.py`)

### Summary
`PuzzleWithRestrictions.from_memo()` reconstructs a custody puzzle tree from an untrusted CLVM memo (e.g. supplied by an offer counterparty, or read back by a wallet for an incoming coin). When the memo encodes an `MofN` puzzle, the method calls itself recursively once per member, with no bound on nesting depth [1](#0-0) .

### Finding Description
`from_memo()` parses the memo's `further_branching` flag; if set, it builds an `MofN` whose `members` are produced by calling `PuzzleWithRestrictions.from_memo()` again for every member memo [2](#0-1) . There is no maximum-depth check anywhere in this recursive chain, and CLVM/`Program` values used as memos (`memo.at(...)`, `.as_iter()`) can be nested arbitrarily deep by an untrusted party constructing an offer, a custody hint, or any CHIP-0043 puzzle memo that is later parsed by a Chia wallet.

This is architecturally identical to CVE-2018-20348: `libpff_item_tree_create_node()` recursed once per crafted tree node with no depth guard, eventually exhausting the call stack and crashing the process (denial of service). Here, `from_memo()` recurses once per nested `MofN` member with no depth guard; a deeply nested (e.g., thousands of levels) `MofN` memo will exhaust the Python call stack and raise an uncaught `RecursionError`, crashing/hanging the wallet process that attempts to parse it.

By contrast, the codebase already recognizes and defends against this exact bug class elsewhere: `sha256_treehash()` is deliberately implemented iteratively "so we don't have to worry about blowing out the python stack" [3](#0-2) , and Data Layer's tree-insert path enforces `chia_rs.datalayer.RecursionDepthExceededError` for deep trees [4](#0-3) . `from_memo()` has no equivalent protection.

### Impact Explanation
A wallet that receives or processes an offer/custody memo containing a maliciously deep `MofN` nesting will hit Python's recursion limit and raise `RecursionError` inside `from_memo()`. If this path is reached during offer parsing, `unknown_puzzles` resolution, or coin-record processing (all of which call `from_memo()`/traverse `MofN` structures recursively per `unknown_puzzles` and `fill_in_unknown_puzzles`), an unhandled exception can halt wallet transaction processing for that wallet — a spend-triggered processing halt consistent with the "Validate" criteria (spend-triggered transaction-processing halt). This is a local denial-of-service against the wallet/offer-processing component, reachable by a single malicious offer counterparty or spend that references such a memo.

### Likelihood Explanation
Likelihood is moderate: constructing a deeply nested `MofN` memo is straightforward (just nest members recursively when building the offer/memo), and any counterparty in an offer or DL/CR-CAT interaction that shares custody memos with the victim wallet can trigger this without needing any special privilege — matching the "offer counterparty" and "wallet user" unprivileged-reach requirement.

### Recommendation
Add an explicit recursion-depth (or total node count) limit to `PuzzleWithRestrictions.from_memo()` (and the correspondingly recursive `unknown_puzzles` and `fill_in_unknown_puzzles` properties/methods on `MofN`/`PuzzleWithRestrictions`), raising a controlled `ValueError` once a maximum nesting depth is exceeded, mirroring the pattern already used for `sha256_treehash()` (iterative traversal) or Data Layer's `RecursionDepthExceededError` bound.

### Proof of Concept
Construct a memo `Program` matching the CHIP-0043 format recognized by `from_memo()`, where the `MofN` hint's `member_memos` list contains, as its single member, another `MofN`-branching memo of the same shape, nested N levels deep (N in the thousands, comfortably exceeding Python's default recursion limit of ~1000). Passing this memo to `PuzzleWithRestrictions.from_memo()` — e.g., as part of parsing an incoming offer's driver dict or custody hint — will recurse once per level via the `member_memos` list comprehension at [5](#0-4)  and raise an uncaught `RecursionError`, terminating whatever wallet code path invoked the parse.

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
