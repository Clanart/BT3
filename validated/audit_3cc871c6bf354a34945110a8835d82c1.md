### Title
Fee and weight calculated before the OP_RETURN data output is accounted, producing underpriced/oversized transactions - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The bug class from the external report — a value (fee) being recorded before a check/accounting step that should have reduced or enlarged it — maps onto `SignableTransaction::new`. The fee (`needed_fee`) and the transaction `weight` are computed from `payments` **before** the `OP_RETURN` data output is included in the weight estimation, and the undercounted values are what get checked (minimum relay fee, funds sufficiency, max weight) and stored in the `SignableTransaction`. The result is a signed transaction whose actual fee rate is lower than requested — potentially below the minimum relay fee — or whose actual weight exceeds `MAX_STANDARD_TX_WEIGHT`, so it cannot be relayed/confirmed.

### Finding Description
`SignableTransaction::new` builds `tx_outs`, including the `OP_RETURN` data output (up to 80 bytes of data plus output overhead, ~90+ non-witness bytes ≈ ~90 vbytes), at `send.rs:193-202`. However, both calls to `calculate_weight_vbytes` pass `payments` — the raw payments slice — not `tx_outs`, so the data output is excluded from `weight`, `vbytes`, and `vbytes_with_change`: [1](#0-0) [2](#0-1) 

All downstream decisions use these undercounted values:

- `needed_fee = fee_per_vbyte * vbytes` and the minimum-relay-fee check (`TooLowFee`) use the data-free `vbytes` (`send.rs:206-213`).
- The funds-sufficiency check `input_sat < payment_sat + needed_fee` passes with the understated fee (`send.rs:215-221`).
- The change-output leftover is computed as `input_sat - payment_sat - fee_with_change` where `fee_with_change` also excludes the data output (`send.rs:225-234`), so change is over-credited by `fee_per_vbyte * data_vbytes`.
- The `MAX_STANDARD_TX_WEIGHT` check uses the understated `weight` (`send.rs:241-243`), and `needed_fee` is persisted into the returned `SignableTransaction` (`send.rs:245-255`).

Because the actual fee paid is `sum(inputs) - sum(outputs)` (`fee()`, `send.rs:137-141`), the signed transaction carries exactly `needed_fee` spread over a *larger* actual vsize, so its real fee rate is strictly below `fee_per_vbyte` whenever `data` is present. With `fee_per_vbyte` at/near the relay minimum, the real rate falls below the minimum relay fee and nodes reject the transaction. The produced transaction can also exceed the standardness weight limit.

### Impact Explanation
An unprivileged party who can cause a `SignableTransaction` to be built with a `data` payload (`data` is a public input to `SignableTransaction::new`, exercised via the wallet API and `tests/wallet.rs::test_data`) obtains threshold signatures over a transaction that is underpriced relative to the requested fee rate — possibly non-relayable — and possibly non-standard by weight. Concretely: funds are committed as inputs to a transaction the network will not propagate/confirm, and when change is present the change output is credited more than the inputs can fund at the *intended* fee rate, burning additional value into fees. This is the same failure shape as the reference bug: the recorded/charged fee does not reflect the true cost because a component (the OP_RETURN output, analog to the debt) was not accounted before the fee was finalized. Medium severity: liveness/fee-leakage impact on funds, reachable with attacker-influenced data, no cryptographic break.

### Likelihood Explanation
Requires a caller to use the `data` parameter (e.g., anchoring/commitment flows), and to matter most at low fee rates. The miscalculation is deterministic whenever `data.is_some()` — every such transaction underpays by `fee_per_vbyte * (~10 + data_len)` vbytes and skips ~4× that in the weight check. The code's own test (`test_data`) never asserts `needed_fee` against `tx.vsize()` for the data case, so the discrepancy is uncaught.

### Recommendation
Compute weight/vbytes from the actual output list. Pass `&tx_outs` (or an equivalent slice including the OP_RETURN output) into `calculate_weight_vbytes` for both the no-change and with-change calls — i.e., perform fee/weight accounting *after* all outputs (payments, data, change) are known, mirroring the external report's "adjust fees after the check" fix. Concretely, change `calculate_weight_vbytes` to take `&[TxOut]` or the full output list, and call it with `tx_outs` plus the candidate change output.

### Proof of Concept
1. Construct `SignableTransaction::new(inputs, &[], Some(change), Some(vec![0u8; 80]), fee_per_vbyte)` with `fee_per_vbyte = 1`.
2. `calculate_weight_vbytes` is invoked with `payments = &[]`, so `vbytes`/`vbytes_with_change` omit the ~90-vbyte OP_RETURN output; `needed_fee = fee_per_vbyte * vbytes` is ~90 sats too low and the min-relay check at `send.rs:211` validates against the wrong size.
3. Sign via `multisig`/`TransactionSignMachine` (the sighash commits to the real tx including the data output, `send.rs:373-390`), then broadcast: `tx.vsize()` exceeds the estimated `vbytes`, so `actual_fee_rate = needed_fee / tx.vsize() < 1 sat/vB`, below `DEFAULT_MIN_RELAY_TX_FEE` — the transaction is rejected for relay despite the `TooLowFee` check having passed. The same underestimation lets `weight` evade the `MAX_STANDARD_TX_WEIGHT` guard at `send.rs:241`. [3](#0-2)

    let mut needed_fee = fee_per_vbyte * vbytes;
    // Technically, if there isn't change, this TX may still pay enough of a fee to pass the
    // minimum fee. Such edge cases aren't worth programming when they go against intent, as the
    // specified fee rate is too low to be valid
    // bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE is in sats/kilo-vbyte
    if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * vbytes) / 1000) {
      Err(TransactionError::TooLowFee)?;
    }

    if input_sat < (payment_sat + needed_fee) {
      Err(TransactionError::NotEnoughFunds {
        inputs: input_sat,
        payments: payment_sat,
        fee: needed_fee,
      })?;
    }

    // If there's a change address, check if there's change to give it
    if let Some(change) = change {
      let (weight_with_change, vbytes_with_change) =
        Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
      let fee_with_change = fee_per_vbyte * vbytes_with_change;
      if let Some(value) = input_sat.checked_sub(payment_sat + fee_with_change) {
        if value >= DUST {
          tx_outs.push(TxOut { value: Amount::from_sat(value), script_pubkey: change });
          weight = weight_with_change;
          needed_fee = fee_with_change;
        }
      }
    }

    if tx_outs.is_empty() {
      Err(TransactionError::NoOutputs)?;
    }

    if weight > u64::from(bitcoin::policy::MAX_STANDARD_TX_WEIGHT) {
      Err(TransactionError::TooLargeTransaction)?;
