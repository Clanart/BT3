### Title
`Noop` Interceptor Activated by Insecure Default `client_verification = false` Grants Any Network Caller Unrestricted Access to Privileged gRPC Methods — (`File: core/src/servers.rs`, `core/src/rpc/interceptors.rs`)

---

### Summary

When `client_verification` is `false` (the default when the `CLIENT_VERIFICATION` environment variable is absent), the server installs the `Noop` interceptor and omits the mTLS `client_ca_root`, removing every authentication gate from the gRPC surface. Any network-reachable caller can then invoke privileged "Internal" methods — `InternalWithdraw`, `InternalEndRound`, `InternalFinalizedPayout`, `InternalCreateAssertCommitmentTxs`, `InternalCreateWatchtowerChallenge` — that are supposed to be callable only by the operator/verifier process itself.

---

**Insecure default**

The env-var parser evaluates `client_verification` as:

```rust
// core/src/config/env.rs  line 181-182
let client_verification =
    read_string_from_env("CLIENT_VERIFICATION").is_ok_and(|s| s == "true" || s == "1");
``` [2](#0-1) 

`read_string_from_env` returns `Err` when the variable is absent; `is_ok_and` then returns `false`. The field therefore defaults to `false`, silently enabling `Noop`.

---

### Impact Explanation

**`InternalWithdraw`**: An unauthenticated caller can submit any `WithdrawParams` (withdrawal index, user taproot signature, input outpoint, output script, amount) directly to the operator. The operator will verify the withdrawal exists in Citrea and check profitability, but it will then construct and broadcast a payout transaction. Because the user's taproot signature uses `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` (as noted in the aggregator's comment), the signature commits only to the output at the same index — an attacker who controls the output construction can craft a transaction that satisfies the signature while redirecting funds, or can race a legitimate withdrawal to drain the operator's fronting capital.

**`InternalEndRound`**: Premature round termination disrupts the deposit lifecycle, potentially invalidating in-flight MuSig2 signing sessions and locking depositor funds.

**`InternalFinalizedPayout`**: Marking a payout as finalized with an attacker-supplied txid corrupts the DB state used to track reimbursement eligibility, potentially causing the operator to lose collateral or miss reimbursement windows.

**`SetOperator` (verifier, non-internal)**: Also reachable without auth when `Noop` is active; an attacker can register a malicious operator key and reimbursement address on every verifier, poisoning the signing committee's view of the operator set.

---

### Likelihood Explanation

The `CLIENT_VERIFICATION` environment variable is absent from the `.env.example` file and is not documented as mandatory. Any operator deploying via environment variables who does not explicitly set `CLIENT_VERIFICATION=true` silently runs with `Noop`. The operator/verifier server emits no warning in this case (only the aggregator server warns — and only when `client_verification = true`, the opposite of the dangerous case). The gRPC port is typically network-accessible. This makes accidental misconfiguration highly plausible in real deployments. [8](#0-7) 

---

### Recommendation

1. **Flip the default**: Change `client_verification` to default to `true` in both the env-var parser and the TOML default. Require an explicit opt-out, not an opt-in.

2. **Emit a startup warning/error when `client_verification = false`** on operator and verifier servers, analogous to the existing (inverted) warning on the aggregator.

3. **Remove or harden `Noop`**: If `Noop` is needed for local/Unix-socket deployments, gate it on `cfg(test)` or on a Unix-socket-only path, not on a runtime boolean that defaults to the insecure value.

4. **Add an application-layer auth check inside `internal_withdraw`** (and other Internal handlers) that is independent of the transport-layer interceptor, so that a misconfigured interceptor cannot alone expose these methods.

---

### Proof of Concept

Deploy an operator with `CLIENT_VERIFICATION` unset (or `false`). Connect to the operator's gRPC port with any TLS client (no client certificate needed — server-only TLS is in effect). Call `InternalWithdraw` directly:

```python
import grpc
# No client cert — server-only TLS
creds = grpc.ssl_channel_credentials(root_certificates=open("certs/ca/ca.pem","rb").read())
channel = grpc.secure_channel("operator-host:17000", creds)
stub = ClementineOperatorStub(channel)

# Supply a valid withdrawal registered in Citrea with a user-provided taproot sig
resp = stub.InternalWithdraw(WithdrawParams(
    withdrawal_id=0,
    input_signature=<valid_user_taproot_sig>,
    input_outpoint=<withdrawal_utxo>,
    output_script_pubkey=<attacker_address_scriptpubkey>,
    output_amount=<amount>,
))
# Operator broadcasts payout tx — no aggregator ECDSA check performed
```

The operator will process the request, construct the payout transaction, and add it to the TxSender queue for broadcast — with no authentication of the caller. [9](#0-8) [10](#0-9) [2](#0-1)

        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),

use tonic::{service::Interceptor, transport::CertificateDer, Request, Status};

#[derive(Debug, Clone)]
pub enum Interceptors {
    OnlyAggregatorAndSelf {
        aggregator_cert: CertificateDer<'static>,
        our_cert: CertificateDer<'static>,
    },
    Noop,
}

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware
    let Some(path) = req.metadata().get("grpc-method") else {
        // No grpc method? this should not happen
        tracing::error!("Missing grpc-method header in request");
        return false;
    };
    path.as_bytes().starts_with(b"Internal")
}

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
