### Title
`Scanner` reports sub-dust outputs as received even though spending them costs more than their value, permanently stranding credited funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The Rio finding is that a minimum-quantity check makes a residual amount unusable while still being counted in the protocol's total balance, so users' withdrawal claims can be backed by funds that can never be moved — effectively lost tokens.

The Serai analog lives in the Bitcoin `Scanner`: `scan_transaction` / `scan_block` push a `ReceivedOutput` for every output whose `script_pubkey` matches a registered script, with no minimum-value check. Any external party can send a tiny (even sub-dust) payment to a Serai deposit address; it is reported as received and credited, yet `SignableTransaction::new` offers no path to spend it economically — its value is below the fee its own input adds. The funds are reported received but are not spendable.

### Finding Description
`Scanner::scan_transaction` iterates all outputs and reports any whose `script_pubkey` is in `self.scripts`, without inspecting `output.value`: [1](#0-0) 

The same applies to `scan_block` (lines 221-227). `ReceivedOutput` simply wraps the output and outpoint.

On the spend side, `SignableTransaction::new` enforces a `DUST` (546 sat) minimum only on *payments* (outputs), not on inputs: [2](#0-1) 

Every included input adds a Taproot key-spend input (~57 vbytes per the commentary in `processor/src/networks/bitcoin.rs`, ~230 weight units) plus its share of base fee. An output worth less than the marginal fee of its own input can never contribute net value to a transaction; at best it errors with `NotEnoughFunds` (line 215), and at worst its entire value is silently burned into the fee (`fee()` at line 139 is just `sum(inputs) - sum(outputs)`). There is also no "sweep dust into fee" helper that would make it rational to include.

Like the Rio `MIN_EXCESS_FULL_WITHDRAWAL_ETH_FOR_SCRAPE` leaving a counted-but-unusable balance, here the scanner's implicit "any amount is receivable" policy leaves a credited-but-unusable balance: the change-output path even explicitly drops leftover `< DUST` into the fee (lines 224-235), confirming the codebase's own model is that sub-dust value is not recoverable as an output — yet the scanner still reports such value as a normal received output.

### Impact Explanation
An unprivileged attacker sends transactions paying dust/uneconomical amounts (1 sat, or anything below ~`fee_per_vbyte * 57` sats) to a Serai multisig's scanned P2TR script. `scan_transaction`/`scan_block` return them as `ReceivedOutput`s, so the protocol counts this BTC toward balances/liabilities. Those outputs can never be profitably spent — including them in `SignableTransaction::new` either fails `NotEnoughFunds` or donates their full value to miners. Result: funds reported received that are not spendable, i.e., permanently locked accounting value that other depositors' legitimate withdrawals may be forced to cover — the same "unused balance backing user claims" impact as the Rio issue.

### Likelihood Explanation
The attacker needs only to broadcast ordinary Bitcoin transactions to a known deposit script — no collusion, no key material, no validator misbehavior. Cost is bounded by the dust amounts sent (trivially cheap). The only mitigating factor is that each stuck output is small, but it can be repeated arbitrarily across outputs, and the wallet provides no remediation path to consolidate or ignore them.

### Recommendation
Add a minimum-value filter in `Scanner::scan_transaction`/`scan_block` (or when constructing `ReceivedOutput`s) so outputs worth less than a spendability threshold (at minimum `DUST`, ideally the marginal cost to spend the input plus margin) are not reported as received. Alternatively/additionally, give `SignableTransaction` a mechanism to exclude or sweep uneconomical inputs so credited funds are never unspendable.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),

        });
      }
    }
