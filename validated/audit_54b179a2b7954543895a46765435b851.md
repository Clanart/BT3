### Title
Global gasless bundle-tx queue limit allows an unprivileged attacker to DoS legitimate KIP-247 gasless users - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`GaslessModule.PreAddTx` admits gasless-bundle transactions (`GaslessApproveTx`/`GaslessSwapTx`) into a single, chain-wide queue counter (`knownTxs.numQueue()`) bounded by `GaslessConfig.MaxBundleTxsInQueue` (default 200). Because admission only requires the tx to structurally look like an approve/swap call to a whitelisted router/token — it does not require the tx to ever become executable or the sender to hold any real balance — any unprivileged account can cheaply mint many distinct signer addresses and flood this shared queue slot budget, exactly the same class of bug as the `updateTrust()` report: a shared, capped resource (`maxVouchees`/`maxVouchers` there, `MaxBundleTxsInQueue` here) that is consumable with worthless/zero-effect entries by an arbitrary unprivileged caller, blocking legitimate users from the same resource.

### Finding Description
`PreAddTx` is invoked for every incoming transaction pool candidate: [1](#0-0) 

If `g.IsBundleTx(tx)` is true, the transaction is unconditionally counted against the single global `MaxBundleTxsInQueue` limit via `g.knownTxs.numQueue()`, with no per-sender limit and no requirement that the tx be economically meaningful: [2](#0-1) 

`IsBundleTx`/`IsModuleTx` merely delegate to `IsApproveTx`/`IsSwapTx`, which only check static structural conditions on the transaction (target token/router whitelisted, function selector, and for approve, `amount == MaxUint256`): [3](#0-2) 

Notably `IsApproveTx`/`IsSwapTx` don't check the sender's real token balance/allowance by themselves (that's a separate, opt-in `GetCheckBalance()` gate used at a different point in the pool's flow, gated behind `BalanceCheckLevel`, default `BalanceCheckLevelAll` which does check balances - see below), but `PreAddTx` (the function that increments the shared queue counter) runs **before** that balance/allowance filtering and does not perform it itself: [1](#0-0) 

An attacker who only needs a whitelisted ERC20 token address and the swap-router address (both public, on-chain, discoverable via the Registry/MultiCall contract) can craft, from many distinct freshly-generated EOA addresses (bare accounts, no funding required beyond gas for the tx itself, or even none if using `AddRemote` and just needing it accepted into the pool logic prior to balance checks), a stream of syntactically valid `GaslessSwapTx`/`GaslessApproveTx` transactions and submit them. Each is treated as `IsBundleTx == true`, incrementing `numQueue()`, until `MaxBundleTxsInQueue` (200 by default, configurable down via `--gasless.max-bundle-txs-in-queue`) is reached, after which `PreAddTx` returns `ErrBundleTxQueueFull` for all subsequent attempts — including from genuine users trying to use the gasless swap feature: [4](#0-3) [5](#0-4) 

This mirrors the reported `UserManager.updateTrust()` bug class: a globally-shared, capacity-limited data structure that any unprivileged, minimally-resourced caller can saturate with "zero-value"/junk entries that satisfy only the syntactic admission check, permanently denying the resource to legitimate participants until the queue-timeout window (`QueueTimeout` = 10s) rolls the entries out — but the attacker can simply resubmit continuously to keep the queue saturated.

### Impact Explanation
This is a Denial-of-Service against the KIP-247 gasless feature: legitimate users' `GaslessApproveTx`/`GaslessSwapTx` pairs are refused admission (`ErrBundleTxQueueFull`) as soon as the shared queue counter is saturated, blocking their access to gas-fee-lending via the gasless mechanism network-wide (the limit is global, not per-sender or per-validator, so any single unprivileged submitter can exhaust it for everyone). This does not directly cause value theft, but it denies a publicly-offered protocol service (gasless transactions) to all other unprivileged users, satisfying the "acceptance of a shared queue resource abuse" class permitted for Medium severity by the validation rules (state divergence is not applicable, but denial of a public transaction-processing service reachable purely via submitted transactions is analogous to the reported DOS).

### Likelihood Explanation
High likelihood of feasibility: the whitelisted token/router addresses are public on-chain data (read via `MultiCallGaslessInfo`), the check performed at admission time (`IsApproveTx`/`IsSwapTx`) is purely structural, and `PreAddTx`'s queue-fullness check has no per-sender quota — an attacker only needs the ability to submit transactions (even ones that will ultimately fail balance checks later or during block building) since the queue-slot consumption happens before those balance checks in the tx-pool flow. The cost to the attacker is bounded by ordinary gas/transaction fees for crafting many structurally-valid, low-cost approve/swap-shaped transactions from disposable accounts.

### Recommendation
- Enforce the `MaxBundleTxsInQueue` limit per-sender (or per unique gasless "session") in addition to (or instead of) the current global counter, so no single actor can exhaust the entire shared budget.
- Move a lightweight economic/balance sanity check (e.g., `ShouldCheckToken`/token balance > 0) earlier, into `PreAddTx` / `IsBundleTx`, before the tx is allowed to consume a global queue slot, so that transactions from accounts holding zero relevant token balance cannot occupy the shared resource.
- Consider requiring the submitting account to already hold a minimal token balance or having done a prior nonce-consuming action, raising the cost of Sybil-style queue flooding.

### Proof of Concept
1. Query the public `Registry`/`MultiCall` system contracts (readable by anyone) to learn the current whitelisted `GaslessSwapRouter` address and allowed ERC20 token addresses, as done in `getGaslessInfo`: [6](#0-5) 
2. Generate `N` (up to `MaxBundleTxsInQueue`, default 200) throwaway EOAs.
3. For each EOA, craft a legacy transaction calling `approve(spender=swapRouter, amount=MaxUint256)` on a whitelisted token, satisfying `IsApproveTx`'s A1/A3/A4 checks in `isApproveTx`: [7](#0-6) 
4. Submit all `N` transactions to any node's tx pool (`AddRemote`/`AddRemotes`). Each call to `PreAddTx` classifies the tx as `IsBundleTx==true` and increments `knownTxs.numQueue()`: [8](#0-7) 
5. Once `numQueue() >= MaxBundleTxsInQueue`, any further legitimate `GaslessApproveTx`/`GaslessSwapTx` from real users is rejected with `ErrBundleTxQueueFull`, confirming denial of service. The attacker resubmits fresh junk transactions before the 10-second `QueueTimeout` expires to keep the queue permanently saturated: [9](#0-8) 

**Note on verification limits**: I was not able to trace, within the available index, the exact ordering/interaction between `PreAddTx` and the transaction pool's other admission checks (e.g., whether `AddRemote` calls balance-related filters — `GetCheckBalance()` — before or after `PreAddTx` for every transaction type, and whether unfunded accounts can pass gas-fee prechecks at all). This ordering detail affects whether a fully-unfunded Sybil account can reach `PreAddTx`, or whether the attacker needs minimally-funded accounts (still cheap, but not free) to get transactions gas-fee-accepted into the pool. A Devin session with full repository/build access would be needed to confirm the exact tx_pool call order (`blockchain/tx_pool.go`) and validate this PoC end-to-end.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1
		g.allowedTokens[args.Token] // S3
}

func getGaslessInfo(bc backends.BlockChainForCaller, header *types.Header) (common.Address, []common.Address, error) {
	statedb, err := bc.StateAt(header.Root)
	if err != nil {
		return common.Address{}, nil, err
	}

	// If Registry is not installed, do not query GaslessSwapRouter contract.
	if statedb.GetCode(system.RegistryAddr) == nil || bc.Config().IsRandaoForkBlockParent(header.Number) {
		return common.Address{}, nil, nil
	}

	caller, err := system.NewMultiCallContractCaller(statedb, bc, header)
	if err != nil {
		return common.Address{}, nil, err
	}

	opts := &bind.CallOpts{BlockNumber: header.Number}
	info, err := caller.MultiCallGaslessInfo(opts)

	return info.Gsr, info.Tokens, err
}
