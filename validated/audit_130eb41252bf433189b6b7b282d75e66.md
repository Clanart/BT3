## Analysis

This is a Bitcoin bridge (Clementine), not an ERC20 vault, so the literal vulnerability (`cancelRedeemRequest` bypassing `_checkTransfer`) doesn't apply directly. However, the underlying bug *class* — an unauthenticated field being trusted to attribute custody/credit, letting an unprivileged party redirect who is credited versus who actually paid — has a concrete analog in the payout attribution mechanism.

### Title
Payout attribution via unauthenticated OP_RETURN allows anyone to front-run a payout and forge which operator is credited for fronting it - (File: core/src/builder/transaction/operator_reimburse.rs, core/src/verifier.rs)

### Summary
`create_payout_txhandler` builds the operator's `payout_tx` with the user's withdrawal input signed under `SIGHASH_SINGLE|ANYONECANPAY`, and appends an `OP_RETURN` output carrying the fronting operator's x-only pubkey. Because `SIGHASH_SINGLE|ANYONECANPAY` only commits to input 0 and output 0, any party who observes this transaction in the mempool can construct a competing, higher-fee transaction that reuses the same signed input/output pair but funds the rest of the payout from a different source and writes an arbitrary x-only pubkey into the `OP_RETURN`. The verifier's `update_finalized_payouts` later attributes the payout purely from that unauthenticated `OP_RETURN` field, with no check that the named operator's key actually signed the additional funding inputs.

### Finding Description
`create_payout_txhandler` [1](#0-0)  constructs the payout with one signed input (the withdrawal dust UTXO, signed by the user with `SinglePlusAnyoneCanPay`) and an `OP_RETURN` output embedding `operator_xonly_pk` — the identity that will later be credited for reimbursement. The `operator_xonly_pk` value comes straight from the caller (`self.signer.xonly_public_key`) in `Operator::withdraw` [2](#0-1) , with the withdrawal output value actually funded afterward by `fund_raw_transaction`/`sign_raw_transaction_with_wallet` [3](#0-2) .

Because the sighash type is `SinglePlusAnyoneCanPay`, the signature commits only to input index 0 and the single corresponding output index 0 [4](#0-3) . All other inputs/outputs — including the `OP_RETURN` payer-attribution output and whatever inputs fund the withdrawal amount — are unconstrained and can be freely substituted by anyone who reuses the same signed input/output pair once it is visible (e.g., as soon as it hits the Bitcoin mempool).

On the read side, `update_finalized_payouts` scans confirmed blocks, finds the payout transaction spending the withdrawal UTXO, and takes the `OP_RETURN` bytes as the "payer operator xonly pk" with no verification that this pubkey corresponds to whoever actually supplied the funding inputs of that transaction [5](#0-4) . This value is persisted via `update_payout_txs_and_payer_operator_xonly_pk` [6](#0-5)  and later used both by `PayoutCheckerTask`/`Operator::validate_payer_is_operator` to decide which operator may claim reimbursement [7](#0-6) , and by verifiers' `is_kickoff_malicious` to decide whether a kickoff is legitimate [8](#0-7) .

The binding that should hold is: `operator credited for a payout == operator whose funds actually paid the withdrawal`. Before the attack: the real operator broadcasts `payout_tx` funded and signed from its own wallet, with its own key in `OP_RETURN`. During the attack: an unprivileged party observing the mempool constructs a replacement transaction with the same signed input/output-0 pair, funds the withdrawal amount itself (or with unrelated funds), and RBF-replaces the honest operator's broadcast with a transaction whose `OP_RETURN` names an arbitrary x-only pubkey (its own, an unregistered key, or another operator's). After: the on-chain payout is attributed to a party that did not actually front it from a verified/attributable wallet path — breaking the credited-vs-paid equality with no signature or role check ever verifying it.

### Impact Explanation
If the attacker names an unregistered/arbitrary pubkey (not a real, collateralized operator participating in the round system), no operator can ever complete a matching kickoff for that withdrawal (the `payer_xonly_pk` recorded will never equal any operator's `signer.xonly_public_key` in `validate_payer_is_operator`), so `PayoutCheckerTask`/`handle_finalized_payout` can never process it and the deposit's `move_to_vault` UTXO becomes permanently unclaimable by any operator — a vault UTXO effectively frozen from the operator-reimbursement path. If instead the attacker names a real operator's pubkey while funding the withdrawal from unrelated/attacker funds, that operator becomes eligible to claim BTC reimbursement from the N-of-N vault for a withdrawal it never actually funded from its own wallet — an operator reimbursed for a payout it never funded. Both outcomes map to the Critical impact category in scope.

### Likelihood Explanation
The attack requires no privileged role (verifier, operator, watchtower, aggregator, security council) — only visibility into the Bitcoin mempool (any node) and the ability to fund/broadcast a competing higher-fee transaction, i.e., a generic unprivileged actor. The `SinglePlusAnyoneCanPay` sighash is intentionally used to allow fee-bumping flexibility, but it also leaves the `OP_RETURN` attribution output completely unauthenticated, which is a structural weakness rather than a rare edge case; a competing broadcast with a higher fee is straightforward to construct and race against the original operator's `withdraw()` broadcast before it confirms.

### Recommendation
Bind the `OP_RETURN` operator attribution to a value that is actually signed/committed by the operator (e.g., use `SIGHASH_ALL` for the fee-funding inputs the operator itself adds, or cover the `OP_RETURN` output under the committed sighash, or require an additional operator signature/commitment covering the entire payout transaction before it is treated as a valid reimbursement claim). Verifiers/operators should not attribute reimbursement credit from an output that is unconstrained by any signature.

### Proof of Concept
1. Operator `O` calls `withdraw()`, producing and broadcasting `payout_tx` with input `dust_utxo` (user-signed `SinglePlusAnyoneCanPay`), output[0] = user payout, `OP_RETURN` = `O`'s xonly pubkey, funded via `O`'s bitcoind wallet [9](#0-8) .
2. Attacker `A` observes `payout_tx` in the mempool (unconfirmed). Because the user's signature is `SinglePlusAnyoneCanPay`, `A` builds `payout_tx'` reusing the exact `dust_utxo` input and output[0], but replaces/adds additional inputs from `A`'s own wallet to fund the withdrawal amount, and sets `OP_RETURN` to an arbitrary pubkey `X` (attacker-controlled or an unregistered key).
3. `A` sets a higher fee and broadcasts `payout_tx'`, which replaces `O`'s `payout_tx` in the mempool/next block via RBF.
4. `update_finalized_payouts` parses the confirmed `payout_tx'`, records `payout_payer_operator_xonly_pk = X` with no check that `X` signed the funding inputs [5](#0-4) .
5. Since no operator's `signer.xonly_public_key` equals `X`, `validate_payer_is_operator`/`get_first_unhandled_payout_by_operator_xonly_pk` never matches, so no kickoff can ever be initiated for this withdrawal — the deposit's move-to-vault UTXO is permanently stuck, even though the user was correctly paid.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
