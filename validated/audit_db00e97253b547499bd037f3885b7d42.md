### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable received funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` iterates over every transaction in a block, including the coinbase transaction `block.txdata[0]`, and returns its outputs as ordinary `ReceivedOutput`s. Bitcoin consensus makes coinbase outputs unspendable for 100 blocks (COINBASE_MATURITY). The scanner performs no maturity check, so an unprivileged miner who pays the Serai Taproot key in a coinbase causes the wallet to report funds that cannot actually be spent — an analog of accepting input without validating a required property (the ID4me expiration/signature omission).

### Finding Description
`scan_transaction` matches outputs purely by `script_pubkey` against the registered scripts map and pushes a `ReceivedOutput` for each match [1](#0-0) . `scan_block` then calls `scan_transaction` for all of `block.txdata` with no special-casing of index 0 and no maturity/confirmation tracking [2](#0-1) . The only acknowledgement is a doc comment telling callers to post-filter or slice `[1 ..]` themselves [3](#0-2) . `ReceivedOutput` itself carries no metadata marking the outpoint as immature [4](#0-3) , and `SignableTransaction::new` / `TransactionMachine` happily accept such an output, produce a fully valid FROST-signed transaction, and `send_raw_transaction` is the first point of failure (consensus rejects with `bad-txns-premature-spend-of-coinbase`).

### Impact Explanation
Funds are reported received that are not spendable. A caller that sums `ReceivedOutput::value()` over `scan_block` results overstates its balance, and a spend constructed with an immature input produces a transaction that consensus rejects — burning a FROST signing attempt and stalling payouts. Since the signed message itself is fine, retries with the same inputs fail identically until maturity.

### Likelihood Explanation
Reachable by an unprivileged party: any miner/pool can pay the Serai vault's P2TR script directly in a coinbase output (a "donation"), which is indistinguishable by script_pubkey from a normal payment. This requires mining a block, so it is not free, but it is well within reach of mining pools and is a normal, common pattern for miner payouts. Medium severity: no theft or forgery, only misreported funds and a temporary spend failure.

### Recommendation
In `scan_block`, skip `block.txdata[0]` or return immature coinbase outputs distinctly (e.g., a `matures_at` field or a separate `scan_block` variant), and have `SignableTransaction::new` reject immature coinbase inputs. Do not rely on callers performing a post-processing pass.

### Proof of Concept
1. Create a `Scanner` for the vault's even Taproot key (`Scanner::new(key)`).
2. A miner constructs a block whose coinbase `txdata[0]` pays `p2tr_script_buf(key)` and broadcasts it.
3. `scanner.scan_block(&block)` returns a `ReceivedOutput` for the coinbase outpoint with `offset == Scalar::ZERO`.
4. `SignableTransaction::new(vec![that_output], &payments, change, None, fee)` succeeds, `multisig(&keys)` succeeds, and the FROST signing session produces a valid-looking signed `Transaction`.
5. Submitting via `send_raw_transaction` fails consensus validation (`bad-txns-premature-spend-of-coinbase`), while `output.value()` was already counted as received funds.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

    let mut res = Vec::new();
