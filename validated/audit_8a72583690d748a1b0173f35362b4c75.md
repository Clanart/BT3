### Title
Unhandled exception (wallet DoS) when processing a malformed NFT metadata-update condition (`-24`) - ([File: chia/wallet/nft_wallet/nft_puzzle_utils.py])

### Summary
`get_metadata_and_phs()` is called by the NFT wallet whenever it processes a coin spend for an NFT it owns, in order to derive the NFT's next metadata and destination puzzle hash from the conditions produced by running the p2 puzzle. When it encounters a `-24` (metadata update) condition it calls `update_metadata(metadata, condition)` [1](#0-0)  without validating the condition's shape or the current metadata dictionary's keys, unlike libxls's cell parser which dereferences a cell pointer that may be NULL when the input XLS file is malformed.

### Finding Description
`update_metadata()` reads the URI/key from the update condition and calls `prepend_value()`: [2](#0-1) 

`prepend_value()` directly indexes `metadata[key]` with no existence check and calls `.insert(0, ...)` assuming the existing value is a list: [3](#0-2) 

- If the update condition's key (`uri.first().as_python()`) is not one of the fixed keys already present in `new_metadata` (which comes from `nft_program_to_metadata(metadata)` at [4](#0-3) ), `metadata[key]` raises `KeyError`.
- If the existing value under that key is not `b""` and not a `list` (e.g., an integer or bytes value placed there by an attacker-crafted NFT/state-layer puzzle), `metadata[key].insert(0, ...)` raises `AttributeError`.
- `update_condition.rest().rest().first()` in `update_metadata` also assumes the condition has at least 3 elements; a shorter list raises inside CLVM's SExp traversal.

None of these exceptions are caught anywhere in the call chain: `get_metadata_and_phs()` has no try/except around the `update_metadata` call [5](#0-4) , and its caller in the NFT wallet coin-processing path likewise does not guard this specific call (it is invoked during normal coin-added handling for every incoming/spent NFT coin belonging to the wallet). This is directly analogous to the reported libxls bug: parsing an externally supplied, insufficiently validated structure (an XLS cell / a CLVM metadata-update condition) and indexing into it without checking that the expected shape/keys are present, causing an unhandled crash during processing of the untrusted input.

### Impact Explanation
Any NFT/DID counterparty, offer counterparty, or arbitrary chain participant who can construct a spend of an NFT that a victim wallet is currently tracking (e.g. via a transfer, DID update, or ownership-layer spend with a crafted `-24` metadata-update condition whose key/value doesn't match the wallet's expected metadata dict shape) can cause the victim wallet process to raise an unhandled exception while processing that coin's state change. Depending on how the wallet's coin-processing dispatcher handles this exception, this can halt/crash the wallet's transaction-processing (sync) loop for the affected wallet, a Medium-severity DoS analogous to the reported libxls NULL-pointer crash on malformed cell data.

### Likelihood Explanation
Exploitation requires only crafting a coin spend (which any spend-bundle submitter/offer counterparty can do) that spends an NFT the victim wallet already owns/tracks, with a metadata-update condition whose key is absent from the tracked metadata dict or whose existing value isn't a list. This is reachable purely through normal NFT/DID protocol interaction, with no privileged access needed, making likelihood moderate-to-high for any wallet actively holding/tracking NFTs from adversarial counterparties.

### Recommendation
In `prepend_value()`, validate `key in metadata` and that `metadata[key]` is a list (or `b""`) before mutating; otherwise skip the update gracefully or raise a caught/validated error. In `update_metadata()`, validate that `update_condition` has the expected list length (>= 3 elements) before calling `.rest().rest().first()`. Wrap the `update_metadata` call in `get_metadata_and_phs()` in a try/except that treats a malformed metadata-update condition as a no-op (ignore) rather than letting the exception propagate into the wallet's coin-processing loop.

### Proof of Concept
1. Mint/acquire an NFT with the ownership layer and standard metadata (`u`, `h`, `mu`, `mh`, `lu`, `lh`, `sn`, `st` keys) tracked by a victim wallet.
2. Construct a spend of that NFT's p2 puzzle whose solution yields a condition `(-24 metadata_updater_solution (<unknown_key> . <int_value>))` where `<unknown_key>` is not one of the recognized metadata keys (e.g., `b"zz"`), or reuses an existing key whose value is not stored as a list.
3. Submit the spend bundle to the network (or send it directly as an offer/transfer to the victim). When the victim's wallet processes the coin change via `get_metadata_and_phs()` → `update_metadata()` → `prepend_value()`, the `KeyError`/`AttributeError` is raised and propagates unguarded, potentially crashing or halting the wallet's coin-processing task for that wallet.

def nft_program_to_metadata(program: Program) -> dict[bytes, Any]:
    """
    Convert a program to a metadata dict
    :param program: Chialisp program contains the metadata
    :return: Metadata dict
    """
    metadata = {}
    for kv_pair in program.as_iter():
        metadata[kv_pair.first().as_atom()] = kv_pair.rest().as_python()
    return metadata

def prepend_value(key: bytes, value: Program, metadata: dict[bytes, Any]) -> None:
    """
    Prepend a value to a list in the metadata
    :param key: Key of the field
    :param value: Value want to add
    :param metadata: Metadata
    :return:
    """
    if value != Program.to(0):
        if metadata[key] == b"":
            metadata[key] = [value.as_python()]
        else:
            metadata[key].insert(0, value.as_python())

def update_metadata(metadata: Program, update_condition: Program) -> Program:
    """
    Apply conditions of metadata updater to the previous metadata
    :param metadata: Previous metadata
    :param update_condition: Update metadata conditions
    :return: Updated metadata
    """
    new_metadata: dict[bytes, Any] = nft_program_to_metadata(metadata)
    uri: Program = update_condition.rest().rest().first()

def get_metadata_and_phs(unft: UncurriedNFT, solution: SerializedProgram) -> tuple[Program, bytes32]:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(Program.from_serialized(solution)))
    metadata = unft.metadata
    puzhash_for_derivation: bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.list_len() < 2:
            # invalid condition
            continue
        condition_code = condition.first().as_int()
        log.debug("Checking condition code: %r", condition_code)
        if condition_code == -24:
            # metadata update
            metadata = update_metadata(metadata, condition)
            metadata = Program.to(metadata)
        elif condition_code == 51:
            atom = condition.rest().rest().first().as_int()

            if atom == 1:
                # destination puzhash
                if puzhash_for_derivation is not None:
                    # ignore duplicated create coin conditions
                    continue
                memo = bytes32(condition.at("rrrff").as_atom())
                puzhash_for_derivation = memo
                log.debug("Got back puzhash from solution: %s", puzhash_for_derivation)
    assert puzhash_for_derivation
    return metadata, puzhash_for_derivation
