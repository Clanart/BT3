### Title
Unauthenticated SSRF via DataLayer mirror coin memos — any spend-bundle submitter can force victim nodes to fetch attacker-chosen URLs - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
Chia's DataLayer mirror mechanism lets **any** on-chain spender attach an arbitrary URL list to **any** `store_id` (launcher id) by creating a coin with a fixed, non-owner-gated puzzle hash and memo-encoded `(launcher_id, urls)`. Any DataLayer node that tracks/subscribes to that `store_id` will automatically ingest the URLs as mirror server candidates and periodically issue outbound HTTP requests to them with no host/scheme validation — a direct analog of the SSRF class described in the report (attacker-controlled URL causing the application to make arbitrary outbound requests).

### Finding Description
The mirror coin puzzle is a fixed, unparameterized puzzle unrelated to the DL singleton owner: [1](#0-0) 

`DataLayerWallet.coin_added()` treats *any* newly seen coin with this fixed puzzle hash as a mirror candidate, decodes `launcher_id` and `urls` straight from the parent coin's spend memos, and persists them as long as the `launcher_id` happens to already be tracked locally — with no check that the creator owns, controls, or is authorized for that launcher/store: [2](#0-1) 

`create_new_mirror()` (reachable via the `dl_new_mirror` wallet RPC) shows mirror creation is just a standard coin creation with `memos=[[launcher_id, *urls]]` — there is no signature or authorization tying the memo content to the `launcher_id`'s singleton owner key: [3](#0-2) 

The `DataLayer` service then pulls these attacker-controlled URLs unconditionally from wallet RPC and stores them as subscription server candidates: [4](#0-3) 

During the periodic sync loop, `fetch_and_validate()` randomly selects one of these subscription URLs and issues an outbound request (`insert_from_delta_file` → `download_file` → `http_download`) with no allow-list, no restriction on private/internal/loopback/link-local addresses, and no TLS/host pinning beyond what `aiohttp` does by default: [5](#0-4) [6](#0-5) 

The project's own module notes confirm this is a known, explicit trust boundary that is documented as merely "not trusted," relying only on later Merkle-root validation of the *content* — not on preventing the SSRF request itself: [7](#0-6) [8](#0-7) 

### Impact Explanation
Any user capable of submitting a spend bundle (an unprivileged blockchain participant) can pay a small fee to create a mirror coin memo-tagged with a `store_id` that a victim DataLayer node tracks (which is the normal, intended state for any publicly subscribed store), and an arbitrary URL, including:
- `http://127.0.0.1:<port>/...` or other loopback/internal-network addresses reachable from the victim host,
- cloud metadata endpoints (e.g., `169.254.169.254`) if the DataLayer node runs in a cloud VM,
- internal RPC/admin endpoints not otherwise exposed to the internet.

The victim's `DataLayer.periodically_manage_data()` background loop will then autonomously issue outbound HTTP(S) requests to that URL on a recurring basis, without any content being trusted (data is still validated against wallet roots before being committed), but the SSRF *request itself* — timing, response codes, banner/error leakage, and any side effects of hitting an internal service — occurs regardless of content validation. This matches the CVE's classic SSRF pattern (unvalidated attacker-supplied URL triggers outbound requests from a privileged host), reachable here as a "Data Layer client" path explicitly in scope.

### Likelihood Explanation
High. No signature, ownership, or authorization check ties the mirror's `launcher_id`/URL memo to the actual singleton owner or to any permission over that store — creating the coin is a normal, low-cost, permissionless wallet operation (`dl_new_mirror`, or even a raw spend bundle to `MIRROR_PUZZLE_HASH` with the desired memos). The only prerequisite is that the target node already tracks the `launcher_id`, which is the default state for anyone subscribed to/replicating a DataLayer store — the very use case DataLayer mirrors exist for.

### Recommendation
- Require that mirror coins be authenticated to the store's singleton owner (e.g., verify the mirror creation is signed by/associated with the owner key of the DL singleton at `launcher_id`, or at minimum require an on-chain announcement coupling from the singleton itself) before treating the memo URLs as trusted subscription candidates.
- Enforce a strict URL scheme allow-list (`https://` only, similar to the pool-URL mainnet enforcement pattern already used in `chia/farmer/farmer.py` and `chia/cmds/plotnft_funcs.py`).
- Reject or filter URLs resolving to private/loopback/link-local/metadata IP ranges before the DataLayer service issues any outbound HTTP request in `fetch_and_validate()`/`download_file()`/`http_download()`.
- Consider rate-limiting/backoff and sandboxing outbound mirror requests (e.g., via a dedicated egress proxy) so a malicious mirror entry cannot be used for internal network reconnaissance.

### Proof of Concept
1. Attacker funds a spend bundle creating a coin with puzzle hash `MIRROR_PUZZLE_HASH` (`create_mirror_puzzle()` in `chia/wallet/db_wallet/db_wallet_puzzles.py`), memoized with `[victim_tracked_launcher_id, b"http://127.0.0.1:8080/admin"]` (or use the public `dl_new_mirror` RPC/CLI `chia data add_mirror -u http://127.0.0.1:8080/admin`).
2. Broadcast/confirm the spend; any node tracking `victim_tracked_launcher_id` observes the new coin in `coin_added()` and stores the mirror (`chia/data_layer/data_layer_wallet.py:775-800`).
3. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` copies the attacker URL into `data_store` subscriptions (`chia/data_layer/data_layer.py:979-985`), and `fetch_and_validate()`/`download_file()` issues an HTTP GET to `http://127.0.0.1:8080/admin` from the victim's own host (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:110-145`) — confirming outbound SSRF traffic driven entirely by attacker-supplied, unauthenticated memo data.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
