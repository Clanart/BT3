### Title
Unbounded chunk-row amplification via `chunk_size=1` in `send_citrea_tx` exhausts the Citrea DA queue — (`crates/clementine-tx-sender/src/client.rs`)

### Summary

The `send_citrea_tx` JSON-RPC handler accepts a caller-controlled `chunk_size` for `CitreaTxRequest::BatchProof`. The clamping logic only enforces an upper bound (`MAX_CHUNK_SIZE = 390,000`) and rejects zero, but imposes **no minimum**. A value of `1` passes through unclamped. Combined with the 50 MB request body limit, a single unauthenticated request can force ~52 million individual DB row insertions into `tx_sender_citrea_raw_tx_queue`, exhausting database storage and permanently blocking legitimate Citrea DA proof submissions.

### Finding Description

**Entry point — no authentication:**

The JSON-RPC server is a plain HTTP server with no authentication, API key, or mTLS: [1](#0-0) 

`MAX_JSONRPC_REQUEST_BODY_SIZE = 50 MB` is the only gate: [2](#0-1) 

**Missing minimum chunk size guard:**

In `send_citrea_tx`, `chunk_size` is clamped only from above and for zero: [3](#0-2) 

`chunk_size = 1` satisfies neither condition and passes through unchanged. With `bytes.len() = 52,428,800 > 1`, the chunking branch is taken: [4](#0-3) 

All ~52 million Borsh-wrapped 1-byte chunks are first collected into a `Vec<Vec<u8>>` in memory, then passed to `insert_citrea_raw_tx_chunks`.

**Unbounded DB insertion loop:**

`insert_citrea_raw_tx_chunks` inserts each chunk as a separate row in a sequential loop inside a single DB transaction: [5](#0-4) 

Chunk rows have `body_hash = NULL`, so they are **not subject to deduplication**. Only the aggregate row (one per unique `full_body_hash`) is deduplicated. An attacker using distinct payloads (different random bytes) can repeat this attack indefinitely, each time inserting ~52 million new rows.

**`MAX_CHUNK_SIZE` is only an upper bound, not a minimum:** [6](#0-5) 

The constant is defined to keep individual reveal transactions under the 400,000 WU standard limit — it was never intended to serve as a minimum chunk size guard.

### Impact Explanation

- **Memory exhaustion on the server process:** ~52 million `Vec<u8>` allocations (each ~10 bytes after Borsh wrapping) are materialized in RAM before any DB write, consuming ~500 MB+ per request.
- **Database storage exhaustion:** Each request inserts ~52 million rows into `tx_sender_citrea_raw_tx_queue`. At ~50 bytes per row, a single request writes ~2.5 GB. Multiple requests with distinct payloads multiply this linearly.
- **Bridge liveness disruption:** `get_citrea_txs_with_null_commit_outpoint` and related polling queries scan this table to find pending DA payloads. With millions of garbage rows, the queue is flooded, legitimate proof rows are buried, and the DA submission loop is effectively blocked.
- **Operator collateral at risk:** If operators cannot submit Citrea DA proofs on time due to queue exhaustion, they may miss challenge windows, exposing their collateral to slashing and preventing bridge users from completing withdrawals.

### Likelihood Explanation

The JSON-RPC server has no authentication. Any network-reachable party can send a single well-formed HTTP POST. The `CitreaTxRequest` type is public and serializable. The attack requires no privileged keys, no operator role, and no prior state — just network access and knowledge of the endpoint.

### Recommendation

1. **Enforce a minimum chunk size.** Add a lower bound check alongside the existing upper bound:
   ```rust
   const MIN_CHUNK_SIZE: u32 = 1024; // or a sensible floor
   if chunk_size < MIN_CHUNK_SIZE {
       chunk_size = MIN_CHUNK_SIZE;
   }
   ```
2. **Enforce a maximum `bytes` length for `BatchProof`.** Reject payloads whose `bytes` field exceeds a documented maximum (e.g., `MAX_CHUNK_SIZE * MAX_CHUNKS`), independent of the JSON-RPC body size limit.
3. **Add authentication to the JSON-RPC server.** Even a shared secret or IP allowlist would eliminate the unauthenticated attack surface.
4. **Cap the number of chunks before DB insertion.** Reject requests where `bytes.len() / chunk_size` exceeds a hard limit (e.g., 1,000 chunks).

### Proof of Concept

```rust

    citrea_tx_request: CitreaTxRequest::BatchProof {

    },
};

// Legitimate Citrea DA submissions: blocked
```
