### Title
Unbounded recursive puzzle-layer matching causes Python stack exhaustion on crafted deeply-nested puzzle reveals - (File: chia/wallet/outer_puzzles.py)

### Summary
The CVE-2016-4570 bug class is "stack consumption via crafted, deeply-nested tree input processed by an unbounded recursive tree walker" (`mxmlDelete` recursing over a crafted XML tree). Chia's wallet-side puzzle-driver framework has the same shape: `match_puzzle()` in `chia/wallet/outer_puzzles.py` dispatches to outer-puzzle drivers (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`) whose `match()` methods recursively call `self._match(UnknownPuzzle(known_program=inner_puzzle))` once per curried puzzle layer, with recursion depth directly controlled by the number of nested layers in an attacker-supplied `puzzle_reveal`/`PuzzleInfo`, and no depth limit is enforced anywhere in the chain. [1](#0-0) [2](#0-1) 

### Finding Description
`match_puzzle()` walks a `puzzle_reveal` by repeatedly uncurrying it and recursing into `_match()` for each successive inner layer, with each driver's `match()` unconditionally recursing into `self._match(UnknownPuzzle(known_program=inner_puzzle))` for any nested `also` puzzle: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`get_inner_puzzle()` and `get_inner_solution()` on these same drivers mirror this pattern (`self._get_inner_puzzle(also, ...)` / `self._get_inner_solution(also, ...)`), so the same crafted structure is walked recursively multiple times during coin-spend processing. [7](#0-6) 

A related unbounded recursive parser exists in the custody framework: `PuzzleWithRestrictions.from_memo()` recursively reconstructs nested `MofN` members from an attacker/counterparty-supplied memo with `[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]`, with no bound on nesting depth of the memo structure being parsed. [8](#0-7) 

None of these code paths use the iterative pattern that `chia/types/blockchain_format/tree_hash.py`'s `sha256_treehash()` explicitly adopts specifically "so we don't have to worry about blowing out the python stack" — that comment shows the project is aware of this exact hazard class for CLVM tree structures, but the awareness/mitigation was not applied to the outer-puzzle driver recursion or the custody memo parser. [9](#0-8) 

Because `Program`/`PuzzleInfo` nesting depth is attacker-controlled (a puzzle reveal can curry an arbitrary number of nested outer-puzzle layers, or a memo can encode arbitrarily deep `MofN` nesting), a wallet processing an untrusted coin spend, offer, or memo can be driven into a Python `RecursionError`, which is an uncaught exception that halts processing of that spend/offer/sync operation.

### Impact Explanation
This does not enable coin theft, inflation, or consensus divergence (the recursion is confined to Python wallet-side driver/memo parsing, not consensus block/mempool validation gated by CLVM cost). Its impact is a spend-triggered processing halt: a malicious offer counterparty, or a peer serving a crafted puzzle reveal during wallet sync, can cause an unhandled `RecursionError` in wallet code paths that call `match_puzzle()`/`get_inner_puzzle()`/`from_memo()`, disrupting wallet operation for that spend/offer. This matches the "spend-triggered transaction-processing halt" impact category, warranting Medium severity, consistent with the CVE-2016-4570 rating.

### Likelihood Explanation
Constructing deeply nested curried puzzles or nested `MofN` custody memos is cheap and entirely within the reach of an unprivileged offer counterparty or coin-spend author; no signature or special privilege is needed to create such structures, only for them to be presented to a victim wallet (e.g., via an offer file or coin_spend fetched from a peer/full node). Python's default recursion limit (~1000) is easily exceeded by a puzzle with a few hundred to a thousand nested layers, encoded compactly.

### Recommendation
Convert `match_puzzle`/driver `_match`/`_get_inner_puzzle`/`_get_inner_solution` chains and `PuzzleWithRestrictions.from_memo`'s `MofN` reconstruction to iterative (worklist/stack-based) traversal, mirroring the approach already used in `sha256_treehash()`. Additionally, enforce an explicit maximum nesting depth when parsing untrusted puzzle reveals or custody memos, rejecting structures that exceed it before recursing.

### Proof of Concept
Conceptually: construct a `Program` puzzle reveal by repeatedly currying an `also`-style outer puzzle (e.g., alternating `CAT_MOD`/`NFT_OWNERSHIP_LAYER` wrappers) around itself N times where N > Python's recursion limit (~1000), then submit it as a `CoinSpend`/offer to a victim wallet so it reaches `match_puzzle()` via `WalletStateManager`/`TradeManager`/offer-parsing code; the resulting call chain `match_puzzle -> Driver.match -> self._match(inner_puzzle) -> ...` recurses N times and raises `RecursionError`, halting the wallet's processing of that spend/offer. Equivalently, craft a `PuzzleWithRestrictions` memo with N nested `MofN` members and call `PuzzleWithRestrictions.from_memo()` on it to trigger the same unbounded recursion. [8](#0-7)

    def get_inner_puzzle(
        self, constructor: PuzzleInfo, puzzle_reveal: UnknownPuzzle, solution: Program | None = None
    ) -> Program | None:

            _, _, _, inner_puzzle = curried_args
            also = constructor.also()
            if also is not None:
                deep_inner_puzzle: Program | None = self._get_inner_puzzle(

    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")

        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]

        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)

            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)
