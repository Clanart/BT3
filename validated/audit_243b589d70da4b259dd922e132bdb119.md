### Title
`Scanner::scan_block` reports immature coinbase outputs as received funds that are not spendable — (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
The Debita bug class is an asset that is credited/committed to a contract while its backing can still be withdrawn afterward, leaving the recipient holding a worthless receipt. In `bitcoin-serai`, `Scanner::scan_block` scans the coinbase transaction and returns its outputs as ordinary `ReceivedOutput`s. Coinbase outputs are consensus-immature for 100 blocks, so Serai can report funds as received that cannot actually be spent — and that disappear entirely if the block is orphaned before maturity — exactly the "receipted value that evaporates" shape of the veAERO report.

### Finding Description
`Scanner::scan_transaction` iterates every output of a transaction and emits a `ReceivedOutput` for any `script_pubkey` matching a registered script, with no notion of coinbase maturity [1](#0-0) . `Scanner::scan_block` then iterates `block.txdata` starting at index 0, so the block's coinbase transaction is scanned like any other [2](#0-1) . A miner (or merged-mining pool) can pay the multisig's P2TR script in a coinbase; the scanner emits it indistinguishably from a normal, spendable output.

Nothing downstream distinguishes the result either: `ReceivedOutput` carries only `offset`, `output`, and `outpoint` [3](#0-2) , and `SignableTransaction::new` accepts any `Vec<ReceivedOutput>`, summing their values and committing them into `Prevouts::All` for the sighash [4](#0-3) [5](#0-4) . There is no maturity check anywhere in the crate; the only mitigation is a doc comment on `scan_block` noting a "post-processing pass is needed" if outputs must be immediately spendable [6](#0-5) . Since the emitted `ReceivedOutput` does not mark its coinbase origin, a caller cannot perform that pass without re-deriving which outpoints came from `block.txdata[0]`. The production processor compensates by manually skipping `block.txdata[1 ..]`'s predecessor in `get_outputs` [7](#0-6) , but the in-scope wallet API itself reports the immature output as received value.

### Impact Explanation
Two failure modes mirror the report:

1. A miner pays the multisig script in a coinbase, the deposit is credited/scanned, and the block is orphaned before coinbase maturity — the credited funds vanish, like the (m)veAERO NFT drained after being locked into the Loan. If the credited value was already acted on (e.g., included in a batch or used to size payments), the multisig is left accounting for value that no longer exists.
2. If the immature output is spent before maturity, `SignableTransaction` produces a transaction that full nodes reject as consensus-invalid, and the fee/other inputs' planned payments silently fail — funds reported spendable that are not.

### Likelihood Explanation
Low-to-moderate. It requires the multisig address to receive a coinbase payout (a miner directing payout to Serai's script, deliberately or via address reuse in pool config) and either a reorg within 100 blocks or the consumer spending the output early. No privileged position is needed beyond the ability to mine a block paying an arbitrary script. The crate fully enables the condition by emitting the immature output without any marker.

### Recommendation
In `Scanner::scan_transaction`/`scan_block`, either skip `txdata[0]` or annotate `ReceivedOutput` with an `is_coinbase`/maturity flag so consumers can exclude immature outputs; alternatively have `scan_block` internally skip the coinbase and offer a separate explicit API for it. Additionally, `SignableTransaction::new` could reject inputs whose outpoint txid corresponds to an unmatured coinbase where that information is available.

### Proof of Concept
On regtest: construct a `Scanner` for an even `key`, mine a block via `generatetoaddress` to `p2tr_script_buf(key)`, then call `scanner.scan_block(&block)` before mining the 100 maturity blocks. `scan_block` returns a `ReceivedOutput` for the coinbase output (as demonstrated in `networks/bitcoin/tests/wallet.rs` which only observes it after mining 100 maturity blocks) [8](#0-7) . Passing that `ReceivedOutput` to `SignableTransaction::new` yields a transaction spending an immature coinbase that `sendrawtransaction` rejects, and reorging the block before maturity removes the credited output entirely.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
