### Title
Identity public key is accepted by Schnorr verification, allowing trivial forgery for the “zero” signer - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
The Schnorr verifier treats the identity point as a normal public key. Because `Ciphersuite::read_G` accepts any canonical point and does not reject identity, an attacker can supply the identity encoding as the public key and then produce a valid `SchnorrSignature` for it by choosing `s` and setting `R = sG`. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrSignature::verify` checks `R + cA - sG == 0` via `batch_statements`, but it never validates that `public_key` is non-identity. [3](#0-2)  The canonical point reader accepts identity as a valid canonical point, so the “zero”/unset signer equivalent can enter verification as `A = identity`. [4](#0-3)  When `A` is identity, the verification equation degenerates to `R - sG == 0`, so any nonce-free forged pair `(R = sG, s)` verifies for any challenge/message bound to that identity key.

### Impact Explanation
This is a signature forgery for the identity public key. In any path where identity represents an absent, cleared, or “no current signer” key, the required approval is still satisfiable by an unprivileged party rather than being impossible or explicitly bypassed. That matches the zero-address signer class: the verifier still demands a signature from a zero-like principal, and that principal is trivially signable by anyone.

### Likelihood Explanation
Reachability requires a caller to accept a public key through canonical point decoding and then call `verify`/`batch_verify` with it. Those are public-input paths: `read_G` accepts the identity encoding, `SchnorrSignature::read` accepts the forged `(R, s)` pair when `R` is non-identity, and `verify` returns true. [5](#0-4)  The forged `R` can be made non-identity by using nonzero `s`, so identity-nonce rejection does not stop the attack.

### Recommendation
Reject identity public keys in `SchnorrSignature::verify` and `batch_verify`, or ensure every public key entering verification is parsed only through an API that rejects identity, such as the FROST `Curve::read_G` wrapper. [6](#0-5)  Separately, document that `Ciphersuite::read_G` admits identity and must not be used for signer/public-key decoding unless identity is explicitly meaningful.

### Proof of Concept
Let `A = identity` be produced by feeding the canonical identity encoding to `Ciphersuite::read_G`. Pick any nonzero scalar `s`; set `R = sG`, so `R` is non-identity. For the verifier’s challenge `c` bound to `(A, R, msg)`, verification computes:

`R + cA - sG = sG + c*0 - sG = 0`

Thus `multiexp_vartime(...).is_identity()` is true and `SchnorrSignature { R, s }.verify(A, c)` returns `true` for a key whose discrete logarithm is unknown/nonexistent. [7](#0-6)

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)

  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
