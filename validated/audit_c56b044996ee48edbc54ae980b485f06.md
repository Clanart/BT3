**Reasoning:**

`getAccountForRepository` intentionally selects the authenticated account by `gitHubRepository.endpoint` only, matching credentials to a *host*, not to a specific `owner/name` pair. [1](#0-0) 

This is the same pattern used elsewhere in the codebase, e.g. `getAccountForEndpoint`/`matchGitHubRepository`, since GitHub credentials authenticate per-host and actual repo-level authorization is enforced server-side by the GitHub API — not by the local account lookup. [2](#0-1) 

The premise that `_switchWorktree` can cause `gitHubRepository.endpoint` to change on the *same* repository record doesn't hold up: `RepositoriesStore.switchWorktree` explicitly carries over the original `repository.gitHubRepository` unchanged when updating `path`/`missing`/`gitDir`/`mainWorktreePath`. [3](#0-2) 

The only way a different `gitHubRepository` is returned is the path-collision branch, where the worktree path matches an *already separately-added* repository record in the local database — in that case the function correctly returns that pre-existing repository's own (correct) `gitHubRepository`, not an attacker-controlled or mismatched one. [4](#0-3) 

That collision requires a repository already registered locally by the legitimate user (not attacker-controlled repo content, API objects, links, or remote responses), and `_switchWorktree` in `app-store.ts` immediately calls `_selectRepository` with the *resolved* result, not the stale prop. [5](#0-4) 

In `add-worktree-dialog.tsx`, the dialog calls `dispatcher.switchWorktree(repository, worktree)` and then immediately dismisses itself without reusing the stale `repository` prop for any further authentication decision. [6](#0-5) 

There is no attacker-controlled path (per the defined scope) that lets an untrusted actor mutate `repository.gitHubRepository.endpoint` on a stale prop to redirect API authentication to an unauthorized account; the "swap the endpoint" proof idea requires direct in-memory/local-state tampering, which is out of scope, and even if achieved, actual repo access is still gated by GitHub's own server-side authorization for that account/token.

export function getAccountForRepository(
  accounts: ReadonlyArray<Account>,
  repository: Repository
): Account | null {
  const gitHubRepository = repository.gitHubRepository
  if (!gitHubRepository) {
    return null
  }

  return getAccountForEndpoint(accounts, gitHubRepository.endpoint)
}

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }
