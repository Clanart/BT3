### Title
Gasless module (KIP-247) forces users into unlimited ERC-20 approvals to the `GaslessSwapRouter`, exposing full token balances if the router contract is compromised - (File: kaiax/gasless/impl/getter.go)

### Summary
The `kaiax/gasless` module implements KIP-247 gasless transactions. Node-level consensus validation (`isApproveTx`) requires that a `GaslessApproveTx` grant an allowance equal to exactly `type(uint256).max` (`abi.MaxUint256`) to the whitelisted `GaslessSwapRouter` contract. Any approve transaction that specifies a bounded/exact amount is rejected as "not a gasless transaction," so an ordinary, unprivileged user who wants to use the gasless flow has no choice but to grant the router unlimited allowance over their ERC-20 token.

### Finding Description
`IsApproveTx`/`isApproveTx` enforce condition **A4**: `args.Amount.Cmp(abi.MaxUint256) == 0`, i.e., only a `type(uint256).max` approval counts as a valid gasless approve transaction: [1](#0-0) 

This condition is checked both when classifying a transaction (`IsApproveTx`) and when verifying tx-pool readiness/executability (`VerifyExecutable`, `checkBalanceForApprove`): [2](#0-1) [3](#0-2) 

The spender of this mandatory unlimited approval, `g.swapRouter`, is not fixed at compile time — it is read dynamically from an on-chain registry/multicall contract each block via `updateAddresses`/`getGaslessInfo`, meaning the "trusted" router address can be swapped (governance-controlled) over the chain's lifetime: [4](#0-3) 

The `GaslessSwapRouter` contract itself is an `Ownable`, mutable contract exposing owner-controlled functions (`transferOwnership`, `renounceOwnership`, `updateCommissionRate`, `removeToken`, `addToken`, `claimCommission`) alongside the user-facing `swapForGas`: [5](#0-4) 

Once a gasless user submits a valid `GaslessApproveTx`, their allowance to the router is set to `MaxUint256` on-chain (a normal `IERC20.approve` state change, not something bounded per-swap): [6](#0-5) 

Because this is enforced as a hard consensus/tx-pool rule (A4) rather than a client-side choice, users cannot opt for bounded approvals while still benefiting from gasless transactions — every legitimate gasless user is forced into an unlimited-approval posture toward a single, owner-controlled system contract.

### Impact Explanation
If the `GaslessSwapRouter` contract (or a future router registered via the on-chain registry) is ever compromised — through an owner-key compromise, an implementation bug, or a malicious governance-approved redeployment — any address that has ever submitted a `GaslessApproveTx` has an outstanding `MaxUint256` allowance on the affected ERC-20 token(s). This allows the compromised/malicious router to call `transferFrom` and drain the entire token balance of every gasless-flow user in a single transaction, rather than being bounded to the specific `amountIn` needed for a swap. This is a protocol-mandated version of the classic "infinite approval" risk: normal `transferFrom`-based DeFi flows usually only expose the swap amount, but here every gasless user is unconditionally exposed to full-balance theft.

### Likelihood Explanation
Every ordinary user of the gasless-transaction feature (an unprivileged, gasless swap user) is compelled by consensus-enforced rule A4 to grant this unlimited allowance; there is no alternative path to use KIP-247 gasless transactions with a bounded approval. The likelihood of the router being compromised is a separate concern (governance/ownership security), but the protocol design guarantees that if such a compromise occurs, the blast radius is every historical gasless approver's full token balance instead of the swap-specific amount.

### Recommendation
Avoid mandating `type(uint256).max` as the sole valid gasless-approve amount. Instead:
- Allow (and require) the `GaslessApproveTx` amount to be bounded to the actual `amountIn` needed for the paired `GaslessSwapTx` (or a small safety margin), and update `isApproveTx`/`VerifyExecutable` (`kaiax/gasless/impl/getter.go`) accordingly.
- If a fixed spender-wide allowance model is kept for UX reasons, consider a permit-based or per-swap signature scheme (e.g., EIP-2612 `permit`) so no persistent on-chain allowance is stored at all, removing the systemic drain risk if the router is ever compromised.

### Proof of Concept
1. A gasless user submits a `GaslessApproveTx` `approve(swapRouter, type(uint256).max)`. Under current rules this is the *only* form of approve that `isApproveTx` accepts (kaiax/gasless/impl/getter.go:79-86), so the tx pool promotes it and it is included in a block, setting `allowance(user, swapRouter) = MaxUint256`.
2. Governance/registry later updates or the owner of `GaslessSwapRouter` is compromised (`transferOwnership`/malicious redeploy registered via the on-chain registry, read each block by `updateAddresses`).
3. The compromised/malicious router calls `token.transferFrom(user, attacker, token.balanceOf(user))` for any user from step 1 — succeeding because the stored allowance is `MaxUint256`, draining the user's entire token balance instead of only the amount that would have been needed for their gasless swap.

// A1. tx.to is a whitelisted ERC20 token.

func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}
