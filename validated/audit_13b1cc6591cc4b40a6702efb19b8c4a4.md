## Title
`isGitHubHost` regex naively classifies attacker-controlled hostnames like `github.<attacker>.com` as GitHub Enterprise, triggering credential-helper GitHub sign-in against the attacker's host - (File: `app/src/lib/api.ts`)

### Summary
Just as the Sherlock report shows a hard-coded mainnet constant silently substituting for a variable, chain-specific value, GitHub Desktop's `isGitHubHost` heuristic hard-codes a naive substring/regex pattern — `/(^|\.)(github)\./` — as a stand-in for "this is a real GitHub Enterprise instance." An attacker can register any hostname that satisfies this pattern (e.g. `github.attacker.com`, `x.github.attacker.io`) without owning `github.com`, `*.ghe.com`, or running real GitHub Enterprise Server software, and the check will misclassify the host as trustworthy.

### Finding Description
`isGitHubHost` in `app/src/lib/api.ts` is used by the credential-helper flow (`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`) to decide whether a remote host Git is talking to should be treated as `'enterprise'` (a GitHub host) or `'generic'` (any other git host): [1](#0-0) 

The check order is:
1. `isDotCom` / `isGHE` — legitimate, address-based checks against `api.github.com`/`github.com`/`*.ghe.com`.
2. `isKnownThirdPartyHost` — a hard-coded denylist of specific SaaS domains (`gitlab.com`, `bitbucket.org`, `dev.azure.com`, `amazonaws.com`, `visualstudio.com`).
3. **The vulnerable step**: `/(^|\.)(github)\./.test(hostname)` — if the hostname *starts with* `github.` or contains `.github.` anywhere, the function immediately returns `true`, completely bypassing the later network-based verification (`/meta` request checking for the `x-github-request-id` header) that would otherwise catch a spoofed host.

Because the regex only checks for the literal substring `github.` bounded by `^` or `.`, any attacker-registered domain such as `github.attacker.com`, `my.github.attacker.io`, or `github.company-that-is-not-real.com` satisfies it trivially. This is exactly analogous to the WETH bug: a hard-coded constant/pattern that is correct only for the "mainnet" case (real `github.com`/`*.github.com` corporate GHES installs) is blindly reused for an attacker-influenced input (an arbitrary git remote hostname), with no assertion that the "chain" (i.e., the actual host) really is what the constant assumes.

`getEndpointKind` uses the result of this classification to decide how to handle Git credential requests for a remote: [2](#0-1) 

If `endpointKind !== 'generic'` and no stored account matches the endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then launches either the dotcom or "Enterprise" GitHub OAuth/PAT sign-in flow **targeting the attacker's endpoint** (since `hostname !== 'github.com'` it takes the enterprise branch and calls `setSignInEndpoint(origin)` with the attacker's origin): [4](#0-3) 

The existing guards do not stop this path:
- `isDotCom`/`isGHE` only check for the real `github.com`/`ghe.com` domains, so they don't catch `github.attacker.com`.
- `isKnownThirdPartyHost` is a denylist of specific known third-party SaaS hosts; it has no knowledge of the attacker's arbitrary domain.
- The subsequent network probe to `/meta` (checking for `x-github-request-id`) — which is the actual verification step meant to catch spoofed hosts — is **never reached** for hostnames matching the regex, because the function returns `true` early on line 2453.

### Impact Explanation
A user who adds/clones a repository from, or is redirected via a crafted deep link/PR reference to, a remote whose hostname matches the naive pattern (`github.<attacker-domain>`) will have Desktop present a "GitHub sign-in" (OAuth or PAT) dialog whose destination is the attacker's server, dressed up with GitHub-branded sign-in UI. Because Desktop itself decided this is a "GitHub host" (`enterprise` classification) rather than a "generic git host," the user is given false assurance and is funneled into Desktop's built-in GitHub credential flow instead of the more suspicious-looking generic-git-auth prompt, increasing the likelihood a user provides a Personal Access Token or completes an OAuth Enterprise flow against the attacker-controlled origin — leading to credential/token exfiltration to a host the attacker controls. This matches the "unauthorized OAuth" / "credential exfiltration" categories in the accepted impact list.

### Likelihood Explanation
Likelihood is medium: the attacker fully controls the choice of hostname (registering any domain containing `github.` as a labeled component) and can plant it as a git remote URL, a PR head/base repo URL, or a "Open in Desktop" deep link (`x-github-client://openRepo?url=...`) — all of which are attacker-influenced inputs per the accepted threat model. No local access, admin rights, or pre-existing malware is required; the only user action is the ordinary act of opening/cloning the crafted repository URL that Desktop is designed to accept.

### Recommendation
Remove the naive `/(^|\.)(github)\./` short-circuit (and the `bitbucket|gitlab` negative-match) from `isGitHubHost`, or at minimum do not let it bypass the actual verification step. Always fall through to the authenticated `/meta` network probe (checking for the `x-github-request-id` response header) before classifying an unknown host as GitHub, and never treat hostname substring matches as proof of GitHub Enterprise identity. If a fast-path heuristic is desired, gate it as a hint that only *shortens* the timeout for the verification request rather than skipping the request entirely.

### Proof of Concept
1. Attacker registers `github.attacker.com` and stands up an arbitrary HTTP server (no need to emulate the real `/meta` endpoint or `x-github-request-id` header, since the code path never reaches that check).
2. Attacker crafts a git remote URL / PR / deep-link referencing `https://github.attacker.com/owner/repo`.
3. Victim opens/clones this in GitHub Desktop; a Git credential request comes in for `github.attacker.com`.
4. `getEndpointKind` → `isGitHubHost('https://github.attacker.com')`:
   - `isDotCom`/`isGHE` return `false`.
   - `isKnownThirdPartyHost('github.attacker.com')` returns `false` (not in the denylist).
   - `/(^|\.)(github)\./.test('github.attacker.com')` → `true` (matches at `^`), function returns `true` immediately — no network verification performed.
5. `getEndpointKind` returns `'enterprise'`.
6. `getCredential` finds no matching stored account, calls `ui.promptForGitHubSignIn('https://github.attacker.com')`.
7. `promptForGitHubSignIn` sees `hostname !== 'github.com'`, calls `beginEnterpriseSignIn` and `setSignInEndpoint('https://github.attacker.com')`, showing the user a "Sign in to GitHub Enterprise" dialog pointed at the attacker's server.
8. Any credentials/PAT/OAuth code the user submits are sent to the attacker's origin.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
