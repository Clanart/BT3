### Title
Unattributed payout OP_RETURN lets an attacker fraudulently credit an uninvolved operator, allowing it to be reimbursed for a payout it never funded - (File: core/src/verifier.rs)

### Summary
`Verifier::update_finalized_payouts` credits whichever `XOnlyPublicKey` appears in the payout transaction's first `OP_RETURN` output as the "payer operator" for a withdrawal, with no check that this operator actually supplied any funds to the payout transaction. Because the withdrawal input is signed by the user with `SinglePlusAnyoneCanPay`, the user (attacker) fully controls the rest of the transaction — including the `OP_RETURN` — and can self-fund the payout while naming an arbitrary, uninvolved operator as payer, causing that operator's automated `PayoutCheckerTask` to claim reimbursement from the deposit's move-to-vault funds for a payout it never made.

### Finding Description
The broken binding is: `operator_credited(withdrawal_idx) == operator_that_funded_payout(withdrawal_idx)`.

- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with the withdrawal UTXO as input (signed `KeySpend` by the user), a user-payout output, an anchor, and an `OP_RETURN` embedding `operator_xonly_pk`.
- The user's signature only needs `SinglePlusAnyoneCanPay` (see `core/src/test/common/setup_utils.rs:529-540`, `core/src/operator.rs:630-637`), which by Bitcoin's sighash rules commits only to the withdrawal input and the output at the same index — the `OP_RETURN` output and any extra funding inputs are **not** covered by this signature and can be added/rewritten by anyone who possesses the withdrawal input's signature, i.e., the withdrawing user themself.
- Withdrawal registration is entirely attacker-controlled: `update_citrea_deposit_and_withdrawals` (`core/src/verifier.rs:2248-2262`) stores whatever `withdrawal_utxo_outpoint` Citrea reports for the given `idx`, and this UTXO belongs to the withdrawing user.
- `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`) identifies "the" payout tx purely by which transaction spent the registered `withdrawal_utxo_txid/vout` — there is no requirement that this spending transaction was constructed or funded by any operator.
- `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) then blindly extracts the operator pubkey via `get_first_op_return_output` + `parse_op_return_data` (`circuits-lib/src/bridge_circuit/mod.rs:608-617,686-692`) from whatever transaction spent that UTXO, and persists it via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:199-251`) with **no signature/ownership check tying that operator to the actual funding inputs**.
- The falsely-named operator B's own node then discovers this via `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) in `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-111`), automatically calling `handle_finalized_payout` (`core/src/operator.rs:839-885`) to start its kickoff and claim reimbursement.
- The only sanity check before reimbursement, `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`), only checks that the DB-recorded `operator_xonly_pk` matches the kickoff sender's own key and that the committed payout blockhash matches — both trivially hold here since B is honestly sending its own kickoff using the (falsely) attributed DB record. Nothing checks that B's wallet actually contributed value to the payout transaction.
- `validate_payer_is_operator` (`core/src/operator.rs:1687-1740`) and `get_reimbursement_txs`/`create_reimburse_txhandler` (`core/src/operator.rs:2098-2150`, `core/src/builder/transaction/operator_reimburse.rs:341-385`) then let B collect the deposit's move-to-vault funds via the pre-signed N-of-N reimburse path, which is generic infrastructure created at deposit time for every possible operator, not tied to actual funding of a specific payout.

### Impact Explanation
An attacker who withdraws to themselves (self-funding the payout output, at no net cost beyond the transaction fee) can attribute the payout to any current, uninvolved operator by forging the `OP_RETURN`. That operator's automation then drains the deposit's move-to-vault collateral through the standard kickoff → reimburse flow, receiving BTC it never fronted. This is exactly the listed Critical impact "an operator reimbursed for a payout it never funded" and simultaneously "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal," since no operator ever paid the withdrawing user. The attack is repeatable per withdrawal/deposit and against any operator whose `XOnlyPublicKey` is public (all operators' keys are public via `fetch_operator_keys`, see `core/src/rpc/aggregator.rs:1859`).

### Likelihood Explanation
Preconditions are minimal and fully within the declared unprivileged attacker capability: deposit BTC, register/withdraw on Citrea with a self-controlled UTXO and self-crafted `SinglePlusAnyoneCanPay` signature, then broadcast a self-authored payout transaction directly to Bitcoin (bypassing all operator/aggregator RPCs) with an `OP_RETURN` naming an arbitrary operator. No majority hashrate, key compromise, or privileged role is required — only normal transaction fees and the withdrawal amount (which the attacker recovers to themselves in the same transaction).

### Recommendation
Do not trust an unauthenticated `OP_RETURN` value as attribution of who funded a payout. Require cryptographic proof that the named operator actually contributed to the payout transaction — e.g., require the operator to co-sign the payout transaction (so their own signature/input is present and verifiable), or otherwise bind the `OP_RETURN` operator claim to a signature produced by that operator's key over the exact finalized transaction, verified in `update_finalized_payouts` before crediting `payout_payer_operator_xonly_pk`.

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

/// Creates a [`TxHandler`] for the `payout_tx`.
///
/// This transaction is sent by the operator to front a peg-out, after which operator will send a kickoff transaction to get reimbursed.
///
/// # Inputs
/// 1. UTXO: User's withdrawal input (committed in Citrea side, with the signature given to operators off-chain)
///
/// # Outputs
/// 1. User payout output
/// 2. OP_RETURN output (with operators x-only pubkey that fronts the peg-out)
///
/// # Arguments
/// * `input_utxo` - The input UTXO for the payout, committed in Citrea side, with the signature given to operators off-chain.
/// * `output_txout` - The output TxOut for the user payout.
/// * `operator_xonly_pk` - The operator's x-only public key that fronts the peg-out.
/// * `user_sig` - The user's signature for the payout, given to operators off-chain.
/// * `network` - The Bitcoin network.
///
/// # Returns
/// A [`TxHandler`] for the payout transaction, or a [`BridgeError`] if construction fails.
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

            .operator

                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later

            .operator

            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }

    pub async fn get_reimbursement_txs(

                    kickoff_txid,
                    current_round_idx,

                let round_idx_after_operations =

                if round_idx_after_operations != current_round_idx {
                    current_round_idx = round_idx_after_operations;
                    continue;
                }
            }
            break;
        }

        Ok(txs_to_send)

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}

/// Computes a deposit constant hash using various transaction and cryptographic components.
///
/// # Parameters
///
/// - `operator_xonlypk`: A 32-byte array representing the operator's X-only public key.
/// - `watchtower_challenge_connector_start_idx`: A 16-bit unsigned integer marking the start index of the watchtower challenge connector.
/// - `watchtower_pubkeys`: A slice of 32-byte arrays representing tweaked watchtower public keys.
/// - `move_txid`: A 32-byte array representing the transaction ID of the move transaction.
/// - `round_txid`: A 32-byte array representing the transaction ID of the round transaction.
/// - `kickoff_round_vout`: A 32-bit unsigned integer indicating the vout of the kickoff round transaction.
/// - `genesis_state_hash`: A 32-byte array representing the genesis state hash.
///
/// # Returns
///
/// A `DepositConstant` containing a 32-byte SHA-256 hash of the concatenated input components.
pub fn deposit_constant(
    operator_xonlypk: [u8; 32],
    watchtower_challenge_connector_start_idx: u32,
    watchtower_pubkeys: &[[u8; 32]],
    move_txid: [u8; 32],
    round_txid: [u8; 32],
    kickoff_round_vout: u32,
    genesis_state_hash: [u8; 32],
) -> DepositConstant {
    // pubkeys are 32 bytes long
    let pubkey_concat = watchtower_pubkeys
        .iter()
        .flat_map(|pubkey| pubkey.to_vec())
        .collect::<Vec<u8>>();

    let watchtower_pubkeys_digest: [u8; 32] = Sha256::digest(&pubkey_concat).into();

    let pre_deposit_constant = [
        &move_txid,
        &watchtower_pubkeys_digest,
        &operator_xonlypk,
        &watchtower_challenge_connector_start_idx.to_be_bytes()[..],
        &round_txid,
        &kickoff_round_vout.to_be_bytes()[..],
        &genesis_state_hash,
    ]
    .concat();

    DepositConstant(Sha256::digest(&pre_deposit_constant).into())
}

pub fn journal_hash(
    payout_tx_blockhash: PayoutTxBlockhash,
    latest_blockhash: LatestBlockhash,
    challenge_sending_watchtowers: ChallengeSendingWatchtowers,
    deposit_constant: DepositConstant,
) -> blake3::Hash {
    let concatenated_data = [
        payout_tx_blockhash.0,
        latest_blockhash.0,
        challenge_sending_watchtowers.0,
    ]
    .concat();

    let binding = blake3::hash(&concatenated_data);
    let hash_bytes = binding.as_bytes();

    let concat_journal = [deposit_constant.0, *hash_bytes].concat();

    blake3::hash(&concat_journal)
}
