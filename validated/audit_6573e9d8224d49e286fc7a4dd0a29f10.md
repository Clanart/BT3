### Title
Denial of Service via out-of-bounds slice index when validating malformed auction bid signatures - (File: kaiax/auction/bid.go)

### Summary
The auction bid signature verification helper `getSigner` in `kaiax/auction/bid.go` indexes into the caller-supplied `SearcherSig`/`AuctioneerSig` byte slices without first checking their length, causing a runtime panic (slice bounds out of range) when a bid with a malformed/short signature is submitted. This mirrors the CWE-190/invalid-index crash class from the Bytom advisory (`checkTopicRegister` not validating an index before array access), but reachable here via a public, unprivileged auction bid submission path rather than p2p discovery.

### Finding Description
`getSigner` unconditionally accesses fixed offsets of the `sig` parameter: [1](#0-0) 

```go
func getSigner(sig, digest []byte) (common.Address, error) {
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}
	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	...
```

There is no length check (e.g., `len(sig) != 65`) before indexing `copiedSig[crypto.RecoveryIDOffset]` or slicing `copiedSig[0:32]` / `copiedSig[32:64]`. If `sig` is `nil`, empty, or shorter than 65 bytes, this line panics with "index out of range" or "slice bounds out of range."

This function is called from `Bid.ValidateSearcherSig` and `Bid.ValidateAuctioneerSig`: [2](#0-1) 

Both `SearcherSig` and `AuctioneerSig` are attacker-controlled fields of the `BidData` structure submitted by any searcher/bidder: [3](#0-2) 

Looking at `validateBid` in the bid pool (the entry point for admitting a submitted bid into the auction pool), the validation order performs several structural checks (block number range, bid value, data size, gas limit) and only afterwards calls `validateBidSigs`, which in turn calls into `ValidateSearcherSig`/`ValidateAuctioneerSig` and ultimately `getSigner`: [4](#0-3) 

None of the preceding checks validate the length of `SearcherSig` or `AuctioneerSig`. As a result, a bid with a short/empty signature field passes all prior checks and reaches the unguarded index/slice operations in `getSigner`, causing a panic.

### Impact Explanation
A panic inside the bid validation path run for every incoming/gossiped auction bid can crash or take down the node process (or at minimum the goroutine handling bid validation) if not recovered at a higher layer, denying service to the auction module and potentially the whole node process depending on whether a `recover()` wraps this call chain. This satisfies CWE-190-style "insufficient validation before indexed access leading to crash," analogous to the Bytom `checkTopicRegister` advisory, but the trigger here is a fully unprivileged, remotely reachable action (submitting an auction bid), not a malicious peer/discovery message — which is within the specified scope (auction bidder path).

### Likelihood Explanation
High likelihood: any external, unauthenticated party that can submit or relay an auction bid (via the auction bid submission RPC/gossip path feeding `BidPool.validateBid`) can trivially craft a `BidData` with `SearcherSig` or `AuctioneerSig` set to `nil` or fewer than 65 bytes. No cryptographic material or special privilege is required to trigger the panic — only a syntactically valid bid struct with a malformed signature field.

### Recommendation
Add an explicit length check at the start of `getSigner` (and/or before calling it in `ValidateSearcherSig`/`ValidateAuctioneerSig`), rejecting any signature whose length is not exactly 65 bytes (`crypto.SignatureLength`) with a proper error instead of allowing the code to index into it. Additionally, verify whether the bid-processing goroutines in `kaiax/auction/impl/bid_pool.go` (e.g., `handleBidMsg`, `handleNewBid`, or the RPC submission handler) wrap bid validation in a `recover()`; if not, add one as defense-in-depth, but the primary fix should be strict input length validation before any indexing.

### Proof of Concept
1. Craft a `BidData` (or equivalent RPC/gossip payload) with valid-looking fields (`BlockNumber` within `[currentBlockNumber+1, currentBlockNumber+allowFutureBlock]`, `Bid > 0`, `Data` within size limit, `CallGasLimit` within limit) but set `SearcherSig` to an empty byte slice (or fewer than 65 bytes), and any value for `AuctioneerSig`.
2. Submit this bid through the auction module's bid ingestion path so it reaches `BidPool.validateBid` → `validateBidSigs` → `Bid.ValidateSearcherSig` → `getSigner`.
3. Execution reaches `copiedSig[crypto.RecoveryIDOffset]` in `kaiax/auction/bid.go` line 145, which panics with "index out of range" because `copiedSig` (a clone of the empty/short `SearcherSig`) has fewer bytes than `crypto.RecoveryIDOffset + 1`.
4. If the calling goroutine/RPC handler lacks a `recover()`, this panic propagates and crashes the node process (or the bid-processing goroutine), denying auction service.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}
