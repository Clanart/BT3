### Title
Unbounded Python recursion through nested "also"-chained outer-puzzle drivers can crash offer/wallet processing on attacker-supplied puzzle reveals - (File: chia/wallet/outer_puzzles.py, chia/wallet/cat_wallet/cat_outer_puzzle.py, chia/wallet/nft_wallet/singleton_outer_puzzle.py, chia/wallet/nft_wallet/ownership_outer_puzzle.py, chia/wallet/nft_wallet/metadata_outer_puzzle.py, chia/wallet/vc_wallet/cr_outer_puzzle.py)

### Summary
CVE-2018-7337 is a Wireshark DOCSIS dissector crash caused by unbounded recursion while parsing attacker-controlled, arbitrarily-nested concatenated PDUs; the fix replaced the recursive algorithm with an iterative one. Chia's own codebase explicitly recognizes this bug class: `sha256_treehash()` in [1](#0-0)  is deliberately implemented as an iterative stack machine "so we don't have to worry about blowing out the python stack" on deeply nested CLVM structures, and the architecture notes reiterate this contract explicitly. [2](#0-1) 

However, the "outer puzzle driver" machinery used to recognize CAT / singleton / NFT ownership / NFT metadata / credential-restricted (CR) layers does the opposite: `match()`, `get_inner_puzzle()`, and `get_inner_solution()` recurse once per "also"-chained layer of an attacker-supplied puzzle, with no depth limit.

### Finding Description
`match_puzzle()` in [3](#0-2)  dispatches to each registered driver (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`) to identify the outer puzzle "layers" of an untrusted `UnknownPuzzle`.

Each of these drivers implements `match()` by recursively calling itself on the inner puzzle whenever it recognizes its own mod hash:
- `CATOuterPuzzle.match()`: [4](#0-3) 
- `SingletonOuterPuzzle.match()`: [5](#0-4) 
- `OwnershipOuterPuzzle.match()`: [6](#0-5) 
- `MetadataOuterPuzzle.match()`: [7](#0-6) 
- `CROuterPuzzle.match()`: [8](#0-7) 

Each `match()` recognizes its own curried mod, extracts the "inner_puzzle" argument, and calls `self._match(UnknownPuzzle(known_program=inner_puzzle))`, which is bound back to the top-level `match_puzzle()` dispatcher. Because `puzzle.curry()` allows arbitrary nesting (curry a CAT puzzle whose inner puzzle is itself a CAT puzzle, whose inner puzzle is itself a CAT puzzle, etc. — this is exactly how nested/wrapped CATs, e.g. RCAT-on-CAT or repeated CAT layers, are legitimately built via `construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)` as shown in [9](#0-8) ), an attacker who fully controls a puzzle reveal can construct a puzzle with thousands of nested nested-CAT (or metadata/ownership) layers. Since each layer costs only a small, cheap CLVM `curry()` wrap, this is computationally trivial to construct off-chain and does not require actually spending a coin on-chain in the CAT-nesting case — the puzzle need only be handed to a wallet as an `UnknownPuzzle` for matching (e.g. via an untrusted **offer** file). The mirrored `get_inner_puzzle()` recursion exists identically in each driver and is invoked from `chia/wallet/outer_puzzles.py` line 65-68.

`chia/wallet/trading/offer.py` imports and relies on `match_puzzle`, `get_inner_puzzle`, and `get_inner_solution` from `chia/wallet/outer_puzzles.py` (imports at lines 29-36) to parse offer files' asset drivers (`driver_dict: dict[bytes32, PuzzleInfo]`). Offer files are attacker-supplied artifacts exchanged between untrusted counterparties before any spend is broadcast, so a maliciously crafted offer containing a puzzle with a very deep nested-CAT/metadata/ownership `also` chain will drive unbounded Python recursion in the recipient wallet's offer-parsing code path when the wallet calls into `match_puzzle`/`get_inner_puzzle` to identify the driver stack for that asset.

CPython's default recursion limit (~1000 frames) means a puzzle with on the order of a few hundred to a thousand nested layers (each `match()` call itself does several nested Python calls, e.g. `_match` -> uncurry -> etc.) is sufficient to trigger a `RecursionError`. Unlike `sha256_treehash`, which Chia deliberately hardened against this exact failure mode, these outer-puzzle drivers were not hardened, leaving a class of bug directly analogous to the Wireshark DOCSIS recursive-PDU crash: attacker-controlled nesting depth driving unbounded native-stack/interpreter-stack recursion during parsing of untrusted structured input.

### Impact Explanation
An attacker (any offer counterparty, or any wallet client processing on-chain CAT/NFT/CR coin data during sync) can supply a puzzle reveal with deep "also"-chain nesting. When the victim wallet processes this via `match_puzzle()`/`get_inner_puzzle()` (offer parsing, NFT wallet coin recognition `chia/wallet/nft_wallet/nft_wallet.py`, or CR-CAT syncing paths), it triggers uncontrolled Python recursion and a `RecursionError`, crashing or hanging that processing path — a spend/offer-triggered transaction-processing halt for wallet clients, matching the "Reject... no-impact... Accept only... spend-triggered transaction-processing halt" acceptance bar in this assessment. This is a remotely-triggerable denial of service against wallet users and offer counterparties without requiring any signature, funds, or privileged access — only a crafted puzzle reveal.

### Likelihood Explanation
Likelihood is high for wallet-to-wallet exposure: offer files are explicitly designed to be exchanged between mutually untrusted parties before any chain interaction occurs, and `Offer` parsing directly depends on the vulnerable recursive matching code. Constructing a deeply nested CAT/metadata/ownership puzzle is computationally cheap (pure Python/CLVM curry operations, no signing or on-chain cost required to create the offer artifact). The exact number of `also` layers needed to exhaust the recursion limit was not empirically verified in this review (no code execution available), so the precise minimum nesting depth is an estimate based on CPython's default recursion limit and the multiple stacked Python calls per `match()` invocation — this should be confirmed by a background agent capable of running the code.

### Recommendation
Convert the recursive `match()`, `get_inner_puzzle()`, `get_inner_solution()`, `construct()`, and `solve()` traversal in `chia/wallet/outer_puzzles.py` and each outer-puzzle driver (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`, and any others implementing the same "also" pattern such as `PuzzleWithRestrictions.from_memo()`/`fill_in_unknown_puzzles()` in `chia/wallet/puzzles/custody/custody_architecture.py`) to an iterative, stack-based traversal similar to `sha256_treehash()`, or explicitly bound recursion depth (e.g., cap total "also" layers to a small constant, such as the number of legitimate outer-puzzle types) and raise a controlled error instead of allowing unbounded native recursion. Apply the same treatment anywhere offer/puzzle-reveal parsing walks attacker-controlled curried structures.
