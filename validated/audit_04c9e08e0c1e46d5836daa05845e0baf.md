Based on the code evidence, there's a real analog in `pallet-consensus-incentives`'s reward-calculation logic, where a default-zero baseline (structurally identical to the LST report's default-zero `discountTimestampByPercent`) causes an incorrect delta calculation — but here it inflates a payout rather than suppressing one.

### Title
First-ever consensus reward for a state machine mints a payout for its entire historic block span instead of the delta since incentivization began - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`calculate_reward` computes `blocks = latest_height - baseline`, where `baseline` falls back to `previous_commitment_height(...).unwrap_or_default()` (i.e. `0`) when `LastRewardedHeight` has never been set for that `state_machine_id`. This mirrors the reported bug class exactly: an accounting array/value that is implicitly zero-initialized (rather than initialized to a meaningful reference point at "activation time") gets fed into a difference calculation, producing a result many orders of magnitude larger (or smaller) than intended.

### Finding Description
In `Pallet::<T>::calculate_reward` [1](#0-0) , the baseline height used to size a relayer's reward is:

```
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`previous_height` itself comes from `host.previous_commitment_height(...).unwrap_or_default()`, and `previous_commitment_height` is backed by `PreviousStateMachineHeight::<T>::get(id)` [2](#0-1) , which is only populated the *first* time `store_latest_commitment_height` runs for that `id` — and even then it's set from `LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default()` [3](#0-2) . So for a state machine's very first consensus update ever processed on Hyperbridge, both `PreviousStateMachineHeight` and `LastRewardedHeight` are unset, and `baseline` resolves to the storage default `0` — not "the height at which this chain was registered/first tracked."

If the chain being bridged already has a large height when it is first onboarded to Hyperbridge (e.g. an existing chain's consensus client added at height 5,000,000), the very first `on_executed` reward computation pays `blocks_as_balance = latest_height - 0 = 5,000,000` blocks worth of `block_cost`, all at once, to whichever relayer happened to submit that first consensus message.

### Impact Explanation
`process_message` unconditionally transfers the computed reward from the treasury to the relayer's account via `T::Currency::transfer(&T::TreasuryAccount::get()..., &relayer_account, reward, ...)` [4](#0-3) . Because the reward for the first update on a newly-tracked (or previously-untracked/never-rewarded) state machine is sized by `latest_height - 0` rather than by the actual number of new blocks the relayer's proof advanced, this is a direct treasury-fund-drain vector: an unprivileged relayer submits one valid consensus proof for a chain's current (already-high) height and is paid as if they delivered every block since genesis. This is a genuine "unauthorized/incorrect transfer of funds" impact matching the bounty's reward-claim category — no malicious peer, prover, or governance actor is required; it only needs a normal relayer submitting the first legitimate consensus update for a chain whose `block_cost` has been configured by governance (an expected, non-privileged operational step, not an admin exploit).

### Likelihood Explanation
This triggers deterministically, not probabilistically, any time `update_cost_per_block` is set for a state machine before or shortly after its first consensus update lands (or more generally, whenever `LastRewardedHeight`/`PreviousStateMachineHeight` are unset while `latest_height` is already non-trivial — including scenarios where the pallet is added to a runtime upgrade for chains that are already live and mid-height). The existing regression test `reward_covers_only_unpaid_heights_after_rollback` [5](#0-4)  only covers the *rollback* scenario where `PreviousStateMachineHeight` already holds a stale-but-nonzero pointer; it does not cover the cold-start case where both storages are entirely empty and `latest_height` is already large, so this path is untested and unguarded.

### Recommendation
Track an explicit `IncentivizationStartHeight` (or equivalent) per `state_machine_id`, set exactly once when the state machine is first configured for rewards (e.g. in `update_cost_per_block` when no prior config exists), and use that as the true baseline instead of falling back to `0`/`unwrap_or_default()`. Reject or clamp reward computation when neither `LastRewardedHeight` nor an explicit start-height marker exists, rather than silently defaulting to height zero.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, block_cost)` for a state machine whose consensus client is being onboarded — no prior `PreviousStateMachineHeight`/`LastRewardedHeight` entries exist.
2. A relayer submits the first valid `ConsensusMessage` for that state machine, and the consensus client reports `latest_commitment_height = H` where `H` is already large (e.g. the chain's real current block height at onboarding time, or simply a state machine that accumulated blocks before incentives were turned on).
3. `store_latest_commitment_height` sets `PreviousStateMachineHeight = 0` (via `unwrap_or_default`) and `LatestStateMachineHeight = H` [3](#0-2) .
4. `on_executed` → `process_message` → `calculate_reward` computes `baseline = LastRewardedHeight::get().unwrap_or(previous_height) = 0`, so `blocks = H - 0 = H` [6](#0-5) .
5. `reward = H * block_cost` is transferred from the treasury to the relayer in a single call, even though the relayer only proved one incremental consensus update, not `H` blocks of delivery.

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
