### Title
Self-triggered `VLMGP.cancelUnlock()` before `getReward()` lets a locker fully bypass the cooldown reward-forfeiture mechanism - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`_calExpireForfeit` computes the forfeit fraction of a user's bonus rewards by calling `vlMGP.getRewardablePercentWAD(_account)` at the *current* block, not from a historical, time-weighted snapshot of the user's cooldown state during the accrual period. Because `getRewardablePercentWAD` only counts `amountInCoolDown` while a slot is still active, a user who is mid-cooldown can call `cancelUnlock()` (which zeroes `amountInCoolDown` for that slot) immediately before `getReward()`, forcing `getRewardablePercentWAD` to return `1e18` and `forfeitAmount` to be `0`, even though real rewards accrued while the user was in cooldown.

### Finding Description
- `getRewardablePercentWAD` in `VLMGP.sol` (and the mirrored `mWomSV.sol`) computes the rewardable percent purely from the account's *current* `fullyInLock`/`inCoolDown` split and the current active `userUnlockings` slots: [1](#0-0) 
- `cancelUnlock()` is a `whenNotPaused`-only function (no time-lock, no penalty, no `onlyOwner`) that any locker can call at will while a slot's `endTime > block.timestamp`, and it sets `slot.amountInCoolDown = 0`: [2](#0-1) 
- `vlMGPBaseRewarder._sendReward` and `_calExpireForfeit` fetch the rewardable percent at call time and compute the forfeit against the user's full accrued `userRewards` balance: [3](#0-2) 
- Reward accrual itself (`_earned`/`rewardPerToken`) is based on `balanceOf(_account) = getUserTotalLocked + getUserAmountInCoolDown`, i.e., cooldown-locked tokens accrue the *same* rewards as fully-locked tokens: [4](#0-3) 
- The intended design is that during cooldown a user should forfeit a time-weighted portion of newly accrued bonus rewards (as encoded by the `else` branch in `getRewardablePercentWAD` for still-in-cooldown slots, and the linear ramp for fully-unlocked-but-unclaimed slots). Since the check is stateless with respect to history (it only looks at whatever unlock slots currently have `amountInCoolDown > 0`), a user can erase this history at will by calling `cancelUnlock()` right before `getReward()`. This resets the slot to `amountInCoolDown == 0`, which is excluded from the loop entirely, so `percent` becomes `fullyInLock * 1e18 / userTotalVlmgp` = `1e18` (since `inCoolDown` is now counted as 0, `userTotalVlmgp` collapses to `fullyInLock`).
- No existing modifier or accounting mechanism prevents this: `cancelUnlock` has no `nonReentrant` restriction that would block same-transaction composition, and even without a custom contract, this is trivially achieved by calling `cancelUnlock()` then `getReward()` in two sequential transactions within the same block (self-front-running requires no interaction with any other party — it is simply sequencing the attacker's own transactions).

### Impact Explanation
This breaks the intended "Conservation" invariant between rewards distributed to a user and rewards that should be redistributed back to the pool (`_queueNewRewardsWithoutTransfer(forfeitAmount, ...)`) as a penalty for exiting participation via cooldown. Every unit of `forfeitAmount` avoided by the attacker is a unit of yield that other bonus-reward-token stakers should have received but do not, since the forfeiture pool is what gets re-queued to `rewardPerTokenStored` for remaining stakers. Repeated, systematic use of this pattern lets any locker who starts an unlock (a routine, permissionless action) claim their full bonus-reward share while in cooldown, defeating the cooldown-based reward-penalty mechanism entirely and diverting yield away from honest, non-gaming users. This matches "theft of unclaimed yield" from other pool participants.

### Likelihood Explanation
- Fully reachable by an unprivileged EOA; requires no special role, no flash loan, no oracle manipulation.
- Only precondition: the attacker must have an active `VLMGP` position and have started (or be willing to start) an unlock slot that is still within its cooldown window.
- Cost is minimal — just gas for `cancelUnlock()` (and, if the user still wants their MGP eventually unlocked, a subsequent `startUnlock()` to re-enter cooldown, restarting the timer).
- Highly repeatable: the pattern (`cancelUnlock` → `getReward` → `startUnlock` again) can be performed every time the attacker wants to harvest bonus rewards, with no cooldown or rate limit on `cancelUnlock`/`startUnlock` cycles beyond `maxSlot` capacity.

### Recommendation
Do not compute the forfeit percentage from the account's live unlock-slot state at claim time. Instead, snapshot/accrue the forfeitable amount incrementally as rewards are earned (e.g., update forfeiture proportionally at each `rewardPerToken` checkpoint using the state at that checkpoint, similar to how `userRewardPerTokenPaid` is tracked), or record a per-slot "reward debt" at the moment `startUnlock`/`cancelUnlock` is called so that later percentage changes cannot retroactively be applied to previously accrued rewards. Alternatively, disallow `cancelUnlock()` from resetting `amountInCoolDown` to zero for the purposes of already-accrued-but-unclaimed rewards (settle/forfeit those rewards at the moment of `cancelUnlock` itself, before the slot state changes).

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder`; lock MGP for `userA`.
2. `userA.startUnlock(amount)` to open a cooldown slot (`endTime = now + coolDownInSecs`).
3. Warp forward partway through the cooldown window; have the pool `queueNewRewards` bonus tokens so `rewardPerTokenStored` increases, accruing `userRewards` for `userA` via `_updateFor`.
4. Compute expected forfeit off-chain using `getRewardablePercentWAD(userA)` while still in cooldown (percent < 1e18) — confirm `calExpireForfeit(userA, token) > 0`.
5. In the same transaction/block (or immediately prior tx), call `vlMGP.cancelUnlock(slotIndex)`.
6. Call `vlMGPBaseRewarder.getReward(userA, ...)` (or `earned`/`_sendReward` path via harvest).
7. Assert: `forfeitAmount == 0` and `toSend == userRewards` (full amount, no penalty applied), versus the pre-cancel expected non-zero forfeit computed in step 4 — demonstrating the bypass.
8. Optionally, repeat `startUnlock` again post-claim to show the attacker can cyclically evade forfeiture indefinitely while still eventually completing the unlock.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;

    }

    function _earned(address _account, address _rewardToken, uint256 _userVlmgpShare) internal view returns (uint256) {
        return ((_userVlmgpShare *
                (rewardPerToken(_rewardToken) -
                    userRewardPerTokenPaid[_rewardToken][_account])) /
                10**vlMGPDecimal) + userRewards[_rewardToken][_account];
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
