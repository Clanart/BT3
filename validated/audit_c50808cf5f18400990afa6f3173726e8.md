### Title
Server-Side Request Forgery (SSRF) in Chia DataLayer mirror/subscription URL fetching - (File: `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer subsystem accepts arbitrary, unvalidated URLs from both a local RPC caller (`subscribe`/`add_mirror`) and from **on-chain mirror coins created by any wallet spend bundle** (`DLNewMirror`). These URLs are later fetched automatically over plain HTTP with no scheme, hostname, or IP-range validation — the same bug class as GHSA-7723-35v7-qcxw (missing anti-localhost/anti-internal-network checks before making an outbound request driven by untrusted, remotely-supplied input).

### Finding Description
`DataLayer.add_mirror()` forwards a user-supplied `urls: list[str]` straight to the wallet RPC `dl_new_mirror`, which creates an on-chain "mirror" coin whose memo encodes the launcher id and URL list with no format/host validation: [1](#0-0) [2](#0-1) 

Any node that is tracking that launcher id (e.g. because it subscribed to the store, or because an offer/DL-dependency caused `dl_track_new` to be called) will observe the mirror coin creation and persist the attacker-chosen URLs verbatim, again without validation: [3](#0-2) [4](#0-3) 

The DataLayer service's periodic sync loop pulls these mirror URLs via `update_subscriptions_from_wallet()` and merges them into the local subscription server list: [5](#0-4) 

`fetch_and_validate()` then randomly selects one of these attacker-controlled server URLs and issues an HTTP download against it via `download_file()`/`http_download()`: [6](#0-5) [7](#0-6) 

There is no equivalent of `verify_url_valid`/`is_local_url` anywhere in the DataLayer code path — the only `is_localhost`/network-range checks found in the codebase live in `chia/server/server.py` and `chia/server/ws_connection.py`, which govern the P2P websocket layer, not the DataLayer HTTP mirror-fetch path. The `subscribe` RPC (`chia/cmds/data.py:332-353`, `chia/data_layer/data_layer.py:895-902`) similarly accepts raw URLs with only `.rstrip("/")` normalization and no scheme/host filtering, and test fixtures even accept non-URL strings such as `"foo"`, `"bar"` as valid mirror URLs, confirming the absence of validation: [8](#0-7) 

This mirrors the reported bug class exactly: an unprivileged remote party supplies a domain/URL that is used to build an outbound request with no localhost/internal-network/IP-resolution checks, allowing the victim's node to be coerced into issuing GET requests to attacker-chosen host:port combinations (e.g. internal services, loopback-bound RPC ports, cloud metadata endpoints reachable from the host).

### Impact Explanation
Any wallet user who can afford the mirror-coin fee can, via a normal signed spend bundle (`DLNewMirror`), plant malicious mirror URLs for a DataLayer store id. Any other node that tracks that launcher (which can happen automatically through DL-offer dependency tracking or explicit subscription) will periodically and automatically issue outbound HTTP GET requests to those attacker-chosen targets from `chia/data_layer/download_data.py`'s `http_download`, with no restriction on target host, port, or IP range. This is a classic blind SSRF gadget: it can be used to probe or interact with services bound to localhost or internal networks on the victim's host (including other local RPC ports if reachable over HTTP), and can be weaponized against internal infrastructure behind the victim's network boundary.

### Likelihood Explanation
Reachable by an unprivileged wallet user submitting a normal signed spend bundle (`DLNewMirror`) or by a local RPC caller invoking the `subscribe`/`add_mirror` DataLayer RPC endpoints with attacker-controlled `urls`. No special privileges, malicious peer, or network-layer position is required — this is a standard DataLayer feature abused with unsanitized input, matching the report's requirement of reachability from a single submitted transaction/RPC action.

### Recommendation
- Validate all mirror/subscription URLs before storing or fetching: enforce `http`/`https` scheme only, reject IP literals and resolved addresses in loopback/private/link-local/cloud-metadata ranges (mirroring the anti-SSRF guidance in the referenced advisory), and reject malformed hosts.
- Perform DNS resolution and re-check resolved IPs immediately before each outbound request (TOCTOU-safe), not just a string comparison against `"localhost"`.
- Disable HTTP redirect following in the `aiohttp.ClientSession` used by `http_download`/`get_downloader`, or re-validate the redirect target.
- Apply the same validation to on-chain mirror memo URLs consumed in `data_layer_wallet.py`'s `coin_added()` before they are persisted/acted upon, not just to locally-typed RPC input.

### Proof of Concept
1. A user (attacker) creates a DataLayer store or targets one they know the `launcher_id` for, then calls `dl_new_mirror` (via `add_mirror` RPC or CLI `chia data add_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/", "http://127.0.0.1:<internal-port>/"]` and pushes the resulting spend bundle to the network — this is entirely valid, unprivileged wallet behavior.
2. Once confirmed, any victim node tracking that `launcher_id` (e.g., after taking/making a DL offer referencing the store, or explicitly subscribing) picks up the mirror coin in `DataLayerWallet.coin_added()` and stores the URL list unmodified via `dl_store.add_mirror`.
3. During the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` merges the URL into the subscription server list, and `fetch_and_validate()` → `download_file()` → `http_download()` issues an HTTP GET to the attacker-chosen host/port with no validation, from the victim's machine.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
