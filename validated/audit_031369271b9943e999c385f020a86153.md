### Title
Untrusted `ReceivedOutput` bytes can inject nonexistent Bitcoin inputs into transaction signing - (`networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` as three independent, attacker-controlled fields without proving that the outpoint actually references the supplied output. [1](#0-0) 

The forged output can satisfy the only cryptographic check performed before signing: `SignableTransaction::multisig` merely compares the supplied prevout’s `script_pubkey` with the address derived from the threshold key plus the supplied offset. [2](#0-1) 

### Finding Description
`ReceivedOutput` represents a previously observed chain output, but its deserializer accepts a complete semantic claim rather than reconstructing one from chain data. [3](#0-2) 

An attacker supplying bytes to `ReceivedOutput::read` can combine:

- a valid offset, including `Scalar::ZERO` for an even group key;
- a `TxOut` paying to `p2tr_script_buf(group_key + offset * G)`;
- an arbitrary or nonexistent `OutPoint`;
- an arbitrary claimed satoshi value.

`SignableTransaction::new` then trusts the claimed value and outpoint when constructing transaction inputs. [4](#0-3) 

During signing, each fake input is committed using `Prevouts::All`, producing valid Schnorr/FROST signature shares for a transaction whose input need not exist. [5](#0-4) 

### Impact Explanation
An attacker can cause Serai’s wallet layer to report or account for funds that are not spendable, and can cause threshold participants to sign a transaction spending a nonexistent or unrelated UTXO. [1](#0-0) 

If the serialized `ReceivedOutput` is used as wallet state, this can inflate balances and create fully signed but invalid transactions. The signatures are cryptographically valid for the supplied prevout set; Bitcoin consensus rejects the transaction because the referenced input is absent or does not contain the claimed output. [6](#0-5) 

### Likelihood Explanation
Exploitation requires an attacker to control bytes passed to `ReceivedOutput::read` and have the resulting object accepted by transaction construction. That is the exposed untrusted deserialization path considered here, not merely a Bitcoin transaction submitted to `Scanner`. [1](#0-0) 

The attacker does not need a private key, validator compromise, malformed curve encoding, or an actual conflicting blockchain output; the value, outpoint, and script relationship are all supplied in the serialized object. [2](#0-1) 

### Recommendation
Do not treat deserialized `ReceivedOutput` values as authenticated observations of confirmed UTXOs. Persist them only through authenticated storage, or revalidate `outpoint -> TxOut` against a trusted Bitcoin node before accounting for or signing the input. [1](#0-0) 

`SignableTransaction::new` or `multisig` should require scanner-derived outputs whose outpoints have been independently resolved from confirmed chain data, rather than relying solely on the internal consistency of offset and `script_pubkey`. [2](#0-1) 

### Proof of Concept
Conceptually:

```rust
// group_key is the even threshold output key.
let offset = Scalar::ZERO;

let fake_txout = TxOut {
  value: Amount::from_sat(1_000_000_000),
  script_pubkey: p2tr_script_buf(group_key).unwrap(),
};

let fake_outpoint = OutPoint {
  txid: arbitrary_txid,
  vout: 0,
};

// Serialize offset || fake_txout || fake_outpoint and feed it to:
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// This counts the fake value and creates an input for the fake outpoint.
let signable = SignableTransaction::new(
  vec![forged],
  &payments,
  change,
  data,
  fee_per_vbyte,
).unwrap();

// This succeeds because the supplied script_pubkey matches group_key + offset * G.
let machine = signable.multisig(&threshold_keys).unwrap();
```

`multisig` checks only that `p2tr_script_buf(offset.group_key())` equals the supplied prevout script, not that `outpoint` resolves to that prevout on chain. [2](#0-1)

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
