### Title
Uncaught TypeError in `CommitMentionLinkFilter.getRefFromComparePath` from malformed compare link crashes markdown rendering - (File: app/src/lib/markdown-filters/commit-mention-link-filter.ts)

### Summary
`CommitMentionLinkFilter.getRefFromComparePath` splits an attacker-controlled URL path segment on the literal `...` and unconditionally indexes into position `1` of the resulting array, assuming two elements are always present. A malformed but otherwise regex-valid `compare/` link (any input matching `/^compare\/(?<range>.+)$/` that doesn't actually contain `...`) produces a one-element array, so `shas[1]` is `undefined` and `.indexOf('/')` throws a `TypeError`. This mirrors the erigon `attnets` bug: a fixed-position index into a variable-length structure derived from external input, guarded by a length check that doesn't cover the actually-required length.

### Finding Description
The regex used to detect a compare path is intentionally loose: [2](#0-1) 

`range` only needs to be non-empty (`.+`); it does not require the `...` separator. `getRefFromComparePath` then does: [3](#0-2) 

`range.split('...')` returns `['range']` (length 1) when there's no `...` in the path. The guard `if (shas.length > 2) return null` only rejects arrays with *more* than 2 elements — it does nothing to protect against fewer than 2. `shas[1]` is `undefined`, and `undefined.indexOf('/')` throws `TypeError: Cannot read properties of undefined (reading 'indexOf')`, exactly analogous to the erigon panic where `peerSubnets[subnetIdx/8]` was indexed without checking `len(peerSubnets) == 8`.

The `filter()` entry point does construct the link's target via `new URL(text)` and matches it against `commitMentionUrl` in the `createFilterTreeWalker` acceptNode callback, but that regex only validates the *href*, not the anchor's `innerText`/`textContent`, which is what actually gets parsed by `getRefFromComparePath` via `this.getRefFromCommitPath(path) ?? this.getRefFromComparePath(path)` — `path` is derived from `text` (the inner text), not the href. [4](#0-3) 

An attacker who controls a commit message, PR/issue body, or PR comment (rendered via `SandboxedMarkdown`) can embed an anchor tag whose `href` equals `innerText` (satisfying the auto-link condition upstream in `marked`) with a path like `.../owner/repo/compare/deadbeef` (no `...`). This node is accepted by the tree walker and passed to `filter()`, which throws.

### Impact Explanation
`SandboxedMarkdown.applyFilters` has no error handling around `await nodeFilter.filter(node)`: [5](#0-4) 

An uncaught rejection here breaks the markdown-filter pipeline for that render pass. Depending on where this promise chain surfaces (`onDocumentDOMContentLoaded` is itself unguarded), this can produce an unhandled promise rejection in the renderer, breaking markdown rendering for commit descriptions/PR bodies/issue bodies that contain the malformed link — a reliable, remotely triggerable renderer-side crash/DoS-of-a-feature caused by content in a repository/PR/issue the user opens, not by any local or privileged action.

### Likelihood Explanation
High for triggering the throw: the regex and split logic are simple to reach with a single crafted link inside markdown content is rendered in Desktop (commit description in `expandable-commit-summary.tsx`, PR/issue view, etc.), requiring no user interaction beyond viewing content that the app auto-renders. No admin rights, local access, or credentials are needed — only that the victim opens/views a repository, commit, or PR containing the crafted text/link.

### Recommendation
In `getRefFromComparePath`, validate `shas.length === 2` (not just `> 2`) before indexing `shas[1]`, returning `null` otherwise — mirroring the erigon fix pattern of checking the exact expected length (`len(peerSubnets) == 8`) before any fixed-index access. Additionally, wrap `nodeFilter.filter(node)` calls in `SandboxedMarkdown.applyFilters` in a try/catch so a single malformed node cannot abort the whole filter pipeline for future defense-in-depth.

### Proof of Concept
1. Render markdown content (e.g., a commit description or PR body, via `SandboxedMarkdown`) containing a bare auto-linked URL such as:
   `https://github.com/<owner>/<repo>/compare/deadbeef`
   where `<owner>/<repo>` matches the current repository so the anchor's `href` equals its `innerText`.
2. `marked` auto-links this into `<a href="...">https://.../compare/deadbeef</a>`.
3. `CommitMentionLinkFilter.createFilterTreeWalker`'s `acceptNode` accepts the node (`href === innerText` and `commitMentionUrl` regex matches `.../compare/deadbeef`).
4. `filter(node)` is invoked; `url.pathname` yields `.../compare/deadbeef`; `getRefFromComparePath` matches `comparePath` regex, `range = 'deadbeef'`, `range.split('...')` → `['deadbeef']`.
5. `shas[1].indexOf('/')` throws `TypeError: Cannot read properties of undefined (reading 'indexOf')`, propagating out of `applyFilters` uncaught.
