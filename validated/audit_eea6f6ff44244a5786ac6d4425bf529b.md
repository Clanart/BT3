### Title
Payout attribution via unsigned OP_RETURN output is malleable, letting anyone divert operator reimbursement credit - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The operator `payout_tx` binds the user's fronted withdrawal to a specific reimbursing operator solely through an OP_RETURN output carrying the operator's x-only pubkey. That output is not covered by the user's signature, because the user signs with `SinglePlusAnyoneCanPay`, which only commits to the single input being spent and the output at the same index (output 0, the user payout). Anyone who observes the broadcast/mempool transaction can rebuild an equivalent transaction with the same witness, same input, and same output 0, but a different OP_RETURN payload, and get it mined instead (e.g. via RBF/fee bump).

### Finding Description
`create_payout_txhandler` builds the payout with output 0 = user payout, output 1 = anchor, output 2 = `op_return_txout` carrying `operator_xonly_pk`: [1](#0-0) 

The operator's `withdraw()` flow constructs this handler from the user-supplied signature and outpoint, and the signature is only checked to be valid for a `SinglePlusAnyoneCanPay`-type sighash over input 0 / output 0: [2](#0-1) 

Because `SIGHASH_SINGLE | ANYONECANPAY` does not commit to outputs other than the one matching the signed input's position, an observer of the not-yet-confirmed transaction can extract the witness and rebroadcast a modified transaction that keeps input 0 and output 0 identical (satisfying the signature) while replacing the OP_RETURN operator-attribution output (output 2) and/or the anchor output (output 1) with arbitrary values, then have it confirmed instead of the operator's original transaction (e.g., via a fee-bumped replacement).

The verifier's finalized-block scanner later determines "who gets credited for this payout" purely from whatever OP_RETURN happens to end up on-chain for the transaction that actually spends the withdrawal UTXO — it does not verify that the attribution matches whichever party truly fronted the funds: [3](#0-2) 

This attribution then drives whether an operator can ever discover and process its own reimbursement, since operators poll for unhandled payouts filtered by their own xonly pubkey: [4](#0-3) 
and cross-check that they themselves are the recorded payer before proceeding to reimbursement: [5](#0-4) 

**Binding broken:** `operator credited (OP_RETURN attribution recorded on-chain) == operator that actually fronted the withdrawal (paid the user)`. Before the attack, operator A funds the user's payout and broadcasts a tx with OP_RETURN = A. After the attacker's substitution, the tx that actually confirms on-chain still pays the same user the same amount (output 0 unchanged, per signature) but carries a different/garbage OP_RETURN. Operator A has spent its own BTC fronting the withdrawal but the `payout_payer_operator_xonly_pk` recorded no longer equals A's key, so A's `validate_payer_is_operator` check will permanently fail for that deposit — A can never trigger the reimbursement kickoff for those funds.

### Impact Explanation
This matches the Critical bullet "an honest operator permanently unable to be reimbursed." An unprivileged party (any Bitcoin network participant capable of relaying an alternate transaction / RBF, no verifier/operator/aggregator role, no key compromise) can permanently sever the honest operator's fronted payment from its reimbursement path by mutating the unsigned OP_RETURN portion of an in-flight payout transaction.

### Likelihood Explanation
The attack only requires: (1) monitoring the Bitcoin mempool for `payout_tx` broadcasts (public), (2) reconstructing a transaction with the same input/witness and same output 0, (3) paying enough fee to have it replace/out-race the original in the mempool. All of this is achievable by any unprivileged party with basic Bitcoin tooling and no protocol-specific access. The griefing has no requirement to actually control a registered operator key — the attacker can set the OP_RETURN to any value (or omit a valid xonly pubkey entirely), which per `update_finalized_payouts` simply results in `operator_xonly_pk = None`, still leaving no operator credited for this payout, i.e., no operator can ever match `get_first_unhandled_payout_by_operator_xonly_pk`.

### Recommendation
Bind the operator-attribution output to the user's signature (e.g., by using `SIGHASH_ALL` covering all outputs, or by having the operator co-sign/commit the OP_RETURN output content as part of a covenant/pre-signed structure), or otherwise make the reimbursement path independent of a freely-mutable, unauthenticated OP_RETURN field — for instance, deriving payer attribution from a value that is cryptographically bound to the specific operator's kickoff/round transaction chain rather than an unsigned tag in the payout transaction.

### Proof of Concept
1. Operator A receives the user's `SinglePlusAnyoneCanPay` signature and broadcasts `payout_tx_A` (input = withdrawal UTXO, output0 = user payout, output1 = anchor, output2 = OP_RETURN(A_xonly_pk)) per `create_payout_txhandler`/`operator.rs::withdraw`.
2. Before confirmation, an unprivileged observer extracts the witness from `payout_tx_A` in the mempool and constructs `payout_tx_X` with the identical input and output0 (satisfying the `SinglePlusAnyoneCanPay` signature), but a different (or invalid) output2 OP_RETURN, adding extra fee via `ANYONECANPAY`-permitted additional inputs to win the mempool/RBF race.
3. `payout_tx_X` confirms instead of `payout_tx_A`. The user still receives their expected payout (output0 unchanged), but `update_finalized_payouts` records `payout_payer_operator_xonly_pk` as garbage/None rather than A.
4. Operator A's `get_first_unhandled_payout_by_operator_xonly_pk` never returns this withdrawal, and `validate_payer_is_operator` fails permanently for the associated deposit — A cannot claim reimbursement for BTC it already fronted.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
