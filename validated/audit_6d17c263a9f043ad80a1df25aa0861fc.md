### Title
Finalized-payout correlation keyed by withdrawal-UTXO value alone lets one real payout satisfy two attacker-duplicated withdrawal indices, double-crediting an operator for a payout it funded only once - (File: `core/src/verifier.rs`, `core/src/database/verifier.rs`)

### Summary
`update_finalized_payouts` derives "which withdrawal got paid" solely from `get_payout_txs_for_withdrawal_utxos`, whose SQL `JOIN` matches on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` value equality with no scoping/uniqueness against the withdrawal's own `idx`/deposit binding. If two different Citrea withdrawal indices (D1, D2) are registered with the same attacker-chosen withdrawal-UTXO outpoint bytes, a single real Bitcoin spend of that outpoint gets joined to *both* rows and is written into both as their `payout_txid`, letting one operator payment be recognized as a valid finalized payout for two separate deposits.

### Finding Description
The binding that should hold is: **finalized-payout record for withdrawal row `idx` == exactly one Bitcoin spend that was specifically fronted for that `idx`'s deposit**. The read path breaks this:

- `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:168-196`) does:
```
SELECT w.idx, bsu.spending_txid
FROM withdrawals w
JOIN bitcoin_syncer_spent_utxos bsu
   ON bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout
WHERE bsu.block_id = $1
```
This is a pure value-equality join on the outpoint columns. It is not restricted to a single `idx` per outpoint value; if two rows in `withdrawals` (idx=D1, idx=D2) carry the identical `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, both rows are returned for the one real spending transaction.
- `update_withdrawal_utxo_from_citrea_withdrawal` (`core/src/database/verifier.rs:108-135`) writes the attacker-supplied withdrawal UTXO per `idx` with no uniqueness check across other `idx` values, and is invoked per new Citrea withdrawal in `update_citrea_deposit_and_withdrawals` (`core/src/verifier.rs:2204-2262`).
- `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) then calls `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:199-251`), which writes the *same* `payout_txid`/`operator_xonly_pk`/`block_hash` into both D1's and D2's rows, because the write is correctly scoped `WHERE w.idx = c.idx`, but the input list it receives already contains a duplicate `payout_txid` for two different `idx`s coming from the flawed read.
- Downstream, `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) and `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:31-113`) surface D2 as "paid" to the operator and call `handle_finalized_payout` for D2's deposit outpoint, driving the reimbursement/kickoff flow for D2's vault even though no independent Bitcoin payment was made to D2's specified recipient/amount.

Root cause: the join key used to correlate "a Bitcoin UTXO got spent" with "this withdrawal is paid" is the raw outpoint bytes, which are attacker-supplied per the stated Citrea `withdraw()` precondition, instead of being scoped to guarantee a 1:1 mapping between a real spend and a single withdrawal index/deposit_id.

### Impact Explanation
If an attacker registers the same withdrawal UTXO (and, to make the operator's single real transaction also satisfy D2's amount/script check, the same output script/amount) for two different Citrea withdrawals D1 and D2, one operator payment that legitimately fronts D1 gets mechanically recorded as also finalizing D2. This lets that operator's reimbursement flow proceed against D2's move-to-vault UTXO without a second, independently-funded payout — matching the Critical category "an operator reimbursed for a payout it never funded" / "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal." The blast radius is per attacker-chosen duplicate pair and is repeatable across any number of deposits the attacker controls, and affects whichever operator happens to front the first of the colliding withdrawals.

### Likelihood Explanation
The exploit requires the Citrea `withdraw()` contract to accept and store a withdrawal-UTXO outpoint value that is not checked for prior use by another withdrawal index — a precondition explicitly asserted in the question but not verifiable from this repository (Citrea's bridge contract is out of this repo's scope). Within `clementine`, the join logic that would let a duplicate collapse two withdrawals into one payout record is real and directly demonstrable by unit-testing `get_payout_txs_for_withdrawal_utxos`/`update_payout_txs_and_payer_operator_xonly_pk` with two `withdrawals` rows sharing one `(withdrawal_utxo_txid, withdrawal_utxo_vout)`. No verifier/operator role, key, or collateral is needed by the attacker — only the ability to call `withdraw()` twice with the same outpoint bytes, which is stated as attacker-controlled.

### Recommendation
Scope the finalized-payout correlation so a spend of a given outpoint can only satisfy a single withdrawal `idx`/deposit. Concretely:
- Add a uniqueness constraint (or an explicit check in `update_withdrawal_utxo_from_citrea_withdrawal`) preventing two different `idx` rows in `withdrawals` from storing the same `(withdrawal_utxo_txid, withdrawal_utxo_vout)` pair, rejecting/flagging the second registration.
- Alternatively/additionally, change `get_payout_txs_for_withdrawal_utxos` to deduplicate by outpoint (e.g., pick the earliest/only `idx` per outpoint, or require the join to also validate that the payout tx's output actually matches that specific `idx`'s recorded `output_script_pubkey`/`output_amount`, not just the shared input).
- Ensure `handle_finalized_payout`/`PayoutCheckerTask` independently verify, per deposit_id, that the payout transaction's output matches that specific deposit's registered recipient/amount before crediting reimbursement.

        &self,

        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,

        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

#[async_trait]
impl<C> Task for PayoutCheckerTask<C>
where
    C: CitreaClientT,
{
    type Output = bool;
    const VARIANT: TaskVariant = TaskVariant::PayoutChecker;

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
}
