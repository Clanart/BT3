### Title
Regex Denial-of-Service in Tendermint Event Subscription Query Matching Stalls Event Publication and Block Finalization - (File: `sei-tendermint/internal/pubsub/query/query.go`)

### Summary
The `MATCHES` operator in the pubsub event-query language compiles and evaluates an attacker-supplied regular expression against event attribute values on every single published chain event (transactions, new blocks, etc.), with no complexity bound, no per-match timeout, and no protection against catastrophic backtracking. This is the same bug class as CVE-2019-5419 (Action View DoS): unbounded, attacker-influenced input is fed into pattern-matching logic that runs on the hot path of every request/event, and a crafted pattern can pin a CPU core, denying service to legitimate users.

### Finding Description
The `TMatches` condition constructor evaluates the pattern supplied by the RPC caller directly against event data on every match check: [1](#0-0) 

This function is invoked once per attribute value for every event published to the bus, via `condition.matchesEvent` → `Query.Matches`: [2](#0-1) 

The `subscribe` JSON-RPC/WebSocket endpoint lets any unauthenticated client register such a query, with the only mitigation being a 512-character length cap on the raw query string — no restriction on regex complexity: [3](#0-2) 

Matching happens inside `pubsub.Server.send`, which runs on a single, dedicated sender goroutine that serially evaluates every registered subscription's query against every published event before delivering it to any subscriber: [4](#0-3) 

Publishing itself is bounded by a fixed-capacity channel (`DefaultBufferCapacity = 10000`); once that queue is full, `Server.publish` blocks the caller until the sender goroutine drains an entry: [5](#0-4) [6](#0-5) 

`EventBus.PublishEventTx` and `EventBus.PublishEventNewBlock` are the calls used by the block execution/finalization path to emit per-transaction and per-block events, and they call `PublishWithEvents` synchronously: [7](#0-6) 

Because the single sender goroutine is what drains this queue, if it becomes stuck evaluating a catastrophic-backtracking regex against one event's attribute value, event delivery for **all** subsequent events halts. Once the 10000-entry queue fills (which happens quickly under normal block/tx throughput), any code path calling `Publish`/`PublishWithEvents` — including the block finalization path — blocks indefinitely waiting for queue space.

### Impact Explanation
A public, unauthenticated RPC client can:
1. Subscribe via the WebSocket `subscribe` method with a query such as `some.attr MATCHES '(a+)+$'` targeting an event attribute tag that will appear in ordinary chain traffic (e.g., a CosmWasm contract's custom event attribute, which the attacker fully controls both in content and length since anyone can deploy and invoke a contract emitting arbitrary attribute values).
2. Trigger matching transactions/events so that the crafted regex is evaluated against an attacker-chosen string, causing exponential-time backtracking in the single serialized pubsub sender goroutine.
3. This stalls all event delivery, fills the fixed 10,000-item publish queue, and then blocks any subsequent call to `PublishEventTx`/`PublishEventNewBlock` from the block finalization path, stalling block production/finalization on the affected node.

If the affected node is a validator, this can cause block delay well beyond 2.5 seconds or a full validator halt; on any node it denies the WebSocket/event-subscription RPC surface to all other clients. This matches the accepted impact categories ("validator halt," "block delay beyond 2.5 seconds," "crash/DoS of default-configuration RPC nodes").

### Likelihood Explanation
Likelihood is high: the `subscribe` RPC method is part of the default, publicly exposed Tendermint RPC surface, requires no special privileges, and the only defense is a 512-character cap on the raw query string — insufficient to block short catastrophic-backtracking patterns like `(a+)+$` or `(a|a)*b`. An attacker only needs the ability to (a) submit a subscribe request and (b) cause an event with an attacker-influenced attribute value to be emitted (trivially achievable via a CosmWasm contract's custom event attributes, which are attacker-controlled in both content and length).

### Recommendation
- Reject or heavily restrict the `MATCHES` operator's regex complexity (e.g., disallow nested quantifiers, cap pattern length independently and strictly, or use RE2-safe subset enforcement — Go's `regexp` is RE2-based and does not suffer classic backtracking blowup, but confirm and add defense-in-depth: enforce input length caps on matched attribute values, and add a per-match timeout/deadline using a separate goroutine with `context` cancellation).
- Move query matching off the single serialized publish path, or bound per-condition match time so a single slow condition cannot stall the entire event bus and, transitively, block finalization publishing.
- Add a non-blocking (drop-oldest or reject) publish policy for the internal event queue so that a stuck consumer cannot block block-finalization callers indefinitely.

### Proof of Concept
1. Deploy (or use) a CosmWasm contract that emits a custom event with an attribute value fully controllable in content/length by the caller, e.g. `wasm.customattr = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!"` (40 a's followed by a non-matching character).
2. Connect to the node's public WebSocket RPC endpoint and issue:
   `{"jsonrpc":"2.0","method":"subscribe","id":1,"params":{"query":"wasm.customattr MATCHES '(a+)+$'"}}`
3. Execute a transaction that invokes the contract to emit the crafted attribute value.
4. Observe that the pubsub sender goroutine (`sei-tendermint/internal/pubsub/pubsub.go:send`) enters exponential-time regex evaluation via `regexp.MatchString` in `sei-tendermint/internal/pubsub/query/query.go:222`, event delivery for other subscribers stalls, the event queue backs up, and subsequent block/tx event publication from the finalization path blocks once the queue fills — observable as rising block times / stalled RPC event delivery on the node.

// matchesEvent reports whether c matches the given event.
func (c condition) matchesEvent(event types.Event) bool {
	vs, tagEqualsType := c.findAttr(event)
	if len(vs) == 0 {
		// As a special case, a condition tag that exactly matches the event type
		// is matched against an empty string. This allows existence checks to
		// work for type-only queries.
		if tagEqualsType {
			return c.match("")
		}
		return false
	}

	// At this point, we have candidate values.
	for _, v := range vs {
		if c.match(v) {
			return true
		}
	}
	return false
}

	s.pubs.RLock()
	defer s.pubs.RUnlock()

	select {
	case <-s.done:
		return ErrServerStopped
	case s.queue <- item{
		Data:   data,
		Events: events,
	}:
		return nil
	}
}

// send delivers the given message to all matching subscribers.  An error in
// query matching stops transmission and is returned.
func (s *Server) send(data types.EventData, events []abci.Event) error {
	// At exit, evict any subscriptions that were too slow.
	evict := make(subInfoSet)
	defer func() {
		if len(evict) != 0 {
			s.subs.Lock()
			defer s.subs.Unlock()
			s.removeSubs(evict, ErrTerminated)
		}
	}()

	// N.B. Order is important here. We must acquire and defer the lock release
	// AFTER deferring the eviction cleanup: The cleanup must happen after the
	// reader lock has released, or it will deadlock.
	s.subs.RLock()
	defer s.subs.RUnlock()

	// If an observer is defined, give it control of the message before
	// attempting to deliver it to any matching subscribers. If the observer
	// fails, the message will not be forwarded.
	if s.subs.observe != nil {
		err := s.subs.observe(Message{
			data:   data,
			events: events,
		})
		if err != nil {
			return fmt.Errorf("observer failed on message: %w", err)
		}
	}

	for si := range s.subs.index.all {
		if !si.query.Matches(events) {
			continue
		}

		// Publish the events to the subscriber's queue. If this fails, e.g.,
		// because the queue is over capacity or out of quota, evict the
		// subscription from the index.
		if err := si.sub.publish(Message{
			subID:  si.sub.id,
			data:   data,
			events: events,
		}); err != nil {
			evict.add(si)
		}
	}

// PublishEventTx publishes tx event with events from Result. Note it will add
// predefined keys (EventTypeKey, TxHashKey). Existing events with the same keys
// will be overwritten.
func (b *EventBus) PublishEventTx(data types.EventDataTx) error {
	events := data.Result.Events

	// add Tendermint-reserved events
	events = append(events, types.EventTx)

	tokens := strings.Split(types.TxHashKey, ".")
	events = append(events, abci.Event{
		Type: tokens[0],
		Attributes: []abci.EventAttribute{
			{
				Key:   []byte(tokens[1]),
				Value: []byte(fmt.Sprintf("%X", types.Tx(data.Tx).Hash())),
			},
		},
	})

	tokens = strings.Split(types.TxHeightKey, ".")
	events = append(events, abci.Event{
		Type: tokens[0],
		Attributes: []abci.EventAttribute{
			{
				Key:   []byte(tokens[1]),
				Value: []byte(fmt.Sprintf("%d", data.Height)),
			},
		},
	})

	return b.pubsub.PublishWithEvents(data, events)
}
