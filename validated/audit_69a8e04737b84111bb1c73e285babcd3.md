This confirms the analog: the `wwwauth[]` credential field is populated by Git directly from the actual HTTP `WWW-Authenticate` response header sent by whatever remote server Git is talking to (per Git's credential-helper protocol), and Desktop's `parseCredential` faithfully stores it verbatim [1](#0-0) . The `getEndpointKind` function in Desktop's credential helper trusts this attacker-influenced value to classify an arbitrary host as a GitHub Enterprise host, and that classification then drives an OAuth/enterprise sign-in flow scoped to the attacker's own origin.

### Title
Untrusted `WWW-Authenticate: realm="GitHub"` header triggers Enterprise sign-in flow bound to an attacker-controlled origin - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` classifies a credential-fill request as `'enterprise'` solely because the remote HTTP server included a `WWW-Authenticate` header containing `realm="GitHub"`, without checking whether the host actually corresponds to any known GitHub/GHE endpoint [2](#0-1) . This is analogous to the Morpho bug: a boolean condition (`isInEMode` / "looks like GitHub") is trusted to select a value (`priceSource` / the sign-in `endpoint`) without validating that the value is actually legitimate for that branch (`priceSource != address(0)` / the host is an actual known GitHub endpoint).

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes the configured credential helper (`desktop`) and forwards any `WWW-Authenticate` headers received from the server as `wwwauth[]` fields on stdin [3](#0-2) . These are parsed verbatim into a `Credential` map by `parseCredential` [1](#0-0) .

In `getEndpointKind`, Desktop iterates these `wwwauth[]` entries and, upon seeing `realm="GitHub"`, immediately returns `'enterprise'` — before ever verifying the host against a known account or against any GitHub-specific network signal: [2](#0-1) 

This classification feeds directly into `getCredential`, which, upon finding `endpointKind !== 'generic'` and no matching stored account, calls `ui.promptForGitHubSignIn(endpoint)` where `endpoint` is the attacker's own remote URL: [4](#0-3) 

`promptForGitHubSignIn` then starts a full Enterprise sign-in flow scoped to that attacker-controlled origin: [5](#0-4) 

Just like the Morpho bug used `priceSource` (attacker/uncontrolled input) unconditionally once `isInEMode` was true, Desktop uses the remote-supplied `realm` string unconditionally once it matches `"GitHub"`, without confirming the host is a genuine, previously-verified GitHub Enterprise instance. `isGitHubHost`, which does perform a legitimate discovery check via a `/meta` HEAD request and header inspection, is only reached as a fallback in `getEndpointKind` — it is bypassed entirely by the `wwwauth[]` header check [6](#0-5) .

### Impact Explanation
Any HTTPS remote the user clones/fetches/pushes to (or any proxy/MITM able to shape responses to such a remote) can serve a `401` response with `WWW-Authenticate: Basic realm="GitHub"`. This causes GitHub Desktop to believe the arbitrary attacker domain is a GitHub Enterprise server and to open Desktop's real Enterprise sign-in UI pointed at that domain (`setSignInEndpoint(origin)` / `beginEnterpriseSignIn`). A user who completes this flow (entering a PAT or completing an OAuth-style login they believe is legitimate, since the domain and Desktop's normal sign-in chrome match what they'd expect for a corporate GHE server) will have Desktop store an account/token scoped to the attacker's origin. Because Desktop's credential helper subsequently returns that stored token via `findGitHubTrampolineAccount`/`credWithAccount` for any future request to that same origin, the token is delivered straight to the attacker's server as an HTTP Basic credential — resulting in credential/token exfiltration triggered purely by fetching/cloning a malicious remote.

### Likelihood Explanation
Exploitation requires nothing beyond the user adding/cloning an attacker-supplied remote URL and Git making an authenticated HTTPS request against it (a routine occurrence for private-looking repos or ones behind attacker-controlled proxies) — no local access, malware, or leaked credentials needed. The remaining variable is whether the user completes the resulting sign-in prompt, but the prompt is Desktop's own legitimate-looking "Sign in to GitHub Enterprise" dialog, which increases plausibility relative to typical phishing.

### Recommendation
Do not classify a host as `'enterprise'`/GitHub based solely on a self-reported `WWW-Authenticate` realm string from the remote server. At minimum, corroborate the `realm="GitHub"` signal with the same discovery check used by `isGitHubHost` (e.g., requiring an `x-github-request-id` header or a successful `/meta` probe) before routing the user into an Enterprise/OAuth sign-in flow, mirroring how the Morpho fix required both `isInEMode` and a validated non-zero `priceSource` before trusting the e-mode price.

### Proof of Concept
1. Host an HTTPS git server (e.g., via a simple proxy) that serves a `401` response to `git-upload-pack`/`git-receive-pack` requests including header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add this server's URL as a remote and perform a fetch/push.
3. Git invokes Desktop's credential helper; `getEndpointKind` reads the forwarded `wwwauth[]` entry and returns `'enterprise'` [2](#0-1) .
4. `getCredential` finds no existing account for the attacker's endpoint and calls `ui.promptForGitHubSignIn(endpoint)`, opening Desktop's Enterprise sign-in flow scoped to the attacker's origin [7](#0-6) .
5. If the user completes sign-in, the resulting token is stored against the attacker's origin and will be sent to that origin on subsequent requests.

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
