### Title
Ed448 accepts low-order points, enabling invalid PedPoP proofs - ([File: crypto/ed448/src/point.rs](https://github.com/blackvul/serai--006/blob/master/crypto/ed448/src/point.rs))

### Summary
`Point::is_torsion_free` checks `(-P) + P == identity`, which is true for every curve point and therefore performs no subgroup validation. Ed448-encoded low-order points are consequently accepted through `read_G`, including PedPoP commitments and Schnorr proof nonces.

### Finding Description
The subgroup check multiplies the candidate by `-1` and adds the original point, producing the identity unconditionally. [1](#0-0)  Point decoding accepts the resulting candidate whenever the negative-zero condition and this ineffective check pass. [2](#0-1) 

PedPoP commitment deserialization passes attacker-controlled bytes directly to `C::read_G` for each coefficient commitment. [3](#0-2)  The first commitment is then used as the public key for the Schnorr proof of knowledge. [4](#0-3)  Verification only requires `R + cA - sG == identity`. [5](#0-4) 

An attacker can therefore submit an identity or low-order Ed448 commitment that should have been rejected. With `A = identity`, `R = identity`, and `s = 0`, the proof passes for every challenge. With an order-4 commitment, the attacker can enumerate the small set of malformed `A`/`R` encodings until `R + cA = identity`.

### Impact Explanation
A malicious participant can cause PedPoP to accept a coefficient commitment outside the intended prime-order group. This invalidates the Schnorr proof-of-knowledge assumption and allows malformed commitments into the DKG's commitment set, group-key derivation, and share-verification equations. Because PedPoP queues the proof for batch verification, a satisfying malformed statement is treated the same as a valid participant proof. [6](#0-5) 

### Likelihood Explanation
The attacker only needs to send a malformed PedPoP `Commitments` message containing attacker-controlled Ed448 encodings. The identity variant is deterministic; the non-identity low-order variant requires evaluating a small number of candidate encodings because only the challenge modulo 4 affects the torsion component. No private key, validator privilege, or unsafe code is required.

### Recommendation
Replace `Point::is_torsion_free` with a real prime-order subgroup check, such as multiplying by the Ed448 prime subgroup order and requiring the identity. Separately reject the identity for public keys and Schnorr nonces where the protocol requires nonzero values, rather than relying solely on generic `read_G` canonicality checks.

### Proof of Concept
Conceptual PedPoP message:

```text
commitment[0] = Ed448 identity encoding
SchnorrSignature.R = Ed448 identity encoding
SchnorrSignature.s = 0
```

`EncryptedMessage::read`/`Commitments::read` accepts both encodings because `read_G` accepts the identity and the defective torsion predicate accepts low-order points. [7](#0-6)  The verifier calculates `identity + c * identity - 0 * G = identity`, so the malformed commitment passes despite violating the requirement that coefficients be generated with `random_nonzero_F`. [8](#0-7)

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
