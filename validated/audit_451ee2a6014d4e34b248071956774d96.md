## Title
Missing zero-value validation for `kip71.gastarget` allows governance-triggered division-by-zero panic in base fee computation - (File: kaiax/gov/param.go, params/kip71_config.go)

### Summary
The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, which accepts any `uint64` value including `0`, unlike the sibling `Kip71BaseFeeDenominator` parameter which explicitly rejects zero (`v != 0`). A `GasTarget` of `0` is a valid, votable/settable governance value that is consumed unguarded by `NextMagmaBlockBaseFee`, the KIP-71 (Magma) base-fee calculation function that every node runs to compute and verify the base fee of every block. This mirrors the reported bug class (missing "must be greater than 0" checks on economically/mathematically critical parameters), except here the consequence is a division-by-zero panic in consensus-critical code rather than an economic exploit.

### Finding Description
`Kip71GasTarget` is defined with `FormatChecker: noopFormatChecker` (always returns `true`), so any `uint64`, including `0`, passes validation both through header governance votes (`NewVoteData` → `param.FormatChecker(cv)`) and through contract governance (`GovParam.setParamIn`/`setParam` → `ParseContractCall` → `PartialParamSet.Add` → same `FormatChecker`): [1](#0-0) 

Compare this to the neighboring `Kip71BaseFeeDenominator` param, which has an explicit non-zero check: [2](#0-1) 

Additionally, `checkConsistency` in header governance only special-cases `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` (bound-crossing checks); `Kip71GasTarget` falls into the default "no additional checks" bucket: [3](#0-2) 

`GasTarget=0` then flows unguarded into `NextMagmaBlockBaseFee`, which is called on every block by every node to compute/verify the base fee (`VerifyMagmaHeader`). When `parentGasUsed > gasTarget` (true whenever `gasTarget == 0` and any gas is used), the code divides by `gasTarget`: [4](#0-3) 

`x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget == 0` is a division by zero on `math/big.Int`, which panics. Unlike `BaseFeeDenominator`, there is no `if kc.GasTarget == 0 { ... }` fallback anywhere in `NextMagmaBlockBaseFee`: [5](#0-4) 

### Impact Explanation
`NextMagmaBlockBaseFee`/`VerifyMagmaHeader` is executed by every full node (proposers and validators alike) during block assembly and header verification post-Magma fork. A single successful governance vote (header-vote by the governing node, or an on-chain `GovParam.setParamIn("kip71.gastarget", 0, ...)` transaction under KIP-81 contract governance) that sets `GasTarget = 0` will cause every node to panic/crash while computing the very next block's base fee (as long as any non-zero gas is used in the parent block, which is virtually guaranteed). This is a network-wide consensus-halting condition — not an isolated node bug — since the panic occurs deterministically for all honest nodes running the same code path, effectively halting block production/verification chain-wide until a patched binary is deployed. This is a much stronger effect than the referenced report's economic-manipulation risk, since it isn't merely an economic exploit but a full liveness/availability failure of the network triggered by an omitted `> 0` input check.

### Likelihood Explanation
Reaching this requires either (a) the current governing node (in "single" governance mode) submitting a header vote for `kip71.gastarget = 0`, or (b) an authorized GC member submitting a `setParamIn`/`setParam` transaction to the `GovParam` contract (KIP-81 on-chain voting) with `kip71.gastarget = 0`. Both are supported, "legitimate" governance-parameter-setting flows explicitly reachable from a submitted transaction (not requiring any node compromise, p2p exploitation, or malicious-validator collusion beyond normal governance rights). Given the format-checker gap is a straightforward oversight (the sibling `BaseFeeDenominator` param already guards against exactly this), and the vote/tx format itself is accepted (confirmed by `TestNewVoteData`'s good-vote cases for `Kip71GasTarget`, none of which reject `0`), the likelihood of this configuration being reachable and unguarded is high, though actually triggering it requires governance-level privilege (single governing node or GC member), making exploitation intentional rather than accidental in most cases.

### Recommendation
Add an explicit non-zero `FormatChecker` for `Kip71GasTarget` analogous to `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
As defense in depth, also guard `NextMagmaBlockBaseFee` in `params/kip71_config.go` against `kc.GasTarget == 0` the same way it already guards `kc.BaseFeeDenominator == 0`, to prevent a panic even if a zero value slips through via some other path (e.g., genesis config, legacy data, or future contract-governance edge cases).

### Proof of Concept
1. Governing node (or GC member via `GovParam.setParamIn`) submits a governance vote/transaction setting `kip71.gastarget = 0`. This passes `NewVoteData`'s canonicalizer/format-checker chain because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`. [6](#0-5) 
2. Once the vote/parameter activates, `ParamSet.GasTarget` becomes `0` for subsequent blocks via `GetParamSet`. [7](#0-6) 
3. On the next block after activation, any node with `parentHeaderGasUsed > 0` computing `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` takes the `parentGasUsed > gasTarget` branch and executes `y := x.Div(x, new(big.Int).SetUint64(0))`, which panics with "division by zero" in Go's `math/big` package. [8](#0-7) 
4. Because this function is invoked both during block proposal and during `VerifyMagmaHeader` by every validating node, the panic occurs network-wide, halting the chain.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
