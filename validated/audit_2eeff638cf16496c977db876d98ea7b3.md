### Title
stSTXbtc / zstSTXbtc Collateral and Debt Valued Using STX Price Instead of BTC Price - (File: mainnet/contracts/utility/v0-1-data.clar)

### Summary
The `get-asset-price` helper in `mainnet/contracts/utility/v0-1-data.clar`, which is used to compute collateral USD value, debt USD value, current LTV, and health factor for an account, resolves the price of `stSTXbtc` and `zstSTXbtc` using the `PYTH-STX` feed instead of the `PYTH-BTC` feed, even though the comments explicitly state these assets should be priced in BTC terms.

### Finding Description
In `get-asset-price`, every other asset branch is correctly mapped to its feed (e.g. `sBTC` → `PYTH-BTC`, `USDC` → `PYTH-USDC`), but the `stSTXbtc` and `zstSTXbtc` branches call `get-pyth-price PYTH-STX` while the accompanying comments say "BTC price (liquid staked STX with BTC yield)": [1](#0-0) 

This same mismap is duplicated verbatim in `local-testing/contracts/utility/protocol-data.clar`'s `get-asset-price`: [2](#0-1) 

This price is consumed by `sum-collateral-usd` and `sum-debt-usd`, which feed directly into `coll-usd`, `debt-usd`, `current-ltv`, and `health-factor` computation: [3](#0-2) 

Because STX's dollar price is orders of magnitude lower than BTC's, using the STX feed for a BTC-tracking asset drastically understates its true USD value. Since `get-asset-price` is used identically for both `sum-collateral-usd` and `sum-debt-usd`, the direction of the error depends on whether `stSTXbtc`/`zstSTXbtc` is held as collateral or as debt:
- As **collateral**, the position's collateral value is understated (hurts the user, not exploitable for theft).
- As **debt**, the position's outstanding debt value is understated relative to its true BTC value, so a borrower's `debt-usd` and `current-ltv` appear far lower than reality — the account looks healthy (or even eligible for further borrowing) while actually holding BTC-value debt priced at STX-value. This benefits the borrower/attacker at the protocol's expense.

### Impact Explanation
I was not able to fully confirm, within the scope of this session, whether `v0-1-data.clar`'s `health-factor` / `is-liquidatable` computation is the actual value consulted by `market/v0-4-market.clar`'s borrow/withdraw/liquidate enforcement path, or whether it is a read-only account-summary helper used only for off-chain display/analytics while `market.clar` independently re-derives health using its own per-asset registered `{type, ident, callcode}` oracle configuration (seen in `resolve-price-feed`/`resolve-callcode` in `v0-4-market.clar`). If this data helper is what gates real borrow/liquidation decisions, the impact is Critical (protocol insolvency / theft of funds via under-collateralized borrowing of a mispriced debt asset). If it is purely a display helper, the impact is limited to incorrect UI/analytics values and would not itself move funds. This distinction could not be conclusively resolved without deeper tracing into `market.clar`'s borrow/liquidate call graph, which I was unable to complete in this pass.

### Likelihood Explanation
No special permissions or configuration mistake are required to trigger the mismap — it fires deterministically any time `get-asset-price` is invoked with `aid = stSTXbtc` or `aid = zstSTXbtc`, which happens whenever a position holds or borrows this asset, i.e., on every account-summary/health computation involving it.

### Recommendation
In `get-asset-price` (both `mainnet/contracts/utility/v0-1-data.clar` and its `local-testing` counterpart `protocol-data.clar`), change the `stSTXbtc` and `zstSTXbtc` branches to call `get-pyth-price PYTH-BTC` instead of `PYTH-STX`, consistent with the existing comments and the `sBTC`/`zsBTC` branches. Additionally, confirm whether this function feeds any on-chain enforcement path in `market.clar`; if so, add a regression test asserting `stSTXbtc`/`zstSTXbtc` USD valuation tracks the BTC feed, not the STX feed.

### Proof of Concept
1. Call the account-summary read-only function in `v0-1-data.clar` (the function containing the code at lines 440-487) for an account holding `stSTXbtc` or `zstSTXbtc` as debt.
2. Observe that `debt-usd` (and therefore `current-ltv` / `health-factor`) is computed using the STX/USD Pyth price rather than the BTC/USD Pyth price for that asset, understating true debt value by the STX:BTC price ratio.
3. If this value is consulted by any enforcement path, a borrower could hold BTC-denominated debt that is treated as if it were worth only the equivalent amount of STX, allowing borrowing beyond actual collateral backing.
