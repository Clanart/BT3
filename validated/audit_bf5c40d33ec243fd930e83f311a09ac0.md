## Title
Attacker can sandwich the `busd`→`mgp` `ROUTER.swapExactTokensForTokens` swap inside `_bullMGP` to inflate `mgpAmountToLcok` and drain the protocol's MGP bonus reserve - (File: `wombat/ArbWomUp2.sol`)

### Summary
`incentiveDeposit(_amount, _minMGPRec, true)` routes a fixed `busdReward` through a live-priced DEX swap in `_bullMGP`, and the resulting `mgpAmountToLcok` (swap output plus a fixed `bullBonusRatio` bonus) is locked directly to the caller's `vlMGP` position. Because the caller supplies `_minMGPRec` themselves and the swap uses the live spot price of `ROUTER` with no TWAP/oracle sanity check, an attacker can sandwich their own `incentiveDeposit(bullMode=true)` call to temporarily depress the `mgp` price, inflate `amounts[1]`, and receive a disproportionately large `mgpAmountToLcok`—including an inflated bonus portion funded from the contract's own pre-funded `mgp` reserve.

### Finding Description
`incentiveDeposit` computes a `busdReward` from a fixed, non-attacker-controlled tier table (`getRewardAmount`, using real WOM deposited) [1](#0-0) , then calls `_bullMGP(rewardToSend, _minMGPRec, msg.sender)`, which swaps `busd` for `mgp` at the router's live spot price and computes `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR`, approving and locking that full amount into `vlMGP` for the caller [2](#0-1) .

Two facts combine to make this exploitable:
1. `_minMGPRec` is fully attacker-controlled (passed straight from the public call), so an attacker can set it to `0` and accept any swap output, defeating slippage protection entirely.
2. `mgpAmountToLcok` scales linearly with `amounts[1]`, the router's real-time swap output, with no TWAP, oracle check, or price-deviation guard.

An attacker can therefore, within a single block/transaction bundle: (a) front-run by trading against the `busd`/`mgp` pool to push the pool price so that `busd`→`mgp` yields more `mgp` per `busd` than fair value, (b) call `incentiveDeposit(_amount, 0, true)`, executing the router swap at the manipulated price and receiving an inflated `amounts[1]`, and thus an inflated `mgpAmountToLcok` (both the swap-derived portion and the `bullBonusRatio` bonus portion, the latter of which is paid out of the contract's own pre-funded MGP balance, since `mgpAmountToLcok` exceeds what was actually received from the swap), and (c) back-run to unwind the manipulation. `whenNotPaused`/`nonReentrant` and receipt-token accounting on `incentiveDeposit` do not address price-manipulation risk; they only prevent reentrancy and pausing.

### Impact Explanation
This falls under theft/permanent loss of unclaimed yield paid from protocol reserves: the `bullBonusRatio` bonus mgp locked into `vlMGP` beyond the fairly-priced swap output is drawn from the contract's own pre-funded `mgp` balance (the bonus can't come from the swap itself, since `mgpAmountToLcok > amounts[1]`). Inflating `amounts[1]` via price manipulation directly increases the bonus mgp drained from this reserve for a fixed, unchanged `busdReward`/WOM cost, i.e., the attacker locks more vlMGP (a token with real voting/yield value) than the protocol intended to pay for that fixed reward tier.

### Likelihood Explanation
Feasibility depends entirely on the depth/liquidity of the specific `busd`/`mgp` pool behind `ROUTER` and the size of `rewardToSend` (which is bounded by tier tables and `busd` balance available) relative to that liquidity: a shallow pool makes this cheaper and more profitable, a deep pool makes the round-trip manipulation cost exceed the bonus gained. The attack is repeatable per eligible WOM deposit tier and requires only capital to move the pool (no privileged role), consistent with the "unprivileged attacker with capital" precondition in the prompt. I could not verify actual on-chain liquidity/depth of the referenced `busd`/`mgp` pool from the repo alone, so exact profitability is unconfirmed without a fork test.

### Recommendation
- Remove attacker control over slippage by enforcing a protocol-computed minimum output derived from a manancipulation-resistant reference price (e.g., a TWAP oracle or a price bound checked against an external oracle), rather than trusting caller-supplied `_minMGPRec`.
- Add a maximum allowed deviation between the router's spot price and a trusted reference price before executing `_bullMGP`'s swap.
- Consider computing the `bullBonusRatio` bonus off of the pre-swap expected/oracle-derived `mgp` value of `_busdAmount` rather than the raw (manipulable) `amounts[1]` swap output.

### Proof of Concept
Foundry/Hardhat fork test plan:
1. Fork BNB chain at a block with an existing low/medium-liquidity `busd`/`mgp` pool on the configured `ROUTER`.
2. Deploy/attach `ArbWomUp2`, configure `setup(busd, mgp, vlMGP, bullBonusRatio, router)`, fund the contract with `busd` and a pre-funded `mgp` bonus reserve, and set up reward tiers via `setMultiplier`.
3. Baseline run: have a user deposit WOM and call `incentiveDeposit(amount, minRec, true)` at unmanipulated pool price; record `mgpAmountToLcok` from the `VLMGPRewarded` event.
4. Attack run: from a fresh state, have the attacker (with enough `mgp`/`busd` capital) submit a bundle: (a) trade against the pool to depress `mgp` price, (b) call `incentiveDeposit(amount, 0, true)` for the same WOM deposit amount/tier, (c) reverse-trade to restore pool price.
5. Compare `mgpAmountToLcok` in the attack run vs the baseline for identical `busdReward`/WOM input; assert the attack run's locked vlMGP amount is measurably higher than the fair-price baseline, and compute attacker net P&L (bonus mgp gained minus round-trip swap fees/slippage) to confirm profitability under the tested pool depth.

```text
    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }
```

```text
    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
```
