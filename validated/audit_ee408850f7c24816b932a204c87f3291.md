### Title
Nonpayable precompile transactions do not reject or refund `msg.value`, permanently locking user funds at the precompile address - ([File: precompiles/common/precompile.go])

### Summary
Cosmos EVM stateful precompiles (staking, gov, distribution, etc.) dispatch transactions through `cmn.SetupABI` / `Execute`, but nowhere in this dispatch path is `contract.Value()` checked against the ABI method's `stateMutability`. Solidity normally prevents a caller from sending value to a `nonpayable` function by generating a bytecode-level check, but that check lives in the *caller's* compiled bytecode, not in the callee. A user can bypass it by crafting a raw call (custom contract, `staticcall`-free low-level `call{value: x}(...)`, or a manually built EVM transaction) that sends non-zero value directly to a nonpayable precompile method such as `staking.delegate`, `gov.deposit`, `distribution.*`, etc. This mirrors the reported Node Operator bug class: a function that can receive ETH but never checks/consumes/returns it.

### Finding Description
`cmn.SetupABI` in [1](#0-0)  resolves the ABI method purely from calldata (or from `contract.Value().Sign() > 0` only for the empty-calldata `receive`/`fallback` case, see [2](#0-1) ). For standard calldata (`standardCallData`), the method is resolved solely by method ID with no validation that `method.StateMutability == "payable"` when `contract.Value().Sign() > 0` [3](#0-2) .

Concretely, `staking.Delegate` is declared `"stateMutability": "nonpayable"` in the ABI [4](#0-3) , and its Go implementation never reads `contract.Value()` at all [5](#0-4) . The staking precompile's `Execute` dispatch also performs no value/mutability check before invoking `Delegate` [6](#0-5) .

Because the go-ethereum EVM `CALL` opcode transfers `value` from caller to callee balance *before* invoking the precompile's `Run`, any ETH sent alongside such a call is deducted from the caller's EVM/bank balance and credited to the precompile's own address balance (e.g. `0x...0800` for staking) at the StateDB/bank level. The WERC20 precompile explicitly handles this by sending the received coins back to the caller via `BankKeeper.SendCoins` in its `Deposit` function [7](#0-6) , proving that receiving-and-refunding value is normally a required precompile responsibility. However, `staking.Delegate` (and other nonpayable transaction methods across the gov/distribution/staking precompiles) have no equivalent logic — they neither consume the value in the underlying Cosmos message nor return it.

Since precompile addresses are not normal user-controlled accounts and have no code path to move out an unexpected balance (no `withdraw`), any native coin sent this way becomes permanently stuck at the precompile's account.

### Impact Explanation
This matches the "Critical permanent freezing/locking/theft of user funds" impact category. Any unprivileged EVM caller who accidentally (or an attacker who tricks a victim contract into) attaches `msg.value` to a nonpayable precompile call permanently loses that value — the coins are deducted from the sender and are not recoverable by any user-facing mechanism, since the precompile's implementation for `Delegate`/`Deposit` (gov)/etc. never processes `contract.Value()`.

### Likelihood Explanation
Direct EOA-originated transactions with calldata generated by a standard ABI-encoding library cannot be tricked into sending value to a nonpayable method (the ABI/tooling refuses), so the primary path requires a contract that forwards `msg.value` to the precompile without going through Solidity's own payable check (e.g., a raw `.call{value: v}(abi.encodeWithSelector(...))`, or a custom-built transaction directly targeting the precompile address with non-empty `value` and valid selector calldata for a nonpayable method). This is plausible for integrators/DeFi contracts that proxy calls to precompiles, and is entirely unprivileged and reachable via ordinary transaction processing — no relayer, validator or governance involvement required.

### Recommendation
Add a mutability check in `cmn.SetupABI` (or in the dispatcher `Execute` of each precompile) that rejects the call — or refunds `contract.Value()` to the caller — whenever `contract.Value().Sign() > 0` and the resolved `method.StateMutability != "payable"`. Alternatively, at minimum, have each transaction handler check `contract.Value()` and revert (mirroring the ETHDeposit report's recommendation) so ETH is never silently absorbed into a precompile's balance without an explicit accounting/refund path, consistent with how `werc20.Deposit` already handles it.

### Proof of Concept
1. Deploy a helper contract with a function:
```solidity
function forceDelegate(address delegator, string calldata valAddr, uint256 amount) external payable {
    STAKING_CONTRACT.delegate{value: msg.value}(delegator, valAddr, amount); 
}
```
(Note: `delegate` is nonpayable in the ABI, so normal Solidity compilation of `IStaking` would reject `{value: ...}` at compile time; the PoC must instead build the low-level call manually, e.g. via inline assembly/`call` opcode with a nonzero `value` and correctly ABI-encoded `delegate(...)` selector/args, bypassing the Solidity-generated payable check.)
2. Call this helper with `msg.value = 1 ether` and `amount = <existing deposit credit / smaller amount>`.
3. Observe: the staking `Delegate` message executes normally using `amount` from calldata, `contract.Value()` (1 ether) is never referenced or refunded, and the caller's EVM balance is reduced by `amount + 1 ether` while only `amount` becomes a delegation — the extra `1 ether` is credited to the staking precompile address `0x...0800`'s bank balance with no code path to reclaim it.

*Note: I was unable to fully verify from the indexed code whether there is a chain-level guard elsewhere (e.g., in the EVM msg handler or ante handler) that rejects value transfers to precompile addresses for nonpayable methods before reaching `RunNativeAction`/`SetupABI`; the dispatch and ABI-setup code reviewed here shows no such check, but a background Devin session with full repo access should confirm this by tracing the complete call path from `x/vm`'s `EVMKeeper.ApplyMessage`/`vm.EVM.Call` through to precompile `Run`.*

// SetupABI runs the initial setup required to run a transaction or a query.
// It returns the ABI method, initial gas and calling arguments.
func SetupABI(
	api abi.ABI,
	contract *vm.Contract,
	readOnly bool,
	isTransaction func(name *abi.Method) bool,
) (method *abi.Method, args []interface{}, err error) {
	// NOTE: This is a special case where the calling transaction does not specify a function name.
	// In this case we default to a `fallback` or `receive` function on the contract.

	// Simplify the calldata checks
	isEmptyCallData := len(contract.Input) == 0
	isShortCallData := len(contract.Input) > 0 && len(contract.Input) < 4
	isStandardCallData := len(contract.Input) >= 4

	switch {
	// Case 1: Calldata is empty
	case isEmptyCallData:
		method, err = emptyCallData(api, contract)

	// Case 2: calldata is non-empty but less than 4 bytes needed for a method
	case isShortCallData:
		method, err = methodIDCallData(api)

	// Case 3: calldata is non-empty and contains the minimum 4 bytes needed for a method
	case isStandardCallData:
		method, err = standardCallData(api, contract)
	}

	if err != nil {
		return nil, nil, err
	}

	// return error if trying to write to state during a read-only call
	if readOnly && isTransaction(method) {
		return nil, nil, vm.ErrWriteProtection
	}

	// if the method type is `function` continue looking for arguments
	if method.Type == abi.Function {
		argsBz := contract.Input[4:]
		args, err = method.Inputs.Unpack(argsBz)
		if err != nil {
			return nil, nil, err
		}
	}

	return method, args, nil
}

// emptyCallData is a helper function that returns the method to be called when the calldata is empty.
func emptyCallData(api abi.ABI, contract *vm.Contract) (method *abi.Method, err error) {
	switch {
	// Case 1.1: Send call or transfer tx - 'receive' is called if present and value is transferred
	case contract.Value().Sign() > 0 && api.HasReceive():
		return &api.Receive, nil
	// Case 1.2: Either 'receive' is not present, or no value is transferred - call 'fallback' if present
	case api.HasFallback():
		return &api.Fallback, nil
	// Case 1.3: Neither 'receive' nor 'fallback' are present - return error
	default:
		return nil, vm.ErrExecutionReverted
	}
}

// standardCallData is a helper function that returns the method to be called when the calldata is 4 bytes or more.
func standardCallData(api abi.ABI, contract *vm.Contract) (method *abi.Method, err error) {
	methodID := contract.Input[:4]
	// NOTE: this function iterates over the method map and returns
	// the method with the given ID
	method, err = api.MethodById(methodID)

	// Case 3.1 calldata contains a non-existing method ID, and `fallback` is not present - return error
	if err != nil && !api.HasFallback() {
		return nil, err
	}

	// Case 3.2: calldata contains a non-existing method ID - 'fallback' is called if present
	if err != nil && api.HasFallback() {
		return &api.Fallback, nil
	}

	return method, nil

// Delegate performs a delegation of coins from a delegator to a validator.
func (p *Precompile) Delegate(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
	method *abi.Method,
	args []interface{},
) ([]byte, error) {
	bondDenom, err := p.stakingKeeper.BondDenom(ctx)
	if err != nil {
		return nil, err
	}
	msg, delegatorHexAddr, err := NewMsgDelegate(args, bondDenom, p.addrCdc)
	if err != nil {
		return nil, err
	}

	p.Logger(ctx).Debug(
		"tx called",
		"method", method.Name,
		"args", fmt.Sprintf(
			"{ delegator_address: %s, validator_address: %s, amount: %s }",
			delegatorHexAddr,
			msg.ValidatorAddress,
			msg.Amount.Amount,
		),
	)

	msgSender := contract.Caller()
	if msgSender != delegatorHexAddr {
		return nil, fmt.Errorf(cmn.ErrRequesterIsNotMsgSender, msgSender.String(), delegatorHexAddr.String())
	}

	// Execute the transaction using the message server
	if _, err = p.stakingMsgServer.Delegate(ctx, msg); err != nil {
		return nil, err
	}

	// Emit the event for the delegate transaction
	if err = p.EmitDelegateEvent(ctx, stateDB, msg, delegatorHexAddr); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

func (p Precompile) Execute(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {
	method, args, err := cmn.SetupABI(p.ABI, contract, readOnly, p.IsTransaction)
	if err != nil {
		return nil, err
	}

	var bz []byte

	switch method.Name {
	// Staking transactions
	case CreateValidatorMethod:
		bz, err = p.CreateValidator(ctx, contract, stateDB, method, args)
	case EditValidatorMethod:
		bz, err = p.EditValidator(ctx, contract, stateDB, method, args)
	case DelegateMethod:
		bz, err = p.Delegate(ctx, contract, stateDB, method, args)
	case UndelegateMethod:
		bz, err = p.Undelegate(ctx, contract, stateDB, method, args)
	case RedelegateMethod:
		bz, err = p.Redelegate(ctx, contract, stateDB, method, args)
	case CancelUnbondingDelegationMethod:
		bz, err = p.CancelUnbondingDelegation(ctx, contract, stateDB, method, args)
	// Staking queries
	case DelegationMethod:
		bz, err = p.Delegation(ctx, contract, method, args)
	case UnbondingDelegationMethod:
		bz, err = p.UnbondingDelegation(ctx, contract, method, args)
	case ValidatorMethod:
		bz, err = p.Validator(ctx, method, contract, args)
	case ValidatorsMethod:
		bz, err = p.Validators(ctx, method, contract, args)
	case RedelegationMethod:
		bz, err = p.Redelegation(ctx, method, contract, args)
	case RedelegationsMethod:
		bz, err = p.Redelegations(ctx, method, contract, args)
	default:
		return nil, fmt.Errorf(cmn.ErrUnknownMethod, method.Name)
	}

	return bz, err
}

// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}
