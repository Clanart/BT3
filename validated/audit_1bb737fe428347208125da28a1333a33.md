[1](#0-0) ### Title
`ReceivedOutput::read` accepts forged “spendable” outputs and can spoof Bitcoin receipts - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput` is defined as a spendable output containing the scalar offset, claimed `TxOut`, and claimed `OutPoint`. [1](#0-0)  Its deserializer accepts those three fields independently and performs no check that the outpoint exists, resolves to the claimed output, or was produced by `Scanner`. [2](#0-1) 

### Finding Description
Legitimate outputs are constructed by `Scanner::scan_transaction`, which both requires the output’s `script_pubkey` to be registered and derives the outpoint from the containing transaction. [3](#0-2)  `ReceivedOutput::read` bypasses that construction path and lets untrusted bytes supply an arbitrary `offset`, `TxOut`, and `OutPoint` tuple. [4](#0-3) 

`SignableTransaction::new` trusts the embedded `TxOut` as the input value and the embedded `OutPoint` as the transaction input. [5](#0-4)  It preserves the claimed `TxOut` as the prevout committed to by the Taproot sighash. [6](#0-5)  The later multisig check validates only that applying the supplied offset to the threshold key produces the claimed `script_pubkey`; it does not authenticate the claimed outpoint or its on-chain output. [7](#0-6) 

An attacker can therefore use `offset = 0`, the wallet’s ordinary P2TR script, an arbitrary amount, and a nonexistent or unrelated `OutPoint`. [8](#0-7)  That object reports the attacker-selected amount as received and can pass the wallet’s key/script consistency check despite not representing a spendable UTXO. [7](#0-6) 

### Impact Explanation
This is an analog of security-UI spoofing: attacker-controlled bytes cause the wallet state to present a received, spendable Bitcoin output when no such output was observed or is spendable. [1](#0-0)  Downstream transaction construction will then sign a transaction referencing the forged input, while Bitcoin consensus rejects it because the referenced UTXO is absent or has different contents. [9](#0-8)  The result is false balance attribution and wasted or stalled threshold-signing attempts for funds reported received but not spendable. [10](#0-9) 

### Likelihood Explanation
The forged object requires no private key, threshold cooperation, or cryptographic break; it only requires an attacker-controlled byte stream reaching `ReceivedOutput::read`. [2](#0-1)  Selecting a valid registered script is sufficient to pass the later key-offset check because the check does not compare the outpoint against blockchain state. [7](#0-6) 

### Recommendation
Do not expose `ReceivedOutput::read` as an authority-producing deserialization API for untrusted input. Either make construction private to `Scanner`, or require a validation step that resolves the claimed `OutPoint` against confirmed blockchain data, compares the full `TxOut`, and verifies the script belongs to a registered scanner offset. [3](#0-2)  At minimum, rename/document the current deserializer as requiring trusted bytes and re-scan the referenced transaction before accounting or signing. [11](#0-10) 

### Proof of Concept
```rust
use bitcoin::{
  consensus::encode::serialize,
  Amount, OutPoint, TxOut,
};
use k256::Scalar;
use frost::{curve::Secp256k1, Participant};
use bitcoin_serai::wallet::{
  tweak_keys, p2tr_script_buf, ReceivedOutput, SignableTransaction,
};

fn forged_received_output(
  keys: &frost::ThresholdKeys<Secp256k1>,
) {
  // A normal, tweaked wallet key produces the wallet's base P2TR script.
  let script = p2tr_script_buf(keys.group_key()).unwrap();

  // Claim a large output at an outpoint never produced by Scanner.
  let claimed_output = TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: script.clone(),
  };
  let fake_outpoint = OutPoint::default();

  // Serialization format: scalar || consensus TxOut || consensus OutPoint.
  let mut bytes = Scalar::ZERO.to_bytes().to_vec();
  bytes.extend(serialize(&claimed_output));
  bytes.extend(serialize(&fake_outpoint));

  // Accepted without checking that fake_outpoint resolves to claimed_output.
  let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
  assert_eq!(forged.value(), 1_000_000);
  assert_eq!(forged.outpoint(), &fake_outpoint);

  // The forged object is accepted into transaction construction.
  let signable = SignableTransaction::new(
    vec![forged],
    &[],
    Some(script),
    None,
    20,
  )
  .unwrap();

  // The key/script check succeeds because offset 0 does derive the claimed
  // script, even though the claimed outpoint is not a spendable wallet UTXO.
  assert!(signable.multisig(keys).is_some());
}
```

The essential primitive is that `ReceivedOutput::read` creates the claimed “spendable output” without reconstructing it from `Scanner` or verifying the `OutPoint` against confirmed blockchain data. [4](#0-3)
