### Title
`ReceivedOutput::read` accepts untrusted outputs without verifying the offset actually derives the output's `script_pubkey`, allowing unspendable outputs to be reported as received - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The external report describes a validation that checked a bound at too coarse a granularity (day-of-week equality instead of same-day) combined with a missing upper-bound check, letting values outside the intended domain pass validation. The analog in Serai's bitcoin crate is `ReceivedOutput::read`: it deserializes a `(offset, output, outpoint)` triple from untrusted bytes while performing zero semantic validation that the claimed `offset` scalar actually derives the Taproot `script_pubkey` present in `output`. The in-band constructor path (`Scanner::scan_transaction`) guarantees this binding by construction; the deserialization path drops it entirely.

### Finding Description
`Scanner` maintains a `HashMap<ScriptBuf, Scalar>` (`scripts`) keyed by the P2TR script of `key + offset·G`, so any `ReceivedOutput` produced by `scan_transaction` is guaranteed spendable via `key.offset(offset)` [1](#0-0) . However, `ReceivedOutput::read` reconstructs the same type from raw bytes — a `Secp256k1` scalar via `read_F`, a `TxOut`, and an `OutPoint` — and returns `Ok` unconditionally, never re-deriving `p2tr_script_buf(self.key + GENERATOR * offset)` and comparing it to `output.script_pubkey` [2](#0-1) . This mirrors the Buffer bug class: the "real" path enforces a tight domain constraint, but an alternate entry point accepts values from a strictly larger domain with only syntactic checks — analogous to `setMaxPeriod` checking only `value >= 1 minutes` and `isInCreationWindow` checking only weekday equality.

### Impact Explanation
An attacker who can feed crafted bytes to `ReceivedOutput::read` (listed as a reachable untrusted-bytes entry point) causes the wallet layer to report funds as received under a scalar offset that does not control the output. Downstream spending (`wallet/send.rs`) derives the signing key from `offset`, producing signatures for a key that does not match the output's `script_pubkey`; the output is unspendable despite being accepted as received. This satisfies the "funds reported received that are not spendable" impact criterion.

### Likelihood Explanation
Exploitation requires an attacker to control or inject the serialized `ReceivedOutput` byte stream (e.g., a corrupted or forged message consumed by a component that deserializes outputs rather than scanning them). It does not require key compromise or threshold collusion — only control over untrusted bytes passed to `read`. The severity is bounded by the fact that the honest scanning path is unaffected; only deserialization consumers are exposed, hence Medium.

### Recommendation
Bind the offset to the output at deserialization time. `ReceivedOutput::read` must take (or be given) the scanned `ProjectivePoint` key and verify `p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset) == Some(output.script_pubkey)`, rejecting otherwise — analogous to checking the exact day rather than the day of week, and to adding an upper bound to `setMaxPeriod`. Alternatively, make `read` a method on `Scanner` so the existing `scripts` map is the single source of truth for offset→script validity.

### Proof of Concept
```rust
// Attacker-controlled bytes: honest offset scalar, but an output paying
// to an arbitrary script_pubkey (e.g., the attacker's own P2TR key).
let mut bytes = vec![];
bytes.extend(Scalar::ZERO.to_bytes());            // valid offset for `key`
bytes.extend(serialize(&TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: attacker_p2tr_script,           // not derivable from key+offset*G
}));
bytes.extend(serialize(&OutPoint::new(txid, 0)));

// Accepted unconditionally — no key/output binding is checked.
let output = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
// `output.offset()` == 0 implies spendability by `key`, but the output is
// actually controlled by the attacker; any spend attempt fails signature checks.
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
