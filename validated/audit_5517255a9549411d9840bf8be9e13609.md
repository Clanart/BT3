### Title
Schnorr verification accepts the identity public key, enabling universal signature forgeries - (File: crypto/schnorr/src/lib.rs)

### Summary
`SchnorrSignature::verify` does not reject the identity point as either the signature nonce commitment `R` or the public key. Because `Ciphersuite::read_G` accepts canonical identity encodings, an attacker can submit an identity public key and a trivial identity/zero Schnorr signature that verifies under every challenge.

### Finding Description
`SchnorrSignature::read` deserializes `R` through `C::read_G` and `s` through `C::read_F` without an identity check. [1](#0-0)  The generic `Ciphersuite::read_G` implementation only checks that the point decodes and re-encodes canonically; it does not reject the identity point. [2](#0-1)  Verification then evaluates `R + cA - sG == 0` without validating that `R` or `A` is non-identity. [3](#0-2) 

For `A = 0`, `R = 0`, and `s = 0`, the equation becomes `0 + c·0 - 0·G = 0`, so the signature verifies for every challenge and message.

### Impact Explanation
Any verification path that accepts an identity public key—for example, a public key deserialized through `Ciphersuite::read_G` or supplied as an optional/default key—can be bypassed with a deterministic forged signature. This is analogous to accepting `address(0)` as a manager: the supposedly required key is absent, but the operation still succeeds.

### Likelihood Explanation
The attack requires the verifier to accept an identity public key as input. `read_G` permits that encoding, and `SchnorrSignature::verify` performs no fallback validation, so no secret information, malformed encoding, or malicious validator is required.

### Recommendation
Reject identity points in `SchnorrSignature::read`/`verify`, or expose and require a `Curve::read_G`-style public-key decoder that rejects identity. At minimum, `verify` should return false when `public_key` or `R` is identity.

### Proof of Concept
```rust
use ciphersuite::{
  Ciphersuite,
  group::{ff::Field, Group},
};
use dalek_ff_group::Ristretto;
use schnorr::SchnorrSignature;

let identity = <Ristretto as Ciphersuite>::G::identity();
let signature = SchnorrSignature::<Ristretto> {
  R: identity,
  s: <Ristretto as Ciphersuite>::F::ZERO,
};

// Any challenge verifies because both R and the public key are identity.
assert!(signature.verify(identity, <Ristretto as Ciphersuite>::F::ONE));
```

The same values can be supplied through public encodings: `SchnorrSignature::read` accepts the canonical identity encoding for `R`, while `Ciphersuite::read_G` accepts the canonical identity encoding for the public key. [1](#0-0) [2](#0-1)
