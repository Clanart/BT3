## Valid Analog Found

### Title
`mWOMSVBaseRewarder._calExpireForfeit` hardcodes `rewardableAmount = _amount`, permanently bypassing the early-unlock forfeit mechanism for mWOMSV reward claims - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder.sol`'s internal forfeit calculation never actually computes a user's rewardable percentage; it hardcodes the full reward amount as "rewardable," which means the forfeit penalty that is supposed to apply to users unlocking mWOMSV early is always zero. This is structurally identical to the reported bug class: a value that should be dynamically derived per-user/per-request is instead hardcoded to a constant, silently defeating the intended charge/penalty logic.

### Finding Description
In `rewards/mWOMSVBaseRewarder.sol`, `_calExpireForfeit` is: [1](#0-0) 

`rewardableAmount` is set equal to `_amount` unconditionally, so `forfeitAmount = _amount - rewardableAmount` is always `0`, regardless of the account's actual lock/cooldown state.

Compare this to the sibling contract `rewards/vlMGPBaseRewarder.sol`, which implements the same function correctly by querying the locker for the user's actual rewardable percentage: [2](#0-1) 

`VLMGP.sol` defines `getRewardablePercentWAD(_user)`, which computes a reduced rewardable percentage for MGP that is in a cooldown/unlocking slot rather than fully locked: [3](#0-2) 

`mWOMSVBaseRewarder` holds a reference to its locker via `ILocker public mWOMSV` and could call the equivalent `mWOMSV.getRewardablePercentWAD(_account)`, but `_calExpireForfeit` never does so — it substitutes the hardcoded `_amount` in place of a real percentage-weighted computation, exactly mirroring the "hardcoded `periods=1`" defect from the external report (a constant is used where a caller/state-derived variable was required).

The forfeited amount is meant to be redistributed to other reward-pool participants via `_queueNewRewardsWithoutTransfer`: [4](#0-3) 
Because `forfeitAmount` is always `0`, this redistribution path is dead code for the mWOMSV rewarder — no yield is ever forfeited or redistributed, no matter how early a user unlocks mWOMSV.

### Impact Explanation
Any ordinary wallet holding mWOMSV that unlocks/cools down early and then calls `getReward`/`getRewards` on `mWOMSVBaseRewarder` receives 100% of its accrued reward instead of the reduced, penalty-adjusted amount intended by the protocol design (as evidenced by the parallel, correctly-implemented `vlMGPBaseRewarder`). The forfeited yield that should have been redistributed to long-term/fully-locked stakers via `_queueNewRewardsWithoutTransfer` is permanently lost to those honest stakers — this is a direct, permanent loss of unclaimed yield for other unprivileged participants in the mWOMSV reward pool, reachable by any wallet through the normal unlock-and-claim flow, with no privileged actor involved.

### Likelihood Explanation
High likelihood: this requires no special conditions — any mWOMSV holder can start an unlock/cooldown and immediately claim rewards through the standard `getReward`/`getRewards` path, always receiving the undiminished amount. The bug is deterministic and triggers on every claim, not an edge case.

### Recommendation
Mirror the `vlMGPBaseRewarder` implementation: query `mWOMSV.getRewardablePercentWAD(_account)` and scale `_amount` by that percentage instead of assigning `rewardableAmount = _amount` directly, e.g.:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    ...
}
```

### Proof of Concept
1. User stakes mWOMSV in `MasterMagpie`/`mWOMSVBaseRewarder` and accrues reward via `rewardPerToken` accounting.
2. User calls `VLMGP`-analogous unlock/cooldown flow on the mWOMSV locker to begin cooling down part or all of their locked balance (partially "unvesting" per `getRewardablePercentWAD` semantics used elsewhere in the protocol).
3. User (or `MasterMagpie` on their behalf) calls `getReward`/`getRewards` on `mWOMSVBaseRewarder`, which internally calls `_sendReward` → `_calExpireForfeit`.
4. `_calExpireForfeit` returns `forfeitAmount = 0` unconditionally (since `rewardableAmount` was hardcoded to `_amount`), so the user receives the entire `userRewards[...]` balance with no penalty, and `_queueNewRewardsWithoutTransfer` is never invoked to compensate the remaining pool participants.     function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
