## Analog Found

### Title
Out-of-bounds buffer read in CLVM canonical-encoding check during mempool spend-bundle processing - (File: `chia/full_node/mempool_manager.py`)

### Summary
The CVE-2018-13867 bug class is an out-of-bounds read caused by trusting an internally-computed length/offset to index into a buffer without validating that the offset stays inside the buffer's actual bounds. The same pattern exists in `is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py`, which parse the raw CLVM byte-serialization of a submitted spend bundle's puzzle/solution to decide `ELIGIBLE_FOR_DEDUP` status [1](#0-0) .

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the length-prefix byte at `offset`, computes a multi-byte atom length (`atom_len`) directly from attacker-controlled bytes, and then repeatedly indexes `clvm_buffer[offset]` while incrementing `offset` for each prefix byte, with no check that `offset` remains `< len(clvm_buffer)` [2](#0-1) . The caller, `is_clvm_canonical()`, then advances its own cursor by the returned `1 + prefix_len + atom_len` and immediately re-indexes `clvm_buffer[offset]` at the top of the next loop iteration without first checking that the new offset is within bounds [3](#0-2) . Because `atom_len` is derived from up to 5 additional length bytes an attacker fully controls, a truncated or malformed CLVM buffer (a puzzle reveal or solution shorter than what its own length-prefix claims) drives `offset` past `len(clvm_buffer)`, causing a raw Python `IndexError` inside buffer indexing — the direct analog of `H5F__accum_read` dereferencing past the end of its accumulator buffer due to insufficient bounds validation of an internally trusted size field.

This canonical-form check exists specifically to gate `ELIGIBLE_FOR_DEDUP` handling for spend bundles submitted to the mempool [4](#0-3) , meaning it runs on attacker/wallet-supplied CLVM bytes as part of ordinary spend-bundle admission — reachable by any unprivileged spend-bundle submitter, exactly matching the "reachable by wallet/spend-bundle submitter" requirement.

### Impact Explanation
An unhandled `IndexError` raised while evaluating dedup-eligibility for a submitted spend bundle is a spend-triggered exception in mempool item processing. Depending on whether this path is wrapped by exception handling further up the call chain (not confirmed from available context), this can surface as an uncaught exception during `add_spend_bundle()`/dedup evaluation, degrading or halting normal transaction admission for that spend and potentially destabilizing mempool processing — the "spend-triggered transaction-processing halt" impact category. This is not a memory-safety issue in Python (no corruption), but it is the direct analog of the reported bug class: reading past a buffer's logical bounds because a length field taken from untrusted input is trusted without validation against the buffer's real size.

### Likelihood Explanation
Reachable trivially: any spend bundle whose puzzle reveal or solution bytes are shorter than what an embedded (possibly deliberately malformed) atom length-prefix claims will trigger this code path when the mempool evaluates it for dedup eligibility, requiring no special privileges beyond submitting a spend bundle.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (raising a handled `ValueError`/returning "not canonical" instead of indexing past the end), and add a length check in `is_clvm_canonical()` before dereferencing `clvm_buffer[offset]` on each loop iteration, so malformed/truncated buffers fail gracefully with a caught exception rather than an unhandled `IndexError`.

### Proof of Concept
Construct a `CoinSpend` whose solution/puzzle-reveal CLVM bytes begin with a multi-byte atom length prefix (e.g. `0xF8`) that declares an oversized `atom_len`/additional prefix bytes but is truncated so the buffer ends before those bytes exist, then submit it as part of a `SpendBundle` to `MempoolManager.add_spend_bundle()`; when the mempool evaluates dedup eligibility it invokes `is_clvm_canonical()`/`is_atom_canonical()` on this buffer, triggering out-of-bounds indexing [5](#0-4) .

**Note on confidence**: I could not retrieve the exact call site invoking `is_clvm_canonical()` (only its definition and test references were available within the tool-call budget), so I cannot confirm with certainty whether the resulting exception is caught and merely rejects the one spend bundle, or whether it can propagate further. This should be verified against the actual caller before treating this as a confirmed halting condition.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

## Canonical serialization

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.
