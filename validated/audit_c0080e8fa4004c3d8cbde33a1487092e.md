Found a concrete NULL Pointer Dereference analog reachable from an unprivileged auction bidder RPC call.

### Title
NULL Pointer Dereference (DoS) in `EncodeData` via unchecked `Bid.Bid` field in `kaiax/auction/impl/bid_pool.go` bid validation path - (File: `kaiax/auction/eip712.go`)

### Summary
The auction bidding subsystem accepts a `Bid` submitted by any external searcher via the `SubmitBid` RPC or via `HandleBid` peer/RPC intake, then computes an EIP-712 digest to validate the searcher signature. The digest-computation code dereferences `b.Bid.Bytes()` (a `*big.Int` field fully controlled by the untrusted caller) without a nil check, unlike the `MaxGasPrice` field on the same struct which is explicitly nil-guarded a few lines below. This mirrors the LibSass NULL-pointer-dereference bug class (JLSEC-2026-503): a crafted/malformed field on an attacker-supplied structure reaches an operation (`operator()`/`Bytes()`) without a null guard, crashing the process.

### Finding Description
`BidData.Bid` is declared as `*big.Int` with no enforced non-nil invariant at decode time: [1](#0-0) 

`EncodeData()` (used for the v2.1 EIP-712 struct hash, invoked by `GetHashTypedData`) directly calls `b.Bid.Bytes()`: [2](#0-1) 

Contrast this with the v3.0 encoder in the same file, which explicitly guards the sibling `*big.Int` field `MaxGasPrice` against nil before calling `.Bytes()`: [3](#0-2) 

The call chain from an unprivileged RPC caller is:
`AuctionAPI.SubmitBid` → `ToBid(bidInput)` → `bidPool.AddBid(bid)` → `validateBid(bid)` → `validateBidSigs(bid)` → `bid.ValidateSearcherSig(...)` → `GetHashTypedData(...)` → `EncodeEIP712(b)` → `b.EncodeData()` → `b.Bid.Bytes()`. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

`validateBid` checks bid amount is positive (`bid.Bid.Sign() <= 0`) but this itself would already panic if `bid.Bid` is nil, since `Sign()` is a method on `*big.Int` that dereferences the receiver: [9](#0-8) 

The `BidInput`/`ToBid` conversion (RPC-facing JSON decode) and RLP `DecodeRLP` for `Bid` (peer-facing `HandleBid` intake) do not appear to enforce that the `Bid` (or `bid`) numeric field is present/non-nil before it reaches `validateBid`/`EncodeData`: [10](#0-9) 

If a JSON RPC payload for `SubmitBid` omits the `bid` field (or a malformed peer-received bid RLP-decodes it to a nil `*big.Int`), `bid.Bid` remains `nil`. This would already panic in `bid.Bid.Sign()` inside `validateBid` before even reaching `EncodeData`, since Go big.Int methods dereference the receiver pointer.

### Impact Explanation
A single external caller (searcher/bidder, unauthenticated at the RPC and node-level auction gossip layer) can trigger a nil pointer dereference panic in the node process by submitting a bid with a missing/nil `Bid` amount field. Because Go panics from nil pointer dereferences (unless recovered) crash the goroutine and can bring down the node process if not wrapped in a `recover()` at the relevant call site, this is a Denial-of-Service vector — directly analogous to the LibSass advisory's "NULL Pointer Dereference ... may cause a Denial of Service (application crash) via a crafted input."

### Likelihood Explanation
The `SubmitBid` RPC endpoint and `HandleBid` peer path are both reachable by any external, unprivileged party who can talk to a node's public RPC or auction gossip channel — no special permission or existing balance is required to submit a bid object. Constructing a bid JSON/RLP payload with a missing/zero-valued big.Int is trivial for an attacker.

### Recommendation
Add explicit nil checks for `BidData.Bid` (and any other `*big.Int`/pointer fields consumed by `validateBid`, `EncodeData`, and `getBidTxGasLimit`) immediately after decode (in `ToBid`, `DecodeRLP`, or as the very first check in `validateBid`), mirroring the pattern already used for `MaxGasPrice` in `bidV3.EncodeData`. Reject bids with nil/missing numeric fields with a defined error (e.g., extend `ErrZeroBid`/add `ErrNilBidAmount`) before any dereference occurs.

### Proof of Concept
1. Craft a `SubmitBid` RPC call (or a raw peer `HandleBid` bid message) whose JSON/RLP payload omits the `bid` numeric field, causing it to decode to a nil `*big.Int` in `BidData.Bid`.
2. Submit via the `auction_submitBid` RPC method (`AuctionAPI.SubmitBid`) or via the peer bid-gossip handler.
3. `BidPool.AddBid` → `validateBid` executes `bid.Bid.Sign()` on the nil pointer, panicking the calling goroutine; if unrecovered in that code path, the node process crashes — a remote unauthenticated DoS.

Note: I could not fully verify from the indexed code whether `ToBid`/JSON unmarshalling of `BidInput` enforces `bid` as a mandatory non-nil field (encoding/json unmarshals a missing JSON number into a nil `*big.Int` by default unless custom UnmarshalJSON exists), nor whether there's a `recover()` wrapping the RPC handler that would only turn this into an RPC error response rather than a full node crash. This should be confirmed with a live/dynamic test or by inspecting `BidInput`'s JSON tags and any goroutine-level `recover()` in the JSON-RPC server before treating this as fully confirmed Medium/High severity.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
