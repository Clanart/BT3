### Title
Missing amount-binding check in `optimistic_payout` allows N-of-N signatures for a payout amount never recorded on Citrea - (File: core/src/rpc/aggregator.rs)

### Summary
`AggregatorServer::optimistic_payout` (core/src/rpc/aggregator.rs:1010-1126) validates that the attacker-supplied `input_outpoint` matches the withdrawal outpoint stored from the Citrea record, but never compares the attacker-supplied `output_amount` against any amount recorded on Citrea for that withdrawal. The only gate on the payout value is a Schnorr signature check against `user_xonly_pk` — the key of the withdrawal UTXO itself, which the withdrawer fully controls and can sign over any amount they choose. This lets the withdrawer obtain N-of-N partial signatures for a `create_optimistic_payout_txhandler` output whose value was never authorized by the Citrea withdrawal record.

### Finding Description
The invariant that should hold is: `output_amount` used to build the optimistic payout transaction == the withdrawal amount `X` that the Citrea Bridge contract recorded for `withdrawal_id`/`deposit_id`.

In `optimistic_payout`:
- `parser::operator::parse_withdrawal_sig_params` extracts `output_script_pubkey` and `output_amount` directly from the attacker-supplied `WithdrawParams`/`OptimisticWithdrawParams` [1](#0-0) .
- The only DB-backed check is on the outpoint: `withdrawal_utxo != input_outpoint` [2](#0-1) . There is no corresponding query/comparison for a recorded withdrawal amount.
- `output_txout` is built straight from the attacker-controlled `output_amount`/`output_script_pubkey` and fed into `create_optimistic_payout_txhandler` together with `deposit_data` (which carries the deposit's move-to-vault UTXO) [3](#0-2) .
- The only re-validation before N-of-N nonce/signature collection is `SECP.verify_schnorr(...)` against `user_xonly_pk`, which is derived from the withdrawal UTXO's own taproot script_pubkey [4](#0-3) . Since the withdrawer owns that UTXO's private key, they can produce a valid `SinglePlusAnyoneCanPay` signature for *any* `output_amount`/`output_script_pubkey` they like — this check only proves "the withdrawer authorized this specific output," not "this output matches what Citrea recorded."
- Contrast with the sibling `Operator::withdraw` path, which explicitly bounds the payout via `Self::is_profitable(input_utxo.txout.value, output_txout.value, bridge_amount, operator_withdrawal_fee_sats)` before funding the transaction [5](#0-4) . No equivalent amount-bounding check exists in the aggregator's optimistic path.

Because the N-of-N-cosigned output value in `optimistic_payout` is never checked against the amount Citrea's Bridge contract recorded for that `deposit_id`, a withdrawer who registered withdrawal amount `X` on Citrea can call the aggregator with a self-signed sighash for amount `Y != X` and still obtain valid N-of-N partial signatures spending from the move-to-vault-derived transaction.

### Impact Explanation
If exploited, N-of-N partial signatures are produced for a spend from the deposit's move-to-vault-linked UTXO paying out an amount that was never authorized by the corresponding Citrea withdrawal record — this is a direct instance of "N-of-N partial signatures for an unauthorised spend" and can result in BTC leaving custody without a matching fronted/authorized withdrawal amount. The blast radius is per-deposit: any deposit that is Citrea-withdrawn is subject to this gap, since the check is identical for every `deposit_id`/`withdrawal_id`. The attacker (the withdrawer) can repeat this for any deposit they control the withdrawal-key for, up to the value available in the transaction's inputs (Bitcoin's conservation of value still caps `Y` by the sum of inputs, but `Y` need not equal the Citrea-recorded `X`).

### Likelihood Explanation
Preconditions: the attacker must be a legitimate depositor/withdrawer who has registered a withdrawal on Citrea (permitted per the threat model — attacker can call `withdraw` on the Citrea Bridge contract and choose the withdrawal UTXO bytes) and must know their own withdrawal UTXO's private key to sign arbitrary sighashes (trivial, since it is their own UTXO). No collusion with verifiers, operators, or key compromise is required. The check that is missing (amount vs. Citrea record) is a straightforward oversight relative to the parallel `is_profitable` check present in `Operator::withdraw`, making this a credible, low-cost, repeatable path (cost: standard Bitcoin fees plus a Citrea withdrawal transaction).

### Recommendation
Before building `output_txout` and invoking `create_optimistic_payout_txhandler`, fetch the withdrawal's recorded amount from the Citrea client/DB (analogous to `get_withdrawal_utxo_from_citrea_withdrawal`) and assert `output_amount == recorded_amount` (or apply the same `is_profitable`-style bound already used in `Operator::withdraw`) before allowing verifiers to nonce/sign. Reject the request otherwise.
