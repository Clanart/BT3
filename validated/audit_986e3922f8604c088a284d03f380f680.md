### Title
Unchecked type assertion on attacker-controlled CW20/CW721/CW1155 contract-info JSON causes a Go panic in the `pointer` precompile - (File: precompiles/pointer/pointer.go)

### Summary
The `addCW20Pointer`, `addCW721Pointer`, and `addCW1155Pointer` methods of the `pointer` EVM precompile query an attacker-deployable CosmWasm contract for its `token_info`/`contract_info`, JSON-decode the response into a `map[string]interface{}`, and then perform a single-value (unchecked) type assertion `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)` to extract the name/symbol before constructing the ERC pointer contract. This is analogous to the CVE-2019-9776 class of bug: unguarded interpretation of externally-supplied/parsed data leads directly to a runtime crash (there, a NULL pointer dereference in `dwg_dxf_LTYPE`; here, a Go interface-conversion panic) because the code never validates that the parsed field exists or is of the expected type before dereferencing/casting it.

### Finding Description
`AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` accept an arbitrary CosmWasm contract address supplied by any EVM caller as the pointer's target: [1](#0-0) [2](#0-1) [3](#0-2) 

The code calls `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, ...)` on the caller-chosen contract, `json.Unmarshal`s the raw response into an untyped `map[string]interface{}`, then does:
```go
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
without using the two-value `v, ok := formattedRes["name"].(string)` form and without checking `ok`. If a malicious/careless CosmWasm contract's `token_info`/`contract_info` query handler returns a JSON object that omits the `"name"` or `"symbol"` key (map lookup returns `nil`) or returns a non-string value for those keys (e.g., a number, bool, or nested object), the type assertion panics with `interface conversion: interface {} is nil, not string` (or similar), because the contract fully controls the shape of its own query response and there is no schema validation before the assertion.

This mirrors the LibreDWG bug class: externally-controlled, weakly-validated structured data (there DWG binary, here contract-returned JSON) is dereferenced/cast assuming a well-formed shape, and the absence of a defensive check turns malformed input directly into a crash.

### Impact Explanation
The panic occurs inside the precompile's `Execute`/`AddCW20`/`AddCW721`/`AddCW1155` path, which runs during EVM message execution for the `addCW20Pointer`, `addCW721Pointer`, and `addCW1155Pointer` calls in `precompiles/pointer/pointer.go`. Whether this crash is limited to the single transaction (recovered by an upstream `recover()` in EVM execution / `runTx`) or propagates further depends on where the panic is caught. No `recover()` was found directly wrapping the pointer precompile's `AddCW20`/`AddCW721`/`AddCW1155` methods (recover calls exist in `distribution`, `wasmd`, `auth`, `authz`, `addr`, `bank` precompiles and in `x/evm/keeper/msg_server.go`, but confirming whether that outer msg-server-level recover fully protects this specific precompile call path, or whether it happens before the outer recover is installed, could not be fully verified with the available tooling). If uncaught by an appropriate recover boundary, any transaction sender can deterministically crash the node processing the block (or at minimum abort/fail the transaction with an unrecoverable panic instead of a graceful `error`), which is a Medium/High-severity availability issue reachable by any address that deploys a trivial CW20/CW721/CW1155 contract and calls the pointer precompile against it.

### Likelihood Explanation
Likelihood is high for reachability: any unprivileged EVM caller can (1) instantiate a minimal CosmWasm contract whose `token_info`/`contract_info` query handler returns JSON without a `name` or `symbol` field (or with a non-string value), and (2) call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the `pointer` precompile (address `0x000000000000000000000000000000000000100b`) passing that contract's bech32 address as `args[0]`. No privileged role, governance action, or special network condition is required — a wasm contract deployer/caller can trigger this from a single submitted transaction.

### Recommendation
Use the safe two-value type assertion form and return a proper `error` instead of panicking when the CW20/CW721/CW1155 response is missing or has the wrong type for `name`/`symbol`:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info response missing valid name field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info response missing valid symbol field")
}
```
Apply this fix to all three call sites (`AddCW20`, `AddCW721`, `AddCW1155`) in `precompiles/pointer/pointer.go`, and audit the legacy pointer precompile versions (`precompiles/pointer/legacy/v552`…`v67`) which contain the same unchecked-assertion pattern, for consistency across historical EVM upgrade handlers.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` (or `contract_info`) query handler returns `{"decimals": 6}` (omitting `"name"` and `"symbol"`), or `{"name": 123, "symbol": 456}` (wrong JSON types).
2. From any EVM account, call `addCW20Pointer(contractAddr)` (or `addCW721Pointer`/`addCW1155Pointer`) on precompile `0x000000000000000000000000000000000000100b`.
3. Execution reaches:
```go
res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
...
formattedRes := map[string]interface{}{}
json.Unmarshal(res, &formattedRes)
name := formattedRes["name"].(string)   // panics: interface conversion: interface {} is nil, not string
``` [4](#0-3) 
causing a runtime panic instead of a handled error.
