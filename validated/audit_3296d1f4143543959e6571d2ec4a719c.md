### Title
External payments to internal Branch/Change/Forwarded script offsets are silently discarded, crediting received funds as non-existent - (File: processor/src/multisigs/mod.rs)

### Summary
`Scanner::scan_transaction` classifies an output purely by `script_pubkey` lookup, mapping it to whatever offset was registered for that script. The processor registers three internal offsets (`Branch`, `Change`, `Forwarded`) derived by `hash_to_F` over fixed public strings against the public group key. Any unprivileged external party can compute these addresses and pay to them; the resulting outputs are retained only if `kind == OutputType::External`, so they are silently dropped from the batch instructions and never credited — the multisig reports no receipt even though spendable funds arrived.

### Finding Description
`Scanner` maps each registered `ScriptBuf` to a scalar offset (`scripts: HashMap<ScriptBuf, Scalar>`), and `scan_transaction` returns every output whose `script_pubkey` matches, attaching only the offset — the "kind" is just whatever offset produced that script [1](#0-0) . The processor builds the full scanner with fixed public offsets `hash_to_F(KEY_DST, b"branch")`, `b"change"`, `b"forward"` keyed on the public `group_key` [2](#0-1) , so these addresses are computable by anyone who knows the public key. In `Bitcoin::get_outputs` each scanned output is tagged with its kind via `kinds[offset_repr]` [3](#0-2) . Then `scanner_event_to_multisig_event` executes `outputs.retain(|output| output.kind() == OutputType::External)` and only the retained outputs become deposit instructions [4](#0-3) . An output received at the `Change`/`Branch`/`Forwarded` script is consumed by the `seen`/`ram_outputs` dedup path in the scanner (it is recorded as scanned) yet produces no `InInstruction`, so the funds are never credited and are never revisited.

### Impact Explanation
Analogous to CVE-2019-18460's incorrect access control on data classification, here the output-classification boundary is incorrect: funds genuinely received by the multisig are classified as internal traffic and excluded from deposit handling. An external sender can deliberately (or accidentally, e.g., an integrator reusing the change-address derivation) send BTC to these derivable addresses; the processor records the output as seen, emits no instruction, and the credited balance omits the funds. Since the output is marked `seen`, it will not be rescanned, so the coins become stranded in the multisig accounting even though they are technically key-spendable — an unrecoverable-by-protocol loss equivalent to "received funds not spendable/reported".

### Likelihood Explanation
The attacker's only requirement is knowledge of the group public key (public) and the constants `KEY_DST = b"Serai Bitcoin Output Offset"` / `"branch"` / `"change"` / `"forward"` — all in-tree. `register_offset` may bump an offset by +1 for even-Y parity, but the resulting script is still deterministic and publicly computable [5](#0-4) . No validator collusion, key material, or authenticated channel is needed; the attacker broadcasts a normal Bitcoin transaction. Medium likelihood: the funds are the attacker's own, but griefing/accidental integrator use permanently strands value with no blame path.

### Recommendation
Distinguish "internally produced" change/branch/forwarded outputs from externally received ones: e.g., only treat non-`External`-kind outputs as internal if they appear in transactions the multisig itself constructed (matchable via `get_eventuality_completions` / known signed TXIDs), and otherwise credit them as `External`. At minimum, emit an explicit event/instruction for non-External-kind outputs paying to the multisig so stranded funds are observable and recoverable rather than silently dropped after `retain`.

### Proof of Concept
1. Validators run a Bitcoin multisig with public group key `K`.
2. Attacker computes `change_off = secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"change")`, increments it until `K + change_off·G` is even-Y, and derives `addr = p2tr(K + change_off·G)` — purely public computation.
3. Attacker broadcasts a transaction paying `X` BTC to `addr` and waits for confirmation.
4. `Bitcoin::get_outputs` returns the output with `kind = OutputType::Change`; `scan_transaction` matched on `script_pubkey` alone [6](#0-5) .
5. In `scanner_event_to_multisig_event`, `outputs.retain(|o| o.kind() == OutputType::External)` removes it; no `InInstruction`/deposit is emitted [4](#0-3) , while the output ID is marked `seen` in `ScannerDb`/`ram_outputs` preventing any rescan [7](#0-6) .
6. Result: `X` BTC is owned by the multisig key but absent from all credited balances and plans — funds received yet unusable by protocol accounting.

pub struct Scanner {
  key: ProjectivePoint,
  scripts: HashMap<ScriptBuf, Scalar>,
}

impl Scanner {
  /// Construct a Scanner for a key.
  ///
  /// Returns None if this key can't be scanned for.
  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
