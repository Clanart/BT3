### Title
Deep-Link Branch Parameter Bypasses Argument-Injection Guard Before Reaching `git checkout` - (File: `app/src/lib/parse-app-url.ts`)

### Summary
GitHub Desktop's `x-github-client://openrepo/...` deep link (the "Open in Desktop" protocol handler) accepts an attacker-controlled `branch` query parameter, validates it with `testForInvalidChars`, and then feeds it directly into a branch-checkout flow. Unlike the sibling function `sanitizedRefName`, `testForInvalidChars` never strips or rejects a leading `-`/`+`, so a crafted deep link can smuggle a value that looks like a git command-line flag (e.g. `--upload-pack=...`, `-B`, `--orphan=...`) past the validation gate. This mirrors the reported bug class: a value that "looks validated" is used in a sensitive downstream operation (invoking git with attacker data) without checking a specific invariant (no leading dash) before use.

### Finding Description
`parseAppURL` validates the `branch` query parameter using `testForInvalidChars`: [1](#0-0) 

`testForInvalidChars` is defined together with `sanitizedRefName` in `sanitize-ref-name.ts`. Note that only `sanitizedRefName` strips a leading `-`/`+` after removing disallowed characters; `testForInvalidChars` simply runs the same character-class regex as a boolean test and does **not** reject leading dashes: [2](#0-1) 

The validated (but not dash-stripped) `branch` value is returned as part of `IOpenRepositoryFromURLAction` and consumed by the dispatcher: [3](#0-2) 

`openBranchNameFromUrl` calls `this.checkoutLocalBranch(repository, branchName)` with the raw, attacker-supplied string. Because the character-class regex `[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$` does not include `-`, a value such as `--upload-pack=...` or `-B` passes `testForInvalidChars` cleanly and is treated as a legitimate branch name by the rest of the pipeline.

I was not able to inspect the exact implementation of `checkoutLocalBranch` (or the underlying `git` argument array it builds) within the remaining tool budget, so I cannot confirm with certainty whether a `--` separator is used before the branch argument in the actual `git checkout` invocation to fully neutralize this. This is the one open verification gap in this finding.

### Impact Explanation
If the downstream git invocation does not insert a `--` separator before the branch name, an attacker who gets a victim to click a single crafted `x-github-client://openrepo/...` link (a "link or deep link the user clicks" — squarely in the stated valid-impact category) could inject arbitrary git command-line options into the checkout invocation. Depending on which flag is smuggled, this could range from corrupting local branch state (e.g., `-B` forcing an unexpected branch reset) to more severe effects if a flag that accepts a path or command is accepted by the specific git subcommand used. This matches the report's underlying theme: a value is used in a sensitive operation without an existing guard actually enforcing the invariant it appears to enforce.

### Likelihood Explanation
Likelihood is moderate: the attacker only needs to control a URL that the victim clicks (email, chat, web page). The protocol handler is registered by default (`possibleProtocols`) and immediately routes to `parseAppURL`/`dispatchURLAction` without additional user confirmation of the branch value itself: [4](#0-3) [5](#0-4) 

The gating factor for actual exploitability is whether `checkoutLocalBranch`'s underlying git invocation uses a `--` separator — this remains unverified.

### Recommendation
- Make `testForInvalidChars` reject (or `parseAppURL` explicitly reject) any `branch` value beginning with `-` or `+`, mirroring the stripping already done in `sanitizedRefName`, so the two functions enforce the same invariant.
- Confirm/ensure `checkoutLocalBranch` and any other git invocation using attacker-influenced ref/branch strings from `parseAppURL` always separates options from positional arguments with `--`.

### Proof of Concept
1. Register/observe that GitHub Desktop handles `x-github-client://` links.
2. Craft a link: `x-github-client://openrepo/https://github.com/octocat/Hello-World?branch=--upload-pack%3Dtouch%2520%2Ftmp%2Fpwned`
3. Confirm via unit test equivalent to `parse-app-url-test.ts` that `parseAppURL` returns `branch: '--upload-pack=touch /tmp/pwned'` (no rejection), then trace whether `checkoutLocalBranch`'s git invocation treats this as an option rather than a ref name (unverified due to tool-call limits — recommend a Devin session to trace the exact `git` argument array building code and confirm/deny exploitability end-to-end).

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }
