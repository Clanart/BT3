### Title
Coinbase outputs are reported as spendable before maturity - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching outputs as `ReceivedOutput`, which is documented as “a spendable output.” Coinbase outputs are consensus-immature for 100 blocks, so the scanner can report funds that cannot yet be spent. [1](#0-0) [2](#0-1) 

### Finding Description
`Scanner::scan_transaction` creates a `ReceivedOutput` for every transaction output whose `script_pubkey` matches a registered scanner script. It records only the key offset, `TxOut`, and outpoint; it does not distinguish whether the containing transaction is a coinbase transaction. [3](#0-2) 

`Scanner::scan_block` then iterates over `block.txdata` from index zero, so `block.txdata[0]`—the coinbase—is included in the returned spendable-output list. [4](#0-3) 

A caller can pass that returned `ReceivedOutput` to `SignableTransaction::new`, which unconditionally converts it into a transaction input and retains it as a prevout. No maturity check or transaction-type check occurs. [5](#0-4) [6](#0-5) 

### Impact Explanation
A valid block can cause the wallet to report a Bitcoin output as spendable while consensus rules prohibit spending it for 100 blocks. The wallet can then construct and threshold-sign a transaction whose input is guaranteed to be rejected until maturity, making the reported balance operationally unavailable. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
Any miner able to produce a valid block can place a coinbase output paying the scanner’s P2TR script. More generally, `scan_block` is a public API for untrusted blocks, and a caller does not need malformed input or privileged access to receive an immature `ReceivedOutput`.

### Recommendation
Do not return coinbase outputs from `Scanner::scan_block`, or extend `ReceivedOutput` with explicit maturity/spendability metadata and make `SignableTransaction::new` reject immature coinbase inputs. If transaction-level scanning remains public, iterate only over `block.txdata[1 ..]` when constructing immediately spendable outputs. [9](#0-8)

let scanner = Scanner::new(group_key).unwrap();
let block: Block = get_untrusted_block();

// If block.txdata[0].output[vout] pays the scanner script,
// this returns a ReceivedOutput for the coinbase UTXO.
let outputs = scanner.scan_block(&block);
let immature = outputs
    .iter()
    .find(|o| o.outpoint().txid == block.txdata[0].compute_txid())
    .unwrap();

// The wallet treats it as an ordinary spendable input.
let signable = SignableTransaction::new(
    vec![immature.clone()],
    &[(payment_script, payment_amount)],
    None,
    None,
    fee_per_vbyte,
).unwrap();

// FROST signing succeeds, but Bitcoin consensus rejects the resulting
// transaction until the coinbase reaches 100 blocks of maturity.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
