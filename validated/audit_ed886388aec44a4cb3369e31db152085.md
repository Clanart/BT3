Unrecovered Go panic from unchecked type assertions on malicious CW20/CW721/CW1155 query responses in the `pointer` precompile - ([File: precompiles/pointer/pointer.go])

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers unmarshal an untrusted JSON response from a CosmWasm contract's `token_info`/`contract_info` smart query into `map[string]interface{}` and then perform unchecked type assertions `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)`. Unlike the C `calloc()`-without-null-check pattern in the CVE, this is the Go analog: dereferencing/converting attacker-influenced data without validating its shape, causing an unrecovered runtime panic when the assumption is violated.

### Finding Description
`AddCW20`, `AddCW721`, and `AddCW1155` all follow the same pattern: [1](#0-0) [2](#0-1) [3](#0-2) 

`p.wasmdKeeper.QuerySmartSafe` executes an arbitrary CosmWasm contract's query handler and returns whatever JSON that contract chooses to return. The result is unmarshaled into a generic `map[string]interface{}`, and then `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)` are asserted without the `, ok` form. If the contract's response omits `name`/`symbol`, or returns them as a non-string JSON type (number, bool, object, array, or `null`), the type assertion panics with `interface conversion: interface {} is <type>, not string`.

Critically, this panic is **not recovered** anywhere in the call chain. `PrecompileExecutor.Execute` in `precompiles/pointer/pointer.go` has no `defer recover()`, and the top-level dispatcher `DynamicGasPrecompile.RunAndCalculateGas` also lacks a recover around `d.executor.Execute`: [4](#0-3) 

This is inconsistent with the rest of the precompile codebase, where equivalent risky logic is explicitly wrapped in `defer recover()` to convert panics into reverts — e.g. the `wasmd` precompile's `instantiate`/`execute` functions: [5](#0-4) 
and the `oracle` precompile's `Execute`: [6](#0-5) 

An integration test in the repo explicitly documents this exact invariant that is violated here: precompile failures "must not surface as a panic" and "must trace as an execution revert": [7](#0-6) 

### Impact Explanation
Any EVM user can deploy a CW20, CW721, or CW1155 contract with a crafted `token_info`/`contract_info` query handler that returns `name`/`symbol` as a non-string JSON value (or omits them). Calling `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against that contract triggers an unrecovered Go panic during EVM precompile execution inside transaction processing (`RunAndCalculateGas`). Because there is no recover boundary at this call site, the panic propagates up through block/transaction execution. Depending on how far up the call stack a recovery exists (e.g., in `runTx`'s panic-recovery middleware), this either surfaces as an unexpected internal error breaking the "never panic" precompile contract, or — if any state divergence occurs between how different node versions/environments handle the panic (e.g., simulation vs. deliver-tx paths) — could produce non-deterministic behavior across validators, risking a chain halt or consensus divergence. At minimum, it is a reachable transaction-triggered crash/DoS vector reachable by any pointer-precompile caller with a malicious CW contract, which the CVE's impact criteria classifies as validator halt / crash of transaction processing.

### Likelihood Explanation
High likelihood of triggering: the attacker fully controls the target CW20/CW721/CW1155 contract's query response, requiring only deployment of a trivial malicious CosmWasm contract and one EVM transaction calling the pointer precompile against it. No special privileges, timing, or race conditions are needed.

### Recommendation
Add explicit `ok` checks (or a `defer recover()` guard consistent with the rest of the precompile suite) around the `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)` assertions in `AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` (and its legacy versioned copies), returning a proper error (e.g., "contract metadata malformed") instead of panicking. Additionally, consider adding a top-level `recover()` in `DynamicGasPrecompile.RunAndCalculateGas` (`precompiles/common/precompiles.go`) as a defense-in-depth backstop for all dynamic-gas precompiles, converting any panic into `vm.ErrExecutionReverted` — matching the pattern already applied in `wasmd` and `oracle` precompiles.

### Proof of Concept
1. Deploy a CW20-like contract whose `{"token_info":{}}` query handler returns JSON such as `{"name": 12345, "symbol": true, "decimals": 6, "total_supply": "0"}` (non-string `name`/`symbol`), or simply omits those fields.
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b` method `addCW20Pointer(<cw_contract_addr>)`.
3. Execution reaches `AddCW20` → `formattedRes["name"].(string)` panics with an interface-conversion error, which is not recovered anywhere in `PrecompileExecutor.Execute` or `DynamicGasPrecompile.RunAndCalculateGas`, propagating as an unrecovered panic during transaction processing rather than a clean EVM revert.

func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}

/**
 * The load-bearing legacy assertion: a precompile that runs out of gas mid-execution
 * must surface as a plain EVM "execution reverted" in traces — never as a Go panic
 * (a "panic occurred" trace would mean a consensus-relevant unhandled error path).
 */
export async function expectTraceRevertedNotPanicked(txHash: string): Promise<void> {
    const trace = await traceTransaction(txHash);
    const error = trace.error ?? '';
    expect(error, `trace of ${txHash} must carry an error`).to.not.equal('');
    expect(error, 'precompile failure must not surface as a panic').to.not.include('panic');
    expect(error, 'precompile failure must trace as an execution revert').to.include(
        'execution reverted',
    );
}
