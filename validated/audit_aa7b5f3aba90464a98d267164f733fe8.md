### Title
PedPoP accepts identity encryption keys, making encrypted secret shares publicly decryptable - (File: `crypto/dkg/pedpop/src/encryption.rs`)

### Summary
`EncryptionKeyMessage::read` accepts any canonical group point as the recipient encryption key, including the identity point. `Decryption::register` stores that key without validating it. When an honest participant encrypts a secret share to the identity key, the ECDH result is always the identity point, so the ChaCha20 encryption key is derivable entirely from public data. An observer can decrypt every share sent to a participant advertising this malformed key.

### Finding Description
`EncryptionKeyMessage::read` deserializes `enc_key` through `C::read_G` after reading the PedPoP commitments. [1](#0-0)  The generic `Ciphersuite::read_G` checks only that the point decodes and re-encodes canonically; it does not reject the identity point. [2](#0-1)  Although `Curve::read_G` does reject identity points, PedPoP is parameterized only by `Ciphersuite` and therefore does not use that stricter reader. [3](#0-2) 

After registration, `Encryption::encrypt` calls `ecdh`, which computes `msg.key * private`. If `msg.key` is the identity point, the shared point is identity for every message. [4](#0-3)  `cipher` derives the ChaCha20 key solely from the protocol context and the encoding of that shared point, with a fixed IV. [5](#0-4) 

The PedPoP proof of knowledge also does not bind the encryption key: its challenge covers only the context, sender, nonce, and polynomial-commitment bytes. [6](#0-5)  Consequently, an attacker can replace the trailing `enc_key` encoding in an otherwise valid `EncryptionKeyMessage` with the canonical identity encoding without invalidating the commitment proof.

### Impact Explanation
Any party able to observe the resulting `EncryptedMessage` can reconstruct the same ChaCha20 keystream and recover the serialized secret share. Collecting all encrypted shares addressed to a participant that registered the identity key reveals that participant’s final PedPoP secret share. In a `1`-of-`n` configuration this directly recovers the threshold signing key; otherwise it exposes one participant’s key share and reduces the threshold-security assumption accordingly.

This violates the confidentiality boundary that PedPoP’s per-message ECDH encryption is intended to provide. The malformed key is reachable through the explicitly supported `EncryptionKeyMessage::read` / `EncryptedMessage::read` input path.

### Likelihood Explanation
A malicious participant can trigger this deterministically during key generation by publishing an otherwise valid commitments message whose encryption key is the identity point. No collusion, malformed curve encoding, leaked private key, or invalid scalar is required. Honest participants accept the key because neither deserialization nor registration applies a non-identity check. [7](#0-6) 

### Recommendation
Reject the identity point for `EncryptionKeyMessage::enc_key` during deserialization and again in `Decryption::register` as defense in depth. PedPoP should use a non-identity point reader equivalent to `Curve::read_G`, or explicitly check `enc_key.is_identity()` before storing it. The encryption key should also be included in the participant-bound proof challenge so an attacker cannot replace it after proof generation.

### Proof of Concept
```rust
// Given a valid EncryptionKeyMessage<C, Commitments<C>> for participant P:
//
// 1. Deserialize it normally.
// 2. Replace `enc_key` with C::G::identity().
// 3. Serialize and send it to an honest PedPoP participant.
//
// The commitment proof remains valid because `challenge` commits only to
// `context`, `participant`, `nonce`, and the polynomial commitments, not
// `enc_key`.
//
// The victim later calls:
let shared = C::G::identity() * ephemeral_private_key;
// shared == C::G::identity()

// The observer reconstructs:
let mut transcript =
    RecommendedTranscript::new(b"DKG Encryption v0.2");
transcript.append_message(b"context", public_context);
transcript.domain_separate(b"encryption_key");
transcript.append_message(
    b"shared_key",
    C::G::identity().to_bytes(),
);

let mut key = chacha20::Key::default();
key.copy_from_slice(&transcript.challenge(b"key")[..32]);

let mut iv = chacha20::Nonce::default();
iv.copy_from_slice(b"DKG IV v0.2\0");

let mut cipher = chacha20::ChaCha20::new(&key, &iv);
cipher.apply_keystream(encrypted_share_bytes);
```

`encrypted_share_bytes` then contains the raw scalar serialization consumed by `SecretShare::read`. [8](#0-7)  Repeating this for each encrypted message sent to the participant yields all delivered secret shares.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();

  /// Read a point from a reader, rejecting identity.
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let res = <Self as Ciphersuite>::read_G(reader)?;
