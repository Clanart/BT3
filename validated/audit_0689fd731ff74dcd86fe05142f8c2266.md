## Analysis

The Sherlock finding's underlying broken invariant is: an authorization/approval value gets applied to whatever endpoint the (untrusted) response tells the client, without re-validating that the endpoint is the one the caller actually intended — `safeApprove()` blindly re-approves an allowance based on trust in prior state, allowing a race/host-confusion window. The closest reachable analog in GitHub Desktop is not approve()/ERC20 semantics, but the credential-helper's endpoint classification logic, which trusts an attacker-controlled `WWW-Authenticate` response to decide that a host is a GitHub/GitHub Enterprise endpoint, and then binds the user's real GitHub OAuth sign-in flow (and future token attachment) to that attacker-chosen origin.

### Title
GitHub Desktop trusts a git server's `WWW-Authenticate` realm to classify a host as GitHub Enterprise, causing OAuth sign-in and token attachment to be bound to an attacker-controlled endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind()` in [1](#0-0)  classifies a remote's credential endpoint as `'enterprise'` if the git server's `WWW-Authenticate` header (forwarded by git into the credential helper's `wwwauth[]` fields) contains `realm="GitHub"`. This value is fully attacker-controlled — any HTTP(S) git server or a MITM proxy sitting in front of a normal-looking clone/fetch URL can emit that header. When classified as `'enterprise'` and no existing account matches, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)` [2](#0-1) , which invokes `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` using that same attacker-controlled `origin` [3](#0-2) . This launches Desktop's real GitHub Enterprise OAuth sign-in flow scoped to the attacker's host.

### Finding Description
Git forwards any `WWW-Authenticate` header returned by an HTTP git remote (or a transparent proxy) to the credential helper as `wwwauth[]` entries. `getEndpointKind()` treats the mere presence of the substring `realm="GitHub"` in that header as proof the host is a GitHub Enterprise server: [4](#0-3) 

There is no verification that the host is actually running GitHub Enterprise Server (e.g., no call to `isGitHubHost()` in that branch, unlike the fallback path a few lines below at line 178). If the endpoint isn't already associated with a signed-in account, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [5](#0-4) 

`promptForGitHubSignIn` then starts the full "Enterprise" sign-in UX and sets the sign-in target origin to the attacker's host verbatim: [6](#0-5) 

Once the user completes what looks like a normal "sign in to your GitHub Enterprise instance" flow (which they may reasonably do, since Desktop itself is prompting it while performing an operation on a repository they cloned/added), the resulting `Account` is stored keyed by that origin. Subsequent git operations against the same remote resolve via `findGitHubTrampolineAccount`, which matches purely by origin: [7](#0-6) 

and the account's token is attached to outgoing credentials: [8](#0-7) 

The net effect: an attacker who controls a git remote's HTTP responses (a self-hosted "plain" git server, or a MITM/proxy in front of one) can spoof a `WWW-Authenticate: realm="GitHub"` header to make Desktop believe it's talking to a GitHub Enterprise deployment, trigger the real OAuth/PAT enterprise sign-in dialog scoped to the attacker's origin, and — once bound — have the user's Enterprise credentials/token silently sent to that attacker-controlled endpoint on every future fetch/push, since `findGitHubTrampolineAccount` only checks origin equality.

### Impact Explanation
This matches the "unauthorized OAuth or account binding" and "credential/token exfiltration" categories in scope: the attacker doesn't need to leak or steal anything pre-existing — they induce Desktop itself to bind a legitimate sign-in/token to an origin they control, and Desktop keeps sending that token on subsequent requests to the same origin. The existing "GitHub host" heuristics (`isDotCom`, `isGHE`, `isGist`, and the authoritative `isGitHubHost()` API check at line 178) are all bypassed by the earlier `wwwauth[]` branch, which trusts response content instead of verifying the host.

### Likelihood Explanation
Requires only that the user add/clone from, or otherwise fetch/push to, a remote whose HTTP endpoint is under attacker control or proxied by an attacker (e.g., a malicious "self-hosted git server" advertised as a normal project, or a MITM on an HTTP git remote). No local access, no prior malware, and no unusual user steps beyond the ordinary "clone this repo and let Desktop's normal sign-in prompt run" — which is expected behavior for legitimate Enterprise remotes. This fits the "attacker controls...a git remote/proxy response" scope explicitly.

### Recommendation
Do not classify a host as `'enterprise'` based solely on the presence of `realm="GitHub"` in an attacker-suppliable `WWW-Authenticate` header. At minimum, treat the `wwwauth[]` hint as advisory and still require the authoritative `isGitHubHost(endpoint)` check (already used at line 178) before invoking `promptForGitHubSignIn`, or require explicit user confirmation that shows the actual hostname before starting an Enterprise sign-in flow triggered implicitly by a credential-helper request.

### Proof of Concept
1. Attacker stands up an HTTP git server (or a proxy in front of one) at `https://evil.example.com/victim/repo.git`.
2. The server is configured to answer authentication challenges with `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds this URL as a remote in GitHub Desktop and performs a fetch/push. Git invokes the credential helper trampoline with `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind()` returns `'enterprise'` purely from that header content [9](#0-8) .
5. Since no account exists for `https://evil.example.com`, Desktop calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which starts the real Enterprise OAuth/PAT sign-in dialog bound to `evil.example.com` [6](#0-5) .
6. If the user completes sign-in (believing it's the legitimate flow for the repo they're working with), the resulting account/token is stored and reused for `evil.example.com` on every subsequent operation via `findGitHubTrampolineAccount` origin matching [7](#0-6) , exfiltrating the token to the attacker's server on each future git operation.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
