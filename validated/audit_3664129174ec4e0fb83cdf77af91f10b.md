## Title
Unbounded atom-length index read in `is_atom_canonical`/`is_clvm_canonical` allows spend-bundle-triggered out-of-bounds crash during mempool admission - (File: `chia/full_node/mempool_manager.py`)

## Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM serialization of a submitted coin spend's `puzzle_reveal` and `solution` to decide DEDUP/canonical eligibility. Like the dnsmasq `extract_name()`/`sort_rrset()` flaw (CVE-2020-25687), these functions decode an attacker-controlled variable-length size prefix and then index into the buffer using that untrusted length **without ever checking the computed offset against the buffer's actual length**. A malicious/unprivileged spend-bundle submitter can craft a puzzle reveal or solution whose length-prefix byte(s) claim more atom bytes than are actually present, driving `offset` past the end of `clvm_buffer` and triggering an unhandled `IndexError` deep in mempool admission.

## Finding Description
`is_atom_canonical()` reads the length-prefix bits from `clvm_buffer[offset]` and, based on the prefix pattern, loops `prefix_len` times reading successive bytes to build `atom_len`: [1](#0-0) 

Two bound violations exist:
1. Inside the `for i in range(prefix_len)` loop, `offset` is incremented and `clvm_buffer[offset]` is read with no check that `offset < len(clvm_buffer)` — a truncated multi-byte length prefix at the end of the buffer raises `IndexError` immediately.
2. After computing `atom_len` (which can be attacker-controlled up to ~`2**40`), the function returns `1 + prefix_len + atom_len` without ever validating it against the remaining buffer size.

`is_clvm_canonical()` consumes that return value directly: [2](#0-1) 

`offset += atom_len` can jump far past `len(clvm_buffer)`. The next loop iteration does `b = clvm_buffer[offset]`, which raises `IndexError` rather than gracefully returning `False`.

This is reachable directly from spend-bundle admission: `validate_spend_bundle()` calls `is_clvm_canonical()` on every coin spend's `puzzle_reveal` and `solution` bytes, which come straight from the submitter with no prior length sanitization: [3](#0-2) 

This mirrors the dnsmasq bug class exactly: a length field parsed from untrusted input is used to index/advance through a buffer before any bounds validation, and the out-of-range access is only caught by luck (in dnsmasq's case, a crash from `memcpy` with negative size; here, an uncaught Python `IndexError`).

## Impact Explanation
`validate_spend_bundle()` runs synchronously inside `MempoolManager`'s admission path, which is invoked from full-node transaction handling for every gossiped/submitted `SpendBundle`. No `try/except` around `is_clvm_canonical()` was found catching `IndexError` — the caller only wraps the CLVM-execution/signature step (`pre_validate_spendbundle`) in a `ValueError` handler, not the canonical-check step in `validate_spend_bundle()`. An unhandled `IndexError` raised inside coroutine handling for an incoming transaction/spend-bundle can propagate and abort processing of that transaction path, meeting the "spend-triggered transaction-processing halt" impact criterion for this analog scan. Because the check operates identically on RPC-submitted bundles (e.g., wallet `push_tx`) and network-received bundles, a single crafted spend bundle from any unprivileged submitter is a sufficient trigger.

## Likelihood Explanation
High reachability: any wallet user or RPC caller can submit a `SpendBundle` with a puzzle_reveal/solution containing a truncated or oversized atom length prefix. No special privileges, peer position, or timing conditions are required — the crafted bytes just need to reach `validate_spend_bundle()`, which happens for every spend bundle considered for mempool admission.

## Recommendation
In `is_atom_canonical()`, before each `clvm_buffer[offset]` access in the prefix-reading loop, verify `offset < len(clvm_buffer)` and raise/return a "non-canonical"/error result instead of indexing unconditionally. Additionally, in `is_clvm_canonical()`, after calling `is_atom_canonical()`, validate that `offset + atom_len <= len(clvm_buffer)` before continuing the loop (or have `is_atom_canonical` accept and check against remaining buffer length directly), returning `False` cleanly on out-of-range values rather than allowing an out-of-bounds index. Also wrap the canonical check in `validate_spend_bundle()` with defensive error handling that converts unexpected exceptions into a mempool `Err` (e.g., `Err.INVALID_COIN_SOLUTION`) so a parsing bug cannot escalate into an unhandled exception in the transaction-processing path.

## Proof of Concept
A spend bundle whose `puzzle_reveal` or `solution` ends with a truncated multi-byte atom length prefix reproduces the out-of-bounds read, analogous to the existing canonical-format tests: [4](#0-3) 

For example, a solution byte string ending in `0xC0` (5+8-bit length prefix indicator) with no following length byte causes `is_atom_canonical()`'s loop to execute `offset += 1; atom_len |= clvm_buffer[offset]` with `offset == len(clvm_buffer)`, raising `IndexError`. Separately, a solution such as `0xC0 0x01` followed by fewer than `0x01`-implied trailing bytes (or any prefix encoding a length exceeding the remaining buffer) causes `is_clvm_canonical()`'s subsequent `b = clvm_buffer[offset]` to index past the buffer end once `offset += atom_len` overshoots — both paths are directly exercised by submitting such a `coin_spend.solution`/`coin_spend.puzzle_reveal` through `MempoolManager.add_spend_bundle()` → `validate_spend_bundle()`.

Note: I could not find, within index limits, a try/except in the call chain from `full_node.py`'s transaction-handling entry points down to `validate_spend_bundle()` that would specifically catch `IndexError` — this weakens certainty about the exact blast radius (single-item failure vs. broader task/loop crash) and would benefit from direct verification with a live Devin session that can run the reproduction against `full_node.py`'s transaction handlers.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
