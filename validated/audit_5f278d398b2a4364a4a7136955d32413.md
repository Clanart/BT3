## Analog Found

### Title
Unbounded recursive parsing of attacker-controlled PlotNFT memo can crash pool-transition tracking via Python stack exhaustion - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively parses a CLVM memo structure into `MofN`/`PuzzleWithRestrictions` objects with no depth bound, mirroring the ALPINE-CVE-2026-55892 pattern where an attacker-controlled tree/trie is walked with a depth counter that is never checked against a safe bound. This function is invoked from `PlotNFT.get_next_from_coin_spend()` in `chia/pools/plotnft_drivers.py` on the `memo_blob` of a `CREATE_COIN` condition emitted by a singleton coin spend — data that is fully attacker-controlled by whoever creates the spend that produces the next PlotNFT singleton coin.

### Finding Description
`PuzzleWithRestrictions.from_memo()` [1](#0-0)  recurses into `MofNHint.from_program()` for every `member_memo` in an `MofN` puzzle hint, and each member is itself parsed via a fresh call to `PuzzleWithRestrictions.from_memo()`. Nothing in this call chain enforces a maximum nesting depth: an attacker can nest `MofN` hints arbitrarily deep inside a memo `Program`, and each level costs only a few CLVM atoms to encode, so a compact memo can encode very deep recursion.

This is reached from `chia/pools/plotnft_drivers.py`, where `PlotNFT.get_next_from_coin_spend()` calls `PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())` [2](#0-1)  whenever it cannot otherwise recognize the PlotNFT's inner puzzle from local state (i.e., any time it must decode purely from on-chain memo data). `memo_blob` comes directly from a `CREATE_COIN` condition's memo field in the coin spend being processed — content fully controlled by whoever created that coin spend, not validated by consensus.

Unlike the CVE's C-level stack array indexing, Python enforces a recursion limit (`sys.setrecursionlimit`), so the practical failure mode is a `RecursionError` raised mid-parse rather than silent memory corruption. But the effect on the reachable path is analogous: an unbounded depth counter walking an attacker-supplied tree structure with no depth cap, crashing the code that processes it. Other recursive helpers in the same file (`MofN.puzzle_hash()`, `PuzzleWithRestrictions.unknown_puzzles`, `PuzzleWithRestrictions.fill_in_unknown_puzzles()`) are similarly unbounded and are invoked as part of the same call chain [3](#0-2) .

### Impact Explanation
A crafted deep memo triggers unbounded Python recursion in `from_memo`, raising a `RecursionError` while a wallet/pool-transition client is trying to resolve the next PlotNFT state from a coin spend. This halts processing of that spend path (a spend-triggered transaction-processing halt for the plotnft/pool-transition tracker), rather than any coin-store or consensus corruption. It does not grant unauthorized coin movement or supply inflation; it is a local denial-of-service against the code path that tracks PlotNFT/pool state transitions for a specific launcher id.

### Likelihood Explanation
Medium. The memo bytes are attacker-controlled whenever a party fully controls the coin spend producing the next singleton generation (e.g., a malicious pool or third party constructing a PlotNFT-like coin with adversarial memo content aimed at a wallet client that will later call `get_next_from_coin_spend`). Exploitation requires no privileged access — just crafting the CLVM memo — but it only affects the party that runs `get_next_from_coin_spend` against that specific spend, not full-node consensus.

### Recommendation
Add an explicit depth limit (and/or convert to an iterative worklist, as already done for `sha256_treehash` in `chia/types/blockchain_format/tree_hash.py`) in `PuzzleWithRestrictions.from_memo()`/`MofNHint.from_program()`, rejecting memo structures beyond a small bounded nesting depth (e.g., matching the maximum realistic custody architecture depth used in practice) before recursing, and catching/handling `RecursionError` defensively as an invalid-memo condition rather than letting it propagate.

### Proof of Concept
Construct a `CREATE_COIN` memo `Program` encoding nested `MofN` hints: `(namespace [nonce, [], 1, [1, [inner_memo]]])` where `inner_memo` is itself another such structure, nested N times (N in the low thousands is sufficient to exceed Python's default recursion limit). Feed a coin spend whose `CREATE_COIN` condition carries this memo through `PlotNFT.get_next_from_coin_spend()`; the call to `PuzzleWithRestrictions.from_memo()` raises `RecursionError` instead of the expected `GetNextPlotNFTError`, crashing/aborting the caller's PlotNFT-state resolution for that spend.

**Confidence caveat:** I could not fully trace every call site consuming `PlotNFT.get_next_from_coin_spend()` (e.g., whether it's used in a long-running sync loop where an unhandled `RecursionError` would abort broader wallet/pool sync vs. just one lookup) due to index coverage limits; a Devin session with full repo access could confirm the blast radius of the crash by tracing all callers of `get_next_from_coin_spend`.

    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(
                m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
            )
        else:
            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)

        return PuzzleWithRestrictions(
            nonce=nonce.as_int(),
            restrictions=[UnknownRestriction(hint) for hint in restriction_hints],
            puzzle=puzzle,
            additional_memos=additional_memos,
