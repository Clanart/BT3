### Title
Session-level `baseline_sha` is not bound to the repo/worktree it was captured from, allowing cross-worktree baseline reuse in `capture_git_baseline` / `compute_v2_review_set` - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`capture_git_baseline` returns a bare SHA (from `git stash create` or `git rev-parse HEAD`) that is stored via `save_baseline_sha(session_id, sha)` with no accompanying repo identity (e.g. `git rev-parse --show-toplevel` / `--git-common-dir`). At Stop time, `compute_v2_review_set` re-derives `repo = _git_toplevel(cwd)` from the *current* cwd and diffs it against the stored `baseline_sha` without ever checking that the SHA actually belongs to that repo/worktree.

### Finding Description
`save_baseline_sha`/`load_baseline_sha` key session state purely by `session_id` and store only the raw SHA string, with no repo-root or git-common-dir binding: [1](#0-0) . `capture_git_baseline(cwd)` likewise returns only a SHA, with no record of which repo it was captured in: [2](#0-1) .

At Stop time, `compute_v2_review_set` re-resolves the repo root fresh from the (possibly changed) `cwd` and passes the stale `baseline_sha` straight into `_git_name_only(repo, baseline_sha)` without verifying that `baseline_sha` is reachable/valid in *this* `repo`: [3](#0-2) .

For **linked git worktrees**, `git worktree`s of the same repository share a single object database (only refs/HEAD/index differ per worktree) — `_git_dir` even explicitly documents relying on this shared-object-store property elsewhere in the codebase (`--git-common-dir`) for the reviewed-SHA log: [4](#0-3) . This means a `baseline_sha` captured in worktree A (e.g. attacker's malicious worktree/branch) is a perfectly valid, resolvable commit object when the session's cwd later moves to worktree B of the *same* repo. `git diff --name-only <baseline_sha>` run from B's toplevel will succeed against that cross-worktree SHA rather than failing — there is no check anywhere in `capture_git_baseline`, `save_baseline_sha`, `load_baseline_sha`, or `compute_v2_review_set` that the baseline came from the worktree currently being diffed. The result: the Stop-hook review set is computed as the diff between worktree B's current state and a commit object that represents worktree A's tree/branch, which can spuriously mark files as "unchanged since baseline" (masking genuinely new malicious edits that happen to match content already present on the attacker's branch) or as changed relative to an unrelated tree (misattribution/noise).

For genuinely separate repositories (different object databases), the stale `baseline_sha` will not resolve at all, `_git_name_only` returns `None` on git failure, and `compute_v2_review_set` correctly falls back to unfiltered `dirty_now` — so the more severe, "review masking" failure mode is specific to the multi-worktree-of-same-repo case, which matches the worktree precondition given in the question.

### Impact Explanation
This is a target-binding violation between a Stop-hook review session and the git object it diffs against. In the worktree-switching scenario, the practical impact is a masked or misattributed security review: legitimate new edits in worktree B can be silently excluded from the LLM security review if they happen to match content already present in the baseline commit captured from worktree A (e.g. attacker deliberately seeds their worktree's stash-baseline content to match code they plan to introduce elsewhere), weakening the review/automation guarantee that all Claude-authored diffs get scanned.

### Likelihood Explanation
Requires a session that spans multiple linked worktrees of the same repository (or resumes a session whose cwd moves between worktrees) — a realistic but non-default workflow (multi-root editing, worktree-based feature branching). No special privileges are needed beyond normal repo/worktree setup; the attacker only needs to control the contents of one worktree's checked-out branch, which is within "ordinary repository content" trust bounds.

### Recommendation
Bind `baseline_sha` (and `head_at_capture`) to the repo identity at capture time — store `_git_dir(repo_root)` (the shared git-common-dir) or the resolved `repo_root` alongside the SHA in session state, and have `compute_v2_review_set`/`get_git_diff` verify at Stop time that the current `_git_dir(cwd)` (or repo_root) still matches the one recorded at capture. If it doesn't match, discard the stale baseline and re-baseline (or fail closed) instead of diffing against a cross-worktree/cross-repo SHA.

### Proof of Concept
Integration test:
1. Create a git repo `main_repo` with an initial commit; add a linked worktree `wt_attacker` on a branch containing attacker-controlled content in `secret.py`.
2. In `wt_attacker`, call `capture_git_baseline(wt_attacker)` and `save_baseline_sha(session_id, sha)` — SHA is a valid object in the shared `.git`.
3. Change cwd to a second worktree `wt_victim` (same repo, different branch/dir layout) and edit `secret.py` there to introduce a vulnerable pattern that matches content already present in `wt_attacker`'s baseline commit.
4. Call `compute_v2_review_set(wt_victim, baseline_sha, head_at_capture, {})` (as Stop-hook would) and assert that `secret.py` is incorrectly excluded from `review_set` (masked) even though it is a genuinely new edit in `wt_victim`'s history — expected/fixed behavior: the function should detect the repo-identity mismatch (`_git_dir(wt_attacker) == _git_dir(wt_victim)` is true but `_git_toplevel` differs) and either re-baseline or flag `secret.py` for review regardless.

def save_baseline_sha(session_id, sha):
    """Save the git baseline SHA to state."""
    def _save(state):
        state["baseline_sha"] = sha
    with_locked_state(session_id, _save)


def load_baseline_sha(session_id):
    """Load the git baseline SHA from state."""
    def _load(state):
        return state.get("baseline_sha")
    return with_locked_state(session_id, _load)

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

def _git_dir(repo_root):
    """Absolute shared `.git` directory for repo_root.

    Uses `rev-parse --git-common-dir` so linked worktrees resolve to the
    SHARED gitdir, not the per-worktree `.git/worktrees/<name>/`. That way
    push-sweep's reviewed-shas record (and the bash-hook-once sentinel)
    is per-clone — a commit reviewed in one worktree counts as reviewed
    if a different worktree later pushes it. Returns None on failure so
    callers can degrade (push-sweep state is best-effort).
    """
    try:
        r = subprocess.run(
            [*GIT_CMD, "rev-parse", "--git-common-dir"],
            cwd=repo_root, capture_output=True, text=True, timeout=5,
        )
        if r.returncode != 0:
            return None
        d = r.stdout.strip()
        return d if os.path.isabs(d) else os.path.join(repo_root, d)
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
