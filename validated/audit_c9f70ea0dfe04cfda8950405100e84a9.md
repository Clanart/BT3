### Title
`extract_frontmatter`'s naive `split('---', 2)` lets a crafted rule body truncate frontmatter and silently downgrade `action: block` to `warn` - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter` in [1](#0-0)  splits the whole file content on the literal substring `'---'` with `maxsplit=2`, rather than on frontmatter fence lines. Any additional `'---'` occurring anywhere before the intended closing fence (in a field value, an embedded markdown rule, or an extra fence) becomes the "closing" delimiter, truncating `frontmatter_text` early and pushing everything after it — including `action: block` — into the unparsed `message` body.

### Finding Description
`load_rules()` globs `.claude/hookify.*.local.md` files [2](#0-1)  and calls `load_rule_file()` → `extract_frontmatter(content)` → `Rule.from_dict(frontmatter, message)` [3](#0-2) .

`extract_frontmatter` does `parts = content.split('---', 2)` and treats `parts[1]` as the entire frontmatter text and `parts[2]` as the message body [1](#0-0) . Because `str.split` matches the bare substring `'---'` anywhere in the text (not just on a line by itself), a third `'---'` occurring before the real closing fence — e.g. embedded in a `pattern:` value, an inline comment, or an extra horizontal-rule line placed inside the intended frontmatter block — is consumed as the "closing" fence. Everything physically after that point, including a later `action: block` line, ends up concatenated into `parts[2]` and is never fed into the key/value parsing loop that builds `frontmatter` [4](#0-3) .

Downstream, `Rule.from_dict` reads `frontmatter.get('action', 'warn')` [5](#0-4) , so a truncated frontmatter silently falls back to `action='warn'` even though the rule author intended `block`. In `RuleEngine.evaluate_rules`, only rules with `rule.action == 'block'` populate `blocking_rules`, which is the only path that emits `"permissionDecision": "deny"` for `PreToolUse`/`PostToolUse` or `"decision": "block"` for `Stop` [6](#0-5) ; a downgraded rule instead lands in `warning_rules`, which only emits a `systemMessage` and allows the tool call to proceed [7](#0-6) .

No validation exists that checks the number of `'---'` occurrences, requires the closing fence to be on its own line, or verifies that fields expected by the rule author (like `action`) actually landed inside the parsed dict. `load_rule_file` only checks `if not frontmatter:` (empty dict) before proceeding [8](#0-7)  — a non-empty but truncated frontmatter passes silently.

### Impact Explanation
An attacker who can add or modify a `.claude/hookify.*.local.md` file (e.g., via a PR) can craft a rule file that *appears* to block a dangerous Bash/Edit pattern (visually contains `action: block`), but due to the delimiter-confusion bug, `action: block` is shifted into the message body and never parsed, so the effective rule silently becomes `action: warn`. This suppresses the intended "deny" enforcement for `PreToolUse`/`PostToolUse`/`Stop` hooks, allowing disallowed Bash or file-edit operations to execute unblocked while only showing a warning message — a direct violation of the deny-means-deny invariant for a security-relevant automation control.

### Likelihood Explanation
This requires only that an attacker can introduce or modify a hookify rule markdown file in the repository (a normal PR-writable artifact, not requiring admin/maintainer privilege on the victim machine). Because the bug is a plain string-based split with no awareness of line boundaries, it is trivially reproducible with any payload containing an extra `'---'` before the intended `action: block` line (e.g., in a regex pattern value like `pattern: "a---b"`, or an inserted markdown horizontal rule). The bug fires deterministically for any such file, not depending on race conditions or special environment configuration.

### Recommendation
Rewrite `extract_frontmatter` to split frontmatter using line-anchored fence detection (e.g., regex `^---\s*$` with `re.MULTILINE`, or iterate lines and stop at the first line that is exactly `---`) instead of `str.split('---', 2)`, and use a real YAML parser (or at least validate that the fields required for enforcement, like `action`, `enabled`, `event`, were captured) before constructing `Rule`. Additionally, `load_rule_file` should fail closed (reject the file / log an error) rather than silently succeeding when the frontmatter dict looks unexpectedly small or when a `---`-like construct is detected inside what should be the frontmatter block.

### Proof of Concept
Unit/fuzz test against `extract_frontmatter` and `Rule.from_dict`:

```python
import pytest
from plugins.hookify.core.config_loader import extract_frontmatter, Rule

PAYLOADS = [
    '---\nname: r1\nenabled: true\nevent: bash\npattern: "a---b"\naction: block\n---\nmsg\n',
    '---\nname: r2\nenabled: true\nevent: bash\n---\naction: block\npattern: "rm -rf"\n---\nmsg\n',
]

@pytest.mark.parametrize("content", PAYLOADS)
def test_action_block_not_lost(content):
    frontmatter, message = extract_frontmatter(content)
    rule = Rule.from_dict(frontmatter, message)
    # Invariant: a rule authored with action: block anywhere in the fenced
    # frontmatter section must not silently downgrade to 'warn'.
    assert 'action: block' in content
    assert rule.action == 'block', (
        f"action:block was shifted into message body; parsed action={rule.action!r}, "
        f"frontmatter={frontmatter!r}, message={message!r}"
    )
```

Running this against the current implementation demonstrates `rule.action == 'warn'` for payloads where an extra `'---'` precedes the `action: block` line, confirming the silent downgrade described above.

    # Simple YAML parser that handles indented list items
    frontmatter = {}
    lines = frontmatter_text.split('\n')

    current_key = None
    current_list = []
    current_dict = {}
    in_list = False
    in_dict_item = False

    for line in lines:
        # Skip empty lines and comments
        stripped = line.strip()
        if not stripped or stripped.startswith('#'):
            continue

        # Check indentation level
        indent = len(line) - len(line.lstrip())

        # Top-level key (no indentation or minimal)
        if indent == 0 and ':' in line and not line.strip().startswith('-'):
            # Save previous list/dict if any
            if in_list and current_key:
                if in_dict_item and current_dict:
                    current_list.append(current_dict)
                    current_dict = {}
                frontmatter[current_key] = current_list
                in_list = False
                in_dict_item = False
                current_list = []

            key, value = line.split(':', 1)
            key = key.strip()
            value = value.strip()

            if not value:
                # Empty value - list or nested structure follows
                current_key = key
                in_list = True
                current_list = []
            else:
                # Simple key-value pair
                value = value.strip('"').strip("'")
                if value.lower() == 'true':
                    value = True
                elif value.lower() == 'false':
                    value = False
                frontmatter[key] = value

        # List item (starts with -)
        elif stripped.startswith('-') and in_list:
            # Save previous dict item if any
            if in_dict_item and current_dict:
                current_list.append(current_dict)
                current_dict = {}

            item_text = stripped[1:].strip()

            # Check if this is an inline dict (key: value on same line)
            if ':' in item_text and ',' in item_text:
                # Inline comma-separated dict: "- field: command, operator: regex_match"
                item_dict = {}
                for part in item_text.split(','):
                    if ':' in part:
                        k, v = part.split(':', 1)
                        item_dict[k.strip()] = v.strip().strip('"').strip("'")
                current_list.append(item_dict)
                in_dict_item = False
            elif ':' in item_text:
                # Start of multi-line dict item: "- field: command"
                in_dict_item = True
                k, v = item_text.split(':', 1)
                current_dict = {k.strip(): v.strip().strip('"').strip("'")}
            else:
                # Simple list item
                current_list.append(item_text.strip('"').strip("'"))
                in_dict_item = False

        # Continuation of dict item (indented under list item)
        elif indent > 2 and in_dict_item and ':' in line:
            # This is a field of the current dict item
            k, v = stripped.split(':', 1)
            current_dict[k.strip()] = v.strip().strip('"').strip("'")

    # Save final list/dict if any
    if in_list and current_key:
        if in_dict_item and current_dict:
            current_list.append(current_dict)
        frontmatter[current_key] = current_list

    return frontmatter, message
