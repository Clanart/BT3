### Title
ProtoJSON serialization ignores `debug_redact` and re-exposes fields marked sensitive - ([File: src/google/protobuf/json/json.h])

### Summary
Protobuf's `debug_redact` field option is designed so that fields containing credentials/secrets are hidden whenever a message is rendered for debugging/logging/display. The C++ implementation only enforces this in `TextFormat`/`DebugString` (`Message::DebugString`, `ShortDebugString`, `Utf8DebugString`) via `TextFormat::Printer::TryRedactFieldValue`, but `PrintOptions`/`ParseOptions` for ProtoJSON (`MessageToJsonString`/`MessageToJsonStream` in `json.h`) contain no redaction knob, and the JSON serialization path (`json/internal/unparser.cc`) never consults `FieldDescriptor`/`FieldOptions.debug_redact()` at all. A consuming application that displays "sensitive credential-like config fields" in a UI (the Mattermost analog) via ProtoJSON rather than TextFormat will leak them verbatim, even though the schema author explicitly annotated those fields as sensitive.

### Finding Description
The Mattermost advisory's failed invariant is: fields intended to be hidden from an administrative UI were nonetheless serialized into the UI output because the display/serialization path did not honor the "sensitive" marking on those fields.

The directly transferable Protobuf analog is the `debug_redact` field option (`src/google/protobuf/descriptor.proto:776-778`):
```
// Indicate that the field value should not be printed out when using debug
// formats, e.g. when the field contains sensitive credentials.
optional bool debug_redact = 16 [default = false];
``` [1](#0-0) 

The invariant "fields marked `debug_redact=true` must not appear in debug/print output" is enforced end-to-end for the TextFormat/DebugString family:
- `TextFormat::Printer::TryRedactFieldValue` checks `TextFormat::GetRedactionState(field)` and substitutes `[REDACTED]` for the value when `redact_debug_string_` is set. [2](#0-1) 
- `Message::DebugString()`/`ShortDebugString()`/`Utf8DebugString()` route through `internal::StringifyMessage`, which always calls `printer.SetRedactDebugString(true)` before printing. [3](#0-2) 
- Extensive unit tests (`RedactedFields`, `TestNestedMessageRedaction`, `unittest_redaction.proto`, `DebugFormatTest`, `text_format_unittest.cc`) validate this for scalar, repeated, map, message, and extension fields. [4](#0-3) [5](#0-4) 

However, the same annotation is **not** consulted anywhere in the ProtoJSON output path:
- `json::PrintOptions` (the only per-call configuration surface for `MessageToJsonString`/`MessageToJsonStream`) has fields for whitespace, enum-as-int, field-name preservation, etc., but no redaction option and no reference to `debug_redact`. [6](#0-5) 
- The field-writing routine `WriteField` in `unparser.cc`, which decides how to emit each field's name/value into the JSON stream, only branches on extension-ness, `preserve_proto_field_names`, map/repeated-ness, and presence — it never queries `FieldOptions.debug_redact()` or any redaction state. [7](#0-6) 
- A repo-wide search for `redact` under `src/google/protobuf/json/**` returns no matches at all, confirming the JSON writer/parser implementation has zero awareness of the option (searched via `grep_search` for `redact` in `src/google/protobuf/json/**`, no results).

Because `google.protobuf.json::MessageToJsonString` is a supported public API that many applications use to render protobuf messages for debugging UIs, config dumps, or admin consoles (functionally the same "render a config/settings object for an operator" use case as Mattermost's System Console), any field marked `debug_redact = true` in the schema will still be fully printed in the JSON output, defeating the schema author's explicit intent and the guarantee implied by the option's own documentation ("the field value should not be printed out when using debug formats").

### Impact Explanation
This is a genuine sensitive-information-disclosure gap: an application relying on `debug_redact` as its cross-format redaction mechanism (reasonably, since it's a schema-level, not format-level, annotation) will unintentionally expose credential/secret fields whenever it renders messages via ProtoJSON instead of TextFormat/DebugString — e.g., logging a request/response as JSON, or rendering a settings/config object in a JSON-based UI. This matches CWE-200 (information exposure) and the CVSS vector's confidentiality-only impact (no integrity/availability effect), analogous in severity to the original Medium-rated Mattermost issue.

### Likelihood Explanation
High likelihood of occurrence in practice: `debug_redact` is documented as a general "don't print in debug formats" mechanism, and ProtoJSON output is a very common way applications log/display messages (arguably more common than C++ TextFormat in many services, especially outside C++). There is no code path or check that will fail loudly — the redaction is silently absent, so any team assuming schema-level `debug_redact` protection is automatically bypassed by choosing JSON as the debug/log format.

### Recommendation
Extend `json::PrintOptions` and the `unparser.cc` `WriteField`/`WriteFields` path to check `FieldDescriptor::options().debug_redact()` (and the equivalent enum/message-option indirection logic already implemented in `TextFormat::GetRedactionState`/`IsOptionSensitive`) and substitute a redacted placeholder for sensitive fields, mirroring the TextFormat behavior. At minimum, this gap should be documented prominently in the `debug_redact` option's comments in `descriptor.proto` so users are not misled into believing it applies uniformly across all "debug" serialization formats, and language runtimes exposing `MessageToJsonString`/similar JSON printers should audit for the same gap.

### Proof of Concept
Given a schema field marked sensitive:
```proto
message RedactedFields {
  string optional_redacted_string = 1 [debug_redact = true];
}
``` [8](#0-7) 

1. `RedactedFields msg; msg.set_optional_redacted_string("super-secret-token");`
2. `msg.DebugString()` correctly yields `optional_redacted_string: [REDACTED]\n` because `StringifyMessage` sets `SetRedactDebugString(true)` before printing. [9](#0-8) 
3. `std::string json; google::protobuf::json::MessageToJsonString(msg, &json);` (or `google::protobuf::util::MessageToJsonString`) produces `{"optionalRedactedString":"super-secret-token"}` — the secret is emitted in full, because `PrintOptions` has no redaction switch and `WriteField` never inspects `debug_redact`. [6](#0-5) [10](#0-9) 

This reproduction is based on static code inspection of the checked-out repository; no test binary was executed to confirm runtime output, but the absence of any `debug_redact`/redaction reference in the entire `src/google/protobuf/json/` tree, contrasted with its thorough implementation and test coverage in `text_format.cc`/`text_format_unittest.cc`, strongly supports this conclusion.

std::string StringifyMessage(const Message& message, Option option,
                             FieldReporterLevel reporter_level) {
  // Indicate all scoped reflection calls are from DebugString function.
  ScopedReflectionMode scope(ReflectionMode::kDebugString);

  TextFormat::Printer printer;
  internal::FieldReporterLevel reporter = reporter_level;
  switch (option) {
    case Option::kShort:
      printer.SetSingleLineMode(true);
      break;
    case Option::kUTF8:
      printer.SetUseUtf8StringEscaping(true);
      break;
    case Option::kNone:
      break;
  }
  printer.SetExpandAny(true);
  printer.SetRedactDebugString(true);
  printer.SetRandomizeDebugString(true);
  printer.SetReportSensitiveFields(reporter);
  std::string result;
  // TODO: Remove this suppression.
  (void)printer.PrintToString(message, &result);

  if (option == Option::kShort) {
    TrimTrailingSpace(result);
  }

  return result;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

        !absl::ascii_isupper(json_name[0])) {
