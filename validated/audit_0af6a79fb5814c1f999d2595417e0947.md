### Title
Server log entry spoofing via newline injection in the `console.log` precompile - (File: blockchain/vm/contracts.go)

### Summary
Kaia ships a Hardhat-compatible `console.log` precompile (`consoleLog`) reachable at the fixed address `0x000000000000000000636F6E736F6C652E6C6F67` from every fork's precompile map [1](#0-0) . Any transaction sender or contract can invoke it with attacker-controlled calldata; the decoded string is written straight into the node's log stream without sanitizing control characters, mirroring the CVE-2021-20333 "server log entry spoofing via newline injection" bug class.

### Finding Description
`consoleLog.Run` decodes the ABI-encoded arguments of the call and passes the resulting string directly to the module logger with no escaping: [2](#0-1) 
The `StringTy`/`BytesTy` decode paths simply slice the raw calldata bytes into a Go `string`/hex string with no filtering of `\n`, `\r`, or ANSI escape sequences: [3](#0-2) 
`toLogString` then joins the decoded parameters with spaces and returns that raw string to `Run`, which forwards it verbatim as `logger.Debug(decoded)` [4](#0-3) .

The logging pipeline's terminal formatter interpolates the log record's message (`r.Msg`) directly into the output line via `fmt.Fprintf`, with no escaping of embedded newlines/control bytes — only key/value context fields go through `formatLogfmtValue`/`escapeString`: [5](#0-4) 
Because the attacker fully controls `r.Msg` (the decoded console.log string) and it bypasses the escaping applied to context values, embedding `"\n"` sequences that look like `[[LEVEL]] ...` allows fabricating or splitting arbitrary log lines in the node's terminal-formatted log output, exactly the "artificial log entries" / "log entries split" scenario described in the CVE.

### Impact Explanation
Any account able to submit a transaction or deploy a contract that performs a `STATICCALL`/`CALL` to the console-log precompile address can forge or corrupt node log entries. This can be used to plant misleading operational/audit records (e.g., fake critical/error lines, injected fabricated key=value pairs), undermining log-based monitoring, incident response, and forensic integrity for validator/full-node operators — matching the Medium severity of the analog CVE.

### Likelihood Explanation
The precompile is present unconditionally in every fork's precompile map (Byzantium through Cancun) [6](#0-5) , requires no special privilege, and can be triggered by a single unprivileged transaction with crafted calldata to the well-known console-log address. The only prerequisite is that the node's log output uses the terminal formatter (common for CLI/local/verbose logging), which does not escape the message field.

### Recommendation
Sanitize the decoded `console.log` string before logging (strip/escape control characters such as `\n`, `\r`, and ANSI escape sequences) in `consoleLog.decode`/`toLogString`, and additionally have `TerminalFormat` (and any other formatter that writes `r.Msg` unescaped) run the message text through the same escaping function used for context values (`escapeString`/`formatLogfmtValue`) before writing it to the log stream.

### Proof of Concept
1. Craft calldata for a `console.log(string)` call (selector matching a registered `common.ConsoleLogSignatures` entry) whose ABI-encoded string payload is:
   `"benign\n[CRIT][01-01|00:00:00] fake critical event module=consensus"`
2. Submit a transaction (or have any contract execute) a `CALL` to `0x000000000000000000636F6E736F6C652E6C6F67` with this calldata.
3. `consoleLog.Run` decodes the string and calls `logger.Debug(decoded)` [7](#0-6) .
4. On a node using the terminal log formatter, the resulting log stream contains two lines instead of one, the second one appearing as a legitimate-looking forged `[CRIT]` entry, because `r.Msg` is written unescaped [8](#0-7) .

// Hardhat console.log accepts format string, however we don't support it.
// Instead, we just join all the parameters with a space.
func (c *consoleLog) toLogString(input []byte) (string, error) {
	if len(input) < 4 {
		return "", errors.New("input too short")
	}
	selector := binary.BigEndian.Uint32(input[:4])
	params := input[4:]

	types, ok := common.ConsoleLogSignatures[selector]
	if !ok {
		return "", errors.New("unknown selector")
	}
	decoded, err := c.decode(params, types)
	if err != nil {
		return "", err
	}

	return strings.Join(decoded, " "), nil
}
