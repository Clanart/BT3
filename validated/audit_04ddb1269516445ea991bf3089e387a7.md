## Analog Found: Spoofed `WWW-Authenticate` Header Lets a Malicious Git Remote Impersonate GitHub Enterprise and Hijack the Sign-In Flow

### Title
Attacker-controlled git host can spoof `WWW-Authenticate: realm="GitHub"` to bypass host verification and hijack Desktop's Enterprise sign-in flow — (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The bug-class in the original report is "a value read from the wrong/attacker-influenced source is trusted to update a security-relevant record." The Desktop analog is `getEndpointKind()` in the trampoline credential helper, which classifies an unknown git remote host as a genuine GitHub Enterprise (`enterprise`) endpoint purely because the **remote server's own HTTP response** contains a `WWW-Authenticate` header with `realm="GitHub"`, skipping the actual network-based authenticity check (`isGitHubHost()`) that exists for exactly this purpose.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's trampoline credential helper, forwarding any `WWW-Authenticate` headers it captured from the server as `wwwauth[...]` parameters: [1](#0-0) 

Specifically:
```
// When Git attempts to authenticate with a host it captures any
// WWW-Authenticate headers and forwards them to the credential helper. We
// use them as a happy-path to determine if the host is a GitHub host without
// having to resort to making a request ourselves.
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
```
This header is entirely attacker-controlled: any git server (a malicious/typosquatted remote, a compromised git host, or a MITM proxy on an internal network) that the user clones/fetches/pushes to can simply respond with `WWW-Authenticate: Basic realm="GitHub"` on a 401 challenge, and Desktop will treat that arbitrary host as `'enterprise'` **without ever calling** `isGitHubHost()`, the function whose entire purpose is to validate a host via version headers or a real network probe to `/meta`: [2](#0-1) .

Once classified as `'enterprise'`, `getCredential()` finds no existing account for that host and calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then wires the attacker's raw origin directly into the Enterprise sign-in flow: [4](#0-3) 

`this.dispatcher.setSignInEndpoint(origin)` sets the sign-in target to the attacker's host, and the subsequent `SignIn` popup is shown with `credentialHelperUrl: endpoint` set to that same attacker URL. If the user proceeds (believing this is a legitimate "sign in to continue this clone/fetch" prompt, since Desktop itself asserted it's a "GitHub" host), the OAuth/basic-auth exchange (`requestOAuthToken`, `fetchUser`) is performed against the attacker's endpoint: [5](#0-4) . This sends the OAuth `client_id`/`client_secret` and, if the flow completes, the user's resulting session/token material to a host the attacker fully controls.

### Impact Explanation
This breaks the invariant that only a network-verified real GitHub/GHE host can trigger Desktop's authenticated sign-in UI and receive OAuth `client_secret`/tokens. An attacker who merely controls a git remote/proxy that the victim clones or fetches from can:
- Trick Desktop into displaying a "Sign in to GitHub Enterprise" prompt for their host, phishing the user's GitHub credentials or OAuth authorization.
- Exfiltrate the OAuth `client_id`/`client_secret` and authorization code sent to `requestOAuthToken`'s `urlBase`, which resolves to the attacker's host.
This matches the accepted impact category: "unauthorized OAuth ... or credential/token exfiltration" triggered by "a git remote/proxy response."

### Likelihood Explanation
Exploitation requires no local access, admin rights, or prior malware — only that the victim adds/clones/fetches from a remote controlled or proxied by the attacker (a common, unprivileged action for GitHub Desktop users), and that the server returns a crafted `WWW-Authenticate` header, which is trivial for any HTTP server to do. The `isGitHubHost()` verification path exists precisely to prevent host spoofing, but the `wwwauth[...]` "happy path" check in `getEndpointKind()` is reached and returns before that verification is ever attempted.

### Recommendation
Do not trust the `WWW-Authenticate` realm string from an unauthenticated host to classify it as GitHub/GHE. Either remove this branch or treat it only as a soft hint that still requires the `isGitHubHost()` network verification (or equivalent TLS/cert-pinned check against known GitHub domains) before returning `'enterprise'`. At minimum, `promptForGitHubSignIn` should refuse to initiate an Enterprise sign-in flow (which exchanges `client_secret`) for a host that has not been positively verified as GitHub-compatible.

### Proof of Concept
1. Attacker sets up an HTTPS git server at `https://evil.example.com/repo.git` (or a MITM proxy intercepting traffic to a spoofed/typosquatted host) that, on any authentication challenge, responds with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this as a remote in GitHub Desktop (or clones it directly) and performs a fetch/push.
3. Git captures the header and forwards it via `wwwauth[...]` to Desktop's trampoline credential helper (`createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`).
4. `getEndpointKind` matches `realm="GitHub"` and returns `'enterprise'` without calling `isGitHubHost`.
5. Since no account exists for `evil.example.com`, `ui.promptForGitHubSignIn('https://evil.example.com')` is invoked, opening a GitHub Enterprise sign-in dialog pointed at the attacker's origin.
6. If the victim signs in, `requestOAuthToken`/basic-auth requests (including Desktop's OAuth `client_id`/`client_secret`) are sent to `evil.example.com`, which the attacker fully controls and can log/relay.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
