### Title
Deterministic nonce reuse in `DkgConfirmer` — a second `share`/`complete` call under the same attempt signs a new message with an identical FROST nonce, allowing public recovery of the validator's signing key share - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The CVE class (use-after-free: an object used after it should have been consumed/invalidated) maps onto Serai as *state-machine reuse*: `AlgorithmSignMachine::from_cache` deterministically regenerates FROST nonces from a 32-byte seed, and `SigningProtocol::preprocess_internal` stores that seed keyed only by `(b"DkgConfirmer", attempt)`, so every call under the same attempt produces the **same** nonce commitments. `share_internal` is invoked twice per attempt — once via `DkgConfirmer::share` (from `generated_key_pair`) and once inside `DkgConfirmer::complete` — and `generated_key_pair` unconditionally overwrites `DkgKeyPair`/`KeyToDkgAttempt` with no duplicate guard, so a second `GeneratedKeyPair` for the same attempt re-signs a *different* `set_keys_message` under identical nonces. ### Finding Description
`AlgorithmMachine::seeded_preprocess` derives nonces via `ChaCha20Rng::from_seed(*seed.0)`, so a `CachedPreprocess` seed fully determines the binomial nonces `(d, e)` [5](#0-4) . The FROST crate documents that a cached preprocess "MUST only be used once" because reuse enables recovery of the private key share [6](#0-5) . `preprocess_internal` stores the seed XOR-encrypted under `CachedPreprocesses` keyed only by `context = (b"DkgConfirmer", attempt)` and re-derives it on every call — it is never consumed or deleted [7](#0-6) . The signed message is `set_keys_message(set, removed, key_pair)`, so the message — and therefore the MuSig/Schnorr challenge — varies with `key_pair` [8](#0-7) . `generated_key_pair` calls `DkgKeyPair::set` (overwriting without any `is_none()` check, unlike `DataDb`/`SlashReports` guards elsewhere in `handle_data`) and then `share()`, publishing a signature share [4](#0-3) . `complete()` re-invokes `share_internal`, producing a second published share [9](#0-8) . The file's own header concedes nonce reuse leaks the share and that safety rests only on BFT message ordering plus an unimplemented "check the commitments generated from the decided nonces are in fact its commitments on-chain (TODO)" [10](#0-9) .

### Impact Explanation
Two published signature shares `s1 = k + c1·x`, `s2 = k + c2·x` under the same nonce `k` (identical `R` in the completed signatures / identical preprocess commitments) but different challenges `c1 ≠ c2` (different `key_pair` or different confirmation-preprocess set) yield the validator's MuSig secret share by `x = (s1 − s2)/(c1 − c2)`. All shares are published on the public tributary as `DkgConfirmed` transactions, so any observer can perform the recovery. This is full key-share recovery of a validator's root-of-trust key, enabling the attacker (combined with the share's weight in MuSig aggregation) to forge `set_keys` confirmations. Severity: High/Critical.

### Likelihood Explanation
Triggering requires `generated_key_pair`/`complete` to be reached twice for one attempt with distinct `key_pair` or preprocess inputs. The overwrite at `handle.rs:54` has no duplicate guard, and DKG key-pair generation is driven by `CoordinatorMessage::Shares`/`VerifyBlame` traffic that unprivileged network peers influence through the DKG shares they publish on tributary (`Transaction::DkgShares` / `InvalidDkgShare` are accepted from any validator and alter the resulting key pair and the confirmation-preprocess set). Because `ConfirmationNonces` is snapshotted at share-accumulation time while `share()`/`complete()` each re-sign whatever the current `key_pair`/preprocess map is, differing inputs produce distinct challenges under the same nonce. The exploit needs no leaked key, no unsafe code, and no colluding threshold — only causing a second confirmation signing under one attempt.

### Recommendation
Consume the cached preprocess: delete `CachedPreprocesses[context]` (or mark it spent) inside `share_internal` before calling `machine.sign`, and refuse to sign if already spent — enforcing "MUST only be used once" in code rather than by BFT assumption. Additionally, guard `generated_key_pair` with `DkgKeyPair::get(...).is_none()` so a second `key_pair` for the same attempt cannot overwrite the first, and implement the noted TODO of verifying the on-chain confirmation nonces match the locally derived preprocess before publishing any share.

### Proof of Concept
Conceptual (protocol trace, all artifacts public on tributary):

1. Attempt `a` of a DKG completes its share round; `ConfirmationNonces` for `a` is stored. Processors emit `GeneratedKeyPair(kp1)`; `generated_key_pair` stores `kp1` and the validator publishes `share1` signing `set_keys_message(set, removed, kp1)` using nonces derived from seed `S = decrypt(CachedPreprocesses[(b"DkgConfirmer", a)])`.
2. A second `GeneratedKeyPair(kp2)`, `kp2 ≠ kp1`, is processed for the same `a` (possible because `DkgKeyPair::set` overwrites unconditionally and no spent flag exists). `share()` re-derives the identical nonce `k` from `S` and publishes `share2` signing `set_keys_message(set, removed, kp2)` — different `c`, same `k`.
3. Attacker reads `share1`, `share2`, reconstructs `c1 = H(R, group_key, msg1)`, `c2 = H(R, group_key, msg2)` from the public commitments/messages, and computes `x = (share1 − share2)·(c1 − c2)⁻¹ mod l`, recovering the validator's Ristretto secret share. Verification: `Ristretto::generator() * x == signer_public_key`.

Uncertainty noted: whether processors can be induced to emit two distinct `GeneratedKeyPair`s for one attempt depends on `processor/src/key_gen.rs` behavior not fully traced here; regardless, `share()` followed by `complete()` already demonstrates the same nonce being loaded twice, and the missing spent-flag/overwrite-guard removes the only enforcement of the single-use precondition the FROST library mandates.

  As for safety, it is explicitly unsafe to reuse nonces across signing sessions. This raises
  concerns regarding our re-execution which is dependent on fixed nonces. Safety is derived from
  the nonces being context-bound under a BFT protocol. The flow is as follows:

  1) Decide the nonce.
  2) Publish the nonces' commitments, receiving everyone elses *and potentially the message to be
     signed*.
  3) Sign and publish the signature share.

  In order for nonce re-use to occur, the received nonce commitments (or the message to be signed)
  would have to be distinct and sign would have to be called again.

  Before we act on any received messages, they're ordered and finalized by a BFT algorithm. The
  only way to operate on distinct received messages would be if:

  1) A logical flaw exists, letting new messages over write prior messages
  2) A reorganization occurred from chain A to chain B, and with it, different messages

  Reorganizations are not supported, as BFT is assumed by the presence of a BFT algorithm. While
  a significant amount of processes may be byzantine, leading to BFT being broken, that still will
  not trigger a reorganization. The only way to move to a distinct chain, with distinct messages,
  would be by rebuilding the local process (this time following chain B). Upon any complete
  rebuild, we'd re-decide nonces, achieving safety. This does set a bound preventing partial
  rebuilds which is accepted.

  fn preprocess_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
  ) -> (AlgorithmSignMachine<Ristretto, Schnorrkel>, [u8; 64]) {
    // Encrypt the cached preprocess as recovery of it will enable recovering the private key
    // While the DB isn't expected to be arbitrarily readable, it isn't a proper secret store and
    // shouldn't be trusted as one
    let mut encryption_key = {
      let mut encryption_key_preimage =
        Zeroizing::new(b"Cached Preprocess Encryption Key".to_vec());
      encryption_key_preimage.extend(self.context.encode());
      let repr = Zeroizing::new(self.key.to_repr());
      encryption_key_preimage.extend(repr.deref());
      Blake2s256::digest(&encryption_key_preimage)
    };
    let encryption_key_slice: &mut [u8] = encryption_key.as_mut();

    let algorithm = Schnorrkel::new(b"substrate");
    let keys: ThresholdKeys<Ristretto> =
      musig(musig_context(self.spec.set().into()), self.key.clone(), participants)
        .expect("signing for a set we aren't in/validator present multiple times")
        .into();

    if CachedPreprocesses::get(self.txn, &self.context).is_none() {
      let (machine, _) =
        AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);

      let mut cache = machine.cache();
      assert_eq!(cache.0.len(), 32);
      #[allow(clippy::needless_range_loop)]
      for b in 0 .. 32 {
        cache.0[b] ^= encryption_key_slice[b];
      }

      CachedPreprocesses::set(self.txn, &self.context, &cache.0);
    }

    let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
    let mut cached: Zeroizing<[u8; 32]> = Zeroizing::new(cached);
    #[allow(clippy::needless_range_loop)]
    for b in 0 .. 32 {
      cached[b] ^= encryption_key_slice[b];
    }
    encryption_key_slice.zeroize();
    let (machine, preprocess) =
      AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached));

    (machine, preprocess.serialize().try_into().unwrap())

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
