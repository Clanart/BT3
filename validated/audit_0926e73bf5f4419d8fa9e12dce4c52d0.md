### Title
Attacker-declared `ReceivedOutput` value satisfies balance/fee checks, crediting non-existent, unspendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Teller bug class is: a sufficiency check (`paymentAmount >= _owedAmount`) is evaluated over attacker-declared values rather than over value actually transferred, so collateral is released without payment. In bitcoin-serai, `ReceivedOutput::read` deserializes an offset, a full `TxOut` (including `value`), and an `OutPoint` entirely from untrusted bytes, with no binding that the outpoint exists on-chain or that the declared `value` is real. `SignableTransaction::new` then evaluates its solvency check (`input_sat >= payment_sat + needed_fee`) against these attacker-declared values — the same "declared amount satisfies the check" flaw — and `SignableTransaction::multisig` only checks self-consistency between the supplied offset and the supplied script, both of which the attacker controls.

### Finding Description
`ReceivedOutput::read` reads `offset`, `output` (a `TxOut` whose `value` field is the claimed balance), and `outpoint` directly from the reader, performing no semantic validation beyond consensus-decodability [1](#0-0) . There is no check that `outpoint` refers to a real UTXO, that the output's `script_pubkey` corresponds to `key + offset*G`, or that `value` matches any on-chain reality.

`SignableTransaction::new` computes `input_sat` by summing `input.output.value` over the provided `ReceivedOutput`s and gates funding on `input_sat < (payment_sat + needed_fee)` [2](#0-1) . An attacker who supplies a `ReceivedOutput` with a fabricated `TxOut.value` (e.g., 21M BTC worth of sats) trivially satisfies this check with zero real funds — the exact analog of passing `paymentAmount >= _owedAmount` by declaring a large `_amount`.

The only later consistency check is in `multisig`: `p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey` [3](#0-2) . Since the attacker chose both `offset` and `TxOut.script_pubkey`, they set `script_pubkey` to the p2tr script of `key + offset*G` themselves — the check compares attacker-supplied data against attacker-supplied data and always passes. The threshold group then runs FROST signing (`TransactionSignMachine::sign`/`complete`) over a sighash committing to `Prevouts::All` containing the fabricated `TxOut` [4](#0-3) .

### Impact Explanation
Funds are reported as received that are not spendable: any consumer treating `ReceivedOutput`s as real deposits credits the declared `value` despite the `outpoint` pointing to a nonexistent or unrelated output. Downstream, the honest threshold signers produce a fully valid FROST signature for a transaction spending phantom coins — wasting signing attempts, burning a nonce/preprocess round, and recording a bogus spend/completion. This mirrors the report's "collateral returned without the lender being paid": a state transition (credit granted / signature produced) is authorized on the basis of a declared quantity rather than transferred value.

### Likelihood Explanation
Reachability is explicit per the scope rules: `ReceivedOutput::read` accepts untrusted bytes. Any deployment where received outputs are relayed between components (scanner → coordinator → signers) or persisted/restored through serialized form lets an unprivileged party inject a forged `ReceivedOutput`. No validator privileges, collusion, or leaked keys are required — only the ability to feed bytes to `read`.

### Recommendation
`ReceivedOutput` (or a wrapper around it) should carry proof of authenticity — e.g., only be constructible via `Scanner::scan_transaction`/`scan_block` against confirmed chain data, or `read` should be paired with a required RPC verification that the `outpoint` resolves to a `TxOut` with matching `value` and `script_pubkey`. At minimum, `SignableTransaction::new`/`multisig` should not treat deserialized `ReceivedOutput`s as authoritative balances; the solvency check must be against verified UTXO values.

//   OutPoint = arbitrary txid:vout (points to nothing on-chain)
let forged = ReceivedOutput::read(&mut attacker_bytes).unwrap();

// SignableTransaction::new sees input_sat = 1e12 and passes the
// input_sat < payment_sat + needed_fee check despite zero real funds.

// multisig() passes because attacker set prevouts[0].script_pubkey to
// p2tr_script_buf((keys.offset(O)).group_key()) — attacker data vs attacker data.
let machine = stx.multisig(&keys).unwrap();
// Threshold signs a tx spending a nonexistent outpoint; signers' nonce round is
// consumed and the fabricated balance is treated as spendable funds.

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
