This is confirmed as an SSRF-analog reachable through a fully unprivileged, on-chain-mempool-reachable path: any wallet user can create a mirror coin advertising arbitrary URLs (`chia/data_layer/data_layer_wallet.py` `create_new_mirror`, memo-encoded via `create_mirror_puzzle`), and any DataLayer subscriber node that later syncs that store will fetch those attacker-chosen URLs from `fetch_and_validate()`/`download_file()` without any host/scheme restriction (`chia/data_layer/download_data.py`), matching the "Data Layer client" reachable category and the report's DNS-rebinding/SSRF bug class, since there's no allow/deny-list on the destination host (no `is_localhost`/private-range check found anywhere in `chia/data_layer/*.py`).

### Title
Unrestricted mirror-URL / plugin-download SSRF in DataLayer sync lets any spend bundle author force victim nodes to fetch attacker-chosen internal/external URLs - (File: chia/data_layer/download_data.py, chia/data_layer/data_layer_wallet.py)

### Summary
A DataLayer mirror coin's URLs are fully attacker-controlled on-chain data (via `CREATE_COIN` memos) that get parsed by `get_mirror_info()` and persisted by any subscribing wallet/DataLayer node, then later dereferenced with unauthenticated outbound HTTP requests by `http_download()`/`download_file()`/`get_plugin_info()` with no destination validation (no localhost/private-IP/DNS-rebinding protection), enabling SSRF against a victim node's local network from a single low-cost mempool-accepted spend.

### Finding Description
Any wallet holder can call `create_new_mirror()` to spend a coin to `create_mirror_puzzle()` with memos `[launcher_id, *urls]` where `urls` are arbitrary attacker-supplied strings [1](#0-0) . This is a normal, unprivileged, cheap spend bundle — no special permission is required to broadcast it.

When any other node's wallet observes this mirror coin on-chain, `coin_added()` decodes the URLs via `get_mirror_info()` (which simply reads CLVM condition memos, performing no validation of scheme/host) and stores them via `dl_store.add_mirror()` [2](#0-1) , and `get_mirror_info()` itself does no URL validation, just decodes memo bytes [3](#0-2) .

If that node's local DataLayer service is subscribed to (or owns) the referenced store, `update_subscriptions_from_wallet()` copies these URLs into the local subscription server list without any filtering [4](#0-3) . The periodic sync loop's `fetch_and_validate()` then picks a URL from `get_available_servers_for_store()` and issues outbound requests to it via `insert_from_delta_file()`/`download_file()` [5](#0-4) .

`download_file()`/`http_download()` and plugin-based `get_plugin_info()` construct `aiohttp` client requests directly against the attacker-chosen URL string with no scheme allow-list, no private/loopback IP block, and no DNS-rebinding protection (e.g. re-resolving/pinning the IP after a redirect or TTL expiry) [6](#0-5) [7](#0-6) . The module's own documentation acknowledges mirror/plugin URLs are "external trust inputs" but only calls out data validation of downloaded content, not destination-host validation [8](#0-7) . Test fixtures even demonstrate mirrors pointing at `http://127.0.0.1/8000` being accepted without any check [9](#0-8) .

This is directly analogous to PYSEC-2024-74/CVE-2024-24759: an SSRF-protection bypass via attacker-controlled destination resolution — except here there is no SSRF protection at all for DataLayer mirror/plugin URLs, so a plain SSRF (not even requiring DNS rebinding) already succeeds.

### Impact Explanation
A single cheap, unprivileged on-chain spend (mirror coin creation) can cause any peer running a DataLayer node that syncs the affected store to issue outbound HTTP requests to attacker-chosen hosts, including internal-network/loopback addresses and cloud metadata endpoints reachable from that node's network. This can be used to probe/attack internal services, exfiltrate data via crafted query strings/paths, or cause resource exhaustion/denial of service against the victim node's DataLayer sync loop (repeated download attempts, `ClientConnectionError` backoff cycles). Because DataLayer subscriptions/mirrors are open to any store participant and this pathway crosses trust boundaries (attacker chain data -> victim node's own network egress), it satisfies "coin-set/DataLayer client-reachable, spend-triggered" impact criteria; severity here is bounded by SSRF rather than fund theft.

### Likelihood Explanation
High likelihood of reachability: creating a mirror coin is a standard, low-cost wallet operation available to any user with the `dl_new_mirror` RPC or direct spend construction; no special privileges, timelord/farmer/harvester access, or malicious peer/network position is needed. The victim only needs to run a DataLayer node subscribed to (or owning, since owned stores also read mirrors for sync) the same store id. Exploitation does not require guessing internal topology in advance if the goal is generic SSRF probing/DoS.

### Recommendation
Add destination validation before any outbound DataLayer HTTP request (`http_download`, plugin `download_file`, `get_plugin_info`, `dl_get_mirrors`-derived subscription URLs): enforce an allow-list of schemes (`http`/`https`), resolve and reject private/loopback/link-local/multicast/metadata IP ranges, pin the resolved IP for the duration of the connection (to defeat DNS rebinding on redirect or reconnection), and reject or explicitly opt-in only for `localhost`/private ranges in trusted/dev configurations. Apply the same validation to plugin `PluginRemote.url` values before any request is made in `chia/data_layer/data_layer.py` and `chia/data_layer/download_data.py`.

### Proof of Concept
1. Attacker creates a DataLayer store or targets an existing one, then calls `dl_new_mirror` (or equivalent wallet RPC / raw spend) with `urls=["http://169.254.169.254/latest/meta-data/", "http://<victim-internal-service>:port/admin"]`, as shown to be trivially accepted in [9](#0-8) .
2. Broadcast the resulting spend bundle to the mempool; it is accepted as an ordinary coin spend.
3. Any victim node's wallet with `DataLayerWallet` tracking that launcher id ingests the mirror coin in `coin_added()`, storing the attacker URLs [2](#0-1) .
4. If the victim's local `DataLayer` service is subscribed to that store, its periodic loop calls `update_subscriptions_from_wallet()` then `fetch_and_validate()`, which will pick the attacker URL and call `download_file()`, causing the victim node process to issue an outbound HTTP request to the attacker-chosen internal/arbitrary address [5](#0-4) [6](#0-5) .

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def get_plugin_info(
    plugin_remote: PluginRemote, timeout: aiohttp.ClientTimeout
) -> tuple[PluginRemote, dict[str, Any]]:
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                plugin_remote.url + "/plugin_info",
                json={},
                headers=plugin_remote.headers,
                timeout=timeout,
            ) as response:
                ret = {"status": response.status}
                if response.status == 200:
                    ret["response"] = json.loads(await response.text())
                return plugin_remote, ret
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        return plugin_remote, {"error": f"{type(e).__name__}: {e}"}
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
