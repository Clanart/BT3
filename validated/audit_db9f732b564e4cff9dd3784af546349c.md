### Title
Empty `SchnorrAggregate` deserializes and verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an aggregate with zero `Rs`, while `verify` only checks that its length equals `keys_and_challenges.len()` before evaluating the linear combination. [1](#0-0) [2](#0-1) 

### Finding Description
When both `Rs` and `keys_and_challenges` are empty and `s == 0`, the verifier constructs only the pair `(-s, generator)`, which evaluates to the identity and returns `true`. [3](#0-2)  This bypasses the invariant enforced by the honest aggregation path, where `SchnorrAggregator::complete` explicitly returns `None` when no signatures were aggregated. [4](#0-3) 

### Impact Explanation
An untrusted party can provide a serialized aggregate signature that verifies without possessing any signer’s secret key. [1](#0-0)  If an application treats successful aggregate verification as authorization over an externally supplied statement set, the empty-statement case creates a forged-signature acceptance path. [2](#0-1) 

### Likelihood Explanation
The malformed object is reachable entirely through public input bytes passed to `SchnorrAggregate::read`, followed by the public `verify` API. [1](#0-0)  The impact is bounded to acceptance of an empty aggregate, but the discrepancy with `SchnorrAggregator::complete` shows this is not an intended valid signature state. [4](#0-3) 

### Recommendation
Reject empty aggregates in both `SchnorrAggregate::read` and `SchnorrAggregate::verify`, or at minimum return `false` whenever `keys_and_challenges.is_empty()`. [1](#0-0) [5](#0-4)

```rust
use frost::curve::Secp256k1;

let mut bytes = Vec::from(0u32.to_le_bytes()); // zero Rs
bytes.extend([0u8; 32]);                       // canonical zero scalar for s

let aggregate = SchnorrAggregate::<Secp256k1>::read(&mut bytes.as_slice()).unwrap();
assert!(aggregate.verify(b"example-domain", &[]));
```

The four-byte count permits `Rs` to be empty, and the zero scalar makes the final `-s * generator` term the identity. [6](#0-5) [3](#0-2)
