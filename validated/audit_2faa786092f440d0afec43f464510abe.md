### Title
Unchecked `upb_Decode` status in PHP `Message::mergeFrom()` causes silent partial merge - (File: `php/ext/google/protobuf/message.c`)

### Summary
The PHP native extension's `Message::mergeFrom()` re-serializes the source message and decodes the resulting bytes into the destination message via `upb_Decode()`. The `upb_DecodeStatus` returned by that call is only checked through `PBPHP_ASSERT(ok)`, a debug-only assertion, rather than through an explicit runtime check that raises a PHP exception (as is done for the sibling encode path two lines above via `Message_checkEncodeStatus`). In a production (non-debug/`NDEBUG`) build the assert compiles away, so a failed decode is silently swallowed and the API returns as if the merge succeeded.

### Finding Description
`Message::mergeFrom()` performs an encode-then-decode round trip: [1](#0-0) 

The encode half is properly checked:
```c
upb_EncodeStatus status = upb_Encode(from->msg, l, 0, arena, &pb, &size);
if (!Message_checkEncodeStatus(status)) return;
```
`Message_checkEncodeStatus` explicitly switches over all failure codes (`kUpb_EncodeStatus_OutOfMemory`, `kUpb_EncodeStatus_MaxDepthExceeded`, `kUpb_EncodeStatus_MissingRequired`) and raises a `zend_exception` for each.

The decode half, in contrast, does:
```c
ok = upb_Decode(pb, size, intern->msg, l, NULL, 0, arena) == kUpb_DecodeStatus_Ok;
PBPHP_ASSERT(ok);
```
`upb_Decode()` is declared `UPB_NODISCARD` and can legitimately return non-`Ok` statuses such as `kUpb_DecodeStatus_MaxDepthExceeded`, `kUpb_DecodeStatus_Malformed`, `kUpb_DecodeStatus_MissingRequired`, or `kUpb_DecodeStatus_OutOfMemory`: [2](#0-1) 

The upb decoder itself can and does stop partway through a message on these conditions — e.g. it throws (via `longjmp`) as soon as `d->depth` is exhausted while recursing into submessages: [3](#0-2) 

When that happens mid-decode, `intern->msg` (the destination, which the caller already owns and may continue to use) is left in a partially-populated state — some fields already written by earlier `_upb_Decoder_DecodeField` iterations, the rest missing — while `Message::mergeFrom()` returns normally with no exception raised, because the only check on `ok` is a debug assertion that is compiled out.

**Invariant that transfers from the ERC20 report:** a function call's status/return value that signals "operation partially or fully failed" must be checked before the caller treats the operation as successful. In the ERC20 report, `transfer()`'s boolean return is ignored, so a failed transfer is treated as successful. Here, `upb_Decode()`'s status is likewise ignored (in release builds) so a failed/partial decode is treated as a successful merge.

### Impact Explanation
A caller invoking `$dest->mergeFrom($source)` on a `$source` message that (directly or indirectly, e.g. because it was originally populated by decoding deeply nested wire bytes or built up via the PHP setter API without any depth restriction at construction time) exceeds the upb decoder's default recursion/depth limit will silently receive a `$dest` object that is only partially merged, with no indication of failure. Application code that assumes a successful `mergeFrom()` implies a fully-updated, consistent message can act on stale/incomplete data — a silent data-integrity failure analogous to unnoticed ERC20 transfer failures. This is a Medium-severity issue: it does not achieve memory corruption or code execution (the C-level `upb_Decode` still enforces its bounds and safely aborts), but it produces reachable, attacker-influenceable silent state corruption in the PHP binding's public API.

### Likelihood Explanation
Reaching a non-`Ok` status requires the caller's own message (`$source`) to already be pathological in a specific way (e.g., depth exceeding the default decode limit), which is plausible in normal object-graph construction via the PHP API (no depth check is enforced when building a message field-by-field) and is trivially reachable by any code that merges a large/deeply nested message that was itself derived from attacker-controlled bytes. `PBPHP_ASSERT` behaves as a debug-only assert in this codebase's PHP extension build model, so production builds (which is how the PHP extension ships) do not perform any check at all, making the missing-check bypass unconditional in production.

### Recommendation
Replace `PBPHP_ASSERT(ok)` in `Message::mergeFrom()` with an explicit runtime check that mirrors `Message_checkEncodeStatus`, e.g. a `Message_checkDecodeStatus(status)` helper that inspects the actual `upb_DecodeStatus` value and raises a PHP exception (`Out of memory`, `Max nesting exceeded`, `Missing required field`, or a generic decode error) instead of silently continuing.

### Proof of Concept
Not independently executed in this pass (no build/test environment available); the analysis is based on static tracing of the code paths cited above:
1. `upb_DecodeStatus upb_Decode(...)` is declared `UPB_NODISCARD` and can return failure statuses (`upb/wire/decode.h:86-113`).
2. `_upb_Decoder_RecurseSubMessage` in `upb/wire/decode.c:191-205` throws `kUpb_DecodeStatus_MaxDepthExceeded` when `d->depth` is exhausted, mid-parse, after some fields of the destination message have already been written.
3. `Message::mergeFrom()` in `php/ext/google/protobuf/message.c:659-687` computes `ok` from the `upb_Decode()` return value and only asserts it (`PBPHP_ASSERT(ok)`), unlike the adjacent encode-status check (`Message_checkEncodeStatus`, lines 634-651) which properly raises exceptions.

A full reproduction would require building the PHP extension in a release (assertions-disabled) configuration, constructing a `$source` message whose corresponding wire-format graph exceeds `kUpb_WireFormat_DefaultDepthLimit`, calling `$dest->mergeFrom($source)`, and confirming that no PHP exception is thrown while `$dest` ends up only partially populated. This confirmation step was not run in this session.

UPB_FORCEINLINE
const char* _upb_Decoder_RecurseSubMessage(upb_Decoder* d, const char* ptr,
                                           upb_Message* submsg,
                                           const upb_MiniTable* subl,
                                           uint32_t expected_end_group) {
  if (--d->depth < 0) {
    upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_MaxDepthExceeded);
  }
  ptr = _upb_Decoder_DecodeMessage(d, ptr, submsg, subl);
  d->depth++;
  if (d->end_group != expected_end_group) {
    upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_Malformed);
  }
  return ptr;
}
