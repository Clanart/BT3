### Title
Unauthenticated tx-sender JSON-RPC `send_tx` / `send_citrea_tx` endpoints let any network caller queue and broadcast arbitrary transactions - ([File: crates/clementine-tx-sender/src/jsonrpc/server.rs])

### Summary
The external report's bug class is: an attacker with no privileged role reaches a state-changing/broadcasting endpoint that a bridge participant would normally trust only from itself, and the endpoint accepts attacker-controlled payloads that get persisted/queued without any signer authentication (the shardeum receipt-gossip endpoint accepted any signer's "receipt" and overwrote account state). The closest reachable analog in Clementine is `clementine-tx-sender`'s optional JSON-RPC server, which exposes `send_tx` and `send_citrea_tx` as fully unauthenticated methods that directly enqueue transactions for broadcast/DA submission, with no caller identity check at all.

### Finding Description
`start_jsonrpc_server` registers two RPC methods on a plain HTTP JSON-RPC server with no authentication layer: [1](#0-0) 

- `send_tx` deserializes an attacker-supplied `signed_tx_hex` and calls `TxSenderClient::insert_try_to_send`, which persists the transaction into `tx_sender`'s DB queue for CPFP/RBF-managed broadcast [2](#0-1) .
- `send_citrea_tx` deserializes an attacker-supplied `CitreaTxRequest` (batch proof / batch-proof method ID / sequencer commitment payload) and calls `TxSenderClient::send_citrea_tx`, which inserts it into `tx_sender_citrea_raw_tx_queue` for later DA submission [3](#0-2) [4](#0-3) .

There is no interceptor, signature check, or peer-certificate check anywhere in this module comparable to the mTLS `Interceptors::OnlyAggregatorAndSelf` used to gate the gRPC `Internal*` methods on the operator/verifier/aggregator servers [5](#0-4) . The bind address is configurable (`TX_SENDER_JSONRPC_BIND`, defaulting to `0.0.0.0` in some deployment scripts) and the smoke-test script demonstrates the intended usage pattern of POSTing directly to this port with no credentials [6](#0-5) [7](#0-6) .

The binding this breaks: "a caller reaching a signing or state-changing method versus the party it is meant for." The tx-sender's queue/fee-bumping machinery is meant to be driven only by the co-located operator/verifier/aggregator core process (via the in-process `TxSenderClient`), but the JSON-RPC feature exposes the same state-changing surface to any network caller who can reach the bound port, with zero verification that the caller is the entity that owns the tx-sender wallet/keys.

### Impact Explanation
This matches the High-severity category "an unauthenticated state-changing or broadcasting call." A caller with no protocol role (no verifier/operator/aggregator identity, no key) can:
- Enqueue arbitrary raw Bitcoin transactions for CPFP/RBF-fee-bumped broadcast via `send_tx`, potentially causing the tx-sender's wallet funds to be spent on fee-bumping unrelated/attacker-chosen transactions, or flooding the DB queue with garbage entries that the background sender loop must process.
- Enqueue arbitrary payloads into the Citrea DA queue via `send_citrea_tx` (`BatchProof`, `BatchProofMethodId`, `SequencerCommitment` kinds), which the tx-sender will eventually sign and submit as blob transactions using its own private key (`TxSenderSigningKey::sign_blob`) [8](#0-7) . This lets an unauthenticated caller cause the operator/verifier's Citrea DA-signing key to sign and broadcast attacker-chosen batch-proof/sequencer-commitment bytes, corrupting the DA queue that feeds Citrea's light client / batch prover.

This is not full custody-loss on its own (it does not directly move BTC out of a move-to-vault UTXO), but it does let an attacker outside any trust boundary drive a bridge participant's signing/broadcast pipeline, which can be used to grief fee-bumping, pollute the Citrea commitment/proof queue, or waste the operator's/verifier's on-chain funds — squarely inside "an unauthenticated state-changing or broadcasting call."

### Likelihood Explanation
Likelihood depends entirely on whether the `json-rpc` feature/server is enabled and how `TX_SENDER_JSONRPC_BIND` is configured. The repository's own example wiring (`run.sh`) defaults the bind address to `127.0.0.1`, and the design intent is clearly that this JSON-RPC surface is an internal control-plane channel, not a public API — there is no authentication because none was designed. If any deployment binds this server to a non-loopback interface (which the config explicitly allows: "Restricted to 127.0.0.1 or 0.0.0.0" per the doc comment in `TxSenderJsonRpcConfig`), the endpoint becomes reachable to any network peer with no credential at all. Because the code has no authentication mechanism built in (unlike the gRPC services, which have the `Interceptors` mTLS layer), likelihood is high whenever the feature is enabled and exposed beyond loopback — this is a code-level gap, not merely a misconfiguration ignoring documented guidance, since the config type itself documents `0.0.0.0` as a supported bind option [9](#0-8) .

### Recommendation
Add authentication/authorization to the tx-sender JSON-RPC server, mirroring the mTLS `Interceptors` scheme already used for the gRPC services (`core/src/rpc/interceptors.rs`), or otherwise cryptographically bind requests to the owning operator/verifier/aggregator (e.g., a shared secret/HMAC, or restrict transport to a local Unix socket / mTLS with a pinned client certificate). At minimum, default `TX_SENDER_JSONRPC_BIND` to loopback-only and document/enforce that this port must never be exposed beyond the local trust boundary; ideally, remove the `0.0.0.0` option from `TxSenderJsonRpcConfig` entirely and require the operator/verifier/aggregator process to be the sole caller via an in-process channel unless authenticated.

### Proof of Concept
1. Deploy `clementine-tx-sender` with the `json-rpc` feature enabled and `TX_SENDER_JSONRPC_BIND=0.0.0.0`, `TX_SENDER_JSONRPC_PORT=3030` (a supported configuration per `TxSenderJsonRpcConfig`).
2. From any unauthenticated network location, POST directly to the exposed port, e.g. the same request shape used in the project's own smoke test:
```
curl -sS -H 'content-type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"send_tx","params":[{"tx_metadata":null,"signed_tx_hex":"<attacker raw tx hex>","fee_paying_type":"NoFunding","rbf_signing_info":null,"cancel_outpoints":[],"cancel_txids":[],"activate_txids":[],"activate_outpoints":[]}]}' \
  http://<target>:3030
```
3. The transaction is inserted into `tx_sender`'s send queue and will be processed/fee-bumped by the background loop using the operator's/verifier's own signing key and wallet funds — with the caller having proven no relationship to the operator/verifier/aggregator whatsoever.
4. Similarly, `send_citrea_tx` can be called with an attacker-chosen `CitreaTxRequest::BatchProof`/`SequencerCommitment` payload to make the tx-sender sign and enqueue arbitrary DA blob data for Citrea, as shown by the reference client call pattern in `crates/tx-sender-jsonrpc-client/src/lib.rs:67-77`.

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    // Citrea-specific RPCs.
    #[cfg(feature = "citrea")]
    {
        module
            .register_async_method("send_citrea_tx", |params, client, _| async move {
                let req: InsertCitreaRawTxParams = params.one().map_err(jsonrpc_err)?;

                let insertion_id = client
                    .send_citrea_tx(req.citrea_tx_request)
                    .await
                    .map_err(jsonrpc_err)?;

                Ok::<i64, ErrorObjectOwned>(insertion_id)
            })
            .map_err(|e| BridgeError::Eyre(e.into()))?;
    }

    let handle = server.start(module);

    Ok(TxSenderJsonRpcServer { handle, local_addr })
}

    #[cfg(feature = "citrea")]
    pub async fn send_citrea_tx(&self, request: CitreaTxRequest) -> Result<i64, eyre::Report> {
        use crate::citrea::data_serialization::DataOnDa;
        use crate::citrea::MAX_CHUNK_SIZE;

        let mut dbtx = self.db.begin_transaction().await?;

        let insertion_id = match request {
            CitreaTxRequest::BatchProof { bytes, chunk_size } => {
                // Hash the original proof bytes so the same proof dedupes even if callers
                // retry it with a different chunk_size or as a non-chunked Complete body.
                let full_body_hash = crate::citrea::calculate_sha256(&bytes);
                let mut chunk_size = chunk_size.unwrap_or(MAX_CHUNK_SIZE);
                if chunk_size == 0 {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                if chunk_size > MAX_CHUNK_SIZE {
                    chunk_size = MAX_CHUNK_SIZE;
                }
                let chunk_size = chunk_size as usize;

                if bytes.len() <= chunk_size {
                    let data = DataOnDa::Complete(bytes);
                    let blob = borsh::to_vec(&data).expect("zk::Proof serialize must not fail");
                    self.db
                        .insert_citrea_raw_tx_single_with_hash(
                            &mut dbtx,
                            TransactionKind::Complete,
                            &blob,
                            &full_body_hash,
                        )
                        .await?
                } else {
                    let chunks: Vec<Vec<u8>> = bytes
                        .chunks(chunk_size)
                        .map(|chunk| {
                            borsh::to_vec(&DataOnDa::Chunk(chunk.to_vec()))
                                .expect("zk::Proof serialize must not fail")
                        })
                        .collect();
                    self.db
                        .insert_citrea_raw_tx_chunks(&mut dbtx, &chunks, &full_body_hash)
                        .await?
                }
            }
            CitreaTxRequest::BatchProofMethodId(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea BatchProofMethodId DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::BatchProofMethodId,
                        &body,
                    )
                    .await?
            }
            CitreaTxRequest::SequencerCommitment(body) => {
                if body.len() as u32 > MAX_CHUNK_SIZE {
                    return Err(eyre!(
                        "Citrea SequencerCommitment DA payload body too large; max {} bytes",
                        MAX_CHUNK_SIZE,
                    ));
                }
                self.db
                    .insert_citrea_raw_tx_single(
                        &mut dbtx,
                        TransactionKind::SequencerCommitment,
                        &body,
                    )
                    .await?
            }
        };

        self.db.commit_transaction(dbtx).await?;
        Ok(insertion_id)
    }

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }

    /// Signs a blob using ECDSA and returns (signature, public_key).
    /// This is used for Citrea DA payload authentication.
    /// Returns (signature, public_key) as serialized bytes.
    #[cfg(feature = "citrea")]
    pub(crate) fn sign_blob(&self, blob: &[u8]) -> (Vec<u8>, Vec<u8>) {
        let secret_key = self.keypair.secret_key();
        let message = {
            let mut hasher = Sha256::default();
            hasher.update(blob);
            hasher.finalize().into()
        };
        let public_key = self.keypair.public_key();
        let msg = Message::from_digest(message);
        let sig = SECP.sign_ecdsa(&msg, &secret_key);
        (
            sig.serialize_compact().to_vec(),
            public_key.serialize().to_vec(),
        )
    }
