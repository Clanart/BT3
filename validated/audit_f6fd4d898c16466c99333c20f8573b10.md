### Title
Unbounded `governance.unitprice` governance parameter allows the governing node to arbitrarily inflate transaction gas price floor and reap transaction senders - (File: kaiax/gov/param.go, kaiax/gov/headergov/impl/header.go)

### Summary
The `GovernanceUnitPrice` governance parameter (the minimum required gas price / "unit price" enforced network-wide, analogous to `trade_open_fee` in the referenced report) is registered with a `noopFormatChecker`, meaning no upper or lower bound is enforced on its value [1](#0-0) . In `single` governance mode, only the `GoverningNode` (an owner-equivalent role) is permitted to cast this vote [4](#0-3) [5](#0-4) . Unlike `kip71.lowerboundbasefee`/`kip71.upperboundbasefee`, which are cross-validated against each other in `checkConsistency` [2](#0-1) , `GovernanceUnitPrice` (along with several other parameters, e.g. `Kip71GasTarget`, `Kip71MaxBlockGasUsedForBaseFee`) falls through to the default branch that performs no additional consistency validation at all [3](#0-2) .

### Finding Description
`GovernanceUnitPrice` directly sets `ChainConfig.UnitPrice`, which is the base gas price floor charged to every transaction sender on the network [1](#0-0) . The vote pipeline (`governance_vote` RPC → `NewVoteData` → `checkConsistency` → header inclusion) validates only that the submitted value canonicalizes to a `uint64`; there is no minimum, maximum, or delta-from-previous-value restriction analogous to the bounded, event-emitting `set_fee()` pattern the reporter highlighted as the "correct" implementation in `Dca.vy`. This means a single transaction (a `governance.unitprice` vote, or a ratified `header.Governance` write at an epoch boundary) from the `GoverningNode` can set the unit price to an arbitrary, extreme `uint64` value with no guard rails, and take effect network-wide as soon as it is ratified at the next epoch.

### Impact Explanation
Every ordinary transaction sender (an unprivileged/regular network user, exactly the class of actor this scan is meant to protect) is forced to pay whatever price floor is currently in effect for every transaction. If the governing node/owner increases `governance.unitprice` to an extreme value, all senders' transactions from that point forward will be priced at the inflated floor with no on-chain protection, mirroring the "traders will not know, so whenever they trade the fees charged from them will be so much" concern in the reference report. Because deferred/collected transaction fees are distributed to block proposers/governance-controlled reward pools, an entity controlling the governing node can extract outsized value from ordinary transaction senders. This is a concrete instance of fee abuse enabled by an unauthorized/uncapped value change reachable through the standard governance-vote transaction path.

### Likelihood Explanation
Exploitation requires control of the `GoverningNode` in `single` governance mode, which is realistic under the same centralization concern raised in the source report (if the governing node key is compromised or misused, there is no on-chain safety net). The vote mechanism is a normal, permitted, single-transaction governance action already exposed via the public `governance_vote` RPC and header-vote mechanism—no privileged internal/consensus bug is needed, only a single vote from the currently authorized governing address.

### Recommendation
Add a `FormatChecker` for `GovernanceUnitPrice` (and similarly unguarded params like `Kip71GasTarget`, `Kip71MaxBlockGasUsedForBaseFee`) that enforces a sane minimum/maximum range, and/or add a `checkConsistency` rule limiting the maximum permitted change per vote (a "delta cap"), consistent with the bounded pattern already used for `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`.

### Proof of Concept
1. Operate/compromise the `GoverningNode` address under `governance.governancemode = "single"`.
2. Call the `governance_vote` RPC (or have the node, as proposer, embed `header.Vote`) with `name = "governance.unitprice"` and an extreme `value` (e.g. `uint64` max or a value many orders of magnitude above the current price) [6](#0-5) .
3. `NewVoteData` canonicalizes the value and passes it through `noopFormatChecker`, which always returns `true` [7](#0-6) [8](#0-7) .
4. `checkConsistency` performs no rejection for `gov.GovernanceUnitPrice` [3](#0-2) .
5. At the next epoch boundary, the vote is ratified into `header.Governance` and `ChainConfig.UnitPrice` is updated to the extreme value, forcing all subsequent transaction senders to pay the inflated price floor with no on-chain cap.

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}

// NewVoteData returns a valid, canonical vote data.
// If return is not nil, the name and the value is valid.
// The format of the value is checked, but consistency and deprecation are NOT checked.
// Deprecation (gov.DeprecatedAt) is the caller's responsibility — see Vote() and VerifyVote().
func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
