## Title
Flash-vote reward sniping via `harvestSinglePool` lets an attacker capture bribe yield accrued by long-term voters — ([File: wombat/WombatBribeManager.sol], [File: wombat/WombatStaking.sol], [File: rewards/BribeRewardPool.sol])

### Summary
`WombatBribeManager.harvestSinglePool` triggers `wombatStaking.vote` with a zero-delta, which still harvests real Wombat bribe rewards and forwards them to `BribeRewardPool.queueNewRewards`. Because `queueNewRewards` distributes the entire harvested amount as an instantaneous bump to `rewardPerTokenStored` divided by the pool's *current* `totalStaked()`, a user who calls `vote(lp, +X)` immediately before triggering the harvest and `unvote(lp)` immediately after can capture a share of rewards proportional to `X` even though that stake existed for zero elapsed time.

### Finding Description
The vote/harvest/reward flow is:
1. `WombatBribeManager.vote()` increases the caller's stake in the pool's `BribeRewardPool` via `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta))` [1](#0-0) .
2. `BribeRewardPool.stakeFor` runs `updateRewards(_for, rewardTokens)` (checkpointing `userRewardPerTokenPaid` to the *current* `rewardPerToken` using the **old** balance) and only then increases `totalSupply`/`_balances[_for]` [2](#0-1) . This means the newly added stake is checkpointed with zero backlog, but it is fully counted in `totalStaked()` for the very next reward event.
3. `harvestSinglePool(_lps)` is a public, permissionless function that calls `wombatStaking.vote(_lps, votes=0, rewarders, address(0))` [3](#0-2) .
4. `WombatStaking.vote` explicitly harvests real pending Wombat bribes even for a zero-delta vote (per its own comment) and forwards the harvested amount into `IBaseRewardPool(_rewarder).queueNewRewards(rewardAmount, rewardToken)` [4](#0-3) [5](#0-4) .
5. `_provisionReward` (invoked by `queueNewRewards`) increases `rewardPerTokenStored` by `_amountReward * 10**decimals / totalStaked()`, using the **current** `totalStaked()` at the moment of harvest — not any time-weighted average [6](#0-5) .
6. The attacker then calls `unvote(lp)`, which calls `withdrawFor(msg.sender, currentVote, true)`, which reads `_earned()` using `rewardPerToken(after) - userRewardPerTokenPaid(checkpoint set in step 2)` and pays it out immediately [7](#0-6) .

Because the attacker's `userRewardPerTokenPaid` was checkpointed to the pre-harvest value in step 2 and `rewardPerTokenStored` then jumps by the entire harvested bribe amount, the attacker earns `X * (rewardPerToken_after - rewardPerToken_before) / 10**decimals`, exactly as if they had been staked for the whole accrual period, despite having staked for zero blocks. This dilutes the share that legitimate, time-weighted voters would otherwise receive, since the denominator `totalStaked()` used to compute `rewardPerTokenStored` includes the attacker's flash stake while the numerator (harvested WOM bribe) was earned entirely by the pre-existing voters.

There is no cooldown, minimum holding period, or time-weighting mechanism between `vote()`, `harvestSinglePool()`, and `unvote()` — all three are freely callable in sequence (even within the same transaction, since `harvestSinglePool` is unauthenticated) [3](#0-2) .

### Impact Explanation
This is theft of unclaimed bribe yield: honest, time-weighted voters of a given LP pool have their forthcoming harvested bribe diluted by an attacker who stakes an instant before harvest and withdraws immediately after, capturing rewards proportional to `X` that were economically earned by other voters over the entire un-harvested period. This matches the Immunefi "theft of unclaimed yield" impact class.

### Likelihood Explanation
The precondition is holding some non-zero vlMGP (locked MGP) — the amount needed scales with desired profit, but the exploit is repeatable indefinitely with the *same* locked vlMGP balance since voting/unvoting does not consume or lock the underlying MGP, only reassigns voting weight (`userVotedForPoolInVlmgp`) which is instantly reversible via `unvote`. Since `harvestSinglePool` is public/permissionless and can be triggered by the attacker themselves (no need to front-run a third party's transaction), the attacker fully controls the sequencing (`vote` → `harvestSinglePool` → `unvote`) within their own transaction bundle, making this deterministic and repeatable for every pool that has accrued pending Wombat bribes.

### Recommendation
Introduce time-weighted reward accrual (e.g., stream harvested rewards linearly over a period, similar to Synthetix `StakingRewards` duration-based distribution) instead of an instantaneous `rewardPerTokenStored` bump, or enforce a minimum staking duration / cooldown between `vote()` and `unvote()`/`withdrawFor()` for a given pool so a user cannot enter and exit around a harvest event.

### Proof of Concept
Foundry test plan:
1. Deploy `BribeRewardPool`, `WombatBribeManager`, mock `WombatStaking`, mock `voter`.
2. Pre-seed the pool with an existing "long-term" voter V1 staked with weight `W` for `T` blocks/epochs before any harvest.
3. Simulate pending Wombat bribe reward `R` accrued for that pool (owned economically by V1).
4. Attacker A locks minimal vlMGP, calls `vote(lp, +X)`.
5. Attacker A calls `harvestSinglePool([lp])`, which triggers `queueNewRewards(R, token)` — assert `rewardPerTokenStored` increases by `R * 1e18 / (W + X)`.
6. Attacker A calls `unvote(lp)` — assert `earned(A, token)` (paid out) ≈ `X * R / (W + X)`, i.e., non-zero despite `A` having staked for 0 elapsed blocks.
7. Assert `earned(V1, token)` after the same harvest is now `W * R / (W + X)`, strictly less than `R` (the full amount V1 would fairly deserve as sole prior staker), proving fair share dilution/theft.

    /// @notice Cast a zero vote to harvest the bribes of selected pools
    /// @notice this  function has a lesser importance than casting votes, hence no rewards will be given to the caller.
    function harvestSinglePool(address[] calldata _lps) public {
        uint256 length = _lps.length;
        int256[] memory votes = new int256[](length);
        address[] memory rewarders = new address[](length);
        for (uint256 i; i < length; i++) {
            address lp = _lps[i];
            Pool storage pool = poolInfos[lp];
            rewarders[i] = pool.rewarder;
            votes[i] = 0;
        }
        wombatStaking.vote(_lps, votes, rewarders, address(0));
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
