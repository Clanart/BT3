## Analysis

The attack path is valid and reachable by an unprivileged attacker, though it is not a true single-block "flash" exploit — locking into `mWomSV` is instantaneous, but exiting requires a mandatory `startUnlock` → `coolDownInSecs` wait via `unlock()`. Critically, there is **no forced/early-unlock path with a monetary penalty** in `mWomSV` (only a time-based cooldown), so the attacker eventually recovers 100% of the temporarily-locked principal with only an opportunity-cost/time cost, while permanently keeping the inflated MGP reward that was already locked into `vlMGP` for them.

Key code facts:

- `ArbWomUp3.getUserTier` reads `mWomSV.getUserTotalLocked(_account)` live at call time with no minimum holding duration check: [1](#0-0) 
- `incentiveDeposit` with `_mode=1` computes `mgpReward = _amountToConvert * rewardMultiplier[getUserTier(_account)] / DENOMINATOR` — a flat percentage of the *current* deposit scaled purely by the instantaneous tier, with **no cumulative/double-counting guard** (that guard, `calDoubledCounted`, is only applied in the `_lock`/mode=2 branch): [2](#0-1) 
- The reward is immediately locked into `vlMGP` for the attacker before any unwind of the temporary `mWomSV` lock: [3](#0-2) 
- `mWomSV.lockFor` increases `getUserTotalLocked` instantly, with no vesting or minimum duration: [4](#0-3) [5](#0-4) 
- Exiting requires `startUnlock` then waiting `coolDownInSecs` before `unlock()` succeeds, but there is no economic penalty applied — the attacker recovers full principal: [6](#0-5) 

Because mode=1 rewards are not gated by any cumulative "already rewarded at this tier" tracker (unlike mode=2's `calDoubledCounted`), an attacker can also repeat `incentiveDeposit(_amount, ..., false, 1)` multiple times while the temporary lock is in place, extracting the inflated-tier rate on arbitrarily many separate deposits (bounded only by the contract's MGP balance), not just once.

### Title
Tier-multiplier gaming via temporary `mWomSV` lock inflates `incentiveDeposit` MGP reward - ([File: wombat/ArbWomUp3.sol])

### Summary
`ArbWomUp3.getUserTier` and `getRewardAmount` (mode=1 branch) determine the reward multiplier from a live, un-vested snapshot of `mWomSV.getUserTotalLocked(_account)`. An attacker can `lockFor` a large amount of `mWom` into `mWomSV` immediately before calling `incentiveDeposit(_amount, _convertRatio, false, 1)`, receive MGP locked into `vlMGP` at an inflated tier rate, then later unlock the temporary `mWomSV` position penalty-free after the cooldown, keeping the excess MGP.

### Finding Description
`getRewardAmount` for the stake path (`_lock=false`, i.e. `_mode=1`) computes `mgpReward = _amountToConvert * rewardMultiplier[getUserTier(_account)] / DENOMINATOR`, where `getUserTier` reads `mWomSV.getUserTotalLocked(_account)` at call time [7](#0-6) [1](#0-0) . `mWomSV.lockFor`/`lock` credit the locked balance instantly via `IMasterMagpie(masterMagpie).depositMWomSVFor` with no minimum holding period [5](#0-4) . The only exit friction is a time-based cooldown (`startUnlock` + `coolDownInSecs` + `unlock`) with no monetary penalty [6](#0-5) . Once `incentiveDeposit` executes, the MGP reward is immediately and irreversibly locked into `vlMGP` for the attacker via `vlMGP.lockFor(rewardToSend, msg.sender)` [8](#0-7) , so unwinding the temporary `mWomSV` lock afterward does not claw back the reward. Unlike the mode=2 branch, which tracks `calDoubledCounted` based on the user's `mWomSV` balance to prevent re-rewarding the same accumulated amount, the mode=1 branch applies the tier multiplier per call with no cumulative cap, allowing repeated exploitation while the inflated lock is held.

### Impact Explanation
This is theft of unclaimed yield: the attacker extracts MGP from the contract's incentive reserve (bounded by `IERC20(mgp).balanceOf(address(this))`) disproportionate to any durable commitment, since the qualifying `mWomSV` balance is withdrawn intact after the cooldown. The excess MGP locked into `vlMGP` represents a real, quantifiable, permanent transfer of protocol incentive funds to the attacker beyond what their genuine committed stake warrants.

### Likelihood Explanation
Feasible for any unprivileged actor holding or able to acquire enough WOM/mWom to cross a higher `rewardTier` threshold. No flashloan is strictly required (mWom can be minted 1:1 from WOM via `IMWom(mWom).deposit`), only capital that must be tied up for `coolDownInSecs` (a cooldown period, not indefinite) with no penalty on exit, and the exploit is repeatable across multiple `incentiveDeposit` calls before unwinding.

### Recommendation
Base the tier multiplier on a time-weighted or minimum-duration-committed `mWomSV` balance (e.g., require the qualifying lock to have existed for a minimum vesting period, or use a decayed/average balance rather than an instantaneous snapshot), and/or apply a cumulative double-counting guard to the mode=1 reward path similar to `calDoubledCounted` in the mode=2 path.

### Proof of Concept
Foundry test outline:
1. Deploy `ArbWomUp3`, `mWomSV`, `vlMGP`, `mWom`, `WOM`, `MasterMagpie` mocks/fixtures matching production config (tier thresholds, `rewardMultiplier`, `coolDownInSecs`).
2. Attacker acquires WOM, mints `mWom`, calls `mWomSV.lockFor(largeAmount, attacker)` to cross into the top `rewardTier`.
3. Attacker calls `ArbWomUp3.incentiveDeposit(smallAmount, ratio, false, 1)`; assert `vlMGP` balance for attacker equals `smallAmount * rewardMultiplier[topTier] / DENOMINATOR` (inflated tier).
4. Attacker calls `mWomSV.startUnlock(largeAmount)`, warps `coolDownInSecs`, calls `mWomSV.unlock(slot)`; assert attacker recovers full `largeAmount` mWom with no penalty.
5. Compare attacker's realized `vlMGP` reward against the reward that would have been computed using `getUserTier` at the attacker's pre-lock (baseline) tier; assert the realized reward is strictly greater, demonstrating the excess MGP extracted without durable commitment.

    function getRewardAmount(uint256 _amountToConvert, address _account, bool _lock) external view returns (uint256) {
        uint256 mgpReward = 0;

        if (!_lock) {
            mgpReward = _amountToConvert * rewardMultiplier[getUserTier(_account)] / DENOMINATOR;
        } else {
            uint256 accumulated = _amountToConvert + mWomSV.getUserTotalLocked(_account);
            uint256 rewardAmount = 0;
            uint256 i = 1;

            while (i < rewardTier.length && accumulated > rewardTier[i]) {
                rewardAmount +=
                    (rewardTier[i] - rewardTier[i - 1]) *
                    rewardMultiplier[i - 1];
                i++;
            }
            rewardAmount += (accumulated - rewardTier[i - 1]) * rewardMultiplier[i - 1];
            mgpReward = (rewardAmount / DENOMINATOR) - calDoubledCounted(_account);
        }

        uint256 mgpleft = IERC20(mgp).balanceOf(address(this));
        return mgpReward > mgpleft ? mgpleft : mgpReward;
    }
