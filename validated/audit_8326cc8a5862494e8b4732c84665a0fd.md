### Title
Unverified `x-github-enterprise-version` response header is cached forever and later trusted as proof of a GitHub host, letting a malicious remote bind itself to the GitHub Enterprise sign-in / credential flow - (File: `app/src/lib/endpoint-capabilities.ts`, `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`isGitHubHost()` normally verifies a host by making a `HEAD /meta` request and checking for the `x-github-request-id` response header. However, it short-circuits that verification if a *cached* Enterprise version exists for the endpoint: `getEndpointVersion(endpoint) !== null` immediately returns `true` [1](#0-0) . That cache is populated by `updateEndpointVersion()`, which persists the raw `x-github-enterprise-version` response header straight into `localStorage`, keyed only by the endpoint hostname, with no cryptographic or identity check that the response actually came from GitHub Enterprise Server software [2](#0-1) . This is the "first minter" pattern from the source report: whichever response is first attributed to a given hostname permanently sets the trusted state for that hostname, and all later logic blindly relies on it.

### Finding Description
`tryUpdateEndpointVersionFromResponse()` reads the `x-github-enterprise-version` header off of any `Response` and calls `updateEndpointVersion(endpoint, gheVersion)` whenever the header is present [3](#0-2) . `updateEndpointVersion` writes this attacker-suppliable string straight to `localStorage` under a key derived only from the endpoint hostname, with no TLS-pinning, signature, or cross-check against a known-good Enterprise instance [4](#0-3) .

`isGitHubHost(url)` is the function Desktop uses to decide "is this actually a GitHub server" before doing the real verification request. Before it ever issues the `/meta` HEAD request, it checks the cache first:
```
if (getEndpointVersion(endpoint) !== null) {
  return true
}
``` [1](#0-0) 
So once *any* response for that hostname has ever contained the `x-github-enterprise-version` header, `isGitHubHost()` will return `true` for that hostname forever after (the value lives in `localStorage`, i.e. persists across app restarts) without ever making the actual verification request again.

This cached "is GitHub host" determination feeds directly into the credential/sign-in decision logic in the trampoline credential helper. `getEndpointKind()` calls `isGitHubHost(endpoint)` and, if true, classifies the endpoint as `'enterprise'` [5](#0-4) . When Git subsequently asks the credential helper for credentials for that host and no matching account exists yet, Desktop treats it as a legitimate GitHub Enterprise endpoint and triggers the GitHub Enterprise sign-in UI, explicitly binding the sign-in flow's endpoint to the attacker-controlled host:
```
if (endpointKind !== 'generic' && !accounts.some(a => a.endpoint === apiEndpoint)) {
  ...
  const account = await ui.promptForGitHubSignIn(endpoint)
``` [6](#0-5) 
`promptForGitHubSignIn` in turn calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` for any non-`github.com` hostname [7](#0-6) , i.e. it starts Desktop's Enterprise OAuth/PAT sign-in machinery pointed at the attacker's server, using the "GitHub Enterprise" trust badge/UI copy rather than the generic-git-auth prompt that would normally be shown for an arbitrary HTTPS remote.

Existing guards that fail to stop this: `isDotCom`/`isGHE` checks are exact hostname matches and are not bypassed here [8](#0-7) , but they are checked *before* the cache lookup, meaning the cache-trust path is reachable for any third-party hostname that isn't in the small `knownThirdPartyHosts` allow/deny-list [9](#0-8) . Nothing re-validates the cached version against a fresh `/meta` probe, and nothing scopes the cache write to a request that was already established as trustworthy — the header is trusted on first sight from whatever endpoint made the request.

### Impact Explanation
This corrupts the value that decides whether an arbitrary git remote host is presented to the user as a genuine "GitHub Enterprise" endpoint (unauthorized account/OAuth binding to a host controlled by the attacker, matching the report's "unauthorized OAuth or account binding" impact category). Because the poisoned classification is persisted in `localStorage` rather than scoped to a single operation, one attacker-controlled response (via a git remote/HTTPS proxy the attacker controls, or a MITM/compromised network responding to any Desktop request to that hostname) permanently changes how Desktop treats that hostname for all future git operations against it in that Desktop installation, echoing the ElasticSwap bug's core issue: a value set by the first (attacker-influenced) interaction is trusted without bound as ground truth for every subsequent user (or, here, every subsequent operation).

### Likelihood Explanation
I was not able to fully enumerate, within the indexed code, every call site that produces the `Response` object passed to `tryUpdateEndpointVersionFromResponse` (`grep` found 5 references in `api.ts` but I could not open all of them in this pass), so I cannot confirm with certainty whether this header is captured on every API call Desktop makes to a host (including ones triggered automatically, e.g. when adding/probing a new remote or clone URL) or only on a narrower subset of authenticated API requests. This uncertainty affects how easily an attacker-controlled host can get a request routed through this code path without user interaction beyond adding/using a malicious remote. Given the indexing limits, a Devin session with full repo access would be needed to trace every caller of `tryUpdateEndpointVersionFromResponse`/`request()` in `api.ts` to establish the exact trigger conditions with certainty.

### Recommendation
Never trust the `x-github-enterprise-version` header from a response used to determine `isGitHubHost()` unless it originates from a response the app already trusts (e.g., only accept the header from within the actual `/meta` verification request/response, not opportunistically from arbitrary API calls). Do not let cache presence alone (`getEndpointVersion(endpoint) !== null`) short-circuit the live `/meta` verification in `isGitHubHost()`; instead use the cache only to skip network calls for hosts that have already independently passed the `x-github-request-id` check, and re-verify periodically or on account-binding decisions specifically. Consider scoping this cache to verified endpoints (accounts.some) instead of persisting it for any arbitrary hostname in `localStorage`.

### Proof of Concept
1. Attacker stands up an HTTPS server (or a MITM proxy in front of one) at `https://attacker.example.com` and adds it as a remote (or hosts a clone URL for the user to add) in Desktop.
2. Desktop makes some API request to that host (path depends on the unconfirmed call sites described above) and the attacker's server includes the header `x-github-enterprise-version: 3.9.0` in its response.
3. `tryUpdateEndpointVersionFromResponse` stores this into `localStorage` via `updateEndpointVersion('https://attacker.example.com', '3.9.0')` [3](#0-2) .
4. Later, when Git needs credentials for `https://attacker.example.com` (e.g. during a fetch/push), the trampoline credential helper calls `getEndpointKind`, which calls `isGitHubHost('https://attacker.example.com')` [5](#0-4) .
5. `isGitHubHost` sees `getEndpointVersion(endpoint) !== null` is true and returns `true` without ever contacting `attacker.example.com/meta` again [1](#0-0) .
6. `getEndpointKind` returns `'enterprise'`, and since no account exists for that endpoint, Desktop calls `ui.promptForGitHubSignIn('https://attacker.example.com...')`, launching the "Sign in to GitHub Enterprise" flow bound to the attacker's origin [6](#0-5) [7](#0-6) .

export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}
