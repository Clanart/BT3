### Title
Uncaught IndexError in `is_clvm_canonical`/`is_atom_canonical` on truncated multi-byte atom length prefixes causes an unhandled exception during spend bundle validation - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` walk a raw CLVM-serialized byte buffer (`puzzle_reveal`/`solution` bytes supplied by a spend bundle submitter) to detect non-canonical/back-reference encodings. Both functions advance an `offset` index and dereference `clvm_buffer[offset]` without ever checking that `offset` stays within `len(clvm_buffer)`. A truncated multi-byte atom-length prefix (the CLVM analog of the "array length" field in the Velociraptor `ConsumeUnit16Array`/`ConsumeUnit64Array` bug) causes the loop to read past the end of the buffer, raising an unhandled `IndexError` instead of returning `False`/an error.

### Finding Description
`is_atom_canonical()` decodes CLVM atom length prefixes that can span up to 6 bytes depending on the leading byte's high bits: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` assumes `prefix_len` additional bytes exist after the initial length-prefix byte, but nothing validates `offset < len(clvm_buffer)` before each dereference. Likewise, `is_clvm_canonical()`'s main loop dereferences `clvm_buffer[offset]` on every iteration without a bounds check: [2](#0-1) 

If an attacker crafts a `puzzle_reveal` or `solution` whose final byte is a multi-byte length-prefix marker (e.g. `0xFC`–`0xFF`, indicating up to 5 trailing length bytes) but omits those trailing bytes, `clvm_buffer[offset]` in the `for i in range(prefix_len)` loop, or the top-level `b = clvm_buffer[offset]` in `is_clvm_canonical`, indexes past the end of the `bytes` object. Unlike slicing, indexing a Python `bytes` object out of range raises `IndexError`, an uncaught exception that is the direct analog of the off-by-one out-of-bounds array read (CWE-193) in Velociraptor's `ConsumeUnit16Array`/`ConsumeUnit64Array`.

### Impact Explanation
An `IndexError` raised inside spend-bundle canonicalization logic that is not wrapped in a broad exception handler will propagate out of the mempool add path, causing the calling task/coroutine to fail. Depending on how the caller (mempool item pre-validation) handles exceptions, this can manifest as a per-request failure or an unhandled exception bubbling up in the full node's transaction-processing pipeline, denying service for that spend-bundle-processing operation. This matches the "spend-triggered transaction-processing halt" impact class called out in the validation criteria — a single malformed, unprivileged spend bundle can trigger a crash/exception in a code path meant to just classify an attacker-supplied buffer as canonical or not.

### Likelihood Explanation
Likelihood is high for reachability: the buffer content (`puzzle_reveal`/`solution`) is fully attacker-controlled bytes submitted as part of a `SpendBundle`/`CoinSpend`, and constructing a truncated multi-byte atom-length prefix requires no special privileges — just crafting the last few bytes of a CLVM program to end mid length-prefix. The existence of a dedicated test module (`chia/_tests/core/mempool/test_mempool_manager.py`) exercising `is_clvm_canonical` confirms it is invoked as part of the standard spend-bundle admission/serialization-canonicality check used by `MempoolManager`.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access inside the `for i in range(prefix_len)` loop (raising/returning a well-defined "non-canonical"/error result if `offset >= len(clvm_buffer)`), and add the same guard at the top of the `is_clvm_canonical()` main loop before dereferencing `clvm_buffer[offset]`. This mirrors the bounds checks already present in the sibling parser `chia/full_node/full_block_utils.py` (e.g. `skip_bytes`, `skip_list`), which explicitly check `n > len(buf)` before consuming bytes: [3](#0-2) 

### Proof of Concept
1. Construct a CLVM buffer whose single remaining unconsumed atom begins with a length-prefix byte requiring trailing bytes, e.g. `b"\xff\xfc"` — `0xFC` signals a 5-byte trailing length field per the `0b11111100` mask branch, but the buffer ends immediately after it.
2. Call `is_clvm_canonical(b"\xff\xfc")` (or embed this buffer as the tail of a `puzzle_reveal`/`solution` supplied in a `CoinSpend`).
3. Execution reaches `is_atom_canonical(clvm_buffer, offset=1)`; the `for i in range(prefix_len)` loop increments `offset` past `len(clvm_buffer)` and executes `clvm_buffer[offset]`, raising `IndexError: index out of range` instead of returning a canonical/non-canonical verdict.
4. The unhandled `IndexError` propagates out of the canonicality check invoked during spend bundle processing, whatever level for a `CoinSpend`/`SpendBundle` submitted by an ordinary wallet user.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
