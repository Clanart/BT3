## Title
SSRF via Attacker-Created DataLayer Mirror Coin Causes Unvalidated Outbound Requests to Internal/Metadata Endpoints - (File: `chia/data_layer/download_data.py`, `chia/data_layer/data_layer_wallet.py`, `chia/wallet/db_wallet/db_wallet_puzzles.py`)

### Summary
DataLayer mirror URLs are sourced from `CREATE_COIN` conditions to a fixed, permissionless puzzle hash (`MIRROR_PUZZLE_HASH` from `create_mirror_puzzle()`), and the URL strings come straight from spend-bundle memos with zero validation. Any unprivileged spend-bundle submitter can create a coin with this puzzle hash and attacker-chosen memo content, causing every DataLayer node tracking that `launcher_id` to add the attacker's URL as a subscription server and later issue unauthenticated outbound HTTP GET requests to it via `http_download()`.

### Finding Description
`create_mirror_puzzle()` is `P2_PARENT.curry(Program.to(1))` — a generic puzzle with a hash (`MIRROR_PUZZLE_HASH`) that is not owned/gated by any specific key. [1](#0-0)  Any wallet (via `DLNewMirror`/`create_new_mirror`) creates such a coin by a standard `generate_signed_transaction` call that attaches the `launcher_id` and arbitrary URL strings as coin memos — this is just a normal XCH spend with a `CREATE_COIN` condition and memos, reachable by any coin owner without needing to own the DataLayer singleton: [2](#0-1) 

When any wallet observes a coin with `puzzle_hash == create_mirror_puzzle().get_tree_hash()`, it decodes the `launcher_id` and URL list purely from the parent spend's `CREATE_COIN` memos with no validation of scheme, host, or network range: [3](#0-2)  and stores them via `dl_store.add_mirror()`: [4](#0-3) 

The DataLayer service periodically pulls these wallet-recorded mirror URLs, with no filtering, and stores them as active subscription sources: [5](#0-4)  and `DataStore.update_subscriptions_from_wallet()` persists these URLs into the subscriptions table unconditionally: [6](#0-5) 

During the periodic sync loop, `fetch_and_validate()` selects one of these subscribed URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs an unauthenticated `aiohttp` GET directly against `server_info.url + "/" + filename` with **no scheme/host allowlisting, no blocking of private IP ranges, localhost, or cloud metadata addresses (e.g. `169.254.169.254`)**: [7](#0-6)  The URL is taken verbatim from `ServerInfo.url`, which originated from the attacker-controlled memo. [8](#0-7) 

This mirrors the BentoML bug class exactly: attacker-controlled data (there, an HTTP multipart/JSON field; here, a mirror-coin memo URL) flows unvalidated into an outbound HTTP client call (`client.get(obj)` in BentoML vs. `session.get(server_info.url + "/" + filename, ...)` here), with no allowlist/denylist for internal networks or metadata services.

### Impact Explanation
Any party who can broadcast a spend bundle (no special permissions, no need to own the targeted DataLayer store) can force every node/wallet operator tracking that `launcher_id`'s DataLayer store — including third parties who independently subscribed to that store for legitimate replication — to make outbound HTTP requests to attacker-chosen addresses. This enables:
- Cloud metadata credential theft (e.g., `http://169.254.169.254/latest/meta-data/`) from any machine running an affected DataLayer/wallet node.
- Internal network reconnaissance and service enumeration behind operator firewalls.
- Bypassing network perimeter controls using the DataLayer node as a proxy.

This is a Data Layer client/local RPC-adjacent path directly reachable by an unprivileged coin-spend (mirror coin creation), matching the "spend-triggered" reachable-path criteria for this analysis.

### Likelihood Explanation
High. Creating a coin with an arbitrary puzzle hash and memo is a completely standard, unprivileged wallet operation (`DLNewMirror`, or even a raw standard-coin spend crafted manually to match `create_mirror_puzzle()`'s puzzle hash and `CREATE_COIN` memo format). No signature from the DataLayer singleton owner or special authorization is required to create the mirror coin; the wallet passively picks it up via `coin_added()` based purely on puzzle hash match. Any node subscribed to (or owning) the targeted store will periodically execute `update_subscriptions_from_wallet()` → `fetch_and_validate()` → `http_download()` on the attacker URL, since `periodically_manage_data()` runs unattended on a fixed interval.

### Recommendation
- Validate mirror/subscription URLs before storing or dialing them: enforce an allowlist of schemes (http/https), and reject/resolve-check against private IP ranges (RFC1918), loopback, link-local (including `169.254.169.254`), and other reserved ranges — both at the hostname and after DNS resolution (to prevent DNS rebinding).
- Apply this validation both when a mirror coin is first parsed in `get_mirror_info()`/`coin_added()` in `chia/data_layer/data_layer_wallet.py`, and again defensively before every outbound request in `http_download()` and `get_downloader()`/`download_file()` in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py`.
- Consider requiring operator confirmation or a configurable allowlist for accepting new externally-advertised mirror URLs, rather than auto-trusting all on-chain mirror memos.

### Proof of Concept
1. Attacker crafts and broadcasts a standard spend bundle that creates a coin with `puzzle_hash = create_mirror_puzzle().get_tree_hash()` (i.e., `P2_PARENT.curry(Program.to(1))`), with a `CREATE_COIN` condition whose memo list is `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]`, where `launcher_id` is the store id of a DataLayer store that some victim node subscribes to or owns.
2. Once confirmed, any wallet tracking that `launcher_id` observes the coin via `DataLayerWallet.coin_added()`, decodes it via `get_mirror_info()`, and records it as a `Mirror` with the attacker URL. [4](#0-3) 
3. The victim's DataLayer service periodically calls `update_subscriptions_from_wallet()` and picks up the new URL as a subscription source. [5](#0-4) 
4. On the next `fetch_and_validate()` cycle, the URL is selected and passed into `http_download()`, causing the victim node to issue `GET http://169.254.169.254/latest/meta-data/<filename>`, an unauthenticated outbound SSRF request from the victim's infrastructure. [9](#0-8) 

Note: I was unable to fully trace the exact byte-level format required for a spend bundle to satisfy `P2_PARENT`'s underlying puzzle logic (only its curried hash and `get_mirror_info()` decode contract were available in the indexed context), so exact CLVM solution construction for the PoC spend was not independently verified against the compiled puzzle bytecode — a background agent with full repo/CLVM access should confirm the exact solution shape needed to trigger `CREATE_COIN` with the desired memos through `P2_PARENT`.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
