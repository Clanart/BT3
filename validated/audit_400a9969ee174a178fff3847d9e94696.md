## Confirmed: `execute()` batches a full extrinsic's `Vec<Message>` into a single `on_executed` call, and `pallet-consensus-incentives` derives the reward recipient from only `messages[0]`. [1](#0-0) [2](#0-1) 

### Title
Consensus relayer rewards for an entire message batch are paid to the signer of `messages[0]` only, allowing theft of other relayers' rewards - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`Pallet::execute` in `pallet-ismp` accepts an arbitrary `Vec<Message>` submitted in a single extrinsic and, after processing them all, calls `T::FeeHandler::on_executed(messages_with_weights, events)` exactly once for the whole batch [1](#0-0) . `pallet-consensus-incentives::on_executed` recovers the reward recipient's account by decoding the signature on `messages.get(0)` only, then iterates every `StateMachineUpdated` event in the whole batch (potentially covering many different state machines whose consensus proofs may have been submitted by different relayers/signers) and pays every one of those rewards to that single first-message signer [3](#0-2) .

### Finding Description
`execute()` takes `messages: Vec<Message>` from a single submitted extrinsic (e.g. a "handle_messages" call bundling multiple `ConsensusMessage`s for different state machines, possibly signed/authored by different relayers via `consensus_msg.signer`), maps them through `handle_incoming_message`, and passes the whole batch's `messages_with_weights` plus the accumulated `events` to `FeeHandler::on_executed` in one shot [1](#0-0) .

Inside `on_executed`:
```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
        Signature::decode(&mut &consensus_msg.signer[..])
            .ok()
            .and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
            .map(|pub_key| pub_key.into())
    } else {
        None::<[u8; 32]>
    }
});
``` [4](#0-3) 

Only the signer of index-0 message is ever recovered. The function then builds `highest_per_state_machine` from **all** `StateMachineUpdated` events emitted by the batch (which can originate from any of the batch's `ConsensusMessage`s, not just `messages[0]`), and calls `process_message` for every state machine in that map using the single `relayer_account` recovered above:
```rust
for (state_machine_id, latest_height) in highest_per_state_machine {
    ...
    let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
}
``` [5](#0-4) 

There is no per-message relayer extraction, no check that each `state_machine_id`'s `StateMachineUpdated` event actually corresponds to a `ConsensusMessage` signed by `relayer_account`, and no guard preventing multiple distinct `ConsensusMessage`s (potentially from distinct relayers, for distinct state machines) from being submitted together in one `execute()` call. `T::Currency::transfer` moves `reward` directly `TreasuryAccount → relayer_account` for every state machine's block-span reward [6](#0-5) , so all of that value lands with the wrong beneficiary whenever the batch spans more than one relayer's proof.

The existing `LastRewardedHeight` watermark logic only prevents *double-payment* for the same state machine across separate batches/extrinsics [7](#0-6) ; it does nothing to bind the reward recipient to the actual submitter of each state machine's consensus proof, so it does not stop this misattribution.

### Impact Explanation
This directly causes unauthorized transfer of relayer-incentive funds from the treasury to the wrong beneficiary — the account whose `ConsensusMessage` happens to occupy index 0 of a batch, rather than each state machine's actual submitter. An attacker (or even benign batching behavior) that groups a self-authored, cheap-to-produce `ConsensusMessage` for one state machine as the first element of a multi-message extrinsic — bundled alongside other relayers' legitimate consensus proofs for other state machines (submitted, e.g., via a shared/batched extrinsic pathway, or any code path that lets multiple messages be included) — collects the full block-span reward for every state machine update in that batch, effectively stealing rewards intended for other relayers. This is a direct value-theft primitive from the treasury via an unprivileged, low-cost extrinsic construction, matching the bounty's "stealing of funds" / "wrong beneficiary" criteria.

### Likelihood Explanation
The trigger requires only the ability to submit or influence the ordering of a batched `execute()` call containing more than one `Message::Consensus` entry — no relayer collusion, admin privilege, or leaked key is needed beyond an actor being able to place their own consensus message first in a batch alongside others' proofs. Whether the production message-submission path (`handle_messages`/messaging client) allows arbitrary third parties to freely compose such mixed-signer batches, versus each relayer submitting their own single-message extrinsics exclusively, is not fully verified from the available code slice — this determines whether the attack is trivially self-triggerable or requires a specific batching entry point. Given the `execute(messages: Vec<Message>)` signature accepts an arbitrary vector, and nothing in `on_executed` or `execute` restricts the batch to a single signer/state machine, the vulnerable code path exists and is reachable through the pallet's public dispatch surface.

### Recommendation
Recover and reward the relayer independently for **each** `ConsensusMessage` in the batch, matching each `StateMachineUpdated` event to the specific `ConsensusMessage`/signer that produced it (e.g., by carrying the state-machine id through `MessageResult::ConsensusMessage` events or by iterating `messages` directly instead of only `messages[0]`), rather than assuming a single batch-wide relayer identity.

### Proof of Concept
Conceptual sequence (exact batching entry point not fully traced within available context):
1. Relayer A holds a valid, signed `ConsensusMessage` for state machine `X` that advances its commitment height.
2. Attacker crafts (or intercepts and reorders, if ordering is attacker-influenceable) a call to `Pallet::execute` with `messages = [attacker_consensus_msg_for_Y, relayer_A_consensus_msg_for_X]`, where the attacker's own message for state machine `Y` is index 0.
3. `execute()` processes both messages, emits `StateMachineUpdated` events for both `X` and `Y`.
4. `on_executed` recovers only the attacker's signer from `messages[0]`, then iterates the `highest_per_state_machine` map containing both `X` and `Y`, transferring both reward computations (`calculate_reward` for `X`'s and `Y`'s block spans) to the attacker's account instead of crediting relayer A for `X`.
5. Repeating this pattern lets the attacker (submitting only cheap/no-op consensus messages of their own placed first) continuously drain the treasury's relayer-incentive budget that should accrue to the actual submitters of other state machines' consensus proofs.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
