`remove_txhandler_from_map` is a generic, stateless helper that simply does a `BTreeMap::remove` and returns `TxError::TxHandlerNotFound` if the key is absent [1](#0-0) . It contains no timelock logic, no deposit-status checks, and no code path that reads or writes `recovery_taproot_address`, `user_takes_after`, or move-to-vault presign state. It is only used internally by `creator.rs` and `states/kickoff.rs` to pull specific transaction handlers (e.g. `ROUND`, `KICKOFF`) out of a map that was already built earlier in the same call, purely as a bookkeeping utility.

The actual `user_takes_after` timelock is constructed in `generate_deposit_address`/`DepositData::get_deposit_scripts`, which embeds a `TimelockScript` with the depositor-supplied `recovery_taproot_address` and the paramset's `user_takes_after` value [2](#0-1) [3](#0-2) . This is an intentional bridge design: it is exactly the mechanism that lets a depositor recover funds if the N-of-N move-to-vault never gets signed/confirmed in time — not a bug. Whether the race the question describes (mining `user_takes_after` blocks before move-to-vault broadcast) results in a real double-spend depends entirely on verifier/aggregator liveness (whether they sign and broadcast move-to-vault before the timelock matures), which is an operational/deployment concern governed by the `user_takes_after` paramset value, not a code defect in `remove_txhandler_from_map` or any function it touches.

Since the named target function has no logic bearing on the claimed binding (move-to-vault presigned state vs. recovery-path spendability), there is no demonstrable code-level vulnerability at this file/function as specified.

/// Removes a [`TxHandler`] from a map by transaction type, returning an error if not found.
///
/// # Arguments
/// * `txhandlers` - The map of transaction handlers.
/// * `tx_type` - The transaction type to remove.
///
/// # Returns
/// The removed [`TxHandler`], or a [`BridgeError`] if not found.
pub fn remove_txhandler_from_map<T: State>(
    txhandlers: &mut BTreeMap<TransactionType, TxHandler<T>>,
    tx_type: TransactionType,
) -> Result<TxHandler<T>, BridgeError> {
    txhandlers
        .remove(&tx_type)
        .ok_or(TxError::TxHandlerNotFound(tx_type).into())
}

pub struct TimelockScript(pub(crate) Option<XOnlyPublicKey>, u16);

impl SpendableScript for TimelockScript {
    fn as_any(&self) -> &dyn Any {
        self
    }

    fn kind(&self) -> ScriptKind {
        ScriptKind::TimelockScript(self)
    }

    fn to_script_buf(&self) -> ScriptBuf {
        let script_builder = Builder::new()
            .push_int(self.1 as i64)
            .push_opcode(OP_CSV)
            .push_opcode(OP_DROP);

        if let Some(xonly_pk) = self.0 {
            script_builder
                .push_x_only_key(&xonly_pk)
                .push_opcode(OP_CHECKSIG)
        } else {
            script_builder.push_opcode(OP_TRUE)
        }
        .into_script()
    }
}

impl TimelockScript {
    pub fn generate_script_inputs(&self, signature: Option<&taproot::Signature>) -> Witness {
        match signature {
            Some(sig) => Witness::from_slice(&[sig.serialize()]),
            None => Witness::default(),
        }
    }

    pub fn new(xonly_pk: Option<XOnlyPublicKey>, block_count: u16) -> Self {
        Self(xonly_pk, block_count)
    }
}
