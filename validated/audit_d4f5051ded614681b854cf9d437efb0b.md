## Title
Consensus relayer reward mis-pricing due to unsettled `LastRewardedHeight` before `cost_per_block` change — ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` computes a relayer's consensus-message reward lazily, at delivery time, by multiplying the *entire* unpaid block span (`latest_height - LastRewardedHeight`) by whatever `cost_per_block` happens to be stored **at the moment the message is processed** — not the rate(s) that were actually in effect while those blocks accrued. `update_cost_per_block` never checkpoints/settles the pending unpaid span before installing the new rate. This is the same broken invariant as the reported Move bug (`update_reward_config` overwriting `reward_config` without first calling `self_update` to flush unclaimed rewards at the old rate).

### Finding Description
`calculate_reward` reads the current rate and the unpaid height span independently of each other: [1](#0-0) 

- `baseline` is `LastRewardedHeight` (or `previous_commitment_height` on first reward).
- `blocks = latest_height.saturating_sub(baseline)` — the full unpaid span, which may have accrued over many blocks/time and possibly across a `cost_per_block` change.
- `reward = blocks * block_cost`, where `block_cost` is whatever `StateMachinesCostPerBlock` currently holds — i.e., the *latest* configured rate, applied to the *whole* unpaid span.

`update_cost_per_block` performs a pure config overwrite with no settlement step: [2](#0-1) 

There is no call that forces `process_message`/reward payout (which would advance `LastRewardedHeight` and "lock in" the old rate for the already-accrued span) before the new `cost_per_block` takes effect. Message delivery is otherwise permissionless — any relayer can submit a valid consensus proof (`ConsensusMessage`) whenever they choose, and `on_executed` only fires — and rewards only calculate — when that delivery happens: [3](#0-2) 

So a relayer that is already entitled to an unpaid span (blocks committed on the source chain but not yet rewarded on Hyperbridge) can simply wait to submit their consensus update until *after* governance raises `cost_per_block`. The reward for the entire withheld span — including all the blocks that accrued under the old, lower rate — is then paid out at the new, higher rate, exactly mirroring the audited Move bug where users "receive rewards based on the new amount instead of the old one."

### Impact Explanation
This is a direct treasury fund-loss/logic-attack vector: an unprivileged relayer controls submission timing to retroactively reprice an entire unpaid reward span at a rate never actually in force for most of that span, extracting more from `T::TreasuryAccount` than the configured economics intended. No malicious governance, prover, or relayer collusion is required — a normal relayer simply delays a legitimate, otherwise-valid message.

### Likelihood Explanation
Likelihood is moderate-to-high: `cost_per_block` is expected to be adjusted over time via `update_cost_per_block` (it's a normal operational lever), and consensus message delivery cadence is entirely relayer-controlled — nothing in the pallet forces prompt settlement. Any relayer who notices (or anticipates) a scheduled rate increase can withhold their next update and profit from the mispricing on the whole backlog, not just newly accrued blocks.

### Recommendation
Before mutating `StateMachinesCostPerBlock` in `update_cost_per_block` (and in `remove_incentives`), force a settlement pass for the affected `state_machine_id`: use the current on-chain `latest_commitment_height` to advance `LastRewardedHeight` and pay out (or explicitly record as owed) the reward for the span accrued under the *old* rate, mirroring the report's suggested fix of running `self_update`/checkpointing `farm.timestamp` prior to applying a new reward configuration. Alternatively, store the rate as part of a rate-history/tranche list so `calculate_reward` can price each sub-span with the rate that was actually active during it.

### Proof of Concept
1. Governance sets `cost_per_block = 10` for `state_machine_id = X` via `update_cost_per_block`.
2. Source chain X advances from height 100 to height 200 without the relayer submitting the corresponding `ConsensusMessage` (the relayer deliberately withholds it). `LastRewardedHeight` stays at 100 (or the prior watermark).
3. Governance later raises `cost_per_block` to `100` via `update_cost_per_block` (a legitimate operational change, e.g. to reflect gas cost increases going forward).
4. The relayer now submits the consensus proof updating X to height 200.
5. `on_executed` → `process_message` → `calculate_reward` computes `blocks = 200 - 100 = 100`, `block_cost = 100` (the new rate), so `reward = 100 * 100 = 10,000`, instead of the `100 * 10 = 1,000` that should have been owed for blocks that accrued entirely under the old rate.
6. `T::Currency::transfer` pays the relayer 10,000 from `TreasuryAccount`, a 10x overpayment attributable purely to submission-timing manipulation around a rate change — no code path checkpoints the span before the rate takes effect. [4](#0-3)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
