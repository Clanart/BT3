This confirms it: at `checkConsistency` in `header.go`, `gov.Kip71GasTarget` falls into the catch-all case that performs **no consistency check beyond the format checker**, and the format checker for `Kip71GasTarget` is `noopFormatChecker` (unlike `Kip71BaseFeeDenominator`, which explicitly requires `v != 0`).### Title
Unvalidated `governance.kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee` — consensus-halting DoS - ([File: params/kip71_config.go])

### Summary
The KIP-71 (Magma) dynamic base-fee formula divides by the governance-controlled parameter `GasTarget` without ever validating that it's non-zero. `BaseFeeDenominator` is explicitly guarded against zero both in the formula itself and in its format checker, but `GasTarget` receives no equivalent protection anywhere in the governance-vote pipeline. This mirrors the CVE's root cause: a codec/library trusts a caller-controlled numeric config field (sample rate) to be non-zero and never validates it, leading to an unhandled degenerate-value crash.

### Finding Description
`KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` (`kc.GasTarget`) directly: [1](#0-0) [2](#0-1) 

`BaseFeeDenominator` is explicitly special-cased with a zero-check right above (`if kc.BaseFeeDenominator == 0 { ... }`) to avoid a panic: [3](#0-2) 

But `GasTarget` has no such fallback. The governance parameter table registers `Kip71GasTarget` with a `noopFormatChecker`, unlike `Kip71BaseFeeDenominator`, which explicitly requires the value to be non-zero: [4](#0-3) 

The header-governance vote-consistency check (`checkConsistency`) treats `Kip71GasTarget` as one of the "no additional check beyond format check" parameters: [5](#0-4) 

Since the `FormatChecker` is a no-op and `checkConsistency` performs no additional validation, a vote of `governance.kip71.gastarget = 0` cast by the (single-mode) governing node — or by any GC member in `none` mode — is accepted as valid at both `governance_vote` submission time and at header ratification/verification time: [6](#0-5) 

Once ratified and effective, every node computing the next block's base fee via `NextMagmaBlockBaseFee` with `parentGasUsed != gasTarget` (i.e., `gasTarget == 0` and any nonzero gas usage takes the `>` branch) executes `new(big.Int).SetUint64(gasTarget)` as a divisor, i.e., division by the big.Int zero value, which panics in Go's `math/big` package.

### Impact Explanation
Once `GasTarget = 0` is ratified, the very next block header requires `NextMagmaBlockBaseFee` to compute the expected `BaseFee`. This function is called uniformly by:
- Block validation (`VerifyMagmaHeader`) on every full node processing every block,
- Block preparation by the proposer,
- RPC `feehistory`'s `processBlock` for gas price oracle queries.

A `big.Int` division by zero panics unconditionally. Because this computation is on the mandatory, always-executed header-verification/consensus path, every honest node in the network will panic when processing the block that follows the ratification (or, depending on scheduling, on producing/verifying the epoch's first block), crashing the client process. This is a chain-halting denial of service affecting the entire network — not a bounded resource-exhaustion bug as in the original CVE, but a strictly worse outright process crash. Because it can permanently stop the chain until every node is patched and restarted with a manually corrected `GasTarget`, this qualifies as at least a Medium/High severity availability bug on state transition/consensus.

### Likelihood Explanation
Reaching this bug requires a valid `governance.kip71.gastarget` vote of `0` to be cast and ratified. Casting the vote itself requires governing-node/GC privilege via the `governance_vote` RPC and subsequent inclusion of `header.Vote`/`header.Governance`. This means the *initial trigger* is not achievable by an arbitrary unprivileged public RPC caller or transaction sender — it needs governance privilege, similar to how the original CVE required a crafted file to be *fed into* the vulnerable library. However, per the scan scope, "governance parameters" is an explicitly in-scope category, and the flaw itself is a straightforward missing-validation bug (no privilege escalation needed beyond a single already-authorized vote/value, no complex conditions), so once a GC member (malicious, compromised, or simply making a config mistake) casts this single value, all nodes crash deterministically at the next non-target-matching block. There is no additional safeguard (e.g., minimum-value clamp, sanity check at ratification, or defensive divide-by-zero guard) anywhere in the pipeline to prevent it, unlike the parallel `BaseFeeDenominator` case which is explicitly hardened.

### Recommendation
- Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` requiring the value to be non-zero, mirroring `Kip71BaseFeeDenominator`'s check (`v != 0`).
- Defensively guard `NextMagmaBlockBaseFee` in `params/kip71_config.go` against `gasTarget == 0` (e.g., clamp to a safe non-zero fallback like the `BaseFeeDenominator` case, or treat it as "use target" no-op) so state-transition code never divides by an attacker/governance-controlled zero.
- Add the same zero-check to `checkConsistency` in `kaiax/gov/headergov/impl/header.go` for `gov.Kip71GasTarget`, rejecting the vote before ratification.

### Proof of Concept
1. As the governing node (single mode) or any GC member (none mode), call:
```
curl "http://localhost:8551" -X POST -H 'Content-Type: application/json' --data '
  {"jsonrpc":"2.0","id":1,"method":"governance_vote","params":[
    "governance.kip71.gastarget",
    0
  ]}'
```
This vote passes `NewVoteData`'s canonicalizer/format check (no-op) and `checkConsistency` (no special-case handling), so it is accepted and stored as `MyVotes` to be included in the header on the next proposed block.
2. Once this node becomes proposer, `PrepareHeader` writes the vote into `header.Vote`; other nodes' `VerifyVote`/`checkConsistency` accept it identically (no zero rejection).
3. At the epoch boundary, the vote is ratified into `header.Governance`, making `GasTarget = 0` effective from the next epoch.
4. In the following block whose `GasUsed != 0` (i.e., `parentGasUsed(0) != gasTarget` is false only if GasUsed is also 0 — any nonzero gas usage triggers the `>` branch), every node calling `NextMagmaBlockBaseFee` (via header verification, block preparation, or `eth_feeHistory`) executes:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // gasTarget == 0 → panic: division by zero
``` [7](#0-6) 
causing every full node in the network to crash simultaneously, halting the chain.

	var (

		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {

	}

		return "", ErrInvalidKeyValue
	}

		return "", ErrDeprecatedVote
	}

		return "", err
	}
