### Title
Unbounded recursive parsing of attacker-controlled coin memo causes stack-overflow DoS in PlotNFT/custody sync - ([File: chia/wallet/puzzles/custody/custody_architecture.py])

### Summary
CVE-2019-9543 is a Poppler recursive-descent parser (`JBIG2Stream::readGenericBitmap()`) that recurses once per attacker-controlled input segment with no depth limit, crashing the process on a crafted file. The chia-blockchain analog is `PuzzleWithRestrictions.from_memo()`, which recursively rebuilds an `MofN` custody tree from an on-chain `memo_blob`/hint with no depth bound, one Python stack frame per nested `MofN` layer.

### Finding Description
`PuzzleWithRestrictions.from_memo()` parses a `Program` memo and, whenever the memo encodes an `MofN` node, recurses into `PuzzleWithRestrictions.from_memo()` for every member: [1](#0-0) . This mirrors the sibling recursive helpers `unknown_puzzles` [2](#0-1)  and `fill_in_unknown_puzzles`, all of which walk the same untrusted, attacker-shaped tree with ordinary (non-tail-call) Python recursion and no maximum-depth check.

This function is reachable from chain data through `PlotNFT.get_next_from_coin_spend()`, which is the client-side sync routine used by pool participants/plotnft owners to follow their singleton lineage. When it cannot otherwise identify the puzzle, it calls `PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())` directly on the `memo_blob` taken from a `CreateCoin` condition output by the spend being processed: [3](#0-2) . The `memo_blob`/hint of a coin is fully attacker-controlled data placed by whoever creates the coin (e.g., a malicious "pool" or a malicious singleton spend crafted by any spend-bundle submitter that creates a coin hinted to this launcher id/puzzle-hash pattern), and is not validated for structural depth before being handed to the recursive parser.

An attacker can encode an `MofNHint` whose `member_memos` nest thousands of `MofN` levels deep. `from_memo()` will recurse once per level; because Python's default recursion limit (and the C stack backing it) is finite, sufficiently deep nesting raises `RecursionError`, and in the CPython C-stack case can even crash the interpreter with a segmentation fault rather than a catchable exception — the direct analog of Poppler's segfault via unbounded `JBIG2Stream::readGenericBitmap()` recursion.

### Impact Explanation
Any client-side code path that walks plotnft/singleton lineage from chain data (`PlotNFT.get_next_from_coin_spend()`, and by extension pool-wallet sync flows built on it) can be crashed or made to raise unhandled `RecursionError`/segfault by a single malicious coin creation with a deeply nested memo. This is a spend-triggered processing halt reachable by any party able to create a coin with an attacker-chosen memo directed at a plotnft/pool participant — satisfying the "spend-triggered transaction-processing halt" impact class. Because the recursion happens in pure Python (not bounded CLVM cost), normal mempool/CLVM cost limits do not protect the parsing step; the cost is paid only once on-chain to create the coin, while the victim client pays the recursion cost locally.

### Likelihood Explanation
Likelihood is Medium-High for any pool participant or plotnft client that resolves an unrecognized inner puzzle via memo. Crafting the malicious nested `MofNHint` memo requires only constructing an `Program` with deep list nesting encoded as `(MofNHint m member_memos)`; no signature or privileged state is needed — only that a coin be created carrying the memo and later observed by `get_next_from_coin_spend()`.

### Recommendation
Add an explicit depth counter/limit to `PuzzleWithRestrictions.from_memo()` (and the paired `unknown_puzzles`/`fill_in_unknown_puzzles` recursive walks in `chia/wallet/puzzles/custody/custody_architecture.py`), raising a clean `ValueError`/`GetNextPlotNFTError` once a maximum nesting depth is exceeded, before recursing further. Alternatively, convert these tree walks to iterative (stack-based) traversal, matching the pattern already used defensively in `sha256_treehash()` [4](#0-3)  and in the Data Layer's node-loading path, which explicitly guards against deep recursion via `chia_rs.datalayer.RecursionDepthExceededError`.

### Proof of Concept
1. Construct a `Program` memo shaped like `MofNHint.to_program()` where `member_memos` contains a single nested `MofNHint` referencing itself recursively N times (e.g., N = 5000), each wrapping another `MofNHint`.
2. Wrap it as the `additional_memos`/memo of a `CreateCoin` condition output by a coin spend whose puzzle hash matches the expected plotnft/singleton pattern (or simply call `PuzzleWithRestrictions.from_memo()` directly on the crafted `Program`, as done in `PlotNFT.get_next_from_coin_spend()` at [5](#0-4) ).
3. Feed the resulting `CoinSpend` to `PlotNFT.get_next_from_coin_spend()`.
4. Observe `RecursionError` (or a process crash under CPython's C-stack limits) inside `PuzzleWithRestrictions.from_memo()` at [6](#0-5) , halting the sync path for the victim client.

        if isinstance(self.puzzle, UnknownMember):

        elif isinstance(self.puzzle, MofN):

                uph: up
                for puz_w_restriction in self.puzzle.members
                for uph, up in puz_w_restriction.unknown_puzzles.items()
            }
        else:
            unknown_puzzles = {}
        return {
            **unknown_puzzles,
