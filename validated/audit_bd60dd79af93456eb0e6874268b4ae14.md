### Title
`addr` precompile `associate()` signature has no chain-ID / domain separation, enabling cross-network replay of forced address association and balance migration - (File: precompiles/addr/addr.go)

### Summary
The `associate` method of the `addr` precompile (`0x0000000000000000000000000000000000001004`) recovers a caller's EVM/Sei address pair from a raw ECDSA signature over an arbitrary, caller-supplied `customMessage`. The hash that is actually signed and verified is `keccak256(customMessage)` with no chain ID, contract address, or any other domain-separation value mixed in. Any valid `(v, r, s, customMessage)` tuple that was produced on one Sei network (e.g. testnet, or a chain that later forks) can be resubmitted verbatim on any other Sei-based network running the same precompile, since nothing in the signed payload ties it to a specific chain instance. This mirrors the exact bug class described in the report: signature schemes lacking replay protection across "contract instances" (here, chain deployments/forks).

### Finding Description
`PrecompileExecutor.associate` decodes `v/r/s` and a `customMessage` string supplied entirely by the caller, then computes: [1](#0-0) 

```
customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
```

No chain identifier, precompile address, or nonce is folded into `customMessageHash`. The recovered addresses are then passed to `associateAddresses`, which checks only that the Sei address is not *already* associated before permanently linking the two addresses and migrating the account's balance: [2](#0-1) 

The actual state mutation happens in `AssociationHelper.AssociateAddresses` / `MigrateBalance`, which unconditionally moves all spendable coins and wei balance from the EVM-cast Cosmos address to the newly associated Sei address, and can remove the cast account entirely once its locked coins are zero: [3](#0-2) 

The Sei codebase already recognizes and defends against exactly this replay pattern for EIP-7702 `SetCodeAuthorization`s: `AuthorityToPreAssociate` explicitly checks `auth.ChainID` against the local chain ID before allowing pre-association, with an explanatory comment describing the precise risk — a signature made for a different chain being replayed to "force-associate" a user, "migrating their direct-cast balance and orphaning staking/distribution state": [4](#0-3) 
This protection, and the corresponding regression test that verifies a foreign-chain authorization is rejected, exist only for the SetCode/EIP-7702 path: [5](#0-4) 

No equivalent chain-ID (or any domain-separation) check exists on the `associate` precompile path. The integration test suite confirms `customMessage` is fully caller-defined and the precompile has no built-in expiry/nonce/chain binding beyond what the client chooses to put in the string: [6](#0-5) 

### Impact Explanation
Any `(v, r, s, customMessage)` tuple that successfully associates an address on one Sei network can be resubmitted, unmodified, on any other Sei network sharing this precompile's bytecode (mainnet, testnet, devnet, or a future chain fork), or replayed later on the same chain by an unrelated relayer who has observed the tuple in a public transaction. Because `associateAddresses` requires only that the target Sei address is *not yet* associated, the first entity to broadcast the tuple on a given chain forces the association there — regardless of whether the user intended association to occur on that chain, or at that time. This directly triggers `MigrateBalance`, which unconditionally sweeps the user's direct-cast account funds into the newly associated account and can delete the cast account. Given the codebase's own documented rationale for the SetCode fix, this can move funds unexpectedly and "orphan staking/distribution state" tied to the direct-cast address, without the affected user's current consent — a state-mutating, fund-moving action triggered by replaying public signature data across network boundaries.

### Likelihood Explanation
Likelihood is high for exploitation feasibility (no special access needed — any public RPC client can submit the replayed `associate` call, and `(v, r, s, customMessage)` tuples are visible on-chain/in the mempool once submitted once), but the trigger requires a specific precondition: the user must have used the same private key across two live Sei-based networks (e.g., testnet and mainnet, or the pre-fork and post-fork chain) and signed the same `associate` message on one of them. This is a plausible but not universal scenario (shared keys across a chain's test/main networks are common in practice, and chain forks are an explicit part of the report's threat model). The severity of the outcome (forced balance migration / orphaned state) once the precondition is met is unmitigated by any code-level defense, unlike the parallel SetCode authorization path which is explicitly hardened.

### Recommendation
Bind the `associate` signature to chain identity by including the current chain ID (and ideally the precompile/contract address) in the hash that is signed and verified, e.g. `keccak256(chainID || AddrAddress || customMessage)`, mirroring the `ChainID` check already implemented in `AuthorityToPreAssociate` for SetCode authorizations. Alternatively, require the client-supplied `customMessage` envelope to embed the chain ID and validate it server-side before accepting the signature, rejecting mismatched chain IDs the same way `AuthorityToPreAssociate` does.

### Proof of Concept
1. On Sei testnet, a user signs the standard association message (`ASSOCIATE_MESSAGE`) with their EVM key and calls `addr.associate(v, r, s, message)` to link their EVM/Sei addresses, exactly as exercised in the integration test: [7](#0-6) 
2. An observer captures the calldata `(v, r, s, message)` from this public testnet transaction.
3. Because `customMessageHash = keccak256(message)` contains no chain identifier, the observer submits the identical calldata to the `addr` precompile at the same address `0x0000000000000000000000000000000000001004` on Sei mainnet (or any other chain running this precompile with the same private key's public exposure).
4. `helpers.GetAddresses` recovers the same `evmAddr`/`seiAddr`/`pubkey` on mainnet; `associateAddresses` finds the mainnet Sei address unassociated and proceeds.
5. `AssociateAddresses`/`MigrateBalance` executes on mainnet, sweeping the user's mainnet direct-cast account balance into the newly associated account — forced by a signature the user only intended for testnet, with no chain-ID check to reject it.

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// already associated. Mirroring validateAuthorization is essential to security: the
// authorization sig hash is computed from the auth's own ChainID, so recovery and
// auth.Authority() succeed for an authorization signed for ANY chain. Without these checks a
// publicly-visible authorization a user signed for another chain (e.g. Ethereum mainnet)
// could be replayed in a sponsored Sei SetCode tx to force-associate them — migrating their
// direct-cast balance and orphaning staking/distribution state — even though the EVM skips
// the wrong-chain authorization and installs no delegation.
func AuthorityToPreAssociate(ctx sdk.Context, k AuthorizationStateReader, auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, bool) {
	// Chain ID must be null or match the local chain.
	if !auth.ChainID.IsZero() && auth.ChainID.CmpBig(k.ChainID(ctx)) != 0 {
		return common.Address{}, nil, nil, false
	}
	// Nonce must not overflow (EIP-2681).
	if auth.Nonce+1 < auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	evmAddr, seiAddr, pubkey, err := RecoverAddressesFromAuthorization(auth)
	if err != nil {
		return common.Address{}, nil, nil, false
	}
	// Cross-check against go-ethereum's authoritative recovery so we only ever act on the
	// exact address SetCode would target during execution.
	if authAddr, aerr := auth.Authority(); aerr != nil || authAddr != evmAddr {
		return common.Address{}, nil, nil, false
	}
	// Authority must have no code, or only an existing delegation designator.
	if code := k.GetCode(ctx, evmAddr); len(code) != 0 {
		if _, ok := ethtypes.ParseDelegation(code); !ok {
			return common.Address{}, nil, nil, false
		}
	}
	// Authority account nonce must match the authorization nonce.
	if k.GetNonce(ctx, evmAddr) != auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	// Already-associated authorities need no pre-association (and cannot be re-mapped).
	if _, associated := k.GetEVMAddress(ctx, seiAddr); associated {
		return common.Address{}, nil, nil, false
	}
	return evmAddr, seiAddr, pubkey, true

/** The canonical association message users sign (mirrors the legacy hardhat suite). */
const ASSOCIATE_MESSAGE =
    'Please sign this message to link your EVM and Sei addresses. No SEI will be spent as a result of this signature.\n\n';

/** EIP-191 envelope the precompile hashes: "\x19Ethereum Signed Message:\n<len><message>". */
const eip191Envelope = (message: string): string =>
    `\x19Ethereum Signed Message:\n${Buffer.from(message, 'utf8').length}${message}`;

/** v/r/s in the precompile's expected shape: v is the 0/1 recovery id as hex. */
const signatureParts = async (wallet: EvmAccount, message: string) => {
    const sig = ethers.Signature.from(await wallet.wallet.signMessage(message));
    return { v: `0x${sig.v - 27}`, r: sig.r, s: sig.s };
};
