### Title
Excess native-token ETH sent to `EvmHost.dispatch`/`fundRequest` is refunded to the Host contract instead of the caller and becomes unrecoverable by users - (File: `evm/src/core/EvmHost.sol`)

### Summary
The External Report's core broken invariant is: *the refund path for excess submission fee credits the wrong beneficiary (a `msg.sender`-derived address that cannot actually receive/claim the funds), causing user value to become permanently stuck*. The local analog is in `EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()` in [1](#0-0) , which forward the caller's entire `msg.value` to `IUniswapV2Router02.swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)`.

### Finding Description
`swapETHForExactTokens` (standard UniswapV2 semantics, also mirrored by the project's own wrapper routers) refunds any unspent ETH dust to `msg.sender` **of that call**, not to the original transaction sender. Because `EvmHost` itself calls the router, `msg.sender` inside the router at refund time is `address(this)` (the `EvmHost` contract), not `_msgSender()` (the actual dApp/user who funded the dispatch). Confirmed in the codebase's own router wrapper implementations, which explicitly forward the refund to `msg.sender` of the wrapper call: [2](#0-1) [3](#0-2) 

`EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()` all follow this same pattern — forwarding `msg.value` unconditionally and never re-checking or refunding a delta to `_msgSender()` afterward: [4](#0-3) [5](#0-4) [6](#0-5) 

Consequently, any excess native ETH (dust) returned by the swap lands in the `EvmHost` contract's own balance rather than back with the caller who overpaid. This is the same broken invariant as the report: the intended refund recipient (the actual payer) never receives their unspent submission funds because the refund target used by the downstream call is bound to the wrong address (the intermediary contract, not the original payer).

By contrast, other parts of the codebase (e.g. `IntentGatewayV2.sol`) explicitly track `msgValue` deltas and refund unspent native tokens back to `msg.sender` after a swap: [7](#0-6) 
This shows the protocol is aware of and normally implements this refund pattern correctly elsewhere, but `EvmHost`'s own `dispatch`/`fundRequest` functions lack the equivalent check.

The only path by which native ETH sitting in `EvmHost` can be moved out is the privileged, cross-chain-governance-gated `withdraw()` function, restricted to `_hostParams.hostManager`: [8](#0-7) 
This function sends funds to an arbitrary `beneficiary` chosen by governance — it has no notion of "whose dust this was," so the overpaying user has no way to reclaim their own excess ETH; it is effectively donated to whichever beneficiary governance later chooses to withdraw to.

### Impact Explanation
Every call to `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, or `fundRequest()` that pays with native token and slightly overestimates the amount needed for the Uniswap swap (an extremely common case, since callers must estimate `post.fee`/`amount` in fee-token terms and provide a native-value cushion) permanently loses the unspent portion into the `EvmHost` contract balance. This is a direct, unprivileged loss of user funds during ordinary bridge usage — falling squarely in the required impact category "stealing or loss of funds." It requires no malicious relayer, prover, or admin — it is triggered purely by normal user/application behavior overestimating the native-value cushion for a routine dispatch call.

### Likelihood Explanation
High likelihood: any unprivileged caller who dispatches a POST/GET request or funds a request using native ETH (rather than pre-approved fee tokens) and provides even a small buffer above the exact swap input amount (which is unknown in advance because it depends on live AMM pricing) will lose the difference. This is the default/expected way to interact with `dispatch{value: ...}()` per the documentation examples shown throughout `docs/content/developers/evm/messaging/post-requests.mdx`, which encourage sending `msg.value` with the call.

### Recommendation
In `EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()`, record `address(this).balance` (or track amounts spent) before invoking `swapETHForExactTokens`, and after the swap, refund the delta (`msg.value - amountSpent`) directly to `_msgSender()`, mirroring the pattern already used in `IntentGatewayV2.sol`'s `placeOrder`/`fillOrder` refund logic.

### Proof of Concept
1. Caller A invokes `EvmHost.dispatch{value: 1 ether}(post)` where `post.fee` only requires `0.4 ether` worth of ETH to swap for the exact `feeToken` amount.
2. `EvmHost.dispatch` forwards the full `1 ether` to `IUniswapV2Router02.swapETHForExactTokens{value: 1 ether}(post.fee, path, address(this), block.timestamp)`.
3. The router computes `amounts[0] = 0.4 ether`, performs the swap, and refunds the remaining `0.6 ether` to `msg.sender` of the router call — which is `EvmHost`, not caller A.
4. `EvmHost`'s ETH balance increases by `0.6 ether`; caller A has no function to reclaim it. The funds sit in the contract until governance calls `withdraw()` to an arbitrary beneficiary — never to caller A.
5. Repeat for `dispatch(DispatchGet)` and `fundRequest()` — same code pattern, same unrecoverable loss for the original payer.

    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();

            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});

            source: string(request.source),
            dest: string(request.dest),
            from: _msgSender(),
            to: abi.encodePacked(request.to),
            nonce: request.nonce,
            timeoutTimestamp: request.timeoutTimestamp,
            body: request.body,
            fee: post.fee
        });
    }

    function fundRequest(bytes32 commitment, uint256 amount) external payable notFrozen {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                amount, path, address(this), block.timestamp
            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }
