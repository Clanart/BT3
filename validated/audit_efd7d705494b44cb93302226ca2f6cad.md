### Title
`isSafeFileExtension` restriction is enforced in every other file context menu but omitted in the Copilot merge-conflict dialog, allowing execution of attacker-controlled files - (`File: app/src/ui/multi-commit-operation/dialog/copilot-conflicts-dialog.tsx`)

### Summary
GitHub Desktop guards the "Open with Default Program" action for files under a repository by checking `isSafeFileExtension`, which on Windows blocks execution of `.cmd`, `.exe`, `.bat`, and `.sh` files (to prevent a cloned/fetched repo from tricking the user into running an attacker-controlled executable). This guard is consistently applied everywhere else the action is offered, but is missing from the Copilot Conflict Resolution dialog's file overflow menu, which calls the same `openFile()` primitive unconditionally. This mirrors the M-28 pattern: a security check is enforced on one code path but not on an equivalent, reachable alternate path, letting the check be trivially bypassed by using the unguarded path.

### Finding Description
`isSafeFileExtension` in `app/src/ui/lib/context-menu.ts` is defined specifically to prevent execution of restricted extensions on Windows: [1](#0-0) [2](#0-1) 

Every other consumer of the "Open with Default Program" action gates it behind this check before calling into `openFile`/`onOpenItem`:
- `app/src/ui/changes/filter-changes-list.tsx`: `enabled: enabled && isSafeExtension` for both the default and rebase context menus. [3](#0-2) 
- `app/src/ui/history/selected-commits.tsx`: `enabled: isSafeExtension && fileExistsOnDisk`. [4](#0-3) 
- `app/src/ui/open-pull-request/pull-request-files-changed.tsx`: same `isSafeExtension` gate. [5](#0-4) 

However, the Copilot merge-conflict dialog's `onOverflowMenuClick` builds an "Open with Default Program" menu item that calls `openFile(absolutePath, dispatcher)` directly, with no `isSafeFileExtension`/`isSafeExtension` check at all: [6](#0-5) 

`openFile()` simply invokes `shell.openExternal('file://' + fullPath)`, which on Windows/macOS/Linux hands the file to the OS default handler — for `.exe`/`.cmd`/`.bat`/`.sh` this typically means executing it: [7](#0-6) 

The conflicted files rendered in this dialog come directly from the working directory's merge-conflict state (`file.path` from the conflict list), i.e., paths that originate from the two merged trees — one of which can be attacker-controlled (a branch/PR/fork the user is merging). By naming a file with a dangerous extension so that it appears as a conflicted file, an attacker causes the "Open with Default Program" item to be offered without the safety gate that exists everywhere else in the codebase.

### Impact Explanation
If the victim clicks "Open with Default Program" on the attacker-named conflicted file from the Copilot conflict resolution overflow menu on Windows, the OS will execute the `.exe`/`.cmd`/`.bat`/`.sh` payload with the user's privileges — full code execution outside any git/Desktop sandboxing. This is a direct violation of the same invariant Desktop enforces elsewhere ("never let a repository-controlled file execute via the default-program action"), silently bypassed via one specific, less-audited UI surface.

### Likelihood Explanation
Reaching this path only requires the victim to open a repository containing a merge conflict where one side introduces a maliciously-named file (e.g., cloning/fetching a branch or opening a PR that conflicts with local changes) and then to use the Copilot conflict-resolution dialog's per-file overflow menu, clicking "Open with Default Program." No local access, admin rights, or pre-existing malware is required — only a crafted git history/branch the user merges, which is squarely within the "attacker controls a cloned/fetched repository" threat model. The main friction is that the user must click the specific menu item, which is a normal, expected interaction (not an unnatural step), and the label itself invites this action.

### Recommendation
Apply the same `isSafeFileExtension(Path.extname(path))` gate to the "Open with Default Program" menu item in `copilot-conflicts-dialog.tsx` that is used in `filter-changes-list.tsx`, `selected-commits.tsx`, and `pull-request-files-changed.tsx`, disabling/removing the item (or refusing to call `openFile`) for restricted extensions.

### Proof of Concept
1. Attacker prepares a branch/fork containing a file `payload.cmd` (or `.exe`/`.bat`/`.sh`) at the same path as a file modified locally by the victim, so that merging produces a conflict.
2. Victim fetches/pulls and merges the attacker's branch, triggering a merge conflict; Desktop opens the Copilot Conflict Resolution dialog listing `payload.cmd` as a conflicted file.
3. Victim opens the file's overflow menu and clicks "Open with Default Program" (`app/src/ui/multi-commit-operation/dialog/copilot-conflicts-dialog.tsx:227-229`).
4. Unlike the equivalent action in Changes/History/PR file lists, no `isSafeFileExtension` check blocks the action; `openFile()` calls `shell.openExternal('file://.../payload.cmd')`, and Windows executes the attacker-controlled script.

  private onOverflowMenuClick = (path: string) => {
    const { repository, dispatcher, resolvedExternalEditor } = this.props
    const absolutePath = join(repository.path, path)

    const items: IMenuItem[] = []

    if (resolvedExternalEditor !== null) {
      items.push({
        label: `Open in ${resolvedExternalEditor}`,
        action: () => this.props.openFileInExternalEditor(absolutePath),
      })
    }

    items.push(
      {
        label: OpenWithDefaultProgramLabel,
        action: () => openFile(absolutePath, dispatcher),
      },
      {
        label: RevealInFileManagerLabel,
        action: () => revealInFileManager(repository, path),
      }
    )

import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
