## Title
Overwritten Per-Operation SSH Credential Tracking Causes Stale/Unwanted Passphrases To Remain Permanently Stored In The OS Keychain - (File: `app/src/lib/ssh/ssh-credential-storage.ts`)

### Summary
`mostRecentSSHCredentials` tracks, per git operation (`operationGUID`/trampoline token), only a **single** pending SSH credential entry that is meant to be rolled back if the git operation fails to authenticate. `setMostRecentSSHCredential` unconditionally overwrites that single entry for the given key, exactly like the Behodler `pendingFlashDecision[target][sender] = flashGovernanceConfig` overwrite. If more than one distinct SSH credential (key passphrase or user password) is prompted for and persisted during the *same* git operation, only the last one is remembered for cleanup — any earlier credential that was already written to the OS keychain becomes "unaccounted for": it is never deleted even when the overall operation is known to have failed authentication.

### Finding Description
`mostRecentSSHCredentials` is a `Map<string, SSHCredentialEntry>` keyed by `operationGUID`, holding exactly one `{ store, key }` pair: [1](#0-0) 

`setSSHCredential`/`setMostRecentSSHCredential` immediately persist the secret to the OS keychain via `TokenStore.setItem`, and *unconditionally* replace whatever was tracked before for that `operationGUID`: [2](#0-1) 

`handleSSHKeyPassphrase` in the askpass trampoline handler is invoked once per `Enter passphrase for key '<path>':` prompt from the underlying `ssh` process, and calls `setSSHKeyPassphrase(operationGUID, keyPath, passphrase)` whenever the user opts to remember it: [3](#0-2) 

A single git command (one `operationGUID`/trampoline token) can legitimately prompt for **multiple, distinct** SSH key passphrases — e.g. a `clone --recurse-submodules` or `fetch` that touches several submodules each configured (via attacker-controlled `.gitmodules`/submodule remote URLs) to use a different SSH key path. Each successive "remember passphrase" answer calls `setSSHKeyPassphrase` again for the same `operationGUID`, overwriting the tracked `{store, key}` pair in `mostRecentSSHCredentials` — even though the *previous* passphrase was already written to the keychain.

When the git operation ultimately fails with an SSH authentication error, `withTrampolineEnv` performs cleanup by deleting only the credential *currently tracked* for that token: [4](#0-3) 

`deleteMostRecentSSHCredential`/`removeMostRecentSSHCredential` operate on the single map entry for `operationGUID`, so only the last-prompted credential is rolled back: [5](#0-4) 

The earlier credential(s) — already committed to the OS keychain via `TokenStore.setItem` inside `setSSHCredential` — are never revisited or removed, even though the operation is known to have failed authentication. This mirrors the report's broken invariant: a keyed pending-state map is overwritten without accounting for or resolving the previous entry first, silently orphaning state that should have been reconciled (there, tokens locked in the contract; here, a stale passphrase permanently kept in the keychain).

### Impact Explanation
A crafted/malicious repository (via submodules or remotes pointing at multiple distinct SSH hosts/keys) can cause a single Desktop git operation to sequentially prompt for and store more than one SSH key passphrase. If the operation subsequently fails authentication (e.g. because one of the attacker-configured remotes deliberately rejects the key), Desktop's cleanup path only removes the last tracked credential. Any earlier, now-known-bad or unwanted passphrase remains permanently persisted in the OS keychain, keyed by a hash of the corresponding key file path. This is a genuine credential-hygiene/state-corruption bug reachable purely through interacting with a malicious cloned/fetched repository (submodule configuration is attacker-controlled content), without any local/physical access, admin rights, or prior compromise. The practical outcome is unwanted, undeleted secret material lingering in the OS credential store, which can later be silently reused by `getSSHKeyPassphrase` for git operations against that key path without re-prompting the user.

### Likelihood Explanation
Reaching this requires only cloning/fetching a repository containing submodules (or other multi-remote operations) referencing distinct SSH key paths within a single git invocation, and the user enabling "remember passphrase" more than once during that operation before an authentication failure occurs later in the same run — a realistic occurrence given how git processes submodules sequentially under one process/trampoline token. No unnatural or many-step social engineering is needed beyond normal repository cloning behavior that Desktop already performs automatically.

### Recommendation
Track pending SSH credentials per-operation as a list/set rather than a single overwritable entry (e.g. `Map<string, SSHCredentialEntry[]>`), and on cleanup (`deleteMostRecentSSHCredential`/`removeMostRecentSSHCredential`) iterate and resolve *all* entries recorded for the given `operationGUID`, not just the last one written.

### Proof of Concept
1. Prepare a malicious repository with two submodules, each configured to require a different SSH private key (different `core.sshCommand`/`IdentityFile` via `.git/config` for the submodule, or distinct SSH URLs mapped to different keys via the user's `~/.ssh/config`).
2. In GitHub Desktop, clone the repository with submodules enabled.
3. When prompted for the passphrase of the first submodule's SSH key, enter it and check "remember this passphrase" — `setSSHKeyPassphrase(operationGUID, keyPath1, passphrase1)` stores it to the keychain and sets `mostRecentSSHCredentials.set(operationGUID, {store, key: hash(keyPath1)})`.
4. When prompted for the second submodule's SSH key, enter it and also choose to remember it — this overwrites the map entry for `operationGUID` to `{store, key: hash(keyPath2)}` per `app/src/lib/ssh/ssh-credential-storage.ts:58-64`, losing track of `keyPath1`'s entry.
5. Cause the overall clone to fail authentication afterward (e.g., the second submodule's remote rejects the key for an unrelated reason, triggering `SSHAuthenticationFailed`).
6. `withTrampolineEnv`'s catch block calls `deleteMostRecentSSHCredential(token)` (`app/src/lib/trampoline/trampoline-environment.ts:148-157`), which deletes only the entry for `keyPath2`.
7. Inspect the OS keychain: the passphrase for `keyPath1` remains stored indefinitely, never cleaned up despite the operation having failed.

/**
 * This map contains the SSH credentials that are pending to be stored. What this
 * means is that a git operation is currently in progress, and the user wanted
 * to store the passphrase for the SSH key, however we don't want to store it
 * until we know the git operation finished successfully.
 */
const mostRecentSSHCredentials = new Map<string, SSHCredentialEntry>()

/**
 * Stores an SSH credential and also keeps it in memory to be deleted later if
 * the ongoing git operation fails to authenticate.
 *
 * @param operationGUID A unique identifier for the ongoing git operation. In
 *                      practice, it will always be the trampoline token for the
 *                      ongoing git operation.
 * @param store         Store where the SSH credential is stored.
 * @param key           Key that identifies the SSH credential (e.g. username or
 *                      key hash).
 * @param password      Password for the SSH key / user.
 */
export async function setSSHCredential(
  operationGUID: string,
  store: string,
  key: string,
  password: string
) {
  setMostRecentSSHCredential(operationGUID, store, key)
  await TokenStore.setItem(store, key, password)
}

/**
 * Keeps the SSH credential details in memory to be deleted later if the ongoing
 * git operation fails to authenticate.
 *
 * @param operationGUID A unique identifier for the ongoing git operation. In
 *                      practice, it will always be the trampoline token for the
 *                      ongoing git operation.
 * @param store         Store where the SSH credential is stored.
 * @param key           Key that identifies the SSH credential (e.g. username or
 *                      key hash).
 */
export function setMostRecentSSHCredential(
  operationGUID: string,
  store: string,
  key: string
) {
  mostRecentSSHCredentials.set(operationGUID, { store, key })
}

/**
 * Removes the SSH credential from memory. This must be used after a git
 * operation finished, regardless the result.
 */
export function removeMostRecentSSHCredential(operationGUID: string) {
  mostRecentSSHCredentials.delete(operationGUID)
}

/**
 * Deletes the SSH credential from the TokenStore. Used when the git operation
 * fails to authenticate.
 */
export async function deleteMostRecentSSHCredential(operationGUID: string) {
  const entry = mostRecentSSHCredentials.get(operationGUID)
  if (entry) {
    log.info(
      `SSH auth failed, deleting credential for ${entry.store}:${entry.key}`
    )

    await TokenStore.deleteItem(entry.store, entry.key)
  }
}

async function handleSSHKeyPassphrase(
  operationGUID: string,
  prompt: string
): Promise<string | undefined> {
  const promptRegex = /^Enter passphrase for key '(.+)': $/

  const matches = promptRegex.exec(prompt)
  if (matches === null || matches.length < 2) {
    return undefined
  }

  let keyPath = matches[1]

  // The ssh bundled with Desktop on Windows, for some reason, provides Unix-like
  // paths for the keys (e.g. /c/Users/.../id_rsa). We need to convert them to
  // Windows-like paths (e.g. C:\Users\...\id_rsa).
  if (__WIN32__ && /^\/\w\//.test(keyPath)) {
    const driveLetter = keyPath[1]
    keyPath = keyPath.slice(2)
    keyPath = `${driveLetter}:${keyPath}`
  }

  const storedPassphrase = await getSSHKeyPassphrase(keyPath)
  if (storedPassphrase !== null) {
    // Keep this stored passphrase around in case it's not valid and we need to
    // delete it if the git operation fails to authenticate.
    await setMostRecentSSHKeyPassphrase(operationGUID, keyPath)
    return storedPassphrase
  }

  if (getIsBackgroundTaskEnvironment(operationGUID)) {
    log.debug(
      'handleSSHKeyPassphrase: background task environment, skipping prompt'
    )
    return undefined
  }

  const { secret: passphrase, storeSecret: storePassphrase } =
    await trampolineUIHelper.promptSSHKeyPassphrase(keyPath)

  // If the user wanted us to remember the passphrase, we'll keep it around to
  // store it later if the git operation succeeds.
  // However, when running a git command, it's possible that the user will need
  // to enter the passphrase multiple times if there are failed attempts.
  // Because of that, we need to remove any pending passphrases to be stored
  // when, in one of those multiple attempts, the user chooses NOT to remember
  // the passphrase.
  if (passphrase !== undefined && storePassphrase) {
    setSSHKeyPassphrase(operationGUID, keyPath, passphrase)
  } else {
    removeMostRecentSSHCredential(operationGUID)
  }

  return passphrase ?? ''
}
