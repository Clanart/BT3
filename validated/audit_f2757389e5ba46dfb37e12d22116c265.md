### Title
Payout transaction's operator attribution (`OP_RETURN`) is unauthenticated and decoupled from who actually funds the withdrawal, allowing reimbursement credit to be misattributed - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The `Payout` transaction that fronts a Citrea withdrawal commits the "paying operator's" x-only public key in a plain, unsigned `OP_RETURN` output. Downstream reimbursement logic treats this `OP_RETURN` value as ground truth for "who paid the withdrawal," but nothing cryptographically binds that value to whoever actually supplies the BTC that funds the payout. This breaks the intended equality `reimbursed_operator == funding_party`, mirroring the external report's bug class where the entity credited for an action is not necessarily the entity that performed/paid for it.

### Finding Description
`create_payout_txhandler` builds the payout transaction with a single user-signed input (the withdrawal UTXO, signed `SIGHASH_SINGLE|ANYONECANPAY`) and writes an arbitrary `operator_xonly_pk` parameter into a plain `OP_RETURN` output: [1](#0-0) 

Because the sighash type is `SIGHASH_SINGLE|ANYONECANPAY`, the user's signature only commits to the user-facing output; any party can attach arbitrary additional funding inputs and an arbitrary `OP_RETURN` payload (i.e., any operator's or any other) to a transaction spending that same withdrawal input, as done in `Operator::withdraw`: [2](#0-1) 

Once such a payout transaction confirms, the verifier's block-sync logic reads whatever x-only public key is present in the `OP_RETURN` and records it in the DB as the "payer operator," with no check that this operator supplied the transaction's actual funding inputs: [3](#0-2) 

This recorded value is later trusted as the definitive attribution of "who paid":
- `is_kickoff_malicious` only checks that the kickoff's operator matches the DB-recorded `operator_xonly_pk` from the `OP_RETURN`, and that the committed block hash matches — it never checks who actually funded the payout tx. [4](#0-3) 
- `validate_payer_is_operator` / `get_reimbursement_txs`, used by an operator's own automation to determine if/when they can claim reimbursement, trust this same field. [5](#0-4) 
- `get_first_unhandled_payout_by_operator_xonly_pk` looks up unhandled payouts strictly by the recorded `payout_payer_operator_xonly_pk`. [6](#0-5) 

The equality that should hold is: `payout_payer_operator_xonly_pk (OP_RETURN) == entity_that_funded_the_payout_tx_inputs`. Nothing enforces this — the `OP_RETURN` is unsigned data that whoever assembles/broadcasts the transaction is free to set to any operator's key (including one who never actually funded anything), because the only cryptographic commitment in the transaction is the user's `ANYONECANPAY` signature over their own withdrawal output.

### Impact Explanation
Because reimbursement, kickoff-validity ("malicious" detection), and the "already handled" bookkeeping are all keyed off this unauthenticated field, an attacker who funds a withdrawal's output themselves (or observes/replaces an in-flight, unconfirmed payout transaction before it confirms) can write any operator's x-only public key into the `OP_RETURN`. That operator will subsequently be treated by the protocol as the one who fronted the payout, letting a party who never funded the withdrawal be credited (matching the "operator credited versus the party that paid" custody-binding break called out in the rules), or letting a targeted honest operator be marked as having already paid a withdrawal it never funded — permanently blocking that operator's legitimate reimbursement path for the corresponding deposit, since the withdrawal will show as handled/attributed to them in the DB.

### Likelihood Explanation
Exploitation requires the attacker to supply the (near-)full withdrawal amount as funding for the transaction, since the user's signed input covers only the dust amount used to bind the signature; the bulk of the payout value must come from additional attacker-supplied inputs. This is not free, but it is entirely within reach of an unprivileged actor with capital and no special role, and does not require compromising any key, verifier, or operator. It also does not require the deployment to deviate from documented configuration.

### Recommendation
Cryptographically bind the `OP_RETURN` operator attribution to the actual funder of the payout transaction, e.g., by requiring the credited operator's signature/commitment over the full payout transaction (not just the user's per-output signature), or by deriving/validating the attributed operator from a signature that only that operator could produce over the specific payout transaction, rather than trusting free-form `OP_RETURN` data written by whoever broadcasts the transaction.

### Proof of Concept
1. A withdrawal is registered on Citrea with a small "dust" input UTXO and a large payout output, signed by the user with `SIGHASH_SINGLE|ANYONECANPAY` (see `generate_withdrawal_transaction_and_signature`). [7](#0-6) 
2. Before the legitimate operator's payout transaction confirms, an attacker constructs a competing transaction spending the same signed withdrawal input, adds their own funding inputs to cover the payout value, and sets the `OP_RETURN` output to the x-only public key of an arbitrary (e.g. victim) operator, mirroring `create_payout_txhandler`'s construction. [8](#0-7) 
3. Once this transaction confirms, `update_finalized_payouts` records the attacker-chosen operator key as the `payout_payer_operator_xonly_pk` for that withdrawal. [9](#0-8) 
4. The victim/credited operator (or the attacker if they choose their own key) is now treated by `is_kickoff_malicious`, `validate_payer_is_operator`, and `get_first_unhandled_payout_by_operator_xonly_pk` as the party that fronted this withdrawal, even though they never supplied its funding.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
