### Title
Cross-recipient replay of `EncryptedMessage` produces valid blame against an honest sender and publishes an unintended ECDH key - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the Guzzle advisory — where a credential bound "for the proxy only" is delivered to an unintended recipient because routing decisions don't strip it — PedPoP's per-message proof-of-possession binds the *sender* but never the *recipient*. `pop_challenge` includes `context`, `nonce`, `key`, `sender`, and the ciphertext, but no `to` field (crypto/dkg/pedpop/src/encryption.rs:302-324). The recipient is only bound implicitly through the ECDH key (`ecdh(private=recipient_enc_key, public=msg.key)`, encryption.rs:95-97). That implicit binding is exactly what fails under replay: a copied message still has a valid PoP for its real sender, so when it is replayed to a different recipient it passes signature verification, decrypts to garbage under that recipient's key, and the blame machinery then attributes the fault to the honest sender — while publishing a valid `EncryptionKeyProof` (an ECDH shared key + DLEq) for a sender/recipient pairing that was never intended.

### Finding Description
- `encrypt` produces `EncryptedMessage { key, pop, msg }` where `pop` is a Schnorr signature over `pop_challenge(context, R, key, from, ciphertext)` (encryption.rs:153-167, 302-324). The challenge transcript at encryption.rs:314-319 appends `nonce`, `key`, `sender`, `message` — no recipient.
- `Decryption::decrypt_with_proof` verifies the PoP against `from` only (encryption.rs:374-379), then verifies the accuser's `EncryptionKeyProof` DLEq against `self.enc_keys[&decryptor]` (encryption.rs:381-390) and decrypts with `proof.key`.
- `BlameMachine::blame_internal` returns `sender` as faulty whenever the decrypted bytes aren't a canonical scalar or fail `share_verification_statements` (lib.rs:590-605).
- Therefore: attacker Eve obtains any valid `EncryptedMessage` authored by Alice for a different recipient (e.g., ciphertext routed through the shared coordinator path consumed by `CoordinatorMessage::VerifyBlame`, processor/src/key_gen.rs:504-549), submits it to her own `KeyMachine::calculate_share` as Alice's share to Eve, receives `InvalidShare { participant: Alice, blame: Some(proof) }`, and publishes it. `proof.key = ecdh(eve_enc_key, X)` is a legitimately-derivable key so the DLEq verifies, decryption yields non-canonical bytes, and `blame_internal` convicts Alice, who sent Eve nothing at all.
- The published `EncryptionKeyProof` additionally discloses the ECDH shared key `e·X` — a credential-like value intended only to exist between the message's real endpoints — to every party evaluating blame (`AdditionalBlameMachine::new` is explicitly usable by non-participants, lib.rs:639-662). Per-message keys exist precisely so that blame reveals only the accused message (encryption.rs:78-93); replay widens disclosure to pairings the sender never created.

### Impact Explanation
Two concrete consequences reachable by an unprivileged participant:
1. **False conviction of an honest party.** `blame_internal` cryptographically convicts Alice (`return sender`, lib.rs:592-604) for a message she never addressed to the accuser. In Serai's deployment this blame feeds `ProcessorMessage::Blame`/fatal slashing (processor/src/key_gen.rs:504-549), so an honest validator can be blamed and the DKG aborted (or worse, penalized) purely from replayed public-transit ciphertext.
2. **Unintended credential disclosure.** The published `EncryptionKeyProof` reveals an ECDH shared key for a pairing the sender never authorized — the direct analog of `Proxy-Authorization` reaching an unintended origin. Its damage is bounded to that ciphertext (which decrypts to garbage), but it violates the library's disclosure guarantee and leaks a valid DLEq-linked shared key.

### Likelihood Explanation
Requirements: the attacker can observe an `EncryptedMessage` authored by the victim (shares transit a coordinator/`VerifyBlame` path, and `AdditionalBlameMachine` is designed for arbitrary third-party evaluation, so ciphertext circulation is assumed by the design) and can submit it as a share addressed to themselves. Both are within the unprivileged-participant model. The missing recipient binding is a one-line omission in `pop_challenge`, not a probabilistic edge case, so the attack is deterministic once ciphertext is observed. Medium severity: it enables false blame/abort and unintended key disclosure, but does not directly recover a secret share or forge a signature.

### Recommendation
Bind the intended recipient into the proof of possession. Add a `to: Participant` parameter to `pop_challenge` (encryption.rs:302) and `transcript.append_message(b"recipient", to.to_bytes())`, threading the recipient index through `encrypt` (encryption.rs:135-168), `Encryption::encrypt` (encryption.rs:460-467), `Encryption::decrypt`/`decrypt_with_proof` (encryption.rs:366-397, 469-501). With the recipient in the challenge, a replayed message fails PoP verification under any recipient other than the original, and `blame_internal`'s `InvalidSignature` arm convicts the relayer instead of the sender. (This requires a transcript version bump since the domain-separated label `DKG Encryption ... v0.2` values would change.)

### Proof of Concept
1. Alice runs `KeyGenMachine`/`SecretShareMachine::generate_secret_shares`, producing `msg_ab = EncryptedMessage` for Bob: `key = X`, `pop = SchnorrSign(x, pop_challenge(ctx, R, X, sender=Alice, ct))`, `ct = ChaCha20(key=H(ctx, ecdh(x, bob_enc))) (share_ab)`.
2. Eve observes `msg_ab` in transit (coordinator-routed share traffic / blame evaluation corpus). Eve builds her `shares` map for `KeyMachine::calculate_share` with `shares[Alice] = msg_ab` (filling other slots with valid shares).
3. `calculate_share` → `Encryption::decrypt(from=Alice, msg_ab)`: PoP verifies (sender=Alice is correct), Eve computes `key' = ecdh(eve_enc_key, X)`, decrypts `ct` → garbage; `from_repr` fails → `PedPoPError::InvalidShare { participant: Alice, blame: Some(EncryptionKeyProof { key: eX, dleq }) }` (lib.rs:477-499).
4. Eve publishes `(Alice, Eve, msg_ab, Some(proof))` via `BlameMachine::blame`/`AdditionalBlameMachine::blame`. `decrypt_with_proof` accepts the PoP, the DLEq verifies against `enc_keys[Eve]`, decryption yields non-scalar bytes → `blame_internal` returns `sender` = Alice (lib.rs:590-593, 604). Honest Alice is convicted; `eX` is now public to all blame evaluators.

```
Alice -- msg_ab(key=X, pop(sender=Alice), ct_b) --> Bob
                        |
        Eve copies msg_ab, submits as "Alice's share to Eve"
                        |
   Eve's machine: pop OK, ecdh(e, X) =/= ct key -> InvalidShare(Alice, proof{eX, DLEq})
                        |
        BlameMachine::blame(Alice, Eve, msg_ab, proof)
            -> decrypts to garbage -> returns `sender` (Alice)  [false conviction]
            -> publishes eX to all blame evaluators            [unintended disclosure]
```

Caveat: reachability depends on an attacker being able to observe a victim's `EncryptedMessage` ciphertexts (e.g., via coordinator routing or the third-party blame corpus); if share ciphertexts are strictly confidential between endpoints, the false-blame path is not mountable, though the missing recipient binding remains a latent defect.
