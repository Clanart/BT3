### Title
Out-of-bounds byte read in CLVM atom length-prefix parser causes unhandled exception on malformed spend bundle - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` parses the variable-length CLVM atom length-prefix directly out of a raw `bytes` buffer using unchecked indexing (`clvm_buffer[offset]`), mirroring the class of bug reported in ALPINE-CVE-2017-11719 (FFmpeg's `dnxhd_decode_header` reading past the end of a crafted header buffer). If a puzzle-reveal/solution byte string ends immediately after a multi-byte length-prefix marker (e.g. `0xF8`), the follow-up loop advances `offset` past the buffer boundary and indexes into it, raising an unhandled `IndexError`.

### Finding Description
`is_atom_canonical()` decodes CLVM's atom length prefix (1–6 bytes depending on the leading byte's high bits) directly from a `bytes` object with no bounds check before reading: [1](#0-0) 

The `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` loop assumes `prefix_len` additional bytes are always present after the marker byte. There is no length check comparing `offset + prefix_len` against `len(clvm_buffer)`. This function is invoked by `is_clvm_canonical()`, which walks an entire serialized CLVM buffer atom-by-atom, again with no bounds guard on `clvm_buffer[offset]` reads at the top of its loop: [2](#0-1) 

Per the project's own documentation, this canonical-serialization check gates DEDUP eligibility for mempool spends — i.e., it runs against attacker-controlled puzzle reveal/solution bytes taken from a submitted spend bundle: [3](#0-2) 

This is structurally the same bug class as the FFmpeg CVE: a length-prefixed/header-style binary format is parsed with fixed-offset indexing that assumes the buffer is always long enough to satisfy the declared length field, with no validation that the buffer actually contains the required trailing bytes.

### Impact Explanation
A crafted CLVM buffer (a spend bundle's puzzle reveal or solution) that ends with a truncated multi-byte atom length-prefix will cause `clvm_buffer[offset]` to be evaluated with `offset >= len(clvm_buffer)`, raising an unhandled Python `IndexError`. In Python this manifests as an exception rather than raw memory corruption, but if this code path is reached from spend bundle intake/processing without a surrounding `try/except`, a single malformed spend bundle from any unprivileged submitter can throw an uncaught exception in the mempool manager's processing logic — a spend-triggered transaction-processing disruption for DEDUP-eligibility checks, analogous in reachability and trigger conditions to the out-of-array read described in the CVE.

### Likelihood Explanation
Reachability depends on whether `is_clvm_canonical`/`is_atom_canonical` are called during normal spend bundle intake (fast-forward/dedup eligibility evaluation) versus only in test code. I was able to confirm the functions exist and are documented as gating DEDUP eligibility, and that unit tests import and exercise them directly: [4](#0-3) 

However, I could not locate within the indexed content the exact call site inside `mempool_manager.py`/`eligible_coin_spends.py` that invokes `is_clvm_canonical` on attacker-supplied bytes during live spend bundle processing (as opposed to only being invoked by unit tests). This is a real limitation of my investigation — I could not fully confirm the production call path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing (`if offset + prefix_len >= len(clvm_buffer): return ..., False` or raise a well-defined validation error), and audit callers of `is_clvm_canonical()`/`is_atom_canonical()` to ensure any `IndexError` (or other parsing exception) raised while validating untrusted spend bundle bytes is caught and converted into a normal rejection (e.g. `Err.INVALID_SPEND_BUNDLE` / ineligibility for dedup) rather than propagating as an unhandled exception.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```markdown
## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.
```
