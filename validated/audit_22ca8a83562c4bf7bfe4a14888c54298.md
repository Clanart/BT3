### Title
Unauthenticated, Rate-Limit-Free tx-sender JSON-RPC Drains Operator Wallet via Fake CPFP Transaction Flooding — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The standalone tx-sender JSON-RPC server exposes `send_tx` and `send_citrea_tx` with no authentication and no rate limiting. When bound to `0.0.0.0` (explicitly permitted by the config), any network-reachable attacker can flood the endpoint with syntactically valid but semantically invalid CPFP transactions. The tx-sender loop will attempt to create a fee-payer UTXO for each queued entry by calling `rpc.send_to_address`, draining the operator's Bitcoin wallet. Once the wallet is exhausted, legitimate bridge transactions (kickoffs, payouts, challenges, disproves) cannot be fee-bumped, breaking bridge liveness with material fund impact.

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds the HTTP server with only a body-size cap:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)  // 50 MB
    .build(bind_addr)
    .await
    ...
``` [1](#0-0) 

No `RateLimitLayer`, no `BufferLayer`, no mTLS, no API-key check — nothing. Compare this with the gRPC servers, which apply both `RateLimitLayer` and `BufferLayer` and enforce mTLS:

```rust
let server_builder = tonic::transport::Server::builder()
    .layer(AddMethodMiddlewareLayer)
    .layer(BufferLayer::new(config.grpc.req_concurrency_limit))
    .layer(RateLimitLayer::new(
        config.grpc.ratelimit_req_count as u64,
        Duration::from_secs(config.grpc.ratelimit_req_interval_secs),
    ))
    ...
``` [2](#0-1) 

The bind address is validated to accept `0.0.0.0` as a legitimate value:

```rust
if bind != "127.0.0.1" && bind != "0.0.0.0" {
    return Err(BridgeError::EnvVarMalformed(...));
}
``` [3](#0-2) 

The `send_tx` handler deserializes the raw transaction bytes and immediately inserts the entry into the DB queue with no further validation:

```rust
let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;
let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;
let try_to_send_id = client.insert_try_to_send(&mut dbtx, ...).await...;
client.db.commit_transaction(dbtx).await...;
``` [4](#0-3) 

The tx-sender loop then processes every pending CPFP entry. For each entry with no confirmed fee-payer UTXOs (i.e., every freshly inserted fake entry), `send_cpfp_tx` calls `create_fee_payer_utxo`, which calls `rpc.send_to_address` to fund a new UTXO from the operator's wallet: [5](#0-4) 

Because the fee-payer UTXO check is scoped per `try_to_send_id`, each distinct fake entry triggers a separate `send_to_address` call regardless of how many unconfirmed UTXOs already exist for other entries. [6](#0-5) 

### Impact Explanation

Each fake CPFP entry inserted via the unauthenticated `send_tx` endpoint causes the tx-sender to spend real satoshis from the operator's Bitcoin wallet to create a fee-payer UTXO. Flooding with N entries drains the wallet by N × (2 × required_fee + dust). Once the wallet balance falls below the minimum required fee, the tx-sender can no longer fund legitimate bridge transactions — kickoffs, payouts, watchtower challenges, and disproves all use CPFP and will stall. This directly breaks bridge liveness with material fund impact on tx-sender-managed balances and operator collateral flows.

### Likelihood Explanation

The attack requires the tx-sender to be deployed in standalone mode with `TX_SENDER_JSONRPC_BIND=0.0.0.0`. This is an explicitly documented and supported configuration value. In containerized deployments where the tx-sender runs as a separate service reachable by other containers or exposed through a port mapping, the endpoint is reachable without any credential. No prior knowledge of keys, sessions, or protocol state is needed — only the ability to send HTTP POST requests with a syntactically valid Bitcoin transaction hex.

### Recommendation

1. **Add authentication**: Require a shared secret or mTLS on the JSON-RPC server before any method is dispatched.
2. **Add rate limiting**: Apply a `tower::limit::RateLimitLayer` (or equivalent `jsonrpsee` middleware) consistent with the gRPC server configuration (`ratelimit_req_count` / `ratelimit_req_interval_secs`).
3. **Restrict bind address in production**: Default to `127.0.0.1` and require an explicit opt-in with a documented warning for `0.0.0.0`.
4. **Cap the pending queue**: Reject `insert_try_to_send` calls when the number of unprocessed entries exceeds a configurable limit, preventing unbounded DB growth.

### Proof of Concept

for i in $(seq 1 10000); do
  curl -s -X POST http://<TARGET_IP>:3030 \
    -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":$i,\"method\":\"send_tx\",\"params\":[{\"signed_tx_hex\":\"$FAKE_TX_HEX\",\"fee_paying_type\":\"CPFP\",\"cancel_outpoints\":[],\"cancel_txids\":[],\"activate_txids\":[],\"activate_outpoints\":[]}]}" &
done
wait
# Result: tx-sender loop calls rpc.send_to_address ~10000 times,
# draining the operator wallet; legitimate bridge txs can no longer be fee-bumped.

    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };
