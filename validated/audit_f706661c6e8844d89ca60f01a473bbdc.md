## Analysis

The Sherlock report's bug class is: a fee/amount that *should* be redistributed to a specific party is instead computed incorrectly (or lost to a shared pool) due to a broken calculation path, permanently denying that party funds they are entitled to. I found a direct structural analog in `mWOMSVBaseRewarder.sol`'s early-exit forfeiture logic.

### Title
Forfeiture calculation in `mWOMSVBaseRewarder` never applies cooldown penalty, permanently denying redistributed yield to loyal mWOMSV stakers - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is supposed to forfeit a portion of a withdrawing user's pending rewards proportional to how much of their `mWOMSV` balance is in cooldown/unlocking (mirroring the sibling `vlMGPBaseRewarder` implementation), and redistribute that forfeited portion to the remaining pool via `_queueNewRewardsWithoutTransfer`. In `mWOMSVBaseRewarder`, the call to the locker's `getRewardablePercentWAD` was omitted, so the forfeited amount is hard-coded to always be zero, meaning the redistribution to loyal stakers never happens.

### Finding Description
Compare the two sibling reward-forfeiture implementations:

`vlMGPBaseRewarder._calExpireForfeit` correctly queries the locker for the user's rewardable percentage based on lock/cooldown state: [1](#0-0) 

`mWOMSVBaseRewarder._calExpireForfeit` omits this query entirely, setting `rewardableAmount` unconditionally equal to the full `_amount`, so `forfeitAmount` is always `_amount - _amount == 0`: [2](#0-1) 

Yet `mWomSV.sol` does implement `getRewardablePercentWAD(address _user)`, which computes the correct rewardable percentage based on `getUserTotalLocked` vs. `getUserAmountInCoolDown`/unlock slot progress — proving the intended design requires this call: [3](#0-2) 

Because `_calExpireForfeit` never consults this percentage, `_sendReward` always sends 100% of `userRewards` to any withdrawing account regardless of cooldown state, and the forfeit-redistribution branch is dead code: [4](#0-3) 

This flow is reachable by any ordinary wallet: a user calls `getReward`/`getRewards` (routed through `MasterMagpie` as `onlyMasterMagpie`), which invokes `_sendReward` → `_calExpireForfeit`, and the forfeiture never fires no matter the account's actual unlocking status. [5](#0-4) 

### Impact Explanation
Under the intended design (mirrored correctly in `vlMGPBaseRewarder`), users who initiate `startUnlock`/are in cooldown should forfeit a portion of their accrued rewards, which is then queued back into the pool (`_queueNewRewardsWithoutTransfer`) and distributed pro-rata to remaining/loyal stakers as additional yield. Because the forfeit calculation is broken and always returns zero, that yield is never generated for loyal stakers — it is a **permanent loss of yield** that the protocol's own accounting model promises to honest, still-locked stakers. This matches the "theft or permanent freezing of unclaimed yield" category, analogous to the referenced report's unrecoverable `lossFee` that never reaches its intended recipient.

### Likelihood Explanation
High likelihood: this triggers on every single `getReward`/`getRewards` call by any mWOMSV staker who has ever used `startUnlock` (a normal, expected user action), with no special preconditions, privileged role, or attacker action required.

### Recommendation
Mirror `vlMGPBaseRewarder._calExpireForfeit`'s logic in `mWOMSVBaseRewarder._calExpireForfeit` by calling `mWOMSV.getRewardablePercentWAD(_account)` and scaling `_amount` by that percentage before computing `forfeitAmount`, so cooldown-based forfeiture and its redistribution to remaining stakers actually functions as intended.

### Proof of Concept
1. User A stakes mWOMSV and accrues pending rewards in `mWOMSVBaseRewarder`.
2. User A calls `mWomSV.startUnlock(amount)`, putting a portion of their balance into cooldown (per `mWomSV.sol` lines 247-277).
3. User A calls `getReward`/`getRewards` (via `MasterMagpie`) before the cooldown ends.
4. `_sendReward` → `_calExpireForfeit(_account, userRewards[...])` is invoked; because `rewardableAmount = _amount` unconditionally (line 386), `forfeitAmount` computed is `0` regardless of the user's cooldown percentage.
5. User A receives 100% of pending rewards despite being partially in cooldown, and `_queueNewRewardsWithoutTransfer` is never called with a nonzero forfeit — the yield that should have accrued to remaining locked stakers is permanently lost.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;

            IERC20(_rewardToken).safeTransfer(_receiver, toSend);

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
