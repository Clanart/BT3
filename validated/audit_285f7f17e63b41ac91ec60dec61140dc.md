Based on my investigation, I found a structurally direct analog to the Timelock bug: a destination-side privileged handler that authenticates a cross-chain governance message by **where it came from (chain id)** but never verifies **who sent it (module/account identity)** — the same class of incomplete authorization that let the Timelock's governor bootstrap unrestricted privilege.

### Title
HostManager and SimplexPaymaster `onAccept` authenticate governance messages only by source chain, never by sender identity - (File: `evm/src/core/HostManager.sol`, `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`HostManager.onAccept` and `SimplexPaymaster.onAccept` are the destination handlers for cross-chain governance actions (host-param updates, host revenue withdrawal, paymaster upgrades/withdrawals). Both check only that `request.source` equals the Hyperbridge chain id; neither validates `request.from` — the specific pallet/account on that chain that dispatched the message.

### Finding Description
`HostManager.onAccept` [1](#0-0)  gates execution with:
```solidity
if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
```
then dispatches to `IHostManager(_params.host).updateHostParams(hostParams)` or `.withdraw(withdrawParams)` based solely on the action byte — `request.from` is never inspected. The same pattern appears in `SimplexPaymaster.onAccept` [2](#0-1) , which checks only `keccak256(incoming.request.source) != keccak256(hyperbridge())` before allowing `UpgradeContract` (arbitrary ERC-1967 upgrade), `WithdrawAssets`, and parameter changes.

On the source side, `PostRequest.from` is fully caller-supplied: `pallet_ismp`'s `IsmpDispatcher::dispatch_request` copies `dispatch_post.from` verbatim into the outgoing `PostRequest` with no enforcement that it matches the calling pallet or account [3](#0-2) . The only production call sites I could confirm construct these governance messages under privileged origins — e.g. `host-executive`'s `update_host_params` requires `T::HostExecutiveOrigin::ensure_origin(origin)?` [4](#0-3) , and `intents-coprocessor`'s paymaster calls require `T::GovernanceOrigin::ensure_origin(origin)?` [5](#0-4) .

The exact parallel to the Timelock bug: Timelock's `setGovernor`/`setDelay` verified *who* called (`onlyRole(GOVERNOR_ROLE)`) but never that the call routed through the timelock's own delayed-execution path — letting the governor bypass the delay by first replacing the trusted identity, then using it. Here it's inverted but structurally identical: the destination trusts *where* a message came from (chain id) as a complete proxy for *who* is authorized, never checking the module/account identity (`from`) that the source-chain runtime is supposed to gate. Any current or future pallet wired into the Nexus/Hyperbridge runtime that can call `dispatch_request` with attacker-influenced `to`/`body` (even under a narrower, unrelated permission) can impersonate `host-executive` or the paymaster's governance origin at the destination, since nothing on the EVM side distinguishes "message from host-executive pallet" from "message from any other pallet/account on Hyperbridge chain."

### Impact Explanation
If any dispatch path lacking `HostExecutiveOrigin`/`GovernanceOrigin` gating (existing or introduced later) can route a `PostRequest` to a `HostManager` or `SimplexPaymaster` address with a crafted body, the caller obtains: rewriting `HostParams.admin`, `hostManager`, `consensusClient`, and `feeToken` to attacker-controlled addresses (full host takeover, including the ability to seed a forged consensus client and mint arbitrary "valid" future state commitments), draining bridge revenue via `withdraw`, or upgrading `SimplexPaymaster`'s implementation via `ERC1967Utils.upgradeToAndCall` to an arbitrary contract, and draining its treasury. This satisfies the bounty's "unauthorized execution / false state acceptance / fund loss" categories.

### Likelihood Explanation
I could not confirm, within this snapshot, a currently-deployed, permissionless (unprivileged-user) Nexus extrinsic that lets a caller freely control both the ISMP `to` address and `body` toward an arbitrary EVM contract — all production call sites I located are gated by privileged origins. The `pallet_example`/`demo` pallets that do let a plain `ensure_signed` user pick `to` (`dispatch_to_evm`) [6](#0-5)  appear to be documentation/demo code rather than mainnet Nexus runtime pallets, and fix the `body` to a hardcoded string, so they aren't directly weaponizable as-is. Given this, the finding is a real, provable **missing defense-in-depth check** at the destination (identity of sender is never validated, only chain-of-origin), rather than a proven end-to-end exploit against the current live configuration — likelihood is Medium, contingent on any future/side pallet or misrouted message gaining `dispatch_request` access with attacker-influenced `to`/`body`.

### Recommendation
Have `HostManager.onAccept` and `SimplexPaymaster.onAccept` also verify `request.from` against a stored, explicit expected sender identity (e.g., the `host-executive`/`intents-coprocessor` pallet id), analogous to how `BandwidthManager` validates `request.from` against a per-source registered manager address (per `docs/content/developers/evm/bandwidth/governance.mdx`). Do not rely on chain-id-only authentication (`request.source == hyperbridge()`) for any state-mutating governance action — bind both source chain and source module/account, mirroring the report's core fix of forcing all privileged mutation through one canonically-verified path rather than an identity that can be substituted mid-flow.

### Proof of Concept
Conceptual (destination-side gap, not a fully weaponized live path confirmed):
1. Any dispatcher on the Hyperbridge/Nexus chain capable of calling `pallet_ismp::dispatch_request` with `DispatchRequest::Post(DispatchPost { dest: StateMachine::Evm(chain), to: hostManagerAddress, from: <anything>, body: [1u8, abi.encode(HostParams{ admin: attacker, hostManager: attacker, consensusClient: attackerConsensus, ... }) ], .. })`.
2. Message arrives at destination `EvmHost`; relayer submits it; `HostManager.onAccept` is invoked with `msg.sender == host` (satisfied) and `request.source.equals(hyperbridge())` (satisfied, since it genuinely originated on the Hyperbridge chain) — `request.from` is never checked [1](#0-0) .
3. `updateHostParams` executes with attacker-supplied `admin`/`hostManager`/`consensusClient`, achieving full host takeover [7](#0-6) .

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) {
            revert UnauthorizedCall();
        }

        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        bytes calldata payload = incoming.request.body[1:];

        if (kind == RequestKind.UpgradeContract) {
            (address newImpl, bytes memory initData) = abi.decode(payload, (address, bytes));
            ERC1967Utils.upgradeToAndCall(newImpl, initData);
        } else if (kind == RequestKind.UpdateParams) {
            _setParams(abi.decode(payload, (Params)));
        } else if (kind == RequestKind.RegisterToken) {
            (address token, address oracle) = abi.decode(payload, (address, address));
            _registerToken(token, AggregatorV3Interface(oracle));
        } else if (kind == RequestKind.DeactivateToken) {
            _deactivateToken(abi.decode(payload, (address)));
        } else if (kind == RequestKind.WithdrawAssets) {
            (address token, uint256 amount) = abi.decode(payload, (address, uint256));
            _withdrawAssets(token, amount);
        }
    }

    /**
     * @dev Updates the HostParams. Will reset all fishermen accounts and initialize any new state machines.
     * @param params, the new host params.
     */
    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;

        // add whitelisted state machines
        for (uint256 i = 0; i < stateMachinesLen; ++i) {
            // create if it doesn't already exist
            if (_latestStateMachineHeight[params.stateMachines[i]] == 0) {
                _latestStateMachineHeight[params.stateMachines[i]] = 1;
            }
        }
    }
