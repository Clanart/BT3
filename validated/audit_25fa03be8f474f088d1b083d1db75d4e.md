Analog identified: `pallet-consensus-incentives`'s reward watermark is not reset when incentives for a state machine are turned off, so disabled/"killed" reward accrual silently continues via chain-height advancement and can be claimed in full, in one shot, by any permissionless relayer once governance re-enables the state machine.

### Title
Reward watermark not cleared on `remove_incentives` lets a relayer retroactively drain the treasury for the entire disabled period - (File: `modules/pallets/consensus-incentives/src/lib.rs`, `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` pays relayers `(latest_height - baseline) * cost_per_block` for advancing a state machine's consensus, where `baseline` comes from the `LastRewardedHeight` watermark [1](#0-0) . Governance can disable rewards for a state machine via `remove_incentives`, which only clears `StateMachinesCostPerBlock` and never touches `LastRewardedHeight` [2](#0-1) . Consensus updates for that state machine keep landing on Hyperbridge regardless (consensus message processing is unsigned/permissionless and independent of the incentive pallet), silently advancing `latest_commitment_height` with zero reward being calculated, since `process_message` short-circuits to `Ok(())` when `StateMachinesCostPerBlock` is `None` and never updates the watermark [3](#0-2) . This is structurally the same broken invariant as the killed gauge: an entity governance marked "should not accrue" keeps silently accruing "claimable" backlog (here, in the form of unpaid block span) instead of that backlog being zeroed or redirected when the kill/off switch is flipped.

### Finding Description
When `remove_incentives(state_machine_id)` is called, `StateMachinesCostPerBlock` is removed but `LastRewardedHeight` for that chain is left untouched [2](#0-1) . While disabled, the chain's `latest_commitment_height` keeps advancing through ordinary (unsigned, permissionless) consensus message submission via `pallet-ismp`, completely independent of this pallet — the reward pallet is just a `FeeHandler` hook that gets called with zero effect because of the early return in `process_message` [4](#0-3) .

When governance later re-enables the state machine with `update_cost_per_block`, the next `on_executed` call computes:
```
baseline = LastRewardedHeight::get(state_machine_id).unwrap_or(previous_height)  // stale, pre-disable value
blocks   = latest_height - baseline                                              // spans the entire disabled window
reward   = blocks * new_cost_per_block
``` [5](#0-4) 

The full backlog of blocks that accrued while rewards were explicitly turned off gets paid out in one lump sum to whichever relayer happens to submit the first consensus proof after re-enable — an unprivileged action requiring no special permission, just monitoring `StateMachineCostPerBlockUpdated`/`StateMachinesCostPerBlock` events and firing off any valid consensus proof for that chain. There is no `NoRewardConfigured`-style all-or-nothing block on this path (unlike the `OutboundRequestDeliveryReward`/`OutboundConsensusDeliveryReward` allowlist checks elsewhere in the relayer pallet, which reject a claim entirely rather than silently accruing towards it) [6](#0-5) .

### Impact Explanation
This is a direct, unauthorized loss of treasury funds: the payout amount is not bounded by the actual incentivized work performed during the enabled window, but by the entire elapsed block span since the last time rewards were active, multiplied by whatever `cost_per_block` governance sets on re-enable. Governance intended `remove_incentives` to stop payouts for that chain; instead it merely pauses the *payment* while the *liability* (unpaid block-span) keeps growing invisibly, then dumps onto a single opportunistic relayer. This directly mirrors the killed-gauge primitive: a disabled/"killed" entity is supposed to stop accruing value, but the accounting invariant (`baseline`/watermark) isn't reset on disable, so it accrues anyway and gets swept out in one shot by whoever calls the permissionless trigger first.

### Likelihood Explanation
Any relayer can observe `StateMachineCostPerBlockUpdated`/`remove_incentives`/`update_cost_per_block` events on-chain (all are ordinary extrinsic events, no special access needed) and simply be the first to submit a consensus proof for the reactivated state machine — a wholly permissionless action already part of normal relayer operation. No malicious peer, prover, or admin collusion is required; the disabled → re-enabled sequence is a normal governance lifecycle (e.g., temporarily pausing a misbehaving/expensive consensus client) that this codebase explicitly supports via `remove_incentives`.

### Recommendation
When `remove_incentives` clears `StateMachinesCostPerBlock` for a state machine, also advance/reset `LastRewardedHeight` to the state machine's current `latest_commitment_height` (or otherwise mark the intervening span as non-rewardable), mirroring the gauge fix of not letting a disabled entity keep accruing claimable value. Symmetrically, `update_cost_per_block` (or a companion call) should re-baseline the watermark to the height at the time incentives resume, so only work performed *after* re-enable is ever rewarded.

### Proof of Concept
1. Governance calls `update_cost_per_block(chain, 100)`; a relayer submits proofs normally, `LastRewardedHeight[chain]` tracks along, as in `test_incentivize_relayer` [7](#0-6) .
2. Governance calls `remove_incentives(chain)` — `StateMachinesCostPerBlock` is cleared, `LastRewardedHeight` stays at its last value (say height 1000) [2](#0-1) .
3. Over the next weeks, ordinary consensus messages keep landing on Hyperbridge for `chain` (independent of this pallet), advancing `latest_commitment_height` to, say, 100000. `process_message` runs on each but no-ops and doesn't touch the watermark, since `StateMachinesCostPerBlock` is `None` [4](#0-3) .
4. Governance re-enables with `update_cost_per_block(chain, 100)`, intending to resume incentivizing only *future* relaying.
5. Any relayer (no special role) submits the next consensus proof; `calculate_reward` computes `blocks = 100000 - 1000 = 99000`, paying `99000 * 100` from the treasury to that single relayer in one extrinsic, for a span where relaying was explicitly unincentivized [8](#0-7) .

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
