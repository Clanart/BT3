### Title
Attacker-controlled threshold size causes quadratic Lagrange deserialization DoS - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
`ThresholdKeys::read` accepts attacker-controlled `t`/`n` values and then performs Lagrange group-key reconstruction with `O(t²)` scalar operations, allowing a small serialized key to consume billions of field multiplications.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, and `i` directly from the input, reads the selected interpolation mode, and then reads `n` verification shares before constructing `ThresholdKeys`. [1](#0-0) [2](#0-1)  Both `t` and `n` are `u16` values, so an input can request up to 65,535 participants without an earlier practical resource limit. [3](#0-2) 

During construction, Serai evaluates one Lagrange interpolation factor for each participant `1..=t`. [4](#0-3)  Each `interpolation_factor` call iterates over the complete participant list and performs field multiplications plus a field inversion. [5](#0-4)  Consequently, deserializing a Lagrange-encoded `ThresholdKeys` with `t = n = 65,535` performs approximately `65,535²` field multiplications—over 4.29 billion—during a single `ThresholdKeys::read` call.

### Impact Explanation
An attacker only needs to provide roughly 2 MiB of valid-looking encodings to trigger this workload because the serialized form contains one scalar and one point per participant. [6](#0-5)  The payload does not need malformed scalars or points: canonical encodings are accepted by `read_F` and `read_G`. [7](#0-6) [8](#0-7)  This is a remotely reachable CPU-exhaustion primitive wherever attacker-supplied key material is deserialized through `ThresholdKeys::read`.

### Likelihood Explanation
The trigger is deterministic and requires no race, malformed transaction, secret information, or repeated requests. [9](#0-8)  Real-world exploitability depends on whether a surrounding deployment accepts serialized threshold keys and imposes a smaller participant bound, but the in-scope implementation itself permits the maximum `u16` size and performs the quadratic work unconditionally.

### Recommendation
Validate `t <= n`, `t != 0`, `n != 0`, and a deployment-specific maximum before reading participant-dependent fields. Calculate all Lagrange coefficients in `O(t)` using shared numerator/denominator prefix products rather than recomputing each coefficient independently. Apply the same optimization to `ThresholdKeys::view`, which currently calls `interpolation_factor` once for every included participant and therefore has the same quadratic structure. [10](#0-9) 

### Proof of Concept
```rust
use ciphersuite::{
  Ciphersuite,
  group::{ff::PrimeField, Group, GroupEncoding},
};
use dkg::ThresholdKeys;

fn deserialize_quadratic_threshold_keys<C: Ciphersuite>() {
    let n = u16::MAX;
    let mut encoded = Vec::new();

    // Curve identifier.
    encoded.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
    encoded.extend(C::ID);

    // t = n = i = 65535.
    encoded.extend(n.to_le_bytes());
    encoded.extend(n.to_le_bytes());
    encoded.extend(n.to_le_bytes());

    // Interpolation::Lagrange.
    encoded.push(1);

    // secret_share = 1.
    encoded.extend(C::F::ONE.to_repr().as_ref());

    // n canonical verification shares, each equal to the generator.
    let generator = C::generator().to_bytes();
    for _ in 0 .. n {
        encoded.extend(generator.as_ref());
    }

    // Performs ~4.29 billion field multiplications during group-key derivation.
    let _ = ThresholdKeys::<C>::read(&mut encoded.as_slice());
}
```

  fn interpolation_factor(&self, i: Participant, included: &[Participant]) -> F {
    match self {
      Interpolation::Constant(c) => c[usize::from(u16::from(i) - 1)],
      Interpolation::Lagrange => {
        let i_f = F::from(u64::from(u16::from(i)));

        let mut num = F::ONE;
        let mut denom = F::ONE;
        for l in included {
          if i == *l {
            continue;
          }

          let share = F::from(u64::from(u16::from(*l)));
          num *= share;
          denom *= share - i_f;
        }

        // Safe as this will only be 0 if we're part of the above loop
        // (which we have an if case to avoid)
        num * denom.invert().unwrap()
