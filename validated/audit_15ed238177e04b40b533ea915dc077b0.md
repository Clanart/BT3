### Title
Forged `ReceivedOutput` deserializes nonexistent UTXOs as spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts a serialized Taproot output, scalar offset, and outpoint without authenticating that the outpoint exists or contains the represented `TxOut`. A forged object can therefore be reported as received and carried into Bitcoin transaction construction, but the signed transaction is unspendable because its input references a nonexistent or unrelated UTXO. [1](#0-0) 

### Finding Description
`ReceivedOutput::read` deserializes `offset`, `output`, and `outpoint` purely from caller-controlled bytes and returns the object without provenance or consistency validation. [2](#0-1)  Its balance is directly derived from the embedded `TxOut` through `ReceivedOutput::value`. [3](#0-2) 

The legitimate scanner creates this object only after matching a transaction output's script and derives the outpoint from the actual transaction, so the attack is specific to deserializing untrusted persisted or transported `ReceivedOutput` values. [4](#0-3) 

Later, `SignableTransaction::multisig` validates only that the claimed script is produced by the key plus stored offset; it does not validate that `outpoint` exists or contains that script and value. [5](#0-4)  Transaction signing then commits to the attacker-supplied `prevouts` and produces witnesses for the fabricated inputs. [6](#0-5) [7](#0-6) 

### Impact Explanation
An attacker who can feed crafted bytes to `ReceivedOutput::read` can make an integration report or queue funds that are not actually spendable. The forged deposit can carry an arbitrary confirmed-looking amount and a valid Serai-controlled script, while its outpoint references no UTXO. Subsequent threshold signing may succeed, but Bitcoin consensus will reject the resulting transaction because the input does not reference the claimed output. [8](#0-7) [5](#0-4) 

### Likelihood Explanation
This requires an input path where serialized `ReceivedOutput` values are attacker-controlled rather than exclusively produced by `Scanner::scan_transaction` or `Scanner::scan_block`. In that path, exploitation only requires supplying the byte representation of a valid offset, a syntactically valid `TxOut`, and a fabricated `OutPoint`; no cryptographic break or validator privilege is needed. [1](#0-0) [4](#0-3) 

### Recommendation
Treat serialized `ReceivedOutput` values as untrusted claims rather than authenticated observations. Before accounting or scheduling them, verify the outpoint exists in a confirmed transaction and that the on-chain `TxOut` exactly equals the embedded `output`; alternatively, authenticate or integrity-protect scanner-produced records so deserialized objects cannot be replaced by forged claims. [1](#0-0) [5](#0-4) 

### Proof of Concept
1. Obtain a legitimate `ReceivedOutput` for a Serai Taproot key and call `serialize`.
2. Preserve the leading scalar offset and `TxOut`, but replace the trailing consensus-encoded `OutPoint` with `OutPoint::new(Txid::from_slice(&[0; 32]).unwrap(), 0)` or any other nonexistent UTXO.
3. Pass the resulting bytes to `ReceivedOutput::read`; the forged object is accepted because the parser does not authenticate the claimed outpoint. [2](#0-1) 
4. Call `SignableTransaction::new` with the forged output; it uses the fake outpoint as a transaction input. [8](#0-7) 
5. Call `multisig`; it succeeds when the copied script still matches the key and stored offset, without checking the outpoint's on-chain contents. [5](#0-4) 
6. Complete signing; the generated transaction is signed but unspendable because its input references a nonexistent prevout. [7](#0-6)

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
