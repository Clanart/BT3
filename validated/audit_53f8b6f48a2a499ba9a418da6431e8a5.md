Debug-mode JSON↔binary conversion logging bypasses `debug_redact` field annotations, leaking sensitive proto field values - ([File: src/google/protobuf/json/internal/parser.cc], [File: src/google/protobuf/json/internal/unparser.cc])

### Summary
Protobuf's debug-logging opt-in (`PROTOBUF_ENABLE_DEBUG_LOGGING_MAY_LEAK_PII`) is intended to log message contents for troubleshooting while still respecting the schema-level `debug_redact` field option, which is the mechanism protobuf provides to mark fields (e.g. secrets/PII) as unsafe to reveal in debug output. In `JsonStreamToMessage` / `MessageToJsonStream` the debug log correctly routes through `Message::DebugString()`, which honors `debug_redact` and prints `[REDACTED]` for sensitive fields. However, in the byte-stream conversion entry points `JsonToBinaryStream` and `BinaryToJsonStream`, the same debug flag instead dumps the **raw hex-encoded bytes** of the JSON/binary payload (`absl::CHexEscape(copy)` / `absl::BytesToHexString(out)`), completely bypassing the redaction logic. This is directly analogous to the Cilium advisory: an explicit "debug mode" toggle that is documented as safe/opt-in nonetheless leaks confidential values (there: HTTP header/secret contents matching policy; here: field values annotated `debug_redact = true`, such as tokens or credentials carried in a proto message) because one code path enforces the intended safety control while a sibling path silently omits it.

### Finding Description
Protobuf defines a real, schema-driven redaction mechanism: `FieldOptions.debug_redact` [1](#0-0) , consumed by `TextFormat::Printer::TryRedactFieldValue`/`GetRedactionState` to replace sensitive field values with `[REDACTED]` in `DebugString()` output [2](#0-1) , and `internal::StringifyMessage` sets `SetRedactDebugString(true)` for the standard `Message::DebugString()` used by application logging [3](#0-2) .

The debug-logging flag `PROTOBUF_ENABLE_DEBUG_LOGGING_MAY_LEAK_PII` gates a compile-time constant `PROTOBUF_DEBUG` [4](#0-3) . Two of the four call sites that check this flag correctly route through the redacting `DebugString()`:
- `JsonStreamToMessage`: `ABSL_DLOG(INFO) << "json2/output: " << message->DebugString();` [5](#0-4) 
- `MessageToJsonStream`: `ABSL_DLOG(INFO) << "json2/input: " << message.DebugString();` [6](#0-5) 

But `JsonToBinaryStream` and `BinaryToJsonStream` — the entry points used to convert between wire-format binary and JSON via a `TypeResolver` (e.g. for Any/gRPC-transcoding style use cases) — capture and log the **raw serialized bytes** instead of a `Message` object, so no redaction pass ever runs:
- Input capture: `ABSL_DLOG(INFO) << "json2/input: " << absl::CHexEscape(copy);` [7](#0-6) 
- Output capture: `ABSL_DLOG(INFO) << "json2/output: " << absl::BytesToHexString(out);` [8](#0-7) 
- Symmetric raw-byte logging in `BinaryToJsonStream`: [9](#0-8) 

In these two functions, a `Message`/`UntypedMessage` is only constructed internally to perform the conversion (`Msg<ParseProto3Type>`, `UntypedMessage::ParseFromStream`), but the logged bytes are taken from the tee'd raw stream (`copy`, `out`), never from a redaction-aware `DebugString()`. Any field carrying `[FieldOptions.debug_redact = true]` — the exact annotation designed to prevent this class of exposure — is emitted in full, byte-for-byte, in the debug log.

### Impact Explanation
This matches the Cilium bug class precisely: an explicit, named "debug mode" that a consuming application may enable in production for troubleshooting (the flag is literally named `..._MAY_LEAK_PII`, acknowledging the risk) nonetheless bypasses the library's own safety control for a subset of its APIs. Any application using `JsonToBinaryStream`/`BinaryToJsonStream` (common in gRPC-JSON transcoding and `google.protobuf.Any`/TypeResolver based services) with debug logging enabled will have secrets/PII fields marked `debug_redact` written verbatim (hex-encoded) into logs, which are often aggregated in less-trusted logging infrastructure than the raw traffic itself — the same disclosure vector CVE-2023-29002 described for Cilium's debug logs. Confidentiality impact is high for affected fields; there is no integrity or availability impact. Given the CWE-532 nature and asymmetry with the neighboring functions that do redact correctly, this is a genuine, reachable High-severity logic flaw in the library's own defense-in-depth mechanism, not merely an "expected" outcome of enabling verbose debug logging.

### Likelihood Explanation
Requires: (1) the library built/run with `PROTOBUF_ENABLE_DEBUG_LOGGING_MAY_LEAK_PII` (an explicit, non-default opt-in — lowering likelihood somewhat), and (2) use of `JsonToBinaryStream`/`BinaryToJsonStream` on messages containing `debug_redact`-annotated fields. This is a realistic combination for services that use `google.protobuf.util::TypeResolver`-based JSON transcoding (e.g., gRPC gateways) and enable debug logging for troubleshooting, exactly mirroring Cilium's scenario where "debug mode" is a documented, occasionally-enabled operational toggle rather than a default posture.

### Recommendation
Route the debug-log output in `JsonToBinaryStream` and `BinaryToJsonStream` through the redacting `DebugString()`-equivalent path instead of emitting raw hex bytes of the wire payload — e.g., decode into a fully-typed `Message`/`UntypedMessage` and log its `DebugString()` (respecting `debug_redact`), or apply the same `TextFormat::Printer` redaction logic to any diagnostic dump of these payloads. At minimum, document prominently that `JsonToBinaryStream`/`BinaryToJsonStream` debug logging does not honor `debug_redact` and should not be enabled for schemas containing sensitive annotated fields.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}
