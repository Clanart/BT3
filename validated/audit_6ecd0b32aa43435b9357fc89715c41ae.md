## Title
Operator payer-attribution for reimbursement is read from an unsigned OP_RETURN, letting any Bitcoin broadcaster credit reimbursement to an operator that never funded the payout - ([File: core/src/builder/transaction/operator_reimburse.rs])

## Summary
The `payout_tx`'s operator-attribution output (OP_RETURN containing `operator_xonly_pk`) is not covered by the withdrawer's `SinglePlusAnyoneCanPay` signature, so anyone who can broadcast a Bitcoin transaction using that signature can attach an arbitrary operator's x-only public key to the payout. The verifier's on-chain scanner (`update_finalized_payouts`) blindly trusts that OP_RETURN value as "who fronted this payout," so a targeted honest operator's automation will subsequently walk the presigned kickoff/round/reimburse graph and collect the deposit's vault funds for a payout it never funded.

## Finding Description
The binding the reimbursement flow depends on is:

`payout_payer_operator_xonly_pk` (DB, set from on-chain OP_RETURN bytes) == the operator that actually funded/broadcast the payout to the user.

This binding is never actually enforced.

`create_payout_txhandler` builds the payout tx with 3 outputs: user payout (index 0), anchor (index 1), and the OP_RETURN carrying `operator_xonly_pk` (index 2). The user's signature is created and verified with `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) , which per BIP341 only commits to the input at index 0 and the *single* output at the same index (output 0). Outputs 1 and 2 — including the OP_RETURN that names the "fronting" operator — are entirely outside the signed message [2](#0-1) .

`Operator::withdraw` enforces this sighash type and, using only the user-supplied signature/outpoint, verifies the Schnorr signature against `sighash_txin(0, ...)` — it never checks or signs anything about outputs 1/2 [3](#0-2) . Consequently, anyone possessing the withdrawer's `(withdrawal_utxo, in_signature)` pair — which per the threat model the attacker chooses directly when calling Citrea's `withdraw()` — can independently construct and broadcast their own valid `payout_tx` using that signature, fund the additional value needed for output 0 themselves, and set the OP_RETURN to any operator's `xonly_pk` they like, without any operator's cooperation.

Once this transaction confirms, `Verifier::update_finalized_payouts` reads the OP_RETURN with `parse_op_return_data`/`get_first_op_return_output` and stores whatever pubkey is present as `payout_payer_operator_xonly_pk`, with zero cryptographic check that this operator actually broadcast or funded anything [4](#0-3) . The targeted operator's own automation (`validate_payer_is_operator` / `handle_finalized_payout` / `get_reimbursement_txs`) trusts this DB value unconditionally: if `payer_xonly_pk == self.signer.xonly_public_key`, it proceeds to kickoff and eventually reimburse itself [5](#0-4) . The verifier-side fraud check `is_kickoff_malicious` only compares the OP_RETURN-derived operator against `kickoff_data.operator_xonly_pk` — both values ultimately trace back to the same forgeable OP_RETURN, so this "guard" is a tautology and does not detect the forgery [6](#0-5) .

## Impact Explanation
The targeted operator, having never spent its own funds to front the withdrawal, walks the full kickoff → challenge-timeout → round → reimburse presigned tx graph and collects `bridge_amount` from that deposit's `MoveToVault` UTXO via the `Reimburse` tx [7](#0-6) . Since the attacker can self-fund output 0 (which pays back to an address of their own choosing per their own signed intent) using their own capital, the "fronting" cost is effectively zero for the attacker while the arbitrarily-chosen operator receives a real, uncontested payout from the bridge vault it never earned. This is a direct instance of "an operator reimbursed for a payout it never funded" (Critical), moving bridge value out of a deposit's `MoveToVault` UTXO to the wrong party, and is repeatable once per withdrawal/deposit against any operator whose x-only public key is publicly known (all operator keys are public protocol data).

## Likelihood Explanation
No special privileges are required beyond what is explicitly granted to the unprivileged attacker: the ability to call Citrea's `withdraw()` choosing the UTXO/signature/sighash flag, and the ability to broadcast a raw Bitcoin transaction. No verifier, aggregator, or operator collusion, key compromise, or majority hashrate is needed. The only cost is normal Bitcoin transaction fees and the capital momentarily used to fund output 0 (which returns to the attacker's own chosen destination). This is fully deterministic and reproducible on regtest with no mainnet or live Citrea dependency, since the sighash-coverage gap is intrinsic to BIP341 `SIGHASH_SINGLE|ANYONECANPAY` semantics applied to a 3-output transaction.

## Recommendation
Do not use an unsigned OP_RETURN as the sole source of truth for reimbursement attribution. Either (a) have the withdrawer's signature cover the OP_RETURN output (e.g., switch to `SIGHASH_ALL|ANYONECANPAY` and require operator to be the only one able to fully construct/fund the transaction before the user co-signs, or move the operator identity into a value the user's signature commits to), or (b) require an operator-signed commitment (e.g., an operator Schnorr signature over the specific payout txid/outpoint) as the source of payer attribution instead of trusting arbitrary on-chain OP_RETURN bytes.

## Proof of Concept
`cargo test` plan (regtest, no mainnet/live Citrea, using existing test harness in `core/src/test/common`):
1. Set up a deposit and two operators, O (honest, intended payer) and V (victim, never intends to pay).
2. Use `generate_withdrawal_transaction_and_signature`-style helper to obtain `(withdrawal_utxo, output_txout, user_sig)` with `TapSighashType::SinglePlusAnyoneCanPay`, exactly as a withdrawer would produce for Citrea's `withdraw()`.
3. Instead of calling operator O's `withdraw` RPC, directly build a payout tx via `create_payout_txhandler(input_utxo, output_txout, V.xonly_pk, user_sig, network)` from the test, fund the extra required input from a test-controlled wallet (simulating the attacker), and broadcast it via `rpc.send_raw_transaction`.
4. Mine blocks, run the verifier's Citrea/BTC sync so `update_finalized_payouts` processes the block; assert `db.get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id` returns `V.xonly_pk` even though V never called `withdraw`.
5. Assert on both sides of the binding: `payout_payer_operator_xonly_pk == V.xonly_pk` (DB) vs. "operator that funded the extra input" == attacker/test wallet, not V — showing the mismatch.
6. Drive V's automation via `get_reimbursement_txs`/kickoff flow and assert the `Reimburse` tx eventually pays V's `operator_reimbursement_address` the `bridge_amount`, confirming BTC left the deposit's `MoveToVault` UTXO to V without V ever broadcasting or funding the payout.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
