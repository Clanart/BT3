## Title
Unauthenticated `shop=` parameter grants access to victim shop's API session via `EnsureInstalled` (legacy non-embedded auth path) - (File: `app/controllers/concerns/shopify_app/ensure_installed.rb`)

## Summary
When `use_new_embedded_auth_strategy?` is false, `ShopifyApp::EnsureInstalled` authorizes and executes actions based solely on the `shop` query parameter, with no verification that the request actually originated from Shopify Admin (no HMAC, no session token, no signed embedded params). This lets any unauthenticated client set `shop=<victim-shop>` and have the controller action run with `installed_shop_session`/`@shop` bound to the victim's stored offline session, using the victim's access token for any Shopify API calls the action performs.

## Finding Description
The `included do` block wires up, for the legacy (non-`use_new_embedded_auth_strategy?`) path:

```ruby
before_action :check_shop_domain
before_action :check_shop_known
before_action :validate_non_embedded_session
``` [1](#0-0) 

- `check_shop_domain` only requires that `params[:shop]` be present and pass `sanitize_shop_domain` — it does not check any cookie, session, HMAC, or signed token: [2](#0-1) 
- `check_shop_known` looks up `installed_shop_session` (i.e., `SessionRepository.retrieve_shop_session_by_shopify_domain(current_shopify_domain)`) purely from the sanitized `shop` param and, if found, lets the request proceed with `@shop` set to that session — no ownership/session-binding check tying the request to that specific shop is performed: [3](#0-2) 
- `validate_non_embedded_session` then makes a live Shopify Admin API call using that session's offline access token, and only redirects to re-auth if Shopify itself returns a 401 (i.e., token revoked) — otherwise it silently succeeds and the request proceeds through the rest of the filter chain and into the controller action, which can now use `@shop`/`installed_shop_session` (bound to the victim's access token) to serve API-backed data in the response: [4](#0-3) 

The only bypass condition is `loaded_directly_from_admin?`, which just checks `params[:embedded] == "1"` combined with `embedded_app?` config — also attacker-controllable and not cryptographically verified: [5](#0-4) 

None of `check_shop_domain`, `check_shop_known`, or `validate_non_embedded_session` verify an HMAC, a Shopify-issued session token/JWT, or any cookie/session value that ties the request to the browser session that actually completed OAuth for that shop. The test suite confirms this design explicitly: a bare `get :index, params: { shop: shopify_domain }` with a stubbed installed session returns `:ok` and drives a real `ShopifyAPI::Clients::Rest::Admin` call bound to that session, with no other credential supplied: [6](#0-5) 

## Impact Explanation
Any unauthenticated attacker who knows (or guesses) a target's `*.myshopify.com` domain — public/non-secret information — can invoke any action protected only by `EnsureInstalled` (legacy mode) with `?shop=victim-shop.myshopify.com` and have the action execute using the victim's offline access token via `installed_shop_session`. If the action returns shop/order/customer data or performs a mutating API call, this constitutes cross-shop session confusion / authorization bypass, exposing another merchant's data or allowing actions to be performed using their access token without any proof of authenticated origin. This matches Shopify's "Broken Authentication" / "Authorization bypass allowing access to another shop's data" impact class.

## Likelihood Explanation
Feasible and fully reproducible: it requires only (1) the app to be configured without `use_new_embedded_auth_strategy?`, (2) a controller including `EnsureInstalled` (no other session-token check), and (3) a previously installed victim shop — all realistic/common conditions for legacy `shopify_app` gem integrations. No secrets, tokens, or insider access are needed; the shop domain is guessable/public. It is repeatable on demand since it depends only on the query parameter.

## Recommendation
For the non-embedded path, do not treat `params[:shop]` matching an existing `SessionRepository` entry as proof of request authenticity. Require a verified Shopify session token (JWT) or signed/HMAC-validated request (as done for embedded/token-exchange flows) before binding `installed_shop_session` and making API calls, or bind the session via a server-set, signed cookie established only after a genuine OAuth/login flow, rather than relying purely on the `shop` query string.

## Proof of Concept
Reusing the existing test controller pattern (`test/controllers/concerns/ensure_installed_test.rb`):
```ruby
test "poc: unauthenticated shop param drives API call with victim's session" do
  victim_session = mock
  ShopifyApp::SessionRepository.stubs(:retrieve_shop_session_by_shopify_domain).returns(victim_session)

  client = mock
  ShopifyAPI::Clients::Rest::Admin.expects(:new).with(session: victim_session).returns(client)
  client.expects(:get).with(path: "shop")

  # No HMAC, no session token, no cookie - only the shop param
  get :index, params: { shop: "victim-shop.myshopify.com" }

  assert_response :ok # action executed using victim's session/access token
end
```
This is functionally identical to the existing "returns :ok if the shop is installed" test at [6](#0-5) , demonstrating that the controller action reaches success (and would render any API-backed content) using only an unauthenticated `shop` parameter.

    def current_shopify_domain
      if params[:shop].blank?
        ShopifyApp::Logger.info("Could not identify installed store from current_shopify_domain")
        return
      end

      @shopify_domain ||= ShopifyApp::Utils.sanitize_shop_domain(params[:shop])
      ShopifyApp::Logger.info("Installed store:  #{@shopify_domain} - deduced from Shopify Admin params")
      @shopify_domain
    end

    def installed_shop_session
      @installed_shop_session ||= SessionRepository.retrieve_shop_session_by_shopify_domain(current_shopify_domain)
    end

    private

    def check_shop_domain
      redirect_to(ShopifyApp.configuration.login_url) unless current_shopify_domain
    end

    def check_shop_known
      @shop = installed_shop_session
      unless @shop
        if embedded_param?
          redirect_for_embedded
        else
          redirect_to(shop_login)
        end
      end
    end

    def validate_non_embedded_session
      return if loaded_directly_from_admin?

      client = ShopifyAPI::Clients::Rest::Admin.new(session: installed_shop_session)
      client.get(path: "shop")
    rescue ShopifyAPI::Errors::HttpResponseError => error
      ShopifyApp::Logger.info("Shop offline session no longer valid. Redirecting to OAuth install")
      redirect_to(shop_login) if error.code == 401
      raise error if error.code != 401
    end
