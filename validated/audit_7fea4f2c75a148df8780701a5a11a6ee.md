### Title
Unbounded native-stack recursion in `AccountKeyRoleBased.DecodeRLP` allows a single crafted transaction/RPC call to crash the node (fatal stack overflow) - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
The RLP decoder for `AccountKeyRoleBased` recursively re-invokes the whole `AccountKeySerializer`/`AccountKeyRoleBased` decode chain for every embedded key with no depth limit. The only safeguard against nested role-based keys (`CheckInstallable`/`CheckUpdatable`'s `IsCompositeType` check) runs *after* decoding completes, so an attacker can submit deeply nested role-based keys that exhaust the Go goroutine stack during decode itself, causing a fatal, unrecoverable `SIGABRT` (Go's runtime treats stack overflow as fatal, not a normal panic) — the same bug class as the referenced RaTeX advisory (CWE-400/CWE-674).

### Finding Description
`AccountKeyRoleBased.DecodeRLP` reads a list of raw byte blobs and, for each blob, calls `rlp.DecodeBytes` into a fresh `AccountKeySerializer`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` in turn constructs the concrete key via `NewAccountKey(keyType)` and decodes into it: [2](#0-1) 

If `keyType` is again `AccountKeyTypeRoleBased`, this loop repeats: each nesting level is native Go call-stack recursion (`AccountKeyRoleBased.DecodeRLP` → `rlp.DecodeBytes` → `AccountKeySerializer.DecodeRLP` → `AccountKeyRoleBased.DecodeRLP` → ...). There is no depth counter anywhere in this chain.

The only protection against nested/composite role-based keys is `IsCompositeType()`/`CheckInstallable`/`CheckUpdatable`, which are checked **after** the object has already been fully decoded: [3](#0-2) 

Because the check happens post-decode, it cannot prevent the stack overflow that occurs while decoding the nested structure. This decode path is reached from two unprivileged, single-request entry points:

1. Any transaction that carries an `AccountKey` field — `TxTypeAccountUpdate`, `TxTypeFeeDelegatedAccountUpdate`, `TxTypeFeeDelegatedAccountUpdateWithRatio`, etc. — goes through `Transaction.DecodeRLP` → `TxInternalDataSerializer.DecodeRLP` → the specific tx's `DecodeRLP`, e.g.: [4](#0-3) 
which decodes the `Key` field through the same `AccountKeySerializer`/`AccountKeyRoleBased` chain, executed during tx-pool admission and block execution, long before `CheckInstallable`/`CheckUpdatable` validation runs.

2. The public JSON-RPC method `kaia_decodeAccountKey`, which takes arbitrary attacker-supplied bytes and decodes them directly with no size or depth limiting: [5](#0-4) 

### Impact Explanation
A single unauthenticated RPC call (`kaia_decodeAccountKey`) or a single submitted `TxType*AccountUpdate*` transaction containing a deeply-nested, RLP-encoded `AccountKeyRoleBased` value can overflow the goroutine stack during decode. Because Go stack overflows are fatal runtime errors (`fatal error: stack overflow`) that cannot be recovered by `defer/recover`, this crashes the entire node process — a reliable, unauthenticated denial-of-service against any Kaia node/validator/RPC endpoint that decodes the malicious blob (e.g., during tx-pool admission, block re-execution by all nodes, or answering the RPC call). This matches the allowed "AccountKey authorization" and "pool admission" categories and causes state-divergence risk if only some nodes crash while others don't process the block in time.

### Likelihood Explanation
High. The attack requires no special privileges, gas payment beyond a normal transaction (if going through tx submission) or literally none (via the RPC call), no prior account state, and no cooperation from other actors. Constructing the payload is mechanical: repeatedly wrap an `AccountKeySerializer` (`[keyType, key]`) whose `key` is itself an RLP-encoded `[][]byte` list containing another wrapped serializer, then RLP-encode the outer bytes as the `Key` field of an account-update transaction or feed it directly to `kaia_decodeAccountKey`.

### Recommendation
Add an explicit recursion/nesting-depth parameter threaded through `AccountKeySerializer.DecodeRLP` and `AccountKeyRoleBased.DecodeRLP` (e.g., reject any `AccountKeyTypeRoleBased` found while already decoding inside another `AccountKeyRoleBased`, mirroring the existing `IsCompositeType` semantics but enforced *during* decode, not after). Alternatively, cap the total number of decode recursions library-wide (similar to a `recursion_limit` in recursive-descent parsers) and return a decode error once exceeded instead of allowing native stack growth to remain unbounded.

### Proof of Concept
Conceptually (pseudo-Go), build nested `AccountKeySerializer` blobs N levels deep:
```
inner = RLP([keyTypeNil, keyPublicOrWhatever])
for i in range(N):        // N large enough to exceed default goroutine stack (e.g. > 50k-100k levels)
    role_list = RLP([inner])              // AccountKeyRoleBased.EncodeRLP format: [][]byte
    inner = RLP([keyTypeRoleBased, role_list])
```
Submit `inner` either as:
- the `Key` field of a `TxTypeFeeDelegatedAccountUpdate` transaction sent via `sendRawTransaction`, or
- directly as the argument to the `kaia_decodeAccountKey` RPC call.

Decoding this input drives `AccountKeyRoleBased.DecodeRLP` → `rlp.DecodeBytes` → `AccountKeySerializer.DecodeRLP` recursion N levels deep with no limit check, exhausting the goroutine stack and aborting the process with `fatal error: stack overflow` before `CheckInstallable`/`CheckUpdatable` ever executes.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (serializer *AccountKeySerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.keyType); err != nil {
		return err
	}

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.key)
}
