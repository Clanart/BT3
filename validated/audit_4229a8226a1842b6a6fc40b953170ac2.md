### Title
Unhandled division by zero in `DelegateVoteRewardPool._updateVote()` can permanently freeze all voting/staking on the delegate pool - ([File: rewards/DelegateVoteRewardPool.sol])

### Summary
`DelegateVoteRewardPool._updateVote()` divides by `totalWeight` with no zero-denominator check, unlike the equivalent computation in `WombatBribeManager.castVotes()` which explicitly guards with `if (totalVlMgpInVote != 0)`. Any ordinary user voting for the delegated pool through `WombatBribeManager.vote()`/`unvote()` triggers this unguarded division, and if `totalWeight == 0` while `votePools` is non-empty, every such call reverts, freezing staking, withdrawal, and reward-claim flows for the delegate pool.

### Finding Description
`_updateVote()` computes, for every pool in `votePools`: [1](#0-0) 
```
uint256 targetVote = (votingWeights[pool] * totalSupply) / totalWeight;
```
There is no check that `totalWeight != 0` before this division, unlike the WombatBribeManager's own analogous vote-casting logic which explicitly guards the same class of computation: [2](#0-1) 

`totalWeight` and `votePools` are populated solely by the owner-only `updateWeight`: [3](#0-2) 
```
totalWeight = totalWeight - votingWeights[lp] + weight;
votingWeights[lp] = weight;
```
It is straightforward for `totalWeight` to be `0` while `votePools.length > 0` — e.g., a pool is registered with an initial weight of `0` (common when onboarding a pool before assigning its vote weight), or the sum of weights is later rebalanced back to zero. In either case `votePools` retains entries but `totalWeight` is `0`.

Once in that state, `_updateVote()` is invoked from `stakeFor`/`withdrawFor`, both callable via `onlyOperator` (the `WombatBribeManager`): [4](#0-3) 

These are reached by ordinary, unprivileged wallets calling `WombatBribeManager.vote()` or `unvote()` for the delegated pool, which internally calls `IBribeRewardPool(pool.rewarder).stakeFor(...)` / `withdrawFor(...)`: [5](#0-4) [6](#0-5) 

When the pool's `rewarder` is the `DelegateVoteRewardPool` (tracked via `delegatedPool` in `WombatBribeManager`), any user's vote/unvote transaction on that delegate pool triggers `_updateVote()`, and if `totalWeight == 0` at that moment, the transaction reverts on division by zero.

### Impact Explanation
Once `totalWeight` is `0` while `votePools` is non-empty, **every** unprivileged user's call to `stakeFor`/`withdrawFor` on `DelegateVoteRewardPool` (triggered via normal `vote()`/`unvote()` calls on `WombatBribeManager`) reverts. This blocks: staking new votes through the delegate pool, withdrawing/unvoting, and claiming rewards routed through `withdrawFor(..., _claim=true)`. Because this state (a registered vote pool with zero weight) is a plausible, non-malicious configuration outcome and not something ordinary users can fix themselves, it constitutes a freeze of user funds/voting rights for the delegate pool lasting until an admin intervenes and rebalances weights — satisfying a 24-hour-plus freeze of user-facing functionality.

### Likelihood Explanation
The trigger condition (`totalWeight == 0` with `votePools.length > 0`) arises from normal admin lifecycle operations (adding a pool with initial weight 0, or rebalancing weights to net zero) rather than an exploit, and the DoS is then triggered automatically by any regular user's next vote/unvote transaction — no attacker action or privilege is required to hit the revert. This makes the likelihood moderate: it depends on the specific weight configuration but does not require any malicious or privileged actor to trigger the freeze once the zero-weight state exists.

### Recommendation
In `_updateVote()`, short-circuit the division when `totalWeight == 0` (mirroring the guard already used in `WombatBribeManager.castVotes()`), e.g., treat `targetVote` as `0` when `totalWeight == 0`, so voting operations do not revert.

### Proof of Concept
1. Owner calls `updateWeight(lpA, 0)` to register `lpA` as a vote pool with weight `0` (first-time registration), leaving `totalWeight == 0` and `votePools = [lpA]`.
2. Any unprivileged user calls `WombatBribeManager.vote([delegatedPoolLp], [delta])` where `delegatedPoolLp`'s rewarder is the `DelegateVoteRewardPool`.
3. This triggers `IBribeRewardPool(rewarder).stakeFor(user, delta)` → `_updateVote()` → `votingWeights[lpA] * totalSupply / totalWeight` → division by zero → transaction reverts.
4. All subsequent stake/withdraw/claim operations on the delegate pool revert until an admin sets a nonzero `totalWeight`.

    function _updateVote() internal {
        uint256 length = votePools.length;
        int256[] memory deltas = new int256[](length);
        for (uint256 index = 0; index < length; ++index) {
            address pool = votePools[index];
            uint256 targetVote = (votingWeights[pool] * totalSupply) /
                totalWeight;
            uint256 currentVote = _getVoteForLp(pool);
            deltas[index] = int256(targetVote) - int256(currentVote);
        }
        IWombatBribeManager(operator).vote(votePools, deltas);
    }
