Confirmed: `DefaultParams()` sets `PermissionlessRegistration: true` [1](#0-0) , meaning any unprivileged account can call `RegisterERC20` to create a `TokenPair` for an arbitrary external ERC20 contract, with the only checks being non-duplication and coin-metadata creation — no validation of the contract's transfer-blocking capabilities [2](#0-1) [3](#0-2) .

### Title
Permissionless registration of pausable/owner-controlled ERC20 tokens permanently freezes bank-coin representation and IBC-escrowed value - (File: x/erc20/keeper/msg_server.go)

### Summary
`x/erc20`'s `RegisterERC20` message handler is permissionless by default (`PermissionlessRegistration: true`) [1](#0-0) , allowing anyone to register any external ERC20 contract as a `TokenPair` with `ContractOwner = OWNER_EXTERNAL` [4](#0-3) . This is the direct analog of the Solana report's "input token mint with freeze authority": nothing in `registerERC20` validates that the underlying ERC20 contract is free of an externally-controlled mechanism (e.g. OpenZeppelin `Pausable`/`AccessControl` roles, as shipped in this very repo's `ERC20MinterBurnerDecimals.sol`) that can permanently block `transfer` calls [5](#0-4) .

### Finding Description
Once such a token pair exists, two module-controlled flows depend on unconditionally successful `transfer` calls against the external, attacker/owner-controlled contract:

- `ConvertERC20` escrows the native ERC20 tokens into the module account and mints/sends the corresponding bank coin to the user [6](#0-5) .
- `ConvertCoinNativeERC20` burns the escrowed bank coin and calls `transfer` from the module account to the receiver to release the underlying ERC20 tokens [7](#0-6) .

If the external ERC20 contract's owner/pauser role (which the erc20 module never validates away, unlike Solana's recommended `mint::freeze_authority = COption::None` check) pauses transfers or blacklists the `types.ModuleAddress` escrow account after coins have already been converted (`ConvertERC20`) and/or moved over IBC (escrowed at the standard ICS20 escrow address, as exercised in `SetupNativeErc20`/`TestOnRecvPacketNativeErc20` flows) [8](#0-7) , the `transfer` call in `ConvertCoinNativeERC20` will permanently revert. Since this call is the *only* redemption path from the bank-coin/IBC representation back to the underlying ERC20 value, all holders of that denom (including funds already escrowed cross-chain in IBC channel escrow accounts) permanently lose the ability to redeem the real backing asset. The bank coin keeps circulating (transferable within Cosmos/IBC) while its 1:1 backing invariant with the real ERC20 supply is irrecoverably broken — a permanent freeze/loss of token-pair-backed value triggered purely by an ordinary permissionless `MsgRegisterERC20` plus normal `ConvertERC20`/`MsgTransfer` usage, with no privileged action needed from the chain's own validators or governance.

### Impact Explanation
This matches the Critical impact bar for "permanent freezing... of user funds... or token-pair-backed balances" and breaks the erc20 module's asset-representation invariant that native coins/IBC escrows must remain 1:1 redeemable against the real ERC20 supply. Because `PermissionlessRegistration` defaults to `true`, no governance or admin action is required to introduce the malicious/pausable token pair.

### Likelihood Explanation
High likelihood: an attacker deploys a standard OpenZeppelin `ERC20Pausable`/role-gated token (trivial, and even shipped as example code in this repo), calls the permissionless `MsgRegisterERC20`, waits for users (or the attacker's own alt account) to `ConvertERC20` and optionally bridge the coin over IBC, then pauses/blacklists the contract, permanently freezing the redemption path for every coin holder.

### Recommendation
Mirror the Solana report's recommendation: reject registration (or require additional governance vetting) of ERC20 contracts whose bytecode exposes pause/blacklist/role-based transfer-restriction capabilities, or enforce that the erc20 module retains exclusive control (ownership) over any such mechanism before creating the `TokenPair` in `registerERC20`. At minimum, disable `PermissionlessRegistration` by default and require a governance-reviewed allowlist for `OWNER_EXTERNAL` token pairs.

### Proof of Concept
1. Deploy a `Pausable`+`AccessControl` ERC20 (e.g. `ERC20MinterBurnerDecimals.sol` pattern) with attacker as `PAUSER_ROLE`/`DEFAULT_ADMIN_ROLE` holder.
2. Call `MsgRegisterERC20` (permissionless, default params) to create a `TokenPair` with `ContractOwner = OWNER_EXTERNAL`.
3. Mint tokens to a victim, victim calls `MsgConvertERC20` to escrow tokens into `types.ModuleAddress` and receive bank coins [6](#0-5) .
4. Attacker calls `pause()` on the contract [9](#0-8) .
5. Victim attempts `MsgConvertCoin` to redeem back to ERC20; the internal `transfer` call from `types.ModuleAddress` reverts permanently [10](#0-9) , and victim's underlying ERC20 value is frozen forever while holding only a non-redeemable bank coin.

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
