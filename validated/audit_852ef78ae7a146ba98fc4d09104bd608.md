### Title
TxPool full-capacity guard rejects same-nonce fee-bump replacements as if they consumed new pool slots - (File: blockchain/tx_pool.go)

### Summary
### Finding Description
When `TxPool.add()` receives a transaction, it first checks whether the pool is globally full before considering whether the transaction is actually a *replacement* for a nonce it already accounts for: [1](#0-0) 

The check is:
```go
if uint64(pool.all.Slots()+numSlots(tx)) > pool.config.ExecSlotsAll+pool.config.NonExecSlotsAll {
    from, _ := types.Sender(pool.signer, tx)
    if pool.queue[from] == nil {
        // reject: "no room for account"
    }
    maxTx := pool.getMaxTxFromQueueWhenNonceIsMissing(tx, &from)
    if maxTx == tx {
        // reject: "does not have missing nonce"
    }
    ...
}
```
`getMaxTxFromQueueWhenNonceIsMissing` returns `tx` itself whenever the tx's nonce already exists in the sender's queue: [2](#0-1) 
```go
func (pool *TxPool) getMaxTxFromQueueWhenNonceIsMissing(tx *types.Transaction, from *common.Address) *types.Transaction {
	txs := pool.queue[*from].txs
	maxTx := tx
	if txs.Get(tx.Nonce()) != nil {
		return maxTx
	}
	...
}
```
So a transaction that *replaces* (fee-bumps) a nonce already present in the pool is misclassified as "not having a missing nonce" and rejected with `"txpool is full and the new tx does not have missing nonce"`, even though replacing an existing nonce does not net-increase `pool.all.Slots()` (the old occupant is removed and the new one takes its place). The actual replace-in-place logic that correctly frees/reuses the slot only exists further down, for the `pending` map: [3](#0-2) 
but that code is unreachable for accounts whose colliding transaction sits in `pool.queue` (non-executable) rather than `pool.pending`, and is also unreachable for accounts with `pool.queue[from] == nil` when the account's outstanding transaction is only in `pending` — those get rejected at step (1) ("no room for the account") before the replacement path at line 1211 is ever consulted.

This mirrors the KUMASwap `_maxCoupons` bug exactly: a global size limit (`_maxCoupons` / `ExecSlotsAll+NonExecSlotsAll`) is checked and causes a revert/rejection without first checking whether the incoming item (`bond.coupon` / `tx` with an already-occupied nonce) is already accounted for in the set, so items that would not actually grow the set are wrongly refused.

### Impact Explanation
Any unprivileged transaction sender submitting an ordinary fee-bump / replacement transaction via public RPC (`eth_sendRawTransaction`) can be denied pool admission purely because the global pool is at capacity, even though their replacement transaction does not consume any additional pool slot. This breaks a core mempool guarantee (fee-bump replacement to get a transaction included/re-priced) at exactly the moment it matters most — when the pool is busy/full — degrading fee-market functioning (an area explicitly in scope: "pool admission and KIP-71 pricing"). It does not directly cause fund loss, but it is a state/availability correctness defect in transaction admission that unfairly and non-deterministically penalizes senders attempting legitimate replacements once the pool reaches capacity, and could be exploited to keep a victim's stuck/underpriced transaction pinned in the pool (denial of the victim's ability to fee-bump out of a stuck state) by an attacker who keeps the pool saturated.

### Likelihood Explanation
The condition is trivially reachable: it only requires (a) the global tx pool to be at or near `ExecSlotsAll+NonExecSlotsAll` capacity (a routine, expected condition during network congestion) and (b) the sender to submit a nonce-colliding (replacement/fee-bump) transaction for one of their own already-queued or already-pending transactions. Both are conditions any ordinary user or an attacker filling the pool can trigger without any privileged access, matching the "unprivileged transaction sender ... public-RPC caller" reachability requirement.

### Recommendation
Before applying the full-pool eviction/rejection logic in `add()`, first check whether the incoming transaction is a same-nonce replacement of a transaction already accounted for in `pool.queue[from]` or `pool.pending[from]`. If so, route it directly into the existing replace-in-place logic (as already done at line 1211 for pending) without going through the "pool is full" rejection path, since a same-nonce replacement is not a net addition to `pool.all.Slots()`. Concretely, mirror the KUMASwap fix pattern: only apply the "reject due to capacity" branch when the transaction's nonce does **not** already exist in the sender's `queue`/`pending`, analogous to `!_coupons.contains(bond.coupon)`.

### Proof of Concept
Not runnable without live infrastructure access; the following is the code-level trace establishing the bug (static PoC):
1. Fill `pool.all` up to `pool.config.ExecSlotsAll + pool.config.NonExecSlotsAll` (e.g., by sending distinct-account transactions until the pool is full).
2. From an account `A` that already has a transaction with nonce `N` sitting in `pool.queue[A]` (non-executable, e.g., a future-nonce tx), submit a new transaction from `A` with the same nonce `N` but a bumped gas price (a legitimate fee-bump replacement).
3. In `add()`, `pool.all.Slots()+numSlots(tx) > ExecSlotsAll+NonExecSlotsAll` is true (pool full).
4. `pool.queue[A] != nil`, so step (1) passes.
5. `getMaxTxFromQueueWhenNonceIsMissing(tx, &A)` finds `txs.Get(N) != nil` and returns `tx` itself, so `maxTx == tx`.
6. `add()` returns the error `"txpool is full and the new tx does not have missing nonce"`, rejecting a transaction that should have simply replaced the existing nonce-`N` entry with no net change in `pool.all.Slots()`. [4](#0-3)

// getMaxTxFromQueueWhenNonceIsMissing finds and returns a trasaction with max nonce in queue when a given Tx has missing nonce.
// Otherwise it returns a given Tx itself.
func (pool *TxPool) getMaxTxFromQueueWhenNonceIsMissing(tx *types.Transaction, from *common.Address) *types.Transaction {
	txs := pool.queue[*from].txs

	maxTx := tx
	if txs.Get(tx.Nonce()) != nil {
		return maxTx
	}

	for _, t := range txs.items {
		if maxTx.Nonce() < t.Nonce() {
			maxTx = t
		}
	}
	return maxTx
}
