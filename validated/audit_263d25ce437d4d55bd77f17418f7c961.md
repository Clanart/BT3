### Title
Payout tx's operator-attribution OP_RETURN is uncommitted by the user's `SinglePlusAnyoneCanPay` signature, letting anyone rewrite it — (`core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` puts `operator_xonly_pk` into output index 2 (OP_RETURN), but the only signature checked in `Operator::withdraw` (`core/src/operator.rs:630-637`) is the user's key-path signature over input 0 with `SinglePlusAnyoneCanPay`, which under BIP-341 only commits to input 0 and output 0 — never to output 2. Consequently, the OP_RETURN attribution is a free-form claim by whoever broadcasts/funds the transaction and can be swapped by any party holding the leaked `user_sig`/`input_utxo`/`output_txout` triple, without invalidating `SECP.verify_schnorr` for input 0.

### Finding Description
Binding claimed and broken: `operator_xonly_pk (OP_RETURN of the mined payout tx)` == `xonly_pk of whoever's wallet supplies the payout tx's fee inputs (add_inputs/CPFP)`. This equality is **assumed** by the downstream attribution logic but **not enforced** anywhere in the signature/transaction validation path.

- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the tx with: output 0 = user payout, output 1 = anchor, output 2 = `op_return_txout(operator_xonly_pk)`. Only input 0 is signed via `set_p2tr_key_spend_witness(&user_sig, 0)`.
- `Operator::withdraw` (`core/src/operator.rs:620-637`) calls `calculate_sighash_txin(0, in_signature.sighash_type)` and verifies with `SECP.verify_schnorr`. When `in_signature.sighash_type == SinglePlusAnyoneCanPay`, BIP-341's SIGHASH_SINGLE commits only to output index 0 (matching input 0) and ANYONECANPAY commits only to input 0 itself — output 1 (anchor) and output 2 (OP_RETURN operator pubkey) are entirely outside the signed message, and so are any other inputs added later.
- The operator's own client code funds the tx via `self.rpc.fund_raw_transaction(.., add_inputs: Some(true), ..)` (`core/src/operator.rs:652-673`), i.e., the "attribution" (whose xonly-pk goes in the OP_RETURN) and "who pays the extra fee inputs" are two independently-controlled, un-bound pieces of data supplied by whoever constructs the transaction.
- Downstream, `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) blindly parses the mined tx's OP_RETURN via `parse_op_return_data` and stores that xonly-pk as the payout's fronting operator with no check tying it to which UTXOs funded the transaction.
- `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`) later only checks `operator_xonly_pk (from payout OP_RETURN) == kickoff_data.operator_xonly_pk` — a purely bookkeeping comparison. It never checks that the entity named actually supplied the funds.

Exploit flow: an unprivileged attacker obtains `(input_utxo, output_txout, in_signature)` — e.g., by observing it in the mempool after any operator (or even the aggregator's public `internal_withdraw`/`withdraw` gRPC, unauthenticated unless `aggregator_verification_address` is configured, per `core/src/rpc/operator.rs:192-239`) broadcasts an attempt, or the aggregator's optimistic-payout path exposes it. The attacker rebuilds `create_payout_txhandler` with the identical `input_utxo`, `output_txout`, `user_sig`, but a different `operator_xonly_pk` (either a real registered operator's key, or a bogus/nonexistent key), funds the extra inputs from their own wallet, and RBF/fee-bumps it ahead of the legitimate transaction. `SECP.verify_schnorr` for input 0 still succeeds because the sighash is unaffected by the OP_RETURN change.

### Impact Explanation
Two concrete outcomes, both matching the listed Critical categories:
1. Attacker names a real registered operator X in the OP_RETURN while X never funded the payout. When Citrea sync records `operator_xonly_pk = X`, and X later submits a kickoff (or is otherwise attributed), `is_kickoff_malicious` finds a match and treats it as non-malicious — X becomes eligible to be reimbursed (spend `DepositInMove` via `create_reimburse_txhandler`) for a payout it never funded, matching Impact "an operator reimbursed for a payout it never funded".
2. Attacker puts a bogus/nonexistent xonly-pk (or garbage bytes) in the OP_RETURN. Once mined, the withdrawal outpoint is permanently spent (so no honest operator can re-front it), but no real operator's `kickoff_data.operator_xonly_pk` will ever match the recorded value, so `is_kickoff_malicious` always returns `true` for any legitimate reimbursement attempt — the corresponding move-to-vault UTXO can never be honestly released, matching "a move-to-vault UTXO permanently frozen" / "an honest operator permanently unable to be reimbursed".

This is repeatable per withdrawal, and its blast radius spans every deposit/withdrawal pair processed by the standard (non-optimistic) payout path, since the root cause is structural (sighash design), not deposit-specific.

### Likelihood Explanation
Preconditions: the attacker needs to obtain a valid `(input_utxo, output_txout, in_signature)` before/instead of the legitimate operator's broadcast confirms. This is plausible because: (a) Bitcoin mempools are public, so any operator's earlier broadcast attempt leaks the exact signed payload; (b) the withdrawal signature itself is explicitly described as "given to operators off-chain," implying multiple untrusted-by-each-other parties already hold it; (c) `Operator::withdraw`'s gRPC (`core/src/rpc/operator.rs`) requires only an optional ECDSA verification signature tied to a configured `aggregator_verification_address` — if unset, the RPC is open to anyone with the withdrawal parameters. Attacker cost is limited to normal BTC transaction fees plus outbidding the legitimate operator's fee/RBF, well within reach of an unprivileged actor. No verifier, aggregator, or operator collusion is required.

### Recommendation
Bind the fronting operator's identity to the transaction cryptographically or require the user's signature to cover the OP_RETURN output, e.g.:
- Have the user sign with a sighash type that also commits to the OP_RETURN output (e.g. require the operator to pre-register/commit `operator_xonly_pk` before requesting the user's signature, and use `SIGHASH_ALL`/`SIGHASH_NONE` semantics tailored so output 2 is covered), or
- Add an operator-side signature (via key-path aggregation or a separate script-path condition) authenticating that the named operator actually authorized/funded this specific payout, so the OP_RETURN cannot be swapped by a third party after the fact, or
- Have `update_finalized_payouts`/`is_kickoff_malicious` additionally verify that the fee-paying inputs of the mined payout tx are provably controlled by the operator named in OP_RETURN (e.g., via a distinguishing script/commitment on those inputs), rather than trusting the raw OP_RETURN bytes.

### Proof of Concept
```rust
// cargo test in core/, no mainnet/no live Citrea required.
#[test]
fn poc_op_return_attribution_not_covered_by_sighash() {
    // 1. Build a user keypair, an input_utxo (P2TR) and output_txout as in withdraw() flow.
    // 2. Have the "user" sign the payout tx (via create_payout_txhandler with operator_a_pk)
    //    using SinglePlusAnyoneCanPay, producing `user_sig`.
    let tx_a = create_payout_txhandler(
        input_utxo.clone(),
        output_txout.clone(),
        operator_a_pk,
        user_sig,
        network,
    ).unwrap();

    // 3. Attacker reuses the SAME input_utxo/output_txout/user_sig but a DIFFERENT operator xonly pk.
    let tx_b = create_payout_txhandler(
        input_utxo.clone(),
        output_txout.clone(),
        operator_b_pk, // different from operator_a_pk, e.g. arbitrary/bogus key
        user_sig,
        network,
    ).unwrap();

    // 4. Recompute sighash for input 0 on both and verify against user_sig — both must pass,
    //    proving the OP_RETURN (operator attribution) is not bound by the signature.
    let sighash_a = tx_a.calculate_sighash_txin(0, user_sig.sighash_type).unwrap();
    let sighash_b = tx_b.calculate_sighash_txin(0, user_sig.sighash_type).unwrap();
    assert_eq!(sighash_a, sighash_b); // sighashes are identical despite different OP_RETURN content

    SECP.verify_schnorr(&user_sig.signature, &Message::from_digest(*sighash_a.as_byte_array()), &user_xonly_pk).unwrap();
    SECP.verify_schnorr(&user_sig.signature, &Message::from_digest(*sighash_b.as_byte_array()), &user_xonly_pk).unwrap();
    // Both verify_schnorr calls succeed, confirming an attacker can freely rewrite operator_xonly_pk.
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }
