### Title
Duplicate `ReceivedOutput`s double-count one UTXO and create an invalid spend - (File: `networks/bitcoin/src/wallet/send.rs`)

### Summary
`SignableTransaction::new` accepts multiple `ReceivedOutput`s identifying the same Bitcoin outpoint and adds each serialized `TxOut` value to `input_sat` independently. It also emits one transaction input per supplied `ReceivedOutput` without rejecting duplicate `previous_output` values. [1](#0-0)  Because `ReceivedOutput::read` accepts the `TxOut` and `OutPoint` entirely from serialized input, an untrusted encoding can repeat a real outpoint while claiming additional spendable value. [2](#0-1) 

### Finding Description
`ReceivedOutput` represents one spendable output using an offset, a `TxOut`, and an `OutPoint`. [3](#0-2)  Its deserializer accepts attacker-controlled bytes for all three fields and performs no uniqueness or chain-state validation. [2](#0-1)  `SignableTransaction::new` then computes `input_sat` by summing every supplied `input.output.value`, without canonicalizing or deduplicating the supplied outpoints. [4](#0-3)  It constructs a separate `TxIn` for every supplied entry, directly copying each `input.outpoint` into `previous_output`. [5](#0-4)  The resulting transaction therefore contains the same UTXO multiple times while its funding check and change calculation treat the UTXO's value as available multiple times. [6](#0-5)  `multisig` only verifies that each claimed previous-output script matches the corresponding offset key; it does not reject duplicate inputs or prove that each claimed amount is the amount actually locked by that outpoint. [7](#0-6)  Signing commits to all supplied `prevouts` through `Prevouts::All`, so the duplicated/misstated input data becomes part of each Taproot signature message. [8](#0-7) 

### Impact Explanation
A duplicate outpoint makes the transaction invalid under Bitcoin consensus rules because the same UTXO is spent by more than one input in the transaction. [5](#0-4)  The wallet can nevertheless authorize payments or change values exceeding the amount actually available because `input_sat` double-counts the copied `TxOut` value. [9](#0-8)  If the claimed `TxOut` amount differs from the chain's actual amount, the Taproot signature is additionally committed to incorrect prevout data through `Prevouts::All`. [8](#0-7)  This is the same accounting error class as the reference issue: value associated with one asset is charged or credited twice because a later stage identifies the asset independently rather than recognizing that it was already consumed. [1](#0-0) 

### Likelihood Explanation
The vulnerable input path is `ReceivedOutput::read`, which accepts serialized offset, output, and outpoint bytes from a caller-provided reader. [2](#0-1)  Exploitation only requires feeding two encoded outputs with the same `OutPoint` into `SignableTransaction::new`; no validator privilege, malformed curve point, leaked key, or malicious peer implementation is needed. [10](#0-9)  The code performs checks for empty inputs, dust, size, fees, and insufficient nominal funds, but contains no `HashSet`/ordering check over `previous_output`. [11](#0-10) 

### Recommendation
Reject duplicate outpoints before calculating `input_sat`, constructing `tx_ins`, offsets, or `prevouts` in `SignableTransaction::new`. [10](#0-9)  Add a `TransactionError::DuplicateInput` variant and insert each `input.outpoint` into a set while iterating over `inputs`, returning an error on insertion failure. [1](#0-0)  Where serialized `ReceivedOutput`s originate from untrusted storage or messages, validate the referenced transaction output and amount against confirmed chain data before calling `SignableTransaction::new`. [2](#0-1) 

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/send.rs API-level demonstration

let real: ReceivedOutput = /* one confirmed ReceivedOutput */;
let duplicate = real.clone();

// `input_sat` becomes `2 * real.value()`, even though only one UTXO exists.
let tx = SignableTransaction::new(
    vec![real.clone(), duplicate],
    &[(payment_script, real.value() + 1)],
    None,
    None,
    fee_per_vbyte,
)
.unwrap();

// The constructed transaction contains the same previous_output twice.
assert_eq!(tx.transaction().input[0].previous_output, *real.outpoint());
assert_eq!(tx.transaction().input[1].previous_output, *real.outpoint());
```

For a serialized-input variant, encode the same `OutPoint` twice through `ReceivedOutput::write`, deserialize both with `ReceivedOutput::read`, and pass both results to `SignableTransaction::new`; the constructor performs no duplicate-outpoint rejection before summing the copied values and creating duplicate `TxIn`s.   /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(&self.offset.to_bytes())?;
    w.write_all(&serialize(&self.output))?;
    w.write_all(&serialize(&self.outpoint))
  }
