### Title
Unauthenticated On-Chain Mirror URLs Let Any Spend Bundle Trigger SSRF in DataLayer's Delta-File Fetcher - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer subsystem tracks "mirror" coins on chain to discover HTTP(S) URLs from which peers should download `.dat` delta/full-tree files for a subscribed store. Any coin spend that creates a coin with the mirror puzzle hash and a memo containing a tracked `launcher_id` plus arbitrary URL strings will be picked up by the wallet and later fed, unfiltered, into the DataLayer service's HTTP client (`http_download`). No scheme/host/IP validation of any kind is performed before the outbound request is issued.

### Finding Description
`DataLayerWallet.coin_added()` recognizes any coin whose puzzle hash equals `create_mirror_puzzle().get_tree_hash()` and, as long as the `launcher_id` embedded in the memo is *already tracked* by the wallet (not necessarily owned by it — subscribed/replicated stores are tracked too), records the accompanying memo strings as mirror URLs with no validation of their content: [1](#0-0) 

The URL strings originate purely from an on-chain `CREATE_COIN` condition's memo field, parsed by `get_mirror_info()`: [2](#0-1) 

These mirror URLs are then surfaced to the DataLayer service via `DataLayer.update_subscriptions_from_wallet()`, which simply strips trailing slashes and stores them as subscription server URLs — again with no validation: [3](#0-2) 

`DataLayer.fetch_and_validate()` later selects one of these `server_info.url` values and passes it into `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) 

`http_download()` performs the outbound network request directly against the attacker-controlled URL string with no scheme restriction, no private/loopback/link-local IP filtering, and no cloud-metadata-endpoint blocking: [5](#0-4) 

The only pre-existing test coverage for mirrors uses local URLs like `http://127.0.0.1/8000` without any rejection, confirming there is no filtering logic anywhere in this path: [6](#0-5) 

### Impact Explanation
Any party able to submit a spend bundle that creates a coin with the mirror puzzle hash (`P2_PARENT.curry(1)`) and a memo naming a `launcher_id` that a victim node happens to track (e.g., because it subscribed to that DataLayer store for legitimate replication) can inject arbitrary URLs — `http://127.0.0.1:<port>/...`, `http://169.254.169.254/latest/meta-data/...`, internal RFC1918 addresses, etc. — into that victim's mirror/subscription table. The victim's `DataLayer` service then makes outbound HTTP GET requests to those URLs during its periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`), fully server-side and attacker-triggered, matching the reported bug class (server-initiated requests to attacker-controlled URLs with no SSRF protection). This can be used to probe/interact with internal services or cloud metadata endpoints reachable from the machine running the DataLayer/wallet process.

### Likelihood Explanation
Creating the mirror coin only requires a standard `CREATE_COIN` condition with the correct puzzle hash and memo layout — no special authorization on the network side, and any wallet participating in DataLayer subscription/replication for a given store is a viable target. This is comparable in reachability to "coin identity and puzzle hashing" / "DataLayer roots and proofs" workflows explicitly listed as in-scope reachable paths.

### Recommendation
Before dispatching any outbound HTTP request in `http_download()` (and the plugin `handle_download`/`handle_upload` calls in `data_layer.py`), validate and restrict mirror/downloader/uploader URLs: enforce an allowed scheme list (e.g., `http`/`https`), resolve and reject private/loopback/link-local/multicast/cloud-metadata IP ranges (including post-DNS-resolution re-checks to prevent DNS rebinding), and consider requiring explicit user opt-in/allow-listing for mirror URLs learned from on-chain data rather than trusting all URLs discovered via `coin_added()` for any tracked launcher.

### Proof of Concept
1. Victim node subscribes to (tracks) a DataLayer store with `launcher_id = L` for replication purposes.
2. Attacker submits a spend bundle creating a coin with `puzzle_hash = create_mirror_puzzle().get_tree_hash()` and memo `[L, b"http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` (mirroring the exact format used in `create_new_mirror()`, see `chia/data_layer/data_layer_wallet.py` lines 687-703).
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` records this as a tracked mirror for `L` since `is_launcher_tracked(L)` is true.
4. On the next DataLayer sync cycle, `update_subscriptions_from_wallet()` copies this URL into the subscription's server list, and `fetch_and_validate()`/`http_download()` issues an outbound GET request to the attacker-chosen URL.

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
