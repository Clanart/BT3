### Title
`ReceivedOutput::read` accepts an unvalidated scalar offset, TxOut, and OutPoint — attacker-supplied bytes are trusted as a spendable, owned output — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to Gitea's `uri.Open(asset.DownloadURL)` accepting a `file://` URL without scheme validation (GHSA-5ggr-2f2h-jmvm), `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs` deserializes a spendable-output record from untrusted bytes without validating any of its three locator fields. The `offset` scalar (read via `Secp256k1::read_F`), the `TxOut` (arbitrary `script_pubkey` and `value`), and the `OutPoint` are all accepted verbatim. Nothing checks that `key + offset·G` — tweaked per `p2tr_script_buf` — actually derives `output.script_pubkey`, that the outpoint exists on-chain, or that the claimed value matches the real UTXO. The scanner path (`Scanner::scan_transaction`, lines 199–214) only ever constructs `ReceivedOutput`s whose offset provably maps the registered script to the output; the deserialization path bypasses that invariant entirely. ### Finding Description
`ReceivedOutput` is the type the Bitcoin network implementation feeds into `Plan::read` as `N::Output::read` (`processor/src/plan.rs:186–188`), so untrusted serialized bytes reach `ReceivedOutput::read`. The function:

- reads `offset` as any canonical scalar with no derivation check against `output.script_pubkey` (contrast `Scanner::register_offset`, lines 180–196, which only records offsets that actually produce a registered script);
- consensus-decodes an arbitrary `TxOut`, so the script can pay to an unrelated key and the `value` field can be inflated;
- consensus-decodes an arbitrary `OutPoint` which may not correspond to any real UTXO.

Downstream, the offset is applied to the threshold keys (via `ThresholdKeys::offset`, the same mechanism used by `tweak_keys` at lines 46–75) to sign for the input. If `offset` does not derive the key behind `script_pubkey`, the produced Schnorr signature will never satisfy the output's key-path spend — yet the output was already accounted as received with its claimed `value()`.

### Impact Explanation
An unprivileged party supplying crafted `ReceivedOutput` bytes causes the processor to report funds as received that are not spendable:

- **Non-spendable "received" funds**: an `offset` that doesn't map to the output's script produces a plan input whose signature can never validate — the wallet counts `output.value` as balance while the UTXO is unspendable by that offset (or doesn't exist at all).
- **Value inflation**: `TxOut.value` is whatever the bytes claim, so accounting reports a higher received amount than the chain records.

This mirrors the Gitea bug's shape exactly: a user-controlled field (`download_url` there; `offset`/`TxOut`/`OutPoint` here) is treated as an authoritative locator for a resource and dereferenced without any validation that the locator is legitimate.

### Likelihood Explanation
Reachability is per the in-scope rule: `ReceivedOutput::read` is an accepted entry point for untrusted bytes. Exploitation requires an attacker to get a crafted serialized output into a `Plan`, after which the mis-accounting is deterministic. Impact is bounded to availability/accounting (unspendable or phantom inputs) rather than direct key compromise, consistent with Medium severity.

### Recommendation
In `ReceivedOutput::read`, validate the deserialized record before returning it:

- Recompute `p2tr_script_buf(key + G·offset)` and require equality with `output.script_pubkey` — this requires the scanner's `key` (pass it as a parameter or make `read` a method on `Scanner`), restoring the invariant the scan path enforces.
- Reject dust/unspendable values and enforce a sane `value` bound at parse time.
- Have consumers confirm the `OutPoint` exists and is confirmed on-chain (and past coinbase maturity) before treating it as spendable balance.

### Proof of Concept
```rust
// networks/bitcoin context: craft a ReceivedOutput whose offset
// does not derive the output's script_pubkey
use networks::bitcoin::wallet::ReceivedOutput;

let mut bytes = vec![];
// offset = 1, arbitrary
bytes.extend(k256::Scalar::ONE.to_bytes());
// a TxOut paying to an unrelated P2TR key, value inflated to 21M BTC
let fake_out = bitcoin::TxOut {
  value: bitcoin::Amount::from_sat(21_000_000_0000_0000),
  script_pubkey: attacker_p2tr_script.clone(),
};
bytes.extend(bitcoin::consensus::encode::serialize(&fake_out));
// an outpoint that may not exist
bytes.extend(bitcoin::consensus::encode::serialize(&fake_outpoint));

// Accepted without any check that offset -> script_pubkey or that the UTXO exists
let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(received.value(), 21_000_000_0000_0000); // phantom balance accepted
```

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
