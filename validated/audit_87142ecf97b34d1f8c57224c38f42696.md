### Title
Unattributed payout attribution lets any party front a withdrawal and credit an arbitrary operator with reimbursement it never funded - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the `payout_tx` using the user's `SinglePlusAnyoneCanPay` signature over input 0/output 0 only, while the third output (OP_RETURN naming the reimbursing `operator_xonly_pk`) is appended by whoever assembles and broadcasts the transaction and is never covered by the user's signature. Verifiers later derive `payout_payer_operator_xonly_pk` solely from this uncommitted OP_RETURN field [1](#0-0) , and the operator's own automation credits itself with reimbursement for any withdrawal whose OP_RETURN names its key [2](#0-1) , without ever checking that the named operator actually supplied the funds in the transaction.

### Finding Description
`create_payout_txhandler` signs only input 0 with the user-provided `taproot::Signature` (`SinglePlusAnyoneCanPay`), and appends an OP_RETURN output containing `operator_xonly_pk` that is completely outside the signed message: [3](#0-2) .

`SinglePlusAnyoneCanPay` (`SIGHASH_SINGLE | ANYONECANPAY`) only binds the signer to their own input and the output at the same index; any party can add further inputs/outputs, including the OP_RETURN at index 2, without invalidating the user's signature. The `withdraw` RPC handler (`internal_withdraw`/`withdraw` in `core/src/rpc/operator.rs`) accepts these parameters over an otherwise unauthenticated channel and simply forwards them to `Operator::withdraw`, which builds the tx with `self.signer.xonly_public_key` [4](#0-3) . Nothing prevents an outside party who has learned the user's signature (submitted publicly to the Citrea `safeWithdraw` contract, see `core/src/test/common/citrea/mod.rs:432-443`) from constructing and directly broadcasting their own copy of this same tx — funding the withdrawal from their own wallet — while inserting an arbitrary registered operator's `xonly_pk` in the OP_RETURN.

On the verifier/operator side, `update_finalized_payouts` parses this uncommitted OP_RETURN and stores it as `payout_payer_operator_xonly_pk` with no cross-check against who actually funded the transaction inputs [5](#0-4) . The named operator's own `PayoutCheckerTask` then picks up this entry via `get_first_unhandled_payout_by_operator_xonly_pk` (which filters purely on the OP_RETURN-derived key) [6](#0-5)  and automatically drives `handle_finalized_payout` → kickoff → `create_reimburse_txhandler`, which pays the full bridge amount out of the move-to-vault UTXO to that operator [7](#0-6)  and [8](#0-7) . `is_kickoff_malicious` only checks that `operator_xonly_pk == kickoff_data.operator_xonly_pk`, i.e. that the OP_RETURN matches the kickoff sender — it never verifies that this operator's own funds appeared anywhere in the payout transaction's inputs [9](#0-8) .

This breaks the intended equality "the operator credited == the party that actually fronted the withdrawal": an unprivileged third party who fronts the withdrawal payment can attribute the resulting reimbursement entitlement to any registered operator of their choosing, purely by controlling the OP_RETURN of the broadcast transaction, which is not covered by the sole cryptographic commitment (the user's `SinglePlusAnyoneCanPay` signature) in the transaction.

### Impact Explanation
This matches the Critical category "an operator reimbursed for a payout it never funded": a targeted operator's automation will unconditionally kick off the reimbursement flow and receive the full `bridge_amount` from the move-to-vault UTXO for a withdrawal it never paid, based solely on unauthenticated OP_RETURN data an outside party controls when assembling/broadcasting the payout transaction.

### Likelihood Explanation
The withdrawal parameters (`input_outpoint`, `output_script_pubkey`, `output_amount`, and the `SinglePlusAnyoneCanPay` `input_signature`) are exposed publicly as part of registering the withdrawal on Citrea (`safeWithdraw`) before any operator processes it, and the payout gRPC (`withdraw`/`internal_withdraw`) is reachable without proof that the caller is the operator whose key ends up in the OP_RETURN. No verifier or operator role is required to mount this — any party who can observe the public withdrawal signature and has enough BTC to front the (typically modest) withdrawal amount can construct and directly broadcast the manipulated transaction to the Bitcoin network, bypassing the honest operator's own RPC entirely.

### Recommendation
Bind the OP_RETURN's `operator_xonly_pk` cryptographically to proof of funding, e.g., require the reimbursing operator to also sign the transaction (covering the OP_RETURN output) with a dedicated key-path signature, or require verifiers/operators to check that the operator's own known change address/UTXO actually supplied the transaction's additional inputs before crediting `payout_payer_operator_xonly_pk`, rather than trusting an unsigned OP_RETURN field.

### Proof of Concept
1. Observe a pending Citrea withdrawal's `safeWithdraw` call, which publicly reveals `input_outpoint`, `output_script_pubkey`, `output_amount`, and the user's `SinglePlusAnyoneCanPay` `input_signature`.
2. Independently construct a `payout_tx`: input 0 = the withdrawal UTXO with the user's signature (unmodified, since ANYONECANPAY permits arbitrary extra inputs), output 0 = the user's payout (unmodified, SIGHASH_SINGLE only pins this output), an added input funded from the attacker's own wallet to cover the payout amount, and an OP_RETURN naming any target registered operator's `xonly_pk`.
3. Broadcast this transaction directly to the Bitcoin network (bypassing the target operator's `withdraw` RPC entirely).
4. Once confirmed, the verifiers' `update_finalized_payouts` records `payout_payer_operator_xonly_pk` = target operator, and the target operator's `PayoutCheckerTask` autonomously issues a kickoff and reimburse transaction, receiving `bridge_amount` from the move-to-vault UTXO for a withdrawal it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
