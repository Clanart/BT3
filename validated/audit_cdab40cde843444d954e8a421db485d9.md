### Title
Unauthenticated `.git/sg-reviewed-shas` marker file lets any local writer pre-forge "already reviewed" commits, silently bypassing the security-guidance LLM review — (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
The `security-guidance` plugin's commit/push review pipeline decides whether to run its LLM-based vulnerability scan on a commit by checking a **plain-text, unsigned, filesystem-writable** log at `.git/sg-reviewed-shas`. Any process capable of writing a file under the repo's `.git/` directory can append arbitrary 40-hex SHAs to that file, causing the hook to treat those commits as "already reviewed" and skip the LLM scan entirely — the same trust-boundary shape as the `JBTiered721Delegate` bug, where an attacker-controlled flag ("already initialized"/"already reviewed") lets a privileged step be silently skipped or spoofed.

### Finding Description
`_reviewed_shas_path`/`_load_reviewed_shas`/`_append_reviewed_shas` in `diffstate.py` implement an append-only, per-clone "reviewed" ledger with no cryptographic binding to the actual diff content that was reviewed — only the SHA string and unauthenticated metadata columns are stored: [1](#0-0) 

Writes to this file are unauthenticated and happen from a bare `open(p, "a")`/`fcntl.flock` pattern with no ownership, signature, or provenance check: [2](#0-1) 

Both consumers trust this file at face value to *skip* the LLM security review:
- `_compute_push_sweep_base` advances the diff base past any SHA present in the reviewed set, meaning a forged entry causes the corresponding commit range to never be diffed/reviewed at all: [3](#0-2) 
- `handle_push_sweep_posttooluse` calls this computation directly on the push range and exits early ("every pushed commit already reviewed") without ever invoking `analyze_code_security`/the agentic reviewer: [4](#0-3) 
- The per-commit reflog-fallback path also filters out any SHA already in this set before treating a commit as needing review: [5](#0-4) 

Git commit SHAs are deterministic hashes of tree, parent, author/committer identity+timestamp, and message — all attacker-controllable inputs (`git commit --date`, `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE`, exact message text). An attacker (or a compromised dependency, malicious pre-commit/postinstall script, or any tool-use path that can write a file — e.g., a prompt-injected instruction that gets Claude to write to `.git/`) can precompute the SHA of a commit they are about to make, append that SHA to `.git/sg-reviewed-shas` beforehand, then actually create the malicious commit. When it is later committed/pushed, the hook sees the SHA already "reviewed" and lets it through with zero LLM findings and zero user-visible warning — functionally identical to the referenced bug's pattern of an attacker priming trusted state before the real/legitimate flow observes it, so "it is like if nothing happened."

### Impact Explanation
This defeats the entire purpose of the `security-guidance` plugin's commit-review and push-sweep hooks: malicious or vulnerable code (hardcoded secrets, injection, backdoors) can be committed and pushed while being marked as already security-reviewed, with the tool reporting `vulns_found: 0`/silently skipping (`skip_reason` telemetry only, no stderr banner) instead of surfacing findings to the user. Because the file lives under `.git/` and persists "across sessions" per the code comments, a single forged entry poisons review coverage for that SHA indefinitely for that clone.

### Likelihood Explanation
Requires local filesystem write access to the target repo's `.git/` directory, which any local tool invocation, subagent, hook, build/CI script, or (most relevant to Claude Code's threat model) a prompt-injected instruction that induces Claude to write a file can obtain — this is the "unprivileged user" analog the same way the original finding only required deployer-level (not root) privilege. No cryptographic secret or elevated OS permission is needed; only ordinary file write capability within the working tree the agent already operates in.

### Recommendation
Do not trust an unauthenticated, plain file as a substitute for having actually run the review. At minimum:
- Bind each ledger entry to a hash of the diff content that was actually reviewed (not just the commit SHA), and re-verify that hash before honoring a "reviewed" skip.
- Store the ledger with an HMAC/signature keyed off a value the plugin controls (e.g., derived from the LLM response) so externally-written entries are rejected.
- Treat `.git/sg-reviewed-shas` as a cache/optimization only, never as a hard skip condition, and fall back to review whenever the entry cannot be cryptographically validated.

### Proof of Concept
1. In a repo with `security-guidance`'s push-sweep enabled, determine the next commit's SHA in advance by fixing author/committer/date/message (or trial-committing locally and inspecting the SHA before pushing).
2. Append `<precomputed-sha>\t<ts>\t<pv>\t0\n` to `.git/sg-reviewed-shas` (any local write path suffices — no special privilege is checked by `_append_reviewed_shas`/`_load_reviewed_shas`).
3. Make the real commit with the malicious payload matching that exact tree/metadata so its SHA equals the forged entry, then `git push`.
4. Observe `handle_push_sweep_posttooluse` → `_compute_push_sweep_base` treats the range as already covered and exits without calling the LLM reviewer, per [4](#0-3) ; no security findings are ever surfaced for the malicious commit.

_REVIEWED_SHAS_CAP = 500

def _reviewed_shas_path(repo_root):
    gd = _git_dir(repo_root)
    return os.path.join(gd, _REVIEWED_SHAS_BASENAME) if gd else None


def _load_reviewed_shas(repo_root):
    """Set of full 40-hex shas previously reviewed in this clone."""
    p = _reviewed_shas_path(repo_root)
    if not p or not os.path.exists(p):
        return set()
    out = set()
    try:
        with open(p, "r") as f:
            for line in f:
                sha = line.split("\t", 1)[0].strip()
                if len(sha) == 40 and all(c in "0123456789abcdef" for c in sha):
                    out.add(sha)
    except OSError:
        pass
    return out

def _append_reviewed_shas(repo_root, shas, vulns_found=0):
    """Record that `shas` were reviewed. Best-effort; never raises.

    Uses fcntl.flock for the read-gc-write; appends are O_APPEND-atomic but
    GC needs the lock so concurrent CC sessions in the same clone don't race
    each other's truncation.
    """
    p = _reviewed_shas_path(repo_root)
    if not p or not shas:
        return
    import time as _time
    ts = int(_time.time())
    pv = _PV or 0
    lines = [f"{s}\t{ts}\t{pv}\t{int(vulns_found)}\n" for s in shas]
    try:
        import fcntl
        with open(p, "a+") as f:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX)
            try:
                f.seek(0)
                existing = f.read().splitlines(keepends=True)
                # Dedup by sha (first column) — keep newest, then cap.
                seen = set()
                merged = []
                for ln in (existing + lines)[::-1]:
                    sha = ln.split("\t", 1)[0].strip()
                    if sha and sha not in seen:
                        seen.add(sha)
                        merged.append(ln if ln.endswith("\n") else ln + "\n")
                merged = merged[:_REVIEWED_SHAS_CAP][::-1]
                f.seek(0)
                f.truncate()
                f.writelines(merged)
            finally:
                fcntl.flock(f.fileno(), fcntl.LOCK_UN)
    except (OSError, ImportError):
        # fcntl unavailable (Windows) or write failed — degrade to plain
        # append; cap enforcement happens on the next locked write.
        try:
            with open(p, "a") as f:
                f.writelines(lines)
        except OSError:
            pass
```

def _compute_push_sweep_base(prev_upstream, push_range, reviewed):
    """Advance the diff base past the contiguous reviewed prefix.

    Spec: review `git diff B..HEAD` where `B` is the newest commit such that
    `prev_upstream..B` is entirely in `reviewed`. Returns (B, unreviewed_tail).
    `B == None` means the whole range is reviewed (caller should skip).
    `push_range` must be oldest→newest.

    Examples (✓=reviewed, ✗=not):
      [✓1, ✗2, ✓3]  → B=1, tail=[2,3]   (cannot trim suffix; Read is at HEAD)
      [✓1, ✓2, ✓3]  → B=None            (all reviewed → skip)
      [✗1, ✓2, ✗3]  → B=prev_upstream, tail=[1,2,3]
      []            → B=None
    """
    i = 0
    while i < len(push_range) and push_range[i] in reviewed:
        i += 1
    if i == len(push_range):
        return None, []
    base = push_range[i - 1] if i > 0 else prev_upstream
    return base, push_range[i:]
```
