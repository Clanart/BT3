### Title
Server-Side Request Forgery via unauthenticated on-chain DataLayer mirror URLs - (File: `chia/data_layer/download_data.py`)

### Summary
Any DataLayer coin owner can attach arbitrary URLs to a "mirror" coin (`create_mirror_puzzle()` / `dl_new_mirror`), which get recorded as CREATE_COIN memos and are later synced by every other subscribing DataLayer node's `update_subscriptions_from_wallet()`/`fetch_and_validate()` loop. The DataLayer service then issues an unauthenticated, server-side HTTP GET to that attacker-chosen URL with no host/scheme allow-listing, exactly analogous to the Shopware Admin SDK SSRF (GHSA-7gm7-8q8v-9gf2), where server-controlled remote-resource fetch functionality could be abused to reach internal resources.

### Finding Description
A DataLayer mirror coin's spend puzzle/solution encodes a `launcher_id` and an arbitrary list of URL byte-strings via `get_mirror_info()`: [1](#0-0) 

These URLs are written into the wallet's mirror tracking table with no validation on their contents (scheme, host, IP range) when the mirror coin is seen on-chain: [2](#0-1) 

`DataLayer.update_subscriptions_from_wallet()` simply flattens every mirror's URL list into the subscription's server list without filtering: [3](#0-2) 

`fetch_and_validate()` then randomly picks one of these `server_info.url` entries and performs an HTTP fetch against it via `insert_from_delta_file()` → `download_file()`: [4](#0-3) 

`download_file()`, when no external plugin `downloader` is configured, calls `http_download()`, which issues `session.get(server_info.url + "/" + filename, ...)` directly, with no restriction on the URL's host or scheme beyond what aiohttp itself accepts: [5](#0-4) 

The project's own internal documentation acknowledges these URLs are untrusted external input, but the described mitigation is limited to validating the *downloaded data* against wallet-advertised roots — not validating or restricting the destination URL itself before the request is made: [6](#0-5) 

Since anyone who can create/spend a mirror coin for a DataLayer store (a normal wallet operation reachable by any store owner via `add_mirror`) fully controls the URL string, they can set it to `http://127.0.0.1:<port>/...`, `http://169.254.169.254/...` (cloud metadata endpoint), or an internal-network address. Any node running a DataLayer service and subscribed to (or owning) that store will then issue a GET request to that destination from the server-side process — an unauthenticated SSRF primitive against the DataLayer host's local/internal network. RPC/CLI plumbing confirms mirror URLs are taken verbatim from caller-supplied input with only an empty-list check: [7](#0-6) 

### Impact Explanation
This grants any spend-bundle submitter with the ability to create a DataLayer mirror coin (store ownership is not required to inject URLs into another node's subscription/mirror sync — any confirmed mirror coin for a tracked launcher id is added regardless of who spent it, per `coin_added()` above) a way to force other DataLayer-running nodes to make outbound HTTP requests to arbitrary internal or loopback addresses. This can be used to probe internal services, hit cloud-provider metadata endpoints to steal instance credentials, or interact with internal-only management APIs reachable from the node's network position — a classic high-impact SSRF as in the referenced Shopware advisory.

### Likelihood Explanation
Likelihood is high for any relying party running the DataLayer service and subscribing to (or being the target of an unsolicited coin creation for) a store with attacker-controlled mirror URLs: the attacker only needs to spend a mirror-puzzle coin naming a `launcher_id` that a victim node tracks; no special privileges, signatures, or victim interaction beyond normal chain sync are required, and the request is fired automatically by the background `periodically_manage_data()`/`update_subscription()` loop.

### Recommendation
Validate and restrict mirror/server URLs before use for outbound HTTP fetches: enforce an allow-list of schemes (https/http only), reject loopback/link-local/private IP ranges (e.g. RFC1918, 127.0.0.0/8, 169.254.0.0/16, IPv6 equivalents) unless explicitly configured for local testing, and consider resolving DNS and re-checking resolved addresses to defeat DNS-rebinding before each `http_download()`/plugin-downloader POST call. Apply this validation both when persisting mirror URLs (`data_layer_wallet.py: coin_added`) and defensively again immediately before each request in `download_data.py`.

### Proof of Concept
1. Attacker creates/owns a DataLayer store or targets a `launcher_id` that a victim node subscribes to.
2. Attacker calls `add_mirror` (wallet RPC `dl_new_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` (or `http://127.0.0.1:<internal-port>/admin`), per `DataLayer.add_mirror()`.
3. Once the mirror coin is confirmed, any victim DataLayer node tracking that launcher id picks up the URL via `coin_added()` → `update_subscriptions_from_wallet()`.
4. On the victim's next sync cycle, `fetch_and_validate()` selects the malicious server and `http_download()` issues `GET http://169.254.169.254/.../` from the victim's server process, exfiltrating internal data/response content into the victim's logs/error messages or triggering internal side effects.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
