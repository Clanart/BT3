### Title
Coinbase outputs are reported as spendable before maturity - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Medium severity. `Scanner::scan_block` scans every transaction in a block, including the coinbase transaction at index 0, and returns matching outputs as ordinary `ReceivedOutput` values without tracking maturity or confirmation depth. [1](#0-0) 

### Finding Description
`scan_block` passes `block.txdata[0]` to `scan_transaction`, which emits a `ReceivedOutput` whenever an output’s `script_pubkey` matches a registered script. [2](#0-1)  `ReceivedOutput` only contains an offset, `TxOut`, and outpoint; it has no field distinguishing an immature coinbase output from a normally spendable output. [3](#0-2)  `SignableTransaction::new` then accepts supplied `ReceivedOutput` values as spendable inputs without checking whether their outpoints reference an immature coinbase. [4](#0-3) 

### Impact Explanation
A wallet or service that consumes `scan_block` can report a newly mined coinbase as received and immediately attempt to spend it. Bitcoin consensus rejects coinbase spends until the output reaches maturity, so the wallet reports funds as available even though transactions spending them are invalid. This matches the accepted impact of funds reported received that are not spendable and can cause automated wallet flows to construct and sign transactions that cannot be included. [5](#0-4) 

### Likelihood Explanation
Every valid Bitcoin block contains a coinbase transaction, so scanning the tip naturally reaches this path whenever the miner pays a watched script. No malicious validator, leaked key, malformed encoding, or special protocol privileges are required; a normal miner-controlled coinbase or ordinary block-processing path is sufficient. [1](#0-0) 

### Recommendation
Make output maturity explicit. `scan_block` should either skip `block.txdata[0]`, require enough subsequent confirmations before returning coinbase outputs, or return coinbase outputs with an immature status that `SignableTransaction::new` rejects. A caller-facing API should not return an immature coinbase as an indistinguishable spendable `ReceivedOutput`.

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
