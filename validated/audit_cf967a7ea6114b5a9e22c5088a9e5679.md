### Title
`SignableTransaction::new` omits the OP_RETURN data output from the fee/weight calculation, so signed transactions underpay the requested fee rate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs` appends an OP_RETURN output carrying caller-supplied `data` to `tx_outs`, but then computes the transaction weight/vbytes — and therefore `needed_fee` — via `calculate_weight_vbytes(tx_ins.len(), payments, ...)` which rebuilds a mock transaction containing only the payment outputs plus optionally the change output. The OP_RETURN output is never included in the fee estimation, analogous to M-02's accounting bug where a per-iteration/per-item cost is miscalculated inside batched-output logic.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is pushed onto `tx_outs` before the weight calculation:

- `tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(data) })` at `send.rs:194-202`.
- Fee estimation then calls `Self::calculate_weight_vbytes(tx_ins.len(), payments, None)` at `send.rs:204`, and again `Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change))` at `send.rs:225-226`.

Inside `calculate_weight_vbytes` (`send.rs:62-99`), the mock transaction's `output` list is built solely from `payments` plus an optional `change` output — there is no parameter for the data output, so its ~90+ bytes (8-byte value, script length, `OP_RETURN` + push opcode + up to 80 bytes of data, as permitted by the `data.len() > 80` check at `send.rs:171`) are excluded from `weight`/`vbytes`. Consequently `needed_fee = fee_per_vbyte * vbytes` (and the `TooLowFee` minimum-relay-fee check at `send.rs:211`) are computed against a smaller transaction than the one actually produced and signed.

When a change output exists, the change amount is `input_sat - payment_sat - fee_with_change`, so the sats that should have paid for the OP_RETURN output's weight are diverted into the change output, and the final transaction's effective fee rate is strictly below `fee_per_vbyte`.

### Impact Explanation
The signed transaction pays less than the requested fee rate. If the caller selects a `fee_per_vbyte` at or near the relay minimum (`DEFAULT_MIN_RELAY_TX_FEE`), the `TooLowFee` guard passes on the underestimated vbytes while the broadcast transaction falls below the minimum relay fee for its true size — the transaction will be rejected or stuck, and any dependent "branch" outputs/change are unspendable until replaced. `needed_fee()` also returns a value lower than the true required fee, so callers that amortize the reported fee across payments (as `Network::prepare_send`/`needed_fee` do) systematically under-account costs whenever a data output is present. This is a concrete incorrect-fee-formula/accounting error, not merely a best-practice issue.

### Likelihood Explanation
The trigger is any call to `SignableTransaction::new` with `Some(data)` — `data` is a public, caller-supplied byte string (up to 80 bytes), requiring no privileged access. The miscalculation is deterministic whenever `data` is non-empty; the severity of the outcome scales with how close the chosen `fee_per_vbyte` is to the relay minimum. (In-tree consumers in `processor/src/networks/bitcoin.rs` currently pass `None`, but the library API is in-scope and accepts untrusted data.)

### Recommendation
Include the OP_RETURN output in the weight calculation. Either add the data output into `calculate_weight_vbytes` (e.g., accept `data: Option<&[u8]>` and append the same `TxOut` to the mock transaction), or compute the weight directly on the fully populated `tx_outs`/`tx_ins` rather than reconstructing a partial mock transaction, ensuring `needed_fee`, the `TooLowFee` check, and the change deduction all reflect the final transaction's true vsize.

### Proof of Concept
At `send.rs:195-204`:

```rust
// Add the OP_RETURN output
if let Some(data) = data {
  tx_outs.push(TxOut {
    value: Amount::ZERO,
    script_pubkey: ScriptBuf::new_op_return(...),
  })
}

let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
```

`calculate_weight_vbytes` (`send.rs:68-99`) constructs `tx.output` only from `payments` (plus optional `change` at line 98). The `data` output already pushed to `tx_outs` is absent from the mock transaction, so `vbytes` — and `needed_fee = fee_per_vbyte * vbytes` — are computed for a strictly smaller transaction than the one stored in `SignableTransaction.tx` and later signed/broadcast. The same omission recurs in the change-enabled path at `send.rs:225-226`, meaning `fee_with_change` is also understated and the excess sats are incorrectly credited to the change output at `send.rs:230`.
