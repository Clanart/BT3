### Title
Last-block `vote()` sniping lets an attacker capture an entire epoch's bribe rewards with a momentary stake - (File: `wombat/WombatBribeManager.sol`, `rewards/BaseRewardPool.sol`)

### Summary
`vote(address[] _lps, int256[] _deltas)` lets any address with vlMGP immediately increase its stake in a pool's `IBribeRewardPool` via `stakeFor()`, and `castVotes()` is permissionlessly callable at any time with no minimum holding period between the two calls. Because bribe rewards are injected into the rewarder as a lump-sum, instantaneous pro-rata top-up (`rewardPerTokenStored += amount * 1e_dec / totalStaked()`), an attacker who calls `vote()` in the block immediately before `castVotes()` captures a full pro-rata share of the entire epoch's accrued bribes despite having held the position for a single block, diluting every voter who held their position for the whole epoch.

### Finding Description
`vote()` immediately calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta))`, which updates `_balances[msg.sender]` and `totalSupply` in the reward pool with no vesting or time-weighting: [1](#0-0) 

`castVotes()` is `public`, has no access control, and can be called by anyone at any time, right after an attacker's `vote()`: [2](#0-1) 

Bribe rewards harvested through `wombatStaking.vote()` are forwarded and eventually queued into each pool's `BribeRewardPool` via `queueNewRewards`/`donateRewards`, which calls `_provisionReward`. That function distributes the incoming reward amount over `rewardPerTokenStored` using the pool's **current** `totalStaked()` at the moment of the call — not a time-weighted or per-block accrual: [3](#0-2) 

`earned()` computes a user's share purely from `balanceOf(_account)` at the time `rewardPerToken` is queried, multiplied by the delta of `rewardPerTokenStored` since the user's last checkpoint: [4](#0-3) 

Because there is no minimum holding period, no reward-vesting linearization, and no checkpoint tied to elapsed time, a stake added one block before `_provisionReward` runs receives an equal share of the full reward lump sum as a stake that existed for the entire epoch. This directly dilutes the payout of every genuine, long-term voter of that pool. Existing checks (`PoolNotActive`, `NotEnoughVote`, `LengthMismatch`) only validate pool state and vlMGP capacity — none of them prevent a same-block or last-block stake-then-cast sequence.

### Impact Explanation
An attacker who locks market-bought MGP into vlMGP and calls `vote()` with a large positive `delta` on a pool immediately before (or in the same transaction bundle as, via `voteAndCast`) a `castVotes()` call receives a full pro-rata share of that pool's entire epoch of bribes. This is a direct transfer of value from long-term stakers to the attacker — a real economic loss of unclaimed yield for existing voters, matching "theft or permanent freezing of unclaimed yield" / "direct theft of user funds."

### Likelihood Explanation
- No privileged role is required; `vote()` and `castVotes()` (and the combined `voteAndCast()`) are public/external and unguarded.
- The attacker only needs vlMGP (obtainable by locking market-bought MGP) and awareness of a pending `castVotes()` call (mempool visibility or simply calling `voteAndCast()` itself, which calls `vote()` then `castVotes()` atomically in one transaction).
- The attack is repeatable every epoch/cast cycle and scales with the amount of vlMGP the attacker can acquire relative to `poolInfos[lp].totalVoteInVlmgp`.
- `voteAndCast()` makes this trivially executable in a single atomic transaction with no front-running risk at all: `vote(_lps, _deltas)` then `castVotes(swapForBnb)` in the same call. [5](#0-4) 

### Recommendation
Introduce a minimum holding/vesting period before newly staked vlMGP votes become eligible for the currently-pending bribe distribution, e.g.:
- Snapshot eligible stake at the start of an epoch/cast cycle and only distribute rewards for that cast to stakers whose position existed before the snapshot, or
- Linearly vest/stream each `_provisionReward` amount over a fixed duration (e.g., the average time between casts) instead of crediting it instantly to `rewardPerTokenStored`, or
- Enforce a minimum delay between a user's last `vote()` increase for a pool and their eligibility to receive rewards from the very next `castVotes()` for that pool.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `WombatBribeManager`, `BribeRewardPool` (or `BribeRewardPool`-derived), `WombatStaking`, mock `IWombatVoter`, `veWom`, `vlMGP`.
2. Set up pool `lp` with an existing long-term voter `Alice` who calls `vote([lp],[+1000e18])` at epoch start and holds for the whole epoch.
3. Simulate epoch bribes accruing in the mock Wombat voter/bribe contract for `lp`.
4. Immediately before calling `castVotes()`, have attacker `Mallory` lock freshly-bought MGP into vlMGP and call `vote([lp],[+1000e18])` (matching Alice's stake) in the same block, then call `castVotes(false)` (or use `voteAndCast` in one transaction).
5. Assert: `IBribeRewardPool(rewarder).earned(mallory, rewardToken) > 0` and roughly equal to `earned(alice, rewardToken)` despite Mallory holding the stake for 0 blocks vs. Alice's full epoch — demonstrating dilution/theft of Alice's accrued yield.
6. Assert `poolInfos[lp].totalVoteInVlmgp` doubled instantly due to Mallory's last-block vote, and `getVoteForLp(lp)` (Wombat voter) diverges from the pre-cast value used to compute the correct Alice-only bribe allocation.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
