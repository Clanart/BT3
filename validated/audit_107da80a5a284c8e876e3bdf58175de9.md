## Title
Spoofed `WWW-Authenticate: realm="GitHub"` Header From Untrusted Git Remote Triggers Enterprise Sign-In Flow Against Attacker Host, Leading To Credential Exfiltration - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The sherlock report's broken invariant is: a permission-classification function trusts an attacker-influenceable signal instead of verifying it against ground truth, causing privileged behavior to be routed incorrectly. In the NFT Port case, `update()`'s docstring promised `UPDATE_CONTRACT_ROLE` was sufficient, but the implementation silently required `ADMIN_ROLE` for the revoke path — a mismatch between the trust boundary a caller expects and the one actually enforced.

The Desktop analog is in the credential-helper trampoline's endpoint classification, `getEndpointKind` in [1](#0-0) , which classifies a remote as `'enterprise'` (a GitHub host) purely because the **server's own HTTP response** contained a `WWW-Authenticate` header with `realm="GitHub"` — a value fully controlled by whatever host git happens to be talking to, including a malicious or compromised git remote/proxy that is not actually GitHub or GitHub Enterprise.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes the configured credential helper (Desktop's trampoline, wired up in `withTrampolineEnv`, [2](#0-1) ) and forwards any `WWW-Authenticate` response headers it received from the *remote server* as `wwwauth[]=...` fields in the credential protocol input.

`getEndpointKind` uses this attacker-controlled header content as a classification signal: [3](#0-2) 

If none of the legitimate checks (`isGist`, `isDotCom`, `isGHE`, existing stored account match) apply, but the server-supplied header contains `realm="GitHub"`, the endpoint is classified `'enterprise'` — i.e., treated as a genuine GitHub Enterprise host — with no verification that the host is actually running GitHub Enterprise Server (no `/meta` check, no certificate/identity check, no allow-list).

That classification then drives `getCredential`: [4](#0-3) 

Because no account is on file for the attacker's arbitrary hostname, Desktop calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` set to the **attacker's host** (line 118). `promptForGitHubSignIn` then starts an Enterprise sign-in flow scoped to that attacker-controlled origin: [5](#0-4) 

This pops the standard "Sign in to GitHub Enterprise" dialog, pre-filled with the attacker's endpoint, and invites the user to authenticate. Nothing in this path re-validates that the target endpoint is a real, trusted GitHub Enterprise instance beyond the spoofable `realm="GitHub"` string the remote itself supplied.

### Impact Explanation
A user only has to `git fetch`/`git pull`/`git push` against a remote controlled by an attacker (a self-hosted "helpful mirror", a malicious HTTP proxy in front of the real remote, or a compromised remote/CDN) that responds with HTTP 401 and `WWW-Authenticate: Basic realm="GitHub"`. Desktop will interpret this as "this is a GitHub(-Enterprise) host" and surface a native sign-in dialog scoped to that attacker host. A user who trusts the Desktop-native sign-in UI and enters GitHub Enterprise credentials (username/password, or proceeds through browser OAuth pointed at the attacker's `origin`) sends authentication material directly to the attacker's server. This matches the "unauthorized OAuth or account binding" / "credential exfiltration" impact class: the attacker never needed local access, admin rights, or a leaked credential — only control of a git remote/proxy response, exactly one of the explicitly valid impact vectors.

### Likelihood Explanation
Likelihood is moderate-to-high in scenarios where users add unfamiliar or third-party git remotes/mirrors/proxies (common in corporate/self-hosted setups, forks, or supply-chain style remote substitution), because the trigger condition is a single, trivially-crafted HTTP response header — no MITM certificate manipulation or DNS control is required, since the attacker is the remote endpoint itself (or a proxy sitting directly in the path of a normal HTTPS `fetch`). The classification logic runs unconditionally on every failed credential lookup, and the “happy path” comment in the code even acknowledges this header is used specifically "without having to resort to making a request ourselves" — i.e., by design it forgoes independent verification.

### Recommendation
Do not classify an endpoint as `'enterprise'` based solely on an unauthenticated, remote-supplied `WWW-Authenticate` header. Require positive verification (e.g., hitting the well-known GHE `/meta` endpoint over the same TLS-validated connection, or requiring the host to already be present in the user's configured/allow-listed Enterprise accounts) before routing to `promptForGitHubSignIn`. At minimum, surface a clear warning in the sign-in dialog when the classification is only header-derived and the host has never been seen before.

### Proof of Concept
1. Attacker stands up a plain HTTPS git server (or transparent proxy in front of any git host) at `https://mirror.example.com/victim/repo.git`.
2. User adds this as a remote in a Desktop-managed repository and performs a `fetch`/`push`.
3. Git requests credentials; the attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Desktop's trampoline credential helper receives this via `wwwauth[]` in the credential-helper stdin protocol and `getEndpointKind` returns `'enterprise'` for `mirror.example.com` [6](#0-5) .
5. Since no account exists for `mirror.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://mirror.example.com')` [7](#0-6) , which opens a native "Sign in to GitHub Enterprise" dialog scoped to that origin [8](#0-7) .
6. A user who completes sign-in sends their GitHub Enterprise credentials/OAuth flow to the attacker-controlled `mirror.example.com`.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
