### Title
Consensus relay reward misattributed to first message's signer for every `StateMachineUpdated` event in a batch, allowing reward theft from other relayers/treasury drain - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::FeeHandler::on_executed` determines who gets paid for **every** consensus-update reward in a processed message batch by recovering the signer of only the **first** message in that batch, then iterating over **all** `StateMachineUpdated` events emitted by the whole batch to compute and pay rewards. Because `pallet-ismp`'s message-submission entrypoint (`handle_unsigned`) is permissionless and accepts an arbitrary `Vec<Message>` in a single call, any caller can bundle their own small consensus update (as message index 0, self-signed) together with other independently-valid consensus proofs for unrelated state machines. All resulting rewards for every chain advanced in that batch are paid to the account recovered from message 0, regardless of who actually produced/relayed the other proofs.

`events` here is the **full set of ISMP events emitted while processing the entire batch**, not scoped to `messages[0]`. `process_message` (lines 41-75) transfers `Reward = (latest_height - baseline) * cost_per_block` from the treasury to `relayer_account` for **each distinct state machine** advanced in the batch, and permanently advances `LastRewardedHeight` for that chain so no one else can be paid for those blocks again. [2](#0-1) 

The `signer` field embedded in every message *other than index 0* is never checked or used — only the first message's embedded signature determines the sole beneficiary for the whole batch's rewards.

Nothing in `pallet-ismp`'s message handling restricts a submitted batch to messages from a single relayer or to a single state machine — `handle_unsigned` is explicitly designed as a permissionless entrypoint accepting a `Vec<Message>` that can mix independent `Message::Consensus` entries for different chains. Valid consensus proofs (GRANDPA/BEEFY justifications, etc.) are public artifacts of the source chain's own finality process — any party can independently reconstruct or observe a proof another relayer intends to submit and repackage it inside their own batch.

### Impact Explanation
An attacker (any ordinary, otherwise-honest network participant — no malicious peer, prover, or compromised operator required) can:
1. Craft/submit their own trivial, self-signed consensus update for state machine A as `messages[0]`.
2. Append one or more already-public, independently-valid consensus proofs for state machines B, C, ... as `messages[1..]`, regardless of who originally produced them and regardless of the `signer` field they carry.
3. Submit the batch via the permissionless `handle_unsigned` extrinsic.

`on_executed` then pays the attacker's account the full `(latest_height - baseline) * cost_per_block` reward for **every** state machine advanced in the batch — not just A — draining `TreasuryAccount` funds meant for the true relayers of B, C, etc., and permanently moving `LastRewardedHeight` for those chains so the legitimate relayers who actually did the work receive zero reward for those blocks when they later submit the same (now redundant) update. This is a direct "wrong beneficiary" / fund-theft outcome against the protocol's own relayer-incentive treasury, exactly the class of bug the source report describes (crediting/penalizing based on unverified association between the reporting party and the reported work).

### Likelihood Explanation
High. The entrypoint is permissionless by design (`ensure_none` / unsigned), consensus proofs are public data usable by anyone who observes the tracked chains, and no code path checks that the signer recovered from message 0 has any relationship to the other messages/events in the same batch. This requires no admin, governance, relayer compromise, or private key theft — only ordinary batching of otherwise-legitimate data, which is squarely within scope as an unprivileged public-entrypoint attack.

### Recommendation
Attribute rewards per-message rather than per-batch: recover and verify the signer embedded in *each* `Message::Consensus` entry, and only credit the `StateMachineUpdated` event(s) that resulted from *that specific message's* processing to *that message's* recovered signer. If per-message-to-event attribution isn't directly available from `events`, restructure `handle_unsigned`/the message pipeline to pass event provenance (which message produced which event) into `FeeHandler::on_executed`, or reject/split batches containing more than one `Message::Consensus` before rewarding.

### Proof of Concept
1. Attacker holds a valid sr25519 keypair and monitors two Hyperbridge-tracked chains, X (cheap/no-op update) and Y (a chain another relayer, Bob, is about to relay).
2. Attacker observes/derives Bob's soon-to-be-submitted valid GRANDPA/BEEFY finality proof for chain Y (public chain data).
3. Attacker builds `Message::Consensus` #0 for chain X, embedding `signer` = signature over `keccak256(consensus_proof)` from the attacker's own key.
4. Attacker builds `Message::Consensus` #1 wrapping Y's valid proof, with an arbitrary/irrelevant `signer` field (never checked).
5. Attacker submits `vec![msg0, msg1]` via `pallet_ismp::handle_unsigned`.
6. Both consensus clients advance, emitting two `IsmpEvent::StateMachineUpdated` events (for X and Y).
7. `pallet_consensus_incentives::on_executed` recovers only the attacker's account from `msg0`, then pays the attacker rewards for **both** X's and Y's block-span advance from `TreasuryAccount`, and sets `LastRewardedHeight` for Y to the new height.
8. When Bob later submits the same Y proof (now stale relative to the watermark), `calculate_reward` for Y yields `blocks = latest_height.saturating_sub(baseline)` = 0, so Bob receives nothing for work he actually performed.

This can be exercised directly against the existing test harness in `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs` by submitting a batch of two independently-signed `Message::Consensus` entries for two different `state_machine_id`s in a single `handle_unsigned` call and asserting that the full combined reward lands on the account recovered from the first message only. 	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
