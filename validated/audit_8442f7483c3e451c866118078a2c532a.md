### Title
Unauthenticated OP_RETURN malleability breaks `is_kickoff_malicious` operator binding, burning honest operator collateral - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `Payout` transaction's user input signature uses `SinglePlusAnyoneCanPay`, which commits only to input 0 and output 0; the OP_RETURN output (index 2, carrying the fronting operator's x-only pubkey) is unauthenticated. An attacker (the withdrawing user, who fully controls the signature and its sighash flag) can take the honest operator's broadcast Payout tx and rebroadcast/replace it with an identical input/output0 but a corrupted OP_RETURN, causing `update_finalized_payouts` to persist `operator_xonly_pk = None`, which `is_kickoff_malicious` then treats as malicious for the honest operator's later correct kickoff.

### Finding Description
The claimed binding is: `kickoff_data.operator_xonly_pk` (operator that sent the kickoff) `==` operator recorded as having funded the withdrawal, derived from the mined Payout tx's OP_RETURN via `get_payout_info_from_move_txid`.

`create_payout_txhandler` builds the Payout tx with output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator_xonly_pk): [1](#0-0) 

The only signature covering the transaction is the user's, verified against `TapSighashType::SinglePlusAnyoneCanPay`, enforced in `parse_withdrawal_sig_params`/`withdraw`: [2](#0-1) [3](#0-2) 

`SIGHASH_SINGLE|ANYONECANPAY` commits only to input 0 and the output at the same index (output 0). Outputs 1 (anchor) and 2 (OP_RETURN) are not covered by any signature at all, so anyone who observes the unconfirmed Payout tx can re-serialize it with a mutated/removed OP_RETURN while keeping the same valid witness, and get that version mined instead (first-seen race or fee-bumped replacement of the anchor-funded, non-standard V3 tx).

When the block is synced, `update_finalized_payouts` parses the OP_RETURN of whatever version was mined: [4](#0-3) 
If parsing fails (`parse_op_return_data` returns `None` or `XOnlyPublicKey::from_slice` fails), `operator_xonly_pk` is `None` and gets persisted via `update_payout_txs_and_payer_operator_xonly_pk`, storing `NULL` in `withdrawals.payout_payer_operator_xonly_pk`: [5](#0-4) 

Later, when the honest operator (who actually fronted the withdrawal) sends its correctly-formed kickoff, `Verifier::is_kickoff_malicious` fetches this row and, seeing `operator_xonly_pk_opt.is_none()`, unconditionally treats the kickoff as malicious: [6](#0-5) 

This triggers a Challenge against the honest operator despite the operator that actually funded the withdrawal being identical to the operator that sent the kickoff — the equality holds in reality, but the on-chain proxy for it (the mined OP_RETURN) was corrupted post-signature by an unprivileged party.

No existing guard catches this: `is_deposit_valid`, `SECP.verify_schnorr` for the user signature, and `verify_storage_proofs`/citrea sync all validate different, unrelated bindings (deposit validity, user signature correctness, L2 withdrawal existence) — none of them re-derive or authenticate the OP_RETURN payload against the actual funding operator. The bridge circuit itself (`circuits-lib/src/bridge_circuit/mod.rs`) also `expect()`s a parsable OP_RETURN pubkey from the mined payout tx, so the honest operator cannot even construct a valid Disprove/assert proof to defend itself once the mined tx's OP_RETURN is corrupted — the same malleable field is load-bearing there too: [7](#0-6) 

### Impact Explanation
The honest operator's kickoff is judged malicious and challenged, and because the bridge circuit itself depends on the same corrupted, unauthenticated OP_RETURN field to build its disprove/assert proof, the operator cannot produce a valid defense — its round collateral is burned via Challenge/Disprove despite having correctly fronted the payout. This is repeatable per-withdrawal and per-operator by any user who initiates a withdrawal (attacker fully controls the withdrawal-input signature and sighash flag as an unprivileged actor), so the blast radius spans every future withdrawal an operator services. This matches the Critical impact category "an honest operator's collateral burned."

### Likelihood Explanation
Preconditions: the attacker only needs to be the withdrawing user (calls Citrea `withdraw`, supplies `in_signature`/sighash), observe the resulting operator Payout tx once broadcast/unconfirmed, and get a malleated (OP_RETURN-corrupted) version mined instead of the operator's original — feasible via first-seen mempool race or fee-bumped replacement since the Payout tx is a non-standard V3 tx with an ephemeral anchor for CPFP and the signature does not cover outputs 1/2. Cost is limited to normal fees; no key compromise, no majority hashrate, and no privileged role is required. This is deterministically repeatable against any operator servicing any withdrawal.

### Recommendation
Change the user's payout signature to cover the OP_RETURN output authenticating the fronting operator — e.g., use `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY` if additional inputs must remain fundable) so the OP_RETURN output committing `operator_xonly_pk` cannot be altered post-signature, or otherwise bind the operator identity to data the user signature covers before relying on it in `is_kickoff_malicious`/`update_finalized_payouts`.

### Proof of Concept
`cargo test` (regtest, `core/src/test`) plan:
1. Fund a deposit and withdrawal as in `deposit_and_withdraw_e2e.rs`; have the honest operator build and broadcast the Payout tx via `withdraw`.
2. Before confirmation, take the raw Payout tx, replace output 2's OP_RETURN script with non-parsable bytes (or remove it), keeping input 0/output 0/witness identical (signature remains valid because `SinglePlusAnyoneCanPay` does not cover output 2); rebroadcast/mine this malleated version first.
3. Run block sync so `update_finalized_payouts` stores `payout_payer_operator_xonly_pk = NULL` for that withdrawal idx — assert via `get_payout_info_from_move_txid` that `operator_xonly_pk_opt == None`.
4. Have the honest operator send its correctly-formed kickoff (correct `kickoff_data.operator_xonly_pk`, correct committed blockhash).
5. Assert `Verifier::handle_kickoff`/`is_kickoff_malicious` returns `true` and that a Challenge tx is sent against the honest operator, demonstrating the equality "operator that funded == operator that kicked off" holds logically but the malicious verdict fires anyway due to the unauthenticated OP_RETURN.

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
