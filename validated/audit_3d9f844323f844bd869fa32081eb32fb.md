## Analysis Summary

I found a valid analog. The bug class in the report — insufficient length validation before reading multi-byte fields from an attacker-controlled buffer, causing an out-of-bounds read/crash — maps directly onto `is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py`, which parses raw CLVM length-prefix bytes from an unprivileged spend bundle's puzzle reveal and solution without bounds-checking the offset against the buffer length.

### Title
Unbounded buffer read in `is_atom_canonical`/`is_clvm_canonical` causes unhandled exception on malformed spend-bundle CLVM data - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` parse the length-prefix encoding of a CLVM-serialized buffer (puzzle reveal / solution bytes) byte-by-byte, advancing an `offset` based on attacker-supplied length-prefix bits, but never verify that `offset` stays within `len(clvm_buffer)` before indexing into it.

### Finding Description
`is_atom_canonical` reads `clvm_buffer[offset]` to determine the prefix class, then reads up to 5 more bytes (`prefix_len`) via `clvm_buffer[offset]` in a loop to compute `atom_len`, with no check that these reads stay inside the buffer: [1](#0-0) 

`is_clvm_canonical` calls this in a `while True` loop, advancing `offset` by `1 + prefix_len + atom_len` for each atom, again without validating that the resulting `offset` is within bounds before the next iteration reads `clvm_buffer[offset]`: [2](#0-1) 

This is directly analogous to the sofia-sip bug: `stun_parse_attr_uint32`/`stun_parse_attr_error_code` read fixed-size fields from a length-prefixed STUN attribute without checking the attribute's declared length against the remaining buffer, causing OOB reads. Here, a truncated or crafted length-prefix byte (e.g., a 0xFC-0xFE-class prefix claiming a 5-byte extension) placed near the end of a puzzle_reveal/solution buffer causes `clvm_buffer[offset]` to be evaluated with `offset >= len(clvm_buffer)`.

### Impact Explanation
`is_clvm_canonical` is invoked on every coin spend's `puzzle_reveal` and `solution` bytes during mempool admission of any submitted `SpendBundle`, before any CLVM execution happens: [3](#0-2) 

Because Python raises `IndexError` on out-of-range `bytes` indexing (unlike a silent OOB read in C), a maliciously crafted spend bundle with a truncated/oversized atom length-prefix causes an unhandled `IndexError` inside `validate_spend_bundle()` instead of the intended graceful `Err.INVALID_COIN_SOLUTION` rejection. This is a spend-triggered exception in the mempool admission path reachable by any unprivileged network peer/wallet submitting a spend bundle, which can propagate up through the mempool manager's validation pipeline and disrupt transaction processing for that call path (denial-of-service class impact), rather than the intended safe rejection of the malformed spend.

### Likelihood Explanation
High reachability: any unprivileged spend-bundle submitter can trigger this by crafting a `puzzle_reveal` or `solution` whose bytes end mid-way through a multi-byte CLVM atom length-prefix (values `>= 0xC0`) or whose final atom's declared length overruns the buffer. No signature validity or special coin ownership is required to reach this code path — it executes unconditionally for every coin spend as part of DEDUP-eligibility processing before any signature/ownership checks matter.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each indexed read (verify `offset < len(clvm_buffer)` prior to reading the prefix byte and each of the `prefix_len` extension bytes), and in `is_clvm_canonical()`'s main loop before reading `clvm_buffer[offset]` on each iteration. On any bounds violation, return non-canonical (`False`) rather than raising, so the caller can convert it into `Err.INVALID_COIN_SOLUTION` as originally intended, matching the pattern already used elsewhere in the codebase (e.g., the explicit length checks in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`): [4](#0-3) 

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) ends with a truncated multi-byte atom length prefix, e.g. a final byte `0xF8` (2+8+8+8+8-bit length prefix class per `is_atom_canonical`, expecting 4 more bytes) placed as the very last byte of the buffer:

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
