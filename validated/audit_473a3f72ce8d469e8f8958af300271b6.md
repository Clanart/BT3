### Title
Bridge circuit never checks `TxOut.value` of the payout output, allowing a zero-value "payout" to produce an identical journal hash to a genuine full-value payout — ([File: circuits-lib/src/bridge_circuit/mod.rs])

### Summary
`bridge_circuit` only asserts that the payout transaction's designated input spends the exact outpoint (`txid`, `vout`) recorded on Citrea as the withdrawal identifier [1](#0-0) . It never reads or constrains the `value` field of any `TxOut` in `payout_spv.transaction`, so a transaction that spends the correct withdrawal outpoint but pays the withdrawer `Amount::ZERO` (or any arbitrary amount) produces the exact same committed `journal_hash` as one that pays the full amount.

### Finding Description
The claimed binding is: `journal_hash(honest_full_payment) == journal_hash(zero_value_payment)` given identical `deposit_constant`-relevant fields — this should NOT hold, but it does.

Tracing `bridge_circuit` (`circuits-lib/src/bridge_circuit/mod.rs:137-245`):
- The only checks tying the payout transaction to the withdrawal request are the two `assert_eq!` calls on `input.payout_spv.transaction.input[payout_input_index].previous_output.txid` and `.vout` against the outpoint (`user_wd_outpoint`, `vout`) recovered from the Citrea storage proof via `verify_storage_proofs` [2](#0-1) .
- `get_first_op_return_output` only extracts the operator's x-only pubkey from the OP_RETURN output; it never inspects any output's `value` [3](#0-2) [4](#0-3) .
- `deposit_constant` is built from `move_txid`, watchtower pubkeys digest, operator pubkey, `watchtower_challenge_connector_start_idx`, `round_txid`, `kickoff_round_vout`, and `genesis_state_hash` — no output value [5](#0-4) .
- `journal_hash` is built from `payout_tx_blockhash`, `latest_blockhash`, `challenge_sending_watchtowers`, and `deposit_constant` — again no output value [6](#0-5) .
- `verify_storage_proofs` itself only recovers the withdrawal outpoint's `txid`/`vout` and the deposit's `move_txid` from Citrea storage; it never reads or verifies a withdrawal *amount* field from Citrea storage [7](#0-6) .

Because none of the checked fields (`txid`, `vout`, OP_RETURN operator key, HCP, LCP, storage proof) encode the paid amount, the two scenarios described (zero-value output vs full-value output at the same index, all else equal) produce bit-identical journal hashes. The circuit's job is specifically to prove that an operator's claimed L1 payment satisfies the withdrawal request; by never binding the actual value transferred, it cannot distinguish "operator paid nothing" from "operator paid in full." None of the pre-existing guards close this gap: `verify_storage_proofs` only binds identity (outpoint/vout/move_txid), the watchtower/work comparison logic is orthogonal to payout value, and the SPV/LCP checks only prove chain inclusion, not payment amount.

### Impact Explanation
A malicious operator can broadcast a payout transaction that spends the correct withdrawal-identifying input but sends the withdrawer effectively nothing (or a token amount), then generate a bridge-circuit proof that is accepted identically to a genuine full payment. This matches "an operator reimbursed for a payout it never funded" — Critical impact — since the operator can subsequently claim full reimbursement from the bridge/kickoff flow for a withdrawal it did not actually fund. This is repeatable across every withdrawal handled by that operator (or any operator), since the missing check is structural in the circuit, not tied to a specific deposit.

### Likelihood Explanation
No special preconditions beyond being able to construct a syntactically valid `BridgeCircuitInput` with an internally consistent SPV/HCP/storage proof for a real (or crafted) withdrawal — something within reach of any party able to act as, or collude with, an operator. The cost is limited to the fee for broadcasting the low/zero-value payout transaction on Bitcoin; no watchtower or verifier logic outside this circuit currently blocks this specific value-omission at proof time. It is deterministic and fully reproducible without mainnet or a live Citrea node, since the circuit function and its inputs can be exercised directly in a unit test.

### Recommendation
Bind the payout output's `value` (and destination `script_pubkey`) into the circuit's checked/committed data: read the expected withdrawal amount (and destination) from the Citrea storage proof (extending `verify_storage_proofs`/the Bridge contract's stored withdrawal record) and add an explicit `assert_eq!` in `bridge_circuit` comparing it against `payout_spv.transaction.output[payout_output_index].value` (and `script_pubkey`), then fold that value into `deposit_constant` or `journal_hash` so that a zero/incorrect-value payout cannot produce the same journal hash as a genuine one.

```
#[test]
fn zero_value_payout_matches_full_value_payout_journal_hash() {
    // Build a valid BridgeCircuitInput `input_honest` from existing test fixtures
    // (wt_raw_tx.bin, kickoff_raw_tx.bin, storage_proof.bin, etc.), with
    // payout_spv.transaction.output[payout_output_index].value = <real withdrawal amount>.
    let input_honest = build_valid_bridge_circuit_input(/* full value */);

    // Clone and mutate only the payout output value to zero; keep txid, vout,
    // OP_RETURN, HCP, LCP, and all storage-proof-derived fields identical.
    let mut input_zero = input_honest.clone();
    input_zero.payout_spv.transaction.output[payout_output_index].value = Amount::ZERO;

    let guest_honest = MockZkvmGuest::new(input_honest);
    let guest_zero = MockZkvmGuest::new(input_zero);

    bridge_circuit(&guest_honest, *REGTEST_WORK_ONLY_IMAGE_ID);
    bridge_circuit(&guest_zero, *REGTEST_WORK_ONLY_IMAGE_ID);

    // Both sides of the binding: journal_hash(zero) should differ from journal_hash(full),
    // but currently they are identical, proving the vulnerability.
    assert_eq!(
        guest_honest.committed_journal_hash(),
        guest_zero.committed_journal_hash(),
        "journal hashes match despite zero-value payout — proof-soundness violated"
    );
}
```
This test invokes production code (`bridge_circuit`, `deposit_constant`, `journal_hash`) directly and demonstrates that the two committed journal hashes are bitwise identical despite the payout output value differing between "no payment" and "full payment."

```rust
pub fn deposit_constant(
    operator_xonlypk: [u8; 32],
    watchtower_challenge_connector_start_idx: u32,
    watchtower_pubkeys: &[[u8; 32]],
    move_txid: [u8; 32],
    round_txid: [u8; 32],
    kickoff_round_vout: u32,
    genesis_state_hash: [u8; 32],
) -> DepositConstant {
    // pubkeys are 32 bytes long
    let pubkey_concat = watchtower_pubkeys
        .iter()
        .flat_map(|pubkey| pubkey.to_vec())
        .collect::<Vec<u8>>();

    let watchtower_pubkeys_digest: [u8; 32] = Sha256::digest(&pubkey_concat).into();

    let pre_deposit_constant = [
        &move_txid,
        &watchtower_pubkeys_digest,
        &operator_xonlypk,
        &watchtower_challenge_connector_start_idx.to_be_bytes()[..],
        &round_txid,
        &kickoff_round_vout.to_be_bytes()[..],
        &genesis_state_hash,
    ]
    .concat();

    DepositConstant(Sha256::digest(&pre_deposit_constant).into())
}
```

```rust
pub fn journal_hash(
    payout_tx_blockhash: PayoutTxBlockhash,
    latest_blockhash: LatestBlockhash,
    challenge_sending_watchtowers: ChallengeSendingWatchtowers,
    deposit_constant: DepositConstant,
) -> blake3::Hash {
    let concatenated_data = [
        payout_tx_blockhash.0,
        latest_blockhash.0,
        challenge_sending_watchtowers.0,
    ]
    .concat();

    let binding = blake3::hash(&concatenated_data);
    let hash_bytes = binding.as_bytes();

    let concat_journal = [deposit_constant.0, *hash_bytes].concat();

    blake3::hash(&concat_journal)
}
```

```rust
pub fn verify_storage_proofs(
    storage_proof: &StorageProof,
    state_root: [u8; 32],
) -> (WithdrawalOutpointTxid, u32, MoveTxid) {
    let utxo_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_utxo)
            .expect("Failed to deserialize UTXO storage proof");

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}
```
