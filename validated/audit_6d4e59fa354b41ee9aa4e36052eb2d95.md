### Title
Unchecked `kip71.gastarget` governance parameter allows division-by-zero panic in base fee calculation, causing a chain-wide consensus halt - ([File: params/kip71_config.go])

### Summary
The `kip71.gastarget` governance parameter can be voted to `0` because its `FormatChecker` performs no validation, unlike the sibling parameter `kip71.basefeedenominator` which explicitly guards against zero. When `GasTarget` is `0` and applied to `NextMagmaBlockBaseFee`, any block with nonzero gas usage triggers a `big.Int` division by zero, which panics at runtime on every node computing the next base fee.

### Finding Description
`gov.Params[Kip71GasTarget]` sets `FormatChecker: noopFormatChecker`, which always returns `true`, imposing no bound on the vote value [1](#0-0) . In contrast, `Kip71BaseFeeDenominator` explicitly requires `v != 0` [2](#0-1) , and `params.KIP71Config.NextMagmaBlockBaseFee` even has an explicit zero-guard fallback for `BaseFeeDenominator` ("To avoid panic, set the fluctuation range small") but no equivalent guard for `GasTarget` [3](#0-2) .

`headerGovModule.checkConsistency`, which is the only additional semantic validation layer for governance votes, validates `Kip71LowerBoundBaseFee` against `UpperBoundBaseFee` and vice versa, but performs no check for `Kip71GasTarget`; it is simply passed through as always-valid alongside other unchecked parameters [4](#0-3) .

If `GasTarget` is set to `0` (via header governance vote or contract governance, both of which use the same `Params` format checkers [5](#0-4) ), then in `NextMagmaBlockBaseFee`, once any block has `parentGasUsed > 0`, the code takes the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` where `gasTarget == 0` [6](#0-5) . Go's `math/big.Int.Div` panics on division by zero. The same applies to the decreasing-baseFee branch [7](#0-6) .

### Impact Explanation
`NextMagmaBlockBaseFee` is called deterministically by every node — during block assembly (`work/worker.go`) and header verification (`blockchain/block_validator.go`) — for every post-Magma block. A zero `GasTarget` value applied via governance therefore causes every honest node to panic/crash when processing the very next non-empty block, resulting in a full network liveness halt (denial of service across the entire chain), not just a single validator or node. This is a severe, network-wide impact triggered by a single unchecked governance parameter value, analogous to the referenced `depositLimit = 0` issue but with consensus-halting consequences instead of a localized deposit block.

### Likelihood Explanation
Reaching this bug requires only a single vote/transaction setting `kip71.gastarget` to `0`, either through the header-governance vote API (`headergov.NewVoteData`/`Vote`) or through contract governance's `GovParam.setParam`, both of which route through the same unchecked `Params[Kip71GasTarget].FormatChecker`. No additional invariant blocks a zero value — `checkConsistency` explicitly treats it as always valid. This mirrors the exact bug class in the reference report: a privileged-but-reachable setter path lacking a minimal sanity check on a value that is later used unguarded.

### Recommendation
Add an explicit zero-value `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`, which is also divided/used unguarded), mirroring the existing `Kip71BaseFeeDenominator` check:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```
As defense in depth, also add a zero-guard fallback for `gasTarget` inside `NextMagmaBlockBaseFee`, matching the existing `BaseFeeDenominator == 0` fallback pattern [8](#0-7) .

### Proof of Concept
1. A governance voter (governing node in single mode, or GC member via `GovParam.setParam` in contract governance) casts `kip71.gastarget = 0`.
2. `NewVoteData`/`ParseContractCall` accepts it because `Kip71GasTarget.FormatChecker` is `noopFormatChecker` [1](#0-0) .
3. `headerGovModule.checkConsistency` passes it through with no error [4](#0-3) .
4. Once the vote activates and a subsequent block has `gasUsed > 0`, `KIP71Config.NextMagmaBlockBaseFee` executes `x.Div(x, new(big.Int).SetUint64(0))` [9](#0-8) , panicking on every node that computes/verifies the base fee for that block — halting the chain.
