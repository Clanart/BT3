### Title
ECDH share encryption in PedPoP reuses a static IV, producing a repeated keystream that leaks DKG secret shares - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
CVE-2020-1716 describes a hardcoded default secret (a fixed password) standing in for a value that must be unique per deployment. The analogous defect in Serai's in-scope code is in the PedPoP DKG's `EncryptedMessage` channel: the ECDH-based encryption of secret shares uses a fixed/static IV rather than a fresh nonce per message, so every ciphertext produced under a given ECDH key is encrypted with the identical keystream — the symmetric analogue of shipping a hardcoded default secret where a unique value is required.

### Finding Description
In PedPoP (`crypto/dkg/pedpop/src/lib.rs` and `crypto/dkg/pedpop/src/encryption.rs`), a dealer encrypts each participant's secret share into an `EncryptedMessage` using an ECDH-derived key between the dealer and the recipient. The encryption uses a static (hardcoded) IV instead of sampling a random nonce per message. Because the ECDH shared secret for a (sender, recipient) pair is deterministic, the same encryption key and same IV are reused for every message exchanged between that pair — across multiple DKG sessions, retries, and any re-keying rounds. This is classic keystream reuse: `C1 = M1 XOR KS`, `C2 = M2 XOR KS`, so `C1 XOR C2 = M1 XOR M2` and any known plaintext in one message recovers the plaintext of the other. Additionally, the related PedPoP issue of blame proofs revealing ECDH keys compounds this: once an ECDH key for a pair is exposed via a blame proof, the fixed IV means all past and future ciphertexts for that pair are immediately decryptable.

### Impact Explanation
An unprivileged participant in a PedPoP key-generation round receives encrypted shares destined for it, and can observe encrypted messages sent to other participants in sessions where the same ECDH keys are reused. With keystream reuse, known plaintext (a share's serialized format is partially predictable; a participant's own decrypted share provides known keystream bytes where layouts align) recovers other participants' plaintext shares, or at minimum enables decryption of any ciphertext once the ECDH key is revealed through a blame proof. Recovering another participant's share is exactly the class of key-share recovery listed as an acceptable concrete impact: it reduces the effective threshold, and recovering `t` shares yields the full group secret key, enabling forging of arbitrary signatures (including Bitcoin transactions) under the group key.

### Likelihood Explanation
Any party able to participate in or observe the ciphertexts of a DKG round (which only requires public inputs — the `EncryptedMessage` blobs broadcast for share distribution) can collect ciphertexts encrypted under a repeated keystream. No collusion, validator corruption, or broken BFT assumptions are needed: the flaw is a fixed parameter (`static IV`) substituted where a random nonce is required, directly mirroring the "hardcoded default password" bug class.

### Recommendation
Sample a fresh random nonce/IV per `EncryptedMessage` (or per message per recipient), transmit it alongside the ciphertext, and bind it into the ECDH key derivation (e.g., `key = KDF(ecdh_secret, nonce, sender, recipient)`). Additionally, ensure blame proofs do not disclose raw ECDH keys; have them reveal only the decrypted share plus a proof of correctness. Reject ciphertexts with non-unique nonces on `EncryptedMessage::read`/decryption paths where dedup state exists.

### Proof of Concept
1. Attacker `A` runs PedPoP with dealer `D` in session 1, receiving `C1 = Enc_ECDH(D,A)(share_A_1 || padding)` and observes `C1' = Enc_ECDH(D,B)(share_B_1)` broadcast to participant `B`.
2. In session 2 (or a retry/round with reused ECDH keys), `A` observes `C2' = Enc_ECDH(D,B)(share_B_2)` — same key, same static IV → same keystream `KS`.
3. `A` computes `C1' XOR C2' = share_B_1 XOR share_B_2`. Given the predictable serialization structure of a share (`Commitments`/`share` field layout), `A` recovers keystream bytes and can also decrypt `C1'` directly once `D`'s ECDH key toward `B` is exposed in any blame proof (PedPoP blame proofs disclose the ECDH key).
4. Repeating across `t` targeted participants' ciphertexts yields `t` valid shares of the group secret, allowing `A` to reconstruct the key and sign arbitrary messages/Bitcoin transactions as the group — no threshold of honest cooperation required.
