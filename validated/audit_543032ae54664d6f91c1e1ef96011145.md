## Finding

The exact analog to the Permit2 `permit` nonce bug exists in GitHub Desktop's SSH credential bookkeeping.

### Title
Single-slot SSH credential tracking causes silent credential-store corruption for multi-host Git operations - (File: `app/src/lib/ssh/ssh-credential-storage.ts`)

### Summary
The Permit2 bug stems from a value (`nonce`) that must be scoped per `(owner, token, spender)` but is instead tracked as a single global value, so a second distinct pair collides with/overwrites the first. GitHub Desktop has the identical structural flaw in its SSH "pending credential" bookkeeping: `mostRecentSSHCredentials` is a `Map` keyed **only** by `operationGUID` (the trampoline token for one Git subprocess invocation), even though a single Git invocation can legitimately prompt for **multiple distinct SSH credentials** (different keys/hosts) when submodules are involved.

### Finding Description
`mostRecentSSHCredentials` in [1](#0-0)  stores at most one pending `{store, key}` entry per `operationGUID`. Both `setSSHKeyPassphrase`/`setMostRecentSSHKeyPassphrase` [2](#0-1)  and the analogous SSH user-password helpers write into this same map keyed by `operationGUID` alone, and `setMostRecentSSHCredential` unconditionally overwrites whatever was previously stored for that key: [3](#0-2) .

A single Git operation (one `operationGUID`/trampoline token, created once per `git()`/`spawnGit()` call in [4](#0-3) ) can involve **multiple SSH askpass prompts for different keys or hosts** — e.g. a `fetch`/`pull --recurse-submodules` operation (referenced in `app/src/lib/git/fetch.ts`, `app/src/lib/git/pull.ts`, `app/src/lib/git/submodule.ts`) where the superproject and one or more submodules live on different SSH remotes/keys. Each askpass prompt for a new key calls `handleSSHKeyPassphrase(operationGUID, prompt)` [5](#0-4) , which calls `setMostRecentSSHKeyPassphrase(operationGUID, keyPath)`/`setSSHKeyPassphrase(operationGUID, keyPath, passphrase)` — silently clobbering the entry for the *previous* key under the *same* `operationGUID`.

If the overall Git operation ultimately fails with an SSH auth error, `withTrampolineEnv`'s catch block calls `deleteMostRecentSSHCredential(token)` exactly once [6](#0-5) , which looks up **only the last entry** in the map: [7](#0-6) . This is structurally identical to the report's "global nonce instead of per-(owner,token,spender)" flaw: the bookkeeping key is missing a dimension (the specific SSH key/host) that the underlying operation actually varies over.

### Impact Explanation
When a rejected/incorrect credential was entered for the *first* key used during a multi-key operation (e.g. wrong passphrase for the superproject's deploy key) but a *different, correct* key was subsequently used for a submodule, and the overall operation still fails (e.g. due to the first key's failure):
- The wrong passphrase for the first key is **never deleted** from the OS credential store (keytar/keychain), because the map entry it stored was already overwritten by the second key's entry.
- The correct/valid passphrase for the second (unrelated) key is deleted instead, since it's the one left in the single-slot map.

This is silent corruption of the user's persisted Git credential state: a bad SSH key passphrase becomes "sticky" (repeatedly offered/attempted by future operations) and a good, unrelated credential for a different remote/submodule is erased without the user's knowledge or consent — undermining the very re-prompt/cleanup logic this code exists to provide. This is triggerable purely by cloning/fetching a repository the attacker controls (via `.gitmodules` pointing to a second SSH host requiring different credentials), fitting the "attacker controls a cloned/fetched repository" impact class and resulting in silent corruption of locally stored credential state.

### Likelihood Explanation
This requires: (1) SSH-based remotes for both the main repository and at least one submodule pointing to a different host/key, and (2) the user going through the askpass flow for more than one key within a single Git invocation, with the operation ultimately failing. This is a real, previously-acknowledged class of bug in this exact code path — the changelog shows two prior fixes for related "wrong SSH key passphrases are not stored"/"stored after multiple attempts" issues (`#12800`, `#12804`) [8](#0-7) , confirming the map's single-slot-per-operation design has a documented history of exactly this class of collision, and the current code still keys `mostRecentSSHCredentials` by `operationGUID` alone with no per-key/store dimension.

### Recommendation
Key `mostRecentSSHCredentials` by `(operationGUID, store, key)` (e.g. a composite string key or a `Map<string, Map<string,string>>`/`Map<string, SSHCredentialEntry[]>`) so that every credential offered during a single Git operation is tracked and can be individually deleted on failure, instead of only the most recently set one. `deleteMostRecentSSHCredential(operationGUID)` should iterate and delete all pending entries for that operation, not just the last.

### Proof of Concept
1. Prepare a malicious repository whose `.gitmodules` references a submodule hosted on a second SSH remote requiring a different deploy key/passphrase than the superproject.
2. Victim clones/fetches this repository with `--recurse-submodules` (or Desktop's submodule update flow) using SSH.
3. During the single Git invocation (one `operationGUID`):
   - Git prompts for passphrase of Key A (superproject). User enters an incorrect passphrase and checks "remember." `setMostRecentSSHKeyPassphrase(token, keyPathA)` stores `{store, hashA}` under `token`.
   - Git prompts for passphrase of Key B (submodule). User enters the correct passphrase and checks "remember." `setMostRecentSSHKeyPassphrase(token, keyPathB)` overwrites the map entry for `token` with `{store, hashB}`.
4. Overall operation fails (Key A's incorrect passphrase caused an auth failure upstream). `withTrampolineEnv`'s catch handler calls `deleteMostRecentSSHCredential(token)`, which deletes the credential for Key B (correct) from the keychain, while Key A's incorrect passphrase remains permanently stored and will be silently reused/reoffered on subsequent operations against that host.

```typescript
async function handleSSHKeyPassphrase(
  operationGUID: string,
  prompt: string
): Promise<string | undefined> {
  const promptRegex = /^Enter passphrase for key '(.+)': $/

  const matches = promptRegex.exec(prompt)
  if (matches === null || matches.length < 2) {
    return undefined
  }

  let keyPath = matches[1]

  // The ssh bundled with Desktop on Windows, for some reason, provides Unix-like
  // paths for the keys (e.g. /c/Users/.../id_rsa). We need to convert them to
  // Windows-like paths (e.g. C:\Users\...\id_rsa).
  if (__WIN32__ && /^\/\w\//.test(keyPath)) {
    const driveLetter = keyPath[1]
    keyPath = keyPath.slice(2)
    keyPath = `${driveLetter}:${keyPath}`
  }

  const storedPassphrase = await getSSHKeyPassphrase(keyPath)
  if (storedPassphrase !== null) {
    // Keep this stored passphrase around in case it's not valid and we need to
    // delete it if the git operation fails to authenticate.
    await setMostRecentSSHKeyPassphrase(operationGUID, keyPath)
    return storedPassphrase
  }

  if (getIsBackgroundTaskEnvironment(operationGUID)) {
    log.debug(
      'handleSSHKeyPassphrase: background task environment, skipping prompt'
    )
    return undefined
  }

  const { secret: passphrase, storeSecret: storePassphrase } =
    await trampolineUIHelper.promptSSHKeyPassphrase(keyPath)

  // If the user wanted us to remember the passphrase, we'll keep it around to
  // store it later if the git operation succeeds.
  // However, when running a git command, it's possible that the user will need
  // to enter the passphrase multiple times if there are failed attempts.
  // Because of that, we need to remove any pending passphrases to be stored
  // when, in one of those multiple attempts, the user chooses NOT to remember
  // the passphrase.
  if (passphrase !== undefined && storePassphrase) {
    setSSHKeyPassphrase(operationGUID, keyPath, passphrase)
  } else {
    removeMostRecentSSHCredential(operationGUID)
  }

  return passphrase ?? ''
}
```
