Confirmed: `ModuleMetadata` (defined in `code.move`) stores only `name`, `source` (gzipped source text), `source_map`, and `extension` — it never stores the actual on-chain module bytecode bytes. This is the concrete evidence that makes `VerifyPackage::execute` a real, exploitable analog of the "withdraw sends everything instead of the requested amount" bug class: the function claims to verify that on-chain bytecode matches local source, but the actual comparison never touches bytecode.

### Title
`aptos move verify-package` validates package metadata but never compares actual on-chain module bytecode - ([File: aptos-move/cli/src/commands.rs])

### Summary
The Aptos CLI's `verify-package` command is documented as checking "that on-chain bytecode matches a local source tree" [1](#0-0)  but its implementation only compares `PackageMetadata` fields (name, deps, `ModuleMetadata` list, manifest, upgrade policy, extension, source digest) between the locally-built package and the on-chain registry — it never fetches or diffs the raw compiled module bytecode.

### Finding Description
`VerifyPackage::execute` builds the package locally, extracts its metadata, fetches the on-chain `PackageRegistry` via `CachedPackageRegistry::create(client, self.account, false)` (note the `false` for `with_bytecode`), and calls `package.verify(&compiled_metadata)`: [2](#0-1) 

`CachedPackageRegistry::create` only downloads module bytecode when `with_bytecode` is `true`: [3](#0-2) 

`verify()` compares `name`, `deps`, `modules` (i.e., `ModuleMetadata` entries), `manifest`, `upgrade_policy`, `extension`, and `source_digest`: [4](#0-3) 

Crucially, `ModuleMetadata` only carries the module's `name`, a gzipped copy of the `source` text, a `source_map`, and an `extension` field — it contains no field for the compiled bytecode itself: [5](#0-4) 

So the "verification" is really a metadata-and-source-text comparison. It never re-derives or fetches the actual `.mv` bytecode published at the account and compares it byte-for-byte against what a compilation of the verified source would produce. The `source_digest` field is computed by the *publisher* at publish time from their own local sources (sha256 of each source file, sorted, then hashed again) [6](#0-5)  and stored as untrusted, self-reported metadata alongside the code, not derived from or checked against the deployed bytecode by the verifier or the VM. Nothing in the on-chain `publish_package` path cross-checks that `source_digest`/`ModuleMetadata.source` corresponds to the actual bytecode bytes being published [7](#0-6) .

This mirrors the report's bug class: a function/flow is supposed to operate on (verify) an exact quantity/artifact (the deployed bytecode) but instead operates on/reports a different, broader-but-unrelated quantity (metadata fields), silently producing a false sense of assurance rather than a wrong balance.

### Impact Explanation
A malicious or compromised package publisher can publish arbitrary bytecode under a `PackageMetadata`/`ModuleMetadata` whose `source`/`source_digest` describe innocuous or different source code. Anyone relying on `aptos move verify-package` (auditors, downstream integrators deciding whether to trust/depend on a package, CI pipelines gating deployments) will see "Successfully verified source of package" even though the deployed bytecode does not match the claimed/reviewed source. This directly satisfies the Publish Impact Gate's "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes" and can facilitate deploying forbidden/malicious bytecode that passes verification checks used to gate trust decisions.

### Likelihood Explanation
High under normal, permissionless usage: no privileged assumption is required — any account can publish a package with mismatched bytecode/source, and any third party who runs `verify-package` (as documented, for "code review and reproducibility") will get a false-positive success result. The bug requires no race condition or governance action, just standard publish + verify usage.

### Recommendation
`verify()` should fetch and byte-compare the actual on-chain module bytecode against the bytecode produced by compiling the local source (i.e., always use `with_bytecode = true` in `CachedPackageRegistry::create` inside `VerifyPackage::execute`, and add a bytecode-equality check per module to `CachedPackageMetadata::verify`), rather than relying solely on self-reported `source_digest`/`ModuleMetadata` fields.

### Proof of Concept
1. Author `module.move` with content A.
2. Compile it, but before publishing, hand-craft/publish a `PackageMetadata`/`code` bundle where the `code` vector contains different bytecode (module content B) while `ModuleMetadata.source`/`source_digest` still reflect content A's gzip/hash (or simply publish B while regenerating a `source_digest` computed over A's source files, since the chain does not check bytecode against `source_digest`).
3. Run `aptos move verify-package --account <addr>` against local source A.
4. Observe: `package.verify(&compiled_metadata)` succeeds ("Successfully verified source of package") even though the deployed bytecode is B, not the local source A that was verified — because `CachedPackageRegistry::create(..., false)` never downloaded bytecode and `verify()` never compares it.

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;

        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {

                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension

            bail!(

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
