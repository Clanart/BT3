### Title
`SignableTransaction`/`TransactionSignMachine` trust the value claimed inside a deserialized `ReceivedOutput`, signing transactions whose declared input amounts are not verified — (File: networks/bitcoin/src/wallet/send.rs, networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class of the reference report — a function schedules/commits a declared amount of value without checking the value was actually supplied (`setConcRewards`/`setAmbRewards` take `weeklyReward` without a `msg.value` check) — exists in `bitcoin-serai`. A `ReceivedOutput` carries an attacker-controlled `TxOut` (including `value`) deserialized by `ReceivedOutput::read`. `SignableTransaction::new` sums these claimed values to budget payments/fee, and `TransactionSignMachine::sign` commits to them via `Prevouts::All` without ever validating that the claimed `value` matches the real on-chain UTXO. The only check performed (`SignableTransaction::multisig`) verifies the `script_pubkey` corresponds to the offset group key — the amount is trusted blindly, exactly as the Canto functions trusted `weeklyReward`.

### Finding Description
`ReceivedOutput::read` deserializes an offset scalar, a full `TxOut`, and an `OutPoint` from untrusted bytes with no authentication of `value` (networks/bitcoin/src/wallet/mod.rs:120-134). `SignableTransaction::new` computes `input_sat` purely from these claimed values (send.rs:175) and uses it to decide affordability and the change amount (send.rs:215-235). At signing time, `TransactionSignMachine::sign` builds `Prevouts::All(&self.tx.prevouts)` — committing each input's *claimed* `value` into the BIP-341 sighash (send.rs:373-390). `multisig` only confirms `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` (send.rs:277-279); the amount is never checked.

Two asymmetric consequences:

- **Underestimated value** (claimed `value` < real UTXO value): the sighash is still valid (Bitcoin consensus validates signatures against the committed prevout values, and the real UTXO is worth more), so the threshold network produces a *valid* transaction that silently pays `real - claimed` to miners as excess fee. Funds are burned.
- **Overestimated value** (claimed `value` > real): the produced transaction is invalid and unbroadcastable — accounting/fee logic (`fee()`, `needed_fee`) reports funds available that are not, i.e., "funds reported received that are not spendable."

### Impact Explanation
An attacker able to supply `ReceivedOutput` bytes (the explicitly permitted untrusted-input path for `ReceivedOutput::read`) to a signer can cause the threshold group to produce a validly-signed transaction that destroys value as miner fees — a rug-pull analogue where value disappears without the signers' intent — or produce permanently-invalid transactions that lock the pending payments. Fund loss via fee burning maps to Medium severity.

### Likelihood Explanation
The `ReceivedOutput` deserialization path is trusted despite being byte-driven: the struct's `value` field flows directly into both economic budgeting and the signature commitment with zero integrity checks. No code anywhere compares the claimed `TxOut` against the chain UTXO set; correctness depends entirely on the bytes being honestly produced by `Scanner::scan_transaction` (mod.rs:199-214). Any feed of tampered bytes reaches `sign` unimpeded.

### Recommendation
When constructing a `SignableTransaction` from externally-sourced `ReceivedOutput`s, authenticate the claimed value — e.g., have signers independently re-scan the referenced outpoint, or commit a hash of the full `ReceivedOutput` set into the signing transcript so all participants provably agree on the same claimed prevout values before producing shares. Reject outputs whose `value` cannot be corroborated rather than committing the attacker-supplied amount into `Prevouts::All`.

### Proof of Concept
1. Send a real 1 BTC P2TR output to `p2tr_script_buf(offset_key)` so the `multisig` script check will pass.
2. Craft `ReceivedOutput` bytes via `ReceivedOutput::read` with the genuine `outpoint` and `script_pubkey`, but `output.value = 0.5 BTC`.
3. Call `SignableTransaction::new(vec![forged], &payments, change, None, fee)` — it passes all checks since `input_sat` is taken at face value; `multisig` passes because the script matches the offset key.
4. `preprocess`/`sign`/`complete` produce a valid signed transaction whose sighash commits to 0.5 BTC while spending a 1 BTC UTXO; the ~0.5 BTC delta is paid as fee and irrecoverably burned.

Alternatively, craft `value` inflated above the real UTXO: signers produce shares over `Prevouts::All` claiming nonexistent funds, yielding an unspendable transaction — reported-inputs that are not actually spendable. [1](#0-0) [2](#0-1) [3](#0-2)
