### Title
Permissionless, unbounded growth of the EVM pointer/tokenfactory registry causes a chain-halting upgrade migration - (File: x/evm/migrations/migrate_all_pointers.go)

### Summary
`AddCW20Pointer`/`AddCW721Pointer`/`AddCW1155Pointer`/`AddNativePointer` on the Pointer precompile are callable by any EVM caller with no cap on how many distinct pointer entries can be registered, and each successful call permanently writes an entry into the `PointerRegistryPrefix` KV space. [1](#0-0)  Analogously, `x/tokenfactory` `CreateDenom` lets any account create arbitrarily many sub-denoms with no global or per-creator limit, each appended to the creator's iteration prefix store. [2](#0-1)  Both registries are later consumed by unbounded, non-resumable, gas-unmetered `for` loops that run during chain upgrades: `x/evm/migrations/migrate_all_pointers.go` iterates every pointer entry and performs an EVM contract query plus a `wasmd` contract migration per entry, [3](#0-2)  and `x/tokenfactory/keeper/migrations.go`'s `Migrate3to4` iterates every denom created via `CreateDenom`. [4](#0-3)  This mirrors the reported `TwapOracle.update` bug class: an unbounded, permanently-growing collection with no removal/paging mechanism that is later processed in a single all-or-nothing loop, which can render the processing step unable to complete.

### Finding Description
The Pointer precompile lets any EVM account register CW20/CW721/CW1155/native pointers without any global limit; each call stores a new entry keyed under `PointerRegistryPrefix` and its type-specific sub-prefix. [5](#0-4)  There is no method to deregister a pointer and no bound on total pointer count — a user can call `addCW20Pointer` (or the other variants) against arbitrary pointee addresses/CW contracts repeatedly, each time producing a fresh, permanently-stored registry key. [1](#0-0) 

When the chain performs an in-place store migration for the EVM module (an upgrade handler operation, which by Cosmos SDK convention runs with an effectively unmetered/very high gas limit for `BeginBlock`), `MigrateERCNativePointers`, `MigrateERCCW20Pointers`, `MigrateERCCW1155Pointers`, `MigrateCWERC20Pointers`, `MigrateCWERC721Pointers`, and `MigrateCWERC1155Pointers` each open a `ReverseIterator` over the *entire* pointer prefix and, for every entry, perform expensive per-item work: an EVM contract call (`QueryERCSingleOutput`), a one-off EVM instance execution (`RunWithOneOffEVMInstance`), or a `wasmd` contract `Migrate` call. [6](#0-5) [7](#0-6)  None of these loops are batched, paginated, or resumable across blocks — they must run to completion within one upgrade block on every validator.

Similarly, `x/tokenfactory`'s `Migrate3to4` iterates every denom ever created via the fully permissionless `CreateDenom` entrypoint, [8](#0-7)  calling `bankKeeper.GetDenomMetaData`/`SetDenomMetaData` per denom with no cap. [4](#0-3) 

Because pointer/denom creation is unprivileged and unbounded, and the corresponding registry is consumed by a single non-resumable loop during a chain upgrade that all validators must execute identically at the same height, an attacker can pre-seed the registry with an enormous number of entries (each cheap to create individually, subject only to per-transaction EVM gas) so that at the next upgrade height the migration loop takes an infeasible amount of time/resources (each iteration does an EVM call + contract creation, or a `wasmd` `Migrate` call) — causing the upgrade block to stall past consensus timeouts on every validator simultaneously, i.e., a chain-wide halt at the upgrade boundary.

### Impact Explanation
This matches "validator halt" / "block delay beyond 2.5 seconds" criteria: because the migration loop is deterministic and must execute identically on every validator during the same upgrade block, and per-entry cost includes EVM contract execution or wasm contract migration (not just a cheap KV read), an attacker-inflated registry can push single-block processing time far past normal block times, stalling the entire network at the upgrade height with no way to skip or resume the affected entries (the loops have no batching/continuation logic, unlike, e.g., `x/evm`'s `PruneZeroStorageSlots`, which is explicitly resumable/batched). [9](#0-8) 

### Likelihood Explanation
Likelihood is constrained by the fact that the impact only manifests at the moment the chain operators trigger the specific upgrade handler that runs these migrations (a node-operator-controlled event), so the attacker must seed the state ahead of a known/scheduled upgrade. However, seeding is entirely unprivileged and cheap (bounded only by per-tx EVM gas, and creation is naturally spread over many blocks/transactions), and the attacker does not need any special access — this differs from the "operator-only" or "governance" exclusions in that the *vulnerable growth path* itself is fully open to any unprivileged sender; only the trigger (an upgrade) is operator-controlled, similar to how the original TwapOracle bug also required the "trigger" (an `update()` call) but the root cause (unbounded registration) was what mattered for severity.

### Recommendation
- Add a maximum cap on the number of pointer registrations (globally and/or per token) and on the number of tokenfactory sub-denoms per creator, enforced at creation time (mirrors the `DenomAllowlistMaxSize` pattern already used elsewhere in tokenfactory params). [10](#0-9) 
- Make all pointer/denom migration loops resumable and bounded per block (batch N entries per `BeginBlock`/upgrade step, continuing across multiple blocks), following the same pattern used for `PruneZeroStorageSlots`. [9](#0-8) 
- Avoid performing EVM/wasm contract calls inside upgrade-time iteration loops that lack per-iteration gas metering; move such per-entry work to a lazy/on-demand upgrade path (e.g., migrate a pointer's version lazily on first subsequent access) rather than eagerly processing the full registry in one shot.

### Proof of Concept
1. Attacker calls `addCW20Pointer`/`addNativePointer` (or CW20 `CreateDenom`) repeatedly from many accounts/transactions across blocks, each call cheap and unprivileged, to register a very large number of pointer entries under `PointerRegistryPrefix` (or tokenfactory denoms under the creator prefix store). [1](#0-0) [2](#0-1) 
2. Node operators schedule/execute a chain upgrade whose handler invokes `MigrateERCCW20Pointers` (or `x/tokenfactory`'s `Migrate3to4`). [3](#0-2) [4](#0-3) 
3. At the upgrade height, every validator's node must iterate the entire attacker-inflated registry within the single upgrade block, performing one EVM call + contract deployment (or `wasmd` migrate call) per entry; with a sufficiently large seeded registry this exceeds practical per-block processing time on all validators simultaneously, stalling block production network-wide.

	store := k.GetCreatorPrefixStore(ctx, creator)
	var denoms []string

		denoms = append(denoms, string(key))
		return nil
	})
	if err != nil {
		return nil, nil, err
	}
	return denoms, pageRes, nil
}

func MigrateERCNativePointers(ctx sdk.Context, k *keeper.Keeper) error {
	iter := prefix.NewStore(ctx.KVStore(k.GetStoreKey()), append(types.PointerRegistryPrefix, types.PointerERC20NativePrefix...)).ReverseIterator(nil, nil)
	defer func() { _ = iter.Close() }()
	seen := map[string]struct{}{}
	for ; iter.Valid(); iter.Next() {
		token := string(iter.Key()[:len(iter.Key())-2]) // last two bytes are version
		if _, ok := seen[token]; ok {
			continue
		}
		seen[token] = struct{}{}
		addr := common.BytesToAddress(iter.Value())
		oName, err := k.QueryERCSingleOutput(ctx, "native", addr, "name")
		if err != nil {
			logger.Error("Failed to upgrade pointer for token due to failed name query", "token", token, "err", err)
			continue
		}
		oSymbol, err := k.QueryERCSingleOutput(ctx, "native", addr, "symbol")
		if err != nil {
			logger.Error("Failed to upgrade pointer for token due to failed symbol query", "token", token, "err", err)
			continue
		}
		oDecimals, err := k.QueryERCSingleOutput(ctx, "native", addr, "decimals")
		if err != nil {
			logger.Error("Failed to upgrade pointer for token due to failed decimal query", "token", token, "err", err)
			continue
		}
		_ = k.RunWithOneOffEVMInstance(ctx, func(e *vm.EVM) error {
			_, err := k.UpsertERCNativePointer(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), e, token, utils.ERCMetadata{
				Name:     oName.(string),
				Symbol:   oSymbol.(string),
				Decimals: oDecimals.(uint8),
			})
			return err
		}, func(s1, s2 string) {
			logger.Error("Failed to upgrade pointer for token at step", "token", token, "from-step", s1, "to-step", s2)
		})
	}
	return nil
}

func MigrateCWERC20Pointers(ctx sdk.Context, k *keeper.Keeper) error {
	iter := prefix.NewStore(ctx.KVStore(k.GetStoreKey()), append(types.PointerRegistryPrefix, types.PointerCW20ERC20Prefix...)).ReverseIterator(nil, nil)
	defer func() { _ = iter.Close() }()
	bz, _ := json.Marshal(map[string]interface{}{})
	moduleAcct := k.AccountKeeper().GetModuleAddress(types.ModuleName)
	codeID := k.GetStoredPointerCodeID(ctx, types.PointerType_ERC20)
	seen := map[string]struct{}{}
	for ; iter.Valid(); iter.Next() {
		evmAddr := string(iter.Key()[:len(iter.Key())-2]) // last two bytes are version
		if _, ok := seen[evmAddr]; ok {
			continue
		}
		seen[evmAddr] = struct{}{}
		addr, err := sdk.AccAddressFromBech32(string(iter.Value()))
		if err != nil {
			logger.Error("error parsing cw-erc20 pointer address", "pointer", string(iter.Value()), "err", err)
			return err
		}
		_, err = k.WasmKeeper().Migrate(ctx, addr, moduleAcct, codeID, bz)

			logger.Error("error migrating cw-erc20 pointer to code ID", "pointer", addr, "code-id", codeID, "err", err)
			return err
		}
	}
	return nil
}

func (m Migrator) Migrate3to4(ctx sdk.Context) error {
	// Set denom metadata for all denoms
	iter := m.keeper.GetAllDenomsIterator(ctx)
	defer func() { _ = iter.Close() }()
	for ; iter.Valid(); iter.Next() {
		denom := string(iter.Value())
		denomMetadata, found := m.keeper.bankKeeper.GetDenomMetaData(ctx, denom)
		if !found {
			panic(fmt.Errorf("denom %s does not exist", denom))
		}
		fmt.Printf("Migrating denom: %s\n", denom)
		m.SetMetadata(&denomMetadata)
		m.keeper.bankKeeper.SetDenomMetaData(ctx, denomMetadata)
	}
	return nil
}
