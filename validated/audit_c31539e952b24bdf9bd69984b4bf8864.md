### Title
CW721 EVM Bridge Query Handler Builds an Unsafe `transferFrom` Payload Instead of `safeTransferFrom`, Risking Permanent NFT Loss - (File: x/evm/client/wasm/query.go)

### Summary
`EVMQueryHandler.HandleERC721TransferPayload` builds the ABI-encoded payload used by any CosmWasm contract (via the `erc721_transfer_payload` custom query exposed through `wasmbinding/queries.go`) to move an ERC721 token that is bridged/pointed to from the Cosmos side. It encodes a plain `transferFrom(from, to, tokenId)` call, whereas the parallel ERC1155 handler in the same file, `HandleERC1155TransferPayload`, deliberately encodes `safeTransferFrom(...)` for the equivalent operation. [1](#0-0) [2](#0-1) 

### Finding Description
Any CosmWasm contract (e.g. the CW721 pointer contract shown in `example/cosmwasm/cw721/src/contract.rs`, or any other contract built by an unprivileged wasm-message sender) can call the `erc721_transfer_payload` custom query to obtain an EVM call payload that moves ownership of the underlying ERC721 token from `from` to `recipient` (both resolved via `h.k.GetEVMAddress`). That payload is then dispatched with `DelegateCallEvm`/similar EVM execution. [3](#0-2) 

Because `HandleERC721TransferPayload` always encodes the unsafe `transferFrom` selector rather than `safeTransferFrom`, the resulting EVM call never invokes `onERC721Received` on the recipient. If `recipient`'s associated EVM address is a smart contract that is designed to accept NFTs only through the safe-transfer callback (e.g., a vault/marketplace contract that records NFT deposits inside `onERC721Received`), the token's ownership silently moves to that contract without the contract ever being notified. Since a pure CosmWasm contract cannot itself originate arbitrary EVM calls to "rescue" the token from the recipient contract, and the recipient contract has no internal accounting entry for a token it never "received" via its hook, the NFT becomes permanently stuck — this mirrors exactly the reported bug class (plain `_transfer` instead of `safeTransfer`, causing tokens to be lost when the destination contract relies on `onERC721Received`).

This is a genuine inconsistency in the same file: the module's authors clearly intended safe-transfer semantics for token-bridging operations (as proven by the ERC1155 counterpart using `safeTransferFrom`), but the ERC721 payload builder was not updated to match.

### Impact Explanation
An NFT bridged/associated between the Cosmos and EVM sides of sei-chain can be irrecoverably locked if moved to a smart-contract recipient that depends on the `onERC721Received` callback for accounting or access control. This is a permanent freezing of a real asset (ERC721 token) reachable by any ordinary CosmWasm contract call, not by a privileged/governance actor, satisfying the "permanent freezing" acceptance criterion for a Medium-severity finding.

### Likelihood Explanation
Likelihood depends on the recipient being an EVM contract that both (a) has an EVM address associated to a Sei account/contract, and (b) requires the safe-transfer callback for deposit accounting. This is a plausible integration pattern for marketplaces, vaults, or other DeFi/NFT contracts that receive tokens cross-domain via this exact bridging primitive, and the flaw is triggerable by any unprivileged wasm caller who invokes the query/transfer flow — no special privileges are required.

### Recommendation
Change `HandleERC721TransferPayload` in `x/evm/client/wasm/query.go` to pack `safeTransferFrom(from, to, tokenId, data)` (mirroring the pattern already used in `HandleERC1155TransferPayload`), so cross-domain NFT transfers correctly invoke `onERC721Received` on contract recipients and revert if the recipient does not support the ERC721 safe-transfer interface.

### Proof of Concept
1. Deploy (or use) an EVM contract `Vault` implementing `IERC721Receiver` that only credits a deposit inside `onERC721Received`.
2. Associate a Sei account/contract address `R` with `Vault`'s EVM address.
3. From a CosmWasm contract, call the custom query `erc721_transfer_payload(from=<owner>, recipient=R, token_id=<id>)`, exposed via `wasmbinding/queries.go` → `x/evm/client/wasm/query.go:HandleERC721TransferPayload`.
4. Execute the returned payload against the EVM ERC721 contract (as done in `example/cosmwasm/cw721/src/contract.rs:transfer_nft`, `x/evm/client/wasm/query.go:219`), which calls `transferFrom` — ownership moves to `Vault`'s address, but `Vault.onERC721Received` is never invoked, so `Vault` has no record of the deposit.
5. The token is now owned by `Vault` on-chain but is inaccessible: `Vault` has no way to identify/return it, and the CosmWasm side has no mechanism to trigger `Vault`'s withdrawal logic for an asset it doesn't know it holds — permanent loss of the NFT.

func (h *EVMQueryHandler) HandleERC721TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string) ([]byte, error) {
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("transferFrom", fromEvmAddr, toEvmAddr, t.BigInt())
	if err != nil {
		return nil, err
	}
	res := bindings.ERCPayloadResponse{EncodedPayload: base64.StdEncoding.EncodeToString(bz)}
	return json.Marshal(res)
}

func (h *EVMQueryHandler) HandleERC1155TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string, amount *sdk.Int) ([]byte, error) {
	abi, err := cw1155.Cw1155MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("safeTransferFrom", fromEvmAddr, toEvmAddr, t.BigInt(), amount.BigInt(), []byte("0x0"))
	if err != nil {
		return nil, err
	}
	res := bindings.ERCPayloadResponse{EncodedPayload: base64.StdEncoding.EncodeToString(bz)}
	return json.Marshal(res)
}

fn transfer_nft(
    deps: DepsMut<EvmQueryWrapper>,
    info: &MessageInfo,
    recipient: &str,
    token_id: &str,
) -> Result<Response<EvmMsg>, ContractError> {
    deps.api.addr_validate(recipient)?;

    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
    let payload = querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new().add_message(msg);

    Ok(res)
}
