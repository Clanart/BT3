## Title
`IntentGatewayV2.instance()` defaults unregistered state machines to `address(this)`, letting a forged cross-chain message pass `authenticate()` and drain escrowed order funds - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

## Summary
This is the exact structural analog of the reported `adapterId == 0` bug: a mapping lookup that returns Solidity's zero-value default is silently treated as "a known, trusted identity" instead of "unregistered." In `BridgeRouter`, an unknown adapter (`adapterToId == 0`) collided with the real adapter registered at id `0`. In `IntentGatewayV2`, an unknown/unregistered source state machine (`_instances[keccak256(source)] == address(0)`) collides with the gateway trusting **itself** (`address(this)`) as the counterparty, in the function used to authenticate incoming escrow-release messages.

## Finding Description
`IntentGatewayV2.instance()` resolves the trusted gateway address for a given state machine, but instead of reverting on an unregistered chain, it falls back to `address(this)`: [1](#0-0) 

This value feeds directly into `authenticate()`, the only gate protecting `RedeemEscrow`/`RefundEscrow` handling in `onAccept()`: [2](#0-1) [3](#0-2) 

For any `request.source` state machine that has never had a `NewDeployment` registered (i.e., `_instances[keccak256(source)] == address(0)`, the Solidity default), `instance(source)` returns `address(this)`. `authenticate()` then only requires `request.from == address(this)` — i.e., that the message claims to originate from "itself." Since `IntentGatewayV2` (and its sibling contracts across the ecosystem) is designed to be deployed at the **same address on every chain via CREATE2** (documented pattern elsewhere in this repo, e.g. `HyperbridgeLzEndpoint`'s "Assumes the same contract address on all chains"), an attacker can permissionlessly redeploy the identical, unmodified `IntentGatewayV2` bytecode with the same public CREATE2 salt on any EVM chain that Hyperbridge already has a live consensus client for but that governance has **not yet** registered via `NewDeployment`. That redeployed contract lands at the exact same address as the legitimate gateway on the destination chain, satisfying `request.from == address(this)`.

From that self-controlled "twin" deployment, the attacker reconstructs a real victim order's commitment (order parameters are public via the `OrderPlaced` event) and dispatches a `RefundEscrow`/`RedeemEscrow` `PostRequest` back to the real gateway, with an attacker-chosen `beneficiary`. Because `_orders[commitment][token]` still holds the victim's real escrowed balance, `withdraw()` will transfer it to the attacker: [4](#0-3) 

Notably, the sibling, presumably-hardened implementation of this exact same contract already reverts instead of defaulting: [5](#0-4) 

The Tron variant of `IntentGatewayV2` never received this fix and still contains the zero-default-collision pattern.

## Impact Explanation
This directly matches "Direct theft of any user funds... at-rest" — a false/forged cross-chain message is accepted as authentic due to a zero-value mapping default colliding with a trusted identity, allowing arbitrary release of escrowed order funds to an attacker-chosen beneficiary. This is the same broken invariant as the reported `BridgeRouter` bug: "unregistered ⇒ id/address 0 ⇒ silently treated as valid."

## Likelihood Explanation
Exploitability requires only: (1) a chain Hyperbridge already consensus-supports but that has not yet had `NewDeployment` called for `IntentGatewayV2` (a normal, expected operational gap during rollout to new chains), and (2) permissionless CREATE2 redeployment of the known/public gateway bytecode+salt. No relayer, prover, admin, or governance compromise is needed — an ordinary user drives the whole flow through the real, permissionless Hyperbridge message-relay path.

## Recommendation
Change `instance()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` to revert on `address(0)` (mirroring `IntentsBase._instance()`'s `UnknownInstance()` revert) instead of falling back to `address(this)`, and audit all other locations across the codebase where the default (zero) value of a mapping is used directly as an implicit "valid"/"self" identity.

## Proof of Concept
1. Attacker identifies a state machine `S` that Hyperbridge already has a live consensus client for, but for which `IntentGatewayV2._instances[keccak256(S)]` has never been set (no `NewDeployment` yet issued for `S`).
2. Attacker deploys the unmodified `IntentGatewayV2` bytecode on chain `S` using the same public CREATE2 factory/salt used for the legitimate deployment, producing an address identical to the real gateway's address on the destination chain (`address(this)`).
3. Victim has an existing order with commitment `C` and non-zero `_orders[C][token]` escrow on the destination chain (visible via the `OrderPlaced` event).
4. From the attacker's twin deployment on `S`, dispatch a `PostRequest` to the destination gateway with `body = RequestKind.RefundEscrow || abi.encode(WithdrawalRequest{commitment: C, tokens: [...], beneficiary: attacker})`, `from = <twin address> == address(this)` on destination.
5. Relay this request through the real, permissionless Hyperbridge handler (`handlePostRequests`) with a valid state proof for chain `S` — no malicious relayer required, standard message delivery.
6. `onAccept()` → `authenticate()` computes `instance(S) == address(0) → address(this)`; since `request.from == address(this)`, authentication passes.
7. `withdraw()` transfers the victim's escrowed tokens for commitment `C` to the attacker-controlled `beneficiary`.

        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
