### Title
`DeleteTokenPair` auto-deletion on ConvertCoin/ConvertERC20 destroys erc20↔denom mapping without checking outstanding circulating supply, permanently freezing escrowed value - (File: x/erc20/keeper/msg_server.go, x/erc20/keeper/token_pairs.go)

### Summary
This is a direct analog of the reported `removeWrapping` bug: a mapping between a "wrapped" representation (here, a native Cosmos coin minted 1:1 against an escrowed ERC-20) and its underlying asset can be irreversibly deleted while units of the wrapped representation are still circulating among holders, permanently breaking their ability to redeem/convert back.

### Finding Description
For token pairs with `ContractOwner == OWNER_EXTERNAL` (`IsNativeERC20()`), the erc20 module lets users mint native coins 1:1 by escrowing ERC-20 tokens into the module account via `ConvertERC20` [1](#0-0) , and later redeem native coins back for ERC-20 tokens via `ConvertCoin`.

Both `ConvertERC20` and `ConvertCoin` contain a heuristic "cleanup" branch: if the underlying ERC-20 contract account appears to have no code (`acc == nil || !acc.HasCodeHash()`), the keeper unconditionally calls `k.DeleteTokenPair(ctx, pair)` and returns, instead of performing the conversion: [2](#0-1) [3](#0-2) 

`DeleteTokenPair` removes the ERC20→denom map, the denom→ERC20 map, and all allowances for the pair with no check on how much of `pair.Denom` is still in circulation as bank balances, nor on whether the module account still holds an outstanding ERC-20 escrow balance for that pair: [4](#0-3) 

This deletion is reachable by **any unprivileged user** simply by calling `MsgConvertCoin` or `MsgConvertERC20` against the affected token/denom — no governance or admin privilege is required to trigger it; the only precondition is that the target ERC-20 contract account looks "codeless" (e.g., after a legitimate `selfdestruct` by the external contract's own EOA owner, which is normal, permissionless contract behavior for an `OWNER_EXTERNAL` pair). Once triggered, `GetTokenPairID`/`MintingEnabled` will return `ErrTokenPairNotFound` for that denom forever after [5](#0-4) , so every other holder of the previously-minted native coin balance permanently loses the only code path that would let them convert those coins back to ERC-20 (`ConvertCoin`), even though their bank balances denominated in `pair.Denom` remain outstanding and any escrowed ERC-20 balance sitting at `types.ModuleAddress` becomes permanently orphaned from the accounting system.

This mirrors the `removeWrapping` finding precisely: the recommended fix there ("only allow removal of a wrapped token when there are 0 [tokens] in circulation") was never implemented for `DeleteTokenPair`. Any external-contract owner can selfdestruct their contract at will while other users still hold minted native coin balances backed by that pair, and the very next `ConvertCoin`/`ConvertERC20` call from anyone will delete the pair mapping and permanently strand those balances/allowances.

### Impact Explanation
This causes permanent freezing/loss of the ability to redeem token-pair-backed native coin balances still held by unrelated third parties, and orphans the escrowed ERC-20 balance held by the erc20 module account — matching the "Critical permanent freezing, locking, theft, or unauthorized extraction of user funds ... or token-pair-backed balances" allowed impact. It is triggerable by an ordinary, unprivileged transaction flow (`ConvertCoin`/`ConvertERC20`), requiring no validator/relayer/governance privilege.

### Likelihood Explanation
The trigger condition (`acc == nil || !acc.HasCodeHash()`) is reachable through completely permissionless actions: the deployer of an `OWNER_EXTERNAL` ERC-20 contract can selfdestruct it at any time they choose (this is ordinary EOA/contract-owner behavior, not a privileged action), and any subsequent user's routine `ConvertCoin`/`ConvertERC20` call — which they have every incentive to make in order to redeem their own tokens — will delete the pair for everyone.

### Recommendation
Before calling `DeleteTokenPair` in the "selfdestructed contract" branches of `ConvertERC20`/`ConvertCoin`, verify that the total circulating bank supply of `pair.Denom` is zero (and/or that the module's escrowed ERC-20 balance is zero) before allowing removal of the mapping, consistent with the audited mitigation for the original `removeWrapping` finding. Alternatively, remove this auto-deletion side effect entirely and require an explicit, supply-checked governance operation to clean up dead token pairs.

### Proof of Concept
1. Governance/permissionless registration creates a `TokenPair` with `ContractOwner = OWNER_EXTERNAL` for ERC-20 contract `C`, denom `D`.
2. User A calls `MsgConvertERC20` to escrow `100 C` into the module account and mint `100 D` to themselves; User B does the same for another `50 C`/`50 D`.
3. The owner of contract `C` calls `selfdestruct` on `C` (permissionless, no privilege required for an externally-owned contract).
4. User A calls `MsgConvertCoin` attempting to redeem `100 D` back to `C`. The keeper sees `!acc.HasCodeHash()`, and instead of erroring safely, calls `k.DeleteTokenPair(ctx, pair)` [3](#0-2) , wiping the erc20↔denom mapping and allowances, returning success with no state change to balances.
5. User B, who still holds `50 D` and never got a chance to redeem, now permanently cannot call `MsgConvertCoin` for denom `D` (or the ERC-20 address) since `GetTokenPairID` returns nothing and `MintingEnabled` fails with `ErrTokenPairNotFound` [6](#0-5) . User B's `50 D` balance and any residual escrow accounting is now permanently orphaned/unredeemable through the module's designed flow.

// DeleteTokenPair removes a token pair.
func (k Keeper) DeleteTokenPair(ctx sdk.Context, tokenPair types.TokenPair) {
	id := tokenPair.GetID()
	k.deleteTokenPair(ctx, id)
	k.deleteERC20Map(ctx, tokenPair.GetERC20Contract())
	k.deleteDenomMap(ctx, tokenPair.Denom)
	k.deleteAllowances(ctx, tokenPair.GetERC20Contract())
}

func (k Keeper) MintingEnabled(

	receiver sdk.AccAddress,
	token string,

		return types.TokenPair{}, errorsmod.Wrap(
			types.ErrERC20Disabled, "module is currently disabled by governance",
		)

	id := k.GetTokenPairID(ctx, token)
	if len(id) == 0 {
		return types.TokenPair{}, errorsmod.Wrapf(

		)

	if !found {
		return types.TokenPair{}, errorsmod.Wrapf(
			types.ErrTokenPairNotFound, "token '%s' not registered", token,
		)
	}
