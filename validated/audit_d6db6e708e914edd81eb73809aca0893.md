### Title
`ReceivedOutput` authenticity check verifies only the offset/script binding, not that the claimed `TxOut` matches the actual on-chain UTXO, enabling loss of funds via fee inflation - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to the Tracer report (where `deployer() == msg.sender` verifies a self-reported field of an attacker-supplied contract and so is ineffective as an authenticity check), `SignableTransaction::multisig` "authenticates" each `ReceivedOutput` only by checking that the deserialized `offset` produces a group key whose P2TR script equals the claimed `script_pubkey`. Both `offset` and `output` come from the same untrusted serialization (`ReceivedOutput::read`), so the check is self-referential: it proves internal consistency, not that the output exists on-chain or that its declared `value` is correct. A forged `ReceivedOutput` can therefore drive fee/change accounting off real funds.

### Finding Description
`ReceivedOutput::read` deserializes `offset`, `output` (a `TxOut` including `value` and `script_pubkey`), and `outpoint` entirely from untrusted bytes, with no binding to chain state [1](#0-0) .

`SignableTransaction::new` then trusts `input.output.value` for the funds/fee/change calculation and `input.outpoint` for the `TxIn` [2](#0-1) .

The only "authenticity" check is in `multisig`:

```rust
let offset = keys.clone().offset(self.offsets[i]);
if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
  None?;
}
``` [3](#0-2) 

An attacker who controls the serialized `ReceivedOutput` sets `offset` and `script_pubkey` consistently (e.g., `offset = 0` and `script_pubkey = p2tr(group_key)`, both computable from the public group key), so the check always passes — exactly like a malicious `oracleWrapper` returning `msg.sender` from `deployer()`. The check never verifies that `outpoint` references a real, unspent UTXO or that the real UTXO's `value` equals the claimed `output.value`.

Since signing uses `Prevouts::All` over the *claimed* prevouts, the produced Taproot signature commits to the forged `TxOut` and is still consensus-valid as long as the real UTXO covers the declared outputs [4](#0-3) . The actual on-chain fee paid is `real_utxo_value - sum(tx.outputs)`, not the `needed_fee` the signer believed.

### Impact Explanation
If the claimed `output.value` is understated relative to the real UTXO it points at, the signed transaction pays `real_value - claimed_value - intended_outputs` as extra miner fees, permanently burning multisig funds. If `value` is overstated or the `outpoint` is fake/spent, the transaction is invalid (DoS of the spend). This is a real loss-of-funds / griefing path reachable purely via untrusted bytes passed to `ReceivedOutput::read` (explicitly listed as an untrusted-bytes sink) without any leaked keys or malicious validators.

### Likelihood Explanation
Requires an integrator/processor path to accept a serialized `ReceivedOutput` (or equivalent output tuple) from an untrusted party and feed it into `SignableTransaction::new`/`multisig` without independently fetching the UTXO from a trusted node. Where outputs are obtained solely from `Scanner::scan_transaction`/`scan_block`, the value is authentic and the issue is unreachable [5](#0-4) . The `read`/`serialize` API existing for inter-process transport makes the untrusted path plausible — hence Medium likelihood.

### Recommendation
- Treat `ReceivedOutput::read` output as unauthenticated input: before constructing a `SignableTransaction`, resolve each `outpoint` against the Bitcoin node and overwrite `output` with the chain-confirmed `TxOut`, or store a commitment (txid + vout + value + script) verified by the scanner.
- In `SignableTransaction::multisig`, additionally verify the claimed prevout against chain data (e.g., require the `ReceivedOutput` to have been produced by `Scanner`, or check `tx.output[vout]` equality via RPC) rather than relying on the offset↔script self-consistency check.
- Document that `ReceivedOutput::read` must only be used for trusted (self-produced) serializations.

### Proof of Concept
```rust
// Attacker knows the public group key (even) and a real deposit UTXO O of value V_real.
let offset = Scalar::ZERO;
let forged = ReceivedOutput::read(&mut serialize(&(
    offset,
    TxOut {
        // passes multisig() check: p2tr_script_buf(group_key) == script_pubkey
        script_pubkey: p2tr_script_buf(group_key).unwrap(),
        // understated: real UTXO holds V_real >> V_claimed
        value: Amount::from_sat(V_claimed),
    },
    outpoint_O, // real outpoint holding V_real
)).as_slice()).unwrap();

let tx = SignableTransaction::new(vec![forged], &payments, change, None, fee_rate)?;
// multisig() accepts: offset 0 -> group_key -> script_pubkey matches
let machine = tx.multisig(&keys).unwrap();
// Sign, broadcast: signature commits to claimed prevouts via Prevouts::All.
// Confirmed fee = V_real - sum(outputs) >> needed_fee; difference is burned to miners.
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
