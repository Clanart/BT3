### Title
Permissionless registration of externally-owned ERC20 contracts as `NativeERC20` token pairs allows unbacked native coin minting via `ConvertERC20` - (File: `x/erc20/keeper/msg_server.go`)

### Summary
When `params.PermissionlessRegistration` is enabled, `Keeper.RegisterERC20` [1](#0-0)  allows *any unprivileged account* to register an arbitrary externally-owned ERC20 contract as a `NativeERC20` (`OWNER_EXTERNAL`) token pair. Because the registered contract is fully controlled by the registrant, the registrant can mint unlimited ERC20 supply to itself, escrow it via `ConvertERC20`, and receive a 1:1 amount of freshly-minted, spendable native Cosmos coins from the bank module — coins backed by nothing. This is the same trust-boundary failure as the SKALE `transferredAmount` bug: a party that controls "mint" on one side of a bridge/conversion path can manufacture value that a downstream contract or module treats as legitimately escrowed/backed.

### Finding Description
`ConvertERC20` → `convertERC20IntoCoinsForNativeToken` [2](#0-1)  handles `NativeERC20` pairs by:
1. Calling `transfer` on the ERC20 contract to move `msg.Amount` tokens from the sender into the erc20 module's escrow address.
2. Verifying the module's ERC20 `balanceOf` increased by exactly `amount` (an internal consistency check only, not an economic-backing check).
3. Calling `k.bankKeeper.MintCoins(ctx, types.ModuleName, coins)` to mint the same amount of native Cosmos coins and send them to the receiver [3](#0-2) .

This flow assumes the ERC20 contract's token supply reflects genuine value. However, `RegisterERC20`'s own comment states "Any account can permissionlessly register a native ERC20 contract to map to a Cosmos Coin" [4](#0-3) , gated only by the governance-configurable `PermissionlessRegistration` param [5](#0-4) . `TokenPair.IsNativeERC20()` marks such pairs as `OWNER_EXTERNAL` [6](#0-5) , meaning the module places no restriction on who can mint the underlying token — that is entirely up to the external contract's own access control, which the registrant (an attacker) fully controls by deploying the contract themselves before registering it.

This mirrors the SKALE `ERC20OnChain`/`DepositBoxERC20` bug exactly: a self-deployed token with an attacker-controlled `mint()` is paired 1:1 with a "real" locked/escrowed value, and the redemption/conversion path (`exitToMainERC20` in SKALE, `ConvertERC20` here) blindly trusts that the token supply presented for redemption is honestly backed.

### Impact Explanation
An attacker can:
1. Deploy a malicious ERC20 contract where they hold mint rights.
2. Call `MsgRegisterERC20` (permissionless when the param is enabled) to register it as a `NativeERC20` pair.
3. Mint an arbitrary amount of tokens to themselves on the malicious contract.
4. Call `MsgConvertERC20`, which escrows the self-minted tokens and mints an equal amount of genuine native Cosmos coins via `bankKeeper.MintCoins`.

The result is unauthorized, unbounded inflation of the native coin supply — real, fully spendable, transferable, stakeable, and IBC-transferable value created from nothing. This directly matches the "Critical unauthorized minting ... of spendable user value across native balances" impact category, since it corrupts the fungibility/accounting invariant of the chain's native asset and dilutes/steals value from all other holders.

### Likelihood Explanation
The only gate is the `PermissionlessRegistration` governance parameter [5](#0-4) . Once that mode is enabled (a supported, documented operational mode per the code's own comment), the entire attack path — contract deployment, registration, minting, and conversion — is executable by any unprivileged EOA using only standard `MsgRegisterERC20` and `MsgConvertERC20` transactions, with no additional privilege required. I was not able to fully verify the compiled default value of `PermissionlessRegistration` in `x/erc20/types/params.go` before running out of iterations, so likelihood is contingent on that parameter's configured value on a given deployment; if disabled by default and never toggled, this path is not reachable by an unprivileged user.

### Recommendation
- For `NativeERC20` (`OWNER_EXTERNAL`) pairs, do not treat `balanceOf` deltas on an externally-owned, permissionlessly-registered contract as sufficient proof of backing for native coin minting.
- Restrict `ConvertERC20`'s native-coin-minting path to token pairs where the ERC20 contract's mint authority is either the erc20 module itself or otherwise provably immutable/non-attacker-controlled (e.g., require `OWNER_MODULE`, or verify the contract has no privileged mint function reachable by the registrant).
- If `PermissionlessRegistration` is intended to remain available, require registered external contracts to pass a mint-safety check (e.g., disallow contracts with an unrestricted or registrant-controlled `mint`), or cap/monitor total native coins mintable per token pair against real independent collateral.

### Proof of Concept
1. Enable `PermissionlessRegistration=true` via governance (or note it is already default-enabled).
2. Attacker deploys `EvilERC20` with `mint(address,uint256)` restricted to `msg.sender == deployer`.
3. Attacker submits `MsgRegisterERC20{Signer: attacker, Erc20Addresses: [EvilERC20]}` → `RegisterERC20` succeeds without governance approval [7](#0-6) , creating a `TokenPair{ContractOwner: OWNER_EXTERNAL}`.
4. Attacker calls `EvilERC20.mint(attacker, 1_000_000e18)` directly via EVM tx.
5. Attacker submits `MsgConvertERC20{ContractAddress: EvilERC20, Amount: 1_000_000e18, Receiver: attacker, Sender: attacker}`.
6. `convertERC20IntoCoinsForNativeToken` escrows the self-minted tokens, verifies the (self-controlled) balance delta, and calls `bankKeeper.MintCoins` + `SendCoinsFromModuleToAccount`, crediting the attacker with 1,000,000 units of a genuine native Cosmos coin denom (`erc20:0x...`) backed by nothing [3](#0-2) .
7. Attacker now holds real, spendable, IBC-transferable native coins created from a worthless self-minted token.

func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}
