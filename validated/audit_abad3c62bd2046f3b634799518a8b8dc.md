### Title
DataLayer server-side request forgery via unvalidated on-chain mirror URLs - (File: chia/data_layer/data_layer.py)

### Summary
Any wallet user can create a DataLayer "mirror" coin whose spend solution carries an arbitrary list of URL strings. These URLs are picked up by any node/service that tracks the corresponding DataLayer store, stored as subscription server info, and later used directly as HTTP(S) targets by the DataLayer sync loop (`fetch_and_validate`) and the plugin downloader dispatch (`get_downloader`). No scheme, host, or destination filtering (no private-IP/loopback/link-local/metadata-endpoint blocklist) is applied anywhere along this path, mirroring the WildFly Elytron `JwtValidator.resolvePublicKey` SSRF pattern where an attacker-supplied `jku` URL is fetched unchecked.

### Finding Description
`DataLayerWallet.coin_added()` detects mirror coins by puzzle hash and decodes the URL list straight from the coin's spend solution with only an emptiness check, no URL validation: [1](#0-0) 

Anyone can create such a mirror coin (via `dl_new_mirror`/`add_mirror`) with arbitrary URL content, since the mirror puzzle only requires paying the mirror amount, not any authorization tied to the store owner: [2](#0-1) 

These attacker-controlled URLs then flow into a subscribing node's `DataStore` via `update_subscriptions_from_wallet()`, which pulls all mirror URLs from wallet RPC and stores them as server info with no filtering: [3](#0-2) 

`fetch_and_validate()` then iterates these server URLs and issues outbound requests against them — either an HTTP GET via `http_download` for the plain path, or a `POST` to `downloader.url + "/handle_download"` for plugin dispatch — with no validation of the target address (e.g., no blocking of `127.0.0.1`, RFC1918 ranges, `169.254.169.254` cloud metadata, etc.): [4](#0-3) [5](#0-4) 

The actual network call for the plain-HTTP case is `download_file()`/`http_download()` in `chia/data_layer/download_data.py`, which performs the request directly against `server_info.url`: [6](#0-5) 

This is directly analogous to the WildFly Elytron bug class: an externally supplied URL (there, the JWT `jku` header; here, an on-chain mirror URL crafted by any wallet participant) is dereferenced by server-side code performing an outbound HTTP request without any destination allow/deny-listing, enabling SSRF against internal services, cloud metadata endpoints, or other hosts reachable from the DataLayer node's network position.

### Impact Explanation
Any unprivileged user who can submit a spend bundle creating a mirror coin (an ordinary, permissionless on-chain action) can cause every DataLayer node subscribed to that store to make attacker-chosen outbound HTTP requests. This can be used to probe/attack internal network services, hit cloud provider metadata endpoints to exfiltrate credentials, or trigger requests against arbitrary third-party targets using the victim node as a proxy — a High-severity SSRF impact matching CVE-2024-1233's CVSS profile (network-reachable, low complexity, no privileges/user interaction, confidentiality/integrity/availability impact on the destination service reachable via the vulnerable server).

### Likelihood Explanation
Likelihood is high for any DataLayer operator who subscribes to third-party stores (a normal, encouraged DataLayer usage pattern): mirror coins are cheap, permissionless to create, and their URLs are consumed automatically by the periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) without operator interaction or confirmation.

### Recommendation
Validate and restrict mirror/server URLs before they are persisted as subscription targets and before any outbound request is issued: enforce an allowed URL scheme, resolve the hostname and reject requests to loopback/private/link-local/multicast ranges and known cloud metadata addresses, and consider re-validating on every use (not just at ingestion) to defend against DNS rebinding. This should be applied consistently in `DataLayerWallet.coin_added()` (mirror ingestion), `DataLayer.update_subscriptions_from_wallet()`, and immediately before dispatching in `fetch_and_validate()`/`http_download()`/`get_downloader()`.

### Proof of Concept
1. Attacker wallet creates a DataLayer mirror coin for a public store id using `add_mirror`, setting the URL list to `["http://169.254.169.254/latest/meta-data/"]` (or an internal RFC1918 address of a victim's private service).
2. `DataLayerWallet.coin_added()` on any node tracking that launcher id decodes and stores the mirror URL with no validation — [7](#0-6) .
3. A victim DataLayer node subscribed to the store runs `update_subscriptions_from_wallet()`, pulling the malicious URL into its local subscription server list — [3](#0-2) .
4. On the next sync cycle, `fetch_and_validate()` selects that server and issues an HTTP request (via `http_download`) directly to the attacker-chosen address — [8](#0-7) , [9](#0-8) , causing the victim node to make an SSRF request on the attacker's behalf.

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
