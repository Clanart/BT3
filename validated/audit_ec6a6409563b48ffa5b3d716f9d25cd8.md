### Title
Missing zero-check on governance `GasTarget` causes division-by-zero panic in KIP-71 base fee calculation - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without verifying it is non-zero, unlike the sibling `BaseFeeDenominator` parameter which explicitly rejects zero at the governance-parameter validation layer. If `GasTarget` is set to `0` via a governance vote, every node computing or verifying the next block's base fee will panic on division by zero, since the change and vote acceptance path never rejects this value.

### Finding Description
`NextMagmaBlockBaseFee` computes the delta to the base fee using `gasTarget` as a divisor in both the "above target" and "below target" branches: [1](#0-0) [2](#0-1) 

Note that the function explicitly guards `BaseFeeDenominator == 0` by substituting a fallback value of `64` before it is used as a divisor: [3](#0-2) 

However, no equivalent guard exists for `gasTarget := kc.GasTarget` before it is used in `x.Div(x, new(big.Int).SetUint64(gasTarget))`. If `gasTarget == 0` and the parent block used any gas at all (`parentGasUsed > 0 = gasTarget`), the code enters the "used more gas than target" branch and divides by zero, causing a runtime panic (`division by zero` in `math/big`).

Crucially, the governance parameter validation for `Kip71GasTarget` does **not** enforce a non-zero value, unlike `Kip71BaseFeeDenominator` which explicitly does: [4](#0-3) 

`Kip71BaseFeeDenominator`'s `FormatChecker` requires `v != 0`, while `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` — it accepts any `uint64`, including `0`. This value flows unchanged through `ParamSet.Set`/`ToKip71Config` into the `KIP71Config` used by consensus-critical code: [5](#0-4) [6](#0-5) 

`NextMagmaBlockBaseFee` is invoked from multiple consensus/RPC-facing code paths, including block preparation (`work/worker.go`), block header/base-fee verification (`params/kip71_config.go:VerifyMagmaHeader`, called from `blockchain/block_validator.go`), fee history and gas-price suggestion (`node/cn/gasprice/feehistory.go`, `node/cn/gasprice/gasprice.go`), and cross-chain bridge info (`node/sc/main_bridge_handler.go`). A panic here would be triggered on every node during ordinary block processing once the fork enacting `GasTarget=0` becomes active.

### Impact Explanation
Setting `GasTarget` to `0` via a legitimate governance vote (governance parameters are within the allowed reachable surface for this analysis) causes every full node to panic while computing/verifying the base fee for any subsequent block that uses gas above 0 — effectively halting block production and header verification network-wide once the parameter takes effect. This is a chain-halt / consensus-liveness DoS, not merely a "resource" issue, because it prevents state transition (block header verification is unconditionally executed by every node for every produced block). Given this codebase explicitly hardens against `BaseFeeDenominator == 0` but omits the same treatment for `GasTarget`, this constitutes a legitimate inconsistency/oversight of the same bug class flagged in the reported audit issue (missing zero-divisor check before division).

### Likelihood Explanation
Reaching this bug requires a governance parameter change to be voted in and enacted (`reward.ratio`/`kip71.gastarget` style vote), which is an established, in-scope path (`kaiax/gov` module, governance parameters explicitly listed as reachable in scope). The parameter passes format validation unchanged because `Kip71GasTarget`'s `FormatChecker` is a no-op, so no additional validation blocks a governing node (or any account with governance voting rights under the configured governance mode) from setting `GasTarget = 0`. Once enacted, the panic is deterministic and triggers on the very next non-empty block, requiring no further conditions.

### Recommendation
Add an explicit zero-check for `GasTarget` in `Kip71GasTarget`'s `FormatChecker` in `kaiax/gov/param.go` (mirroring the check already used for `Kip71BaseFeeDenominator`, i.e., `return ok && v != 0`), so that governance cannot vote in a zero `GasTarget`. As defense in depth, also guard against `gasTarget == 0` directly inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` (e.g., fallback to a safe default similarly to the existing `BaseFeeDenominator == 0` handling) so that a zero value from any source (default config, genesis, or future code paths) cannot crash the node.

### Proof of Concept
1. Governance vote sets `kip71.gastarget = 0` (accepted because `Kip71GasTarget.FormatChecker = noopFormatChecker` performs no validation, per `kaiax/gov/param.go`).
2. The vote is enacted; `ParamSet.GasTarget` becomes `0` and flows into `KIP71Config.GasTarget` via `ToKip71Config()`.
3. On the next block after enactment, any block with `GasUsed > 0` causes `NextMagmaBlockBaseFee` to take the `parentGasUsed > gasTarget` branch (since `gasTarget = 0`).
4. Inside that branch, `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` executes `big.Int.Div` with a zero divisor, which panics ("division by zero"), crashing every node that verifies or prepares that block header — including consensus-critical header verification (`VerifyMagmaHeader`) and block proposal (`work/worker.go`).
