### Title
Unauthenticated `ReceivedOutput` deserialization can mint unspendable deposits - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without binding them to a scanner, transaction, or confirmed UTXO. [1](#0-0) 

### Finding Description
`ReceivedOutput` represents a spendable output, but its fields are supplied directly during deserialization and no check verifies that the encoded output appeared in a transaction or that the outpoint exists. [2](#0-1) 
The authenticated construction path is `Scanner::scan_transaction`, which derives the stored `OutPoint` from the transaction ID and output index and only records offsets whose script was registered. [3](#0-2) 
Calling `ReceivedOutput::read` bypasses that provenance check and creates the same privileged “spendable output” object from bytes alone. [1](#0-0) 

### Impact Explanation
An attacker can encode a large balance at a nonexistent or incorrect outpoint while using a script matching the wallet’s expected key, causing downstream logic to report funds as received even though the input cannot be spent. [4](#0-3) 
`SignableTransaction::new` trusts the supplied `ReceivedOutput` value and outpoint when calculating inputs and constructing `TxIn`s. [5](#0-4) 
`SignableTransaction::multisig` checks only that the supplied prevout script matches the offset group key, so a forged `ReceivedOutput` carrying the wallet script and a fabricated outpoint can reach transaction signing while remaining unspendable. [6](#0-5) 

### Likelihood Explanation
The attack requires only public knowledge of the wallet’s Taproot script and the ability to submit serialized bytes to a caller that treats `ReceivedOutput::read` input as authoritative. [7](#0-6) 
No private key, malformed curve encoding, malicious threshold participant, or invalid transaction relay is required because deserialization itself creates the false spendable-output claim. [1](#0-0) 

### Recommendation
Do not feed attacker-controlled bytes to `ReceivedOutput::read` as authoritative wallet state. [1](#0-0) 
Persisted scanner results should be authenticated as trusted local state, and externally supplied claims should be reconstructed through `Scanner::scan_transaction` against a chain transaction whose computed transaction ID, output index, and script all match the claimed `OutPoint` and `TxOut`. [3](#0-2) 
Before spending, also verify the referenced UTXO exists, remains unspent, and has the same value and script recorded in `ReceivedOutput`. [6](#0-5) 

### Proof of Concept
```rust
use k256::{ProjectivePoint, Scalar};
use bitcoin::{
  consensus::serialize,
  Amount, OutPoint, TxOut,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput};

let wallet_script = p2tr_script_buf(ProjectivePoint::GENERATOR).unwrap();

let fake_txout = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: wallet_script,
};

// An invalid/null outpoint makes the claimed UTXO unspendable.
let fake_outpoint = OutPoint::null();

let mut encoded = Scalar::ZERO.to_bytes().to_vec();
encoded.extend(serialize(&fake_txout));
encoded.extend(serialize(&fake_outpoint));

let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();
assert_eq!(forged.value(), 1_000_000);
assert_eq!(forged.outpoint(), &OutPoint::null());
```
The forged object reports one million satoshis and is accepted as a `ReceivedOutput` despite never being produced by `Scanner::scan_transaction`. [4](#0-3)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
