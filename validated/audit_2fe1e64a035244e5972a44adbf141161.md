### Title
`SignableTransaction::new` omits the OP_RETURN output from the fee calculation, underpaying the promised fee rate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` pushes an OP_RETURN output onto `tx_outs` when `data` is specified, but computes the transaction weight/vbytes — and therefore `needed_fee` — from `payments` (and optionally `change`) only. The OP_RETURN output's weight is never accounted for, so the resulting transaction pays a lower effective fee rate than `fee_per_vbyte` and may fall below the minimum relay fee.

### Finding Description
When `data` is `Some`, an OP_RETURN `TxOut` is appended to the outputs at lines 194–202. However, both calls to `calculate_weight_vbytes` pass `payments`, not `tx_outs`:

- Line 204: `Self::calculate_weight_vbytes(tx_ins.len(), payments, None)` — excludes the OP_RETURN output.
- Line 226: same omission for the with-change estimate.

Inside `calculate_weight_vbytes` (lines 62–99), the dummy transaction's outputs are built solely from `payments` plus an optional change output, so the OP_RETURN output (~13–93 bytes depending on `data` length up to 80 bytes) contributes zero weight to the estimate.

Consequences:

- `needed_fee` (line 206) and `fee_with_change` (line 227) are both too low by roughly `fee_per_vbyte * (data_len/4 + ~11)` vbytes.
- The minimum-relay check at line 211 uses the underestimated `vbytes`, so a transaction whose true vsize would still pass the floor can instead be built paying a sub-minimum effective rate: with `change`, the change output absorbs the difference (`value = input_sat - payment_sat - fee_with_change`, line 228–230), making the actual fee `fee_with_change`, which is below the minimum relay fee for the true size. The transaction will not be relayed by default-policy nodes despite `TooLowFee` not being returned.

This is an accounting asymmetry analogous to the reported bug: an output (cost) is added on one side of the ledger (the actual transaction) but never debited on the accounting side (the fee calculation). Callers relying on `needed_fee()`/`fee()` and the `fee_per_vbyte` contract get a transaction that silently underpays.

### Impact Explanation
Any caller that supplies `data` produces a transaction paying less than the requested fee rate — potentially below `DEFAULT_MIN_RELAY_TX_FEE` for the true vsize — causing the signed transaction to be unrelayable or to stall unconfirmed. Since inputs are consumed outpoints, funds are effectively locked until a replacement is constructed. No secret leakage occurs, but availability of the wallet's funds and correctness of the documented fee contract are compromised.

### Likelihood Explanation
Reachable through the public API: any unprivileged caller (or integrator flow) that passes `Some(data)` to `SignableTransaction::new` triggers it deterministically. Whether it crosses the relay minimum depends on `fee_per_vbyte` margin and `data` length, but the underpayment relative to the requested rate occurs on every call with `data` set.

### Recommendation
Include the OP_RETURN output in the weight estimate. Either pass `tx_outs`-equivalent output descriptors (payments + OP_RETURN) into `calculate_weight_vbytes`, or add an explicit `data_len`/`extra_output` parameter so the dummy transaction at lines 68–99 includes an OP_RETURN output of the real script size before computing `tx.weight()`.

### Proof of Concept
```rust
// Conceptual: single input of 100_000 sats, one payment, no change.
let tx = SignableTransaction::new(
  inputs,                        // 100_000 sats
  &payments,                     // e.g. [(addr, 50_000)]
  None,                          // no change -> actual fee = input_sat - payment_sat
  Some(vec![0u8; 80]),           // 80-byte OP_RETURN
  fee_per_vbyte,                 // e.g. 1
).unwrap();
// needed_fee was computed from a dummy tx without the OP_RETURN output.
// tx.fee() == needed_fee == fee_per_vbyte * vbytes_without_opreturn
// but the real vsize is ~90+ bytes larger, so the effective sat/vbyte is
// well below `fee_per_vbyte`, and can be < DEFAULT_MIN_RELAY_TX_FEE.
assert!(tx.fee() < fee_per_vbyte * real_vsize); // underpayment
```

Key lines: OP_RETURN appended at `send.rs:194-202`; fee estimates at `send.rs:204` and `send.rs:226` ignore it; dummy-tx construction in `calculate_weight_vbytes` at `send.rs:85-99` only uses `payments` + `change`.
