### Title
mWOMSVBaseRewarder._calExpireForfeit never applies mWomSV.getRewardablePercentWAD, causing 100% reward payout and permanent 0 forfeiture for early/cooldown unlockers - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` sets `rewardableAmount = _amount` unconditionally instead of scaling by `mWOMSV.getRewardablePercentWAD(_account)` as the sibling `vlMGPBaseRewarder._calExpireForfeit` does with `vlMGP.getRewardablePercentWAD(_account)`. As a result, `forfeitAmount` is always `0` regardless of a user's lock/cooldown state, so any `mWomSV` holder who initiates a partial/early unlock and is still owed a penalty on rewards receives 100% of `userRewards` when calling `getReward()`/`getRewards()` via MasterMagpie.

### Finding Description
`mWOMSVBaseRewarder._sendReward` computes `forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account])` and forwards `toSend = userRewards - forfeitAmount` to the user, queuing `forfeitAmount` back into the pool for other stakers via `_queueNewRewardsWithoutTransfer`: [1](#0-0) 

However `_calExpireForfeit` in `mWOMSVBaseRewarder` never queries `mWOMSV.getRewardablePercentWAD(_account)`, it just does `rewardableAmount = _amount`, so `forfeitAmount = _amount - rewardableAmount` is always `0`: [2](#0-1) 

Compare this to the correct pattern in `vlMGPBaseRewarder._calExpireForfeit`, which fetches `rewardablePercentWAD` from the locker and scales the rewardable amount before computing the forfeiture: [3](#0-2) 

The `mWomSV` locker itself does implement `getRewardablePercentWAD` correctly, returning less than `1e18` for users with amounts in cooldown or with partially expired lock schedules: [4](#0-3) 

This is dead/unused logic in `mWOMSVBaseRewarder` — the getter exists on the locker but the rewarder never calls it, breaking the documented forfeiture invariant that mirrors `vlMGP`. Any unprivileged `mWomSV` holder who has non-fully-locked balance (i.e., anyone who has called `unlock`/started cooldown) reaches this path simply by calling `getReward`/`getRewards` on `mWOMSVBaseRewarder` through `MasterMagpie`, with no additional permissions required: [5](#0-4) 

### Impact Explanation
This results in permanent under-collection of forfeited rewards from users who should be penalized for early/partial unlocking of `mWomSV`. Because `forfeitAmount` is always `0`, the pool never re-queues any penalty share via `_queueNewRewardsWithoutTransfer`, meaning the remaining fully-locked stakers never receive the redistributed yield they are economically entitled to under the design mirrored by `vlMGPBaseRewarder`. This is a theft/permanent loss of unclaimed yield for the remaining honest lockers, matching the Immunefi "theft of unclaimed yield" impact class.

### Likelihood Explanation
Trivial to trigger and requires no special capital or privilege: any holder of `mWomSV` who starts an unlock (partial or full cooldown) and then calls `getReward`/`getRewards` will bypass forfeiture entirely and collect 100% of `userRewards`. This is a standard user flow through `MasterMagpie`, fully repeatable on every claim by every non-fully-locked holder.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to call `mWOMSV.getRewardablePercentWAD(_account)` and scale `rewardableAmount = _amount * rewardablePercentWAD / 1e18`, matching the implementation in `vlMGPBaseRewarder._calExpireForfeit`.

### Proof of Concept
Foundry test plan:
1. Deploy `mWomSV`, `mWOMSVBaseRewarder`, and `MasterMagpie` per existing test fixtures.
2. Have two users, A and B, lock equal `mWOM` into `mWomSV`.
3. Queue rewards into `mWOMSVBaseRewarder` so both accrue `userRewards`.
4. Have user A call `unlock`/start cooldown so that `mWomSV.getRewardablePercentWAD(A) < 1e18`.
5. Call `mWOMSVBaseRewarder.calExpireForfeit(A, rewardToken)` and assert it returns `0` despite `getRewardablePercentWAD(A) < 1e18`.
6. Deploy an equivalent `vlMGP`/`vlMGPBaseRewarder` fixture, replicate the same cooldown/lock ratio for a `vlMGP` holder, and assert `vlMGPBaseRewarder.calExpireForfeit` returns a non-zero forfeit for the same `rewardablePercentWAD`.
7. Have user A call `getReward` via `MasterMagpie` and assert they receive 100% of `userRewards` with no amount queued back via `ForfeitRewardAdded` event, confirming forfeited rewards are never redistributed to user B.

        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
