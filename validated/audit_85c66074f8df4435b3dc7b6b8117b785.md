### Title
Unix Socket gRPC Server Omits mTLS Interceptor, Allowing Unauthorized Internal Method Calls — (File: `core/src/servers.rs`)

---

### Summary

`create_grpc_server` applies the mTLS certificate-based interceptor only on the TCP code path. The Unix socket code path adds the service directly, with no interceptor at all. Any local process that can reach the socket file can call every gRPC method — including `Internal*` methods that are supposed to be restricted to the entity's own certificate — without presenting any credential.

---

### Finding Description

In `core/src/servers.rs`, the TCP branch wraps the service in `InterceptedService::new(service, interceptor)` before registering it. The interceptor is either `OnlyAggregatorAndSelf` (when `config.client_verification = true`) or `Noop`: [1](#0-0) 

The Unix socket branch, compiled for all `#[cfg(unix)]` targets, skips this wrapper entirely and calls `.add_service(service)` directly on the raw builder: [2](#0-1) 

The `Interceptors` enum and its `only_aggregator_and_self` function enforce two invariants documented in `docs/usage.md`:

1. Non-internal methods may only be called by the aggregator or the entity itself.
2. `Internal*` methods may only be called by the entity's own client certificate. [3](#0-2) 

Because the interceptor is never instantiated for Unix socket connections, both invariants are silently dropped. The `AddMethodMiddlewareLayer` is still applied (so the `grpc-method` header is set), but the code that reads that header and enforces the certificate check never runs.

The `is_internal()` helper that gates `Internal*` methods is only reachable through the interceptor's `call()` method: [4](#0-3) 

This is the direct analog to the external report: `ERC20PausableUpgradable` documents that the inheriting contract *must* expose `pause()`/`unpause()` — failing to do so makes the pause mechanism unreachable. Here, the `Interceptors` mechanism is designed to be applied to every gRPC service; failing to apply it on the Unix socket path makes the entire authentication mechanism unreachable for that transport.

The Unix socket path is not test-only (`#[cfg(test)]`); it is a `#[cfg(unix)]` production feature. The testnet4 Docker config explicitly sets `socket_path`: [5](#0-4) 

---

### Impact Explanation

Any OS-level process that can open the Unix socket file can call every registered gRPC method on the operator or verifier without a certificate. This includes:

- **`internal_end_round`** on the operator — prematurely ends the current collateral round, potentially causing the operator to miss legitimate kickoffs and lose collateral.
- **`InternalSendTx`** / **`InternalGetEmergencyStopTx`** on the aggregator — can broadcast arbitrary pre-signed transactions or retrieve encrypted emergency-stop transactions.
- Any other `Internal*` method added in the future.

Unauthorized advancement of the round or kickoff state machines can break bridge safety: an operator forced into the wrong round state may be unable to respond to challenges in time, resulting in slashable collateral exposure or permanent lock of bridge-controlled UTXOs.

---

### Likelihood Explanation

Exploitation requires local access to the Unix socket file. In containerized deployments (Docker Compose, Kubernetes pods with shared volumes, or sidecar patterns), a compromised co-located service can reach the socket without any network exposure. The testnet4 production config already enables the Unix socket path, making this reachable in a real deployment.

---

### Recommendation

Apply the same `InterceptedService` wrapper in the Unix socket branch that is already applied in the TCP branch:

```rust
// Unix socket path — add interceptor before registering the service
let service = InterceptedService::new(
    service,
    if config.client_verification {
        OnlyAggregatorAndSelf {
            aggregator_cert: ...,
            our_cert: ...,
        }
    } else {
        Noop
    },
);

let server_builder = tonic::transport::Server::builder()
    // ... layers ...
    .add_service(service);  // now intercepted
```

Because Unix sockets carry no TLS peer certificates, `req.peer_certs()` will return `None`. The existing `only_aggregator_and_self` function already handles this case: in non-test mode it returns `Unauthenticated`; in test mode it passes through. This means the fix works correctly without any changes to the interceptor logic itself. [6](#0-5) 

---

### Proof of Concept

1. Deploy operator or verifier with a valid `socket_path` (e.g., `/tmp/clementine-op.sock`).
2. From any process on the same host, open a raw gRPC connection to `unix:///tmp/clementine-op.sock` — no TLS, no certificate.
3. Call `internal_end_round` (or any other `Internal*` method).
4. The call succeeds: the `AddMethodMiddlewareLayer` sets the `grpc-method` header, but the interceptor that would reject the unauthenticated request is never in the call stack.
5. The operator's round state machine advances without authorization, breaking the invariant that only the entity itself (via its own mTLS certificate) may trigger internal state transitions. [7](#0-6)

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
}
