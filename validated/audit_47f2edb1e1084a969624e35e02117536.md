### Title
Data Layer mirror URLs enable Server-Side Request Forgery against subscribed peers - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can publish an on-chain "mirror" record for a DataLayer store containing arbitrary attacker-controlled URLs via `dl_new_mirror`/`add_mirror`. Any other DataLayer node that subscribes to that store id will automatically parse these URLs and issue outbound HTTP GET requests to them with no scheme/host restriction and no allowlisting, exactly mirroring the EspoCRM "fetch remote resource from unprivileged, attacker-supplied URL" SSRF pattern.

### Finding Description
`DataLayerWallet.create_new_mirror` lets any wallet owner spend a small amount into a `create_mirror_puzzle()` coin carrying an arbitrary list of URL strings that get committed on-chain [1](#0-0) . Any peer that later syncs this coin (`DataLayerWallet.coin_added`) decodes the URLs and stores them locally as an untrusted mirror for the given `launcher_id`, with no host/scheme validation, only rejecting empty URL lists [2](#0-1) .

The DataLayer service periodically calls `update_subscriptions_from_wallet`, which pulls these attacker-supplied URLs straight from wallet RPC and feeds them into the local subscription server list without validation [3](#0-2) . `fetch_and_validate` then iterates these `server_info.url` values and calls `insert_from_delta_file` → `download_file` → `http_download`, which performs a raw `aiohttp` `session.get(server_info.url + "/" + filename, ...)` request with no restriction on the target host/IP (no check against private/internal ranges, no scheme allowlist beyond what `aiohttp` accepts) [4](#0-3) , [5](#0-4) .

This is directly analogous to the EspoCRM SSRF: an unprivileged actor (here, any wallet holder capable of creating a DL mirror coin — a cheap, permissionless on-chain action) supplies a URL that a different, victim node will fetch automatically. There is no server-side check preventing the URL from pointing to `127.0.0.1`, link-local metadata endpoints (e.g. `169.254.169.254`), or other internal-only hosts/ports reachable from the victim's network, and (as in the EspoCRM case) there is no meaningful content-type/response validation before the request is issued — the request itself, and any error/timing/content leaked back through logs, is the SSRF primitive.

### Impact Explanation
A malicious mirror publisher can force any peer that subscribes to (or discovers) their DataLayer store to make outbound HTTP requests to arbitrary internal or firewalled hosts of the attacker's choosing. This can be used to probe internal services, hit cloud metadata endpoints, or interact with internal HTTP APIs reachable only from the victim node's network — a classic SSRF impact. Because publishing a mirror only requires a minor on-chain spend by any wallet user, the attack is available to any unprivileged Data Layer participant, satisfying "Data Layer client" reachability in scope.

### Likelihood Explanation
Likelihood is high for any operator who runs a DataLayer service and subscribes to (or auto-pseudo-subscribes to, or is induced to subscribe to) a store with attacker-controlled mirrors. `update_subscription()`'s ordered step of "sync subscription URLs from wallet mirrors" runs automatically as part of the periodic `periodically_manage_data()` loop, requiring no manual approval of individual mirror URLs by the node operator.

### Recommendation
Validate and restrict mirror/server URLs before they are used for outbound HTTP fetches in `chia/data_layer/download_data.py::http_download` and in `DataLayer.get_downloader`/`fetch_and_validate`: enforce an allowed scheme set (http/https only), resolve and reject requests to private/loopback/link-local/metadata address ranges, and consider requiring operator opt-in/allowlisting of mirror hosts rather than blind auto-subscription to on-chain-advertised URLs.

### Proof of Concept
1. Attacker creates a DataLayer store and wallet, then calls `dl_new_mirror`/`add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-service.local:8080/admin"]` [6](#0-5) .
2. Victim's DataLayer node subscribes to (or is auto-pseudo-subscribed to) the attacker's store id, e.g. through `subscribe` RPC or normal discovery.
3. Victim's `periodically_manage_data` loop runs `update_subscription`, which calls `update_subscriptions_from_wallet` to pull the attacker's mirror URLs into the local server list [3](#0-2) .
4. `fetch_and_validate` picks one of these URLs and calls `insert_from_delta_file` → `download_file` → `http_download`, which issues `session.get(url + "/" + filename, ...)` directly against the attacker-chosen internal host [4](#0-3) .
5. The victim node's outbound request (and any resulting error message, timing, or exception logged) can be used by the attacker to fingerprint or interact with internal-only infrastructure it should never be able to reach.

@streamable
@dataclasses.dataclass(frozen=True)
class Mirror(Streamable):
    coin_id: bytes32
    launcher_id: bytes32
    amount: uint64
    urls: list[str]
    ours: bool
    confirmed_at_height: uint32 | None

    @staticmethod
    def encode_urls(urls: list[str]) -> list[bytes]:
        return [url.encode("utf8") for url in urls]

    @staticmethod
    def decode_urls(urls: list[bytes]) -> list[str]:
        return [url.decode("utf8") for url in urls]

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
