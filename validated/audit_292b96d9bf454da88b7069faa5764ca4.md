### Title
Unbounded per-owner CW721 token enumeration/transfer loop in the `solo` precompile's `ClaimSpecific` can permanently OOG-revert legacy asset claims - ([File: precompiles/solo/solo.go])

### Summary
The `solo` precompile's `ClaimSpecific` handler enumerates *all* CW721 tokens owned by the claiming account via an unbounded pagination loop, then executes a second unbounded loop that submits one `transfer_nft` CosmWasm execution per token — all within a single gas-metered EVM call. This mirrors the HoprStakeBase `redeemedNft` bug class: a loop whose iteration count is controlled by an amount of on-chain state (owned NFTs) that grows independently of the caller, with no page/size cap, so once that count is large enough the call can no longer complete within a block's gas limit.

### Finding Description
`PrecompileExecutor.ClaimSpecific` ( [1](#0-0) ) resolves a legacy Sei "sender" account via a signed claim message (`p.validate`, [2](#0-1) ) and, for CW721 assets, executes two unbounded loops:

```
allTokens := []string{}
startAfter := ""
for {
    res, _ := p.wasmViewKeeper.QuerySmartSafe(ctx, contractAddr, CW721TokensQueryPayload(sender, startAfter))
    tokens, _ := ParseCW721TokensQueryResponse(res)
    if len(tokens) == 0 { break }
    allTokens = append(allTokens, tokens...)
    startAfter = tokens[len(tokens)-1]
}
for _, token := range allTokens {
    p.wasmKeeper.Execute(ctx, contractAddr, sender, CW721TransferPayload(callerSeiAddr, token), sdk.NewCoins())
}
``` [3](#0-2) 

There is no cap on `len(allTokens)`, no per-call limit on the number of pages queried, and no limit on the number of `Execute` (transfer_nft) sub-calls performed. Each iteration costs a CW smart-query plus, in the second loop, a full contract `Execute` call (state read/write, event emission, gas metering overhead) — orders of magnitude more expensive than a single storage read/write, exactly as in the `HoprStakeBase._unlockFor` analog where the per-element cost of a redemption-array loop made the whole call unexecutable once the array grew large enough.

The token count enumerated is the number of CW721 tokens owned by the legacy `sender` address on a specific CW721 contract. If that CW721 contract allows public/cheap minting (a very common CW721 pattern), or if the legacy account otherwise accumulates many tokens, an attacker can mint enough tokens to that address to make the token count large enough that the combined query+transfer loop exceeds the transaction's EVM gas limit.

### Impact Explanation
`ClaimSpecific` is the *only* path in the precompile to transfer CW721 assets out of the legacy claimable sender account into the EVM caller's Sei address (`Claim` only moves native bank balances). If the loop can never complete inside the gas budget:
- The specific `claimSpecificMsg` for that CW721 contract permanently reverts out-of-gas every time it is attempted (increasing the tokens further only makes it worse, and the tokens cannot otherwise be moved by this path).
- The underlying claim message includes a sequence-number increment tied to the legacy account's signature (`sigverify`, [4](#0-3) ), meaning even partial-progress retries are constrained by the same signed message/sequence, so the CW721 assets end up permanently unclaimable/frozen for that account via this precompile.

This is a fund-freezing bug class (permanent loss of the ability to migrate/claim NFTs), analogous in root cause to the HoprStakeBase finding, though the blast radius is scoped to affected legacy-claim accounts/CW721 contracts rather than the whole chain.

### Likelihood Explanation
Reaching this requires: (1) a legacy Sei account eligible for `ClaimSpecific` that owns/receives many CW721 tokens on one contract, and (2) that contract permitting enough tokens to be associated with the account (either self-minted before migrating, or minted by a griefer if the CW721 allows open minting to arbitrary addresses). Since CW721 contracts on Sei are permissionless CosmWasm code (some allow public minting), an attacker can deliberately inflate a victim's token count on a griefing target, or a legitimate large NFT holder can organically hit this ceiling. The precompile is reachable by any EOA caller via a normal EVM transaction carrying a signed claim tx, satisfying the "unprivileged transaction sender" reachability bar.

### Recommendation
Bound the CW721 enumeration and transfer loop in `ClaimSpecific`:
- Cap the total number of tokens processed per call (e.g. a `MaxClaimTokensPerCall` constant), rejecting/erroring cleanly if the owned-token count exceeds the cap instead of looping until OOG.
- Support paginated/partial claims (a `startAfter`/continuation argument in `MsgClaimSpecific`) so a large NFT balance can be claimed across multiple transactions instead of requiring one all-or-nothing call.
- Consider metering/charging gas proportional to `len(allTokens)` up front so the call fails fast with a clear error rather than an opaque out-of-gas panic deep in the loop.

### Proof of Concept
1. Identify (or set up) a legacy Sei account `sender` eligible for `MsgClaimSpecific` against a CW721 contract that permits (public or attacker-controlled) minting to arbitrary addresses.
2. Mint a large number of tokens (e.g. several hundred to a few thousand, contract-dependent) to `sender`.
3. Call the `solo` precompile's `claimSpecific` method with a validly signed claim tx for that CW721 asset (empty/omitted specific token id, per `asset.GetDenom() == ""` branch, [5](#0-4) ), from an EOA at gas limits at or below the chain's practical per-tx cap.
4. Observe the call runs out of gas while iterating the pagination query loop and/or the per-token `Execute` loop, and that every retry with the same or larger token count fails identically, permanently blocking the NFT claim for that `sender`/contract pair.

func (p PrecompileExecutor) validate(ctx sdk.Context, caller common.Address, args []interface{}, readOnly bool) (claimMsg, sdk.AccAddress, error) {
	if readOnly {
		return nil, nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, nil, err
	}
	tx, err := p.txConfig.TxDecoder()(args[0].([]byte))
	if err != nil {
		return nil, nil, fmt.Errorf("failed to decode claim tx due to %w", err)
	}
	if len(tx.GetMsgs()) != 1 {
		return nil, nil, fmt.Errorf("claim tx must contain exactly 1 message but %d were found", len(tx.GetMsgs()))
	}
	claimMsg, ok := tx.GetMsgs()[0].(claimMsg)
	if !ok {
		return nil, nil, errors.New("claim tx can only contain MsgClaim or MsgClaimSpecific type")
	}
	if common.HexToAddress(claimMsg.GetClaimer()).Cmp(caller) != 0 {
		return nil, nil, fmt.Errorf("claim tx is meant for %s but was sent by %s", claimMsg.GetClaimer(), caller.Hex())
	}
	sender, err := sdk.AccAddressFromBech32(claimMsg.GetSender())
	if err != nil {
		return nil, nil, fmt.Errorf("failed to parse claim tx sender due to %s", err)
	}
	if err := p.sigverify(ctx, tx, claimMsg, sender); err != nil {
		return nil, nil, err
	}
	return claimMsg, sender, nil
}

func (p PrecompileExecutor) sigverify(ctx sdk.Context, tx sdk.Tx, claimMsg claimMsg, sender sdk.AccAddress) error {
	sigTx, ok := tx.(authsigning.SigVerifiableTx)
	if !ok {
		return errors.New("claim tx must be a SigVerifiableTx")
	}
	var pubkey cryptotypes.PubKey
	pubkeys, err := sigTx.GetPubKeys()
	acct := p.accountKeeper.GetAccount(ctx, sender)
	if acct == nil {
		return fmt.Errorf("account %s does not exist", claimMsg.GetSender())
	}
	if err == nil {
		if len(pubkeys) != 1 {
			return fmt.Errorf("claim tx can be signed by exactly 1 key but %d signed", len(pubkeys))
		}
		pubkey = pubkeys[0]
	} else {
		// try find pubkey from storage
		pubkey = acct.GetPubKey()
		if pubkey == nil {
			return errors.New("must provide pubkey from accounts that have never sent transactions")
		}
	}
	pubkeyAddr := sdk.AccAddress(pubkey.Address())
	if !bytes.Equal(pubkeyAddr, sender) {
		return fmt.Errorf("claim message is for %s but was signed by %s", sender.String(), pubkeyAddr.String())
	}
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return fmt.Errorf("failed to get signatures due to %w", err)
	}
	if len(sigs) != 1 {
		return fmt.Errorf("claim tx should have exactly 1 signature but got %d", len(sigs))
	}
	sig := sigs[0]
	if sig.Sequence != acct.GetSequence() {
		return fmt.Errorf("account sequence mismatch for claim tx (%d vs. %d)", sig.Sequence, acct.GetSequence())
	}
	if err := authante.DefaultSigVerificationGasConsumer(ctx.GasMeter(), sig, p.accountKeeper.GetParams(ctx)); err != nil {
		return fmt.Errorf("insufficient gas for sig verification: %w", err)
	}
	signerData := authsigning.SignerData{
		ChainID:       ctx.ChainID(),
		AccountNumber: acct.GetAccountNumber(),
		Sequence:      acct.GetSequence(),
	}
	if err := authsigning.VerifySignature(pubkey, signerData, sig.Data, p.txConfig.SignModeHandler(), tx); err != nil {
		return fmt.Errorf("failed to verify signature for claim tx: %w", err)
	}
	// increment sequence
	_ = acct.SetSequence(acct.GetSequence() + 1)
	p.accountKeeper.SetAccount(ctx, acct)
	return nil
