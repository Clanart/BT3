## Title
`discardChangesFromSelection` applies a stale, zero-context patch computed from an outdated diff snapshot instead of the current working-directory content — ([File: app/src/lib/git/apply.ts])

### Summary
The Sushi Trident bug is a case of computing a derived operation on stale state (`_reserve0/_reserve1`) instead of the freshly-updated state (`balance0/balance1`) that the preceding step already produced, causing the second computation to silently diverge from what actually happened. The structural analog in GitHub Desktop is `discardChangesFromSelection`, which builds a git patch from a `diff`/`selection` snapshot that was captured earlier in the UI and is applied later with no re-validation that the working-directory file still matches that snapshot, using a context-free (`--unidiff-zero`) patch that is applied purely by line offset.

### Finding Description
`discardChangesFromSelection` in `app/src/lib/git/apply.ts` takes a `diff: ITextDiff` and `selection: DiffSelection` argument, builds a patch via `formatPatchToDiscardChanges`, and applies it with: [1](#0-0) 

Note the flags: `['apply', '--unidiff-zero', '--whitespace=nowarn', '-']` — `--unidiff-zero` means the generated hunks carry zero lines of context, so `git apply` has nothing to use to confirm the patch still matches the current file content; it applies strictly by line-number bookkeeping in the hunk headers.

The `diff` object passed into this function is not re-fetched at apply time — it originates from UI state that was computed earlier and passed down through props/dispatcher calls: [2](#0-1) 

and from the discard confirmation dialog, which stores the `diff` as a prop set when the dialog was opened and only invokes the discard once the user confirms — an async gap during which the working directory can change (e.g. background refresh, external edit, or another git operation completing): [3](#0-2) [4](#0-3) 

The same pattern exists in `Changes.onDiscardChanges`, which forwards `this.props.diff` (from `changesState`) straight to the dispatcher without re-diffing: [5](#0-4) 

`formatPatchToDiscardChanges` builds hunk headers purely from the old diff's line offsets (`hunk.header.oldStartLine`/`newStartLine`), with no comparison against the file's current on-disk content: [6](#0-5) 

This mirrors the Trident bug: `burn` (fresh state, i.e. what the user actually has on disk now) computes one thing, but the subsequent "swap"-equivalent operation (`discardChangesFromSelection` -> `git apply`) is computed against the stale snapshot (the old diff/reserve) instead of the current balance/content.

### Impact Explanation
If the working directory file changes between the moment the diff was captured (e.g. dialog opened, or hunk right-clicked) and the moment the discard patch is applied — due to an external editor autosave, a background repository refresh triggering a new diff that the user hasn't yet seen, or another concurrent git operation — the zero-context patch will be applied against stale line offsets. Because there is no context to validate against, `git apply` can succeed while corrupting content: removing or reverting lines that no longer correspond to what the user intended to discard, silently modifying the working tree in a way the user did not request and did not confirm. This corrupts what the user ultimately commits/pushes, matching the "Valid Impact" criteria (silent corruption of what the user commits, attacker/external-content controlled if the file is one whose content originates from an untrusted source, e.g. a file changed by a build tool or a git hook after fetch).

### Likelihood Explanation
The staleness window is real: diff computation, dialog confirmation, and discard application are separated by async UI interactions and repository refresh cycles that are not gated on diff freshness (unlike commit staging, which recomputes `getWorkingDirectoryDiff` immediately before building the patch — see `app/src/lib/git/apply.ts:60` `applyPatchToIndex`). No commit-hash/mtime check exists in `discardChangesFromSelection` or `formatPatchToDiscardChanges` to detect that the file changed since the diff was generated, and `--unidiff-zero` removes the one guard (context-line matching) that could otherwise catch a mismatch.

### Recommendation
Before applying the discard patch, re-fetch the current working-directory diff for the file and verify it matches (or is compatible with) the diff/selection being discarded (e.g., compare a content hash or byte length of the pre-image), aborting/re-prompting the user if the file has changed. Alternatively, retain at least minimal context lines in the generated patch (avoid `--unidiff-zero`) so `git apply` can reject a patch that no longer matches, and combine this with a `--check` pass before applying for real.

### Proof of Concept
1. Modify a tracked file to produce a multi-hunk diff, open the "Discard changes" confirmation dialog for a selected hunk/lines (this snapshots `diff`/`selection` into dialog props/state) — `app/src/ui/discard-changes/discard-selection-dialog.tsx`.
2. Before confirming, cause the underlying file to change on disk (simulating an external editor save, a build step, or a background git operation completing) so that line offsets shift relative to the captured diff.
3. Confirm the discard. `discardChangesFromSelection` (`app/src/lib/git/apply.ts:102-119`) builds and applies a zero-context patch based on the stale line offsets from step 1, not the file's current content.
4. Because `--unidiff-zero` provides no context to validate against, `git apply` can succeed while removing/reverting the wrong lines relative to the file's actual current state, silently corrupting content that will later be committed — analogous to `ConstantProductPool.burnSingle` computing the swap amount from stale reserves instead of the just-updated balance.

export async function discardChangesFromSelection(
  repository: Repository,
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
) {
  const patch = formatPatchToDiscardChanges(filePath, diff, selection)

  if (patch === null) {
    // When the patch is null we don't need to apply it since it will be a noop.
    return
  }

  const args = ['apply', '--unidiff-zero', '--whitespace=nowarn', '-']

  await git(args, repository.path, 'discardChangesFromSelection', {
    stdin: patch,
  })

export function formatPatchToDiscardChanges(
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
): string | null {
  let patch = ''

  diff.hunks.forEach((hunk, hunkIndex) => {
    let hunkBuf = ''

    let oldCount = 0
    let newCount = 0

    let anyAdditionsOrDeletions = false

    hunk.lines.forEach((line, lineIndex) => {
      const absoluteIndex = hunk.unifiedDiffStart + lineIndex

      // We write our own hunk headers
      if (line.type === DiffLineType.Hunk) {
        return
      }

      // Context lines can always be let through, they will
      // never appear for new files.
      if (line.type === DiffLineType.Context) {
        hunkBuf += `${line.text}\n`
        oldCount++
        newCount++
      } else if (selection.isSelected(absoluteIndex)) {
        // Reverse the change (if it was an added line, treat it as removed and vice versa).
        if (line.type === DiffLineType.Add) {
          hunkBuf += `-${line.text.substring(1)}\n`
          newCount++
        } else if (line.type === DiffLineType.Delete) {
          hunkBuf += `+${line.text.substring(1)}\n`
          oldCount++
        } else {
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }

        anyAdditionsOrDeletions = true
      } else {
        if (line.type === DiffLineType.Add) {
          // An unselected added line will stay in the file after discarding the changes,
          // so we just print it untouched on the diff.
          oldCount++
          newCount++
          hunkBuf += ` ${line.text.substring(1)}\n`
        } else if (line.type === DiffLineType.Delete) {
          // An unselected removed line has no impact on this patch since it's not
          // found on the current working copy of the file, so we can ignore it.
          return
        } else {
          // Guarantee that we've covered all the line types.
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }
      }

      if (line.noTrailingNewLine) {
        hunkBuf += '\\ No newline at end of file\n'
      }
    })

    // Skip writing this hunk if all there is is context lines.
    if (!anyAdditionsOrDeletions) {
      return
    }

    patch += formatHunkHeader(
      hunk.header.newStartLine,
      newCount,
      hunk.header.oldStartLine,
      oldCount
    )
    patch += hunkBuf
  })

  if (patch.length === 0) {
    // The selection resulted in an empty patch.
    return null
  }

  return formatPatchHeader(filePath, filePath) + patch
}
