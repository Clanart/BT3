### Title
Unescaped `Any.type_url` embedded verbatim into TextFormat/DebugString output enables structural injection - (File: `src/google/protobuf/text_format.cc`)

### Summary
The OpenClaw advisory's failed invariant is: "any string that will be interpolated into a structured, downstream-parsed/consumed output (an LLM prompt) must be sanitized of control/structural characters before embedding." The attacker-controlled value (CWD name) was written raw into the prompt text with no escaping, so control/bidi characters broke the intended structure and were interpreted as new instructions. The closest genuine analog in Protobuf's own trusted parsing/printing surface is `TextFormat::Printer::PrintAny` (and its Java counterpart), which writes the value of the `Any.type_url` string field directly into the `[...]` bracket syntax of TextFormat/DebugString output without applying the same escaping that is applied to every other STRING field printed by TextFormat.

### Finding Description
`Any.type_url` is an ordinary, attacker-controllable `string` field. It reaches the application either via `ParseFromString`/`MergeFrom` on bounded binary input, or via ProtoJSON parsing of an `Any` (`@type`), both of which are supported public parse APIs and treat the field as unconstrained UTF-8 text (constrained only by normal string validity, not to the "alphanumeric + limited symbol set" convention documented in `any.proto` for a *well-formed* type URL — that convention is documentation only, not enforced by the parser).

When such a message is later formatted for debugging/logging via `Message::DebugString()`, `ShortDebugString()`, `Utf8DebugString()`, or an explicit `TextFormat::Printer` with `SetExpandAny(true)`, `TextFormat::Printer::PrintAny` does:

```
generator->PrintLiteral("[");
generator->PrintString(type_url);
generator->PrintLiteral("]");
``` [1](#0-0) 

Contrast this with the printer used for every ordinary STRING field, `FastFieldValuePrinter::PrintString`, which explicitly checks for and escapes control characters, quotes, and backslashes via `ContainsCharactersToCEscape` / `absl::CEscape` before printing: [2](#0-1) 

and the even-more-careful `HardenedPrintString` path used elsewhere for untrusted string content, which walks the string and CEscapes anything that "definitely needs escaping" (control chars, quotes, backslash) or fails UTF-8 validation: [3](#0-2) [4](#0-3) 

`PrintAny`'s `generator->PrintString(type_url)` call goes to `BaseTextGenerator::PrintString`, the raw output primitive of the text generator — not through `FastFieldValuePrinter::PrintString`/`HardenedPrintString` escaping. The only validation performed on `type_url` before printing is `internal::ParseAnyTypeUrl`, which merely locates the last `/` to split prefix from type name and looks up the type in the registry/pool; it performs **no character-class validation** (no rejection of newlines, quotes, `]`, backslashes, or control characters) — that is confirmed by its declared contract in `any.h`, which only documents splitting on `/`: [5](#0-4) 

The Java implementation has the identical unescaped pattern in `printAny`:
```
generator.print("[");
generator.print(typeUrl);
generator.print("]");
``` [6](#0-5) 

`generator.print(String)` is the raw text-generator append, not the escaping path used for STRING fields at `printFieldValue` (which does call `TextFormatEscaper.escapeText`/`escapeDoubleQuotesAndBackslashes`): [7](#0-6) 

So in both the C++ and Java implementations, a bracketed Any header is the one place in the entire TextFormat/DebugString output surface where an ordinary attacker-supplied string field bypasses the escaping invariant that every other string field is subject to.

### Impact Explanation
An attacker who controls the bytes of a `google.protobuf.Any` submessage (a completely ordinary, schema-legal thing to send through any binary Protobuf or ProtoJSON parse API) can set `type_url` to a string containing newlines, `"`, `\`, `{`, `}`, `[`, `]`, or other control characters that are structurally significant to the TextFormat grammar. When the receiving application later calls `DebugString()`/`ShortDebugString()`/`TextFormat::PrintToString()` for logging, tracing, error messages, or (increasingly common in modern applications) feeding structured debug context into downstream text-consuming systems such as log parsers, alerting pipelines, or LLM-based analysis/agent tooling, the injected characters can:
- break the visual/structural integrity of the emitted TextFormat document (inject fabricated-looking `field: value` lines or bogus nested `{ ... }` blocks that were never part of the actual message),
- if the resulting text is ever fed back into a TextFormat parser or any text-based ingestion pipeline that trusts the shape of the debug dump, cause misinterpretation of the document boundaries — the same "prompt/structure injection" class of failure as the OpenClaw CWE-77 report, just against Protobuf's own structured text output rather than an LLM prompt directly.

This does not corrupt memory, and TextFormat parsing of a *re-ingested* malicious debug string is bounded by normal parser limits, so it does not rise to RCE. But it is a genuine violation of the sanitization invariant that Protobuf enforces everywhere else in the same output format, and it is reachable purely from a trusted schema + attacker-controlled bounded field value via a public API — matching the report's threat model (ordinary client, bounded input, no privileged access).

### Likelihood Explanation
High likelihood of reachability: `Any` is a first-class, extremely common well-known type; any service that accepts `Any`-typed fields anywhere in its message graph and logs/debug-prints messages (a very common practice, and explicitly one of the stated purposes of `DebugString()`) is exposed. No special configuration, extension registry manipulation, or malformed wire data is required — a syntactically valid `Any` with an arbitrary `type_url` string is sufficient, and `type_url` need not even resolve to a real registered type for the raw `[type_url]` bracket to be emitted in some code paths that print it unexpanded (e.g., when `SetExpandAny` is used but the type can't be resolved, the plain, non-Any field printer still applies proper escaping — but the `PrintAny` bracket path, taken whenever a resolvable/parseable type is found, does not).

### Recommendation
Escape `type_url` the same way every other STRING field is escaped before writing it into the `[...]` bracket in both `TextFormat::Printer::PrintAny` (C++, `src/google/protobuf/text_format.cc`) and `Printer.printAny` (Java, `java/core/src/main/java/com/google/protobuf/TextFormat.java`), e.g. by routing it through `HardenedPrintString`/`FastFieldValuePrinter::PrintString`-equivalent CEscape logic (or `TextFormatEscaper.escapeText` in Java) rather than the raw `PrintLiteral`/`print` primitive. Add a regression test asserting that a `type_url` containing `\n`, `"`, `]`, and `\\` is escaped in `DebugString()`/`PrintToString()` output and round-trips safely.

### Proof of Concept
1. Construct (via the public API, using only valid wire bytes — no malformed input required) an `Any` message whose `type_url` field is set to a string such as:
   `type.googleapis.com/proto2_unittest.OneString]\n  injected_field: "pwned"\n[x`
   and whose `value` field contains a validly serialized `proto2_unittest.OneString`.
2. Call `TextFormat::Printer` with `SetExpandAny(true)` (the mode used by `DebugString()`), i.e. `message.DebugString()`.
3. Observe that `PrintAny` at `src/google/protobuf/text_format.cc:2564-2566` writes the `type_url` value unescaped, producing an output whose bracket section contains literal newlines and a fabricated `injected_field: "pwned"` line rather than a single well-formed `[type_url]` token — unlike every other string field printed via `FastFieldValuePrinter::PrintString`, which would have CEscaped the same characters (`src/google/protobuf/text_format.cc:2227-2238`).
4. I was not able to execute this against a live build in this environment (no code execution available), so the PoC is a static trace of the exact call path and a diff against the sibling escaping code that is applied everywhere else; running it in a Devin session with build tooling would provide byte-for-byte confirmation of the produced (unescaped) output string.

// Returns true if `ch` needs to be escaped in TextFormat, independent of any
// UTF-8 validity issues.
bool DefinitelyNeedsEscape(unsigned char ch) {
  if (ch >= 0x80) {
    return false;  // High byte; no escapes necessary if UTF-8 is valid.
  }

  if (!absl::ascii_isprint(ch)) {
    return true;  // Unprintable characters need escape.
  }

  switch (ch) {
    case '\"':
    case '\'':
    case '\\':
      // These characters need escapes despite being printable.
      return true;
  }

  return false;
}

void TextFormat::Printer::HardenedPrintString(
    absl::string_view src, TextFormat::BaseTextGenerator* generator) {
  // Print as UTF-8, while guarding against any invalid UTF-8 in the string
  // field.
  //
  // If in the future we have a guaranteed invariant that invalid UTF-8 will
  // never be present, we could avoid the UTF-8 check here.

  generator->PrintLiteral("\"");
  while (!src.empty()) {
    size_t n = SkipPassthroughBytes(src);
    if (n != 0) {
      generator->PrintString(src.substr(0, n));
      src.remove_prefix(n);
      if (src.empty()) break;
    }

    // If repeated calls to CEscape() and PrintString() are expensive, we could
    // consider batching them, at the cost of some complexity.
    generator->PrintString(absl::CEscape(src.substr(0, 1)));
    src.remove_prefix(1);
  }
  generator->PrintLiteral("\"");
}

bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}

}  // namespace

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}
