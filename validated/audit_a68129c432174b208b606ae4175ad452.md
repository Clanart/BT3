## Title
Single-bid phantom-order price snapshot can be trivially manipulated to mis-price real Intent Gateway orders — ([File: sdk/packages/sdk/src/protocols/intents/quote/phantomSnapshot.ts])

### Summary
The Intent Gateway's phantom-order auction is the on-chain analog of the English-auction pattern in the reported issue: a price is supposed to emerge from *competing* solver bids collected during a short bidding window (`phantom_bid_window`, seen configured to as little as `1` block in `sdk/packages/simplex/src/tests/phantom-e2e.simnode.test.ts:263-290`). When the window closes, whatever bids landed are aggregated into a `medianPrice` that the SDK later treats as ground-truth market price for sizing **real, value-bearing orders** via `quoteIntent`/`PhantomSnapshotIntentQuoteStrategy`. There is no minimum bid count, no minimum competing-solver requirement, and no staleness/liquidity floor beyond "at least one verified bid" — exactly the missing invariant the external report calls out for English auctions.

### Finding Description
- Bids for a phantom order are collected only during a narrow window (`PhantomOrderBidWindowClosed` enforced in `modules/pallets/intents-coprocessor/src/lib.rs:294-298`); the window can be configured arbitrarily short.
- Once the window closes, `handlePhantomOrderPrices` (`sdk/packages/indexer/src/handlers/events/substrateChains/handlePhantomOrderPrices.handler.ts:77-99`) calls `aggregatePhantomBids` (`sdk/packages/sdk/src/protocols/intents/phantom-aggregation.ts:419-531`), which computes a **liquidity-weighted median** over whatever bids survived verification.
- Critically, `weightedMedian` over a single surviving quote simply returns that quote's price — the "weight" (solver liquidity) has no effect when there is only one bidder. The code even documents `lowestPrice`/`highestPrice` are forced equal to `medianPrice` so a single bid is indistinguishable from a well-formed multi-bid consensus (`phantom-aggregation.ts:517-530`).
- `PhantomSnapshotIntentQuoteStrategy.validateSnapshot` (`sdk/packages/sdk/src/protocols/intents/quote/phantomSnapshot.ts:132-145`) only checks `bidCount > 0`, `medianPrice > 0`, `standardAmount > 0` — there is **no minimum bidder count, no minimum weight/liquidity threshold, and no competition check**.
- `quoteSnapshot` (`phantomSnapshot.ts:83-101`) then uses that unverified single-bid price directly to compute `amountIn`/`amountOut` for constructing real orders: `amountOut = (netAmountIn * snapshot.medianPrice) / snapshot.standardAmount`.
- Any unprivileged actor can become "a solver": self-delegate an EOA to `SolverAccount` via EIP-7702 (a no-op, permissionless action described in `docs/content/developers/evm/intent-gateway/overview.mdx:116-120`) and call `place_bid` on `pallet-intents-coprocessor` (`modules/pallets/intents-coprocessor/src/lib.rs:279-328`), which is `ensure_signed`-gated only, not solver-allowlisted.

During network congestion (or simply by controlling timing given the short, configurable window), an attacker can ensure their own lowball/skewed bid is the only one landing in the window, becoming the sole contributor to the snapshot. This directly mirrors the reported English-auction bug: "very low priced bids may be filled with no counterparty bidders competing against them."

### Impact Explanation
The manipulated `medianPrice` is not merely informational — it is consumed by `quoteIntent` to size the `inputs`/`output.assets` of **actual IntentGateway orders** that users place and fund with real escrowed tokens (per `docs/content/developers/sdk/api/intent-gateway.mdx:230-232`: "Use the returned amounts directly as the order's `inputs` and `output.assets` — no further fee or slippage adjustment is required"). A user who trusts this SDK-suggested pricing during a congested/short window can be induced to escrow more input than a fair market price warrants, and the same attacker (or an accomplice) can then win the fill of that mispriced real order via `IntentGatewayV2.fillOrder` (`evm/src/apps/IntentGatewayV2.sol:413-452`), capturing the difference. This is a direct loss-of-funds path for the end user, driven purely by an unprivileged actor's ability to dominate a single-bid price snapshot — no relayer/prover/admin compromise required.

### Likelihood Explanation
The bid window is governance-configurable and has been exercised at `1` block in tests; under any real network congestion or simply by an attacker submitting at the last valid block while suppressing/out-timing other bids, becoming the sole contributor is straightforward. The verification pipeline (`isVerifiedSolverBid`) only checks the bid is signed by a `SolverAccount`-delegated EOA — self-delegation is free and permissionless, so any attacker can be "a solver." No collusion with a relayer, prover, or admin is needed.

### Recommendation
- Require a minimum number of distinct, liquidity-weighted verified bids (e.g. ≥3) before a `PhantomOrderPriceSnapshot` is considered valid for pricing; reject/flag single-bidder snapshots in `validateSnapshot`.
- Require a minimum aggregate weight (liquidity) threshold before trusting `medianPrice`, not just `bidCount > 0`.
- Consider widening the bid window's minimum bound (disallow governance from setting it to a value low enough to make single-bid domination trivial) and/or cross-checking phantom snapshot pricing against an independent oracle (e.g. Uniswap V4 quote) before it is used to size real orders, falling back or reverting on excessive deviation.

### Proof of Concept
1. Governance (or default config) sets `phantom_bid_window` to a small value (already demonstrated at `1` block in `phantom-e2e.simnode.test.ts:263-290`).
2. Attacker self-delegates an EOA to `SolverAccount` via a no-op EIP-7702 UserOp (permissionless, described in `overview.mdx:116-120`).
3. When a new phantom order is generated (`CurrentPhantomOrder`), attacker calls `place_bid` with a skewed `user_op` quoting a favorable-to-attacker rate, timed to land within the short window while other solvers' bids are delayed by congestion or simply outraced.
4. `PhantomBidWindowExhausted` fires; `handlePhantomOrderPrices` aggregates — with only the attacker's bid surviving, `aggregatePhantomBids` returns `bidCount: 1`, `medianPrice` = attacker's quoted price (`phantom-aggregation.ts:517-530`).
5. A victim user calls `quoteIntent` for the same pair; `PhantomSnapshotIntentQuoteStrategy.validateSnapshot` accepts the single-bid snapshot (`bidCount=1` passes `> 0`) and sizes the victim's real order using the attacker-controlled `medianPrice` (`phantomSnapshot.ts:83-145`).
6. Victim places the order on-chain per the SDK-suggested (mispriced) `inputs`/`output.assets`; attacker (or colluding solver) fills it via `fillOrder`, capturing the mispriced spread. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5)

		pub fn place_bid(
			origin: OriginFor<T>,
			commitment: H256,
			user_op: BoundedVec<u8, ConstU32<1_048_576>>,
		) -> DispatchResult {
			let filler = ensure_signed(origin)?;

			// Validate user_op is not empty
			ensure!(!user_op.is_empty(), Error::<T>::InvalidUserOp);

			// Phantom orders have stricter rules: one bid per filler, no updates, and only
			// within the configured acceptance window after the order was registered. Every
			// active pair is checked, not just the most recently generated one.
			if let Some(active) = CurrentPhantomOrder::<T>::get() {
				if let Some((_, info)) = active.iter().find(|(c, _)| *c == commitment) {
					let window: BlockNumberFor<T> = Self::phantom_bid_window().into();
					ensure!(
						frame_system::Pallet::<T>::block_number() <= info.created_at_block + window,
						Error::<T>::PhantomOrderBidWindowClosed
					);
					ensure!(
						!Bids::<T>::contains_key(&commitment, &filler),
						Error::<T>::DuplicatePhantomBid
					);
				}
			}

			// If a bid already exists, unreserve the old deposit first
			if let Some(old_deposit) = Bids::<T>::get(&commitment, &filler) {
				<T as Config>::Currency::unreserve(&filler, old_deposit);
			}

			let deposit = Self::storage_deposit_fee();

			// Reserve the new deposit
			<T as Config>::Currency::reserve(&filler, deposit)
				.map_err(|_| Error::<T>::InsufficientBalance)?;

			// Store the bid in offchain storage
			let bid = Bid { filler: filler.clone(), user_op: user_op.to_vec() };
			let offchain_key = Self::offchain_bid_key(&commitment, &filler);
			offchain_index::set(&offchain_key, &bid.encode());

			// Store deposit amount in onchain storage for discoverability and accurate refunds
			Bids::<T>::insert(&commitment, &filler, deposit);

			Self::deposit_event(Event::BidPlaced { filler, commitment, deposit });

			Ok(())
		}

	private quoteSnapshot(
		params: QuoteIntentParams,
		protocolFeeBps: bigint,
		snapshot: PhantomOrderPriceSnapshot,
	): PhantomSnapshotQuoteIntentResult {
		if (params.amountIn !== undefined) {
			const netAmountIn = deductProtocolFee(params.amountIn, protocolFeeBps)
			const amountOut = (netAmountIn * snapshot.medianPrice) / snapshot.standardAmount
			if (amountOut <= 0n) {
				throw new InvalidPhantomSnapshotError(snapshot.commitment, "quote rounds down to zero output")
			}
			return this.buildResult("EXACT_INPUT", params.amountIn, amountOut, protocolFeeBps, snapshot)
		}

		if (params.amountOut === undefined) throw new Error("Quote amount is missing after validation")
		const netAmountIn = divCeil(params.amountOut * snapshot.standardAmount, snapshot.medianPrice)
		const amountIn = grossUpForProtocolFee(netAmountIn, protocolFeeBps)
		return this.buildResult("EXACT_OUTPUT", amountIn, params.amountOut, protocolFeeBps, snapshot)
	}

	private buildResult(
		tradeType: PhantomSnapshotQuoteIntentResult["tradeType"],
		amountIn: bigint,
		amountOut: bigint,
		protocolFeeBps: bigint,
		snapshot: PhantomOrderPriceSnapshot,
	): PhantomSnapshotQuoteIntentResult {
		return {
			strategy: "phantom_snapshot",
			tradeType,
			amountIn,
			amountOut,
			quoteMetadata: {
				quoteChain: PHANTOM_INTENT_QUOTE_CHAIN,
				commitment: snapshot.commitment,
				tokenA: snapshot.tokenA,
				tokenB: snapshot.tokenB,
				standardAmount: snapshot.standardAmount,
				medianPrice: snapshot.medianPrice,
				lowestPrice: snapshot.lowestPrice,
				highestPrice: snapshot.highestPrice,
				blockNumber: snapshot.blockNumber,
				snapshotTime: snapshot.snapshotTime,
				bidCount: snapshot.bidCount,
				protocolFeeBps,
			},
		}
	}

	private validateSnapshot(snapshot: PhantomOrderPriceSnapshot): void {
		if (snapshot.standardAmount <= 0n) {
			throw new InvalidPhantomSnapshotError(snapshot.commitment, "standardAmount must be greater than zero")
		}
		if (snapshot.medianPrice <= 0n) {
			throw new InvalidPhantomSnapshotError(snapshot.commitment, "medianPrice must be greater than zero")
		}
		if (snapshot.bidCount <= 0) {
			throw new InvalidPhantomSnapshotError(snapshot.commitment, "bidCount must be greater than zero")
		}
		if (Number.isNaN(snapshot.snapshotTime.getTime())) {
			throw new InvalidPhantomSnapshotError(snapshot.commitment, "snapshotTime is invalid")
		}
	}

    function fillOrder(Order calldata order, FillOptions calldata options) public payable nonReentrant {
        if (order.deadline < _blockNumber()) revert Expired();
        bytes32 commitment = keccak256(abi.encode(order));

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain && orderSource != currentChain) revert WrongChain();
        if (!isSameChain && orderDest != currentChain) revert WrongChain();

        if (_filled[commitment] != address(0)) revert Filled();

        if (_params.solverSelection) {
            bytes32 storedSelectionHash;
            assembly {
                storedSelectionHash := tload(commitment)
            }

            bytes32 expectedSelectionHash = keccak256(abi.encode(msg.sender, order.session));
            if (storedSelectionHash != expectedSelectionHash) revert Unauthorized();
        }

        uint256 outputsLen = order.output.assets.length;
        if (options.outputs.length != outputsLen) revert InvalidInput();
        if (order.inputs.length != outputsLen) revert InvalidInput();

        if (isSameChain) {
            _fillSameChain(order, options, commitment);
        } else {
            _fillCrossChain(order, options, commitment);
        }

        if (_params.priceOracle != address(0)) {
            IIntentPriceOracle(_params.priceOracle)
                .recordSpread(commitment, order.source, order.inputs, options.outputs);
        }
    }
