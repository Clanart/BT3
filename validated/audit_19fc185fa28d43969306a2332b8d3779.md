### Title
Unsynchronized read of `auctionEntryPointVersion` in `BidPool.getBidTxGasLimit` races with `updateAuctionInfo` writes, causing corrupted call-data encoding for auction bids - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool.getBidTxGasLimit` releases `auctionInfoMu` before reading the `bp.auctionEntryPointVersion` field, while `updateAuctionInfo` (invoked from `PostInsertBlock` on every block) writes `bp.auctionEntryPointVersion` (and clears/rebuilds the pool) under the same mutex. This is structurally the same bug class as the reported ice driver CVE: a shared configuration field is protected by a lock in some access paths but read outside the lock in another, allowing an asynchronous background update (block processing) to race with a synchronously-triggered configuration consumer (bid ingestion), producing a torn/inconsistent read.

### Finding Description
`BidPool` stores auction configuration (`auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, `bidTxGasBuffer`) under `auctionInfoMu` [1](#0-0) .

`updateAuctionInfo` is called once per block from `PostInsertBlock` and mutates all four fields, including `auctionEntryPointVersion`, while holding the write lock for the whole function body [2](#0-1) , and this is triggered unconditionally on every inserted block after the Randao fork [3](#0-2) .

`AddBid` (reachable via the public `auction_submitBid` RPC and via P2P `HandleBid`) calls `validateBid` → `validateBidSigs`, which correctly takes `auctionInfoMu.RLock()` for the whole function and reads `bp.auctionEntryPoint`/`bp.auctioneer` safely [4](#0-3) . However, `AddBid` then calls `getBidTxGasLimit`, which takes the lock only to read `bidTxGasBuffer`, releases it, and afterwards reads `bp.auctionEntryPointVersion` completely unprotected: [5](#0-4) 

```go
func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	...
```

`bp.auctionEntryPointVersion` is a Go `string` (a `{pointer,len}` header). A concurrent unsynchronized write from `updateAuctionInfo` racing with this read is a data race that can yield a torn value (mismatched pointer/length pair), which can either panic the node (out-of-bounds slice access when the runtime dereferences a stale pointer with an inconsistent length) or silently select the wrong version constant for `system.EncodeAuctionCallData`.

This directly parallels the CVE's root cause: the ice driver protected some access paths to shared XDP configuration with a lock but left a window where an asynchronously triggered event (PF reset) could race with configuration reads, producing use of stale/inconsistent state and a crash. Here, the asynchronous trigger is `PostInsertBlock`/`updateAuctionInfo` (fired every block during normal chain progression), and the racing reader is `AddBid`, reachable from an ordinary auction bidder via RPC or P2P.

### Impact Explanation
- If `EncodeAuctionCallData` is invoked with a torn/incorrect `auctionEntryPointVersion`, it can select the wrong ABI encoding path for the bid's call data or the wrong gas floor computation for a different version's selector, causing bids to be executed against the auction entry point with mismatched semantics (e.g., wrong function selector/version assumed by `bidTxGasBuffer`/`floorDataGas`), which can misprice/underprice gas for the injected bid transaction or otherwise corrupt the bundle building for that block.
- A torn Go string read is undefined behavior at the runtime level and can cause a segfault/panic in the CN process (`-race` would flag this immediately), which is a liveness/availability impact on block production nodes running the auction module — this can be triggered purely by normal chain progression plus a bid submitted by any external auction bidder, satisfying the "state divergence between honest nodes / DoS via crash" criteria within the allowed auction-module scope.

### Likelihood Explanation
`updateAuctionInfo` runs on every single block once the Randao fork and auction module are active [3](#0-2) , so the writer side fires continuously and predictably. Any bidder submitting a bid via `auction_submitBid` RPC or P2P `HandleBid` at any time triggers `AddBid` → `getBidTxGasLimit`'s unprotected read. Given the frequency of block insertion (every block interval) and the fact that bid submission is fully attacker-controlled and unauthenticated at the network layer (any public bidder), the race window is realistically hit under sustained bid traffic, especially near block boundaries.

### Recommendation
Read `bp.auctionEntryPointVersion` under `auctionInfoMu` (RLock) in `getBidTxGasLimit`, consistent with how `validateBidSigs` already does it, e.g.:
```go
bp.auctionInfoMu.RLock()
buffer := bp.bidTxGasBuffer
version := bp.auctionEntryPointVersion
bp.auctionInfoMu.RUnlock()

data, err := system.EncodeAuctionCallData(bid, version)
```
More broadly, audit all direct field accesses on `BidPool` (`bp.auctionEntryPointVersion`, `bp.auctioneer`, `bp.auctionEntryPoint`, `bp.bidTxGasBuffer`) outside of `validateBidSigs`/`updateAuctionInfo` to ensure every read/write is done while holding `auctionInfoMu`, mirroring the fix pattern in the referenced CVE (add/verify a single mutex protects all accesses of the shared configuration, with no unprotected windows).

### Proof of Concept
1. Start a CN node with the auction module enabled post-Randao fork, with valid `auctioneer`/`AuctionEntryPoint` system contract configuration.
2. Run the node normally so `PostInsertBlock` → `updateAuctionInfo` executes on every new block (this happens automatically as blocks are produced) — this continuously calls `bp.auctionInfoMu.Lock()` and writes `bp.auctionEntryPointVersion` under lock [2](#0-1) .
3. Concurrently, have a bidder repeatedly call `auction_submitBid` (or send bids via the CN-P2P bid channel) so `AddBid` → `getBidTxGasLimit` executes concurrently and reads `bp.auctionEntryPointVersion` without the lock [5](#0-4) .
4. Run this scenario under `go test -race` (or equivalent instrumented binary) to observe the detected data race on `bp.auctionEntryPointVersion`; under production (non-instrumented) conditions this manifests intermittently as either an incorrect ABI/version selection in `system.EncodeAuctionCallData` or a runtime panic from a torn string header.

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}
