### Title
Gasless lend/repay amounts computed from nominal transaction `Fee()` (gas limit) instead of actual gas consumed, enabling proposer-fund drain via gas-limit inflation - (File: kaiax/gasless/impl/getter.go)

### Summary
The gasless bundling module computes the amount the block proposer lends to a gasless user (`LendAmount`) and the amount the user must repay via the token swap (`RepayAmount`) from the *nominal* `Transaction.Fee()` of the user's own `ApproveTx`/`SwapTx` (i.e. `GasLimit * GasPrice`), not from the gas that is *actually consumed* when those transactions execute. This is the same "preview vs. action" inconsistency class described in the external report: a value computed by an estimating/nominal function is substituted for the value produced by the actual execution path, and the two are never reconciled.

### Finding Description
`lendAmount()` and `repayAmount()` in [1](#0-0)  derive the amount lent to (and later repaid by) a gasless user purely from `tx.Fee()` of the caller-supplied `ApproveTx`/`SwapTx` legacy transactions:
- `LendAmount = ApproveTx.Fee() + SwapTx.Fee()`
- `RepayAmount = SwapTx.GasPrice()*TxGas + LendAmount`

`GetLendTxGenerator` then mints a proposer-funded `LendTx` crediting the user's EOA with exactly this `LendAmount` before the `ApproveTx`/`SwapTx` are executed: [2](#0-1) . The bundle (`LendTx`, optional `ApproveTx`, `SwapTx`) is assembled per-sender directly from mempool transactions in `ExtractTxBundles`, which any unprivileged sender can trigger just by submitting an approve+swap tx pair recognized by `IsApproveTx`/`IsSwapTx`: [3](#0-2) .

`Transaction.Fee()`-style nominal fee is a *preview* quantity based on the declared `Gas()` (gas limit), whereas the state transition that actually executes `ApproveTx`/`SwapTx` only ever burns/pays `gasUsed * gasPrice`, refunding the unused portion of the gas allowance back to the sender via `returnGas()` before computing the fee that is transferred to the coinbase/rewardbase: [4](#0-3) . Because a legacy sender fully controls both `GasPrice` and `GasLimit` of their own `ApproveTx`/`SwapTx` (these must be `TxTypeLegacyTransaction` per `decodeFunctionCall`: [5](#0-4) ), a user can set an inflated `GasLimit` while the call itself consumes only a small fraction of that gas (`gasUsed << gasLimit`).

The `LendTx` credits the user with the full nominal `Fee()`-based `LendAmount`, but the `ApproveTx`/`SwapTx` execution only spends `gasUsed*gasPrice` of it, refunding the rest back into the same account. The user is only required to route `RepayAmount` (computed off the same inflated nominal `Fee()`) back to the proposer through the swap — which is funded from the user's *own* ERC20 tokens being swapped, not from the leftover lent KAIA. The difference `(GasLimit - GasUsed) * GasPrice`, summed over the approve/swap legs, is never reclaimed from the user: it was credited by the proposer's `LendTx` but never consumed nor repaid, and remains in the user's wallet as clear profit extracted from the proposer.

### Impact Explanation
Any unprivileged sender able to submit a gasless approve+swap transaction pair can inflate `GasLimit` on those legacy transactions (keeping `GasPrice` at whatever is required to make `IsGaslessPattern`/`VerifyExecutable` pass) to increase `LendAmount`/`RepayAmount` far beyond the gas actually consumed, then pocket the unspent lent KAIA that the state-transition refund mechanism leaves in their own account. This is a direct, unauthorized value transfer from the block proposer (who funds `LendTx`) to the transaction sender, i.e. fee-delegation/gasless-settlement abuse reachable purely via a submitted transaction bundle.

### Likelihood Explanation
High feasibility: the attacker fully controls the `GasLimit` field of their own `ApproveTx` and `SwapTx` (both self-signed legacy transactions), and `ExtractTxBundles`/`VerifyExecutable` only check that `AmountRepay` matches the formula-derived value — they never validate that `GasLimit` is close to actual gas usage, nor recompute `LendAmount`/`RepayAmount` from post-execution `GasUsed`. No special privileges, timing, or node cooperation beyond normal mempool submission are required.

### Recommendation
Compute `LendAmount`/`RepayAmount` from the intrinsic/expected gas cost of the `approve`/`swapForGas` calls (or cap the allowed `GasLimit` for these legacy transactions to a tightly bounded value, e.g. the intrinsic gas plus a small fixed margin), rather than trusting the caller-supplied `GasLimit` via `Fee()`. Alternatively, settle `LendAmount`/`RepayAmount` post-execution using each transaction's actual `GasUsed` (as reported in the receipt) instead of the pre-execution nominal fee.

### Proof of Concept
1. Attacker crafts a legacy `ApproveTx` (`approve(spender=SwapRouter, amount=MaxUint256)`) with `GasPrice = P` and an inflated `GasLimit = L_a` (e.g. 10,000,000), even though `approve` only consumes ~46,000 gas.
2. Attacker crafts a matching legacy `SwapTx` (`swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)`) with the same `GasPrice = P` and inflated `GasLimit = L_s`, where `amountRepay` is set to exactly `repayAmount(approveTx, swapTx)` as required by `VerifyExecutable`'s SP4 check ( [6](#0-5) ), so the bundle passes validation.
3. The node's `ExtractTxBundles` builds a `LendTx` crediting the attacker's EOA with `LendAmount = (L_a+L_s)*P` ( [7](#0-6) , [2](#0-1) ).
4. During execution, `ApproveTx`/`SwapTx` only consume `gasUsed_a`/`gasUsed_s` (each far below `L_a`/`L_s`); `blockchain/state_transition.go`'s `returnGas()` refunds `(L_a - gasUsed_a)*P` and `(L_s - gasUsed_s)*P` back to the attacker's account before the coinbase/rewardbase fee transfer of only `gasUsed*P` occurs ( [4](#0-3) ).
5. `SwapTx` repays `amountRepay` to the proposer strictly from the swapped ERC20 proceeds, which is fully accounted for by the formula and unrelated to the unspent lent KAIA sitting in the attacker's wallet.
6. Net result: the attacker retains `(L_a - gasUsed_a + L_s - gasUsed_s) * P` KAIA that was funded by the proposer's `LendTx` and never repaid or consumed — profit scales linearly with the attacker-chosen gas-limit inflation.

Note: this analysis assumes `Transaction.Fee()` (declared in `blockchain/types/transaction.go`) computes `GasLimit * GasPrice` per standard Kaia/Ethereum convention; the exact body of `Fee()` was not directly retrievable in this session due to tool/iteration limits, so this specific implementation detail should be re-confirmed against source before remediation.

func decodeFunctionCall(tx *types.Transaction, method abi.Method) (common.Address, map[string]interface{}, bool) {
	if tx.Type() != types.TxTypeLegacyTransaction || // not legacy tx: unable to statically determine the max gas fee.
		tx.To() == nil || // not a contract call.
		len(tx.Data()) < 4 || // too short to be a contract call.
		!bytes.Equal(tx.Data()[:4], method.ID) { // not the target function.
		return common.Address{}, nil, false
	}

	inputs := make(map[string]interface{})
	err := method.Inputs.UnpackIntoMap(inputs, tx.Data()[4:])
	return *tx.To(), inputs, err == nil
}

func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
