### Title
CosmWasm-to-EVM delegatecall bypasses the `WhitelistedCwCodeHashesForDelegateCall` security-manager-style allowlist - (File: x/evm/keeper/evm.go)

### Summary
The Tomcat CVE (GHSA-3mjp-p938-4329) is a case where a security boundary (the `SecurityManager`) was supposed to be enforced based on a configuration parameter, but the enforcement point never actually checked that parameter, letting an untrusted caller escape the sandbox. Sei-chain has a structurally identical pattern: `x/evm` params define `WhitelistedCwCodeHashesForDelegateCall`, a governance-configured allowlist of CosmWasm code hashes that are meant to be permitted to `delegatecall` into EVM contract storage context. However, the actual message handler that executes a CW→EVM delegatecall, `HandleInternalEVMDelegateCall`, never reads or checks this parameter.

### Finding Description
`x/evm/types/params.go` defines and validates `WhitelistedCwCodeHashesForDelegateCall` as a `[][]byte` parameter [1](#0-0) , and it is wired into the parameter set for every historical params version [2](#0-1) . The wasm binding layer that builds the `MsgInternalEVMDelegateCall` populates a `CodeHash` field taken directly from the calling CosmWasm contract's `CodeInfo.CodeHash` [3](#0-2) , clearly intending that hash to be checked against the whitelist before the delegatecall is allowed to proceed (this is the "delegatecall gating by configuration" analog to Tomcat's JSP-Servlet-parameter-based SecurityManager gate).

The actual enforcement point, `Keeper.HandleInternalEVMDelegateCall` in `x/evm/keeper/evm.go`, only checks that the `FromContract` is a registered pointer contract for the target EVM address via `GetAnyPointerInfo`/`PointerReverseRegistryKey` — it never reads `req.CodeHash`, never calls `GetParams().WhitelistedCwCodeHashesForDelegateCall`, and never calls the `Whitelist.IsHashInWhiteList` helper that exists specifically for this purpose [4](#0-3) . The `IsHashInWhiteList` helper method exists in the codebase [5](#0-4)  but a full-index search across the entire repository shows no call site in `x/evm/keeper/*.go` that invokes it or the `WhitelistedCwCodeHashesForDelegateCall` param at the delegatecall message-handling boundary.

This mirrors the Tomcat bug class precisely: a governance/config-controlled allowlist exists and is validated/marshaled correctly, but the code path that is supposed to consult it at request time silently omits the check, so the configured restriction has no actual effect on who can delegatecall.

### Impact Explanation
If `HandleInternalEVMDelegateCall` is the only place code-hash gating for CW→EVM delegatecalls is supposed to happen, any CosmWasm contract registered as a pointer contract (via `AddCW20`/`AddCW721`/`AddNative` in the pointer precompile) can perform delegatecalls into the associated EVM contract's storage context regardless of the governance-configured `WhitelistedCwCodeHashesForDelegateCall` allowlist. A delegatecall runs with the target contract's code but the caller's storage/state context; an attacker-controlled or malicious pointer/wrapper CW contract that should not be trusted with delegatecall privileges (per the on-chain allowlist) can arbitrarily manipulate EVM contract storage slots it delegatecalls into. Depending on what logic lives behind the pointer-registered EVM contracts, this can lead to unauthorized token transfers, balance/allowance corruption, or other state manipulation — i.e., concrete fund loss or unauthorized transfer via the pointer bridge, which is in scope per the validation criteria.

### Likelihood Explanation
Reachable directly by any pointer-registered CosmWasm contract's message handling, i.e. by any wasm contract that has been registered as a pointer for an EVM target and that a user can invoke with a `DelegateCallEVM` binding message via `wasmbinding/encoder.go` → `x/evm/client/wasm/encoder.go` → `HandleInternalEVMDelegateCall`. No validator or governance collusion is required beyond the normal (public) act of registering a pointer contract, which is itself an unprivileged, permissionless action (unless `RegisterPointerDisabled` is set). This is high likelihood because it requires only a single wasm message from a normal CosmWasm user/pointer deployer — exactly the entities in scope per the rules.

### Recommendation
Add an explicit check inside `HandleInternalEVMDelegateCall` (or immediately before it is invoked) that: (1) loads `k.GetParams(ctx).WhitelistedCwCodeHashesForDelegateCall`, (2) constructs/uses the `Whitelist` type's `IsHashInWhiteList` (or equivalent byte-slice comparison) against `req.CodeHash`, and (3) rejects the delegatecall with an error if the hash is not present in the allowlist — mirroring the intent already encoded in `EncodeDelegateCallEVM`'s population of `CodeHash`.

### Proof of Concept
1. Deploy/instantiate a CosmWasm contract whose code hash is *not* present in the chain's `WhitelistedCwCodeHashesForDelegateCall` param (default is an empty list, so essentially any contract's hash is absent) [6](#0-5) .
2. Register that contract as a pointer for a target EVM contract using the pointer precompile's `AddCW20`/`AddCW721`/`AddNative` flow.
3. From the CosmWasm contract, issue a `DelegateCallEVM` binding message; this is translated to `MsgInternalEVMDelegateCall` with `CodeHash` set to the contract's own code hash [3](#0-2) .
4. `Keeper.HandleInternalEVMDelegateCall` verifies only the pointer registry match and proceeds to `CallEVM`, executing the delegatecall against the target EVM contract's storage context without ever checking `req.CodeHash` against the configured whitelist [4](#0-3) .
5. Because no whitelist check occurred, the delegatecall succeeds despite the contract's code hash not being allowlisted, demonstrating the bypass of the intended access-control gate.

Note: I could not find any other call site across the repository (including `wasmbinding/`) that performs the whitelist check before this point; the index search for `WhitelistedCwCodeHashesForDelegateCall` and `IsHashInWhiteList` usage returned only definition/param-plumbing files, never an enforcement call. If such a check exists in code not covered by the index (e.g., an ante handler or a file excluded by index size limits), this would need to be confirmed with a full repository clone/Devin session before treating the finding as certain.

func EncodeDelegateCallEVM(rawMsg json.RawMessage, sender sdk.AccAddress, info wasmvmtypes.MessageInfo, codeInfo wasmtypes.CodeInfo) ([]sdk.Msg, error) {
	encodedCallEVM := bindings.DelegateCallEVM{}
	if err := json.Unmarshal(rawMsg, &encodedCallEVM); err != nil {
		return []sdk.Msg{}, err
	}
	decodedData, err := base64.StdEncoding.DecodeString(encodedCallEVM.Data)
	if err != nil {
		return []sdk.Msg{}, err
	}
	s := sender
	if origSender, err := sdk.AccAddressFromBech32(info.Sender); err == nil {
		s = origSender
	}
	internalCallEVMMsg := types.MsgInternalEVMDelegateCall{
		Sender:       s.String(),
		To:           encodedCallEVM.To,
		CodeHash:     codeInfo.CodeHash,
		Data:         decodedData,
		FromContract: sender.String(),
	}
	return []sdk.Msg{&internalCallEVMMsg}, nil
}

func (k *Keeper) HandleInternalEVMDelegateCall(ctx sdk.Context, req *types.MsgInternalEVMDelegateCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	} else {
		return nil, errors.New("cannot use a CosmWasm contract to delegate-create an EVM contract")
	}
	addr, _, exists := k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(common.BytesToAddress([]byte(req.FromContract))))
	if !exists || common.BytesToAddress(addr).Cmp(*to) != 0 {
		return nil, errors.New("only pointer contract can make delegatecalls")
	}
	zeroInt := sdk.ZeroInt()
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	// delegatecall caller must be associated; otherwise any state change on EVM contract will be lost
	// after they asssociate.
	senderEvmAddr, found := k.GetEVMAddress(ctx, senderAddr)
	if !found {
		err := types.NewAssociationMissingErr(req.Sender)
		evmKeeperMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "evm_handle_internal_evm_delegate_call"), attribute.String("type", err.AddressType())))
		return nil, err
	}
	ret, err := k.CallEVM(ctx, senderEvmAddr, to, &zeroInt, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}

package types

import "github.com/ethereum/go-ethereum/common"

func (w *Whitelist) IsHashInWhiteList(h common.Hash) bool {
	for _, s := range w.Hashes {
		if s == h.Hex() {
			return true
		}
	}
	return false
}
