### Title
Payout tx OP_RETURN is unsigned under `SinglePlusAnyoneCanPay`, letting anyone rewrite it to a bogus operator xonly pk and permanently orphan the honest operator's reimbursement - (File: `core/src/verifier.rs`, `core/src/builder/transaction/operator_reimburse.rs`, `core/src/rpc/parser/operator.rs`)

### Summary
The payout transaction's sole input is signed with `TapSighashType::SinglePlusAnyoneCanPay`, which under BIP341 only commits to the input itself and the output at the same index (index 0, the user payout). The anchor output (index 1) and the OP_RETURN output (index 2) carrying the fronting operator's xonly pk are completely unsigned, so anyone who observes the broadcast/mempool payout tx can rebuild a variant with the same signed input/output but an attacker-chosen (nonexistent) xonly pk in the OP_RETURN, and get that variant confirmed instead. `update_finalized_payouts` blindly trusts whatever OP_RETURN ends up on-chain to attribute the payout to an operator, and `get_first_unhandled_payout_by_operator_xonly_pk` requires an exact match to a real operator's key, so the honest operator that actually fronted the withdrawal never gets picked up for reimbursement.

### Finding Description
The broken binding, stated as an equality:
`withdrawals.payout_payer_operator_xonly_pk` (as recorded by `update_finalized_payouts` from the confirmed payout tx's OP_RETURN) `==` xonly public key of the operator who actually signed/broadcast/fronted the withdrawal's payout output.

Root cause and path:
1. `Operator::withdraw` builds the payout tx via `create_payout_txhandler`, which has exactly one input (the withdrawal UTXO, key-path spend) and three outputs: `[0] payout, [1] anchor, [2] OP_RETURN(operator_xonly_pk)`. [1](#0-0) 
2. The user's `in_signature` for that input is required to use `TapSighashType::SinglePlusAnyoneCanPay`, enforced both at the operator ("Ensure the signature uses SinglePlusAnyoneCanPay sighash type") and at the gRPC parser (`parse_withdrawal_sig_params`). [2](#0-1) [3](#0-2) 
3. Under BIP341, `SIGHASH_SINGLE|ANYONECANPAY` commits only to the signed input and the output at the *same index* as that input (index 0). It does **not** commit to any other output, including the anchor (index 1) or the OP_RETURN (index 2), and `ANYONECANPAY` means no other inputs need to be signed either. Any party who observes the signed input+witness (visible once the tx enters the mempool, or even earlier if leaked) can therefore construct a different transaction that reuses the same signed input/witness and the same output-0, but with a different anchor and/or a fabricated OP_RETURN payload (any 33 arbitrary bytes such that `XOnlyPublicKey::from_slice` succeeds but corresponds to no registered operator), fund it with their own extra input for fees, and get it mined first (or via RBF replacement) instead of the honest operator's original.
4. When this attacker-shaped payout tx confirms, `update_finalized_payouts` parses the OP_RETURN and stores whatever xonly pk is there (or `None` if invalid) as `payout_payer_operator_xonly_pk`, with no cross-check against which operator's collateral/kickoff/round actually authorized fronting this withdrawal idx. [4](#0-3) 
5. `get_first_unhandled_payout_by_operator_xonly_pk` only returns withdrawals whose `payout_payer_operator_xonly_pk` exactly equals the querying operator's own key. [5](#0-4) 
6. `PayoutCheckerTask::run_once` is the only automated production entry point that calls `handle_finalized_payout`/starts the reimbursement kickoff, and it is entirely gated by step 5. [6](#0-5) 
7. `InternalFinalizedPayout` (the only other caller of `handle_finalized_payout`) is explicitly test-only and returns `permission_denied` outside `cfg!(test)`, so it is not a real bypass in production. [7](#0-6) 

Since the fabricated xonly pk matches no real operator, no operator's `PayoutCheckerTask` will ever find this idx as "unhandled," so `handle_finalized_payout`/kickoff is never triggered for it. The honest operator who actually paid the user out of their own funds has no way to be reimbursed for this withdrawal.

### Impact Explanation
This permanently locks the honest operator's collateral/kickoff path for the specific withdrawal idx: the operator already paid BTC to the user off-chain-fronted (their own wallet funds left the operator), but the bridge's bookkeeping never attributes the confirmed payout to any real operator, so `handle_finalized_payout` (which allocates a kickoff/reimburse connector) is never invoked for that idx, and `mark_payout_handled` never runs. This matches the Critical category "an honest operator permanently unable to be reimbursed." It is repeatable per withdrawal: any withdrawal fronted by an operator is exposed to this race as long as the attacker can observe the mempool (or the leaked payout tx) before/at confirmation and get their malleated variant mined instead (e.g., via a higher-fee RBF replacement using the `ANYONECANPAY` flexibility to add fee inputs).

### Likelihood Explanation
Preconditions are low-privilege and cheap: the attacker only needs (a) visibility into the mempool or the broadcast payout tx (trivial, it's a public Bitcoin transaction), and (b) enough BTC to pay a competitive/higher fee via an additional `ANYONECANPAY` input for their replacement transaction. No operator, verifier, or aggregator credentials are needed; the signature reuse is possible precisely because the protocol permits/enforces `SinglePlusAnyoneCanPay`, which was seemingly chosen to let operators freely construct the surrounding transaction, but leaves the OP_RETURN unauthenticated. This is fully within the "unprivileged attacker" threat model (broadcast transactions, pay fees) and does not require majority hashrate — only a mempool/fee race, or convincing a miner to include the attacker's version (e.g. same-fee-rate race, or RBF with a higher fee).

### Recommendation
Bind the operator attribution to something the signature actually commits to, rather than trusting an unauthenticated OP_RETURN output on a `SinglePlusAnyoneCanPay`-signed input. Options:
- Change the withdrawal signature scheme so it covers the OP_RETURN output (e.g., require `SIGHASH_ALL` for the withdrawal input, or restructure so operator attribution is committed within the sighash's covered output(s)).
- Alternatively, remove reliance on the on-chain OP_RETURN entirely for reimbursement bookkeeping: have each operator independently record (in its own DB, at `withdraw()` time, before broadcast) that it is fronting withdrawal idx `i`, and have `update_finalized_payouts`/`PayoutCheckerTask` cross-check the confirmed payout tx's spent input (`withdrawal_utxo` outpoint) against that operator's own local "sent payout" record instead of (or in addition to) the OP_RETURN content, so a mutated/foreign OP_RETURN cannot orphan the fronting operator's claim.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
