### Title
Use of `transfer()` instead of `call()` in the shipped `WSEI.sol` contract can permanently freeze withdrawals - (File: contracts/src/WSEI.sol)

### Summary
The canonical "Wrapped Sei" (WSEI) contract, whose source is [1](#0-0)  and whose compiled bytecode is embedded and shipped as a production artifact of the EVM module (`x/evm/artifacts/wsei/WSEI.bin`, loaded via `GetBin()`), implements `withdraw()` using Solidity's `.transfer()` primitive instead of the recommended low-level `call()` pattern.

### Finding Description
`WSEI.withdraw()` sends the underlying native value back to `msg.sender` with `payable(msg.sender).transfer(wad)`: [1](#0-0) 

`transfer()` forwards a hard-capped stipend of 2300 gas to the recipient. This artifact is not merely a test fixture — it is embedded and served by the production `x/evm/artifacts/wsei` package, which exposes `GetBin()`/`GetABI()` used by the chain's CLI to deploy the canonical WSEI contract on any Sei EVM chain (`CmdDeployWSEI`): [2](#0-1) [3](#0-2) 

Any unprivileged EVM user, smart-contract wallet, DEX router, or other contract that holds WSEI and calls `withdraw()` can be denied its funds if:
1. The caller is a smart contract without a payable fallback/receive function.
2. The caller's `receive`/fallback function needs more than 2300 gas (e.g., it emits an event, writes storage, or forwards through a proxy's `delegatecall` dispatcher, which itself consumes gas before reaching the actual logic).
3. The call passes through an intermediate proxy contract, which alone can exceed the 2300 gas stipend even if the final logic is trivial.

In all these cases, `transfer()` reverts the entire transaction, so the caller's WSEI balance was already decremented in the same call before the revert only reverts the whole transaction atomically (so no fund loss from partial state change) — but any contract-based caller with such a fallback pattern is permanently unable to withdraw WSEI back into native SEI through this contract, since there is no alternative unwrap path once WSEI is the entrenched canonical wrapped-native asset on the chain.

### Impact Explanation
This meets the "permanent freezing" bar: contracts (e.g., proxy wallets, multisigs, DEX pools, or any smart contract integrating with WSEI as if it were a standard WETH-style wrapped native asset) that hold WSEI cannot ever unwrap it back to native SEI if their receiving logic requires more than 2300 gas or is behind a proxy. Because WSEI is deployed and distributed as the chain's official wrapped-native ERC20 (via `CmdDeployWSEI`/`x/evm/artifacts/wsei`), this affects any downstream integrator relying on the artifact rather than a hypothetical hand-rolled contract, and the funds have no other unwrap mechanism.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: proxy-pattern wallets (e.g., Gnosis-Safe-style multisigs, ERC-1967/UUPS proxies) are extremely common receivers of ERC-20/WETH-style tokens, and their fallback dispatch logic routinely exceeds 2300 gas. Any protocol or wallet that integrates with the officially shipped WSEI artifact using such a pattern will hit this problem on the very first withdrawal attempt.

### Recommendation
Replace `payable(msg.sender).transfer(wad)` in `withdraw()` with a low-level `call` and explicit success check, e.g.:
```solidity
(bool success, ) = msg.sender.call{value: wad}("");
require(success, "WSEI: ETH transfer failed");
```
Add a reentrancy guard (checks-effects-interactions is already followed since balance is decremented before the external call) and re-deploy/re-publish the corrected artifact bytecode in `x/evm/artifacts/wsei`.

### Proof of Concept
1. Deploy a receiver contract `C` behind a minimal proxy (e.g., an EIP-1167 clone) whose `fallback()`/`receive()` dispatches via `delegatecall` to implementation logic that writes to storage (any realistic proxy wallet pattern), consuming > 2300 gas.
2. From `C`, call `WSEI.deposit()` with some native SEI value to mint WSEI balance.
3. From `C`, call `WSEI.withdraw(wad)`.
4. Observe the internal `msg.sender.transfer(wad)` call reverts due to out-of-gas within the 2300 gas stipend, causing the whole `withdraw` transaction to revert.
5. `C`'s WSEI balance remains locked with no alternative code path to redeem it for native SEI, since `WSEI.sol` provides only `withdraw()` for unwrapping.

			}

				return err
			}

					return err
				}
			}

			if err != nil {
				return err
			}

func GetParsedABI() *abi.ABI {
	if cachedABI != nil {
		return cachedABI
	}
	parsedABI, err := abi.JSON(strings.NewReader(string(GetABI())))
	if err != nil {
		panic(err)
	}
	cachedABI = &parsedABI
	return cachedABI
}

func GetBin() []byte {
	if cachedBin != nil {
		return cachedBin
	}
	code, err := f.ReadFile("WSEI.bin")
	if err != nil {
		panic("failed to read WSEI contract binary")
	}
	bz, err := hex.DecodeString(string(code))
	if err != nil {
		panic("failed to decode WSEI contract binary")
	}
	cachedBin = bz
	return bz
}
