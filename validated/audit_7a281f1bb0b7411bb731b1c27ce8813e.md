### Title
SSRF via unauthorized on-chain Mirror coins causing DataLayer to fetch attacker-controlled URLs - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
DataLayer's mirror-URL mechanism lets **any wallet on the network**, without any relationship to a store's owner, publish a "mirror" record for *any* DataLayer singleton (`launcher_id`) by spending a coin to the generic `create_mirror_puzzle()` address with the target `launcher_id` and arbitrary URL strings encoded as memos. Any node that tracks that store will treat those attacker-chosen URLs as legitimate mirror/subscription servers and will automatically issue outbound HTTP requests to them, matching the SSRF bug class in CVE-2024-22873 (Blueking CMDB's subscription webhook feature blindly POSTing to attacker-supplied URLs).

### Finding Description
The mirror-coin puzzle is a shared, unauthenticated puzzle hash: [1](#0-0) 

Anyone can spend to it and encode an arbitrary `launcher_id` plus arbitrary URL strings as `CREATE_COIN` memos: [2](#0-1) 

`get_mirror_info()` parses those memos straight from the spend's conditions with no restriction tying the `launcher_id` to the spender's identity or ownership: [3](#0-2) 

On sync, `DataLayerWallet.coin_added()` accepts and stores *any* mirror coin as long as the wallet is tracking that `launcher_id` (i.e., subscribed to the store) — it does **not** verify that the mirror creator owns or is authorized for that store: [4](#0-3) 

The DataLayer service periodically pulls these wallet-recorded mirror URLs and merges them into its local subscription list: [5](#0-4) [6](#0-5) 

Those URLs are then used, without validation of scheme/host, as real download targets by `fetch_and_validate()` / `download_file()` / `http_download()`, which open outbound `aiohttp` HTTP connections (`GET`/`POST`) to the attacker-supplied host: [7](#0-6) [8](#0-7) 

This entire chain — mirror creation → wallet sync → `periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()` → outbound HTTP — runs automatically in the background loop without any local operator action: [9](#0-8) 

### Impact Explanation
Any unprivileged party who can submit a spend bundle (i.e., anyone with a small amount of XCH) can force a DataLayer node that is subscribed to/tracking a given `launcher_id` to make unsolicited outbound HTTP requests to attacker-chosen addresses — including `127.0.0.1`, internal/private network ranges, or link-local metadata endpoints — at the time the node's own background sync loop runs. This is a classic SSRF: the requesting node discloses its network position/reachability (through timing/response of the download attempt, error logs, or successful data exfiltration into the DataLayer file cache) and can be used to probe/attack internal services reachable only from that node. It does not by itself constitute coin theft or consensus divergence, but it is a genuine, unauthenticated network-reachable vulnerability matching the CVE's bug class (SSRF via subscription mechanism) and meets the "Medium/High" severity bar due to network-boundary violation from an untrusted, on-chain-triggered input.

### Likelihood Explanation
Likelihood is high for any node that runs the DataLayer service and subscribes to/tracks third-party stores (a normal DataLayer usage pattern for mirroring/replicating other people's stores). Creating a malicious mirror coin costs only a small amount of XCH plus a fee, requires no special privilege, and needs no coordination with the store owner. The exploit is fully passive from the victim's perspective — the victim's own `periodically_manage_data()` loop will pick up the malicious mirror URL and attempt to fetch from it automatically.

### Recommendation
- Restrict who can create effective "mirror" entries for a given `launcher_id`, e.g., require the mirror-creating spend to be authorized by (or otherwise cryptographically tied to) the store's singleton owner, rather than accepting any coin spend that merely references the `launcher_id` in a memo.
- Validate/sanitize mirror and subscription URLs before use: reject non-HTTP(S) schemes, private/loopback/link-local IP ranges, and known cloud-metadata addresses (SSRF allow/deny-listing), or route DataLayer HTTP fetches through an egress proxy with such restrictions enforced.
- Consider making `update_subscriptions_from_wallet` treat externally-supplied (`from_wallet == 1`) mirror URLs as lower-trust than locally configured subscription URLs, and require explicit operator opt-in before auto-fetching from them.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (via `DataLayerWallet.create_new_mirror`) targeting a victim's `launcher_id` (any DataLayer store the attacker does not own), with `urls=["http://169.254.169.254/latest/meta-data/", "http://10.0.0.5:9999/internal-admin"]`, per [2](#0-1) .
2. This spend is broadcast and confirmed on-chain like any normal transaction.
3. A victim node that is tracking that `launcher_id` (e.g., via `dl_track_new`/subscription to the store) picks up the new mirror coin in `coin_added()` and stores the attacker's URLs as `from_wallet=1` mirrors, per [4](#0-3) .
4. On its next `periodically_manage_data()` cycle, the victim's DataLayer service calls `update_subscriptions_from_wallet()` → merges the attacker URLs into its subscription table → `fetch_and_validate()` selects one of the URLs and issues an HTTP request to it via `download_file()`/`http_download()`, per [7](#0-6)  and [8](#0-7) .
5. The victim node has now made an unauthenticated outbound request to an attacker-chosen internal/local address, completing the SSRF.

**Uncertainty note:** I could not fully inspect `http_download()`'s implementation (only its call site was retrieved) to confirm whether it enforces any scheme/host allow-list before connecting; if such validation exists there, it would partially mitigate this finding. This should be verified directly in `chia/data_layer/download_data.py` before treating this as fully confirmed.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False
```
