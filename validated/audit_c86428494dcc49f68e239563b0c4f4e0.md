### Title
Unauthenticated disclosure of emergency-stop transaction data via `InternalGetEmergencyStopTx` when `client_verification=false` - ([File: core/src/rpc/interceptors.rs])

### Summary
The `Interceptors::Noop` variant, installed whenever `client_verification` is `false`, unconditionally forwards every gRPC request without invoking `is_internal`/`only_aggregator_and_self`. This means the aggregator's `Internal*`-prefixed methods—intended only for the aggregator's own certificate to call—are reachable by any unauthenticated client, including `InternalGetEmergencyStopTx`, which returns emergency-stop transaction commitments for arbitrary known txids.

### Finding Description
The intended binding is: caller identity (`leaf_cert`) == `our_cert` for any RPC whose `grpc-method` starts with `Internal`, as enforced by `is_internal` inside `only_aggregator_and_self` [1](#0-0) , applied at lines 62-69 [2](#0-1) .

However, `Interceptors::call` for the `Noop` variant simply returns `Ok(req)` without any check at all [3](#0-2) . The `Noop` variant is selected in `create_grpc_server` precisely when `config.client_verification` is `false` [4](#0-3) , and the aggregator server explicitly warns only when verification is *enabled*, implying `false` is a supported/expected deployment mode [5](#0-4) . In that mode there is no TLS client-certificate check and no method-prefix gating whatsoever — `InternalGetEmergencyStopTx` becomes reachable by any TCP client that can reach the aggregator's gRPC port, contradicting the documented design intent that `Internal*` methods are self-only.

### Impact Explanation
An attacker who can merely connect to the aggregator's open port (no TLS cert, no protocol role) can request and receive `encrypted_emergency_stop_txs` for known deposit txids before the emergency-stop mechanism is intended to be revealed. This is a premature disclosure of a protocol commitment (the emergency-stop tx material), matching the "High" impact category (premature disclosure of a protocol commitment) defined in scope. It does not by itself move BTC or forge a payout, so it does not rise to a "Critical" bridge-fund-loss category, but it undermines the secrecy guarantee the emergency-stop design relies on and is repeatable across every deposit whose txid the attacker can guess or observe on-chain.

### Likelihood Explanation
This requires the deployment to run the aggregator with `client_verification=false` — a supported configuration flag, not a hypothetical misconfiguration outside the codebase's own logic; the code path (`Noop` selection) exists specifically for this setting. No BTC cost, no privileged role, and no cryptographic material are needed by the attacker beyond knowing/guessing a deposit txid; the call is a single unauthenticated gRPC request. Given that `client_verification=false` is an explicit supported branch in `create_grpc_server`, and the `Noop` interceptor performs literally zero authentication, exploitability is straightforward whenever this configuration is active.

### Recommendation
Have `Interceptors::Noop::call` (or remove the `Noop` variant entirely for methods gated by `is_internal`) still enforce that `Internal*`-prefixed methods require verified self-certificate identity, or refuse to start the aggregator with `client_verification=false` if any `Internal*` RPC is exposed on that same listener. At minimum, gate `Internal*` methods behind the mTLS check regardless of the `client_verification` toggle, since these are meant to be callable only by the aggregator itself.

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware
    let Some(path) = req.metadata().get("grpc-method") else {
        // No grpc method? this should not happen
        tracing::error!("Missing grpc-method header in request");
        return false;
    };
    path.as_bytes().starts_with(b"Internal")
}

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}
