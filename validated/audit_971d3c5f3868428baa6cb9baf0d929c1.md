### Title
Uncontrolled recursion (CWE-674) in wallet outer-puzzle driver matching via nested puzzle layers in an untrusted offer/spend bundle - (File: `chia/wallet/outer_puzzles.py`, `chia/wallet/cat_wallet/cat_outer_puzzle.py`, `chia/wallet/trading/offer.py`)

### Summary
`Offer.from_spend_bundle()` calls `match_puzzle()` on every `CoinSpend.puzzle_reveal` contained in an untrusted spend bundle (e.g. an offer file received from a counterparty). Each outer-puzzle driver's `match()` implementation (CAT, singleton, ownership, metadata, credential-restricted) recognizes its own puzzle layer and then recurses into the inner puzzle by calling `self._match()` again with no depth bound. An attacker can construct a puzzle reveal with an arbitrarily deep, self-similar nesting of recognized puzzle layers (e.g. `CAT(CAT(CAT(...ACS...)))`), causing unbounded Python-side recursion before any CLVM cost limit ever applies, crashing the wallet process with an unhandled `RecursionError`.

### Finding Description
`match_puzzle()` in `chia/wallet/outer_puzzles.py` iterates the driver table and calls `driver.match(puzzle)`: [1](#0-0) 

Each concrete driver's `match()` recurses into its inner puzzle without any recursion-depth guard. For example, `CATOuterPuzzle.match()`: [2](#0-1) 

The same unbounded recursive pattern exists in `SingletonOuterPuzzle.match()`, `OwnershipOuterPuzzle.match()`, `MetadataOuterPuzzle.match()`, and `CROuterPuzzle.match()`: [3](#0-2) [4](#0-3) 

This matching chain is triggered directly from untrusted data in `Offer.from_spend_bundle()`, which parses every coin spend's `puzzle_reveal` in a spend bundle supplied by an offer counterparty (an offer file, or any spend bundle a wallet is asked to inspect/accept): [5](#0-4) 

Because each layer of the recursion only requires that the inner program is curried in the shape recognized by `match_cat_puzzle`/`match_singleton_puzzle`/etc. (readily reproducible by an attacker who fully controls the puzzle_reveal bytes before any CLVM execution or mempool cost accounting occurs), the recursion depth is entirely attacker-controlled and unbounded by any consensus cost limit. This mirrors the root cause of the liquidjs advisory: an attacker-controlled nesting structure drives unbounded recursive re-entry into the same rendering/matching logic with no termination/depth check, consuming stack (here) instead of heap. Notably, the codebase is aware of this exact class of bug and defends against it elsewhere — `chia/types/blockchain_format/tree_hash.py` explicitly implements `sha256_treehash` non-recursively "so we don't have to worry about blowing out the python stack" — but no equivalent protection exists in the outer-puzzle driver matching chain. [6](#0-5) 

### Impact Explanation
A wallet user who inspects/accepts a malicious offer, or any code path that calls `match_puzzle`/`Offer.from_spend_bundle` on an attacker-supplied spend bundle, can be crashed via Python's `RecursionError` (typically default limit ~1000 frames, easily reached with a few hundred nested layers of small curried puzzle bytes). This is a spend/offer-triggered processing halt reachable by an unprivileged offer counterparty or wallet-RPC caller, causing denial of service to the wallet process without requiring any signature or fee — the same DoS impact class as the reference advisory, though the underlying resource exhausted is stack (Python recursion) rather than heap.

### Likelihood Explanation
High likelihood: constructing deeply nested, self-similar curried puzzles (CAT-in-CAT, singleton-in-singleton, etc.) is straightforward with the existing `construct_cat_puzzle`/`puzzle_for_singleton` helpers, and no additional cost, fee, or on-chain validation gates the puzzle_reveal before `match_puzzle` recurses over it. The attack requires only sending an offer file or spend bundle to a target wallet.

### Recommendation
Add an explicit recursion/depth limit (or convert the `match`/`get_inner_puzzle`/`get_inner_solution`/`construct`/`solve` driver chains to an iterative loop) in `chia/wallet/outer_puzzles.py` and each driver implementation (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`), similar to the pattern already used in `chia/types/blockchain_format/tree_hash.py`. Reject or fail gracefully (raising a catchable, well-typed error rather than an unhandled `RecursionError`) once a sane maximum nesting depth is exceeded, before processing any attacker-supplied `puzzle_reveal` from an offer or spend bundle.

### Proof of Concept
1. Build a deeply self-nested CAT puzzle in Python using the wallet's own helper:
```python
from chia.wallet.cat_wallet.cat_utils import CAT_MOD, construct_cat_puzzle
from chia.types.blockchain_format.program import Program

tail = bytes32.zeros
puz = Program.to(1)  # ACS
for _ in range(5000):
    puz = construct_cat_puzzle(CAT_MOD, tail, puz)
```
2. Wrap it in a `CoinSpend`/`WalletSpendBundle` as the `puzzle_reveal` for a dummy coin, and construct an `Offer` (or simply call `match_puzzle` directly) on it:
```python
from chia.wallet.outer_puzzles import match_puzzle
from chia.wallet.puzzles.puzzle_drivers import UnknownPuzzle

match_puzzle(UnknownPuzzle(known_program=puz))  # recurses ~5000 levels
```
3. Observe an unhandled `RecursionError` raised from the recursive `self._match()` chain in `CATOuterPuzzle.match`, crashing whatever process invoked it (e.g. a wallet processing an incoming offer via `Offer.from_spend_bundle`).
