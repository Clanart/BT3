The Discourse bug is unauthorized disclosure of a private stream; in Serai the matching shape is the PedPoP blame channel, which is designed to reveal one encrypted share's ECDH key. The code explicitly documents the attack it's defending against: reusing another party's per-message key `X` so the victim publishes `bX`, which then also decrypts the honest party's private message. ### Title
Invalid-scalar share triggers blame reveal of another party's ECDH key before the key's proof-of-possession is verified - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` decrypts each incoming `EncryptedMessage` and returns a publishable `EncryptionKeyProof` (the ECDH shared point `bK` plus a DLEq) when the decrypted bytes fail `C::F::from_repr`. The Schnorr proof-of-possession for `msg.key` is only *queued* into a `BatchVerifier` in `Encryption::decrypt` and is only checked by `batch.verify_with_vartime_blame()` — which is never reached on this error path. A malicious participant Eve can therefore copy the per-message key `X` from Alice's private message to Bob into her own message to Bob, attach garbage ciphertext and a forged PoP, and force Bob to emit a blame proof that reveals `bX`. Anyone who sees that proof can decrypt Alice's real share to Bob.

### Finding Description
`Encryption::decrypt` (crypto/dkg/pedpop/src/encryption.rs:469-501) always computes `key = ecdh(self.enc_key, msg.key)` and returns `EncryptionKeyProof { key, dleq }`; the PoP check is deferred via `msg.pop.batch_verify(...)`. In `calculate_share` (crypto/dkg/pedpop/src/lib.rs:476-492), for each share:

1. `decrypt` is called, queuing the PoP under `BatchId::Decryption(l)` and returning `(share_bytes, blame)`.
2. `C::F::from_repr(share_bytes.0)` is evaluated; on failure it returns `PedPoPError::InvalidShare { participant: l, blame: Some(blame) }` via `?` — exiting `calculate_share` before `batch.verify_with_vartime_blame()` at line 493 runs.

So when the decrypted share is a non-canonical scalar, the ECDH-revealing blame proof is produced without ever verifying that the sender actually knows the discrete log of `msg.key`. This is precisely the attack the PoP was added to prevent, documented in the comment on `EncryptedMessage` (encryption.rs:83-90): Eve observes Alice encrypt to Bob with key `X`, sends Bob a message claiming key `X`, and Bob's blame of Eve reveals `bX`, which decrypts Alice's message. The PoP binds `sender` in `pop_challenge` (encryption.rs:302-324), so Eve cannot reuse Alice's PoP — but on the `from_repr` path that PoP is never checked.

The reveal is real even though `BlameMachine::blame`/`decrypt_with_proof` later verifies the PoP and correctly attributes fault to Eve (`DecryptionError::InvalidSignature`, encryption.rs:374-379): by then Bob has already published `EncryptionKeyProof { key: bX, dleq }`, whose DLEq verifies against Bob's registered `enc_key` and `X` (encryption.rs:381-392). Applying `cipher(context, bX)` to Alice's ciphertext recovers her share `f_Alice(Bob)` in cleartext to every observer of the blame (e.g., via `CoordinatorMessage::VerifyBlame` handling in processor/src/key_gen.rs:504).

Eve needs the decrypted garbage to be non-canonical, which she cannot fully control since she doesn't know the keystream — but a random 32-byte ciphertext decrypts to a non-canonical scalar with high probability (≈15/16 for ristretto255), and she can retry across attempts.

### Impact Explanation
An unprivileged DKG participant can force the public disclosure of the ECDH decryption key for another participant's private secret share. The leaked value `f_Alice(Bob)` is a real Pedersen/Feldman share contribution: it reduces the secrecy of Bob's finalized share to the remaining contributions, and the code itself classifies this side effect as "massive" and capable of breaking protocols. At the library level, only Bob's `calculate_share` errors; other participants who received well-formed messages from Eve still complete, so the leaked material can correspond to a session that partially or fully finalizes depending on integrator abort handling. Severity: Medium — secret-share material leaks to unauthorized parties via reachable public inputs (an `EncryptedMessage` crafted by a participant), but recovery of a full key share requires additional conditions.

### Likelihood Explanation
The attack requires only that Eve be a DKG participant sending one crafted `EncryptedMessage` to one victim, that the victim's blame proof become visible (it is designed to be published), and that the decrypted bytes be non-canonical (~94% per attempt, repeatable). No collusion, no malicious coordinator, and no channel manipulation is needed — the authenticated-channel assumption does not help because everything Eve uses is in her own message slot. The main mitigating factor is that aborted-session shares lose value if the protocol is globally restarted with fresh polynomials.

### Recommendation
In `calculate_share`, do not release `EncryptionKeyProof` until the PoP has been verified for that message. Options:

- Verify `msg.pop` inline (non-batch) before computing the ECDH/decryption, or
- Restructure so the `from_repr` check is deferred until after `batch.verify_with_vartime_blame()` confirms the `BatchId::Decryption(l)` statements, returning `blame: None` (PoP-invalid, self-explanatory) when the PoP fails.

This restores the documented invariant that `bK` is only ever revealed for messages whose per-message key the sender proved possession of.

### Proof of Concept
1. Alice and Eve are participants in a PedPoP DKG with Bob (`SecretShareMachine`/`generate_secret_shares`).
2. Alice sends Bob `EncryptedMessage { key: X, pop: sig_A, msg: enc(f_A(Bob)) }` — honestly.
3. Eve reads Alice's message (publicly transmitted), extracts `X`, and sends Bob `EncryptedMessage { key: X, pop: forged, msg: <random 32 bytes> }` as her own share. `pop_challenge` binds `sender = Eve`, so Eve cannot copy Alice's `sig_A`; any bytes suffice since the PoP will never be verified.
4. Bob runs `KeyMachine::calculate_share`. For Eve's entry, `Encryption::decrypt` queues the PoP, computes `key = bX`, decrypts to (with ~15/16 probability) a non-canonical scalar, and returns `blame = EncryptionKeyProof { key: bX, dleq(enc_pub_Bob, X → bX) }`.
5. `C::F::from_repr` fails; `calculate_share` returns `InvalidShare { participant: Eve, blame: Some(proof) }` at lib.rs:480-482 — before line 493 verifies the queued PoP.
6. Bob publishes `blame` per protocol (e.g., `VerifyBlame`). Any observer computes `cipher(context, bX)` and XORs it against Alice's `msg` ciphertext, recovering `f_Alice(Bob)` — a private share Eve was never entitled to read. Blame is correctly attributed to Eve afterward, but the disclosure is irreversible.
