### Title
Deserialized `ReceivedOutput` bypasses scanner provenance checks and permits signing against fabricated Bitcoin UTXOs - ([File: `networks/bitcoin/src/wallet/mod.rs`])

### Summary
`ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without establishing that the output exists on-chain or was discovered through a registered scanner script [1](#0-0) . In contrast, `Scanner::scan_transaction` constructs a `ReceivedOutput` only for an output actually present in a supplied transaction and only when its `script_pubkey` maps to a registered offset [2](#0-1) . The spending path later validates only that the claimed previous output’s script corresponds to the selected key and offset, not that the referenced outpoint or amount exists [3](#0-2) .

### Finding Description
The scanner-enforced invariant is that a spendable `ReceivedOutput` represents an actual transaction output whose script was registered as controlled by the base key plus a known offset [4](#0-3) . Deserialization creates the same type directly from untrusted bytes, but omits the transaction-membership and scanner-registration provenance established by `Scanner::scan_transaction` [1](#0-0) .

`SignableTransaction::new` trusts the embedded `TxOut` amount as input value and embeds the attacker-selected `OutPoint` in the transaction [5](#0-4) . `SignableTransaction::multisig` then checks only `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey`, which proves script/key consistency but not UTXO existence or value correctness [6](#0-5) . During signing, every supplied previous output, including its fabricated value and script, is committed through `Prevouts::All` and the Taproot sighash [7](#0-6) .

### Impact Explanation
An attacker able to supply serialized `ReceivedOutput` bytes can cause funds to be reported as received or selected for spending when no such spendable UTXO exists [1](#0-0) . If the bytes use a real-looking registered script and a fabricated `OutPoint`/value, the signing machines can be driven to produce threshold signature shares for a transaction that the Bitcoin network will reject or that commits to an incorrect previous-output amount [7](#0-6) . This creates a signing-path denial of service and can cause unavailable or misaccounted funds; it does not directly reveal key material [5](#0-4) .

### Likelihood Explanation
Exploitation requires an attacker to reach a caller that consumes serialized `ReceivedOutput` values rather than outputs produced directly by `Scanner::scan_transaction` or `Scanner::scan_block` [8](#0-7) . No private key is needed to construct the bytes because the offset is canonical scalar data and the `TxOut` and `OutPoint` are ordinary consensus-encoded attacker-controlled fields [9](#0-8) . The issue is conditional on an integration accepting untrusted `ReceivedOutput` encodings, but the exposed parser provides no marker, proof, or commitment allowing callers to distinguish scanner-derived outputs from fabricated ones [10](#0-9) .

### Recommendation
Do not deserialize `ReceivedOutput` into an authoritative spendable representation without validating it against the originating transaction, its outpoint, and the scanner’s offset map [1](#0-0) . Prefer serializing a scanner proof or enough transaction context to re-derive the output, or require `SignableTransaction`/its caller to verify that every `prevout` exists in the confirmed UTXO view before `multisig` signs it [11](#0-10) . At minimum, make `ReceivedOutput::read` an explicitly untrusted transport representation and add a separate checked constructor that recomputes `p2tr_script_buf(key + G * offset)` and confirms the referenced output before signing [6](#0-5) .

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
