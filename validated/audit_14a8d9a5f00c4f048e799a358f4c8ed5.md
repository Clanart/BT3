### Title
Manipulable per-block median fee oracle lets an unprivileged sender inflate the multisig's fee rate and burn Serai funds as miner fees - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::make_signable_transaction` derives the fee rate for every Bitcoin transaction the Serai multisig signs from a single function, `median_fee`, which computes the median feerate of transactions inside exactly one block (`block.txdata[1..]`). Any unprivileged party who gets transactions confirmed in that block can push the median arbitrarily high, causing the protocol to sign transactions paying far more fee than necessary. The overpaid fee is subtracted from the multisig's inputs (reducing change or consuming extra inputs) and is irrecoverable.

### Finding Description
In `make_signable_transaction`, the fee is obtained as:

- `let block_for_fee = self.get_block(block_number).await?;`
- `let fee = self.median_fee(&block_for_fee).await?;`

then passed directly to `BSignableTransaction::new(..., fee.0)` as `fee_per_vbyte` [1](#0-0) .

`median_fee` iterates over `block.txdata[1 ..]`, sums each transaction's input value minus output value, divides by that transaction's `vsize`, sorts, and returns the middle element with only `fee.max(1)` as a floor — there is no cap and no smoothing across blocks [2](#0-1) . The code even carries a `TODO2` acknowledging the single-block design [3](#0-2) .

Because the median is taken over a single block, an attacker controls the result whenever attacker transactions occupy the median position. For a block with an odd number of non-coinbase transactions, a single attacker transaction with an extreme feerate *is* the median. The attacker pays that fee only on their own transaction; the induced `fee_per_vbyte` is then applied to the multisig's much larger transaction, so `needed_fee = fee_per_vbyte * vbytes` in `SignableTransaction::new` burns multisig funds proportional to the protocol transaction's size, not the attacker's [4](#0-3) . Since change is only created when `input_sat - payment_sat - fee_with_change >= DUST`, an inflated fee also shrinks or eliminates the change output, permanently donating the excess to miners [5](#0-4) .

### Impact Explanation
The threshold multisig signs a transaction paying an attacker-influenced fee. The excess `fee_per_vbyte * vbytes` comes directly out of Serai-controlled inputs (lower change / consumed UTXOs) and is unrecoverable once mined. This mirrors the reported incident class — a manipulated external data source (here, on-chain feerates treated as an oracle) causing the protocol to execute value-losing transactions — with direct, measurable fund loss rather than a price misquote. Severity is bounded by the multisig's spendable input value per transaction, hence Medium rather than High.

### Likelihood Explanation
Reachability is fully unprivileged: the attacker only needs to broadcast ordinary Bitcoin transactions that land in the same block Serai samples, satisfying the "Bitcoin transactions they send" reachability rule. The cost is the fee paid on their own transaction(s); if the attacker (or a cooperating miner) mines the block, even that cost is recaptured, and a rational miner is additionally rewarded with the inflated protocol fee. Blocks with few transactions — common on low-activity periods — make the median trivially capturable.

### Recommendation
- Compute the fee rate over a rolling window of several confirmed blocks (per the existing `TODO2`) and/or use the node's `estimatesmartfee` with a confirmation target.
- Impose a hard upper bound on `fee_per_vbyte` (e.g., a multiple of the relay minimum or a configurable ceiling) before calling `BSignableTransaction::new`.
- Consider sampling feerates from a block deep enough that it cannot be influenced by transactions raced into the same block the spend is built from.

### Proof of Concept
Conceptual, using the real call chain:

1. Serai calls `make_signable_transaction(block_number, inputs, payments, change, false)` to spend a multisig UTXO.
2. `median_fee` reads `get_block(block_number)` and computes feerates over `block.txdata[1..]` [6](#0-5) .
3. The attacker broadcasts one transaction into that block with a feerate of e.g. 100,000 sat/vbyte (a large `in_value - out` over a small vsize). If it is the median element, `median_fee` returns `Fee(100000)`.
4. `BSignableTransaction::new(..., fee.0)` sets `needed_fee = 100000 * vbytes`; for a ~200 vbyte transaction this commits ~20,000,000 sats (~0.2 BTC) of multisig funds to fees, taken from change via `input_sat - payment_sat - fee_with_change` [7](#0-6) .
5. The FROST `TransactionMachine` signs and `complete` produces the transaction [8](#0-7) ; once broadcast, the excess fee is claimed by the block's miner and cannot be recovered.

  async fn median_fee(&self, block: &Block) -> Result<Fee, NetworkError> {
    let mut fees = vec![];
    if block.txdata.len() > 1 {
      for tx in &block.txdata[1 ..] {
        let mut in_value = 0;
        for input in &tx.input {
          let mut input_tx = input.previous_output.txid.to_raw_hash().to_byte_array();
          input_tx.reverse();
          in_value += self
            .rpc
            .get_transaction(&input_tx)
            .await
            .map_err(|_| NetworkError::ConnectionError)?
            .output[usize::try_from(input.previous_output.vout).unwrap()]
          .value
          .to_sat();
        }
        let out = tx.output.iter().map(|output| output.value.to_sat()).sum::<u64>();
        fees.push((in_value - out) / u64::try_from(tx.vsize()).unwrap());
      }
    }
    fees.sort();
    let fee = fees.get(fees.len() / 2).copied().unwrap_or(0);

    // The DUST constant documentation notes a relay rule practically enforcing a
    // 1000 sat/kilo-vbyte minimum fee.
    Ok(Fee(fee.max(1)))
