### Title
`pretooluse.py:main()` fails open (allows the tool call) on ANY unhandled exception during rule evaluation, silently bypassing block-type hookify rules - ([File: plugins/hookify/hooks/pretooluse.py])

### Finding Description
`main()` wraps the entire rule-loading/evaluation pipeline in a single `try/except Exception` that, on any error, only prints a `systemMessage` and falls through to `finally: sys.exit(0)`: [1](#0-0) 

Exit code `0` is Claude Code's "allow" signal for a `PreToolUse` hook, so any exception raised anywhere inside `load_rules()`/`RuleEngine.evaluate_rules()` causes the tool call (Bash/Write/Edit) to be permitted, even if a `block`-type rule would otherwise have matched and denied it.

There is a concrete unguarded exception path: `_extract_field` reads an entire `transcript` file into memory with `f.read()` and only catches `FileNotFoundError`, `PermissionError`, `(IOError, OSError)`, and `UnicodeDecodeError` — not `MemoryError`: [2](#0-1) 

A `MemoryError` (or any other unforeseen exception, e.g. `AttributeError`/`TypeError` from a malformed `Rule`/`Condition`) thrown anywhere inside `_rule_matches`/`_check_condition`/`evaluate_rules` propagates all the way up and is swallowed by `main()`'s blanket `except Exception`, which always results in "allow" (exit 0) regardless of whether a `block` rule was about to fire: [3](#0-2) 

Separately, `_regex_match` only catches `re.error` (bad pattern syntax), not runaway execution time: [4](#0-3) 

A catastrophic-backtracking regex (e.g. `(a+)+$`) matched against attacker-influenced input (a long Bash `command`, file `content`, or `transcript` text) does not raise an exception — it hangs the process. This is not caught by `except Exception`, so the fail-open behavior for that specific case would depend on whatever external timeout mechanism Claude Code's hook runner applies when a hook process doesn't return in time; that mechanism is not implemented in this repo/file and could not be verified here.

### Impact Explanation
Any block-type hookify rule (the mechanism a user/project relies on to hard-deny dangerous `Bash`/`Write`/`Edit` operations) is silently disabled for the current tool invocation whenever rule evaluation throws for any reason. Concretely, an oversized `transcript`/`content`/`command` value that triggers a `MemoryError` (or any other unhandled exception) causes hookify to emit an informational `systemMessage` but still allow the dangerous operation, defeating the entire purpose of `action: block` rules. This is a fail-open trust-boundary bypass of a security enforcement hook.

### Likelihood Explanation
The design is explicit and intentional per the code comment "ALWAYS exit 0 — never block operations due to hook errors," meaning every unhandled exception in the evaluation pipeline reaches this fallback deterministically — no timing race or partial mitigation exists once an exception occurs. Triggering it only requires content that overwhelms memory during `transcript`/field extraction, or any bug/edge case in `_check_condition`/`_extract_field`/`Rule.from_dict`, all of which are reachable from ordinary hook input (`tool_input`, `transcript_path`) without any elevated privilege.

### Recommendation
Do not treat all exceptions identically. For `block`-type rule evaluation failures, fail closed (deny with an explanatory `systemMessage`) rather than fail open; reserve fail-open behavior for hookify plumbing/import errors only. Additionally, bound the size of data read for `transcript`/`content` fields before regex evaluation, and apply a regex execution timeout (or use a backtracking-safe regex engine) in `_regex_match` to prevent hangs from reaching whatever external timeout/kill behavior Claude Code applies to hooks.

### Proof of Concept
Unit test (`rule_engine_test.py`):
1. Construct a `block` rule with `field="command", operator="regex_match", pattern="rm -rf"`.
2. Monkeypatch `RuleEngine._extract_field` (or feed a `transcript_path` pointing to a multi-GB file) so that evaluating the condition raises `MemoryError`.
3. Call `pretooluse.main()` with stdin JSON containing `tool_name: "Bash"`, `tool_input: {"command": "rm -rf /"}`.
4. Capture stdout and process exit code.
5. Assert failure: current behavior prints `{"systemMessage": "Hookify error: ..."}` and exits `0` (allow) even though the block rule matched — demonstrating the block rule was bypassed. Expected secure behavior: exit code / hook output should represent `deny`/non-zero for block-rule evaluation failures, not silent allow.

    def evaluate_rules(self, rules: List[Rule], input_data: Dict[str, Any]) -> Dict[str, Any]:
        """Evaluate all rules and return combined results.

        Checks all rules and accumulates matches. Blocking rules take priority
        over warning rules. All matching rule messages are combined.

        Args:
            rules: List of Rule objects to evaluate
            input_data: Hook input JSON (tool_name, tool_input, etc.)

        Returns:
            Response dict with systemMessage, hookSpecificOutput, etc.
            Empty dict {} if no rules match.
        """
        hook_event = input_data.get('hook_event_name', '')
        blocking_rules = []
        warning_rules = []

        for rule in rules:
            if self._rule_matches(rule, input_data):
                if rule.action == 'block':
                    blocking_rules.append(rule)
                else:
                    warning_rules.append(rule)

        # If any blocking rules matched, block the operation
        if blocking_rules:
            messages = [f"**[{r.name}]**\n{r.message}" for r in blocking_rules]
            combined_message = "\n\n".join(messages)

            # Use appropriate blocking format based on event type
            if hook_event == 'Stop':
                return {
                    "decision": "block",
                    "reason": combined_message,
                    "systemMessage": combined_message
                }
            elif hook_event in ['PreToolUse', 'PostToolUse']:
                return {
                    "hookSpecificOutput": {
                        "hookEventName": hook_event,
                        "permissionDecision": "deny"
                    },
                    "systemMessage": combined_message
                }
            else:
                # For other events, just show message
                return {
                    "systemMessage": combined_message
                }

        # If only warnings, show them but allow operation
        if warning_rules:
            messages = [f"**[{r.name}]**\n{r.message}" for r in warning_rules]
            return {
                "systemMessage": "\n\n".join(messages)
            }

        # No matches - allow operation
        return {}

    def _regex_match(self, pattern: str, text: str) -> bool:
        """Check if pattern matches text using regex.

        Args:
            pattern: Regex pattern
            text: Text to match against

        Returns:
            True if pattern matches
        """
        try:
            # Use cached compiled regex (LRU cache with max 128 patterns)
            regex = compile_regex(pattern)
            return bool(regex.search(text))

        except re.error as e:
            print(f"Invalid regex pattern '{pattern}': {e}", file=sys.stderr)
            return False
