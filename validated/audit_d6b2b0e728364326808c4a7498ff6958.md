### Title
Arbitrary local file overwrite via unvalidated caller-supplied `foldername` and non-`O_EXCL` file open in DataLayer `add_missing_files` RPC - (File: chia/data_layer/data_layer_rpc_api.py / chia/data_layer/download_data.py)

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts a client-supplied `foldername` and `overwrite` flag with no path validation, and passes them straight into `write_files_for_root()`, which opens the resulting file path with a plain `open(path, "wb")` (or `"xb"`) call. Neither the RPC layer nor `write_files_for_root()` verifies that the resolved target path is not a pre-existing symlink before writing, so a local RPC caller can direct the DataLayer service to follow a symlink and overwrite an arbitrary file the service process can write to — the same root cause class as CVE-2018-13054 (a privileged process writing user-influenced content to a path without checking whether it is a symlink).

### Finding Description
`DataLayerRpcApi.add_missing_files` takes `foldername` directly from the RPC request dict with no validation and forwards it to the service layer: [1](#0-0) 

`DataLayer.add_missing_files` then calls `write_files_for_root()` using that folder for every generation of the requested store, with `overwrite` also taken verbatim from the request: [2](#0-1) 

`write_files_for_root()` computes the target file paths deterministically from `store_id`, `node_hash`, and `generation`, then opens them directly: [3](#0-2) 

When `overwrite=True`, the mode is `"wb"`, which truncates and writes through any existing file at that path — including a symlink. Python's `open()` does not use `O_NOFOLLOW`/`O_EXCL` in this branch, so if a symlink already exists at the computed path (e.g., `{store_id}-{node_hash}-full-{generation}-v1.0.dat` inside the attacker-chosen `foldername`), the write follows the link and overwrites whatever file it points to, with content coming from `data_store.write_tree_to_file()` (the caller's own DataLayer tree content, which the caller fully controls since they control `store_id`'s data).

This mirrors the CVE-2018-13054 pattern: a component with write privileges different from the untrusted caller's target location writes to a filename that is influenced/enumerable by the requester without checking for symlinks, letting the requester redirect the write to an arbitrary filesystem location the DataLayer process can access.

### Impact Explanation
Because `foldername` is entirely attacker-supplied and the resulting filename is predictable from `store_id`/`node_hash`/`generation` (values the requester controls or can enumerate), a local RPC caller can pre-place a symlink at the exact expected path (in any directory the DataLayer process has read/write access to) and then invoke `add_missing_files` with `overwrite=True` to have the service overwrite an arbitrary target file with attacker-controlled tree data. This is a genuine local file-integrity violation (arbitrary file overwrite) reachable purely from the DataLayer RPC surface, without needing any on-chain spend or wallet secret — a medium/high severity local-privilege/data-integrity issue consistent with the CVE's classification (CVSS 8.1, `I:H/A:H`).

### Likelihood Explanation
Requires: (1) local access to the DataLayer RPC (a "local RPC caller" is explicitly a valid actor for this analysis), and (2) the ability to place a symlink at the predictable target path before calling the endpoint — a straightforward local TOCTOU setup. No on-chain state or additional privileges are required beyond already being able to reach the DataLayer RPC and having filesystem write access to some accessible location plus knowledge of `store_id`/`node_hash`/`generation`.

### Recommendation
- Validate `foldername` against DataLayer's own `server_files_location` root (or an explicit allow-list) rather than accepting an arbitrary caller-supplied path.
- In `write_files_for_root()`, use `os.open()` with `O_NOFOLLOW | O_EXCL` (for create) or explicitly `os.path.islink()`-check/`os.lstat()` the target before opening, and reject writes through symlinks.
- Avoid `overwrite=True` following existing files at all; write to a temp file within the target directory and atomically `os.replace()` only after confirming the destination is not a symlink.

### Proof of Concept
1. Local attacker with access to the DataLayer RPC creates/knows a store with `store_id` and inserts data producing a known `node_hash`/`generation`.
2. Attacker creates a symlink at `<chosen_dir>/{store_id}-{node_hash}-full-{generation}-v1.0.dat` pointing to a sensitive file the DataLayer service process can write (e.g., another config or data file within the service's write scope).
3. Attacker calls the `add_missing_files` RPC with `foldername=<chosen_dir>`, `overwrite=true`, `ids=[store_id]`.
4. `write_files_for_root()` opens the symlink path with `"wb"` and writes the store's tree contents, overwriting the symlink target file.

Note: I could not fully verify runtime authentication/authorization requirements for reaching the DataLayer RPC in this snapshot (cert-based local admin API per repository documentation notes), which affects exact exploitability preconditions but not the underlying root-cause code path identified above.         """

        overwrite = request.get("overwrite", False)

        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)
