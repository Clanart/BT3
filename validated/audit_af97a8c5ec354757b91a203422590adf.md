### Title
Missing slippage/price-fairness enforcement in `_bullMGP()` allows AMM price manipulation to mint disproportionate vlMGP lock - ([File: wombat/ArbWomUp2.sol])

### Summary
`_bullMGP()` swaps a fixed `_busdAmount` (derived from the caller's own WOM-deposit reward tier) for MGP through `ROUTER.swapExactTokensForTokens`, using a caller-supplied `_minRec` with no independent fairness check, then applies `bullBonusRatio` on top of whatever `amounts[1]` the swap returns and locks that amount into `vlMGP` for the caller. Because the output amount is entirely a function of the instantaneous ROUTER pool reserves, and the contract enforces no TWAP/oracle-independent floor on the exchange rate, an attacker can transiently manipulate the busd/mgp pool (e.g., via a flash loan) immediately before calling `incentiveDeposit(_bullMode=true)` to receive an inflated `amounts[1]`, which is then further amplified by `bullBonusRatio` before being locked as vlMGP.

### Finding Description
`incentiveDeposit` computes `rewardToSend` from the WOM-deposit tier table via `getRewardAmount` [1](#0-0) , then calls `_bullMGP(rewardToSend, _minMGPRec, msg.sender)`. Inside `_bullMGP`, the busd amount is swapped for MGP through the PancakeRouter-style `ROUTER`, and the resulting `amounts[1]` — the actual output of that specific swap under the pool's current reserves — directly determines `mgpAmountToLcok`, multiplied by `(DENOMINATOR + bullBonusRatio) / DENOMINATOR`: [2](#0-1) 

There is no check comparing `amounts[1]` against any independent reference price (e.g., TWAP, oracle, or a governance-set fair rate) — the only protection is `_minMGPRec`, which is caller-supplied and only prevents the swap from returning *less* than the caller wants; it does nothing to prevent the caller from arranging for the pool to return *more* than a fair-market rate. An attacker can, in the same transaction (or immediately preceding block via flash loan), shift the pool reserves so that MGP is temporarily cheap relative to BUSD, call `incentiveDeposit` to receive an inflated `amounts[1]` for the same fixed busd spend, then reverse the manipulation to repay the flash loan. `nonReentrant` and `whenNotPaused` do not protect against this because the manipulation happens across router state, not via reentrancy into this contract, and the "amount" the caller spends (`rewardToSend`) is unaffected by the swap execution price — only the MGP they receive is.

### Impact Explanation
The resulting `mgpAmountToLcok` is locked via `vlMGP.lockFor(mgpAmountToLcok, _account)`, which grants the attacker locked-MGP governance/emission share in the vlMGP/MasterMagpie system disproportionate to the real BUSD value they contributed. This corresponds to theft/dilution of other stakers' pro-rata MGP emission share (unclaimed yield) and/or drains real MGP liquidity from the ROUTER pool at an unfair rate — a concrete, quantifiable loss of backing between BUSD spent and MGP locked. This matches the "theft of unclaimed yield" / "protocol insolvency via disproportionate share minting" impact class.

### Likelihood Explanation
Exploitability depends entirely on the liquidity depth of the specific busd/mgp `ROUTER` pool configured via `setup()`. If that pool is thin (plausible for a bespoke/limited liquidity pair rather than a deep, widely-arbitraged pool), a modest flash loan is sufficient to shift the exchange rate meaningfully within a single transaction, and the attack is fully repeatable per call to `incentiveDeposit` (bounded only by the attacker's available WOM deposit for tier-based `rewardToSend` and by pool depth/attacker capital for the manipulation leg). No privileged access is required — only a flash loan, an EOA/contract call, and a WOM balance to deposit.

### Recommendation
Do not rely solely on the instantaneous `ROUTER.swapExactTokensForTokens` output to size the vlMGP lock. Introduce an independent fair-price reference (e.g., a TWAP oracle, or a protocol-set exchange rate) and bound `mgpAmountToLcok` by that reference regardless of the actual swap output, or cap `bullBonusRatio` gains to a fixed reference rate rather than the manipulable spot swap result. Alternatively, route the busd→mgp conversion through a venue not manipulable within a single transaction (e.g., a controlled internal price feed) rather than a public AMM pool, or require the swap size to be small enough relative to pool depth that price impact is bounded.

### Proof of Concept
Foundry fork test plan:
1. Deploy/fork with `ArbWomUp2` configured (`setup`) against a real or mock low-liquidity busd/mgp `ROUTER` pool, `bullBonusRatio` set to a nonzero value.
2. Attacker obtains WOM sufficient to be entitled to a known `rewardToSend` (BUSD) via `getRewardAmount`.
3. Baseline: call `incentiveDeposit(amt, _minMGPRec=quoted, true)` without manipulation; record `mgpAmountToLcok_baseline` from `VLMGPRewarded` event.
4. Attack: flash-loan funds, dump MGP into the busd/mgp pool to depress MGP price, call `incentiveDeposit(amt, _minMGPRec=0, true)` in the same transaction, record `mgpAmountToLcok_attack`, then reverse the swap and repay the flash loan.
5. Assert `mgpAmountToLcok_attack` significantly exceeds `mgpAmountToLcok_baseline` for the same `_busdAmount`, and assert the attacker's post-attack vlMGP lock / MasterMagpie emission share is disproportionate relative to other depositors' BUSD-to-lock ratio, confirming dilution of other vlMGP holders' pro-rata MGP emissions.

        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
