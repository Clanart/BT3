### Title
Unauthenticated disclosure of encrypted emergency-stop transactions via `InternalGetEmergencyStopTx` when `client_verification=false` - ([File: core/src/servers.rs] / [File: core/src/rpc/interceptors.rs])

### Summary
The `Internal*` method gate (`is_internal` in `core/src/rpc/interceptors.rs`) is only enforced inside the `OnlyAggregatorAndSelf` interceptor branch, which `create_grpc_server` only installs when `config.client_verification == true`; when it is `false`, `Interceptors::Noop` is installed instead, which returns `Ok(req)` unconditionally with no certificate check at all. This means `internal_get_emergency_stop_tx` (and every other `Internal*`-prefixed RPC) is reachable by any unauthenticated caller on the aggregator's public gRPC port whenever `client_verification=false`, defeating the "self-only" binding the naming convention is meant to guarantee.

### Finding Description
The claimed binding is: `caller_certificate == aggregator/self_certificate` for any RPC method whose gRPC path starts with `"Internal"` (enforced by `is_internal` at [1](#0-0)  and `only_aggregator_and_self` at [2](#0-1) ).

That binding is only wired up conditionally in `create_grpc_server`: `InterceptedService::new` is given `OnlyAggregatorAndSelf{...}` only `if config.client_verification`, and `Noop` otherwise [3](#0-2) . The `Noop` variant of the interceptor performs no check whatsoever and passes every request through [4](#0-3) .

Consequently, when the aggregator (or any server) is deployed with `client_verification=false`, the `is_internal` gate is never evaluated at all — not weakened, but entirely absent — so any unauthenticated network client can invoke `internal_get_emergency_stop_tx` (and any other `Internal*` RPC) directly, e.g. via `ClementineAggregatorServer::call -> AggregatorServer::internal_get_emergency_stop_tx`, and retrieve `encrypted_emergency_stop_txs` for arbitrary kickoff/round txids without holding any certificate, key share, or bridge role.

### Impact Explanation
The disclosed material is protocol-internal emergency-stop transaction data intended to remain confidential until deliberately revealed (its very naming as `Internal*` signals it is not meant to be a public API for arbitrary clients). Premature disclosure of this commitment to an unprivileged party matches the rules' High-severity category "premature disclosure of a protocol commitment." The exposure is repeatable across every deposit/kickoff for which emergency-stop tx material exists, since the request simply takes arbitrary `txids`, and it affects every deployment where `client_verification=false` (the mode explicitly supported and toggled off by default in this code path).

### Likelihood Explanation
The only precondition is a deployment with `client_verification=false` on the aggregator's gRPC listener, which is a fully supported and directly toggled configuration path in this codebase (not a hypothetical misconfiguration exploit — it is the exact `Noop` branch wired in `create_grpc_server`). No BTC cost, no key material, and no privileged role is required; the attacker only needs network access to the public gRPC port and knowledge of a `txid` associated with a deposit (obtainable from the public Bitcoin chain). This is trivially repeatable for any/all deposits.

### Recommendation
Enforce the `Internal*` self-only check unconditionally, independent of `client_verification`/TLS mode — e.g., have `Interceptors::Noop` still invoke `is_internal` and reject calls to `Internal*` methods (or refuse to serve `Internal*` methods at all when TLS/mTLS is disabled), rather than allowing the gate to be silently skipped whenever `client_verification=false`.

### Proof of Concept
```rust
// core/src/rpc/tests_emergency_stop_leak.rs (new test, illustrative)
#[tokio::test]
async fn internal_get_emergency_stop_tx_reachable_without_cert() {
    // 1. Build a BridgeConfig with client_verification = false.
    let mut config = create_test_config().await;
    config.client_verification = false;

    // 2. Start aggregator gRPC server (Noop interceptor path).
    let (addr, _shutdown) = create_aggregator_grpc_server(config.clone()).await.unwrap();

    // 3. Connect WITHOUT presenting any client certificate (plain/no-mTLS channel).
    let mut client = ClementineAggregatorClient::connect(format!("http://{}", addr))
        .await
        .unwrap();

    // 4. Call InternalGetEmergencyStopTx with txids belonging to a deposit the caller never created.
    let resp = client
        .internal_get_emergency_stop_tx(GetEmergencyStopTxRequest {
            txids: vec![known_kickoff_txid.into()],
        })
        .await
        .unwrap();

    // Assertion: unauthenticated caller (no aggregator/self cert, binding
    // `caller_cert == self_cert` never checked) still receives encrypted
    // emergency-stop tx material.
    assert!(!resp.into_inner().encrypted_emergency_stop_txs.is_empty());
}
```
This demonstrates that with `client_verification=false` (the `Noop` interceptor path), the `is_internal`/self-cert binding asserted by the question is never evaluated, and the RPC's protected data is returned to an unauthenticated caller.
