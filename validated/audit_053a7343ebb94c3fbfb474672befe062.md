### Title
Empty aggregate signature verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an aggregate containing zero nonce points and a scalar `s`. `SchnorrAggregate::verify` only checks that the number of serialized nonces equals the number of supplied public keys, then builds one multi-scalar multiplication containing `-sG` when no signers are present. [1](#0-0) [2](#0-1) 

### Finding Description
An attacker can encode an aggregate signature with `Rs.len() == 0` and `s == 0`. When verification is invoked with an empty `keys_and_challenges` list, the length check succeeds, no signer statements are queued, and `-sG` is the identity because `s` is zero. `multiexp_vartime` therefore evaluates to the identity and `verify` returns `true`. [2](#0-1) 

### Impact Explanation
This is a forged aggregate signature accepted by the public verification API without any signer participation or private-key knowledge. The impact is bounded by the caller’s policy: an empty signer set does not itself establish quorum, but any integration that treats successful aggregate verification plus separately supplied signer metadata as authorization can accept a proof produced by nobody. The verification API does not enforce the minimum security invariant that at least one authorized signer participated. [1](#0-0) [2](#0-1) 

### Likelihood Explanation
The input is entirely attacker-controlled public bytes fed to `SchnorrAggregate::read`, followed by a call to `verify` with an empty signer list. No collision, malicious validator set, leaked key, malformed curve, or computational assumption is required; the acceptance follows directly from the identity result produced by an empty statement list with `s = 0`. [1](#0-0) 

### Recommendation
Reject empty aggregates and empty signer lists in `SchnorrAggregate::verify`, preferably before evaluating the multi-scalar multiplication. Also reject zero-length `Rs` in `SchnorrAggregate::read` when serialization is intended only for signatures. Callers should additionally enforce quorum and signer authorization independently rather than relying on aggregate verification alone. [1](#0-0)

use ciphersuite::Ciphersuite;
use schnorr::aggregate::SchnorrAggregate;

fn empty_aggregate_is_accepted<C: Ciphersuite>(dst: &'static [u8]) -> io::Result<()> {
  let mut encoded = vec![0; 4];
  encoded.extend(C::F::ZERO.to_repr().as_ref());

  let aggregate = SchnorrAggregate::<C>::read(&mut encoded.as_slice())?;

  // Accepted: no nonce points, no public keys, and s = 0 produce only -0G.
  assert!(aggregate.verify(dst, &[]));
  Ok(())
}
