### Title
Missing bounds check in CLVM atom-length-prefix canonical-encoding check causes unhandled `IndexError` on crafted spend-bundle puzzle/solution bytes - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in [1](#0-0)  parse the raw CLVM atom length-prefix of a coin spend's `puzzle_reveal`/`solution` bytes without verifying that the multi-byte length-prefix continuation bytes actually exist inside the buffer, mirroring the reported CVE's root cause (insufficient bounds checking on a variable-length payload-descriptor field before reading continuation bytes).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` determines, from the high bits of `clvm_buffer[offset]`, how many additional length-prefix bytes (`prefix_len`, up to 5) follow, then loops reading `clvm_buffer[offset]` for each additional byte: [2](#0-1) 
There is no check that `offset + prefix_len` stays within `len(clvm_buffer)` before or during this loop. `is_clvm_canonical()` also advances `offset` by the returned `atom_len` size without confirming the new `offset` remains within buffer bounds before the next iteration re-indexes `clvm_buffer[offset]`: [3](#0-2) 
Any of these out-of-range index accesses raises an uncaught Python `IndexError`.

Test coverage confirms these functions are exercised directly against attacker-controlled `puzzle_reveal`/`solution` bytes from a submitted `SpendBundle`, and that canonical-encoding validation is invoked unconditionally inside `MempoolManager.add_spend_bundle` for every coin spend regardless of dedup/fast-forward eligibility flags: [4](#0-3) [5](#0-4) 

### Impact Explanation
An unprivileged spend-bundle submitter can craft a `puzzle_reveal` or `solution` blob whose final atom begins with a multi-byte length-prefix marker (e.g. `0xFC`, which signals a 5-byte continuation) but is truncated before the continuation bytes are present. When `MempoolManager.add_spend_bundle` reaches the canonical-encoding check on this spend, `is_atom_canonical`/`is_clvm_canonical` will raise an unhandled `IndexError` instead of returning a normal `False`/rejecting the spend with `Err.INVALID_COIN_SOLUTION`. This turns a should-be-rejected malformed transaction into an unhandled exception inside spend-bundle admission logic, disrupting normal transaction-processing flow for that request path.

### Likelihood Explanation
This is highly reachable: canonical-encoding validation runs on every submitted spend bundle's puzzle reveal and solution bytes as part of ordinary mempool admission, with no privileged access required. The trigger only requires a single truncated atom length-prefix byte sequence, which is trivial for any wallet-level or RPC submitter to construct.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before reading each continuation byte (`offset + i < len(clvm_buffer)`), and validate that `offset` (after advancing by `atom_len`) stays within `len(clvm_buffer)` in `is_clvm_canonical` before the next iteration dereferences `clvm_buffer[offset]`; raise/return a normal rejection (e.g., treat as non-canonical / raise `ValidationError` caught upstream) instead of allowing `IndexError` to propagate.

### Proof of Concept
Submit a `SpendBundle` whose coin spend uses a `solution` (or `puzzle_reveal`) ending in the byte `0xFC` with fewer than 5 trailing bytes, e.g. `bytes.fromhex("fc0000")`. When `MempoolManager.add_spend_bundle` calls `is_clvm_canonical()` on this buffer, `is_atom_canonical` enters the `prefix_len = 5` branch and attempts to read 5 continuation bytes that do not exist, raising `IndexError: index out of range` instead of the expected `Err.INVALID_COIN_SOLUTION` rejection path exercised in `test_mempool_requires_canonical_clvm`.

Note on confidence: within the available tool budget I confirmed the missing bounds check and its exercise via `chia/_tests/core/mempool/test_mempool_manager.py`'s `test_mempool_requires_canonical_clvm`/`test_bundles_are_canonical`, but could not trace the exact exception-handling layer above `MempoolManager.add_spend_bundle` (e.g., the peer-message/RPC handler that ultimately invokes it) to confirm whether the resulting `IndexError` is caught and logged versus fully unhandled at that layer. This should be verified with a live reproduction before treating the "processing halt" impact as fully confirmed.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
