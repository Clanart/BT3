### Title
Unchecked CLVM atom-length parsing causes uncaught IndexError / heap-style over-read in `is_atom_canonical` / `is_clvm_canonical` - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk a raw, attacker-supplied CLVM byte buffer (a spend bundle's `puzzle_reveal`/`solution`) by repeatedly indexing `clvm_buffer[offset]` and trusting length prefixes decoded straight out of that same untrusted buffer, without ever checking that `offset` (or `offset + atom_len`) stays within `len(clvm_buffer)`. This mirrors the CVE-2017-9620 root cause: `xps_select_font_encoding`/`xps_encode_font_char_imp` trusted attacker-controlled length/index fields from a parsed document and read past the buffer, causing a heap over-read/crash.

### Finding Description
`is_atom_canonical` decodes a multi-byte length prefix directly from the buffer: [1](#0-0) 

For each of the multi-byte prefix cases (`prefix_len` up to 5), the loop does:
```python
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
There is no check that `offset < len(clvm_buffer)` before this access, so a truncated buffer whose last byte declares a multi-byte length prefix causes `clvm_buffer[offset]` to run past the end of the bytes object.

The caller, `is_clvm_canonical`, then trusts the returned `atom_len` and advances the cursor unconditionally: [2](#0-1) 
```python
atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
...
offset += atom_len
```
`atom_len` can be an arbitrarily large declared value (up to `2**48`-ish per the 6-byte-prefix branch) that has no relationship to the actual remaining buffer length. On the next loop iteration, `b = clvm_buffer[offset]` is evaluated with `offset` potentially far past `len(clvm_buffer)`, raising an unhandled `IndexError` in normal Python bytes-object semantics (the CPython analog of a bounds-checked "safe" over-read that still surfaces as an uncontrolled exception instead of a validation failure).

This function is exercised directly against CLVM data coming from spend bundles: the test `test_bundles_are_canonical` calls `is_clvm_canonical(bytes(spend.puzzle_reveal))` and `is_clvm_canonical(bytes(spend.solution))` for every coin spend in a bundle: [3](#0-2) 
confirming that `puzzle_reveal`/`solution` bytes — fully attacker-controlled fields of an unprivileged `SpendBundle` — are the intended input domain for this canonical-encoding check, which per `.cursor/context/clvm-execution.md` exists to reject non-canonical/back-reference encodings during mempool-mode validation.

### Impact Explanation
An unprivileged spend-bundle submitter can craft a `puzzle_reveal` or `solution` byte string that begins a large/multi-byte atom-length prefix but is truncated before the declared atom body, or whose declared `atom_len` field causes the cursor to jump past the end of the buffer. Feeding this into `is_clvm_canonical` (reached from spend-bundle validation processing untrusted mempool input) raises an unhandled `IndexError` instead of returning a clean `False`/rejection. Depending on where this exception propagates in the mempool validation pipeline, this can manifest as a spend-triggered exception path that isn't the intended `ValidationError`/`Err` rejection flow, i.e. a DoS-style disruption of the transaction-processing path for a single crafted bundle — the closest reachable analog to the referenced "denial of service (crash)" bug class, without requiring any privileged capability.

### Likelihood Explanation
Any wallet user, offer counterparty, or RPC caller who can submit a `SpendBundle` controls the exact byte content of `puzzle_reveal`/`solution`. Constructing a byte string with a dangling multi-byte CLVM atom-length prefix is trivial (a handful of crafted bytes), requiring no cryptographic material, valid signatures beyond what mempool acceptance otherwise requires, or special privileges — only that the buffer reach this canonical-check code path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access in the multi-byte prefix loop (raise/return non-canonical rather than indexing out of range), and in `is_clvm_canonical` validate that `offset + atom_len <= len(clvm_buffer)` before advancing the cursor and before the next `clvm_buffer[offset]` read, returning `False` for any input where declared lengths exceed the remaining buffer.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
