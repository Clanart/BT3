### Title
Algorithmic Complexity DoS in `ThresholdKeys::read` via attacker-controlled threshold parameter - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::<C>::read` deserializes `t`, `n`, and `i` directly from attacker-controlled bytes, then calls `ThresholdKeys::new`, which computes the group key by evaluating `interpolation_factor` for every participant `1..=t`. Each `interpolation_factor` call is O(t), making group-key derivation O(t²) in a parameter the attacker fully controls, with t up to 65535.

### Finding Description
The Hono advisory describes quadratic CPU consumption from processing a single attacker-controlled string (`parts.slice(0, i).join('-')` for every prefix). The Serai analog is the deserialization + group-key-derivation path for threshold keys.

In `ThresholdKeys::read`, `t`, `n`, and `i` are read as raw `u16`s from the input stream with no bound other than `t <= n <= 65535` (enforced inside `ThresholdParams::new`, called at the end) [1](#0-0) . After reading `n` scalars (Constant interpolation) or `n` points (Lagrange), `read` calls `ThresholdKeys::new` [2](#0-1) .

`ThresholdKeys::new` computes the group key as `sum over i in 1..=t of verification_shares[i] * interpolation_factor(i, t)` [3](#0-2) . For `Interpolation::Lagrange`, each `interpolation_factor` iterates the full `included` list performing a field multiplication and subtraction per element, plus a field inversion [4](#0-3) . Total work is therefore Θ(t²) field multiplications plus t inversions and t point-scalar multiplications, all driven by a 2-byte attacker field.

The input size grows only linearly (n points ≈ 32 bytes each, so ~2 MB maximum for Ristretto-class encodings), while CPU work grows quadratically: at `t = n = 65535`, ~4.3·10⁹ field multiplications and 65535 field inversions are performed synchronously from a single ~2 MB input. The same O(t²) pattern reappears in `ThresholdKeys::view`/`ThresholdView::interpolation_factor`, which calls `interpolation_factor` once per included signer [5](#0-4) .

### Impact Explanation
An unprivileged party who can feed bytes to `ThresholdKeys::read` (listed as an accepted untrusted-input sink) can cause CPU work quadratic in the encoded `t` parameter while supplying only linear-size input. Repeated submissions block the calling thread/event loop for orders of magnitude longer than the input size would suggest — the same asymmetric-amplification DoS class as GHSA-54fx-42gc-7vw4. Any service deserializing threshold keys from untrusted sources (e.g., validator-set or key material transmitted over the network) can be stalled per request.

### Likelihood Explanation
Reachability depends on a deployment exposing `ThresholdKeys::read` (or `ThresholdView` construction) to untrusted bytes; the rules explicitly accept this sink. The trigger requires only setting `t`/`n` to large u16 values with validly-encoded (even identity-free) scalars/points — no malformed encodings needed, so no early error path prevents the quadratic work. `ThresholdKeys::new` performs the interpolation before returning, so the cost is paid on every `read` call.

### Recommendation
Bound `t` and `n` in `ThresholdKeys::read`/`ThresholdParams::new` to a protocol-appropriate maximum (e.g., `MAX_KEY_SHARES_PER_SET`) before doing interpolation work, and/or compute the Lagrange group key via O(t) prefix/suffix products (accumulate numerator and denominator products once, then derive each participant's factor incrementally) rather than recomputing the full product per participant — directly mirroring the advisory's fix of avoiding per-prefix reconstruction.

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use dkg::ThresholdKeys;
use frost::curve::Ristretto;

// Build a serialized ThresholdKeys blob with t = n = 65535, Lagrange interpolation.
// Size: ~32 * 65535 bytes of verification shares ≈ 2 MB.
let mut buf = vec![];
let id = <Ristretto as Ciphersuite>::ID;
buf.extend((id.len() as u32).to_le_bytes());
buf.extend(id);
buf.extend(65535u16.to_le_bytes()); // t
buf.extend(65535u16.to_le_bytes()); // n
buf.extend(1u16.to_le_bytes());     // i
buf.push(1u8);                      // Interpolation::Lagrange
buf.extend(<Ristretto as Ciphersuite>::F::ONE.to_repr()); // secret_share
let g = <Ristretto as Ciphersuite>::generator().to_bytes();
for _ in 0 .. 65535u16 {
  buf.extend(g.as_ref()); // verification shares
}

// Performs ~t^2 ≈ 4.3e9 field multiplications + 65535 field inversions
// inside ThresholdKeys::new's group_key derivation.
let _ = ThresholdKeys::<Ristretto>::read(&mut buf.as_slice());
```
