### Title
Empty aggregate Schnorr signature verifies successfully - (File: crypto/schnorr/src/aggregate.rs)

### Summary
Medium. `SchnorrAggregate::read` accepts an aggregate containing zero nonces, and `SchnorrAggregate::verify` accepts it when supplied with an empty key/challenge list and `s = 0`, even though `SchnorrAggregator::complete` refuses to produce an empty aggregate.

### Finding Description
`SchnorrAggregate::read` deserializes the declared number of `R` values without requiring at least one. [1](#0-0)  During verification, the only length check is equality between the encoded `Rs` and caller-provided `keys_and_challenges`. [2](#0-1)  When both are empty, the verification equation degenerates to checking that `-sG` is identity, so a canonical zero scalar makes verification succeed. [3](#0-2)  This is inconsistent with the generation path, which explicitly returns `None` when no signatures were aggregated. [4](#0-3) 

### Impact Explanation
An unauthenticated party can submit a serialized aggregate signature encoding zero signatures and a zero `s` value. If a verifier interprets a corresponding empty signer list as invalid—or mistakenly allows a dynamic signer list to become empty—the verifier still accepts the aggregate as valid, producing a forged aggregate signature acceptance. [5](#0-4) 

### Likelihood Explanation
Exploitation requires a verification path that accepts an empty signer set and passes attacker-controlled bytes through `SchnorrAggregate::read`. The implementation has no internal defense for that case, and its own aggregation API demonstrates that an empty aggregate is semantically invalid. [4](#0-3) 

### Recommendation
Reject `Rs.is_empty()` in `SchnorrAggregate::read` and defensively return `false` for an empty `keys_and_challenges` list in `SchnorrAggregate::verify`. This aligns deserialization and verification with `SchnorrAggregator::complete`, which already treats zero aggregated signatures as unrepresentable. [4](#0-3) 

### Proof of Concept
For a field whose canonical zero encoding is 32 zero bytes, the following wire input is accepted and verifies against an empty signer list:

```rust
let mut encoded = 0u32.to_le_bytes().to_vec(); // zero R values
encoded.extend([0u8; 32]);                     // s = 0

let aggregate =
  SchnorrAggregate::<Secp256k1>::read(&mut encoded.as_slice()).unwrap();

assert!(aggregate.verify(DST, &[]));
```

The verifier reaches an empty loop and checks only `multiexp_vartime(&[(-0, G)]).is_identity()`, which succeeds. [3](#0-2)
