### Title
`MessageDifferencer::StreamReporter` prints raw field values via `TextFormat::PrintFieldValueToString`, bypassing `debug_redact` field annotations - ([File: src/google/protobuf/util/message_differencer.cc])

### Summary
Apache NiFi's CVE-2020-1942 stems from a flow-fingerprint comparison mechanism that, when two configurations are found not to be mergeable, logs the fingerprint of both configs in plaintext — including sensitive property values that should have been protected. The failed invariant is: *a diagnostic/comparison code path that is expected to redact sensitive values instead prints them verbatim because the redaction logic that exists elsewhere in the codebase (for normal debug output) is not applied on this particular code path.* Protobuf has an almost exact structural analog: it has a `debug_redact` field-option mechanism specifically to keep sensitive field values out of debug/diagnostic text, but the `MessageDifferencer::StreamReporter` diffing/reporting path calls `TextFormat::PrintFieldValueToString` directly rather than going through the `Printer` machinery that checks `TryRedactFieldValue`/`debug_redact`.

### Finding Description
Protobuf provides an explicit, well-tested redaction feature for exactly this class of concern: fields (or nested message fields) annotated `[debug_redact = true]` are supposed to be printed as `[REDACTED]` instead of their real value whenever a "safe debug format" is requested. The mechanism lives in `TextFormat::Printer`:

- `TextFormat::Printer::TryRedactFieldValue()` and `GetRedactionState()`/`IsOptionSensitive()` check whether a field (or fields nested in its `FieldOptions`) is annotated `debug_redact = true`, and if `redact_debug_string_` is enabled, print `[REDACTED]` instead of the value. [1](#0-0) 
- This is wired into the normal `PrintFieldValue` path used by `Message::DebugString()`/`StringifyMessage()`. [2](#0-1) [3](#0-2) 

However, `google::protobuf::util::MessageDifferencer` — the diffing/comparison utility that computes and *reports* the differences between two messages (directly analogous to NiFi comparing local vs. cluster flow fingerprints and printing the diff) — uses a separate, standalone static API, `TextFormat::PrintFieldValueToString`, to render field values for its `StreamReporter::PrintValue`, `PrintMapKey`, `ReportAdded`, `ReportDeleted`, and `ReportModified` callbacks: [4](#0-3) [5](#0-4) [6](#0-5) 

`TextFormat::PrintFieldValueToString` is declared as a plain, stateless static helper on the `TextFormat` namespace class rather than as a method on a `Printer` instance that carries `redact_debug_string_`/`report_sensitive_fields_` state: [7](#0-6) 

Because it does not go through a `Printer` configured with `SetRedactDebugString(true)`, the `TryRedactFieldValue` check is never invoked for values printed by `MessageDifferencer`. Any application that logs the output of `MessageDifferencer::Compare()`'s `ReportDifferencesToString`/`StreamReporter` for diagnostic or audit purposes — e.g., comparing a "before" and "after" configuration message, similar to NiFi comparing cluster vs. local flow state — will have `debug_redact`-annotated sensitive fields (credentials, tokens, etc.) printed in cleartext in the diff output, exactly mirroring the NiFi flaw where the flow-fingerprint comparison path leaked sensitive values that normal flow serialization/printing would have protected.

### Impact Explanation
If an application relies on `debug_redact` annotations as its guarantee that sensitive fields never appear in logs/diagnostics (which is the documented purpose of the annotation: "Indicate that the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials"), and that application also uses `MessageDifferencer` to log or display differences between two protobuf messages (a common pattern for audit trails, config-drift detection, or test/CI diffing, directly analogous to NiFi's flow-fingerprint comparison), the sensitive values will be disclosed in the diff/report output even though the exact same fields would be redacted by `Message::DebugString()`. This is an information-disclosure issue matching the NiFi CVE's severity class (sensitive data disclosed in logs during a comparison/merge operation), not a memory-safety or RCE issue.

### Likelihood Explanation
The likelihood depends on the consuming application's use of `MessageDifferencer` reporting APIs (`ReportDifferencesToString`, `ReportDifferencesToStream`, or a custom `StreamReporter`) on messages containing `debug_redact`-annotated fields, combined with logging that output. This is a plausible, realistic usage pattern (config diffing, testing frameworks comparing protos and printing mismatches to logs), but it requires the developer to have already opted into `debug_redact` protection elsewhere and to not realize the diff-reporting path is not covered by the same protection — an inconsistency/documentation gap rather than a parser-level flaw reachable purely from untrusted binary/ProtoJSON input. No malicious input is required to trigger it beyond a message that already has sensitive data (attacker does not need to control anything to exploit unless they can view the log/diff output, similar to NiFi's log-exposure scenario).

### Recommendation
- Route `MessageDifferencer::StreamReporter` field-value printing through a `TextFormat::Printer` instance configured with `SetRedactDebugString(true)` (the same mechanism `Message::DebugString()` uses) instead of the raw static `TextFormat::PrintFieldValueToString`.
- Alternatively/additionally, make `PrintFieldValueToString` itself consult `TextFormat::GetRedactionState()`/`TryRedactFieldValue` for the field being printed, so any caller of this static API gets consistent redaction behavior.
- Document clearly in `message_differencer.h` that `StreamReporter` output is NOT currently redaction-aware, so consumers relying on `debug_redact` are not misled, until the mechanism is unified.

### Proof of Concept
Conceptual reproduction (not run in this environment — index/tooling here is read-only):
1. Define a proto message with a field annotated `[debug_redact = true]` (e.g., `string secret = 1 [debug_redact = true];`), as used in the existing redaction test schema `rust/test/unittest.proto` (`optional_redacted_string`, etc.). [8](#0-7) 
2. Construct two instances of that message, `msg1` with `secret = "OLD_CREDENTIAL"` and `msg2` with `secret = "NEW_CREDENTIAL"`.
3. Call `google::protobuf::Message::DebugString()`/`StringifyMessage()` on either message → output shows `secret: "[REDACTED]"` because `TryRedactFieldValue` is applied.
4. Call `util::MessageDifferencer differencer; differencer.ReportDifferencesToString(&output); differencer.Compare(msg1, msg2);` → the `StreamReporter::ReportModified` → `PrintValue` → `TextFormat::PrintFieldValueToString` path prints `modified: secret: "OLD_CREDENTIAL" -> "NEW_CREDENTIAL"` — the real secret values in plaintext, in the same process/library that redacts them via `DebugString()`.

This demonstrates the exact "the print/fingerprint path skips the redaction check that a sibling code path enforces" pattern that CVE-2020-1942 describes for NiFi's flow-fingerprint comparison. I was not able to execute this PoC in this read-only environment; the trace is based on static code reading of `message_differencer.cc`/`.h` and `text_format.cc`/`.h` as cited above.

std::string StringifyMessage(const Message& message, Option option,
                             FieldReporterLevel reporter_level) {
  // Indicate all scoped reflection calls are from DebugString function.
  ScopedReflectionMode scope(ReflectionMode::kDebugString);

  TextFormat::Printer printer;
  internal::FieldReporterLevel reporter = reporter_level;
  switch (option) {
    case Option::kShort:
      printer.SetSingleLineMode(true);
      break;
    case Option::kUTF8:
      printer.SetUseUtf8StringEscaping(true);
      break;
    case Option::kNone:
      break;
  }
  printer.SetExpandAny(true);
  printer.SetRedactDebugString(true);
  printer.SetRandomizeDebugString(true);
  printer.SetReportSensitiveFields(reporter);
  std::string result;
  // TODO: Remove this suppression.
  (void)printer.PrintToString(message, &result);

  if (option == Option::kShort) {
    TrimTrailingSpace(result);
  }

  return result;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

void MessageDifferencer::StreamReporter::PrintMapKey(
    bool left_side, const SpecificField& specific_field) {
  if (message1_ == nullptr || message2_ == nullptr) {
    ABSL_LOG(INFO) << "PrintPath cannot log map keys; "
                      "use SetMessages to provide the messages "
                      "being compared prior to any processing.";
    return;
  }

  const Message* found_message =
      left_side ? specific_field.map_entry1 : specific_field.map_entry2;
  std::string key_string = "";
  if (found_message != nullptr) {
    // NB: the map key is always the first field
    const FieldDescriptor* fd = found_message->GetDescriptor()->field(0);
    if (fd->cpp_type() == FieldDescriptor::CPPTYPE_STRING) {
      // Not using PrintFieldValueToString for strings to avoid extra
      // characters
      key_string = found_message->GetReflection()->GetString(
          *found_message, found_message->GetDescriptor()->field(0));
    } else {
      TextFormat::PrintFieldValueToString(*found_message, fd, -1, &key_string);
    }
    if (key_string.empty()) {
      key_string = "''";
    }
    printer_->PrintRaw(absl::StrCat("[", key_string, "]"));
  }
}

void MessageDifferencer::StreamReporter::ReportModified(
    const Message& message1, const Message& message2,
    const std::vector<SpecificField>& field_path) {
  if (!report_modified_aggregates_ && field_path.back().field == nullptr) {
    if (field_path.back().unknown_field_type == UnknownField::TYPE_GROUP) {
      // Any changes to the subfields have already been printed.
      return;
    }
  } else if (!report_modified_aggregates_) {
    if (field_path.back().field->cpp_type() ==
        FieldDescriptor::CPPTYPE_MESSAGE) {
      // Any changes to the subfields have already been printed.
      return;
    }
  }

  printer_->Print("modified: ");
  PrintPath(field_path, true);
  if (CheckPathChanged(field_path)) {
    printer_->Print(" -> ");
    PrintPath(field_path, false);
  }
  printer_->Print(": ");
  PrintValue(message1, field_path, true);
  printer_->Print(" -> ");
  PrintValue(message2, field_path, false);
  printer_->Print("\n");  // Print for newlines.
}
