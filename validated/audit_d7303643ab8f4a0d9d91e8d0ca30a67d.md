### Title
Zero-length aggregate signature accepted as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts a serialized aggregate containing zero `R` values, while `SchnorrAggregate::verify` accepts a matching empty `keys_and_challenges` list and reduces verification to checking `-s * G == identity`. Supplying `len = 0` and `s = 0` therefore produces a forged aggregate signature that verifies without any signatures or public keys. [1](#0-0) [2](#0-1) 

### Finding Description
The deserializer reads an attacker-controlled `u32` count and permits that count to be zero. [3](#0-2)  Verification only requires `self.Rs.len() == keys_and_challenges.len()`, then creates one statement `(-s, G)` when both lists are empty. [2](#0-1)  With serialized `s = 0`, that statement evaluates to identity, so verification succeeds. [4](#0-3)  The legitimate aggregation API explicitly rejects completing an aggregate with no signatures, establishing that empty aggregates are not meant to be valid. [5](#0-4) 

### Impact Explanation
An unprivileged party can submit a four-byte zero count followed by a canonical zero scalar and obtain an aggregate signature accepted as valid for an empty signer/message set. This bypasses the signature requirement without knowing any private key, satisfying a forged-signature condition wherever a caller can verify attacker-supplied aggregates against an empty `keys_and_challenges` list. [1](#0-0) [2](#0-1) 

### Likelihood Explanation
The input is fully controlled through `SchnorrAggregate::read`, has minimal size, and deterministically verifies. No malformed cryptographic encoding, private state, or race condition is required; only an empty verification context is needed. [1](#0-0) [2](#0-1) 

### Recommendation
Reject `Rs` counts of zero in `SchnorrAggregate::read` and independently reject empty `keys_and_challenges` in `verify`, matching `SchnorrAggregator::complete`, which already refuses to emit an empty aggregate. [1](#0-0) [5](#0-4) 

### Proof of Concept
For any `C: Ciphersuite` whose zero scalar has an all-zero canonical representation, the serialized aggregate is `00 00 00 00 || 00...00`. Deserializing it produces `Rs = []` and `s = 0`; `verify(dst, &[])` then evaluates the single statement `(-0) * G`, which is identity and returns `true`. [1](#0-0) [4](#0-3)
