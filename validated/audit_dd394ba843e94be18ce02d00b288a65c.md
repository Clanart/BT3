## Analysis

The Sherlock report describes a bug class where a system computes a **new key/identity** for ownership transfer but leaves prior records (and control) tied to the **old key**, causing loss of the funds/state that should have followed the new identity.

The sei-chain codebase has a directly analogous, already-partially-documented pattern in the EVM `addr` precompile's address-association flow: re-associating an EVM address (via `associate`/`associatePubKey`, address `0x1004`) computes a fresh Sei-address mapping for that EVM address, but any protocol state that was created under the EVM address's *previous* identity — its direct-cast Sei address (`sdk.AccAddress(evmAddr[:])`) — is not migrated to the new key and becomes permanently unreachable.

### Root cause

`SetAddressMapping` [1](#0-0)  simply overwrites the `EVMAddressToSeiAddressKey`/`SeiAddressToEVMAddressKey` entries whenever `associate`/`associatePubKey` is called through the permissionless `addr` precompile [2](#0-1) . `AssociateAddresses` only migrates **bank spendable coins and wei balance** from the old direct-cast address to the new Sei address [3](#0-2) ; it does not, and cannot, migrate staking delegations, validator records, unbonding queues, gov deposits, or any other module state keyed by the direct-cast address.

Once the mapping is rewritten, `CanAddressReceive`/`CanSendTo` permanently block the old direct-cast address from receiving any further funds [4](#0-3) [5](#0-4) . Any staking delegation, validator commission, unbonding delegation, or gov deposit that was created while the account operated under its direct-cast identity is now **permanently frozen** — it can never be paid out to that address again, and there is no path that automatically migrates it to the new true Sei address.

This is not purely theoretical: the codebase's own regression tests confirm the state becomes stuck/orphaned:
- Validator commission force-withdraw fails and is diverted to the community pool instead of the rightful validator [6](#0-5) .
- Unbonding delegations cannot complete and are retained forever in the queue, permanently withholding the delegator's tokens [7](#0-6) .
- Gov deposit refunds cannot be completed for an account associated after depositing [8](#0-7) .

The comments in the ante-handler code explicitly acknowledge this design gap: "a later associatePubKey call can remap, orphaning any staking/distribution state created under the direct-cast identity (which can then halt the chain via the distribution validator-removal hook)" [9](#0-8) , and `utils/helpers/address.go` [10](#0-9) .

### Reachability

`associate`/`associatePubKey` are **public, permissionless, unprivileged** EVM precompile methods at `0x1004` [11](#0-10) . Anyone can call `associatePubKey` for **any target's public key** (not just their own) — it takes a raw pubkey with no signature/ownership proof, deriving both the EVM and Sei addresses from it [12](#0-11) . If the target already has staking, unbonding, validator, or governance state resting under their EVM address's direct-cast Sei identity (a common occurrence, since new EVM users often interact via cast address before formally associating), any third party can trigger the re-association and permanently strand that state — with no user consent required for the timing of the freeze.

### Title
Permissionless address re-association via the `addr` precompile permanently strands staking, unbonding, and governance state tied to the direct-cast Sei address - (File: `precompiles/addr/addr.go`, `utils/helpers/associate.go`)

### Summary
`associate`/`associatePubKey` in the `addr` precompile let anyone rewrite the EVM↔Sei address mapping for an EVM address. Only bank balances are migrated to the new Sei address; state recorded under the old direct-cast Sei address (staking delegations, unbonding queues, validator commission, governance deposits) is left behind and becomes permanently unreachable once `CanSendTo`/`CanAddressReceive` blocks the direct-cast address.

### Finding Description
`SetAddressMapping` overwrites the EVM↔Sei mapping unconditionally [1](#0-0) . `AssociateAddresses`/`MigrateBalance` migrate only bank coin and wei balances from `castAddr = sdk.AccAddress(evmAddr[:])` to the newly associated `seiAddr` [3](#0-2) . No other module (staking, distribution, gov, wasm, etc.) is notified or migrated. After association, `CanAddressReceive`/`CanSendTo` permanently reject the direct-cast address as a valid recipient [4](#0-3) [5](#0-4) , so any pending payout owed to it (unbonding maturity, commission withdrawal, deposit refund) can never be delivered.

### Impact Explanation
This causes permanent freezing of user funds: validator commission is diverted to the community pool instead of the rightful recipient [13](#0-12) ; unbonding delegations are retained indefinitely and their queue entries never clear, permanently withholding delegator tokens [14](#0-13) ; governance deposits cannot be refunded [15](#0-14) . This meets the "permanent freezing" bar for validity.

### Likelihood Explanation
`associate`/`associatePubKey` are unauthenticated, unprivileged, fee-only EVM precompile calls reachable by any address (no ownership proof of the pubkey required) [12](#0-11) . Any account that delegates, deposits on governance proposals, or runs a validator while still using its unassociated direct-cast EVM identity is exposed the moment anyone (including itself, unknowingly) associates that EVM address to a different or even the same-but-freshly-derived Sei address.

### Recommendation
Before allowing `SetAddressMapping` to rewrite an EVM address's mapping, either (a) block re-association while the current direct-cast address still has outstanding staking/unbonding/governance state, or (b) extend the migration logic to also transfer/re-point staking delegations, unbonding queue entries, validator records, and governance deposits from the direct-cast address to the newly associated Sei address, mirroring what should have been done for `newBorrowingKey` in the referenced report.

### Proof of Concept
1. A user submits a staking delegation, an unbonding delegation, or a governance deposit from `castAddr = sdk.AccAddress(evmAddr[:])` before ever formally associating their EVM address (a legitimate and common flow since Sei allows unassociated cast addresses to hold and spend funds).
2. Any third party calls `associatePubKey(pubkey)` on the `addr` precompile (`0x1004`) with a pubkey whose derived EVM address equals `evmAddr` and whose derived Sei address (`seiAddr`) differs from `castAddr` — no signature over anything belonging to the caller is required, and the pubkey can be lifted from any prior chain activity by the target.
3. `SetAddressMapping(seiAddr, evmAddr)` is committed, and `MigrateBalance` moves only bank/wei balances; staking/gov state stays keyed to `castAddr`.
4. `CanAddressReceive(ctx, castAddr)` now returns `false` because `GetSeiAddress(castAddr's direct-cast evm) == seiAddr != castAddr` [16](#0-15) .
5. When the unbonding delegation matures, `EndBlocker` cannot pay out `castAddr` and the delegation is retained forever (as directly reproduced in `TestEndBlockRetainsUnbondingForInvalidRecipient` [7](#0-6) ), permanently freezing the delegator's principal.

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
