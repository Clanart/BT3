### Title
Coinbase outputs are reported as immediately spendable received funds - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`Scanner::scan_block` treats a coinbase transaction like any other transaction and returns matching outputs as `ReceivedOutput`s without recording that they are immature. Downstream transaction construction accepts those outputs solely based on the stored outpoint, script, value, and offset, allowing an application to create a spend transaction that Bitcoin consensus will reject until the coinbase has matured.

### Finding Description
`Scanner::scan_block` iterates over every transaction in `block.txdata`, including `block.txdata[0]`, which is the coinbase transaction. [1](#0-0) 

`Scanner::scan_transaction` matches outputs only by `script_pubkey`, creates a `ReceivedOutput` containing the output and outpoint, and provides no maturity state or other indication that the output cannot yet be spent. [2](#0-1) 

`SignableTransaction::new` accepts caller-provided `ReceivedOutput`s and converts their outpoints directly into transaction inputs without checking whether the referenced outputs are coinbase outputs or have sufficient confirmations. [3](#0-2) 

`SignableTransaction::multisig` likewise validates only that the tweaked group key corresponds to the previous output’s `script_pubkey`, not that the previous output is currently spendable. [4](#0-3) 

### Impact Explanation
A valid block producer can place an output paying the wallet’s P2TR script in the block’s coinbase transaction. `scan_block` reports that output through the same `ReceivedOutput` type used for immediately spendable outputs, even though Bitcoin consensus does not permit the coinbase output to be spent until it reaches maturity.

An application that passes the returned object to `SignableTransaction::new` can construct and threshold-sign a transaction spending an immature coinbase output. The transaction will be consensus-invalid when broadcast, so the wallet has reported and attempted to spend funds that are not currently spendable. This can disrupt automated wallet operation and cause failed withdrawal or payment attempts.

### Likelihood Explanation
The attacker does not need access to Serai keys, nodes, peers, validators, or RPC credentials. They need only produce a valid Bitcoin block containing a coinbase output to the target wallet’s script. This requires mining capability, but it is an externally reachable condition using public Bitcoin block data. The affected path is the normal `scan_block` → `ReceivedOutput` → `SignableTransaction` flow.

### Recommendation
Do not return coinbase outputs from `Scanner::scan_block` as ordinary spendable `ReceivedOutput`s. Either:

- Skip `block.txdata[0]` in `scan_block`, or
- Extend `ReceivedOutput` with maturity metadata and require `SignableTransaction::new` to reject immature coinbase outputs.

If scanning coinbase transactions is needed for accounting, expose it through a separate API or return a distinct type that cannot be passed to transaction construction until maturity has been established.

### Proof of Concept
Conceptually:

```rust
// A miner creates a valid block whose coinbase transaction contains:
//   output[0].script_pubkey = scanner_p2tr_script

let outputs = scanner.scan_block(&block);

// Because scan_transaction matched only script_pubkey, this contains the
// immature coinbase output as an ordinary ReceivedOutput.
assert_eq!(outputs.len(), 1);

// The wallet accepts it as an input.
let signable = SignableTransaction::new(
  outputs,
  &[(payment_script, payment_amount)],
  None,
  None,
  fee_per_vbyte,
).unwrap();

// Key/script validation also succeeds because the script_pubkey matches.
let machine = signable.multisig(&keys).unwrap();

// The resulting signed transaction necessarily fails consensus validation
// while the coinbase output remains immature.
```

The root cause is that `scan_block` collapses coinbase outputs into the same representation used for mature transaction outputs, while neither `ReceivedOutput` nor `SignableTransaction` carries or enforces coinbase maturity. [5](#0-4) [6](#0-5)

          offset: *offset,
