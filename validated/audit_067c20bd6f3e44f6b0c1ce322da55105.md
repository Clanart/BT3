### Title
Overpaid native fee in `EvmHost.dispatch`/`fundRequest` is never refunded to the caller — (File: `evm/src/core/EvmHost.sol`)

### Summary

### Finding Description
`EvmHost` exposes several `payable` entry points — `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest` — that accept native token (`msg.value`) as an alternative way to pay the ISMP request fee [1](#0-0) , [2](#0-1) , [3](#0-2) .

In each case, the entire `msg.value` is forwarded to the local UniswapV2 router via `swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)`. This is an *exact-output* swap: the router only consumes as much ETH as is needed to produce `fee`/`amount` fee tokens, and by design refunds any unused ETH back to `msg.sender` of that call. Because `EvmHost` itself is the caller of the router (not the original end user), that refund lands in `EvmHost`'s own balance, not back in the wallet of the user who called `dispatch`/`fundRequest`.

Just like the referenced report's `sendZkSafeTransaction`, these functions accept native ETH via `payable` but provide no code path to return unused/excess value to the sender — the surplus is silently absorbed by the contract with no corresponding accounting entry (it is not added to `FeeMetadata.fee`, not tracked per-user, and there is no `msg.sender.call{value: ...}` refund like the pattern used correctly in `evm/src/apps/intentsv2/ExtrinsicIntents.sol:164-168` for solver overpayment).

### Impact Explanation
Any user who overestimates the native-token amount needed to cover a swap-derived fee (e.g., due to price movement between quoting and execution, or simply passing a safety margin) permanently loses the excess ETH into `EvmHost`. This is a direct, unprivileged loss of user funds triggered purely through the public `dispatch`/`fundRequest` entry points — no relayer, prover, or admin action is required. It matches the "stealing or loss of funds" and "funds must move exactly once and only to the rightful beneficiary and amount" criteria: the surplus ends up owned by the protocol contract rather than the depositor.

### Likelihood Explanation
High likelihood in practice: because the exact native amount required depends on live Uniswap pricing at execution time, callers routinely send a slightly higher `msg.value` than strictly necessary to avoid reverts from slippage between quoting and submission (the same pattern documented for the SDK's `send()`/`bridge()` flows, e.g. `sdk/packages/sdk/src/protocols/hyperFungibleToken.ts:334-341`, which adds `fee.totalNativeCost` without an explicit refund step). Every such overpayment on `dispatch`/`fundRequest` is trapped.

### Recommendation
Track the actual `feeToken` amount received/spent versus `msg.value` supplied, and refund any leftover native ETH to `_msgSender()` (or `post.payer`/`get`'s original caller) at the end of `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest`, mirroring the refund pattern already implemented in `ExtrinsicIntents.sol` (`if (msgValue > 0) { (bool sent,) = msg.sender.call{value: msgValue}(""); ... }`). Alternatively, replace the exact-output swap with an exact-input swap plus explicit fee accounting so no ETH is ever silently retained by the router refund path.

### Proof of Concept
1. Compute `fee` required for a `DispatchPost` (via `feeToken()`/router quote).
2. Call `dispatch{value: fee_in_eth + extra}(post)` from an EOA, where `extra > 0` represents normal slippage buffer.
3. Internally, `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)` only spends enough ETH to buy `post.fee` fee tokens; the router refunds `extra` ETH — but to `EvmHost` (`msg.sender` inside the router call), not to the original caller.
4. `EvmHost`'s ETH balance increases by `extra`, and there is no function in `EvmHost.sol` reachable by the depositor to reclaim it; `FeeMetadata` only records `fee`/`post.fee`, so the surplus is untracked and effectively permanently lost to the depositor. [4](#0-3)

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
