### Title
Non-recursive `BaseCallFilter::contains` check allows filtered calls to be dispatched via batch/proxy wrapper calls - (File: modules/pallets/hyper-fungible-token/src/module.rs)

### Summary
The `on_accept` handler decodes an attacker/relayer-supplied `runtime_call` from cross-chain calldata and gates its execution with a single, non-recursive `BaseCallFilter::contains(&runtime_call)` check before dispatching it with `RawOrigin::Signed(origin)`.

### Finding Description
At [1](#0-0) , the pallet decodes an attacker-controlled `SubstrateCalldata::runtime_call` blob (arriving via a cross-chain `PostRequest`, gated only by an existing `ContractToAsset` mapping, which is not privileged) into a `T::RuntimeCall`, checks `BaseCallFilter::contains(&runtime_call)`, and if it passes, dispatches it via `Dispatchable::dispatch(RawOrigin::Signed(origin.clone()).into())`.

`Contains::contains` implementations in Substrate typically pattern-match only the *outer* `RuntimeCall` variant. If the runtime's `BaseCallFilter` is a simple `Everything`/enum-matcher type that does not explicitly recurse into wrapper calls (e.g. `pallet_utility::Call::batch`/`batch_all`/`force_batch`, `pallet_proxy::Call::proxy`, `pallet_multisig::Call::as_multi`, `pallet_scheduler::Call::schedule`), then wrapping a filtered inner call inside one of these wrapper calls would let the outer `contains()` check pass (since the wrapper call itself is not filtered) while the actual filtered/privileged inner call still executes once the wrapper call is dispatched and internally re-dispatches its inner calls with the same signed origin.

Both Gargantua and Nexus runtimes include `pallet_utility` and `pallet_proxy` in their `RuntimeCall` enums (confirmed via their weight files), so these wrapper calls are part of the dispatchable surface reachable from this code path.

### Impact Explanation
If the concrete `BaseCallFilter` in these runtimes does not recursively filter nested calls, an attacker with any `ContractToAsset` entry (a normal token bridge configuration, not privileged) could bypass maintenance-mode/`SafeMode` restrictions and execute otherwise-filtered dispatchables using `RawOrigin::Signed(beneficiary)`, violating the stated invariant that cross-chain messages must never reach dispatchables the runtime has filtered out.

### Likelihood Explanation
This depends entirely on the actual `BaseCallFilter` implementation configured for `frame_system::Config` in the Gargantua/Nexus runtimes. If that filter is implemented with explicit recursive matching for `Utility`/`Proxy`/`Multisig` wrapper calls (a common and recommended Substrate pattern for `SafeMode`/`TxPause`-style filters), this is not exploitable. I could not conclusively verify this filter's implementation due to file-content limits in the index for `parachain/runtimes/nexus/src/lib.rs` and `parachain/runtimes/gargantua/src/lib.rs`.

### Recommendation
Verify (or, if a background Devin session is used, inspect the full `parachain/runtimes/{gargantua,nexus}/src/lib.rs` `type BaseCallFilter = ...` definition) whether the filter recursively inspects wrapper-call variants (`pallet_utility::Call::batch*`, `pallet_proxy::Call::proxy*`, `pallet_multisig::Call::as_multi*`, `pallet_scheduler::Call::schedule*`). If it does not, either implement recursive filtering in the `Contains` impl, or explicitly deny dispatch of these wrapper call variants from within `HyperFungibleToken::on_accept`.
