### Title
`ReceivedOutput::read` instantiates a spendable output from unvalidated bytes (offset/outpoint/TxOut never checked against the scanner key or chain) - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to M06's "unchecked address used to instantiate a contract," `ReceivedOutput::read` instantiates a spendable-output object from three attacker-controlled fields — a scalar `offset`, a `TxOut`, and an `OutPoint` — without validating that they are mutually consistent or correspond to any real, spendable UTXO. The scanner's own constructor (`Scanner::scan_transaction`) only ever creates `ReceivedOutput`s whose `script_pubkey` was proven to match `key + offset*G` and whose `outpoint`/`value` come from an actual chain transaction; the deserialization path performs none of that validation.

### Finding Description
`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F`, then consensus-decodes an arbitrary `TxOut` and `OutPoint`, and returns the object unconditionally (`networks/bitcoin/src/wallet/mod.rs:122-134`). The missing checks are:

1. **No offset/output binding**: it never verifies `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey` — the exact relation `Scanner::scan_transaction` establishes (`mod.rs:205-211`) and `SignableTransaction::multisig` later relies on (`send.rs:277-279`).
2. **No outpoint/output binding**: the `outpoint` need not reference the decoded `output` at all — the claimed `output.value` can exceed the real UTXO's value or reference a nonexistent prevout.
3. **No spendability check**: `output.value` may be below dust or the `script_pubkey` may not even be a P2TR output.

Like the report's `IPerpetual(perpetualAddress)` instantiation, the object is constructed from raw input and the inconsistency only surfaces later: `multisig` returns `None` mid-flow for case (1) (mirroring M06's downstream revert breaking rebalancing), and for cases (2)-(3) signing proceeds to completion — `TransactionSignatureMachine::complete` produces a fully "signed" transaction spending a fabricated prevout/value that is invalid or unspendable on-chain.

### Impact Explanation
An unprivileged party who can supply serialized `ReceivedOutput` bytes (the prompt's permitted `ReceivedOutput::read` surface) causes the wallet to report funds as received that are not spendable: `ReceivedOutput::value()` returns the attacker-chosen `output.value` (`mod.rs:116-118`), and `SignableTransaction::new` sums those fabricated values into `input_sat` for balance/fee accounting (`send.rs:175`). A `ReceivedOutput` with a real `script_pubkey` (so `multisig` passes) but a wrong `outpoint` or inflated `value` yields a signed transaction the network rejects, while accounting credited the full fabricated amount — a funds-reported-received-that-are-not-spendable condition, matching the prompt's accepted impact class.

### Likelihood Explanation
Likelihood is moderate: it requires the deployment to accept `ReceivedOutput` bytes from an untrusted channel rather than solely from `Scanner::scan_block`/`scan_transaction`. When reachable, no cryptographic break is needed — only malformed serialization. The honest-path guard in `multisig` (`send.rs:277`) catches only the offset/script mismatch subset, and only after the wallet has already counted the phantom value; mismatched outpoints or inflated values pass that check entirely.

### Recommendation
In `ReceivedOutput::read`, or a dedicated validated constructor, take the scanner's `ProjectivePoint` key and require `p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset) == Some(output.script_pubkey)` before returning — analogous to the report's recommended `isContract` check. Additionally, verify the `TxOut` is P2TR and non-dust. Binding `outpoint` to `output` requires chain data, so document that `read` outputs must be re-verified against chain state before being treated as received funds (or expose a `Scanner::verify_received(key, &ReceivedOutput)` helper).

### Proof of Concept
```rust
// Attacker-crafted bytes fed to ReceivedOutput::read
let mut buf = vec![];
// offset = 0x01.. (any scalar, need not correspond to the output)
buf.extend(Scalar::ONE.to_bytes());
// output: a TxOut whose script_pubkey is the *real* wallet P2TR script,
// but whose value is inflated (e.g., 100 BTC when the real UTXO has 0.001 BTC)
consensus_encode(&TxOut { value: Amount::from_sat(10_000_000_000), script_pubkey: real_script }, &mut buf);
// outpoint: any fabricated or low-value real prevout
consensus_encode(&OutPoint::new(Txid::from_raw_hash(..), 0), &mut buf);

let received = ReceivedOutput::read(&mut buf.as_ref()).unwrap();
assert_eq!(received.value(), 10_000_000_000); // credited, never validated

// SignableTransaction::new counts the full 100 BTC as inputs (send.rs:175)
// multisig() passes since script_pubkey genuinely matches the key (send.rs:277)
// complete() returns a signed TX the network rejects -> funds reported, not spendable
```
