### Title
Unauthenticated broadcast of attacker-supplied transactions via `AggregatorServer::internal_send_tx` when `client_verification=false` - (`core/src/servers.rs`, `core/src/rpc/interceptors.rs`)

### Summary
The `Internal*`-prefixed gRPC methods (e.g. `internal_send_tx`) are meant to be reachable only by the aggregator's own client certificate, enforced solely by `only_aggregator_and_self`'s `is_internal` check. That check, and all certificate verification, is skipped entirely when `Interceptors::Noop` is installed, which `create_grpc_server` does whenever `config.client_verification == false`. Critically, `BridgeConfig::check_mainnet_requirements` only forbids `client_verification=false` for `Actor::Verifier` and `Actor::Operator`, not for `Actor::Aggregator`, so this misconfiguration is not blocked even on mainnet.

### Finding Description
The intended binding is:
`CALLER_IDENTITY(request to an "Internal*" method) == AGGREGATOR_OWN_CLIENT_CERT`

This is enforced only inside `only_aggregator_and_self`, which checks `is_internal(&req)` (matching methods whose gRPC path starts with `"Internal"`) and then requires `leaf_cert == our_cert` [1](#0-0) .

`create_grpc_server` selects the interceptor based on `config.client_verification`: if `true` it installs `OnlyAggregatorAndSelf`, otherwise it installs `Interceptors::Noop`, which simply forwards the request unchanged with no certificate or identity check at all [2](#0-1) . `Interceptors::Noop`'s `call` implementation returns `Ok(req)` unconditionally [3](#0-2) .

`create_aggregator_grpc_server` merely emits a `tracing::warn!` when `client_verification` is enabled — there is no corresponding hard failure or warning path when it is disabled — and then calls `create_grpc_server` with whatever `client_verification` value is in the config [4](#0-3) .

Root cause of exposure at scale: `BridgeConfig::check_mainnet_requirements` only pushes a misconfiguration error for `client_verification=false` when `actor_type` is `Verifier` or `Operator`; the `Aggregator` actor type is not checked, so a mainnet aggregator can legally run with `client_verification=false` and no safety net catches it [5](#0-4) .

With `client_verification=false`, any TCP client that can reach the aggregator's gRPC port — with no TLS client certificate at all — has its request pass through `Noop` untouched and lands directly on `ClementineAggregatorServer::internal_send_tx` → `AggregatorServer::internal_send_tx`, exactly as though it held the aggregator's own client certificate. The `is_internal`/self-only guard that is supposed to gate this method never executes.

I was not able to view the full body of `AggregatorServer::internal_send_tx` in `core/src/rpc/aggregator.rs` (the file is 2691 lines and the relevant section was truncated beyond line 1000 in what I could retrieve), so I cannot fully confirm what validation, if any, `internal_send_tx` performs on the supplied `raw_tx` before queueing it for broadcast/fee-bumping through the tx-sender. This is a genuine gap in my verification and should be checked directly in that file before remediation.

### Impact Explanation
At minimum this is an unauthenticated state-changing/broadcasting call reachable by any network peer able to connect to the aggregator's plain gRPC port with no client certificate — this matches the High-severity category verbatim ("an unauthenticated state-changing or broadcasting call"). Whether it escalates to Critical (BTC leaving a move-to-vault UTXO without a matching fronted withdrawal) depends on whether `internal_send_tx` will broadcast/fee-bump *any* attacker-supplied signed transaction without re-validating that it originated from a legitimate internal signing flow — attackers still cannot forge the N-of-N MuSig2 signature needed to spend a move-to-vault UTXO, so genuine bridge-fund theft would require the attacker to already possess a validly signed transaction, which is outside the stated unprivileged-attacker capabilities. The confirmed, in-scope impact is the authentication bypass itself, repeatable against every aggregator instance deployed with `client_verification=false` (a config state that mainnet checks do not prevent for the Aggregator actor).

### Likelihood Explanation
Requires the operator to have deployed the aggregator with `client_verification=false` — the default is `true` [6](#0-5)  — but nothing in `check_mainnet_requirements` blocks this for the Aggregator actor even on mainnet, so it is a plausible operational misconfiguration rather than a purely theoretical one. No BTC cost is required to reach the vulnerable code path itself (no signature forgery, no fee spend needed to trigger the missing-check bypass); cost only arises if a further step (obtaining/forging a validly signed spending transaction) is attempted, which is out of reach for an unprivileged attacker per the stated preconditions.

### Recommendation
Add `client_verification=false` to `check_mainnet_requirements` misconfigurations for `Actor::Aggregator`, not just `Verifier`/`Operator`. More fundamentally, do not rely solely on the interceptor for the "Internal"-only guarantee: reject `Internal*`-prefixed RPCs outright (regardless of `client_verification` setting) unless the connection is authenticated via mTLS with the aggregator's own certificate, or bind these internal-only endpoints to a loopback/unix-socket transport rather than the public TCP gRPC listener.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
