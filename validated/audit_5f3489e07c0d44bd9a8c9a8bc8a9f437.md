## Title
Verifiers accept a self-funded UTXO as a `ReplacementDeposit` for any attacker-chosen `old_move_txid`, minting a fresh N-of-N vault with no linkage to a security-council-authorized spend - (File: core/src/deposit.rs, core/src/verifier.rs)

## Summary
`DepositData::get_deposit_scripts` for `DepositType::ReplacementDeposit` builds the expected taproot scriptPubkey purely from public data — `nofn_xonly_pk`, the attacker-supplied `old_move_txid`, and the public `security_council` config — via `ReplacementDepositScript::new` and `Multisig::from_security_council`. `Verifier::is_deposit_valid` (`core/src/verifier.rs:660-705`) only checks that some on-chain UTXO matches this expected scriptPubkey and has value `bridge_amount`; it never verifies that this UTXO is the actual output produced by the security council spending the `old_move_txid` move-to-vault output.

## Finding Description
The claimed binding: *a move txid the verifiers presign == one unspent `bridge_amount` deposit output that is the security-council-authorized successor of `old_move_txid`*.

Trace:
- `create_replacement_deposit_txhandler` (`core/src/builder/transaction/mod.rs:404-446`) shows the *intended* design: a replacement deposit's **input** must be spent from a taproot output with leaves `[CheckSig(old_nofn_xonly_pk), Multisig::from_security_council(...)]` — i.e., the actual old move-to-vault UTXO, spendable only by nofn or the security council. This is the honest-path construction used only in tests (`#[cfg(test)]`).
- However, `DepositData::get_deposit_scripts` (`core/src/deposit.rs:206-217`), the function actually used by verifiers to validate an incoming deposit, does **not** derive the expected script from any real prior UTXO. It simply constructs `ReplacementDepositScript::new(nofn_xonly_pk, replacement_deposit_data.old_move_txid)` — where `old_move_txid` is attacker-supplied `ReplacementDepositData` from the gRPC `Deposit.replacement_deposit.old_move_txid` field (`core/src/rpc/clementine.proto:120-123`) — plus `Multisig::from_security_council(self.security_council.clone())`.
- `Verifier::is_deposit_valid` (`core/src/verifier.rs:659-705`) computes `expected_scriptpubkey` from `get_deposit_scripts` and only checks: (1) `security_council` matches config, (2) actor uniqueness limits, (3) the on-chain `deposit_outpoint` transaction has `value == bridge_amount` and `script_pubkey == expected_scriptpubkey`, (4) block height ≥ `start_height`. There is no check that `deposit_outpoint`'s transaction spends the output of `old_move_txid`, that `old_move_txid` exists, is unspent/spent, or was spent via `Multisig::from_security_council` specifically.
- Since `ReplacementDepositScript::to_script_buf` (`core/src/builder/script.rs:526-538`) and the security council multisig script are both fully deterministic from public keys and the attacker-chosen `old_move_txid` bytes, an attacker can independently compute `generate_replacement_deposit_address(T, nofn_xonly_pk, network, security_council)` (`core/src/builder/address.rs:89-103`) for **any** `T`, including the `move_txid` of a completed, already-reimbursed withdrawal cycle, fund that address from their own wallet with `bridge_amount`, and submit it as `deposit_outpoint` in a `Deposit{ deposit_data: ReplacementDeposit{ old_move_txid: T } }` request to the aggregator's `new_deposit`/`deposit_sign` RPCs.
- `Verifier::deposit_sign` (`core/src/verifier.rs:866-886`) calls `is_deposit_valid` and, on success, persists the deposit and proceeds to co-sign a brand-new `move_to_vault_tx` (`create_move_to_vault_txhandler`, `core/src/builder/transaction/mod.rs:306-343`) moving `bridge_amount` from the attacker's self-funded UTXO into a fresh N-of-N + security-council vault output.

Root cause: the on-chain-verifiable binding between a `ReplacementDeposit` and the security-council-authorized consumption of `old_move_txid`'s output is asserted only by the *test helper* `create_replacement_deposit_txhandler`/`sign_replacement_deposit_tx_with_sec_council`, never by the verifier's actual acceptance check (`get_deposit_scripts` + `is_deposit_valid`). The verifier trusts the scriptPubkey shape alone, and that shape is fully attacker-computable and fundable without any spend of `old_move_txid` ever occurring.

## Impact Explanation
This lets an unprivileged attacker mint an arbitrary N-of-N presigned vault (`move_to_vault_tx`) backed only by their own self-funded UTXO, citing a completed/settled `move_txid` as pretext. Once the verifiers presign the new move-to-vault transaction and any downstream deposit/payout machinery treats the citrea-side `replaceDeposit` call as authorizing a Citrea-side deposit credit, this is a "N-of-N partial signatures for an unauthorised spend"-class and potential BTC-movement issue: the vault is presigned as a legitimate replacement without any security-council authorization event ever having occurred against `old_move_txid`. It is repeatable across any completed or even non-existent `old_move_txid` and does not depend on which operator is involved, since the check is purely at the verifier/deposit-validation layer shared by all deposits.

## Likelihood Explanation
Preconditions are minimal: the attacker needs only public information (`nofn_xonly_pk`, `security_council` config — both retrievable via `get_nofn_aggregated_xonly_pk` gRPC and known config) and any `Txid` value of their choosing, then must fund the derived taproot address with `bridge_amount` BTC of their own money (real cost = `bridge_amount` + fees, which they can arrange to reclaim once the vault mints or via other paths) and call the aggregator's public `new_deposit`/`deposit_sign` gRPC endpoints, matching the explicit unprivileged-attacker capability list in the rules (deposit into the bridge, send requests to the aggregator's public gRPC port). No verifier, operator, or security-council collusion is required.

## Recommendation
`DepositData::get_deposit_scripts`/`Verifier::is_deposit_valid` must not accept a `ReplacementDeposit` based solely on scriptPubkey shape. The verifier must independently confirm that: (1) `old_move_txid` refers to a `move_to_vault_tx` that verifiers actually previously signed/track in their DB, (2) that `old_move_txid`'s move-to-vault output has actually been spent, and (3) the spending transaction's witness used the `Multisig::from_security_council` script path (not the N-of-N `CheckSig` path used for legitimate withdrawals), and that `deposit_outpoint` is exactly that spend's output. This requires walking the chain from `old_move_txid`'s output to its spending transaction and validating the witness/script-path used, analogous to how `create_replacement_deposit_txhandler`'s input side is constructed in tests, rather than trusting an attacker-suppliable scriptPubkey match alone.

/// Struct for deposit script that replaces an old move tx with a replacement deposit (to update bridge design on chain)
/// It commits to the old move txid inside the script.
#[derive(Debug, Clone)]
pub struct ReplacementDepositScript(pub(crate) XOnlyPublicKey, Txid);

impl SpendableScript for ReplacementDepositScript {
    fn as_any(&self) -> &dyn Any {
        self
    }

    fn kind(&self) -> ScriptKind {
        ScriptKind::ReplacementDepositScript(self)
    }

    fn to_script_buf(&self) -> ScriptBuf {
        let citrea_replace: [u8; 13] = "citreaReplace".as_bytes().try_into().expect("length == 13");

        Builder::new()
            .push_x_only_key(&self.0)
            .push_opcode(OP_CHECKSIG)
            .push_opcode(OP_FALSE)
            .push_opcode(OP_IF)
            .push_slice(citrea_replace)
            .push_slice(self.1.as_byte_array())
            .push_opcode(OP_ENDIF)
            .into_script()
    }
}

impl ReplacementDepositScript {
    pub fn generate_script_inputs(&self, signature: &taproot::Signature) -> Witness {
        Witness::from_slice(&[signature.serialize()])
    }

    pub fn new(nofn_xonly_pk: XOnlyPublicKey, old_move_txid: Txid) -> Self {
        Self(nofn_xonly_pk, old_move_txid)
    }
}

    nofn_xonly_pk: XOnlyPublicKey,

pub fn create_move_to_vault_txhandler(
    deposit_data: &mut DepositData,
    paramset: &'static ProtocolParamset,
) -> Result<TxHandler<Unsigned>, BridgeError> {
    let nofn_xonly_pk = deposit_data.get_nofn_xonly_pk()?;
    let deposit_outpoint = deposit_data.get_deposit_outpoint();
    let nofn_script = Arc::new(CheckSig::new(nofn_xonly_pk));
    let security_council_script = Arc::new(Multisig::from_security_council(
        deposit_data.security_council.clone(),
    ));

    let deposit_scripts = deposit_data.get_deposit_scripts(paramset)?;

    Ok(TxHandlerBuilder::new(TransactionType::MoveToVault)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            SpendableTxIn::from_scripts(
                deposit_outpoint,
                paramset.bridge_amount,
                deposit_scripts,
                None,
                paramset.network,
            ),
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_scripts(
            paramset.bridge_amount,
            vec![nofn_script, security_council_script],
            None,
            paramset.network,
        ))
        // always use 0 sat anchor for move_tx, this will keep the amount in move to vault tx exactly the bridge amount
        .add_output(UnspentTxOut::from_partial(anchor_output(Amount::from_sat(
            0,
        ))))
        .finalize())

pub fn create_replacement_deposit_txhandler(
    old_move_txid: Txid,
    input_outpoint: OutPoint,
    old_nofn_xonly_pk: XOnlyPublicKey,
    new_nofn_xonly_pk: XOnlyPublicKey,
    paramset: &'static ProtocolParamset,
    security_council: SecurityCouncil,
) -> Result<TxHandler, BridgeError> {
    Ok(TxHandlerBuilder::new(TransactionType::ReplacementDeposit)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NoSignature,
            SpendableTxIn::from_scripts(
                input_outpoint,
                paramset.bridge_amount,
                vec![
                    Arc::new(CheckSig::new(old_nofn_xonly_pk)),
                    Arc::new(Multisig::from_security_council(security_council.clone())),
                ],
                None,
                paramset.network,
            ),
            crate::builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(UnspentTxOut::from_scripts(
            paramset.bridge_amount,
            vec![
                Arc::new(ReplacementDepositScript::new(
                    new_nofn_xonly_pk,
                    old_move_txid,
                )),
                Arc::new(Multisig::from_security_council(security_council)),
            ],
            None,
            paramset.network,
        ))
        // always use 0 sat anchor for replacement deposit tx, this will keep the amount in replacement deposit tx exactly the bridge amount
        .add_output(UnspentTxOut::from_partial(anchor_output(Amount::from_sat(
            0,
        ))))
        .finalize())
}
