### Title
`SchnorrAggregate::verify` aggregation weights do not bind `Rs` or the public keys, enabling trivial forgery of aggregate signatures - ([File: crypto/schnorr/src/aggregate.rs])

### Summary
`SchnorrAggregate::verify` computes a per-signature weight `z` via `weight(&mut digest)`, but the `DigestTranscript` is only fed the verifier-supplied `challenge` scalars. The attacker-controlled `Rs` (the signature nonces) and the `keys` are never appended to the transcript. Because `z` is therefore a publicly-computable function of public data only, a forger can solve the single verification equation `Σ zᵢ·Rᵢ + Σ zᵢ·cᵢ·Aᵢ − s·G = 0` by choosing all-but-one `Rᵢ` and `s` arbitrarily and solving for the last `Rₙ` — no discrete log knowledge is needed.

### Finding Description
The kernel analog is a read-modify-write where only part of a wide value is actually controlled, leaving the rest to a stale/zero value. Here, the aggregation "weight" is meant to bind the entire verification statement (as required by eprint 2021/350, which the code cites), yet it binds only the `challenge` component while `Rs` and `keys` — both attacker-influenced — are excluded from the digest.

Relevant code in `crypto/schnorr/src/aggregate.rs`:

```rust
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}

for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
  let z = weight(&mut digest);
  pairs.push((z, self.Rs[i]));
  pairs.push((z * challenge, *key));
}
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity().into()
```

`z` depends only on `dst` and the challenges. `self.Rs` (fully attacker-controlled via `SchnorrAggregate::read`, which only enforces canonical point encodings) is never hashed.

### Impact Explanation
Any verifier calling `SchnorrAggregate::verify` accepts a forged aggregate signature over arbitrary `keys_and_challenges`. The forger:

1. Obtains the intended `keys_and_challenges` (public keys and their Schnorr challenges — both public).
2. Locally computes each `zᵢ = weight(digest)` since it is deterministic public data.
3. Picks `s` and `R₁..R_{n-1}` arbitrarily.
4. Sets `Rₙ = zₙ⁻¹·(s·G − Σ_{i<n} zᵢ·Rᵢ − Σᵢ zᵢ·cᵢ·Aᵢ)`.
5. Submits `SchnorrAggregate { Rs, s }`, which serializes/reads cleanly and passes `multiexp_vartime(...) == identity`.

This yields a forged "aggregate signature" attributed to honest public keys for arbitrary messages — a signature forgery reachable entirely from public inputs (the `Rs` and `s` bytes fed to `verify`).

### Likelihood Explanation
Deterministic. The weights are a pure function of the public challenges, so the forgery requires only a finite-field inversion and a few point operations. `weight` produces a nonzero scalar except with negligible probability, so `zₙ⁻¹` almost always exists. Reachability is through the documented public API `SchnorrAggregate::read` → `verify`; this verifier is used by in-tree consumers such as the Tributary Tendermint commit aggregator (`DST = b"Tributary Tendermint Commit Aggregator"`), where aggregate signatures are supplied by external parties.

### Recommendation
Bind every component of each statement into the weight derivation: for each index, append `Rs[i].to_bytes()`, `key.to_bytes()`, and the challenge to `digest` before calling `weight`, or incorporate the full statement into a per-signature transcript. Additionally, reject `z == 0` explicitly rather than relying on the negligible probability.

### Proof of Concept
```rust
// Given public keys_and_challenges: Vec<(C::G, C::F)> of length n
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in &keys_and_challenges {
  digest.append_message(b"challenge", c.to_repr());
}
let zs: Vec<C::F> = (0 .. n).map(|_| weight(&mut digest)).collect();

// Fixed component of the equation the attacker cannot avoid
let mut acc = C::G::identity();              // Σ z_i c_i A_i
for (i, (key, c)) in keys_and_challenges.iter().enumerate() {
  acc += *key * (zs[i] * c);
}

let s = C::F::ZERO;                          // free choice
let mut rs = vec![C::G::generator(); n - 1]; // free choices
let mut r_sum = C::G::identity();
for i in 0 .. (n - 1) {
  r_sum += rs[i] * zs[i];
}
// Solve z_n * R_n = s*G - acc - r_sum
let r_n = (C::generator() * s - acc - r_sum) * zs[n - 1].invert().unwrap();
rs.push(r_n);

let forged = SchnorrAggregate::<C> { Rs: rs, s };
assert!(forged.verify(dst, &keys_and_challenges)); // passes — forgery

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
