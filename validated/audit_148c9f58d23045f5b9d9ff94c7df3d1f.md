### Title
Attacker-controlled `_minMGPRec=0` in `_bullMGP` allows manipulated busd→mgp swap rate to inflate locked MGP beyond real value - ([File: wombat/ArbWomUp2.sol])

### Summary
`incentiveDeposit` lets any unprivileged caller pass `_minMGPRec` directly into the busd→mgp `ROUTER.swapExactTokensForTokens` call inside `_bullMGP`, with no protocol-side floor or oracle check on the accepted swap rate. Because the caller can set `_minMGPRec = 0`, an attacker can manipulate the busd/mgp AMM pool price immediately before/around their own transaction (via a bundled front-run and back-run) so the fixed protocol-held `_busdAmount` buys an inflated `amounts[1]` of MGP, which is then scaled up further by `bullBonusRatio` and locked to the attacker via `vlMGP.lockFor`.

### Finding Description
`incentiveDeposit` computes `rewardToSend` (busd) deterministically from the attacker's real WOM deposit and tier tables via `getRewardAmount`, independent of any market price [1](#0-0) . When `_bullMode` is true, this busd amount is swapped for MGP through `ROUTER.swapExactTokensForTokens(_busdAmount, _minRec, path, address(this), block.timestamp)`, and the resulting `amounts[1]` directly determines `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR`, which is locked into `vlMGP` on behalf of the caller [2](#0-1) .

The `_minRec` value passed into the router call is the caller-supplied `_minMGPRec` from `incentiveDeposit`, with no protocol-enforced floor (e.g., no on-chain TWAP/oracle sanity check, no minimum-acceptable-rate stored in contract state). By setting `_minMGPRec = 0`, the attacker removes all slippage protection on the swap. The attacker can then bundle (or otherwise arrange, e.g. via a searcher/atomic multi-tx bundle or a manipulable pool with thin liquidity) a trade that depresses the mgp price in the busd/mgp pool immediately before this swap executes, causing the fixed protocol busd amount to purchase an abnormally large amount of MGP, and restore/arbitrage the price afterward. Since `mgpAmountToLcok` scales linearly with `amounts[1]`, the attacker's locked-MGP position becomes inflated well beyond what the busd amount is actually worth at a fair/uncontaminated price — this MGP is drawn from the protocol's own busd reserves via the swap, so the excess minted "reward" is a direct loss of protocol-held value (busd converted at a manipulated rate) captured by the attacker as locked voting/yield power in `vlMGP`.

`whenNotPaused` and `nonReentrant` do not mitigate this since the manipulation happens through legitimate external swaps against the AMM pool, not reentrancy into this contract.

### Impact Explanation
This allows an unprivileged attacker to convert protocol-held busd into an inflated, artificially cheap MGP position locked in `vlMGP`, which grants outsized voting power and future yield entitlement disproportionate to the real economic value contributed. This constitutes theft of protocol-held funds/unclaimed value converted into a locked position, matching the "theft of unclaimed yield" / protocol insolvency impact class.

### Likelihood Explanation
Exploitability depends on the attacker's ability to move the busd/mgp pool price momentarily (e.g., low liquidity pool, or capital to swing price within one block/bundle) and on `_minMGPRec` being settable to 0 by the caller, which the code permits unconditionally. This is repeatable each time the contract holds busd rewards and the pool has exploitable liquidity depth, making it a realistic and repeatable griefing/theft vector rather than a one-off edge case.

### Recommendation
Do not trust caller-supplied `_minMGPRec` as the sole slippage protection for a swap funded by protocol treasury funds. Enforce a protocol-controlled minimum acceptable rate (e.g., derived from a TWAP oracle or a configurable maximum-slippage bound relative to a trusted reference price) inside `_bullMGP`, independent of attacker input, and/or cap `mgpAmountToLcok` growth per transaction/block.

### Proof of Concept
Foundry fork test plan:
1. Deploy/fork `ArbWomUp2` with a real (or mock AMM with price-impact behavior) busd/mgp router pool, funded busd treasury, and `vlMGP`.
2. Attacker acquires WOM and calls `incentiveDeposit(_amount, 0, true)` — set `_minMGPRec = 0`.
3. In the same block/bundle, before this call executes, attacker sells MGP into the pool to depress its price against busd (front-run leg), and after the incentiveDeposit tx, buys MGP back / arbitrages to restore price (back-run leg).
4. Assert that `amounts[1]` returned by the router swap (and thus `mgpAmountToLcok` locked via `vlMGP.lockFor`) is significantly higher than the MGP amount obtainable at the pre-manipulation (fair) price for the same `_busdAmount`.
5. Assert `mgpAmountToLcok / rewardToSend` (mgp received per busd spent) exceeds the value implied by `bullBonusRatio` alone, demonstrating the attacker captured additional value purely from price manipulation rather than the intended bonus.

    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
