### Title
Tab/space indentation ambiguity in `extract_frontmatter`'s hand-rolled YAML parser silently drops condition fields, letting a crafted `.local.md` rule appear to enforce a `block` action while never actually matching - ([File: plugins/hookify/core/config_loader.py -> extract_frontmatter])

### Summary
`extract_frontmatter` classifies lines purely by `indent = len(line) - len(line.lstrip())` compared against hardcoded thresholds (`== 0` for top-level keys, `> 2` for dict-item continuation lines) [1](#0-0) [2](#0-1) . Because tab characters count as 1 column in Python's `len()` regardless of their visual width, a rule file that uses tabs for the nested `field:`/`operator:`/`pattern:` lines under a `- field: ...` list item can produce `indent` values of 1 or 2 that satisfy none of the parser's branches, causing those continuation lines to be silently discarded with no error.

### Finding Description
`extract_frontmatter` builds `Condition` dicts from a `conditions:` YAML-like list using three mutually exclusive branches keyed only on `indent`:
- `indent == 0` → new top-level key [3](#0-2) 
- `stripped.startswith('-')` → new list item (indent-independent) [4](#0-3) 
- `indent > 2 and in_dict_item` → continuation field of the current dict item [2](#0-1) 

There is no `else` clause, so any line that doesn't fall into one of these three buckets is dropped without warning. A rule such as:
```
conditions:
	- field: command
		operator: regex_match
		pattern: rm\s+-rf
```
using a single tab (`indent=1`) for the `-` line and two tabs (`indent=2`) for the continuation lines produces `indent=2` on `operator:`/`pattern:`, which is neither `0` nor `>2`, so both fields are dropped. `Condition.from_dict` then fills in defaults: `operator='regex_match'`, `pattern=''` [5](#0-4) . An empty-string regex pattern matches every input via `re.search('', text)`, so depending on which field ends up dropped, the rule either becomes unconditionally matching (over-broad) or, if the `field:` key itself is the one that lands on a dropped continuation line (e.g. author orders `pattern`/`operator` first and `field` second), `Condition.field` defaults to `''`. At evaluation time `_extract_field('', ...)` matches no known field name and returns `None` [6](#0-5) , `_check_condition` then returns `False` because `field_value is None` [7](#0-6) , and since `_rule_matches` requires every condition in `rule.conditions` to pass [8](#0-7) , the entire `action: block` rule permanently fails to fire — with `enabled: true` and no error ever surfaced to the user.

This is a genuine parser-differential bug: identical logical content, differing only in whitespace character used, yields different `Rule.conditions`, and the divergence is invisible in most editors/diffs (tabs vs. spaces render similarly), making it a realistic vector for smuggling a defanged security rule into a repository's `.claude/hookify.*.local.md` files via a normal-looking PR that a reviewer approves.

### Impact Explanation
This breaks the integrity of hookify's `block`-action rules, which are explicitly documented as the mechanism to "prevent unwanted behaviors" like dangerous `rm -rf` commands or credential leaks [9](#0-8) . An attacker who can get a rule file merged (project contributions are explicitly invited: "Found a useful rule pattern? Consider sharing example files via PR!" [10](#0-9) ) can craft a rule that visually appears to block a dangerous operation but, due to the tab/space parsing bug, never actually matches — silently disabling an intended safety guardrail without any error message, log entry, or `/hookify:list` indication of misconfiguration (the file loads successfully with a non-empty `conditions` list; the failure is purely semantic).

### Likelihood Explanation
Exploitability is limited by the following facts: (1) the attacker still needs their crafted `.local.md` rule file to be added to the target's `.claude/` directory, generally via a merged PR or copy-pasted "example rule" (no code execution or privilege escalation is required — this is a supply-chain/social trust issue), and (2) whether the bug manifests as "over-broad match" (harmless/annoying) versus "silent disable" (security bypass) depends on which field of the YAML dict happens to land on an under-indented continuation line, which is deterministic per file but requires the attacker to test/tune their PoC file locally before submission. Since tabs and spaces are visually similar in most diff viewers/editors, this is a realistic and repeatable review-evasion technique once crafted.

### Recommendation
Rewrite `extract_frontmatter` to normalize tabs to a fixed number of spaces (or reject tabs outright) before computing `indent`, and use relative indentation tracking (e.g., compare against the indent of the enclosing `-` line) rather than hardcoded absolute thresholds of `0`/`2`. Alternatively, replace the hand-rolled parser with Python's standard `yaml.safe_load` (already a common practice for frontmatter), which correctly rejects tab indentation per the YAML spec instead of silently dropping data. Additionally, `Rule.from_dict`/`_rule_matches` should treat a `Condition` with an empty `field` as a load-time validation error (reject/warn) rather than silently defaulting to `''` and failing at runtime.

### Proof of Concept
```python
import textwrap
from plugins.hookify.core.config_loader import extract_frontmatter, Rule

space_doc = textwrap.dedent("""\
---
name: block-rm
enabled: true
event: bash
action: block
conditions:
  - field: command
    operator: regex_match
    pattern: rm\\s+-rf
---
Blocked!
""")

tab_doc = "---\nname: block-rm\nenabled: true\nevent: bash\naction: block\nconditions:\n\t- field: command\n\t\toperator: regex_match\n\t\tpattern: rm\\s+-rf\n---\nBlocked!\n"

fm_space, msg_space = extract_frontmatter(space_doc)
fm_tab, msg_tab = extract_frontmatter(tab_doc)

rule_space = Rule.from_dict(fm_space, msg_space)
rule_tab = Rule.from_dict(fm_tab, msg_tab)

# Differential assertion: identical semantic content must yield identical conditions
assert rule_space.conditions == rule_tab.conditions, (
    f"Parser divergence detected: space={rule_space.conditions} tab={rule_tab.conditions}"
)

# Demonstrate the security bypass: the tab-indented rule never matches a dangerous command
from plugins.hookify.core.rule_engine import RuleEngine
engine = RuleEngine()
result = engine.evaluate_rules([rule_tab], {
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /"}
})
assert result == {}, "Block rule failed to trigger due to tab-indentation parsing bug"
```
Expected: the `assert rule_space.conditions == rule_tab.conditions` fails, demonstrating the parser-differential vulnerability, and the second assertion shows the `block` rule silently fails to fire on the exact dangerous command it was written to catch.

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
