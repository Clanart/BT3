### Title
Malicious signer forces the aggregate nonce `R` to the point at infinity, panicking every honest Bitcoin signing participant - (File: networks/bitcoin/src/crypto.rs)

### Summary
CVE-2024-25177 is a null/edge-case crash in LuaJIT leading to DoS. The reachable analog in Serai's in-scope code is a panic on the point at infinity inside the BIP-340 HRAm helper `x()`/`x_only()`, which a malicious FROST participant can deterministically trigger by choosing preprocess commitments that cancel the aggregate nonce `R` to identity.

### Finding Description
`x()` panics when passed the point at infinity (`expect("point at infinity")`), and `Hram::hram` calls `x(R)` and `x(A)` unconditionally (`networks/bitcoin/src/crypto.rs:13-23, 59-73`).

In `AlgorithmSignMachine::sign`, attacker-supplied preprocesses become entries in the `BindingFactor` map `B` (`crypto/frost/src/sign.rs:347-357`). The binding factors `rho` are computed deterministically from the transcript covering all participants' commitments (`sign.rs:361-379`), and the per-input aggregate nonce is `Rs = B.nonces(&nonces)` (`sign.rs:383`) — a linear combination `Σ_l (D_l + rho_l * E_l)` over *attacker-controlled* commitment points. Because `rho_l` is publicly computable from the full preprocess set before the attacker publishes their own preprocess, an attacker who speaks last can pick their hiding nonce commitment `D_l` to satisfy `D_l = -(Σ_{j≠l}(D_j + rho_j E_j) + rho_l E_l)`, forcing `R` to the identity. `sign_share` then invokes `Hram::hram(R, A, msg)`, which calls `x(R)` and panics, aborting the honest signer's process.

The code even documents this hazard — "`verify`, `verify_share` MUST be called after `sign_share`... this library MAY panic" and "may panic if called with nonces/a group key which are the point at infinity (which have a negligible probability for a well-reasoned caller, even with malicious participants present)" (`crypto.rs:54, 78-83`) — but the probability is not negligible: it is fully adversary-controlled, since the attacker solves for the cancelling commitment after seeing everyone else's preprocesses.

### Impact Explanation
An unprivileged party in the threshold signing set sends a single crafted preprocess (public bytes read via `read_preprocess` / `Commitments::read`) that reliably panics `TransactionSignMachine::sign` → `AlgorithmSignMachine::sign` → `Schnorr::sign_share` → `Hram::hram` → `x(R)`. This crashes the signer — a remote, input-triggered DoS of Bitcoin multisig signing, matching the advisory's DoS bug class. In hosts like the relayer, a task panic is promoted to `std::process::exit` (`networks/ethereum/relayer/src/main.rs:11-19`), amplifying a task crash into a node crash.

### Likelihood Explanation
High within any signing session containing one malicious participant. The attacker needs no secret material: `rho` is derived from the public `FROST_rho` transcript over `group_key`, `hash_msg`, and the `preprocesses` commitment hash (`sign.rs:361-371`), so solving for the cancelling commitment is linear algebra over public values. `Commitments::read` accepts arbitrary `read_G` points with no non-identity check on the aggregate.

### Recommendation
Reject identity aggregate nonces: in `B.nonces`/before `sign_share`, check `R.is_identity()` and return `FrostError::InvalidCommitments(l)` (or re-randomize blame) rather than panicking. Defensively, make `x()`/`x_only()`/`Hram::hram` return `Option`/`io::Result` instead of `expect`ing, and have `verify_share`/`verify` treat an identity `R` as an invalid share so blame can be attributed instead of aborting.

### Proof of Concept
1. Honest signer runs `SignableTransaction::multisig` → `TransactionSignMachine` for a 1-input taproot spend; attacker is another `Participant` in `included`.
2. Honest preprocess is broadcast (commitments `D_h, E_h`). Attacker computes the `FROST_rho` transcript exactly as `sign.rs:361-371` does, obtaining their binding factor `rho_a`.
3. Attacker sets `E_a` to any point and `D_a = -(D_h + rho_h * E_h) - rho_a * E_a`, encodes via `Preprocess::write`, and sends it.
4. Honest node calls `sign()`; `B.nonces` yields `R = identity`; `sign_share` calls `Hram::hram(&R, &A, msg)` → `x(R)` → `expect("point at infinity")` panics (`crypto.rs:15`), aborting signing. [1](#0-0) [2](#0-1) [3](#0-2)
