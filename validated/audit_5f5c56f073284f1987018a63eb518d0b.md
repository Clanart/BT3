### Title
Encrypted DKG shares are not bound to their recipient, enabling cross-recipient replay that frames an honest sender and aborts the DKG - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
CVE-2017-13721 concerns an authenticated party replacing another client's shared-memory segment within the same session. The analog in Serai's PedPoP DKG (`crypto/dkg/pedpop`) is that an `EncryptedMessage` — the per-recipient encrypted secret share — is cryptographically bound to its *sender* and to the DKG *context*, but never to its intended *recipient*. Any party that observes the ciphertext addressed to one participant (they are meant to be distributed over authenticated, not confidential, channels — the code itself notes the DKG "offers no authenticated channel" and relies on an external one, and blame proofs are explicitly designed to be shown to third parties) can replay it to a different participant as that sender's share. The replayed message passes all authentication checks, deterministically decrypts to garbage under the wrong recipient's key, and causes the *honest sender* to be identified as faulty — aborting the key-generation session with incorrect blame attribution.

### Finding Description
`encrypt` produces an `EncryptedMessage { key, pop, msg }` where `pop` is a Schnorr proof-of-possession over `pop_challenge(context, pub_nonce, pub_key, from, msg)`. The challenge transcript commits to `context`, the ephemeral key, the *sender* index, and the ciphertext — but not the recipient `to` [1](#0-0) . The recipient only enters implicitly via `ecdh(key, to)` inside `cipher`, which is never part of the authentication check [2](#0-1) .

On decryption, `Encryption::decrypt` verifies the PoP with `from` taken from the share map key — i.e., the *claimed* sender — so a replayed message still verifies, since the signature genuinely is the sender's [3](#0-2) . Decryption then uses the *victim's own* `enc_key`, yielding garbage [4](#0-3) .

In `blame_internal`, an accusation against the honest sender resolves by calling `decrypt_with_proof(sender, recipient, msg, proof)`: the PoP still verifies (it's the sender's real signature), the recipient's ECDH proof is valid for *their* key, and the message decrypts to either a non-canonical scalar or a scalar failing `share_verification_statements` — in every case `blame_internal` returns `sender` [5](#0-4) . The honest sender is provably "faulty" and the session aborts.

### Impact Explanation
A single unprivileged DKG participant (or any party able to read/re-inject the authenticated share channel, which the library explicitly does not provide) can take any honestly generated encrypted share and deliver it to a different recipient. The result is a deterministic abort of `calculate_share` for that recipient, and — worse — `blame`/`AdditionalBlameMachine` will attribute the fault to the honest *sender*, since the message is authentic and merely mis-delivered. This corrupts the per-session shared state (the share matrix) belonging to other participants, exactly matching the CVE's "replace shared memory segments of other X clients in the same session," and converts a correct participant into a blamed one, which in an accountable DKG deployment can cause honest-party exclusion/slashing-equivalent consequences and prevents key generation from completing.

### Likelihood Explanation
Reachability requires only that the attacker observe one encrypted share not addressed to them and inject it into another participant's share map — inputs that flow through `EncryptedMessage::read` and `calculate_share`/`blame` [6](#0-5) . Since blame proofs are designed to be evaluated by non-participants (`AdditionalBlameMachine::new` takes only the commitment messages), the share ciphertexts are not confidentiality-protected artifacts of the protocol. No threshold collusion, no key compromise, and no broken transcript assumption is required — only a missing field in the PoP challenge.

### Recommendation
Bind the intended recipient into the per-message authentication: append `to` (the recipient `Participant` index or their registered `enc_key`) in `pop_challenge`, and pass the recipient through `encrypt`/`decrypt`/`decrypt_with_proof` so a share is only authentic for the `(sender, recipient)` pair it was created for. This also hardens `blame_internal` against adjudicating replayed messages.

### Proof of Concept
1. Honest sender `s` runs `generate_secret_shares`, producing `msg_b = EncryptedMessage` addressed to participant `b` (ECDH against `b`'s registered `enc_key`).
2. Attacker `c` (or an eavesdropping relay) obtains `msg_b`'s serialization and delivers it to participant `r ≠ b` as `s`'s share to `r`.
3. `r`'s `calculate_share` calls `self.encryption.decrypt(..., from = s, msg_b)`: `msg_b.pop` verifies because `pop_challenge` uses `s` and the unmodified ciphertext — the recipient is never checked [3](#0-2) . Decryption under `r`'s `enc_key` yields garbage; `from_repr` fails or `share_verification_statements` fails → `PedPoPError::InvalidShare { participant: s }`.
4. Blame adjudication via `blame_internal(s, r, msg_b, r's proof)`: PoP passes, `r`'s DLEq proof verifies, decryption yields an invalid/non-canonical share → returns `s`. Honest `s` is blamed and the session aborts, despite `s` having behaved correctly [7](#0-6) .

fn encrypt<R: RngCore + CryptoRng, C: Ciphersuite, E: Encryptable>(
  rng: &mut R,
  context: [u8; 32],
  from: Participant,
  to: C::G,
  mut msg: Zeroizing<E>,
) -> EncryptedMessage<C, E> {
  /*
  The following code could be used to replace the requirement on an RNG here.
  It's just currently not an issue to require taking in an RNG here.
  let last = self.last_enc_key.to_bytes();
  self.last_enc_key = C::hash_to_F(b"encryption_base", last.as_ref());
  let key = C::hash_to_F(b"encryption_key", last.as_ref());
  last.as_mut().zeroize();
  */

  // Generate a new key for this message, satisfying cipher's requirement of distinct keys per
  // message, and enabling revealing this message without revealing any others
  let key = Zeroizing::new(C::random_nonzero_F(rng));
  cipher::<C>(context, &ecdh::<C>(&key, to)).apply_keystream(msg.as_mut().as_mut());

  let pub_key = C::generator() * key.deref();
  let nonce = Zeroizing::new(C::random_nonzero_F(rng));
  let pub_nonce = C::generator() * nonce.deref();
  EncryptedMessage {
    key: pub_key,
    pop: SchnorrSignature::sign(
      &key,
      nonce,
      pop_challenge::<C>(context, pub_nonce, pub_key, from, msg.deref().as_ref()),
    ),
    msg,
  }
}

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}

  pub fn calculate_share<R: RngCore + CryptoRng>(
    mut self,
    rng: &mut R,
    mut shares: HashMap<Participant, EncryptedMessage<C, SecretShare<C::F>>>,
  ) -> Result<BlameMachine<C>, PedPoPError<C>> {
    validate_map(
      &shares,
      &self.params.all_participant_indexes().collect::<Vec<_>>(),
      self.params.i(),
    )?;

    let mut batch = BatchVerifier::new(shares.len());
    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {
      let (mut share_bytes, blame) =
        self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
      let share =
        Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0)).ok_or_else(|| {
          PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }
        })?);
      share_bytes.zeroize();
      *self.secret += share.deref();

      blames.insert(l, blame);
      batch.queue(
        rng,
        BatchId::Share(l),
        share_verification_statements::<C>(self.params.i(), &self.commitments[&l], share),
      );
    }
    batch.verify_with_vartime_blame().map_err(|id| {
      let (l, blame) = match id {
        BatchId::Decryption(l) => (l, None),
        BatchId::Share(l) => (l, Some(blames.remove(&l).unwrap())),
      };
      PedPoPError::InvalidShare { participant: l, blame }
    })?;
