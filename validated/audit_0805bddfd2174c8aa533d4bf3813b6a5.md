### Title
Asymmetric recursion-depth accounting on parse failure permanently leaks `CodedInputStream` recursion budget - (File: `src/google/protobuf/wire_format_lite.h`)

### Summary
`CodedInputStream::IncrementRecursionDepth()`/`DecrementRecursionDepth()` maintain a per-instance `recursion_budget_` counter that gates how deeply nested groups/messages may be parsed [1](#0-0) . Several call sites decrement this counter before attempting a nested parse but only restore it on the success path, so any failed inner parse (not just a recursion-limit hit) leaves the budget permanently reduced for the lifetime of that `CodedInputStream` object, mirroring the Rio report's pattern of a state counter that is consumed but never restored, blocking future legitimate operations that depend on it.

### Finding Description
`WireFormatLite::ReadGroup` and `ReadMessage` (used by generated proto2 group/message fields) follow this pattern:
```cpp
if (!input->IncrementRecursionDepth()) return false;
if (!value->MergePartialFromCodedStream(input)) return false;
input->UnsafeDecrementRecursionDepth();
``` [2](#0-1) 

The matching decrement (`UnsafeDecrementRecursionDepth`/`DecrementRecursionDepth`) is only reached when the inner parse succeeds. If `MergePartialFromCodedStream` fails for *any* reason — a truncated field, an unknown wiretype, a bad UTF-8 string, or the recursion limit itself being hit one level deeper — the function returns `false` while `recursion_budget_` remains decremented. The same asymmetric pattern appears in the unknown-field skip path:
```cpp
case WireFormatLite::WIRETYPE_START_GROUP: {
  if (!input->IncrementRecursionDepth()) return false;
  if (!SkipMessage(input)) return false;
  input->DecrementRecursionDepth();
  ...
}
``` [3](#0-2) [4](#0-3) 

`DecrementRecursionDepth()`/`UnsafeDecrementRecursionDepth()` never runs on the failure path, so `recursion_budget_` is not restored to its pre-call value; the invariant that increments and decrements are balanced across a full parse attempt is broken whenever a single nested field fails, not just when the true recursion limit is exceeded.

**External invariant that transfers:** the Rio report shows a counter (`currentEpochsByAsset`) that must be incremented after a state-changing operation to allow future operations to proceed; failing to restore it after the operation permanently blocks subsequent legitimate use. Here, `recursion_budget_` is the analogous counter: it must be restored after every parse attempt (success or failure) to allow subsequent parses on the same object to use the full recursion depth; the increment/decrement pairing is broken on the failure path.

**Why existing checks don't catch it:** `IncrementRecursionDepth()` simply decrements and range-checks; there is no `finally`/RAII guard ensuring the compensating decrement runs regardless of outcome, unlike `google::protobuf::internal::ParseContext`, where `depth_`/`group_depth_` are restored via explicit post-conditions and `ABSL_DCHECK_EQ` (debug-only) checks after `_InternalParse` [5](#0-4) . The legacy `CodedInputStream` path used by `WireFormatLite`/`WireFormat` (proto2 reflection-based and generated legacy parsers) has no such invariant-restoring mechanism and no DCHECK to surface the leak even in debug builds.

### Impact Explanation
The impact is confined to correctness/availability of subsequent parses that reuse the same `CodedInputStream` instance, not memory safety. **Consuming-application exposure assumption:** this only manifests when application code holds one `CodedInputStream` open across multiple independent parse attempts and continues using it after a parse failure (a supported, common pattern for parsing streams of length-delimited messages, e.g. via `google::protobuf::util::ParseDelimitedFromCodedStream`-style loops that treat one malformed record as "skip and continue"). In that scenario, an ordinary client can send one or more bounded, malformed length-delimited/group-typed sub-messages; each failure permanently consumes one unit of `recursion_budget_`. After enough failed attempts (bounded by the default recursion limit of 100), `recursion_budget_` reaches zero/negative, and all subsequent — otherwise entirely valid — messages on that same stream that contain any nested message/group field will spuriously fail to parse, i.e. legitimate later inputs are permanently rejected until the stream object is discarded and recreated. This is a persistent-state availability bug analogous to the Rio finding (permanently stuck state blocking legitimate future operations), not a crash or memory-corruption issue.

### Likelihood Explanation
High in exposure but conditional on application usage pattern: any client sending one bounded, syntactically malformed nested message/group field over a supported binary-parsing API can trigger the leak; no privileged access or crafted schema is required, and inputs are small and bounded (a single malformed varint or truncated field inside a group is sufficient). The observable failure only surfaces for applications that keep a `CodedInputStream` alive across multiple parse attempts and swallow individual failures — this narrows real-world likelihood versus a single top-level `ParseFromString`/`ParseFromCodedStream` call whose `CodedInputStream` is discarded immediately after failure (the overwhelmingly common usage), in which case the leaked budget is inconsequential.

### Recommendation
Wrap the increment/parse/decrement sequences in `WireFormatLite::ReadGroup`, `WireFormatLite::ReadMessage`, `WireFormatLite::SkipField`, and `WireFormat::SkipField` in an RAII guard (or explicit `absl::Cleanup`) that unconditionally calls `DecrementRecursionDepth()` regardless of whether the inner parse succeeds, matching the restore-on-all-paths behavior already used for `ParseContext::depth_`/`group_depth_` in `parse_context.h`. Add a debug-mode invariant check (e.g. `ABSL_DCHECK_EQ`) asserting `recursion_budget_` is restored to its pre-call value after each `ReadGroup`/`SkipField` call, whether it returns success or failure.

### Proof of Concept
1. Construct a single `io::CodedInputStream` over a `ZeroCopyInputStream` supplied by an application that repeatedly calls it to parse a sequence of independent length-delimited messages (the documented delimited-message pattern), continuing to the next message when one parse call returns `false`.
2. Feed message N containing a field with wiretype `WIRETYPE_START_GROUP` whose payload is deliberately truncated (missing the matching end-group tag or containing a malformed inner varint), causing `WireFormatLite::ReadGroup`/`WireFormat::SkipField` to hit `IncrementRecursionDepth()` then fail inside the inner parse/skip, returning `false` without the compensating `DecrementRecursionDepth()`.
3. Observe (by instrumenting/inspecting `recursion_budget_`, which is not otherwise exposed publicly) that it is one less than before message N was parsed, even though message N's parse "cleanly" failed and the stream continues to message N+1.
4. Repeat step 2 up to `default_recursion_limit_` (100) times; after the budget is exhausted, feed a subsequent, fully well-formed message containing legitimately nested (but shallow, e.g. depth 1) groups/messages on the same stream and observe `IncrementRecursionDepth()` returning `false` for that legitimate message, causing an otherwise-valid client message to be spuriously rejected.
This reproduction requires only bounded, client-suppliable binary protobuf input and an application that reuses one `CodedInputStream` across multiple parse attempts, consistent with the stated exposure assumption; I was not able to execute this against a live build in this environment, so the sequence above is a manual code-path trace based on [6](#0-5)  and [3](#0-2)  rather than an executed test.

inline bool CodedInputStream::IncrementRecursionDepth() {
  --recursion_budget_;
  return recursion_budget_ >= 0;
}

inline void CodedInputStream::DecrementRecursionDepth() {
  if (recursion_budget_ < recursion_limit_) ++recursion_budget_;
}

inline void CodedInputStream::UnsafeDecrementRecursionDepth() {
  assert(recursion_budget_ < recursion_limit_);
  ++recursion_budget_;
}

template <typename MessageType>
inline bool WireFormatLite::ReadGroup(int field_number,
                                      io::CodedInputStream* input,
                                      MessageType* value) {
  if (!input->IncrementRecursionDepth()) return false;
  if (!value->MergePartialFromCodedStream(input)) return false;
  input->UnsafeDecrementRecursionDepth();
  // Make sure the last thing read was an end tag for this group.
  if (!input->LastTagWas(MakeTag(field_number, WIRETYPE_END_GROUP))) {
    return false;
  }
  return true;
}
template <typename MessageType>
inline bool WireFormatLite::ReadMessage(io::CodedInputStream* input,
                                        MessageType* value) {
  int length;
  if (!input->ReadVarintSizeAsInt(&length)) return false;
  std::pair<io::CodedInputStream::Limit, int> p =
      input->IncrementRecursionDepthAndPushLimit(length);
  if (p.second < 0 || !value->MergePartialFromCodedStream(input)) return false;
  // Make sure that parsing stopped when the limit was hit, not at an endgroup
  // tag.
  return input->DecrementRecursionDepthAndPopLimit(p.first);

    if (--depth_ < 0) return nullptr;
    group_depth_++;
    auto old_depth = depth_;
    auto old_group_depth = group_depth_;
    ptr = msg->_InternalParse(ptr, this);
    if (ptr != nullptr) {
      ABSL_DCHECK_EQ(old_depth, depth_);
      ABSL_DCHECK_EQ(old_group_depth, group_depth_);

    group_depth_--;
    depth_++;
