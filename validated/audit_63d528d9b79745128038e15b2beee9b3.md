### Title
Ed448 torsion points are accepted as prime-group elements, enabling Schnorr signature forgeries - (File: crypto/ed448/src/point.rs)

### Summary
Ed448 point decoding attempts to reject non-prime-order points, but `Point::is_torsion_free` evaluates `(-P) + P`, which is identity for every point and therefore performs no torsion check. [1](#0-0)  Canonical scalar and point decoding then expose the malformed point through `Ciphersuite::read_G`, allowing it to be used as a public key, nonce, commitment, or proof element. [2](#0-1)  This breaks the `PrimeGroup` invariant relied on by `SchnorrSignature::verify`, whose equation is `R + cA - sG == 0`. [3](#0-2) 

### Finding Description
The decoding path correctly recovers `x`, rejects negative zero, and then calls `point.is_torsion_free()` to decide whether the decoded Ed448 point is valid. [4](#0-3)  However, `is_torsion_free` multiplies the point by `-1` and adds the original point, producing identity unconditionally. [5](#0-4) 

As a result, Ed448's order-two and order-four points deserialize successfully even though `Ciphersuite::G` is required to be a `PrimeGroup`. [6](#0-5)  `SchnorrSignature::read` also places no additional subgroup restriction on `R`, so untrusted signature bytes can carry a torsion nonce. [7](#0-6) 

For an order-two public key `A = T`, an attacker can submit `R = T` and `s = 0`; verification succeeds whenever the challenge `c` is odd because `R + cA - sG = (c + 1)T = identity`. [3](#0-2)  The attacker only has to vary the message or challenge transcript until the challenge is odd, which succeeds with probability `1/2`. [8](#0-7) 

### Impact Explanation
A remote party can forge a Schnorr signature under a malformed Ed448 public key without knowing a discrete logarithm or private key. [4](#0-3)  The same malformed encodings can enter PedPoP commitment messages and FROST preprocessing because those APIs deserialize group elements supplied by other participants. [9](#0-8) [10](#0-9)  These low-order components invalidate the verifier's assumption that all group operations occur in the prime-order subgroup. [6](#0-5) 

### Likelihood Explanation
The malicious input is a fixed byte encoding that can be generated publicly, and no validator privileges, leaked secrets, collusion, or network-control assumptions are required. [2](#0-1)  The order-two forgery requires only an odd Fiat-Shamir challenge, giving a practical one-in-two success condition when the attacker can choose or vary the signed message. [3](#0-2) 

### Recommendation
Replace `Point::is_torsion_free` with a real subgroup-membership check, such as verifying multiplication by the prime group order returns identity while keeping the protocol-level identity rejection. [5](#0-4)  Add regression vectors proving that all nonidentity low-order Ed448 encodings, including the order-two point `(0, -1)`, are rejected by `Ed448::read_G`, `SchnorrSignature::read`, DLEq decoding, PedPoP commitments, and FROST preprocess decoding. [2](#0-1) [9](#0-8) [10](#0-9) 

### Proof of Concept
A crate-local Ed448 test can construct the order-two point `(0, -1)`, serialize it, and show that the public decoder accepts it:

```rust
// crypto/ed448/src/point.rs test context
let torsion_bytes = Point {
  x: FieldElement::ZERO,
  y: -FieldElement::ONE,
  z: FieldElement::ONE,
}.to_bytes();

let torsion =
  <Ed448 as Ciphersuite>::read_G(&mut torsion_bytes.as_ref()).unwrap();
assert!(!bool::from(torsion.is_identity()));
```

The accepted torsion point can then be used in the Schnorr verifier as both `A` and `R`; `s = 0` verifies whenever the challenge is odd:

```rust
let sig = SchnorrSignature::<Ed448> {
  R: torsion,
  s: <Ed448 as Ciphersuite>::F::ZERO,
};

for counter in 0u64.. {
  let challenge = Ed448::hash_to_F(
    b"forgery challenge",
    &[torsion_bytes.as_ref(), torsion_bytes.as_ref(), &counter.to_le_bytes()].concat(),
  );

  if bool::from(challenge.is_odd()) {
    assert!(sig.verify(torsion, challenge));
    break;
  }
}
```

This reaches a forged verification result through public bytes supplied to `read_G`/`SchnorrSignature::read`, with the root cause located at `crypto/ed448/src/point.rs`. [1](#0-0)
