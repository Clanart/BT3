### Title
Unauthenticated SSRF via arbitrary DataLayer mirror URLs fetched by other nodes - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can create a DataLayer "mirror" coin that advertises arbitrary URLs for *any* existing store/launcher_id — including one they do not own — because mirror creation only encodes `launcher_id` and `urls` as coin memos with no proof of ownership or relationship to that singleton. Other participants who subscribe to that `store_id` treat these attacker-supplied URLs as legitimate mirror servers and have their DataLayer service issue outbound HTTP requests to them, with no validation of scheme/host/IP range, analogous to the Zimbra RSS-parser SSRF (CVE-2025-25065).

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a plain coin spend whose only DataLayer-specific content is memos `[launcher_id, *urls]` attached to a coin sent to the mirror puzzle hash: [1](#0-0) 

There is no check that the spending wallet owns, controls, or has any relationship to `launcher_id` — it is simply data supplied by the caller. When the resulting coin is seen on chain, `DataLayerWallet.coin_added()` decodes `launcher_id, urls` from the spend and, as long as the `launcher_id` is *any* store being tracked locally (`is_launcher_tracked`), stores the mirror in the DL wallet DB: [2](#0-1) 

The DataLayer service later reads back *all* mirrors for a store id (not filtered to ones created by the store owner) and uses their URLs to seed the subscription/download server list: [3](#0-2) 

When syncing a store, `fetch_and_validate()` picks a server URL from this attacker-controllable list and downloads a delta file over `aiohttp` with no scheme/host allow-listing, no restriction against internal/loopback/link-local addresses: [4](#0-3) [5](#0-4) 

The `is_filename_valid()` check only validates the *filename* structure, not the URL/host being contacted: [6](#0-5) 

The project's own module notes acknowledge mirror/plugin URLs as external, untrusted input for data content, but do not address that the request destination itself (not just the payload) is attacker controlled:


### Impact Explanation
An unprivileged wallet/DataLayer participant can force any other DataLayer node that subscribes to a given `store_id` to make outbound HTTP GET requests to attacker-chosen destinations (e.g., internal admin panels, cloud metadata endpoints such as `169.254.169.254`, other services bound to `localhost`/private IPs on the victim host). This is a server-side request forgery: it can be used for internal network reconnaissance/port scanning, hitting internal-only HTTP APIs, or triggering side effects on internal services reachable from the DataLayer host — matching the impact class of the Zimbra advisory (unauthorized redirection to internal network endpoints). It does not directly grant coin/asset control, but it is a concrete network-reachable SSRF primitive driven by unauthenticated on-chain data.

### Likelihood Explanation
Likelihood is moderate: the attacker only needs to spend a low-value coin to the mirror puzzle with arbitrary memos naming any target `launcher_id` and any URL list, then wait for a victim node that already tracks/subscribes to that store to run its periodic `update_subscription()`/`fetch_and_validate()` cycle. No signature or permission over the target singleton is required, and mirror creation is a normal, permitted wallet operation exposed via RPC/CLI (`dl_new_mirror`, `add_mirror`).

### Recommendation
- When compiling subscription URLs from `dl_get_mirrors`, only trust mirrors flagged `ours` or otherwise cryptographically tied to the store owner/singleton, or explicitly warn/require user confirmation before adding third-party mirror URLs to the download server list.
- Before issuing outbound requests in `http_download()`/`get_downloader()`, validate the resolved host against a blocklist of private/loopback/link-local ranges (SSRF protection), and restrict schemes to `http`/`https` explicitly.
- Consider requiring an allow-list or per-store opt-in for external mirror URLs rather than auto-trusting any mirror coin associated with a tracked launcher id.

### Proof of Concept
1. Attacker runs `chia data add_mirror -id <victim_store_id> -u http://169.254.169.254/latest/meta-data/ -a 1` (or calls `dl_new_mirror` RPC directly) for a `store_id` they do not own, using the DataLayer wallet's normal add-mirror flow (`chia/data_layer/data_layer.py:965`, `chia/cmds/data_funcs.py:270`).
2. The resulting mirror coin is confirmed on chain; any node tracking `victim_store_id` records it via `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775`).
3. On its next `update_subscription()`/`fetch_and_validate()` cycle, the victim node calls `update_subscriptions_from_wallet()`, which merges the attacker's URL into `data_store` subscription servers (`chia/data_layer/data_layer.py:979`).
4. `fetch_and_validate()` selects this server and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim process to perform `GET http://169.254.169.254/latest/meta-data/...` (`chia/data_layer/download_data.py:298`), an SSRF request to an internal/cloud-metadata endpoint chosen entirely by the attacker.

def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
