I found a direct structural analog to the Burve bug in `evm/src/utils/CallDispatcher.sol`. This shared "call dispatcher" contract is used by multiple Hyperbridge bridge apps (`IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken`, etc.) to execute solver/attached calldata, and it has exactly the same unrestricted-function pattern as the reported Burve callback.

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain funds transiently held by the shared dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch(bytes memory encoded)` is a fully public, unauthenticated function that decodes an attacker-supplied `Call[]` array and executes `to.call{value: call.value}(call.data)` for each entry using the `CallDispatcher` contract's own balance and identity as `msg.sender`. There is no `onlyOwner`/`onlyCaller`/`onlyGateway` restriction whatsoever, exactly matching the Burve `uniswapV3MintCallback` bug class: an external, unrestricted function that moves value held by/associated with the contract to an address decoded from caller-supplied `data`. [1](#0-0) 

### Finding Description
`CallDispatcher` is a shared singleton referenced by protocol config (`_params.dispatcher` in `IntentGatewayV2`, `_dispatcher` in `HyperFungibleToken`/`WrappedHyperFungibleToken`), and is designed to transiently hold user/protocol funds during order execution:

- `IntentGatewayV2._fillOrder` pushes native ETH and ERC20 `predispatch.assets` directly to `dispatcher` *before* invoking `dispatch()`: [2](#0-1) 

- The subsequent sweep-back step trusts `dispatcher`'s *entire current balance* (`balanceOf(dispatcher)`/`address(dispatcher).balance`), not a tracked delta, and routes any surplus into a `DustCollected` accounting bucket rather than verifying provenance: [3](#0-2) 

- `CallDispatcher` also has an unrestricted `receive()` that accepts ETH from anyone: [4](#0-3) 

Because `dispatch()` has no caller restriction, any address — not just the trusted `IntentGatewayV2`/token-bridge contract that is supposed to own the transient balance for the duration of one atomic fill — can call `CallDispatcher.dispatch()` directly with a `Call[]` such as `{to: attacker, value: address(dispatcher).balance, data: ""}` (for native ETH) or an ERC20 `transfer` call moving out any token balance currently sitting in the contract. Since the sweep logic elsewhere in the protocol already relies on "whatever is in `dispatcher`'s balance belongs to the in-flight order," any residual balance — dust from partial predispatch execution, ETH sent via the unrestricted `receive()`, or tokens transferred in by a not-yet-completed fill — is fair game for anyone to redirect to themselves before the legitimate protocol-owned sweep call executes.

### Impact Explanation
This directly threatens escrowed/transient bridge funds: token or native-ETH balances that legitimately belong to an order filler or the protocol (dust destined for `_params.beneficiary`) can be redirected to an attacker with a single unauthenticated call, causing direct loss of funds — the same "High/High" impact class as the source report.

### Likelihood Explanation
No privileged role, relayer, prover, or governance actor is needed; any externally-owned account can call `CallDispatcher.dispatch()` at will and race a pending `_fillOrder`/`onAccept` transaction that is known to push funds into the dispatcher before making its own `dispatch()` call, or simply sweep any ETH sitting in the contract from its unrestricted `receive()`.

### Recommendation
Restrict `CallDispatcher.dispatch()` to only be callable by the specific, pre-registered protocol contract(s) that are expected to own funds in it during a call (e.g., an `onlyOwner`/`onlyAuthorizedCaller` check set at construction, or by making `CallDispatcher` a non-shared, per-caller instance), and avoid trusting `balanceOf(dispatcher)`/`address(dispatcher).balance` deltas for sweep accounting instead of exact tracked amounts.

### Proof of Concept
1. `IntentGatewayV2._fillOrder` sends `order.predispatch.assets` (native ETH or ERC20) to the shared `dispatcher` address, then calls `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)`.
2. Before/around this step, an attacker calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: address(dispatcher).balance, data: ""})]))` directly (no access control check exists).
3. The `CallDispatcher` forwards its full balance to the attacker.
4. `IntentGatewayV2`'s subsequent balance-based sweep for `order.inputs` (`balanceOf(dispatcher)`/`balance < requiredAmount`) now reverts or under-collects, and any funds the attacker pulled out are permanently lost to the legitimate order/protocol. [5](#0-4) [6](#0-5)

/**
 * @title The CallDispatcher
 * @author Polytope Labs (hello@polytope.technology)
 *
 * @notice This contract is used to dispatch calls to other contracts.
 */
contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
}
