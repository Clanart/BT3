## Title
Native-token overpayment in `EvmHost.dispatch()` is permanently trapped in the host instead of being refunded to the caller - (File: `evm/src/core/EvmHost.sol`)

## Summary
This is a structural analog of the reported TapiocaOFT bug: a function forwards the caller's `msg.value` into a downstream swap call whose "refund" mechanism sends unspent value to the wrong party. In TapiocaOFT, the refund escaped to an attacker-controlled `refundAddress`; here it escapes to `address(this)` of `EvmHost` itself (i.e. the protocol contract), because `EvmHost` — not the original transaction sender — is the immediate caller of the swap.

## Finding Description
`EvmHost.dispatch(DispatchPost)` and `EvmHost.dispatch(DispatchGet)` accept native token payment and swap it for the exact `feeToken` amount needed via `swapETHForExactTokens`: [1](#0-0) 

`swapETHForExactTokens` is an exact-output swap: the caller supplies `msg.value` as an upper bound and is refunded any unspent ETH. Whether the configured `_hostParams.uniswapV2` router is the real Uniswap V2 router or the project's own `UniV4UniswapV2Wrapper`, the refund of unspent ETH is sent to `msg.sender` of that call: [2](#0-1) 

Because `EvmHost` itself is the direct caller of `swapETHForExactTokens` (the end user only calls `EvmHost.dispatch`), `msg.sender` inside the router/wrapper resolves to `EvmHost`'s own address, not the end user's address. The refunded ETH therefore lands back in `EvmHost`'s balance rather than being returned to the actual payer. `EvmHost.dispatch()` never checks for or forwards any leftover value back to `_msgSender()` after the swap call returns — there is no refund step at all in the function body.

This mirrors the core broken invariant from the external report: value that should return to the payer of a cross-call instead flows to a party that is not the rightful beneficiary, purely because of who is the immediate caller in the call chain.

## Impact Explanation
Any user who dispatches a POST or GET request paying with native token via `msg.value` and slightly overestimates the amount needed to cover `post.fee`/`get.fee` (which is normal and expected, since exact swap output pricing is unknown to the caller ahead of time due to slippage/price movement) permanently loses the difference — it becomes stuck inside `EvmHost`, unrecoverable by the caller. This is a direct, protocol-level loss of user funds on every affected dispatch call, not a one-off edge case.

## Likelihood Explanation
This triggers on the ordinary, unprivileged, public entrypoints `dispatch(DispatchPost)` and `dispatch(DispatchGet)` whenever `msg.value` exceeds the exact amount consumed by the swap — which is the normal case since callers cannot know the router's exact required input in advance and must pad `msg.value` to avoid reverts. No malicious relayer, prover, or admin is required; a single unprivileged caller triggers the loss on their own transaction.

## Recommendation
After the `swapETHForExactTokens` call in both `dispatch(DispatchPost)` and `dispatch(DispatchGet)`, compute the leftover `address(this).balance` delta (or capture the router's returned `amounts[0]`) and forward the unspent `msg.value - amounts[0]` back to `_msgSender()` before returning from `dispatch()`.

## Proof of Concept
1. Configure `EvmHost` with `_hostParams.uniswapV2` pointing to `UniV4UniswapV2Wrapper` (or a standard UniswapV2Router02).
2. User calls `EvmHost.dispatch{value: X}(DispatchPost{..., fee: F, ...})` where `X > requiredInput` for swapping to `F` fee tokens (e.g. user pads for slippage).
3. Inside `dispatch`, `IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: X}(F, path, address(this), block.timestamp)` executes; the router/wrapper computes `requiredInput < X`, refunds `X - requiredInput` to `msg.sender`, which is `EvmHost`.
4. `EvmHost`'s ETH balance increases by `X - requiredInput`; the user receives nothing back and `dispatch()` returns normally with no revert.
5. Repeating step 2 across many users/calls causes systemic native-token loss that accumulates inside `EvmHost`, with no code path returning it to payers.
