### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over every transaction in a block — including `txdata[0]`, the coinbase — via `scan_transaction`, which matches solely on `script_pubkey`. Coinbase outputs are bound by a 100-block maturity rule, so any output the scanner returns from the coinbase is reported to the caller as a received, spendable `ReceivedOutput` even though the Bitcoin network will reject any transaction spending it. This is the Serai analog of the aptdaemon flaw: untrusted, attacker-controlled block data is consumed without validating a protocol-critical property (coinbase maturity), producing a trusted-looking result (`ReceivedOutput`) that encodes a false claim.

### Finding Description
`scan_transaction` matches `output.script_pubkey` against registered scripts and emits a `ReceivedOutput` with no other checks [1](#0-0) . `scan_block` then feeds it `block.txdata` unfiltered, i.e. including the coinbase transaction at index 0 [2](#0-1) . Nothing in `ReceivedOutput`, `scan_transaction`, or `scan_block` records that the outpoint belongs to a coinbase input (coinbase inputs have a null prevout, `txid == 0, vout == 0xFFFFFFFF`) or is maturity-bound. Contrast with `ReceivedOutput::read`/`write`, which serialize the outpoint verbatim — there is no field or flag distinguishing an immature coinbase output from a normal one [3](#0-2) . The only mitigation is a doc comment telling callers to do "a post-processing pass" or scan `block.txdata[1 ..]` themselves [4](#0-3)  — the safe behavior is opt-out, not enforced. Notably, Serai's own processor had to special-case this exact hazard by manually skipping `block.txdata[1 ..]`'s coinbase when consuming scanned outputs [5](#0-4) , demonstrating the default API is unsafe for in-tree consumers.

### Impact Explanation
Any miner (or mining pool) can include a payout to a Serai wallet's registered script_pubkey in a coinbase transaction. `scan_block` then reports those funds as received with a normal `ReceivedOutput` indistinguishable from a spendable UTXO. A wallet or downstream consumer that trusts the result will (a) inflate the reported balance for ~100 blocks, and (b) construct and attempt to sign/broadcast a `SignableTransaction` spending an immature coinbase outpoint, which every node rejects — wasting signing rounds in the FROST multisig flow and enabling repeated griefing whenever the miner wins a block. This matches the accepted impact class "funds reported received that are not spendable."

### Likelihood Explanation
Triggering requires a coinbase output paying to the wallet's script, which means the attacker must control block production — feasible for miners/pools but not for arbitrary users. The impact is bounded to false balance reporting and failed spends rather than key compromise, so Medium is appropriate.

### Recommendation
In `Scanner::scan_block` (networks/bitcoin/src/wallet/mod.rs), skip `block.txdata[0]` or check `tx.is_coinbase()`/`tx.input[0].previous_output.is_null()` per transaction before scanning, so `ReceivedOutput` is only ever produced for mature outputs. Alternatively, record coinbase provenance on `ReceivedOutput` and enforce a confirmation/maturity check before it can be used as a `SignableTransaction` input.

### Proof of Concept
```rust
// Given a Scanner for an even key `key`, a miner crafts a block whose
// coinbase tx pays to p2tr_script_buf(key) at output index 0.

// BUG: outputs[0] is a ReceivedOutput for the coinbase outpoint, reported as
// spendable even though spending it violates consensus for 100 blocks.

// Any SignableTransaction built from outputs[0] is unbroadcastable.
```

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
