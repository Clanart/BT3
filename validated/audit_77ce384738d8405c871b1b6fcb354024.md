Confirmed: `RunAndCalculateGas` in `precompiles/common/precompiles.go` (the dynamic-gas precompile wrapper used by the pointer precompile) has no `recover()` around the call to `d.executor.Execute(...)`. Only `chargeDecodeGas` has a narrowly-scoped recover for gas-meter panics; anything else, including a type-assertion panic, propagates unrecovered through `RunAndCalculateGas` and up through the EVM interpreter into the node process.

### Title
Unrecovered panic in the `pointer` precompile's CW20/CW721/CW1155 registration via untrusted contract response causes node crash - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile at address `0x100b` exposes `addCW20Pointer`, `addCW721Pointer`, and `addCW1155Pointer`, which query an attacker-supplied CosmWasm contract address for `token_info`/`contract_info` and then perform unchecked type assertions on the JSON response fields `name` and `symbol`.

### Finding Description
`AddCW20`, `AddCW721`, and `AddCW1155` in [1](#0-0)  take a caller-supplied CosmWasm contract address, call `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))`, unmarshal the arbitrary JSON response into `map[string]interface{}{}`, and then execute `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` without the comma-ok form: [2](#0-1) . The same unchecked pattern repeats for `AddCW721` [3](#0-2)  and `AddCW1155` [4](#0-3) .

If the target CW contract is malicious (attacker deploys their own contract and points the pointer registration at it) and returns a `token_info`/`contract_info` response where `"name"` or `"symbol"` is absent (so the map value is `nil`) or is not a JSON string (e.g. a number, object, or array), the Go type assertion panics with `interface conversion: interface {} is <nil or wrong type>, not string`.

Unlike sibling precompiles (`addr`, `oracle`, `distribution`, `solo`), which wrap `Execute` in a `defer recover()` specifically to "catch gas meter panics" (and incidentally catch any other panic), the `pointer` precompile's `Execute` has no such guard [5](#0-4) . The dispatch wrapper `RunAndCalculateGas` in `precompiles/common/precompiles.go` also does not recover generic panics from `d.executor.Execute` — its only `recover()` is scoped narrowly to `chargeDecodeGas` for gas-meter/out-of-gas panics, and explicitly re-panics anything else: [6](#0-5) . Consequently a type-assertion panic from `AddCW20`/`AddCW721`/`AddCW1155` propagates unrecovered through the precompile dispatch and into the EVM interpreter's precompile call path, crashing the validator/RPC node process handling that transaction (or block, at `DeliverTx` time).

### Impact Explanation
This is directly analogous to CVE-2018-20190's class of bug: a crafted, attacker-controlled input (there, a `.scss` file; here, a CosmWasm smart-query JSON response) triggers a nil/type dereference that the calling code fails to guard against, causing a crash. Here the reachable path is worse because it is triggerable on-chain by any EVM transaction sender who (1) deploys or reuses a minimal CW contract that answers `token_info`/`contract_info` with a manipulated shape, and (2) calls `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on precompile `0x100b` pointing at that contract. A successful trigger during `DeliverTx` crashes the node processing the block, which — if it affects multiple validators identically (deterministic execution) — can halt block production entirely, satisfying the "validator halt" / "crash of default-configuration nodes" impact bar.

### Likelihood Explanation
Likelihood is high: deploying a CosmWasm contract with a crafted `token_info` query handler is trivial and requires no special privileges (only the normal CW upload/instantiate flow, or use of an existing pointer-caller-reachable CW contract), and calling the `pointer` precompile is a plain, permissionless EVM `CALL`. No staking, governance, or validator privilege is required — only a wasm contract deployer and pointer-precompile caller role, both explicitly in scope.

### Recommendation
In `precompiles/pointer/pointer.go`, replace the unchecked type assertions with the comma-ok form and return a proper `error` (not a panic) when `"name"`/`"symbol"` are missing or not strings, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info response missing/invalid name field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract token_info response missing/invalid symbol field")
}
```
Apply the same fix to `AddCW721` and `AddCW1155`. As defense in depth, add the same `defer recover()` pattern used in `addr`, `oracle`, `distribution`, and `solo` precompiles to `pointer.Execute`, and/or add a top-level recover in `RunAndCalculateGas`/`Run` in `precompiles/common/precompiles.go` so that any executor panic (not just gas-meter ones) is converted into `vm.ErrExecutionReverted` instead of crashing the process.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` (or `contract_info`) query handler returns JSON such as `{"decimals": 18}` (omitting `name`/`symbol`) or `{"name": 123, "symbol": 456}` (wrong types).
2. As any funded EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b`, method `addCW20Pointer(string cwAddr)` (or `addCW721Pointer`/`addCW1155Pointer`), passing the malicious contract's bech32 address.
3. `AddCW20` in `precompiles/pointer/pointer.go` executes `formattedRes["name"].(string)` on the crafted response, panics with an unrecovered `interface conversion` error, and the panic propagates out of `RunAndCalculateGas` (no generic recover) into the node process handling the transaction, crashing it.

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
