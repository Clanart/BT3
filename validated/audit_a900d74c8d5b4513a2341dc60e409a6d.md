### Title
Unprivileged dust deposits to the Serai multisig address are reported as spendable inputs, forcing net-negative-fee spending (griefing) — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The Solvent report describes an unprivileged, cost-free action (`unstake_nft`) that anyone could repeat to deny the system rewards; the fix was to make the action cost something (transferring all of the farmer's lamports). The analog in Serai's Bitcoin wallet code is `Scanner::scan_transaction`/`scan_block`: any transaction on the public Bitcoin network paying to the multisig's P2TR script is reported as a `ReceivedOutput` with **no minimum-value, dust, or fee-recovery check anywhere in the in-scope library**. An attacker can cheaply flood the multisig with dust outputs; each is treated as a first-class spendable input, and spending one costs more in transaction fees than it contributes — a repeatable, unprofitable-to-block denial of economic value exactly matching the reported class.

### Finding Description
`Scanner::new` registers the base P2TR script (`p2tr_script_buf(key)`) and `register_offset` adds derived scripts; `scan_transaction` then emits a `ReceivedOutput` for every matching `TxOut` unconditionally:

```rust
// networks/bitcoin/src/wallet/mod.rs
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput {
    offset: *offset,
    output: output.clone(),
    outpoint: OutPoint::new(tx.compute_txid(), vout),
  });
}
```

`ReceivedOutput` stores `offset`, `output`, `outpoint` — there is no value threshold at all. `DUST = 546` exists in `networks/bitcoin/src/wallet/send.rs` but is only applied to *payments* and *change* created by `SignableTransaction::new`, never to *inputs*. `SignableTransaction::new` accepts any `Vec<ReceivedOutput>`, and `multisig()` will construct per-input FROST machines (`AlgorithmMachine::new(Schnorr::new(), keys.offset(...))`) for each, committing to sign them all under `Prevouts::All`.

A Taproot key-spend input adds ~58 vbytes. Any received output whose value is below `58 * fee_per_vbyte` is economically unspendable — including it in a transaction makes `fee() >` its contributed value — yet nothing in this crate prevents or even flags such inputs. The only dust filter (`output.balance().amount.0 >= N::DUST`) lives in `processor/src/multisigs/scanner.rs`, outside the wallet library's own guarantees, and only filters *below* dust; outputs of e.g. 600–5000 sats still pass it while remaining fee-negative at realistic fee rates, and unlike Solvent's fix there is no charge imposed on the depositor within this library.

### Impact Explanation
An unprivileged attacker with only the publicly known multisig address can, for the cost of dust (which they can fan out in a single transaction — one tx can carry hundreds of outputs to the same script, each costing them only ~546 sats):

- Force accumulation of UTXOs that Serai can never profitably spend; any consolidation/spend transaction signed via `TransactionSignMachine` burns more fees than the inputs contribute, draining the multisig's effective balance.
- Inflate `SignableTransaction` input count toward `MAX_STANDARD_TX_WEIGHT`, consuming block space and fee budget on worthless inputs if consumed, or permanently encumbering the wallet's input set if ignored.
- Repeat indefinitely at near-zero marginal cost — mirroring the Solvent attacker who unstakes in a loop to deny the contract its rewards.

This is a griefing/economic-denial attack: funds are "reported received" by `Scanner` that are not economically spendable, and consuming them realizes a guaranteed loss.

### Likelihood Explanation
The attack surface is fully permissionless — sending to a P2TR address requires no privilege, and the scan path applies no criteria beyond `script_pubkey` equality. The cost per iteration is bounded by the dust relay limit, and hundreds of griefing outputs fit in one attacker transaction. The only mitigations are external to this crate (the processor's `N::DUST` check, which is a fixed floor unrelated to prevailing fee rates and does not charge the depositor). Medium likelihood given low cost and no required privilege; impact bounded to fee drain and UTXO-set bloat rather than direct theft.

### Recommendation
Mirror the Solvent remediation — make the action cost the initiator:

1. In `Scanner::scan_transaction`/`scan_block`, drop outputs below a configurable value threshold rather than a hard-coded dust constant, or annotate `ReceivedOutput` with enough information for callers to reject fee-negative inputs.
2. In `SignableTransaction::new`, reject (or require explicit opt-in for) any input whose `value < input_vbytes * fee_per_vbyte`, so signing machines can never be constructed for economically irrational inputs.
3. At the protocol level, charge the flat per-received-output fee described in `spec/processor/UTXO Management.md` before crediting the deposit, so spamming the multisig costs the attacker more than the aggregation fees it inflicts.

### Proof of Concept
1. Compute Serai's public P2TR script: `p2tr_script_buf(group_key)` — publicly derivable.
2. Attacker publishes one Bitcoin transaction with N outputs of 546–1000 sats each to that script.
3. `scanner.scan_block(&block)` returns N `ReceivedOutput`s — all accepted, since `scan_transaction` applies no value check.
4. At a fee rate of e.g. 20 sat/vB, each input costs ~1160 sats to spend while contributing ≤1000 sats; any `SignableTransaction` including them runs at a net loss, and omitting them leaves permanent dead UTXOs. Repeating scales the drain linearly at ~546 sats/output cost to the attacker — the same unbounded, unprivileged, near-free denial loop as repeated `unstake_nft` calls. [1](#0-0) [2](#0-1) [3](#0-2)

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);

      }
```
