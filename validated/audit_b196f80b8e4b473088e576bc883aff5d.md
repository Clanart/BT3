## Title
Pool v2 authentication tokens (bearer-token equivalent) are written to the farmer log in plaintext at default INFO level, enabling replay to hijack payout instructions - (File: `chia/farmer/farmer.py`)

### Summary
The Apache Ranger CVE describes replayable JWT bearer tokens being written into application logs, letting anyone with log access impersonate the token holder. Chia's farmer↔pool protocol has a directly analogous bearer-token flow: for pool protocol v2, the farmer calls `GET /auth`, receives a short opaque `authentication_token` string (functionally a bearer/session token with an `expiration`), caches it, and then presents it as `authentication_token_v2` on subsequent `GET/POST/PUT /farmer` and `POST /partial` calls instead of re-signing with a private key. That token, and the requests carrying it, are logged in plaintext by the farmer at default (INFO/DEBUG) log levels.

### Finding Description
`GetAuthResponse` carries the pool-issued bearer token as a plain string: [1](#0-0) 

`Farmer._get_current_authentication_token()` obtains and caches this v2 token via `_pool_get_auth()`, then reuses it (`authentication_tokens[launcher_id]`) until expiration: [2](#0-1) 

Every pool HTTP call, including the `GET /auth` call that returns the token, goes through `make_pool_protocol_request()`, which unconditionally logs the full response JSON at `logging.INFO` (only escalated to WARNING on error) and logs the outgoing request object at DEBUG: [3](#0-2) 

Because `GetAuthResponse.to_json_dict()` includes the raw `authentication_token` field, the `GET /auth response: {...}` log line at line 148 persists the plaintext, replayable bearer token to the farmer's log file at default INFO verbosity — no debug logging needs to be enabled.

Subsequent requests that carry `authentication_token_v2` (e.g. `GetFarmerRequestV2`, `PutFarmerRequest`) are also passed into the same debug-level request logger, and the partial-submission path explicitly re-logs the token-bearing request object: [4](#0-3) 

Critically, for pool protocol v2 the `PUT /farmer` payload (which sets `payout_instructions`) is sent **without any signature** — authentication relies solely on possession of the bearer token: [5](#0-4) [6](#0-5) 

Separately, the shared daemon message redaction helper (`redact_sensitive_data`) only strips keys matching `"pass"`, `"key"`, `"secret"`, `"mnemonic"` — `authentication_token`/`authentication_token_v2` are not covered even if such payloads ever crossed that path: [7](#0-6) 

showing this class of secret is not treated as sensitive anywhere in the logging pipeline for the farmer/pool flow.

### Impact Explanation
Anyone with read access to the farmer's log file (local users, log shipping/aggregation, support bundles, backups) can extract a valid `authentication_token_v2` bearer token before it expires and replay it directly against the pool's HTTP API — without ever needing the farmer's owner/authentication private keys. Because v2 `PUT /farmer` requires no signature, the stolen token alone is sufficient to change `payout_instructions`, redirecting the victim's pool payouts to an attacker-controlled address (reward redirection). The token can also be used to read/modify farmer account state (`GET/POST/PUT /farmer`) and submit partials on the victim's behalf.

### Likelihood Explanation
This requires only read access to a log artifact that is produced automatically and continuously during normal pool operation (every `_get_current_authentication_token` refresh cycle logs the token at INFO level), with no special user interaction, malicious peer, or elevated privilege beyond generic log/file access — a realistic and common exposure vector (shared hosting, log aggregation pipelines, ticket/support log attachments, misconfigured file permissions).

### Recommendation
- Add `"token"` (and any bearer/session-token field names) to the redaction trigger set, and apply the same `redact_sensitive_data()`-style filtering to farmer/pool logging in `make_pool_protocol_request()` and the `/partial` debug log, not just the daemon websocket path.
- Never log `GetAuthResponse`/`authentication_token_v2` fields in cleartext; log only redacted/truncated placeholders.
- Require signature-based authentication (not bearer-token-only) for state-mutating pool endpoints such as `PUT /farmer`, even in protocol v2.

### Proof of Concept
1. Configure a farmer against a v2 pool; let it run normally.
2. Observe the farmer log (`log/farmer.log`) at default INFO level after a pool auth refresh — the `GET /auth response: {...}` line contains the plaintext `authentication_token` (see `chia/farmer/farmer.py:146-149`).
3. Copy the token value before its `expiration`.
4. From any host, call `PUT /v2/farmer` on the pool with `{"authentication_token_v2": "<stolen token>", "payout_instructions": "<attacker address>", ...}` — per `PutFarmerRequest`/`PutFarmerPayload` (`chia/protocols/pool_protocol.py:160-171`) and `Farmer._pool_put_farmer()` (`chia/farmer/farmer.py:579-612`), v2 requests carry `signature=None`, so the pool has only the bearer token to authenticate the change, redirecting the victim's future payouts.

    async def _get_current_authentication_token(
        self, pool_config: PoolingShareState, authentication_token_timeout: uint8
    ) -> str | pool_protocol.ErrorResponse | None:
        if pool_config.version == 1:
            return str(pool_protocol.get_current_authentication_token(authentication_token_timeout))
        elif pool_config.version == 2:
            cached_auth_token = self.authentication_tokens.get(pool_config.launcher_id, None)
            if cached_auth_token is None or datetime.fromtimestamp(
                cached_auth_token[1], tz=timezone.utc
            ) < datetime.fromtimestamp(self.get_current_time(), tz=timezone.utc):
                auth_response = await self._pool_get_auth(pool_config)
                if isinstance(auth_response, pool_protocol.GetAuthResponse):
                    self.authentication_tokens[pool_config.launcher_id] = (
                        auth_response.authentication_token,
                        auth_response.expiration,
                    )
                    return auth_response.authentication_token
                else:
                    return auth_response
            else:
                # seems sketchy because in theory we should check for non-None here but
                # the auth token can't be None AND expired so semantics guarantee a non-None, non-expired token here
                return cached_auth_token[0]
        else:
            raise ValueError("Unknown pool protocol version specified in pooling config")

    async def _pool_put_farmer(
        self, pool_config: PoolingShareState, authentication_token_timeout: uint8
    ) -> pool_protocol.PutFarmerResponse | pool_protocol.ErrorResponse | None:
        auth_sk: PrivateKey | None = self.get_authentication_sk(pool_config)
        if auth_sk is None:
            return None
        authentication_token = await self._get_current_authentication_token(pool_config, authentication_token_timeout)
        if not isinstance(authentication_token, str):
            self.log.error(f"Attempting to PUT farmer details without being logged into {pool_config.pool_url}")
            return authentication_token
        put_farmer_payload = pool_protocol.PutFarmerPayload(
            pool_config.launcher_id,
            uint64(authentication_token) if pool_config.version == 1 else uint64(0),
            auth_sk.get_g1(),
            pool_config.payout_instructions,
            None,
            authentication_token_v2=authentication_token,
        )
        if pool_config.version == 1:
            # impossible for this to fail when get_authentication_sk above succeeds
            owner_sk = find_owner_sk(self.all_root_sks, pool_config.owner_public_key)[0]  # type: ignore[index]

            signature = None
        put_farmer_request = pool_protocol.PutFarmerRequest(put_farmer_payload, signature)
        response, _ = await make_pool_protocol_request(
            self=self,
            pool_config=pool_config,
            method="PUT",
            endpoint_name="farmer",
            request=put_farmer_request,
            response_type=pool_protocol.PutFarmerResponse,
        )
        return response

def redact_sensitive_data(obj: Any, redaction_triggers: Collection[str] = ("pass", "key", "secret", "mnemonic")) -> Any:
    """Recursively redact sensitive data from nested dictionaries."""
    if isinstance(obj, dict):
        return {
            key: "***<redacted>***"
            if any(trigger.casefold() in key.casefold() for trigger in redaction_triggers)
            else redact_sensitive_data(value, redaction_triggers)
            for key, value in obj.items()
        }
    else:
        return obj
