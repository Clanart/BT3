### Title
`file_path` regex conditions in hookify rules are bypassable via unnormalized path variants (symlinks, `./` prefixes, trailing slashes) - ([File: plugins/hookify/core/rule_engine.py])

### Summary
`RuleEngine._extract_field` returns the raw, unnormalized `tool_input['file_path']` string directly from the `Edit`/`Write`/`MultiEdit` tool call, and `_regex_match` performs a plain `re.search` against that raw string with no path canonicalization. An attacker-controlled agent action (or any automation flow issuing a tool call) can supply a `file_path` whose literal string form doesn't match a sensitive-file rule pattern (e.g. `\.env$`) while the underlying filesystem write still resolves to the protected file, defeating the only enforcement mechanism hookify provides.

### Finding Description
In `plugins/hookify/hooks/pretooluse.py`, the hook reads the raw `tool_input` from stdin JSON and passes it unmodified to `RuleEngine.evaluate_rules` [1](#0-0) . `_check_condition` calls `_extract_field(condition.field, ...)` to get the string to test [2](#0-1) . For `Write`/`Edit`/`MultiEdit` tools, `_extract_field` returns `tool_input.get('file_path', '')` verbatim - no `os.path.normpath`, `os.path.realpath`, `Path.resolve()`, or case-folding is applied anywhere in the field-extraction path [3](#0-2) . The value is then matched with a plain regex `search()` in `_regex_match`, with no canonicalization performed before or after [4](#0-3) .

Because the match is purely a string-level regex on the caller-supplied `file_path`, any tool call whose `file_path` field takes a form other than the canonical guarded path will bypass a suffix-anchored pattern such as `\.env$`:
- A symlink whose name doesn't end in `.env` (e.g. `notes.txt -> .env`) resolves to the protected file on write, but the string `notes.txt` never matches `\.env$`.
- A trailing slash (`.env/`) breaks a `$`-anchored match even though many filesystem APIs will still treat it as the same file/directory entry.
- Case differences on case-insensitive filesystems (e.g. `.ENV`) are actually caught here because `compile_regex` uses `re.IGNORECASE` [5](#0-4) , so that specific variant is not exploitable, but the symlink and trailing-slash cases are not covered by any check.

No component in the reachable call chain (`pretooluse.py` → `RuleEngine.evaluate_rules` → `_rule_matches` → `_check_condition` → `_extract_field`/`_regex_match`) performs symlink resolution or path canonicalization before the regex test, so the rule engine's file-path protections are bound to the literal string an untrusted tool call happened to supply, not to the resolved target of the write.

### Impact Explanation
Hookify's `.env`/credential-protecting rules are the only local enforcement mechanism preventing sensitive file writes/reads through `Edit`/`Write`/`MultiEdit` tool calls. Because path matching is done on the raw, unresolved string, a workflow that ends up issuing a tool call with a symlink path or slightly different path spelling can write/overwrite the actual protected file (e.g. `.env`, `id_rsa`-adjacent config) while the guarding rule silently fails to trigger, allowing unauthorized modification/disclosure of sensitive local files.

### Likelihood Explanation
Exploitability requires: (1) a hookify rule configured to guard sensitive files by `file_path` regex (a common documented use case per `plugins/hookify/skills/writing-rules/SKILL.md`), and (2) a tool call reaching `Edit`/`Write`/`MultiEdit` with a `file_path` argument that is a symlink or otherwise not the canonical form matched by the pattern. Creating a symlink in the working tree pointing at `.env` and referencing the symlink name in a tool call is straightforward for any workflow that can influence tool arguments, making this a low-effort, repeatable bypass whenever such rules are relied upon.

### Recommendation
Normalize `file_path` before regex matching: use `os.path.realpath()` (to resolve symlinks) combined with `os.path.normpath()` on the extracted `file_path` in `_extract_field` (or immediately before calling `_regex_match`) so the value evaluated by rules is the canonical, resolved path rather than the raw caller-supplied string. Ensure trailing slashes are stripped consistently and that comparisons happen against the fully resolved absolute path.

### Proof of Concept
Unit test in `plugins/hookify/core` test suite:
1. Define a rule `Condition(field="file_path", operator="regex_match", pattern=r"\.env$")`.
2. Create a temp directory containing a real `.env` file and a symlink `link.txt -> .env`.
3. Call `RuleEngine()._check_condition(condition, "Write", {"file_path": ".env"}, {})` → expect `True`.
4. Call the same with `{"file_path": "link.txt"}` (pointing at the same `.env` via symlink) → current behavior returns `False` (bypass); expected/fixed behavior should return `True` after resolving the symlink.
5. Repeat with `{"file_path": ".env/"}` (trailing slash) → current behavior returns `False`; assert it should match after normalization.
6. Assert all path variants produce the same match decision as the canonical `.env` path, failing on the current implementation and passing after adding `os.path.realpath`/`os.path.normpath` normalization in `_extract_field`.

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```

```python
    def _regex_match(self, pattern: str, text: str) -> bool:
        """Check if pattern matches text using regex.

        Args:
            pattern: Regex pattern
            text: Text to match against

        Returns:
            True if pattern matches
        """
        try:
            # Use cached compiled regex (LRU cache with max 128 patterns)
            regex = compile_regex(pattern)
            return bool(regex.search(text))

        except re.error as e:
            print(f"Invalid regex pattern '{pattern}': {e}", file=sys.stderr)
            return False
```
