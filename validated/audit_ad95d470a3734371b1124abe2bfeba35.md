### Title
Unauthorized re-deployment of live CW20/CW721/CW1155/native ERC pointer contracts via the pointer precompile - ([File: precompiles/pointer/pointer.go])

### Summary
The current (non-legacy) `pointer` precompile at `0x100b` lets **any unprivileged EVM caller** re-trigger deployment of an already-registered ERC pointer contract (native/CW20/CW721/CW1155) at its existing address, without any authorization check tied to the original deployer/registrant. This silently overwrites the pointer's live bytecode/state via `evm.GetDeploymentCode`, which is functionally the "any user can overwrite a shared resource that others depend on" bug class from CVE-2023-48239 (Nextcloud external-storage overwrite), except here the shared resource is a token pointer contract that every holder of the underlying denom/CW20/CW721/CW1155 asset relies on.

### Finding Description
All **legacy** pointer precompile implementations gate re-registration with an explicit ownership/version check before allowing any state mutation: [1](#0-0) 

That is: `AddNative`/`AddCW20`/`AddCW721` in every `legacy/vXXX` package reject the call outright with `"pointer ... exists when trying to set pointer for version ..."` unless the caller is upgrading to a strictly newer pointer version.

The **current** `precompiles/pointer/pointer.go` implementation removed this existence/version guard entirely. `AddNative`, `AddCW20`, `AddCW721`, and `AddCW1155` now unconditionally call the keeper's `UpsertERC*Pointer` methods regardless of whether a pointer already exists and regardless of who the caller is: [2](#0-1) [3](#0-2) 

`UpsertERCPointer` in the keeper then looks up the existing pointer address and, if found, calls `evm.GetDeploymentCode(...)` to regenerate contract init code and `k.SetCode(...)` to overwrite the bytecode **at the pre-existing contract address**, then updates the pointer registry entry: [4](#0-3) 

There is no check that `caller` is the original registrant, a governance actor, or otherwise privileged — `caller` is accepted but never compared against anything in `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155`. Any EVM account can call `addNativePointer(token)` for a `token` denom that already has a pointer, or `addCW20Pointer(cwAddr)`/`addCW721Pointer(cwAddr)`/`addCW1155Pointer(cwAddr)` for any already-pointered CW contract, and force the keeper to redeploy fresh constructor bytecode over the live pointer contract that every EVM holder of that asset is currently using through wallets, DEXs, and other integrations (per the ERC20/CW20 pointer test suite showing per-holder state such as `approve()`/`allowance()` is tracked in the pointer contract itself): [5](#0-4) 

### Impact Explanation
Because the pointer contract is the sole ERC20/ERC721/ERC1155 entrypoint that DEXs, wallets, and other EVM contracts interact with for a given native/CW asset, an unprivileged, unauthenticated re-deployment forced by any third party:
- Re-runs the constructor over the live contract address, which per the `UpsertERCPointer` implementation is treated as re-initialization rather than a metadata-only patch (it calls `evm.GetDeploymentCode`/`SetCode`, the same mechanism used for brand-new deployments).
- Can invalidate any in-flight transactions or integrations relying on a stable pointer state and forcibly resets on-chain metadata (name/symbol/decimals) to whatever the current queried source (bank denom metadata or CW `token_info`/`contract_info`) returns at call time, which is attacker-influenceable if the caller also controls the underlying denom/CW contract's mutable metadata.
- Makes the shared pointer temporarily or effectively unusable for every other user relying on it (matching the "inaccessible for everyone else" impact class of the Nextcloud CVE), and can be triggered repeatedly by anyone with a Sei EVM address at essentially the cost of one transaction, satisfying "permanent freezing" style impact for a shared, widely used asset entrypoint.

This is reachable purely from a public EVM transaction sent by any unprivileged account to the `pointer` precompile at `0x100b`, no special permission required.

### Likelihood Explanation
High. The precompile is public, requires no privileged role, no CosmWasm-side approval, and no minimum stake — a single `addNativePointer`/`addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` call against any already-registered denom/CW contract triggers the unconditional upsert path. The bug is a straightforward removal of a check that clearly exists in every legacy version of the same precompile, strongly suggesting an unintentional regression rather than a deliberate design change.

### Recommendation
Restore an authorization/version gate in `precompiles/pointer/pointer.go`'s `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155` (mirroring the legacy `existingVersion >= currentVersion` reject logic) so that re-registration/upsert of an existing pointer is only permitted for genuine version upgrades (module-internal migration calls) and not from arbitrary EVM callers hitting the public precompile with an already-registered token/address.

### Proof of Concept
1. User A registers a CW20 pointer via `addCW20Pointer(cwAddr)` on the pointer precompile (`0x100b`); pointer contract `P` is deployed and adopted by wallets/DEXs for that CW20 token.
2. Attacker (any unprivileged EVM account) calls `addCW20Pointer(cwAddr)` again from a different EOA.
3. `precompiles/pointer/pointer.go:AddCW20` performs no ownership/version check and calls `p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, freshMetadata)`.
4. `x/evm/keeper/pointer_upgrade.go:UpsertERCPointer` finds the existing pointer address, calls `evm.GetDeploymentCode(...)` and `k.SetCode(...)` to overwrite bytecode at `P`, re-emitting `EventTypePointerRegistered`.
5. Result: the shared pointer contract `P` used by all other holders is redeployed/reset without their consent, at the sole discretion of any third-party caller — reproducing the "any user can make a shared resource inaccessible for others" bug class from CVE-2023-48239. [6](#0-5) [7](#0-6)

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}
	if err != nil {
		return
	}
	ctx.GasMeter().ConsumeGas(k.GetCosmosGasLimitFromEVMGas(ctx, suppliedGas-remainingGas), "ERC pointer deployment")
	if err = setter(liveCtx(), pointee, contractAddr); err != nil {
		return
	}
	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, typ),
		sdk.NewAttribute(types.AttributeKeyPointerAddress, contractAddr.Hex()), sdk.NewAttribute(types.AttributeKeyPointee, pointee)))
	return
}
