## Confirmed vulnerability

The binding claimed to hold is:

`OP_RETURN operator_xonlypk field in the payout tx == the operator who actually funded/broadcast the payout (i.e. paid the withdrawer out of their own balance)`

Tracing the code shows this binding is **never enforced anywhere** — it is pure unauthenticated data copied verbatim from chain scan into the attribution DB column, and later trusted as ground truth by the reimbursement automation.

- `update_finalized_payouts` (core/src/verifier.rs:2283-2352) scans any transaction that spends a registered withdrawal UTXO, extracts whatever bytes are pushed after `OP_RETURN` and parses them as an x-only pubkey — no signature, no ownership proof, nothing ties this pubkey to whoever actually funded the tx's inputs: [1](#0-0) 
- That value is written straight into `withdrawals.payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk`: [2](#0-1) 
- The operator's own automation (`PayoutCheckerTask`) polls `get_first_unhandled_payout_by_operator_xonly_pk` filtered **only** by this DB column and, if found, calls `handle_finalized_payout`, which proceeds to build the kickoff/reimburse chain: [3](#0-2) [4](#0-3) 
- `bridge_circuit` (the zk proof consumed at reimbursement time) only checks that `payout_input_index` spends `(wd_txid, vout)` and that *some* OP_RETURN exists; it never checks the value of any output, never sums inputs/outputs, and never checks who funded the other inputs: [5](#0-4) 
- `create_payout_txhandler` normally has a **single input** (the withdrawal UTXO), signed by the user with `SpendPath::KeySpend`: [6](#0-5)  — but the sighash type of that single signature is attacker-controlled (per the threat model), and nothing in `verifier.rs`/`aggregator.rs`/`operator.rs` restricts it to `SIGHASH_ALL` (non-ANYONECANPAY). If it is `ANYONECANPAY`, an attacker who owns the withdrawal UTXO (which they do, since they are the withdrawing user) can independently assemble and broadcast their own transaction that reuses this valid signature, adds arbitrary additional attacker-funded inputs to actually cover the payout output, pays themselves out of their own added input, and stuffs *any* registered operator's x-only pubkey into the OP_RETURN.
- `is_kickoff_malicious` (core/src/verifier.rs:1859-1915) only cross-checks that the OP_RETURN pubkey equals the kickoff's claimed operator and that the committed blockhash matches — it never checks that the named operator's balance/keys funded the extra inputs of the payout tx: [7](#0-6) 

Because the OP_RETURN attribution is (a) unauthenticated data and (b) the sole source used to decide who gets `Reimburse`, a self-funded attacker transaction that names an uninvolved operator's pubkey will cause that operator's own automation to trigger a real `Reimburse` payout from the vault (`create_reimburse_txhandler` pays `move_txhandler`'s `DepositInMove` value to the operator's reimbursement address) — for a payout the operator never funded: [8](#0-7) 

### Title
Unauthenticated OP_RETURN operator attribution lets a self-funded payout tx trigger reimbursement for an operator who never fronted funds - (File: circuits-lib/src/bridge_circuit/mod.rs, core/src/verifier.rs, core/src/database/verifier.rs)

### Summary
`bridge_circuit` and the whole payout-attribution pipeline treat the OP_RETURN `operator_xonlypk` push in the payout transaction as authoritative proof that "this operator fronted the withdrawal," without ever checking that the operator's own funds paid for the output. Since the withdrawal UTXO's spending signature can be crafted with an ANYONECANPAY sighash flag by the withdrawing user (who is the attacker), a self-funded transaction can be broadcast that pays the attacker from a second attacker-owned input while naming any registered operator's pubkey in the OP_RETURN, causing that operator's automation to claim a real vault reimbursement it never funded.

### Finding Description
The broken binding is `payout_payer_operator_xonly_pk (attributed) == actual funder of the payout output`. This is set purely from unauthenticated OP_RETURN bytes scanned in `update_finalized_payouts` [9](#0-8) , stored via `update_payout_txs_and_payer_operator_xonly_pk` [2](#0-1) , and consumed by `PayoutCheckerTask::run_once` filtering solely on this stored pubkey [10](#0-9) . `bridge_circuit` in mod.rs never sums input/output values or checks the source of funds for the non-`payout_input_index` inputs — it only requires `payout_input_index` to spend the registered `(wd_txid, vout)` and requires *an* OP_RETURN to exist [5](#0-4) . `is_kickoff_malicious` cross-checks pubkey/blockhash consistency but never validates fund provenance [7](#0-6) . Since the withdrawal UTXO is spent via a single key-path signature whose sighash flag the signer (the withdrawing user/attacker) controls, choosing an ANYONECANPAY variant lets anyone append extra self-funded inputs to a transaction reusing that valid signature while freely choosing the OP_RETURN's operator pubkey (which is unsigned, plain script data).

### Impact Explanation
A named operator's automation is caused to broadcast the presigned Kickoff/Reimburse chain, and `create_reimburse_txhandler` pays that operator the full `DepositInMove` value from the vault [11](#0-10)  for a payout it never funded. This matches the Critical category "an operator reimbursed for a payout it never funded." It is repeatable per withdrawal/deposit and can target any registered operator's xonly pubkey, since the attacker fully controls the OP_RETURN contents.

### Likelihood Explanation
Requires: (1) the withdrawal UTXO's spend signature to accept a non-default (ANYONECANPAY) sighash type unrestricted by protocol/software checks, and (2) the attacker to fund the actual payout amount themselves via an additional input (i.e., it costs the attacker the payout amount, which they receive back themselves — no net cost beyond fees). This is inexpensive and fully within attacker capabilities (they choose their own signature/sighash flag and OP_RETURN bytes as permitted by the threat model).

### Recommendation
Do not attribute reimbursement based on unauthenticated OP_RETURN data alone. Require the operator to co-sign or otherwise cryptographically commit to the specific payout transaction it is claiming to have funded (e.g., verify that the operator's own broadcast/tracked txid, stored when they called `withdraw()`/TxSender, matches the on-chain payout txid before marking it "unhandled" for that operator), and/or enforce a fixed sighash type (`SIGHASH_ALL`, no ANYONECANPAY) on the withdrawal UTXO's signature so the operator's own signed transaction cannot be reused/extended by third parties.

### Proof of Concept
`cargo test` plan (core/src/test):
1. Register a withdrawal (own dust UTXO) as in `generate_withdrawal_transaction_and_signature`, obtaining `sig` with `TapSighashType::AllPlusAnyoneCanPay` instead of the intended non-ANYONECANPAY type.
2. Independently build a transaction: input[0] = withdrawal UTXO signed with the attacker's own key/sig; input[1] = attacker-owned funding UTXO; outputs = [payout to attacker's own address funded from input[1], anchor, OP_RETURN(victim_operator_xonlypk)].
3. Broadcast; run `update_finalized_payouts` and assert `withdrawals.payout_payer_operator_xonly_pk == victim_operator_xonlypk`.
4. Run `PayoutCheckerTask::run_once` for the victim operator and assert it returns `Ok(true)` and calls `handle_finalized_payout`, producing a `kickoff_txid`.
5. Assert `create_reimburse_txhandler` for that kickoff pays `victim_operator_reimbursement_address` the full `bridge_amount`, while asserting the victim operator's on-chain wallet balance never decreased by that amount (i.e., they funded $0 of the payout output).

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,

    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
