### Title
`get_outputs` applies the last matching transaction's embedded InInstruction to all Serai outputs in a block, letting an attacker re-attribute a victim's deposit - (File: processor/src/networks/bitcoin.rs)

### Summary
The bug class in the external report is "two distinct assets sharing one data feed, so one asset is valued/described by another's data". In Serai's Bitcoin processor, the analog exists in `Bitcoin::get_outputs`: the `outputs` vector and the `data`/`presumed_origin` attribution loop are scoped to the **block**, not the transaction, so an attacker's transaction later in the same block overwrites the `InInstruction` data attached to a victim's deposit output from an earlier transaction.

### Finding Description
In `get_outputs`, the `outputs` vector is declared once before iterating over `block.txdata[1 ..]`:

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ... outputs.push(output); }
  if outputs.is_empty() { continue; }
  // compute presumed_origin and data from *this* tx
  for output in &mut outputs {
    if output.kind == OutputType::External { output.data.clone_from(&data); }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
```

Because `outputs` accumulates across transactions, `outputs.is_empty()` is false for every transaction after the first Serai output is seen in the block. Any later transaction in the same block — which does not need to contain any Serai output at all — causes `presumed_origin` (derived from `tx.input[0]`'s spent output) and `data` (from `extract_serai_data(tx)`, the `InInstruction` embedded via the P2WSH data-embedding mechanism shown in `processor/src/tests/literal/mod.rs`) to be **re-derived from the attacker's transaction and written over every previously collected output**, including outputs whose `tx_id()` belongs to a different transaction. [1](#0-0) 

This is exactly the report's shape: one asset's (transaction's) data feed is silently applied to a different asset (a deposit output belonging to a different tx), and the per-output `assert_eq!(output.tx_id(), tx.id())` only guards newly scanned outputs at push time, not the later mutation loop.

### Impact Explanation
`output.data` carries the Serai `InInstruction` (e.g., which Serai address a deposit should be credited to) and `presumed_origin` identifies the refund/origin address. An attacker who places a transaction in the same block after a victim's deposit can cause the victim's `External` output to be reported with the attacker's `InInstruction` data and the attacker's origin address, redirecting credit/refund attribution of funds the attacker does not own. Alternatively the attacker can attach no data at all (`extract_serai_data` returning empty), destroying the victim's instruction so the deposit is mishandled. Outputs are emitted as received funds with corrupted metadata — meeting the bar of funds reported received with wrong attribution.

### Likelihood Explanation
Fully reachable by an unprivileged party: the attacker only needs to broadcast a Bitcoin transaction mined in the same block as a victim's deposit, with control over `input[0]` and an optional embedded `InInstruction` (the standard data-embedding path). No validator key, collusion, or RPC compromise is required. It does require same-block ordering (attacker tx after victim tx), which is feasible by observing the mempool and fee-bumping.

### Recommendation
Scope `data` and `presumed_origin` per transaction: collect the scanned outputs of each `tx` into a per-tx vector, and only apply that tx's `extract_serai_data`/`presumed_origin` to outputs scanned from that same tx (e.g., skip with `continue` when that tx produced no outputs, and mutate only the freshly scanned slice). Alternatively, keep a global `outputs` but record which tx each output came from and apply metadata only to matching outputs.

### Proof of Concept
```rust
// Within one block:
// txdata[1]: victim's deposit tx paying the Serai external address,
//            embedding InInstruction crediting victim_serai_addr (normal flow).
// txdata[2]: attacker's arbitrary tx (no Serai outputs), embedding
//            InInstruction crediting attacker_serai_addr, input[0] spending
//            an attacker-owned output.

let outputs = bitcoin.get_outputs(&block, group_key).await;
// outputs[0] is the victim's deposit (tx_id == txdata[1].id()),
// but outputs[0].data == attacker's InInstruction and
// outputs[0].presumed_origin == attacker's address,
// because the block-level `outputs` vec bypassed the `is_empty()` continue
// for txdata[2] and the `for output in &mut outputs` loop overwrote
// metadata computed from txdata[2].
```

```rust
  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
```
