Based on the code in this repo, `id_token_from_url_param` in `lib/shopify_app/controller_concerns/with_shopify_id_token.rb` does allow an `id_token` to be read from the `id_token` query parameter as a fallback when there's no `Authorization` header, and that value flows to `shopify_id_token`, into `current_shopify_session_id`, and into `ShopifyAPI::Utils::SessionUtils.session_id_from_shopify_id_token` in `lib/shopify_app/controller_concerns/token_exchange.rb#current_shopify_session_id`. [1](#0-0) [2](#0-1) [3](#0-2) 

However, the actual signature/`aud`/`exp` verification of the JWT happens inside `ShopifyAPI::Auth::JwtPayload` and `ShopifyAPI::Utils::SessionUtils.session_id_from_shopify_id_token`, which live in the `shopify_api` gem — an external dependency, not code present in this repository. This repo's test suite treats that verification as a black box: it stubs `session_id_from_shopify_id_token` and asserts that when it raises `ShopifyAPI::Errors::InvalidJwtTokenError`/`MissingJwtTokenError` (i.e., invalid/forged tokens), the controller redirects to the bounce page or responds `:unauthorized`, never resolving a session. [4](#0-3) [5](#0-4) [6](#0-5) 

Per the audit rules, "dependency bugs alone" and issues outside this repo's context are out of scope — the actual JWT cryptographic verification enforcement is implemented in the `shopify_api` gem, not in `shopify_app`. Within this repo, the design correctly funnels any id_token (from header or URL param) through the gem's verification (`session_id_from_shopify_id_token`) before it is ever used to derive a session id, and this repo's error-handling paths (`INVALID_SHOPIFY_ID_TOKEN_ERRORS` rescue) demonstrate that unverifiable/forged tokens are rejected rather than resolved to a session. There is no code in this repo that bypasses or weakens that verification for id_token supplied via the URL param versus the header — both go through the identical `session_id_from_shopify_id_token` call.     def respond_to_invalid_shopify_id_token(error)
      ShopifyApp::Logger.debug("Responding to invalid Shopify ID token: #{error.message}")
      return if performed?

      if request.headers["HTTP_AUTHORIZATION"].blank?
        if embedded?
          redirect_to_bounce_page
        else
          redirect_to_embed_app_in_admin
        end
      else
        ShopifyApp::Logger.debug("Responding to invalid Shopify ID token with unauthorized response")
        response.set_header("X-Shopify-Retry-Invalid-Session-Request", 1)
        unauthorized_response = { message: :unauthorized }
        render(json: { errors: [unauthorized_response] }, status: :unauthorized)
      end
    end
