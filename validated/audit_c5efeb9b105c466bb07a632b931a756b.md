### Title
Uninitialized `LastRewardedHeight`/`previous_commitment_height` baseline lets the first consensus reward drain the treasury - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::calculate_reward` computes a relayer's payout as `(latest_height − baseline) × cost_per_block`, where `baseline` falls back to `0` whenever neither `LastRewardedHeight` nor the host's `previous_commitment_height` has a value yet. This is the same class of bug as the RocketJoe report: an unset baseline (`lastRewardTimestamp == 0` there, `baseline == 0` here) is treated as "the origin of time/height" instead of "unknown," so the very first payout for a state machine can be computed over its entire historical height instead of over the actual span of new blocks the relayer delivered.

```rust
fn calculate_reward(...) -> Result<..., Error<T>> {
    let host = <T::IsmpHost>::default();
    let latest_height = host.latest_commitment_height(state_machine_id.clone())...?;
    let previous_height =
        host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

    // Use the rewarded watermark as the baseline and fall back to the previous height until
    // the first reward is recorded for this chain.
    let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

    let blocks = latest_height.saturating_sub(baseline);
    let reward = blocks_as_balance.saturating_mul(block_cost);
    Ok(reward)
}
```

Both fallbacks compound into a single unsafe default:
- `LastRewardedHeight` is `OptionQuery` and starts empty for every `state_machine_id` — exactly like `RocketJoeStaking.lastRewardTimestamp` starting at `0`.
- `host.previous_commitment_height(..)` also returns `None` whenever `pallet-ismp` has not yet recorded two consecutive `StateMachineUpdated` events for that state machine (e.g., the very first consensus update ever accepted for a newly onboarded/re-onboarded state machine, or one whose bounded history entry aged out). `.unwrap_or_default()` silently turns that "unknown" into `0`.

When both are unset, `baseline = 0`, so `blocks = latest_height − 0 = latest_height`. For any real chain, `latest_height` at onboarding time is not `0` — it is the chain's current block/height (often already in the thousands or millions for an EVM/parachain being added to Hyperbridge). The reward paid out is `latest_height × cost_per_block`, i.e., the relayer is paid as though it delivered every block from genesis, not just the actual new blocks in this update.

This mirrors the audited RocketJoe defect precisely: an accounting baseline that should represent "no progress yet" is instead read as "progress since the beginning of time," and the fix pattern is identical — track an explicit, always-initialized watermark rather than deriving it from a value that can legitimately be absent.

### Impact Explanation
`process_message` unconditionally transfers the computed `reward` from the treasury to the recovered relayer account: [2](#0-1) 

There is no cap on `blocks`, no sanity check that `baseline` is non-zero before a "genuine" first reward, and `saturating_mul` will happily produce a reward equal to `latest_height × cost_per_block`. For a state machine onboarded at a non-trivial height with any non-trivial `cost_per_block`, this single payout can be orders of magnitude larger than intended and can drain the `TreasuryAccount` in one relay of a legitimate consensus proof — this is direct, unauthorized loss of protocol funds (treasury), matching the bounty's "stealing or loss of funds" / "reward claims" category.

### Likelihood Explanation
The trigger condition — no `LastRewardedHeight` entry and no `previous_commitment_height` recorded — is not a contrived edge case; it is the *normal* state for any state machine the very first time it is rewarded, and can also recur if `pallet-ismp`'s previous-height tracking for that chain is reset (e.g. bounded/pruned history, as shown by the pallet's own rollback test using `PreviousStateMachineHeight`). No relayer privilege is required: any relayer that is first to submit a valid, signed `ConsensusMessage` for a state machine in this state triggers the inflated payout through the normal `on_executed`/`FeeHandler` path — it requires no proof forgery, no admin action, and no compromised key, only ordinary submission of the first consensus update for a newly configured `StateMachinesCostPerBlock` entry.

### Recommendation
Do not derive the reward baseline from a value (`previous_commitment_height`) that can legitimately be `None`/`0`. Instead:
- Initialize `LastRewardedHeight` explicitly to `latest_height` (not paying for historical blocks) the first time a state machine is configured with `update_cost_per_block`, or
- Require `previous_commitment_height` to be `Some` before paying any reward, and reject/no-op (rather than default to `0`) when it is `None`, mirroring the RocketJoe fix of tracking an explicit, always-correctly-initialized state variable instead of inferring it from a possibly-absent external value.

### Proof of Concept
1. Governance calls `update_cost_per_block(state_machine_id, cost_per_block)` for a new/newly re-onboarded EVM or parachain state machine whose current chain height is already large (e.g. `latest_height = 5_000_000`), and for which `pallet-ismp` has not yet stored a `previous_commitment_height`/`PreviousStateMachineHeight` entry (fresh consensus client, or history pruned).
2. Any relayer submits the first valid `ConsensusMessage` that advances Hyperbridge's view of that state machine to `latest_height = 5_000_000`, producing a `StateMachineUpdated` event.
3. `FeeHandler::on_executed` → `process_message` → `calculate_reward` runs:
   - `LastRewardedHeight::get(state_machine_id)` → `None`
   - `host.previous_commitment_height(state_machine_id)` → `None` → `.unwrap_or_default()` → `0`
   - `baseline = 0`
   - `blocks = 5_000_000 − 0 = 5_000_000`
   - `reward = 5_000_000 × cost_per_block`
4. `T::Currency::transfer(treasury, relayer, reward, ...)` executes, paying the relayer as if it delivered 5,000,000 blocks' worth of consensus work in a single update, draining the treasury far beyond the intended per-update incentive — confirmed by the existing test file's rollback scenario at [3](#0-2)  which demonstrates the exact "baseline defaults when no watermark exists" mechanics, just without exercising the case where `previous_commitment_height` is also `None` on genuinely first-time onboarding.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

// A relayer is paid once for advancing a state machine across a span of heights. When the latest
// height is rolled back and later resubmitted, the reward should still only cover the new blocks.
// The `LastRewardedHeight` watermark keeps each payout scoped to the span that has not been paid.
#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
