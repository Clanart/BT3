### Identity encryption keys accepted during PedPoP deserialization expose encrypted secret shares - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
PedPoP accepts the identity point as a participant encryption key when deserializing an `EncryptionKeyMessage`. Every secret share sent to that participant is then encrypted under a publicly computable ECDH result, allowing observers to recover the plaintext `SecretShare` values.

### Finding Description
`EncryptionKeyMessage::read` parses `enc_key` using `C::read_G`, which validates only that the point decodes correctly and has a canonical encoding; it does not reject the identity point. [1](#0-0) [2](#0-1) 

`verify_r1` verifies the Schnorr proof over the DKG commitments, but it does not validate ownership or non-identity of `enc_key`; `Decryption::register` stores the supplied point without further checks. [3](#0-2) [4](#0-3) 

When a share is encrypted, Serai computes `ecdh = enc_key * ephemeral_key`; if `enc_key` is the identity, the result is always identity regardless of the ephemeral key. [5](#0-4) [6](#0-5) 

The ChaCha20 stream key is derived from the public DKG context and this shared point, followed by a fixed IV. [7](#0-6)  Consequently, anyone who observes the PedPoP transcript can derive the keystream and decrypt every share addressed to the malicious participant. [8](#0-7) 

### Impact Explanation
A malicious PedPoP participant can force all incoming encrypted share messages to be publicly decryptable by registering the identity point as its encryption key. This exposes sender-to-recipient secret-share material that the ECDH layer is intended to protect and constitutes key-share recovery by observers.

### Likelihood Explanation
The attack is deterministic and requires only replacing the final point in an otherwise valid serialized commitment message with the canonical identity encoding. It requires a DKG participant slot and observation of the authenticated PedPoP transcript, but no timing conditions, malformed encodings, or invalid signatures.

### Recommendation
Reject identity encryption keys in `EncryptionKeyMessage::read` or `Decryption::register`, before any key is stored for encryption. The check should mirror FROST’s non-identity point reader and return an error for `enc_key.is_identity()`. [9](#0-8)  A regression test should mutate a valid Ristretto `EncryptionKeyMessage` to use the identity point and assert that deserialization or registration fails.

### Proof of Concept
```rust
use rand_core::OsRng;
use dalek_ff_group::{dalek::ristretto::RistrettoPoint, Ristretto};
use ciphersuite::Ciphersuite;
use pedpop::{
  Commitments, EncryptionKeyMessage, KeyGenMachine,
};
use dkg::{Participant, ThresholdParams};

let params = ThresholdParams::new(3, 5, Participant::new(2).unwrap()).unwrap();
let context = [7; 32];

// Generate a valid commitment/encryption-key message.
let (_machine, msg) =
  KeyGenMachine::<Ristretto>::new(params, context).generate_coefficients(&mut OsRng);

let mut raw = msg.serialize();

// Replace the trailing enc_key point with the canonical Ristretto identity encoding.
let identity = RistrettoPoint::identity().compress().to_bytes();
raw[(raw.len() - identity.len()) ..].copy_from_slice(&identity);

// Currently accepted: Commitments::read succeeds, then C::read_G accepts identity.
let parsed =
  EncryptionKeyMessage::<Ristretto, Commitments<Ristretto>>::read(
    &mut raw.as_slice(),
    params,
  )
  .unwrap();
```

When another participant feeds `parsed` into `generate_secret_shares`, the resulting `EncryptedMessage` is produced with ECDH result `identity * ephemeral_key == identity`; the observer derives the same key from the public context and identity encoding, then applies the fixed `"DKG IV v0.2\0"` ChaCha20 IV to recover the serialized `SecretShare`.   pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
