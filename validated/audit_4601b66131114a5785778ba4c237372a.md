## Finding: Confirmed

The code at `modules/pallets/consensus-incentives/src/impls.rs` matches the vulnerability described exactly.

### Title
Reward misattribution to `messages[0]`'s signer for all `StateMachineUpdated` events in a batch - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`FeeHandler::on_executed` derives the sole reward recipient (`relayer_account`) from the signature on `messages[0]`, then pays that single account for *every* `StateMachineUpdated` event across *all* state machines present in the batch, regardless of which message actually produced each event or who signed it.

### Finding Description
`on_executed` recovers `relayer_account` only from the first message in the batch: [1](#0-0) 

It never inspects the `signer` field of any other `Message::Consensus` entries later in the batch. It then aggregates every `StateMachineUpdated` event in the whole batch into `highest_per_state_machine` (one entry per distinct `state_machine_id`) and pays the reward for each of them to the single `relayer_account` recovered from message 0: [2](#0-1) 

The batch itself is produced by `Pallet::<T>::execute(messages: Vec<Message>)`, which is invoked once per extrinsic call with the full `Vec<Message>` the caller supplies, and which forwards the *combined* result events for the whole batch to `FeeHandler::on_executed` in one shot: [3](#0-2) 

Because ISMP relaying is permissionless and consensus/state proofs are public, verifiable data (not secrets tied to a specific submitter), any unprivileged caller can:
1. Construct their own `Message::Consensus` (message index 0), sign it with their own key so `Signature::verify_and_get_sr25519_pubkey` resolves to their account.
2. Append additional, independently valid `Message::Consensus` entries for other state machines (which may be signed by different keys, or simply copied/rebuilt from publicly available consensus data for chains they did not do the "real" verification work for) into the same `Vec<Message>` passed to `execute`.

Since `handle_incoming_message` processes each message independently and produces `StateMachineUpdated` events per state machine, the resulting `events` list can contain updates for multiple, unrelated state machines. `on_executed` then attributes *all* of those rewards to the attacker's account derived solely from message 0 — completely ignoring the `signer` fields embedded in the other Consensus messages that are supposed to identify the actual relayer credited with each state machine's work.

This breaks the intended per-work relayer attribution invariant: the `signer` field inside each `ConsensusMessage` exists specifically to identify the reward recipient independent of the extrinsic origin (supporting sponsored/meta-tx relaying), but `on_executed` only honors it for the first message in the batch.

### Impact Explanation
An unprivileged actor can redirect relayer rewards for consensus updates on state machines they did not necessarily do the qualifying verification work for, by simply bundling their own signed message at index 0 alongside other legitimately valid consensus messages/events in a single batch submission. This directly matches the "wrong beneficiary" / broken reward-accounting impact called out in the Hyperbridge Pivots ("relayer rewards ... must move exactly once and only to the rightful beneficiary").

### Likelihood Explanation
Exploitation only requires the ability to submit an ISMP `handle`-style extrinsic with an attacker-controlled `Vec<Message>` ordering, and knowledge of one or more valid (publicly derivable) consensus proofs for other state machines — both of which are within reach of any unprivileged relayer under the permissionless relaying design. No compromise of another relayer's key or infrastructure is required for the core defect (misattribution keys off message index, not message content), though maximizing reward theft benefits from being the first to bundle proofs for multiple chains.

### Recommendation
Attribute each `StateMachineUpdated` reward to the signer of the specific `Message::Consensus` that produced it (matching events to messages, e.g., via `state_machine_id`/proof correlation) instead of using a single signer recovered from `messages[0]` for the entire batch's events.

### Proof of Concept
1. Attacker crafts `msg0 = Message::Consensus { consensus_proof: p0, signer: sig_attacker(p0) }` for state machine `SM0`.
2. Attacker also includes `msg1 = Message::Consensus { consensus_proof: p1, signer: sig_other(p1) }` for `SM1` and `msg2` for `SM2`, both independently valid proofs advancing those chains' commitments.
3. Attacker submits `execute([msg0, msg1, msg2])` in one extrinsic.
4. `handle_incoming_message` succeeds for all three, emitting `StateMachineUpdated` for `SM0`, `SM1`, `SM2`.
5. `on_executed` recovers `relayer_account = attacker` from `msg0` only [1](#0-0) , builds `highest_per_state_machine = {SM0: h0, SM1: h1, SM2: h2}`, and calls `Self::process_message(..., attacker)` for all three state machines [4](#0-3) , transferring rewards for `SM1` and `SM2` (which `msg1`/`msg2`'s embedded signer designates for someone else) to the attacker instead.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;
