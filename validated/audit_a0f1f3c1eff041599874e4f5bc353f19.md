### Title
Empty aggregate Schnorr signature verifies as valid - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero signatures, while `SchnorrAggregator::complete` explicitly refuses to produce such an aggregate. An attacker can therefore serialize an empty `Rs` vector with `s = 0`; `verify` then checks only `-0 * G`, which is the identity and returns `true`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`SchnorrAggregate::read` accepts a length of zero and any canonical scalar. During verification, matching empty `Rs` and `keys_and_challenges` inputs causes the verifier to construct only the statement `-s * G`; when the attacker supplies `s = 0`, the statement is vacuously satisfied. This bypasses the nonzero-size invariant enforced by the aggregation API. [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation
An unprivileged party can provide serialized bytes that are accepted as a valid aggregate signature despite no signers or signature components being present. In any caller workflow treating a verified aggregate as authorization for an associated request, this permits acceptance of an unsigned aggregate. The issue is a concrete incorrect verifier boundary rather than a malformed-encoding rejection problem. [1](#0-0) [4](#0-3) 

### Likelihood Explanation
Exploitation requires an application to deserialize an attacker-controlled `SchnorrAggregate` and invoke `verify` with an empty `keys_and_challenges` list. The attack requires no secrets, computation, races, or malformed field encodings; it is deterministic once that reachable verifier configuration exists. [1](#0-0) [5](#0-4) 

### Recommendation
Reject `Rs.is_empty()` in both `SchnorrAggregate::read` and `SchnorrAggregate::verify`, matching `SchnorrAggregator::complete`, which already returns `None` for an empty aggregation. A defense-in-depth check should also reject a zero scalar for an empty aggregate before constructing the multiexp. [1](#0-0) [2](#0-1) [3](#0-2)
