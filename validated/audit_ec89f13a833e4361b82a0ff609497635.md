### Title
Unauthenticated OP_RETURN operator attribution lets any Bitcoin broadcaster fabricate the "payer" of a withdrawal, causing an operator to be reimbursed for a payout it never funded - ([File: core/src/verifier.rs])

### Summary
The verifier's chain-sync logic determines which operator "fronted" a withdrawal purely by reading the `OP_RETURN` output of whichever transaction happens to spend the tracked withdrawal UTXO on Bitcoin, with no cryptographic proof that the named operator authorized or funded that specific transaction. Because the payout transaction's binding input signature uses `SIGHASH_SinglePlusAnyoneCanPay`, any party can construct and fund an alternative payout transaction that pays the correct user output while stamping an arbitrary registered operator's x-only public key into the `OP_RETURN`. This breaks the intended binding "operator credited == operator that actually paid," letting an unrelated (non-funding) operator's own automated `PayoutCheckerTask` be tricked into claiming reimbursement for money it never sent.

### Finding Description
`create_payout_txhandler` builds the payout transaction with an `OP_RETURN` output containing the caller-supplied `operator_xonly_pk`, and signs only input 0 with the user's presigned `SinglePlusAnyoneCanPay` signature — meaning nothing else in the transaction (extra funding inputs, the OP_RETURN content) is bound to that signature or to any operator key: [1](#0-0) 

The withdrawal-authorizing signature covers only the dust input and the payout output (script/amount), by design, via `SinglePlusAnyoneCanPay`: [2](#0-1) 

When the chain syncer detects that the tracked withdrawal UTXO has been spent, it locates the spending transaction and simply parses whatever `OP_RETURN` output it finds to determine `operator_xonly_pk`, storing it verbatim as the "payer" for that withdrawal — with no signature check binding that pubkey to the actual funder of the transaction: [3](#0-2) 

This value is persisted via `update_payout_txs_and_payer_operator_xonly_pk` and later trusted as ground truth by:
- `get_first_unhandled_payout_by_operator_xonly_pk`, which each operator's `PayoutCheckerTask` polls filtered only by `payout_payer_operator_xonly_pk = self.signer.xonly_public_key`, with no further authentication: [4](#0-3) [5](#0-4) 
- `is_kickoff_malicious`, which only checks that the OP_RETURN-derived pubkey equals the kickoff's operator pubkey, again trusting the unauthenticated OP_RETURN value as proof of "who paid": [6](#0-5) 

Because any party holding the publicly-derivable withdrawal parameters (`input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount` — the same fields sent over the `Withdraw`/`InternalWithdraw` RPCs and needed by any operator to front the payout) can independently build this same transaction, fund it with its own BTC to satisfy the exact required output, and set the `OP_RETURN` to any registered operator's `xonly_pk`, the resulting on-chain attribution is fully attacker-controlled data, exactly analogous to the ClearingHouse bug where SeaPort's fallback call data (attacker-controlled) was trusted to identify a "genuine" settlement without any authenticity check.

### Impact Explanation
Once an attacker-funded transaction is mined that pays the user correctly but carries operator X's pubkey in the OP_RETURN, operator X's own `PayoutCheckerTask` (its own automated, unattended background task) will pick up this "unhandled payout" as if it were its own and proceed through `handle_finalized_payout` → kickoff → BitVM assert/reimbursement flow, ultimately reclaiming the bridge_amount from the vault for a withdrawal that operator X never actually funded. This matches the Critical impact class "an operator reimbursed for a payout it never funded" directly, since the crediting/attribution step has zero cryptographic binding to the operator's key — the same class of failure as the ClearingHouse bug where a caller-controlled callback was blindly trusted to represent a genuine settlement.

### Likelihood Explanation
Exploitation only requires knowledge of the public withdrawal parameters (which any operator would need anyway to front the withdrawal, and which are derivable from the Citrea withdrawal record/rollup state that the withdrawal-syncing logic itself reads) and the ability to front the exact payout amount in a competing Bitcoin transaction with a higher fee/priority. No verifier, operator, or aggregator key compromise is required — the only privileged component is that operator X's honest automation will passively and automatically claim the reimbursement once the DB attributes the payout to it, with no manual review or independent verification that operator X actually broadcast that specific transaction.

### Recommendation
Bind the "payer" attribution cryptographically to the operator that constructed the payout, rather than trusting an arbitrary OP_RETURN value read from whichever transaction happens to spend the withdrawal UTXO. For example, require the payout transaction's OP_RETURN commitment (or an accompanying signature) to be signed by the operator's key over the full transaction (or at least the OP_RETURN payload + outpoint), and have `update_finalized_payouts`/`is_kickoff_malicious` verify that signature before recording or trusting the claimed `operator_xonly_pk`, so a third party cannot forge the attribution merely by embedding a public key it does not control into an unsigned output.

### Proof of Concept
1. Observe a pending Citrea withdrawal request's parameters: `withdrawal_id`, `input_signature` (SIGHASH_SinglePlusAnyoneCanPay over the dust input/output), `input_outpoint`, `output_script_pubkey`, `output_amount` (these are the same fields any operator uses to build the payout tx via `create_payout_txhandler` / the `Withdraw` RPC, see `core/src/operator.rs:560-637` and `core/src/rpc/clementine.proto:391-405`).
2. Independently construct the payout transaction: spend `input_outpoint` with the given `input_signature` on input 0, add the required output paying `output_script_pubkey`/`output_amount`, and add your own funding input(s) covering the amount (using `bitcoin::fund_raw_transaction`-style coin selection, exactly as `Operator::withdraw` does at `core/src/operator.rs:620-673`).
3. Instead of stamping your own key, set the third output's `OP_RETURN` push data to the x-only public key of a target registered operator (`op_return_txout(PushBytesBuf::from(target_operator_xonly_pk.serialize()))`, per `create_payout_txhandler` at `core/src/builder/transaction/operator_reimburse.rs:407-436`).
4. Broadcast and get this transaction mined (with sufficient fee to be preferred by miners) before the withdrawal is otherwise settled.
5. Once finalized, `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) will parse the OP_RETURN and record `payout_payer_operator_xonly_pk = target_operator_xonly_pk` in the `withdrawals` table.
6. The target operator's own `PayoutCheckerTask` (`core/src/task/payout_checker.rs:39-111`) will subsequently find this "unhandled payout" filtered by its own pubkey and automatically call `handle_finalized_payout`, driving the kickoff/reimbursement flow to claim the bridge_amount from the vault — despite that operator never having funded the payout itself.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

fn sign_withdrawal_output(
    config: &BridgeConfig,
    dust_utxo: &UTXO,
    withdrawal_address: &bitcoin::Address,
    withdrawal_amount: bitcoin::Amount,
) -> (bitcoin::TxOut, taproot::Signature) {
    let signer = Actor::new(config.secret_key, config.protocol_paramset().network);
    let txin = builder::transaction::input::SpendableTxIn::new(
        dust_utxo.outpoint,
        dust_utxo.txout.clone(),
        vec![],
        None,
    );
    let txout = bitcoin::TxOut {
        value: withdrawal_amount,
        script_pubkey: withdrawal_address.script_pubkey(),
    };
    let unspent_txout = builder::transaction::output::UnspentTxOut::from_partial(txout.clone());

    let tx = builder::transaction::TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            builder::transaction::DEFAULT_SEQUENCE,
        )
        .add_output(unspent_txout.clone())
        .finalize();

    let sighash = tx
        .calculate_sighash_txin(0, sighash::TapSighashType::SinglePlusAnyoneCanPay)
        .expect("Failed to calculate sighash");

    let sig = signer
        .sign_with_tweak_data(sighash, builder::sighash::TapTweakData::KeyPath(None), None)
        .expect("Failed to sign");

    let sig = taproot::Signature {
        signature: sig,
        sighash_type: sighash::TapSighashType::SinglePlusAnyoneCanPay,
    };

    (txout, sig)

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
