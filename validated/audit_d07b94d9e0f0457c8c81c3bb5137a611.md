### Title
App Proxy signature verification lacks timestamp freshness check, permitting indefinite replay of Shopify-signed proxy requests - (File: lib/shopify_app/controller_concerns/app_proxy_verification.rb)

### Summary
`ShopifyApp::AppProxyVerification` verifies that an incoming app-proxy request's `signature` query parameter matches an HMAC computed over the other query parameters (which include a `timestamp` value supplied and signed by Shopify), but it never checks that the `timestamp` is recent. This mirrors the reported bug class: signed data is accepted outside the context/time window it was intended for because a value that is present in the signed payload (here, `timestamp`, analogous to the missing `chainId`) is never validated by the verifier.

### Finding Description
`query_string_valid?` and `calculated_signature` in `lib/shopify_app/controller_concerns/app_proxy_verification.rb` recompute the HMAC over all query parameters except `signature` and compare it (constant-time) to the supplied `signature`: [1](#0-0) 

The verification logic only checks that the signature matches the (shop, path_prefix, timestamp, and any custom) parameters — it never inspects or bounds `timestamp` itself. As a result, any request URL that was ever validly signed by Shopify for this app's proxy endpoint (e.g., one that leaked via browser history, a shared link, server access logs, a Referer header sent to a third party, or a proxied CDN cache) remains a "valid" request forever, since the signature check has no notion of expiry. This is the same root defect pattern as the reported issue — a value that should scope/bind the validity of the signed data (chain-id there, timestamp here) is present in the payload but not enforced by the verifier — so previously-issued signed requests can be replayed outside their intended validity window.

### Impact Explanation
Any endpoint protected only by `ShopifyApp::AppProxyVerification` (the standard mechanism recommended for app-proxy controllers, e.g. the generated `AppProxyController`) will accept a replayed, Shopify-signed request indefinitely after it was first issued. If the app-proxy endpoint performs any state-changing or sensitive action (not just read-only storefront rendering), an attacker who captures a previously valid signed proxy URL (through logs, caches, or leaked links) can replay it at any later time to have it accepted as if it were a fresh, legitimate Shopify-forwarded request — an accepted forged/replayed signed request.

### Likelihood Explanation
Exploitation requires an attacker to first obtain a previously-signed app-proxy URL (e.g., from logs, shared links, browser/proxy caches, or a captured Referer). This is a realistic but not universal exposure vector; likelihood is moderate and depends on how/whether such URLs leak in a given deployment and whether the app-proxy controller performs non-idempotent actions.

### Recommendation
Extract and validate the `timestamp` query parameter in `verify_proxy_request`/`query_string_valid?`, rejecting requests whose timestamp is outside a small acceptable window (e.g., a few minutes), in addition to the existing signature check, per Shopify's own app-proxy verification guidance.

### Proof of Concept
1. Capture (or replay from logs) a previously valid, Shopify-signed app-proxy request URL, e.g.:
   `GET /app_proxy/basic?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid-signature>`
2. Send this exact request at any later time (days/months after `timestamp`).
3. `query_string_valid?` recomputes the HMAC over the same parameter set and it still matches `signature`, so `verify_proxy_request` allows the request through — as demonstrated by the existing test fixture where a fixed, long-past `timestamp=1466106083` and its precomputed signature still validate successfully with no freshness check: [2](#0-1)

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
