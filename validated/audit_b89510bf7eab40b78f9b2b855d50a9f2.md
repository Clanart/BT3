### Title
`resolve-ststx` aborts on `call-ststx-ratio` external-call failure, permanently freezing liquidation of all stSTX/zstSTX-collateralized positions - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
`resolve-ststx` unwraps the result of `call-ststx-ratio` with `(unwrap! ... ERR-ORACLE-CALLCODE)`, and `call-ststx-ratio` is a bare, unguarded pass-through of an external contract call to `'SP4SZE494VC2YC5JYG7AYFQ44F5Q4PYV7DVMDPBG.block-info-nakamoto-ststx-ratio-v2 get-ststx-ratio-v3`. If that external contract ever returns `(err ...)` (paused, upgraded/ABI-mismatched, or reverted), every code path that prices stSTX or zstSTX collateral (via `resolve-callcode` → `price-resolve` → `get-assets`, used by health checks and `liquidate`) aborts entirely.

### Finding Description
Tracing the price path for stSTX collateral: `price-resolve` (mainnet/contracts/market/v0-4-market.clar:373-395) calls `resolve-callcode` (lines 349-358), which for `CALLCODE-STSTX` (0x00) or `CALLCODE-ZSTSTX` (0x03) invokes `resolve-ststx` (lines 339-341):
```
(define-private (resolve-ststx (p uint))
  (let ((ratio (unwrap! (call-ststx-ratio) ERR-ORACLE-CALLCODE)))
    (ok (mul-div-down p ratio STSTX-RATIO-DECIMALS))))
```
`call-ststx-ratio` (lines 1015-1016) is:
```
(define-public (call-ststx-ratio)
  (contract-call? 'SP4SZE494VC2YC5JYG7AYFQ44F5Q4PYV7DVMDPBG.block-info-nakamoto-ststx-ratio-v2 get-ststx-ratio-v3))
```
This has no fallback, no cached last-known-good ratio, and no defensive handling — the raw `Response` from the external contract is returned as-is. If that external contract's call reverts, is paused, or its trait signature no longer matches (e.g. after an upgrade), the `contract-call?` yields `(err ...)`, which propagates through `call-ststx-ratio` → `unwrap!` in `resolve-ststx` fails and returns `ERR-ORACLE-CALLCODE` → `resolve-callcode` returns that error → `price-resolve` returns that error via `try!` → any caller depending on stSTX/zstSTX pricing (health checks, `liquidate`, collateral/borrow operations for the egroup) aborts with `ERR-ORACLE-CALLCODE`, never reaching the LTV/health math.

There is no gate downstream (no disabled-collateral fallback, no stale-price fallback) that recovers from this failure for the pricing of stSTX itself — `oracle-price-legal`/`oracle-timestamp-fresh` in `price-resolve` are never reached because the abort happens earlier, inside `resolve-callcode`.

### Impact Explanation
Direction: neither collateral is overvalued nor debt undervalued numerically — instead, the entire pricing/health computation for any position holding stSTX or zstSTX collateral becomes uncomputable, so `liquidate` (and other operations depending on `get-assets`/`price-resolve` for that egroup) always reverts. An underwater borrower (current-ltv ≥ ltv-liq-partial) cannot be liquidated while the upstream ratio contract is broken/paused, allowing bad debt to accrue at the protocol's expense; this matches the in-scope "permanent freezing of funds / protocol insolvency" category, assuming the upstream failure persists (which is plausible for contract pauses/upgrades and is not something this code defends against).

### Likelihood Explanation
This does not require a privileged attacker — it is a systemic robustness gap in the collateral-pricing pipeline that manifests any time the external ratio contract is unavailable (pause, revert, ABI change). An unprivileged actor cannot directly trigger the external contract's failure, but once it occurs (e.g., an upgrade to `block-info-nakamoto-ststx-ratio-v2` that changes its interface, or the contract being paused by its own operators), every liquidator's `liquidate` call against stSTX-collateralized positions will deterministically fail with `ERR-ORACLE-CALLCODE`, and this is fully repeatable/deterministic for as long as the dependency is broken.

### Recommendation
Add resilience around the ststx ratio call in `resolve-ststx`/`call-ststx-ratio`: cache the last successfully observed ratio (similar to `oracle-last-update`/index caching used elsewhere) and fall back to it (with a staleness bound) if the live call errors, or expose a DAO-controlled circuit breaker path that allows liquidation to proceed using a last-known-good ratio rather than hard-aborting the entire health/liquidation computation on a single external call failure.

2. Register stSTX (aid=2) as collateral with `callcode: (some CALLCODE-STSTX)` per existing egroup config, and open a borrower position with stSTX collateral and a debt asset such that `current-ltv >= ltv-liq-partial`.
3. As the liquidator, call `liquidate(borrower, stSTX-ft, debt-ft, ...)`.
4. Assert the call returns `(err u400011)` (`ERR-ORACLE-CALLCODE`), confirming the abort happens inside `resolve-ststx`/`call-ststx-ratio` before any LTV/health computation, and that this is deterministic and repeatable across attempts as long as the mocked ratio contract keeps erroring. (define-private (price-resolve
```text
  (data { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint }))
  (let ((type (get type data))
        (ident (get ident data))
        (key { type: type, ident: ident })
        (resolution (try! (resolve-price-feed type ident)))
        (price (get value resolution))
        (callcode (get callcode data))
        (final-price (try! (resolve-callcode price callcode)))
        (last-update-time (oracle-last-update key))
        (timestamp (get timestamp resolution))
        (max-staleness (get max-staleness data)))

    ;; validate price and timestamp using max-staleness from oracle data
    (asserts! (and (oracle-price-legal final-price) (oracle-timestamp-fresh timestamp last-update-time max-staleness))
              ERR-ORACLE-INVARIANT)

    ;; update timestamp if newer
    (if (> timestamp last-update-time)
        (map-set last-update key timestamp)
        false)

    (ok final-price)))
```
