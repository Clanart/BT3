### Title
Tokenfactory `DenomAllowList` restriction can be bypassed via CosmWasm contract fund transfers - ([File: sei-wasmd/x/wasm/keeper/keeper.go])

### Summary
The `x/bank` module's tokenfactory `DenomAllowList` feature is a Sei-native, ERC-1404-like restriction mechanism: a denom creator can restrict which addresses may send or receive a given `factory/...` denom [1](#0-0) . This restriction is correctly enforced in the normal `MsgSend`/`MsgMultiSend` path via `IsInDenomAllowList`, checked for both sender and receiver [2](#0-1) . However, CosmWasm contracts move coins through a different code path, `BankCoinTransferrer.TransferCoins`, which only checks `IsSendEnabledCoins` and `BlockedAddr`, never `IsInDenomAllowList` [3](#0-2) . This mirrors the reported Centrifuge bug class: one transfer-restriction-enforcing code path (`MsgSend`) exists alongside an alternate one (CW fund transfers) that omits the restriction check entirely.

### Finding Description
`SendKeeper.IsInDenomAllowList` is the sole allow-list enforcement primitive in `x/bank`, and it is invoked only from `msgServer.Send` and `msgServer.MultiSend` [4](#0-3) . The lower-level `BaseSendKeeper.SendCoins` itself does not perform this check [5](#0-4) , meaning any caller of `SendCoins` other than the bank message server silently skips the allow-list restriction.

`sei-wasmd`'s `BankCoinTransferrer`, used to move coins alongside `MsgExecuteContract`/`MsgInstantiateContract` `Funds`, calls `SendCoins` directly after only validating `IsSendEnabledCoins` and `BlockedAddr(toAddr)`: [3](#0-2) 

This transferrer is wired into the wasm `Keeper` by default: [6](#0-5) 

Since it never calls `IsInDenomAllowList`, a non-member address (one not present in a tokenfactory denom's `AllowList`) can still transfer that restricted denom to a CosmWasm contract via `Funds` on `MsgExecuteContract`/`MsgInstantiateContract`, or a contract itself can move such restricted coins to a non-member `Funds` recipient in a sub-message call, entirely bypassing the compliance/whitelist mechanism that the same denom's issuer relies on when using `MsgSend`.

### Impact Explanation
The `DenomAllowList` mechanism is Sei's mechanism for compliance-restricted tokenfactory assets (analogous to the ERC-1404 member/frozen list in the referenced report). Bypassing it via the CosmWasm funds-transfer path allows unauthorized/blacklisted or non-member addresses to receive or route restricted tokens, defeating the regulatory/whitelist guarantee the token issuer configured. This is an unauthorized-transfer-of-restricted-asset condition reachable by any CosmWasm user (`MsgExecuteContract`/`MsgInstantiateContract` with `Funds`), matching the "unauthorized transfer via precompile or pointer"-class impact for compliance-gated assets, though it does not itself directly mint/burn/freeze native `usei`.

### Likelihood Explanation
Likelihood is Medium: it requires a token creator to have actually configured a `DenomAllowList` for a `factory/...` denom (an opt-in feature), and it requires interacting with a CosmWasm contract via `Funds`. No special privileges are needed beyond being able to submit a standard `MsgExecuteContract`/`MsgInstantiateContract`, which any address can do.

### Recommendation
Add an `IsInDenomAllowList` check (for both the `fromAddr` and `toAddr`) inside `BankCoinTransferrer.TransferCoins` in `sei-wasmd/x/wasm/keeper/keeper.go`, mirroring the checks already present in `x/bank`'s `msgServer.Send`/`MultiSend`, so that CosmWasm-driven coin movement cannot circumvent tokenfactory denom allow lists.

### Proof of Concept
1. A denom creator creates `factory/<creator>/RESTRICTED` and sets a `DenomAllowList` containing only a small set of addresses via `SetDenomAllowList`/`MsgUpdateDenom` [7](#0-6) .
2. An address `X` that is NOT in the allow list holds some `RESTRICTED` coins (e.g., obtained directly from the minter/admin outside `MsgSend`, or is itself the admin).
3. `X` submits `MsgExecuteContract` (or `MsgInstantiateContract`) targeting any CosmWasm contract, attaching `Funds` denominated in `RESTRICTED` and sending them to a contract address `C`, where neither `X` nor `C` is in the `AllowList`.
4. This funds transfer is executed through `BankCoinTransferrer.TransferCoins`, which checks only `IsSendEnabledCoins` and `BlockedAddr(C)` — never `IsInDenomAllowList` — so the transfer succeeds despite `X`/`C` not being members, whereas the same transfer attempted via a direct `MsgSend` would be rejected with `"... is not allowed to send/receive funds"` [2](#0-1) .

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
	for _, e := range em.Events() {
		if e.Type == sdk.EventTypeMessage { // skip messages as we talk to the keeper directly
			continue
		}
		parentCtx.EventManager().EmitEvent(e)
	}
	return nil
}
