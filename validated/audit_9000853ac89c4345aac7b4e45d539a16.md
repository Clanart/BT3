### Title
Unrecovered panic in the `pointer` precompile from unchecked type assertions on attacker-controlled CosmWasm query responses - (File: precompiles/pointer/pointer.go)

### Summary
`AddCW20`, `AddCW721`, and `AddCW1155` in the pointer precompile query an arbitrary CosmWasm contract (`token_info`/`contract_info`) and then perform unchecked type assertions `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)` on the decoded JSON response, without checking that these keys exist or are strings.

### Finding Description
Any EVM caller can invoke `addCW20Pointer` / `addCW721Pointer` / `addCW1155Pointer` against a CosmWasm contract address they control. The precompile calls `p.wasmdKeeper.QuerySmartSafe` against that contract, decodes the returned JSON into `map[string]interface{}{}`, and then does: [1](#0-0) [2](#0-1) [3](#0-2) 

If the queried contract's `token_info`/`contract_info` handler returns a JSON object where `"name"` or `"symbol"` is absent (decodes to `nil`) or is a non-string type (number, bool, array, object), the type assertion `interface{}.(string)` panics because there is no `, ok` check. Since the contract's query response is fully attacker-controlled (the caller writes and deploys the CosmWasm contract themselves, or targets any deployed contract that happens to omit these fields), this is directly reachable and triggerable by an unprivileged transaction — the same bug class as Nomad's artifact-stanza panic, where an attacker-supplied malformed input (there, a bad S3/GCS URL; here, a malformed/missing JSON field in a query response) hits an unchecked parse/assert path.

Unlike `wasmd.query()` in the wasmd precompile, which wraps its execution in a `defer recover()` (see `precompiles/wasmd/legacy/v552/wasmd.go:474-482`), the pointer precompile's `AddCW20`/`AddCW721`/`AddCW1155` executor methods have no such recovery. The outer dynamic-gas precompile wrapper (`precompiles/common/precompiles.go` `RunAndCalculateGas`, and its `chargeDecodeGas` defer) only recovers `sdk.ErrorOutOfGas`/`sdk.ErrorGasOverflow` panics from its own charging step and explicitly re-panics anything else: [4](#0-3) 
This means a panic raised inside `d.executor.Execute(...)` (i.e., inside `AddCW20`/`AddCW721`/`AddCW1155`) is not caught there and propagates upward through the EVM interpreter into the transaction-processing stack.

### Impact Explanation
Whether this crashes a node depends on whether a higher layer (`runTx`/`DeliverTx`/giga executor) recovers arbitrary panics. The codebase does have broad recovery middleware at `sei-cosmos/baseapp/baseapp.go` `runTx` and `app/legacyabci/deliver_tx.go`/`app/app.go` `makeGigaDeliverTx`, which recover generic panics into `ErrPanic` ABCI responses rather than crashing the process: [5](#0-4) [6](#0-5) 
Given this defense-in-depth, the panic is likely converted into a failed/reverted transaction (`ErrPanic`) rather than a full node crash for `DeliverTx`/normal transaction execution. However, this still represents a validated input-handling gap that deviates from the pattern used elsewhere in the same precompile family (`wasmd.query` explicitly guards with `recover()`), and any code path that calls this precompile logic outside of the recovery-wrapped `runTx`/giga paths (e.g., `eth_call`/`eth_estimateGas` simulation paths in `evmrpc/`, or `CheckTx`) could behave differently. I could not conclusively verify a path that bypasses all panic recovery layers and reaches raw `net/http` handling to definitively confirm an RPC-node crash of the CVE-2022-41606 severity; this uncertainty should be resolved by testing `eth_call`/`eth_estimateGas`/`eth_sendRawTransaction` against a maliciously-responding CW20/CW721 contract to confirm whether recovery holds in every RPC-reachable execution path.

### Likelihood Explanation
High reachability: creating a CosmWasm contract with a `token_info`/`contract_info` handler that omits `name`/`symbol` or returns non-string values, then calling `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against it, requires no special privileges — it is available to any transaction sender with gas to pay. The trigger condition (malformed contract response) is entirely under attacker control.

### Recommendation
Replace the unchecked type assertions in `AddNative` (already partially guarded), `AddCW20`, `AddCW721`, and `AddCW1155` with safe, checked assertions (`v, ok := formattedRes["name"].(string); if !ok { return nil, 0, fmt.Errorf(...) }`), matching the defensive pattern already used in `precompiles/wasmd/legacy/v552/wasmd.go`'s `query()` recover wrapper. Apply the same fix across all versioned copies of `pointer.go` under `precompiles/pointer/legacy/`.

### Proof of Concept
1. Deploy a CosmWasm contract whose `QueryMsg::TokenInfo {}` (or `ContractInfo {}`) handler returns `{"decimals": 18}` (omitting `name`/`symbol`), or returns `{"name": 123, "symbol": true}`.
2. From any EVM account, call `addCW20Pointer(contractAddr)` (or the CW721/CW1155 equivalents) on the pointer precompile at `0x000000000000000000000000000000000000100b`.
3. Observe that `p.wasmdKeeper.QuerySmartSafe` succeeds and returns the malformed JSON, `json.Unmarshal` succeeds into `map[string]interface{}`, and `formattedRes["name"].(string)` panics with an interface conversion error, propagating out of `Execute` uncaught by the pointer precompile itself. // chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
