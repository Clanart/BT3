Audit Report

## Title
Repair-nonce eviction allows unauthenticated remote DoS of shred repair - ([File: core/src/repair/outstanding_requests.rs])

## Summary
`OutstandingRequests::register_response` deletes ("invalidates") a pending outstanding repair request from its LRU cache whenever a packet with a matching nonce fails `verify_response` or has expired, and this function is reachable from an unauthenticated packet-receive path (`verify_repair_nonce` in `core/src/shred_fetch_stage.rs`) that performs no sender-address or signature check before calling it. An attacker who can guess or brute-force a live 32-bit nonce out of the bounded 16,384-entry cache can pre-empt and evict a victim's legitimate outstanding repair request before the real response arrives, forcing the request to fall back to the 60-second expiration/retry cycle.

## Finding Description
`OutstandingRequests::register_response` looks up `nonce` in its LRU cache and, if the associated request's `verify_response` fails (or the request has expired), explicitly marks the entry `should_delete = true` and removes it from the cache before returning `None`: [1](#0-0) 

This is called from `verify_repair_nonce` in the shred-fetch/repair receive path, which extracts a shred and trailing nonce from *any* packet flagged `PacketFlags::REPAIR` and calls `register_response` with no check that the packet originated from the peer the request was actually sent to: [2](#0-1) 

The nonce space is a full `u32`, while the cache used to track outstanding requests is capped at 16,384 entries: [3](#0-2) 

The same call pattern — unauthenticated packet parsing followed directly by `register_response`, with deletion on verification failure — also appears in `core/src/repair/ancestor_hashes_service.rs` and `core/src/repair/block_id_repair_service.rs`.

However, close inspection of the actual `verify_response` implementations for the shred-repair analog (`ShredRepairType`) shows they check the shred's slot and index against the *specific* outstanding request (e.g., `ShredRepairType::Shred(slot, index)` requires `shred_slot == *slot && get_shred_index(shred) == Some(*index)`): [4](#0-3) 

This does not change the core defect: `register_response` deletes the entry whenever `verify_response` returns `false` — which is exactly what happens for essentially any spoofed/garbage packet with a matching nonce but arbitrary or mismatched slot/index, since forging a correctly matching slot+index is not required to trigger the eviction, only to guess the nonce. To reach this code, an attacker's packet must still parse successfully as a shred with a trailing nonce via `shred::layout::get_shred_and_repair_nonce` (referenced in `verify_repair_nonce`), which requires conforming to the shred wire layout, but I was unable to fully confirm from the index whether this layout parsing enforces cryptographic signature verification or only structural/length checks — this remains a genuine gap in my analysis given the tool budget. If only structural parsing is required (no signature check), the claim's exploit path holds as described.

## Impact Explanation
If the parsing step (`get_shred_and_repair_nonce`) does not require a valid shred signature, an unauthenticated remote attacker can flood the repair-response UDP port with garbage shred-shaped packets carrying varied nonces. Any packet matching a live nonce (own probability ≈ 16384/2^32 per packet, given the bounded cache vs. full nonce space) causes `register_response` to delete the victim's real outstanding request before the legitimate response arrives, and the legitimate response is subsequently dropped as "unexpected nonce" per `verify_repair_nonce`'s `.is_some()` check. This degrades a validator's ability to complete shred/ancestor-hash/block-id repair in a timely manner, falling within the "non-RPC remote exhaustion/degradation" impact class for repair.

## Likelihood Explanation
The attack requires no stake, no valid keypair, and no privileged network position, only the ability to send UDP packets to the target's repair-response port, satisfying the "unprivileged, public inputs" requirement. The main uncertainty affecting real-world feasibility is whether `shred::layout::get_shred_and_repair_nonce` enforces cryptographic shred-signature validity before returning a parsed shred+nonce pair; if it does, the practical brute-force cost rises substantially since an attacker would need a validly-signed shred (which normally requires collusion with, or capture of packets from, a real leader/validator) rather than pure garbage bytes, materially reducing likelihood. This could not be confirmed from the available index within the tool budget.

## Recommendation
- Bind response acceptance to the socket address/pubkey the corresponding request was actually sent to, rejecting responses from unexpected peers before calling `register_response`.
- Avoid eagerly deleting (`should_delete = true`) an outstanding request purely because a single response fails `verify_response`; rely on the existing expiration timer (`DEFAULT_REQUEST_EXPIRATION_MS`) instead of first-failure eviction, so a single spoofed packet cannot pre-empt the legitimate response.
- Confirm and, if necessary, strengthen the structural/signature checks performed in `shred::layout::get_shred_and_repair_nonce` so that garbage packets cannot cheaply reach `register_response` at all.

## Proof of Concept
1. Attacker crafts UDP packets shaped to pass `shred::layout::get_shred_and_repair_nonce` parsing (shred bytes + trailing nonce), with varied 32-bit nonce values, and floods the victim's repair socket.
2. For any nonce matching a live outstanding request, `verify_repair_nonce` → `register_response` finds the entry; because the injected shred's slot/index do not match the actual request, `ShredRepairType::verify_response` returns `false`, `should_delete` is set, and the entry is evicted per `core/src/repair/outstanding_requests.rs` L74-78/88-92.
3. The real repair peer's genuine response later arrives; `register_response` no longer finds the nonce (returns `None`), `verify_repair_nonce`'s `.is_some()` is `false`, and the packet is discarded — reproducible via a unit test that: (a) inserts a request via `add_request`, (b) calls `register_response` once with a deliberately mismatched/garbage response and observes the entry is removed via `pop`, then (c) calls `register_response` again with the correct response and observes it now returns `None` instead of succeeding.
4. Whether step 1 is achievable with unsigned garbage bytes (full DoS feasibility) versus requiring a validly-signed shred (much higher attacker cost) depends on the unconfirmed signature-check behavior of `shred::layout::get_shred_and_repair_nonce`, which should be verified in a follow-up session with full file access to `ledger/src/shred/wire.rs` and `ledger/src/shred/layout.rs`.

    pub fn register_response<R>(
        &mut self,
        nonce: u32,
        response: &S,
        now: u64,
        success_fn: impl Fn(&T) -> R,
    ) -> Option<R> {
        let mut should_delete = false;
        let response = self.requests.get_mut(&nonce).and_then(|status| {
            if status.num_expected_responses == 0 {
                // No more expected responses
                return None;
            }

            if now >= status.expire_timestamp || !status.request.verify_response(response) {
                // Invalid/expired response should invalidate this nonce.
                should_delete = true;
                return None;
            }

            status.num_expected_responses -= 1;
            if status.num_expected_responses == 0 && status.metadata.is_none() {
                // No metadata, and no more expected responses safe to delete eagerly.
                should_delete = true;
            }
            Some(success_fn(&status.request))
        });

        if should_delete {
            self.requests
                .pop(&nonce)
                .expect("request must exist when marked for deletion");
        }
        response
    }

fn verify_repair_nonce(
    packet: PacketRef,
    now: u64, // solana_time_utils::timestamp()
    outstanding_repair_requests: &mut OutstandingShredRepairs,
) -> bool {
    debug_assert!(packet.meta().flags.contains(PacketFlags::REPAIR));
    let Some((shred, Some(nonce))) = shred::layout::get_shred_and_repair_nonce(packet) else {
        return false;
    };
    outstanding_repair_requests
        .register_response(nonce, shred, now, |_| ())
        .is_some()
}

    fn verify_response(&self, shred: &Self::Response) -> bool {
        #[inline]
        fn get_shred_index(shred: &[u8]) -> Option<u64> {
            shred::layout::get_index(shred).map(u64::from)
        }
        let Some(shred_slot) = shred::layout::get_slot(shred) else {
            return false;
        };
        match self {
            ShredRepairType::Orphan(slot) => shred_slot <= *slot,
            ShredRepairType::HighestShred(slot, index) => {
                shred_slot == *slot && get_shred_index(shred) >= Some(*index)
            }
            ShredRepairType::Shred(slot, index) => {
                shred_slot == *slot && get_shred_index(shred) == Some(*index)
            }
            ShredRepairType::ShredForBlockId {
                slot,
                index,
                fec_set_merkle_root,
                ..
            } => {
                shred_slot == *slot
                    && matches!(shred::layout::get_shred_type(shred), Ok(ShredType::Data))
                    && shred::layout::get_index(shred) == Some(*index)
                    && get_merkle_root(shred) == Some(*fec_set_merkle_root)
            }
        }
    }
}
