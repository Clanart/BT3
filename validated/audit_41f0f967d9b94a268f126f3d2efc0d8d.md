### Title
`bridge_circuit` accepts an attacker-chosen `payout_input_index` with no output-binding or exclusivity check, letting one payout transaction satisfy two distinct withdrawals' proof-of-payment — ([File: circuits-lib/src/bridge_circuit/mod.rs])

### Summary
`bridge_circuit` in `circuits-lib/src/bridge_circuit/mod.rs` verifies withdrawal payment solely by checking that `payout_spv.transaction.input[payout_input_index].previous_output` equals the `(txid, vout)` produced by `verify_storage_proofs` for a given `storage_proof.index`, where `payout_input_index` is a host-supplied `u32` that is never independently recomputed inside the guest. Because Citrea's `withdraw`/`safeWithdraw` call lets any unprivileged caller pick arbitrary outpoint bytes as the "withdrawal UTXO" for its own index, and because the payout tx's user input uses `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY` (which does not commit to any other input in the transaction), an attacker can register a second withdrawal whose UTXO equals some other input the attacker adds to an honest operator's real payout transaction, causing the same confirmed transaction to satisfy the `assert_eq!` checks for two different `storage_proof.index` values.

### Finding Description
Binding claimed to be broken: for storage index `i`, `verify_storage_proofs(sp_i)` returns `(user_wd_outpoint_i, vout_i, move_txid_i)`, and the circuit asserts
```
input.payout_spv.transaction.input[payout_input_index].previous_output.txid  == user_wd_txid_i
input.payout_spv.transaction.input[payout_input_index].previous_output.vout  == vout_i
``` [1](#0-0) 
This is the *only* check tying a Bitcoin payment event to a specific Citrea withdrawal index; there is no check that the output at the same tx position (or any output) actually pays the recipient/amount registered for withdrawal `i`, and no check that a given payout tx or a given input index can only be "consumed" once across different index proofs.

`payout_input_index` itself is produced host-side by a linear scan matching on `previous_output.txid` only (`get_payout_input_index`), and is passed through unchecked into the guest input `BridgeCircuitInput.payout_input_index`: [2](#0-1) [3](#0-2) 
The guest never re-derives or cross-checks this index against the transaction; it trusts whatever value the host supplies.

Root cause and exploit path:
1. Citrea's withdrawal registration lets the caller supply arbitrary outpoint bytes as the withdrawal UTXO for any withdrawal index (confirmed by the `collect_withdrawal_utxos`/`withdraw` flow, which stores whatever `(txid, vout)` bytes are passed to the contract) [4](#0-3) . An attacker registers withdrawal B's UTXO to equal an outpoint they themselves control.
2. The real payout transaction (built by `create_payout_txhandler`) authorizes only the withdrawal-A input via `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY` [5](#0-4) . `ANYONECANPAY` signatures commit only to the signed input and the output at the *same index*; they do not commit to any other input added to the transaction, so any unprivileged party who can broadcast Bitcoin transactions can add an additional input of their own (e.g. via RBF while the payout is still unconfirmed) to the same transaction without invalidating the A input's signature.
3. If the attacker's added input happens to spend the outpoint they registered as withdrawal B's UTXO, this single confirmed transaction now has: index `k` truly paying A (with a real committed output), and index `j` (attacker's own input, no output committed to it) that just happens to equal B's registered outpoint.
4. On-chain detection of "payout happened" is done purely by watching for a registered withdrawal UTXO being spent anywhere on chain (`insert_spent_utxo` / `get_payout_txs_for_withdrawal_utxos`), with no requirement that the spend correspond to a dedicated output for that withdrawal [6](#0-5) . This causes the same `payout_txid` to be recorded against both index A and index B.
5. When the bridge circuit proof is generated for index B, `get_payout_input_index` will find the attacker's injected input `j` (its scan only matches `previous_output.txid`), and the guest's two `assert_eq!`s pass — even though transaction slot `j` never paid anyone matching B's actual recipient/amount, because the circuit performs no such check.
6. `deposit_constant` binds `move_txid` (from the same, now-forged storage proof `i=B`), `round_txid`, and `kickoff_round_vout` from B's own kickoff [7](#0-6) , so the resulting journal looks fully valid and distinct from A's journal, satisfying "distinct-looking but simultaneously satisfiable" proofs from a single Bitcoin funding event.

No existing guard closes this gap: `verify_storage_proofs` only authenticates the *values* Citrea stored (which the attacker legitimately controls at registration time) [8](#0-7) ; `SPV::verify` only proves the transaction is mined, not that a particular input funds a particular recipient; and the disprove/challenge path (`verify_additional_disprove_conditions`) recomputes the exact same `deposit_constant` using the same unchecked binding, so it cannot detect the discrepancy either [9](#0-8) .

### Impact Explanation
This lets an operator's proof-of-payment for withdrawal B be manufactured from a transaction that never actually paid B, causing the operator to be credited with reimbursement for a withdrawal it never funded ("Critical - an operator reimbursed for a payout it never funded"). Because reimbursement is paid from the operator's collateral/round-tx pool rather than the move-to-vault UTXO directly, this is repeatable per attacker-registered withdrawal index and per operator, and does not require compromising any key material, the aggregator, or Citrea — only the ability to register a withdrawal UTXO on Citrea and to broadcast/replace a Bitcoin transaction before it confirms (both available to an unprivileged user per the threat model).

### Likelihood Explanation
Requires: (1) attacker registers a withdrawal UTXO (B) whose outpoint they control and can also spend as an ordinary Bitcoin input; (2) attacker can observe/replace an operator's unconfirmed payout transaction for a different withdrawal (A) to append their own additional input before it confirms (RBF-style malleability, standard/cheap, only costs marginal fees); (3) the operator or its automated payout-checker then unknowingly treats the doubly-consuming transaction as payment proof for both A and B. No mainnet funds beyond normal fees are required to demonstrate the core defect at the circuit level.

### Recommendation
In `bridge_circuit`, do not trust host-supplied `payout_input_index` at face value. At minimum:
- Re-derive the payout input index inside the guest (mirroring `get_payout_input_index`) rather than trusting the host value, and additionally verify uniqueness (no other input in the same transaction matches any *other* withdrawal outpoint being proven in a separate circuit run needs to be prevented structurally, not by convention).
- Require that the input's SIGHASH_SINGLE|ANYONECANPAY-committed output (the output at the *same index* as the spent input) matches the withdrawal's registered recipient script/amount from Citrea state, closing the "any spend counts as payment" gap.
- Consider rejecting payout transactions containing extraneous, non-anchor/non-OP_RETURN inputs beyond the ones the protocol itself constructs (user input + optional move-tx input), so third parties cannot append arbitrary additional inputs via ANYONECANPAY malleability.

### Proof of Concept
In `circuits-lib/src/bridge_circuit/mod.rs` (unit-test scope, no mainnet/Citrea required):
1. Construct a single `Transaction` `payout_tx` with two inputs: input 0 spends outpoint `OA` (paired with a real output 0 paying a chosen script/amount), input 1 spends outpoint `OB` (no corresponding output needs to exist for `OB` beyond satisfying signature validity for the test harness).
2. Build `StorageProof` fixtures `sp_A` and `sp_B` (following `storage_proof.rs`'s test pattern) such that `verify_storage_proofs(&sp_A, root)` returns `(OA.txid, OA.vout, move_txid_A)` and `verify_storage_proofs(&sp_B, root)` returns `(OB.txid, OB.vout, move_txid_B)`.
3. Build two `BridgeCircuitInput`s that share the same `payout_spv.transaction = payout_tx` and differ only in `sp` and `payout_input_index` (0 for A, 1 for B).
4. Assert both calls to `bridge_circuit(...)` (or the underlying `assert_eq!` block extracted for testing) complete without panicking, and that the two resulting `journal_hash` values differ (proving they are treated as two independent, valid withdrawal-payment proofs) despite deriving from the same Bitcoin funding event and the same `payout_spv.transaction`.

fn get_payout_input_index(
    wd_txid: Txid,
    payout_tx: &Transaction,
) -> Result<u32, BridgeCircuitHostParamsError> {
    for (index, input) in payout_tx.input.iter().enumerate() {
        if input.previous_output.txid == wd_txid {
            return u32::try_from(index).map_err(|_| {
                // This should never happen
                BridgeCircuitHostParamsError::PayoutInputIndexTooLarge(index)
            });
        }
    }
    Err(BridgeCircuitHostParamsError::PayoutInputIndexNotFound)
}

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

pub fn verify_storage_proofs(
    storage_proof: &StorageProof,
    state_root: [u8; 32],
) -> (WithdrawalOutpointTxid, u32, MoveTxid) {
    let utxo_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_utxo)
            .expect("Failed to deserialize UTXO storage proof");

    let vout_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_vout)
            .expect("Failed to deserialize vout storage proof");

    let deposit_storage_proof: EIP1186StorageProof =
        serde_json::from_str(&storage_proof.storage_proof_deposit_txid)
            .expect("Failed to deserialize deposit storage proof");

    let storage_address: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(UTXOS_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let storage_key_utxo: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2);

    let storage_key_vout: alloy_primitives::Uint<256, 4> =
        storage_address + U256::from(storage_proof.index * 2 + 1);

    let storage_address_deposit: U256 = {
        let mut keccak = Keccak256::new();
        keccak.update(DEPOSIT_STORAGE_INDEX);
        let hash = keccak.finalize();
        U256::from_be_bytes(
            <[u8; 32]>::try_from(&hash[..]).expect("Hash slice has incorrect length"),
        )
    };

    let deposit_storage_key: alloy_primitives::Uint<256, 4> =
        storage_address_deposit + U256::from(storage_proof.index);

    let deposit_storage_key_bytes = deposit_storage_key.to_be_bytes::<32>();

    if deposit_storage_key_bytes != deposit_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid deposit storage key. left: {:?} right: {:?}",
            deposit_storage_key_bytes,
            deposit_storage_proof.key.as_b256().0
        );
    }

    if storage_key_utxo.to_be_bytes() != utxo_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal UTXO storage key. left: {:?} right: {:?}",
            storage_key_utxo.to_be_bytes::<32>(),
            utxo_storage_proof.key.as_b256().0
        );
    }

    if storage_key_vout.to_be_bytes() != vout_storage_proof.key.as_b256().0 {
        panic!(
            "Invalid withdrawal vout storage key. left: {:?} right: {:?}",
            storage_key_vout.to_be_bytes::<32>(),
            vout_storage_proof.key.as_b256().0
        );
    }

    storage_verify(&utxo_storage_proof, state_root);

    storage_verify(&deposit_storage_proof, state_root);

    storage_verify(&vout_storage_proof, state_root);

    let buf: [u8; 32] = vout_storage_proof.value.to_be_bytes();

    // ENDIANNESS SHOULD BE CHECKED THIS FIELD IS 4 BYTES in the contract
    let vout = u32::from_le_bytes(
        buf[28..32]
            .try_into()
            .expect("Vout value conversion failed"),
    );

    let wd_outpoint = WithdrawalOutpointTxid(utxo_storage_proof.value.to_be_bytes());

    let move_txid = MoveTxid(deposit_storage_proof.value.to_be_bytes());

    (wd_outpoint, vout, move_txid)
}
