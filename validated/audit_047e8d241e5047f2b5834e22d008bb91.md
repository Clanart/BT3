### Title
Silent, unvalidated rewrite of the git remote URL from GitHub API data (`clone_url`) — ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`Handler.cross_chain_erc20_settlement`'s core flaw was that a value that determines the destination of a state-changing operation (`to_handler`) was taken at face value without checking it against a whitelist, so the operation ("send funds") could silently target an untrusted destination with no way to detect or roll back the mistake. The same broken invariant exists in `updateRemoteUrl`, which takes `clone_url` from a GitHub API response and rewrites the local repository's git remote — the destination of every future `push`/`fetch` — without validating that the new host/owner is the one the user actually trusts.

### Finding Description
`updateRemoteUrl` is called from `AppStore.repositoryWithRefreshedGitHubRepository` [1](#0-0)  whenever Desktop refetches the GitHub repository metadata for a locally tracked repo:

```
const apiRepo = await api.fetchRepository(owner, name)
...
if (repository.gitHubRepository) {
  const gitStore = this.gitStoreCache.get(repository)
  await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
}
``` [2](#0-1) 

`updateRemoteUrl` itself only performs three checks before calling `gitStore.setRemoteURL`, none of which validate the *host* of the new URL:

```
const protocolsMatch =
  parsedRemoteUrl.protocol !== null &&
  parsedUpdatedRemoteUrl.protocol !== null &&
  parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

const remoteUrlUnchanged =
  gitStore.defaultRemote &&
  urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
  await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
``` [3](#0-2) 

`protocolsMatch` only compares the URL *scheme* (`https:` vs `ssh:`), and `urlMatchesRemote`/`urlsMatch` are only used to detect "no change needed" or "user manually customized the remote" cases — they never assert that the new `clone_url`'s hostname equals the account's known endpoint (`github.com` or the specific GHE host). There is no whitelist check comparable to `is_valid_handler(to_chain, to_handler)` from the report. If `apiRepo.clone_url` (an attacker-influenced value coming from a proxy/MITM'd GHE server response, or from a compromised/malicious GHE deployment) resolves to a different hostname, the function still passes `protocolsMatch` (still `https:`) and `remoteUrlUnchanged` (the user hadn't manually edited the remote), so `gitStore.setRemoteURL` is invoked to silently overwrite `origin` with the attacker-controlled URL via `git remote set-url` [4](#0-3) .

The corrupted value is the git `origin` remote URL for the working repository. Existing guards (`protocolsMatch`, `remoteUrlUnchanged`, `urlsMatch`) do not stop this path because they compare *equality/unchanged-ness*, not *trustedness of the new host*.

### Impact Explanation
Once the remote is silently repointed, the next user-initiated `git push` (via Desktop's push flow, which resolves the target from the stored remote) will send commits/branches to the attacker-controlled host instead of the intended GitHub repository — a direct instance of "silent corruption of what the user commits or pushes," one of the explicitly valid impact classes. Depending on how the attacker's endpoint is configured, this can also exfiltrate credentials used for the push (if HTTPS credential helper reuses cached tokens for the new host) or private source code. The user receives no dialog or confirmation; the change happens as a side effect of a routine background repository-info refresh.

### Likelihood Explanation
This requires the attacker to control (or MITM) a GitHub Enterprise Server's API responses, or to otherwise cause `fetchRepository` to return an attacker-chosen `clone_url` (e.g., via a compromised/rogue GHE instance the user has added an account for, or an on-path proxy response for that instance) — squarely within the report's accepted attacker model ("attacker controls ... a git remote/proxy response"). No local access, admin rights, or pre-existing malware is required. The refresh path is a normal, non-interactive background operation (`repositoryWithRefreshedGitHubRepository`), so the update happens automatically without any unusual user action.

### Recommendation
In `updateRemoteUrl`, before calling `gitStore.setRemoteURL`, verify that the new `updatedRemoteUrl`'s parsed hostname matches the hostname/endpoint the `GitHubRepository`/account was originally associated with (i.e., pin the destination host, analogous to checking `is_valid_handler`/whitelisting `to_chain` in the report). Only allow the owner/name portion of the URL to change (e.g., on rename/transfer within the same trusted host), and reject or prompt the user when the hostname itself changes.

### Proof of Concept
1. Add a GitHub Enterprise account in Desktop pointing at `https://ghe.example.com`.
2. Clone a repository from that instance; Desktop stores `origin` as `https://ghe.example.com/org/repo.git`.
3. Attacker positioned to influence the API response for that endpoint (compromised/rogue GHE instance or on-path proxy) returns, for `GET /repos/org/repo`, a `clone_url` of `https://attacker.example.com/org/repo.git` (same `https:` scheme).
4. On the next background refresh, `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` runs: `protocolsMatch` is true (`https:` == `https:`), `remoteUrlUnchanged` is true (user never touched the remote), `urlsMatch` is false (different host) → `gitStore.setRemoteURL('origin', 'https://attacker.example.com/org/repo.git')` executes silently.
5. The user's next `git push` from Desktop sends their commits to `attacker.example.com` with no warning shown. [5](#0-4) [6](#0-5)

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
