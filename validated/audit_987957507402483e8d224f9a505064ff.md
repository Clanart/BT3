### Title
Stale timestamp-keyed liquidity-index cache in `market.clar` lets collateral be overvalued after an in-block bad-debt write-down via `socialize-debt` - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`market.clar` caches each vault's liquidity index (`lindex`) per `(stacks-block-time, aid)` key to avoid repeated cross-contract calls to the vaults within a block. This cache is a direct analog of the Blend fee-vault's `last_update_timestamp`/`b_rate` cache: it is only refreshed the *first* time it is populated for a given timestamp, and every subsequent lookup in the same block is served from the cache even if the vault's real `lindex` has since changed. A vault's `lindex` is written down immediately (not gradually) whenever `socialize-debt` runs on a bad-debt event, exactly like Blend's `default_liabilities` immediately cuts `b_rate`. If `socialize-debt` executes on a vault after the market has already cached that vault's index for the current block, later operations in the same block will price ztoken collateral of that vault using the pre-default, stale (higher) `lindex`.

### Finding Description
`accrue-and-cache` populates `index-cache` keyed by `{ timestamp: stacks-block-time, aid: aid }` and returns the cached entry on any subsequent hit for that key within the block, without re-querying the vault: [1](#0-0) 

`resolve-ztoken`, used during price/health resolution for rehypothecated (ztoken) collateral, reads this cache directly via `get-cached-indexes` and multiplies the underlying price by the cached `lindex`: [2](#0-1) [3](#0-2) 

Meanwhile, a vault's real `lindex` is written down immediately and non-gradually whenever bad debt is socialized (e.g., after an under-collateralized liquidation leaves unrecoverable debt): [4](#0-3) 

Because the index cache is keyed only by `(timestamp, aid)` and not invalidated by state-changing calls like `socialize-debt`, any transaction earlier in the same block that already triggered `accrue-and-cache` for that vault's `aid` leaves a now-stale (higher) `lindex` sitting in `index-cache` for the rest of the block. A later transaction in the same block that revalues zToken collateral for that same `aid` (borrow, withdrawal, health check) will get a cache hit and use the outdated, higher `lindex`, exactly mirroring the fee-vault bug where `last_update_timestamp == now` caused a stale `b_rate` to be reused after a default.

### Impact Explanation
Direction of the error: collateral backed by the just-defaulted vault's ztoken is overvalued (stale higher `lindex` multiplies the underlying price upward relative to the vault's true post-default state). This benefits the borrower/attacker who bundles the sequence — they can borrow more than their real collateral value supports, or avoid a liquidation that should otherwise trigger, while the shortfall is ultimately borne by the vault/protocol as additional undercollateralized debt. This lands in the **Critical – protocol insolvency** category: it lets debt be issued against overstated collateral immediately after a default event, compounding bad debt beyond what the on-chain accounting can recover.

### Likelihood Explanation
This requires: (1) a bad-debt/default event that calls `socialize-debt` on a vault, and (2) that same vault's `aid` to have already been cached earlier in the same block by an ordinary market operation (deposit/borrow/health-check) before the default lands, and (3) a subsequent operation using that ztoken as collateral in the same block. All three steps can be bundled by a single caller in one Stacks block (analogous to the original PoC's 3-tx bundle in one EVM block), so no privileged access or third-party dependency is required — only a live bad-debt/default path, which is a legitimate protocol mechanism already present (`socialize-debt`). Likelihood is comparable to the original Blend finding: edge-case but self-triggerable and requiring no MEV.

### Recommendation
Invalidate or refresh the cached `(timestamp, aid)` entry whenever `socialize-debt` (or any other function that force-writes `lindex`/`index`) is invoked on a vault, e.g., by deleting the corresponding `index-cache` entry, or by having `accrue-and-cache` always re-query the vault instead of trusting a same-timestamp cache hit unconditionally when a default has occurred within that block.

### Proof of Concept
1. Block N, tx 1: A user performs an ordinary market action (deposit/borrow) referencing zSTX collateral. This calls `accrue-and-cache` for `aid = STX`, caching `lindex = L0` under key `{timestamp: T, aid: STX}`.
2. Block N, tx 2: A liquidation on the STX vault results in bad debt; the market (or authorized liquidator) calls `vault-stx socialize-debt`, which immediately writes `lindex` down to `L1 < L0` in vault-stx storage per `socialize-debt`'s calculation.
3. Block N, tx 3 (same block, same `T`): The same or another user performs a borrow using zSTX as collateral. `resolve-ztoken` calls `get-cached-indexes(STX)`, which still returns the stale cached entry `{index, lindex: L0}` from tx 1 because `index-cache` was never invalidated. The user's zSTX collateral is valued using `L0` instead of the correct `L1`, overstating collateral value and permitting borrowing beyond the vault's real backing.

```text
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
