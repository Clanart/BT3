**Rationale:** The premise doesn't hold in this codebase. `externalFileContents.oldContents` (consumed by `applyFileContents` in `app/src/ui/diff/seamless-diff-switcher.tsx`) is never derived from the Copilot model's response — it is populated via `buildFileContents()` in `app/src/ui/multi-commit-operation/dialog/copilot-conflicts-changes.tsx`, using `result.oldContents` returned from `getResolutionDiff()`.

<cite repo="Annirich/desktop--013" path="app/src/lib/git/diff.ts" start="456="463">httpstart="456" end="463"</cite>

Specifically, `getResolutionDiff()` always reads the base content directly from the working-tree file on disk via `readFile(Path.join(repository.path, filePath), 'utf8')` and only uses the model's `resolvedContent` as the *target* ("new") side of the diff, never as the "old" side: [1](#0-0) 

The reassembled resolution content the model supplies (`IFileResolution.resolvedContent`) is passed in as `{ content: resolution.resolvedContent }`, which only feeds `targetContent`/`newContents`, not `oldContents`: [2](#0-1) 

`buildFileContents()` then constructs `IFileContents` straight from that `IResolutionDiff`, so `oldContents` in the object handed to `SeamlessDiffSwitcher` via `externalFileContents` is always the literal bytes just read from the on-disk conflicted file — never attacker/model-influenced: [3](#0-2) 

Additionally, the actual write path (`_applyCopilotConflictResolutions`) re-checks the on-disk file status immediately before writing and skips files whose conflict markers have already been resolved externally, guarding against a TOCTOU divergence between the previewed diff and the write target: [4](#0-3) 

Since the "before" side of the diff is sourced from a direct filesystem read rather than any Copilot-controlled value, there is no path by which a crafted model response can cause the seamless switcher to render a misleading "before" state or cause silent divergence between the displayed diff and what gets committed.

  private buildFileContents(
    file: CommittedFileChange,
    result: IResolutionDiff
  ): IFileContents {
    // Mirror the standard getFileContents path, which caps the amount of
    // content it hands to the syntax-highlighting worker. We only allow
    // expansion when the whole (untruncated) resolution fits under the limit.
    const canBeExpanded =
      result.newContents.length <= MaxDiffExpansionNewContentLength
    const oldContents = result.oldContents
      .slice(0, MaxDiffExpansionNewContentLength)
      .split(/\r?\n/)
    const newContents = result.newContents
      .slice(0, MaxDiffExpansionNewContentLength)
      .split(/\r?\n/)

    return { file, oldContents, newContents, canBeExpanded }
  }
