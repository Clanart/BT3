### Title
Unbounded default auction bid-pool size (`MaxBidPoolSize = math.MaxInt64`) allows memory-exhaustion flooding via `auction_submitBid` — analogous to Suricata's unbounded HTTP2 stream-0 buffering

### Summary
The Suricata CVE stems from a code path that lets attacker-controlled input accumulate in memory without ever hitting the parser's normal per-item/per-stream cap, because the reserved value (stream ID 0) bypassed the intended bound. Kaia's `kaiax/auction` bid pool exhibits the same structural weakness: the pool's item cap defaults to `math.MaxInt64` (i.e., effectively "no cap"), and this un-bounded pool is fed directly by an externally reachable RPC method (`SubmitBid`), with cleanup only occurring at block boundaries.

### Finding Description
`DefaultMaxBidPoolSize` is set to `math.MaxInt64`, and this value is used unless the node operator explicitly overrides `--auction.max-bid-pool-size`: [1](#0-0) [2](#0-1) 

The `BidPool` stores every accepted bid in three maps (`bidMap`, `bidTargetMap`, `bidWinnerMap`), each entry potentially carrying up to `BidTxMaxDataSize` (64KB) of attacker-controlled `Data`: [3](#0-2) 

`insertBid` only rejects a *new* target-tx-hash bid once `len(bp.bidMap) >= bp.maxBidPoolSize`; when the effective config leaves this at `math.MaxInt64`, the check is a no-op: [4](#0-3) 

Pool entries are only purged when a block advances past `blockNumber` (`removeOldBids`), and valid bids can target the *current block number + 1* or *+2* (`allowFutureBlock = 2`): [5](#0-4) [6](#0-5) 

The externally reachable entry point is `AuctionAPI.SubmitBid`, which forwards any well-formed `BidInput` straight into `bidPool.AddBid`: [7](#0-6) 

Unlike the p2p gossip path (`HandleBid`), which applies a per-peer token-bucket rate limiter (`bidsPerSecondPerPeer = 300`, LRU-capped at `rateLimiterCacheSize`): [8](#0-7) 
the direct RPC path (`SubmitBid` → `AddBid` → `insertBid`) has **no rate limiter and no default pool cap**, so the only gates against flooding are (a) a valid EIP-712 `SearcherSig` from the bidder's own key, and (b) a valid `AuctioneerSig`. Critically, `ValidateAuctioneerSig` verifies the auctioneer's signature only over `keccak256("\x19Ethereum Signed Message:\n" + len(SearcherSig) + SearcherSig)` — i.e., it attests to a specific `SearcherSig` blob, not independently to the bid's `TargetTxHash`, `BlockNumber`, `Nonce`, `Data`, or `Bid` amount fields: [9](#0-8) [10](#0-9) 

Because a normal bidder can independently produce arbitrarily many distinct, fully valid `SearcherSig`s (signing over its own EIP-712 digest for many candidate target-tx hashes/blocks with its own key) and only needs the auctioneer to co-sign, an operator running the auction feature with default settings admits an unbounded number of large (~64KB) bid entries into memory during the ~2-block acceptance window, capped only by wall-clock/blocks-per-second throughput, not by any pool-size guard.

### Impact Explanation
An auction bidder participating in normal Kaia auction flow (an explicitly in-scope actor per this assessment's rules) can cause uncontrolled memory growth on any consensus node running the auction module with its default configuration, since `MaxBidPoolSize` effectively imposes no limit. This mirrors the Suricata bug class: a resource-tracking structure meant to be bounded is not bounded on the code's default/most commonly deployed path, leading to potential node crash or degraded availability (loss of visibility/service) — a resource-starvation impact matching CWE-770/CVE-2025-53538's class.

### Likelihood Explanation
Medium. Exploitation requires the auction module to be enabled (consensus nodes with `Disable=false`) and requires the attacker to obtain auctioneer co-signatures for many distinct bids, which somewhat limits scale to whatever throughput the auctioneer service allows a bidder to negotiate. However, because the auctioneer's signature does not itself bound the number/size of distinct bids, and because the default cap is effectively infinite, a bidder with sustained legitimate access to the auctioneer's signing service could still accumulate memory pressure far beyond what any bounded pool would allow, with no operator-visible warning unless they specifically tune `--auction.max-bid-pool-size`.

### Recommendation
- Change `DefaultMaxBidPoolSize` to a sane finite default (e.g., in the low thousands) rather than `math.MaxInt64`, so unconfigured nodes are protected by default.
- Apply a per-sender or per-block-number cap in `insertBid`/`initializeBidMap`, independent of the global cap, to prevent a single bidder from monopolizing pool capacity within the 2-block window.
- Add rate limiting to the direct RPC path (`SubmitBid`) similar to the existing per-peer limiter used for `HandleBid`.
- Consider binding `AuctioneerSig` to the full bid digest (not just the `SearcherSig` bytes) to make the auctioneer's approval verifiably scoped to specific bid content.

### Proof of Concept
1. Deploy a Kaia consensus node with the auction module enabled and default config (`MaxBidPoolSize` unset ⇒ `math.MaxInt64`).
2. As a registered auction bidder with a cooperating/compromised-throughput auctioneer signing service, generate N distinct `BidData` payloads (varying `TargetTxHash`/`Nonce`, each carrying `Data` near `BidTxMaxDataSize` = 64KB), sign each with a fresh valid EIP-712 `SearcherSig`, and obtain a valid `AuctioneerSig` for each (the auctioneer only needs to sign the `SearcherSig` bytes, not audit bid content volume).
3. Call `auction_submitBid` repeatedly for all N bids within a 2-block window (`allowFutureBlock`), targeting `currentBlock+1` and `currentBlock+2`.
4. Observe `bidMap`/`bidTargetMap`/`bidWinnerMap` growing unbounded (no rejection from `insertBid`, since `maxBidPoolSize` is `math.MaxInt64`) until node memory pressure/OOM occurs — confirming the resource-starvation path via [4](#0-3) .

// removeOldBids removes the old bids for the given block number.
func (bp *BidPool) removeOldBids(num uint64, txHashMap map[common.Hash]struct{}) {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	// Remove the old bids.
	for bn := range bp.bidWinnerMap {
		if bn > num {
			continue
		}

		for _, bh := range bp.bidWinnerMap[bn] {
			delete(bp.bidMap, bh)
		}
		delete(bp.bidTargetMap, bn)
		delete(bp.bidWinnerMap, bn)
	}

func (bp *BidPool) HandleBid(peerID string, bid *auction.Bid) {
	if atomic.LoadUint32(&bp.running) == 0 || bid == nil {
		return
	}

	// Check rate limit for this peer
	if !bp.checkRateLimit(peerID) {
		logger.Trace("Rate limit exceeded for peer", "peerID", peerID)
		return
	}

	select {
	case bp.bidMsgCh <- bid:
	default:
		logger.Trace("Bid queue is full, dropping bid", "peerID", peerID)
	}
}

// checkRateLimit checks if the peer is within rate limit
func (bp *BidPool) checkRateLimit(peerID string) bool {
	bp.peerRateLimiterMu.Lock()
	defer bp.peerRateLimiterMu.Unlock()

	limiter, exists := bp.peerRateLimiter.Get(peerID)
	if !exists {
		// Create new rate limiter for this peer
		// Use burst equal to the rate limit (we only use rate limit, not the burst)
		limiter = rate.NewLimiter(rate.Limit(bidsPerSecondPerPeer), bidsPerSecondPerPeer)
		bp.peerRateLimiter.Add(peerID, limiter)
	}

	// It'll simply discard the bid if the rate limit is exceeded
	// We don't need to reserve for a bid here because the original bid will be sent from auctioneer through different channel (see #api.SubmitBid)
	return limiter.(*rate.Limiter).Allow()
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}
