### Title
Recursive clone disables Git's anti-RCE clone protection via `GIT_CLONE_PROTECTION_ACTIVE: 'false'` - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` in `app/src/lib/git/clone.ts` runs `git clone --recursive` with a merged environment that hardcodes `GIT_CLONE_PROTECTION_ACTIVE: 'false'`, unconditionally, for every clone Desktop performs (both GitHub-hosted and arbitrary/Generic-tab URLs). [1](#0-0) 
This environment variable is a real upstream Git escape hatch tied to the fix for the submodule-hooks RCE (Git advisory GHSA-vw2c-22j3-3jqj / CVE-2024-32002), which Git's own test suite uses to *disable* the protection in order to reproduce the vulnerable pre-fix behavior. Shipping it hardcoded to `'false'` in production code means Desktop deliberately re-opens that RCE path for every recursive clone it performs.

### Finding Description
The upstream fix for CVE-2024-32002 added a runtime check in `git clone` (and submodule-related recursive checkout) that aborts when a repository's layout could let a symlink or case-insensitive collision place attacker content into `.git/hooks` (or otherwise escape the intended submodule directory) on case-insensitive/symlink-capable filesystems (macOS default, Windows). Git's test harness toggles this protection off via `GIT_CLONE_PROTECTION_ACTIVE=false` purely to validate that the *unpatched* behavior would have been exploitable — it is not meant to ship in any real invocation of git.

Desktop's `clone()` builds its `IGitStringExecutionOptions.env` by spreading `envForRemoteOperation(url)` (auth/proxy variables) and then always adding `GIT_CLONE_PROTECTION_ACTIVE: 'false'`: [1](#0-0) 
It then runs `clone --recursive` (submodules are always initialized) with that environment, using the `--` url/path terminator but with no other safeguard against the hooks-collision attack: [2](#0-1) 

The "invariant" that should hold — analogous to the PoolTogether report's individual/total balance invariant — is: *"Git's built-in clone-time protections against hostile submodule layouts must remain active for every clone Desktop performs."* Just as the PoolTogether bug silently broke the sum invariant by special-casing the sponsorship address without decrementing the total, Desktop silently breaks Git's safety invariant by special-casing every clone with `GIT_CLONE_PROTECTION_ACTIVE=false`, without any compensating validation elsewhere in the clone/submodule pipeline.

Existing guards do not stop this path:
- `isClonePathSensitive()` only validates the *destination directory* is not a sensitive host path (e.g. `~/.ssh`), it does nothing to validate the contents of the cloned repository or its submodules. [3](#0-2) 
- `updateSubmodulesAfterOperation()` (used for pull/checkout submodule updates) similarly focuses on optionally allowing `file://` submodule URLs and does not restore or re-check the hooks-collision protection. [4](#0-3) 
- `envForRemoteOperation`/`envForProxy` only deal with authentication and proxy resolution, they never touch or restore `GIT_CLONE_PROTECTION_ACTIVE`. [5](#0-4) 

### Impact Explanation
This is a code-execution primitive fully controlled by a remote/attacker-hosted repository: any repository (including one supplied through the Generic-tab clone URL, `github://` clone deep-link/protocol handler, or a repository the user is invited/tricked into cloning) that is crafted per the CVE-2024-32002 technique (a submodule whose name collides with `.git`/`hooks` under case-insensitive or symlink-aware handling) will have its protection disabled in Desktop, allowing arbitrary hook scripts to be placed and later executed on the victim's machine — i.e., renderer/host code execution outside the sandbox and outside of what the user intended to trust, on both macOS and Windows (Desktop's primary supported, case-insensitive-by-default platforms).

### Likelihood Explanation
Likelihood is high: the vulnerable path is hit on every single clone Desktop performs (`clone --recursive` always runs with this env var), no user action beyond "Clone a repository" (the core, everyday Desktop feature) is required, and the attacker only needs to control the source repository content — no local access, no admin rights, no pre-existing malware, and no unnatural user steps.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override entirely so Git's built-in clone protection (added specifically to fix CVE-2024-32002) remains active. If there was a legitimate reason to disable it (e.g., a compatibility workaround), that reasoning should be revisited — this variable is documented in upstream Git as a test-only bypass and should never be set in a production client. Additionally, ensure the bundled/embedded Git version used by Desktop (via dugite) is >= the fixed version (2.45.1+) so the protection logic even exists to be honored.

### Proof of Concept
1. Attacker publishes a git repository containing a submodule configured (per the CVE-2024-32002 technique) so that, upon recursive clone/checkout on a case-insensitive filesystem, files intended for a submodule's working tree are instead written into `.git/hooks` of the containing repository (via symlink or case-collision with `.git`), with a hook script (e.g. `post-checkout`) that executes attacker code.
2. Victim uses GitHub Desktop's "Clone repository" (Generic URL tab, or an `x-github-client://` clone deep link) pointing at the attacker's repository.
3. Desktop calls `clone(url, path, options)`, which spawns `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `env.GIT_CLONE_PROTECTION_ACTIVE = 'false'`. [6](#0-5) 
4. Because the protection that Git 2.45.1+ would otherwise enforce is explicitly disabled, the hostile hook is written and later invoked by Git itself during the clone/checkout, resulting in code execution on the victim's machine outside of any application sandbox, without any additional user interaction.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
