### Title
Permanent, unscoped "Trust Repository" (`safe.directory`) whitelist enables silent code execution for any future attacker on a shared path - (File: app/src/lib/git/config.ts)

### Summary
GitHub Desktop's handling of Git's "dubious ownership" protection mirrors the reported bug class: a security control that is supposed to be a narrow, reviewed, one-time decision is instead implemented as a **permanent, globally-scoped state change** with no expiry, no re-validation, and no way to revoke it from the UI. Once a user clicks "Trust Repository" for a path Git reports as unsafe, that exact path is added forever to the global `safe.directory` git config, silently disabling Git's ownership check for *any* future repository content placed at that path by *any* user/process — including an attacker who later gains write access to the same shared location.

### Finding Description
When Desktop detects an "unsafe" repository (owned by a different user than the current process), it surfaces a "Trust Repository" action in both `MissingRepository` and `AddExistingRepository`: [1](#0-0) 

Both call `addSafeDirectory(unsafePath)`, which writes the path into the **global** git config, not scoped to the specific repository, commit, or session: [2](#0-1) 

The `unsafePath` value itself originates from parsing Git's own stderr message via a regex, and is used verbatim without any additional binding to repository identity (remote URL, commit hash, etc.): [3](#0-2) 

Because `safe.directory` is a path-based, not repository-based, exception, the trust decision is not "trust this specific clone" but "trust anything ever placed at this filesystem path." Git's own dubious-ownership check exists precisely because a repository at a given path executes local config (`core.hooksPath`, `core.pager`, `core.fsmonitor`, `core.sshCommand`, etc.) automatically during normal Git operations — the same warning text is shown to the user in the dialog itself: [4](#0-3) 

The changelog confirms this trust mechanism explicitly supports UNC/network-share paths — i.e., paths that are inherently multi-tenant and writable by other accounts: [5](#0-4) 

**Broken invariant:** "Trust this specific unsafe repository, once, after review" is implemented as "permanently disable Git's ownership protection for this path, for every repository that will ever exist there." There is no UI anywhere in the app to list or revoke previously-trusted directories, and no scoping to the content that was reviewed at trust time — exactly analogous to the emergency-mode finding where a supposedly one-way/guarded state becomes a durable, broad, unmonitored privilege.

### Impact Explanation
On a shared workstation, a mapped/mounted network drive, or a CI/build agent that reuses a working directory across jobs owned by different accounts, once any legitimate user has clicked "Trust Repository" for that path, `safe.directory` permanently whitelists it. An attacker who later gains write access to that same path (a co-worker with access to the share, a different CI job, a container reusing a host-mounted volume, etc.) can drop a malicious `.git` directory with a hostile `core.hooksPath`/`core.fsmonitor`/`core.sshCommand`/pager configuration. The next time Desktop (or the user directly) runs any git command against that path, the attacker's config executes with no prompt, no warning, and no further user interaction — silent arbitrary code execution outside of any explicit user consent for *that* specific attacker payload.

### Likelihood Explanation
Requires that the victim previously trusted the exact same path for a legitimate reason, and that path is subsequently writable by another party — a realistic scenario in shared/enterprise environments (network shares, shared build machines, CI runners with persistent workspace directories). Desktop explicitly ships support for trusting such shared/UNC paths, increasing exposure. No admin rights, malware, or leaked credentials are needed by the attacker beyond ordinary write access to a location the victim already trusted.

### Recommendation
- Do not persist trust decisions as a bare, permanent, global filesystem path with unlimited future scope.
- Scope trust to repository identity at the time of approval (e.g., remote URL + initial commit hash) and re-validate on subsequent access rather than relying solely on `safe.directory`.
- Add a Desktop settings UI to view and revoke previously trusted directories.
- Show a stronger, distinct warning (and avoid one-click trust) when the unsafe path is a network/UNC share or otherwise identified as multi-tenant.

### Proof of Concept
1. On a shared machine/network share, User A clones/creates a legitimate repo at path `P` and, due to differing OS ownership metadata, is shown Desktop's "unsafe repository" warning; User A clicks "Trust Repository," which calls `addSafeDirectory(P)` and permanently adds `P` to `~/.gitconfig`'s `safe.directory`. [1](#0-0) [6](#0-5) 
2. Later, Attacker (any other account with write access to `P`, e.g. via the same network share) deletes or replaces the contents at `P` with a hostile repository containing a malicious `.git/config` (e.g., `core.fsmonitor` or `core.pager` pointing at an attacker script) or hooks.
3. User A (or Desktop performing background refresh/fetch operations) subsequently interacts with path `P` again. Because `P` is already in `safe.directory`, Git's dubious-ownership protection never triggers, `getRepositoryType` returns `'regular'` instead of `'unsafe'` [7](#0-6) , and the attacker's local config/hooks execute silently with no re-prompt from Desktop.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }
```
