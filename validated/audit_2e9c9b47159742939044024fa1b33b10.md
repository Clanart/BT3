### Title
Unchecked type assertion on attacker-controlled CosmWasm query response panics the pointer precompile's `AddCW20`/`AddCW721`/`AddCW1155` handlers - ([File: precompiles/pointer/pointer.go])

### Summary
The EVM pointer precompile creates ERC20/ERC721/ERC1155 "pointer" contracts for CosmWasm CW20/CW721/CW1155 tokens by querying the target CW contract's `token_info`/`contract_info` and reading the `name`/`symbol` fields out of the raw JSON response with an unchecked Go type assertion (`.(string)`), rather than a checked assertion or typed unmarshal. Because the queried contract is fully attacker-controlled (any user can instantiate/upload a CosmWasm contract), an attacker can make the query return a `name`/`symbol` field that is missing, `null`, a number, an object, or an array, causing `formattedRes["name"].(string)` to panic instead of returning an error.

### Finding Description
`AddCW20`, `AddCW721`, and `AddCW1155` in the pointer precompile (present in the current `precompiles/pointer/pointer.go` and in essentially every legacy pointer precompile version, e.g. `precompiles/pointer/legacy/v552/pointer.go`, `v555`, `v562`, ... `v67`) call into a CosmWasm contract's smart query and then do: [1](#0-0) [2](#0-1) 

```go
res, err := p.wasmdKeeper.QuerySmart(ctx, cwAddress, []byte("{\"token_info\":{}}"))
...
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```

`res` is the raw JSON payload returned by the queried CW20/CW721/CW1155 contract's own `token_info`/`contract_info` query handler — code the attacker deployed and fully controls (`sei-wasmd/x/wasm/keeper/keeper.go: QuerySmart`, `sei-wasmd/x/wasm/keeper/query_plugins.go: WasmQuerier`). If that contract's response omits the `name`/`symbol` keys or encodes them as a non-string JSON value, `formattedRes["name"]` is `nil` or a non-`string` `interface{}`, and the single-value type assertion `.(string)` panics with `interface conversion: interface {} is <nil/type>, not string`.

This is the same bug class as the Mattermost/Playbooks CVE: user-supplied, unvalidated structured data (there: `RetrospectivePost` props; here: a CW20/CW721/CW1155 `token_info`/`contract_info` JSON response) is consumed by application code without a type/shape check, and the mishandling panics rather than gracefully erroring.

The reachable trigger path for an unprivileged actor is: (1) deploy/instantiate a malicious CW20/CW721/CW1155 contract whose query handler returns a malformed `name`/`symbol`; (2) call the EVM pointer precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` method against that contract address from any EVM transaction, contract, or `eth_call`. This is directly reachable by any transaction sender or contract deployer — no privileged role required.

### Impact Explanation
Whether this rises to a genuine node crash / consensus-relevant DoS versus "just a failed transaction" depends on where the panic is caught, which could not be conclusively confirmed:
- In the committed `DeliverTx`/`CheckTx` path, panics originating inside EVM message application are typically caught by Cosmos SDK's outer `runTx` panic recovery, which would convert this into a failed transaction rather than crashing the node. I was not able to locate/inspect `sei-cosmos`'s `runTx` implementation directly to confirm this recovery wraps the full EVM precompile call stack in this repo's fork.
- For simulation-only entry points (`eth_call`, `eth_estimateGas`), the RPC layer (`evmrpc/simulate.go`) does install `defer recover()` around `SimulationAPI.Call`/`EstimateGas`, which appears to convert the panic into a JSON-RPC error rather than crashing the RPC process.
- The dynamic-gas precompile dispatcher (`precompiles/common/precompiles.go: RunAndCalculateGas`) that ultimately invokes `AddCW20`/`AddCW721`/`AddCW1155` does **not** itself install a `recover()` — it only wraps errors returned normally via `HandlePrecompileError`. So protection against this specific panic, if any, exists further up the stack (SDK/RPC layers) rather than at the precompile boundary itself.

Given the extensive, deliberate panic-recovery hardening already present throughout the EVM RPC and precompile layers elsewhere in this codebase (e.g., `evmrpc/simulate.go`, `precompiles/addr/*`'s explicit `recover()` in `Execute`, `sei-tendermint`'s JSON-RPC `recoverAndLogHandler`), and the likely presence of an outer Cosmos SDK panic-recovery wrapper around transaction execution, I could not confirm with the available tooling that this panic actually escapes all recovery layers to crash a node or halt the chain. This is a real, unguarded type-assertion bug and a clear robustness defect, but I was unable to prove it satisfies this scan's bar of "crash of a default-configuration node" or "block delay beyond 2.5 seconds" without deeper tracing through `sei-cosmos`'s `BaseApp.runTx` and the EVM ante/message-application call chain, which the available search tooling did not surface.

### Likelihood Explanation
Triggering the malformed response requires only deploying an ordinary CosmWasm contract (no special permission) and crafting its `token_info`/`contract_info` query handler to omit or mistype the `name`/`symbol` fields, then invoking the pointer precompile against it — both steps are available to any unprivileged user. Likelihood of hitting the code path is high; likelihood of it actually producing chain-level impact (vs. a caught, non-fatal error) is uncertain per the Impact Explanation above.

### Recommendation
Replace the unchecked type assertions in `AddCW20`, `AddCW721`, and `AddCW1155` (and their legacy-version counterparts) with checked assertions or a typed struct decode, returning a normal precompile error instead of panicking, e.g.:
```go
nameVal, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract %s returned invalid name field", cwAddr)
}
```
Apply the same fix to `symbol`, and audit other precompile/keeper code paths that `json.Unmarshal` a CosmWasm query response into `map[string]interface{}` and then index+assert fields directly, since the same pattern recurs across `AddCW20`/`AddCW721`/`AddCW1155` in every pointer precompile version.

### Proof of Concept
1. Upload and instantiate a CosmWasm contract whose `token_info` (for CW20) or `contract_info` (for CW721/CW1155) query handler returns `{"name": 12345, "symbol": null}` (or omits the fields entirely) instead of the expected string fields.
2. From any EVM account, call the pointer precompile's `addCW20Pointer(address)` (or `addCW721Pointer`/`addCW1155Pointer`) method, passing the CW contract's bech32 address, either via a signed EVM transaction or `eth_call`.
3. `p.wasmdKeeper.QuerySmart` returns the attacker's crafted JSON; `json.Unmarshal` succeeds into `map[string]interface{}`; `formattedRes["name"].(string)` panics with `interface conversion: interface {} is float64/nil, not string` inside precompile execution. [3](#0-2)
