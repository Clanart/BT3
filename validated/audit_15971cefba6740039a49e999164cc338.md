Found a concrete analog worth flagging: `_findPullRequestBranch` in `app-store.ts`, which is reached via `openPullRequestFromUrl` — an attacker-controlled deep-link / GitHub API path.

### Title
Race condition in `_findPullRequestBranch`/`_checkoutPullRequest` allows a concurrent operation on the same repository to check out or push to a wrong/attacker-influenced remote - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The eclair bug class is: a lookup used to decide "is there already a live handler for this key" can return a stale/soon-to-be-invalid object because the check and the action are not atomic, causing the operation to silently go to the wrong destination (or nowhere). The strongest matching pattern reachable from an attacker-controlled input in Desktop is `_findPullRequestBranch`, invoked by `dispatcher.ts`'s `openPullRequestFromUrl`, which is triggered by a `x-github-client://openPullRequest` deep link containing attacker-controlled `headRepoOwner`, `headCloneUrl`, and `headRefName`. [1](#0-0) [2](#0-1) 

### Finding Description
`_findPullRequestBranch` reads `gitStore.allBranches`/`gitStore.defaultRemote` from the `GitStoreCache` singleton for the repository (obtained via `this.gitStoreCache.get(repository)`), then separately calls `addRemote`, `_fetchRemote`, and finally `_createBranch`, all against the *same* shared `GitStore`/`repository` object without re-validating that the repository state hasn't concurrently changed. [3](#0-2) 

`GitStoreCache.get()` mirrors the exact pattern described in the eclair report: a map lookup is used to decide whether to reuse an existing handler (`GitStore`) instance, with no coordination against in-flight consumers of that instance. [4](#0-3) 

Because deep-link driven PR checkout (`openPullRequestFromUrl`) does not go through `withPushPullFetch`/`withIsCommitting` guards (unlike `_push`/`_pull`, which explicitly serialize via `isPushPullFetchInProgress`), a user simultaneously running a manual fetch/push while clicking an "Open in Desktop" PR link can interleave `addRemote`/`_fetchRemote` calls on the same `GitStore` instance. The remote name derived (`forkPullRequestRemoteName(headRepoOwner)`) is attacker-supplied via the link, and `urlMatchesRemote` matching plus `addRemote` can add or reuse a remote whose name collides with, or shadows, an existing trusted remote if the interleaving lands mid-refresh. The `app-store.ts` comment thread around `performPush`'s `safeRemote` explicitly documents that the team is aware "remote" and "branch.remote" can be out of sync due to unsynchronized refreshes, and add a `sendNonFatalException` safeguard only for the push path — `_findPullRequestBranch` has no equivalent safeguard. [5](#0-4) 

### Impact Explanation
If an interleaved fetch/refresh completes between `gitStore.allBranches.find(...)` and the subsequent `_createBranch`/checkout call, the branch object resolved to check out could reference stale ref data (a different SHA than what the attacker's PR head advertised, or from a remote whose URL was concurrently changed by a legitimate refresh). This is a silent-corruption-of-what-the-user-checks-out class issue: the user believes they are opening the specific PR advertised by the deep link but Desktop may check out content from a different/mutated remote state, mirroring the eclair bug where the relay handler could silently target the wrong destination due to the stale-lookup race.

### Likelihood Explanation
Requires precise timing: the user (or an automatic background fetch/indicator refresh) must be performing a concurrent Git network operation on the exact same repository at the moment a malicious "Open in Desktop" PR link is clicked, and the deep link's `headCloneUrl`/`headRefName` must coincide with in-flight remote state changes. `_fetchRefspec` and `_findPullRequestBranch`'s note explicitly acknowledge this class of issue exists ("does not opt-in to checks that prevent multiple concurrent network actions... might require some rework") but no proof-of-concept confirming actual exploitability was found in the available code/tests — this is a plausible but unconfirmed race window. [6](#0-5) 

### Recommendation
Snapshot the `GitStore` remote/branch state at the start of `_findPullRequestBranch`, and re-validate (or re-fetch) it immediately before the final checkout, rejecting the operation if the underlying remote URL changed mid-flight, similar to the `safeRemote`/`sendNonFatalException` guard already used in `performPush`. Also consider serializing `_findPullRequestBranch`/`_checkoutPullRequest` through the same `withPushPullFetch` gate used by `_push`/`_pull`.

### Proof of Concept
Not independently verified — this requires a running two-window/timing race test (open a PR deep link while a fetch/pull is in flight on the same repository) that could not be executed from static code review alone. I flag this with **moderate confidence** as a structurally analogous race (same "cache lookup without atomic reservation" defect class as the eclair report) but **cannot confirm** actual exploitable corruption without dynamic testing; a Devin session with a running Desktop instance would be needed to construct and verify a working PoC.

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

  public get(repository: Repository): GitStore {
    let gitStore = this.gitStores.get(repository.hash)
    if (gitStore === undefined) {
      gitStore = new GitStore(repository, this.shell, this.statsStore)
      gitStore.onDidUpdate(() => this.onGitStoreUpdated(repository, gitStore!))
      gitStore.onDidError(error => this.onDidError(error))

      this.gitStores.set(repository.hash, gitStore)
    }

    return gitStore
  }
