### Title
Empty serialized Schnorr aggregate bypasses signature verification - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` permits an encoded aggregate containing zero `R` values, while `SchnorrAggregate::verify` accepts that value whenever `keys_and_challenges` is also empty because the resulting verification equation is trivially satisfied. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrAggregate::read` reads a caller-controlled 32-bit count, deserializes that many nonces, and accepts a count of zero without rejecting the empty aggregate. [1](#0-0)  `verify` only checks that the number of encoded nonces equals the number of supplied keys/challenges, so an empty aggregate paired with an empty verification set passes that check. [3](#0-2)  With no entries, the verification loop adds no randomized statements; when `s` is zero, the sole remaining statement is `-0 * G`, which is the identity and therefore verifies successfully. [4](#0-3)  The honest aggregation path explicitly refuses to emit an empty aggregate through `SchnorrAggregator::complete`, but this invariant is not enforced when untrusted bytes are deserialized. [5](#0-4) 

### Impact Explanation
An unprivileged party can provide a serialized aggregate signature containing no signatures and a zero scalar, and it will pass `SchnorrAggregate::verify` for an empty `keys_and_challenges` input. [1](#0-0) [2](#0-1)  This bypasses the intended invariant that an aggregate represents at least one successfully aggregated Schnorr signature, which is enforced by `SchnorrAggregator::complete` but skipped on the deserialization path. [6](#0-5) 

### Likelihood Explanation
The malicious object requires only a four-byte zero length followed by a canonical encoding of scalar zero, so it is easy to construct and submit to any reachable `SchnorrAggregate::read` consumer. [1](#0-0)  Exploitation requires the verifier to invoke `verify` with an empty `keys_and_challenges` set for attacker-controlled aggregate bytes; in that path, acceptance is deterministic rather than probabilistic. [2](#0-1) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::read` after decoding the length, and also reject empty `keys_and_challenges` in `SchnorrAggregate::verify` before checking equality so the invariant is enforced even for manually constructed values. [1](#0-0) [3](#0-2) 

### Proof of Concept
The following generic test demonstrates that a serialized empty aggregate verifies successfully:

```rust
// crypto/schnorr/src/aggregate.rs
use ff::PrimeField;

let mut encoded = 0u32.to_le_bytes().to_vec();
encoded.extend(<C::F as PrimeField>::ZERO.to_repr().as_ref());

let aggregate = SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();
assert!(aggregate.verify(b"aggregate-dst", &[]));
```

The encoded length is zero, `s` is the zero scalar, and verification evaluates only the identity-producing `-s * G` statement. [7](#0-6) [4](#0-3)
