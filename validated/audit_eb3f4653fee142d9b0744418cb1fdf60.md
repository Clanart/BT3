### Title
Hand-rolled frontmatter parser silently truncates comma-containing regex patterns, neutering `block` rules - (`plugins/hookify/core/config_loader.py`)

### Summary
The custom inline-dict parser in `extract_frontmatter` splits list-item text unconditionally on every comma, so a `pattern` value containing a literal comma (e.g. inside a regex character class `[/,~]`) is truncated at the first comma and the remainder is dropped because it lacks a `key: value` colon. This produces a corrupted, often syntactically-invalid regex that either fails to compile (caught and treated as non-match) or compiles into a weaker pattern, causing security-critical `block` rules to silently stop matching while the rule file still reads `enabled: true`.

### Finding Description
`load_rule_file` calls `extract_frontmatter` (`plugins/hookify/core/config_loader.py:87-195`) which, for `- field: ..., operator: ..., pattern: ...` list items, enters the branch at line 164: `if ':' in item_text and ',' in item_text:` and does `item_text.split(',')` at line 167, discarding any resulting fragment without a `:` in it (lines 168-170). Any comma embedded in the `pattern` value (very common in regex character classes and alternations) breaks the field apart, and the tail fragment after the last colon-less split is lost. The corrupted dict is appended to `current_list` and eventually returned as `frontmatter['conditions']`. `Condition.from_dict` (`plugins/hookify/core/config_loader.py:22-29`) and `Rule.from_dict` (`plugins/hookify/core/config_loader.py:44-84`) pass this truncated `pattern` through unchanged — there is no validation of regex well-formedness or round-trip check against the original text. At evaluation time `RuleEngine._regex_match` (`plugins/hookify/core/rule_engine.py:256-273`) calls `re.compile` on the corrupted pattern inside a `try/except re.error`, which on failure just logs to stderr and returns `False`, so the condition — and thus the whole blocking rule — silently never matches. Nothing downstream re-validates that the parsed pattern matches the author's intent, so a rule that looks like `enabled: true`, `action: block` with a seemingly-present `pattern` field is effectively inert.

### Impact Explanation
This is a silent security-control bypass: a hookify rule intended to block dangerous commands (e.g. `rm -rf` with a character class covering `/`, home dir, etc.) or dangerous file writes can be rendered permanently non-functional by an attacker who crafts (or a well-meaning contributor who writes) a rule file with a comma inside the pattern. Because `evaluate_rules` (`plugins/hookify/core/rule_engine.py:35-94`) returns `{}` (allow) when no blocking rule matches, PreToolUse/PostToolUse hooks will approve the dangerous Bash command or file write that the rule was supposed to block, while the markdown file still visually shows `enabled: true` to a reviewer — matching the "hook enforcement bypass leading to unauthorized command/file action" bounty category.

### Likelihood Explanation
Highly feasible and repeatable: it requires no special privilege beyond being able to add/modify a `.claude/hookify.*.local.md` rule file (e.g. via a PR to the repo, since these rules are loaded via `glob.glob('.claude/hookify.*.local.md')` in `load_rules`, `plugins/hookify/core/config_loader.py:198-241`). Any pattern containing a comma-triggering character class or alternation deterministically reproduces the truncation — this is a parser logic bug, not a probabilistic race.

### Recommendation
Replace the hand-rolled comma-splitting inline-dict parser with a proper YAML parser (e.g. `pyyaml` or Python's `yaml.safe_load`) for the frontmatter block, or at minimum change the inline-dict tokenizer to split only on `, ` sequences that are followed by a recognized key name pattern (e.g. regex `,\s*(field|operator|pattern):`) rather than every comma, and add a round-trip sanity check (e.g. attempt `re.compile` on any `regex_match` pattern at load time and reject/log the rule loudly if it fails, rather than silently returning "no match" at evaluation time).

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules

    def evaluate_rules(self, rules: List[Rule], input_data: Dict[str, Any]) -> Dict[str, Any]:
        """Evaluate all rules and return combined results.

        Checks all rules and accumulates matches. Blocking rules take priority
        over warning rules. All matching rule messages are combined.

        Args:
            rules: List of Rule objects to evaluate
            input_data: Hook input JSON (tool_name, tool_input, etc.)

        Returns:
            Response dict with systemMessage, hookSpecificOutput, etc.
            Empty dict {} if no rules match.
        """
        hook_event = input_data.get('hook_event_name', '')
        blocking_rules = []
        warning_rules = []

        for rule in rules:
            if self._rule_matches(rule, input_data):
                if rule.action == 'block':
                    blocking_rules.append(rule)
                else:
                    warning_rules.append(rule)

        # If any blocking rules matched, block the operation
        if blocking_rules:
            messages = [f"**[{r.name}]**\n{r.message}" for r in blocking_rules]
            combined_message = "\n\n".join(messages)

            # Use appropriate blocking format based on event type
            if hook_event == 'Stop':
                return {
                    "decision": "block",
                    "reason": combined_message,
                    "systemMessage": combined_message
                }
            elif hook_event in ['PreToolUse', 'PostToolUse']:
                return {
                    "hookSpecificOutput": {
                        "hookEventName": hook_event,
                        "permissionDecision": "deny"
                    },
                    "systemMessage": combined_message
                }
            else:
                # For other events, just show message
                return {
                    "systemMessage": combined_message
                }

        # If only warnings, show them but allow operation
        if warning_rules:
            messages = [f"**[{r.name}]**\n{r.message}" for r in warning_rules]
            return {
                "systemMessage": "\n\n".join(messages)
            }

        # No matches - allow operation
        return {}
