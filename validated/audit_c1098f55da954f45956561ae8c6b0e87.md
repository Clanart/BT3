## Title
`IntentGatewayV2` (Tron) authenticates cross-chain settlement messages against an unregistered-chain fallback that defaults to `address(this)`, enabling forged `RedeemEscrow`/`RefundEscrow` messages to drain real escrow — (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The standalone Tron implementation of `IntentGatewayV2` re-implements cross-chain authentication with a subtly different `instance()` lookup than the canonical EVM implementation. Where the EVM version's `_instance()` **reverts** with `UnknownInstance()` when a state machine has no registered gateway, the Tron version's `instance()` silently **falls back to `address(this)`**. Because `authenticate()` — the sole gate protecting `RedeemEscrow`/`RefundEscrow` settlement — calls this defaulting `instance()`, any inbound ISMP message claiming to originate from a chain that has never been registered via `NewDeployment` will authenticate successfully as long as `request.from` equals the gateway's own address on the destination chain. This lets an attacker who can get code deployed at that exact address on any Hyperbridge-connected but unregistered chain forge a withdrawal request and redeem another user's real escrowed funds.

### Finding Description
Compare the two implementations:

Canonical EVM version (`evm/src/apps/intentsv2/IntentsBase.sol`): [1](#0-0) 

Tron monolithic version (`evm/tron/contracts/apps/IntentGatewayV2.sol`): [2](#0-1) 

The canonical `_instance()` reverts with `UnknownInstance()` if `_instances[keccak256(stateMachineId)]` is zero. The Tron `instance()` instead returns `address(this)` as a default. This function is used directly inside `authenticate()`, the only check gating `RedeemEscrow`/`RefundEscrow` processing in `onAccept()`: [3](#0-2) 

`onAccept` is restricted to `onlyHost`, i.e. any ISMP message the host has proof-verified and routed for `dest == this chain` reaches this branch — the host only vouches for the *existence and provenance* of the message (source chain + `from` address), not for whether the app-level `_instances` registry recognizes that pairing. Since `authenticate()` compares `instance(request.source)` (which resolves to `address(this)` for any state machine ID never registered by governance's `NewDeployment` message) against `module = address(bytes20(request.from))`, a message whose claimed `request.source` is an unregistered chain and whose `request.from` equals the gateway's own address will pass authentication.

`withdraw()` then transfers the named escrowed tokens straight to an attacker-chosen `beneficiary`: [4](#0-3) 

The escrowed amounts and token addresses for any order are public (`OrderPlaced`/`DustCollected` events, and `_orders[commitment][token]` storage), so an attacker only needs to name a real, currently-escrowed `commitment`/token/amount and set `beneficiary` to their own address.

### Impact Explanation
This is a false-acceptance / unauthenticated-execution bug matching the bounty's core categories: it lets an unprivileged actor forge a settlement message that Hyperbridge's host correctly delivers (a legitimate, proof-verified message from *some* connected chain) but that the app layer should have rejected because no gateway is registered for that source. The result is direct theft of another user's escrowed input tokens plus the escrowed transaction fee (`TRANSACTION_FEES`), i.e. unauthorized transaction execution and fund loss/wrong-beneficiary payout — squarely within "stealing or loss of funds" / "false proof/state acceptance" / "unauthorized transaction or execution."

### Likelihood Explanation
Exploitability hinges only on the attacker being able to place code at the same address the gateway occupies on the destination chain, on some other Hyperbridge-connected chain that has not yet had `NewDeployment` called for it. Given the codebase's explicit reliance on deterministic CREATE2 addresses to keep the gateway bytecode/address identical across chains (noted in `IntentsBase._blockNumber()`'s comment about "preserving deterministic CREATE2 deployment addresses"), this is a realistic condition on any newly supported or not-yet-fully-configured state machine — no malicious relayer, prover, or governance actor is required, only an unprivileged deployer racing to occupy an address before/without official registration.

### Recommendation
Make `instance()` (and any authentication path using it) revert on an unregistered state machine instead of defaulting to `address(this)`, mirroring `IntentsBase._instance()`'s `UnknownInstance()` behavior in the canonical EVM contracts. If a same-chain fallback is genuinely intended for some flows, split that behavior into a separate, explicitly-named helper that is never used inside `authenticate()`.

### Proof of Concept
1. Governance has not yet called `NewDeployment` for state machine `X` on the destination-chain `IntentGatewayV2`, so `_instances[keccak256(X)] == address(0)`.
2. Attacker observes a real order's `OrderPlaced` event/`_orders` storage on the destination chain and notes `commitment`, escrowed `token`, `amount`.
3. Attacker deploys (or otherwise obtains) a contract at `address(this)` (the gateway's own deterministic CREATE2 address) on chain `X`, and gets Hyperbridge to relay a POST message with `source = X`, `from = abi.encodePacked(address(this))`, `to = abi.encodePacked(address(this))`, body = `RequestKind.RedeemEscrow` + `WithdrawalRequest{commitment, tokens: [{token, amount}], beneficiary: attacker}`.
4. `onAccept()` → `authenticate()` calls `instance(X)`, which returns `address(this)` (fallback), matching `module = address(this)` from `request.from` → authentication passes.
5. `withdraw()` transfers `amount` of `token` from the real order's escrow to the attacker's `beneficiary` address, stealing the user's escrowed funds without ever legitimately filling the order. [2](#0-1) [3](#0-2) [4](#0-3) [1](#0-0)

     * @dev Fetch the IntentGateway contract instance for a chain.
     */
    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;
    }

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
