### Title
Unauthenticated call to `internal_send_tx` when `client_verification=false` bypasses `only_aggregator_and_self` caller check - ([File: core/src/rpc/interceptors.rs], [File: core/src/rpc/aggregator.rs])

### Summary
The `is_internal()`/`only_aggregator_and_self()` caller-identity check that is supposed to restrict `Internal*`-prefixed gRPC methods (e.g. `internal_send_tx`) to the aggregator's own client certificate is implemented purely inside the `Interceptors::OnlyAggregatorAndSelf` variant. When `config.client_verification == false`, the server installs `Interceptors::Noop` instead, which does not call `is_internal()` at all and simply forwards every request unauthenticated. This lets any unauthenticated caller reach `internal_send_tx` and insert an attacker-chosen transaction into the aggregator's `tx_sender` fee-bump/RBF tracking.

### Finding Description
The binding the code intends to enforce is:
`caller_of_Internal*_method == self.our_cert` (asserted by `only_aggregator_and_self` when `is_internal(&req)` is true) [1](#0-0) .

That equality is only ever evaluated inside the `OnlyAggregatorAndSelf` branch of the `Interceptor::call` dispatch [2](#0-1) . The alternate `Noop` variant returns `Ok(req)` unconditionally, never consulting `is_internal()` or any certificate [3](#0-2) .

Which variant gets installed is decided at server construction time based on `config.client_verification`:
```
if config.client_verification { ... OnlyAggregatorAndSelf { ... } } else { Noop }
``` [4](#0-3) 

This is wired into `create_aggregator_grpc_server`, which builds the aggregator's `ClementineAggregatorServer` and calls `create_grpc_server` with the config, so the same TCP-exposed aggregator port carries whichever interceptor was chosen [5](#0-4) .

So when `client_verification == false`: `is_internal()`'s prefix check and the `leaf_cert == our_cert` comparison are never executed for any request, including `internal_*` RPCs. The equality `caller_cert == our_cert` degenerates to "no check is performed," i.e. `caller_cert` can be `None`/anything and the call still proceeds to `ClementineAggregator::internal_send_tx`, which (following the same pattern shown by the sibling `send_emergency_stop_tx` helper) opens a db transaction, calls `self.tx_sender.insert_try_to_send(...)` with the attacker-supplied transaction and fee type, and commits [6](#0-5) . No signature, ownership, or role check is applied to the raw transaction bytes at this layer; the only gate was supposed to be the interceptor's certificate check, which is absent under `Noop`.

Existing guards that might otherwise stop this do not apply here: `is_deposit_valid`, `SECP.verify_schnorr`, `SPV::verify`, and the presigned transaction graph govern deposit/withdrawal/kickoff correctness, not who may call `internal_send_tx`; none of them gate this RPC.

### Impact Explanation
This is an unauthenticated state-changing/broadcasting-adjacent call: an attacker can make the aggregator track (and later fee-bump/rebroadcast via CPFP/RBF) an arbitrary transaction of the attacker's choosing, consuming the aggregator's own UTXO/fee infrastructure to propagate it. By itself, this does not let the attacker directly spend a bridge UTXO or credit a fraudulent reimbursement — `insert_try_to_send` only queues a transaction the attacker already had bytes for; it does not forge N-of-N signatures or bypass deposit/withdrawal validation elsewhere in the system. It matches the "High - an unauthenticated state-changing or broadcasting call" category rather than any of the Critical categories, since none of the Critical impacts (BTC leaving a move-to-vault UTXO, wrongful reimbursement, frozen vault, false claim proved, forged N-of-N signature, leaked secnonce) is demonstrated to follow from this call alone. The blast radius is repeatable per call (each call inserts one more attacker tx into the aggregator's queue) and is present for the whole lifetime of any deployment run with `client_verification=false`.

### Likelihood Explanation
Requires the operator/deployer to run the aggregator with `client_verification=false` (i.e., without mutual TLS) and the `automation` feature compiled in — both are deployment/config choices, not defaults enforced by the code; the code only emits a `tracing::warn!` about this in `create_aggregator_grpc_server` [7](#0-6)  but does not disable the internal RPCs. Given that configuration, exploitation costs nothing beyond network access to the aggregator's gRPC port and a syntactically valid `raw_tx`/`fee_type` payload — no BTC, no signature forgery, no privileged role needed.

### Recommendation
Perform the `is_internal()` prefix check (and reject if no verified caller certificate is present) unconditionally in the gRPC middleware/interceptor layer regardless of which `Interceptors` variant is active, or refuse to construct `Interceptors::Noop` for servers that expose `Internal*` methods. At minimum, `Interceptors::Noop::call` should still enforce `is_internal(&req) == false` (i.e., reject any request to an `Internal*`-prefixed method when no certificate-based caller verification is configured) instead of unconditionally returning `Ok(req)`.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
