### Title
DataLayer Mirror URL Server-Side Request Forgery via Unvalidated On-Chain URL Memos - ([File: chia/data_layer/download_data.py])

### Summary
Any user can pay a small fee to publish a DataLayer "mirror" coin whose `urls` memo field is an arbitrary, completely unvalidated string. That memo is later read by any other participant's DataLayer node that tracks/subscribes to the same store, and is used directly as a target for outbound HTTP requests (`aiohttp` `GET`/`POST`) during routine sync. This is a direct analog of CVE-2020-9298 (Spinnaker SSRF via unvalidated template/URL resolution): attacker-supplied, on-chain-propagated URL data drives server-initiated network requests with no scheme/host allow-listing.

### Finding Description
`DataLayerWallet.create_new_mirror()` lets any wallet create a mirror coin carrying a `launcher_id` plus arbitrary `urls` in the `CREATE_COIN` memo field, with no validation of the URL strings: [1](#0-0) 

The RPC surface (`add_mirror` / `dl_new_mirror`) forwards these attacker-chosen strings unchanged: [2](#0-1) [3](#0-2) 

When the mirror coin is spent/created, any node tracking that launcher id decodes and stores the URLs verbatim, with no format or scheme check: [4](#0-3) [5](#0-4) 

Any DataLayer service subscribed to (or that owns) the store periodically fetches these mirror URLs from the wallet and feeds them into `DataStore` as candidate servers for the store: [6](#0-5) 

During the periodic sync loop, `fetch_and_validate()` iterates the resulting `servers_info` (URLs sourced from these mirrors) and calls `insert_from_delta_file()`/`download_file()`/`http_download()`, which performs an outbound `aiohttp` HTTP GET directly against the attacker-supplied URL with no scheme restriction, no private/internal-IP blocking, and no allow-list: [7](#0-6) [8](#0-7) 

The same pattern applies to the plugin `downloader`/`uploader` path, which also POSTs JSON containing the raw mirror URL to a configured plugin endpoint: [9](#0-8) 

No component in this chain — `create_new_mirror`, `add_mirror`, `get_mirror_info`, `update_subscriptions_from_wallet`, or `http_download` — validates the URL's scheme (`file://`, arbitrary ports), host (loopback, link-local metadata addresses such as `169.254.169.254`, RFC1918 private ranges, or internal service hostnames), or otherwise restricts destinations before the DataLayer service issues the request.

### Impact Explanation
Any spend-bundle submitter/wallet user can force other DataLayer participants' nodes (any node that tracks the launcher id or auto-subscribes to owned/local stores) to make outbound HTTP requests to attacker-chosen destinations, entirely under attacker control of host/port/path. This enables classic SSRF outcomes reachable from a fully unprivileged on-chain action: probing/reaching internal-only services and cloud metadata endpoints reachable from the victim's DataLayer host, triggering internal side effects on services that accept unauthenticated GET/POST, and indirectly leaking whether internal hosts are reachable (via response/timeout behavior surfaced in logs, `get_downloader`/plugin responses, or sync success/failure). This qualifies as at least a High-severity SSRF, matching the referenced CVE's class and CVSS profile, since it requires no privileged access — only publishing a coin with a memo, and it triggers the victim's own server to make unauthenticated internal requests.

### Likelihood Explanation
Likelihood is high: creating a mirror coin only requires a wallet transaction and paying `amount` + `fee`, and there is no scheme/host validation anywhere in the pipeline (`create_new_mirror`, `add_mirror`, `dl_new_mirror`, `get_mirror_info`, `update_subscriptions_from_wallet`, `http_download`). Any node that tracks the launcher id (which any node can do via `dl_track_new`), or that owns/subscribes to the store, will automatically pick up and fetch from the malicious mirror URL during its normal periodic `periodically_manage_data()` sync loop without any user interaction required on the victim side.

### Recommendation
Validate and restrict mirror/subscription URLs before they are persisted or dereferenced: enforce an `http(s)://` scheme allow-list, reject loopback/link-local/private-network hosts (or provide an explicit opt-in/allow-list config for such hosts), and apply the same validation both when a mirror memo is decoded (`get_mirror_info`/`coin_added`) and when `add_mirror`/`subscribe` accept URLs via RPC. Consider resolving hostnames and re-checking the resolved IP against a deny-list immediately before each `aiohttp` request in `http_download()`/`download_file()`/`get_downloader()` to prevent DNS-rebinding bypass of allow-list checks performed earlier.

### Proof of Concept
1. Attacker creates a DataLayer store or reuses an existing `launcher_id`, then calls `add_mirror` (`data_rpc_api.add_mirror({"id": store_id.hex(), "urls": ["http://169.254.169.254/latest/meta-data/"], "amount": 1, "fee": 1})`), publishing a mirror coin with an internal/metadata-service URL memo, as validated by the existing test harness pattern: [10](#0-9) 
2. Victim's DataLayer node tracks the same `launcher_id` (e.g., via `dl_track_new`, or automatically as an owned/auto-subscribed store) and periodically calls `update_subscriptions_from_wallet()`, pulling the attacker's URL into its subscription server list: [6](#0-5) 
3. During the next `periodically_manage_data()` cycle, `fetch_and_validate()`/`insert_from_delta_file()`/`http_download()` issues an outbound HTTP GET from the victim's DataLayer host directly to `http://169.254.169.254/latest/meta-data/` with no destination validation: [8](#0-7)

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
