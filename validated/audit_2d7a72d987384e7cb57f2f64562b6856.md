### Title
Webhook shop attribution derived from unverified `X-Shopify-Shop-Domain` header, not the HMAC-signed payload - (File: `lib/shopify_app/controller_concerns/webhook_verification.rb`)

### Summary
`ShopifyApp::WebhookVerification#shop_domain` returns the raw, attacker-controlled `HTTP_X_SHOPIFY_SHOP_DOMAIN` header, and `hmac_valid?` (in `PayloadVerification`) computes the HMAC only over `request.raw_post` using the app's single shared secret. Because the app-wide secret (not a per-shop secret) is used and the domain header is never included in the HMAC computation, a valid `(body, HMAC)` pair captured from any shop's webhook remains valid when replayed with a different `X-Shopify-Shop-Domain` header, allowing shop attribution spoofing.

### Finding Description
`verify_request` only checks `hmac_valid?(request.raw_post)` before allowing the request through: [1](#0-0) 

`hmac_valid?` computes `HMAC-SHA256(secret, raw_post)` using `ShopifyApp.configuration.secret`/`old_secret`, which are app-level (client) secrets shared across all shops that installed the app — not shop-specific: [2](#0-1) 

Separately, `shop_domain` is derived purely from the unverified header, with no cross-check against any claim in the signed body: [3](#0-2) 

Because the HMAC digest input (`data`) is only the raw body and the shared secret is identical for every shop using this app, the domain header is completely outside the cryptographic binding. An attacker who owns (or can trigger webhooks in) any single shop that has installed the app can capture a legitimate `(raw_post, X-Shopify-Hmac-Sha256)` pair from their own store's webhook deliveries, then replay that exact body/HMAC to the app's webhook endpoint while setting `X-Shopify-Shop-Domain` to a victim shop's domain. `hmac_valid?` will still return true (same secret, same body, same HMAC), and `shop_domain` will report the victim's domain to the including controller.

The default `ShopifyApp::WebhooksController#receive` action forwards the raw body/headers to `ShopifyAPI::Webhooks::Registry.process`, which is provided by the `shopify_api` gem (not in this repo) — so the shipped controller does not exhibit the impact directly in this codebase. However, `shop_domain` is a public API intended for use by including controllers/handlers in host apps, and the module offers no mechanism ensuring downstream consumers bind the topic/shop claim in the payload to the header-derived domain. Any handler that trusts `shop_domain` from this concern to select which shop's session/data to act on is vulnerable to cross-shop confusion.

### Impact Explanation
Concrete scoped impact: cross-shop confusion where an attacker who controls one legitimate installation's webhook traffic can cause the app to process/attribute the replayed webhook payload as belonging to a different shop, since the shop binding is taken from an unauthenticated header rather than any signed claim. This matches "Shopify webhook forgery / cross-shop confusion" impact class — potential unauthorized state changes or data attributed to the wrong shop's session in any handler that relies on this module's `shop_domain`.

### Likelihood Explanation
Preconditions: the attacker needs to have or obtain at least one legitimate `(raw_post, HMAC)` webhook pair from any shop using the app (achievable for an attacker who installs the app on their own unrelated shop and triggers a webhook event, e.g., via `orders/create`), and must be able to send arbitrary headers to the app's public webhook endpoint (trivially true for an anonymous HTTP client). The replay is straightforward and fully repeatable since the shared secret and body never change per shop. The main mitigating factor is that the stock `WebhooksController#receive` delegates real processing/verification to the `shopify_api` gem's `Registry.process`, whose internal domain-binding behavior is outside this repo and unverified here.

### Recommendation
Do not treat `shop_domain` as trustworthy for shop attribution unless it is cross-validated against a claim actually covered by the signature, or unless per-shop replay protection is added (e.g., a nonce/timestamp check plus binding the domain into the HMAC-covered data, or validating the domain against the shop that owns the webhook topic/resource ID in the payload). At minimum, document that `shop_domain` in this module is unverified and must not be used alone to select a tenant/session; require the app to fetch or validate the shop domain via `ShopifyAPI::Webhooks::Registry.process`'s verified context rather than this header method.

test "replayed valid HMAC/body from shop A is accepted while spoofing shop B's domain" do
  body = '{"id":123,"topic":"orders/create"}'
  hmac = Base64.strict_encode64(OpenSSL::HMAC.digest("sha256", ShopifyApp.configuration.secret, body))

  post "/webhooks/dummy",
    params: body,
    headers: {
      "HTTP_X_SHOPIFY_HMAC_SHA256" => hmac,
      "HTTP_X_SHOPIFY_SHOP_DOMAIN" => "shop-b.myshopify.com", # attacker-chosen, unrelated to body
      "CONTENT_TYPE" => "application/json",
    }

  assert_response :ok
  # Expected (secure) behavior: request should be rejected because domain is not bound to signed payload
  # Actual behavior: request passes verify_request, shop_domain returns "shop-b.myshopify.com"
end

module ShopifyApp
  module WebhookVerification
    extend ActiveSupport::Concern
    include ShopifyApp::PayloadVerification

    included do
      skip_before_action :verify_authenticity_token, raise: false
      before_action :verify_request
    end

    private

    def verify_request
      data = request.raw_post
      unless hmac_valid?(data)
        ShopifyApp::Logger.debug("Webhook verification failed - HMAC invalid")
        head(:unauthorized)
      end
    end

    def shop_domain
      request.headers["HTTP_X_SHOPIFY_SHOP_DOMAIN"]
    end
  end
end

# frozen_string_literal: true

module ShopifyApp
  module PayloadVerification
    extend ActiveSupport::Concern

    private

    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
  end
end
