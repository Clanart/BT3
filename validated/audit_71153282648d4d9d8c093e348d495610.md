### Title
Attacker-controlled deposits are misclassified as internal Branch/Change/Forwarded outputs via address-only object reference - (File: processor/src/networks/bitcoin.rs)

### Summary
The Bitcoin scanner classifies every scanned output solely by which registered `script_pubkey` it matches (`Scanner::scan_transaction`), then maps the matched offset back to an `OutputType` in `Bitcoin::get_outputs` without verifying the output was created by the protocol (an IDOR-style analog: the "object role" is selected by the attacker's chosen address with no ownership check). An unprivileged user who sends funds to the multisig's Branch, Change, or Forwarded derived address causes those coins to be treated as protocol-internal outputs rather than `External` deposits.

### Finding Description
`Scanner` registers internal offsets deterministically via `Secp256k1::hash_to_F(KEY_DST, b"branch" | b"change" | b"forward")` (`processor/src/networks/bitcoin.rs:308-346`, `scanner()`). `scan_transaction` matches on `output.script_pubkey` alone (`networks/bitcoin/src/wallet/mod.rs:199-214`), and `get_outputs` then assigns `kind = kinds[offset_repr]` and leaves `data` empty unless `kind == OutputType::External` (`processor/src/networks/bitcoin.rs:686-737`). The `register_offset` doc itself warns that arbitrary offsets "may introduce a script path into the output" and must be "securely generated" (`wallet/mod.rs:168-180`), yet any third party can derive the same addresses (the offsets are a public function of the group key and fixed labels) and pay to them.

### Impact Explanation
Deposits sent to the Change/Forwarded/Branch addresses are reported to the scheduler as internal outputs (not `External`, no `InInstruction` data attached). `Forwarded`/`Branch` outputs are ones the protocol itself creates during plan execution and forwarding; treating attacker-created coins as such injects unplanned, unattributed funds into plan accounting — outputs get scheduled/spent under semantics never authorized for them, and `presumed_origin`/data attribution is lost. Because `register_offset` is surjective (odd keys increment the offset), the attacker can also collide with an offset slot the protocol has not yet registered for that key, changing which `OutputType` later registrations resolve to. This is a concrete "funds reported with wrong semantics" condition reachable with only a Bitcoin transaction the attacker sends.

### Likelihood Explanation
The derived addresses are publicly computable (group key is public; `KEY_DST` and the labels are constants in the file). Any depositor or observer can craft a tx paying to the change/forward script_pubkey. Likelihood of accidental or deliberate occurrence is moderate; the blast radius is limited to mis-accounted funds within the affected multisig, consistent with Medium.

### Recommendation
Tag internal outputs at creation time (e.g., embed a protocol marker/commitment in the tx creating Branch/Change/Forwarded outputs, or match outputs against the scheduler's expected outpoints rather than script_pubkey alone) so scanner classification cannot be claimed by unsolicited payments. At minimum, reject or quarantine non-`External` outputs whose creating transaction is not a protocol-issued tx.

### Proof of Concept
1. Observe the multisig group key `K` on chain.
2. Compute `change = p2tr(key + G*hash_to_F(KEY_DST,"change") adjusted to even)` using `scanner()`/`forward_address` logic in `processor/src/networks/bitcoin.rs:314-346`.
3. Send a normal Bitcoin tx paying ≥ dust to that script_pubkey.
4. `get_outputs` returns it as `Output{ kind: OutputType::Change, data: vec![], presumed_origin: <attacker> }` — indistinguishable from protocol-generated change, entering the scheduler's input pool.

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
