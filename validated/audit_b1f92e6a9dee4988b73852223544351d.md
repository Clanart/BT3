### Title
Unrestricted arbitrary file deletion via harvester RPC `/delete_plot` `filename` parameter - (File: `chia/harvester/harvester.py`)

### Summary
The harvester RPC endpoint `/delete_plot` accepts an attacker/caller-supplied `filename` string and passes it, unvalidated, straight into a filesystem `unlink()` call. There is no check that the resolved path lies within one of the harvester's configured plot directories, nor that the target file has a `.plot`/`.plot2` extension, nor any canonicalization/allow-list check to prevent path traversal (`../`) or use of an absolute path pointing anywhere on disk. Any caller authorized to reach the harvester RPC (e.g. a lower-privileged local/automation client, or any party that obtains harvester RPC access) can delete arbitrary files reachable by the harvester process, which is the same bug class as the reported CVE-2024-0763 (unsanitized removal parameter enabling path traversal / arbitrary deletion behind an authorized-but-limited endpoint).

### Finding Description
The RPC handler extracts the filename directly from the request body with no sanitization: [1](#0-0) 

It forwards to `Harvester.delete_plot()`: [2](#0-1) 

Which calls `remove_plot()`: [3](#0-2) 

`remove_plot()` performs no validation whatsoever beyond `path.exists()` — it does not verify that `path` is one of the paths currently tracked in `PlotManager.plots`/`plot_filename_paths`, does not restrict the path to configured plot directories (`get_plot_directories()`), and does not reject relative traversal sequences or absolute paths outside those directories. The module's own documentation confirms this is intentional/known: "There is no extra ownership model in this module; RPC authorization and local file permissions are the relevant gates." [4](#0-3) 

Because the only gate is generic RPC authorization (not authorization tied to *which* file/directory may be touched), any caller with harvester RPC access — which is a narrower/lower trust boundary than full node-owner control — can pass an arbitrary absolute path or a relative path containing `..` segments and delete any file the harvester process has permission to remove (config files, SSL keys, plot files belonging to other configured directories, databases, etc.), not just files actually located in a configured plot directory.

### Impact Explanation
This is a High-severity issue analogous to CVE-2024-0763: an authorized-but-scope-limited caller can delete arbitrary files on the harvester host, causing denial of service (loss of plot files/keys/config, harvester process crash, farming outage) or destruction of data outside the intended plot-management scope. Unlike the upstream report's recursive folder deletion, the impact here is single-file `unlink()`, but it is unauthenticated-with-respect-to-target (no ownership/scope check) and directly reachable from any client holding harvester RPC credentials.

### Likelihood Explanation
Likelihood is high for any actor who already has some level of access to the harvester RPC (the same precondition the original report requires — "attacker would need access to the server at some privilege level since this endpoint is protected and requires authorization"). No additional exploitation complexity is required beyond crafting a `filename` value; the code path performs no defensive checks at all.

### Recommendation
In `remove_plot()` (`chia/plotting/util.py`) and/or `Harvester.delete_plot()`, resolve the supplied path with `Path(str_path).resolve()` and require that the resolved path is a child of one of the currently configured plot directories (`get_plot_directories(root_path)`) and/or is present in `PlotManager.plots`/`plot_filename_paths` before calling `unlink()`. Reject the request otherwise.

### Proof of Concept
1. Obtain harvester RPC access with any account/credential capable of calling `/delete_plot` (this is the same authorization level the CVE report assumes).
2. Send:
```json
POST /delete_plot
{"filename": "/home/user/.chia/mainnet/config/config.yaml"}
```
or a relative traversal such as `"filename": "../../../../etc/passwd"` depending on process cwd/permissions.
3. `HarvesterRpcApi.delete_plot()` → `Harvester.delete_plot()` → `remove_plot()` executes `Path(str_path).unlink()` with no ownership check, deleting the target file if the harvester process has permission, regardless of whether it is a tracked plot file. [1](#0-0) [2](#0-1) [3](#0-2)
