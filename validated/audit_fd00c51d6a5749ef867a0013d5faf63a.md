### Title
Spoofable `WWW-Authenticate` header lets an attacker-controlled Git remote trigger an "Enterprise sign-in" flow bound to their own server - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The bug-class in the report is a *desync between two independent trust decisions that should be linked* — one contract (`OasisSwapFactory`) could be reconfigured independently from the one actually consulted at call time (`OasisSwapRouter`/`OasisSwapPair`), letting an attacker exploit whichever value was weaker. The Desktop analog is the credential-helper's endpoint-classification logic: it has two ways to decide "is this remote a real GitHub host?" — an authoritative network probe (`isGitHubHost`) and an unauthenticated heuristic based on the HTTP `WWW-Authenticate` header that Git forwards verbatim from the remote server. The heuristic is checked *first* and short-circuits the authoritative check, so a malicious remote server can force Desktop to treat it as GitHub Enterprise and open a bound sign-in flow to itself.

### Finding Description
`getEndpointKind()` classifies a credential request by trying several signals in order, and returns as soon as one matches: [1](#0-0) 

The relevant branch trusts the `wwwauth[N]` credential field — populated straight from the remote HTTP server's `WWW-Authenticate` response header, per Git's credential-helper protocol — and classifies the host as `'enterprise'` whenever it contains `realm="GitHub"`: [2](#0-1) 

This check happens *before* the only authoritative signal, `isGitHubHost(endpoint)`, which actually probes the remote: [3](#0-2) 

Once classified `'enterprise'`, `getCredential()` — finding no existing account for that endpoint — invokes the GitHub sign-in prompt directly against the attacker's own host: [4](#0-3) 

`promptForGitHubSignIn` then binds the sign-in flow to that raw endpoint origin (not a validated GitHub host) and shows the popup with the attacker's URL displayed as the credential-helper target: [5](#0-4) 

`SignInStore.setEndpoint`/`_setSignInEndpoint` only validates that the URL is syntactically well-formed HTTPS (`validateURL`) — it does **not** re-verify that the host is actually a GitHub/GHE instance: [6](#0-5) [7](#0-6) 

Finally, `authenticateWithBrowser` opens the OS browser at an OAuth-authorize URL built from that same attacker-controlled endpoint: [8](#0-7) 

This is the same broken-invariant shape as the report: the "is this trusted GitHub" decision is supposed to be a single, verified value, but the code allows a cheap, remote-supplied signal (the header) to override/bypass the authoritative probe, so the two paths can disagree — and the attacker fully controls which one wins.

### Impact Explanation
An attacker who controls a Git HTTPS remote (e.g., a malicious clone URL, a compromised/typosquatted server, or a proxy/MITM on an HTTPS git operation) can respond to Git's authentication challenge with `WWW-Authenticate: Basic realm="GitHub"`. When the user performs any git operation against that remote from Desktop (clone, fetch, push, pull), Desktop's credential helper will:
1. classify the host as GitHub Enterprise purely from that header, with no verification that the host is actually GitHub-branded software,
2. pop the trusted "Sign in" dialog with text implying legitimacy ("Git requesting credentials to access `<url>`"),
3. bind the enterprise sign-in/OAuth flow to the attacker's own origin, and
4. open the system browser at an OAuth authorize URL served entirely by the attacker.

Because the flow is initiated by Desktop's own UI, it lends credibility to what is effectively an OAuth/credential phishing page, matches "unauthorized OAuth or account binding" directly, and could result in the user's GitHub credentials/token being harvested by the attacker's fake authorize/login page, or an attacker endpoint being bound as a trusted account inside Desktop.

### Likelihood Explanation
Triggering the header is trivial for anyone who controls the git server end of an HTTPS connection — no special git configuration or privileged position beyond "the remote/proxy the user is talking to" is required, which matches the report's accepted attacker model ("a git remote/proxy response"). The only gating condition is that the user doesn't already have an account matching that literal endpoint, which is the common case for a brand-new/attacker-supplied remote.

### Recommendation
Do not let the unauthenticated `WWW-Authenticate` heuristic be sufficient, by itself, to launch the interactive Enterprise sign-in/OAuth flow. Either:
- Require confirmation via the authoritative `isGitHubHost()` probe (or an equivalent server-side verification, e.g. checking for GitHub-specific response headers over a real request) before ever transitioning to `'enterprise'`/prompting sign-in based on `wwwauth[]` alone, or
- Surface to the user, before opening the browser, the concrete host that will receive their OAuth session, and require explicit confirmation that they intend to add that specific host as a GitHub Enterprise account — removing the implicit "silently treat as GitHub" behavior added purely as a network-request-saving heuristic.

### Proof of Concept
1. Stand up an HTTPS git server (or MITM proxy) that, on any credential-required request, returns a `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add this remote and attempt a fetch/push over HTTPS.
3. Git captures the header and forwards `wwwauth[0]=...realm="GitHub"...` to Desktop's credential-helper trampoline (`createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`).
4. Observe that `getEndpointKind` returns `'enterprise'` without ever calling `isGitHubHost`, and Desktop shows the "Sign in" dialog with `credentialHelperUrl` set to the attacker's URL and initiates `beginEnterpriseSignIn` + `setSignInEndpoint(origin)` bound to the attacker's host.
5. If the user proceeds, `authenticateWithBrowser` opens the system browser at an OAuth-authorize URL rooted at the attacker's server, which the attacker fully controls.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export function validateURL(address: string): string {
  // ensure user has specified text and not just whitespace
  // we will interact with this server so we can be fairly
  // relaxed here about what we accept for the server name
  const trimmed = address.trim()
  if (trimmed.length === 0) {
    const error = new Error('Unknown address')
    error.name = InvalidURLErrorName
    throw error
  }

  let url = URL.parse(trimmed)
  if (!url.host) {
    // E.g., if they user entered 'ghe.io', let's assume they're using https.
    address = `https://${trimmed}`
    url = URL.parse(address)
  }

  if (!url.protocol) {
    const error = new Error('Invalid URL')
    error.name = InvalidURLErrorName
    throw error
  }

  if (url.protocol !== 'https:') {
    const error = new Error('Invalid protocol')
    error.name = InvalidProtocolErrorName
    throw error
  }

  return address
}

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
