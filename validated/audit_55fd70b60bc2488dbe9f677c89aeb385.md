## Title
Server-Side Request Forgery via unvalidated DataLayer mirror URLs - (`chia/data_layer/download_data.py`)

## Summary
Any wallet user can publish an arbitrary URL on-chain as a DataLayer "mirror" for a store. Every other DataLayer node that subscribes to that store id (which happens automatically for any store a peer chooses to sync) will fetch that attacker-controlled URL over HTTP with no validation of scheme, host, or address range, i.e. a server-side request forgery, directly analogous to the CVAT SSRF where user-supplied import/annotation URLs were fetched without validation.

## Finding Description
A wallet holder creates an on-chain "mirror" coin for a DataLayer store by calling `create_new_mirror()`, which spends XCH into a `create_mirror_puzzle()` coin whose memo encodes `[launcher_id, *urls]` with fully attacker-chosen `urls`: [1](#0-0) 

This is reachable through the public `dl_new_mirror` wallet RPC and the DataLayer `add_mirror` RPC — the only check performed is that the URL list is non-empty: [2](#0-1) 

When any other node's `DataLayerWallet` observes the mirror coin being created (which happens for every peer tracking that launcher id), it decodes the memo and persists the raw URLs with no validation of scheme or host: [3](#0-2) [4](#0-3) 

The DataLayer service then pulls these mirror URLs from wallet RPC and stores them directly as subscription server URLs, again without validation: [5](#0-4) 

During the periodic sync loop, `fetch_and_validate()` iterates over these attacker-controlled server URLs and passes them straight into the download pipeline: [6](#0-5) 

`insert_from_delta_file()` → `download_file()` → `http_download()` performs an outbound `aiohttp` GET directly against `server_info.url` with no allow-list, no scheme restriction, and no check against loopback/link-local/private address ranges (e.g. cloud metadata endpoints such as `169.254.169.254`): [7](#0-6) [8](#0-7) 

This is confirmed by the project's own module documentation, which explicitly flags mirror/plugin URLs as untrusted external inputs but only speaks to validating downloaded *data*, not the *destination* of the request: [9](#0-8) [10](#0-9) 

## Impact Explanation
Any funded wallet user (no special privileges required) can register a mirror URL pointing at an internal-only endpoint (cloud instance metadata service, another service on the operator's LAN, the node's own unauthenticated internal ports, etc.). Any DataLayer operator who subscribes to that store — a normal, expected DataLayer client action — will have their node issue outbound HTTP requests to the attacker-chosen destination. This can be used for internal network reconnaissance, reaching otherwise unreachable internal services, or exfiltrating cloud metadata/credentials in cloud-hosted deployments, matching the class and severity of the CVAT SSRF (CVE-2022-31188). It is not a mempool/consensus asset-forgery bug, but it is a genuine SSRF reachable by an unprivileged DataLayer/wallet client interacting with normal on-chain mirror publication.

## Likelihood Explanation
High: publishing a mirror is a normal, permissionless, low-cost DataLayer operation (`dl_new_mirror`/`add_mirror`), and any node subscribing to the targeted store will automatically perform the vulnerable fetch during its regular sync loop with no user interaction or confirmation required.

## Recommendation
Validate mirror/server URLs before they are persisted as subscription sources and again before `http_download()` issues the request: enforce an allow-listed scheme (e.g. `http`/`https` only), resolve and reject requests targeting loopback, link-local, and private/reserved address ranges (unless explicitly opted in for local testing), and consider requiring operator confirmation before adding new mirror server URLs discovered on-chain.

## Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (or `data add_mirror` CLI/RPC) for a store id with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` and a minimal fee, per `chia/data_layer/data_layer.py:965-970` and `chia/data_layer/data_layer_wallet.py:687-703`.
2. The mirror coin is confirmed on-chain; any victim DataLayer node subscribed to that store id observes the coin via `DataLayerWallet.coin_added` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores the URL as a mirror/subscription server.
3. On the victim's next sync cycle, `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-694`) picks the malicious URL and calls `insert_from_delta_file → download_file → http_download` (`chia/data_layer/download_data.py:110-145,298-319`), causing the victim node to issue an outbound HTTP GET to the attacker-chosen internal address.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```

```markdown
- `update_subscription()` performs four ordered steps: sync subscription URLs from wallet mirrors, fetch/validate remote data, upload local files for owned/current data, then prune old full files. Reordering these affects mirror discovery and file availability.
- Wallet reachability failures are intentionally non-fatal. Subscription tracking stops early if the wallet RPC connection is unavailable and retries next cycle; per-subscription failures are logged without killing the loop.
- `fetch_and_validate()` uses wallet singleton history as the target generation/root sequence, randomizes eligible server URLs, tries plugin-specific or plain HTTP delta downloads, and marks mirror/server failures with backoff in the subscriptions table.
```
