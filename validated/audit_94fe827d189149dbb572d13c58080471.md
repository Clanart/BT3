## Finding: Division-by-zero DoS via ungated `kip71.gastarget` governance parameter

### Title
Panic (chain-wide DoS) via zero `GasTarget` in `KIP71Config.NextMagmaBlockBaseFee` - (File: `params/kip71_config.go`)

### Summary
The `NextMagmaBlockBaseFee` function computes the EIP-1559/KIP-71 style base-fee delta by dividing by `gasTarget` without checking for zero, mirroring the Firebird `sdl_desc()` bug where an unvalidated, attacker-controlled length is later used as a divisor. In Kaia, the `kip71.gastarget` governance parameter is accepted with **no format validation** (`noopFormatChecker`) and is exempted from consistency checks in header governance, so it can legitimately be ratified to `0`, after which every node panics computing/verifying the next block's base fee.

### Finding Description
`KIP71Config.NextMagmaBlockBaseFee` reads `gasTarget := kc.GasTarget` and, whenever the parent block's gas usage differs from `gasTarget`, divides by it directly with no zero-check: [1](#0-0) [2](#0-1) 

Unlike `BaseFeeDenominator`, which has an explicit fallback (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = 64 }`) at [3](#0-2) , `GasTarget` has no such safety net.

The governance parameter registry defines `Kip71GasTarget` with `FormatChecker: noopFormatChecker`, i.e., any value (including `0`) passes format validation: [4](#0-3) [5](#0-4) 

The header-governance vote-consistency checker (`checkConsistency`) explicitly whitelists `gov.Kip71GasTarget` into the "no additional check" bucket, alongside other params that pass through unconditionally: [6](#0-5) 

By contrast, `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` do get bound-consistency checks in the same function (lines 188-201), showing `GasTarget` was overlooked.

Once ratified (via `governance_vote` from the governing node in `single` mode, or any council member in `none` mode, per [7](#0-6) ), `GasTarget = 0` takes effect at the next epoch. From that point on, `NextMagmaBlockBaseFee` is invoked on every block (in `VerifyMagmaHeader` for header verification, and in `feehistory.go` for RPC) with `parentHeaderGasUsed` typically `> 0`. Since `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` will be `> gasTarget (0)`, the code enters the "increase" branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))`, i.e., `big.Int.Div(x, 0)`, which panics in Go's `math/big` package.

This is invoked from block processing on every node (`VerifyMagmaHeader`) and from the public `eth_feeHistory` RPC (`node/cn/gasprice/feehistory.go` `processBlock`) at [8](#0-7) , so any node — including non-governing full/endpoint nodes just verifying blocks or serving RPC — panics/crashes.

### Impact Explanation
Once the parameter is ratified network-wide, **every node** (validators, full nodes, endpoint/RPC nodes) crashes as soon as it tries to compute or verify the next block's base fee, or serve `eth_feeHistory`. This halts the entire chain — a complete network-wide denial of service, matching the "High" impact class of the referenced Firebird analog (unauthenticated crash via unvalidated divisor).

### Likelihood Explanation
Likelihood depends on governance access: in `single` mode only the governing node can cast/ratify votes (`ErrVotePermissionDenied` gate in [9](#0-8) ); in `none` mode any council member can. Either way, no code path currently prevents a governing entity from ratifying `kip71.gastarget = 0` — the format checker (`noopFormatChecker`) and consistency checker (unconditional `nil`) both accept it. This is a real gap: a single malicious or careless governance vote (not a bug in consensus/crypto) permanently bricks the network the moment it becomes effective, with no way to un-ratify without a hard fork/code patch, since the crash happens before any subsequent corrective vote could be processed.

### Recommendation
Add a zero-value rejection to `Kip71GasTarget`'s `FormatChecker` (e.g., `v > 0`), and add explicit `gasTarget == 0` handling (reject the vote, or apply a safe fallback similar to `BaseFeeDenominator`'s fallback) in `checkConsistency` for `gov.Kip71GasTarget`. Defensively, `KIP71Config.NextMagmaBlockBaseFee` should also guard against `gasTarget == 0` before dividing, returning a safe default (e.g., treat it like the equal-usage case, or clamp to a nonzero fallback) rather than dividing by zero.

### Proof of Concept
1. Governing node calls `governance_vote("kip71.gastarget", 0)`. This passes `NewVoteData`/`checkConsistency` unchanged since `Kip71GasTarget` has `noopFormatChecker` and is in the unconditional-`nil` branch of `checkConsistency`.
2. The vote is included in `header.Vote`, ratified at the next epoch boundary, and becomes effective at `(k+1)*epoch + 1`.
3. At the first block after activation with `parentHeaderGasUsed > 0` (virtually guaranteed on any live chain), every node calling `KIP71Config.NextMagmaBlockBaseFee` (via `VerifyMagmaHeader` during block import/verification, or via `eth_feeHistory` RPC) executes `x.Div(x, big.NewInt(0))`, which panics, crashing the node process.

```go
// (2) integrity of the voter (the voter must be the block proposer),
// (3) the vote value must be consistent compared to the latest ParamSet.
func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}
```
