### Title
Scanner::scan_block reports coinbase outputs as received despite them being immature and unspendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The kernel bug (CVE-2024-41012) is a failure-to-reliably-remove-state bug: a lock that should have been deleted survives and is later read back via `/proc/locks`, yielding information the consumer should never have acted on. The Serai analog is `Scanner::scan_block` in `networks/bitcoin/src/wallet/mod.rs`, which iterates `block.txdata` including `txdata[0]` — the coinbase transaction. Coinbase outputs are encumbered by a 100-block maturity rule and cannot be spent, yet `scan_block` returns them as ordinary `ReceivedOutput`s indistinguishable from spendable ones.

### Finding Description
`Scanner::scan_block` scans every transaction in the block:

```rust
// networks/bitcoin/src/wallet/mod.rs
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
```

`scan_transaction` matches only `output.script_pubkey` against the registered script map, so a coinbase output paying to a Serai Taproot key produces a `ReceivedOutput` with a valid `offset` and `outpoint`. Nothing in `ReceivedOutput`, `Scanner`, or the serialization format (`ReceivedOutput::read`) records that this output originated from a coinbase, so downstream consumers cannot distinguish it from a normal, immediately-spendable UTXO.

The doc comment acknowledges the hazard ("a post-processing pass is needed to remove those outputs"), but the API actively hands back the stale/unusable entry — mirroring the kernel bug where a lock that should have been removed was still enumerated and read. The downstream danger is real rather than hypothetical: the processor's own Bitcoin integration deliberately skips the coinbase (`for tx in &block.txdata[1 ..]` in `processor/src/networks/bitcoin.rs`, `get_outputs`), demonstrating that feeding coinbase outputs into the spend pipeline is a recognized failure mode that `bitcoin_serai`'s `Scanner` does not itself prevent. Any consumer that uses `scan_block` as the natural "scan this confirmed block" API — rather than manually slicing `block.txdata[1 ..]` — receives a `ReceivedOutput` it cannot spend, and any signer building a `SignableTransaction` over it will produce a transaction Bitcoin consensus rejects (BIP-30/maturity violation), or worse, the output is registered in scheduling/accounting state as available balance that never materializes as spendable.

### Impact Explanation
Funds are reported as received that are not spendable for ~100 blocks. A wallet or scheduler consuming `ReceivedOutput`s from `scan_block` may (a) count immature coinbase value toward spendable balance and construct a `SignableTransaction` spending it, yielding a transaction that can never be mined, stalling payments, or (b) account the output as received collateral while any spending attempt permanently fails until maturity. This matches the "funds reported received that are not spendable" acceptance criterion.

### Likelihood Explanation
Reachable by an unprivileged party only insofar as a miner (or mining pool) can direct a coinbase payout to the watched P2TR script — this does occur in practice when pools pay out via coinbase or when an attacker mines/regtest-mines to the address deliberately. Exploitation requires a downstream consumer that trusts `scan_block` output without the documented post-processing; the library provides no type-level or runtime guard, so this is a realistic integration failure. Medium likelihood, medium impact.

### Recommendation
In `Scanner::scan_block`, skip `block.txdata[0]` (or filter `tx.is_coinbase()`), and/or mark `ReceivedOutput` with a maturity flag so consumers can enforce spendability. If coinbase scanning is intentionally retained, return a distinct type that cannot be fed directly into `SignableTransaction::new`.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
