### Title
Unbounded Per-Operator Bitcoin RPC Loop in `is_deposit_valid` Permanently Stalls Deposit Finalization as Operator Set Grows — (`core/src/verifier.rs`)

---

### Summary

`is_deposit_valid` in `core/src/verifier.rs` fetches every row from the `operators` table and, for each row, executes a full `collateral_check` that itself loops over every protocol round and fires multiple Bitcoin RPC calls. Because operators are only ever inserted into the DB and never pruned, the total work per deposit validation grows as `O(|operators_in_db| × num_round_txs)` Bitcoin RPC calls. Once the operator set is large enough, the function exceeds the deposit-pipeline timeout, making every subsequent deposit attempt fail permanently with no recovery path.

---

### Finding Description

**Root cause — `is_deposit_valid` (lines 605–628, `core/src/verifier.rs`)**

```rust
let operators_in_db = self.db.get_operators(None).await?;   // unbounded SELECT *
for (xonly_pk, reimburse_addr, collateral_funding_outpoint) in operators_in_db.iter() {
    // DB query per operator
    let kickoff_winternitz_pks = self.db
        .get_operator_kickoff_winternitz_public_keys(None, *xonly_pk).await?;
    // Bitcoin RPC fan-out per operator
    let is_collateral_usable = self.rpc
        .collateral_check(&operator_data, &kickoff_wpks, self.config.protocol_paramset())
        .await?;
    ...
}

**`collateral_check` cost per operator (`core/src/extended_bitcoin_rpc.rs`, lines 88–240)**

Inside `collateral_check`, after two initial RPC calls (`get_tx_of_txid`, `is_tx_on_chain`), there is a second loop over every round:

```rust
for round_idx in RoundIndex::iter_rounds(paramset.num_round_txs) {
    // is_tx_on_chain, get_blockhash_of_tx, get_block_info, is_utxo_spent
    ...
}
``` [2](#0-1) 

Each operator therefore costs `2 + O(num_round_txs × 4)` synchronous Bitcoin RPC calls. The calls are sequential (no parallelism), so wall-clock time scales linearly with both dimensions.

**Operators accumulate without bound**

`insert_operator_if_not_exists` adds a row on every `set_operator` call and never deletes rows:

```rust
"INSERT INTO operators (xonly_pk, wallet_reimburse_address, collateral_funding_outpoint)
 VALUES ($1, $2, $3)
 ON CONFLICT (xonly_pk) DO NOTHING"
``` [3](#0-2) 

`get_operators` returns every row unconditionally:

```rust
"SELECT xonly_pk, wallet_reimburse_address, collateral_funding_outpoint FROM operators;"
``` [4](#0-3) 

There is no `DELETE FROM operators` path anywhere in the codebase. Operators that have exited the protocol (collateral spent) remain in the table and are still iterated on every deposit.

**Call site — deposit nonce generation**

`is_deposit_valid` is called inside the verifier's deposit-nonce-generation handler, which is invoked by the aggregator's `new_deposit` pipeline. The pipeline runs under `OVERALL_DEPOSIT_TIMEOUT`:

```rust
timed_request(OVERALL_DEPOSIT_TIMEOUT, "Overall new deposit", async { ... })
``` [5](#0-4) 

Once the sequential RPC fan-out exceeds that timeout, every `new_deposit` call fails and the bridge's deposit path is permanently stalled.

---

### Impact Explanation

- **Deposit liveness permanently broken.** No new BTC can be moved into the bridge vault once `is_deposit_valid` consistently times out. Existing vault UTXOs are unaffected, but the bridge becomes one-directional (withdrawals only) until the code is patched and the service restarted.
- **No self-healing.** There is no operator-pruning RPC, no DB migration, and no pagination in `get_operators`. The only remediation is a code change plus DB cleanup.
- **Severity: Medium** — matches the external report's classification: liveness loss without direct fund theft, but with permanent, unrecoverable bridge impact.

---

### Likelihood Explanation

- Operators are registered by the aggregator (a trusted actor), so this is not an instant exploit.
- However, the growth is **organic**: every operator that ever joined the protocol, even those long since exited, remains in the DB. A bridge that has cycled through dozens of operators over its lifetime will accumulate them all.
- `collateral_check` is itself expensive: for each operator it walks the full round-tx chain on Bitcoin, making the timeout reachable with a surprisingly small operator count (e.g., 20 operators × 10 rounds × 4 RPC calls = 800 sequential calls).
- No privileged attacker is required; normal protocol operation is sufficient.

---

### Recommendation

1. **Paginate or cap the operator scan.** Add a `LIMIT`/`OFFSET` to `get_operators`, or introduce a separate `get_active_operators` query that filters by a `is_active` flag set to `false` when collateral is detected as spent by the state machine.
2. **Cache collateral status.** The state machine already tracks operator exit (`RoundEvent::OperatorExit`). Persist a `collateral_usable` boolean in the `operators` table and update it on exit; `is_deposit_valid` can then skip the RPC fan-out for exited operators.
3. **Parallelize `collateral_check` calls.** Even without pruning, running all operator checks concurrently with `try_join_all` would reduce wall-clock time from `O(N)` to `O(1)` (bounded by the slowest single check).
4. **Add a hard cap on registered operators.** Reject `set_operator` if `SELECT COUNT(*) FROM operators` exceeds a protocol-defined maximum, consistent with how `MAX_EXTRA_WATCHTOWERS` and `MAX_NUMBER_OF_WATCHTOWERS` are enforced. [6](#0-5) 

---

### Proof of Concept

1. Register N operators via the aggregator `setup` RPC (each calls `set_operator` on every verifier, inserting a row into `operators`).
2. Have some operators exit the protocol (spend their collateral outside the bridge). Their rows remain in the DB.
3. Submit a new deposit via `aggregator.new_deposit(...)`.
4. The verifier's `is_deposit_valid` fetches all N rows and calls `collateral_check` sequentially for each, making `N × (2 + num_round_txs × 4)` Bitcoin RPC calls.
5. With N large enough (exact threshold depends on `num_round_txs` and Bitcoin node latency), the call chain exceeds `OVERALL_DEPOSIT_TIMEOUT`.
6. Every subsequent deposit attempt returns a timeout error; the deposit path is permanently stalled. [7](#0-6) [8](#0-7) [9](#0-8)

        // check if security council is the same as in our config
        if deposit_data.security_council != self.config.security_council {

    async fn collateral_check(
        &self,
        operator_data: &OperatorData,
        kickoff_wpks: &KickoffWinternitzKeys,
        paramset: &'static ProtocolParamset,
    ) -> std::result::Result<bool, BridgeError> {
        // first check if the collateral utxo is on chain or mempool
        let tx = self
            .get_tx_of_txid(&operator_data.collateral_funding_outpoint.txid)
            .await
            .wrap_err(format!(
                "Failed to find collateral utxo in chain for outpoint {:?}",
                operator_data.collateral_funding_outpoint
            ))?;
        let collateral_outpoint = match tx
            .output
            .get(operator_data.collateral_funding_outpoint.vout as usize)
        {
            Some(output) => output,
            None => {
                tracing::warn!(
                    "No output at index {} for txid {} while checking for collateral existence",
                    operator_data.collateral_funding_outpoint.vout,
                    operator_data.collateral_funding_outpoint.txid
                );
                return Ok(false);
            }
        };

        if collateral_outpoint.value != paramset.collateral_funding_amount {
            tracing::error!(
                "Collateral amount for collateral {:?} is not correct: expected {}, got {}",
                operator_data.collateral_funding_outpoint,
                paramset.collateral_funding_amount,
                collateral_outpoint.value
            );
            return Ok(false);
        }

        let operator_tpr_address =
            create_taproot_address(&[], Some(operator_data.xonly_pk), paramset.network).0;

        if collateral_outpoint.script_pubkey != operator_tpr_address.script_pubkey() {
            tracing::error!(
                "Collateral script pubkey for collateral {:?} is not correct: expected {}, got {}",
                operator_data.collateral_funding_outpoint,
                operator_tpr_address.script_pubkey(),
                collateral_outpoint.script_pubkey
            );
            return Ok(false);
        }

        // we additionally check if collateral utxo is on chain (so not in mempool)
        // on mainnet we fail if collateral utxo is not on chain because if it is in mempool,
        // the txid of the utxo can change if the fee is bumped
        // on other networks, we allow collateral to be in mempool to not wait for collateral to be on chain to do deposits for faster testing
        let is_on_chain = self
            .is_tx_on_chain(&operator_data.collateral_funding_outpoint.txid)
            .await?;
        if !is_on_chain {
            return match paramset.network {
                bitcoin::Network::Bitcoin => Ok(false),
                _ => Ok(true),
            };
        }

        let mut current_collateral_outpoint: OutPoint = operator_data.collateral_funding_outpoint;
        let mut prev_ready_to_reimburse: Option<TxHandler> = None;
        // iterate over all rounds
        for round_idx in RoundIndex::iter_rounds(paramset.num_round_txs) {
            // create round and ready to reimburse txs for the round
            let txhandlers = create_round_txhandlers(
                paramset,
                round_idx,
                operator_data,
                kickoff_wpks,
                prev_ready_to_reimburse.as_ref(),
            )?;

            let mut round_txhandler_opt = None;
            let mut ready_to_reimburse_txhandler_opt = None;
            for txhandler in &txhandlers {
                match txhandler.get_transaction_type() {
                    TransactionType::Round => round_txhandler_opt = Some(txhandler),
                    TransactionType::ReadyToReimburse => {
                        ready_to_reimburse_txhandler_opt = Some(txhandler)
                    }
                    _ => {}
                }
            }
            if round_txhandler_opt.is_none() || ready_to_reimburse_txhandler_opt.is_none() {
                return Err(eyre!(
                    "Failed to create round and ready to reimburse txs for round {:?} for operator {}",
                    round_idx,
                    operator_data.xonly_pk
                ).into());
            }

            let round_txid = round_txhandler_opt
                .expect("Round txhandler should exist, checked above")
                .get_cached_tx()
                .compute_txid();
            let is_round_tx_on_chain = self.is_tx_on_chain(&round_txid).await?;
            if !is_round_tx_on_chain {
                break;
            }
            let block_hash = self.get_blockhash_of_tx(&round_txid).await?;
            let block_height = self
                .get_block_info(&block_hash)
                .await
                .wrap_err(format!(
                    "Failed to get block info for block hash {block_hash}"
                ))?
                .height;
            if block_height < paramset.start_height as usize {
                tracing::warn!(
                    "Collateral utxo of operator {operator_data:?} is spent in a block before paramset start height: {block_height} < {0}",
                    paramset.start_height
                );
                return Ok(false);
            }
            current_collateral_outpoint = OutPoint {
                txid: round_txid,
                vout: UtxoVout::CollateralInRound.get_vout(),
            };
            if round_idx == RoundIndex::Round(paramset.num_round_txs - 1) {
                // for the last round, only check round tx, as if the operator sent the ready to reimburse tx of last round,
                // it cannot create more kickoffs anymore
                break;
            }
            let ready_to_reimburse_txhandler = ready_to_reimburse_txhandler_opt
                .expect("Ready to reimburse txhandler should exist");
            let ready_to_reimburse_txid =
                ready_to_reimburse_txhandler.get_cached_tx().compute_txid();
            let is_ready_to_reimburse_tx_on_chain =
                self.is_tx_on_chain(&ready_to_reimburse_txid).await?;
            if !is_ready_to_reimburse_tx_on_chain {
                break;
            }

            current_collateral_outpoint = OutPoint {
                txid: ready_to_reimburse_txid,
                vout: UtxoVout::CollateralInReadyToReimburse.get_vout(),
            };

            prev_ready_to_reimburse = Some(ready_to_reimburse_txhandler.clone());
        }

        // if the collateral utxo we found latest in the round tx chain is spent, operators collateral is spent from Clementine
        // bridge protocol, thus it is unusable and operator cannot fulfill withdrawals anymore
        // if not spent, it should exist in chain, which is checked below
        Ok(!self.is_utxo_spent(&current_collateral_outpoint).await?)
    }

    pub async fn get_operators(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
    ) -> Result<Vec<(XOnlyPublicKey, bitcoin::Address, OutPoint)>, BridgeError> {
        let query = sqlx::query_as(
            "SELECT xonly_pk, wallet_reimburse_address, collateral_funding_outpoint FROM operators;"
        );

        let operators: Vec<(XOnlyPublicKeyDB, AddressDB, OutPointDB)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        // Convert the result to the desired format
        let data = operators
            .into_iter()
            .map(|(pk, addr, outpoint_db)| {
                let xonly_pk = pk.0;
                let addr = addr.0.assume_checked();
                let outpoint = outpoint_db.0; // Extract the Txid from TxidDB
                Ok((xonly_pk, addr, outpoint))
            })
            .collect::<Result<Vec<_>, BridgeError>>()?;
        Ok(data)
    }
