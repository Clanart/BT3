### Title
Uncontrolled recursion in `AccountKeySerializer`/`AccountKeyRoleBased` RLP decoding causes unrecoverable stack-overflow crash via a deeply nested `AccountKeyRoleBased` in a transaction's `Key` field (DoS) - (File: `blockchain/types/accountkey/account_key_serializer.go`, `blockchain/types/accountkey/account_key_role_based.go`)

### Summary
`AccountKeySerializer.DecodeRLP` and `AccountKeyRoleBased.DecodeRLP` form a mutually-recursive decoding cycle with no nesting-depth limit, directly analogous to the NLTK `FeatStructReader` bug class (CWE-674, uncontrolled recursion). An `AccountUpdate`/`FeeDelegatedAccountUpdate`-style transaction (or any RLP blob containing an `AccountKeySerializer`) whose `Key` field encodes a deeply nested `AccountKeyRoleBased` (a role-based key containing a role-based key containing a role-based key, ...) drives the decoder into unbounded recursion during `rlp.DecodeBytes`/`rlp.Stream.Decode`, which happens on ordinary transaction ingestion/decoding, before any signature or semantic validation occurs.

### Finding Description
The recursive call chain:

1. `AccountKeySerializer.DecodeRLP` reads the key type, calls `NewAccountKey(keyType)`, and then calls `s.Decode(serializer.key)`: [1](#0-0) 

2. If `keyType == AccountKeyTypeRoleBased`, `NewAccountKey` returns an `*AccountKeyRoleBased`: [2](#0-1) 

3. `AccountKeyRoleBased.DecodeRLP` decodes a list of raw byte blobs and, for **each element**, creates a fresh `AccountKeySerializer` and calls `rlp.DecodeBytes` on it — re-entering step 1: [3](#0-2) 

This closes the cycle `AccountKeySerializer.DecodeRLP → AccountKeyRoleBased.DecodeRLP → AccountKeySerializer.DecodeRLP → ...` with no `MAX_*_DEPTH`-style guard anywhere in `blockchain/types/accountkey`. Each additional layer of nested `AccountKeyRoleBased` in the input adds one more full cycle of Go call frames.

The intended business rule — "a `RoleBased` key must not contain a nested `RoleBased` key as one of its role keys" — is only checked in the JSON-RPC convenience helper `checkAccountKeyZeroValues`, used solely by the `kaia_encodeAccountKey` API: [4](#0-3) 

It is **not** enforced inside `AccountKeyRoleBased.DecodeRLP` itself, and is not called from the RLP-decoding path used for ordinary transaction processing (`TxInternalDataAccountUpdate.UnmarshalJSON` / struct-tag-driven RLP decode of `TxInternalDataAccountUpdate`/`TxInternalDataAccountCreation`, both of which just call `rlp.DecodeBytes(js.Key, ser)` and take whatever `ser.GetKey()` returns): [5](#0-4) [6](#0-5) 

Unlike the Python `RecursionError` in the original NLTK report (which is catchable), an uncontrolled Go recursion of this kind exhausts the goroutine stack and triggers a **fatal, unrecoverable `runtime: goroutine stack exceeds ... — fatal error: stack overflow`**, which cannot be caught by `recover()` and terminates the entire process, not just the current request/goroutine.

### Impact Explanation
Any code path that RLP-decodes a transaction's `Key` field — transaction-pool admission on `eth_sendRawTransaction`/p2p tx propagation, block processing/state-transition when applying an `AccountUpdate` or `FeeDelegatedAccountUpdate*` transaction, or the `kaia_decodeAccountKey` RPC — reaches this decoder. A single crafted transaction with a sufficiently deep chain of nested `AccountKeyRoleBased` structures in its `Key` bytes can crash any full node (or all nodes, if propagated over the network / included as a candidate transaction) that attempts to decode it, since the crash is a hard process-level `fatal error`, not a recoverable panic. This is a State divergence / node-crash Denial-of-Service reachable from an unprivileged, unauthenticated transaction sender or RPC caller, matching the accepted impact category "acceptance/decoding of an invalid transaction causing crash / state divergence between honest nodes" (nodes that fail to decode crash, while others that never receive/attempt to decode it stay alive).

### Likelihood Explanation
The payload is trivial to construct: repeatedly wrap an `AccountKeyRoleBased` list containing one nested serialized `AccountKeyRoleBased` blob, RLP-encode it, and place it as the `Key` field of an `AccountUpdate` transaction (or feed it directly to `kaia_decodeAccountKey`). No valid signatures, special privileges, or costly computation are required — only nesting depth, achievable in well under a kilobyte of encoded data, similar to the ~700-byte PoC in the original report. Since decoding happens before fee/nonce/signature checks in most ingestion paths, the recursive decode executes even for tx-pool admission of an as-yet-unvalidated transaction.

### Recommendation
Add an explicit recursion-depth counter (e.g., a `maxAccountKeyNestDepth` constant, mirroring `MAX_PARSE_DEPTH`/`MAX_DECODE_DEPTH` patterns) threaded through `AccountKeySerializer.DecodeRLP` and `AccountKeyRoleBased.DecodeRLP`, returning a normal decode error once exceeded instead of recursing further. Additionally, enforce the existing "no nested `RoleBased` key" invariant directly inside `AccountKeyRoleBased.DecodeRLP` (and its `UnmarshalJSON` counterpart) rather than only in the `api_kaia.go` RPC helper, so that a single level of nesting is structurally rejected at decode time before recursion can occur.

### Proof of Concept
Conceptual reproduction (Go, using this repo's `accountkey` and `rlp` packages):
```go
// Build increasingly nested AccountKeyRoleBased blobs.
inner := accountkey.NewAccountKeyRoleBasedWithValues(accountkey.AccountKeyRoleBased{
    accountkey.NewAccountKeyLegacy(),
})
for i := 0; i < 100000; i++ { // depth tunable; a few thousand is enough to overflow the goroutine stack
    inner = accountkey.NewAccountKeyRoleBasedWithValues(accountkey.AccountKeyRoleBased{
        inner,
    })
}
enc, _ := rlp.EncodeToBytes(accountkey.NewAccountKeySerializerWithAccountKey(inner))

// Decoding this blob (as done for any AccountUpdate tx's Key field, or via
// KaiaAPI.DecodeAccountKey) recurses AccountKeySerializer.DecodeRLP <-> AccountKeyRoleBased.DecodeRLP
// with no depth limit, ending in a fatal, unrecoverable stack overflow:
dec := accountkey.NewAccountKeySerializer()
_ = rlp.DecodeBytes(enc, &dec) // process crashes with "fatal error: stack overflow"
```
This mirrors placing such an `enc` blob as the `Key` field of a serialized `TxInternalDataAccountUpdate`/`TxInternalDataFeeDelegatedAccountUpdate` and submitting it via `eth_sendRawTransaction` or propagating it over the p2p network for other nodes to decode.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

// checkAccountKeyZeroValues returns errors if the input account key contains zero values of threshold or weight.
func checkAccountKeyZeroValues(key accountkey.AccountKey, isNested bool) error {
	switch key.Type() {
	case accountkey.AccountKeyTypeWeightedMultiSig:
		multiSigKey, _ := key.(*accountkey.AccountKeyWeightedMultiSig)
		if multiSigKey.Threshold == 0 {
			return errors.New("invalid threshold of the multiSigKey")
		}
		for _, weightedKey := range multiSigKey.Keys {
			if weightedKey.Weight == 0 {
				return errors.New("invalid weight of the multiSigKey")
			}
		}
	case accountkey.AccountKeyTypeRoleBased:
		if isNested {
			return errors.New("roleBasedKey cannot contains a roleBasedKey as a role key")
		}
		roleBasedKey, _ := key.(*accountkey.AccountKeyRoleBased)
		for _, roleKey := range *roleBasedKey {
			if err := checkAccountKeyZeroValues(roleKey, true); err != nil {
				return err
			}
		}
	}
	return nil
}

	js := &TxInternalDataAccountUpdateJSON{}
	if err := json.Unmarshal(b, js); err != nil {
		return err
	}

	ser := accountkey.NewAccountKeySerializer()
	if err := rlp.DecodeBytes(js.Key, ser); err != nil {
		logger.Warn("UnmarshalJSON failed", "err", err)
		return kerrors.ErrUnserializableKey
	}

	t.AccountNonce = uint64(js.AccountNonce)
	t.Price = (*big.Int)(js.Price)
	t.GasLimit = uint64(js.GasLimit)
	t.From = js.From
	t.Key = ser.GetKey()
	t.TxSignatures = js.TxSignatures.ToTxSignatures()
	t.Hash = js.Hash

	return nil
}
