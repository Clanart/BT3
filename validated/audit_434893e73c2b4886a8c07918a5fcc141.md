### Title
Payout OP_RETURN operator attribution is unauthenticated (SIGHASH_SINGLE|ANYONECANPAY leaves it unsigned), letting anyone credit a reimbursement to an uninvolved operator - (File: `core/src/verifier.rs`, `core/src/rpc/parser/operator.rs`, `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The withdrawal input's user signature is mandatorily `TapSighashType::SinglePlusAnyoneCanPay`, which only commits to input 0 and output 0 of the Payout transaction. Outputs 1 (anchor) and 2 (OP_RETURN operator attribution) are unsigned and freely rewritable by anyone holding that signature, including the withdrawing user (an unprivileged attacker). `Verifier::update_finalized_payouts` trusts whichever transaction wins the race to spend the withdrawal UTXO and blindly parses its OP_RETURN as ground truth for "who fronted this payout," with no check that the named operator actually supplied the funding inputs.

### Finding Description
Binding claimed to hold: `operator credited for withdrawal i` (`withdrawals.payout_payer_operator_xonly_pk`, set by `Verifier::update_finalized_payouts`) `== operator whose wallet funded output 0 of the confirmed payout tx for withdrawal i`.

Trace:
1. `parse_withdrawal_sig_params` enforces the withdrawal's `input_signature.sighash_type == TapSighashType::SinglePlusAnyoneCanPay`, normalizing bare 64-byte sigs to it as well: [1](#0-0) 
2. `create_payout_txhandler` builds the Payout tx with exactly this key-spend signature on input 0 only, plus an unrelated/unsigned anchor output and an unsigned OP_RETURN output carrying the fronting operator's x-only pubkey: [2](#0-1) 
3. `calculate_pubkey_spend_sighash` confirms that for `SinglePlusAnyoneCanPay` the sighash only commits to `Prevouts::One(txin_index, ...)`, i.e. only input 0's own prevout and (per BIP341/BIP143 SIGHASH_SINGLE) output 0 - none of the other inputs or outputs (including the OP_RETURN) are covered: [3](#0-2) 
4. `get_payout_txs_for_withdrawal_utxos` records, for a given withdrawal `idx`, whichever transaction is observed on-chain spending the recorded `withdrawal_utxo_txid`/`vout` - i.e. whichever version of the Payout tx (original or attacker's rewrite) actually gets confirmed: [4](#0-3) 
5. `Verifier::update_finalized_payouts` then extracts the operator xonly pk purely from that confirmed tx's OP_RETURN with no signature/ownership check, and persists it via `update_payout_txs_and_payer_operator_xonly_pk`: [5](#0-4) 
6. `PayoutCheckerTask::run_once` polls `get_first_unhandled_payout_by_operator_xonly_pk` for the (now falsely-credited) operator B, finds the unhandled withdrawal, and calls `Operator::handle_finalized_payout`: [6](#0-5) 
7. `handle_finalized_payout` unconditionally grabs an unused kickoff connector for `self.signer.xonly_public_key` (operator B) and drives the kickoff→Reimburse flow for that deposit, with no check that B's own wallet actually funded the confirmed payout's non-signed inputs: [7](#0-6) 
8. `create_reimburse_txhandler` pays operator B's `reimburse_addr` the full value of the deposit's `DepositInMove` output (`bridge_amount`), spent from the shared MoveToVault UTXO: [8](#0-7) 

Why the one existing guard fails: `Verifier::is_kickoff_malicious` re-derives `operator_xonly_pk` from `get_payout_info_from_move_txid` (the same DB row corrupted by the attacker's OP_RETURN rewrite) and only checks that it matches `kickoff_data.operator_xonly_pk` and that the committed blockhash matches - both of which trivially hold for operator B's kickoff, since the DB and the confirmed on-chain OP_RETURN both already say "B": [9](#0-8) . No component ever verifies that the operator named in the OP_RETURN is the one whose wallet UTXOs actually fund the transaction (the only cryptographically-authenticated portions are input 0 and output 0, both controlled by the withdrawing user, not by any operator).

Exploit flow: the withdrawing user (an unprivileged attacker who calls `withdraw` on the Citrea bridge contract and holds their own `SinglePlusAnyoneCanPay` signature over their withdrawal UTXO/output) constructs a Bitcoin transaction reusing input 0 + output 0 unchanged (preserving the valid signature), adds their own funding input(s) to cover the payout amount, and sets the OP_RETURN to an arbitrary uninvolved operator B's x-only pubkey. They broadcast this and win the race to get it confirmed instead of (or before) any operator-fronted version. `update_finalized_payouts` records operator B as payer for withdrawal i; B's automated `PayoutCheckerTask` then produces a Reimburse tx draining that deposit's `bridge_amount` to B.

### Impact Explanation
The move-to-vault UTXO's `bridge_amount` for the deposit matched to withdrawal index i is spent via a Reimburse transaction to an operator who never funded that payout - Critical impact category "an operator reimbursed for a payout it never funded" / "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal." This is repeatable per withdrawal/deposit slot as long as the attacker can win the confirmation race for that specific withdrawal UTXO, and does not require any operator, verifier, or aggregator key material - only the withdrawing user's own signature (which they legitimately possess) and the ability to broadcast a competing Bitcoin transaction.

### Likelihood Explanation

    round_txhandler: &TxHandler,

        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,

            DEFAULT_SEQUENCE,
        )

            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,

    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    pub fn calculate_pubkey_spend_sighash(
        &self,
        txin_index: usize,
        sighash_type: TapSighashType,
    ) -> Result<TapSighash, BridgeError> {
        let prevouts_vec: Vec<&TxOut> = self
            .txins
            .iter()
            .map(|s| s.get_spendable().get_prevout())
            .collect();
        let mut sighash_cache: SighashCache<&bitcoin::Transaction> =
            SighashCache::new(&self.cached_tx);
        let prevouts = match sighash_type {
            TapSighashType::SinglePlusAnyoneCanPay
            | TapSighashType::AllPlusAnyoneCanPay
            | TapSighashType::NonePlusAnyoneCanPay => {
                bitcoin::sighash::Prevouts::One(txin_index, prevouts_vec[txin_index])
            }
            _ => bitcoin::sighash::Prevouts::All(&prevouts_vec),
        };

        let sig_hash = sighash_cache
            .taproot_key_spend_signature_hash(txin_index, &prevouts, sighash_type)
            .wrap_err("Failed to calculate taproot sighash for key spend")?;

    /// Returns the withdrawal indexes and their spending txid for the given

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }
