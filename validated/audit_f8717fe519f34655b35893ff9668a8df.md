### Title
Race between `BidPool.stop()` closing channels and concurrent `AddBid`/`HandleBid` sends causes panic ("send on closed channel") - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.stop()` closes `bp.bidMsgCh` and `bp.newBidCh` without any synchronization against concurrent producers (`AddBid` and `HandleBid`) that check the `running` flag and then send on those same channels. Because the "is running" check and the "close channel" operation are not mutually exclusive, an unprivileged auction bidder's RPC call (`auction_submitBid` → `AddBid`) or an incoming p2p bid message (`HandleBid`) can race with `AuctionModule.Stop()`/module restart and panic the whole node process.

### Finding Description
`BidPool.AddBid` reads the atomic `running` flag, then unconditionally sends on `bp.newBidCh`: [1](#0-0) 

`BidPool.HandleBid` similarly checks `running` and then sends on `bp.bidMsgCh`: [2](#0-1) 

`BidPool.stop()` clears `running`, then (independently, with no lock shared with the senders) closes both channels: [3](#0-2) 

There is a check-then-act TOCTOU window: a goroutine executing `AddBid`/`HandleBid` can pass the `running==1` check, then be preempted; concurrently `stop()` runs, flips `running` to 0, and closes `bp.newBidCh` / `bp.bidMsgCh`; the original goroutine resumes and executes `bp.newBidCh <- bid` (or `bp.bidMsgCh <- bid`) on an already-closed channel, which panics in Go ("send on closed channel"). This is the direct analog of the reported kernel bug class: a shared resource (channel/work item) is torn down/closed concurrently with a path that assumes it is still live, because initialization/teardown ordering isn't properly synchronized with the reachable request path.

`AuctionModule.Start()`/`Stop()` (which call `bp.start()`/`bp.stop()`) are lifecycle hooks that a running CN can invoke repeatedly (module restarts, e.g. on chain-config/head changes or explicit re-init), while `SubmitBid` (RPC, public though currently `Public: false` in `APIs()`) and `HandleBid` (invoked from the p2p message handler for any connected peer relaying a bid) are reachable at any time from an external bidder/peer. [4](#0-3) [5](#0-4) [6](#0-5) 

### Impact Explanation
A crash of the send-on-closed-channel panic is unrecovered (no `recover()` wraps `AddBid`/`HandleBid` or the RPC dispatch path for this), which will crash the entire node process — a full denial of service. Because `HandleBid` is reachable from any connected peer relaying auction bid gossip, and `AddBid` is reachable via the auction RPC, an attacker who can trigger (or simply race against) a module stop/restart cycle can crash a Consensus Node, impacting availability, block production, and — if multiple CNs run this code and are triggered similarly — potentially network-wide liveness. This satisfies the "state divergence between honest nodes" / DoS bar because a validator process crash directly affects block assembly/liveness for the affected node.

### Likelihood Explanation
Exploitability depends on being able to align a bid submission (or p2p bid relay) with the module's stop/restart window (e.g., during a config update, hard-fork switch, or explicit module restart triggered by governance-parameter or auction-config changes). This is a narrower window than a simple direct call but is still deterministically reachable by a bidder simply submitting bids continuously through such transitions, or by racing many bid submissions concurrently with restarts; it does not require special privilege, only normal use of the public bid/gossip surface.

### Recommendation
Synchronize channel close with in-flight senders, e.g. by guarding sends on `bidMsgCh`/`newBidCh` with the same lock/flag transition used in `stop()`, or by never closing these channels at all (use a separate `quit` channel + `select` in `AddBid`/`HandleBid` to detect shutdown instead of sending directly), or by wrapping sends in a `recover()`-based guard and treating a panic as "pool stopped, drop bid" rather than crashing the process.

### Proof of Concept
1. Start a CN with the auction module enabled and running (`bp.running == 1`).
2. In one goroutine, repeatedly call `AuctionAPI.SubmitBid` (or feed p2p bid messages via `HandleBid`) at high frequency.
3. In another goroutine, call `AuctionModule.Stop()` (as happens on module restart/reconfiguration) concurrently.
4. Because the `running` check in `AddBid`/`HandleBid` and the channel close in `stop()` are not mutually exclusive, occasionally a goroutine will read `running==1`, then `stop()` will close `bidMsgCh`/`newBidCh` before the send executes, causing a `panic: send on closed channel` that crashes the node.

func (bp *BidPool) stop() {
	// Stop the bid pool.
	atomic.CompareAndSwapUint32(&bp.running, 1, 0)
	bp.clearBidPool()

	// Only close channels if they haven't been closed before
	if atomic.CompareAndSwapUint32(&bp.stopped, 0, 1) {
		close(bp.bidMsgCh)
		close(bp.newBidCh)
	}
	bp.wg.Wait()
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
```

func (bp *BidPool) HandleBid(peerID string, bid *auction.Bid) {
	if atomic.LoadUint32(&bp.running) == 0 || bid == nil {
		return
	}

	// Check rate limit for this peer
	if !bp.checkRateLimit(peerID) {
		logger.Trace("Rate limit exceeded for peer", "peerID", peerID)
		return
	}

	select {
	case bp.bidMsgCh <- bid:
	default:
		logger.Trace("Bid queue is full, dropping bid", "peerID", peerID)
	}
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
```
