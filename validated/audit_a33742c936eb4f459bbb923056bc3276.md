### Title
Deserialized `ThresholdKeys` accept identity verification shares, yielding an identity (zeroed) group key with universally forgeable signatures - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` deserializes each verification share via `Ciphersuite::read_G`, which performs only canonical-encoding checks and does not reject the identity point (`crypto/ciphersuite/src/lib.rs:91-101`). `ThresholdKeys::new` then computes `group_key` as `Σ verification_shares[i] * interpolation_factor(i)` over participants `1..=t` (`crypto/dkg/src/lib.rs:376-378`) without checking that the result is non-identity, and without checking that `secret_share` is consistent with `verification_shares[i]` (`crypto/dkg/src/lib.rs:349-391`). An attacker supplying crafted bytes to `ThresholdKeys::read` (e.g., all verification shares set to the identity encoding) produces `ThresholdKeys` whose `group_key()` is the identity — analogous to the report where a lock zeroes `totalSTokenUnderlying` and a later conversion/withdraw operates on the zeroed aggregate. Schnorr verification `sG == R + cA` with `A = identity` is satisfied by any `s` with `R = sG`, so signatures for the resulting group key are trivially forgeable.

### Finding Description
- `Curve::read_G` in FROST explicitly rejects identity (`crypto/frost/src/curve/mod.rs:125-131`), but `ThresholdKeys::read` uses `C::read_G` — the ciphersuite-level reader — which only enforces canonical encoding (`crypto/dkg/src/lib.rs:620-623`, `crypto/ciphersuite/src/lib.rs:91-101`).
- `ThresholdKeys::new` computes the group key from the attacker-controlled shares with no identity/consistency check (`crypto/dkg/src/lib.rs:376-390`); `ThresholdParams`/`Participant` bounds-check only indices, not point validity.
- `SchnorrSignature::verify` checks `R + cA - sG == 0` via multiexp (`crypto/schnorr/src/lib.rs:88-110`). With `A = identity`, `(R = sG, s arbitrary)` always verifies — a forged signature for any challenge/message.
- Like the Carapace issue (aggregate zeroed → exchange rate 0 → shares burned for nothing), a zeroed aggregate (identity group key) is consumed downstream as if valid.

### Impact Explanation
Any consumer that accepts serialized `ThresholdKeys` from an untrusted source (or whose verification shares are corrupted/tampered, e.g., via storage or a malicious counterparty's key-package exchange) ends up with a group key of identity. Schnorr signatures "for" that key are forgeable by anyone, so funds or authorizations gated on the group key's signatures are fully compromised — equivalent to recovering assets with zero backing.

### Likelihood Explanation
Requires attacker-controlled bytes reaching `ThresholdKeys::read`/`ThresholdKeys::new` as verification shares. This is a real path in any flow deserializing or reconstructing keys from peer-supplied or stored data, but not exploitable purely via a signing round — hence Medium rather than High.

### Recommendation
In `ThresholdKeys::new` (and/or `read`), reject identity verification shares (use an identity-rejecting point read, as `Curve::read_G` does), assert `group_key` is non-identity, and verify `C::generator() * secret_share == verification_shares[params.i()]` before constructing the keys.

### Proof of Concept
```rust
// Craft serialized ThresholdKeys with all verification shares = identity.
let mut buf = vec![];
buf.extend((C::ID.len() as u32).to_le_bytes());
buf.extend(C::ID);
buf.extend(1u16.to_le_bytes()); // t = 1
buf.extend(1u16.to_le_bytes()); // n = 1
buf.extend(1u16.to_le_bytes()); // i = 1
buf.push(1);                    // Interpolation::Lagrange
buf.extend(C::F::ZERO.to_repr().as_ref());        // secret_share
buf.extend(C::G::identity().to_bytes().as_ref()); // identity verification share

let keys = ThresholdKeys::<C>::read(&mut buf.as_slice()).unwrap();
assert!(bool::from(keys.group_key().is_identity())); // zeroed aggregate accepted

// Forge a signature for this group key: pick any s, set R = s*G.
let s = C::F::random(rng);
let forged = SchnorrSignature::<C> { R: C::generator() * s, s };
// For ANY challenge c: R + c*identity - s*G == 0
assert!(forged.verify(keys.group_key(), arbitrary_challenge));
```
