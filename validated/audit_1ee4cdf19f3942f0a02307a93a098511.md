Confirmed: `http_download` in `chia/data_layer/download_data.py` performs an unrestricted `session.get(server_info.url + "/" + filename, ...)` with no scheme/host allow-listing, and `server_info.url` originates from attacker-controlled on-chain mirror data (mirror coin memos decoded via `get_mirror_info` and stored via `DataLayerWallet.coin_added` → `dl_store.add_mirror`, exposed through `dl_get_mirrors`/`update_subscriptions_from_wallet` in `chia/data_layer/data_layer.py`).

### Title
Server-Side Request Forgery via unrestricted mirror URLs in DataLayer subscription sync - (File: chia/data_layer/download_data.py)

### Summary
Any DataLayer store owner can publish arbitrary mirror URLs on-chain via `create_new_mirror`/`add_mirror` (`chia/data_layer/data_layer_wallet.py` lines 687-703, `chia/data_layer/data_layer.py` lines 965-970). These URLs are embedded as coin memos on a `create_mirror_puzzle()` coin and are picked up automatically by any peer that subscribes to that store — no privileged relationship between publisher and subscriber is required. When a subscribing node's periodic sync (`DataLayer.fetch_and_validate` / `update_subscription`, `chia/data_layer/data_layer.py` lines 606-706) runs, it calls `insert_from_delta_file` → `download_file` → `http_download` (`chia/data_layer/download_data.py` lines 298-319), which issues an `aiohttp` GET directly to `server_info.url + "/" + filename` with no validation of scheme, host, or destination (no blocking of loopback/link-local/internal ranges, no DNS-rebind protection).

### Finding Description
`http_download()` builds the request target purely from `server_info.url`, a string sourced from `Mirror.urls`, which in turn is decoded verbatim from a spend's puzzle solution by `get_mirror_info()` and persisted by `DataLayerWallet.coin_added` (`chia/data_layer/data_layer_wallet.py` lines 775-799) with no allow-list or network-destination check. Any user who can create a mirror coin (an ordinary, unprivileged wallet action — `dl_new_mirror`/`add_mirror` RPC, `chia/wallet/wallet_rpc_api.py` lines 3255-3274) for a store id can set `urls=["http://169.254.169.254/latest/meta-data/", "http://127.0.0.1:<internal-port>/...", "http://internal-host/..."]` or a URL pointing at another service on the victim's LAN. Any node that later subscribes to that store id (a completely standard, low-privilege Data Layer client action) will have its full-node/DataLayer service automatically make outbound HTTP requests to that attacker-chosen destination during routine sync (`fetch_and_validate`/`update_subscription`), with the response body written straight to disk and then parsed as delta-file data. This is the direct analog of the reported CWE-1336 issue: unsanitized, attacker-supplied destination data flows into a server-side network request (there it was a template-engine expression, here it's a URL string), enabling SSRF against internal infrastructure the DataLayer node can reach (cloud metadata endpoints, internal admin ports, etc.), and the response is even written to local storage/read into the node's data model.

### Impact Explanation
This lets an unprivileged attacker (any DataLayer store owner) coerce another user's full node/DataLayer service into making arbitrary outbound HTTP requests to attacker-chosen hosts/ports whenever the victim subscribes to the attacker's store — a classic SSRF impact: probing/exfiltrating from internal services, cloud metadata endpoints, or other hosts reachable only from the victim's network, using the victim node as a proxy. It also causes the node to write attacker-controlled response bytes to local files under `server_files_location`, which are subsequently parsed by the delta-file/Merkle insertion path — increasing the practical severity beyond plain SSRF (data written to disk, parsed by application logic), though the parsed content is still validated against the wallet-advertised root before being committed (per `insert_from_delta_file`), which limits — but does not eliminate — the blast radius of a malicious response.

### Likelihood Explanation
High reachability: creating a mirror coin with attacker-chosen URLs is a normal, unprivileged wallet operation available to any Data Layer client, and subscribing to a store is likewise a routine, low-privilege action any Data Layer user performs to sync store data. No special permissions, race conditions, or social engineering beyond "subscribe to this store" are needed for the SSRF request to fire.

### Recommendation
Validate and constrain mirror URLs at the point they are consumed for outbound requests: enforce an allow-list of schemes (http/https only), reject requests targeting loopback/link-local/private address ranges (or require this to be opt-in/configurable, off by default), and consider resolving+pinning the destination IP prior to the request to prevent DNS-rebinding. Apply the same checks to `PluginRemote` downloader URLs and any other subscriber-configurable network destination in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py`.

### Proof of Concept
1. Attacker creates a DataLayer store and publishes a mirror via `add_mirror`/`dl_new_mirror` with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` (or any internal victim-reachable host): [1](#0-0) 
2. Victim runs a DataLayer node and subscribes to attacker's store id (standard client action).
3. Victim's periodic sync loop calls `fetch_and_validate` → `insert_from_delta_file` → `download_file` → `http_download`, issuing `session.get(server_info.url + "/" + filename, ...)` with `server_info.url` equal to the attacker-supplied internal URL, with no destination filtering: [2](#0-1) 
4. The victim node's outbound request reaches the internal/attacker-chosen endpoint; the response body is written to the victim's local filesystem and fed into delta-file parsing. [3](#0-2) [4](#0-3) [5](#0-4)

    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,

    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.

            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )

    async def dl_new_mirror(
        self,
        request: DLNewMirror,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""
        if self.service.wallet_state_manager is None:
            raise ValueError("The wallet service is not currently initialized")

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()
        async with self.service.wallet_state_manager.lock:
            await dl_wallet.create_new_mirror(
                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )
